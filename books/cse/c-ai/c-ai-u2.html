2.1 Searching for solutions: search trees and strategies

A search algorithm finds a solution by growing a search tree. The root is the initial state, each branch is an action, and each node stands for one path from the root to some state. At every step the algorithm picks one leaf, checks whether it is a goal, and if not, expands it by generating its children. The rule that picks the leaf is the search strategy, and it is the only thing that changes between the algorithms of this unit. Route planners, puzzle solvers and game programs all run this loop.

You need: problem formulation (initial state, actions, transition model, goal test, path cost) from Unit 1, Problem-solving agents and problem formulation, and the state space from Unit 1, State-space search, control strategies and production systems.

State space and search tree

The state space is a graph in which every state appears once. The search tree grows from it, and one state can appear in many nodes, one per path that reaches it. In Figure 2.1.1 a state space of only four states gives an infinite tree, since S → A → S → A … never ends.

A node is a record with five fields: its state; its parent node (following parents back to the root gives the solution path); the action applied to the parent; the path cost g(n) from the root; and its depth, the number of steps from the root. The frontier (also called the open list or fringe) holds the nodes generated but not yet expanded. The explored set (closed list) holds the states already expanded. A loopy path visits a state twice, such as S → A → S; a redundant path reaches a state by a second, costlier route, such as S → B directly (cost 4) when S → A → B costs 3.

Tree search and graph search

Every algorithm in Chapters 2.2 to 2.5 is this loop, written here as graph search:

  1. Put a node for the initial state in the frontier. Make the explored set empty.
  2. If the frontier is empty, return failure.
  3. Choose a node n and remove it from the frontier. The strategy decides which.
  4. If the state of n is a goal, return the path from the root to n by following parent links.
  5. Add the state of n to the explored set.
  6. Expand n. Add each child to the frontier unless its state is already in the frontier or the explored set. Go to step 2.

Tree search is the same loop without the explored set and the check in step 6. It needs less bookkeeping, but on a state space with cycles it can run forever. Graph search expands each state at most once, so on a finite state space it always stops. Breadth-first search moves the goal test into step 6 to save one level (Chapter 2.2); uniform-cost search and A* keep it in step 4, and replace a frontier node when they find a cheaper path to its state.

Strategies and how to judge them

The frontier is a queue, and the kind of queue is the strategy. A first-in first-out (FIFO) queue gives breadth-first search; a last-in first-out (LIFO) stack gives depth-first search; a priority queue ordered by g(n) gives uniform-cost search. These are uninformed (blind) strategies: they use only the problem definition. Informed (heuristic) strategies also use an estimate h(n) of the cost from n to a goal: ordering by h(n) gives greedy best-first search, and by g(n) + h(n) gives A* (Chapter 2.5). This choice of order is called the control strategy.

Strategies are compared on four measures: completeness, whether it always finds a solution when one exists; optimality, whether it finds the cheapest; time complexity, the nodes it generates; and space complexity, the nodes it stores at once.

Complexity is stated with three numbers: b, the branching factor (the largest number of children of any node); d, the depth of the shallowest goal; and m, the maximum depth of any path, which may be infinite. A full tree to depth d has 1 + b + b² + … + bd = (bd+1 − 1)/(b − 1) nodes, and the last level dominates, so the count is O(bd).

Three more ideas that some syllabi list here. Data-driven (forward) search starts from the given facts; goal-driven (backward) search starts from the goal and works back. Goal-driven suits one stated goal with few ways to reach it; Chapter 2.4 runs both at once. Generate-and-test produces a candidate, tests it and repeats; done systematically it is an exhaustive search, and with feedback from the test it becomes hill climbing (Chapter 2.6). When an action can have several outcomes, the solution is a contingency plan, and the tree has AND nodes, where every outcome must be handled, besides the usual OR nodes, where the agent picks one action.

Exam traps

  • A node is not a state. Two nodes can hold the same state with different parents and costs: in strategy (c), state B had a node with g = 4 and another with g = 3.
  • Tree search on a graph with cycles can loop forever. If the state space has loops, write graph search with an explored set.
  • d is the depth of the shallowest goal and m the depth of the deepest path. Mixing them up is the most common slip in complexity answers.
  • Time complexity counts nodes generated, not seconds; space complexity counts nodes stored.
  • Favourite question: "Write the general search algorithm and show how the choice of frontier gives breadth-first, depth-first and uniform-cost search."

2.2 Breadth-first and uniform-cost search

Breadth-first search (BFS) expands the shallowest node first, so it explores the tree level by level and finds the solution with the fewest steps. Uniform-cost search (UCS) expands the cheapest node first, the one with the lowest path cost g(n), so it finds the solution with the lowest total cost even when steps cost different amounts. BFS answers "fewest flight changes from Kochi to Guwahati"; UCS answers "least total travel time", and it is Dijkstra's shortest-path algorithm stopped at the goal.

Breadth-first search

BFS keeps the frontier in a FIFO queue. New nodes join at the back, so every node at depth k is expanded before any node at depth k + 1. Because a goal found at depth k can only be beaten by a shallower one, and all shallower nodes are already done, BFS tests the goal as soon as a child is generated.

  1. If the start state is a goal, return it. Otherwise put it in a FIFO frontier; make the explored set empty.
  2. If the frontier is empty, return failure. Otherwise remove the node n at the front and add its state to the explored set.
  3. For each child of n whose state is neither explored nor in the frontier: if it is a goal, return its path; otherwise add it to the back of the frontier. Go to step 2.

Properties. BFS is complete when b is finite. It is optimal only when every step costs the same, because then fewest steps means cheapest. It generates b + b² + … + bd nodes, so time is O(bd), and since the whole last level waits in the frontier, space is also O(bd). Memory runs out long before patience does. Uniform-cost search

UCS keeps the frontier in a priority queue ordered by g(n) and always removes the node with the smallest g. Two changes to the loop make it correct for unequal costs:

  • The goal is tested when a node is chosen, not when generated, because a goal reached first by an expensive road may later be reached more cheaply (in the worked example, G appears at g = 11, then at g = 9).
  • If a child's state is already in the frontier with a higher g, the cheaper node replaces it. The code below does this by pushing the new copy and skipping the stale one.

Properties. UCS expands nodes in increasing order of g, so the first goal it chooses is the cheapest: it is optimal. It is complete if every step costs at least some ε > 0; with zero-cost steps it can circle forever. Let C* be the cost of the optimal solution. UCS may explore every path cheaper than C*, and such a path can have up to ⌊C*/ε⌋ steps, so time and space are O(b1+⌊C*/ε⌋). When all steps cost the same, this becomes O(bd+1): UCS then does what BFS does, plus one level, because it tests the goal later.

In Python 3, the two searches differ only in the queue and in where the goal test sits:

import heapq
from collections import deque

ROADS = {'S': {'A': 2, 'B': 3, 'F': 2}, 'A': {'S': 2, 'C': 2, 'D': 9},
         'B': {'S': 3, 'D': 4}, 'C': {'A': 2, 'D': 1, 'E': 3},
         'D': {'A': 9, 'B': 4, 'C': 1, 'G': 6}, 'E': {'C': 3, 'G': 2},
         'F': {'S': 2, 'H': 3}, 'G': {'D': 6, 'E': 2}, 'H': {'F': 3}}

def path_to(parent, n):
    p = [n]
    while parent[n]:
        n = parent[n]; p.append(n)
    return p[::-1]

def bfs(start, goal):
    frontier, parent = deque([start]), {start: None}
    while frontier:
        n = frontier.popleft()                    # FIFO: oldest first
        for m in sorted(ROADS[n]):
            if m not in parent:
                parent[m] = n
                if m == goal:                     # test when generated
                    return path_to(parent, m)
                frontier.append(m)

def ucs(start, goal):
    frontier, g, parent, done = [(0, start)], {start: 0}, {start: None}, set()
    while frontier:
        cost, n = heapq.heappop(frontier)         # cheapest g first
        if n in done:
            continue                              # stale, costlier copy
        if n == goal:                             # test when expanded
            return path_to(parent, n), cost
        done.add(n)
        for m, c in ROADS[n].items():
            if cost + c < g.get(m, float('inf')):
                g[m], parent[m] = cost + c, n
                heapq.heappush(frontier, (cost + c, m))

print('BFS:', bfs('S', 'G'))
print('UCS:', ucs('S', 'G'))

Output:

BFS: ['S', 'A', 'D', 'G']
UCS: (['S', 'A', 'C', 'E', 'G'], 9)

2.3 Depth-first, depth-limited and iterative deepening search

Depth-first search (DFS) always expands the deepest node in the frontier: it dives down one branch until it reaches a dead end, then backs up and tries the next branch. It needs very little memory, but it can wander down an endless branch and miss a goal close to the root. Depth-limited search (DLS) stops the dive at a fixed depth, and iterative deepening search (IDS) runs DLS with limits 0, 1, 2, … until a goal turns up. IDS gets the guarantees of BFS with the memory of DFS, and it is the usual choice of uninformed search when the space is large and the solution depth is unknown.

You need: the search loop and the symbols b, d, m from 2.1, and BFS from 2.2 for comparison.

Depth-first search

DFS keeps the frontier in a LIFO stack, or uses recursion, which is the same thing: the newest node is expanded first. Its properties are mixed:

  • Not complete in general. The tree-search version can loop (A → B → A → …), and in an infinite space any version can go down an endless path. The graph-search version is complete on a finite space.
  • Not optimal. On the delivery map of Figure 2.2.1, with neighbours in alphabetical order, DFS visits S, A, C, D, B, G and returns S–A–C–D–G, 11 minutes: neither the fewest roads (BFS, 3) nor the quickest (UCS, 9 minutes).
  • Time O(bm), where m is the deepest path. This can be far worse than bd when m is much larger than d.
  • Space O(bm). DFS stores only the current path and the unexpanded siblings of each node on it. With b = 10 and m = 12 that is about 120 nodes, against about 1012 for BFS at depth 12. A variant called backtracking search generates one child at a time and needs only O(m).

Depth-limited search

DLS is DFS with a depth limit ℓ: a node at depth ℓ is treated as if it had no children. It can end in three ways: a solution; failure, meaning no solution exists at all; or cutoff, meaning none was found within the limit. It is incomplete if ℓ < d and not optimal if ℓ > d. Time is O(bℓ) and space O(bℓ). Knowledge of the problem sets ℓ: on a map of 20 towns no route needs more than 19 roads, so ℓ = 19 is safe, and if any town reaches any other in at most 9 roads (the map's diameter), ℓ = 9 is better. The recursive form, DLS(n, ℓ):

  1. If n is a goal, return the solution.
  2. If ℓ = 0, return cutoff.
  3. For each child c of n: let r = DLS(c, ℓ − 1). If r is a solution, return it; if r is cutoff, remember that a cutoff happened.
  4. Return cutoff if any child was cut off; otherwise return failure.

Iterative deepening search

IDS calls DLS with ℓ = 0, then 1, then 2, and so on, and stops at the first result that is not cutoff. It looks wasteful, since the top of the tree is generated again in every round, but the top is small. With the goal at depth d, nodes at depth d are generated once, at depth d − 1 twice, and at depth 1 d times:

N(IDS) = d·b + (d − 1)·b² + … + 2·bd−1 + 1·bd

Most nodes sit on the bottom level, so the total is still O(bd). IDS is complete when b is finite, optimal when all steps cost the same (it finds the shallowest goal first, like BFS), and needs only O(bd) space, like DFS. The repeated work matters most when b is small: as d grows, the ratio N(IDS)/N(BFS) approaches b/(b − 1), which is 1.11 for b = 10 but 2 for b = 2.

2.4 Bidirectional search

Bidirectional search runs two searches at once, one forward from the start and one backward from the goal, and stops when the two frontiers meet. Each search goes only half the distance, and because a search tree grows exponentially, two half-depth trees are far smaller than one full-depth tree: about 2bd/2 nodes instead of bd. Road-routing software uses the idea widely.

You need: BFS and UCS from 2.2, and goal-driven search from 2.1.

How it works

  1. Put the start state in the forward frontier and the goal state in the backward frontier.
  2. Alternate: expand one level (or one node) forward, using the actions; then one backward, using predecessors, the states from which one action leads to the current state.
  3. After each expansion, check every new state against the other search's frontier and explored set. On a match the frontiers have met: join the forward path to that state with the reversed backward path.

Two conditions must hold. The goal must be one explicit state, not a test such as "any position where the king is checkmated". And predecessors must be computable, which is easy when actions can be undone (roads, sliding-tile moves) and hard when they cannot.

Why it saves time and memory

Each side reaches depth d/2, so time is O(bd/2). With b = 10 and the goal at d = 6, one BFS generates 10 + 100 + … + 106 = 1,111,110 nodes, while two BFS runs to depth 3 generate 2 × (10 + 100 + 1,000) = 2,220: about 500 times fewer. Space is also O(bd/2), since one frontier must stay in memory for the meeting test. With BFS on both sides the method is complete, and optimal when all steps cost the same. With unequal costs (UCS on both sides), the first meeting is not always the cheapest path: keep going until the smallest g in the forward frontier plus the smallest g in the backward frontier is at least the cost of the best path found so far.

  • With step costs, the first meeting point need not give the cheapest path.

2.5 Heuristic functions; greedy best-first and A* search

A heuristic function h(n) estimates the cost of the cheapest path from node n to a goal, such as the straight-line distance to the destination. Informed search uses it to expand the most promising node first. Greedy best-first search trusts h alone; A* adds the cost already paid, f(n) = g(n) + h(n), and finds the cheapest path whenever h never overestimates. A* is the standard path finder in games, robots and maps.

You need: UCS and the delivery map from 2.2, and the strategy comparison of 2.3.

Heuristics and best-first search

A heuristic is problem knowledge written as a number: h(n) ≥ 0, and h = 0 at a goal. Best-first search is graph search with a priority queue ordered by an evaluation function f(n): f = g gives UCS, f = h greedy best-first, and f = g + h A*. In Figure 2.5.1, h is the rider's time along a straight line at top speed, never more than the real time.

Greedy best-first search

Greedy search expands the node that looks closest to the goal. With a good h it is fast, but it ignores the cost already paid, so it is not optimal. As tree search it is not complete (it can swing between two states that both look close); as graph search it is complete on a finite space. Worst-case time and space are O(bm).

A* search

A* orders the frontier by f(n) = g(n) + h(n), the estimated cost of the cheapest solution through n. Two properties of h decide whether A* is optimal. Let h*(n) be the true cheapest cost from n to a goal.

  • Admissible: h(n) ≤ h*(n) for every n; h never overestimates.
  • Consistent (monotone): h(n) ≤ c(n, n′) + h(n′) for every successor n′, a triangle inequality. Every consistent h is admissible, and with a consistent h the value of f never decreases along a path: f(n′) = g(n) + c(n, n′) + h(n′) ≥ g(n) + h(n) = f(n).

Optimality. Tree-search A* is optimal when h is admissible; graph-search A* is optimal when h is consistent. The argument: let C* be the optimal cost and G₂ a worse goal in the frontier, so f(G₂) = g(G₂) > C*. Some node n on the optimal path is also in the frontier, and admissibility gives f(n) ≤ C* < f(G₂), so n, and in turn the whole optimal path, is expanded before G₂. A* expands every node with f(n) < C* and none with f(n) > C*; no other optimal algorithm with the same h is guaranteed to expand fewer. Its weakness is memory: it keeps every generated node.

In code, A* is the Python UCS program of Chapter 2.2 with priority g[m] + H[m], reading path costs from g instead of the popped number.

Designing heuristics

For the 8-puzzle, two classic admissible heuristics (blank not counted):

  • h₁ = the number of misplaced tiles. Each misplaced tile needs at least one move.
  • h₂ = the sum of the Manhattan distances of the tiles from their goal squares (rows apart plus columns apart). Each tile needs at least that many moves.

Since h₂(n) ≥ h₁(n) for every state, h₂ dominates h₁: A* with h₂ never expands more nodes, apart from ties. Both come from relaxed problems: h₁ is the exact cost if a tile could jump anywhere, h₂ if it could slide onto an occupied square, and the exact cost of a relaxed problem is always admissible. The maximum of several admissible heuristics is admissible too. Quality is measured by the effective branching factor b*: if A* generates N nodes for a solution at depth d, b* solves N + 1 = 1 + b* + (b*)² + … + (b*)d. The closer b* is to 1, the better the heuristic.

Memory-bounded heuristic search

A* keeps every node it generates, so memory runs out first. Three versions trade time for memory:

  • IDA* (iterative-deepening A*): IDS with an f-limit instead of a depth limit. Each round is a depth-first search that prunes nodes with f above the limit; the next limit is the smallest f pruned. Space O(bd).
  • RBFS (recursive best-first search): a depth-first recursion that remembers the f of the best alternative path and unwinds when the current f exceeds it, storing the best f of the dropped subtree in its parent. Linear space.
  • SMA* (simplified memory-bounded A*): A* until memory is full, then it drops the leaf with the highest f and backs that value up to the parent, so the subtree can be regrown later. Optimal if the optimal solution fits in memory.

2.6 Local search: hill climbing and simulated annealing

Local search keeps one current state and keeps moving it to a better neighbouring state; it forgets the path. It suits problems where only the final state matters: placing n queens, a class timetable, a delivery tour, a chip layout. It needs almost no memory and works on spaces far too large for tree search. Hill climbing always takes the best move and can get stuck; simulated annealing sometimes accepts a worse move, often at first and rarely later, so it can escape.

You need: the n-queens formulation from Unit 1, Toy problems, and generate-and-test from 2.1.

The state-space landscape

Every state has a value: an objective function to maximise, or a cost to minimise, such as h = the number of pairs of queens that attack each other. Minimising h is the same as maximising −h. Picture the states along a line and each state's value as a height: this is the landscape of Figure 2.6.1. The neighbours of a state are the states one small change away; in 8-queens with one queen per column, moving one queen within its column gives 8 × 7 = 56 neighbours.

The global maximum is the best state of all; a local maximum is better than all its neighbours but worse than the global one. A plateau is a flat area: a flat local maximum has no way up, a shoulder has one further along. A ridge is a chain of local maxima rising in a direction no single move points to, so every single move looks downhill.

Hill climbing

Steepest-ascent hill climbing:

  1. Set current to the initial state.
  2. Generate all neighbours of current and pick the one with the highest value, next.
  3. If value(next) ≤ value(current), return current: it is a peak, perhaps only a local one.
  4. Otherwise set current to next and go to step 2.

It is fast and uses constant memory, but it is neither complete nor optimal. On 8-queens (88 ≈ 16.8 million states) a run of 10,000 random starts made for this book solved 14% and got stuck in 86%, taking about 4 moves when it solved and 3 when it got stuck. Rich and Knight describe it as generate-and-test in which the test's result guides the next guess. Its variants:

  • Sideways moves: accept a neighbour of equal value, up to a limit such as 100 in a row, to cross shoulders. In the same run this raised the success rate to 94%, at about 19 moves per success.
  • Stochastic hill climbing: choose at random among uphill moves, steeper ones more likely. First-choice: take the first random neighbour that is better, useful when there are thousands of neighbours.
  • Random-restart hill climbing: start again from random states until a goal is found. If one run succeeds with probability p, about 1/p runs are needed: 1/0.14 ≈ 7 for 8-queens.

Simulated annealing

In metallurgy, annealing heats a metal and cools it slowly so that its atoms settle into a low-energy crystal. Simulated annealing (SA) copies this with a "temperature" T:

  1. Set current to the initial state and T to a starting temperature T₀.
  2. Pick a random neighbour, next. Let ΔE = value(next) − value(current).
  3. If ΔE > 0 (better), move to next. Otherwise move with probability p = eΔE/T.
  4. Lower T by the schedule, for example T ← αT with α between 0.9 and 0.99. Stop when T is close to 0; otherwise go to step 2.

For a worse move ΔE ≤ 0, so p lies between 0 and 1: small steps down are accepted more often than big ones, and all steps down more often while T is high. If T falls slowly enough, SA finds a global optimum with probability approaching 1. For a cost c to be minimised, use ΔE = c(current) − c(next).

Local beam search

Local beam search keeps k states. At each step generate all neighbours of all k and keep the best k. Unlike k separate restarts, a state with good neighbours can take over several places, so effort moves to where progress is. The k states can crowd into one region; stochastic beam search picks the survivors at random, better ones more likely. Chapter 2.7 adds recombination to this idea.

2.7 Genetic algorithms

A genetic algorithm (GA) searches with a population of candidate solutions instead of one. Each candidate is written as a string, like a chromosome. The fitter candidates are chosen as parents, pairs of parent strings are cut and joined (crossover), a few symbols are changed at random (mutation), and the children form the next generation. Over many generations the population moves towards good solutions. GAs are used where the space is huge and irregular: timetables, antenna and engine design, and tuning controllers or machine-learning models.

You need: local search, simulated annealing and local beam search from 2.6, and binary numbers.

The parts of a GA

  • Individual or chromosome: one candidate solution written as a string. A gene is one position in the string; an allele is the value at that position.
  • Encoding: how a solution becomes a string. A number x from 0 to 31 becomes 5 bits (22 → 10110). An 8-queens state becomes 8 digits, the row of the queen in each column (15863724). A delivery tour becomes the order of the cities, a permutation.
  • Fitness function: the value to maximise. For 8-queens it is the number of non-attacking pairs, at most C(8, 2) = 28 for a solution.
  • Population: the N individuals of one generation.

The algorithm

  1. Create an initial population of N random individuals.
  2. Compute the fitness of each. Stop if one is good enough or the generation limit is reached, and return the best.
  3. Select parents, fitter individuals more likely.
  4. Pair the parents and apply crossover with probability pc (often 0.6 to 0.9); otherwise copy them.
  5. Mutate each gene of each child with a small probability pm, often about 1/L for strings of length L.
  6. The children, plus the best few parents if elitism is used, form the next generation. Go to step 2.

Selection, crossover and mutation

Roulette-wheel (fitness-proportionate) selection gives individual i a slice of a wheel in proportion to its fitness: pi = fi / Σfj. Its expected number of copies is fi / f̄, its fitness over the average fitness. It needs positive fitness, and one very fit individual can fill the population early, which is premature convergence. Tournament selection picks k individuals at random and keeps the fittest; a larger k means stronger selection. Rank selection uses the rank, not the raw fitness.

Crossover mixes parents. Single-point cuts both strings at one position and swaps the tails; two-point swaps the middle section; uniform takes each gene from either parent with probability 0.5. For permutations these break the tour (a city appears twice), so special operators such as order crossover (OX) or partially mapped crossover (PMX) are used. Mutation flips a bit, changes a digit or swaps two cities. Crossover can only recombine values already present; mutation brings in new ones and keeps the population diverse.

Why it works and when to use it

A schema is a pattern of fixed and free genes, such as 1**0* (* = any value). Holland's schema theorem says that short schemata with few fixed genes and above-average fitness get an increasing number of copies in later generations. So crossover can join good building blocks from different parents, which works best when genes that belong together sit close together in the string. Compared with Chapter 2.6, a GA is stochastic beam search with crossover added: like annealing it uses randomness to escape local optima, and like all local search it needs no gradient and no path. But it gives no guarantee of the optimum, it has many settings to tune (N, pc, pm, the selection method), and evaluating fitness for every individual in every generation can be slow.

Takeaways

  1. Every search in Chapters 2.1 to 2.5 is one loop: choose a frontier node, test it, expand it. The strategy is only the order of choosing.
  2. Judge a strategy by completeness, optimality, time and space, written with b, d and m (and C* and ε for costs).
  3. BFS finds the fewest steps; UCS finds the lowest cost and must test the goal when a node is chosen.
  4. DFS needs only O(bm) memory but is neither complete nor optimal. IDS keeps that memory and gains BFS's guarantees for about 11% extra work at b = 10.
  5. Bidirectional search cuts bd to about 2bd/2 when the goal is one explicit state and predecessors can be computed.
  6. A* with f = g + h is optimal when h is admissible (tree search) or consistent (graph search); greedy best-first is fast but not optimal.
  7. A larger admissible heuristic is a better one: Manhattan distance dominates misplaced tiles. The effective branching factor b* measures the gain.
  8. Local search keeps only the current state. Hill climbing stops at local maxima, plateaus and ridges; sideways moves, restarts, annealing and beams fight this.
  9. A genetic algorithm evolves a population by selection (p = fi/Σf), crossover and mutation; in the worked example one generation doubled the average fitness.

Glossary

A* search
Best-first search on f(n) = g(n) + h(n); optimal with an admissible (tree) or consistent (graph) heuristic.
Admissible heuristic
A heuristic that never overestimates: h(n) ≤ h*(n).
Bidirectional search
Forward search from the start and backward search from the goal, stopping when they meet.
Branching factor (b)
The largest number of children of any node.
Breadth-first search
Expands the shallowest node first, using a FIFO queue.
Consistent heuristic
One with h(n) ≤ c(n, n′) + h(n′) for every successor n′; also called monotone.
Crossover
A GA operator that builds children by combining parts of two parent strings.
Depth-first search
Expands the deepest node first, using a LIFO stack or recursion.
Depth-limited search
DFS that treats nodes at depth ℓ as leaves; returns a solution, failure or cutoff.
Effective branching factor (b*)
The branching factor of a uniform tree of depth d holding the N + 1 nodes A* generated.
Explored set
The states already expanded (the closed list).
Fitness function
The value a genetic algorithm maximises for each individual.
Frontier
Nodes generated but not yet expanded (the open list or fringe).
Generate-and-test
Produce a candidate, test it, repeat until one passes.
Genetic algorithm
Search with a population of strings improved by selection, crossover and mutation.
Greedy best-first search
Best-first search on f(n) = h(n); fast but not optimal.
Heuristic function
h(n), an estimate of the cheapest cost from n to a goal.
Hill climbing
Local search that always moves to the best neighbour and stops when none is better.
Iterative deepening search
DLS run with limits 0, 1, 2, … until a solution is found.
Local beam search
Local search that keeps the best k states out of all neighbours of the current k.
Local maximum
A state better than all its neighbours but not the best overall.
Mutation
A GA operator that changes a gene at random with a small probability.
Node
A search-tree record: state, parent, action, path cost and depth.
Plateau
A flat region of the landscape: a flat local maximum or a shoulder.
Relaxed problem
The problem with some rules removed; its exact cost is an admissible heuristic.
Ridge
A rising chain of local maxima that no single move climbs along.
Roulette-wheel selection
Choosing parents with probability fi / Σfj.
Simulated annealing
Local search that accepts a worse move with probability eΔE/T while T falls.
Uniform-cost search
Expands the node with the lowest path cost g(n); optimal for positive step costs.
