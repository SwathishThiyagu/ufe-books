4.1 Knowledge-based agents and the Wumpus world

A knowledge-based agent keeps a knowledge base (KB): a set of sentences, written in a formal language, that describe its world. It tells the KB what it perceives, asks the KB what to do, and the answer comes from inference (deriving new sentences from old ones) instead of a fixed table of reactions. This lets it combine clues gathered at different times and places. The Wumpus world is the small cave game used to test such agents, because in it the dangers can only be found by reasoning.

You need: Unit 1, Intelligent agents: structure and types of agents and Task environments and their properties.

The knowledge base and the inference engine

Each sentence of the KB is written in a knowledge representation language (in this unit: propositional logic, then first-order logic). Sentences given to the agent at the start, not derived from others, are called axioms. The agent works through two operations:

  • TELL adds a sentence to the KB, for example "at time 3 I feel a breeze".
  • ASK poses a question, for example "is room [2,2] safe?". The answer must follow from what has been told; the KB never makes up an answer.

The part that works out the answers is the inference engine. The generic agent program, in the pseudocode used by Russell and Norvig, is:

function KB-AGENT(percept) returns an action
    persistent: KB, a knowledge base
                t, a counter for time, initially 0
    TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t))
    action ← ASK(KB, MAKE-ACTION-QUERY(t))
    TELL(KB, MAKE-ACTION-SENTENCE(action, t))
    t ← t + 1
    return action

Each call does three things: records what it sensed at time t, asks which action is best now, and records that it took that action. An agent can be described at three levels: the knowledge level (what it knows and what its goals are), the logical level (the sentences that encode this) and the implementation level (the data structures and code). Building an agent by telling it sentences is the declarative approach; coding the behaviour directly is the procedural approach.

The Wumpus world: PEAS description

The cave is a 4 × 4 grid of rooms. A room is named [x, y], with x the column and y the row, so the agent starts in [1,1] at the bottom left, facing east. One room holds the Wumpus, a beast that eats anyone who enters; one holds a heap of gold; every room other than [1,1] holds a bottomless pit with probability 0.2.

As a task environment (Unit 1) the cave is partially observable (the agent senses only its own room), deterministic, static, discrete, sequential and single-agent.

Reasoning in the cave, step by step

  1. At [1,1] the percept is [None, None, None, None, None]. No breeze, so neither neighbour [1,2] nor [2,1] has a pit; no stench, so neither has the Wumpus. Both are safe (OK). The agent moves east to [2,1].
  2. At [2,1] it feels a Breeze: a pit is in [2,2] or [3,1], or both. Neither is known safe, so the cautious agent goes back and up to [1,2].
  3. At [1,2] it smells a Stench but feels no breeze. The Wumpus is next to [1,2]: in [1,3] or [2,2] ([1,1] is known clear). But there was no stench in [2,1], so the Wumpus is not in [2,2]. Hence it is in [1,3].
  4. No breeze in [1,2] means no pit in [2,2]. The breeze in [2,1] therefore comes from [3,1]. And [2,2] has neither pit nor Wumpus: it is OK.

A simple reflex agent (Unit 1) cannot do this, because no single percept says where the Wumpus is. When no room is provably safe, the agent must shoot at a likely Wumpus or take a risk; weighing that risk needs probability (Unit 5).

4.2 Propositional logic: syntax, semantics and inference

Propositional logic is the simplest logic an agent can use. Its basic units are proposition symbols, each standing for a statement that is either true or false, such as "there is a pit in [1,2]". Connectives join symbols into sentences, truth tables fix their meaning, and inference finds what must be true whenever the KB is true.

You need: Chapter 4.1 (knowledge base, Wumpus world).

Syntax: how sentences are built

An atomic sentence is a single symbol: True, False, or a proposition symbol such as P, Q or P1,1 ("pit in [1,1]"). A complex sentence is built with five connectives:

ConnectiveNameExample and reading
¬negation (not)¬P: "P is false"
∧conjunction (and)P ∧ Q: both are true; P and Q are the conjuncts
∨disjunction (or)P ∨ Q: at least one is true (inclusive or)
⇒implication (if … then)P ⇒ Q: P is the premise, Q the conclusion
⇔biconditional (if and only if)P ⇔ Q: P and Q have the same truth value

A literal is an atomic sentence or its negation (P or ¬P). Brackets group parts; without them, the order of precedence from tightest to loosest is ¬, ∧, ∨, ⇒, ⇔. So ¬A ∧ B ∨ C ⇒ D means ((¬A ∧ B) ∨ C) ⇒ D. The grammar is:

Sentence        → AtomicSentence | ComplexSentence
AtomicSentence  → True | False | P | Q | R | …
ComplexSentence → ( Sentence ) | ¬ Sentence
                | Sentence ∧ Sentence | Sentence ∨ Sentence
                | Sentence ⇒ Sentence | Sentence ⇔ Sentence

The row to remember is P ⇒ Q: it is false only when P is true and Q is false. When P is false, P ⇒ Q is true whatever Q is. It does not mean cause and effect: "if 7 is even then Chennai is in Kerala" is true because its premise is false.

Entailment, validity and satisfiability

A sentence α is entailed by the KB, written KB ⊨ α, when α is true in every model in which the KB is true. In set terms, M(KB) ⊆ M(α), where M(x) is the set of models that make x true. Three related ideas:

  • Valid (a tautology): true in all models, for example P ∨ ¬P.
  • Satisfiable: true in at least one model, for example P ⇒ Q.
  • Unsatisfiable: true in no model, for example P ∧ ¬P.

Two links to entailment drive Chapter 4.3. Deduction theorem: α ⊨ β exactly when α ⇒ β is valid. Refutation: α ⊨ β exactly when α ∧ ¬β is unsatisfiable. Two sentences are logically equivalent, α ≡ β, when they are true in the same models. The equivalences used most are:

Implication elimination   α ⇒ β  ≡  ¬α ∨ β
Biconditional elimination α ⇔ β  ≡  (α ⇒ β) ∧ (β ⇒ α)
Contraposition            α ⇒ β  ≡  ¬β ⇒ ¬α
Double negation           ¬¬α    ≡  α
De Morgan                 ¬(α ∧ β) ≡ ¬α ∨ ¬β ;  ¬(α ∨ β) ≡ ¬α ∧ ¬β
Distributivity            α ∨ (β ∧ γ) ≡ (α ∨ β) ∧ (α ∨ γ)

A knowledge base for the Wumpus world, and inference rules

Let Px,y mean "pit in [x,y]" and Bx,y "breeze in [x,y]". The rules and the first two percepts of Chapter 4.1 become:

R1: ¬P1,1                          (no pit at the start)
R2: B1,1 ⇔ (P1,2 ∨ P2,1)            (breeze rule for [1,1])
R3: B2,1 ⇔ (P1,1 ∨ P2,2 ∨ P3,1)     (breeze rule for [2,1])
R4: ¬B1,1                          (percept in [1,1])
R5: B2,1                           (percept in [2,1])

The breeze rules use ⇔ because both directions are needed. "Breeze ⇒ a pit next door" lets a breeze point to a pit, as in [3,1]. "Pit next door ⇒ breeze", read by contraposition as "no breeze ⇒ no pit next door", is what proved rooms safe in Chapter 4.1.

An inference rule derives a new sentence from old ones. The two basic rules are Modus Ponens (from α ⇒ β and α, derive β) and And-Elimination (from α ∧ β, derive α). Each equivalence above also gives two rules, one in each direction. KB ⊢ α means α can be derived from KB by the rules. A procedure is sound if everything it derives is entailed, and complete if it can derive everything that is entailed. Chapter 4.3 puts these rules to work.

Exam traps

  • P ⇒ Q is true when P is false. Students mark the first two rows F; that is the commonest error.
  • ⇒ is a connective inside a sentence; ⊨ is a claim about sentences (entailment); ⊢ means "derivable by rules". Do not write one for another.
  • ∨ is inclusive: P ∨ Q is true when both are true. "Either … or but not both" needs (P ∨ Q) ∧ ¬(P ∧ Q).
  • Precedence: A ∨ B ∧ C is A ∨ (B ∧ C), because ∧ binds tighter than ∨.
  • "Not valid" does not mean "unsatisfiable": P ⇒ Q is neither valid nor unsatisfiable.

If KB ⊨ α, every model of KB makes α true, so no model makes KB true and α false: KB ∧ ¬α has no model. Conversely, if KB ∧ ¬α has no model, no model of KB makes α false, so all of them make α true. This is why resolution proves α by refuting ¬α.

4.3 Reasoning patterns: model checking, theorem proving, resolution

To answer ASK(KB, α) the agent must decide whether KB ⊨ α. There are three standard ways. Model checking looks at every model and confirms that α holds wherever the KB holds. Theorem proving applies inference rules to the sentences themselves, never listing models. Resolution is theorem proving with one single rule: it adds ¬α to the KB and shows that the result is a contradiction.

You need: Chapter 4.2 (entailment, equivalences, the Wumpus KB R1–R5).

Model checking

The direct method, truth-table enumeration (TT-ENTAILS in Russell and Norvig), lists all 2ⁿ models of the n symbols in KB and α. In each model where KB is true it checks α; one model with KB true and α false means "not entailed". It is sound and complete for propositional logic, uses O(n) memory when the models are generated depth-first, but takes O(2ⁿ) time: 30 symbols already mean over a billion models.

Practical model checkers search the models cleverly. DPLL is backtracking search over truth assignments (the same idea as CSP backtracking, Unit 3) with three improvements: stop a branch as soon as a clause is false or all clauses are true (early termination); give a symbol that appears with only one sign that sign (pure symbol); and set at once any clause left with one literal (unit clause). WalkSAT is local search (Unit 2): start from a random model, pick a false clause, and flip one of its symbols, either at random or the one that makes the most clauses true. WalkSAT is fast but can never prove that no model exists. 3-SAT is satisfiability of a CNF sentence (defined below) with exactly three literals per clause; random 3-SAT is hardest when there are about 4.3 clauses per symbol.

Theorem proving with inference rules

A proof is a chain of sentences, each one in the KB or derived from earlier ones by a sound rule. Finding a proof is a search problem: the state is the set of sentences known, an action applies a rule, and the goal is a state containing α. From R2 and R4 of Chapter 4.2, the agent proves that [1,2] and [2,1] have no pit:

R6:  (B1,1 ⇒ (P1,2 ∨ P2,1)) ∧ ((P1,2 ∨ P2,1) ⇒ B1,1)   biconditional elimination on R2
R7:  (P1,2 ∨ P2,1) ⇒ B1,1                             And-Elimination on R6
R8:  ¬B1,1 ⇒ ¬(P1,2 ∨ P2,1)                           contraposition on R7
R9:  ¬(P1,2 ∨ P2,1)                                   Modus Ponens on R8 and R4
R10: ¬P1,2 ∧ ¬P2,1                                    De Morgan on R9

The proof ignores the irrelevant symbols, so it can be far shorter than a truth table. Logic is monotonic: adding sentences to a KB never removes an entailment, so a proved fact stays proved. The weakness is that the rule set above may not be complete, and choosing which rule to apply needs a good search strategy.

Resolution and conjunctive normal form

Resolution works on sentences in conjunctive normal form (CNF): an AND of clauses, each clause an OR of literals, such as (¬A ∨ B) ∧ (A ∨ C). Every sentence converts to CNF in four steps:

  1. Eliminate ⇔: α ⇔ β becomes (α ⇒ β) ∧ (β ⇒ α).
  2. Eliminate ⇒: α ⇒ β becomes ¬α ∨ β.
  3. Move ¬ inwards to the symbols with De Morgan and double negation.
  4. Distribute ∨ over ∧: α ∨ (β ∧ γ) becomes (α ∨ β) ∧ (α ∨ γ).

The resolution rule takes two clauses that contain a complementary pair of literals (ℓ in one, ¬ℓ in the other) and produces the resolvent: all their other literals in one clause, with duplicates removed (factoring).

  ℓ1 ∨ … ∨ ℓk,    m1 ∨ … ∨ mn        where ℓi = ¬mj
  ─────────────────────────────────────────────────────────
  ℓ1 ∨ … ∨ ℓi−1 ∨ ℓi+1 ∨ … ∨ ℓk ∨ m1 ∨ … ∨ mj−1 ∨ mj+1 ∨ … ∨ mn

For example, P1,1 ∨ P3,1 and ¬P1,1 resolve to P3,1. The proof method, resolution refutation, has three steps: convert KB ∧ ¬α to CNF; resolve pairs of clauses and add each new resolvent; stop when the empty clause appears (a contradiction, so KB ⊨ α) or when no new clause can be added (KB does not entail α). It is sound, and by the ground resolution theorem it is complete for propositional logic.

Exam traps

  • Resolution refutation adds the negation of the goal. Adding the goal itself proves nothing.
  • In CNF you distribute ∨ over ∧, never ∧ over ∨; the result must be an AND of ORs.
  • Resolve on one complementary pair at a time. P ∨ Q and ¬P ∨ ¬Q give Q ∨ ¬Q (always true, useless), not the empty clause.
  • The model count is 2ⁿ for n symbols, not for n rooms or n sentences.
  • Running out of new clauses means "not entailed"; it does not mean ¬α is entailed.

4.4 First-order predicate logic: syntax and semantics

Propositional logic needs a separate symbol for every fact: to say "every room next to a pit is breezy" in a 4 × 4 cave it needs 16 sentences, and it cannot say it at all for a cave of unknown size. First-order logic (FOL, also called predicate logic or predicate calculus) talks about objects, their properties, the relations between them and functions on them, and uses variables with the quantifiers "for all" and "there exists". One FOL sentence then covers every room, every student or every train.

You need: Chapter 4.2 (connectives, models, entailment).

Syntax: terms and sentences

FOL sentences are built from these symbols:

  • Constant symbols name objects: Ravi, Chennai, M1.
  • Predicate symbols name relations, with a fixed number of arguments: Student(x) (a property, one argument), Parent(x, y), Adjacent(r, s).
  • Function symbols map objects to an object: MotherOf(x), LeftLeg(x).
  • Variables x, y, z; the connectives ¬ ∧ ∨ ⇒ ⇔; the quantifiers ∀ (for all) and ∃ (there exists); and equality =.

A term refers to an object: a constant, a variable, or a function applied to terms, such as MotherOf(Ravi). An atomic sentence is a predicate applied to terms, such as Parent(MotherOf(Ravi), Ravi), or an equality between terms; it is true or false. Complex sentences are built with connectives and quantifiers, as in propositional logic. A variable not bound by a quantifier is free; a sentence for the KB must have none.

Sentence → AtomicSentence | ¬ Sentence | Sentence Connective Sentence
         | Quantifier Variable, … Sentence
AtomicSentence → Predicate(Term, …) | Term = Term
Term → Function(Term, …) | Constant | Variable

Semantics: domain and interpretation

A model of FOL has two parts. The domain is a non-empty set of objects. The interpretation says which object each constant names, which set of tuples each predicate is true of, and which object each function returns for each argument (functions must be total). An atomic sentence is true when the objects its terms name stand in the relation its predicate names. Then:

  • ∀x P is true when P is true for every object of the domain put in place of x.
  • ∃x P is true when P is true for at least one object put in place of x.

Unlike propositional logic, the number of FOL models is unbounded (any domain size, any interpretation), so entailment cannot be checked by listing models; proof methods (Chapters 4.5 and 4.6) are needed.

Quantifiers: the two rules that save marks

∀ goes with ⇒. "Every student passes" is ∀x Student(x) ⇒ Passes(x). Writing ∀x Student(x) ∧ Passes(x) says that every object, including laptops, is a student who passes. ∃ goes with ∧. "Some student topped" is ∃x Student(x) ∧ Topped(x). Writing ∃x Student(x) ⇒ Topped(x) is true as soon as one object is not a student, which says nothing.

Order matters when quantifiers are nested. ∀x ∃y Loves(x, y): everyone loves someone (perhaps different people). ∃y ∀x Loves(x, y): one person is loved by everyone. The two quantifiers are linked through negation, ∀x ¬P ≡ ¬∃x P and ¬∀x P ≡ ∃x ¬P, which is De Morgan's law for quantifiers. Equality lets you count: "Ravi has at least two brothers" is ∃x ∃y Brother(x, Ravi) ∧ Brother(y, Ravi) ∧ ¬(x = y).

Two extensions of FOL are often asked for: ∃! ("there exists exactly one"), which abbreviates ∃x P(x) ∧ ∀y (P(y) ⇒ y = x), and higher-order logic, which quantifies over relations and functions themselves. FOL itself quantifies over objects only.

Using FOL: kinship, the Wumpus world and change

Definitions are written with ⇔. Kinship: ∀x, y Sibling(x, y) ⇔ ¬(x = y) ∧ ∃p Parent(p, x) ∧ Parent(p, y). For the Wumpus world, one sentence replaces all 16 breeze rules: ∀s Breezy(s) ⇔ ∃r Adjacent(r, s) ∧ Pit(r), with rooms as terms [x, y] and Adjacent defined once by arithmetic on x and y.

Facts like the agent's position change with time, so the situation calculus gives such predicates, called fluents, an extra situation argument: At(Agent, [1,1], S0) holds in the initial situation S0, and Result(a, s) names the situation after doing action a in s. An effect axiom says what an action changes, for example ∀s At(Agent, [1,1], s) ∧ FacingEast(s) ⇒ At(Agent, [2,1], Result(Forward, s)). The frame problem is that the agent must also be told what an action does not change (moving does not move the gold); successor-state axioms, one per fluent, state both at once. A goal-based agent then asks for a situation in which its goal holds; that question leads to planning (Unit 6).

4.5 Unification and lifting

The inference rules of Chapter 4.3 work on sentences without variables. A first-order KB is full of variables: "∀x King(x) ∧ Greedy(x) ⇒ Evil(x)". To use such a rule on the fact King(John), the agent must find the value of x that makes King(x) and King(John) identical. Finding such values is unification. Lifting means rewriting a propositional rule (Modus Ponens, resolution) so that it works directly on sentences with variables, using unification to make only the substitutions it needs.

You need: Chapter 4.4 (terms, quantifiers) and Chapter 4.3 (resolution, CNF).

The slow way: instantiation and propositionalization

Two rules remove quantifiers. Universal instantiation (UI): from ∀v α, infer α with v replaced by any ground term (a term with no variables); from the rule above, King(John) ∧ Greedy(John) ⇒ Evil(John). Existential instantiation (EI): from ∃v α, infer α with v replaced by a brand-new constant, a Skolem constant; from ∃x Crown(x) ∧ OnHead(x, John), infer Crown(C1) ∧ OnHead(C1, John).

Propositionalization applies UI with every ground term, then runs propositional inference. It works, but it creates useless facts (Greedy(Richard) ⇒ Evil(Richard) for every person Richard), and with a function symbol there are infinitely many ground terms: Father(John), Father(Father(John)), … By Herbrand's theorem a proof, if one exists, needs only finitely many of them, so the agent can try deeper and deeper terms. It will find every proof, but if the sentence is not entailed it may run for ever: entailment in FOL is semidecidable.

Unification

A substitution θ is a set of bindings such as {x/John, y/Mother(John)}; SUBST(θ, α) replaces each variable in α by its binding. UNIFY(p, q) returns a θ that makes p and q identical, SUBST(θ, p) = SUBST(θ, q), or fails if none exists. The examples in Russell and Norvig's textbook:

pqUNIFY(p, q)
Knows(John, x)Knows(John, Jane){x/Jane}
Knows(John, x)Knows(y, Bill){x/Bill, y/John}
Knows(John, x)Knows(y, Mother(y)){y/John, x/Mother(John)}
Knows(John, x)Knows(x, Elizabeth)fail: x cannot be both John and Elizabeth

The last one fails only because both sentences happen to use the name x. The variables of different sentences are independent, so before unifying the agent standardizes apart, renaming them: Knows(x17, Elizabeth) unifies with {x/Elizabeth, x17/John}.

Several unifiers can exist. For Knows(John, x) and Knows(y, z), both {y/John, x/z} and {y/John, x/John, z/John} work, but the first commits to less. The most general unifier (MGU) is the one that binds as little as possible; every other unifier is the MGU followed by further bindings. The MGU is unique up to renaming of variables, and UNIFY returns it.

The unification algorithm

UNIFY(p, q, θ) starts with θ empty and walks both expressions together:

  1. If p and q are identical, return θ.
  2. If p is a variable, call UNIFY-VAR(p, q, θ); if q is a variable, call UNIFY-VAR(q, p, θ).
  3. If both are compound (a predicate or function with arguments) with the same symbol and the same number of arguments, unify the argument lists pair by pair, passing the growing θ along.
  4. Otherwise (two different constants, different symbols, different numbers of arguments) return failure.

UNIFY-VAR(v, t, θ): if v is already bound in θ, unify its value with t; if t is a bound variable, unify v with t's value; if v occurs anywhere inside t, fail; otherwise add v/t to θ. The middle test is the occurs check: x and f(x) must not unify, because x = f(x) has no finite solution. The check makes unification time quadratic in the size of the expressions, so Prolog leaves it out for speed.

Lifting: Generalized Modus Ponens and first-order resolution

Generalized Modus Ponens (GMP) is the lifted Modus Ponens. For atomic sentences pi, pi′ and q, if one θ makes SUBST(θ, pi′) = SUBST(θ, pi) for every i, then:

p1′,  p2′,  …,  pn′,   (p1 ∧ p2 ∧ … ∧ pn ⇒ q)
──────────────────────────────────────────────
                SUBST(θ, q)

From King(John), Greedy(y) ("everyone is greedy") and King(x) ∧ Greedy(x) ⇒ Evil(x), the unifier θ = {x/John, y/John} gives Evil(John) in one step, without instantiating the rule for anyone else. GMP is sound; it is the rule behind forward and backward chaining (Chapter 4.6).

Resolution lifts the same way. First convert to first-order CNF: eliminate ⇔ and ⇒; move ¬ inwards (¬∀x p becomes ∃x ¬p); standardize variables apart; Skolemize; drop the ∀ signs; distribute ∨ over ∧. Skolemizing replaces each ∃ variable by a Skolem function of the ∀ variables that enclose it: "every student has a roll number", ∀x Student(x) ⇒ ∃n RollNo(n, x), becomes ¬Student(x) ∨ RollNo(F(x), x), since each student has their own number F(x). Two clauses then resolve when a literal of one unifies with the negation of a literal of the other; the MGU is applied to the rest. With factoring, this is complete for refutation, and by the lifting lemma every ground resolution proof has a matching lifted one. Answer extraction adds a literal Answer(z) to the negated goal: the proof ends at Answer(value) instead of the empty clause, and the value is the answer.

4.6 Forward and backward chaining

Chaining is proof by repeated Generalized Modus Ponens on if–then rules. Forward chaining starts from the known facts and fires every rule whose premises are all satisfied, adding its conclusion, until the query appears or nothing new can be added. Backward chaining starts from the query and works back: to prove a goal it finds a rule that concludes it and tries to prove that rule's premises. Both are fast and easy to explain, which is why rule-based expert systems and Prolog are built on them.

You need: Chapter 4.5 (unification, Generalized Modus Ponens).

Definite clauses: the language chaining works on

A definite clause is a clause with exactly one positive literal. Written as a rule, ¬A ∨ ¬B ∨ C is A ∧ B ⇒ C: a conjunction of positive premises implying one positive conclusion. A fact is a definite clause with no premises, such as Missile(M1). A Horn clause has at most one positive literal, so it also allows goal clauses such as ¬A ∨ ¬B. Chaining with GMP is sound and complete for KBs of definite clauses, and for propositional definite clauses it runs in time linear in the size of the KB. A definite-clause KB with no function symbols is called Datalog.

The standard example, from Russell and Norvig: "The law says that it is a crime for an American to sell weapons to hostile nations. The country Nono, an enemy of America, has some missiles, and all of its missiles were sold to it by Colonel West, who is American." Prove that West is a criminal. As definite clauses (M1 is the Skolem constant for "some missile"):

(1) American(x) ∧ Weapon(y) ∧ Sells(x, y, z) ∧ Hostile(z) ⇒ Criminal(x)
(2) Owns(Nono, M1)                (3) Missile(M1)
(4) Missile(x) ∧ Owns(Nono, x) ⇒ Sells(West, x, Nono)
(5) Missile(x) ⇒ Weapon(x)
(6) Enemy(x, America) ⇒ Hostile(x)
(7) American(West)                (8) Enemy(Nono, America)

Forward chaining (data-driven)

  1. Start with the facts of the KB.
  2. In each iteration, for every rule, find every θ that unifies all its premises with known facts at once. If SUBST(θ, conclusion) is new (not just a renaming of a known fact), collect it.
  3. Add the collected facts. Stop with success if the query is among them; stop with failure if an iteration adds nothing (a fixed point).

On a Datalog KB forward chaining always terminates: with p predicates of at most k arguments and n constants there are at most p·nᵏ distinct facts. Two speed-ups matter in practice. Incremental forward chaining only re-checks rules that have a premise unifying with a fact added in the previous iteration. The Rete algorithm, used in production systems (Chapter 4.7), keeps partial matches of rule premises in a network so that they are not recomputed each cycle. For propositional rules the method keeps a count of unproved premises per rule and an agenda of facts to process; a rule fires when its count reaches 0 (Worked example 2).

Backward chaining (goal-driven)

  1. Put the query on the goal list.
  2. Take the first goal and apply the current θ to it. If it unifies with a fact, extend θ and drop the goal.
  3. Otherwise pick a rule whose conclusion unifies with it (standardized apart), and replace the goal by that rule's premises, to be proved left to right with the extended θ.
  4. If no fact or rule works, backtrack to the last choice. Succeed when the goal list is empty.

This is depth-first search of an AND–OR tree: the premises of one rule must all be proved (AND), while different rules for the same goal are alternatives (OR). It needs memory only linear in the depth of the proof and looks only at goals relevant to the query. Its weaknesses are those of depth-first search: it can repeat work, and it can loop for ever on a rule such as Path(x, z) ⇐ Path(x, y) ∧ Link(y, z) when the recursive premise is tried first. Prolog (Chapter 4.8) is backward chaining with these properties.

Exam traps

  • Chaining is complete only for definite (Horn) clauses. A fact such as P ∨ Q cannot be used; you need resolution.

  • In backward chaining, apply the bindings found so far to the next goal before trying it (Weapon(y) gives y/M1 for Sells).

  • Write the iteration number for each new fact in forward chaining; examiners mark the order.

4.7 Knowledge representation: frames, semantic networks, production rules

Logic is exact, but a knowledge engineer describing birds, trains or diseases wants something closer to how people organise knowledge. Semantic networks draw knowledge as a graph of objects and categories, frames store it as records with slots, and production rules store it as IF–THEN pairs that act on a working memory. All three are still logic underneath, made easier to read and faster for common inferences such as inheritance.

You need: Chapter 4.4 (FOL) and Chapter 4.6 (chaining).

Approaches to knowledge representation

A good representation, in the list made popular by Rich and Knight, has four properties: representational adequacy (it can express all the knowledge needed), inferential adequacy (it can derive new knowledge from old), inferential efficiency (it can steer inference quickly to the useful parts) and acquisitional efficiency (new knowledge is easy to add). Knowledge itself comes in four kinds: simple relational knowledge (tables, as in a database), inheritable knowledge (class hierarchies, below), inferential knowledge (logic rules) and procedural knowledge (how to do something, as code or production rules). The general categories an agent uses, such as Animal, Event or Place, together form its ontology.

Semantic networks

A semantic network is a labelled graph. Nodes are objects or categories; arcs are relations. Two arcs are special: is-a links a category to a more general one (Bird is-a Animal), and instance-of links an individual to its category (Mayil instance-of Peacock). To find a property of a node, look at the node first, then follow is-a and instance-of arcs upwards; the nearest value found wins. This is inheritance, and it lets a property be stored once, at the most general node, as a default that lower nodes can override (Figure 4.7.1).

Networks have limits. Plain arcs cannot say "not", "or" or "every" cleanly, and with multiple inheritance two parents can give conflicting defaults: Nixon was a Quaker (Quakers are pacifists) and a Republican (Republicans are not), so the network cannot decide. Extended semantic networks add the power of clausal logic: arcs stand for binary predicates, and a rule is drawn with its condition arcs and conclusion arcs in two different styles, so implications and negations can be drawn and reasoned with on the graph.

Frames, scripts and conceptual dependency

A frame (Minsky's idea) is a record describing a typical object or situation. It has named slots (attributes), each holding a filler (value), and each slot can carry facets: value, default, range (allowed values), if-needed (a procedure that computes the value when asked) and if-added (a procedure that runs when a value is stored). Frames link to each other by is-a and instance-of slots, so they inherit exactly like a semantic network; a frame system is a semantic network written as records. Classes in object-oriented programming descend from this idea.

A script (Schank and Abelson) is a frame for a stereotyped sequence of events. A "train journey" script has entry conditions (passenger has a ticket), roles (passenger, TTE, porter), props (ticket, berth, luggage), scenes in order (reach the station, find the coach, TTE checks the ticket, get off) and results (passenger at the destination). Given "Ravi showed his e-ticket and slept till Madurai", the script fills in that he boarded a train and had a berth. Conceptual dependency (Schank) writes the meaning of a sentence with a few primitive acts, so that sentences with the same meaning get the same representation: ATRANS (transfer of possession), PTRANS (change of place), MTRANS (transfer of information), INGEST, PROPEL, GRASP and a few others. "Ravi gave Asha a book" and "Asha got a book from Ravi" both become ATRANS with actor Ravi, object book, from Ravi, to Asha.

Production rules and production systems

A production rule is an IF condition THEN action pair. A production system has three parts: a rule base, a working memory (WM) of facts about the current problem, and an interpreter that runs the recognize–act cycle:

  1. Match: find every rule whose conditions are all in WM. These rules form the conflict set.
  2. Resolve: pick one rule by a conflict-resolution strategy: refraction (never fire a rule twice on the same facts), recency (prefer rules that match the newest facts), specificity (prefer the rule with more conditions), or a fixed priority.
  3. Act: perform the action, which adds or deletes WM facts. Repeat until the conflict set is empty or a rule says halt.

Rules are modular, read like an expert's advice, and make explanation easy ("I concluded tiger because …"). Large rule sets, however, interact in ways that are hard to predict. Production systems as a search method appear in Unit 1; expert systems built on them are in Unit 6.

4.8 Logic programming and natural deduction

In logic programming the program is a set of logical sentences, and running it means proving a query from them. Prolog, the main logic programming language, stores knowledge as definite clauses and answers questions by backward chaining. Natural deduction looks at the other side of logic: how a person writes a proof, using one rule to introduce and one rule to use each connective. Two other proof systems, the axiomatic system and the semantic tableau, are covered here briefly.

You need: Chapter 4.6 (backward chaining) and Chapter 4.3 (inference rules).

Prolog: facts, rules and queries

A Prolog program is a list of definite clauses. Names of objects and predicates start with a lower-case letter, variables with an upper-case letter, :- is read "if" (⇐), a comma is AND, and every clause ends with a full stop. Here is a small family program in Prolog:

parent(meena, ravi).      % fact 1
parent(meena, priya).     % fact 2
parent(meena, kiran).     % fact 3
parent(ravi, anu).        % fact 4
parent(kiran, dev).       % fact 5
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).

The rule says: for all X, Y, Z, parent(X, Y) ∧ parent(Y, Z) ⇒ grandparent(X, Z). A query asks Prolog to prove a goal and report the bindings:

?- grandparent(meena, W).
W = anu ;
W = dev.

Typing ; asks for the next answer. Prolog runs SLD resolution, which is backward chaining (Chapter 4.6) with fixed choices: clauses are tried in program order, the goals of a rule body left to right, depth-first, and on failure it backtracks to the most recent choice that has untried clauses (Figure 4.8.1).

Three features make Prolog more than pure logic. Negation as failure: \+ G succeeds when G cannot be proved, which assumes that anything not stated is false (the closed-world assumption); childless(X) :- person(X), \+ parent(X, _). makes Priya childless. The cut ! removes the remaining choices, trading completeness for speed. And Prolog omits the occurs check (Chapter 4.5). Because the search is depth-first, clause order matters: a rule whose first goal calls itself, such as ancestor(X, Y) :- ancestor(Z, Y), parent(X, Z)., loops for ever. The animal rules of Chapter 4.7 can be written as Prolog rules and run backwards.

Natural deduction

A natural deduction system gives each connective an introduction rule (how to prove a sentence with it) and an elimination rule (how to use one). A proof may open a temporary assumption; any conclusion that depends on it stays inside its box until a rule discharges it.

ConnectiveIntroductionElimination
∧from α and β, infer α ∧ βfrom α ∧ β, infer α (or β)
⇒assume α, derive β; discharge and infer α ⇒ βfrom α ⇒ β and α, infer β (Modus Ponens)
∨from α, infer α ∨ βfrom α ∨ β, α ⇒ γ and β ⇒ γ, infer γ (cases)
¬assume α, derive ⊥; discharge and infer ¬αfrom α and ¬α, infer ⊥ (contradiction)

Classical logic adds double-negation elimination: from ¬¬α infer α.

Axiomatic system and semantic tableau

An axiomatic (Hilbert-style) system uses no assumptions, only axiom schemas and Modus Ponens. A standard choice is A1: α ⇒ (β ⇒ α); A2: (α ⇒ (β ⇒ γ)) ⇒ ((α ⇒ β) ⇒ (α ⇒ γ)); A3: (¬α ⇒ ¬β) ⇒ (β ⇒ α). Even P ⇒ P takes five lines:

1. (P ⇒ ((P ⇒ P) ⇒ P)) ⇒ ((P ⇒ (P ⇒ P)) ⇒ (P ⇒ P))   A2, β = P ⇒ P, γ = P
2. P ⇒ ((P ⇒ P) ⇒ P)                                 A1, β = P ⇒ P
3. (P ⇒ (P ⇒ P)) ⇒ (P ⇒ P)                           MP 1, 2
4. P ⇒ (P ⇒ P)                                       A1, β = P
5. P ⇒ P                                             MP 3, 4

A semantic tableau proves α valid by refuting ¬α as a tree. Start with ¬α and break formulas apart: α ∧ β puts both on the branch; α ∨ β splits the branch in two; α ⇒ β splits into ¬α and β; ¬(α ⇒ β) puts α and ¬β on the branch; ¬¬α gives α. A branch closes when it holds a formula and its negation. If every branch closes, ¬α has no model and α is valid; an open, fully expanded branch describes a model in which α is false.

Tableau for (P ∧ (P ⇒ Q)) ⇒ Q:
1. ¬((P ∧ (P ⇒ Q)) ⇒ Q)      negated goal
2. P ∧ (P ⇒ Q)               from 1
3. ¬Q                        from 1
4. P                         from 2
5. P ⇒ Q                     from 2
          ┌──────── split 5 ────────┐
6.       ¬P                         Q
     closed (4, 6)            closed (3, 6)

Both branches close, so the formula (Modus Ponens written as one sentence) is valid.

AnalyzeWhy is first-order logic needed for the Wumpus world? Discuss what propositional logic cannot express, and how FOL represents change over time.13 marks

Outline (spans 4.2 and 4.4): one PL rule per room; no way to say "every room"; time-stamped symbols multiply further. FOL: ∀s Breezy(s) ⇔ ∃r Adjacent(r, s) ∧ Pit(r); situation calculus with fluents and Result(a, s); effect axioms; the frame problem and successor-state axioms; cost: FOL entailment is only semidecidable.

AnalyzeCompare forward and backward chaining. Which does a production system use, which does Prolog use, and which suits a diagnosis expert system? Justify.13 marks

Outline (spans 4.6–4.8): comparison table (start point, driven by, search, relevance, risks, termination on Datalog); production systems and Rete run forward; Prolog runs backward (SLD, depth-first); diagnosis has a specific question, so backward chaining, as in MYCIN; monitoring prefers forward chaining.

AnalyzeProve (P ⇒ Q) ⇒ (¬Q ⇒ ¬P) by natural deduction and by a semantic tableau. Compare these with the axiomatic system.13 marks

Outline: natural deduction: assume P ⇒ Q, assume ¬Q, assume P, get Q by ⇒E, ⊥ by ¬E, ¬P by ¬I, then ⇒I twice. Tableau: ¬((P ⇒ Q) ⇒ (¬Q ⇒ ¬P)) gives P ⇒ Q, ¬(¬Q ⇒ ¬P), then ¬Q and ¬¬P, so P; split P ⇒ Q into ¬P (closes with P) and Q (closes with ¬Q): valid. Axiomatic: only axioms and MP, proofs long even for P ⇒ P; natural deduction is closest to human reasoning; tableaux are mechanical and also give countermodels.

AnalyzeEvaluate semantic networks and frames against first-order logic as knowledge representations. Discuss inheritance, defaults and their effect on monotonic reasoning.13 marks

Outline (spans 4.4 and 4.7): nets and frames are readable and make inheritance fast; FOL is precise and expressive (negation, disjunction, quantifiers). Defaults with exceptions (penguins) are natural in nets but make reasoning non-monotonic: adding "Pingu is a penguin" withdraws "Pingu can fly", which classical FOL cannot do; Nixon diamond; extended semantic networks recover logical power; Unit 5 treats non-monotonic reasoning.

Glossary

Answer extraction
Adding an Answer(z) literal to the negated goal so that a resolution proof also returns the value of z.
Axiom
A sentence given to the KB, not derived from others.
Backward chaining
Goal-driven inference: prove a goal by proving the premises of a rule that concludes it.
Clause
A disjunction of literals, such as ¬A ∨ B ∨ C.
Closed-world assumption
Anything not known to be true is taken as false.
CNF
Conjunctive normal form: an AND of clauses.
Conflict set
The production rules whose conditions all match working memory in a cycle.
Definite clause
A clause with exactly one positive literal; a rule or a fact.
Entailment
KB ⊨ α: α is true in every model in which KB is true.
Facet
Extra information about a frame slot: default, range, if-needed, if-added.
Forward chaining
Data-driven inference: fire rules on known facts until the query appears or nothing new is added.
Frame
A record for a typical object or situation, made of slots and fillers.
Generalized Modus Ponens
Modus Ponens lifted to first-order logic using a unifier θ.
Horn clause
A clause with at most one positive literal.
Inheritance
Taking a property from a more general node through is-a or instance-of links.
Literal
An atomic sentence or its negation.
Model
An assignment of truth values (propositional) or a domain plus interpretation (first-order).
Most general unifier
The unifier that binds the fewest variables; all others extend it.
Negation as failure
Prolog's \+: a goal is treated as false when it cannot be proved.
Occurs check
The test that stops a variable being bound to a term that contains it.
Production rule
An IF condition THEN action pair acting on working memory.
Resolution
The rule that combines two clauses with complementary literals into one.
Satisfiable
True in at least one model.
Semantic network
A graph of objects and categories joined by labelled relation arcs.
Semantic tableau
A tree proof that shows α valid by closing every branch that starts from ¬α.
Situation calculus
FOL with situation arguments and Result(a, s) for representing change.
Skolem function
A new function replacing an existential variable that lies inside universal quantifiers.
Sound, complete
Derives only entailed sentences; derives every entailed sentence.
Unification
Finding a substitution that makes two expressions identical.
Valid
True in every model; a tautology.
