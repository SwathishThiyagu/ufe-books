6.1 Planning problems and simple planning agents

Planning means working out a sequence of actions that takes an agent from where it is to where it wants to be, before it acts. Search in Unit 2 did this too, but it treated every state as a sealed box. A planner looks inside: a state is a set of facts, and an action says which facts it needs and which it changes. With that structure the planner can ignore actions that do not matter, split a goal into parts and use one action description for thousands of objects. Planning runs warehouse robots, Mars rovers and airline logistics.

You need: state-space search (Unit 2, Searching for solutions: search trees and strategies) and predicates (Unit 4, First-order predicate logic: syntax and semantics).

What a planning problem contains

A planning problem has three parts: an initial state, a goal and a set of actions. The standard notation comes from STRIPS (Stanford Research Institute Problem Solver, Fikes and Nilsson, 1971); today's planners use PDDL (Planning Domain Definition Language).

  • A state is a set of ground atoms: facts with no variables, such as At(C1, MAA), "cargo C1 is at Chennai airport". The closed-world assumption applies: any fact not listed is false.
  • A goal is a set of literals that must all be true, such as At(C1, DEL). It is partial: every state that contains these facts is a goal state, whatever else is true.
  • An action schema has a name with parameters, a precondition PRE (facts that must hold before), an add list ADD (facts made true) and a delete list DEL (facts made false). Replacing the parameters by objects gives a ground action.

Here is a small air-cargo domain, written in STRIPS style. MAA is Chennai, DEL is Delhi and BLR is Bengaluru; c is a cargo item, p a plane, a an airport.

Load(c, p, a)     PRE: At(c, a), At(p, a)    ADD: In(c, p)    DEL: At(c, a)
Unload(c, p, a)   PRE: In(c, p), At(p, a)    ADD: At(c, a)    DEL: In(c, p)
Fly(p, x, y)      PRE: At(p, x)              ADD: At(p, y)    DEL: At(p, x)

A ground action a is applicable in state s when PRE(a) ⊆ s, every precondition is in the state. Applying it gives the next state:

Result(s, a) = (s − DEL(a)) ∪ ADD(a)

Facts not mentioned stay as they were, which sidesteps the frame problem (below).

Forward and backward planning

Forward planning (progression) starts at the initial state, applies applicable actions and stops when the goal is a subset of the state. Any search from Unit 2, such as A*, can run it. Its weakness is width: even a tiny world has dozens of applicable actions, most irrelevant to the goal.

Backward planning (regression) starts from the goal. It picks a relevant action, one that adds at least one goal literal and deletes none, and asks what must have been true before it:

g′ = (g − ADD(a)) ∪ PRE(a)

Here g is the current goal and g′ the regressed goal. Regression repeats until g′ holds in the initial state. Following only relevant actions keeps its branching small. Figure 6.1.1 shows both directions.

Planning in situation calculus

Situation calculus names each moment a situation: S0 is the start, and Result(a, s) is the situation after doing action a in s. A fact that changes, a fluent, takes the situation as its last argument: At(P1, MAA, S0).

A possibility axiom says when an action can be done: Poss(Fly(p, x, y), s) ⇔ At(p, x, s). A successor-state axiom says exactly when a fluent is true after an action: At(p, y, Result(a, s)) ⇔ [a = Fly(p, x, y) ∧ Poss(a, s)] ∨ [At(p, y, s) ∧ ¬∃z a = Fly(p, y, z)]. In words, a plane is at y afterwards if it just flew there, or it was there and did not fly away.

The frame problem is the difficulty of saying what does not change: without such axioms, nothing tells the prover that flying P1 leaves other cargo where it was. Planning becomes proving ∃s At(C1, DEL, s); the plan is the value of s the proof finds (answer extraction, Unit 4): Result(Unload(C1,P1,DEL), Result(Fly(P1,MAA,DEL), Result(Load(C1,P1,MAA), S0))). It is exact but slow, so STRIPS-style planners took over.

A simple planning agent

When its plan is empty it asks its knowledge base for a goal and calls the planner; otherwise it does the next action.

function SIMPLE-PLANNING-AGENT(percept) returns an action
    TELL(KB, percept)                    // record what was seen
    if plan is empty:
        state ← current state from KB
        goal  ← ASK(KB, what should I achieve?)
        plan  ← PLANNER(state, goal, actions)
    if plan is empty: return NoOp         // no plan exists
    action ← FIRST(plan); plan ← REST(plan)
    TELL(KB, action)
    return action

This agent runs its plan open loop: it assumes each action works.

Question. With the air-cargo actions above, the initial state is At(C1, MAA) ∧ At(P1, MAA) and the goal is At(C1, DEL). (a) Find a plan by forward planning, showing the state after each action. (b) Check it by regression. (c) The world grows to 3 airports (MAA, DEL, BLR), 2 planes and 4 cargo items. How many ground actions exist, and how many apply if everything starts at MAA? (8 marks)

  4. Unload(C1,P1,DEL): PRE In(C1,P1) and At(P1,DEL) are both in S2. S3 = {At(C1,DEL), At(P1,DEL)}. The goal At(C1,DEL) ⊆ S3, so the plan is Load(C1,P1,MAA), Fly(P1,MAA,DEL), Unload(C1,P1,DEL), length 3.
  5. Regression: Unload(C1,p,DEL) adds At(C1,DEL) and deletes only In(C1,p), so it is relevant. g1 = ({At(C1,DEL)} − {At(C1,DEL)}) ∪ {In(C1,p), At(p,DEL)} = {In(C1,p), At(p,DEL)}. Through Fly(p,MAA,DEL): g2 = {In(C1,p), At(p,MAA)}. Through Load(C1,p,MAA): g3 = {At(C1,MAA), At(p,MAA)}, which is true in S0 with p = P1. The plan checks out.
  6. Ground actions: Load has 4 × 2 × 3 = 24 versions, Unload 24, and Fly 2 planes × 3 origins × 2 destinations = 12. Total 60.
  7. With everything at MAA, 4 × 2 = 8 Loads and 2 × 2 = 4 Flys apply: 12 branches. Six actions deep, a forward search can meet up to 12⁶ ≈ 3 million states.

Exam traps

  • Progression uses applicable actions (PRE ⊆ state); regression uses relevant actions (adds a goal literal, deletes none).
  • Regression formula: g′ = (g − ADD) ∪ PRE. Students often subtract DEL instead of ADD.
  • A STRIPS state lists only true facts (closed world); a goal can be partial, so do not list every fact of the final state as the goal.
  • The favourite question, "What is the frame problem?", wants an example of a fact that should not change and the fix (successor-state axioms, or STRIPS's "everything else stays").

6.2 Blocks world and means-ends analysis

The blocks world is a table, a few lettered blocks and a robot arm that moves one block at a time. It is small enough to draw yet tricky enough to break careless planners, so it is the standard test of planning ideas. Means-ends analysis is the planning method of the General Problem Solver (GPS) of Newell and Simon: find the difference between where you are and where you want to be, pick an operator that reduces it, and fix that operator's preconditions first.

You need: Chapter 6.1 (STRIPS actions with PRE, ADD and DEL lists).

The blocks world in STRIPS

The facts are On(x, y) (block x sits on block y), OnTable(x), Clear(x) (nothing is on x), Holding(x) and ArmEmpty. The arm has four operators:

PICKUP(x)     PRE: OnTable(x), Clear(x), ArmEmpty   ADD: Holding(x)             DEL: OnTable(x), ArmEmpty
PUTDOWN(x)    PRE: Holding(x)                       ADD: OnTable(x), ArmEmpty   DEL: Holding(x)
UNSTACK(x,y)  PRE: On(x,y), Clear(x), ArmEmpty      ADD: Holding(x), Clear(y)   DEL: On(x,y), ArmEmpty
STACK(x,y)    PRE: Holding(x), Clear(y)             ADD: On(x,y), ArmEmpty      DEL: Holding(x), Clear(y)

Means-ends analysis

  1. Compare the current state with the goal and list the differences (goal facts that are false).
  2. Pick the most important difference.
  3. Look up an operator that reduces it in a difference table.
  4. If the operator's preconditions are not all true, make them a subgoal and solve it by means-ends analysis first (operator subgoaling).
  5. Apply the operator, then solve the remaining differences from the new state the same way.

The Sussman anomaly

A planner that solves goals strictly one after another is a linear planner. Gerald Sussman's example in Figure 6.2.1 shows its limit: whichever subgoal it does first, the second undoes it. The fix is to interleave steps of different subgoals, which partial-order planning does naturally (Chapter 6.3).

Worked example

Question. Initial state: C on A, A and B on the table, arm empty. Goal: On(A,B) ∧ On(B,C). Use means-ends analysis to find (a) the plan when On(A,B) is tackled first and On(B,C) after it, without interleaving, and (b) the shortest plan. Count the actions. (6 marks)

  1. Difference On(A,B): operator STACK(A,B) needs Holding(A) and Clear(B). Holding(A) needs PICKUP(A), which needs Clear(A); C is on A, so the subgoal gives UNSTACK(C,A), PUTDOWN(C). Then PICKUP(A), STACK(A,B). That is 4 actions; now A is on B, and B and C are on the table.
  2. Difference On(B,C): STACK(B,C) needs Holding(B), which needs Clear(B), but A is on B. So UNSTACK(A,B), PUTDOWN(A), PICKUP(B), STACK(B,C). On(A,B) is now false again, so PICKUP(A), STACK(A,B). That is 6 more.
  3. (a) Total = 4 + 6 = 10 actions. (On(B,C) first is worse: 2 + 6 + 6 = 14.)
  4. (b) Interleave: UNSTACK(C,A), PUTDOWN(C) (a subgoal of On(A,B)); PICKUP(B), STACK(B,C) (achieves On(B,C)); PICKUP(A), STACK(A,B) (achieves On(A,B)). Every precondition holds when its action runs. The shortest plan has 6 actions.

Exam traps

  • Clear(x) means nothing is on top of x; it does not mean x is on the table.
  • The arm holds one block: UNSTACK and PICKUP both need ArmEmpty.
  • The Sussman anomaly is solvable; the point is that solving subgoals strictly one at a time cannot find the shortest plan.
  • Means-ends analysis is neither purely forward nor purely backward: choosing an operator works back from the goal, applying it moves forward.

6.3 Partial-order planning and planning graphs

A partial-order planner does not fix the order of every step in advance. It commits only to the orderings it is forced to, the principle of least commitment, so independent pieces of a plan (left shoe and right shoe, or parcels for two cities) stay independent and can be interleaved or run in parallel. A planning graph is a different tool: a layered graph, built in polynomial time, that tells how many steps a goal needs at the least. Planners use it as a heuristic, and the GRAPHPLAN algorithm extracts a plan from it directly.

You need: Chapter 6.1 (STRIPS actions) and Chapter 6.2 (the Sussman anomaly, which a partial-order planner solves).

What a partial-order plan contains

  • Actions, including two dummy steps: Start, whose effects are the initial state, and Finish, whose preconditions are the goal.
  • Ordering constraints A ≺ B: A happens some time before B, not necessarily just before.
  • Causal links A →p B: A achieves the fact p that B needs, so p must stay true from A until B.
  • Open preconditions: preconditions not yet supplied by any causal link.

A plan is consistent when its orderings have no cycle and no causal link is threatened. A solution is a consistent plan with no open preconditions. Every linearization of a solution, a total order that respects all its constraints, is a valid step-by-step plan.

The partial-order planning (POP) algorithm

  1. Start with the plan {Start, Finish}, Start ≺ Finish; the open preconditions are Finish's preconditions (the goal).
  2. Pick an open precondition p of some action B.
  3. Choose an action A that achieves p, either a step already in the plan or a new one from the action schemas. Add the link A →p B and the ordering A ≺ B (and Start ≺ A ≺ Finish for a new step). A's own preconditions become open.
  4. Resolve threats. An action C threatens A →p B if C deletes p and could fall between A and B. Fix it by demotion (add C ≺ A) or promotion (add B ≺ C).
  5. If a threat cannot be fixed or no action achieves p, backtrack to the last choice. Stop when no open preconditions remain.

A threat in the air-cargo world of Chapter 6.1: one plane must take C1 to DEL and also load C2 at MAA. The link Start →At(P1,MAA) Load(C2,P1,MAA) is threatened by Fly(P1,MAA,DEL), which deletes At(P1,MAA). Demotion would put Fly before Start, which is impossible, so promotion adds Load(C2,P1,MAA) ≺ Fly(P1,MAA,DEL): load both parcels, then fly.

Planning graphs

A planning graph alternates state levels S0, S1, S2, … (sets of literals that might be true) and action levels A0, A1, … (actions that might be done). S0 holds the initial literals. Ai holds every action whose preconditions are in Si and not mutex, plus a persistence (no-op) action for each literal, which simply carries it forward. Si+1 holds every effect of Ai.

Mutex (mutual exclusion) links mark pairs that cannot happen together. Two actions at the same level are mutex for inconsistent effects (one undoes the other's effect), interference (one deletes the other's precondition) or competing needs (their preconditions are mutex). Two literals are mutex if one is the negation of the other, or for inconsistent support (every pair of actions that could produce them is mutex). The graph grows until two consecutive levels are identical (it levels off); its size is polynomial in the number of literals and actions.

The level cost of a literal is the first level where it appears. For a goal of several literals, max-level takes the largest level cost, level sum adds them, and set-level is the first level where all appear with no pair mutex. Each is a quick estimate of how far the goal is. GRAPHPLAN (Blum and Furst) expands the graph until the goals appear together without mutexes, then searches backward through the levels for a plan, adding a level if the search fails.

Worked example

Question. (a) Build a partial-order plan to put on both shoes and socks with POP, and count its linearizations. (b) Have-cake problem: initial Have(Cake); goal Have(Cake) ∧ Eaten(Cake); Eat(Cake) needs Have(Cake) and gives ¬Have(Cake), Eaten(Cake); Bake(Cake) needs ¬Have(Cake) and gives Have(Cake). Find the level costs and set-level, and extract a plan. (10 marks)

  1. (a) Open preconditions of Finish: RightShoeOn, LeftShoeOn. Add RightShoe with link RightShoe →RightShoeOn Finish; its precondition RightSockOn is now open.
  2. Add RightSock with RightSock →RightSockOn RightShoe. Its precondition is empty, so Start ≺ RightSock is enough. Do the same for the left foot. No action deletes a linked fact, so there are no threats.
  3. Linearizations: 4 actions in which the right pair and the left pair each keep their own order. Count = 4! ÷ (2! × 2!) = 24 ÷ 4 = 6, for example (right sock, left sock, right shoe, left shoe).
  4. (b) S0 = {Have, ¬Eaten}. A0 = {Eat, no-op(Have), no-op(¬Eaten)}; Bake is absent because ¬Have is not in S0. S1 = {Have, ¬Have, Eaten, ¬Eaten} with the mutexes of Figure 6.3.2.
  5. Level costs: Have = 0, Eaten = 1. Max-level = max(0, 1) = 1; level sum = 0 + 1 = 1. Set-level: at S1 Have and Eaten are mutex, so not 1.
  6. A1 adds Bake (¬Have is in S1). In S2, Have comes from Bake and Eaten from no-op(Eaten). Their preconditions ¬Have and Eaten are not mutex at S1 (Eat gives both), so the two actions are not mutex, and Have, Eaten are non-mutex at S2: set-level = 2.
  7. Extract backward: at A1 choose Bake and no-op(Eaten), needing ¬Have and Eaten at S1; at A0 Eat supplies both and needs Have, true in S0. Plan: Eat(Cake), then Bake(Cake).

Exam traps

  • Demotion puts the threat before the producer (C ≺ A); promotion puts it after the consumer (B ≺ C). Students often swap them.
  • A partial-order plan is not a parallel plan by itself; it is a set of constraints, and any linearization is a correct sequence.
  • Literals in a planning graph "might be true"; appearing at Si does not mean reachable in i steps unless no mutex blocks the set. Use set-level, not max-level, when goals interact.
  • Forgetting the no-op actions is the usual mistake when drawing a planning graph; without them literals vanish between levels.

6.4 Forms of learning: supervised, unsupervised and reinforcement

An agent learns when its performance on future tasks improves after it observes the world. The kind of feedback it gets decides the form of learning. In supervised learning every example comes with the right answer; in unsupervised learning there are no answers and the agent looks for structure; in reinforcement learning the agent acts and receives only rewards or penalties, often long after the action that earned them. A spam filter, a customer-segment finder and a game-playing program are one of each.

You need: Unit 1, Intelligent agents: structure and types of agents (the learning agent).

The learning agent

A learning agent has four parts. The performance element chooses actions; this is the whole agent of Unit 1. The critic compares what happened with a fixed performance standard and gives feedback. The learning element uses that feedback to improve the performance element. The problem generator suggests new, exploratory actions so the agent does not only repeat what it already knows. The forms of learning below differ in what the critic can tell the learning element.

Supervised learning

The agent gets a training set of N examples (x₁, y₁), …, (x_N, y_N), where x is an input (for example the words of an email) and y = f(x) is the output for some unknown function f. It must find a hypothesis h, from a hypothesis space H, that approximates f. When y comes from a fixed set of classes (spam or not spam) the task is classification; when y is a number (a flat's price in Bengaluru) it is regression.

The real test is generalization: h must work on new inputs. So the data is split, h is learned on the training set and scored on a separate test set. A hypothesis that fits the training set perfectly but fails on the test set has overfitted: it learned the noise as well as the pattern. Decision trees (Chapter 6.5) and neural networks (Chapter 6.6) are supervised; so is naive Bayes (Unit 5).

Unsupervised learning

The agent sees only inputs x, with no labels. It looks for structure: clustering puts similar inputs in groups (Chapter 6.7); dimensionality reduction finds a few combined features that keep most of the information; association rules find items that occur together ("people who buy dosa batter also buy coconut chutney"). There is no answer key, so results are judged by usefulness or by measures such as within-cluster distance. Between the two lies semi-supervised learning: a few labelled examples and many unlabelled ones.

Reinforcement learning

The agent is in a state s, takes an action a, and the environment returns a reward r and a new state s′. Nobody says which action was right. The agent must learn a policy π, a rule that picks an action in each state, to maximise the return:

G = r₁ + γ r₂ + γ² r₃ + …

Here r₁, r₂, … are the rewards that follow, and the discount factor γ (between 0 and 1) makes later rewards count less. Two problems mark this form: credit assignment (which of many earlier actions earned a late reward?) and exploration versus exploitation (try something new, or use what seems best?). Q-learning keeps a value Q(s, a) for each state-action pair and updates it after every step:

Q(s, a) ← Q(s, a) + α [ r + γ · max over a′ of Q(s′, a′) − Q(s, a) ]

Here α is the learning rate (between 0 and 1) and the bracket is the gap between the new estimate and the old one.

  • Rote learning: store a computed result and look it up next time, like caching.
  • Learning by analogy: map a solved problem in a source domain onto a similar target, for example reasoning about electric current from water flowing in pipes.
  • Explanation-based learning (EBL): from one example and a domain theory, explain why the example fits the concept, then generalize the explanation into a rule. From one cup the learner proves it is liftable, stable and holds liquid, and keeps that as the rule for any cup.
  • Discovery: find new concepts with no teacher; Lenat's AM program generated mathematical concepts such as prime numbers this way.

Exam traps

  • Classification and regression are both supervised; the difference is the type of output (class or number), not the presence of labels.
  • Clustering is unsupervised even though the clusters end up with names; the names are given after learning, not used during it.
  • In reinforcement learning the reward is not a label: it says how good the outcome was, not which action was correct.
  • γ multiplies later rewards: the third reward is weighted γ², not 3γ.
  • A model with 100% training accuracy may still be poor; always quote test performance.

6.5 Inductive learning and decision trees

Inductive learning means generalizing from examples: given inputs paired with their correct outputs, find a rule that also predicts the outputs of inputs never seen. A decision tree is one of the most readable such rules, a flowchart of attribute tests that ends in a decision, so a bank officer or a doctor can follow why it decided. The ID3 algorithm grows the tree from the top, at each node choosing the attribute that best separates the classes as measured by information gain. Eight of the ten universities list this chapter.

You need: Chapter 6.4 (supervised learning, test set, overfitting) and logarithms to base 2 (log₂ x = ln x ÷ ln 2).

Inductive learning

There is an unknown function f. The learner sees examples (x, f(x)) and must output a hypothesis h that approximates f. A hypothesis is consistent if it agrees with every example. Usually many hypotheses are consistent; the learner prefers the simplest, a rule called Ockham's razor, because a simple rule that fits is less likely to be fitting chance. Unlike deduction in Unit 4, induction can be wrong: it guesses a general rule from particular cases, and one new example can break it. The choice of hypothesis space is a trade-off: a richer space can express the true f, but is harder to search and easier to overfit.

Decision trees

Each internal node tests an attribute, each branch is one value of that attribute, and each leaf gives a class. To classify an input, start at the root and follow the branches that match it. Every root-to-leaf path reads as an IF–THEN rule, which is why trees are a common way to build rule bases for expert systems (Chapter 6.8). A tree can represent any function of discrete attributes, but some functions need very large trees: the parity function of n bits needs 2ⁿ leaves.

Choosing the attribute: entropy and information gain

A good test splits the examples into groups that are as pure as possible. Purity is measured by entropy:

H(S) = − Σ pᵢ log₂ pᵢ

Here S is a set of examples and pᵢ is the fraction of S in class i (a term with pᵢ = 0 counts as 0). With two classes, H = 0 for a pure set and H = 1 for a 50–50 set. The information gain of attribute A is the drop in entropy after splitting on it:

Gain(S, A) = H(S) − Σ over values v of (|Sᵥ| ÷ |S|) × H(Sᵥ)

Here Sᵥ is the subset of S whose value of A is v, and |S| is the number of examples in S. The ID3 algorithm (Quinlan) applies this recursively:

  1. If all examples have the same class, return a leaf with that class.
  2. If no attributes are left, return a leaf with the majority class. If no examples are left, use the parent's majority class.
  3. Otherwise compute the gain of every remaining attribute and test the one with the highest gain.
  4. Make one branch per value, and build each subtree from that value's examples, with the attribute removed.

Gain favours attributes with many values (a roll number splits the data into pure singletons and is useless), so C4.5 divides it by the split information to give the gain ratio. CART uses the Gini index, 1 − Σ pᵢ², in place of entropy. Numeric attributes are split at a threshold, such as Marks ≤ 60.

Overfitting and pruning

Grown until every leaf is pure, a tree fits noise in the data. Pre-pruning stops early: no split when the gain is tiny, a node has too few examples, or a chi-square test says the split could be chance. Post-pruning grows the full tree, then replaces a subtree by a leaf whenever accuracy on a separate validation set does not fall. Post-pruning is usually better because a split that looks useless can enable good splits below it.

6.6 Neural networks: perceptron and multilayer feed-forward networks

An artificial neural network is built from simple units, each of which adds up its weighted inputs and passes the sum through an activation function. One unit with a step activation is a perceptron; it learns any classification that a straight line can separate. Layers of units with smooth activations, trained by backpropagation, can learn curved boundaries, and stacking many layers gives deep learning, behind today's speech and image recognition. Seven universities list this chapter.

You need: Chapter 6.4 (supervised learning) and the chain rule of differentiation.

The neuron and the perceptron

A unit with inputs x₁ … xₙ computes z = w₁x₁ + w₂x₂ + … + wₙxₙ + b and outputs y = g(z). The weights wᵢ say how much each input matters, the bias b shifts the threshold, and g is the activation function. The perceptron (Rosenblatt, 1958) uses a step: y = 1 if z > 0, else 0. Its learning rule changes the weights only when the output is wrong:

wᵢ ← wᵢ + η (t − y) xᵢ        b ← b + η (t − y)

Here t is the target output and η (eta) the learning rate, a small positive number. The decision boundary w·x + b = 0 is a straight line (a hyperplane in more dimensions). The perceptron convergence theorem says that if some line separates the classes, the rule finds one after a finite number of updates. If none does, as for XOR (Figure 6.6.1), it never settles, a limit Minsky and Papert stressed in 1969.

A multilayer network has an input layer, one or more hidden layers and an output layer. It is feed-forward: signals flow one way, with no loops. Each hidden unit draws its own boundary and the next layer combines them, so the network can carve curved and closed regions. Training: gradient descent and backpropagation

Training minimises a loss, here E = ½ Σ (t − y)², by gradient descent: move each weight a small step downhill, w ← w − η ∂E/∂w. Batch gradient descent uses all examples per step; stochastic gradient descent (SGD) uses one; mini-batch uses a few dozen. Backpropagation computes every ∂E/∂w with the chain rule, from the output back:

output unit:   δₒ = (y − t) · y(1 − y)
hidden unit j: δⱼ = hⱼ(1 − hⱼ) · Σₖ wⱼₖ δₖ
any weight:    w ← w − η · δ(of the unit it feeds) · (input it carries)

Here y and hⱼ are sigmoid outputs, wⱼₖ is the weight from hidden unit j to unit k of the next layer, and δ is a unit's share of the error.

From shallow to deep networks

Each backward step multiplies the gradient by a sigmoid derivative of at most 0.25, so after ten sigmoid layers it can shrink by 0.25¹⁰, below one millionth: the vanishing gradient. A unit whose |z| is large is saturated: its derivative is near 0 and it stops learning. ReLU, whose derivative is 1 for positive z, eases this. Batch normalization rescales each layer's inputs over a mini-batch to mean 0 and variance 1. Overfitting is fought by regularization (L2 adds λΣw² to the loss), dropout (randomly switching off units during training) and early stopping. The learning rate, layer sizes, batch size and epochs are hyperparameters, tuned on a validation set.

Exam traps

  • A single perceptron cannot learn XOR; a multilayer network can.
  • The perceptron rule uses (t − y); backpropagation's output delta for sigmoid units is (y − t)·y(1 − y), with the minus sign in the update. Keep signs consistent.
  • Use the hidden unit's output, not its z, in h(1 − h).
  • Compute all deltas with the old weights first, then update; updating the output weights before finding the hidden deltas is a common slip.

6.7 Clustering: k-means and hierarchical clustering

Clustering puts data points into groups, called clusters, so that points in the same group are similar and points in different groups are not, without any labels. k-means splits the data into a chosen number k of clusters around centres that move until they settle. Hierarchical clustering builds a whole tree of nested clusters, the dendrogram, which can be cut at any level. A food-delivery company in Chennai can cluster order locations to decide where to put its dark stores; a bank can cluster customers to design offers.

You need: Chapter 6.4 (unsupervised learning) and the distance between two points.

Distance

Clustering needs a way to say how far apart two points are. For points p = (p₁, p₂, …) and q = (q₁, q₂, …), the Euclidean distance is d(p, q) = √((p₁ − q₁)² + (p₂ − q₂)² + …) and the Manhattan distance is |p₁ − q₁| + |p₂ − q₂| + …. Scale the features first: if one feature is income in rupees and another is age in years, income would decide every distance on its own.

k-means

k-means looks for k centres μ₁ … μₖ that make the within-cluster sum of squares small:

J = Σ over clusters c  Σ over points x in c  ‖x − μ_c‖²

Here μ_c is the centroid (mean) of cluster c and ‖x − μ_c‖² is the squared Euclidean distance. J is also called SSE or WCSS.

  1. Choose k and pick k starting centroids, for example k of the data points.
  2. Assign each point to its nearest centroid.
  3. Update each centroid to the mean of the points assigned to it.
  4. Repeat steps 2 and 3 until no point changes cluster.

Neither step can increase J, so k-means always stops, but at a local minimum that depends on the starting centroids. In practice it is run several times, or started with k-means++, which spreads the first centroids apart. To choose k, plot J against k and take the elbow, where adding a cluster stops helping much. Each iteration costs about n × k × d distance terms for n points in d dimensions, so k-means scales to millions of points. Its weaknesses: k must be given, it prefers round clusters of similar size, and outliers drag the means (k-medoids, which uses real points as centres, resists this).

Hierarchical clustering

Agglomerative (bottom-up) clustering starts with every point as its own cluster and repeatedly merges the two closest clusters until one is left. Divisive (top-down) clustering starts with one cluster and splits it repeatedly. The distance between two clusters, the linkage, can be defined several ways:

  • Single linkage: the distance between the closest pair of members. It follows long chains.
  • Complete linkage: the distance between the farthest pair. It gives compact clusters.
  • Average linkage: the mean distance over all pairs. Ward's method merges the pair that least increases J.

The dendrogram records every merge at the height of its distance. Cutting it with a horizontal line at height h gives the clusters whose members merged below h, so one run serves every k. The price is cost: the distance matrix needs memory for n² entries, which suits a few thousand points, not millions.

Worked example 2: agglomerative clustering

Question. Five bus stops on a straight road are at P = 0, Q = 1, R = 3, S = 7 and T = 8.5 km. Cluster them by single linkage and by complete linkage, give the merge heights, and find the clusters at a cut of 2.5 km. (8 marks)

  • Assign every point using the old centroids, then update all centroids together; updating one centroid in the middle of a pass is a different algorithm.
  • k-means converges, but not necessarily to the best clustering; different starts can give different answers.
  • Single linkage uses the minimum distance, complete the maximum. Swapping them changes every merge height after the first ones.
  • Clustering is unsupervised: there is no accuracy against labels during learning.

6.8 Expert systems: architecture, roles and knowledge acquisition

An expert system is a program that solves problems in a narrow field at the level of a human expert, by reasoning with knowledge collected from experts, mostly as IF–THEN rules. Its key design choice is to keep the knowledge (the knowledge base) apart from the reasoning (the inference engine), so experts can add rules without reprogramming and the system can explain how it reached a conclusion. Expert systems were AI's first big commercial success in the 1980s, and rule engines built on the same idea still approve loans, check insurance claims and guide machine repair.

You need: Unit 4, Forward and backward chaining, and Unit 4, Knowledge representation: frames, semantic networks, production rules.

What makes a program an expert system

  • Narrow domain, high performance: it knows one field (blood infections, scooter repair) and performs near expert level there, and nowhere else.
  • Heuristic, symbolic reasoning: it uses rules of thumb and symbols, not only formulas.
  • Explanation: it can say why it asks a question and how it reached a conclusion.
  • Uncertainty: it can reason with evidence that is likely rather than certain (certainty factors, Chapter 6.9; Unit 5).
  • Knowledge separate from control: in an ordinary program the knowledge is buried in the code; here it sits in a rule base that can be read and edited.

Architecture

Figure 6.8.1 shows the parts. The knowledge base holds the domain knowledge: facts, rules of the form IF premise THEN conclusion, and heuristics. Some systems also hold meta-knowledge, knowledge about how to use the knowledge, such as "try rules about common faults before rare ones". The working memory holds the facts of the current case: what the user said and what has been concluded so far.

The inference engine applies the rules to the working memory. It can chain forward from facts to conclusions (data-driven) or backward from a hypothesis to the facts that would prove it (goal-driven). A forward-chaining engine repeats a recognise–act cycle:

  1. Match: find every rule whose premises are all in working memory. These form the conflict set.
  2. Conflict resolution: choose one rule. Common strategies are refractoriness (do not fire a rule twice on the same facts), specificity (prefer the rule with more conditions), recency (prefer rules that use the newest facts) and rule order.
  3. Act: fire the rule, adding its conclusion to working memory. Stop when the conflict set is empty or a goal is reached.

The explanation facility answers two questions. WHY, asked when the system requests a fact, gets the rule it is trying to use. HOW, asked about a conclusion, gets the chain of rules and facts that produced it. The knowledge acquisition facility lets the knowledge engineer and expert enter, edit and check rules, and the user interface runs the question-and-answer dialogue.

Roles: who builds it and what it does

Three people matter. The domain expert has the knowledge, often without being able to state it neatly. The knowledge engineer draws it out, structures it, encodes it as rules and tests it. The end user, such as a junior doctor or a field technician, consults the finished system. Larger projects add a tool builder who makes the shell and a maintainer who keeps the rules up to date.

Syllabi that ask for the "roles of expert systems" also mean the kinds of task they do: interpretation (DENDRAL inferred molecular structure from mass-spectrometer data), diagnosis (MYCIN, blood infections), design and configuration (XCON, which configured DEC VAX computer orders), planning, prediction, monitoring, repair, instruction and control.

Knowledge acquisition

Getting knowledge out of the expert is the slowest, costliest step, the knowledge acquisition bottleneck, because much expert knowledge is tacit: the expert just "sees" the answer. The work passes through five stages: identification (the problem, the people, the resources), conceptualization (the key concepts and how they relate), formalization (choose rules, frames or another representation), implementation (write the rules) and testing (run real cases, find wrong answers, refine). Methods include structured and unstructured interviews, protocol analysis (the expert thinks aloud while solving a case and the transcript is mined for rules), observation on the job, case analysis of past records, and machine induction, where rules are learned from examples as in Chapter 6.5.

Worked example

Question. A scooter-repair expert system has the rules below. A customer reports that the engine cranks, the tank has fuel and the spark plug is wet. Run forward chaining with conflict resolution by refractoriness, then specificity, then recency. Show each cycle, then answer the user's question "HOW did you conclude the plug is flooded?" (8 marks)

R1: IF engine cranks AND fuel present   THEN fuel supply OK
R2: IF engine cranks                    THEN battery OK
R3: IF fuel supply OK AND plug wet      THEN plug flooded
R4: IF plug flooded                     THEN ADVISE "remove, dry and refit the plug"
  1. Working memory (WM) = {engine cranks, fuel present, plug wet}.
  2. Cycle 1: conflict set {R1, R2}. R1 has two conditions, R2 one; specificity picks R1. WM gains "fuel supply OK".
  3. Cycle 2: R1 is refractory. Conflict set {R2, R3}; R3 has two conditions, so R3 fires. WM gains "plug flooded".
  4. Cycle 3: conflict set {R2, R4}, one condition each. Recency: R4 uses "plug flooded", added in cycle 2; R2 uses an initial fact. R4 fires and gives the advice.
  5. Cycle 4: conflict set {R2}; R2 fires, WM gains "battery OK". Cycle 5: every matching rule has fired, so the run stops. Four rules fired in all.
  6. HOW: "Plug flooded was concluded by R3 from fuel supply OK and plug wet. Plug wet was given by you. Fuel supply OK was concluded by R1 from engine cranks and fuel present, both given by you."

Exam traps

  • The knowledge base holds general rules; the working memory holds facts about this case. Do not merge them in the architecture diagram.
  • WHY is asked during a consultation, about a question; HOW is asked after, about a conclusion.
  • The knowledge engineer is not the domain expert: one knows the field, the other knows how to encode it.
  • The bottleneck is acquiring knowledge, not running the inference engine.

6.9 Expert system examples: MYCIN, DART; expert system shells

Two classic systems show what expert systems could do and where they stopped: MYCIN, which advised doctors on blood infections, and DART, which diagnosed faults in IBM computer equipment. An expert system shell is what remains when the domain knowledge is taken out: an inference engine, interface and explanation facility waiting for a new knowledge base.

You need: Chapter 6.8 (architecture, WHY and HOW) and Unit 4, Forward and backward chaining.

MYCIN

MYCIN was built at Stanford in the 1970s by Edward Shortliffe with Bruce Buchanan, and written in Lisp. From a patient's details and laboratory results it identified the bacteria likely to be causing a severe infection such as bacteraemia or meningitis, and suggested antibiotics with doses. A typical rule, in words: IF the organism is gram-negative AND rod-shaped AND anaerobic, THEN there is suggestive evidence (0.6) that it is Bacteroides.

  • Backward chaining: it starts from the goal "which organisms need treatment?" and asks the doctor only for facts a rule needs.
  • Certainty factors (CF) run from −1 (certainly false) to +1 (certainly true). A rule's conclusion gets CF(rule) × CF(premise), where the premise CF of an AND is the minimum of its parts; MYCIN used a premise only if its CF was above 0.2.
  • Combining two CFs for the same conclusion: both positive, CF₁ + CF₂(1 − CF₁); both negative, CF₁ + CF₂(1 + CF₁); opposite signs, (CF₁ + CF₂) ÷ (1 − min(|CF₁|, |CF₂|)).

In evaluations MYCIN's advice compared well with infection specialists', yet it was never used routinely in hospitals: legal responsibility, the time doctors spent typing answers, and no link to hospital records kept it in the lab.

DART

DART was developed at Stanford with IBM around 1981 to help IBM field engineers find faulty components in computer installations. Michael Genesereth's version used design descriptions: a model of the device's parts and how they connect, written in logic. From the model and the wrong outputs it found which parts could be at fault, so one program could serve any described device. This is model-based or "deep" diagnosis, unlike MYCIN's "shallow" rules that link symptoms straight to conclusions. Do not confuse it with another DART, the Dynamic Analysis and Replanning Tool, a logistics planner used by US forces in 1991.

Expert system shells

A shell holds every part of Figure 6.8.1 except the knowledge: inference engine, working memory, explanation facility, rule editor and user interface. To build a new expert system, the knowledge engineer only writes rules. After EMYCIN, OPS5 offered forward chaining with the fast Rete matching algorithm; CLIPS, released by NASA in 1985 and written in C, is still free to use; Jess runs in Java, and Drools serves business rules today. A shell speeds development and comes with a tested engine, but its fixed representation and inference style may not fit every domain.

Worked example

Question. A MYCIN-style rule says: IF gram-negative AND rod AND anaerobic THEN Bacteroides (CF 0.6). The lab gives gram-negative CF 0.9, rod CF 0.8, anaerobic CF 0.7. A second rule concludes Bacteroides with CF 0.5 and a third against it with CF −0.3. Find the final CF. (6 marks)

  1. Premise CF = min(0.9, 0.8, 0.7) = 0.7, which is above 0.2, so the rule fires.
  2. CF₁ = 0.6 × 0.7 = 0.42.
  3. Both positive: CF = 0.42 + 0.5 × (1 − 0.42) = 0.42 + 0.29 = 0.71.
  4. Opposite signs: CF = (0.71 − 0.3) ÷ (1 − min(0.71, 0.3)) = 0.41 ÷ 0.7 = 0.59. Evidence against lowers belief but does not cancel it.

Exam traps

  • MYCIN reasons backward (goal-driven), not forward.
  • Certainty factors are not probabilities: they range from −1 to +1 and are combined by MYCIN's own formulas, not Bayes' rule (Unit 5).
  • For an AND premise take the minimum CF; for OR, the maximum.

Takeaways

  1. A planner sees states as sets of facts and actions as PRE, ADD and DEL lists; forward planning applies applicable actions, backward planning regresses the goal through relevant ones.
  2. Situation calculus states planning in logic; its frame problem is solved by successor-state axioms, and a simple planning agent needs execution monitoring to survive failed actions.
  3. Means-ends analysis reduces differences and subgoals on preconditions; the Sussman anomaly shows that solving subgoals strictly in sequence cannot find the shortest plan.
  4. Partial-order planning commits only to forced orderings and protects causal links by promotion or demotion; planning graphs give level-cost heuristics and GRAPHPLAN.
  5. The form of learning follows the feedback: labels (supervised), none (unsupervised) or rewards (reinforcement, with the discounted return and Q-learning).
  6. ID3 grows a decision tree by the highest information gain, recomputed inside every branch, and pruning keeps it from fitting noise.
  7. A perceptron learns only linearly separable classes; hidden layers trained by backpropagation learn curved boundaries, and deep networks need ReLU, normalization and regularization.
  8. k-means alternates assign and update to a local minimum of the within-cluster sum of squares; hierarchical clustering gives a dendrogram that can be cut at any height.
  9. An expert system keeps the knowledge base apart from the inference engine and can explain WHY and HOW; acquiring the knowledge is the bottleneck.
  10. MYCIN (backward chaining with certainty factors) and DART (model-based diagnosis) are the classic examples; a shell such as EMYCIN or CLIPS is the system without its knowledge.

Glossary

Action schema
A parameterised action with a precondition, an add list and a delete list (STRIPS, PDDL).
Agglomerative clustering
Hierarchical clustering that starts from single points and repeatedly merges the two closest clusters.
Backpropagation
Computing the gradient of the loss for every weight by applying the chain rule from the output layer backwards.
Causal link
A →p B: action A supplies fact p that action B needs; p must not be deleted between them.
Certainty factor
MYCIN's measure of belief in a conclusion, from −1 (false) to +1 (true).
Closed-world assumption
Any fact not stated in the state is taken to be false.
Conflict resolution
Choosing which matching rule to fire, by refractoriness, specificity, recency or rule order.
Decision tree
A tree of attribute tests whose leaves give a class; each path is an IF–THEN rule.
Dendrogram
The tree drawn by hierarchical clustering, with each merge at the height of its distance.
Discount factor γ
A number between 0 and 1 that makes later rewards count less in the return.
Entropy
H(S) = −Σ pᵢ log₂ pᵢ, the impurity of a set of examples; 0 when pure.
Expert system shell
An expert system without domain knowledge: engine, interface, explanation and rule editor.
Explanation facility
The part of an expert system that answers WHY a question is asked and HOW a conclusion was reached.
Frame problem
The difficulty of stating, in logic, everything an action leaves unchanged.
Inference engine
The program that applies rules to facts by forward or backward chaining.
Information gain
The drop in entropy obtained by splitting a set on an attribute.
Knowledge acquisition bottleneck
The slow, costly work of drawing knowledge out of experts and encoding it.
Knowledge engineer
The person who elicits, structures, encodes and tests an expert's knowledge.
Least commitment
Fixing only the orderings and choices a plan is forced to make.
Linkage
The rule for the distance between two clusters: single, complete, average or Ward's.
Means-ends analysis
Planning by reducing the difference between state and goal, subgoaling on operator preconditions.
Mutex
A planning-graph link marking two actions or two literals that cannot occur together at that level.
Overfitting
Fitting noise in the training data, so performance on new data is poor.
Perceptron
A single unit with a step activation, trained by wᵢ ← wᵢ + η(t − y)xᵢ.
Planning graph
Alternating levels of literals and actions with mutex links, used for heuristics and GRAPHPLAN.
Q-learning
Reinforcement learning that updates a value Q(s, a) for each state-action pair from rewards.
Situation calculus
A first-order logic of actions, with situations S0 and Result(a, s) and fluents that take a situation argument.
Sussman anomaly
A three-block problem whose two subgoals undo each other unless their steps are interleaved.
Vanishing gradient
Gradients shrinking layer by layer in deep sigmoid networks, so early layers barely learn.
