3.1 Games and optimal decisions in games

In a game the result depends on your moves and on the moves of an opponent who is trying to beat you. The search of Unit 2 assumed that only the agent changes the world; here a second agent with the opposite goal moves in between. Planning ahead in such a competitive, multiagent world is called adversarial search. AI studies board games because the rules are exact, the score is clear and the problems are still hard.

You need: search trees and depth-first search (Unit 2, Searching for solutions: search trees and strategies) and the words multiagent, deterministic and fully observable (Unit 1, Task environments and their properties). Tic-tac-toe as a toy problem is in Unit 1.

Kinds of games

Two questions sort every game. Is there chance, such as dice or shuffled cards? Can each player see the whole state (perfect information), or is part of it hidden (imperfect information)?

Perfect informationImperfect information
Deterministicchess, Go, checkers, tic-tac-toeBattleship, Stratego
ChanceLudo, backgammon, Monopolypoker, bridge, rummy, Scrabble

Most of this unit is about the top-left cell: two players, taking turns, with perfect information, no chance, and a zero-sum score. Zero-sum means that the two players' scores add up to the same total in every outcome, so whatever one gains the other loses. Chess is zero-sum with scores 1 + 0, 0 + 1 or ½ + ½. Chapter 3.4 adds dice.

A game as a search problem

Call the two players MAX (moves first and wants a high score) and MIN (wants a low score). A game is defined by six parts:

  • S0, the initial state: how the game starts (the empty board).
  • PLAYER(s): whose turn it is in state s.
  • ACTIONS(s): the legal moves in s.
  • RESULT(s, a): the transition model, the state after move a is made in s.
  • TERMINAL-TEST(s): true when the game is over. States where it is true are terminal states. The 4th edition of Russell and Norvig writes IS-TERMINAL(s), and TO-MOVE(s) for PLAYER(s).
  • UTILITY(s, p): the final score of terminal state s for player p. In tic-tac-toe we use +1 for an X win, 0 for a draw and −1 for an O win, always seen from MAX (X).

S0, ACTIONS and RESULT together define the game tree. Its nodes are states, its edges are moves, and its levels alternate between MAX and MIN. One level is one ply: a move by one player. (Chess players say "one move" for a move by each side, which is two plies.) The branching factor b is the number of legal moves in a state, and m is the greatest depth of the tree.

Game trees grow fast. Tic-tac-toe has 9 first moves, then 8, then 7, so there are at most 9! = 362 880 move sequences, small enough for a computer to search completely. Chess has b ≈ 35, and a game often lasts 80 plies, so the tree has about 3580 ≈ 10123 move sequences. No computer can search that; Chapter 3.4 shows what programs do instead.

What "optimal" means against an opponent

In Unit 2 a solution was a fixed sequence of actions. In a game MAX cannot fix a sequence, because MIN's replies are not known in advance. MAX needs a strategy: a move now and a move ready for every possible reply of MIN, all the way down. An optimal strategy does at least as well as any other strategy when the opponent also plays perfectly.

The minimax value of a state s is the utility, for MAX, of the terminal state reached when both players play optimally from s:

MINIMAX(s) = UTILITY(s)                           if TERMINAL-TEST(s)
           = max over a in ACTIONS(s) of MINIMAX(RESULT(s, a))   if PLAYER(s) = MAX
           = min over a in ACTIONS(s) of MINIMAX(RESULT(s, a))   if PLAYER(s) = MIN

Here max means MAX picks the child with the highest value and min means MIN picks the lowest. The move MAX makes to its best child is the minimax decision. The value is a guarantee: whatever MIN does, MAX scores at least that much, and more if MIN plays badly.

Worked example

Question. In the tic-tac-toe position of Figure 3.1.1, X (MAX) is to move and squares 5, 8 and 9 are empty. Utilities are +1 if X wins, 0 for a draw and −1 if O wins. Draw the complete game tree, back up the minimax values and state X's optimal move. (6 marks)

  1. Read the threats. O holds 3 and 7, so O wins at once by taking 5 (line 3–5–7). X holds 1, 2 and 6.
  2. X plays 5. O can reply 8 or 9. If O plays 8, X takes the last square 9 and completes 1–5–9: +1. If O plays 9, X takes 8 and completes 2–5–8: +1. The MIN node is min(+1, +1) = +1. Square 5 blocks O and makes two threats at once (a fork), so O cannot stop both.
  3. X plays 8. O replies 5 and completes 3–5–7: −1, a terminal state. If O instead plays 9, X takes 5 and completes 2–5–8: +1. The MIN node is min(−1, +1) = −1.
  4. X plays 9. O replies 5 and wins: −1. If O plays 8, X takes 5 and completes 1–5–9: +1. The MIN node is min(−1, +1) = −1.
  5. Root. MAX takes max(+1, −1, −1) = +1.

Answer. X should play square 5 (the centre). Its minimax value is +1, so X wins against every reply. Moves 8 and 9 score −1 even though they contain a winning line for X, because minimax judges a move by the opponent's best reply, not by the luckiest outcome.

Exam traps

  • All utilities are written from MAX's side, at every level. Do not flip signs at MIN levels unless you are writing the negamax form and say so.
  • A ply is one player's move. "Search to depth 4" means two moves by each side.
  • Zero-sum does not mean the score is zero. It means the players' scores add to the same constant in every outcome.
  • The minimax value is a guarantee against a perfect opponent, not a forecast of what a weak opponent will do.
  • Favourite question: "Define a game as a search problem and explain each component with tic-tac-toe." Name all six parts.

3.2 Minimax algorithm

The minimax algorithm computes the minimax value of Chapter 3.1 by depth-first search. It walks down to the terminal states, scores them with the utility function, and passes the values back up, taking the maximum at MAX levels and the minimum at MIN levels. It gives the exact best move for small games, and it is the skeleton that alpha-beta pruning (Chapter 3.3) and every chess program are built on.

You need: the minimax value and the six parts of a game (Chapter 3.1) and depth-first search with its O(bm) memory (Unit 2, Depth-first, depth-limited and iterative deepening search).

The algorithm

  1. Generate the game tree depth first, from the current state down to the terminal states.
  2. Apply UTILITY to each terminal state.
  3. Back the values up. A MIN node gets the smallest value among its children; a MAX node gets the largest.
  4. At the root, make the move that leads to the child with the highest value. That move is the minimax decision.

Written as two functions that call each other (the usual exam form):

function MINIMAX-DECISION(s): return the action a in ACTIONS(s) with the largest MIN-VALUE(RESULT(s, a))

function MAX-VALUE(s):
    if TERMINAL-TEST(s): return UTILITY(s)
    v ← −∞
    for each a in ACTIONS(s): v ← max(v, MIN-VALUE(RESULT(s, a)))
    return v

function MIN-VALUE(s):
    if TERMINAL-TEST(s): return UTILITY(s)
    v ← +∞
    for each a in ACTIONS(s): v ← min(v, MAX-VALUE(RESULT(s, a)))
    return v

The same idea in Python, for the tree of Figure 3.2.1. The tree is stored in a dictionary: each inner node maps to the list of its children, and a leaf is just its utility (an integer). The flag is_max flips at every level.

tree = {'A': ['B', 'C'], 'B': ['D', 'E'], 'C': ['F', 'G'],
        'D': [3, 5], 'E': [6, 9], 'F': [1, 4], 'G': [7, 2]}

def minimax(node, is_max):
    if isinstance(node, int):              # a leaf: return its utility
        return node
    values = [minimax(child, not is_max) for child in tree[node]]
    v = max(values) if is_max else min(values)
    print(node, 'MAX' if is_max else 'MIN', values, '->', v)
    return v

print('value of A =', minimax('A', True))

Output (each node prints when its value is known, which is the post-order of depth-first search):

D MAX [3, 5] -> 5
E MAX [6, 9] -> 9
B MIN [5, 9] -> 5
F MAX [1, 4] -> 4
G MAX [7, 2] -> 7
C MIN [4, 7] -> 4
A MAX [5, 4] -> 5
value of A = 5

Properties

PropertyMinimax
Complete?Yes, if the game tree is finite.
Optimal?Yes, against an optimal opponent.
TimeO(bm): it visits every node of the tree.
SpaceO(bm) if all moves of a node are generated at once; O(m) if they are generated one at a time.

Here b is the branching factor and m the maximum depth. The space is small because depth-first search keeps only the current path and its siblings. The time is the problem: for chess, bm is about 10123 (Chapter 3.1). So real programs run minimax only to a fixed depth and score the positions there with an evaluation function (Chapter 3.4), and they prune with alpha-beta (Chapter 3.3).

Second example: how deep can minimax go? A program evaluates 106 nodes per second and has 3 minutes per move in a game with b = 35. In 180 s it can evaluate 1.8 × 108 nodes. Since 355 = 52 521 875 ≈ 5.3 × 107 fits but 356 ≈ 1.8 × 109 does not, minimax can search only 5 plies. Chapter 3.3 shows how alpha-beta raises this.

Exam traps

  • A MIN node takes the minimum of its own children, not of the whole level below.
  • Time O(bm) and space O(bm): students often swap them or write O(bd) without saying d is the depth.
  • The answer has two parts: the root value and the move. Many answers give only the number.
  • The order in which leaves are visited does not change any minimax value; it matters only for alpha-beta.

3.3 Alpha-beta pruning

Alpha-beta pruning returns exactly the same value and move as minimax, but it skips branches that cannot change the decision. While it searches it carries two bounds: α, the best value MAX is already sure of on the current path, and β, the best (lowest) value MIN is already sure of. As soon as a node is proved to lie outside the window from α to β, its remaining children are dropped. With good move ordering it searches about twice as deep as minimax in the same time, which is why every game program uses it.

You need: the minimax algorithm and the tree of Figure 3.2.1 (Chapter 3.2).

Why some branches cannot matter

Look again at the tree of Figure 3.2.1. After the left half is searched, B = 5, so MAX at A is sure of at least 5. Now search C. Its first child F comes back as 4. C is a MIN node, so C ≤ 4 whatever G turns out to be. MAX already has 5 from B and will never choose C. So G and both its leaves need not be looked at. In symbols, for any value g of G:

MINIMAX(A) = max(5, min(4, g)) = 5,   because min(4, g) ≤ 4 < 5

The same thing happens one level down inside B. D = 5, so MIN at B is sure of at most 5. Under E, the first leaf is 6, so E ≥ 6. MIN will never pick E, and E's second leaf (9) is not needed.

α, β and the cutoff rules

  • α (alpha) = the highest value found so far for MAX along the path from the root to the current node. It starts at −∞ and only MAX nodes raise it.
  • β (beta) = the lowest value found so far for MIN along that path. It starts at +∞ and only MIN nodes lower it.
  • α and β are passed down to the children; node values are passed up.
  • Cutoff at a MAX node: if its value v ≥ β, stop and return v. MIN above already has something no larger than β, so it will not come here. This is a beta cutoff.
  • Cutoff at a MIN node: if v ≤ α, stop and return v. MAX above already has α. This is an alpha cutoff.

In Python, using the tree dictionary of Chapter 3.2; the list seen records which leaves are actually evaluated:

import math
seen = []

def alphabeta(node, alpha, beta, is_max):
    if isinstance(node, int):
        seen.append(node)
        return node
    if is_max:
        v = -math.inf
        for child in tree[node]:
            v = max(v, alphabeta(child, alpha, beta, False))
            if v >= beta:              # MIN above will never allow this
                return v               # prune the remaining children
            alpha = max(alpha, v)
    else:
        v = math.inf
        for child in tree[node]:
            v = min(v, alphabeta(child, alpha, beta, True))
            if v <= alpha:             # MAX above already has better
                return v
            beta = min(beta, v)
    return v

print('value of A =', alphabeta('A', -math.inf, math.inf, True))
print('leaves evaluated:', seen)

Output:

value of A = 5
leaves evaluated: [3, 5, 6, 1, 4]

Five leaves instead of eight, and the same answer, 5.

Move ordering and complexity

How much is pruned depends on the order in which moves are tried. If the best move at every node is tried first (perfect ordering), alpha-beta examines only about bm/2 nodes instead of bm; the exact smallest number of leaves for a uniform tree is b⌈m/2⌉ + b⌊m/2⌋ − 1 (Knuth and Moore, 1975). So the effective branching factor drops from b to √b: about 6 instead of 35 for chess. In the same time, alpha-beta searches about twice as deep as minimax. With random move order the cost is roughly O(b3m/4). In the worst case (worst moves first) nothing is pruned and the cost is O(bm), the same as minimax.

Programs get close to the best case by trying captures first, then threats, then quiet moves; by trying first the "killer moves" that caused cutoffs elsewhere; and, in iterative deepening, by trying first the move that was best at the previous depth. A transposition table stores the values of positions already searched, because the same position can be reached by different move orders.

Back to Chapter 3.2's program that can afford 1.8 × 108 nodes with b = 35. With perfect ordering it needs about 35m/2 nodes, and 355 ≈ 5.3 × 107 fits, so m/2 = 5 and it reaches about 10 plies instead of 5.

Exam traps

  • α and β travel down the tree; values travel up. Do not copy a child's α back into its parent.
  • MAX nodes change α and cut when v ≥ β; MIN nodes change β and cut when v ≤ α. Swapping the two is the commonest error.
  • A node that was cut returns only a bound: in Figure 3.3.1, E returns 6 although its true minimax value is 9. Only the root value is guaranteed exact.
  • Best case is O(bm/2), meaning the exponent is halved, not the branching factor: √b, not b/2.
  • When you draw the answer, cross out each pruned edge and write the cut condition beside it; examiners give marks for both.

Beyond the syllabus

3.4 Imperfect real-time decisions and expectimax search

Real games put a time limit on each move. So programs stop the search at a fixed depth and score the positions there with an evaluation function, an estimate of the true utility. Some games also have dice; there a third kind of node, the chance node, takes the probability-weighted average of its children. This is expectimax search.

Cutting off the search

Minimax is changed in two places. TERMINAL-TEST becomes CUTOFF-TEST(s, d), true when the depth d reaches a limit or s is terminal. UTILITY becomes EVAL(s). The usual EVAL is a weighted linear function

EVAL(s) = w1·f1(s) + w2·f2(s) + … + wn·fn(s)

where each fi is a feature of the position and wi its weight. In chess, f1 might be (my pawns − opponent's pawns) with w1 = 1, and knights and bishops count 3, rooks 5 and the queen 9. A good EVAL agrees with UTILITY on terminal states, is fast, and rises with the real chance of winning. Programs use iterative deepening (depth 1, 2, 3, … until time runs out) and play the best move of the deepest finished search.

Two dangers follow. A cut-off in the middle of a capture exchange gives a wrong score, so programs search on until the position is quiescent (quiet): quiescence search. And the horizon effect: a program can push an unavoidable loss beyond its depth limit with delaying moves and think the loss has gone.

Expectimax and chance nodes

For a chance node, the value is the expected value of its children:

value(chance node) = Σ over outcomes r of P(r) × value(child after r)

Expectimax has MAX and chance nodes. Expectiminimax adds MIN nodes for games like backgammon and Ludo, where both players roll. With n distinct outcomes per roll the cost grows to O(bmnm); backgammon has n = 21 distinct rolls of two dice. Chance also changes what EVAL must be: in minimax only the order of the leaf values matters, but averages use the numbers themselves, so EVAL must be a positive linear function of the true expected utility.

Worked example

Question. In Figure 3.4.1, MAX chooses move A or move B. Then MAX rolls a die: a six (probability 1/6) or not (5/6). EVAL scores the four results as A: 3 (no six), 5 (six); B: 1 (no six), 9 (six). (a) Find each move's expectimax value and MAX's choice. (b) A new EVAL keeps the same order but scores 9 as 40. Does the choice change? (5 marks)

  1. A = (5/6)(3) + (1/6)(5) = 15/6 + 5/6 = 20/6 ≈ 3.33.
  2. B = (5/6)(1) + (1/6)(9) = 5/6 + 9/6 = 14/6 ≈ 2.33. MAX chooses A.
  3. Rescaled: A is unchanged at 3.33; B = (5/6)(1) + (1/6)(40) = 45/6 = 7.5. MAX now chooses B.

Answer. A (3.33) with the first EVAL, B (7.5) with the second. With MIN nodes instead of dice, A = 3 and B = 1 under both EVALs, so minimax would not change.

Exam traps

  • A chance node takes a weighted average, not a max or a min, and its probabilities must add to 1.
  • EVAL is applied only at cut-off nodes; values above them are still backed up by max, min or average.
  • The horizon effect is the problem; quiescence search and deeper search are remedies. Do not define one as the other.

3.5 Constraint satisfaction problems: variables, domains and constraints

A constraint satisfaction problem (CSP) describes a task by a set of variables, the values each variable may take, and rules that limit which combinations are allowed. A solution gives every variable a value without breaking any rule. Exam timetables, Sudoku, map colouring, seat allotment and chip layout all fit this form, and once a problem is written this way, one general solver (Chapter 3.6) works on all of them.

You need: states, actions and goal tests from Unit 1, Problem-solving agents and problem formulation.

The three parts of a CSP

  • X = {X1, …, Xn}, a set of variables.
  • D = {D1, …, Dn}, one domain per variable: the set of values that variable may take.
  • C, a set of constraints. Each constraint has a scope (the variables it involves) and a relation (the value combinations it allows), for example ⟨(X1, X2), X1 ≠ X2⟩.

A state of the search is an assignment of values to some or all variables. An assignment that breaks no constraint is consistent (legal). One that gives every variable a value is complete; otherwise it is partial. A solution is an assignment that is both consistent and complete.

Why bother? In Unit 2 a state was a black box: the search could only ask "is this the goal?". In a CSP a state has visible parts (a factored representation), so the solver can see which variable breaks which rule and discard every assignment that contains the same mistake at once.

Running example: colouring the South India map. Colour Kerala (KL), Tamil Nadu (TN), Karnataka (KA), Andhra Pradesh (AP) and Telangana (TS) with red, green and blue so that states sharing a border get different colours.

  • X = {KL, TN, KA, AP, TS}.
  • Di = {R, G, B} for every state.
  • C = {KL ≠ TN, KL ≠ KA, TN ≠ KA, TN ≠ AP, KA ≠ AP, KA ≠ TS, AP ≠ TS}: one rule per shared border, 7 in all.

A binary CSP (every constraint links two variables) is drawn as a constraint graph: a node per variable and an edge per constraint (Figure 3.5.1). One solution is KA = R, TN = G, AP = B, KL = B, TS = G.

Kinds of variables and domains

The constraint domain of a problem is the kind of values its variables can take:

  • Discrete, finite domains: colours, rows of a chessboard, digits 0–9. With n variables and d values each there are dn complete assignments: 35 = 243 for our map.
  • Discrete, infinite domains: integers with no upper limit, such as the start day of a job. The allowed pairs cannot be listed in a table, so constraints are written as formulas, for example T1 + d1 ≤ T2 (job 1, lasting d1 days, ends before job 2 starts). Linear constraints like this can be solved; no algorithm solves general nonlinear constraints on integers.
  • Continuous domains: real numbers, such as observation times on a telescope. Linear constraints over reals are solved by linear programming in polynomial time.

Kinds of constraints

  • Unary: one variable, e.g. TN ≠ G, or "the OS exam is not on Monday".
  • Binary: two variables, e.g. KA ≠ AP. These are the edges of the constraint graph.
  • Global (higher-order): any number of variables, e.g. Alldiff(X1, …, Xk), all different. Each row of a Sudoku is an Alldiff on 9 cells, and each column of a cryptarithmetic sum (Chapter 3.7) links three or more letters. These are drawn as a constraint hypergraph.
  • Preference (soft) constraints: "Prof. Rao prefers morning slots". Breaking one costs something but does not make the assignment illegal. A CSP with costs is a constraint optimisation problem (COP).

Any finite-domain global constraint can be rewritten as binary constraints by adding helper variables, which is why many solvers handle only binary constraints.

Worked example

Question. Formulate the 4-queens problem (place 4 queens on a 4 × 4 board so that no two attack each other) as a CSP. Give the variables, domains and constraints, count the complete assignments, and check whether (2, 4, 1, 3) and (1, 3, 4, 2) are solutions. (8 marks)

  1. Variables. Q1, Q2, Q3, Q4, where Qi is the row of the queen in column i. One queen per column is built into this choice.
  2. Domains. Di = {1, 2, 3, 4}.
  3. Constraints. For every pair i < j: Qi ≠ Qj (not the same row) and |Qi − Qj| ≠ j − i (not the same diagonal). There are 4C2 = 6 pairs, so 6 binary constraints.
  4. Size. 44 = 256 complete assignments. (Had we used one variable per square with values {queen, empty}, there would be 216 = 65 536. The choice of variables matters.)
  5. Check (2, 4, 1, 3). Rows 2, 4, 1, 3 are all different. Diagonals, |row difference| against column difference: (1,2): 2 vs 1; (1,3): 1 vs 2; (1,4): 1 vs 3; (2,3): 3 vs 1; (2,4): 1 vs 2; (3,4): 2 vs 1. No pair is equal, so it is consistent and complete: a solution.
  6. Check (1, 3, 4, 2). Columns 2 and 3: |3 − 4| = 1 = 3 − 2, the same diagonal. Not a solution.

Answer. X = {Q1, …, Q4}, Di = {1, 2, 3, 4}, 6 pairwise row-and-diagonal constraints, 256 complete assignments. Only two of them are solutions: (2, 4, 1, 3) and its mirror image (3, 1, 4, 2).

Exam traps

  • A consistent partial assignment is not a solution; a solution must also be complete.
  • The number of complete assignments is dn (domain size to the power of the number of variables), not nd or n × d.
  • Edges of a constraint graph are constraints, not physical roads; two states that touch only at a single point need no edge.
  • A soft constraint never makes an assignment illegal; it only adds a cost.
  • Favourite question: "Define a CSP. Formulate map colouring (or 8-queens, or a timetable) as a CSP and draw its constraint graph."

3.6 CSP as search: backtracking and constraint propagation

A CSP can be solved as a search problem: start with nothing assigned, give one variable a value at a time, and undo the latest choice as soon as a constraint breaks. This is backtracking search, depth-first search over partial assignments. Two things make it fast: choosing the next variable and value with care, and constraint propagation, which uses the constraints to shrink the other variables' domains before searching further.

You need: the CSP of Chapter 3.5 and depth-first search (Unit 2).

From CSP to search tree

As a search problem: the initial state is the empty assignment {}; an action gives a value to an unassigned variable without breaking a constraint; the goal test is "assignment complete". Every solution lies at depth n, the number of variables.

A careless search tree would allow any of n variables with any of d values at the top (nd branches), (n − 1)d at the next level, and so on: n!·dn leaves, though only dn complete assignments exist. But assignments are commutative: setting KA = R then TN = G gives the same state as TN = G then KA = R. So backtracking assigns one variable per level, and the tree has dn leaves.

Backtracking search

function BACKTRACK(assignment, csp):
    if assignment is complete: return assignment
    var ← SELECT-UNASSIGNED-VARIABLE(csp, assignment)      // e.g. MRV
    for each value in ORDER-DOMAIN-VALUES(var, assignment)  // e.g. LCV
        if value is consistent with assignment:
            add {var = value} to assignment
            inferences ← INFERENCE(csp, var, value)        // e.g. forward checking
            if inferences ≠ failure:
                result ← BACKTRACK(assignment, csp)
                if result ≠ failure: return result
            remove {var = value} and its inferences       // backtrack
    return failure

Called first as BACKTRACK({}, csp). Plain backtracking tests each value only against variables already assigned. Figure 3.6.1 shows it on 4-queens.

Choosing the variable and the value

  • Minimum remaining values (MRV), also called "most constrained variable" or "fail-first": choose the variable with the fewest legal values left. If some variable has 0 values, the failure is found at once.
  • Degree heuristic: to break ties (and at the start, when all domains are equal), choose the variable in the most constraints with unassigned variables. In Figure 3.5.1, KA has degree 4, the most, so KA goes first.
  • Least constraining value (LCV): for the chosen variable, try first the value that removes the fewest values from its neighbours' domains.

Variables are chosen fail-first, because every variable must be assigned anyway and early failure prunes more; values are chosen succeed-first, because only one solution is needed.

Constraint propagation

  • Node consistency: every value in Di satisfies the unary constraints on Xi. Just delete the values that do not.
  • Forward checking (FC): after assigning X = x, delete from the domain of every unassigned neighbour Y each value that conflicts with x. If some domain becomes empty, backtrack at once.
  • Arc consistency: the arc Xi → Xj is consistent if every value in Di has at least one supporting value in Dj that satisfies their constraint. AC-3 (Mackworth, 1977) puts every arc in a queue. It takes an arc (Xi, Xj) and REVISEs it, deleting the values of Di that have no support. If Di shrank, it adds back every arc (Xk, Xi) for the other neighbours Xk. It stops when the queue is empty, or reports failure when a domain becomes empty. Its time is O(c·d3) for c binary constraints and domain size d.
  • MAC (maintaining arc consistency) runs AC-3 after every assignment. It is stronger than FC, which only checks arcs into the newly assigned variable.

Stronger forms exist (path consistency for triples, k-consistency), and conflict-directed backjumping jumps back to the variable that caused a failure instead of the most recent one. Local search can solve CSPs too: the min-conflicts heuristic repeatedly moves one variable to the value with the fewest conflicts (compare hill climbing in Unit 2).

Question 2. Variables A, B, C with domains {1, 2, 3} and constraints A < B and B < C. Run AC-3. (5 marks)

  1. Queue: (A,B), (B,A), (B,C), (C,B).
  2. REVISE(A,B): A = 3 has no larger B, so D(A) = {1, 2}. A has no other neighbour, so nothing is added.
  3. REVISE(B,A): B = 1 has no smaller A, so D(B) = {2, 3}. Add (C,B), already queued.
  4. REVISE(B,C): B = 3 has no larger C, so D(B) = {2}. Add (A,B).
  5. REVISE(C,B): C must exceed 2, so D(C) = {3}.
  6. REVISE(A,B): A must be below 2, so D(A) = {1}. Queue empty.

Answer: A = 1, B = 2, C = 3, found by propagation alone with no search.

Exam traps

  • MRV chooses the variable; LCV chooses the value. Swapping them is the commonest slip.
  • When D(Xi) shrinks in AC-3, add the arcs pointing into Xi, (Xk, Xi), not the arcs out of it.
  • Arc consistency does not prove a solution exists: three mutually adjacent variables with domains {R, G} are arc-consistent, but cannot all differ.
  • FC checks only the neighbours of the variable just assigned; it misses conflicts between two unassigned variables, which AC-3 finds.

3.7 Cryptarithmetic and map colouring problems

Two classic puzzles that are solved by hand as CSPs. In a cryptarithmetic puzzle each letter stands for a different digit and the sum must be correct. In map colouring (or room colouring) neighbours must get different colours. Both are common exam questions wherever CSPs are taught.

Cryptarithmetic as a CSP

  • Variables: the letters, plus one carry variable C1, C2, … per column.
  • Domains: {0, …, 9} for letters; {0, 1} for carries when two numbers are added.
  • Constraints: Alldiff over the letters; leading letters ≠ 0; one column equation per column: digits + carry in = result digit + 10 × carry out.

By hand, start from the leftmost column, where domains are smallest (MRV again), and put each value found into every equation.

Worked example

Question. Solve SEND + MORE = MONEY. (8 marks)

  1. Ten-thousands: M = C4, and M ≠ 0, so M = 1.
  2. Thousands: S + 1 + C3 = O + 10. With S ≤ 9, O ≤ 1; 1 is taken, so O = 0, and S = 9 − C3.
  3. Hundreds: E + 0 + C2 = N + 10·C3. If C3 = 1, then E + C2 ≥ 10 forces E = 9, C2 = 1, N = 0, but O = 0. So C3 = 0 and S = 9. Then E + C2 = N; since N ≠ E, C2 = 1 and N = E + 1.
  4. Tens: N + R + C1 = E + 10. Put N = E + 1: R + C1 = 9. R = 9 is taken by S, so C1 = 1 and R = 8.
  5. Units: D + E = Y + 10. Digits left: {2, 3, 4, 5, 6, 7}, and Y ≥ 2 means D + E ≥ 12. Since D = Y + 10 − E, the values E = 2, 3, 4 need D ≥ 10, 9 or 8, and 8 and 9 are taken. E = 5, N = 6: D = Y + 5 gives Y = 2, D = 7 (Y = 3 or 4 would need D = 8 or 9). E = 6, N = 7 fails (D would clash with 6, 7, 8 or 9).

Answer. S = 9, E = 5, N = 6, D = 7, M = 1, O = 0, R = 8, Y = 2. Check: 9567 + 1085 = 10652. The solution is unique.

Map and room colouring

The South India map of Chapter 3.5 is the standard map-colouring CSP, solved in Chapter 3.6. Room colouring is the same problem on a floor plan: rooms sharing a wall must differ. Say hall H shares walls with kitchen K, bathroom Ba and bedrooms B1, B2, and K–Ba, Ba–B2, B2–B1 also share walls. Degree picks H first (degree 4): H = red. The chain K–Ba–B2–B1 then needs two colours: K = green, Ba = blue, B2 = green, B1 = blue. Three colours are needed, since H, K, Ba form a triangle. The least number is the chromatic number; by the four colour theorem (Appel and Haken, 1976) four always suffice for a flat map.

Exam traps

  • Forgetting the carries, or giving them the domain 0–9; for two numbers a carry is 0 or 1.
  • The extra leading digit of a two-number sum is always 1.
  • Show the reasoning column by column; a bare answer earns few marks.

Takeaways

  1. A two-player game is a search problem with six parts; its solution is a strategy, not a fixed path.
  2. The minimax value backs utilities up the tree: max at MAX nodes, min at MIN nodes. It guarantees MAX's score against a perfect opponent.
  3. Minimax is depth-first: time O(bm), space O(bm). For real games it must be cut off at a fixed depth and use an evaluation function.
  4. Alpha-beta pruning gives the same root value and move as minimax. With best-first move ordering it costs O(bm/2), so it searches about twice as deep.
  5. Chance nodes average their children by probability. Under chance, the actual numbers given by EVAL matter, not just their order.
  6. A CSP is variables, domains and constraints; a solution is a consistent, complete assignment. There are dn complete assignments.
  7. Backtracking assigns one variable per level and undoes failures. MRV and degree pick the variable, LCV the value, and forward checking or AC-3 shrink the domains.
  8. Cryptarithmetic adds carry variables and one equation per column; map and room colouring are graph colouring. Both are solved by propagation plus a little search.

Q11 "Alpha-beta pruning and constraint propagation both cut the search tree." Compare the two. (spans Chapters 3.3 and 3.6) 10 marks

Points: both work inside depth-first search; alpha-beta uses bounds on values (an optimisation against an opponent), propagation uses constraints on domains (a feasibility problem); alpha-beta never changes the answer, propagation never removes a solution; both depend on ordering (moves; variables and values); both find failures early; alpha-beta works after values are known, FC and AC-3 work before the next choice.

Q12 Design a tic-tac-toe player: formulate the game, choose between full minimax, alpha-beta and depth-limited search with an evaluation function, and justify your choice. (spans Chapters 3.1–3.4) 12 marks

Points: six components; at most 9! = 362 880 move sequences, so full minimax is affordable and plays perfectly (a draw against perfect play); alpha-beta gives the same moves faster; a depth-limited version with e(p) = open lines for X − open lines for O suits weaker hardware and shows the cut-off idea; move ordering (centre, corners, edges).

Q13 When should a program use expectimax instead of minimax? Use a numerical example to show why the scale of the evaluation function matters only under chance. 8 marks

Points: expectimax for dice or a random opponent, minimax for a rational adversary; the Ludo example of Chapter 3.4 (A 3.33 vs B 2.33, then B 7.5 after 9 → 40); under min nodes the decision is unchanged; EVAL must be a positive linear function of the expected utility.

Q14 Formulate your college's end-semester exam timetable as a CSP and say which heuristics and propagation you would use. (spans Chapters 3.5–3.6) 10 marks

Points: variables = exams; domains = slots (day and session), possibly halls; hard constraints: exams sharing students differ, hall capacity, unary "not before day 3"; soft: gaps for a batch; constraint graph; MRV and degree (exams with most shared students first), LCV for slots, FC or MAC; min-conflicts for large instances; COP for soft constraints.

Glossary

Adversarial search
Search in a world where an opponent moves between your moves and tries to make you lose.
Alpha (α)
The best value MAX is already sure of along the current path.
Alpha-beta pruning
Minimax that skips branches proved unable to change the decision.
Arc consistency
Every value of Xi has a supporting value in Xj for their constraint.
Assignment
Values given to some (partial) or all (complete) variables of a CSP; consistent if no constraint is broken.
Backtracking search
Depth-first search that assigns one variable per level and undoes the last choice on failure.
Beta (β)
The best (lowest) value MIN is already sure of along the current path.
Branching factor (b)
The number of moves or children per node.
Chance node
A node for dice or other randomness; its value is the probability-weighted average of its children.
Chromatic number
The least number of colours that colours a graph with no two neighbours alike.
Constraint graph
A graph with a node per variable and an edge per binary constraint.
Constraint propagation
Using constraints to remove values from domains before or during search.
CSP
Constraint satisfaction problem: variables, domains and constraints.
Cryptarithmetic
A puzzle in which letters stand for distinct digits in a correct sum.
Cut-off test
The test that stops a game search at a depth limit.
Degree heuristic
Pick the variable in the most constraints with unassigned variables.
Domain
The set of values a variable may take.
Evaluation function
An estimate of a position's utility, used at cut-off nodes.
Expectimax
Game search with MAX nodes and chance nodes; with MIN nodes too it is expectiminimax.
Forward checking
After an assignment, delete conflicting values from the neighbours' domains.
Game tree
The tree of all positions reachable by legal moves, levels alternating between players.
Horizon effect
A depth-limited search pushes an unavoidable loss beyond its depth limit and misses it.
LCV
Least constraining value: try first the value that rules out the fewest neighbour values.
Minimax value
The utility MAX gets when both players play optimally from a state.
MRV
Minimum remaining values: pick the variable with the fewest legal values left.
Ply
One move by one player; one level of the game tree.
Quiescence search
Extending the search until the position is quiet, with no pending captures.
Strategy
A plan giving a move for every possible reply of the opponent.
Utility function
The final score of a terminal state for a player.
Zero-sum game
A game whose players' utilities add to the same constant in every outcome.
