4.1 PHP basics: syntax, variables, data types, operators

PHP is a server-side scripting language. A .php file holds ordinary HTML plus one or more PHP code blocks. When a request arrives, the web server hands the file to the PHP interpreter, which runs the code and sends back only the HTML output. That is how a shop page can show today's price instead of a price typed once into HTML. This chapter covers the syntax of those blocks, variables written with a $ sign, the eight data types, and the operators that combine values. Every later PHP form handler and session script is built from these pieces.

You need: the HTTP request and client-server picture from Unit 1, and basic HTML from Unit 2.

A PHP file is HTML with PHP blocks

PHP stands for PHP: Hypertext Preprocessor. It is a server-side language: the code runs on the web server, not in the browser. A .php file is mostly ordinary HTML. The PHP parts sit inside PHP tags, and only those parts are executed. Everything outside the tags is copied to the output as it is.

  1. The browser asks Apache for pay.php.
  2. Apache sees the .php ending and passes the file to the PHP interpreter.
  3. PHP runs the code between the PHP tags. HTML outside the tags is output unchanged.
  4. echo writes text into that output.
  5. Apache sends the finished HTML to the browser. The browser never receives the PHP source.

A statement ends with a semicolon. echo "Hi"; prints Hi. print does the same and returns 1. Comments run from // or # to the end of the line, or sit between /* and */ for a block.

<?php
// first PHP block
echo "Hello, Chennai";
?>

Output

Hello, Chennai

Variables are $ names; constants do not change

Variables in PHP begin with a dollar sign. After the $, the name starts with a letter or underscore, then letters, digits or underscores. $price, $total_1 and $_name are valid; $1price is not. Names are case-sensitive: $price and $Price are two different variables.

You do not declare a type; a variable simply takes the type of its current value. This is loose typing. For example, $price = 250; makes an int, and a later $price = "costly"; makes a string. PHP also converts values automatically inside expressions, for example "250" * 2 gives 500; that automatic conversion is called type juggling. A non-numeric string does not safely become a number, so keep numbers as numbers.

Constants hold a value that cannot change. Write define("GST_RATE", 0.18); or const GST_RATE = 0.18;. The name has no $ when used: $gst = $total * GST_RATE;. Constants are global and are useful for rates, limits and version numbers.

Data types and operators

PHP has eight data types. bool is true or false. int is a whole number such as 250. float is a decimal such as 0.18. string is text such as "Chennai". array is an ordered map that holds many values (see 4.3). object is an instance of a class. resource is a handle to something external, such as an open file. NULL means no value. is_int($x), is_float, is_string, is_array, is_null and similar functions test a value. Casting changes the view: (int) "250" gives 250, (string) 250 gives "250", and (bool) 0 gives false.

  • Arithmetic: + - * / % and ** for power. 7 / 2 gives 3.5; 7 % 2 gives 1.
  • Assignment: =, +=, -=, *=, /=, .=.
  • Comparison: == equal after type juggling; === equal in value and type; !=, <>, !==, <, >, <=, >=, <=>.
  • Logical: &&, ||, !. The words and, or, xor also exist but bind loosely.
  • String concatenation uses a dot: "Pay: " . $pay, not +.
  • Increment and decrement: ++$x, $x++, --$x, $x--.
  • Ternary: $ok ? "yes" : "no".
  • Null coalescing: $name ?? "guest" returns the left side if it is set and not null, otherwise the right side.
  • Spaceship: $a <=> $b returns -1, 0 or 1.

Precedence decides order: ** first, then * / %, then + -, then comparison, then &&, then ||. Use brackets when unsure. The big trap is == versus ===: 0 == "0" is true, but 0 === "0" is false. In current PHP, concatenation binds more loosely than + and -, so write "Total: " . ($a + $b).

Exam traps

  • Using + to join strings. "Pay: " + 885 does not join text: PHP tries to add, and in PHP 8 it stops with a TypeError because "Pay: " is not numeric. Use the dot: "Pay: " . 885.
  • Using == where === is needed. 0 == "0" is true, but the two values have different types, so 0 === "0" is false.
  • $price and price are different. A missing $ turns a variable into a constant name or an error.
  • Forgetting the semicolon at the end of a PHP statement.
  • Assuming a numeric string is an int. is_int("250") is false even though "250" * 2 works.

4.2 Server setup: XAMPP, Apache, Tomcat and IIS

A PHP file is only text until a web server hands it to a PHP interpreter. A Java servlet needs a container that starts it and calls it for each request. XAMPP is a free package that puts Apache, PHP, MySQL or MariaDB and Perl on one laptop, with a control panel to start and stop them. Developers use it to run and test code on localhost before uploading to a hosted server. Some syllabi call this environment setup.

You need: Unit 1's client-server and web-server ideas, and 4.1 for what a .php file contains.

XAMPP: one package for a laptop

XAMPP installs four parts: Apache is the web server, MySQL or MariaDB is the database, PHP is the server-side language, and Perl is included for older scripts. The control panel is a small program that starts and stops Apache and MySQL; it is not itself a web server. A green label means the service is running. The control panel also shows the Apache and PHP version numbers. On Windows the usual install folder is C:/xampp.

The document root is the folder whose files Apache serves. In XAMPP it is htdocs, so C:/xampp/htdocs/shop/pay.php is requested as http://localhost/shop/pay.php. The folder shop becomes part of the URL path. MySQL listens on port 3306 by default, and PHP connects to it with an extension such as mysqli or PDO.

Two text files control the setup. php.ini holds PHP settings: error display, upload size, and which extensions load. httpd.conf holds Apache settings: the port in a Listen line, the DocumentRoot, and module loading. After editing either file, restart the service from the control panel.

Apache: ports, modules and virtual hosts

Apache is an HTTP server. It listens on a port: 80 for http and 443 for https with TLS. A URL path is mapped under the document root; static files are sent directly, while a .php request is passed to PHP. Apache can run PHP as a module inside its own process, or send the request to a separate FastCGI process. XAMPP usually loads the module; IIS uses FastCGI.

A module is an optional feature loaded at start. mod_ssl adds HTTPS, mod_rewrite rewrites URLs, and mod_proxy forwards requests. Each has a LoadModule line in httpd.conf.

A virtual host lets one Apache serve several site names on the same IP and port. The browser sends a Host header, and Apache picks the matching VirtualHost block with its ServerName and DocumentRoot. localhost is a name for the loopback address 127.0.0.1; the hosts file resolves it before DNS. Only one program can listen on a given address and port. If another program already uses 80, Apache fails to start. Change Listen 80 to another port in httpd.conf, or stop the other program. A non-default port must appear in the URL, as in http://localhost:8080/.

Tomcat for servlets, IIS for Windows PHP

Tomcat is a servlet container and JSP engine. It runs Java servlets and JSP pages; it does not run PHP. Its default connector port is 8080. The webapps folder is where web applications live. A folder shop with a WEB-INF folder is a web application, reached at http://localhost:8080/shop/. A WAR file is a zipped web application: copy shop.war into webapps, and Tomcat unpacks it on start. The connector port is set in server.xml.

IIS is Microsoft's web server for Windows. It listens on port 80 by default. It does not run PHP natively; install PHP and add a FastCGI handler that runs php-cgi.exe. IIS organises sites with bindings and application pools. A site whose root is the project folder can serve http://localhost/pay.php.

Port conflicts are the common failure. Apache and IIS both default to 80, so they cannot both use the same address and port. Tomcat uses 8080, and MySQL uses 3306. Use netstat to see which program holds a port. The hosts file, at C:/Windows/System32/drivers/etc/hosts on Windows or /etc/hosts on Linux and macOS, maps names such as localhost to 127.0.0.1.

Worked example

Question. A Windows laptop runs XAMPP at C:/xampp. The file C:/xampp/htdocs/shop/pay.php must be opened in a browser, and a shop.war is deployed to Tomcat. Give the two URLs and their ports. Port 80 is already used by another program: what do you change?

  1. XAMPP's document root is C:/xampp/htdocs. The file lies in the shop folder under it, so its URL path is /shop/pay.php. Apache listens on port 80 by default, and 80 is the default for http, so no port is written: http://localhost/shop/pay.php.
  2. Tomcat listens on port 8080 by default. A file shop.war in webapps becomes the context /shop, so the servlet URL is http://localhost:8080/shop/. The port 8080 must be written because it is not the default for http.
  3. If port 80 is taken, Apache cannot bind to it. Stop the other program, or change Listen 80 to another free port in httpd.conf. If Apache takes 8080, Tomcat must move its connector to a different free port in server.xml, because two programs cannot share one port.

Answer. The PHP page is http://localhost/shop/pay.php on port 80; the servlet application is http://localhost:8080/shop/ on port 8080.

Exam traps

  • Calling Tomcat a PHP server: Tomcat runs servlets and JSP, not .php files.
  • Putting PHP files in Tomcat's webapps folder: XAMPP serves PHP from htdocs.
  • Mixing up php.ini and httpd.conf: the first sets PHP options, the second sets Apache's port and document root.
  • Thinking localhost is a folder: it is a hostname for 127.0.0.1, resolved through the hosts file.
  • Changing Listen 80 in httpd.conf and expecting Tomcat's 8080 port to move too; the Tomcat connector is set in server.xml.

4.3 PHP decisions, loops, functions and arrays

PHP control statements choose and repeat work. An if picks a branch, a loop repeats a block, and a function wraps a block under a name with its own scope. An array stores many values under keys, and foreach walks them in order. These four ideas turn a static page into server-side logic: a UPI payment page checks a status code, prints a message, and lists the last five transactions. Some syllabi call this decision making and loop controls.

You need: Chapter 4.1 for PHP syntax, dollar-prefixed variables, data types and operators.

Decisions: if, switch and match

An if statement runs a block when its condition is true. The condition is any expression that evaluates to true or false. elseif is tested only when the earlier conditions were false. else is the default branch and has no condition. PHP also has a short ternary form, but the full if is clearer for more than one branch.

switch compares one expression with case labels. The comparison is loose (==) by default, so "1" and 1 can match. Each case should end with break; without break, control falls through to the next case. default runs when no case matches.

PHP 8 added match. It compares with strict identity (===), returns a value, and needs no break. A match arm is value => result. If no arm matches, match throws an error unless a default arm exists.

Use decisions for validation: a form field is empty, a UPI status is "SUCCESS", or a mark crosses 40. Keep conditions simple; move a long test into a function.

Loops: while, do-while, for and foreach

while tests its condition before each pass. If the condition is false at the start, the body never runs. do-while tests after the body, so the body runs at least once. for packs init, condition and update into one line. Use for when the number of passes is known; use while when it is not.

foreach walks an array. It visits each key => value pair once, in insertion order. The loop variable is a copy; changing it does not change the array unless you write &$value. Remove the & after the loop.

break leaves the loop or switch at once. continue skips the rest of the current pass and goes to the next pass. In a for loop, continue still runs the update expression. A loop that never changes its condition is infinite; PHP stops at max_execution_time.

Example: for ($i = 1; $i <= 5; $i++) prints 1 to 5. The init runs once, the condition is checked before every pass, and the update runs after every pass.

Functions, scope and recursion

A function is a named block. Parameters are inputs; default values make an argument optional. return sends a value back and ends the function at once. A function without return gives null.

Each function has its own scope. A variable made inside is local and disappears on return. It cannot see an outside variable unless that variable is passed as a parameter or declared global. global $x; links to the global $x. A static variable keeps its value between calls: static $count = 0; $count++.

Recursion is a function that calls itself. Every recursive function needs a base case that stops the chain, and a recursive case that moves toward the base. For a positive integer n, fact(n) = n × fact(n − 1) with base fact(1) = 1. Another example is Fibonacci: fib(1) = 1, fib(2) = 1, fib(n) = fib(n − 1) + fib(n − 2). Fibonacci repeats work, so it is slower than the loop version for large n.

Arrays: indexed, associative and multidimensional

A PHP array is an ordered map: each value has a key. An indexed array uses keys 0, 1, 2, ...; PHP fills them when you write $a = [10, 20, 30]. An associative array uses string or integer keys you choose, such as ["name" => "Asha", "city" => "Pune"]. A multidimensional array is an array whose values are arrays; use $marks["math"][0] to reach an inner cell.

count($a) returns the number of elements. array_push($a, $x) adds $x at the end. array_keys($a) returns an array of all keys. in_array($x, $a) returns true if value $x is present. sort($a) sorts values in ascending order and resets keys; it returns true, not the sorted array.

foreach ($a as $v) gives each value. foreach ($a as $k => $v) gives each key and value. Use the key form when the key carries meaning, as in an associative array of prices. Form arrays such as $_POST come in Chapter 4.5.

  5. fact(5) = 5 × fact(4) = 5 × 24 = 120.

Exam traps

  • A recursive function with no base case recurses until PHP runs out of memory or hits a stack limit. Always write and test the base case first.
  • A function cannot read an outside variable by default. Pass it as a parameter or declare global $name inside the function; otherwise PHP reports an undefined variable.

  • foreach by value gives a copy. To change elements, use foreach ($a as &$v) and unset($v) after the loop, or loop by key.

4.4 String processing and regular expressions

PHP strings hold text from forms, files and databases. Built-in functions measure, cut, replace, split, join, format and escape that text. Regular expressions describe a pattern, and PHP's PCRE functions test or rewrite a string against it. You use them to clean a phone number, check an email or date, and escape output before it reaches the browser. The same ideas appear in every server-side language, but PHP's function names and pattern syntax are what you write in this unit.

You need: 4.1 for variables and strings, and 4.3 for functions and arrays.

PHP string functions

PHP strings are byte sequences. Each function returns a new value; assign it to change the variable.

  • strlen($s) returns the number of bytes. For ASCII text, bytes equal characters.
  • strpos($h, $n) returns the first position of $n in $h, or false. Position 0 is a real match, so compare with !== false.
  • substr($s, $start, $len) cuts a piece; str_replace($a, $b, $s) replaces every $a with $b.
  • strtolower, strtoupper, ucfirst change case; trim($s) removes whitespace at both ends: spaces, tabs, vertical tabs, newlines, carriage returns and NUL bytes.
  • explode($d, $s) splits a string into an array at delimiter $d; implode($g, $arr) joins array items with glue $g.
  • sprintf("%.2f", $price) formats a number to two decimals. htmlspecialchars($s, ENT_QUOTES, 'UTF-8') turns &, <, >, " and ' into HTML entities. nl2br($s) inserts
    before each newline.

Example: $parts = explode(" ", "98765 43210") gives two items. implode("", $parts) joins them back. For Indian text, bytes differ from characters; use mb_* functions when needed.

PCRE patterns

PCRE means Perl Compatible Regular Expressions; PHP uses it for pattern matching. A pattern sits between delimiters, usually slashes: /pattern/. preg_match($pat, $s) returns 1 if found, 0 if not, and false on error. It stops at the first match. preg_match_all returns the number of matches. preg_replace($pat, $rep, $s) returns a new string with matches replaced. preg_split($pat, $s) splits by a pattern.

^[6-9]\d{9}$

^ is the start anchor; [6-9] is one digit from 6 to 9; \d is any digit 0–9; {9} repeats exactly nine times; $ is the end anchor.

  • Anchors: ^ start, $ end. Without them, a match inside a longer string also returns 1.
  • Classes: [6-9] one digit from 6 to 9; \d digit, \w word character (letter, digit, underscore), \s space, tab or newline.
  • Quantifiers: * zero or more, + one or more, ? zero or one, {9} exactly nine.
  • Groups (...) and alternation |: /(cat|dog)/ matches either word.
  • Modifiers after the closing slash: i ignores case, m makes anchors match at line breaks, u treats the string as UTF-8.

Use single-quoted PHP strings for patterns: '/^[6-9]\d{9}$/'. In a double-quoted string PHP interprets escapes such as \n, \t, \\ and \1, so a pattern containing a backslash-digit sequence or a literal backslash can change; single quotes pass the pattern to PCRE unchanged.

Validation and safe output

Validation checks the shape of user input before it reaches the database or a page. Clean first, then test, then escape when printing.

  1. Read the field, for example $phone = $_POST['phone']. Form handling is in 4.5.
  2. Remove spaces with preg_replace('/\s+/', '', $phone); this turns 98765 43210 into 9876543210.
  3. Test the whole string with preg_match('/^[6-9]\d{9}$/', $phone). Use === 1 for valid.
  4. For email, a simple pattern is /^[^@\s]+@[^@\s]+\.[a-z]{2,}$/i. It checks one @, no spaces, and a dot in the domain; it does not prove the mailbox exists.
  5. For a date, /^\d{4}-\d{2}-\d{2}$/ checks only the shape YYYY-MM-DD. It accepts 2024-99-99; use checkdate($m, $d, $y) for a real calendar date.
  6. Escape every user string before HTML output: echo htmlspecialchars($name, ENT_QUOTES, 'UTF-8');. This blocks script injection in the page.

Regular expressions match patterns; they are not a full HTML parser. Do not use one regex to read nested tags. Use DOMDocument or an HTML parser for that job.

4.5 Form processing with GET and POST

A form collects values in input controls and sends them to a server script as name=value pairs. The method decides where the pairs travel: GET appends them to the URL as a query string, POST puts them in the request body. PHP exposes the first in $_GET and the second in $_POST. This is how a login, a marks lookup or a UPI payment request reaches server code. The rule is simple: GET for reading, POST for secrets and changes.

You need: HTML forms from Unit 2 (input names and submit buttons), HTTP methods from Unit 1, and PHP arrays from 4.3.

One form, two places for the pairs

A form is a set of controls inside <form action='result.php' method='post'>. The action is the URL of the script. The method is the HTTP method: get or post. Each control that has a name sends one name=value pair when the user presses the submit button. A control without a name is not sent.

With method='get', the browser puts the pairs after a ? at the end of the action URL. Pairs are joined by &. Spaces and special characters are percent-encoded. A form with name=Anu and marks=78 sent to result.php becomes result.php?name=Anu&marks=78. The URL is visible, bookmarkable and can be cached.

With method='post', the same pairs go into the request body, not the URL. The browser sends POST /result.php and a body such as name=Anu&marks=78, usually with Content-Type: application/x-www-form-urlencoded. The URL stays clean, but the request is not bookmarkable in the same way.

GET is for reading. A GET is safe (it should not change data on the server) and idempotent (sending it twice leaves the server in the same state as sending it once). POST is neither safe nor idempotent in general. POST is for changes and secrets: login passwords, payment confirmations, inserting a record. URL length is limited by browsers and servers, so GET is not for large data. A file upload needs enctype='multipart/form-data'; file storage is outside this chapter.

PHP reads GET, POST and the request method

PHP fills two superglobal arrays from the request. $_GET holds pairs from the query string; $_POST holds pairs from the body. The key is the control name. If the form sends name=Anu, then $_POST['name'] is 'Anu'. If the same form used GET, $_GET['name'] is 'Anu'. Values arrive as strings unless a filter converts them.

$_REQUEST merges GET, POST and (depending on the request_order setting) cookies, in an order set by configuration. With the common default order 'GP' a query-string value overrides a POST value of the same name, and cookies are left out. Read $_GET or $_POST instead. Cookies are covered in 4.6.

Three checks make input safe. isset($_POST['marks']) is true when the key exists and is not null. empty($_POST['marks']) is true for missing, '', '0', 0 and null, so it is not a good marks check. filter_input(INPUT_POST, 'marks', FILTER_VALIDATE_INT) returns the integer when the value is a valid integer, false when the value is present but not a valid integer, and null when the field is missing. Check for null as well as false. For GET use INPUT_GET.

$_SERVER['REQUEST_METHOD'] is 'GET' or 'POST'. A script can send the form to itself and branch on this value. That is a self-submit: first request shows the form, second request processes it.

Validate before use. Marks must be an integer from 0 to 100. Escape before printing: htmlspecialchars($name, ENT_QUOTES, 'UTF-8') turns < into &lt; and stops script injection. After a successful POST, send header('Location: thanks.php') and exit so a refresh does not resend the data.

A safe processing order

  1. Show the form with method='post' and action pointing to the processing script, or to the same script.
  2. If REQUEST_METHOD is POST, read each field with filter_input, or with isset plus validation.
  3. Reject bad values; keep the error and show the form again.
  4. Escape every value before printing it in HTML.
  5. On success, redirect with header('Location: ...') and exit.
  6. For uploads, set enctype='multipart/form-data' and read $_FILES; storage is not covered here.

The order matters. Validate raw input, then escape for output. Redirect after POST prevents duplicate inserts when the user refreshes. Never put a password in a GET URL: it enters browser history, server logs and the Referer header sent to other sites. A POST body is not shown in the URL, but it is still untrusted input, and it is plain text on the network; use HTTPS so the whole request is encrypted.

4.6 Cookies and session tracking

A web server treats every HTTP request as a stranger. Login on one page means nothing on the next; HTTP carries no memory. Cookies and sessions restore memory. A cookie is a small name=value pair the server asks the browser to keep and resend. A session keeps data on the server and gives the browser only an ID. Shopping carts, UPI logins and IRCTC bookings use this pair. This chapter shows PHP calls for both, and settings that stop leaks.

You need: HTTP request and response headers (see Unit 1, HTTP and HTTPS: URLs, requests, responses and methods) and form handling from 4.5 Form processing with GET and POST.

Cookies: state kept in the browser

A cookie is a small name=value string. The server sends it in a Set-Cookie response header. The browser stores it and attaches it in a Cookie request header to later requests to the same site. That round trip is the mechanism. Some syllabi call this state management or session tracking.

setcookie(name, value, expires, path, domain, secure, httponly)

name is the cookie name; value is its text; expires is a Unix timestamp in seconds (time()+1800 means 30 minutes from now); path is the URL prefix that receives it, "/" for the whole site; domain limits it to one domain; secure=true sends it only over HTTPS; httponly=true hides it from JavaScript. Later arguments may be left out. SameSite cannot be passed positionally; set it with the options array, for example setcookie('user', 'Anu', ['expires' => time()+1800, 'path' => '/', 'httponly' => true, 'samesite' => 'Lax']).

PHP reads a cookie back from $_COOKIE, for example $_COOKIE['user']. The array is filled from the request header before your script runs.

To delete a cookie, send it again with an expiry in the past: setcookie('user', '', time() - 3600, '/'). The browser then drops it. Setting an empty value alone does not delete it.

  • A cookie holds about 4 KB and a browser keeps a few dozen per site, so store an ID, never a whole cart.
  • setcookie writes a response header, so it must run before any output, including a blank line or a space before <?php.

Sessions: state kept on the server

A session flips the idea. The data stays on the server, and the browser gets only a random key called the session ID. The server keeps a small file (or a database row) per ID holding that visitor's values.

  1. The script calls session_start() before any output.
  2. PHP looks for the session cookie in the request. If none exists, it creates a random ID and sends it back as a Set-Cookie header. The default cookie name is PHPSESSID.
  3. You read and write the session array: $_SESSION['user'] = 'Anu';.
  4. At the end of the script PHP saves $_SESSION back to the session store under that ID.
  5. The next request carries the same cookie, so session_start() finds the same store and your $_SESSION values are there again.

session_id() returns the current ID as a string. session_regenerate_id(true) issues a fresh ID, copies the data to it and deletes the old one; call it right after a successful login, so an ID known to an attacker becomes useless.

session_destroy() deletes the stored data. The cookie may remain in the browser, so also clear $_SESSION and expire the cookie if the logout must be complete.

Old session files are removed by garbage collection. On some requests PHP runs a clean-up that deletes files untouched for gc_maxlifetime seconds, by default 1440 seconds (24 minutes). The trigger is random, set by gc_probability divided by gc_divisor. This is why a session can vanish without anyone calling session_destroy().

Keeping cookies and sessions safe

  • httponly = true stops JavaScript from reading the cookie, so an XSS bug cannot steal the session ID. See Unit 6, Authentication and web security.
  • secure = true sends the cookie only over HTTPS. Without it, the browser would also send the cookie on a plain-HTTP request, where anyone sharing the Wi-Fi can read the header.
  • samesite = "Lax" or "Strict" stops another site from triggering a request that carries your cookie, which blocks most CSRF attacks.
  • A cookie is plain text, not encrypted. It travels in a header anyone on the path can read. Never put a password, an OTP, a card number or a secret in it.
  • Session fixation: an attacker plants a known session ID, waits for the victim to log in, then reuses the ID. session_regenerate_id(true) after login defeats it.
  • In PHP 7.3 and later use session_set_cookie_params([...]) before session_start() to set these flags for the session cookie itself.

4.7 Java Servlets: life cycle, request and response

A servlet is a Java class that answers HTTP requests inside a servlet container such as Tomcat. The container creates one object, calls init() once, service() for every request, and destroy() at shutdown. You write doGet() or doPost() to read parameters, headers and sessions, then write HTML or JSON back. This design gives Java web applications a single shared object with container-managed setup and cleanup. Servlets are the base under JSP, JSF and many Spring Boot request paths.

You need: Java classes and objects, the HTTP request and response model from Unit 1, Tomcat setup from 4.2, and session tracking from 4.6.

Life cycle: one object, many requests

A servlet is a Java object whose life the container controls. Tomcat loads the class and creates exactly one instance for a mapping. After construction, the container calls init(ServletConfig) once, before the first request. Put one-time setup there, such as a database pool or a configuration value. Then service() runs for every request. HttpServlet.service() reads the HTTP method and calls doGet(), doPost(), doPut() and so on. At shutdown or undeploy, destroy() runs once.

Map the servlet in code with @WebServlet("/greet"), or in web.xml with servlet and servlet-mapping entries. Older containers use javax.servlet imports. Newer containers use jakarta.servlet. A class with the wrong import package is not a servlet for that container and fails to load.

The container uses one thread per request on the one servlet object. Instance fields are shared by all those threads. A field such as String userName can show one user's data to another user. Keep per-request data in local variables or request attributes. Use a synchronized block only for a true shared counter, and expect lower throughput.

Reading a request and writing a response

Write a servlet by extending HttpServlet. The usual methods are protected void doGet(HttpServletRequest req, HttpServletResponse res) throws IOException, ServletException and the same signature for doPost. HttpServletRequest gives getParameter("name"), which returns a String or null. For an application/x-www-form-urlencoded form POST, Tomcat parses the body and getParameter still works. For multipart/form-data, add @MultipartConfig or read parts with getPart(). Use Integer.parseInt() for numbers. getParameter returns null if the parameter is missing, so check for null and catch NumberFormatException before using Integer.parseInt().

Read headers with getHeader("User-Agent") and the method with getMethod(). On the response, call setContentType("text/html;charset=UTF-8") before getWriter(). The writer is a PrintWriter; out.println() writes the body. setStatus(404) or sendError(404, "Not found") sets the status. Do not write to the writer after a forward.

GET puts data in the URL, so it suits reads and bookmarkable pages. POST puts data in the body, so it suits form submissions and changes. If a servlet overrides only doPost, a GET reaches the default doGet, which returns 405 Method Not Allowed. The client sends the HTTP method in the request line. service() reads it and dispatches to the matching doXxx() method; your code never calls doGet() or doPost() itself.

Forward, redirect, parameters and session

A forward stays on the server: req.getRequestDispatcher("/view.jsp").forward(req, res) sends the same request and response objects to another resource. The browser URL does not change. A redirect sends 302 to the browser: res.sendRedirect("next"). The browser makes a new request, the URL changes, and request attributes are lost. Use forward for MVC views; use redirect after a POST so refresh does not resubmit.

Init-params belong to one servlet: getServletConfig().getInitParameter("db"). Context-params belong to the whole web app: getServletContext().getInitParameter("db"). Init-params are set in web.xml or with @WebInitParam inside @WebServlet. Context-params have no annotation; set them in web.xml with <context-param>, or at startup in a ServletContextListener using getServletContext().setInitParameter(). Both reach your code as strings.

For login state use HttpSession session = req.getSession(true), then session.setAttribute("user", name). The session ID travels in a cookie, as in 4.6. Session attributes are shared across requests from the same browser, so guard mutable objects. Remove with removeAttribute or invalidate() at logout.

Answer. One request prints Anu scored 78; across three requests init() runs 1 time, service() runs 3 times, and destroy() runs 1 time.

Exam traps

  • Putting per-user data in an instance field of the servlet. The container has one servlet object, so all requests share that field.
  • Expecting doPost to run for a GET. service() dispatches by HTTP method, and the default doGet returns 405.
  • Calling getWriter() before setContentType(). Set the content type and charset first.
  • Confusing forward with sendRedirect. Forward keeps the URL and request attributes; redirect starts a new request in the browser.
  • Mixing javax.servlet and jakarta.servlet imports. A container accepts only one package name.

4.8 JSP and JSF for dynamic pages

A JSP is an HTML page with Java inside. The container translates it into a servlet on first request, compiles it once, then reuses that servlet. You write the page, not println lines. JSF declares inputs and buttons as components, binds them to Java beans, and writes and reads HTML for you. Only a few universities still teach JSP and JSF; most new work uses Spring or React.

You need 4.7 for the servlet life cycle and HTML forms.

From hello.jsp to a running servlet

hello.jsp is plain text. On first request the container translates it to hello_jsp.java, which extends a JSP base servlet, compiles it to hello_jsp.class, loads it, and creates one instance.

  1. translate hello.jsp → hello_jsp.java
  2. compile → hello_jsp.class
  3. load, jspInit() once
  4. _jspService() per request
  5. jspDestroy() at shutdown

This is the life cycle of 4.7 with two renamed methods.

Directives configure the page. <%@ page import="java.util.*" %> sets imports, content type or session use. <%@ include file="header.jsp" %> copies a file at translation time; <jsp:include page="..." /> runs at request time. <%@ taglib %> declares a tag library.

Scriptlets, implicit objects, EL and JSTL

Three tags carry Java: scriptlet <% %>, expression <%= %>, declaration <%! %>.

Nine implicit objects exist. Main five: request, response, out, session (see 4.6), application; rest are config, page, pageContext, exception.

EL reads values: ${param.name} is a parameter, ${sessionScope.user} a session attribute. JSTL: <c:forEach> loops, <c:if test="..."> decides, <c:out value="..." /> prints with HTML escaping.

MVC and the JSF component tree

A JSP should only display. A servlet controller reads parameters, calls model classes, stores results as request attributes, then forwards with request.getRequestDispatcher("/show.jsp").forward(request, response). The JSP prints ${student.marks}.

JSF builds on servlets. A Facelet (.xhtml) uses h: tags and the framework builds a component tree, one object per input/button. <h:inputText value="#{marksBean.name}"/> calls getName() when rendering and setName() on submit.

A JSF request has six phases: restore view, apply request values, process validations, update model values, invoke application, render response. required="true" is checked in phase three; on failure phases four and five are skipped, so your action never runs and the page redraws with the message.

4.9 Spring Boot REST services with JPA

Spring Boot builds a web service you start with one command. It packs an embedded Tomcat inside your JAR, so you install no separate server. @RestController turns a Java method into a URL that answers JSON. Spring Data JPA turns a repository call into SQL against a real table. Teams use this stack for payment APIs, order services and mobile backends. Only a few universities teach it. You need servlet request and response and REST, JSON and databases (Unit 6).

You need: 4.7 Java Servlets, and Unit 6 REST, JSON and databases.

Starters and the embedded server

A Spring Boot project is a Maven project with a parent that fixes library versions. You add a starter, not a library: a starter is a bundle of dependencies tested together.

  • spring-boot-starter-web brings Spring MVC, Jackson for JSON, and embedded Tomcat.
  • spring-boot-starter-data-jpa brings JPA and Hibernate; the H2 or MySQL driver is added separately.
  • spring-boot-starter-test brings JUnit and Mockito.

The class carrying @SpringBootApplication is three annotations in one: @Configuration, @EnableAutoConfiguration and @ComponentScan. Its main method calls SpringApplication.run(App.class, args).

Auto-configuration reads application.properties. Set spring.datasource.url, spring.datasource.username and spring.datasource.password for the database. Add spring.jpa.hibernate.ddl-auto=update so Hibernate creates or alters tables.

Embedded Tomcat starts inside the same Java process, by default on port 8080. mvn package builds one runnable JAR, and java -jar app.jar starts the whole service on any machine with a JVM.

@RestController: one method, one URL

@RestController marks a class whose methods return data, not page names. Spring MVC maps the URL to a method, then Jackson writes the returned object as JSON.

The mapping annotation fixes the HTTP method: @GetMapping reads, @PostMapping inserts, @PutMapping and @DeleteMapping handle the rest. A path such as /api/students/{id} holds a stand-in.

  • @PathVariable Long id reads {id} from the URL and converts it to Long.
  • @RequestBody Student s reads the JSON body and converts it to a Student.
  • ResponseEntity<Student> carries body and status together: ResponseEntity.status(201).body(saved).

A plain returned object gets status 200. Use ResponseEntity when the status must differ, for example 201 after an insert.

Spring Data JPA: an interface that writes SQL

JPA maps a class to a table. @Entity marks the class, @Id marks the primary key, and @GeneratedValue(strategy = GenerationType.IDENTITY) lets the database supply the next id. The class needs a public no-arg constructor, because Hibernate builds instances by reflection.

A repository is an interface, not a class: interface StudentRepository extends JpaRepository<Student, Long>. The two type parameters are the entity and the id type. Spring writes the implementation at startup.

  • findById(1L) returns Optional<Student> and runs a SELECT by primary key.
  • findAll() runs SELECT * FROM student.
  • save(s) runs INSERT when the id is null and UPDATE when it is set.

For learning use H2 in memory: jdbc:h2:mem:testdb. For a real service use MySQL: jdbc:mysql://localhost:3306/college.

Worked example

Question. The table student has columns id, name and marks, and row (1, Anu, 78) exists. Write the entity, repository and controller for GET /api/students/1 and give the JSON. Then give the POST that adds Ravi with 65 marks, and its response.

@Entity
class Student {
  @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
  Long id;
  String name;
  int marks;
  Student() {}
  // getters and setters
}

interface StudentRepository extends JpaRepository<Student, Long> {}

@RestController
@RequestMapping("/api/students")
class StudentController {
  private final StudentRepository repo;
  StudentController(StudentRepository repo) { this.repo = repo; }

  @GetMapping("/{id}")
  Student one(@PathVariable Long id) {
    return repo.findById(id).orElseThrow();
  }

  @PostMapping
  ResponseEntity<Student> add(@RequestBody Student s) {
    Student saved = repo.save(s);
    return ResponseEntity.status(201).body(saved);
  }
}
  1. Entity Student: @Entity, @Id @GeneratedValue(strategy = GenerationType.IDENTITY) Long id, String name, int marks, and a no-arg constructor. Hibernate maps it to table student.
  2. Repository: interface StudentRepository extends JpaRepository<Student, Long>. Spring generates the class; findById(1L) becomes SELECT * FROM student WHERE id = 1.
  3. Controller: @RestController with @GetMapping("/{id}") and method Student one(@PathVariable Long id) { return repo.findById(id).orElseThrow(); }.
  4. Jackson writes the returned object as {"id":1,"name":"Anu","marks":78}. The method returned normally, so the status is 200.
  5. POST /api/students with body {"name":"Ravi","marks":65}: @RequestBody builds a Student, repo.save inserts the row, IDENTITY returns id 2, and ResponseEntity.status(201) sends 201 with {"id":2,"name":"Ravi","marks":65}.

Exam traps

  • An @Entity without @Id, or without a no-arg constructor, fails at startup; Hibernate also needs getters or field access, so pick one style.
  • JpaRepository is an interface. You never write new StudentRepository(); you inject it into the controller constructor.
  • Returning the entity leaks every column and can trigger lazy loading while Jackson writes JSON; a DTO is safer.
  • @Controller returns a view name, @RestController writes the body. Mixing them gives a rendered page or a 404, not JSON.
  • @PathVariable reads the URL, @RequestBody reads the JSON body. Swapping them gives a null field or a 400.

Takeaways

  1. A .php file is HTML with PHP islands; the server runs the islands and sends only the result.
  2. PHP variables are $names with no declared type, so the same name can hold an int and later a string.
  3. XAMPP is for learning on a laptop: Apache serves, PHP interprets, MySQL stores.
  4. Control statements and functions are the same ideas as in C or Java, but PHP arrays are ordered maps that foreach walks directly.
  5. Regular expressions move validation from long if-chains to one pattern string.
  6. GET puts form data in the URL, POST puts it in the body; a self-submitting page reads one or the other.
  7. Cookies live in the browser and are small; sessions live on the server and the browser keeps only the ID.
  8. A servlet is one object reused for many requests: the container calls init once, service per request, destroy once.
  9. JSP and JSF are built on top of the servlet API, not beside it.
  10. Spring Boot removes the external server step: the server is inside the JAR, and a controller method becomes a JSON endpoint.

Glossary

Constant
A name defined once with define() or const whose value cannot change afterwards.
Cookie
A small name=value string the server asks the browser to store and return on later requests to that site.
Dependency injection
A container creates an object's collaborators and passes them in, instead of the object creating them.
Deployment descriptor
The web.xml file that maps servlet classes to URL patterns and sets startup and session options.
Document root
The folder a web server treats as the top of the website, so a file there is reached by its path in the URL.
Indexed array
A PHP array whose keys are 0, 1, 2 … by default, like a list.
Interpreter
A program that reads code and executes it line by line instead of compiling it to a file first.
JPA
Jakarta Persistence API, the standard set of annotations and interfaces used for ORM in Java.
JSF
JavaServer Faces: a component-based Java web framework built on servlets.
JSON endpoint
A URL whose response is JSON data rather than an HTML page, usually consumed by a front end or app.
JSP
JavaServer Pages: an HTML file with Java pieces that the container translates into a servlet.
Managed bean
A Java object whose life cycle JSF controls and whose properties page fields read and write.
Operator precedence
The fixed order in which operators in one expression are evaluated, e.g. * before +.
ORM
Object-relational mapping: linking Java class fields to database table columns so you work in objects, not SQL strings.
PCRE
Perl Compatible Regular Expressions, the pattern flavour used by PHP's preg_* family.
PHP
A scripting language designed for web pages, embedded inside HTML inside <?php ?> tags.
Query string
The part of a URL after ?, holding name=value pairs joined by &.
Recursion
A function that calls itself on a smaller input, with a base case that stops the calls.
Request body
The part of an HTTP request after the headers that carries form data or other content.
Server-side scripting
Code that runs on the web server and sends only its output to the browser, so the source is never seen by the user.
Servlet
A Java class extending HttpServlet that the container calls to answer HTTP requests.
Session
Server-side storage tied to one visitor by a session ID, used for logins and carts.
Session ID
A long random string that links a browser's cookie to the right server-side session data.
Spring Boot
A Spring framework layer that auto-configures an application and starts an embedded server.
Superglobal
A PHP array such as $_GET, $_POST, $_COOKIE or $_SESSION that is available in every scope without a global keyword.
