3.1 JavaScript basics: variables, operators and control statements

JavaScript is the language a browser runs inside a web page. It lets a page react: read a value, compare it, choose a branch, repeat a step. A program is just a list of statements, run top to bottom. Variables hold values, operators combine values, and control statements decide which statements run. The same ideas power form checks, UPI payment buttons, and live cricket score widgets. This chapter covers the base syntax that every later JavaScript topic in this unit assumes.

You need: an HTML page from Unit 2 to hold the script, and the browser console from Unit 1 to read output.

A script in a page, output, and data types

Put JavaScript inside an HTML page in one of two ways. An inline script sits between <script> and </script>. An external file is loaded with <script src='app.js'></script>. Put the tag just before </body>, or add defer to an external script. defer downloads the file now but runs it after the HTML is parsed, in file order.

To see a value, use console.log(value); it prints to the browser console. alert(value) shows a popup. Use the console while debugging and alert only for a real user message.

JavaScript has these data types: number (72, 3.14), string ('C'), boolean (true, false), null (a deliberate empty value), undefined (a variable with no value yet), object (a collection; arrays are objects), symbol (a unique key), and bigint (a whole number written with n, like 10n). typeof value returns a string naming the type. Two quirks: typeof null is 'object', and typeof function is 'function'.

Automatic type coercion means JavaScript converts a value when an operator needs another type. '5' * 2 gives 10, because * forces numbers. '5' + 2 gives '52', because + joins strings when either side is a string. Arrays and objects are covered in <a href='#functions-arrays-and-objects'>3.2.

Variables and operators

Declare a variable with var, let or const. var is function scoped: a var inside a block leaks to the whole function, and it can be redeclared. let is block scoped: it exists only inside the nearest { }, cannot be redeclared in that block, and can be reassigned. const is block scoped and must be initialised; the name cannot be reassigned. Prefer const; use let only when the value changes. Avoid var in new code.

Arithmetic operators: + add, - subtract, * multiply, / divide, % remainder, ** power. Assignment operators store: =, +=, -=, *=, /=, %=. Comparison: >, <, >=, <=, ==, ===, !=, !==.

== converts types and compares value; === compares value and type with no conversion. So '5' == 5 is true, but '5' === 5 is false. Use === and !== unless you have a reason.

condition ? valueIfTrue : valueIfFalse

condition is any expression; valueIfTrue runs when condition is truthy; valueIfFalse runs when it is falsy.

Logical: && and, || or, ! not. Nullish: a ?? b returns b only when a is null or undefined. Difference: 0 || 5 gives 5, but 0 ?? 5 gives 0, because || treats 0 as false. Precedence: ** before * / %, then + -, then comparisons, then &&, then ||, then ?:, then assignment. Use parentheses to be clear.

Control statements and loops

if (condition) statement runs the statement when condition is truthy. Falsy values are false, 0, '', null, undefined and NaN. Everything else is truthy. Add else for the other path. Chain tests with else if: JavaScript checks from top to bottom and runs only the first true branch. The figure traces marks = 72 through an else-if ladder.

switch (expression) compares expression with each case value using ===. break exits the switch. Without break, control falls through into the next case. default runs when no case matches.

Loops repeat. for (let i = 1; i <= 5; i++) runs init once, tests before each pass, and updates after each pass. while (condition) tests first. do { ... } while (condition) runs the body once, then tests. for (const x of array) walks values in order. break leaves the loop; continue skips to the next update or test. Changing the page itself is <a href='#document-object-model-and-dynamic-html'>3.4.

3.2 Functions, arrays and objects

A function is a named block of steps. You write it once and call it many times. An array is one variable that holds many values in a fixed order, reached by a number called an index. An object holds many values under names called keys. These three ideas let a program grow without repeating lines. A marks table, a shopping cart and a UPI payment record are all built from them. Every browser runs JavaScript, so you meet functions, arrays and objects in page scripts, in server code and in API replies.

You need 3.1 for variables, loops and operators, because a function body is built from those statements.

Functions name a block

A function is a named block of steps. Write it once, call it by name, and the same steps run again. In function average(a) { ... }, average is the function name and a is a parameter: a name in the definition that receives a value. The value you pass at the call, as in average(marks), is an argument.

A function declaration is the form above. A function expression stores a function in a variable: const average = function (a) { ... }; here the name average works only after this line. A declaration is hoisted, so the name exists before its line. A function expression is not hoisted; you must reach the assignment first.

return ends the function and sends a value back. A function with no return gives undefined, not the last value. Default parameters fill a missing argument: function area(l, w = 1) uses w = 1 when the second argument is missing or undefined. Rest parameters collect extra arguments into a real array: function sum(...nums) { /* nums is a real array */ }. Inside the body, nums is a real array.

Scope is where a name can be seen. A variable made inside a function is local to that function. Hoisting moves declarations to the top of their scope; it does not move the value assignment. Recursion is a function calling itself. For factorial, fact(n) returns n * fact(n - 1), with base fact(0) = 1. Arrow functions and classes are in 3.5.

Arrays keep order

An array stores many values in one variable, in order. A literal is let marks = [45, 72, 90, 38];. The length is marks.length, here 4. An index is a position number starting at 0. marks[0] is 45; the last index is length - 1, here 3.

push(x) adds to the end; pop() removes the end; shift() removes the start; unshift(x) adds to the start. splice(start, deleteCount, ...items) changes the original array. slice(start, end) copies a part into a new array, and end is excluded. concat joins arrays into a new array. join(sep) makes a string with sep between values. indexOf(x) gives the first index or -1; includes(x) gives true or false.

sort() without a comparator compares values as strings, so [10, 9, 1] becomes [1, 10, 9]. Use sort((a, b) => a - b) for numbers. A callback is a function passed to another function. map(callback) builds a new array by applying the callback to each value. filter(callback) keeps values where the callback returns true. reduce(callback, start) folds the array into one value, such as a sum. forEach(callback) runs for each value for a side effect and returns undefined. map and filter do not change the original array.

Objects hold named values

An object stores values under names called keys. A literal is let student = { name: 'Asha', marks: 88 };. Dot access is student.name; bracket access is student['name']. Use brackets when the key has a space or is held in a variable.

A method is a function stored as a property. A nested object is an object inside another. In let school = { topper: { name: 'Asha', marks: { math: 88 } } }; the object school.topper.marks sits two levels deep, and school.topper.marks.math gives 88. Object.keys(obj) returns an array of keys; Object.values(obj) returns an array of values; Object.entries(obj) returns an array of [key, value] pairs. delete obj.key removes a property.

new Date() gives the current date and time; getFullYear() gives the year, and getMonth() gives 0 for January to 11 for December. Math.round(x) rounds to the nearest integer. x.toFixed(2) writes a number with two decimal places and returns a string, which is right for printing money or marks, such as ₹61.25.

3.3 Events and event handling

A web page is not a still picture. The user clicks a button, types a letter, submits a form, or scrolls, and the browser tells the page. That signal is an event. An event handler is the JavaScript function you register to run when the signal fires. Events are how a page reacts without a reload, from a UPI 'Pay' button to a live search box. This chapter covers the terms, the three ways to attach a handler, the event object, default actions, and the capture–bubble path a single click travels.

You need: 3.1 and 3.2, because a handler is just a function you pass by name.

An event, a source, and a handler

An event is a signal from the browser that something happened: a click, a key press, a form submission, a page finishing load. The event source, also called the event target, is the object where it happened — a button, an input, the document, the window. A listener is the registration you make. A handler is the function that runs. One source can have many listeners for the same event.

  1. Inline attribute: <button onclick='pay()'>Pay ₹500</button>. The browser runs the string as code when the click fires. It is quick for a demo, but it mixes markup with logic, allows only one handler, and a strict Content-Security-Policy can block it.
  2. Element property: b.onclick = pay;. This stores one function in the property. A second assignment replaces the first.
  3. addEventListener: b.addEventListener('click', pay);. This adds to a list, so several handlers can listen to the same event on the same element. They run in the order added.

Remove with b.removeEventListener('click', pay);. You must pass the same function reference and the same capture option used when adding. removeEventListener('click', () => {}) removes nothing because the arrow is a new object. Keep a named function when you plan to remove it.

The event object, default actions, and the three phases

Every handler receives an event object. event.type is the event name, such as 'click'. event.target is the element where the event started. event.currentTarget is the element whose listener is running now; it can be an ancestor of the target. For a key event, event.key is 'Enter', 'a' or 'ArrowLeft'. For a mouse event, event.clientX is the horizontal distance in CSS pixels from the left edge of the viewport.

Some events have a default action: a link navigates, a form submit sends a request and reloads the page, a checkbox toggles. event.preventDefault() cancels that default. It does not stop other listeners. event.stopPropagation() stops the event from travelling to the next node on the path. It does not cancel the default action. Use it sparingly; it can break delegation and page analytics.

The browser builds a path from window down to the target. The event visits it in three phases. Capture: listeners registered with {capture:true} run from window down to the target's parent. Target: listeners on the target run. Bubble: ordinary listeners run from the target's parent back up to window. addEventListener('click', fn) without options listens in the bubble phase.

Delegation uses bubbling. Put one listener on a parent <ul> instead of one per <li>. In the handler, event.target.closest('li') finds the item that was clicked. This also works for items added after the listener was attached. The reverse direction — a child component telling its parent — is a React idea; see Unit 5.

Exam traps

  • Forgetting event.preventDefault() in a form submit handler. The browser sends the form and reloads the page, so your JavaScript output disappears. Call it for every AJAX form.
  • Expecting a parent's ordinary bubble listener to run before the child's target listener. The target runs first; the parent runs on the way back up.
  • removeEventListener fails silently if the function reference or the capture flag differs from the one used in addEventListener.
  • Mixing preventDefault() and stopPropagation(). The first cancels the browser default; the second stops the event path. One does not do the other's job.
  • Using change for live typing. For a text input, change fires when the field loses focus or the user presses Enter; input fires on every keystroke. For a <select>, change fires as soon as the choice changes.

3.4 Document Object Model and dynamic HTML

A browser does not keep your HTML as text. It parses the tags and builds a tree of objects in memory called the Document Object Model, or DOM. Each tag becomes an element node, each run of text becomes a text node, and each attribute becomes an attribute node. JavaScript can walk this tree, read it and change it. Every change appears on screen at once. That is dynamic HTML: one loaded page that updates itself — a cart count, a live score, a filtered product list — without a full page reload.

You need: Unit 2 (HTML tags and forms), 3.1 and 3.3.

The page becomes a tree

When the browser loads an HTML file it parses the tags from top to bottom. A tag becomes an element node; the text between tags becomes a text node; an attribute becomes an attribute node on its element. The result is the DOM, a tree with one root, document.

Under document is html. Its children are head and body. A node directly above another is its parent; nodes directly below are its children; nodes sharing a parent are siblings.

In the figure, document → html → body → h1#t and ul#items. The h1 has one text child, "Cart". The ul has one li child, and that li has the text child "Pen". White space between tags also makes text nodes; most tools ignore them.

The tree is live. Change a node and the browser repaints that part of the page. No HTTP request is needed.

Selecting and changing nodes

Five methods find elements. document.getElementById('t') returns the one element with id t, or null. getElementsByClassName('red') and getElementsByTagName('li') return a live HTMLCollection. document.querySelector('#items li') returns the first match for any CSS selector. document.querySelectorAll('#items li') returns a NodeList of all matches.

A NodeList looks like an array: it has length and index access. It is not an array. It has no map, filter or push. Use Array.from(list) or [...list] when you need array methods.

Read text with el.textContent: it returns the text of the element and all descendants, tags removed. Set it to replace those children with one text node. Use el.innerHTML only for real HTML: it parses the string, discards existing children and their listeners, and inserts the resulting nodes. A script tag inserted this way does not execute, but event-handler attributes such as onerror and javascript: URLs do fire, so untrusted text is still an XSS risk.

For inputs read input.value. For attributes use el.getAttribute('href') and setAttribute('href', '/cart'). For classes use classList.add('red'), remove, toggle, contains. Inline styles use camelCase and units: el.style.backgroundColor = 'gold'; el.style.width = '200px'.

Creating nodes and the BOM

To add a node: create, fill, attach. const li = document.createElement('li') makes a detached element. li.textContent = 'Tea' gives it text. ul.appendChild(li) makes it the last child. ul.insertBefore(li, ref) puts it before the child ref. li.remove() deletes a node. ul.replaceChildren(a, b) replaces all children with a and b.

The browser also gives objects outside the document, together called the BOM (Browser Object Model). window is the global object. window.location.href = '/login' navigates to another page. history.back() goes to the previous page; history.length counts entries. navigator.userAgent is a string naming the browser. screen.width is display width in pixels. alert, confirm and prompt show dialogs. setTimeout(fn, 500) runs fn once after 500 ms; setInterval(fn, 1000) runs it every 1000 ms until clearInterval.

Session data usually lives on the server; the browser stores a cookie holding the session id and sends it with every request to that site. See Unit 4.

3.5 ES6 features: let, const, arrow functions, classes, modules

ES6, also called ES2015, is the 2015 update to JavaScript that gave the language block-scoped names, short arrow functions, class syntax and file modules. Before it, var leaked across blocks and big programs shared one global script file. ES6 keeps each name near where it is used and splits a large app into small files. Modern browsers and Node.js accept it. You use it in every React component, every fetch call and every npm package in later units.

You need: 3.1, 3.2 and 3.4, because this chapter rewrites their code in ES6.

Block scope: let and const

var is function-scoped: a var name is visible in the whole function, even before its line. let and const are block-scoped: the name lives only inside the nearest { }. A block is any pair of braces, such as an if body, a loop body or a bare { }. This stops a loop counter from leaking into the rest of the function.

let allows reassignment but not re-declaration in the same block. const must be initialized when declared and cannot be reassigned. const does not freeze an object: const o = {}; o.x = 1; is legal, because const binds the name o to one object; the object's properties can still change. Object.freeze(o) stops adding, changing or deleting o's own properties; it is shallow, so objects held inside o can still change.

Both let and const are hoisted to the top of their block but stay in a temporal dead zone (TDZ) until the declaration runs. Reading one before that line throws ReferenceError. var instead reads as undefined. Prefer const by default, let when the value must change, and avoid var in new code.

Templates, destructuring, spread and arrows

Template literals use backticks, not quotes: `Hi ${name}`. The ${ } inserts a value and the literal may span lines. Destructuring copies values by pattern: const [a, b] = [1, 2]; and const {name, age} = user;. Rename with {name: n} and give defaults with {age = 18}.

Spread ... expands: [...arr] copies an array, {...obj} copies an object. Rest collects: function f(...args) puts extra arguments in args; const [first, ...rest] = arr puts the tail in rest.

An arrow function is shorter: const add = (a, b) => a + b;. One parameter may drop parentheses. A multi-statement body needs braces and return. An arrow has no own this or arguments; this comes from the enclosing scope. Do not use an arrow as an object method when the method needs the object's this; use a method shorthand or a normal function.

Classes, modules and the rest

Class syntax groups a constructor and methods. class Animal { constructor(name) { this.name = name; } speak() { return this.name; } static kind() { return 'animal'; } get label() { return this.name.toUpperCase(); } }. constructor runs on new. speak is a method. static kind() belongs to the class, not an instance. get label() is a getter read as a.label. In class Dog extends Animal { constructor(name) { super(name); } speak() { return this.name + ' barks'; } }, extends inherits and super(name) calls the parent constructor.

Modules split code into files. Named export: export const x = 1; export function f() {}; import: import { x, f } from './m.js';. Rename with import { x as y }. Default export: export default class App {}; import: import App from './App.js';. One module per file; many named exports, one default. In a browser, load the file as <script type="module" src="./m.js"></script>. A module has its own scope, runs deferred and is strict. Without type="module", import is a syntax error.

for (const v of arr) loops over values. new Map() stores key-value pairs with set, get, has. new Set() stores unique values. Enhanced object literals shorten code: const o = { x, method() {}, [key]: 1 };. Promises are named here only; their behaviour is in 3.6.

3.6 Asynchronous JavaScript: callbacks, promises and async/await

JavaScript has one call stack, so it runs one piece of code at a time. Slow work such as a timer or a network reply is handed to the browser, and JavaScript picks up the result later through queues and the event loop. This chapter shows the order: normal code first, then promise callbacks, then timer callbacks. You will use callbacks, promises and async/await to keep a page responsive while data loads. The same idea powers a UPI payment status check that updates without freezing the screen.

You need: 3.2 for callbacks and 3.1 for statements and expressions.

The stack, Web APIs and two queues

JavaScript runs on one call stack. A function call pushes a frame; a return pops it. The engine does one thing at a time, so if a function waits 2 seconds, nothing else on the stack runs. The browser helps by providing Web APIs: timers, network requests and DOM events. When such work finishes, its callback is not run immediately. It is placed in a queue.

There are two queues to know. The task queue (also called macrotask queue) holds timer callbacks and events. The microtask queue holds promise callbacks and queueMicrotask callbacks. The event loop follows one rule: run the stack until empty; drain every microtask; then take one macrotask. After each macrotask, microtasks drain again.

Timers use milliseconds (ms). setTimeout(fn, delay) schedules fn to run after at least delay ms. setInterval(fn, delay) repeats every delay ms. clearTimeout(id) and clearInterval(id) cancel them. A delay of 0 does not mean immediate: the callback still waits for the stack and all microtasks.

  • Task queue: timer callbacks, DOM events, network replies.
  • Microtask queue: promise .then, .catch, .finally callbacks.
  • Rule: stack empty → all microtasks → one macrotask → repeat.

Callbacks, callback hell and promises

A callback is a function passed to another function, to be called later. Event handlers are callbacks (see 3.3). Nesting many callbacks for sequential steps creates callback hell: deep indentation, repeated error checks and shared variables that are hard to follow.

A promise is an object for a future value. It has three states: pending (not settled), fulfilled (completed with a value) and rejected (failed with a reason). You create one with new Promise((resolve, reject) => { ... }) or with Promise.resolve(value).

then(onFulfilled) runs when fulfilled. catch(onRejected) runs when rejected. finally(fn) runs when settled, whatever the result. then returns a new promise, so calls chain. Returning a value fulfils the next promise; throwing rejects it.

Combinators handle many promises. Promise.all(list) fulfils with an array when all fulfil, and rejects on the first rejection. Promise.race(list) settles with the first promise to settle. Promise.allSettled(list) waits for all and gives each result as fulfilled or rejected.

async/await, errors and parallel requests

An async function always returns a promise. A returned value fulfils it; a thrown error rejects it. Inside it, await p pauses that async function until promise p settles. Other code still runs. Use try/catch around await to handle rejection.

Do not await independent requests one by one inside a loop. Start all promises first, then await Promise.all. If 3 requests each take about 200 ms, serial awaits wait about 600 ms; parallel waits about 200 ms, plus small overhead. This is the usual fix for a slow dashboard loading several cards.

To wait with a timer, wrap it: await new Promise(r => setTimeout(r, 1000)) waits at least 1000 ms. In a React component, async state initialization means starting the load and calling the state setter when it resolves; the first render shows a loading state (see Unit 5). Network calls with fetch are in 3.7.

3.7 AJAX, XMLHttpRequest and JSON

AJAX means Asynchronous JavaScript and XML. It is the trick of asking the server for data after the page has already loaded, then writing the reply into one part of the page. The page does not reload. Before AJAX, every click that needed new data sent the whole page to the server and got a whole new page back. With AJAX a small request goes out in the background and only one element changes. Search suggestions, a college portal's marks lookup, UPI balance refresh and IRCTC seat availability all run on this.

You need: 3.4 for writing into the page, and 3.6 for call-backs, so you understand that the reply arrives later.

The path from page to server and back

AJAX stands for Asynchronous JavaScript and XML. The name is old — XML was the usual reply format when the term was coined — but the idea is simple: ask the server for data after the page has loaded, and patch one part of the page with the reply.

Asynchronous is the important word. The browser sends the request and does not wait for it. The user keeps typing or scrolling, and a call-back function runs when the reply arrives. 3.6 explains how that call-back is queued.

  1. Create an XMLHttpRequest object. It is the browser's built-in messenger; your JavaScript never opens a socket itself.
  2. Call open() to set the HTTP method and the URL, then send() to transmit.
  3. The web server receives the request (HTTP is in Unit 1, Internet, Web and HTTP), runs its code, and replies with a status code and a body.
  4. The XHR object receives the reply and calls your function. You read the body, parse it, and write the result into the DOM with textContent (3.4). The page never reloaded.

The XMLHttpRequest object

Create one with new XMLHttpRequest(). Three calls then set it up.

  • open(method, url, async) — method is 'GET' or 'POST', url is the endpoint, async is true for AJAX. Passing false blocks the whole page until the reply arrives, so almost nobody does it.
  • setRequestHeader(name, value) — adds a request header. A form-encoded POST needs Content-Type: application/x-www-form-urlencoded.
  • send(body) — sends it. GET sends null; POST sends the encoded string, for example name=Ravi&marks=65.

GET reads, POST writes. Use GET when the call only fetches data, because GET replies can be cached and bookmarked. Use POST when data changes on the server or the payload is long.

JSON, and the modern fetch()

JSON is JavaScript Object Notation, a text format with three building blocks: objects {key: value}, arrays [a, b, c], and values (string, number, true, false, null). Its syntax has hard rules.

  • Every key is a double-quoted string.
  • Strings use double quotes, never single quotes.
  • No comma after the last item of an object or array.
  • No comments, no functions, no undefined, no NaN.

Two functions convert between text and live values. JSON.stringify(value) returns text, which is what you send to a server. JSON.parse(text) returns a value, which is what you do to responseText. 3.8 XML, DTD and XML Schema

XML writes data as a tree of tags. One root element holds nested elements, and attributes sit inside opening tags. A DTD or an XML Schema is a contract: it lists which elements and attributes may appear, in what order, and how many times. The contract lets two systems exchange a catalogue or a purchase order without guessing the shape. A DTD checks structure only. An XML Schema also checks types, so a price can be forced to be a number. This chapter writes both contracts for one bookstore record and tests a rupee sign against them.

You need Unit 2 for tag and attribute syntax, and 3.7 for XML as an AJAX reply.

XML: a tree with strict syntax

XML (Extensible Markup Language) stores data as a tree of elements. An element is a pair of tags with content between them: <title>Web Tech</title>. The opening tag may carry attributes, written name="value" inside the tag: <book id="b1">. Attribute values need quotes. Elements nest, and exactly one element is the root. XML is case sensitive: <Title> and <title> are different names.

An element with no content can be written as a single self-closing tag, <price/>, which is the same as <price></price>. The DTD content model EMPTY describes exactly this element.

An XML file may start with <?xml version="1.0" encoding="UTF-8"?>, which gives the version and character encoding. Comments are <!-- note -->. CDATA keeps text unparsed: <![CDATA[ a < b ]]>. Entities write reserved characters: the entity &lt; writes a less-than sign and &amp; writes an ampersand. A namespace declares a vocabulary: <b:book xmlns:b="urn:shop"> puts book in the b vocabulary, so two vocabularies do not clash.

A document is well-formed when it obeys these syntax rules: one root, matched tags, quoted attributes, no stray angle bracket. Well-formed is a syntax test. Valid is stronger: the document also follows a DTD or XML Schema that says which elements and attributes may appear, and in what order. HTML is a fixed tag language with forgiving parsing; XML lets you invent tags and demands strict parsing. Browsers parse XML with DOMParser, and AJAX replies appear as responseXML; see 3.7.

DTD: element and attribute rules

A DTD (Document Type Definition) is a grammar for XML. <!DOCTYPE bookstore SYSTEM "bookstore.dtd"> attaches an external DTD. <!ELEMENT bookstore (book+)> says bookstore contains one or more book elements. <!ELEMENT book (title, price)> says each book holds title then price, in that order. <!ELEMENT title (#PCDATA)> says title holds parsed character data, meaning plain text. EMPTY allows no content; ANY allows anything.

Occurrence symbols control counts: ? means zero or one, * zero or more, + one or more. No symbol means exactly once. <!ATTLIST book id ID #REQUIRED> declares id on book; ID means a unique name and #REQUIRED means it must be present. #IMPLIED means optional. A default value such as status CDATA "available" fills the attribute when it is missing.

A DTD sees every element value as text. In <!ELEMENT price (#PCDATA)>, the contents 350, ₹350 and abc are all character data. The DTD cannot say price must be a number, cannot check a date format, and cannot give a range. It checks structure only.

XSD: a schema with data types

XML Schema, usually called XSD (XML Schema Definition), is a grammar written in XML. It adds data types. The root is <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">. <xs:element name="bookstore"> starts a declaration; its <xs:complexType> holds child elements and <xs:sequence> fixes their order. <xs:element name="book" minOccurs="1" maxOccurs="unbounded"> allows one or more books; unbounded means no upper limit. Inside book, <xs:element name="title" type="xs:string"/> and <xs:element name="price" type="xs:integer"/> declare the children. <xs:attribute name="id" type="xs:ID" use="required"/> declares the attribute.

Built-in types include xs:string for text, xs:integer for whole numbers, xs:decimal for decimal numbers with or without a decimal point (350 and 350.50 are both valid xs:decimal values), and xs:date for YYYY-MM-DD dates. A simple type with a restriction narrows a built-in type: <xs:simpleType name="priceType"><xs:restriction base="xs:decimal"><xs:minInclusive value="0"/></xs:restriction></xs:simpleType> forbids negative prices. The element then uses type="priceType".

An XSD parser knows price has type xs:integer. It converts the text and tests the integer rules, so ₹350 fails. A DTD has no type slot; it only tests that text is present. That is why XSD can type-check and a DTD cannot.

Worked example

Question. An online bookstore sends one record: title "Web Tech", price 350, id "b1". (a) Write the XML. (b) Write a DTD that allows one or more books, each with a required title followed by a price, and a required unique id attribute. (c) Write an XSD fragment that forces price to be xs:integer. (d) Is <price>₹350</price> valid? Answer for well-formedness, DTD validity and XSD validity.

  1. XML: <?xml version="1.0" encoding="UTF-8"?> <bookstore> <book id="b1"> <title>Web Tech</title> <price>350</price> </book> </bookstore>. The root is bookstore; it holds one book element, which holds title then price.
  2. DTD: <!ELEMENT bookstore (book+)> <!ELEMENT book (title, price)> <!ELEMENT title (#PCDATA)> <!ELEMENT price (#PCDATA)> <!ATTLIST book id ID #REQUIRED>. The plus sign allows one or more books; the comma forces title before price; ATTLIST makes id required and unique.
  3. XSD fragment: <xs:element name="bookstore"><xs:complexType><xs:sequence><xs:element name="book" minOccurs="1" maxOccurs="unbounded"><xs:complexType><xs:sequence><xs:element name="title" type="xs:string"/><xs:element name="price" type="xs:integer"/></xs:sequence><xs:attribute name="id" type="xs:ID" use="required"/></xs:complexType></xs:element></xs:sequence></xs:complexType></xs:element>. The price element is forced to xs:integer.
  4. Test <price>₹350</price>. Well-formed: yes, with UTF-8 the rupee sign is an ordinary character and the tags match. DTD validity: yes, because price is #PCDATA and any text passes. XSD validity: no, because xs:integer allows an optional sign and digits only; ₹ is not a digit, so the value fails the integer type.

Answer. The record is well-formed and DTD-valid but not XSD-valid: ₹350 is not an xs:integer.

Exam traps

  • Well-formed and valid are not the same thing. A document with no DTD or schema can be well-formed but cannot be valid.
  • XML allows exactly one root element. Two top-level elements make the document not well-formed, so validity never gets tested.
  • A DTD treats every element value as text. It accepts <price>abc</price> and <price>₹350</price>; only an XSD type such as xs:integer rejects them.
  • XML is case sensitive. A DTD that declares price does not accept Price.
  • #REQUIRED makes a missing attribute an error. A default value does the opposite: it fills an attribute that is missing.

3.9 jQuery basics

jQuery is a small JavaScript library that wraps three common jobs — selecting elements, handling events and asking the server for data — into short calls that chain with dots. It exists because older browsers disagreed about the DOM and events, so the same code could fail on one browser and work on another. A student today meets it in legacy pages, in quick college projects and in plugins that still expect it. The core habit it teaches is: select a set, change the set, repeat. That habit carries into modern frameworks.

You need: <a href='#document-object-model-and-dynamic-html'>3.4 for DOM selection, <a href='#events-and-event-handling'>3.3 for events and <a href='#ajax-xmlhttprequest-and-json'>3.7 for AJAX.

The $ function and the jQuery object

jQuery is one .js file. Add it from a CDN before your own script, or use a local copy. The library defines a function named $, also written jQuery. With a string, $ selects.

<script src='https://code.jquery.com/jquery-3.7.1.min.js'></script>

$('#items li') asks for all li inside #items and wraps them in a jQuery object. The object is array-like: it holds matched DOM elements in order and adds methods such as .text() and .css(). It is not a DOM element.

$(document).ready(fn) runs fn after the DOM is built. The shorthand is $(fn). This is earlier than window.onload, which waits for images too.

Selectors are CSS selectors: tag, .class, #id, [attr='v']. jQuery adds its own extension selectors such as :input, which is not a CSS pseudo-class, and filters such as :first, :last, :even (0,2,4...), :odd. So $('#items li:first') is the first item.

Most methods return the same jQuery object. That is why calls chain. The set stays the same unless a method like .first() or .eq(1) narrows it.

Changing text, classes, elements and visibility

Getters and setters share one name. With no argument, .text() returns the text of the first element only. With an argument, .text('New') sets the text of every element in the set. The same pattern holds for .html() (markup), .val() (form field value), .attr('href') and .css('color','red').

Class methods: .addClass('sel'), .removeClass('sel'), .toggleClass('sel'). .data('id') reads a data-id attribute; .data('id', 7) stores a value in jQuery's data store.

Add and remove elements: .append(x) puts x inside at the end; .prepend(x) inside at the start; .before(x) and .after(x) outside; .remove() deletes the set and its events; .empty() deletes children only.

Effects: .hide(400), .show(400), .fadeIn(400), .fadeOut(400), .slideUp(400). The number is duration in milliseconds; 400 ms is 0.4 s. With no number, jQuery uses its default speed. To run code when an effect ends, pass a callback: .fadeIn(400, function(){ ... }), or use .promise().done(fn). Chaining another effect, like .fadeOut(400) after .fadeIn(400), does wait, because effects queue on the element. Ordinary methods do not wait: in .fadeIn(400).addClass('done') the class is added at once.

Events, loops and AJAX

Event shortcuts: .click(fn) binds a click. The general form is .on('click', fn); .off('click', fn) removes it. Inside fn, this is the real DOM element, so $(this) wraps it. .each(function(i, el){...}) loops over the set; i is the index and el is the DOM element.

AJAX: $.ajax({url:'/api/items', method:'GET', dataType:'json'}).done(fn).fail(fn). dataType 'json' parses the reply into a JavaScript object. $.get(url, fn) is a short GET; $.post(url, data, fn) is a short POST. .done runs on success and .fail on error.

$.ajax returns a jqXHR object. .done() and .fail() return that same jqXHR, which is a promise, not a jQuery element set.

Chaining on an element set returns the same jQuery object. To leave jQuery and get the real DOM element, use .get(0) or [0]. $('#items')[0] is the ul itself.

Exam traps

  • Calling .text() on a set returns only the first element's text, not all texts joined. Use .each() or .map().get().join() to collect every text.
  • A jQuery object is not a DOM element. $('#items') is a wrapper; $('#items')[0] or $('#items').get(0) is the real ul. Inside an event handler, this is already the DOM element.
  • :even and :first are zero-based jQuery filters, not CSS. :first picks one element from the whole set; CSS :first-child checks each parent separately.
  • .html('x') inserts markup; .text('x') inserts literal text. Putting user input through .html() can run a script, an XSS risk.
  • $(document).ready waits for the DOM only. window.onload waits for images and other assets too. Scripts that touch the DOM should wait for ready or sit at the end of the body.

Takeaways

  1. A JavaScript program is a list of statements; variables store values, operators combine them, and control statements choose the path.
  2. Functions, arrays and objects are the three containers that let you stop repeating code and start organising data.
  3. An event fires on a target, travels down in capture and up in bubble, and your handler receives an event object describing it.
  4. The browser turns HTML into a DOM tree of element, text and attribute nodes, and editing that tree is what makes a page dynamic.
  5. ES6 gives block scope with let and const, short arrow functions, class syntax and modules, so big programs stay readable.
  6. JavaScript has one call stack, so slow work goes to the browser and returns through the event loop into callbacks, promises or await.
  7. AJAX sends a request with XMLHttpRequest or fetch, gets back text or JSON, and patches the page without a reload.
  8. XML describes data as nested tags; a DTD or an XML Schema is the contract that says which tags may appear and in what order.
  9. jQuery shortens selection, events and AJAX into chained calls that behave alike across browsers.
