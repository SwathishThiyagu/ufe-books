2.1 HTML document structure, tags, elements and attributes

An HTML page is a text file. The browser reads it and builds a tree of elements in memory. Tags mark where an element begins and ends; attributes in the start tag tune it. The skeleton — doctype, html, head, body — keeps page information apart from page content. Every screen in this subject sits on it: the notice board below, the forms of chapter 2.3, and the React components of Unit 5, which reach the browser as ordinary HTML.

You need: how a browser fetches a URL over HTTP and where the developer console lives (Unit 1, Internet, World Wide Web and DNS; Unit 1, Developer tools: VS Code, Git and browser consoles).

The skeleton: doctype, html, head and body

An HTML file is plain text. The browser reads it from top to bottom and builds a tree of elements in memory. The same skeleton opens every page you will write.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Notices</title>
  <link rel="stylesheet" href="notice.css">
</head>
<body>
  <h1>Notices</h1>
  <p>Notice: the exam is <em>today</em>.</p>
</body>
</html>

The first line is the doctype: an exclamation mark, the word DOCTYPE, and the word html. It is not an element and has no closing tag. It tells the browser to use modern standard rules, not an old compatibility mode whose default sizes differ, so a page without it can look slightly wrong even when the markup is fine.

html is the root element; every other element sits inside it. Its lang attribute names the language of the text — en for English, ta for Tamil — and screen readers and spell checkers use it.

head holds information about the page, not content the reader sees. Several things live there. title is the text on the browser tab and in a bookmark. meta with charset="UTF-8" declares the character set; without it, the rupee sign ₹ or a Tamil letter can appear as garbage. meta with name="viewport" and content="width=device-width, initial-scale=1" tells a phone to use its real width, which responsive layout needs (chapter 2.8). link with rel="stylesheet" attaches an external CSS file. A script element with a src attribute loads JavaScript the same way.

body holds everything visible: headings, paragraphs, images, forms.

Tag, element, attribute — three different words

A tag is markup you type: the element name inside angle brackets. The name alone is a start tag; the name after a slash is an end tag. Tags are punctuation, nothing more.

An element is the whole unit: start tag, content, end tag. A paragraph element is the start tag, the sentence, and the end tag together. Elements nest; an element inside another is its child, the outer one its parent.

An attribute is a name="value" pair inside the start tag. In an a element, href gives the destination and target="_blank" opens it in a new tab. The head's link element also uses href, but there it names the file being attached, and it has no target attribute. Double quotes are the convention and single quotes also work. Leave quotes on. An unquoted value cannot contain spaces, quotes, =, less-than or greater-than signs, or a backtick, and cannot be empty.

Void elements have no content and no end tag. Six appear constantly: br (line break), hr (horizontal rule), img (image), input (form field), meta and link. In img, input, meta and link the data arrives through attributes; br and hr simply mark a break or a rule, and their attributes only tune it. A stray end tag for one is quietly ignored.

A comment starts with <!-- and ends with -->, for example <!-- notice board starts here -->. It shows nothing on the page, but it is still a node in the DOM tree and you will see it in the Elements panel. It is not counted when you count elements.

Tag names are case-insensitive: upper case and lower case names give the same element. Write them in lower case, because that is the convention and the only form XHTML allows.

Global attributes work on every element. id gives one unique name per page. class gives a space-separated list of names many elements may share. style carries inline CSS. title shows a tooltip on hover. lang marks a language change inside the page.

The page is a tree, not a list

Nesting makes the document a tree. html is the root. head and body are its two children. title, meta and link are children of head. h1 and p are children of body. The em is a child of the p.

Two nesting rules matter. A child must close before its parent closes. And a p cannot contain another p or a heading; the browser ends the first paragraph and starts a new one without asking.

Browsers repair bad markup silently: a missing end tag, a closed void element, a paragraph inside a paragraph. The screen often looks right while the tree is wrong, and the CSS and JavaScript you add later act on the wrong tree. To see the repaired tree, right-click the page and choose Inspect, then the Elements panel. If the panel disagrees with your file, your markup is wrong. A validator such as the Nu HTML Checker lists the same faults.

Worked example

Question. Write the smallest valid HTML5 page for a college notice board. It must have the document title "Notices", a level-1 heading "Notices", one paragraph in which the word "today" is emphasised, and a link to an external stylesheet. Draw the element tree and count the total elements, the void elements and the non-void elements.

  1. Line 1: doctype. Not an element, not counted.
  2. Open html with lang="en". Count = 1.
  3. Open head. Count = 2.
  4. title with content Notices. Count = 3.
  5. meta charset="UTF-8". Void. Count = 4.
  6. link rel="stylesheet" href="notice.css". Void. Count = 5.
  7. Close head and open body. Count = 6.
  8. h1 with content Notices. Count = 7.
  9. p containing text and an em around today. p makes 8, em makes 9.
  10. Close p, body and html. Tree: html at root, head and body as children, title, meta and link under head, h1 and p under body, em under p.
  11. Total elements = 1 html + 1 head + 1 title + 1 meta + 1 link + 1 body + 1 h1 + 1 p + 1 em = 9.
  12. Void elements = meta and link = 2.
  13. Non-void elements = 9 − 2 = 7.

Answer. The page has 9 elements in total: 7 non-void elements (html, head, title, body, h1, p, em) and 2 void elements (meta and link).

Exam traps

  • Mixing up title and h1. title is the browser tab and belongs in head; h1 is the visible heading and belongs in body. Examiners show a page with a heading but a blank tab and ask what is missing.
  • Closing a void element, as in an img or meta with an end tag. A trailing slash in an image start tag is allowed; a separate end tag for img is the error. The page often looks correct and the error surfaces only in the validator.
  • Nesting a p inside a p, or a heading inside a p. The browser closes the outer paragraph early, so the tree and element count differ from what you wrote.
  • Counting the doctype or a comment as an element. Neither is an element, so neither is counted in the element tree.
  • Forgetting meta charset and then displaying ₹ or an Indian-language word. The page loads but the characters come out as garbage.

2.2 Text formatting, hyperlinks, lists, tables and images

Most of a page is text and data. HTML has a small set of elements for that job: headings, inline emphasis, links, lists, tables and images. Each element carries meaning, not just appearance. A screen reader can tell a table header from a cell, and a browser can follow a link or load an image. The same elements carry prices on a shopping page, marks in a result table, and captions under a photo. Learn the tags and their attributes once, and most static pages become easy to write by hand.

You need: Chapter 2.1 for elements, attributes and correct nesting.

Text formatting and headings

Headings h1 to h6 rank content. h1 is the page main title; h6 is the lowest level. Use them in order. Do not pick a heading by its size; CSS sets size, as Chapter 2.7 shows.

Inline elements change meaning or display inside a line. b makes bold text with no extra importance. strong marks important text and usually looks bold. i sets italic text in an alternate voice. em marks stressed text and usually looks italic. u underlines. mark highlights like a pen. small is for side comments. sub makes subscript, as in H2O. sup makes superscript, as in x2.

code marks a code fragment. pre keeps spaces and line breaks, so it suits a code block or aligned text. br breaks a line inside a paragraph. hr marks a thematic break between sections. Use br and hr for meaning, not for spacing; margins from CSS (Chapter 2.6) do spacing.

Hyperlinks and lists

A link is an a element with an href attribute. The value is a URL. An absolute URL has scheme and host, such as https://example.com/page. A relative URL is resolved against the current page, such as contact.html or ../images/logo.png. Use absolute URLs for other sites and relative URLs inside your own site.

target=_blank opens the link in a new tab; add rel=noopener with it. A mailto: URL starts a mail app, for example mailto:office@example.com. A tel: URL starts the phone dialler on a mobile. A jump link points to an element with an id: give a heading id=fees and link with href=#fees. An image can sit inside a link, so the picture becomes clickable. For example, <a href=page.html><img src=logo.png alt=Home>.

Lists group related items. ul is an unordered bullet list. ol is an ordered list; start=3 begins at 3, and type=A uses A, B, C. The allowed type values are 1, A, a, I and i. dl is a description list with dt for a term and dd for its description. For a nested list, put the inner ul or ol inside an li, never directly inside the outer list.

Tables and images

A table holds data in rows and columns. table contains an optional caption, then thead, tbody and tfoot. Each row is tr. A header cell is th; a data cell is td. Put scope=col on a column header and scope=row on a row header. Screen readers then connect each cell to its headers.

colspan=2 makes one cell cover two columns to its right. rowspan=2 makes it cover two rows downward. Count the cells in each row after merges. Never use a table for page layout; CSS layout is in Chapter 2.8. Old presentational attributes such as align and bgcolor are not the modern way; CSS borders, backgrounds and text alignment replaced them (Chapters 2.6 and 2.7).

An image uses img with src, the URL of the file. The alt attribute is required: it describes the image when the file is missing and for a screen reader. width and height are pixel sizes; they reserve space and reduce layout shift. loading=lazy delays loading an off-screen image. Wrap a picture and its caption in figure, with the caption in figcaption.

Worked example

Question. Write HTML5 markup for a price table. The header row is Item, Qty, Rs. The body rows are Pen 2 20 and Ink 1 50. The footer row has one cell reading Sum with colspan=2, then a last cell reading 70. Show the grid and check the arithmetic. Treat Rs as the line amount, not the unit price.

  1. Open table and add captionStationery bill/caption. In thead, make one tr with three th cells: Item, Qty, Rs. Give each scope=col.
  2. In tbody, row 1 has tdPen, td2, td20. Row 2 has tdInk, td1, td50.
  3. In tfoot, the row has two td cells. The first is td colspan=2Sum; it covers columns 1 and 2. The second is td70 in column 3.
  4. Grid check: rows 1 to 3 each use 3 cells. Row 4 uses 2 cells, but the first spans 2 columns, so row 4 still covers 3 columns. Total table size is 4 rows by 3 columns.
  5. Amount check: Rs values are 20 and 50. Sum = 20 + 50 = 70. The quantities 2 and 1 are already reflected in the line amounts, so we do not multiply again.

Exam traps

  • Swapping colspan (merge across columns) with rowspan (merge down rows). Count cells after each merge.
  • Using old align or bgcolor on table cells. These are presentational attributes; CSS handles alignment and background.
  • Writing img without alt. The text is required for accessibility and appears if the image fails to load.
  • Putting a nested ul directly inside another ul. It must go inside an li.
  • Treating b and strong as identical in meaning. Both usually look bold, but only strong says the text is important.

2.3 HTML forms and form controls

A form is how a web page asks the user for something and sends the answer to a server. HTTP can carry only text, so the browser flattens a form into pairs of name=value, joins them with &, and ships them either in the URL (GET) or in the request body (POST). Search boxes, login pages, IRCTC ticket booking, UPI payment details and feedback forms all run on this one mechanism. Learn the form element, the controls inside it, and the attributes that label, limit and check the input, and you can build any of them.

You need Chapter 2.1 for elements and attributes, Chapter 2.2 for nesting and inline text, and Unit 1 for URLs and HTTP methods.

The form element: typing becomes name=value pairs

A form is a container for controls plus instructions for sending them. Two attributes carry the instructions. action is the URL of the server program that will receive the data. method is the HTTP method used, get or post. Leave action out and the browser submits to the current page's URL; leave method out and it uses get.

Each control has a name and holds a current value. At submission the browser walks the controls in document order and builds one name=value pair per control. A control with no name is skipped silently, even if the user filled it.

  1. The user clicks a submit button, or presses Enter inside a single-line text field.
  2. The browser runs its built-in validation and blocks the send if a field fails.
  3. It reads the current value of every named control.
  4. With get the pairs are appended to the action URL after a ?; with post they go into the request body.
  5. The browser requests that URL and shows the response in place of the page.

Values are URL-encoded before travel. A space becomes %20 or +, and any character outside plain ASCII becomes a percent sign plus two hex digits, so a rupee sign or a Tamil letter still arrives intact.

GET reads, POST writes. GET keeps the pairs in the address bar: bookmarkable, shareable, limited to a few thousand characters, and wrong for passwords. POST hides them in the body, has no small length limit, and is required for file uploads, where the form also needs enctype="multipart/form-data".

Controls: input types, textarea, select, datalist, button

input is an empty element. Its type changes what the user sees and which on-screen keyboard a phone shows; the pair it sends has the same shape whatever the type.

  • Text family: text, password (dots on screen, plain text on the wire), email, url, tel, search.
  • Numbers and dates: number, range (a slider), date, all obeying min, max and step.
  • Colour: color, which sends a value like #1a73e8.
  • Choice: radio for one of many — radios sharing one name form a group and the chosen one sends its value; checkbox for many of many, each ticked box sending its own value.
  • Other: file opens the system picker; hidden carries a value the user never sees, such as a record id.
  • Actions: submit sends the form; reset restores every control to its default.

textarea is the multi-line box. rows and cols size it, and its starting text sits between the tags, not in a value attribute.

select holds option elements. An option's value attribute is what is sent; the text between its tags is what the user reads, and the two may differ. selected marks the default option. optgroup with a label groups related options under a heading, and multiple on the select allows more than one choice.

datalist attaches suggestions to a text input through list="id": the user may pick one or type something else, and whatever is in the box is sent. A button element is a submit button that may hold HTML, with type="submit", "reset" or "button".

Labels, groups and the attributes that check input

A label with for="x" is tied to the control whose id is x. Clicking the label focuses the control, and a screen reader announces the label with the field. Labels matter most for radios and checkboxes, where a tiny square is hard to hit on a phone.

fieldset draws a box around related controls and legend gives it a caption. A radio group belongs in a fieldset so the question and its options travel together; disabling the fieldset disables every control inside it.

  • name — the key in the pair; no name means no data.
  • value — the value sent when the user changes nothing.
  • stand-in — grey hint text inside the box; never submitted.
  • required — the form cannot be sent while the field is empty.
  • readonly — visible, not editable, still submitted; disabled — greyed out and not submitted.
  • pattern — a regular expression the whole value must match, e.g. [0-9]{6} for a PIN code.
  • min, max, step — bounds and allowed jumps for numbers, ranges and dates.
  • autocomplete — on, off, or a token such as email that lets the browser fill saved values.

The browser checks these before submitting: an empty required field, a malformed email, a pattern mismatch or an out-of-range number stops the send and shows a bubble on the offending field. CSS can style it with :invalid, and novalidate on the form switches the check off. This is a courtesy to the user, not a security control; the server must check again (see Unit 4, Form processing with GET and POST).

Worked example

Question. A search form has action="/search" and method="get". Inside it sit a text input with name="q" holding the typed text html, a select with name="lang" whose selected option has value="en" and the visible text English, and a submit button with no name. The user clicks the button. Write the exact URL the browser requests, and state where in the HTTP request it appears.

<form action="/search" method="get">
  <input type="text" name="q" value="html">
  <select name="lang">
    <option value="en" selected>English</option>
  </select>
  <button type="submit">Search</button>
</form>
  1. Read the two attributes: action="/search" gives the path, method="get" says the pairs go into the URL.
  2. Walk the controls in document order. First the text input: its name is q, its current value is html, so the pair is q=html.
  3. Next the select: its name is lang, the selected option's value is en, so the pair is lang=en.
  4. The submit button has no name, so it adds no pair.
  5. Join the pairs with & and place ? between the path and the first pair: /search?q=html&lang=en.
  6. The browser sends this as the request line GET /search?q=html&lang=en HTTP/1.1; the server reads the pairs from the query string.

Answer. The browser requests /search?q=html&lang=en, with both pairs carried in the URL query string.

Exam traps

  • No name, no data. A control without a name is invisible to the submission, so the server receives nothing even though the user typed.
  • Radio group: one shared name, different values. Different names create independent groups and let the user tick several at once.
  • disabled versus readonly. A disabled control is greyed out and not submitted; a readonly control is shown, not editable, and is submitted.
  • stand-in is a hint, not a value. An untouched field sends its value attribute (often empty), never the stand-in text.
  • textarea takes its starting text between its tags; a value attribute on it does nothing.

The same name/value model sits under the Constraint Validation API — checkValidity() and setCustomValidity() — and the FormData object, which serialises a form into pairs for a fetch request (Unit 3). 2.4 HTML5 semantic elements, multimedia and frames

HTML5 semantic elements are named containers that say what a region of a page is for. A header holds the masthead, nav holds a menu, main holds the unique content, and footer holds the copyright line. Before HTML5, authors wrote div boxes with class names, so only a human could guess the structure. Semantic tags expose that structure to screen readers, search engines and browser reading modes. HTML5 also plays video and audio with native tags, so no plugin is needed, and embeds another page with iframe. The same tags appear on news sites, course portals and video lesson pages.

You need: <a href='#html-document-structure-tags-elements-and-attributes'>Chapter 2.1 for nesting and attributes, and <a href='#text-formatting-hyperlinks-lists-tables-and-images'>Chapter 2.2 for links and images.

Named regions and their rules

A semantic element names the job of the content inside it. Use the element that matches the job, not a div with a class.

  • header: masthead, logo and site name; may repeat inside an article.
  • nav: a block of major links; not every group of links.
  • main: the one block of content unique to this page; appears once.
  • section: a thematic group with its own heading; a section without a heading is usually wrong.
  • article: a self-contained item that could be syndicated, such as one news story; it has its own heading.
  • aside: related links or side notes that are not the main flow.
  • footer: copyright, contact or closing notes.

Source order for a simple page is header, nav, main, aside, footer. The figure shows that order. CSS can move these boxes later; source order keeps reading order correct.

Article versus section: an article stands alone and makes sense outside the page; a section groups related content inside a page. A story is an article; 'Related coverage' inside that story is a section if it has a heading.

  • figure with figcaption: an image, diagram or code listing plus its caption.
  • details with summary: a disclosure box; summary is the always-visible label.
  • time: a date or time; the datetime attribute gives machine-readable form.
  • mark: text highlighted for reference.
  • progress: completion of a task, value between 0 and max.
  • meter: a measurement inside a known range, such as disk use.

Landmark regions read by assistive technology are header, nav, main, aside and footer. A section becomes a region only when it has an accessible name.

Video and audio without plugins

The video element plays a movie inside the page. The audio element plays sound only. Both take child source elements.

  • src: file path when using one file; with several sources, put src on source children.
  • controls: show browser play, pause and volume controls.
  • autoplay: start when the page loads; browsers block it unless muted is also present.
  • muted: start with sound off.
  • loop: restart at the end.
  • preload: hint, none, metadata or auto, for how much to fetch early.
  • poster: image shown before play; video only.

Use several source children when formats differ. The browser takes the first file it can play. The type attribute names the format, such as video/mp4 or video/webm. A 90-second clip in MP4 and WebM gives two source lines and one video element.

track adds captions or subtitles. kind='captions' gives sound descriptions and speech for deaf viewers; kind='subtitles' translates dialogue. srclang names the language, label is the menu name, and default picks the starting track. A caption file is WebVTT text.

Audio uses the same controls, autoplay, muted, loop and preload attributes, and source children. Poster, width and height belong to video. A browser that cannot play either format shows the fallback text between the tags.

iframes, obsolete frames and graphics

An iframe embeds another HTML page inside a rectangular window. It is used for maps, video players and payment forms from another site.

  • src: URL of the embedded page.
  • title: short name read by screen readers; required in practice.
  • width and height: size in pixels; CSS can also set them.
  • sandbox: restricts the frame; an empty sandbox blocks scripts, forms and popups. Add tokens such as allow-scripts only when needed.

Old HTML used frameset with frame children to split the window into fixed panes. Frameset is obsolete; iframe replaces it for one embedded region. Old exam questions still expect that sentence. marquee is also obsolete; use CSS animation instead.

Two drawing tags complete the picture. canvas is a blank pixel grid drawn by JavaScript. Inline svg carries shapes as elements in the DOM. Both are alternatives to images for charts and icons.

2.5 CSS syntax, selectors and ways to include styles

A CSS rule is a selector plus a block of declarations, and a page usually holds many rules that fight over the same element. CSS defines a winner with the cascade: importance first, then specificity, then document order. Specificity is a four-part counter — inline style, ids, classes and attributes, elements — compared left to right. Every page you have ever seen uses this: the blue header on IRCTC, the red error text under a UPI form, the hover colour on a button. Get the counters right and the page looks as designed; get them wrong and you spend an evening wondering why nothing changes.

You need chapter 2.1 for the link and style elements, and chapter 2.2 for the content elements you will style.

Anatomy of a rule and its units

A CSS rule has two parts. The selector chooses the elements; the declaration block says what to change. Each declaration inside the braces is a property, a colon, a value and a semicolon: p { color: #333; font-size: 16px; }. Here p is the selector, color and font-size are properties, #333 and 16px are values.

Write the semicolon after every declaration, the last one included. A missing semicolon between two declarations glues them into one invalid declaration; the browser drops that one declaration and continues with the rest of the block. The last declaration may legally omit the semicolon before }, but write it anyway so that adding a new line later cannot break the block. Comments sit between /* and */, may span lines, and cannot be nested. Property names are lowercase.

A length needs a unit; only 0 may drop it. The common units:

UnitMeasured againstOne unit is

remthe root element's font-size16px unless html says otherwise

Three ways to include CSS

Inline. <p style="color: green;">text</p> puts declarations in a style attribute on one element. No selector is written; they apply to that element only, and they beat any selector except !important. Useful for a one-off; bad for a site, because the style cannot be reused or cached.

Internal. A <style> element inside <head> applies to the whole document but only to that one page. Handy for a single page or a quick test.

External. <link rel="stylesheet" href="css/site.css"> in the head fetches a separate file. The browser caches it and reuses it on every page that links it. This is the normal choice for a real site: one file, many pages, and the CSS is fetched in parallel with the HTML.

@import url("print.css"); at the top of a stylesheet pulls in another file. It works, but it is slower. The browser cannot discover the imported file until it has downloaded and parsed the file that imports it — an extra round trip — and rendering may be held up meanwhile. A <link> is found as soon as the head is scanned, so prefer it.

Selectors: choosing elements

A selector pattern is matched against the document tree. Learn these by name; examiners ask for them by name.

  • * — universal, every element.
  • p — type, every p element.
  • .note — class, every element with class="note".
  • #intro — id, the single element with id="intro".
  • [type="text"] — attribute, elements whose attribute has that value.
  • h1, h2 — grouping, one declaration block for both.
  • div p — descendant, any p inside a div at any depth.
  • div > p — child, only direct children.
  • h2 + p — adjacent sibling, the p straight after an h2.
  • h2 ~ p — general sibling, every p after an h2 under the same parent.
  • a:hover, input:focus, li:first-child, li:nth-child(2n), p:not(.note) — pseudo-classes: a state or a position, written with one colon.
  • p::before, p::after, p::first-line — pseudo-elements: a part of an element, written with two colons.

A pseudo-class adds nothing new to the tree; it filters. :nth-child(2n) counts from 1, so 2n means items 2, 4, 6 and :nth-child(2n+1) means 1, 3, 5. ::before and ::after generate a box only when the rule also sets content, for example content: "→";.

Cascade, inheritance and specificity

When several rules match one element, the cascade decides in this order: importance (!important first), then origin, then specificity, then document order — among equals, the later rule wins. Only the winning value for a property is applied; the other declarations are not merged.

Specificity is four counters, compared left to right, never added: (1) is there an inline style attribute, (2) how many ids, (3) how many classes, attributes and pseudo-classes, (4) how many elements and pseudo-elements. * counts nothing. So #intro p is (0,1,0,1) and p.note is (0,0,1,1).

Inheritance is separate from the cascade. Text properties such as color, font-family and line-height pass from parent to child when the child sets nothing. Box properties — margin, padding, border, width — do not pass down.

!important after a value lifts that declaration above normal ones, including an inline style. It is a last resort: a few of them are fine, a file full of them means the selectors were written badly.

Worked example

Question. Two rules match the same paragraph: #intro p { color: blue; } and p.note { color: red; }. Which colour is painted? Then style="color: green" is added to that element — which colour now? Finally the red rule alone is marked !important, the attribute still says green. Which colour now?

  1. Counter for #intro p: 0 inline styles, 1 id, 0 classes, 1 element = (0,1,0,1).
  2. Counter for p.note: 0 inline styles, 0 ids, 1 class, 1 element = (0,0,1,1).
  3. Compare position by position: first counter 0 = 0, second counter 1 > 0, so the id rule wins. The text is blue.
  4. Adding the style attribute creates a third entry, (1,0,0,0). Its first counter is 1 against 0 for both rules, so it wins immediately. The text turns green.
  5. Marking the red rule !important changes the order of the cascade, not the counters. Importance is checked before specificity, and the style attribute is not important, so red wins.
  6. Final sequence of colours: blue, then green, then red.

Answer. The paragraph is blue, then green after the inline style, then red once the red rule is marked !important.

Exam traps

  • Adding the four counters into one number. (0,1,0,1) and (0,0,1,1) both sum to 2, but the id rule wins. Compare left to right, position by position.
  • Forgetting that a pseudo-class sits in the third counter (with classes and attributes) while a pseudo-element sits in the fourth. a:hover is (0,0,1,1), not (0,0,0,1).
  • Thinking an inline style always wins. It beats ids and classes, but a declaration marked !important in a normal stylesheet beats it.
  • :nth-child(2n) counts from 1 among all siblings, so it selects the 2nd, 4th, 6th child — not the 0th, 2nd, 4th. Write 2n+1 for odd items.
  • A missing semicolon between two declarations glues them into one invalid declaration; the browser drops that one declaration and continues with the rest of the block. The last declaration may legally omit its semicolon before }, but write it anyway. !important must come before the semicolon: color: red !important;.

2.6 CSS box model: margins, borders and padding

Every element a browser draws is a rectangle, and CSS builds that rectangle from four layers. Content sits in the middle. Padding adds space inside the border, the border draws the visible edge, and the margin pushes neighbours away. The browser adds these widths to find how much room the element really takes. That is why a box declared 300px wide can render wider, and why one declaration, box-sizing, changes the arithmetic.

You need Chapter 2.5 for selectors, units and the cascade, and Chapter 2.2 for the elements being boxed.

The four layers

Every element generates a rectangular box. CSS describes that box as four layers, one inside the next. From the outside in they are margin, border, padding and content. Picture a framed photograph with a mat around it and empty wall space around the frame.

The content box holds the element's text, image or child boxes. The width and height properties size this content box, not the whole visible box. An element declared width: 300px has 300px of content space before anything else is added.

Padding is space inside the border, between the border and the content. It takes the element's background colour, so it looks like part of the element. It cannot be negative. The four sides are set with padding-top, padding-right, padding-bottom and padding-left.

The border is the visible edge around the padding. It has three parts: width, style and colour. If the style is none, nothing is drawn even when a width is given.

The margin is transparent space outside the border. It separates the element from its neighbours. Margin can be negative, which pulls neighbours closer or makes boxes overlap.

rendered width = width + padding-left + padding-right + border-left-width + border-right-width

width is the content width in px under the default content-box; padding and border widths are lengths in px.

Margins are added on top when we ask how much room the element blocks out: outer width = rendered width + margin-left + margin-right. Background and border stop at the border edge; margins are always transparent.

border-box, shorthands and outlines

The default surprises beginners. Declare width: 300px, add padding: 20px and border: 5px, and the browser draws a box 350px wide. The width measured only the content. This is box-sizing: content-box, the initial value.

Designers often set box-sizing: border-box on every element. Then a declared width includes padding and border, and the content shrinks to fit: content width = declared width − left/right padding − left/right border. Margins stay outside. This makes percentage widths and side-by-side layouts predictable.

The padding and margin shorthands take one to four values, running clockwise from the top.

ShorthandResult
padding: 10pxall four sides 10px
padding: 10px 20pxtop/bottom 10px, left/right 20px
padding: 10px 20px 30pxtop 10px, left/right 20px, bottom 30px
padding: 10px 20px 30px 40pxtop, right, bottom, left in that order

Border shorthands follow the same idea. border: 2px dashed #333 sets width, style and colour in one declaration, and the style is mandatory for a visible line. Sides have their own properties, such as border-top-width. border-radius: 8px rounds the corners; a square with border-radius: 50% becomes a circle.

An outline is drawn outside the border. It takes no space in layout and does not change the box size. Browsers use it for the focus ring on links and buttons.

Margins, display and overflow

margin: auto on a block element with a fixed width shares the leftover horizontal space equally, centring the box. It works only when the element is narrower than its container; without a width the block fills the line and there is nothing to share.

Negative margins are legal. margin-left: -20px pulls the element 20px left, over its neighbour. They are used for overlapping cards and for closing gaps, but they make layout harder to reason about.

Vertical margins of two stacked block boxes collapse. If one has margin-bottom: 24px and the next has margin-top: 16px, the gap between them is 24px, the larger value, not 40px. Parent and child margins can collapse too when no border, padding or content separates them. Horizontal margins never collapse.

display decides how a box treats width and vertical margins. A block box starts on a new line, fills the available width and respects width, height and all margins. An inline box sits in a line of text; width and height are ignored and vertical margins do not push lines apart. inline-block sits in the line like inline content but is sized like a block, which suits buttons and small cards.

When content is larger than its box, overflow decides what happens. visible lets it spill out, hidden clips it, scroll always shows scrollbars and auto shows them only when needed. Prefer auto for text panels.

Question. A card is styled with width: 300px; padding: 20px; border: 5px solid black; margin: 10px. The page uses the default box-sizing. 2.7 Colors, backgrounds, fonts and text styling

Colour, background, font and text properties are ordinary CSS declarations: a property name plus a value, and most values can be written in more than one notation. The same tomato red is #FF6347, rgb(255, 99, 71) or hsl(9, 100%, 64%). Knowing all three matters because design tools export hex, brand guides quote rgb, and lightening a shade is easiest in hsl. Every sale badge, UPI app theme and IRCTC header you have seen is built from these few declarations.

You need: chapter 2.5 for declarations and units, and chapter 2.6 for what sits inside the box.

Colour: several notations, one value

A colour property ends up as one RGBA value inside the browser, but CSS lets you write it several ways. Choose the notation that makes your intent clearest.

  • Keywords: about 140 names such as red, tomato and gold, plus rebeccapurple. Fine for a quick test, useless for a brand colour.
  • Hex: #RRGGBB is three pairs of hexadecimal digits from 00 to FF, giving 256 × 256 × 256 = 16,777,216 colours. The shorthand #RGB doubles each digit, so #F00 means #FF0000.
  • rgb(255, 99, 71): decimal channels 0 to 255. Modern CSS also accepts percentages and a fourth alpha value.
  • hsl(9, 100%, 64%): hue in degrees 0–360 (0 red, 120 green, 240 blue), then saturation and lightness as percentages. Change only lightness and you get a natural lighter or darker shade.
  • currentColor copies the element's own color value, so a border or an inline SVG icon always matches the text beside it.

V = 16 × d₁ + d₂

V is the decimal channel value 0–255; d₁ is the value of the first hex digit (0–9, then A = 10 … F = 15) and d₂ the second. Example: FF = 16 × 15 + 15 = 255.

Alpha is a fourth channel written 0–1: rgba(255, 99, 71, 0.6) is 60% opaque. The separate opacity property also fades content, but it fades the whole element — text, border and every child box — while an alpha channel fades only the one colour it is attached to.

Backgrounds: paint behind the content

Every box has a background layer painted behind its content, its padding and its border, out to the outer edge of the border. background-clip: border-box is the default; set it to padding-box or content-box to pull the background in.

  • background-color: any colour value; the default is transparent.
  • background-image: url("logo.png") or a gradient. The image sits on top of the colour.
  • background-repeat: repeat (default), repeat-x, repeat-y or no-repeat.
  • background-position: two values, x then y — center, 50% 50%, right 10px bottom 20px.
  • background-size: auto, a length or percentage, cover or contain. cover fills the box and crops the overflow; contain shows the whole image and may leave gaps.
  • background-attachment: scroll (default) or fixed, which pins the image while the page scrolls.
  • background-clip: where the background is cut off: border-box (default, out to the outer border edge), padding-box or content-box.
  • background-origin: where background-position is measured from: padding-box (default), border-box or content-box.

A gradient is an image made of code. linear-gradient(90deg, #FF6347, gold) runs along 90 degrees, left to right, from the first stop to the last; radial-gradient(circle, #FF6347, gold) spreads out from the centre. A stop with a percentage, such as #FF6347 40%, tells the blend where to finish.

The background shorthand sets everything at once: background: #FF6347 url("logo.png") no-repeat center / cover fixed; Any order works, except that size must follow position after a slash.

Fonts: family, weight, and em versus rem

font-family takes a comma-separated stack, read left to right until one family is available. Multi-word names go in quotes, and the last item should be a generic family the browser certainly has: serif, sans-serif, monospace, cursive or fantasy. Example: font-family: "Noto Sans", Arial, sans-serif.

A web font arrives through @font-face, which gives a family name and points to a font file the browser can load. Add font-display: swap so readers see fallback text at once instead of a blank patch.

  • font-size: px, em, rem, % or keywords like small. The browser default is 16px.
  • font-weight: 100 to 900 in steps of 100; normal is 400, bold is 700. The font file must really carry the weight, or the browser picks the nearest.
  • font-style: normal, italic or oblique.
  • line-height: a bare number is best — 1.5 means 1.5 × this element's own font size — or a length such as 24px.

em and rem differ. In font-size, 1em is the parent's font size, so nested em sizes compound; 1rem is always the root (html) font size, so rem never compounds. For padding and margins, 1em means this element's own font size.

Text: alignment, spacing, decoration

  • text-align: left, right, center or justify; justify stretches word spaces so both edges are flush.
  • text-decoration: underline, line-through, overline or none, with optional style, thickness and colour, e.g. underline wavy #FF6347.
  • text-transform: uppercase, lowercase or capitalize. It changes display only; an assistive reader may still spell out the original.
  • letter-spacing: 0.05em between characters; word-spacing: 4px between words; text-indent: 2em indents only the first line of a block.
  • text-shadow: x-offset y-offset blur colour, e.g. 2px 2px 4px rgba(0, 0, 0, 0.4). Commas stack several shadows.
  • white-space: normal (collapse spaces, wrap), nowrap (collapse but never wrap), pre (keep spaces and line breaks, no wrap), pre-wrap (keep both and wrap).

nowrap on a badge keeps SALE on one line; pre keeps a code listing exactly as typed.

Worked example

Question. A sale badge uses the colour #FF6347. Convert it to rgb() and to hsl(), then write the same colour at 60% opacity.

  1. Split the hex into three pairs: FF, 63, 47.
  2. FF = 16 × 15 + 15 = 255; 63 = 16 × 6 + 3 = 99; 47 = 16 × 4 + 7 = 71. So rgb(255, 99, 71).
  3. For hsl, take max = 255 and min = 71; the range is 255 − 71 = 184.
  4. Lightness L = (max + min) ÷ 2 ÷ 255 = (255 + 71) ÷ 510 = 326 ÷ 510 = 0.6392, that is 63.9% ≈ 64%.
  5. Saturation: L is above 50%, so S = range ÷ (2 × 255 − max − min) = 184 ÷ (510 − 255 − 71) = 184 ÷ 184 = 1, that is 100%.

  7. A 60% alpha is 0.6, not 60: rgba(255, 99, 71, 0.6), or hsla(9, 100%, 64%, 0.6).

Answer. #FF6347 = rgb(255, 99, 71) = hsl(9, 100%, 64%); at 60% opacity it is rgba(255, 99, 71, 0.6).

Exam traps

  • Reading hex as decimal: FF is 255, not 15 and not 100. Each pair is base 16, with A = 10 … F = 15.
  • Giving alpha as 0–255. In rgba() and hsla() the alpha is 0–1, so 60% is 0.6.
  • Confusing opacity with alpha. opacity fades the element and all its children; an alpha channel fades one colour only.
  • Swapping cover and contain. cover fills the box and crops; contain shows everything and leaves empty space.
  • Forgetting that em compounds down nested elements while rem always measures against the root font size.

2.8 Layout: positioning, Flexbox, Grid and responsive design

Every page is a pile of boxes, and CSS layout decides where each box sits. Normal flow stacks them, position lifts one out, Flexbox lines items along one axis, Grid builds rows and columns, and media queries rearrange the whole thing for a narrow screen. The same HTML document then serves a phone in a Chennai bus queue and a large office monitor. This chapter shows how each tool measures space, so you can predict the pixel widths before you open the browser.

You need: the box model from chapter 2.6 and selector and media-query syntax from chapter 2.5.

Normal flow, display and the position property

Before any CSS, boxes follow normal flow. Block boxes stack top to bottom and fill the parent's width; inline boxes sit side by side on a line. The display property changes this: block, inline, inline-block, flex, grid or none. display: none removes the box and its space; visibility: hidden hides the paint but keeps the space.

position sets how the browser places a box. static is the default and ignores top, right, bottom, left. relative shifts the box from its normal spot by those offsets but keeps the original space. absolute lifts the box out of flow and measures the offsets from its containing block: the nearest ancestor whose position is not static, or the page's initial containing block if there is none. fixed does the same against the viewport, so it stays put while the page scrolls. sticky acts relative until the box reaches a scroll threshold, then sticks inside its parent.

z-index decides which overlapping box paints on top. It works on positioned boxes and on flex and grid items; higher numbers win, and equal values fall back to source order. The old layout technique was float: left or right, with clear: both on the next element so it stops wrapping around the float. You will still see it in legacy code, but Flexbox and Grid replaced it.

Flexbox: one dimension at a time

Set display: flex on a container and its direct children become flex items arranged on one axis. flex-direction: row (the default) runs the main axis left to right; column runs it top to bottom. justify-content spreads items along the main axis (flex-start, center, flex-end, space-between, space-around, space-evenly). align-items places them across the cross axis: stretch is the default, and center, flex-start, flex-end, baseline are the alternatives. align-self overrides alignment for one item, flex-wrap: wrap lets items drop to a new line, and gap adds fixed space between items without margins.

Sizing uses three numbers. flex-basis is the item's starting size on the main axis, flex-grow is its share of leftover free space (default 0), and flex-shrink says how much it gives up when space is short (default 1). The shorthand flex: 1 means grow 1, shrink 1, basis 0, so the whole container counts as free space and splits by grow ratio.

widthᵢ = (W − (n − 1)g) × growᵢ ÷ Σgrow

W is the container's inner width in px; n is the number of items; g is the gap in px; growᵢ is that item's flex-grow; Σgrow is the sum of all grow values.

order: 2 moves an item later on the screen without touching the HTML. Screen readers and Tab order still follow the HTML source, so the visual and spoken sequences differ. Never use it to reorder content that has a meaningful sequence.

Grid: rows and columns together

display: grid makes a two-dimensional container. grid-template-columns lists track sizes; grid-template-rows does the same downward. The fr unit is a share of the space left after fixed tracks and gaps, so grid-template-columns: 200px 1fr 2fr gives 200 px, then one third and two thirds of the rest. repeat(3, 1fr) means 1fr 1fr 1fr, and minmax(150px, 1fr) sets a floor of 150 px and lets the track grow freely above it, sharing the leftover space with the other fr tracks.

auto-fill and auto-fit both create as many tracks as fit; auto-fill keeps the empty ones, auto-fit collapses them so the items stretch. grid-template-areas draws the layout as strings of names, and each child claims a name with grid-area: header. Items can also be placed by line: grid-column: 1 / 3 spans the first two columns, and grid-column: span 2 does the same from wherever the item lands. gap separates tracks. Use Flexbox for a navbar or a row of buttons, Grid for the page skeleton.

Responsive design: one layout for every screen

Without help, a phone browser pretends the page is about 980 px wide and shrinks it. The viewport meta tag fixes that.

<meta name="viewport" content="width=device-width, initial-scale=1">

Responsive design means one HTML document and CSS that adapts. Mobile-first writes the small-screen rules as the base and adds larger ones inside @media (min-width: 768px) { ... }. Breakpoints are chosen where the content breaks, not by device names; 576, 768, 992 and 1200 px are common. Sizes use relative units — %, rem, em, vw — so text and boxes scale with the root font size or the screen.

Images get max-width: 100% and height: auto so they never overflow. srcset lists several files with width descriptors plus a sizes attribute; the browser picks the file whose width suits the space the image will occupy and the screen's pixel density. The picture element with a source media="(min-width: 768px)" child serves a different crop on wide screens. Test by dragging the browser narrow, not by trusting the CSS.

Worked example

Question. A flex container is 600 px wide and holds three items with flex: 1, flex: 2 and flex: 1 and flex-basis 0. Find each item's width (a) when gap is 0 and (b) when gap: 30px is applied.

  1. Sum the grow values: 1 + 2 + 1 = 4, so the shares are 1/4, 2/4 and 1/4.
  2. Case (a), gap 0: free space = 600 − 0 = 600 px.
  3. Item A = 600 × 1/4 = 150 px; item B = 600 × 2/4 = 300 px; item C = 600 × 1/4 = 150 px. Check: 150 + 300 + 150 = 600 px.
  4. Case (b), gap 30 px: three items have two gaps between them, so total gap space = 2 × 30 = 60 px.
  5. Free space = 600 − 60 = 540 px.
  6. Item A = 540 × 1/4 = 135 px; item B = 540 × 2/4 = 270 px; item C = 540 × 1/4 = 135 px.
  7. Check the total: 135 + 270 + 135 + 60 = 600 px, which matches the container.

Answer. With no gap the widths are 150 px, 300 px and 150 px; with a 30 px gap they become 135 px, 270 px and 135 px.

Exam traps

  • position: absolute measures from the nearest ancestor that is not static, not from the page. If no ancestor is positioned, the box lands relative to the initial containing block. Give the parent position: relative.
  • flex: 1 is flex: 1 1 0, with basis zero, so widths follow the grow ratio, not the content. flex: auto is 1 1 auto, which starts from the content size and only distributes what is left.
  • A 1fr track is really minmax(auto, 1fr). A child with a min-width or one long unbroken word pushes the track wider and the grid overflows. Use minmax(0, 1fr) or overflow-wrap on the child.
  • z-index is ignored on an ordinary static box; it applies to positioned boxes and to flex and grid items. A child is trapped inside its parent's stacking context. A z-index: 9999 child still paints below any element outside that context that stacks above the parent, such as a sibling of the parent with a higher z-index.
  • Leave out the viewport meta tag and media queries fire at the wrong width on a phone. Also order matters: in mobile-first CSS, min-width queries must run from smallest to largest so later rules add, not cancel.

2.9 Bootstrap and CSS frameworks

Bootstrap is a CSS framework: a ready-made CSS file plus a JavaScript bundle that gives you a reset, a 12-column grid, components and utility classes. Instead of writing new CSS for every page, you assemble the page from class names such as container, row, col-md-6, card and m-3. This saves time and keeps spacing consistent across a team. It is used for admin dashboards, college portals, landing pages and prototypes, where a responsive layout is needed quickly. The same idea appears in Tailwind, Bulma, Foundation and Materialize.

You need: selectors and the cascade from 2.5, the box model from 2.6, colour and type from 2.7, and Flexbox plus media queries from 2.8.

What a framework supplies and the 12-column grid

Bootstrap is a CSS framework: one CSS file plus one JavaScript bundle. The CSS file supplies four things. A reset (Bootstrap calls it Reboot) removes browser default differences. A grid places content in rows and columns. Components are finished blocks such as buttons and navbars. Utilities are single-purpose classes such as m-3 for margin. The JavaScript bundle adds behaviour to components that need it, such as a modal opening. You use the framework by writing class names in HTML, not by writing new CSS for each page.

The grid has three levels. container is a centred wrapper with a maximum width; container-fluid spans the full viewport width. Inside it, row is a flex container with negative side margins. Inside the row, every col-* is a flex item with side padding. The padding and negative margin form the gutter, the space between columns. A row holds 12 column units.

column width = (W ÷ 12) × s

W is the row content width in pixels (960 px in the worked example); s is the span in column units, from 1 to 12. These widths ignore the gutter; treat them as the share of the row taken by each column.

Three col-4 columns fill the row because 4 + 4 + 4 = 12.

Breakpoints, gutters and responsive spans

Breakpoints make the grid responsive. Bootstrap defines sm 576 px, md 768 px, lg 992 px, xl 1200 px and, from version 5, xxl 1400 px. A class such as col-md-4 means: from 768 px upward, this column spans 4 units. Below 768 px it takes the full row width and stacks. The suffix is a minimum, not an exact width; col-md-4 still applies at 1000 px and at 1400 px unless a larger suffix overrides it. A row with spans that total more than 12 does not shrink its columns. Bootstrap uses flex wrapping, so extra columns move to the next line. A row of three col-md-6 has spans 6 + 6 + 6 = 18, so the first two sit side by side and the third wraps. Always keep col-* inside row, and row inside a container. Putting a column straight inside a container loses the row's flex context and gutter alignment.

Components, utilities and versions

Components are named blocks: navbar for the top menu, card for a boxed item, btn for buttons, form-control for input, alert for a message and modal for a dialog. Utilities set one property: m-3 sets margin on all sides to spacing step 3, p-2 sets padding step 2, text-center centres text and d-flex turns the element into a flex container. The spacing number is a scale step, not a pixel count. Version 4 needs jQuery for its JavaScript components and uses ml/mr for left/right margin. Version 5 drops jQuery, uses ms/me (start/end) and adds the xxl breakpoint. You can load the compiled files from a CDN or copy bootstrap.min.css and bootstrap.bundle.min.js into your project. To change colours, spacing or breakpoints before compiling, override Sass variables. Other frameworks follow the same idea: Tailwind is utility-first, Bulma is class-based without JavaScript, Foundation is configurable, and Materialize follows Material Design. Deep Sass build setups with npm belong to Unit 6.

Exam traps

  • Putting a col-* directly inside a container with no row between: without the row there is no flex container and no negative margins, so the gutter padding disappears and the columns no longer line up beside each other as intended.
  • Expecting columns to shrink when spans exceed 12: Bootstrap wraps the extra column to the next line; it does not divide 12 again.

Placing one element completely inside another, which creates the parent-child tree of the document.
Query string
The ?name=value&name=value part appended to a URL, used by forms with method="get".
Relative URL
An address written relative to the current page, such as images/logo.png, so the site can move as a folder.
Selector
The pattern at the start of a CSS rule that decides which elements are styled, for example .card or li a.
Semantic markup
Choosing tags for what the content means (nav, article, footer) rather than only for how it looks.
Specificity
A four-part weight (inline, id, class, element) that decides which of two conflicting rules wins.
Tag
The angle-bracket marker such as <h1> or </h1> that opens or closes an element.
Utility class
A framework class that sets exactly one property, such as text-center or mt-3, used to avoid writing new CSS.
Viewport meta tag
The head element <meta name="viewport" content="width=device-width, initial-scale=1"> that makes a phone report its real width.
Void element
An element that cannot hold content and therefore has no end tag, such as img or input.
