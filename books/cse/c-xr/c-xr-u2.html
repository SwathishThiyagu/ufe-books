2.1 Input device characteristics and desktop input devices

Every 3D interface begins with what the user can physically do, and that comes from the input device. A device turns a hand movement or a button press into numbers the program reads. We judge it by how many independent motions it reports, how those motions map to the task, and what the hand feels while using it. Desktop devices such as the mouse, joystick, keyboard and touchscreen are the baseline: every VR controller is compared against them, and most VR systems still use them for setup and menus. This chapter defines those measures, then applies them to desktop and special purpose devices.

You need Unit 1, for where input sits among the components of a VR system.

An input device and its degrees of freedom

An input device turns a user's action into data a program can read: a position, a rate, a button state or a hand shape. The same small set of characteristics describes every device, so a VR controller and an office mouse can be compared on equal terms.

Degrees of freedom (DOF) is the number of independent motions the device reports. A mouse has 2 DOF, left-right and forward-back on the desk. A 6-DOF device reports three translations (x, y, z) and three rotations (yaw, pitch, roll). DOF counts motions, not buttons: a mouse with three buttons still has 2 DOF of motion.

An absolute device reports where it is inside its own workspace; a touchscreen knows the finger is at a fixed spot on the glass. A relative device reports only how far it moved since the last reading, like a mouse. Absolute readings map straight to a position. Relative readings must be added up, and a lost reading is lost for good.

In position control the device's displacement sets the object's position: move the mouse 3 cm and the cursor jumps a fixed number of pixels. In rate control the displacement sets a velocity: push the joystick further and the viewpoint moves faster. Position control is zero-order, rate control first-order, and acceleration control (second-order) is harder to learn. Chapter 2.3 applies this to travel.

Isotonic, isometric and elastic; and quality measures

Devices also differ in what the hand feels.

  • Isotonic: moves with the hand and measures displacement, like a mouse or a pen. Proprioception, the body's sense of limb position, tells the user where it is, so the eyes stay on the screen.
  • Isometric: hardly moves and measures force, like a stiff force stick or a spaceball. Workspace is unlimited because nothing travels, but the hand gets no position cue.
  • Elastic: moves a little against a spring and measures that small displacement, like a self-centering joystick that returns to the middle when released.

These numbers compare two devices:

  • Resolution: the smallest change reported, such as counts per inch.
  • Accuracy: closeness of the reading to the true value. Precision: how tightly repeated readings cluster, right or wrong.
  • Repeatability: the same action twice gives the same reading.
  • Latency: delay from action to system, in milliseconds. Update rate: readings per second, in hertz, so 120 Hz is one reading every 8.3 ms.
  • Jitter: how much the latency varies between readings.
  • Workspace, fatigue and cost in rupees.

Desktop input devices and 3D mice

  • Mouse: 2 DOF, relative, isotonic, position control. Resolution runs to thousands of counts per inch and the buttons give discrete input. It runs out of desk, so the user lifts and repositions; the lift reports nothing, which is exactly what relative reporting tolerates.
  • Trackball: the same 2 DOF, but the ball is fixed and the hand rolls it. No desk travel is needed, which helps on a crowded desk; fine pointing is harder for many users.
  • Touchpad: 2 DOF, relative and indirect, because the finger's place on the pad is not the cursor's place on the screen.
  • Joystick: 2 or 3 DOF, elastic and self-centering. Good as a rate control for steering, poor for picking a small target.
  • Spaceball: 6 DOF, isometric. Push, pull and twist with almost no travel. Good for turning a 3D model, weak for accurate translation.
  • Keyboard: discrete keys only, no analogue motion, still the fastest text entry. Touchscreen: absolute and direct, natural pointing, but the finger covers the target and resolution is coarse.
  • 3D mice: a 6-DOF puck reports six motions per sample. Some syllabi call these special purpose input devices. Two-handed use, puck in one hand and mouse in the other, is common in CAD.

Selecting a device for a 3D interface

  1. Write the task in one line: select a target, steer continuously, or enter text.
  2. Decide discrete or continuous. A menu choice wants a button or a key; steering wants an analogue axis.
  3. Choose position or rate control by distance and precision. Short precise moves want position control; long travel wants rate control.
  4. Count the DOF the task needs, then add feedback only if the task needs it.
  5. Check latency, update rate, jitter, workspace, fatigue and cost against the budget.
  6. Test on the real task with a few users; if it fails, go back to step one.

Worked example

Question. A VR cricket game renders 60 frames per second, so one frame lasts 16.7 ms. The bat tracker samples at 120 Hz. (a) How many tracker samples arrive per frame? (b) The menu cursor is driven by a mouse with 800 counts per inch; the user slides it 1.5 inches. How many counts is that? (c) How many DOF must the bat tracker report?

Python program.

rate = 120

counts = int(800 * 1.5)

  1. Frame period T = 1/60 s = 0.0167 s = 16.7 ms.

  3. Samples per frame = 120 Hz × 0.0167 s = 2.0, which is the same as 120 ÷ 60.
  4. Counts = 800 counts/inch × 1.5 inch = 1200 counts.
  5. DOF = 3 translations (x, y, z of the bat) + 3 rotations (its swing angles) = 6 DOF.

Exam traps

  • DOF counts independent motions, not buttons or sensors. A mouse has 2 DOF of motion and three buttons; a 6-DOF puck has six motions and often no useful button.
  • A mouse reports relative movement, so it has no absolute position to hand to a tracker. Never quote mouse readings as world coordinates.
  • Isotonic and isometric are swapped easily. Isotonic means the device moves with the hand, isometric means it measures force with almost no movement.
  • Update rate is not latency. A 120 Hz device with 40 ms latency and heavy jitter feels worse than a steady 60 Hz device.
  • Repeatability is not accuracy: a device can return the same wrong value every single time.

2.2 3D position trackers and their types

A 3D position tracker reports the pose of a sensor: its position in three axes and its orientation, in a fixed reference frame, many times a second. VR and AR need this because the picture must follow the head, hand or tool. Each tracker family measures a different physical quantity, so each trades workspace, accuracy, latency and immunity to interference differently. Trackers drive head-mounted displays, motion capture, surgical navigation and phone AR.

You need Chapter 2.1 for degrees of freedom, resolution, accuracy and latency, and Unit 4 for the transforms that turn tracker readings into poses.

What a tracker reports

A tracker gives a pose, written (x, y, z, yaw, pitch, roll). x, y and z are metres from a fixed origin. Yaw, pitch and roll are rotations about vertical, left-right and forward axes, in degrees. A six-degree-of-freedom (6-DOF) tracker reports all six; a 3-DOF tracker reports orientation only. The frame is the fixed coordinate system the host software uses.

Update rate is reports per second, in hertz. Latency is the delay from motion to a new report, in milliseconds. Workspace is the volume where readings stay valid, in cubic metres. Accuracy is closeness to truth; resolution is the smallest change it can show. A fine resolution with a large systematic offset is still inaccurate. A tethered tracker has a cable to the host; a wireless one does not.

Trackers exist because no single sensor gives fast, accurate, untethered pose in every room. The designer picks the family that matches the workspace and the disturbance.

Mechanical, magnetic and ultrasonic trackers

A mechanical tracker is a linked arm. Joints hold encoders that measure angle. Forward kinematics multiplies link transforms to give the tip pose. Workspace is the arm's reach, typically a cubic metre or two. Accuracy is high, often under a millimetre, and latency is low. It is tethered and contact-based, so it suits a tool or a hand, not a walking user.

A magnetic tracker drives three coils in a transmitter and senses the induced signal in a receiver. AC and DC forms differ in pulse timing. It gives 6-DOF through a non-metal body, with no line of sight. Workspace is a few metres around the transmitter. Accuracy is millimetres to a centimetre. Steel, rebar and CRT monitors distort the field, so readings bend near metal.

An ultrasonic tracker times a pulse from an emitter to a microphone. Distance is d = v × t, where v is the speed of sound in air (about 343 m/s at 20 °C) and t is time of flight in seconds. Three or more distances give position by triangulation. Workspace is a room. Accuracy is millimetres. Air temperature and echoes disturb it; it needs line of sight.

Optical, inertial and hybrid trackers

An optical tracker uses cameras to see markers or LEDs. Outside-in systems put cameras in the room and markers on the user; inside-out systems put cameras on the headset and markers in the room. It gives 6-DOF with millimetre accuracy over a room. It needs line of sight and is disturbed by bright sunlight or occlusion. Latency is a few milliseconds.

An inertial tracker measures angular rate with a gyroscope and linear acceleration plus gravity with an accelerometer. Integrating rate gives angle, but small bias accumulates as drift. It is wireless, fast and never occluded. It cannot give absolute position alone.

A hybrid tracker fuses optical and inertial data. Optical fixes drift; inertial fills gaps between camera frames. Almost every modern headset uses this pair. Choose mechanical for a fixed tool, magnetic for a body inside a metal-free volume, ultrasonic for a cheap room, optical for a room-scale headset, inertial for fast rotation, and hybrid for both.

Worked example

Question. An ultrasonic tracker measures a time of flight of 2.9 ms from an emitter to a microphone. The speed of sound in air at 20 °C is 343 m/s. (a) Find the distance. (b) Three such distances from fixed emitters give position; if each distance has 1 mm error, state the order of position error. (c) At 30 °C the speed is 349 m/s. What distance does the same 2.9 ms report?

  1. Convert time: t = 2.9 ms = 0.0029 s.
  2. (a) d = v × t = 343 × 0.0029 = 0.9947 m ≈ 0.995 m.
  3. (b) Each distance error is 1 mm = 0.001 m; geometry maps it almost directly, so position error is about 1 mm.
  4. (c) d = 349 × 0.0029 = 1.0121 m ≈ 1.012 m.
  5. Change = 1.0121 − 0.9947 = 0.0174 m = 17.4 mm longer with no motion.

Answer. (a) 0.995 m; (b) about 1 mm; (c) 1.012 m, about 17.4 mm longer than at 20 °C.

Exam traps

  • Resolution is not accuracy: a 0.1 mm resolution with a 5 mm bias is inaccurate.
  • An ultrasonic distance depends on the speed of sound; a warm room looks like a moved sensor.
  • Magnetic trackers fail near steel and CRT monitors; the error is not random noise.
  • Inertial tracking drifts: integrating gyro rate accumulates bias, so it needs an absolute fix.

2.3 Navigation and manipulation interfaces

Navigation and manipulation interfaces are the part of a VR or AR system that turns tracked hand and head motion into action. Navigation moves the viewpoint; manipulation moves objects. Both exist because a user must reach a shop, a model or a menu in a space larger than the room. The techniques are chosen by distance, precision, occlusion and the display. A phone AR app, a headset design review and a surgical trainer all use the same small set of ideas.

You need: Chapter 2.2 for the tracked hand pose and Unit 1 for interaction among the three I's; Chapter 2.1 for degrees of freedom helps.

Travel and wayfinding

Navigation has two tasks. Travel moves the viewpoint through the virtual world. Wayfinding is knowing where you are and how to reach a target. A user can travel well and still be lost; a landmark or a map solves wayfinding. Gesture input and the sensors behind it are covered in Chapter 2.4.

  • Physical walking: headset pose follows real walking. One metre real is one metre virtual. Good for small rooms. Limited by tracking space and walls.
  • Steering: user holds a direction with joystick, gaze or hand ray. Viewpoint moves continuously. Speed is the main parameter; high speed raises sickness.
  • Teleport: user points to a target and jumps. It removes continuous optic flow and reduces sickness. It weakens spatial continuity.
  • Fly: six-degree-of-freedom movement adds vertical and roll. It suits inspection and is hard for beginners.
  • Point-and-fly: user points in a direction and the system moves along it. It joins selection and travel.
  • World-in-Miniature (WIM): a small copy of the world. User moves a tiny avatar or grabs the world. It gives overview and fast far travel; scale changes can confuse.

Choose travel by distance, space and sickness. Walking suits near precise work; teleport suits far travel; steering suits medium moves; WIM suits overview. Wayfinding returns in Unit 5.

Selection techniques

Selection picks the object before manipulation. The hand or head defines a ray or a region.

  • Ray casting: a ray starts at the hand or eye and follows the pointing direction. The first object hit is selected. Good for far objects; fails for small or occluded objects and hand jitter.
  • Occlusion: user places the hand over an object. The object that the user's hand hides from the camera, that is the object just behind the hand, is selected. Good for small or distant objects; fails when the hand cannot be tracked accurately or when another object overlaps the target.
  • Go-Go: below D = 0.25 m, virtual hand distance equals real d. Above D, virtual = D + k(d − D), with gain k = 2 in the example. This is the simplified linear form; the original Go-Go mapping makes the gain grow with d above D. The arithmetic below uses the linear form. It extends reach; it can feel odd at large d.
  • Aperture: hand or cone forms a selection window; objects inside are candidates. Good for small targets and groups; ambiguous when many fall inside.
  • Sticky finger: the user points with the finger and the object nearest the finger line sticks to it and follows the hand, so it can be pulled close. It suits small targets at a distance; it picks the wrong object when two objects lie close together along the pointing direction.

Ray casting, aperture and sticky finger favour far targets; occlusion and direct hand favour nearby targets.

Manipulation techniques

Manipulation changes position, orientation or scale after selection. Direct hand is natural: the tracked hand grabs and moves the object one-to-one. Its reach is the arm's reach, and it fatigues over long sessions.

  • HOMER: select with a ray, then move the object with the hand using a scaled mapping. It combines far selection with precise manipulation. Too much gain makes fine control hard.
  • Scaled-World Grab: grab the world and scale or translate it so a far object comes to the hand. User stays still; world moves. Suits distant or large objects; changed scale can confuse spatial memory.
  • Voodoo doll: a small proxy of the object is manipulated. The real object follows. Suits remote or dangerous objects; the proxy mapping must be understood.

Direct hand suits near objects. HOMER suits far precise work. Scaled-World Grab suits huge scenes. Voodoo doll suits remote objects. Force feedback is Unit 3.

System control, fatigue and limits

System control issues commands rather than moving the viewpoint or an object. 3D menus float in space. Gestures use hand shape, and Chapter 2.4 covers the sensors. Speech uses voice commands. Unit 5 covers menus, gesture commands and evaluation in depth. A menu is good for visible choices, a gesture for a quick mode change, and speech for a named command. In a noisy place speech fails; in a crowded scene a menu can be hidden; a long gesture vocabulary is hard to remember.

Every technique fails somewhere. Far objects defeat direct hand. Small objects defeat bare ray casting. Occluded objects defeat any first-hit ray. Long sessions defeat mid-air arm holding; fatigue changes accuracy. Choose for distance, precision, occlusion and display. Chapter 2.5 supplies hand shape data for gestures. A tracked hand can select and manipulate in one motion, but then the system must decide whether a pinch means grab or command.

Worked example

Question. In a Go-Go system, the threshold is D = 0.25 m and the gain above threshold is k = 2. The mapping is virtual = d for d ≤ D, and virtual = D + k(d − D) for d > D. (a) Find virtual distance for d = 0.15 m. (b) For d = 0.40 m. (c) For d = 0.80 m. (d) A shelf is 2 m away in the virtual room. What physical hand distance d is needed? Comment on the result.

  1. Write the mapping: virtual = d when d ≤ D; virtual = D + k(d − D) when d > D. Use D = 0.25 m and k = 2.
  2. This is the simplified linear form; the original Go-Go mapping makes the gain grow with d above D. The arithmetic uses the linear form.
  3. (a) d = 0.15 m is below D, so virtual = 0.15 m.
  4. (b) d = 0.40 m is above D. d − D = 0.40 − 0.25 = 0.15 m. k(d − D) = 2 × 0.15 = 0.30 m. virtual = 0.25 + 0.30 = 0.55 m.
  5. (c) d = 0.80 m is above D. d − D = 0.80 − 0.25 = 0.55 m. k(d − D) = 2 × 0.55 = 1.10 m. virtual = 0.25 + 1.10 = 1.35 m.
  6. (d) Set virtual = 2 m. 2 = 0.25 + 2(d − 0.25). So 1.75 = 2(d − 0.25). So d − 0.25 = 0.875 m. So d = 1.125 m.
  7. This is still a long reach for a seated user, so Go-Go alone is poor for very distant targets.

Answer. The virtual distances are 0.15 m, 0.55 m and 1.35 m, and a 2 m target needs a physical hand distance d = 1.125 m, an uncomfortable stretch.

Exam traps

  • Ray casting selects the first object along the ray. It cannot pick an object hidden behind another; use another viewpoint or a different selection method.
  • For Go-Go, use virtual = D + k(d − D) only when d > D. Below D the mapping is one-to-one, virtual = d.
  • Travel moves the viewpoint; manipulation moves an object. Wayfinding is knowing position and route, not moving.
  • Teleport reduces sickness but removes continuous motion cues. It is not automatically better for precise placement.
  • HOMER, Scaled-World Grab and voodoo doll are different: HOMER ray-selects then hand-manipulates; Scaled-World Grab moves or scales the world; voodoo doll moves a proxy.

2.4 Gesture interfaces and data gloves

A gesture interface reads the shape and motion of your hand and turns it into a command, so no button or stick is needed. It exists because the hand is already a precise, many-jointed tool: you point at a menu, curl your fingers to grab, flick to scroll. A data glove is the direct way to measure hand shape — bend sensors along each finger report how far it is curled. Gesture interfaces appear in VR menus, AR assembly guidance, sign-language capture, and teleoperation of robots.

You need: Chapter 2.1 for what makes an input device good, Chapter 2.2 for 6-DOF tracking of the hand, and Chapter 2.3 for selection, which a gesture often replaces.

What a gesture interface is

A gesture interface is an input device plus software that turns the shape or motion of a hand into a command, with no button or stick in between. Reading the hand directly is attractive because the hand carries more than twenty degrees of freedom. Gestures often replace the selection step of Chapter 2.3; using gestures for system control is covered in Unit 5.

  • Static posture: the hand shape alone, held still, carries the meaning — a flat palm, a pinch.
  • Dynamic gesture: the meaning is in the movement over time — a swipe, a wave, a circle drawn in air.
  • Contact versus non-contact: in a contact interface hardware touches the hand (a glove, a ring); in a non-contact one a camera, depth sensor or radar watches from a distance.
  • Symbolic, deictic, manipulative: a symbolic gesture is a learned sign such as thumbs-up for OK; a deictic gesture points at a target, meaning "that one"; a manipulative gesture grabs, moves or turns an object.

Devices that capture a gesture

  • Flex-sensor glove: a thin resistive strip runs along each finger. Bending stretches the strip and its resistance rises, so a voltage divider gives a bend reading.
  • Fibre-optic glove: light runs through a looped fibre and bending lets some escape, so the light reaching the detector falls as the finger curls. No electrical parts sit on the finger.
  • Resistive-ink glove: bend-sensitive ink is printed on fabric. Cheap, but the reading drifts as the fabric stretches.
  • Pinch glove: contact sensors between the thumb and each fingertip. It reports touch, not how hard you press.
  • 6-DOF wand with buttons: a tracked handle from Chapter 2.2. The command is button plus motion; hand shape is ignored entirely.
  • Bare-hand camera tracking: nothing is worn, but fingers hide each other, which the skeleton fitting of Chapter 2.5 must resolve.
  • EMG armband: electrodes on the forearm read muscle activity and can catch intent a few tens of milliseconds before the finger moves. Noisy, and trained per user.

Contact devices give a reliable hand shape and work when the hand is out of camera view. Non-contact devices keep the hand free but lose accuracy when fingers overlap.

From sensor readings to a gesture event

  1. Sense: each sensor outputs a voltage that falls or rises with bend.
  2. Amplify and digitise: an ADC turns the voltage into counts, for example 8 bits giving 256 counts over the full bend range.
  3. Calibrate: record the open-hand and fist reading of every sensor for this user and map each to 0–1.
  4. Segment: find where the gesture starts and ends, using a rest threshold, a velocity trigger, or a fixed window of frames.
  5. Extract features: normalised bend per sensor, fingertip distances, and speed.
  6. Classify: template matching takes the smallest Euclidean distance to stored feature vectors; dynamic time warping (DTW) matches a template to the same gesture made at a different speed; a hidden Markov model (HMM) suits a gesture built from ordered stages; a small neural net classifies a window of raw frames.
  7. Decide: apply hysteresis to the score (enter high, leave low) and a confidence threshold, then wait a few frames of debounce.

accept g* if p(g* | x) ≥ τ

g* is the most likely gesture class, x is the feature window, p is the classifier's score, and τ is the confidence threshold (often 0.8); below τ the event is rejected as no gesture.

Specifying a glove

  • Sensor count: 10 sensors is common, roughly two per finger. The hand has about 27 bones in many coupled joints, so 10 readings are not 10 independent joint angles.
  • Resolution: bend range ÷ 2^(ADC bits). A 180° range on 8 bits gives 180 ÷ 256 ≈ 0.70° per count.
  • Sample rate: 100 Hz is standard, because hand motion has little energy above about 20 Hz.
  • Repeatability: the same pose read twice should agree to within a few degrees.
  • Calibration is per user and per sensor: a glove calibrated on one hand misreads another.
  • Comfort over a session: heat and sweat under the fabric, cable drag, a minute or two to put on, and sensor zero drifting as the glove warms or shifts on the hand.

Worked example

Question. A data glove has 10 flex sensors, each read by an 8-bit ADC over a bend range of 0° to 180°, and it samples at 100 Hz. (a) What is the bend resolution in degrees per count? (b) How many bytes per second does the raw stream carry, counting one byte per sensor? (c) How many samples fall inside a 2-second calibration pose? (d) The fist threshold is 140° and the sensor jitters by ±3°. What goes wrong, and what two thresholds fix it?

  1. (a) An 8-bit ADC gives 2⁸ = 256 counts across the whole range.
  2. (a) Resolution = 180° ÷ 256 = 0.703125°, that is about 0.70° per count.
  3. (b) One frame carries one byte per sensor = 10 bytes. At 100 frames per second the stream is 10 × 100 = 1000 bytes per second.

  5. (d) A 140° bend with ±3° jitter reads anywhere from 137° to 143°, so the reading crosses 140° on almost every sample: the fist fires, releases and fires again.
  6. (d) The hysteresis band must be wider than the ±3° jitter band, otherwise a finger held near 140° still reaches both thresholds. Take a 5° margin: enter at 140 + 5 = 145° and leave at 140 − 5 = 135°. Between 135° and 145° the state holds, so one fist gives one event.

Exam traps

  • Counting flex sensors as degrees of freedom: a 10-sensor glove does not give 10 independent joint angles, because finger joints are coupled and move together.
  • One threshold without hysteresis: a held gesture then repeats every frame instead of firing once.
  • Mixing static posture with dynamic gesture: a pose needs one frame, a swipe needs a window of frames and a segmenter.
  • Mixing deictic with symbolic: pointing at a target is deictic; a thumbs-up meaning OK is symbolic whatever it points at.
  • Forgetting calibration: a glove calibrated on one user reads another user's fist as a half-curl.

2.5 Body tracking, hand tracking and motion capture

Body tracking and hand tracking turn a person's motion into numbers a computer can use. Sensors measure points on the body or hand; a skeleton model is fitted to those points; the fitted joint angles drive an avatar or an animation. Motion capture is the recording side of the same idea: it stores the motion for replay. The work appears in film and game animation, live sports analysis, VR avatars, and clinical biomechanics. Some syllabi call this movement capture or video-based input.

You need Chapter 2.2 for tracker coordinates and Chapter 2.4 for glove sensing; Unit 4 covers the kinematic chain and joint hierarchy.

Skeleton, calibration and inverse kinematics

A tracked body is a joint hierarchy: a root at the pelvis, then spine, neck, head, arms and legs, each joint a parent of the next. The hierarchy gives a compact state: joint angles plus the root position and orientation (6 degrees of freedom for the root). A T-pose calibration records each marker's offset from its bone while the actor stands with arms out. These offsets form the rest pose. During a take, cameras triangulate marker positions. Forward kinematics computes joint positions from angles; inverse kinematics solves the reverse, finding angles that place joints so markers match measurement. Occlusion happens when a body part hides a marker from a camera; the solver must bridge the gap. The capture volume is the space seen by enough cameras at once.

  1. Place 40 reflective markers on bony landmarks.
  2. Record a T-pose; store each marker offset in its bone frame.
  3. Triangulate each marker from at least two camera views.
  4. Fit the skeleton by inverse kinematics to the measured points.
  5. Write joint angles per frame; fill gaps where markers were hidden.

Motion capture systems differ in what they measure and what they cost to clean. Passive optical systems use retro-reflective markers that bounce camera light back; active optical systems use LEDs that blink in patterns; markerless systems use video and image features; magnetic systems measure a field; mechanical exoskeletons measure joint angles directly; inertial suits integrate accelerometers and gyroscopes. Hand tracking and where it is used

A hand model commonly has 21 joints: the wrist plus four joints for each finger. Camera-based hand tracking estimates these joints from images. Fingers occlude each other: from one view a bent finger can hide the next finger, and depth is ambiguous. A data glove (see Chapter 2.4) measures bend directly and avoids this, but it needs wiring and calibration. In a VR headset, hand tracking must run on limited power, so it uses lower resolution and predicts missing joints. Body and hand capture feed animation, live performance, sports biomechanics, VR avatars, and face capture.

  • Animation: retarget joint angles to a character.
  • Live performance: drive an avatar on set.
  • Sports: measure joint angles and timing.
  • VR: map headset cameras to hand joints for input.

Worked example

Question. An optical motion capture stage uses 12 cameras at 120 frames per second and 40 markers on the actor. A 10-second take is recorded. (a) How many marker samples are there? (b) Each sample is three coordinates stored as 4-byte floats; what is the raw data size? (c) The actor turns and 5 markers are hidden from all cameras for 0.5 s; how many marker samples are lost?

  1. (a) Marker samples = markers × frames per second × seconds = 40 × 120 × 10 = 48,000 marker samples.
  2. (b) Coordinates = 48,000 × 3 = 144,000 coordinates. Raw bytes = 144,000 × 4 = 576,000 bytes, about 576 kB using 1 kB = 1000 bytes.
  3. (c) Lost samples = lost markers × frames per second × lost time = 5 × 120 × 0.5 = 300 marker samples.

Answer. The take has 48,000 marker samples, raw data is 576,000 bytes (about 576 kB), and 300 marker samples are lost.

Exam traps

  • Markers give positions, not joint angles; the skeleton fit is a separate step that produces angles.
  • A lost marker is not a lost limb: the solver interpolates across the gap and can invent motion that never happened.
  • A T-pose is a rest calibration pose, not an animation pose; mistaking it for the take corrupts the bone offsets.
  • More cameras increase capture volume and redundancy, but they do not automatically raise the frame rate.
  • Do not swap active and passive optical systems: active markers emit light, passive markers reflect camera light.

2.6 Sensors used in VR and AR

A VR or AR system cannot see, balance or respond without sensing. Sensors convert one physical quantity — acceleration, angular rate, magnetic field, light, distance or touch — into an electrical signal. Each sensor has a unit, a noise level, a bias and a drift, and the system combines several because no single sensor is enough. The same parts sit in a headset, a phone and a controller. This chapter groups them by what they measure and shows where each error comes from, so later tracker designs make sense.

You need the tracker view from Chapter 2.2; this chapter opens those trackers and looks at the sensors inside.

Inertial sensors: acceleration, rotation and heading

An accelerometer measures specific force along one axis. Specific force is the non-gravitational force per unit mass, so a stationary sensor reads g pointing up, not zero. Unit: m/s². A phone lying flat reads about 9.81 m/s² on its z axis, while free fall reads 0.

A gyroscope measures angular rate about one axis. Unit: rad/s or °/s. It gives fast rotation but has a bias: a small non-zero reading when still. Integrating rate gives angle, and bias adds up.

θ_drift = b_g × t

b_g is the gyroscope bias in degrees per second, t is the integration time in seconds, and θ_drift is the angle error in degrees.

A magnetometer measures the local magnetic field vector. Unit: microtesla, µT. Its direction gives an absolute heading, but steel, motors, speakers and desks distort the field, so the heading error can be large yet does not grow with time.

Dead reckoning means integrating rates and accelerations to update pose. Small errors add, so an unaided inertial sensor drifts. Fusion fixes this: a complementary filter or Kalman filter blends short-term gyro data with absolute gravity from the accelerometer and heading from the magnetometer. Head tracking uses this in Chapter 2.7.

Inside a headset the IMU sits rigidly near the front or side; inside a phone it sits on the main board.

Cameras and depth sensors: light and distance

An RGB camera measures visible light falling on a grid. Unit: pixel counts, later converted to colour. It supplies rich texture but suffers rolling shutter: rows are exposed one after another, so fast head motion skews the image. Auto-exposure changes brightness between frames. An IR camera sees a scene lit by infrared LEDs; it works in dim light but is affected by sunlight and reflective surfaces.

A depth sensor reports distance from the device to a surface. Unit: metres. Three common designs:

  • Structured light: projects an IR pattern and measures how the pattern shifts; error rises on shiny, dark or distant surfaces.
  • Time of flight (ToF): measures round-trip time of light, d = c t / 2, where c is speed of light and t is round-trip time; error rises in bright sunlight and at edges.
  • Stereo: matches two camera views and uses disparity; error rises on textureless walls.

In a headset, cameras sit on the front face and look outward at the world. These cameras support inside-out tracking: the headset works out its own pose from what it sees. Outside-in tracking is the opposite arrangement, where fixed external cameras or base stations look at the headset and its controllers. Eye cameras sit inside the headset near the lenses. In a phone, cameras are on the back and front. These sensors feed tracking, but marker and markerless tracking and SLAM are Unit 6.

Environmental and body sensors: contact and the user

These sensors measure the user or the surface they touch. Each has a unit and a dominant error:

  • Capacitive touch measures change in capacitance, in farads (F); error comes from sweat, gloves and contact area. It sits in controllers, touchpads and phones.
  • Flex sensor measures bend as a resistance change, often read in ohms (Ω) or mapped to angle; error comes from repeated bending and fit. It sits in gloves.
  • Force and pressure sensors measure newtons (N) or pascals (Pa); error comes from creep and placement. They sit under buttons, grips and shoe insoles.
  • Temperature sensors measure °C; error comes from self-heating and slow response. They sit in headsets to watch heat.
  • EMG measures muscle electrical activity in microvolts (µV); error comes from skin preparation, sweat and crosstalk. It sits on the forearm in research bands.

Gaze tracking uses pupil-centre corneal reflection. An IR light makes a bright corneal spot on the eye. An eye camera finds the pupil centre and the corneal spot, and the system tracks the vector between them. That vector shifts with head position and with each person's eye geometry, so on its own it is not gaze direction. After a short calibration for that user, the system maps the vector to gaze direction, reported in degrees. Error comes from glasses, dry eyes and headset slip. It sits inside the headset near each eye.

Worked example

Question. A headset at rest reads a_z = 8.50 m/s² on the axis pointing up, with g = 9.81 m/s². (a) What tilt angle does that imply? (b) The gyroscope has a bias of 0.5° per second. How far does the integrated angle drift in 60 s? (c) A magnetometer heading is off by 10° because of a steel desk nearby; what happens to that error over time?

  1. For a static accelerometer, the measured specific force is the component of gravity along the axis: a_z = g cos θ.
  2. cos θ = a_z / g = 8.50 / 9.81 = 0.8665.
  3. θ = arccos(0.8665) ≈ 29.9°, about 30°.
  4. Gyro bias integrates: θ_drift = b_g t = 0.5°/s × 60 s = 30.0°.
  5. The magnetometer gives an absolute heading, so the 10° disturbance is not integrated; it stays 10.0° while the disturbance is present.

Answer. The tilt is about 29.9° (roughly 30°), the gyro-only angle drifts by 30.0° in 60 s, and the magnetometer heading error stays 10.0°.

Exam traps

  • A stationary accelerometer does not read zero; it reads g pointing up.
  • Gyroscope bias integrates into a growing angle error, while accelerometer and magnetometer errors do not grow in the same way.
  • Unit slips: gyroscope in °/s or rad/s, accelerometer in m/s², magnetometer in µT, depth in metres.
  • Steel desks and motors disturb magnetic heading; do not trust a magnetometer indoors without a disturbance check.
  • Rolling shutter and auto-exposure corrupt camera features during fast head motion.

2.7 Head tracking: orientation, tilt, drift, lighthouse

Head tracking keeps the virtual view fixed to the real world as the head turns. A gyroscope reports angular rate; integrating it gives yaw, pitch and roll. An accelerometer adds the gravity direction, which fixes tilt but not heading. Gyro bias makes the pose drift, so systems correct with a magnetometer or camera and predict ahead to hide latency. Lighthouse uses external base stations that sweep infrared beams; photodiodes time each hit, and angles from two stations fix one photodiode's position; several photodiodes give full 6-DOF pose.

You need: Chapter 2.6 for gyroscope and accelerometer behaviour; rotation maths is in Unit 4.

Orientation, tilt and drift

3-DOF tracking gives orientation only. 6-DOF adds x, y and z position. Use one sign convention: positive yaw turns left, positive pitch looks up, positive roll tilts the head to the left. Yaw is about the vertical axis, pitch about the side-to-side axis, roll about the front-to-back axis.

A gyroscope measures angular rate ω in ° s⁻¹, not angle. Integrating gives angle: θ(t) = θ(0) + ∫ω dt, where θ is angle, θ(0) is start angle, ω is rate and t is time. Discrete form: θ ← θ + ω Δt, where Δt is sample interval in s. Gyro bias b is a false rate when still. Integration makes drift: error = b × t, where t is elapsed time in s. A still headset still drifts.

An accelerometer measures gravity plus linear acceleration. When still, the gravity vector gives tilt: pitch and roll from vertical. Gravity cannot correct yaw, because rotation about vertical leaves gravity unchanged. Yaw needs a magnetometer for Earth's field or a camera for known features. Prediction θ_pred = θ + ωL, where L is latency in s, hides delay.

Inside-out sensors sit on the headset and look out. Outside-in sensors sit in the room and look at the headset.

Lighthouse tracking

Lighthouse puts the emitters in the room and the sensors on the headset. The base stations are fixed and known, but the light is received on the headset, so the sensing itself is inside-out; it is often loosely called outside-in because the reference points are in the room. Two base stations A and B sit at known positions. Each sweeps a narrow infrared beam across the room, first X then Y. Photodiodes on the headset time each hit. A 60 Hz frame is 16.67 ms: A sweeps X 0–4.17 ms and Y 4.17–8.33 ms; B sweeps X 8.33–12.5 ms and Y 12.5–16.67 ms. The figure shows this order. Each photodiode can be hit four times per frame.

The sweep is a moving fan. A hit at time t is at angle θ = (t ÷ T) × F, where t is hit time in ms, T is sweep duration in ms and F is fan angle in degrees. Timing gives the angle to that station, not distance. X and Y angles from one station give the direction of that photodiode from the station. Two stations give two directions, whose intersection fixes that photodiode's position, 3 numbers. Several photodiodes at known offsets on the headset are needed to also get orientation, giving the full 6-DOF pose. Small timing errors become angle errors. It needs a clear line of sight from each station.

Worked example

Question. A headset gyroscope gives steady yaw rate 90° s⁻¹ for 0.5 s. (a) Find yaw change. (b) A bias of 0.2° s⁻¹ is never removed; find yaw error after 5 min. (c) A lighthouse station sweeps a 120° fan in 4.17 ms; find beam angular rate. (d) A photodiode is hit 1.00 ms after sweep start; find its angle from fan start.

  1. 5 min = 5 × 60 = 300 s. Let Δψ be yaw change, ω = 90° s⁻¹, Δt = 0.5 s. (a) Δψ = ω Δt = 90 × 0.5 = 45°.
  2. (b) Bias b = 0.2° s⁻¹. Error = b t = 0.2 × 300 = 60°.
  3. (c) Fan F = 120°, sweep T = 4.17 ms = 0.00417 s. Rate = F ÷ T = 120 ÷ 0.00417 = 28,776.98 ≈ 28,777° s⁻¹.
  4. (d) Hit time t = 1.00 ms. θ = (t ÷ T) × F = (1.00 ÷ 4.17) × 120 = 28.77698 ≈ 28.8°.

Answer. The yaw change is 45°, the bias adds 60° of yaw error in 5 min, the beam rate is about 28,777° s⁻¹, and the hit is 28.8° into the fan.

Exam traps

  • Drift grows with elapsed time, not turn rate; a still headset still drifts.
  • Gravity fixes pitch and roll but never yaw; gravity has no heading.
  • 3-DOF is orientation only; 6-DOF adds position. A gyro alone is not a position tracker.
  • Lighthouse timing gives angles, not distances; two stations and known geometry are needed for full pose.

Takeaways

  1. An input device is a channel with limited degrees of freedom, a mapping to the task, and a feedback path; the same task can feel easy or impossible depending on that mapping.
  2. Desktop devices such as the mouse and joystick are the reference point: they are precise and cheap but were never designed for 3D rotation.
  3. Every tracker family sits somewhere on a trade-off between workspace, accuracy, latency, update rate and immunity to interference, so no single tracker is best.
  4. Position tracking alone is not interaction: navigation, selection and manipulation techniques are the layer that turns pose data into usable action.
  5. Techniques are chosen to match distance and precision, so teleport suits a large world while direct hand reach suits an arm's-length task.
  6. A data glove measures hand shape; a gesture interface adds recognition, and the hard part is separating intended gestures from ordinary hand movement.
  7. Body and hand tracking reconstruct a skeleton from noisy sensors, and motion capture is the same reconstruction used to drive animation.
  8. Every sensor measures one physical quantity and carries its own noise, bias and drift, which is why practical systems fuse several sensors.
  9. A headset gets yaw from the gyroscope and pitch and roll from gravity, then removes slow gyroscope drift with an external reference such as lighthouse beams.

Apply A user must pick a small component on a distant shelf in a large virtual factory. Choose a navigation technique and a manipulation technique, and justify both. 13 marks

Large distance favours teleport or scaled fly over real walking; Precision at distance favours ray casting or go-go extended reach; Gain and confirmation feedback to avoid mis-selection; Why direct hand reach fails beyond arm's length; Combine: teleport close, then direct manipulation.

Apply A tracker updates at 120 Hz and the pipeline adds 25 ms of latency. A hand moves at 1.2 m/s. Compute the positional error in the display and state whether the error is acceptable for touching a virtual button 4 cm wide. 10 marks

Lag distance = speed × latency = 1.2 × 0.025 = 0.03 m = 3 cm; Update period = 1/120 s ≈ 8.3 ms; Compare 3 cm with target size 4 cm: marginal, so prediction or higher rate needed; Distinguish latency from update rate.

Apply You must build a low-cost hand gesture input for a phone-based AR app. Select the sensors and the recognition approach, and defend the choice against a data glove. 12 marks

Camera plus computer vision, markerless hand skeleton from landmarks; Depth or ToF sensor to segment the hand from the background; Static shapes by classifier, dynamic gestures by template or sequence model; Glove gives accurate angles but needs hardware and fitting; Lighting, occluded fingers, battery and processing limits on a phone.

Apply A magnetic tracker is to be installed in a room with steel furniture and CRT monitors. Analyse the expected errors and propose a remedy using tracker selection or hybrid design. 10 marks

Ferromagnetic metal and electric currents distort the field; Errors appear as jitter and wrong position, not clean noise; Options: move the workspace, shield, calibrate, or switch to optical or inertial; Hybrid: inertial rates corrected by optical fixes; State the trade-off honestly: no zero-cost fix.

Analyze and evaluate

Analyze Compare mechanical, magnetic, optical and inertial trackers on workspace, accuracy, latency, update rate and immunity to interference, and recommend one for a seated head-mounted VR setup and one for a room-scale multi-user setup. 15 marks

Structured table across the five criteria; Mechanical: high accuracy, tiny workspace, heavy; Magnetic: no occlusion, distortion-prone; Optical outside-in: large workspace, occlusion and cost; Inertial: cheap and fast, drifting alone, good when fused; Justified recommendation with a stated assumption.

Evaluate Drift is unavoidable in inertial head tracking. Explain its origin, and evaluate the lighthouse approach as a way of removing it. 13 marks

Bias in gyroscope output integrates into angle error that grows with time; Gravity fixes pitch and roll but not yaw; Lighthouse base station sweeps beams; sensors time the hits; Angles from timing, then position by triangulation; periodic absolute fix resets drift; Costs: base station setup, line of sight to the emitters, room calibration.

Analyze Analyse how a motion capture pipeline turns recorded sensor data into an animated skeleton, and identify where error enters at each stage. 14 marks

Sensors: markers, inertial suits, or camera images; Correspondence and labelling of markers to joints; Noise and occlusion causing gaps; interpolation; Fitting: bone lengths fixed, joint angles solved by IK; ambiguity of rotation; Retargeting to a different character changes proportions and foot contact; Filtering and cleanup as the practical fix.

Evaluate Gesture interfaces remove the button but add fatigue and ambiguity. Evaluate gesture input against a handheld controller for a public self-service kiosk, using arm fatigue, hygiene, lighting and user diversity as criteria. 13 marks

Gorilla arm from unsupported mid-air pointing; Hygiene argument: no shared touch surface; Lighting and background affect camera-based recognition; User diversity: hand size, skin tone, sleeve, disability; Ambiguity and false triggers; need for dwell or confirmation feedback; Recommendation with a mixed design: gestures for coarse choice, one physical control for confirm.

Evaluate A wrist-worn inertial unit drives hand tracking for AR. Evaluate which sensors it needs, how fusion is done, and where the design will fail in practice. 12 marks

Accelerometer for gravity, gyroscope for rate, magnetometer for heading; Complementary or Kalman filter; quaternion orientation output; Position cannot come from a wrist IMU alone without a model; Failures: magnetic disturbance indoors, drift in yaw, no absolute position, gesture ambiguity; Practical fix: occasional camera-based correction.

Glossary

3D mouse
A six-degree-of-freedom desktop controller, often a sprung puck, used to rotate and move a model in CAD work.
Accelerometer
A sensor that measures proper acceleration, which at rest is the gravity vector and during motion is gravity plus movement.
Accuracy
How close the reported value is to the true value, in the same units, stated as an error or a percentage of range.
Base station
A fixed emitter that broadcasts reference signals, such as lighthouse sweeps, for other devices to measure against.
Bend sensor
A sensor whose resistance or capacitance changes with curvature, used along the fingers of a data glove.
Bias
A constant offset in a sensor's output that is present even when the true input is zero.
Dead reckoning
Estimating the current pose by adding up integrated motion since the last known absolute fix.
Frame of reference
The coordinate system, with an origin and axes, in which a pose is expressed.
Gorilla arm
Muscle fatigue from holding the arm raised in mid-air for long periods, the main cost of gesture interfaces.
Gyroscope
A sensor that measures angular rate; its output is integrated over time to give angle.
HOMER
A selection technique where a ray picks the object and the hand then grabs it at a scaled arm length.
Input device
Any hardware that carries the user's intention, position or body state into the computing system.
Inside-out tracking
Tracking where cameras or sensors on the headset or device observe the room.
Isometric input
An input that senses force while barely moving, such as a force-sensing stick, so the user gets no travel feedback from the device.
Isotonic input
An input whose displacement changes with the force or motion applied, such as a joystick or mouse, so position is sensed rather than force.
Jitter
Small random frame-to-frame variation in the reported pose while the object is actually still.
Magnetometer
A sensor that measures the local magnetic field direction, giving an absolute heading reference for yaw.
Marker-based capture
Motion capture that tracks reflective or active markers attached to the body and solves their positions from camera images.
Markerless capture
Motion capture that finds body or hand joints directly in camera images without physical markers.
Outside-in tracking
Tracking where sensors fixed in the room observe markers on the user.
Pinch gesture
Bringing thumb and index finger together, the most common grab gesture in hand-tracked interfaces.
Ray casting selection
Selection by pointing a virtual ray from the hand or head and choosing the first object it meets, good for distant targets.
Resolution
The smallest change in the measured quantity that the device can report.
Structured light
A depth-sensing method that projects a known pattern and solves the shape from how the pattern deforms.
Teleportation
A navigation technique that jumps the viewpoint to a marked point, removing the motion that causes simulator sickness.
Update rate
How many pose samples the tracker delivers per second, in hertz.
