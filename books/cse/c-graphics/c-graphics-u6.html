6.1 Multimedia system design and architecture

A multimedia system is not one program; it is a stack of stages joined by a common clock. It captures sound and pictures, compresses each stream, buffers the result, stores or sends it, and finally plays it out. The design exists because audio and video are continuous: they must arrive at a fixed rate. A phone video call, an online class recording and a railway safety video all use this pipeline. This chapter names the layers and shows where timing is protected.

You need Unit 4 (media types and compression basics); network timing appears later in 6.5.

Temporal and non-temporal media

Text and a still image are non-temporal. The system may show a page in 10 ms or in 10 s; nothing breaks. Audio, video and animation are temporal, also called continuous media. A video has a frame rate, for example 30 frames per second. A frame shown late is a glitch; a frame lost is a gap. Audio has a sample rate, for example 44,100 samples per second. Samples must be played at that rate. A clock drives presentation, not the user's click.

The architecture is layered because each job is different. Capture makes a digital stream from a microphone, camera or file. The codec reduces bits. The buffer and synchronisation unit holds short bursts and aligns audio with video. Storage and the file system keep blocks on disk. Network delivery sends packets. Presentation plays out to screen and speaker. The buffer stage is special: it is where timing is repaired rather than merely carried.

The same six stages appear in a phone, a set-top box and a classroom PC. Their hardware changes; the contracts between stages do not. That is why the model is called general purpose.

General-purpose architecture

  1. Capture converts light or sound into numbers: pixel values, PCM samples or a compressed file read from storage.
  2. The codec stage compresses each media type separately. A video codec and an audio codec may run on the same chip, but they produce separate streams.
  3. The buffer and synchronisation stage stores a small playout buffer. It absorbs jitter and inserts or drops timing so that audio and video share one timeline.
  4. The file system stores media in blocks and uses read-ahead so that a disk can supply a continuous stream without long waits.
  5. The network interface packetises the stream for delivery. It may mark packets for quality of service, as covered in 6.5.
  6. The presentation layer decodes, renders and plays out frames and samples at the rate the user expects.

R = W × H × d × f + f_s × b_s × c

R is the raw bit rate in bit/s; W and H are frame width and height in pixels; d is bits per pixel; f is frames per second; f_s is audio samples per second; b_s is bits per sample; c is the number of audio channels. Compression and packet overhead are not included.

The formula shows why multimedia stresses a system. A modest frame size at a common colour depth already produces hundreds of megabits per second if left raw. Compression exists to bring R down to what storage and networks can carry.

Device and interface examples

USB is a device and data interface. A webcam sends frames over USB; a microphone sends PCM samples; the same cable supplies power. HDMI is a display and data interface. It carries uncompressed video with embedded audio from a set-top box or laptop to a screen. HDMI is a live link, not a file system.

Worked example

Question. A video is 640 × 480 pixels, 24 bits per pixel, at 30 frames per second, with stereo audio at 44.1 kHz and 16 bits per sample. Find the raw video bit rate, the audio bit rate, the total bit rate and the storage for a 2-minute clip. Use 1 GB = 10^9 bytes.

  1. List the data: W = 640 pixels, H = 480 pixels, d = 24 bit/pixel, f = 30 frame/s, f_s = 44,100 sample/s, b_s = 16 bit/sample, c = 2 channels, t = 120 s.
  2. Video bits per frame = W × H × d = 640 × 480 × 24 = 7,372,800 bit/frame.
  3. Video bit rate = 7,372,800 × 30 = 221,184,000 bit/s = 221.184 Mbit/s.
  4. Audio bit rate = f_s × b_s × c = 44,100 × 16 × 2 = 1,411,200 bit/s = 1.4112 Mbit/s.
  5. Total bit rate = 221,184,000 + 1,411,200 = 222,595,200 bit/s = 222.5952 Mbit/s.
  6. Storage in bits = 222,595,200 × 120 = 26,711,424,000 bit.
  7. Storage in bytes = 26,711,424,000 ÷ 8 = 3,338,928,000 bytes = 3.338928 GB ≈ 3.34 GB.

Answer. The raw total bit rate is 222,595,200 bit/s, about 222.6 Mbit/s, and the 2-minute clip needs 3,338,928,000 bytes, about 3.34 GB, before compression.

Exam traps

  • Forgetting that audio adds its own bit rate. A video-only answer misses 1,411,200 bit/s in the worked example.
  • Mixing bits with bytes. 640 × 480 × 24 is bits per frame, not bytes; divide by 8 only when bytes are asked.
  • Multiplying sample rate by frame rate. Audio and video have independent clocks and independent bit rates.
  • Treating a buffer as compression. A buffer absorbs jitter and aligns streams; it does not reduce the number of bits.
  • Confusing Mbit/s with MB/s. A rate of 222.6 Mbit/s is about 27.8 MB/s, not 222.6 MB/s.

6.2 Distributed multimedia systems

A distributed multimedia system keeps media on one machine, metadata on another and delivery on a third. The user still expects one film, one song or one lecture to play with a single timeline. Splitting the work lets many clients share storage and lets a nearby cache carry the bytes. This chapter follows a request from the directory lookup to the first playable frame, then shows how separate audio and video servers stay in step. It ends with the link capacity needed for a media server.

You need: 6.1 for the layered pipeline and Unit 4 for compression and synchronisation.

Roles and deployment models

A distributed multimedia system is a set of networked computers that share storage, processing and delivery of continuous media. Continuous media are audio and video whose samples must arrive on time. The system hides the split from the user: one title, one play button, one timeline.

  • A media server stores encoded files and sends packets. It owns the session state: play, pause and seek.
  • A directory server maps a title or ID to a media URL, the address of the media resource. It does not carry the media stream.
  • A proxy or cache sits near clients and keeps recently requested chunks. It cuts repeated traffic on the long link.
  • A small site may use one server for both roles; a large site separates them.

Client–server puts one media server in charge. Peer-to-peer lets clients exchange chunks directly, so total upload capacity grows as users join, but control and rights management are harder. Cloud models rent storage and delivery and add a directory service in front.

Finding a title and opening a session

  1. The client sends the title and user rights to the directory server.
  2. The directory server checks the catalogue and returns a media URL, a session token and the media type. A token is a short proof of rights.
  3. The client opens a session with the media server at that URL. A session is the server-side state for one stream: session ID, current position and play or pause.
  4. The media server reserves link and disk time for the stream, chooses the first segment and returns the session ID and its rate, codec and segment size.
  5. The media server sends packets; the client buffers them and starts playout when its buffer holds enough media.
  6. A pause or seek command goes to the same media server, which changes the send position; the session ID keeps the state.

The directory server is consulted once per title, not once per packet. After step 2 the timing contract is between client and media server. A proxy may answer step 3 if it already holds the segment. Keep the two roles separate in an exam answer: the directory does lookup, the media server does delivery.

One timeline across servers

Audio and video may come from different media servers. The client, not the servers, builds the shared timeline. Each packet carries a timestamp from a common clock. The client waits until it has the first complete unit of both streams, then sets one playout start time.

T<sub>play</sub> = max(t<sub>A</sub>, t<sub>B</sub>) + b

Tplay is the common playout start time in seconds; tA and tB are the arrival times of the first complete audio and video units in seconds; b is the safety buffer in seconds.

Skew is the time difference that grows between two streams. After playout starts, the client compares timestamps with its local clock. If skew passes one video frame, it drops or repeats a frame. For audio it adjusts the resampling rate slightly. This keeps a voice matched to moving lips without restarting the session.

Cloud, edge and link capacity

Cloud storage keeps the master copy in a data centre. An edge node is a smaller server placed close to users. A request first goes to the directory, which may return an edge URL. On a miss the edge fetches from cloud storage and caches the segment. Start-up delay is the time from pressing play to the first frame. A nearby edge lowers start-up delay because the first packets travel a shorter distance, so propagation delay and round-trip time are smaller. Propagation delay is signal travel time; round-trip time is the time for a request to go and a reply to return. After buffering, throughput matters more than distance.

N = C ÷ (r × (1 + o))

N is the number of simultaneous clients; C is the link rate in Mbit/s; r is the average stream rate per client in Mbit/s; o is protocol overhead as a fraction.

Use the average rate for normal planning and the peak rate for worst-case admission. Protocol overhead adds headers and retransmissions, so the link must carry r × (1 + o) per client. A 25% overhead means multiply by 1.25, not 0.25. The answer is a whole number of clients; round down. A link at 100 Mbit/s is 100 × 10⁶ bit/s; a stream at 2 Mbit/s is 2 × 10⁶ bit/s, so the units cancel.

Worked example

Question. A media server sends streams of 2 Mbit/s on average. Its network link is 100 Mbit/s and protocol overhead is 25%. How many clients can it serve at the average rate? If the peak rate is 4 Mbit/s, how many at peak?

  1. Overhead factor = 1 + 0.25 = 1.25.
  2. Average link rate per client = 2 Mbit/s × 1.25 = 2.5 Mbit/s.
  3. Average clients Navg = 100 Mbit/s ÷ 2.5 Mbit/s = 40.
  4. Peak link rate per client = 4 Mbit/s × 1.25 = 5 Mbit/s.
  5. Peak clients Npeak = 100 Mbit/s ÷ 5 Mbit/s = 20.

Answer. The server supports 40 clients at the average rate and 20 clients at the peak rate.

Exam traps

  • Using the peak rate when the question says average, or the reverse, and then reporting a different client count.
  • Forgetting overhead: 25% overhead gives a factor 1.25, not 0.25, and not 25.
  • Confusing Mbit/s with MB/s; multiply or divide by 8 before comparing a link rate with a file size.
  • Saying the directory server streams the media or keeps the playout timeline; it only returns the URL and token.
  • Treating start-up delay as only bandwidth; distance adds propagation and round-trip delay before the first byte.

6.3 Multimedia databases and content retrieval

A multimedia database stores each item's metadata and a small feature vector. Metadata answers exact questions such as date or owner. Content-based retrieval answers similarity questions: show images like this one. The user gives an example, the system extracts features, compares them by a distance, and ranks the nearest items. This is how photo apps find a face, video archives find a scene, and digital libraries find a slide by colour or shape. The database design matters because comparing every stored item is too slow; indexes make similarity search practical.

You need: Unit 4 (image and audio features, MPEG-7 overview) and 6.1.

Metadata search and query by example

Every multimedia item enters the database with metadata: title, owner, date, place, format, duration and keywords. A metadata query is exact or Boolean. 'Find lectures recorded after 2024' or 'find files owned by the design team' uses rows in a table, not pixels. This is fast and predictable, but it cannot answer 'find images that look like this sunset'.

Content-based retrieval, also called query by example, takes the user's item as the question. The system extracts a feature vector from the query and from every stored item, then ranks stored items by similarity. The vector is short: a colour histogram, texture numbers, shape descriptors, video key-frame features or audio short-term spectra. A feature is a measurement, not a compressed copy. The original file stays in storage; the database keeps the vector beside the metadata.

Two consequences follow. First, a good feature must survive small changes such as cropping, scaling or re-encoding. Second, retrieval is approximate by design: the answer is a ranked list, not a single true row. The user sees the top k items, where k is the number returned.

Features and distance measures

For images, a colour histogram counts how much of each colour bin is present. It ignores position, so a rotated image gives the same histogram. Texture describes local variation, for example using edge density or co-occurrence statistics. Shape uses boundaries or region descriptors. For video, key frames summarise shots; for audio, short-term spectra summarise small time windows. These features are chosen because they are compact and can be compared quickly.

Three distance or similarity measures are common. The L1 distance adds absolute differences. The Euclidean distance adds squared differences and takes the square root. Cosine similarity compares direction and ignores length.

d₁(x, y) = Σᵢ |xᵢ − yᵢ|,   d₂(x, y) = √(Σᵢ (xᵢ − yᵢ)²),   cos θ = (x·y) / (‖x‖ ‖y‖)

x and y are feature vectors with components xᵢ and yᵢ; i runs from 1 to n, where n is their length; d₁ is the L1 distance; d₂ is the Euclidean distance; θ is the angle between x and y; x·y = Σᵢ xᵢyᵢ; ‖x‖ = √(Σᵢ xᵢ²). For d₁ and d₂ smaller means more similar; for cos θ larger means more similar.

For L1 and Euclidean, smaller means more similar. For cosine, larger means more similar; the angle θ is between 0 and 90° for non-negative vectors. Histograms are non-negative, so cosine is common in text and audio retrieval.

Indexing, quality and applications

Checking every stored vector is linear search: for each query, compare with all N items. That is too slow for a library. An index stores vectors so whole regions can be skipped. A k-d tree splits the vector space by one coordinate at a time; it works well for low-dimensional vectors. An R-tree groups nearby objects by minimum bounding rectangles and is common for spatial data and image regions. An inverted file maps a feature value or visual word to the list of items that contain it. High-dimensional vectors weaken tree indexes, so practical systems often combine inverted files with approximate nearest-neighbour search.

Retrieval quality is measured with precision and recall.

precision = R / N_r, recall = R / N_all

R is the number of relevant items returned; N_r is the total number of items returned; N_all is the total number of relevant items in the database.

Precision asks: of the items returned, how many are relevant? Recall asks: of all relevant items, how many did we return? A system that returns one safe item has high precision and low recall; a system that returns everything has high recall and low precision.

Image retrieval uses colour, texture and shape. Video retrieval uses key frames plus motion or audio. Digital libraries use metadata for catalogue search and content-based retrieval for slides, maps, photographs and recorded lectures. MPEG-7 is a standard for describing media: it defines description schemes for metadata and low-level features so different systems can exchange them. It is not a compression standard; compression belongs to MPEG-1, MPEG-2 and MPEG-4.

Worked example

Question. A multimedia database stores four-bin colour histograms that sum to 1. The query histogram is q = [0.40, 0.30, 0.20, 0.10]. Image A has h_A = [0.50, 0.20, 0.20, 0.10]; image B has h_B = [0.10, 0.10, 0.30, 0.50]. (a) Compute the L1 distance from q to each image and rank them. (b) The system returns 20 images, of which 12 are relevant; the database contains 30 relevant images. Compute precision and recall.

  1. For image A, bin 1: |0.40 − 0.50| = 0.10; bin 2: |0.30 − 0.20| = 0.10; bin 3: |0.20 − 0.20| = 0.00; bin 4: |0.10 − 0.10| = 0.00.
  2. L1(q, A) = 0.10 + 0.10 + 0.00 + 0.00 = 0.20. The histogram scale has no unit.
  3. For image B, bin 1: |0.40 − 0.10| = 0.30; bin 2: |0.30 − 0.10| = 0.20; bin 3: |0.20 − 0.30| = 0.10; bin 4: |0.10 − 0.50| = 0.40.
  4. L1(q, B) = 0.30 + 0.20 + 0.10 + 0.40 = 1.00.
  5. A has the smaller L1 distance, so A ranks first and B second.
  6. Precision = relevant returned / returned = 12 / 20 = 0.60.
  7. Recall = relevant returned / all relevant = 12 / 30 = 0.40.

Answer. A ranks first with L1 distance 0.20; B has 1.00; precision is 0.60 and recall is 0.40.

Exam traps

  • Swapping precision and recall: precision looks at what was returned, recall looks at what was missed.
  • Treating Euclidean distance as L1: Euclidean squares differences before summing and then takes a square root; L1 does not.
  • Thinking the feature vector is the stored image: the database stores a compact measurement beside metadata, while the original file stays in storage.
  • Confusing MPEG-7 with compression: MPEG-7 describes media content; MPEG-1, MPEG-2 and MPEG-4 handle compression.
  • Using cosine as a distance where larger means worse: cosine similarity is larger for more similar vectors, so rank by decreasing cosine.

6.4 Hypermedia and hypermedia messaging

Hypermedia is a set of media nodes — pages, images, audio, video — joined by links. A link lets a reader jump from one node to another, or start a clip at a fixed moment. Hypermedia messaging carries those links between systems so that every copy of a site agrees on what points where, and when linked media should play. It is used in web sites, e-learning modules, museum guides and streaming catalogues.

You need: 6.1 and Unit 5 on authoring and presentation structure.

Nodes, anchors and links

A node is one addressable media object: an HTML page, a JPEG image, a 30-second audio clip, a video segment. An anchor is a marked place inside a node — a word, a paragraph, a rectangle in an image, a time range in a clip. A link is a directed connection from a source anchor to a target node or target anchor. Write it as a pair (s, t): s is the source anchor, t is the target.

Hypertext has text nodes only. Hypermedia allows images, audio, video and animation as nodes. The prefix hyper means beyond linear reading: the reader chooses the next node. A 1990s CD-ROM encyclopedia was hypermedia; a web page with an embedded video is hypermedia today.

A static link is stored with the document. In HTML, code such as href="unit6.html" is a static link: the address is in the file. A search engine builds result links from your query; a recommendation engine links “customers also watched”. A dynamic link is not stored in the document file. A program builds it at request time from a database, query or user profile and writes it into the page before sending it; so the stored file has no fixed address for it.

Time-based links and link messages

In time-based hypermedia a link fixes when the target plays, not only where it appears. Clicking a word in a lecture transcript may start the video at 00:12 and stop it at 00:20. The link carries a time interval [t₁, t₂]. t₁ is the start time in seconds; t₂ is the end time in seconds. This is common in e-learning and sports replays. Presentation-level synchronisation belongs to Unit 4; here the focus is the link record.

The Dexter model is a reference model for hypertext systems. It splits a system into the storage layer (nodes, links and anchors as stored), the within-component layer (the inside of one node, where anchors are marked) and the run-time layer (what is presented now). The model exists so that one link database can serve different presentations.

Link integrity means every link has a live source and target. A dangling link points to a node or anchor that no longer exists. It causes a dead jump or a 404. Systems check links after every content change.

Hypermedia messaging is the set of messages that create, update or delete links. A create message carries source id, target id, link type and timing. An update message changes the target or the time interval. A delete message removes the link and may leave a tombstone. A content management system sends these messages to caches and delivery nodes so all copies agree.

Clicks count links, not pages

A path is a sequence of nodes joined by links. Its length is the number of links, not the number of nodes. Three nodes in a row give two clicks: Home, FAQ, Notes. This is the trap examiners use.

|P| = n − 1

|P| is the number of clicks along path P; n is the number of nodes visited.

Worked example

Question. A hypermedia site has these links: Home → Courses, Courses → Unit6, Unit6 → Notes, Home → Contact, Contact → FAQ, FAQ → Notes, Home → FAQ. Find the fewest clicks from Home to Notes and list the path.

  1. Write the adjacency list: Home → {Courses, Contact, FAQ}; Courses → {Unit6}; Unit6 → {Notes}; Contact → {FAQ}; FAQ → {Notes}; Notes → {}.
  2. Start at Home with 0 clicks. Its direct neighbours are Courses, Contact and FAQ, so each is at 1 click. Notes is not among them.
  3. From FAQ at 1 click, the link FAQ → Notes reaches Notes at 2 clicks. The path is Home → FAQ → Notes.
  4. The longer paths are Home → Contact → FAQ → Notes and Home → Courses → Unit6 → Notes. Each uses 3 links, so both are longer.
  5. Home → FAQ → Notes visits 3 nodes and uses 2 links. The answer is the link count, 2 clicks.

6.5 QoS issues in multimedia communication

A video call can look perfect on a fast link and still freeze, blur or swallow words. QoS (quality of service) is a set of measurable promises: minimum bandwidth, maximum delay, maximum jitter, maximum loss. Each is a number with a unit, so each can be written into a contract, measured at the receiver, and enforced by buffering, shaping and admission control. Every streaming app, IP phone and live class depends on these four numbers being kept.

You need: distributed multimedia systems for the shared timeline across machines, and the synchronisation ideas from Unit 4.

The four parameters, each with a unit

A multimedia stream is judged by four independent numbers. None can be traded for another: spare bandwidth does not fix jitter, and low delay does not fix loss.

ParameterUnitWhat it limitsUser sees
Bandwidthkbit/s or Mbit/saverage rate the stream needsstalls, long buffering
Delaymstime from capture to playoutpeople talk over each other
Jittermschange in delay between packetsclicks, gaps, jerky motion
Loss% of packetspackets that never arrivedropouts, blocky frames

Bandwidth is the only rate; the other three are errors in time or count. The codec sets bandwidth. Compressed voice runs at about 64 kbit/s with a simple waveform codec; compressed video needs a few hundred kbit/s and upwards, depending on frame size and motion.

Delay and jitter differ. Delay is how late packet i is. Jitter is how much that lateness changes from packet to packet. A steady 200 ms delay is easy to play — shift everything 200 ms later. A delay swinging between 0 and 200 ms needs a buffer, and that buffer costs interactivity.

Measuring delay and jitter, and sizing the playout buffer

Let packet i be sent at time s_i and arrive at time a_i, both in milliseconds, both read on the receiver's clock. Its transit delay is:

d_i = a_i − s_i

d_i is the transit delay of packet i in ms; s_i is its send time in ms; a_i is its arrival time in ms.

The mean transit delay says how late the stream is on average:

d̄ = (1/n) Σ d_i

n is the number of packets measured; d̄ is the mean transit delay in ms.

One common teaching measure of jitter is the mean distance of each delay from that mean:

J = (1/n) Σ |d_i − d̄|

J is the mean deviation, in ms; the bars mean absolute value.

Jitter is not the peak-to-peak spread S = d_max − d_min. The spread is the worst case and sizes the buffer; the mean deviation is the smooth figure reported back to the sender. RTP instead smooths the mean of |d_i − d_(i−1)|, so the two numbers are close but not identical.

A fixed clock offset adds a constant to every d_i. Jitter and spread are safe; the mean delay is meaningful only if clocks are roughly synchronised, for example by NTP or the RTP timestamp mapping.

The buffer must cover the spread. Buffer depth = spread = d_max − d_min. The playout offset from send time is D = d_min + buffer + margin, which is at least d_max. Play packet i at s_i + D; discard any that arrives after its play time.

Buffering hides jitter but adds delay, and delay spoils conversation. Telephony practice treats about 150 ms one-way as comfortable and 400 ms as the practical ceiling. That is the trade: a bigger buffer means smoother video and slower replies.

Shaping, reserving and admitting flows

The network keeps promises in three ways: shape traffic to match what was promised, reserve resources, and admit only as many flows as the link can carry.

A leaky bucket pushes traffic out at one fixed rate and holds or drops the excess. Over any window it guarantees:

bits sent over T ≤ r × T + b

r is the drain rate in bit/s; T is the window length in s; b is the bucket size in bits, the largest burst allowed.

A token bucket is gentler. Tokens arrive at rate r and pile up to a limit b; a packet of L bits leaves only if L tokens are available. Idle time stores tokens, so a flow may burst up to b bits at once — useful after a scene change — while the long-run average stays at r.

Admission control is the gate. A new flow is accepted only if the sum of admitted peak rates stays under link capacity; otherwise it is refused or renegotiated. RSVP carries the request: a host asks routers along the path to reserve bandwidth, and each router accepts or rejects.

RTP makes measurement possible: it stamps each media packet with a sequence number and timestamp, so the receiver can work out delay, jitter and loss. RTCP reports those figures back. Best-effort service promises nothing; guaranteed service reserves the parameters; priority classes sit in between.

Worked example

Question. Five packets of a voice stream are sent at 0, 20, 40, 60 and 80 ms and arrive at 0, 22, 45, 60 and 85 ms. Find each transit delay, the mean transit delay, the mean deviation (jitter) and the peak-to-peak spread. State the minimum playout buffer that removes every late arrival, and the play time of each packet.

  1. Transit delays d_i = a_i − s_i: 0, 2, 5, 0 and 5 ms.
  2. Sum of delays = 12 ms, so mean d̄ = 12 ÷ 5 = 2.4 ms.
  3. Deviations |d_i − d̄|: 2.4, 0.4, 2.6, 2.4 and 2.6 ms. Sum = 10.4 ms, so jitter J = 10.4 ÷ 5 = 2.08 ms.
  4. Spread S = 5 − 0 = 5 ms. Largest delay d_max = 5 ms, so buffer depth = 5 ms and playout offset D ≥ d_max = 5 ms.
  5. With D = 5 ms the play times are s_i + 5 = 5, 25, 45, 65 and 85 ms. Every arrival is at or before its play time, so no packet is late.

Answer. Mean transit delay 2.4 ms, jitter 2.08 ms, spread 5 ms, and a playout buffer of at least 5 ms plays all five packets on time.

Worked example 2

Question. A router shapes a flow with a leaky bucket of drain rate r = 2 Mbit/s and bucket size b = 8000 bits. Over T = 0.5 s, what is the largest number of bits the bucket may release?

  1. Largest release = r × T + b.
  2. r × T = 2 000 000 bit/s × 0.5 s = 1 000 000 bits.
  3. Add the burst allowance b = 8000 bits.
  4. Largest release = 1 008 000 bits in 0.5 s.
  5. That is an average of 1 008 000 ÷ 0.5 = 2 016 000 bit/s = 2.016 Mbit/s, slightly above r because of the burst.

Answer. At most 1 008 000 bits in 0.5 s, i.e. 2.016 Mbit/s with the burst counted.

Exam traps

  • Reporting the peak-to-peak spread as jitter. Jitter is the mean deviation |d_i − d̄|; the spread d_max − d_min is a different, larger number, and it is the spread that sizes the buffer.
  • Treating delay and jitter as one number. A link can add 300 ms of steady delay (bad for talk, trivial to play out) or 100 ms of jitter (fine average delay, needs a large buffer).
  • Forgetting that a playout buffer buys smoothness with delay. Adding 200 ms of buffer to cure jitter makes a two-way call feel sluggish.
  • Mixing units in r × T + b: r in bit/s, T in s, b in bits. Convert kbit/s and bytes before substituting.
  • Assuming good bandwidth means good QoS. A link with spare capacity still fails if packets are lost or delayed unevenly.

6.6 Media on demand and multimedia streaming

Media on demand lets a viewer start a stored video at any moment, while live streaming sends one shared timeline to everyone. Neither can wait for a whole file. The server cuts the media into short segments, a client buffer absorbs network variation, and the player fetches each next segment at a rate the link can hold. The same machinery runs YouTube, Netflix and Hotstar cricket; two-way calls use a different path, RTP over UDP, because they cannot wait for HTTP retransmission. This chapter shows the segment arithmetic and the adaptive loop that keeps playout moving.

You need: the split of storage and delivery in distributed multimedia systems, the four QoS measures in QoS issues, and compression basics from Unit 4.

On demand, live, push and pull

Video on demand (VOD) serves stored media. The viewer may start, pause and seek to any point. A live stream serves a timeline that is being produced now; every viewer joins near the same edge, and seeking back is limited by what the server keeps.

A plain download waits for the whole file before playout; a stream plays while later parts arrive.

In server push, the server sends media at a rate it chooses. The client buffer absorbs the difference between arrival and playout. In client pull, the client asks for each piece. Pull fits HTTP: caches can answer, and the client can change quality on the next request.

The session is controlled separately from the media. A player may send PLAY, PAUSE or TEARDOWN for a stream. HLS (HTTP Live Streaming) and DASH (Dynamic Adaptive Streaming over HTTP) avoid a separate control protocol: they use HTTP requests and a manifest file.

Segmentation and the segment arithmetic

Streaming starts by cutting the encoded video into segments. A segment is a fixed-duration chunk, usually 2 s to 10 s, that begins with a keyframe, a frame that decodes without earlier frames. HLS uses a playlist of segment URLs; DASH uses an XML manifest called the Media Presentation Description (MPD). Both are HTTP-friendly: every segment is a normal object that a cache can store.

The count and size follow from two formulas.

N = T ÷ L

N is the number of segments; T is the total duration in seconds; L is the segment duration in seconds.

S = R × L

S is the segment size in megabits (Mbit); R is the bit rate in megabits per second (Mbit/s); L is the segment duration in seconds. For megabytes (MB), divide S by 8.

The whole file size is R × T, which equals N × S when every segment has the same size.

The bit-rate ladder and adaptive switching

One encoded copy cannot fit every link. The encoder makes a ladder: the same video at several bit rates and resolutions, for example 240p at 0.3 Mbit/s up to 1080p at 5 Mbit/s. Each rung is segmented separately, and the manifest lists all rungs for each time slot.

Adaptive bitrate (ABR) chooses the rung for the next segment. The player estimates throughput from recent downloads and checks buffer health. If the buffer is deep and throughput is high, it climbs; if the buffer is shallow, it drops. Switching happens at a segment boundary, so the decoder never changes format inside a segment. Timestamps keep the shared timeline after a switch.

The loop is a control loop. The client buffer reports its health; the player maps that report to a rate request. A wrong choice is visible as a rebuffer (playout stops) or as needless blur (a low rung on a fast link).

Edge caches, buffers and start-up delay

A content delivery network (CDN) keeps copies of segments at edge servers near users. The origin or cloud store holds the full library; the edge answers most requests. This cuts delay and backbone traffic. A cloud streaming service adds encoding, packaging and storage as rented services, so a small broadcaster can serve many viewers without owning the whole chain.

The client buffer is measured in seconds of playout, not bytes. If it holds k segments of L seconds, the reserve is B = k × L. A larger B survives longer jitter and throughput dips, but the viewer waits longer before the first frame. The start-up delay is the time to fill the initial reserve plus the time to fetch the first segment. A common design keeps a few seconds of reserve and refills it during play.

RTSP (Real Time Streaming Protocol) is one session-control protocol. RTP (Real-time Transport Protocol) is used where low delay matters, such as live contribution; it carries sequence numbers and timestamps but does not guarantee delivery. HLS and DASH use HTTP over TCP, where retransmission hides loss but can add delay.

Worked example

Question. A 2-minute video is encoded at 3 Mbit/s and cut into 4-second segments. (a) How many segments are made? (b) What is the size of one segment in Mbit and in MB? (c) What is the whole file size? (d) If the client holds three segments, how many seconds of playout are in reserve?

  2. Segment count: N = T ÷ L = 120 s ÷ 4 s = 30 segments.

  4. One segment in MB: 12 Mbit ÷ 8 = 1.5 MB.
  5. Whole file: N × S = 30 × 1.5 MB = 45 MB. Check: R × T = 3 Mbit/s × 120 s = 360 Mbit = 45 MB.
  6. Buffer reserve: B = k × L = 3 × 4 s = 12 s.

Answer. 30 segments, each 12 Mbit (1.5 MB); the whole file is 45 MB; 3 segments give 12 s of playout in reserve.

  • 12 Mbit is 1.5 MB, not 12 MB; divide megabits by 8 before calling it megabytes.
  • Segment count uses T ÷ L; 2 minutes is 120 s, so do not divide 2 by 4.
  • Segment size is R × L; the whole file is R × T, not R × L unless there is one segment.
  • ABR changes the rung at a segment boundary; it does not change quality inside a segment.
  • RTSP is session control, not a media transport; RTP carries the timestamped media packets.

6.7 Operating system support for multimedia

Continuous media such as audio and video must be produced on time, not merely soon. The operating system (OS) therefore schedules CPU, disk and input/output (I/O) against deadlines. This is real-time scheduling, not fairness. A video call on a phone, a streaming box and a classroom lecture capture all depend on it. Only a few universities teach this topic. The main model gives each task a period, an execution time and a deadline; from these you compute utilisation and test a scheduling policy.

You need: Chapter 6.1 for the layered pipeline and Chapter 6.5 for the QoS promises.

Real-time task model and CPU scheduling tests

Each periodic task i has period T_i (time between releases, ms), execution time C_i (CPU time needed, ms) and deadline D_i, often equal to T_i. Utilisation is U = Σ C_i/T_i; n is task count, and C_i/T_i is the fraction of CPU task i demands. A set is schedulable if a policy can meet every deadline.

Rate-monotonic (RM) scheduling is fixed priority: shorter period gets higher priority. For n tasks the sufficient RM utilisation bound is U ≤ n(2^(1/n) − 1). At n = 3 this is 3(2^(1/3) − 1) = 0.7798. Earliest-deadline-first (EDF) is dynamic: the ready task with the earliest deadline runs. For preemptive periodic tasks with D_i = T_i, EDF is schedulable exactly when U ≤ 1. Both tests assume preemption and no blocking.

U = Σ (C_i ÷ T_i) ≤ 1 for EDF; for RM, U ≤ n(2^(1/n) − 1)

C_i is execution time of task i in ms; T_i is its period in ms; n is the number of periodic tasks; U is CPU utilisation.

Disk, I/O and blocking support

Continuous media also need disk and I/O deadlines. A media file is stored in contiguous blocks or large extents so a request needs few seeks; random small blocks waste head movement. Disk scheduling has two useful policies. SCAN sweeps the head from one end to the other, serving requests in track order. EDF-for-disk serves the pending request with the earliest deadline, even if the head must move farther. SCAN gives good throughput; disk EDF protects playout deadlines. Double buffering plays buffer A while buffer B fills, then swaps them. Read-ahead fetches the next blocks before they are needed. Resource reservation admits a new stream only if CPU, disk bandwidth and network share remain. Priority inversion happens when a low-priority thread holds a lock needed by a video thread, and a medium-priority thread preempts the holder. The video thread waits although it has higher priority. Priority inheritance lets the holder run at the waiter's priority until it releases the lock.

Worked example

Question. Three periodic tasks share one CPU. Audio runs 4 ms every 10 ms; video runs 10 ms every 40 ms; network runs 5 ms every 20 ms. (a) Find total utilisation U. (b) State whether EDF guarantees all deadlines. (c) Compute the RM bound for three tasks and compare.

  1. Read periods and execution times: audio C1 = 4 ms, T1 = 10 ms; video C2 = 10 ms, T2 = 40 ms; network C3 = 5 ms, T3 = 20 ms.
  2. Compute each share: audio 4/10 = 0.40; video 10/40 = 0.25; network 5/20 = 0.25.
  3. Add the shares: U = 0.40 + 0.25 + 0.25 = 0.90.
  4. EDF test for D_i = T_i: 0.90 ≤ 1, so EDF guarantees every deadline.
  5. RM bound for n = 3: 3(2^(1/3) − 1) = 3(1.259921 − 1) = 3(0.259921) = 0.779763 ≈ 0.7798.
  6. Compare: 0.90 > 0.7798, so the RM sufficient test fails; RM may still work but the bound cannot guarantee it.

Answer. U = 0.90; EDF guarantees all deadlines; RM bound = 0.7798, so RM alone cannot guarantee every deadline.

Exam traps

  • Using n = 2 when three tasks are present: the RM bound is 0.8284 for n = 2, not 0.7798 for n = 3.
  • Treating U ≤ 1 as an RM test. It is the exact EDF test for D_i = T_i; the RM sufficient bound is lower.
  • Forgetting preemption: both tests assume a higher-priority or earlier-deadline task can interrupt the running task.
  • Mixing CPU EDF with disk EDF: CPU picks by deadline among runnable tasks; disk picks by deadline among pending I/O requests, and head position still matters for SCAN.
  • Calling priority inversion a deadline miss: the miss is the symptom; inversion is a low-priority lock holder blocking a high-priority thread.

6.8 Multimedia in social networks and surveillance

A phone upload or a camera feed produces media faster than any person can watch it. So social networks and surveillance systems both turn media into a machine-readable record: detect, describe, index, store, act. The stages are the same; the goal differs. One ranks posts for attention, the other raises alerts for safety. Only a few universities teach this material, and it is the practical face of multimedia big data.

You need: 6.3 for feature vectors kept beside metadata, and 6.6 for segmentation and buffering.

The social media pipeline

An upload lands unchanged in object storage. A worker then builds a transcoding ladder: the same clip re-encoded at 240p, 480p, 720p and 1080p and cut into short segments. A phone on a weak link starts at the bottom rung and climbs, as in 6.6.

Duplicate and copyright checks use a perceptual hash: a short fingerprint that barely changes after resizing, re-compression or a small crop. A cryptographic hash such as SHA-256 flips completely on one bit, so it can never match a re-encoded copy. Two perceptual fingerprints within a small distance are declared the same media.

Tagging adds text: captions, speech-to-text transcripts, classifier labels. Those labels and the fingerprint become a feature vector stored beside the row (6.3). Ranking then scores candidate posts for one user by predicted engagement, freshness and similarity to past viewing, and returns the top few.

The surveillance pipeline

Most surveillance frames are empty. A motion gate compares each frame with a background model and drops frames that differ little. On a quiet corridor at night this one step cuts detection compute by an order of magnitude.

Detection finds people and vehicles in the surviving frames; tracking gives each one a stable id. The metadata stage writes a small row per event: timestamp, camera id, site, object class, bounding box, track id and a perceptual hash of the frame. Video goes to storage; the row goes to an index.

Storage is tiered: recent footage on fast disk for a week or two, older footage on cheap object storage or deleted. A retention policy fixes the days per tier, often 7 hot and 30 cold. A search such as "red truck, gate 3, after 21:00" is answered from the index without decoding video. Alerts fire on rules or on classifier scores. Consent and purpose limitation are legal duties, not features.

GB per camera per day = (R × 86,400) ÷ 8 ÷ 10⁹

R is the recording bit rate in bit/s; 86,400 is the number of seconds in one day; dividing by 8 converts bits to bytes; dividing by 10⁹ gives GB.

  • Using 86,400 s correctly but then forgetting the 30 days, or using 3600 s per day by mistake.
  • Confusing the perceptual hash with a cryptographic hash. One must survive re-encoding; the other must not.
  • Assuming a motion gate shrinks storage. It shrinks compute; storage drops only if the recording policy itself becomes event-only.

It gives a short fingerprint that stays nearly the same after resizing, re-compression or cropping, so near-duplicate media can be matched.

The clip exists at several bitrates as segments, so the client starts at a low rung it can sustain and moves up when bandwidth allows.

The gate skips frames before detection, saving compute. Recording still covers 24 hours at a fixed bit rate, and storage depends on bit rate × time, not on how many frames were analysed.

6.9 Multimedia security and forensics

Multimedia security protects a photo, audio clip or video from copying, editing and false claims about origin. It exists because one share can reach millions in seconds. Four goals are separate: confidentiality hides content, integrity proves no change, authenticity proves who made it, and ownership proves who owns it. Watermarks, hashes and signatures serve different goals, so one tool cannot do all four. Forensics works backwards from a suspect file to evidence. You meet it in CCTV checks, insurance claims, newsroom verification and leaked paper images.

You need: image formats and lossy compression from Unit 4, and feature vectors from 6.3.

Four goals and three kinds of mark

Confidentiality hides content. Symmetric encryption uses one shared key; asymmetric encryption uses a public key and a private key. Integrity proves the bits did not change. Authenticity proves who made the file. Ownership proves who owns the media. Encryption gives confidentiality only; it does not prove origin after decryption.

A watermark is a mark embedded in cover media, the original image, audio or video. The marked output is sent to users. Steganography hides the existence of a message. Fingerprinting embeds a different mark in each copy, so a leak can be traced to one recipient.

  • Watermark: ownership proof or tamper check.
  • Steganography: secret message whose existence is hidden.
  • Fingerprint: unique mark per recipient for leak tracing.

Embedding a mark: LSB and DCT

An 8-bit pixel holds a value from 0 to 255. Its least significant bit (LSB) is the bit with weight 1. Changing it alters the value by at most 1, so the eye rarely sees the change.

  1. Convert the mark to a bit stream.
  2. For each chosen pixel, replace bit 0 with one message bit.
  3. Record the pixel positions and the key.
  4. At the detector, read bit 0 and rebuild the mark.

LSB embedding has high capacity and low robustness. Resaving as JPEG, cropping or scaling destroys it. DCT embedding works on 8×8 blocks. Transform pixels to frequency coefficients, change mid-frequency coefficients, then inverse transform. JPEG also quantises DCT coefficients, so the mark survives ordinary compression better.

MSE = (1/N) Σ (x<sub>i</sub> − y<sub>i</sub>)² ; PSNR = 10 log₁₀(MAX² ÷ MSE)

N is the number of pixels in the block or image; xi is the original pixel value; yi is the marked pixel value; MAX is the peak value, 255 for 8-bit images; MSE is in squared pixel levels; PSNR is in decibels (dB).

Capacity, robustness and imperceptibility pull against each other. More hidden bits means more change. A stronger mark means visible artefacts. PSNR above about 40 dB usually means the change is invisible for 8-bit images.

Hashes, signatures and forensic steps

A cryptographic hash maps a file to a fixed digest. Any bit change gives a different digest with very high probability. Store the digest; later recompute and compare. A digital signature signs the digest with a private key; anyone with the public key verifies it. This detects edits but does not hide content.

Forensics works backwards from a suspect file to evidence. Follow these steps.

  • Read metadata: camera model, time, GPS and software edits.
  • Look for copy-move: the same texture or object pasted twice inside one image.
  • Look for resave traces: JPEG block patterns and double compression.
  • Keep chain of custody: log every person, time and hash from seizure to court.

The same evidence pipeline appears in 6.8, where cameras produce media faster than people can watch.

Worked example

Question. An 8-bit grayscale image has three pixels with values 150, 152 and 155. Hide bits 1, 0, 1 in the least significant bit of each pixel. Find the new pixel values, the mean squared error over these three pixels, and the PSNR. Use MAX = 255.

  1. Pixel 150 is even, so its bit 0 is 0. Set bit 0 to 1: 150 → 151. Squared error = (150 − 151)² = 1.
  2. Pixel 152 is even, so its bit 0 is 0. Set bit 0 to 0: 152 → 152. Squared error = 0.
  3. Pixel 155 is odd, so its bit 0 is 1. Set bit 0 to 1: 155 → 155. Squared error = 0.
  4. MSE = (1 + 0 + 0) ÷ 3 = 1/3 = 0.333 in squared pixel levels.
  5. PSNR = 10 log₁₀(255² ÷ (1/3)) = 10 log₁₀(195,075) ≈ 52.9 dB.

Answer. New pixels are 151, 152 and 155; MSE = 1/3 ≈ 0.333 in squared pixel levels; PSNR ≈ 52.9 dB.

Exam traps

  • Using 20 log₁₀ in PSNR. PSNR uses 10 log₁₀ because it is a power ratio; 20 log₁₀ belongs to amplitude ratios such as voltage gain.
  • Averaging squared error only over changed pixels. MSE divides by N, all pixels in the block or image.
  • Calling any hidden mark a watermark. Steganography hides existence; fingerprinting traces a recipient; watermarking usually proves ownership or tamper.
  • Saying a hash encrypts the file. A hash is a one-way digest, not encryption; it detects change but does not hide content.
  • Expecting LSB marks to survive JPEG. Lossy compression and scaling erase LSB; DCT-domain marks are more robust.

Check yourself

Remember Name the four separate goals of multimedia security. 2 marks

Confidentiality, integrity, authenticity and ownership.

Understand State one difference between watermarking and fingerprinting. 3 marks

A watermark usually carries one mark for ownership or tamper checks. Fingerprinting embeds a different mark in each copy, so a leaked copy can be traced to one recipient.

Apply Pixels 100, 101 and 102 carry bits 1, 0 and 1 in their least significant bits. Find the new pixel values, MSE and PSNR with MAX = 255. 4 marks

100 → 101 (error 1); 101 → 100 (error 1); 102 → 103 (error 1). MSE = 3/3 = 1. PSNR = 10 log₁₀(255² ÷ 1) ≈ 48.1 dB.

Analyze Why does DCT-domain embedding survive JPEG better than LSB embedding? 4 marks

JPEG quantises DCT coefficients, and a mid-frequency DCT mark is changed in the same transform domain. LSB embedding lives in exact pixel values, and quantisation and resaving alter those low bits.

Understand How does a digital signature detect a change in a media file? 3 marks

The signer signs a hash digest with a private key. The verifier recomputes the digest and checks the signature with the public key. A changed file gives a different digest, so verification fails.

Apply A marked image has MSE = 4 in squared pixel levels. Find PSNR with MAX = 255. 3 marks

PSNR = 10 log₁₀(255² ÷ 4) = 10 log₁₀(16,256.25) ≈ 42.1 dB.

Analyze Why does a forensic report need both a hash log and a chain-of-custody record? 4 marks

The hash log proves the file bits did not change. The chain-of-custody record proves who handled the file, when, and through which transfers. Together they connect the court copy to the seized original.

Takeaways

  1. A multimedia system is a pipeline of capture, compress, buffer, synchronise, store, deliver and present, and every stage is designed around the timing of temporal media.
  2. Non-temporal media can be delivered late without harm; temporal media cannot, and that single fact explains buffering, QoS and real-time scheduling.
  3. A distributed multimedia system adds network delay and clock differences to the problem, so one shared timeline must be reconstructed at the receiver.
  4. Multimedia databases answer by similarity: feature vectors give the ranking, metadata gives the filter, and both are needed.
  5. Hypermedia adds structure to media through typed links, and messaging must carry the link plus its timing information.
  6. QoS is only useful when it is measured as numbers: bandwidth, delay, jitter and loss, each with a target.
  7. Streaming works by trading start-up delay for smoothness: segments, client buffer and an adaptive choice of bitrate.
  8. An operating system serving continuous media must schedule against deadlines; fairness to all tasks is the wrong goal.
  9. Phones and cameras produce media faster than people can watch, so detection, description and indexing must be automated.
  10. Security rests on two different tools: marks that survive processing (watermark, fingerprint) and hashes that change on any edit.

Glossary

Content delivery network
A set of edge servers that keep copies of media close to users so that latency and origin load are reduced.
Continuous media
Media whose data represents a signal over time, so that correct presentation requires correct spacing between the pieces.
Digital signature
A cryptographic value computed over the exact bytes of a file with a private key, so any later change makes verification fail.
Inter-stream synchronisation
Keeping two related streams, such as audio and video, aligned to each other during presentation.
Intra-stream synchronisation
Keeping the samples of one stream evenly spaced at presentation time, which needs a stable playout clock.
Media on demand
A service in which each user chooses what to watch and when, so the server must serve many independent timelines.
Media server
A machine or cluster whose storage and I/O are arranged to serve many continuous media streams at once.
Metadata
Structured description of a media item — title, creator, date, format, subject — stored beside the content and used to filter queries.
MPEG-7
A standard for describing multimedia content with metadata and descriptors so that it can be searched and reused across systems.
Multimedia
The integrated presentation of two or more media types, at least one of them temporal, under the control of a single program or document.
Perceptual hash
A short value computed from the perceived content of an image or clip, nearly equal for near-identical copies and different for different content.
Playout buffer
Memory at the receiver that holds arriving media for a short fixed time so that late packets can still be presented in order.
Precision
Fraction of retrieved items that are relevant; used to judge a retrieval system's accuracy.
Real-time task
A task whose correctness depends on finishing before a deadline, not only on producing the right result.
Recall
Fraction of relevant items that were retrieved; used to judge how completely a retrieval system found them.
RSVP
A signalling protocol that lets a receiver reserve network resources along a path for a flow.
Segment
A short independently decodable chunk of a media file that a client can fetch and play on its own.
Similarity search
Retrieval that ranks items by distance between feature vectors instead of requiring an exact match.
Steganography
Hiding the existence of a message inside ordinary carrier data, so an observer does not notice a message at all.
Streaming
Delivering media continuously so that playback begins before the whole file has arrived.
Timestamp
A number in the packet header giving the media time of the first sample carried, used by the receiver to schedule playout.
Token bucket
A shaper model in which tokens accumulate at rate r up to depth b, and each packet spends tokens equal to its size.
Transcoding
Converting a media file from one codec, bitrate or resolution to another, usually to fit a delivery link or device.
Watermarking
Embedding a mark in the media signal so that ownership or origin can be verified after distribution.
