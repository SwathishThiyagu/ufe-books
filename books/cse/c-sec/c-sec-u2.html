2.1 Modular arithmetic and congruences

Modular arithmetic is arithmetic on a clock. You count as usual, but after a fixed number n you wrap back to 0. Two integers that land on the same tick are congruent. This single idea powers RSA, Diffie–Hellman and SHA, and it lets a computer handle 2048-bit numbers while storing only 2048 bits per value. It is the arithmetic behind every public-key system in these notes.

You need school arithmetic: remainders, multiplication and powers; Unit 1's security goals give context only.

Same remainder, same class

Fix a positive integer n, called the modulus, with n ≥ 2. Two integers a and b are congruent modulo n when n divides a − b. We write a ≡ b (mod n). Here n divides a − b means (a − b)/n is an integer.

That is the same as saying a and b leave the same remainder when divided by n. For example, 17 ≡ 5 (mod 12), because 17 − 5 = 12.

Every integer belongs to one residue class modulo n: the set of all integers with the same remainder. The class is named by its least non-negative remainder. Modulo 5, the class of 2 is {..., −8, −3, 2, 7, 12, ...}. The set of all classes is Zn = {0, 1, ..., n−1}.

A negative number is reduced by adding n until it lies in 0 to n−1: −3 ≡ 2 (mod 5). Congruence is an equivalence relation: every integer is congruent to itself, the order of a and b does not matter, and if a ≡ b and b ≡ c then a ≡ c.

Adding and multiplying in Z_n

Addition, subtraction and multiplication follow one rule: do the ordinary operation, then take the remainder modulo n. The answer is always in Zn.

(a + b) mod n = ((a mod n) + (b mod n)) mod n

a and b are integers; n is the modulus, a positive integer with n ≥ 2; mod returns the least non-negative remainder.

Modulo 7: 5 + 6 = 11 ≡ 4; 5 × 6 = 30 ≡ 2; 3⁴ = 81 ≡ 4. For subtraction, 3 − 5 = −2 ≡ 5 (mod 7). Modulo 12, 9 + 8 = 17 ≡ 5, and 9 × 8 = 72 ≡ 0. The clock face uses n = 12: 10 + 4 = 2, since 14:00 is 2 PM.

Multiplication is always possible. Division is not: 3 ÷ 5 modulo 7 means multiplying by the inverse of 5, which Section 4 covers. Powers are repeated multiplication, so they reduce the same way.

Fast exponentiation: square and multiply

Naive exponentiation computes a^e by e − 1 multiplications. If e has 300 digits, that is more operations than there are atoms in the observable universe. Square-and-multiply uses the binary digits of e instead.

  1. Write the exponent e in binary.
  2. Start with result R = 1.
  3. Read the bits from left to right. Square R. If the bit is 1, multiply R by a. Reduce modulo n after every squaring and multiplication.
  4. Equivalently, build a¹, a², a⁴, a⁸, ... by squaring, then multiply the entries whose bit is 1.

Cost: about log₂ e squarings and at most log₂ e multiplications, so O(log e) modular multiplications. For 7²³, the binary exponent is 10111. Five squarings and three extra multiplications replace 22 multiplications.

Never reduce the exponent modulo n. Exponent reduction uses φ(n) and is covered in Chapter 2.5. The figure traces the method for 7²³ mod 13.

When does an inverse exist?

An inverse of a modulo n is an integer b with a·b ≡ 1 (mod n). We write b = a⁻¹ mod n. It exists if and only if gcd(a, n) = 1. Then it is unique in Zn.

Why: if d = gcd(a, n) > 1, every multiple a·b is divisible by d, so a·b − 1 is not, and cannot be a multiple of n. If gcd(a, n) = 1, the extended Euclidean algorithm gives integers x and y with a·x + n·y = 1, so a·x ≡ 1 (mod n).

Examples: 3⁻¹ ≡ 5 (mod 7) because 15 ≡ 1. 5⁻¹ ≡ 7 (mod 17) because 5 × 7 = 35 = 2 × 17 + 1. 6 has no inverse modulo 9 because gcd(6, 9) = 3.

To divide by a modulo n, multiply by a⁻¹. This is legal only when gcd(a, n) = 1. When n is prime, every a from 1 to n−1 has gcd(a, n) = 1, so every non-zero element is invertible; Zp is a field (see Chapter 2.3).

Worked example

Question. Compute 7²³ mod 13 using square-and-multiply. Show the powers and the final multiplication.

  1. Write 23 in binary: 23 = 16 + 4 + 2 + 1, so the bits for 2⁴, 2³, 2², 2¹, 2⁰ are 1, 0, 1, 1, 1.
  2. Compute 7¹ ≡ 7 (mod 13).
  3. 7² = 49 = 3 × 13 + 10, so 7² ≡ 10.
  4. 7⁴ ≡ 10² = 100 = 7 × 13 + 9, so 7⁴ ≡ 9.
  5. 7⁸ ≡ 9² = 81 = 6 × 13 + 3, so 7⁸ ≡ 3.
  6. 7¹⁶ ≡ 3² = 9.
  7. The bits equal to 1 are 16, 4, 2 and 1, so 7²³ ≡ 7¹⁶ × 7⁴ × 7² × 7¹ ≡ 9 × 9 × 10 × 7 (mod 13).
  8. 9 × 9 = 81 ≡ 3; 3 × 10 = 30 ≡ 4; 4 × 7 = 28 ≡ 2.

Answer. 7²³ ≡ 2 (mod 13).

Exam traps

  • a ≡ b (mod n) is not ordinary equality. It says n divides a − b. For example, 17 ≡ 5 (mod 12) but 17 ≠ 5.
  • Reducing an exponent modulo n. In 7²³ mod 13, 23 mod 13 = 10 and 7¹⁰ ≡ 4, not 2. Exponent reduction uses φ(n) and needs gcd(base, n) = 1 (Chapter 2.5).
  • Assuming every number has an inverse. 2 has no inverse modulo 4 because gcd(2, 4) = 2; an inverse exists only when gcd(a, n) = 1.
  • Leaving a negative answer. −3 mod 5 is 2, not −3; add n until the result is in 0 to n−1.

2.2 Euclidean and extended Euclidean algorithms

The greatest common divisor (gcd) of two integers a and b is the largest positive integer that divides both. Euclid's algorithm finds it by repeated division: each remainder becomes the new divisor, and the last nonzero remainder is the gcd. The extended version also returns integers x and y with ax + by = gcd(a,b). That pair is how cryptography computes modular inverses, for example the private exponent in RSA and inverse elements inside finite-field arithmetic. Both algorithms are short, exact and fast: O(log min(a,b)) divisions.

You need: remainders and congruences from Chapter 2.1, especially the meaning of a mod n and the fact that a ≡ b (mod n) when n divides a−b.

Euclid's algorithm by division

The greatest common divisor of positive integers a and b is the largest positive integer d that divides both; write it gcd(a,b). For example gcd(252,105)=21. Euclid's algorithm uses one fact: the gcd does not change when the larger number is replaced by its remainder modulo the smaller number.

Start with r0=a, r1=b, a>b>0. Divide r0 by r1: r0=q1r1+r2, where q1=⌊r0/r1⌋ is the quotient and 0 ≤ r2 < r1 is the remainder. Then gcd(r0,r1)=gcd(r1,r2). Replace (r0,r1) by (r1,r2) and repeat. The remainders decrease strictly, so some remainder becomes 0. The last nonzero remainder is gcd(a,b).

r0 = q r1 + r2, 0 ≤ r2 < r1

r0 and r1 are the current pair; q=⌊r0/r1⌋ is the quotient; r2 is the remainder. The gcd is unchanged by replacing (r0,r1) with (r1,r2).

  1. Set r0=a and r1=b.
  2. While r1≠0, compute q=⌊r0/r1⌋ and r2=r0−q r1.
  3. Shift r0←r1 and r1←r2.
  4. Output r0 when r1=0.

Why it works: any common divisor of r0 and r1 divides r0−q r1=r2, and any common divisor of r1 and r2 divides q r1+r2=r0. The two pairs have the same common divisors, so the same gcd. The loop takes O(log min(a,b)) divisions; each division works on numbers no larger than a.

The extended Euclidean algorithm

The extended Euclidean algorithm returns g=gcd(a,b) and integers x,y with ax+by=g. This is Bézout's identity; x and y are Bézout coefficients and may be negative. For a=252,b=105 the result is 21=(−2)×252+5×105, so x=−2,y=5. Some syllabi call it extended GCD.

Keep two coefficient pairs. Set s0=1,s1=0 and t0=0,t1=1. At each division r0=q r1+r2, compute s2=s0−q s1 and t2=t0−q t1. Then shift r0←r1, r1←r2; s0←s1, s1←s2; t0←t1, t1←t2. Stop when r2=0. Output g=r1, x=s1, y=t1.

The invariant ri=sia+tib holds at the start and survives every update. Back-substitution is the same calculation written upward from the last division. The table method avoids sign errors because each new coefficient uses one multiplication and one subtraction.

Modular inverse and running time

If gcd(a,n)=1, the integers a and n are coprime. Extended Euclid gives ax+ny=1. Modulo n this becomes ax≡1 (mod n), so x mod n is the inverse a−1 mod n. RSA uses this: d=e−1 mod φ(n) when gcd(e,φ(n))=1; see Unit 4, RSA cryptosystem.

If gcd(a,n)=g>1, no inverse exists. Every multiple of a modulo n is a multiple of g, so none can equal 1 modulo n. Cancelling a in a congruence is valid only when gcd(a,n)=1.

Running time: remainders shrink by at least half every two steps, so the loop has O(log min(a,b)) divisions. The extended version adds constant work per division, so it has the same bound.

Worked example

Question. Use the extended Euclidean algorithm on a=252 and b=105. Find g=gcd(252,105), and integers x,y with 252x+105y=g. Show every division and check the result.

  1. Set r0=252, r1=105; s0=1, s1=0; t0=0, t1=1.
  2. Divide: 252=2×105+42, so q=2 and r2=42. Then s2=1−2×0=1 and t2=0−2×1=−2. Shift to r0=105, r1=42; s0=0, s1=1; t0=1, t1=−2.
  3. Divide: 105=2×42+21, so q=2 and r2=21. Then s2=0−2×1=−2 and t2=1−2×(−2)=5. Shift to r0=42, r1=21; s0=1, s1=−2; t0=−2, t1=5.
  4. Divide: 42=2×21+0, so q=2 and r2=0. Then s2=1−2×(−2)=5 and t2=−2−2×5=−12. Remainder is 0, so stop.
  5. Last nonzero remainder is r1=21, so g=21. Coefficients are x=s1=−2 and y=t1=5.
  6. Check: 252×(−2)+105×5=−504+525=21.

  • Losing signs when back-substituting; write ri = ri−2 − qi−1 ri−1, where qi−1 = ⌊ri−2/ri−1⌋, and multiply out to check.

2.3 Groups, rings and finite fields

A cryptosystem is a set of numbers plus rules for adding and multiplying them. Groups, rings and fields name the rule-sets that make those operations behave predictably: you can add, subtract, and, in a field, divide by anything nonzero. RSA works in the ring Z_n, Diffie-Hellman in the group Z_p*, AES inside the field GF(2⁸). Once you know which structure you are in, you know which shortcuts are legal: cancelling, taking inverses, reducing exponents. This chapter defines the three structures and shows why Z_p is a field exactly when p is prime.

You need: modular arithmetic from Chapter 2.1 and gcd plus inverses from Chapter 2.2.

Groups: one operation, four rules

A group is a set G with one operation * that combines two elements into a third. Four rules must hold for all a, b, c in G.

  • Closure: a*b is again an element of G.
  • Associativity: (a*b)*c = a*(b*c).
  • Identity: some e in G satisfies e*a = a*e = a.
  • Inverse: for every a there is b with a*b = b*a = e.

If also a*b = b*a for every pair, the group is abelian, that is, commutative. Addition modulo n always gives an abelian group, with identity 0 and inverse n−a.

The order of the group, written |G|, is its number of elements. The order of an element a is the smallest positive k with a^k = e, where a^k means a*a*...*a repeated k times. In Z_6 under addition the group order is 6, and 2 has order 3 because 2+2+2 ≡ 0 (mod 6).

A group is cyclic if one element g produces every element as a power: G = {g, g², g³, ..., e}. That g is a generator. The nonzero residues mod 7 form a group of order 6 under multiplication, and 3 generates it: 3¹ = 3, 3² = 2, 3³ = 6, 3⁴ = 4, 3⁵ = 5, 3⁶ = 1, all mod 7.

Cauchy's theorem: if a prime q divides |G|, then G has an element of order q. In the group above, |G| = 6, so primes 2 and 3 divide it. 6² = 36 ≡ 1 (mod 7) gives an element of order 2, and 2³ = 8 ≡ 1 gives one of order 3.

Cryptography cares because key sizes rest on group orders. Diffie-Hellman and ElGamal work inside Z_p* and need a subgroup of large prime order. See Unit 4, Public Key Cryptography and Hashing.

Rings and fields: two operations

A ring is a set R with two operations, + and ×, such that (R, +) is an abelian group, × is associative, and × distributes over +: a×(b+c) = a×b + a×c. A commutative ring with unity (an element 1 with 1×a = a) is the setting used in cryptography.

A field is a commutative ring with unity in which every nonzero element has a multiplicative inverse. Equivalently, (F, +) and (F without 0, ×) are both abelian groups. Division by any nonzero element is allowed, so you may cancel: if a×b = a×c and a ≠ 0, then b = c.

Z_n is a field ⟺ n is prime

Z_n is the set {0, 1, ..., n−1} with addition and multiplication modulo n, and n ≥ 2.

Z_n is a commutative ring for every n ≥ 2. An element a has an inverse mod n exactly when gcd(a, n) = 1, as shown in Chapter 2.2. If n = p is prime, every a from 1 to p−1 is coprime to p, so all are invertible and Z_p is a field. If n is composite, take a factor d with 1 < d < n. Then gcd(d, n) = d > 1, so d has no inverse mod n by the gcd test.

Composite moduli also have zero divisors: nonzero a and b with a×b ≡ 0. In Z_6, 2×3 = 6 ≡ 0. A field never has zero divisors. RSA works modulo n = p×q, a ring and not a field; anyone who finds a zero divisor mod n has factored n.

Finite fields GF(p) and GF(2^m)

A finite field with q elements exists if and only if q = p^m for a prime p and an integer m ≥ 1. It is unique up to renaming elements and is written GF(q). GF(p) is simply Z_p. The case m ≥ 2 is a different object from Z_{p^m}.

GF(2^m) has as its elements the polynomials of degree less than m with coefficients 0 or 1: a_{m−1}x^{m−1} + ... + a₁x + a₀. There are 2^m of them. Addition is coefficient-wise mod 2, which is XOR. Multiplication is polynomial multiplication, then reduction modulo a fixed irreducible polynomial m(x) of degree m, one that cannot be written as a product of two lower-degree polynomials over GF(2).

  1. Multiply the two polynomials over GF(2): coefficients add mod 2, so x + x = 0.
  2. Divide the product by m(x) and keep the remainder.
  3. The remainder, of degree less than m, is the field product; its coefficients are the bits of the answer.

AES uses GF(2⁸) with m(x) = x⁸ + x⁴ + x³ + x + 1. A byte is a polynomial: 0x57 means x⁶ + x⁴ + x² + x + 1. MixColumns multiplies such bytes inside this field. Unit 3, Symmetric Key Cryptography covers the cipher.

The nonzero elements of GF(q) form a group of order q−1 under multiplication, and that group is cyclic. This is why discrete-log systems have a well-defined generator.

Worked example

Question. Show that Z_7 is a field by finding the multiplicative inverse of every nonzero element, and hence write down 3⁻¹ mod 7.

  1. The elements are 0, 1, 2, 3, 4, 5, 6, with addition and multiplication modulo 7.
  2. The modulus 7 is prime, so gcd(a, 7) = 1 for every a from 1 to 6. Each has an inverse mod 7.
  3. Test the products: 1×1 = 1; 2×4 = 8 ≡ 1; 3×5 = 15 ≡ 1; 4×2 = 8 ≡ 1; 5×3 = 15 ≡ 1; 6×6 = 36 ≡ 1 (mod 7).
  4. Reading off the pairs: 1⁻¹ = 1, 2⁻¹ = 4, 3⁻¹ = 5, 4⁻¹ = 2, 5⁻¹ = 3, 6⁻¹ = 6.
  5. Addition is inherited from the integers, so it stays commutative and associative mod 7 with identity 0, and × distributes over +. So Z_7 is a commutative ring with unity where every nonzero element is invertible: a field.
  6. Check the required answer: 3×5 = 15 = 2×7 + 1, so 3×5 ≡ 1 (mod 7).

Answer. Every nonzero element of Z_7 has an inverse, so Z_7 is a field, and 3⁻¹ ≡ 5 (mod 7).

Worked example 2

Question. In GF(2⁴) built with m(x) = x⁴ + x + 1, reduce x⁴ and find the product (x + 1)(x + 1).

  1. In the field, x⁴ + x + 1 ≡ 0, so x⁴ ≡ x⁴ + (x⁴ + x + 1) = x + 1 (mod m(x)), since x⁴ + x⁴ = 0 and 1 + 1 = 0 over GF(2).
  2. Multiply as polynomials over GF(2): (x + 1)(x + 1) = x² + x + x + 1 = x² + 1, because x + x = 0.
  3. The degree is 2, less than 4, so no reduction is needed.

Answer. x⁴ ≡ x + 1, and (x + 1)(x + 1) = x² + 1 in GF(2⁴).

Exam traps

  • Z_n is a field only when n is prime. Z_6, Z_8 and Z_9 are rings with zero divisors, not fields.
  • GF(2^m) is not Z_{2^m}. In Z_8, 2×4 ≡ 0; GF(8) has no zero divisors at all.
  • A group has one operation. The question 'is Z_6 a group?' is incomplete until you say addition or multiplication.
  • The order of an element is not the order of the group. In Z_7* the group order is 6, but the element 6 has order 2.
  • Multiplication in GF(2^m) is not integer multiplication mod 2^m; you must reduce the polynomial product by the chosen irreducible polynomial.

2.4 Prime numbers and primality testing

A prime is an integer greater than 1 whose only positive divisors are 1 and itself. Primes are the atoms of the integers: every integer greater than 1 factors into primes in one way, apart from the order of the factors. Cryptography uses large primes as secret ingredients; RSA and Diffie-Hellman, in Unit 4, need them. Factoring a large product is hard, but testing whether a number is prime is fast. That gap is the engine of public-key security. This chapter shows how to test primality without factoring.

You need: modular arithmetic and gcd computation.

Primes as atoms

A prime has no divisor except 1 and itself. A composite number has a smaller factor. The list starts 2, 3, 5, 7, 11, 13. The number 1 is not prime, and 2 is the only even prime.

The fundamental theorem of arithmetic says every integer n > 1 is a product of primes, and that product is unique apart from order. For example, 341 = 11 × 31.

n = p₁^e₁ × p₂^e₂ × … × pₖ^eₖ

p₁, p₂, …, pₖ are distinct primes; e₁, e₂, …, eₖ are positive integer exponents; n is any integer greater than 1.

Euclid proved there are infinitely many primes. Suppose the list were finite: p₁, p₂, …, pₖ. Let N = p₁p₂…pₖ + 1. Dividing N by any listed prime leaves remainder 1, so N has a prime factor not on the list. Contradiction.

Crypto needs primes of hundreds of bits. Key generation for RSA, in Unit 4, picks two large primes p and q and publishes n = pq. Anyone who factors n can break the key. Factoring is believed hard; primality testing is easy.

From trial division to Miller-Rabin

Trial division tries every prime up to √n. It proves primality, but for a 1024-bit n, √n has about 512 bits. Listing those primes is impossible.

The Fermat probable-prime test uses Fermat's little theorem: if n is prime and gcd(a, n) = 1, then a^(n−1) ≡ 1 (mod n). Compute the power by fast modular exponentiation. If the result is not 1, n is composite. If it is 1, call n a probable prime for base a. Primes always pass; some composites also pass.

Carmichael numbers pass Fermat for every base coprime to n. The number 341 is not a Carmichael number, but it passes the Fermat test for base 2 (2³⁴⁰ ≡ 1 mod 341). Miller-Rabin with base 2, shown below, still rejects it. One pass is not proof.

Assume n is odd and n > 2. (Even n > 2 is composite at once.) Then write n − 1 = 2^s d with d odd.

n − 1 = 2^s × d

s is the number of factors 2 in n−1; d is the odd part of n−1; s ≥ 1 for odd n.

  1. Write n − 1 = 2^s d with d odd.
  2. Choose a base a with 2 ≤ a ≤ n − 2.
  3. Compute x = a^d mod n.
  4. If x = 1 or x = n − 1, stop: probable prime for this base.
  5. Repeat s − 1 times: replace x by x² mod n. If x = n − 1, stop: probable prime for this base. If x = 1, stop: composite.
  6. After the loop ends without stopping, declare composite.

This is the Miller-Rabin test. A composite that passes is a strong pseudoprime to base a. For any odd composite n, at most 1/4 of the bases a chosen uniformly from {2, 3, …, n − 2} pass one round. With t independent random bases, the error is at most 4^(−t).

P(error) ≤ 4^(−t)

t is the number of independent Miller-Rabin rounds; P(error) is the chance that a composite is accepted as probable prime.

Generating a random prime

To generate a k-bit prime, pick a random odd integer with top bit 1 and k bits. Run Miller-Rabin with t bases. If it passes, use it as the prime; else pick another candidate. The test rejects almost all composites at once.

About 1 in 355 odd 1024-bit numbers is prime, so a generator may try a few hundred candidates. Each failed candidate costs only a few modular exponentiations. RSA key generation uses this loop, then checks gcd(e, p−1) = 1. See Unit 4, RSA.

Worked example

Question. Use the Miller-Rabin test with base a = 2 to test n = 341. Show s, d, the first value of x, the squared value, and decide whether 341 is prime or composite.

  1. Write n − 1 = 341 − 1 = 340.
  2. Factor 340 = 4 × 85 = 2² × 85. So s = 2 and d = 85.
  3. Compute x = 2⁸⁵ mod 341. Since 2¹⁰ = 1024 = 3 × 341 + 1, 2¹⁰ ≡ 1 (mod 341). Also 85 = 8 × 10 + 5, so 2⁸⁵ = (2¹⁰)⁸ × 2⁵ ≡ 1 × 32 = 32 (mod 341). Thus x = 32.
  4. Check: x is not 1 and not 340, so continue.
  5. Square x: 32² = 1024 ≡ 1 (mod 341). Now x = 1. The previous value was 32, not 340, so 341 is composite.
  6. Factor check: 341 = 11 × 31.

Answer. 341 is composite: Miller-Rabin with base 2 gives s = 2, d = 85, first x = 32, then x = 1 after squaring, so 341 fails the test.

Exam traps

  • A single Fermat pass is not a proof: 341 passes base 2 but is composite. Carmichael numbers pass Fermat for all coprime bases.
  • Do not confuse probable prime with proven prime. Miller-Rabin gives a tiny error probability, not certainty, unless you use a deterministic base set for small n.
  • In Miller-Rabin, if squaring gives x = 1 and the previous x was not n − 1, the number is composite. Students often accept it as prime.
  • Keep s and d correct: n − 1 = 2^s d with d odd. For 341, s = 2 and d = 85, not s = 4 or d = 340.
  • Trial division up to √n is exact but too slow for large crypto primes. It is not the test used in RSA key generation.

2.5 Fermat's and Euler's theorems

Exponents modulo n repeat in a cycle. Fermat's little theorem and Euler's theorem measure that cycle: for a prime p, the cycle length divides p−1; for any modulus n, it divides φ(n), the count of numbers coprime to n. Once you know the cycle length, a huge exponent can be cut down before you compute. This is the everyday trick behind RSA, Diffie–Hellman and ElGamal, where exponentials are huge and the modulus is large. It also gives a quick way to find modular inverses.

You need: Chapter 2.1 for congruences, Chapter 2.3 for group order, and Chapter 2.4 for primes and factorization.

Fermat's little theorem

Work modulo a prime p. The nonzero residues 1, 2, …, p−1 form a group under multiplication (Chapter 2.3). Its size is p−1. For any a with p ∤ a, the powers a, a², a³, … run inside that group and eventually return to 1. The number of steps before the first return divides the group size p−1.

ap−1 ≡ 1 (mod p)

p is prime; a is an integer with p ∤ a (p does not divide a). The exponent is p−1, not p.

Multiplying both sides by a gives ap ≡ a (mod p). This also holds when p | a, because both sides are 0 modulo p. The form is the basis of the Fermat primality test; Chapter 2.4 explains why one pass is not proof.

  1. Write the exponent e as e = q(p−1)+r with 0 ≤ r < p−1.
  2. Replace ae by ar modulo p, because (ap−1)q ≡ 1q ≡ 1.
  3. Compute ar modulo p by repeated squaring.

Euler's totient and Euler's theorem

φ(n) counts the integers k with 1 ≤ k ≤ n and gcd(k,n)=1. These are exactly the residues that have inverses modulo n. For a prime p, every k from 1 to p−1 is coprime to p, so φ(p)=p−1.

φ(n) = n × (1 − 1/p₁) × (1 − 1/p₂) × … × (1 − 1/p<sub>r</sub>)

p₁, …, pr are the distinct primes that divide n; φ(n) counts integers k with 1 ≤ k ≤ n and gcd(k,n)=1.

For n=10=2×5, φ(10)=10(1−1/2)(1−1/5)=4. The four residues are 1, 3, 7, 9. For n=12=2²×3, φ(12)=12(1−1/2)(1−1/3)=4; the residues are 1, 5, 7, 11.

aφ(n) ≡ 1 (mod n)

n is a positive integer; a is an integer with gcd(a,n)=1.

Set e=φ(n)−1. Then a·aφ(n)−1 ≡ 1 (mod n), so the inverse of a modulo n is aφ(n)−1 mod n. For example, 3φ(10)−1 = 3³ = 27 ≡ 7 (mod 10), and 3×7=21≡1.

Reducing exponents and the converse trap

Euler's theorem turns exponent arithmetic into arithmetic modulo φ(n). If e = qφ(n)+r with 0 ≤ r < φ(n), then the exponent can be replaced by r.

ae ≡ ar (mod n)

e = qφ(n)+r with 0 ≤ r < φ(n); valid when gcd(a,n)=1.

The reduction is modulo φ(n), never modulo n. For 3¹⁰⁰ mod 7, the correct exponent reduction uses 100 mod 6 = 4; using 100 mod 7 = 2 gives the wrong value 2.

The converse of Fermat's theorem fails. A composite n can satisfy an−1 ≡ 1 (mod n) for every a coprime to n. Such n are Carmichael numbers; 561=3×11×17 is the smallest. So this test cannot prove primality.

RSA uses modulus N=pq and reduces exponents modulo φ(N)=(p−1)(q−1); see Unit 4, RSA cryptosystem.

Worked example

Question. Find 3¹⁰⁰ mod 7 using Fermat's little theorem. Show every step.

  1. The modulus 7 is prime and 7 does not divide 3, so Fermat's little theorem applies: 3⁶ ≡ 1 (mod 7).
  2. Divide the exponent by 6: 100 = 6×16 + 4, so the quotient is 16 and the remainder is 4.
  3. Write 3¹⁰⁰ = (3⁶)¹⁶ × 3⁴.
  4. Replace 3⁶ by 1 modulo 7: (3⁶)¹⁶ × 3⁴ ≡ 1¹⁶ × 3⁴ ≡ 3⁴ (mod 7).
  5. Compute 3⁴ = 81.
  6. Divide 81 by 7: 81 = 7×11 + 4, so 81 ≡ 4 (mod 7).

Answer. 3¹⁰⁰ mod 7 = 4.

Exam traps

  • Using Fermat's theorem with a composite modulus. The theorem needs a prime p; for composite n use Euler's theorem with φ(n), and only when gcd(a,n)=1.
  • Reducing the exponent modulo n instead of modulo p−1 or φ(n). In 3¹⁰⁰ mod 7, reduce 100 modulo 6, not modulo 7.
  • Forgetting the condition gcd(a,n)=1. Euler's theorem does not apply to a=2, n=4, because φ(4)=2 but 2²=4≡0 (mod 4).
  • Treating ap−1 ≡ 1 (mod p) as a primality proof. Carmichael numbers such as 561 pass the test while composite.
  • Writing φ(p)=p for a prime p. It is p−1, because p itself is not coprime to p.

2.6 Chinese remainder theorem

The Chinese remainder theorem (CRT) says that one congruence modulo a product can be split into separate congruences modulo coprime factors. Solve the small pieces, then glue the answers back into one value modulo the product. It exists because many modular calculations are easier with small moduli. It is used to speed up RSA decryption, to share secrets, and to solve systems of congruences in coding and cryptography.

You need: congruences from Chapter 2.1 and modular inverses from Chapter 2.2.

Split, solve, recombine

Two integers m and n are coprime when gcd(m,n)=1. A list of moduli is pairwise coprime when every pair has gcd 1. For example, 3, 5 and 7 are pairwise coprime; 4 and 6 are not, because gcd(4,6)=2.

Let m₁, m₂, …, mₖ be pairwise coprime moduli, and let M = m₁m₂⋯mₖ. Let a₁, a₂, …, aₖ be any chosen residues. The system x ≡ a₁ (mod m₁), x ≡ a₂ (mod m₂), …, x ≡ aₖ (mod mₖ) has exactly one solution modulo M.

x ≡ a₁ (mod m₁), x ≡ a₂ (mod m₂), …, x ≡ aₖ (mod mₖ)

x is the unknown integer; aᵢ is the required residue for modulus mᵢ; the moduli mᵢ are pairwise coprime; M is their product; the solution is unique modulo M.

Uniqueness is simple. If x and x′ both solve the system, then mᵢ divides x − x′ for every i. Because the mᵢ are pairwise coprime, their product M also divides x − x′. So x ≡ x′ (mod M). The theorem does not say the solution is a small number; it says the solution is one class modulo M.

The generalized form drops the pairwise coprime condition in a limited way. For moduli that are not coprime, a system may have no solution or several solutions modulo the product. A solution exists only when every pair of congruences agrees on their common factor, that is, aᵢ ≡ aⱼ (mod gcd(mᵢ,mⱼ)). The full proof is not needed here. For cryptography, the coprime case is the one used.

The construction with Mᵢ and inverses

The standard construction turns each congruence into a term that is 1 modulo its own modulus and 0 modulo every other modulus. Set Mᵢ = M / mᵢ. Since the moduli are pairwise coprime, gcd(Mᵢ, mᵢ)=1, so Mᵢ has an inverse modulo mᵢ. Call that inverse yᵢ, so Mᵢ yᵢ ≡ 1 (mod mᵢ).

x = (a₁M₁y₁ + a₂M₂y₂ + … + aₖMₖyₖ) mod M

Mᵢ = M/mᵢ; yᵢ = Mᵢ⁻¹ mod mᵢ; the whole sum is reduced modulo M at the end.

  1. Check gcd(mᵢ,mⱼ)=1 for every i≠j.
  2. Compute M = m₁m₂⋯mₖ.
  3. For each i compute Mᵢ = M/mᵢ.
  4. Find yᵢ = inverse of Mᵢ modulo mᵢ, using the extended Euclidean algorithm.
  5. Compute S = a₁M₁y₁ + a₂M₂y₂ + … + aₖMₖyₖ.
  6. Answer x = S mod M.

Why the terms work: for j ≠ i, Mⱼ contains the factor mᵢ, so Mⱼ ≡ 0 (mod mᵢ). The only term that survives modulo mᵢ is aᵢMᵢyᵢ, and Mᵢyᵢ ≡ 1 (mod mᵢ), so the sum is ≡ aᵢ (mod mᵢ).

This construction is a formula, not a search. It solves any number of pairwise coprime congruences in one pass. Always reduce the final sum modulo M. The unreduced sum can be much larger than M.

Use in cryptography

RSA decryption computes c^d mod n, with n = pq. CRT lets the receiver compute the result modulo p and modulo q separately, then combine. Each exponentiation uses numbers about half the bit length, so it is faster than one exponentiation modulo n. The private key often stores p, q and the CRT inverses for this reason. See Unit 4, Public Key Cryptography and Hashing, for RSA itself.

Secret sharing uses CRT as one classic construction. A dealer picks pairwise coprime moduli and gives each person one residue. A large enough set of residues determines the secret modulo the product; a smaller set leaves many possible values. This is a threshold idea, related to but different from Shamir's polynomial scheme.

CRT also appears in fast arithmetic: represent a big integer by its residues modulo several small primes, do addition and multiplication componentwise, then reconstruct. It is a bridge between one large modulus and several small ones.

2.7 Quadratic residues, Legendre and Jacobi symbols

A quadratic residue modulo a prime p is a number that equals some square modulo p. The Legendre symbol packs the answer into one value: 1 for a square, −1 for a non-square, 0 for a multiple of p. Euler's criterion computes it with one exponent. The Jacobi symbol extends the same idea to odd composite moduli and is calculated by reciprocity without factoring. These symbols appear in primality testing, square-root algorithms and RSA-style cryptosystems. Only a few universities teach this topic.

You need: modular arithmetic, Fermat's theorem and Euler's criterion, and the Chinese remainder theorem.

Squares modulo a prime

Fix an odd prime p. An integer a with p∤a is a quadratic residue modulo p when x² ≡ a (mod p) has a solution x. Otherwise a is a quadratic non-residue. The squares of 1, 2, …, p−1 produce every quadratic residue modulo p, each nonzero square twice. Each square has exactly two roots, x and p−x, because (p−x)² ≡ x² (mod p). So the p−1 nonzero residues split into (p−1)/2 squares and (p−1)/2 non-squares. For p = 11, 1²=1, 2²=4, 3²=9, 4²=16≡5, 5²=25≡3. The reverse order repeats: 6²≡3, 7²≡5, 8²≡9, 9²≡4, 10²≡1. The residues are {1,3,4,5,9}; the non-residues are {2,6,7,8,10}. Listing squares costs about p multiplications. The symbols below answer the same question much faster. This split is why half of all nonzero values are squares. A residue has a root below p/2 and one above p/2; a non-residue has none.

Legendre symbol and Euler's criterion

For an odd prime p and integer a, the Legendre symbol (a/p) is 0 if p divides a, 1 if a is a nonzero square modulo p, and −1 otherwise. Euler's criterion computes it: a^{(p−1)/2} ≡ (a/p) (mod p). The right side is 0, 1 or −1, so reduce the power modulo p and replace p−1 by −1. The symbol is multiplicative in the numerator: (ab/p) = (a/p)(b/p). Also (a²/p)=1 when p∤a. Quadratic reciprocity links two distinct odd primes p and q: (p/q)(q/p) = (−1)^{((p−1)/2)((q−1)/2)}. It lets you flip a symbol and reduce the numerator, like the Euclidean algorithm. For example, (2/11) uses Euler: 2⁵=32≡10≡−1, so (2/11)=−1. The next section keeps the same notation for composite moduli. The law is symmetric: swapping p and q changes the sign only when both primes are 3 mod 4.

Jacobi symbol for composite moduli

Let n be an odd positive integer with prime factorisation n = ∏ p_i^{e_i}. The Jacobi symbol is (a/n) = ∏ (a/p_i)^{e_i}. It equals 0 when gcd(a,n)>1, and ±1 otherwise. You compute it by the same rules: it depends only on a mod n, it is multiplicative in the numerator, and reciprocity holds for odd coprime m and n: (m/n)(n/m) = (−1)^{((m−1)/2)((n−1)/2)}. The supplement rules supply the values for −1 and 2: (−1/n) = (−1)^{(n−1)/2}, and (2/n) = (−1)^{(n²−1)/8}. A value of 1 does not prove that a is a square modulo n. Take n=15=3·5 and a=2. Then (2/15)=(2/3)(2/5)=(−1)(−1)=1. But the squares modulo 15 are 1,4,9,1,10,6,4,4,6,10,1,9,4,1; the value 2 is missing. So Jacobi 1 means an even number of prime factors report 'non-residue', not that a has a square root. The Jacobi symbol costs O(log² n) bit operations, like the Euclidean algorithm. It is a fast filter, not a complete square test. For prime n it agrees with the Legendre symbol. For composite n it can lie in the positive direction.

Beyond the syllabus

Not for the exam. The Jacobi symbol drives the Solovay–Strassen primality test and the Baillie–PSW test, and it appears in the quadratic sieve factoring method. Takeaways

  1. Two integers are congruent modulo n exactly when n divides their difference, so arithmetic can use remainders from 0 to n−1.
  2. The Euclidean algorithm finds gcd by repeated remainder; the extended version also gives a modular inverse when gcd is 1.
  3. A field supplies addition, subtraction, multiplication and division by nonzero elements, which is what many public-key formulas need.
  4. Large primes are chosen randomly and tested; a primality test answers prime or composite without factoring the number.
  5. Fermat and Euler theorems let you reduce large exponents modulo p or φ(n), which makes modular exponentiation practical.
  6. The Chinese remainder theorem turns one congruence modulo a product into smaller independent congruences and back again.
  7. Quadratic residues detect squares modulo p; Legendre and Jacobi symbols test this by calculation rather than listing squares.
  8. A modular inverse exists only for coprime numbers, a condition that underlies RSA key setup and many cryptographic steps.

Glossary

Abelian group
A group whose operation is commutative.
Bézout identity
The equation ax+by=gcd(a,b) for suitable integers x and y.
Chinese remainder theorem
A system of congruences with coprime moduli has a unique solution modulo their product.
Composite
An integer greater than 1 that is not prime.
Congruence
The relation a≡b (mod n), meaning n divides a−b.
Coprime
Two integers whose greatest common divisor is 1.
Euclidean algorithm
A repeated-remainder method that computes the greatest common divisor of two integers.
Euler's criterion
For odd prime p and p∤a, a^((p−1)/2)≡(a/p) (mod p).
Euler's theorem
For gcd(a,n)=1, a^φ(n)≡1 (mod n).
Euler's totient function
φ(n) counts the integers from 1 to n that are coprime to n.
Extended Euclidean algorithm
The Euclidean algorithm plus back-substitution, producing Bézout coefficients and modular inverses.
Fermat's little theorem
For prime p and a not divisible by p, a^(p−1)≡1 (mod p).
Field
A commutative ring in which every nonzero element has a multiplicative inverse.
Finite field
A field with finitely many elements; GF(p) has p elements for prime p.
Greatest common divisor
The largest positive integer that divides both given integers.
Group
A set with one operation that is closed, associative, has an identity, and has inverses.
Jacobi symbol
A generalization of the Legendre symbol to odd composite moduli by multiplying over prime factors.
Legendre symbol
(a/p) records whether a is a quadratic residue, nonresidue, or zero modulo odd prime p.
Modular arithmetic
Arithmetic in which numbers are reduced to remainders modulo a fixed integer.
Modular inverse
An integer a⁻¹ such that a·a⁻¹≡1 (mod n), existing exactly when gcd(a,n)=1.
Modulus
The fixed positive integer n used in a congruence or remainder system.
Primality test
An algorithm that answers prime or composite for a given integer.
Prime
An integer greater than 1 with no positive divisors other than 1 and itself.
Quadratic residue
An integer a that equals some square x² modulo p.
Residue
The remainder r in 0≤r<n when an integer is divided by n.
Ring
A set with addition and multiplication satisfying the distributive and additive group laws.
