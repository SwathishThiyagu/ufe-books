1.1 Origins and applications of image processing and vision

Image processing and computer vision both turn pictures into numbers and then into useful results. Image processing takes an image in and gives an image out: sharper, smaller, cleaner. Computer vision takes an image in and gives a description, count or decision: “cheque valid”, “lane clear”, “tumour present”. The same chain runs from a scene to a sensor to a digital image to a process to a decision. You meet it in hospital scans, satellite maps, OCR (optical character recognition), factory inspection, robots, security cameras, entertainment filters and QR or cheque scanning.

One picture, two outputs

A digital image is a grid of numbers. Each element of the grid is a pixel, and the number stored at it is the brightness (intensity) of that pixel. A grayscale image stores one number per pixel; a colour image stores one number per channel, for example three numbers per pixel in RGB. Image processing changes those numbers and returns another image. Examples are contrast stretching of an X-ray, noise removal from a scanned form and compression of a photo. Computer vision uses the numbers to answer a question. It returns a label, a count, a position or an action. Reading a vehicle number plate and deciding whether a seat belt is worn are vision tasks.

The field grew from three pressures. Newspaper picture transmission needed pictures sent over long wires, so images had to be coded, sent and rebuilt. Medical imaging produced X-ray, ultrasound, CT (computed tomography) and MRI (magnetic resonance imaging) pictures that needed enhancement and measurement. Satellite imaging produced large images of land and weather. Factory inspection added a fourth pressure: fast, repeatable checks of manufactured parts.

The two names mark the output, not the difficulty. Some syllabi call the image-to-image side digital image processing and the decision side computer vision. Both need acquisition, storage and display. The figure below sizes one cheque scan and sets the two outputs side by side; acquisition details are in 1.4 and system blocks in 1.2.

Output tells the task apart

The clean test is the output. If the output keeps the same pixel grid and only changes the brightness values (sharper, cleaner, smaller file), the task is image processing. If the output assigns a class, count, box, region label or action, the task is computer vision. A mask is a label map: one class label per pixel, not an improved copy of the input, so segmentation counts as vision. A system can contain both sides. A blur removal step is processing; the later character read is vision.

Worked example

Question. A shop scans a 1200×800 pixel cheque image at 8 bits per pixel. It stores three copies and sends them over a link. Find the size of one uncompressed copy in bytes and the total for three copies.

  1. Pixel count = W × H = 1200 × 800 = 960,000 pixels.
  2. Bits in one copy = 960,000 × 8 bits/pixel = 7,680,000 bits.
  3. Bytes in one copy = 7,680,000 ÷ 8 = 960,000 bytes.
  4. Using 1 MB = 1,000,000 bytes, one copy = 960,000 ÷ 1,000,000 = 0.96 MB.
  5. Three copies = 960,000 × 3 = 2,880,000 bytes = 2.88 MB.

Answer. One uncompressed copy is 960,000 bytes (0.96 MB); three copies are 2,880,000 bytes (2.88 MB).

Exam traps

  • Do not call every task computer vision. If the output keeps the same pixel grid and only changes the brightness values, it is image processing.
  • Do not mix bits and bytes. A pixel at 8 bits needs one byte; a 24-bit RGB pixel needs three bytes before compression.
  • Do not mix decimal and binary megabytes. The example uses 1 MB = 1,000,000 bytes; if a question uses 1 MB = 1,048,576 bytes, state it.
  • Do not think vision always means deep learning. Thresholding, edge detection and template matching are classical vision steps.
  • Do not forget that OCR, QR decoding and cheque reading contain both processing and vision parts.

1.2 Fundamental steps and components of image processing systems

A digital image system is not one program but a chain. Light from a scene reaches a sensor, the sensor's charge becomes numbers, and those numbers pass through a series of jobs: cleaned, sharpened, compressed, cut into objects, described, matched to a name. Each job has a physical home — a camera, a cable, a processor, a disk, a screen. So every first unit looks at the same system twice: the blocks you can point at, and the steps you can name. Both views let you place a new algorithm on the chain instead of treating it as an isolated trick.

You need: 1.1 Origins and applications for why the chain exists, and 1.4 Light, image sensing and acquisition for what happens inside the first block.

The functional chain: nine jobs from photons to a label

Look at any image system and ask two questions. What blocks does the signal pass through? What job does each block do? The first question gives physical components. The second gives functional steps, which some syllabi call the fundamental steps in digital image processing.

Acquisition turns scene energy into numbers: a lens and a sensor give a continuous signal, and a digitizer samples it on a grid and quantizes each sample to an integer. Preprocessing is the cheap cleaning done before any clever step — rescale intensities, remove a fixed sensor pattern, flatten uneven lighting.

Enhancement makes the picture look better to a human eye, such as brightening a night photo of a Chennai street. A viewer judges it, so two viewers may disagree. Restoration undoes a known damage — hand shake, motion blur, sensor noise. It needs a model of how the damage was made, and that model is the difference from enhancement.

Color processing works in a color space: correct a colour cast, or map a grey X-ray to false colour. Compression spends fewer bits on the same picture, so it sits before storage or transmission, not after. Segmentation cuts the image into parts — road, number plate, person. Representation and description turn a part into numbers: a boundary as a chain code, a region as its area and centroid. Recognition attaches the name: this region is a number plate.

  • Low level: image in, image out — acquisition, preprocessing, enhancement, restoration, color, compression.
  • Mid level: image in, attributes out — segmentation, representation.
  • High level: attributes in, decision out — recognition.
  • Not every system runs all nine. A barcode reader runs acquisition, threshold, decode.

The frame buffer must hold at least one full frame. For a 2048×2048 sensor at 12 bits per pixel that is 2048×2048×12 = 50,331,648 bits, about 6 MiB — the number worked out in the example below. A phone that scans a UPI QR code holds one small frame in the buffer, runs thresholding and decoding on the processor, and never writes to disk.

The sensor is not the digitizer. The sensor outputs a continuous voltage; the digitizer decides where to sample and how many brightness levels exist. Those two choices are resolution, and they are the subject of 1.6 Sampling and quantization.

Feedback: the chain is not one-way

The chain can point back; the figure draws one return arrow, from recognition to segmentation. If recognition keeps rejecting a region, the split was wrong, so you return to segmentation with a different threshold. If enhancement exposes noise that was invisible before, you return to restoration, or to acquisition for a longer exposure. If the compressed file misses its bit budget, you return to enhancement and soften it. Drawing these return arrows is correct engineering, not a mistake.

Some orders are fixed by purpose. Compression must come before storage or transmission, because its whole job is to save bits there. Representation must come before recognition, because a classifier compares numbers, not pixels. Color processing sits before compression in the figure because a colour transform is often the first stage of the compressor itself.

One order is a convention. Restoration and enhancement are both preparation; some books put restoration first because a degradation model is known and objective, while enhancement is judged by eye. Follow whichever order your syllabus draws and say why.

Worked example

Question. A machine-vision camera has a 2048×2048 pixel sensor and stores 12 bits per pixel. Raw frames go to a 4 GiB pen drive (sold as 4 GB). Ignoring file headers, find (a) the bits and bytes in one raw frame, (b) how many whole frames fit on the drive, and (c) where compression sits in the functional chain.

  1. Pixels per frame = 2048 × 2048 = 4,194,304 pixels.
  2. Bits per frame = 4,194,304 × 12 = 50,331,648 bits.
  3. Bytes per frame = 50,331,648 ÷ 8 = 6,291,456 bytes.
  4. In mebibytes = 6,291,456 ÷ 1,048,576 = 6 MiB exactly.
  5. Drive size = 4 GiB = 4 × 1024 = 4096 MiB.
  6. Whole frames = 4096 ÷ 6 = 682.67, so 682 frames; 682 × 6 = 4092 MiB used, 4 MiB left over.
  7. Compression sits after enhancement and restoration and before storage or transmission, since its purpose is to save bits exactly there.

Answer. One frame is 50,331,648 bits = 6,291,456 bytes = 6 MiB, 682 whole frames fit on the 4 GiB drive, and compression sits after enhancement/restoration and before storage or transmission.

Exam traps

  • Calling segmentation a low-level preprocessing step. It is mid-level: image in, attributes out. Thresholding a noisy night frame on raw intensities splits on noise, not on objects.
  • Putting compression before enhancement or restoration. You compress the picture you intend to keep; compressing earlier discards detail no later step can bring back.
  • Mixing up enhancement and restoration. Enhancement is subjective and needs no model; restoration is objective and needs a degradation model. Examiners love this pair.
  • Saying the sensor and the digitizer are the same block. The sensor gives a continuous signal; the digitizer (ADC) samples and quantizes it.
  • Drawing the chain as strictly one-way. Feedback from recognition back to segmentation, or from enhancement back to acquisition, is allowed and often expected.

1.3 Elements of visual perception and the human eye

The human eye is a compact optical sensor plus a neural processor. The cornea and lens form a focused image on the retina; rods and cones convert light into signals; the optic nerve carries them to the brain. Its response to brightness is strongly nonuniform: we notice ratios of intensity more than absolute changes, and we adapt over a huge range. This matters in image processing because a display, camera or algorithm must respect those limits when it decides what a viewer can see.

You need: 1.1 Origins and applications for what a digital image is and where processing sits.

The eye as an optical instrument

The eye is an optical instrument. Light first crosses the cornea, a clear curved layer that does most of the bending. It then passes through the aqueous humour, a watery fluid, and through the pupil. The iris is the colored ring that opens or closes the pupil; the pupil is the aperture that controls how much light enters. The lens sits behind the pupil. It is flexible and changes shape to focus on near or far objects. This change is called accommodation. The vitreous humour, a jelly-like fluid, fills the space behind the lens and holds the retina in place. The cornea and lens together form an inverted, reduced image on the retina. The retina is the sensor surface: it contains light-sensitive cells. Pupil control is fast, like a camera aperture; accommodation is slower, like autofocus. A camera can imitate both, but the eye does not produce a uniform pixel grid. Its sampling and sensitivity vary across the retina. Some syllabi call this set of ideas elements of visual perception.

Retina: rods, cones, fovea and blind spot

The retina has two main types of photoreceptor. Rods work in dim light. They are many, they are sensitive, and they do not signal color. Cones work in brighter light. They signal color and fine detail. The fovea is a small central pit packed with cones. When you look directly at a word, its image falls on the fovea. Away from the fovea, rods dominate and acuity falls. This is why you move your eyes to read. The optic nerve leaves the retina at a point with no photoreceptors, the blind spot. The brain fills in the missing area, so you do not see a hole. The retina also performs early processing before signals leave the eye. Its cells compare neighboring responses, sharpen edges and compress the range of light levels. So vision is not a camera sending raw pixels. The eye sends a processed signal. For image processing, the lesson is that spatial resolution and brightness sensitivity are not uniform over the field of view. A fixed grid of pixels is a useful engineering model, not a copy of the retina. Color behavior is covered in 1.9 Color models.

Brightness adaptation and discrimination

Brightness adaptation is the eye's change of sensitivity with light level. In dark adaptation, the pupil widens and the photoreceptors become more sensitive over minutes. In light adaptation, the reverse happens quickly. This lets you read a phone at night and then step into sunlight, though not instantly. Brightness discrimination is the ability to detect a small change in intensity. The smallest detectable change is the just noticeable difference, written ΔI. The background intensity is I. Over a middle range, the ratio ΔI/I is roughly constant. This ratio is the Weber ratio, and the constant is the Weber fraction k. A small k means fine discrimination. If I doubles, the smallest detectable ΔI also roughly doubles. A fixed ΔI is therefore not equally visible at all levels. The exact k varies with background, observer and measurement. Contrast sensitivity describes how well the eye sees patterns of different spatial frequency at low contrast. It is high for some middle frequencies and falls for very fine or very coarse patterns. Mach bands are bright and dark bands seen near an edge. They appear because neighboring retinal responses inhibit each other. The eye does not report intensity directly; it reports local contrast. A display with limited gray levels, or an algorithm that stretches contrast, must respect these limits. Otherwise smooth gradients can show false bands.

ΔI / I ≈ k

ΔI is the smallest detectable change in intensity; I is the background intensity; k is the Weber fraction, a dimensionless number roughly constant over a middle range.

Worked example

Question. A display has background intensity I = 50 cd/m². A test patch is just noticeable when its intensity is 52 cd/m². Find ΔI and the approximate Weber fraction. If the background rises to 100 cd/m² at the same fraction, estimate the new just-noticeable ΔI.

  1. Identify the background intensity I = 50 cd/m² and the just-noticeable test intensity I + ΔI = 52 cd/m².
  2. Find the intensity change: ΔI = 52 − 50 = 2 cd/m².
  3. Find the Weber fraction: ΔI/I = 2/50 = 0.04. This is dimensionless.
  4. At I = 100 cd/m², use the same fraction: ΔI ≈ 0.04 × 100 = 4 cd/m².

Answer. ΔI = 2 cd/m², ΔI/I = 0.04, and at I = 100 cd/m² the new just-noticeable ΔI is about 4 cd/m².

Exam traps

  • Pupil and lens are not the same control. The pupil changes aperture and light level; the lens changes focus by accommodation.
  • Rods and cones are not interchangeable. Rods give dim-light vision without color; cones give color and detail in brighter light.
  • The Weber ratio is ΔI/I, not ΔI. At a higher background I, the same ratio allows a larger absolute change ΔI.
  • The blind spot is where the optic nerve leaves the retina. It is not the fovea, and it is not a lack of attention.
  • Fovea does not mean high light sensitivity. It means high acuity from dense cones; rods dominate in dim peripheral vision.

1.4 Light, image sensing and image acquisition

A camera records numbers from a sensor, not a picture. Scene energy, usually light, falls on a sensor, which gives an electrical signal; a digitizer turns that signal into integers. This chapter follows the chain: spectrum bands that carry scene information, sensor response to light, and single, line and array arrangements that build a two-dimensional image.

You need: Chapter 1.1 for where these images are used, and Chapter 1.3 for the eye as a reference sensor.

Light and the electromagnetic spectrum

Imaging records energy that leaves a scene. Most of it is electromagnetic radiation, described by its wavelength λ, the distance between successive crests, measured in metres. Imaging bands are quoted in nm (10⁻⁹ m) or µm (10⁻⁶ m). The wavelength decides what the radiation interacts with, so each band reveals different material.

  • Visible: about 400 nm (violet) to 700 nm (red). Reflected sunlight or a lamp; ordinary photography.
  • X-ray: about 0.01 nm to 10 nm. Passes through soft tissue, blocked by bone and metal; medical and industrial inspection.
  • Ultraviolet: about 10 nm to 400 nm. Fluorescence and surface cracks.
  • Infrared: about 700 nm to 1 mm. Emitted heat and reflected near-infrared; night vision and thermal cameras.
  • Microwave and radio: 1 mm to metres. Radar, satellite imaging, and MRI radio pulses.

When radiation reaches an object, part is reflected, part absorbed and part transmitted. Reflectance ρ(λ) is the fraction reflected at wavelength λ, between 0 and 1. A leaf reflects green and absorbs red and blue, so it looks green. The sensor records the radiation leaving the scene: reflected source light plus any light the object emits.

E = P / (4πd²)

E is the irradiance on the surface in W/m², P is the radiant power of a point source in W, and d is the source-to-surface distance in m. Doubling d quarters E, which is why a lamp-lit photo dims fast with distance.

From photons to numbers

A sensor converts incident radiation into an electrical signal. In silicon cameras (CCD and CMOS), a photon frees an electron, and electrons collect as charge proportional to the light on that element during exposure. Readout gives a voltage v, and v ≈ R·E·t, where v is output voltage in V, R is responsivity in V·m²/J, E is irradiance in W/m², and t is exposure time in s. Since 1 J = 1 W·s, R·E·t has units of volts. Doubling t doubles v until the element saturates; in darkness a small noise floor remains.

The sensor output is continuous in space and value. The digitizer, or ADC (analog-to-digital converter), does two jobs: sampling fixes the positions or instants at which the signal is read, and quantization rounds each reading to the nearest of a fixed set of integers. In an array camera the sensor element grid fixes the positions and the ADC quantizes. Sampling and quantization rules are in Chapter 1.6.

A pixel (picture element) is one sample on the image grid. Bit depth is the number of bits b stored per sample; the sample takes 2^b levels, from 0 to 2^b − 1, so 8 bits gives 256 levels and 12 bits gives 4096. A frame is one complete two-dimensional image captured at one instant; video is a sequence of frames, and frame rate is in frames per second (fps). A sensor element is not a display pixel: a line sensor may have 4096 elements while the screen has 1920 columns.

storage = rows × columns × b bits

rows and columns are the image dimensions in pixels and b is the bit depth in bits per pixel. Divide by 8 for bytes.

Three sensor arrangements

A single sensing element measures one point, so a two-dimensional image needs relative motion. In the classic drum-scanner and laboratory stage setup the sensor stays fixed and the object moves on a stage:

  1. Place the object on a stage and illuminate it.
  2. Read the element once; that gives one pixel.
  3. Step the stage along one axis and read again, building one image row.
  4. Step the stage along the perpendicular axis and repeat until all rows are collected.

This single-sensor method is slow but cheap, and some syllabi call it the single-sensor arrangement. A line sensor is a row of elements, for example 4096 side by side: one exposure gives a whole image row, and as the scene moves past at constant speed, row after row is appended. That is a pushbroom scan, used in Earth-observation satellites, flatbed document scanners and web-inspection cameras. An array sensor is a two-dimensional grid, for example 1920 × 1080 elements; one exposure gives a full frame at one instant, as in phone and machine-vision cameras.

The choice follows the motion. Array sensors suit moving or momentary scenes; line and single sensors suit flat or steadily moving objects and give very high resolution along one axis. Sampling is uniform when points are equally spaced in both directions, the normal case, and nonuniform when spacing varies, for example a log-polar grid dense at the centre. Nonuniform grids complicate indexing, so most pipelines resample them to a uniform grid.

Worked example

Question. A line sensor has 4096 elements and 12 bits per pixel. It scans a page 3000 lines long, at 400 lines per second. Find the raw image size in bytes and in MB and MiB, and the scan time in seconds.

  1. Pixels = elements per line × number of lines = 4096 × 3000 = 12,288,000 pixels.
  2. Bits = pixels × bits per pixel = 12,288,000 × 12 = 147,456,000 bits.
  3. Bytes = bits ÷ 8 = 147,456,000 ÷ 8 = 18,432,000 bytes.
  4. Decimal MB = 18,432,000 ÷ 10⁶ = 18.432 MB.
  5. Binary MiB = 18,432,000 ÷ 1,048,576 = 17.578125 MiB, about 17.58 MiB.

1.5 Image formation models and photometric image formation

An image forms in two separate steps. Geometry decides where a scene point lands on the sensor: a point at camera position (X, Y, Z) maps near (f X/Z, f Y/Z). Photometry decides how bright that pixel becomes: scene radiance passes through the lens, becomes irradiance on the sensor, and is converted to a number. Phone cameras, CCTV and ball-tracking in cricket depend on both. Keep the two models apart and most image-formation problems become simple. Some syllabi call the combined topic image formation.

You need: 1.4 for how light becomes a signal, and 1.2 for where acquisition sits in the system chain.

Geometry: where a point lands

World coordinates (Xw, Yw, Zw) fix the scene. Camera coordinates (X, Y, Z) are the same point after rotation and translation; this chapter uses only camera coordinates. Finding that rotation and translation is camera calibration, in Unit 5. Image coordinates (x, y) are distances on the sensor, in metres, before pixels.

Put the camera at the origin with its Z axis forward. A scene point has Z > 0. The image plane sits at distance f from the pinhole, where f is the focal length in metres. Pinhole projection is:

x = f X/Z, y = f Y/Z

x and y are image-plane coordinates from the principal point; f is focal length in metres; X, Y, Z are camera coordinates in metres; Z is depth. Use magnitudes if your image plane is drawn behind the pinhole.

A point twice as far has half the image displacement. A real lens adds focus. The thin-lens equation is:

1/f = 1/u + 1/v

f is focal length; u is object distance from the lens; v is image distance from the lens. Use the same unit for all three. For a real object and real image, v > 0.

Magnification is m = -v/u. A negative m means an inverted image; size uses |m|. For sensor width w, field of view is θ = 2 arctan(w/(2f)). Depth of field is the range of u that stays acceptably sharp; a smaller aperture and shorter f enlarge it.

Photometry: how bright the pixel becomes

Radiance L is power per unit area per unit solid angle leaving a surface, in W/(m²·sr). Irradiance E is power per unit area falling on a surface, in W/m². The lens collects radiance and delivers irradiance to the sensor. A usable proportionality is E ∝ L (d/f)², where d is aperture diameter; the missing constant is not needed here.

Reflectance ρ is the fraction of incident irradiance reflected, 0 ≤ ρ ≤ 1. A Lambertian surface has the same radiance in every direction. Its outgoing radiance is Lo = (ρ/π) Ei. The BRDF is the general function for this; for a Lambertian surface it is ρ/π. Only a few syllabi go deeper.

Shading comes from geometry. If light arrives at angle θ to the surface normal, Ei = E0 cos θ. Then Lo = (ρ/π) E0 cos θ. This cosine law makes a sphere bright near the light and dark at the edge. The sensor converts irradiance to charge over exposure time t: pixel value = g E t + offset, then clipped and quantized. Quantization is in 1.6.

Using both models

Geometry says where; photometry says how bright. In the worked example, geometry puts a 20 mm object at 500 mm from a 50 mm lens as an inverted 2.22 mm image. Photometry sets the pixel values on that image.

A pinhole has infinite depth of field and no focus, but collects little light. A lens collects more and focuses one distance; other distances blur. Field of view depends on sensor size and focal length, not object distance. Depth of field depends on aperture, focal length and distance.

1.6 Sampling and quantization; spatial and intensity resolution

An image sensor makes a continuous pattern of voltages; a computer stores numbers. Sampling chooses which points exist: it keeps brightness on a grid and drops the spaces between. Quantization chooses how many brightness values each point may take. Together they turn a scene into a finite array of integers: the digital image. Every camera, scanner, ultrasound machine and phone screen uses both steps. Choose them badly and detail is lost before any algorithm runs; choose them wastefully and storage and bandwidth bills grow.

You need: 1.4 for how a sensor turns light into a signal, and 1.5 for what brightness at a point means.

Sampling turns a continuum into a grid

A continuous image is a function f(x, y). Sampling keeps values on a grid: f[m, n] = f(mΔx, nΔy). Δx and Δy are sampling intervals in metres or millimetres; m, n are integers. The product mΔx is a physical position; m is its index.

Sampling rate is r = 1/Δx samples per metre. A finer grid means smaller Δx and larger r. In 1D, s[k] = s(kT) for interval T seconds.

Let fmax be the highest frequency in cycles per unit length. The Nyquist criterion says recovery is possible only if r > 2fmax. The quantity 2fmax is the Nyquist rate; r/2 is the Nyquist frequency. Nothing above r/2 is represented.

A grid can show detail only coarser than about two samples. A sensor with 2 μm pixels has Δx = 2 μm and resolves nothing finer than roughly 4 μm, whatever the lens does.

Aliasing: what a coarse grid invents

If the Nyquist criterion fails, a frequency above r/2 is recorded as a different, lower frequency. This false identity is aliasing.

A moving car makes a picket fence seem to drift in slow bands. A phone photo of a striped shirt or brick wall shows wavy moiré. A fan blade filmed at 24 frames per second can seem stopped or backwards.

Aliasing cannot be undone after sampling: two different scenes have produced the same numbers. The cure acts before sampling: low-pass filter so nothing above r/2 survives. Cameras use an anti-aliasing filter; resizing code blurs before dropping pixels (Unit 2).

Quantization turns brightness into levels

Sampling makes coordinates discrete; quantization makes brightness discrete. Each real sample maps to one of a finite set of levels. With b bits we get 2b levels; b is the bit depth. b = 8 gives 256 levels; b = 1 gives a two-level black-and-white image.

Uniform quantization spaces levels equally. Each sample x becomes its nearest level Q(x). The error is e = x − Q(x); with rounding |e| ≤ Δ/2. For a full-range signal the mean squared error is about Δ²/12.

Δ = L / (2b − 1)

Δ is the gap between neighbouring levels in brightness units; L is the full input range, equal to 1.0 for a normalised image; b is the bit depth, so 2b is the number of levels when both ends are used.

Nonuniform quantization uses small steps where the eye is sensitive and large steps elsewhere, such as near black. Logarithmic quantizers and display encoding do this. Unit 3 reuses the idea in compression.

Spatial and intensity resolution, and the storage bill

Spatial resolution says how much fine detail the grid can hold. It is quoted as pixels per unit length (dots per inch, line pairs per millimetre), a true density, or as total pixel count (a 12 megapixel camera), only the number of samples.

Intensity resolution says how finely brightness is graded. It is quoted in bits or gray levels: 8 bits means 256 levels.

S = M × N × b

S is uncompressed storage in bits; M is the number of rows; N is the number of columns; b is the bit depth (bits per pixel).

A 1920 × 1080 frame at 8 bits: 2,073,600 × 8 = 16,588,800 bits = 2,073,600 bytes = 2.07 MB (decimal, 106 bytes) = 1.98 MiB (220 bytes). At 12 bits: 24,883,200 bits = 3,110,400 bytes = 3.11 MB = 2.97 MiB.

Doubling M and N quadruples the pixel count. Adding one bit doubles storage at the same pixel count, so 12-bit costs 1.5 times 8-bit. Output limits mean extra bits may buy only file size (Unit 3).

Exam traps

  • Higher bit depth does not raise spatial resolution. Bit depth sets brightness levels; sampling interval sets detail. A 16-bit image at 50 dpi is still blurry.
  • Aliasing comes from sampling too coarsely, not quantizing too coarsely. Coarse quantization gives banding and false contours, never moiré.
  • Nyquist rate 2fmax is a minimum, not a target. Sampling exactly at it is fragile; real systems sample well above it and filter first.
  • Watch the examiner's convention. With 2b levels over [0, L] including both ends, Δ = L/(2b − 1) and there are 2b levels. 1.7 Pixel relationships: neighbors, connectivity and distance measures

A pixel is a number at a grid point. That number becomes an image only when we say which grid points are neighbours, when two pixels belong to one object, and how far apart two pixels are. These rules drive filtering, edge detection, segmentation and morphology. A filter averages a neighbourhood; segmentation groups connected pixels; a boundary is where connection stops. The vocabulary is: N4, ND, N8, adjacency, connectivity, path, connected component, region, boundary, and the distances D4, D8, De.

You need: the sampling grid and pixel coordinates from 1.6.

Coordinates and three neighbourhoods

Write a pixel p as (x, y). x is the column index and y is the row index, both integers. The origin is usually top-left. Indexing from 0 or 1 changes the numbers but not the rules.

  • N4(p) = {(x+1,y), (x−1,y), (x,y+1), (x,y−1)}. These are the four side neighbours: east, west, south, north.
  • ND(p) = {(x+1,y+1), (x+1,y−1), (x−1,y+1), (x−1,y−1)}. These are the four diagonal neighbours.
  • N8(p) = N4(p) ∪ ND(p). These are all eight surrounding pixels.

N4 is also called the 4-neighbourhood. ND is the diagonal neighbourhood. N8 is the 8-neighbourhood. A pixel on the image border has fewer neighbours because points outside the array do not exist.

Neighbourhoods are used directly in filtering. A 3×3 mean filter replaces p by the average of N8(p) plus p. A 4-neighbour Laplacian uses N4; an 8-neighbour Laplacian uses N8.

Adjacency, connectivity and regions

Some syllabi call these rules basic relationships between pixels. Fix a set V of intensity values that belongs to the object. For a binary image, V = {1}. Two pixels p and q are adjacent if q is in a chosen neighbourhood of p and both f(p) and f(q) are in V. f(p) is the intensity at p.

  • 4-adjacency: q ∈ N4(p).
  • 8-adjacency: q ∈ N8(p).
  • m-adjacency: q ∈ N4(p), or q ∈ ND(p) and the set N4(p) ∩ N4(q) contains no pixels whose values are in V.

The m-adjacency condition removes a double path. Under 8-adjacency, two diagonal pixels can both touch the same two side pixels and create a crossing. Under m-adjacency, the diagonal link is allowed only when N4(p) ∩ N4(q) holds no pixels with values in V.

A path from p to q is a sequence p = p0, p1, …, pn = q where each pi is adjacent to pi−1. The length is n, the number of steps. A connected component is a set of pixels in which every pair has a path inside the set. A region is a connected set with a shared property, such as similar intensity. A boundary pixel of a region R is a pixel of R that has at least one 4-neighbour not in R. Some texts use an 8-neighbour version of this definition; use it only when the text says so.

Connected components and region segmentation are developed in Unit 4, Image Segmentation and Representation.

Distance measures

Distance measures compare pixel positions, not intensities. Let p = (x, y) and q = (x′, y′). Let Δx = |x − x′| and Δy = |y − y′|.

D<sub>e</sub>(p,q) = √((x − x′)² + (y − y′)²) = √(Δx² + Δy²)

De is straight-line distance between pixel centres, in pixel units; p = (x,y) and q = (x′,y′).

D<sub>4</sub>(p,q) = |x − x′| + |y − y′| = Δx + Δy

D4 is city-block distance, also called Manhattan distance; it counts side moves only.

D<sub>8</sub>(p,q) = max(|x − x′|, |y − y′|) = max(Δx, Δy)

D8 is chessboard distance; it counts side and diagonal moves like a king on a chessboard.

For one side step, Δx = 1, Δy = 0: D4 = 1, D8 = 1, De = 1. For one diagonal step, Δx = 1, Δy = 1: D4 = 2, D8 = 1, De = √2 ≈ 1.414. Use D4 and D8 when the algorithm walks on the grid. Use De when true geometric length is needed. Euclidean distance never decides adjacency. On the grid, D4 = 1 exactly when q ∈ N4(p), and D8 = 1 exactly when q ∈ N8(p), so the grid distances do match N4 and N8; only De is irrelevant to adjacency.

Worked example

Question. Pixels p = (1,1) and q = (2,2). Find D4, D8 and De. Are they 4-connected or 8-connected?

  1. Set p = (1,1) and q = (2,2). Then Δx = |2−1| = 1 and Δy = |2−1| = 1 pixel step.
  2. City-block: D4 = Δx + Δy = 1 + 1 = 2 pixel steps.
  3. Chessboard: D8 = max(Δx, Δy) = max(1,1) = 1 pixel step.
  4. Euclidean: De = √(1² + 1²) = √2 ≈ 1.414 pixel units.
  5. Assume both pixels have values in the chosen set V (for a binary object image, V = {1}). Adjacency test: 4-adjacent needs D4 = 1, but D4 = 2, so not 4-adjacent. 8-adjacent needs D8 = 1, and D8 = 1, so they are 8-adjacent.

Answer. D4 = 2, D8 = 1, De ≈ 1.414; p and q are 8-adjacent but not 4-adjacent.

Exam traps

  • Using Euclidean distance in a grid adjacency test: adjacency depends on N4 or N8, not on straight-line length.
  • D8 is max, not sum. D4 is the sum. Mixing the two gives wrong boundary and path lengths.
  • Forgetting the extra condition in m-adjacency: q in ND(p) is not enough; N4(p) ∩ N4(q) must contain no pixels whose values are in V, not simply be empty.
  • Swapping coordinate order: (x,y) is column,row while many arrays use row,column. Distances stay symmetric, but neighbour names can flip.

1.8 Arithmetic, logical and geometric operations on images

An image is an array of numbers. A grey image is a matrix f(x,y); x is the column, y is the row, and f is the pixel value. Arithmetic operations change the numbers, logical operations change the bits of those numbers, and geometric operations move the numbers to new coordinates. These three families are the basic verbs of image processing. They are used to average noisy phone-camera frames, subtract a background in CCTV, mask a region with bit operations, and rotate or scale a scanned answer sheet before reading it.

You need: the pixel grid and 8-bit range from 1.6, and neighbour coordinates from 1.7.

Images as arrays; arithmetic operations

A digital grey image is a matrix f(x,y). x is the column index, y is the row index, and f(x,y) is the pixel value. For b bits per pixel the value lies in 0 to 2^b−1. For b=8 the range is 0 to 255, where 0 is black and 255 is white. An operation reads one or more images and writes a new image g.

Arithmetic operations work pixel by pixel. Add: g=f1+f2. Subtract: g=f1−f2. Multiply: g=f1·f2 or g=c·f. Divide: g=f1/f2. All images must have the same size, or one operand is a scalar. Guard division by zero.

The result may leave the stored range. Saturation (clipping) clamps to the nearest limit. For 8 bits, 200+100=300 becomes 255. Modulo wraparound keeps the low 8 bits, so 300 becomes 44. Use saturate for display; use modulo only when the problem states it. This is the first trap.

g(x,y) = (1/M) Σ_{i=1}^{M} f_i(x,y)

M is the number of frames; f_i is frame i; g is the averaged image. If the noise is independent with variance σ², the average has variance σ²/M and the signal-to-noise ratio improves by √M.

Averaging M frames of a still scene reduces random noise; the variance falls to σ²/M. Phone night mode does this. Difference |f1−f2| finds changes between two frames or a frame and a background. CCTV motion detection and PCB inspection use it.

Logical operations and masks

Logical operations treat each pixel as a b-bit binary word. Bit plane k is the set of k-th bits over the whole image. AND outputs 1 only when both bits are 1. OR outputs 1 when at least one bit is 1. NOT flips every bit. XOR outputs 1 when the bits differ.

A region mask for an 8-bit grey image uses 0 and 255. 255 has all eight bits 1, so g=f AND m keeps the full pixel where m=255 and gives 0 where m=0. If a mask is stored as 0 and 1, do not AND it with a grey image: 200 AND 1 is 0, not 200. Multiply the image by the 0/1 mask, or scale the mask to 0/255, before AND. OR sets chosen bits. XOR toggles bits, so it can compare two bit planes or hide a watermark. NOT on an 8-bit image gives g=255−f.

Logical operations are not arithmetic. In the worked example 200 AND 100 is 64, not 300. Use masks to select a region before measurement, to combine bit planes, or to invert a binary image. In code, Python's &, | and ^ on non-negative 8-bit values stay in 0–255. ~ is not a fixed-width 8-bit NOT: ~200 is −201. For an 8-bit NOT write (~f) & 0xFF, which gives 55 for 200. Masks also ignore padded borders before an operation.

Geometric operations and inverse mapping

Geometric operations move pixel values to new coordinates. Forward mapping sends each input (x,y) to output (x′,y′). Forward mapping can leave holes whenever mapped points skip output pixels, for example scaling up or rotation. Inverse mapping visits every output pixel, computes its source coordinate, and samples the input there. Use inverse mapping for rotation and scaling.

Translation: x′=x+tx, y′=y+ty. Scaling: x′=sx·x, y′=sy·y. Rotation by θ about (cx,cy), with y pointing down and θ positive clockwise: x′=cx+(x−cx)cosθ−(y−cy)sinθ; y′=cy+(x−cx)sinθ+(y−cy)cosθ. An affine transform has six parameters and preserves parallel lines. A projective transform (homography) has eight parameters and maps lines to lines; parallel lines may meet. Document rectification uses a homography.

After inverse mapping the source coordinate is usually not an integer. Nearest-neighbour interpolation takes the closest pixel; it is fast and blocky. Bilinear interpolation takes a weighted average of four neighbours: f(x,y)≈(1−a)(1−b)f00+a(1−b)f10+(1−a)b f01+ab f11. Here f00=f(⌊x⌋,⌊y⌋), f10=f(⌈x⌉,⌊y⌋), f01=f(⌊x⌋,⌈y⌉), f11=f(⌈x⌉,⌈y⌉), a=x−⌊x⌋ and b=y−⌊y⌋. The four points are the surrounding pixels. Unit 2 covers resampling filters.

Worked example

Question. Let A = [[200, 50], [10, 240]] and B = [[100, 20], [250, 30]]. Compute (a) A+B with 8-bit saturation, (b) A AND B bitwise, and (c) A rotated 90° clockwise.

  1. Write A = [[200, 50], [10, 240]] and B = [[100, 20], [250, 30]] as 2×2 arrays.
  2. (a) Add elementwise: 200+100=300; 50+20=70; 10+250=260; 240+30=270. Saturate to 0 to 255: 300→255; 70 stays 70; 260→255; 270→255. Result A+B = [[255, 70], [255, 255]].

1.9 Color models and color image processing: RGB, HSI

A color image stores three numbers per pixel instead of one. RGB is the additive model that matches screens: red, green and blue light add to white. HSI describes the same pixel by hue (which color), saturation (how pure) and intensity (how bright), so an algorithm can act on color without being confused by lighting. This chapter covers the RGB cube, 24-bit color, HSI definitions and the conversion formulas. Uses include skin detection in selfies, ripeness sorting of fruit, and traffic-sign detection in driver-assist systems.

You need: 1.6 for bit depth and quantization, and 1.5 for how a sensor turns light into a pixel value.

RGB: an additive cube of three channels

A color image is three images stacked. Each pixel carries a red value R, a green value G and a blue value B. In an 8-bit color image each channel runs from 0 to 255, so one pixel takes 24 bits. That is 24-bit color: 8 bits per channel, 256 levels per channel, and 256³ = 16,777,216 possible colors per pixel.

RGB is additive; lights add. Red light plus green light looks yellow. The three primaries are red (255,0,0), green (0,255,0) and blue (0,0,255). The secondaries are the pairwise sums: yellow (255,255,0), magenta (255,0,255) and cyan (0,255,255). All channels at maximum give white (255,255,255); all at zero give black (0,0,0). Equal values in all three channels, R = G = B, give a gray level.

Put R, G and B on three perpendicular axes and every pixel sits inside a cube of side 255 — the RGB color cube. The diagonal from black to white is the gray axis.

RGB is device-friendly, not perception-friendly. Camera sensors, phone screens and JPEG files speak RGB, so that is where images arrive. But the numbers do not match what you see: distance inside the cube does not track how different two colors look, and a change of lighting moves all three numbers at once.

HSI: hue, saturation, intensity

HSI describes a pixel the way a person does: what color is it, how pure is it, how bright is it.

  • Hue H: which color, an angle from 0° to 360° around a color wheel. Red sits at 0°, green at 120°, blue at 240°. Hue says nothing about brightness.
  • Saturation S: how far the color is from gray, from 0 to 1. S = 0 means gray or white; S = 1 means a fully pure color. Mixing white paint into red lowers S and leaves the hue red.
  • Intensity I: brightness, from 0 (black) up to the maximum level. It is the average of the three channels, not the largest channel.

Switch on a lamp and the pixel gets brighter — I moves, H stays roughly put. A shadow dims the pixel — again mostly I. So a threshold on H and S copes with lighting changes that would break the same threshold in RGB. Skin detection, fruit ripeness grading and traffic-sign detection often convert to HSI for this reason.

HSV, also called HSB, is a close relative: its brightness term V is max(R,G,B), not the average, so the two models give different numbers for the same pixel.

Converting RGB to HSI, and what color processing means

Three formulas do the conversion. Keep R, G and B on one scale — 0 to 1, or 0 to 255. The ratio and difference forms cancel a common scale, but a pixel written with mixed scales gives a wrong hue.

I = (R + G + B) / 3

R, G, B are the channel values on one common scale; I is intensity on that same scale.

S = 1 − 3·min(R, G, B) / (R + G + B)

min(R,G,B) is the smallest of the three channel values; S is saturation, in [0, 1]; if R = G = B = 0 the pixel is black and S is defined as 0.

H = 60°·(G − B)/(max − min) if max = R;  H = 60°·[2 + (B − R)/(max − min)] if max = G;  H = 60°·[4 + (R − G)/(max − min)] if max = B

max and min are the largest and smallest of R, G and B; H is hue in degrees, in [0°, 360°); add 360° to a negative result; if max = min the pixel is gray, hue is undefined and by convention H = 0°.

  1. Take the three channel values of the pixel on one common scale.
  2. Find max, min and the sum R + G + B.
  3. Compute I as the sum divided by 3.
  4. Compute S from the ratio of min to the sum; use S = 0 when the sum is 0.
  5. Pick the hue case by which channel equals max, and evaluate it.
  6. If H came out negative, add 360° to bring it into [0°, 360°).

When two channels tie at the maximum, the cases agree at that boundary.

Two names cover the work. Pseudo-color processing maps a single-channel gray image to colors for display only — intensity slicing of a thermal or X-ray image adds no new measurement. Full-color processing works on the three channels of a real color image. Running the same gray-level operation on R, G and B separately is cheap and correct for geometry and smoothing, but per-channel histogram equalization changes the three channels by different amounts and tints a plain gray wall. The fix is to convert to HSI, change I alone, and convert back with H and S untouched.

Color enhancement and filtering are taken up in Unit 2, color segmentation in Unit 4, and calibration and color constancy in Unit 5.

Worked example

Question. An 8-bit color pixel has RGB = (255, 128, 0). Convert it to HSI. Give H in degrees to one decimal place, S to two decimals, and I on the 0–255 scale.

  1. max = 255 (the red channel), min = 0 (the blue channel), sum = 255 + 128 + 0 = 383.
  2. I = 383 / 3 = 127.67, on the 0–255 scale.
  3. S = 1 − 3 × 0 / 383 = 1 − 0 = 1.0, so the color is fully saturated.
  4. max = R, so use the red case: H = 60° × (G − B) / (max − min) = 60° × (128 − 0) / 255.
  5. H = 60° × 0.50196 = 30.12°, which rounds to 30.1°.
  6. H is positive, so no 360° correction is needed.

Answer. H ≈ 30.1°, S = 1.0 and I ≈ 127.67, a fully saturated orange.

Exam traps

  • I is the average of the three channels, not the maximum. Writing I = max(R,G,B) is the V of HSV, not I of HSI; the two models give different numbers for the same pixel.
  • Hue is an angle. Hues 350° and 10° are 20° apart, crossing 0°, not 340° apart.
  • The hue formulas need a scale-consistent max − min. Mixing 0–1 and 0–255 values inside one pixel gives a wrong hue.
  • For a black pixel R = G = B = 0 the saturation term becomes 0/0. State S = 0, H = 0 and do not divide.
  • 24-bit color means 8 bits per channel, not 24 levels per channel. Three channels at 8 bits give 256³ ≈ 16.8 million colors.

Evaluate Design a complete pipeline, from sensor to decision, for automatically reading number plates at a toll plaza. Name the step of the image processing chain used at each stage. 16 marks

Acquisition: camera and illumination, fixed exposure, synchronised trigger; Preprocessing: denoise, correct lens distortion, convert to grey; Enhancement: contrast stretch or histogram equalisation for night frames; Segmentation: locate the plate region, using edges and connected components; Morphology and connectivity rules to join plate characters; Representation and description: character bounding boxes, size and aspect filters; Recognition: template or classifier per character; confidence threshold; Compression: store only kept frames to save bandwidth; Feedback: log failures and retune thresholds; Mention resolution needed: character height in pixels must be large enough for the classifier.

Evaluate Justify the statement that sampling and quantization are the two independent choices that fix an image's information content. Use a fixed budget in bits to argue the trade-off. 13 marks

An image of M × N pixels with n bits per pixel needs M·N·n bits; Sampling fixes M and N; quantization fixes n; For a fixed total, more pixels means fewer levels and vice versa; Human vision is more sensitive to intensity banding in smooth regions than to small detail loss in textured regions; Aliasing appears before quantisation banding when sampling is reduced too far, for edges and fine texture; Practical rule: fix the sample spacing from the smallest object you must see, then spend remaining bits on intensity; Give a numeric example at a fixed 64 Kbit budget.

Glossary

Additive colour
A colour system in which lights add, so red plus green plus blue at full strength gives white.
Adjacency
The relation between two pixels that are neighbours and whose values satisfy a similarity rule.
Albedo
The fraction of light a surface reflects; a white wall has high albedo and a black cloth low albedo.
Aliasing
False low-frequency patterns created when a scene is sampled too coarsely for its detail, seen as jagged edges or moiré.
Bayer filter
A colour filter array over a sensor with more green than red or blue cells, demosaiced later to give full colour.
Bit-plane
The 2-D binary image formed by taking one bit position from every pixel, useful for showing subtle texture.
Boundary
The set of pixels in a region that have at least one neighbour outside the region.
Compression
Encoding an image with fewer bits, either losslessly or by discarding detail the viewer will not notice.
Digital image
A finite 2-D array f(x, y) whose entries are brightness values at sampled grid points.
Dynamic range
The ratio between the brightest and darkest values a sensor, display or scene can handle.
Enhancement
Processing that makes an image more useful for a viewer or a later algorithm, without a physical model of degradation.
Fovea
The small central patch of the retina packed with cones, giving the sharpest vision.
Gamma correction
A power-law mapping applied so that stored values match how a display and the eye respond.
Grey level
One of the discrete intensity values available at a given bit depth; 8 bits give 256 grey levels.
Histogram
A count of how many pixels take each intensity value, used to judge contrast and to drive equalisation.
Hue
The attribute of colour that we name as red, green or blue, measured as an angle on the colour circle.
Intensity
The brightness value stored at a pixel, usually an integer from 0 to 2ⁿ−1 for n bits.
Interpolation
Estimating pixel values at new coordinates, by nearest-neighbour, bilinear or bicubic rules.
Lateral inhibition
Neighbouring retinal cells suppress each other, which sharpens edges and produces effects such as Mach bands.
Lens
A curved refracting element that focuses scene light onto the sensor plane.
Pixel
One element of a digital image, identified by its row and column index and holding one or more values.
Preprocessing
Early operations that clean an image, such as noise removal or correcting illumination, before the main task.
Recognition
Assigning a label or class to a segmented region or to the whole image.
Saturation
How pure a colour is, from 0 for grey to 1 for a fully saturated hue.
