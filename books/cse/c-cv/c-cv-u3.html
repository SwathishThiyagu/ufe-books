3.1 Image degradation and restoration model

Every photograph is a spoiled copy of the scene. The lens blurs it, the sensor adds noise, the shutter smears anything that moves. Restoration begins by writing that spoiling as one line of mathematics: g(x,y) = H[f(x,y)] + n(x,y), where f is the true image, H is the degradation, n is the noise and g is what the camera gave you. If you can estimate H and the noise, you can undo them and come close to f. Forensic blur removal, old photo repair, satellite imaging and CT all work from this model.

You need convolution, correlation and the discrete Fourier transform from Unit 2, Image Enhancement and Filtering.

The model, and why the order matters

Photograph a printed page in dim light and zoom in. The letters are soft, and a fine grain sits on top of them. Two different things spoiled the picture: the blur of the lens and the noise of the sensor. The degradation model writes both in one line.

g(x,y) = H[f(x,y)] + n(x,y)

g(x,y) is the observed image, the one you have; f(x,y) is the true, undegraded image; H is the degradation operator, any process that smears a pixel with its neighbours; n(x,y) is additive noise, a random value added to each pixel; (x,y) are pixel coordinates, x the column and y the row.

H acts first, noise comes second. Blur belongs to the optics and to motion, which act on the light before it reaches the sensor. Noise belongs to the sensor electronics and to the transmission channel, and arrives afterwards. Writing g = H[f + n] would blur the noise along with the image, which is physically wrong and makes the noise correlated from pixel to pixel.

Restoration is the reverse journey. It estimates what H did, estimates the noise, and then applies an operator R to g to produce an estimate f̂. If H is not known or cannot be estimated, the model gives you nothing.

Restoration is objective. It carries a model of what went wrong, tries to recover the actual f, and success is judged against that model. Enhancement is subjective: histogram equalisation or sharpening makes an image look better to a viewer with no claim about the true scene. Reading a blurred number plate for a court case is restoration. Making a wedding photo brighter is enhancement.

Linear, shift-invariant H becomes convolution

To invert H, H must be simple. The standard assumption is that H is linear and shift-invariant. Linear means superposition: H[a·f₁ + b·f₂] = a·H[f₁] + b·H[f₂] for constants a and b. Shift-invariant means the blur is the same everywhere: if the input moves by (x₀, y₀), the output moves by exactly (x₀, y₀) and changes in no other way. A lens that is sharp in the centre and soft at the edges breaks this. So does motion blur over a road that recedes into the distance.

Under these two assumptions H is completely described by one small image: its response to a single bright point. Feed in a point source and what comes out is the point spread function, PSF, written h(x,y). The degradation is then a convolution.

g(x,y) = (h * f)(x,y) + n(x,y) = Σm Σn h(m,n) f(x−m, y−n) + n(x,y)

h(m,n) is the point spread function, the blur kernel; m and n are offsets inside the kernel; the double sum runs over the kernel's support; * denotes convolution.

Take the DFT of both sides. Convolution becomes multiplication.

G(u,v) = H(u,v) F(u,v) + N(u,v)

G, F, N are the DFTs of g, f, n; H(u,v) is the DFT of h, called the optical transfer function (OTF); u and v are frequency indices. Undoing the blur in this domain looks like a division by H.

  • h is real and non-negative for any physical blur.
  • Σ h(m,n) = 1 when the blur only redistributes light rather than creating it; equivalently H(0,0) = 1, so average brightness survives.
  • h equal to a single 1 at the origin means no blur at all; the model then has only noise (see 3.2).
  • A blur that varies across the frame cannot be written as one convolution.

Estimating the degradation function

Every restoration filter needs h or H as input, so estimating the degradation is the first job. There are four routes, roughly in order of reliability.

  1. Point source. Photograph a bright point against black with the same camera settings — a star, an LED, a pinhole in card. The recorded patch is h directly.
  2. Line or edge. A sharp straight edge in the scene, such as a building against the sky, becomes an S-shaped ramp after blur. Differentiating that ramp across the edge gives the line spread function, and for a separable blur this gives h.
  3. Physical model. Derive h from geometry. Uniform motion of L pixels during the exposure gives h(x) = 1/L for x = 0 … L−1 and 0 elsewhere. An out-of-focus lens of aperture radius R gives a disc: h = 1/(πR²) inside a circle of radius R, 0 outside. Atmospheric turbulence has its own standard model.
  4. Experiment. When the scene offers no point, edge or known physics, image a test chart, or the same static scene with and without the suspected cause, and compare the two.

Sanity-check any candidate kernel before using it: it must be non-negative and sum to 1. Once h is known, the filters in 3.3 and 3.5 take over. The statistics of n are covered in 3.2.

Worked example

Question. A camera moves exactly 4 pixels horizontally while the shutter is open, so each recorded pixel is the average of 4 successive scene positions. (a) Write the degradation kernel h(x). (b) For a 256-pixel row, at which frequencies u does H(u) = 0? (c) What does that mean for an inverse filter?

  1. The exposure averages 4 positions, so h(x) = 1/4 for x = 0, 1, 2, 3 and h(x) = 0 elsewhere. Check the brightness: 1/4 + 1/4 + 1/4 + 1/4 = 1, so Σh = 1 and light is only redistributed.
  2. For a row of N = 256 pixels the OTF is H(u) = Σ(x=0 to 3) (1/4)·e^(−j2πux/256), with u = 0, 1, …, 255.
  3. The four terms are unit vectors at angles 0, −2πu/256, −4πu/256 and −6πu/256. They sum to zero when consecutive angles differ by 2π/4 = π/2, that is when 2πu/256 = 2πk/4, so u = 64k.

  5. At u = 64, 128, 192 the observed spectrum is G(u) = 0·F(u) + N(u) = N(u). The scene information at those frequencies is destroyed; only noise remains there.
  6. (c) An inverse filter computes F̂(u) = G(u)/H(u). At those three frequencies it divides by zero, so the output explodes. They must be handled by a regularised filter, as in 3.5.

Exam traps

  • Putting noise before the blur, g = H[f + n]. That colours the noise and contradicts the physics; the order is always blur first, noise second.
  • Treating restoration as a synonym for enhancement. Restoration is judged against a degradation model; enhancement is judged by the eye.
  • Forgetting that Σh must equal 1. A kernel that does not sum to 1 changes the brightness, and the restored image will come out too dark or too bright.
  • Confusing h(x,y) with H(u,v). They are the same blur in two domains — PSF in space, OTF in frequency — not two different degradations.
  • Assuming the convolution form always holds. It needs H to be linear and shift-invariant; a lens that blurs differently across the frame breaks it.

3.2 Noise models

Noise is a random signal added to the true pixel value. Its probability density p(z) tells how likely each grey level z is. The shape of p(z) matters because a filter that suits Gaussian noise may fail on salt-and-pepper noise. Engineers measure the density on a flat patch, then choose a filter. This chapter lists the standard densities, their parameters, and the physical source of each.

You need: 3.1 for where n enters the model, and Unit 2 histograms.

Additive noise model

The observed pixel is g(x,y) = f(x,y) + n(x,y). f is the true grey level, n is a random noise value, and x,y are pixel coordinates. n is independent of f and changes from pixel to pixel. The same equation holds for all pixels, so we can drop coordinates and write g = f + n.

Multiplicative noise is different: g = f·n, common in radar and laser speckle. A log transform turns it into additive noise.

The noise is described by its probability density p(z). z is a grey level, and p(z)dz is the probability that n lies between z and z+dz. The mean µ = E[z] and variance σ² = E[(z−µ)²] summarise the centre and spread. A flat patch has almost constant f, so the histogram of that patch estimates p(z).

Periodic noise, such as a sine ripple from a power supply, is not random in this sense and does not fit these densities. It gets a frequency-domain treatment in 3.4.

Estimating parameters from a flat patch

Noise is measured where the true image is flat. A textured or edged region adds real variation and inflates the estimate.

µ̂ = (1/N) Σ z_i, σ̂² = (1/N) Σ (z_i − µ̂)²

z_i is the i-th pixel in the patch; N is the number of pixels; µ̂ is the sample mean; σ̂² is the sample variance.

  1. Pick a region with no edges or texture, at least 20×20 pixels if possible.
  2. Plot its histogram; for a flat patch this histogram estimates p(z).
  3. Compute the sample mean and variance with the formulas above.
  4. Match the histogram shape: symmetric bell → Gaussian; one-sided tail with z≥a → Rayleigh or gamma; flat top → uniform; spikes at two levels → impulse.
  5. For a Gaussian, assume zero-mean noise, estimate the flat level by µ̂, and report σ̂ as the noise standard deviation. For other densities, solve the mean and variance equations for the PDF parameters.

The fitted density is only a model. If the histogram has isolated spikes, treat the image as having impulse noise first; a mean filter is the wrong tool there. Filters for each density are in 3.3.

Question. A flat 3×3 patch reads 8, 10, 12, 10, 12, 14, 12, 14, 16 grey levels. Estimate the mean, variance and standard deviation of these readings, and state a suitable noise density.

Exam traps

  • Reporting the variance of the whole image as the noise variance. Edges and texture inflate it; measure only on a flat patch.
  • Using a mean filter on impulse noise. Impulses have no useful variance, and averaging smears them instead of removing them; use an order-statistic filter from 3.3.
  • Confusing variance σ² with standard deviation σ. The Gaussian parameter in p(z) is σ, not σ².
  • Using the wrong parameterisation for Rayleigh or gamma noise. The mean is not a or b alone; check the mean and variance formulas before fitting.
  • Treating periodic noise as a PDF noise. A sine ripple gives spectral spikes, not a smooth histogram; use the notch filter in 3.4.

3.3 Restoration filters: mean, order-statistic and adaptive

Restoration filters clean a noisy image when blur is absent: g(x,y) = f(x,y) + n(x,y), where g is the observed image, f is the true image and n is the noise. The filter must match the noise. Averaging suits Gaussian noise, order statistics delete impulses, and adaptive filters vary strength with local variance. Only a few universities teach this topic at this depth. Phone cameras, CCTV cleanup and medical scans use these cheap neighbourhood operations before any inverse or Wiener stage.

You need noise types from 3.2 and neighbourhood smoothing from Unit 2.

Mean filters

Let S_xy be an M×N window centred at (x,y), and g(s,t) a noisy pixel in it. The arithmetic mean is f̄ = (1/MN) Σ g(s,t). The geometric mean is [Π g(s,t)]^{1/MN}. The harmonic mean is MN / Σ [1/g(s,t)]. The contraharmonic mean is Σ g(s,t)^{Q+1} / Σ g(s,t)^Q, where Q is a real order. Q = 0 gives the arithmetic mean; Q > 0 removes pepper (dark spots); Q < 0 removes salt (bright spots). Averaging blurs edges. The harmonic mean handles salt noise but fails on pepper because a near-zero pixel makes 1/g large.

Order-statistic filters

Order-statistic filters sort the MN values and pick a rank. The median is the middle value, at position (MN+1)/2 for odd MN. It deletes salt-and-pepper impulses because they sit at extreme ranks. The max filter outputs the largest value; it removes pepper noise. The min filter outputs the smallest value; it removes salt noise. The midpoint is (z_min + z_max)/2, where z_min and z_max are the smallest and largest values. It suits Gaussian or uniform noise but one impulse ruins it. The alpha-trimmed mean sorts the values, deletes d/2 from each end (d even), and averages the rest. d is the number trimmed, 0 ≤ d ≤ MN−1. d = 0 gives the arithmetic mean; d = MN−1 gives the median. A large median window can erase thin lines.

Adaptive filters

Adaptive filters read local statistics before smoothing. The adaptive local noise reduction filter is f̂(x,y) = g(x,y) − (σ²ₙ / σ²_L) [g(x,y) − m_L]. Here g is the noisy pixel, m_L is the local mean, σ²_L is the local variance, and σ²ₙ is the noise variance. In a flat region σ²_L ≈ σ²ₙ, so the ratio is near 1 and the output is close to m_L: strong smoothing. At an edge σ²_L ≫ σ²ₙ, so the ratio is near 0 and the output stays close to g: no smoothing.

The adaptive median filter grows a window from 3×3 up to S_max, the largest allowed window size. Let z_min, z_med, z_max be the smallest, median and largest values, and z_xy the centre pixel. If z_min < z_med < z_max, go to level B; otherwise enlarge the window. If the window reaches S_max, output z_med. At level B, output z_xy if z_min < z_xy < z_max; else output z_med. This removes impulses without flattening detail.

3.4 Periodic noise reduction in the frequency domain

Periodic noise is interference from a machine or a cable, not random grain. It adds a repeating stripe or grid to the image. In the Fourier spectrum, a pure sinusoid becomes a pair of bright points away from the centre. A notch filter deletes those points and leaves the rest. Use it on scanner lines, power-supply hum and camera readout patterns.

You need: 3.1 for the degradation model, 3.2 for why periodic noise is not covered by the PDF models, and Unit 2, Filtering in the frequency domain, for the DFT and masks.

From interference to two spectral spikes

Periodic noise is a repeating pattern added during capture. A scanner clock, a motor, a power supply or a camera readout can inject a sinusoid into every row or column. In the space domain you see stripes or a grid. In the frequency domain you see two bright points.

n(x,y) = A cos(2π(u₀x/N + v₀y/M) + φ)

n is the added noise; A is its amplitude; x and y are pixel indices; N and M are the image width and height in pixels; (u₀,v₀) is the interference frequency in cycles per image; φ is phase.

The DFT of a real image satisfies F(u,v) = F*(N−u, M−v), with indices taken modulo N and M. F* is the complex conjugate. So a real sinusoid gives a conjugate pair at (u₀,v₀) and (N−u₀, M−v₀).

Vertical stripes vary along x, so v₀ = 0. If the stripe period is T pixels, u₀ = N/T. The two spikes sit on the u-axis. Random noise spreads over the whole spectrum; periodic noise concentrates. That is why a tiny mask can remove it without blurring the whole image.

Notch filters: ideal, Butterworth, Gaussian

Work in unshifted DFT coordinates u = 0…N−1 and v = 0…M−1. Let D₀ be the notch radius in frequency bins. Define the distance to the first spike and to its partner:

D₁(u,v) = √((u−u₀)² + (v−v₀)²),   D₂(u,v) = √((u−(N−u₀))² + (v−(M−v₀))²)

D₁ is the distance from frequency point (u,v) to the spike at (u₀,v₀); D₂ is the distance to the partner at (N−u₀, M−v₀); all distances are in frequency bins.

Build one high-pass factor for each notch and multiply: H(u,v) = H₁(u,v) H₂(u,v). At D_k = 0 the factor is 0; far from both notches H ≈ 1.

  • Ideal: Hk = 0 if Dk ≤ D₀, else 1. Hard edge, so it can ring.
  • Butterworth of order n: Hk = 1 / [1 + (D₀/Dk)2n]. Smooth transition.
  • Gaussian: Hk = 1 − exp(−Dk²/(2D₀²)). Smooth, less ringing.
  • Notch pass: Hpass = 1 − Hreject. It keeps the interference and removes the rest; use it only to inspect the noise.
  • Band-reject removes a ring of radii; band-pass is its complement. A notch is the limiting case of a very narrow band-reject.

The notch filtering recipe

Work on the unshifted DFT. The display can be shifted, but the mask coordinates and the array you multiply must use the same origin.

  1. Compute F = DFT of the noisy image g.
  2. Compute L = log(1 + |F|) and display it centred with fftshift. The spikes become visible.
  3. Read each spike coordinate in unshifted indices. For (u₀,v₀), add the partner (N−u₀, M−v₀).
  4. Choose D₀, usually 1–3 bins, and a filter type. Build H with notches at both points.
  5. Multiply the complex spectrum: F ← F · H.
  6. Take the inverse DFT, keep the real part, and clip to 0–255 for 8-bit display.

The log magnitude is only a viewing aid. Do not multiply the log by H; multiply the complex F. After the inverse DFT, round-off leaves a tiny imaginary part; discard it. Keep D₀ small. A wide notch removes real image frequencies near the spike and blurs edges. A narrow notch can leave a faint residual stripe.

Worked example

Question. A 256×256 image has vertical stripes with a period of T = 8 pixels. (a) Find the interference frequency u₀. (b) Give both spike locations in the DFT. (c) State a suitable notch radius D₀. (d) Find the distance between the two spikes and explain why notching only one fails.

  1. N = 256 pixels and T = 8 pixels, so u₀ = N/T = 256/8 = 32 cycles per image width.
  2. Vertical stripes vary along x, so v₀ = 0. The first spike is at (u,v) = (32,0).
  3. The conjugate partner is (N−u₀, M−v₀) = (256−32, 256−0) = (224,0).
  4. A notch radius D₀ = 2 bins is enough for a clean spike on a 256×256 image.
  5. Distance between spikes = |224−32| = 192 bins along the u-axis.
  6. A notch of radius 2 at (32,0) has H ≈ 1 at (224,0) because D = 192 is far greater than 2. The partner survives, so the residual sinusoid is still visible. Mask both points.

Answer. u₀ = 32 cycles per image width; spikes at (32,0) and (224,0); D₀ = 2 bins; separation 192 bins, so both spikes must be notched.

Exam traps

  • Notching a single spike and forgetting the conjugate partner. A real image has a symmetric DFT, so half the sinusoid remains.
  • Notching the origin (0,0). That removes the DC term; the inverse DFT has zero mean and the image turns mid-grey.
  • Using fftshifted coordinates in an unshifted mask, or the reverse. The notch lands in the wrong place and the stripe survives.
  • Making D₀ too large. Real image frequencies near the spike are removed and the restored image blurs.
  • Confusing notch reject with notch pass. Reject removes the interference; pass keeps it and is only for inspection.

3.5 Inverse filtering and Wiener filtering

A blurred photograph is the true image multiplied by a blur kernel H in the frequency domain, plus noise. Inverse filtering divides the observed spectrum by H and recovers the image when H is strong. It explodes where H is small, because noise is divided by the same small number. The Wiener filter adds a noise-to-signal term to the denominator, so it trusts the data only where H is large. These filters are used in microscopy, astronomy, medical imaging and restoring old photographs.

You need: 3.1 for H, 3.2 for noise power, and the DFT from Unit 2.

Inverse filtering and its failure

Write the frequency-domain degradation model as G(u,v) = H(u,v)F(u,v) + N(u,v). G, F and N are the DFTs of the observed image, the true image and the noise. H is the degradation transfer function. u and v are frequency indices. The inverse filter estimates the true spectrum by dividing: F̂ = G/H. Substitute the model: F̂ = F + N/H. The image spectrum passes through unchanged. The noise spectrum is multiplied by 1/H.

F̂(u,v) = G(u,v)/H(u,v) = F(u,v) + N(u,v)/H(u,v)

F̂ is the estimated image spectrum; G is the observed spectrum; H is the degradation transfer function; F is the true spectrum; N is the noise spectrum.

At |H| = 1, noise passes unchanged. At |H| = 0.01, noise is multiplied by 100. At a zero of H the division is undefined, and numerical noise produces a huge value. Inverse filtering therefore needs a high signal-to-noise ratio and an H with no zeros in the band.

  1. Pad H to the image size.
  2. Take the DFT of the observed image.
  3. Divide point by point by H.
  4. Take the inverse DFT.
  5. Keep the real part and clip to the display range.

Wiener filter

The Wiener filter chooses F̂ to minimise the mean square error E[|F − F̂|²] in the frequency domain, which equals the spatial-domain error E[(f − f̂)²]. Here F and F̂ are complex spectra, so the modulus squared is taken. Its frequency-domain form adds a noise-to-signal term to the denominator, so the filter backs off where H is small.

F̂(u,v) = [H<sup>*</sup>(u,v) / (|H(u,v)|² + S<sub>n</sub>(u,v)/S<sub>f</sub>(u,v))] G(u,v)

F̂ is the estimated spectrum; H is the degradation transfer function; H* is its complex conjugate; |H|² = HH*; Sn is the noise power spectrum; Sf is the image power spectrum; G is the observed spectrum.

H* is the complex conjugate of H. |H|² = HH*. Sn is the noise power spectrum, the average |N|². Sf is the image power spectrum, the average |F|². The ratio Sn/Sf is the local noise-to-signal ratio.

Two limits show the behaviour. For K = Sn/Sf > 0, the gain is H*/(|H|² + K). At H = 0 this gain is 0, because the numerator H* is 0 and the denominator is K > 0. Frequencies with no image information are suppressed instead of amplified. In the noiseless limit K = 0, the Wiener formula becomes H*/|H|² = 1/H for H ≠ 0, the inverse filter. At H = 0 it is 0/0 and must be treated separately; the ideal inverse is undefined there.

Sf is unknown in practice, so replace Sn/Sf by a constant K. For real H the gain is H/(H² + K). Its magnitude peaks at |H| = √K, where the value is 1/(2√K). Small K gives sharpness but noise; large K gives smoothness but blur.

Constrained least squares replaces the fixed ratio by a smoothness penalty; it is the same regularised division.

Using the filters

Estimate H from a calibration target, a known motion path, or a physical model. Estimate K from noise variance and image variance, then tune it by trial. Pad H to the image size before the FFT; a short H array used directly causes circular wrap-around and ringing. After the inverse FFT, take the real part and clip to the display range. Filter colour images channel by channel, or filter luminance only. Check flat regions: if noise is visible, increase K. Check edges: if they look soft, decrease K. A small K keeps edges but leaves grain; a large K removes grain but softens edges. The Wiener filter needs H, so it cannot fix an unknown blur; for that use blind deconvolution. For an N-pixel image the FFT cost is O(N log N). K is a tuning knob, not a fixed law.

Worked example

Question. A blurred image has a known real H(u) row. The noise-to-signal ratio is K = 0.001. For |H| = 1, 0.1, 0.01 and 0, compute the inverse gain 1/|H| and the Wiener gain |H|/(|H|² + K). Also find the peak Wiener gain.

  1. K = 0.001.
  2. At |H| = 1: inverse gain = 1/1 = 1.000. Wiener gain = 1/(1² + 0.001) = 1/1.001 = 0.999.
  3. At |H| = 0.1: inverse gain = 1/0.1 = 10.000. Wiener gain = 0.1/(0.1² + 0.001) = 0.1/0.011 = 9.091.
  4. At |H| = 0.01: inverse gain = 1/0.01 = 100.000. Wiener gain = 0.01/(0.01² + 0.001) = 0.01/0.0011 = 9.091.
  5. At |H| = 0: inverse gain is undefined (infinite). Wiener gain = 0/(0² + 0.001) = 0.
  6. Peak: maximise w(h) = h/(h² + K). Set dw/dh = (K − h²)/(h² + K)² = 0, so h = √K = √0.001 = 0.0316. Peak gain = 0.0316/(0.001 + 0.001) = 15.811.

Answer. The gains are dimensionless: at |H| = 0.01 the inverse gain is 100.000 and the Wiener gain is 9.091; at |H| = 0 the inverse gain is infinite and the Wiener gain is 0; the Wiener peak is 15.811.

Exam traps

  • Dropping H* in the Wiener numerator: the numerator is the complex conjugate, not |H| or H².
  • Letting K be negative. K is a power ratio Sn/Sf, so it must be zero or positive.
  • Forgetting to pad H to the image size before the FFT. A short H causes circular wrap-around and ringing.
  • Treating the inverse gain at H = 0 as infinite in code. Division by zero gives an error or an overflow value, not a useful image.
  • Mixing Sn and Sf: Sn is noise power, Sf is image power, and the ratio is noise-to-signal.

3.6 Image reconstruction from projections

An X-ray CT scanner never photographs a slice. It fires X-rays through the slice from many angles and measures absorption, so each reading is a line integral of an unknown cross-section f(x,y). Reconstruction turns these line integrals back into a picture. The same idea rebuilds PET and seismic maps. Here reconstruction means building the image from its projections; restoration, the repair of an already-formed blurred image, is a separate topic.

You need: the degradation model of 3.1 and the 2-D Fourier transform from Unit 2.

The Radon transform and the sinogram

A CT slice is f(x,y): attenuation coefficient in 1/m. A ray is labelled by ρ, signed perpendicular distance from the origin, and θ, angle of that perpendicular from the x axis. Points on the ray satisfy x cos θ + y sin θ = ρ.

R(ρ,θ) = ∫∫ f(x,y) δ(x cos θ + y sin θ − ρ) dx dy

f(x,y) is the object cross-section; θ is the projection angle in radians from the x axis; ρ is the signed perpendicular distance of the ray from the origin, in the same units as x and y; δ is the Dirac delta, zero except where its argument is zero, so the double integral collapses onto the line x cos θ + y sin θ = ρ; R(ρ,θ) is the measured projection value for that ray.

R(ρ,θ) is the total of f along one ray. For fixed θ, R(·,θ) is one view. Stack views as rows to get the sinogram: ray position along one axis, angle along the other. This is the scanner's raw data.

  • Linearity: R of a·f + b·g is a·R_f + b·R_g, because the integral is linear.
  • Symmetry: R(ρ, θ+π) = R(−ρ, θ). The ray at angle θ+π and distance ρ is the same line as at θ and distance −ρ, so a 360° scan repeats itself. Scanners cover 180° plus the fan width.
  • A point object at (x₀,y₀) is non-zero only where ρ = x₀ cos θ + y₀ sin θ, so it draws one sine curve in the sinogram.

The Fourier slice theorem

Take the 1-D Fourier transform of one projection: P_θ(ω) = ∫ R(ρ,θ) e^(−i2πωρ) dρ. The Fourier slice theorem says this is F(u,v) read along one radial line.

P_θ(ω) = F(ω cos θ, ω sin θ)

P_θ(ω) is the 1-D Fourier transform of the projection at angle θ; ω is spatial frequency in cycles per unit length; F(u,v) is the 2-D Fourier transform of f(x,y); the right side is F evaluated at u = ω cos θ and v = ω sin θ.

  1. Write P_θ(ω) = ∫ [∫∫ f(x,y) δ(x cos θ + y sin θ − ρ) dx dy] e^(−i2πωρ) dρ.
  2. Swap the order of integration, so the ρ-integral acts on the delta alone.
  3. The delta forces ρ = x cos θ + y sin θ, so e^(−i2πωρ) becomes e^(−i2πω(x cos θ + y sin θ)).
  4. What remains is ∫∫ f(x,y) e^(−i2π(ux+vy)) dx dy with u = ω cos θ and v = ω sin θ, which is F(u,v).

One projection gives one line through the origin of the spectrum. Enough angles fill the frequency plane, and one inverse 2-D transform gives the image.

Filtered back-projection and its digital form

In polar frequency coordinates (ω,θ), du dv becomes ω dω dθ. That factor |ω| is the ramp; it is the Jacobian, not a design choice.

f(x,y) = ∫₀^π Q_θ(x cos θ + y sin θ) dθ,  Q_θ(ρ) = ∫ |ω| P_θ(ω) e^(i2πωρ) dω

|ω| is the ramp filter, the Jacobian of the polar change of variables; Q_θ is the filtered projection at angle θ; ρ = x cos θ + y sin θ selects, for pixel (x,y), the ray passing through it; the outer integral sums the filtered projections over all angles from 0 to π.

Q_θ is the filtered projection: the ramp lifts high frequencies, removing the 1/r blur of plain back-projection. Back-projection then smears each Q_θ along its rays and adds.

  1. Sample θ over [0, π) with a step Δθ of about 2/N radians (equivalently about (π/2)N views over 180°) for an N×N image.
  2. Sample ρ at the detector pitch Δρ, one sample per detector channel.
  3. Zero-pad each projection to at least twice its length and take its FFT.
  4. Multiply by the ramp, then inverse FFT, to get Q_θ.
  5. For each pixel, interpolate Q_θ linearly between the two nearest ρ samples, add over all θ, and multiply by Δθ.

Pure |ω| cut at ω_c = 1/(2Δρ) is Ram-Lak. Shepp-Logan multiplies |ω| by a sinc window; Hamming by a raised-cosine window. Both soften the cutoff, trading edge sharpness for less noise.

Fourier reconstruction for MRI

MRI measures k-space. With gradients on, each readout is one sample of the 2-D Fourier transform of proton density. No line integrals, so no Radon transform. Reconstruction is a 2-D inverse FFT, plus phase and field correction; non-Cartesian trajectories are gridded first.

Same theorem, different door: CT enters through projections and uses FBP; MRI enters through the spectrum and uses inverse FFT. Skipped phase-encode lines leave k-space gaps that partial-Fourier and compressed-sensing methods can fill.

Worked example

Question. A 2×2 object has f(0,0) = 1, f(1,0) = 0, f(0,1) = 0, f(1,1) = 1, with x and y in pixels. (a) Compute the projections at θ = 0°, 90° and 45°, giving the ray position ρ of each sample. (b) Show that the 0° and 90° views alone cannot separate f from h, where h(1,0) = h(0,1) = 1 and the rest is zero. (c) Compute the unfiltered back-projection b(x,y) using all three views.

  1. θ = 0°: ρ = x. The ray ρ = 0 passes through (0,0) and (0,1), giving R(0,0°) = 1 + 0 = 1. The ray ρ = 1 passes through (1,0) and (1,1), giving R(1,0°) = 0 + 1 = 1.
  2. θ = 90°: ρ = y. R(0,90°) = f(0,0) + f(1,0) = 1 + 0 = 1. R(1,90°) = f(0,1) + f(1,1) = 0 + 1 = 1.
  3. For h the same two views give column sums 0 + 1 = 1 and 1 + 0 = 1, and row sums 0 + 1 = 1 and 1 + 0 = 1. Both views are identical to f's, so they cannot tell the two objects apart.
  4. θ = 45°: ρ = (x + y)/√2. Ray ρ = 0 through (0,0) gives 1. Ray ρ = 1/√2 ≈ 0.7071 through (1,0) and (0,1) gives 0 + 0 = 0. Ray ρ = √2 ≈ 1.4142 through (1,1) gives 1. For h these three values are 0, 2, 0, which separates the objects.
  5. Back-project: b(x,y) = Σ_θ R(x cos θ + y sin θ, θ). Pixel (0,0) hits ρ = 0, 0, 0, so b = 1 + 1 + 1 = 3. Pixel (1,0) hits ρ = 1, 0, 0.7071, so b = 1 + 1 + 0 = 2. Pixel (0,1) hits ρ = 0, 1, 0.7071, so b = 2. Pixel (1,1) hits ρ = 1, 1, 1.4142, so b = 3.
  6. Result: b = [[3,2],[2,3]] against the true f = [[1,0],[0,1]]. The two pixels that should be 0 carry 2 each, and the total is 10 instead of 2. This is the 1/r blur that the ramp filter is there to remove.

Answer. b = [[3,2],[2,3]] in the same intensity units as f, a blurred version of f = [[1,0],[0,1]] whose total is 10 instead of 2.

Exam traps

  • Back-project first and you get the 1/r halo of the example: bright pixels are smeared over the whole image, so the pixel values are wrong and the total is inflated (10 instead of 2 in the example). Filter, then back-project, in that order.
  • θ in the formulas is in radians, but scanners step in degrees. Convert before you evaluate cos θ and sin θ.
  • The symmetry R(ρ, θ+π) = R(−ρ, θ) flips the sign of ρ. Folding a 360° scan into [0, π) without the sign flip mirrors half the sinogram.
  • The ramp |ω| is neither low-pass nor high-pass: it is zero at ω = 0 and rises linearly. It must be band-limited at ω_c = 1/(2Δρ): the sharp-cutoff version is Ram-Lak, and the smoother Shepp-Logan (sinc) and Hamming (raised-cosine) windows trade edge sharpness for less amplified noise.
  • Filtered back-projection assumes parallel rays. Fan-beam or cone-beam data must be rebinned to parallel geometry, or a fan-beam formula used, before the parallel-beam result applies.

3.7 Image compression fundamentals and data redundancy

A 1024×1024 grey image at 8 bits per pixel is 1 MiB of raw data, and a phone photo is many such images. Most of those bits repeat information. Image compression measures that repetition as coding, interpixel and psychovisual redundancy, then removes as much as the user allows. The result is smaller files for storage, faster uploads on slow links, and fewer bytes sent over a network. This chapter sets up the vocabulary, the ratios and the entropy limit that the actual coders obey.

You need: bits per pixel from Unit 1, Sampling and quantization, and the encoder is the reverse of the degradation path in 3.1.

Why an image file is large

Raw image size is rows × columns × bits per pixel. A 1024×1024 grey image at 8 bits per pixel needs 1024×1024×8 = 8,388,608 bits, which is 1 MiB. A colour image triples that. Sending millions of such images is expensive, so we compress.

Compression works because most of those bits repeat information. Three kinds of repetition are recognised.

  • Coding redundancy: the code words are longer than the symbol probabilities require. A fixed 8-bit code for a pixel value that appears 90% of the time wastes bits.
  • Interpixel redundancy: neighbouring pixels are correlated. A sky patch has almost the same value at (x,y) and (x+1,y).
  • Psychovisual redundancy: the eye does not see all fine detail equally. Removing detail the eye cannot notice saves bits but changes the image.

Lossless compression removes only the first two. Lossy compression also removes the third, so it can reach much smaller files.

Measuring compression and fidelity

C = b / B

b is the original number of bits, B is the compressed number of bits, and C is the compression ratio. C = 4 means the file is one quarter of the original size.

R = 1 − 1 / C

R is the relative data redundancy, a fraction between 0 and 1. C = 4 gives R = 0.75, so 75% of the original data was redundant.

Bits per pixel = total bits / (M × N), where M is the number of rows and N is the number of columns. A 1 MiB image at 1024×1024 has 8 bits per pixel. After compression to 256 KiB it has 2 bits per pixel.

Lossless means the decoder reproduces every pixel exactly. Lossy means pixels change, so we need a fidelity measure.

MSE = (1 / MN) Σ<sub>x=0</sub><sup>M−1</sup> Σ<sub>y=0</sub><sup>N−1</sup> [f(x,y) − g(x,y)]<sup>2</sup>

f(x,y) is the original pixel, g(x,y) is the decoded pixel, M rows and N columns. Lower MSE means better quality.

PSNR = 10 log<sub>10</sub>(MAX<sup>2</sup> / MSE)

MAX is the largest possible pixel value, for example 255 for 8-bit images. PSNR is in decibels (dB), and higher is better.

SNR compares signal power to error power: SNR = 10 log10(σf2 / σe2), where σf2 is the variance of the original image and σe2 is the variance of the error. Higher SNR means better quality.

The source encoder and the entropy limit

A source encoder has three blocks: mapper, quantizer and symbol coder. The decoder runs them in reverse.

  • Mapper: transforms pixels to reduce interpixel redundancy. It is reversible. Prediction and the DCT are mappers.
  • Quantizer: rounds values to reduce psychovisual redundancy. It is the only lossy step.
  • Symbol coder: gives short code words to likely symbols to reduce coding redundancy. It is lossless. Huffman coding is in 3.8.
H = − Σ p<sub>i</sub> log<sub>2</sub> p<sub>i</sub>

pi is the probability of symbol i, and H is the entropy in bits per symbol. No lossless code can average fewer than H bits per symbol.

If four symbols have probabilities 0.5, 0.25, 0.125 and 0.125, then H = 1.75 bits per symbol. A fixed 2-bit code uses 2 bits for every symbol; an entropy coder can approach 1.75.

Predictive coding and transform coding are the practical mappers; they are in 3.9. This chapter only fixes the model and the limits.

Worked example

Question. A 1024×1024 8-bit grey image is compressed to a 256 KiB file. (a) Find the original bits, the compressed bits, the compressed bits per pixel, the compression ratio C and the relative data redundancy R. (b) Four symbols have probabilities 0.5, 0.25, 0.125 and 0.125. Find the entropy H.

  1. Original bits b = 1024 × 1024 × 8 = 8,388,608 bits.
  2. Original bytes = 8,388,608 / 8 = 1,048,576 bytes = 1 MiB.
  3. Compressed bytes = 256 × 1024 = 262,144 bytes.
  4. Compressed bits B = 262,144 × 8 = 2,097,152 bits.
  5. Compressed bits per pixel = 2,097,152 / (1024 × 1024) = 2 bits per pixel.
  6. Compression ratio C = b / B = 8,388,608 / 2,097,152 = 4.
  7. Relative data redundancy R = 1 − 1/C = 1 − 1/4 = 0.75, which is 75%.
  8. Entropy H = −Σ pi log2 pi.
  9. 0.5 × log2(1/0.5) = 0.5 × 1 = 0.5 bits.
  10. 0.25 × log2(1/0.25) = 0.25 × 2 = 0.5 bits.
  11. 0.125 × log2(1/0.125) = 0.125 × 3 = 0.375 bits, and this appears twice, so 0.75 bits.
  12. H = 0.5 + 0.5 + 0.75 = 1.75 bits per symbol.

Answer. C = 4, R = 0.75 (75% redundant), the compressed image is 2 bits per pixel, and H = 1.75 bits per symbol.

Exam traps

  • C and R are different numbers for the same file. C = 4 means R = 0.75, not R = 4 and not R = 75.
  • Entropy uses log2 because the answer is in bits per symbol. Using log10 gives a smaller number in the wrong unit.
  • Keep b and B in the same unit inside C = b / B. Do not divide original bits by compressed bytes.
  • Lossless compression cannot average below the entropy H. A claim of lossless compression below H is impossible, not just difficult.
  • PSNR is in dB and higher is better; MSE is lower when the image is better. Do not say a low PSNR means good quality.

3.8 Huffman, arithmetic and run-length coding

Huffman coding and arithmetic coding are entropy coders. They turn a stream of symbols into bits, giving short code words to likely symbols and long code words to rare ones. Huffman coding builds an optimal prefix code from a tree. Arithmetic coding keeps a whole message inside one shrinking interval and writes a fraction from that interval. Run-length coding is a simple repeat-collapsing coder that replaces repeated values by a count; it is often used before an entropy coder. Huffman and arithmetic coding sit after quantization in an image compressor, and run-length coding often prepares data for them. A fax page, a palette image and a JPEG block all use one of them. The aim is to approach the entropy H, the theoretical minimum bits per symbol.

You need: 3.7 for entropy and bits per pixel.

Huffman coding: merge the two lowest probabilities

Huffman coding gives short code words to likely symbols. A prefix code is a set of code words in which no code word is the start of another. That property lets a decoder read bits one by one and stop as soon as a complete code word appears.

  1. Make one leaf for each symbol, labelled with its probability pᵢ.
  2. Put all nodes in a list.
  3. Repeatedly remove the two nodes with the smallest probabilities and join them under a parent whose probability is their sum.
  4. Stop when one root remains; label one child edge 0 and the other 1.
  5. Read each symbol's code from root to leaf.
  6. To decode, start at the root; for each bit go left on 0 or right on 1; at a leaf output the symbol and return to the root.

L = Σ pᵢ lᵢ

L is the average length in bits per symbol; pᵢ is the probability of symbol i; lᵢ is the length in bits of its code word.

H = −Σ pᵢ log₂ pᵢ

H is the entropy in bits per symbol; log₂ is the base-2 logarithm; Σ runs over all symbols.

Every Huffman code has L ≥ H. Huffman is optimal among prefix codes, and L < H + 1. Two limits matter. With exactly two symbols, both code words must be 1 bit long, so L = 1 even when H is small (for p = 0.9 and 0.1, H ≈ 0.469 but L = 1). With more symbols the code words take different lengths and L can be larger than 1. The code table or the tree must be sent once, and that overhead matters for short messages.

Arithmetic coding: one interval for the whole message

Arithmetic coding does not give one code word per symbol. It represents the whole message by a number in [0, 1). Start with low = 0 and high = 1. For each symbol, take its cumulative lower bound cᵢ and probability pᵢ. The new interval is [low + (high − low)cᵢ, low + (high − low)(cᵢ + pᵢ)). After the last symbol, any number inside the final interval identifies the message, but the decoder needs to know when to stop. The encoder writes enough bits of such a number and also sends the message length, or uses a special end-of-message symbol, so the decoder stops after the right number of symbols.

The decoder mirrors the encoder. It starts with [0, 1), finds which symbol's subinterval contains the received number, outputs that symbol, then maps the number into that subinterval and repeats. It stops when it has output the sent message length, or when it outputs the end-of-message symbol. For skewed probabilities arithmetic coding beats Huffman over long messages. In a long message with p = 0.9, arithmetic coding spends about −log₂ 0.9 = 0.152 bits per occurrence of that symbol on average, against a full 1 bit for Huffman. A single short message still costs whole bits plus a termination cost. Finite precision limits the interval size; practical coders renormalize and emit bits as they go.

Run-length coding: turn repeats into count pairs

Run-length coding (RLE) replaces each run by a pair (value, length). A run is a maximal sequence of equal values. Encoding: scan left to right; start a count at 1; add 1 while the next value is the same; when the value changes, write the pair and start a new count; write the last pair. Decoding: read a pair (v, l), write v exactly l times, then read the next pair.

For binary and palette images, long runs of the same value are common, so RLE is simple and fast. For a noisy photograph, neighbouring pixels rarely repeat, so most runs have length 1 and the count adds overhead; the file can grow.

Worked example

Question. Four symbols have probabilities a = 0.4, b = 0.2, c = 0.2, d = 0.2. Build the Huffman tree, give each code, compute average length L and entropy H, and encode the bit row 0000111000 with run-length coding. State whether the Huffman code is within 0.1 bit of H.

  1. Start with four leaves: a = 0.4, b = 0.2, c = 0.2, d = 0.2.
  2. Merge the two lowest probabilities, b and c: b + c = 0.4. The list is now a = 0.4, d = 0.2, and the pair node 0.4.
  3. Merge the two lowest probabilities, d and the pair node: d + 0.4 = 0.6. The list is now a = 0.4 and 0.6.
  4. Merge a and 0.6: 0.4 + 0.6 = 1.0. This is the root.
  5. Read codes with left edge 0 and right edge 1: a = 0, d = 10, b = 110, c = 111.
  6. The code lengths are l(a) = 1, l(d) = 2, l(b) = 3, l(c) = 3 bits.
  7. Compute L = 0.4(1) + 0.2(2) + 0.2(3) + 0.2(3) = 0.4 + 0.4 + 0.6 + 0.6 = 2.0 bits per symbol.
  8. Compute H = −0.4 log₂ 0.4 − 3(0.2 log₂ 0.2). Using log₂ 0.4 = −1.321928 and log₂ 0.2 = −2.321928 gives H = 0.528771 + 1.393157 = 1.921928 ≈ 1.92 bits per symbol.
  9. The gap is L − H = 2.0 − 1.92 = 0.08 bit, which is within 0.1 bit.
  10. Run-length encode 0000111000: 0000 → (0,4), 111 → (1,3), 000 → (0,3). That is 3 pairs.

Answer. The Huffman codes are a = 0, d = 10, b = 110, c = 111; L = 2.0 bits per symbol, H ≈ 1.92 bits per symbol, a gap of 0.08 bit; the row encodes as (0,4)(1,3)(0,3), 3 pairs.

Exam traps

  • Merging the two highest probabilities gives a valid tree but not a minimum-length Huffman code; always merge the two lowest.
  • A code such as a = 0, b = 01 is not prefix-free because 0 is a prefix of 01; codes must sit only at leaves.
  • Average length weights each code length by its probability pᵢ, not by how many symbols have that length.
  • Run-length coding is not automatically smaller; a noisy photograph has short runs, so the count pairs add overhead.
  • The Huffman tree or code table is part of the compressed data, so ignore it only when the decoder already knows it.

3.9 Predictive coding, transform coding and compression standards

Neighbouring pixels are usually nearly equal; that near-equality is where compression comes from. Predictive coding guesses the next pixel and sends only the small error. Transform coding rotates an 8×8 block into frequency coefficients that are mostly near zero, then drops tiny ones. Both hand small numbers to the entropy coder in 3.8. JPEG, PNG and phone cameras use one of the two.

You need 3.7 for the encoder model and entropy, 3.8 for Huffman and run-length coding, and the DCT from Unit 2.

Predictive coding: send the error, not the pixel

A raster scan sends pixels row by row. When the decoder reaches (x,y), it already holds pixels above and left, which are close to f(x,y). A fixed weighted sum of them is a good guess. Send the guess's mistake.

f̂(x,y) = round( Σₙ aₙ · f(x−iₙ, y−jₙ) ) ,   e(x,y) = f(x,y) − f̂(x,y)

f(x,y) is the true pixel (0–255 for 8-bit grey); f̂ is the prediction from already-reconstructed neighbours; n numbers the neighbours; aₙ is the weight and (iₙ,jₙ) the offset for neighbour n; round() makes encoder and decoder agree exactly; e is the prediction error, the only number sent.

Predict from the left pixel. Row 120, 122, 124, 126 gives errors 120 (first pixel), 2, 2, 2. Pixels over 0–255 cost 7–8 bits each; errors near zero cost far less. This removes interpixel redundancy from 3.7 before coding.

  1. Encoder: build f̂ from reconstructed neighbours.
  2. Encoder: e = f − f̂.
  3. Encoder: quantise ê = round(e/q)·q; q = 1 for lossless.
  4. Encoder: entropy-code ê.
  5. Encoder: reconstruct f̃ = f̂ + ê and store it as a neighbour.
  6. Decoder: read ê, rebuild f̂ from stored neighbours, add, store f̃.

With q = 1 nothing is rounded, so the coder is lossless and f̃ = f. A quantiser inside the loop makes it lossy DPCM. The predictor must use reconstructed values; using original f makes encoder and decoder drift apart.

Transform coding: rotate the block, then quantise

Transform coding works on an 8×8 block, 64 pixels at once, and changes the axis. The 2-D DCT from Unit 2 rewrites it as 64 frequency coefficients F(u,v).

F(u,v) = C(u)·C(v)·Σₓ Σᵧ f(x,y)·cos[(2x+1)uπ/16]·cos[(2y+1)vπ/16]

N = 8, so u and v run 0 to 7; C(0) = √(1/8) = 0.354, C(k) = √(2/8) = 0.5 for k > 0; F(0,0) is DC and equals 8 × block mean; the other 63 are AC coefficients.

Natural blocks are smooth, so DC carries most energy and AC terms fall fast with frequency. A flat block has all AC zero. This is energy compaction: 64 pixels become one big number, a few small ones and many near-zeros.

  • DCT output is real; DFT of a real block is complex, so it needs two numbers per coefficient. No complex arithmetic means cheap integer hardware.
  • Separable: eight 1-D row transforms then eight 1-D column transforms, about 1024 multiply-adds naively, against about 4096 for direct 64-term sums.
  • Energy compaction is close to Karhunen–Loève optimum for natural images, and no wrap-around discontinuity at block edges as with DFT.
T(u,v) = round( F(u,v) / Q′(u,v) ) ,   decoded F′(u,v) = T(u,v) · Q′(u,v)

Q′(u,v) is the step for that coefficient from a standard table scaled by a quality factor; smaller quality means larger steps and fewer bits; T(u,v) is the integer sent; this rounding is the only lossy step in baseline JPEG. The luma table starts 16, 11, 10, 16, 24, 40, 51, 61, so DC gets a fine step and high frequencies coarse ones. That is bit allocation written down.

After quantisation the block is read zig-zag from DC outward. Zeros then sit together at the end, so run-length coding collapses them into (run, value) pairs ending in end-of-block, and Huffman codes those symbols. Without the scan the zeros are scattered and run-length coding gains little. At very low bit rates neighbouring blocks round to slightly different DC levels and the 8×8 grid shows — blockiness.

The standards

JPEG baseline is that pipeline: 8×8 DCT, scaled table, zig-zag. The DC coefficient is DPCM-coded as a difference from the previous block's DC and Huffman-coded; AC coefficients are zig-zag scanned and run-length coded. JPEG progressive sends the same coefficients in several scans, low frequencies first, so a slow link shows a rough picture early. JPEG also defines a lossless DPCM mode, rarely used because PNG and JPEG-LS beat it. JPEG 2000 replaces the 8×8 DCT with a wavelet transform over the whole image: no blockiness, and smooth scaling in quality and resolution.

MPEG-1/2/4, H.264/AVC and HEVC/H.265 split each frame into blocks. Inter-coded blocks are predicted from one or two previously decoded reference frames, which for B-frames may lie later in display order; intra-coded blocks are predicted spatially inside the same frame. The residual is transform-coded, then Huffman- or arithmetic-coded. So video is prediction between frames plus transform coding within a frame.

Analyze Explain how the zig-zag scan plus run-length coding reduces the bit count, and what happens if you skip the scan. 5 marks

After quantisation most high-frequency coefficients are zero. Zig-zag reads DC outward so zeros form one long run at the end. Takeaways

  1. Image restoration starts from a model g(x,y)=H[f(x,y)]+n(x,y); without a model, filtering is only guesswork.
  2. The probability density of noise decides which restoration filter is suitable.
  3. Averaging reduces Gaussian noise but blurs edges; median filtering removes impulse noise while preserving edges better.
  4. Adaptive filters change their strength according to local variance, so flat areas are smoothed more than detailed areas.
  5. Periodic noise appears as spikes away from the spectrum centre and is removed by notch filtering those spikes.
  6. Inverse filtering is unstable when H is small; the Wiener filter controls this by adding a noise-to-signal term.
  7. The Radon transform collects line integrals, and filtered back-projection reconstructs an image by ramping projections before back-projecting them.
  8. Compression works by finding and removing coding, interpixel and psychovisual redundancy.
  9. Practical compression pipelines combine prediction or transform coding with quantization and an entropy coder such as Huffman, arithmetic or run-length coding.

Evaluate Compare predictive coding and transform coding. Design a block-based compression pipeline that includes quantization and entropy coding, and explain where loss occurs. 15 marks

Prediction from neighbouring pixels; Transform such as DCT concentrates energy; Quantization is the main lossy step; Entropy coding of coefficients or prediction errors; Trade-off between bit rate and visual quality.

Evaluate Evaluate Huffman coding, arithmetic coding and run-length coding for image compression. State when each is effective and where each is weak. 12 marks

Huffman is optimal prefix coding but needs integer code lengths and a code table; Arithmetic coding approaches entropy more closely and handles skewed probabilities well; Run-length coding works on repeated runs and is simple; Choice depends on symbol statistics and image structure.

Glossary

Adaptive filter
Filter whose behaviour changes with local image statistics such as mean and variance.
Arithmetic coding
Entropy coding method that represents a whole message by one number or interval.
Back-projection
Reconstruction step that smears each projection back across the image plane.
Compression ratio
Ratio of the original data size to the compressed data size.
Degradation model
Mathematical description of how an imaging system and noise transform the true image into the observed image.
Discrete cosine transform (DCT)
Orthogonal transform that concentrates energy of natural image blocks into few coefficients.
Entropy
Average information per symbol in a source, measured in bits per symbol.
Huffman tree
Binary tree built by merging least probable symbols, used to assign Huffman code words.
Image restoration
Process of estimating the true image from a degraded and noisy observed image using a degradation model.
Inverse filter
Restoration filter that divides the observed spectrum by the degradation function H.
Mean filter
Filter that replaces a pixel by an average of its neighbourhood values.
Notch filter
Frequency-domain filter that removes narrow selected frequency bands.
Order-statistic filter
Filter that ranks neighbourhood pixel values and chooses one, such as the median or maximum.
Periodic noise
Noise that repeats at one or more frequencies and appears as spikes in the Fourier spectrum.
Point spread function
Response of a linear imaging system to a point source, used as the spatial form of H.
Predictive coding
Compression method that codes the difference between a pixel and a prediction from nearby pixels.
Prefix code
Code in which no code word is the beginning of another code word, allowing unique decoding.
Projection
Set of line integrals of an object along parallel lines at one angle.
Quantization
Mapping of many possible values to a smaller set, usually the main lossy step in compression.
Radon transform
Transform that maps an image to its line integrals as a function of angle and offset.
Run-length encoding
Compression method that stores repeated values as a value-count pair.
Sinogram
Two-dimensional display of projections indexed by angle and offset.
Transform coding
Compression method that transforms blocks, quantizes coefficients, and entropy-codes the result.
White noise
Noise whose power is spread uniformly over all frequencies.
Wiener filter
Restoration filter that minimizes mean square error by balancing inverse filtering against noise amplification.
