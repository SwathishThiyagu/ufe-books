2.1 Basic intensity transformations: negative, log, power-law

A point operation changes a pixel using only its own value. The same curve s = T(r) is applied to every pixel, independent of neighbours. It exists because many images are too dark, too bright, or have a range too wide for a display. The negative, log and power-law curves are the basic shapes; contrast stretching is a piecewise-linear extension. Phone camera exposure sliders, medical X-ray display and Fourier-spectrum viewers all use these maps.

You need the 8-bit image model from Unit 1: integer pixel values 0 to 255, L = 256 levels, and normalised values r/255 in 0 to 1.

Point operation and the lookup table

An image is an array of pixels. In an 8-bit grey image each pixel is an integer r from 0 to 255, where L = 256 is the number of levels. A point operation, also called an intensity transformation, computes the output pixel s from r alone: s = T(r). The function T is fixed for the whole image. It does not look at neighbours, so a 12-megapixel photo needs the same curve at every point. Identity is T(r) = r.

A lookup table (LUT) makes this fast. Compute T(0) to T(255) once, store 256 bytes, then for each pixel read table[r] and write s. For RGB, apply the same table to R, G and B separately unless you are changing only intensity in HSI.

s = T(r)

s is the output intensity 0–255; r is the input intensity 0–255; T is the fixed mapping curve.

  1. Build a 256-entry table: table[r] = T(r) for r = 0, 1, 2, ..., 255.
  2. Read the next pixel value r.
  3. Set the output pixel to table[r].
  4. Repeat for every pixel and every colour channel if needed.

Negative and log transforms

The negative is the simplest curve: s = L − 1 − r. For 8-bit data, s = 255 − r. It reverses brightness: black becomes white. It is used to display a faint mammogram or a dark film scan because the eye reads dark detail on a bright background better. The shape is a straight line with slope −1.

The log transform is s = c log(1 + r). Here log is natural log (ln), c is a scale constant. For 8-bit values choose c = (L − 1)/ln(L) = 255/ln(256) ≈ 45.99. Then r = 0 gives s = 0 and r = 255 gives s = 255 exactly. The curve rises fast at low r and flattens near the top, so it lifts dark pixels and compresses a wide range. Fourier spectra are the classic user: one bright DC value can be millions of times larger than the weak high-frequency terms, and the log view makes all frequencies visible.

The inverse-log (exponential) curve does the opposite: it expands bright values and leaves dark values low. A normalised form is s = (e^(a r) − 1)/(e^a − 1), with a > 0 controlling steepness. It is used when highlights, not shadows, carry the detail. A log curve with too large a scale constant c can exceed 255 and clip; choose c so T(255) = 255.

Power law and contrast stretching

Power-law, or gamma, transformation is s = c r^γ, with r normalised to 0 ≤ r ≤ 1. For 8-bit integers use s = 255 c (r/255)^γ. γ (gamma) is a positive number; c is a scale factor, usually 1 when the input is already normalised. For γ > 1 the curve lies below the identity: bright values are pulled down and the bright range is expanded, so a washed-out image gains contrast in the highlights. For γ < 1 the curve lies above the identity: dark values are raised, shadows are lifted, and the dark range is expanded, so a dark image brightens. γ = 1 is identity.

Contrast stretching is a piecewise-linear curve. Pick two control points (r1, s1) and (r2, s2), with r1 < r2 and s1 < s2. Map r ≤ r1 to s1, r ≥ r2 to s2, and map the middle by a straight line. Values below r1 and above r2 are clipped to the display range. An image whose histogram sits in 40 to 180 can be stretched to 0 to 255 this way. Choosing the points from a histogram is the link to histogram processing.

s = s1 + (s2 − s1)(r − r1)/(r2 − r1)

for r1 < r < r2; below r1 use s1, above r2 use s2.

Worked example

Question. An 8-bit image has pixel values 0, 64, 128, 192 and 255. Apply (a) the negative, (b) the log transform s = 45.98 ln(1 + r), (c) the power law with γ = 0.4 and c = 1. Give the outputs rounded to integers.

  1. Use L = 256, so the 8-bit maximum is L − 1 = 255.
  2. Negative: s = 255 − r. For r = 0, 64, 128, 192, 255 the outputs are 255, 191, 127, 63, 0.
  3. Log: s = 45.98 ln(1 + r). r = 0 gives 45.98 ln 1 = 0. r = 64 gives 45.98 ln 65 = 191.94 ≈ 192. r = 128 gives 45.98 ln 129 = 223.45 ≈ 223. r = 192 gives 45.98 ln 193 = 241.98 ≈ 242. r = 255 gives 45.98 ln 256 = 254.96 ≈ 255.
  4. Gamma 0.4: s = 255(r/255)^0.4. r = 0 gives 0. r = 64 gives 255(64/255)^0.4 = 146.68 ≈ 147. r = 128 gives 255(128/255)^0.4 = 193.55 ≈ 194. r = 192 gives 255(192/255)^0.4 = 227.64 ≈ 228. r = 255 gives 255.
  5. The log curve pushes the low values 64 and 128 far up while the top stays near 255. That is dynamic-range compression. Check that the log curve maps r = 255 exactly to 255 because c was chosen for that.

Answer. Negative outputs: 255, 191, 127, 63, 0. Log outputs: 0, 192, 223, 242, 255. Gamma 0.4 outputs: 0, 147, 194, 228, 255.

Exam traps

  • Gamma on raw values: computing 255·(r)^γ with r = 64 gives an enormous number (about 1346 for γ = 0.4), not the intended 147. Use r/255 inside the power and multiply by 255 after.
  • Missing c in s = c log(1 + r): with c = 1 an 8-bit output is at most 5.5 and appears black. For 8-bit use c = 255/ln 256 ≈ 45.99.
  • Top endpoint: for increasing compression curves such as log and power-law, choose c so T(255) = 255; the negative deliberately maps 255 to 0. Check the endpoint for the specific curve before writing the LUT.
  • Negative on colour: in HSI invert intensity I only; in RGB invert each channel separately. Mixing them gives wrong hue.
  • Piecewise contrast stretch: keep control points ordered r1 < r2 and s1 < s2; reversed points make a falling curve and invert contrast.

2.2 Histogram processing: equalization and specification

A histogram counts how many pixels take each grey level. Histogram equalisation uses that count to build a curve that spreads busy levels apart and squeezes empty ones together, so the output fills the whole 0 to L−1 range. It is a standard first move for washed-out or dark images in phone camera previews, medical X-ray display and document scanning. Specification goes further: you supply the histogram you want, and the method finds a curve that produces it.

You need: Chapter 2.1, where a point operation s = T(r) uses only the pixel's own value, and the 0 to L−1 output range.

Histogram, normalised counts and the equalisation curve

For an image with M rows and N columns, the histogram counts pixels at each grey level. Write h(r_k) = n_k, where r_k is the k-th grey level, k = 0, 1, …, L−1, L is the number of levels (256 for 8-bit), and n_k is how many pixels have value r_k. The counts add to MN. Divide by MN to get the normalised histogram p(r_k) = n_k/(MN). It is a probability: p(r_k) is the chance that a pixel picked at random has level r_k, and the p(r_k) sum to 1.

Equalisation uses the running total of p. In the continuous case, treat r as a real number from 0 to L−1 with density p_r(r). Define s = T(r) = (L−1) ∫₀^r p_r(w) dw. Here s is the output level and w is a dummy variable for integration. The slope is ds/dr = (L−1)p_r(r). For a monotonic T, the output density is p_s(s) = p_r(r) / (ds/dr) = 1/(L−1). So s is uniform on 0 to L−1: every output band of equal width gets the same share of pixels. That is the goal. T is a cumulative distribution, so it never decreases; the order of grey levels is preserved, dark stays darker than bright.

s = T(r) = (L−1) ∫₀^r p_r(w) dw

s is the output level from 0 to L−1; r is the input level; L is the number of grey levels (256 for 8-bit); p_r(w) is the input probability density; w is the dummy variable of integration.

Discrete equalisation: scale, round, merge

In a digital image the integral becomes a sum. The discrete equalisation is s_k = T(r_k) = (L−1) Σ_{j=0}^{k} p(r_j) = ((L−1)/MN) Σ_{j=0}^{k} n_j. The sum is the cumulative count up to level r_k. Multiply it by (L−1)/MN, then round to the nearest integer. The rounding is essential: s_k must be a valid grey level.

  1. Count n_k for every input level r_k.
  2. Form the cumulative count c_k = n_0 + n_1 + … + n_k.
  3. Compute s_k = round((L−1)c_k/(MN)).
  4. Build the lookup table r_k → s_k.
  5. Replace every pixel value r_k by s_k.

Two things surprise students. First, the output histogram is not flat. Rounding sends several input levels to the same output level, so the output has spikes. In the figure, levels 3 and 4 both become 6, and levels 5, 6, 7 all become 7: five input levels merge into two output levels. Second, the curve acts on pixel values, not on the histogram bins. You do not equalise the counts; you equalise the image. Equalisation can over-brighten a mostly dark image, because the crowded dark levels get spread over most of the output range. The sparse bright levels are squeezed into the top of the range. That is why the method is often applied locally or with a clip limit.

s_k = round( ((L−1)/MN) Σ_{j=0}^{k} n_j )

s_k is the output level for input level r_k; n_j is the count at level r_j; M×N is the total number of pixels; L is the number of levels; round(·) rounds to the nearest integer.

Specification (matching) and local equalisation

Equalisation always aims at a flat output. Specification lets you aim at a chosen histogram p_z(z). Some syllabi call it histogram matching. Procedure: equalise the input to s = T(r) = (L−1)Σ p_r. Equalise the desired histogram to a flat scale G(z) = (L−1)Σ p_z. Both s and G(z) lie on the same 0 to L−1 axis. Invert G to get z = G⁻¹(s), and the mapping is r → s → z. In discrete form, compute s_k for every input level, compute G(z_q) for every desired level z_q, and for each s_k pick the z_q whose G(z_q) is closest. That lookup table is applied to the pixels. Use it when two images must share a tone scale, such as a satellite tile matched to a reference scene.

Global equalisation uses one curve for the whole image. Local equalisation divides the image into blocks, often an 8×8 grid of tiles, equalises each block, and blends across block borders. CLAHE, contrast-limited adaptive histogram equalisation, adds a clip limit: counts above the limit are clipped and redistributed before the cumulative sum. The clip stops flat regions from being amplified into noise. Most imaging libraries ship a histogram-equalisation function and a CLAHE class, for example equalizeHist and createCLAHE in OpenCV. Apply the method to the intensity channel of an HSI image, not to R, G and B separately, or colours shift. Local block operations are a step towards the spatial filtering of Chapter 2.3.

Exam traps

  • Scaling by 1/MN instead of (L−1)/MN leaves the output in 0 to 1, not 0 to L−1.
  • Applying the transform to the histogram counts instead of to the pixels gives a flattened histogram but the wrong image.
  • Claiming equalisation gives a perfectly flat histogram in the discrete case. Rounding merges levels, so spikes remain.
  • Forgetting to round, or using a non-monotonic curve. T must never decrease, or grey order reverses.
  • Equalising R, G and B channels separately in colour shifts hues; use the intensity channel (HSI) or a colour-preserving method.

2.3 Spatial filtering basics: correlation and convolution

Spatial filtering replaces each pixel by a weighted sum of its neighbours. A small array of weights, the mask, slides over the image; at every position its weights multiply the pixels underneath and the results are added. This is the first neighbourhood operation after the point operations of chapter 2.1. It removes noise, sharpens edges and finds local patterns, so it sits inside phone-camera denoising, medical scan enhancement and the first layers of a CNN. This chapter keeps to grey images; colour is Unit 1.

You need: Unit 1 pixel neighbourhoods and coordinate conventions, and chapter 2.1 for the point-operation contrast.

The mask and the sliding sum

Mask. A spatial filter is a small array w of weights. Textbooks call it a mask, kernel, window or template. Its size is m×n, usually odd, such as 3×3 or 5×5. The anchor is the mask cell placed on the output pixel. For an odd mask the anchor is the centre cell.

Sliding sum. Put the anchor on pixel (x,y) of grey image f. Multiply every weight w(s,t) by the pixel under it, f(x+s,y+t), and add all products. The result is output g(x,y). Move the anchor one pixel and repeat.

g(x,y) = Σ<sub>s</sub> Σ<sub>t</sub> w(s,t)·f(x+s, y+t)

g(x,y) is the output pixel; w(s,t) is the mask weight at offset (s,t); f(x+s,y+t) is the input pixel under that weight; the sums run over all mask offsets. For a 3×3 mask, s and t each run from −1 to 1, giving 9 terms.

Linear shift-invariant. The same mask must act at every pixel. This holds when the system is linear, so the response to a sum of inputs is the sum of responses, and shift-invariant, so moving the input moves the output by the same amount. The mask weights then do not depend on x or y.

Correlation and convolution

Correlation uses w exactly as written. It is the formula above. Convolution rotates w by 180° before the sliding sum: reverse the rows and columns. An even mask has no centre cell; rotate about the point between its four middle entries. If an even mask uses its top-left entry as anchor, the rotation moves the anchor to the bottom-right entry; place that cell on the output pixel for convolution.

g(x,y) = Σ<sub>s</sub> Σ<sub>t</sub> w(−s,−t)·f(x+s, y+t)

w(−s,−t) is the mask after a 180° rotation; all other symbols are as in correlation. Equivalently, convolution is Σ w(s,t)·f(x−s, y−t).

Why flip? Convolution is commutative and associative, and the Fourier transform turns it into multiplication (chapter 2.6). Correlation is the natural rule for template matching, where the mask is a patch to find. If w is symmetric about its centre, such as a box, Gaussian or Laplacian mask, the flip changes nothing and both rules give the same numbers.

Borders, padding and separable masks

Output shrinks. For an M×N image and an m×n mask with no padding, valid correlation has (M−m+1)×(N−n+1) pixels. A 5×5 image with a 3×3 mask gives 3×3 output; border pixels have no full window.

Padding. Add pixels outside before filtering. Zero padding uses 0; replicate padding repeats the nearest edge pixel; mirror padding reflects across the edge. Zero can create a dark rim; replicate adds no new values and holds the edge value flat; mirror avoids a jump in pixel value at the border and keeps the trend of the edge, but it reverses the slope direction. Both avoid the artificial step that zero padding can create. Pad by one pixel on each side for a 3×3 mask to keep the output size M×N.

Separable masks. A mask is separable when w(s,t)=u(s)v(t). Apply u as a 1-D pass along one axis, then v along the other. For P pixels, a full m×n mask costs about mnP multiplications; the two passes cost about (m+n)P. A 3×3 mask drops from 9 to 6 multiplications per pixel. Box and Gaussian masks are separable; a general mask is not. Chapter 2.4 uses these masks for smoothing and chapter 2.5 for sharpening.

Worked example

Question. A 3×3 grey image has rows 1 2 3 / 4 5 6 / 7 8 9. A 2×2 mask w is 1 2 / 3 4, with its anchor at the top-left entry. Using the top-left 2×2 window, compute correlation and convolution. State why the answers differ.

  1. The top-left 2×2 window of f is 1 2 / 4 5. Read row by row: 1, 2, 4, 5.
  2. Correlation uses w as it is: 1 2 / 3 4. Products: 1×1=1, 2×2=4, 4×3=12, 5×4=20. Sum = 1+4+12+20 = 37 at pixel (0,0).
  3. Convolution flips w by 180° about its centre. The flipped mask is 4 3 / 2 1. Because the original anchor was the top-left entry, after the flip it is the bottom-right entry. Place that bottom-right cell on the output pixel. With the top-left 2×2 window, the products are 1×4=4, 2×3=6, 4×2=8, 5×1=5. Sum = 4+6+8+5 = 23 at pixel (1,1). At pixel (0,0) convolution would need pixels outside the image.
  4. For a 2×2 mask the centre lies between the four cells, so the flip is a 180° rotation of the whole 2×2 array. For even masks, the anchor convention decides which output pixel receives the sum.
  5. The two sums differ because w is not symmetric about its centre. A symmetric mask would give equal correlation and convolution outputs.

Answer. Correlation output is 37 at pixel (0,0). Convolution output is 23 at pixel (1,1), because the flipped mask's bottom-right cell is placed on that pixel. They differ because w is not symmetric.

Exam traps

  • A convolution answer that skips the 180° flip is a correlation answer; with a non-symmetric mask it is wrong.
  • For an even-sized mask, flip about the point between the four middle entries, not about the top-left entry; state the anchor convention.
  • Do not drop border pixels silently: give the output size or the padding rule, because a 3×3 mask on an M×N image shrinks the valid output.
  • Zero padding is only one choice; say zero, replicate or mirror, because the outside values change border results.
  • A separable filter is not the same as a symmetric filter; only a rank-1 mask splits into two 1-D passes.

2.4 Smoothing spatial filters

A smoothing spatial filter replaces each output pixel with a weighted average of the input pixel and its neighbours. A single noisy pixel is pulled towards the local average, so noise falls. The same average also softens true changes, so edges and fine text blur. This is why smoothing is used before thresholding, before shrinking an image, or as a first step in edge detection, and why it must be tuned. A night photo of a vehicle number plate is a good test: smoothing can remove grain but can also merge the digits.

You need: correlation, convolution and padding from Chapter 2.3; smoothing is correlation with a mask whose weights are positive and sum to 1.

Box filter: average of neighbours

A box filter, also called a mean filter, replaces a pixel by the average of a k × k window around it. The mask is a small matrix of weights, here all 1/k², so every neighbour has equal say. For k = 3 each weight is 1/9. Correlation is enough because the mask is symmetric; see Chapter 2.3. On a night number-plate photo, grain appears as one or two pixels much brighter or darker than their neighbours. Averaging pulls an isolated bright pixel down. The cost is that a true edge is also averaged: background and digit mix, and the transition spreads over about k pixels. Inside a flat region the output equals the input. A larger window removes more noise but blurs more. A 3 × 3 is common; 5 × 5 is slower and visibly softer. Thin lines fade because the window contains more background than line.

g(x,y) = (1/k²) × Σ f(x+s, y+t)

g(x,y) is the output pixel at row x and column y; f is the input image; k is the window width, so k² is the number of pixels; s and t run from −a to +a with k = 2a + 1.

Use this filter when the noise is random and the objects are large. Do not use it when the smallest detail is the digit stroke itself. The next figure compares the box weight with a Gaussian weight at the same distance from the centre.

Gaussian mask: distance matters

A Gaussian smoothing mask gives the centre pixel the largest weight and farther pixels smaller weights. The 3 × 3 mask with rows 1 2 1, 2 4 2, 1 2 1 has weights that sum to 16. Its centre weight is 4/16 = 0.25, an edge neighbour is 2/16 = 0.125, and a corner is 1/16 = 0.0625. The box filter gives every position 1/9 ≈ 0.111. So the Gaussian keeps the centre stronger and treats far neighbours less. That is why an edge survives a little better: the mix is less uniform. For an isolated spike the box can pull the value down more, but it also smears the spike equally in all directions.

G(d) = (1/(√(2π) σ)) exp(−d²/(2σ²))

G(d) is the weight at distance d pixels from the mask centre; σ is the standard deviation in pixels, which sets the width of the blur; exp means e raised to the power shown; the factor before exp makes the area under the curve equal 1.

In two dimensions the Gaussian is the product of two 1-D Gaussians, one along rows and one along columns. This is called separability: a k × k Gaussian costs about 2k operations per pixel instead of k². It is isotropic, meaning the blur is the same in every direction, so a slanted edge blurs like a vertical edge. In the frequency domain it has one smooth low-pass lobe and no ringing side lobes; see Chapter 2.7. A practical rule is that the mask width is about 6σ + 1, or radius about 3σ. For σ = 1 pixel, a 7 × 7 mask is a good fit; a 3 × 3 mask is a fast, rough approximation.

Normalisation, repeated smoothing and shrinking

Always divide by the sum of the mask weights. If the weights sum to S, compute weighted sum / S. A mask that sums to 0.8 darkens the image; a mask that sums to 1.25 brightens it. A 3 × 3 Gaussian with weights summing to 16 must be divided by 16, not by 9. The same rule applies at borders, where a full window may not fit: pad the image, or average only over the pixels that exist. Otherwise dark borders appear.

σ_total² = σ₁² + σ₂²

σ_total is the equivalent blur of two Gaussian passes in pixels; σ₁ and σ₂ are the standard deviations of the two passes. For n identical passes, σ_total = σ√n.

Two small Gaussian passes therefore approximate one larger Gaussian. This is useful in hardware: apply the separable 1-D mask twice instead of storing a large 2-D mask. Smoothing also comes before downsampling. If you shrink an image by 2 without blurring first, fine grain and thin lines fold into false patterns, called aliasing. A low-pass blur removes the frequencies that the smaller grid cannot represent. That step is developed in Chapter 2.8. Smoothing is the opposite of sharpening in Chapter 2.5.

Worked example

Question. A 3 × 3 window from a noisy night number-plate image has intensities 10, 10, 10 / 10, 80, 10 / 10, 10, 10, where 80 is a noise spike. (a) Apply a 3 × 3 box filter at the centre. (b) Apply the Gaussian mask 1 2 1 / 2 4 2 / 1 2 1 at the centre. Give each centre result.

  1. Write the window and note that there are eight values equal to 10 and one centre value equal to 80.
  2. Box filter: sum = 10 + 10 + 10 + 10 + 80 + 10 + 10 + 10 + 10 = 8 × 10 + 80 = 160.
  3. Box average = 160 / 9 = 17.777... intensity units, which is 17.8 to one decimal place, or 18 if rounded to an integer.
  4. Gaussian weighted sum, row by row: top row = 1 × 10 + 2 × 10 + 1 × 10 = 40; middle row = 2 × 10 + 4 × 80 + 2 × 10 = 20 + 320 + 20 = 360; bottom row = 1 × 10 + 2 × 10 + 1 × 10 = 40.
  5. Total weighted sum = 40 + 360 + 40 = 440. The mask weights sum to 1 + 2 + 1 + 2 + 4 + 2 + 1 + 2 + 1 = 16.
  6. Gaussian average = 440 / 16 = 27.5 intensity units.
  7. The box result is 17.8, rounded to 18; the Gaussian result is 27.5. The box pulls the spike lower, but the Gaussian gives the centre more weight, so a true edge is preserved slightly better.

Answer. The box filter gives 17.8 intensity units (18 rounded), and the Gaussian mask gives 27.5 intensity units.

Exam traps

  • Dividing by 9 when the mask weights sum to 16. Always divide by the sum of the weights; otherwise the output brightens.
  • Thinking a smoothing filter removes all noise without cost. It lowers noise and also blurs edges, thin lines and small text.
  • Using a large mask on a number plate because it gives a cleaner background. The digits merge, so choose the smallest mask that controls the noise.
  • Confusing box and Gaussian results. A box suppresses an isolated spike more, but it spreads the spike equally to all neighbours; the Gaussian keeps the centre stronger.
  • Forgetting border handling. At image edges a full window does not fit, so pad the image or use only valid pixels; otherwise values wrap or go dark.

2.5 Sharpening filters: derivatives, Laplacian and unsharp masking

An edge is where brightness changes quickly. A derivative measures change, so it is large at edges and near zero on flat areas. Adding a scaled derivative back to the original strengthens edges and leaves flat areas alone — sharpening. It is used in phone camera sharpen sliders, scanned documents, medical and satellite images, and the mask step in printing. This chapter builds sharpening from first and second differences, the Laplacian filter, unsharp masking and high-boost filtering.

You need chapter 2.3 for correlation and convolution, and chapter 2.4 for the blur that supplies f̄.

Derivatives respond to change

A derivative measures how fast intensity changes with position. On flat regions it is zero, so derivative sharpening does not disturb them. Where intensity rises or falls, it is non-zero.

f′(x) = f(x+1) − f(x)

f(x) is the intensity at position x, and f′(x) is the first difference, an estimate of the first derivative at x.

f″(x) = f(x+1) − 2f(x) + f(x−1)

f″(x) is the second difference, an estimate of the second derivative at x. It uses one neighbour on each side.

Ramps and steps show the difference clearly.

  • On a ramp, f′ is a block of equal non-zero values — a thick response spread over the whole ramp.
  • On the same ramp, f″ is non-zero only at the two ends: a positive spike where the slope starts and a negative spike where it ends.
  • On an ideal step, f′ gives one spike; f″ gives a positive spike just before the step and a negative one just after.

The second derivative locates detail finely, but it answers with two spikes, one on each side of the edge, while the first derivative gives a single, thicker edge. Sharpening usually wants the thin response, so the Laplacian, a second derivative, is the standard sharpening tool.

The Laplacian: second derivative in two dimensions

An image has two dimensions, so add the second differences along x and along y. That sum is the Laplacian.

∇²f(x,y) = f(x+1,y) + f(x−1,y) + f(x,y+1) + f(x,y−1) − 4f(x,y)

∇²f is the Laplacian response at pixel (x,y); the four terms are its up, down, left and right neighbours, and 4f(x,y) is four times the centre value.

As a 3×3 mask in the order top row, middle row, bottom row, this is 0 1 0 / 1 −4 1 / 0 1 0, applied by convolution as in chapter 2.3. Adding the diagonals gives 1 1 1 / 1 −8 1 / 1 1 1, which also responds to diagonal edges.

Both masks sum to zero. On a constant patch every neighbour equals the centre, so the response is zero. A mask whose coefficients sum to anything else adds constant brightness instead of sharpening.

g(x,y) = f(x,y) − ∇²f(x,y)

g is the sharpened image and f the original. A bright spot has a negative Laplacian, so subtracting it brightens the spot.

If your mask has +4 in the centre instead of −4, add instead: g = f + ∇²f. Folding the subtraction into the mask gives 0 −1 0 / −1 5 −1 / 0 −1 0, whose coefficients sum to 1.

Unsharp masking and high-boost filtering

Unsharp masking comes from the darkroom: blur a copy, subtract it to get the detail, and add that detail back to the original.

g(x,y) = f(x,y) + k·(f(x,y) − f̄(x,y))

f̄ is a blurred copy of f (Gaussian or box, from chapter 2.4), the bracket is the mask, and k ≥ 0 is a gain. k = 1 is the classical setting.

On flat regions the blur equals the original, so the mask is zero. Near an edge f − f̄ is large where a pixel differs from its neighbourhood, so adding it raises contrast there.

  1. Blur the original with a Gaussian to get f̄.
  2. Subtract: mask = f − f̄. Flat areas give zero.
  3. Multiply the mask by k and add it to f.
  4. Clip to the valid range, for example 0 to 255 for 8-bit images.

A large k gives crisp edges but also bright and dark halos around strong edges, and it amplifies noise. Small k is safer.

g = A·f − f̄ = (A−1)·f + (f − f̄), A ≥ 1

A is the boost factor. A = 1 gives ordinary unsharp masking with k = 1. A > 1 keeps more of the original: weight (A−1) on f, weight 1 on the mask.

The Sobel operator is the first-order cousin: it estimates a first derivative along one direction. Edge detection with such operators is covered in Unit 4, Detection of points, lines and edges.

Worked example

Question. An 8-bit grey patch is 10 10 10 / 10 20 10 / 10 10 10, a bright spot on a dark background. (a) Find the 4-neighbour Laplacian at the centre and g = f − ∇²f.   1. Centre f = 20; the four nearest neighbours are 10.

  3. 8-neighbour: ∇²f = 8×10 − 8×20 = −80; g = 20 − (−80) = 100.

  5. High-boost: g = 3×20 − 14 = 46.

Exam traps

  • Sign convention: the mask 0 1 0 / 1 −4 1 / 0 1 0 needs g = f − ∇²f. Using plus with that mask darkens edges — in the worked example the centre gives −20 instead of 60.
  • Calling any subtraction an unsharp mask. f̄ must be a genuinely blurred copy of the same image, not a shifted copy, not a smaller copy, and not a second photo of the same scene.
  • A residual Laplacian mask used inside g = f − ∇²f must sum to zero, or flat regions no longer cancel. The folded mask 0 −1 0 / −1 5 −1 / 0 −1 0 is the exception: it sums to 1 by design because it performs the subtraction itself, and it is applied directly, not added on top.
  • Forgetting to clip. Sharpened values often leave 0–255; wrapping modulo 256 turns a white edge into a black one.
  • Believing large k is free sharpening. It amplifies noise and makes halos, so the examiner's favourite question is why a sharpened noisy image looks worse.

2.6 Fourier transform and the discrete Fourier transform

A Fourier transform rewrites an image as a sum of sine waves of different frequencies, each with a strength and a shift. Slow, smooth shading is low frequency; edges, texture and noise are high frequency. Doing this with arithmetic instead of glass is what the discrete Fourier transform, or DFT, gives you. Once the image is in that form, convolution becomes a plain multiply, so filtering, denoising and compression all get cheaper. It is the tool behind fast convolution, JPEG's parent transforms and every spectrum you have seen drawn beside an image in a textbook.

You need: the image as a sampled discrete function f(x,y) from Unit 1 (sampling and quantisation), and convolution as weighted neighbour summing from 2.3.

From the continuous transform to samples

Any signal can be built by adding sine waves: pick a frequency, give it an amplitude and a shift, add it to the pile, repeat. The Fourier transform answers the reverse question. Given the finished signal f(x), how much of each frequency is inside it?

F(μ) = ∫ f(x)·e^(−j2πμx) dx

F(μ) is the complex spectrum at frequency μ, in cycles per unit length; x is distance; j = √−1; e^(−jθ) = cos θ − j sin θ, so the kernel is a wave of unit magnitude that completes one turn every 1/μ units of x.

The inverse puts the pieces back together.

f(x) = ∫ F(μ)·e^(j2πμx) dμ

only the sign of the exponent changes. |F(μ)| is the magnitude, how strong that frequency is; ∠F(μ) is the phase, where in x that wave is placed.

An image is such a signal over two axes. Smooth shading is mostly low frequency; edges, texture and noise are high frequency. That is why the transform earns a chapter: it splits the picture into bands that can be treated separately. Two photographs can look equally bright on average and differ completely in where their energy sits along the frequency axis.

A computer cannot integrate. The image is already sampled at x = 0, 1, …, N−1, and sampling in space makes the frequency axis discrete too. The integral collapses to a finite sum, and that sum is the DFT.

The 1-D DFT and its inverse

X(k) = Σ (n = 0 to N−1) x(n)·e^(−j2πkn/N),  k = 0, 1, …, N−1

X(k) is the complex coefficient of frequency bin k; n is the sample index; N is the number of samples; bin k sits at k/N cycles per sample. Each X(k) is the signal correlated with one wave.

x(n) = (1/N) Σ (k = 0 to N−1) X(k)·e^(j2πkn/N)

the 1/N restores the scale; without it the round trip returns N·x(n) instead of x(n).

Two facts drop straight out of the exponent. First, the spectrum repeats: X(k + N) = X(k), because e^(−j2πn) = 1 for every integer n. Second, if x(n) is real — every image is — then X(N − k) = X*(k), the complex conjugate. Half the spectrum is therefore redundant, and the negative frequencies are stored at the top of the array: k = N−1, N−2, and so on down.

Two dimensions, and the row–column trick

F(u,v) = Σ (m = 0 to M−1) Σ (n = 0 to N−1) f(m,n)·e^(−j2π(um/M + vn/N))

f is the M×N image, m is the row index and n the column index, u is the vertical frequency index (0…M−1), v the horizontal one (0…N−1), and F(u,v) is complex. The inverse carries 1/(MN) and a +j exponent.

Taken literally this is ruinous: MN outputs, each an MN-term sum, so (MN)² products. The exponent rescues it, because it splits:

e^(−j2π(um/M + vn/N)) = e^(−j2πum/M) · e^(−j2πvn/N)

the kernel is a product of one term in m alone and one in n alone. This is separability: the 2-D DFT is a 1-D DFT along every row, then a 1-D DFT along every column of that result. The two orders commute.

  1. Run a 1-D DFT of length N on each of the M rows.
  2. Run a 1-D DFT of length M on each of the N columns of the result.
  3. Store the complex output as F(u,v). Cost is MN(M+N) products, not (MN)².

Properties, phase, and the FFT

  • Linearity: a·f + b·g ↔ a·F + b·G.
  • Shift theorem: f(m − m₀, n − n₀) ↔ F(u,v)·e^(−j2π(um₀/M + vn₀/N)). The magnitude is untouched; only the phase changes, linearly in u and v.
  • Convolution theorem: f * h ↔ F·H. One multiply per pixel in frequency replaces a sliding-window sum in space (2.7).
  • DC term: F(0,0) = ΣΣ f(m,n) = MN × mean intensity. A 64×64 image of mean 100 has F(0,0) = 64×64×100 = 409600.
  • Periodicity: F(u + M, v) = F(u, v + N) = F(u, v).

Magnitude says how much of each frequency is present; phase says where it is. Put the phase of image B into the magnitude of image A and the result looks like B, because the position of every edge lives in the phase. The phase spectrum, usually printed as grey noise, is not junk.

The fast Fourier transform computes the same X(k). For N a power of 2 it splits the sum into even and odd samples and recurses, costing (N/2)·log₂N complex multiplications against N² for the direct sum. At N = 1024 that is 5,120 against 1,048,576, roughly 200 times fewer — the reason a real image transforms in milliseconds.

Worked example

Question. Find the 4-point DFT of x = [1, 1, 0, 0], state its magnitude spectrum, and compare the cost of the direct DFT and the FFT for N = 1024.

  2. k = 0: e^0 = 1, so X(0) = 1 + 1 = 2. Check: MN × mean = 4 × 0.5 = 2.
  3. k = 1: e^(−jπ/2) = −j, so X(1) = 1 − j; |X(1)| = √2 = 1.414, phase −45°.
  4. k = 2: e^(−jπ) = −1, so X(2) = 1 − 1 = 0.
  5. k = 3: e^(−j3π/2) = +j, so X(3) = 1 + j; magnitude 1.414, phase +45°, the conjugate of X(1) as symmetry demands.
  6. Cost at N = 1024: direct DFT needs N² = 1024² = 1,048,576 complex multiplications; FFT needs (N/2)·log₂N = 512 × 10 = 5,120.

Exam traps

  • The index runs 0 to N−1, so negative frequencies sit at the top of the array and the spectrum repeats. Move the DC term to the centre before display.
  • Dropping the 1/N in the 1-D inverse or the 1/(MN) in the 2-D inverse; the round trip then returns a scaled copy.
  • Reading bin k as a frequency in Hz. Bin k is k/N cycles per sample, or k/(N·Δx) cycles per unit length when samples are Δx apart.
  • Claiming the magnitude spectrum alone reconstructs the image. Phase is needed; magnitude and phase together are the image.
  • Using the DFT as if it gave linear convolution. It multiplies circularly, so pad with zeros before multiplying spectra.

2.7 Filtering in the frequency domain

Filtering in the frequency domain means changing an image by multiplying its DFT by a mask H(u,v). The mask keeps some frequencies and kills others. A low-pass mask keeps the centre, so noise and fine detail go and the picture blurs. A high-pass mask does the reverse, and edges survive. This is used for denoising, for removing periodic scan lines from a scanned page, and for flattening uneven lighting in a photograph. This chapter gives the pipeline, the three standard low-pass shapes and their high-pass partners.

You need: Chapter 2.6 — the DFT pair, separability and the convolution theorem.

The filter is one multiplication

In space, a filter is a convolution with a mask (see 2.3). In frequency, the same filter is a single multiplication, because convolution in space equals multiplication in frequency. That is the convolution theorem from Chapter 2.6.

g(x,y) = Re{ IDFT[ H(u,v) · F(u,v) ] }

f(x,y) is the input image; F(u,v) is its DFT; H(u,v) is the transfer function, a mask of the same size; the dot is a pixel-by-pixel multiply at every (u,v); IDFT is the inverse discrete Fourier transform; Re takes the real part; g(x,y) is the filtered image.

  1. Centre the spectrum: multiply f(x,y) by (−1)^(x+y) before the DFT, or shift the spectrum after it.
  2. Compute F(u,v) with the 2-D FFT.
  3. Build H(u,v) of the same size, usually from the distance D(u,v).
  4. Multiply: G(u,v) = H(u,v) · F(u,v) at every point.
  5. Inverse FFT to return to space.
  6. Take the real part and clip to 0–255.

The FFT is what makes this practical. For an N×N image the direct DFT costs about N⁴ operations and the 2-D FFT about N² log₂ N. At N = 1024 that is roughly 10⁵ times fewer operations, so a full-image frequency filter runs in a fraction of a second on a laptop. Once F is in memory, applying H is only N² complex multiplies — cheaper than one pass of a 3×3 spatial mask.

Distance D(u,v) and the ideal low-pass

The raw DFT puts zero frequency at pixel (0,0). A radial filter wants it in the middle, so the spectrum is centred first. Distance from the centre is D(u,v) = √(u² + v²), where u and v are counted from the centre pixel of the M×N spectrum. D is measured in spectrum pixels, not in hertz.

A filter written as H(D) depends only on distance, so it is circularly symmetric: it treats horizontal and vertical detail alike. The radius D₀ is the cutoff.

H_ideal(D) = 1 for D ≤ D₀, and 0 for D > D₀

D₀ is the cutoff radius in spectrum pixels; every frequency inside the circle of radius D₀ passes unchanged, everything outside is set to zero.

The ideal filter is the sharpest possible cut, and that is its problem. A step in H has a sinc-shaped inverse transform, so the output shows ripples around every edge. This is ringing, and it gets worse as D₀ shrinks. Sharpening the cutoff sharpens the ripples too.

Butterworth and Gaussian low-pass

The Butterworth filter softens the step.

H(D) = 1 / (1 + (D/D₀)^(2n))

n is the order, a positive number that sets how sharp the knee is; D₀ is the cutoff radius; D is the distance from the centre. At D = D₀ the ratio is 1, so H = 1/2 for every order — a fixed half-power point.

Small n gives a gentle roll-off and almost no ringing. As n grows, the curve approaches the ideal step and ringing comes back. Order 2 is a common compromise.

The Gaussian filter has no order at all.

H(D) = e^(−D² / (2D₀²))

D₀ sets the width of the passband (not a hard cutoff); D is the distance from the centre; e ≈ 2.718. At D = D₀, H = e^(−0.5) = 0.607, and at D = 2D₀, H = e^(−2) = 0.135.

The inverse transform of a Gaussian is another Gaussian, which has no side lobes. So the equivalent spatial mask is smooth, and a Gaussian low-pass never rings. That is why it is the default choice for smoothing in the frequency domain.

High-pass, notch and homomorphic filtering

Every low-pass has a high-pass partner: H_hp(u,v) = 1 − H_lp(u,v). Whatever the low-pass removed, the high-pass keeps. A Gaussian high-pass is 1 − e^(−D²/2D₀²): zero at the centre, tending to 1 far out. This is the frequency-domain form of the sharpening in 2.5 — edges and texture survive, flat regions go grey.

Selective filters kill narrow bands instead of whole regions. A band-reject mask sets H = 0 on a ring of radii; a notch sets H = 0 in small spots. The usual target is periodic noise — scan lines, a striped shirt, mains hum — which shows up as bright spikes away from the centre. Because the DFT of a real image is conjugate symmetric, F(u,v) = F*(M−u, N−v), a notch at (u₀,v₀) must be repeated at (M−u₀, N−v₀).

For uneven lighting, take logs first: log f = log i + log r, where i is the illumination (slowly varying, low frequency) and r is the reflectance (the object's detail, high frequency). Low-pass the log to estimate i, subtract it, then exponentiate. This is homomorphic filtering; it removes a shadow gradient without destroying contrast. Unit 3 takes periodic-noise removal further.

Worked example

Question. A 256×256 grayscale image is filtered in the frequency domain with a centred spectrum. The cutoff is D₀ = 50 spectrum pixels. Find the transfer function H at the two radii D = 50 and D = 100 for (a) an ideal low-pass filter, (b) a Butterworth low-pass of order n = 2, (c) a Gaussian low-pass with the same D₀. State which one rings.

  1. Ideal filter: H = 1 when D ≤ D₀ and 0 otherwise. At D = 50 the point lies exactly on the boundary, so take the inside value, H = 1. At D = 100 > 50, H = 0.
  2. Butterworth, exponent 2n = 4. At D = 50: (50/50)⁴ = 1, so H = 1/(1+1) = 0.5. This is the half-power point, true for any order.
  3. Butterworth at D = 100: (100/50)⁴ = 2⁴ = 16, so H = 1/(1+16) = 1/17 = 0.0588.
  4. Gaussian. Exponent is −D²/(2D₀²) = −2500/5000 = −0.5 at D = 50, so H = e^(−0.5) = 0.607.
  5. Gaussian at D = 100: −10000/5000 = −2, so H = e^(−2) = 0.135. The Gaussian roll-off is gentler than Butterworth order 2 at the same D₀.
  6. Ringing comes from a sharp step in H. Only the ideal filter has one, so only (a) rings; the Gaussian never does.

Answer. At D = 50 the three filters give H = 1, 0.5 and 0.607; at D = 100 they give H = 0, 0.0588 and 0.135, and only the ideal filter rings.

  2. At D = 100: (1)⁶ = 1, H = 1/(1+1) = 0.5.

Exam traps

  • Forgetting the real part after the inverse DFT. The spectrum of a real image is conjugate symmetric, so the result is real in theory, but floating point leaves a tiny imaginary residue; passing a complex array to an 8-bit display gives a wrong image.
  • Forgetting to centre the spectrum. With the origin at the corner, D = √(u²+v²) places the passband at a corner instead of the middle, so the wrong frequencies are kept.
  • Swapping D₀ and n. D₀ is a radius in spectrum pixels and controls the size of the passband; n is the Butterworth order and controls the sharpness of the knee.
  • Assuming the ideal filter is the best one. It is the sharpest cut and the worst ringer; the expected answer is usually that the Gaussian has no ringing because its inverse transform has no side lobes.
  • Placing a single notch. A notch at (u₀,v₀) must be duplicated at (M−u₀, N−v₀), otherwise the output is not real.

2.8 Image transforms: DCT, wavelets and image pyramids

An image transform is a change of coordinates: the same pixels, rewritten as weights on fixed patterns. The DCT writes an 8×8 block as weights on cosines, and a smooth block puts almost all its weight in one coefficient. Wavelets and pyramids write the image at several scales, so coarse layout and fine detail sit in separate bands. This is the machinery behind JPEG, photo blending and multi-scale matching. Nothing is lost — the information is repacked into a form easier to compress, filter or compare.

You need: Gaussian smoothing from Chapter 2.4 and keeping or killing bands from Chapter 2.7.

The DCT: a real transform on 8×8 blocks

The DFT of a real image is complex, and its second half is the mirror conjugate of the first — the same magnitudes with opposite signs of the imaginary part. The discrete cosine transform (DCT) keeps only the cosine part, so every coefficient is real and nothing repeats. On an N×N block:

F(u,v) = (2/N) · C(u) · C(v) · Σ<sub>x=0</sub><sup>N−1</sup> Σ<sub>y=0</sub><sup>N−1</sup> f(x,y) · cos((2x+1)uπ / 2N) · cos((2y+1)vπ / 2N)

f(x,y) is the pixel at row x, column y; F(u,v) is the coefficient for vertical frequency u and horizontal frequency v; N is the block side (8 in JPEG); C(0) = 1/√2 and C(k) = 1 for k ≥ 1.

The integers u and v count half-cycles of a cosine across the block. u = 3 means three half-cycles down the height. For N = 8, 2/N = 1/4 and C(0)C(0) = 1/2, so F(0,0) = (1/8) ΣΣ f(x,y) = 8 × (mean of the block). F(0,0) is the DC coefficient; the other 63 are AC coefficients.

Energy compaction is the payoff. In a smooth block neighbours are nearly equal, so every cosine with u > 0 or v > 0 sums to almost zero. A nearly flat patch of sky leaves a big F(0,0) and a scatter of near-zero AC values; quantising those to zero costs almost nothing in picture quality and saves many bits. A busy block spreads its energy over many coefficients, so JPEG spends more bits on it.

  1. Cut the image into 8×8 blocks.
  2. Subtract 128 from each pixel, so the block is centred on zero.
  3. Take the 2-D DCT of the block.
  4. Divide each coefficient by its step from a quantisation table; many become exactly zero.
  5. Read the coefficients in zigzag order, low frequency first, and entropy-code them.

The quantisation tables and the entropy coder belong to Unit 3, Image Restoration and Compression. The point here is that the DCT, not the DFT, is chosen: real, cheap, and it packs energy into few coefficients.

Gaussian and Laplacian pyramids

A Gaussian pyramid keeps the same picture at falling resolution. Start with G0, the image. Blur it with a Gaussian and keep every second row and column: G1 is half as wide and half as tall. Repeat to get G2, G3 and so on.

Gk+1 = (Gk ∗ g) ↓ 2

Gk is level k of the pyramid; g is the Gaussian kernel; ∗ is convolution; ↓2 means keep every second sample in each direction, so the result is half the width and half the height of Gk.

The blur is not optional. A 256-pixel-wide image can hold detail up to 128 cycles across. After subsampling to 128 pixels only 64 cycles fit, and anything finer folds back to a wrong, lower frequency — aliasing. The Gaussian blur removes the frequencies that cannot survive the subsampling.

The Laplacian pyramid stores what each level lost: Lk = Gk − expand(Gk+1), where expand upsamples by inserting zero rows and columns and then blurs. Each Lk is band-pass: mostly near zero, bright only where that scale has edges. Reconstruction is exact: Gk = Lk + expand(Gk+1), with the smallest level stored as it is.

Blending uses this directly. Take the Laplacian pyramids of two photos and a Gaussian pyramid of a mask; at each level copy pixels from photo A where the mask is bright and from photo B where it is dark; add the levels back. Seams vanish because each scale is blended on its own. Pyramid matching splits the picture into 2l × 2l cells at level l and compares histograms cell by cell. Weight level l by 1/2l to favour coarse layout, or by 1/2L−l (the usual spatial pyramid matching choice) to favour fine detail; the weights are a design choice and must be stated with the result. With 1/2l, coarse layout counts more than exact position.

The Haar wavelet: averages and details

The Haar wavelet replaces each pair of neighbouring samples by one average and one difference.

a = (x<sub>1</sub> + x<sub>2</sub>) / √2,    d = (x<sub>1</sub> − x<sub>2</sub>) / √2

x1, x2 are two adjacent samples; a is the approximation (their scaled average); d is the detail (their scaled difference); √2 ≈ 1.41421.

In two dimensions, transform every row, then every column. One level turns an N×N image into four (N/2)×(N/2) bands: LL, the approximation from two low-pass steps; LH, HL and HH, the details that catch horizontal, vertical and diagonal edges. Only LL is split again. A detail band is not a thumbnail of the picture — it holds differences and looks like noise.

The 1/√2 factor preserves energy: a² + d² = x1² + x2². The transform is a rotation of the data, not a loss, and the original can be recovered exactly. If the factor is dropped, that check fails by a factor of 2 at each level.

Only a few universities teach wavelets inside this unit; most stop at the DCT and pyramids, so treat this part as awareness. Wavelet subband coding replaces the 8×8 DCT in JPEG2000, and the whole-image transform is what removes the blockiness of DCT-coded pictures at high compression.

Worked example

Question. Apply two levels of the 1-D Haar transform, with the 1/√2 scaling, to the signal x = [4, 6, 10, 12]. Give every coefficient and check that the energy is unchanged.

  1. Pair the samples in order: (4, 6) and (10, 12).
  2. Level 1: a1 = 10/√2 = 7.0711, a2 = 22/√2 = 15.5563, d1 = −2/√2 = −1.4142, d2 = −1.4142.
  3. Level 2 works on (7.0711, 15.5563): A = 22.6274/√2 = 16.0, D = −8.4853/√2 = −6.0.
  4. Coefficients, level 2 first: 16.0, −6.0, −1.4142, −1.4142.
  5. Energy in: 16 + 36 + 100 + 144 = 296. Energy out: 256 + 36 + 2.0 + 2.0 = 296. Equal, so nothing was lost.
  6. Storing 16.0, −6.0 and two small values of size 1.41 costs few bits once the two small details are quantised to zero; only two numbers then survive. That is the compression argument, and quantisation is what makes it work.

Answer. The Haar coefficients are 16.0, −6.0, −1.4142 and −1.4142, and the energy stays 296 before and after the transform.

Exam traps

  • Subsampling before smoothing. Skipping the Gaussian makes high frequencies fold back as aliasing, so the blur comes first at every level.
  • Dropping the 1/√2 factor in the Haar transform. Averages come out √2 times too large and the energy check doubles at each level.
  • Expecting a detail band to look like a thumbnail. LH, HL and HH hold differences, so they look like noise or faint edges; only LL is a small image.
  • Confusing DCT with DFT. The DCT is real and has no repeated half; for an 8×8 block the DC coefficient is 8 × the block mean, not the mean.
  • Rebuilding a Laplacian level by plain upsampling. expand must upsample and then blur, else the pyramid no longer sums back to the original.

The mask position that is aligned with the current output pixel.

Adding values such as zeros or edge copies around an image before filtering.
Box filter
A smoothing filter whose mask has equal weights over a rectangle.
Butterworth filter
A frequency filter with a smooth transition between passed and removed bands.

For a histogram, the running total of pixel counts up to a gray level.

The discrete cosine transform, a real transform with strong energy compaction.

A filter that responds to change and is used to find edges.

An algorithm that computes the DFT much faster than direct summation.

A transform that rewrites a signal or image as a sum of sinusoids.

A representation of an image by the weights of its sinusoidal components.

A power-law mapping used to correct or change display brightness.

Sharpening that adds scaled high-pass detail to the original with gain A > 1.

A count of how many pixels have each gray level.

Another name for histogram specification, matching an image histogram to a target.

Processing that makes an image more useful for display or later analysis without adding new information.
