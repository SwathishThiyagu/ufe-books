6.1 C++ streams: formatted and unformatted I/O

A stream is a sequence of bytes flowing between a program and a device: the keyboard, the screen, a file or a string in memory. C++ hides every device behind the same few classes, so cin >> x reads the keyboard exactly the way a file stream reads a file. Unformatted I/O moves characters as they are (get, put, getline, read, write). Formatted I/O converts values to and from text under your control of width, precision, fill character and flags.

You need: Unit 1, Namespaces, preprocessor directives and stream manipulators (setw, setprecision, endl), and Unit 3, Virtual base classes and ambiguity resolution.

The stream classes

Output does not go to the screen one character at a time. Characters wait in a buffer (an object of class streambuf) and are sent in blocks. The buffer is flushed on endl or flush, when it is full, when the program ends, and before cin waits for input (because cin is tied to cout).

The classes form a hierarchy (Figure 6.1.1). ios_base stores the format state: flags, width and precision. ios adds the error-state flags and a pointer to the buffer. istream adds input: the extraction operator >>, get, getline, read. ostream adds output: the insertion operator <<, put, write. iostream inherits both. Because ios is a virtual base of istream and ostream, an iostream object has only one copy of the format and error state: the diamond problem of Unit 3, solved in the standard library itself.

Four objects are ready when main starts: cin (an istream, the keyboard), cout (an ostream, the screen, buffered), cerr (error messages, unbuffered so they appear at once) and clog (log messages, buffered).

Unformatted I/O

Unformatted functions do no conversion and do not skip spaces. They are members of istream and ostream:

  • cin.get(ch) reads one character into ch, including a space or a newline. cout.put(ch) writes one character.
  • cin.getline(buf, n) reads at most n − 1 characters or up to the newline, throws the newline away and ends buf with '\0'. For a std::string use the free function getline(cin, s).
  • cin.read(buf, n) and cout.write(buf, n) move exactly n bytes with no '\0' added. They are the workhorses of binary files (Chapter 6.3). cin.gcount() returns how many characters the last unformatted read took.
  • cin.ignore(n, '\n') skips up to n characters or past the next newline; cin.peek() looks at the next character without taking it.

Compare this with formatted input: cin >> s skips leading spaces and stops at the next space, so for the input Ravi Kumar it gives only Ravi. The C++ program below reads a line, echoes three characters, then counts characters up to a #.

#include <iostream>
using namespace std;
int main() {
    char name[20];  char ch;  int n = 0;
    cin.getline(name, 20);            // whole line, spaces included
    cout.write(name, 3);              // exactly 3 characters
    cout.put('\n');
    while (cin.get(ch) && ch != '#')  // get() keeps the space
        n++;
    cout << n << '\n';
}

With the input Anu Priya on the first line and ab c# on the second, it prints Anu and then 4: the characters a, b, space, c. With cin >> ch the count would be 3, because >> skips the space.

Exam traps

  • width() lasts for one item only; fill(), precision() and flags stay. cout.width(8); cout.fill('#'); cout << 42 << 7; prints ######427.
  • Without fixed, precision counts significant digits: 1675.25 with precision(2) prints 1.7e+03, not 1675.25.
  • Use the two-argument setf(ios::left, ios::adjustfield). After setf(ios::right), a plain setf(ios::left) leaves both bits on, and the output stays right-aligned.
  • cin >> age; followed by getline(cin, city); gives an empty city, because >> left the newline behind. Put cin.ignore(100, '\n'); between them.
  • cerr is unbuffered and clog is buffered; endl flushes but '\n' does not.

6.2 File stream classes, file modes and operations

A file stream is a stream whose device is a file on disk. The header <fstream> gives three classes: ifstream to read, ofstream to write and fstream to do both. They derive from istream, ostream and iostream, so every operator and function of Chapter 6.1 works on files unchanged. What is new is opening a file in the right mode, moving the read and write positions, and checking for errors.

You need: 6.1 C++ streams, and Unit 2, Destructors and object lifetime.

The classes and the five steps of any file program

  • ifstream (from istream): default mode ios::in.
  • ofstream (from ostream): default mode ios::out, which also truncates.
  • fstream (from iostream): default mode ios::in | ios::out.
  • Each holds a filebuf, the buffer that connects the stream to the operating system's file.
  1. Include <fstream>.
  2. Create a stream object and open the file, through the constructor ofstream out("bill.txt"); or later with out.open("bill.txt", ios::app);.
  3. Check that it opened: if (!out) or if (!out.is_open()).
  4. Read or write with >>, <<, get, put, getline, read, write.
  5. Close with out.close(), or let the destructor close the file when the object goes out of scope.

File modes

The mode is the second argument of the constructor or open(). Modes are bit flags, so you combine them with |: ios::in | ios::out | ios::binary.

File pointers: seekg, seekp, tellg, tellp

The get pointer is the byte position of the next read and the put pointer is the position of the next write. tellg() and tellp() return them; seekg() and seekp() move them.

  • seekg(n): go to byte n from the start.
  • seekg(off, dir): move off bytes from dir, which is ios::beg, ios::cur or ios::end. A negative offset moves back: seekg(-2, ios::end) on a 10-byte file goes to byte 8.
  • File size in bytes: seekg(0, ios::end); long n = tellg();

Textbooks draw the two pointers separately. In a file stream they are really one position kept by the filebuf, so after seekg(3) a put() also writes at byte 3. Seek explicitly before you switch between reading and writing.

Error handling with member functions

Every stream carries four state bits. Test them with member functions instead of guessing why a loop stopped.

if (!f) is the same as if (f.fail()), which is true when failbit or badbit is set. rdstate() returns all bits, and clear() resets them; a stream with failbit set ignores every later operation, including seekg, until you call clear(). If you prefer exceptions (Unit 5), call f.exceptions(ios::failbit | ios::badbit); and a failure throws ios_base::failure.

6.3 Sequential and binary file reading and writing

Sequential access reads or writes a file in order from the first byte to the last, the way a playlist plays from the top. Random access jumps straight to the record it needs, the way you tap one song. The second choice is how to store values: a text (ASCII) file stores numbers as characters you can open in Notepad, while a binary file stores the raw bytes a value occupies in memory.

You need: 6.2 File modes and seekg/seekp.

Text files and binary files

Take int n = 12345;. Written with out << n, the file gets five characters '1' '2' '3' '4' '5', which are bytes 31 32 33 34 35 in hexadecimal ASCII. Written with out.write(...) in binary mode, it gets the four bytes of the int as they sit in memory: 12345 = 0x3039, stored low byte first on an Intel or AMD machine (little-endian), so 39 30 00 00 (Figure 6.3.1).

Text is not always bigger. The 1,000 numbers 0 to 999, one per line, take 10 × 1 + 90 × 2 + 900 × 3 = 2,890 digit bytes plus 1,000 newlines = 3,890 bytes, against 1,000 × 4 = 4,000 bytes in binary. The numbers 100000 to 100999 take 7 bytes each as text = 7,000 bytes, still 4,000 in binary. Binary wins on fixed size and speed, not always on space. In text mode on Windows, '\n' is also written as the two bytes 0D 0A; ios::binary switches that translation off.

Sequential reading and writing of a text file

Write with << and a separator; read back in a loop whose condition is the read itself. This C++ fragment stores three students and prints their average.

ofstream out("marks.txt");
out << "101 Anu 78\n102 Bala 64\n103 Chitra 91\n";
out.close();
ifstream in("marks.txt");
int roll, m, total = 0, count = 0;  string name;
while (in >> roll >> name >> m) { total += m; count++; }
cout << count << " students, total " << total
     << ", average " << total / (double)count << '\n';

Output: 3 students, total 233, average 77.6667 (78 + 64 + 91 = 233; 233 ÷ 3 = 77.6667). The same pattern reads line by line with while (getline(in, line)) and character by character with while (in.get(ch)), which is how a file-copy program works.

Binary records and random access

  • Write one record: out.write(reinterpret_cast<const char*>(&s), sizeof(s));
  • Read one record: in.read(reinterpret_cast<char*>(&s), sizeof(s)); The cast is needed because both functions take a char pointer.
  • Record k (counting from 0) starts at byte k × sizeof(record); number of records = file size ÷ sizeof(record).
  • Only plain structs of numbers and char arrays may be written this way. A std::string member holds a pointer to heap memory, so the file would store an address, not the name; a class with virtual functions would store its hidden vtable pointer.
  • sizeof includes padding: struct {char g; int r;} is 8 bytes on GCC for x86-64, not 5.

Question. Store three student records (name, roll, CGPA) in a binary file. Find the number of records from the file size, read the second record directly, change its CGPA to 7.75 after revaluation, and list the file. Give the output. (10 marks)

    char  name[12];
    int   roll;
    float cgpa;
};
int main() {

Exam traps

  • Forgetting ios::binary on Windows: every byte 0A inside a number gets a 0D added, and later records shift.
  • Writing a class with a std::string, a pointer or a virtual function in binary saves addresses, which mean nothing in the next run.
  • Record size is sizeof, padding included, not the sum you expect.

6.4 Multithreading: creating threads and thread priorities

A thread is one independent path of execution inside a program. One process can run several threads at once; they share the same objects and static fields, but each has its own stack and its own place in the code. Multithreading keeps a program responsive (a UPI app checks the server while its screen still answers taps) and uses every core of the CPU.

You need: Unit 3, Interfaces: defining and implementing them, and Unit 5, Exception handling: try, catch and throw.

Processes, threads and the scheduler

Process-based multitasking runs separate programs together, such as a browser and a music player, each with its own memory. Thread-based multitasking runs several tasks inside one program, such as a word processor that checks spelling while you type. Threads share memory, so they are cheaper to create and switch than processes; that sharing is also their danger.

The operating system's scheduler decides which thread runs. On one core it gives each thread a short time slice in turn, so they only appear to run together; on four cores four threads truly run at the same moment. You cannot predict the order, so a correct program must not depend on it.

Creating threads in Java

  1. Extend Thread and override public void run(); then create the object and call start().
  2. Implement Runnable (one method, run()), pass the object to new Thread(r), and call start(). Since Runnable is a functional interface, a lambda also works: new Thread(() -> download()).start();

Prefer Runnable: Java allows only one superclass, so a class that implements Runnable can still extend another class, and the task (what to do) stays separate from the worker (the thread). start() asks the JVM for a new thread, which then calls run(). Calling run() yourself just runs it on the current thread, with no concurrency. Calling start() twice on one object throws IllegalThreadStateException.

Other methods you will use: Thread.sleep(ms) pauses the current thread and may throw the checked InterruptedException; t.join() makes the caller wait until t finishes; isAlive(), getName(), setName(), Thread.currentThread() and interrupt().

Thread priorities

  • A priority is an int from 1 to 10: Thread.MIN_PRIORITY = 1, Thread.NORM_PRIORITY = 5, Thread.MAX_PRIORITY = 10.
  • t.setPriority(p) sets it and t.getPriority() reads it. A value outside 1 to 10 throws IllegalArgumentException.
  • A new thread starts with the priority of the thread that created it; main runs at 5.
  • Priority is only a hint. When several threads are Ready, the scheduler may prefer the higher one, but the operating system decides, and many systems ignore Java priorities. A very low thread may wait a long time (starvation). Never use priority to make a program correct; use synchronization.
  • Java 21's virtual threads always report priority 5, and setPriority has no effect on them.

Synchronization and thread communication

count++ looks like one step but is three: read count, add 1, write it back. When two threads interleave those steps, one update is lost: a race condition. Every Java object has a monitor (lock). A synchronized method, or a block synchronized (obj) { … }, lets only one thread at a time hold that lock, so the three steps run as one.

For inter-thread communication, wait(), notify() and notifyAll() (methods of Object) let one thread sleep until another signals it. They must be called inside synchronized code, or Java throws IllegalMonitorStateException. The classic producer-consumer slot:

class Slot {                                  // holds one item at a time
    private int item;  private boolean full = false;
    synchronized void put(int x) throws InterruptedException {
        while (full) wait();                  // releases the lock and waits
        item = x;  full = true;
        notifyAll();                          // wake the consumer
    }
    synchronized int take() throws InterruptedException {
        while (!full) wait();
        full = false;  notifyAll();
        return item;
    }
}

If one thread holds lock A and waits for lock B while another holds B and waits for A, both wait forever: a deadlock. Take locks in the same order everywhere. In C++11, std::thread t(work, 1); t.join(); creates and joins a thread, and std::mutex plays the role of the monitor; standard C++ has no thread priorities. In the standard CPython build only one thread runs Python code at a time (the global interpreter lock), so threads help I/O-bound work, not number crunching.

6.5 Event handling in GUI programs

A GUI program does not run from top to bottom and stop. It builds a window and then waits. Every click, key press or mouse movement becomes an event, and the program reacts by running a small method called an event handler. This style is event-driven programming. Java's version is the delegation event model: a component that produces events delegates the work of handling them to listener objects that have registered with it.

You need: Unit 3, Interfaces: defining and implementing them, and 6.4 Multithreading.

Source, event object and listener

  • Event source: the component where something happened, such as a JButton, a text field or a window.
  • Event object: carries the details. An ActionEvent knows its source and its action command (the button text); a MouseEvent knows the x and y position and the click count; a KeyEvent knows the key.
  • Listener: an object of a class that implements a listener interface. It registers with source.addXxxListener(listener) and can leave with removeXxxListener. A source may have many listeners; each gets every event.

How one click travels

  1. At start-up the program registers a listener with the source: plus.addActionListener(this).
  2. The user clicks; the operating system tells the Java runtime.
  3. The source creates an ActionEvent describing the click.
  4. The event is posted on the event queue, behind any earlier events.
  5. The event dispatch thread (EDT) takes the next event from the queue.
  6. It calls actionPerformed(e) on every listener registered with that source.
  7. The handler updates components, for example label.setText(...); the EDT repaints and goes back to the queue.

Four ways to write a handler, and adapter classes

  1. The window class itself implements the listener and registers this; one method serves several buttons by testing e.getSource() (used in the worked example).
  2. A separate or inner class implements the listener.
  3. An anonymous inner class: b.addActionListener(new ActionListener() { public void actionPerformed(ActionEvent e) { … } });
  4. A lambda (Java 8 onwards), only for interfaces with one method: b.addActionListener(e -> label.setText("Paid"));

MouseListener has five methods and WindowListener seven, and a class that implements an interface must define them all. Adapter classes (MouseAdapter, KeyAdapter, WindowAdapter) implement every method with an empty body, so you extend the adapter and override only the one you need.

Two rules follow from Figure 6.5.1. Keep handlers short: a handler that waits 10 seconds for a server freezes every button for 10 seconds, so long work goes to a background thread (Chapter 6.4, or SwingWorker). And change components only on the EDT: from another thread, use SwingUtilities.invokeLater(...) (JavaFX: Platform.runLater(...)). In JavaFX the handler is an EventHandler<ActionEvent> set with button.setOnAction(e -> …); an event first travels down the scene graph (event filters run) and then bubbles back up (handlers run).

6.6 GUI programming with JavaFX controls

JavaFX is Java's current toolkit for desktop GUIs, the successor to Swing. A JavaFX program builds a tree of objects, the scene graph, inside a window, and the controls in that tree (buttons, text fields, check boxes) raise the events you learned to handle in Chapter 6.5. Since JDK 11, JavaFX is not bundled with the JDK; it is a separate open-source download called OpenJFX.

Stage, scene and scene graph

  • Every JavaFX program extends javafx.application.Application and overrides start(Stage). main only calls launch(args).

  1. Create the controls.
  2. Put them in a layout pane, which becomes the root.
  3. Attach handlers with setOnAction and similar methods.
  4. Make the scene: stage.setScene(new Scene(root, w, h));

6.7 Object-oriented design patterns

A design pattern is a named, proven solution to a design problem that keeps coming back, described so that you reuse the idea rather than the code. The 1994 book Design Patterns: Elements of Reusable Object-Oriented Software by Gamma, Helm, Johnson and Vlissides, the "Gang of Four" (GoF), catalogued 23 of them. Patterns give a team shared words: "make the logger a Singleton" says in five words what would otherwise take a paragraph.

You need: Unit 3, Aggregation and composition and Interfaces; Unit 4, Virtual functions and late binding; Unit 1, Modeling classes with UML diagrams.

What a pattern contains, and the three families

Every GoF pattern is described by four essential elements: its name, the problem (when to use it), the solution (the classes, their roles and how they collaborate) and the consequences (the trade-offs).

FamilyDeals withGoF patterns
Creational (5)how objects are createdSingleton, Factory Method, Abstract Factory, Builder, Prototype

Behavioural (11)how objects share work and communicateChain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor

Two principles run through the book: program to an interface, not an implementation, and favour object composition over class inheritance. Both rely on run-time polymorphism: the caller holds an interface reference, and the object behind it can be swapped.

Six patterns examiners ask about

Singleton (creational): a class with exactly one object and a global way to reach it, used for a configuration, a logger or a connection pool. Make the constructor private, keep the object in a static field, and hand it out from a static method.

class Config {
    private static Config instance;               // the one object
    private Config() { System.out.println("Config created"); }
    static synchronized Config getInstance() {    // safe with threads (6.4)
        if (instance == null) instance = new Config();
        return instance;
    }
}
// in main:
Config x = Config.getInstance();
Config y = Config.getInstance();
System.out.println(x == y);

Output: Config created once, then true: both references point to the same object.

Factory Method (creational): a method decides which subclass to create, so callers write Shape s = ShapeFactory.create("circle"); and never name the concrete class. Adapter (structural): converts the interface of an existing class into the one a client expects, like a travel plug adapter; a PrinterAdapter can implement your Printer interface by calling an old LegacyPrinter.printText(). Decorator (structural): wraps an object to add behaviour while keeping its interface. Java I/O is built this way: new BufferedReader(new FileReader("marks.txt")) adds buffering and readLine() to any Reader (Chapter 6.3). Python's @decorator syntax wraps functions in the same spirit, but it is a language feature, not the GoF pattern. Strategy (behavioural): a family of interchangeable algorithms behind one interface; the Comparator you pass to Collections.sort is a strategy. Observer (behavioural) is next.

And since functions are objects, a Strategy is often just a function passed as an argument.

Observer in detail

Problem: when one object changes, several others must react, and the changing object should not know their classes. Solution: the subject keeps a list of objects that implement an observer interface; attach and detach manage the list, and every change calls update on each one. You have already used it: in Chapter 6.5 the JButton is the subject, ActionListener is the observer interface, addActionListener is attach and actionPerformed is update.

Exam traps

  • A Singleton needs a private constructor; without synchronized (or eager creation), two threads can each see null and create two objects.
  • Adapter, Decorator and Proxy all wrap an object. Adapter changes the interface; Decorator keeps it and adds behaviour; Proxy keeps it and controls access.
  • Strategy and State look alike. In Strategy the client picks the algorithm; in State the object switches its own behaviour when its state changes.
  • Know the counts: 23 = 5 creational + 7 structural + 11 behavioural, and the family of each pattern you name.
  • An observer that is never detached stays reachable from the subject's list and is never garbage-collected (the "lapsed listener" leak).

Analyze When is a Singleton a poor choice? 4 marks

It is global state: any class can change it, hidden dependencies make code hard to follow, and tests cannot replace it with a fake easily. If two configurations are ever needed (say, two bank branches), the design must be undone. Passing the object in (dependency injection) is often better.

Glossary

Adapter class
A class that implements a listener interface with empty methods, so a subclass overrides only the ones it needs.
Binary file
A file that stores the raw memory bytes of values; compact for fixed-size records, not human-readable.
Buffer
Memory where stream data waits before being sent to or after being read from a device.
Deadlock
Two or more threads each waiting for a lock the other holds, so none can continue.
Decorator
A structural pattern that wraps an object to add behaviour while keeping its interface.
Delegation event model
Java's event model: a source passes each event to the listeners registered with it.
Design pattern
A named, reusable solution to a recurring design problem.
Event
An object describing something that happened, such as a click or a key press.
Event dispatch thread
The single thread that takes events from the queue and runs their handlers in a Swing program.
Event source
The component that generates an event, such as a button.
File mode
A flag such as ios::in or ios::app that says how a file is opened.
Formatted I/O
Input or output that converts values to and from text under width, precision, fill and flag settings.
Get pointer
The byte position of the next read in a stream; moved with seekg.
Listener
An object implementing a listener interface whose methods run when an event occurs.
Monitor
The lock every Java object carries; synchronized code holds it.
Observer
A behavioural pattern in which a subject notifies all attached observers when it changes.
Put pointer
The byte position of the next write in a stream; moved with seekp.
Race condition
A bug where the result depends on how threads' steps happen to interleave.
Random access
Reading or writing at any position directly, without reading what comes before.
Runnable
Java's one-method interface (run()) for a task that a thread can execute.
Scene graph
The tree of nodes that makes up a JavaFX window's content.
Sequential access
Reading or writing a file in order from the start.
Singleton
A creational pattern that allows exactly one object of a class.
Stage
A JavaFX window.
Stream
A sequence of bytes flowing between a program and a device.
Stream state
The goodbit, eofbit, failbit and badbit that record what went wrong in a stream.
Text file
A file that stores values as readable characters, usually in lines.
Thread
An independent path of execution inside a process, sharing its memory.
Thread priority
An int from 1 to 10 the scheduler may use as a hint when choosing the next thread.
Unformatted I/O
Input or output of characters or bytes with no conversion, such as get, put, read, write.
