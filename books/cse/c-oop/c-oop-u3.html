3.1 Inheritance basics: base and derived classes

Inheritance lets you write a new class by starting from an existing one. The existing class is the base class; the new one is the derived class. The derived class gets the data members and member functions of the base, adds its own, and may change some of what it got. It exists so that common code is written once: a bank writes Account once and derives Savings, Current and FixedDeposit from it. Every large library uses it, from Java's exception classes to the widget classes of a GUI toolkit.

You need: classes, objects and access specifiers from Unit 2 (Classes and objects: member data and member functions; Access specifiers: public, private and protected).

The words and the is-a test

Three pairs of words mean the same thing, and examiners use all of them: base class = parent class = superclass; derived class = child class = subclass.

Use inheritance only when the sentence "every derived object is a base object" is true. A savings account is an account, so Savings may derive from Account. A car is not an engine; a car has an engine, so Car should contain an Engine object instead (Chapter 3.9). Apply this is-a test first in any design question.

Writing a derived class in C++, Java and Python

Each language names the base class in the header of the derived class:

// C++
class Savings : public Account { /* new members */ };

// Java
class Savings extends Account { /* new members */ }

# Python
class Savings(Account):
    pass

In C++ the word public before Account is the inheritance mode; Chapter 3.3 explains it and the other two modes. Java and Python have only one mode, and it behaves like C++ public inheritance.

What the derived class gets, and what it does not

  1. Every data member. A derived object holds a complete copy of the base's members, called the base subobject, followed by its own members. Even the private members of the base are stored in it.
  2. Access only to public and protected members. Private base members are present, but the derived class's code cannot name them; it must go through public or protected functions of the base. This is why base classes often mark their data protected.
  3. Every ordinary member function. You call it on the derived object as if it were written in the derived class.
  4. Not inherited: constructors, the destructor, the copy assignment operator and friend functions. The derived class has its own, and they call the base versions (Chapter 3.4).

A derived class can do three things with what it gets: use it unchanged, add new members beside it, or redefine a function with a new body (overriding, Chapter 3.5).

Exam traps

  • "Private members are not inherited" is wrong. They are inherited (they take memory, as sizeof shows) but they are not accessible in the derived class. Write "inherited but not accessible".
  • Constructors and destructors are not inherited. Each class has its own, and the derived one calls the base one.
  • In a UML class diagram the hollow-triangle arrow points from the derived class to the base class. Drawing it the other way loses marks.
  • Inheritance is for is-a only. class Car : public Engine is a design error; a car has an engine.
  • Favourite question: "What is inheritance? Explain with an example and list its advantages." List code reuse, less duplication, one place to fix a bug, easy extension, and support for run-time polymorphism (Unit 4).

3.2 Types of inheritance: single, multiple, multilevel, hierarchical, hybrid

A class hierarchy can take five shapes. They are named by two counts: how many direct base classes a derived class has, and how many levels the chain has. Naming the shape is a standard short question, drawing all five is a standard long one, and the shape tells you in advance which problems can appear: name clashes and duplicate grandparents happen only in multiple and hybrid inheritance.

You need: 3.1 Inheritance basics.

The five shapes

  1. Single: one derived class with exactly one base. class Savings : public Account {};
  2. Multiple: one derived class with two or more direct bases at the same time. class TA : public Student, public Employee {}; A teaching assistant is both a student and an employee.
  3. Multilevel: a chain, where a derived class becomes the base of another. class Student : public Person {}; then class Exam : public Student {};
  4. Hierarchical: one base with two or more derived classes. Car, Bus and Auto all derive from Vehicle.
  5. Hybrid: any mix of two or more of the above in one design. The common one is the diamond: Student and Employee derive from Person (hierarchical), and TA derives from both (multiple).

Direct and indirect bases

In the multilevel chain Person → Student → Exam, Student is the direct base of Exam, and Person is an indirect base. Members flow down the whole chain, so an Exam object holds a Person part, then a Student part, then its own members, and an Exam member function may use the protected members of both ancestors. A chain can be as long as you like, but beyond three or four levels a reader has to open many files to learn what one class does.

Exam traps

  • Multiple versus multilevel: multiple means one class with several parents at once; multilevel means a grandparent chain. Draw the arrows before you name the type.

  • "Java does not support multiple inheritance" is true only for classes. A class can implement any number of interfaces.
  • Hybrid is not a keyword or a special syntax; it is the name for a mixture, and not every hybrid is a diamond.

3.3 Public, private and protected inheritance

In C++ the word written before the base class name, public, protected or private, is the inheritance mode (also called the visibility mode or derivation mode). It does not change what the derived class itself can reach. It changes how the inherited public and protected members look to everyone else: code in main() and classes derived further down. Public inheritance keeps the is-a relationship; private inheritance uses the base only as a hidden part of the implementation. Java and Python have no inheritance modes, and the end of this chapter shows what they use instead.

You need: Unit 2, Access specifiers: public, private and protected; 3.1 Inheritance basics.

The rule in one line

Order the three words from open to closed: public, then protected, then private. An inherited member's access in the derived class is the more closed of two things: its access in the base, and the inheritance mode. The one exception: a member that is private in the base is not accessible in the derived class under any mode. It is still stored in every derived object, but no derived-class code can name it.

What each mode is for

  • Public inheritance keeps the base's public interface public. A Savings object can be used wherever an Account is expected. This is is-a, and it is the mode you will use almost always.
  • Protected inheritance turns the base's public members into protected ones. Code in main() can no longer call them on the derived object, but classes derived further down still can. It is rare.
  • Private inheritance turns every inherited member private. Neither outside code nor grandchildren can use them. The derived class uses the base as a hidden tool, which is called "implemented in terms of": a Stack built by privately inheriting vector<int> can offer only push and pop, so users cannot insert into the middle.

The default mode is private for a class and public for a struct. Because only public inheritance is is-a, the compiler refuses to convert a privately derived object to its base outside the class: Base* p = &z; gives "'Base' is an inaccessible base of 'PriD'".

Opening one member again, and the Java and Python view

A derived class can make one inherited member public again with a using-declaration in its public section: using Base::a;. It can only restore what the base itself made public or protected. Older books write Base::a; without using (an "access declaration"); compilers now warn that this form is deprecated.

Java has only one kind of inheritance, extends, which behaves like public inheritance, and an overriding method may not reduce access (Chapter 3.5). Python has no modes and no enforced access at all: a name starting with one underscore, _rate, is "internal" by convention, and a name starting with two, __rate, is renamed by Python to _Account__rate so that a subclass does not clash with it by accident.

3.4 Constructors and destructors in derived classes

A derived object contains a base part, so building it means building the base part first. The base class's constructor runs before the body of the derived constructor, and the destructors run in exactly the reverse order. When the base constructor needs arguments, the derived class must pass them on: through the member initializer list in C++, with super(...) in Java, and with super().__init__(...) in Python.

You need: Unit 2, Constructors: default, parameterized and copy; Unit 2, Destructors and object lifetime; 3.2 Types of inheritance.

The order of calls

For C obj;, where C has bases and member objects, C++ runs these steps:

  1. Constructors of virtual base classes, if there are any (Chapter 3.6).
  2. Constructors of the direct base classes, in the order they are listed in the class header, left to right.
  3. Constructors of the member objects, in the order they are declared in the class.
  4. The body of C's own constructor.

Destruction is the exact mirror: the body of ~C(), then the members in reverse declaration order, then the bases from right to left. The reason is safety. The body of C() may use its bases and members, so they must already exist; the body of ~C() may still use them, so they must not be gone yet. In a multilevel chain Person → Student → Exam the same rule gives Person, Student, Exam for construction and Exam, Student, Person for destruction.

Passing arguments to the base constructor

In C++ the derived constructor names the base constructor in its member initializer list, after the colon:

Box(int x, int y, int z) : Rectangle(x, y), h(z) { }

If the base has only a parameterized constructor and the derived constructor does not call it, the compiler tries the base's default constructor, finds none, and stops with "no matching function for call to 'Rectangle::Rectangle()'". Java uses super(x, y);, which must be the first statement of the subclass constructor; if you leave it out, Java inserts super() and reports "constructor Account in class Account cannot be applied to given types" when no such constructor exists. Python does not call the parent's __init__ for you at all:

class Account:
    def __init__(self, bal):
        self.bal = bal

class Savings(Account):
    def __init__(self, bal, rate):
        super().__init__(bal)     # build the Account part
        self.rate = rate

s = Savings(5000, 0.04)
print(s.bal * s.rate)             # 200.0

Remove the super().__init__(bal) line and s.bal fails with "AttributeError: 'Savings' object has no attribute 'bal'", because the Account part was never set up.

Destructors when classes use new and delete

Each class frees only what it allocated. The derived destructor deletes its own memory; the base destructor then runs automatically and deletes the base's memory. Never call the base destructor yourself, or the memory is freed twice.

class Buffer {
protected:
    int* data;
public:
    Buffer(int n) { data = new int[n]; cout << "Buffer " << n << "\n"; }
    ~Buffer()     { delete[] data;     cout << "~Buffer\n"; }
};
class Log : public Buffer {
    char* name;
public:
    Log(int n) : Buffer(n) { name = new char[16]; cout << "Log\n"; }
    ~Log()                 { delete[] name;        cout << "~Log\n"; }
};

A block { Log g(100); } prints Buffer 100, Log, ~Log, ~Buffer. If a Log created with new is deleted through a Buffer*, the base destructor must be declared virtual; that is Unit 4, Virtual destructors.

3.5 Method overriding and the super keyword

Overriding means a subclass gives its own body to a method it inherited, keeping the same name and the same parameter list. When the method is called on a subclass object, the subclass's version runs. The keyword super lets the new version call the old one, so a subclass can extend what the parent does instead of rewriting it. Every framework relies on this: you override toString() in Java or __str__ in Python to control how your object prints.

You need: 3.1 Inheritance basics. Overloading is taught in Unit 4 (Function and method overloading); only the difference is needed here.

Overriding is not overloading

Overloading is two methods with the same name but different parameter lists, usually in the same class; the compiler picks one from the arguments (Unit 4). Overriding is a method in a subclass with the same name and the same parameter list as one in its superclass; the version that runs depends on the class of the object. Change one parameter type in the subclass and you have written an overload, not an override, and the parent's version still runs.

The rules for a valid override in Java

  1. Same name, and the same number, types and order of parameters.
  2. The same return type, or a subclass of it (a covariant return type).
  3. Access the same or more open, never more closed. Overriding a public method without public fails with "attempting to assign weaker access privileges; was public".
  4. final methods cannot be overridden. A static method with the same signature hides the parent's; it does not override it. private methods are not inherited, so they cannot be overridden.
  5. The override may not throw new or broader checked exceptions (Unit 5).

Write @Override above every override. It asks the compiler to check the rules, so a typo such as intrest(double) becomes a compile error instead of a silent new method.

super in Java and Python, and the C++ way

Java's super has three uses: super.method(args) calls the parent's version of a method, super.field reads a parent field hidden by a same-named field, and super(args) calls the parent constructor (Chapter 3.4). Python writes super().method(args); in a multiple-inheritance class it follows the method resolution order, which Chapter 3.6 explains. C++ has no super keyword: you name the base class with the scope operator, Account::interest(bal).

One difference between the languages matters a lot. In Java and Python every overridable method is chosen by the object's real class at run time. In C++ that happens only if the base declares the function virtual; without it, a call through a base-class pointer runs the base version. That mechanism is Unit 4 (Virtual functions and late binding). Here, all calls are made on the object itself, where every language behaves the same.

3.6 Virtual base classes and ambiguity resolution

Multiple inheritance brings two kinds of ambiguity. Two bases may have members with the same name, and the compiler cannot choose between them. And in a diamond, the grandparent reaches the bottom class by two paths, so each object holds two copies of it. C++ fixes the first with the scope resolution operator and the second with virtual base classes, which keep one shared copy. Python avoids duplicate copies by design and decides which method runs with its method resolution order (MRO).

You need: 3.2 Types of inheritance and 3.4 Constructors in derived classes.

Same name in two bases: the scope resolution operator

class Printer { public: void show() { cout << "Printer\n"; } };
class Scanner { public: void show() { cout << "Scanner\n"; } };
class AllInOne : public Printer, public Scanner { };

AllInOne d;
d.show();            // error: request for member 'show' is ambiguous
d.Printer::show();   // prints Printer

The error appears only when the ambiguous name is used, not when the class is declared. Two fixes: name the base with :: at the call, as above, or give AllInOne its own show() that decides, for example by calling Printer::show(); and then Scanner::show();. The second fix is better design, because users of the class no longer need to know its bases.

The diamond and virtual base classes

Take Student with a roll number, two classes Test and Sports derived from it, and Result derived from both. Without anything special, a Result object contains a Test part and a Sports part, and each contains its own Student part. There are now two roll numbers. r.roll is ambiguous, and r.Test::roll and r.Sports::roll can hold different values, which is wrong data, not just a compile error.

Declaring the shared base virtual in both middle classes tells the compiler to keep one Student part for the whole object:

class Test   : virtual public Student { ... };
class Sports : virtual public Student { ... };   // public virtual also works
class Result : public Test, public Sports { ... };

Two rules follow. First, the most derived class constructs the virtual base. When a Result is built, any Student(r) calls written in Test's and Sports' initializer lists are skipped; Result must call Student(r) itself, or Student's default constructor runs. Second, virtual bases are built before all other bases (step 1 in Chapter 3.4). The compiler finds the shared part through hidden bookkeeping, so object sizes grow and depend on the compiler: with one int in each of the four classes, g++ on 64-bit Linux gives 20 bytes for the plain diamond and 40 bytes for the virtual one. Do not try to predict such sizes in an exam.

Python's answer: the MRO and C3 linearization

A Python object keeps all its attributes in one place, so a diamond never holds two copies of the data. The open question is which method runs, and Python answers it with the MRO: one list of classes, in search order, stored as ClassName.__mro__. It is computed by C3 linearization:

L[C] = C + merge(L[B1], L[B2], ..., L[Bn], [B1, B2, ..., Bn])

Here B1 to Bn are the direct bases of C in the order written. merge repeatedly looks at the first element (the head) of each list in turn, and takes the first head that does not appear anywhere except first in any other list; it appends that class to the result and deletes it from every list. If no head qualifies, Python refuses to create the class with a TypeError. In plain words: a child always comes before its parents, and parents keep the order you wrote them in. super() follows this list, so it means "the next class in the MRO", which is not always the parent.

3.7 Interfaces: defining and implementing them

An interface is a named list of method signatures with no object state: a contract. A class that implements it promises to supply a body for every method in the list. Code written against the interface, such as a checkout that accepts any Payment, then works with every class that implements it: UPI, card, net banking, and payment types added next year. Java has an interface keyword; C++ builds an interface from a class whose functions are all pure virtual; Python uses an abstract base class. Abstract classes and pure virtual functions in full are Unit 4.

You need: 3.5 Method overriding and 3.2 Types of inheritance.

Defining an interface in Java

interface Payment {
    double pay(double amount);   // no body
}

Java fills in several words for you, and examiners ask for them:

  • A method without a body is public abstract.
  • A field is public static final: a constant shared by everyone.
  • There are no constructors, so new Payment() is an error. A reference of interface type is fine: Payment p = new Upi();
  • Since Java 8 an interface may also hold default methods, which have a body and are inherited by implementing classes, and static methods. Since Java 9 it may hold private helper methods for its default methods.

Implementing one or many

  1. Write implements after the class name: class Upi implements Payment.
  2. Give every abstract method a body, marked public; otherwise declare the class abstract.
  3. A class may extend one class and implement any number of interfaces, in that order: class Card extends Instrument implements Payment, Refundable. This is how Java gets multiple inheritance of type without the diamond's duplicate state.
  4. An interface may extend one or more interfaces: interface Wallet extends Payment, Refundable { }.

3.8 Packages, modules and member access

A package groups related classes under one name, the way a folder groups files. It does two jobs. It gives names their own space, so the booking team and the catering team can each have a class called Ticket. And it draws an access boundary: in Java, a member with no access word is visible inside its own package only. Java has packages; Python has modules (one .py file each) and packages (folders of modules); C++ has namespaces (Unit 1) and, since C++20, modules.

You need: Unit 2, Access specifiers; Unit 1, Namespaces, preprocessor directives and stream manipulators; 3.3 Public, private and protected inheritance.

Creating and using a Java package

  1. Make package in.rail.booking; the first statement of the file (only comments may come before it). Package names are lowercase and usually start with the organisation's web domain reversed.
  2. Store the file in matching folders: in/rail/booking/Ticket.java.
  3. Compile with an output folder: javac -d out in/rail/booking/Ticket.java in/rail/app/*.java. javac creates out/in/rail/booking/Ticket.class and the matching folders for the others.
  4. Use the class from another package with import in.rail.booking.Ticket; (one class), import in.rail.booking.*; (all its public classes, but not its subpackages), or the fully qualified name in.rail.booking.Ticket.
  5. Run the class that has main by its full name: java -cp out in.rail.app.App.

Two more rules: java.lang (String, Math, System) is imported automatically, and only a public class can be used outside its package; a public class must live in a file of the same name.

3.9 Aggregation and composition

Not every relationship between classes is is-a. Very often one object has another: a car has an engine, a cricket team has players. These has-a relationships are written by putting one object, or a reference to it, inside another. UML separates two strengths. In aggregation the whole and its parts live independently, and a part may belong to several wholes. In composition each part belongs to one whole and is destroyed with it. Choosing between these, and between them and inheritance, is a design question examiners like. It completes the unit by giving the main alternative to inheritance.

You need: 3.1 Inheritance basics, 3.4 Constructors and destructors; Unit 1, Modeling classes with UML diagrams.

Association, aggregation and composition

  • Association: any lasting link in which objects of one class know objects of another, such as a Student enrolled in a Course. UML draws a plain line.
  • Aggregation: a whole-part association in which the part can exist without the whole and may be shared. A Team has Players; a Department has Professors. UML puts a hollow diamond at the whole's end.
  • Composition: a strong whole-part relationship. Each part belongs to exactly one whole at a time, is created with it or by it, and is destroyed with it. A House has Rooms; in our model a Car has its Engine. UML puts a filled diamond at the whole's end.

The deciding question is lifetime and ownership: "if the whole is destroyed, must the part go too?" The kind of variable used is only a hint.

Writing them in code

In C++, composition is usually a member object such as Engine e;. It is constructed in the whole's initializer list and destroyed automatically right after the whole's destructor body (the member step of Chapter 3.4). Aggregation is a pointer or reference to an object created elsewhere, such as vector<Player*> squad;, and the whole's destructor must not delete those parts, because it does not own them.

Java and Python have no destructors, so the difference is ownership. Composition: the whole creates the part itself and never hands it out, as in Java's private final Engine engine = new Engine(1197); or Python's self.engine = Engine(1197). Aggregation: the part is passed in from outside, as in team.add(player). When nothing refers to a car any more, the garbage collector can reclaim its engine with it; a player still referred to elsewhere stays alive.

Composition or inheritance?

The book Design Patterns (Gamma, Helm, Johnson and Vlissides, 1994) gave the rule "Favor object composition over class inheritance". A class that contains a part shows only the operations it chooses, can swap the part at run time (a petrol engine for an electric motor), and avoids fragile base classes and diamonds. Inheritance remains right when is-a holds and you want a derived object to be usable as a base object. So: Phone and Smartphone, is-a, inheritance; Phone and Battery, has-a and owned, composition; Playlist and Song, has-a and shared, aggregation.

Exam traps

  • The diamond goes at the whole's end of the line, not the part's.
  • Filled diamond = composition, hollow diamond = aggregation. Swapping them is the commonest mistake in UML answers.
  • A pointer does not automatically mean aggregation: a part held by std::unique_ptr and created by the whole is composition. Decide by lifetime and ownership.
  • In aggregation the whole must not delete its parts; doing so leaves the real owner with dangling pointers and a double delete.
  • Composition is not inheritance: a Car with an Engine member does not get Engine's public functions unless it forwards them.

Takeaways

  1. Use inheritance only for is-a; use aggregation or composition for has-a.
  2. A derived object contains a complete base part. Private base members are inherited but not accessible.
  3. Name the shape by counting direct bases and levels. Java classes allow single, multilevel and hierarchical inheritance; multiple and hybrid come through interfaces.
  4. In C++ an inherited member's access is the more closed of its base access and the mode; a class inherits privately by default.
  5. Bases are built first in header order, then members, then the derived body; destruction runs in exactly the reverse order.
  6. Overriding replaces or extends a method; super (or Base:: in C++) reaches the parent's version.
  7. A diamond duplicates the grandparent unless both middle classes inherit it as a virtual base; Python orders the search with the C3 MRO, and super() follows it.
  8. An interface is a contract without state; implementing it means overriding every abstract method with a public body.
  9. Packages group classes and draw access lines: default means same package, protected adds subclasses elsewhere.

Glossary

Aggregation
A whole-part relationship in which the parts exist independently of the whole and may be shared; hollow diamond in UML.
Association
Any lasting link between objects of two classes.
Base class
The class another class inherits from; also called parent class or superclass.
Base subobject
The complete copy of the base's members stored inside every derived object.
C3 linearization
The algorithm Python uses to build a class's method resolution order.
Composition
A strong whole-part relationship in which each part is owned by one whole and destroyed with it; filled diamond in UML.
Covariant return type
An overriding method's return type that is a subclass of the original method's return type.
Default access
Java access with no modifier word: visible only inside the same package (package-private).
Default method
A Java interface method with a body, inherited by implementing classes (Java 8 onwards).
Derived class
A class that inherits from another; also called child class or subclass.
Diamond problem
In hybrid inheritance, a class reaches the same base by two paths and gets two copies of it.
Direct and indirect base
The class named in the header, and a base further up the chain.
Hybrid inheritance
A design mixing two or more types of inheritance.
implements
The Java keyword by which a class promises to provide the methods of an interface.
Inheritance mode
In C++, the word public, protected or private before a base class name, which sets how inherited members appear outside.
Interface
A named set of method signatures without object state, used as a contract.
is-a and has-a
The tests for inheritance and for aggregation or composition.
Member initializer list
The part of a C++ constructor after the colon that passes arguments to bases and members.
Method resolution order (MRO)
The ordered list of classes Python searches for a method; super() follows it.
Module
In Python, one .py file; a folder of modules is a package.
Multilevel inheritance
A chain in which a derived class is the base of another.
Multiple inheritance
One class with two or more direct base classes.
Overriding
Giving an inherited method a new body with the same name and parameter list.
Package
In Java, a named group of classes stored in matching folders; it is also an access boundary.
Private inheritance
C++ inheritance that makes all inherited members private; models "implemented in terms of".
protected
Access for the class and its subclasses (and, in Java, the whole package).
super
The keyword (Java) or function (Python) that reaches the parent's version of a method or constructor.
using-declaration
A C++ line such as using Base::a; that brings an inherited name into a section with new access.
Virtual base class
A base declared virtual in the middle classes so that the most derived object holds a single shared copy.
