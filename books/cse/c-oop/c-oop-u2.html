2.1 Classes and objects: member data and member functions

A class is a type that you define: it bundles some data (the member data, also called data members or attributes) with the functions that are allowed to work on that data (the member functions, also called methods). An object is one variable of that type, with its own copy of the data. Classes exist so that a program can be organised around the things it models (an account, a student, a train ticket) instead of around loose variables and functions. Every later chapter of this unit adds one feature to the class you learn to write here.

You need: the OOP vocabulary of Unit 1 (abstraction, encapsulation) and basic C++ syntax (functions, cout, data types) from Unit 1, Program structure, tokens and data types.

Declaring a class

A C++ class declaration names the type, lists its members and ends with a semicolon. The semicolon is the first thing examiners look for in a written answer.

class Account {
private:
    long accNo;        // member data
    double balance;    // member data
public:
    void open(long no, double amt);   // member function (prototype only)
    void deposit(double amt) { balance = balance + amt; }   // defined inside
    double getBalance() { return balance; }
};                     // the semicolon is part of the declaration

Nothing is stored yet. The declaration is a blueprint; it tells the compiler what every Account will contain and what can be done to it. Some syllabi call the class the abstraction mechanism: it shows the outside world a short list of operations (open, deposit, getBalance) and hides how the money is actually represented. That hiding is enforced by the access specifiers of Chapter 2.2; for now, note that the data is private and the functions are public, which is the normal shape of a class.

Defining member functions inside and outside the class

A member function can be defined in two places. Defined inside the class body, as deposit is above, it is treated as an inline function (Chapter 2.6). Defined outside, the class body holds only the prototype, and the definition says which class it belongs to with the scope resolution operator :::

void Account::open(long no, double amt) {
    accNo = no;
    balance = amt;
}

Read Account::open as "the function open that belongs to Account". Without the Account:: prefix the compiler would create an ordinary free function named open that has no access to accNo and balance. Inside a member function the data members are used by their bare names; the compiler knows which object's copy is meant through the this pointer of Chapter 2.8. The usual convention is to keep the class declaration short (prototypes only) and define the longer functions outside, which is also how header files (.h) and source files (.cpp) split a class.

Creating objects and calling members

An object is created exactly like a variable of a built-in type, and its public members are reached with the dot operator:

Account a1, a2;        // two objects, each with its own accNo and balance
a1.open(1001, 5000);   // message to a1: "open yourself with these values"
a2.open(1002, 3000);
a1.deposit(1500);
cout << a1.getBalance();   // prints 6500

Some syllabi call a call such as a1.deposit(1500) message passing: the program sends the object a message (the function name) with some data (the arguments), and the object responds by running its own member function on its own data. When you hold a pointer to an object instead of the object itself, the arrow operator replaces the dot: Account *p = &a1; p->deposit(100);.

Memory allocation for objects

Memory is not allocated when the class is declared; it is allocated when an object is defined. Each object gets its own copy of every (non-static) data member, so a1 and a2 above occupy two separate blocks, each holding a long and a double. Member functions are different: there is only one copy of the code of deposit in the program, shared by every Account object, and that single copy is told which object to work on at each call. This is why sizeof(Account) counts only the data members (here 8 + 8 = 16 bytes on a typical 64-bit compiler) and not the functions. Objects defined inside a function live on the stack and vanish when the function returns; objects created with new live on the heap until delete (Chapter 2.4, and Unit 1, Pointers and dynamic memory).

The same class in Java and Python

Java has the same shape without the trailing semicolon and with the access word repeated on every member: class Account { private double balance; public void deposit(double amt) { balance += amt; } }. Objects are always created with new: Account a1 = new Account();. Python declares the data members inside the constructor and names the object explicitly in every method: class Account: / def deposit(self, amt): self.balance += amt. Chapters 2.3 and 2.8 return to both.

Exam traps

  • Forgetting the semicolon after the closing brace of the class. It is a syntax error, and examiners deduct for it in written code.
  • Defining a member function outside the class without ClassName::. The result is an unrelated free function, and the compiler reports that balance is undeclared.
  • Saying "memory is allocated when the class is declared". It is allocated per object, for data members only; member functions have one shared copy.
  • Using the dot operator on a pointer (p.deposit()) or the arrow on an object (a1->deposit()). Dot for objects, arrow for pointers.
  • The favourite 2-mark question: "Distinguish class and object." A class is a user-defined type (a blueprint, no memory); an object is an instance of that type (a variable, has memory).

2.2 Access specifiers: public, private and protected

An access specifier is a keyword in the class body that says who may use the members listed after it. public members can be used by any code that has an object; private members only by the class's own member functions (and its friends); protected members by the class and by classes derived from it. This is the mechanism behind encapsulation: the data is locked, the functions are the only door, and the class can therefore promise things about its data that no outside code can break.

You need: Chapter 2.1 (writing a class). Inheritance itself is Unit 3; here you only need to know that a derived class is a new class built on top of an existing one.

The three specifiers

Each specifier applies to every member after it until the next specifier appears, and a class may use them in any order and any number of times.

SpecifierOwn member functionsDerived class membersAny other code (e.g. main)
privateyesnono
protectedyesyesno
publicyesyesyes

Two defaults matter. In a class, members before the first specifier are private. In a struct, they are public. That is the only difference between the two keywords in C++. Access is checked by the compiler, at compile time, on the name being used; it does not depend on which object the name belongs to. So a member function of Account may read the private balance of another Account object passed to it, which is what makes copy constructors (Chapter 2.3) and comparison functions possible.

Why data goes private and functions go public

Consider marks out of 100. If marks is public, any line anywhere can write s.marks = 250. If it is private, the only way in is a setter that checks the value, and the class can promise that marks is always between 0 and 100. Functions that read a private member are called getters or accessors (getMarks()); functions that change one are setters or mutators (setMarks(m)). Not every data member needs both: a read-only property gets a getter only, and some data has no getter at all because nobody outside needs it.

Some syllabi ask you to differentiate abstraction and encapsulation, and the two are easy to blur. Abstraction is about the view: the class shows a short list of meaningful operations and hides detail (design decision). Encapsulation is about the enforcement: data and the functions that operate on it are kept in one unit, and the access specifiers make the hiding real (language mechanism). Abstraction is what you decide; encapsulation is how the compiler holds you to it.

Protected: a door for the children

protected is private with one exception: member functions of derived classes can use it. A Vehicle class might keep speed protected so that a derived Car can adjust it directly, while main still cannot. Until you reach Unit 3, treat protected exactly like private; the difference only appears once there is a derived class, and Unit 3 (Public, private and protected inheritance) covers how the inheritance mode changes the levels again.

Java and Python

Java uses the same three words plus a fourth level, the default (no keyword), which is visible to the whole package; and in Java the word is written in front of each member separately. Python has no enforced access at all. By convention a single leading underscore (_marks) means "internal, please do not touch", and a double leading underscore (__marks) triggers name mangling: the interpreter stores the attribute as _Student__marks, so an accidental s.__marks from outside fails, though a determined programmer can still reach it. A Python course expects you to know both conventions and the @property decorator, which turns a getter into something that reads like a plain attribute.

Question (6 marks). Write a class Student whose marks cannot be set outside the range 0 to 100. Show what happens when main tries to set marks directly, then fix it using a setter. Test with marks 87 and then 105.

class Student {
    int marks;                 // private by default

        marks = m;

    int getMarks() { return marks; }
};

    cout << s.setMarks(87)  << " " << s.getMarks() << endl;
    cout << s.setMarks(105) << " " << s.getMarks() << endl;
    return 0;
}

Exam traps

  • "The default access in a class is public." Wrong: it is private for class and public for struct. This is the most common 2-mark slip.
  • Thinking private means "private to the object". It is private to the class: a member function may touch the private members of any object of its own class.
  • Confusing abstraction with encapsulation. Abstraction hides detail in the design; encapsulation binds data and functions and enforces the hiding with access specifiers.
  • Treating protected as a weaker public. From outside the class hierarchy it is exactly as closed as private.
  • In Python, writing "private members are declared with private". Python has conventions (_x, __x with name mangling), not keywords.

2.3 Constructors: default, parameterized and copy

A constructor is a special member function that runs automatically the moment an object is created, so that no object ever exists with garbage inside it. A default constructor takes no arguments, a parameterized constructor takes the starting values, and a copy constructor builds a new object as a copy of an existing one. Constructors exist because "declare, then remember to initialise" is the source of half the bugs in procedural code; a class with a constructor cannot be used uninitialised.

You need: Chapter 2.1 (member functions) and Chapter 2.2 (why data is private). For the deep-copy example you need new and delete from Unit 1, Pointers and dynamic memory.

Rules every constructor follows

  • It has the same name as the class and no return type, not even void.
  • It is called automatically when an object is defined, never on an existing object.
  • It is normally public; a private constructor is a deliberate trick to stop outsiders creating objects.
  • It can be overloaded: the arguments at the point of creation choose which constructor runs.
  • It cannot be virtual and is not inherited (Unit 3 covers how derived classes call base constructors).

Default and parameterized constructors

class Point {
    int x, y;
public:
    Point() { x = 0; y = 0; }                    // default constructor
    Point(int a, int b) : x(a), y(b) { }         // parameterized, with an initializer list
    void show() { cout << "(" << x << ", " << y << ")"; }
};

Point p;          // default constructor: (0, 0)
Point q(3, 4);    // parameterized: (3, 4)
Point r{3, 4};    // same, with the brace syntax of C++11
Point s = Point(5, 6);   // also parameterized

Two facts about the default constructor trip up students. First, if you write no constructor at all, the compiler supplies a default one that does nothing to built-in members, so x and y hold garbage. Second, the moment you write any constructor, the compiler stops supplying the default one; a class with only Point(int, int) rejects Point p;. You then either write Point() yourself or give the parameters default values, Point(int a = 0, int b = 0), so that one constructor serves as both default and parameterized. One more trap: Point p(); with empty brackets declares a function named p, not an object; write Point p;.

The initializer list (: x(a), y(b)) initialises members before the body runs. It is the only way to initialise const members, reference members and member objects without a default constructor.

The copy constructor

A copy constructor takes a reference to an object of the same class, almost always a const reference, and builds the new object from it:

Point(const Point &p) { x = p.x; y = p.y; }

The parameter must be a reference. If it were passed by value, passing it would itself require a copy, which would call the copy constructor, which would need a copy… forever; the compiler refuses Point(Point p) for this reason. The copy constructor runs in three situations:

  1. When a new object is initialised from an existing one: Point q = p; or Point q(p);. Some syllabi call this copy initialization.
  2. When an object is passed to a function by value (Chapter 2.7).
  3. When a function returns an object by value (modern compilers usually skip this copy; the rule is called copy elision).

Contrast step 1 with plain assignment: q = p; where q already exists calls the assignment operator (Unit 4, Operator overloading), not the copy constructor. The question is always whether a new object is being born. If you write no copy constructor, the compiler supplies one that copies every member one by one, a member-wise or shallow copy. That is right for Point and wrong for a class that owns memory through a pointer.

Shallow copy versus deep copy

Suppose a class holds int *arr pointing to a block created with new. A shallow copy copies the pointer, so both objects point to the same block: a change through one shows up in the other, and when both destructors run the block is deleted twice, which crashes. A deep copy allocates a fresh block for the new object and copies the contents across. Whenever a class has a destructor that deletes something, it also needs a hand-written copy constructor and assignment operator: the rule of three.

Java and Python

Java constructors follow the same naming rule and overloading, but Java has no automatic copy constructor: Point q = p; copies only the reference, so both names are the same object. Python's constructor is __init__(self, ...), there is one per class, and default parameter values play the role of overloading. Copying is explicit: copy.copy(p) is shallow, copy.deepcopy(p) is deep.

Worked example 2: a deep copy

Question (8 marks). A class Marks stores n marks in a dynamically allocated array. Write its copy constructor so that changing a copy does not change the original, and demonstrate with marks 70, 80, 90.

class Marks {
    int n;
    int *arr;
public:
    Marks(int size, const int src[]) : n(size) {
        arr = new int[n];
        for (int i = 0; i < n; i++) arr[i] = src[i];
    }
    Marks(const Marks &o) : n(o.n) {        // deep copy
        arr = new int[n];                    // own block
        for (int i = 0; i < n; i++) arr[i] = o.arr[i];
    }
    ~Marks() { delete[] arr; }
    void set(int i, int v) { arr[i] = v; }
    int get(int i) { return arr[i]; }
};

int main() {
    int src[] = {70, 80, 90};
    Marks m1(3, src);
    Marks m2 = m1;          // copy constructor
    m2.set(0, 95);
    cout << m1.get(0) << " " << m2.get(0) << endl;
}

Trace. m1 allocates a block holding {70, 80, 90}. Marks m2 = m1 calls the copy constructor: n = 3, a second block is allocated and the three values copied. m2.set(0, 95) writes into m2's block only. Output: 70 95. At the end of main each destructor frees its own block exactly once. With the compiler's shallow copy the output would have been 95 95, followed by undefined behaviour from the double delete (usually a crash).

  • Writing a return type: void Box() is not a constructor; it is an error.
  • Box b(); declares a function, not a default-constructed object. Write Box b;.
  • "Every class has a default constructor." Only if you wrote none at all. Writing any constructor removes the compiler's default one.
  • Copy constructor parameter by value (Box(Box o)): infinite recursion; the compiler rejects it. Use const Box &.
  • Box c = b; (new object: copy constructor) versus c = b; (existing object: assignment operator). Some syllabi list "assignment and copy initialization" by name.

2.4 Destructors and object lifetime

A destructor is the member function that runs automatically at the moment an object ceases to exist, so that whatever the object acquired (heap memory, an open file, a network socket) is given back without the programmer remembering to do it. Where a constructor is the birth of an object, the destructor is its funeral. Knowing exactly when that moment comes, for local objects, heap objects, global objects and temporaries, is what examiners mean by "object lifetime", and it is the part of this chapter most 8-mark trace questions test.

You need: Chapter 2.3 (constructors) and new/delete from Unit 1, Pointers and dynamic memory with new and delete.

The destructor

class File {
    FILE *fp;
public:
    File(const char *name) { fp = fopen(name, "r"); }
    ~File() { if (fp) fclose(fp); }     // destructor
};

The destructor's name is the class name with a tilde (~) in front. It takes no arguments and has no return type, so there can be only one per class: it cannot be overloaded. Like a constructor it is never called by name in normal code; the compiler inserts the call at the right moment. If you write none, the compiler provides an empty one, which is fine for a class whose members are plain values or standard-library objects (a std::string member cleans itself up). You write one when the class holds something that must be released by hand: memory from new, a C file handle, a lock. The body usually mirrors the constructor: what the constructor took with new, the destructor returns with delete; what it opened, the destructor closes.

Four kinds of lifetime

When the destructor runs depends only on how the object was created. Syllabi list this as "memory allocation for objects" or "memory management".

  1. Automatic (local) objects, declared inside a function or block, live on the stack. They are constructed where the declaration is reached and destroyed when control leaves the enclosing block (the closing }, a return, or an exception).
  2. Dynamic objects, created with new, live on the heap. They are destroyed only by delete, and if you lose the pointer first the object is never destroyed: a memory leak. delete runs the destructor first, then frees the memory.
  3. Static and global objects are constructed before main starts (or on first use, for a function-local static) and destroyed after main returns.
  4. Temporary objects, such as the unnamed Point(1, 2) in an expression, are destroyed at the end of the full expression that created them, usually the semicolon.

Order of destruction

Within one scope, objects are destroyed in the reverse order of their construction: last constructed, first destroyed, like plates on a stack. The reason is dependency: a later object may hold a pointer to an earlier one, so the later one must go first. The same rule applies to the elements of an array of objects (Chapter 2.7), which are constructed from index 0 upwards and destroyed from the last index downwards, and to a derived object, where the derived part is destroyed before the base part (Unit 3, Constructors and destructors in derived classes).

Java and Python

Java has no destructors. Objects are reclaimed by the garbage collector some time after the last reference to them disappears, and you cannot know when; finalize() is deprecated and should not be used. Resources such as files are released explicitly with close() or automatically by a try-with-resources block. Python has __del__(self), which CPython calls when the object's reference count drops to zero, usually immediately; but del x only removes the name x, and the object survives while any other reference to it exists. Python courses list "constructors and destructors" too, so know __del__, and know that the recommended tool for releasing resources is a context manager (with open(...) as f:), not __del__.

2.5 Static data members and static functions

Every data member you have met so far is copied into each object. A static data member is different: there is exactly one copy for the whole class, shared by all its objects, and it exists even when no object does. A static member function is a function of the class that works without any object and can therefore touch only static data. Together they give a class a place to keep things that belong to the type as a whole: how many objects exist, the next ticket number to issue, a conversion rate used by every object.

You need: Chapter 2.1 (memory per object) and Chapter 2.3 (constructors), since the worked example counts objects in the constructor.

Static data members

class Ticket {
    static int count;        // declaration: one copy for the class
    long pnr;                // ordinary member: one copy per object
public:
    Ticket() { count++; }
    ~Ticket() { count--; }
};
int Ticket::count = 0;       // definition and initialisation, outside the class, once

Three rules follow from "one copy for the class":

  1. The line inside the class is only a declaration. The member must be defined exactly once outside the class, with the type, the class name and ::, and that is where it is initialised. If you omit this line, the program fails to link with an "undefined reference to Ticket::count" error. (The static keyword is not repeated in the definition.) Since C++17 you may write inline static int count = 0; inside the class instead, and a static const int may be initialised in the class since long before that.
  2. It is initialised to zero by default and lives from before main starts until the program ends, like a global variable, but its name is inside the class scope and it obeys the access specifier: a private static member is still private.
  3. It is not part of any object, so sizeof(Ticket) excludes it, and it can be reached either through an object (t1.count, if public) or, better, through the class name (Ticket::count) with no object at all.

Some syllabi also mention "static variables" in the C sense: a static local variable inside a function keeps its value between calls. Same keyword, same idea (one copy, whole program lifetime), different scope.

Static member functions

class Ticket {
    ...
public:
    static int alive() { return count; }   // no object needed
};
cout << Ticket::alive();                    // called through the class

A static member function is called with the class name and ::, and it receives no this pointer (Chapter 2.8) because there may be no object at all. So it can use only static data members and other static functions; a line such as return pnr; inside it is an error, because the compiler cannot know whose pnr is meant. It cannot be const and cannot be virtual. Typical uses: reporting a count, issuing the next serial number, converting units, and "factory" functions that create objects in a controlled way (the Factory pattern is built on static functions).

Java and Python

Java uses the same keyword with the same meaning: static int count; is a class field initialised in place, and static int alive() is called as Ticket.alive(); Math.sqrt and main itself are static methods. Python distinguishes a class attribute, written directly in the class body (count = 0) and shared, from an instance attribute, created through self in __init__ and per object. Writing Ticket.count += 1 updates the shared value; writing self.count += 1 by mistake creates a new instance attribute that shadows it. Python's @staticmethod takes no object, and @classmethod receives the class as cls, which is the usual way to write counters and factories.

2.6 Inline functions and friend functions

These two features bend the normal rules on purpose. An inline function asks the compiler to paste the function's body at each place it is called, removing the cost of a function call for tiny functions. A friend function is an ordinary non-member function that a class has explicitly allowed to use its private members, for the few jobs that genuinely need to see inside two objects or two classes at once. They appear together in every syllabus because both are declared inside the class body yet neither behaves like a normal member.

You need: Chapter 2.1 (member functions defined inside and outside the class) and Chapter 2.2 (private access).

Inline functions: removing the cost of a call

Every function call has a cost: the arguments are pushed, control jumps to the function, a return address is saved, and on return the stack is cleaned up. For a function whose body is a single expression, this bookkeeping can take longer than the work. Writing inline in front of the definition asks the compiler to replace each call with a copy of the body, as if you had typed the expression there yourself:

inline double area(double r) { return 3.14159 * r * r; }

double a = area(2.0);   // compiled as if: double a = 3.14159 * 2.0 * 2.0;

Four facts about inline:

  1. It is a request, not a command. The compiler may ignore it, and usually does for functions that contain loops, recursion, a switch, static variables, or are simply long.
  2. A member function defined inside the class body is inline automatically, with no keyword. That is why short getters and setters are written in the class body (Chapter 2.1).
  3. The definition must be visible wherever the function is called, which is why inline functions are written in header files rather than .cpp files.
  4. Expansion trades code size for speed: a 20-line function inlined at 50 call sites makes the program bigger, and a bigger program may run slower because less of it fits in the processor's cache. Keep inline for one- or two-line functions.

Inline functions replace C's #define macros for small computations. A macro is a textual substitution with no type checking and surprising precedence; an inline function is a real function, type-checked, and its argument is evaluated once. The worked example shows the difference in numbers.

Friend functions: a key to the private room

Sometimes a function needs the private data of a class but should not be a member: it belongs equally to two classes, or it must be called without an object (as an overloaded operator such as << must be, see Unit 4). The class can declare such a function a friend:

class Box {
    double volume;
public:
    Box(double v) : volume(v) {}
    friend bool bigger(const Box &a, const Box &b);   // declaration inside the class
};
bool bigger(const Box &a, const Box &b) {               // defined outside, no Box::
    return a.volume > b.volume;                            // private access allowed
}
// called like any function:  if (bigger(b1, b2)) ...

Properties that examiners ask for: a friend is declared with the keyword friend inside the class, in any access section (public or private makes no difference); it is not a member, so it is defined without Box::, is called without an object and has no this pointer; it receives the objects it works on as arguments; one function can be a friend of several classes (then at least one class must be forward-declared, as the second example shows); and a whole class can be made a friend (friend class Inspector;), after which all of that class's member functions may use the private members. Friendship is granted, never taken: the class being accessed lists its friends, the friend cannot declare itself. It is also not symmetric (A friend of B does not make B a friend of A), not transitive (a friend of a friend is not a friend) and not inherited (Unit 3).

A friend widens the circle of code that can see the private data, so it must be treated as part of the class's interface and used only when a member function cannot do the job. Two legitimate uses: operator overloading where the left operand is not an object of the class (cout << obj), and a function that compares or combines two different classes.

Worked example 1: inline function versus macro

Question (4 marks). With #define SQUARE(x) x * x and inline int sq(int x) { return x * x; }, find SQUARE(a + 1) and sq(a + 1) for a = 3. Language: C++.

The macro is text substitution: SQUARE(a + 1) becomes a + 1 * a + 1. With a = 3, operator precedence gives 3 + (1 × 3) + 1 = 7. The inline function evaluates its argument first: a + 1 = 4, then 4 × 4 = 16, which is the intended square. The inline function is also type-checked (passing a string is an error), whereas the macro would silently produce nonsense. The compiled code for sq(a + 1) is as fast as the macro because no call is made.

2.7 Arrays of objects; objects as function arguments

Once a class exists, its objects behave like values of any other type: you can put them in an array, pass them to functions and return them from functions. An array of objects is how a program holds fifty students or a hundred train coaches without fifty variable names. Passing objects to functions raises one question that built-in types never make you think about: does the function get a copy (by value, which runs the copy constructor) or the original (by reference)? The answer decides both correctness and speed.

You need: Chapter 2.3 (default and copy constructors) and ordinary arrays and references from Unit 1.

Arrays of objects

class Employee {
    string name; double salary;
public:
    Employee() : salary(0) {}                 // needed by  Employee e[3];
    Employee(string n, double s) : name(n), salary(s) {}
    void read()  { cin >> name >> salary; }
    double pay() { return salary; }
    string who() { return name; }
};

Employee e[3];                       // three objects, default-constructed
Employee p[2] = { Employee("Asha", 52000), Employee("Ravi", 61000) };
e[1].read();                         // member access: index first, then dot

An array of objects is declared exactly like an array of int: type, name, size. The elements are stored one after another in memory (contiguously), so an array of three Employee objects occupies 3 × sizeof(Employee) bytes. Three consequences follow:

  1. Construction. Employee e[3]; calls the default constructor three times, for e[0], e[1], e[2] in that order. If the class has constructors but no default one, this line is an error; you must then initialise every element with a brace list, as p does, which calls the parameterized constructor for each.
  2. Access. e[i].pay(): subscript first, then the member. For a pointer to the array, (e + i)->pay() is the same thing.
  3. Destruction. When the array goes out of scope, destructors run in reverse: e[2], e[1], e[0]. A heap array (Employee *q = new Employee[n];) is destroyed only by delete[] q;, with the brackets; plain delete q destroys one element and leaks the rest.

In Java an array of objects is an array of references, all null until each element is created with new. In Python a list of objects plays the same role. In modern C++ std::vector<Employee> (Unit 5, STL containers) grows on demand and is what real code uses; the fixed array is what the exam asks for.

A function may also return an object by value: it builds a local result and hands it back, as the second worked example does. Returning a reference to a local object is a bug: the local is destroyed when the function returns and the reference points at nothing.

Question (8 marks). Define a class Time (hours, minutes). Write a member function add that takes another Time object and returns a new Time object holding the sum. Add 2 h 45 min and 1 h 30 min.

class Time {
    int h, m;
public:
    Time(int hh = 0, int mm = 0) : h(hh), m(mm) {}
    Time add(const Time &t) {            // object as argument, by const reference
        Time r;                           // local result object
        int total = (h * 60 + m) + (t.h * 60 + t.m);   // t.h is private, but same class
        r.h = total / 60;
        r.m = total % 60;
        return r;                         // object returned by value
    }
    void show() { cout << h << " h " << m << " min" << endl; }
};

int main() {
    Time t1(2, 45), t2(1, 30);
    Time t3 = t1.add(t2);
    t3.show();
}

Working. t1 in minutes: 2 × 60 + 45 = 165. t2: 1 × 60 + 30 = 90. total = 255. r.h = 255 / 60 = 4 (integer division), r.m = 255 mod 60 = 15. Output: 4 h 15 min. Because t is passed by const reference, no copy of t2 is made and add cannot change it; the result r is returned by value and lands in t3.

Exam traps

  • Employee e[3]; with a class that has only a parameterized constructor. Error: no default constructor. Either add one or initialise with a brace list.
  • Passing a large object by value in a loop and wondering why the program is slow: a copy constructor and a destructor run on every call. Use const &.
  • Expecting a function with a by-value parameter to change the caller's object. It changes the copy.
  • Returning a reference or pointer to a local object. The local dies at return; the caller gets garbage.
  • delete q instead of delete[] q for an array created with new Employee[n].
  • The examiner's favourite: "How many times is the constructor called for Student s[5];?" Five, the default constructor once per element, in index order.

2.8 The this pointer and the self reference

Chapter 2.1 said that one shared copy of a member function serves every object, and that the copy is "told which object to work on". The this pointer is how it is told: every non-static member function receives, as a hidden first argument, the address of the object it was called on, and this is the name of that argument. Python makes the same argument visible and calls it self; Java hides it and calls it this. Understanding this one mechanism explains how a1.deposit(100) reaches a1's balance, how setters can be chained, and why static functions and friends have no this.

You need: Chapter 2.1 (member functions), Chapter 2.5 (why static functions have no object) and pointers from Unit 1.

What this is

When you write b.setL(3), the compiler compiles something close to Box::setL(&b, 3): the object's address travels as an extra argument. Inside setL, that address is available as this, whose type is "pointer to Box" (strictly Box *const, so you cannot reassign it; in a const member function it is const Box *). Every bare use of a data member inside a member function is silently this->member:

void Box::setL(double v) { l = v; }          // what you write
void Box::setL(double v) { this->l = v; }    // what the compiler sees

Because this is the address of a specific object, it exists only where there is one: in non-static member functions. A static member function (Chapter 2.5) is called through the class and has no this; a friend function (Chapter 2.6) is not a member and has none either, which is why both must receive objects as explicit arguments.

Three things this is used for

  1. Telling a parameter from a member with the same name. Programmers like to write setL(double l); inside, the bare name l now means the parameter, and the member is hidden. this->l = l; says "the member l of this object gets the parameter l". The same line in Java is this.l = l; and in Python self.l = l.
  2. Returning the object itself so that calls can be chained. A setter that ends with return *this; and returns Box& gives back the very object it changed, so the next .set…() applies to the same object: b.setL(3).setB(4).setH(5);. *this is the object; this alone is its address.
  3. Identifying the object. Comparing this == &other detects self-assignment in an overloaded = (Unit 4), and passing this to another function lets an object register itself with a list or a manager.

Python's self

Python refuses to hide the mechanism. Every method takes the object as its explicit first parameter, conventionally named self (any name works, but every reviewer expects self), and every attribute access must go through it: a bare balance inside a method is a local variable, not the attribute. A call a.deposit(500) is exactly Account.deposit(a, 500); Python fills in the first argument when the method is reached through an object. Instance attributes are created the first time they are assigned through self, usually in __init__. Python syllabi list "self keyword and object" by name: self is not a keyword, it is a parameter; that distinction is a favourite 2-mark question.

Worked example 1: chained setters in C++

Question (6 marks). Write a class Box whose setters use this to resolve name clashes and return *this so that calls can be chained. Compute the volume of a 3 × 4 × 5 box using one chained statement.

Worked example 2: self in Python

Question (6 marks). Define a Python class Account with a constructor that sets the holder and balance, a deposit method and a __str__ method. Show that a.deposit(1500) and Account.deposit(a, 500) act on the same object. Language: Python 3.

class Account:
    def __init__(self, holder, balance=0):
        self.holder = holder          # instance attributes created through self
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount        # without self, balance would be a new local
        return self                   # allows chaining, like return *this

    def __str__(self):
        return f"{self.holder}: {self.balance}"

a = Account("Asha", 5000)
a.deposit(1500)
Account.deposit(a, 500)               # same call, self passed by hand
print(a)
print(a.deposit(100).deposit(200))

Trace. Account("Asha", 5000) creates an object and calls __init__ with self bound to it: holder = "Asha", balance = 5000. a.deposit(1500) binds self to a: 5000 + 1500 = 6500. Account.deposit(a, 500) passes a explicitly: 6500 + 500 = 7000. The chained line adds 100 then 200: 7300, and print calls __str__.

Output:

Asha: 7000
Asha: 7300

Exam traps

  • Writing l = l; in a setter whose parameter is also called l. The member is never set. Use this->l = l; or rename the parameter.
  • Returning this when *this is meant. this is an address; chaining with the dot operator needs the object (or a reference to it).
  • Using this inside a static member function or a friend function. Neither has one.
  • In Python, forgetting self in a method's parameter list, or writing balance += amount without self.. The first gives "takes 0 positional arguments but 1 was given"; the second creates an unrelated local variable.
  • Calling self a keyword in a Python answer. It is a conventional parameter name; this in C++ and Java is a keyword.

Analyze A C++ class stores this in a global list in its constructor and never removes it in the destructor. What can go wrong? 3 marks

After an object dies (end of scope or delete) the list still holds its old address: a dangling pointer. Any later use through the list reads freed memory, which may crash or silently return garbage. The destructor must remove this from the list, which is the symmetry rule of Chapter 2.4.

Beyond the syllabus

The explicit object parameter is becoming visible in C++ too: C++23 lets you write void f(this Box& self) ("deducing this"), which simplifies chaining and avoids duplicating const and non-const overloads. Chaining through return *this is the basis of the builder pattern and of fluent interfaces such as Java's StringBuilder and Python's pandas method chains. Rust names the receiver self like Python and makes its mode (&self, &mut self, self) part of the signature. Search "deducing this C++23" and "fluent interface". Not needed for the exam.

Takeaways

  1. A class is a type; an object is a variable of that type. Memory is allocated per object for data members only; member function code exists once.
  2. Keep data private and functions public; a class default is private, a struct default is public. Abstraction is the design choice, encapsulation is the enforcement.
  3. A constructor has the class name, no return type, and runs automatically. Writing any constructor removes the compiler's default one; C obj(); declares a function.
  4. The copy constructor takes const C & and runs on initialisation from an object, pass by value and return by value. Classes that own memory through pointers need a deep copy.
  5. A destructor ~C() takes nothing and returns nothing. Local objects die at the closing brace in reverse order; heap objects die only at delete.
  6. A static data member is one shared copy, defined once outside the class; a static function has no this and is called through the class name.
  7. inline is a request to expand a small function at its call sites; members defined inside the class are inline automatically.
  8. A friend is a non-member with private access, declared inside the class, defined outside without ::, called without an object. Friendship is not inherited, symmetric or transitive.
  9. An array of objects needs a default constructor and is destroyed in reverse; pass objects by const & unless you need a copy or must modify the original.
  10. this is the hidden address of the current object; this->x = x resolves name clashes and return *this chains calls. Python's self is the same argument made explicit.

Glossary

Abstraction
Showing a type's essential operations and hiding its representation; a design decision.
Access specifier
public, private or protected: a label in the class body that sets who may use the members that follow it.
Accessor / mutator
Public member functions that read (getter) or change (setter) a private data member, usually with checks.
Array of objects
A contiguous sequence of objects of one class, C a[n];, each element constructed by the default constructor.
Class
A user-defined type that bundles data members with the member functions that operate on them; uses no memory itself.
Class attribute (Python)
A variable defined in the class body and shared by all instances; the counterpart of a static data member.
Constructor
A member function with the class's name and no return type that runs automatically when an object is created.
Copy constructor
Constructor of the form C(const C &) that builds a new object from an existing one; runs on copy-initialisation, pass by value and return by value.
Copy elision
The compiler's omission of a copy constructor call when returning or initialising from a temporary.
Deep copy
A copy that allocates its own resources and duplicates contents, so the copy and the original are independent.
Default constructor
A constructor that can be called with no arguments; supplied by the compiler only if no constructor is written.
Destructor
~C(): the member function that runs automatically when an object is destroyed; releases what the object acquired.
Encapsulation
Binding data and the functions that operate on it into one unit and enforcing the hiding with access specifiers.
Friend function
A non-member function that a class declares with friend, giving it access to private and protected members.
Initializer list
The : m(v), n(w) part of a constructor that initialises members before the body runs.
Inline function
A function the compiler is asked to expand at each call site instead of calling; member functions defined inside the class are inline by default.
Instance attribute (Python)
A variable created through self that belongs to one object.
Member function / method
A function declared inside a class that operates on the object it is called on.
Message passing
Calling a member function on an object, obj.f(args): the object is sent a message and responds.
Name mangling (Python)
Rewriting an attribute __x inside class C to _C__x, which discourages but does not prevent outside access.
Object
An instance of a class: a variable with its own copy of the data members.
Parameterized constructor
A constructor that takes arguments to set the initial state.
Pass by reference
Passing an object as C & or const C &, so the function works on the caller's object with no copy.
Pass by value
Passing an object so that the function receives a fresh copy made by the copy constructor.
RAII
Resource Acquisition Is Initialization: tying a resource's lifetime to a stack object's constructor and destructor.
Rule of three
If a class needs a hand-written destructor, it needs a copy constructor and an assignment operator too.
Scope resolution operator
::, used to define a member outside its class (C::f) and to reach static members (C::count).
self
The conventional name of the explicit first parameter of a Python method, bound to the object the method is called on.
Shallow copy
A member-wise copy; pointer members are copied as addresses, so both objects share the pointed-to block.
Static data member
A data member with one copy for the whole class, declared with static inside and defined once outside.
Static member function
A member function callable through the class name without an object; has no this and uses static members only.
this pointer
The hidden pointer, available in non-static member functions, holding the address of the object the function was called on.
