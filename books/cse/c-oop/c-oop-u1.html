1.1 Procedural versus object-oriented programming

A procedural program is a list of instructions grouped into functions, and the functions all work on data that sits outside them, usually global. C, Pascal and FORTRAN are built for this, and it breaks down as programs grow: any function can change any data, so a change to the data forces a check of every function. Object-oriented programming (OOP) turns the picture inside out: the data is put inside objects, each object carries the only functions allowed to touch its data, and the program runs by objects sending requests ("messages") to one another. Syllabi word this chapter as "procedure oriented programming vs object oriented programming" and "characteristics of object-oriented languages", or as "paradigms, principles, benefits, applications".

Procedural programming: functions over shared data

In the procedural (procedure-oriented, POP) style the programmer asks "what must be done?" and breaks the job top-down into functions: read input, compute, print. The data is global or passed around in long argument lists. Three habits follow. Data moves freely, so nothing stops a function from writing a wrong value into a shared array. Functions are organised around actions, not around the things the program models: a bank program has deposit() and withdraw() but nothing called an account. And reuse is by copying: a second kind of account means copying and editing the functions.

Object-oriented programming: objects that own their data

An object is a bundle of data (its state: attributes or data members) and the functions that may act on that data (its behaviour: methods or member functions). A class is the type, the blueprint, from which objects are created; Account is a class, acc1 with balance ₹1000 is an object. Design is bottom-up: first ask "what things are there?" (accounts, customers, transactions), write a class for each, then write the flow that connects them. Because the data is private to its object, the only way to change a balance is to call a member function, and that function can refuse. Objects communicate by message passing: acc1.withdraw(500) asks acc1 to run its own withdraw with the argument 500.

Paradigms, and what makes a language object-oriented

A paradigm is a style of thinking about a program. Four are usually named: imperative / procedural (a sequence of commands that change state: C, Pascal), object-oriented (objects exchanging messages: Smalltalk, C++, Java, Python), functional (functions that return values without changing state: Haskell, Lisp, the lambdas of modern C++, Java and Python) and logic (facts and rules the system reasons over: Prolog). Most languages mix them; C++ is a hybrid that keeps all of C, which is why a C++ program may have no class at all.

Examiners ask for the characteristics of an object-oriented language. Give seven, one phrase each: (1) emphasis on data rather than procedures; (2) the program is divided into objects; (3) data is hidden from outside functions (data hiding); (4) objects communicate by message passing; (5) new data and functions are added by writing new classes; (6) classes are built from existing classes (inheritance), so code is reused, not copied; (7) the function to run can be chosen at run time (dynamic binding, Unit 4). The benefits that syllabi list follow: reuse through inheritance, easier maintenance because a change stays inside one class, a closer match to real-world things, and security through data hiding. Typical applications: GUIs, simulation, games, CAD, database systems and machine-learning frameworks.

Worked example

Question. Write a bank-balance program (a) procedurally and (b) as a C++ class. Trace both for: start ₹1000, deposit ₹500, withdraw ₹1200, withdraw ₹500. (c) A minimum balance of ₹500 must now be kept after every withdrawal. Show what changes in each version and the new final balance. (8 marks)

Solution. (a) Procedural, in C++ without a class (compiles in C with printf):

double balance = 1000;                 // global, visible to every function
void deposit(double a)  { balance += a; }
void withdraw(double a) {
    if (a > balance) std::cout << "Insufficient\n";
    else balance -= a;
}
int main() {
    deposit(500); withdraw(1200); withdraw(500);
    std::cout << balance << '\n';
}

(b) The class version keeps balance private; the only door is withdraw, which returns whether it worked:

class Account {
    double balance;                                    // private by default
public:
    Account(double b) : balance(b) {}
    void deposit(double a) { balance += a; }
    bool withdraw(double a) {
        if (a > balance) return false;
        balance -= a; return true;
    }
    double getBalance() const { return balance; }
};
int main() {
    Account acc(1000);
    acc.deposit(500);
    if (!acc.withdraw(1200)) std::cout << "Insufficient\n";
    if (!acc.withdraw(500))  std::cout << "Insufficient\n";
    std::cout << acc.getBalance() << '\n';
}

Dry run (both versions behave the same here):

StepCallCheckBalance afterOutput

2withdraw(1200)1200 > 1500? no300

(c) The rule "balance − amount must not fall below 500". Procedural version: the rule goes into withdraw, but because balance is global, any other function (a fee deduction, a line in main that writes balance -= 50;) can still break it, so every function must be searched. Class version: the only line that subtracts from balance is inside withdraw, so one condition changes:

if (balance - a < 500) return false;   // replaces  if (a > balance)

New trace: 1000 → deposit → 1500; withdraw(1200): 1500 − 1200 = 300 < 500, refused, prints "Insufficient"; withdraw(500): 1500 − 500 = 1000 ≥ 500, allowed. Final balance ₹1000; output: Insufficient then 1000.

Exam traps

  • "C++ is a pure object-oriented language": no. It is a hybrid that allows global functions and data and treats int as a plain value. Java is closer to pure; Smalltalk is pure.
  • Top-down belongs to POP, bottom-up to OOP. Students swap them.
  • Data hiding and data abstraction are different (Chapter 1.2): hiding keeps the data private; abstraction shows only the essential features.
  • An object is not a class. The class is the type (Account); the object is a variable of that type (acc) with its own values.
  • The examiner's favourite: "Compare POP and OOP" for 8 marks wants a table of six or seven points, not a paragraph; "characteristics of OOP" wants the seven-point list above.

1.2 OOP principles: abstraction, encapsulation, inheritance, polymorphism

Four ideas carry the whole subject. Abstraction: show a user only what matters and hide the rest. Encapsulation: keep data and the functions that handle it together in one unit, and let the unit decide who gets in. Inheritance: build a new class on an existing one instead of copying it. Polymorphism: let the same call do different things depending on the object that receives it. Every syllabus lists them; some ask you to "differentiate between abstraction and encapsulation", some add "message passing", others "objects, classes, attributes, methods". This chapter defines each with ten lines of C++ and leaves the full machinery to Units 2 to 4.

You need: the object and class vocabulary of Chapter 1.1.

Objects, classes, attributes, methods, messages

An object has three things: state (its data: the attributes or data members, such as a balance of ₹1000), behaviour (what it can do: its methods or member functions, such as withdraw) and identity (two accounts with the same balance are still two objects, at two addresses). A class describes the state and behaviour once; each object is an instance of its class. C++ says member function where Java and Python say method; all three say attribute or field for the data. Message passing is the OOP word for calling a method on a specific object: acc.withdraw(500) sends the message "withdraw 500" to acc, and acc runs its own code in reply.

Abstraction and encapsulation, and how they differ

Abstraction means presenting only the essential features of a thing and leaving out the details. A car's steering wheel abstracts the whole steering mechanism; an ATM screen abstracts the bank. In code, abstraction is the interface a class offers (deposit, withdraw, getBalance) without the user needing to know how the balance is stored or how the ledger is updated. A class designed this way is a data abstraction or abstract data type (ADT): a type defined by its operations, not by its storage.

Encapsulation means binding the data and the functions that work on it into a single unit, the class, and controlling access with access specifiers: private members can be used only by the class's own functions, public ones by anyone (Unit 2 covers protected). Because the balance is private, no outside code can set it to −5000; that protection is data hiding, and it is a consequence of encapsulation. The difference the examiner wants: abstraction is about the design (what is exposed), encapsulation is about the mechanism (how data and code are packed and protected). Abstraction answers "what does this object do?"; encapsulation answers "who may touch its data?".

Inheritance and polymorphism

Inheritance lets a new class (the derived or child class; Java says subclass) take all the members of an existing class (the base or parent class; superclass) and add or change some. SavingsAccount inherits from Account: it gets deposit and withdraw free and adds interest. The relationship must be is-a: a savings account is an account. Inheritance is the reuse mechanism of OOP, and it forms hierarchies (Unit 3).

Polymorphism (Greek, "many forms") means one name, many behaviours. It comes in two kinds. Compile-time polymorphism: the compiler picks the function from the argument types; this is function overloading (area(int r) and area(int l, int b)) and operator overloading (+ on strings). Run-time polymorphism: the object picks the function while the program runs; a base-class pointer calls area() and a Circle computes πr² while a Rect computes l × b. In C++ this needs the function to be declared virtual; Java methods are virtual by default; Python resolves every call at run time. Unit 4 is entirely about this.

In Java / In Python. Java uses the same four words; overriding works without virtual, and multiple inheritance of classes is replaced by interfaces (Unit 3). Python has no real private: a leading underscore (_balance) is a convention, a double underscore (__balance) is name-mangled to discourage access, and @property gives controlled getters and setters. Python's polymorphism is "duck typing": any object with an area() method will do (Unit 4).

Worked example

Question. Write a C++ program with a base class Account (private balance, deposit, virtual monthEnd()) and two derived classes: Savings, whose month end adds interest at 4 % per year, and Current, whose month end deducts a ₹50 service charge. Keep a Savings account with ₹12,000 and a Current account with ₹5,000 in an array of base-class pointers, run one month end on each, print the balances, and name the principle each part of the program shows. (10 marks)

Solution.

#include <iostream>
class Account {
protected:
    double balance;                        // encapsulation: not public
public:
    Account(double b) : balance(b) {}
    void deposit(double a) { balance += a; }
    double getBalance() const { return balance; }   // abstraction: the interface
    virtual void monthEnd() {}             // run-time polymorphism starts here
};
class Savings : public Account {           // inheritance: Savings is an Account
public:
    Savings(double b) : Account(b) {}
    void monthEnd() override { balance += balance * 0.04 / 12; }
};
class Current : public Account {
public:
    Current(double b) : Account(b) {}
    void monthEnd() override { balance -= 50; }
};
int main() {
    Savings s(12000); Current c(5000);
    Account* list[2] = { &s, &c };
    for (Account* a : list) a->monthEnd();     // one call, two behaviours
    std::cout << s.getBalance() << ' ' << c.getBalance() << '\n';
}

s (Savings)12,000Savings::monthEnd12000 × 0.04 / 12 = 4012,040
c (Current)5,000Current::monthEnd5000 − 504,950

Principles: balance kept out of public is encapsulation (data hiding); the three public functions are the abstraction the user sees; class Savings : public Account is inheritance; the loop calling a->monthEnd() through a base pointer and getting two different results is run-time polymorphism, which works only because monthEnd is virtual. Without virtual the base version would run twice and the output would be 12000 5000.

Exam traps

  • Abstraction is not encapsulation. Abstraction = showing the essential interface; encapsulation = packing data with code and restricting access. Data hiding is the result of encapsulation, not a synonym of abstraction.
  • Polymorphism is not only overloading. Say both kinds: compile-time (overloading) and run-time (overriding through virtual functions).
  • Inheritance models is-a. A Car has an Engine; that is composition (an Engine member), not inheritance (Unit 3).
  • In C++, overriding works through a base pointer only if the base function is virtual; Java needs no keyword. Mixing the two languages in one answer loses marks.
  • The examiner's favourite: "Explain the principles of OOP with examples" (8 or 13 marks): one definition, one real-world example and one line of code for each of the four, plus objects, classes and message passing.

1.3 Program structure, tokens and data types

A compiler sees a program in layers: a file laid out in a fixed order of sections, each section a stream of tokens (the smallest meaningful pieces: words, numbers, symbols), and every variable tagged with a data type that fixes how many bytes it takes and what can be done with it. This chapter is those three layers for C++, with the Java and Python equivalents in a line each. Syllabi list it as "C++ program structure, constructs and syntax, tokens, variables, data-types" or "character set and tokens, data type"; some add "static variables and constants".

The structure of a C++ program

A C++ source file is read top to bottom, so everything must be declared before it is used. The usual order: (1) a comment saying what the file does; (2) preprocessor directives such as #include <iostream>, which paste in the declarations of the input/output library (Chapter 1.7); (3) a namespace line, using namespace std;, or the prefix std:: on every library name; (4) global declarations: constants, global variables, function prototypes; (5) class definitions with their member functions; (6) main(), the entry point where execution starts, whose return 0; tells the operating system the run succeeded. Figure 1.3.1 labels a complete program; compiled with g++ circle.cpp -o circle and run with ./circle, it prints 12.5664.

In Java / In Python. A Java file holds a public class named like the file, with public static void main(String[] args) inside it, and import instead of #include. A Python file simply runs top to bottom; main exists only if you write if __name__ == "__main__":.

Character set and tokens

The character set is what may appear in a source file: letters, digits, special characters (+ - * / = < > ( ) { } [ ] ; , . # & | ! ' " \ _) and white space, which separates tokens and is otherwise ignored. The compiler groups characters into tokens of five kinds (examiners ask for this list):

  1. Keywords: reserved words with fixed meaning that cannot be used as names: int, class, return, if, while, new, public. All C++ keywords are lower case. Java reserves 50 keywords, Python 35.
  2. Identifiers: names you choose for variables, functions, classes. Rules: letters, digits and underscore only; must not start with a digit; case-sensitive (total and Total differ); never a keyword. roll_no, _tmp, Account2 are valid; 2fast, roll-no, class are not.
  3. Constants (literals): fixed values. Integer: 42, octal 052 (leading zero), hex 0x2A, binary 0b101010; floating: 3.14, 2.5e3 (= 2500.0), 3.14f for float; character: 'A' (stored as its code, 65), escapes '\n' newline, '\t' tab, '\0' null; string: "Hello", an array of char ending in '\0', so 6 bytes; boolean: true, false.
  4. Operators: + - * / % = == < > && ++ << -> :: and the rest of Chapter 1.4.
  5. Punctuators (separators): ; , ( ) { } [ ] #. Comments (// to end of line, /* block */) are not tokens; they are removed before compilation.

Data types and variables

A data type tells the compiler how many bytes a value occupies, how to read the bits and which operations are legal. Figure 1.3.2 is the classification every exam asks for: built-in (fundamental) types, derived types built from them (array, pointer, reference, function) and user-defined types (struct, union, enum, class, and names made with typedef or using). The modifiers signed, unsigned, short and long change the range of the integer types. The standard fixes only that char is 1 byte and that sizes never shrink along char ≤ short ≤ int ≤ long ≤ long long; the usual sizes on a 64-bit Linux compiler are:

A variable is a named piece of memory of one type. int count; declares it (a local then holds garbage); int count = 0; or int count{0}; initialises it. Its scope is where the name is visible: a local lives to the closing brace of its block, a global to the end of the file. const int MAX = 100; makes a value the compiler will not let you change. A static local (static int calls = 0; inside a function) is created once and keeps its value between calls. In Java the eight primitive types have fixed sizes everywhere (byte 1, short 2, int 4, long 8, float 4, double 8, char 2, boolean) and final replaces const. In Python a name has no declared type; it is bound to an object (int of unlimited size, float = a C double, str, bool) and type(x) tells you which.

Worked example

Question. (a) List the tokens in int total = count * 2 + 10; with their kinds. (b) A short occupies 2 bytes: derive its signed and unsigned ranges. (c) Predict the output of the program below on a 64-bit Linux compiler and explain the second line. (8 marks)

#include <iostream>
int main() {
    std::cout << sizeof(short) << ' ' << sizeof(int) << ' ' << sizeof(double) << '\n';
    unsigned short u = 70000;          // too big for 16 bits
    short s = 32767;  s = s + 1;       // one past the maximum
    std::cout << u << ' ' << s << ' ' << sizeof(3.14) << ' ' << sizeof('A') << '\n';
}

Solution. (a) Nine tokens: int keyword; total identifier; = operator; count identifier; * operator; 2 integer constant; + operator; 10 integer constant; ; punctuator. The spaces are not tokens.

(b) 2 bytes = 16 bits = 2¹⁶ = 65,536 different bit patterns. Unsigned: 0 to 65,535. Signed (two's complement, one bit for the sign): −2¹⁵ to 2¹⁵ − 1 = −32,768 to 32,767.

(c) First line: 2 4 8. Second line: u holds only 0 to 65,535, so 70,000 is stored modulo 65,536: 70,000 − 65,536 = 4,464. s + 1 is computed as an int, 32,768, and putting it back into a short wraps to −32,768 on every common compiler. 3.14 is a double literal, so sizeof gives 8; 'A' is a char in C++, so 1 (in C it would be an int, 4). Output: 4464 -32768 8 1.

Exam traps

  • 3.14 is a double; write 3.14f for a float. float f = 1.1; silently rounds a double to float.
  • "int is 4 bytes" is usual, not guaranteed; say "typically 4 bytes" and quote the guarantee (sizeof(char) == 1, non-shrinking order).
  • 'A' is a character constant worth 65; "A" is a string of two bytes, 'A' and '\0'. 010 is octal, worth 8. 1,000 is not a literal (the comma is an operator).
  • Identifiers: 2nd_max, roll-no and new are invalid; _count and Count are valid, and Count is not count.
  • The examiner's favourite: "Explain the structure of a C++ program with an example" (8 marks) wants the six labelled sections and a program that compiles; "What are tokens?" wants the five kinds with two examples each.

1.4 Operators, expressions and type conversion

An expression is anything that produces a value: 7, a + b, x > 0 && y != 0, acc.getBalance(). The compiler evaluates it by two rules: precedence decides which operator binds first, and associativity decides the order among operators of equal precedence. When the two sides of an operator have different types, the compiler silently converts one of them, and that is where "why does 1/3 print 0?" comes from. Every syllabus lists operators and type conversion; some ask you to "apply implicit and explicit type conversions in simple C++ programs".

Type conversion: implicit and explicit

Every operator wants both operands of the same type. When they differ, the compiler applies implicit (automatic) conversion in two steps. First integer promotion: anything smaller than int (char, short, bool) becomes int, which is why 'A' + 1 is the int 66. Then the usual arithmetic conversions climb a ladder: if either operand is long double the other becomes long double; else double; else float; else the integer of higher rank (long long over long over int), and at equal rank unsigned wins. So 10 / 3 is 3, 10 / 3.0 is 3.333, and −1 < 1u is false because −1 becomes the unsigned 4,294,967,295. On assignment the value is converted to the variable's type: int n = 3.99; stores 3 (truncation toward zero, not rounding) and char c = 321; keeps the low 8 bits, 65, that is 'A'.

Explicit conversion (a cast) is you ordering the change: C-style (double)x, functional double(x), or static_cast<double>(x), preferred in C++ because it is easy to search for and refuses dangerous conversions. A cast applies only to the operand it touches: (double)x / y converts x before the division and gives 3.333; (double)(x / y) divides the integers first and gives 3.0. Conversions to and from classes you write are operator overloading, Unit 4.

1.5 Control statements: decisions and loops

A program is a sequence of statements, but a useful program must choose and repeat. Selection statements (if, if–else, switch) pick one path out of several; iteration statements (while, do–while, for) run a block again and again while a condition holds; and jump statements (break, continue, return) leave early. Every program ever written needs only sequence, selection and iteration. The exam skill is tracing: given ten lines of code, writing down the value of every variable after every step and predicting the output. Some syllabi word it exactly so ("trace C++ programs using conditional statements and looping constructs"); others list "flow control and decision making statements" or "conditional statements, loops".

Selection: if, if–else ladder and switch

if (condition) statement; runs the statement when the condition is true (any non-zero value counts as true in C++). if … else … picks one of two; an else-if ladder picks one of many and is read top to bottom, so put the most specific test first. Braces { } group several statements into one block; without them only the next statement belongs to the if. In a nested if without braces, an else pairs with the nearest unmatched if (the "dangling else" rule). The conditional operator max = (a > b) ? a : b; is an if–else that yields a value.

switch (expr) compares an integer, character or enumeration value against constant case labels and jumps to the matching one; a default label catches the rest. Execution then falls through into the following cases until it meets a break, which is both a feature (several labels sharing one action) and the most common bug in the exam. A switch cannot test a floating-point value, a range, or a C++ string; use an if ladder for those. In Java switch also accepts String and enums, and the newer arrow form case 'A' -> … does not fall through. In Python there is if / elif / else, and since version 3.10 a match statement that never falls through.

Iteration: while, do–while, for

while (condition) body is entry-controlled: the condition is tested first, so the body may run zero times. do body while (condition); is exit-controlled: the body runs once before the first test, so it runs at least once; note the semicolon after the condition. for (init; condition; update) body packs a counted loop into one line: init runs once, then on each round the condition is tested, the body runs and the update runs. The three loops are interchangeable in power; choose for when you know the count, while when you do not, and do–while when the body must run first (a menu that is shown before it is read). break leaves the innermost loop or switch at once; continue skips to the next round (in a for the update still runs); goto label; exists but is avoided. C++11 added the range-based form for (int x : marks) that visits each element of an array or container. In Java the same four loops exist, the range form being for (int x : marks); in Python there are only while and for x in range(1, 11) (which stops before 11), no do–while, and a loop may carry an else that runs when it ends without break.

How to trace a program

  1. Write one column per variable and one row per statement that changes something; add a column for output.
  2. For a loop, write the condition test as its own row with the value true or false; the row where it turns false is where the loop ends.
  3. Apply integer arithmetic exactly as Chapter 1.4 says (1234 / 10 is 123, not 123.4).
  4. Only copy to the output column what a cout actually prints, with its spaces and newlines.

1.6 Pointers and dynamic memory with new and delete

Every variable lives at an address in memory, and a pointer is a variable that holds such an address. Pointers let a function change the caller's variables, let a loop walk an array by arithmetic, and, most important for this subject, let a program ask for memory while it runs: new takes memory from the heap and delete gives it back. Every object created at run time in Unit 2, every linked structure and every polymorphic call through a base-class pointer in Unit 4 depends on this chapter. Syllabi list "dynamic memory allocation with new and delete", "memory management" or "pointers and pointer arithmetic with arrays"; some place pointers in a later unit alongside run-time polymorphism, so you may meet this material again there.

You need: data types and sizeof from Chapter 1.3; arrays as in your first programming course.

Addresses, & and *

int n = 42; puts 42 in four bytes at some address, say 1000. int *p = &n; declares p as a pointer to int and stores that address in it: the address-of operator & asks "where is n?". *p, the dereference (indirection) operator, means "the int at the address in p", so *p = 50; changes n to 50 and cout << *p prints 50. The type matters: p is declared as a pointer to int so that the compiler knows four bytes belong together at that address. A pointer that points nowhere should hold nullptr (older code writes NULL or 0), and dereferencing it crashes the program instead of silently corrupting something. Every pointer, whatever it points to, is the same size, 8 bytes on a 64-bit machine. A reference, int &r = n;, is a second name for n that needs no *; it is how C++ passes arguments by reference ("pass by value / pass by reference" in some syllabi). For objects, Account *a = &acc; a->deposit(500); uses the arrow operator ->, short for (*a).deposit(500).

Pointer arithmetic and arrays

Adding 1 to a pointer moves it to the next element, not the next byte: for an int * the address grows by sizeof(int) = 4, for a double * by 8. An array name is the address of its first element, so int a[5]; int *p = a; makes p point at a[0], and a[i] is defined as *(a + i). Subtracting two pointers into the same array gives the number of elements between them; comparing them tells which comes first. A loop can therefore read an array as for (int *p = a; p < a + 5; p++) sum += *p;. Going outside the array is not an error the compiler can see; it is undefined behaviour, and the source of most security holes in C and C++.

The heap: new and delete

Local variables live on the stack: created when their block starts, destroyed when it ends, and their sizes must be known at compile time. When the size is known only at run time (how many students will be entered?) or the data must outlive the function that made it, the program allocates on the heap (free store). int *p = new int(5); allocates one int, initialises it to 5 and returns its address; int *marks = new int[n]; allocates n consecutive ints. The memory stays allocated until you free it: delete p; for a single object, delete[] marks; for an array. If memory runs out, new throws std::bad_alloc (Unit 5) rather than returning a null pointer the way C's malloc does; and unlike malloc, new runs the constructor of a class object (Unit 2), which is why C++ code uses new, not malloc.

Three bugs follow from manual freeing, and the examiner loves them. A memory leak: the pointer is lost (reassigned, or the function returns) before delete, so the block can never be freed. A dangling pointer: delete was done but the pointer still holds the old address and is used again. A double delete: the same block freed twice, which corrupts the heap. The habit that prevents the last two is delete p; p = nullptr;. In Java there are no pointers, only references; new exists, delete does not, because the garbage collector frees objects nobody refers to. In Python every name is a reference to an object, id(x) shows its address, and memory is reclaimed by reference counting; del x only removes the name.

1.7 Namespaces, preprocessor directives and stream manipulators

Three pieces of C++ housekeeping that every program uses and every paper asks about. A namespace is a named region of scope that keeps the names of one library from colliding with another's, which is why the standard library lives in std. The preprocessor is a text editor that runs over your file before the compiler sees it, obeying lines that start with #: pasting in headers, replacing macros, switching code on and off. Stream manipulators are the functions you push into cout to control widths, decimals and number bases. Some syllabi list only "namespace"; others list all three as "preprocessor directives, namespace, input/output streams and manipulators". Java and Python have the first and the third in other clothes and no preprocessor at all.

Namespaces and the scope resolution operator

Two libraries can both define a function called max or a class called List; if both are included, the compiler cannot tell which one you mean. A namespace fixes this by giving each library its own surname: namespace maths { int add(int a, int b) { return a + b; } } puts add inside maths, and the full name is maths::add, written with the scope resolution operator ::. The whole standard library (cout, string, vector) is in the namespace std, and there are three ways to reach it: write the full name every time, std::cout (safest, used in all serious code); bring in one name, using std::cout;; or bring in everything, using namespace std;, which is fine in a short program and a mistake in a header file, because it dumps hundreds of names on every file that includes it. Namespaces can be nested (std::chrono::seconds), reopened in several files, and left unnamed (an anonymous namespace makes names private to one file). :: has a second job: ::count reaches a global variable hidden by a local of the same name, and Unit 2 uses Account::deposit to define a member function outside its class. In Java a package does this job (java.util.Scanner, import java.util.*;); in Python a module does (import math; math.sqrt(2), from math import sqrt, and the discouraged from math import *, which is exactly using namespace).

Preprocessor directives

Figure 1.7.1 shows where the preprocessor sits: it rewrites the source text, and only the result reaches the compiler. Its directives: #include <iostream> pastes the named header in at that point (angle brackets search the system directories; "myfile.h" searches the current directory first). #define PI 3.14159 defines an object-like macro: every later token PI is replaced by the text 3.14159, with no type checking and no scope. #define SQR(x) ((x) * (x)) is a function-like macro, a textual template; the parentheses are essential (see the worked example). #undef removes a macro. Conditional compilation, #ifdef DEBUG … #endif, #if, #else, #ifndef, keeps or drops a block of code depending on a macro, which is how one source builds for several platforms, and how the include guard #ifndef ACCOUNT_H / #define ACCOUNT_H / … / #endif (or #pragma once) stops a header being pasted twice. Predefined macros such as __LINE__ and __FILE__ help error messages. In C++ a const or constexpr variable is preferred to a #define constant, and an inline function (Unit 2) to a function-like macro, because both are typed, scoped and visible to the debugger.

Stream manipulators

cout is an object (of class ostream) and << is its insertion operator; cin and >> are the input pair. A manipulator is a function inserted into the stream to change how the following items are formatted. From <iostream>: endl (newline plus flush), fixed and scientific, left and right, showpoint, boolalpha (print true instead of 1), hex, oct, dec. From <iomanip>, the ones that take an argument: setw(n) (minimum field width, applies to the next item only), setfill(c) (the padding character), setprecision(n). Precision is the trap: by default it counts significant digits (six of them, which is why 3.333333 printed as 3.33333 in Chapter 1.4), but after fixed it counts digits after the decimal point. Every setting except setw stays in force until changed. The same controls exist as member functions, cout.precision(2) and cout.width(8). Unit 6 covers the full stream classes and file I/O. In Java System.out.printf("%8.2f", price) does the job; in Python an f-string, f"{price:8.2f}".

Exam traps

  • setprecision(n) alone means n significant digits; with fixed it means n decimals. State which one you are using.
  • setw affects only the next item; setfill, fixed, setprecision, hex stay on. Students pad only the first column, or forget that hex is still on for the next number.

  • using namespace std; in a header file, and #include <iostream.h> (the pre-standard Turbo C++ form) are both marked wrong in current papers; write <iostream> with std::.
  • endl is '\n' plus a flush; in a loop printing a million lines it is noticeably slower. The examiner's favourite: "differentiate endl and \n" and "explain any five manipulators with output".

1.8 Modeling classes with UML diagrams

Before a design is typed into a compiler it is drawn, and the drawing language is UML, the Unified Modeling Language, a standard of the Object Management Group (current version 2.5.1). Its class diagram shows the static structure of a program: each class as a box with its attributes and operations, and the lines between boxes for association, aggregation, composition and inheritance. Its use-case diagram shows what the system does for whom. A class diagram is the fastest way to answer any "design a system for a library / bank / college" question, and some courses are named Object Oriented Design and Programming for this reason.

You need: the four principles of Chapter 1.2. Interfaces, aggregation and composition in code are Unit 3.

The class box

A class is a rectangle with three compartments: the name (singular, capitalised; in italics or marked {abstract} if the class cannot be instantiated), the attributes and the operations. An attribute is written visibility name: type [multiplicity] = default, for example − balance: double = 0. An operation is written visibility name(parameter: type, …): returnType, for example + withdraw(amt: double): bool. The visibility symbols are + public, − private, # protected and ~ package (Java only). A static member is underlined; an abstract operation is in italics. Each line maps directly to code, which is how the exam expects you to move from diagram to program:

Relationships between classes

Lines between boxes say how objects of the classes are connected, and each line ends with a multiplicity: 1 exactly one, 0..1 optional, * or 0..* any number, 1..* at least one. The multiplicity is written at the far end: "a Customer owns 1..* Accounts" puts 1..* next to Account.

  1. Association (plain line): objects know each other; a Customer owns Accounts. In code, a member that is a pointer, a reference or a collection. An arrowhead shows which side can navigate to the other.
  2. Aggregation (hollow diamond at the whole): a "has-a" where the parts can exist on their own; a Team has Players, and a Player survives when the Team is disbanded.
  3. Composition (filled diamond at the whole): a "has-a" where the parts die with the whole; an Account owns its Transactions, and deleting the account deletes them. In C++ this is usually a member object or an owned new-allocated part freed in the destructor (Unit 2).
  4. Generalization (solid line, hollow triangle at the base class): "is-a", inheritance; the arrow points from Savings to Account.
  5. Realization (dashed line, hollow triangle): a class implements an interface (Unit 3). Dependency (dashed arrow): a class merely uses another, for example as a parameter type.

Use-case and object diagrams

A use-case diagram is drawn before the class diagram to agree what the system must do. An actor (stick figure) is a role outside the system, human or another system; a use case (oval) is one goal the actor achieves; the system boundary is a rectangle around the use cases; lines join actors to the use cases they take part in. Two dashed arrows refine it: «include» when one use case always performs another (withdrawing always authenticates), and «extend» when one optionally adds to another (printing a receipt). An object diagram is a snapshot of a class diagram at one moment: boxes named acc1 : Account with actual values, as in Figure 1.1.1. The sequence, activity and state diagrams of UML belong to Software Engineering.

  1. Procedural programs organise code around functions acting on shared data; object-oriented programs organise it around objects that own their data. The difference shows when a program changes: in OOP the change stays inside one class.
  2. Abstraction is the interface a class shows; encapsulation is the packing of data with code and the access control that hides the data. Inheritance reuses a class (is-a); polymorphism lets one call behave differently per object, at compile time by overloading and at run time by virtual overriding.
  3. A C++ program is read as sections (directives, namespace, globals, classes, main) made of five kinds of tokens; every variable has a type whose size is typical, not guaranteed, except that char is one byte.
  4. Expressions are evaluated by precedence and associativity, and mixed types are converted up the ladder int → float → double; integer division truncates, and an out-of-range value wraps modulo 2ⁿ.
  5. while tests first, do–while tests last, for packs init, test and update together; a switch falls through until break. Tracing with a table of variables answers every "what is the output" question.
  6. A pointer holds an address and moves in units of the pointed-to type; new allocates on the heap and delete (or delete[]) must free it, or the memory leaks; a freed pointer must not be used again.
  7. Namespaces prevent name clashes (std::); the preprocessor edits text before compilation (#include, #define, #ifdef); manipulators format output, and setprecision means decimals only after fixed.
  8. A UML class diagram turns a design into boxes and lines you can code directly: attributes and operations with visibility, and association, aggregation, composition and generalization with multiplicities.
  9. Java and Python follow the same ideas with different syntax: no pointers, garbage collection instead of delete, packages and modules instead of namespaces, printf and f-strings instead of manipulators.

Glossary

Abstraction
Presenting only the essential features of an object (its interface) and hiding the implementation.
Access specifier
public, private or protected: who may use a class member.
Aggregation
UML has-a relationship (hollow diamond) in which the part can exist without the whole.
Association
UML line showing that objects of two classes know each other, with multiplicities at the ends.
Cast
An explicit type conversion: (double)x, double(x) or static_cast<double>(x).
Class
A user-defined type that describes the data and functions of its objects.
Composition
UML has-a relationship (filled diamond) in which the parts are created and destroyed with the whole.
Dangling pointer
A pointer that still holds the address of memory already freed.
Data hiding
Keeping data members private so that only the class's own functions can change them; the result of encapsulation.
Dereference
Using *p to reach the value at the address held in pointer p.
Encapsulation
Binding data and the functions that operate on it into one unit, the class, with controlled access.
Entry-controlled loop
A loop that tests its condition before each run of the body (while, for); do–while is exit-controlled.
Fall-through
In a switch, execution continuing into the next case because no break was met.
Heap (free store)
Memory allocated at run time with new and freed with delete; the stack holds automatic (local) variables.
Identifier
A name chosen by the programmer: letters, digits and underscore, not starting with a digit, not a keyword.
Include guard
#ifndef X / #define X / … / #endif around a header so it is pasted at most once.
Inheritance
Deriving a new class from an existing one, reusing and extending its members (is-a).
Keyword
A reserved word with a fixed meaning (int, class, return) that cannot be an identifier.
Macro
A name defined with #define that the preprocessor replaces by text before compilation.
Manipulator
A function inserted into a stream to change formatting: setw, setprecision, fixed, endl.
Memory leak
Heap memory whose address has been lost before it was freed, so it can never be reclaimed.
Message passing
Objects communicating by calling one another's member functions: acc.withdraw(500).
Multiplicity
UML count at the end of a line: 1, 0..1, *, 1..*.
Namespace
A named scope that keeps the names of one library from clashing with another's; std holds the standard library.
Object
An instance of a class: its own state (attributes), its behaviour (methods) and an identity.
Paradigm
A style of programming: procedural, object-oriented, functional, logic.
Pointer
A variable holding the address of another variable; declared with *, assigned with &.
Polymorphism
One name or call with many behaviours: overloading (compile time) and virtual overriding (run time).
Precedence
The rule deciding which operator in an expression is applied first; associativity breaks ties.
Token

Sources and further reading

  • E. Balagurusamy, Object Oriented Programming with C++, McGraw Hill Education: the textbook most Indian OOP syllabi are built from; its early chapters cover principles, tokens, expressions, control structures and pointers in the same order as this unit.
  • Bjarne Stroustrup, The C++ Programming Language, 4th edition, Addison-Wesley, 2013: the reference by the language's designer; the chapters on types, pointers, namespaces and the preprocessor.
  • Bjarne Stroustrup, Programming: Principles and Practice Using C++, Addison-Wesley: the gentler teaching book, with the same material plus its reasons.
  • Robert Lafore, Object-Oriented Programming in C++, 4th edition, Sams, 2001: the classic beginner's path from procedural C++ to classes.
  • Herbert Schildt, Java: The Complete Reference, McGraw Hill, for Java courses; Mark Lutz, Learning Python, O'Reilly, for Python courses.
  • Grady Booch, Robert Maksimchuk et al., Object-Oriented Analysis and Design with Applications, 3rd edition, Addison-Wesley, 2007, and Martin Fowler, UML Distilled, 3rd edition, Addison-Wesley, 2003: the design and UML background for Chapters 1.1, 1.2 and 1.8.
  • cppreference: C++ operator precedence: the full 17-level table behind Chapter 1.4.
  • cppreference: std::setprecision: the default precision of 6 and the digits printed for π at each precision (Chapter 1.7).
  • Object Management Group: UML specification: the current version, 2.5.1 (December 2017), and the history of versions (Chapter 1.8).
  • C++ Core Guidelines (ISO C++ Foundation): the rules on resource management and RAII that the "beyond" boxes point to; rule R.11, "Avoid calling new and delete explicitly", is cited by its title in the page's own index.
  • Sizes and ranges of the fundamental types, the usual arithmetic conversions and the behaviour of new on failure are standard C++ facts taken from the author's knowledge of the ISO C++ standard; sizes are quoted for a 64-bit Linux compiler and marked "typical".
  • Syllabi: the universal syllabus and a range of university course documents.
