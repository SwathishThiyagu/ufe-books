5.1 Attention mechanism and attention over images

Attention is a soft dictionary lookup. A query vector asks what we want; key vectors are labels to compare against; value vectors are the content to mix. Compare the query with every key, turn the scores into weights that sum to one, and return the weighted mix of the values. This lets a model look back at many inputs instead of squeezing them into one fixed vector. Translation, image captioning, speech recognition, document classification and chatbots use it.

You need Unit 4's encoder-decoder seq2seq and Unit 1's softmax and dot products; 5.2 builds self-attention from this.

The soft lookup: query, key, value

A query q is a vector that says what we want. Each key k_i is a vector that describes one item we can look at. Each value v_i is the vector we return for that item. The index i runs over N items. Keys and query must have the same length d_k so we can compare them; values can have another length d_v.

s_i = q·k_i = Σ_{j=1}^{d_k} q_j k_ij

q is the query vector; k_i is the i-th key vector; d_k is their length; q_j and k_ij are the j-th components; s_i is the match score.

The score measures match. For stability, scaled dot-product attention divides by √d_k: s_i = q·k_i / √d_k. Bahdanau additive attention uses a small network: s_i = w^T tanh(W_q q + W_k k_i), where W_q, W_k and w are learned. Luong dot attention uses s_i = q·k_i; Luong multiplicative attention uses s_i = q^T W k_i with a learned matrix W.

α_i = exp(s_i) / Σ_{j=1}^{N} exp(s_j)

α_i is the weight for key i; N is the number of keys; exp is e raised to the power; the denominator normalizes the weights to sum to 1.

c = Σ_{i=1}^{N} α_i v_i

c is the context vector; α_i is the weight; v_i is the i-th value vector.

  1. Score every key with the query.
  2. Apply softmax over the N scores to get weights that sum to 1.
  3. Return c = Σ α_i v_i, a weighted mix of values.

Attention in translation

An encoder-decoder translator reads a source sentence with an encoder RNN and writes a target sentence with a decoder RNN (see Unit 4). Without attention the encoder's last state must carry the whole source; long sentences lose detail. Attention removes this bottleneck.

At decoder step t, the decoder hidden state s_t is the query q. The encoder hidden states h_1, ..., h_T are keys and values. Score s_t with each h_i, softmax to α_{t,i}, and form context c_t = Σ_i α_{t,i} h_i. The decoder combines c_t with its previous output to predict the next word. At each step the weights change, so the decoder can look at the source word it needs now. When producing a noun it can put weight on the source noun and less on function words. The weights are recomputed per decoder step and are not learned parameters.

This is cross-attention: query from the decoder, keys and values from the encoder. Self-attention, where query, key and value come from the same sequence, is the next step; see 5.2.

Attention over images and hierarchy

A CNN turns an image into a grid of feature vectors. A 7×7 grid from the last convolutional layer gives 49 vectors, one per region (see Unit 3). Flatten the grid to h_1, ..., h_N with N = 49; each h_i is a key and a value. A caption decoder produces words one at a time. At word t its state q_t is the query. Scores q_t·h_i, softmax over regions gives α_{t,i}, and c_t = Σ α_{t,i} h_i. The decoder can focus on the region with the cat when it writes 'cat'.

Soft attention uses all regions through the weighted average; it is differentiable, so normal backpropagation trains it. Hard attention samples one region index z from the distribution α_t and uses c_t = h_z. Sampling is not differentiable, so training uses reinforcement: treat the sampled region as an action and use the caption score as reward, often with a baseline to reduce variance.

Hierarchical attention stacks two levels. For a document, word attention inside each sentence mixes word states into a sentence vector using a learned word-level query. Sentence attention then mixes sentence vectors into a document vector using a learned sentence-level query. This lets a classifier point to important sentences and, inside them, important words. Some syllabi call this whole topic Attention Models.

Worked example

Question. A decoder state q = [1, 0] attends over three encoder states using unscaled dot-product scores. The keys are k1 = [1, 0], k2 = [0, 1], k3 = [1, 1]; the values are v1 = [10, 0], v2 = [0, 10], v3 = [5, 5]. Find the three scores, the softmax weights to 3 decimals, and the context vector to 3 decimals. Use e ≈ 2.718.

  1. Scores: q·k1 = 1×1 + 0×0 = 1; q·k2 = 1×0 + 0×1 = 0; q·k3 = 1×1 + 0×1 = 1. Because the scores are unscaled, we do not divide by √2.
  2. Exponentials: e^1 = 2.718, e^0 = 1, e^1 = 2.718. Sum = 2.718 + 1 + 2.718 = 6.436.
  3. Weights: α1 = 2.718 / 6.436 = 0.422; α2 = 1 / 6.436 = 0.155; α3 = 2.718 / 6.436 = 0.422. They sum to 0.999, which is 1 within rounding.
  4. Context: c1 = 0.4223188×10 + 0.1553634×0 + 0.4223188×5 = 6.3348 → 6.335. c2 = 0.4223188×0 + 0.1553634×10 + 0.4223188×5 = 3.6652 → 3.665.

Answer. The weights are 0.422, 0.155 and 0.422, and the context is c = [6.335, 3.665]; the first and third encoder states tie and together supply most of the context.

Exam traps

  • Attention weights are computed from q and k at run time; they are not learned parameters. They always sum to 1 across the keys, and a weight changes when the query changes.
  • Use a weighted sum, not a plain average, of the values. The weights come from softmax scores, and the value vectors can have a different length from the keys.
  • For scaled dot-product attention divide scores by √d_k, where d_k is the key and query length, before softmax. Forgetting the scale makes large scores and nearly one-hot weights.
  • Soft attention is differentiable and trained by backpropagation; hard attention samples one region, so it is trained by reinforcement or a relaxed estimator.
  • In encoder-decoder attention the decoder state is the query, while encoder states are keys and values; in self-attention all three come from the same sequence.

5.2 Self-attention and the Transformer architecture

Self-attention lets every position in a sequence look at every other position and build a new vector from what it finds. A Transformer block wraps this idea with several attention heads, positional encodings, residual connections, layer normalization and a small feed-forward network. Recurrence is gone, so training can run in parallel and long-range links are one matrix multiply away. Translation systems, BERT, GPT and many vision models use this block. The next sections build it from one matrix of token vectors.

You need: 5.1 for queries, keys, values and softmax weights; Unit 4 for encoder-decoder sequence models; Unit 1 for softmax; Unit 2 for normalization.

From one sequence to queries, keys and values

Take a sequence of n tokens. Each token is already a vector of length d_model, so the sequence is a matrix X with n rows and d_model columns. Self-attention does not use a separate input and output sequence: all three views come from X. Learn three weight matrices W_Q, W_K and W_V, each of size d_model × d_k. Then Q = XW_Q, K = XW_K and V = XW_V. Q holds queries, K holds keys and V holds values. Row i of Q is the query for token i.

Attention(Q, K, V) = softmax(QKᵀ / √d_k) V

Q is the n×d_k query matrix; K is the n×d_k key matrix; V is the n×d_v value matrix; QKᵀ is the n×n score matrix whose entry (i,j) is the dot product q_i·k_j; d_k is the key width; softmax is applied to each row; the output has n rows and d_v columns.

The score s_ij measures how much token i reads from token j. A dot product of d_k entries with variance 1 has variance d_k. Large scores make the softmax nearly one-hot; gradients through it become tiny. Dividing by √d_k brings the variance back to about 1. Each softmax row sums to 1, so each output row is a weighted mix of all value rows. QKᵀ costs n²d_k operations and mixing values costs n²d_v; with d ≈ d_k ≈ d_v the total is O(n²d) time and memory.

Several heads and a sense of position

One attention pattern is not enough. Multi-head attention runs h attention operations in parallel. Head i has its own W_Q^i, W_K^i and W_V^i, and width d_k = d_model/h. Concatenate the h outputs along features to get n×d_model, then multiply by W_O, a d_model×d_model matrix, to mix heads. The total width stays d_model: the model splits width across heads, it does not multiply it. With d_model = 768 and h = 8, d_k = 96.

head_i = Attention(XW_Q^i, XW_K^i, XW_V^i),   MultiHead(X) = Concat(head_1, …, head_h) W_O

X is the n×d_model input; W_Q^i, W_K^i, W_V^i are head-specific weights; h is the number of heads; d_k = d_model/h is each head's width; Concat joins along features; W_O mixes the concatenated heads back to d_model.

Attention alone is permutation equivariant: shuffle the tokens and each output shuffles the same way. Word order would vanish. Positional encoding adds a vector p_pos to the embedding at position pos. For dimension index i from 0 to d_model−1:

PE(pos, 2i) = sin(pos / 10000^(2i/d_model)),   PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))

pos is the token position starting at 0; i indexes pairs of dimensions; d_model is the embedding width; 2i and 2i+1 are even and odd feature indices; the denominator gives wavelengths from 2π to 10000·2π.

The encoding is added to the embedding, not concatenated. Different dimensions oscillate at different rates, so the pattern carries a unique position signature.

Encoder block, decoder block and cost

An encoder block has two sublayers. First is multi-head self-attention over the input sequence. Second is a feed-forward network applied to each position separately: two linear layers with a ReLU between, expanding d_model to d_ff and back. A common choice is d_ff = 4×d_model, so 768 → 3072 → 768.

  1. Run multi-head self-attention on X.
  2. Add the input and apply layer norm: x = LayerNorm(x + attention(x)).
  3. Run the feed-forward network on each row.
  4. Add the previous x and apply layer norm again: y = LayerNorm(x + feed_forward(x)).

The x + ... terms are residual connections; they give gradients a short path. Layer norm normalizes each token vector across its features. A decoder block has three sublayers.

  1. Masked multi-head self-attention on the tokens produced so far. Before softmax, set every score with key position j > query position i to −∞, so its weight becomes 0.
  2. Cross-attention: Q comes from the decoder, K and V come from the encoder output, so each output token reads the whole input sentence.
  3. Feed-forward network, with add-and-norm around each sublayer.

The original design stacks six encoder and six decoder blocks. Self-attention builds an n×n score matrix, so time and memory are O(n²d). Doubling n quadruples that matrix; long context is expensive. Some syllabi list Spatial Transformers in this unit. That is a different vision module: it learns a small warp of an image grid before a CNN, not a sequence attention block.

Worked example

Question. Two tokens have vectors x₁ = [1, 0] and x₂ = [0, 1]. Use W_Q = W_K = W_V = I, where I is the 2×2 identity, and d_k = 2. Compute the scaled dot-product attention output for both tokens. Also compute the first row when the √d_k scaling is removed.

  1. X = [[1,0],[0,1]]. With identity weights, Q = K = V = X.
  2. Before scaling, QKᵀ = [[1,0],[0,1]]: self dot-products are 1, cross dot-products are 0.
  3. d_k = 2, so √d_k = 1.4142. Scaled scores: [[0.7071,0],[0,0.7071]].
  4. Row 1 softmax: exp(0.7071)=2.0281, exp(0)=1, sum=3.0281; weights [0.6698,0.3302].
  5. Row 2 softmax: [0.3302,0.6698].
  6. Output row 1 = 0.6698[1,0] + 0.3302[0,1] = [0.6698,0.3302]; row 2 = [0.3302,0.6698].
  7. Without scaling, row 1 scores [1,0]: exp(1)=2.7183, exp(0)=1, sum=3.7183; weights [0.7311,0.2689].

Answer. Scaled attention rows are [0.6698, 0.3302] and [0.3302, 0.6698]; without √d_k the first row is [0.7311, 0.2689].

Exam traps

  • Positional encodings are added to token embeddings, not concatenated. Concatenation changes the width and costs extra parameters.
  • In a decoder, the mask is applied to the scores before softmax. Setting future scores to −∞ makes their softmax weight exactly 0; zeroing after softmax breaks the sum-to-1 property.
  • Multi-head attention splits d_model across heads: d_k = d_model/h. The concatenated output width is still d_model, not h×d_model.
  • Scale by √d_k, not by d_k. The scores are not probabilities; softmax comes after scaling.
  • Cross-attention takes Q from the decoder but K and V from the encoder. Spatial Transformers are a vision warping module, not this attention block.

5.3 Pretrained language models: BERT and GPT

A pretrained language model is a Transformer that has already learned language from a large pile of unlabelled text, so you can reuse its weights on your own small labelled dataset. Labelling ten thousand sentences by hand can cost lakhs; raw text is free. BERT reads a sentence in both directions and fills in blanks. GPT reads left to right and predicts the next token. Both sit inside modern search, tagging, translation and chatbots.

You need: 5.2 for the Transformer block, Unit 4 for language modelling and word embeddings, and Unit 1 for cross-entropy.

Pretraining is self-supervised

A supervised model needs a label for every input. Text already carries its own label: hide part of a sentence and ask the model to recover it. This is self-supervised learning, and it is the whole reason pretraining exists — billions of web pages can be used without paying a single annotator.

The result is a set of weights that encodes general language: grammar, word senses, common facts. You then reuse it in one of two ways.

  • Fine-tuning: add a small task head and update every weight on your labelled data. A few thousand examples are often enough.
  • Feature extraction: freeze the pretrained weights and train only the head. Cheaper, usually a little weaker, and the right choice when your dataset is tiny.

The fine-tuning recipe is three steps.

  1. Load the pretrained checkpoint and attach a task head.
  2. Train with a small learning rate, roughly 2e-5 to 5e-5, for three or four epochs.
  3. Evaluate on the task benchmark, for example the GLUE suite of sentence-level tasks (acceptability, sentiment, inference, paraphrase, similarity).

BERT: masked language modelling

BERT means Bidirectional Encoder Representations from Transformers. It is an encoder-only stack, built as in 5.2 but with no causal mask, so every position sees both its left and right context at the same time.

  1. Pick 15% of the tokens at random.
  2. Replace 80% of those with [MASK], 10% with a random vocabulary token, and leave 10% unchanged.
  3. Predict the original token at every chosen position with a softmax over the vocabulary.
  4. Compute cross-entropy only at the chosen positions; the untouched 85% adds nothing to the loss.

L_MLM = −(1/|M|) × Σ log p(xᵢ | x̃)

M is the set of chosen positions, xᵢ is the true token there, x̃ is the corrupted sentence, and p is the model's softmax probability for that token.

The 80/10/10 split matters. If every chosen token became [MASK], the model would never see the symbol [MASK] during fine-tuning, and the random 10% forces it to distrust the input token rather than copy it. Two special tokens complete the input: [CLS] sits first and its final state is the whole-sentence vector used for classification, while [SEP] marks where one segment ends and the next begins. The original paper also trained next sentence prediction, asking whether segment B follows A; later work showed it adds little, and RoBERTa dropped it.

BERT-base has 12 layers, hidden size 768, 12 heads and about 110 million parameters. BERT-large has 24 layers, 1024 hidden, 16 heads and about 340 million.

GPT, the other families, and metrics

GPT is decoder-only. A causal mask lets position i attend only to positions up to i, so the model computes p(token t+1 | tokens 1…t) and nothing more. Every token in the corpus is therefore a training example, far denser than BERT's 15%. The family grew fast: GPT-1 had about 117 million parameters, GPT-2 about 1.5 billion, GPT-3 about 175 billion. Scaling that run is 5.4.

PPL = exp(L)

L is the mean cross-entropy loss in nats per token, so perplexity is the number of equally likely tokens the model is effectively choosing among. Lower is better; 1 would be perfect certainty. If your loss is in bits, use PPL = 2^L instead; both forms give the same number.

Encoder-decoder models such as T5 and BART use both halves: an encoder reads the input bidirectionally and a decoder writes the output left to right. They suit translation and summarisation, where input and output are different sequences. NVIDIA NeMo is a toolkit for building and fine-tuning these models — it is not a model family.

Where you attach the task head depends on the family. For a classifier on an encoder, attach a head to the [CLS] state; on a decoder-only model, attach it to the state at the final position. For tagging or question answering, attach heads to the token states. Fine-tuning updates all weights; prompting changes none of them and belongs to 5.6.

Worked example

Question. (a) A BERT masked-LM head reads 'the cat sat on the [MASK]'. It gives P(mat) = 0.5, P(floor) = 0.2, P(dog) = 0.1, and 0.2 spread over all remaining words. Find the cross-entropy loss at this position in nats and in bits. (b) A small GPT scores the three true tokens of a sequence with probabilities 0.5, 0.25 and 0.125. Find its perplexity on that sequence.

  1. (a) The true token is mat, predicted with probability 0.5.
  2. Loss = −ln p = −ln 0.5 = 0.6931 nats.
  3. Convert to bits: 0.6931 ÷ ln 2 = 0.6931 ÷ 0.6931 = 1.0 bit.
  4. (b) Multiply the three probabilities: 0.5 × 0.25 × 0.125 = 0.015625 = 1/64.
  5. Take the geometric mean: (1/64)^(1/3) = 1/4 = 0.25.
  6. Perplexity = 1 ÷ 0.25 = 4.0, so the model is as unsure as choosing among 4 equally likely tokens.

Answer. The masked-LM loss is 0.6931 nats, which is 1.0 bit; the GPT's perplexity is 4.0.

Exam traps

  • BERT cannot generate text: its masked objective needs the whole sentence at once, so there is no left-to-right order to sample from.
  • 15% is the fraction of tokens chosen, and only 80% of those become [MASK], so the real mask rate is 12% of all tokens.
  • Few-shot examples in a prompt change no weights. Prompting is inference; only gradient steps update parameters.
  • Perplexity must match the log base of the loss: PPL = exp(L) when L is in nats, and PPL = 2^L when L is in bits. The two give the same number. Mixing them — exp of a bit-loss, or 2^L of a nat-loss — gives a wrong value.
  • NVIDIA NeMo is a toolkit for building and fine-tuning models, not a model family like BERT or GPT.

5.4 Large language models: training, scaling and fine-tuning

A large language model is a decoder-only Transformer trained to predict the next token on a very large text corpus. Training is planned, not guessed: compute is about 6ND FLOPs for N parameters and D tokens, and loss falls as a power law as parameters, data and compute grow. After pretraining, fine-tuning adapts the model to instructions or a domain. The same ideas run search engines, code assistants and UPI help desks that answer in Indian languages. This chapter shows the pipeline, the scaling arithmetic and the fine-tuning choices.

You need: 5.3 for pretraining and fine-tuning, 5.2 for the Transformer block, and Unit 2 for Adam and learning-rate schedules.

Pretraining pipeline and the 6ND estimate

Pretraining starts with text: web pages, books, code and conversation logs. The raw text is cleaned, quality-filtered and deduplicated. Duplicates waste compute and push the model to memorise repeated sentences. A byte-pair encoding tokenizer is trained on a sample. It starts from bytes and repeatedly merges the most frequent adjacent pair into one token. Common words become single tokens; rare words split into pieces.

The model is a decoder-only Transformer (see 5.2). It reads tokens and outputs a score for every vocabulary token at every position. The loss is mean next-token cross-entropy:

L = −(1/T) Σ log p(x<sub>t</sub> | x<sub>1</sub>, …, x<sub>t−1</sub>)

L is mean cross-entropy per token; T is the number of predicted tokens; xt is the actual token at position t; p is the model's probability for that token given the earlier tokens. Lower L is better.

Training uses AdamW, warmup then cosine decay, mixed precision and gradient clipping (Unit 2). AdamW is Adam with decoupled weight decay. Warmup raises the learning rate from near zero; cosine decay lowers it smoothly. Mixed precision keeps some tensors in 16-bit to save memory and time. Clipping caps the gradient norm so one bad batch cannot blow up the weights.

Plan compute before booking GPUs.

C ≈ 6ND

C is training compute in FLOPs; N is the number of parameters; D is the number of training tokens. The factor 6 is about 2 FLOPs per parameter per token in the forward pass plus 4 in the backward pass.

Scaling laws and compute-optimal planning

Loss falls as a power law as scale grows. A power law has the form L = a + bN^−α. Here L is test loss, N is parameters, a is the irreducible loss, b sets the size of the reducible part, and α is the exponent. Kaplan and co-workers reported exponents near −0.076 for parameters and −0.095 for data. The exact numbers depend on the data and architecture; the shape is the point. A curve fitted to early runs predicts later runs within a factor.

The figure plots L = 2.0 + 1.2C^−0.25, where C is relative compute. Loss drops fast at first and then flattens. At C = 16, L = 2.6. This flattening is why a bigger model gives diminishing returns per rupee after a point.

For a fixed compute budget, split it between N and D. Chinchilla found a compute-optimal ratio near 20 tokens per parameter: D ≈ 20N. A model trained far below this ratio is undertrained; far above it with a fixed small model gives diminishing returns. Some abilities, such as multi-step arithmetic or reading a table, appear only past a certain scale. Do not assume a small model has the same ability at lower loss.

Fine-tuning and evaluation

Full fine-tuning starts from pretrained weights and updates every parameter on a labelled or instruction dataset. It works well but stores a full copy and optimizer state per task. Instruction tuning uses question-answer pairs, for example, explain UPI in two lines, so the model learns to follow formats and requests; it does not add much new factual knowledge.

Parameter-efficient fine-tuning trains a small number of new weights and freezes W. Adapters insert small bottleneck layers. Prefix tuning learns virtual key-value vectors prepended to attention. LoRA adds a low-rank update:

W′ = W + BA

W′ is the adapted weight; W is the frozen d×k weight; B is a d×r matrix; A is an r×k matrix; r ≪ min(d,k) is the rank. Only B and A are trained. At inference you may merge W + BA, keeping the original shape.

Domain adaptation continues pretraining or fine-tuning on in-domain text such as medical notes, legal contracts or code. It shifts vocabulary and style. Evaluation uses held-out loss, perplexity = exp(L), task benchmarks and human review. Perplexity is comparable only with the same tokenizer. Benchmarks catch task accuracy; human review catches tone, safety and fluent nonsense.

Worked example

Question. A 1B-parameter decoder-only Transformer is pretrained on 20B tokens, the Chinchilla ratio of 20 tokens per parameter. (a) Estimate training compute with C ≈ 6ND. Exam traps

  • 6ND is a dense training estimate. Inference cost scales with generated tokens and can be larger over a product's life.

  • Perplexity is exp(loss), not loss as a percentage; lower is better, and it is comparable only with the same tokenizer.
  • LoRA trains BA, not W. At inference you may merge W + BA, so the deployed layer has the original shape and speed.

5.5 Reinforcement learning from human feedback (RLHF)

Reinforcement learning from human feedback (RLHF) turns a text predictor into an assistant that answers the way people prefer. Humans cannot state a score reliably, but they can say which of two answers is better. RLHF collects such comparisons, trains a reward model to imitate them, then tunes the language model with reinforcement learning to earn a high reward, held on a short leash so it cannot drift into nonsense. Chat assistants are built this way. Only a few universities teach it.

You need: 5.3 for pretraining, 5.4 for fine-tuning, and the policy-gradient idea and optimizers from Unit 2.

Stage 1: supervised fine-tuning (SFT)

A pretrained model only continues text (see 5.3); ask it a question and it may reply with another question. Stage 1 collects demonstrations: a human writes a good answer to each prompt, and the model is fine-tuned on those prompt–answer pairs with the next-token loss of 5.4. The result is the SFT model, written π_ref, and it is frozen after this. RLHF reshapes which answers the model prefers; it adds no new facts and no grammar.

Stage 2: a reward model from pairwise preferences

Writing a good answer takes minutes; judging two answers takes seconds. So for each prompt x, sample two answers from π_ref and have a human mark the chosen one y_w (won) and the rejected one y_l (lost).

The reward model r(x, y) is a copy of the SFT model whose head outputs one number instead of a word distribution. The Bradley–Terry model turns a score gap into a preference probability:

P(y_w ≻ y_l | x) = σ(r(x, y_w) − r(x, y_l)),   σ(z) = 1 / (1 + e^(−z))

y_w is the preferred answer and y_l the rejected one; r(x, y) is the scalar reward for prompt x and answer y; σ is the sigmoid; ≻ reads "is preferred to".

Training minimises the negative log of that probability over all comparison pairs:

L = −log σ(r(x, y_w) − r(x, y_l))

L is the loss for one pair, in nats because the log is natural; it is small when the chosen answer scores far above the rejected one, and large when the scores are close or reversed.

Only the gap enters, so the reward is fixed only up to a constant shift. That is why pairwise labels beat absolute 1–10 ratings: two people rarely agree on a number, but they usually agree on which answer is better.

Stage 3: PPO with a KL leash

The SFT model now becomes a policy π that generates an answer y for a prompt x, and the reward model scores it. The objective is

max E_{y~π(·|x)}[ r(x, y) ] − β · KL(π(·|x) ‖ π_ref(·|x))

E[·] is the average reward over sampled answers; β ≥ 0 is the penalty weight; KL is the Kullback–Leibler divergence, a non-negative number measuring how far the policy's token probabilities have moved from the frozen reference model π_ref.

The first term pulls the model towards answers the reward model likes. The second term is a leash. r is a learned proxy, not a human, so a free search finds rubbish that scores high — reward hacking. The KL term is summed over tokens, so drifting on every token costs a lot and the policy stays near fluent text.

The optimiser is proximal policy optimisation (PPO), a policy-gradient method from Unit 2. Two parts are named, not derived here: the clipped objective, which caps how far one update can move the probability of an action, and the value head, a critic that predicts the expected reward and supplies the baseline in the advantage.

  • Reward-model bias: annotators favour confident, formal answers, so the model learns their taste, not correctness.
  • Length bias: longer answers win comparisons, so the model pads.
  • Over-optimisation: reward keeps climbing while real quality peaks and falls.

Direct preference optimisation (DPO) is a cheaper alternative: it fits the same preference pairs with one supervised-style loss, with no separate reward model and no RL loop.

Worked example

Question. A reward model scores response A at 2.0 and response B at 1.0 for the same prompt, and humans preferred A. (a) Find the Bradley–Terry probability that A beats B and the loss for this pair. (b) In a PPO step a sampled response earns reward 2.0 and sits at KL divergence 0.5 from the reference model, with β = 0.1. Find the objective value.

  1. Score gap: d = r(x, y_w) − r(x, y_l) = 2.0 − 1.0 = 1.0 reward units.
  2. Probability: e^(−1.0) = 0.3679, so 1 + e^(−1.0) = 1.3679 and P = 1 / 1.3679 = 0.731.
  3. Loss: L = −ln(0.731) = 0.313 nats.
  4. Penalty: β × KL = 0.1 × 0.5 = 0.05.
  5. Objective: 2.0 − 0.05 = 1.95.

0.313
1.95

Exam traps

  • The reward model is a learned proxy, not human judgement, so the KL term is never optional; drop β and you get reward hacking, not alignment.
  • RLHF is not fine-tuning on human-written answers. That is only stage 1; stages 2 and 3 are preferences and reinforcement learning.
  • Bradley–Terry uses the score difference. Adding 5 to both rewards changes nothing; only the gap matters.
  • β is the KL weight, not a learning rate. A larger β means a tighter leash: less drift, but also a smaller reward gain.
  • The loss uses natural log, so the answer is in nats. A base-10 log gives 0.136 where the correct value is 0.313.

5.6 Prompt engineering and chatbots

A large language model's weights do not change when you use it. The only lever you hold is the text you send, the prompt. Prompt engineering is the craft of writing that text so the model does the right task, in the right format, with the right examples. A chatbot packages this: a system message, a growing conversation history and one API call, wrapped in an app. Chatbots answer customers in bank apps, sort help-desk tickets and clear study doubts.

You need: 5.3 and 5.4 for what the model learns, and softmax from Unit 1 for the sampling maths.

Prompt design: instruction, role, format

A prompt has four parts: the task instruction, the data it must work on, optional examples, and the output format. Keeping them separate makes the prompt readable and the answer predictable.

The system message (system prompt) fixes the role and the rules: You are a billing assistant for a phone company. Answer only from the plan table below. The model stores no memory between API calls, so the system message is resent with every turn.

Wrap the data in clear delimiters: triple quotes, a line of ###, or tags such as <review> ... </review>. Delimiters mark where data stops and instruction starts, and they blunt prompt injection, where a user pastes 'ignore all previous instructions' inside the data.

State the output format exactly. Reply with JSON: {"refund": true, "reason": "..."} lets a program parse the reply without guessing.

For a long task, write the steps as a numbered procedure inside the prompt, or call the model once per step.

Zero-shot, one-shot and in-context learning

  • Zero-shot: the instruction alone, no examples.
  • One-shot: one solved example placed before the real input.
  • Few-shot: a handful of solved examples, usually three to five, in the same format you want back.

This is called in-context learning. The examples sit in the context window, so the model conditions on them when predicting the next token. No weight changes, no gradient step, nothing is stored.

Chain-of-thought prompting asks the model to show its working: give the steps, then the final line. Each step is generated as ordinary tokens, which then condition the next step; a single forward pass cannot carry a partial sum, but a written one can be read by the next pass. This helps multi-step arithmetic, unit conversion and logic puzzles. It wastes tokens on simple lookups.

Examples and working cost tokens and money: a prompt four times longer costs about four times more per call.

Sampling: temperature and top-p

The model ends with one logit z for each token in its vocabulary. Softmax turns the logits into a probability distribution over the next token. Pure greedy decoding always picks the largest logit.

pᵢ = exp(zᵢ / T) ÷ Σⱼ exp(zⱼ / T)

pᵢ is the probability of token i; zᵢ is its logit; T is the temperature, a positive number; the sum runs over the whole vocabulary. T = 1 is the plain softmax.

Temperature rescales the logits before the softmax. T below 1 divides the logits by a small number, so gaps widen and the distribution sharpens; T above 1 flattens it. As T → 0 the distribution becomes a spike on the top token, greedy decoding.

Top-p (nucleus) sampling sorts the tokens by probability, keeps the smallest set whose probabilities add to at least p, discards the rest, and renormalises the kept probabilities to 1. Top-k is the fixed-size cousin: keep exactly k tokens. Use T near 0 for extraction and code, and T near 0.7–1.0 with top-p near 0.9 for free writing.

The chatbot stack and the context window

A chatbot has five layers: the user interface, a backend that holds the conversation, the prompt assembly step, the model API called with a secret key, and response rendering. Prompt assembly concatenates the system message, examples, stored history and the new question into one string.

All of that shares one context window, a hard limit in tokens. The budget is system message + examples + history + the reply: a chat that fits on turn one overflows on turn twenty.

Two fixes: truncate (keep the system message, the last few turns, and drop the middle) or summarise (replace old turns with a short recap written by the model). Both lose detail. Add a line to the system message telling the model that older turns may be missing, so it asks again instead of inventing an answer.

Retrieval-augmented generation (RAG) is one line of this stack: search a document store for text matching the question, paste the top passages into the prompt as delimiters, and ask the model to answer only from them. It supplies facts the model never learned.

Tools some syllabi name: the OpenAI API for hosted models, LangChain for chaining prompts and memory, Ollama for running open models locally, and no-code builders such as Botsonic and Chatbase.

Exam traps

  • Few-shot examples do not train the model. Nothing is stored; they only fill the context. Remove them and the behaviour reverts.
  • Count the reply inside the context window: budget = system message + examples + history + reply.
  • Instructions alone cannot supply a fact. If a fact is in neither the weights nor the prompt text, no wording can produce it; instructions such as 'do not hallucinate' reduce confabulation but never remove it. Pasting the fact into the context (RAG) does work: the fact is then in the prompt.
  • Top-p is not top-k. Top-p keeps a variable number of tokens; top-k keeps a fixed number.
  • Temperature scales the logits before the softmax, not the probabilities after it. For any T > 0 the ranking of tokens is unchanged.

5.7 Model compression: distillation, quantization and pruning

Big models predict well but cost memory, battery and latency. Compression keeps most of the accuracy in a much smaller package. Three standard routes are distillation (a small student model learns from a large teacher), quantization (weights and activations use fewer bits, usually INT8 instead of FP32) and pruning (small or structured weights are removed). You meet this when a phone runs a speech recogniser offline, when a startup serves a language model on one GPU, or when a booking site must answer many users cheaply.

You need: 5.3 and 5.4 for model structure and size, and Unit 2 for regularization and fine-tuning.

Distillation: soft targets at a temperature

Distillation trains a small student to imitate a large teacher. The teacher's softmax gives a probability for every class, not just the true label. A picture of a cat may get 0.80 cat, 0.15 dog and 0.05 fox, which tells the student that cat and dog are similar. A one-hot label hides that information.

L = α·CE(y, p_s) + (1 − α)·T²·KL(p_t^T ‖ p_s^T)

L is the student loss; y is the true one-hot label; p_s is the student's normal softmax output; p_t^T = softmax(z_t/T) and p_s^T = softmax(z_s/T) are softened outputs from teacher logits z_t and student logits z_s; T > 0 is the temperature; α in [0,1] weights the two terms; CE is cross-entropy; KL is Kullback–Leibler divergence.

Temperature T > 1 softens the distribution: rare classes get visible probability. The T² factor keeps the gradient scale similar when T changes. α balances the hard-label loss and the imitation loss. Use T = 1 and the student alone at inference.

  1. Train or obtain the teacher.
  2. Run each training input through the teacher at temperature T and keep the soft outputs.
  3. Train the student on the same inputs with the combined loss L.
  4. Set T = 1 and deploy only the student.

Distillation is common when a large BERT-style encoder must become a small encoder for a phone, or when a large chat model must become a smaller chat model.

Quantization: FP32 to INT8

Quantization maps real numbers to low-precision integers. A weight x is stored as an integer code q, and the model computes with q. The scale s and zero point z are chosen so the important range fits.

q = clamp(round(x/s) + z, q_min, q_max),   x̂ = s(q − z)

x is the real value; q is the stored integer code; s is the scale (real units per integer step); z is the integer zero point; q_min and q_max are the integer limits, for example −127 and 127 for symmetric INT8; x̂ is the dequantized value.

Clamp keeps q inside the chosen integer range. For symmetric INT8, z = 0 and q lies in [−127, 127]. For asymmetric, z maps real zero to an integer, so zero padding stays zero.

FP16 and BF16 are the easy middle step: half the memory of FP32, little accuracy loss. INT8 cuts memory four times and often speeds inference. Post-training quantization (PTQ) calibrates s and z on a small sample and needs no retraining. Quantization-aware training (QAT) simulates rounding during training and usually gives better accuracy. Use per-channel scales for convolution and linear layers when one channel has an outlier.

For a tensor, per-tensor uses one s and z for all values; per-channel uses one pair per output channel. A single outlier weight can stretch a per-tensor scale and crush small values into zero.

Pruning: remove weights, then fine-tune

Pruning removes weights. Magnitude pruning deletes weights with |w| below a threshold. Unstructured pruning gives a sparse matrix; it saves memory but ordinary hardware rarely speeds up because the nonzeros are irregular. Structured pruning removes whole channels, filters or attention heads; the result is a dense smaller model that runs fast on ordinary GPUs and phones.

Prune iteratively: train, remove a small fraction, fine-tune, repeat. Fine-tuning after each round recovers accuracy. The lottery-ticket idea says a sparse subnetwork found early can sometimes retrain to full accuracy; treat it as a research guide, not a deployment promise.

Deployment is the end point. Export the compressed model to TFLite for mobile or ONNX Runtime for servers, then check accuracy and latency on the target device. A common pipeline uses all three routes: distill a large teacher, quantize the student, prune structured blocks, and fine-tune once more.

  5. For x = 0.0: x/s = 0.0, round to q = 0. Dequantize: x̂ = 0 × 0.0070866 = 0.000. Error = 0.0000.
  6. Largest error = 0.0016. FP32 storage = 4 × 32 = 128 bits. INT8 storage = 4 × 8 = 32 bits. Saving = 128 / 32 = 4×.

Exam traps

  • A single outlier weight can wreck a per-tensor scale: small weights round to zero. Check per-channel scales or clip the range.
  • Pruning without fine-tuning loses accuracy. Sparsity does not speed up ordinary hardware unless the structure is regular, such as whole channels or heads.
  • In distillation, forget the T² factor and the gradient scale changes; forget T = 1 at inference and the student stays softened.
  • INT8 saves 4× memory, not always 4× time. Activation conversions, memory bandwidth and kernels decide the real speedup.
  • The zero point is not always 0. Symmetric quantization uses z = 0; asymmetric quantization needs z to map real zero correctly.

Check yourself

Remember What does the temperature T do in distillation? 2 marks

T > 1 softens the teacher and student softmax distributions, making rare-class probabilities visible. At inference the student uses T = 1.

Understand Why are soft targets more informative than one-hot labels? 3 marks

Soft targets give a probability for every class. They show which classes are similar, for example cat 0.80 and dog 0.15. A one-hot label gives only the true class.

Apply A weight 0.4 is quantized with s = 0.01 and z = 0. Give q and the dequantized value. 2 marks

q = round(0.4 / 0.01) + 0 = 40. Dequantized value = 0.01 × (40 − 0) = 0.4.

Apply A model has 1,000,000 FP32 weights. What is the INT8 memory in MB, and what is the saving? Use 32 bits for FP32 and 8 bits for INT8. 3 marks

FP32 memory = 1,000,000 × 32 / 8 = 4,000,000 bytes = 4 MB. INT8 memory = 1,000,000 × 8 / 8 = 1,000,000 bytes = 1 MB. Saving = 4×.

Analyze One weight is 10 while most weights lie in [−1, 1]. Why can per-tensor INT8 hurt accuracy? 4 marks

The large value sets s from the maximum absolute value. With s based on 10, a step is large, so weights near 0.1 or 0.01 round to zero or very few levels. Per-channel scales or clipping reduce this damage.

Analyze Why does 90% unstructured sparsity not guarantee a 10× speedup? 4 marks

The remaining weights are scattered irregularly. Dense hardware and libraries cannot skip them efficiently without sparse kernels, so memory may fall but time may not.

Understand What is the difference between post-training quantization and quantization-aware training? 3 marks

PTQ quantizes an already trained model using calibration data. QAT simulates rounding during training so the model learns to tolerate quantization, usually giving better accuracy.

Beyond the syllabus

Takeaways

  1. Attention is a soft dictionary lookup: compare the query with every key, turn the scores into weights that sum to 1, and return the weighted mix of the values.
  2. Self-attention lets each position of a sequence read every other position, which is why the Transformer replaced recurrence for language tasks.
  3. A Transformer block = multi-head self-attention + residual + layer norm + feed-forward network + residual + layer norm; positional encoding supplies the order.
  4. Pretraining is self-supervised on raw text; fine-tuning reuses those weights for a labelled task, so one pretrained model serves many downstream jobs.
  5. BERT reads both directions with masked prediction and suits understanding tasks; GPT reads left to right with next-token prediction and suits generation.
  6. Scaling laws make training runs plannable: loss falls predictably with parameters, data and compute, so a budget buys a known quality.
  7. RLHF converts human preference comparisons into a reward model and then tunes the language model against it, with a KL penalty holding it near the original.
  8. A prompt is the program for a frozen model; wording, examples and format steer it, and compression (distillation, quantization, pruning) decides where it can be served.

Exam question bank

Long answers are expected to write the attention equations with Q, K, V, draw the full Transformer block, contrast BERT and GPT objectives, and then connect training, scaling, alignment and deployment of large language models.

Remember and understand

Understand Explain attention as a soft dictionary lookup. Define query, key and value, write the weight formula, and state why the weights must be normalised. 10 marks

Query = search request, keys = labels of stored items, values = stored content; Score s(q, kᵢ) for each key, then softmax gives aᵢ ≥ 0, Σaᵢ = 1; Output = Σᵢ aᵢvᵢ, a convex combination of the values; Soft (weighted) vs hard (argmax) lookup — soft keeps the function differentiable; Sharp softmax (low temperature) behaves like nearest-neighbour lookup.

Understand Describe self-attention and multi-head attention with equations. Why is the dot product divided by √dₖ, and what does each head learn? 13 marks

Q = XW_Q, K = XW_K, V = XW_V from the same sequence X; Attention(Q,K,V) = softmax(QKᵗ/√dₖ)V; Scaling keeps variance of scores near 1 so softmax gradients do not vanish; h heads on d/h-dimension projections, concatenate, multiply by W₀; Different heads attend to syntax, position, coreference, etc.; cost O(n²d).

Understand Write the components of a Transformer block and explain the role of positional encoding, residual connections and layer normalisation. 12 marks

Multi-head self-attention, then add-and-norm, then feed-forward network, then add-and-norm; Residual connections give a short gradient path and let a block learn a small correction; Layer norm normalises across features per token, which stabilises training; Sinusoidal or learned positional vectors added to embeddings; self-attention is permutation-invariant without them; Encoder uses unmasked attention; decoder adds causal mask and cross-attention.

Understand Compare BERT and GPT: pretraining objective, attention mask, typical use, and the meaning of fine-tuning. 12 marks

BERT: encoder, bidirectional, masked language modelling plus next-sentence prediction; GPT: decoder, causal mask, next-token prediction on long unlabelled text; BERT suits classification, NER, extractive QA; GPT suits generation, chat, completion; Pretraining is self-supervised, so no human labels are needed; Fine-tuning adds a task head or uses prompt-style output and trains with a small learning rate.

Understand Define zero-shot, one-shot and few-shot prompting and chain-of-thought prompting, with one example of each. 8 marks

Zero-shot: instruction only, no examples; One-shot: one worked example before the question; Few-shot: several examples set the format and label space; this is in-context learning with frozen weights; Chain-of-thought: ask for intermediate steps, then the answer; Examples must match the test format; order and delimiters affect quality.

Apply A team plans a training run. Explain how scaling laws let them choose parameters N and data tokens D for a fixed compute budget C, and show the FLOPs estimate per token. 12 marks

Compute C ≈ 6·N·D FLOPs for a dense Transformer (forward plus backward); Loss falls as a power law in N and in D; each has diminishing returns; Compute-optimal split: grow N and D together, roughly 20 tokens per parameter; Loss also has an irreducible floor; more compute beyond it is wasted; Verify with small runs and extrapolate, then reserve compute for evaluation and fine-tuning.

fp16: 2 bytes per parameter, so 7 × 10⁹ × 2 bytes = 14 GB; int8: 1 byte per parameter, so about 7 GB plus small scale factors; Activation memory, KV cache and batch size add to the total; Quantization gives roughly 2× memory saving and faster matrix products; Accuracy loss is small for weight-only 8-bit; check with a validation set.

Analyze and evaluate

Analyze Describe the RLHF pipeline end to end. Why is a reward model needed, why is a KL penalty added, and what can go wrong if β is too small or too large? 14 marks

Supervised fine-tuning on demonstrations gives the starting policy π_ref; Humans compare pairs of answers; a reward model is trained with a pairwise ranking loss; RL (for example PPO) maximises E[r(x,y)] − β·KL(π_θ ‖ π_ref); Small β: reward hacking, verbose or unnatural text, drift from the reference; Large β: model barely changes, alignment gain lost; evaluate with held-out humans.

Evaluate For a labelled classification task with limited data, compare full fine-tuning, parameter-efficient fine-tuning and pure prompting of a large model. Give a recommendation with reasons. 13 marks

Full fine-tuning: best fit, but one full copy of weights per task and risk of overfitting on small data; Parameter-efficient methods (adapters, low-rank updates): few trainable parameters, many tasks share one base model; Prompting with few-shot examples: no training, fastest to try, weakest on specialised labels; Data size decides: hundreds of labels favour prompting or PEFT; thousands favour full fine-tuning; Also weigh inference cost, latency, privacy and the need to re-train when data changes.

Analyze Explain attention over images with a single query (k = 1). Compare it with global average pooling for image classification and image captioning, and relate it to cross-attention in a caption generator. 12 marks

CNN or patch encoder gives N region vectors; learned keys and values per region; One query gives N scores, softmax weights, one pooled vector — attention pooling; Global average pooling uses fixed equal weights and cannot select regions; Attention weights are interpretable and can highlight the object; In captioning the decoder query attends over image regions at every step (cross-attention).

Evaluate Compare distillation, quantization and pruning for deploying a language model on a phone. Judge which combination you would use and how you would measure the loss. 12 marks

Distillation changes the architecture or size; student trained on teacher soft targets; Quantization keeps the architecture and shrinks bits per weight; easiest win, good tooling; Pruning removes weights or heads, needs fine-tuning, gains only with sparse hardware support; Combine: distill to a smaller model, then int8 quantize, then optionally prune; Measure task accuracy, perplexity, latency and memory on the target device, not only on a server.

Evaluate A chatbot built on a frozen model starts giving wrong answers after users paste long documents. Analyse the causes using the context window, attention cost and prompt injection, and propose fixes. 14 marks

Context window is a hard token limit; older turns are silently dropped; Attention cost grows as O(n²) in sequence length; long inputs slow and dilute focus; Middle of a long context is used poorly; key facts lose weight; Retrieved or pasted text can carry instructions — prompt injection; separate data by delimiters and restrict tool access; Fixes: retrieval of top-k chunks, summarise history, pin the system message, cap output with max tokens and top-p.

Glossary

Attention
A layer that mixes a set of value vectors using weights computed from the similarity of one query to a set of keys.
Causal mask
A mask that sets scores to −∞ for future positions so a token can only attend to earlier tokens.
Context window
The maximum number of tokens a model can attend to at once, set by its positional encoding and memory.
Cross-attention
Attention where queries come from the decoder and keys and values come from the encoder or image features.
Distillation
Training a smaller student model to reproduce the output distribution of a larger teacher model.
Encoder–decoder Transformer
An architecture with an unmasked encoder stack and a masked decoder stack linked by cross-attention, used for translation and captioning.
Fine-tuning
Further training of pretrained weights on a smaller labelled dataset for one task.
In-context learning
Improvement in a frozen model's output caused only by examples placed in the prompt.
Key
A vector attached to each stored item, compared with the query to produce a score.
Layer normalisation
Normalising the features of each token to zero mean and unit variance, then scaling and shifting with learned parameters.
Logit
The raw, unnormalised score a model produces for each vocabulary token before softmax.
Multi-head attention
Several attention computations in parallel on projected inputs, concatenated and linearly mixed.
Positional encoding
A vector added to token embeddings so the model knows each token's position in the sequence.
Pretraining
Self-supervised training on large unlabelled text that produces general-purpose language weights.
Prompt injection
An attack where text inside user data contains instructions that hijack the model away from its system message.
Quantization
Representing weights or activations with fewer bits, such as int8 instead of fp32.
Query
The vector that states what the current position or decoder step is looking for.
Residual connection
Adding a layer's input to its output, x + f(x), which eases gradient flow in deep stacks.
Retrieval-augmented generation
Fetching relevant documents and placing them in the prompt so the model answers from supplied evidence.
Reward model
A learned scorer trained on human preference comparisons that RLHF uses as its training signal.
Scaled dot-product attention
Attention computed as softmax(QKᵗ/√dₖ)V, the standard attention formula in Transformers.
Scaling law
An empirical power-law relation between model loss and parameters, data or compute.
Self-attention
Attention in which queries, keys and values all come from the same sequence.
Softmax
softmax(sᵢ) = exp(sᵢ)/Σⱼ exp(sⱼ); it turns arbitrary scores into positive weights that sum to 1.
Top-p (nucleus) sampling
Sample from the smallest set of tokens whose total probability exceeds p, which cuts unlikely tokens.
Value
The content vector that is actually averaged, weighted by the attention scores.
