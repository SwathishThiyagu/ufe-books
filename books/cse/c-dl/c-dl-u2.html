2.1 Gradient descent and its limitations

Gradient descent is the basic optimizer that moves a model’s parameters opposite to the gradient of the loss. Deep learning loss surfaces are non-convex, so this simple update can stop in a bad local minimum or crawl through flat saddle regions. Choosing the learning rate η is delicate: too small wastes compute, too large jumps wildly. Some syllabi call this the limitations of gradient descent learning algorithm. This chapter covers batch gradient descent, its geometry, and basic escapes such as random restarts. Later chapters add momentum (2.3) and adaptive updates (2.4).

You need: forward propagation and backpropagation from Unit 1, plus basic calculus; the noisy gradient version is in 2.2.

Batch update and the loss surface

A neural network has learnable weights and biases. Collect all of them into one vector θ. The training set has m examples (x(i), y(i)). The loss J(θ) is the average per-example loss L over all m examples. Batch gradient descent computes the exact gradient of the full training loss, then updates θ.

J(θ) = (1/m) Σ_{i=1}^{m} L(f(x(i); θ), y(i))

J(θ) is the average training loss; L is the per-example loss; f(x(i); θ) is the network output for example i; m is the number of training examples.

θ ← θ − η ∇J(θ)

θ is the parameter vector; η is the learning rate (a positive step size); ∇J(θ) is the gradient of J with respect to θ.

  1. Forward-pass all m examples and compute J.
  2. Backpropagate to obtain ∂J/∂θ_j for every parameter j.
  3. Update every parameter by θ_j ← θ_j − η ∂J/∂θ_j.
  4. Repeat with the same full dataset until the loss or validation loss stops improving.

The gradient points uphill. Subtracting η times the gradient therefore steps downhill. The size of the step is η times the magnitude of the gradient.

Where batch gradient descent gets stuck

Deep learning losses are usually non-convex. A one-dimensional slice can have several valleys. A local minimum is a point where J is lower than all nearby points, but not necessarily the global minimum. Batch gradient descent may settle there if the gradient becomes zero. In the worked example, the curve has a shallow local minimum at w = 0 and a much lower global minimum at w = 4. The first step from w = 0.5 moves toward w = 0, not w = 4.

Saddle points are another hazard. At a saddle point the gradient is zero, but the point is a minimum in some directions and a maximum in other directions. In high dimensions, many flat regions have tiny gradients, so training can appear stuck even though a lower loss exists elsewhere.

Curvature also matters. In a narrow valley the gradient is steep, so a moderately large η may jump across the valley. In a flat direction the same η may move only a tiny amount. A single constant learning rate cannot match every direction.

Learning rate sensitivity and basic heuristics

η is the step size. If η is too small, training makes many slow updates and may need too many epochs. If η is too large, the update can overshoot the minimum, bounce between opposite sides of a valley, or increase J. In the worked example, η = 0.1 gives only a small descent because the slope at the start is mild.

Basic heuristics reduce the chance of a bad ending. Random restarts run training from several different random initial θ values and choose the run with the lowest validation loss. Careful initialization keeps weights small and random; see 2.6. Scaling input features to similar ranges reduces uneven gradients. Momentum and adaptive optimizers handle curvature better, but they are covered later in 2.3 and 2.4.

Worked example

Question. Let J(w) = ¼w⁴ − (5/3)w³ + 2w² + 3. Starting at w = 0.5, perform one batch gradient descent step with η = 0.1. Compute the derivative at the start, the updated value of w, J(0.5), J(0.4125), and J(4). Explain what the step missed.

  1. The derivative is dJ/dw = w³ − 5w² + 4w.
  2. At w = 0.5, the gradient is (0.5)³ − 5(0.5)² + 4(0.5) = 0.125 − 1.25 + 2 = 0.875.
  3. The update is w ← 0.5 − 0.1 × 0.875 = 0.4125.
  4. Loss before: J(0.5) = 0.25(0.5)⁴ − (5/3)(0.5)³ + 2(0.5)² + 3 = 3.3073.
  5. Loss after: J(0.4125) = 3.2306, so the step reduces loss.
  6. At w = 4, J(4) = 0.25(4)⁴ − (5/3)(4)³ + 2(4)² + 3 = −7.6667, the much lower global minimum.
  7. The step moves left toward the shallow local minimum at w = 0, so it misses the global minimum at w = 4.

Answer. One update gives w = 0.4125 and J = 3.2306; the much lower global minimum at w = 4 has J = −7.6667.

Exam traps

  • Subtract the gradient; do not add it. Adding ∇J moves uphill, not downhill.
  • Evaluate the gradient at the old θ before computing θ_new. Using the new θ to compute the gradient gives a different, incorrect update.
  • Do not confuse a local minimum with the global minimum. A falling loss after one step is not proof that the run is heading to the best valley.
  • A zero gradient at a saddle point is not a minimum. Check whether the update can escape with small random noise or second-order information.
  • For full-batch gradient descent, the gradient must be the average over all m training examples, not one example. Forgetting the 1/m average gives a gradient that is m times too large.

2.2 Stochastic and mini-batch gradient descent

Training a deep network means repeatedly adjusting weights to reduce a loss. Full batch gradient descent computes the gradient on the whole dataset before each update, which is too slow and memory-heavy for large datasets. Stochastic gradient descent (SGD) estimates the gradient from one sample per update. Mini-batch gradient descent uses a small subset, usually 32, 64, or 128 samples. The update rule is θ ← θ − η (1/m)∑i∇Li(θ). This gives faster updates and often better generalization. It is the standard way to train modern neural networks.

You need: the gradient descent update from Chapter 2.1 and the loss-function derivatives from Unit 1.

Full batch and stochastic gradient descent

Full batch gradient descent computes the gradient of the average loss over all N training samples. Its update is θ ← θ − η (1/N)∑i ∇Li(θ). Here θ is the weight vector, η is the learning rate, N is the number of samples, and ∇Li(θ) is the gradient of the loss on sample i. If N is 1 000 000, one update needs 1 000 000 forward and backward passes. Training is slow, and the step is exactly the steepest downhill direction for the whole dataset.

Stochastic gradient descent avoids this huge computation. It selects one sample at random and uses its loss gradient as an estimate of the full gradient. The update is θ ← θ − η ∇Li(θ). The sample index i is random. One pass through all N samples is called an epoch. SGD takes N updates per epoch, but each update is N times cheaper than full batch. The noisy gradient estimate gives a jittery path, not a smooth one.

Mini-batch gradient descent and epochs

Mini-batch gradient descent balances the two extremes. It splits the dataset into mini-batches of size m. For each mini-batch B, it computes the average gradient over the m samples in B. The update is θ ← θ − η (1/m)∑i∈B ∇Li(θ). The factor 1/m is essential: it averages the gradients, so the step size does not grow with batch size. If you forget to divide by m, a batch of 128 would produce a step about 128 times too large.

An epoch is one complete pass over the dataset. At the start of every epoch, the samples are shuffled randomly and then split into mini-batches. Shuffling reduces correlation between consecutive updates and helps the optimizer move through the data more fairly. Common mini-batch sizes are 32, 64, and 128. They fit in GPU memory and give reliable gradient estimates.

  1. Initialize weights θ and learning rate η.
  2. For each epoch: shuffle the dataset.
  3. Split into mini-batches of size m.
  4. For each mini-batch B: compute g = (1/m)∑i∈B ∇Li(θ).
  5. Update θ ← θ − η g.

Why small-batch noise can help

The full batch gradient is exact. It may walk into a sharp local minimum and stop, even if a flatter minimum nearby generalizes better. SGD and mini-batch updates contain random errors. These errors can jump the weight vector out of narrow minima or explore different valleys. The noise is not only wasted; it often helps the optimizer find flatter solutions that perform better on unseen data.

Smaller mini-batches have more noise; larger mini-batches give more accurate gradient estimates but cost more computation per step. In practice, memory size and stability set the batch size. A very large batch can converge to sharp minima, while a very small batch can be too noisy and need many epochs. Libraries default to 32 or 64 for image tasks, sometimes larger for language models.

Worked example

Question. Training samples are (1, 2), (2, 4), (3, 6). The model is y = w x. The loss is L = ½(y − w x)². Start with w = 1 and learning rate η = 0.1. Compute the next weight after one mini-batch update using samples 1 and 2, one SGD update using sample 1, and one full-batch update using all three samples. Show all gradients and averages.

  1. For loss L = ½(y − w x)², the derivative is dL/dw = −x(y − w x).
  2. At w = 1: sample (1, 2) has gradient −1 × (2 − 1 × 1) = −1; sample (2, 4) has −2 × (4 − 1 × 2) = −4; sample (3, 6) has −3 × (6 − 1 × 3) = −9.
  3. Mini-batch with samples 1 and 2: average gradient = (−1 + −4) / 2 = −2.5. Update: w = 1 − 0.1 × (−2.5) = 1.25.
  4. SGD on sample (1, 2): gradient = −1. Update: w = 1 − 0.1 × (−1) = 1.1.
  5. Full batch with all three samples: average gradient = (−1 − 4 − 9) / 3 = −14/3 ≈ −4.6667. Update: w = 1 − 0.1 × (−14/3) = 1.4667.

Answer. Mini-batch w = 1.25, SGD w = 1.1, full batch w ≈ 1.4667.

Exam traps

  • Forgetting to divide by m when averaging gradients in a mini-batch. The average, not the sum, must be used.
  • Mixing up SGD and mini-batch: some syllabi use SGD for one sample and mini-batch for a small subset; do not call a batch of 32 'pure SGD' unless the syllabus does.
  • Not shuffling samples at the start of each epoch. The same order every epoch can bias the path and slow convergence.
  • Confusing epoch with iteration: one epoch for a dataset of size N and batch size m has ⌈N/m⌉ iterations, not one update.
  • Sign slip: the update subtracts η times the gradient; adding the gradient moves weights uphill, increasing the loss.

2.3 Momentum and Nesterov accelerated gradient descent

Momentum and Nesterov accelerated gradient descent are small changes to gradient descent that make training faster and more stable. Instead of using only the current gradient, they keep a short memory of past updates as a velocity. This smooths the path in narrow valleys where plain gradient descent oscillates. Nesterov momentum improves the idea by first taking a step along the old velocity, looking ahead, and then computing the gradient. Both methods are standard choices in optimizers for deep networks. Momentum appears inside Adam; Nesterov acceleration is used in variants such as Nadam.

You need: stochastic and mini-batch gradient descent and the idea of a gradient from gradient descent and its limitations.

Momentum: a velocity of past gradients

Plain gradient descent subtracts the learning rate times the gradient from the weights:

g<sub>t</sub> = ∇J(θ<sub>t−1</sub>)   θ<sub>t</sub> = θ<sub>t−1</sub> − η g<sub>t</sub>

η is the learning rate, θ are the weights, and g is the gradient.

In a narrow valley, the gradient changes sign on each side. The update zig-zags sideways and the path along the valley moves slowly.

Momentum keeps a velocity v so past directions are not thrown away.

v<sub>t</sub> = β v<sub>t−1</sub> + η g<sub>t</sub>   θ<sub>t</sub> = θ<sub>t−1</sub> − v<sub>t</sub>

β is the momentum constant, usually about 0.9; v is the velocity; g_t is the gradient at step t.

  1. Compute the gradient gt = ∇J(θt−1).
  2. Update velocity vt = β vt−1 + η gt.
  3. Move weights θt = θt−1 − vt.
  • β close to 0.9 means the velocity changes slowly.
  • Momentum acts like a heavy ball rolling downhill: it speeds up when the gradient direction stays the same.
  • With β = 0, momentum becomes plain gradient descent.

Nesterov accelerated gradient descent

Nesterov accelerated gradient, often called NAG, makes one change. It evaluates the gradient at a lookahead point, before the actual move.

First form a lookahead point by subtracting β vt−1; no weight update is made yet. Then compute the gradient at that point.

θt−1 − β vt−1

β is the momentum constant and v_{t−1} is the previous velocity.

v<sub>t</sub> = β v<sub>t−1</sub> + η ∇J(θ<sub>t−1</sub> − β v<sub>t−1</sub>)   θ<sub>t</sub> = θ<sub>t−1</sub> − v<sub>t</sub>

∇J is the gradient of the loss. The gradient is taken at the lookahead point, not at θ_{t−1}.

This is like a ball that can see the slope a little ahead. It often brakes earlier near the bottom, so it oscillates less.

  1. Compute lookahead θt−1 − β vt−1.
  2. Find the gradient gt at the lookahead point.
  3. Update velocity vt = β vt−1 + η gt.
  4. Move weights θt = θt−1 − vt.
  • The first step of NAG is the same as momentum because v0 = 0.
  • In libraries, NAG is often implemented as momentum with a little algebra, but the lookahead idea stays the same.

Worked example

Question. Use the loss J(w)=½w², whose gradient is ∇J(w)=w. Start at w=1.0, learning rate η=0.1, momentum constant β=0.9. Perform two updates with (a) plain gradient descent, (b) momentum, and (c) Nesterov accelerated gradient. Give the value of w after each update.

  1. Plain GD step 1: gradient g=1.0, w = 1.0 − 0.1×1.0 = 0.90.
  2. Plain GD step 2: gradient g=0.90, w = 0.90 − 0.1×0.90 = 0.81.
  3. Momentum step 1: start v=0. g=1.0. v = 0.9×0 + 0.1×1.0 = 0.10, w = 1.0 − 0.10 = 0.90.
  4. Momentum step 2: g=0.90. v = 0.9×0.10 + 0.1×0.90 = 0.18, w = 0.90 − 0.18 = 0.72.
  5. Nesterov step 1: v=0, lookahead = 1.0 − 0.9×0 = 1.0. g=1.0. v = 0.9×0 + 0.1×1.0 = 0.10, w = 1.0 − 0.10 = 0.90.
  6. Nesterov step 2: lookahead = 0.90 − 0.9×0.10 = 0.81. g=0.81. v = 0.9×0.10 + 0.1×0.81 = 0.171, w = 0.90 − 0.171 = 0.729.

Answer. After two updates, plain gradient descent gives w=0.81, momentum gives w=0.72, and Nesterov gives w=0.729.

Exam traps

  • Using the old gradient at θt−1 for NAG instead of the gradient at the lookahead θt−1 − β vt−1. That silently turns NAG into plain momentum.
  • Forgetting the β in front of v_{t−1} when updating velocity. The update v_t = η g_t + v_{t−1} is not standard momentum and can diverge.
  • Writing the lookahead with v_t instead of v_{t−1}; at step t you only have v_{t−1} before the velocity update.
  • Changing β as if it were the learning rate. β usually stays near 0.9; η is the parameter to tune first.
  • Adding v instead of subtracting it. The standard sign is θ ← θ − v because v is the accumulated gradient direction for minimizing J.

2.4 Adaptive optimizers: AdaGrad, RMSProp and Adam

AdaGrad, RMSProp and Adam fix one weakness of plain gradient descent: one learning rate for every weight. They give each weight its own effective step size from the history of its gradients. Adam is the default in many deep-learning libraries. The idea is simple: large, noisy gradients get smaller updates; small, rare gradients get larger updates. You meet them whenever a network is trained with mini-batches.

You need: mini-batch updates and momentum from Chapter 2.

AdaGrad: per-weight sum of squared gradients

AdaGrad changes the step size for every weight separately. Let gt be the gradient of loss J with respect to weight w at step t. AdaGrad keeps a cumulative sum Gt. Large past gradients make the denominator large, so the current step becomes smaller. Small, rare gradients keep the denominator small, so their step remains larger. This suits sparse features, like one-hot encoded words in text models, where many weights get zero gradient most of the time.

G<sub>t</sub> = G<sub>t−1</sub> + g<sub>t</sub><sup>2</sup>

Gt is the sum of squared gradients up to step t; G0 is usually 0.

The update is wt+1 = wt − η gt / (√Gt + ε). η is the base learning rate; ε is a tiny constant, often 10⁻⁸, to avoid division by zero. The weakness is clear: G only grows. After many steps, √G becomes very large, so the update can become nearly zero before the loss is low.

RMSProp: a decaying average of squared gradients

RMSProp fixes AdaGrad's ever-growing denominator. It does not sum all past squared gradients. It keeps an exponentially weighted moving average, usually written E[g²]t. Old squared gradients decay by factor β, so the denominator can rise and fall.

E[g²]<sub>t</sub> = β E[g²]<sub>t−1</sub> + (1−β) g<sub>t</sub><sup>2</sup>

E[g²]t is the moving estimate of squared gradient; β is decay rate, typically 0.9.

Update: wt+1 = wt − η gt / (√E[g²]t + ε). A noisy burst raises E[g²], so the step shrinks. When gradients become small again, E[g²] falls and the step can grow. RMSProp has no momentum; it only rescales the gradient. It is often used for recurrent networks and tasks where the gradient scale changes over time.

Adam: momentum plus adaptive scaling

Adam combines momentum with RMSProp-style adaptive scaling. It keeps two moving averages: mt for the gradient mean and vt for the squared gradient.

m<sub>t</sub> = β<sub>1</sub> m<sub>t−1</sub> + (1−β<sub>1</sub>) g<sub>t</sub>

mt is the first moment estimate of the gradient.

v<sub>t</sub> = β<sub>2</sub> v<sub>t−1</sub> + (1−β<sub>2</sub>) g<sub>t</sub><sup>2</sup>

vt is the second moment estimate.

At the start m and v are zero, so early estimates are biased low. Adam corrects the bias: m̂t = mt / (1−β₁t), v̂t = vt / (1−β₂t). Then wt+1 = wt − η m̂t / (√v̂t + ε). Standard defaults are η=0.001, β₁=0.9, β₂=0.999, ε=10⁻⁸. Adam is often the first optimizer to try because these defaults work across many deep networks.

2.5 Vanishing and exploding gradients

Deep networks multiply many small numbers in backpropagation. When these numbers are below 1, the gradient for early layers becomes so small that the weight update is almost zero: the gradient vanishes. When the numbers are above 1, the gradient grows rapidly and the update becomes huge: the gradient explodes. Vanishing gradients make training stall; exploding gradients make the loss jump and weights become unusable. This chapter explains why the product behaves this way, shows the math for a ten-layer chain, and lists the common fixes.

You need: Unit 1 backpropagation and the chain rule, and gradient descent from this unit.

Repeated multiplication through layers

In backpropagation, the upstream gradient flows from the output back to each weight. Between layer l and the loss, the gradient passes through every later layer. Each layer applies its local derivative, often called a Jacobian. For depth L, the gradient at layer l can be written as a product:

g<sub>l</sub> = J<sub>l+1</sub><sup>T</sup> J<sub>l+2</sub><sup>T</sup> ⋯ J<sub>L</sub><sup>T</sup> g<sub>L</sub>

gl is the gradient column vector of the loss with respect to the outputs of layer l; gL is the gradient at the top layer; Jk is the Jacobian matrix ∂hk/∂hk−1. For row-vector gradients, the order is reversed: gl = gL JL JL−1 ⋯ Jl+1.

For a scalar chain, each Jacobian is just a number. Suppose the chain has L layers. To move the gradient from the output of layer L back to the output of layer 1, we multiply L−1 factors, one for each later layer from L down to 2. If each factor is 0.25 and L = 10, the total multiplier is 0.25⁹ ≈ 3.81×10⁻⁶. If each factor is 2, the total multiplier is 2⁹ = 512. The figure below plots both curves for 1 to 9 multiplication steps. The vanishing product falls so fast that it looks flat on a scale that reaches 512.

Why sigmoid and weight choices make it worse

The most common vanishing cause is a saturating activation. The sigmoid function is s(x) = 1/(1+e−x). Its derivative is s(x)(1−s(x)), whose maximum is 0.25 at x=0. For large positive or negative x, the derivative is close to zero. A deep network with sigmoid in every layer multiplies many numbers at most 0.25, so the gradient becomes tiny. Tanh has derivative 1−tanh²(x), with maximum 1 at x=0, but it also saturates to zero away from zero. ReLU derivative is 1 for positive input and 0 for negative input, so it avoids the 0.25 cap, but negative half can still kill gradients if many units are dead.

Weight initialization also controls the product. If initial weights are too large, Jacobian entries become large and gradients can explode. If they are too small, gradients shrink. For a scalar chain, a per-layer weight multiplier of 0.1 gives a product of 0.1L−1, which vanishes. A multiplier of 3 gives 3L−1, which explodes. For an actual matrix layer, the effective multiplier is the spectral norm, the largest singular value of the layer's Jacobian. If that norm is below 1, gradient products shrink; if it is above 1, they grow. Recurrent networks unfold the same matrix at every time step, so backpropagation through time multiplies the same factors again and again.

Practical mitigations

  • Use ReLU or Leaky ReLU for hidden layers. Leaky ReLU gives a small slope, for example 0.01, for negative input, so the gradient never becomes exactly zero.
  • Initialize weights carefully. He initialization for ReLU and Xavier/Glorot for sigmoid/tanh set the variance so that activations and gradients stay at a similar scale. See Chapter 2.6: Weight initialization methods.
  • Add batch normalization after linear layers. It normalizes each mini-batch to zero mean and unit variance, then learns scale γ and shift β. See Chapter 2.7: Batch normalization.
  • Clip gradients when training deep or recurrent networks. If the gradient norm exceeds a threshold, scale the gradient to that threshold. This stops explosion.
  • Add residual connections, such as H(x) = F(x) + x. The gradient can flow through the identity path, even if F(x) has a small derivative. ResNet uses this idea (see Unit 3).
  • Use LSTM or GRU in sequence models. Their gates control how much of the previous state is kept, so the gradient can flow for many time steps. See Unit 4.

Worked example

Question. A toy network has ten layers in a chain. For network A, each connection from a later layer output to the previous layer output multiplies the incoming gradient by 0.25 because of sigmoid saturation. Exam traps

  • Confusing activation value saturation with gradient saturation. A sigmoid output near 1 or 0 is saturated, but the gradient is also near zero because the derivative is small. The value being large is not the problem; the derivative is.
  • Checking only weight magnitudes. Even if weights are moderate, a long chain of sigmoid derivatives each below 0.25 can vanish. You must multiply weight and activation derivatives together.
  • Thinking ReLU eliminates vanishing gradients completely. ReLU avoids positive-side saturation, but if too many units receive negative input, the gradient through those units is exactly zero (dead ReLU). Leaky ReLU reduces this.
  • Forgetting that exploding gradients can happen before loss becomes NaN. Even a multiplier of 2 over 9 connections gives 512; the loss may jump but not yet be NaN. Clip early.
  • Using gradient clipping as a fix for vanishing gradients. Clipping only reduces large gradients; it does not help small ones.

2.6 Weight initialization methods

Weight initialization sets the variance of initial weights so activations and gradients do not immediately vanish or explode. A bad scale makes signals shrink or grow at every layer. This chapter gives the standard variance rules for tanh, sigmoid and ReLU networks. They are applied before training, so the first forward and backward passes produce useful gradient sizes. Some syllabi call this topic weight initialization methods or He initialization.

You need: forward and backward passes from Unit 1, the derivative shapes of tanh, sigmoid and ReLU, and the repeated-multiplication idea in Chapter 2.5.

Why initialization matters

Two wrong choices break training. Zero initialization makes every hidden unit compute the same output. Backprop gives the same gradient to corresponding incoming weights of different hidden units, so they update identically and symmetry remains. The network effectively learns only one feature per hidden layer.

Small random weights make signals too small. Let fan_in = n, the number of inputs to a layer. Suppose inputs have variance q and weights have variance σ². For a linear layer y = W x + b, each output y_i is a sum of n products W_ij x_j plus bias b_i. If weights and inputs are independent with zero mean, the variance of y_i is close to n σ² q. With n = 100 and σ = 0.01, n σ² = 100 × 0.0001 = 0.01, so the output variance is only 1 percent of q. Repeated layers make gradients vanish.

Large random weights push tanh and sigmoid units into flat saturation regions. Their derivative is near zero, so gradients vanish. A large scale can also make ReLU outputs grow quickly. The goal is to choose σ² so forward and backward variances stay roughly constant. Batch normalization later reduces this sensitivity.

Xavier/Glorot initialization for tanh and sigmoid

Xavier initialization, also called Glorot initialization, is designed for roughly symmetric nonlinearities such as tanh. It balances the forward pass and the backward pass. The forward sum uses fan_in terms; the backward sum for the gradient with respect to the input uses fan_out terms. The common compromise uses their sum.

σ² = 2 / (fan_in + fan_out), and r = √(6 / (fan_in + fan_out))

σ is the normal standard deviation, r is the uniform half-range, fan_in is the number of inputs, and fan_out is the number of outputs.

For tanh with fan_in = 256 and fan_out = 128, σ² = 2 / (256 + 128) = 2 / 384 = 1 / 192, so σ = √(1 / 192) ≈ 0.0722. Biases are usually set to zero with Xavier. The rule keeps the variance reasonable while tanh is near its linear part. It also works for sigmoid, but sigmoid also saturates and has a smaller maximum derivative, so very deep sigmoid networks may need a different scale.

He/Kaiming initialization for ReLU

ReLU outputs zero for all negative inputs. This removes about half the variance of a layer's pre-activations. To keep the post-ReLU variance close to the input variance, the weight variance needs a factor of 2 compared with the simple 1/fan_in rule. He initialization, also called Kaiming initialization or He initialization, uses fan_in only.

σ² = 2 / fan_in, and r = √(6 / fan_in)

σ is the normal standard deviation; r is the uniform half-range; fan_in is the number of inputs to the layer.

For a ReLU layer with fan_in = 256, σ = √(2 / 256) = √(1 / 128) ≈ 0.088. The uniform bound is r = √(6 / 256) = √(3 / 128) ≈ 0.153. The figure shows the rounded values 0.09 and 0.15.

Biases usually start at zero. A small positive bias such as 0.01 is an old trick to reduce dead ReLU units at the start. For ReLU and related activations such as leaky ReLU and GELU, fan-in-based initialization is common. For leaky ReLU and PReLU, use the slope-adjusted form.

Exam traps

  • Zero initialization: all hidden units stay identical, so no symmetry breaking occurs. Never initialize all weights to zero except for biases or special residual tricks.
  • Using fan_out inside He initialization: He/Kaiming for ReLU uses fan_in only. Using fan_in + fan_out gives too small a variance for ReLU.
  • Using variance as the standard deviation: σ² = 2 / fan_in, so σ = √(2 / fan_in). Forgetting the square root understates the expected weight spread.
  • Uniform bound is not the standard deviation: for a uniform distribution on [−r, r], the standard deviation is r / √3. Therefore r = √3 σ, so r is always larger than σ.
  • Using one global variance for every layer: layers with different fan_in need different σ or r, computed layer by layer.

2.7 Batch normalization

Deep networks can shift the distribution of activations during training. Batch normalization normalizes each mini-batch activation to zero mean and unit variance, then applies learned scale γ and shift β. This stabilizes the input to the next layer, reduces internal covariate shift, and often allows higher learning rates. It is used in nearly all modern CNN architectures and many MLPs after linear layers and before activation. The same idea appears wherever very deep networks are trained on GPUs in mini-batches.

You need: mini-batch statistics from Chapter 2.2 and stable initialization from Chapter 2.6.

Batch normalization forward pass

Batch normalization is a small layer inserted between a linear transformation and a non-linear activation. It works on one mini-batch at a time. For a mini-batch B with m examples, let x_i be one activation value from one neuron for example i.

The operation normalizes the values to zero mean and unit variance, then shifts and scales them with learned parameters.

μ_B = (1/m) Σ_{i=1}^{m} x_i

μ_B is the mini-batch mean; m is the number of examples in the mini-batch; x_i is the activation value for example i.

σ²_B = (1/m) Σ_{i=1}^{m} (x_i − μ_B)²

σ²_B is the mini-batch variance; the denominator is m, not m−1, because it is the population variance of the current mini-batch.

x̂_i = (x_i − μ_B) / √(σ²_B + ε)

x̂_i is the normalized value; ε is a small constant such as 10⁻⁵. It prevents division by zero when all x_i are equal.

y_i = γ x̂_i + β

γ is the learned scale; β is the learned shift; y_i is the output passed to the next layer. γ and β are updated by backpropagation like any other weights.

Training and inference behavior

During training, μ_B and σ²_B are computed from the current mini-batch. This adds a little noise because each mini-batch is a random sample. The noise gives a mild regularizing effect.

The network also keeps running averages μ_run and σ²_run over training mini-batches. A common update with momentum ρ is:

μ_run ← ρ μ_run + (1−ρ) μ_B

ρ is usually about 0.99; μ_B is the current mini-batch mean; ← means update the stored running mean. The running variance σ²_run updates the same way.

At inference, use the fixed running averages, not the current test batch:

y = γ (x − μ_run) / √(σ²_run + ε) + β

x is one test activation; μ_run and σ²_run are fixed after training; γ and β are the same learned parameters.

  • Use the saved running mean and variance for validation and deployment.
  • Do not update running averages on test data.
  • The learned γ and β apply in both training and inference.

Why batch normalization helps

Deep layers see input distributions that shift as earlier layers update. This shift, often called internal covariate shift, can slow learning. Batch normalization reduces it by re-centering and re-scaling each mini-batch.

Stable activation ranges also help gradients flow. This often allows a higher learning rate and can reduce vanishing or exploding gradients (see Chapter 2.5).

  • Works well after fully connected layers and convolutional layers.
  • Usually placed before the activation function such as ReLU.
  • Common in CNN and residual network architectures.
  • Adds a slight regularization effect from mini-batch noise.

The learned γ and β keep the layer powerful. If identity is better, the network can learn γ = √(σ²_B + ε) and β = μ_B to recover the original value. Batch normalization does not simply force every activation to have unit variance. Some syllabi list batch normalization as part of faster training.

Worked example

Question. Given a mini-batch x = [2, 4, 6], learned scale γ = 2, learned shift β = 1, and ε = 10⁻⁵, compute the batch normalization outputs y.

  1. Mini-batch size m = 3. Compute mean μ_B = (2+4+6)/3 = 12/3 = 4.
  2. Compute variance σ²_B = [(2−4)² + (4−4)² + (6−4)²] / 3 = (4 + 0 + 4)/3 = 8/3 ≈ 2.667.
  3. Compute standard deviation σ_B = √(2.667) ≈ 1.633. The small ε = 10⁻⁵ does not change the result at this precision.
  4. Normalize each value: x̂₁ = (2−4)/1.633 ≈ −1.22; x̂₂ = (4−4)/1.633 = 0; x̂₃ = (6−4)/1.633 ≈ 1.22.
  5. Apply scale and shift: y₁ = 2×(−1.22) + 1 = −1.44 ≈ −1.4; y₂ = 2×0 + 1 = 1; y₃ = 2×1.22 + 1 = 3.44 ≈ 3.4.

Exam traps

  • At test time, using the current mini-batch mean and variance instead of the saved running averages. This makes predictions depend on the test batch size and order.
  • Omitting the learnable γ and β. If you just normalize, the layer may lose expressiveness and sometimes cannot recover the original scale.
  • Forgetting ε or setting it too large. Without ε, a constant mini-batch gives division by zero; too large an ε dampens normalization.
  • Computing variance with denominator m−1 instead of m. Batch normalization uses the mini-batch population variance with denominator m.
  • Updating the running statistics during validation or test. They must be frozen after training.

2.8 Regularization: weight penalties, dropout and early stopping

Deep networks can memorize training data. Overfitting means a small training loss but a worse test loss. Regularization reduces overfitting by limiting model capacity during training. Three common tools are L2 weight penalties, dropout, and early stopping. L2 adds a penalty for large weights. Dropout randomly removes hidden units in each step. Early stopping stops training when validation loss stops improving. These tools are cheap, easy to add, and widely used in image and text models.

You need: gradient descent, mini-batch training, and Unit 1 overfitting and bias-variance.

L2 regularization: penalising large weights

Overfitting happens when some weights become very large. A small change in an input then causes a large change in the output. L2 regularization adds a quadratic penalty that pushes every weight toward zero.

J_total = J_data + (λ ÷ 2) × Σ w²

J_total is total loss; J_data is normal data loss; λ is non-negative regularization strength; Σ w² sums the squares of all trainable weights, usually excluding biases.

The gradient of the penalty term is λw. So the total gradient for one weight w is:

∂J_total/∂w = ∂J_data/∂w + λw

∂J_data/∂w is the gradient from the data loss; λw is the L2 penalty gradient.

The update becomes w ← w − η(∂J_data/∂w + λw). Rewriting: w ← (1 − ηλ)w − η × ∂J_data/∂w. This is why L2 penalty is also called weight decay: before the data step, the weight shrinks by factor (1 − ηλ).

  • Large λ gives strong shrink and may underfit.
  • Small λ gives weak regularization and may overfit.
  • Choose λ on a validation set; cross-validation is common.

Quick check: w = 2, data gradient = −0.5, λ = 0.01, η = 0.1. The penalty gradient is 0.01 × 2 = 0.02. Total gradient = −0.5 + 0.02 = −0.48. Updated weight = 2 − 0.1 × (−0.48) = 2.048.

Dropout: training a random subnetwork

Dropout randomly switches off some hidden units while training. Each unit has keep probability p. A dropped unit outputs 0 for that step. This forces the network not to rely on any one unit. At test time, every unit is active.

  1. At each training step, sample a Bernoulli mask r for a hidden unit: P(r = 1) = p, P(r = 0) = 1 − p.
  2. Multiply the activation a by the mask: a_masked = r × a.
  3. In inverted dropout, also divide by p: a_train = (r × a) ÷ p. This keeps E[a_train] = a.
  4. Backpropagate through the kept units only. At test time, use the full activations with no dropout and no scaling.

For example, with p = 0.5 and activations [4, 6, 8], mask [1, 0, 1] gives inverted outputs [4 ÷ 0.5, 0, 8 ÷ 0.5] = [8, 0, 16]. The expected value of each output is the original activation.

  • Common choice: p = 0.5 for hidden layers; p = 0.8 for input layer; p = 1.0 (no dropout) for output layer.
  • Dropout is active only during training, not evaluation.
  • It approximates averaging many smaller networks, since a network with N hidden units has 2^N possible masks.

Early stopping: stop when validation loss stops improving

Early stopping monitors a validation loss after each epoch. The validation set is separate from training and test data. When validation loss stops improving, training stops. The weights from the best validation epoch are restored.

  1. Split training data into a training part and a validation part. Keep a separate test set.
  2. After each epoch, compute validation loss. If it is lower than the best so far, save the weights.
  3. If no new best appears for patience epochs, stop training.
  4. Restore the saved best weights.

Patience is the number of epochs to wait. A typical value is 5 to 20. Too small a patience stops during a temporary plateau. Too large wastes computation.

Early stopping regularizes because it halts before the optimizer fits noisy train detail. It is cheap and often combined with L2 and dropout. Dataset augmentation and hyperparameter tuning are in Chapter 2.9.

Worked example

Question. A model has one trainable weight w = 2. A mini-batch gives a data-loss gradient ∂J_data/∂w = −0.5. The total loss includes an L2 penalty with λ = 0.01. The learning rate is η = 0.1. (a) Compute the total gradient and the updated weight. (b) A hidden layer uses inverted dropout with p = 0.5. Its activations are [4, 6, 8] and the Bernoulli mask for one step is [1, 0, 1]. Compute the training-time outputs.

  1. L2 penalty gradient: λw = 0.01 × 2 = 0.02.
  2. Total gradient: ∂J_data/∂w + λw = −0.5 + 0.02 = −0.48.
  3. Weight update: w_new = w − η × total gradient = 2 − 0.1 × (−0.48) = 2 + 0.048 = 2.048.
  4. Inverted dropout for each kept activation: divide by p = 0.5. For a_1 = 4, 4 ÷ 0.5 = 8.
  5. For dropped second unit, output = 0.
  6. For a_3 = 8, 8 ÷ 0.5 = 16. Training outputs = [8, 0, 16].

Answer. The updated weight is 2.048, and the inverted dropout outputs are [8, 0, 16].

Exam traps

  • Forgetting the λw penalty gradient when computing the total gradient. The L2 loss term is (λ/2)w², so the derivative is λw; using λ or 2λw is a sign/slope slip.
  • Using standard dropout by multiplying test-time activations by p after already dividing by p in training. Inverted dropout needs no test scaling.
  • Applying dropout at test time. Dropout is a training-time random mask; test-time inference uses all units.
  • Early stopping on training loss instead of validation loss. Training loss can keep decreasing while validation loss rises because of overfitting.
  • Regularizing biases with L2. Most implementations exclude biases from the weight penalty because biases usually do not cause the same input-sensitivity problem.

Remember What does p = 0.5 mean in dropout? 2 marks

Remember Define early stopping. 2 marks

Understand Why does an L2 penalty reduce overfitting? 3 marks

It adds λ/2 Σ w² to the loss, so the gradient pushes large weights toward zero. Smaller weights make the network less sensitive to small input changes and smoothen the learned function.

Understand Why does inverted dropout divide by p during training? 3 marks

To keep the expected activation unchanged: E[(r a)/p] = a. Then no scaling is needed at test time.

2.9 Dataset augmentation and hyperparameter tuning

Dataset augmentation creates extra training examples by applying label-preserving changes to the data you already have. It is cheap compared with collecting new labelled data and reduces overfitting. Hyperparameter tuning searches training settings such as learning rate and batch size by measuring performance on a validation set. Both techniques are used in almost every deep learning project before the final test evaluation.

You need: regularization and early stopping; Unit 1 cross-validation and overfitting.

Dataset augmentation

Dataset augmentation builds more training examples from existing ones by applying label-preserving changes. It is cheap compared with collecting new labelled data, and it regularises the network so it overfits less. For images, common transforms are horizontal flip, random crop, rotation, colour jitter, and mixup. Text models can use synonym replacement or back-translation: translate a sentence into another language and then back. Speech models can add background noise or change speed and pitch. A change is valid only when a human would still give the same label. Do not augment the test set; the test set should remain realistic. Each original example and its valid variations are all kept in the training set. If you use m independent binary augmentations, each image gives 2ᵐ copies. For N = 1000 images and m = 2, N′ = N × 2ᵐ = 1000 × 2² = 4000 images.

Hyperparameters and validation

Hyperparameters are training settings that do not change during backpropagation. Common hyperparameters are learning rate, mini-batch size, depth, width, dropout probability, and weight decay. Learning rate controls step size; if it is too large, training may diverge, and if it is too small, training is slow. Batch size controls how many examples are used to estimate each gradient. Depth and width control model capacity. Dropout probability and weight decay control regularisation. To choose hyperparameters, evaluate them on a validation set. A simple split uses 80% of the training data for training and 20% for validation. For small datasets, k-fold cross-validation is better: divide the data into k folds, train on k−1 folds, validate on the remaining fold, and repeat k times. Use exactly the same data splits for every setting so results are comparable. Never adjust hyperparameters on the test set; test data is only for the final report.

Tuning methods and run cost

There are three common ways to search hyperparameters: grid search, random search, and Bayesian search. Grid search tries every combination in a Cartesian product of chosen values. If a grid has L learning rates and B batch sizes, it has L × B settings. With F-fold cross-validation, every setting is trained F times, so the total number of runs is R = L × B × F. Random search samples each hyperparameter from a distribution and often finds a good setting with fewer runs because it does not repeat unimportant values. Bayesian search fits a cheap probabilistic model of validation loss after each trial and chooses the next trial where expected improvement is largest. Cost grows quickly: for L = 2, B = 3, F = 5, R = 2 × 3 × 5 = 30. If each run takes t = 10 minutes, total time T = R × t = 30 × 10 = 300 minutes. Use early stopping inside each run to save time; it also acts as a regularizer.

Worked example

Question. A training set has 1000 images. You augment with two independent binary transforms: horizontal flip and Gaussian noise. Create every combination (no change, flip, noise, flip + noise). Then use grid search with 2 learning rates, 3 batch sizes, and 5-fold cross-validation. One training run takes 10 minutes. Find the augmented dataset size, the total number of training runs, and total tuning time.

  1. Each image gives 2² = 4 copies because there are two independent binary augmentations.
  2. Augmented size = 1000 × 4 = 4000 images.
  3. Grid search has 2 × 3 = 6 settings. With 5-fold cross-validation, total runs = 6 × 5 = 30.
  4. Total time = 30 × 10 min = 300 min.

Answer. Augmented size 4000 images, total runs 30, total time 300 minutes.

Exam traps

  • Using vertical flip for handwritten digit 6 or 9 changes the label, so it is not a valid augmentation.
  • Tuning hyperparameters directly on the test set leaks test information and gives over-optimistic results.
  • Counting only the grid size and forgetting the cross-validation folds: total runs = hyperparameter combinations × folds.
  • Augmenting the validation or test folds while keeping the training set fixed changes the data distribution and invalidates evaluation.
  • Treating augmentation as replacement of original data instead of addition: original and augmented copies must all be kept.

Takeaways

  1. Gradient descent is the base optimizer, but one global learning rate and poor loss surfaces can make it slow or stuck.
  2. Mini-batch stochastic gradient descent usually gives the best practical speed-generalization trade-off.
  3. Momentum and Nesterov momentum build velocity from past gradients to damp oscillations and speed descent.
  4. Adaptive optimizers give each weight its own learning rate from gradient history; Adam is a common default.
  5. Vanishing and exploding gradients arise from repeated multiplication through deep layers; ReLU, initialization, and batch normalization reduce them.
  6. Regularization methods such as L2, dropout, and early stopping attack overfitting through different mechanisms.
  7. Data augmentation and hyperparameter tuning are essential parts of training, not optional extras.
  8. Bias-variance tradeoff explains overfitting; validation and regularization help choose the right capacity.

Understand Write the update equations for AdaGrad, RMSProp, and Adam. Compare their per-parameter learning rate behaviour and state one practical scenario for each. 13 marks

Understand Explain the causes of vanishing and exploding gradients in deep feedforward networks. Describe three mitigation strategies: ReLU activation, careful weight initialization, and batch normalization. 13 marks
