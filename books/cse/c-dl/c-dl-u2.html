2.1 Gradient descent and its limitations

Training a network means finding weights that make the loss small. Gradient descent does this by repeating one move: compute the gradient of the loss, which points uphill, and step a little in the opposite direction. Every optimizer in this unit, from SGD to Adam, is this move with a smarter step. Plain gradient descent is slow on large datasets, sensitive to the step size and easily stalled by flat regions, saddle points and narrow valleys; the rest of the unit fixes those limits.

You need: the gradient of a loss from backpropagation (Unit 1, Forward propagation and backpropagation) and the loss functions of Unit 1 (Loss functions and output layers).

The update rule

Collect every weight and bias of the network in one vector w. The loss L(w) is the average error over the training set. Its gradient ∇L(w) is the vector of partial derivatives ∂L/∂wᵢ; it points in the direction in which L rises fastest. Gradient descent moves the other way:

w(t+1) = w(t) − η · ∇L(w(t))

Here t counts steps (iterations), η (eta) is the learning rate, a small positive number such as 0.1 or 0.001, and ∇L(w(t)) is the gradient at the current point. The product η·∇L is the step. Near the minimum the gradient shrinks towards zero, so the steps shrink too and the weights settle.

In the classic form, called batch or full-batch gradient descent, the gradient is the average over all N training examples: ∇L = (1/N) Σᵢ ∇ℓᵢ, where ℓᵢ is the loss on example i. One step therefore needs a forward and backward pass over the whole dataset.

  1. Start from initial weights w(0) (Chapter 2.6).
  2. Run forward and backward passes over all N examples and average the gradients.
  3. Update every weight, w ← w − η·∇L, and repeat until the loss stops falling, the gradient norm is tiny (say ‖∇L‖ < 10⁻⁴) or a step budget runs out.

How the learning rate decides everything

Take the one-weight loss L(w) = (w − 3)², whose minimum is at w = 3. Its gradient is dL/dw = 2(w − 3), so one step gives w(t+1) = w(t) − 2η(w(t) − 3). Measure the distance from the minimum, e(t) = w(t) − 3. Then e(t+1) = (1 − 2η)·e(t): every step multiplies the error by the factor (1 − 2η).

  • 0 < η < 0.5: the factor is between 0 and 1, so w walks smoothly to 3.
  • 0.5 < η < 1: the factor is between −1 and 0, so w jumps across the minimum each step but still closes in.
  • η = 1: the factor is −1; w bounces between the same two points for ever.
  • η > 1: the size of the factor exceeds 1, so the error grows every step and training diverges.

The limit η < 1 comes from the curvature: the second derivative is 2, and descent is stable only when η < 2 / (curvature). A real network has millions of directions with different curvatures, and one η must suit them all.

Worked example

Question. A single weight has loss L(w) = (w − 3)². Starting at w₀ = 0, perform three steps of gradient descent with (a) η = 0.1 and (b) η = 1.1. Give w and L after each step and comment. (6 marks)

Gradient. dL/dw = 2(w − 3). Update: w ← w − η · 2(w − 3).

(a) η = 0.1.

  1. Step 1: gradient at w = 0 is 2(0 − 3) = −6. w₁ = 0 − 0.1 × (−6) = 0.6. L = (0.6 − 3)² = 5.76.
  2. Step 2: gradient = 2(0.6 − 3) = −4.8. w₂ = 0.6 + 0.48 = 1.08. L = (−1.92)² = 3.6864.
  3. Step 3: gradient = 2(1.08 − 3) = −3.84. w₃ = 1.08 + 0.384 = 1.464. L = (−1.536)² = 2.3593.

The error shrinks by 0.8 each step (3 → 2.4 → 1.92 → 1.536), so w(t) = 3 − 3 × 0.8ᵗ. It converges, but slowly: 21 steps to get within 0.03 of 3.

(b) η = 1.1.

  1. Step 1: w₁ = 0 − 1.1 × (−6) = 6.6. L = 3.6² = 12.96.
  2. Step 2: gradient = 2(6.6 − 3) = 7.2. w₂ = 6.6 − 7.92 = −1.32. L = (−4.32)² = 18.6624.
  3. Step 3: gradient = 2(−1.32 − 3) = −8.64. w₃ = −1.32 + 9.504 = 8.184. L = 5.184² = 26.8739.

Comment. The error is multiplied by 1 − 2 × 1.1 = −1.2 each step: it changes sign and grows by 20 %. The loss rises from 9 to 26.87, so the run diverges. Any η below 1 converges for this loss; η = 0.5 would reach w = 3 in one step.

The limitations

Syllabi ask for these as a list ("limitations of the gradient descent learning algorithm"). Each is fixed by a later chapter.

  1. Cost per step. With N = 10 lakh images, one update is a full pass over the data. Fix: stochastic and mini-batch descent (Chapter 2.2).
  2. Choosing η. Too small wastes hours; too large diverges, as in the example. Fix: schedules (Chapter 2.9) and adaptive methods (Chapter 2.4).
  3. Flat regions and plateaus. Where the loss is almost flat the gradient and the steps are tiny, even far from a minimum. Fix: momentum (Chapter 2.3).
  4. Saddle points. Zero gradient, but a minimum in some directions and a maximum in others, like the middle of a horse saddle. In high dimensions they are far more common than bad local minima, and plain descent crawls near them.
  5. Local minima. The loss is not convex, so descent can settle in a minimum that is not the global one. Large networks have many minima of similar quality, so this matters less than students expect.
  6. Ill-conditioning (ravines). If the loss is steep in one direction and shallow in another, say L = w₁² + 50 w₂², η must be small for the steep w₂, so w₁ crawls and the path zigzags across the valley. Fix: momentum and per-weight learning rates (Chapters 2.3 and 2.4).
  7. One learning rate for all weights. Rare features get few gradients and learn slowly. Fix: AdaGrad and its successors (Chapter 2.4).

Deep networks add one more: gradients that vanish or explode through many layers (Chapter 2.5).

Exam traps

  • The sign: the update subtracts η times the gradient. Writing w + η∇L climbs the loss (that is gradient ascent).
  • "Gradient descent always finds the global minimum" is false for neural networks; it is true only for convex losses with a suitable η.
  • A larger learning rate is not always faster: past the stability limit (η < 1 for (w − 3)²) it diverges.
  • Zero gradient does not mean a minimum; at a saddle point the gradient is zero too.
  • "Batch gradient descent" means the gradient over the whole training set, not over a mini-batch. Read the question carefully.

2.2 Stochastic and mini-batch gradient descent

Full-batch gradient descent waits for the whole dataset before it moves once. Stochastic gradient descent (SGD) moves after every single example, and mini-batch gradient descent moves after a small group of examples, typically 32 to 512. The gradient from a few examples is a noisy but fair estimate of the full gradient, and taking many cheap noisy steps beats taking a few exact expensive ones. Mini-batch descent is how essentially every deep network today is trained, on GPUs that process a batch in parallel.

You need: the update rule and full-batch descent (Chapter 2.1).

Three ways to estimate the gradient

Let the training set have N examples and let ℓᵢ(w) be the loss on example i. The three variants differ only in how many examples B go into one gradient estimate:

VariantExamples per update (B)Gradient usedUpdates per epoch
Batch (full-batch) GDB = N(1/N) Σ over all i of ∇ℓᵢ1
Stochastic GD (SGD)B = 1∇ℓᵢ for one example iN
Mini-batch GD1 < B < N(1/B) Σ over the batch of ∇ℓᵢ⌈N / B⌉

Two words to keep straight: an iteration (or step) is one weight update; an epoch is one full pass over the training set. With N examples and batch size B, one epoch has ⌈N/B⌉ iterations; ⌈ ⌉ means round up, because the last batch may be smaller.

The mini-batch gradient is an unbiased estimate of the full gradient: if the batch is drawn at random, its average equals the true gradient on average. Its noise falls as the batch grows; the standard deviation of the estimate shrinks roughly like 1/√B. So going from B = 32 to B = 128 costs four times the computation per step but only halves the noise.

The algorithm

  1. Shuffle the N training examples at the start of each epoch, so batches differ from epoch to epoch and do not follow any order in the file.
  2. Split the shuffled list into batches of B examples.
  3. For each batch: forward pass, loss averaged over the batch, backward pass, then w ← w − η · (batch-average gradient).
  4. After the last batch, the epoch ends; evaluate on the validation set and start the next epoch.

In everyday speech and in libraries, "SGD" usually means mini-batch descent. PyTorch's torch.optim.SGD, for example, simply applies the update to whatever batch you feed it. In an exam, define the term you use.

Why the noise helps, and when it hurts

  • Speed. Many updates per epoch. On 50,000 images with B = 128, mini-batch descent makes 391 updates in the time full-batch descent makes one.
  • Escaping. The noise jiggles the weights out of saddle points and shallow, sharp minima. Minima reached with small batches tend to be wider and to generalize better.
  • Hardware. A GPU does a batch of 128 nearly as fast as a batch of 1, so pure SGD (B = 1) wastes the hardware. This is why mini-batches won.
  • Memory. Only one batch of activations must be stored for backpropagation, so a dataset of any size fits.
  • The cost. Because the gradient is noisy, the loss curve is jagged and the weights never settle exactly; they jitter around the minimum. The usual fix is to lower η over time (a schedule, Chapter 2.9).

Choosing the batch size

The batch size is a hyperparameter (Chapter 2.9). Powers of two (32, 64, 128, 256) suit GPU memory layouts. Small batches give more noise, more updates and often better generalization; large batches give smoother gradients, better hardware use and fewer updates. A common rule of thumb, the linear scaling rule, says that if you multiply B by k you can multiply η by about k as well, with a few warm-up epochs at the start. Batch size also interacts with batch normalization (Chapter 2.7), which needs batches big enough for a reliable mean.

Worked example

Question. A dataset has 50,000 training images. How many iterations are in one epoch with B = 128, and how many updates happen in 10 epochs? How big is the last batch? (3 marks)

50,000 / 128 = 390.625, so one epoch has ⌈390.625⌉ = 391 iterations. 390 full batches hold 390 × 128 = 49,920 images, so the last batch has 50,000 − 49,920 = 80 images. Ten epochs give 391 × 10 = 3,910 updates. Full-batch descent would make only 10.

Exam traps

  • Epoch versus iteration: an epoch is a pass over the data; an iteration is one update. With B = 1 there are N iterations per epoch.
  • "SGD uses one example" is the textbook definition, but libraries call mini-batch training SGD. State your meaning.
  • Forgetting to shuffle: if the data is sorted by class, each batch holds one class and training swings wildly.
  • Average, not sum: the batch gradient is divided by B. Summing makes the step size depend on B.
  • The noise does not make SGD wrong: its gradient is unbiased; only its variance is higher.

2.3 Momentum and Nesterov accelerated gradient descent

Plain gradient descent forgets its past: each step depends only on the current gradient. Momentum gives the weights a memory. It keeps a running "velocity" that adds up past gradients, so steps grow along directions where the gradient keeps pointing the same way and cancel along directions where it keeps flipping. Think of a ball rolling down a hill: it gathers speed on a long slope, rolls across small flat patches and does not rattle from side to side in a narrow valley. Nesterov accelerated gradient (NAG) is a refinement that looks ahead before it steps, so it brakes earlier and overshoots less.

You need: gradient descent and its limitations, especially plateaus and ravines (Chapter 2.1), and mini-batch gradients (Chapter 2.2).

Momentum-based gradient descent

Momentum keeps a vector v of the same size as w, set to zero at the start. Each step:

v(t) = β · v(t−1) + η · ∇L(w(t−1))
w(t) = w(t−1) − v(t)

Here v(t) is the velocity (the update actually applied), β (beta, also written γ) is the momentum coefficient, usually 0.9, and η is the learning rate. Unrolling the first line shows what the velocity holds:

v(t) = η·g(t) + β·η·g(t−1) + β²·η·g(t−2) + …

where g(t) is the gradient used at step t. The update is an exponentially weighted sum of all past gradients: the newest counts fully, one step older counts 0.9, two steps older 0.81, and so on. Two effects follow.

  • Acceleration. If the gradient is the same g every step, v approaches η·g / (1 − β). With β = 0.9 that is 10 times the plain step. Long gentle slopes and plateaus are crossed quickly.
  • Damping. In a ravine the gradient across the valley flips sign each step, so those terms cancel in the sum; the component along the valley floor keeps the same sign and adds up. The zigzag shrinks.

Some books write the same idea as v ← βv − η∇L and w ← w + v. The sign of v is flipped but the weights follow exactly the same path. Use one form and stay with it.

Nesterov accelerated gradient (NAG)

Momentum has a flaw: it computes the gradient where the weights are now, then adds the old velocity on top. Near a minimum the velocity carries the ball past it before the gradient can react. Yurii Nesterov's idea (1983) is to compute the gradient at the point where the velocity is about to take you, the look-ahead point:

w_look = w(t−1) − β · v(t−1)
v(t)   = β · v(t−1) + η · ∇L(w_look)
w(t)   = w(t−1) − v(t)

If the look-ahead point is already past the minimum, its gradient points back, and the new velocity is smaller at once. NAG is "look before you leap"; momentum is "leap, then look".

  1. Move temporarily by the old velocity: w_look = w − βv.
  2. Compute the gradient at w_look (one forward and backward pass, the same cost as momentum).
  3. Update the velocity with that gradient: v ← βv + η∇L(w_look).
  4. Move the real weights: w ← w − v.

Choosing β and what to expect

β = 0.9 is the usual default, sometimes 0.99 for very noisy gradients. A larger β means a longer memory (about 1/(1 − β) steps) and more overshoot. Momentum also smooths the noise of mini-batch gradients from Chapter 2.2, because it averages over many batches. In this one-dimensional bowl plain descent with a good η is already fine, so the overshoot looks like a cost; in real networks with plateaus and ravines the acceleration wins clearly. SGD with Nesterov momentum is still a strong choice for training image classifiers.

Exam traps

  • NAG evaluates the gradient at w − βv, not at w. Writing ∇L(w) in the NAG formula turns it back into plain momentum.
  • Momentum does not cost an extra gradient computation; neither does NAG. Each needs one gradient per step and one extra vector v in memory.
  • The velocity starts at zero, so the first step of momentum (and of NAG) equals the plain gradient-descent step.
  • Momentum can overshoot the minimum; "momentum always converges faster" is not true for every step.
  • The steady-state step is η·g/(1 − β), not η·g·β.

2.4 Adaptive optimizers: AdaGrad, RMSProp and Adam

Gradient descent and momentum use one learning rate for every weight. Adaptive optimizers give each weight its own effective learning rate, worked out from the size of that weight's past gradients: weights with large, frequent gradients take smaller steps, weights with small or rare gradients take larger ones. AdaGrad started the idea, RMSProp fixed its main flaw, and Adam combined RMSProp with momentum. Adam is the default optimizer in most deep learning work today, from image models to large language models.

You need: momentum and exponentially weighted sums (Chapter 2.3). All operations below are element-wise: each weight has its own accumulators, and g² means each gradient component squared.

AdaGrad: divide by the history of gradients

AdaGrad (Duchi, Hazan and Singer, 2011) keeps, for each weight, the running sum of its squared gradients:

G(t) = G(t−1) + g(t)²
w(t) = w(t−1) − η · g(t) / (√G(t) + ε)

g(t) is the current gradient, G(t) the sum of all squared gradients so far (G(0) = 0), and ε a tiny number such as 10⁻⁸ that prevents division by zero. A weight that has seen big gradients has a big √G and so takes small steps; a weight tied to a rare feature (a rare word in a text model) has a small √G and takes big steps when it finally gets a gradient. That is why AdaGrad suits sparse data.

Its flaw: G only grows. With a steady gradient, √G grows like √t, so the step shrinks like 1/√t and eventually becomes too small to learn anything. On long deep-network runs AdaGrad stops early.

RMSProp: forget the distant past

RMSProp (proposed by Geoffrey Hinton in a lecture course, around 2012) replaces the sum by an exponentially weighted average, so old gradients fade out:

E(t) = ρ · E(t−1) + (1 − ρ) · g(t)²
w(t) = w(t−1) − η · g(t) / (√E(t) + ε)

ρ (rho, the decay rate) is usually 0.9; √E is the root of the mean of the squares, the "RMS" in the name. E tracks the recent size of the gradient, so the effective step settles to a steady value instead of dying. RMSProp works well on the non-stationary problems of deep learning and on recurrent networks.

Adam: momentum plus RMSProp, with bias correction

Adam (Kingma and Ba, 2015; the name comes from "adaptive moment estimation") keeps two averages for each weight: m, an average of gradients (the first moment, like momentum), and v, an average of squared gradients (the second moment, like RMSProp).

m(t) = β₁ · m(t−1) + (1 − β₁) · g(t)
v(t) = β₂ · v(t−1) + (1 − β₂) · g(t)²
m̂(t) = m(t) / (1 − β₁ᵗ)        v̂(t) = v(t) / (1 − β₂ᵗ)
w(t) = w(t−1) − η · m̂(t) / (√v̂(t) + ε)

The defaults from the paper are β₁ = 0.9, β₂ = 0.999, ε = 10⁻⁸, with η = 0.001 a common starting learning rate. β₁ᵗ means β₁ to the power t, the step number.

Why bias correction? m and v start at 0, so for the first steps they are pulled towards zero. At t = 1, m(1) = 0.1·g, only a tenth of the gradient. Dividing by (1 − β₁ᵗ) = 0.1 restores it to g. As t grows, β₁ᵗ → 0 and the correction fades away. The same holds for v with β₂. Without the correction the first steps would be the wrong size; RMSProp, which has no correction, takes oversized early steps for exactly this reason (Figure 2.4.1).

Worked example

Question. A weight starts at w₀ = 1. Its gradients on two steps are g₁ = 4 and g₂ = 2. Using Adam with η = 0.1, β₁ = 0.9, β₂ = 0.999 and ε negligible, find w after each step. Then give the first AdaGrad and RMSProp (ρ = 0.9) step for g₁ = 4 with the same η. (8 marks)

2.5 Vanishing and exploding gradients

Backpropagation multiplies one factor per layer as it carries the gradient from the output back to the input. If those factors are mostly smaller than 1, the gradient shrinks exponentially and the early layers stop learning: the vanishing gradient problem. If they are mostly larger than 1, the gradient grows exponentially and the weights jump to huge values or NaN: the exploding gradient problem. This one fact explains why deep networks were hard to train before about 2010, and why ReLU, careful initialization, batch normalization and residual connections matter.

You need: the chain rule in backpropagation (Unit 1, Forward propagation and backpropagation) and the sigmoid, tanh and ReLU functions (Unit 1, Activation functions).

Where the product comes from

Take a chain of L layers, one neuron each, to see the mechanism with scalars. Layer k computes zₖ = wₖ·aₖ₋₁ + bₖ and aₖ = f(zₖ), where f is the activation, wₖ the weight and aₖ the output. By the chain rule the gradient of the loss with respect to the first layer's output is

∂L/∂a₁ = ∂L/∂a_L · Π (k = 2 to L) [ f′(zₖ) · wₖ ]

Each layer contributes one factor f′(zₖ)·wₖ. In a real network the scalars become matrices (the weight matrix times a diagonal matrix of activation derivatives), and the size of the product depends on how much those matrices stretch or shrink vectors, but the conclusion is the same: the gradient at layer 1 is a product of L − 1 factors, and a product of many numbers is either tiny or huge unless the numbers stay close to 1.

Why sigmoid makes gradients vanish

The sigmoid σ(z) = 1/(1 + e⁻ᶻ) has derivative σ′(z) = σ(z)(1 − σ(z)). Its largest value is at z = 0, where σ = 0.5 and σ′ = 0.5 × 0.5 = 0.25. For |z| large the neuron saturates: σ is near 0 or 1 and σ′ is near 0 (at z = 5, σ′ ≈ 0.0066). So with weights near 1, each sigmoid layer multiplies the gradient by at most 0.25. Tanh is better (its derivative peaks at 1) but still saturates. Vanishing gradients mean the layers near the input learn almost nothing, while the layers near the output learn; the network behaves like a shallow one.

The same problem appears in recurrent networks, where the "layers" are time steps; Unit 4 (Backpropagation through time, LSTM) treats it there.

Why gradients explode

If the factors exceed 1, for example ReLU units (derivative 1 when active) with weights of 2, each layer doubles the gradient. Symptoms: the loss suddenly jumps to a huge value or becomes NaN, and the weights become very large. Exploding gradients are most common in recurrent networks and in deep networks with poorly scaled initial weights.

Worked example

Question. A chain network has 10 hidden layers, one neuron per layer, all weights wₖ = w and every pre-activation zₖ = 0 for this input. Find the factor by which the gradient is multiplied between the output and the first layer for (a) sigmoid, w = 1; (b) ReLU, w = 1 (active units); (c) ReLU, w = 2. Then (d) clip a gradient vector g = (30, 40) to a maximum norm of 5. (8 marks)

  1. (a) Each factor is σ′(0)·w = 0.25 × 1 = 0.25. Ten factors: 0.25¹⁰ = 9.54 × 10⁻⁷. A gradient of 1 at the output arrives as less than one millionth. Even after 5 layers it is 0.25⁵ = 0.00098, about 1/1000.
  2. (b) ReLU's derivative is 1 for z > 0, so each factor is 1 × 1 = 1 and the product is 1¹⁰ = 1. The gradient passes unchanged. (Strictly, ReLU′(0) is undefined; libraries use 0 or 1. Take z slightly above 0.)
  3. (c) Each factor is 1 × 2 = 2. Ten factors: 2¹⁰ = 1024. A gradient of 1 becomes 1024; with η = 0.01 the first layer's weight would jump by about 10 in one step.
  4. (d) ‖g‖ = √(30² + 40²) = √2500 = 50 > 5. Scale by 5/50 = 0.1: g_clipped = (3, 4), whose norm is 5. The direction is unchanged; only the length is capped.

Mitigation

Each remedy keeps the per-layer factor close to 1, from a different side. Some syllabi list this as "mitigation" or "heuristics for avoiding bad local minima and for faster training".

  1. ReLU and its variants (Leaky ReLU, ELU, GELU): derivative 1 for positive inputs, no saturation on that side. ReLU's arrival around 2010–2012 was a big reason deep networks became trainable. Its own risk is "dying ReLU", units stuck at z < 0 with zero gradient; Leaky ReLU keeps a small slope such as 0.01 there.
  2. Careful weight initialization (Xavier, He): choose the scale of the starting weights so that the signal and gradient variance stay constant across layers (Chapter 2.6).
  3. Batch normalization: re-centre and re-scale each layer's inputs so that pre-activations stay out of saturation (Chapter 2.7).
  4. Residual (skip) connections: aₖ = aₖ₋₁ + F(aₖ₋₁) adds an identity path, so the per-layer factor becomes 1 + (something) and the gradient can flow straight back. This is ResNet (Unit 3, Deeper architectures: Inception and ResNet).
  5. Gated units in recurrent networks: LSTM and GRU (Unit 4).
  6. Gradient clipping for exploding gradients: if ‖g‖ > c, replace g by c·g/‖g‖, as in part (d). Clipping does nothing for vanishing gradients.
  7. Smaller learning rate and adaptive optimizers soften the effect of a large gradient but do not cure the cause.

Exam traps

  • The maximum of the sigmoid derivative is 0.25, not 0.5 (0.5 is the value of σ at 0).
  • Vanishing gradients hit the early layers (near the input), not the output layers.
  • Gradient clipping fixes exploding gradients only; it cannot enlarge a vanishing one.
  • ReLU solves vanishing for active units but creates dead units; do not claim it "removes all gradient problems".
  • Clipping by norm keeps the direction; clipping each component to [−c, c] can change the direction. Say which one you use.

2.6 Weight initialization methods

Before the first gradient step, every weight needs a starting value. The choice decides whether training starts at all. All zeros makes every neuron in a layer identical for ever; weights that are too small shrink the signal layer by layer until it vanishes; weights that are too large blow it up or saturate every neuron. Xavier (Glorot) and He initialization pick the spread of random starting weights from the layer's size so that the signal keeps the same variance from layer to layer. It costs one line of code and is a main defence against the vanishing and exploding gradients of Chapter 2.5.

You need: vanishing and exploding gradients (Chapter 2.5), and mean and variance of a random variable.

Why not zeros, and why not just "small random"

Symmetry. If every weight of a layer starts at the same value (zero or any constant), every neuron of that layer computes the same output, receives the same gradient and changes in the same way. They stay identical: a layer of 256 neurons behaves like one neuron. Random starting values break the symmetry. Biases do not cause this problem and are usually set to 0.

Scale. Random is not enough; the spread matters. A neuron computes z = Σᵢ wᵢxᵢ over its n_in inputs (n_in is the fan-in; the number of neurons it feeds, n_out, is the fan-out). If the weights and inputs are independent with mean zero,

Var(z) = n_in · Var(w) · Var(x)

So each layer multiplies the variance of the signal by n_in·Var(w). If that product is below 1 the signal shrinks geometrically through the layers; above 1 it grows. The same factor (with n_out in place of n_in) applies to the gradients flowing backwards.

The three standard rules

  • LeCun initialization: set n_in·Var(w) = 1, so Var(w) = 1/n_in. Keeps the forward signal steady for linear or tanh-like units.
  • Xavier (Glorot) initialization (Glorot and Bengio, 2010): the forward pass wants Var(w) = 1/n_in and the backward pass wants 1/n_out; Xavier takes the compromise Var(w) = 2/(n_in + n_out). Use with sigmoid, tanh and softmax layers.
  • He (Kaiming) initialization (He et al., 2015): ReLU sets half its inputs to zero, which halves the variance passed on. To make up for it, double the variance: Var(w) = 2/n_in. Use with ReLU and its variants.

Each rule comes in a normal and a uniform form. For a normal distribution N(0, σ²) take σ = √Var. A uniform distribution U[−a, a] has variance a²/3, so the limit is a = √(3·Var); for Xavier that gives the familiar a = √(6/(n_in + n_out)).

2.7 Batch normalization

As a network trains, the weights of every layer change, so the inputs that each later layer receives keep shifting in mean and spread. Batch normalization (BN) fixes the scale at every layer: for each neuron it subtracts the mini-batch mean and divides by the mini-batch standard deviation, then lets the network re-scale and re-shift the result with two learned numbers, γ and β. Introduced by Ioffe and Szegedy in 2015, it lets networks train with much higher learning rates, makes them far less sensitive to initialization, and adds a mild regularizing effect. It is a standard layer in convolutional networks.

You need: mini-batches (Chapter 2.2), saturation and vanishing gradients (Chapter 2.5) and initialization (Chapter 2.6).

The transform, step by step

Take one neuron (one feature) and a mini-batch of m examples. Its pre-activations on the batch are x₁, x₂, …, x_m. BN computes:

  1. Batch mean: μ_B = (1/m) Σᵢ xᵢ.
  2. Batch variance: σ²_B = (1/m) Σᵢ (xᵢ − μ_B)².
  3. Normalize: x̂ᵢ = (xᵢ − μ_B) / √(σ²_B + ε). Now the batch has mean 0 and variance (almost) 1. ε, such as 10⁻⁵, guards against division by zero.
  4. Scale and shift: yᵢ = γ·x̂ᵢ + β, where γ (gamma) and β (beta) are trainable parameters of this neuron, learned by backpropagation like weights.

Why steps 4 and the two parameters? Forcing every layer to mean 0 and variance 1 could limit what the network can represent; a sigmoid fed only values near 0 would act almost linearly. γ and β give that freedom back. If the network learns γ = √(σ²_B + ε) and β = μ_B, BN becomes the identity; usually it learns something in between. γ starts at 1 and β at 0. Because β already shifts the output, the bias of the layer before BN is redundant and is usually dropped.

Each BN layer has 2 trainable parameters per neuron (γ, β) and stores 2 more non-trainable numbers per neuron (the running mean and variance, below). A BN layer after 256 neurons adds 512 trainable parameters.

Worked example

Question. A neuron produces the values 2, 4, 6, 8 on a mini-batch of four examples. Its BN parameters are γ = 2 and β = 1; take ε as negligible. (a) Find the BN outputs. (b) At test time the stored running mean is 5 and running variance 5; find the output for a single test input x = 7. (6 marks)

(a) Training.

  1. μ_B = (2 + 4 + 6 + 8)/4 = 20/4 = 5.
  2. σ²_B = [(2 − 5)² + (4 − 5)² + (6 − 5)² + (8 − 5)²]/4 = (9 + 1 + 1 + 9)/4 = 5. √5 = 2.236.
  3. x̂ = (−3, −1, 1, 3)/2.236 = (−1.342, −0.447, 0.447, 1.342). Check: mean 0, and (1.8 + 0.2 + 0.2 + 1.8)/4 = 1, variance 1.
  4. y = 2x̂ + 1 = (−1.683, 0.106, 1.894, 3.683).

The outputs have mean β = 1 and standard deviation γ = 2, whatever the raw values were.

(b) Inference. A single test example has no batch to average over, so BN uses the stored statistics: x̂ = (7 − 5)/√5 = 2/2.236 = 0.894, y = 2 × 0.894 + 1 = 2.789.

Training versus inference

During training BN uses each mini-batch's own μ_B and σ²_B, and also updates a running average of them, for example running_mean ← 0.9 × running_mean + 0.1 × μ_B (the same for the variance). At inference it switches to those running values, so the output for an example no longer depends on which other examples share its batch, and a single example can be processed. In PyTorch this switch is model.train() versus model.eval(); forgetting model.eval() before testing is a classic bug that gives unstable predictions.

Where to put it: the original paper places BN after the linear or convolution step and before the activation (linear → BN → ReLU), and that is what most exam answers expect; placing it after the activation also works in practice. In a convolutional layer, BN normalizes per channel, averaging over the batch and over all spatial positions, so one γ and one β serve each channel.

Why it helps, and its limits

  • Higher learning rates. Pre-activations stay in a fixed range whatever the weights' scale, so larger steps do not push neurons into saturation or blow up activations. The original paper reported reaching the same accuracy on an ImageNet model with 14 times fewer training steps.
  • Less sensitive to initialization. A badly scaled layer is re-scaled at once.
  • Mild regularization. μ_B and σ_B change from batch to batch, which adds noise to each example's output, a little like dropout (Chapter 2.8).
  • The explanation. The paper's motivation was reducing internal covariate shift, the change in each layer's input distribution during training. Later work (Santurkar et al., 2018) argued that the main benefit is a smoother loss surface, which makes gradients more predictable. Exam answers usually give the original explanation; mention that it is debated.
  • Limits. Very small batches (m = 2 to 4) give noisy statistics and hurt accuracy. Recurrent networks and Transformers use layer normalization instead, which normalizes across the features of one example rather than across the batch (Unit 5).

Exam traps

  • BN normalizes each feature over the batch, not each example over its features (that is layer normalization).
  • At test time BN uses running averages, not the test batch's statistics.
  • γ and β are learned; μ_B and σ_B are computed. Do not list μ and σ as trainable parameters.
  • The batch variance divides by m, not m − 1, in the transform.
  • BN does not replace good initialization or regularization entirely; it reduces the need for them.

2.8 Regularization: weight penalties, dropout and early stopping

A deep network has enough parameters to memorize its training set, noise and all, and then fails on new data: it overfits. Regularization is any change to training that lowers the error on unseen data, even if it raises the training error a little. This chapter covers the three methods every syllabus asks for: weight penalties (L2 and L1), which keep weights small; dropout, which randomly switches off neurons so that none can rely on another; and early stopping, which ends training when the validation loss stops improving.

You need: overfitting and the bias-variance trade-off (Unit 1, Generalization, overfitting and the bias-variance trade-off; not re-taught here) and the gradient descent update (Chapter 2.1).

Weight penalties: L2 (weight decay) and L1

Add a term to the loss that grows with the size of the weights:

L2:  L̃(w) = L(w) + (λ/2) · Σ wᵢ²
L1:  L̃(w) = L(w) + λ · Σ |wᵢ|

L is the data loss, L̃ the regularized loss and λ (lambda) the regularization strength, a hyperparameter such as 10⁻⁴ to 10⁻². Biases are usually not penalized. Smaller weights give a smoother function that cannot bend to fit every noisy point.

L2 as weight decay. The gradient of (λ/2)w² is λw, so the update becomes

w ← w − η(∇L + λw) = (1 − ηλ)·w − η∇L

Every step first shrinks each weight by the factor (1 − ηλ), then takes the usual step: the weights "decay" towards zero unless the data keeps pushing them up. Large weights shrink fastest. L2 is the same as placing a Gaussian prior on the weights.

L1 gives sparsity. The gradient of λ|w| is λ·sign(w): a fixed push of size λ towards zero however small w is. Small weights are driven to exactly zero, so L1 performs feature selection. L2's push λw fades as w shrinks, so L2 weights become small but rarely exactly zero.

Dropout

Dropout (Srivastava, Hinton and colleagues; journal paper 2014) works on the neurons rather than the loss. On each training step, every unit of a layer is kept with probability p (the keep probability) and set to zero otherwise, with a fresh random mask every step. A neuron cannot rely on any particular other neuron being present, so it learns features that are useful on their own; this prevents co-adaptation. Each step trains a different thinned sub-network, and the full network at test time acts like an average of all of them, an inexpensive kind of ensemble.

  1. Training: draw a mask mᵢ ∈ {0, 1} with P(mᵢ = 1) = p for each unit.
  2. Multiply: h̃ᵢ = mᵢ·hᵢ / p. Dividing by p is inverted dropout; it keeps the expected value of each unit equal to hᵢ.
  3. Backpropagate only through the kept units.
  4. Testing: use all units with no mask and no scaling. (In the original, non-inverted form, nothing is scaled in training and outputs are multiplied by p at test time; the result is the same.)

Typical drop rates are 0.5 for large fully connected layers and 0.1 to 0.3 elsewhere. Be careful with the wording: PyTorch's nn.Dropout(p=0.5) takes the drop probability, while many textbooks write p for the keep probability.

Early stopping

Training loss keeps falling as training goes on, but validation loss falls, reaches a minimum and then rises as the network starts to memorize. Early stopping keeps the weights from the best validation epoch.

  1. Hold out a validation set. After each epoch, compute the validation loss.
  2. If it is the best so far, save a copy of the weights.
  3. If it has not improved for patience epochs in a row (for example 3), stop.
  4. Restore the saved best weights.

Early stopping is free, needs no change to the loss, and limits how far the weights can travel from their small initial values, which for simple models has an effect similar to L2. The number of epochs becomes a hyperparameter chosen by the data itself.

Worked example

Question. (a) A weight w = 0.5 has data gradient 0.2; η = 0.1, λ = 0.01. Find the updated weight with no penalty, with L2 and with L1. (b) A small weight w = 0.002 gets no data gradient. Apply two steps of each penalty. (c) A layer outputs h = (2.0, 0.5, 1.0, 3.0); apply inverted dropout with p = 0.5 and mask (1, 0, 0, 1). (d) Validation losses for epochs 1–8 are 0.90, 0.72, 0.61, 0.55, 0.53, 0.54, 0.56, 0.59. With patience 3, when does training stop and which weights are kept? (10 marks)

  1. (a) No penalty: 0.5 − 0.1 × 0.2 = 0.48. L2: 0.5 − 0.1 × (0.2 + 0.01 × 0.5) = 0.5 − 0.0205 = 0.4795. L1: 0.5 − 0.1 × (0.2 + 0.01) = 0.479.
  2. (b) L2: w ← (1 − 0.001)w: 0.002 → 0.001998 → 0.001996, almost unchanged. L1: each step subtracts ηλ = 0.001: 0.002 → 0.001 → 0. L1 removes the weight; L2 keeps it.
  3. (c) Masked: (2.0, 0, 0, 3.0). Divide by 0.5: (4.0, 0, 0, 6.0). Expected value of unit 1: 0.5 × 4.0 + 0.5 × 0 = 2.0, the original value.
  4. (d) The best is 0.53 at epoch 5. Epochs 6, 7, 8 do not improve on it (0.54, 0.56, 0.59), so after epoch 8 the patience of 3 is used up: stop after epoch 8 and restore the epoch-5 weights.

Other regularizers in brief

Adding Gaussian noise to inputs or weights; label smoothing (training on 0.9 instead of 1 for the true class); max-norm constraints on each neuron's weight vector; and data augmentation (Chapter 2.9) all regularize. Adversarial training, listed in some syllabi, trains on inputs nudged in the direction that most increases the loss, for example x′ = x + ε·sign(∇ₓL) with a small ε such as 0.01; it makes the model robust to tiny, deliberate perturbations. Batch normalization also regularizes slightly (Chapter 2.7). Regularized autoencoders are in Unit 6.

Exam traps

  • L1 gives sparse weights (exact zeros); L2 gives small weights. The reason is the constant λ·sign(w) push versus the shrinking λw push.
  • Dropout is switched off at test time. With inverted dropout no test-time scaling is needed.
  • "p" can mean keep or drop probability; state which. p_keep = 0.8 means 20 % of units are dropped.
  • Early stopping monitors the validation loss, never the training loss or the test set.
  • The L2 gradient is λw for the penalty (λ/2)Σw²; if the penalty is written λΣw², the gradient is 2λw.

2.9 Dataset augmentation and hyperparameter tuning

The surest cure for overfitting is more data. Dataset augmentation manufactures it: it makes new training examples from old ones by transformations that do not change the label, such as flipping or cropping a photo. Hyperparameter tuning is the other half of making a network work in practice: choosing the learning rate, batch size, regularization strength and the rest by trying settings on a validation set. Together they decide much of a real model's final accuracy.

You need: regularization and validation sets (Chapter 2.8) and the optimizers' settings (Chapters 2.2 to 2.4).

Dataset augmentation

An augmentation is a random transformation T applied to a training input x, keeping its label y: the network trains on (T(x), y). Each epoch draws fresh random transformations, so the network rarely sees exactly the same input twice. This teaches invariance: a cat shifted, mirrored or slightly darker is still a cat.

DataCommon augmentations
Imageshorizontal flip, random crop with padding, small rotation and scaling, colour jitter (brightness, contrast), Gaussian noise, cutout (blank out a patch), mixup (blend two images and their labels)
Textsynonym replacement, random word deletion or swap, back-translation (translate to Hindi and back to English)
Audiotime shift, speed change, background noise, masking bands of the spectrogram (SpecAugment)

Rules that examiners test:

  • The transformation must keep the label. Rotating a handwritten 6 by 180° makes a 9; flipping a road sign with an arrow changes its meaning. Choose transforms that suit the task.
  • Augment the training set only. Validation and test data stay untouched, or the scores no longer measure the real task.
  • Augmentation is done on the fly, inside the data loader, so storage does not grow.

Worked example

Question. A dataset has 50,000 colour images of 32 × 32 pixels. Each training image is padded by 4 pixels on every side, randomly cropped back to 32 × 32 and flipped horizontally with probability 0.5. How many distinct versions of one image can the network see, and how many training views does the dataset give in total? (4 marks)

  1. Padded size: 32 + 4 + 4 = 40 pixels each way.
  2. A 32-wide window fits in 40 pixels at offsets 0, 1, …, 8: that is 40 − 32 + 1 = 9 positions horizontally and 9 vertically, so 9 × 9 = 81 crops.
  3. Each crop is used flipped or not: 81 × 2 = 162 versions per image.
  4. Whole dataset: 50,000 × 162 = 8,100,000, about 81 lakh distinct training views from 50,000 stored images.

The views are correlated, so they are worth less than 81 lakh new photos, but they cut overfitting markedly.

Hyperparameters and how to search them

Parameters (weights, biases, BN's γ and β) are learned by gradient descent. Hyperparameters are set before training and are not learned by it: the learning rate η and its schedule, batch size, number of epochs, momentum β, Adam's β₁ and β₂, weight decay λ, dropout rate, number of layers and units, the activation and the optimizer itself. They are chosen by training with each setting and comparing scores on the validation set; the test set is used once, at the very end. For small datasets, k-fold cross-validation (train on k − 1 folds, validate on the remaining one, rotate, average) gives a steadier score.

  1. Manual search: change one thing, watch the loss curves. Good for learning; slow and biased.
  2. Grid search: pick a few values for each hyperparameter and try every combination. The number of trials multiplies: 4 hyperparameters with 5 values each is 5⁴ = 625 runs.
  3. Random search: draw each trial's values at random from ranges. Usually better than grid for the same budget (Bergstra and Bengio, 2012), because only a few hyperparameters matter much, and random search tries a new value of each important one on every trial (Figure 2.9.2).
  4. Bayesian optimization: fit a model of "score versus settings" to the trials so far and choose the next trial where improvement looks most likely. Tools: Optuna, Keras Tuner, Ray Tune.
  5. Early-stopping schemes such as successive halving and Hyperband start many trials, train each briefly and keep only the best half for longer.

Search scale-type hyperparameters on a log scale: draw η = 10ᵘ with u uniform between −5 and −1, so 10⁻⁵ to 10⁻⁴ is explored as well as 0.01 to 0.1. Tune in order of importance: learning rate first, then batch size and schedule, then regularization (λ, dropout), then architecture.

Learning-rate schedules

The learning rate itself is usually varied during training. Step decay multiplies η by a factor at fixed epochs: η₀ = 0.1, × 0.1 every 30 epochs gives 0.01 at epoch 45. Exponential decay uses ηₜ = η₀·kᵗ. Cosine annealing uses ηₜ = η_min + ½(η_max − η_min)(1 + cos(πt/T)) over T epochs, gliding from η_max to η_min; at t = T/2 it is exactly half-way. Warm-up raises η from near zero over the first few hundred or thousand steps, which helps Adam and large batches. Reduce on plateau cuts η by, say, 10 when validation loss stalls.

Worked example

Question. Each training run takes 20 minutes. (a) How long does a grid search over 4 hyperparameters with 5 values each take? (b) Show that 60 random trials have about a 95 % chance that at least one lands in the best 5 % of the search space, and give the time. (5 marks)

  1. (a) 5⁴ = 625 runs × 20 min = 12,500 min = 208.3 hours, more than 8 days on one GPU.
  2. (b) Each random trial misses the best 5 % with probability 0.95. All 60 miss with probability 0.95⁶⁰ = e^(60 × ln 0.95) = e^(−3.078) = 0.046.
  3. So P(at least one in the top 5 %) = 1 − 0.046 = 0.954, about 95 %.
  4. Time: 60 × 20 = 1,200 min = 20 hours, under a tenth of the grid.

Exam traps

  • Hyperparameters are tuned on the validation set, never on the test set; tuning on test data makes the reported accuracy optimistic.
  • Augmentation applies only to training data, and only label-preserving transforms are allowed.
  • The learning rate is searched on a log scale, not a linear one.
  • Weights are parameters, not hyperparameters; the learning rate, batch size and dropout rate are hyperparameters.
  • Grid search cost is the product of the numbers of values, not the sum.

Momentum with the gradient taken at the look-ahead point w − βv.
AdaGrad
Adaptive optimizer dividing each step by the root of the sum of past squared gradients.
RMSProp
Adaptive optimizer dividing by the root of an exponentially weighted average of squared gradients.
Adam
Optimizer combining momentum (first moment) and RMSProp (second moment) with bias correction.
Bias correction
Dividing Adam's moment estimates by 1 − βᵗ to undo their pull towards zero at the start.
Vanishing gradient
Gradients that shrink exponentially through layers, so early layers barely learn.
Exploding gradient
Gradients that grow exponentially through layers, causing huge updates or NaN.
Gradient clipping
Rescaling a gradient whose norm exceeds a threshold down to that threshold.
Fan-in, fan-out
The number of inputs to, and outputs from, a neuron or layer.
Xavier (Glorot) initialization
Random weights with variance 2/(n_in + n_out); for sigmoid and tanh.
He (Kaiming) initialization
Random weights with variance 2/n_in; for ReLU.
Symmetry breaking
Using random initial weights so neurons in a layer learn different features.
Batch normalization
Normalizing each feature over the mini-batch, then scaling by γ and shifting by β.
Internal covariate shift
The change in a layer's input distribution as earlier layers' weights change.
Weight decay
Shrinking weights by (1 − ηλ) each step; the update form of L2 regularization.
Dropout
Randomly zeroing units during training with a fresh mask each step.
Early stopping
Stopping training when validation loss stops improving and keeping the best weights.
Patience
Number of non-improving epochs allowed before early stopping acts.
Data augmentation
Creating extra training examples by label-preserving transformations.
Hyperparameter
A setting chosen before training (η, batch size, λ, dropout rate), tuned on validation data.
Learning-rate schedule
A rule that changes η during training, such as step decay, cosine annealing or warm-up.
