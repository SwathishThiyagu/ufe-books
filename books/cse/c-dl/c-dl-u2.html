2.1 Gradient descent and its limitations

Gradient descent is the engine under every trained network. It measures the slope of the loss with respect to each parameter and moves every parameter a small step in the opposite direction. One fixed step size, the learning rate, serves all of them. Repeat a few thousand times and the loss falls. It exists because the loss of a deep network has millions of dimensions and no closed-form minimum. Training a cheque-clearing image classifier for a bank, or a language model, starts here. This chapter gives the rule, the loop, and the reasons the plain version is not enough.

You need Unit 1: loss functions, forward propagation and backpropagation, and the idea of a parameter vector.

The update rule

Stack every weight matrix and bias vector of the model into one vector θ. For a network, θ is simply all the trainable numbers in a single column. Write L(θ) for the average loss over the N training samples.

L(θ) = (1/N) Σᵢ₌₁ᴺ ℓ(f(xᵢ; θ), yᵢ)

xᵢ is the i-th input, yᵢ its target, f(xᵢ; θ) the network output, ℓ the per-sample loss (cross-entropy or squared error, Unit 1), and N the number of training samples.

The gradient ∇L(θ) collects the partial derivatives ∂L/∂θⱼ. It points uphill, the direction in which L rises fastest, so we step the other way.

θ ← θ − η∇L(θ)

η is the learning rate, a positive scalar. Because ∇L is measured in units of loss per unit of θ, η is measured in units of θ per unit of gradient (that is, θ² per unit of loss). Only when the gradient is dimensionless do η and θ share a unit. Example: with θ in volts and a dimensionless loss, η is in volts². The minus sign is what makes the loss go down.

Some syllabi call this batch gradient descent or steepest descent. The word batch refers to using the whole batch of data, all N samples, to compute one gradient.

One pass, one update

The loop below is the whole algorithm. Nothing else changes between steps.

  1. Forward pass: run all N samples through the network and average the per-sample losses to get L(θ).
  2. Backward pass: backpropagate to get ∂L/∂θⱼ for every parameter. Because L is an average, the gradient is the average of the N per-sample gradients.
  3. Update: apply θ ← θ − η∇L(θ) to every parameter at once.
  4. Test: recompute L. If it has stopped falling, stop. Otherwise go back to the forward pass.

One pass over the training set is an epoch, and here an epoch gives exactly one update. That single fact fixes the cost. With N = 60,000 samples, the size of the MNIST digit set, one step costs 60,000 forward passes plus 60,000 backward passes. A thousand epochs means only a thousand updates.

Where plain gradient descent fails

  • Cost per step. One update needs the full dataset. On a million-image training set that is a million forward and backward passes for one step.
  • One step size for all parameters. Early layers and late layers, weights and biases, all share η, though their gradient scales differ by orders of magnitude. See 2.4.
  • Ravines. In a long narrow valley the steep walls force a small η while the floor needs a large one. The path zig-zags across the valley and crawls along it.
  • Flat regions and saddle points. Where the gradient is near zero the step is near zero, and training stalls even though better ground lies nearby. In high dimensions saddles are far more common than local minima.
  • Divergence. If η is too large, each step overshoots, the loss jumps, and after a few steps it becomes NaN.
  • No noise. Every step sees the same data in the same order, so the whole path is fixed by the starting point θ₀.

The loss is not convex, so it can have many local minima. Batch gradient descent has no mechanism inside it to climb out of one.

Bad minima and the usual heuristics

Two old heuristics help against a bad local minimum. The first is random restarts: train from several different starting weights and keep the model with the lowest final loss, which is why the starting spread matters (see 2.6). The second is added noise: jitter the parameters or the gradient estimates so the path can leave a shallow basin.

The noise idea turns out to be the useful one. 2.2 estimates the gradient from one small random batch, so each step is cheap and the estimate is noisy; that noise alone shakes the path out of shallow basins. 2.3 then attacks the ravine problem by smoothing the path with momentum.

Worked example

Question. Take L(θ) = θ² with a single scalar parameter θ. Start at θ₀ = 4 and run three steps of gradient descent with η = 0.1. List θ₁, θ₂, θ₃ and the factor by which the loss shrinks each step. Then repeat with η = 1.1 and state what happens.

  1. Gradient: ∇L = dL/dθ = 2θ. At θ₀ = 4 the gradient is 8.
  2. θ₁ = 4 − 0.1 × 8 = 4 − 0.8 = 3.2. The new gradient is 2 × 3.2 = 6.4.
  3. θ₂ = 3.2 − 0.1 × 6.4 = 3.2 − 0.64 = 2.56. The new gradient is 5.12.
  4. θ₃ = 2.56 − 0.1 × 5.12 = 2.56 − 0.512 = 2.048.
  5. Each step is θ ← θ − η(2θ) = (1 − 2η)θ. Here 1 − 2η = 0.8, so θ is multiplied by 0.8 and L = θ² by 0.8² = 0.64 per step.
  6. Now η = 1.1, so 1 − 2η = −1.2. The magnitude grows by 1.2 per step and the sign flips: θ₁ = 4 − 1.1 × 8 = −4.8; the gradient there is −9.6; θ₂ = −4.8 − 1.1 × (−9.6) = −4.8 + 10.56 = 5.76.
  7. The loss went from 16 to 23.04 to 33.18, so it grows without bound: the run diverges.

Answer. With η = 0.1 the parameter goes 4 → 3.2 → 2.56 → 2.048 and the loss shrinks by a factor 0.64 per step; with η = 1.1 it goes 4 → −4.8 → 5.76 and the loss diverges.

Exam traps

  • A loss curve that jumps up and down, or turns into NaN, is divergence from a too-large η. It is not a local minimum.
  • One epoch is one step in batch gradient descent, not many. Students who assume otherwise get the training time wrong by a factor of N.
  • Forgetting the 1/N. Summing instead of averaging scales the gradient by N, which is the same as multiplying η by N.
  • Sign slip: θ ← θ + η∇L climbs the surface. Check by asking whether the loss went down.
  • η multiplies the gradient, so its size is tied to the gradient's scale. Changing the scale of the inputs changes the gradient and hence the effective step, so η must be re-tuned.

2.2 Stochastic and mini-batch gradient descent

Full gradient descent computes the loss gradient over all N training samples before one update. Stochastic gradient descent replaces that full gradient with an estimate from one sample; mini-batch gradient descent uses B samples. Each step is cheap, so many updates fit in the same time. The estimate is noisy, but the noise helps: it shakes training out of flat regions and saddles. This is the default training loop for deep networks, from image classifiers on a phone to language models on a cluster.

You need: 2.1 for the update rule and the learning rate.

One sample, B samples, or all N

Full-batch gradient descent uses the average gradient over all N samples. Let N be the number of training samples, θ the parameter vector, η the learning rate, and ℓi(θ) the loss on sample i. The full gradient is g = (1/N) Σi=1N ∇ℓi(θ). One update needs a pass over all N samples. When N is large, that is too expensive.

Mini-batch gradient descent uses a random set Bt of B sample indices. The update is:

θ<sub>t+1</sub> = θ<sub>t</sub> − η · (1/B) Σ<sub>i∈B<sub>t</sub></sub> ∇ℓ<sub>i</sub>(θ<sub>t</sub>)

θt is the parameter vector after t updates; η is the learning rate, a positive step size; Bt is the set of indices in batch t (size B); ∇ℓi(θt) is the gradient of sample i's loss at θt; B is the batch size.

Plain SGD is B = 1; some syllabi call it on-line learning. A mini-batch uses B > 1, commonly 32, 64, 128 or 256. Powers of two map well to GPU and TPU memory. The batch gradient gB is an estimate of g. An epoch is one pass over all N samples. An iteration is one update. If N is divisible by B, iterations per epoch = N/B. If not, the last batch is smaller, so use ⌈N/B⌉ iterations.

  1. Draw a random permutation of the N sample indices.
  2. Cut it into batches of B; the last batch may be smaller.
  3. For each batch, compute the average sample gradient and apply one update.
  4. After the last batch, the epoch ends.

The figure uses N = 12 and B = 4, so one epoch has three batches.

Unbiased estimate, shrinking noise

Draw the batch uniformly at random. Then E[gB] = g. The mini-batch gradient is unbiased: its average over all possible batches equals the full gradient. If one sample's gradient has variance σ² and samples are independent, then the batch gradient has variance:

Var(gB) = σ2 / B

gB is the mini-batch gradient; σ2 is the variance of the single-sample gradient; B is the number of samples in the batch. The standard deviation is σ/√B.

Doubling B halves the variance and divides the standard deviation by √2. The estimate is still noisy, but less noisy. Noise is not only a cost. In a flat region or at a saddle point, the full gradient is near zero and full-batch descent can stall. The random part of gB gives a push. Too much noise, however, makes the final steps jump around, so B and η must be chosen together.

Linear scaling heuristic: if you multiply B by k, try multiplying η by k. A batch k times larger has variance k times smaller, so a larger step may keep similar progress. This is a heuristic, not a law; check the loss and validation score. Momentum smooths this noise; see 2.3.

Shuffling and batch-size judgment

Shuffle the order every epoch. Without shuffling, the network sees the same sample order and often the same class order in every epoch. Batches become correlated, the gradient can oscillate, and the model can fit order rather than content. A fresh random permutation each epoch makes batches different.

Small batches give a cheap update but a high-variance estimate. If B is very small, one unusual sample can dominate the step. Large batches give a reliable gradient but cost more per update and may need a larger η; they also give fewer updates per epoch. Use the largest B that fits memory and still trains well, then tune η.

One epoch is not one update. With N = 1000 and B = 100, one epoch has 10 updates. Comparing SGD steps with gradient descent epochs is a factor-of-ten error here. Record iterations, epochs and updates separately.

  1. Track training loss every iteration.
  2. Track validation loss every epoch.
  3. If loss spikes, lower η or raise B.
  4. If progress is slow, raise η cautiously.

Worked example

Question. A UPI fraud classifier has N = 1000 labelled transactions. You train with mini-batch gradient descent using B = 100 for 20 epochs. (a) How many iterations per epoch?   5. Mini-batch standard deviation = √0.004 ≈ 0.0632, rounded to 0.063 gradient units.

Exam traps

  • Calling an epoch an iteration. An epoch has N/B iterations when batches are full; only full-batch descent has one update per epoch.
  • Comparing SGD steps with gradient descent epochs. With N = 1000 and B = 100, 20 SGD epochs are 200 updates, not 20.
  • Forgetting to shuffle. Fixed order makes batches correlated and can teach the model the order of classes rather than the features.
  • Using a tiny batch and blaming the learning rate. A very small B gives a high-variance gradient estimate; the direction itself is unreliable.
  • Treating linear scaling as a law. Multiplying B by k and η by k is only a starting guess; large steps can diverge.

2.3 Momentum and Nesterov accelerated gradient descent

Plain gradient descent takes each step using only the current gradient. In a narrow valley it zig-zags: sideways components cancel slowly while the useful direction grows slowly. Momentum adds a velocity that remembers past gradients. Consistent directions build up speed; opposite directions cancel. The method costs one extra number per parameter. It is used in training deep networks, in convolutional and sequence models, and inside optimizers such as Adam. Nesterov accelerated gradient is a refinement: it looks ahead along the current velocity before measuring the gradient, so it starts braking before an overshoot.

You need gradient descent and mini-batch gradient descent.

Why velocity helps

Plain gradient descent takes a step opposite the current gradient: θ ← θ − η∇L(θ). In a narrow valley, the gradient points across the valley more than along it. Sideways steps alternate sign and cancel slowly, while the small along-valley component gives slow progress. Momentum adds a velocity v that remembers past gradients.

v ← βv + η∇L(θ), θ ← θ − v

v is the velocity vector, one component per parameter; β is the momentum coefficient, 0 ≤ β < 1; η is the learning rate; ∇L(θ) is the gradient of the loss L at the current parameters θ. The arrow means replace the left side by the right side.

β is the momentum coefficient, usually 0.9. It is not the learning rate. With β = 0 the velocity is just the current gradient step, so the method is plain gradient descent. With β = 0.9 the velocity is roughly a weighted sum of the last 1/(1 − β) ≈ 10 gradients. A steady direction builds speed; a direction that flips cancels.

For a constant gradient g, the velocity settles at v = ηg/(1 − β). The effective step is then η/(1 − β), about ten times η when β = 0.9. Raising β therefore acts like raising η, but it also smooths noisy mini-batch gradients and can overshoot.

The momentum update

The method stores one velocity for every parameter. It needs the same memory as the parameters themselves, so the memory used on the parameter side grows by about one number per parameter; memory for activations is unchanged. No extra forward pass is needed.

  1. Initialise v = 0 for every parameter.
  2. At step k, compute the gradient ∇L(θ) on the current mini-batch.
  3. Update v ← βv + η∇L(θ).
  4. Update θ ← θ − v.
  5. Repeat until the loss stops improving.

The order matters. The gradient is added to the old velocity, and the new velocity moves the parameters. Do not add η twice: if the velocity already contains η∇L, the position update is θ ← θ − v, not θ ← θ − ηv.

  • β = 0.9 is a common default; β = 0.99 remembers about 100 gradients and is slower to react.
  • Large β gives long memory and a large effective step; it can overshoot near a minimum.
  • Momentum works well with mini-batches because the velocity averages away some gradient noise (see 2.2).

Nesterov accelerated gradient

Momentum measures the gradient at the current θ. Nesterov accelerated gradient measures it at the point where the velocity is about to take the parameters. Write the look-ahead point as θ − βv. The update becomes:

v ← βv + η∇L(θ − βv), θ ← θ − v

θ − βv is the look-ahead point; the gradient is measured there, not at θ. β and η are as above.

The look-ahead point is a prediction. If the velocity is about to overshoot a minimum, the look-ahead point lies past the minimum. The gradient there points back, so the velocity is corrected before the overshoot, not after it. This usually gives less overshoot and faster settling than plain momentum. Some syllabi spell the name Nestrov.

With a descent direction g = −∇L, the same method is written v ← βv + ηg(θ + βv), then θ ← θ + v. The sign changes because v now points in the direction that lowers the loss. The memory cost is still one velocity per parameter, and the gradient cost is still one gradient per step.

Exam traps

  • Mixing the two forms. If v already contains η∇L, the position update must be θ ← θ − v, not θ ← θ − ηv (that applies η twice). If v stores only ∇L, the position update must be θ ← θ − ηv, not θ ← θ − v (that applies no learning rate). Pick one form and stay in it.
  • Comparing momentum at η with plain gradient descent at the same η and concluding momentum is free speed. The effective steady step is η/(1 − β), about 10η for β = 0.9.
  • In Nesterov, taking the gradient at θ instead of the look-ahead θ − βv. The whole point is the look-ahead.
  • Mixing the sign conventions. With v ← βv + η∇L and θ ← θ − v, the look-ahead is θ − βv. With a descent direction g = −∇L and θ ← θ + v, it is θ + βv.
  • Forgetting to initialise v to zero. A non-zero starting velocity adds an unrequested first step.

2.4 Adaptive optimizers: AdaGrad, RMSProp and Adam

A single learning rate forces every parameter to move by the same scale. Adaptive optimizers give each parameter its own step size, built from a running summary of that parameter's recent gradients. AdaGrad sums squared gradients; RMSProp forgets old ones; Adam tracks both a mean and a variance. They are default choices for deep networks, including image classifiers and language models, because they train reliably with little tuning of the step size.

You need: 2.3 for the running-average idea, and the chain rule from Unit 1 for where g comes from.

AdaGrad: accumulate squared gradients

Plain gradient descent uses one step size η for all parameters. A rare feature may need a large step while a common feature already has large gradients and needs a small one. AdaGrad keeps a separate accumulator s for each parameter, starting at 0.

s ← s + g²

s is the accumulator for one parameter; g is that parameter's gradient at the current step.

θ ← θ − η g / (√s + ε)

θ is the parameter; η is the base learning rate; ε is a tiny positive number such as 1e-8.

The accumulator only grows. If a parameter keeps receiving large gradients, s becomes large and √s makes its effective step small. If a parameter is rarely active, s stays small and its steps stay relatively large. This helps sparse features, such as rare words in a language model.

The weakness is the same growth. After many steps s can be so large that the effective step is near zero. Training then slows or stalls, even when the parameter still needs to move. AdaGrad is historically important but rarely the first choice for long deep-network training today.

RMSProp: forget old gradients

RMSProp replaces the sum with a leaky average. Old squared gradients are multiplied by ρ and the new one by 1−ρ. With ρ = 0.9, the average mostly covers roughly the last ten gradients, so old large gradients fade.

s ← ρs + (1 − ρ)g²

ρ is the decay rate, usually 0.9; s is the running average of squared gradients for one parameter.

The update is the same as AdaGrad: θ ← θ − η g / (√s + ε). Because s no longer only grows, the effective step can rise again when gradients shrink. RMSProp works well on non-stationary problems and on mini-batch noise, where the scale of gradients changes over training.

The decay rate controls memory: ρ close to 1 remembers longer; ρ smaller reacts faster but is noisier. The name comes from root mean square: √s is an estimate of the root mean square gradient for that parameter. RMSProp remains a strong baseline for mini-batch training.

Adam: mean and variance

Adam adds momentum to RMSProp. It keeps a first moment m, an average of gradients, and a second moment v, an average of squared gradients. Both start at 0.

m ← β₁m + (1 − β₁)g

m is the first moment for one parameter; β₁ is its decay rate, usually 0.9.

v ← β₂v + (1 − β₂)g²

v is the second moment; β₂ is its decay rate, usually 0.999.

At step t, both averages are biased toward 0 because they started at 0. Adam corrects this by dividing by 1 − βᵗ: m̂ = m / (1 − β₁ᵗ) and v̂ = v / (1 − β₂ᵗ). The corrected values estimate the true mean and the true mean square (uncentered second moment) of recent gradients.

θ ← θ − η m̂ / (√v̂ + ε)

η is the step size, often 0.001 for Adam; ε is a tiny constant, often 1e-8.

The defaults β₁ = 0.9, β₂ = 0.999 and ε = 1e-8 are standard. AdamW decouples weight decay from the adaptive step, a detail only a few universities teach; see 2.8.

Reading the update

ε has two jobs. It prevents division by zero when v̂ or s is 0, and it damps the step when gradients are tiny. If ε is too large, it blunts Adam's per-parameter scaling.

The first Adam steps are about η in size, even if g is large, because m̂/√v̂ is near 1 or −1. Later steps follow the ratio of mean gradient to root-mean-square gradient. This is why Adam is less sensitive to the gradient scale than plain gradient descent.

Do not copy η from one optimizer to another. η = 0.001 suits Adam; η = 0.1 often suits SGD with momentum. Tune η and the decay rates on a validation split; see 2.9.

All three methods are still gradient descent. They change only the step taken for each parameter, using history; the gradient g still comes from backpropagation.

2.5 Vanishing and exploding gradients

Backpropagation sends the error backward one layer at a time. At every layer it multiplies the gradient by that layer's Jacobian, the matrix of local derivatives. A deep network therefore multiplies one such factor per layer. If each factor is below 1, the product shrinks toward zero; that is the vanishing gradient. If each is above 1, it grows without bound; that is the exploding gradient. The same product appears in recurrent nets unrolled over time. Recognising it explains why early layers stop learning, why losses turn into NaN, and why clipping, ReLU, careful initialization and normalization exist.

You need: backpropagation from Unit 1, and 2.1 for what happens to the gradient after it is computed.

One Jacobian per layer

Backpropagation computes the gradient of the loss with respect to every layer's activations by working backward. At each step it multiplies by one local Jacobian. A Jacobian is the matrix that holds every partial derivative of a layer's output with respect to its input.

∂E/∂h<sup>(1)</sup> = J<sub>2</sub><sup>T</sup> J<sub>3</sub><sup>T</sup> ⋯ J<sub>L</sub><sup>T</sup> · ∂E/∂h<sup>(L)</sup>

E is the loss; h(1) is the first hidden layer's activation vector; h(L) is the output-side activation vector; L is the number of layers; ℓ indexes a layer; Jℓ is the Jacobian ∂h(ℓ)/∂h(ℓ−1), of size nℓ × nℓ−1, where nℓ is the number of units in layer ℓ; JℓT is its transpose, of size nℓ−1 × nℓ.

Read the product from the right. The first step is JLT times ∂E/∂h(L), then JL−1T times that result, and so on down to J2T. Each JℓT maps a gradient on layer ℓ back to layer ℓ−1, so the transpose is what applies, not Jℓ itself. A network with L layers has L − 1 Jacobians between h(L) and h(1).

For a dense layer h(ℓ) = f(W(ℓ) h(ℓ−1) + b(ℓ)), the Jacobian is diag(f′(z(ℓ))) W(ℓ). Here W(ℓ) is the weight matrix, b(ℓ) the bias vector, z(ℓ) = W(ℓ) h(ℓ−1) + b(ℓ) the pre-activation, and f′ the derivative of the activation. The scale of this Jacobian decides whether the gradient shrinks or grows as it passes that layer.

For the sigmoid, f′(z) = σ(z)(1 − σ(z)). This derivative is largest at z = 0, where it equals 0.25, and it approaches 0 for large positive or negative z. One sigmoid layer can therefore cut the gradient to a quarter. L sigmoid layers in a row cut it to 0.25L if the weight matrices add no gain.

Small factors vanish, large factors explode

The full gradient at layer 1 is the product of the Jacobians between the output side and layer 1. For L layers there are L − 1 such Jacobians. Their norms control the size of the gradient, and a matrix-norm bound makes this exact: ‖J2T ⋯ JLT‖ ≤ ‖J2‖ ⋯ ‖JL‖. So if every per-layer factor has norm at most 0.25, the whole product has norm at most 0.25L−1. In the table below, L counts the number of factors, that is the number of layers the gradient passes through, so L = 10 means ten multiplicative steps. Small factors compound like compound interest in reverse.

Exploding gradients show up as weights that jump, a loss that oscillates or becomes NaN, and gradient values that overflow to infinity.

Mitigations and checks

The fixes attack either the factors or the product. Gradient clipping is the standard guard against exploding gradients.

g ← g · min(1, c / ‖g‖)

g is the gradient vector; ‖g‖ is its Euclidean norm; c is the clipping threshold, a positive number chosen in advance. If ‖g‖ ≤ c the vector is unchanged. If ‖g‖ > c, the direction stays the same and the norm becomes exactly c.

  • Use ReLU instead of sigmoid in hidden layers (see Unit 1, Activation functions). Its derivative is 1 for positive pre-activations, so it does not shrink the gradient by itself.
  • Initialize each weight matrix with a variance suited to its fan-in and activation; He initialization is in 2.6.
  • Normalize pre-activations across each mini-batch with batch normalization (2.7).
  • Add residual connections in very deep feedforward and convolutional nets (see Unit 3, Deeper architectures: Inception and ResNet) and gated units in recurrent nets (see Unit 4, Long short-term memory (LSTM) and gated units).
  • Clip gradients when they explode; clipping never restores a vanished gradient.

Check the per-layer gradient norms during training, not only the loss. A first layer with a norm a million times smaller than the last layer is direct evidence of vanishing. A dead ReLU shows a zero gradient for one unit, not a shrinking trend across all layers.

  • Large weights can also cause vanishing: they push the sigmoid into saturation, where its derivative is near zero.

2.6 Weight initialization methods

Weight initialization sets each weight matrix's starting spread before training. The aim is to keep activations and gradients at roughly the same scale layer after layer. Equal starting weights make all hidden units learn the same thing, so random draws are used to break symmetry. The correct variance depends on fan-in, fan-out and the activation function. This idea is used in every deep network, from a small classifier on a phone to a large language model.

You need: 2.5 for why the scale matters, and Unit 1 for layer shapes and fan-in.

Symmetry and what fan-in means

A dense layer computes zi = Σj wij xj + bi. Here xj is input j, wij is the weight from input j to unit i, bi is the bias, and zi is the pre-activation. If every weight and bias starts equal, every hidden unit computes the same zi and the same activation. Backpropagation then sends the same gradient to each unit. A wide layer acts like one unit. Random draws break this symmetry.

Fan-in nin is the number of inputs to one unit. Fan-out nout is the number of units that unit feeds. For a weight matrix W of shape nout × nin, each output unit has nin weights. A layer with 100 inputs and 50 ReLU units has nin = 100 and nout = 50. Fan-in controls how many terms add into zi. Fan-out controls how many places the gradient of one input goes. Both matter because the same matrix is used forward and backward.

Randomness alone is not enough. The scale of the random draws sets the scale of zi and of the gradients. A too-small scale shrinks the signal. A too-large scale saturates tanh or sigmoid, or makes ReLU activations grow. The rules below keep variance near one through the stack.

Xavier for tanh and sigmoid, He for ReLU

Use Xavier or Glorot initialization for tanh and sigmoid layers. It averages fan-in and fan-out:

Var(W) = 2 / (n_in + n_out)

Var(W) is the variance of each weight; n_in is fan-in; n_out is fan-out. Use this for tanh and sigmoid.

The matching uniform form uses the same variance:

W ~ U(-√(6/(n_in + n_out)), +√(6/(n_in + n_out)))

U(a,b) is a uniform draw between a and b. The bound gives the same variance as the rule above.

Here Var(W) is the variance of each weight, σ(W) = √Var(W) is its standard deviation, nin is fan-in, and nout is fan-out. The sum nin + nout balances the forward signal and the backward gradient. For tanh and sigmoid, this stops activations from collapsing or saturating.

Use He or Kaiming initialization for ReLU layers. ReLU sets negative pre-activations to zero, so about half the inputs to a unit are inactive. The weights must be larger to keep the active signal at the same scale:

Var(W) = 2 / n_in

Var(W) is the weight variance; n_in is fan-in. Use this for ReLU.

The matching uniform half-width is √(6/nin). Biases start at zero in both schemes. A zero bias adds no noise and lets the random weights do the symmetry breaking. Orthogonal initialization draws a matrix with orthonormal columns; only a few universities teach it, and it is an option for very deep stacks. A wrong scale brings back the shrinking or exploding gradients of 2.5.

Procedure and comparison

  1. Read nin and nout from the layer shapes. nin is the previous layer width; nout is the current layer width.
  2. Pick the rule by activation: Xavier for tanh or sigmoid, He for ReLU.
  3. Compute the variance. Convert it to a standard deviation σ = √Var for normal draws.
  4. Draw every weight independently from a zero-mean normal with that standard deviation, or use the matching uniform bound.
  5. Set every bias to zero. Do not draw biases at random.

2.7 Batch normalization

Batch normalization rescales each layer's pre-activations using the mean and variance of the current mini-batch, then learns a per-feature scale γ and shift β. It exists because deep networks are sensitive to the scale of activations: small changes in early layers can push later pre-activations into saturated or tiny regions. Normalizing before the activation keeps that scale controlled, so larger learning rates survive and initialization matters less. It is standard in convolutional and fully connected networks, and its batch-independent cousin LayerNorm appears in transformers.

You need: 2.1 for the update rule, 2.5 for the scale problem it fixes, and 2.6 for the initialization it makes less critical.

The normalization step

Take one layer. For one feature, the layer receives B pre-activation values z1, …, zB from the B examples in the mini-batch. Batch normalization computes the batch mean and batch variance:

μ = (1/B) Σ z<sub>i</sub>,    σ² = (1/B) Σ (z<sub>i</sub> − μ)²

B is the number of examples in the mini-batch; zi is the pre-activation for example i; μ is the batch mean; σ² is the batch variance; the sum runs over i = 1 to B.

It then standardizes each value:

ẑ<sub>i</sub> = (z<sub>i</sub> − μ) / √(σ² + ε)

ẑi is the normalized value; ε is a small positive constant, often 10⁻⁵, added so the denominator never becomes zero. Across the batch, ẑ has mean 0 and variance 1, up to the effect of ε.

Finally the layer applies a learned scale and shift:

yi = γ ẑi + β

yi is the batch-normalized output; γ is a learned scale parameter; β is a learned shift parameter. Both are one pair per feature, learned by the same gradient descent as weights and biases. If γ = 1 and β = 0, the output is exactly the standardized value.

In a layer with d features, where d is the number of features in the layer, the procedure repeats independently for each feature: d means, d variances, and d pairs of γ and β. The normalization sits before the activation, so the activation receives y, not z.

Training uses batch statistics; inference does not

While training, the layer uses μ and σ² computed from the current mini-batch. That ties the output for one example to the other examples in the same batch. The tie is acceptable during training because the gradient step already uses the whole batch.

At inference there is no safe batch to borrow statistics from. A user's single image or single sentence must get a prediction that does not change when other items appear alongside it. So the layer stores running averages during training:

μ<sub>run</sub> ← ρ μ<sub>run</sub> + (1 − ρ) μ<sub>batch</sub>,    σ²<sub>run</sub> ← ρ σ²<sub>run</sub> + (1 − ρ) σ²<sub>batch</sub>

μrun and σ²run are the stored running averages; μbatch and σ²batch are the current batch statistics; ρ is the decay rate, commonly 0.9. A value near 1 keeps a long memory; a value near 0 follows the latest batch.

At prediction time the layer uses μrun and σ²run in place of μ and σ², and applies the same learned γ and β. The result depends only on the input example and the stored parameters.

This split is the usual source of bugs. If code uses batch statistics at test time, a prediction changes with its batch-mates. If code uses running averages during training, the training signal no longer matches the forward pass. Frameworks switch between the two modes explicitly: PyTorch calls them train() and eval(); Keras passes training=True or training=False.

Why it helps, what it costs

Batch normalization helps optimization in three connected ways. First, it keeps the scale of each pre-activation roughly fixed as earlier layers change, so a learning rate that worked at the start does not suddenly become too large. Second, it makes the loss less sensitive to the initial scale of weights: 2.6 still matters, but poor scaling is partly corrected. Third, because μ and σ² come from a random mini-batch, they add slight noise to every forward pass, which can regularize a little, similar in spirit to the noise in 2.2.

The costs are real. Each normalized layer computes extra sums, square roots and divisions, and stores running averages. The method depends on batch size: with B = 1 the batch variance is zero, so normalization becomes degenerate; with very small batches the statistics are noisy. It can interact badly with recurrent networks, where sequence lengths and batch shapes vary, and with distributed training, where each device may see only a slice of the batch. It also adds two parameter vectors per layer.

LayerNorm is the batch-independent cousin. It normalizes across the features of each single example, so it needs no running averages and behaves the same in training and inference. Transformer blocks use it heavily; see Unit 5, Attention, Transformers and Language Models. Normalization inside convolutional layers, often called batch norm over the channel dimension, is covered in Unit 3, Convolutional Neural Networks.

Exam traps

  • Using the current batch's μ and σ² at inference. Then one prediction changes with its batch-mates; use the stored running averages instead.
  • Normalizing after the activation. Batch normalization is placed before ReLU or tanh, on the pre-activation z.
  • Treating γ and β as fixed constants. They are learned parameters, one pair per feature, updated by backpropagation.
  • Forgetting ε. With zero variance a feature would divide by zero; ε keeps the denominator positive.
  • Setting B = 1 and expecting stable statistics. The batch variance is zero, so the normalized value carries no useful signal.

2.8 Regularization: weight penalties, dropout and early stopping

A deep network can drive its training loss to zero by memorising noise, and then fail on new data. Regularization is any rule that charges the model for complexity, so fitting the data becomes a trade-off instead of the only goal. The charge can sit in the loss (weight penalties), in the activations (dropout), or in the number of training steps (early stopping). All three are a few lines of code in a modern framework, and all three are used in real systems: dropout in classifiers, weight decay in almost every Adam recipe, early stopping in most training scripts.

You need: overfitting and the bias-variance trade-off from Unit 1, and 2.7 for the other stabiliser often used in the same models.

Weight penalties: L2 and L1

A network with many weights can memorise its training set, noise included. A weight penalty adds a small charge for large weights to the loss, so the optimizer shrinks them unless the data insists otherwise. Backpropagation is unchanged: the penalty is simply one more term to differentiate.

J(w) = L(w) + (λ/2)·||w||²

J is the penalised loss the optimizer minimises; L is the ordinary data loss (cross-entropy or squared error); w is the vector of weights; ||w||² = Σᵢ wᵢ² is the sum of squared weights; λ ≥ 0 (lambda) is the penalty strength, a hyperparameter you choose.

Differentiate the penalty. The derivative of (λ/2)·Σⱼ wⱼ² with respect to wᵢ is λwᵢ. So every weight receives one extra gradient proportional to its own size, and the update becomes:

wᵢ ← wᵢ − η(∂L/∂wᵢ + λwᵢ) = (1 − ηλ)·wᵢ − η·∂L/∂wᵢ

η (eta) is the learning rate. The factor (1 − ηλ) shrinks the weight by a fixed fraction every step, even when the data gradient is zero; this is why L2 is called weight decay.

L1 uses absolute values instead of squares. Its gradient is λ·sign(wᵢ): a constant push towards zero whatever the weight's size.

J(w) = L(w) + λ·||w||₁

||w||₁ = Σᵢ |wᵢ| is the sum of absolute weight values; λ is the same kind of strength hyperparameter.

The difference matters. An L2 force grows with the weight, so it shrinks large weights fast and never reaches exactly zero. The L1 force is constant all the way down, so unhelpful weights land on exactly zero — sparsity, which is why L1 doubles as feature selection. Larger λ means a simpler model and more bias. Bias terms are usually left out of the penalty: shrinking a bias shifts an activation threshold rather than smoothing the function, and it rarely reduces overfitting.

Dropout

Dropout randomly deletes units while training, so no unit can depend on a particular partner being present. Each mini-batch trains a different thinned network, and the full network at test time behaves like an average of all of them. It is the standard regularizer for fully connected layers.

  1. During training, draw a random mask: each unit survives with probability 1 − p and is set to 0 with probability p.
  2. Divide every surviving activation by (1 − p). This is inverted dropout.
  3. Run the forward and backward pass as usual on the masked, scaled values. Dropped units receive no gradient this step.
  4. At test time do nothing: no mask, no scaling. Dropout is the identity.

The scaling is what makes step 4 legal. Without it, train-time activations would average a·(1 − p) while test-time activations average a, and every downstream layer would see the wrong scale.

E[a] = (1 − p)·(a/(1 − p)) + p·0 = a

a is one activation value; 1 − p is the fraction of masks in which the unit survives. The average over masks equals the unscaled activation, so test time needs no correction.

Typical rates are p = 0.5 for hidden units and p = 0.1 to 0.2 for inputs, since dropping an input deletes a feature outright. In convolutional layers plain dropout damages neighbouring pixels, so structured variants drop whole channels.

Early stopping

As training runs, validation loss falls, bottoms out, and then climbs while training loss keeps dropping — the model has moved from fitting the pattern to fitting the noise. Early stopping turns that observation into a rule.

  1. Hold out a validation split and compute its loss after every epoch, with dropout switched off.
  2. If the validation loss is the lowest seen so far, save a copy of the weights and reset a counter.
  3. Otherwise increase the counter. Stop when the counter reaches the patience — the number of epochs without improvement.
  4. Restore the best saved weights, not the weights from the last epoch.

Patience is usually 5 to 20 epochs, because validation loss is noisy and a single bad epoch proves nothing. The cost is that you cannot know the stopping point in advance, so a run takes longer than a fixed schedule. The prize is a free hyperparameter: no λ to choose.

In a simple quadratic loss, early stopping behaves like an L2 penalty. Gradient descent started from zero on a quadratic shrinks the solution's components much as weight decay does, and stopping after t steps acts like a penalty of strength roughly 1/(ηt) — more steps, weaker penalty. The identity is exact only for that quadratic case, but the intuition carries over: both methods limit how far the weights travel from their starting point.

Worked example

Question. A network has a single weight w = 2.0 and no bias, and the data-loss gradient with respect to it is currently zero. L2 regularization uses λ = 0.01 and the learning rate is η = 0.1. (a) Find the penalty value. (b) Find the penalty's gradient contribution. (c) Find how much the weight moves in one step. (d) Give the weight after that step. (e) A hidden unit has activation 3.0 and dropout uses p = 0.5; give its scaled value when it survives the mask, and its expected activation over both masks.

  1. (a) Penalty = (λ/2)·w² = (0.01/2)·2.0² = 0.005 × 4.0 = 0.02.
  2. (b) Gradient of the penalty = λw = 0.01 × 2.0 = 0.02.
  3. (c) The data gradient is zero, so the whole update comes from the penalty: η × 0.02 = 0.1 × 0.02 = 0.002.
  4. (d) w ← 2.0 − 0.002 = 1.998. Check with the decay factor: (1 − ηλ) = 1 − 0.001 = 0.999, and 2.0 × 0.999 = 1.998.
  5. (e) If the unit survives, its activation is divided by (1 − p) = 0.5, giving 3.0/0.5 = 6.0.
  6. (e, continued) Expected activation = 0.5 × 6.0 + 0.5 × 0 = 3.0, the same as the un-dropped value.

Answer. Penalty 0.02, extra gradient 0.02, step 0.002, weight 1.998; surviving activation 6.0, expected activation 3.0.

Exam traps

  • Leaving dropout on at test time. The model keeps sampling masks, so the same input gives a different, random prediction on every call.
  • Forgetting the 1/(1 − p) scaling. Train-time activations then average a·(1 − p) against a at test time, and every downstream layer sees a shifted input.
  • Watching the training loss for early stopping. Training loss almost always keeps falling; the only useful signal is the validation loss, measured with dropout off.
  • Penalising bias terms and batch-norm scale and shift parameters. Bias shrinkage just moves activation thresholds, and normalisation parameters are normally excluded too.
  • Confusing λ with η in the factor (1 − ηλ). With λ = 0.01 and η = 0.1 the weight loses 0.1 % per step, not 1 %.

Analyze Explain why L1 regularization produces weights that are exactly zero while L2 does not. 4 marks

Analyze A student stops training when the training loss stops improving, and keeps the weights from the last epoch. Give two things wrong with this. 5 marks

First, training loss keeps falling as the model overfits, so it is a poor stopping signal; early stopping must track validation loss. 2.9 Dataset augmentation and hyperparameter tuning

Dataset augmentation makes more training data without new labels: flip an image, shift a sound, or paraphrase a sentence, and keep the same target. Hyperparameter tuning chooses the settings that gradient descent cannot learn, such as learning rate η, batch size B, weight decay λ and dropout p. Both work against overfitting and wasted compute. You meet them in every image classifier, speech recognizer and text model, from a phone camera app to a bank's fraud model.

You need: 2.2 for batch size and epochs, 2.4 for optimizer settings, and 2.8 for λ and dropout p.

Two levers before training

Parameters are learned by gradient descent: weights and biases. Hyperparameters are set before training: learning rate η, batch size B, weight decay λ, dropout p, and network depth. Their gradient does not exist, so you search on a validation split.

Augmentation grows the training set with label-preserving changes. A horizontal flip keeps a cat a cat. For digits, a 180° rotation turns 6 into 9, and a left-right flip gives a mirrored 6, so flips and rotations of that kind change the label and are wrong for digits. The label must survive, and augmented copies go only into training.

Tuning uses three splits: training, validation, test. Train on training data, compare runs on validation, and touch test once at the end. Keep the same seed and epoch budget for every run. The figure shows 9 runs; the best cell is 0.88 at η = 0.01, B = 128.

Image, audio and text

Images. Use horizontal flips, random crops with padding, small rotations (about ±10°), colour jitter, and cutout (black out a small square). Avoid vertical flips for upright letters and crops that remove the object.

x̃ = λ x<sub>i</sub> + (1 − λ) x<sub>j</sub>,  ỹ = λ y<sub>i</sub> + (1 − λ) y<sub>j</sub>

xi, xj are two images; yi, yj are their one-hot labels; λ ∈ [0, 1] is a mixing weight. This is mixup, an advanced extra.

Audio. Shift the clip a little in time, or add low-level background noise such as fan hum. Keep the spoken word and its label; do not shift the event out of the clip.

Text. Paraphrasing or back-translation (translate to another language and back) adds wording. Use it with care: 'not good' can become 'good' and flip the label. It is risky in sentiment, medical notes and legal text.

Validation and test get one clean, fixed version, such as a centre crop. Augmented copies stay in training.

Searching settings

Search procedure:

  1. Split data into training, validation and test.
  2. Pick ranges: η on a log scale, say 10−4 to 10−1; B 32 to 512; λ 10−5 to 10−2; p 0 to 0.5.
  3. Fix the seed and epoch budget for all runs.
  4. Run a grid or random search.
  5. Refine coarse-to-fine around the best point.
  6. Score test once with the final model.

Grid search tries every combination. Three η values and three B values make 9 runs; cost multiplies with each added hyperparameter. Random search samples combinations. For the same number of runs it often finds a good configuration because only a few hyperparameters matter. Use a log scale for η and λ, a linear scale for p.

Coarse-to-fine: first try η = 0.1, 0.01, 0.001; if 0.01 wins, try 0.03, 0.01, 0.003.

Schedules. Step decay multiplies η by 0.1 at set epochs. Cosine schedule lowers it smoothly: ηt = ηmin + ½(ηmax − ηmin)(1 + cos(π t/T)). Here t is the current epoch and T is the total epochs. Tune the schedule and early-stopping patience too.

Bayesian optimization builds a model of validation score against settings and chooses the next run; advanced.

Takeaways

  1. Plain gradient descent with one global step size fails on ill-conditioned surfaces, saddle points and large datasets.
  2. Mini-batch SGD gives a cheap, noisy gradient whose noise helps escape sharp regions and saddle points.
  3. Momentum turns past gradients into a velocity that speeds steady directions and cancels zig-zag; Nesterov looks ahead before measuring the gradient.
  4. Adaptive methods give each parameter its own step size from its own gradient history, which removes most learning-rate tuning.
  5. A deep network's gradient is a long product of Jacobians, so it shrinks or blows up unless initialization, normalisation and ReLU-type units keep the scale near 1.
  6. Correct initialization is chosen from fan-in and fan-out so variance is preserved layer to layer; He scaling for ReLU, Xavier for tanh.
  7. Batch normalization stabilises and speeds training and allows larger learning rates, but it changes what the network computes at inference.
  8. Regularization charges the model for complexity in the loss (L2), the activations (dropout) or the number of steps (early stopping).
  9. Augmentation enlarges the training set for free, and hyperparameters must be tuned on a validation split, never on the test set.

Apply You must train an image classifier on a small dataset of 4,000 pictures. Describe a full training recipe covering augmentation, initialization, normalisation, optimizer and early stopping, and justify each choice. 12 marks

Augmentation: flips, crops, rotation, colour jitter, label preserving; He initialization with ReLU units; Batch norm after each convolution; Adam or SGD with momentum, learning-rate schedule; Dropout or weight decay to control capacity; Validation split, early stopping, no tuning on test data.

Analyze and evaluate

Analyze Backpropagation multiplies one Jacobian per layer. Use this to explain vanishing and exploding gradients, and evaluate four remedies. 13 marks

Chain rule as a product of Jacobians; Singular values below 1 shrink the product; above 1 it grows; Saturation of sigmoid and tanh contributes; Remedies: ReLU family, careful initialization, batch norm, residual connections, gradient clipping; Clipping handles explosion, not vanishing; Trade-offs and when each remedy is sufficient.

Analyze Explain the bias-variance trade-off for deep networks and analyse how regularization and training-set size move a model between underfitting and overfitting. 13 marks

Decomposition of expected error into bias, variance and noise; Underfitting: high bias; overfitting: high variance; Training and validation loss curves as diagnostic; Regularization raises bias, lowers variance; More data and augmentation lower variance; Modern over-parameterised nets can fit noise yet still generalise; the classical picture is incomplete.

Evaluate After 30 epochs the training loss keeps falling but validation loss has risen for 8 epochs. Diagnose the situation and propose a fix plan using ideas from at least four chapters of this unit. 15 marks

Identify overfitting from the diverging curves; Early stopping with restore-best-weights; Add dropout, weight decay or augmentation; Check optimizer and learning rate; try lower η or schedule; Check initialization and use batch norm if training is unstable; Re-examine the validation split and its size; Order the fixes from cheapest to most expensive and justify.

Evaluate 'Batch normalization makes dropout unnecessary.' Evaluate this claim. 10 marks

Batch norm stabilises optimisation and permits larger learning rates; Dropout regularises by preventing co-adaptation; The two act on different problems: conditioning vs capacity control; Empirical evidence that they can be combined or used alone; Effect of batch size on batch-norm statistics; Conclusion: not a substitute in general, depends on data size and architecture.

Analyze Compare grid search, random search and manual search for hyperparameter tuning, and explain why tuning must be done on a validation split with cross-validation. 10 marks

Hyperparameters are not learned by gradient descent; Grid search cost grows exponentially with dimensions; Random search covers important dimensions better at equal budget; Cross-validation reduces the variance of the estimate; Test set must be touched once only; Learning rate is usually the most important hyperparameter.

Glossary

AdaGrad
An adaptive method that divides each step by the square root of the sum of all past squared gradients.
Adam
An adaptive method combining momentum and RMSProp with bias correction.
Adaptive learning rate
A per-parameter step size computed from the history of that parameter's gradients.
Batch gradient descent
Gradient descent that computes the exact gradient over the entire training set in each step.
Convex function
A function whose graph lies below every chord, so any local minimum is also the global minimum.
Data augmentation
Producing extra training examples by applying label-preserving transformations to existing ones.
Dropout mask
A random binary vector that zeroes a chosen fraction of activations during a training step.
Early stopping
Stopping training at the epoch of best validation loss and keeping those weights.
Epoch
One full pass of the optimizer over the training set.
Fan-in
The number of inputs arriving at a unit or layer; used in variance formulas for initialization.
Fan-out
The number of units a neuron feeds into; used in Xavier initialization.
Gradient
The vector of partial derivatives of the loss with respect to every parameter; it points in the direction of steepest increase.
Gradient clipping
Capping the norm or value of the gradient before the update to prevent explosive steps.
Hyperparameter
A setting chosen before training, such as learning rate, batch size or dropout rate, that gradient descent does not learn.
Internal covariate shift
The change in the distribution of a layer's inputs as the layers before it are updated.
Learning rate
The scalar that multiplies the gradient in an update and sets how far each step moves.
Mini-batch size
The number of examples B used in one gradient estimate; commonly between 32 and 512.
Momentum
An optimizer that keeps a decaying running sum of past gradients as a velocity.
Nesterov accelerated gradient
Momentum that measures the gradient at the point the velocity is about to reach.
RMSProp
An adaptive method that divides each step by the square root of a decaying average of squared gradients.
Running statistic
A moving average of mean or variance kept during training and frozen for inference.
Saddle point
A point where the gradient is zero but the surface rises in some directions and falls in others.
Second moment estimate
A running average of squared gradients, used as a per-parameter measure of gradient magnitude.
Shuffling
Randomly reordering the training set before each epoch so mini-batches differ.
Stochastic gradient descent
Gradient descent that uses one example or a small random mini-batch to estimate the gradient at each step.
Weight decay
The effect of an L2 penalty, which shrinks every weight by a small factor each step.
