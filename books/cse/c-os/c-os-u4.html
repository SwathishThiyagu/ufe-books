4.1 Memory management strategies and address spaces

Memory must be given to many programs at the same time. Different strategies decide how the main memory is split and how a process sees its own address space. The idea is to use RAM efficiently and to protect processes from each other. These strategies are used in every modern OS, from phones to servers.

You need: address translation basics from Unit 1.

Fixed and variable partitions

In fixed partitioning the RAM is divided into blocks of equal size before any process arrives. Each block can hold one process only. The size is chosen by the OS designer.

Fixed partitions are simple to implement. The OS only needs a table of free blocks. They cause internal fragmentation because a process may not use the whole block.

Variable partitioning creates a hole of any size that fits the arriving process. The OS keeps a free‑list of holes. Allocation uses first‑fit, best‑fit or worst‑fit policies.

Variable partitions reduce internal fragmentation but can leave many small holes. This is external fragmentation.

  • Use fixed partitions for embedded systems with predictable workloads.
  • Use variable partitions when process sizes vary widely.

Some syllabi call this "memory allocation strategies".

Paging and segmentation

Paging removes external fragmentation. Memory is divided into equal pages, typically 4 KB or 16 KB. A process address space is also divided into pages of the same size.

The OS keeps a page table. Each entry maps a logical page number to a physical frame number.

Segmentation keeps the logical view of a program. A segment can be code, data or stack. Each segment has a base address and a limit.

Segmentation gives a more natural view but can still suffer external fragmentation. Modern OSes often combine both: each segment is divided into pages.

  • Paging is preferred when fast allocation and deallocation are needed.
  • Segmentation is useful when programs need separate logical regions.

For details on paging see 4.4.

Logical, physical, and virtual addresses

A logical address (also called virtual address) is generated by the CPU while a program runs.

The OS translates the logical address to a physical address that points to a real byte in RAM.

Translation uses a base register and a limit register in simple schemes.

The base register holds the start of the process region in physical memory. The limit register holds the size of that region.

If the logical address is greater than or equal to the limit, the OS raises an out‑of‑bounds fault.

Physical = Base + Logical

Physical is the physical address; Base is the value in the base register; Logical is the logical address.

When paging is used, the translation also adds the offset inside the page after looking up the frame number.

Choosing a strategy depends on the workload. Real‑time systems often use fixed partitions for predictability. General‑purpose OSes use paging for flexibility.

Worked example

Question. Physical memory = 64 KB, page size = 16 KB, base register = 0x8000, logical address = 0x2A3F. Compute the physical address using the simple base‑plus‑offset method.

C program.

#include <stdio.h>
int main(){
    unsigned int base = 0x8000;
    unsigned int logical = 0x2A3F;
    unsigned int physical = base + logical;
    printf("Physical address: 0x%X (%u)\n", physical, physical);
    return 0;
}
  1. Convert base register to decimal: 0x8000 = 32768 bytes.
  2. Convert logical address to decimal: 0x2A3F = 10815 bytes.
  3. Add base and logical: 32768 + 10815 = 43583 bytes.
  4. Convert result back to hex: 43583 = 0xAA3F.
  5. Check that 0xAA3F < 64 KB (65536 bytes). It fits.

Output

Physical address: 0xAA3F (43583)

Answer. The physical address is 0xAA3F (43583 decimal).

Exam traps

  • Confusing logical address with physical address; the logical value must be added to the base.
  • Forgetting that the limit register must be checked before translation; otherwise out‑of‑bounds errors are missed.
  • Using page size in the simple base‑plus‑offset formula; page size is only needed for paging calculations.
  • Assuming any address fits in memory; always verify that the final physical address is below the total RAM size.

4.2 Swapping of processes

Swapping moves whole processes between main memory and a designated area on secondary storage called swap space. It is used when RAM cannot hold all active processes, allowing the operating system to free memory for a newly ready process. Swapping is common in systems with limited RAM, such as low‑end servers, embedded devices, or during heavy load on a desktop when many applications are opened.

You need: Memory management strategies and address spaces.

Swap space and basic operation

Swap space is a reserved portion of the disk that the OS treats as an extension of RAM. It is created during system installation or by a system administrator. Each process that is swapped out has its entire address image written to one or more blocks in the swap area; the blocks need not be contiguous. The image includes code, data, stack and heap segments.

When a process is swapped in, the OS reads its image back into a free region of RAM. The process resumes execution as if it had never left memory. The whole operation is called a swap‑in (load) or swap‑out (store).

  • Swap‑in: Disk → RAM
  • Swap‑out: RAM → Disk
  • Swap space size is often chosen as a fraction or multiple of RAM, e.g., 1× to 2× RAM, but the optimal size depends on the workload and system configuration.

When swapping is invoked and its overhead

Swapping is invoked when the ready queue contains a process that cannot be placed in RAM because all frames are occupied. The OS selects a victim process, writes its image to swap, updates the process control block (PCB) to reflect the new location, and then loads the waiting process.

  1. Check if a free frame exists.
  2. If none, choose a victim process.
  3. Write the victim’s entire memory image to swap (swap‑out).
  4. Mark the frames as free.
  5. Read the waiting process image from swap (swap‑in).
  6. Update the PCB and schedule the process.

The overhead consists of disk I/O time, which is orders of magnitude slower than RAM access. A typical hard‑disk transfer rate of 100 MB/s translates to about 80 ms to move an 8 MB process image, while RAM access is in nanoseconds. Consequently, swapping can increase response time if used excessively.

Policy, difference from paging, and simple example

Swapping differs from paging in that paging moves fixed‑size pages, while swapping moves the whole process image. Paging allows a process to stay partially resident, reducing I/O, whereas swapping removes the process completely.

A simple policy taught in many syllabi is to swap out the longest idle process. The OS maintains a timestamp of the last CPU burst for each resident process. The one with the earliest timestamp is selected as the victim.

  • Advantage: easy to implement, no need for page‑level bookkeeping.
  • Disadvantage: large I/O cost, may evict a process that will be needed soon.
Swap‑out time = (Process size) ÷ (Disk transfer rate)

Process size is in MB; Disk transfer rate is in MB/s; result is in seconds.

Worked example

Question. RAM = 16 MB, swap space = 32 MB, processes P1‑P4 each need 8 MB. After loading P1 and P2, the scheduler wants to run P3. Using the longest‑idle policy, which process is swapped out and how much memory is freed?

C program.

#include <stdio.h>
int main(){
    int ram = 16; // MB
    int proc = 8; // MB per process
    int free = ram - 2*proc; // after P1 and P2
    // longest idle is P1, swap it out
    free += proc; // free 8 MB
    printf("Free RAM after swap: %d MB\n", free);
    return 0;
}
  1. Step 1: Total RAM = 16 MB, each process = 8 MB, so two processes fit.
  2. Step 2: P1 is loaded first, then P2. P1 has been idle longer than P2.
  3. Step 3: The longest‑idle victim is P1.
  4. Step 4: Swapping out P1 writes its 8 MB image to swap and frees 8 MB of RAM.
  5. Step 5: P3 is loaded into the freed 8 MB region.

Output

Free RAM after swap: 8 MB

Answer. Process P1 is swapped out, freeing 8 MB of RAM.

Exam traps

  • Assuming swapping always improves response time without accounting for the disk I/O delay.
  • Confusing swapping with paging and thinking that a swapped‑out process still occupies RAM frames.
  • Swapping the process that just used the CPU because it appears in the ready queue, ignoring the longest‑idle rule.
  • Using the size of swap space as a limit for how many processes can be resident, instead of RAM size.

4.3 Contiguous memory allocation and fragmentation

Contiguous memory allocation puts each process in one continuous block of RAM. It is simple to implement but creates two kinds of waste: internal fragmentation, the unused part inside an allocated block, and external fragmentation, the unusable holes left between blocks. The chapter explains fixed and dynamic partitions, the three classic placement algorithms, and how compaction can recover external holes.

You need: swapping concepts from Swapping of processes.

Fixed and dynamic partitions

In a fixed‑partition system the OS divides main memory into a small number of equal‑sized slots at boot time. Each slot can hold at most one process. If a process needs less than the slot size, the remaining part of the slot stays idle. This idle part is called internal fragmentation. Fixed partitions are easy to manage but waste memory when processes have varied sizes.

Dynamic partitions, also called variable‑size partitions, are created when a process arrives. The OS searches the free list for a hole that can fit the process and allocates exactly the required size. The remaining part of the hole becomes external fragmentation. Dynamic partitions reduce internal waste but introduce external fragmentation because holes of different sizes appear between allocated blocks.

IF = Partition size – Process size

IF is internal fragmentation in bytes for a fixed‑size partition; Partition size is the size of the allocated block (the fixed slot size); Process size is the actual memory needed by the process. For variable‑size partitions the internal fragmentation is zero because the allocated size equals the process size.

  • Fixed partitions: simple, fast allocation, high internal fragmentation.
  • Dynamic partitions: flexible, low internal fragmentation, possible external fragmentation.

External fragmentation and placement algorithms

External fragmentation is the total free memory that cannot be used because it is split into holes smaller than the largest pending request. In other words, external fragmentation = total free memory – size of the largest free hole. It appears only in dynamic‑partition systems because each allocation can leave holes of varying sizes.

  1. First‑fit: scan the free list from the beginning and allocate the first hole that is large enough.
  2. Best‑fit: scan the entire list and choose the smallest hole that fits the request.
  3. Worst‑fit: choose the largest hole, leaving a bigger remainder that may be useful later.

All three algorithms run in O(n) time where n is the number of holes. First‑fit is fastest in practice because it stops at the first suitable hole. Best‑fit reduces average external fragmentation but increases search time. Worst‑fit tends to leave large holes, which can help later large allocations but may also increase internal fragmentation.

  • First‑fit: low search cost, moderate fragmentation.
  • Best‑fit: low external fragmentation, high search cost.
  • Worst‑fit: creates big leftovers, may increase internal waste.

Compaction

Compaction is a technique that moves allocated blocks to one end of memory, merging all free holes into a single large block. The OS must update each process's base address in its segment table (or any address‑translation structure used). Compaction eliminates external fragmentation at the cost of CPU time and possible process suspension.

  1. Identify all free holes.
  2. Shift each allocated block leftwards to fill the first hole.
  3. Update the base address of each moved process.
  4. Create one contiguous free region at the high end of memory.

In real systems compaction is rarely used because it interferes with real‑time guarantees and can be expensive. Modern OSes prefer non‑contiguous schemes such as paging, which avoid external fragmentation altogether.

Worked example

Question. Total memory = 100 KB. Initially the memory layout is: 20 KB allocated, 20 KB free, 35 KB allocated, 15 KB free, 10 KB allocated. A process requests 15 KB. Using first‑fit, show the layout after allocation and compute the external fragmentation (total free memory minus the size of the largest free hole).

C program.

#include <stdio.h>
int main(){
    int first_hole = 20; // KB
    int request = 15;    // KB
    int remaining = first_hole - request; // 5 KB
    int second_hole = 15; // KB
    int total_free = remaining + second_hole; // 20 KB
    int largest = second_hole; // 15 KB
    int external = total_free - largest; // 5 KB
    printf("External fragmentation = %d KB\n", external);
    return 0;
}
  1. First‑fit scans from the low address. The first free hole is 20 KB, which is large enough for the 15 KB request.
  2. Allocate 15 KB in that hole. The hole now has 20 KB – 15 KB = 5 KB remaining.
  3. The memory layout becomes: 20 KB allocated, 15 KB allocated, 5 KB free, 35 KB allocated, 15 KB free, 10 KB allocated.
  4. Total free memory = 5 KB + 15 KB = 20 KB.
  5. Largest free hole = 15 KB.
  6. External fragmentation = total free – largest hole = 20 KB – 15 KB = 5 KB.

Exam traps

  • Confusing internal fragmentation (unused space inside a block) with external fragmentation (holes between blocks).
  • Adding the sizes of all free holes and reporting that as external fragmentation without subtracting the largest hole.
  • Assuming first‑fit always leaves the smallest possible hole; it actually leaves the remainder of the first suitable hole, which may be large.
  • Forgetting to update the base address of a process after compaction, leading to incorrect memory references.

4.4 Paging and the translation look-aside buffer

Paging splits logical memory into fixed‑size pages and physical memory into frames of the same size. A page table records which frame holds each page. The translation look‑aside buffer (TLB) caches recent page‑table entries so the CPU can translate a virtual address to a physical address in a few nanoseconds. This mechanism is used in all modern desktops, smartphones and servers to give each process its own address space while keeping access fast.

You need: Memory management strategies and address spaces and Contiguous memory allocation and fragmentation.

Paging basics

A page is a block of logical memory of size P bytes. A frame is a block of physical memory of the same size. The operating system maintains a page table with one entry per page. Each entry stores the frame number, a present/absent bit and optional protection bits. When a process generates a logical address, the high‑order bits select a page number and the low‑order bits give the offset inside the page.

  1. Extract page number and offset from the virtual address.
  2. Look up the page number in the page table to obtain the frame number.
  3. Combine frame number with offset to form the physical address.

VA = pageⱼ × P + offset

VA is the virtual address; pageⱼ is the page number; P is the page size in bytes; offset < P.

  • Internal fragmentation is limited to the unused part of the last page of a process.
  • External fragmentation disappears because any free frame can hold any page.

Translation look‑aside buffer

The TLB is an associative memory that stores a small number of recent page‑table entries. A TLB hit occurs when the required page number is found in the TLB; the frame number is then available without accessing main memory. A miss forces a normal page‑table lookup, which costs an extra memory access.

  1. Send the page number to the TLB.
  2. If the entry is present (hit), read the frame number.
  3. If the entry is absent (miss), read the required page‑table entry from RAM, update the TLB, and then perform the normal memory access for the data.
EAT = h·(t_TLB + t_mem) + (1‑h)·(t_TLB + 2·t_mem)

EAT is effective access time; h is TLB hit ratio; t_TLB is TLB lookup time; t_mem is main‑memory access time.

C program.

#include <stdio.h>
int main(){
    double h=0.8, tTLB=1.0, tMem=100.0;
    double eat = h*(tTLB+tMem) + (1-h)*(tTLB+2*tMem);
    printf("EAT = %.1f ns\n", eat);
    return 0;
}

Output

EAT = 121.0 ns

Performance analysis

The effective access time shows how the hit ratio dominates performance. Increasing the hit ratio from 0.5 to 1.0 reduces the average cost by roughly half of the extra memory access. Designers therefore size the TLB to hold enough entries for the working set of a process.

  • Typical modern CPUs have TLB hit ratios above 0.95.
  • If a miss occurs, the page‑table walk may take several hundred nanoseconds.

Worked example

Question. A system has t_TLB = 1 ns, t_mem = 100 ns and a TLB hit ratio of 0.8. Compute the effective memory access time in nanoseconds.

C program.

#include <stdio.h>
int main(){
    double h=0.8, tTLB=1.0, tMem=100.0;
    double hit = tTLB + tMem;
    double miss = tTLB + 2*tMem;
    double eat = h*hit + (1-h)*miss;
    printf("%0.1f\n", eat);
    return 0;
}
  1. Compute the cost of a hit: t_TLB + t_mem = 1 ns + 100 ns = 101 ns.
  2. Compute the cost of a miss: t_TLB + 2·t_mem = 1 ns + 200 ns = 201 ns.
  3. Apply the formula EAT = h·(hit cost) + (1‑h)·(miss cost).
  4. Insert h = 0.8: EAT = 0.8·101 ns + 0.2·201 ns.
  5. Calculate 0.8·101 = 80.8 ns and 0.2·201 = 40.2 ns.
  6. Add the two parts: 80.8 ns + 40.2 ns = 121.0 ns.

  • Treating the page‑table access as a single memory read ignores that a miss requires two accesses.
  • Omitting the units (ns) can cause a student to add milliseconds to nanoseconds incorrectly.

4.5 Structure of the page table

Page‑table structures arrange translation data for fast address lookup. They exist because a process uses virtual addresses while hardware works with physical frames. The structures are used in every modern OS that supports paging, from smartphones to servers.

You need: Paging and the TLB.

Page‑table entry fields

Each entry describes one virtual page. The present bit tells whether the page is in RAM. The frame number gives the physical frame that holds the page. Protection bits allow read, write or execute access. The dirty bit shows if the page was modified.

  • Present = 1 means the page is resident; 0 triggers a page fault.
  • Frame number size depends on physical memory. For 4 GB RAM it needs 20 bits.
  • Protection bits are usually three bits: R, W, X.
  • Dirty = 1 means the page must be written back before eviction.

PFN = Page Frame Number, the index of the physical frame that stores the page.

Entry size = 1 bit (present) + 1 bit (dirty) + 3 bits (protection) + PFN bits

PFN = number of bits needed to index a physical frame

Single‑level page table and size calculation

A single‑level table has one entry for every virtual page. With a 32‑bit address and 4 KB pages the offset uses 12 bits. The remaining 20 bits form the virtual‑page number (VPN).

Number of entries = 2²⁰

2²⁰ = 1,048,576 entries

If each entry occupies 4 bytes, the table needs 4 MiB of memory.

Table size = 2²⁰ × 4 B = 4 MiB

MiB = 2²⁰ bytes

A single‑level table is simple but wasteful when a process uses only a small fraction of its address space.

Two‑level hierarchical and inverted tables

A two‑level table splits the VPN into two indexes. For the same 32‑bit address we use 10 bits for the first level, 10 bits for the second level, and 12 bits for the offset.

Entries per level = 2¹⁰ = 1,024

Each index selects one entry in its table

The first‑level table always occupies 1,024 × 4 B = 4 KB. Second‑level tables are created only when a page in that region is used.

An inverted page table stores one entry per physical frame instead of per virtual page. For a 4 GB RAM with 4 KB pages there are 2²⁰ frames. If each inverted entry is 8 bytes, the table needs 8 MiB.

  • Hierarchical tables save memory for sparse address spaces.
  • Inverted tables reduce the number of entries but require a hash search for each lookup.

Worked example

4.6 Segmentation of memory

Segmentation splits a process address space into logical parts such as code, data, stack, and heap. Each part gets its own base address and size limit, so the OS can protect and relocate them independently. It is used in some older operating systems, such as early Intel x86 OSes, or in certain embedded controllers.

You need: page‑table structure from Chapter 5.

Concept of segmentation

A segment is a contiguous block that contains a logically related set of bytes. Typical segments are code, global data, heap, and stack. The programmer or compiler assigns a segment number to each logical block. The OS stores a base‑limit pair for every segment in a segment table.

  • Base: physical start address of the segment.
  • Limit: maximum length of the segment in bytes.
  • Protection bits: read, write, execute flags for the segment; may also include privilege level (user vs. kernel).

When a process generates a logical address, it consists of a segment number s and an offset o. The OS first checks that o < limit[s]. If the check passes, the physical address is computed as base[s] + o.

PA = Base[s] + Offset

PA is the physical address; Base[s] is the base stored for segment s; Offset is the offset part of the logical address.

  1. Extract segment number s and offset o from the logical address.
  2. Read Base[s] and Limit[s] from the segment table.
  3. If o ≥ Limit[s] raise a segment‑fault.
  4. Otherwise compute PA = Base[s] + o.

Segment table and address translation

Each process has its own segment table. The table is indexed by segment number and holds a base‑limit pair plus protection bits. The table itself resides in main memory; a small cache called the segment‑table register (STR) may hold the most recent entry for fast access.

  • Entry size is usually 8 bytes (4 bytes base, 4 bytes limit) on a 32‑bit machine.
  • Protection bits are added as a separate word or packed into the limit field.

C program.

#include <stdio.h>

int main(void) {
    unsigned int segment = 2;        // segment number
    unsigned int offset  = 0x0500;   // offset within segment 2
    unsigned int base    = 0x3000;   // base of segment 2
    unsigned int limit   = 0x2000;   // size of segment 2
    if (offset >= limit) {
        printf("Segment fault\n");
        return 1;
    }
    unsigned int physical = base + offset;
    printf("Physical address = 0x%X\n", physical);
    return 0;
}

Output

Physical address = 0x3500

The same translation steps are used when segmentation is combined with paging. First the segment table gives a page‑table base, then the page table supplies the final frame number. This two‑level lookup is shown in the figure.

External fragmentation and hybrid schemes

Because each segment must be placed in a contiguous hole, free memory can become split into many small pieces. This is external fragmentation. Compaction can move segments to coalesce free space, but it is costly and rarely done in modern systems.

  • Segmentation alone cannot guarantee that a process will fit even if total free memory is sufficient.
  • Paging eliminates external fragmentation by breaking each segment into fixed‑size pages.

A hybrid called segmented paging keeps the logical convenience of segments while using paging to avoid external fragmentation. The segment table points to a page table; each segment can grow independently as pages are added.

  1. Identify the segment number from the logical address.
  2. Use the segment table to locate the page table for that segment.
  3. Translate the page number and offset using the page table as in pure paging.

4.7 Virtual memory, demand paging, page faults, copy-on-write

Virtual memory lets a process use more memory than physically present by swapping pages between RAM and disk. Demand paging brings a page only when the process accesses it, reducing start‑up load. Copy‑on‑write shares pages between processes until one writes, saving RAM and I/O. These mechanisms are essential for running large applications on smartphones, for handling many web requests on a server, and for supporting multiple virtual machines on a single host.

You need: Chapter 6 (segmentation).

Virtual memory and demand paging

Virtual memory abstracts the physical memory as a large, continuous address space. The operating system divides this space into fixed‑size pages (usually 4 KB). Only a subset of pages resides in RAM; the rest stay on secondary storage. Demand paging means a page is loaded only when the CPU tries to read or write an address that is not currently in RAM.

  • Page size is a power of two, simplifying address translation.
  • The page table maps virtual page numbers to physical frame numbers or marks the page as not present.
  • A page‑fault interrupt signals the OS that the required page is missing.

EAT = (1 − p) × ma + p × pf_time

EAT is effective access time; p is page‑fault rate (probability of a fault per memory reference); ma is memory access time (time to read a word from RAM); pf_time is the average time to service a page fault, including disk I/O and table updates.

Demand paging reduces the amount of RAM needed at program start, which is why mobile phones can run many apps simultaneously and why cloud servers can host many containers on the same hardware.

Page‑fault handling

  1. CPU generates a virtual address and sends it to the MMU.
  2. MMU looks up the page‑table entry. The entry shows ‘not present’, so the MMU raises a page‑fault interrupt to the OS.
  3. OS selects a free frame or evicts a victim page using a replacement algorithm.
  4. OS issues a read request to the Disk for the needed page.
  5. Disk returns the page data to the OS.
  6. OS updates the page‑table entry with the new frame number and sets the present bit.
  7. MMU resumes the interrupted instruction, now translating to a physical address.

The time spent in steps 3‑5 dominates the page‑fault service time. If the fault rate is high, the effective access time grows sharply, leading to thrashing.

EAT = (1 − p) × ma + p × (pf_time + ma)

EAT is effective access time; p is page‑fault rate; ma is memory access time; pf_time is the average page‑fault service time.

EAT = (1 − 0.001) × 100 ns + 0.001 × (8 ms + 100 ns)

0.001 is the fault rate; 100 ns is the RAM access time; 8 ms = 8 000 000 ns is the average service time for a page fault.

Copy‑on‑write (advanced)

Copy‑on‑write (COW) is used when a process creates a copy of its address space, for example during fork(). Both parent and child share the same physical pages marked read‑only. When either process attempts to write, the OS copies the page to a new frame, updates the page‑table, and then performs the write.

  • Reduces memory usage for processes that soon exec a new program.
  • Improves performance of fork() in Unix‑like systems.
  • Used by virtualization platforms to share identical guest OS pages.

COW is an optimization; it does not change the logical view of memory for the processes. The mechanism relies on the hardware support for page‑level protection bits.

Worked example

Question. Memory access time = 100 ns, page‑fault service time = 8 ms, fault rate = 0.001. Compute the effective access time of the system.

Exam traps

  • Adding the page‑fault time directly to the memory access time without weighting by the fault probability.
  • Confusing the page‑fault service time (disk I/O) with the time to update the page table; only the total service time belongs in the formula.
  • Assuming that a page fault always incurs a full disk read; in reality a dirty page may need to be written back first, increasing the service time.
  • Using megabytes (MB) instead of megabits (Mb) when quoting disk transfer rates, leading to a factor‑8 error.

4.8 Page replacement algorithms: FIFO, LRU, optimal

Page‑replacement algorithms decide which page to evict when a new page is needed and all frames are occupied. They keep the system running without running out of memory and affect overall speed. FIFO, LRU and the theoretical optimal algorithm are the three most taught methods. They are used in any OS that supports virtual memory, from mobile phones handling app switching to servers running many processes.

You need: Virtual memory, demand paging, page faults, copy‑on‑write.

First‑in‑first‑out (FIFO)

FIFO keeps pages in the order they entered memory. When a replacement is needed, the page that has been in memory the longest is removed, regardless of how often it was used.

  1. Maintain a queue of pages currently in frames.
  2. On a page fault, if a free frame exists, insert the page at the tail of the queue.
  3. If all frames are full, remove the page at the head of the queue and insert the new page at the tail.
  • Simple to implement with a circular buffer.
  • Can suffer from Belady’s anomaly – more frames may cause more faults.
F_faults = number of page references that are not in the current frame set

F_faults counts each miss; the algorithm does not use any future information.

Least‑recently‑used (LRU) and Optimal

LRU replaces the page that has not been used for the longest time. It approximates the optimal algorithm by using past information.

  1. Maintain a stack with most‑recently used page on top.
  2. On a hit, move the page to the top of the stack.
  3. On a fault, if a free frame exists, push the new page on top.
  4. If no free frame, pop the bottom page (least recent) and push the new page.

Optimal (Belady) replaces the page whose next use is farthest in the future. It gives the minimum possible faults for a given reference string but cannot be implemented online.

  • LRU can be implemented with hardware support such as reference bits, or approximated by algorithms like the Clock (second‑chance) method.
  • Optimal is used only for analysis and to benchmark other algorithms.

Worked example

Question. Reference string: 1 2 3 4 1 2 5 1 2 3 4 5 with 3 frames. Compute the number of page faults for FIFO, LRU and Optimal replacement.

C program.

#include <stdio.h>
#define FRAMES 3
int main(){
    int ref[] = {1,2,3,4,1,2,5,1,2,3,4,5};
    int n = sizeof(ref)/sizeof(ref[0]);
    int fifo_faults = 0, lru_faults = 0, opt_faults = 0;
    // FIFO simulation
    int q[FRAMES]; int qsize=0; int head=0;
    for(int i=0;i<n;i++){
        int p=ref[i]; int found=0;
        for(int j=0;j<qsize;j++) if(q[j]==p){found=1;break;}
        if(!found){
            fifo_faults++;
            if(qsize<FRAMES){q[qsize++]=p;}
            else{q[head]=p; head=(head+1)%FRAMES;}
        }
    }
    // LRU simulation (stack)
    int stack[FRAMES]; int sz=0;
    for(int i=0;i<n;i++){
        int p=ref[i]; int pos=-1;
        for(int j=0;j<sz;j++) if(stack[j]==p){pos=j;break;}
        if(pos==-1){
            lru_faults++;
            if(sz<FRAMES){stack[sz++]=p;}
            else{ // shift left
                for(int j=0;j<sz-1;j++) stack[j]=stack[j+1];
                stack[sz-1]=p;
            }
        }else{
            // move to top
            for(int j=pos;j<sz-1;j++) stack[j]=stack[j+1];
            stack[sz-1]=p;
        }
    }
    // Optimal simulation
    int frames[FRAMES]; int fsz=0;
    for(int i=0;i<n;i++){
        int p=ref[i]; int hit=0;
        for(int j=0;j<fsz;j++) if(frames[j]==p){hit=1;break;}
        if(hit) continue;
        opt_faults++;
        if(fsz<FRAMES){frames[fsz++]=p;}
        else{
            int farthest=-1, idx=-1;
            for(int j=0;j<FRAMES;j++){
                int next=1000; // large number
                for(int k=i+1;k<n;k++) if(ref[k]==frames[j]){next=k;break;}
                if(next>farthest){farthest=next; idx=j;}
            }
            frames[idx]=p;
        }
    }
    printf("%d\n%d\n%d\n", fifo_faults, lru_faults, opt_faults);
    return 0;
}

  2. Process each reference in order, applying the chosen algorithm.
  3. Count a fault whenever the referenced page is not already in a frame.
  4. For FIFO, evict the page that entered earliest when needed.
  5. For LRU, evict the page whose last use is oldest.
  6. For Optimal, look ahead and evict the page whose next use is farthest (or never used).

4.9 Frame allocation and thrashing

Frame allocation decides how many page frames each process may use. It keeps the system responsive when many processes compete for memory. Policies such as proportional allocation, global replacement, and local replacement control this sharing. When allocation is too small, processes generate many page faults. The resulting thrashing makes the CPU spend most time handling faults instead of useful work. Detecting thrashing early helps the OS to adjust allocation or to swap out processes. This chapter explains the policies, shows how to spot thrashing, and works through a small numeric example.

You need: Chapter 4.8 on page‑replacement algorithms.

Proportional frame allocation

The OS knows the size of each process in pages. Let p_i be the number of pages of process i. Let F be the total number of frames that can be allocated to processes (i.e., the sum of all frames currently available for use). The OS gives process i a share F_i = (p_i / Σ p_j) × F. This is called proportional allocation.

F_i = (p_i ÷ Σ p_j) × F

F_i is frames for process i; p_i is pages of process i; Σ p_j is total pages of all active processes; F is total frames that can be allocated.

Proportional allocation is fair when processes have similar working sets. It can still cause thrashing if the working set of a process exceeds its allocated frames.

  1. Collect p_i for each running process.
  2. Compute Σ p_j.
  3. Apply the formula to get F_i for each process.
  4. Round F_i to the nearest integer.

After rounding, adjust the allocations (e.g., give or take a frame from the process with the largest fractional remainder) so that the total allocated frames equals F.

Global vs local replacement

When a page fault occurs, the OS must choose a victim page to evict. In global replacement the victim can belong to any process. In local replacement the victim must be from the faulting process.

  • Global replacement can improve overall throughput because the OS can free a rarely used page from any process.
  • Local replacement protects a process from losing all its frames. It avoids starvation of a process that needs many frames.

A trap is to ignore that global replacement may starve a small process while a large process holds most frames.

Python program.

def select_victim(frames, faulting_proc, global_policy=True):
    if global_policy:
        # Choose the oldest page among all frames (FIFO example)
        return min(frames, key=lambda f: f.load_time)
    else:
        # Choose oldest page of the faulting process only
        return min(frames, key=lambda f: (f.proc_id != faulting_proc, f.load_time))

# Example usage
class Frame:
    def __init__(self, proc_id, load_time):
        self.proc_id = proc_id
        self.load_time = load_time

frames = [Frame(proc_id=1, load_time=10), Frame(proc_id=5, load_time=12)]
victim = select_victim(frames, faulting_proc=5, global_policy=False)
print(victim.load_time)  # -> 12

Working‑set model and thrashing detection

The working set W(t, Δ) of a process is the set of pages referenced in the last Δ time units before time t. If the sum of all working‑set sizes exceeds the total frames, the system thrashes.

Σ |W_i(t, Δ)| > F → thrashing

|W_i| is the number of distinct pages used by process i in the window Δ; F is total frames.

A practical symptom is a high page‑fault rate. The OS can monitor faults per second. If the rate exceeds a threshold (for example 20 faults/second per process) it flags thrashing.

The exact threshold depends on the system workload and hardware; 20 faults/s is just an illustrative value.

  1. Measure page faults for each process over a sliding window.
  2. Compute the average faults per second.
  3. If the average > threshold, declare thrashing.
  4. Reduce load by swapping out a process or increasing its frames.

Example: two processes, six frames

Process A needs 4 pages. Process B needs 4 pages. Total frames F = 6. Using proportional allocation each gets F_i = (4 ÷ (4+4)) × 6 = 3 frames.

Both processes now have fewer frames than pages. Each will fault on every reference that is not in its 3‑frame set. The page‑fault rate becomes high. The OS sees Σ |W_i| = 4+4 = 8 > 6 and flags thrashing.

Worked example

Question. Two processes each require 4 pages. The system has 6 free frames. Using proportional allocation compute the frames per process. Then determine if thrashing occurs by checking Σ |W_i| > F. Assume each process's working set equals its page demand.

C program.

#include <stdio.h>
int main(){
    int F = 6, pagesA = 4, pagesB = 4;
    int total = pagesA + pagesB;
    int FA = (pagesA * F) / total; // integer arithmetic gives 3
    int FB = (pagesB * F) / total;
    int working = pagesA + pagesB;
    int thrash = working > F;
    printf("%d %d %d\n", FA, FB, thrash);
    return 0;
}
  1. Compute total pages needed: 4 + 4 = 8.
  2. Apply proportional formula: F_A = (4 ÷ 8) × 6 = 3 frames.
  3. Similarly, F_B = 3 frames.
  4. Working set size of A = 4 pages, of B = 4 pages.
  5. Sum of working sets = 4 + 4 = 8 pages.
  6. Compare with total frames 6: 8 > 6, so thrashing occurs.

Exam traps

  • Confusing proportional allocation with equal allocation; equal allocation ignores process size.
  • Assuming global replacement always improves performance; it can cause a small process to lose all frames.
  • Using the page‑fault rate alone without checking working‑set size; a high rate may be temporary and not thrashing.

Takeaways

  1. Contiguous allocation is simple but suffers from fragmentation.
  2. Swapping enables the system to run more processes than fit in RAM.
  3. Paging eliminates external fragmentation by using fixed‑size pages.
  4. The TLB speeds up address translation by caching recent page‑frame mappings.
  5. Hierarchical page tables reduce the memory overhead of storing mappings.
  6. Segmentation provides a logical view of a program but still needs paging for protection.
  7. Demand paging brings pages into memory only when needed, reducing I/O.
  8. Copy‑on‑write shares pages until a write occurs, saving memory.
