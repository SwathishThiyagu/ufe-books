1.1 Number systems: binary, octal, decimal, hexadecimal; conversions

A number system is a way of writing a quantity with a fixed set of digit symbols, where the position of each digit carries a weight. We count in decimal because we have ten fingers; a digital circuit has two stable states, so it counts in binary. Octal and hexadecimal are shorthand: one octal digit stands for three bits and one hex digit for four, so a long bit pattern can be written and read without slips. Every memory address, colour code and register value you will meet is in one of these bases, and the first question of a Digital Logic paper is nearly always a conversion.

Positional notation and the radix

The radix (or base) r of a number system is the number of digit symbols it uses: 0 to r − 1. Decimal has r = 10; binary has r = 2 and the digits 0 and 1, each called a bit; octal has r = 8 and the digits 0–7; hexadecimal has r = 16 and needs six extra symbols, A = 10, B = 11, C = 12, D = 13, E = 14, F = 15. The base is written as a subscript: 2026₁₀, 3752₈, 7EA₁₆.

The digit in position i (0 just left of the point, negative to the right) is multiplied by rⁱ, so a number with digits dₙ … d₁ d₀ . d₋₁ d₋₂ … has the value

N = dₙ·rⁿ + … + d₁·r¹ + d₀·r⁰ + d₋₁·r⁻¹ + d₋₂·r⁻² + …

Here dᵢ is a digit (0 ≤ dᵢ < r) and rⁱ is the weight of its position. In binary the weights are 1, 2, 4, 8, 16, 32, 64, 128 … to the left of the point and ½, ¼, ⅛ … to the right. The leftmost bit is the MSB (most significant bit), the rightmost the LSB; 4 bits make a nibble and 8 bits a byte. With n bits you can write 2ⁿ patterns, the unsigned values 0 to 2ⁿ − 1: a byte holds 0 to 255.

Any base to decimal: expand the weights

Multiply each digit by its weight and add. 752₈ = 7×64 + 5×8 + 2×1 = 490₁₀. 2F.8₁₆ = 2×16 + 15×1 + 8×(1/16) = 47.5₁₀. For a long binary number the double-and-add shortcut is faster: start at 0 and, for each bit from the MSB, double the total and add the bit. For 1101₂: 0→1→3→6→13.

Decimal to any base: divide the integer, multiply the fraction

  1. Split the decimal number at its point into an integer part and a fraction part.
  2. Integer part: divide by r, note the remainder, and divide the quotient again until it is 0. The remainders read from last to first are the digits from MSB to LSB.
  3. Fraction part: multiply by r, note the integer carry (0 … r − 1), keep only the fraction, and multiply again. The carries read from first to last are the digits after the point.
  4. Stop when the fraction becomes 0 or you have enough digits. Many decimal fractions never end in binary: 0.1₁₀ = 0.000110011…₂, because its denominator 10 has the factor 5 and a binary fraction's denominator is always a power of 2.

Between binary, octal and hex: group the bits

Because 8 = 2³ and 16 = 2⁴, three bits are exactly one octal digit and four bits exactly one hex digit. Starting at the binary point and moving outward in both directions, cut the bits into groups, pad the outermost groups with zeros, and replace each group by its digit. To go the other way, replace each digit by its 3-bit or 4-bit pattern. Octal to hex goes through binary: 3752₈ = 011 111 101 010₂ = 0111 1110 1010₂ = 7EA₁₆.

Exam traps

  • Remainders are read upward, carries downward. The first remainder of the integer division is the LSB; the first carry of the fraction multiplication is the first digit after the point. Writing the remainders in the order you found them reverses the number.
  • Group from the binary point, not from the left. 101101.0101₂ in octal is 101 101 . 010 100, not 1 011 010 101. Pad with zeros only at the two outer ends.
  • A base-r number never contains the digit r. 18₈ is not an octal number and 1G₁₆ is not hex. Write the table 10 … 15 = A … F in the margin before a hex question; under pressure students read E as 15.
  • Favourite question: "convert the decimal fraction to binary up to 6 places" when the fraction does not terminate (0.1, 0.3, 0.7). Stop at the asked number of places and say the expansion repeats; do not round unless asked.

Understand Why do programmers write bit patterns in hexadecimal rather than octal? 3 marks

Memory is organised in bytes of 8 bits. Four bits make one hex digit, so a byte is exactly two hex digits (00 to FF) and a 32-bit word exactly eight. Three bits do not divide 8, so octal digits straddle byte boundaries. Octal survives where fields are 3 bits wide, such as Unix file permissions (rwx).

Analyze Which is larger, 777₈ or 1FF₁₆? What do both tell you about the largest value of an n-bit field? 4 marks

777₈ = 7×64 + 7×8 + 7 = 511 and 1FF₁₆ = 256 + 240 + 15 = 511: they are equal, both being nine 1-bits, 111111111₂. The largest unsigned value of n bits is always 2ⁿ − 1, here 2⁹ − 1 = 511, whatever base you write it in.

Analyze A register must hold any decimal number from 0 to 9999. How many bits does it need, and why can the answer not be 13? 3 marks

2¹³ = 8192 patterns are not enough for 10 000 values; 2¹⁴ = 16 384 are. So 14 bits, with 6384 patterns unused. (A BCD register, chapter 1.5, would need 16 bits for the same range.)

1.2 Binary arithmetic: addition, subtraction, multiplication, division

Binary arithmetic is the school arithmetic you already know, with two digits instead of ten. You still add column by column and carry, subtract and borrow, multiply by partial products and divide by trial subtraction; only the tables are shorter. Practise it by hand because an adder, a multiplier and a divider circuit do exactly these steps in silicon: the carry you write between two columns is the carry wire of Unit 3. Exams ask for the working, carries and all, and sometimes for the same sums in octal and hexadecimal.

You need: place weights and base conversion from chapter 1.1.

Addition: four rules and the carry

Adding two bits gives a sum bit and a carry bit: 0 + 0 = 0, 0 + 1 = 1, 1 + 0 = 1, and 1 + 1 = 10₂, that is sum 0 with carry 1. When a carry arrives from the column on the right there are three bits to add, and 1 + 1 + 1 = 11₂: sum 1, carry 1. Work from the LSB leftward, writing each carry above the next column; a carry out of the last column becomes a new MSB. Numbers with fractions are added after lining up their binary points, exactly as with decimal points. The circuit that adds one column, two bits plus a carry in, is the full adder of Unit 3.

Subtraction: the borrow

The rules are 0 − 0 = 0, 1 − 0 = 1, 1 − 1 = 0, and 0 − 1 = 1 with a borrow of 1 from the next column (because 10₂ − 1 = 1). A borrow lowers the next column's top digit by 1 before that column is worked; if that digit was 0 it becomes 1 with a further borrow, so borrows can chain through a run of zeros. Hardware does not borrow at all: it adds the 2's complement of the subtrahend, which is chapter 1.3.

Multiplication: shift and add

The binary multiplication table has one non-trivial entry: 1 × 1 = 1; everything else is 0. So each bit of the multiplier produces a partial product that is either the multiplicand itself or all zeros, shifted left to the bit's position, and the product is the sum of the partial products. Multiplying by 2 is therefore a shift left by one place, as multiplying by 10 appends a zero in decimal. An n-bit number times an m-bit number needs up to n + m bits: 4 × 3 bits gave 7 bits in the figure. Add the partial products one at a time to keep the carries manageable.

Division: shift, compare, subtract

Long division in binary is simpler than in decimal because each quotient digit is 0 or 1: at each step, if the divisor fits into the current partial remainder, write 1 and subtract, else write 0 and subtract nothing; then bring down the next bit. The remainder at the end is always smaller than the divisor. A hardware divider does the same loop of shift, compare and subtract (restoring division).

Octal and hex arithmetic follow the same rules with a carry at 8 or 16. In hex, 2A7₁₆ + 1CB₁₆: 7 + B = 18 = 16 + 2, write 2 carry 1; A + C + 1 = 23 = 16 + 7, write 7 carry 1; 2 + 1 + 1 = 4. Result 472₁₆. ✓

Exam traps

  • 1 + 1 is 10, not 2, and 1 + 1 + 1 is 11. Writing a "2" in a binary column is the commonest slip under time pressure. Say "zero, carry one" aloud as you write.
  • Line up the binary points before adding. 1101.1 + 1011.11 must be written as 1101.10 + 1011.11; pairing the right-hand ends as written gives the wrong columns.
  • Every partial product shifts one more place. The second starts one column to the left, the third two columns. A forgotten shift is the usual reason a product comes out as 15 instead of 65.
  • A borrow changes the next column before you work it. Cross out the top digit and write the reduced value above it, or you will subtract the borrow twice or not at all.
  • Favourite question: subtract a larger number from a smaller one (0111 − 1011). The borrow method leaves a dangling borrow; the examiner wants you to say the result is negative and use 2's complement (chapter 1.3).

1.3 Complements and signed number representation

A register has a fixed number of bits and no minus sign, so a negative number has to be encoded in the bits themselves. Three schemes exist: sign-magnitude, 1's complement and 2's complement. Every modern processor uses 2's complement because it lets one adder do both addition and subtraction, with no separate subtractor and no special treatment of the sign. The same idea works in any base: the 9's and 10's complements of decimal numbers, which examiners like to ask alongside the binary ones. NIT Trichy lists this chapter as "number complements" and NIT Surathkal as "1's & 2's complement".

You need: binary addition and the borrow from chapter 1.2.

Radix complements: (r − 1)'s and r's

For an n-digit number N in base r, the (r − 1)'s complement is (rⁿ − 1) − N, found by subtracting every digit from r − 1, and the r's complement is rⁿ − N, which equals the (r − 1)'s complement plus 1 (for N ≠ 0). In decimal, the 9's complement of 03250 is 99999 − 03250 = 96749 and the 10's complement is 96750. In binary, r − 1 = 1, so the 1's complement is simply every bit inverted, and the 2's complement is the 1's complement plus 1. A faster rule for the 2's complement: copy the bits from the right up to and including the first 1, then invert all the remaining bits. For 01011000: copy 1000, invert 0101 → 10101000. Taking the 2's complement twice gives back the original number, so the same rule reads a negative pattern back into its magnitude.

Three ways to write a negative number

In all three systems the MSB is the sign: 0 for positive, 1 for negative, and positive numbers look the same everywhere. They differ in how the magnitude of a negative number is stored. In sign-magnitude the remaining bits hold the magnitude: +5 = 0101, −5 = 1101. In 1's complement a negative number is the bitwise inverse of the positive one: −5 = 1010. In 2's complement it is the 2's complement of the positive one: −5 = 1011. The first two systems have two zeros (0000 and 1000 or 1111), which wastes a pattern and complicates comparison; 2's complement has one zero and one extra negative number. With n bits it covers −2ⁿ⁻¹ to +2ⁿ⁻¹ − 1, so an 8-bit byte holds −128 to +127 and a 16-bit word −32 768 to +32 767. The neatest way to read a 2's complement pattern is to give the MSB a negative weight: for 4 bits, value = −8·b₃ + 4·b₂ + 2·b₁ + 1·b₀, so 1011 = −8 + 2 + 1 = −5.

Subtraction by adding a complement

To compute A − B with n-bit numbers, add A to the 2's complement of B and discard any carry out of the MSB. If there was a carry out, the result is positive and is read directly. If there was no carry out, the result is negative and is already in 2's complement form; take its 2's complement to read the magnitude. With the 1's complement the rule is slightly different: add A to the 1's complement of B and, if a carry comes out, add it back into the LSB (the end-around carry); no carry again means a negative result in 1's complement form. The decimal versions use the 10's and 9's complements in the same way: 72532 − 3250 = 72532 + 96750 = 169282, drop the carry, 69282. ✓

Range, sign extension and overflow

Moving a signed number into a wider register is sign extension: copy the sign bit into the new positions, so −5 = 1011 in 4 bits becomes 11111011 in 8 bits (both are −5; padding with zeros would give +11). Overflow is a result outside the range of the register. In 2's complement it can only happen when two numbers of the same sign are added, and it shows as a result of the opposite sign: 0101 + 0110 = 1011, that is 5 + 6 = −5 in 4 bits, because the true answer 11 exceeds +7. The hardware test is that the carry into the sign bit differs from the carry out of it (C₃ ⊕ C₄ = 1). A carry out by itself means nothing in signed arithmetic: 1011 + 0110 = 1 0001 drops the carry and correctly gives −5 + 6 = +1.

Worked example: 2's complement subtraction

Question. Using 8-bit 2's complement arithmetic, compute 53 − 87 and verify the result. (6 marks)

  1. Write both numbers in 8 bits: 53 = 00110101₂, 87 = 01010111₂.

Worked example: 1's complement and overflow

Question. (a) Compute 01010₂ − 00111₂ using 1's complement arithmetic. (b) Add 0101₂ and 0110₂ as 4-bit 2's complement numbers and say whether the result is valid. (6 marks)

(a) 1's complement of 00111 is 11000. Add: 01010 + 11000 = 1 00010, a carry out of 1. End-around carry: 00010 + 1 = 00011. Result = 00011₂ = +3, and 10 − 7 = 3. ✓

(b) 0101 + 0110 = 1011. Both operands are positive (MSB 0) but the sum has MSB 1, so the result −5 is invalid: overflow. Carry into the sign bit is 1 (from 1 + 1 in bit 2) and carry out of it is 0; they differ, which is the hardware's overflow flag. The true sum 11 needs 5 bits: 01011.

Exam traps

  • Carry out is not overflow. In unsigned addition a carry out means the result does not fit; in signed 2's complement addition you discard the carry and check the signs (or C₃ ⊕ C₄). The examiner's favourite question gives a sum with both a carry out and no overflow, or an overflow and no carry out.
  • Only the subtrahend is complemented. For A − B, complement B and add A as it is. Complementing both gives −(A + B).
  • The range is not symmetric. 8 bits run from −128 to +127; 10000000 is −128 and has no positive partner. The 2's complement of 0 is 0 (the carry out of 1111 + 1 is dropped), so there is no −0.
  • Sign-extend when you widen. Writing 1011 (−5) as 00001011 turns it into +11. Copy the sign bit, not zeros.
  • 1's complement keeps the carry, 2's complement throws it away. End-around carry belongs to 1's complement (and 9's complement) only. Mixing the two rules is the usual reason an answer is off by one.

1.4 Fixed-point and floating-point representation

A bit pattern contains no decimal point; where the point sits is a convention. In fixed-point the point is fixed by agreement at one position, so the hardware is ordinary integer hardware and the programmer remembers the scale. In floating-point each number carries its own exponent, so the point floats: the same 32 bits can hold 0.000001 or 6 × 10²³, at the price of a limited number of significant digits. IEEE 754 is the standard every processor follows, in single (32-bit) and double (64-bit) precision. Anna University's list says "floating point numbers and operations"; NIT Surathkal and IIT Bombay list both representations.

You need: binary fractions from chapter 1.1 and 2's complement from chapter 1.3.

Fixed point: an integer with a scale factor

A fixed-point format Qm.n keeps m bits before the binary point and n after it, so the stored integer I represents the value I / 2ⁿ. The resolution (smallest step) is 2⁻ⁿ and the range is 0 to 2ᵐ − 2⁻ⁿ unsigned, or −2ᵐ⁻¹ to 2ᵐ⁻¹ − 2⁻ⁿ in 2's complement. To store 3.1416 in unsigned Q8.8, multiply by 2⁸ = 256: 804.25, round to 804 = 0000 0011 0010 0100₂ = 0324₁₆, which reads back as 804 / 256 = 3.140625, an error of 0.001. Two numbers in the same format add with the plain integer adder; a product has 2n fraction bits and must be shifted right by n. Fixed point is fast and exact for money (UPI and bank systems keep rupees as an integer count of paise) and for DSP chips, which use Q1.15 for signals in the range −1 to +1; its weakness is that the programmer must track the range by hand.

Floating point: sign, exponent, significand

Floating point is scientific notation in base 2. A number is written as ±1.f × 2ᴱ with exactly one non-zero digit before the point, which in binary is always a 1. Such a number is normalised. Three fields are stored: the sign s (1 bit, 1 = negative), the exponent E in biased form e = E + bias, and the fraction f, the bits after the leading 1. The leading 1 is not stored; it is the hidden bit, and it buys one extra bit of precision for free. The value is

value = (−1)ˢ × 1.f × 2^(e − bias)

Single precision uses 1 sign bit, 8 exponent bits with bias 127, and 23 fraction bits (24 significant bits with the hidden 1). Double precision uses 1, 11 (bias 1023) and 52. Storing the exponent with a bias instead of in 2's complement makes the whole pattern sort like an unsigned integer, so comparisons are cheap: a bigger exponent field always means a bigger magnitude.

Encoding a decimal number step by step

  1. Convert the magnitude to binary (chapter 1.1): 6.25 = 110.01₂.
  2. Normalise by moving the point so one 1 stands before it: 110.01 = 1.1001 × 2². The shift count is the true exponent E = 2.
  3. Add the bias: e = 2 + 127 = 129 = 10000001₂ (8 bits).
  4. Take the bits after the point as the fraction and pad with zeros to 23 bits: 1001 000…0.
  5. Write sign, exponent, fraction and read the 32 bits in groups of four as hex.

To decode, reverse the steps: read the sign, subtract the bias from the exponent field, put the hidden 1 in front of the fraction, and multiply.

Special values, range and precision

Two exponent patterns are reserved. All zeros with a zero fraction is zero (+0 and −0 both exist); all zeros with a non-zero fraction is a denormal number, read as 0.f × 2⁻¹²⁶ without the hidden 1, which lets values fade gradually towards zero. All ones with a zero fraction is infinity (the result of 1/0), and all ones with a non-zero fraction is NaN, "not a number" (the result of 0/0 or √−1). Normal single-precision values run from about 1.18 × 10⁻³⁸ to 3.40 × 10³⁸ with 24 significant bits, roughly 7 decimal digits; double precision runs from about 2.23 × 10⁻³⁰⁸ to 1.80 × 10³⁰⁸ with 53 significant bits, roughly 16 digits. Range comes from the exponent, precision from the fraction. Results are rounded to the nearest representable value (ties to even), which is why 0.1 + 0.2 prints as 0.30000000000000004 in most languages: neither 0.1 nor 0.2 has a finite binary form. Addition aligns the two exponents by shifting the smaller significand right, adds, renormalises and rounds; multiplication multiplies the significands and adds the true exponents.

1.5 Binary codes: BCD, Gray, Excess-3 and ASCII

A code is an agreed table that gives each symbol, a decimal digit, a letter or a shaft position, its own bit pattern. Pure binary is one such table, but not always the best one: a calculator display wants each decimal digit kept separate (BCD), a decimal adder wants a code whose complement is easy (Excess-3), a rotating sensor wants neighbouring positions to differ in only one bit (Gray), and a keyboard wants letters and punctuation (ASCII). NIT Trichy words this chapter as "binary codes, weighted and non-weighted"; NIT Calicut, Manipal and Christ assume BCD in their adder units.

You need: binary and hex conversion from chapter 1.1, the 9's complement from chapter 1.3.

What a code is: weighted and non-weighted

A 4-bit code for the ten decimal digits uses 10 of the 16 available patterns. In a weighted code each bit position has a fixed weight and the digit is the sum of the weights of its 1 bits: 8421 (ordinary BCD), 2421, 5211 and 84-2-1 (two negative weights) are the usual examples. A non-weighted code has no such weights; Excess-3 and Gray are the ones you need. A code is self-complementing when inverting every bit of a digit's code gives the code of its 9's complement, 9 − d: 2421, 84-2-1 and Excess-3 are self-complementing, plain 8421 BCD is not. That property matters for decimal subtraction by complements.

BCD and Excess-3

BCD (binary-coded decimal) writes each decimal digit separately as its 4-bit binary value, so 2026 becomes 0010 0000 0010 0110, sixteen bits where pure binary needs eleven. The six patterns 1010 to 1111 never occur. The wasted patterns are paid for wherever digits go in and out one at a time: calculators, digital clocks, meters and the seven-segment displays that Unit 3 decodes. Adding BCD digits needs a correction: add the two nibbles as binary and, if the result is greater than 9 or produced a carry out of the nibble, add 0110 (6) to skip the six unused patterns and push the carry into the next digit. Excess-3 (XS-3) is BCD plus 3: digit d is coded as the binary of d + 3, so 0 = 0011 and 9 = 1100. It is self-complementing (the 1's complement of 0101, digit 2, is 1010, digit 7 = 9 − 2) and has no all-zeros code word, so a dead data line is noticed.

Gray code: one bit changes at a time

In the Gray (reflected) code consecutive values differ in exactly one bit: a unit-distance code. Build it by reflection: write the n-bit list, mirror it, prefix the top half with 0 and the bottom half with 1 to get the (n + 1)-bit list. Conversion needs no table. Binary to Gray: copy the MSB, then each Gray bit is the XOR of the two neighbouring binary bits, gᵢ = bᵢ ⊕ bᵢ₊₁. Gray to binary: copy the MSB, then each binary bit is the XOR of the Gray bit with the binary bit you just produced, bᵢ = gᵢ ⊕ bᵢ₊₁. Gray code matters where a value is read while it changes: on a shaft encoder a binary pattern going from 0111 to 1000 could momentarily read 1111 or 0000 if the four tracks switch a fraction apart, while a Gray pattern passes through no false value. The same property orders the rows and columns of a Karnaugh map (Unit 2).

ASCII and other alphanumeric codes

ASCII (American Standard Code for Information Interchange) is a 7-bit code with 128 code points: 0 to 31 are control characters (10 = line feed, 13 = carriage return, 27 = escape), 32 is the space, 48 to 57 (30₁₆ to 39₁₆) are the digits '0' to '9', 65 to 90 (41₁₆ to 5A₁₆) are 'A' to 'Z', 97 to 122 (61₁₆ to 7A₁₆) are 'a' to 'z', and 127 is delete. Two facts save you the table: a digit character minus 30₁₆ is its numeric value, and upper and lower case differ only in bit 5 (20₁₆), so 'A' = 41₁₆ and 'a' = 61₁₆. The eighth bit of a byte was originally a parity bit (chapter 1.6). IBM mainframes use the 8-bit EBCDIC code instead. Unicode, which covers Tamil, Devanagari and emoji, keeps the 128 ASCII codes as its first block, so an ASCII file is also a valid UTF-8 file.

1.6 Error detecting and correcting codes: parity, Hamming

Bits get flipped: by noise on a cable, a cosmic ray in a memory chip, a scratch on a disc. An error-control code adds redundant bits, computed from the data, so that the receiver can tell that something changed (detection) or even which bit changed and put it back (correction). A single parity bit is the cheapest detector. Richard Hamming's code of 1950 is the classic corrector: parity bits placed at the powers of two so that their check results spell out the position of the error, an idea still inside every ECC memory module. IIT Delhi lists this as "error correction" and NIT Trichy as "error detecting and error correcting codes"; the parity generator circuit itself is in Unit 3.

You need: XOR (⊕, 1 when the two inputs differ) and binary position numbers from chapter 1.1.

Why redundancy works: Hamming distance

The Hamming distance between two words of equal length is the number of bit positions in which they differ: 1011 and 1110 differ in two. The distance of a code, d_min, is the smallest distance between any two of its valid code words. An error in fewer than d_min bits can never turn one valid word into another, so it is detected; and if the errors number at most half of that, the corrupted word is still nearer its original than any other valid word, so it can be corrected. To detect up to e errors you need d_min ≥ e + 1; to correct up to t errors you need d_min ≥ 2t + 1. A parity code has d_min = 2 (detects 1 error), the Hamming (7,4) code has d_min = 3 (corrects 1, or detects 2), and one more overall parity bit gives d_min = 4 (corrects 1 and detects 2 at once: SECDED).

Parity: one extra bit

A parity bit is appended to a data word to make the total number of 1s even (even parity) or odd (odd parity). For even parity the bit is simply the XOR of all the data bits; for odd parity it is the inverse. The ASCII code of 'A', 1000001, has two 1s, so its even-parity byte is 01000001 and its odd-parity byte 11000001. The receiver XORs all eight bits: 0 means the word passed the even-parity check. One parity bit catches any odd number of flipped bits, misses any even number, and never says which bit is wrong. Adding a parity bit to every row and every column of a block (two-dimensional parity) locates a single error at the crossing of the failing row and column. Serial links (a UART set to 7E1 sends 7 data bits with even parity) and old memory modules use parity.

Hamming code: parity bits at the powers of two

Number the bit positions of the code word from 1 and put a parity bit at every position that is a power of two (1, 2, 4, 8 …), with the data bits filling the remaining positions in order. Parity bit p₁ checks every position whose number has a 1 in its binary units place (1, 3, 5, 7 …), p₂ every position with a 1 in the twos place (2, 3, 6, 7 …), p₄ every position with a 1 in the fours place (4, 5, 6, 7 …). Each parity bit is set so that its own group has even parity. For m data bits you need the smallest r with 2ʳ ≥ m + r + 1: 4 data bits need 3 parity bits (the 7-bit (7,4) code), 8 data bits need 4 (a 12-bit word), 64 data bits need 7.

Decoding: the syndrome points at the error

  1. Recompute each parity check over its whole group, parity bit included: c₁ = XOR of positions 1, 3, 5, 7; c₂ = XOR of positions 2, 3, 6, 7; c₄ = XOR of positions 4, 5, 6, 7. A check that comes out 0 passed (even parity), 1 failed.
  2. Write the results as the binary number c₄c₂c₁, the syndrome.
  3. Syndrome 000: no single error. Any other value is the position number of the flipped bit; invert that bit. This works whether the flipped bit was data or parity.
  4. Read the data bits out of positions 3, 5, 6 and 7.

Two flipped bits produce a non-zero syndrome that points at a third, innocent position, so the (7,4) code alone cannot tell a double error from a single one. The SECDED extension adds an eighth bit holding the parity of all seven: a non-zero syndrome with correct overall parity means two errors, which are reported rather than "corrected".

Question. Encode the data word 1011 as a 7-bit even-parity Hamming code. (6 marks)

  1. Place the data in positions 3, 5, 6, 7: d₁ = 1 at 3, d₂ = 0 at 5, d₃ = 1 at 6, d₄ = 1 at 7. Positions 1, 2, 4 are the parity bits.
  2. p₁ covers 1, 3, 5, 7: the data there are 1, 0, 1, so p₁ = 1 ⊕ 0 ⊕ 1 = 0.
  3. p₂ covers 2, 3, 6, 7: the data there are 1, 1, 1, so p₂ = 1 ⊕ 1 ⊕ 1 = 1.
  4. p₄ covers 4, 5, 6, 7: the data there are 0, 1, 1, so p₄ = 0 ⊕ 1 ⊕ 1 = 0.
  5. Assemble positions 1 to 7: 0 1 1 0 0 1 1. Code word = 0110011. Check: group 1,3,5,7 = 0,1,0,1; group 2,3,6,7 = 1,1,1,1; group 4,5,6,7 = 0,0,1,1; each has an even number of 1s. ✓

Worked example: detect and correct

Question. The word 0110111 is received, encoded with the even-parity Hamming code above. Find the error, if any, and the correct data. (6 marks)

Positions 1 to 7 hold 0, 1, 1, 0, 1, 1, 1.

c₁ = pos 1 ⊕ 3 ⊕ 5 ⊕ 7 = 0 ⊕ 1 ⊕ 1 ⊕ 1 = 1   (fails)
c₂ = pos 2 ⊕ 3 ⊕ 6 ⊕ 7 = 1 ⊕ 1 ⊕ 1 ⊕ 1 = 0   (passes)
c₄ = pos 4 ⊕ 5 ⊕ 6 ⊕ 7 = 0 ⊕ 1 ⊕ 1 ⊕ 1 = 1   (fails)

Syndrome c₄c₂c₁ = 101₂ = 5, so bit 5 is wrong: it was received as 1 and should be 0. Corrected word: 0110011. Data from positions 3, 5, 6, 7: 1011, the word we encoded. ✓ Only the checks that include position 5 (p₁ and p₄) failed; that is how the syndrome encodes the position.

Exam traps

  • Say which parity you use. Even and odd parity give different code words for the same data; if the question does not specify, write "even parity assumed" and keep it throughout.
  • Positions start at 1, and the direction matters. This book (and Mano) numbers positions from the left; some books and most online calculators number from the right, which writes the same code word reversed. State your convention; the syndrome rule is unchanged.
  • Include the parity bit when re-checking, and order the syndrome as c₄c₂c₁. Checking only the data bits gives a syndrome that is always zero; writing c₁c₂c₄ turns position 3 (011) into 110 and points at the wrong bit.
  • Favourite question: "How many parity bits for 8 data bits, and where?" 2ʳ ≥ 8 + r + 1 gives r = 4, at positions 1, 2, 4, 8 of a 12-bit word.

Check yourself

Remember Define even parity, and state where the parity bits sit in a 7-bit Hamming code word. 2 marks

Even parity: the parity bit is chosen so the total number of 1s in the word is even (it equals the XOR of the data bits). Hamming (7,4): parity at positions 1, 2 and 4; data at 3, 5, 6 and 7.

Understand Why does a code with minimum distance 3 correct one error but not two? 3 marks

One flipped bit leaves the word at distance 1 from its original and at least 2 from every other valid word, so the nearest valid word is the right one. Two flips put it at distance 2 from the original and possibly distance 1 from another valid word, so nearest-word decoding picks the wrong one.

Apply Append an even parity bit (as MSB) to the ASCII code of 'C', 1000011, and then to the result of flipping its two lowest bits. What does the receiver conclude in each case? 3 marks

1000011 has three 1s, so the parity bit is 1: 11000011. Flipping the two lowest bits gives 11000000, two 1s, which still passes the even check: the double error goes undetected.

Apply The even-parity Hamming word 1010110 is received. Correct it and extract the data. 4 marks

c₁ = 1 ⊕ 1 ⊕ 1 ⊕ 0 = 1; c₂ = 0 ⊕ 1 ⊕ 1 ⊕ 0 = 0; c₄ = 0 ⊕ 1 ⊕ 1 ⊕ 0 = 0. Syndrome 001 = position 1, a parity bit. Corrected word 0010110; data (positions 3, 5, 6, 7) = 1110.

Analyze The word 0110011 is sent and bits 1 and 2 both flip. Show what the (7,4) decoder does, and explain how an eighth overall parity bit would help. 4 marks

Received 1010011: c₁ = 1 ⊕ 1 ⊕ 0 ⊕ 1 = 1, c₂ = 0 ⊕ 1 ⊕ 1 ⊕ 1 = 1, c₄ = 0 ⊕ 0 ⊕ 1 ⊕ 1 = 0; syndrome 011 = 3, so the decoder flips data bit 3 and delivers 0011 instead of 1011: a confident wrong answer. An eighth bit holding the parity of all seven is unchanged by two flips while the syndrome is non-zero; that combination means "two errors, retransmit" (SECDED).

Beyond the syllabus

Not for the exam. Server memory uses a SECDED Hamming code on each 64-bit word (72 bits stored), and the same idea protects caches on modern chips. Beyond single bits, cyclic redundancy checks (CRC-32 in Ethernet frames, ZIP and PNG files) catch burst errors, Reed–Solomon codes let a scratched CD or a torn QR code on a shop's UPI sticker still read correctly, and the LDPC and polar codes in 5G and Wi-Fi 6 get close to Shannon's channel capacity. Check digits are the same idea for numbers people type: the last digit of an Aadhaar number is a Verhoeff check digit, and card numbers use the Luhn formula. Search: "Hamming code SECDED", "CRC-32", "Reed–Solomon QR code".

  1. A base is a set of digit symbols and a weight rⁱ for each position; convert to decimal by expanding weights, from decimal by repeated division (integer) and multiplication (fraction).
  2. Octal and hex are shorthand for binary: 3 or 4 bits per digit, grouped outward from the binary point.
  3. Binary arithmetic uses the school algorithms with 1 + 1 = 10; a product needs n + m bits and a division is a loop of compare and subtract.
  4. 2's complement turns subtraction into addition: complement the subtrahend, add, discard the carry; overflow is a same-sign addition that changes sign, not a carry out.
  5. n bits of 2's complement run from −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1, with one zero and a MSB of weight −2ⁿ⁻¹; widen by sign extension.
  6. Fixed point is an integer with an agreed scale 2⁻ⁿ; floating point stores sign, biased exponent and fraction with a hidden 1, trading exactness for range.
  7. IEEE 754 single precision is 1 + 8 + 23 bits with bias 127; all-ones and all-zeros exponents are reserved for infinity, NaN, zero and denormals.
  8. BCD keeps each decimal digit in its own nibble and needs a +6 correction after addition; Excess-3 is self-complementing; Gray changes one bit per step; ASCII is a 7-bit text code.
  9. A parity bit detects any odd number of errors; a Hamming code with parity bits at positions 1, 2, 4 … corrects one error because the failing checks spell out its position.

Remember and understand

1. Define radix, weighted code, non-weighted code and self-complementing code, with one example of each. (8 marks)

Radix = number of digit symbols, with position weights rⁱ (binary 2, octal 8, hex 16). Weighted code: each bit has a fixed weight, e.g. 8421 BCD, 2421. Non-weighted: Excess-3, Gray. Self-complementing: inverting the code of d gives the code of 9 − d, e.g. Excess-3 (2 = 0101 ↔ 7 = 1010), 2421; show that 8421 BCD is not (invert 0010 = 1101, invalid).

2. Compare sign-magnitude, 1's complement and 2's complement for 8-bit numbers: encoding of −5, number of zeros, range, and hardware for subtraction. (8 marks)

−5: 10000101 / 11111010 / 11111011. Zeros: two / two / one. Range: ±127 / ±127 / −128 to +127. Subtraction: sign-magnitude needs a separate subtractor and sign logic; 1's complement needs an end-around carry (second pass); 2's complement needs one adder with the carry discarded. Conclude why processors use 2's complement.

3. Describe the IEEE 754 single-precision format: fields, bias, hidden bit, normalised and denormal numbers, zero, infinity and NaN, and the range and precision it gives. (10 marks)

1 sign, 8 exponent (bias 127), 23 fraction; value (−1)ˢ × 1.f × 2^(e − 127). Hidden 1 gives 24 significant bits (≈ 7 decimal digits). e = 0: zero (f = 0) or denormal 0.f × 2⁻¹²⁶; e = 255: infinity (f = 0) or NaN. Normal range ≈ 1.18 × 10⁻³⁸ to 3.40 × 10³⁸. Mention double precision (11 + 52, bias 1023, ≈ 16 digits) and rounding to nearest even.

4. Explain Hamming distance and show why a code with minimum distance 3 can correct one error or detect two, and what one more parity bit adds. (8 marks)

Distance = number of differing positions; d_min over all code-word pairs. Detect e errors needs d_min ≥ e + 1; correct t needs d_min ≥ 2t + 1. With d_min = 3, one flip stays nearest its original (correct), two flips may be nearest another word (detect only). Overall parity makes d_min = 4: SECDED, double errors flagged rather than mis-corrected.

Apply

5. Convert: (a) 2026₁₀ to binary, octal and hex; (b) 0.6875₁₀ to binary; (c) 3752₈ to hex; (d) 7EA₁₆ and 110101.11₂ to decimal. (10 marks)

(a) 11111101010₂, 3752₈, 7EA₁₆ with the division table and groupings shown. (b) 0.6875 → 1.375, 0.75, 1.5, 1.0 → 0.1011₂. (c) 011 111 101 010 → 0111 1110 1010 → 7EA₁₆. (d) 7×256 + 14×16 + 10 = 2026; 32 + 16 + 4 + 1 + 0.5 + 0.25 = 53.75.

7. Using 8-bit 2's complement arithmetic compute (a) 53 − 87, (b) −100 + 37, (c) 100 + 50, and state for each whether overflow occurs. (12 marks)

Analyze and evaluate

11. A payments app stores rupee amounts in single-precision float and adds ₹0.10 ten times. Explain why the total is not exactly ₹1.00, evaluate the alternatives (double precision, fixed point in paise, BCD), and find the largest amount a 32-bit signed paise count can hold. (12 marks)

0.1 has a repeating binary expansion (chapter 1.1), so each addition rounds (chapter 1.4). Double precision only hides the error. Fixed point in paise is exact and fast: 2³¹ − 1 paise = ₹21 474 836.47, about ₹2.1 crore, so use 64-bit integers for bank totals. BCD or decimal floating point is exact but slower; it suits printing and legacy systems. Spans chapters 1.1, 1.4 and 1.5.

12. Explain how one adder performs both addition and subtraction in a 2's complement machine, and analyse why "carry out" and "overflow" must be two separate flags. Use 4-bit examples including 0111 + 0001, 1000 − 0001 and 1011 + 0110. (12 marks)

A − B = A + (B̄ + 1): invert B and feed 1 as carry-in, no borrow logic (chapters 1.2, 1.3). 0111 + 0001 = 1000: no carry out, but overflow (+7 + 1 = −8). 1000 − 0001 = 1000 + 1111 = 1 0111: carry out, and overflow (−8 − 1 = +7). 1011 + 0110 = 1 0001: carry out, no overflow (−5 + 6 = +1). Unsigned code tests carry; signed code tests C_in ⊕ C_out of the sign bit; a CPU keeps both flags.

13. A four-digit decimal sensor reading is sent over a noisy link to a display. Choose and justify the code at each stage: the encoder on the sensor shaft, the stored number (BCD or binary), and the error protection (parity or Hamming), with bit counts. (12 marks)

Shaft: Gray code, so a reading taken mid-change is off by at most one step. Storage: BCD (16 bits) if the only use is the seven-segment display; binary (14 bits) if arithmetic follows. Protection: parity (one bit) only detects; a Hamming code corrects without retransmission: four (7,4) words for BCD = 28 bits, or 14 data bits + 5 parity = 19 bits for binary, 20 with SECDED. Evaluate: noisy link and no return channel favour Hamming on the binary form. Spans chapters 1.5 and 1.6.

14. Two bits of a (7,4) Hamming word flip in transit. Show what the decoder does, compare the overhead of the (7,4) code with the (72,64) code used in ECC memory, and evaluate when each is appropriate. (10 marks)

Example: 0110011 with bits 1 and 2 flipped → syndrome 011, bit 3 "corrected", data 0011 instead of 1011: silent miscorrection. Overhead: 3/4 = 75 % for (7,4), 8/64 = 12.5 % for (72,64) SECDED. Long words amortise the parity bits but each word still corrects only one error, so they suit memory (rare, isolated flips); bursty channels need CRC or Reed–Solomon instead.

Glossary

Radix (base)
The number of digit symbols in a positional number system; the weight of each position is a power of it.
Bit, nibble, byte
One binary digit; a group of 4 bits (one hex digit); a group of 8 bits (two hex digits).
MSB, LSB
Most and least significant bit: the leftmost and rightmost bits of a pattern.
Carry
The 1 passed to the next column when a column sum reaches the base.
Borrow
The 1 taken from the next column when a column difference would be negative.
Partial product
The multiplicand (or zero) shifted left to the position of one multiplier bit; the product is their sum.
(r − 1)'s complement
(rⁿ − 1) − N: each digit subtracted from r − 1; in binary, every bit inverted (1's complement).
r's complement
rⁿ − N, the (r − 1)'s complement plus 1; in binary, the 2's complement.
Sign-magnitude
Representation with a sign bit followed by the magnitude; has two zeros.
End-around carry
In 1's complement subtraction, the carry out of the MSB added back into the LSB.
Sign extension
Copying the sign bit into the new high positions when a signed number is widened.
Overflow
A result outside the range of the register; in 2's complement, a same-sign addition whose result has the opposite sign.
Fixed point (Qm.n)
An integer interpreted with an agreed binary point: m integer bits, n fraction bits, value I / 2ⁿ.
Floating point
Representation as sign × significand × 2^exponent, so the binary point moves with the exponent.
Biased exponent
The true exponent plus a constant (127 single, 1023 double), stored as an unsigned field.
Hidden bit
The leading 1 of a normalised significand, implied and not stored.
Denormal (subnormal)
A number with the all-zeros exponent field and no hidden 1, filling the gap next to zero.
NaN
"Not a number": the all-ones exponent with a non-zero fraction, produced by 0/0 or √−1.
BCD
Binary-coded decimal: each decimal digit stored as its own 4-bit binary value (8421 weights).
Weighted code
A code in which each bit position has a fixed weight; 8421, 2421, 5211, 84-2-1.
Self-complementing code
A code in which inverting the bits of digit d gives the code of 9 − d; Excess-3, 2421.
Excess-3
The decimal digit d coded as the binary of d + 3.
Gray code
A reflected, unit-distance code: consecutive values differ in exactly one bit.
ASCII
The 7-bit character code: digits from 30₁₆, upper case from 41₁₆, lower case from 61₁₆.
Parity bit
An extra bit making the count of 1s even (or odd); detects any odd number of errors.
Hamming distance
The number of bit positions in which two words differ; a code's minimum distance sets what it can detect and correct.
Hamming code
A single-error-correcting code with parity bits at the power-of-two positions.
Syndrome
The pattern of failed parity checks at the receiver; read as a binary number it is the position of the flipped bit.
SECDED
Single-error-correcting, double-error-detecting: a Hamming code plus one overall parity bit.
