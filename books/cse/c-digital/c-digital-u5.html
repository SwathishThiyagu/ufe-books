5.1 Analysis of clocked sequential circuits: state tables, diagrams

Analysis is reading: you are handed a circuit with flip-flops and gates and must say what it does. Write the Boolean equation feeding each flip-flop input, convert it into a next-state equation with the flip-flop's characteristic equation, tabulate every combination of present state and input, and draw the table as a state diagram. Once the diagram exists, the behaviour on any input sequence can be traced with a pencil, which is what examiners ask you to do.

You need: flip-flop characteristic equations and excitation tables (Unit 4, Flip-flops: SR, JK, D and T) and K-map simplification (Unit 2).

The general model of a clocked sequential circuit

Every clocked (synchronous) sequential circuit is a combinational block plus a row of flip-flops sharing one clock. This picture is often called the general model of sequential networks. The flip-flop outputs are the present state, written with letters such as A and B. The combinational block takes the present state and the external inputs (x) and produces the flip-flop inputs, which decide the next state at the next active clock edge, and the external outputs (y). Nothing changes between clock edges; that single fact makes analysis a table-filling job.

Three equations describe the circuit completely:

  • Input equations (also called excitation equations): what each flip-flop input is fed with, for example DA = Bx + Ax′.
  • Next-state equations (state equations): the state after the clock edge, A(t+1), as a function of present state and input. For a D flip-flop, A(t+1) = DA; for JK, A(t+1) = JAA′ + KA′A; for T, A(t+1) = TA ⊕ A. Design with state equations starts from exactly these.
  • Output equations: y as a function of present state (and, in a Mealy circuit, of the input too; see 5.2).

The analysis procedure

  1. Label the flip-flop outputs (A, B, …) and the inputs (x) and outputs (y). Read the input equation of every flip-flop straight off the gates.
  2. Convert each input equation into a next-state equation with the characteristic equation of that flip-flop type. With D flip-flops this step is trivial: the next state equals the D input.
  3. Build the state table. Its rows are every combination of present state and input (2m+n rows for m flip-flops and n inputs); its columns are next state and output. Fill it row by row from the equations.
  4. Draw the state diagram: one circle per state (labelled with the state's binary code), one arrow per table row, labelled "input / output" for a Mealy circuit or just "input" with the output written inside the circle for a Moore circuit.
  5. Describe the behaviour in words if asked, and trace a given input sequence from the reset state.

The table may also be written with one row per state and one column per input value (the layout in Mano's book). Either way, every (state, input) pair must appear exactly once.

Worked example

Question. A clocked sequential circuit has two positive-edge-triggered D flip-flops A and B, one input x and one output y. The gate network gives DA = Bx + Ax′, DB = A′x and y = Ax. Worked example 2: JK flip-flops

Question. A circuit has JK flip-flops A and B with JA = Bx, KA = x′, JB = x, KB = A. Find the next state for each present state and input.

Solution. Use the JK characteristic equation Q(t+1) = JQ′ + K′Q for each flip-flop: A(t+1) = (Bx)A′ + xA, B(t+1) = xB′ + A′B. Now substitute. For ABx = 011: A(t+1) = 1·1·1 + 1·0 = 1, B(t+1) = 1·0 + 1·1 = 1, so next state 11. For ABx = 110: A(t+1) = 0 + 0·1 = 0, B(t+1) = 0 + 0·1 = 0, so next state 00. Doing all eight rows: 000→00, 001→01, 010→01, 011→11, 100→00, 101→11, 110→00, 111→10. Cross-check one row from the JK truth table: at 101, JAKA = 00 (hold, A stays 1) and JBKB = 11 (toggle, B becomes 1): 11, as computed.

Exam traps

  • Writing DA and calling it "the next state" without saying why: state the characteristic equation (A(t+1) = DA) in one line; it is a mark.
  • Forgetting that a JK next state is JQQ′ + KQ′Q, not J + K′. The prime on K is where the error hides.
  • Missing rows: m flip-flops and n inputs give 2m+n rows. With 2 flip-flops and 2 inputs that is 16 rows, not 8.
  • Putting a Mealy output inside the circle of a state diagram. If y depends on x, it belongs on the arrow as x/y; if it is inside the circle the examiner reads the machine as Moore and marks the trace wrong.
  • Tracing an input sequence but reporting the output of the next state instead of the present one. In a Mealy circuit the output is produced in the same clock period as the input that causes it.

5.2 Moore and Mealy machine models

A finite state machine (FSM) has two places it can compute its output from. A Moore machine computes the output from the present state only, so the output is written inside each state circle. A Mealy machine computes the output from the present state and the present input, so the output is written on the arrows. Both are equally powerful (any behaviour one can produce, the other can), but they differ in state count, in output timing and in glitch behaviour, and examiners ask you to convert between them and to say which to pick.

Definitions

Let S be the state, X the input and Y the output. Both models share the next-state function S(t+1) = f(S, X). They differ in the output function:

  • Moore: Y = g(S). The output changes only when the state changes, which happens only at a clock edge. Output is therefore synchronous with the clock and free of glitches caused by input changes.
  • Mealy: Y = g(S, X). The output can change the moment the input changes, in the middle of a clock period. It responds one clock earlier than a Moore output for the same job, but it can glitch if the input glitches.

In a state table the difference is visible in the output columns: a Moore table has one output per row of present state; a Mealy table has one output per (present state, input) pair. The three representations are the block diagram (Figure 5.2.1), the state diagram and the state table.

Converting between the models

  1. Moore → Mealy. Take each state's output and write it on every arrow entering that state. The number of states does not change. The Mealy machine now produces each output one clock earlier than the Moore machine did.
  2. Mealy → Moore. For each state, list the outputs on its incoming arrows. If they are all the same, keep the state and give it that output. If they differ, split the state into one copy per distinct output value; every copy keeps the original's outgoing arrows, and each incoming arrow goes to the copy whose output matches it. The Moore machine may need more states, up to the number of states times the number of distinct output values.
  3. Re-check the reset state: if the reset state got split, pick the copy whose output is the one you want at reset.

Which to choose

Choose Mealy when you need the output in the same clock period as the input that triggers it, or when you want fewer states. Choose Moore when the output drives something that must not glitch (a motor, a write-enable line, a counter clock) or when a later stage samples the output on the same clock. Synthesis tools and coding guidelines prefer registered Moore outputs for exactly this reason. Note the timing rule you will be asked for: for the same specification, the Moore output appears one clock period later than the Mealy output.

Worked example

Question. A Mealy machine detects two consecutive 1s on a serial input x (overlapping allowed). Its states are S0 (no 1 pending) and S1 (one 1 seen); transitions are S0: 0→S0/0, 1→S1/0; S1: 0→S0/0, 1→S1/1. Convert it to a Moore machine and compare the output sequences for the input 0, 1, 1, 1, 0, 1, 1.

Step 1: incoming outputs. S0 has incoming arrows from S0 (output 0) and S1 (output 0): all 0, so S0 stays one state, call it A with output 0. S1 has incoming arrows from S0 (output 0) and from S1 (output 1): two different values, so S1 splits into B (output 0, "one 1 seen, nothing to report yet") and C (output 1, "two 1s seen").

Step 2: redirect arrows. Every arrow that went to S1 with output 0 now goes to B; every arrow to S1 with output 1 now goes to C. Both B and C keep S1's outgoing behaviour: on 0 go to A, on 1 go to C (because S1 on 1 gave output 1, which is C's output).

Exam traps

  • "Moore has more states" is a tendency, not a law. When every state's incoming arrows carry one output value, the Moore machine has exactly the same number of states.
  • Converting Mealy to Moore by simply moving the arrow output into the destination circle without splitting. If the arrows into a state disagree, the result is not a valid Moore machine.
  • Reporting the Moore output in the same clock as the input. It appears after the next clock edge; the one-clock delay is the answer the examiner expects in "compare the two" questions.
  • Saying Mealy outputs are "asynchronous". They are combinational functions of a synchronous state and an input; the word asynchronous is reserved for circuits without a clock (chapter 5.6).
  • In a state table, writing a Moore output under each input column. Write it once per state, or the table will be read as Mealy.

At most n × k. Each Mealy state is split into one copy per distinct output value that arrives on its incoming arrows, and there are at most k such values.

Apply Convert the Moore machine A(0): 0→A, 1→B; B(1): 0→A, 1→B into a Mealy machine. 4 marks

Copy each state's output onto its incoming arrows: arrows into A get output 0, arrows into B get output 1. Mealy: A: 0→A/0, 1→B/1; B: 0→A/0, 1→B/1. Both states now have identical rows, so they are equivalent and the Mealy machine reduces to a single state with y = x.

Apply A Mealy machine has states P and Q. Arrows into Q carry outputs 0, 1 and 1; arrows into P carry 0 only. How many Moore states result? 2 marks

Q splits into two (one per distinct value 0 and 1), P stays one: 3 Moore states.

Analyze A controller's output enables writing into a memory. Which model would you use and why? What is the cost? 4 marks

Moore (or a registered output). A write-enable that glitches can corrupt memory, and a Moore output is glitch-free between clock edges because it depends only on the state register. The cost is possibly more states and a one-clock delay before the enable responds to an input.

Beyond the syllabus

HDL coding guidelines (the Sunburst Design FSM papers by Clifford Cummings, and the FPGA vendors' style guides) go one step past Moore: they recommend registered outputs, where the output logic is computed one clock early and stored in its own flip-flops, so the output has zero combinational delay after the edge. Synthesis tools detect the FSM style from the code and re-encode it (binary, Gray, one-hot) for speed. In theoretical computer science the same two models appear as transducers, and the Moore/Mealy distinction reappears in reactive programming and protocol design. Search "registered output FSM" and "Mealy transducer". Not for the exam.

5.3 Finite state machine design

Design is analysis run backwards. You start from a sentence ("count 0, 1, 2, 4, 6 and repeat", "open the gate after two valid coins") and must end with flip-flops and gates. The route is fixed: state diagram → state table → state codes → excitation table → K-maps → circuit. The only creative step is the first one; everything after it is a procedure. This chapter gives the procedure, a complete example with unused states, and the timing check that decides how fast the finished circuit can be clocked.

You need: excitation tables of D, JK and T flip-flops (Unit 4), K-maps with don't-cares (Unit 2), and the state table of chapter 5.1.

The design procedure

  1. Specification to state diagram. Decide what the circuit must remember. Each distinct thing it must remember is a state. Draw the states, then for every state and every input value draw exactly one outgoing arrow. Mark the reset state.
  2. State table. Write the diagram as a table of present state, input, next state and output. Reduce the number of states if any are equivalent (chapter 5.4).
  3. State assignment. Give each state a binary code using n flip-flops, where 2n ≥ number of states. Codes not used by any state are unused states.
  4. Choose the flip-flop type and build the excitation table. For each row, look up the flip-flop inputs that move the present bit to the next bit: for D, the next bit itself; for JK, the excitation table (0→0: J=0, K=X; 0→1: J=1, K=X; 1→0: J=X, K=1; 1→1: J=X, K=0); for T, T = 1 when the bit changes.
  5. Simplify. One K-map per flip-flop input and per output, with unused states as don't-cares. The result is the next-state decoder (the usual name for this combinational block).
  6. Draw the circuit and check the unused states: feed each unused code through the equations and confirm it leads back into the valid sequence. If it does not, the circuit can lock up after a power-up glitch; either redo the K-maps with those cells forced, or add a reset.

Counters with arbitrary sequences

Unit 4 designed counters that count in order. The same procedure designs a counter with any sequence. A counter is an FSM with no external input: every state has exactly one outgoing arrow. With 5 states and 3 flip-flops, three codes are unused; treating them as don't-cares makes the K-maps smaller, but you must then verify where they lead.

Checking the timing: setup, hold and skew

Timing belongs to this unit too. The clock period T must give the slowest path time to settle. Let tcq be the flip-flop clock-to-output delay, tpd the delay through the next-state logic and tsu the setup time of the receiving flip-flop. Then

T ≥ t_cq + t_pd(max) + t_su          (setup constraint; sets the maximum clock frequency)
t_cq + t_pd(min) ≥ t_hold            (hold constraint; independent of T)

Example: tcq = 2 ns, tpd(max) = 5 ns, tsu = 1 ns give T ≥ 8 ns, so fmax = 1/8 ns = 125 MHz. Clock skew (the clock reaching two flip-flops at different times) eats the hold margin when the receiving flip-flop gets the clock late, and the setup margin when it gets it early; a static timing analysis tool checks every path for both constraints. Propagation delay analysis is this calculation counted gate by gate.

Exam traps

  • Not stating which bit is the most significant. Write "A B C, A = MSB" before the table; otherwise 4 and 1 can be swapped and everything after is wrong.
  • Using the don't-cares in the K-map and then forgetting to check where they lead. "Check unused states" is often a separate part-mark.
  • Mixing up the JK excitation table: 1→0 needs J = X, K = 1; students write J = 0, K = 1 and lose the don't-care that would simplify the map.
  • Drawing a state diagram with a state that has two arrows for the same input, or none. Each state must have exactly one arrow per input value.
  • Computing fmax from the sum of all gate delays in the circuit instead of the longest single path from one flip-flop to the next.

5.4 State reduction and state assignment

A state diagram drawn from a specification usually has more states than the job needs, because two states that "feel" different may behave identically from the outside. State reduction finds such equivalent states and merges them, which can remove a flip-flop and always simplifies the logic. State assignment then decides which binary code each surviving state gets; the choice does not change the behaviour, but it changes the amount of logic, sometimes by a factor of two. Both are examined as procedures with a table to fill, so learn the mechanics.

Equivalent states

Two states p and q are equivalent if, for every input sequence, the machine produces the same output sequence whether it starts in p or in q. Checking all sequences is impossible, so use the recursive definition: p ≡ q if (1) for every input value they give the same output, and (2) for every input value their next states are equivalent (either the same state, or a pair already known to be equivalent, or the pair p, q itself). Equivalent states can be merged into one with no change in behaviour. Some syllabi call the result "exact state reduction" to distinguish it from the compatibility-based merging used for incompletely specified machines (those with don't-care outputs), where states need only be compatible, not equivalent, and the merging is not unique (see chapter 5.7 for the asynchronous version).

Two ways to find them

  1. Row matching. Look for two rows of the state table that are identical (same next states and same outputs for every input). Merge them by deleting one and renaming it to the other everywhere. Repeat until no identical rows remain. Quick and enough for most exam tables, but it can miss equivalences that are only visible through a chain of implications.
  2. Implication chart. A triangular table with one cell for every pair of states (Figure 5.4.1). Put ✗ in every cell whose pair has different outputs for some input. In every other cell, write the pairs of next states that must be equivalent for this pair to be equivalent. Then sweep: cross out any cell that lists a crossed-out pair; repeat until a sweep changes nothing. The cells that survive are the equivalent pairs. This method is exact.

Choosing codes

For n states the choices are binary (⌈log2 n⌉ flip-flops, the fewest), Gray (same count, adjacent states differ in one bit, which reduces logic when the sequence is mostly linear), and one-hot (n flip-flops, one per state, exactly one of them 1). One-hot costs flip-flops but the next-state logic becomes one or two gates per state and the decoding of outputs is free, which is why FPGA tools prefer it. The three heuristics for binary assignment are: give adjacent codes to states that have the same next state for a given input; to states that are the next states of one state; and to states with the same output. They are guidelines, not guarantees; the exact optimum needs trying all assignments, which is impractical beyond a handful of states.

Exam traps

  • Merging two states because their next states are the same while ignoring that their outputs differ. Equal outputs for every input is the first test, before anything else.
  • Stopping row matching after one pass. Each merge can create new identical rows; repeat until nothing changes, as the chain b→d, c→e, a→b above shows.
  • In the implication chart, writing "a–a" and treating it as a condition. A pair of a state with itself is trivially true; only pairs of different states can fail.
  • Claiming that state reduction always reduces the number of flip-flops. 6 → 5 states still needs 3 flip-flops; the saving is then only in the logic.
  • Describing one-hot as "wasteful" without the other half: it uses more flip-flops but less combinational logic and runs faster.

Beyond the syllabus

Exact minimisation of completely specified machines is polynomial (Hopcroft's partition-refinement algorithm runs in O(n log n) for n states, the same algorithm that minimises deterministic finite automata in compiler courses). State assignment for minimum logic is also hard; classic tools (NOVA, MUSTANG) and today's synthesis engines use heuristics based on the structure of the next-state function. 5.5 Sequence detector design

A sequence detector watches a serial input, one bit per clock, and raises its output when the last few bits match a given pattern. It is the standard FSM design question because it exercises every step of chapter 5.3 and because its state diagram has a trick: when the pattern fails part-way, the machine must not forget bits that could be the start of a new match. This chapter designs an overlapping Mealy detector for 1011 from the sentence to the gate equations, then shows how the Moore and non-overlapping variants differ.

You need: the design procedure (5.3), Mealy and Moore models (5.2).

States are "how much of the pattern have I seen"

For a pattern of length n, the detector needs states for "nothing useful seen", "first bit matched", "first two matched", …, "first n−1 matched". A Mealy detector therefore needs n states and raises the output on the arrow that completes the match; a Moore detector needs n + 1 states, the extra one being "pattern complete" with output 1. The sequence 1011 gives Mealy states S0 (nothing), S1 (seen 1), S2 (seen 10), S3 (seen 101).

The rule for the arrows: from each state and each input bit, the next state is the longest suffix of the bits seen so far that is also a prefix of the pattern. For example, in S3 (seen 101) an input 0 gives the history 1010; its longest suffix that starts the pattern 1011 is 10, so go to S2, not to S0. This is the part students get wrong, so check every "failure" arrow against the rule.

Overlapping or not

In an overlapping detector the bits of one match may be reused for the next: in 1011011 the pattern 1011 appears twice, sharing the middle 1. After a match the machine goes to the state for the longest useful suffix (here 1, so S1). In a non-overlapping detector the machine returns to S0 after each match and 1011011 contains only one match. Exam questions say which they want; if they do not, state your assumption and design the overlapping version.

Variants the examiner may ask

  • Sending every failed bit back to S0. Apply the longest-suffix rule to each failure arrow; for 1011, S3 on 0 goes to S2 and S1 on 1 stays in S1.

  • Marking the Mealy output 1 inside S3. S3 means "101 seen", and the output is 1 only on the arrow with input 1.
  • Counting states wrongly: Mealy needs n states for a length-n pattern, Moore needs n + 1.
  • Skipping verification. Tracing a short input through the final equations (not the diagram) catches K-map slips and is usually worth marks.

5.6 Asynchronous sequential circuits: fundamental and pulse mode

Take the clock away and a sequential circuit becomes a combinational block whose outputs are wired back to its own inputs through the small delays of real gates. It changes state whenever an input changes, so it is faster and needs no clock distribution, but it can also chase its own tail. An asynchronous sequential circuit is analysed with a transition table whose stable states are the only places it can rest. The latches of Unit 4 are the simplest examples; this chapter gives the general model, the two operating modes and the analysis procedure.

You need: SR and gated latches (Unit 4), K-maps (Unit 2).

The model and the two modes

Figure 5.6.1 (left) shows the model. The combinational logic receives the external inputs x1, x2, … and the present state variables y1, y2, …, called the secondary variables. It produces the outputs and the next state variables Y1, Y2, …, called the excitation variables. Each Y feeds back to become y after the propagation delay of the gates (drawn as a delay element). While Y ≠ y the circuit is in an unstable state and is still moving; when Y = y for the present inputs it is in a stable state and stays there until an input changes.

  • Fundamental mode: the inputs are levels. Only one input is allowed to change at a time, and the circuit must reach a stable state before the next change. This is the usual mode and the one the design methods of chapter 5.7 assume.
  • Pulse mode: the inputs are short pulses. At most one input pulses at a time, and the pulse is long enough to change the state but gone before the new state can feed back. Each pulse plays the role of a clock edge, so pulse-mode circuits are analysed like clocked circuits and are often built from flip-flops clocked by the pulses.

Analysis procedure (fundamental mode)

  1. Cut each feedback loop and name the signal there: y on the input side (present state), Y on the output side (next state). One pair per loop.
  2. Write the Boolean equation of each Y and of each output in terms of the inputs and the y variables.
  3. Draw the transition table: rows are the combinations of y variables, columns are the input combinations in Gray order (00, 01, 11, 10), cells hold the Y values. Circle every cell whose Y equals the row's y: these are the stable states.
  4. To trace behaviour, start in a stable state. When an input changes, move horizontally to the new column in the same row. If that cell is circled, you are done; if not, move vertically to the row named by the cell (y becomes Y) and look again. Repeat until a circled cell is reached.
  5. Replace the binary rows by letters if you want a flow table (chapter 5.7); it is the same information with named states and the outputs added.

Pulse mode in one example

Suppose a circuit has two pulse inputs P1 and P2 and must set its output z to 1 after P1 has pulsed twice without an intervening P2, and clear z on any P2. Because pulses never overlap, the "input combinations" are just P1 and P2, and the analysis is a Moore state table: states A (no P1 yet, z = 0), B (one P1, z = 0), C (two P1, z = 1); A: P1 → B, P2 → A; B: P1 → C, P2 → A; C: P1 → C, P2 → A. The circuit is built with flip-flops clocked by the pulses, and the table has no stable/unstable distinction because the state changes once per pulse. Syllabi that cover both modes treat pulse-mode design as the clocked procedure of chapter 5.3 with the pulse as the clock.

Exam traps

  • Circling the wrong cells: a cell is stable when its entry equals the row value y, not when it equals the neighbouring cell.
  • Writing the input columns in binary order 00, 01, 10, 11. Use Gray order 00, 01, 11, 10 so that a single input change is a move to an adjacent column; the race analysis of chapter 5.7 depends on it.
  • Moving diagonally in the table. An input change is a horizontal move; a state change is a vertical move; never both at once.
  • Confusing the secondary variables y (present, after the delay) with the excitation variables Y (next, before the delay).
  • Treating a Mealy clocked circuit as "asynchronous" because its output changes between edges. Asynchronous means no clock at all.

5.7 Flow tables, races, cycles and race-free assignment

Designing an asynchronous circuit runs the analysis of chapter 5.6 backwards: specification → primitive flow table → reduced flow table → binary codes → excitation maps → gates. The danger is at the coding step. When a transition asks two state variables to change together, the gates will not change them at the same instant, and the circuit passes through an intermediate code it was never meant to visit. That is a race; if the intermediate code leads to a different stable state the race is critical and the circuit is wrong. A race-free assignment makes every transition change one variable at a time, adding spare states and deliberate cycles where needed.

You need: transition tables and stable states (5.6), state reduction ideas (5.4).

Primitive flow table and its reduction

A flow table is a transition table with named rows and the outputs added: each cell holds the next state (circled when stable) and the output. A primitive flow table is the first one drawn from the specification; it has exactly one stable state per row, and because only one input changes at a time, the cells two input-bits away from the stable one are don't-cares. Two rows are compatible if in every column they have the same next state or one of them is a don't-care, and their specified outputs agree. Compatible rows are merged (a merger diagram shows which rows can go together), giving a reduced flow table with several stable states per row: the asynchronous version of chapter 5.4, with don't-cares doing most of the work.

Races and cycles

  • Race: a transition in which two or more state variables must change, for example from 00 to 11. Depending on which gate is faster, the circuit passes through 01 or 10.
  • Non-critical race: whichever path is taken, the circuit ends in the same stable state. Harmless.
  • Critical race: different paths end in different stable states, or one path is stable at the intermediate code. The final state depends on gate delays: a design error.
  • Cycle: a sequence of unstable states passed through on the way to a stable one, such as a → d → c, where d is unstable in that column. A deliberate cycle is the standard cure for a race; a cycle that never reaches a stable state is an oscillation and must be avoided.

To find a race, write each transition as a pair of codes; if they differ in more than one bit, it is a race. To classify it, look up every intermediate code in the same column and see where it leads.

Race-free assignment

  1. Draw the transition diagram: one node per state of the reduced flow table, one line for every transition that occurs in some column. States joined by a line must get adjacent codes.
  2. Try to place the states on an n-cube (a square for 2 variables, a cube for 3) so that every line joins neighbours. A triangle in the diagram makes this impossible without help.
  3. Add spare states (unused codes) and route the awkward transitions through them as cycles, as in Figure 5.7.1. A three-row flow table needs 4 codes; a four-row table whose diagram has all six lines needs 3 variables (8 codes).
  4. If spare codes are not enough, use a multiple-row assignment (each state gets two codes, so that every other state is adjacent to one of them) or a one-hot assignment, which changes two bits per transition and so needs a "two-hot" intermediate cycle.
  5. Write the final transition table with the spare rows filled, and draw an excitation map (a K-map) for each Y to obtain the gate equations.

  • Forgetting the output during the cycle: give the intermediate unstable state the output of the start or the end state so the output does not glitch.
  • Mixing primitive and reduced tables: the primitive table has one stable state per row; a merged table has several.

Check yourself

Remember Define race, critical race and cycle. 3 marks

Race: two or more state variables change in one transition. Critical race: the final stable state depends on which variable changes first. Cycle: a sequence of unstable states passed through before reaching a stable state.

Remember What is special about a primitive flow table? 1 mark

It has exactly one stable state in each row.

Understand Why does Gray-order column labelling matter for race analysis? 2 marks

A single input change moves to an adjacent column. With Gray order, adjacent columns differ in one input bit, so a horizontal step of one column is a legal fundamental-mode change and the table can be read directly.

Understand Why can a non-critical race be left in a design? 2 marks

All possible paths through the intermediate codes end at the same stable state, so the behaviour does not depend on delays; only the transient path differs, which does not affect the function (though the output should be checked for glitches).

Apply In column 01 of a transition table, the circuit starts in row 00 and both state bits must change to reach the stable state 11. Rows 00, 01 and 10 all go to 11. Is the race critical? 3 marks

From 00 to 11 the intermediate codes are 01 and 10; both go to 11 in that column, so every path ends at the same stable state: non-critical.

Apply A four-state flow table has transitions a–b, b–c, c–d, d–a only. Give a race-free two-variable assignment. 3 marks

The diagram is a square, so place the states on the cycle of the 2-cube: a = 00, b = 01, c = 11, d = 10. Every transition changes one bit; no spare states are needed.

Analyze Compare the spare-state method and the one-hot method of race-free assignment for a 3-state table. 4 marks

Spare state: 2 variables, one extra row, two transitions become two-step cycles; least hardware. One-hot: 3 variables (100, 010, 001); every transition changes two bits, so each goes through a two-hot intermediate (e.g. 110) that must be filled in, giving one extra step on every transition; more flip-flop-like variables but a systematic table that is easy to fill and always race-free.

Beyond the syllabus

Race-free assignment with the fewest state variables is a classic hard problem (Unger's 1969 book and Tracey's method are the references), and tools such as Petrify synthesise asynchronous controllers from signal transition graphs rather than flow tables. Modern asynchronous design mostly uses speed-independent or delay-insensitive styles, where correctness does not depend on gate delays at all. Search "Petrify STG synthesis" and "speed-independent circuits". Not for the exam.

5.8 Static, dynamic and essential hazards; hazard-free design

A Boolean function says what the output must be for every input; it says nothing about the few nanoseconds during an input change, when some gates have seen the new value and others have not. A hazard is a condition in which that gap can produce a momentary wrong output, a glitch. In a clocked circuit the glitch dies before the next edge. In an asynchronous circuit it is fed straight back as a state change, so hazards must be removed by design, and the removal is a K-map trick: add the redundant product term that bridges the gap.

You need: K-maps and prime implicants (Unit 2), transition tables (5.6). The "structural, data and control hazards" some syllabi list elsewhere are processor-pipeline hazards, a different topic.

The three kinds

  • Static-1 hazard: the output should stay 1 while one input changes, but it dips to 0 for a moment. It occurs in sum-of-products (AND-OR) circuits when two adjacent 1-cells of the K-map are covered by different product terms and no term covers both.
  • Static-0 hazard: the output should stay 0 but spikes to 1. The dual case, in product-of-sums (OR-AND) circuits, when two adjacent 0-cells are covered by different sum terms.
  • Dynamic hazard: the output should change once (0 → 1) but changes three times (0 → 1 → 0 → 1). It needs three or more paths of different delay from input to output, so it occurs only in circuits with more than two levels.
  • Essential hazard: specific to asynchronous sequential circuits. An input change reaches the state logic by two routes, directly and through the feedback; if the feedback route is faster than the direct one (say the direct route passes through a slow inverter), the circuit acts as if the input had changed three times and ends in the wrong stable state. It is a property of the flow table, not of the gates, so no K-map work removes it.

Hazard-free design

  1. Draw the K-map and the minimal SOP cover as usual.
  2. Look for every pair of adjacent 1-cells that are not inside a common loop. Each such pair is a static-1 hazard for the input whose change moves between the two cells.
  3. Add a product term that covers the pair, which is always the consensus of the two terms involved (for xy′ + y z the consensus is xz). The function is unchanged, since the consensus term is implied by the others; only the circuit changes.
  4. Repeat until every adjacent pair of 1s shares a loop. The two-level AND-OR circuit is then free of static-1 hazards and, being two-level, of dynamic hazards, for single input changes. For a POS circuit cover every pair of adjacent 0s with a common sum term.
  5. In an asynchronous circuit, also test the flow table for essential hazards (below) and add a delay in the feedback path where one is found.

Finding an essential hazard

Use the flow table. From a stable state s with input x, let s1 be the stable state reached after one change of x, and s3 the stable state reached after three changes (x → x′ → x → x′). If s1 ≠ s3, the table has an essential hazard at (s, x): a delayed copy of the input can act as the extra two changes and send the circuit to s3. Any circuit that toggles on every change of an input has this property. The fix is enough delay in the feedback path that the new input value reaches every gate before the state variables change; re-mapping the logic cannot remove it, which is why it is called essential.

Worked example

Question. F(A, B, C) = Σm(2, 5, 6, 7) is implemented as the minimal SOP F = BC′ + AC with gates of 10 ns delay. (a) Show that the circuit has a static-1 hazard and find the duration of the glitch when A = B = 1 and C changes from 1 to 0. (b) Design a hazard-free circuit.

(a) Locating the hazard. The map (Figure 5.8.1) has 1s at m2 (A′BC′), m6 (ABC′), m5 (AB′C) and m7 (ABC). BC′ covers m2 and m6; AC covers m5 and m7. The adjacent pair m7–m6 differs only in C and has no common loop: a static-1 hazard for a change of C when A = B = 1.

Timing. Take t = 0 as the instant C falls. The inverter output C′ rises at t = 10 ns. The AND gate AC sees C fall at t = 0 and its output falls at t = 10 ns. The AND gate BC′ sees C′ rise at t = 10 ns and its output rises at t = 20 ns. The OR gate sees AC fall at 10 ns, so F falls at 20 ns; it sees BC′ rise at 20 ns, so F rises again at 30 ns. F should have stayed 1; instead it is 0 from t = 20 ns to t = 30 ns, a 10 ns glitch. In a clocked system with a 100 ns period this is harmless; fed back into an asynchronous latch it could reset it.

(b) Hazard-free design. The consensus of BC′ and AC (eliminate C) is AB, which covers exactly m6 and m7. Add it: F = BC′ + AC + AB. During the change above AB = 1 throughout, so F stays 1. The other adjacent pairs: m2–m6 share BC′, m5–m7 share AC, m6–m7 now share AB. No pair is uncovered, so the circuit is free of static-1 hazards, at the cost of one 2-input AND gate and one more OR input.

Exam traps

  • Saying "the minimal expression is the hazard-free one". It is the opposite: the hazard-free cover is the minimal cover plus the consensus terms, so it is never smaller.
  • Looking for hazards between 1s that are not adjacent (differ in two inputs). Hazards are defined for single input changes; only adjacent cells matter.
  • Checking only the K-map for an asynchronous design. Essential hazards live in the flow table and survive any gate-level fix; they need a feedback delay.
  • Claiming dynamic hazards are fixed by the consensus term alone. They are avoided by using a two-level, static-hazard-free realisation; multi-level factoring can reintroduce them.
  • Giving the glitch duration by reflex. Work it from the path lengths: here the slower path has one extra gate (the inverter), so the glitch lasts one gate delay; the OR gate's own delay shifts both edges equally and does not add to it.

Check yourself

Remember Define static-1, static-0 and dynamic hazards. 3 marks

Static-1: output should stay 1 but momentarily goes to 0. Static-0: output should stay 0 but momentarily goes to 1. Dynamic: output should change once but changes three (or more) times.

Remember Which kind of hazard cannot be removed by adding gates, and what removes it? 2 marks

The essential hazard; it is removed by inserting delay in the feedback path so the input change reaches the logic before the state change does.

Understand Why does the consensus term not change the function? 2 marks

The consensus theorem states xy + x′z + yz = xy + x′z: the term yz is implied by the other two, so adding it changes the circuit but not the truth table.

Understand Why are hazards tolerated in synchronous circuits? 2 marks

Flip-flops sample their inputs only at the clock edge; as long as the glitch settles before the setup time of the next edge, it has no effect. In asynchronous circuits there is no edge to wait for, so a glitch can be captured as a state change.

Apply F = (A + B)(A′ + C) is built from OR gates and an AND gate. Find the static-0 hazard and the hazard-free POS expression. 4 marks

With B = 0, C = 0: F = A·A′ = 0 for both values of A. When A rises 0 → 1, (A + B) rises after one gate delay while (A′ + C) falls only after the inverter plus the OR, so both are 1 for one gate delay and the AND output spikes to 1: a static-0 hazard. Add the consensus sum term (B + C): F = (A + B)(A′ + C)(B + C); with B = C = 0 the new term holds F at 0.

Apply G(A, B, C, D) = AB′ + BD + A′D is a minimal cover. Which adjacent 1-pairs are uncovered, and what is the hazard-free SOP? 4 marks

1-cells: AB′ = {8, 9, 10, 11}, BD = {5, 7, 13, 15}, A′D = {1, 3, 5, 7}. Uncovered adjacent pairs: m9–m13 and m11–m15 (B changes, between AB′ and BD), fixed by the consensus AD; m1–m9 and m3–m11 (A changes, between A′D and AB′), fixed by the consensus B′D. BD and A′D overlap at m5 and m7, so their pairs are already covered. Hazard-free G = AB′ + BD + A′D + AD + B′D.

Analyze A designer argues that making all gates exactly equal in delay removes hazards. Evaluate the claim. 4 marks

It does not. The static-1 hazard in the worked example comes from path length: the BC′ path has an extra inverter, so even with identical gate delays the two paths differ by one gate. Equal delays only remove hazards that arise from unequal delays on paths of equal length. Hazard-free design must not rely on delay matching, which also drifts with temperature and supply voltage.

Beyond the syllabus

Hazard analysis today is done by timing simulation, and glitch power is a real concern: every glitch in CMOS charges and discharges a load, and in large datapaths glitches are a sizeable fraction of dynamic power, so synthesis tools balance path delays to reduce them. In security, deliberately injected glitches (fault injection) are a standard attack on smart cards. Search "glitch power CMOS" and "fault injection glitch attack". Not for the exam.

Takeaways

  1. Analysis is always: input equations → next-state equations (via the characteristic equation) → state table → state diagram → trace.
  2. Moore outputs depend on state only and are glitch-free but one clock late; Mealy outputs depend on state and input and respond at once.
  3. Design is the same chain in reverse, plus state assignment, the excitation table of the chosen flip-flop and K-maps with unused states as don't-cares; always check where the unused states go.
  4. Two states are equivalent when their outputs agree and their next states are equivalent; row matching is quick, the implication chart is exact.
  5. A good assignment gives adjacent codes to states that are "near" each other in the diagram; one-hot trades flip-flops for logic.
  6. In a sequence detector, every failed bit sends the machine to the longest useful suffix, never blindly to the start.
  7. Without a clock, a circuit rests only in stable states (Y = y); analysis moves horizontally on an input change and vertically on a state change.
  8. A transition that changes two state variables is a race; it is critical if the outcome depends on delays, and it is cured by adjacent codes, spare rows and cycles.
  9. A static hazard is an uncovered pair of adjacent 1s (or 0s); the consensus term removes it. Essential hazards live in the flow table and need a feedback delay.
  10. The maximum clock frequency comes from the slowest flip-flop-to-flip-flop path: T ≥ tcq + tpd + tsu.

Glossary

Characteristic equation
Formula for a flip-flop's next output in terms of its inputs and present output (D: Q⁺ = D; JK: Q⁺ = JQ′ + K′Q; T: Q⁺ = T ⊕ Q).
Clocked (synchronous) circuit
Sequential circuit whose flip-flops all change state only at the active edge of one clock.
Critical race
Race whose final stable state depends on which state variable changes first.
Cycle
Sequence of unstable states passed through before a stable state is reached.
Dynamic hazard
Output changes three or more times when it should change once; needs three or more paths of different delay.
Equivalent states
States that give the same output sequence for every input sequence; mergeable without changing behaviour.
Essential hazard
Flow-table hazard in which an input change reaching the logic later than the resulting state change sends the circuit to the wrong stable state.
Excitation table
Table giving the flip-flop inputs needed for each present-to-next transition of one bit.
Excitation variable (Y)
Next-state value computed by the logic of an asynchronous circuit, before the feedback delay.
Flow table
Transition table of an asynchronous circuit with named rows, circled stable states and outputs.
Fundamental mode
Operation with level inputs, one input change at a time, and settling before the next change.
Implication chart
Triangular table of state pairs used to find all equivalent states exactly.
Mealy machine
FSM whose output depends on present state and present input; outputs written on the arcs.
Moore machine
FSM whose output depends on the present state only; outputs written in the states.
Next-state decoder
The combinational logic that computes flip-flop inputs from present state and inputs.
One-hot assignment
One flip-flop per state, exactly one of them 1 at a time.
Overlapping detector
Sequence detector that may reuse the tail of one match as the start of the next.
Primitive flow table
First flow table drawn from a specification, with one stable state per row.
Pulse mode
Operation with non-overlapping pulse inputs, each pulse causing one state transition.
Race
Transition in which two or more state variables must change at once.
Secondary variable (y)
Present-state value of an asynchronous circuit, the fed-back copy of Y.
Self-correcting counter
Counter whose unused states all lead back into the valid sequence.
Sequence detector
FSM that outputs 1 when the last bits of a serial input match a given pattern.
Setup and hold time
Intervals before and after the clock edge during which a flip-flop's input must be steady.
Stable state
Row and input column of a transition table where Y = y, so the circuit rests.
State assignment
Choice of binary code for each state.
State reduction
Merging of equivalent (or compatible) states to obtain a smaller machine.
Static hazard
Momentary wrong output when the output should stay constant (static-1 dips to 0, static-0 spikes to 1).
Transition table
Table of next-state values Y for each present state y and input combination.
