2.1 NumPy arrays: creation, indexing, slicing and reshaping

A NumPy array (type ndarray, "n-dimensional array") is a grid of values of one type, stored side by side in one block of memory. Because every element has the same type and size, NumPy runs a whole calculation in fast compiled code instead of a slow Python loop. pandas, scikit-learn and Matplotlib all keep their numbers in NumPy arrays, so every later chapter of this unit stands on this one.

You need: Python lists, loops and functions, and the idea of structured (tabular) data from Unit 1 (Facets of data: structured, semi-structured and unstructured).

What an array is

After import numpy as np (the usual short name), every array tells you four facts about itself:

  • ndim: the number of axes (dimensions). A list of numbers has 1; a table has 2.
  • shape: a tuple with the length along each axis. A table of 4 rows and 3 columns has shape (4, 3).
  • size: the total number of elements, the product of the shape: 4 × 3 = 12.
  • dtype: the type of every element, such as int64 (64-bit integer, 8 bytes each), float64, bool or <U5 (text of up to 5 characters).

In a 2-D array, axis 0 runs down the rows and axis 1 runs across the columns. A Python list is different: it holds pointers to separate objects of any type, so [1, 2] * 2 repeats the list to [1, 2, 1, 2], while np.array([1, 2]) * 2 doubles each element to [2 4]. Arithmetic on arrays is element-wise. Mixed input is upcast to one type: np.array([1, 2.5, 3]) becomes float64, and np.array([1, 'a']) becomes text.

Creating arrays

np.array([[1, 2], [3, 4]])      # from nested lists, shape (2, 2)
np.zeros((2, 3))                # 2 x 3 array of 0.0
np.ones(5); np.full((2, 2), 7)  # five 1.0s; a 2 x 2 array of 7s
np.arange(0, 10, 2)             # [0 2 4 6 8]: start, stop (excluded), step
np.linspace(0, 1, 5)            # [0.   0.25 0.5  0.75 1.  ]: 5 points, both ends included
np.eye(3)                       # 3 x 3 identity matrix
rng = np.random.default_rng(42)
rng.integers(1, 7, size=10)     # ten dice throws
a.astype(float)                 # a copy of a with a new dtype

Examiners like this pair: arange takes a step and leaves out the stop; linspace takes a count and includes both ends.

Indexing, slicing and masks

Indexing picks one element. Positions count from 0, and negative positions count from the end, so a[-1] is the last element. In 2-D, a[i, j] is row i, column j.

Slicing picks a range with start:stop:step. The stop position is not included; a missing start means 0 and a missing stop means "to the end". So a[1:3, 0:2] is rows 1 and 2, columns 0 and 1; a[:, 2] is all of column 2; np.arange(10)[2:8:2] is [2 4 6]; a[::-1] reverses.

A slice is a view: it shares memory with the original array, so writing into the slice changes the original. NumPy does this to avoid copying crores of numbers for every slice. Call .copy() when you need an independent array.

A boolean mask is an array of True/False of the same shape, made by a comparison such as a > 80. a[mask] keeps the True positions. Combine conditions with &, | and ~ (and, or, not): (a > 50) & (a < 80). Fancy indexing passes a list of positions: a[[0, 2, 5]]. Masks and fancy indexing return copies, not views.

With an axis, sum(axis=0) collapses the rows and gives one total per column; sum(axis=1) gives one per row. mean, max and min work the same way.

Reshaping

  1. reshape(r, c) gives the same data a new shape. The sizes must match: r × c must equal size, or NumPy raises ValueError: cannot reshape array of size 12 into shape (5,2).
  2. One length may be -1, meaning "work it out": twelve elements reshaped to (-1, 4) become (3, 4).
  3. Elements are laid in row-major (C) order: row 0 fills first, then row 1 (Figure 2.1.1).
  4. ravel() flattens to 1-D (a view when it can), flatten() always copies, .T transposes (3, 4) to (4, 3), and reshape(-1, 1) makes one column.

Exam traps

  • The stop index is left out: a[1:3] is two elements (positions 1 and 2), not three.
  • Slices are views; masks and fancy indexing are copies. Changing a slice silently changes the original.
  • axis=0 means "collapse the rows", so sum(axis=0) gives column totals. Students often swap the two.
  • marks[:, 0] > 80 & marks[:, 1] > 80 fails because & binds tighter than >; bracket each condition, and never use and or or on arrays.
  • The favourite question: "Differentiate a Python list from a NumPy array" (one type, one memory block, element-wise arithmetic, speed).

Beyond the syllabus

Not for the exam. An array is really a block of bytes plus a shape and strides (how many bytes to jump to reach the next row or column); reshape, transpose and slicing only change these numbers, which is why they cost nothing. The Python array API standard lets the same code run on GPU libraries such as CuPy and on JAX and PyTorch, whose "tensors" are ndarrays by another name. 2.2 Pandas Series and DataFrames

pandas puts labels on NumPy arrays. A Series is a one-dimensional array with an index of labels; a DataFrame is a table made of several Series that share one row index, one Series per column, each column with its own type. It exists because real tables mix types (names, dates, rupees) and are addressed by name ("the fee column", "student 102"), not by position. Every cleaning step in the rest of this unit is a DataFrame operation.

You need: Chapter 2.1 (arrays, slicing, boolean masks).

Series: values with labels

import pandas as pd
runs = pd.Series({'Kohli': 82, 'Rohit': 45, 'Gill': 67})
runs['Rohit']       # 45   by label
runs.iloc[0]        # 82   by position
runs.values         # [82 45 67], the NumPy array inside
runs[runs > 50]     # Kohli 82, Gill 67: a mask, as in NumPy

Built from a list, a Series gets the default index 0, 1, 2, …; built from a dict, the keys become the index. The rule that makes pandas different from NumPy is alignment: when two Series are combined, pandas matches labels, not positions.

s1 = pd.Series([10, 20, 30], index=['a', 'b', 'c'])
s2 = pd.Series([1, 2, 3], index=['b', 'c', 'd'])
print(s1 + s2)

Label a exists only in s1 and d only in s2, so their sums are NaN ("not a number", pandas' mark for a missing value; Chapter 2.3). NaN is a float, which is why the integers became float64.

DataFrame: a table of Series

You can build a DataFrame from a dict of lists (each key becomes a column), from a list of dicts (each dict becomes a row), or from a NumPy array with columns=[…]. Most often you read a file: pd.read_csv('fees.csv'), read_excel, read_json or read_sql. The first look at any new table is always the same five calls:

  • df.shape: (rows, columns). df.columns and df.index: the two sets of labels.
  • df.head(): the first 5 rows.
  • df.info(): each column's non-null count and dtype. A text column shows object in pandas 2 and str in pandas 3.
  • df.describe(): count, mean, standard deviation, minimum, quartiles and maximum of each numeric column (the statistics themselves are Unit 3).

2.3 Data cleaning: missing values and duplicates

Data cleaning fixes the parts of a table that are missing, repeated or wrong before anyone analyses it. This chapter takes the first two. Values go missing when a sensor stops during a Chennai power cut or a student skips a form field; rows repeat when someone double-taps "Submit" or the same customer comes from two files. Both quietly bend averages and counts, so a model trained on them learns the wrong thing. Anna Univ calls this step "cleansing", SRM lists "handling missing data", NITK and Manipal list "imputation", and NITC lists "duplicates" and "missing data".

You need: Chapter 2.2 (DataFrames, masks, loc). The mean, median and mode are measured properly in Unit 3; here they are only used as fill values.

Why values go missing

The reason a value is missing decides what you may do about it. There are three standard cases:

  • MCAR, missing completely at random. The gap has nothing to do with any data: a temperature logger lost power for an hour. Deleting such rows loses data but does not bias the rest.
  • MAR, missing at random. The chance of a gap depends on another column you do have: older customers skip the email field more often. Filling within groups (by age band) handles it well.
  • MNAR, missing not at random. The chance depends on the missing value itself: people with very high incomes leave the income question blank. No fill rule fully repairs this; say so in your report.

Finding missing values

pandas marks a missing number as NaN, a missing date as NaT, and a missing text value as NaN or None. df.isna() gives a True/False table of the same shape; df.isna().sum() counts the gaps in each column, and df.isna().mean() * 100 gives the percentage. df[df['age'].isna()] shows the affected rows.

Watch for disguised missing values: −999, an age of 0, "NA", "?" or "-". pandas sees them as real values. Declare them while reading, pd.read_csv('f.csv', na_values=['?', '-', -999]), or afterwards with df.replace(-999, np.nan).

Dealing with missing values

  1. Delete. dropna() drops every row with any NaN; how='all' drops only fully empty rows; thresh=k keeps rows with at least k values; subset=['fee'] looks only at chosen columns; axis=1 drops columns. Use it when few rows are affected and the gaps are MCAR.
  2. Fill with a constant when the gap has a meaning: fillna(0) for "no purchases", fillna('Unknown') for a category.
  3. Impute with a statistic. Use the mean for a roughly symmetric number column, the median when the column is skewed or has outliers, and the mode (most frequent value) for a category. Filling by group is often better: df['fee'] = df.groupby('city')['fee'].transform(lambda s: s.fillna(s.mean())) uses each city's own mean.
  4. Use the neighbours in ordered data such as daily readings. For [30, NaN, NaN, 36], ffill() carries the last value forward to give [30, 30, 30, 36], and interpolate() draws a straight line to give [30, 32, 34, 36].
  5. Predict the value from other columns with a model such as regression or nearest neighbours (models are Unit 5).

Before filling, add an indicator column, df['age_missing'] = df['age'].isna(), so that a model can still learn that the value was missing.

Duplicates

df.duplicated() is True for every row that repeats an earlier row in all columns. With keep='first' (the default) the first copy counts as the original; keep='last' keeps the last copy; keep=False marks every copy. df.drop_duplicates(subset=['sid'], keep='last') compares only the key column and keeps the latest record of each student.

Near-duplicates such as "Ravi" and "ravi " are not caught, because the text differs. Make the text uniform first (strip spaces, one case; Chapter 2.7), then remove duplicates. Matching the same person across two different files is record linkage (Chapter 2.9). Always remove duplicates before imputing, because a repeated row is counted twice in a mean.

2.4 Handling errors and outliers

An error is a value that is wrong: a typing slip, an impossible age of 250, a price in paise among prices in rupees. An outlier is a value far from the rest. Some outliers are errors, but many are real (a Diwali sales spike, a genuine ₹5 lakh UPI transfer), and those are often the most important rows. So the job has two parts: detect unusual values with a clear rule, then decide case by case whether to correct, remove, cap or keep them. SRM lists this as "outlier/noise and anomalies", NITK as "outlier removal" and NITC as "errors and outliers"; NITT goes further into distance-based and density-based anomaly detection and the local outlier factor.

You need: Chapter 2.3 (NaN and filling). Quartiles, standard deviation, z-scores and box plots are defined in Unit 3; here they are only detection rules.

Kinds of errors and their fixes

  • Format errors: numbers stored as text, such as "1,500", "₹1200" or "abc". Strip the symbols; pd.to_numeric(…, errors='coerce') turns anything unreadable into NaN.
  • Validity errors: impossible values such as age 250, a negative quantity, 31 February or 140%. Write the rule down and apply it: df.loc[df['age'] > 120, 'age'] = np.nan.
  • Unit errors: one branch sends kilograms and another grams, or paise instead of rupees. They show up as values about 100 or 1000 times the rest; fix them by converting, not deleting.
  • Inconsistent categories: "TN", "Tamil Nadu" and "tamilnadu". Map them to one form (Chapters 2.5 and 2.7).
  • Noise: small random measurement errors. Smooth them by binning (Chapter 2.5) or averaging; do not delete them.
raw = pd.Series(['1200', '1,500', 'abc', '-40', '980'])
num = pd.to_numeric(raw.str.replace(',', ''), errors='coerce')  # [1200, 1500, NaN, -40, 980]
num = num.mask(num < 0)                                        # [1200, 1500, NaN, NaN, 980]

Detecting outliers in one column

Z-score rule. z = (x − x̄)/s, where x̄ is the mean and s the standard deviation; flag the value when |z| > 3. It suits large, roughly bell-shaped data. Its weakness is masking: the outlier itself raises both x̄ and s, which shrinks its own z. With n values the largest possible |z| is (n − 1)/√n, only 3.02 for n = 11, so on a small sample the rule almost never fires.

IQR rule (Tukey's fences). Q1 and Q3 are the 25th and 75th percentiles and IQR = Q3 − Q1. Flag x when

x < Q1 − 1.5 × IQR   (lower fence)     or     x > Q3 + 1.5 × IQR   (upper fence)

Quartiles hardly move when one extreme value is added, so this rule is robust; it is also how a box plot decides which points to draw separately. Quartile methods differ slightly between books and software; pandas by default interpolates at position (n − 1)p of the sorted list, counting from 0. In an exam, state the method you use.

Modified z-score. M = 0.6745 (x − median)/MAD, where MAD is the median of the absolute deviations |x − median|. Flag |M| > 3.5. It replaces the mean and s by robust versions.

Outliers across several columns

A record can look normal in each column but odd as a pair, such as height 150 cm with weight 95 kg. Distance-based methods flag a point whose k-th nearest neighbour is far away, or that has few points within a distance d. Density-based methods compare how crowded a point's neighbourhood is with how crowded its neighbours' neighbourhoods are. The local outlier factor (LOF) is that ratio: about 1 for an ordinary point, well above 1 for a point in a sparse region.

Treating outliers

  1. Correct it when the true value is known (divide paise by 100).
  2. Remove it when it is an error that cannot be fixed.
  3. Cap (winsorize) it at the fences or at the 1st and 99th percentiles: s.clip(lower, upper).
  4. Transform the column, for example with a log, so large values pull less (Chapter 2.5).
  5. Keep and flag it with an is_outlier column, and use the median or a robust model. Write every decision down.

2.5 Data transformation: normalization, discretization and mapping

Data transformation changes the values of a column into a form that models and people can use, without changing what they mean. Normalization puts numbers on a common scale, discretization (binning) cuts a range of numbers into labelled intervals, and mapping replaces each value by another through a dictionary or a function. Without scaling, a model that measures distance (k-means or nearest neighbours, Unit 5) lets a salary of ₹6,00,000 drown an age of 21. SRM lists this as "binning, classing and standardization", NITC as "transformation using a function/mapping" and "discretisation", and NITK as "normalization".

You need: Chapter 2.4 (outliers, which must be handled before scaling). The mean, standard deviation and z-scores are defined in Unit 3 (Normal distribution and z-scores).

Normalization and standardization

  • Min-max normalization to [0, 1]: x′ = (x − min)/(max − min). To a range [a, b]: x′ = a + (x − min)(b − a)/(max − min). It keeps the shape of the data, but one huge value squashes everything else near 0.
  • Z-score standardization: z = (x − μ)/σ, where μ is the mean and σ the standard deviation. The result has mean 0 and standard deviation 1 and is not bounded. NumPy's np.std divides by n (population σ); pandas' .std() divides by n − 1 (sample s). Say which one you used.
  • Decimal scaling: x′ = x/10j, where j is the smallest integer that makes every |x′| < 1.
  • Robust scaling: (x − median)/IQR, which outliers barely affect.
  • Log transform for right-skewed data such as incomes or video views: log10 turns 1, 10, 100, 1000 into 0, 1, 2, 3. Use log(1 + x) when zeros occur.

Compute the min, max, μ and σ on the training data only and reuse those same numbers on new data. A new value can then fall outside [0, 1], and that is correct.

Discretization (binning)

Equal-width binning makes k intervals of width w = (max − min)/k: pd.cut(x, k), or pd.cut(x, bins=[…], labels=[…]) with your own edges. It is easy to explain, but the bins can hold very different counts. Equal-frequency (equal-depth) binning puts about n/k values in each bin: pd.qcut(x, k). Figure 2.5.1 shows both on the same data.

Binning also smooths noise. In smoothing by bin means each value is replaced by its bin's mean; in smoothing by bin boundaries each value is replaced by the nearer of its bin's minimum and maximum. Bins with names (young, middle, senior) form a concept hierarchy, as do city → state → region.

pandas intervals are closed on the right, (a, b]. When it chooses the edges itself, pd.cut stretches the lowest edge by 0.1% of the range so the minimum is included, which is why you see (17.955, 33.0].

Mapping

Series.map replaces every value through a dictionary or a function; values missing from the dictionary become NaN. Series.replace changes only the values it finds and leaves the rest alone. For grades ['A', 'B', 'A', 'C', 'S'] with {'S': 10, 'A': 9, 'B': 8}, map gives [9, 8, 9, NaN, 10] and replace gives [9, 8, 9, 'C', 10]. map(func) and apply(func) run any function, such as np.log10 or a rule that maps a pincode to a district. Turning categories into numeric columns for a model is feature engineering (Chapter 2.8).

2.6 Combining, merging, reshaping and pivoting datasets

Data rarely sits in one table. Marks are in one file and student names in another; each month's sales arrive as a new sheet. Combining stacks tables, merging joins them on a shared key column, and reshaping and pivoting switch a table between long form (one row per observation) and wide form (one column per category). Only SRM ("merging on index, concatenate, combining with overlap, reshaping, pivoting") and NITC ("combining and merging data, reshaping and pivoting") list this as a separate topic, so this chapter is short.

Combining and merging

  • pd.concat([a, b]) stacks rows; axis=1 places tables side by side. Missing columns become NaN; ignore_index=True renumbers the rows.
  • pd.merge(a, b, on='sid', how=…) works like an SQL join. inner keeps keys found in both tables, left keeps every row of a, right every row of b, outer every key from either, with NaN where a side is missing.
  • Merging on index: left_index=True, right_index=True, or the shortcut a.join(b).
  • Combining with overlap: a.combine_first(b) keeps a's values and fills its gaps from b, matching labels.

Reshaping and pivoting

pivot(index, columns, values) turns long data into wide: one row per index value, one column per category. If an (index, column) pair occurs twice it raises an error; pivot_table then combines the repeats with aggfunc (mean by default, or 'sum', 'count'). melt does the reverse, wide to long. stack and unstack move a level between rows and columns of a multi-level index (Chapter 2.7).

2.7 Data wrangling and hierarchical indexing

Data wrangling, also called data munging, is the whole hands-on job of turning raw data into a tidy table ready for analysis: parsing, cleaning, transforming, combining, reshaping and summarizing. Chapters 2.3 to 2.6 are its parts; this chapter adds the glue: tidy data, text clean-up, grouping, and hierarchical (multi-level) indexing, which lets a two-dimensional table hold data with more dimensions, such as city × quarter. Anna Univ, SRM and NITC teach it; NITC also lists data quality, metadata, canonicalization and the legal and ethical aspects, and SRM lists string manipulation and summarizing.

You need: Chapter 2.2 (DataFrames, loc) and Chapter 2.6 (pivoting).

Tidy data and the wrangling loop

A table is tidy when every variable is a column, every observation is a row, and every value sits in one cell. Sales stored in columns named Q1_2025 and Q2_2025 are not tidy, because the quarter (a variable) is hidden in the column names; melt fixes that. Wrangling goes round a loop:

  1. Discover: info(), head(), value_counts() on each text column.
  2. Structure: correct the types, reshape to tidy form.
  3. Clean: missing values, duplicates, errors (Chapters 2.3, 2.4).
  4. Enrich: merge other tables, add derived columns (Chapters 2.6, 2.8).
  5. Validate: check rules such as "fee > 0" and "one row per student".
  6. Publish: save the clean table with its metadata (data about the data: what each column means, its unit, source and date), usually as a data dictionary.

Data quality is judged on accuracy, completeness, consistency, timeliness, validity and uniqueness; each step of the loop improves one or more of them.

String manipulation and canonicalization

Text columns have a .str accessor that applies a string method to every value: strip(), lower(), title(), replace(), split(), contains(), len() and extract() with a regular expression. Canonicalization brings every spelling of the same thing to one standard form, so that grouping and matching work:

city.str.strip().str.title().replace({'Madras': 'Chennai'})   # ' chennai', 'CHENNAI', 'Madras' → 'Chennai'
phone.str.replace(r'\D', '', regex=True).str[-10:]            # '+91 98400 12345' → '9840012345'

Dates are canonicalized the same way, to one format such as 2026-01-05 (Chapter 2.9).

Group, apply, combine

df.groupby('city')['sales'].sum() splits the rows by city, applies a function to each group and combines the answers into one result. agg(['sum', 'mean', 'count']) applies several functions at once. transform returns one value per original row, which is how Chapter 2.3 filled gaps with each city's own mean. Grouping by two keys gives a result with a two-level index.

Hierarchical indexing

A MultiIndex has two or more levels, so each row label is a tuple such as ('Chennai', 'Q2'). You get one from set_index(['city', 'quarter']), from a two-key groupby, or from pd.MultiIndex.from_tuples or from_product.

  • Select: t.loc['Delhi'] takes every row whose outer label is Delhi (partial indexing); t.loc[('Chennai', 'Q2')] takes one; t.xs('Q1', level='quarter') takes a cross-section on the inner level. Slicing a range of labels needs a sorted index, so call sort_index() first.
  • Reshape: unstack() moves the inner level to the columns; stack() moves it back; swaplevel() swaps the levels; reset_index() turns them into ordinary columns.
  • Aggregate by level: t.groupby(level='city').sum().

Legal and ethical care

Wrangling often touches personal data: names, phone numbers, Aadhaar numbers, health records. India's Digital Personal Data Protection Act, 2023 requires personal data to be processed for a lawful purpose, usually with the person's consent. 2.8 Feature engineering and feature selection

A feature is one input column that a model learns from. Feature engineering builds better features from raw columns using what you know about the problem; feature selection keeps the useful features and drops the rest. Good features often matter more than the choice of algorithm: "is it a weekend?" predicts food-delivery orders better than a raw date ever can. Seven universities teach this. IITB lists "feature engineering, imputation, forward selection, backward elimination"; NITT lists "classifying feature selection methods, information theory-based filtering, chi-square based filtering, wrapper-type feature selection"; Manipal lists feature engineering beside data preparation and imputation.

You need: Chapters 2.3 (imputation), 2.5 (scaling, binning, mapping) and 2.7 (grouping). Models and validation accuracy appear properly in Unit 5.

Engineering features

  • Encoding categories. One-hot encoding, pd.get_dummies(df, columns=['city']), makes one 0/1 column per category. For ordered categories (S > A > B) map them to numbers instead (Chapter 2.5).
  • Dates and times. Day of week, month, a weekend flag, hour of day, days since the last purchase, a festival-week flag.
  • Ratios and combinations. Amount per item, price per square foot, BMI = weight/height² (kg/m²).
  • Aggregates. A customer's average order value or number of orders in the last 30 days, built with groupby and transform (Chapter 2.7).
  • Transforms, bins and flags. A log of a skewed amount, age bands, and a "was missing" indicator beside an imputed column (Chapters 2.3, 2.5).

Why select features

More columns are not always better. Irrelevant features add noise; redundant ones (height in cm and in inches) add nothing; and with many features and few rows a model fits chance patterns in the training data, the curse of dimensionality. Fewer features also train faster and are easier to explain to a bank manager or a doctor.

Three families of selection methods

Filter methods score each feature with a statistic, without any model, and keep the best k. Common scores: variance (drop near-constant columns), Pearson correlation with a numeric target (Unit 3), the chi-square test for a categorical feature against a categorical target (Unit 4), and mutual information or information gain, which measures how much knowing the feature reduces uncertainty about the target. Filters are fast, but they judge one feature at a time, so they keep redundant pairs and miss features that only help together.

Wrapper methods search over subsets, training and validating the model on each one.

  1. Forward selection: start with no features; in each round add the one feature that raises the validation score most; stop when the best gain is below a set amount.
  2. Backward elimination: start with all features; in each round remove the feature whose removal hurts least (or helps); stop when every removal hurts too much.
  3. Recursive feature elimination: train, drop the feature with the smallest weight or importance, and repeat.

Trying every subset of n features needs 2n − 1 fits: for 20 features, 10,48,575. Forward selection needs at most n + (n − 1) + … + 1 = n(n + 1)/2, which is 210. Wrappers are accurate but slow, and with small data they can overfit the validation set.

Embedded methods select while the model trains. L1 (Lasso) regularization pushes the weights of weak features to exactly zero; decision trees and random forests give every feature an importance score. Do not confuse selection with feature extraction: PCA and LDA (Unit 5, Dimensionality reduction) build new features as combinations of the old ones, while selection keeps a subset of the original columns.

2.9 Data integration and ETL processes

Data integration combines data from several sources into one consistent view. ETL (extract, transform, load) is the pipeline that does it on a schedule, usually to fill a data warehouse. A college keeps fees in an accounts system, attendance in a biometric system and marks in an exam portal; the question "do students with fee dues miss more classes?" needs all three joined correctly, with the same student recognised in each. Seven universities teach this: Anna Univ lists "integrating" as a step of the data science process, Manipal lists "data integration", and Christ lists "big data integration and ETL processes".

You need: Chapters 2.3–2.7 (every transform step reuses them) and Unit 1 (Data sources and data collection).

Problems integration must solve

  1. Entity identification (schema matching). One system says cust_id, another CustomerNo. Are they the same attribute? Read the metadata (data dictionary) and map each source column to one target name.
  2. Value conflicts. Paise against rupees, kilograms against pounds, "M/F" against 1/2, and dates: 06-01-2026 is 6 January in India but 1 June in the United States.
  3. Redundancy. The same fact stored twice or derivable from another column (age and date of birth; annual = 12 × monthly). Correlation for numbers (Unit 3) and the chi-square test for categories (Unit 4) reveal it.
  4. Duplicate entities across sources. "R. Kumar" in one system and "Ravi Kumar" in another may be one person. Record linkage matches them on canonicalized name, phone and date of birth (Chapter 2.7).
  5. Different grain. Daily rows in one source and monthly totals in another must be brought to one level, usually by aggregating the finer one.

The ETL process

  • Extract: read from databases, CSV and Excel files, web APIs and log files. A full extract reads everything; an incremental extract reads only rows changed since the last run, found by a last-modified timestamp or by change data capture.
  • Stage: keep the raw copies in a staging area, so a failed transform can be rerun without touching the source systems again.
  • Transform: clean (Chapters 2.3, 2.4), conform (one name, unit, date format and code list for each attribute), match keys and remove duplicates, join and aggregate (Chapters 2.6, 2.7), create surrogate keys, and validate (row counts, totals, rules such as amount > 0).
  • Load: write into the target, either a full reload or an incremental append or update. A warehouse stores events in fact tables (each sale) and descriptions in dimension tables (customer, product, date, branch); Unit 6 covers warehouses and data lakes.
  • Schedule and monitor: run nightly or hourly, log each run, and raise an alert when a row count suddenly drops.

ETL, ELT and big data integration

In ELT the raw data are loaded first into a cloud warehouse or data lake and transformed there with SQL. It suits large volumes, and the raw data stay available for questions nobody has asked yet. Batch integration runs on a schedule; stream integration processes each event as it arrives, which a fraud alert on a UPI payment needs (Unit 6, Apache Spark and stream processing). Big data adds variety (JSON, logs, images) and volume, so the same steps run on cluster tools instead of one laptop.

Takeaways

  1. A NumPy array holds one type in one block of memory; arithmetic is element-wise, slices are views, and masks and fancy indexing are copies.
  2. pandas adds labels: loc selects by label with the end included, iloc by position with the end excluded, and Series arithmetic aligns on labels.
  3. Remove duplicates first, then fill gaps: median for skewed numbers, mode for categories, forward fill or interpolation for ordered readings, and an indicator column when missingness itself may matter.
  4. An outlier is not automatically an error. The IQR rule is robust; the z-score rule suffers from masking and cannot fire on small samples.
  5. Scale with numbers learned from the training data only: min-max, z-score, decimal scaling, robust scaling or a log. Bin by equal width or equal frequency and smooth by bin means or boundaries.
  6. merge is an SQL join; pivot, pivot_table and melt switch between wide and long form. Check the row count after every merge.
  7. Canonicalize text before grouping; a MultiIndex keeps higher-dimensional data in one table, and unstack/stack reshape it.
  8. Feature engineering builds features, feature selection keeps the useful ones (filter, wrapper, embedded), and target leakage makes a model look better than it is.
  9. Integration resolves entity identification, value conflicts, redundancy and duplicate entities; ETL extracts, transforms and loads on a schedule, and ELT loads before transforming.

Analyze11. Compare the z-score rule, the IQR rule and the local outlier factor for outlier detection. Give a case where each fails.10 marks

Glossary

ndarray
NumPy's n-dimensional array: values of one type in one block of memory, with a shape and a dtype.
View
An array or DataFrame that shares memory with another, so a change to one shows in the other; a slice is a view.
Boolean mask
An array of True/False used to keep the positions or rows where a condition holds.
Series
pandas' one-dimensional labelled array: values plus an index.
DataFrame
pandas' table: columns of possibly different types that share one row index.
Index
The labels of the rows (or of a Series) used for lookup and alignment.
NaN
"Not a number": the floating-point value pandas uses to mark a missing value.
Imputation
Filling missing values with estimates such as the mean, median, mode or a model's prediction.
MCAR, MAR, MNAR
Missing completely at random, at random given other columns, and not at random (depending on the missing value itself).
Outlier
A value far from the rest of the data; it may be an error or a real, important case.
IQR
Interquartile range, Q3 − Q1: the spread of the middle half of the data.
Masking
An outlier inflating the mean and standard deviation so that its own z-score looks ordinary.
Winsorizing
Capping extreme values at chosen limits (fences or percentiles) instead of deleting them.
Local outlier factor
A density-based score comparing a point's neighbourhood density with that of its neighbours; well above 1 means outlier.
Normalization
Rescaling values to a fixed range, usually [0, 1] (min-max).
Standardization
Rescaling to mean 0 and standard deviation 1 (z-score).
Discretization
Cutting a numeric range into intervals (bins), by equal width or equal frequency.
Concept hierarchy
Levels of generality for a value, such as age → age band, or city → state → region.
Merge (join)
Combining two tables by matching the values of key columns: inner, left, right or outer.
Pivot table
A wide table with one row per index value and one column per category, combining repeats with an aggregate function.
Tidy data
A layout where every variable is a column, every observation a row and every value one cell.
Data wrangling
The whole job of turning raw data into an analysis-ready table; also called data munging.
Canonicalization
Converting every variant of the same value to one standard form.
Metadata
Data about data: meaning, unit, source and date of each column, often kept in a data dictionary.
MultiIndex
A pandas index with two or more levels, so each row label is a tuple.
One-hot encoding
Turning a category column into one 0/1 column per category.
Target leakage
A feature or preprocessing step that uses information not available at prediction time, making accuracy look falsely high.
Forward selection / backward elimination
Wrapper methods that add the most useful feature, or remove the least useful one, one round at a time.
Entity identification
Deciding which attributes or records in different sources describe the same real thing.
ETL / ELT
Extract, transform, load (transform before loading) / extract, load, transform (transform inside the target).
