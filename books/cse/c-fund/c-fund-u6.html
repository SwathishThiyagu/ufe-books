6.1 Pointers and passing addresses to functions

Every variable lives at a numbered location in memory, its address. A pointer is a variable whose value is an address. C has pointers so that a function can reach data that is not its own: with a plain argument a function gets a copy and can only read; with an address it can go to the original and change it. That is how scanf fills your variable, how swap actually swaps, and how a function hands back two results instead of one.

You need: call by value (Unit 5, Parameter passing), arrays and their memory map (Unit 5), and memory as numbered bytes (Unit 1).

Address, pointer, and the two operators

When you write int a = 25; the compiler reserves 4 bytes somewhere, say at address 1000, and stores 25 there. The name a is your label for address 1000. Two operators work with the address itself:

  • &a (address-of) gives the address of a: the number 1000.
  • *p (dereference, "value at") goes to the address stored in p and reads or writes the variable there.

A pointer is declared by writing the type of thing it points to, a star, and the name: int *p; reads as "*p is an int", so p is a pointer to int. The type tells the compiler how many bytes to read at that address (4 for int, 1 for char, 8 for double on the usual 64-bit compilers) and how far to step in pointer arithmetic.

int a = 25;
int *p = &a;      /* p holds 1000, the address of a */
printf("%d\n", *p);   /* prints 25: the value at 1000 */
*p = 30;              /* writes 30 into a, through p  */
printf("%d\n", a);    /* prints 30                    */

A pointer that points nowhere should hold NULL (defined in <stdio.h> as address 0). Dereferencing NULL or an uninitialised pointer crashes the program with a segmentation fault, so initialise every pointer and test if (p != NULL) before using one that might be empty.

Pointer arithmetic and arrays

Adding 1 to a pointer moves it to the next element, not the next byte. If int *q holds 1000, then q + 1 is 1004 and q + 3 is 1012, because each int takes 4 bytes. This is why an array name behaves like a pointer to its first element: for int m[5], m[i] is defined as *(m + i).

int m[5] = {10, 20, 30, 40, 50};
int *q = m;                 /* same as q = &m[0] */
printf("%d %d\n", m[2], *(q + 2));   /* 30 30 */

An array argument is passed as the address of its first element, so a function that receives an array can modify the caller's array directly, and it needs the size as a separate parameter because a pointer does not know how long the array is.

Passing addresses to a function

C passes every argument by value: the function gets a copy, works on the copy, and the caller's variable is untouched. So void swap_wrong(int x, int y) { int t = x; x = y; y = t; } does nothing useful. The fix, called call by reference in the syllabus (strictly, call by value where the value is an address), is to pass &a and &b. The function receives copies of the addresses, and a copy of an address still points at the original variable. Syllabi list this as "Program to demonstrate call by value and call by reference"; the worked example below is that program.

  1. In the function header, declare the parameter as a pointer: int *x.
  2. Inside the function, use *x wherever you mean the caller's variable.
  3. At the call, pass the address: swap(&a, &b);.
  4. If the thing passed is already an array or a pointer, pass it as it is; do not add another &.

Worked example

Question (8 marks). Write a C program that demonstrates the difference between call by value and call by reference by swapping two integers a = 25 and b = 40. Show the output of both versions and explain it with a memory diagram.

#include <stdio.h>

void swap_value(int x, int y) {        /* call by value */
    int t = x; x = y; y = t;
}
void swap_ref(int *x, int *y) {        /* call by reference */
    int t = *x; *x = *y; *y = t;
}
int main(void) {
    int a = 25, b = 40;
    swap_value(a, b);
    printf("after swap_value: a=%d b=%d\n", a, b);
    swap_ref(&a, &b);
    printf("after swap_ref:   a=%d b=%d\n", a, b);
    return 0;
}

Second example: two results from one function. Split ₹1,375 into ₹500 notes and the remainder. A function returns one value, so pass addresses for both outputs:

void split(int amount, int note, int *count, int *rest) {
    *count = amount / note;      /* 1375 / 500 = 2  */
    *rest  = amount % note;      /* 1375 % 500 = 375 */
}
int c, r;
split(1375, 500, &c, &r);        /* c = 2, r = 375 */

After the call c is 2 and r is 375 although split returned nothing: it wrote into them through the addresses, exactly as scanf("%d", &n) does.

Exam traps

  • The two meanings of *. In a declaration, int *p creates a pointer. In a statement, *p is the value pointed to. int *p = &a; stores the address in p, not in *p.
  • Forgetting & in scanf. scanf("%d", n) passes the value of n as if it were an address and crashes. Strings are the exception: scanf("%s", name) has no & because an array name is already an address.
  • "Pointer size depends on what it points to." No: every pointer is the same size on a machine (8 bytes on 64-bit systems) because every address has the same width. The pointed-to type changes only how *p and p + 1 behave.
  • p + 1 is not "address plus one". It is address plus sizeof(*p). Examiners love "if p is 1000, what is p + 3?" for an int *: 1012, not 1003.
  • Returning the address of a local variable. The local dies when the function returns and the pointer dangles. Return a value, or write through a pointer the caller supplied.

Check yourself

RememberWhat do the operators & and * mean when used with a pointer? 2 marks

&v gives the address of variable v; *p gives the value stored at the address held in pointer p (dereference). One finds a location, the other visits it.

UnderstandWhy does void inc(int n) { n++; } fail to change the caller's variable, and how do you fix it? 4 marks

C passes arguments by value: n is a copy, so incrementing it changes only the copy, which is discarded on return. Fix: void inc(int *n) { (*n)++; } and call inc(&count);. The function now receives the address and writes through it.

UnderstandWhy does a function that receives an array also need its length as a separate argument? 3 marks

An array argument decays to a pointer to its first element. A pointer holds an address, not a count, so sizeof inside the function gives the pointer size (8), not the array size.

Applyint v[4] = {3, 6, 9, 12}; int *p = v; p = p + 2; printf("%d %d", *p, *(p - 1)); What prints, and what is the value in p if v starts at address 5000? 4 marks

p + 2 points to v[2], so *p is 9 and *(p - 1) is v[1] = 6. Output: 9 6. Address: 5000 + 2 × 4 = 5008.

AnalyzeA student writes int *f(void) { int x = 10; return &x; } and then printf("%d", *f());. It prints 10 on their laptop. Is the program correct? 4 marks

No. x is a local variable whose storage is released when f returns, so the returned pointer dangles. It printed 10 only because nothing had yet overwritten that stack slot; the behaviour is undefined and will change with another call in between, a different compiler, or optimisation. Return the value, or have the caller pass an address to fill.

Beyond the syllabus

Not for the exam. Pointers are why C still runs operating systems, database engines and the firmware in your phone's modem: they map directly onto machine addresses with no hidden cost. They are also the source of most security bugs in C (buffer overflows, use-after-free), which is why Rust's borrow checker and C++'s smart pointers exist and why Google and the US CISA now push memory-safe languages for new systems code. ACM/IEEE CS2023 keeps memory and pointers under Systems Fundamentals because a cache, a page table or a malloc bug makes no sense without them. Search next: "pointer to pointer", "function pointers and callbacks", "malloc and free", and "AddressSanitizer".

6.2 Structures: declaring and accessing members

An array holds many values of one type. A structure holds a fixed set of values of different types under one name: a student's roll number (int), name (char array) and CGPA (float) travel together as one record. C has structures so that related data can be declared once, copied in one assignment, passed to a function as one argument and stored in an array as one element. Every real C program, from the Linux kernel to a UPI payment library, is built from them.

You need: arrays and strings (Unit 5), pointers and &/* (Chapter 6.1).

Declaring a structure

A structure is declared with the keyword struct, a tag (the name of the new type) and a list of members inside braces. The declaration creates a type, not a variable; no memory is used until you declare a variable of that type.

struct Student {          /* "Student" is the tag        */
    int   roll;           /* members: each has a type     */
    char  name[12];
    float cgpa;
};                        /* the semicolon is compulsory  */

struct Student s1;                         /* one variable        */
struct Student s2 = {101, "Asha", 8.7f};   /* initialised in order */
struct Student s3 = {.roll = 102, .cgpa = 9.1f};   /* C99 designated */

Three common variations: declaring variables straight after the closing brace (struct Student { ... } s1, s2;), giving the type a short name with typedef struct { ... } Student; so you can write Student s1;, and nesting one structure inside another (struct Date dob; as a member of Student). Some syllabi call the members "structure elements"; textbooks also say "fields".

Accessing members: the dot and the arrow

Members are reached with the dot operator on a structure variable, and with the arrow operator on a pointer to a structure. The arrow is only a shorthand: p->cgpa means (*p).cgpa. The brackets are needed because . binds tighter than *.

s1.roll = 103;
strcpy(s1.name, "Ravi");        /* a char array needs strcpy, not = */
s1.cgpa = 7.9f;
struct Student *p = &s1;
printf("%d %s %.1f\n", p->roll, p->name, p->cgpa);   /* 103 Ravi 7.9 */

Unlike arrays, whole structures can be assigned: s2 = s1; copies every member. They cannot be compared with ==; compare member by member. A structure passed to a function is copied (call by value), which is slow for a large record and does not let the function change it, so functions usually take struct Student * and use the arrow.

Arrays of structures

A class register is simply an array whose element type is a structure. struct Student cls[60]; gives 60 records; cls[i].cgpa is the CGPA of the i-th one, and a for loop over i visits every record. This array-of-records pattern is what syllabi mean by "storing structure elements": a table where each row is one structure and each column is one member.

How a structure sits in memory

Members are stored in declaration order, each at an offset from the start of the variable. The compiler may insert unused padding bytes so that each member starts at an address that is a multiple of its own size (an int on a 4-byte boundary, a double on an 8-byte boundary) because the CPU reads aligned data faster. So sizeof(struct) is at least the sum of the member sizes, and often more. The rule for working it out by hand:

  1. Place members in order. Before each member, advance the offset to the next multiple of that member's alignment (its size, for the basic types; the largest member for a nested struct; 1 for a char array).
  2. Add the member's size to get the next free offset.
  3. At the end, round the total up to a multiple of the largest alignment in the structure, so that elements of an array of this struct are all aligned.

Worked example

Question (8 marks). Define a structure to hold a student's roll number, name and CGPA. Write a program that reads three students into an array of structures and prints the name of the student with the highest CGPA. Show a dry run for the records (101, Asha, 8.7), (102, Bala, 9.1), (103, Ravi, 7.9).

#include <stdio.h>
struct Student { int roll; char name[12]; float cgpa; };

int main(void) {
    struct Student cls[3];
    for (int i = 0; i < 3; i++)
        scanf("%d %s %f", &cls[i].roll, cls[i].name, &cls[i].cgpa);
    int top = 0;                         /* index of the best so far */
    for (int i = 1; i < 3; i++)
        if (cls[i].cgpa > cls[top].cgpa) top = i;
    printf("Topper: %s (roll %d, CGPA %.1f)\n",
           cls[top].name, cls[top].roll, cls[top].cgpa);
    return 0;
}

Note the scanf line: &cls[i].roll needs the address-of, but cls[i].name does not, because a char array is already an address (Chapter 6.1). Dry run of the search loop:

Expected output: Topper: Bala (roll 102, CGPA 9.1). Memory used by the array: 3 × sizeof(struct Student) = 3 × 20 = 60 bytes, with cls[1] starting at offset 20 and cls[2] at offset 40.

Second example: sizeof by hand. Find sizeof(struct T) for struct T { char c; int i; char d; }; on a compiler where int is 4 bytes.

  1. c (1 byte, align 1) goes at offset 0; next free offset 1.
  2. i (4 bytes, align 4): round 1 up to 4; occupies 4–7; next free 8.
  3. d (1 byte): offset 8; next free 9.
  4. Largest alignment is 4, so round 9 up to 12. Answer: 12 bytes, of which 6 are padding.

Reordering to { int i; char c; char d; } gives offsets 0, 4, 5 and a size of 8: the same data, four bytes smaller. This is a favourite viva question.

Exam traps

  • Missing semicolon after the closing brace. struct Student { ... } without ; turns the next line into a declaration of that type, with a confusing error far from the real mistake.
  • Assigning a string member with =. s.name = "Asha" does not compile; name is an array. Use strcpy(s.name, "Asha") (from <string.h>) or initialise at declaration.
  • Dot versus arrow. Use . on a structure variable and -> on a pointer. p.roll when p is a pointer is an error; (*p).roll and p->roll are the same thing.
  • "sizeof is the sum of the members." Only when no padding is needed. Examiners set {char; int; char} precisely because the answer is 12, not 6.
  • Comparing structures with ==. Not allowed in C; compare member by member (and use strcmp for string members).

The tag (Student in struct Student) names the type and takes no memory; a variable (s1) is an instance of that type and occupies sizeof(struct Student) bytes.

UnderstandWhy do functions usually receive a pointer to a structure rather than the structure itself? 3 marks

Passing the structure copies every member (call by value), which costs time for large records and means the function cannot change the caller's record. Passing &s copies only an 8-byte address, and the function can read or update the original through p->member.

ApplyFor struct P { double x; char tag; int n; }; give the offset of each member and sizeof(struct P) (double 8 bytes, int 4). 4 marks

x at 0 (next free 8); tag at 8 (next free 9); n needs a multiple of 4, so offset 12 (next free 16); largest alignment 8, and 16 is already a multiple of 8. sizeof = 16, with 3 padding bytes at 9–11.

AnalyzeA program stores 1 lakh records of struct { char flag; double amount; char type; }. A friend says reordering the members would save memory. Is she right, and by how much? 4 marks

Yes. As declared: flag at 0, amount at 8, type at 16, rounded to 24 bytes. Reordered as { double amount; char flag; char type; }: offsets 0, 8, 9, rounded to 16 bytes. Saving 8 bytes per record × 100,000 = 800,000 bytes, about 0.8 MB, with no change to the program's logic.

Beyond the syllabus

Not for the exam. The structure is the ancestor of the class: C++, Java and Python objects are structures with functions attached. In systems code the exact byte layout matters, because a structure is often the format of a network packet or a file header, which is why engineers reach for offsetof (in <stddef.h>), #pragma pack and fixed-width types like uint32_t. Linked lists, trees and graphs in your Data Structures course are all structures that contain pointers to other structures of the same type. Search next: "self-referential structure", "struct padding and alignment", "offsetof", and "bit fields in C".

6.3 Unions versus structures

A union is declared exactly like a structure, but all its members start at offset 0 and share the same bytes. A structure is big enough for all its members at once; a union is big enough for the largest one, and holds only one member's value at a time. C has unions for records that need "either this or that" (a payment is a UPI id or a card number, never both), for saving memory on small devices, and for looking at the same bytes as two different types.

You need: structures, offsets and padding (Chapter 6.2); binary and hexadecimal (Unit 2).

Declaring and using a union

union Value {
    int   i;        /* 4 bytes */
    float f;        /* 4 bytes */
    char  c;        /* 1 byte  */
};
union Value v;
v.i = 100;          /* the 4 bytes now hold the int 100   */
v.f = 2.5f;         /* the SAME 4 bytes now hold 2.5      */
v.c = 'X';          /* the first byte now holds 'X'       */
printf("%c\n", v.c);   /* X : the last member written     */

The syntax is the structure's syntax with union in place of struct: tag, members, semicolon, dot operator on a variable, arrow on a pointer. The difference is entirely in the memory map. Only the member written last holds a meaningful value; reading another member reinterprets the same bytes as a different type, which the C standard calls type punning. An initialiser with braces, union Value v = {7};, sets the first member; use {.f = 2.5f} to set another.

Size and alignment

The size of a union is the size of its largest member, rounded up to a multiple of the strictest alignment among its members, so that arrays of the union stay aligned. For union Value the largest member is 4 bytes and the strictest alignment is 4, so sizeof(union Value) = 4. The structure with the same three members needs 4 + 4 + 1 = 9, rounded up to 12. Both rules are the ones from Chapter 6.2; only the starting offsets differ.

Where unions are used

Variant records. A union by itself cannot tell you which member is live, so the usual pattern is a structure that pairs a tag with a union, often called a tagged union or discriminated union:

enum Kind { UPI, CARD };
struct Payment {
    enum Kind kind;            /* which member of u is valid */
    union {
        char upi[32];          /* "asha@okaxis"              */
        long long card;        /* 16-digit number            */
    } u;
};
struct Payment p = { UPI };
strcpy(p.u.upi, "asha@okaxis");
if (p.kind == UPI) printf("%s\n", p.u.upi);

The union costs 32 bytes (the larger member), not 40; with ten million payments the saving is 80 MB. Byte-level views are the second use: a union of an int and a char[4] lets you look at the individual bytes of the int, which is how programs test whether the machine is little-endian (see the worked example). Hardware registers, network packet decoders and the float-to-bits tricks in graphics code all rely on this.

Worked example

Question (8 marks). Write a program that stores the integer 0x41424344 in a union and then prints its four bytes as characters. Explain the output and what it tells you about the machine. Also find sizeof for union U { char name[13]; int id; double amount; };.

#include <stdio.h>
union Bytes { int whole; char part[4]; };

int main(void) {
    union Bytes b;
    b.whole = 0x41424344;        /* 'A'=0x41 'B'=0x42 'C'=0x43 'D'=0x44 */
    for (int k = 0; k < 4; k++)
        printf("part[%d] = %c\n", k, b.part[k]);
    printf("sizeof(union Bytes) = %zu\n", sizeof(union Bytes));
    return 0;
}

Dry run. The int 0x41424344 occupies bytes 0–3 of the union. A little-endian CPU (every Intel, AMD and ARM laptop or phone you are likely to use) stores the least significant byte first:

Byte offset0123
Contents (hex)44434241
Read as part[k]'D''C''B''A'

Expected output on a little-endian machine:

part[0] = D
part[1] = C
part[2] = B
part[3] = A
sizeof(union Bytes) = 4

On a big-endian machine the order would be A B C D. Since the program printed D first, the machine is little-endian; this four-line test is the standard endianness check, and it ties back to the byte-order discussion in Unit 2. The size is 4 because both members are 4 bytes and the int's alignment is 4.

Second part: sizeof(union U). Largest member: name[13] = 13 bytes (int is 4, double is 8). Strictest alignment: the double, 8. Round 13 up to the next multiple of 8: 16 bytes. The same three members as a structure would be 13 (name) → pad to 16 (id at 16–19) → pad to 24 (amount at 24–31) = 32 bytes; the union halves it.

Overwriting in sequence. With union Value v; from above: v.f = 2.5f stores the IEEE-754 bit pattern 0x40200000. Then v.c = 'X' (0x58) replaces byte 0, giving 0x40200058. Reading v.i now yields 1,075,839,064, a number nobody asked for: the proof that only the last-written member is meaningful.

Exam traps

  • "sizeof(union) = sum of members." No, that is the structure. Union = largest member, rounded to the strictest alignment (13 bytes of char next to a double gives 16, not 13).
  • Initialising all members. union Value v = {100, 2.5f, 'X'}; is an error (too many initialisers); braces fill only the first member. There is no way for all three to hold values at once.
  • Reading a member you did not write. It is not "wrong" syntax, so the compiler stays silent, but the value is the reinterpretation of another type's bytes. Examiners ask "what is printed?" and want "garbage / implementation-dependent", with the reason.
  • Forgetting the tag in a variant record. A union does not remember which member is live; without the kind field the program cannot know whether to read upi or card.
  • Writing struct when the question says union in the 2-mark "declare a union" question. The keyword is the whole point.

Check yourself

RememberDeclare a union Number that can hold an int, a float or a double, and state its size. 2 marks

union Number { int i; float f; double d; }; Size = largest member = 8 bytes (double); alignment 8, so no rounding needed.

RememberState two differences between a structure and a union. 2 marks

(1) Structure members have distinct offsets and all hold values at once; union members all start at offset 0 and only the last written is valid. (2) sizeof(struct) ≥ sum of members; sizeof(union) = largest member.

UnderstandWhy is a tag field normally stored alongside a union? 3 marks

The union itself records nothing about which member was last written. A tag (usually an enum) in an enclosing structure lets the program choose the right member to read; reading the wrong one silently reinterprets bytes.

Applyunion Q { short s; int n; char tag[6]; }; Find sizeof(union Q) and sizeof of the same members as a struct (short 2, int 4). 4 marks

Union: largest member 6 (tag), strictest alignment 4 (int), round 6 up to 8. Struct: s at 0, n at 4, tag at 8–13, total 14 rounded to a multiple of 4 = 16.

Applyunion Bytes b; b.whole = 258; printf("%d %d", b.part[0], b.part[1]); What prints on a little-endian machine? 3 marks

258 = 0x00000102. Little-endian stores 02 01 00 00, so part[0] = 2 and part[1] = 1. Output: 2 1.

AnalyzeA sensor logger on a microcontroller with 2 KB of RAM must store 100 readings, each either a 4-byte temperature float or a 20-character text alarm. Would you use a struct with both members or a union? Compare the memory. 4 marks

Struct with both: 4 + 20 = 24 bytes × 100 = 2,400 bytes, more than the whole RAM. A bare union is 20 bytes (2,000 bytes for 100 readings), but it cannot say which member is live; adding a 1-byte tag pads the record back to 24 bytes, because the union must start on a 4-byte boundary (tag at 0, union at 4–23), so 100 readings again need 2,400 bytes. The real fix is a tagged union plus shorter alarm text: with 8 characters the record is 1 + 3 padding + 8 = 12 bytes, and 100 readings take 1,200 bytes. The union is necessary but not sufficient; the analysis shows where the bytes go.

Beyond the syllabus

Not for the exam. The tagged union became a first-class language feature elsewhere: Rust's enum with data, Swift's associated values, TypeScript's discriminated unions, and std::variant in C++17 all enforce the tag the C programmer has to remember by hand. Type punning through a union is legal in C (since C99) but not in C++, which is why portable code uses memcpy instead. Unions still matter in device drivers, protocol parsers and interpreters, where a "value" cell must hold an int, a double or a pointer without wasting space. Search next: "tagged union", "std::variant", "type punning memcpy", and "anonymous union C11".

6.4 Macros and preprocessor directives: #include, #define, #ifdef

Before the compiler reads a single statement, a separate tool, the preprocessor, makes a pass over your source file and rewrites it. Every line that begins with # is an instruction to this tool, a directive, and none of them is C: #include pastes another file in, #define sets up a text replacement called a macro, and #ifdef keeps or drops lines depending on what has been defined. Preprocessing exists so that one program can share declarations across files, name its constants once, and be built in different versions (debug or release, Windows or Linux) from the same source.

You need: the structure of a program and header files (Unit 4), and compiling, linking and loading (Unit 1, System software).

Where the preprocessor sits

Building a C program is a pipeline (Figure 6.4.1). The preprocessor runs first and produces pure C with no # lines left; the compiler turns that into assembly, the assembler into an object file, and the linker joins object files and the standard library into the executable. With gcc you can stop after the first stage: gcc -E hello.c prints the preprocessed text, which for a 5-line hello program runs to several hundred lines, almost all pasted in from stdio.h. Syllabi list these directives together with "compiling and linking" for exactly this reason.

#include: paste a file here

#include <stdio.h> replaces the line with the whole contents of the file stdio.h. Angle brackets tell the preprocessor to look in the system include directories (/usr/include on Linux); double quotes, #include "mylib.h", look first in the directory of the current file. Header files contain declarations (prototypes, structure declarations, macros), never function bodies; the bodies live in the library the linker adds later. That is why forgetting #include <string.h> is reported as an implicit declaration of strcpy (a warning in older compilers, an error from GCC 14 on) rather than a link error: the body of strcpy is in the library either way.

#define: macros

An object-like macro is a name that stands for a piece of text: #define PI 3.14159 makes the preprocessor replace every later token PI with 3.14159. There is no type, no memory and no semicolon; it is pure text substitution, so #define PI 3.14159; would paste the semicolon too and break area = PI * r * r;. A function-like macro takes parameters:

#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))
area = PI * SQUARE(r);        /* becomes  area = 3.14159 * ((r) * (r)); */

The parentheses around every parameter and around the whole body are not decoration. Without them, operator precedence in the argument leaks into the expansion; the worked example shows the wrong answer that produces. Two more rules: a macro argument that has a side effect (SQUARE(i++)) is pasted twice and so runs twice, and a macro is expanded wherever its name appears as a token, but not inside string literals. #undef PI removes a definition. The preprocessor also predefines a few macros for you: __FILE__ (the file name as a string), __LINE__ (the current line number), __DATE__ and __TIME__.

Compared with a function, a macro saves the call overhead and works for any type (MAX above handles int, float and char), but it is not type-checked, cannot be debugged step by step, enlarges the code at every use, and has the side-effect trap.

#ifdef, #ifndef, #if: conditional compilation

Lines between #ifdef NAME and #endif are kept only if NAME has been defined (by a #define or by the compiler flag -DNAME); #ifndef keeps them only if it has not; #if expression tests a constant expression, and #elif and #else add branches. Three everyday uses:

  1. Debug printing. Wrap tracing in #ifdef DEBUG … #endif; build with gcc -DDEBUG prog.c while testing and without it for submission. The release build does not even contain the printf calls.
  2. Include guards. Every header starts with #ifndef MYLIB_H / #define MYLIB_H and ends with #endif, so a second inclusion is skipped and nothing is declared twice.
  3. Portability. #if defined(_WIN32) … #else … #endif picks the Windows or Linux version of a system call from one source file.

Worked example

Question (8 marks). Explain, with the expanded text, why #define SQUARE(x) x*x gives a wrong value for SQUARE(a+1) when a = 3, and show the corrected macro. Then write a program that uses PI as a macro to compute the area of a circle of radius 7 cm, and prints a debugging line only when DEBUG is defined.

Step 1: expand the bad macro. The preprocessor substitutes the text a+1 for x:

SQUARE(a+1)   →   a+1*a+1

Step 2: evaluate as C. Multiplication binds tighter than addition, so the compiler reads it as a + (1*a) + 1. With a = 3: 3 + 3 + 1 = 7, not the expected (3+1)² = 16.

Step 3: the fix. #define SQUARE(x) ((x) * (x)) expands to ((a+1) * (a+1)) = 4 × 4 = 16. The outer brackets matter too: with only the inner ones, 100 / SQUARE(a+1) would become 100 / (a+1) * (a+1) = 25 × 4 = 100 instead of 100 / 16 = 6.

Step 4: the program.

#include <stdio.h>
#define PI 3.14159
#define SQUARE(x) ((x) * (x))

int main(void) {
    float r = 7.0f;
    float area = PI * SQUARE(r);
#ifdef DEBUG
    printf("[%s line %d] r = %.1f\n", __FILE__, __LINE__, r);
#endif
    printf("Area = %.2f sq cm\n", area);
    return 0;
}

After preprocessing, line 7 is float area = 3.14159 * ((r) * (r)); and the three #ifdef lines are either gone or reduced to the single printf. Area = 3.14159 × 49 = 153.93791 → printed as 153.94. Expected output for the two builds:

$ gcc circle.c -o circle && ./circle
Area = 153.94 sq cm

$ gcc -DDEBUG circle.c -o circle && ./circle
[circle.c line 9] r = 7.0
Area = 153.94 sq cm

Second example: an include guard. student.h declares struct Student. If main.c includes both student.h and marks.h, and marks.h itself includes student.h, the structure would be declared twice and the compiler would refuse. The guard makes the second paste empty:

#ifndef STUDENT_H          /* first time: not yet defined, so keep */
#define STUDENT_H          /* now it is defined                    */
struct Student { int roll; char name[12]; float cgpa; };
#endif                     /* second time: defined, lines dropped   */

Exam traps

  • Semicolon or = in a #define. #define N = 10; replaces N with = 10;, so int a[N]; becomes int a[= 10;];. Directives are text, not statements.
  • Missing parentheses in function-like macros. The examiner's favourite: "what does SQUARE(a+1) give?" Expand the text on paper before answering.
  • Side effects in macro arguments. MAX(i++, j) pastes i++ twice, so i may be incremented twice; the result is unpredictable. Never pass ++, -- or a function call with effects to a macro.
  • Space before the parameter list. #define SQUARE (x) ((x)*(x)) is an object-like macro whose body is (x) ((x)*(x)). The ( must touch the name.

Check yourself

RememberWhat is the difference between #include <file.h> and #include "file.h"? 2 marks

Angle brackets search only the system include directories; quotes search the current file's directory first and then the system directories. Use quotes for your own headers.

RememberName the four stages that turn prog.c into an executable and say which one handles #define. 2 marks

Preprocessor, compiler, assembler, linker. The preprocessor handles every # directive, including #define.

UnderstandWhy does every header file begin with #ifndef / #define and end with #endif? 3 marks

It is an include guard. The first inclusion defines the guard name and keeps the contents; any later inclusion in the same translation unit finds the name defined, so the lines are dropped. This prevents duplicate declarations of structures and typedefs when headers include each other.

UnderstandGive two advantages and two disadvantages of a macro compared with a function. 4 marks

Advantages: no call overhead (text is inlined); works for any argument type. Disadvantages: no type checking and no debugging as a unit; arguments with side effects are evaluated more than once; every use enlarges the code.

Apply#define CUBE(x) x*x*x. What does CUBE(2+1) evaluate to, and what should the macro be? 3 marks

Expansion: 2+1*2+1*2+1 = 2 + 2 + 2 + 1 = 7 (expected 27). Correct form: #define CUBE(x) ((x)*(x)*(x)), which gives 3 × 3 × 3 = 27.

AnalyzeA team replaced #define MAX_USERS 100 with const int MAX_USERS = 100; and their build broke at int table[MAX_USERS]; declared at file scope. Explain, and say which they should prefer in general. 4 marks

In C (unlike C++) a const int is a variable, not a constant expression, so it cannot size an array at file scope; the macro worked because the preprocessor pasted the literal 100. Fix: keep the macro, or use enum { MAX_USERS = 100 };, which is a true constant. In general prefer const or enum for type safety and debugging, and reserve macros for cases like this, conditional compilation and generic one-liners.

Beyond the syllabus

Not for the exam. The preprocessor has more operators than the syllabus shows: # turns a macro argument into a string, ## glues two tokens into one, #pragma once replaces include guards on every current compiler, #error stops the build with a message, and C23 adds #elifdef and #embed. Large projects drive conditional compilation from build systems (CMake, Meson) that generate a config.h, and C++20 modules are the first real attempt to retire textual #include. Modern style keeps macros for conditional compilation and uses const, enum and inline functions elsewhere. Search next: "X macros", "stringizing and token pasting", "#pragma once vs include guards", "C23 #embed".

Takeaways

  1. A pointer is a variable that stores an address; & finds an address and * visits it.
  2. C passes everything by value. To let a function change the caller's variable, pass its address and write through the pointer; arrays are passed as addresses automatically.
  3. p + 1 moves by sizeof(*p) bytes, which is why a[i] and *(a + i) are the same thing.
  4. A structure groups members of different types under one name; use . on a variable and -> on a pointer, and strcpy for string members.
  5. sizeof a structure is the padded, aligned layout, not the sum of the members: {char; int; char} is 12 bytes; reorder to 8.
  6. A union overlays all its members on the same bytes; its size is the largest member rounded to alignment, and only the last-written member is meaningful.
  7. Pair a union with a tag when a record must hold "one of several" types.
  8. The preprocessor edits text before compilation: #include pastes, #define substitutes, #ifdef selects.
  9. Bracket every macro parameter and the whole body, and never pass i++ to a macro.
  10. Every header file wears an include guard so it can be included twice without harm.

Exam question bank

Syllabi that end with "Program to demonstrate call by value and call by reference" set the swap program as a full-marks long answer. Syllabi that name the directives one by one (#include, #define, #ifdef, #ifndef) next to "compiling and linking", set a question that walks the build pipeline and places each directive in it.

Remember and understand

1. Define a pointer. Explain the address-of and dereference operators with a diagram and a short program. (8 marks)

Points: pointer = variable holding an address; declaration int *p; &a gives address, *p gives value; memory diagram with addresses (boxes for a at 1000, p at 2000 holding 1000); program printing a, &a, p, *p; NULL and the danger of an uninitialised pointer.

2. Explain call by value and call by reference in C. Why is "call by reference" in C really call by value? (8 marks)

Points: every argument is copied; value copy cannot change caller; passing &a copies the address, and writing through the copy reaches the original; swap program both ways with outputs 25 40 / 40 25; note that C has no true reference type (C++ does), the "reference" is a pointer value.

3. What is a structure? Explain declaration, initialisation, accessing members with the dot and arrow operators, and arrays of structures. (12 marks)

Points: keyword struct, tag, members, semicolon; variable declaration and brace initialisation; typedef; s.m; pointer and p->m ≡ (*p).m; whole-structure assignment allowed, comparison not; array struct Student cls[60] and cls[i].cgpa; passing to a function by pointer.

4. Compare structures and unions under at least five heads, with declarations and memory diagrams. (10 marks)

Points: keyword; member offsets (increasing vs all zero); sizeof (sum with padding vs largest member); members valid simultaneously (all vs one); initialiser (in order vs first member); typical use (record vs variant); diagram like Figure 6.3.1 with sizes 12 and 4 for {int, float, char}.

5. What is the C preprocessor? Describe #include, #define, #undef, #ifdef, #ifndef, #else and #endif with one example each. (12 marks)

Points: runs before compilation, handles # lines, output has no directives; #include < > vs " "; object-like and function-like #define; #undef; conditional compilation with a DEBUG example and an include guard; gcc -E to see the result.

6. Explain the four stages of building a C program and state exactly what the preprocessor removes from and adds to the source. (8 marks)

Points: preprocessor (.i), compiler (.s), assembler (.o), linker (a.out) with gcc -E/-S/-c; preprocessor adds header contents and macro expansions, removes directives, comments and unselected conditional blocks; linker supplies library bodies such as printf.

Apply

7. Write a function that receives an array of n integers and returns, through pointer parameters, the sum and the average. Show the call for {12, 18, 30, 40}. (8 marks)

Points: void stats(int a[], int n, int *sum, float *avg); loop accumulates *sum; *avg = (float)*sum / n; call stats(v, 4, &s, &m); result sum = 100, avg = 25.0; explain why the array needs no & but s and m do.

8. For struct E { char code; double salary; int id; short grade; }; compute each member's offset and sizeof(struct E), then reorder the members to minimise the size. (8 marks)

Points: code 0; salary aligned to 8 → 8–15; id 16–19; grade 20–21; total 22 → round to 24. Reordered {double salary; int id; short grade; char code;}: 0, 8, 12, 14, total 15 → 16. Saving 8 bytes per record; state the alignment rule used.

9. Write a program using a structure array to store the names and runs of 5 cricketers and print the one with the most runs, with a dry run of the search loop. (10 marks)

Points: struct Player { char name[20]; int runs; } team[5];; input loop; best = 0, loop if (team[i].runs > team[best].runs) best = i; dry-run table of i, runs, best; output line; note scanf("%s", team[i].name) without &.

10. A union holds an int, a float and a char array of 20. Show its size, then show step by step what happens to the stored bytes when the three members are written one after another. (8 marks)

Points: size = 20 (largest member; alignment 4 and 20 is a multiple); writes overlap at offset 0; after i = 65, f = 1.0, strcpy(s, "hi") only s is valid; reading i gives the reinterpretation of "hi\0" plus leftover float bytes; conclusion: last-written member only.

11. Define a macro to find the larger of two numbers and a macro to compute the area of a circle. Show the expanded text for MAX(a+b, c) and AREA(r+1) with and without parentheses, and evaluate for a=2, b=3, c=4, r=1. (10 marks)

Points: MAX(x,y) ((x)>(y)?(x):(y)) → 5; AREA(r) (3.14159*(r)*(r)) → 3.14159 × 2 × 2 = 12.566; unparenthesised AREA(r) 3.14159*r*r gives 3.14159×1+1×1+1 = 5.14159; explain precedence; side-effect warning.

Analyze and evaluate

12. (Spans 6.1 and 6.2) A function void update(struct Student s) { s.cgpa += 0.5; } is called as update(cls[2]); and the record does not change. Diagnose, fix with a pointer, and discuss the cost of each version for a 1,000-byte structure. (10 marks)

Points: structure passed by value, copy modified; fix update(struct Student *p) { p->cgpa += 0.5f; } and update(&cls[2]); cost: value copy moves 1,000 bytes per call, pointer moves 8; memory diagram of the copy versus the pointer into the array.

13. (Spans 6.2 and 6.3) A railway reservation record must hold a PNR (10 chars), and either a berth number (int) for a confirmed ticket or a waiting-list position (int) and a queue name (8 chars) for a waitlisted one. Design the record with a tagged union, compute its size, and compare with a plain structure holding every field. (12 marks)

Points: enum Status { CONFIRMED, WAITLIST }; struct with pnr[11], status, union { int berth; struct { int pos; char queue[9]; } wl; }; union size = 16 (the waitlist struct is 4 + 9 = 13 bytes, rounded up to 16 for int alignment); total 11 → pad to 12, status 12–15, union 16–31, total 32; plain struct 11 → 12, 4, 4, 4, 9 → 33 → 36; discuss when the saving matters and the need for the tag.

14. (Spans 6.4 and 6.2) Two header files both declare struct Point, and main.c includes both; the compiler reports a redefinition. Explain what the preprocessor produced, fix it with include guards, and explain why a function in a .c file does not need the same protection. (8 marks)

Points: the preprocessor pasted the declaration twice into one translation unit; guards #ifndef POINT_H … #endif around a single shared header; the second paste becomes empty; function bodies live in one .c file compiled once, and the linker rejects duplicate definitions across files rather than the preprocessor.

15. Evaluate the statement "macros should be replaced by functions and const variables wherever possible" for a C programmer. (8 marks)

Points for: type checking, debugging, no double evaluation, smaller code. Points against: macros needed for conditional compilation, array sizes at file scope (const int is not a constant expression in C; enum alternative), generic one-liners for any type, stringizing. Conclusion with a rule of thumb.

16. A student claims that on their computer sizeof(int *) is 4 while sizeof(double *) is 8 "because doubles are bigger". Evaluate the claim and design a two-line test to settle it. (6 marks)

Points: wrong; all data pointers are address-sized (8 on 64-bit, 4 on 32-bit); pointed-to size affects *p and p + 1 only; test: printf("%zu %zu\n", sizeof(int *), sizeof(double *)); prints 8 8 (or 4 4); mention that a 32-bit build (-m32) gives 4 4.

Glossary

Address
The number of a memory location; what &v gives and a pointer stores.
Pointer
A variable whose value is an address; declared T *p.
Dereference
Following a pointer to the value it points to, written *p.
NULL
The pointer value 0, meaning "points nowhere"; must never be dereferenced.
Pointer arithmetic
Adding k to a pointer moves it by k elements, k × sizeof(*p) bytes.
Call by value
The callee receives a copy of each argument; the caller's variables are unchanged.
Call by reference
In C, passing an address so the callee can modify the caller's variable through a pointer.
Dangling pointer
A pointer to memory that no longer holds the variable, such as a returned local's address.
Segmentation fault
The crash produced by reading or writing an address the program does not own.
Structure
A user-defined type grouping members of possibly different types under one name.
Tag
The name after struct or union that identifies the type.
Member (element, field)
One named component of a structure or union.
Dot operator
s.m: member m of structure variable s.
Arrow operator
p->m: member m of the structure p points to; same as (*p).m.
typedef
Gives a type a new name, so Student s; can replace struct Student s;.
Offset
A member's distance in bytes from the start of its structure.
Alignment
The requirement that a value start at an address that is a multiple of its size.
Padding
Unused bytes the compiler inserts to satisfy alignment.
Array of structures
A table of records, struct T a[n], accessed as a[i].m.
Union
A type whose members all share the same memory, starting at offset 0.
Active member
The union member most recently written; the only one with a meaningful value.
Tagged union
A structure holding a tag (usually an enum) plus a union, so the live member is known.
Type punning
Reading a union member other than the one written, to view the same bytes as another type.
Endianness
Byte order of a multi-byte value; little-endian stores the least significant byte first.
Preprocessor
The first build stage; processes # directives and outputs pure C text.
Directive
A line beginning with # that instructs the preprocessor.
Macro
A name defined with #define that the preprocessor replaces with text; may take parameters.
Conditional compilation
Keeping or dropping source lines with #if, #ifdef, #ifndef, #else, #endif.
Include guard
#ifndef X / #define X / … / #endif around a header so it is processed once.
Linker
The build stage that joins object files and libraries into one executable.
