4.1 Algorithms and flowcharts

An algorithm is a finite list of unambiguous steps that turns an input into an output; a flowchart is the same list drawn as boxes and arrows so that the order of the steps, and where they branch and repeat, can be seen at a glance. Both exist because a computer does exactly what it is told and nothing more, so the plan has to be complete before the first line of code. Every program in this unit, and every program you will ever write, starts as one.

You need: nothing from earlier units. If you want to know why the steps must be so small, see Unit 1, Instruction set and the fetch-execute cycle: the processor executes one tiny instruction at a time.

What makes a list of steps an algorithm

A recipe says "add salt to taste"; an algorithm may not. Donald Knuth's five properties, which examiners ask for by name, are the test:

  • Input: zero or more values are supplied before or during the steps (a number n, a list of marks).
  • Output: at least one value is produced (the sum, a yes/no, a sorted list).
  • Definiteness: every step is precise and has one meaning. "Divide n by 10 and keep the quotient" is definite; "simplify n" is not.
  • Finiteness: the steps end after a finite number of operations for every valid input. A loop that waits for a number that never comes breaks this rule.
  • Effectiveness: each step is basic enough to be done exactly, by hand with pencil and paper, in finite time.

Algorithms are written in numbered English steps or in pseudocode, a half-English, half-code style that uses words such as read, set, if … then, while … do and print, but no particular language's punctuation. Pseudocode is for people; the compiler never sees it.

Flowchart symbols

A flowchart uses a small fixed set of shapes (the ISO 5807 set used in every textbook), joined by arrows called flow lines:

  • Terminal (rounded box): Start and Stop. Exactly one Start; one Stop.
  • Input/output (parallelogram): reading a value or printing a result.
  • Process (rectangle): a calculation or an assignment such as sum = sum + d.
  • Decision (diamond): a question with a yes/no answer; one arrow enters, two leave, each labelled Yes or No (or True/False).
  • Connector (small circle with a letter): joins a flow line that had to be broken, for example to continue on the next page.

Three drawing rules keep a flowchart readable: flow runs top to bottom and left to right; arrows never cross if a rearrangement can avoid it; and a loop is a flow line that goes back up to a point above a decision, so the question is asked again.

From problem to flowchart in four steps

  1. Name the input and the output. Sum of digits: input is a positive integer n; output is one integer, the sum.
  2. Write the steps in English, one action each. Set sum to 0. While n is greater than 0: take the last digit (n mod 10), add it to sum, drop the last digit (n div 10, the integer quotient). Print sum.
  3. Mark which steps repeat and which choose. The three "take, add, drop" steps repeat; the choice is "is n still greater than 0?". That gives one diamond with a loop.
  4. Draw it and dry-run it. Pick a small input, follow the arrows with a finger, and write every variable's value after each box in a table. If the table never reaches Stop, the algorithm is not finite; if two readers get different values, a step is not definite.

Exam traps

  • A diamond with one exit. Every decision must have two labelled arrows (Yes and No). A diamond with one arrow out is the most common lost mark.
  • No way out of the loop. If the body never changes the variable in the condition (forgetting n = n div 10), n stays 4729 forever and finiteness is broken. Examiners ask "which property does this violate?"; the answer is finiteness.
  • Wrong shape for input. "Read n" goes in a parallelogram, not a rectangle; "sum = 0" goes in a rectangle, not a parallelogram.
  • Forgetting to initialise. An algorithm that says "sum = sum + d" without first setting sum = 0 is not definite: the first sum has no value.
  • Favourite question: "Define algorithm, list its characteristics, and draw a flowchart for X" where X is sum of digits, largest of three numbers, factorial, or whether a number is prime. Practise all four until the shapes come automatically.

Analyze A student's algorithm for the factorial of n writes "Step 4: f = f × i; Step 5: go to Step 4". Which property fails, and what two changes fix it? 4 marks

Finiteness fails: nothing changes i and nothing tests it, so the jump back repeats forever. Fix 1: add "i = i + 1" after the multiplication. Fix 2: replace the unconditional jump by a decision "i ≤ n?" that exits to the print step when false. (Also initialise f = 1 and i = 1 before the loop.)

4.2 Structure of a simple program and header files

A C program is a text file with a fixed skeleton: a few lines that pull in declarations from header files, optional global definitions, and one function called main where execution starts and ends. Header files exist so that a program can use printf or sqrt without the programmer writing or even seeing their code; the compiler needs only the declaration, and the linker later supplies the compiled body from a library. Knowing which line does what is the first thing an examiner checks when asking you to "write a program to add two numbers".

You need: Unit 1, System software: compiling, linking, assembling and loading (what a compiler and a linker are). Unit 6 covers #define and #ifdef in detail; here you only need #include.

The sections of a C program

Textbooks (Balagurusamy's layout is the one most Indian exams expect) divide a program into six sections, top to bottom. Only the main function is compulsory.

  1. Documentation section: comments giving the program's name, author and purpose. /* … */ can span lines; // runs to the end of the line (C99 onwards).
  2. Link (preprocessor) section: #include lines that bring in header files. #include <stdio.h> is needed for printf and scanf.
  3. Definition section: symbolic constants such as #define PI 3.14159.
  4. Global declaration section: variables declared outside every function, visible everywhere (Unit 5, Scope and lifetime of variables).
  5. main() function: the entry point. Inside its braces come the declaration part (variables this function uses) and the executable part (statements, each ending in a semicolon). return 0; hands a success code back to the operating system.
  6. Subprogram section: the programmer's own functions, after main (Unit 5, Functions).

Two facts about the shape: C is free-form, so indentation and line breaks are for people and the compiler ignores them, but every statement must end with a semicolon and every { must have its }. And execution always begins at main, whatever is written before or after it.

What a header file is, and what it is not

A header file (extension .h) is a text file of declarations: function prototypes such as int printf(const char *format, ...);, constants such as INT_MAX, macros and type names. It does not contain the compiled code of printf. #include <stdio.h> is handled by the preprocessor, which pastes the whole header into your file before compilation. The compiler then knows the name, parameters and return type of every library function you call, and can check your calls. The code itself lives in the standard library (libc on Linux), and the linker joins it to your compiled program (Unit 1).

Angle brackets, #include <stdio.h>, tell the preprocessor to look in the system include folders; quotes, #include "mylib.h", look in your own folder first. The headers this unit uses:

With GCC on Linux: gcc add.c -o add preprocesses, compiles and links in one command; ./add runs it. If you use sqrt, the link step needs the maths library: gcc area.c -o area -lm; leaving out -lm gives "undefined reference to sqrt", a linker error, not a compiler error, because the header declared the function but no library supplied its body. For C++ use g++ add.cpp -o add.

Exam traps

  • Header file ≠ library. The header holds declarations; the library holds compiled code. "Undefined reference" is a linker error caused by a missing library (-lm), not a missing header; "implicit declaration" is a compiler warning caused by a missing header.
  • Missing & in scanf. scanf("%d", a) compiles with a warning and crashes at run time; scanf needs the address, &a. printf takes the value, a.
  • Wrong format specifier. %d for int, %f for float and double in printf, %lf for double in scanf, %c for char, %s for a string. Mixing them prints rubbish, not an error.
  • Semicolon after main() or after a #include. Preprocessor lines take no semicolon; a function header takes none either.
  • Favourite question: "Explain the basic structure of a C program with an example", worth 8 to 10 marks. List the six sections in order, write the add-two-numbers program, and label each section in the margin, exactly as in Figure 4.2.1.

4.3 Data types, variables and constants

A variable is a named box in memory; its data type fixes how big the box is, how the bits inside are read (whole number, fraction, character), and which operations are allowed on it. Constants are the values that never change: the literal 100 in your code, the character 'A', or a named value such as PI. Types exist because the same 32 bits mean one thing as an int and something completely different as a float (Unit 2), so the compiler must be told which reading to use. Syllabi list this chapter as "data type declaration".

You need: Unit 2, One's and two's complement (why an int has a negative half) and Fixed-point and floating-point numbers (why a float has limited precision). Unit 2, Codes: ASCII explains why 'A' is 65.

The primary data types

C has four primary (built-in) types plus void, and three modifiers that stretch or shrink them. Sizes are not fixed by the language; the standard only guarantees minimum widths and the order char ≤ short ≤ int ≤ long ≤ long long. Variables: declare, initialise, assign

A declaration names the variable and its type and reserves memory: int count;. Several of one type can share a line: int a, b, c;. An initialisation gives a first value in the same statement: int count = 0;. An assignment changes the value later: count = count + 1;. A local variable that is declared but not initialised holds garbage, and reading it is a bug the compiler will not always catch. In C89 all declarations had to come before the first statement of a block; C99 and C++ allow them anywhere, but putting them first is still the exam habit. Names must follow the identifier rules of 4.4.

Constants

A literal constant is a value written directly in the code. Its spelling tells the compiler its type:

  • Integer: 100 (decimal), 0144 (octal, leading 0), 0x64 (hexadecimal, leading 0x); all three are one hundred. Suffix U for unsigned, L for long: 100000L.
  • Real: 3.14 is a double; 3.14f a float; 2.5e3 is 2.5 × 10³ = 2500.0.
  • Character: 'A', one character in single quotes, value 65 in ASCII. Escape sequences spell the unprintable ones: '\n' newline, '\t' tab, '\0' null, '\\' backslash, '\'' single quote.
  • String: "Hello" in double quotes; stored as the characters followed by a hidden '\0', so it takes 6 bytes (Unit 5, Strings). "A" and 'A' are different things.

A symbolic constant gives a literal a name. #define PI 3.14159 is a preprocessor substitution: every PI is replaced by the digits before compilation; it has no type and no memory (Unit 6, Macros). const float pi = 3.14159f; is a real typed variable that the compiler refuses to let you change. Modern style prefers const (and constexpr in C++) because it is type-checked and visible in the debugger; exams accept either, but ask you to know the difference.

Worked example

Question. Predict the output of the program and explain each line. Assume a 64-bit GCC machine. (8 marks)

#include <stdio.h>
int main(void)
{
    char c = 'A';
    short s = 32767;
    int   p = 7 / 2;
    float q = 7 / 2;
    float r = 7 / 2.0;
    c = c + 2;
    s = s + 1;
    printf("%c %d\n", c, c);
    printf("%d\n", s);
    printf("%d %f %f\n", p, q, r);
    printf("%zu %zu %zu\n", sizeof(c), sizeof(int), sizeof(3.14));
    return 0;
}

Solution, line by line.

  1. c = 'A' stores 65. c + 2 is 67, which is 'C'. %c prints the character, %d prints the number: C 67.
  2. s = 32767 is the largest short. Adding 1 gives 32768, which does not fit in 16 bits; the bit pattern 1000 0000 0000 0000 read as a signed two's-complement short is −32768 (Unit 2). Output: −32768. This is overflow, and the program gives no warning.
  3. 7 / 2: both operands are int, so the division is integer division, 3. p = 3. q also receives 3 (the division happened before the float saw it), printed as 3.000000. 7 / 2.0: one operand is double, so 7 is promoted and the result is 3.5. Output: 3 3.000000 3.500000.
  4. sizeof(c) = 1, sizeof(int) = 4, and 3.14 is a double literal, so sizeof(3.14) = 8. Output: 1 4 8. (%zu is the specifier for the type sizeof returns.)

Exam traps

  • Integer division hides in float variables. float q = 7 / 2; is 3.0, not 3.5. The operands decide, not the destination.
  • 'A' versus "A". Single quotes make a one-byte char with value 65; double quotes make a two-byte string ('A' then '\0').
  • Overflow is silent. 32767 + 1 in a short wraps to −32768; 2,147,483,647 + 1 in an int is undefined behaviour in C and in practice wraps the same way. Use a wider type (long long) for sums that can grow.
  • Octal by accident. int pin = 0123; is octal 123 = 83 decimal, not one hundred and twenty-three.
  • Favourite questions: "List the primary data types with their size and range", "distinguish between const and #define", and "what is the output" of a snippet mixing char arithmetic and integer division. Learn the table above by heart.

Beyond the syllabus

Not for the exam. "int is 4 bytes" is a convention, not a law, and portable code uses the fixed-width types of <stdint.h> (int32_t, uint8_t, int64_t) so that a sensor driver behaves the same on an 8-bit microcontroller and a 64-bit server. 4.4 Naming conventions and coding style

The compiler accepts any legal identifier and any layout, so the rules in this chapter exist for the other reader of your code: the lab examiner, your project partner, or yourself three weeks later. The identifier rules are law (break them and the program will not compile); the conventions and style are agreements that make a program readable without running it. Syllabi list this as "naming conventions and styles", and it is worth marks in every lab viva and most theory papers as a short question.

Identifier rules: what the compiler enforces

An identifier is the name of a variable, constant, function, array or type. The rules in C and C++:

  1. Only letters (A–Z, a–z), digits (0–9) and the underscore _. No spaces, hyphens, dots or currency signs: total-marks is total minus marks; $price is illegal.
  2. The first character must be a letter or an underscore, never a digit: 2ndValue is illegal, value2 is fine. Names starting with an underscore are legal but reserved for the compiler and library in many positions, so avoid them.
  3. Names are case-sensitive: Total, total and TOTAL are three different variables.
  4. A keyword cannot be a name. C89 has 32 keywords (int, if, while, return, sizeof …); C99 added five (inline, restrict, _Bool, _Complex, _Imaginary) and C11 seven more, for 44; C23 adds bool, true, false, nullptr and others. C++ has around 90. Int with a capital I is legal because case matters, but it is a terrible name.
  5. Any length is allowed; the C99 standard guarantees at least 63 significant characters for internal names and 31 for external ones. Older compilers truncated at 8 or 32, which is why old books say "up to 31 characters".

Conventions: what good programmers agree on

  • Names say what they hold. unit_price, student_count, is_prime, not a, x1, temp2. Single letters are accepted only for loop counters (i, j, k) and well-known maths symbols (n, x, y).
  • Pick a case style and keep it. snake_case (words joined by underscores) is the C tradition and the Linux kernel style. camelCase (first word lower, later words capitalised) is common in C++ and Java. PascalCase is used for type names (StudentRecord). UPPER_SNAKE_CASE is reserved for constants and macros (MAX_SIZE, PI). Mixing styles in one file is the mark of copied code.
  • Functions are verbs, variables are nouns. compute_total(), print_bill(); total, bill. Boolean names read as questions: is_valid, has_passed.
  • No magic numbers. price * 18 / 100 hides what 18 is; price * GST_PERCENT / 100 says it, and changing the rate becomes a one-line edit.

Coding style: layout and comments

  • Indent every block by one level (4 spaces, or one tab, never both in one file). The eye should see the shape of if, else and loops without reading the braces.
  • One statement per line, a space on each side of binary operators (a + b, x = y), none after a function name (printf(). Lines under about 80 characters so they fit a phone and a printout.
  • Braces consistently. K&R style puts { at the end of the if/for line; Allman style puts it on its own line. Either is fine; use one. Always brace the body of an if or loop, even for one statement: it prevents the classic bug where a second line is added and silently falls outside.
  • Comments explain why, not what. i = i + 1; /* increment i */ says nothing; /* skip the header row */ helps. A comment block at the top of each file and each function (purpose, inputs, outputs) is what examiners look for.
  • Declare near first use, initialise at declaration, and keep functions short enough to read on one screen (Unit 5, Modular programming).

4.5 Operators and expressions

An operator is a symbol that tells the compiler to perform an operation on one, two or three values (its operands); an expression is any combination of operands and operators that produces a value, from a lone 5 to (a + b) * c / 2.0. The two things that make expressions exam material are precedence (which operator is applied first) and type conversion (what happens when an int meets a double). Get those two right and every "predict the output" question in this unit falls.

You need: 4.3 for the types and integer division; Unit 3, Boolean operations (the bitwise operators act on bits exactly as the logic gates do).

Precedence and associativity

When an expression has several operators, precedence decides which binds tighter; among operators of equal precedence, associativity decides the direction. The levels you need, highest first:

  1. Postfix: () function call, [], ., ->, a++, a−−. Left to right.
  2. Unary: ++a, −−a, unary + −, !, ~, (type) cast, *, &, sizeof. Right to left.
  3. Multiplicative: * / %. Left to right.
  4. Additive: + −. Left to right.
  5. Shift: << >>.
  6. Relational: < <= > >=; then equality: == !=.
  7. Bitwise &, then ^, then |.
  8. Logical &&, then ||.
  9. Conditional ?:. Right to left.
  10. Assignment = += … Right to left, so a = b = 5 sets b first.
  11. Comma ,: lowest of all.

Precedence says how the expression is grouped, not the order in which operands are fetched; i = i++ + ++i; is undefined behaviour because i is modified twice without a sequence point, and no exam answer is "correct" for it. Parentheses override everything; when in doubt, add them.

Type conversion in expressions

When the two operands of a binary operator have different types, C converts the "smaller" one up before computing (implicit conversion, also called promotion): char and short become int; if either side is double, the other becomes double; else if either is float, the other becomes float; else if either is long, the other becomes long. So 7 / 2.0 is a double division (3.5) while 7 / 2 is an int division (3). In an assignment the result is converted to the type of the variable on the left, which may lose data: int k = 3.99; stores 3 (truncation, not rounding). An explicit conversion or cast forces a type: (float) a / b casts a before the division, so the division is in float; (float)(a / b) casts after it, too late.

4.6 Decision control: if, if-else, nested if and switch

A decision statement lets a program take one of several paths depending on a condition, which is the diamond of a flowchart written in code. if and if-else choose between two paths on a true/false test; nesting them or chaining them as an else-if ladder chooses among many; switch chooses among many on the value of a single integer or character. Syllabi call this "the decision control structure" or "conditions and selection statements", and most set a lab program on it (bill slabs, grades, a menu).

You need: 4.5, relational and logical operators (a condition is just an expression whose value is tested for zero or non-zero).

if, if-else and the else-if ladder

if (condition) statement; runs the statement only when the condition is non-zero. Any expression is a condition: if (n % 2) is true for odd n because the remainder 1 is non-zero. if (condition) A else B runs exactly one of A and B. To run several statements, wrap them in braces to make a compound statement; without braces only the first statement belongs to the if (4.4).

A nested if is an if inside the branch of another: "if the candidate is 18 or older, then if they have ID, allow". The rule for a missing brace pair is the dangling else: an else pairs with the nearest unmatched if above it, whatever the indentation says. An else-if ladder is the nested form written flat:

if (marks >= 90)       grade = 'S';
else if (marks >= 80)  grade = 'A';
else if (marks >= 70)  grade = 'B';
else                   grade = 'F';

The conditions are tested top to bottom and the first true one wins; the rest are skipped, which is why the ladder must be ordered from the strictest test downwards. The final else catches everything left. The conditional operator c ? x : y is an if-else that produces a value: max = (a > b) ? a : b;.

switch

switch (expression) compares an integer or character expression against a list of constant case labels and jumps to the matching one; default catches no match. Execution then falls through into the following cases until it meets a break, which is the single most-tested fact about switch:

switch (day) {
    case 1: printf("Mon"); break;
    case 2: printf("Tue"); break;
    case 6:
    case 7: printf("Weekend"); break;   /* 6 falls into 7 on purpose */
    default: printf("Invalid");
}

Rules: the expression must be an integer type (int, char, enum; not float, not a string); case labels must be constants, distinct, and cannot be ranges (case 1...5 is a GCC extension, not standard C); break leaves the switch; without it the next case's statements run too. Use switch for a menu or a fixed set of codes; use an else-if ladder for ranges and compound conditions. C++ switch is identical. A nested switch is a switch inside a case of another, used for a sub-menu.

Worked example

Question. A supply board charges ₹3 per unit for the first 100 units, ₹5 per unit for the next 100, and ₹8 per unit above 200, plus a fixed charge of ₹50. Write a C program that reads the units and prints the bill. Dry-run it for 250 units and for 80 units. (8 marks)

#include <stdio.h>

Dry run, units = 250. 250 <= 100 false → 250 <= 200 false → else branch: bill = 800 + (250 − 200) × 8 = 800 + 50 × 8 = 800 + 400 = 1200. Then bill = 1200 + 50 = 1250. Output: Bill = Rs 1250.00. (Check: 100 × 3 + 100 × 5 + 50 × 8 = 300 + 500 + 400 = 1200, plus 50.)

Dry run, units = 80. 80 <= 100 true → bill = 80 × 3 = 240; the other tests are skipped. bill = 240 + 50 = 290. Output: Bill = Rs 290.00.

The constants 300 and 800 are the full cost of the earlier slabs (100 × 3 and 300 + 100 × 5); writing them out is what makes the ladder correct at the slab boundaries. units = 100 gives 300 + 50 by the first branch and would give 300 + 0 × 5 + 50 by the second, so the boundary is safe either way.

Exam traps

  • Missing break. Without break, every case after the match also runs. "What is the output of this switch with no breaks?" is a standard 2-mark question: the answer is all the cases from the match to the end.
  • Dangling else. if (a) if (b) x(); else y();: the else belongs to if (b), not if (a), no matter how it is indented. Add braces.
  • Ladder in the wrong order. Testing marks >= 70 before marks >= 90 gives every topper a B. Order the tests from the most restrictive down.
  • switch on the wrong type. switch (3.5) and switch ("yes") do not compile; case labels must be integer constants, not variables or ranges.
  • Semicolon after the condition. if (x > 0); is a complete empty if; the next line runs always.
  • Favourite questions: "Compare switch with else-if", "Write a program for grades / electricity bill / a calculator menu", and the output of a switch without breaks.

4.7 Loops: while, for, do-while; break and continue

A loop repeats a block of statements while a condition stays true, which is the back-arrow of a flowchart written in code. C has three: while tests first and may run zero times; do-while runs first and tests after, so it runs at least once; for is a while with the initialisation, test and update written on one line, which makes it the natural shape for counting. break leaves a loop early and continue skips to the next pass. Lab lists usually set one program per loop; some syllabi call this "looping and control structures".

You need: 4.1 (the loop in a flowchart and the dry-run table), 4.5 (++, %, compound assignment) and 4.6 (conditions).

The three loops

Every loop has four parts: an initialisation that sets the starting state, a test that decides whether to go round again, a body, and an update that moves the state towards making the test false. Leave out the update and the loop never ends.

/* while: entry-controlled */        /* do-while: exit-controlled */        /* for: counting */
int i = 1;                           int i = 1;                             int i;
while (i <= 5) {                     do {                                   for (i = 1; i <= 5; i++) {
    printf("%d ", i);                    printf("%d ", i);                      printf("%d ", i);
    i++;                                 i++;                               }
}                                    } while (i <= 5);

All three print 1 2 3 4 5. The difference shows when the test is false at the start: with i = 6, while and for print nothing, but do-while prints 6 once, because its body runs before the test. Note the semicolon after while (…) in do-while; it is the one place where while takes one. In for (init; test; update) any of the three parts may be empty: for (;;) is an infinite loop, the same as while (1). The update runs after the body on every pass, including the last.

Use for when you know the count in advance (counter-controlled: print a table, sum n marks); while when you stop on a condition found in the data (sentinel-controlled: read numbers until −1, strip digits until n is 0); do-while when the body must run at least once (a menu that must show before the user chooses). Loops nest: a loop inside the body of another, as in printing a multiplication table (outer loop over rows, inner over columns).

break and continue

break ends the innermost enclosing loop (or switch) immediately; control goes to the first statement after it. It is the standard way to stop a search as soon as the answer is found. continue abandons the rest of the current pass and goes to the next test; in a for loop the update still runs first, so i++ is not skipped. In nested loops both act on the inner loop only; to leave both you need a flag variable or goto, which exams expect you to avoid. The classic errors are the off-by-one (i < n versus i <= n changes the count by one) and the infinite loop (an update that never makes the test false, or a while whose body forgets the update).

Trace. i = 1: not a multiple of 3, not > 8, sum = 1, print 1. i = 2: sum = 3, print 2. i = 3: 3 % 3 == 0, continue; the update i++ still runs. i = 4: sum = 7, print 4. i = 5: sum = 12, print 5. i = 6: continue. i = 7: sum = 19, print 7. i = 8: sum = 27, print 8. i = 9: continue (tested before the break, so 9 does not break). i = 10: not a multiple of 3; 10 > 8, break: the loop ends with i still 10 and no update.

sum = 27, i = 10

Swap the two if lines and 9 reaches the break first: the output stops at 8 as before, but i ends as 9. The order of break and continue tests inside a body matters.

Exam traps

  • Semicolon after the loop header. while (i < 5); and for (i = 0; i < 5; i++); are complete loops with empty bodies; the first never ends, the second runs the following block once with i = 5.
  • do-while runs once regardless. "How many times does the body execute if the condition is false initially?" while/for: 0; do-while: 1.
  • continue in for still updates. Students write "i stays the same" and loop forever in their trace. In for, continue jumps to the update; in while, you must update before continue or the loop is infinite.
  • break leaves only the innermost loop. In a nested loop the outer loop carries on.
  • Off-by-one. for (i = 1; i < n; i++) runs n − 1 times; i <= n runs n times. Count the passes in the dry run, do not guess.
  • Favourite questions: "Compare while, do-while and for" (6 marks; use the table of entry/exit control, minimum runs and typical use), "reverse a number / sum of digits / factorial / Fibonacci / primes" with a dry run, and "explain break and continue with an example" (4 marks).

Check yourself

Remember Which loop is exit-controlled, and what does that guarantee? 1 mark

do-while; its body executes at least once because the test comes after the body.

Remember Name the three parts of a for-loop header in order. 1 mark

Initialisation; test (condition); update, separated by semicolons.

Understand Why is a do-while loop the right choice for a menu program? 2 marks

The menu must be displayed and a choice read at least once before the program can know whether the user wants to continue; the test ("choice != exit") only makes sense after the body has run, which is exactly the exit-controlled shape.

Understand Explain the difference between break and continue inside a loop. 2 marks

break terminates the loop immediately and continues after it. continue abandons only the current pass and jumps to the next test (via the update in a for loop); the loop goes on.

Apply How many times does the body run, and what is printed? int i = 10; while (i > 0) { printf("%d ", i); i -= 3; } 2 marks

i takes 10, 7, 4, 1 (then −2 fails the test). Four times; output 10 7 4 1.

Apply Write a for loop that prints the factorial of n = 6 and trace the running product. 4 marks

long f = 1; for (i = 1; i <= n; i++) f = f * i; printf("%ld", f);. Trace: i = 1 → 1; i = 2 → 2; i = 3 → 6; i = 4 → 24; i = 5 → 120; i = 6 → 720. Output 720. Use long or long long: 13! already exceeds int.

Analyze This loop is meant to read marks until −1 and count them, but it never ends: scanf("%d", &m); while (m != -1) { count++; }. Diagnose and fix, then say which kind of loop control it is. 4 marks

The body never reads a new value, so m stays at its first value and the test never becomes false: the update is missing. Fix: move the scanf into the body, while (m != -1) { count++; scanf("%d", &m); }, or use while (scanf("%d", &m) == 1 && m != -1) count++;. It is sentinel-controlled: the loop stops on a special data value, not a count.

Beyond the syllabus

Not for the exam. Loops are where a program spends its time, so they are where compilers work hardest: unrolling, vectorising with SIMD instructions, and hoisting unchanging calculations out of the body. The dry-run table you drew is the mental model behind the loop invariants used to prove programs correct. Modern languages hide the counter: C++ has range-based for (auto x : v), Python has for x in items, and functional styles replace loops with map and reduce. In embedded systems the infinite for (;;) is the whole program, the "super loop" that reads sensors and drives outputs forever. Search for "loop invariant", "range-based for" and "super loop architecture".

Takeaways

  1. Plan first: an algorithm is finite, definite and effective, and a flowchart shows its sequence, decisions and loops before any code exists.
  2. A C program is #include lines, optional globals, and main; a header supplies declarations and the linker supplies the library code.
  3. The type of a variable fixes its size, its range and how its bits are read; integer arithmetic overflows silently and integer division drops the fraction.
  4. 'A' is the number 65; "A" is two bytes. #define is text substitution; const is a typed read-only variable.
  5. Identifiers: letters, digits, underscore, not starting with a digit, case-sensitive, not keywords. Everything else about naming and layout is for the human reader, and examiners are human readers.
  6. Precedence groups an expression (* / % before + −, relational before logical, assignment last); associativity breaks ties; a cast must be applied to an operand, not to the result.
  7. Relational and logical expressions produce 1 or 0; && and || short-circuit; = in a condition is assignment, not comparison.
  8. An else-if ladder picks the first true test; a switch jumps on an integer and falls through without break.
  9. while and for may run zero times; do-while runs at least once; every loop needs an update that eventually makes its test false.
  10. The dry-run table, one row per pass with every variable, is the tool that answers every "what is the output" question.

Remember and understand

1. Define an algorithm. Explain its five characteristics with one example each, and draw the flowchart symbols with their meaning. (10 marks)

Definition (finite sequence of unambiguous steps, input to output). Input, output, definiteness, finiteness, effectiveness, each with a one-line example (a step that breaks it is the best example). Five symbols drawn and labelled: terminal, I/O, process, decision with two exits, connector; flow lines with arrows. (4.1)

2. Explain the basic structure of a C program with a suitable example, naming each section. (8 marks)

Six sections in order with one line each; a complete add-two-numbers program; margin labels tying lines to sections; the role of #include, main, declarations, statements, return 0; one sentence on header versus library. (4.2)

3. List the primary data types in C with their typical size, range and format specifier. Explain the use of the modifiers short, long, signed and unsigned. (8 marks)

Table of char, int, float, double, void with bytes, range and %c/%d/%f/%lf; "machine dependent, use sizeof"; modifiers change width or drop the sign; one example each (unsigned char 0–255, long long for large totals). (4.3)

4. State the rules for naming identifiers in C and explain, with examples, the conventions good programmers follow for names, indentation and comments. (8 marks)

Four rules with a valid/invalid example each; keyword count; case-sensitivity. Conventions: descriptive names, snake_case/camelCase consistency, UPPER_CASE constants, no magic numbers, indentation, braces always, one statement per line, comments that explain why. (4.4)

5. Explain the different categories of operators in C with an example of each, and explain the precedence and associativity rules with an expression. (12 marks)

Eight families (arithmetic, relational, logical, assignment, increment/decrement, bitwise, conditional, special) with one example each; precedence table top to bottom; associativity for equal levels; worked grouping of 10 + 2 * 3 % 4 − 8 / 3 with the expression tree. (4.5)

6. Compare the while, do-while and for loops with respect to syntax, entry/exit control, minimum number of executions and typical use. Give one example of each. (8 marks)

Three syntaxes; entry vs exit control with the flowchart difference; 0 vs 1 minimum runs; counter-controlled (for), sentinel-controlled (while), menu (do-while); the semicolon after do-while; equivalence of for and while. (4.7)

Apply

7. Write an algorithm and draw a flowchart to check whether a number is prime, then write the C program and dry-run it for 9 and 7. (12 marks)

Algorithm: read n; for d from 2 while d × d ≤ n: if n mod d = 0 then not prime, stop; print prime. Flowchart with one diamond for the divisibility test and one for the loop test. Program with a flag and break. Dry run: 9 → d = 2 (9 % 2 = 1), d = 3 (9 % 3 = 0) not prime; 7 → d = 2 (7 % 2 = 1), 3 × 3 = 9 > 7 exits, prime. (4.1, 4.7)

8. Write a C program that reads marks in five subjects, computes total and percentage, and prints the grade using an else-if ladder (≥ 90 S, ≥ 80 A, ≥ 70 B, ≥ 60 C, else F). Show the output for 78, 85, 92, 66, 88. (10 marks)

Declarations (int marks, total; float pct); five scanf or a for loop; total = 409; pct = total / 5.0 = 81.8 (must divide by 5.0, not 5); ladder in descending order; output "Total 409, Percentage 81.80, Grade A". (4.3, 4.5, 4.6, 4.7)

9. Predict the output, showing the evaluation of every expression: int a = 10, b = 3; float f; f = a / b; printf("%.2f ", f); f = (float) a / b; printf("%.2f ", f); printf("%d %d ", a++ * 2, ++b); printf("%d", a > b && b % 2 == 0); (8 marks)

a / b = 3 → 3.00; (float) a / b = 3.33; a++ * 2 uses 10 → 20, a becomes 11; ++b → 4; a > b (11 > 4 = 1) && (4 % 2 == 0 = 1) → 1. Output: 3.00 3.33 20 4 1. Note the order of arguments in one printf is unspecified in C, so a careful answer says the values assume left-to-right evaluation; examiners accept that remark. (4.3, 4.5)

10. Write a menu-driven calculator using switch (+, −, *, /) inside a do-while loop that repeats until the user enters 'q'. Explain why do-while is chosen and how division by zero is handled. (12 marks)

char op; float x, y; do { read op; if op is 'q' break; read x, y; switch (op) { case '+': … break; case '/': if (y == 0) print error else print x / y; break; default: invalid } } while (op != 'q'). do-while because the menu must appear at least once; break inside switch leaves the switch, the loop test or a break after it leaves the loop. Sample output for 7 and 2 with each operator. (4.6, 4.7)

11. Write a program using nested loops to print the multiplication tables of 2 to 4, each up to 5, and show the output. (8 marks)

Outer for (t = 2 to 4), inner for (i = 1 to 5), printf("%d x %d = %d\n", t, i, t * i), a blank line after each table. Output: 15 lines from "2 x 1 = 2" to "4 x 5 = 20". State that the inner loop runs 5 times per outer pass, 15 in total. (4.7)

Analyze and evaluate

12. A student's program computes the average of three ints with avg = (a + b + c) / 3; into a float and prints wrong results for 1, 2, 2. Explain the cause with the type conversion rules, give two fixes, and state which is preferred and why. (8 marks)

(1 + 2 + 2) / 3 is int / int = 1, assigned to float as 1.0 instead of 1.67. Fix A: divide by 3.0 (literal is double). Fix B: cast, (float)(a + b + c) / 3. Both promote the division; the cast version is preferred when the divisor is a variable (count), since there is no literal to change. Mention that (float)((a + b + c) / 3) does not work. (4.3, 4.5)

13. The following switch is meant to print the number of days in a month but prints several lines for some inputs. Find all faults and rewrite it correctly, then say when an else-if ladder would be a better choice. switch (m) { case 1: case 3: case 5: printf("31"); case 2: printf("28"); break; case 4: case 6: printf("30"); } (8 marks)

Faults: missing break after "31" (fall-through prints 31 then 28); months 7 to 12 missing; no default for invalid months. Rewrite with all months grouped, breaks after each group, default "invalid". Ladder preferable if the test were a range (days ≤ 31) or involved a leap-year condition (year % 4 == 0 && …), which switch cannot express. (4.6)

14. Compare break and continue. Then analyse this loop and give its output and the final value of i: for (i = 0; i < 10; i++) { if (i % 2) continue; if (i > 6) break; printf("%d ", i); } (8 marks)

break ends the loop; continue skips to the update and test. Trace: i = 0 print; 1 continue; 2 print; 3 continue; 4 print; 5 continue; 6 print; 7 continue (odd, tested before the break); 8 → 8 > 6 break. Output 0 2 4 6; final i = 8 (break skips the update). (4.7)

15. "Indentation, naming and comments do not affect the output, so they do not matter in an exam." Evaluate this claim with reference to the bugs that style prevents, and the dangling-else and unbraced-if problems. (6 marks)

Output is unchanged, but marks are not: lab vivas grade readability. Style prevents real bugs: braces stop the unbraced second statement and make the dangling else explicit; named constants stop inconsistent magic numbers; descriptive names catch type mix-ups (price in paise versus rupees). Conclude: style is cheap insurance, and an unreadable correct program is still penalised. (4.4, 4.6)

16. Design a program that reads integers until a sentinel (−1) and prints the largest, the count, and the average. Justify your loop choice, your data types and how you avoid division by zero when no numbers are entered. (10 marks)

while loop (sentinel-controlled, zero or more values); int for count and largest (initialise largest to the first value or INT_MIN from limits.h); long long for the sum to avoid overflow; average as (double) sum / count; guard with if (count > 0) before dividing. Dry run on 4, 9, 2, −1: largest 9, count 3, average 5.00. (4.3, 4.5, 4.7)

Glossary

Algorithm
A finite sequence of definite, effective steps that produces an output from an input.
Flowchart
A diagram of an algorithm using standard symbols joined by flow lines.
Pseudocode
An informal, language-independent way of writing algorithm steps.
Dry run
Executing a program by hand, recording every variable after each statement in a table.
Header file
A .h file of declarations (prototypes, constants, macros) pasted in by #include.
Preprocessor
The first stage of compilation; handles #include and #define by text substitution.
Linker
The tool that joins compiled code with library code to make an executable.
main()
The function where execution of a C or C++ program begins and ends.
Data type
The classification of a value that fixes its size, range, representation and allowed operations.
Variable
A named memory location whose value can change during the program.
Constant
A value that cannot change: a literal, a #define symbol, or a const variable.
Escape sequence
A backslash code for a special character: \n, \t, \0, \\.
sizeof
An operator giving the size of a type or variable in bytes.
Identifier
A programmer-chosen name for a variable, function, type or constant.
Keyword
A word reserved by the language (32 in C89) that cannot be used as an identifier.
Operator
A symbol that performs an operation on one, two or three operands.
Expression
A combination of operands and operators that evaluates to a value.
Precedence
The rule that decides which operator in an expression is applied first.
Associativity
The direction (left-to-right or right-to-left) in which operators of equal precedence group.
Implicit conversion
Automatic promotion of an operand to a wider type (int to double) in a mixed expression.
Cast
An explicit conversion written as (type) value.
Short-circuit evaluation
&& and || skip the right operand when the left one already decides the result.
Compound statement
Several statements grouped in braces so that they act as one.
Else-if ladder
A chain of if-else statements that picks the first condition that is true.
Dangling else
The rule that an else pairs with the nearest unmatched if.
Fall-through
In a switch, execution continuing into the next case when no break is present.
Entry-controlled loop
A loop that tests its condition before each pass (while, for).
Exit-controlled loop
A loop that tests its condition after each pass (do-while).
Sentinel
A special input value (such as −1) that tells a loop to stop.
Off-by-one error
A loop that runs one pass too many or too few because of < versus <=.
