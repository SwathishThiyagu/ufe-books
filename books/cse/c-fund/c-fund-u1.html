1.1 Brief history of computing

Computing history is the story of three ideas arriving one after another: a machine that calculates by itself, a machine that follows a program you can change, and a switching device (gear, relay, vacuum tube, transistor, chip) that makes the machine smaller, faster and cheaper every decade. Exams ask for machines, dates and generations; the dates become easy to remember once you see which of the three ideas each machine added.

Before electronics: calculating machines and the idea of a program

The abacus is thousands of years old, but the first machine that added by itself was Blaise Pascal's Pascaline (1642), a box of gears in which a carry turned the next wheel. Gottfried Leibniz's stepped reckoner (1673) could also multiply. These are calculators: a person feeds in every number and chooses every operation.

The idea of a program came from weaving. Joseph Jacquard's loom (1804) read a chain of punched cards and raised the threads the holes selected, so one loom could weave any pattern. Charles Babbage carried the idea into arithmetic: his Analytical Engine (designed from 1837) had a mill that did the arithmetic, a store that held numbers, and punched cards that supplied the instructions. That is the shape of a modern computer: ALU, memory and program. It was never completed in his lifetime, but Ada Lovelace's notes on it (1843) describe how a sequence of cards could compute Bernoulli numbers, which is why she is called the first programmer.

Punched cards did their first large job for Herman Hollerith, whose electric tabulating machines counted the 1890 US census in a fraction of the usual time. His company later became part of IBM, and the punched card remained the usual way to feed data and programs into computers until the 1970s.

Three first-generation machines matter most. ENIAC (1946, University of Pennsylvania) was the first general-purpose electronic computer: about 18,000 vacuum tubes doing 5,000 additions a second, but it was programmed by plugging cables and setting switches, which took days. In 1945 John von Neumann wrote the First Draft of a Report on the EDVAC, describing a machine whose program is stored in the same memory as its data, so that changing the program means writing new numbers into memory. The Manchester Baby ran the first such stored program on 21 June 1948, and EDSAC at Cambridge (1949) was the first practical stored-program computer. UNIVAC I (1951) was the first commercial computer. Chapter 1.4 explains why the stored program is the idea every later machine kept.

The transistor (Bell Labs, 1947) replaced the hot, failure-prone tube; the integrated circuit (Jack Kilby in 1958, Robert Noyce in 1959) put many transistors on one piece of silicon; and the microprocessor put a whole CPU on one chip: the Intel 4004 of 1971 had about 2,300 transistors. Gordon Moore observed in 1965 that the number of transistors on a chip was doubling regularly; the usual modern form of Moore's law is a doubling every two years. That doubling, repeated for fifty years, is the fourth generation: the same architecture with a billion times more transistors.

Computing in India

India's first computer, a British HEC-2M, was installed at the Indian Statistical Institute, Kolkata, in 1955. The first computer designed and built in India was TIFRAC at the Tata Institute of Fundamental Research, Mumbai: a pilot machine worked in 1956 and the full machine was commissioned and named by Jawaharlal Nehru in 1960. C-DAC's PARAM 8000 (1991) was India's first supercomputer, built after export restrictions blocked buying one. Today some of the world's largest computing systems in daily use are Indian: Aadhaar, IRCTC and UPI, which handles billions of payments a month.

Worked example

Question. The Intel 4004 (1971) had about 2,300 transistors. (a) If the transistor count on a chip doubles every two years, in which year does a chip reach one billion (10⁹) transistors? (b) ENIAC performed 5,000 additions per second. A modern core at 3 GHz can complete one addition every clock cycle. How many times faster is it?

Solution (a). After n doublings the count is 2300 × 2ⁿ. We need 2300 × 2ⁿ ≥ 10⁹, so 2ⁿ ≥ 10⁹ / 2300 = 434,783.

Take logarithms: n ≥ log₂(434,783) = log₁₀(434,783) / log₁₀(2) = 5.638 / 0.301 = 18.7. So n = 19 doublings; 18 is not enough, because 2300 × 2¹⁸ = 2300 × 262,144 = 6.03 × 10⁸, below 10⁹, while 2300 × 2¹⁹ = 1.21 × 10⁹.

Time = 19 doublings × 2 years = 38 years, so the year is 1971 + 38 = 2009. In reality the first processors with more than a billion transistors shipped around 2008–2010, so the two-year rule held for almost forty years.

Solution (b). The modern core does 3 GHz = 3 × 10⁹ cycles per second = 3 × 10⁹ additions per second. Ratio = 3 × 10⁹ / 5,000 = 6 × 10⁵: about six hundred thousand times faster, from one core of a chip smaller than a fingernail against a room full of 18,000 tubes.

Exam traps

  • "Which was the first computer?" has three correct answers depending on the definition, so state the definition: first programmable machine, Zuse Z3 (1941); first general-purpose electronic computer, ENIAC (1946); first stored-program computer, the Manchester Baby (1948), with EDSAC (1949) the first in regular use.
  • Generations are defined by the switching device (tube, transistor, integrated circuit, microprocessor), not by decades. Remember the device and you can rebuild the order even if a year slips.
  • Babbage designed the Analytical Engine but never completed it; Ada Lovelace wrote the first program for it. "Babbage built the first computer" loses the mark.
  • Von Neumann described the stored-program idea in 1945; he did not build the first computer, and the EDVAC design was joint work with Eckert, Mauchly and their team.
  • Integrated circuit (third generation, 1958–59) and microprocessor (fourth, 1971) are different things: a microprocessor is an integrated circuit that contains a complete CPU.

Analyze Why did the integrated circuit make computer families such as the IBM System/360 and time-sharing operating systems practical, when earlier generations did not? 4 marks

Integrated circuits cut the cost and size per logic gate sharply, so (1) a maker could build several models of different speed with the same instruction set, and one program ran on all of them; (2) memory became large and cheap enough to hold an operating system and several user programs at once; (3) reliability rose, so one machine could run continuously and serve many terminals.

Dennard scaling (the rule that smaller transistors use proportionally less power) ended around 2005, which is why clock speeds stopped near 3–5 GHz and chips went multicore instead, and the response has been specialised hardware: GPUs for graphics and machine learning, Google's TPUs, the neural engines in phone chips, and chiplets that stitch several dies into one package. 1.2 Components of a modern computer system

A computer system is hardware plus software working on data. The hardware takes data in, stores it, processes it and sends results out; the software tells the hardware what to do. Every machine from a smartwatch to a bank's mainframe has the same four hardware functions and the same two layers of software, so once you can name them in one machine you can name them in all.

The four functions and the block diagram

The classic block diagram has an input unit (keyboard, touchscreen, sensors) that turns actions in the world into bits; a memory unit that holds the program and its data while they are in use; a central processing unit (CPU) made of a control unit and an arithmetic-logic unit; and an output unit (display, speaker, printer) that turns bits back into something a person or a machine can use. Secondary storage (SSD, hard disk) keeps programs and files when the power is off. The parts are joined by the system bus, a set of parallel wires carrying addresses, data and control signals (Chapter 1.4 looks at the bus, 1.5 at memory and devices).

Input → process → output, with storage in the middle, is what every program does: a UPI payment takes an amount and a PIN (input), checks and updates balances (processing and storage) and shows a confirmation (output). The characteristics textbooks list follow from the hardware: speed (billions of operations a second), accuracy (it does exactly what the program says, so a wrong program gives wrong answers: garbage in, garbage out), diligence (no fatigue), large storage and versatility (the same hardware runs a game and a spreadsheet). It has no intelligence of its own; every decision it takes was written into a program.

Inside a laptop or a phone: hardware you can name

Open a laptop and the block diagram becomes parts you can point at. The processor is a chip with several cores, each running the fetch-execute cycle of Chapter 1.6 at 3–5 GHz, with a few megabytes of cache on the same chip. Main memory is DRAM, 8–32 GB, holding the running programs; it loses its contents when power goes. Storage is an SSD or a hard disk, 256 GB to 2 TB, which keeps the operating system, apps and files. The motherboard carries the buses and the chipset that connects the CPU to memory, storage and the ports (USB, HDMI, Wi-Fi). A GPU draws the screen and, increasingly, runs machine-learning work. The battery, the fans and the input-output devices (keyboard, trackpad, camera, microphone, display, speakers) complete it.

A phone has the same parts but packs CPU cores, GPU, modem, image processor and a neural engine onto one system on a chip (SoC), with 6–12 GB of RAM and 128–512 GB of flash storage beside it. A washing machine's controller is the same block diagram at a much smaller scale: a microcontroller with a few kilobytes of RAM, sensors as input and the motor as output.

Software: system and application

Hardware without software does nothing. Software is the set of programs, in two layers. System software runs the machine for the benefit of other programs: the operating system (Windows, Linux, Android, iOS) manages the processor, memory, files and devices; device drivers talk to particular hardware; language translators, linkers and loaders turn source code into running programs (Chapter 1.7); utilities such as file managers and antivirus tools do housekeeping. Application software does the user's work: a browser, a UPI app, a word processor, a game. Firmware is software stored in non-volatile memory on the hardware itself, such as the BIOS/UEFI that starts the boot sequence.

Two pairs of words from this picture appear in exams. Data is raw facts (a list of marks); information is data processed into something useful (the class average). A program is a sequence of instructions; a process is a program while it is running.

Classifying computers

By size and power: supercomputers (PARAM Siddhi-AI, AIRAWAT) for weather and simulation; mainframes for banks and railways, running millions of transactions reliably; servers in data centres; desktops, laptops and tablets; smartphones; and embedded computers inside cars, ATMs and appliances, the most numerous of all. By the signal they process: digital computers work on discrete binary values (almost everything today); analog computers represent quantities by continuous voltages or rotations (a slide rule, old flight simulators); hybrid machines combine both, such as an ECG monitor with analog sensing and digital processing. By purpose: general-purpose (programmable for any task) against special-purpose (a calculator, a traffic-light controller).

Exam traps

  • In everyday speech "the CPU" is the whole cabinet; in an exam it is the processor only: control unit, ALU and registers. Memory and disks are not part of the CPU.
  • Memory (RAM) is not storage (SSD or HDD). "16 GB / 512 GB" in an advertisement is RAM, then storage; a phone saying "storage full" means its flash, not its RAM.
  • Network speeds are in bits per second (Mb/s), file sizes in bytes (MB): divide by 8. And 1 GB is 10⁹ bytes to a disk maker but 2³⁰ bytes (1 GiB) to Windows.
  • Some devices are both input and output: a touchscreen, a network card, a disk. Say "both" rather than guessing one.
  • Firmware is software even though it lives in a ROM chip; a device driver is system software, not hardware.

1.3 CPU organization: ALU, control unit and registers

The CPU is the part of the computer that actually computes, and inside it there are only three kinds of things: registers that hold the handful of values being worked on right now, an arithmetic-logic unit (ALU) that combines two of those values into a result, and a control unit that decides, clock tick by clock tick, which register feeds the ALU, what the ALU does and where the result goes. Every instruction of every program is carried out by this trio.

Registers: the CPU's own fast storage

A register is a small store for one word (8, 16, 32 or 64 bits) built from flip-flops inside the processor. It is read or written in a fraction of a nanosecond, about a hundred times faster than main memory, which is why the CPU keeps its working values in registers and goes to memory only to load and store. The ALU: arithmetic and logic in one block

The ALU is a block of logic gates with two data inputs A and B, an operation-select input from the control unit, a result output and flag outputs. A basic ALU does integer add, subtract (as addition of the two's complement, Unit 2), increment, compare, AND, OR, XOR, NOT and shifts; multiply, divide and floating-point work are done by extra units beside it. The ALU is combinational: its output is a function of its present inputs only and it remembers nothing, so every result must be written into a register or memory before the inputs change.

With each result the ALU sets the flags: Z = 1 if the result is zero; N = 1 if the result's leading bit is 1, meaning negative in two's complement; C = 1 if a carry came out of the top bit, meaning an unsigned result did not fit; V = 1 if the signed result did not fit, which happens when the carry into the top bit differs from the carry out of it. A compare instruction is a subtraction that keeps only the flags, and a conditional jump (JZ, JNZ, JC, …) reads them: that is how an if or a loop reaches the hardware.

The control unit: the conductor

The control unit (CU) turns the opcode in the IR into a timed sequence of control signals: load this register, put that register on the bus, select ADD at the ALU, read memory, write memory. It steps through the fetch-decode-execute cycle of Chapter 1.6 once per instruction, in time with the clock, a square wave whose frequency f is the number on the box: 3 GHz means 3 × 10⁹ ticks per second and a period T = 1/f = 0.33 ns. An instruction may need several ticks; the average is the CPI (cycles per instruction), so instructions per second = f / CPI.

A hardwired CU is a fixed logic circuit that produces the signals directly; it is fast and is used in RISC processors. A microprogrammed CU stores, for each opcode, a tiny program of micro-instructions in a control memory and reads it out step by step; it is slower but easy to extend, which suited the large instruction sets of CISC machines.

How the pieces connect

Inside the chip an internal bus joins the registers to the ALU inputs and carries the result back. MAR and MDR are the doorway to the outside: MAR drives the address bus, MDR sends and receives on the data bus, and the CU drives the read and write lines of the control bus. A modern CPU adds cache (Chapter 1.5), a pipeline, and several copies of the whole thing as cores; each core still has exactly this figure inside it.

Worked example

Question 1. An 8-bit ALU adds A = 9C₁₆ and B = 7A₁₆. Find the 8-bit result and the flags Z, N, C and V, and interpret the operation (i) as unsigned and (ii) as two's-complement signed arithmetic.

Solution. In binary, 9C₁₆ = 1001 1100₂: 156 unsigned, or −100 signed because the leading bit is 1 (156 − 256 = −100). 7A₁₆ = 0111 1010₂ = 122 either way.

carries:   1 1 1 1 1 0 0 0
A (9C):      1 0 0 1 1 1 0 0
B (7A):      0 1 1 1 1 0 1 0
           -----------------
sum:       1 0 0 0 1 0 1 1 0   carry out = 1, result = 0001 0110 = 16₁₆

Flags: the result 0001 0110 is not zero, so Z = 0; its leading bit is 0, so N = 0; a 1 fell off the top, so C = 1; the carry into the top bit (1) equals the carry out (1), so V = 0.

(i) Unsigned: 156 + 122 = 278, which does not fit in 8 bits (maximum 255). The ALU gives 278 − 256 = 22 = 16₁₆, and C = 1 warns that the true sum is 256 more. (ii) Signed: −100 + 122 = +22 = 16₁₆, correct, and V = 0 confirms it. Same bits, two meanings; the program decides which flag matters.

Question 2. A CPU runs at 2.5 GHz with an average of 4 clock cycles per instruction. Find the clock period, the instructions executed per second, and the time taken by a program of 50 million instructions.

Solution. Period T = 1/f = 1/(2.5 × 10⁹ Hz) = 0.4 ns. Instructions per second = f / CPI = 2.5 × 10⁹ / 4 = 6.25 × 10⁸. Time = 50 × 10⁶ / 6.25 × 10⁸ = 0.08 s = 80 ms.

Exam traps

  • MAR holds an address; MDR holds data. The PC holds the address of the next instruction; the IR holds the current instruction itself. Mixing these four costs the easiest marks on the paper.
  • The control unit decides, the ALU computes, the registers hold. The ALU never fetches an instruction and the control unit never adds two numbers.
  • C and V are different flags: C is unsigned overflow (a carry out), V is signed overflow. 7F₁₆ + 01₁₆ = 80₁₆ gives C = 0 but V = 1; the example above gives C = 1 but V = 0.
  • Clock speed is cycles per second, not instructions per second: divide by CPI. A 3 GHz chip with CPI 2 is slower than a 2.5 GHz chip with CPI 1.
  • Hardwired is faster and typical of RISC; microprogrammed is flexible and typical of CISC.

1.4 Von Neumann architecture

Von Neumann architecture is the design in which a program is stored in the same memory as the data it works on, as the same kind of numbers, and a single processor fetches those instructions one at a time over a single bus and executes them in order. Every laptop, phone and server follows it, which is why "stored-program computer" and "von Neumann machine" mean the same thing in an exam.

The stored program: instructions are data

ENIAC (1946) computed electronically but was programmed by cables and switches; a new problem meant days of rewiring. The 1945 First Draft of a Report on the EDVAC, written by John von Neumann from the work of the EDVAC team of Eckert and Mauchly, proposed putting the program into memory as numbers, next to the data. The Manchester Baby ran the first stored program on 21 June 1948 and EDSAC followed in 1949 (Chapter 1.1).

Four things follow. To change the program you write new values into memory, in microseconds, not days. A program can be read in from a disk or a network like any other data, so one machine runs thousands of programs. A program can produce another program as its output, which is what a compiler does (Chapter 1.7). And an instruction and a number look identical in memory: the word 100A₁₆ is "LOAD from address 10" if the CPU fetches it as an instruction and the number 4106 if it loads it as data. The CPU does not label words; whatever it fetches during the fetch phase it treats as an instruction.

The parts and the buses

The report describes five parts: a memory holding both instructions and data in one address space; an arithmetic unit (the ALU); a control unit that fetches, decodes and executes in sequence; and input and output. The processor reaches memory through the system bus, which has three groups of lines:

  • The address bus carries the address from MAR to memory, one way. Its width sets how much memory can be addressed: n lines reach 2ⁿ locations, so 32 lines reach 4 GiB (Chapter 1.5).
  • The data bus carries words between MDR and memory both ways; its width is the bits moved per transfer, usually the word size.
  • The control bus carries read, write, clock and interrupt signals.

Execution is sequential: the control unit fetches the instruction at the address in the PC, increments the PC, executes, and repeats (Chapter 1.6). Only a jump breaks the order, by loading a new address into the PC.

The von Neumann bottleneck

Because instructions and data share one memory and one bus, the processor can do only one memory transfer at a time, and it needs one for every instruction fetch plus one for every load or store. John Backus described this von Neumann bottleneck in his 1977 Turing Award lecture, and it has grown worse since: a core can execute a few instructions per nanosecond while a DRAM access takes about 100 ns. Left alone, the CPU would spend most of its time waiting.

The fixes sit around the processor rather than inside the architecture: caches, small fast SRAM memories that keep copies of recently used words so that most accesses never reach the bus; separate instruction and data caches so a fetch and a load can happen in the same cycle; wider buses and several memory channels; prefetching. The worked example shows the arithmetic.

Harvard architecture and the modern mix

The Harvard architecture, named after the relay-based Harvard Mark I of 1944, keeps instructions and data in separate memories with separate buses, so both can be accessed in the same cycle and a program cannot overwrite itself by accident. It is common in microcontrollers (the AVR in an Arduino, PIC chips) and signal processors, where the program lives in flash and the data in RAM. Its cost is rigidity: the two memories cannot share free space, and loading a new program as data needs a special path. Modern laptop and phone processors are a modified Harvard design: separate level-1 instruction and data caches at each core, fed from one main memory that holds both.

Worked example

Question 1. A processor executes 2 × 10⁹ instructions per second. Every instruction is 4 bytes long, and on average one instruction in three also reads or writes an 8-byte data word. The memory bus moves 64 bits per transfer at 400 million transfers per second. (a) What memory bandwidth does the processor demand? (b) What does the bus supply? (c) What fraction of the demand is met, and what happens to the processor? (d) A cache now serves 95% of all accesses without using the bus. What is the bus demand?

Solution (a). Instruction fetches: 2 × 10⁹ per second × 4 bytes = 8 × 10⁹ B/s = 8 GB/s. Data accesses: (2 × 10⁹ / 3) per second × 8 bytes = 5.33 × 10⁹ B/s = 5.33 GB/s. Demand = 8 + 5.33 = 13.33 GB/s.

Solution (b). 64 bits = 8 bytes per transfer; 8 B × 400 × 10⁶ per second = 3.2 GB/s.

Solution (c). Fraction served = 3.2 / 13.33 = 0.24, about 24%. The processor runs at 24% of its speed, 0.24 × 2 × 10⁹ = 4.8 × 10⁸ instructions per second, and stalls the other 76% of the time. That is the bottleneck in numbers.

Solution (d). Only 5% of accesses reach the bus: 0.05 × 13.33 = 0.67 GB/s, well under the 3.2 GB/s supply. The processor runs at full speed; this is why every CPU since the 1980s carries cache.

Question 2. In Figure 1.4.1 the opcodes are 1 = LOAD, 2 = ADD, 3 = STORE, 0 = HALT and each instruction's operand is a memory address. What does the program compute, and what happens if the word at address 1 is overwritten with ADD 4 before the program runs?

Solution. LOAD 4 puts M[4] = 25 in the accumulator; ADD 5 adds M[5] = 17, giving 42; STORE 6 writes 42 into word 6; HALT stops. If word 1 becomes ADD 4, the second step adds M[4] = 25 instead, and word 6 receives 25 + 25 = 50. Writing a data value into an address changed the program: instructions are data.

Exam traps

  • The defining feature is the stored program in a single shared memory, not "it has a CPU, memory and I/O". Say "same memory, same bus, fetched in sequence".
  • The bottleneck is the CPU–memory path, not a slow CPU. A faster processor makes it worse; caches, wider buses and more channels make it better.
  • Asked "is a modern PC von Neumann or Harvard?", answer both: von Neumann at main memory, Harvard-style split caches at level 1 (modified Harvard).
  • Von Neumann wrote the 1945 report; he did not invent the computer. The first machine to run a stored program was the Manchester Baby in 1948, not EDVAC.
  • "Instructions and data are stored the same way" does not mean the CPU cannot tell them apart: anything fetched in the fetch phase is an instruction.

1.5 Memory and input-output devices

Memory is where the program and its data wait for the processor: a long row of numbered cells, each holding one byte or word. No single kind of memory is fast, large and cheap at once, so a computer stacks several kinds into a hierarchy, from registers and cache through DRAM to SSDs and disks. Input and output devices sit at the edge of the machine, turning keystrokes, light and sound into bits and back; the CPU reaches them through controllers, interrupts and direct memory access.

Addresses, words and capacity

Every memory cell has an address, a number from 0 upwards, and the CPU reads or writes a cell by placing its address on the address bus (from MAR) and the data on the data bus (through MDR). Most machines are byte-addressable: each address names one byte, and a 4-byte word occupies four consecutive addresses. The access time is how long one read or write takes.

Two numbers fix a memory's capacity. With n address lines the CPU can name 2ⁿ locations; with w data lines each location holds w bits. So capacity = 2ⁿ × w bits. A 32-bit address reaches 2³² = 4,294,967,296 bytes = 4 GiB, which is why 32-bit computers could not use more than 4 GB of RAM. The binary prefixes matter here: 1 KiB = 2¹⁰ = 1,024 bytes, 1 MiB = 2²⁰, 1 GiB = 2³⁰, whereas disk makers and networks use 1 KB = 1,000 and 1 GB = 10⁹ (Chapter 1.2).

The hierarchy, and the kinds of memory in it

Each level of the hierarchy in Figure 1.5.1 is slower, bigger and cheaper per byte than the one above. The arrangement works because programs show locality: they reuse the same words soon after using them (temporal locality) and touch neighbouring addresses together (spatial locality), so a small fast level holding recent data satisfies 90–99% of accesses.

Primary memory is what the CPU addresses directly. RAM (random-access memory: any address takes the same time) is read-write and volatile. SRAM stores each bit in a flip-flop of six transistors: fast (about 1 ns) but expensive, so it is used for cache. DRAM stores each bit as charge on one capacitor with one transistor: dense and cheap, but the charge leaks and must be refreshed thousands of times a second, and it is slower (about 100 ns), so it is used for main memory as DDR4 or DDR5 modules. ROM (read-only memory) keeps its contents without power and holds firmware: mask ROM is written at the factory, PROM once by the user, EPROM is erased by ultraviolet light, EEPROM and its descendant flash electrically. Flash is now the storage in every SSD, phone and pen drive.

Secondary storage

A hard disk drive (HDD) stores bits magnetically on spinning platters divided into tracks and sectors, with a read-write head on a moving arm. Reading a block takes seek time (move the arm to the track, about 5–10 ms), rotational latency (wait for the sector to arrive under the head: on average half a rotation) and transfer time (block size ÷ transfer rate). A solid-state drive (SSD) is flash memory with no moving parts: access in about 0.1 ms, silent and shock-proof, but costlier per terabyte and worn slowly by writes. Optical discs (CD 700 MB, DVD 4.7 GB, Blu-ray 25 GB) and magnetic tape serve distribution and archives; "cloud storage" is someone else's disks reached over the network.

Input and output devices and how the CPU reaches them

Input devices turn the world into bits: keyboard, mouse, touchscreen, scanner, microphone, camera, QR readers, fingerprint and iris sensors (the Aadhaar enrolment kit has all three), accelerometers and GPS. Output devices turn bits into the world: display (a grid of pixels, 1920 × 1080 for full HD), printer (inkjet or laser, rated in dots per inch), speakers, projector, motors. Some are both: a touchscreen, a network card, a disk drive.

Each device has a controller (an interface circuit with its own registers), a port (USB, HDMI, Bluetooth) and a device driver (system software that knows the controller's registers). The CPU moves data in three ways. In programmed I/O the CPU polls the controller's status register in a loop and moves each word itself, wasting the CPU while it waits. In interrupt-driven I/O the CPU starts the transfer and goes on with other work; when the device is ready it raises an interrupt, the CPU pauses the current program, runs a short handler that moves the data, and resumes. In direct memory access (DMA) a DMA controller moves whole blocks between the device and memory by itself and interrupts once at the end; this is how disks, SSDs and network cards are served.

Worked example

Question. (a) A memory chip has 20 address lines and 8 data lines. What is its capacity? (b) How many address lines are needed for 64 KiB of byte-addressable memory, and how much memory can a 32-bit address bus reach? (c) A hard disk spins at 7200 rpm, has an average seek time of 9 ms and transfers data at 150 MB/s. How long does it take to read one 4 KiB block (4096 bytes)? Compare with an SSD that answers in 80 µs.

Solution (a). Locations = 2²⁰ = 1,048,576. Each holds 8 bits = 1 byte. Capacity = 1,048,576 × 8 bits = 8,388,608 bits = 1,048,576 bytes = 1 MiB.

Solution (b). 64 KiB = 64 × 1024 = 65,536 = 2¹⁶ bytes, so 16 address lines. A 32-bit bus reaches 2³² bytes = 4,294,967,296 bytes = 4 GiB.

Solution (c). One rotation takes 60 s / 7200 = 8.33 ms, so the average rotational latency (half a rotation) = 4.17 ms. Transfer time = 4096 bytes / (150 × 10⁶ bytes per second) = 2.73 × 10⁻⁵ s = 0.027 ms. Total = seek + latency + transfer = 9 + 4.17 + 0.027 = 13.2 ms. The SSD takes 0.08 ms, so it is 13.2 / 0.08 = 165 times faster for this access. Almost all of the disk's time is mechanical waiting; the data transfer is 0.2% of it.

  • Average rotational latency is half a rotation, not a full one: 4.17 ms at 7200 rpm, not 8.33 ms.

  • SRAM is faster, needs no refresh and goes in cache; DRAM needs refresh and is main memory. Examiners ask for two differences and one use each.
  • In DMA the CPU does not move the words; in interrupt-driven I/O it still moves them in the handler. Say which one bypasses the CPU.

1.6 Instruction set and the fetch-execute cycle

An instruction set is the vocabulary a processor understands: every program, whatever language it was written in, is finally a list of these instructions in memory. The processor runs them with one fixed routine, the fetch-decode-execute cycle, repeated billions of times a second: fetch the word the PC points at, work out what it asks for, do it, and move the PC on. Learn the cycle with the registers named and you can trace any program by hand.

You need: the registers PC, IR, MAR, MDR and ACC from Chapter 1.3, and the stored-program idea from Chapter 1.4.

What an instruction looks like

An instruction is a bit pattern with fields. The opcode says what to do (add, load, jump); the operands say what to do it to: a register number, a memory address, or a constant. A simple format, used by the Toy-16 machine in this chapter, is a 16-bit word with a 4-bit opcode and a 12-bit address: 4 bits allow 2⁴ = 16 different instructions, and 12 bits address 2¹² = 4096 words. Real machines have several formats: RISC processors such as ARM and RISC-V use fixed 32-bit instructions with three register fields (ADD R1, R2, R3), while x86 instructions vary from 1 to 15 bytes and may name a memory operand directly. Humans write instructions as mnemonics (ADD, LOAD) in assembly language; the assembler turns them into the bit patterns (Chapter 1.7).

Instructions fall into four classes, and every exam asks for them with an example each: data transfer (LOAD, STORE, MOVE) between memory and registers; arithmetic and logic (ADD, SUB, AND, OR, shift, compare), which set the flags; control transfer (JMP, conditional jumps such as JZ, CALL, RETURN), which change the PC; and input-output and control (IN, OUT, HALT, NOP). Where an operand comes from is its addressing mode: immediate (the constant is inside the instruction: ADD #5), direct (the address is in the instruction: ADD 11), register (ADD R2), register indirect (the register holds the address: LOAD (R2), which is how a pointer works, Unit 6) and indexed (base register plus an offset, used for arrays, Unit 5).

The cycle, register by register

The control unit performs the same steps for every instruction. Written as register transfers, where M[x] means the memory word at address x and ← means "is loaded with":

  1. Fetch. MAR ← PC (the address of the next instruction goes to the memory address register). MDR ← M[MAR] (memory read; the word arrives in the data register). IR ← MDR (it becomes the current instruction). PC ← PC + 1 (the PC already points to the following word; on a byte-addressed machine with 4-byte instructions this is PC + 4).
  2. Decode. The control unit reads the opcode field of IR and selects the control signals for it. If the instruction names a memory operand, its address field is copied to MAR.
  3. Execute. For LOAD: MDR ← M[MAR], ACC ← MDR. For ADD: MDR ← M[MAR], ACC ← ACC + MDR, flags set. For STORE: MDR ← ACC, M[MAR] ← MDR (a memory write). For JMP: PC ← address field. For JZ: PC ← address field only if Z = 1, otherwise nothing. For HALT: the clock to the control unit stops.
  4. Check for interrupts. If a device has raised one (Chapter 1.5), save the PC and jump to the handler; otherwise go back to step 1.

Each step is one or more clock cycles, and a memory access takes many cycles of waiting unless the word is in cache, which is why a LOAD costs more than an ADD between registers. Notice the order of the two memory reads in an ADD: the first (in fetch) brings the instruction, the second (in execute) brings the operand.

RISC and CISC

A CISC (complex instruction set computer, such as x86) has many instructions of varying length, some of which read memory, compute and write back in one go; the control unit is usually microprogrammed. A RISC (reduced instruction set computer, such as ARM and RISC-V) has fewer, simpler, fixed-length instructions, only LOAD and STORE touch memory, and arithmetic works on registers; the hardwired control unit and uniform format make pipelining easy. Most phones run RISC chips, most desktops run CISC chips that translate x86 into RISC-like micro-operations inside.

1.7 System software: compiling, linking, assembling and loading

The processor understands only the bit patterns of its instruction set (Chapter 1.6), and your program is a text file. System software is the set of programs that close that gap and run the machine: the operating system, and the toolchain that takes a C or C++ source file through four stages, preprocessing, compiling, assembling and linking, to an executable file that the loader puts into memory and starts. Knowing which stage does what tells you which stage produced the error message on your screen.

System software, application software and language levels

System software serves other programs and the hardware: the operating system (process, memory, file and device management), language translators (compilers, assemblers, interpreters), the linker, the loader, and utilities such as editors and debuggers. Application software serves the user (Chapter 1.2). Programs are written at three levels. Machine language is the binary instructions themselves. Assembly language gives each instruction a mnemonic (imull %esi, %eax) and each address a name; one line becomes one instruction. A high-level language such as C, C++, Java or Python describes the computation independently of the processor; one line may become many instructions.

A high-level program reaches the CPU in one of two ways. A compiler translates the whole source file into machine code once, producing an executable that runs again and again without the compiler; C and C++ work this way. An interpreter reads the source one statement at a time and performs it directly, every time the program runs; Python works this way: easier to test, slower to run, nothing to distribute but the source. Java sits between: compiled to bytecode, then run by a virtual machine. NITC's course uses C++; the stages below are identical with g++ in place of gcc.

From source to object file: preprocessor, compiler, assembler

The preprocessor is a text editor that runs first. #include <stdio.h> is replaced by the contents of that header file (declarations of printf and friends), #define names are replaced by their text, and #ifdef blocks are kept or dropped (Unit 6). Comments are removed. The output, a .i file, is still C, just longer: gcc -E shows it.

The compiler proper translates that C into assembly language for one processor (gcc -S stops here and leaves a .s file). It reads the characters into tokens, checks the grammar, checks types and declarations (an undeclared variable or a missing semicolon is reported here), optimises, and emits instructions. The assembler (as, run by gcc -c) turns each mnemonic into its bit pattern and produces an object file, .o: machine code plus a symbol table of the names it defines and the names it uses but does not define. An object file is not runnable: its addresses start at 0, and calls to functions in other files or in the C library point nowhere yet.

Linking

The linker (ld, called by gcc when you do not say -c) joins object files and libraries into one executable. It does two jobs. Symbol resolution matches every undefined name to exactly one definition: main.o needs total and printf; total.o supplies total, and the C library supplies printf. A name nobody defines is an "undefined reference" error; a name defined twice is a "multiple definition" error. Relocation then places the sections of all the files one after another and patches every address. A static library (.a) is copied into the executable; a shared library (.so on Linux, .dll on Windows) is only noted and connected when the program is loaded, so one copy of libc.so.6 in memory serves every running program. Separate compilation is the point: a project of a thousand files recompiles only the file you changed, then relinks.

Loading and running

The loader is part of the operating system (on Linux, the execve system call plus the dynamic linker ld-linux). When you type ./bill, it reads the executable's headers, maps the code and data sections into a fresh region of memory, loads the shared libraries it names, sets up the stack with the command-line arguments, and sets the PC to the entry point. From then on the program is a process (Chapter 1.2) running the fetch-execute cycle; when main returns, the OS frees the memory. The linker runs once when you build; the loader runs every time you run.

Worked example

Question. A program is split across two C files. Build it stage by stage with gcc on Linux, show what each stage produces, and explain the error that appears when the second file is left out of the link.

{
    int bill = total(45, 3);        /* 3 cups of tea at Rs 45 */
    printf("Bill: Rs %d\n", bill);

/* total.c */

}

The assembly the compiler wrote for total (x86-64, AT&T syntax), and the bytes the assembler made of it:

total:
    endbr64                 f3 0f 1e fa

Ten bytes of machine code for a three-line C function. The link error is a linker message, not a compiler one: main.c compiled without complaint because the declaration on line 3 told the compiler that total exists somewhere; only the linker found that no object file defined it. Adding total.o resolves the symbol, and the loader then runs the result: 45 × 3 = 135.

Exam traps

  • "undefined reference to X" is a linker error (no definition of X in any object file or library, or a missing -lm); "X undeclared" or "expected ';'" is a compiler error; "No such file or directory" for a header is a preprocessor error. Name the stage.
  • A header file holds declarations (prototypes), not the code. #include <stdio.h> does not "import the printf library"; the linker joins the library.
  • The assembler translates assembly one-to-one into machine code and makes an object file; it is not the compiler, and its output is not yet an executable.
  • The loader is part of the operating system and runs every time you run the program; the linker runs once when you build.
  • An interpreter never produces an executable; a compiler does. Python shows a type error when that line runs; C shows it before the program exists.
  • In exam wording "compiling" often means all four build stages together. Asked to "explain compiling and linking", describe the stages separately and say where the object file sits between them.

Check yourself

Remember List the four stages that turn a C file into an executable, with the input and output of each. 4 marks

Preprocessor: .c → .i (headers pasted, macros expanded). Compiler: .i → .s (assembly). Assembler: .s → .o (object file with machine code and a symbol table). Linker: .o files + libraries → executable.

Remember Give two differences between a compiler and an interpreter. 2 marks

A compiler translates the whole program once into machine code that runs without it; an interpreter translates and executes statement by statement, every run. Compiled code runs faster; interpreted programs are easier to test and need no build step, and errors appear only when the line runs.

Understand Why is linking a separate stage rather than part of compiling? 3 marks

Programs are split into many files and use libraries written by others. Compiling each file separately means only changed files are recompiled, libraries can be shipped as object code without source, and the same object file can be linked into many programs. The linker is the step that joins the independently compiled pieces by resolving names and relocating addresses.

Understand What are static and dynamic linking, and give one advantage of each. 3 marks

Static: library code is copied into the executable at link time; the file is self-contained and runs anywhere. Dynamic: the executable only names the shared library, which the loader connects at run time; the file is small, one copy of the library in memory serves all programs, and a library update fixes every program at once.

Apply Name the stage that produces each message: (i) "fatal error: stdoi.h: No such file or directory"; (ii) "error: 'bil' undeclared"; (iii) "undefined reference to `sqrt'". Give the fix for each. 4 marks

(i) Preprocessor: the header name is misspelt; write stdio.h. (ii) Compiler: a variable used without a declaration; declare it or fix the spelling. (iii) Linker: the maths library was not linked; add -lm to the gcc command.

Analyze A phone app vendor must choose between static and dynamic linking of a 4 MB graphics library used by 20 of its apps. Weigh the choice. 4 marks

Dynamic: saves 4 MB × 19 of storage, one in-memory copy serves all running apps, and a security fix to the library reaches every app in one update; but all 20 apps break together if the shared copy is missing or changes behaviour. Static: each app carries its own copy, self-contained and immune to version clashes, at the cost of 80 MB of duplicated code and 20 separate updates for one bug.

Beyond the syllabus

Not for the exam. Modern toolchains blur the stages: Clang/LLVM compiles to an intermediate representation that is optimised across files at link time; just-in-time compilers (Java's HotSpot, the V8 engine behind JavaScript in your browser) compile hot code while the program runs; WebAssembly is a machine-independent object format for the web. Build systems (make, CMake, Gradle) decide which files need recompiling. The chapter "Linking" in Bryant and O'Hallaron's Computer Systems: A Programmer's Perspective is the standard deeper read.

Glossary

Accumulator (ACC)
The register that holds the running result of arithmetic in a simple CPU.
Address bus
One-way lines carrying the address from MAR to memory; n lines reach 2ⁿ locations.
ALU
Arithmetic-logic unit: a combinational circuit that produces a result and flags from two inputs and an operation code.
Assembler
System software that turns assembly mnemonics into machine code in an object file, one instruction per line.
Cache
Small, fast SRAM between the CPU and main memory that keeps copies of recently used words.
CISC / RISC
Complex instruction set (many variable-length instructions, memory operands) against reduced instruction set (few fixed-length instructions, load/store only).
Compiler
Translator from a high-level language to assembly or machine code, run once before the program runs.
Control unit
The part of the CPU that decodes the opcode and issues timed control signals to registers, ALU and memory.
CPI
Average clock cycles per instruction; instructions per second = clock frequency ÷ CPI.
DMA
Direct memory access: a controller moves blocks between a device and memory without the CPU copying each word.
DRAM / SRAM
Dynamic RAM stores a bit as capacitor charge and needs refresh (main memory); static RAM uses a flip-flop and is faster (cache).
Fetch-decode-execute cycle
The routine the control unit repeats for every instruction: fetch the word at PC, decode it, carry it out.
Firmware
Software stored in non-volatile memory on the hardware, such as the BIOS/UEFI.
Flags
Status bits Z (zero), N (negative), C (carry), V (overflow) set by the ALU and read by conditional jumps.
Harvard architecture
Separate memories and buses for instructions and data; used in microcontrollers and in the L1 caches of modern CPUs.
Instruction set
The complete list of instructions a processor can execute, with their formats; also called the ISA.
Interrupt
A signal from a device that makes the CPU pause the current program, run a handler, and resume.
Linker
System software that joins object files and libraries into one executable by resolving symbols and relocating addresses.
Loader
The part of the operating system that copies an executable into memory and starts it as a process.
Locality
The tendency of programs to reuse recent words (temporal) and neighbouring words (spatial); the reason caches work.
MAR / MDR
Memory address register (holds the address being accessed) and memory data register (holds the word moving to or from memory).
Moore's law
The observation that transistors per chip double about every two years.
Object file
Machine code plus a symbol table and relocation information; not runnable until linked.
Opcode / operand
The field of an instruction that names the operation, and the fields that name what it acts on.
Preprocessor
The first stage of a C build: pastes #include files, expands #define macros, removes comments.
Program counter (PC)
The register holding the address of the next instruction; incremented during fetch, overwritten by jumps.
Stored program
The von Neumann idea that instructions are kept in memory as numbers, alongside data.
System software
Programs that run the machine for other programs: operating system, translators, linker, loader, utilities.
Von Neumann bottleneck
The limit set by the single path between CPU and memory that carries both instructions and data.
Word
The natural unit of data a CPU handles at once, 32 or 64 bits today.
