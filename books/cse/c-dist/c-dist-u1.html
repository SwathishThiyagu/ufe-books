1.1 Need for parallel processing and levels of parallelism

A single processor runs one instruction at a time, and its clock cannot keep rising because of heat and power limits. Parallel processing answers this by using many execution units together: several cores on one chip, many lanes inside one core, or hundreds of machines in a cluster. The same idea appears at levels from adding 64 bits in one clock to splitting a training job across 1000 servers. This chapter explains why parallelism is needed, which levels exist, and which design problems every parallel program must solve.

Why one processor is no longer enough

For thirty years each new chip ran faster than the last. That stopped. Clock frequency is now limited by heat. The dynamic power a chip burns rises with the square of the supply voltage and in proportion to the clock, so pushing the clock up makes the chip overheat or drains a phone battery in hours. Engineers call this the power wall.

P ≈ C × V² × f

P is the dynamic power in watts, C is the switched capacitance in farads, V is the supply voltage in volts, and f is the clock frequency in hertz. Halving V cuts P to one quarter (divides it by 4) at the same f.

A second wall is memory. Processor cycles became shorter much faster than DRAM access time did, so one core can wait hundreds of cycles for a single load. Many cores waiting together hide that gap; one very fast core cannot.

A third wall is instruction-level. A superscalar core already issues a few instructions per cycle, and true dependencies between instructions stop it going much wider.

Meanwhile the work grew. A UPI switch clears thousands of transactions every second, and a team training a language model wants billions of arithmetic operations per second. One core delivers neither. The answer is to build machines that do many things at once: several cores on a die, wide vector units, and clusters of machines.

Levels of parallelism and granularity

Parallelism is not one thing. It appears at five levels, from a trick inside the adder to a data centre.

  • Bit level: a 64-bit adder works on 64 bit pairs in one operation instead of an 8-bit adder taking eight steps. Carry look-ahead adders are the classic example, since they compute all carries in parallel rather than letting one carry ripple through.
  • Instruction level: a pipeline overlaps stages of different instructions, so while instruction 1 writes its result, a later instruction (three stages behind in a classic 5-stage pipeline) is decoding, and several instructions are in flight at once. A superscalar core issues two to six instructions in the same cycle.
  • Data level: one instruction acts on many data items. A vector unit adds eight floating-point numbers per instruction; a GPU runs thousands of lanes on the same instruction over different elements.
  • Task level: different threads do different jobs on different cores, for example one thread renders video while another plays audio. Threads share data, so synchronisation enters.
  • Job level: independent programs run on separate machines, such as 500 batch jobs on a cluster.

The levels differ in granularity: the amount of useful work done between two communication or synchronisation events. Bit-level work has no communication at all. A thread hand-off costs tens of nanoseconds, a cluster message microseconds. Fine-grained parallelism needs cheap communication; coarse-grained parallelism tolerates expensive communication. The SIMD and MIMD labels for these machines are in Flynn's models.

Parallel versus distributed, design issues, and the ecosystem

Parallel computing and distributed computing overlap but are not the same. Parallel computing usually means tightly coupled hardware: cores that share one memory, a fast interconnect, one operating system, communication in nanoseconds, and any core able to read what another wrote. Distributed computing means independent computers on a network, each with its own memory and clock, able to fail alone, where messages can be delayed or lost. A 32-core server is parallel; a cloud region or a set of bank ATMs is distributed. See Unit 4, Distributed System Models and Logical Time, for the distributed side.

Every parallel system faces the same five design issues.

  • Partitioning: cut the work into pieces that can run at the same time (Chapter 1.7).
  • Communication: move data between pieces and count its cost (Chapter 1.5).
  • Synchronisation: make pieces wait at the right points (Unit 3).
  • Scalability: keep efficiency as processors are added (Chapter 1.6).
  • Fault tolerance: keep going when one piece or one machine fails (Unit 5).

Hardware follows the same trade-offs. A multicore CPU gives 8 to 64 powerful cores that share cache. A GPU gives thousands of small lanes with high memory bandwidth. A cluster joins commodity servers on Ethernet or InfiniBand. Cloud instances are rented by the hour. Doubling cores rarely doubles speed, because coordination and idle time grow, and a data centre pays for power and cooling on every core.

Worked example

Question. A program takes 100 s on one processor. Of that run time, 20% is serial work that cannot be parallelised and 80% is parallel work that scales perfectly. (a) Find the maximum speedup with any number of processors. (b) Find the speedup and efficiency with 16 processors. (c) Say in one line why the answer to (b) is not 16.

  1. Let f be the serial fraction and p the number of processors. Here f = 0.20 and the parallel fraction is 1 − f = 0.80.
  2. (a) With p processors the time is T(p) = T(1) × (f + (1 − f)/p). As p grows, the term (1 − f)/p falls to 0, so T(p) → T(1) × f and the speedup is capped at 1/f.
  3. S(max) = 1 ÷ 0.20 = 5. Even with infinite processors the program cannot run more than 5 times faster than one processor.
  4. (b) Put p = 16: T(16) = T(1) × (0.20 + 0.80 ÷ 16) = T(1) × (0.20 + 0.05) = T(1) × 0.25.
  5. S(16) = T(1) ÷ T(16) = 1 ÷ 0.25 = 4, so the run time falls from 100 s to 25 s.
  6. Efficiency = S(16) ÷ p = 4 ÷ 16 = 0.25, that is 25% of the 16 processors' capacity is used.
  7. (c) The remaining 20 s of serial work still runs on one processor, so the time can never drop below 20 s.

Answer. (a) Maximum speedup is 5. (b) With 16 processors the speedup is 4 and the efficiency is 0.25 (25%).

Exam traps

  • Swapping the fractions: 20% serial means f = 0.20, not 0.80. Always divide 1 by the serial fraction for the unlimited-processor bound.
  • Assuming speedup equals the number of processors. Amdahl's bound caps it at 1/f, and real machines fall below even that because of overhead.
  • Calling a multithreaded program on one server 'distributed'. Distributed means separate memories, separate clocks and partial failure; a shared-memory server is parallel.
  • Confusing granularity with level. Granularity is the work done per communication event; the five levels are where the parallelism sits.

1.2 Flynn's models: SIMD, MIMD and dataflow

Flynn's models classify a computer by how many instruction streams and data streams it uses at the same time. An instruction stream is the sequence of operations a control unit issues. A data stream is the set of operands those operations work on. The four classes are SISD, SIMD, MISD and MIMD. The names matter in exams and in design: a GPU is SIMD-like, a multicore CPU is MIMD, and a dataflow machine is a different idea. Each class has a clear rule, a common example, and a limit.

You need: Chapter 1.1 for the levels of parallelism and why parallel processing helps.

Streams and the four Flynn classes

Flynn's models use two counts: instruction streams and data streams. A stream is active at one time. One CPU core fetching and executing one program has one instruction stream. The operands that one instruction works on form one data stream. The four classes come from the possible counts.

SISD is the scalar CPU: one instruction works on one data item. A SIMD computer has one control unit: issues one instruction, and many ALUs apply it to many data items. MISD has many instruction streams working on one data stream. It is mostly theoretical; no common general-purpose machine uses it. In a MIMD multiprocessor, each processor or core has its own instruction stream and its own data stream. Shared-memory and distributed-memory forms are in Chapter 1.3.

SIMD: one instruction, many data

A SIMD computer has one control unit, many ALUs, and vector or array registers. The control unit fetches one instruction, such as add, and broadcasts it. Each ALU takes its own element from the data stream. All ALUs run in lockstep: they start and finish the same instruction together.

  1. The control unit fetches one instruction, for example add.
  2. It broadcasts that instruction to all ALUs.
  3. Each ALU reads its own data element.
  4. All ALUs execute the instruction in lockstep.
  5. Mask bits switch off lanes that must not write.

Array add shows the idea. To compute C[i] = A[i] + B[i], one instruction adds A[i] and B[i] for every active lane i. If n is larger than the lane count, the hardware repeats in chunks. A mask is one bit per lane. Mask bit 1 lets the lane write; 0 makes it idle. Masks handle tails and branches: the hardware computes both sides of an if, then masks select the correct lanes.

Shared-memory SIMD algorithms mean the same operation on many array elements. A vector sum, an image filter, or a matrix row update is written as lane-wise work. The programmer thinks in arrays, not one scalar at a time. GPUs are the common SIMD-like machine today; Unit 3 covers CUDA lanes and warps. A GPU warp runs a group of lanes in lockstep.

MIMD: independent streams

A MIMD multiprocessor has many processors. Each processor fetches its own instructions and uses its own data. The processors are independent: one can run a database query while another runs a web server. They can also run different parts of one parallel program. This is the class of most multicore CPUs and cluster nodes.

Two forms matter. In shared-memory MIMD, all processors see one address space; threads communicate by reading and writing shared variables. In message-passing MIMD, each node has private memory; processes communicate by sending messages. MIMD needs synchronization: locks, barriers, or messages. Without it, two threads can update the same counter and lose an update.

SPMD means single program, multiple data. All processes run the same program text, but each has a different rank and works on different data. MPI programs are SPMD. SPMD is a programming style on MIMD machines, not a Flynn class. Do not call it a fifth class. Data parallelism and model parallelism are in Chapter 1.8.

Dataflow: operands trigger work

A dataflow machine does not use a program counter to choose the next instruction. It uses a dataflow graph. A node is an operation, such as add or multiply. An edge carries a value. A node fires when all its input operands are ready; then it computes and sends results along output edges.

  1. Place values, called tokens, on input edges.
  2. A node is enabled when every input edge has a token.
  3. The node fires: it reads the tokens, computes, and removes them.
  4. It puts result tokens on its output edges.
  5. Repeat until no node is enabled.

An adder with tokens 3 and 4 fires and sends 7. If one input is missing, it waits. This data-driven order is not a Flynn class: Flynn counts instruction and data streams, while dataflow counts readiness of operands. A dataflow graph can expose parallelism: independent nodes fire at the same time. Some processors use dataflow ideas inside schedulers, but a full dataflow machine is not common.

Worked example

Question. Name the Flynn class for each case. (a) A GPU runs one add instruction on many lanes. (b) An 8-core CPU runs a different program on each core. (c) A scalar CPU adds two registers. (d) A dataflow adder fires when both inputs arrive. Explain each answer in one line.

  1. Read each case for instruction streams and data streams.
  2. (a) One add instruction, many lane data: one instruction stream, many data streams. Class is SIMD.
  3. (b) Eight cores run different programs: many instruction streams, many data streams. Class is MIMD.
  4. (c) One core runs one add on two registers: one instruction stream, one data stream. Class is SISD.
  5. (d) Firing depends on operand arrival, not on a control unit's instruction count. This is dataflow, which is not a Flynn class.

Answer. (a) SIMD, (b) MIMD, (c) SISD, (d) dataflow, which is not a Flynn class.

Exam traps

  • A multicore CPU is MIMD, not SIMD. Many cores alone do not make SIMD; SIMD needs one instruction over many data items.
  • MISD is mostly theoretical. Do not invent a common MISD computer for an exam answer.
  • Dataflow is not a Flynn class. Flynn counts streams; dataflow uses operand readiness.
  • SPMD is a programming style on MIMD, not a fifth Flynn class.
  • SIMD lockstep does not mean all lanes do useful work. A mask can switch lanes off.

1.3 Shared-memory and distributed-memory architectures

Two memory pictures cover most parallel machines. In a shared-memory machine, all processors use one address space, so a write by one core can be read by another. In a distributed-memory machine, each node has private RAM and nodes exchange messages. The first is common inside a server or chip; the second is common across servers, clusters and cloud data centres. The choice changes both hardware and programming style: threads and locks on one side, send and receive on the other.

You need: Chapter 1.1 for why parallel time matters, and Chapter 1.2 for SIMD and MIMD names.

Shared memory: one address space

A shared-memory machine gives every processor one view of memory. A load or store names an address, and any processor can use that address. The operating system and programs see one address space. This makes data sharing direct: write a value, and another processor can read it. It also makes locking and producer-consumer queues simpler than in a message-based machine.

The common form is UMA, uniform memory access, also called SMP, symmetric multiprocessing. All processors reach all memory banks in about the same time. Small systems join processors and memory with a bus. A bus is simple, but only one transfer can use it at a time. Larger systems use a crossbar, a switch that connects any processor to any memory bank; it gives more bandwidth and costs more wires.

  • UMA / SMP: one address space; similar latency to all RAM; bus or crossbar.
  • NUMA: each processor has local RAM; local access is faster; remote access crosses an interconnect and has higher latency. The address space is still one.
  • COMA: cache-only memory architecture; main memory is treated as a large cache and data migrates to where it is used. It is a research and specialized design form.

A cache stores copies of recently used lines. On a shared-memory machine, two caches may hold the same line. Cache coherence is the problem of keeping those copies consistent when one processor writes. That one line is enough here; protocols belong to Unit 5.

Shared-memory SIMD is another architecture form: many lanes run one instruction stream over different data, often with a shared control unit. The tree and mesh machines are network forms; see Chapter 1.5.

Distributed memory: private memory and messages

A distributed-memory machine is built from nodes. Each node has a processor, its own RAM, and a network interface. A node cannot load or store an address in another node's RAM. To share data, one node sends a message and another receives it. The address space is not shared. This is the main difference from a shared-memory machine.

A cluster is a set of complete computers joined by a network; each computer keeps its own operating system image in the usual case. An MPP, massively parallel processor, is a large machine designed for scale, often with a specialized interconnect and many nodes. Modern multicore nodes combine both ideas: inside a node, cores share RAM; across nodes, the machine passes messages.

The basic primitives are send and receive. send(destination, buffer) sends the bytes in buffer to a named destination. receive(source, buffer) waits for a message and copies it into buffer. A synchronous send waits until the receiver has taken the message, or at least until it is safe to reuse the buffer. An asynchronous send returns at once and lets the program do other work; the system completes the transfer later. Full protocols, matching and buffering are in Unit 4.

Message passing has a cost that shared memory hides: the sender must copy data into the network, the network carries it, and the receiver copies it out. Latency is the time for one small message; bandwidth is the bytes per second for large messages. Local shared-memory access is usually nanoseconds; a network message is often microseconds or more.

T_msg ≈ L + n/B + 2·T_copy

T_msg is the time for one message of n bytes; L is startup latency in seconds; B is bandwidth in bytes per second; T_copy is one local copy time in seconds.

Comparing the two architectures

The choice is not just hardware. Shared memory is easy for pointer-based data structures and fine-grained sharing. Message passing forces explicit data movement, so the programmer must partition data and schedule communication. That extra effort can pay back in scalability: a cluster can grow by adding nodes, while a bus-based SMP has a fixed limit and a large shared address space must be kept coherent.

Worked example

Question. A job takes 100 s on one core. 20 s is serial and 80 s can run in parallel. (a) On a 4-core SMP with no message cost, find T4 and speedup S4. (b) On a 2-node cluster, the parallel part divides equally over 2 nodes and message overhead is 10 s; find T2node and speedup. (c) Which architecture is faster here?

  1. One-core time T1 = 100 s. Serial part = 20 s. Parallel part = 100 − 20 = 80 s.
  2. (a) SMP: T4 = serial + parallel/4 = 20 + 80/4 = 20 + 20 = 40 s. S4 = T1/T4 = 100/40 = 2.5.
  3. (b) Cluster: T2node = serial + parallel/2 + overhead = 20 + 80/2 + 10 = 20 + 40 + 10 = 70 s. S2node = 100/70 = 1.428571... ≈ 1.43.
  4. (c) 40 s < 70 s, so the 4-core SMP is faster in this model.

Answer. The 4-core SMP takes 40 s with speedup 2.5; the 2-node cluster takes 70 s with speedup 1.43, so the SMP wins here.

Exam traps

  • Shared memory is not communication-free: NUMA remote access, bus contention and cache coherence all add time.
  • One address space does not mean one physical memory. In NUMA, local and remote RAM have different latencies.
  • A cluster is not the same as an SMP: nodes have private RAM; a thread cannot directly load a remote node's variable.
  • Speedup uses one-processor time in the numerator; do not divide by the number of cores when serial time is present.
  • Synchronous send does not always mean the receiver has read the data; it means the sender may safely continue or reuse the buffer under the stated rule.

1.4 PRAM model and its variants

PRAM (Parallel Random Access Machine) is an ideal shared-memory computer: P processors, one shared memory, lockstep steps, and unit-cost reads and writes. It exists so parallel algorithms can be compared without real network delay, caches or contention. EREW, CREW and CRCW are its variants. It remains the standard analysis model for shared-memory algorithms.

You need: shared-memory architectures for one address space and Flynn's MIMD model for many processors.

One memory, lockstep steps

PRAM has P processors, numbered 0 to P−1, and M shared cells. In one step each processor may read one cell, compute, and write one cell. All processors step together: the model is synchronous. Every read and write costs 1 time unit, whatever the address. The model has no interconnection network, so no message delay and no contention cost. PRAM is ideal, not hardware. Parallel time T(P) is the number of steps. Cost C(P) = T(P) × P processor-time units; cost is also called work. Real caches and barriers add time, so PRAM time is a best case.

C(P) = T(P) × P

T(P) is parallel time in steps; P is the number of processors; C is cost in processor-time units.

EREW, CREW and CRCW

EREW (Exclusive Read, Exclusive Write): at most one processor reads a cell and at most one writes it per step. CREW (Concurrent Read, Exclusive Write): many may read one cell, but only one may write it. CRCW (Concurrent Read, Concurrent Write): many may read and many may write one cell. A CRCW write conflict needs a rule. Common: all writers must write the same value, else the result is undefined. Arbitrary: one writer wins, but the model does not say which. Priority: the highest-numbered processor wins.

VariantSame cell per step
EREWone reader, one writer
CREWmany readers, one writer

CRCW priorityhighest index wins

Simulating one variant by another

A CRCW machine simulates EREW directly, because CRCW permits every EREW step. EREW must serialise a CRCW write conflict. For common, arbitrary and priority rules, a binary tree combine resolves P writes in ⌈log₂ P⌉ rounds. Concurrent reads use one read plus a broadcast tree, also ⌈log₂ P⌉ rounds. The variants differ by at most a logarithmic time factor here. State algorithms on the weakest variant that works.

rounds = ⌈log₂ P⌉

P is the number of contending processors; ⌈⌉ rounds up to a whole number.

Worked example

Question. P = 8 processors all write to cell A in one step. (a) Under EREW with a binary-tree combine, how many rounds and what is the cost? (b) Under priority CRCW, how many rounds and what is the cost? One round = 1 time unit.

  1. 1. Tree combine halves the active values: 8 → 4 → 2 → 1. Rounds = log₂ 8 = 3.
  2. 2. EREW time = 3 rounds × 1 time unit = 3 time units.
  3. 3. EREW cost = 3 × 8 = 24 processor-time units.
  4. 4. Priority CRCW resolves the write in 1 round; time = 1 time unit.
  5. 5. CRCW cost = 1 × 8 = 8 processor-time units.

Answer. EREW: 3 rounds, cost 24 processor-time units. Priority CRCW: 1 round, cost 8 processor-time units.

Exam traps

  • PRAM is not hardware. A PRAM speedup is not a real speedup; it ignores network delay and memory contention.
  • CREW allows concurrent reads only. Many writers to one cell in one step is CRCW.
  • Time is steps; cost is steps × processors. If the question asks for cost, giving only time loses marks.
  • In a write conflict, common, arbitrary and priority are different rules. Do not answer one when another is asked.

1.5 Interconnection networks: mesh, tree, hypercube, butterfly

A parallel machine is only as fast as the paths between its processors. The interconnection network is the wiring and switches that carry data. Four classic shapes trade three costs: degree (links per node), diameter (longest shortest path) and bisection width (links cut when the machine splits in half). Mesh, tree, hypercube and butterfly pick different balances. Designers use them in supercomputers, multicore chips and network-on-chip fabrics.

You need Chapter 1.3 for separate processors joined by links, plus basic graph terms (node, edge, path).

Degree, diameter and bisection width

A network has N nodes and some links. Four counts describe cost and speed.

  • Degree d: links at one node. High degree costs pins and router ports.
  • Diameter D: largest number of hops in the shortest path between any two nodes. A worst-case message needs D steps.
  • Bisection width B: fewest links cut to split nodes into two halves of N/2. A big exchange crosses this cut.
  • Link count: N × d ÷ 2 for a regular network, because each link has two ends.
  • Routing: rule for the next link; good networks keep it local and simple.

Mesh and tree

A k × k mesh puts nodes on a grid. Node (i, j) links to (i ± 1, j) and (i, j ± 1). An inside node has degree 4, an edge node 3, a corner 2. With N = k², links = 2k(k − 1), diameter = 2(k − 1), bisection = k. For an r × c rectangle, diameter = (r − 1) + (c − 1) and bisection = min(r, c).

A mesh is cheap: wires reach only neighbours. Its diameter grows as 2√N, so far corners talk slowly.

A binary tree gives each node one parent and up to two children. Internal nodes have degree 3, leaves 1, root 2. N nodes sit in log₂ N levels with N − 1 links. Diameter is about 2 log₂ N, leaf up to root and down.

Bisection width is 1: cut the link under the root and the tree splits. Every left-right message shares that link. A fat tree widens links near the root; data centres use this.

Hypercube and butterfly

An n-cube has N = 2ⁿ nodes, each with an n-bit address. Two nodes link exactly when their addresses differ in one bit. The 3-cube has 8 nodes and 12 links.

Degree n, diameter n, links n·2ⁿ⁻¹ = nN/2, bisection N/2. It is recursive: two (n − 1)-cubes joined by 2ⁿ⁻¹ matching links. Routing: compare current and destination addresses, flip one differing bit; at most n hops.

Cost: degree n = log₂ N and a wide cut of N/2 links. Wires per node grow with the machine.

A butterfly is multistage: n + 1 stages, each with 2ⁿ nodes in a column. In stage i, node x links to two nodes in stage i + 1: node x itself (the straight link) and the node whose address differs from x in bit i (the cross link). Interior switches have degree 4 (two backward, two forward); first and last stages have degree 2, so degree is at most 4. Any input reaches any output, and each stage settles one address bit. Butterflies realize permutations and serve the FFT and sorting networks. Price: many more nodes for fixed degree, easier to lay out than a hypercube's growing degree.

Embeddings and other topologies

An embedding lays network A onto network B so B runs A's programs. Each A-link is simulated by a path in B. Dilation is the longest such path; expansion is B nodes per A node; congestion is the largest number of simulated links sharing one B-link.

Mesh into hypercube: for a k × k mesh take n = 2⌈log₂ k⌉. Use reflected Gray code: G(x) = x ⊕ (x >> 1), where ⊕ is bitwise XOR and >> shifts right. Give node (i, j) the address G(i) followed by G(j). Consecutive i or j values differ in exactly one bit, so each mesh link maps to one hypercube link: dilation 1. Expansion is 2ⁿ/k² ≤ 4.

Tree into hypercube: a complete binary tree with 2ⁿ − 1 nodes (n levels) embeds in the n-cube with small constant dilation and small constant congestion. A hypercube therefore simulates a tree with little slowdown.

  • Fully connected: degree N − 1, diameter 1. Fastest, impossible for large N.
  • Pyramid: degree 5 (four children plus a parent), or 9 if in-plane links exist at every level; diameter about log₂ N; mirrors quadtree image decomposition.
  • Perfect shuffle: degree 2 plus an exchange link, O(log N) diameter.
  • Cube-connected cycles: each cube node becomes a small cycle, degree 3, diameter a little over twice the cube's.

1.6 Performance measures: speedup and efficiency

A parallel program uses p processors to finish sooner than one processor can. Speedup compares the two times, and efficiency says how much of each processor's capacity the work actually uses. These two numbers decide whether buying more cores is worth it. They appear in every parallel benchmark, in cluster job reports, and in cloud bills where you pay per processor-hour. This chapter defines the measures, gives Amdahl's law for the ceiling they impose, and explains what overhead, load imbalance and memory effects do to real measurements.

You need Chapter 1.1 for why parallelism exists and Chapter 1.3 for where the processors sit.

Time, speedup, efficiency and cost

Let T₁ be the time in seconds for one processor to finish a problem. Let Tₚ be the time in seconds for p processors to finish the same problem. The processor count p is a plain number, at least 1. Speedup compares the two times.

S = T₁ ÷ Tₚ

S is speedup (no unit); T₁ is one-processor time in seconds; Tₚ is p-processor time in seconds.

Speedup S answers: how many times faster is the parallel run? If Tₚ = T₁ ÷ p, then S = p. That is perfect linear speedup, and it is the best the basic model allows.

Efficiency divides speedup by the number of processors. It answers: how well is each processor used?

E = S ÷ p = T₁ ÷ (p × Tₚ)

E is efficiency (no unit, often written as a fraction or percentage); S is speedup; p is the processor count; T₁ and Tₚ are times in seconds.

Perfect efficiency is E = 1, or 100 percent. A value of E = 0.6 means each processor does useful work only 60 percent of the time. The rest goes to waiting, communication or idle time.

Cost C = p × Tₚ is the total processor time spent, measured in processor-seconds. Work W = T₁ is the one-processor time, measured in seconds. Their ratio is dimensionless and is exactly the efficiency: E = W ÷ C = T₁ ÷ (p × Tₚ). When E < 1, part of the cost buys no useful work.

C = p × Tₚ

C is cost in processor-seconds; p is the processor count; Tₚ is the parallel time in seconds. Work W = T₁ is in seconds.

Amdahl's law and its ceiling

Some part of a program cannot be parallelised: input reading, a final reduction, a serial loop. Let f be the fraction of the one-processor time spent in that serial part. The parallel part is 1 − f. On p processors, the parallel part can shrink, but the serial part cannot.

Tₚ ≥ f × T₁ + (1 − f) × T₁ ÷ p

f is the serial fraction of T₁ (0 ≤ f ≤ 1); T₁ is one-processor time in seconds; Tₚ is the best possible p-processor time in seconds; p is the processor count.

Divide T₁ by both sides of the inequality. The left side becomes T₁ ÷ Tₚ, which is S, so S ≤ 1 ÷ (f + (1 − f) ÷ p). This is Amdahl's law, an upper bound on speedup.

S(p) ≤ 1 ÷ (f + (1 − f) ÷ p)

S(p) is the maximum speedup on p processors; f is the serial fraction; p is the processor count.

As p grows, the term (1 − f) ÷ p goes to zero. The bound approaches 1 ÷ f. A program with f = 0.1 can never exceed speedup 10, however many processors you add. With f = 0.2 the ceiling is 5.

Gustafson's law looks at the other case: the problem size grows with p. If the parallel part expands to fill the extra processors, scaled speedup is S′ = fG + p(1 − fG). Here fG is the serial fraction of the parallel run's time, and fG ≠ f in general. The ceiling is no longer 1 ÷ f, because the serial part stays fixed while useful work grows.

Overhead, imbalance and scaling

Real time Tₚ includes work plus overhead. Overhead is communication between processors, synchronisation at barriers, process startup and message packing. Overhead adds seconds, so it lowers S below the Amdahl bound. A program with perfect load balance can still be slow because of overhead.

Load imbalance means some processors finish early and wait. The slowest processor sets Tₚ. If one processor gets twice the work of the others, adding processors does not help much. Task splitting and load balancing are covered in Chapter 1.7.

Superlinear speedup means S > p. Within the basic formula this is impossible, because Tₚ cannot be less than T₁ ÷ p. It can appear in measurements through cache and memory effects: with p processors each core may hold a larger slice of the data in its private cache, so the parallel run reads less from slow memory. Report such results with the cache explanation, not as a formula result.

Strong scalability fixes the problem size and increases p. Speedup rises, then flattens, and efficiency falls as overhead grows. Weak scalability increases the problem size along with p so that time per processor stays constant. Efficiency near 1 under weak scaling means the machine can handle larger jobs without losing throughput.

Worked example

Question. A program takes 200 s on one processor. Of that time, 20 s is serial and 180 s is parallel. It runs on 8 processors with perfect scaling of the parallel part. Find T₈, the speedup, the efficiency and the maximum speedup as p → ∞. What limits the result?

  1. Serial time = 20 s. Parallel time on one processor = 200 − 20 = 180 s.
  2. On 8 processors the parallel part takes 180 ÷ 8 = 22.5 s.
  3. T₈ = serial time + parallel time = 20 + 22.5 = 42.5 s.
  4. Speedup S = T₁ ÷ T₈ = 200 ÷ 42.5 = 4.7059, about 4.71.
  5. Efficiency E = S ÷ p = 4.7059 ÷ 8 = 0.5882, about 0.588.
  6. Serial fraction f = 20 ÷ 200 = 0.1. Maximum speedup = 1 ÷ f = 1 ÷ 0.1 = 10.
  7. The serial 20 s sets the ceiling. Real overhead would make T₈ larger than 42.5 s and the speedup smaller than 4.71.

Answer. T₈ = 42.5 s, S ≈ 4.71, E ≈ 0.588, and the maximum speedup is 10; the 20 s serial part limits the result.

  • Do not treat the Amdahl bound as a measured result. Overhead and load imbalance make real speedup lower.
  • Keep units straight: T₁ and Tₚ are seconds, cost is processor-seconds, and S and E have no unit.
  • A measured speedup above p is not allowed by the formula. Check for cache or memory effects before claiming it.
  • The serial fraction f is a fraction of one-processor time, not a count of serial lines of code.

1.7 Problem decomposition and load balancing

Problem decomposition turns a large computation into smaller tasks. Load balancing places those tasks on processors so each finishes near the same time. Decomposition decides what can run in parallel; balancing decides where it runs. Both matter on a phone chip with four cores, a cloud cluster, or a lab cluster. Bad decomposition creates too many tiny messages; bad balancing leaves cores idle while one core carries the tail. This chapter shows the main decomposition styles, the dependence graph, granularity, and the static and dynamic mapping methods that keep a parallel program busy.

You need: Chapter 1.1 for why parallel work exists and Chapter 1.6 for speedup and efficiency.

Four ways to decompose work

Decomposition is the first design step. You take one problem and cut it into tasks. A task is a unit of work that one processor can run. The cut must expose parallelism and keep dependencies small.

Data or domain decomposition splits the data. Each task works on a slice. A 4000 × 4000 image can be cut into 16 tiles of 1000 × 1000 pixels; each tile is a task. The same rule applies to rows of a matrix or records of a UPI transaction file.

Functional or task decomposition splits the operations. One task reads input, another filters, another aggregates, another writes results. The tasks may run on different data or pass data in a stream.

Recursive decomposition applies divide and conquer. A task splits into smaller tasks until a base case. A merge sort on 8 numbers can split into two halves, then four quarters, giving a tree of tasks.

Pipeline decomposition gives each stage to a different worker. Stage 1 reads, stage 2 validates, stage 3 scores. Items move through stages like cars on an assembly line. This works when many items arrive and stages can overlap.

Dependence graph, granularity and cost

A dependence graph shows tasks as nodes and dependencies as directed edges. If task B needs A's output, an edge A → B exists. B cannot start before A finishes. A chain of edges creates a critical path; its length sets a lower bound on parallel time even with unlimited processors.

Granularity is the amount of work in one task. Coarse tasks are few and large; fine tasks are many and small. Fine tasks give more choices for balancing but add communication and scheduling cost. A task of 50 ms with 1 ms message cost is coarse enough; a task of 2 ms with 1 ms message cost is usually too fine.

Communication cost is the time a task spends sending or receiving data. It includes message start-up, transfer and waiting. If a task waits for a message, that wait appears as idle time even when the processor has no ready task.

T = max(load₁, load₂, …, load_P),   E = W ÷ (P × T),   idle = P × T − W

T is makespan in ms; load_i is the total task time on processor i in ms; W is total work in ms; P is the number of processors; E is efficiency as a fraction between 0 and 1; idle is total idle processor time in ms.

Load imbalance = (maximum load − average load) ÷ average load. Average load is W ÷ P. A small imbalance means processors finish close together.

Mapping tasks to processors

Mapping assigns tasks to processors. Static mapping fixes the assignment before the run. It is cheap and works when task times are known and equal. Dynamic mapping decides at run time, so it handles unequal tasks and sudden slowdowns. This mapping is not the operating system's CPU scheduler; it is the parallel program's or runtime's task placement.

Block distribution gives each processor one contiguous chunk. With 8 tasks and 3 processors, Proc 1 gets T1–T3, Proc 2 gets T4–T6, Proc 3 gets T7–T8. Block is good when neighbouring tasks share data. With unequal tasks, block can be bad: times 8, 1, 1, 1, 1, 1, 1, 1 ms give block loads 11 and 4 ms on two processors; cyclic or dynamic mapping spreads the 8 ms task better.

Cyclic distribution gives task i to processor i mod P. With 8 tasks and 3 processors, Proc 1 gets T1, T4, T7; Proc 2 gets T2, T5, T8; Proc 3 gets T3, T6. Cyclic spreads a heavy task among processors but hurts locality.

Block-cyclic distribution uses blocks of size b in round-robin order. b = 1 is cyclic; b ≥ n/P is block. It balances locality and spread.

Master-worker is a dynamic method. A master holds a queue and gives the next task to a free worker. Work stealing lets an idle worker take a task from another worker's queue. Guided scheduling gives large chunks first and smaller chunks later, reducing queue overhead near the end.

Worked example

Question. Eight tasks T1 to T8 each take 5 ms. They run on three processors under static block distribution in task order. Find the makespan, total work, total capacity, efficiency, idle time and load imbalance. Use maximum load and average load for the imbalance.

  1. Total work W = 8 tasks × 5 ms = 40 ms.
  2. Block distribution: Proc 1 gets T1–T3, so load₁ = 3 × 5 = 15 ms. Proc 2 gets T4–T6, so load₂ = 3 × 5 = 15 ms. Proc 3 gets T7–T8, so load₃ = 2 × 5 = 10 ms.
  3. Makespan T = max(15, 15, 10) = 15 ms.
  4. Capacity = P × T = 3 × 15 = 45 ms.
  5. Efficiency E = W ÷ (P × T) = 40 ÷ 45 = 0.888… ≈ 0.889.
  6. Idle time = capacity − W = 45 − 40 = 5 ms. Proc 3 is idle from 10 ms to 15 ms.
  7. Average load = W ÷ P = 40 ÷ 3 = 13.333 ms. Maximum load = 15 ms. Load imbalance = (15 − 13.333) ÷ 13.333 = 0.125 = 12.5%.

  • Equal task counts do not guarantee balance when tasks have different sizes or dependencies.
  • Block and cyclic are not the same. Block gives contiguous chunks; cyclic gives round-robin single tasks.
  • Communication cost belongs in the schedule. A task that waits on a message is idle even if its processor has no work.
  • Dynamic balancing is not free. Queue access, task migration and work stealing add overhead; on tiny tasks this can erase the gain.

1.8 Data parallelism and model parallelism

Data parallelism and model parallelism are two ways to spread one machine-learning job over several devices. Data parallelism copies the model to every device and sends each device a different slice of the batch. Model parallelism does the opposite: it keeps the data whole and cuts the model into pieces. Both appear in GPU training, and both echo older ideas: data parallelism is SIMD at a larger scale, and model parallelism is a pipeline. The choice decides speed, memory use and link traffic.

You need: Flynn's SIMD model, shared and distributed memory, and decomposition and load balancing.

Data parallelism: same code, different data

Data parallelism runs the same code on different data. The simplest form is a vector add, c[i] = a[i] + b[i]: one instruction stream, many data lanes. Flynn calls this SIMD, and GPU lanes and CPU vector units implement it in hardware. In training, the data is a mini-batch. With batch B and P devices, each device gets B_dev = B ÷ P examples. Each device holds a full copy of the model. It runs forward and backward on its slice and produces a gradient vector. An all-reduce sums or averages these vectors across devices, so every replica applies the same update. The cost per step is compute plus one gradient exchange. Data parallelism is the default when the model, gradients and optimizer state fit on one device. Its weakness is that the full model must fit everywhere, and the all-reduce grows with the number of parameters. Shared-memory threads use Pthreads or OpenMP; clusters use MPI; GPUs use CUDA or OpenCL. Unit 3 gives the syntax; here the point is the mapping of data to devices.

B_dev = B ÷ P

B_dev is the number of examples per device; B is the global batch size in examples; P is the number of replicas (devices).

Model parallelism: split the model

Model parallelism splits the model, not the batch. In pipeline parallelism, layers are grouped into stages and each stage sits on a different device. Device 0 runs layers 1–6, device 1 runs layers 7–12; the activation of layer 6 is sent over the link to device 1. During backpropagation, gradients travel the other way. The first output is delayed by every stage and every link: T_first = t₁ + t_link + t₂ for two stages. After the pipeline fills, a new micro-batch leaves every max(t₁, t_link, t₂). The start-up and drain periods are pipeline bubbles, when some devices idle. Tensor parallelism is finer: one layer's weight matrix is split by rows or columns, and devices combine partial results inside the layer. Model parallelism lets a model larger than one device's memory run at all. The price is communication at every stage boundary and possible idle time. It suits small micro-batches and fast interconnects.

T_first = t₁ + t_link + t₂,   T_steady = max(t₁, t_link, t₂)

t₁ and t₂ are stage compute times in ms; t_link is the activation transfer time in ms; T_first is the time to the first output in ms; T_steady is the interval between later micro-batches in ms.

Choosing between them

Use data parallelism when the model fits on one device and the batch can be large. Use model parallelism when the model does not fit, or when one layer is too large for one device. The table compares the main pressures.

PressureData parallelModel parallel
Model memoryFull model on every deviceModel split across devices
BatchNeeds a large global batchWorks with small micro-batches
Link trafficGradients once per stepActivations at every stage
Idle timeSmallPipeline bubbles
Best caseModel fits, fast linkModel too large, fast link

Hybrid parallelism combines both: a group of devices splits the model, and several such groups process different batch slices. For example, 2-way tensor parallelism inside a group and 4-way data parallelism across groups uses 8 devices and gives 4 model replicas. The best split depends on link bandwidth, batch size and the memory per device. Measure before choosing.

Worked example

Question. A batch of 64 images trains a 12-layer network on 2 GPUs. Data parallel: each GPU gets 32 images and the full model. One step takes 80 ms of compute plus 10 ms for the gradient all-reduce. Model parallel: layers 1–6 run on GPU 0 and layers 7–12 on GPU 1; each half computes in 40 ms per micro-batch, and a 100 MB activation crosses the link in 30 ms. Find (a) the data-parallel step time and throughput in images/ms, (b) the model-parallel time to first output and the steady interval between micro-batches.

  1. Data parallel slice: each GPU gets 64 ÷ 2 = 32 images.
  2. Data parallel step time: 80 ms compute + 10 ms gradient all-reduce = 90 ms.
  3. Data parallel throughput: 64 images ÷ 90 ms = 0.711 images/ms, or 711 images/s.
  4. Model parallel first output: stage 0 takes 40 ms, the activation takes 30 ms on the link, stage 1 takes 40 ms, total 40 + 30 + 40 = 110 ms.
  5. Model parallel steady interval: stages overlap on different micro-batches, so the slower of 40 ms compute and 30 ms link sets the pace: max(40, 30) = 40 ms per micro-batch.
  6. If one micro-batch is one image, steady throughput = 1 ÷ 40 ms = 0.025 images/ms = 25 images/s. Data parallel is about 28 times faster here because the model fits and the batch is large.

Answer. Data parallel: 90 ms per step and 0.711 images/ms (711 images/s). Model parallel: first output at 110 ms, then one micro-batch every 40 ms (0.025 images/ms or 25 images/s for one-image micro-batches).

Exam traps

  • Data parallelism does not split the model. Every replica holds the full model, gradients and optimizer state, so it fails when the model does not fit on one device.
  • Model parallelism is not free memory: it adds activation messages at every stage boundary and can leave devices idle in pipeline bubbles.
  • Do not report the first output time of a pipeline as its throughput. The first output includes fill time; steady throughput uses the interval between outputs.
  • Match units: ms and s, images/ms and images/s. A throughput of 0.711 images/ms is 711 images/s, not 0.711 images/s.
  • Data parallel all-reduce averages gradients, not weights; each replica then applies the same update. Averaging weights after separate updates is not the same algorithm.

Check yourself

Remember Define data parallelism in one sentence. 2 marks

Data parallelism keeps the same model and code on every device and gives each device a different slice of the input data.

Understand Why does data parallelism match Flynn's SIMD model? 3 marks

SIMD applies one instruction stream to many data lanes at once. Data parallelism applies one training program to many examples at once, one slice per device, so the same operation runs on different data in parallel.

Apply A batch of 128 images is split over 8 GPUs in data parallelism. How many images per GPU? 2 marks

128 ÷ 8 = 16 images per GPU.

Analyze A model-parallel pipeline has first output at 110 ms and steady interval 40 ms. Explain why these two numbers differ and which one a user notices in a long training run. 4 marks

The first output includes the fill time of all stages and links, so it is larger. After the pipeline fills, stages work on different micro-batches and a new output leaves every slowest stage or link, 40 ms. A long run is dominated by the steady interval, so throughput uses 40 ms, not 110 ms.

Apply A data-parallel step has 70 ms of compute and 20 ms for the all-reduce. What is the throughput for a batch of 64 images? 3 marks

Step time = 70 + 20 = 90 ms. Throughput = 64 ÷ 90 = 0.711 images/ms.

Analyze Give two conditions that favour model parallelism over data parallelism. 4 marks

The model, gradients and optimizer state do not fit on one device; or one layer is too large for one device. A small batch or a fast link between devices also makes model parallelism more attractive.

Remember What is a pipeline bubble? 2 marks

A pipeline bubble is the idle time at the start or end of a pipeline, when some stages have no work because the pipeline is filling or draining.

Apply A hybrid job uses 2-way tensor parallelism and 4-way data parallelism. How many devices and how many model replicas? 3 marks

Devices = 2 × 4 = 8. Model replicas = 4, one per data-parallel group.

Takeaways

  1. Time and problem size are the two pressures that push computing from one core to many.
  2. Flynn's four boxes are a coarse label: SISD, SIMD, MISD and MIMD; almost every modern server is MIMD.
  3. Shared memory is easy to program and hard to scale; distributed memory scales and forces you to think in messages.
  4. PRAM is not a machine you buy, it is a measuring stick for how much parallelism an algorithm really contains.
  5. An interconnection network is a set of trade-offs: more links per node buys a smaller diameter at a higher wiring cost.
  6. Speedup is bounded by the sequential part of the code, so efficiency falls as you add processors beyond the useful point.
  7. Good decomposition plus good mapping beats a faster machine on a badly split problem.
  8. Data parallelism splits the work, model parallelism splits the network; large training jobs usually need both.

Glossary

All-reduce
A collective in which every process ends with the same combined value, such as a summed gradient.
Amdahl's law
The speedup bound set by the serial fraction of the program.
Cache coherence
The rule that keeps copies of a memory word in several caches consistent.
Concurrency
Several activities that may overlap in time but need not run on separate hardware.
CRCW
Concurrent Read, Concurrent Write: several processors may write one cell in a step, under a stated rule.
Cube-connected cycles
A hypercube in which each node is replaced by a cycle, giving constant degree and logarithmic diameter.
Dataflow
A computation style in which an instruction fires as soon as its input values arrive.
Decomposition
The step of breaking a problem into tasks that can run independently.
Fully connected network
Every node joined directly to every other; degree N−1 and diameter 1.
Grain size
The amount of computation in one task; coarse grain means few large tasks.
Interconnection network
The set of links and switches that moves data between processors or between processors and memory.
Link
A single communication channel joining two nodes.
Mapping
The step of assigning tasks to processors so that work and communication stay balanced.
Message passing
Communication in which one process sends a buffer and another process receives it.
MIMD
Independent processors each running their own instruction stream on their own data.
Node
One processor with its memory and its network connection point.
NUMA
Non-Uniform Memory Access: a processor reaches its local memory faster than remote memory.
Parallelism
Doing several pieces of work at the same time on separate hardware units.
Perfect shuffle
A fixed permutation that splits the address bits and interleaves them, used between butterfly stages.
PRAM step
One round in which every processor reads, computes and writes in lockstep.
Routing
Choosing the path a message follows through a network.
Scalability
How well performance keeps growing as processors and problem size increase together.
SIMD
One instruction stream applied to many data items at once.
SISD
A single processor executing one instruction stream on one data stream, the classical von Neumann machine.
Superlinear speedup
Speedup larger than p, usually from extra cache or a search that prunes more work.
UMA
Uniform Memory Access: every processor reaches every memory word in about the same time.
