2.1 Parallel matrix transpose

Parallel matrix transpose rearranges an n×n matrix a so that row i becomes column i. For every i<j, a[i][j] and a[j][i] swap; diagonal cells stay. The in-place sequential version does n(n−1) reads and n(n−1) writes, which is Θ(n²). It does no arithmetic: the cost is data movement. On a PRAM with n² processors all n(n−1)/2 off-diagonal pairs swap in one step. On a mesh the same work takes O(n) steps because cells must walk. Transpose is used in linear algebra, image processing, graph adjacency matrices and communication libraries. It also prepares data for products such as parallel matrix multiplication.

You need: the PRAM and mesh models from Unit 1 and row-major storage of a 2-D array.

Definition and PRAM cost

Take an n×n matrix a with row index i and column index j. Transposing a in place makes row i become column i. For every i<j, swap a[i][j] with a[j][i]. Diagonal cells a[i][i] stay. For n=3, a(0,1)=2 swaps with a(1,0)=4. Sequential in-place code reads the two cells of each pair and writes them back: n(n−1) reads and n(n−1) writes, which is Θ(n²). It performs no addition or multiplication, so arithmetic is zero and the whole cost is data movement.

On a PRAM with n² processors, give one processor to each cell. A processor at (i,j) with i<j reads a[i][j] and a[j][i], then writes the two cells swapped. Processors on the diagonal do nothing. All n(n−1)/2 unordered off-diagonal pairs act in the same step. The pair count is n(n−1)/2 because the diagonal is excluded and each unordered pair is counted once. Parallel time is O(1), assuming free routing. Work is n(n−1) reads plus n(n−1) writes, which is Θ(n²), the same as sequential, so the algorithm is work-optimal.

Mesh and blocked hypercube

On a mesh, routing is not free. Place the n² cells on an n×n mesh, one per processor. A cell can move only to a neighbour in one step. A standard mesh transpose routes cells by row and column rotations: each cell walks along its row, then along its column, using offsets so no two cells collide. A cell travels at most 2n hops, so the parallel time is O(n). Thus the PRAM O(1) and mesh O(n) costs differ only because of routing, not because of extra arithmetic.

The blocked hypercube version works on blocks. Assume n = 2k. Cut the matrix into four n/2×n/2 blocks: top-left A, top-right B, bottom-left C, bottom-right D. The block transpose is [[Aᵀ,Cᵀ],[Bᵀ,Dᵀ]]. In place, exchange B and C with transposition: B becomes Cᵀ and C becomes Bᵀ; then transpose A and D recursively. Equivalently, swap B and C as whole blocks, then recursively transpose all four blocks. On a hypercube laid out so each block maps to a subcube, each recursion level exchanges two off-diagonal blocks between cube neighbours. There are k = log₂ n levels. The off-diagonal elements moved total n(n−1) = Θ(n²), so transpose is work-optimal. For general n, pad the matrix to the next power of two or handle uneven blocks.

Worked example

Question. Transpose A = [[1,2,3],[4,5,6],[7,8,9]] on 9 PRAM processors, one per cell. List the swapping pairs and the cells that stay. Give the PRAM step count, the number of swapping pairs, and the total reads and writes.

  1. Index cells row-major: a(0,0)=1, a(0,1)=2, a(0,2)=3, a(1,0)=4, a(1,1)=5, a(1,2)=6, a(2,0)=7, a(2,1)=8, a(2,2)=9.
  2. Use only pairs with i<j. Pair (0,1)-(1,0) swaps 2 and 4. Pair (0,2)-(2,0) swaps 3 and 7. Pair (1,2)-(2,1) swaps 6 and 8.
  3. Diagonal cells (0,0)=1, (1,1)=5, (2,2)=9 stay.
  4. One processor handles each pair. Three processors swap in the same PRAM step, so parallel time is 1 step.
  5. Each pair does 2 reads and 2 writes. Totals: 3×2=6 reads and 3×2=6 writes. The diagonal does no read or write in this scheme.

Answer. The PRAM transpose takes 1 step, uses 3 swapping pairs, and performs 6 reads and 6 writes.

Exam traps

  • O(1) PRAM time assumes free routing. On a mesh the same n²-processor transpose takes O(n) steps.
  • Each unordered pair must be handled by exactly one processor. If both (i,j) and (j,i) write both cells, the cost doubles and races appear.
  • The diagonal never swaps. a[i][i] = a[i][i], so writing it again is redundant and can create a race.
  • The pair count n(n−1)/2 is not the work. In place, work is n(n−1) reads plus n(n−1) writes, which is Θ(n²); the pair count is half the off-diagonal cells.
  • Transpose is not matrix multiplication. There is no dot product; b[i][j] copies a[j][i].

2.2 Parallel matrix and matrix-vector multiplication

A matrix product is a grid of dot products. Each output cell uses one row of A and one column of B, and no output cell needs another. That independence is why parallel machines are good at matrix work: hand each cell to a processor, or hand each product term to a processor, and the arithmetic spreads out. The same idea drives graphics transforms, training neural networks, solving linear equations, and ranking pages. This chapter counts the steps for three processor budgets and for the matrix-vector case.

You need: Chapter 2.1 for column access to B, and Unit 1 for the PRAM cost model and the speedup definition.

A product is a grid of dot products

For n×n matrices A and B, the product C = A×B is also n×n. Its entry in row i and column j is c[i][j] = Σ(k=0 to n−1) a[i][k]·b[k][j]. Here a[i][k] is the entry of A in row i, column k; b[k][j] is the entry of B in row k, column j; n is the number of rows and columns; and k is the dummy index that walks across the row and down the column.

c[i][j] = Σ(k=0 to n−1) a[i][k]·b[k][j]

c[i][j] is the output cell in row i, column j; a[i][k] and b[k][j] are input entries; n is the matrix size.

Read the formula as one dot product. Take row i of A and column j of B, multiply the first pair, the second pair, and so on, then add the n products. Each c[i][j] is independent of every other c. The processor for c₁₁ never waits for c₁₂. That is the whole source of parallelism: the output grid has n² cells, and each cell is a length-n job.

Column access matters. A row of A is stored next to itself; a column of B is strided in row-major storage. Fetching b[k][j] for k=0,...,n−1 touches one element per row of B, so the memory system sees a stride of n elements. Parallel transpose in Chapter 2.1 rearranges B when repeated column reads cost too much.

Three processor budgets

With n³ processors, give one processor to each product term a[i][k]·b[k][j]. The n terms for a fixed output cell sit in a tree. Pairs multiply, then pairs of products add, and the fan-in finishes in log₂ n steps. The work is n³ multiplications plus n³−n² additions, but the parallel time is O(log n).

With n² processors, give one processor to each output cell. That processor reads a whole row of A and a whole column of B and runs the dot product itself. It does n multiplications and n−1 additions, so parallel time is O(n). This is the usual exam case because n² is practical for small n.

With p processors, where p can be less than n², split the n² output cells over p processors. The total arithmetic is n³ multiplications, so the time is Θ(n³/p); uneven division adds at most one extra cell, that is n extra steps, which does not change the order when p ≤ n². Load balance matters for the constant factor. Better load balance comes from blocked storage (each processor owns a square submatrix of C) or striped storage (processor q owns output cells q, q+p, q+2p, ...).

T_p = O(n³/p)

T_p is parallel time with p processors; n is matrix size; p is processor count.

On an n×n mesh, use broadcast instead of long dot products. In step k, send a[i][k] along row i and b[k][j] down column j. Cell (i,j) receives one pair, multiplies, and adds to its running c[i][j]. Every cell does one multiply-add per step, so n steps finish the product. Cannon's algorithm is a different mesh schedule, in which blocks are skewed at the start and then, in each of n rounds, every cell does one multiply-add and passes its A value one step left and its B value one step up.

Matrix-vector and the speedup limit

For y = A·x, the output is a vector, not a grid. Entry y[i] = Σ(j=0 to n−1) a[i][j]·x[j]. Here x is the input vector with entries x[j], and y[i] is the output entry for row i. There are only n output entries, so the natural processor count is n, one per y[i].

The vector x must be broadcast to every processor before the dot products start. A broadcast copies one value to all p processors in log p steps; Chapter 2.3 gives that procedure. After the broadcast, each y[i] needs a fan-in sum of log n steps if its n products are spread over n processors. With one processor per row, each row does n multiply-adds and the time is O(n), not O(log n).

A simple speedup model for the n²-processor matrix product adds the fan-in cost to the arithmetic cost: S = n³ / (n³/p + log p). The numerator n³ is the serial multiplication count; n³/p is the arithmetic time with p processors; log p is the fan-in or reduction overhead; S is speedup, the serial time divided by parallel time. Early on, n³/p dominates, so S grows almost linearly with p. S saturates when n³/p becomes comparable to log p; after that, more processors mostly add communication, and the curve flattens.

Worked example

Question. Let A = [[2,1],[3,4]] and B = [[5,6],[7,8]]. Use four processors, one per output cell of C = A×B. (a) Compute all four entries of C. (b) State the number of multiplications and the parallel time in multiply-add steps. (c) For x = (2,3), compute y = A·x and state what must happen to x before the row dot products.

  1. Matrix size n = 2 and processor count p = 4 = n², so each output cell gets one processor.
  2. c₁₁ = row 1 of A · column 1 of B = 2×5 + 1×7 = 10 + 7 = 17.
  3. c₁₂ = row 1 of A · column 2 of B = 2×6 + 1×8 = 12 + 8 = 20.
  4. c₂₁ = row 2 of A · column 1 of B = 3×5 + 4×7 = 15 + 28 = 43.
  5. c₂₂ = row 2 of A · column 2 of B = 3×6 + 4×8 = 18 + 32 = 50.
  6. Each processor does n = 2 multiplications and n−1 = 1 addition. Parallel time is 2 multiply-add steps. Total work is 4 cells × 2 = 8 multiplications.
  7. y₁ = 2×2 + 1×3 = 4 + 3 = 7.
  8. y₂ = 3×2 + 4×3 = 6 + 12 = 18.
  9. The vector y has n = 2 entries, so two processors, one per row of A, each need every entry of x; x is broadcast to those two before the row dot products start.

Answer. C = [[17,20],[43,50]], y = (7,18), with 8 multiplications and parallel time 2 multiply-add steps; x is broadcast first.

Exam traps

  • Writing speedup S = n² (= p) when p = n², as if the dot products cost only their multiplications. The model S = n³/(n³/p + log p) gives S ≈ n³/(n + log n²), a little below n², because the reduction and vector-broadcast overhead sit in the denominator.
  • Using time n when p < n². If processors hold several output cells, time is n³/p, and uneven division lets the slowest processor set the time.
  • Mixing n³ and n². n³ is the number of product terms, one per multiplication; n² is the number of output cells, one per dot product.
  • Forgetting that B is read by column in the row-column method. Row-major storage makes that a strided access, not a contiguous one.
  • Treating the mesh broadcast as free. The mesh needs n rounds, and each cell adds one arriving product into a running value per round.

2.3 Broadcasting and computing prefix sums

Broadcasting copies one value from one processor to every other processor. Prefix sums, also called scan, give every element the running total of all elements up to and including it. (Some texts use the exclusive form, which leaves out the element itself and starts from x₀ = 0.) In this chapter y_i is the inclusive form. Both use a doubling idea: in broadcast the number of holders doubles each step; in scan the length of the summed block doubles from d to 2d each step. A broadcast finishes in ⌈log₂ p⌉ steps; a scan finishes in ⌈log₂ n⌉ steps. Scan appears in ranking, stream compaction, radix sort and load balancing. The simple scan is fast but does too much total work, so a two-level version restores work-optimality.

You need: tree and hypercube networks, parallel time and work, and log₂ notation from Unit 1, Foundations; 2.1 shows why data movement can set parallel cost.

One value to all processors

Broadcast means one processor, called the root, holds a datum d and every one of the p processors needs a copy. On a tree network the root sends d to its children. Each child repeats the send to its own children. After one step two processors hold d, after two steps four hold it, and after k steps 2^k hold it. So every processor has d in ⌈log₂ p⌉ steps. The root may be any processor; the step count does not depend on which one.

On a hypercube the same doubling works dimension by dimension: at step k a holder sends along dimension k, and the number of holders doubles. All-to-all broadcast uses the same idea, but each processor starts with its own datum and every processor finishes with all p data; recursive doubling combines larger and larger groups. Broadcast carries a pivot, a block total or a termination signal, so it appears inside selection, sorting and graph algorithms.

Prefix sums by doubling

Prefix sums, also called scan or all-prefix-sums, start with x₀, x₁, …, x_{n−1} and produce running totals. The last output y_{n−1} is the total of all inputs. A sequential loop uses n−1 additions.

y_i = x₀ + x₁ + … + x_i

y_i is the prefix sum at index i; x_j is the input at index j, for 0 ≤ j ≤ i.

The parallel doubling algorithm keeps a working array a, initially equal to x. At step d = 1, 2, 4, … every element with index i ≥ d sets a_i = a_i + a_{i−d}, using the values from before the step. For i ≥ d, after step d the value at i is the sum of the original block of length d+1 ending at i. After ⌈log₂ n⌉ steps every a_i is y_i. The parallel time is ⌈log₂ n⌉ steps.

W = n⌈log₂ n⌉

W is the doubling scan's work in addition slots; n is the number of elements.

At step d, n−d elements do useful additions, but the simple cost count treats all n elements as active, giving n⌈log₂ n⌉ addition slots. That is Θ(n log₂ n) work, so the doubling scan is fast but not work-optimal. Every element must read old values, so use a barrier or a double buffer; otherwise an updated neighbour is read too early.

Two-level scan that stays work-optimal

The two-level scan restores work-optimality. Split the n elements into p contiguous blocks of about n/p elements, one block per processor. Each processor scans its block sequentially and keeps the block total. Now the p block totals are prefix summed among the processors; doubling takes ⌈log₂ p⌉ steps. Each processor receives the sum of all block totals before its block, called its offset. It adds that offset to every element in its block. For p ≤ n this beats the simple doubling scan in work.

T_p = O(n/p + log₂ p)

T_p is parallel time with p processors; n is the number of elements.

The total work is W = O(n + p log₂ p), which is O(n) when p is at most about n/log₂ n; alternatively one processor scans the p block totals sequentially in O(p) time, giving W = Θ(n) for p ≤ n. The two-level scan is the version used for ranking, stream compaction, counting, radix sort, quicksort partitioning and load balancing.

Worked example

Question. Take x = [3, 1, 4, 1, 5, 9, 2, 6] with n = 8, one element per processor. (a) Run the doubling prefix-sum algorithm and write the array after d = 1, d = 2 and d = 4. (b) Give the final prefix sums. (c) State the parallel time in steps. (d) Count the sequential additions, the doubling addition slots and the active additions; decide whether the doubling scan is work-optimal.

  1. Start: a = [3, 1, 4, 1, 5, 9, 2, 6]. At d = 1 every i ≥ 1 adds the old value at i−1: a becomes [3, 1+3=4, 4+1=5, 1+4=5, 5+1=6, 9+5=14, 2+9=11, 6+2=8].
  2. At d = 2 every i ≥ 2 adds the old value at i−2: [3, 4, 5+3=8, 5+4=9, 6+5=11, 14+5=19, 11+6=17, 8+14=22].
  3. At d = 4 every i ≥ 4 adds the old value at i−4: [3, 4, 8, 9, 11+3=14, 19+4=23, 17+8=25, 22+9=31].
  4. Final prefix sums y = [3, 4, 8, 9, 14, 23, 25, 31]. Check: 3+1+4+1+5+9+2+6 = 31, the last cell.
  5. Parallel time = ⌈log₂ 8⌉ = 3 steps.
  6. Sequential additions = n−1 = 7.
  7. Active additions in doubling: step d=1 has 7, d=2 has 6, d=4 has 4; total 17. Addition slots if all n elements are counted each step: 8×3 = 24.
  8. Work is Θ(n log₂ n), not Θ(n), so the doubling scan is not work-optimal.

Answer. The final prefix sums are [3, 4, 8, 9, 14, 23, 25, 31]; parallel time is 3 steps, sequential work is 7 additions, doubling uses 24 addition slots or 17 active additions, so it is not work-optimal.

Exam traps

  • Updating in place and then reading new values: at step d every element must read the old value at i−d, so a barrier or a double buffer is needed.
  • Calling the doubling scan work-optimal: it uses n⌈log₂ n⌉ addition slots, which is Θ(n log₂ n), not O(n).
  • Swapping p and n: broadcast counts processors p, while prefix sums count elements n. The step counts are ⌈log₂ p⌉ and ⌈log₂ n⌉.
  • Reporting only the total: the prefix-sum output has n values, y₀ … y_{n−1}; the total is only y_{n−1}.
  • The favourite exam question asks for the array after every d, not only the final answer. Show each row and state which old values are added.

2.4 Parallel selection and searching

Selection takes n keys in any order and an integer k, and returns the k-th smallest. Searching takes sorted keys and one key x, and returns its position or reports it absent. Both discard data: one comparison decides which part can be thrown away. With p processors discarding different parts at once, the range shrinks faster and the steps fall. Databases use this for ORDER BY ... LIMIT and for medians; sorted-index lookups such as a railway timetable search use it too.

You need the PRAM cost model and the EREW/CRCW variants from Unit 1, plus broadcast from Chapter 2.3.

Selection: the k-th smallest key

Selection takes n keys in any order and an integer k with 1 ≤ k ≤ n, and returns the key that would sit at position k if the keys were sorted. The keys are never sorted.

Sequential quickselect picks a pivot, splits by it, and recurses into the one side holding rank k. Expected time O(n); worst case O(n²), when every round drops one key.

The parallel version picks the pivot from p samples, so the split stays balanced for any input.

  1. Processor j takes block j of about n/p keys and returns its median: the key at position ⌈m/2⌉ of its m keys.
  2. Sort the p medians and take the one at position ⌈p/2⌉. That key is the pivot.
  3. Broadcast the pivot to all processors.
  4. Each processor counts keys below the pivot in its block. A prefix sum over the p counts gives the number of keys below the pivot; the pivot's rank is r = that count + 1.
  5. If r = k, return the pivot. If k < r, keep the keys below the pivot, leave k unchanged, and repeat on the survivors. If k > r, keep the keys above the pivot, replace k by k − r, and repeat on the survivors.
T_p = Θ(log n) when p = n;  W = Θ(n) total work over all rounds

T_p is the parallel time with p processors, W is the total work (all processor steps added over all rounds), and n is the number of keys. The round sizes n, 3n/4, 9n/16, … sum to 4n. The product p · T_p = Θ(n log n) is only the processor-time product: it counts processors sitting idle in later rounds, so it is not the work.

The pivot is never extreme. At least ⌈p/2⌉ block medians are ≤ the pivot, and each of those blocks has at least ⌈m/2⌉ keys ≤ its own median, so at least (p/2)(m/2) = n/4 keys are ≤ the pivot. The same argument gives at least n/4 keys ≥ the pivot, so each round keeps at most 3n/4 keys and O(log n) rounds finish.

Ranking by enumeration avoids pivots: each key is compared with every other key in parallel and counts how many are smaller; the key with count k − 1 is the answer. Work O(n²), time O(n) with n processors.

Searching a sorted array with p processors

Searching takes a sorted array a[0..n−1] and a key x, and returns an index i with a[i] = x, or reports x absent. Binary search on one processor needs ⌈log₂(n+1)⌉ comparisons in the worst case.

Plan A, blocks. Cut the array into p equal blocks, one per processor. Processor j binary searches its own block in ⌈log₂(n/p + 1)⌉ comparisons, so the block search costs Θ(log(n/p)). Reading the p per-block answers is a combine step: O(1) with a concurrent read, or O(log p) as a reduction. The full time is Θ(log(n/p) + log p) = Θ(log n).

Plan B, p-ary search. In one parallel step the p processors compare x with p − 1 probes that cut the range into p equal parts. Only the part between the two probes that bracket x survives, so the length falls by a factor p.

S(n, p) = ⌈log_p(n+1)⌉ = O(log n / log p)

S is the number of parallel steps, n is the number of sorted keys, p is the number of processors, and each step costs one broadcast of x plus p − 1 comparisons done at the same instant.

So p-ary search trades work for time: p − 1 comparisons per step make the total work O(p log_p n). Block split keeps the work at O(p log(n/p)), but its speedup stops growing once n/p becomes small.

Worked example

Question. a = [3, 8, 12, 17, 21, 25, 29, 34, 38, 42, 47, 51, 55, 60, 66], n = 15, p = 4. (a) Find x = 42 by binary search and by 4-ary search, with the steps. (b) Select the k = 5 smallest key: give the block medians, the pivot, its rank, and how many keys are discarded.

  1. Binary search: mid = 7, a[7] = 34 < 42, so lo = 8. mid = 11, a[11] = 51 > 42, so hi = 10. mid = 9, a[9] = 42. Found at index 9 in 3 comparisons.
  2. 4-ary step 1: length 15, probes at 0 + 15//4 = 3, 0 + 30//4 = 7, 0 + 45//4 = 11, giving a[3] = 17, a[7] = 34, a[11] = 51. Since 34 < 42 ≤ 51, keep a[8..10].
  3. 4-ary step 2: length 3, probes at 8 + 3//4 = 8 and 8 + 6//4 = 9, giving a[8] = 38 < 42 and a[9] = 42. Found at index 9 in 2 steps.
  4. Block sizes: n//p = 3 with remainder 3, so the blocks hold 4, 4, 4, 3 keys: a[0..3], a[4..7], a[8..11], a[12..14]. Medians at position ⌈m/2⌉ are 8, 25, 42, 60.
  5. Median of the four medians is the 2nd smallest, 25. Pivot = 25; 5 keys (3, 8, 12, 17, 21) are below it, so its rank is r = 6.
  6. k = 5 < 6, so keep the 5 keys below 25 and discard the pivot with the 9 keys above it: 10 of 15 keys dropped. The 5th smallest of the survivors is 21.

Exam traps

  • Quoting the parallel time alone. With p = n the time is Θ(log n) and the work is Θ(n); the product p · T_p = Θ(n log n) is not the work.
  • Mixing selection with searching. Selection reads unsorted keys and returns a value by rank; searching needs sorted keys and returns a position.
  • Using ⌈log₂(n+1)⌉ where p-ary search needs ⌈log_p(n+1)⌉, and forgetting that each p-ary step does p − 1 comparisons, not one.
  • Reporting only O(log(n/p)) for block-split search. Dropping the combine step leaves the p per-block answers unread, so no answer is reported; the combine costs O(1) with a concurrent read or O(log p) as a reduction, giving Θ(log(n/p) + log p) = Θ(log n) in total.
  • Calling the median of the block medians the true median. It is a pivot with rank near the middle, usually not n/2.

Every processor must split its block against the same key. Different pivots would make the block counts incomparable and the prefix-sum rank meaningless.

Beyond the syllabus

Not for the exam. numpy.partition uses introselect, which falls back to a median-of-medians pivot when recursion runs deep. Databases run top-k selection over shards and merge the per-shard ranks. GPU libraries run multi-way search over sorted arrays for joins and for learned index lookups.

2.5 Sorting networks and parallel sorting algorithms

A sorting network is a fixed pattern of compare-exchange units wired between input and output wires. The pattern never changes with the data, so it suits hardware and SIMD machines. Parallel time is the network's depth: the longest chain of comparators from input to output. Networks sort in routers, GPUs and merge hardware.

You need Chapter 2.3 for broadcast, Chapter 2.4 for pivot selection, and Unit 1 for mesh and hypercube networks.

Comparators, size and depth

A comparator has two input wires and two output wires. An ascending comparator puts the smaller key on the top wire; a descending comparator reverses them. A sorting network is a fixed list of comparators, the same for every input: no branches, no data-dependent indices.

Size is the comparator count. Depth is the longest chain from input to output; all comparators in one stage run together, so depth is parallel time.

T = depth × t_cmp

T is parallel time; depth is the number of stages on the longest path; t_cmp is the delay of one comparator.

0-1 principle: a network sorts every input if and only if it sorts all 2ⁿ inputs of 0s and 1s. For n = 4, test all 16 binary inputs instead of testing a few sample key arrays.

Array sorts and networks

Odd-even transposition sort on a linear array of n processors alternates phases. Even phase compares (0,1), (2,3), ...; odd phase compares (1,2), (3,4), .... Run n phases, about n/2 comparators in parallel each, so time is O(n) with n processors.

Insertion sort on a linear array pipelines keys through in O(n) phases.

A bitonic sequence first increases and then decreases (cyclically, only one rise and one fall). Bitonic sort pairs elements with comparators in alternating directions to build bitonic sequences of length 2, 4, 8, …, then merges each bitonic sequence into a sorted one. For n = 2^k, depth is k(k+1)/2 = O(log² n), size O(n log² n).

Odd-even merge sort has the same depth k(k+1)/2 and the same O(n log² n) size, with a smaller comparator count, but its merge network is more intricate than the bitonic merge.

Enumeration sort ranks each key by counting smaller keys, using about n²/2 comparisons. On a CRCW machine with n² processors all pairs are compared in one step. The n comparison results of each key are then added, for example by a tree in O(log n) steps, giving O(log n) time with n² processors (O(n) time if only n processors are used).

Quicksort, hyperquicksort, mesh sort, merging

Parallel quicksort chooses a pivot, splits keys into smaller and larger sets, and recurses on both sets in parallel. Balanced pivots keep the recursion shallow; Chapter 2.4 covers pivot selection.

Hyperquicksort runs on a hypercube. Each processor sorts its block and broadcasts its local median. The median of these p local medians is chosen as the pivot and broadcast along the hypercube. Each processor then splits its own block around the pivot and sends one part to the partner in the other subcube, so each half holds about n/2 keys even though the split is not exact. The cube dimension drops by one. Expected time is O((n/p) log(n/p) + log² p) for p processors.

Mesh sort for n² keys on an n×n mesh: snake-order rows, sort rows, sort columns, sort rows. This takes O(n) steps.

Parallel merging on CREW/EREW: binary-search each key of A in B and each key of B in A to find its rank. Every key then writes once to its output position; each rank costs O(log n).

  3. Stage 3: (0,1) and (2,3) ascending give [1, 2, 3, 4].

  • Testing one input and declaring the network correct. Use the 0-1 principle: all 2ⁿ binary inputs.
  • Reporting size when asked for depth. Depth is parallel time; size is total work.
  • Forgetting the descending comparator in the first bitonic stage. The first half rises, the second falls.

2.6 Parallel solution of linear equations and root finding

Solving A·x = b, where A is an n×n coefficient matrix, x the unknown vector and b the known right side, appears in circuits, structures and graphics. Gaussian elimination clears one column at a time. At column k every row below the pivot changes by the same row operation, so all those rows update together. Root finding behaves similarly: many intervals or starting points can be tested at once. The work is to find independent arithmetic and isolate the broadcast that joins it.

You need: Chapter 2.2 for matrix-vector products and the speedup formula from Unit 1.

Elimination updates a whole column

At step k the entry a_kk is the pivot. For each row i below it, the multiplier is m_ik = a_ik / a_kk. The new row is row_i − m_ik·row_k. Every i = k+1, …, n uses the same old pivot row, so all these subtractions are independent. Each entry can be updated by its own processor; the inner work is the matrix row update from Chapter 2.2.

row_i ← row_i − m_ik·row_k,   m_ik = a_ik / a_kk

a_ik is the entry in row i, column k; a_kk is the pivot; row_k is the pivot row; m_ik is the multiplier that zeroes a_ik.

  1. Choose pivot row k.
  2. Compute all multipliers m_ik for i > k.
  3. Broadcast row k to every processor holding a lower row.
  4. Update all lower rows in parallel.
  5. Repeat for k = 1 to n−1.
  6. Back substitute from row n upward.

After n−1 steps A is upper triangular. Back substitution then finds x_n, x_{n−1}, …, x_1 in that order.

Broadcast, pivoting and many starts

The broadcast is a separate step. Using broadcast, it costs log n steps, so n−1 elimination steps plus communication give about n log n steps. With O(n²) processors the flop count is O(n³), the same as serial elimination. Counting only arithmetic, no work is wasted; but the total work including the log n broadcast per column is O(n³ log n), so the method is not work-optimal. The speedup is near n / log n unless each processor already holds the pivot row. Partial pivoting swaps in the row with the largest |a_ik| before dividing. This protects accuracy, but the swap rule must be fixed before comparing rounding.

Jacobi iteration is fully data-parallel: x_new = D⁻¹(b − (L+U)·x_old), where D is the diagonal, L the strict lower and U the strict upper part of A. Each sweep is one matrix-vector product, so it maps to Chapter 2.2. For f(x)=0, bisection can run on many sub-intervals at once; keep only intervals where f(a)·f(b) < 0. Newton's method can start from many points at once to reach different roots.

Worked example

Question. Solve the system x + y + z = 6, 2x + y + 3z = 13, x + 4y + z = 12 by Gaussian elimination. Identify the two multipliers at step 1 and state which row updates can run in parallel.

  1. Write the augmented matrix: row1 (1, 1, 1 | 6), row2 (2, 1, 3 | 13), row3 (1, 4, 1 | 12).
  2. Step 1 pivot is a_11 = 1. Multipliers: m21 = 2/1 = 2 and m31 = 1/1 = 1.
  3. Rows 2 and 3 update at the same time. row2 − 2·row1 = (0, −1, 1 | 1). row3 − 1·row1 = (0, 3, 0 | 6).
  4. Step 2 pivot is a_22 = −1. Multiplier m32 = 3/(−1) = −3.
  5. row3 − (−3)·row2 = row3 + 3·row2 = (0, 0, 3 | 9).
  6. Back substitution: 3z = 9 gives z = 3. Then −y + z = 1 gives y = 2. Then x + y + z = 6 gives x = 1.

Answer. x = 1, y = 2, z = 3; at step 1 the two multipliers are 2 and 1, and rows 2 and 3 update in parallel.

Exam traps

  • Counting the pivot broadcast as free; speedup is near n/log n, not n.
  • Dividing by a_kk = 0 without pivoting; partial pivoting swaps rows first.
  • Comparing two runs with different pivoting or rounding rules.
  • Assuming Jacobi always converges; it can diverge for some A.
  • Using bisection on an interval with two roots: f(a)·f(b) has no sign change, so the root is lost.

So x_new = D⁻¹(b − (L+U)x_old), one matrix-vector product per sweep; every component is independent, so the sweep is data-parallel.

Analyze Why can bisection test many intervals at once but still lose a root? 4 marks

Sign tests are independent, but an interval with two roots has no sign change and is discarded.

2.7 Parallel graph algorithms: connectivity and spanning trees

A graph is connected when a path joins every pair of vertices. A spanning tree uses n−1 edges to connect all n vertices with no cycle. Parallel algorithms for connectivity and spanning trees use rounds: every vertex or every component makes a local choice at the same time, then the choices are merged. This appears in network planning, chip wiring and clustering.

You need: Chapter 2.5 for sorting an edge list, and Unit 1 for the PRAM and network models that run the rounds.

Connectivity by shortcutting

Take G = (V, E), with n = |V| vertices and m = |E| edges. Store E as an adjacency list, which lists each vertex's neighbours, or as an n × n adjacency matrix, which marks edge (u, v). A connected component is a maximal set of vertices joined by paths.

  1. Give every vertex a parent pointer. Start with each vertex pointing to its lowest-numbered neighbour. Break a two-vertex cycle by keeping only the smaller vertex's choice, so every component has a root.
  2. In one round, every vertex replaces its pointer by its parent's pointer. This is pointer jumping: a pointer that was k steps from the root becomes about k/2 steps away.
  3. Repeat until every pointer points to the component root. Vertices with the same root are in one component.
  4. For a BFS tree from a chosen root, expand one level at a time: all vertices on the current frontier read their unvisited neighbours in the same round.
rounds = O(log n); work per round = O(n + m) with an adjacency list, O(n²) with an adjacency matrix

n is the number of vertices, m is the number of edges. Total work is rounds × per-round work.

Borůvka's spanning tree

Let each edge carry a weight. A minimum spanning tree (MST) is a spanning tree of least total weight. Borůvka's algorithm works in rounds. A component is a set of vertices already joined by chosen edges.

  1. For every component, find its minimum-weight outgoing edge: an edge with one end inside and one end outside.
  2. All components choose at the same time. Add the distinct chosen edges. If several choices repeat an edge, add it once.
  3. Hook the components joined by the new edges and contract each group into one supervertex. Edges inside a supervertex are discarded.
  4. Stop when one component remains; then the chosen edges form an MST.

rounds ≤ ⌈log₂ n⌉

n is the number of vertices. Every round at least halves the number of components, because each component picks an edge to another component.

Prim and Kruskal add one edge at a time, so each step depends on the previous. Their parallel versions work on the edge list but still need a global order. A BFS tree is a spanning tree for an unweighted graph; with weights it need not be an MST.

Worked example

Question. Use Borůvka's algorithm on vertices A–E with edges A–B 4, A–C 8, B–C 11, C–D 7, C–E 2, D–E 9. Give each round's picks, the components after the round, the final MST and its total weight, and the number of rounds.

  1. Round 1: A picks A–B (4); B picks A–B (4); C picks C–E (2); D picks C–D (7); E picks C–E (2).
  2. Distinct picks: A–B 4, C–E 2, C–D 7. Components: {A, B} and {C, D, E}.
  3. Round 2: outgoing edges from {A,B} are A–C 8 and B–C 11, so it picks A–C 8. {C,D,E} also picks A–C 8. Add A–C once.
  4. Now one component remains. Tree edges: A–B 4, C–E 2, C–D 7, A–C 8. Total = 4 + 2 + 7 + 8 = 21. Rounds = 2.

Answer. The MST is {A–B 4, C–E 2, C–D 7, A–C 8} with total weight 21, found in 2 rounds.

Exam traps

  • In Borůvka, adding an edge whose two ends are already in one component makes a cycle; check the component labels before adding.
  • O(log n) rounds of O(n + m) work each is O((n + m) log n) total work, not O(log n).
  • Borůvka may add several edges in one round; Kruskal adds one edge at a time, so Kruskal is the sequential comparison.
  • A BFS tree is a spanning tree for an unweighted graph; it need not be a minimum spanning tree when edges have weights.
  • Pointer jumping needs a root or cycle break; two vertices pointing at each other forever is not a root.

Long answers usually ask for a parallel algorithm, a step-by-step trace, and a time/work/cost analysis, often comparing PRAM, mesh, and network models.

Remember and understand

Understand Explain why parallel matrix transpose is a data-movement problem. For an n×n matrix, show that n(n−1)/2 off-diagonal pairs can be swapped simultaneously and state the parallel time with enough processors. 10 marks

Define Aᵀ[i][j] = A[j][i]; Count off-diagonal pairs: n(n−1)/2; Each pair is independent; swap all at once; Ideal PRAM time O(1); realistic cost is data movement O(n²/p).

Understand Describe broadcast by doubling and the prefix-sum scan. Derive the number of steps for p processors and n elements. 13 marks

Doubling distances 1,2,4,... give ⌈log₂ p⌉ steps; Inclusive prefix y_i = x₁+...+x_i; Recursive doubling on pairs gives O(log n) steps; Naive scan work O(n log n); two-level scan can be O(n).

Remember Define comparator, compare-exchange, sorting network, and depth. State the depth and comparator count of bitonic and odd-even merge networks. 12 marks

Comparator outputs two inputs in order; Network is fixed comparators; depth is longest comparator path; Bitonic: depth O(log² n), comparators O(n log² n); Odd-even merge: same order bounds; Depth is parallel time; comparator count is work.

Understand Explain the pivot and row-update step in Gaussian elimination. Why can all rows below the pivot update at the same time? 10 marks

At step k use A[k][k] as pivot; For each row i>k update row i using row k; Updates in different rows are independent; Parallel time per step O(n) with enough processors; n steps give O(n²) span.

Apply

Apply For n×n matrix multiplication on p processors with one output cell per processor, derive parallel time, total work, and cost. Compare with the sequential algorithm. 13 marks

C[i][j] = Σ_{k=1}^n A[i][k]B[k][j]; One dot product length n: time O(n); With p processors, time O(n³/p) if work balanced; Total work O(n³), same as sequential; Cost = p × T_p; speedup limited by work and communication.

Apply Design a two-level parallel prefix sum for n elements on p processors. Compute time and work, and give the condition for work-optimality. 14 marks

Each processor sums a block of n/p elements; Scan the p block sums; Add block prefix offsets to local elements; Time O(n/p + log p); Work O(n + p log p); work-optimal when p log p = O(n).

Apply Use p-way search to find a key in a sorted array of n elements. Derive the number of rounds and the speedup over binary search. 10 marks

Compare with p−1 split points per round; Keep one of p subranges; Rounds = ⌈log_p n⌉ = ⌈log₂ n / log₂ p⌉; Speedup over binary search about log₂ p if comparisons cost O(1); Mention load balance and communication.

Apply Construct a bitonic sorting network for n = 8. Show the comparator layers, total depth, and comparator count. 12 marks

Build bitonic sequences of length 2,4,8; Bitonic merge uses log₂ 8 = 3 layers; Total depth = 3(3+1)/2 = 6 layers; Comparator count = n/2 × depth = 4×6 = 24; Trace one input to show sorted output.

Apply Describe one parallel Boruvka step for minimum spanning tree. Show how components choose and merge cheapest edges, and analyze rounds. 12 marks

Each component finds minimum outgoing edge; All components add their chosen edge; At least two components merge per round; Rounds O(log n); Use union-find or contraction to relabel components.

Apply Parallelize Gaussian elimination for an n×n system on p processors. Give the time for forward elimination and back substitution, and state the total work. 14 marks

Pivot row k is broadcast; Rows below update in parallel: O(n) work per row; Elimination span O(n²) with n processors; general time O(n³/p); Back substitution span O(n²) if each row uses prior results; Total work O(n³).

Analyze and evaluate

Analyze Compare sorting on a linear array, on a mesh, and on an EREW SIMD PRAM. Discuss parallel time, work, and cost; identify which model gives work-optimal sorting. 16 marks

Linear array: nearest-neighbor moves; simple schemes need O(n) time and O(n²) work; Mesh: O(n) or O(√n log n) time depending on algorithm; good locality; EREW PRAM: O(log n) time with O(n log n) work for parallel merge sort; Cost = p × T_p; compare with O(n log n) sequential lower bound; Work-optimal means O(n log n) total work.

Evaluate A program transposes an n×n matrix and then multiplies it by an n×n matrix. Identify communication and computation bottlenecks, and propose a blocked parallel design. 14 marks

Transpose moves n² elements; multiplication does n³ arithmetic operations; Unblocked transpose causes scattered memory access; Blocked transpose improves locality and message size; Multiplication reuses blocks; one output cell per processor has O(n) dot product; Report time, work, cost; balance blocks to processors.

Evaluate Compare parallel selection with parallel root finding. Both discard candidates; discuss speedup limits, load balance, and when each is useful. 13 marks

Selection keeps one of p subranges per round; rounds O(log_p n); Root finding tests many intervals or starts; independent trials; Both suffer if one processor has much more work; Selection has data-dependent partitioning; root finding may need global convergence test; Speedup bounded by sequential fraction and communication.

Analyze Explain how parallel connectivity and spanning-tree algorithms use hooking and contraction. Analyze their rounds, work, and cost. 15 marks

Each vertex or component chooses a neighbor or cheapest edge; Hooking merges components; at least halving per round; Contraction builds a smaller graph; Rounds O(log n) for connectivity and Boruvka MST; Work depends on edge scanning; cost = p × T_p.

Glossary

Back substitution
Solving a triangular system from the last equation upward.
Binary search
Repeatedly halve a sorted range by comparing with its middle element.
Bitonic sequence
A sequence that first increases and then decreases, or can be rotated into that form.
Broadcast
A one-to-all communication that copies one value to every processor.
Comparator
A two-input unit that outputs its inputs in nondecreasing order.
Compare-exchange
A comparator operation that swaps two values if they are out of order.
Connected components
The maximal sets of vertices in which every pair has a path between them.
Cost
Parallel time multiplied by number of processors, compared with sequential time.
Depth
The maximum number of comparator layers from input to output in a network.
Dot product
The sum of products Σ a_k b_k of two equal-length vectors.
Exclusive scan
A prefix sum where y_i includes x₁,...,x_{i−1} but not x_i.
Gaussian elimination
A method that uses row operations to turn a linear system into triangular form.
In-place transpose
A transpose that uses only O(1) extra matrix space by swapping pairs.
Inclusive scan
A prefix sum where y_i includes x_i.
Minimum spanning tree
A spanning tree of a weighted graph whose total edge weight is as small as possible.
p-way search
A search that splits the range into p parts and keeps one part per round.
Pivot
The nonzero entry used to eliminate other entries in its column.
Prefix sum
A scan that turns x₁,...,x_n into all running totals.
Root finding
Computing a value x with f(x)=0 for a given function f.
Selection problem
The problem of finding the k-th smallest item in a set.
Sorting network
A fixed wiring of comparators that sorts every input of a given size.
Span
The time on an unlimited number of processors, also called critical path length.
Speedup
Sequential time divided by parallel time, S = T₁ / T_p.
Transpose
The matrix Aᵀ formed by swapping rows and columns, so Aᵀ[i][j] = A[j][i].
Work
The total number of basic operations performed by all processors.
Work-optimal algorithm
A parallel algorithm whose total work is within a constant factor of the best sequential work.
