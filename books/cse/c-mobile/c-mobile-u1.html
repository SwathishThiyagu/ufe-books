1.1 Mobile computing: characteristics, structure and applications

Mobile computing means computing by a user who is moving. The device changes its point of attachment to the network. Keeping a session alive across that change is the hard part. This drives the design: a small battery-powered host, a fading radio link, and a fixed network tracking the user. UPI payments, IRCTC bookings, telemedicine and fleet tracking rest on this structure. This chapter gives the definition, characteristics, three-part structure and applications.

You need only the basic idea that data travels in packets with addresses; radio details come later in wireless LANs.

Definition and characteristics

A mobile host is a computer that changes its point of attachment to the network. Keeping an open session alive across that change is the hard part. Mobility is the change of attachment; session continuity is the difficulty.

Wireless is not mobile. A desktop on Wi-Fi is wireless but never moves. A laptop plugged into a train's wired network keeps its session while the train moves, so it is mobile but not wireless.

  • Ubiquity: the user can compute from a bus, field or shop counter.
  • Location independence: the service follows the person; the address changes, the identity does not.
  • Adaptivity: the app adjusts to changing bandwidth, screen size and battery level.
  • Personalisation: one device, one owner, so content and alerts fit that person.
  • Connectivity: the user stays reachable, though the link drops in and out.
  • Constraint: small battery, modest CPU, small screen, metered data.

Structure: three parts and a middle layer

Every mobile system has three parts. The mobile host is the phone running the app. The radio access network is the first hop: a base station (BTS) for cellular, or a Wi-Fi access point. The fixed network is everything behind it plus servers holding data and business logic.

  1. The app on the mobile host builds a small request.
  2. The radio link carries it to the nearest base station or access point.
  3. Mobile middleware handles location, security and sync.
  4. The fixed network routes it to the server over IP.
  5. The reply returns along the same chain.

Middleware does three jobs. Location management answers where the user is now, so a reply reaches a host that has moved; see Mobile IP. Security covers authentication, air encryption and safe key storage. Synchronisation reconciles a local copy with the server after a coverage gap.

Heavy work such as location lookup, authentication and sync reconciliation runs on servers in the network. Small client pieces such as the sync client and key store sit on the handset. When the host leaves a cell, handover moves it without dropping the session; see handover and location tracking.

Where it is used

  • UPI payments: a few-kilobyte request reaches the payment server; the bank replies in under a second.
  • IRCTC ticketing: seat availability and booking from a moving train; the app caches the last view.
  • Telemedicine: a doctor reads a patient's report from a village clinic over a weak link.
  • Fleet tracking: a truck's GPS position is pushed to a control room every few minutes.

For interactive cases (payments, ticketing, telemedicine), delay matters more than data rate. Fleet tracking is delay-tolerant but needs the position to arrive reliably.

Worked example

Question. A UPI app on a phone sends a 2 KB request over a 4G link that runs at 5 Mbps. The one-way delay is 40 ms. Find the transmission time and total one-way time.

  1. 2 KB = 2048 bytes = 16 384 bits.
  2. 5 Mbps = 5 000 000 bit/s.
  3. Transmission time = 16 384 ÷ 5 000 000 = 3.2768 ms.
  4. Total one-way time = 3.2768 + 40 = 43.2768 ms.

Answer. The request takes 3.2768 ms to push onto the link and 43.2768 ms total one way, so delay dominates, not data rate.

Worked example 2

Question. A 4 KB photo uploads over a 10 Mbps link with a 30 ms one-way delay. Find the transmission time and total one-way time.

  1. 4 KB = 32 768 bits.
  2. 10 Mbps = 10 000 000 bit/s.
  3. Transmission time = 32 768 ÷ 10 000 000 = 3.2768 ms.
  4. Total = 3.2768 + 30 = 33.2768 ms.

Answer. Transmission time is 3.2768 ms and total one-way time is 33.2768 ms.

Exam traps

  • Mobile and wireless are not synonyms. A laptop plugged into a train's wired network is mobile but not wireless; a desktop on Wi-Fi is wireless but not mobile.
  • Middleware is not the app. Heavy location lookup, security and sync reconciliation run as network services; small client pieces run on the handset.
  • Unit slip: here 1 KB means 1024 bytes, so 2 KB is 2048 bytes and 16 384 bits, not 16 000.
  • 1 Mbps means 10⁶ bit/s, not 2²⁰ bit/s. This shifts transmission time by about 5%; total time barely moves because delay dominates.
  • Handover keeps a live session alive; location tracking finds an idle user. Examiners ask for both and mark them separately.

1.2 Evolution of mobile technologies and cellular generations

Cellular generations are a short history of one idea: each generation adds one new capability to the mobile network. 1G carried analog voice. 2G made voice digital and added SMS. 2.5G added packet data. 3G raised data rates. 4G moved user traffic to IP packets. 5G targets high speed, low delay and network slicing. Mobile app developers care because the network under the app changes what the app may assume: always-on data, latency, and cost per megabyte. The figure puts the generations on a timeline and times one 5 MB song on 2G, 3G and 4G.

You need: Chapter 1.1 for the device, link and fixed network picture.

1G analog voice, 2G digital voice and SMS

The first generation (1G) sent voice as an analog radio signal. AMPS (Advanced Mobile Phone System) started in the United States in 1983. NMT (Nordic Mobile Telephone) started earlier in Northern Europe. Each call took one frequency channel. There was no native data service; a modem over the voice channel was the only option.

The second generation (2G) encoded voice as bits before transmission. GSM (Global System for Mobile Communications) began in Europe in 1991. IS-95 cdmaOne was the main 2G standard in North America and parts of Asia. Digital voice gave more calls per band, encryption, and cheaper handsets.

SMS (Short Message Service) came with GSM as a use of the signalling channel. A short text message did not need a call to be set up. Typical 2G circuit data ran at an order of 10 kbps (kilobits per second), for example 9.6 kbps. That is enough for text, not for images or music.

2.5G packet data and 3G higher rates

GPRS (General Packet Radio Service) added packet switching to GSM. A phone could stay online and pay for the bytes it sent, not for the time it held a circuit. GPRS data rates are an order of 100 kbps; the common textbook peak is 171.2 kbps. EDGE improved the modulation and reached an order of 200 kbps. Operators marketed both as 2.5G.

3G introduced a new radio interface. UMTS (Universal Mobile Telecommunications System) uses WCDMA (Wideband Code Division Multiple Access). CDMA2000 is the other main 3G family. 3G data rates are an order of 2 Mbps at peak and often 384 kbps in practice. That made mobile video calling and early mobile web usable. HSDPA is a 3.5G downlink upgrade inside UMTS, with rates an order of 10 Mbps. The internal GSM, GPRS and UMTS architecture is in Chapter 1.3.

T = S ÷ R

T is the download time in seconds; S is the file size in bits; R is the data rate in bits per second.

4G all-IP and 5G network slicing

4G LTE (Long Term Evolution) dropped circuit switching for user traffic. Voice, SMS and web all travel as IP packets; VoLTE carries voice over the same packet network. LTE uses OFDMA (Orthogonal Frequency Division Multiple Access) on the downlink: many narrow subcarriers are shared among users. 4G rates are an order of 100 Mbps. The ITU IMT-Advanced target was 100 Mbps for a moving user and 1 Gbps for a slow user.

5G NR (New Radio) is the 5G air interface. It uses wider channels, including mmWave bands above 24 GHz, and massive antenna arrays. 5G rates are an order of 1 Gbps. It also targets low latency, about 1 ms in the radio link for some services. Network slicing divides one physical network into virtual networks, each with its own speed, latency and capacity guarantee. A factory robot slice can differ from a video streaming slice.

Satellite and terrestrial broadcast as other paths

A mobile user can also receive data without a cellular tower. Satellite systems cover oceans and rural areas. GEO satellites sit at about 35,786 km and add about 250 ms one-way delay; LEO constellations are lower and faster but need many satellites. A satellite link is shared and costly per megabyte.

Terrestrial broadcast systems send one signal from a tall tower to many receivers. FM radio, digital audio broadcast and DVB-T television are examples. Broadcast is cheap for popular content because the cost does not grow with each viewer. It is mostly downlink: the user needs another path for requests.

Worked example

Question. A 5 MB song must be downloaded to a phone. Use 1 MB = 10⁶ bytes and 1 byte = 8 bits. Find the download time on 2G at 9.6 kbps, on 3G at 384 kbps, and on 4G at 20 Mbps. Give seconds, and minutes where useful.

  1. Convert the file size to bits: S = 5 × 8 × 10⁶ = 40,000,000 bit.
  2. Convert the rates: 2G R = 9.6 kbps = 9,600 bps; 3G R = 384 kbps = 384,000 bps; 4G R = 20 Mbps = 20,000,000 bps.
  3. 2G time: T = 40,000,000 ÷ 9,600 = 4166.7 s. In minutes: 4166.7 ÷ 60 = 69.4 min.
  4. 3G time: T = 40,000,000 ÷ 384,000 = 104.2 s. In minutes: 104.2 ÷ 60 = 1.7 min.
  5. 4G time: T = 40,000,000 ÷ 20,000,000 = 2.0 s.

Answer. About 4167 s (69.4 min) on 2G, 104.2 s (1.7 min) on 3G, and 2.0 s on 4G.

Exam traps

  • GPRS is 2.5G, not 3G. 3G starts with UMTS/WCDMA or CDMA2000.
  • 2.5G and 3.5G are upgrades inside the same system. They do not replace the air interface.
  • 5 MB is 40 Mbit, not 5 Mbit. Convert bytes to bits before dividing by a rate in bits per second.
  • cdmaOne (IS-95) is 2G; CDMA2000 is 3G. The similar names are an easy slip.
  • A higher generation number does not promise a fixed speed. Rate depends on load, distance and spectrum.

1.3 GSM, GPRS and UMTS mobile systems

GSM is the second-generation cellular system that carries voice as a circuit. GPRS keeps the same towers and core but adds packet data for Internet use. UMTS keeps the core and changes the radio to wideband CDMA. Phones still fall back to these networks for voice, SMS, and older data services. For an app developer, coverage, data speed, and circuit versus packet behaviour decide what an app can do. The parts below are the ones exams ask for.

You need: Chapter 1.2 for where 2G and 3G sit in the timeline.

GSM: mobile station, base station subsystem, network subsystem

GSM divides the network into three parts. The mobile station (MS) is the handset plus the SIM. The ME is the handset hardware; the SIM holds the subscriber identity (IMSI) and the authentication key. The base station subsystem (BSS) is the radio access network. It has the BTS (base transceiver station), the tower and radio unit, and the BSC (base station controller), which assigns radio channels and manages handover between BTSs. The network subsystem (NSS) switches calls and stores subscriber data. The MSC (mobile switching centre) connects calls to the PSTN. The VLR (visitor location register) is a temporary copy of subscriber data for the area an MSC serves. The HLR (home location register) is the permanent home record: subscription, services, and the current VLR address. The AUC (authentication centre) supplies keys for checking the SIM. The EIR (equipment identity register) lists stolen or blocked handset identities. Interfaces have names: Um between MS and BTS, Abis between BTS and BSC, A between BSC and MSC. The split lets radio vendors and switch vendors work separately, and it keeps billing and roaming data in a few central databases. On the radio side, GSM uses 200 kHz carriers. Each carrier is shared by frequency division (FDMA) and by time division (TDMA).

T<sub>slot</sub> = T<sub>frame</sub> ÷ 8;  f<sub>frame</sub> = 1 ÷ T<sub>frame</sub>

Tslot is one time slot in ms; Tframe = 4.615 ms is the frame length; fframe is the frame rate in frames per second. With 8 slots per frame, Tslot = 576.875 µs and fframe = 216.7 frames per second. A voice call reserves one slot for the whole call, even during silence.

GPRS: packets added to the GSM core

GPRS adds packet switching to the GSM network without replacing the towers or the MSC. Two new nodes matter. The SGSN (serving GPRS support node) serves the mobile in its routing area. It authenticates the user, tracks the mobile, and forwards packets to the right BSS. The GGSN (gateway GPRS support node) is the gateway to external packet networks such as the Internet. It assigns the mobile an IP address and hides the mobile's location from the outside network. A PDP context is the session record that maps the mobile's IP address to a tunnel between SGSN and GGSN. To use data, the phone first attaches to the SGSN, then activates a PDP context. After that the connection is always-on: there is no dial-up step for each app, and packets are sent only when there is data. The same GSM time slots carry both voice and GPRS packets, so the operator divides capacity between them. Circuit switching holds a slot for the whole call; packet switching shares slots and sends only when needed.

UMTS: WCDMA radio and UTRAN

UMTS is the 3G system that keeps the GSM/GPRS core and changes the radio access. The new radio network is UTRAN (UMTS terrestrial radio access network). It has Node B, the 3G base station, and the RNC (radio network controller), which controls several Node Bs and manages radio resources. The air interface is WCDMA (wideband code division multiple access). WCDMA uses 5 MHz carriers. All users share the same carrier at the same time, and each user is separated by a code. The wide band gives a high chip rate, which spreads each signal and makes the receiver resistant to narrowband interference. UMTS introduces soft handover. In soft handover, the phone is connected to two or more Node Bs at the same time, and the RNC combines the received signals. The call is not dropped at the cell edge because the new link is made before the old one is broken. Handover signalling details are in Chapter 1.5. UMTS data rates are higher than GPRS, and later HSPA upgrades raise them further. The core still uses MSC and VLR for voice and SGSN and GGSN for packets.

Worked example

Question. A GSM cell has 4 carriers. Each carrier has 8 time slots in a 4.615 ms frame. One slot in the whole cell is reserved for the control channel. (a) How many calls can run at once? (b) What is the frame rate? (c) How long is one time slot?

  1. Total time slots = 4 carriers × 8 slots per carrier = 32 slots.
  2. Traffic slots = 32 − 1 control slot = 31. So 31 calls can run at once.
  3. Frame rate = 1 ÷ 4.615 ms = 216.6847 frames per second ≈ 216.7 frames per second.
  4. Slot length = 4.615 ms ÷ 8 = 0.576875 ms = 576.875 µs.

Answer. 31 calls, a frame rate of 216.7 frames per second, and a slot length of 576.875 µs.

Exam traps

  • HLR and VLR: the HLR is the permanent home record; the VLR is the temporary copy for the visited area.
  • SGSN and GGSN: the SGSN serves the mobile; the GGSN is the gateway to the Internet.
  • MSC and BSC: the MSC switches calls; the BSC controls radio channels and BTS handover.
  • GSM uses FDMA plus TDMA on 200 kHz carriers; UMTS uses WCDMA on 5 MHz carriers.
  • Circuit and packet: a GSM voice call reserves a time slot; GPRS shares slots and sends only when there is data.

1.4 Cellular concepts: frequency reuse and channel allocation

A cellular operator owns a fixed slice of radio spectrum, too small to give every subscriber a separate channel. The fix is frequency reuse: the same channel is used again in a cell far enough away that the two signals do not spoil each other. Cells are drawn as hexagons, grouped into clusters, and the pattern repeats across the city. The arithmetic below gives cluster size, reuse distance and signal-to-interference ratio, then the allocation choices. Every GSM or LTE tower you use runs on this idea.

You need Chapter 1.3 for what a cell and a carrier are; here a cell is one base station's radio coverage area.

Cells, clusters and the hexagonal layout

Radio spectrum is scarce. An operator splits its area into cells, each served by one base station. The cell radius R is the distance from the centre to a hexagon corner. The operator divides its channels into groups. If every cell had its own group, the spectrum would run out. Instead a group is reused far away. The set of cells that uses every group once is a cluster, of size N cells. The cluster pattern repeats. Touching cells use different groups; cells that reuse a group are co-channel cells. The figure shows a seven-cell cluster: A is the centre, B to G its six neighbours.

A hexagon is chosen because it tiles the plane with six equal neighbours, so the worst-case distance to a neighbour is easy to write.

Cluster size, reuse distance and SIR

Choose non-negative shift integers i and j. Move i cells along one hexagon axis and j cells along the next; the landing cell may reuse the same channels.

N = i² + ij + j²

N is the cluster size in cells; i and j are non-negative shift integers.

D = R√(3N)

D is the reuse distance in km; R is the cell radius in km; N is the cluster size.

Q = D/R = √(3N)

Q is the co-channel reuse ratio, a pure number.

D is the centre-to-centre reuse distance. Six co-channel cells form the first ring. With path-loss exponent k, received power falls as distance to the power k.

SIR = Q^k ÷ 6

SIR is the signal-to-interference power ratio; k is the path-loss exponent, about 4 in a city and 2 in free space; 6 is the number of first-ring co-channel interferers.

For k = 4, SIR = (√(3N))⁴ ÷ 6 = 9N² ÷ 6 = 1.5N². A larger N raises D and lowers interference but leaves fewer channels per cell.

Channel allocation: fixed, dynamic, hybrid, borrowing

Fixed allocation gives each cell a permanent set of channels: simple, no central control, but a busy cell blocks calls while a quiet neighbour sits idle. Dynamic allocation pools all channels and assigns them on demand: it handles hot spots better but needs fast coordination to keep co-channel separation. Hybrid allocation fixes some channels per cell and keeps a pool for demand. Channel borrowing lets a busy cell use a neighbour's idle channel, provided the borrowed channel is not already used within distance D. Erlang-B gives the blocking probability for a fixed number of channels and a given offered load; one line is enough here. When a user crosses a cell boundary the call moves to the new cell; see Chapter 1.5.

Worked example

Question. A network uses a cluster with shift integers i = 2 and j = 1. Cell radius R = 1 km. Path-loss exponent k = 4. The operator owns 350 channels. Find N, D, Q, SIR in dB, and channels per cell.

  1. N = i² + ij + j² = 2² + 2×1 + 1² = 4 + 2 + 1 = 7 cells.
  2. D = R√(3N) = 1 × √(3×7) = √21 = 4.58 km.
  3. Q = D/R = 4.58 ÷ 1 = √21 = 4.58, a pure number.
  4. SIR = Q⁴ ÷ 6 = (√21)⁴ ÷ 6 = 441 ÷ 6 = 73.5. In dB: 10 log₁₀ 73.5 = 18.66 dB.
  5. Channels per cell = 350 ÷ 7 = 50 channels.

Answer. N = 7, D = 4.58 km, Q = 4.58, SIR = 73.5 (18.66 dB), and each cell gets 50 channels.

Exam traps

  • Using D = R√N instead of D = R√(3N).
  • Forgetting the six co-channel interferers, so SIR = Q^k instead of SIR = Q^k ÷ 6.
  • Writing 73.5 dB; 73.5 is a power ratio, while 18.66 dB is its dB value.
  • Reusing a channel in a touching cell; reuse needs the full distance D.
  • Swapping i and j changes nothing because N is symmetric; do not invent two different N values for (2,1) and (1,2).

1.5 Handover, location tracking and mobility management

An active call must survive when the user moves from one cell to the next. An idle phone must still be found when a call arrives. Cellular mobility management does both jobs. Handover moves an active connection to a new base station without dropping the call. Location tracking lets the network find an idle phone with low signalling. GSM and UMTS use these mechanisms every day, and later mobile networks reuse the same ideas. This chapter covers handover types and phases, the main handover signals, and the location-area method for paging.

You need: Chapter 1.3 for HLR, VLR and MSC, and Chapter 1.4 for cell boundaries and reuse.

Handover: types and four phases

A cell boundary is where a neighbour base station's signal becomes stronger or cleaner than the serving base station. If the call stayed on the old cell, the link would fail. Handover moves the radio link to a new base station while the call continues. Some texts call it handoff.

Hard handover breaks the old link before making the new one. The phone retunes to a new channel, so the call is interrupted briefly. GSM uses hard handover. Soft handover makes the new link before breaking the old one. The phone talks to two base stations at once. Soft handover fits code division multiple access naturally, so WCDMA, the radio interface of UMTS, uses it. Later systems can also hold two links at once, for example dual connectivity in LTE. See Chapter 1.3.

  1. Measurement: the mobile station (MS, the phone) and the base station measure signal strength and quality for the serving and neighbour cells.
  2. Initiation: a measurement crosses a threshold, or a timer fires, so handover becomes a candidate.
  3. Decision: the base station subsystem (BSS, base station and controller) or the mobile switching centre (MSC, the switch) chooses the target cell and the moment.
  4. Execution: the network reserves a channel, sends the command, the MS accesses the new cell, and the old channel is released.

f = (H × t_b) ÷ T

f is the fraction of call time lost; H is the number of handovers; t_b is the break per hard handover in seconds; T is the call duration in seconds.

Handover signalling and the VLR

The figure shows the main messages. The MS sends a measurement report to the old BSS. The old BSS sends handover required to the MSC. The MSC, with the visitor location register (VLR, a local database of subscribers in its area), sends handover request to the new BSS. The new BSS reserves a channel and returns an acknowledgement, channel ready. The MSC sends handover command to the old BSS, which forwards it to the MS. The MS sends handover access to the new BSS. The new BSS reports handover complete to the MSC. The MSC releases the old channel. Real GSM has more messages; these are the main ones.

The serving VLR (and MSC) changes only when the phone moves into a new MSC area. Inside the same MSC area the radio path moves and the stored location area in the VLR is updated, but the subscriber record is not fetched again. If the MS moves to a new MSC, the new VLR sends an update location to the home location register (HLR, the permanent subscription database). The HLR stores the new VLR address, sends the subscription data to the new VLR, and cancels the record in the old VLR. This is inter-MSC handover.

Newer cores use SDN (software-defined networking) for centralised control and NFV (network function virtualisation) to run core functions as software; the handover and location jobs stay the same.

Location tracking: attach, update and paging

An idle phone has no call, but the network must find it when a call arrives. Tracking every idle phone's exact cell would need an update at every cell change, which drains battery and loads signalling. Instead, cells are grouped into a location area (LA). An LA is a set of cells with one identity, the location area identity (LAI). The phone can move inside the LA without telling the network.

  • Attach: on switch-on, the phone registers; the VLR creates or refreshes the subscriber record.
  • Detach: on switch-off or SIM removal, the phone tells the network; the VLR marks the record detached or removes it.
  1. Detect: the phone reads the broadcast LAI and finds it differs from the stored LAI.
  2. Request: the phone sends a location update request through the new BSS to the MSC/VLR.
  3. Update: the VLR updates the record; if the MSC changed, the HLR is told the new serving VLR address.
  4. Acknowledge: the network returns an acknowledgement, and the phone stores the new LAI.

Paging is the reverse. For an incoming call, the MSC asks the VLR for the LA. The MSC sends a paging message to all cells in that LA. The phone answers, and the call is set up. A large LA makes paging expensive because many cells transmit. A small LA makes updates expensive because the phone crosses LA boundaries often. That trade-off is the core of location management.

Worked example

Question. A call lasts 120 s. The user crosses a cell boundary every 15 s. Each hard handover breaks the link for 60 ms. Find the number of handovers, the total break time in ms and in s, the fraction of the call lost, and the percentage lost.

  1. Handovers: H = 120 s ÷ 15 s = 8.
  2. Break per handover: t_b = 60 ms ÷ 1000 = 0.06 s.
  3. Total break: H × t_b = 8 × 0.06 s = 0.48 s = 480 ms.
  4. Call duration: T = 120 s.
  5. Fraction lost: f = 0.48 s ÷ 120 s = 0.004.
  6. Percentage lost: 0.004 × 100 = 0.4 percent.

Answer. The call has 8 handovers, loses 480 ms in total, and the lost fraction is 0.004, which is 0.4 percent of the call time.

Exam traps

  • The phone does not send a location update at every cell change. It updates when it enters a new location area, plus on a periodic timer; inside the area the network pages it.
  • Hard is break before make (GSM); soft is make before break (WCDMA). Do not swap them.
  • The VLR is temporary and local to an MSC area; the HLR is the permanent home database.
  • Convert milliseconds to seconds before dividing by a call time in seconds: 60 ms is 0.06 s.
  • In the message sequence, the MS sends measurement report to the old BSS; the MSC sends handover request to the new BSS.

1.6 Mobile IP and packet delivery

Mobile IP keeps one permanent IP address for a device that moves between networks. An IP address does two jobs at once: it names the device and it says where the device is. Move the device and the second job breaks, because routers still send packets to the old subnet. Mobile IP splits the two jobs: a home address that never changes, and a care-of address borrowed from the visited network. A home agent forwards traffic to the care-of address. The idea matters wherever a device must stay reachable at a fixed address while roaming, across operators or across a campus.

You need Chapter 1.5 for handover and location tracking inside one operator's network, because this chapter pushes mobility across networks.

Why plain IP breaks when a node moves

A router forwards a packet using only the destination prefix. A phone with address 10.20.30.4 that moves to a café in another city now sits behind a router that has never heard of 10.20.30.0/24. Packets aimed at the phone still travel to the home network and are dropped there. Giving the phone a local address fixes routing but breaks identity: TCP names a connection by its address pair, so every open connection dies, and the DNS name still points to the old address.

Mobile IP keeps the address and moves the packets instead. It defines four entities:

  • Mobile node (MN): the device that moves, and keeps its home address.
  • Home agent (HA): a router on the home network that tracks where the MN is now and forwards its traffic.
  • Foreign agent (FA): a router in the visited network that helps the MN and can hand it tunneled packets.
  • Correspondent node (CN): any host that talks to the MN.

The split is the whole idea. The home address is permanent; apps, DNS and TCP see only this. The care-of address (CoA) is temporary, belongs to the visited network, and is where packets are actually delivered.

Discovery and registration

Before traffic can flow, the MN must learn a care-of address and tell its HA where it is.

  1. Every HA and FA broadcasts an agent advertisement on its link: an ICMP router advertisement with a mobility extension, giving the agent's address, a lifetime, and flags saying whether it offers a foreign-agent care-of address.
  2. A node that has just arrived and hears nothing sends an agent solicitation; the agent answers with an advertisement at once.
  3. The MN takes the care-of address from the advertisement (an FA care-of address, shared by all visitors) or, if it configured itself by DHCP, uses a co-located care-of address.
  4. It sends a registration request through the FA to its HA: home address, care-of address, requested lifetime, and an authentication extension.
  5. The HA verifies the request and creates a binding: home address → care-of address, valid for the lifetime in seconds. The reply travels back through the FA, which adds the node to its visitor list.
  6. The MN re-registers before the lifetime expires. An expired binding means the HA stops forwarding.

Nothing else in the network changes. The home address keeps working in DNS and in transport connections.

Tunnelling, decapsulation and the triangle route

The CN sends to the home address, so ordinary routing delivers the datagram to the home network. The HA intercepts it — it answers ARP for the home address on behalf of the absent node — and encapsulates it: a new outer IP header with source = HA, destination = care-of address, protocol number 4 for IP-in-IP. The original datagram, headers and all, becomes the payload. That is the tunnel. The FA receives the outer packet, strips the outer header (decapsulation), and forwards the original datagram to the MN on the visited link. Replies normally go straight from the MN to the CN, with the home address as source. If the visited network filters packets whose source address is foreign to it, replies must also be tunnelled back through the HA.

Triangle routing. The path CN → HA → FA is longer than CN → FA. Every packet makes the detour, and one HA carries the traffic of all its roaming nodes. Route optimisation removes the detour: the CN caches the node's binding and sends straight to the care-of address. Mobile IPv6 builds this in. It also drops the foreign agent: every IPv6 node forms its own care-of address by stateless autoconfiguration, registers it with the HA using a Binding Update, and can send Binding Updates to correspondents. Those updates are authenticated, because a forged one would redirect a victim's traffic.

Worked example

Question. A mobile node receives a 100-byte payload. The original IP header is 20 bytes. The home agent tunnels the datagram to the foreign agent with a 20-byte outer IP header. (a) How many bytes cross the tunnel? (b) What is the tunnelling overhead as a percentage of the original datagram? (c) How long does the tunneled datagram take on a 2 Mbps link?

  1. Original datagram = payload + inner header = 100 + 20 = 120 bytes.
  2. Tunneled datagram = original datagram + outer header = 120 + 20 = 140 bytes, so 140 bytes cross the tunnel.
  3. Overhead = outer header ÷ original datagram = 20 ÷ 120 = 0.1667, that is 16.7 percent.
  4. Bits on the link = 140 × 8 = 1120 bits.
  5. Transmission time = 1120 bits ÷ 2 000 000 bits/s = 0.00056 s = 0.56 ms.

Answer. 140 bytes cross the tunnel, the overhead is 16.7 percent, and the datagram takes 0.56 ms on a 2 Mbps link.

Exam traps

  • Swapping home address and care-of address. The home address never changes; the care-of address is temporary and belongs to the visited network.
  • Saying IP-in-IP replaces the original header. It adds an outer header; the inner datagram is carried whole, so the packet grows.
  • Thinking the tunnel shortens the path. Basic Mobile IPv4 sends every packet through the home agent, which is a detour — that is exactly the triangle route.
  • Claiming a correspondent always knows the care-of address. In basic Mobile IPv4 only the home agent knows it; the CN learns it only after route optimisation.
  • Reversing registration: the mobile node registers its care-of address with the home agent, not the other way round.

1.7 Wireless LANs (IEEE 802.11) and Bluetooth

A wireless LAN joins phones and laptops over radio instead of cable. IEEE 802.11 (Wi-Fi) shares one channel politely: stations listen, wait and back off before sending, so collisions are avoided, not detected. Bluetooth is the opposite: one master tightly controls a small piconet of slaves. Both replace the last few metres of cable — a campus hotspot, a Chennai coffee shop, earbuds paired to a phone.

You need the access-network part of Chapter 1.1.

802.11 architecture: stations, APs and service sets

A station (STA) is a device with a wireless network card. An access point (AP) is a fixed box that bridges the radio channel to the wired network.

A basic service set (BSS) is one AP plus the stations joined to it. A BSS with no AP is independent — an ad hoc network, covered in Chapter 1.8.

An extended service set (ESS) joins two or more BSSs through a distribution system (DS), usually wired Ethernet. The DS forwards frames between APs, so a user walks from one classroom to the next and stays on the same network. The service set identifier (SSID) is the Wi-Fi name you pick from the list; inside an ESS the same name is also called the ESSID.

Two layers and the join procedure

802.11 defines two layers. The physical layer (PHY) turns bits into radio: direct-sequence spread spectrum (DSSS) in 802.11b, orthogonal frequency-division multiplexing (OFDM) from 802.11a and 802.11g onward. The MAC layer decides who transmits next, adds addresses and a checksum.

  1. Scan: listen for beacon frames; an AP beacons about every 100 ms with its SSID and data rates.
  2. Probe and authenticate: send a probe request, then exchange authentication frames.
  3. Associate: the AP accepts the station and returns an association ID (AID); data frames follow.

CSMA/CA: sharing one channel

Ethernet uses CSMA/CD — listen, send, and detect collisions while sending. A radio cannot hear itself transmit, so 802.11 uses CSMA/CA: carrier sense multiple access with collision avoidance.

A station with a frame waits until the channel is idle for a DIFS (DCF interframe space). It then counts a random backoff down in idle slots, freezing the counter when the channel goes busy. At zero it transmits, and the receiver replies with an ACK after a SIFS (short interframe space). Since SIFS < DIFS, the ACK grabs the channel before other stations can start.

backoff = random(0, CW) × slot

CW is the contention window in slots, starting at 15 or 31 and doubling to 1023 after each failure; slot is 9 µs or 20 µs depending on the PHY.

Hidden nodes: A and C both reach AP B but not each other, so both may transmit and collide at B. With RTS/CTS the sender asks using a request-to-send frame, B answers with clear-to-send, and every station that hears the CTS keeps quiet for that exchange.

Bluetooth: piconet, FHSS and profiles

Bluetooth is a short-range (about 10 m) cable replacement for earbuds, keyboards and car audio. A piconet is one master and up to seven active slaves sharing a channel.

The master polls one slave at a time, so the link is time-division duplex with no collisions. The channel hops 1600 times a second over 79 channels of 1 MHz in the 2.4 GHz band (frequency-hopping spread spectrum, FHSS), which dodges interference from Wi-Fi and microwave ovens.

A device that belongs to two piconets at once links them; the linked piconets together form a scatternet. The link manager handles link setup, power and security, while a profile states what a use case needs, such as hands-free audio or a serial port.

HIPERLAN/2 and wireless ATM were rival broadband wireless systems; both are now history.

  2. Transmission time = 12 000 ÷ 11 000 000 = 1.09 ms.

Exam traps

  • Saying Wi-Fi uses CSMA/CD like Ethernet. A radio cannot listen while it transmits, so 802.11 avoids collisions with DIFS, backoff and ACK, plus RTS/CTS for hidden nodes.
  • Mixing BSS and ESS. A BSS is one AP; an ESS is several BSSs joined by the distribution system.
  • Forgetting SIFS < DIFS. That short gap is exactly why the ACK goes out before other backoffs expire.
  • Writing 'one master and eight active slaves'. It is seven active slaves; further devices can be parked.
  • Swapping the radios: Bluetooth uses FHSS and time-division duplex, while 802.11b uses DSSS with CSMA/CA.

Understand Explain the hidden node problem and the RTS/CTS cure. 4 marks

Two stations reach the AP but not each other, so both sense an idle channel and collide at the AP. The sender transmits an RTS; the AP answers with a CTS that both stations hear, so the other one stays silent for that exchange.

Analyze Why does the contention window double after each failed attempt? 5 marks

A failure means the channel is crowded, so a wider window spreads the retries of all stations over more slots and lowers the chance of another collision. With a fixed small window on a busy channel, collisions repeat and throughput collapses.

1.8 Mobile ad hoc networks

A mobile ad hoc network (MANET) is a set of wireless nodes that route packets for each other. There is no base station and no fixed backbone. Each node is both a host and a router. Two nodes out of radio range talk through other nodes, so a path can be several hops long. MANETs exist where infrastructure is missing or too slow to set up: disaster relief, vehicle convoys, sensor fields and tactical teams. The aim here is route discovery, not the full protocol suite.

You need: Chapter 1.7 for the radio link, hidden nodes and CSMA/CA; Chapter 1.1 for the device-link-network view.

No infrastructure, many constraints

A MANET has no access point and no router owned by an operator. Every node has a radio with limited range. A node that receives a packet for someone else forwards it. That makes the network self-configuring: two nodes join by coming into range and leave by moving away.

  • Multi-hop paths: A reaches D through B, not by one long radio jump.
  • Changing topology: every move adds or removes links, so old routes expire.
  • Limited energy: forwarding drains a battery, so routing must not waste transmissions.
  • Limited bandwidth: the radio channel is shared, and every forward uses it again.
  • No central authority: address assignment and security are harder.

Disaster relief uses MANETs when cell towers are down. Vehicle networks connect cars that warn each other about braking. Sensor fields report temperature or motion through many small nodes. Tactical teams use radios with no fixed base. A classroom mesh or a phone-to-phone file share is a small MANET too. In each case, a node's battery pays for other people's traffic.

Routing classes and route discovery

Routing protocols are classed by when they keep routes. Proactive (table-driven) protocols keep a route to every node all the time; DSDV is the standard example. Reactive (on-demand) protocols find a route only when a packet needs one; AODV and DSR are examples. Hybrid protocols, such as ZRP, keep routes nearby and search farther away on demand.

ProactiveAll the timeDSDV
ReactiveOn demandAODV, DSR
HybridNearby now, far on demandZRP

Reactive discovery uses three message types. A route request (RREQ) is broadcast. A route reply (RREP) is unicast back. A route error (RERR) reports a broken link.

  1. Source broadcasts RREQ with target D and a request id.
  2. Each neighbour rebroadcasts once; duplicate ids are dropped.
  3. When D receives RREQ, it unicasts RREP along the reverse path.
  4. Source sends data; if a link breaks, a node sends RERR and discovery restarts.

If every node rebroadcasts every new RREQ, transmissions grow fast. This is the broadcast storm problem. Sequence numbers, a hop limit, and a random delay before rebroadcast reduce it. TCP over multi-hop ad hoc paths performs poorly because link loss is read as congestion. MANET security needs keys without a central server.

Worked example

Question. Source A has neighbours B and C. B is a neighbour of D; C is a neighbour of E. A wants a route to D. A broadcasts one route request, and every node that receives a new request rebroadcasts it once. D answers B by unicast, and B forwards the reply to A. Find (a) the number of broadcast transmissions, (b) the hop count of the route found, (c) the number of unicast reply transmissions.

  1. A sends RREQ: 1 broadcast.
  2. B and C each rebroadcast once. E hears C's copy and rebroadcasts it once, and E's copy reaches only C, which drops it as a duplicate. So B, C and E each transmit once: 1 + 3 = 4 broadcast transmissions.
  3. D is a neighbour of B, so D receives RREQ via B; E's copy does not reach D. D unicasts RREP to B: 1 unicast.
  4. B forwards RREP to A: 1 more unicast, total 2.
  5. Route is A→B→D: 2 hops.

Answer. 4 broadcast transmissions, a 2-hop route, and 2 unicast reply transmissions.

Exam traps

  • A MANET does not need an access point; an access point is infrastructure, which a MANET by definition lacks.
  • A route is not permanent. Movement or battery loss breaks links, and a route error triggers fresh discovery.
  • AODV is reactive, DSDV is proactive. Do not swap the labels.
  • Broadcast count is not the number of nodes. Every node that gets a new request rebroadcasts once, including a leaf like E, and duplicate request ids are dropped.
  • Hop count is the number of links, not the number of relay nodes. A→B→D has two links and one relay.

Takeaways

  1. Mobile computing needs four things together: a device, a wireless link, a fixed network and middleware; remove one and the problem changes completely.
  2. Each cellular generation added exactly one big capability: analog voice, then digital voice and SMS, then packet data, then broadband all-IP.
  3. GSM carries voice on circuits, GPRS overlays packet switching on the same network, and UMTS replaces only the radio with WCDMA.
  4. Frequency reuse is what makes cellular work: N = i² + ij + j² sets how far co-channel cells sit, and Q = √(3N) sets the interference.
  5. Mobility management is two jobs: handover keeps a call alive, and location update plus paging keeps an idle user findable.
  6. Mobile IP keeps one permanent home address and forwards packets through a tunnel to the care-of address; triangle routing is its main inefficiency.
  7. IEEE 802.11 shares the radio with CSMA/CA and RTS/CTS, while Bluetooth organises nearby devices into a piconet under one master.
  8. In a MANET every node is also a router, so the routing protocol, not the radio, is the hard design problem.

Remember and understand

Understand Define mobile computing. Explain the three parts of its structure with a labelled diagram, and give two Indian applications. 10 marks

Definition: a user computes while moving, not just a small computer; Device layer: phone, tablet, laptop, sensor; Wireless link: cellular, Wi-Fi or Bluetooth, with limited bandwidth and errors; Fixed network plus middleware that hides mobility and disconnection; Diagram: device → air interface → base station → fixed network → server; Applications: UPI payment from a moving phone, IRCTC booking on a train, field service, ambulance telemetry.

Understand Trace the evolution from 1G to 5G. For each generation, state the new capability added and the multiple access method used. 13 marks

1G: analog voice, FDMA, poor security; 2G: digital voice and SMS, GSM uses TDMA, IS-95 uses CDMA; 2.5G: GPRS and EDGE add packet data; 3G: UMTS and WCDMA, mobile internet with voice and data together; 4G: LTE all-IP, OFDMA, flat architecture; 5G: NR, wider bandwidth, network slicing, low latency; Table form with generation, year band, data rate order and access method; One line on what stayed the same: the cellular reuse idea.

Understand Draw the GSM system architecture. Explain the role of MS, BTS, BSC, MSC, HLR and VLR, then explain how GPRS adds packet data. 13 marks

MS = mobile equipment plus SIM; IMSI identifies the subscriber; BTS is the radio cell, BSC controls several BTS; MSC switches calls and connects to the PSTN; HLR and VLR hold registers; GSM voice path is circuit-switched, set up by signalling before speech; GPRS adds SGSN and GGSN, a packet control unit and PDP context activation; GPRS attach and PDP context request as the two setup steps; UMTS then replaces the radio with WCDMA and adds Node B and RNC.

Understand Explain frequency reuse in a hexagonal cellular layout. Derive N = i² + ij + j² and Q = D/R = √(3N). 12 marks

Hexagon chosen because it tiles without gaps and approximates a circle; A cluster of N cells uses all channels once, then repeats; i and j are step counts along the two hexagon axes; N = i² + ij + j² with a worked example such as i = 2, j = 1 giving N = 7; Geometry gives D/R = √(3N); Large N: more reuse distance, less interference, fewer channels per cell; Small N: more capacity, more interference.

Apply

Apply An operator has 840 channels in total and uses a reuse cluster of N = 7. Find the channels per cell and D/R. Repeat for N = 4 and comment on capacity against interference. 10 marks

Channels per cell = 840/7 = 120; D/R = √(3 × 7) = √21 ≈ 4.58; For N = 4: 840/4 = 210 channels per cell; D/R = √12 ≈ 3.46, so co-channel cells are closer; Capacity per cell rises, carrier-to-interference ratio falls; Conclusion: N is a planned trade-off between capacity and quality.

Apply A user on a moving train crosses three cells during one call. Describe the handover process step by step and the signalling between MS, BSC and MSC. 12 marks

MS measures its own and neighbour cell signal strengths and reports them; Serving BSC compares and decides a handover is needed; Handover request to MSC, which asks the target BSC for a channel; Target allocates a traffic channel and returns an acknowledgement; MSC switches the voice path to the new BSC; MS tunes to the new channel and sends handover complete; Old channel released; hysteresis and dwell time prevent ping-pong; Hard handover in GSM, soft handover in CDMA where two links run together.

Apply A mobile node leaves its home network and attaches to a foreign network. Explain agent discovery, registration and packet delivery, naming every message. 13 marks

Agent advertisement or agent solicitation finds the foreign agent; MN builds a care-of address, either foreign-agent CoA or co-located CoA; Registration request goes to FA, then to HA; HA updates its binding cache; Registration reply returns to the MN with lifetime; CN sends a packet to the home address; HA intercepts it; HA tunnels the packet to the CoA using IP-in-IP; FA decapsulates and delivers to the MN; Reverse tunneling for replies when ingress filtering is used.

Apply Explain CSMA/CA in IEEE 802.11 with DIFS, backoff and the RTS/CTS exchange, and show how it deals with the hidden node problem. 13 marks

Carrier sense plus interframe spacing: SIFS for ACK, DIFS for new transmissions; Random backoff counts down only while the channel is idle; Receiver sends ACK; no ACK means collision, so retransmit; Hidden node: two stations cannot hear each other and both send; RTS from sender and CTS from receiver carry a duration value; Other stations set their NAV and stay silent for that time; Fragmentation threshold and physical versus virtual carrier sense; Contrast with CSMA/CD, which detects collisions instead of avoiding them.

Apply Five nodes form an ad hoc network with no access point. Explain how a reactive protocol such as AODV discovers a route and repairs it after a link breaks. 12 marks

Source broadcasts RREQ with destination, sequence number and hop count; Intermediate nodes store a reverse route to the source; Destination replies with a unicast RREP along the reverse path; Forward route entries installed with a lifetime; Data flows; hello messages or link-layer feedback detect a break; A node sends RERR upstream; affected routes are invalidated; New RREQ only when a route is needed, which saves energy; Compare with a proactive protocol, which keeps routes for all nodes all the time.

Analyze and evaluate

Analyze Analyse triangle routing in Mobile IP. Evaluate route optimisation as a remedy, including its costs and risks. 13 marks

Packets go CN → HA → MN even when CN and MN share a foreign network; Costs: extra delay, load on HA, longer path, possible congestion on the home link; Route optimisation: HA sends a binding update to the CN; CN keeps a binding cache and tunnels directly to the CoA; Savings show up as shorter path and lower delay; Costs: binding cache state in every CN, authentication of updates, stale bindings, security against spoofed updates; HA still needed for the first packet and for nodes that do not support it.

Evaluate Compare a cellular network, an IEEE 802.11 WLAN and a mobile ad hoc network for three deployments: a metro city, a college campus, and a flood-hit area with no infrastructure. Recommend one for each with reasons. 14 marks

City: licensed cellular, wide coverage, managed handover, high cost and spectrum licence; Campus: WLAN with access points and backhaul, high data rate, low cost, limited range; Disaster area: MANET, no base station, nodes relay for each other, but limited battery and capacity; Compare coverage, mobility support, bandwidth, delay, energy, cost and reliability; Cellular needs location tracking and handover; WLAN needs CSMA/CA; MANET needs a routing protocol; State the recommendation with the reason, and mention a hybrid such as phones acting as hotspots.

Evaluate Compare FDM/TDM cellular systems with cellular CDMA on capacity, reuse, power control and handover. 13 marks

FDM/TDM: hard reuse factor about 1/7, careful frequency planning; CDMA: reuse factor 1 everywhere, interference limited, soft capacity; Near-far problem makes power control essential in CDMA; TPC loop; Voice activity factor and sectorisation raise CDMA capacity; Soft handover in CDMA versus hard handover in GSM; Erlang capacity comparison and what limits each system; Grade of service and trunking: blocking versus interference limit.

Analyze Analyse how cell size and user speed affect handover rate and location update signalling load. How does the network balance the two? 12 marks

Higher speed or smaller cells mean more cell crossings per call, so more handovers; More handovers mean more signalling and a higher drop risk; Small cells mean more location updates for idle users but cheaper paging; Large location areas mean few updates but expensive wide paging; Tune the boundary with hysteresis, dwell timers and neighbour lists; Umbrella cells over microcells for fast users; Trade-off stated as a signalling cost balance between update and paging.

Glossary

Access point
The fixed WLAN device that bridges wireless stations to the wired network.
Agent advertisement
A periodic message from a home or foreign agent announcing its presence and care-of address to mobile nodes.
Agent solicitation
A message a mobile node broadcasts to ask for an immediate agent advertisement.
Base station
The fixed radio equipment that serves one cell and connects mobile devices to the network.
CDMA
Code Division Multiple Access: all users share the whole band at once and are separated by spreading codes.
Cell
The geographical area covered by one base station antenna, drawn as a hexagon in planning.
Correspondent node
The host that is communicating with the mobile node.
Decapsulation
Removing the outer header of a tunnelled packet to recover the original packet.
FDMA
Frequency Division Multiple Access: each user is given its own narrow frequency band for the whole call.
Foreign agent
Router on the visited network that delivers tunnelled packets to the visiting mobile node.
Hidden terminal problem
Two stations that cannot hear each other both transmit to the same receiver and collide.
IMSI
International Mobile Subscriber Identity: the unique number stored in the SIM that identifies the subscriber.
LTE
Long Term Evolution: the all-IP 4G cellular standard with a flat architecture and OFDMA radio.
MSC
Mobile Switching Centre: the exchange that sets up and switches calls in a cellular network.
Proactive routing
Keeping routes to all destinations up to date all the time, as in DSDV and OLSR.
Reactive routing
Finding a route only when a packet must be sent, as in AODV and DSR.
Roaming
Using a mobile service on a network other than the home network, arranged through inter-operator agreements.
Route optimisation
Informing the correspondent node of the binding so packets can go directly to the care-of address.
RTS/CTS
Request To Send and Clear To Send frames that reserve the medium and silence hidden stations.
SIM
Subscriber Identity Module: the card that holds the subscriber identity and authenticates it to the network.
SSID
Service Set Identifier: the name that identifies an IEEE 802.11 network.
TDMA
Time Division Multiple Access: users share one frequency but transmit in separate time slots.
Tunneling
Wrapping a packet inside another IP packet so it can be delivered to a temporary address.
WPA2
A Wi-Fi security standard using AES encryption and a key exchange to protect the wireless link.
