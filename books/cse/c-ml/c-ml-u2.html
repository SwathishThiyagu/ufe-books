2.1 Linear regression: least squares, simple and multiple

Linear regression fits a straight line (or hyperplane) to data by minimizing the sum of squared differences between observed values and the line’s predictions. It gives the simplest way to predict a continuous quantity such as a used phone price from its age, and it forms the basis for many more complex models used in finance, health, and engineering.

You need: basic algebra, summation notation, and matrix multiplication; see Unit 1.

Simple linear regression

In simple regression we have one input variable x (e.g., age in months) and one output variable y (e.g., price in rupees). The model assumes a linear relationship ŷ = a + b·x, where a is the intercept and b is the slope. The goal is to choose a and b so that the total squared error Σ(yᵢ − ŷᵢ)² is as small as possible.

  1. Write the error for each observation: eᵢ = yᵢ − (a + b·xᵢ).
  2. Form the sum of squared errors: S(b,a) = Σ eᵢ².
  3. Take partial derivatives ∂S/∂a and ∂S/∂b, set them to zero, and solve the resulting two equations.

b = Σ(xᵢ − x̄)(yᵢ − ȳ) ÷ Σ(xᵢ − x̄)²

b is the slope; x̄ is the mean of x; ȳ is the mean of y.

a = ȳ − b·x̄

a is the intercept; the other symbols are as defined above.

  • The numerator measures how x and y vary together (covariance).
  • The denominator measures the spread of x (variance).
  • If the denominator is zero the data have no variation in x and a line cannot be fitted.

Applying these formulas to the phone‑price data (1,10000), (3,8000), (5,6000), (7,4000), (9,2000) gives a slope of –1000 ₹/month and an intercept of 11000 ₹. The fitted line is ŷ = 11000 − 1000·x.

Normal equations and multiple regression

When more than one predictor is available (e.g., age, storage capacity, and brand), we write the model in vector form ŷ = X·β. Here X is an n × (p+1) matrix whose first column is all ones (for the intercept) and the remaining p columns contain the predictors. β is a (p+1)‑dimensional coefficient vector.

  1. Form the design matrix X and the response vector y.
  2. Compute the matrix product XᵀX.
  3. Invert XᵀX (if it is nonsingular).
  4. Multiply the inverse by Xᵀy to obtain β̂ = (XᵀX)⁻¹ Xᵀ y.

β̂ = (XᵀX)⁻¹ Xᵀ y

β̂ is the vector of estimated coefficients; Xᵀ is the transpose of X; (XᵀX)⁻¹ is the matrix inverse.

The same procedure is called ordinary least squares (OLS) in many syllabi. OLS gives the unique set of coefficients that minimise the total squared residuals, provided the columns of X are linearly independent.

Assumptions of ordinary least squares

OLS results are reliable only if certain conditions hold. The most common assumptions are:

  • Linearity: the true relationship between predictors and response is linear.
  • Independence: observations are independent of each other.
  • Homoscedasticity: the variance of the error term is constant for all values of the predictors.
  • No perfect multicollinearity: no predictor is an exact linear combination of the others.
  • Normality of errors (optional for inference): error terms are normally distributed.

Violating these assumptions can lead to inefficient estimates (e.g., heteroscedasticity) or biased estimates (e.g., non‑linearity, omitted variables, or correlated errors). For example, if variance grows with age, the fitted line may still pass through the data points but predictions for older phones become unreliable.

The next chapter Loss functions and gradient descent shows how to obtain the same coefficients by iteratively moving opposite to the gradient of the squared‑error loss.

Worked example

Question. A retailer collects the following data for used smartphones: (Age in months, Price in ₹) = (1,10000), (3,8000), (5,6000), (7,4000), (9,2000). Using ordinary least squares, compute the slope and intercept of the best‑fit line and predict the price of a phone that is 4 months old.

C program.

#include <stdio.h>
int main(){
    int age = 4;
    int intercept = 11000;
    int slope = -1000;
    int price = intercept + slope*age;
    printf("Predicted price: %d\n", price);
    return 0;
}
  1. Compute the means: x̄ = (1+3+5+7+9)/5 = 5, ȳ = (10000+8000+6000+4000+2000)/5 = 6000.
  2. Compute Σ(xᵢ − x̄)(yᵢ − ȳ) = (1‑5)(10000‑6000) + (3‑5)(8000‑6000) + (5‑5)(6000‑6000) + (7‑5)(4000‑6000) + (9‑5)(2000‑6000) = (‑4)(4000) + (‑2)(2000) + 0 + (2)(‑2000) + (4)(‑4000) = ‑16000‑4000‑0‑4000‑16000 = ‑40000.
  3. Compute Σ(xᵢ − x̄)² = (1‑5)² + (3‑5)² + (5‑5)² + (7‑5)² + (9‑5)² = 16 + 4 + 0 + 4 + 16 = 40.
  4. Slope b = ‑40000 ÷ 40 = ‑1000 ₹/month.
  5. Intercept a = ȳ − b·x̄ = 6000 − (‑1000)·5 = 6000 + 5000 = 11000 ₹.
  6. Prediction for age 4 months: ŷ = 11000 − 1000·4 = 7000 ₹.

Exam traps

  • Omitting the intercept forces the line through the origin. For the phone‑price data the slope would be Σ x y ÷ Σ x² = 110000 ÷ 165 ≈ 667 ₹/month, which is a positive slope and gives a poor fit because the line cannot capture the decreasing trend.

  • Using the raw sums Σx·y and Σx² without centering can produce the same result but only if you also include the correct intercept term; forgetting the intercept leads to a biased line.
  • Confusing the predicted price (7000 ₹) with the residual error (actual‑predicted) may cause a loss of marks.

2.2 Loss functions and gradient descent, batch and stochastic

Gradient descent updates model parameters by moving them opposite to the slope of a loss function. The idea is to minimise the error measured on the training data, because a smaller loss usually means better predictions. It is used for linear regression, neural networks and many other models where an analytical solution is unavailable or costly. By iterating the update, the algorithm approaches a set of parameters that (locally) minimise the loss.

You need: Chapter 1 linear regression.

Mean‑squared error loss and its gradient

For a dataset of n examples (x_i , y_i) the mean‑squared error (MSE) loss is L(w) = (1/n) Σ_{i=1}^{n} (y_i – w·x_i)². Here w is the scalar weight for a simple linear model, x_i is the input feature, and y_i is the target value. The loss has units of the square of the target.

∂L/∂w = -(2/n) Σ x_i (y_i – w·x_i)

∂L/∂w is the gradient of the loss; n is the number of training points; x_i and y_i are as defined above.

If the gradient is negative, increasing w will decrease the loss; if the gradient is positive, decreasing w will decrease the loss.

Batch gradient descent

Batch gradient descent (BGD) computes the gradient using the whole training set, then updates w once per iteration.

  1. Initialize w (often to 0).
  2. Compute the gradient g = -(2/n) Σ x_i (y_i – w·x_i).
  3. Update w ← w – η·g, where η > 0 is the learning rate.
  4. Check a stopping condition (loss change below a threshold or max iterations).
  • Learning rate η must be small enough to keep the loss decreasing.
  • Each iteration uses O(n) time because all points are visited.

w_{new} = w_{old} – η·∂L/∂w

w_{new} is the weight after the update; w_{old} is the weight before the update; η is the learning rate.

Stochastic gradient descent

Stochastic gradient descent (SGD) approximates the full gradient by using a random mini‑batch of size m (often m = 1). This makes each update cheap and introduces noise that can help escape shallow local minima.

  1. Shuffle the training data.
  2. For each mini‑batch B:
  3. Compute g_B = -(2/|B|) Σ_{i∈B} x_i (y_i – w·x_i).
  4. Update w ← w – η·g_B.
  5. After one pass over all mini‑batches, optionally reduce η.
  • A too‑large η can make the loss diverge because the noisy updates overshoot.
  • Convergence is usually judged by monitoring the loss on a validation set.

Some syllabi call this method "stochastic gradient descent" and treat it as the standard optimisation tool for neural networks.

Worked example

Question. A training set has three points: (x, y) = (1, 2), (2, 3), (3, 5). Using mean‑squared error loss, start with w = 0 and a learning rate η = 0.1. Perform one batch gradient descent update. Show all intermediate calculations and give the new weight w₁.

Python program.

x = [1,2,3]
y = [2,3,5]
w = 0.0
eta = 0.1
n = len(x)
# compute gradient
grad = -(2/n) * sum(x[i]*(y[i] - w*x[i]) for i in range(n))
# update weight
w = w - eta*grad
print('New weight:', round(w,2))
  1. Compute the gradient: ∂L/∂w = -(2/3)[1·(2‑0) + 2·(3‑0) + 3·(5‑0)] = -(2/3)[2 + 6 + 15] = -(2/3)·23 = -46/3 ≈ -15.33.
  2. Update rule: w₁ = w₀ – η·∂L/∂w = 0 – 0.1·(-15.33) = 0 + 1.533 ≈ 1.53.

Exam traps

  • Using Σ(y‑wx) instead of Σ x (y‑wx) omits the factor x and gives a wrong gradient.
  • Applying w ← w + η·gradient (adding instead of subtracting) makes the loss increase.
  • Choosing η = 1.0 for the same data will overshoot and cause divergence.
  • Stopping after the first iteration without checking loss change leads to a premature halt.
  • Confusing batch size with learning rate; a larger mini‑batch does not require a larger η.

For further reading, search for "learning rate schedules" and "mini‑batch selection strategies" in modern machine‑learning literature.

2.3 Logistic regression for classification

Logistic regression predicts a class by turning a linear score into a probability. The probability comes from the sigmoid function, which maps any real number to the interval [0, 1]. Using the probability we can decide the class with a simple threshold. This model is called a probabilistic discriminative model because it directly models the conditional probability of the label given the features. It is used for binary decisions such as fraud detection, credit approval, or spam filtering, and it extends to many‑class problems with one‑vs‑rest.

You need: Chapter 2 loss functions and gradient descent ().

Sigmoid function and probability output

A logistic model first computes a linear score z = w·x + b, where w is the weight vector, x is the feature vector, and b is the bias. The score can be any real number.

The sigmoid function σ(z) = 1/(1+e⁻ᶻ) converts the score into a probability p = σ(z). The output p lies between 0 and 1.

σ(z) = 1/(1+e⁻ᶻ)

σ(z) is the probability of the positive class; z is the linear score.

  1. Compute the score z = w·x + b.
  2. Apply the sigmoid: p = 1/(1+exp(-z)).
  • If p ≈ 1, the model is confident the sample belongs to class 1.
  • If p ≈ 0, the model is confident the sample belongs to class 0.
  • Values near 0.5 indicate uncertainty.

Log‑likelihood loss and gradient

Training chooses w and b to maximise the likelihood of the observed labels. For a single example with true label y ∈ {0,1}, the likelihood is pⁿʸ (1‑p)¹⁻ʸ.

Taking the negative log gives the binary cross‑entropy loss L = –[y·log(p) + (1‑y)·log(1‑p)].

L = –[y·log σ(z) + (1‑y)·log(1‑σ(z))]

L is the loss for one sample; y is the true label; σ(z) is the predicted probability.

  1. Compute z = w·x + b.
  2. Compute p = σ(z).
  3. Compute loss L using the formula above.
  4. Compute gradient ∂L/∂w = (p‑y)·x and ∂L/∂b = p‑y.
  5. Update w ← w – η·∂L/∂w, b ← b – η·∂L/∂b, where η is the learning rate.
  • The gradient (p‑y) has the same sign as the prediction error.
  • If the model predicts too high (p>y), the weight update reduces w·x.
  • If the model predicts too low (p<y), the update increases w·x.

Decision rule and multiclass extension

After training, we classify a new example by comparing its probability to a threshold. The common threshold is 0.5.

predict = 1 if σ(z) ≥ 0.5 else 0

σ(z) is the predicted probability.

For more than two classes we train K binary logistic regressors in a one‑vs‑rest scheme. Each classifier i predicts the probability that the sample belongs to class i. The final class is the one with the highest probability.

  • One‑vs‑rest keeps the binary loss and gradient unchanged.
  • The approach works because probabilities are comparable across classifiers.
  • Training time grows linearly with the number of classes.

Worked example

Question. A bank wants to flag a transaction as fraudulent. The feature vector is x = [₹5000, 22] where the first entry is amount in rupees and the second is hour of day. The model uses weights w = [0.0002, 0.03] and bias b = 0. Compute the probability of fraud and the final decision using the 0.5 threshold.

Python program.

import math
x = [5000, 22]
w = [0.0002, 0.03]
b = 0
z = sum(wi*xi for wi,xi in zip(w,x)) + b
p = 1/(1+math.exp(-z))
print('Score z =', z)
print('Probability =', round(p,2))
print('Decision =', 'fraud' if p>=0.5 else 'legit')
  1. Compute the linear score: z = w·x + b = 0.0002×5000 + 0.03×22 + 0 = 1 + 0.66 = 1.66.
  2. Apply the sigmoid: p = 1/(1+exp(-1.66)) ≈ 0.84.
  3. Compare p with 0.5: 0.84 ≥ 0.5, so predict fraud (class 1).

2.4 Linear classifiers: discriminant functions, binary and multiclass

Linear classifiers separate data points by a straight line (in two dimensions) or a hyperplane (in higher dimensions). The decision is made by a linear discriminant function g(x)=w·x+b. If g(x)≥0 the point belongs to one class, otherwise to the other. For more than two classes the class with the largest discriminant value is chosen. This idea appears in many real‑world systems such as credit‑card fraud detection, spam filtering, and UPI transaction risk scoring, where a fast, interpretable rule is valuable.

You need: logistic regression for classification .

Binary linear discriminant

Define the discriminant g(x)=w·x+b where w is the weight vector, x the feature vector, and b the bias (a scalar). The dot product w·x adds each feature multiplied by its weight. The rule g(x)≥0 assigns the point to class +1, otherwise to class –1. The boundary g(x)=0 is a hyperplane that separates the two regions.

g(x)=∑_{i=1}^{d} w_i x_i + b

w_i is the i‑th weight, x_i the i‑th feature, d the number of features, b the bias term.

  1. Collect a training set with known class labels.
  2. Choose a loss (e.g., hinge loss) and an optimization method such as gradient descent.
  3. Update w and b iteratively to reduce the loss.
  • Only linear boundaries can be learned in the original feature space; non‑linear boundaries become possible after transforming the features (e.g., polynomial features).
  • Feature scaling improves convergence.

Multiclass classification by one‑vs‑rest

For K classes train K binary discriminants. The k‑th discriminant uses weight vector w_k and bias b_k and returns a score g_k(x). The final decision is class = argmax_k g_k(x). This is called the one‑vs‑rest scheme because each binary learner separates one class from all others.

class(x)=argmax_{k∈{1,…,K}} (w_k·x + b_k)

w_k and b_k are the parameters of the k‑th binary classifier.

  • All K scores are computed for the same x.
  • The highest score decides the label.

Relation to the perceptron algorithm

Some syllabi mention the perceptron as a classic way to learn a linear discriminant. The perceptron updates w←w+η y x and b←b+η y whenever a point is mis‑classified (y∈{+1,–1}). The same update rule works for each binary learner in the one‑vs‑rest setting. Any modern optimizer such as batch gradient descent or stochastic gradient descent can replace the perceptron update. A closed‑form least‑squares solution can be used for linear regression but is not generally appropriate for perceptron‑style classification.

  1. Initialize w and b to zero.
  2. For each training example compute g(x).
  3. If y·g(x)≤0 update w and b.
  • Convergence is guaranteed only if the data are linearly separable.
  • Learning rate η controls step size.

Worked example

Question. A cricket match records runs=150 and wickets=4. Three classes are defined: Low, Medium, High. The feature vector is x=[150,4]. The weight vectors are w₁=[0.02, -0.5] for Low, w₂=[0.05, -0.2] for Medium, and w₃=[0.08, 0.1] for High and the bias term is b=0 (bias is a separate scalar, not part of the weight vector). Compute the three discriminant scores and state the predicted class.

Python program.

w1 = [0.02, -0.5]
w2 = [0.05, -0.2]
w3 = [0.08, 0.1]
x = [150, 4]

g1 = w1[0]*x[0] + w1[1]*x[1]
g2 = w2[0]*x[0] + w2[1]*x[1]
g3 = w3[0]*x[0] + w3[1]*x[1]

scores = [g1, g2, g3]
labels = ['Low', 'Medium', 'High']
idx = scores.index(max(scores))
print('Score:', scores[idx])
print('Class:', labels[idx])
  1. Compute g₁ = 0.02×150 + (‑0.5)×4 = 3 – 2 = 1.
  2. Compute g₂ = 0.05×150 + (‑0.2)×4 = 7.5 – 0.8 = 6.7.
  3. Compute g₃ = 0.08×150 + 0.1×4 = 12 + 0.4 = 12.4.
  4. Select the class with the largest score: g₃ is highest, so the prediction is High.

Exam traps

  • Using the same weight vector for all classes instead of one‑vs‑rest leads to identical scores and ambiguous predictions.
  • Neglecting the bias term b makes the decision boundary pass through the origin, which may misclassify data that are offset.
  • Confusing the argmax rule with a threshold rule; the multiclass decision requires the highest score, not a fixed cutoff.
  • Treating the discriminant value as a probability; linear scores are not bounded between 0 and 1 unless passed through a sigmoid.
  • Mixing up feature order; w·x must pair each weight with the correct feature column.

2.5 Overfitting, underfitting and the bias-variance trade-off

When a model learns from data its error on new data can be split into three parts: bias, variance and irreducible noise. Bias measures how far the average prediction of the model is from the true function. Variance measures how much the predictions change when we train on different data sets. The trade‑off tells us why a very simple model under‑fits (high bias) and a very complex model over‑fits (high variance). Understanding it helps you choose the right model size for house‑price, UPI fraud detection or any other Indian‑scale problem.

You need: basic linear regression and loss functions from 2.1 and 2.2.

Error decomposition

Training error is the average loss on the data used to fit the model. Test error is the average loss on unseen data drawn from the same distribution. The expected test error can be written as

E[(y‑f̂(x))²] = Bias² + Variance + σ²

y is the true output; f̂(x) is the model’s prediction; Bias² = (E[f̂(x)]‑f(x))²; Variance = E[(f̂(x)‑E[f̂(x)])²]; σ² is irreducible noise (variance of the data itself).

  • Bias² is zero when the average model equals the true function.
  • Variance is zero when every training set produces the same model.
  • σ² cannot be reduced by any learning algorithm.

Bias–variance trade‑off

As model complexity grows, bias² usually falls while variance rises. The sum forms a U‑shaped curve. The minimum of the curve is the sweet spot where the model is neither too simple nor too flexible.

  • High bias → under‑fitting: the model cannot capture the pattern.
  • High variance → over‑fitting: the model captures noise as if it were pattern.
  1. Choose a range of model complexities (e.g., polynomial degree).
  2. Compute training error for each complexity.
  3. Estimate test error by cross‑validation.
  4. Select the complexity with the lowest estimated test error.

Practical view with house‑price data

Suppose we have monthly house‑price data in rupees and we fit three polynomial models. The degree‑1 model gives a test error of ₹12 000, the degree‑3 model gives ₹5 000 and the degree‑9 model gives ₹18 000. The middle model balances bias and variance, while the extreme models illustrate under‑ and over‑fit.

  • Degree 1: high bias, low variance → under‑fit.
  • Degree 3: moderate bias, moderate variance → good fit.
  • Degree 9: low bias, high variance → over‑fit.

Worked example

Question. A regression problem has model complexity x = 3. Using the bias‑variance formulas Bias² = 20/(x+1), Variance = 5·x and irreducible noise σ² = 5, compute the bias², variance, total error and state whether the model is likely under‑fit, well‑fit or over‑fit.

C program.

#include <stdio.h>
int main(){
    double x = 3.0;
    double bias2 = 20.0/(x+1.0);
    double variance = 5.0*x;
    double noise = 5.0;
    double total = bias2 + variance + noise;
    printf("Bias^2 = %.0f\n", bias2);
    printf("Variance = %.0f\n", variance);
    printf("Total error = %.0f\n", total);
    return 0;
}
  1. Compute Bias²: 20/(3+1) = 20/4 = 5.
  2. Compute Variance: 5·3 = 15.
  3. Add irreducible noise: σ² = 5.
  4. Total error = Bias² + Variance + σ² = 5 + 15 + 5 = 25.
  5. Bias² is moderate and variance is moderate, so the model is in the well‑fit region.

Exam traps

  • Assuming a low training error guarantees low test error – the opposite can happen when variance is high.
  • Confusing high bias with low variance; they are independent dimensions.
  • Forgetting the irreducible noise term σ², which means total error never reaches zero.
  • Using the bias‑variance formula on classification loss (e.g., 0‑1 loss) without modification.
  • Treating the plotted ‘Bias²’ curve as the actual bias; it is only a model of how bias behaves with complexity.

2.6 Regularization: ridge and lasso

Regularization adds a penalty to the regression coefficients. The penalty shrinks the coefficients, which reduces model variance and prevents over‑fitting. Ridge (L2) and Lasso (L1) are the two most common penalties and are used whenever many correlated features exist or when we want automatic feature selection.

You need: bias‑variance trade‑off from chapter 2.5 and linear regression from chapter 2.1.

The idea of penalising coefficients

In ordinary least squares we minimise the sum of squared errors (SSE), which is proportional to the mean‑squared error (MSE). When the training data are noisy, the fitted coefficients can become large and vary a lot with small changes in the data. Adding a penalty term to the loss forces the optimisation to prefer smaller coefficients. The penalty is controlled by a non‑negative number λ called the regularisation strength.

  • Large λ → strong shrinkage → high bias, low variance.
  • Small λ → little shrinkage → low bias, high variance.

Only a few universities teach Lasso in depth because the optimisation is not closed‑form. Both methods require the features to be on the same scale; otherwise the penalty would shrink some features more than others.

Ridge regression (L2 penalty)

Ridge adds the sum of squared coefficients to the loss. The ridge loss is

Lridge = (1/n) Σ (y_i – ŷ_i)² + λ Σ w_j²

n is the number of training points; y_i is the true target; ŷ_i = w·x_i + b is the prediction; w_j are the feature coefficients; λ ≥ 0 controls the penalty.

Because the penalty is quadratic, the optimisation remains a convex quadratic problem with a closed‑form solution.

ŵ = (XᵀX + n·λ I)⁻¹ Xᵀ y

X is the n×p design matrix; y is the n‑vector of targets; I is the p×p identity matrix; n·λ I adds n·λ to each diagonal element of XᵀX. The intercept b is not regularised.

  1. Standardise each column of X to mean 0 and variance 1.
  2. Choose λ (e.g., by cross‑validation).
  3. Form the matrix XᵀX and add n·λ I.
  4. Invert the resulting matrix and multiply by Xᵀy to obtain ŵ.
  • Do not regularise the intercept; keep it separate from the penalty.

Ridge never forces a coefficient exactly to zero, so all features stay in the model. It is useful when many features are correlated, as it distributes the weight among them.

Lasso regression (L1 penalty)

Lasso adds the sum of absolute coefficients to the loss. The lasso loss is

Llasso = (1/n) Σ (y_i – ŷ_i)² + λ Σ |w_j|

All symbols are as defined for ridge; |w_j| is the absolute value of coefficient w_j.

The L1 penalty is not differentiable at zero, so there is no closed‑form solution. A common algorithm is coordinate descent.

  1. Standardise the features.
  2. Initialize all coefficient weights w_j to zero (the intercept b is handled separately and is not penalised).
  3. For each coordinate j, compute the partial residual r_j = y – X_{‑j} w_{‑j}.
  4. Update w_j using soft‑thresholding: w_j = S( (X_jᵀ r_j) / n , λ / n ), where S(z,γ) = sign(z)·max(|z|–γ,0).
  5. Repeat until the change in all w_j is below a tolerance.

Because the soft‑thresholding can set w_j exactly to zero, lasso performs automatic feature selection. When many features are irrelevant, lasso yields a sparse model that is easier to interpret.

Practical workflow

1. Split the data into training and validation sets. 2. Standardise the training features (subtract mean, divide by standard deviation) and apply the same transformation to validation data. 3. Use k‑fold cross‑validation on the training set to pick λ that gives the lowest validation MSE. 4. Retrain the chosen model on the full training set with the selected λ. 5. Evaluate on the held‑out test set.

  • Skipping standardisation leads to uneven shrinkage; the penalty will act more strongly on features with larger numeric range.
  • Very large λ makes all coefficients near zero – the model reduces to predicting the mean of y.
  • Very small λ recovers ordinary least squares.

The next chapter explains how to choose λ automatically using cross‑validation.

Worked example

Question. A used‑car price model uses two features: age (years) and mileage (thousands of km). The training data have not been standardised. For λ = 1, ridge regression gives coefficients w_age = 2.3 and w_mileage = 0.8. For λ = 0.5, lasso gives w_age = 2.1 and w_mileage = 0. Compute the predicted price for a car with age = 3 years and mileage = 40 000 km (i.e., mileage = 40). Assume the intercept term b = 5 (trained on raw features).

C program.

#include <stdio.h>

}

  2. Compute ridge prediction: ŷ_ridge = b + w_age·age + w_mileage·mileage = 5 + 2.3·3 + 0.8·40.
  3. 2.3·3 = 6.9. 0.8·40 = 32.0. Sum = 5 + 6.9 + 32.0 = 43.9.
  4. Compute lasso prediction: ŷ_lasso = 5 + 2.1·3 + 0·40 (mileage coefficient is zero).
  5. 2.1·3 = 6.3. Sum = 5 + 6.3 = 11.3.

  • Using raw features without standardisation makes λ shrink large‑scale features more than small‑scale ones.
  • Confusing the L1 penalty (∑|w|) with the L2 penalty (∑w²) leads to wrong formulae and wrong optimisation steps.

  • For ridge, forgetting to add λI to XᵀX (instead adding λ to every entry) produces a biased estimator.

2.7 Cross-validation, evaluation metrics and model selection

When a model is trained it must work well on data it has never seen. Cross‑validation estimates that future performance and helps pick the best model among many. It is used before a final test on a hold‑out set, in competitions, and in industry pipelines such as predicting demand for UPI transactions or forecasting power load after a Chennai power cut.

You need: regularization concepts from Chapter 2.6.

Data splitting and cross‑validation

The simplest split is train / validation / test. The training part fits the parameters. The validation part tunes hyper‑parameters. The test part gives the final unbiased estimate. Some syllabi call the validation set a "hold‑out" set.

  • Train set: used to learn model weights.
  • Validation set: used to choose λ, depth, etc.
  • Test set: never touched until the end.

k‑fold cross‑validation reduces variance of the validation estimate. The data are divided into k equal folds. Each fold becomes validation once while the other k‑1 folds form the training set. The metric is averaged over the k runs.

  1. Shuffle the whole data set.
  2. Split into k folds of equal size.
  3. For i = 1 to k:
  4. Train on all folds except i.
  5. Validate on fold i and record the metric.
  6. Average the k recorded metrics.
  • Leave‑one‑out CV is k‑fold with k = n (number of samples).
  • Stratified CV keeps class proportions in each fold for classification.

Evaluation metrics

For regression the common metrics are RMSE and MAE.

RMSE = √( Σ(e²) ÷ n )

e = predicted – actual; n = number of examples; Σ(e²) = sum of squared errors.

MAE = Σ|e| ÷ n

|e| = absolute error for each example.

For classification the basic metrics are accuracy, precision, recall and F1‑score.

Accuracy = (TP + TN) ÷ (TP + TN + FP + FN)

TP = true positives; TN = true negatives; FP = false positives; FN = false negatives.

Precision = TP ÷ (TP + FP)

Measures how many predicted positives are correct.

Recall = TP ÷ (TP + FN)

Measures how many actual positives are captured.

F1 = 2 × (Precision × Recall) ÷ (Precision + Recall)

Harmonic mean of precision and recall.

Some syllabi label these as "evaluation metrics" and stress that the same metric must be used for all folds when comparing models.

Model selection and common pitfalls

Model selection means choosing the algorithm and its hyper‑parameters that give the lowest expected error on new data. The process is: define a search space, evaluate each candidate with cross‑validation, pick the best, then train on the full training set and finally test once.

  1. List candidate models (e.g., linear, ridge, lasso).
  2. Choose hyper‑parameter grid (e.g., λ = 0.1, 1, 10).
  3. Run k‑fold CV for every candidate.
  4. Record the average metric.
  5. Select the candidate with the smallest error metric (e.g., RMSE, MAE) or the largest score metric (e.g., accuracy, F1).
  6. Retrain on train + validation data.
  7. Report performance on the untouched test set.
  • Using the test set to tune hyper‑parameters leaks information and gives an optimistic estimate.
  • Data leakage can also happen if preprocessing (scaling, imputation) is fitted on the whole data before splitting.
  • When the data are time‑ordered, use a forward‑chaining split instead of random k‑fold.

In some syllabi the term "model selection" is used interchangeably with "hyper‑parameter tuning". Both are part of the validation workflow described above.

Worked example

Question. A data set contains 1000 house‑price records (price in ₹ thousand). You apply ridge regression with λ = 1 and use 5‑fold cross‑validation. The RMSE obtained on the five folds are 4.2, 4.5, 4.1, 4.3 and 4.4. Compute the average RMSE and state whether the model meets a target error of 5 ₹ thousand.

C program.

#include <stdio.h>
int main(){
    double vals[5] = {4.2,4.5,4.1,4.3,4.4};
    double sum=0.0;
    for(int i=0;i<5;i++) sum+=vals[i];
    double avg = sum/5.0;
    printf("%.1f\n", avg);
    return 0;
}
  1. Add the five RMSE values: 4.2 + 4.5 + 4.1 + 4.3 + 4.4 = 21.5.
  2. Divide by the number of folds (5): 21.5 ÷ 5 = 4.3 ₹ thousand.
  3. Compare 4.3 with the target 5 ₹ thousand. Since 4.3 ≤ 5, the model satisfies the requirement.

Output

4.3

Answer. The average RMSE is 4.3 ₹ thousand, which meets the target of ≤ 5 ₹ thousand.

Exam traps

  • Using the test set to choose λ gives an overly optimistic RMSE; the test data must stay unseen until the final evaluation.
  • Confusing MAE with RMSE: MAE does not square errors, so its scale is different and cannot be compared directly to RMSE values.
  • When computing precision and recall, swapping TP with FP changes the numbers dramatically; always read the definition carefully.
  • In leave‑one‑out CV, the computation time grows proportionally to n times the cost of training a model, which can become very high for large n.

Glossary

Adjusted R²
R² adjusted for number of predictors, penalising extra variables
Batch
Processing the entire training set in one update
Bias
Error from erroneous assumptions in the learning algorithm
Confusion Matrix
Table summarising true/false positives and negatives
Cross‑Validation
Method to estimate model performance by rotating validation folds
Decision Boundary
Surface that separates predicted classes in feature space
F1‑Score
Harmonic mean of precision and recall
Hyperplane
Generalisation of a line or plane to higher dimensions
Irreducible Noise
Random error that cannot be reduced by any model
k‑Fold
Cross‑validation variant that splits data into k equal parts
L1 Penalty
Sum of absolute coefficients used in lasso regression
L2 Penalty
Sum of squared coefficients used in ridge regression
Learning Rate
Step size that controls how far parameters move during gradient descent
Leave‑One‑Out
Cross‑validation where k equals the number of samples
Linear Regression
Predicts a continuous target as a linear combination of input features
Loss Function
Quantifies error between predictions and true values
Mean Absolute Error
Average of |y_i - ŷ_i| across all samples
Mini‑batch
Processing a small subset of examples per update
Multiple Linear Regression
Extension of linear regression with more than one predictor
Precision
TP ÷ (TP + FP), proportion of predicted positives that are correct
Probability
Likelihood of an event expressed between 0 and 1
Recall
TP ÷ (TP + FN), proportion of actual positives that are found
Regularization
Technique that adds a penalty to the loss to prevent overfitting
Sigmoid
S‑shaped function that maps real numbers to (0,1)
Stochastic
Processing a single randomly chosen training example per update
Variance
Error from sensitivity to fluctuations in the training data
