3.1 Decision tree learning: ID3, entropy, information gain

Decision tree learning builds a flowchart that asks one question at a time and ends in a class label. ID3 is the classic algorithm: it measures how mixed the classes are by entropy, tries every attribute, and splits on the attribute that removes the most entropy. That drop is information gain. You meet this idea in credit scoring, medical triage, churn prediction and any place where a human must read the model's reasoning. The tree below predicts Play from Weather and Wind on six days.

You need: Unit 1 concept learning and basic probability, especially fractions and averages.

Entropy: a number for class mixing

Entropy measures how mixed the class labels are in a set of examples. It answers a practical question: if you pick one example at random from S, how unsure are you about its class?

H(S) = −Σ<sub>i</sub> p<sub>i</sub> log₂ p<sub>i</sub>

S is the example set; i runs over class labels; pi is the fraction of S with class i; log₂ is base-2 logarithm; H is measured in bits. Use 0 log₂ 0 = 0.

Low entropy means a nearly pure set. High entropy means classes are mixed. A pure set has H(S)=0 bits. For two classes, H is largest at a 50-50 split and equals 1 bit. Entropy is not the error rate; it uses the logarithm of the class probabilities.

  • H=0 bits only when every example has the same class.
  • H=1 bit is the maximum for two balanced classes.
  • Use log₂ here; the unit is the bit.

Information gain: the entropy drop

Information gain asks how much a split on attribute A lowers entropy. ID3 compares attributes by this drop.

IG(S,A) = H(S) − Σ<sub>v</sub> (|S<sub>v</sub>|/|S|) H(S<sub>v</sub>)

A is the attribute being tested; v runs over A's values; Sv is the subset of S with A=v; |S| is the number of examples in S; H(Sv) is child entropy.

The second term is the weighted average entropy of the children. Each child Sv gets weight |Sv|/|S|, the fraction of examples that go down that branch. A split that makes pure children has gain H(S). A split that leaves class mixing unchanged has gain 0.

ID3 computes IG(S,A) for every attribute, picks the largest, and uses that attribute at the node. It does not use gain itself as the child's entropy; the child is built by recursion.

ID3: grow the tree by recursion

ID3 grows a tree by recursion. Some syllabi call the same idea decision tree induction.

  1. If all examples in S share one class, return a leaf with that class.
  2. If no attributes remain, return a leaf with the majority class of S.
  3. Compute IG(S,A) for every remaining attribute A.
  4. Pick A* with the largest information gain and make it the node.
  5. For each value v of A*, make branch v and recurse on Sv without A*.

Stop when the node is pure or when no attributes remain; in the second case use the majority class as the leaf label. A high-branch attribute can get high gain just by having many values. An ID or row number has one value per row, so each child is tiny and often pure. Information gain is biased this way; do not split on identifiers. C4.5 later uses gain ratio, and CART uses Gini impurity; those are names here, not details.

Worked example

Question. Six days predict Play from Weather and Wind: (Sunny, Weak, Yes), (Sunny, Strong, No), (Rain, Weak, Yes), (Rain, Strong, No), (Sunny, Weak, Yes), (Rain, Weak, Yes). Compute H(S), IG(S,Weather), IG(S,Wind), and give the first ID3 split. Use log₂.

  1. Count S: 4 Yes and 2 No, so |S|=6. pYes=4/6 and pNo=2/6.
  2. H(S) = −(4/6)log₂(4/6) − (2/6)log₂(2/6) = 0.918 bits.
  3. Split Weather. Sunny rows are 2 Yes, 1 No: H=0.918 bits. Rain rows are 2 Yes, 1 No: H=0.918 bits. Weighted child entropy = (3/6)(0.918) + (3/6)(0.918) = 0.918 bits. IG(Weather) = 0.918 − 0.918 = 0 bits.
  4. Split Wind. Weak rows are 4 Yes, 0 No: H=0 bits. Strong rows are 0 Yes, 2 No: H=0 bits. Weighted child entropy = (4/6)(0) + (2/6)(0) = 0 bits. IG(Wind) = 0.918 − 0 = 0.918 bits.
  5. IG(Wind) is larger, so ID3 picks Wind at the root. Branch Weak ends at leaf Yes; branch Strong ends at leaf No.

Answer. ID3 picks Wind first; the tree has root Wind, branch Weak→Yes, branch Strong→No, with IG(Wind)=0.918 bits and IG(Weather)=0 bits.

Exam traps

  • Entropy of the parent and information gain are not the same; gain is parent entropy minus weighted child entropy.
  • Do not average child entropies without the |S_v|/|S| weights.
  • Do not split on an ID or row number; it has one value per row and can look perfect but cannot generalize.
  • Use log₂ and bits in this syllabus; base 10 gives different numbers, though ranking can be the same if used consistently.
  • A leaf can be impure when attributes run out; label it by the majority class, not by the first row.

3.2 Bayes theorem, MAP and maximum likelihood estimation

Bayes theorem turns a prior belief about a hypothesis into a posterior belief after seeing data. Data alone is ambiguous: a coin that shows seven heads in ten tosses could have bias 0.5 or 0.8. Bayes weighs both the prior and the likelihood. MAP keeps the prior; maximum likelihood estimation (MLE) drops it. This chapter builds both, then uses a coin-toss example to show how a strong prior can overrule the likelihood. The same arithmetic powers Naive Bayes and Bayesian networks.

You need: conditional probability, independence and the binomial distribution from Unit 1, Foundations: Learning Problems and Concepts.

Bayes theorem over hypotheses

In supervised learning we often have several candidate hypotheses h. A hypothesis may be a rule, a parameter value, or a whole model. We observe data D, such as ten coin tosses. Bayes theorem tells us how to score each h after seeing D.

P(h|D) = P(D|h) P(h) / P(D)

h is one hypothesis; D is the observed data; P(h) is the prior belief before data; P(D|h) is the likelihood, how well h predicts D; P(h|D) is the posterior belief after data; P(D) is the evidence, the same normalizer for every h.

P(D) does not depend on h. When we compare hypotheses for the same dataset, we can drop it and compare P(D|h)P(h). The posterior is proportional to likelihood times prior. This is the whole engine: prior times likelihood, then normalize.

  • Prior P(h): domain knowledge or an earlier experiment. A doctor's belief that a disease is rare enters here.
  • Likelihood P(D|h): the probability of the exact data under h. For a coin with bias p, this is a binomial term.
  • Posterior P(h|D): the updated score. A strong prior can dominate a small dataset.

In concept learning, h can be a rule such as 'all mammals are warm-blooded' and D can be labelled examples. Bayes theorem ranks h without pretending the data speaks for itself. The Naive Bayes classifier in 3.3 applies this formula to features.

MAP and maximum likelihood

MAP (maximum a posteriori) picks the hypothesis with the largest posterior. Because P(D) is constant across h, we ignore it:

h_MAP = argmax_h P(D|h) P(h)

h_MAP is the chosen hypothesis; argmax_h means the h that makes the expression largest; P(D|h) is the likelihood; P(h) is the prior.

MLE (maximum likelihood estimation) ignores the prior and picks the hypothesis that makes the data most probable:

h_MLE = argmax_h P(D|h)

h_MLE is the maximum likelihood hypothesis; the other symbols are as above.

MLE is MAP with a uniform prior. If every h has the same P(h), the prior multiplies every score by the same constant and cannot change the winner. MAP adds a prior that can act like regularization: it pulls the answer toward plausible values when data are few. See Regularization: ridge and lasso.

The Bayes optimal classifier in 3.4 uses the full posterior over hypotheses, not only the MAP winner. MAP is a point estimate; it keeps one h.

Coin toss: binomial likelihood and MLE

A coin has unknown bias p, the probability of heads. Toss it n times and see k heads. If tosses are independent, the likelihood is:

P(D|p) = C(n,k) p<sup>k</sup> (1−p)<sup>n−k</sup>

n is the number of tosses; k is the number of heads; p is the probability of heads on one toss; C(n,k) = n! / (k!(n−k)!) is the binomial coefficient, the number of orders in which k heads can appear.

To find the MLE, maximize this expression over p. Take the log (same maximum), differentiate, set to zero:

p_MLE = k / n

p_MLE is the maximum likelihood estimate of the coin bias; k is the number of heads; n is the number of tosses.

This is parametric density estimation: we assume a family (Bernoulli or binomial) and estimate its parameter. With a Beta(α, β) prior on p, where α and β are positive prior pseudo-counts, the posterior is Beta(k+α, n−k+β). The MAP (mode) is (k+α−1)/(n+α+β−2). The posterior mean is (k+α)/(n+α+β). For Beta(1,1) the MAP is k/n, which matches MLE. The smoothed estimate (k+1)/(n+2) used in Laplace smoothing is the posterior mean with a Beta(1,1) prior, not the MAP. Some syllabi call MLE 'maximum likelihood estimation' and MAP 'maximum a posteriori'.

Worked example

Question. A coin is tossed n = 10 times and k = 7 heads appear. Two hypotheses are h1: p = 0.5 and h2: p = 0.8. The prior beliefs are P(h1) = 0.9 and P(h2) = 0.1. Compute P(D|h1), P(D|h2), the posterior scores P(D|h)P(h), the normalized posteriors, the MLE choice and the MAP choice. Also give the unrestricted MLE of p.

  1. Count orders: C(10,7) = 10!/(7!3!) = 120.
  2. P(D|h1) = 120 × (0.5)^10 = 120/1024 = 0.1171875.
  3. P(D|h2): (0.8)^7 = 0.2097152; (0.2)^3 = 0.008; product = 0.0016777216; times 120 = 0.201326592.
  4. Posterior score for h1 = 0.9 × 0.1171875 = 0.10546875.
  5. Posterior score for h2 = 0.1 × 0.201326592 = 0.0201326592.
  6. Normalizer P(D) = 0.10546875 + 0.0201326592 = 0.1256014092.
  7. Normalized posterior for h1 = 0.10546875 / 0.1256014092 = 0.8397; for h2 = 0.0201326592 / 0.1256014092 = 0.1603.
  8. MLE compares likelihoods: 0.201326592 > 0.1171875, so MLE picks h2 (p = 0.8).
  9. MAP compares posterior scores: 0.10546875 > 0.0201326592, so MAP picks h1 (p = 0.5). The prior 0.9 flips the decision.
  10. Unrestricted MLE of p = k/n = 7/10 = 0.7.

Answer. MLE chooses h2 (p = 0.8); MAP chooses h1 (p = 0.5); the unrestricted MLE of p is 0.7.

Exam traps

  • P(D|h) is the likelihood, not the posterior. The posterior is P(h|D) and includes the prior.
  • You can drop P(D) only when comparing hypotheses on the same data. If the data changes, the normalizer changes.
  • MLE ignores the prior, so for a rare disease it can over-call the disease, while MAP with a strong prior toward healthy may miss it. Decide which question is being asked.
  • C(n,k) counts orders, not probability. Do not multiply by n! again.
  • For a coin, p_MLE = k/n is the unrestricted estimate. If the question restricts you to two hypotheses, compare only those two likelihoods.

3.3 Naive Bayes classifier

Naive Bayes is a classifier that scores each class by its prior probability multiplied by the probability of every feature value in that class. It assumes features are independent once the class is known, so the joint probability becomes a simple product. This makes training fast: count feature values per class and multiply. It is a standard baseline for spam filtering, news topics, sentiment labels, medical screening and any high-dimensional text problem where a quick, explainable probability model is useful.

You need: 3.2 Bayes theorem, MAP and maximum likelihood estimation and the probability basics from Unit 1, Foundations.

The model and its independence assumption

Let C be the class label, such as Yes or No. Let x₁, ..., xₙ be the feature values of one record, such as Weather = Sunny and Wind = Strong. Bayes theorem gives:

P(C | x₁, ..., xₙ) = P(C) × P(x₁, ..., xₙ | C) ÷ P(x₁, ..., xₙ)

C is the class label; x₁, ..., xₙ are the feature values; P(C) is the prior; P(x₁, ..., xₙ | C) is the likelihood; P(x₁, ..., xₙ) is the evidence.

The denominator P(x₁, ..., xₙ) is the same for every class. It does not change which class wins, so we drop it. We need only a score:

score(C) = P(C) × Π P(xᵢ | C)

Π means product over i = 1 to n; xᵢ is feature i; score(C) is an unnormalized score for class C.

The exact joint likelihood P(x₁, ..., xₙ | C) needs counts for every feature combination. That grows exponentially. Naive Bayes assumes features are conditionally independent given C:

P(x₁, ..., xₙ | C) = Π P(xᵢ | C)

This is the conditional independence assumption: each feature is independent of the others once C is known.

Independence is a modelling assumption, not a claim about the world. Weather and Wind may be related, but the classifier still uses the product. This trade keeps parameters small: one table per feature per class. A full graph that allows dependence is 3.5 Bayesian belief networks. Some syllabi call this 'idiot Bayes' because the independence assumption is simple.

Counts, Laplace smoothing and Gaussian features

For a categorical feature, estimate each conditional probability by counting. Before smoothing:

P(xᵢ = a | C) = count(xᵢ = a, C) ÷ count(C)

a is a feature value; count(xᵢ = a, C) is the number of training rows with that value and class; count(C) is the number of rows of class C.

A zero count sends the whole product to zero. One unseen value then vetoes a class, even when other features support it strongly. Laplace smoothing adds a small constant α to every count and adds αV to the denominator:

P(xᵢ = a | C) = (count(xᵢ = a, C) + α) ÷ (count(C) + αV)

α is the smoothing constant; V is the number of possible values of feature i. α = 1 is common.

For a numeric feature, Gaussian Naive Bayes replaces counts by a normal density for each class:

P(xᵢ = v | C) = (1 ÷ √(2πσ²)) × exp(−(v − μ)² ÷ (2σ²))

v is the observed value; μ and σ² are the mean and variance of feature i among rows of class C; π is 3.14159...; exp is the exponential function.

Scoring, logs and decisions

Multiply many small probabilities and the score underflows. In practice add logs. Because log is increasing, the class with the highest log score is the same class.

log score(C) = log P(C) + Σ log P(xᵢ | C)

log is any fixed base, usually natural log; Σ is the sum over features; the largest log score gives the prediction.

The raw score is not a calibrated probability. To compare classes as probabilities, divide each score by the sum of scores over all classes:

P(C | x) ≈ score(C) ÷ Σ score(C′)

C′ runs over all classes; the result is a normalized score, not a guarantee of true probability.

Training has two passes: count classes and feature values, then smooth or fit means and variances. Prediction computes one score per class and returns the top class. This is why Naive Bayes is fast on a phone-sized model and easy to explain in an exam.

Worked example

Question. A weather dataset has six training days: (Sunny, Weak, Yes), (Rain, Weak, Yes), (Rain, Weak, Yes), (Sunny, Weak, Yes), (Sunny, Strong, No), (Rain, Strong, No). Classify the new day (Weather = Sunny, Wind = Strong) using Naive Bayes with Laplace smoothing α = 1. Weather has V = 2 values; Wind has V = 2 values. Give priors, smoothed conditionals, unnormalized scores and the predicted class.

  1. Count classes: Yes = 4, No = 2, total = 6. Priors: P(Yes) = 4/6 = 0.667 and P(No) = 2/6 = 0.333.
  2. Weather, V = 2. Yes rows: Sunny count 2. P(Sunny|Yes) = (2 + 1) ÷ (4 + 2) = 3/6 = 0.5. No rows: Sunny count 1. P(Sunny|No) = (1 + 1) ÷ (2 + 2) = 2/4 = 0.5.
  3. Wind, V = 2. Yes rows: Strong count 0. P(Strong|Yes) = (0 + 1) ÷ (4 + 2) = 1/6 = 0.167. No rows: Strong count 2. P(Strong|No) = (2 + 1) ÷ (2 + 2) = 3/4 = 0.75.
  4. Score Yes = 0.667 × 0.5 × 0.167 = 0.0556. Score No = 0.333 × 0.5 × 0.75 = 0.125.
  5. Compare: 0.125 > 0.0556, so predict No. Normalized posterior for No = 0.125 ÷ (0.125 + 0.0556) = 0.692.

Answer. Predict No; unnormalized scores are Yes = 0.0556 and No = 0.125, and the normalized posterior for No is about 0.692.

Exam traps

  • A zero count makes the whole product zero; smooth before comparing classes.
  • Independence is an assumption, not a fact. Correlated features double-count evidence and make scores overconfident.
  • Unnormalized scores are not probabilities. Normalize only when you need a probability, and remember the result is approximate.
  • Use the same V and α in training and prediction. Changing either changes the smoothed conditional values.
  • Gaussian Naive Bayes divides by variance; a constant feature within a class gives zero variance, so use a variance floor or drop that feature.

3.4 Bayes optimal classifier and Gibbs algorithm

The Bayes optimal classifier is the best possible classifier when you know the posterior over hypotheses. It does not pick one hypothesis. It lets every hypothesis vote for a label, and weights each vote by P(h|D), the probability that h is correct after seeing training data D. The result is P(c|x,D), the posterior probability of label c for test input x. It is an ideal because the full hypothesis space is usually too large to sum over. Gibbs is a randomised shortcut: draw one hypothesis from P(h|D) and predict with it. Bayesian learning theory uses both to reason about optimal and sampled decisions.

You need: Bayes theorem and posterior probability from 3.2.

The Bayes optimal rule

Let H be the set of all hypotheses under consideration. A hypothesis h is one possible classifier, such as one decision tree or one set of parameter values. After training on data D, Bayesian learning gives a posterior P(h|D) for each h. The Bayes optimal classifier does not choose one h. It asks: for a test input x, what is the probability of each label c?

P(c|x,D) = Σ_h P(c|x,h) P(h|D)

h is a hypothesis; H is the hypothesis space; D is the training data; x is the test input; c is a class label; P(h|D) is the posterior weight of h; P(c|x,h) is the vote of h for label c. For a deterministic classifier it is 1 when h predicts c and 0 otherwise.

The sum adds the posterior weights of all hypotheses that vote for c. The prediction is the label with the largest P(c|x,D). For two labels, P(No|x,D) = 1 - P(Yes|x,D). This is averaging over the whole hypothesis space, so it is an ideal. It is not the MAP hypothesis, which is argmax_h P(h|D). MAP keeps the single most probable h; Bayes optimal lets all h vote.

Gibbs algorithm

Gibbs algorithm is a randomised approximation. It draws one hypothesis h at random from the posterior P(h|D), then predicts h(x) for the test input x. The sampling rule is the whole algorithm.

  1. Compute or obtain the posterior P(h|D) for every hypothesis h in H.
  2. Draw one hypothesis h at random, with probability P(h|D).
  3. Use that one hypothesis to predict the label h(x) for the test input x.
  4. Repeat the draw for another prediction if a fresh random choice is wanted.

In the three-hypothesis example, h1 is drawn with probability 0.5, h2 with 0.3, h3 with 0.2. A different run may draw a different hypothesis. If h1 is drawn, the prediction is Yes; h2 gives No; h3 gives Yes. So Gibbs predicts Yes with probability 0.7 and No with 0.3. It is not a majority vote over hypotheses. It is also not sampling the label from P(c|x,D); it samples a hypothesis and then uses that hypothesis. Only a few universities teach Gibbs in detail, so know the sampling rule and that it is randomized.

Why the ideal is useful

Why use an ideal that cannot be computed? It gives a target. The Bayes optimal error is the smallest possible average 0-1 error for the given hypothesis space and prior. Any real classifier, such as Naive Bayes or a decision tree, can be compared with it in theory. The formula also explains model averaging: many models weighted by how likely they are after data can beat one model. Ensembles do this in practice, but they are not exact Bayes optimal; see 3.8. In real problems the sum over H is too large, so we approximate by sampling, variational methods or a single MAP model. The Bayes optimal classifier also reminds us that uncertainty over hypotheses matters. A confident MAP model can be wrong when many less likely hypotheses vote for another label.

Worked example

Question. Three hypotheses remain after training: P(h1|D)=0.5, P(h2|D)=0.3, P(h3|D)=0.2. On a test input x, h1 and h3 predict Yes, while h2 predicts No. (a) Compute the Bayes optimal posterior P(Yes|x,D) and P(No|x,D), and state the predicted label. (b) For the Gibbs algorithm, give the probability that it predicts Yes and No. (c) Explain why the Gibbs answer is not a new posterior calculation.

  1. Bayes optimal sums posterior weights of hypotheses that vote Yes. The Yes-voters are h1 and h3.
  2. P(Yes|x,D) = P(h1|D)×1 + P(h2|D)×0 + P(h3|D)×1 = 0.5 + 0 + 0.2 = 0.7.
  3. P(No|x,D) = P(h2|D)×1 = 0.3. Check: 0.7 + 0.3 = 1.0.
  4. The larger value is 0.7, so Bayes optimal predicts Yes.
  5. Gibbs draws one hypothesis with probabilities P(h1|D)=0.5, P(h2|D)=0.3, P(h3|D)=0.2. It predicts Yes when h1 or h3 is drawn: 0.5 + 0.2 = 0.7. It predicts No when h2 is drawn: 0.3.
  6. Gibbs does not compute a posterior over labels. It samples a hypothesis and uses that hypothesis; the Yes probability 0.7 is the total posterior mass of hypotheses that output Yes.

Answer. Bayes optimal predicts Yes with P(Yes|x,D)=0.7 and P(No|x,D)=0.3; Gibbs predicts Yes with probability 0.7 and No with probability 0.3.

Exam traps

  • Bayes optimal is not the MAP hypothesis. MAP picks the single most probable h; Bayes optimal averages every h and may choose a different label.
  • Gibbs is not majority vote. It draws one hypothesis from the posterior and uses that hypothesis; its prediction is random across runs.
  • P(c|x,D) is a posterior probability over labels, not over hypotheses. Do not sum P(h|D) as if it were P(c|D).
  • A high posterior for one hypothesis does not make it the Bayes optimal label for every x. The vote P(c|x,h) depends on x.
  • Do not confuse Bayes optimal classifier with Naive Bayes. Naive Bayes is one restricted hypothesis with an independence assumption.

3.5 Bayesian belief networks

A Bayesian belief network (Bayes net) is a directed acyclic graph whose nodes are random variables. Each node stores a conditional probability table for itself given its parents. The graph gives a compact way to write one large joint probability as a product of small local factors. It is used in diagnosis, fault finding, risk analysis and spam filtering, where causes and effects are linked and evidence arrives piece by piece. This chapter shows the product rule, the independence the graph encodes, and inference by enumeration and variable elimination.

You need 3.2 Bayes theorem and conditional probability from Unit 1.

Graph and joint distribution

A Bayesian belief network is a directed acyclic graph. Each node is a random variable Xi. An arrow points from a parent to a child and says the parent directly affects the child. Acyclic means no directed loop: following arrows never returns to the same node.

Each node stores a conditional probability table (CPT). The CPT gives P(Xi | parents(Xi)) for every parent combination. A root node has no parents, so its table is P(Xi).

P(X<sub>1</sub>,…,X<sub>n</sub>) = Π<sub>i</sub> P(X<sub>i</sub> | parents(X<sub>i</sub>))

P(X1,…,Xn) is the joint probability of one full assignment; parents(Xi) is the set of parent values of node i; the product runs over all n nodes.

The product is compact. A full joint table for n binary variables needs 2ⁿ − 1 numbers. A Bayes net with at most k parents per node needs about n·2ᵏ numbers. This saving is why the graph exists.

For the fear–study–pass chain, P(F)=0.3. The Study CPT has P(S|F)=0.8 and P(S|¬F)=0.5. The Pass CPT has P(P|S)=0.9 and P(P|¬S)=0.3. One joint entry is P(F=true, S=true, P=true)=0.3×0.8×0.9=0.216.

Conditional independence and graph reading

Conditional independence means X and Y are independent given Z when P(X,Y|Z)=P(X|Z)P(Y|Z). A Bayes net encodes a local rule: each node is independent of its non-descendants given its parents. This is the Markov condition.

In the chain Fear → Study → Pass, Study blocks the path. Given Study, Fear and Pass are independent: P(Pass | Study, Fear)=P(Pass | Study). Without conditioning on Study, Fear and Pass are dependent. The arrow directions give the factorization; they need not prove causation.

To build a Bayes net from a problem description:

  1. List the random variables and their possible values.
  2. Add an arrow from each direct parent to its child.
  3. Check that no directed cycle exists.
  4. Write one CPT for each node from its parents.
  5. Read the joint as the product of all CPTs.

Some syllabi call this a Bayes net or belief network.

Inference: enumeration and variable elimination

Inference computes a query probability from the joint, given evidence. Evidence fixes some variables. Hidden variables are summed out. With query Q and evidence E=e:

P(Q | E=e) = α Σh P(Q, E=e, h)

α=1/P(E=e) normalises the result; h ranges over all assignments of the hidden variables; P(Q,E=e,h) is read from the joint product.

Enumeration repeats many sums. Variable elimination pushes each sum inward. A factor is a table over a set of variables. Multiply all factors that contain the hidden variable, then sum that variable out. The order matters: a good order keeps intermediate factors small.

  1. Write the joint as a product of CPT factors.
  2. Fix every evidence variable to its observed value.
  3. Pick a hidden variable, multiply its factors, sum it out, and keep the new factor.
  4. Repeat until only query and evidence variables remain.
  5. Multiply the remaining factors and divide by P(E=e).

For P(Pass) in the chain, eliminate Fear first: ΣF P(F)P(S|F) gives P(S). Then eliminate Study: ΣS P(S)P(Pass|S) gives P(Pass). The next example computes both values.

3.6 k-nearest neighbour and instance-based learning

k-nearest neighbour (kNN) keeps the training examples and their labels. To classify a new query, it measures how far the query is from each stored example, picks the k closest ones, and returns the majority label. It builds no equation or tree before prediction. It is used in image search, simple recommendation, medical screening baselines and handwritten digit recognition. Its weakness is cost at prediction time and sensitivity to feature scale.

You need: Unit 1 on distance and data representation; Unit 2 on cross-validation for choosing k.

Store now, decide later

kNN stores a training set D = {(xi, yi)}. Each xi is a feature vector and yi is its class label. A query x is classified only when it arrives. No parameters are fitted before that. This is why some syllabi call kNN instance-based learning or memory-based learning.

d(x, x<sub>i</sub>) = √(Σ<sub>j=1</sub><sup>p</sup> (x<sub>j</sub> − x<sub>ij</sub>)<sup>2</sup>)

d is the Euclidean distance; xj is the query's j-th feature; xij is stored example i's j-th feature; p is the number of features.

  1. Store every training pair (xi, yi).
  2. Choose a positive integer k.
  3. For a query x, compute d(x, xi) to every stored point.
  4. Sort the distances and keep the k smallest.
  5. For classification, take the majority label among those k; for regression, take their mean y.
  6. Optional: weight each neighbour by 1/d or 1/(d+ε).

For two classes, an odd k avoids a tie. With k = 1, every stored point owns a region: a query in that region is closer to that point than to any other. These regions are Voronoi cells.

Choosing k and weighting votes

Small k follows local detail and can fit noise. Large k smooths across many points and can wash out a small class. Choose k by cross-validation on training folds, never on the test set. A common starting point is a small odd number, then tune it.

ŷ = argmax<sub>c</sub> Σ<sub>i∈N<sub>k</sub>(x), y<sub>i</sub>=c</sub> w<sub>i</sub>

ŷ is the predicted class; Nk(x) is the set of k nearest stored points; c is a class label; wi is the neighbour's weight.

Distance-weighted kNN uses wi = 1/d(x, xi), or wi = 1/(d+ε) with a tiny ε > 0 to avoid division by zero. A close neighbour then counts more than a far one. For regression, return the weighted mean of the neighbours' y values. For a local linear fit instead of a local vote, see Chapter 3.9.

Scale and the shape of the boundary

Features carry units. A salary in rupees may range from 10,000 to 1,00,000; age ranges from 18 to 70. Squared salary differences are about 106 times larger (up to 8.1 × 109 against about 2.7 × 103), so Euclidean distance ignores age. Standardise each feature before kNN: z = (x − μ)/σ, where μ is the training mean and σ is the training standard deviation. Use the same μ and σ for the query.

kNN is non-parametric: it does not fix a small set of coefficients. Its boundary can follow any shape, but it needs the training data at prediction time. For 1NN the plane is cut into Voronoi cells: every query in a cell is closer to that cell's stored point than to any other. In high dimensions many distances become similar; see Unit 4, principal component analysis, for reducing dimensions. A large-margin alternative is support vector machines.

3.7 Support vector machines: maximum margin and kernels

A support vector machine (SVM) classifies points by drawing the separating line or plane that leaves the widest empty gap around it. The widest gap is the maximum margin, and the few points that touch the gap are the support vectors. A kernel lets the same method draw curved boundaries without listing the curved features explicitly. SVMs are used in text classification, spam filtering, handwritten digit recognition and small-data problems where a clear boundary matters. This chapter builds the linear SVM, adds slack for noisy data, then replaces dot products with kernels.

You need Unit 2 linear classifiers and logistic regression for the boundary score, and Unit 1 vectors and dot products for w·x; compare the stored-example view in 3.6.

The maximum-margin hyperplane

Start with two classes and labels y_i ∈ {−1,+1}. A linear classifier uses a hyperplane w·x+b=0. Here x is the feature vector, w is the weight vector, b is the bias, and w·x is the dot product. The sign of w·x+b gives the predicted class. In two dimensions the hyperplane is a line; in higher dimensions it is a plane or flat surface.

Many lines can separate the same data. The SVM picks the one with the largest margin: the widest empty strip between the classes, measured perpendicular to the boundary. For the canonical form, scale w and b so the closest positive point gives w·x_i+b=+1 and the closest negative point gives w·x_i+b=−1. Then every point must satisfy y_i(w·x_i+b) ≥ 1.

minimize ½||w||² subject to y_i(w·x_i+b) ≥ 1 for all i

||w|| is the length of w, y_i is the true label (+1 or −1), x_i is a training feature vector, b is the bias, and the constraint says each point is on its correct side and outside the margin.

The distance from a point to the boundary is |w·x_i+b| / ||w||. At a support vector this equals 1/||w||. The full margin from the negative support vector to the positive one is therefore 2/||w||. Maximising 2/||w|| is the same as minimising ½||w||², which is the form above. The points where y_i(w·x_i+b)=1 are the support vectors. They alone fix the boundary; other points can move without changing it.

Soft margin and the dual

Real data has noise and overlap. The hard margin above then has no solution. The soft margin adds a slack variable ξ_i ≥ 0 for each point. A point may sit inside the margin or on the wrong side, and ξ_i records how far the constraint is broken. The new problem is:

minimize ½||w||² + C Σ ξ_i subject to y_i(w·x_i+b) ≥ 1 − ξ_i and ξ_i ≥ 0

ξ_i (xi) is the slack for point i, C > 0 is the cost of slack, and Σ is over all training points. A large C punishes slack heavily and gives a narrow margin; a small C allows more slack and a wider margin.

This is a quadratic programming (QP) problem: a quadratic objective with linear constraints. The dual form introduces one multiplier α_i ≥ 0 per training point. It uses only dot products x_i·x_j, and the solution has w = Σ α_i y_i x_i. Most α_i become zero; the nonzero ones are the support vectors. Some syllabi show the QP dual and ask for its form, not a hand solve. The dual also shows why kernels enter: if the data appear only as dot products, we can replace each dot product by a kernel value.

Kernels: curved boundaries without curved features

A linear boundary is limiting. A kernel function K(x,z) returns the dot product of two points after a mapping φ: K(x,z)=φ(x)·φ(z). The SVM never needs φ(x) explicitly; it only needs K values inside the dual. This is the kernel trick. The boundary in the original space can be curved even though the boundary in the mapped space is flat.

  • Polynomial kernel: K(x,z)=(x·z+1)^d. d is the degree. d=1 gives a linear SVM; higher d allows curved boundaries.
  • RBF kernel: K(x,z)=exp(−γ||x−z||²). γ (gamma) controls width. Large γ makes each point's influence narrow; small γ makes it broad.
  • Linear kernel: K(x,z)=x·z, the plain dot product.

A kernel computes similarity between two examples. If two points are close under the kernel, they push each other's classification in the same direction. For RBF, γ>0 must be set; it is not learned by the basic SVM. The polynomial degree d and RBF γ are hyperparameters chosen by cross-validation, see Unit 2. Kernel SVMs are used for text, images, and small biological datasets. They can be slow on very large data because the dual compares pairs of points.

3.8 Ensembles: bagging, boosting and random forests

One decision tree can change a lot when the training data changes a little. An ensemble trains several models and combines their answers. Bagging and random forests average many trees trained on random copies of the data; this cuts variance. Boosting trains models one after another, giving more weight to examples that earlier models got wrong; this cuts bias. Banks use random forests to flag risky loans, hospitals use them in disease screening, and fraud teams use boosting on UPI transaction streams. This chapter shows the three methods and the arithmetic behind AdaBoost.

You need: decision trees (Chapter 3.1) and the bias-variance trade-off with cross-validation (Unit 2).

Bagging: average bootstrap models

Bagging means bootstrap aggregating. It trains B base models on B random copies of the training set. Each copy, called a bootstrap sample, has the same size N as the original. Rows are picked with replacement: one row can appear many times, and about 37% of rows are left out of a given copy. B is the number of models, a chosen value such as 100.

For a new point, classification takes a majority vote; regression averages the outputs. A single deep tree can swing when one training row changes. Averaging many trees smooths that swing. This mostly reduces variance, the error from sensitivity to the training sample. It leaves bias, the error from a model that is too simple, roughly unchanged.

Var(average) = σ² / B

σ² is the variance of one base model and B is the number of models. Real bagged models are correlated, so the fall is smaller than this ideal.

The left-out rows are out-of-bag (OOB) examples for that tree. They give a free error estimate. Never report accuracy on the bootstrap rows only: the trees have already seen those rows. In a bank loan model, bagged trees vote on default risk; one tree's odd split matters less.

Random forests: decorrelate the trees

A random forest is a bagged set of decision trees with one extra rule: at every split, the tree may choose only from a random subset of m features out of all d features. A common default is m = √d for classification. Each tree is grown deep, often without pruning. Prediction is a majority vote or average.

Why the extra rule? If one feature is very strong, every bagged tree splits on it near the root. The trees then look alike and make the same mistakes. Their average is still correlated. Restricting features at each node forces different trees to use different evidence. Less correlation means the average has lower variance than plain bagging.

The feature subset is chosen at each split, not once per tree and not only by sampling rows. Out-of-bag error still works. Random forests are a standard first choice for tabular data: disease screening, credit scoring, and sensor fault detection. They handle mixed feature types and need little scaling. A student project may use a forest for diabetic retinopathy screening or zoonotic disease detection, where many weak risk factors combine.

Boosting and AdaBoost: focus on mistakes

Boosting trains models in sequence. Each new model looks at the examples the earlier ones handled badly. AdaBoost is the classic binary version. Labels are y_i in {−1, +1}. Start with equal weights w_i = 1/N, where N is the number of examples and w_i is the importance of example i.

ε_t = Σ_i w_i·1[h_t(x_i) ≠ y_i] ; α_t = ½ ln((1 − ε_t)/ε_t)

ε_t is the weighted error of weak classifier h_t; 1[...] is 1 when the condition is true and 0 otherwise; α_t is the classifier's vote weight; ln is the natural logarithm.

Round t trains h_t on the weighted examples. h_t only needs to be slightly better than chance. If ε_t = 0.5, then α_t = 0 and the model gets no vote. If ε_t > 0.5, α_t is negative; the classifier is worse than chance, so flip its labels or stop.

After the round, multiply the weight of every wrong example by e^{α_t} and every correct example by e^{−α_t}. Then divide all weights by their sum so they add to 1. Wrong examples become heavier, so the next classifier pays more attention to them. The final prediction is sign(Σ_t α_t h_t(x)): each classifier votes, and α_t sets how loud its vote is.

Boosting mainly reduces bias: a sequence of weak rules can fit a curved boundary. Too many rounds can fit label noise, so watch validation error and stop early. AdaBoost is used in face detection and fraud screening, where many simple rules combine into a strong one.

Worked example

Question. Four points are (x=1, y=+1), (x=2, y=+1), (x=3, y=−1), (x=4, y=−1). AdaBoost starts with w_i = 1/4. A weak classifier h predicts +1 for x ≤ 3 and −1 for x > 3. Run one round: find ε, α, the raw updated weights, the normalized weights, and the vote weight of h.

  1. N = 4, so each initial weight is w_i = 0.25.
  2. h is correct at x = 1, 2, 4 and wrong at x = 3.
  3. ε = 0.25, because only the wrong point contributes its weight.
  4. α = 0.5 ln((1 − 0.25)/0.25) = 0.5 ln 3 = 0.5493.
  5. Raw weights: wrong x = 3: 0.25 e^{0.5493} = 0.4330. Each correct point: 0.25 e^{−0.5493} = 0.1443.
  6. Sum = 0.4330 + 3 × 0.1443 = 0.8660.
  7. Normalized: x = 3: 0.4330/0.8660 = 0.5000. x = 1, 2, 4: 0.1443/0.8660 = 0.1667 each.
  8. With one classifier the ensemble prediction is h; its vote weight is α = 0.5493. It still misclassifies x = 3, but the next round will focus there.

Answer. ε = 0.25 and α = 0.5493; after normalization x = 3 has weight 0.5000 and x = 1, 2, 4 have weight 0.1667 each.

Exam traps

  • Bagging draws bootstrap samples with replacement; boosting changes example weights. Bagging does not use misclassification weights.
  • A random forest chooses a random feature subset at each split, not just a random row sample. It is not bagging plus one fixed feature.
  • Do not report accuracy on the bootstrap samples. Those rows are memorized. Use out-of-bag examples or a separate validation set.
  • In AdaBoost, α = ½ ln((1 − ε)/ε) is the vote weight, not the updated example weight. The example weight multiplies by e^{α} for errors and e^{−α} for correct points.
  • Boosting can overfit noisy labels if run too many rounds. More rounds lower bias but not always test accuracy; use validation or early stopping.

3.9 Locally weighted regression, RBF networks, case-based reasoning

Nearest-neighbour methods assume the answer changes slowly near the query. Local methods keep that assumption but do more than vote. Locally weighted regression fits a fresh small model around each query. A radial basis function network adds up fixed Gaussian bumps at chosen centres. Case-based reasoning stores whole solved problems and adapts the closest one. You meet them in house-price estimates, soft sensors in process plants, and help-desk systems that suggest the fix used on a similar ticket.

You need: 3.6 kNN for the neighbour idea, and weighted least squares from Unit 2, Regression and Model Evaluation.

Locally weighted regression

kNN predicts by averaging the labels of nearby training points. When the target rises or falls steadily with x, a straight line through those neighbours beats a flat average. Locally weighted regression (LWR) does that: for each query x it fits a fresh weighted model, giving nearby training points more say than distant ones.

w_i = exp(−(x_i − x)² / (2τ²))

x_i is a training input, x is the query, τ is the bandwidth (same units as x, τ > 0), and w_i is the weight of training point i. w_i lies between 0 and 1, and w_i = 1 when x_i = x.

τ sets the width of the neighbourhood. A small τ lets only very close points count, so the fitted curve can wiggle and follow noise. A large τ makes all weights close to 1, and LWR turns into ordinary least squares over the whole data set.

  1. Store every training pair (x_i, y_i) and fit nothing in advance — LWR is a lazy learner.
  2. For a query x, compute w_i for every training point.
  3. Minimise Σ w_i (y_i − a − b·x_i)² to get a local straight line.
  4. Predict a + b·x at the query.
a = (S_y·S_xx − S_x·S_xy) / (S·S_xx − S_x²),  b = (S·S_xy − S_x·S_y) / (S·S_xx − S_x²)

S = Σ w_i, S_x = Σ w_i x_i, S_xx = Σ w_i x_i², S_y = Σ w_i y_i, S_xy = Σ w_i x_i y_i; a is the local intercept and b the local slope.

Each query rebuilds the sums and solves a small linear system, roughly O(n·d²) work for n points and d features, so LWR is slow when queries arrive fast. The training data must also stay available at prediction time.

Radial basis function networks

An RBF network places a few Gaussian bumps in input space and learns how much each contributes to the output. Hidden units compute bumps; the output unit is linear.

φ_j(x) = exp(−||x − μ_j||² / (2σ_j²)),   y(x) = b + Σ_j w_j φ_j(x)

μ_j is the centre vector of hidden unit j, σ_j is its width, ||·|| is Euclidean distance, φ_j(x) is that unit's activation (between 0 and 1), w_j is its output weight, and b is a bias.

Each hidden unit answers one question: how close is the query to my centre? Because the output is linear in w_j, the weights come from ordinary least squares once centres and widths are fixed.

  1. Choose centres: random training points, a grid, or k-means on the inputs (Unit 4, K-means clustering).
  2. Set each width, for example to the average distance to the nearest centres.
  3. Solve least squares for w_j and b, using the activations as features.
  4. Predict with one dot product.

LWR puts one bump on every training point and refits at every query. An RBF network keeps a handful of fixed bumps and one weight vector shared by all queries, so prediction is a short sum. That speed is why RBF networks appear in soft sensors, control loops and small classifiers. Only some syllabi teach them here; others leave them for Unit 5.

Case-based reasoning

Case-based reasoning (CBR) solves a new problem by remembering old ones. A case stores the problem, the solution that was used, and the outcome. Nothing is compressed into a model; the cases themselves are the knowledge.

  1. Retrieve: score stored cases with a similarity measure and take the k closest (see 3.6 kNN).
  2. Reuse: copy the best case's solution, or adapt it to the differences.
  3. Revise: test the proposed solution, in simulation or with a human, and repair it if it fails.
  4. Retain: store the new problem and its verified solution as a case.

The similarity measure decides quality. For numeric features use a weighted Euclidean distance; for symbolic features count matching attributes or use distance in a taxonomy. Weights come from domain experts, so scaling matters: a salary in rupees must not swamp an age in years.

Example: a bank's loan desk keeps past applications with their repayment outcomes. A new application is matched to similar past ones and a decision is proposed, then reviewed. CBR is easy to explain because you can show the retrieved case, and it learns from a single new example. Its costs are case-base upkeep — duplicates, outdated cases — and weak generalisation when nothing similar is stored.

Worked example

Question. Training points are (x=0, y=1), (x=1, y=2) and (x=2, y=4). Use locally weighted regression with a Gaussian weight and bandwidth τ = 1 to predict y at the query x = 1. Use a local straight line y = a + b·x. Find the three weights, the weighted sums, a, b and the prediction.

  1. Weights: w_i = exp(−(x_i − 1)²/2). w_0 = exp(−0.5) = 0.607, w_1 = exp(0) = 1.000, w_2 = exp(−0.5) = 0.607.
  2. S = 0.607 + 1.000 + 0.607 = 2.213.
  3. S_x = 0.607(0) + 1.000(1) + 0.607(2) = 2.213.
  4. S_xx = 0.607(0) + 1.000(1) + 0.607(4) = 3.426.
  5. S_y = 0.607(1) + 1.000(2) + 0.607(4) = 5.033.
  6. S_xy = 0.607(0)(1) + 1.000(1)(2) + 0.607(2)(4) = 6.852.
  7. det = S·S_xx − S_x² = 2.213 × 3.426 − 2.213² = 7.582 − 4.898 = 2.685.
  8. a = (S_y·S_xx − S_x·S_xy)/det = (5.033 × 3.426 − 2.213 × 6.852)/2.685 = (17.242 − 15.164)/2.685 = 0.774.
  9. b = (S·S_xy − S_x·S_y)/det = (2.213 × 6.852 − 2.213 × 5.033)/2.685 = (15.164 − 11.138)/2.685 = 1.500.
  10. Prediction at x = 1: y = 0.774 + 1.500 = 2.274.

Answer. The local linear fit is y = 0.774 + 1.500x, giving a prediction of 2.274 at x = 1.

Exam traps

  • LWR is lazy: no model exists until a query arrives, and the weights and fit are recomputed for every query. Never describe it as trained once in advance.
  • An RBF network is not the SVM RBF kernel of 3.7. The SVM uses the Gaussian form as a similarity between points inside a margin maximiser; the RBF network has explicit centres and learned output weights.
  • LWR, τ too large: every weight is nearly 1, so the local fit collapses to one global straight line and misses curvature. τ too small: the curve follows noise.
  • RBF network, σ too large: every bump flattens, activations approach 1, the output barely changes with x, and the network loses all locality — a nearly constant, over-smooth function. σ too small: bumps are very narrow, activations fall to near 0 between centres, the design matrix turns ill-conditioned, and predictions go spiky away from the centres.
  • Gaussian weights are similarities, not probabilities. They do not sum to 1, and all of them can be tiny when the query is far from every training point.
  • CBR fails quietly when the similarity measure is wrong: unscaled features or renamed attributes make retrieval return cases that look close but are not. Fix scaling and weights before blaming the case base.

Beyond the syllabus

Not for the exam. Gaussian process regression is the Bayesian version of LWR: instead of one weighted fit per query it returns a mean and a variance, so the model states how unsure it is. RBF networks were a stepping stone to kernel methods. CBR survives in recommender systems and in maintenance logs that suggest the fix used for a similar machine.

Takeaways

  1. ID3 chooses the split that removes the most entropy, and information gain is the number it maximises.
  2. Bayes theorem turns a prior plus a likelihood into a posterior; MAP keeps the prior, MLE drops it.
  3. Naive Bayes is fast and needs little data because it multiplies one probability per feature instead of modelling their interactions.
  4. The Bayes optimal classifier is the best you can do given the hypothesis space, but it is usually too expensive to compute.
  5. A Bayesian belief network stores a large joint distribution compactly as local conditional tables on a DAG.
  6. kNN is accurate but slow at prediction time and stores the whole training set.
  7. An SVM maximises the margin, so only the support vectors decide the boundary, and kernels make it non-linear.
  8. Bagging and random forests average away variance; boosting drives down bias by fixing mistakes.
  9. Local methods such as kNN, RBF networks and locally weighted regression fit the query point, not the whole dataset.

Glossary

AdaBoost
A boosting algorithm that reweights misclassified examples upward and gives each weak learner a vote based on its accuracy.
Bayes optimal classifier
The classifier that predicts the class with the highest posterior probability averaged over all hypotheses.
Bayesian belief network
A directed acyclic graph whose nodes are random variables and whose edges encode direct conditional dependence.
Bootstrap sample
A sample of the same size as the training set, drawn with replacement so some rows appear more than once.
Case-based reasoning
Solving a new problem by retrieving a similar stored case and adapting its known solution.
Conditional probability table
The table at a network node listing the probability of each value of that node for every combination of its parents.
Curse of dimensionality
The loss of meaning of distance as dimensions grow, because points become almost equidistant from each other.
Entropy
A measure of the impurity of a labelled set, zero when all labels agree and largest when they are evenly mixed.
Evidence
The term P(D) in Bayes theorem, a normalising constant that makes posteriors sum to one.
Gibbs algorithm
A randomised learner that samples one hypothesis by its posterior and predicts with that hypothesis only.
Information gain
The expected reduction in entropy obtained by splitting a set on one attribute.
k-nearest neighbour
A classifier that assigns a query the majority label among the k stored training points closest to it.
Kernel function
A similarity function that equals a dot product in some feature space, letting a linear method act non-linearly.
Laplace smoothing
Adding a small count to every feature value so that unseen combinations do not get probability zero.
Likelihood
The probability of the observed data under a given hypothesis, treated as a function of the hypothesis.
Margin
The distance between the separating hyperplane and the closest training points on either side, equal to 2/‖w‖.
Maximum a posteriori
Choosing the parameter or hypothesis with the largest posterior probability.
Maximum likelihood estimation
Choosing the parameter value that makes the observed data most probable, ignoring the prior.
Naive Bayes classifier
A classifier that multiplies a class prior by per-feature likelihoods, assuming features are independent given the class.
Posterior probability
The updated probability of a hypothesis after the data is taken into account.
Prior probability
The probability assigned to a hypothesis or class before any evidence is observed.
Pruning
Removing unhelpful subtrees from a grown tree to reduce overfitting on unseen data.
Random forest
A collection of decision trees, each grown on a bootstrap sample and split on a random subset of features, combined by vote.
Splitting attribute
The attribute chosen at a tree node, namely the one with the highest information gain or lowest Gini impurity.
Support vector
A training point that lies on or inside the margin and therefore fixes the SVM boundary.
Voronoi diagram
The partition of the feature space into regions, each region holding the points closer to one training example than to any other.
