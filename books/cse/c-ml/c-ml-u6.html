6.1 Reinforcement learning: agents, states, actions and rewards

Reinforcement learning is learning what to do through interaction. An agent chooses actions, observes their consequences and uses numerical rewards to improve later decisions. Its aim is a good sequence of outcomes, so an action with an immediate cost can still be worthwhile.

You need: probability and the distinction between learning types from Unit 1, Foundations: Learning Problems and Concepts.

The interaction and the Markov state

At time t, the agent receives state Sₜ, selects action Aₜ and receives reward Rₜ₊₁ together with next state Sₜ₊₁. The environment is everything outside the decision maker that determines these consequences. A warehouse trolley is an agent; its position and battery charge can form a state; move, wait and recharge are actions. A reward might combine timely delivery with a penalty for energy use. These are modelling choices, not properties automatically supplied by a dataset.

A state is a representation of the information needed for predicting the next transition. The Markov property says that, given the current state and action, earlier history supplies no additional predictive information. Position alone is inadequate when battery charge changes whether a move succeeds. Adding charge can repair that omission. A camera observation is not necessarily a full state; hidden obstacles or unobserved demand can make the problem partially observable.

A finite Markov decision process, or MDP, specifies a state set S, an available-action set A(s), a transition-and-reward distribution p(s′, r | s, a), and a discount factor γ. Here s′ denotes a possible next state and r a possible reward. The probability distribution describes uncertainty even when the policy is deterministic. A policy π(a | s) gives the probability of choosing action a in state s. A deterministic policy chooses one action for each state.

Reward, return and value

Reward is the immediate scalar feedback. Return is the accumulated objective. For a task ending at time T, the discounted return from time t is Gₜ = Rₜ₊₁ + γRₜ₊₂ + … + γ^(T−t−1)R_T. The factor γ, with 0 ≤ γ ≤ 1, controls the weight of later rewards. For a continuing task, using γ < 1 with bounded rewards makes the infinite discounted sum finite. An undiscounted episodic task can instead use γ = 1 when its expected total reward is well defined.

The state value vπ(s) is the expected return starting in state s and then following policy π. The action value qπ(s, a) is the expected return after first taking action a in s and then following π. Expectation matters: one lucky journey does not establish a high value. The optimal action value q*(s, a) is the greatest achievable expected return under the task's assumptions. A greedy optimal policy selects an action with the largest q* value.

The Bellman expectation relation is vπ(s) = Σₐ π(a | s) Σₛ′,ᵣ p(s′, r | s, a)[r + γvπ(s′)]. The first sum averages action choices; the second averages environmental outcomes. The bracket separates one immediate reward from the discounted value of what follows. A terminal state's future value is zero. This relation links long sequences through one-step transitions; it does not require future rewards to be available immediately.

Learning through decisions

Exploration tries actions to obtain information. Exploitation uses current estimates to obtain reward. Always choosing the present favourite can leave a better action untried. An ε-greedy policy chooses a random available action with probability ε and a greedy action otherwise. The random branch can choose the greedy action too. Exploration may incur real costs, so a physical system needs safe action restrictions rather than unrestricted experiments.

Model-based learning estimates or uses transition probabilities and rewards, then plans with that model. Model-free learning estimates values or policies directly from experience. Temporal-difference learning is a model-free value-learning method that updates an estimate using another estimate. Its one-step prediction error is δₜ = Rₜ₊₁ + γV(Sₜ₊₁) − V(Sₜ), where V is the current state-value table. The update V(Sₜ) ← V(Sₜ) + αδₜ uses learning rate α. Chapter 6.2 applies the same bootstrapping idea to action values.

  1. Specify the state, legal actions, terminal condition and reward before choosing an algorithm.
  2. Collect transitions while balancing information gathering with useful decisions.
  3. Update values or the policy and evaluate performance on separate runs.
  4. Check whether the resulting behaviour matches the intended task, including rare failures.

Worked example

A trolley has two deterministic routes to a terminal delivery. Route A gives rewards −2, −2 and +10 over three transitions. Route B gives +4 and terminates immediately. With γ = 0.9, which route has greater return?

For A, G₀ = −2 + 0.9(−2) + 0.9²(10) = −2 − 1.8 + 8.1 = 4.3 reward units. For B, G₀ = 4 reward units. Thus A is better by 0.3 reward units, although its first reward is lower. If γ = 0.5, A gives −2 − 1 + 2.5 = −0.5, while B still gives 4. The preferred route depends on the stated objective.

Now suppose V(start) = 3, V(next) = 5, the observed reward is −2, γ = 0.9 and α = 0.2. The TD target is −2 + 0.9(5) = 2.5; the error is 2.5 − 3 = −0.5. The updated value is 3 + 0.2(−0.5) = 2.9 reward units. One transition lowers the estimate; it does not prove that the route is poor on average.

Exam traps

  • Do not confuse a reward received now with the sum of future rewards.
  • A state must contain predictive information; an observation need not satisfy the Markov property.
  • The terminal reward is included once; no future value is added after termination.
  • A model-free algorithm can still maintain a value table; model-free does not mean memory-free.

6.2 Q-learning algorithm

Q-learning learns an action-value table from sampled transitions. It moves each estimate towards the observed reward plus the best estimated continuation value. The table can guide decisions without an explicit transition model.

You need: states, returns and exploration from Chapter 6.1.

The update and its meaning

Write Q(s, a) for the current estimate of the optimal return from taking action a in state s. For an observed transition (s, a, r, s′), the nonterminal target is y = r + γ max_b Q(s′, b). Here b ranges over legal actions in the next state, γ is the discount factor and r is the reward just received. The temporal-difference error is δ = y − Q(s, a). The update is Q(s, a) ← Q(s, a) + αδ, where α is the learning rate.

Equivalently, the new estimate is (1 − α)Q(s, a) + αy. This form shows that for 0 < α ≤ 1 the update moves towards the target without overshooting it. Only the visited state-action entry changes in a tabular update. The maximum is taken over next-state actions, not current-state actions. If s′ is terminal, set y = r: there is no next decision and therefore no bootstrapped continuation value.

The Bellman optimality equation averages r + γ max_b q*(s′, b) over possible outcomes. Q-learning replaces that environmental expectation by sampled outcomes. An individual update can be noisy and can even reduce a useful action's estimate. Repeated exploration and appropriate learning rates are needed to average experience. A large reward on one trial is evidence, not an exact expected value.

Behaviour, target and stopping

Q-learning is off-policy because its update targets the greedy continuation while the behaviour policy may explore. With ε-greedy behaviour, the agent sometimes takes an action other than the present maximum. Nevertheless, the target still uses max_b Q(s′, b). SARSA instead uses the value of the actual next action selected by its behaviour policy. For that comparison, SARSA's target is r + γQ(s′, a′), where a′ is that selected action. A question asking for Q-learning needs the maximum even when the recorded next action is exploratory.

  1. Create one value for every legal state-action pair, often initialized to zero.
  2. Start an episode in its initial state and select an action with the behaviour policy.
  3. Execute the action and record reward, next state and whether the task ended.
  4. Form the terminal or nonterminal target and update only the selected entry.
  5. Continue from the next state, or reset after a terminal transition. Repeat and evaluate a greedy policy separately.

In finite discounted MDPs, standard tabular convergence results require every state-action pair to be visited infinitely often and learning-rate sequences whose sums diverge while sums of squares converge. These are mathematical conditions, not a guarantee for an arbitrary short training run. Constant α is useful for tracking change but does not satisfy those diminishing-step conditions. If exploration disappears before important actions are tried, the table may stay wrong.

An episode can also stop because a simulator imposes a time limit. A true terminal state has no continuation value. A time-limit truncation in an otherwise continuing task may still need a bootstrap estimate. State the convention in an exam answer and distinguish the two flags in software. Also ensure that the state contains enough information for the MDP assumption; no update formula can repair a fundamentally misleading state representation.

A transparent implementation

The following Python example updates a tiny deterministic delivery problem. At S, “go” reaches T with reward −1. At T, “finish” gives 10 and terminates. A separate “wait” value at S remains zero. The supplied experience stream isolates the arithmetic; it is not a complete exploration policy or a convergence experiment.

Q = {"S": {"go": 0.0, "wait": 0.0},
     "T": {"finish": 0.0}}
alpha, gamma = 0.5, 0.9
samples = [("S", "go", -1, "T", False),
           ("T", "finish", 10, None, True),
           ("S", "go", -1, "T", False)]
for state, action, reward, nxt, terminal in samples:
    target = reward
    if not terminal:
        target += gamma * max(Q[nxt].values())
    Q[state][action] += alpha * (target - Q[state][action])
    print(state, action, f"{Q[state][action]:.2f}")

Worked example

Dry-run the code with zero initial values. All values below are in reward units.

StepOld entryTargetNew entry
1: S, go0−1 + 0.9(0) = −1−0.5
2: T, finish010, terminal5
3: S, go−0.5−1 + 0.9(5) = 3.5−0.5 + 0.5(4) = 1.5

The exact output is:

S go -0.50
T finish 5.00
S go 1.50

The final greedy action at S is go because 1.5 > 0. The true optimal value of go in this deterministic task is −1 + 0.9(10) = 8. The learned value has not yet reached it. Reward information must propagate backwards across visits; the first sample did not know that finishing would later pay 10.

Worked example

A transition has old Q(s, a) = 4, reward 2 and next-state values 3 and 7. With α = 0.25 and γ = 0.8, the Q-learning target is 2 + 0.8(7) = 7.6. The TD error is 3.6 and the updated value is 4 + 0.25(3.6) = 4.9. If the behaviour policy actually chooses the next action valued at 3, this does not change the Q-learning calculation. SARSA on that same next action would use target 4.4 and produce 4.1.

Exam traps

  • Apply the discount to the next value, not to the immediate reward.
  • Use the pre-update value when computing the error and show which entry changed.
  • A terminal target excludes the maximum even if the software stores a terminal row.
  • Do not claim convergence merely because a few successive episodes earned high rewards.

6.3 Learning rule sets: sequential covering algorithms

Sequential covering learns a classifier as a collection of if–then rules. It finds one rule that covers useful positive examples, removes the positives already handled and repeats. Each rule describes a small region; their combination describes a broader concept.

Only a few universities teach this advanced topic. It extends the classification ideas in Unit 3, especially decision trees, but searches for one rule at a time instead of growing an entire tree.

Rules and coverage

A rule has the form IF conditions THEN class. Its conditions usually form a conjunction, such as overdue = yes AND balance > ₹500. An example is covered when it satisfies every condition, whether its true label is positive or negative. A positive covered example is a correct positive prediction; a negative covered example is an error. Coverage and correctness are therefore different quantities.

Rules can form an unordered disjunction: predict positive if any rule fires, otherwise predict negative. An ordered decision list instead uses the first matching rule and ends with a default prediction. These semantics affect conflicts, so always state them. Here we learn an unordered positive rule set with a negative default. Multiple rules covering the same positive do not create multiple correct examples.

Separate and conquer

  1. Keep the currently uncovered positives and the training negatives.
  2. Start a candidate rule with an empty body, which covers every example.
  3. Add conditions that improve the chosen rule-quality measure. Each added condition specializes the rule and shrinks its covered set.
  4. Stop growing under the stated rule criterion, then prune using held-out data or another justified estimate.
  5. Accept a useful rule and remove the positive examples it covers. Repeat until no useful rule remains or all positives are covered.

This is also called separate-and-conquer learning. It differs from divide-and-conquer tree learning, where a split creates branches that partition the data at a node. Overlapping rules need not partition examples. A quality measure such as precision p/(p + n) uses covered-positive count p and covered-negative count n. Maximizing precision alone can select a tiny rule that memorizes one example; minimum coverage or validation can discourage that result.

Retaining negatives matters. If a negative covered by a bad rule simply disappears, later search can lose evidence about errors. Different covering algorithms have different removal and pruning conventions; report the chosen convention. On noisy data, demanding zero training errors can create long, brittle rules. A stopping rule, minimum improvement threshold and default class make the final classifier well defined even when some positives remain uncovered.

Inspecting a learned set

Use a separate validation set to choose complexity, then a test set for final evaluation, as in Unit 2. Measure the whole rule set rather than averaging individual-rule precisions: overlaps make that average misleading.

Worked example

Three positives have attributes P1 = (A yes, B no), P2 = (A yes, B yes), P3 = (A no, B yes). Two negatives N1 and N2 both have A no and B no. Learn rules for the positive class.

The empty body covers p = 3 and n = 2, giving precision 3/5 = 0.6. Candidate A = yes covers P1 and P2 only: precision 2/2 = 1. Candidate B = yes covers P2 and P3 only, also precision 1. Break the tie by choosing A first. Remove P1 and P2 from the uncovered-positive pool.

P3 remains. The rule B = yes covers that remaining positive and no negative, so add it. The final classifier is positive if A = yes OR B = yes, otherwise negative. On the original five examples, TP = 3, FP = 0, FN = 0 and TN = 2. Precision and recall are both 1 on this training set. Summing rule coverages gives 4, which is wrong as a count of distinct positives because P2 belongs to both sets. No test accuracy follows from these five training outcomes.

Exam traps

  • Adding an AND condition specializes one rule; adding an OR rule broadens the rule set.
  • Do not remove every negative merely because a rule covers it.
  • State whether rules are ordered and what happens when no rule fires.

6.4 Learning first-order rules

First-order rule learning represents relationships among objects instead of describing each example only through a fixed attribute vector. Shared variables connect facts, allowing a learned rule to express patterns such as two people having a common parent.

Only a few universities teach this advanced topic. Read Chapter 6.3 for covering; here the search language becomes relational.

Predicates, variables and witnesses

A predicate names a relation. For example, parent(asha, bala) says that Asha is a parent of Bala. Lower-case names here denote constants, while X, Y and Z denote variables. A positive Horn rule has one conclusion, or head, and a conjunction of premises, or body. The rule grandparent(X, Z) ← parent(X, Y) AND parent(Y, Z) says that a two-step parent chain establishes the target relationship.

The shared Y is essential. Both premises must hold under one consistent substitution of constants for variables. A body variable not in the head acts as an existential witness when finding answers: there must be some matching intermediate person. The clause as a logical implication is universally quantified over its variables. These two views agree: any successful witness supplies a body instance whose head follows.

A propositional rule might use fixed features such as “has_parent_named_bala”. A relational rule can use a newly encountered person's name without inventing a separate feature for every constant. This expressiveness also enlarges the search space. Type restrictions, connected literals and limits on body length can keep candidate rules meaningful and computation manageable.

Learning one clause and then a set

  1. Choose the target predicate and supply labelled positive and negative target tuples plus background relations.
  2. Start with a general target clause and enumerate legal body literals.
  3. Evaluate specializations by how they retain positive bindings while excluding negative bindings.
  4. Add a useful literal, update the bindings and continue until the stopping criterion is met.
  5. Add the accepted clause to the set, remove covered positive target tuples and repeat for other patterns.

FOIL, First Order Inductive Learner, is a classic specialization approach. A commonly used literal score is FOIL-gain = t[log₂(p₁/(p₁ + n₁)) − log₂(p₀/(p₀ + n₀))]. Counts p₀ and n₀ refer to positive and negative bindings before the literal; p₁ and n₁ refer to extended bindings after it. The factor t counts positive bindings from before specialization that retain an extension. Bindings can multiply when a new variable is introduced, so these counts need not equal counts of distinct target examples.

Inductive logic programming, or ILP, studies learning logical descriptions using examples and background knowledge. FOIL is one approach within this broader area. Practical systems must specify whether missing facts mean false under a closed-world assumption or merely unknown. A learner cannot silently treat incomplete records as explicit negative evidence without changing the learning problem.

Testing entailment

A candidate covers a target tuple when the background facts together with the clause establish it. Testing a conjunction resembles joining relational tables on shared variables. Check every body literal under the same substitution. Learning a set of clauses uses OR across clauses and AND inside a body.

Worked example

Background facts are parent(asha, bala), parent(bala, chitra) and parent(dev, eesha). Test grandparent(asha, chitra) and grandparent(asha, eesha) with the clause above.

For the first tuple, bind X = asha and Z = chitra. The first body fact gives Y = bala; parent(bala, chitra) is present, so both literals hold. The positive tuple is covered. For the second, the first literal again requires Y = bala, but parent(bala, eesha) is absent. Under the stated closed-world assumption, the tuple is not covered. The fact parent(dev, eesha) cannot help because it would require Y = dev, inconsistent with the first literal.

For a separate scoring exercise, suppose p₀ = 4, n₀ = 4, p₁ = 3, n₁ = 0 and t = 3. FOIL-gain = 3[log₂(1) − log₂(1/2)] = 3[0 − (−1)] = 3. This measures improvement for the candidate literal under these binding counts; it is not a test-set accuracy or a probability.

Exam traps

  • Keep repeated variables consistent; two unrelated facts do not form a chain.
  • Do not identify binding counts with distinct example counts after introducing a variable.
  • State how absent facts are interpreted; unknown and false differ.

6.5 Explanation-based and inductive-analytical learning

Analytical learning uses prior knowledge to explain why an example satisfies a target concept. Explanation-based learning generalizes the proof into a useful rule. Inductive-analytical learning also uses observed examples to guide or correct what prior knowledge suggests.

Only a few universities teach this advanced topic. The first-order clauses of Chapter 6.4 provide a language for expressing the background theory and the explanation.

From one example to an explanation

Explanation-based learning, or EBL, takes a training example, a target concept, a domain theory and an operationality criterion. The domain theory contains facts and inference rules. The operationality criterion specifies which predicates are acceptable in the learned rule, often because they can be measured cheaply. The learner proves that the example satisfies the target, then keeps the proof's relevant requirements while replacing unnecessary constants by variables.

Consider a parcel accepted for a delivery robot. A useful explanation might depend on its measured mass and the robot's capacity, not its colour or tracking number. EBL asks which conditions made the proof work. It does not simply erase every constant: a safety threshold justified by the theory must remain. Nor is any condition true of the example automatically necessary for the proof.

  1. Prove the target for the training instance using the domain theory.
  2. Trace which facts and rule premises support that proof.
  3. Generalize the proof while preserving shared variables and required constraints.
  4. Express the resulting sufficient condition in operational predicates.
  5. Check that the learned rule covers the example and is justified by the theory.

Under a correct theory, the learned condition is sufficient for the target. It need not be necessary: another valid explanation may establish the same target. EBL can improve problem-solving speed by compiling a long inference into a short test. Pure deductive EBL does not establish new consequences beyond what the theory already entails. Learning from one example is possible because the theory supplies strong knowledge; it is not a general statistical guarantee from one observation.

Combining induction and analysis

A domain theory can be incomplete, too specific or wrong. Induction learns regularities from labelled examples, while analysis uses theory to constrain the search. Inductive-analytical methods combine these sources instead of assuming either is sufficient. For example, a theoretical rule can seed a candidate description, then training data can suggest extra literals or alternative clauses. Validation determines whether the resulting change generalizes.

FOCL, First Order Combined Learner, combines explanation-based guidance with a FOIL-style first-order rule search. Prior knowledge can suggest useful operational conditions; empirical candidate evaluation still matters. An incorrect theory should not be treated as an unquestionable source of labels. Conflicts can indicate faulty premises, noisy examples or a mismatch between the theory's scope and the actual task.

What to evaluate

Evaluate both predictive behaviour and computational cost. Use separate validation data, as in Unit 2, and record which theory assumptions were used.

Worked example

A theory states eligible(P, R) if mass(P) ≤ capacity(R) AND route_clear(R). Parcel p weighs 3 kg; robot r has capacity 5 kg and a clear route. Parcel colour is blue. Derive a reusable operational rule.

First, 3 kg ≤ 5 kg is true and route_clear(r) is true. Both premises prove eligible(p, r). Replace p and r by variables P and R while retaining the mass-capacity comparison. The generalized rule is eligible(P, R) ← mass(P) ≤ capacity(R) AND route_clear(R). Colour is excluded because the proof never used it. The numerical values 3 and 5 are replaced by measured quantities, but the ≤ relation remains essential.

A new parcel of 4 kg with capacity 5 kg and a clear route satisfies the rule. A 6 kg parcel does not, since 6 ≤ 5 is false. This failed test does not prove ineligibility under every possible theory; it shows that this sufficient condition is not met. If operational data include a rejected 4 kg parcel because of excessive width, the theory may lack a width constraint. A hybrid learner can propose that condition, then test it on additional labelled data.

Exam traps

  • An explanation is a logical proof, not a verbal justification invented after prediction.
  • A sufficient learned rule need not cover every valid target example.
  • Do not confuse theory-guided generalization with statistical evidence from one example.

Describe first-order rules and explain consistent substitution. (10 marks)

Define predicates, constants, variables, head and body. Use a two-link relationship, demonstrate a shared witness and distinguish absent from false background facts.

Apply

Compute discounted returns and one TD update for the trolley routes in Chapter 6.1. (12 marks)

Show all discount powers. At γ = 0.9, route A gives 4.3 and B gives 4. For the given TD sample, target 2.5, error −0.5 and updated value 2.9.

Trace the three Q-learning samples and explain backward reward propagation. (12 marks)

Use α = 0.5, γ = 0.9 and zero initial values. Updated entries are −0.5, 5 and 1.5. Show terminal handling and explain why the table has not yet reached the true go value 8.

Learn a covering rule set for the five examples in Chapter 6.3. (10 marks)

Compare initial precision 0.6 with each single-condition rule precision 1. Choose A first, remove P1 and P2, then choose B. Count the union as three distinct positives; state the negative default.

Prove two target tuples using parent facts and compute FOIL-gain. (12 marks)

Show X, Y and Z substitutions from Chapter 6.4. The asha–chitra tuple follows; the asha–eesha tuple does not under closed-world semantics. With the supplied binding counts, gain is 3.

Analyze and evaluate

Compare exploration in reinforcement learning with coverage in supervised rule learning. (12 marks)

Span Chapters 6.1–6.3. RL actions affect future observations and rewards; a fixed labelled rule dataset does not offer that interaction. Compare evaluation and generalization without treating coverage as exploration.

Explain how sequential covering extends to a set of relational clauses. (12 marks)

Span Chapters 6.3–6.4. Preserve the outer covering loop, replace attribute conditions by predicates, track bindings and joins, and distinguish OR across clauses from AND within one clause.

Derive an EBL rule and discuss a counterexample caused by an incomplete theory. (16 marks)

Use the parcel proof. Preserve the mass-capacity comparison and clear-route premise, omit colour, then analyze missing width information. Distinguish a sufficient proof condition from complete characterization.

Compare FOIL, EBL and FOCL as sources of generalization. (16 marks)

Span Chapters 6.4–6.5. FOIL searches clauses using labelled evidence; EBL compiles theory-supported explanations; FOCL combines theoretical guidance with inductive search. Discuss binding consistency, theory errors and independent validation.

Glossary

Agent
Decision maker interacting with an environment.
State
Information used to predict the next transition given an action.
Action
A choice available to the agent.
Reward
Immediate numerical feedback from a transition.
Return
Accumulated, possibly discounted, future reward.
Policy
A mapping from states to action probabilities.
Episode
A sequence ending at a terminal state.
Discount factor
Weight controlling the contribution of later rewards.
Action value
Expected return after a specified first action.
Bootstrapping
Updating an estimate using another estimate.
Off-policy learning
Learning a target policy from behaviour that may differ.
Exploration
Trying actions to gain information.
Coverage
The examples satisfying a rule body.
Sequential covering
Learning rules one at a time while removing covered positives.
Predicate
A named relation over objects.
Substitution
Consistent assignment of terms to variables.
Horn rule
An implication with a conjunction of premises and one positive head.
Closed-world assumption
Treating facts not established by the knowledge base as false.
Domain theory
Background facts and rules used for reasoning.
Operationality
Acceptability of predicates for the learned description.
EBL
Explanation-based learning through generalized proofs.
FOCL
First Order Combined Learner, combining inductive and analytical guidance.
