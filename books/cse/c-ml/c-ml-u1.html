1.1 What machine learning is and its applications

Machine learning builds programs that improve from data instead of being written with fixed rules. It exists because many tasks change over time or are too complex for manual coding. It is used in spam filters, UPI fraud detection, cricket score prediction, traffic flow estimation and many other real‑world problems where patterns must be learned from examples.

Formal definition and typical applications

A learning algorithm receives a set of training examples D = { (x i , y i ) } i=1…N . Each x i is a feature vector that describes an input and y i is the desired output. The algorithm searches for a function f that maps any new feature vector x to a prediction ŷ = f(x). The function f is called the model.

f : X → Y

X is the space of feature vectors; Y is the set of possible outputs (e.g., {Yes,No} for fraud detection).

  • Spam filtering for e‑mail services.
  • UPI fraud detection in banking apps.
  • Predicting the total runs in a cricket innings.
  • Estimating traffic speed on city roads.

Some syllabi call this chapter "Introduction to Machine Learning" because it establishes the basic language used throughout the course.

From data to prediction: the learning pipeline

The pipeline has three stages. First, raw data are collected and transformed into a numeric feature matrix X. Second, a learning algorithm uses X together with known outputs Y to train a model – this is the training step. Third, the trained model receives new feature vectors and produces predictions; this is called inference.

  1. Collect raw observations (transactions, sensor readings, etc.).
  2. Convert each observation into a fixed‑length vector of numbers.
  3. Apply a learning algorithm to obtain model parameters.
  4. Use the model to predict the label of unseen vectors.

The figure after this section visualises the same three blocks – Data, Model and Prediction – and the arrows labelled “train” and “infer”.

Learning versus hard‑coded rules

A hard‑coded rule is a fixed logical condition such as “if amount > 10,000 then fraud”. It never changes unless a programmer edits the code. A learned model, by contrast, adjusts its parameters automatically when new data arrive, allowing it to capture emerging fraud patterns.

  • Rules are easy to understand but brittle.
  • Models can handle many interacting features.
  • Models require data, computation and validation.

Later chapters will show how to train models, evaluate them, and improve their performance.

Worked example

Question. A bank wants to decide whether a new transaction of ₹5,000 made at 22:00 (10 pm) in merchant category code 3 is fraudulent. The bank uses a linear model f(x) = w1·amount + w2·hour + w3·category + b. The learned weights are w1 = 0.0004 ₹⁻¹, w2 = 0.1 hour⁻¹, w3 = 0.2 code⁻¹ and bias b = –1.0. Compute the model score and give the prediction (Yes for fraud, No for legitimate).

C program.

#include <stdio.h>
int main(){
    double amount=5000, hour=22, cat=3;
    double w1=0.0004, w2=0.1, w3=0.2, b=-1.0;
    double score = w1*amount + w2*hour + w3*cat + b;
    printf("Score = %.1f\n", score);
    if(score>0) printf("Prediction: Yes (fraud)\n");
    else printf("Prediction: No (legitimate)\n");
    return 0;
}
  1. Convert the transaction into a feature vector x = (amount, hour, category) = (5,000, 22, 3).
  2. Compute each term:
  3. w1·amount = 0.0004 × 5,000 = 2.0
  4. w2·hour = 0.1 × 22 = 2.2
  5. w3·category = 0.2 × 3 = 0.6
  6. Add the bias: b = –1.0
  7. Sum all terms: score = 2.0 + 2.2 + 0.6 – 1.0 = 3.8
  8. Since the score > 0, the model predicts Yes (fraud).

  • Using the sign of the bias alone to decide the class; the bias must be added to the weighted sum.
  • Confusing the unit of the weight w1 (per rupee) with a dimensionless number; forgetting to multiply amount by 0.0004 leads to a huge error.

1.2 Types of learning: supervised, unsupervised, reinforcement

Machine learning can be grouped into three main paradigms. Each paradigm tells how data and feedback are given to the learner. Supervised learning uses input–output pairs that are already labeled. Unsupervised learning receives only inputs and must discover structure on its own. Reinforcement learning lets an agent act in an environment and receive a reward signal that guides future actions. Knowing the type helps you pick the right algorithm for problems such as spam detection, customer segmentation, or a bot that books the cheapest train seat.

You need: the basics of what machine learning is and its applications .

Supervised learning

In supervised learning the training set consists of examples (x, y). x is the input vector, y is the target label. The learner builds a function f̂(x) that predicts y for new inputs. The goal is to minimise the empirical risk L = (1/n) Σ ℓ(y_i, f̂(x_i)). Here n is the number of examples, ℓ is a loss function such as zero‑one loss, and Σ denotes summation over i = 1 … n.

  • Labeled data are required.
  • Common tasks: classification and regression.
  • Algorithms include decision trees, SVM, and neural nets.

L = (1/n) Σ ℓ(y_i, f̂(x_i))

L is average loss; n is number of training examples; ℓ is loss per example; y_i is true label; f̂(x_i) is predicted label.

Unsupervised learning

Unsupervised learning receives only input vectors x without any label y. The learner seeks patterns such as clusters or low‑dimensional structure. A typical objective is to minimise within‑cluster variance: J = Σ_{k=1}^{K} Σ_{x_i∈C_k} ||x_i – μ_k||². Here K is the number of clusters, C_k is the set of points in cluster k, μ_k is the centroid of cluster k, and ||·|| denotes Euclidean distance.

  • No labeled data are needed.
  • Tasks include clustering, density estimation, and dimensionality reduction.
  • Algorithms include k‑means, hierarchical clustering, and PCA.

J = Σ_{k=1}^{K} Σ_{x_i∈C_k} ||x_i – μ_k||²

J is total intra‑cluster variance; K is number of clusters; C_k is cluster k; μ_k is centroid of cluster k; ||·|| is Euclidean norm.

Reinforcement learning

Reinforcement learning (RL) involves an agent that interacts with an environment over discrete time steps t = 0,1,… . At each step the agent observes a state s_t, selects an action a_t, and receives a scalar reward r_t. The objective is to maximise the expected return G = Σ_{t=0}^{∞} γ^t r_t, where γ (0 ≤ γ < 1) is the discount factor that reduces the weight of distant rewards.

  • Requires a reward signal, not explicit labels.
  • Used for control, game playing, and recommendation.
  • Key concepts: policy, value function, and exploration.

G = Σ_{t=0}^{∞} γ^t r_t

G is total discounted return; γ is discount factor; r_t is reward at step t.

1.3 Designing a learning system; well-posed learning problems

A learning system is built step by step. Each step adds a clear piece: what we want to solve, how we will judge success, the data we will use, the set of models we allow, and the algorithm that picks a model. This pipeline makes the problem well‑posed so that the answer can be found, measured and compared. It is used in every real‑world ML project, from fraud detection to predicting train delays.

You need: What machine learning is and its applications, Types of learning.

The five components of a learning system

First we define the task. The task states the input space X and the output space Y. For classification, X could be a vector of features and Y a set of class labels.

Second we choose a performance measure. A common measure for classification is accuracy = (correct predictions) ÷ (total predictions).

accuracy = \frac{\text{correct}}{\text{total}}

correct = number of predictions that match the true label; total = number of examples evaluated.

Third we collect a data set D = {(x_i , y_i)}_{i=1}^{N}. N is the number of examples. The data must be representative of the real world.

Fourth we specify a hypothesis space H. H contains all models the learner may choose. For a linear model, H = {h_w,b (x)= w·x + b | w ∈ ℝ^d , b ∈ ℝ}.

Fifth we select a learning algorithm A. A takes D and returns a hypothesis h ∈ H that optimises the performance measure on D.

  • Task definition gives purpose.
  • Performance measure tells us what good looks like.
  • Data set supplies evidence.
  • Hypothesis space limits the search.
  • Learning algorithm performs the search.

Well‑posed learning problems

A problem is well‑posed when it satisfies three criteria.

  • Finite: the data set contains a finite number of examples, so computation can finish.
  • Computable: the learning algorithm can be executed on a digital computer; the optimisation objective must be algorithmically evaluable.
  • Evaluable: a performance measure exists that can be computed on unseen data.

If any criterion is missing, the system may never finish, may give meaningless output, or cannot be compared with alternatives.

Some syllabi call this topic "Designing a Learning System" or "Well‑Posed Learning Problems".

Putting the pipeline together

  1. Define the task (what to predict).
  2. Collect data that reflect the task.
  3. Choose a hypothesis space that can express plausible solutions.
  4. Train the learning algorithm on the data.
  5. Evaluate the learned model on a held‑out set.

Each step feeds the next. Skipping a step breaks the well‑posedness. For example, training without a performance measure leaves the algorithm without a goal.

  9. Accuracy = correct ÷ total = 5 ÷ 5 = 1.0 = 100 %.
  10. Well‑posed check:
  11. Finite – the data set has 5 examples (finite).

1.4 Challenges and issues in machine learning

Machine learning models often look good on paper but fail in real use because of practical problems. These problems include fitting the training data too tightly (overfitting), not learning enough (underfitting), noisy or missing data, changing patterns over time (concept drift), and issues of fairness, privacy and explainability. Recognising and handling these challenges is essential for any system that must work on real‑world Indian data such as UPI transaction logs, cricket scores or power‑grid sensor streams.

You need: basic definitions from What machine learning is and its applications and the learning pipeline from Designing a learning system; well‑posed learning problems.

Data and Model Issues

Data quality directly influences model behaviour. Noise means random errors in the input features or labels, while missing values reduce the amount of information the learner can use. When the training set is small or contains many outliers, a model may learn patterns that do not exist in the true population.

Model issues arise when the hypothesis space is too large or too small. An overly complex model (many parameters, deep trees, high‑degree polynomials) can memorize the training points – this is overfitting. A too‑simple model (linear regression on a nonlinear problem) cannot capture the underlying relationship – this is underfitting.

  • Noise – random fluctuations in data, e.g., sensor glitches during a Chennai power cut.
  • Missing values – absent entries in a CSV of UPI transactions.
  • Overfitting – very low training error but high test error.
  • Underfitting – high error on both training and test sets.

E[(y‑f̂)²] = (Bias)² + Variance + σ²

y is the true output; f̂ is the model prediction; Bias = E[ f̂ ] – f is the difference between the expected model prediction and the true function; (Bias)² appears in the decomposition; Variance is error from sensitivity to training data; σ² is irreducible noise in the data.

Bias‑Variance Trade‑off

The bias‑variance trade‑off explains why neither a very simple nor a very complex model is universally best. Reducing bias usually means adding capacity, which raises variance. Reducing variance usually means simplifying the model, which raises bias. The optimal point balances the two so that total expected error is minimal.

  1. Choose a hypothesis class (e.g., degree‑2 polynomial).
  2. Train on the available data and compute training error.
  3. Validate on a separate set to estimate test error.
  4. If training error is low but test error is high, increase bias (simplify).
  5. If both errors are high, decrease bias (add capacity).

Cross‑validation, described in Math review, provides a systematic way to estimate the trade‑off without using the final test set.

Key Metrics

Overfitting ratio = test error ÷ training error; a larger value indicates greater overfitting.

Ethical and Practical Concerns

Beyond statistical performance, machine‑learning systems must respect ethical norms. Training data can embed societal bias, leading to unfair predictions for certain groups. Privacy regulations in India require that personal data, such as bank account numbers, be protected during model development and deployment.

  • Bias – discrimination that can arise from historical data (e.g., loan approval patterns).
  • Privacy – need for techniques like differential privacy when using personal transaction logs.
  • Interpretability – ability to explain why a model gave a particular output, important for regulatory compliance.
  • Concept drift – when the underlying data distribution changes over time, such as new payment methods appearing on UPI.

Monitoring tools and periodic retraining are common ways to mitigate concept drift. Explainable AI methods, like SHAP values, help address interpretability requirements.

  • Dividing by the training error without checking for zero, leading to a runtime error.

1.5 Math review: linear algebra, probability and distributions

Linear algebra and probability are the common language of almost every machine‑learning algorithm. Vectors and matrices let us write predictions, losses and updates compactly. Probability describes data uncertainty and guides inference. Together they appear in linear regression, logistic models, Bayesian classifiers and many neural‑network calculations. This chapter reviews the essential symbols and operations so you can follow later algorithmic sections without getting stuck on the math.

You need the basics of what machine learning is (what‑machine‑learning‑is‑and‑its‑applications) and the three learning paradigms (types‑of‑learning‑supervised‑unsupervised‑reinforcement).

Vectors, dot product and linear models

A vector is an ordered list of numbers. A column vector can be written as a vertical list, e.g. v = [v₁] [v₂] … [vₙ]. It is also common to write a row vector and add a transpose symbol: v = [v₁, v₂, …, vₙ]ᵀ. The dot product of two vectors of the same length is the sum of pairwise products: u·v = Σ_{i=1}^{n} uᵢ·vᵢ. The result is a single scalar.

y = w·x + b

y is the model output; w is the weight vector; x is the feature vector; b is the bias (scalar).

  1. Multiply each weight wᵢ with the corresponding feature xᵢ.
  2. Add all the products to obtain the dot product w·x.
  3. Add the bias b to get the final prediction y.

Python program.

w = [2, -1]
x = [3, 4]
b = 5
y = sum(wi*xi for wi, xi in zip(w, x)) + b
print('y =', y)

Output

y = 7

Matrices and matrix‑vector multiplication

A matrix is a rectangular array of numbers with rows and columns. If A is an m×n matrix and v is an n‑dimensional vector, the product A·v is an m‑dimensional vector whose i‑th entry is the dot product of the i‑th row of A with v.

z = A·v

z is the resulting vector; A is the matrix; v is the input vector.

  1. For each row i of A, compute Σ_{j=1}^{n} A_{ij}·v_j.
  2. Collect the results into vector z.

C program.

#include <stdio.h>
int main(){
    int A[2][2] = {{1,2},{3,4}};
    int v[2] = {5,6};
    int z[2];
    for(int i=0;i<2;i++){
        z[i]=0;
        for(int j=0;j<2;j++)
            z[i] += A[i][j]*v[j];

Probability basics

A probability space consists of a sample space Ω, events (subsets of Ω) and a probability measure P that assigns a number between 0 and 1 to each event. For a discrete random variable X, the expectation is E[X] = Σ_x x·P(X=x). For a continuous variable with density f(x), the expectation is E[X] = ∫_{-∞}^{∞} x·f(x) dx. Variance measures spread: Var(X) = E[(X‑E[X])²].

E[X] = Σ x·P(X=x)

x runs over all possible values of X; P(X=x) is the probability of each value.

  1. List each possible value of X and its probability.
  2. Multiply value by its probability.
  3. Sum all products to obtain the expectation.

Python program.

values = [1,2,3]

1.6 Concept learning: Find-S, version spaces, candidate elimination

Concept learning treats classification as a search for a hypothesis that matches observed examples. It uses a simple hypothesis space of conjunctions of attribute values, making the learning process transparent. Algorithms such as Find‑S quickly locate the most specific hypothesis, while Candidate Elimination maintains both the most specific (S) and most general (G) boundaries of the version space. This approach is useful when the domain has a small number of discrete attributes, for example in a rule‑based spam filter or a medical diagnosis system that decides based on a few test results.

You need: basic probability and linear algebra from Math review.

Hypothesis space for concept learning

A concept is a Boolean function that maps an instance to Yes (target) or No (non‑target). The hypothesis space H consists of all conjunctions of the form ⟨a1, a2, …, an⟩ where each ai is either a specific attribute value or the wildcard ‘?’. The wildcard matches any value of that attribute. For n attributes each having vi possible values, the size of H is ∏(vi+1).

|H| = ∏_{i=1}^{n} (v_i + 1)

|H| is the number of hypotheses; v_i is the number of possible values for attribute i.

  • Specific hypothesis: no ‘?’ symbols; matches only one instance.
  • General hypothesis: all ‘?’ symbols; matches every instance.

Find‑S algorithm

Find‑S starts with the most specific hypothesis ⟨⊥, ⊥, …, ⊥⟩ and processes only positive examples. For each positive example it updates the hypothesis: if an attribute is still ⊥, it takes the example’s value; if the current value differs from the example’s value, it becomes ‘?’ to stay consistent with all seen positives.

  1. Initialize S = ⟨⊥, ⊥, …, ⊥⟩.
  2. For each positive example e:
  3. For each attribute i:
  4. If S[i] is ⊥ then set S[i] = e[i];
  5. Else if S[i] ≠ e[i] then set S[i] = ‘?’.

Python program.

def find_s(examples, attrs):
    # None is used as the marker for ⊥ (most specific)
    S = [None] * len(attrs)
    for ex in examples:
        if ex['label'] != 'Yes':
            continue
        for i, val in enumerate(ex['vals']):
            if S[i] is None:
                S[i] = val
            elif S[i] != val:
                S[i] = '?'
    return S

# Example usage
attrs = ['Weather', 'Temp']
examples = [
    {'vals': ['Sunny', 'Hot'], 'label': 'Yes'},
    {'vals': ['Sunny', 'Cold'], 'label': 'Yes'},
    {'vals': ['Rainy', 'Hot'], 'label': 'No'}
]
print(find_s(examples, attrs))

Version spaces and Candidate Elimination

A version space V is the set of all hypotheses in H consistent with the training data seen so far. V can be represented by its boundaries: S (most specific) and G (most general). Candidate Elimination updates both boundaries for each training example, keeping them consistent with all positives and negatives.

  1. Initialize S = ⟨⊥, ⊥, …, ⊥⟩ and G = {⟨?, ?, …, ?⟩}.
  2. For a positive example:
  3. Remove any hypothesis from G that does not cover the example.
  4. Generalize S minimally to cover the example.
  5. For a negative example:
  6. Remove any hypothesis from S that covers the example.
  7. Specialize G minimally to exclude the example.
  • When a positive example conflicts with the current S, replace the conflicting attribute value in S with ‘?’ to make it more general.
  • Specialization replaces a ‘?’ in G with all values except the one in the negative example.

Worked example

Question. Consider the attributes Weather ∈ {Sunny,Rainy} and Temp ∈ {Hot,Cold}. The training set contains: 1) Sunny, Hot → Yes 2) Sunny, Cold → Yes 3) Rainy, Hot → No Apply the Find‑S algorithm and then the Candidate Elimination algorithm. Show the contents of S and G after each example.

Python program.

def candidate_elimination(examples, attrs):
    # S starts as most specific (⊥) represented by None
    S = [None] * len(attrs)
    G = [ ['?'] * len(attrs) ]
    for ex in examples:
        vals, label = ex['vals'], ex['label']
        if label == 'Yes':
            # update S (generalize minimally)
            for i, v in enumerate(vals):
                if S[i] is None:
                    S[i] = v
                elif S[i] != v:
                    S[i] = '?'
            # remove inconsistent G
            G = [g for g in G if all(g[i] == '?' or g[i] == vals[i] for i in range(len(attrs)))]
        else:
            # remove inconsistent S
            if all(S[i] is None or S[i] == vals[i] for i in range(len(attrs))):
                S = [None] * len(attrs)
            # specialize G minimally
            new_G = []
            for g in G:
                if all(g[i] == '?' or g[i] == vals[i] for i in range(len(attrs))):
                    for i, v in enumerate(vals):
                        if g[i] == '?':
                            for alt in set(attrs[i]) - {v}:
                                h = g.copy()
                                h[i] = alt
                                new_G.append(h)
                else:
                    new_G.append(g)
            G = new_G
    return S, G

attrs = [ ['Sunny','Rainy'], ['Hot','Cold'] ]

    {'vals': ['Sunny','Hot'], 'label': 'Yes'},
    {'vals': ['Sunny','Cold'], 'label': 'Yes'},
    {'vals': ['Rainy','Hot'], 'label': 'No'}
]

1.7 Inductive bias and generalization

Inductive bias is the set of assumptions a learning algorithm makes to predict unseen data. Without bias a learner cannot prefer one hypothesis over another when both fit the training set. Bias lets us trade off simplicity, smoothness or linearity against over‑fitting noisy data, and it appears in every model from linear regression to deep networks.

You need: basic probability and linear algebra from Math review.

Definition of inductive bias

Inductive bias is any prior knowledge that restricts the hypothesis space H before seeing the data. It tells the learner which functions are more plausible. The bias can be explicit, such as limiting H to linear functions, or implicit, such as using a regulariser that penalises large weights.

  • Preference for simpler models – often called Occam’s razor.
  • Assumption that similar inputs have similar outputs – smoothness.
  • Restriction to a particular geometric form, e.g., linear separators.

In practice the bias decides whether a model will under‑fit or over‑fit. A strong bias (very simple H) may miss patterns; a weak bias (very rich H) may fit noise. The right bias depends on the problem domain, such as predicting electricity demand in Chennai or estimating fare for a UPI transaction.

Common bias examples

1. **Simplicity bias** – choose the hypothesis with the fewest parameters that still fits the data. Linear regression uses this bias by restricting the hypothesis space to linear functions, i.e., straight lines, rather than high‑degree polynomials.

2. **Linear separator bias** – assume that two classes can be separated by a hyperplane. Support Vector Machines adopt this bias and maximise the margin.

3. **Smoothness bias** – assume the target function changes slowly with the input. Kernel methods and Gaussian processes encode this by weighting nearby points more heavily.

These biases are built into algorithms, but they can be altered. For example, adding polynomial features reduces the linear‑separator bias and increases model complexity.

Bias, VC dimension and the generalisation bound

The Vapnik–Chervonenkis (VC) dimension h measures the capacity of a hypothesis space. A larger h means the space can shatter more data points, i.e., represent more complex patterns. The VC theory gives a bound on the difference between training error and true error.

Generalisation error ≤ √((h·(log(2n/h)+1) + log(2/δ))/n)

n is the number of training examples; δ is the confidence parameter (probability that the bound holds); h is the VC dimension of H.

The bound shows two forces: increasing n shrinks the error, while increasing h or lowering δ widens it. Choosing a hypothesis space with an appropriate VC dimension is therefore a concrete way to apply inductive bias.

Some syllabi list this relationship under the heading "Inductive Bias". The bound guides model selection: if two models have similar training error, the one with smaller h will usually have a tighter bound and better test performance.

Worked example

Question. Two models are trained on the same data set of n = 200 examples. Model A uses a hypothesis space with VC dimension h = 2 and achieves training error 8 % and test error 12 %. Model B uses h = 6, attains training error 0 % but test error 30 %. Using δ = 0.05, compute the generalisation‑error bound for each model and decide which model has the lower bound.

Python program.

import math
n = 200
h = 2
term = h * math.log(2*n/h) + math.log(20)
print('Bound for h=2:', math.sqrt(term/n))
  1. Compute the term log(2n/h) for each model.
  2. For Model A: 2n/h = 400/2 = 200, log(200) ≈ 5.2983.
  3. Multiply by h: 2 × 5.2983 = 10.5966.
  4. Add log(1/δ) = log(20) ≈ 2.9957 → total = 13.5923.
  5. Divide by n: 13.5923 / 200 = 0.06796.
  6. Take square root: √0.06796 ≈ 0.2607 (26.1 %).
  7. For Model B: 2n/h = 400/6 ≈ 66.6667, log(66.6667) ≈ 4.1997.
  8. Multiply by h: 6 × 4.1997 = 25.1982.
  9. Add log(20) → total = 28.1939.
  10. Divide by n: 28.1939 / 200 = 0.14097.
  11. Square root: √0.14097 ≈ 0.3755 (37.6 %).
  12. Compare bounds: Model A bound (26.1 %) < Model B bound (37.6 %).
  13. Therefore Model A is expected to generalise better despite higher training error.

Exam traps

  • Assuming that a lower training error always means a lower test error; the bound shows why over‑fitting can increase test error.
  • Confusing VC dimension h with the number of parameters; they are related but not identical.
  • Using the bound without specifying δ; the bound widens as δ becomes smaller, so forgetting δ leads to an unrealistically tight estimate.
  • Treating the bound as the actual error rather than an upper limit that holds with probability 1‑δ.
