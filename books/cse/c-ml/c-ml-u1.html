1.1 What machine learning is and its applications

Machine learning builds programs that get better at a job as they see more data. Instead of writing every rule by hand, you give the program examples and let it find the rule. A spam filter that learns from emails you have already marked, a bank that scores a UPI payment for fraud, a site that recommends the next product — all work this way. This chapter gives the standard definition, the terms that go with it, the steps of a machine learning project, and the places the idea is used.

You need only school-level algebra and the idea of a fraction; probability enters in 1.5.

The definition: task, performance, experience

Machine learning is the study of computer programs whose performance on a task improves with experience. The experience is usually data. A widely used definition makes the three parts explicit.

A program learns from experience E with respect to task T and performance measure P if its performance on T, measured by P, improves with E.

P on T ↑ as E ↑

T is the task, the job to be done; P is the performance measure, a number that scores how well T is done; E is the experience, usually a set of past examples with known answers. The arrow ↑ means increases.

An example with a known answer is a labelled example, and the answer itself is the label. For a spam filter the label is spam or not spam. The things you measure about an example are its features: word counts, message length, number of links. One example written as a list of feature values is a feature vector.

The model is what gets learned. It is a rule, a set of weights or a formula that turns a feature vector into a prediction. Any single candidate model is called a hypothesis, and the set of all hypotheses the learner may return is the hypothesis space.

Using data is not the same as learning from it. A bank can write a fixed rule by hand — flag any payment above ₹2,00,000 — and that rule uses data but never changes. It is not machine learning. Learning needs a program that adjusts itself when it sees more examples.

The machine learning process

Building a machine learning system is a pipeline. Each step feeds the next, and a mistake early on is hard to repair later.

  1. Collect data. Gather examples that look like the cases the system will meet in use, and record the labels if the task has them.
  2. Prepare features. Clean the data, drop duplicates, and turn each example into a feature vector of numbers. Scaling features to a common range often helps.
  3. Choose a model. Pick a family of hypotheses that suits the task and the amount of data you have.
  4. Train. Run the learning algorithm on the training set; it searches the hypothesis space and returns the model that scores best.
  5. Evaluate. Measure performance on a separate test set the learner has never seen.
  6. Deploy. Put the model into service and keep watching its performance as real data arrives.

The split into training set and test set carries the whole idea of evaluation. The training set is the experience E. The test set stands in for the future and must never be used to fit the model. Training accuracy alone is misleading, because any model can memorise the examples it was shown.

accuracy = correct ÷ total

correct is the number of test examples labelled correctly; total is the number of test examples. The result lies between 0 and 1, and is often written as a percentage.

Where machine learning is used

Machine learning earns its place when the rule is too complex or too changeable to write by hand.

  • Spam filtering. A filter learns from emails already marked spam or not spam, using word counts and sender details as features.
  • UPI and card fraud. A bank scores each transaction for the chance that it is fraudulent, from amount, time of day, device and distance from the last transaction. Fraud patterns shift, so a model retrained on fresh data beats a fixed rule.
  • Product recommendation. A shopping site predicts what you will click or buy, from your past clicks, past purchases and the behaviour of similar users.
  • Crop-yield prediction. Rainfall, soil type, area sown and fertiliser use predict yield in quintals per hectare, helping a farmer or a district office plan.
  • Medical screening. A model reads test values or images and flags patients who need a closer look. A missed case costs far more than a false alarm, so the performance measure must reflect that.
  • Speech and language. Voice assistants convert speech to text and translation tools move text between languages; both are learned from large paired datasets.

Worked example

Question. A spam filter is trained on 1000 emails: 200 spam and 800 not spam. The learned rule marks an email as spam if it contains the word lottery at least twice. On 10 test emails the rule is right on 8. Write down the task T, the performance measure P and the experience E for this system. Then compute the test accuracy as a fraction and as a percentage.

  1. T, the task: read one email and label it spam or not spam. This is a classification task with two classes.
  2. P, the performance measure: the fraction of test emails whose label the rule gets right. That is accuracy.
  3. E, the experience: the 1000 labelled emails, of which 200 are spam and 800 are not spam.
  4. Check the data: 200 + 800 = 1000 emails, so the spam share is 200 ÷ 1000 = 0.20, that is 20%.
  5. Test outcome: 8 correct out of 10 test emails, so correct = 8 and total = 10.
  6. Accuracy = correct ÷ total = 8 ÷ 10 = 0.8.
  7. As a percentage: 0.8 × 100 = 80%.

Answer. T is labelling an email spam or not spam, P is the fraction labelled correctly, E is the 1000 labelled emails; the test accuracy is 0.8, that is 80%.

Exam traps

  • Calling any program that uses data machine learning. A hand-written rule that never changes is not learning, however much data passes through it.
  • Swapping the training set and the test set. Training data is the experience E; test data only measures performance and must never be used to fit the model.
  • Confusing a feature with a label. A word count is a feature; spam or not spam is the label. The label is what you want to predict.
  • Quoting training accuracy as the model's real performance. A model can score 100% on the training set and still fail on new inputs.
  • Writing P as a vague phrase such as 'good performance'. The examiner wants a stated measure, for example the fraction of emails labelled correctly.

1.2 Types of learning: supervised, unsupervised, reinforcement

Learning types differ by the feedback a learner receives. Supervised learning gets labelled examples, so it learns a mapping from input to known answer. Unsupervised learning gets only inputs and looks for structure such as groups. Reinforcement learning gets a reward after actions, often delayed. This choice sets the data you need, the loss you use and how you judge success. IRCTC waitlist prediction, UPI fraud checks, crop grouping and game-playing agents are everyday places where the three types appear.

You need: Chapter 1.1 for task, data and model terms.

Supervised learning: labels give the answer

Supervised learning uses pairs (x, y). x is the input vector, called features. y is the target, called the label. The learner searches for a function f that predicts y from x. At test time a new x arrives without y, and f(x) gives the prediction. The labels make the error measurable, so training can adjust f to reduce mistakes.

y = f(x) + ε

y is the target; x is the feature vector; f is the learned model; ε is noise or error not explained by x.

If y is discrete, the task is classification. Example: from 200 labelled emails, predict spam or not spam. If y is a number, the task is regression. Example: predict house price in rupees from area in square feet. The same features can support either task; the type of y decides the name.

  • Classification output: class label, such as spam/not spam, confirmed/waitlisted.
  • Regression output: real number, such as price or waiting-list position.
  • Training data must be labelled; wrong labels teach wrong rules.

A typical supervised pipeline is: collect labelled examples, split into train and test, fit the model on train, tune with validation, report test error. Details of regression, logistic regression, trees and SVM come in Units 2 and 3.

Unsupervised learning: structure without labels

Unsupervised learning uses inputs x only. No y is given, so the learner cannot measure a prediction error against a correct answer. It looks for structure: groups of similar points, low-dimensional directions, or a probability distribution that could have produced the data.

Clustering puts points into groups so that points in one group are more similar to each other than to points outside. Example: group 500 customers by monthly spend and visit frequency. The bank may name the groups later, but the algorithm only sees features. Density estimation models how data is distributed; it can flag a UPI transaction as unusual if it lies in a low-density region.

  • Clustering: hard or soft group assignment; number of groups may be chosen by the analyst.
  • Density estimation: a model p(x) over inputs; useful for anomaly detection.
  • No labels means no single correct answer; evaluation uses separation, stability or domain review.

A typical pipeline is: choose features, scale them, pick a similarity or distance, run the method, inspect groups. Unit 4 covers k-means, hierarchical clustering, Gaussian mixtures and PCA. Some syllabi call semi-supervised learning a mix: a few labels plus many unlabelled inputs. Self-supervised learning makes labels from the data itself, such as predicting the next word.

Reinforcement learning: reward from actions

Reinforcement learning (RL) trains an agent that acts in an environment. At each step the agent sees a state s, chooses an action a, and receives a reward r plus the next state. The reward is a number, not a correct action label. The agent must discover which actions lead to high total reward over time. The agent's policy is its rule for choosing actions.

Feedback is delayed. A cricket shot may score runs only after the ball reaches the boundary; a robot gets +1 only when it exits the maze. The agent explores actions to learn, then exploits good actions. This trade-off between exploration and exploitation is central.

  1. Observe current state s.
  2. Choose action a, sometimes random for exploration.
  3. Receive reward r and next state s′.
  4. Update the estimate of how good each action is, or the policy, from the reward.
  5. Repeat until the run ends; test the learned policy.

Example: teach a robot to exit a maze with +1 at the exit and 0 elsewhere. The agent is the robot; states are cell positions; actions are up/down/left/right; reward is +1 on exit. Unit 6 covers Q-learning and related methods.

Worked example

Question. Classify each task as supervised classification, supervised regression, unsupervised clustering or reinforcement learning. Also count how many tasks fall in each of the three broad types. (1) Predict house price from area. (2) Group 500 customers by monthly spend. (3) Teach a robot to exit a maze using +1 at the exit. (4) Label email spam from 200 labelled examples. (5) Find clusters in 1000 UPI transactions. (6) Choose a cricket shot using runs scored as reward.

  1. Task 1: target is house price, a number in rupees. The label is numeric, so this is supervised regression.
  2. Task 2: no target label; input is monthly spend. Grouping customers by similarity is unsupervised clustering.
  3. Task 3: the robot takes actions and gets +1 at the exit. Reward is delayed, not a labelled correct action, so this is reinforcement learning.
  4. Task 4: target is spam/not spam, a discrete label, with 200 labelled examples. This is supervised classification.
  5. Task 5: no labels on UPI transactions; the goal is to find groups. This is unsupervised clustering.
  6. Task 6: a cricket shot is chosen; runs scored is a reward signal. This is reinforcement learning.
  7. Count: supervised = tasks 1 and 4 = 2. Unsupervised = tasks 2 and 5 = 2. Reinforcement = tasks 3 and 6 = 2.

Output

2
2

Answer. Tasks 1, 2, 3, 4, 5 and 6 are supervised regression, unsupervised clustering, reinforcement learning, supervised classification, unsupervised clustering and reinforcement learning; the counts are 2 supervised, 2 unsupervised and 2 reinforcement.

Exam traps

  • Clustering is not classification. Classification needs labels; clustering only has inputs and finds groups.
  • Reinforcement learning uses rewards, not labelled correct actions. A reward tells how good an action was, not what the action should have been.
  • Regression predicts a number; classification predicts a class. A price in rupees is regression even if you later bucket it.
  • Unsupervised does not mean unvalidated. You still check cluster stability, separation or business meaning.
  • Semi-supervised is not unsupervised. It uses a small labelled set plus a large unlabelled set.

1.3 Designing a learning system; well-posed learning problems

A machine learning project starts before any algorithm is chosen. It starts with a promise: a task, a way to score it, and data that can teach it. When those three are stated, the problem is well posed and a learning system can be designed. The design turns the promise into a pipeline: collect data, choose features, pick a hypothesis space and algorithm, measure performance, then deploy. Banks use this to decide loan risk; IRCTC uses it to predict waitlist clearance; a phone keypad uses it to suggest the next word. The same discipline applies to each.

You need: Chapter 1.1 for features and labels, and Chapter 1.2 for learning types.

Well-posed means T, P and E

Well-posed learning problem. A learning problem is well posed when three parts are fixed. T is the task: the exact mapping from inputs to outputs that the system must perform. P is the performance measure: a number computed on cases not used in training. E is the experience: the data, labels, rewards or interactions available for learning. Write the triple as (T, P, E).

  • T answers: what is the input, and what is the output?
  • P answers: how is success scored, and on which cases?
  • E answers: what past cases or feedback are available?

A fourth check is the data source. Who recorded the data? Is it labelled? Is it from the same population as deployment? A problem with T and P but no honest E is not solvable; it is only a wish. For example, 'predict loan default' is not well posed until P (accuracy? recall? cost?) and E (5000 past loans with repayment outcomes) are fixed. A clear data source makes the problem testable.

Design cycle in eight steps

  1. Write T, P, E and the data source in one page; fix the unit of P, such as accuracy or rupees of cost.
  2. Collect data from the deployment population; record labels or rewards with the same definition used at prediction time.
  3. Prepare data: repair errors, handle missing values, and split into training, validation and test sets before any feature choice.
  4. Choose a representation: define the feature vector x and label y; a feature is a measurable input property.
  5. Choose a hypothesis space H: lines, trees, rules or networks that the learner may return.
  6. Choose a learning algorithm: the procedure that searches H using E.
  7. Train on the training set, tune on validation with P, and report the test score once.
  8. Deploy, monitor inputs and errors, and retrain when the population changes.

h* = arg maxh ∈ H P(h)

h* is the chosen hypothesis; H is the hypothesis space, the set of candidate models; P(h) is the validation performance of hypothesis h.

Two failure points deserve a check. First, choose P before seeing results, otherwise the score can be chosen to flatter the model. Second, keep test data untouched; leakage makes P optimistic. Chapter 1.4 lists the common data and generalization failures. Full evaluation metrics come in Unit 2, Regression and Model Evaluation.

Three views and search

Three views help when choosing a representation.

  • Geometric view: each example is a point in feature space; the model is a boundary, line or curve that separates or fits the points.
  • Probabilistic view: the model estimates P(y | x), the probability of label y given features x; this also gives uncertainty.
  • Logical view: the model is a rule, such as 'if income is high and debt is low then repay'; the rule is true or false for each example.

Learning is search over hypotheses. The hypothesis space H is the set of all models the algorithm may return. E supplies the evidence, and P scores each candidate. With many features, H can be huge or infinite. The algorithm cannot test every model, so it uses a search strategy and an inductive bias. Chapter 1.6 shows Find-S and version spaces for concept learning. Chapter 1.7 explains why bias is necessary for generalization. The same search view applies to decision trees, neural networks and support vector machines later in the course.

Worked example

Question. A bank has 5000 past loan records. 500 borrowers defaulted; 4500 repaid. The bank first states: T = predict repay or default at application; P = accuracy; E = the 5000 labelled records. (a) Compute the accuracy of a model that always predicts repay. (b) Compute its recall for the default class. (c) If a missed default costs ₹1,00,000 and a wrongly rejected good loan costs ₹5,000, compute the total cost of this always-repay model. (d) Explain why the problem is not well designed and state one better P.

  1. Total records N = 5000. Defaulters D = 500. Repayers R = 5000 - 500 = 4500.
  2. Always-repay predicts repay for all 5000 records. Correct predictions = 4500. Accuracy = 4500 / 5000 = 0.90 = 90%.
  3. Take default as the positive class. True positives TP = 0; false negatives FN = 500. Recall = TP / (TP + FN) = 0 / 500 = 0.0.
  4. Missed defaults = 500. False rejects = 0. Cost = 500 × ₹1,00,000 + 0 × ₹5,000 = ₹5,00,00,000.
  5. The score P hides the default class: 90% accuracy comes from the majority class, and recall is 0. A better P is recall on defaults at a fixed false-positive budget, or expected rupee cost.

Answer. The always-repay model has accuracy 0.90 (90%), recall 0.0 for default, and cost ₹5,00,00,000; the problem is not well posed for the bank until P targets default detection or cost.

Exam traps

  • Stating only the task T and forgetting the performance measure P and the experience E. A task alone is not a learning problem.
  • Using accuracy on imbalanced data as the only performance measure. A trivial majority-class rule can look strong while the rare class is never found.
  • Confusing E with the whole database. E is the experience actually available for learning, with its labels and data source checked.
  • Choosing an algorithm before fixing the representation and the measure. The score can then be picked to suit the model instead of the goal.

1.4 Challenges and issues in machine learning

Most machine learning failures come from data and generalization, not from the algorithm alone. A model can fit its training rows and still fail on a new customer, a new city or next month's traffic. This chapter lists the common challenges: small or noisy data, missing values, imbalanced classes, overfitting and underfitting, the bias-variance trade-off, high dimensionality, feature scaling, data leakage, concept drift and poor evaluation. These checks matter in UPI fraud detection, IRCTC demand forecasts and a Chennai power-cut predictor. The goal is a model that works on unseen data.

You need: Chapter 1.3 for the design cycle and performance measure.

Generalization, overfitting and underfitting

A model is useful only if it works on data it has not seen. Training error is error on the rows used for fitting; validation error is error on held-out rows. Underfitting means the model is too simple: both errors are high. Overfitting means the model is too flexible: training error is low but validation error is high. The gap validation error minus training error measures overfitting. Bias is error from wrong assumptions. Variance is error from sensitivity to the training sample. More complex models usually lower bias and raise variance. The bias-variance trade-off picks the complexity that minimises total error. See Unit 2 for the full derivation, regularization and cross-validation.

E[(y − f̂(x))²] = bias² + variance + σ²

y is the true target; f̂(x) is the model prediction; bias is the average gap between the true rule and the model's average prediction; variance is how much the prediction changes across training samples; σ² is unavoidable noise.

Figure 1.4.1 plots both errors against polynomial degree, which stands for model complexity. At complexity 3, validation error is 0.12, close to training error 0.10. At complexity 5, training error is 0.04 but validation error is 0.25. At complexity 9, training error falls to 0.01 but validation error rises to 0.45. That is overfitting: the model has learned detail that does not generalise.

Data problems

Data problems cause most failures. With small data, a sample of 30 loan applications cannot support a rule with hundreds of features; variance dominates. Noisy labels teach wrong patterns: one mislabelled UPI fraud record is a wrong lesson. Missing values are common; a sensor can fail during a Chennai power cut. Dropping rows loses information, and mean filling can distort distributions. Imbalanced classes need care: if fraud is 1 in 1000 transactions, a model that always says 'not fraud' is 99.9% accurate and catches nothing. Use precision, recall or F1, and resample with care. The curse of dimensionality means that as features grow, data become sparse. Distance-based methods such as kNN lose meaning because nearest and farthest neighbours become similar. Feature scaling puts features on comparable ranges; a salary in rupees can dominate age in years. Standardise or normalise using training statistics only. See Unit 4 for dimensionality reduction and Unit 2 for metrics.

Evaluation, leakage and change

Evaluation must mimic deployment. Data leakage happens when information from the test set or the target leaks into training. A common slip is scaling features using all data before splitting, or using a future transaction to predict a past one. Keep the test set untouched and use it once. Concept drift means the relation between features and target changes over time. A model for electricity demand in Chennai learns summer patterns but fails after a new tariff or a heat wave. Monitor error and feature distributions, then retrain on recent data. Domain shift means test data come from a different source than training data, such as a model trained on Delhi traffic applied to Chennai. Only a few universities teach domain shift under this name. Evaluation choice matters: accuracy hides imbalance, and one split can be lucky. Use cross-validation and choose the metric that matches the cost of errors. Full treatment in Unit 2.

Worked example

Question. A polynomial model is fitted at three degrees. Degree 1: training error 0.30, validation error 0.32. Degree 3: training error 0.10, validation error 0.12. Degree 9: training error 0.01, validation error 0.45. Compute the generalization gap for each degree. Which model underfits, which is a good fit, and which overfits?

  1. Gap = validation error − training error. Errors are unitless.
  2. Degree 1: 0.32 − 0.30 = 0.02.
  3. Degree 3: 0.12 − 0.10 = 0.02.
  4. Degree 9: 0.45 − 0.01 = 0.44.
  5. Degree 1 has gap 0.02, but both errors are high (0.30 and 0.32), so it underfits.
  6. Degree 3 has low training and validation error, so it is a good fit.
  7. Degree 9 has low training error 0.01 but high validation error 0.45 and gap 0.44, so it overfits.

Answer. The gaps are 0.02, 0.02 and 0.44 (unitless); degree 1 underfits, degree 3 is a good fit, and degree 9 overfits.

Exam traps

  • Judging a model by training error alone. Low training error can mean overfitting, not a better model.
  • Calling every validation failure overfitting. If training and validation error are both high, the model underfits.
  • Scaling or filling missing values before the train-test split. That leaks test information into training.
  • Reporting accuracy on imbalanced data. A majority-class predictor can look strong and be useless.
  • Confusing concept drift with noise. Drift is a change in the feature-target relation, not random label errors.

1.5 Math review: linear algebra, probability and distributions

Linear algebra and probability are the working languages of machine learning. Linear algebra packs one example into a vector and a table into a matrix, so a model becomes a short formula. Probability describes what is not known: noise, missing labels, and the chance that a new user behaves like an old one. Distributions describe patterns of values; the Gaussian is the default bell curve. These ideas appear when you scale features, read a correlation matrix, or write a likelihood. This chapter gives the minimum needed for the rest of the course.

You need: Chapter 1.1 for features and data terms, and school algebra.

Vectors, matrices and dot products

A vector is an ordered list of numbers. A feature vector x = (x1, x2, …, xn) stores n measurements for one example, such as age, monthly income in rupees, and number of UPI payments. A matrix X stores many examples: one row per example, one column per feature. If X has m rows and n columns, its shape is m × n.

The dot product combines two vectors into one number. It measures alignment. If θ is the angle between a and b, the dot product is also ||a|| ||b|| cos θ. The norm ||a|| = √(a · a) is length; ||a||2 is the Euclidean length. A perceptron score and a linear-regression prediction both start with a dot product.

a · b = Σ<sub>i=1</sub><sup>n</sup> a<sub>i</sub>b<sub>i</sub> = ||a|| ||b|| cos θ

a and b are vectors of length n; ai and bi are their i-th entries; ||a|| is the Euclidean norm; θ is the angle between them.

Matrix multiplication composes linear maps: C = AB has Cij = Σk AikBkj. The transpose Aᵀ flips rows and columns. The inverse A−1 satisfies A−1A = I when A is square and full rank; many data matrices are not invertible, so least squares or regularization is used. Eigenvalues λ satisfy Av = λv for a nonzero vector v; PCA later uses them to find directions of largest variance.

Probability and conditioning

A random variable maps an outcome to a number. A discrete random variable takes separate values, such as number of purchases (0, 1, 2, …). A continuous random variable takes any value in an interval, such as delivery time in minutes. P(A) is the probability of event A, a number from 0 to 1. P(A and B) is joint probability. P(A) alone is marginal probability. Conditional probability asks about one event given another.

P(B|A) = P(A and B) / P(A)

P(B|A) is the conditional probability of B given A; P(A and B) is the joint probability of both events; P(A) is the marginal probability of A, with P(A) > 0.

Expectation E[X] is the long-run average. Variance Var(X) = E[(X−μ)²] is spread, with μ = E[X]. Its square root is standard deviation. Covariance Cov(X,Y) = E[(X−μX)(Y−μY)] measures joint movement; correlation ρ = Cov(X,Y)/(σXσY) lies between −1 and 1 and has no units. Bayes rule rewrites P(A|B) using P(B|A); Unit 3 uses it for classifiers.

Independence means P(A and B) = P(A)P(B), equivalently P(B|A) = P(B). It is not the same as zero correlation in general. The UPI example below shows the arithmetic.

Bernoulli, binomial, uniform, Gaussian

Bernoulli(p) is one yes/no trial: P(1) = p, P(0) = 1−p, E[X] = p, Var(X) = p(1−p). Binomial(n,p) counts successes in n independent Bernoulli trials: P(X=k) = C(n,k)pk(1−p)n−k, where C(n,k) counts ways to choose k items from n. Uniform(a,b) gives equal density 1/(b−a) on [a,b]. The Gaussian (normal) N(μ,σ²) has a density set by its centre and spread.

f(x) = (1/(σ√(2π))) exp(−(x−μ)²/(2σ²))

f(x) is the density at x; μ is the mean; σ is the standard deviation; σ² is the variance; π ≈ 3.14159.

A multivariate Gaussian N(μ, Σ) has a mean vector μ and covariance matrix Σ. Its shape is set by Σ: diagonal entries are variances, off-diagonal entries are covariances. Two Gaussian curves with the same σ = 1 and different means have the same bell shape, shifted along the axis. The density is not a probability at a point; area under the curve gives probability.

Quick data exploration

Before a model, look at each feature. Mean is the arithmetic average, sensitive to outliers. Median is the middle value after sorting, robust to outliers. IQR = Q3 − Q1 is the middle 50% spread; Q1 and Q3 are the 25th and 75th percentiles. A histogram shows the shape of one variable; a box plot shows median, quartiles and possible outliers; a scatter plot shows two variables and hints at correlation.

Use these plots to find typos, missing values, heavy tails and engineering-unit mistakes. For example, a delivery-time column in seconds instead of minutes shows as a faraway cluster. Do not delete an outlier without a reason: it may be the rare fraud case you need. Correlation describes linear association only; a curved relation can have ρ near 0. See Unit 4 for feature selection and correlation analysis.

Worked example

Question. Among 1000 users, A means uses UPI and B means shops online. Counts: 400 use both, 200 use UPI only, 100 shop online only, and 300 neither. Find P(A), P(B), P(A and B) and P(B|A). Are A and B independent?

  1. Total users = 400 + 200 + 100 + 300 = 1000.
  2. P(A) = (400 + 200)/1000 = 600/1000 = 0.60.
  3. P(B) = (400 + 100)/1000 = 500/1000 = 0.50.
  4. P(A and B) = 400/1000 = 0.40.
  5. P(B|A) = P(A and B)/P(A) = 0.40/0.60 = 400/600 = 0.667, rounded to three decimals.
  6. Independence needs P(B|A) = P(B). Here 0.667 ≠ 0.50, so A and B are not independent.

Answer. P(A) = 0.60, P(B) = 0.50, P(A and B) = 0.40, P(B|A) = 0.667; A and B are not independent.

Exam traps

  • P(A|B) and P(B|A) swap the conditioning event; use the denominator of the event that is given.
  • Variance has squared units; standard deviation returns to the original units.
  • Zero correlation means no linear association, not independence; independence implies zero covariance, but the reverse fails in general.
  • A density can exceed 1 for a narrow continuous variable; it is not a probability.
  • For skewed income data, mean is pulled by large values while median stays near the middle.

1.6 Concept learning: Find-S, version spaces, candidate elimination

Concept learning learns a rule from labelled examples. Each example is a row of attribute values marked positive or negative. The learner searches a space of possible rules for one that covers all positives and rejects all negatives. This chapter studies three standard tools: Find-S, version spaces and candidate elimination. They are used in small logical learning problems and as the basis for later rule learners. The ideas explain how a machine can move from examples to a general rule, and why the choice of hypothesis language limits what it can learn.

You need: Chapter 1.3 for hypothesis space and learning as search, and Chapter 1.5 for sets and basic probability intuition.

The concept learning task

Concept learning takes a set of examples, each described by attribute values and marked positive or negative, and produces a rule that separates them. The rule is the target concept. In this chapter an example is a row with three attributes: Sky, Temp, Wind. A positive example belongs to the concept; a negative example does not.

Let X be the set of examples and C:X→{0,1} the target concept. A hypothesis h is a conjunction of constraints, one per attribute. A constraint is a fixed value, ? (any value), or ∅ (no value allowed). h covers x when every attribute matches. ? matches any value; ∅ matches no value. The hypothesis space H is all such conjunctions. For three attributes with small domains H is finite, so learning is search through H.

General-to-specific ordering: h1 is more general than h2 exactly when h1 covers every example that h2 covers. Replacing a fixed value or ∅ by ? makes that hypothesis more general. Do not compare hypotheses by counting ?; two hypotheses with different numbers of ? can be incomparable. The all-? hypothesis ⊤ covers everything. The all-∅ hypothesis ⊥ covers nothing. Find-S and candidate elimination both use this order.

Find-S

Find-S starts at the most specific hypothesis h=(∅,∅,∅). For each positive example, if h covers it, leave h unchanged. If not, replace each conflicting fixed value by ?. For each negative example, do nothing. Return h after all positives.

  1. Set h=(∅,∅,∅).
  2. For each positive x: for each attribute a, if h[a]=∅ set it to x[a]; if h[a]≠x[a] set it to ?.
  3. For each negative example: skip it.
  4. Return h.

Example: positives (Sunny,Warm,Strong) and (Sunny,Warm,Weak) give h=(Sunny,Warm,?) after the second example. The negatives (Rainy,Cold,Strong) and (Sunny,Cold,Strong) do not change h. Find-S returns one most specific hypothesis covering all positive examples. It is consistent with all examples only when a consistent conjunction exists, that is, when there is no noise and the hypothesis language is adequate. Find-S does not check negatives, so its answer can still cover a negative example if those conditions fail.

Version spaces and candidate elimination

A version space is the set of all hypotheses in H that cover every positive example and no negative example. It is represented by two boundary sets. S is the set of most specific hypotheses in the version space. G is the set of most general hypotheses. Every consistent hypothesis lies between some s in S and some g in G under the general-to-specific order.

Candidate elimination updates S and G example by example. For a positive example x: remove from G every hypothesis that does not cover x; generalize each s in S minimally so that it covers x; remove from S any hypothesis more general than another member of S. For a negative example x: remove from S every hypothesis that covers x. For each g in G that covers x, replace g with all minimal specializations that exclude x and remain consistent with the positives, then prune G. If g already excludes x, leave it.

List-then-eliminate is the brute-force version: list all h in H, keep those consistent with every example. It gives the same version space but costs time proportional to |H|. Candidate elimination can be cheaper because it stores only the boundaries. Some syllabi use the phrase candidate elimination for the boundary update itself. If S or G becomes empty, no hypothesis in H fits the data.

Worked example

Question. Attributes: Sky, Temp, Wind. Positive examples: P1=(Sunny,Warm,Strong), P2=(Sunny,Warm,Weak). Negative examples: N1=(Rainy,Cold,Strong), N2=(Sunny,Cold,Strong). Run Find-S. Run candidate elimination. State final S and G and the number of hypotheses in each boundary set.

  1. Find-S starts at h0=(∅,∅,∅).
  2. P1: h1=(Sunny,Warm,Strong).
  3. P2: Wind differs (Strong vs Weak), so h2=(Sunny,Warm,?).
  4. N1 and N2 are negative, so h stays (Sunny,Warm,?). Final Find-S hypothesis: h=(Sunny,Warm,?).
  5. Candidate elimination starts with S0={(∅,∅,∅)} and G0={(?,?,?)}.
  6. After P1: S1={(Sunny,Warm,Strong)}; G1={(?,?,?)}.
  7. After P2: S2={(Sunny,Warm,?)}; G2={(?,?,?)}.
  8. N1: S2 does not cover N1, so S stays. Remove (?,?,?) from G. Minimal specializations covering both positives and excluding N1 are (Sunny,?,?) and (?,Warm,?). G3={(Sunny,?,?), (?,Warm,?)}.
  9. N2: S2 does not cover N2, so S stays. (?,Warm,?) does not cover N2, so it stays. (Sunny,?,?) covers N2; replace it by (Sunny,Warm,?). Prune (Sunny,Warm,?) because (?,Warm,?) is more general. G4={(?,Warm,?)}.
  10. Final S={(Sunny,Warm,?)} and G={(?,Warm,?)}. Number in S=1. Number in G=1.

Answer. Final Find-S hypothesis is (Sunny,Warm,?); final S=(Sunny,Warm,?) with one hypothesis; final G=(?,Warm,?) with one hypothesis.

Exam traps

  • Positive examples mainly generalize S and also filter G; negative examples mainly specialize G and also filter S. A negative example covered by an S hypothesis removes that S hypothesis.
  • ? matches any value; ∅ matches no value. They are not the same, and ∅ is not a missing value.
  • Find-S ignores negatives, so do not claim it always rejects all negatives.
  • In G, specializing means replacing ? by a value or ∅; adding ? makes a hypothesis more general, not more specific.
  • If S or G is empty, the version space is empty; do not invent a boundary hypothesis.

1.7 Inductive bias and generalization

A learner sees a finite set of examples and must choose a rule that works on unseen cases. Usually many rules fit the training data exactly. Inductive bias is the set of assumptions that breaks the tie and picks one general rule. It is why a learner can generalize at all. Find-S, candidate elimination and decision trees each carry a different bias. In practice, bias is chosen to match the domain: spam filters, credit scoring, medical triage. The same idea appears as a prior in Bayesian learning.

You need: Chapter 1.6 for version spaces and Find-S, and Chapter 1.4 for the overfitting preview.

Bias chooses one rule from many

A hypothesis is one rule that labels examples. The hypothesis space is the set of all rules the learner is allowed to consider. With 20 emails and 10 binary features, the space can hold more than a thousand rules. Many of them fit the same 20 labels. Training data alone cannot say which one to keep.

Inductive bias is the set of assumptions a learner uses to choose one general rule among the many rules consistent with the data. Consistent means zero training error on the seen examples. The bias can be a restriction on the rule language, an order on rules, or a preference score.

Find-S has a simple bias: it keeps the most specific hypothesis. It starts from the most specific rule and generalizes only when a positive example forces it. It never generalizes beyond what the positive examples force. Candidate elimination keeps all consistent hypotheses in the version space. Its bias is the chosen hypothesis space: usually conjunctions of attribute constraints, with a most specific and a most general boundary.

A decision tree learner prefers shorter trees. A shorter tree is a simpler rule, and the preference is a bias, not a proof. This is the Occam preference. The no-free-lunch result says no learner is best on every possible task. A bias that helps on email spam may hurt on a task with reversed labels. So bias must match the domain.

Training error, test error and the gap

Generalization means performance on new examples from the same distribution. Training error measures fit on seen examples. Test error measures fit on unseen examples. A model can have low training error and high test error. That is overfitting.

training error = wrong on training ÷ n_train

wrong on training is the number of training examples misclassified; n_train is the number of training examples.

Test error uses a separate test set with n_test examples. The generalization gap is test error minus training error. Report both errors as percentages, so the gap is in percentage points.

generalization gap = test error − training error

the gap is in percentage points when both errors are percentages; a large positive gap signals overfitting.

A small gap with high training error is underfitting. A large gap with low training error is overfitting. The worked example shows two rules with the same training error but different test error.

Bias as a prior: the MAP view

Probability turns bias into a prior. A prior P(h) gives each hypothesis a starting preference before seeing data. The likelihood P(D | h) says how well h explains data D. The posterior P(h | D) combines both.

P(h | D) ∝ P(D | h) × P(h)

P(h | D) is the posterior probability of hypothesis h after data D; P(D | h) is the likelihood of the data under h; P(h) is the prior probability of h; ∝ means proportional to.

MAP learning picks the single hypothesis with the largest posterior. The prior is the inductive bias. A prior that prefers short decision trees makes MAP prefer shorter trees. Full Bayes averages over many hypotheses instead of picking one; see Unit 3, Classification: Trees, Bayes, kNN, SVM.

h_MAP = argmax_h [log P(D | h) + log P(h)]

h_MAP is the chosen hypothesis; argmax_h picks the h with the largest value; log turns products into sums.

Worked example

Question. Two hypotheses h1 and h2 both fit 20 training emails with 18 correct. h1 is a complex rule with 30 conditions; h2 has 3 conditions. On 100 test emails, h1 is correct on 65 and h2 on 80. Compute training error, test error and the generalization gap for each.

  1. Training errors: h1 is wrong on 20 − 18 = 2 emails, so 2 ÷ 20 × 100 = 10%. h2 is also wrong on 2 emails, so 2 ÷ 20 × 100 = 10%.
  2. Test errors: h1 is wrong on 100 − 65 = 35 emails, so 35 ÷ 100 × 100 = 35%. h2 is wrong on 100 − 80 = 20 emails, so 20 ÷ 100 × 100 = 20%.
  3. Generalization gaps: h1 gap = 35% − 10% = 25 percentage points. h2 gap = 20% − 10% = 10 percentage points.
  4. The simpler h2 has the smaller gap, so the complexity preference is a useful inductive bias here.

Answer. h1: training error 10%, test error 35%, gap 25 percentage points. h2: training error 10%, test error 20%, gap 10 percentage points. h2 generalizes better.

Exam traps

  • Saying a learner has no bias. Every learner that generalizes beyond seen data has some inductive bias.
  • Confusing inductive bias with statistical bias or the bias term in the bias-variance trade-off. They are different ideas.
  • Reporting training error as if it were generalization. Always state test error and the gap.
  • Writing a gap of 25% when the errors are percentages. The gap is 25 percentage points, not 25 percent.
  • Assuming the shorter tree is always better. Occam preference is a bias, not a guarantee; test data decides.

Initialise h to the most specific hypothesis, all attributes at their null value; Read each example in order; Update only on positive examples: replace a null with the example's value, or generalise to '?' on mismatch; Ignore negative examples unless they contradict h, which signals noise; Write the final hypothesis as a conjunction of attribute constraints; State the weakness: the result depends on example order and on the first positive example.

Apply Apply the candidate elimination algorithm to the same PlayTennis data. Show the general boundary G and specific boundary S after each example and hence the version space. 13 marks

Initialise S to the most specific hypothesis and G to the most general hypothesis {?, ?, ?}; Positive example: generalise S, remove from G any hypothesis that does not cover it; Negative example: specialise G so that it excludes the example, keep S unchanged; Correct treatment of a hypothesis in G that is more specific than a hypothesis in S; Final version space described as everything between S and G; Note that the version space shrinks monotonically and can become empty with noise.

Apply Design a learning system for predicting whether a farmer's crop will fail, covering task, performance measure, experience, features, data split and evaluation. 13 marks

Task statement and decision the output supports; Performance measure such as recall on the failure class, not accuracy alone; Experience: which fields, which seasons, how many labelled records; Feature list with units and how each would be collected; Train, validation and test split; keeping the same season out of both sides; Baseline to beat and error analysis loop; Deployment and monitoring concerns such as domain shift.

Apply Compute the mean, variance and correlation between two features, then standardise both features. Explain in one paragraph why standardisation matters before a distance-based method such as k-nearest neighbours. 13 marks

Correct formulas with units and n or n−1 in the denominator; Correlation as covariance divided by the product of standard deviations, between −1 and +1; Standardisation z = (x − mean) / standard deviation; Distance dominated by the feature with the larger scale without it; Worked numeric substitution; Interpretation of a positive and a negative correlation.

Analyze and evaluate

Analyze Discuss the main challenges in machine learning under the headings data, model and evaluation. Give one concrete failure for each heading. 13 marks

Data: insufficient quantity, noisy labels, missing values, class imbalance, biased sampling; Model: overfitting, underfitting, curse of dimensionality, poor inductive bias for the problem; Evaluation: leakage between train and test, wrong metric, distribution shift at deployment; Each failure tied to a realistic example; Mitigations: more and cleaner data, regularisation, cross-validation, held-out testing.

Analyze Explain the bias-variance trade-off. Relate it to model complexity, training error, test error and the size of the training set. 13 marks

Expected squared error split into bias², variance and irreducible noise; High bias: simple model, underfits, both errors high; High variance: complex model, small training error, large test error; Effect of increasing training data on variance; Regularisation as a way to trade variance for bias; How cross-validation estimates test error and guides the choice.

Evaluate A hospital wants a screening tool for a disease that affects 1 in 1000 people. Compare accuracy with precision, recall and the confusion matrix as the reported metric, and recommend a design. 13 marks

Confusion matrix layout: true positive, false positive, false negative, true negative; Why accuracy is misleading when the classes are imbalanced: a model that always says 'no' scores 99.9 percent; Recall as the fraction of true cases found; the cost of a false negative in screening; Precision and the cost of false positives such as extra tests and anxiety; Recommended metric and decision threshold chosen from the cost of each error; Need for calibration and for testing on a sample with the real prevalence.

Evaluate Compare Find-S, candidate elimination and a decision-tree learner on the same concept-learning task. Which would you choose and why? 16 marks

What each returns: one hypothesis, the whole version space, a tree; Sensitivity to example order and to noise; Handling of negative examples only through consistency; Expressiveness: conjunctions only versus disjunctions through trees; Cost: number of hypotheses examined; Decision justified by what the user needs, a single rule or a ranked set of rules.

Analyze Trace the full path from a business question to a deployed model: problem framing, data preparation, model choice, evaluation and monitoring. Use a UPI fraud detection example. 16 marks

Framing as a well-posed problem with task, performance measure and experience; Label definition: which transactions count as fraud, and the delay in confirming them; Feature engineering from transaction amount, time, device and merchant history; Imbalance and the choice of precision, recall or cost-weighted metric; Model choice and a held-out or time-based split; Threshold selection and the human review queue; Monitoring for domain shift: new fraud patterns change the input distribution.

Glossary

Classification
Supervised learning where the label is one of a finite set of classes.
Clustering
Unsupervised grouping of examples so that similar examples fall in the same group.
Consistent hypothesis
A hypothesis that gives the correct label for every training example seen so far.
Domain shift
A change in the input distribution between training and deployment that lowers performance.
Experience E
The data or interactions the program learns from.
General boundary G
The most general hypotheses in the version space.
Generalization error
The expected error of a learned model on new examples drawn from the same distribution.
Hypothesis
A candidate rule that maps a feature vector to a prediction or label.
Hypothesis space
The set of all hypotheses the learner is allowed to search.
Inductive bias
The set of assumptions that lets a learner rank or restrict hypotheses beyond the data.
Learning
A change in behaviour or performance that comes from experience rather than from explicit programming.
Marginalisation
Summing or integrating a joint distribution over one variable to get the distribution of the others.
Negative example
An example for which the target concept is false.
Overfitting
Fitting noise in the training data so that performance on new data drops.
Performance measure P
The number used to judge the program on the task, for example accuracy or recall.
Positive example
An example for which the target concept is true.
Random variable
A variable whose value is uncertain and is described by a probability distribution.
Regression
Supervised learning where the label is a real number with units.
Regularisation
Adding a penalty on model size or weight magnitude to reduce overfitting.
Reward
A scalar signal in reinforcement learning telling the agent how good the last action was.
Specific boundary S
The most specific hypotheses in the version space.
Supervised learning
Learning a mapping from inputs to outputs using labelled example pairs.
Task T
The exact job the learned program must do, such as classify or predict a number.
Vector
An ordered list of numbers, used here to hold the feature values of one example.
Version space
The set of all hypotheses consistent with the training data.
