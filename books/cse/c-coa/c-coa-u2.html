2.1 Memory locations, addresses and memory operations

Main memory is a long row of storage cells, and each cell has a number called its address. The processor uses only two operations on it: Load (read a cell) and Store (write a cell). Every instruction in this unit names either a register or one of these addresses, so you need to know how addresses are counted, how a multi-byte number is laid out across cells, and what happens on the buses during a read or a write.

You need: the memory unit, MAR and MDR from Unit 1, Functional units of a computer, and the address and data buses from Unit 1, Bus structures.

Bits, bytes, words and the address space

Memory stores bits, but it never hands out one bit at a time. A byte is 8 bits. A word is the group of bits the processor normally reads or writes in one operation, and its size is the word length: 16, 32 or 64 bits on most machines. A 32-bit word holds four bytes, for example four characters or one integer.

Each location has an address. If addresses are k bits long, there are 2k different addresses, numbered 0 to 2k − 1. This set is the address space. In memory sizes, K = 210 = 1024, M = 220 and G = 230:

  • k = 16 gives 216 = 65,536 locations (64K).
  • k = 24 gives 224 = 16,777,216 locations (16M).
  • k = 32 gives 232 = 4,294,967,296 locations (4G).

The same rule sizes a memory chip. A chip organised as 64K × 16 has 216 words of 16 bits, so it needs 16 address lines and 16 data lines.

Byte addressing, alignment and byte order

Almost every modern machine is byte-addressable: each byte has its own address. With 32-bit words, word 0 occupies bytes 0 to 3, the next word starts at byte 4, then 8, 12, and so on. That is why array element i of a 32-bit integer array sits at base + 4 × i.

A word of s bytes is aligned when its address is a multiple of s: 4-byte words at 0, 4, 8, and 8-byte words at 0, 8, 16. Aligned words can be moved in one memory access. MIPS refuses an unaligned lw and raises an address-error exception; x86 accepts it but may need two accesses.

When a 4-byte number is stored, which byte goes to the lowest address? There are two conventions, shown in Figure 2.1.1:

  • Big-endian: the most significant byte (MSB) goes to the lowest address. Used by IBM mainframes, classic MIPS and SPARC, and by network protocols ("network byte order").
  • Little-endian: the least significant byte (LSB) goes to the lowest address. Used by x86, by ARM as normally configured, and by RISC-V.

Byte order only matters when the same bytes are read with a different size than they were written, or moved to another machine. The bits inside a byte are not reversed, and a text string is stored first character first on both kinds of machine.

Memory operations: Load and Store

A Load (read) copies the contents of a location into the processor and leaves the location unchanged. A Store (write) puts new data into a location and destroys what was there. In register transfer notation, where [X] means "the contents of X":

Load : R2 ← [LOC]      (copy the word at address LOC into register R2)
Store: [LOC] ← R4      (copy register R4 into the word at address LOC)

Inside the processor, both go through two registers: the memory address register (MAR), which drives the address bus, and the memory data register (MDR), which connects to the data bus.

  1. Read: the processor puts the address in MAR and raises the Read line on the control bus.
  2. The memory finds the location and places its contents on the data bus; it signals Memory Function Completed (MFC).
  3. The word is latched into MDR and then copied to the destination register.
  4. Write: the processor puts the address in MAR and the data in MDR, then raises the Write line; the memory stores the word and signals MFC.

ISAs also offer smaller transfers. MIPS has lw/sw for words and lb, lbu, sb for single bytes; lb sign-extends the byte to 32 bits, lbu fills with zeros.

Segmented addresses on the 8086

The 8086 forms a physical address from a 16-bit segment register and a 16-bit offset:

Physical address = segment × 10h + offset     (shift the segment left by 4 bits, then add)

The segment registers are CS (code), DS (data), SS (stack) and ES (extra); each segment spans up to 64 KB. For the next instruction, CS = 2000h and IP = 0150h give 20000h + 0150h = 20150h. Chapter 2.4 uses this rule with each addressing mode.

Worked example

Question. A byte-addressable computer has 32-bit words and 24-bit addresses. (a) How many bytes and how many words can it address? (b) The word 0x0A1B2C3D is stored at address 2000. Show the bytes at 2000 to 2003 in big-endian and in little-endian order. (c) Which of 2000, 2006 and 2012 can hold an aligned word? (d) How many address and data lines does a 256K × 8 memory chip need? (e) On an 8086, DS = 3A00h and the offset is 0124h. Find the physical address.

  1. (a) Bytes = 224 = 16,777,216 (16 MB). Words = 224 ÷ 4 = 222 = 4,194,304 (4M words).
  2. (b) Big-endian: 2000 → 0A, 2001 → 1B, 2002 → 2C, 2003 → 3D. Little-endian: 2000 → 3D, 2001 → 2C, 2002 → 1B, 2003 → 0A.
  3. (c) Aligned means address mod 4 = 0. 2000 mod 4 = 0, aligned. 2006 mod 4 = 2, not aligned. 2012 mod 4 = 0, aligned.
  4. (d) 256K = 28 × 210 = 218 words, so 18 address lines; 8 bits per word, so 8 data lines.
  5. (e) 3A00h × 10h = 3A000h; 3A000h + 0124h = 3A124h.

Exam traps

  • 2k counts locations, not bytes. A word-addressable memory with 224 locations of 4 bytes holds 64 MB, not 16 MB.
  • In memory sizes 64K means 65,536, not 64,000.
  • Endianness reorders bytes, never the bits inside a byte, and never the characters of a string.
  • The next 32-bit word is at address + 4, not + 1, on a byte-addressable machine.
  • Favourite question: "Show how 0x… is stored in big- and little-endian memory." Draw the four cells with their addresses.

2.2 Instructions and instruction sequencing

A program is a list of instructions stored in memory. The processor fetches the instruction whose address is in the program counter (PC), executes it, and moves to the next. Instruction sequencing is the rule for moving on: straight to the next address by default, or to another address when a branch says so. This chapter names the kinds of instructions, shows how many operand addresses an instruction can carry, and follows the PC and the condition flags through a real loop.

You need: Load and Store from 2.1, and the fetch–execute cycle from Unit 1, Basic operational concepts.

Notation and the four kinds of instructions

Register transfer notation (RTN) says what an instruction does: R3 ← [R1] + [R2] means "add the contents of R1 and R2 and put the result in R3". Assembly notation says how it is written: Add R3, R1, R2. In this book the destination comes first, as in MIPS, ARM and Intel-syntax x86. Some textbooks put it last, so check the convention in every question.

Every ISA has instructions of four kinds:

  • Data transfer: between memory and registers (Load, Store, Move).
  • Arithmetic and logic: Add, Subtract, Multiply, And, Or, Shift.
  • Program sequencing and control: Branch, Jump, Call, Return.
  • Input/output: moving data to and from devices (Unit 6).

Three-, two-, one- and zero-address instructions

An instruction must say where its operands are. Take C ← [A] + [B], where A, B and C are memory locations:

  • Three-address: Add C, A, B. One instruction, but it carries three full addresses, so it is long.
  • Two-address: Move C, A then Add C, B. The destination is also a source, so its old value is overwritten.
  • One-address: Load A, Add B, Store C. A hidden register, the accumulator (AC), is the second operand and the destination.
  • Zero-address: Push A, Push B, Add, Pop C. Operands are taken from the top of a stack, and the result goes back on it.

RISC machines use the load/store style: only Load and Store touch memory, and arithmetic works on registers, for example Load R1, A, Load R2, B, Add R3, R1, R2, Store R3, C. More addresses per instruction means longer instructions but fewer of them; chapter 2.3 shows what this costs in bits.

Straight-line sequencing and the program counter

Instructions sit at consecutive addresses. With 4-byte instructions on a byte-addressable machine they are at i, i + 4, i + 8, and so on. The PC holds the address of the next instruction. Each cycle has two phases:

  1. Fetch: IR ← [[PC]] (read the word whose address is in PC into the instruction register), then PC ← [PC] + 4.
  2. Execute: decode IR and perform the operation. The PC already points at the following instruction.

Without branches the processor simply walks down memory. This is straight-line sequencing.

Branching and condition codes

A branch loads a new address, the branch target, into the PC. An unconditional branch always does this. A conditional branch does it only when a condition holds; otherwise the PC keeps its PC + 4 value and the program falls through. The program below adds a list of N numbers this way: the five instructions from LOOP run once per number, and the branch sends the PC back while the counter R2 is still positive. LOAD A           ; AC = 2

Exam traps

  • Check the operand order. Add R3, R1, R2 puts the result in R3 here; in a destination-last book the same line puts it in R2.
  • The PC holds the address of the next instruction. While the instruction at 1028 executes, PC already reads 1032.
  • Flags are set by the last arithmetic or logic instruction, not by the branch that tests them.
  • Zero-address does not mean no operands: they are implicit on the stack top. ADD pops two and pushes one.
  • Favourite question: "Evaluate X = (A + B) × (C + D) with 3-, 2-, 1- and 0-address instructions."

2.3 Instruction formats and encoding of machine instructions

In memory an instruction is just a binary word. Its format divides that word into fields: an opcode that names the operation, and operand fields that name registers, memory addresses or constants. Encoding turns an assembly line into those bits, and decoding turns bits back into an operation; the processor's control unit decodes every instruction it fetches. The format fixes how many operations, how many registers and how large a constant a machine can have, so it is where hardware cost and programmer convenience meet.

You need: the three-, two-, one- and zero-address forms from 2.2, and binary–hex conversion with two's complement from Unit 3.

Fields, widths and length

A typical instruction has some of these fields: opcode (which operation), register specifiers, a memory address or displacement, an immediate (a constant inside the instruction), and mode bits that say how to interpret an operand (chapter 2.4). A field of b bits can name 2b things, so the width needed for n items is ⌈log2 n⌉ bits: 32 registers need 5 bits, 100 opcodes need 7.

The number of addresses per instruction (chapter 2.2) drives the length. Three full 32-bit memory addresses would need a 96-bit operand part. That is why RISC machines allow memory addresses only in Load and Store, and use 5-bit register numbers everywhere else.

  • Fixed length: every instruction has the same size, 32 bits on MIPS, ARM (A32) and RISC-V. Fetch and decode are simple and the next instruction is always at PC + 4, which suits pipelining (Unit 5). Some bits are wasted on simple instructions.
  • Variable length: size depends on the operation and its operands. An x86 instruction takes 1 to 15 bytes; the 8086's take 1 to 6. Code is compact, but the decoder must find where each instruction ends before it can start the next.
  • Hybrid: ARM Thumb and RISC-V's compressed extension add 16-bit forms of the most common instructions to save memory.

The three MIPS formats

MIPS, the ISA used by many textbooks, has 32 registers and only three formats, all 32 bits long (Figure 2.3.1). Fields are read from bit 31 on the left to bit 0 on the right.

  • R-type (register): op(6) rs(5) rt(5) rd(5) shamt(5) funct(6). Used for add, sub, and, or, slt and shifts. op is 0 and the 6-bit funct picks the operation: add = 32, sub = 34, and = 36, or = 37, slt = 42. rs and rt are sources, rd the destination, shamt the shift amount.
  • I-type (immediate): op(6) rs(5) rt(5) immediate(16). Used for lw (op 35), sw (43), addi (8), beq (4) and bne (5). The immediate is a signed 16-bit value, −32,768 to 32,767. For loads and addi, rt is the destination.
  • J-type (jump): op(6) address(26). Used for j (op 2) and jal (op 3). The field holds the target address divided by 4.

Register numbers used below: $zero = 0, $v0–$v1 = 2–3, $a0–$a3 = 4–7, $t0–$t7 = 8–15, $s0–$s7 = 16–23, $sp = 29, $ra = 31.

Encoding and decoding, step by step

  1. Look up the instruction's format and its op (and funct) values.
  2. Write every field's value in decimal: register numbers, shift amount, immediate.
  3. Convert each value to binary of exactly its field width; a negative immediate becomes 16-bit two's complement.
  4. Join the fields from op to the last field and regroup the 32 bits into eight hex digits.

Decoding runs backwards: expand the hex to 32 bits, read op from bits 31–26, then split the rest by the format that op implies. Note that the assembly order of add rd, rs, rt is not the field order (rs, rt, rd).

Expanding opcodes

When some instructions need fewer address fields, their unused address bits can carry more opcode bits. This expanding opcode gives short opcodes to instructions with many operands and longer opcodes to those with few. One opcode pattern of the short kind is kept back as an "escape" meaning "the opcode continues in the next field". The count is a budget: every pattern used at one level removes 2(bits left) encodings from the total.

Worked example

Question 1. Encode sub $s0, $t1, $t2 and addi $t1, $t1, -4 in hex, and decode 0x8E2A0008.

  1. sub is R-type: op 0, rs = $t1 = 9, rt = $t2 = 10, rd = $s0 = 16, shamt 0, funct 34. Bits: 000000 01001 01010 10000 00000 100010 → 0x012A8022.
  2. addi is I-type: op 8, rs = 9, rt = 9, immediate −4 = 1111 1111 1111 1100. Bits: 001000 01001 01001 1111111111111100 → 0x2129FFFC.
  3. 0x8E2A0008 = 1000 1110 0010 1010 0000 0000 0000 1000. op = 100011 = 35 (lw), so I-type: rs = 10001 = 17 ($s1), rt = 01010 = 10 ($t2), immediate = 8. The instruction is lw $t2, 8($s1).

Question 2. (a) A machine has 16-bit instructions and 4-bit register fields. It needs 14 three-address and 30 two-address instructions and 31 one-address instructions. Using expanding opcodes, how many zero-address instructions can it still have? (b) A 32-bit instruction has an opcode, two register fields and an immediate; there are 100 opcodes and 64 registers. Find the immediate's width and signed range.

  1. (a) Total patterns 216 = 65,536. Three-address: 14 opcodes × 212 = 57,344. Two-address: 30 × 28 = 7,680. One-address: 31 × 24 = 496.
  2. Left over: 65,536 − 57,344 − 7,680 − 496 = 16, so 16 zero-address instructions.
  3. (b) Opcode ⌈log2 100⌉ = 7 bits; registers 2 × 6 = 12 bits; immediate = 32 − 7 − 12 = 13 bits, range −4,096 to 4,095.

Exam traps

  • In add $t0, $s1, $s2 the destination $t0 is written first but encoded in the third register field (rd).
  • In lw and addi the destination is rt, not rd: I-type has no rd field.
  • Negative immediates must be 16-bit two's complement: −4 is FFFC, not 8004.
  • Field width is ⌈log2 n⌉: 100 opcodes need 7 bits; 6 bits give only 64.
  • Favourite question: "Encode this MIPS instruction in hex" or "decode this hex word". Write the field boundaries before converting.

2.4 Addressing modes

An addressing mode is the rule an instruction uses to find its operand: inside the instruction, in a register, or in memory at an address worked out from the instruction's fields and registers. That worked-out address is the effective address (EA). Different modes exist because programs reach different kinds of data: constants, variables, pointers, array elements and stack items. With the right mode, each takes one instruction instead of three.

You need: byte addresses and the 8086 physical-address rule from 2.1, and the MIPS formats from 2.3.

MIPS addressing for 32-bit immediates and addresses

MIPS has five modes: register (add), immediate (addi), base or displacement (lw $t0, 32($s3): EA = 32 + [$s3]), PC-relative (branches) and pseudodirect (jumps). Its 16-bit immediates and 26-bit jump fields cannot hold a full 32-bit value, so three tricks fill the gap:

  • 32-bit constants: lui loads 16 bits into the upper half and clears the lower half; ori fills the lower half. For 4,000,000 = 0x003D0900: lui $s0, 61 (0x003D) gives 0x003D0000, then ori $s0, $s0, 2304 (0x0900) gives 0x003D0900.
  • Branches: target = (PC + 4) + offset × 4. The offset counts instructions, so a branch reaches about ±215 instructions (±128 KB). A beq at 0x00400010 with offset 5 goes to 0x00400014 + 20 = 0x00400028.
  • Jumps: target = upper 4 bits of PC + 4, joined to the 26-bit field × 4. Jumps stay inside the current 256 MB region; jr through a register reaches anywhere.

8086 modes and physical addresses

The 8086 computes a 16-bit offset (its EA) and then the physical address PA = segment × 10h + EA, using DS by default and SS when BP is the base register. Modes: immediate MOV AX, 1234h; register MOV AX, BX; direct MOV AX, [5000h]; register indirect MOV AX, [BX]; based [BX+disp] or [BP+disp]; indexed [SI+disp] or [DI+disp]; based indexed [BX+SI]; and based indexed with displacement [BX+SI+disp].

2.5 RISC versus CISC instruction sets

There are two broad ways to design an instruction set. A CISC (complex instruction set computer) offers many powerful instructions, many addressing modes and variable lengths, so a program needs few instructions. A RISC (reduced instruction set computer) offers simple, fixed-length instructions that work on registers, with only Load and Store touching memory, so each instruction finishes quickly and the hardware pipelines well. This chapter compares them point by point, measures them with the CPU time equation, and explains why the line is blurred inside today's chips.

You need: the CPU time equation from Unit 1, Performance metrics, formats from 2.3 and modes from 2.4.

Why each style appeared

In the 1970s memory was small and expensive, and compilers were weak. Designers moved work into the hardware: instructions that copied whole strings, evaluated polynomials or did arithmetic directly on memory operands, often implemented in microcode (Unit 4). Short programs saved memory. The DEC VAX, Motorola 68000 and Intel x86 come from this line.

By the early 1980s, measurements showed that compilers used a small core of simple instructions most of the time, while the rare complex ones made the control unit large and slowed everything. Research projects named RISC and MIPS built processors with only simple instructions, many registers and a pipeline, and let the compiler do the clever work. MIPS, SPARC, PowerPC, ARM and RISC-V follow this idea.

The central difference shows on one task, C = A × B with all three in memory: CISC does it in one memory-to-memory instruction (MUL C, A, B), while RISC uses two loads, a register multiply and a store.

Measuring the difference

Neither style wins by definition. The CPU time equation decides:

CPU time = IC × CPI × T = IC × CPI ÷ f

Here IC is the number of instructions executed, CPI the average clock cycles per instruction, T the clock period and f the clock rate. CISC lowers IC; RISC lowers CPI and, with simpler control, allows a shorter T. Only the product counts. MIPS ratings (million instructions per second) mislead across ISAs, because a RISC instruction does less work than a CISC one.

The picture today

Since the Pentium Pro in the mid-1990s, x86 processors decode each CISC instruction into simple RISC-like micro-operations and run those on a pipelined, out-of-order core. The x86 ISA stays for compatibility; the decoder pays the price. Meanwhile RISC ISAs grew: ARM added 16-bit Thumb code and vector instructions. So "RISC versus CISC" now describes the ISA software sees and the cost of decoding it more than the core underneath. ARM dominates phones for its energy efficiency, and Apple's M-series laptops run on ARM.

Worked example

Question. Program P runs 50 million instructions on a CISC machine with average CPI 3.0 at 2 GHz. Its RISC version runs 1.6 times as many instructions with average CPI 1.2 at 2.5 GHz. (a) Find the CPU time on each. (b) Which is faster, and by how much? (c) Find each machine's MIPS rating and comment. (d) The program has 12,000 instructions in its CISC binary, averaging 3.5 bytes, and 1.6 times as many 4-byte instructions in its RISC binary. Compare code sizes.

  1. (a) CISC: 50 × 106 × 3.0 ÷ (2 × 109) = 150 × 106 ÷ 2 × 109 = 0.075 s = 75 ms.
  2. RISC: IC = 1.6 × 50 × 106 = 80 × 106. Time = 80 × 106 × 1.2 ÷ (2.5 × 109) = 96 × 106 ÷ 2.5 × 109 = 0.0384 s = 38.4 ms.
  3. (b) Speedup = 75 ÷ 38.4 = 1.95. The RISC machine is about 1.95 times faster.
  4. (c) MIPS = f ÷ (CPI × 106). CISC: 2 × 109 ÷ (3.0 × 106) = 666.7. RISC: 2.5 × 109 ÷ (1.2 × 106) = 2,083.3. The MIPS ratio is 3.1 but the real speedup is only 1.95, because each RISC instruction does less work.
  5. (d) CISC: 12,000 × 3.5 = 42,000 bytes. RISC: 19,200 × 4 = 76,800 bytes, about 1.83 times larger.

  • Do not compare MIPS ratings across different ISAs; compare CPU time.
  • Microprogrammed control for CISC and hardwired for RISC are typical choices, not definitions.
  • A modern x86 core runs micro-operations internally, but its ISA is still CISC: programs see variable-length instructions with memory operands.

2.6 Assembly language programming: MIPS, ARM and x86

Assembly language is the readable form of machine code: one line per instruction, written with mnemonics, register names and labels instead of bits. An assembler turns it into machine code (chapter 2.8). You write assembly to understand what the processor really does, to read compiler output while debugging, and to program small embedded devices. This chapter shows the parts of an assembly program, the registers of the three ISAs your universities use, one program written in all three, and how procedures are called.

You need: the formats in 2.3 and the addressing modes in 2.4.

Parts of an assembly program

  • Label: a name for an address, ending in a colon (loop:). The assembler replaces it with the number.
  • Mnemonic and operands: add $t2, $t2, $t3.
  • Comment: after # in MIPS, @ in GNU ARM, ; in x86.
  • Directive: a command to the assembler, not an instruction. .data and .text start the data and code sections; .word (MIPS, ARM) or DW (8086) reserves and fills memory.
  • Pseudo-instruction: a convenient form the assembler expands into real instructions. In MIPS, li (load immediate), la (load address) and move are pseudo-instructions; move $a0, $t2 becomes add $a0, $zero, $t2.

x86 has two spellings. Intel syntax (MASM, NASM) writes the destination first: mov ebx, eax. AT&T syntax (the GNU assembler) writes the source first and marks registers with %: movl %eax, %ebx. Both mean "copy EAX into EBX".

The three register sets

MIPS has 32 general registers, with $zero wired to 0 and software conventions for the rest. ARM's 32-bit A32 state has 16 registers r0–r15, three of them special, and keeps N, Z, C, V flags in the CPSR. The 8086 has eight 16-bit general registers, four segment registers, IP and FLAGS; its 32- and 64-bit successors widen them to EAX and RAX.

Procedure calls

A call must save the return address and jump; a return must jump back to it.

  • MIPS: jal square sets $ra ← PC + 4 and jumps; jr $ra returns. Arguments go in $a0–$a3, the result in $v0. A procedure that calls another must first save $ra on the stack (addi $sp, $sp, -4 then sw $ra, 0($sp)).
  • ARM: BL square puts the return address in LR (r14); BX LR returns. PUSH {r4, LR} and POP {r4, PC} save and restore in one instruction each.
  • x86: CALL pushes the return address on the stack; RET pops it into IP. Parameters travel in registers or on the stack.
square: mul  $v0, $a0, $a0    # MIPS: $v0 = x * x
        jr   $ra               # return to caller
main:   li   $a0, 9            # argument x = 9
        jal  square            # $ra = return address; afterwards $v0 = 81

2.7 Logical operations and instructions for making decisions

Programs often work on single bits: packing small fields into a word, testing a status bit from a device, clearing a permission flag. Logical and shift instructions do this. Programs also choose between paths: every if, while, for and switch in C becomes compare and branch instructions. This chapter covers both, in MIPS with the ARM and x86 equivalents, and shows the patterns a compiler uses so you can write them by hand.

You need: branches and condition flags from 2.2, PC-relative branch targets from 2.4, and the registers in 2.6.

Compare and branch

MIPS compares inside the branch and has no flags:

  • beq rs, rt, L and bne rs, rt, L: branch if equal or not equal.
  • slt rd, rs, rt: set rd = 1 if rs < rt (signed), else 0. slti compares with a constant; sltu and sltiu compare as unsigned.
  • j L: jump unconditionally. jr jumps to the address in a register.

MIPS has no hardware "branch if less than". The assembler offers blt, bgt, ble, bge as pseudo-instructions and expands each into slt plus beq or bne, using $at. The designers kept only equality tests in the branch so the branch decision stays fast.

ARM sets the flags with CMP r0, r1 (a subtraction that keeps only the flags) and branches with BEQ, BNE, BLT, BGT, BLE, BGE for signed values and BLO, BHI for unsigned. In A32 most instructions can also carry a condition, such as MOVGT r2, r0, which runs only if the last compare found "greater than". x86 uses CMP and then JE, JNE, JL, JG (signed) or JB, JA (unsigned); TEST ANDs two operands to set flags for a bit test.

Compiling if, while and switch

  1. if–else: test the opposite of the C condition and branch to Else; after the then-part, jump to Exit.
  2. while: at the top, branch out to Exit if the condition is false; at the bottom, jump back to the top.
  3. switch: when the cases are 0, 1, 2, …, store the case addresses in a jump table, load the entry for the case value, and jr to it. One indexed load replaces a chain of compares.

Worked example

Question 1. $s0 = 0x0000B6C9 and $s1 = 0xFFFFFF80. Find the result of each: (a) sll $t0, $s0, 4; (b) srl $t1, $s0, 8; (c) bits 7–4 of $s0 using srl and andi; (d) andi $t3, $s0, 0xFF00 and ori $t4, $s0, 0x000F; (e) nor $t5, $s0, $zero; (f) sra and srl of $s1 by 2.

  1. (a) Shifting left by 4 bits moves every hex digit one place: 0x000B6C90 (46,793 × 16 = 748,688).
  2. (b) Shifting right by 8 drops the low two hex digits: 0x000000B6.
  3. (c) srl $t2, $s0, 4 gives 0x00000B6C; andi $t2, $t2, 0xF keeps the low 4 bits: 0xC = 12.
  4. (d) AND keeps bits 15–8: 0x0000B600. OR sets bits 3–0: 0x0000B6CF.
  5. (e) NOR with zero is NOT: 0xFFFF4936.
  6. (f) $s1 = −128. sra copies the sign: 0xFFFFFFE0 = −32. srl brings in zeros: 0x3FFFFFE0 = 1,073,741,792.

  • blt is a MIPS pseudo-instruction; written as real code it is slt plus bne.
  • Logical right shift divides only unsigned numbers correctly; for signed numbers use arithmetic shift.

2.8 Translating and starting a program: assemble, link, load

Four tools turn a C file into a running program: the compiler writes assembly, the assembler makes an object file, the linker joins object files and libraries into an executable, and the loader puts it in memory and starts it. How the compiler works inside belongs to the Compiler Design subject.

Assembler and object file

The assembler expands pseudo-instructions (chapter 2.6) and encodes each instruction (chapter 2.3). A label may be used before it is defined, as in a forward branch, so assemblers make two passes: pass 1 records every label's address in a symbol table; pass 2 produces the bits. A Unix object file has six parts:

  1. Header: sizes and positions of the other parts.
  2. Text segment: the machine code.
  3. Static data segment: global variables and constants.
  4. Relocation information: instructions and data words holding addresses that must change once the file's final position is known.
  5. Symbol table: labels defined here, and external labels still unresolved.
  6. Debugging information.

Linker and loader

The linker places the text and data of every module in memory, resolves each external label through the symbol tables, and patches every address listed in the relocation information. Its output is an executable. With dynamic linking, library code (.so or .dll files) is linked at load time or on its first call, so programs share one copy and pick up library fixes without relinking.

The loader, part of the operating system, reads the header, creates an address space, copies text and data into memory, puts the program's arguments on the stack, sets the registers and stack pointer, and jumps to a start-up routine that calls main and finally exit.

Worked example

Question. Object file A has 0x100 bytes of text and 0x20 bytes of data (variable X at data offset 0) and contains jal B. Object file B has 0x200 bytes of text and 0x30 bytes of data (variable Y at offset 0). Using the MIPS layout (text from 0x00400000, data from 0x10000000, $gp = 0x10008000), link A then B. Give the final addresses and the patched fields for jal B, lw $a0, X($gp) and sw $a1, Y($gp).

  1. Text: A at 0x00400000–0x004000FF, B at 0x00400100–0x004002FF. Data: X at 0x10000000, Y at 0x10000020.
  2. jal B: address field = 0x00400100 ÷ 4 = 0x100040.
  3. lw: offset = 0x10000000 − 0x10008000 = −32,768, stored as 0x8000.
  4. sw: offset = 0x10000020 − 0x10008000 = −32,736, stored as 0x8020.

Exam traps

  • An object file cannot run: its external addresses are still unresolved.
  • Relocation information lists places to patch; the symbol table lists label names. Do not mix them.
  • The linker produces the executable; the loader only copies it into memory and starts it.

Beyond the syllabus

Not for the exam. Linux uses the ELF object format, Windows uses PE. Position-independent executables let the loader place a program at a random address (ASLR), a defence against attacks. Link-time optimisation lets the linker optimise across files, and Java's JIT compiler translates bytecode while the program runs. Takeaways

  1. Memory is an array of bytes; k address bits give 2k locations, and a 32-bit word occupies four consecutive byte addresses.
  2. Big-endian stores the MSB at the lowest address, little-endian the LSB; aligned words sit at multiples of their size.
  3. The PC holds the next instruction's address; it advances by 4 unless a branch writes a target into it.
  4. Fewer addresses per instruction (3, 2, 1, 0) give shorter instructions but longer programs.
  5. An instruction format is a set of fields; ⌈log2 n⌉ bits name n things, and MIPS fits everything into R, I and J formats of 32 bits.
  6. Addressing modes compute the effective address; relative mode adds to the updated PC, and indirect mode costs an extra memory read.
  7. RISC lowers CPI and clock period, CISC lowers instruction count; compare them with CPU time, never with MIPS ratings.
  8. Every if, while and switch becomes compare-and-branch code: slt/beq/bne in MIPS, CMP plus a conditional branch in ARM and x86.
  9. Assembler, linker and loader turn assembly into a running process; relocation information and symbol tables let separately assembled files be joined.

Analyze and evaluate

AnalyzeFor a[i] = a[i] + 10; (int array, a in $s0, i in $s1), write MIPS code, name the addressing mode of each instruction, encode the load, and compare with one x86 instruction.12 marks

sll $t0, $s1, 2 (register, shamt); add $t0, $t0, $s0 (register); lw $t1, 0($t0) (base) = 0x8D090000; addi $t1, $t1, 10 (immediate); sw $t1, 0($t0) (base). x86: add dword ptr [esi+ebx*4], 10, one instruction with a scaled-index memory operand. Discuss IC versus CPI (spans 2.3 to 2.6).

AnalyzeA 32-bit ISA has 64 registers. Design R-type (three registers) and I-type (two registers and an immediate) formats with a 6-bit opcode, and compare with MIPS.10 marks

Register fields 6 bits. R: 6 + 18 = 24, leaving 8 bits for funct or shift. I: 6 + 12 = 18, so a 14-bit immediate (−8,192 to 8,191). Compared with MIPS: more registers, fewer spills, but smaller constants and a branch range of ±213 instructions instead of ±215.

Evaluate"Modern processors are neither RISC nor CISC." Evaluate this statement with examples.8 marks

For: x86 cores run RISC-like micro-ops out of order; ARM has added Thumb, vectors and complex addressing. Against: the ISA still matters to software (variable versus fixed length, memory operands, decoder cost and energy). Conclude that the label now describes the visible ISA, with RISC-V as a clean modern example.

AnalyzeProgram P: 40 million instructions, CPI 2.5, 3 GHz on machine X; 52 million instructions, CPI 1.4, 2.6 GHz on machine Y. Which is faster, and do MIPS ratings agree?8 marks

X: 40 × 106 × 2.5 ÷ 3 × 109 = 33.3 ms. Y: 52 × 106 × 1.4 ÷ 2.6 × 109 = 28.0 ms. Y faster by 1.19. MIPS: X = 1,200, Y = 1,857; the ratio 1.55 overstates Y's advantage because Y executes more instructions.

Glossary

Address space
All the addresses a processor can generate: 2k for k-bit addresses.
Addressing mode
The rule an instruction uses to locate its operand.
Alignment
Placing an s-byte item at an address that is a multiple of s.
Assembler
Program that turns assembly language into an object file.
Assembler directive
A command to the assembler, such as .data or DW, that produces no instruction.
Big-endian
Byte order with the most significant byte at the lowest address.
Branch
An instruction that may load a new address into the PC.
CISC
Complex instruction set computer: many instructions and modes, variable length.
Condition code flags
Status bits N, Z, V, C set by results and tested by branches.
Effective address
The address of the operand after the addressing mode is applied.
Expanding opcode
An opcode that grows into unused address fields when fewer operands are needed.
Immediate
A constant operand stored inside the instruction.
Instruction format
The division of an instruction word into opcode and operand fields.
ISA
Instruction set architecture: the registers, memory model and instructions visible to software.
Jump table
An array of code addresses used to implement a switch with one indexed jump.
Linker
Program that combines object files and libraries into an executable.
Little-endian
Byte order with the least significant byte at the lowest address.
Load/store architecture
An ISA in which only Load and Store access memory.
Loader
Operating-system code that copies an executable into memory and starts it.
Opcode
The field that names the operation.
Program counter
Register holding the address of the next instruction.
Pseudo-instruction
Assembler shorthand expanded into one or more real instructions.
Relocation information
List of places in an object file whose addresses must be patched when it is placed in memory.
RISC
Reduced instruction set computer: simple, fixed-length, register-to-register instructions.
Symbol table
The assembler's list of labels and their addresses or external status.
Word
The unit of data the processor normally handles in one operation, such as 32 bits.
