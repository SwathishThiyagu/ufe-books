4.1 Fundamental concepts of the basic processing unit

The basic processing unit is the part of the processor that fetches each instruction from memory, works out what it asks for, and carries it out. Patterson and Hennessy call the same hardware the datapath and its control. Whatever the instruction, the work reduces to a few register-level moves, and this chapter names the registers, the four basic operations and the handshake with memory that the rest of the unit builds on.

You need: Unit 1, Functional units of a computer and Basic operational concepts and instruction execution cycle; Unit 2, Instruction formats and encoding of machine instructions.

The registers inside the processor

A register is a group of flip-flops holding one word (32 bits here). Programmer-visible registers are the ones an instruction can name: the general-purpose registers R0 to R(n−1), with n usually 16 or 32. Hidden registers are used only by the hardware; no instruction can name them.

The ALU (Unit 3) does the arithmetic. The control unit reads the opcode in IR and produces control signals: one-bit wires that open each register's connection to the internal bus, choose the ALU operation and tell memory to read or write. Only MAR and MDR face the memory bus.

The four basic operations

Every instruction is carried out as a sequence of four kinds of operation:

  1. Transfer a word from one register to another, or to the ALU.
  2. Perform an arithmetic or logic operation and put the result in a register.
  3. Fetch the contents of a memory location into a register (a memory read).
  4. Store the contents of a register into a memory location (a memory write).

Register transfer notation (RTN) writes these compactly. [R1] means "the contents of R1", and R2 ← [R1] means "copy the contents of R1 into R2". The fetch phase of every instruction is then two lines:

IR ← [[PC]]      the word whose address is in PC goes into IR
PC ← [PC] + 4    PC now points at the next instruction

The 4 comes from byte addressing: a 32-bit instruction fills four byte addresses (Unit 2). The execute phase then depends on the opcode.

Talking to memory: MAR, MDR and MFC

Memory is slower than the processor and its speed is not fixed: a cache hit takes a cycle or two, a miss many more. So the processor puts the address in MAR, raises Read and waits until memory raises MFC (memory function completed), meaning the word is now in MDR. Reading the word whose address is in R1 into R2:

  1. MAR ← [R1]; Read.
  2. WMFC (wait for MFC); memory loads MDR from the data lines.
  3. R2 ← [MDR].

A write is the mirror image: MAR ← address, MDR ← data, Write, WMFC. MDR has two sides: it can be loaded from, and can drive, either the internal bus or the memory data lines. MFC is the signal memory sends; WMFC is the processor's step that waits for it. During the wait the processor may do work that does not need the word, which is why the fetch increments PC then.

One step, one clock cycle

Each control step takes one clock cycle: a source register drives the bus, the value reaches the ALU or the destination, and the destination captures it at the clock edge. So the clock period T must cover the trip:

T ≥ t_out + t_bus + t_ALU + t_setup

Here t_out is the delay of a register's output gates, t_bus the travel time on the bus, t_ALU the ALU delay (zero for a plain transfer) and t_setup the time the destination needs before the edge. With 0.3 + 0.5 + 1.4 + 0.2 = 2.4 ns, a 2.5 ns clock (400 MHz) works. A WMFC step lasts as many cycles as memory needs.

Worked example

Question. A processor has a 2.5 ns clock, byte-addressable memory and 32-bit instructions. PC holds 2000, and the word at address 2000 is the instruction Add R1, R2. The address reaches memory at the end of the first step, and memory needs 7 ns from then to deliver the word. (a) Write the fetch as control steps and give the register contents after each. (b) How many clock cycles and how many nanoseconds does the fetch take? (c) If every instruction needs the fetch plus 2 execute cycles, how many instructions does the processor finish per second? (d) Repeat (b) and (c) if the instruction is in a cache that answers in 2 ns.

(a) Control steps.

(b) Fetch time. Wait cycles = ⌈t_mem / T⌉ = ⌈7 / 2.5⌉ = ⌈2.8⌉ = 3 (steps 2, 3 and 4). Fetch = 1 + 3 + 1 = 5 cycles = 5 × 2.5 ns = 12.5 ns. Check: MFC at 9.5 ns falls inside cycle 4 (7.5 to 10 ns), so step 5 can use MDR.

(c) Rate. Cycles per instruction = 5 + 2 = 7. Time per instruction = 7 × 2.5 ns = 17.5 ns. Instructions per second = 1 / (17.5 × 10⁻⁹ s) = 57.1 million.

(d) With the cache. Wait cycles = ⌈2 / 2.5⌉ = 1, so fetch = 3 cycles = 7.5 ns; each instruction = 5 cycles = 12.5 ns, giving 80 million instructions per second, 1.4 times faster at the same clock.

Exam traps

  • MAR holds an address, MDR holds data. Writing "MAR holds the word read from memory" loses the marks.
  • After the fetch, PC already points to the next instruction (2004, not 2000). Branch offsets are added to this updated PC.
  • MFC comes from memory; WMFC is the processor's step that waits for it. "The WMFC signal from memory" is wrong.
  • Add 4, not 1, for 32-bit instructions in byte-addressable memory. Use +1 only when the question says memory is word-addressable.
  • IR, MAR, MDR, Y, Z and TEMP are not programmer-visible; no instruction can name them.

Apply t_out = 0.25 ns, t_bus = 0.4 ns, t_ALU = 1.2 ns, t_setup = 0.15 ns. Find the shortest clock period and the highest clock rate. 2 marks

Analyze A designer wants to remove MDR and let memory drive the internal bus directly. What goes wrong? 4 marks

The bus would be tied up for the whole memory wait, so nothing could overlap with it. The word arrives at a time set by memory, so it needs a register to wait in until a step uses it. Write data must stay steady for the whole write while the bus does other transfers. MDR buffers between the two sides.

Beyond the syllabus

Real processors have no single MAR and MDR; load-store units and buffers beside the level-1 cache keep many memory requests in flight at once. The handshake survives in on-chip bus protocols such as ARM's AMBA AXI, where VALID and READY do the job of Read and MFC. ACM/IEEE CS2023 places this material in its Architecture and Organization knowledge area. Search "SAP-1 breadboard computer" or the small RISC-V core PicoRV32 to see a whole processing unit. Not for the exam.

4.2 Register transfers and executing a complete instruction

An instruction such as Add (R3), R1 is executed as a fixed list of control steps, each a few register transfers done in one clock cycle. Writing that list, the control sequence, is the exam task here.

You need: Chapter 4.1 (registers, MFC); Unit 2, Addressing modes (register indirect).

Gating a register onto the bus

Each register meets the single internal bus through two switches. Riin = 1 loads the bus value into Ri at the clock edge. Riout = 1 lets tri-state gates drive Ri's contents onto the bus; at 0 the gates float. So R4 ← [R1] is one step: R1out and R4in together. Only one out signal may be active per step.

The ALU needs two inputs but the bus carries one value per step, so the first operand waits in Y. A multiplexer (MUX) feeds ALU input A with Y (SelectY) or the constant 4 (Select4, for PC + 4). The result goes into Z, because the bus still carries the second operand (step 6 in Figure 4.2.1).

The control sequence for Add (R3), R1

This instruction adds the memory word whose address is in R3 to R1: R1 ← [R1] + [[R3]].

Steps 1 to 3 are the fetch, the same for every instruction. Step 2 keeps the new PC in Y for branches; here step 5 overwrites it. End starts the next fetch.

Branch instructions

An unconditional branch: steps 1 to 3 fetch; step 4 is Offset-field-of-IRout, Add, Zin (Z ← [Y] + offset); step 5 is Zout, PCin, End. Branch<0 adds "if N = 0 then End" to step 4: if the last result was not negative, the instruction stops there and PC keeps its new value.

Exam traps

  • Two out signals in one step on a single bus is a bus conflict; examiners mark the sequence wrong.
  • WMFC never goes in the same step as Read: the address reaches memory only at the end of the step that loads MAR.
  • Select4 in step 1 (add 4 to PC) but SelectY in step 6 (add the operand). Mixing them up adds 4 to R1.
  • [R3] = 1500 is an address; [[R3]] = 17 is the operand. Do not forget End in the last step.

4.3 Single-bus and multiple-bus processor organization

The internal bus is the road inside the processor. With one bus, only one value moves per clock step; with two or three buses, a single step can read two operands and write back a result. More buses mean fewer steps for register operations, paid for with more wiring and a bigger register file.

You need: Chapter 4.2 (control sequences on a single bus).

Single-bus organization

Every register, the internal side of MDR, Y and Z hang on one bus. Because the bus carries one value per step, the addition R6 ← [R4] + [R5] needs three steps after the fetch: R4 into Y; R5 on the bus while the ALU adds into Z; Z into R6. The single bus is the cheapest design: least wiring, a register file with one port, and the fewest control signals. Its weakness is that every instruction queues for the same bus.

Two-bus and three-bus organizations

The three-bus organization gives the register file two read ports and one write port. Buses A and B carry two source operands to the ALU at once, and bus C carries the result back, so Y and Z are no longer needed. Three more features make it work:

  • The ALU can pass one input straight through. R=B copies bus B to bus C; that is how PC reaches MAR and MDR reaches IR.
  • PC has its own incrementer (signal IncPC), so the fetch does not need the ALU.
  • A MUX on ALU input A chooses bus A or a constant; SelectA picks bus A.

A two-bus design sits in between: in a common form one bus carries source operands and the other carries results, which removes the Z step but still needs a holding register for one operand. The price of more buses is real. Each bus adds a wire per bit across the datapath, each register-file port adds gates to every register cell, and longer wires can stretch the clock period.

Comparing the step counts

On three buses, Add R4, R5, R6 (meaning R6 ← [R4] + [R5]) is:

  1. PCout, R=B, MARin, Read, IncPC
  2. WMFC
  3. MDRoutB, R=B, IRin
  4. R4outA, R5outB, SelectA, Add, R6in, End

On the single bus the same instruction is: 1. PCout, MARin, Read, Select4, Add, Zin; 2. Zout, PCin, Yin, WMFC; 3. MDRout, IRin; 4. R4out, Yin; 5. R5out, SelectY, Add, Zin; 6. Zout, R6in, End.

InstructionSingle busThree buses
Add R4, R5, R66 steps4 steps
Load R2 from address in R36 steps6 steps
Branch with offset5 steps4 steps

The Load gains nothing. After the fetch it sends an address, waits for memory and copies MDR to R2, and no internal bus shortens the memory wait.

Worked example

Question. A program runs 200 million instructions: 50% register adds, 30% loads and 20% branches, with the step counts in the table above. The single-bus processor runs at a 2.0 ns clock; the three-bus one needs 2.2 ns because of its longer wires. Every WMFC finishes in one cycle (cache hits). Find each run time and the speedup.

  1. Average steps, single bus = 0.5 × 6 + 0.3 × 6 + 0.2 × 5 = 3.0 + 1.8 + 1.0 = 5.8.
  2. Average steps, three buses = 0.5 × 4 + 0.3 × 6 + 0.2 × 4 = 2.0 + 1.8 + 0.8 = 4.6.
  3. Time per instruction: 5.8 × 2.0 ns = 11.6 ns; 4.6 × 2.2 ns = 10.12 ns.
  4. Run time: 200 × 10⁶ × 11.6 ns = 2.32 s; 200 × 10⁶ × 10.12 ns = 2.024 s.
  5. Speedup = 2.32 / 2.024 = 1.15.

Answer. The three-bus processor is about 15% faster, not 6 / 4 = 1.5 times, because loads do not improve and its clock is slower.

Exam traps

  • "More buses make every instruction faster" is false: memory-bound instructions such as Load gain nothing.
  • Three buses need a register file with two read ports and one write port; a one-port file cannot feed A and B together.
  • R=A and R=B are ALU pass-through functions, not registers.
  • These internal buses are not the system bus (address, data and control lines) of Unit 1, Bus structures.
  • On one bus, PC + 4 uses the ALU (Select4); on three buses the incrementer does it (IncPC).

Beyond the syllabus

Modern superscalar cores issue several instructions per cycle, so their register files need many read and write ports, and area and power grow quickly with the port count. Designers add bypass (forwarding) networks so results skip the register file altogether, which you meet in Unit 5. Search "register file ports" and "bypass network" to go further. Not for the exam.

4.4 Building a datapath for a simple processor

A datapath is the set of hardware units that hold and transform data inside the processor: PC, memories, register file, ALU, adders and the multiplexers that join them. Patterson and Hennessy build one for a small MIPS subset (add, sub, and, or, slt, lw, sw, beq) by asking what each instruction class needs and merging the pieces. RISC-V and ARM versions differ only in field positions.

You need: Unit 2, Instruction formats and encoding of machine instructions (MIPS R- and I-formats); Unit 3, ALU design for arithmetic and logic operations; Chapter 4.1.

The building blocks

Combinational elements produce outputs from their current inputs only: the ALU, adders, multiplexers and the sign-extend unit, which copies bit 15 of a 16-bit immediate into bits 16 to 31 so that −8 stays −8 in 32 bits. State elements hold values between clock edges: PC, the register file and the memories. The register file holds 32 registers of 32 bits with two read ports (5-bit register number in, contents out) and one write port (5-bit number, 32-bit data, and RegWrite to allow the write at the clock edge). Since state changes only at the edge, a register can be read and written in one cycle; the read sees the old value.

The two MIPS formats used here are R-format: op (6 bits) | rs (5) | rt (5) | rd (5) | shamt (5) | funct (6), and I-format: op (6) | rs (5) | rt (5) | immediate (16).

Building it one instruction class at a time

  1. Fetch, for every instruction. PC addresses the instruction memory; an adder computes PC + 4.
  2. R-format, add $rd, $rs, $rt: read rs and rt, let the ALU operate, write the result into rd.
  3. Load and store, lw $rt, offset($rs): the ALU adds [rs] and the sign-extended offset to form the address. lw reads data memory into rt; sw writes [rt] into data memory.
  4. Branch, beq $rs, $rt, offset: the ALU subtracts and raises Zero if the two are equal. A separate adder forms the target (PC + 4) + offset × 4; the × 4 is a shift left by 2 because the offset counts words.
  5. Merge with multiplexers wherever two sources compete for one input: ALUSrc (register or immediate into ALU input B), MemtoReg (ALU result or memory data back to the registers), RegDst (rt or rd as the write register) and PCSrc (PC + 4 or the branch target).

Single-cycle and multi-cycle

In the single-cycle design every instruction finishes in one clock cycle, so the cycle must fit the slowest instruction, lw, which uses all five units in series; faster instructions waste the rest. The multi-cycle design cuts each instruction into steps, one per shorter cycle: instruction fetch (IF), decode and register read (ID), execute (EX), memory access (MEM) and write back (WB). lw takes 5 cycles, sw and R-format 4, beq 3. Hidden registers (IR, MDR, A, B, ALUOut) carry values between steps, and one memory and one ALU are shared across cycles. Its control is a finite-state machine (Chapter 4.5) or a microprogram (Chapter 4.6); Unit 5 overlaps the same steps in a pipeline.

Worked example 1: tracing lw

Question. PC = 400 and memory[400] holds lw $t0, 8($s1). Register $s1 (number 17) holds 1000, $t0 is register 8, and data memory[1008] = 55. Encode the instruction, give every control signal, and trace the values through Figure 4.4.1.

  1. Encoding: op = 35 = 100011, rs = 17 = 10001, rt = 8 = 01000, immediate = 8. Bits: 100011 10001 01000 0000000000001000 = 0x8E280008.
  2. Control (lw row): RegDst = 0, ALUSrc = 1, MemtoReg = 1, RegWrite = 1, MemRead = 1, MemWrite = 0, Branch = 0, ALUOp = 00.
  3. Fetch: the instruction leaves instruction memory; the adder gives PC + 4 = 404.
  4. Register read: read register 17 gives 1000. Sign-extend 8 gives 0x00000008.
  5. ALU: ALUSrc = 1 selects the immediate, so 1000 + 8 = 1008.
  6. Data memory: MemRead = 1 reads memory[1008] = 55.
  7. Write back: MemtoReg = 1 picks 55; RegDst = 0 picks rt = 8; RegWrite = 1 stores $t0 = 55.
  8. Next PC: Branch = 0, so PCSrc = 0 and PC = 404.

If the instruction at 404 were beq $t0, $t1, 3 with $t1 = 55, the ALU would give 55 − 55 = 0, Zero = 1, and PC = (404 + 4) + 3 × 4 = 420.

Worked example 2: single-cycle against multi-cycle

Question. Delays: instruction memory 200 ps, register read 100 ps, ALU 150 ps, data memory 200 ps, register write 50 ps; ignore multiplexers, adders and sign-extend. The mix is 25% lw, 10% sw, 45% R-format and 20% beq. Compare the average time per instruction for single-cycle and multi-cycle (clock = slowest step).

  1. Path lengths: R-format 200 + 100 + 150 + 50 = 500 ps; lw 200 + 100 + 150 + 200 + 50 = 700 ps; sw 200 + 100 + 150 + 200 = 650 ps; beq 200 + 100 + 150 = 450 ps.
  2. Single-cycle: clock = slowest path = 700 ps, so every instruction takes 700 ps. (The mix only needs 0.25 × 700 + 0.10 × 650 + 0.45 × 500 + 0.20 × 450 = 555 ps on average; 145 ps per instruction is wasted.)
  3. Multi-cycle: clock = slowest step = 200 ps. CPI = 0.25 × 5 + 0.10 × 4 + 0.45 × 4 + 0.20 × 3 = 1.25 + 0.40 + 1.80 + 0.60 = 4.05.
  4. Time per instruction = 4.05 × 200 ps = 810 ps.

Answer. Here multi-cycle is slower (810 against 700 ps) because its steps are unbalanced: a 50 ps register write still gets a full 200 ps cycle. Multi-cycle pays off when some instructions are much longer than others (multiply, divide) and when sharing units saves hardware. The big gain comes from pipelining (Unit 5).

Exam traps

  • The branch target is (PC + 4) + offset × 4, not PC + offset.
  • lw writes rt, not rd, so RegDst = 0 for lw and 1 for R-format.
  • sw has RegWrite = 0; writing 0 instead of X for RegDst and MemtoReg is accepted, but never RegWrite = 1.
  • The single-cycle clock is set by the slowest instruction (lw), not by the average.
  • Offsets for lw, sw and beq are sign-extended, not zero-extended: 0xFFF8 means −8.

Real cores add branch predictors and caches, but the multiplexer-and-control-signal pattern stays. Search "RISC-V single-cycle datapath". Not for the exam.

4.5 Hardwired control unit

A hardwired control unit makes the control signals with fixed logic: a counter that tracks the step, two decoders, and a network of AND and OR gates. It is the fastest way to produce control signals and the hardest to change, because any change means new circuits. Most syllabi list it, nearly always paired with microprogrammed control (Chapter 4.6) in a compare question.

You need: Chapter 4.2 (control sequences) and Chapter 4.4 (control signals of a datapath).

What each control signal depends on

Look down any control sequence and you see that a signal is on or off depending on three things: which step of the instruction the processor is in, which instruction is in IR, and the condition codes and external inputs. The hardwired unit produces exactly these three inputs and combines them:

  • Control step counter: counts clock cycles inside the instruction (1, 2, 3, …); it advances on each clock while Run = 1.
  • Step decoder: turns the count into timing signals T1, T2, …, Tn. Exactly one is 1 in each step (one-hot).
  • Instruction decoder: turns the opcode in IR into one line per instruction, INS1 … INSm (ADD, BR, BRN, …). Exactly one is 1.
  • Encoder: the AND–OR network that combines the T lines, the INS lines, the condition codes (N, Z, V, C) and external inputs (MFC, interrupt request) into every control signal.

End resets the counter to 1 so the next fetch begins. While a WMFC step waits and MFC is still 0, Run is held at 0 and the counter stops, so the processor stays in that step.

Deriving the logic for one signal

Read the control sequences of Chapter 4.2 column by column. Zin is on in step 1 of every instruction (the fetch), in step 6 of Add (R3), R1, and in step 4 of both branches. Each "step k of instruction X" becomes an AND term, and the terms are ORed:

Zin = T1 + T6·ADD + T4·BR + T4·BRN + …
End = T7·ADD + T5·BR + (T5·N + T4·N̄)·BRN + …

The "…" stands for the terms of the rest of the instruction set. In End, BRN (branch if negative) finishes at step 4 when N = 0 (not taken) and at step 5 when N = 1 (taken). A complete hardwired unit is one such equation per control signal, each built straight into gates.

The same idea for the single-cycle datapath

The single-cycle datapath of Chapter 4.4 has no steps, so its control unit is a pure decoder of the 6-bit opcode op5 … op0 (′ means NOT). The opcodes are R-format 000000, lw 100011, sw 101011 and beq 000100.

Rformat  = op5′·op4′·op3′·op2′·op1′·op0′
lw       = op5·op4′·op3′·op2′·op1·op0
sw       = op5·op4′·op3·op2′·op1·op0
beq      = op5′·op4′·op3′·op2·op1′·op0′
RegDst   = Rformat        ALUSrc   = lw + sw
MemtoReg = lw             RegWrite = Rformat + lw
MemRead  = lw             MemWrite = sw
Branch   = beq            ALUOp1 = Rformat, ALUOp0 = beq

Four AND gates feed two OR gates: a small programmable logic array (PLA). For the multi-cycle datapath the counter becomes a state register and the unit becomes a finite-state machine: next-state logic picks the next step from the current state and the opcode.

A worked case: a controller for Booth's multiplier

Some syllabi ask for hardwired and microprogrammed control of a Booth multiplier. Its datapath (Unit 3, Booth's algorithm and fast multiplication) holds the multiplicand M, accumulator A, multiplier Q, the extra bit Q₋₁ and a counter. The hardwired controller is a four-state machine:

StateActionNext state
S0 StartA ← 0, Q₋₁ ← 0, Count ← nS1
S1 TestQ₀Q₋₁ = 10: A ← A − M; 01: A ← A + M; 00 or 11: nothingS2
S2 Shiftarithmetic shift right A, Q, Q₋₁; Count ← Count − 1S1 if Count ≠ 0, else S3
S3 Doneraise Donestay in S3

Two flip-flops hold the state, and the outputs are gates: Sub = S1·Q₀·Q₋₁′, Add = S1·Q₀′·Q₋₁, Shift = S2. For n = 4 bits the machine runs S0 and then S1–S2 four times: 1 + 4 × 2 = 9 clock cycles before Done.

Worked example

Question. The processor of Chapter 4.2 has Add (R3), R1 (7 steps), an unconditional branch BR (5 steps) and branch-if-negative BRN. (a) Write Zin and End for these three instructions. (b) BRN is at address 3000 with offset −40, so Y = 3004 after the fetch. Trace steps 4 and 5 for N = 0 and for N = 1. (c) The full instruction set has 40 instructions and the longest needs 12 steps. How wide are the step counter and the two decoders?

(a) Zin = T1 + T6·ADD + T4·(BR + BRN). End = T7·ADD + T5·BR + (T5·N + T4·N̄)·BRN.

(b) At T4 with BRN = 1: Zin = T4·BRN = 1, so Z = 3004 + (−40) = 2964.

N = 0T4·N̄·BRN = 1·1·1 = 1not reached3004 (not taken)4
N = 1T4·N̄·BRN = 0Zout, PCin, End2964 (taken)5

(c) Step counter: ⌈log₂ 12⌉ = 4 bits, feeding a 4-to-16 step decoder of which T1–T12 are used. Opcode: ⌈log₂ 40⌉ = 6 bits, feeding a 6-to-64 instruction decoder of which 40 outputs are used.

Exam traps

  • Forgetting T1 in the signals the fetch uses (PCout, MARin, Read, Zin) is the commonest slip.
  • Hardwired does not mean "no clock": the step counter is clocked, and Run can freeze it.
  • BRN needs the N̄ term in End: a branch not taken finishes one step earlier.
  • T lines and INS lines are one-hot: T3 and T4 are never 1 together.
  • "Hardwired is always better because it is faster" is wrong for large CISC instruction sets, where the logic becomes huge and hard to check.

Check yourself

Control step counter, step decoder, instruction decoder, encoder.

Understand What do the signals End and Run do? 2 marks

End resets the step counter to 1 to start the next fetch. Run = 0 stops the counter, holding the processor in a WMFC step until MFC arrives.

Analyze A new instruction is added to the set. What must change in a hardwired unit, and why is that a drawback? 4 marks

The instruction decoder needs a new output, and every control signal the instruction uses needs new AND terms in the encoder, so the circuit must be redesigned, re-verified and, on a chip, re-fabricated. A microprogrammed unit would only need a new microroutine in the control store.

Beyond the syllabus

RISC cores such as those of RISC-V and ARM decode instructions in hardwired logic. Designers no longer draw the gates: they write the state machine in Verilog or VHDL and a synthesis tool produces the logic. x86 processors decode common instructions with hardwired decoders and fall back to a microcode ROM for complex ones. Search "FSM controller in Verilog" to see a control unit written as code. Not for the exam.

4.6 Microprogrammed control unit and microinstructions

A microprogrammed control unit stores the control signals as bits in a small fast memory, the control store, instead of building them from gates. Each word is a microinstruction that says which signals are on in one step, and the words that carry out one machine instruction form its microroutine. Maurice Wilkes proposed the idea in 1951; EDSAC 2 (1958) was the first machine built this way, and IBM used it across the System/360 family. It is slower than hardwired control but far easier to design, check and change.

You need: Chapter 4.2 (control sequences) and Chapter 4.5 (what the control unit must produce).

Control words and microroutines

A control word (CW) has one bit per control signal; 1 means the signal is on in that step. The seven steps of Add (R3), R1 (Chapter 4.2) become the seven columns below (Select: 1 = Select4, 0 = SelectY). They are Add's microroutine; all microroutines together form the microprogram, usually in ROM.

Sequencing: where the next microinstruction comes from

The microprogram counter (μPC) holds the address of the next microinstruction. Normally it just increments. It is loaded with a new address in three cases:

  1. New instruction: when IR is loaded, the starting address generator turns the opcode into the address of that instruction's microroutine.
  2. Branch: a microinstruction tests a condition code (N, Z, …) or an external input and jumps.
  3. End: μPC returns to the start of the fetch microroutine.

The branch address comes from a separate branch microinstruction or from a next-address field in every word, which removes the incrementer but widens the word. With bit-ORing, the generator ORs condition bits into the low bits of the next address, giving a two-way or four-way branch with no separate test. For the Booth multiplier, ORing Q₀Q₋₁ into base address 4 sends control to 4, 5, 6 or 7:

1branch: OR Q₀Q₋₁ into base 44, 5, 6 or 7
4 (00), 7 (11)no arithmetic8
5 (01)A ← A + M8
6 (10)A ← A − M8
8shift right A, Q, Q₋₁; Count ← Count − 11 if Count ≠ 0, else End

Microinstruction formats

Horizontal: one bit per signal, as in the table above; many signals can be on together, but words are wide. Vertical: signals packed into a few short coded fields, each decoded by hardware; words are narrow, but fewer signals can be on together, routines get longer and decoding adds delay. Most designs use field encoding in between: signals never on in the same step share a field. On a single bus only one register may drive the bus per step, so all the "out" signals form one field. A field for k signals needs ⌈log₂(k + 1)⌉ bits; the +1 is the code for "none".

Worked example 1: field encoding

Question. A single-bus processor has 42 control signals in the groups below. Design a field-encoded microinstruction, compare its width with the horizontal format, and compare control-store sizes for 1024 microinstructions.

FieldSignals in the fieldCodesBits
F1 bus source9: PCout, MDRout, Zout, Offsetout, TEMPout, R0out–R3out9 + 1 = 104
F2 destination A7: PCin, IRin, Zin, R0in–R3in83
F3 destination B4: MARin, MDRin, TEMPin, Yin53
F4 ALU function16 functions (Add, Sub, …)164
F5 memory2: Read, Write32
F6 MUX2: SelectY, Select421
F7, F8WMFC; End2 each1 + 1
  1. Horizontal width = number of signals = 9 + 7 + 4 + 16 + 2 + 2 + 1 + 1 = 42 bits.
  2. Encoded width = 4 + 3 + 3 + 4 + 2 + 1 + 1 + 1 = 19 bits.
  3. Control store: 1024 × 42 = 43,008 bits against 1024 × 19 = 19,456 bits, a saving of 1 − 19/42 = 55%.
  4. Check the fields with step 2 of the fetch (Zout, PCin, Yin, WMFC): Zout is in F1, PCin in F2, Yin in F3, WMFC in F7. No two are in one field, so the step can be coded. That is why the destinations are split into two fields.

The price is one decoder per field and a little decoding delay in every step.

Worked example 2: control-store size

Question. A horizontal microinstruction has 48 control bits. The microprogram can branch on any one of 16 status conditions, every word has a next-address field, and the control store holds 2048 words. Find the word width and the control-store size.

  1. Next-address field: log₂ 2048 = 11 bits.
  2. Condition-select field: log₂ 16 = 4 bits.
  3. Width = 48 + 4 + 11 = 63 bits.
  4. Size = 2048 × 63 = 129,024 bits = 16,128 bytes = 15.75 KB (1 KB = 1024 bytes).

If an "always branch" option is needed besides the 16 conditions, there are 17 choices, the select field needs 5 bits and the word becomes 64 bits.

Exam traps

  • Control store is not main memory, a microinstruction is not a machine instruction, and μPC is not PC.
  • Horizontal is wide and fast; vertical is narrow and needs decoders. Students often swap them.
  • In field encoding, signals that are on in the same step must sit in different fields (PCin and Yin in fetch step 2).
  • A field for k signals needs ⌈log₂(k + 1)⌉ bits: forgetting the "none" code gives 3 bits for 8 signals instead of 4.
  • The microprogram is firmware fixed in ROM by the maker, not software the user writes.

Check yourself

Remember Define control word, microroutine and control store. 3 marks

Control word: the bits that say which control signals are on in one step. Microroutine: the sequence of microinstructions that executes one machine instruction. Control store: the memory, usually ROM, that holds all microroutines.

Understand Why is microprogrammed control slower than hardwired control? 2 marks

Every step needs a read of the control store (and decoding, if fields are encoded) before the signals are ready; hardwired gates produce them directly.

Understand How does bit-ORing give a branch without a separate test microinstruction? 3 marks

The address generator ORs a condition bit into the low bit(s) of the next address, so the same microinstruction leads to different addresses depending on the condition.

Apply A field must encode 12 mutually exclusive signals. How many bits does it need? 1 mark

⌈log₂(12 + 1)⌉ = ⌈3.7⌉ = 4 bits.

Apply A control store has 4096 words; each has 32 control bits, a 3-bit condition field and a next-address field. Find the word width and the store size in bits. 3 marks

Next address = log₂ 4096 = 12 bits. Width = 32 + 3 + 12 = 47 bits. Size = 4096 × 47 = 192,512 bits.

Apply From the control-word table, write Zout as a hardwired equation for Add (R3), R1. 2 marks

Zout is 1 in steps 2 and 7: Zout = T2 + T7·ADD (T2 because every fetch uses it).

Analyze Why did CISC processors of the 1960s–80s choose microprogramming, while RISC designs chose hardwired control? 4 marks

CISC sets had hundreds of complex multi-step instructions; writing microroutines was far easier than designing and checking that much logic, and one instruction set could run on cheap and fast models. RISC instructions are few and simple, so the control logic is small and hardwired speed matters more.

Beyond the syllabus

Microcode is alive in today's x86 processors and can be patched: in 2018 Intel shipped microcode updates adding controls against the Spectre variant 2 attack. The Motorola 68000 used a two-level control store, short microcode words pointing to wide nanocode words, to save ROM. Search "microcode update" and "nanoprogramming". Not for the exam.

Takeaways

  1. Every instruction is built from four basic operations: register transfer, ALU operation, memory read and memory write.
  2. MAR and MDR are the processor's only doors to memory, and the MFC handshake lets it work with memory of any speed.
  3. A control sequence lists, step by step, which gates are open; on a single bus, one value moves per step.
  4. More internal buses cut the steps of register operations, not the waits of memory operations.
  5. A datapath is built by giving each instruction class what it needs and merging the parts with multiplexers driven by control signals.
  6. A single-cycle clock is set by the slowest instruction; multi-cycle uses shorter cycles and shares units; pipelining overlaps the steps.
  7. Hardwired control turns "which step, which instruction, which flags" into signals with gates: fast but hard to change.
  8. Microprogrammed control reads each step's signals from a control store: easier to design and change, but slower; field encoding trades word width for decoding.
