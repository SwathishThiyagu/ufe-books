1.1 History and classes of computers

A computer is a machine that takes in data, keeps it in memory together with a program, processes it under that program's control and gives out results. Its history is mostly the history of its switching device, which went from relays to vacuum tubes, transistors, integrated circuits and single-chip microprocessors, each step smaller, faster, cheaper and less power-hungry. The classes of computers, from the chip inside a washing machine to a supercomputer, exist because the same basic design is tuned for different targets of cost, speed and energy.

Before electronics

Mechanical calculators such as Pascal's adding machine (1642) could only add and subtract. In the 1830s Charles Babbage designed the Analytical Engine, which already had a "store" for numbers and a "mill" to work on them: the ideas we now call memory and ALU. It was never completed. The Harvard Mark I (1944) worked with electromechanical relays and read its instructions from punched paper tape. Relays click open and shut in milliseconds, so these machines did only a few operations per second.

The generations of electronic computers

Textbooks group electronic computers into generations by switching device. The years overlap and books draw the lines a little differently, so in an exam give the device, an example machine and what changed, rather than arguing about exact years.

ENIAC used 17,468 vacuum tubes, drew about 150 kW and did about 5,000 additions per second. Tubes burn out, so keeping it running was a daily job. It was not a stored-program machine when it was built: changing the program meant rewiring it. The idea of keeping the program in memory came in 1945 (Chapter 1.3), and EDSAC (1949) was among the first machines to use it in regular work.

The Intel 4004 of 1971 put a 4-bit processor of about 2,300 transistors on one chip. The 8086 of 1978 was the first x86 processor; its descendants still run its instruction set today. In 1965 Gordon Moore observed that the number of transistors on a chip was doubling at a steady rate, later stated as about every two years. This is Moore's law; Chapter 1.7 shows where it led.

India's own story runs alongside. TIFRAC, built in Mumbai, was commissioned in 1960. C-DAC in Pune released the PARAM 8000 parallel supercomputer in 1991.

Classes of computers

Today's textbooks (Patterson and Hennessy) sort computers by what they are used for, because that decides what the designer optimises.

  • Personal mobile devices (PMDs): phones and tablets. Run on a battery, so energy per task matters as much as speed. Cost is tight.
  • Personal computers (desktops and laptops): one user, good performance at low cost.
  • Servers: shared by many users over a network, for example the computers that answer IRCTC booking requests. They are judged by throughput (requests served per second) and reliability.
  • Clusters and warehouse-scale computers: tens of thousands of servers in one building acting as one service, such as cloud platforms and search engines.
  • Supercomputers: the fastest machines, built for one huge scientific calculation such as a monsoon forecast. Measured in floating-point operations per second (Chapter 1.6).
  • Embedded computers: hidden inside other products, such as a washing machine, a car's engine controller or a FASTag reader. They do one job, at the lowest cost and power. They are by far the most numerous class.

Older books add mainframes (enterprise systems) and workstations, and also classify by size (micro, mini, mainframe, super) or by data type (analog, digital, hybrid). If the question says "types of computers", give the purpose-based list and mention one older scheme.

Worked example

Question (8 marks). (a) ENIAC did about 5,000 additions per second and drew about 150 kW. A phone processor core runs at 2.4 GHz, completes 2 additions per clock cycle and draws 2 W. For each machine find the additions per second and the additions per joule, and compare. (b) Name the class of each computer, with one reason: the IRCTC booking back end; a washing-machine controller; a student's laptop; the computer running a monsoon forecast model; a phone paying through UPI.

Solution.

  1. ENIAC rate = 5,000 additions/s. Power 150 kW = 150,000 J/s. Additions per joule = 5,000 ÷ 150,000 = 0.0333, so one addition cost about 30 J.
  2. Phone rate = 2.4 × 10⁹ cycles/s × 2 = 4.8 × 10⁹ additions/s. Additions per joule = 4.8 × 10⁹ ÷ 2 = 2.4 × 10⁹, so one addition costs about 0.42 nJ.
  3. Speed ratio = 4.8 × 10⁹ ÷ 5,000 = 9.6 × 10⁵: the phone core is about a million times faster.
  4. Energy ratio = 2.4 × 10⁹ ÷ 0.0333 = 7.2 × 10¹⁰: about 72 billion times more additions per joule. The gain in energy efficiency is even larger than the gain in speed.
  5. (b) IRCTC back end: server or cluster (many users at once, throughput and reliability during the Tatkal rush). Washing machine: embedded (one fixed job, very low cost). Laptop: personal computer (one user, general purpose). Monsoon model: supercomputer (one huge floating-point calculation). Phone: personal mobile device (battery, so energy per task matters).

Exam traps

  • ENIAC was not a stored-program computer when built; it was programmed by rewiring. Do not call it "the first stored-program computer".
  • Generation years differ between books. Marks come from the device, an example and what changed.
  • Server versus supercomputer: a server handles many independent requests (throughput); a supercomputer attacks one big problem (FLOPS).
  • Moore's law is about the number of transistors on a chip, not clock speed or performance.
  • The most numerous class is embedded computers, not PCs or phones.

1.2 Functional units of a computer

Every computer, from a phone to a server, is built from five functional units: input, memory, the arithmetic and logic unit (ALU), the control unit, and output. The ALU and the control unit, with a set of fast registers, together form the processor or CPU. The units are joined by an interconnection, usually buses (Chapter 1.5). This block diagram is the single most asked figure of the unit.

You need: the idea of a program as a list of instructions (Chapter 1.1).

Architecture and organization

Two words name two views of the same machine. Computer architecture is what the programmer sees: the instruction set, the data types, the number of registers, the addressing modes and how input and output are done. Computer organization is how that architecture is built: the control signals, the memory technology, the width of the internal paths, and whether multiplication has its own hardware or is done by repeated addition. Whether a machine has a multiply instruction is architecture; how the multiply is carried out is organization. One architecture can have many organizations: every x86 chip since 1978 runs the same basic instructions on very different hardware.

The five units

  • Input unit. Accepts information from the outside world and turns it into binary codes. A keyboard sends a code for each key (in ASCII the letter A is 65, binary 01000001); a microphone, camera, touch screen or network interface does the same for sound, images, touches and messages. The codes go to memory or to the processor.
  • Memory unit. Stores programs and data. Primary (main) memory is semiconductor RAM, organised as a large number of cells, each holding a fixed number of bits called a word; the word length is typically 16 to 64 bits. Each word has an address, and any word can be reached in the same time whatever its address, which is why it is called random-access memory. Main memory is volatile: it loses its contents when power goes. A small, faster cache sits between the processor and main memory. Secondary memory (SSD, hard disk) is slower and cheaper, keeps data without power, and is not addressed directly by the processor: a program must be loaded into main memory before it runs.
  • Arithmetic and logic unit (ALU). Performs arithmetic (add, subtract, multiply, divide) and logic operations (AND, OR, NOT, compare). Operands are first brought into registers, small storage cells inside the processor that can be read and written in one clock cycle, much faster than main memory.
  • Control unit. Fetches each instruction from memory, works out what it means, and sends timing and control signals to every other unit so that each acts at the right moment. It is the coordinator; in real hardware its circuits are spread across the chip rather than sitting in one box.
  • Output unit. Sends results to the outside world: a display, printer or speaker, or a network message. Some devices, like a touch screen, are both input and output.

How the units work together

Take the billing counter of a supermarket in Chennai. The barcode scanner (input) sends the code of each item to memory. The control unit fetches the billing program's instructions one by one. For each item, the price is brought into a register, the ALU adds it to the running total, and the total goes back to a register or to memory. At the end, the total is sent to the display and the printer (output). Every step is started by a signal from the control unit, and every piece of data passes through memory or the processor's registers.

The units above are the hardware. Software is the programs: system software (the operating system, compilers, device drivers) manages the hardware and runs application software (the billing program, a browser, a game). The operating system loads a program from secondary memory into main memory and starts the processor on it.

Worked example

Question (6 marks). A program reads two marks, 78 and 64, adds them and prints the total. (a) Say which functional unit does what. (b) In this machine an ALU operation or a register access takes 1 ns and a main-memory access takes 50 ns. Version A keeps both marks and the total in memory: it reads each mark from memory, adds, and writes the total back. Version B already has both marks in registers and leaves the total in a register. Find the time for the addition step in each version and the ratio.

Solution.

  1. (a) Input: the keyboard sends the codes for 78 and 64; they are stored in memory, say at addresses 1000 and 1004. Control: fetches the program's instructions from memory and signals each step. Memory to registers: R1 = 78, R2 = 64. ALU: 78 + 64 = 142. Memory: the total is stored at address 1008. Output: the display shows 142.
  2. (b) Version A: 2 memory reads + 1 memory write = 3 accesses × 50 ns = 150 ns, plus 1 ns for the ALU. Total = 151 ns.
  3. Version B: read R1 and R2 (1 ns + 1 ns), add (1 ns), write the result register (1 ns). Total = 4 ns.
  4. Ratio = 151 ÷ 4 ≈ 38. Keeping operands in registers makes the step about 38 times faster. This is why processors have registers, why compilers keep busy variables in registers, and why caches exist (Unit 6).

Exam traps

  • The CPU is the ALU plus the control unit plus registers. Main memory is not part of the CPU, even though caches sit on the same chip.
  • Architecture versus organization: "has a multiply instruction" is architecture; "uses a separate multiplier circuit" is organization.
  • Secondary memory is not directly addressed by the processor; programs run from main memory.
  • A block diagram without arrows, or without the difference between data paths and control signals, loses marks. Label every box and both kinds of line.

1.3 Von Neumann and Harvard architectures

There are two classic ways to connect the processor to memory. In the von Neumann architecture one memory holds both the instructions and the data, and the processor reaches it over one path. In the Harvard architecture instructions and data live in separate memories with separate paths, so the processor can fetch the next instruction while it reads or writes data. Laptops and phones look like von Neumann machines to the programmer but use a split (Harvard-style) design inside; small microcontrollers and signal processors are often pure Harvard.

You need: the functional units (Chapter 1.2).

The stored-program concept

ENIAC had to be rewired for every new problem (Chapter 1.1). In 1945 John von Neumann wrote the "First Draft of a Report on the EDVAC", which described a machine that keeps its program in the same memory as its data, as numbers. A new program could then be loaded like any data, in minutes instead of days. The idea grew out of the ENIAC team's work with J. Presper Eckert and John Mauchly, but it carries von Neumann's name. The IAS computer built to this plan (completed 1952) had a memory of 1,000 words of 40 bits each.

The features examiners ask for:

  1. One read-write memory holds both instructions and data.
  2. Memory is addressed by location; the hardware cannot tell an instruction from data by looking at a word.
  3. Instructions run one after another in address order, unless an instruction (a jump or branch) changes the order.
  4. The machine has a processor (ALU, control unit, registers), memory, and input/output, connected by a common path.

The von Neumann bottleneck

Because instructions and data share one memory and one bus, every instruction fetch and every data access must take turns. The processor can compute far faster than memory can deliver words, so it often waits. John Backus named this the "von Neumann bottleneck" in his 1977 Turing Award lecture. Designers reduce it with caches (a fast copy of recently used words, Unit 6), wider buses that bring more bits per access, and prefetching the next instructions before they are needed.

The Harvard architecture

The name comes from the Harvard Mark I (1944), which read instructions from punched paper tape and kept data in separate counters. A Harvard machine has an instruction memory and a data memory, each with its own address and data lines. In the same clock cycle the processor can fetch one instruction and read or write one data word. The two memories can even have different word widths: the AVR microcontroller in an Arduino Uno (ATmega328P) has 32 KB of flash for 16-bit instructions and 2 KB of RAM for 8-bit data.

The cost is more wiring and less flexibility. Each memory has a fixed size, so spare data memory cannot be used for code. A program cannot simply write new instructions into data memory and run them; reading a constant table stored in program memory needs a special instruction. For a microcontroller that runs one fixed program from flash, these limits do not matter, and the speed and simplicity win. Digital signal processors (DSPs), which read a data sample and a coefficient on almost every instruction, gain the most.

Modified Harvard: what modern processors do

Desktop, server and phone processors keep one main memory, so the operating system can load any program into it like data (von Neumann at the programmer's level). Inside the chip, the first-level cache is split into an instruction cache and a data cache with separate paths to the core. Most accesses hit these caches, so the core gets Harvard-style parallel access most of the time. This is called a modified Harvard architecture. It also lets a pipelined processor fetch one instruction while another accesses data without a clash (Unit 5, structural hazards).

Worked example

Question (6 marks). A program executes 2 × 10⁶ instructions. Every instruction needs one instruction fetch, and 30% of them (loads and stores) also need one data access. Each memory access occupies its bus for one cycle of 5 ns, and the processor waits for memory. (a) Find the memory time on a von Neumann machine with one shared bus. (b) Find it on a Harvard machine where instruction and data accesses overlap fully. (c) Find the speedup. (d) Repeat (c) for a signal-processing loop in which every instruction needs one data access.

Solution.

  1. (a) Accesses = 2 × 10⁶ fetches + 0.3 × 2 × 10⁶ data = 2.6 × 10⁶. Time = 2.6 × 10⁶ × 5 ns = 13 ms.
  2. (b) The instruction bus is busy for 2 × 10⁶ cycles; the data bus for 0.6 × 10⁶ cycles at the same time. Total = the longer one = 2 × 10⁶ × 5 ns = 10 ms.
  3. (c) Speedup = 13 ÷ 10 = 1.3. Per instruction: 1.3 bus cycles against 1.0.
  4. (d) With a data access on every instruction: von Neumann needs 2 cycles per instruction, Harvard 1. Speedup = 2 ÷ 1 = 2. This is why DSPs use the Harvard design.

Exam traps

  • Both designs are stored-program machines. Harvard also stores its program; only the place differs.
  • The bottleneck is the shared path between processor and memory, not the size of memory.
  • A PC with split L1 caches is "modified Harvard", not pure Harvard: main memory is still unified.
  • Harvard does not mean "twice the memory"; the two memories can be of any sizes, and data memory is often much smaller.

Analyze Why do modern CPUs choose modified Harvard rather than pure Harvard or pure von Neumann? 4 marks

One main memory keeps the flexibility to load any program as data. Split L1 caches give two accesses per cycle for the common case, removing most of the bottleneck and the pipeline's fetch/data clash, at the cost of only a small extra cache path.

Beyond the syllabus

The gap between processor speed and memory speed is called the "memory wall", a term from a 1995 paper by Wulf and McKee. Research on processing-in-memory and compute-in-memory chips tries to remove the bottleneck by doing simple operations inside the memory itself, and AI accelerators keep weights in large on-chip buffers for the same reason. Search for "processing in memory" and "memory wall" to follow this. Not for the exam.

1.4 Basic operational concepts and instruction execution cycle

A program is a list of instructions stored in memory. The processor runs it by repeating one loop, the instruction cycle: fetch the instruction whose address is in the program counter, decode it, get its operands, execute it, store the result, check for interrupts, and start again with the next instruction. A handful of registers (PC, IR, MAR, MDR and the general-purpose registers) make this loop work.

You need: the functional units (Chapter 1.2) and the stored-program idea (Chapter 1.3).

The registers that run a program

  • Program counter (PC): holds the address of the next instruction to be fetched.
  • Instruction register (IR): holds the instruction now being executed, so the control unit can decode it.
  • Memory address register (MAR): holds the address of the memory word to be read or written. Its outputs drive the address lines to memory.
  • Memory data register (MDR): holds the word just read from memory or about to be written. Stallings calls it the memory buffer register (MBR).
  • General-purpose registers R0 to R(n−1): hold operands and results while the program works on them.

The processor talks to memory only through MAR and MDR, plus two control signals: Read and Write. We write register transfers in a short notation: MAR ← [PC] means "copy the contents of PC into MAR", and M[5000] means "the memory word at address 5000". Unit 4 breaks each step into the exact control signals.

The instruction cycle, step by step

Take a 32-bit machine with byte-addressable memory, so each instruction occupies 4 bytes and the next instruction is 4 addresses further on. Instructions are written as in Hamacher's book: Load R2, LOC copies the memory word at LOC into R2; Add R4, R2, R3 puts R2 + R3 into R4; Store R4, LOC copies R4 into memory at LOC.

  1. Fetch. MAR ← [PC]; the control unit sends Read; memory places the word on the data lines; MDR ← M[MAR]; IR ← [MDR]. Then PC ← [PC] + 4, so the PC already points to the next instruction.
  2. Decode. The control unit reads the opcode in IR and works out the operation and where the operands are.
  3. Operand fetch. If an operand is in memory, MAR ← address, Read, MDR ← M[MAR]. If the instruction gives the operand's address indirectly (the instruction points to a word that holds the address), one more memory read is needed first; Stallings and Mano call this the indirect cycle.
  4. Execute. The ALU performs the operation on the operands in registers.
  5. Store result. Into a register, or into memory: MAR ← address, MDR ← result, Write.
  6. Interrupt check. If a device has raised an interrupt request, the processor saves the PC and jumps to the interrupt-service routine (Unit 6). Otherwise it goes back to step 1.

Stallings draws the same loop as an instruction cycle state diagram with finer states: instruction address calculation, instruction fetch, instruction operation decoding, operand address calculation, operand fetch, data operation, operand store, and interrupt check. The operand states repeat when an instruction has several operands. Step 1 is the fetch phase; steps 2 to 5 are the execute phase.

Clock cycles, machine cycles and instruction cycles

Three times are easy to mix up. A clock cycle (also called a T-state) is one period of the processor clock: 0.5 ns at 2 GHz. A machine cycle (bus cycle) is one complete operation on the bus, such as a memory read, a memory write, an I/O read or an I/O write; it takes several clock cycles (four in the 8086). An instruction cycle is the whole time to fetch and execute one instruction; it contains one or more machine cycles. Load R2, LOC needs two machine cycles (instruction fetch, operand read); Add R4, R2, R3 needs only one (the fetch).

Worked example

Question (8 marks). Memory holds this program (decimal addresses, 4 bytes per instruction):

Initially PC = 2000, R3 = 17 and M[5000] = 25. (a) Trace PC, MAR, MDR, IR and the changed register or memory word through each fetch and execute phase. (b) Each memory access takes 4 clock cycles; decode, an ALU operation and a register write take 1 cycle each. Find the cycles per instruction and the total time at 1 GHz. (c) What fraction of the time is spent on memory?

  2. Add: fetch 4 + decode 1 + ALU 1 + write R4 1 = 7 cycles.
  3. Store: fetch 4 + decode 1 + memory write 4 = 9 cycles.
  4. Total = 10 + 7 + 9 = 26 cycles. At 1 GHz one cycle is 1 ns, so the time is 26 ns. Average = 26 ÷ 3 ≈ 8.7 cycles per instruction (this average is the CPI of Chapter 1.6).

Exam traps

  • The PC holds the address of the next instruction, not the current one; it is increased during the fetch.
  • MAR holds an address and sends it one way, to memory; MDR holds data and works both ways. Do not swap them.
  • Add 4 to the PC for 32-bit instructions in byte-addressable memory; add 1 only if memory is word-addressed or instructions are one byte.
  • Clock cycle, machine cycle and instruction cycle are three different lengths of time.
  • Interrupts are checked at the end of an instruction, not in the middle of one.

1.5 Bus structures: data, address and control buses

A bus is a shared set of wires that connects several units and carries one transfer at a time. The system bus that joins processor, memory and I/O has three groups of lines: the address bus says where, the data bus carries the value, and the control bus says what to do and when. The width of the address bus fixes how much memory can be reached; the width and speed of the data bus fix how fast data moves.

You need: MAR, MDR and the Read and Write signals (Chapter 1.4).

The three groups of lines

  • Data bus: carries the word being transferred. It is bidirectional: data goes to memory on a write and comes from memory on a read. Its width is the number of bits moved per transfer: 8 in the 8085, 16 in the 8086, 64 in a modern PC's memory channel.
  • Address bus: carries the address from MAR. It is unidirectional, driven by the processor (or a DMA controller) and read by memory and I/O. With n address lines there are 2n distinct addresses: 16 lines (8085) give 2¹⁶ = 65,536 = 64 KB; 20 lines (8086) give 2²⁰ = 1,048,576 = 1 MB; 32 lines give 4 GB, all for byte-addressable memory.
  • Control bus: a set of separate signals, each with its own direction. Typical lines: memory read, memory write, I/O read, I/O write, clock, reset, interrupt request and acknowledge, bus request and grant, and a ready or acknowledge line from slow devices.

Single bus and multiple buses

In a single-bus structure every unit sits on one bus. It is simple and cheap, and new devices are easy to add. But only one pair of units can talk at a time, and devices of very different speeds share it, so each I/O interface has a buffer register to hold data while the slow device catches up. With many devices, the bus becomes the bottleneck.

A multiple-bus structure (bus hierarchy) separates fast and slow traffic. A short, fast processor–memory bus carries cache and memory traffic; slower I/O buses hang off it through bridges. In a modern PC the memory controller is on the processor chip, PCI Express links go to the graphics card and SSD, and a chipset serves USB and SATA. Each bus runs at its own speed, and transfers on different buses can happen at the same time. Unit 4 uses "single-bus" and "multiple-bus" for the internal buses inside the processor; that is a different thing from the system bus here.

Bus timing: the memory read and write cycles

On a synchronous bus every transfer is timed by a common clock. One read or write is a bus cycle of several clock periods, called T-states. A typical memory read (Figure 1.5.2): in T1 the processor puts the address on the address bus; in T2 it asserts the read signal (RD goes low, because it is active low); the memory finds the word and places it on the data bus during T3; the processor latches the data at the end of T3; in T4 RD goes high and the bus is released. A write is similar, except that the processor drives the data bus and asserts WR, and memory stores the word by the end of the cycle.

If memory is too slow, it holds the READY line low and the processor inserts wait states (extra T-states) until the data is valid. The 8086 also multiplexes its bus: lines AD0–AD15 carry the address in T1 and data later, saving pins; the ALE (address latch enable) signal tells an external latch to hold the address for the rest of the cycle. An asynchronous bus uses a handshake (master-ready, slave-ready) instead of a common clock; Unit 6 covers it with I/O protocols.

The bus bandwidth is the peak data rate: bandwidth = (bytes per transfer) × (transfers per second) = (data-bus width ÷ 8) × (clock rate ÷ clock cycles per transfer).

Worked example

Question (8 marks). A processor has a 32-bit address bus and a 64-bit data bus to byte-addressable memory. The synchronous bus runs at 200 MHz, and a memory read takes 4 bus clock cycles. Find (a) the largest memory it can address, (b) the time for one read cycle, (c) the peak read bandwidth, (d) the time to read a 4 KB block, (e) the bandwidth and block time if memory needs 2 wait states per read. (f) For comparison, find the same peak bandwidth for an 8086 at 5 MHz (16-bit data bus, 4 T-states per bus cycle).

Solution.

  1. (a) 2³² bytes = 4,294,967,296 bytes = 4 GB (4 GiB).
  2. (b) Clock period = 1 ÷ (200 × 10⁶) = 5 ns. Read cycle = 4 × 5 ns = 20 ns.
  3. (c) Each read moves 64 ÷ 8 = 8 bytes. Bandwidth = 8 B ÷ 20 ns = 0.4 B/ns = 400 MB/s.
  4. (d) 4 KB = 4,096 bytes ÷ 8 = 512 reads. Time = 512 × 20 ns = 10,240 ns = 10.24 µs.
  5. (e) With 2 wait states a read takes 6 × 5 = 30 ns. Bandwidth = 8 ÷ 30 ns ≈ 266.7 MB/s; block time = 512 × 30 ns = 15.36 µs.
  6. (f) 8086: T-state = 1 ÷ 5 MHz = 200 ns; bus cycle = 4 × 200 = 800 ns; 2 bytes per cycle. Bandwidth = 2 ÷ 800 ns = 2.5 MB/s, 160 times less than (c).

Exam traps

  • Address-bus width sets the memory size (2n); data-bus width sets the bits per transfer. Students often swap them.
  • 2²⁰ is 1,048,576, not 1,000,000. Write "1 MB (2²⁰ bytes)".
  • The address bus is one-way and the data bus two-way; control lines are each one-way, but the group carries signals in both directions.
  • MB/s (bytes) and Mb/s (bits) differ by a factor of 8; read the unit asked for.
  • A "64-bit processor" has 64-bit registers and ALU; it need not have 64 address lines.

1.6 Performance metrics: CPI, MIPS and MFLOPS

"Faster" needs a number. The only fully reliable measure is the time a real program takes. The CPU performance equation splits that time into three factors, instruction count, cycles per instruction (CPI) and clock period, so you can see which design choice changed what. MIPS and MFLOPS are rates that are easy to quote and easy to misuse.

You need: clock cycles and cycles per instruction (Chapter 1.4).

Execution time, throughput and "faster"

  • Response time (execution time, latency): time from the start to the end of one task, such as one UPI payment.
  • Throughput: tasks completed per unit time, such as IRCTC bookings per minute. Adding servers raises throughput without making any single booking quicker.
  • Performance = 1 ÷ execution time. "X is n times faster than Y" means n = PerformanceX ÷ PerformanceY = TimeY ÷ TimeX.
  • CPU time counts only the time the processor spends on the program; elapsed (wall-clock) time also includes waiting for disk, network and other programs.

The CPU performance equation

CPU time = IC × CPI × T  =  (IC × CPI) ÷ f

Here IC is the instruction count, the number of instructions actually executed (a loop of 10 instructions run 1,000 times counts 10,000); CPI is the average clock cycles per instruction; T is the clock period in seconds; f = 1 ÷ T is the clock rate in hertz. Hamacher writes the same equation as T = (N × S) ÷ R, with N instructions, S basic steps (cycles) per instruction and R the clock rate.

Different instruction classes take different numbers of cycles. If class i has CPIi and makes up a fraction Fi of the executed instructions, then

CPI (average) = Σ CPI_i × F_i        total cycles = Σ CPI_i × IC_i

MIPS, MFLOPS and their limits

MIPS (million instructions per second) = IC ÷ (execution time × 10⁶) = f ÷ (CPI × 10⁶). It is easy to understand, but it misleads in three ways: it cannot compare machines with different instruction sets, because one instruction does different amounts of work on each; it changes from program to program on the same machine; and it can even rise while performance falls (Example 2 below).

MFLOPS (million floating-point operations per second) = number of floating-point operations ÷ (execution time × 10⁶). It counts work (operations on real numbers) rather than instructions, so it suits scientific computing, but it ignores integer work and treats a fast addition and a slow division alike. Supercomputers are ranked on the TOP500 list by a floating-point benchmark; the fastest passed 10¹⁸ FLOPS (an exaFLOPS) in 2022. Fair comparison of general-purpose machines uses benchmark suites such as SPEC CPU, which time real programs and summarise them with a geometric mean.

One more rule ties this together. Amdahl's law: if a fraction p of the time is sped up s times, overall speedup = 1 ÷ ((1 − p) + p ÷ s). Improving a part that is rarely used gains little. Unit 5 uses the same law for parallel processors.

Worked example 1: instruction mix

Question (8 marks). A program executes 5 × 10⁸ instructions on a 2 GHz processor: 50% ALU instructions (CPI 1), 30% loads and stores (CPI 3), 20% branches (CPI 2). It performs 1.2 × 10⁸ floating-point operations. Find (a) the average CPI, (b) the CPU time, (c) MIPS, (d) MFLOPS, (e) the speedup if a better cache cuts the load/store CPI to 2.

  1. (a) CPI = 0.5 × 1 + 0.3 × 3 + 0.2 × 2 = 0.5 + 0.9 + 0.4 = 1.8.
  2. (b) Cycles = 5 × 10⁸ × 1.8 = 9 × 10⁸. Time = 9 × 10⁸ ÷ (2 × 10⁹) = 0.45 s.
  3. (c) MIPS = 2,000 MHz ÷ 1.8 = 1,111. Check: 5 × 10⁸ ÷ (0.45 × 10⁶) = 1,111.
  4. (d) MFLOPS = 1.2 × 10⁸ ÷ (0.45 × 10⁶) = 266.7.
  5. (e) New CPI = 0.5 + 0.3 × 2 + 0.4 = 1.5. New time = 5 × 10⁸ × 1.5 ÷ (2 × 10⁹) = 0.375 s. Speedup = 0.45 ÷ 0.375 = 1.2.

Worked example 2: when MIPS lies

Question (6 marks). The same source program is compiled for two machines. P: 3 GHz, 1.0 × 10⁹ instructions, CPI 1.5. Q (a different instruction set): 2.5 GHz, 1.4 × 10⁹ instructions, CPI 1.0. Which is faster, and which has the higher MIPS?

  1. P: time = 1.0 × 10⁹ × 1.5 ÷ (3 × 10⁹) = 0.50 s; MIPS = 3,000 ÷ 1.5 = 2,000.
  2. Q: time = 1.4 × 10⁹ × 1.0 ÷ (2.5 × 10⁹) = 0.56 s; MIPS = 2,500 ÷ 1.0 = 2,500.
  3. P is faster by 0.56 ÷ 0.50 = 1.12 times, yet Q has the higher MIPS. Q's instructions do less work each, so it needs more of them.

Exam traps

  • Speedup = old time ÷ new time. Dividing the other way gives a number below 1.
  • A higher clock rate alone does not mean faster; IC and CPI matter equally.
  • IC counts executed instructions (loops counted every time round), not lines in the program.
  • Average CPI is weighted by the fraction of instructions in each class, not the fraction of time.
  • Units: 2 GHz = 2 × 10⁹ cycles/s; MIPS divides by 10⁶. Write units at every step.

1.7 Technology trends and the power wall

For decades, shrinking transistors gave faster clocks at roughly constant power. In the mid-2000s clock rates stopped rising because chips could not shed the heat: the power wall. It is why your laptop has many cores rather than one very fast one.

You need: clock rate and CPU time (Chapter 1.6).

Technology trends

Chips are made on silicon wafers cut into dies. Smaller transistors put more on each die: the Intel 4004 of 1971 had about 2,300, large chips of the 2020s have tens of billions (Moore's law, Chapter 1.1), and DRAM capacity grew the same way. Not every die works, so cost per die = cost per wafer ÷ (dies per wafer × yield); big dies have lower yield and cost more.

Dynamic power and the wall

Most of a chip's power goes into charging and discharging capacitance each time transistors switch:

P_dynamic = ½ × C × V² × f

C is the capacitance switched per cycle (farads), V the supply voltage (volts), f the switching frequency (hertz). Added to this is static power = leakage current × V, drawn even when nothing switches.

Robert Dennard's 1974 scaling rule said that as transistors shrink, voltage can shrink with them, keeping power per unit area constant. So supply voltage fell from 5 V to about 1 V while clock rates rose. Near 1 V this stopped: a lower voltage needs a lower threshold voltage, and leakage then rises steeply. With V stuck, every rise in f raises power, and a desktop chip can shed only about 100 W with ordinary cooling. Clock rates have stayed at a few gigahertz since the mid-2000s.

What designers did instead

They spent the extra transistors on more cores at a moderate clock (see the worked example). Phones and laptops use dynamic voltage and frequency scaling (DVFS), lowering V and f under light load, and power gating to switch off idle blocks. Accelerators (GPUs, neural processing units) do one kind of work with far less energy per operation.

Worked example

Question (8 marks). Design A: one core, 3.0 GHz, 1.2 V, switching 40 nF per cycle. Design B: 1.0 V, which allows only 2.4 GHz. Design C: two B cores. Find (a) A's dynamic power, (b) B's power and the saving, (c) C's power and throughput relative to A, (d) the energy of a 6 × 10⁹-cycle task on A and on B.

  1. (a) P = ½ × 40 × 10⁻⁹ F × (1.2 V)² × 3.0 × 10⁹ Hz = ½ × 40 × 1.44 × 3.0 = 86.4 W.
  2. (b) P = ½ × 40 × 10⁻⁹ × 1.0² × 2.4 × 10⁹ = 48 W. Saving = (86.4 − 48) ÷ 86.4 = 44.4%, while speed falls only 20%.
  3. (c) Power = 2 × 48 = 96 W (11% above A). Throughput = 2 × 2.4 ÷ 3.0 = 1.6 times A, if the work splits evenly over both cores.
  4. (d) A: time = 6 × 10⁹ ÷ 3 × 10⁹ = 2 s; energy = 86.4 × 2 = 172.8 J. B: time = 2.5 s; energy = 48 × 2.5 = 120 J. B is slower but uses 31% less energy, because energy per cycle (½CV²) falls from 28.8 nJ to 20 nJ.

Exam traps

  • Power goes as V² but only as f: a 10% voltage cut saves about 19%, a 10% frequency cut only 10%.
  • Power (watts) decides heat; energy (joules = watts × seconds) decides battery life.
  • Extra cores help only if the program runs in parallel (Amdahl's law, Chapter 1.6).

Glossary

Accelerator
A processing unit built for one kind of work, such as graphics or neural networks, with low energy per operation.
Address bus
The one-way lines that carry the address of the memory word or I/O port being accessed.
ALU
Arithmetic and logic unit: the circuit that adds, subtracts, compares and does logic operations.
Amdahl's law
Overall speedup = 1 ÷ ((1 − p) + p ÷ s) when a fraction p of the time is sped up s times.
Bandwidth (bus)
The peak data rate of a bus, in bytes per second.
Bus
A shared set of wires connecting several units; one transfer at a time.
Clock rate
Clock cycles per second (hertz); the inverse of the clock period.
Control bus
Individual signals such as read, write, interrupt request and ready that time and direct transfers.
Control unit
The part of the processor that fetches and decodes instructions and sends control signals to every unit.
CPI
Average clock cycles per instruction for a program.
Data bus
The two-way lines that carry the data word being transferred.
Dennard scaling
The rule that shrinking transistors allows a proportional cut in voltage, keeping power density constant; it ended in the mid-2000s.
Dynamic power
Power spent switching transistors: ½ × C × V² × f.
Embedded computer
A computer inside another product, doing one job at low cost and power.
Harvard architecture
Separate memories and buses for instructions and data.
Instruction cycle
The fetch, decode, operand fetch, execute, store and interrupt-check steps for one instruction.
IR
Instruction register: holds the instruction being executed.
Machine cycle
One bus operation, such as a memory read, taking a few clock cycles.
MAR
Memory address register: holds the address sent to memory.
MDR
Memory data register: holds the word read from or written to memory.
MFLOPS
Million floating-point operations per second.
MIPS
Million instructions per second = clock rate ÷ (CPI × 10⁶).
Moore's law
The observation that transistors per chip double about every two years.
PC
Program counter: holds the address of the next instruction.
Stored-program concept
Keeping the program in memory as data so the machine can load and run any program.
Throughput
Tasks completed per unit time.
Von Neumann bottleneck
The speed limit caused by instructions and data sharing one path to memory.
Wait state
An extra clock period inserted into a bus cycle while a slow device gets ready.
