5.1 Basic pipelining concepts, stages and timing diagrams

Pipelining splits the work of one instruction into stages and lets a new instruction enter the first stage every clock cycle while older instructions move on to later stages. One instruction still takes about as long as before, but the processor finishes far more instructions per second, the way a college canteen serves more students when token, dosa, chutney and billing are handled by four people standing in a line instead of one. Almost every processor made today, from the microcontroller in a smartwatch to a laptop chip, is pipelined.

You need: the instruction execution cycle (Unit 1, Basic operational concepts and instruction execution cycle), the single-cycle datapath (Unit 4, Building a datapath for a simple processor) and CPI (Unit 1, Performance metrics: CPI, MIPS and MFLOPS).

Latency and throughput

Latency is the time one instruction takes from start to finish. Throughput is the number of instructions completed per unit time. Pipelining improves throughput, not latency.

In the canteen, four jobs take 1 minute each. One cook serves 15 students an hour. With four people in a line, the first student still waits 4 minutes, but then one student leaves every minute: close to 60 an hour. Nobody worked faster; the jobs overlapped.

The five stages of the classic MIPS pipeline

  1. IF, instruction fetch. Read the instruction at address PC from instruction memory; compute PC + 4.
  2. ID, instruction decode and register read. Decode the opcode, read the two source registers, sign-extend the immediate field.
  3. EX, execute. The ALU does the arithmetic, or adds base + offset to form a memory address, or computes a branch target.
  4. MEM, memory access. A load (lw) reads data memory; a store (sw) writes it; other instructions pass through.
  5. WB, write back. The result is written into the destination register.

Every instruction passes through all five stages, even when it does nothing in one (an add idles in MEM), so each moves exactly one stage per clock. Between stages sit pipeline registers (also called latches or buffers) that hold one stage's results for the next; Chapter 5.2 looks inside them. The idea is the same.

Clock period, timing diagram and speedup

Let the pipeline have k stages with delays τ₁ … τₖ, and let each pipeline register add a delay d. All stages share one clock, so the clock period is set by the slowest stage:

τ = max(τ₁, τ₂, …, τₖ) + d

A timing diagram (also called a space-time diagram) has one row per instruction and one column per clock cycle. Read a row to follow one instruction through IF, ID, EX, MEM, WB. Read a column to see which instruction is in which stage during that cycle.

The first instruction needs k cycles to come out. Each of the other n − 1 instructions comes out one cycle later. So n instructions take

T_pipe = (k + n − 1) × τ
T_seq  = n × T_single          (T_single = time of one instruction without a pipeline)
Speedup S = T_seq / T_pipe
With equal stages and no latch delay, T_single = k × τ, so
S = n k / (k + n − 1)  →  k  as n becomes very large
Efficiency E = S / k = n / (k + n − 1)
Throughput W = n / T_pipe

Here k is the number of stages, n the number of instructions and τ the clock period. In the steady state the ideal CPI is 1. Real speedup stays below k because stages are unequal, every register adds delay, the pipeline must fill and drain, and hazards (Chapters 5.3 and 5.4) insert stalls.

Worked example

Question. A non-pipelined processor executes each instruction in four steps taking 60 ps, 50 ps, 90 ps and 80 ps. It is converted into a four-stage pipeline in which each pipeline register adds 10 ps. (a) Find the pipelined clock period. (b) Find the time to run 1000 instructions on both machines. (c) Find the speedup and compare it with the ideal value 4. (d) Find the latency of one instruction in the pipeline. (8 marks)

  1. Non-pipelined time per instruction: 60 + 50 + 90 + 80 = 280 ps.
  2. Pipelined clock: τ = max(60, 50, 90, 80) + 10 = 90 + 10 = 100 ps.
  3. Non-pipelined, 1000 instructions: 1000 × 280 ps = 280 000 ps = 280 ns.
  4. Pipelined: (k + n − 1) τ = (4 + 1000 − 1) × 100 ps = 1003 × 100 = 100 300 ps = 100.3 ns.
  5. Speedup S = 280 / 100.3 = 2.79. Even for very large n it only reaches 280 / 100 = 2.8, not 4, because the 90 ps stage sets the clock (the 50 ps stage waits 40 ps every cycle) and each register adds 10 ps.
  6. Latency of one instruction in the pipeline: 4 × 100 = 400 ps, more than the 280 ps without a pipeline. One instruction became slower; a thousand became 2.79 times faster.

Second question. A five-stage pipeline with equal stages has τ = 2 ns. For 100 instructions with no hazards, find the time, the speedup over a non-pipelined machine that takes 5τ per instruction, the efficiency and the throughput. (4 marks)

  1. T_pipe = (5 + 100 − 1) × 2 ns = 104 × 2 = 208 ns.
  2. T_seq = 100 × 5 × 2 ns = 1000 ns, so S = 1000 / 208 = 4.81.
  3. Efficiency E = 4.81 / 5 = 0.96, that is 96%.
  4. Throughput W = 100 / 208 ns = 0.481 instructions per ns = 4.81 × 10⁸ per second = 481 MIPS.

Exam traps

  • Pipelining raises throughput; it does not shorten the latency of one instruction. Latency usually grows because of register delay.
  • Total time is (k + n − 1) cycles. Writing k × n (no overlap) or n (forgetting the fill) loses marks.
  • The clock period is the slowest stage plus the register delay, never the average stage delay.
  • Maximum speedup equals the number of stages only with equal stages, zero register delay, no hazards and very many instructions.
  • In a timing diagram each instruction starts exactly one cycle after the previous one unless a stall is shown.

Understand Why does pipelining increase the latency of one instruction while reducing the total time for a program? 2 marks

Every stage now takes a full clock set by the slowest stage, plus register delay, so one instruction takes k × τ, which is more than the sum of the real stage delays. But k instructions are in flight at once, so one finishes every cycle.

Understand Why must an add pass through the MEM stage even though it never touches memory? 2 marks

If add skipped MEM it would reach WB in the same cycle as the load in front of it, and both would need the register write port. A fixed five-stage path keeps exactly one instruction per stage and avoids that structural conflict.

Apply A six-stage pipeline has τ = 1.5 ns. How long do 50 instructions take, and what is the speedup over a machine that takes 6τ per instruction? 4 marks

Analyze A designer splits every stage of a five-stage pipeline in half to get ten stages. Give two reasons why the real speedup is less than 2. 4 marks

The register delay stays the same while the useful work per stage halves, so it becomes a larger share of τ; stages cannot be cut into exactly equal halves; hazards cost more cycles because results and branch decisions are now more stages away; and clock skew and power grow with clock rate.

5.2 Pipelined datapath and control

The pipelined datapath is the single-cycle datapath of Unit 4 cut into five pieces by four pipeline registers, IF/ID, ID/EX, EX/MEM and MEM/WB. Each register is named after the two stages it separates and holds everything the later stages will need about the instruction that just passed. Control signals are made once, in ID, and then ride along with their instruction, so five different instructions can be in five stages with five different sets of control values.

You need: Chapter 5.1, and from Unit 4 the single-cycle datapath and the hardwired control unit (Building a datapath for a simple processor; Hardwired control unit).

Pipeline registers: what each one holds

The rule is simple: a stage may only use values in the pipeline register just before it. It cannot look back into IF/ID, because IF/ID already holds a newer instruction. So anything needed later must be copied forward at every clock edge.

The destination register must travel too

In the single-cycle design of Unit 4 the register to be written came straight from the instruction bits. In the pipeline that fails: when lw reaches WB, the instruction register IF/ID holds an instruction three places younger, so its rt field names a different register. The fix is to carry the destination register number (rt for a load, rd for an R-type, chosen by the RegDst multiplexer in EX) through ID/EX, EX/MEM and MEM/WB, and to write the register named in MEM/WB.

One more detail lets WB and ID share the register file in the same cycle: the register file is written in the first half of the clock cycle and read in the second half. An instruction in ID therefore reads a value that WB is writing in that very cycle.

Pipelined control

The main control unit decodes the opcode in ID and produces nine signals, the same ones as in the single-cycle design. IF and ID need none of them: every instruction is fetched and decoded the same way, and the PC and IF/ID are written every cycle (until Chapter 5.3 adds stalls). The other nine are grouped by the stage that uses them and stored in the ID/EX control fields.

Examiners often ask for the second one, or for what each pipeline register holds in a given cycle.

Exam traps

  • The destination register number must travel down to MEM/WB. Taking it from IF/ID in WB writes the wrong register; examiners call this the classic pipelined-datapath bug.
  • Control signals are produced once, in ID, and carried forward; they are not decoded again in each stage.
  • Register write happens in the first half of the cycle and read in the second; this is why WB and ID can overlap safely.
  • Pipeline registers are invisible to the programmer; do not list them with $0–$31.
  • The PC plays the role of the register in front of IF; there is no pipeline register after WB.

5.3 Data hazards: forwarding versus stalling

A data hazard occurs when an instruction needs a result that an earlier instruction, still inside the pipeline, has not yet written to the register file. There are two cures. Forwarding (also called bypassing) takes the result straight from the pipeline register where it already sits and feeds it to the ALU. Stalling holds the dependent instruction back until the value exists. Forwarding removes almost every stall; only a load followed at once by a use of its value still costs one cycle.

You need: Chapter 5.1 (timing diagrams) and Chapter 5.2 (what each pipeline register holds).

Three kinds of dependence

  • RAW (read after write, a true dependence): sub $2, $1, $3 then and $12, $2, $5. The second reads what the first writes.
  • WAR (write after read, an anti-dependence): add $4, $2, $3 then sub $2, $5, $6. The second overwrites a register the first reads.
  • WAW (write after write, an output dependence): two instructions write the same register.

In the in-order five-stage pipeline, registers are read only in ID and written only in WB, in program order, so only RAW causes hazards; WAR and WAW matter in out-of-order machines (Chapter 5.6).

Without forwarding, and waits until sub writes $2 in cycle 5: with the split-cycle register file (Chapter 5.2), 2 stall cycles.

Forwarding

The value of $2 exists at the end of cycle 3 in EX/MEM, and one cycle later in MEM/WB. Forwarding adds a multiplexer in front of each ALU input and a forwarding unit in EX that picks one of three sources: the register file (select 00), MEM/WB (01) or EX/MEM (10). Here "Rd" means the destination register number carried in the pipeline register (rt for a load).

EX hazard (newest result):
  if (EX/MEM.RegWrite and EX/MEM.Rd ≠ 0 and EX/MEM.Rd = ID/EX.Rs)  ForwardA = 10
  if (EX/MEM.RegWrite and EX/MEM.Rd ≠ 0 and EX/MEM.Rd = ID/EX.Rt)  ForwardB = 10
MEM hazard (older result, only if no EX hazard on the same register):
  if (MEM/WB.RegWrite and MEM/WB.Rd ≠ 0
      and not (EX/MEM.RegWrite and EX/MEM.Rd ≠ 0 and EX/MEM.Rd = ID/EX.Rs)
      and MEM/WB.Rd = ID/EX.Rs)                                     ForwardA = 01
  (the same with Rt for ForwardB)

RegWrite = 1 is tested because sw and beq write no register; Rd ≠ 0 because $0 is always zero. The EX hazard wins when both match, because EX/MEM holds the newer value: in add $1,$1,$2; add $1,$1,$3; add $1,$1,$4 the third add must take $1 from the second add, not the first.

The load-use hazard needs a stall

A load gets its data only at the end of MEM. If the very next instruction needs it at the start of its EX, the arrow would point backward in time. No wire can do that, so the pipeline must stall one cycle. A hazard detection unit in ID checks:

if (ID/EX.MemRead and (ID/EX.Rt = IF/ID.Rs or ID/EX.Rt = IF/ID.Rt))  stall one cycle
  1. Hold the PC and IF/ID (PCWrite = 0, IF/IDWrite = 0), so the same two instructions are fetched and decoded again.
  2. Write zeros into the control fields entering ID/EX. This empty slot, a bubble, flows down the pipeline like a nop and changes nothing.
  3. Next cycle the load is in MEM/WB, and forwarding from MEM/WB supplies the value.

A compiler can often hide this stall by moving an independent instruction between the load and its use: instruction scheduling, shown in the second example.

Worked example

Question. Initially $1 = 30, $3 = 12, $5 = 7, $6 = 5 and $15 = 99. For the code below, (a) list the dependences, (b) find the cycles needed without forwarding, (c) show which forwarding paths are used and the value each instruction produces. (8 marks)

sub $2, $1, $3
and $12, $2, $5
or  $13, $6, $2
add $14, $2, $2
sw  $15, 100($2)
  1. Dependences: RAW on $2 from sub to all four later instructions.
  2. Without forwarding: sub writes $2 in the first half of cycle 5, so and must do ID in cycle 5 instead of 3: 2 stalls. The rest then read $2 from the register file. Cycles = 5 + 5 − 1 + 2 = 11.
  3. With forwarding, cycle 4: and is in EX and $2 = 30 − 12 = 18 is in EX/MEM, so ForwardA = 10. Result 18 AND 7 = 10010₂ AND 00111₂ = 00010₂ = 2.
  4. Cycle 5: or is in EX and sub is in MEM/WB, so ForwardB = 01 (rt is $2). Result 5 OR 18 = 00101₂ OR 10010₂ = 10111₂ = 23.
  5. Cycle 6: add did ID in cycle 5, when $2 was written in the first half, so it read 18 from the register file; no forwarding. Result 36.
  6. Cycle 7: sw computes 18 + 100 = 118 and in cycle 8 writes 99 to address 118. Total with forwarding = 5 + 5 − 1 = 9 cycles; speedup 11 / 9 = 1.22.

Second question. A wallet app computes A = B + E and C = B + F, where B, E and F are at offsets 0, 4 and 8 from $t0, A goes to 12 and C to 16. With forwarding, how many cycles does the code take, and how can reordering help? Take B = 40, E = 2, F = 7. (6 marks)

lw  $t1, 0($t0)      # B = 40
lw  $t2, 4($t0)      # E = 2
add $t3, $t1, $t2    # uses $t2 at once: 1 stall
sw  $t3, 12($t0)     # A = 42
lw  $t4, 8($t0)      # F = 7
add $t5, $t1, $t4    # uses $t4 at once: 1 stall
sw  $t5, 16($t0)     # C = 47
  1. Seven instructions with two load-use stalls: 5 + 7 − 1 + 2 = 13 cycles.
  2. Move lw $t4, 8($t0) up to third place. Now add $t3 follows it by one instruction and add $t5 is three behind its load, so forwarding covers both.
  3. New time 5 + 7 − 1 = 11 cycles; speedup 13 / 11 = 1.18. Results are unchanged: A = 42, C = 47. The price: three registers ($t1, $t2, $t4) now hold live values at the same time instead of two.

Exam traps

  • Even with full forwarding, a load followed at once by a use of its result needs one stall; examiners ask this often.
  • Forward only when RegWrite = 1 and Rd ≠ 0; forwarding from a sw or into $0 is wrong.
  • When EX/MEM and MEM/WB both match, take EX/MEM: it holds the newer value.
  • Without forwarding, an adjacent RAW costs 2 stalls, not 3, because the register file writes in the first half and reads in the second.
  • WAR and WAW are not hazards in the simple in-order five-stage pipeline; do not list them as stalls there.

5.4 Structural and control hazards; handling branches

A structural hazard occurs when two instructions need the same piece of hardware in the same clock cycle. A control hazard (branch hazard) occurs because the pipeline must fetch the next instruction before it knows whether a branch is taken. Structural hazards are cured with more or better-organised hardware. Branches are cured by deciding early, predicting the outcome, or letting the compiler fill a delay slot. Branch prediction is in every modern processor, because one instruction in five or six is typically a branch.

You need: Chapters 5.1 to 5.3, and the Harvard architecture (Unit 1, Von Neumann and Harvard architectures).

Structural hazards

  • One memory for instructions and data. In cycle 4 a lw is in MEM while the fourth instruction is in IF; both need the memory. Fix: separate instruction and data caches (a Harvard-style split, Unit 6), or stall the fetch for one cycle.
  • Register file. WB writes while ID reads. Fix: two read ports and one write port, with write in the first half of the cycle.
  • An unpipelined functional unit. If a divider takes 10 cycles and is not pipelined, a second divide must wait. Fix: pipeline the unit or provide two.

A designer sometimes accepts a rare structural hazard because the extra hardware costs more than the occasional stall. The cost is stall cycles per instruction = (fraction of instructions that collide) × (stall cycles each).

Control hazards and the branch penalty

In the basic pipeline of Chapter 5.2, beq compares registers in EX and updates the PC in MEM. By then three more instructions have been fetched. If the branch is taken, they are wrong, so the branch penalty is 3 cycles. Five ways to cut it:

  1. Stall on every branch until it resolves: simple, but pays 3 cycles on every branch.
  2. Decide in ID. Move an equality comparator and the target adder into ID. The penalty falls to 1 cycle. The comparator may need forwarded values, and a stall if the register comes from the instruction just before.
  3. Predict not taken. Keep fetching in sequence. If the branch is taken, flush the wrongly fetched instruction by zeroing its control bits (the IF.Flush signal). Not-taken branches cost nothing.
  4. Delayed branch. Classic MIPS defines one branch delay slot: the instruction right after a branch always executes. The compiler moves an independent instruction from before the branch into the slot, or puts a nop.
  5. Dynamic branch prediction. A branch history table (BHT, or branch prediction buffer), indexed by low bits of the branch address, keeps a few bits of history per branch. A branch target buffer (BTB) caches each taken branch's target address so fetch can jump without waiting.

A 1-bit predictor remembers the last outcome. At the end of a loop it mispredicts twice: once on the exit, and once more on re-entry because it now says "not taken". A 2-bit predictor is a saturating counter that must be wrong twice in a row before it changes its prediction. Some books draw a variant in which a wrong guess in a weak state jumps straight to the opposite strong state; the two-wrong-guesses idea is the same.

All of these reduce to one formula. With an ideal CPI of 1,

CPI = 1 + (branch frequency) × (fraction of branches that cost a penalty) × (penalty in cycles)

Worked example

Question. 20% of instructions are branches and 60% of branches are taken. In the basic pipeline a branch resolves in MEM, so the penalty is 3 cycles. Find the CPI for (a) stall on every branch, (b) predict not taken with resolution in MEM, (c) predict not taken with resolution in ID, (d) a dynamic predictor that is 90% accurate with a 1-cycle misprediction penalty and a BTB. 5.5 Exceptions in pipelined processors

An exception is an unscheduled event that breaks the normal flow of a program: arithmetic overflow, an undefined instruction, a page fault, a system call. The processor must save where it was, record why, and jump to the operating system's handler. In a single-cycle machine that is easy. In a pipeline five instructions are in flight, so the hard part is stopping at one clean point, with every older instruction finished and every younger one cancelled. That is a precise exception, and it is what lets the operating system fix a page fault and resume the program as if nothing happened.

You need: Chapters 5.2 and 5.4 (flushing), and Unit 6, Interrupts and interrupt handling, for the operating-system side.

What the hardware does

  1. Save the address of the offending instruction in the EPC (Exception Program Counter).
  2. Record the reason in the Cause register. In MIPS the code 10 means undefined (reserved) instruction and 12 means arithmetic overflow.
  3. Load the PC with the handler's address, 8000 0180hex in MIPS, and fetch from there next cycle.
  4. The handler reads Cause, acts (ends the program, or loads the missing page), and returns to the address in EPC.

This is a single entry point. The other design is a vectored interrupt: the cause selects the handler's address from a table, as in x86 and ARM vector tables.

Precise exceptions in the pipeline

Suppose add $1, $2, $1 overflows in EX. The pipeline must:

  1. Let the older instructions in MEM and WB finish normally.
  2. Flush the add and the two younger instructions in ID and IF by zeroing their control signals (EX.Flush, ID.Flush, IF.Flush), turning them into bubbles. The add must not write $1, so the handler sees the original value.
  3. Write EPC and Cause, and load the PC with the handler address.

If two instructions raise exceptions in the same cycle, the processor services the older one, the one deeper in the pipeline, because a non-pipelined machine would have met it first. An external interrupt has no culprit instruction, so the processor picks a convenient boundary, flushes the younger instructions and saves the address of the first one not completed. Some long floating-point pipelines once allowed imprecise exceptions, reported after later instructions had already finished; the operating system then had to work out what failed. Almost all processors today are precise; out-of-order cores use the reorder buffer of Chapter 5.6 to achieve it.

5.6 Instruction-level parallelism and superscalar processors

Instruction-level parallelism (ILP) is the overlap of independent instructions from one program. A pipeline already exploits it one instruction per cycle. To go beyond CPI = 1, a processor must issue several instructions per cycle. If the compiler groups them in advance it is a static multiple-issue or VLIW machine; if the hardware picks them at run time it is a superscalar processor. Every phone and laptop core today is superscalar, most of them executing out of order.

You need: Chapters 5.3 and 5.4 (dependences, prediction).

Two routes to more ILP, and how to measure it

A deeper pipeline (superpipelining) overlaps more instructions by cutting each into more stages. Multiple issue places several instructions in each stage at once. With multiple issue we use IPC, instructions per cycle, which is 1/CPI. An n-issue machine has an ideal CPI of 1/n: a 4-issue core at 3 GHz could peak at 4 × 3 × 10⁹ = 12 billion instructions per second, but dependences, branches and cache misses keep real IPC far lower.

Static multiple issue (VLIW)

The compiler packs instructions into an issue packet, one long instruction word with fixed slots. A simple two-issue MIPS has one slot for an ALU or branch instruction and one for a load or store. The hardware does little checking; when the compiler finds nothing safe for a slot, it puts a nop. Two compiler tricks find more independent work: loop unrolling (copy the loop body several times and cut the loop overhead) and register renaming by the compiler (use different registers in each copy so the copies do not falsely depend on each other). VLIW survives in digital signal processors and some AI accelerators; Intel's Itanium (EPIC) was the best-known general-purpose attempt.

Dynamic issue: superscalar and out-of-order execution

A superscalar processor fetches several instructions per cycle, checks their dependences in hardware and issues zero to n of them. Most also use dynamic pipeline scheduling, which lets an instruction run as soon as its operands are ready, even ahead of older stalled ones. The scheme goes back to Tomasulo's algorithm on the IBM 360/91 (1967).

  1. Fetch and decode in order. Predict branches (Chapter 5.4) and send instructions to reservation stations in front of the functional units.
  2. Execute out of order. A station launches its instruction when both operands have arrived. Results go straight to any station waiting for them.
  3. Commit in order. The commit unit keeps a reorder buffer and writes results to registers and memory only in program order. If a branch was mispredicted, or an instruction faults, everything younger is simply discarded, which gives precise exceptions (Chapter 5.5).

Register renaming makes this work. WAR and WAW hazards (Chapter 5.3) are only clashes of register names, so the hardware maps each new destination to a fresh physical register. In div $1,$2,$3; add $4,$1,$5; sub $1,$6,$7, the slow div holds up add (a true RAW), but sub gets a new physical register for $1 and runs at once. Executing past a predicted branch before it resolves is called speculation.

5.7 Flynn's classification: SIMD and MIMD

In 1966 Michael Flynn sorted computers by two counts: how many instruction streams they follow at once and how many data streams they work on. That gives four classes, SISD, SIMD, MISD and MIMD. Two of them matter in every modern machine. SIMD applies one instruction to many data items at once, as in vector units and GPUs. MIMD runs many independent instruction streams, as in multicore chips and clusters. The classification gives you the words to describe any parallel computer in one line.

You need: Chapter 5.6 (what one core does with one instruction stream).

Instruction streams and data streams

An instruction stream is a sequence of instructions fetched by one control unit, with its own program counter. A data stream is a sequence of operands flowing between memory and a processing element.

SIMD: one instruction, many data

One control unit fetches and decodes each instruction and broadcasts it to N processing elements (PEs, also called lanes). Every PE performs the same operation, in lock-step, on its own data element. This suits data-level parallelism: brightening every pixel of a photo, mixing audio samples, multiplying matrices in machine learning.

  • Widths you will meet. x86 SSE registers are 128 bits (4 single-precision floats); AVX registers are 256 bits (8 floats); AVX-512 holds 16. ARM NEON registers are 128 bits.
  • Conditionals. Lanes cannot branch separately. For an if-else, the machine runs both paths and uses a mask to switch off the lanes that should not write. Lanes that are switched off do no useful work.
  • Why it pays. One fetch and decode drive many operations, so SIMD saves energy and needs no synchronisation between lanes.

MIMD: many instructions, many data

Each processor has its own control unit and program counter, fetches its own instructions and works on its own data, without lock-step. MIMD machines split by memory:

  • Shared-memory MIMD (multiprocessors): all processors share one address space and communicate by ordinary loads and stores. Multicore chips are this kind.
  • Distributed-memory MIMD (multicomputers, clusters): each node has private memory, and nodes communicate by sending messages over a network.

The usual way to program MIMD is SPMD, single program multiple data: every processor runs the same program on its own part of the data, each taking its own branches. SPMD is a programming style, not a fifth Flynn class. Real systems are hybrids: a laptop chip is MIMD across its cores, each core has SIMD units, and its GPU is a SIMD machine that NVIDIA describes as SIMT (single instruction, multiple threads).

5.8 Vector and array processors

A vector processor has instructions that work on whole vectors: one instruction loads 64 numbers, the next multiplies all 64 pairs. Its functional units are deeply pipelined and accept one element per clock, so the parallelism is in time. An array processor instead has many processing elements that each handle one element in the same clock, so the parallelism is in space. Both are SIMD machines (Chapter 5.7). They began in supercomputers such as the Cray-1 (1976) and live on today in the vector extensions of ARM and RISC-V and in GPUs.

You need: Chapter 5.1 (pipelines), Chapter 5.3 (forwarding) and Chapter 5.7 (SIMD). MFLOPS is defined in Unit 1, Performance metrics.

Vector architecture

Textbooks use a model machine called VMIPS (Hennessy and Patterson), shaped like the Cray-1. Its parts:

  • Vector registers: 8 registers, V0 to V7, each holding 64 elements of 64 bits.
  • Vector functional units: fully pipelined floating-point add, multiply and divide units, plus integer and logical units, each accepting a new element every cycle.
  • Vector load/store unit: a pipelined memory unit that moves a whole vector between memory and a vector register.
  • Scalar registers: give scalar operands (the a in a × X) and memory addresses.
  • Vector length register (VLR): how many elements an instruction processes, up to the maximum vector length MVL = 64. Vector mask register: one bit per element, to switch elements off for conditional code.

The classic program is DAXPY, Y = a × X + Y in double precision (from the LINPACK benchmark). For 64 elements the vector code is six instructions:

L.D     F0, a         ; scalar a
LV      V1, Rx        ; load vector X
MULVS.D V2, V1, F0    ; V2 = a × X, element by element
LV      V3, Ry        ; load vector Y
ADDVV.D V4, V2, V3    ; V4 = a × X + Y
SV      V4, Ry        ; store the result into Y

A scalar MIPS loop needs about 9 instructions per element (2 loads, multiply, add, store, 2 pointer updates, a test and a branch), so about 9 × 64 + 2 = 578 instructions. The vector version fetches 96 times fewer instructions, has no loop branches, and needs no hazard checks between elements because they are independent.

Timing: chaining, convoys, chimes and strip mining

  • Chaining is forwarding for vectors: as each element of a result leaves one unit, it goes straight into the next dependent unit.
  • A convoy is a group of vector instructions that can run together: no two need the same unit (with one memory pipeline, two loads cannot share a convoy), and dependent ones are chained.
  • A chime is the time to run one convoy, about n cycles for a vector of n elements. So time ≈ (number of convoys) × n + the start-up latency of each convoy, where start-up is the depth of the pipelines involved.
  • Strip mining: when n is larger than MVL, the loop is cut into ⌈n / MVL⌉ strips, one of length n mod MVL and the rest of length MVL, with VLR set for each.
  • Stride is the distance in memory between consecutive elements. A column of a row-major 100 × 100 matrix of doubles has stride 100 × 8 = 800 bytes. Scattered elements are fetched by gather and stored by scatter using an index vector.

Array processors

An array processor has one control unit and N processing elements (PEs), each with its own local memory, joined by an interconnection network such as a mesh. The control unit broadcasts an instruction and all active PEs execute it at once on their own data; a mask bit per PE turns PEs off. Historical examples are ILLIAC IV, with 64 PEs, and the Connection Machine CM-2, with up to 65 536 one-bit PEs. Time for n elements is about ⌈n / N⌉ steps.

Worked example

Question. Run DAXPY on n = 200 elements on VMIPS with MVL = 64, one memory pipeline and chaining. Start-up latencies: load/store 12 cycles, multiply 7 cycles, add 6 cycles. Form the convoys, find the number of strips, the total cycles and the cycles per element. At 1 GHz, find the MFLOPS. (8 marks)

  1. Convoys: (1) LV V1 with MULVS.D chained; (2) LV V3 with ADDVV.D chained; (3) SV. The two loads and the store each need the single memory pipeline, so they cannot share a convoy. That is 3 chimes.
  2. Time for a strip of length L: (12 + 7 + L) + (12 + 6 + L) + (12 + L) = 49 + 3L cycles.
  3. Strips: ⌈200 / 64⌉ = 4, of lengths 200 mod 64 = 8, then 64, 64, 64.
  4. Total = 4 × 49 + 3 × (8 + 64 + 64 + 64) = 196 + 600 = 796 cycles, which is 796 / 200 = 3.98 cycles per element. The ideal is 3 (one per chime); start-up adds the rest.
  5. DAXPY does 2 floating-point operations per element (one multiply, one add): 400 operations in 796 ns at 1 GHz, so 400 / (796 × 10⁻⁹) = 5.03 × 10⁸ per second = 503 MFLOPS.

Second question. An array processor has 16 PEs. How many steps does it need to add two 200-element vectors, and what fraction of PEs is idle in the last step? (2 marks)

  1. ⌈200 / 16⌉ = 13 steps: 12 full steps cover 192 elements.
  2. The last step has 8 elements, so 8 of 16 PEs, 50%, are masked off.

Exam traps

  • Vector processor: parallelism in time through pipelined units. Array processor: parallelism in space through many PEs. Both are SIMD.
  • Chaining is the vector form of forwarding; without it the add waits for the whole multiply to finish.
  • For n > MVL you must strip-mine; the number of strips is ⌈n / MVL⌉, not n / MVL rounded down.
  • VLR says how many elements; the mask register says which elements. Do not mix them up.
  • Time is counted in chimes plus start-up, not in instructions: three instructions in one convoy cost one chime.

Check yourself

Remember List the main components of a vector processor. 2 marks

Vector registers, pipelined vector functional units, a vector load/store unit, scalar registers, a vector length register and a vector mask register.

Understand Why does a vector instruction avoid the data and control hazards of the equivalent scalar loop? 3 marks

The elements of one vector operation are independent by definition, so the hardware needs no checks between them, and the loop branch disappears because one instruction covers the whole vector.

Understand Distinguish a vector processor from an array processor. 3 marks

A vector processor pipelines one unit across elements (temporal) and keeps operands in vector registers. An array processor replicates PEs with local memories that work on different elements in the same cycle (spatial).

Apply For n = 300 and MVL = 64, how many strips are needed and what are their lengths? 2 marks

Apply Ignoring start-up, how many cycles does 64-element DAXPY take in 3 chimes, and what MFLOPS does that give at 1 GHz? 3 marks

Analyze Memory has 8 banks, word-interleaved. Compare a vector load with stride 1 and one with stride 8 words. 4 marks

Stride 1 visits banks 0, 1, 2, … 7 in turn, so each bank has 8 cycles to recover and the load streams one word per cycle. Stride 8 sends every access to the same bank (8 mod 8 = 0), so each access waits for that bank to recover and the load slows by the bank busy time. Strides that share a factor with the bank count cause such conflicts.

Japan's Fugaku supercomputer is built on the Fujitsu A64FX processor with 512-bit SVE units, and NEC still sells classic vector engines. GPUs carry the SIMD idea to thousands of lanes (Chapter 5.7). 5.9 Multiprocessors, multithreading and clusters

When one instruction stream has no more independent work to offer, a computer runs several threads at once. This is thread-level parallelism, and hardware supports it in three ways. A multiprocessor puts several processors (today, cores on one chip) on one shared memory. Hardware multithreading lets one core hold several threads and switch between or mix them to keep its units busy. A cluster joins complete computers with a network, each with its own memory. Amdahl's law tells you how much any of them can gain.

You need: Chapters 5.6 and 5.7, cache memory (Unit 6, Cache memory: mapping functions and organization) and the power wall (Unit 1, Technology trends and the power wall), which is why chips went multicore.

Shared-memory multiprocessors

All processors share one physical address space and communicate through ordinary loads and stores. Access to shared data is guarded by locks built on atomic instructions, such as MIPS ll/sc (load-linked and store-conditional) or x86 compare-and-swap.

  • UMA (uniform memory access), also called SMP (symmetric multiprocessor): every processor reaches every memory word in the same time. Typical of one multicore chip.
  • NUMA (non-uniform memory access): each processor has memory attached to it; local memory is faster than memory on another processor. Typical of multi-socket servers.

Hardware multithreading

A multithreaded core keeps a program counter and register set for each thread but shares its functional units, caches and pipeline.

  1. Coarse-grained: run one thread until it hits a long stall, such as a last-level cache miss, then switch. Each thread runs at full speed, but each switch costs a pipeline refill, and short stalls are not hidden.
  2. Fine-grained: switch threads every cycle, round-robin, skipping stalled threads. Short and long stalls are both hidden, but a single thread runs slower.
  3. Simultaneous multithreading (SMT): in a multiple-issue, out-of-order core, fill the issue slots of one cycle with instructions from several threads. Register renaming keeps their registers apart. Intel sells this as Hyper-Threading, two threads per core.

Clusters and message passing

A cluster is a set of complete computers, called nodes, each with its own memory and its own copy of the operating system, joined by a network. Nodes cannot load each other's memory; they cooperate by message passing, explicit send and receive calls, usually through the MPI library. Clusters are cheap (ordinary servers), scale to thousands of nodes, and isolate failures: a dead node is swapped while the rest keep working. The cost is communication that takes microseconds instead of nanoseconds and harder programming. The data centres behind web search, UPI payments and IRCTC bookings are clusters of many thousands of servers, sometimes called warehouse-scale computers, as are most of the largest supercomputers.

Amdahl's law

If a fraction f of the single-processor running time can be spread over p processors and the rest (1 − f) stays serial,

Speedup S(p) = 1 / ((1 − f) + f / p)        limit as p → ∞:  1 / (1 − f)

Speeding up a problem of fixed size is strong scaling. Growing the problem with the machine, so the parallel part grows while the serial part stays fixed, is weak scaling (Gustafson's view). Uneven work per processor, called poor load balance, lowers speedup further.

Worked example

Question. A program takes 100 s on one core and 90% of that time can be parallelised. (a) Find the time and speedup on 10 and on 100 cores. (b) What is the largest possible speedup? (c) What parallel fraction is needed for a speedup of 90 on 100 cores? (6 marks)

  1. 10 cores: serial 10 s + parallel 90 / 10 = 9 s, total 19 s, S = 100 / 19 = 5.26.
  2. 100 cores: 10 + 0.9 = 10.9 s, S = 9.17. Ten times the cores gave less than twice the speed.
  3. Limit: 1 / (1 − 0.9) = 10, however many cores are added.
  4. For S = 90 on 100 cores: (1 − f) + f / 100 = 1 / 90 = 0.01111, so 1 − 0.99 f = 0.01111 and f = 0.98889 / 0.99 = 0.99888. Only about 0.11% of the time may be serial.

Second question. Cores P1 and P2 use MSI write-invalidate snooping with write-back caches. Shared variable X is 5 in memory. Trace the states and values for: P1 reads X; P2 reads X; P1 writes 8; P2 reads X; P2 writes 10. (6 marks)

Exam traps

  • Multicore means several cores; multithreading means several thread contexts in one core. Hyper-Threading doubles logical processors, not cores.
  • SMT needs a multiple-issue core; coarse- and fine-grained multithreading also work on a single-issue pipeline.
  • In Amdahl's law f is a fraction of execution time, not of lines of code, and the speedup can never pass 1 / (1 − f).
  • Cluster nodes share no memory and communicate by messages; a multiprocessor communicates by loads and stores.
  • In write-invalidate a write broadcasts an invalidate, not the new value; the new value is supplied on the next miss.

Check yourself

Remember Define UMA and NUMA multiprocessors. 2 marks

UMA: every processor sees the same access time to every memory word. NUMA: memory is attached to processors, and local access is faster than remote access.

Understand Distinguish coarse-grained, fine-grained and simultaneous multithreading. 3 marks

Coarse: switch only on long stalls. Fine: switch every cycle among ready threads. SMT: issue from several threads in the same cycle on a superscalar core.

Understand Why do clusters scale to thousands of nodes more easily than shared-memory multiprocessors? 3 marks

They need no hardware cache coherence or shared memory bus, which become bottlenecks as processors are added; each node is an ordinary computer and the network grows with them. Failures are also isolated to one node.

Apply With f = 0.8, find the speedup on 4 processors and the limit. 2 marks

S = 1 / (0.2 + 0.8 / 4) = 1 / 0.4 = 2.5. Limit = 1 / 0.2 = 5.

Apply One thread alone gets IPC 1.2 on a core. With SMT, two threads together get IPC 1.6. Find the throughput gain and each thread's IPC. 3 marks

Gain = 1.6 / 1.2 = 1.33, a 33% gain in throughput. Each thread gets about 0.8, so each runs slower than alone while the core does more work.

Analyze Amdahl's law suggests large machines are pointless, yet supercomputers have millions of cores. Explain. 4 marks

Amdahl assumes a fixed problem. Supercomputers solve bigger problems on bigger machines (weak scaling): the parallel work grows with p while the serial part stays about the same. Gustafson's scaled speedup is S = s + p(1 − s) for serial fraction s measured on the parallel machine; with s = 0.01 and p = 100, S = 0.01 + 99 = 99.01.

Takeaways

  1. Pipelining raises throughput, not latency: n instructions take (k + n − 1) cycles, and the slowest stage sets the clock.
  2. Pipeline registers carry every instruction's data, destination register number and control signals down the pipe.
  3. RAW hazards are cured by forwarding; a load followed at once by its use still needs one stall, which a compiler can often hide.
  4. Structural hazards need more or split hardware; branch costs shrink by deciding early and predicting well: CPI = 1 + branch frequency × fraction penalised × penalty.
  5. A precise exception lets older instructions finish, flushes the rest, saves EPC and Cause, and jumps to the handler.
  6. Multiple issue lifts IPC above 1; out-of-order cores execute out of order, rename registers and commit in order.
  7. Of Flynn's four classes, SIMD and MIMD matter; vector processors are parallel in time, array processors in space.
  8. Multiprocessors, multithreaded cores and clusters exploit thread-level parallelism, and Amdahl's law caps the gain at 1 / (1 − f).

Analyze and evaluate

Analyze 11. Compare superscalar, VLIW, vector and multicore designs as ways to raise performance: where each finds parallelism, what it costs, and what limits it. 12 marks

Superscalar: ILP found by hardware, cost in dependence checks and power, limited by dependences and mispredictions. VLIW: ILP found by the compiler, simple hardware, code size and binary compatibility issues. Vector: data-level parallelism, few instructions, needs regular data. Multicore: thread-level parallelism, needs parallel software, limited by Amdahl's law and coherence traffic. This question spans Chapters 5.6 to 5.9.

Analyze 12. Explain how a five-stage pipeline makes exceptions precise, and how an out-of-order superscalar processor does the same with a reorder buffer. 10 marks

Definition of precise; in-order pipeline: finish older, flush faulting and younger with IF/ID/EX flush, EPC and Cause, handler address, oldest exception first; out-of-order: results held in the reorder buffer, committed in order, exception recorded with the instruction and raised at commit, younger entries discarded. Spans Chapters 5.5 and 5.6.

Evaluate 13. A designer can either double the pipeline depth or double the issue width of a five-stage, single-issue core. Evaluate both choices. 12 marks

Deeper: higher clock, but more register overhead, larger branch and load-use penalties, more power. Glossary

Amdahl's law
Speedup on p processors is 1 / ((1 − f) + f / p), where f is the parallel fraction of the time.
Branch delay slot
The instruction position after a branch that always executes, in classic MIPS.
Branch target buffer
A cache of the target addresses of recently taken branches.
Bubble
An empty slot (a nop) inserted into the pipeline during a stall.
Cache coherence
Keeping all cached copies of a shared memory word consistent across processors.
Chaining
Feeding each result element of one vector unit straight into the next dependent unit.
Chime
The time to run one convoy of vector instructions, about n cycles for n elements.
Cluster
Complete computers joined by a network, each with private memory, cooperating by messages.
Control hazard
A stall caused by not knowing the next instruction address until a branch resolves.
Data hazard
A stall caused by an instruction needing a result that is not yet written.
EPC
Exception Program Counter: holds the address of the instruction that caused an exception.
Flush
Turning instructions already in the pipeline into bubbles so they change nothing.
Forwarding
Passing a result from a pipeline register directly to a later instruction's ALU input; also called bypassing.
Hazard detection unit
Logic in ID that detects a load-use hazard and stalls the pipeline.
ILP
Instruction-level parallelism: overlap among the instructions of one program.
IPC
Instructions per cycle, the reciprocal of CPI.
MIMD
Multiple instruction streams, multiple data streams: multicores and clusters.
NUMA
Non-uniform memory access: local memory is faster than memory attached to another processor.
Pipeline register
A register between two stages that holds one instruction's values for the next stage.
Precise exception
One where all earlier instructions complete and no later instruction changes state.
Register renaming
Mapping register names to fresh physical registers to remove WAR and WAW hazards.
Reorder buffer
A buffer that holds results of out-of-order execution until they can commit in program order.
Reservation station
A buffer in front of a functional unit where an instruction waits for its operands.
SIMD
Single instruction stream, multiple data streams: vector units, array processors, GPUs.
SMT
Simultaneous multithreading: issuing instructions from several threads in the same cycle.
Strip mining
Splitting a long vector loop into pieces no longer than the maximum vector length.
Structural hazard
A stall caused by two instructions needing the same hardware in the same cycle.
Superscalar
A processor whose hardware issues more than one instruction per cycle.
VLIW
Very long instruction word: the compiler packs several operations into one issue packet.
