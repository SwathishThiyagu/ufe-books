6.1 Memory hierarchy and locality of reference

No single memory is fast, large and cheap at once. Fast memory (SRAM inside the processor) costs a lot per byte, and cheap memory (disks) is a million times slower. The memory hierarchy stacks several levels, small and fast near the processor, large and cheap far away, and keeps copies of the data in use in the fast levels. It works because programs show locality of reference: they reuse what they used recently and use what sits next to it.

You need: the functional units and the memory read and write operations of Unit 1 (Functional units of a computer) and Unit 2 (Memory locations, addresses and memory operations).

The levels and the trade-off

Going down the hierarchy, each level is larger, slower and cheaper per byte than the one above it. Figure 6.1.1 shows the payoff for two levels, a 2 ns cache in front of 60 ns DRAM.

  • Registers: a few dozen words inside the processor, read in one clock cycle. The compiler decides what lives in them.
  • Cache (L1, L2, L3): SRAM on the processor chip. The hardware copies data in and out automatically; the programmer does not see it.
  • Main memory: DRAM chips on modules (DIMMs), several gigabytes. Chapter 6.2 explains the technology.
  • Secondary storage: SSDs and hard disks, terabytes, non-volatile. The operating system moves pages between main memory and disk (Chapter 6.5).

Two rules keep the levels consistent. Data moves only between adjacent levels, in fixed-size units: a block (or line, usually 64 bytes) between cache and main memory, a page (usually 4 KB) between main memory and disk. And in an inclusive hierarchy each level holds a subset of the level below it, so a word found in L1 also has a copy in L2 and in main memory.

In a server with two processor sockets, each socket has its own DRAM. A core can read the other socket's memory, but it takes longer. Memory whose access time depends on where it sits is called NUMA (non-uniform memory access).

Locality of reference

A hierarchy pays off only if most accesses find their data in the fast levels. Programs make this happen through two kinds of locality.

  • Temporal locality: an item used now is likely to be used again soon. Loop counters, a running total and the instructions of a loop body are reused on every iteration. The cache keeps recently used blocks for this reason.
  • Spatial locality: items near a used item are likely to be used soon. Array elements, the fields of a structure and instructions that follow one another sit at neighbouring addresses. The cache fetches a whole block, not one word, for this reason.

Look at this C loop that adds the marks of 1,000 students:

int a[1000], sum = 0;
for (int i = 0; i < 1000; i++)
    sum += a[i];

The variables sum and i and the four or five loop instructions show temporal locality. The array shows spatial locality: each int is 4 bytes, so a 64-byte block holds 16 elements. The first access to a block misses and the next 15 hit. Starting with an empty cache, the array gives 1,000 / 16 ≈ 63 misses for 1,000 reads, a miss rate of 1/16 = 6.25%.

Locality belongs to the program, not to the hardware, so code can destroy it. C stores a two-dimensional array row by row (row-major order). Walking m[i][j] with j in the inner loop moves 4 bytes per step. Swapping the loops so that i is inside jumps a whole row (4 KB for a 1024-column int array) per step, and nearly every access misses.

Hit, miss and average access time

When the processor finds the item in the upper level it is a hit; otherwise a miss, and the block must be brought from the lower level. The hit ratio h is the fraction of accesses that hit; the miss ratio is 1 − h. For two levels with access times T₁ (upper) and T₂ (lower), textbooks use two models, and the question tells you which one:

Hierarchical (look in level 1 first, then go to level 2):
    T_avg = T₁ + (1 − h) × T₂
Simultaneous (both levels searched at once):
    T_avg = h × T₁ + (1 − h) × T₂

The access efficiency is T₁ / T_avg; it tells how close the pair comes to the speed of level 1 alone. The average cost per byte is c = (c₁S₁ + c₂S₂) / (S₁ + S₂), where c₁, c₂ are costs per byte and S₁, S₂ are sizes. Chapter 6.4 extends T_avg to caches with several levels and to processor CPI.

Worked example

Question. A computer has a 2 MB cache with access time 2 ns and an 8 GB main memory (8,192 MB) with access time 60 ns. The hit ratio is 0.97. Assume the cache costs ₹500 per MB and DRAM ₹0.25 per MB. Find (a) the average access time in the hierarchical model, (b) the average access time in the simultaneous model, (c) the access efficiency and the speed-up over main memory alone, (d) the average cost per MB. (8 marks)

  1. Miss ratio 1 − h = 1 − 0.97 = 0.03.
  2. (a) T_avg = T₁ + (1 − h)T₂ = 2 + 0.03 × 60 = 2 + 1.8 = 3.8 ns.
  3. (b) T_avg = hT₁ + (1 − h)T₂ = 0.97 × 2 + 0.03 × 60 = 1.94 + 1.8 = 3.74 ns.
  4. (c) Efficiency = T₁ / T_avg = 2 / 3.8 = 0.53 (53%). Speed-up over DRAM alone = 60 / 3.8 = 15.8 times.
  5. (d) Cost of cache = 500 × 2 = ₹1,000. Cost of DRAM = 0.25 × 8,192 = ₹2,048. Average cost = (1,000 + 2,048) / (2 + 8,192) = 3,048 / 8,194 = ₹0.37 per MB.

What it shows. The pair costs barely more per MB than DRAM (₹0.37 against ₹0.25) yet runs about sixteen times faster than DRAM. That is the whole case for a hierarchy. Raise h to 0.99 and T_avg in (a) falls to 2 + 0.01 × 60 = 2.6 ns, so small gains in hit ratio matter a lot.

Exam traps

  • Two formulas for T_avg exist. If the question says the lower level is accessed “after a miss” or “on a miss”, use T₁ + (1 − h)T₂; if it says “in parallel”, use hT₁ + (1 − h)T₂. State the model you use.
  • Hit ratio is given as a percentage (97%) or a fraction (0.97); never multiply by 97.
  • Temporal locality is about the same item again; spatial is about neighbouring items. A loop body is temporal; walking an array is spatial.
  • Favourite question: “Why does a memory hierarchy work?” Answer with locality, not only with cost.

6.2 Memory technologies: RAM, ROM, PROM, EPROM, EEPROM

Semiconductor memory comes in two families. RAM (random-access memory) can be read and written quickly but forgets everything when power goes, as anyone who lost an unsaved file in a Chennai power cut knows. ROM (read-only memory) and its descendants PROM, EPROM, EEPROM and flash keep their contents without power but are slow or awkward to write. Caches use SRAM, main memory uses DRAM, and the firmware that starts the machine sits in ROM-family chips.

You need: Chapter 6.1 (where each technology sits in the hierarchy) and decoders from your digital logic course.

RAM: SRAM and DRAM

Both are volatile: they lose data when power is removed. They differ in how a bit is held.

  • SRAM (static RAM) stores a bit in a latch of two cross-coupled inverters, plus two access transistors: six transistors per bit. The latch holds its value as long as power is on, so SRAM needs no refresh. It is fast (around 1 ns) but large and costly, so it is used for caches and register files.
  • DRAM (dynamic RAM) stores a bit as charge on a tiny capacitor, with one access transistor: one transistor and one capacitor per bit. It is several times denser than SRAM and much cheaper per bit, so main memory is DRAM. The charge leaks away in milliseconds, so every row must be refreshed (read and rewritten); the common standard is every row within 64 ms. Reading also drains the capacitor, so the sense amplifier writes the value back after each read.

A DRAM chip is a grid of rows and columns. To save pins, the address is sent in two halves on the same pins: the row address with the RAS (row address strobe) signal, then the column address with CAS (column address strobe). SDRAM (synchronous DRAM) times these steps with the bus clock, and DDR (double data rate) SDRAM moves data on both clock edges. A DDR4-3200 module makes 3,200 million transfers per second on a 64-bit (8-byte) bus, so its peak rate is 3,200 × 10⁶ × 8 = 25.6 GB/s.

In a memory read cycle the processor places the address on the address bus and asserts Read; after the access time the memory places the data on the data bus and signals that it is ready (often called MFC, memory function completed), and the processor latches it. A write cycle is the same with the data driven by the processor and Write asserted. Unit 1, Bus structures, covers the buses themselves.

ROM, PROM, EPROM, EEPROM and flash

These are non-volatile: they keep data without power. All are randomly accessible, like RAM; the names differ in how the contents are written and erased. EPROM, EEPROM and flash store a bit as charge trapped on a floating gate, an insulated extra gate inside a transistor that changes whether the transistor conducts.

Building a memory from chips

A chip is described as words × bits: a 1M × 8 chip has 2²⁰ locations of 8 bits, so it needs 20 address lines and 8 data lines. To make wider words, place chips side by side and share the address; to make more words, stack rows of chips and use a decoder on the high address bits to select one row with the chip-select (CS) inputs. The number of chips is (total bits needed) ÷ (bits per chip).

Worked example

Question. Design a 4M × 32 memory using 1M × 8 DRAM chips. Find the number of chips, the total address lines, and how the address lines are used. The chips have 8,192 rows each, every row must be refreshed within 64 ms, and refreshing one row takes 50 ns. Find the refresh interval per row and the fraction of time spent refreshing. (8 marks)

  1. Chips = total bits ÷ bits per chip = (4M × 32) ÷ (1M × 8) = 4 × 4 = 16 chips.
  2. Word size: 32 ÷ 8 = 4 chips side by side make one 32-bit row. Word count: 4M ÷ 1M = 4 rows.
  3. Address lines: 4M = 2²² words, so 22 lines, A0–A21.
  4. A0–A19 (20 lines) go to every chip and pick the word inside a chip. A20–A21 (2 lines) feed a 2-to-4 decoder whose outputs CS0–CS3 select one row (Figure 6.2.1). For example, address 0x2ABCDE has A21 A20 = 1 0, so row 2 responds.
  5. Refresh interval per row = 64 ms ÷ 8,192 = 7.8 µs. Every 7.8 µs the controller refreshes one row.
  6. Time spent refreshing per 64 ms = 8,192 × 50 ns = 409.6 µs. Fraction = 409.6 µs ÷ 64 ms = 0.64% of the time.

Error detection and correction

A stray alpha particle or cosmic ray can flip a DRAM bit; this is a soft error. Servers use ECC memory, which stores check bits with each word. A Hamming code with k check bits for m data bits corrects any single-bit error when 2ᵏ ≥ m + k + 1. For m = 64, k = 7 works (128 ≥ 72). One more overall parity bit also detects double errors, giving SEC-DED (single error correction, double error detection): 64 + 8 = 72 bits, which is why ECC modules are 72 bits wide. For m = 32 the same rule gives k = 6 (64 ≥ 39, while k = 5 fails since 32 < 38), so SEC-DED needs 7 check bits, an overhead of 7/32 ≈ 22% against 8/64 = 12.5% for 64 bits.

Exam traps

  • ROM is random access too; the contrast between RAM and ROM is about writing, not access order.
  • SRAM needs no refresh but is still volatile. Do not write “static means non-volatile”.
  • EPROM is erased by ultraviolet light, whole chip, out of the circuit; EEPROM electrically, byte by byte, in the circuit; flash electrically, a block at a time.
  • Chips needed = total bits ÷ chip bits, not total words ÷ chip words. Check both word count and word width.
  • Hamming check bits come from 2ᵏ ≥ m + k + 1; add one more bit for double-error detection.

6.3 Cache memory: mapping functions and organization

A cache is a small, fast SRAM memory between the processor and main memory that holds copies of recently used blocks. Because it is thousands of times smaller than main memory, many memory blocks compete for each place in it. The mapping function is the rule that says where a block may be placed and therefore how the hardware finds it again. Direct, fully associative and set-associative mapping trade speed and cost against how often blocks collide. Every processor, from a phone chip to a server, uses set-associative caches at its first levels.

You need: Chapter 6.1 (blocks, hits and misses) and binary addresses from Unit 2.

Blocks, lines, tags and the valid bit

Main memory is divided into blocks of B bytes (commonly 64). The cache is divided into lines of the same size, each holding one block. Next to each line the cache stores a tag, the high-order address bits that say which block is there now, and a valid bit V that says whether the line holds anything at all (all V bits are 0 at power-on). The processor's address is split into fields:

  • Offset: log₂B bits, the byte inside the block.
  • Index (line or set number): log₂(number of lines or sets) bits, where to look.
  • Tag: all remaining bits, compared with the stored tag.

A hit needs a valid line whose stored tag equals the address tag.

The three mapping functions

Direct mapping. Block j may go only to line j mod L, where L is the number of lines. The address is Tag | Line | Offset. The line field picks one line, and one comparator checks its tag. It is the simplest and fastest design, but two busy blocks that map to the same line throw each other out again and again, even when the rest of the cache is empty. These are conflict misses.

Fully associative mapping. A block may go into any line. The address is just Tag | Offset, and the hardware compares the tag with every stored tag at once, which needs one comparator per line. It has no conflict misses but is costly and slow for large caches, so it is used only for small structures such as the TLB (Chapter 6.5).

k-way set-associative mapping. The L lines are grouped into S = L ÷ k sets of k lines. Block j goes to set j mod S, into any of its k lines. The address is Tag | Set | Offset, and k comparators check the set in parallel. Direct mapping is the case k = 1; fully associative is the case S = 1. Typical L1 caches are 8-way, a good balance of hit rate and speed.

Replacement and write policies

On a miss in an associative or set-associative cache, a line of the set must be chosen to evict. A direct-mapped cache has no choice.

  • LRU (least recently used): evict the line unused for the longest time. Good hit rate; for 2 ways one bit per set is enough, but exact LRU gets costly beyond 4 ways, so hardware uses approximations.
  • FIFO: evict the oldest arrival. Random: cheap and, for large caches, nearly as good as LRU. LFU: evict the least frequently used.

Writes need a policy too. Write-through updates the cache and main memory on every store, usually through a write buffer so the processor need not wait. Write-back updates only the cache and sets a dirty bit; the block is written to memory only when evicted. On a write miss, write-allocate brings the block into the cache first, while no-write-allocate writes straight to memory. Write-back usually goes with write-allocate.

The cache controller can be built as a finite-state machine. In the textbook design by Patterson and Hennessy it has four states: Idle, Compare Tag, Write-Back (send a dirty victim to memory) and Allocate (fetch the new block).

6.4 Measuring and improving cache performance

A cache is judged by how much time it saves, not by its hit rate alone. Two numbers capture this: the average memory access time (AMAT), and the extra clock cycles per instruction (CPI) the processor loses waiting for memory. Every technique for a better cache lowers one of three things: the hit time, the miss rate or the miss penalty. Usually lowering one raises another, and the formulas of this chapter tell you whether a change is worth it.

You need: Chapter 6.3 (mapping and policies) and Unit 1, Performance metrics: CPI, MIPS and MFLOPS.

The measures

Let the hit time be the time to find data in the cache, the miss rate the fraction of accesses that miss, and the miss penalty the extra time to bring a block from the next level. Then:

AMAT = Hit time + Miss rate × Miss penalty

Memory-stall cycles per instruction
     = (memory accesses per instruction) × Miss rate × Miss penalty

CPI_effective = CPI_base + memory-stall cycles per instruction
CPU time      = IC × CPI_effective × clock cycle time

Here CPI_base is the CPI with a perfect cache that never misses, and IC is the instruction count. Every instruction makes one instruction fetch; only loads and stores also make a data access. So instruction-cache and data-cache stalls are counted separately and added. Industry often quotes MPKI, misses per thousand instructions, which already folds in the accesses per instruction.

Where misses come from: the three Cs

  • Compulsory (cold) misses: the first access to a block. They happen even in an infinite cache.
  • Capacity misses: the program's working set is larger than the cache, so blocks are evicted and fetched again.
  • Conflict misses: too many blocks map to the same set, though other sets have room. A fully associative cache of the same size would not have them.

Multiprocessors add a fourth C, coherence misses, covered in Unit 5, Multiprocessors, multithreading and clusters.

Multilevel caches. With an L2 cache, the L1 miss penalty is no longer a trip to DRAM but the L2 access time plus, on an L2 miss, the DRAM time:

AMAT = HT₁ + MR₁ × (HT₂ + MR₂ × MP₂)

HT is hit time, MR miss rate and MP miss penalty, with subscripts for the level. MR₂ here is the local miss rate of L2, the fraction of accesses reaching L2 that miss. The global miss rate, the fraction of all processor accesses that reach DRAM, is MR₁ × MR₂. A local L2 miss rate of 20% sounds bad but, after a 5% L1, means only 1% of accesses go to DRAM.

Worked example

Question. A 2 GHz processor has CPI_base = 1.2. The instruction cache misses on 2% of fetches and the data cache on 5% of data accesses; 30% of instructions are loads or stores.   2. Data stalls per instruction = 0.30 × 0.05 × 100 = 1.5 cycles.
  3. CPI_effective = 1.2 + 2.0 + 1.5 = 4.7. A perfect cache gives a speed-up of 4.7 ÷ 1.2 = 3.9 times: this processor spends three quarters of its time waiting for memory.
  4. (b) New L1 miss penalty = HT₂ + MR₂ × MP₂ = 10 + 0.20 × 100 = 30 cycles.
  5. Instruction stalls = 0.02 × 30 = 0.6; data stalls = 0.30 × 0.05 × 30 = 0.45.

Exam traps

  • Instruction misses happen on every instruction; data misses only on the fraction that are loads and stores. Forgetting the 0.30 multiplies data stalls by more than three.
  • The hit time is paid on every access, including misses, in AMAT = HT + MR × MP. Do not write HT × (1 − MR).
  • Local versus global L2 miss rate: the formula needs local; DRAM traffic is global = MR₁ × MR₂.
  • Keep cycles and nanoseconds apart; convert with the clock period (0.5 ns at 2 GHz) at the end.
  • Larger blocks do not always help: past a point the miss rate rises again because the cache holds fewer blocks.

6.5 Virtual memory, paging and TLB

Virtual memory lets every program believe it owns a large, private memory starting at address 0, while the physical DRAM is smaller and shared by many programs. The hardware and the operating system translate each virtual address into a physical address, page by page. Pages in use sit in DRAM; the rest wait on disk. The same mechanism protects programs from one another. A small cache of recent translations, the TLB, makes the translation almost free. This is the level of the hierarchy between main memory and disk.

You need: Chapter 6.1 (hierarchy), Chapter 6.3 (the TLB is a cache) and Unit 5, Exceptions in pipelined processors (a page fault is an exception).

Pages, frames and the page table

Virtual memory is cut into pages of P bytes (usually 4 KB = 2¹²) and physical memory into frames of the same size. With p = log₂P, a virtual address splits into a virtual page number (VPN, the high bits) and a p-bit offset. Translation replaces the VPN with a physical frame number (PFN); the offset is copied unchanged.

The map is the page table, one per process, kept in main memory and located by the page-table base register (PTBR). It has one page-table entry (PTE) per virtual page, indexed by the VPN. A PTE holds:

  • a valid bit (is the page in DRAM?) and the PFN;
  • a dirty bit (modified since loaded, so it must be written back to disk) and a reference bit (used recently, for replacement);
  • protection bits: read, write, execute, and user or kernel only.

A miss at this level, a page fault, costs millions of cycles because the page comes from disk. This one fact shapes the design: pages are large (to spread the cost), placement is fully associative (any page in any frame, to avoid conflict misses), writes are always write-back (via the dirty bit), and misses are handled in software by the operating system, which can afford a clever replacement choice.

Page faults and demand paging

In demand paging a page is loaded only when first touched. On a fault the hardware raises an exception; the OS finds the page on disk, picks a free frame (evicting a victim if needed, writing it back if dirty), reads the page in, sets the PTE valid and restarts the faulting instruction. When the pages a process needs constantly do not fit, it spends its time faulting; this is thrashing.

Faults must be very rare. With DRAM at 100 ns and a fault costing 8 ms, a fault rate of one in 100,000 accesses gives an average of about 100 + 10⁻⁵ × 8,000,000 = 180 ns: memory looks 80% slower.

Size of the page table

A 32-bit virtual address with 4 KB pages has a 20-bit VPN, so 2²⁰ PTEs; at 4 bytes each, the table is 4 MB per process, mostly describing pages never used. A two-level page table splits the VPN into 10 + 10 bits: the outer table points to inner tables, and an inner table exists only for regions in use. Hashed and inverted page tables are other answers to the same problem. The x86-64 architecture uses four levels for its 48-bit virtual addresses (9 + 9 + 9 + 9 bits and a 12-bit offset).

The TLB

With the page table in memory, every load would need two memory accesses: one for the PTE and one for the data. The translation lookaside buffer (TLB) is a small cache, typically fully or highly set-associative with tens to a few hundred entries, that holds recent VPN → PFN translations with their protection bits. Because of locality a TLB hits on almost every access. On a TLB miss the hardware (x86, ARM) or the OS (MIPS) walks the page table; if the PTE is valid the translation is copied into the TLB, otherwise a page fault follows. A TLB miss is not a page fault. On a process switch the TLB must be flushed, unless each entry is tagged with an address-space identifier (ASID).

With TLB lookup time t, memory access time m and TLB hit ratio h, and a one-level page table:

EAT = h × (t + m) + (1 − h) × (t + 2m)

A hypervisor runs several guest operating systems, each with its own page tables; modern processors add a second level of translation (guest-physical to host-physical) in hardware so that guests run at near full speed.

Worked example

Question. A machine has 32-bit virtual addresses, 1 GB of physical memory, 4 KB pages and 4-byte PTEs. (a) Find the offset, VPN and PFN widths, the number of PTEs and the page-table size.   1. (a) Offset = log₂4096 = 12 bits. VPN = 32 − 12 = 20 bits, so 2²⁰ = 1,048,576 PTEs. Physical address = log₂(2³⁰) = 30 bits, so PFN = 30 − 12 = 18 bits. Table size = 2²⁰ × 4 B = 4 MB.
  2. (b) The low 12 bits (three hex digits) are the offset: 0xA7C. The VPN is 0x00403. Replace it with 0x2B1F: physical address = 0x2B1F followed by A7C = 0x02B1FA7C.
  3. (c) EAT = 0.98 × (2 + 80) + 0.02 × (2 + 160) = 80.36 + 3.24 = 83.6 ns, only 4.5% above the 80 ns of a bare access; without a TLB every access would take 160 ns.
  4. (d) Outer table: 2¹⁰ entries × 4 B = 4 KB. Each inner table maps 1,024 pages × 4 KB = 4 MB, so 8 MB needs 2 inner tables of 4 KB. Total = 4 + 2 × 4 = 12 KB, against 4 MB for the flat table.

Exam traps

  • A TLB miss is not a page fault. A TLB miss with a valid PTE costs a memory access or two; a page fault costs milliseconds.
  • The number of PTEs depends on the virtual address space (2^VPN bits); the number of frames on the physical memory size. Do not mix them.
  • The offset is never translated; its width depends only on the page size.
  • On a TLB miss with a one-level table the EAT term is t + 2m, not t + m.
  • Each process has its own page table; the TLB entries of one process are invalid for another unless tagged with an ASID.

6.6 Secondary storage: magnetic disks, SSDs and RAID

Secondary storage is the bottom of the hierarchy: large, cheap, non-volatile, and far slower than DRAM. Two technologies dominate. The magnetic hard disk stores bits on spinning platters and is cheapest per terabyte; the solid-state drive (SSD) stores them in NAND flash and has no moving parts, so it answers in microseconds instead of milliseconds. RAID combines several drives so that the array is faster than one drive, survives the failure of one, or both. Your college's file server, the IRCTC booking database and your phone's photo storage all sit on these technologies.

You need: Chapter 6.2 (flash is EEPROM-family memory) and Chapter 6.5 (page faults read from disk).

Magnetic disks

A disk has one or more platters coated with magnetic material on both surfaces, fixed to a spindle that turns at constant speed (5,400, 7,200 or 15,000 rpm). Each surface is divided into concentric tracks, and each track into sectors, the smallest unit read or written (512 bytes in older drives, 4 KB in newer ones). One read/write head per surface rides on an arm; all arms move together, so the tracks under the heads at one moment form a cylinder. Outer tracks are longer, so modern drives put more sectors on them (zoned recording).

Reading a sector takes four steps, and the access time is their sum:

Access time = seek time + rotational latency + transfer time + controller overhead
Average rotational latency = ½ × (60 ÷ rpm) seconds
Transfer time = bytes to move ÷ transfer rate

Seek time moves the arm to the right track; rotational latency waits for the sector to come under the head, on average half a turn. Capacity = surfaces × tracks per surface × sectors per track × bytes per sector. Because seeks dominate, the operating system reorders pending requests to shorten arm travel: FCFS, SSTF (shortest seek first), SCAN (the elevator), C-SCAN and LOOK.

Solid-state drives

An SSD stores bits as charge in NAND flash cells (Chapter 6.2). A cell holds 1 bit (SLC), 2 (MLC), 3 (TLC) or 4 (QLC); more bits per cell means cheaper storage but slower writes and fewer program/erase cycles before the cell wears out. Flash has an awkward rule: data is written in pages (a few KB) but a page can be written only after its whole block (hundreds of pages) is erased. So the SSD controller runs a flash translation layer (FTL) that:

  • writes every update to a fresh page and remaps the logical address (out-of-place writes);
  • runs garbage collection: copies the live pages out of a mostly stale block, then erases it;
  • does wear levelling: spreads erases evenly so no block wears out early.

With no seek or rotation, an SSD reads a random 4 KB page in tens of microseconds. SATA links cap an SSD near 600 MB/s; NVMe drives on PCI Express reach several GB/s and accept thousands of commands in parallel queues (Chapter 6.7).

RAID

RAID, a redundant array of inexpensive (or independent) disks, spreads data across n drives. Striping puts consecutive blocks on different drives so they can be read in parallel; redundancy (mirrors or parity) lets the array rebuild a failed drive. Parity is the XOR of the data blocks in a stripe, so any one lost block equals the XOR of all the others.

6.7 I/O devices, interfaces and I/O protocols

Input/output (I/O) devices differ wildly: a keyboard sends a few bytes a second, an NVMe SSD several gigabytes. They also differ in data format, voltage and timing. The processor cannot handle each one specially, so every device sits behind an I/O interface (also called a controller or port) that looks to the processor like a few registers. The processor reads and writes those registers, and a bus protocol fixes the timing of each transfer. This chapter covers interfaces, how the processor addresses them, programmed I/O, and bus protocols; the next two chapters cover interrupts and DMA.

You need: Unit 1, Bus structures: data, address and control buses.

The I/O interface

An interface connects the system bus on one side and a device on the other. It contains:

  • a data register (or buffer) that holds the byte or word being transferred;
  • a status register with flags such as READY (data has arrived) or BUSY (device still working);
  • a control register where the processor sets modes, such as “enable interrupts”;
  • an address decoder that recognises the interface's addresses on the bus, and control logic;
  • on the device side, whatever conversion the device needs: parallel to serial, voltage levels, buffering.

The software that knows a device's registers is its device driver.

Programmed I/O

There are three ways to move data: programmed I/O, where the processor checks the status register in a loop (polling) and moves each word itself; interrupt-driven I/O, where the device tells the processor when it is ready (Chapter 6.8); and DMA, where a controller moves whole blocks (Chapter 6.9). In C, with a memory-mapped status register at address 0x4000 (bit 0 is READY) and a data register at 0x4004, reading one character by polling looks like this:

#define STATUS (*(volatile unsigned char *)0x4000)
#define DATA   (*(volatile unsigned char *)0x4004)

while ((STATUS & 0x01) == 0)
    ;              /* busy-wait until READY = 1 */
char c = DATA;     /* reading DATA also clears READY */

The keyword volatile tells the compiler that the value can change by itself, so it must read the register on every pass and not keep a copy. If the user types “A”, the loop spins until the key arrives and then c holds 0x41. Every pass of the loop is processor time spent waiting.

Bus protocols: synchronous and asynchronous

A synchronous bus has a common clock, and every transfer takes a fixed number of clock cycles. It is simple and fast, but every device must keep up with the clock (a slow one inserts wait states), and clock skew limits the bus length. An asynchronous bus has no clock; master and slave pace each other with handshake signals, so devices of any speed can share it. In a full handshake for an input transfer, the master puts the address and Read command on the bus and, after a short delay, raises Master-ready; the addressed slave puts the data on the bus and raises Slave-ready; the master latches the data and drops Master-ready, then removes the address; the slave, seeing Master-ready drop, removes the data and drops Slave-ready. Each edge answers the other side's edge, so no clock is needed.

6.8 Interrupts and interrupt handling

An interrupt is a signal from a device asking the processor for attention. Instead of checking the device again and again (polling), the processor runs its program and, when the signal comes, pauses at the end of the current instruction, runs a short interrupt service routine (ISR) for the device, and then resumes exactly where it stopped. It is the difference between checking the door every minute and waiting for the doorbell. Interrupts also drive the operating system's timer, report hardware errors and carry system calls.

You need: Chapter 6.7 (interfaces and polling) and Unit 5, Exceptions in pipelined processors.

What happens on an interrupt

  1. The device interface raises the interrupt-request line (INTR or IRQ) when it is ready, for example when a key arrives in its data register.
  2. The processor finishes the instruction it is executing. Interrupts are checked between instructions, never in the middle of one.
  3. If interrupts are enabled (the interrupt-enable flag in the processor status word, PSW) and this request is not masked, the processor accepts it and may send an acknowledge signal (INTA) to the device.
  4. It saves the program counter (PC, now pointing to the next instruction) and the PSW, usually on the stack, and disables further interrupts.
  5. It loads the PC with the ISR's address, often found through an interrupt vector (below).
  6. The ISR saves any registers it will use, services the device (reads the data, which also clears the request), and restores those registers.
  7. A return-from-interrupt instruction (IRET on x86) restores the PSW and PC, and the interrupted program continues as if nothing happened.

The time from the request to the first ISR instruction is the interrupt latency. Saving and restoring state is pure overhead, so ISRs are kept short.

Finding the source and setting priority

With many devices, the processor must learn which one interrupted and decide who goes first.

  • Polling the devices (software): one common ISR reads each interface's status register in a fixed order. Simple, but slow with many devices; the order sets the priority.
  • Vectored interrupts: the device (or a controller) sends a number, the vector, during acknowledge. The processor uses it to index a table of ISR addresses. On the 8086 the interrupt vector table holds 256 entries of 4 bytes (IP, then CS) from physical address 0, so type n's entry is at 4n.
  • Daisy chain: all devices share one request line, and the acknowledge signal passes from device to device; the first requesting device in the chain keeps it. Priority is fixed by position.
  • Priority interrupt controller: a chip such as the Intel 8259A takes 8 request lines, resolves priority, masks lines on request and supplies the vector. One master and eight slaves give 64 lines.

Interrupts can be masked (ignored for a while) by clearing the processor's enable flag, a device's enable bit or a bit in the controller's mask register. A non-maskable interrupt (NMI) cannot be masked and is kept for emergencies such as a power failure or a memory error. If an ISR re-enables interrupts, a higher-priority request can interrupt it: nested interrupts.

Interrupts, exceptions and traps

A hardware interrupt is asynchronous: it comes from outside and has nothing to do with the instruction running. An exception is synchronous: the instruction itself causes it, as with divide by zero, an illegal opcode or a page fault (Chapter 6.5). A trap or software interrupt is a deliberate instruction (INT 21h on the 8086, ecall on RISC-V) used for system calls. All three use the same save-state-and-jump mechanism. One difference matters: after an interrupt the program resumes at the next instruction, but after a page fault the faulting instruction is executed again.

Worked example

Question. (a) On an 8086, a device signals interrupt type 21h. Where is its vector, and if the four bytes there hold IP = 1234h and CS = A000h, where is the ISR? (b) A 2 GHz processor receives 50,000 network interrupts per second, each costing 1,000 cycles in total. What fraction of the processor do they use? (c) The 100 MB/s device of Chapter 6.7 interrupts once per 16 bytes at the same 1,000 cycles. Is interrupt-driven I/O enough? (8 marks)

  1. (a) Vector address = 4 × 21h = 84h. IP occupies 84h–85h and CS occupies 86h–87h.
  2. ISR physical address = CS × 16 + IP = A0000h + 1234h = A1234h.
  3. (b) Cycles per second = 50,000 × 1,000 = 5 × 10⁷. Fraction = 5 × 10⁷ ÷ 2 × 10⁹ = 2.5%.
  4. (c) Interrupts per second = 100 × 10⁶ ÷ 16 = 6.25 × 10⁶. Cycles = 6.25 × 10⁹ per second, which is 312% of a 2 GHz processor. No: interrupts remove the waiting of polling but not the per-word cost. Fast block devices need DMA (Chapter 6.9).

Exam traps

  • The processor accepts an interrupt only at the end of an instruction, and only if interrupts are enabled.
  • The 8086 vector for type n is at 4n, not n; and the ISR address is CS × 16 + IP, not CS + IP.
  • The ISR must clear the device's request (often by reading its data register); otherwise the same interrupt fires again on return.
  • Interrupts are asynchronous, exceptions synchronous. A page fault is an exception, not an I/O interrupt.
  • In a daisy chain, the device electrically nearest the processor has the highest priority.

6.9 Direct memory access (DMA)

Polling and interrupts both make the processor move every word itself, which is far too slow for disks, SSDs and network cards. Direct memory access hands the job to a DMA controller: the processor tells it where the data is, where it goes and how much, and the controller moves the whole block between the device and main memory over the system bus. The processor is involved only twice, once to set up the transfer and once to handle an interrupt when it is done. Every storage and network transfer in a modern computer uses DMA.

You need: Chapter 6.7 (interfaces, programmed I/O) and Chapter 6.8 (interrupts).

How a DMA transfer works

The DMA controller has, for each channel, a memory address register, a word count register, and a control/status register that holds the direction (read from or write to memory), the mode, an interrupt-enable bit and a done flag. Reading a disk block into memory goes like this:

  1. The processor writes the buffer's start address, the word count and the command (device to memory, interrupt when done) into the DMA controller, tells the disk controller which block to read, and goes back to other work.
  2. When the disk has a word ready it raises DMA request (DREQ). The DMA controller asks the processor for the bus with bus request (BR; HOLD on the 8085 and 8086).
  3. The processor finishes its current bus cycle, lets go of the bus lines and answers with bus grant (BG; HLDA on Intel chips). The DMA controller is now the bus master.
  4. The controller puts the memory address on the bus and signals DMA acknowledge (DACK) to the disk, which places the word on the data bus; memory writes it in one bus cycle.
  5. The controller increments the address and decrements the count, and repeats from step 2 (or continues, in burst mode).
  6. When the count reaches zero it releases the bus, sets its done flag and raises an interrupt. The ISR checks the status and starts the next transfer.

Transfer modes

  • Burst (block) mode: the controller keeps the bus until the whole block is moved. Fastest for the device, but the processor cannot reach memory meanwhile (it can still run from its cache).
  • Cycle stealing: the controller takes the bus for one word at a time and gives it back, so the processor is slowed slightly but never stopped for long. Each transfer “steals” a bus cycle.
  • Transparent (hidden) mode: the controller uses only cycles in which the processor is not using the bus. No slowdown at all, but the transfer is slowest and the logic more complex.

Bus arbitration

With several possible bus masters (processor, DMA channels, bus-mastering cards), an arbitration scheme decides who gets the bus next. In centralised arbitration one arbiter, often inside the processor, receives the request lines and passes bus grant along a daisy chain, so the device nearest the arbiter wins; a bus-busy (BBSY) line tells others the bus is taken. In distributed arbitration each device has an identity number; contenders place their IDs on shared arbitration lines and the highest ID wins, with no central arbiter.

The original IBM PC used the Intel 8237 DMA controller with four channels. Today most high-speed devices are their own bus masters: a network card or NVMe SSD reads a ring of descriptors in memory, each giving an address and a length, so one command can gather data from many scattered buffers (scatter-gather). Because DMA writes memory behind the processor's back, the cache may hold stale copies; hardware snooping or software flush and invalidate operations keep them coherent. An IOMMU translates and checks device addresses, as the MMU does for programs (Chapter 6.5).

Worked example

Question. (a) A 1 GHz processor serves a disk that transfers continuously at 200 MB/s in 4 KB blocks by DMA. Setting up each transfer costs 1,000 cycles and the completion interrupt 500 cycles. What fraction of the processor does the disk use? Compare with polling (Chapter 6.7). (b) A device delivers 4 MB/s as 32-bit words by cycle stealing, each steal taking one 50 ns bus cycle. What fraction of bus time is stolen, and how long would one 4 KB block hold the bus in burst mode? (8 marks)

  1. (a) Blocks per second = 200 × 10⁶ ÷ 4,096 = 48,828.
  2. Processor cycles per block = 1,000 + 500 = 1,500. Cycles per second = 48,828 × 1,500 = 7.32 × 10⁷.
  3. Fraction = 7.32 × 10⁷ ÷ 10⁹ = 7.3%. Polling the same disk in 16-byte units needed 250% of a processor of this speed; DMA makes the transfer possible and leaves over 92% of the processor free.
  4. (b) Words per second = 4 × 10⁶ ÷ 4 = 10⁶. Bus time stolen = 10⁶ × 50 ns = 0.05 s per second = 5% of bus time.
  5. Burst mode: 4,096 ÷ 4 = 1,024 words × 50 ns = 51.2 µs during which the processor cannot use the bus.

Exam traps

  • DMA does not remove the processor completely: it sets up each transfer and handles one interrupt per block, not per word.
  • The DMA controller uses the same system bus as the processor; in cycle stealing the processor waits only when it needs the bus at that moment.
  • Do not mix up the two handshakes: BR/BG (HOLD/HLDA) is between DMA controller and processor; DREQ/DACK is between DMA controller and device.
  • Burst mode is fastest for the transfer but blocks the processor longest; transparent mode never blocks it but is slowest.
  • Favourite question: “Compare programmed I/O, interrupt-driven I/O and DMA.” Answer with who moves each word and how many interrupts happen per block.

Takeaways

  1. A memory hierarchy gives nearly the speed of its top level at nearly the cost of its bottom level, because programs show temporal and spatial locality.
  2. SRAM (no refresh, six transistors) builds caches; DRAM (one transistor and a capacitor, refreshed) builds main memory; the ROM family, ending in flash, holds firmware and SSD data. ECC protects DRAM from soft errors.
  3. The mapping function fixes the address split: offset from the block size, index from the number of lines or sets, tag from the rest. Direct is 1-way; fully associative is one set.
  4. Judge a cache by AMAT and by CPI with memory stalls. Misses are compulsory, capacity or conflict; multilevel caches cut the miss penalty.
  5. Virtual memory maps virtual pages to physical frames through per-process page tables; the TLB caches translations. A TLB miss is cheap, a page fault costs milliseconds.
  6. Disk time is dominated by seek and rotation; SSDs avoid both but must erase whole blocks; RAID trades capacity for parallel speed and redundancy, and is not a backup.
  7. Devices appear as data, status and control registers, reached by memory-mapped or isolated I/O, over synchronous or handshaking buses.
  8. Polling, interrupts and DMA move progressively more work off the processor. Multiply events per second by cycles per event to see which method a device can afford.

Glossary

AMAT
Average memory access time: hit time + miss rate × miss penalty.
Associativity
The number of lines (ways) in a set where a block may be placed.
Block (line)
The fixed-size unit, often 64 bytes, moved between cache and main memory.
Bus master
A unit that currently controls the bus and starts transfers, such as the processor or a DMA controller.
Cycle stealing
A DMA mode that takes the bus for one word at a time, slowing the processor slightly.
Cylinder
The set of tracks under all the disk heads at one arm position.
Daisy chain
A priority scheme where a grant or acknowledge signal passes from device to device in order.
Demand paging
Loading a page into memory only when a program first touches it.
Dirty bit
A bit set when a cached block or a page has been modified and must be written back.
DMA
Direct memory access: a controller moves a block between device and memory without the processor.
DRAM
Dynamic RAM: one transistor and one capacitor per bit; dense, cheap, needs refresh.
ECC (SEC-DED)
Error-correcting code that corrects single-bit and detects double-bit errors.
EEPROM
Electrically erasable PROM: erased and rewritten byte by byte in the circuit.
EPROM
Erasable PROM: programmed electrically, erased as a whole by ultraviolet light.
Flash translation layer
SSD firmware that remaps writes, collects garbage and levels wear.
Hit ratio
The fraction of accesses found in the upper level.
Interrupt vector
A number that selects the ISR's address from a table.
ISR
Interrupt service routine: the code run in response to an interrupt.
Locality of reference
The tendency of programs to reuse recent items (temporal) and nearby items (spatial).
Memory-mapped I/O
Device registers placed in the memory address space and reached with loads and stores.
NMI
Non-maskable interrupt, which software cannot disable.
NUMA
Non-uniform memory access: memory latency depends on which socket's DRAM holds the data.
Page fault
An exception raised when a referenced page is not in main memory.
Page table
The per-process table that maps virtual page numbers to physical frame numbers.
PROM
Programmable ROM: written once by the user by blowing fuses.
RAID
Redundant array of inexpensive (independent) disks, using striping, mirroring or parity.
Rotational latency
Waiting time for the sector to rotate under the head; on average half a rotation.
SRAM
Static RAM: a six-transistor latch per bit; fast, needs no refresh, used for caches.
Thrashing
Constant page faulting because a process's active pages do not fit in memory.
TLB
Translation lookaside buffer: a small cache of recent virtual-to-physical translations.
