3.1 Signed and unsigned integer representation

A register holds n bits and nothing else. Whether the byte 1101 0011 means 211 or −45 is a convention shared by the programmer, the compiler and the hardware. The unsigned convention gives all 2ⁿ patterns to the numbers 0 to 2ⁿ − 1. The signed conventions split the patterns between negative and positive numbers. Every modern processor uses one of them, two's complement, because then a single adder works for both kinds of number. NITK lists this as "signed and unsigned integers"; SRM, IITD, IITB and NITK also call the wider topic "number systems".

You need: binary and hexadecimal place values from your digital logic course, and the idea of a register from Unit 1, Functional units of a computer.

Unsigned integers

An n-bit unsigned number bn−1 … b1 b0 has the value

V = b(n−1)·2^(n−1) + … + b1·2 + b0

Here bi is bit i (0 or 1) and 2i is its weight. The smallest value is 0 (all bits 0) and the largest is 2ⁿ − 1 (all bits 1). So 8 bits hold 0 to 255, 16 bits hold 0 to 65 535 and 32 bits hold 0 to 4 294 967 295. Memory addresses, pixel brightness values and character codes are unsigned. We write long patterns in hexadecimal, one hex digit per group of four bits: 1101 0011 is D3, written 0xD3.

Three ways to show a sign

Sign-magnitude. The leftmost bit (the most significant bit, MSB) is the sign: 0 for plus, 1 for minus. The other n − 1 bits hold the size. In 8 bits, +45 = 0010 1101 and −45 = 1010 1101. It has two zeros (0000 0000 and 1000 0000), and the adder must compare sizes before it can subtract. It survives in the significand of floating-point numbers (Chapter 3.7).

One's complement. A negative number is the positive pattern with every bit inverted: −45 = 1101 0010. It still has two zeros (0000 0000 and 1111 1111), and addition needs an "end-around carry" that feeds the carry out back into bit 0. It survives in the Internet checksum of IPv4 headers.

Two's complement. A negative number is the positive pattern inverted, plus 1: −45 = 1101 0010 + 1 = 1101 0011. There is one zero, and n bits hold −2n−1 to 2n−1 − 1, so 8 bits hold −128 to +127.

Why two's complement wins

The weight view. In two's complement the MSB has a negative weight, −2n−1; every other bit keeps its usual positive weight. So 1101 0011 = −128 + 64 + 16 + 2 + 1 = −128 + 83 = −45. A pattern is negative exactly when its MSB is 1, so the MSB is still called the sign bit.

The clock view. An n-bit adder throws away the carry out of the top bit, so it computes modulo 2ⁿ, like a clock face that has 2ⁿ hours. Two's complement stores −x as 2ⁿ − x: in 8 bits, −45 is stored as 256 − 45 = 211, which is 1101 0011. Adding 211 on this clock is the same as subtracting 45. That is why one adder serves both readings: the bits that come out are right whether you read them as unsigned or as signed, as long as the true answer fits in n bits. Figure 3.1.1 draws this clock for n = 4.

A quick way to negate. Copy the bits from the right up to and including the first 1, then invert all the bits to its left. For 0010 1101 the first 1 is bit 0, so keep that 1 and invert the rest: 1101 0011.

Sign extension. To widen a two's complement number, copy its sign bit into every new position. The 8-bit −45, 1101 0011, becomes the 16-bit 1111 1111 1101 0011 (0xFFD3), still −45. An unsigned number is widened with zeros instead (zero extension). Instruction sets give you both: MIPS and RISC-V have lb, which sign-extends a loaded byte, and lbu, which zero-extends it (see Unit 2, Memory locations, addresses and memory operations).

Excess (biased) notation. A fourth format stores V + bias as an unsigned number: with bias 127, −1 is stored as 126. IEEE 754 stores its exponent this way (Chapter 3.7).

Worked example

Question (6 marks). (a) Write −45 in 8-bit sign-magnitude, one's complement and two's complement. (b) A program reads the byte 1101 0011 from memory. What value does it hold as an unsigned byte and as a signed byte? (c) Sign-extend it to 16 bits and check the value. (d) State the range of 8-bit and 16-bit two's complement integers.

  1. Write +45 in binary: 45 = 32 + 8 + 4 + 1, so +45 = 0010 1101.
  2. Sign-magnitude: set the sign bit to 1, keep the magnitude: 1010 1101.
  3. One's complement: invert every bit of 0010 1101: 1101 0010.
  4. Two's complement: add 1 to the one's complement: 1101 0010 + 1 = 1101 0011 (0xD3).
  5. (b) Unsigned: 128 + 64 + 16 + 2 + 1 = 211. Signed: the MSB weighs −128, so −128 + 64 + 16 + 2 + 1 = −45. Check: 211 − 256 = −45.
  6. (c) Copy the sign bit 1 into the eight new bits: 1111 1111 1101 0011 = 0xFFD3. As unsigned it is 65 491, and 65 491 − 65 536 = −45, so the value is unchanged.
  7. (d) 8 bits: −2⁷ to 2⁷ − 1 = −128 to +127. 16 bits: −2¹⁵ to 2¹⁵ − 1 = −32 768 to +32 767.

Answer: −45 is 1010 1101 (SM), 1101 0010 (1's), 1101 0011 (2's); the byte 0xD3 is 211 unsigned and −45 signed; widened it is 0xFFD3.

Exam traps

  • Positive numbers are never inverted. "Find the two's complement representation of +45" is just 0010 1101.
  • The range is lopsided: 8 bits reach −128 but only +127. Negating 1000 0000 gives 1000 0000 again, which is why abs(INT_MIN) overflows in C.
  • Sign-magnitude and one's complement have two zeros, so their 8-bit range is −127 to +127, not −128 to +127.
  • Sign-extend signed values and zero-extend unsigned ones. Padding 1101 0011 with zeros gives 211, not −45.

Analyze Add the 4-bit two's complement patterns of +5 and −3 and explain, using arithmetic modulo 16, why no special sign logic is needed. 4 marks

0101 + 1101 = 1 0010; the adder drops the carry, leaving 0010 = +2. −3 is stored as 16 − 3 = 13, and 5 + 13 = 18 ≡ 2 (mod 16). Dropping the carry is exactly the "mod 16", so the plain unsigned adder gives the signed answer.

Analyze A C program tests if (-1 < sizeof(int)) and takes the false branch. Explain. 3 marks

sizeof gives an unsigned size_t. C converts −1 to that unsigned type, which gives the all-ones pattern, the largest value (2⁶⁴ − 1 on a 64-bit system). That is not less than 4, so the test is false. The bits never changed; only their reading did.

3.2 Addition and subtraction of signed numbers

Hardware adds two n-bit numbers one bit position at a time, with a full adder in each position passing its carry to the left. Because negative numbers are in two's complement, the same adder also subtracts: A − B = A + B̄ + 1, where B̄ is B with every bit inverted. One row of XOR gates and the carry-in turn the adder into an adder/subtractor. The one new problem is overflow, a true result that does not fit in n bits, which the hardware detects and reports in status flags. Anna Univ lists the parts as "Binary Adder", "Binary Parallel Adder" and "Subtractor"; NITT and NITK list "Addition and Subtraction" and "Arithmetic operations".

You need: two's complement and its range (Chapter 3.1), and XOR, AND and OR gates from your digital logic course.

Half adder, full adder and the ripple-carry adder

A half adder adds two bits a and b: the sum is s = a ⊕ b (⊕ is XOR) and the carry is c = a · b (AND). A full adder adds three bits, ai, bi and the incoming carry ci:

s(i)   = a(i) ⊕ b(i) ⊕ c(i)
c(i+1) = a(i)·b(i) + a(i)·c(i) + b(i)·c(i)

The sum is 1 when an odd number of inputs are 1; the carry out is 1 when at least two inputs are 1. Chain n full adders, the carry out of position i wired to the carry in of position i + 1, and you have an n-bit ripple-carry adder. Anna Univ calls it a "binary parallel adder" because all n bit pairs arrive at once. The sums do not finish at once, though: position i must wait for ci to arrive. With two gate delays per carry (one AND level, one OR level), cn is ready only after 2n gate delays, 64 delays for a 32-bit adder. Chapter 3.3 removes most of that wait.

One circuit that adds and subtracts

Subtraction needs no new hardware. In two's complement, −B = B̄ + 1, so

A − B = A + B̄ + 1

Put an XOR gate on each B input, with a control line M on its other input. When M = 0, Bi ⊕ 0 = Bi passes unchanged; when M = 1, Bi ⊕ 1 = B̄i is inverted. Wire M to the carry-in c0 as well, and the "+ 1" comes free. Figure 3.2.1 shows the 4-bit version.

Read as unsigned numbers, the same circuit computes A − B modulo 2ⁿ. The carry out then tells you about borrowing: cn = 1 means A ≥ B (no borrow) and cn = 0 means A < B (a borrow was needed).

Overflow and the status flags

Overflow means the true result lies outside −2n−1 to 2n−1 − 1, so the n result bits show a wrong value. Three equivalent tests:

  1. Adding numbers of opposite signs never overflows: the result lies between the two operands.
  2. Adding numbers of the same sign overflows exactly when the result has the other sign (two positives give a "negative", or two negatives give a "positive").
  3. In hardware: V = cn ⊕ cn−1, the carry into the sign position differs from the carry out of it.

For subtraction, apply the tests to A + (−B): A − B can overflow only when A and B have opposite signs. After every ALU operation the processor records four status flags: N (the sign bit of the result), Z (all result bits are 0), C (the carry out cn) and V (overflow). ARM and x86 keep them in a flags register for conditional branches (see Unit 2, Logical operations and instructions for making decisions). MIPS has no flags: its add raises an exception on overflow while addu ignores it. RISC-V has no flags either; software checks overflow with an extra compare.

Exam traps

  • Carry is not overflow. C is the out-of-range signal for unsigned numbers and V for signed ones; case (b) above has V = 1 with C = 0.
  • Check the signs first: two operands of opposite sign can never overflow, whatever the carries look like.
  • Subtracting without setting c0 = 1 gives A − B − 1, because inverting B alone gives the one's complement.
  • After a subtraction in this circuit, C = 1 means no borrow. ARM keeps that meaning; x86 stores the opposite, a borrow flag. Say which convention you use.
  • Sign-extend the narrower operand before adding numbers of different widths (an 8-bit and a 16-bit value).

3.3 Fast adders: carry lookahead addition

A ripple-carry adder is slow because each carry waits for the one before it: a 64-bit add would take 128 gate delays. A carry-lookahead adder (CLA) computes every carry directly from the input bits, in a small fixed number of gate levels, by asking two questions of each bit position: does it make a carry by itself, and would it pass on a carry that arrives? Anna Univ lists this as "Design of Fast Adder"; NITC, Manipal and Christ teach it too. Some form of lookahead sits in the adder of every processor's ALU.

You need: the full adder and the ripple-carry adder (Chapter 3.2).

Generate and propagate

For bit position i define two signals that depend only on ai and bi:

g(i) = a(i) · b(i)      generate: both bits are 1, so a carry leaves position i whatever comes in
p(i) = a(i) ⊕ b(i)      propagate: exactly one bit is 1, so an incoming carry passes straight through

Then the carry and sum of position i are

c(i+1) = g(i) + p(i)·c(i)
s(i)   = p(i) ⊕ c(i)

Some books define pi = ai + bi (OR). The carries come out the same, because when both bits are 1, gi = 1 already forces the carry; but the sum then needs its own XOR of ai, bi and ci.

Expanding the carries

Substitute each carry into the next, so that every carry depends only on the g's, the p's and c0:

c1 = g0 + p0·c0
c2 = g1 + p1·g0 + p1·p0·c0
c3 = g2 + p2·g1 + p2·p1·g0 + p2·p1·p0·c0
c4 = g3 + p3·g2 + p3·p2·g1 + p3·p2·p1·g0 + p3·p2·p1·p0·c0

Read c4 in words: a carry leaves the block if some bit generates one and every bit above it passes it on. Each equation is a sum of products, so it needs one level of AND gates and one OR gate. Counting gate delays from the moment a and b arrive: g and p take 1, all four carries take 1 + 2 = 3, and the sums need one more XOR, 4 in all. A 4-bit ripple adder needs 8 for c4. Figure 3.3.1 shows the block.

The cost is width: cn needs gates with n + 1 inputs, and real gates allow only about 4 or 5, so lookahead is built in 4-bit blocks.

Bigger adders: blocks and a second level

Rippling between blocks. Join 4-bit CLA blocks so that each block's c4 becomes the next block's c0. In a 16-bit adder, c4 is ready at 3 gate delays and each later block adds 2: c8 at 5, c12 at 7, c16 at 9. Inside the last block the carries need 2 more after c12, and the sum 1 more, so s15 is ready at 10.

A second level of lookahead. Let each block also output a group generate G and a group propagate P:

G = g3 + p3·g2 + p3·p2·g1 + p3·p2·p1·g0     the block makes a carry by itself
P = p3·p2·p1·p0                              the block passes an incoming carry through

A second lookahead unit, identical in form, treats the four blocks as four "bits": c16 = G3 + P3·G2 + P3·P2·G1 + P3·P2·P1·G0 + P3·P2·P1·P0·c0. G is ready at 3 gate delays (1 for g, 2 for the AND-OR) and P at 2, so c4, c8, c12 and c16 all appear at 3 + 2 = 5. The carries inside each block take 2 more (7) and the sums 1 more, so s15 is ready at 8. A third level does the same for four 16-bit groups.

Worked example

Question (8 marks). A 4-bit CLA adds A = 1011 and B = 0110 with c0 = 0. Find every gi, pi, carry and sum bit, check the result in decimal, and find the block's group G and P.

  1. Bits from position 3 down to 0: a = 1 0 1 1, b = 0 1 1 0.
  2. Generate gi = ai·bi: g3 = 0, g2 = 0, g1 = 1, g0 = 0.
  3. Propagate pi = ai ⊕ bi: p3 = 1, p2 = 1, p1 = 0, p0 = 1.
  4. c1 = g0 + p0·c0 = 0 + 1·0 = 0.
  5. c2 = g1 + p1·g0 + p1·p0·c0 = 1 + 0 + 0 = 1.
  6. c3 = g2 + p2·g1 + p2·p1·g0 + p2·p1·p0·c0 = 0 + 1·1 + 0 + 0 = 1.
  7. c4 = g3 + p3·g2 + p3·p2·g1 + p3·p2·p1·g0 + p3·p2·p1·p0·c0 = 0 + 0 + 1·1·1 + 0 + 0 = 1.
  8. Sums si = pi ⊕ ci: s0 = 1 ⊕ 0 = 1, s1 = 0 ⊕ 0 = 0, s2 = 1 ⊕ 1 = 0, s3 = 1 ⊕ 1 = 0.
  9. Result: c4 s3 s2 s1 s0 = 1 0001 = 17. Check: 11 + 6 = 17.
  10. Group signals: G = g3 + p3·g2 + p3·p2·g1 + p3·p2·p1·g0 = 0 + 0 + 1 + 0 = 1; P = p3·p2·p1·p0 = 1·1·0·1 = 0.

Answer: carries c1…c4 = 0, 1, 1, 1; sum 0001 with carry out 1 (17). G = 1 and P = 0: this block makes its own carry out (from bit 1, passed by bits 2 and 3) and would block a carry coming in, so c4 = 1 whatever c0 is.

Exam traps

  • The sum uses pi = ai ⊕ bi. If your book defines pi with OR, the carries are unchanged but si must still be ai ⊕ bi ⊕ ci.
  • Lookahead does not make the delay constant for every n. Fan-in limits force blocks, and the delay grows with the number of levels, about log₄ n.
  • Count gate delays from the arrival of a and b: 1 for g and p, then 2 for each AND-OR level, then 1 for the sum XOR.
  • A block's G is not just g3; it collects the generate terms of all four bits.
  • The favourite question: "Derive c4, draw the 4-bit CLA and compare its delay with a ripple-carry adder."

3.4 Multiplication of unsigned and signed numbers

Binary multiplication is the school method with a much smaller table: each multiplier bit is 0 or 1, so each partial product is either 0 or a shifted copy of the multiplicand. Hardware does it either step by step, with one adder and two shift registers (the sequential shift-and-add multiplier), or all at once, with a grid of AND gates and adders (the array multiplier). Two n-bit numbers give a 2n-bit product. Signed operands need extra care, and Chapter 3.5 gives the general method. Anna Univ lists this as "Multiplication of Signed and Unsigned Numbers", NITT as "Multiplication" and Manipal as "Multiplication of signed numbers".

You need: the n-bit adder (Chapter 3.2), sign extension (Chapter 3.1) and shift registers from your digital logic course.

Pencil and paper in binary

Multiply M = 1101 (13), the multiplicand, by Q = 1011 (11), the multiplier. Each bit qi of the multiplier selects either M shifted left by i places or 0:

            1 1 0 1      M = 13
          × 1 0 1 1      Q = 11
          ---------
            1 1 0 1      q0 = 1: M
          1 1 0 1        q1 = 1: M shifted 1
        0 0 0 0          q2 = 0: 0
      1 1 0 1            q3 = 1: M shifted 3
      -------------
    1 0 0 0 1 1 1 1      = 143

The product of an n-bit and an n-bit unsigned number can need 2n bits: 15 × 15 = 225 needs all 8.

The sequential shift-and-add multiplier

Figure 3.4.1 shows the hardware. Register M holds the multiplicand and register Q the multiplier. Register A, the accumulator, starts at 0 and builds the high half of the product; C is a one-bit flip-flop that catches the adder's carry out. The control sequencer runs n cycles:

  1. Set A ← 0, C ← 0 and count ← n.
  2. Look at q0, the rightmost bit of Q. If q0 = 1, the multiplexer passes M and C, A ← A + M. If q0 = 0, it passes 0 and A is unchanged.
  3. Shift C, A and Q right one place together: C enters the top of A, the bottom bit of A enters the top of Q, and the used multiplier bit falls out of Q.
  4. count ← count − 1. If count is not 0, go back to step 2.
  5. The 2n-bit product is in A (high half) and Q (low half).

Shifting the running sum right by one place each cycle has the same effect as shifting each new partial product left, and it keeps the adder only n bits wide. The cost is n clock cycles, each with one addition.

The array multiplier

An array multiplier does all n steps at once in combinational logic. Each partial-product bit mj·qi is one AND gate, so an n × n multiplier needs n² AND gates. The bits are arranged in shifted rows, as in the pencil method, and rows of adder cells add them column by column:

                     m3q0  m2q0  m1q0  m0q0
               m3q1  m2q1  m1q1  m0q1
         m3q2  m2q2  m1q2  m0q2
   m3q3  m2q3  m1q3  m0q3
p7  p6    p5    p4    p3    p2    p1    p0

With n − 1 rows of n adder cells, a 4 × 4 array uses 16 AND gates and 12 adder cells. It needs no clock cycles, but the worst-case path runs down the rows and along the last row, roughly 2n adder stages, and its size grows as n².

Signed operands

Negative multiplicand, positive multiplier. Sign-extend every partial product to the full 2n bits before adding. For (−5) × 3 with 4-bit operands, M = 1011 and Q = 0011:

  1111 1011     M sign-extended to 8 bits   (q0 = 1)
+ 1111 0110     M shifted 1, sign-extended (q1 = 1)
-----------
1 1111 0001     keep 8 bits: 1111 0001 = −15

Negative multiplier. The multiplier's sign bit has weight −2n−1 (Chapter 3.1), so its partial product must be subtracted, not added. For 3 × (−5), Q = 1011 = −8 + 2 + 1, and the product is 3·1 + 3·2 − 3·8 = 3 + 6 − 24 = −15. Another fix is to negate both operands when the multiplier is negative, which leaves the product unchanged. Booth's algorithm (Chapter 3.5) handles every sign case with one rule.

Multiplying the patterns as if they were unsigned gives the wrong answer: 1011 × 0011 = 11 × 3 = 33 = 0010 0001, not 1111 0001. Notice that the low four bits (0001) agree. The low n bits of a product are the same for signed and unsigned operands; only the high half differs. That is why RISC-V has a single mul for the low half but three instructions, mulh, mulhu and mulhsu, for the high half.

3.5 Booth's algorithm and fast multiplication

Booth's algorithm, published by Andrew Booth in 1951, multiplies two's complement numbers directly, with no sign fix-ups, by recoding the multiplier: a run of 1s is replaced by one subtraction at its right end and one addition just past its left end. Bit-pair recoding then halves the number of partial products, and carry-save adder trees add those partial products without waiting for carries. Together these are the "fast multiplication" of the syllabus. Anna Univ, NITK, NITC, Manipal and Christ teach this; Manipal also asks for the hardwired and microprogrammed control of a Booth multiplier.

You need: the sequential multiplier and the sign problem (Chapter 3.4), and two's complement subtraction (Chapter 3.2).

The idea: a run of 1s is a difference

The multiplier 0011 1100 (60) has a run of four 1s, but 0011 1100 = 0100 0000 − 0000 0100 = 64 − 4. So M × 60 = M × 64 − M × 4: one subtraction and one addition instead of four additions. In general a run of 1s from bit i up to bit j equals 2j+1 − 2i.

Booth's rule scans the multiplier from right to left, looking at each bit qi together with the bit to its right, qi−1 (with an imaginary q−1 = 0), and replaces qi by a recoded digit:

qi qi−1Recoded digitMeaningAction at step i
0 00inside a run of 0sshift only
0 1+1just past the end of a run of 1sadd M, then shift
1 0−1start of a run of 1ssubtract M, then shift
1 10inside a run of 1sshift only

So 0011 1100 recodes to 0 +1 0 0 0 −1 0 0. A negative multiplier is a pattern whose top run of 1s reaches the sign bit; its closing "+1" never comes, and that missing addition is exactly the −2n−1 weight of the sign bit. This is why Booth's method is correct for negative multipliers without any special case.

Booth's algorithm in hardware

The hardware is the multiplier of Chapter 3.4 with an adder/subtractor, no C flip-flop and one extra bit Q−1 to the right of Q. Figure 3.5.1 is the flowchart.

  1. A ← 0, Q−1 ← 0, M ← multiplicand, Q ← multiplier, count ← n.
  2. Examine Q0 Q−1. If 10, A ← A − M. If 01, A ← A + M. If 00 or 11, do nothing. Ignore any carry out of A.
  3. Arithmetic shift right A, Q and Q−1 together: the sign bit of A is copied into itself, A's bottom bit enters Q, and Q's bottom bit enters Q−1.
  4. count ← count − 1. Repeat from step 2 until count = 0. The 2n-bit product is in A and Q.

Control (Manipal's topic). Hardwired control turns this flowchart into a state machine with a counter; microprogrammed control stores each box as a microinstruction and the Q0 Q−1 test as a conditional branch (Unit 4, Hardwired control unit and Microprogrammed control unit and microinstructions).

Faster still: bit-pair recoding and carry-save trees

Bit-pair (radix-4) recoding. Take the multiplier bits two at a time and look at three bits, qi+1 qi qi−1, for i = 0, 2, 4 and so on. Each group becomes one digit from −2 to +2 with weight 4k:

000 → 0    001 → +1    010 → +1    011 → +2
100 → −2   101 → −1    110 → −1    111 →  0

Multiplying by ±2 is just a shift of ±M, so every digit is cheap, and an n-bit multiplier gives at most n/2 partial products instead of n.

Carry-save addition. A carry-save adder (CSA) is a row of full adders with no carry chain. It takes three numbers X, Y, Z and returns two: a sum vector S = X ⊕ Y ⊕ Z and a carry vector C (each bit is 1 when at least two of the three input bits are 1), with C worth one place more. Its delay is one full adder for any width. Check with X = 0101 (5), Y = 0011 (3), Z = 0110 (6): S = 0000 and C = 0111, shifted to 1110 (14); S + C = 14 = 5 + 3 + 6.

Wallace tree. Each level of CSAs turns k numbers into about 2k/3. For 32 partial products: 32 → 22 → 15 → 10 → 7 → 5 → 4 → 3 → 2, so 8 levels, followed by one fast carry-propagate adder (Chapter 3.3). With bit-pair recoding there are 16 partial products and only 6 levels (16 → 11 → 8 → 6 → 4 → 3 → 2).

3.6 Integer division: restoring and non-restoring methods

Hardware division is long division in binary. Shift the next dividend bit into a partial remainder, try subtracting the divisor, and write 1 in the quotient if it fitted or 0 if it did not. The restoring method undoes a failed subtraction at once by adding the divisor back. The non-restoring method skips the undo and makes up for it in the next step by adding instead of subtracting, so every step costs exactly one addition or subtraction. Anna Univ lists "Integer Division"; Christ lists "Integer division & its Hardware Implementation" and "Restoring and Non Restoring algorithms"; NITT and Manipal list "Division".

You need: two's complement subtraction (Chapter 3.2) and the shift-register layout of the multiplier (Chapter 3.4).

Long division in binary

Divide 11 (1011) by 4 (100). Bring down one dividend bit at a time; at each step the divisor either fits (quotient bit 1, subtract) or does not (quotient bit 0):

partial remainder 1     less than 100  → q = 0
partial remainder 10    less than 100  → q = 0
partial remainder 101   at least 100   → q = 1, remainder 101 − 100 = 1
partial remainder 11    less than 100  → q = 0
quotient 0010 = 2, remainder 11 = 3       check: 2 × 4 + 3 = 11

The result always satisfies dividend = quotient × divisor + remainder, with 0 ≤ remainder < divisor for unsigned numbers. Hardware cannot "see" whether the divisor fits, so it subtracts and looks at the sign of the result.

Restoring division

Register M holds the divisor and Q the dividend, which is replaced bit by bit with the quotient. Register A holds the partial remainder and starts at 0. A and M have n + 1 bits, one more than the operands, because after a shift the partial remainder can reach 2M − 1 and the extra sign bit shows whether a subtraction went negative.

  1. A ← 0, count ← n.
  2. Shift A and Q left one place together: the top bit of Q enters the bottom of A, and q0 is left empty.
  3. A ← A − M.
  4. If A is negative (sign bit 1), set q0 ← 0 and restore A ← A + M. Otherwise set q0 ← 1.
  5. count ← count − 1; repeat from step 2 until count = 0. The quotient is in Q and the remainder in A.

A failed step costs two operations, a subtraction and a restoring addition, so n-bit restoring division needs up to 2n additions and subtractions.

Non-restoring division

Look at what restoring does after a failed subtraction: it restores (A + M), then in the next cycle shifts and subtracts, giving 2(A + M) − M = 2A + M. So it is enough to leave A negative, and in the next cycle shift and add M. That is the whole idea:

  1. A ← 0, count ← n.
  2. If A ≥ 0: shift A and Q left, then A ← A − M. If A < 0: shift A and Q left, then A ← A + M.
  3. If the new A ≥ 0, set q0 ← 1; otherwise q0 ← 0.
  4. count ← count − 1; repeat from step 2 until count = 0.
  5. If A is negative at the end, A ← A + M. This corrects the remainder only; the quotient is already right.

Every cycle costs exactly one operation, plus at most one at the end: n + 1 in the worst case against 2n for restoring.

3.7 Floating-point representation: IEEE 754 standard

A 32-bit integer cannot hold 0.000 001 or 6 × 10²³. Floating point stores a number in binary scientific notation, as a sign, a significand and an exponent, so the same 32 bits reach from about 10⁻³⁸ to 10³⁸ with about 7 significant decimal digits. The IEEE 754 standard, first published in 1985 and revised in 2008 and 2019, fixes the exact layout and the special values, so a float means the same thing on every processor. IITB and NITK list this as "fixed and floating point representation", Manipal as "IEEE standard floating-point representation" and Anna Univ as "Floating Point Numbers".

You need: sign-magnitude and excess (biased) notation (Chapter 3.1), and converting decimal fractions to binary by repeated doubling.

Fixed point first

A fixed-point number puts the binary point at an agreed place. With 8 bits and 4 fraction bits, a format often called Q4.4, the pattern 0101 1000 means 0101.1000 = 4 + 1 + 0.5 = 5.5. The step between neighbours is 2⁻⁴ = 0.0625 and the two's complement range is −8 to 7.9375. Fixed point needs only integer hardware, so microcontrollers and signal processors use it widely. Its weakness is that range and precision are fixed together: the same format cannot hold both 0.001 and 1000.

Normalised binary scientific notation

Any non-zero binary number can be written as ±1.F × 2e, where F is the fraction after the binary point and e is the exponent. For example 6.75 = 110.11 in binary (6 = 110, and 0.75 = 0.5 + 0.25 = 0.11), which normalises to 1.1011 × 2². Because the digit before the point is always 1, IEEE 754 does not store it. This hidden bit gives one bit of precision for free.

value = (−1)^S × 1.F × 2^(E − bias)

where S is the sign bit (0 positive, 1 negative), F is the stored fraction and E is the stored exponent field, an unsigned number in excess notation. Figure 3.7.1 shows the two common formats.

Worked example

Question (8 marks). (a) Write −6.75 in IEEE 754 single precision, in binary and hex, and give its exponent in double precision. (b) Decode 0x41200000. (c) Show that 0.1 cannot be stored exactly.

  1. (a) Sign: the number is negative, so S = 1.
  2. Binary: 6 = 110 and 0.75 = 0.11 (0.75 × 2 = 1.5, digit 1; 0.5 × 2 = 1.0, digit 1), so 6.75 = 110.11.
  3. Normalise: 110.11 = 1.1011 × 2², so e = 2.
  4. Exponent field: E = 2 + 127 = 129 = 1000 0001.
  5. Fraction: drop the hidden 1, F = 1011 followed by nineteen 0s.
  6. Assemble and group in fours: 1 10000001 1011000…0 = 1100 0000 1101 1000 0000 0000 0000 0000 = 0xC0D80000. In double precision E = 2 + 1023 = 1025 = 100 0000 0001, giving 0xC01B000000000000.
  7. (b) 0x41200000 = 0100 0001 0010 0000 …: S = 0, E = 1000 0010 = 130, so e = 130 − 127 = 3; F = 01000…, so the significand is 1.01 (binary) = 1.25. Value = +1.25 × 2³ = 10.0.
  8. (c) Doubling 0.1 repeatedly gives digits 0.000110011001100… with "1100" repeating forever. Normalised, 1.10011001100… × 2⁻⁴, E = 123. The 23-bit fraction must be cut and rounded: the stored float is 0x3DCCCCCD = 0.100000001490116…, close but not equal to 0.1.

Answer: −6.75 = 0xC0D80000; 0x41200000 = 10.0; 0.1 has no finite binary form. This is why a bank or UPI ledger should keep money as whole paise in an integer, never as floating-point rupees.

Exam traps

  • The bias is 127 for single and 1023 for double: E = e + bias. A bias of 128 is a common slip.
  • The hidden 1 is not stored. For 1.1011 × 2², F = 1011…, not 11011….
  • E = 0 and E = 255 are reserved, so the largest normal true exponent is +127 and the smallest is −126, not −127.
  • The significand is sign-magnitude, not two's complement: negating a float flips only bit 31, and +0 and −0 both exist (they compare equal).
  • 0.1 + 0.2 is not exactly 0.3 in binary floating point, so never test floats with ==; compare with a tolerance.

3.8 Floating-point arithmetic operations

Floating-point arithmetic is built from the integer parts of this unit. A small integer adder handles the exponents; the circuits of Chapters 3.2 to 3.6 add, multiply or divide the significands; and two extra steps, normalising and rounding, put the result back into IEEE 754 form. Addition is the harder operation, because the two exponents must be made equal first. Anna Univ lists this as "Floating Point Numbers and Operations"; Manipal lists "Floating point arithmetic"; NITT and NITK cover it under floating point and arithmetic operations.

You need: the IEEE 754 format, the hidden bit and the bias (Chapter 3.7), and integer addition and multiplication (Chapters 3.2 and 3.4).

Addition and subtraction

Write each operand as its sign, its exponent field E and its significand 1.F, with the hidden 1 put back. Then:

  1. Compare exponents. d = EA − EB. The bias cancels in the difference, so the fields can be subtracted directly.
  2. Align. Shift the significand of the operand with the smaller exponent right by |d| places. The result takes the larger exponent. Bits shifted out are kept as guard, round and sticky bits (below).
  3. Add or subtract the significands. If the signs are equal, add. If they differ, subtract the smaller magnitude from the larger and give the result the sign of the larger.
  4. Normalise. If the sum is 2 or more (10.xxx), shift right one place and add 1 to the exponent. If it is below 1 (0.0…1xx), shift left until the leading bit is 1, subtracting 1 from the exponent per shift.
  5. Round to 23 fraction bits. If rounding carries all the way up (1.11…1 becomes 10.00…0), normalise again.
  6. Check the exponent. A field that reaches 255 is overflow (the result becomes ±∞); one that falls below 1 is underflow (the result becomes subnormal or 0).

Multiplication and division

Multiplication needs no alignment, so it is simpler:

  1. Sign: S = SA ⊕ SB.
  2. Exponent: E = EA + EB − 127. Both fields contain the bias, so one bias is subtracted.
  3. Significand: 1.FA × 1.FB, an unsigned 24-bit by 24-bit integer multiply (Chapters 3.4 and 3.5). The product lies between 1 and 4.
  4. Normalise (at most one right shift), round, and check the exponent for overflow and underflow.

Division mirrors it: S = SA ⊕ SB, E = EA − EB + 127, significand 1.FA ÷ 1.FB by the methods of Chapter 3.6 (the quotient lies between 0.5 and 2, so at most one left shift), then round. Dividing a non-zero number by zero gives ±∞; 0/0 gives NaN.

Guard, round and sticky bits; rounding modes

Bits that fall off the right during alignment or normalisation decide the rounding, so the hardware keeps three of them: the guard bit G (the first bit beyond the kept fraction), the round bit R (the second) and the sticky bit S (the OR of every bit after that). The default IEEE mode is round to nearest, ties to even: if G = 0, truncate; if G R S = 100, the value is exactly halfway, so round whichever way makes the last kept bit 0; otherwise round up. Worked example

Question (10 marks). In IEEE 754 single precision, compute (a) 9.75 + 0.5625 and (b) (−1.5) × 2.25. Show every step and give each result in hex.

(a) A = 9.75 = 1001.11 = 1.00111 × 2³, EA = 130 (0x411C0000). B = 0.5625 = 0.1001 = 1.001 × 2⁻¹, EB = 126 (0x3F100000).

  1. d = 130 − 126 = 4.
  2. Align B: 1.001 shifted right 4 places = 0.0001001, now × 2³.
  3. Add: 1.0011100 + 0.0001001 = 1.0100101.
  4. Normalise: already of the form 1.xxx, so E stays 130.
  5. Round: 7 fraction bits fit in 23, nothing is lost.
  6. Assemble: 0 10000010 0100101 followed by 16 zeros = 0x41250000. Check: 1.0100101 × 2³ = 1010.0101 = 10.3125 = 9.75 + 0.5625.

(b) A = −1.1 × 2⁰, EA = 127. B = 2.25 = 10.01 = 1.001 × 2¹, EB = 128.

  1. Sign: 1 ⊕ 0 = 1.
  2. Exponent: 127 + 128 − 127 = 128.
  3. Significands: 1.1 × 1.001 = 1.1011 (that is, 1.5 × 1.125 = 1.6875).
  4. Already normalised and exact.
  5. Assemble: 1 10000000 1011 followed by 19 zeros = 0xC0580000 = −1.6875 × 2 = −3.375. Check: −1.5 × 2.25 = −3.375.

Normalising after a subtraction. 1.5 − 1.375 = 1.100 × 2⁰ − 1.011 × 2⁰ = 0.001 × 2⁰. Shift left 3 places: 1.000 × 2⁻³ = 0.125, and the exponent field drops from 127 to 124.

Exam traps

  • Always shift the operand with the smaller exponent to the right. Shifting the larger one left pushes its leading bits out of the register.
  • Put the hidden 1 back before aligning or multiplying, and drop it again when you assemble the result.
  • In multiplication subtract the bias once: EA + EB − 127. Forgetting it doubles the bias; subtracting it twice removes it entirely.
  • Subtracting nearly equal numbers needs many left shifts. The zeros shifted in carry no information, which is why such results lose accuracy ("cancellation").
  • Floating-point addition is not associative. In double precision (10²⁰ − 10²⁰) + 3.14 = 3.14, but 10²⁰ + (−10²⁰ + 3.14) = 0, because doubles near 10²⁰ are 16 384 apart.

3.9 ALU design for arithmetic and logic operations

The arithmetic logic unit (ALU) is the combinational block that does a processor's integer work. It takes two operands and a few control bits and produces one result plus the status flags. It is built from parts you have already met: the adder/subtractor of Chapter 3.2 (made fast by Chapter 3.3), a few logic gates, and a multiplexer that picks which answer to pass out. Designers build it as a row of identical 1-bit slices. Unit 4 places this ALU in the datapath and generates its control bits. Anna Univ teaches it with "Multiplexers" and "Decoders"; Manipal and Christ title it "Arithmetic Logic Unit".

You need: the adder/subtractor and the status flags (Chapter 3.2), and multiplexers from your digital logic course.

The 1-bit ALU slice

Figure 3.9.1 shows one slice. Input b first passes a 2-to-1 multiplexer controlled by Binvert, which selects b or its inverse b̄. Then an AND gate, an OR gate and a full adder all work on a and the chosen b at the same time. A 4-to-1 multiplexer, steered by the 2-bit Operation code, passes one of their outputs to Result: 00 gives a AND b, 01 gives a OR b, 10 gives the adder's sum, and 11 passes the Less input (used for set-on-less-than, below). Inside, a 4-to-1 multiplexer is a 2-to-4 decoder driving AND and OR gates, which is where Anna Univ's multiplexers and decoders meet this unit.

From one bit to n bits

Place n slices side by side and connect the CarryOut of slice i to the CarryIn of slice i + 1. Tie Binvert of every slice and the CarryIn of slice 0 to one control line, often called Bnegate, so that a single bit turns "add" into "subtract". Three extras complete the ALU:

  • Zero flag: Z = NOR of all n result bits, so Z = 1 exactly when the result is 0. A branch-if-equal instruction subtracts and tests Z.
  • Overflow: the top slice computes V = CarryIn ⊕ CarryOut of its adder (Chapter 3.2).
  • Set on less than (slt): Result = 1 if a < b, else 0. The ALU computes a − b; the top slice's sign bit, corrected by overflow (sign ⊕ V), is wired to the Less input of slice 0, and every other slice gets Less = 0.

Adding an Ainvert line in front of input a gives NOR as well, since ā AND b̄ = NOT(a OR b). Shifts and subword parallelism

Shifts sit beside the ALU in a barrel shifter, which shifts by any amount in one step using log₂ n levels of 2-to-1 multiplexers: for 32 bits, five levels that shift by 1, 2, 4, 8 and 16 places or not at all. NITT also lists "subword parallelism" and x86's SSE and AVX extensions. Q = 0100; A < 0, so A + M = 00010. Quotient 4, remainder 2; restoring gives the same after 3 restoring additions. Check 4 × 3 + 2 = 14.

Apply 8. Represent 85.125 and −0.0625 in IEEE 754 single precision. 8 marks

85.125 = 1010101.001 = 1.010101001 × 2⁶: S = 0, E = 133 = 1000 0101, F = 010101001 0…: 0x42AA4000. −0.0625 = −1.0 × 2⁻⁴: S = 1, E = 123 = 0111 1011, F = 0: 0xBD800000.

Apply 9. Add 12.5 and −3.75 in IEEE 754 single precision, showing alignment, normalisation and the final bit pattern. 8 marks

12.5 = 1.1001 × 2³ (E = 130); −3.75 = −1.111 × 2¹ (E = 128). d = 2: 1.111 → 0.01111. Signs differ: 1.10010 − 0.01111 = 1.00011, already normalised, E = 130. Result 1.00011 × 2³ = 8.75 = 0x410C0000.

Analyze and evaluate

Analyze 10. Compare restoring and non-restoring division in number of operations, hardware and control. Which would you choose, and why? 8 marks

Same registers (A and M with n + 1 bits, Q) and adder/subtractor. Restoring: up to 2n operations, simple rule. Non-restoring: exactly n plus at most one correction, the add/subtract choice taken from the sign of A. Non-restoring is faster for the same hardware; its control is only slightly more complex. Mention that fast CPUs extend it (SRT).

Evaluate 11. A team needs a 32-bit multiplier for a low-power sensor chip and another for a server processor. Evaluate the sequential multiplier, the array multiplier and a radix-4 Booth multiplier with a Wallace tree for each. 12 marks

Sequential: one adder, 32 cycles, smallest area and power, fine for a sensor. Array: 1024 AND gates, about 992 adder cells, one long delay, large. Radix-4 Booth: 16 partial products; Wallace tree: 6 CSA levels plus a fast adder (Chapter 3.3), pipelined for one result per cycle, best for a server. Weigh area, power, latency and throughput; this spans Chapters 3.3 to 3.5.

Analyze 12. Explain how floating-point multiplication and addition reuse the integer hardware of this unit. Illustrate with (−1.5) × 2.25. 12 marks

Exponents use a small integer adder (Chapter 3.2): EA + EB − 127 = 128. Significands use the integer multiplier (3.4, 3.5): 1.1 × 1.001 = 1.1011. Sign by XOR. Normalising uses a shifter (3.9); rounding uses G, R, S bits and an incrementer. Result 0xC0580000 = −3.375. For addition: the alignment shifter, the significand adder/subtractor (3.2, 3.3) and a leading-zero count for normalising.

Analyze 13. Design a 32-bit ALU that performs AND, OR, add, subtract, set-on-less-than and NOR. Give the 1-bit slice, the control table, and explain zero detection and overflow. 12 marks

Slice as Figure 3.9.1 with Ainvert and Binvert; 32 slices with the carry chained; Bnegate drives Binvert and CarryIn of bit 0. Control 0000 AND, 0001 OR, 0010 add, 0110 sub, 0111 slt, 1100 NOR. Z = NOR of the 32 result bits; V = CarryIn ⊕ CarryOut of bit 31; slt takes sign ⊕ V into Less of bit 0. Note the ripple delay and the option of a CLA (Chapter 3.3).

Evaluate 14. "Floating point is always better than fixed point." Evaluate this claim with examples. 8 marks

For floating point: huge range, constant relative precision, standard behaviour (IEEE 754). Against: needs a larger, slower, more power-hungry unit; results are rounded (0.1 is inexact, addition is not associative); money must be exact. Fixed point suits microcontrollers, DSP filters and money in paise. Conclude that the choice depends on range, exactness and hardware budget.

Glossary

ALU
Arithmetic logic unit: the combinational block that performs integer arithmetic and logic operations selected by control bits.
Array multiplier
A combinational multiplier made of n² AND gates and rows of adder cells.
Barrel shifter
A shifter that moves a word by any amount in one step, using log₂ n levels of multiplexers.
Bias
The constant added to the true exponent before storing it (127 in single, 1023 in double precision).
Bit-pair recoding
Radix-4 Booth recoding: multiplier digits from −2 to +2, halving the partial products.
Booth's algorithm
A signed multiplication method that adds or subtracts the multiplicand only at the ends of runs of 1s in the multiplier.
Carry-lookahead adder
An adder that computes all carries directly from generate and propagate signals instead of letting them ripple.
Carry-save adder
A row of full adders without a carry chain that reduces three numbers to two.
Excess (biased) notation
Storing a signed value V as the unsigned number V + bias.
Full adder
A circuit that adds three bits and gives a sum bit and a carry bit.
Generate (g)
gi = aibi: bit position i produces a carry by itself.
Guard, round, sticky bits
Three extra bits kept beyond the fraction so that floating-point results are rounded correctly.
Hidden bit
The leading 1 of a normalised significand, which IEEE 754 does not store.
Machine epsilon
The gap between 1 and the next larger float: 2⁻²³ in single, 2⁻⁵² in double precision.
NaN
"Not a number": the result of an invalid operation such as 0/0, coded with an all-1s exponent and a non-zero fraction.
Non-restoring division
Division that, after a negative partial remainder, adds the divisor in the next step instead of restoring at once.
Normalisation
Shifting a significand so it has the form 1.F, adjusting the exponent to match.
One's complement
A signed format in which −x is x with every bit inverted.
Overflow
A result too large or too small for the format; for signed integers V = cn ⊕ cn−1.
Propagate (p)
pi = ai ⊕ bi: bit position i passes an incoming carry on.
Restoring division
Division that subtracts the divisor each step and adds it back when the result goes negative.
Ripple-carry adder
A chain of full adders in which each carry waits for the previous one.
Sign extension
Widening a two's complement number by copying its sign bit into the new high bits.
Sign-magnitude
A signed format with one sign bit followed by the magnitude.
Status flags
N, Z, C and V: negative, zero, carry and overflow, set by the ALU after an operation.
Subnormal number
A float with exponent field 0 and no hidden 1, filling the gap between 0 and the smallest normal number.
Subword parallelism
Using one wide adder as several narrow ones by cutting the carry at lane boundaries (SIMD).
Two's complement
The signed format in which −x is stored as 2ⁿ − x, found by inverting the bits and adding 1.
Wallace tree
A tree of carry-save adders that reduces many partial products to two in about log1.5 n levels.
