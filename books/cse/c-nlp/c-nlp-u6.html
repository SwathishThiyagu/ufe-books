6.1 Feedforward and convolutional networks for text

A text classifier does not have to read words one at a time. Two simple neural designs work well. The first flattens a document into one fixed vector — a TF-IDF row or the average of its word vectors — and pushes it through one or two dense layers to a softmax. The second keeps word order, embeds each token, and slides small one-dimensional filters over the token sequence, so each filter reacts to a short pattern such as "not good". Both train fast on small datasets and both are the baseline before recurrent or transformer models.

You need: TF-IDF feature vectors, word embeddings and softmax with cross-entropy from Unit 5, and tokenization from Unit 1.

Feedforward network on one fixed vector

The input is one vector x of length d, where d is the number of features of the whole document. Unit 5 builds it two ways: a TF-IDF row, whose numbers are weighted word counts, or the average of the word vectors of all tokens. Either way the sentence length disappears.

The vector goes through a hidden layer with k units, a weight matrix W₁ of shape k×d, and a bias vector b₁ of length k.

h = ReLU(W₁x + b₁)

x is the d×1 input feature vector, W₁ is the k×d hidden weight matrix, b₁ is the k×1 bias, ReLU(t) = max(0, t) keeps positive values and sets negatives to zero, and h is the k×1 hidden activation. tanh works as an alternative.

A second dense layer turns h into one score per class, and softmax turns the scores into probabilities that sum to 1.

p = softmax(W₂h + b₂), L = −Σ_c y_c log p_c

W₂ is the C×k output matrix for C classes, b₂ is the C×1 output bias, p_c is the predicted probability of class c, y_c is 1 for the true class and 0 for the others, and L is the cross-entropy loss for one document.

Dropout is the regularizer between layers. In training each hidden unit is set to zero with probability 0.5 and the rest are scaled by 1/(1 − 0.5) = 2. At test time dropout is off and the full network is used. It stops the classifier from depending on one lucky feature.

Why use it when logistic regression already classifies text? A linear model draws only a straight boundary in TF-IDF space. One hidden layer bends it, so "refund" together with "not received" can outvote either word alone. A common use is sorting UPI complaint tickets into fraud, delay and wrong-amount before a human reads them.

1D convolution over the token sequence

The convolutional model keeps the order. Each token t_i is replaced by its embedding e_i, a vector of d numbers looked up from the embedding matrix E from Unit 5. A sentence of n tokens becomes an n×d matrix.

A filter of width w covers w neighbouring tokens at a time, so w is the n-gram size. The filter has w·d weights and one bias b. Slide it from position 1 to position n−w+1 to get one score per position.

c_i = ReLU(W · x_{i:i+w−1} + b),  ĉ = max(c_1, …, c_{n−w+1})

x_{i:i+w−1} is the concatenation of the embeddings of tokens i to i+w−1, a column of w·d numbers; W is that filter's weight vector of length w·d; b is its bias; c_i is the filter's score at position i; ĉ is the max-pooled feature, one number per filter.

  1. Tokenize the sentence and look up one embedding per token, giving an n×d matrix.
  2. Choose filter widths 2, 3 and 4, with m filters of each width. Width 3 means a 3-gram detector.
  3. For every filter, slide over all positions, add the bias, apply ReLU. This gives one feature map per filter.
  4. Max-pool each feature map over positions. Every sentence now gives m numbers per width, whatever its length.
  5. Concatenate the pooled numbers, pass them through a dense layer, apply softmax, train with cross-entropy loss.

Where each design is used, and its limits

The 1D CNN is the standard small model for sentiment and sentence classification. A width-2 filter on a Hindi-English review learns that "nahi" next to "accha" flips the polarity, and max-pooling keeps that signal wherever the phrase sits.

Max-pooling runs over token positions, so a 20-token and a 5-token sentence give the same pooled vector size. That is why one classifier accepts reviews of any length. The cost is losing where the pattern was found: fine for sentiment, wrong when position matters.

A window of tokens around each word can also do token classification such as named entity recognition, one label per position. The CRF layer that fixes illegal label sequences stays in Unit 2.

Both designs read a bounded context: the feedforward net sees a bag of features, a CNN filter sees w tokens. Long-range dependencies need a state carried across the sentence, which is 6.2, or attention over all positions, which is 6.4.

Question. Classify the review "food was great" with 3-dimensional word vectors food = [1,0,1], was = [0,1,0], great = [1,1,0]. One filter has width 2 and weights w = [1,−1,0,0,1,−1] with bias b = 0. Compute the score at each window after ReLU, and the max-pooled feature.

Exam traps

  • Filter width is the n-gram size, not the number of filters. The filter count sets the pooled vector size.
  • Applying ReLU after max-pooling. The order is dot product, add bias, ReLU, then max-pool.
  • Max-pooling runs over token positions, not over filters. The pooled vector has one number per filter and is the same size for any sentence length.
  • Concatenating windows instead of embeddings: a width-2 filter takes 2·d numbers from two adjacent tokens, here 6.
  • Expecting the CNN to model long-range order. A width-2 filter only ever sees two adjacent tokens.

Analyze A feedforward classifier on averaged word vectors and a 1D CNN are trained on the same sentiment data. On which test sentence would the CNN most clearly win, and why? 4 marks

On "the food was not good". Averaging mixes "not" with "good", so the input vector looks positive. A width-2 filter on "not good" gives a strong negative score that max-pooling keeps.

Understand What does dropout do during training, and what changes at test time? 3 marks

In training each hidden unit is dropped with probability p, commonly 0.5, and the survivors are scaled by 1/(1−p). At test time nothing is dropped and nothing scaled; the full network is used.

Hidden layer: 100 × 5000 = 500000 weights plus 100 biases. Output layer: 3 × 100 = 300 weights plus 3 biases. Total = 500000 + 100 + 300 + 3 = 500403.

Max-pooling reduces each filter to exactly one number, so the pooled vector length equals the total number of filters, whatever their widths. Filter count sets the dense layer input size; width only fixes which n-gram size each filter sees.

6.2 RNN, LSTM and GRU sequence models

An RNN reads a sequence one word at a time. At each step it mixes the current word vector with a hidden state that carries earlier context, so the same word can get different predictions in different positions. The hidden state is updated by a tanh of a weighted sum, then an output layer makes a label or a next-word score. This idea powers part-of-speech tagging, named entity recognition, sentiment over a sentence and language modelling. LSTMs and GRUs add gates that decide what to keep, write and expose, which makes long-range context easier to learn.

You need: 6.1 for word vectors and softmax, and Unit 2 for sequence labeling with HMM and CRF, which this chapter compares with neural taggers.

The RNN cell and BPTT

A sequence is x1, ..., xT; each xt is a word vector of dimension d. The hidden state ht is a vector of dimension k. The vanilla RNN updates:

h<sub>t</sub> = tanh(W<sub>x</sub>x<sub>t</sub> + W<sub>h</sub>h<sub>t-1</sub> + b)

Wx maps d to k; Wh maps k to k; b is a k-vector; tanh is applied elementwise; h0 is a zero vector.

The output layer is yt = softmax(Wyht + by) for classification, or a linear score for regression. The same Wx, Wh, b are used at every step, so the model works for any sequence length.

Training uses backpropagation through time (BPTT). The network is unrolled over T steps, the loss at each step is added, and gradients flow backward through the chain of hidden states. Each step multiplies by a Jacobian that contains Wh and a tanh derivative. Many multiplications make gradients shrink to zero (vanishing) or grow without bound (exploding).

Gradient clipping fixes exploding gradients: if the global norm of the gradient vector is above a threshold, scale the whole vector down to that threshold. Vanishing gradients need gates, which the next section gives.

LSTM: cell state and gates

An LSTM adds a cell state ct that runs beside ht. Gates are sigmoid layers that output values from 0 to 1; 0 closes, 1 opens. The candidate is a tanh layer from -1 to 1.

f<sub>t</sub> = σ(W<sub>f</sub>[h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>f</sub>); i<sub>t</sub> = σ(W<sub>i</sub>[h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>i</sub>); c̃<sub>t</sub> = tanh(W<sub>c</sub>[h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>c</sub>); c<sub>t</sub> = f<sub>t</sub> ⊙ c<sub>t-1</sub> + i<sub>t</sub> ⊙ c̃<sub>t</sub>; o<sub>t</sub> = σ(W<sub>o</sub>[h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>o</sub>); h<sub>t</sub> = o<sub>t</sub> ⊙ tanh(c<sub>t</sub>)

σ is sigmoid; ⊙ is elementwise product; [h,x] is concatenation; W and b are learned; c̃t is the candidate.

The forget gate ft decides how much of the old cell ct-1 survives. The input gate it decides how much of the new candidate c̃t is written. The output gate ot decides how much of the cell is exposed as ht.

Because the cell state is updated by addition and elementwise multiplication, gradients can flow along a shorter path. A forget gate near 1 keeps information for many steps. This is why LSTMs handle longer dependencies than a vanilla RNN.

GRU, bidirectional and stacked RNNs

A GRU drops the separate cell state and uses two gates. The reset gate rt controls how much old hidden state enters the candidate. The update gate zt mixes the old hidden state with the candidate.

r<sub>t</sub> = σ(W<sub>r</sub>[h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>r</sub>); z<sub>t</sub> = σ(W<sub>z</sub>[h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>z</sub>); h̃<sub>t</sub> = tanh(W<sub>h</sub>[r<sub>t</sub> ⊙ h<sub>t-1</sub>, x<sub>t</sub>] + b<sub>h</sub>); h<sub>t</sub> = (1 - z<sub>t</sub>) ⊙ h<sub>t-1</sub> + z<sub>t</sub> ⊙ h̃<sub>t</sub>

rt and zt are sigmoid gates; h̃t is the candidate; ⊙ is elementwise product. A GRU has fewer parameters than an LSTM.

A bidirectional RNN runs one RNN left-to-right and another right-to-left. At position t it concatenates the two hidden states, so the tag for a word sees both left and right context. This is standard for POS tagging and NER. A stacked RNN stacks layers: the hidden sequence from layer 1 becomes the input to layer 2.

For sequence labeling, the output at each step is a tag from a tag set (see Unit 2 for tags and CRF training). For sentiment, the last hidden state or a pooled state feeds a classifier. For language modelling, yt gives the probability of the next word. The encoder side of 6.3 is an RNN of this kind.

Worked example

Question. A scalar RNN computes ht = tanh(0.5 ht-1 + xt) with h0 = 0. The inputs are x1 = 1, x2 = 0.5, x3 = -1. Find h1, h2, h3 to three decimal places.

  1. h1 = tanh(0.5 × 0 + 1) = tanh(1) = 0.7616, so h1 ≈ 0.762.
  2. Weighted sum for step 2 = 0.5 × 0.7616 + 0.5 = 0.8808. h2 = tanh(0.8808) = 0.7068, so h2 ≈ 0.707.
  3. Weighted sum for step 3 = 0.5 × 0.7068 - 1 = -0.6466. h3 = tanh(-0.6466) = -0.5695, so h3 ≈ -0.570.

Answer. h1 ≈ 0.762, h2 ≈ 0.707, h3 ≈ -0.570.

Exam traps

  • Gates use sigmoid and give values 0 to 1; the candidate uses tanh and gives -1 to 1. Swapping them is the usual error.
  • h0 is a zero vector, not x1. The first hidden state uses x1 plus h0.
  • BPTT multiplies many Jacobians. Repeated multiplication is why gradients vanish or explode; clipping addresses the explode side.
  • A forget gate value of 1 keeps the old cell; 0 drops it. Do not reverse the meaning.
  • A GRU has no separate cell state. Its update gate mixes old hidden state and candidate; it is not the same as the LSTM forget gate.

The backward pass needs future words. At generation time future words do not exist, so the backward hidden state cannot be computed. Bidirectional models are used when the whole sentence is available, as in tagging.

6.3 Encoder-decoder models, seq2seq and attention

A sequence-to-sequence model translates one sentence into another of a different length. An encoder RNN reads the source; a decoder RNN writes the target. In the plain version the encoder squeezes the whole source into one fixed vector, and long sentences suffer. Attention fixes this: at each output step the decoder weights every encoder state by relevance. The same idea runs translation, summarisation, dialogue and speech-to-text, and reappears in the transformer as cross-attention.

You need the recurrent, LSTM and GRU cell from 6.2, and word vectors from 5.6 for the first layer.

Seq2seq: an encoder reads, a decoder writes

Seq2seq uses two recurrent networks. The encoder reads the source, one token at a time; the decoder writes the target, one token at a time. The two sentences need not be the same length: a 12-word English sentence can become a 9-word Hindi one.

The encoder runs over source tokens x₁, x₂, …, xₙ and produces a hidden state at every step: h₁, h₂, …, hₙ. In the original design only the last state hₙ is kept. That single vector is the context vector c — the encoder's whole summary of the source.

The decoder is a second RNN. It starts from state s₀ = c, reads a start token ⟨s⟩, and predicts the first target word. That word is fed back as the next input, and so on until the model emits ⟨/s⟩ or hits a length limit. Each step is a softmax over the target vocabulary.

  1. Run the encoder over all source tokens and store h₁ … hₙ.
  2. Set the decoder's first state to the context vector and feed the start token.
  3. At step t, compute s_t from s_{t−1} and the previous target token y_{t−1}.
  4. Turn s_t into a score for every vocabulary word and pick one (argmax or beam search — see 6.6).
  5. Feed that word back as y_t and repeat until ⟨/s⟩.

During training the decoder is fed the gold previous token, not its own guess; this is teacher forcing. The loss is cross-entropy at every step against the gold next token, and gradients flow back through time across both networks. At test time no gold tokens exist, so the model feeds its own output back. It never practised recovering from its own errors; that mismatch is exposure bias.

The bottleneck, and how attention removes it

One fixed vector is a bottleneck: everything the decoder will ever know about the source must fit into, say, 256 numbers. On a long sentence early words are overwritten as the encoder keeps updating, and quality falls sharply with length.

Attention removes the bottleneck. The decoder keeps all n encoder states and, at each step, decides which source positions matter now. The decoder state s_t is scored against every encoder state hᵢ to give eᵢ; a softmax turns the scores into weights αᵢ that are positive and sum to 1; the context is their weighted average of the encoder states. The decoder combines that context with its own state and the previous token to predict the next word.

eᵢ = score(s_t, hᵢ),   αᵢ = exp(eᵢ) / Σⱼ exp(eⱼ),   c_t = Σᵢ αᵢ hᵢ

s_t is the decoder state at step t; hᵢ is encoder state i; eᵢ is the raw score for position i; αᵢ is the attention weight for position i (αᵢ ≥ 0 and Σᵢ αᵢ = 1); c_t is the context vector for step t, same dimension as hᵢ.

  1. Score the current decoder state against every encoder state.
  2. Softmax the scores into positive weights that sum to 1.
  3. Form the context c_t = Σᵢ αᵢ hᵢ, a weighted average of encoder states.
  4. Combine c_t with s_t and run the output layer to predict the next token.
  5. Repeat at every step; the weights change from step to step.

The weights are readable. A high αᵢ means the decoder is looking hard at source position i. Plotted as source position against target position, the weights often form a diagonal: the model learned word alignment without anyone labelling it.

Bahdanau, Luong, and padding masks

Bahdanau attention is additive: eᵢ = vᵀ tanh(W_a s_{t−1} + U_a hᵢ), where W_a and U_a are learned matrices and v is a learned vector. It is flexible and costs one matrix multiply per source position per step.

Luong attention is multiplicative: eᵢ = s_tᵀ hᵢ, or eᵢ = s_tᵀ W_a hᵢ with a learned matrix in between. The plain dot product is dot attention; the version with W_a is general attention. Both are cheaper than the additive form and work about as well. Transformers later parallelised scaled dot products; see 6.4.

Batches mix sentence lengths, so shorter sources are padded. Padded positions carry no information and must get weight zero. Before the softmax, set their score to −∞ — in code a large negative number such as −1e9. exp(−∞) = 0, so the padded weight becomes 0 and the real weights still sum to 1.

  • Forget the mask and the decoder wastes probability mass on pads; quality drops and the weights no longer sum to 1 over real words.
  • Attention is not only for translation: summarisation, dialogue and speech recognition use the same skeleton, and the same scores reappear inside the transformer as cross-attention.

Worked example

Question. Three encoder states are h₁ = [1, 0], h₂ = [0, 1], h₃ = [1, 1]. At decoding step t the decoder state scores them as e = [1, 2, 3]. Compute the attention weights α and the context vector c_t. (No padding, so no mask is needed.)

  1. Exponentiate each score: exp(1) = 2.718, exp(2) = 7.389, exp(3) = 20.086.
  2. Add them: 2.718 + 7.389 + 20.086 = 30.193, the softmax denominator.
  3. Divide: α₁ = 0.090, α₂ = 0.245, α₃ = 0.665. They sum to 1.000.
  4. First coordinate: 0.090 × 1 + 0.245 × 0 + 0.665 × 1 = 0.755.
  5. Second coordinate: 0.090 × 0 + 0.245 × 1 + 0.665 × 1 = 0.910.
  6. So c_t = [0.755, 0.910]. Position 3 dominates because exp grows fast: a score gap of 2 became a weight ratio of about 7.4.

Answer. α = [0.090, 0.245, 0.665] and the context vector is c_t = [0.755, 0.910].

Question. Same three states, but a mask now marks position 3 as a pad token. Recompute the weights and the context.

  1. Set e₃ = −1e9 before the softmax. exp(−1e9) = 0.
  2. New denominator: 2.718 + 7.389 + 0 = 10.108.
  3. α₁ = 0.269, α₂ = 0.731, α₃ = 0.
  4. First coordinate: 0.269 × 1 + 0.731 × 0 + 0 × 1 = 0.269.
  5. Second coordinate: 0.269 × 0 + 0.731 × 1 + 0 × 1 = 0.731.
  6. The pad state contributes nothing and the real weights again sum to 1.

Exam traps

  • Attention weights are a softmax over source positions: positive, summing to 1. They are weights, not encoder states, and not the context vector.
  • Teacher forcing is training time only. At test time the decoder consumes its own predictions, which is where exposure bias comes from.
  • Plain seq2seq keeps only the last encoder state. Attention keeps all of them and builds a fresh context at every step.
  • Forgetting the padding mask lets pad positions share the probability mass, so weights do not sum to 1 over real words.
  • Bahdanau is additive (tanh of a sum of projections); Luong is multiplicative (dot product). Swapping the names is a favourite slip.

Fixes: scheduled sampling (mix gold and predicted tokens as inputs), and beam search or a stronger attention so single errors are less likely; more data and longer training help too.

Luong uses a dot product (sᵀh or sᵀWh), one vector product per source position; Bahdanau needs a tanh over a projected sum, so more matrix work per position per step. Additive attention wins when encoder and decoder state sizes differ, or when the score needs a nonlinear shape a dot product cannot express.

Word alignment: target position j puts most weight on its corresponding source position. No alignment labels were used, so the grid is free evidence of what the model attends to and a quick way to spot errors.

6.4 Transformers, BERT and GPT

A transformer reads all tokens of a sentence at once. Self-attention lets each token look at every other token, so a word's vector depends on the whole sentence. This removes the step-by-step bottleneck of an RNN from 6.2. BERT and GPT are two large pretrained transformers. BERT reads both directions and is fine-tuned for classification or span tasks. GPT reads left to right and is fine-tuned or prompted to generate text. Search engines, mail filters, chatbots and translation tools use these models.

You need: attention from 6.3, softmax from 6.1, and word vectors from Unit 5.

Self-attention in parallel

Self-attention turns each token vector into three vectors: a query Q, a key K and a value V. A learned matrix makes each one from the input. The query asks what this token needs. The key says what each token offers. The value carries the content that is passed on. For n tokens, Q, K and V are n × dk matrices. dk is the query/key width.

Attention(Q, K, V) = softmax(QK<sup>T</sup> / √d<sub>k</sub>) V

Q is the query matrix, K is the key matrix, V is the value matrix, dk is the key width. QKT holds one dot-product score per token pair; softmax turns each row of scores into weights that sum to 1.

The score q·k measures how much one token should listen to another. The dot product grows with dk, so dividing by √dk keeps the softmax from saturating. The weights multiply V. Each output row is a weighted sum of all value rows. Every token is computed in parallel, so a GPU can process a whole batch of sentences.

One attention head learns one kind of relation. Multi-head attention runs h heads in parallel, each with its own learned projections. The h outputs are concatenated and projected back to the model width. A head may track subject-verb links; another may track nearby words. The model learns these roles; they are not hand-coded.

Self-attention has no sense of order. Token 1 and token 5 get the same treatment if their vectors are the same. A positional encoding fixes this. It is a vector added to each token embedding. The original transformer uses fixed sine and cosine waves of different frequencies. Learned position vectors are also common. Addition, not concatenation, is the standard.

Encoder and decoder blocks

An encoder block has two sublayers. The first is multi-head self-attention. The second is a feed-forward network applied to each position separately. Each sublayer has a residual connection and layer normalisation: output = LayerNorm(x + Sublayer(x)). The residual lets gradients flow through deep stacks. Layer norm keeps activations stable. The feed-forward part is usually two dense layers with a ReLU or GELU between them; it expands the width by about 4× and projects back.

A decoder block adds two changes. First, masked self-attention stops a position from seeing future tokens. The upper triangle of the score matrix is set to −∞ before softmax, so those weights become 0. Second, cross-attention takes queries from the decoder and keys and values from the encoder output. This is the same attention idea as 6.3, now inside each layer.

A stack of 6 to 12 such blocks is normal. Encoder-only stacks produce contextual vectors. Decoder-only stacks produce the next-token distribution. Encoder-decoder stacks are used for translation and summarisation; see 6.6.

BERT, GPT and fine-tuning

BERT is an encoder-only transformer. It is pretrained on unlabelled text with masked language modelling. About 15 percent of tokens are chosen; 80 percent of those become [MASK], 10 percent become a random token and 10 percent stay unchanged. The model predicts the original token from both sides. A second objective, next-sentence prediction, asks whether sentence B follows sentence A. Special tokens mark the input: [CLS] at the start and [SEP] between sentences. The final [CLS] vector is used for classification. Unlike Word2Vec or FastText, a BERT vector for “bank” changes with the sentence.

Fine-tuning adds a small task head. For sentiment, a dense layer maps the [CLS] vector to positive or negative. For question answering, two vectors score the start and end of an answer span; see 6.7. The whole BERT stack is updated with a small learning rate. This is cheaper than pretraining from scratch.

GPT is a decoder-only transformer. It uses a causal mask and is trained to predict the next token at every position. The loss is the negative log-likelihood of the true next token. After pretraining, GPT can be fine-tuned on a labelled task or used by prompting. It generates text one token at a time; decoding is covered in 6.5. RoBERTa is a BERT variant trained longer without next-sentence prediction; DistilBERT is a smaller, faster BERT.

Worked example

Question. One query attends over two keys with dk = 2. q₁ = [1,0], k₁ = [1,0], k₂ = [0,1], v₁ = [1,1], v₂ = [0,1]. Compute the attention output.

  1. Scores: q₁·k₁ = 1×1 + 0×0 = 1. q₁·k₂ = 1×0 + 0×1 = 0. The score row is [1, 0].
  2. Scale by √dk = √2 = 1.414: [1/1.414, 0/1.414] = [0.707, 0].
  3. Softmax: exp(0.707) = 2.028, exp(0) = 1. The sum is 2.028 + 1 = 3.028.
  4. Weights: w₁ = 2.028/3.028 = 0.670, w₂ = 1/3.028 = 0.330. They sum to 1.000.
  5. Output = w₁v₁ + w₂v₂ = 0.670×[1,1] + 0.330×[0,1] = [0.670, 0.670] + [0, 0.330] = [0.670, 1.000].

Answer. The attention output is [0.670, 1.000], with weights [0.670, 0.330].

Exam traps

  • BERT is encoder-only and GPT is decoder-only. BERT cannot generate left to right.
  • The scale √dk is applied inside the softmax, to the scores, not to the final output.
  • Positional encodings are added to token embeddings, not concatenated.
  • Masked self-attention belongs to the decoder. An encoder uses unmasked self-attention.
  • Next-sentence prediction is a BERT pretraining objective, not a GPT objective.

6.5 Large language models and language generation

A large language model is a decoder-only transformer trained on a very large text corpus to predict the next token. Scaling parameters, data and compute gives a general generator that can answer, summarise, translate and write code from a prompt. It produces text one token at a time, and a decoding rule chooses each token from the model's probability distribution. Chat assistants, code helpers and voice assistants use this loop.

You need: 6.4 for the transformer decoder and self-attention, and 6.3 for the encoder-decoder view of generation.

Size, tokens and pretraining

A model's size is its number of parameters, the learned weights. Large language models have billions. Three quantities scale together: parameters, training tokens and compute. Scaling behaviour means training loss falls smoothly as each grows, so builders scale all three.

A token is a piece of text, not always a word. Byte-pair encoding (BPE) starts from characters and repeatedly merges the most frequent adjacent pair. Common words become one token; rare words split into subword pieces. This keeps the vocabulary finite and handles new words.

Pretraining uses a decoder-only transformer from 6.4. The task is next-token prediction: given x₁ to xₜ₋₁, predict xₜ. A causal mask stops a position seeing later tokens. No human labels are needed because the next token is the label.

L = −Σₜ log P(xₜ | x₁, …, xₜ₋₁)

L is the training loss; xₜ is the token at position t; P is the model's probability for the true next token.

History runs from word vectors (Unit 5) to RNNs (6.2) to transformers, then to scaled chat models such as GPT-3, GPT-4 and Llama. Some are closed, some have open weights.

Prompts, in-context learning and instruction tuning

A prompt is the text handed to the model: an instruction, context, examples or all three. Prompting works because pretraining teaches continuation patterns. In-context learning means the model picks up a task from examples inside the prompt without changing weights. Zero-shot gives no example; one-shot gives one; few-shot gives a few. Two labelled sentiment reviews, for example, can set the format for a third.

Instruction tuning fine-tunes the pretrained model on instruction-response pairs. It changes behaviour: the model learns to follow requests. It does not change the tokenizer or add new facts to the weights. Reinforcement learning from human feedback (RLHF) goes further: people rank outputs, a reward model learns the ranking, and reinforcement learning adjusts the model.

A chatbot wraps this generator in a dialogue loop and keeps recent turns as context. A voice assistant adds speech recognition and synthesis; see Unit 7.

Decoding and evaluation

At each step the transformer outputs a logit zᵢ for every token i in the vocabulary. Softmax turns logits into probabilities. Temperature T divides the logits first.

pᵢ = exp(zᵢ / T) ÷ Σⱼ exp(zⱼ / T)

pᵢ is the probability of token i; zᵢ is its logit; T is the temperature, a positive number; the sum runs over all vocabulary tokens.

T > 1 flattens the distribution: probability spreads toward unlikely tokens, so output is more random. T < 1 sharpens it: the largest logit dominates, so output is more repetitive. T = 1 leaves the softmax unchanged. T → 0 approaches greedy decoding, and T = 0 is not a valid division. Greedy picks the highest-probability token. Beam search keeps B best partial sequences and scores them by summed log probability. Sampling draws from p. top-k keeps the k highest tokens and renormalises. top-p keeps the smallest set whose cumulative probability reaches p and renormalises; it adapts to flat or sharp distributions.

Low temperature and top-p reduce wild output, but do not remove hallucination: fluent text that is false. Greedy decoding often repeats phrases.

Perplexity is PP = exp(−(1/N) Σ ln p(wₜ)), where N is the number of tokens and p(wₜ) is the probability the model gave the true token. Lower is better, and values compare only under the same tokenizer. Task accuracy uses exact match or F1. Translation uses BLEU (6.6). Human preference compares two outputs side by side.

Worked example

Question. A next-token step gives logits [2.0, 1.0, 0.5, −1.0] for four tokens A, B, C, D. Decode with temperature T = 0.5, then keep the top 2 tokens. Find the four probabilities after temperature and the two probabilities after top-2 renormalisation.

  1. Divide each logit by T = 0.5: [4.0, 2.0, 1.0, −2.0].
  2. Exponentiate each value: [54.598, 7.389, 2.718, 0.135].
  3. Sum the exponentials: 54.598 + 7.389 + 2.718 + 0.135 = 64.840.
  4. Normalise: [54.598/64.840, 7.389/64.840, 2.718/64.840, 0.135/64.840] = [0.842, 0.114, 0.042, 0.002].
  5. Top-2 keeps 0.842 and 0.114. Their sum is 0.956. Renormalise: 0.842/0.956 = 0.881 and 0.114/0.956 = 0.119.

Answer. After T = 0.5 the probabilities are [0.842, 0.114, 0.042, 0.002]; after top-2 they are [0.881, 0.119].

Exam traps

  • Temperature divides logits before softmax. T = 0 means greedy decoding, not a legal division.
  • top-k keeps exactly k tokens; top-p keeps the smallest set whose cumulative probability reaches p. They are not the same rule.
  • Instruction tuning changes behaviour, not the tokenizer and not the facts stored in the weights.
  • Perplexity is per-token and lower is better; it is not task accuracy and is comparable only under the same tokenizer.
  • Beam search returns a high-probability sequence, not a guaranteed correct or factual one.

6.6 Machine translation

Machine translation takes a sentence in a source language and produces a sentence with the same meaning in a target language. It exists because people need to read, trade and study across languages, from a Hindi news item translated to English to a Tamil customer message answered in Hindi. Modern systems learn from parallel sentences, split words into subword pieces, and use an encoder-decoder transformer. Quality is checked by comparing the output with reference translations, most often with BLEU. This chapter covers the pipeline, the training and decoding steps, and the BLEU calculation.

You need: 6.3 and 6.4 for seq2seq, attention and transformers; Unit 1 for tokenization; Unit 2 for n-gram counting.

Three generations of translation

Machine translation (MT) maps a source sentence x = (x1, ..., xm) in one language to a target sentence y = (y1, ..., yn) in another. The lengths m and n can differ, and word order can change. A parallel corpus is a set of sentence pairs that say the same thing in two languages; it is the fuel for learning translation.

Rule-based MT analyses the source, transfers structure, and generates the target. It is predictable but expensive to build for each language pair. Statistical MT learns from parallel corpora. IBM alignment models estimate word alignments, phrase pairs go into a phrase table, and a decoder combines phrases with a target language model. Neural MT replaced phrase tables with an encoder-decoder network: the encoder reads the source, the decoder writes the target, and attention links them. The transformer from 6.4 made this parallel and strong.

Subwords, training and decoding

A word-level vocabulary misses rare names and inflected forms. Subword tokenization splits text into pieces learned by byte-pair encoding (BPE) or word pieces. A frequent word stays one piece; a rare word becomes known pieces. This gives an open vocabulary and shorter, shared units across languages.

Training uses teacher forcing: at each target position t, the decoder is given the correct previous target tokens, and the model predicts the next token. The loss is cross-entropy on target tokens.

L = −(1/T) Σ<sub>t=1</sub><sup>T</sup> log P(y<sub>t</sub> | y<sub>1</sub>, ..., y<sub>t−1</sub>, x)

T is the number of target tokens; yt is the correct target token at position t; y1 ... yt−1 is the target prefix; x is the source sentence; P is the model probability.

At test time the correct prefix is unknown. Greedy decoding takes the most likely token each step. Beam search keeps the k best partial hypotheses, where k is the beam width, and returns the highest-scoring complete sentence. It is a search, not a proof of the best sentence. Multilingual models share one model across many languages, and low-resource pairs can use a pivot language through a high-resource middle language; see 6.8 for cross-lingual retrieval.

BLEU: clipped precision and brevity

BLEU compares a candidate translation with one or more reference translations. It asks how many candidate n-grams occur in the references, with clipping: a candidate n-gram is counted at most as many times as it appears in a reference. This stops a system from repeating one correct word to get a high score.

p<sub>n</sub> = Σ<sub>g</sub> min(count<sub>c</sub>(g), max<sub>ref</sub> count<sub>r</sub>(g)) ÷ Σ<sub>g</sub> count<sub>c</sub>(g)

pn is clipped n-gram precision; g runs over candidate n-grams of length n; countc(g) is the count in the candidate; maxref countr(g) is the largest count in any one reference.

BLEU also has a brevity penalty (BP), because precision alone rewards very short outputs. Let c be candidate length and r the reference length. The final score for N n-gram orders uses a geometric mean. The geometric mean punishes any order with pn = 0. chrF compares character n-grams and is kinder to morphology; human evaluation remains the final judge.

BP = 1 if c ≥ r; BP = exp(1 − r/c) if c < r. BLEU = BP × exp(Σ<sub>n=1</sub><sup>N</sup> (1/N) log p<sub>n</sub>)

BP is the brevity penalty; c is candidate length in tokens; r is reference length in tokens; N is the largest n-gram order (N = 2 for BLEU-2); pn is clipped n-gram precision.

Worked example

Question. Compute BLEU-2 for the candidate translation “the cat sat on the mat” against the reference “the cat is on the mat”. Show clipped unigram and bigram counts, p1, p2, BP and the final score.

  1. Tokenize both sentences. Candidate length c = 6 tokens; reference length r = 6 tokens.
  2. Candidate unigrams: the×2, cat×1, sat×1, on×1, mat×1. Reference unigrams: the×2, cat×1, is×1, on×1, mat×1.
  3. Clip unigram counts: the min(2,2)=2; cat=1; on=1; mat=1; sat=0. Total matched unigrams = 5 of 6, so p1 = 5 ÷ 6 = 0.833333.
  4. Candidate bigrams: (the,cat), (cat,sat), (sat,on), (on,the), (the,mat). Reference bigrams: (the,cat), (cat,is), (is,on), (on,the), (the,mat).
  5. Clipped bigram matches: (the,cat), (on,the), (the,mat) = 3 of 5, so p2 = 3 ÷ 5 = 0.6.
  6. c = 6 and r = 6, so c ≥ r and BP = 1.
  7. BLEU-2 = BP × (p1 × p2)1/2 = 1 × (0.833333 × 0.6)1/2 = 0.707107.

Answer. BLEU-2 = 0.707107 (dimensionless).

Exam traps

  • BLEU is precision-only, not recall. It checks candidate n-grams against references, so a candidate can miss meaning and still score if its counted n-grams are correct.
  • Clipping is mandatory. Without clipping, a candidate repeating “the” could match a reference with one “the” and get p1 = 1; clipping limits the match to the reference count.
  • The brevity penalty is below 1 only when the candidate is shorter than the reference (c < r). If c = r or c > r, BP = 1.
  • For corpus BLEU, add clipped counts and totals over the whole corpus first, then compute pn, BP and the geometric mean. Do not average sentence BLEU scores.
  • BLEU-2 uses both unigram and bigram precision. It is not just bigram precision; a zero in either order makes the geometric mean zero.

6.7 Question answering and textual entailment

Two tasks in this chapter look different and share one shape. Question answering takes a question and a passage and returns an answer — either a span copied from the passage or a sentence a model writes. Textual entailment takes a premise and a hypothesis and returns one label: entailment, contradiction or neutral. Both feed two texts into a single encoder and read a decision off the joint representation. Search engines, bank chatbots, helpline desks and fact-checking tools use them. This chapter gives the pipeline, the labels, and the two numbers that score question answering.

You need: BERT fine-tuning and the [CLS] vector from 6.4, and named entity recognition for entity-type answers from Unit 2.

Two texts in, one decision out

Question answering and textual entailment are both sentence-pair tasks. One text is the question or the premise; the second is the passage or the hypothesis. The model reads both and produces a small output — a span, a generated sentence, or one label out of three.

The recipe is the one from 6.4. Join the two texts into one sequence with a separator token between them. Run the encoder. Read the decision from the joint representation — either the [CLS] vector at the front or the per-token vectors of the second text.

Sharing one encoder is why these two tasks are taught together. The engineering is the same work every time: tokenise a pair, pad to one length, fine-tune, evaluate. Only the output head and the label set change.

Question answering: find, or generate

A factoid question wants a short answer: a name, a date, a number. "Who wrote the national anthem of India?" wants a person. If you know the expected answer type in advance, named entity recognition from Unit 2 can filter candidate answers.

In open-domain QA no passage is supplied. The system runs in two stages — retrieval, then reading. The retriever ranks passages from a large collection against the question (see 6.8). The reader then looks inside the top few passages only.

In reading comprehension the passage is given and the answer is usually a span copied out of it. SQuAD is the standard benchmark of this kind: people wrote questions against Wikipedia paragraphs and marked the answer as a character range inside the paragraph.

Generative QA drops the span constraint. A large language model from 6.5 writes the answer in its own words, and those words may appear nowhere in the passage.

The extractive reader: score a start and an end

An extractive reader treats the answer as a pair of positions in the passage. For every passage token the model produces a start logit and an end logit.

P_start(i) = softmax over passage tokens of (w<sub>s</sub> · h<sub>i</sub>)

hi is the encoder output vector at passage token i; ws is a learned weight vector; the softmax runs across all passage tokens; P_end(j) uses a second vector we in the same way.

Training puts cross-entropy on the gold start index and on the gold end index. At test time you pick the pair (i, j) with i ≤ j that maximises P_start(i) × P_end(j). The tokens from i to j, joined back into a string, are the answer.

Two numbers score that string. Exact match (EM) compares normalised strings and gives 1 or 0. F1 compares tokens and gives partial credit.

F1 = 2 × P × R ÷ (P + R)

P = overlap ÷ number of predicted tokens; R = overlap ÷ number of gold tokens; overlap is the number of token positions the two answers share; EM = 1 only when the normalised strings are identical, else 0.

Textual entailment: which way does support flow?

Textual entailment, also called natural language inference (NLI), takes a premise and a hypothesis and asks whether a reader who accepts the premise must accept the hypothesis.

There are three labels. Entailment: the hypothesis follows from the premise. Contradiction: the hypothesis cannot be true when the premise is true. Neutral: neither — the premise leaves the question open. SNLI pairs image captions with written hypotheses; MultiNLI does the same with text from several genres.

The model is a sentence-pair classifier. Feed premise and hypothesis through BERT and put a three-way softmax on the [CLS] vector. Stronger designs add cross-attention, so each hypothesis word attends over the premise words and the comparison happens word by word.

Direction matters. The premise entails the hypothesis, not the reverse. "A dog is barking" entails "an animal is making a noise"; the second does not entail the first. Some syllabi call the topic text entailment; the labels are the same.

Worked example

Question. A reading-comprehension system returns the span the cat. The gold answer is cat. After normalisation (lower case, punctuation stripped), compute exact match and token-level F1, showing precision and recall.

  1. Tokenise both strings. Gold: [cat] → 1 token. Predicted: [the, cat] → 2 tokens.
  2. Find the overlap of token positions: the token cat appears in both, so overlap = 1.
  3. Check exact match: the strings 'the cat' and 'cat' are not identical, so EM = 0.
  4. Precision P = overlap ÷ predicted tokens = 1 ÷ 2 = 0.5.
  5. Recall R = overlap ÷ gold tokens = 1 ÷ 1 = 1.0.
  6. F1 = 2 × P × R ÷ (P + R) = 2 × 0.5 × 1.0 ÷ 1.5 = 1.0 ÷ 1.5 = 0.667.

Output

0
0.667

Answer. EM = 0 and F1 = 0.667, so the system gets no exact-match credit but about two-thirds of the token credit.

Exam traps

  • EM is 1 only when the normalised strings match exactly; F1 gives partial credit for shared tokens. A system with F1 near 0.8 can still have a much lower EM. Report both and never call either one 'accuracy'.
  • Entailment is one-directional. Read the arrow from premise to hypothesis. 'A dog is barking' entails 'an animal is making a noise', but the reverse fails, and the reverse pair is not a contradiction either.
  • Neutral is not contradiction. If the premise does not entail the hypothesis, the pair may still be perfectly consistent. 'A man is playing guitar' and 'A man is playing a musical instrument' are compatible, so the label is entailment, not neutral; pick neutral only when the premise genuinely leaves it open.
  • In extractive QA the answer must be a span of the passage: the start index is at or before the end index, both lie inside the passage tokens, and neither is in the question. A model that points into the question has learned the wrong thing.
  • A generative QA model can answer with words that never occur in the passage. EM and F1 then compare strings, so a correct paraphrase may score 0 EM. Use a human or model-based judgement for generative answers.

6.8 Information retrieval and cross-lingual retrieval

A search box takes a few words and returns documents that answer them. An information retrieval system indexes a fixed collection, scores each document against the query and puts the best first. Cross-lingual retrieval does the same when the query is in one language and the documents in another, for example a Tamil query over an English news archive. Web search, library catalogues and question answering all run on this machinery.

You need: TF-IDF and text features from Unit 5, Text Classification and Word Embeddings; tokenization and stemming from Unit 1, Foundations; and 6.4 for BERT and mBERT sentence vectors.

Boolean retrieval and the inverted index

Boolean retrieval is the oldest design: query terms joined by AND, OR and NOT, and every document either matches or does not. Each document passes through an analyzer that tokenizes, lowercases, removes stop words and stems. The query must use the same analyzer, or a query term can fail to match the stored form of the same word.

  1. Tokenize, normalize and stem each document.
  2. Collect the terms into a dictionary of unique terms.
  3. For each term, append the document id to its postings list, keeping ids sorted.
  4. Store term frequency with each posting so scoring needs no second pass.

The index is inverted: each term points to a sorted postings list of the documents containing it. For neural AND network, merge-intersect the two sorted lists; the cost is proportional to the postings examined, |L1| + |L2|. Skip pointers cut this further. A forward index (document → its terms) would force a scan of every document for every query.

Boolean matching returns an unordered set: a document with both query terms and one with a single term are equally matching. Ranking by a relevance score fixes this.

Scoring with TF-IDF and BM25

Term frequency tf(t,d) is the number of times term t occurs in document d. Inverse document frequency is idf(t) = log₁₀(N ÷ df(t)), where N is the number of documents and df(t) the number containing t. A rare term gets a large idf; a term in every document gets idf = 0 and adds nothing.

score(q,d) = Σ<sub>t ∈ q</sub> tf(t,d) × idf(t)

q is the query, d a document, t a query term, tf(t,d) the count of t in d, idf(t) = log₁₀(N ÷ df(t)), N the number of documents, df(t) the number of documents containing t.

Two flaws remain. Term frequency grows without limit, so a document that repeats a term wins. Long documents contain more terms by accident. BM25 saturates the term frequency and normalizes for length.

score(q,d) = Σ<sub>t ∈ q</sub> idf(t) × [ tf(t,d) × (k₁ + 1) ] ÷ [ tf(t,d) + k₁ × (1 − b + b × |d| ÷ avgdl) ]

k₁ (typically 1.2 to 2.0) controls how fast extra occurrences stop helping; b (0.75 is standard) controls length normalization; |d| is the length of d in tokens and avgdl the mean document length.

With b = 0 length is ignored; with b = 1 it is applied fully. BM25 is the standard lexical baseline and is still hard to beat on keyword-heavy queries and exact names.

Measuring retrieval quality

Evaluation needs judged documents: assessors mark which documents are relevant for each query, and scores are computed against those judgements.

  • Precision@k: relevant documents among the top k, divided by k. Of what I showed, how much was right?
  • Recall: relevant documents retrieved, divided by all judged relevant documents. Of what existed, how much did I show?
  • Mean average precision (MAP): for each query, take the precision at the rank of every retrieved relevant document, add them, divide by the number of judged relevant documents for that query (including ones never retrieved), then average over queries.
  • Mean reciprocal rank (MRR): mean of 1 ÷ rank of the first relevant document. Suits tasks with one right answer.
  • NDCG: DCG = Σᵢ relᵢ ÷ log₂(1 + i) over positions i = 1, 2, …, where relᵢ is the graded relevance at position i; NDCG = DCG ÷ the DCG of the ideal ordering of the same documents.

Precision and recall pull against each other. One correct document at rank 1 gives precision@1 = 1 while recall may be 0.1. Report both, and always state k.

Dense retrieval and cross-lingual retrieval

Dense retrieval replaces term matching with vectors. A bi-encoder encodes the query and the document independently, with no cross-attention between them, so every document vector can be precomputed offline (see 6.4). Relevance is the cosine similarity cos(q,d) = (q·d) ÷ (|q| × |d|): 1 for parallel vectors, 0 for perpendicular vectors, −1 for opposite vectors.

Document vectors are stored in an index. At query time an approximate nearest-neighbour search — a graph such as HNSW, or inverted lists with IVF — returns the top k in milliseconds, trading a little recall for speed. Dense retrieval catches paraphrase; lexical retrieval catches exact names and codes. Many systems run both and merge the lists.

Cross-lingual information retrieval (CLIR) is retrieval when the query and the documents are in different languages, for example a Tamil query over an English archive. Four standard routes exist.

  • Query translation: translate the query into the document language, then run monolingual retrieval. Cheap, but the translated query is short and error-prone.
  • Document translation: translate the whole collection offline. Expensive once, but the query stays in the user's own words.
  • Pivot language: with no direct translator, go query → English → document language; errors from two translations accumulate.
  • Multilingual embeddings: mBERT or XLM-R place many languages in one vector space, so query and document vectors compare directly with no translation step (see 6.6).

Translated queries are ambiguous: one Tamil word may map to several English words, and a name may be transliterated differently each time. Adding all translation candidates raises recall and adds noise. Score CLIR against a monolingual system on the same judged queries; the gap is the real cost of crossing languages.

Question. A collection has three documents: d1 = neural network model, d2 = neural machine translation, d3 = cricket match. The query is q = neural network. Using idf(t) = log₁₀(N ÷ df(t)) with N = 3 and raw term frequency, compute the TF-IDF score of each document and give the ranking.

Question. A query has 4 judged relevant documents, at ranks 1, 3, 4 and 8 of the returned list. The list is evaluated in full. Compute recall and average precision for this query.

Exam traps

  • IDF is zero for a term in every document, so that term adds nothing to the score. Students often keep giving it weight.
  • Precision and recall must be reported together with k. A system with precision@1 = 1 can have very low recall.
  • df(t) counts documents; tf(t,d) counts occurrences inside one document.
  • In BM25, b = 0 removes length normalization and b = 1 applies it fully; b is not a threshold and k₁ is not the number of documents.
  • In CLIR, a translated query may change meaning. Without a monolingual baseline on the same judged queries you cannot tell whether translation or retrieval caused the loss.

Takeaways

  1. A text classifier only needs a fixed-size vector, but a 1D convolution can learn which local word patterns matter instead of treating the vector as a bag.
  2. A recurrent network is the simplest way to make word order matter, because the hidden state is a running summary of everything read so far.
  3. Gates in LSTM and GRU let the network keep useful information for many steps and drop the rest, which fights the vanishing gradient.
  4. Attention removes the bottleneck of squeezing a whole sentence into one vector, and it is the idea that made transformers possible.
  5. Self-attention compares every position with every other position in parallel, which is why transformers train faster on GPUs than RNNs.
  6. Pretraining on unlabelled text teaches general language; fine-tuning on a few thousand labelled examples adapts it to the actual task.
  7. A decoder-only large language model is just a next-token predictor; the decoding rule decides whether the output is safe and repetitive or creative and risky.
  8. BLEU compares surface n-grams, so it rewards overlap with references and can miss a correct paraphrase.
  9. Question answering and textual entailment are both sentence-pair classification once the text is tokenised into one joint input.
  10. Retrieval and generation are usually combined: find the right documents first, then let the model read them, instead of trusting its memory.

Splitting rare words into frequent pieces so the model can handle unseen words, as in byte-pair encoding.
Temperature
A number that divides the logits before softmax; low values make output focused, high values make it random.
Token
The unit of text a model reads, usually a word or a subword piece produced by a tokeniser.
Token probability distribution
The softmax output over the vocabulary at one decoding step, from which the next token is chosen.
Vanishing gradient
The shrinking of gradients as they are backpropagated through many steps, which stops early layers from learning.
Word2vec
A method that learns word vectors by predicting a word from its neighbours, or its neighbours from the word.
