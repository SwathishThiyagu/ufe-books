5.1 Text features: bag of words and TF-IDF

A classifier cannot read raw text; it needs numbers. Text features turn each document into a vector over a fixed vocabulary. The bag-of-words model counts term occurrences and ignores order. TF-IDF multiplies each term frequency by a weight that is high for rare terms and low for common ones. These vectors feed spam filters, review classifiers and search ranking. The job is to build the vocabulary, compute counts and TF-IDF, and read the matrix that classifiers consume.

You need: Unit 1, tokenization and normalization — splitting text into terms and lowercasing them.

Vocabulary and the bag of words

The first step is a fixed vocabulary V. Tokenize each document, normalize case, optionally remove stop words and apply stemming. Collect every distinct term; each term gets a column. Build the vocabulary from training data only. Terms in test documents that are outside V are ignored or mapped to an unknown token. This keeps the vector size fixed and prevents information leakage.

In bag of words, document d becomes a vector c(d). The entry c(t,d) is the number of times term t occurs in d. Word order is lost, hence the name bag. Two documents with the same words in different order get the same vector. For topic and spam tasks this loss is often acceptable.

c(t,d) = number of occurrences of term t in document d

c(t,d) is the raw count; t is a vocabulary term; d is a document.

  • Binary bag of words sets c(t,d) = 1 if count > 0, else 0. Use it when presence matters more than repetition.
  • n-gram features use phrases such as not good or character trigrams. They capture local order. Keep n small, usually 1 to 3, to control vocabulary size.
  • Document length |d| is the total number of term occurrences after tokenization. For D1 = cricket bat ball, |d| = 3.

TF-IDF: term frequency and inverse document frequency

Raw counts over-weight long documents and common words such as the. TF-IDF fixes both. Term frequency is tf(t,d) = count(t,d) ÷ |d|. It is the share of document d taken by term t. Inverse document frequency is idf(t) = log₁₀(N ÷ df(t)). N is the number of documents. df(t) is the number of documents that contain t. A term in every document gets idf = log₁₀(1) = 0. The weight is w(t,d) = tf(t,d) × idf(t).

w(t,d) = (count(t,d) ÷ |d|) × log₁₀(N ÷ df(t))

w(t,d) is the TF-IDF weight; count(t,d) is raw occurrences; |d| is total terms in d; N is number of documents; df(t) is document frequency of t. Log base 10 is common; base e or 2 changes scale, not ranking.

df counts documents, not total occurrences. If cricket appears five times in D1 and once in D2, df(cricket) = 2. Adding new documents changes df and idf for every term. Recompute the weights when the corpus changes. A term absent from d gets weight 0. The document-term matrix has rows for documents and columns for terms. It is sparse: most cells are zero. These vectors go to classifiers in 5.2.

Variants, smoothing and normalization

Real corpora need small fixes. Add-one smoothing replaces N by N + 1 and df(t) by df(t) + 1 in the idf ratio. It keeps idf finite when df(t) is 0 or very small. It does not remove the zero weight of a term that appears in every document: if df(t) = N, then (N + 1) ÷ (N + 1) = 1 and log₁₀(1) = 0. Libraries add 1 to the whole idf, idf(t) = log₁₀((N + 1) ÷ (df(t) + 1)) + 1, so even an everywhere-term keeps a small non-zero weight. Sublinear (logarithmic) tf uses tf = 1 + log(count) instead of count ÷ |d|. A saturating tf uses tf = count ÷ (count + k), with k around 1; it caps the count without a logarithm. L2 normalization divides each document vector by √(Σ w²) so long documents do not dominate. These variants preserve relative term importance.

idf(t) = log₁₀((N + 1) ÷ (df(t) + 1)) + 1

N is number of documents; df(t) is number of documents containing t. The +1 outside is a common library convention; it keeps a small non-zero weight when df(t) = N. Without the outside +1, a term in every document has idf = log₁₀(1) = 0.

  • Add-one smoothing: idf = log((N + 1) ÷ (df + 1)). It stays finite for df = 0 or small df, but still gives 0 when df = N.
  • Sublinear (logarithmic) tf: tf = 1 + log(count) when count > 0.
  • Saturating tf: tf = count ÷ (count + k), with k around 1. It caps the count without a logarithm.
  • L2 normalization: w ← w ÷ √(Σ w²) over terms in the document.

Some syllabi call this term weighting or the vector space model. The output is a document-term matrix: rows are documents, columns are terms, cells are weights. In code, scikit-learn TfidfVectorizer does this, with smooth_idf and sublinear_tf options. For dense word vectors, see 5.5.

Exam traps

  • Using raw counts as TF-IDF. The tf part must be normalized by |d| in this definition, and then multiplied by idf.
  • Counting df as total occurrences. df(t) is the number of documents containing t, not the number of times t appears.
  • Forgetting that idf changes when documents are added. A weight computed on a small corpus is not valid on a larger one.
  • Treating a term in every document as important. Its idf is zero, so its TF-IDF weight is zero.
  • Building the vocabulary separately on training and test sets. The columns must match; unseen test terms need an unknown token or must be dropped.

5.2 Text classification with Naive Bayes, logistic regression, SVM

Text classification maps a document to a label such as spam or not spam. The document first becomes a feature vector, usually word counts or TF-IDF weights. A supervised classifier then learns from labelled examples how those features point to each label. Naive Bayes learns class-conditional word probabilities, logistic regression learns weights for a probability, and a linear SVM learns a separating margin. These methods are fast, need little memory, and run well on a phone. They are used for spam filtering, support-ticket routing, review sentiment and news topic tagging.

You need 5.1, where text becomes a feature vector of counts or TF-IDF weights.

Multinomial Naive Bayes counts words

A bag-of-words vector gives term counts. Multinomial Naive Bayes treats each term in the document as evidence for a class. It asks: which class c makes this document d most likely? The model uses Bayes rule and assumes terms are independent once the class is known.

P(c|d) ∝ P(c) ∏t∈d P(t|c)

P(c|d) is the posterior score for class c given document d; P(c) is the prior, the fraction of training documents in class c; P(t|c) is the smoothed probability of term t in class c; the product runs over terms t in d.

P(t|c) = (count(t, c) + 1) / (count(c) + |V|)

count(t,c) is how many times term t occurs in class c; count(c) is the total number of term occurrences in class c; |V| is the vocabulary size; add-one puts 1 in the numerator and |V| in the denominator.

  1. Count term occurrences per class and the class priors.
  2. For every term and class, apply add-one smoothing.
  3. Multiply the prior by the smoothed probabilities of terms in the test document.
  4. Take the class with the largest score.
  • Without smoothing an unseen term gives P(t|c)=0 and kills the whole product.
  • Many small probabilities underflow, so add log scores: log P(c) + Σ log P(t|c).
  • The independence assumption is false for real text, but the ranking often works.

Logistic regression gives a probability

Logistic regression is a linear classifier with a probabilistic output. It gives each feature a weight. A positive weight raises the chance of the positive class; a negative weight lowers it. The weighted sum is passed through a sigmoid to keep the output between 0 and 1.

p(y=1|x) = 1 / (1 + e−(w·x + b))

x is the feature vector; w is the weight vector; b is the bias; w·x + b is the linear score z; p is the predicted probability that the label is 1.

L = −Σ<sub>i</sub> [ y<sub>i</sub> log p<sub>i</sub> + (1 − y<sub>i</sub>) log(1 − p<sub>i</sub>) ]

yi is the true label, 0 or 1; pi is the predicted probability for example i; L is cross-entropy loss, lower is better.

For many classes, softmax replaces the sigmoid. It turns class scores into probabilities that sum to 1. Training minimises cross-entropy by gradient descent, often with L2 regularisation to shrink weights.

Prediction uses a threshold, usually 0.5. The decision boundary is linear in the feature space. In text, sparse word counts make this model fast and easy to update. Use the evaluation metrics in 5.3 to compare classifiers.

Linear SVM maximises the margin

A support vector machine labels examples with a separating line or hyperplane. For text, a linear SVM is common. It uses labels +1 and −1. The score is w·x+b. The sign gives the predicted class. The SVM wants the score to be at least +1 for the positive class and at most −1 for the negative class, leaving a margin.

loss = max(0, 1 − y(w·x + b))

y is the true label, +1 or −1; w·x+b is the score; the loss is 0 when the example is correct and outside the margin; otherwise it grows linearly.

Training minimises the sum of hinge losses plus λ||w||². The regularisation term controls overfitting. Only points near or inside the margin, the support vectors, affect the boundary.

The kernel trick replaces x·z with K(x,z)=φ(x)·φ(z). It lets a linear method act in a higher-dimensional space without building φ(x). Text often uses a linear kernel; small datasets may use polynomial or RBF kernels.

Naive Bayes is fastest and works with tiny data. Logistic regression gives calibrated probabilities. Linear SVM often gives strong accuracy on sparse text. All three are baselines before neural models in Unit 6. Some syllabi add decision trees for text; only a few universities examine them. A tree splits on feature thresholds and is not a linear classifier.

Worked example

Question. Training data: positive = good film; negative = bad film. Vocabulary V = {good, bad, film}. Use multinomial Naive Bayes with add-one smoothing. Test document d = good film. Compute the priors, smoothed likelihoods, class scores and prediction.

  1. |V| = 3. Positive class has 2 term occurrences; negative class has 2 term occurrences.
  2. P(pos) = 1/2 = 0.5 and P(neg) = 1/2 = 0.5.
  3. count(good, pos) = 1, so P(good|pos) = (1+1)/(2+3) = 2/5 = 0.4.
  4. count(film, pos) = 1, so P(film|pos) = (1+1)/(2+3) = 2/5 = 0.4.
  5. Positive score = 0.5 × 0.4 × 0.4 = 0.08.
  6. count(good, neg) = 0, so P(good|neg) = (0+1)/(2+3) = 1/5 = 0.2.
  7. count(film, neg) = 1, so P(film|neg) = (1+1)/(2+3) = 2/5 = 0.4.
  8. Negative score = 0.5 × 0.2 × 0.4 = 0.04.
  9. 0.08 > 0.04, so the document is predicted positive.

Answer. The positive score is 0.08 and the negative score is 0.04, so the prediction is positive.

Exam traps

  • Forgetting Laplace smoothing makes P(good|negative)=0, so the negative score becomes 0 even when other words support it. Add one to every term count and |V| to the denominator.
  • Multiplying raw probabilities underflows for long documents. Compare log scores; the largest sum of logs wins.
  • In logistic regression the threshold 0.5 is not a law. A spam filter may choose a different threshold to trade false positives for false negatives.
  • SVM labels must be +1 and −1 for the hinge formula. Using 0 and 1 in max(0,1−y(w·x+b)) gives the wrong loss.
  • Naive Bayes independence assumption does not mean words are independent in reality; it is a modelling shortcut, not a data claim.

5.3 Feature engineering and evaluation metrics for text

A classifier sees only numbers. Feature engineering turns each document into numbers that separate the classes, and evaluation metrics tell you whether those numbers produced a useful classifier. A spam filter that catches 80 of 90 spam emails but marks 20 good emails as spam faces different costs from one that misses half the spam. Accuracy alone hides this. This chapter covers feature types, feature selection, and the confusion-matrix metrics — precision, recall, F1, macro and micro averages, ROC-AUC — plus cross-validation. These tools are used in spam filtering, support-ticket routing, and review moderation.

You need: text classifiers from 5.2 and bag-of-words/TF-IDF vectors from 5.1.

Feature types for text

A feature is a number computed from a document. The classifier learns a weight for each feature. Good features make the classes separable; a feature with the same value in both classes adds noise.

  • Word n-grams: unigrams such as "refund" and bigrams such as "not good". Bigrams keep negation and short phrases. Vocabulary size grows fast.
  • Character n-grams: fixed-length character slices. The 3-grams of "refund" are "ref", "efu", "fun", "und". They survive spelling mistakes and work for morphologically rich Indian languages.
  • TF-IDF weight: tf(t,d) × log(N ÷ df(t)). tf is the count of term t in document d; df is the number of documents containing t; N is the total number of documents. Rare discriminative words get high weight; "the" gets low weight. See 5.1.
  • Presence flags: 1 if a word or pattern occurs, else 0. A flag for "!!!" or "Rs." or "OTP" can be a strong spam signal.
  • Document length: token count or number of sentences. Short messages like "call me" differ from long newsletters.
  • Punctuation and case: count of exclamation marks, ratio of uppercase letters, number of currency symbols.
  • POS tags: counts of nouns, verbs and adjectives from a tagger (Unit 2). Useful when word identity matters less than syntax.

For a phone SMS spam filter, the feature vector may hold 5,000 word unigrams, 2,000 character 4-grams, a presence flag for "OTP", and the count of digits. Each row is one SMS; each column is one feature.

Feature selection with chi-square and mutual information

A vocabulary of 50,000 words gives 50,000 columns. Most are rare and useless. Feature selection keeps the top k columns that are statistically tied to the class label. Two standard scores are chi-square and mutual information.

χ² = Σ (O − E)² ÷ E

O is the observed count in one cell of the 2×2 table (feature present/absent vs class spam/ham); E = (row total × column total) ÷ N; N is the number of training documents. Large χ² means feature and class are not independent.

Mutual information measures how much knowing the feature reduces uncertainty about the class.

I(T;C) = Σ p(t,c) log₂ [ p(t,c) ÷ (p(t) × p(c)) ]

p(t,c) is the fraction of documents with feature value t and class c. I is 0 when feature and class are independent. Keep features with the highest I.

Compute both scores on the training data only. If you select features using the full dataset before cross-validation, the test fold leaks into training and your score is too optimistic. This is a common bug in student projects.

Metrics from the confusion matrix

A confusion matrix counts four outcomes for a binary classifier. Take spam as the positive class: TP = spam correctly marked spam; FP = ham marked spam; FN = spam marked ham; TN = ham marked ham.

Precision P = TP ÷ (TP + FP)

TP is true positives; FP is false positives. Precision is the fraction of predicted spam that is really spam.

Recall R = TP ÷ (TP + FN)

FN is false negatives. Recall is the fraction of real spam that was caught.

F1 = 2 P R ÷ (P + R)

P is precision; R is recall. F1 is the harmonic mean and is high only when both P and R are high.

Accuracy = (TP + TN) ÷ (TP + FP + FN + TN)

The denominator is the total number of emails. Accuracy is the fraction classified correctly.

Class imbalance makes accuracy misleading. If 91% of emails are ham, a classifier that always says ham gets 91% accuracy and catches zero spam. Always report precision and recall on the rare class. Macro averaging computes the metric per class and takes the unweighted mean; every class counts equally. Micro averaging sums TP, FP and FN over classes first, then computes one metric; large classes dominate.

ROC-AUC plots true positive rate (recall) against false positive rate FP ÷ (FP + TN) as the decision threshold moves. AUC = 0.5 is random; 1.0 is perfect. It is threshold-free but still ignores class balance in the training data. Use stratified k-fold cross-validation: split the data into k folds that keep the same spam/ham ratio, train on k−1 folds, test on the held-out fold, and average the k scores.

Worked example

Question. A spam classifier is tested on 1000 emails: TP=80, FP=20, FN=10, TN=890. Compute precision, recall, F1 and accuracy.

  1. Total emails = 80 + 20 + 10 + 890 = 1000. Actual spam = TP + FN = 90. Predicted spam = TP + FP = 100.
  2. Precision = 80 ÷ (80 + 20) = 80 ÷ 100 = 0.800.
  3. Recall = 80 ÷ (80 + 10) = 80 ÷ 90 = 0.8889 (0.889 rounded).
  4. F1 = 2 × 0.800 × 0.8889 ÷ (0.800 + 0.8889) = 1.4222 ÷ 1.6889 = 0.8421 (0.842 rounded).
  5. Accuracy = (80 + 890) ÷ 1000 = 970 ÷ 1000 = 0.970.

Answer. Precision = 0.8, recall = 0.889, F1 = 0.842, accuracy = 0.97.

Exam traps

  • Accuracy trap: 0.97 looks high, but recall is 0.889 — 10 of 90 spam emails still reach the inbox. On a rare class, report precision and recall, not accuracy.
  • Precision vs recall swap: precision divides by predicted positives (TP + FP); recall divides by actual positives (TP + FN). Swapping the denominators is the most common exam slip.
  • Macro vs micro: macro averages class scores equally; micro sums counts first. A 90/10 imbalance makes micro close to accuracy.
  • Feature-selection leakage: selecting the top chi-square features on all data before cross-validation inflates the score. Select inside each training fold.
  • Confusion matrix orientation: rows are predicted and columns are actual, or the reverse. Read the labels before computing anything.

5.4 Sentiment analysis: lexicon-based and machine learning approaches

Sentiment analysis finds attitude in text: positive, negative, neutral or an emotion. It exists because no team can read a lakh UPI app reviews by hand. A lexicon scores known opinion words; a classifier learns weights from labelled reviews. Banks use it on complaint tweets, film teams on song reviews, product teams on feedback. This chapter covers binary, multi-class and aspect-based sentiment, lexicon scoring with negation and intensifiers, machine learning on text features, and evaluation with precision, recall and F1.

You need: 5.1 for bag-of-words and TF-IDF, 5.2 for Naive Bayes, logistic regression and SVM, and 5.3 for features and metrics.

What is being classified

Binary sentiment gives one label: positive or negative. Multi-class sentiment adds neutral or a 1-to-5 star scale; stars are ordinal, so confusing 1 with 2 is a smaller error than 1 with 5. Emotion labels such as joy and anger are related, but speech emotion recognition belongs to Unit 7.

Aspect-based sentiment keeps the target. “The film is dull but the songs are excellent” gives film negative and songs positive. One overall positive score hides the film complaint. Aspects are entities or features: film, songs, battery, delivery, refund. Each gets its own polarity.

Labels must match the decision. “Not bad” is often positive, while “bad” alone is negative. A factual review such as “delivery arrived on Tuesday” is neutral, not positive. With 90 percent positive reviews, accuracy 90 percent may only match always saying positive; use per-class metrics from 5.3.

Lexicon-based sentiment scoring

A lexicon maps words to polarity scores. Simple scale: good = +2, excellent = +3, bad = -2. SentiWordNet-style lexicons store positive, negative and objective scores for each word sense, so meaning matters; see Unit 4 on WordNet senses.

Score in four steps: tokenize; find opinion words; apply negation and intensifiers; add scores. Basic sum:

score(s) = Σ p(w_i) × neg_i × int_i

score(s) is total polarity; p(w_i) is the lexicon score of token w_i; neg_i is -1 when a negator such as not scopes over w_i, else +1; int_i is 1.5 for very, 0.5 for slightly, else 1. Scores are dimensionless.

Negation flips the next opinion word: not good = +2 × -1 = -2. Intensifiers scale: very good = +2 × 1.5 = +3. Contrast words such as but and however change weight; a simple rule halves the clause before but and keeps the clause after. Drop objective words, which add noise.

Lexicons need no training data and are easy to explain. They fail on domain shift: unpredictable is bad for a banking app and good for a thriller. They also miss sarcasm and implicit complaints such as “I waited two hours”.

Machine learning approaches

Machine learning treats sentiment as text classification. Label reviews positive, negative or neutral. Convert each review to bag-of-words or TF-IDF features plus word and character n-grams (5.1). Mark negation as one token, so not_good is a feature. Train Naive Bayes, logistic regression or SVM (5.2).

Naive Bayes is fast and works on small data; it assumes independent features, so treat it as a baseline. Logistic regression gives probabilities and readable weights. A linear SVM handles sparse high-dimensional text well and maximises the margin. For multi-class, use one-vs-rest or softmax.

A few hundred labelled reviews per class can beat a lexicon in one domain, because the model learns local words such as refund and crash. The cost is annotation and overfitting. Use cross-validation; tune smoothing for Naive Bayes and C for logistic regression and SVM, as in 5.3.

Evaluation with precision, recall and F1

Test on held-out labelled reviews. For positive as the class of interest: TP = predicted positive and truly positive; FP = predicted positive but negative; FN = truly positive but predicted negative. Then:

P = TP/(TP+FP), R = TP/(TP+FN), F1 = 2PR/(P+R)

P is precision, the share of predicted positives that are correct; R is recall, the share of true positives found; F1 is their harmonic mean. TP, FP and FN are counts, so P, R and F1 are proportions.

Report per-class P, R and F1, not only accuracy. For aspects, compute P, R and F1 separately for film, songs and battery. Macro-F1 is the unweighted mean of aspect F1 values and exposes a weak rare aspect; micro-F1 pools decisions and favours frequent aspects. State which one you report.

Use a confusion matrix to see which classes are confused, especially neutral. For star ratings, add mean absolute error. Compare against a majority-class baseline.

5.5 Word representations: one-hot encoding and word vectors

A word needs a numeric form before a classifier or a similarity search can use it. One-hot encoding gives each word its own position in a long vector of zeros and a single one. Dense word vectors give each word a short list of real numbers. The dense geometry can place cricket near bat and far from monsoon, even when the words never share a sentence. Search, clustering, sentiment models and neural NLP all begin from such representations.

You need: 5.1 term vectors and basic vector arithmetic (dot product, length).

One-hot vectors

Let V be the vocabulary, the set of distinct words the system knows, and let |V| be its size. Number the words 1 to |V|. The one-hot vector e_w for word w has dimension |V| and Euclidean length 1. Every entry is 0 except position w, which is 1. In a vocabulary of 50,000 words, each vector has 49,999 zeros. The vector is sparse.

Different words put their 1 in different positions. Their dot product is 0 and the angle between them is 90°. Cosine similarity, which depends only on angle, is therefore 0 for every pair of different one-hot words. Cricket and bat look as unrelated as cricket and ball. The representation stores identity, not meaning. One-hot vectors still work as input to the classifiers in 5.2; the classifier learns which positions matter.

cos(a, b) = (a · b) / (|a| |b|)

a and b are vectors; a · b = Σᵢ aᵢbᵢ is the dot product; |a| = √(a · a) is the length. Cosine is 1 for same direction, 0 for perpendicular, −1 for opposite.

Counts to dense vectors

Build a co-occurrence matrix M from a corpus. Pick a window, for example 5 words to the left and 5 to the right. For every occurrence of a word w, count each context word c in the window. M[w, c] is that count. Rows are words, columns are context words. The matrix is large and sparse.

Raw counts are dominated by frequent words such as the. Positive pointwise mutual information (PPMI) compares the observed count with what chance would give. Estimate probabilities from the matrix: P(w,c)=count(w,c)/T, P(w)=row total/T, P(c)=column total/T, where T is the sum of all counts. Then PMI(w,c)=log₂(P(w,c)/(P(w)P(c))). PPMI(w,c)=max(PMI(w,c),0). Negative PMI means the pair occurs less than chance; PPMI sets it to 0.

M ≈ U Σ Vᵀ

M is the PPMI matrix; U and V have orthonormal columns; Σ is diagonal with singular values in decreasing order. Keep the k largest singular values. The dense vector for word w is row w of U_k Σ_k, a list of k real numbers.

Singular value decomposition (SVD) compresses the matrix. This use of SVD on a word-context count matrix is a count-based distributional method; the same idea applied to a term-document matrix is latent semantic analysis (LSA). Some syllabi call the whole idea vector semantics or distributed representations. A word's vector now depends on the company it keeps. The link between context and similarity is developed in 5.7.

Comparing dense vectors

Dense vectors are short, for example 100 or 300 numbers. They are not one-hot and not interpretable one entry per word. Their geometry matters. Words used in similar contexts get vectors with small angles. Compare them with cosine, not by checking equality.

Cosine ignores vector length. If you also need distance, normalize each vector to unit length first: x̂ = x/|x|. Then the dot product of two unit vectors equals their cosine, and Euclidean distance is √(2−2cos). This avoids a long vector looking far away only because of scale.

Dense vectors help when labelled data is small, because they share statistical strength across similar words. In document clustering, average the dense vectors of the document's words, then cluster the averages; see 5.7. For unknown words, use a reserved unknown token; do not silently use a zero vector.

Worked example

Question. Vocabulary = {cricket, bat, ball}. One-hot: cricket=[1,0,0], bat=[0,1,0]. Dense: cricket=[0.8,0.2], bat=[0.6,0.4]. Compute the one-hot cosine and the dense cosine between cricket and bat.

  1. The vocabulary has 3 words, so each one-hot vector has dimension 3. cricket has its 1 in position 1: [1,0,0]. bat has its 1 in position 2: [0,1,0].
  2. One-hot dot product = 1×0 + 0×1 + 0×0 = 0. Each one-hot vector has length 1 because it has one non-zero entry equal to 1.
  3. One-hot cosine = 0 / (1×1) = 0.
  4. Dense dot product = 0.8×0.6 + 0.2×0.4 = 0.48 + 0.08 = 0.56.
  5. Length of cricket = √(0.8² + 0.2²) = √(0.64 + 0.04) = √0.68 ≈ 0.8246.
  6. Length of bat = √(0.6² + 0.4²) = √(0.36 + 0.16) = √0.52 ≈ 0.7211.
  7. Dense cosine = 0.56 / (0.8246×0.7211) ≈ 0.9417.

Answer. One-hot cosine = 0; dense cosine ≈ 0.942 (0.9417 to four decimal places).

Exam traps

  • A one-hot vector's dimension is |V|, the vocabulary size, so all words use the same number of entries. Its Euclidean length is always 1, because exactly one entry equals 1.
  • Cosine similarity of two different one-hot vectors is 0. That does not mean the words are unrelated; it means the representation cannot express relatedness.
  • PPMI replaces negative PMI with 0 after taking the log. Do not clip counts before the log.
  • SVD gives U, Σ and Vᵀ, and row w of U_kΣ_k is row w of U_k scaled by σ_w. Cosine is unaffected by that scaling, but dot products and Euclidean distances are not; state which you use before using either.
  • Dense vector similarity is not Euclidean distance unless vectors are normalized. Cosine is an angle, not a distance.

5.6 Word embeddings: Word2Vec, GloVe and Doc2Vec

Word embeddings map each word to a dense vector learned from context. Word2Vec trains a small predictor: CBOW predicts a target from its neighbours, skip-gram predicts neighbours from the target, with negative sampling or hierarchical softmax for speed. GloVe fits vectors to global co-occurrence counts by weighted least squares. Doc2Vec adds a learned vector for a whole document. The vectors support similarity search, clustering, classification features, and analogies such as king − man + woman ≈ queen. The mechanisms matter because cosine comparison decides whether two vectors count as similar.

You need one-hot and dense word vectors plus cosine similarity from 5.5.

Word2Vec: local context predicts words

Word2Vec learns a dense vector for each word from local context windows. It keeps input vectors U, with row uw for word w, and output vectors V, with row vw. The usual embedding is uw, or sometimes uw+vw. Dimension d is commonly 50 to 300.

CBOW (continuous bag of words) predicts a target word wt from its neighbours. Skip-gram reverses the task: it predicts each neighbour from the target. Skip-gram makes more training pairs for rare words and is slower. Window size k is often 2 to 10.

p(c|w) = exp(v<sub>c</sub>·u<sub>w</sub>) / Σ<sub>w′∈V</sub> exp(v<sub>w′</sub>·u<sub>w</sub>)

V is the vocabulary; c is a context word; uw is the input vector of target w; vc is the output vector of c; · is the dot product.

The denominator sums over every word, which is costly for large V. Negative sampling replaces it with a binary task: a true pair (w,c) gets label 1, and k noise words get label 0. A common noise distribution is Pn(w) ∝ count(w)0.75. Hierarchical softmax puts words at leaves of a binary tree and multiplies sigmoid probabilities along the path, giving O(log V) cost.

  1. Tokenize the corpus and build the vocabulary.
  2. Slide a window over each sentence to make (target, context) pairs.
  3. Update U and V by stochastic gradient descent on the prediction loss.
  4. Keep U as the word vectors.

GloVe: global co-occurrence counts

GloVe (Global Vectors) starts from a word–context co-occurrence matrix X. Xij is the number of times word j appears within a window of word i. The matrix is large and sparse: V rows and V columns. GloVe uses these counts once, not a stream of windows.

J = Σ<sub>i,j=1</sub><sup>V</sup> f(X<sub>ij</sub>) (w<sub>i</sub>·c<sub>j</sub> + b<sub>i</sub> + b<sub>j</sub> − log X<sub>ij</sub>)²

J is the loss; Xij is the co-occurrence count; wi is the word vector; cj is the context vector; bi and bj are scalar biases; f is a weighting function.

A standard choice is f(x)=min(1,(x/xmax)0.75) with xmax=100, which stops very frequent pairs from dominating. The log turns counts into additive geometry: a large Xij should make wi·cj large.

Why it works: ratios of co-occurrence probabilities carry meaning. If word i co-occurs with ice more than with steam, and word j does the opposite, the vectors encode that contrast. Training runs gradient descent on the nonzero entries of X. GloVe often gives similar nearest neighbours to Word2Vec but can be faster on a fixed corpus.

Doc2Vec: a vector for a document

Doc2Vec extends Word2Vec with a learned vector for each document. The document ID is treated like an extra word that is always present in that document. In PV-DM (paragraph vector distributed memory), the model predicts a target word from the average of the context word vectors and the document vector. In PV-DBOW (distributed bag of words), the document vector predicts randomly sampled words from the document, like skip-gram with the document as the only input.

p(w<sub>t</sub> | context, d) = exp(v<sub>w<sub>t</sub></sub>·h) / Σ<sub>w′∈V</sub> exp(v<sub>w′</sub>·h)

wt is the target word; d is the document vector; h is the concatenation or average of the context vectors and d; V is the vocabulary.

The document vector acts as a memory of what the document is about. Training uses the same negative sampling or hierarchical softmax as Word2Vec. To embed a new document, freeze the word vectors and learn only its document vector by the same prediction task. Document vectors are used for similarity search, clustering, and as features for a classifier. They are dense and learned from context, not a bag-of-words count.

Analogies, nearest neighbours and cosine

Word vectors support approximate arithmetic. A famous pattern is king − man + woman ≈ queen. The model was never told about gender; the relation appears because man and woman occur in similar contexts and king and queen occur in similar contexts. The result is approximate: it depends on the corpus, window size, dimension, and training time.

cos(a,b) = (a·b) / (||a|| ||b||)

a·b is the dot product; ||a||=√(a·a) is the Euclidean length; the value lies in [−1,1].

Raw dot products are not comparable across vectors of different lengths: a long vector can have a large dot product with everything. Cosine divides out length. Use cosine for word similarity, document similarity, and analogy scoring. For an analogy a is to b as c is to d, compute x = b − a + c and choose the word whose vector has the highest cosine with x, excluding a, b, c. In the figure, man=[1,0], woman=[0,1], king=[1,1], queen=[0,2]; king − man + woman = [0,2], exactly queen. On real vectors the match is close, not exact.

FastText adds subword n-gram vectors, which helps with morphology; only a few universities teach it. Transformers such as BERT are covered in Unit 6.

Worked example

Question. Given man=[1,0], woman=[0,1], king=[1,1] and queen=[0,2], compute king − man + woman. Does it equal queen? Give the cosine similarity between the result and queen.

  1. Subtract man from king: [1,1] − [1,0] = [0,1].
  2. Add woman: [0,1] + [0,1] = [0,2].
  3. Compare with queen [0,2]: the difference is [0,0], so the vectors are equal.
  4. Dot product with queen: 0×0 + 2×2 = 4.
  5. Length of result = √(0²+2²) = 2. Length of queen = √(0²+2²) = 2.
  6. Cosine = 4 / (2×2) = 1.0.

Answer. The result is [0,2], which equals queen; the cosine similarity is 1.0.

Exam traps

  • Raw dot product is not cosine. A long vector can win on dot product even when its direction is a poor match; normalise by length.
  • Analogy arithmetic is approximate. Results change with corpus, window size, dimension and training; do not expect an exact queen every time.
  • CBOW and skip-gram are reversed. CBOW predicts the target from context; skip-gram predicts context from the target.
  • Negative sampling does not mean antonyms or negative sentiment. It samples noise words for a binary classifier.
  • GloVe uses log Xij, not Xij, inside the squared error, and f(0)=0 so zero counts are skipped.

5.7 Distributional semantics and document clustering

Distributional semantics says a word's meaning is revealed by the company it keeps: words in similar contexts get similar vectors. The same idea extends to documents: a document's vector is built from its words, and documents with similar vectors land near each other. Clustering then groups them without labels. It is used in news grouping, customer-feedback sorting, library cataloguing and search-result organisation.

You need: 5.1 TF-IDF and 5.6 Doc2Vec.

Meaning from context

The distributional hypothesis states that words used in similar contexts tend to have similar meanings. Loan and credit appear near bank, interest and account; river and water appear near bank and flow. Count those neighbours and the geometry starts to capture meaning. This is the idea behind the word vectors in 5.5 and 5.6. Neural language models predict a word from its context and learn such vectors as a by-product.

Build a word-context matrix M. M[w][c] counts how many times context word c appears within a window of, say, 5 words around target w across a corpus. Raw counts favour frequent words, so convert them to PPMI.

PPMI(w,c) = max(0, log₂( (count(w,c) × N) ÷ (count(w) × count(c)) ))

PPMI(w,c) is positive pointwise mutual information for word w and context c; count(w,c) is their co-occurrence count; count(w) and count(c) are marginal counts; N is the total number of co-occurrence pairs.

  • PPMI keeps positive association and sets negative values to 0.
  • SVD factorises M ≈ U Σ Vᵀ; keep the first 100–300 singular values.
  • A row of UΣ gives a dense vector for a word. Cosine between rows measures similarity.

From words to document vectors

A document vector is an aggregate of its words. TF-IDF from 5.1 gives a sparse vector: each dimension is a vocabulary term, and the weight is term frequency × inverse document frequency. Doc2Vec from 5.6 gives a dense learned vector for the whole document.

Two documents are similar if their vectors point in the same direction. Cosine similarity ignores length, which suits documents of different sizes. Euclidean distance measures straight-line separation; it is sensitive to vector length, so normalise first if you use it for text.

cos(u,v) = (u · v) ÷ (‖u‖ ‖v‖)

u and v are document vectors; u · v is the dot product; ‖u‖ and ‖v‖ are their lengths. The value is between −1 and 1, and is 0 for unrelated, perpendicular vectors.

k-means document clustering

k-means partitions N document vectors into k groups. Pick k, place k centroids, then alternate assignment and update.

  1. Choose k and initial centroids, often by picking k documents at random.
  2. Assign each document to the nearest centroid using cosine or Euclidean distance.
  3. Recompute each centroid as the mean vector of its assigned documents.
  4. Repeat until assignments stop changing or a maximum iteration count is reached.

J = Σᵢ Σₓ∈Cᵢ ‖x − μᵢ‖²

J is the within-cluster sum of squares; Cᵢ is cluster i; x is a document vector; μᵢ is the centroid of Cᵢ. Smaller J means tighter clusters.

The mean-based update matches Euclidean distance. For cosine, average the vectors and then normalise each centroid to unit length. k-means assumes roughly convex, similar-sized clusters. Agglomerative hierarchical clustering starts with each document as a cluster and repeatedly merges the two closest clusters. Cut the dendrogram at a chosen height to get clusters. It is slower on large corpora but shows nested structure.

Evaluation and meaning of clusters

Purity measures how well clusters match known classes. For each cluster, take its most common gold class, then average over all documents.

purity = (1 ÷ N) Σₖ maxⱼ |Cₖ ∩ Lⱼ|

N is the number of documents; Cₖ is cluster k; Lⱼ is gold class j; |Cₖ ∩ Lⱼ| counts documents in both. Purity ranges from 0 to 1. It rises easily when k is large, so report k with it.

The silhouette score uses distances instead of labels. For document i, let a(i) be its mean distance to documents in its own cluster and b(i) its mean distance to documents in the nearest other cluster.

s(i) = (b(i) − a(i)) ÷ max(a(i), b(i))

s(i) is the silhouette of document i. It ranges from −1 to 1: near 1 means tight and well separated, near 0 means overlapping clusters, and negative values suggest the document may be in the wrong cluster.

Cluster numbers carry no meaning: cluster 1 in one run may be cluster 2 in another. Topic modelling, such as LDA, is related but gives soft topic mixtures rather than hard clusters.

  7. New C1 = mean([3,0],[2,1]) = [(3+2)/2,(0+1)/2] = [2.5,0.5].
  8. New C2 = mean([0,3],[1,2]) = [(0+1)/2,(3+2)/2] = [0.5,2.5].
  9. Reassignment with new centroids: D1 to C1 ≈0.707, to C2≈3.536; D2 to C1≈0.707, to C2≈2.121; D3 to C1≈3.536, to C2≈0.707; D4 to C1≈2.121, to C2≈0.707. Every document stays in its cluster, so the algorithm has converged.

Answer. The final centroids are C1=[2.5,0.5] and C2=[0.5,2.5]; cluster 1 is {D1,D2} and cluster 2 is {D3,D4}.

Exam traps

  • k-means depends on the initial centroids. Different starts can give different final clusters, so run several restarts and keep the result with the smallest J.
  • k is chosen by you, not discovered by the algorithm. A larger k always lowers within-cluster distance, but it does not always give more useful clusters.
  • Euclidean and cosine distance can give different clusters. Euclidean is sensitive to document length; cosine ignores length but also ignores magnitude.
  • Cluster numbers are arbitrary. Cluster 1 in one run can be cluster 2 in another; never treat the number as a class label.
  • Purity rises with k, and purity with k=N is trivially 1. Compare purity only at the same k, or use a measure that corrects for chance.

Check yourself

Remember State the distributional hypothesis in one sentence. 2 marks

Words that appear in similar contexts tend to have similar meanings.

Understand Why is PPMI preferred to raw co-occurrence counts when building word vectors? 3 marks

Raw counts are dominated by frequent words and common contexts. PPMI divides by marginal frequencies, so it measures association above chance and clips negative values to 0.

Apply Centroids are C1=(2,1) and C2=(5,5). A document vector is (3,2). Using Euclidean distance, which cluster gets the document? Show the two distances. 3 marks

To C1: √((3−2)²+(2−1)²)=√2≈1.414. To C2: √((3−5)²+(2−5)²)=√13≈3.606. The document goes to C1.

Apply Cluster C1 contains documents with gold labels A, A, B. Cluster C2 contains documents with gold labels A, B. Compute purity. 4 marks

For C1, the most common class is A with 2 documents. For C2, A and B tie at 1, so take 1. Purity = (2+1)/5 = 0.6.

Analyze A silhouette score for one document is negative. What does that suggest, and what should you check? 4 marks

Negative s(i) means a(i) > b(i): the document is farther from its own cluster than from the nearest other cluster. Check whether the document is misassigned, whether k is too large, or whether the distance measure is unsuitable.

Understand How does topic modelling differ from k-means document clustering? 3 marks

k-means gives a hard assignment: each document belongs to exactly one cluster. Topic modelling gives a soft assignment: each document is a mixture of topics with weights.

Analyze Why can TF-IDF vectors and Doc2Vec vectors produce different clusters for the same corpus? 4 marks

TF-IDF weights exact vocabulary terms and is sparse and high-dimensional. Doc2Vec learns dense context-based vectors and can place different words with similar usage close together. The two representations emphasise different kinds of similarity, so the same distance rule can group documents differently.

Takeaways

  1. A document becomes a fixed-length numeric vector through bag of words or TF-IDF, and everything downstream depends on that vector.
  2. TF-IDF down-weights words that appear in most documents, so common words like 'the' stop dominating the feature vector.
  3. Naive Bayes is fast and works with tiny training sets; logistic regression and SVM usually win when labelled data is plentiful.
  4. Accuracy lies on skewed classes; precision, recall and macro-F1 on a confusion matrix show the real behaviour.
  5. Lexicon methods need no training data but fail on sarcasm and domain words; trained classifiers need labelled examples but adapt to the domain.
  6. A one-hot vector carries no notion of similarity, while a dense embedding places similar words close together in space.
  7. Word2Vec learns from local context windows, GloVe from global co-occurrence counts; both end up with vectors where cosine similarity approximates relatedness.
  8. Distributional similarity gives both word vectors and document vectors, and document vectors can be clustered without any labels.

Exam question bank

Long answers are expected to move from feature construction (BoW, TF-IDF weights written out) through the classifier's objective and decision rule, and to finish with the evaluation metric that would actually decide the choice.

Remember and understand

Understand Explain how a raw text document is converted into a TF-IDF vector. Write the formulas for term frequency and inverse document frequency, and explain why the product is used instead of raw counts. 10 marks

Vocabulary is built from the training corpus after tokenisation and normalisation; tf(t,d) counts the term or divides by document length; idf(t) = log(N ÷ df(t)); Product w(t,d) = tf × idf gives high weight to terms frequent here and rare elsewhere; Common stopwords get idf near zero, so their contribution shrinks; Result is a sparse vector of length |V|, one per document, ready for a classifier.

Understand State the Naive Bayes assumption for text classification and derive the decision rule from Bayes' theorem. Show how Laplace smoothing changes the estimate. 12 marks

Bayes: P(c|d) ∝ P(c) Π P(wᵢ|c); Conditional independence of words given the class is the 'naive' part; Estimate P(c) from class frequencies; P(wᵢ|c) from counts within the class; Unseen word gives zero, so add-one smoothing with |V| in the denominator; Predict the class with the maximum posterior; work in log space to avoid underflow.

Remember Define precision, recall and F1 for a two-class text classifier and explain, with a spam-filter example, why accuracy alone can mislead. 8 marks

Definitions in terms of TP, FP, FN, TN; F1 as the harmonic mean, and why harmonic rather than arithmetic mean; Example where 95 percent of documents are 'not spam', so a constant classifier gets 95 percent accuracy; Precision and recall of that constant classifier are zero or undefined; Conclusion: report per-class metrics or macro-F1.

Understand Compare one-hot word vectors with dense word embeddings in terms of dimensionality, sparsity, and ability to express similarity. 10 marks

One-hot has length |V|, is sparse, has exactly one 1; All distinct one-hot vectors are orthogonal, so cosine similarity is 0; Dense embeddings have 50–300 dimensions, all entries real numbers; Similar words get high cosine similarity by construction of training; Trade-off: one-hot is exact and interpretation-free, embeddings generalise.

Apply

Apply A training set has 1000 documents, of which 200 are 'positive'. The word 'excellent' appears in 60 positive and 10 negative documents. With add-one smoothing over a vocabulary of 5000 words, compute the smoothed likelihoods and state which class the word favours. 10 marks

P(excellent|pos) = (60+1) ÷ (total positive word tokens + 5000); P(excellent|neg) = (10+1) ÷ (total negative word tokens + 5000); Prior P(pos) = 0.2, P(neg) = 0.8; Likelihood ratio is about 6, prior ratio is about 0.25, so combine both; Show the log-space arithmetic and the final comparison.

Apply Describe how you would build a sentiment classifier for product reviews on an e-commerce site. Cover label definition, features beyond unigrams, class imbalance, and the metric you would report. 14 marks

Define labels from star ratings, e.g. 1–2 negative, 4–5 positive, drop the middle; Features: unigrams and bigrams, negation handling, TF-IDF weighting, review length; Handle class imbalance with class weights or resampling; Report macro-F1 and the confusion matrix, not plain accuracy; Validate on held-out reviews from the same product category.

Apply Explain the skip-gram Word2Vec training procedure. Write the objective it maximises and explain how negative sampling makes it practical for a large vocabulary. 13 marks

Slide a context window of size m over the corpus; Objective: maximise Σ Σ log P(w_{t+j} | w_t) over context words; Softmax over the full vocabulary is expensive: O(|V|) per update; Negative sampling replaces it with a binary task against k random words; Result: dense vectors where the dot product of a word and its context is large.

Apply You have 20,000 unlabelled news articles. Describe how to represent them and cluster them, including choice of vector, distance measure, choice of k, and how you would judge the clusters. 12 marks

TF-IDF vectors or averaged Doc2Vec vectors; Cosine distance is preferred over Euclidean for text; k-means with several random starts; pick k by silhouette score or elbow; Inspect top terms per cluster, not just the numeric score; Limitation: cluster labels are uninterpretable without human reading.

Apply Show how a linear SVM classifies a TF-IDF document vector. Write the decision function, explain the margin, and say what the C parameter controls. 11 marks

Decision: f(x) = sign(w·x + b); Margin is 2 ÷ ‖w‖; maximise it subject to correct classification; Soft margin adds slack variables ξᵢ with penalty C Σ ξᵢ; Small C means a wide, tolerant margin; large C means few training errors; Sparse TF-IDF vectors make the dot product cheap.

Analyze and evaluate

Analyze Compare lexicon-based and machine-learning sentiment analysis. For each, state the resource needed, the failure modes, and the situation where it would be the better choice. 13 marks

Lexicon: needs a polarity word list and negation rules; no training data; Lexicon fails on sarcasm, domain-specific words, and context-dependent polarity; ML: needs labelled data; learns domain words and combinations automatically; ML fails when the test domain differs from training domain; Recommendation: lexicon for a quick baseline or a new domain with no labels; ML when labelled data exists and accuracy matters.

Analyze A team reports 96 percent accuracy on a fake-news classifier where 4 percent of articles are fake. Analyse the result, state what additional numbers you need, and propose a better evaluation plan. 12 marks

Accuracy is inflated by the majority class; a constant 'real' predictor already gets 96 percent; Ask for the confusion matrix, per-class precision and recall; Macro-F1 and the false-negative rate on the fake class matter most; Consider precision at a fixed recall if editorial review capacity is limited; Recommend stratified splits and a held-out set from a later time period.

Evaluate Word vectors trained on one corpus are used for document clustering of another corpus. Evaluate the risks and describe how you would check whether the representation is suitable. 14 marks

Domain and time shift change word usage, so neighbours may be wrong; Rare and out-of-vocabulary words get poor vectors; Check intrinsic quality on similarity benchmarks and by inspecting nearest neighbours; Check extrinsic quality: cluster purity on a small hand-labelled sample; Alternatives: train in-domain embeddings, use FastText subwords, or fall back to TF-IDF.

Evaluate Discuss whether a bag-of-words representation can ever be enough for text classification. Support your answer with cases where word order matters and with the practical costs of richer representations. 13 marks

Bag of words discards order, so 'dog bites man' equals 'man bites dog'; Topic classification and spam filtering work well with n-grams and TF-IDF; Negation, sarcasm and aspect sentiment need order or syntax; Richer models cost more data, more compute and lose interpretability; Practical rule: start sparse, move to embeddings when data justifies it.

Glossary

Centroid
The mean vector of all points currently assigned to a cluster.
Class imbalance
A training set where one label is far more frequent than another, which biases accuracy as a metric.
Co-occurrence matrix
A table whose entry (i,j) counts how often word j appears near word i in a corpus.
Context window
The number of words to the left and right of a target word that a Word2Vec model treats as its context.
Cross-entropy loss
The negative log probability the model assigns to the correct label; minimising it trains logistic regression.
Document frequency
The number of documents in the collection that contain a given term.
Embedding
A dense, low-dimensional learned vector that represents a word, sentence or document.
Hyperplane
The set of points satisfying w·x + b = 0; in text classification it is the decision boundary between classes.
Kernel trick
Computing dot products in a higher-dimensional space without explicitly mapping the data there.
Lemmatisation
Reducing a word to its dictionary form using grammatical knowledge, so 'better' becomes 'good'.
Macro-average
Averaging a metric over classes with equal weight for each class, regardless of class size.
Margin
The distance between the separating hyperplane and the nearest training points; SVM maximises it.
Named entity recognition
The task of finding and labelling names of people, places, organisations and similar categories in text.
Negation handling
A rule that flips or reduces the polarity of words appearing after 'not', 'never' or 'no' within a short scope.
Negative sampling
A training shortcut that teaches the model to separate real context words from a few randomly drawn fake ones.
Out-of-vocabulary (OOV) word
A word in the test data that never appeared in training, so no learned vector exists for it.
Polarity
The positive, negative or neutral orientation assigned to a word, phrase or document in sentiment analysis.
Sigmoid function
σ(z) = 1 ÷ (1 + e⁻ᶻ), which maps any real number to a probability between 0 and 1.
Silhouette score
A clustering quality measure comparing how close a point is to its own cluster against the nearest other cluster.
Sparse vector
A vector with mostly zero entries, as produced by bag of words and TF-IDF.
Stemming
Crudely cutting a word to a common root, so 'running' and 'runs' both become 'run'.
Stopword
A very frequent word such as 'the' or 'is' that is often removed or down-weighted because it carries little topical signal.
Tokenisation
Splitting a string of characters into words, punctuation marks or subword pieces.
Vocabulary (V)
The set of distinct terms kept after preprocessing; its size is written |V|.
