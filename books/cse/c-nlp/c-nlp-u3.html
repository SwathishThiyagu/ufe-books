3.1 Context-free grammars and grammar rules for English

A sentence is not a flat list of words. Words group into phrases, and phrases into bigger phrases, and a context-free grammar writes those groupings as a small set of rewrite rules: S → NP VP, NP → Det N, VP → V NP. Three sets — nonterminals, terminals and rules — and one start symbol are enough to generate infinitely many sentences, each with its own tree. Parsers, grammar checkers, machine translation decoders and treebank annotators all begin from this object, so it is the first thing syntax in NLP builds.

You need: word classes and POS tags such as Det, N, V and P from Unit 1 (morphology, word classes) and Unit 2 (POS tagging).

Four sets and a start symbol

A context-free grammar (CFG) is a 4-tuple G = (N, Σ, R, S). N is a finite set of nonterminals: symbols that stand for phrases, written in capitals — S, NP, VP, PP, Det, N, V. Σ is a finite set of terminals: the actual words, written in lower case — the, boy, ate. N and Σ share no symbol. R is a finite set of rules, each written A → β, where A is one nonterminal and β is a string of nonterminals and terminals. S is the start symbol, one member of N; every tree begins there.

Context-free names the left side of a rule: one nonterminal stands alone and is rewritten whatever surrounds it. NP → Det N behaves the same inside the boy ate the cake as at the top of a sentence.

A derivation records the rules applied in order. Write α ⇒ β when one rule turns the string α into β in one step, and S ⇒* w when zero or more steps take S to the terminal string w. A leftmost derivation always rewrites the leftmost nonterminal next. A parse tree shows the same history: root S, each internal node a nonterminal with the children given by the rule used on it, leaves the terminals. The yield of a tree is its leaves read left to right; the tree in the figure has yield “the boy ate a cake”.

Generation asks which strings w satisfy S ⇒* w; that set is the language L(G). Recognition is the reverse: given G and a string w, decide whether w ∈ L(G). A recogniser answers yes or no; a parser returns the trees. How to do it without blind search is in 3.3.

Rules for English phrase structure

English phrase structure sits in a rule set this small. Nonterminals are capitalised, words are not.

  • S → NP VP — a sentence is a subject noun phrase and a predicate verb phrase.
  • NP → Det N — a noun phrase is a determiner and a noun.
  • NP → NP PP — a noun phrase may be a noun phrase plus a prepositional phrase.
  • VP → V NP — a verb phrase is a verb and its object noun phrase.
  • VP → VP PP — a verb phrase may take a prepositional phrase.
  • PP → P NP — a prepositional phrase is a preposition and a noun phrase.
  • Lexical rules: Det → the | a, N → boy | cake | girl | car | dog | spoon | kitchen, V → ate | saw, P → in | with.

NP → NP PP and PP → P NP feed each other: NP ⇒ NP PP ⇒ NP P NP ⇒ NP PP P NP, so the same six rules produce “the boy with the girl in the car with the dog”. The rule list never grows; only the tree does. This is recursion, and it is why a finite grammar covers unbounded sentences. VP → VP PP does the same on the verb side: “ate the cake with a spoon in the kitchen”.

Some syllabi call these phrase-structure rules, or a phrase-structure grammar (PSG); it is the same object. In the Chomsky hierarchy a CFG is Type 2: it sits above regular grammars (Type 3, finite-state machines from Unit 1) and below context-sensitive grammars (Type 1). The dividing line is counting and nesting: a finite-state machine cannot track how many phrases are still open, a CFG can.

Features and unification

A plain CFG overgenerates. Nothing in S → NP VP blocks “the boys eats”. A feature structure, or attribute-value matrix (AVM), hangs attributes on a symbol: NP becomes [CAT NP, NUM pl, AGR 3pl]. Unification merges two AVMs: it succeeds when no attribute is given two different values, and the result keeps every attribute of both. It fails on [NUM sg] against [NUM pl].

Enforce agreement by requiring the NUM of the subject NP and the NUM of the VP to unify; the value flows from one to the other. “the boys eats” gives NP [NUM pl] and VP [NUM sg], so unification fails and the string is rejected, while “the boy eats” unifies on [NUM sg]. Only a few universities teach feature structures this early; the same machinery returns in unification-based grammars and in feature-based taggers.

Exam traps

  • Writing a terminal as a nonterminal: boy is in Σ and N is in N; the rule is N → boy, never boy → N.
  • Taking the start symbol to be the first rule written. S is a named member of N; reordering R changes nothing in L(G).
  • Expecting a plain CFG to enforce agreement. “the boys eats” is generated by an agreement-free rule set; features or a stronger formalism are needed.
  • Confusing a derivation with a parse tree. The tree forgets step order; one tree can have many derivations but only one leftmost derivation.

3.2 Treebanks and normal forms for grammars

A treebank is a corpus of sentences with hand-checked syntax trees attached, so grammar writing becomes counting: read the rules off the trees and count them. Raw treebank rules are untidy — long right-hand sides, mixed terminals and nonterminals, unit rules — and the CYK parser wants them in Chomsky normal form, where every rule is A → BC or A → a. This chapter covers both halves: how trees turn into grammar rules, and how any grammar is rewritten into CNF without changing the language it generates.

You need: 3.1 for rules, derivations and parse trees.

Treebanks: a grammar hiding in annotated sentences

A treebank is a corpus of sentences, each stored with its syntactic annotation — a parse tree drawn and checked by a human. The best known is the Penn Treebank, built from Wall Street Journal articles. In a constituency treebank a sentence appears as a bracketed tree: (S (NP (DT the) (NN boy)) (VP (VBZ eats) (NP (DT a) (NN sweet)))). The inner nodes are phrase labels: S for sentence, NP for noun phrase, VP for verb phrase. The leaves are words, each sitting under a part-of-speech tag: DT determiner, NN noun, VBZ verb.

A dependency treebank stores the same sentence differently: every word points to its head word and carries a label for the relation, so boy is the nsubj (subject) of eats. Universal Dependencies is the open collection most projects use, and it covers Hindi, Tamil and Marathi among its languages. Which kind you need depends on the parser you will run; see 3.6.

A treebank is also a grammar. Every local tree — one node with its immediate children — is one rule: the subtree (NP (DT the) (NN boy)) gives NP → DT NN. Read every local tree in the corpus and you have a grammar with counts. A rule seen 40,000 times is core English; a rule seen once may be an annotation slip. A rule that never occurs in the treebank will never be proposed by a parser trained on it — the sparse-data problem, handled by smoothing in 3.5.

Chomsky normal form

Chomsky normal form (CNF) is a restricted shape for a context-free grammar: every rule is either A → BC, with exactly two nonterminals on the right, or A → a, with exactly one terminal. A, B, C are nonterminals; a is a terminal, that is, a word. Nothing else is allowed: no right-hand side of three or more symbols, no rule mixing a word with a nonterminal, no unit rule A → B, no empty rule A → ε. The one exception is S → ε, allowed only when the empty string is in the language.

Why bother: CYK (3.3) fills a table over spans of the sentence, and for each span it tries every split into two smaller spans. Binary rules make that loop uniform — one split, one rule, one lookup. Every CFG has an equivalent CNF grammar: the same set of sentences, with different rule shapes.

Converting any grammar to CNF

  1. Isolate terminals. A word that shares a right-hand side with nonterminals, as in S → NP VP ., gets a nonterminal of its own: PERIOD → ., and the rule becomes S → NP VP PERIOD. Reuse one helper nonterminal per word, not a fresh one per occurrence.
  2. Binarise long rules. A → B1 B2 … Bn with n ≥ 3 becomes A → B1 X1, X1 → B2 X2, up to X(n−2) → B(n−1) Bn. Keep the left-to-right order of the symbols. One rule of length n becomes n − 1 rules.
  3. Remove ε rules. Find the nullable nonterminals, those that can derive the empty string, add versions of the rules with the nullable symbols dropped, then delete the ε rules. If the empty string is in the language, add a fresh start symbol with S0 → S and S0 → ε.
  4. Remove unit rules. Delete A → B by copying every rule of B under A, and repeat until no unit rule remains. Break cycles such as A → B with B → A first, keeping one direction. Remove ε rules first, because dropping nullable symbols can create unit rules; then remove unit rules as the last shape-fixing step, and check once more that no unit rule appeared.

The language does not change. Only the derivations change: a sentence that took one step now takes several, and the parse tree gains helper nodes. Binarising and isolating terminals are linear: a rule of n symbols becomes n − 1 rules. Unit-rule removal copies rules and can grow the grammar polynomially in the worst case. The language never changes; only the size and the derivations do. Greibach normal form is the other named form: there every rule is A → aα, one terminal first and then any number of nonterminals.

Worked example

Question. Convert this grammar to Chomsky normal form and give the number of rules before and after: S → NP VP PP; NP → Det N; VP → V NP; PP → P NP; Det → the | a; N → boy | girl; V → ate; P → with.

  1. Write each alternative as its own rule and count: S → NP VP PP, NP → Det N, VP → V NP, PP → P NP, Det → the, Det → a, N → boy, N → girl, V → ate, P → with. That is 10 rules.
  2. Step 1, isolate terminals: the, a, boy, girl, ate and with each already stand alone in a lexical rule, so no rule mixes a word with nonterminals. Nothing to do.
  3. Step 2, binarise: only S → NP VP PP is longer than two symbols. Add X1 → VP PP and rewrite S → NP X1. One rule is replaced by two, so one new nonterminal and a net gain of one rule.
  4. Steps 3 and 4: no unit rules A → B and no ε rules exist, so nothing is removed and no new start symbol is needed.
  5. Count the result: 10 − 1 + 2 = 11 rules. The single helper node X1 keeps the children in the order NP, VP, PP, so every yield is unchanged.

Answer. The CNF grammar has 11 rules against 10 before, adds one nonterminal X1, and generates exactly the same sentences.

Exam traps

  • Binarising out of order: A → B C D must become A → B X, X → C D, never A → B X, X → D C, because swapping the two groups changes the word order of every yield.
  • Adding S → NP X1 and forgetting X1 → VP PP: a nonterminal with no rule of its own can never be rewritten, so the sentence is lost.
  • Deleting a unit rule like VP → V without copying V's rules under VP, or forgetting the fresh start symbol S0 → S, S0 → ε when the empty string is in the language.
  • Believing CNF changes the language. It changes derivations and tree shape only; the set of sentences is exactly the same.
  • Creating a new helper nonterminal for every occurrence of the same word instead of reusing one, which bloats the grammar for no reason.

3.3 Parsing algorithms: CYK and Earley

A grammar says which strings are sentences; a parser proves that one particular string is a sentence and returns its trees. Trying rules blindly takes exponential time, so both standard algorithms use a table instead. CYK fills a triangular table of word spans, bottom-up, and needs the grammar in Chomsky normal form. Earley walks the sentence left to right carrying dotted rules and accepts any CFG. Both run in polynomial time.

You need: 3.1 for CFG rules and trees, and 3.2 for Chomsky normal form, which CYK requires.

Recognition, trees, and three families of parser

A context-free grammar is G = (N, Σ, P, S): N is the set of nonterminals such as NP, Σ is the set of terminal words, P is the set of rules, and S is the start symbol. Parsing answers two questions. Recognition asks whether a word string w = w₁w₂…wₙ is in L(G). Tree extraction asks for the parse trees themselves.

The number of possible trees grows fast: 14 binary trees over 5 leaves, 4862 over 10. Testing them one by one is exponential, so every practical algorithm stores the answer to each subproblem once. That store is a chart: a table indexed by positions in the sentence.

Top-down parsing starts at S and expands rules until the leaves match the words. Recursive descent writes one function per nonterminal and reads like the grammar. Its weakness is left recursion: a rule A → A α makes the function call itself on the same input forever. Rewriting the grammar to remove left recursion, or replacing recursion with an explicit stack and a loop, removes the loop.

Bottom-up parsing starts at the words and joins them into nonterminals. CYK is a bottom-up chart parser over spans; Earley is a left-to-right chart parser over dotted rules. Shift-reduce parsing, a bottom-up method that uses a stack, is in 3.8.

CYK: a triangular table of spans

The Cocke–Younger–Kasami algorithm assumes Chomsky normal form, so every rule is either A → B C or A → a. Conversion is in 3.2.

  1. n is the number of words. Make one cell (i, j) for every pair with 1 ≤ i ≤ j ≤ n: n(n+1)/2 cells, a triangle.
  2. Cell (i, j) holds the set of nonterminals that derive words i to j, both ends included.
  3. Length 1: put A in (i, i) if the rule A → wᵢ exists.
  4. Lengths L = 2 to n: for (i, j) with j = i + L − 1, try every split k from i to j − 1. If B is in (i, k), C is in (k+1, j), and A → B C is a rule, add A to (i, j).
  5. Accept when S is in (1, n).
splits(n) = n(n−1)(n+1) / 6,   T(n) = O(n³ · |G|)

n is the number of words; |G| is the number of grammar rules; splits(n) counts the (i, k, j) triples tried. For n = 5 that is 20.

Each nonterminal is stored once per cell, even when two splits both produce it. That discarding of multiplicity keeps the run polynomial instead of exponential.

Recognition is not a tree. To print one, store a back pointer whenever a nonterminal is added: the split k and the rule A → B C. Reading pointers back from (1, n) rebuilds the tree. For the best tree under a probability model see 3.5; the loop is the same with a maximum in place of set union.

Earley: dotted rules read left to right

An Earley state is a rule with a dot and an origin, written (A → α · β, i). The parser is working on A → αβ, has matched α, the dot sits before β, and i is the position where this rule started.

There is one chart set per position, S₀ to Sₙ; a state in S_j has its dot after j words. S₀ starts with (S′ → · S, 0), where S′ is a fresh start symbol.

  1. PREDICTOR: a state (A → α · B β, i) in S_j predicts every rule of B: add (B → · γ, j) to S_j for each rule B → γ.
  2. SCANNER: a state (A → α · a β, i) in S_j with a a word. If word j+1 is a, add (A → α a · β, i) to S_{j+1}.
  3. COMPLETER: (B → γ ·, i) in S_j means B covers words i+1 to j. For each (A → α · B β, k) in S_i, add (A → α B · β, k) to S_j.
  4. Accept when (S′ → S ·, 0) is in S_n.

Repeat the moves until no set grows; they are steps inside one pass, not three algorithms.

T(n) = O(n³) general,  O(n²) unambiguous grammar,  O(n) bounded-state grammar

n is the number of words. A bounded-state grammar is one where no chart set S_j ever holds more than a fixed number of states, however long the sentence is; most programming-language grammars are of this kind.

Earley accepts any CFG: left recursion, ε rules and unit rules need no rewriting. The price is bookkeeping: each set holds many states and each new state must be checked against those already present.

Exam traps

  • Running CYK on a grammar that is not in CNF. A rule A → B C D or a unit rule A → B fills cells wrongly; convert first.
  • Reading cell (i, j) as words i to j−1. It is i to j inclusive, so (1, n) is the whole sentence and a span of length 1 has i = j.
  • Stopping at the first split k that fills a cell. Every split must be tried; a later split may add a different nonterminal and change whether S reaches (1, n).
  • Saying CYK is O(n²) because the table has O(n²) cells. Filling one cell costs O(n) splits, so the total is O(n³ · |G|).

3.4 Syntactic ambiguity and attachment resolution

One sentence can have more than one parse tree. 'I saw the man with the telescope' has two: the man holds the telescope, or the seeing is done with it. The grammar allows both, so the parser must choose using evidence beyond the grammar: rule probabilities, head words, word meanings, or a heuristic. This choice matters wherever a tree feeds another task, such as machine translation, question answering or information extraction, because a wrong attachment gives a wrong answer downstream.

You need parse trees from 3.1 and the fact that a parser returns every parse from 3.3.

Structural and lexical ambiguity

Structural ambiguity, also called syntactic ambiguity, means one word sequence with fixed part-of-speech tags has two or more valid parse trees. No single word is unclear; the grammar itself licenses both bracketings.

Lexical ambiguity is a different fault. One word carries two senses or two categories: 'bank' is a river side or a money house, 'book' is a noun or a verb. A tagger settles the category (Unit 2) and word sense disambiguation settles the sense (Unit 4). Lexical ambiguity can create structural ambiguity: if 'book' is tagged as a verb, the sentence needs a verb phrase. But the two causes are separate, and an exam question often asks you to name which one you are looking at.

Local ambiguity means a span can be built in two ways while the parser is still reading, and only one of those survives to the end. Global ambiguity means the finished sentence has two complete trees. CYK and Earley keep every live option, so local ambiguity costs time, not correctness.

The count grows fast. For n prepositional phrases in a row, the number of attachment trees follows the Catalan numbers 1, 1, 2, 5, 14, 42, so five phrases already give 42 readings. Every extra phrase multiplies the work.

Four patterns to recognise

  • PP attachment. A prepositional phrase can hang from the noun phrase before it or from the verb phrase above it: 'I saw the man with the telescope', 'She ate the cake with a fork'. The two trees answer different questions: which man, or how she ate.
  • Coordination scope. 'Old men and women' brackets as [old [men and women]], where both are old, or as [[old men] and women], where only the men are old. A conjunction can join words, phrases or clauses, and its reach fixes the meaning.
  • Noun-noun compounds. 'The university cricket ground staff' nests four nouns with no marker of grouping. [university [cricket ground]] staff and [[university cricket] ground] staff describe different organisations.
  • Garden path. 'The horse raced past the barn fell' makes you take 'raced' as the main verb; 'fell' then forces 'raced past the barn' to be a reduced relative clause modifying 'horse'. The first reading is locally fine and globally dead, so the reader must backtrack.

Evidence that chooses a tree

Rule probabilities. A probabilistic CFG gives every rule a probability, and the probability of a tree is the product of its rule probabilities; the parser picks the tree with the highest product (3.5). Its weakness is that a rule such as VP → VP PP always has one probability, whatever the noun and preposition are, so the model cannot see that 'man with' and 'saw with' behave differently.

Head words. Lexicalized models condition each rule on the head word of the phrase, so the score for attaching a PP to 'man' differs from attaching it to 'saw' (3.8). This is the single strongest signal for PP attachment.

Selectional restrictions and word senses. A telescope is an instrument someone looks through, so 'seeing with a telescope' is a normal event; a man 'with a telescope' is normal possession too, so word meaning alone does not settle this one. 'The scientist watched the bacteria with a powerful microscope' does settle, because bacteria cannot own a microscope (Unit 4).

Heuristics. Low attachment means attaching the new phrase to the most recent phrase; it fails on 'The scientist watched the bacteria with a powerful microscope', where it picks the bacteria. Minimal attachment means building the fewest new nodes; it fails on 'The horse raced past the barn fell', where it commits to 'raced' as main verb. Both are guesses, not rules, and they can point to different trees for the same sentence.

Practical parsers keep an n-best list, the top few trees rather than one, and rerank them with head words, word senses or a neural model. The final tree is the reranker's choice.

Worked example

Question. The sentence 'I saw the man with the telescope' is structurally ambiguous at the prepositional phrase. (a) Write both bracketings and name the reading each gives. (b) The grammar has P(VP → VP PP) = 0.6 and P(NP → NP PP) = 0.2, and every other rule used by the two parses has the same probability. Write the probability of each parse as a multiple of the shared factor and say which parse the PCFG chooses. (c) Give the ratio of the two probabilities.

  1. Locate the ambiguity: the PP 'with the telescope' can attach to the NP 'the man' or to the VP 'saw the man'. Both attachments are licensed by the context-free grammar, so the grammar does not choose.
  2. Parse A: [S [NP I] [VP saw [NP the man [PP with the telescope]]]]. The PP sits inside the NP, so the man has the telescope.
  3. Parse B: [S [NP I] [VP [VP saw [NP the man]] [PP with the telescope]]]. The PP sits inside the VP, so the seeing is done with the telescope.
  4. Shared rules: S → NP VP, VP → V NP, NP → Det N, PP → P NP, plus the lexical rules. Their product is one number K, identical in both parses.
  5. Probability of Parse A = 0.2 × K, because the only rule that differs is NP → NP PP with probability 0.2.
  6. Probability of Parse B = 0.6 × K, because the differing rule is VP → VP PP with probability 0.6.
  7. Compare: 0.6K > 0.2K, so Parse B wins. Ratio = 0.6 / 0.2 = 3.
  8. Keep the loser: a reranker using word senses could still prefer Parse A next time, because a man holding a telescope is an ordinary event. Note also that low attachment, which attaches to the most recent phrase (here the NP), would pick Parse A, so the heuristic and the probability model disagree on this sentence.

Answer. Parse A scores 0.2K (the man has the telescope) and Parse B scores 0.6K (the seeing is done with the telescope); the PCFG chooses Parse B, which is 3 times more probable than Parse A.

Exam traps

  • Calling a word with two senses 'structurally ambiguous'. A word like 'bank' gives lexical ambiguity; the tree changes only after a sense is chosen.
  • Assuming the highest-probability tree is the correct meaning. A PCFG scores structure with rule frequencies and knows nothing about truth, so its top tree can be the wrong reading.
  • Treating low attachment and minimal attachment as rules. Each is a heuristic that fails on ordinary sentences, and the two can point to different trees for the same sentence.
  • Confusing local with global ambiguity. A sentence can be locally ambiguous at every step of the parse and still finish with a single tree.
  • Thinking more grammar rules mean fewer parses. Every rule that can apply adds trees; broader coverage gives more ambiguity, not less.

3.5 Probabilistic CFGs and statistical parsing

A probabilistic context-free grammar (PCFG) attaches a probability to every rewrite rule of a CFG. The probability of a parse tree is the product of the probabilities of the rules it uses. This turns parsing into a search for the most likely tree, not just any tree. Statistical parsers use PCFGs and their relatives to rank readings of news sentences, questions and commands. The same numbers also give a sentence probability, which later scores speech and translation candidates.

You need 3.1 for rules, 3.2 for treebank counts, and 3.3 for the CYK table.

A probability on every rule

A probabilistic context-free grammar (PCFG) is a context-free grammar plus a probability for every rewrite rule. If a rule is A → α, its probability is written P(A → α). For each nonterminal A, the probabilities of all rules with left side A must sum to 1: Σα P(A → α) = 1. A rule not listed has probability 0. The grammar part is the same as in 3.1; the probabilities rank the trees.

P(T) = Π over every node n in T of P(rule used at n)

P(T) is the probability of tree T; the product runs over nodes, so a rule used at two nodes is multiplied twice.

The model assumes each rule is chosen independently once its parent is fixed. The children of a node are independent given the parent. The choice does not look at the head word, at words outside the span, or at the rest of the sentence. These are strong independence assumptions; they are what makes the dynamic program in the next section possible.

Inside probability and probabilistic CYK

Number the sentence words 1 to n. For a nonterminal A and a span from word i to word j, the inside probability β(i, j, A) is the sum of the probabilities of all subtrees rooted at A that cover exactly words i to j. For a binary rule A → B C, split the span at k.

β(i, j, A) = Σ over rules A → B C and splits k from i to j−1 of P(A → B C) × β(i, k, B) × β(k + 1, j, C)

β(i, j, A) is the inside probability; P(A → B C) is the probability of the binary rule expanded at the root of the span; i and j are word positions; B and C are the two children; k is the last word of the left child's span.

For i = j, β(i, i, A) = P(A → wi) if that rule exists, else 0. Convert the grammar to Chomsky normal form first, as in 3.2. The sentence probability is β(1, n, S). Probabilistic CYK fills the same table as 3.3. It uses sum in the formula above to get the sentence probability. For the most likely tree it uses max:

δ(i, j, A) = max over A → B C and k of δ(i, k, B) × δ(k + 1, j, C) × P(A → B C)

δ(i, j, A) is the probability of the best subtree rooted at A over words i to j; backpointers store the split and rule. The max cell for S is the best tree probability, not the sentence probability.

Time = O(n³ · |G|)

n is the number of words; |G| is the number of grammar rules. The n³ comes from spans and split points; |G| comes from trying rules.

Estimating the numbers and judging the result

A treebank gives counts. The relative-frequency estimate is P(A → α) = Count(A → α) ÷ Count(A), where Count(A → α) is the number of times that rule is used in the treebank and Count(A) is the number of times A is expanded. Add counts over all trees. This is the maximum-likelihood estimate.

Sparse data is the main problem. Many valid rules never appear, so their probability is 0 and any tree using them gets probability 0. Smoothing, covered in Unit 2, gives unseen rules small counts.

Limitations follow from the independence assumptions. A PCFG is biased toward small trees: when rule probabilities are below 1, every extra node multiplies the tree probability by a number below 1. It has no lexical sensitivity: P(NP → Det N) is the same for 'the boy' and 'the cake'. It is weak on attachment because it has no head word or outside context; see 3.4 and 3.8.

Evaluation compares the constituents (span plus label) in the parser's tree with those in a gold tree. Labelled precision = correct predicted constituents ÷ all predicted constituents. Labelled recall = correct predicted constituents ÷ all gold constituents. F1 = 2 × precision × recall ÷ (precision + recall). Parent annotation and Markovisation are two standard refinements of the nonterminal set; they are named here only.

Exam traps

  • A rule used at two nodes is multiplied twice. A common slip is to count each distinct rule once.
  • All rules with the same left side must have probabilities summing to 1. P(NP → Det N) = 0.5 and P(NP → Det N PP) = 0.6 cannot both sit in one PCFG.

3.6 Dependency grammar and dependency parsing

Dependency grammar describes a sentence as words joined by labelled links. Each link runs from a head word to a dependent word, and every word except one leans on exactly one other. Dependency parsing is the job of finding the best set of such links for a given sentence and its part-of-speech tags. It exists because many languages, Hindi and Tamil among them, move words around freely while keeping the same word-to-word relations. Question answering, information extraction and machine translation all use dependency trees to find out who did what to whom.

You need Chapter 3.1 for constituency as a contrast, and the POS tags of Unit 2, because a dependency parser reads tags as well as words.

Heads, dependents and labelled arcs

A dependency tree treats every word as a node. A link runs from a head to a dependent. The head governs the relation; the dependent leans on it. In The boy ate the cake, the verb ate is the head of boy and of cake. Boy is the head of The, and cake is the head of the.

One word has no head inside the sentence. It is joined to a special node called ROOT, placed at position 0 before the first word. Here ate is that word. The links must satisfy four conditions.

  • Each word has exactly one head, except the one word that links to ROOT.
  • Exactly one word links to ROOT.
  • No cycles: following heads from any word must end at ROOT.
  • All words are connected: no word floats free.

Each link carries a label naming the grammatical relation. The table lists the labels used in this chapter.

LabelRelationExample
nsubjnominal subjectate → boy
dobjdirect objectate → cake
detdeterminerboy → The
amodadjectival modifiercake → chocolate
advmodadverbial modifierate → quickly
prepprepositional relationate → in

Label names come from the treebank the parser learned from. Some syllabi call the preposition link prep, others case or obl. The shape of the tree matters more than the spelling of the label.

Projectivity and free word order

Draw the arcs above the words. A tree is projective when no two arcs cross. The test is simple: if word i is the head of word j, every word strictly between them must be a descendant of i. An arc that crosses another is a crossing arc, and a tree containing one is non-projective.

English is mostly projective, but questions and fronted phrases break it. Hindi and Tamil usually put the verb last and let arguments appear in several orders. Their bracketing into phrases shifts as words move; the head-dependent links do not. That stability is the reason dependency grammar suits free word order languages: the parser predicts relations, not positions.

So the parser's task is the same everywhere. Score the plausible links, then pick one complete, legal tree.

Arc-standard transition parsing

Arc-standard parsing builds the tree left to right using two lists.

  • Stack: words read from the sentence, with ROOT at the bottom, whose head and dependents are not yet all fixed. A word is popped only when it has been given a head and has taken all its dependents.
  • Buffer: words not yet read, in sentence order.
  • Arc set: the links built so far.

Let i be the word on top of the stack and j the first word in the buffer. Three actions are possible, plus a stop rule.

  1. SHIFT: move j from the buffer to the top of the stack.
  2. LEFT-ARC(l): add the arc j → i with label l, then pop i. Allowed only if i has no head yet and i is not ROOT; ROOT is never popped.
  3. RIGHT-ARC(l): add the arc i → j with label l, remove j from the buffer, then pop i and put it back at the front of the buffer so it can take more dependents. Allowed only when j already has all its own dependents.
  4. Stop when the buffer is empty and the stack holds only ROOT.

Which action is right? During training the gold tree answers that. A program called the oracle reads the current configuration and returns the correct move.

A classifier then learns to imitate the oracle. Its features are the top stack words, their POS tags, and the first words of the buffer; its output is a score for each legal action. At test time the parser takes the best-scoring legal action and never backtracks, so one early mistake spoils later arcs.

Graph-based parsing takes the other route. Every possible head-dependent pair is scored on its own, and the tree with the largest total score is found exactly by the Chu-Liu/Edmonds algorithm.

A neural shift-reduce parser replaces hand-written features with embeddings. The top three stack words and the next three buffer words are looked up as vectors and fed to a feed-forward network that scores SHIFT, LEFT-ARC and RIGHT-ARC. Only a few universities go this deep; most exams stop at the three actions above.

Worked example

Question. The gold dependency tree for The boy ate the cake quickly has these arcs: ate → boy (nsubj), boy → The (det), ate → cake (dobj), cake → the (det), ate → quickly (advmod), and ate → ROOT. A system outputs every arc correctly except that it links cake → quickly (advmod) instead of ate → quickly (advmod). Counting every arc, including the one from ate to ROOT, find UAS and LAS.

  1. Count the gold arcs: five word-to-word arcs plus one ROOT arc gives 6 arcs. The denominator for both measures is 6.
  2. Unlabelled attachment: an arc is correct when head and dependent match, whatever the label. Five arcs match. The wrong one has head cake where the gold has ate, so it fails. UAS = 5 / 6 = 0.8333.
  3. Labelled attachment: an arc is correct only when head, dependent and label all match. The same five arcs match. The wrong arc has the wrong head and also carries advmod under the wrong head, so it fails. LAS = 5 / 6 = 0.8333.
  4. The two scores coincide because the single error breaks the head and the label together. If the system had linked ate → quickly with the label dobj, UAS would stay 0.8333 while LAS would fall to 4 / 6 = 0.6667.

Answer. There are 6 arcs; 5 are correct, so UAS = 5/6 = 0.8333 and LAS = 5/6 = 0.8333.

Exam traps

  • Dropping the ROOT arc from the denominator. The link from the main word to ROOT is an arc and is counted; a six-word sentence with a root arc has 6 arcs, not 5.
  • Counting words instead of arcs. UAS and LAS are ratios of arcs; a 10-word sentence contributes 10 arcs, not 9 or 10 tokens minus something.
  • Accepting a set of high-scoring arcs that is not a tree. A word with two heads, or a cycle with no path to ROOT, is invalid and scores nothing, however sensible each arc looks alone.
  • Reversing arc direction. Arcs run head → dependent, so ate → boy is correct and boy → ate is wrong even though both name the same pair.
  • Treating a crossing arc as an error. Projectivity is a structural property; free word order languages often need non-projective trees, and a parser that forbids them will be wrong.

3.7 Shallow parsing and chunking

Shallow parsing, also called chunking, groups the words of a sentence into short flat units — noun phrases, verb phrases, prepositional phrases — without building a tree inside each unit. It exists because many tasks need only the boundaries of these units, and a chunker is far cheaper and faster than a full parser. A named-entity recogniser, an information-extraction rule, or a parser that has failed on a long sentence can all work from chunks. This chapter shows the IOB tag scheme, how chunking becomes sequence labelling, and how to score it.

You need: 3.1 for phrase types and Unit 2 for POS tagging and CRF tagging.

Chunks are flat groups

A chunk is a short, non-overlapping, non-nesting group of words that acts as one unit. A base noun phrase is the noun phrase without a following prepositional phrase: in “the cake in the park”, the chunk is “the cake”, not the whole phrase. Common chunk types are NP (noun phrase), VP (verb phrase), PP (prepositional phrase), ADJP (adjective phrase) and ADVP (adverb phrase). Each word belongs to at most one chunk, and chunks never sit inside each other. Words that belong to no chunk carry the label O, meaning outside.

A rule-based chunker matches patterns over POS tags. The pattern Det? Adj* N+ means an optional determiner, any number of adjectives, then one or more nouns. It matches “the cake”, “a red car” and “fresh milk”. A chink is a word or pattern that cannot be inside a chunk and therefore breaks it — a verb between two nouns, for example. Some chunkers find chunks and chinks together, then label the chunks.

Shallow parsing is shallow because it stops at the boundary. You learn that “the cake” is an NP, but not how the determiner and noun combine inside it. That missing tree is exactly what 3.3 builds. For phrase types, see 3.1.

IOB tags and sequence labelling

Chunking is written as one tag per word using IOB tags, in the IOB2 convention where every chunk starts with B-. B-X begins a chunk of type X; I-X continues a chunk of type X; O is outside every chunk. A B- tag always opens a new chunk of its own type. An I- tag can only follow a B- or I- with the same type. So “B-NP I-NP” is one NP, while “B-NP B-NP” is two NPs.

  1. Write the words in order with their POS tags.
  2. Mark the first word of each chunk B-X, where X is that chunk's type (for example B-NP, B-VP, B-PP).
  3. Mark later words of the same chunk I-<type>.
  4. Mark every word outside a chunk O.

BILOU is a five-tag variant: B begin, I inside, L last, O outside, U unit, where U is a one-word chunk. It makes the end of a chunk explicit.

Because each word gets one tag, chunking is sequence labelling: input is the word/POS sequence, output is the IOB sequence. The HMM, MEMM and CRF taggers from Unit 2 apply unchanged — a CRF is common because neighbouring tags constrain each other. The figure shows the tag string for one sentence.

Scoring chunks and where they are used

Score chunks, not tokens. A predicted chunk is correct only when its start, its end and its label all match a gold chunk. With C correct chunks, N_pred predicted chunks and N_gold gold chunks:

P = C / N_pred, R = C / N_gold, F1 = 2PR / (P + R)

P is chunk-level precision; R is chunk-level recall; F1 is their harmonic mean; C counts chunks with exact boundary and label match; N_pred is the number of predicted chunks; N_gold is the number of gold chunks.

A labelled score uses the type; an unlabelled score ignores the type but still demands exact boundaries. In the example below, one wrong label leaves unlabelled F1 at 1.0 while labelled F1 falls to 0.75.

Uses: named-entity recognition often starts from NP chunks and then classifies each chunk (see Unit 2); information extraction writes patterns over chunk sequences; a fast partial parse gives a first analysis of a long stream; and when a full parser fails or is too slow, chunks are the fallback. Chunks also feed semantic-role labelling (see Unit 4). They are not a substitute for a tree when the task needs internal structure or long-distance attachment.

Worked example

Question. A sentence has gold chunks [The boy]NP, [ate]VP, [the cake]NP and [in the park]PP. A chunker outputs [The boy]NP, [ate]VP, [the cake]NP and [in the park]NP. Compute labelled and unlabelled precision, recall and F1 for the chunker.

  1. Count gold chunks: N_gold = 4.
  2. Count predicted chunks: N_pred = 4. All four predicted spans are among the four gold spans, but the last label is NP instead of PP.
  3. Labelled matches: the first three predicted chunks match a gold chunk in both boundary and label; the last does not. So C_lab = 3.
  4. Labelled precision = 3/4 = 0.75; labelled recall = 3/4 = 0.75; labelled F1 = 2×0.75×0.75/(0.75+0.75) = 0.75.
  5. Unlabelled matches: all four predicted boundaries equal the four gold boundaries, so C_unlab = 4. Unlabelled precision = 4/4 = 1.0; recall = 4/4 = 1.0; F1 = 1.0.

Answer. Labelled precision, recall and F1 are all 0.75; unlabelled precision, recall and F1 are all 1.0.

Exam traps

  • Scoring token-level accuracy instead of chunk-level precision and recall; token accuracy stays high even when every boundary is shifted.
  • Counting a chunk as correct when its boundary is right but its label is wrong. Only the labelled score punishes that; the unlabelled score does not.
  • Letting an I- tag continue a chunk of a different type. B-NP must open a new NP; I-VP cannot follow B-NP.
  • Assuming chunks nest or overlap. IOB assigns each word at most one chunk tag, so nested or crossing chunks need a richer scheme.
  • Calling a chunker a full parser. It gives flat spans and labels, not a tree, so it cannot answer attachment questions.

3.8 Lexicalized PCFGs and shift-reduce parsing

A plain PCFG gives a rule such as NP → NP PP one probability, whatever the words are. So it cannot weigh the triple (saw, man, with) against (ate, pizza, with): the words do not enter the rule probability. Words inside the PP such as 'telescope' are not heads under these head rules. A lexicalized PCFG writes each nonterminal with its head word and head tag, and conditions each rule on those heads. This makes the grammar sensitive to lexical choice. Shift-reduce parsing then builds the tree left to right with a stack of subtrees and a queue of input words; a classifier picks SHIFT or a REDUCE action. Parsers of this family are used in constituency and dependency analysis, and their features feed information extraction.

You need 3.5 for PCFG probabilities, 3.4 for PP attachment, and 3.3 for the CYK contrast.

Lexicalized PCFG

Take 'she saw the man with the telescope' and 'she ate the pizza with a fork'. Each string has two trees. The PP 'with the telescope' may attach inside the NP (the man owns a telescope) or inside the VP (she used a telescope). A plain PCFG gives NP → NP PP and VP → VP PP fixed probabilities. The words 'saw', 'man' and 'with' do not change those numbers, so the grammar cannot use the lexical evidence that decides the case.

Lexicalization adds the head word to each nonterminal. The head is the word that carries the phrase's main meaning and fixes its category. Write a nonterminal as X(w, t): X is the phrase category, w is the head word, t is its part-of-speech tag. For example NP(man, N) is a noun phrase headed by 'man'.

A preterminal such as Det or N has no head child; its head is its word. Phrase rules percolate: S and VP take the verb, NP takes the noun, PP takes the preposition. Apply these rules recursively to annotate treebank trees. A lexicalized rule is A(a) → B(b) C(c), and its probability is conditioned on the three heads.

P(A(a) → B(b) C(c)) = P(A → B C | a, b, c)

A, B, C are phrase categories; a, b, c are their head words. The parent head a and both child heads b and c are the condition. A unary rule uses P(A → B | a, b).

Shift-reduce parsing

Shift-reduce parsing reads the sentence once, left to right. It keeps a stack of subtrees already built and a queue of words not yet read. A classifier looks at the top of the stack, the next word, and their tags, then picks one action.

  • SHIFT: move the next word from the queue to the stack as a tagged preterminal subtree.
  • REDUCE-UNARY: pop one subtree and push a unary parent, such as NP → N.
  • REDUCE-BINARY-LEFT: pop the top two subtrees and push a parent whose head comes from the left child.
  • REDUCE-BINARY-RIGHT: same, but the head comes from the right child.
  • FINISH: stop when the queue is empty and the stack holds one tree.

Greedy search means one path only. A wrong early action changes the stack, and later actions build on that error, so one mistake can spoil the whole tree. Good features reduce this risk but do not remove it.

SHIFT/REDUCE moves = n + (n − 1) + u = 2n − 1 + u

n is the number of words; u is the number of unary reductions. FINISH adds one more action, so total actions = 2n + u.

CYK (3.3), by contrast, fills a table for every span and keeps all parses. It is exhaustive and slower, but it cannot be misled by an early choice. Shift-reduce is fast and linear in the number of actions, but it commits early.

Backoff and parser families

Lexicalized probabilities are sparse. A head word may appear in only a few treebank rules. Back off from the head word to the head tag to no lexical condition, and smooth the estimates. Without backoff, many lexicalized rules would have zero counts.

Collins-style parsers are one family of lexicalized statistical parsers. They annotate trees with heads, estimate lexicalized rule probabilities with smoothing, and search for the best tree. Shift-reduce parsers are another family: they replace exhaustive search with a learned action classifier. A neural shift-reduce dependency parser uses the same stack-and-queue control and learns features with a network; full neural architectures belong to Unit 6.

Use lexicalized PCFGs when word choice decides structure: PP attachment, coordination, subject-object choices. Use shift-reduce when speed matters and a labelled treebank is available. For long sentences, greedy errors are the main risk.

Exam traps

  • Conditioning a rule only on the parent head word. The child head words carry the lexical evidence; condition on all three heads as in P(A(a) → B(b) C(c)) = P(A → B C | a, b, c).
  • Treating a greedy shift-reduce choice as reversible. There is no backtracking; an early wrong reduce corrupts the stack and every later action.
  • Skipping backoff and smoothing. Lexicalized rules are sparse; use head word → head tag → no lexical condition, and smooth counts.
  • Reading LEFT/RIGHT as the direction of attachment. The label names the child that supplies the parent head: LEFT means the left of the two popped subtrees is the head, not that the phrase attaches to the left.
  • Miscounting actions. For n words with u unary reductions, building moves are 2n − 1 + u, and FINISH adds one, so total is 2n + u.

Takeaways

  1. A context-free grammar is a handful of rewrite rules that can generate infinitely many sentences, and English phrase structure fits this form well.
  2. Generation goes from S to a sentence; recognition goes from a sentence back to trees, and parsing is recognition plus building the trees.
  3. Chomsky normal form turns any CFG into binary rules, which is exactly the shape the CYK table needs.
  4. CYK and Earley both avoid blind search: CYK fills spans bottom-up, Earley shares partial parses across the whole sentence.
  5. A grammar alone cannot pick between parses; ambiguity is resolved with probabilities, head words, or meaning.
  6. A PCFG scores every tree as a product of rule probabilities, so the best tree is found by dynamic programming rather than enumeration.
  7. Dependency grammar drops phrases and links words directly, which suits free word order languages and gives fast linear-time parsers.
  8. Shallow parsing gives flat chunks cheaply and is often enough for named entities or noun-group extraction.
  9. Lexicalizing a PCFG with head words fixes many wrong attachments that a plain PCFG prefers.
  10. Shift-reduce parsing builds trees with a stack and a queue and runs in time linear in sentence length.

Glossary

Ambiguity
The property that one word string has more than one parse tree under a grammar.
Attachment ambiguity
Ambiguity over which node a phrase, typically a prepositional phrase, attaches to.
Chomsky normal form
A grammar whose rules are only A → B C or A → w, with ε allowed only from the start symbol.
Chunk
A flat, non-overlapping group of words such as a noun group, marked without internal structure.
Context-free grammar
A finite set of rewrite rules whose left side is a single nonterminal, able to generate an infinite language.
CYK algorithm
A bottom-up table parser for CNF grammars that fills spans by increasing length.
Dependency tree
A tree of words in which every word except the root has exactly one head.
Derivation
A sequence of rule applications turning the start symbol into a sentence.
Dotted rule
A grammar rule with a dot showing how much of its right side has been matched.
Earley parser
A chart parser that stores dotted rules with their start positions and reads the sentence left to right.
Feature structure
A set of attribute–value pairs attached to a node to record number, person, case or subcategorisation.
Generation
Producing strings by applying rules forward from the start symbol.
Inside algorithm
Dynamic programming that sums or maximises rule probabilities over every span and nonterminal.
IOB tagging
A tagging scheme using B-X, I-X and O to mark chunk boundaries and types.
Lexicalized PCFG
A PCFG whose nonterminals include the head word, making rule probabilities word-sensitive.
Nonterminal
A symbol such as NP or VP standing for a phrase and always rewritten by a rule.
Parse tree
A tree recording which rule applied at each node, with words as leaves.
Probabilistic CFG
A CFG in which each rule carries a probability, so each tree gets a probability.
Recognition
Deciding whether a given string can be derived from the start symbol.
Recursion
A rule whose expansion contains its own nonterminal, which lets a grammar build unboundedly long sentences.
Shift-reduce parsing
A parser that uses a stack and a queue and applies shift or reduce actions in sequence.
Start symbol
The nonterminal from which every derivation begins, normally S.
Terminal
A symbol that appears as a word in the sentence and is never rewritten.
Treebank
A corpus of sentences annotated with full syntactic trees.
Unification
Combining two feature structures, succeeding only when shared attributes agree.
Yield
The left-to-right sequence of leaf labels of a parse tree.
