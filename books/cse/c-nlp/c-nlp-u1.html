1.1 NLP history, applications and challenges

Natural language processing is the work of turning human text or speech into a structure another program can use: a label, a tree, a translation, a spoken reply. A bank wants to know whether a customer message is a complaint or a request. A student wants a Hindi sentence in English. Both need the same first move: take the raw input, find the units, and attach structure and meaning to them. NLP exists because language is the easiest way for people to give instructions and the hardest way to give them to a machine. It is used in search, translation, banking chatbots, review analysis and voice assistants.

You need only basic programming comfort; the language layers are introduced in levels of language analysis.

From hand-written rules to learned vectors

NLP is the field that builds programs which read or write human language. The input is text or speech. The output is a structure another program can use: a label, a tree, a translation, a short answer, a probability.

The work splits into two halves. Natural language understanding (NLU) goes from text to meaning. Natural language generation (NLG) goes from meaning to text. A rail enquiry chatbot needs both: it must read "when does the 6:40 to Tambaram leave" and then write a reply. Some syllabi use the single word NLP for the pair.

The field moved through three eras. They overlap, and none of them died.

  • Rules era. Linguists wrote grammars and dictionaries by hand, and the program checked the sentence against those patterns. It worked on clean, narrow text and broke on anything unexpected.
  • Statistical era. From the 1990s, text collections called corpora grew large enough to count. Instead of asking a linguist, the system estimated probabilities from counts: which word follows which, which tag fits which word. See Unit 2, N-gram Models.
  • Neural era. Words become vectors learned from data, and large pretrained models are fine-tuned on a small labelled set for each task. See Unit 5 for embeddings and Unit 6 for transformers. The gain is less hand-written rules and more generalisation; the cost is more data and compute.

Where NLP is used

Each item below is one task, not a separate field.

  • Spam filtering. A mail is labelled spam or not spam from its words and headers. This is binary text classification.
  • Machine translation. A sentence in one language becomes a sentence in another. See Unit 6.
  • Sentiment on product reviews. A review is labelled positive, negative or neutral. Sellers on Indian e-commerce sites read these at scale.
  • Search. A query is matched to documents and the documents are ranked by relevance. See Unit 6, information retrieval.
  • Chatbots for banking and rail enquiry. A fixed set of intents is recognised, then a template or a database lookup produces the reply.
  • Voice assistants. Speech is transcribed to text, NLP handles the text, and text-to-speech speaks the answer. See Unit 7.
  • Résumé screening. A CV is parsed into name, degree, skills and years of experience, then matched to a job description.

Ambiguity: one string, many readings

Ambiguity is the central difficulty. The same string carries more than one reading, and the reader must pick using context.

Lexical ambiguity: one word, several senses. "Bank" is a river edge or a money institution. "Bat" is a cricket bat or an animal. The fix needs surrounding words. See Unit 4, word sense disambiguation.

Syntactic ambiguity: one word sequence, two structures. In "She saw the man with the binoculars", the phrase "with the binoculars" attaches to "saw" (she used them) or to "the man" (he carried them). Parsing and attachment are covered in Unit 3.

Semantic ambiguity: the structure is fixed but the meaning of the whole is not. "Every student read a book" can mean one particular book for all students, or a possibly different book for each; the scope of "a book" changes. A different case is "The chicken is ready to eat": who does the eating changes, so it is an argument-structure ambiguity in "eat", not a fixed-structure semantic one. Selectional restrictions are covered in Unit 4.

Pragmatic ambiguity: the words are clear, the intended act is not. "Can you pass the salt?" asks about ability on paper; in a kitchen it is a request. Pragmatics is covered in levels of language analysis.

Systems rarely resolve these fully. Real pipelines carry several readings forward and let later evidence score them.

Beyond ambiguity: language variety, data and evaluation

Creativity and novel words. People coin words such as "selfie" and "upskilling", and they invent hashtags. A model trained on old text meets these as unknowns. Subword units help, but the first sighting is still a guess.

Code-mixing. Hinglish switches language inside one sentence: "kal meeting cancel hai". A word-level model trained on English sees noise, and the morphology rules of neither language apply cleanly.

Spelling variation on social media. "gud mrng", "plzz", doubled letters, dropped vowels. Standard dictionaries fail. Edit distance helps, as in spelling correction and minimum edit distance, but a deliberate misspelling and a typo look alike.

Rich morphology and free word order. Hindi, Tamil, Telugu and many other Indian languages carry case and agreement in suffixes and reorder arguments freely. English-shaped features lose this information. See morphology and finite-state transducers and tokenization.

Scarce labelled data. Raw text is easy to collect. Labelled data, meaning sentiment tags, parse trees or named entities, needs trained annotators and money. Most Indian languages have far less than English, so transfer from a high-resource language is common.

Evaluation. One sentence can have two correct translations, so a single accuracy number hides the truth. Test sets must be documented, and two scores may be compared only on the same split. See building corpora.

Worked example

Question. Name the type of ambiguity in each sentence. (a) "He sat by the bank." (b) "Visiting relatives can be troublesome." (c) "Can you pass the salt?" (d) "She saw the man with the binoculars."

  1. (a) The word "bank" has a river-edge sense and a money sense. One word, two senses, so the ambiguity is lexical.
  2. (b) "Visiting relatives" can be a noun phrase (relatives who visit) or a verb with its object (the act of visiting relatives). One string, two structures, so the ambiguity is syntactic.
  3. (c) The form is a yes/no question about ability. Said at a dinner table it is a request to pass the salt. The words are clear and the act is not, so the ambiguity is pragmatic.
  4. (d) The phrase "with the binoculars" can attach to "saw" (she used them) or to "the man" (he carried them). The words are unambiguous; the attachment site is not, so the ambiguity is syntactic.

Answer. (a) lexical, (b) syntactic, (c) pragmatic, (d) syntactic attachment.

Exam traps

  • "NLP means machine translation." Translation is one application; the field also covers tagging, parsing, classification and generation.
  • "NLP began with deep learning." The rules era and the statistical era came first; deep learning is the third era, not the origin.
  • Mixing lexical and syntactic ambiguity. Lexical is one word with two senses; syntactic is one word string with two structures.
  • Treating a question form as a question in use. "Can you pass the salt?" is a request, so the label is pragmatic.
  • Assuming an English score transfers. A model good on English Wikipedia text is not automatically good on Hinglish tweets or Tamil news.

1.2 Levels of language analysis: syntax, semantics, pragmatics

Language is not one flat string of words. It is built in layers. Each layer has its own unit and answers its own question. Speech sounds form words; words form phrases and sentences; sentences carry literal meaning; meaning changes with context. NLP systems copy this order because a wrong choice low down corrupts every layer above. Search, translation, voice assistants and chatbots all depend on these layers. The five levels are named here, one sentence is read at each, and the order explains why errors spread.

You need: Chapter 1.1 for the applications that each level serves.

The five layers and their units

Start at the bottom. Phonetics studies speech sounds as physical events. Phonology studies the sound units, called phonemes, that distinguish one word from another in a language. The unit is the phoneme; the question is “which sounds matter here?” Morphology studies how words are built from morphemes, the smallest meaning-bearing pieces. pay plus a past-tense morpheme gives paid, an irregular surface form. The unit is the morpheme; the question is “what is this word made of?” Syntax groups words into phrases and sentences and fixes word order. The unit is the phrase or sentence; the question is “what goes with what?” Semantics assigns literal meaning to words and sentences. The unit is the word sense or the sentence meaning; the question is “what does this literally say?” Pragmatics studies meaning in context: speaker intent, implied meaning and speech acts such as request or report. Discourse extends this across sentences. The unit is the utterance in context; the question is “what is the speaker doing and what is left unsaid?” Some syllabi call this set the levels of linguistic analysis. Higher layers use the output of lower layers, as the figure shows.

Higher layers depend on lower ones

The dependency is strict in one direction. Syntax cannot group words until tokenization and morphology give it words with part-of-speech guesses. Semantics cannot choose the right sense of bank until syntax says it is a noun and shows the phrase it sits in. Pragmatics cannot infer intent until semantics gives a literal meaning to reject or extend. Discourse cannot resolve it until earlier sentences and syntax give possible antecedents. A lower-level mistake therefore spreads upward. If paid is tagged as a noun, syntax may look for a subject after it. If Anna Salai is split into two tokens, the parser may see two places. If the bill is attached to bank instead of paid, the literal meaning changes. Higher context can sometimes repair a lower error, but not reliably.

Ambiguity is local at each level. Phonology: read has two pronunciations. Morphology: unlockable can mean able to be unlocked or not lockable. Syntax: I saw the man with the telescope has two attachments. Semantics: bank has several senses. Pragmatics: Can you pass the salt? is a request, not a yes/no question.

Steps in the NLP process

An NLP pipeline follows the layers. First normalize and tokenize the raw text (Chapter 1.4). Next assign morphology and lemma (Chapter 1.5, Chapter 1.6). Then tag parts of speech and build syntax; Unit 2 and Unit 3 cover these steps. Then assign literal meaning and word senses; Unit 4 covers this. Finally use context, discourse and intent. The order is not decoration. A wrong token changes the lemma; a wrong lemma changes the part of speech; a wrong part of speech changes the parse; a wrong parse changes the meaning. In a Chennai power-cut message, current must become the electricity sense, not a river current. That choice needs sentence context, but it also needs correct tokenization and a noun tag. Most system errors are not deep reasoning failures. They are lower-layer decisions made once and never checked.

Worked example

Question. Annotate the sentence Ravi paid the bill at the bank near Anna Salai at each of the five levels. State the number of morphemes in paid and the number of prepositional phrases in the syntax.

  1. Phonology: Ravi has two syllables. paid ends in the sound /d/; bank has the sounds /bæŋk/. The article the is pronounced /ðə/ before the consonant sounds in bill and bank. English also has /ðiː/ before vowel sounds, but it is not used here.
  2. Morphology: Ravi is one free morpheme. For this annotation, paid is the verb stem pay plus a past-tense morpheme, realized irregularly as paid; count 2 morphemes. the, bill, at, bank and near are single free morphemes. Anna Salai is a proper name.
  3. Syntax: subject noun phrase Ravi; verb paid; object noun phrase the bill; prepositional phrase at the bank; inside that noun phrase, prepositional phrase near Anna Salai. Count 2 prepositional phrases.
  4. Semantics: bill means an amount owed, not a bird beak or a proposed law. bank means a financial building, not a river side. Literal meaning: Ravi settled an amount owed at a financial building located near Anna Salai.
  5. Pragmatics: the sentence reports a past event and informs the listener. The listener is expected to know which bank is meant, or to infer it from Anna Salai. It is not a question or a request.

Answer. The sentence is annotated at all five levels; paid has 2 morphemes and the syntax has 2 prepositional phrases.

Exam traps

  • Do not put syntax below morphology. Word-internal structure is morphology; phrase structure is syntax.
  • Do not call pragmatics only politeness. It covers intent, context, implied meaning and speech acts.
  • Do not confuse phonetics with phonology. Phonetics is physical sound; phonology is the sound system that distinguishes words.
  • Do not expect a higher layer to repair a lower-layer error. A wrong token or lemma usually survives to the final answer.
  • Do not treat semantics as context-dependent. Literal meaning is semantics; what the speaker means here is pragmatics.

1.3 Regular expressions and finite-state automata

A regular expression is a short pattern that names a set of strings. For example, ^baa+!$ names b, then two or more a, then !. A finite-state automaton is a machine with states and labeled arcs. It reads a string once, left to right, and says accept or reject. The two views are equivalent: every pattern has an automaton, and every such automaton has a pattern. NLP uses this for tokenization, spelling rules, and morphology.

You need: strings and sets, plus the idea of language layers from chapter 1.2.

Patterns describe sets of strings

A regular expression (regex) is a pattern over an alphabet Σ, a finite set of symbols. The language L(R) of pattern R is the set of strings that R matches. For example, with Σ = {a,b,!}, the pattern baa+! has language {baa!, baaa!, baaaa!, ...}.

L(R) = { w ∈ Σ* | w matches R }

L(R) is the language of pattern R; w is a string; Σ* is the set of all finite strings over alphabet Σ.

  • a literal matches itself; concatenation ab matches a then b.
  • Union a|b matches a or b.
  • Kleene star a* matches zero or more a. Plus a+ matches one or more; ? matches zero or one.
  • [a-z] matches one character in the range; [^0-9] matches one character not a digit; . matches any one character.
  • ^ anchors to string start; $ anchors to string end. Without anchors a pattern may match a substring.
  • Parentheses group; backslash escapes a metacharacter, so \. is a literal dot.

Precedence: star, then concatenation, then union; use parentheses to be clear.

From pattern to NFA

An NFA (nondeterministic finite automaton) has states, a start state, final states, and arcs labeled by symbols or by ε. ε is the empty string: an epsilon jump consumes no input. From one state an NFA may have several arcs with the same symbol, or an ε arc. It accepts a string if some path from start to a final state spells the string.

  1. A literal symbol becomes two states joined by that symbol.
  2. Concatenation joins fragments: final of one to start of next.
  3. Union R|S adds a new start with ε arcs to both fragments, and ε arcs from both finals to a new final.
  4. Star R* adds a new start and a new final with four ε arcs: new start → new final (skip), new start → R's start (enter), R's final → new final (exit), and R's final → R's start (repeat).

Each operator adds at most two states and some ε arcs. For baa+!, plus is one or more: write it as b a a a* !. The NFA has a loop for extra a. The DFA in the figure has q0 start, q4 final, and q3 looping on a.

Subset construction to a DFA

A DFA (deterministic finite automaton) is an NFA with two restrictions: no ε arcs, and at most one arc per symbol from each state; if we insist on a total machine, missing arcs all go to one non-final dead state. It is easy to run: keep one current state, read one symbol, follow one arc. If no arc exists, the machine dies and rejects.

  1. The DFA start state is the ε-closure of the NFA start: the set of NFA states reachable by ε alone.
  2. For a DFA state S and symbol c, move to the ε-closure of all NFA states reachable from any state in S on c.
  3. Repeat for every new set. A DFA state is final if it contains any NFA final state.

The number of DFA states is finite, at most 2k for k NFA states. For baa+! the equivalent DFA is the table:

q0 is start; q4 is final. A dash means no arc.

What a finite machine cannot count

A finite automaton has a fixed, finite number of states. That is its only memory. It cannot store an unbounded count. So no regular expression or finite automaton can match the language {anbn | n ≥ 1}: n a's followed by n b's. To check equal counts for every n, the machine would need to remember how many a's it has seen, and n can grow without limit. The same limit blocks balanced parentheses, brackets and XML tags.

Real regex engines add backreferences and recursion, which go beyond this model. Standard regular expressions do not.

A finite-state transducer is the same machine with an output symbol on each arc. It maps one string to another, which is how morphological rules are compiled; see chapter 1.6. Tokenizers also use patterns; see chapter 1.4. Counting needs context-free grammars, covered in Unit 3.

Worked example

Question. Write a regular expression for the sheep language: a word is b, then at least two a, then !. Draw a deterministic automaton. Check baa!, baaa! and ba!.

  1. Alphabet {a,b,!}. After b, at least two a means b, a, then one or more a, then !. So the pattern is b a a+ !.
  2. Add anchors: ^baa+!$. ^ is start, $ is end, + means one or more of the previous a. The shortest match is baa!.
  3. Build a DFA with 5 states q0 to q4: q0 start, q4 final. Arcs: q0-b->q1, q1-a->q2, q2-a->q3, q3-a->q3, q3-!->q4.
  4. Check baa!: q0-b->q1-a->q2-a->q3-!->q4. q4 is final, so accepted = 1.
  5. Check baaa!: q0-b->q1-a->q2-a->q3-a->q3-!->q4. q4 is final, so accepted = 1.
  6. Check ba!: q0-b->q1-a->q2. Next is !, but q2 has no ! arc. The machine dies, so rejected = 0.

Answer. The pattern is ^baa+!$. The DFA has 5 states. baa! is accepted (1), baaa! is accepted (1), ba! is rejected (0).

Exam traps

  • Star * matches zero or more, so ab* matches a and ab; plus + is one or more.
  • A pattern without ^ and $ can match part of a string; ab matches abc.
  • Character classes match one character, not a word.
  • Standard regex cannot match anbn or balanced brackets; backreferences are an extension, not finite-state.
  • Escaping matters: . is any character, \. is a literal dot.

1.4 Tokenization, text cleaning and normalization

Tokenization cuts a raw character stream into the units every later step counts. Before the cut, text is cleaned and normalized, because one word can arrive in several byte-level forms and each form becomes a different token. Normalization fixes character form, sentence segmentation finds sentence boundaries, and tokenization finds word boundaries inside each sentence. Tagging, parsing, search and classification all inherit these decisions, and two systems compare fairly only when they cut text the same way.

You need: chapter 1.3 for the regular expressions and finite-state automata that tokenizer rules are written in.

Cleaning and normalization: make the bytes agree

Text arrives from chat logs, PDFs, web pages and OCR. Four kinds of noise repeat: wrong character encoding, several Unicode spellings of one character, markup and HTML entities, and inconsistent case, spacing, digits and dates. Cleaning removes what is not text. Normalization rewrites the remaining characters into one canonical form. Tokenization then cuts that form.

Encoding. A file is a sequence of bytes, and a decoder maps bytes to characters. UTF-8 maps each character to one to four bytes and is the safe default. Decode once, at the door, and keep text as Unicode strings; a wrong decode turns ₹ into mojibake no later rule can repair.

Unicode normalization. The accented e in café is either U+00E9 or e followed by U+0301; the full word is c a f plus that accented e. The two strings look identical and compare unequal, so the same word becomes two token types. Unicode defines normal forms: NFC composes, NFD decomposes. Pick NFC and apply it to every string before storing or comparing.

Python program.

import unicodedata

s = "cafe" + chr(0x301)   # e followed by a combining acute accent
nfc = unicodedata.normalize("NFC", s)
print(len(s))
print(len(nfc))
print(s == nfc)

Case, digits and accents. Case folding merges UPI, Upi and upi into one type and shrinks the vocabulary, but it deletes evidence a named-entity tagger needs, so many pipelines keep a cased copy. Replacing numbers, dates and money amounts with stand-ins such as [NUM] or [DATE] shrinks the vocabulary and helps a classifier generalise. Strip accents only when the task does not depend on them.

  1. Decode the bytes as UTF-8 and repair or drop undecodable bytes.
  2. Remove scripts, styles and HTML tags, then unescape HTML entities into plain characters.
  3. Normalize every string to NFC.
  4. Map curly quotes to straight ones, collapse runs of whitespace, delete zero-width characters.
  5. Choose case folding and stand-ins, and record the choice, because every later count depends on it.

Sentence segmentation and its hard cases

Sentence segmentation places a boundary between the last character of one sentence and the first of the next. Taggers, parsers and translation systems run sentence by sentence, so one bad split damages every stage after it.

The naive rule — an end mark (. ! ?) followed by a space begins a new sentence — over-splits abbreviations (Dr. Rao), initials (A. P. J.), ellipsis (...), and splits before a closing quote after a full stop. A second naive rule, any period ends a sentence, breaks on decimals (5.5, ₹1,250.50) and on site names (site.in), because those periods sit inside one number or address.

A rule-based splitter protects these cases: a period between two digits does not end a sentence, a single capital letter followed by a period is an initial, and a period inside a known e-mail or URL pattern is shielded. After protection, end mark plus whitespace plus a capital letter ends the sentence.

Not every script ends a sentence with a period. Devanagari and several other Indic scripts use the danda । (U+0964). A splitter that searches only for . ! ? returns a whole Hindi paragraph as one sentence. Add each script's own end marks to the rule set.

  1. Tag every character that could be an end mark: . ! ? and the script's own marks.
  2. Shield the hard cases: abbreviation list, digit-dot-digit, single initial, e-mail and URL patterns.
  3. Split at a surviving end mark followed by whitespace and a capital letter.
  4. Attach a closing quote or bracket after the end mark to the sentence it closes.

Word tokenization, and token types versus token counts

Word tokenization cuts a sentence into word-like units. Splitting on whitespace is the simplest rule and the first to break: in Chennai; and now. the punctuation stays glued to the word, and don't becomes one token covering two words.

A working rule set does four things. It makes each punctuation mark its own token. It keeps protected patterns whole: money (₹1,250.50), dates (3/5/24), times, e-mail addresses (rao@site.in), URLs, hashtags and each emoji. It splits clitics, so don't becomes do + n't and it's becomes it + 's. It decides about hyphens once — state-of-the-art as one token, four word tokens (state, of, the, art), or seven tokens if each hyphen is also a token — and applies that decision everywhere. Some syllabi call tokenization lexical analysis or segmentation.

Hindi, Tamil, Telugu, Bengali and Marathi mark word boundaries with spaces, as English does, so whitespace splitting works at the top level. Two things differ. Words agglutinate, so one whitespace token can carry a stem with case endings (and, in some languages, attached postpositions) that English writes separately; tokens get longer and the type vocabulary grows. And casing rules do nothing, because these scripts have no case. Script-aware tokenizers add the danda and the script's punctuation to the rules.

Token types and token counts. A token is one occurrence; a type is one distinct string. In the cat saw the dog there are five tokens and four types. Vocabulary size counts types; corpus size counts tokens. Normalization moves both: case folding merges types, splitting contractions adds tokens.

1.5 Stemming, lemmatization and stop-word removal

Three cheap operations shrink a token list before a model reads it. Stemming cuts endings by fixed rules, so cats becomes cat. Lemmatization returns the dictionary base form and needs a part of speech, so ran becomes run. Stop-word removal deletes very frequent tokens such as the and was. The aim is a smaller, denser vocabulary; the risk is losing meaning.

You need: Chapter 1.4 for the token list that this chapter reduces.

Word forms, stems and lemmas

A token is one occurrence of a word in running text. A word form is the exact string of that occurrence. The distinct strings in a corpus form its vocabulary, also called its types. A news corpus of a million running words has a few tens of thousands of types, and most are rare inflections of common words.

A stem is what is left after mechanical suffix stripping. It is a string, not necessarily an English word: studies gives studi. A lemma is the dictionary headword. It is always a real word and is tied to a part of speech: the lemma of studies is study.

Stemming is fast and crude; lemmatization is slower, needs a lexicon and a tag, and gives the right base form when the tag is right. Both cut the vocabulary and merge counts of related forms. Neither is reversible: from studi you cannot tell whether the source was studies or studied.

Stemming: cutting suffixes by rule

A stemmer is a fixed program, not a trained model. The Porter stemmer is the standard teaching example: it pushes the word through steps, each holding a list of suffixes.

  1. Set the current string to the input word.
  2. At each step, compare the string with that step's suffix rules, longest suffix first.
  3. Apply the first rule whose suffix matches and whose condition on the remaining stem is true; if none matches, go to the next step.
  4. After the last step, return the string.

m = number of VC sequences in C(VC)ᵐV

m is the measure of a stem. C is a consonant letter, V a vowel letter, and the bracket repeats m times. If a word ends in a consonant after the last V, treat a V as following: cat = CVC is treated as CVCV. m counts vowel-then-consonant pairs after the first consonant run. cat has m = 1; better (CVCCVC) has m = 2.

  • Step 1a, ies → i: ponies becomes poni, lies becomes li.
  • Step 1a: delete a final s only when the part before it contains a vowel not immediately before the s: cats becomes cat; gas stays gas; was stays was.
  • Step 1a, sses → ss: classes becomes class.

Lovins' stemmer, one of the earliest, matched a long table of endings, each with its own context condition. The Lancaster stemmer strips endings until no rule matches, so its stems are shorter and rougher.

Errors run two ways. Over-stemming merges words of different meaning: university and universe both reduce to univers. Under-stemming leaves related forms apart: lies becomes li while lie stays lie, so two forms of one lemma never meet.

Lemmatization: the dictionary form needs a tag

Lemmatization asks which headword a word form belongs to. The answer depends on part of speech, so the input is a pair of word form and POS tag, not a bare string. A lexicon or a morphological analyser supplies the mapping; Chapter 1.6 builds one with a finite-state transducer.

Saw as a verb is the past tense of see; saw as a noun is the headword saw. Feed the wrong tag and you get the wrong lemma.

Stop words: dropping the frequent and empty

A stop word is a token so frequent that it says little about topic. Articles, prepositions, auxiliaries and pronouns fill the top of every frequency list: the, a, of, is, was, and, to. A stop list is a set of such strings, and removal deletes every token in the set before counting.

List length is a design choice. Published English lists run from about 100 to a few hundred entries, and no single list suits all work. The list depends on the domain: patient says little in general text but is central in clinical notes, and an engine that drops the cannot answer a query about the band The Who. Build the list from your own frequency counts and read the top 100 by hand.

Negation is the dangerous case. Once not is deleted, not good and good become the same bag of words, so a sentiment system reads a negative review as positive. Keep not, no, never and none whenever the task depends on polarity. Other pipelines keep all stop words and let weighting such as TF-IDF, see Unit 5, push them down.

Removal shortens documents and shrinks the vocabulary, which speeds training and reduces sparsity. It also throws away word order and negation cues, so accuracy can fall. Measure both effects on your own task rather than trusting a default list.

1.6 Morphology and finite-state transducers

Morphology is the study of how words are built from smaller meaningful pieces. A finite-state transducer (FST) turns those building rules into a machine with two tapes: one tape holds a surface word, the other holds its lemma and features. The same machine runs forwards to generate a word and backwards to analyse one. This matters in search, spell checking, machine translation and Indian-language text processing, where one stem can take many endings.

You need: finite-state automata and lemmas and stems.

Morphemes, roots and affixes

A morpheme is the smallest unit that carries meaning or grammatical function. In cats, cat means the animal and -s marks plural, so there are two morphemes. A free morpheme can stand alone as a word, such as cat. A bound morpheme must attach to another morpheme, such as -s.

The root is the core morpheme that carries the main meaning. The stem is what remains when inflectional endings are removed; it may be a root or a root plus derivational affixes. An affix is a bound morpheme added to a stem. A prefix comes before (un-happy), a suffix after (walk-ed), an infix inside a root, and a circumfix has two parts around the stem.

Inflection keeps the same lexeme and adds a grammatical feature: cat to cats is plural; walk to walked is past tense. Derivation makes a new lexeme, often changing part of speech: nation to national. Compounding joins two or more free stems into one word: railway, toothbrush.

  • Regular plural: add -s, with y→ies after a consonant (city→cities) and -es after words ending in s, x, z, ch or sh (fox→foxes); x ends in the sibilant sound /s/.
  • Past tense: add -ed; e-drop before -ing (make→making), and consonant doubling in some words (stop→stopped).
  • Irregular forms are stored in a lexicon: goose→geese, go→went.

Morphological typology and Indian languages

An isolating language uses mostly one morpheme per word and shows grammar with word order and separate particles; Mandarin Chinese is often described this way.

An agglutinative language strings clear, separate suffixes or prefixes, each with one meaning; Tamil, Kannada and Turkish are examples.

A fusional language fuses several grammatical meanings into one ending; Latin and Hindi are examples.

A polysynthetic language packs many morphemes, often including several roots, into one word; Inuktitut is an example.

Dravidian languages such as Tamil and Kannada are agglutinative. A Tamil stem can take a long suffix chain for plural, case and person: maram 'tree', marangal 'trees', marangalil 'in the trees'. Kannada works similarly: mane 'house', manegalu 'houses', manegalalli 'in the houses'. Hindi is more fusional and uses postpositions after the noun: ladka 'boy', ladke 'boys', with separate words for case. Sanskrit has rich inflection and sandhi, systematic sound changes at morpheme and word boundaries; compounding is common. Compounding is productive across these languages.

Finite-state transducers for morphology

A finite-state transducer (FST) is a finite-state machine with two tapes. The upper tape is the input and the lower tape is the output. Each arc is labelled x:y: read x on the upper tape and write y on the lower tape. The symbol ε (epsilon) is the empty string, so ε:s reads nothing and writes s. A path from the start state to a final state maps one string to another; one path corresponds to one word pair.

T = T_lex ∘ T_rule

T_lex is the lexicon transducer that maps a lemma to its stem or irregular form; T_rule is the rule transducer for affixes and spelling changes; ∘ is composition, so the output tape of T_lex becomes the input tape of T_rule.

Build morphology in two layers. The lexicon transducer lists stems and irregular forms: cat:cat, fox:fox, goose:geese. The rule transducer adds regular endings and handles spelling: ε:s for most nouns, ε:es after a sibilant, and a change such as y:ies. Compose the two transducers. The composed machine maps fox to foxes without a special rule for every word.

Typical rule for English plural: if the stem ends in s, x, z, ch or sh, write es; if it ends in consonant + y, change y to ies; otherwise write s. Irregular forms stay on single arcs in the lexicon transducer.

Analysis, generation and ambiguity

Run the same FST in two directions. Generation starts with a lemma and features and writes the surface word: fox + plural → foxes. Analysis starts with the surface word and returns a lemma plus features: cats → cat + plural. For analysis, walk arcs in reverse and swap the two labels.

Analysis can be ambiguous. saw may be the noun saw (a tool) or the past tense of see. found may be the past tense of find or the present tense of the verb found (to establish). A transducer returns all paths that reach a final state; later stages choose using context. This is why morphological analysis feeds tagging; it does not replace it (see Unit 2).

Only a few universities teach automatic morphology learning. The aim is to induce stems, affixes and paradigms from an unannotated corpus by finding repeated substrings and their contexts. It helps low-resource languages with no morphology lexicon, but the learned rules need checking.

  • Do not apply English -s or y→ies rules to Tamil or Hindi. Tamil uses suffix chains; Hindi often uses postpositions.
  • A transducer is bidirectional. The same machine is an analyser and a generator; do not build two unrelated diagrams.
  • Irregular forms such as goose→geese are stored in the lexicon, not produced by the regular plural rule.

1.7 Spelling correction and minimum edit distance

Minimum edit distance is the smallest number of single-character insertions, deletions and substitutions that turns one string into another. It exists because typing, speech recognition and translation all make small string errors, and a corrector needs a cheap way to compare a wrong string with a right one. It is used in spelling correction, in aligning words between a source sentence and its translation, and in scoring speech or translation output against a reference. The same table also gives the character alignment that explains each edit.

You need token boundaries from Chapter 1.4 and word forms from Chapter 1.5.

Operations, cost and distance

An edit operation changes one character position. There are three basic operations. Insertion adds one target character. Deletion removes one source character. Substitution replaces one source character by one target character. Each operation has cost 1 by default. The minimum edit distance between strings s and t is the lowest total cost of a sequence that turns s into t. With unit costs this is the Levenshtein distance. A fourth operation, transposition, swaps two adjacent characters at cost 1. Adding it to the three basic operations gives Damerau–Levenshtein distance. The simple table version that edits no substring twice is the restricted (optimal string alignment) distance, and it can break the triangle inequality; the full Damerau–Levenshtein distance keeps the metric properties.

  • d(s, s) = 0, because no operation is needed.
  • d(s, t) = d(t, s), so distance is symmetric.
  • d(s, u) ≤ d(s, t) + d(t, u), the triangle inequality.

These properties let edit distance act as a metric, so it can index words and prune candidates. For example, cat to cart is distance 1 by one insertion. The typo teh to the is distance 2 under Levenshtein distance, but 1 under Damerau distance because one transposition fixes it.

Prefix table and recurrence

Number the source characters a1…am and target characters b1…bn. Let D[i][j] be the distance from the first i source characters to the first j target characters. The first row and column come from empty strings: D[i][0] = i and D[0][j] = j.

D[i][j] = min( D[i−1][j] + 1, D[i][j−1] + 1, D[i−1][j−1] + c )

D[i][j] is the minimum edit distance from the first i source characters to the first j target characters; c = 0 when the two current characters are equal and c = 1 otherwise.

  1. Fill row 0 as 0, 1, 2, …, n and column 0 as 0, 1, 2, …, m.
  2. Fill the remaining cells left to right, top to bottom.
  3. For each cell, take the smallest of three values: the cell above plus 1 for a deletion, the cell on the left plus 1 for an insertion, and the diagonal cell plus c for substitution or copy.
  4. The bottom-right cell D[m][n] is the required distance.
  5. Backtrace from the bottom-right cell. A diagonal move copies or substitutes, an upward move deletes a source character, and a left move inserts a target character.

Correcting spelling errors

Spelling errors come in two kinds. A non-word error produces a string that is not in the dictionary, such as recieve. A real-word error produces a valid word in the wrong place, such as there for their. For non-word errors, a corrector checks the token against a dictionary, generates candidates within edit distance 1 or 2, and ranks them. Candidate generation is cheap: for a word of length L, distance 1 allows about 26(L+1) insertions, about 26L substitutions, L deletions and L−1 transpositions, roughly 54L edits in all. Distance 2 is much larger, so pruning matters. Ranking uses word frequency and typo probability; the full probabilistic score with an n-gram language model is Unit 2.

For real-word errors, edit distance alone cannot help because the wrong word is already a word. The system needs context and a confusion set, for example {there, their, they're}. A context model chooses the likely word. Edit distance also scores machine translation and speech output: compare a produced string with a reference and count edits; lower distance is better. Machine translation is Unit 6.

Answer. The minimum edit distance is 1 edit operation, with one alignment c a t → c a r t where r is inserted.

Exam traps

  • When the two characters match, the diagonal cost is 0. Writing 1 inflates every matching cell and the final distance.
  • The backtrace counts operations, not cells visited. A long diagonal of matching characters still adds 0 to the distance.
  • Moving up in the table deletes a source character; moving left inserts a target character. Swapping these labels reverses the alignment explanation.
  • A real-word error such as there for their is already in the dictionary, so a distance-0 dictionary lookup never flags it; context is needed.
  • Levenshtein distance treats teh to the as 2. Damerau distance with a transposition gives 1; do not mix the definitions.

Check yourself

Remember List the three basic edit operations and their default cost. 2 marks

Insertion, deletion and substitution. Each costs 1 by default.

Understand Why is the substitution cost 0 when the two current characters match? 3 marks

No character change is needed. The diagonal move copies the same character, so it adds 0 to the distance.

Apply Compute the Levenshtein distance from book to back. Give the final row of the table. 4 marks

The final row is 4, 3, 3, 3, 2. The bottom-right value is 2, from substituting o to a and o to c while copying b and k.

Analyze Why can edit distance alone not fix the sentence 'I will go to there house'? 4 marks

There is a valid word, so distance 0 to the dictionary entry there. The correct word their is distance 2 away, but distance alone prefers the wrong word. A context model and confusion set are needed.

Analyze If d(A, B) = 2 and d(B, C) = 3, what is the strongest upper bound on d(A, C)? 2 marks

d(A, C) ≤ 5, and d(A, C) ≥ |2 − 3| = 1, so the actual value lies between 1 and 5.

Remember What extra operation defines Damerau distance? 2 marks

Transposition of two adjacent characters, at cost 1.

Understand Why does candidate generation at edit distance 2 need pruning in a spell checker? 4 marks

The number of candidates grows quickly with word length because single and double edits include many nonsense strings. Ranking by word frequency and typo probability removes most of them.

Beyond the syllabus

Not for the exam. Production spell checkers use a noisy-channel or neural ranker over edit-distance candidates, not edit distance alone. Search next for Levenshtein automata, BK-trees and SymSpell for fast dictionary search. Research versions add weighted edits, phonetic costs and context. Word alignment in machine translation uses edit distance as a simple baseline before statistical alignment. Damerau distance and longest common subsequence are close relatives.

1.8 Building corpora from text sources and web scraping

A corpus is a fixed, cleaned, documented collection of real text, gathered so that every later model is trained and compared on the same data. Without one, two teams report accuracy on different sentences and neither number means anything. Sources include plain text, HTML pages, PDFs, subtitles, newspaper archives, government portals, Wikipedia dumps, public web crawls and speech transcripts. Only a few universities teach corpus building as a named topic, yet every project in this unit starts here.

You need the normalization and tokenization decisions of Chapter 1.4, because extracted text must be cut into tokens before any count is meaningful.

Sources, formats and permission

A corpus starts from text a computer can read. Plain .txt is simplest. HTML hides text inside markup. PDFs store glyph positions, so extraction may reorder words. Subtitles come as timed blocks. Wikipedia dumps and public web crawls, such as Common Crawl, arrive already packaged. Speech transcripts first need a recognizer, whose errors enter your corpus.

Permission comes before code. Copyright protects expression, not facts. Check the licence. robots.txt at a site root lists paths a crawler should avoid for a given User-agent; it is a convention, not a law, and ignoring it can get your address blocked. Terms of service may forbid scraping. Personal data such as names, phone numbers and identity numbers must be removed or never collected. Institutional ethics approval may be required before storing text about people.

  • Send one request every few seconds, not ten at once.
  • Identify your crawler in the User-agent header.
  • Honour Retry-After and cache pages so a rerun does not hit the server again.

From a URL to clean text

  1. Pick URLs from sitemaps or link lists and record each one.
  2. Fetch with a delay and store the raw HTML.
  3. Parse HTML with a parser, never with a regular expression.
  4. Select content elements: article, main, headings.
  5. Extract text, decode as UTF-8, unescape entities.
  6. Drop boilerplate: menus, footers, ads, cookie notices.
  7. Remove near-duplicates: split each document into 5-word shingles, hash them, compare Jaccard overlap.
  8. Filter by language.
  9. Hand-check a small random sample.
  10. Split into train, development and test.

A shingle is a contiguous run of 5 tokens from a document. Two documents are compared by Jaccard overlap = |A ∩ B| ÷ |A ∪ B|, where A and B are their shingle sets. Values near 1 mean near-duplicates.

Split first. Any threshold a cleaning step needs, such as a language-filter score, must be chosen on training documents only. Steps that need no threshold, such as boilerplate removal, may run on all documents. Near-duplicates must be removed before the split; otherwise a copy of a test document sits in training and inflates the score.

Storing the corpus

Store one document per line in JSONL, with fields id, url, date and text. A CSV with a text column works for small corpora. Plain files need a manifest listing filename, source, licence and split. Record the random seed and the split counts. Vocabulary size is the number of distinct word types, counted after normalization such as lowercasing. Because the same words repeat across a corpus, it is much smaller than the token count: 208,000 tokens may come from only a few thousand types. Some syllabi add word association measures, pointwise mutual information PMI(w₁,w₂) = log₂[P(w₁,w₂)/(P(w₁)P(w₂))] and the t-score, to rank collocations; see Unit 5.

Worked example

Question. You scrape 400 pages at an average of 650 words per page. Each word takes 5 characters plus 1 space in storage. Find the word-token count and the raw size in MB. Boilerplate removal then deletes 20 percent of the words; find the remaining tokens and size. Use 1 MB = 1,000,000 characters.

  1. Token count = 400 × 650 = 260,000 word tokens.
  2. Characters per token = 5 + 1 = 6.
  3. Raw characters = 260,000 × 6 = 1,560,000.
  4. Raw size = 1,560,000 ÷ 1,000,000 = 1.56 MB.
  5. Kept fraction = 1 − 0.20 = 0.80.
  6. Kept tokens = 0.80 × 260,000 = 208,000.
  7. Kept characters = 208,000 × 6 = 1,248,000.
  8. Kept size = 1,248,000 ÷ 1,000,000 = 1.248 MB.

Output

raw tokens = 260000
raw characters = 1560000
raw size = 1.56 MB
kept tokens = 208000
kept characters = 1248000
kept size = 1.248 MB

Answer. The raw corpus has 260,000 word tokens and 1.56 MB; after boilerplate removal it has 208,000 word tokens and 1.248 MB.

Exam traps

  • Counting HTML tags as text; tags inflate the vocabulary with fake tokens such as div and span.
  • Ignoring robots.txt and request rate limits, then wondering why the server blocks your address.
  • Deduplicating after the train and test split, so near-copies of test documents sit in training.
  • Confusing word-token count with vocabulary size; 208,000 tokens may come from only a few thousand distinct word types.
  • Decoding UTF-8 bytes as Latin-1 and storing mojibake without noticing.

Check yourself

Remember What is robots.txt and what does it contain? 2 marks

A file at a site root with User-agent and Disallow lines, telling crawlers which paths to avoid.

Understand Why split into train, development and test before tuning a language filter? 3 marks

Tuning on test data leaks test information, so the reported score is too high.

Apply You scrape 300 pages of 700 words each; a word takes 5 characters plus 1 space. Boilerplate removal deletes 10 percent. Find tokens, raw MB and kept MB. 4 marks

Tokens = 300 × 700 = 210,000. Raw characters = 210,000 × 6 = 1,260,000, so 1.26 MB. Kept = 0.9 × 210,000 = 189,000 tokens; 189,000 × 6 = 1,134,000 characters, so 1.134 MB.

Analyze Two documents have 5-word shingle sets of sizes 120 and 100, with 20 shingles shared. Compute Jaccard overlap and say whether they are near-duplicates. 4 marks

Jaccard = 20 ÷ (120 + 100 − 20) = 20 ÷ 200 = 0.10. That is low overlap, so they are not near-duplicates.

Understand Why must boilerplate be removed before counting words? 2 marks

Menus, footers and cookie notices repeat on every page, so they inflate counts and teach the model site layout rather than content.

Remember Name two storage formats for a corpus and one field each should hold. 2 marks

JSONL with one document per line holding id, url, date, text; or CSV with a text column.

Beyond the syllabus

Not for the exam. Large projects store raw crawls as WARC files and deduplicate with MinHash or SimHash at billion-page scale. Data cards record source, licence, date and known biases. Search terms: Common Crawl, WARC, MinHash deduplication, data card, corpus manifest.

Takeaways

  1. NLP has moved from hand-written rules, to counts over corpora, to learned representations, and each stage still solves problems the others handle badly.
  2. Language is analysed in layers — phonetics, phonology, morphology, syntax, semantics, pragmatics, discourse — and each layer brings its own kind of ambiguity.
  3. A regular expression denotes a set of strings, and every such set has an equivalent finite-state automaton that decides membership in one pass.
  4. Tokenization and normalization are decided together: change the casing or the punctuation rule and the token list changes.
  5. Stemming is fast and crude, lemmatization is slower and correct; stop-word removal helps retrieval but can destroy negation and sentiment.
  6. A finite-state transducer compiles morphological rules into a two-tape machine that analyses a word and generates it back, both from the same rule set.
  7. Minimum edit distance is the cheapest sequence of single-character edits; it underlies spelling correction, word alignment and fuzzy matching.
  8. A corpus is only useful if it is fixed, cleaned and documented, so every later model is trained and compared on the same data.

Glossary

Affix
A bound morpheme attached to a root: prefix, suffix, infix or circumfix.
Agglutinative language
A language whose words are long, regular chains of separately meaningful morphemes.
Compounding
Joining two or more free morphemes into one word.
Corpus
A fixed, documented body of real text used for training and evaluation.
Derivation
Affixation that creates a new word, often of a different class.
Deterministic
A machine with exactly one transition per state and symbol, so its path is fixed.
Finite-state automaton
A five-tuple of states, alphabet, transitions, start state and accept states that accepts or rejects strings.
Finite-state transducer
A finite-state machine that reads one tape and writes another, used for morphological analysis and generation.
Fusional language
A language whose single suffix may encode several grammatical features at once.
Inflection
Suffixation that adds grammatical features without changing word class.
Isolating language
A language with almost no inflection; grammatical information is carried by separate words.
Lemma
The dictionary base form under which inflected forms are listed.
Minimum edit distance
The cheapest total cost of single-character edits that turns one string into another.
Morpheme
The smallest meaningful unit of a word.
NLP
The field that builds systems which read, interpret or produce human language.
Non-word error
A misspelling that is not a valid word, so a dictionary check finds it.
Normalization
Rewriting raw text into a standard form before further processing.
Regular expression
A pattern that denotes a set of strings.
Root
The core morpheme that carries the main meaning of a word.
Stem
The part of a word left after suffix stripping, not necessarily a word.
Stop word
A very frequent word dropped from an index or a model input.
Token
One unit of text after segmentation, usually a word or punctuation mark.
Tokenization
The step that cuts a character stream into tokens.
Transposition
Swapping two adjacent characters, an edit operation in the Damerau variant.
Type
A distinct token form; the number of types is the vocabulary size.
