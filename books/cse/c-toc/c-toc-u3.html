3.1 Context-free grammars: definitions and examples

A context-free grammar is a set of rewriting rules plus a start symbol. Rewrite the start symbol until no symbol can be rewritten; the ordinary letters left form a string of the language. This idea explains why programming languages nest brackets, blocks and expressions without limit. Compilers build parse trees from such grammars, and the grammar yacc, bison and ANTLR read is the same object, written in BNF or EBNF with declarations and actions added.

You need Unit 1: alphabets, strings, languages and the Kleene star, from alphabets, strings and formal languages.

A grammar is a four-part rewriting machine

A context-free grammar produces strings by rewriting. Start with one symbol, replace it using a rule, and keep replacing until only ordinary letters remain. Those letters form a string of the grammar's language.

G = (V, T, P, S)

G is the grammar; V is the finite set of variables (nonterminals), written in capitals such as S, A, B; T is the finite set of terminals, the letters of final strings, written in lowercase such as a, b, or as words such as id; P is the finite set of productions; S is the start symbol, and S ∈ V. V and T are finite, nonempty and disjoint.

The union V ∪ T is the alphabet of the grammar. Every production has one variable on the left and any string of variables and terminals on the right.

A → α, with A ∈ V and α ∈ (V ∪ T)*

A is the single variable being replaced; α (alpha) is the replacement string, possibly empty; (V ∪ T)* means any finite sequence of variables and terminals, including the empty sequence.

The name context-free describes the left side. A rule replaces A wherever A appears. Nothing is tested about symbols beside A. A context-sensitive rule such as aAb → aXb is not allowed in a CFG, because it demands that A be between a and b.

Why the model exists: nesting. A finite automaton has a fixed number of states, so it cannot compare a count on the left with a count on the right. The pair of rules S → aSb | ε adds one a at the front and one b at the back per step, and S → ε ends with the counts equal. Nested brackets, nested if-else chains and nested arithmetic need exactly this power.

Shorthand, then five grammars

Two shorthand forms keep grammars short. The bar | separates alternatives, so S → aSb | ε stands for two productions. The symbol ε (epsilon) is the empty string, of length zero. Round brackets group symbols on a right side: with B → b | c, the rule A → a(B)c is shorthand for A → abc | acc.

  • Equal a's then b's: S → aSb | ε gives {aⁿbⁿ : n ≥ 0}. In order of length: ε, ab, aabb, aaabbb.
  • Balanced round brackets: S → (S)S | ε gives every bracket string that closes properly, such as ()() and (()). Here ( and ) are terminals of the language, not the grouping shorthand. The string )( is not generated.
  • Palindromes over {a, b}: S → aSa | bSb | a | b | ε gives strings that read the same both ways, such as abba and baab.
  • Arithmetic expressions: E → E + T | T, T → T × F | F, F → (E) | id. Here id is a number or variable name. The three levels force × to bind tighter than +, and F reaches the brackets.
  • if-else in C: S → if (C) S | if (C) S else S | other. C is a condition and other is any simple statement. This grammar is ambiguous for the dangling else, as 3.3 shows.

Derivation steps and the language

A derivation is the written record of rewriting. Write u ⇒ v when one step turns string u into string v: one variable inside u is replaced by the right side of one of its productions. Write u ⇒* v for zero or more such steps; the star is the Kleene star applied to the arrow.

L(G) = { w ∈ T* : S ⇒* w }

L(G) is the language generated by G; w ranges over strings of terminals only; S ⇒* w means the start symbol reaches w in finitely many steps.

  1. Write the start symbol S.
  2. Pick any variable and any production for it; replace that one occurrence.
  3. Repeat until no variables remain.
  4. The remaining terminal string belongs to L(G).

Which variable you expand, and in what order, does not change the set of strings you can reach. Two orders of the same expansion give two derivations of the same string, and drawn as a tree they are the same tree. Trees are the subject of 3.2.

Only a few universities teach the phrase "type 2 grammar" in the first course: in the Chomsky hierarchy a type 2 grammar is exactly a context-free grammar (see 3.9). BNF in compiler books is the same object with ::= instead of → and angle brackets around variables.

Exam traps

  • The grammar is not the language. {aⁿbⁿ : n ≥ 1} is generated by S → ab | aSb as well as by S → aSb | ε with the ε case unused; to get all of {aⁿbⁿ : n ≥ 0} from a different rule list, use S → A, A → aAb | ε. The bar is shorthand for two productions, never a character of the generated string.
  • ε is a string, not a letter inside a derivation. S → ε erases S; it does not leave ε in the string. L(G) contains ε exactly when S ⇒* ε.
  • A production must be context-free: the left side is exactly one variable. Writing aS → ab or SA → aA is not allowed, and examiners deduct marks for it without comment.
  • Each step replaces exactly one occurrence of one variable. Replacing every S at once, or assuming two expansion orders give two different parse trees, is wrong.
  • L(G) holds terminal strings only. A string with a variable still in it is an intermediate sentential form, not a word of the language.

3.2 Derivations and parse trees

A derivation is the step-by-step rewriting of a string using grammar rules. A parse tree draws the same rewriting as a tree. The tree shows grouping; the derivation shows order. Compilers build trees because the tree is what the next phase needs. This chapter defines both views and connects them.

You need: 3.1 for grammar notation, and Unit 1 for strings and concatenation.

Derivation: rewriting with rules

A context-free grammar has productions such as A → α. A variable (nonterminal) is a symbol that can be replaced. A terminal is a symbol that cannot. A derivation starts from the start symbol S. At each step, choose one variable in the current string and replace it by the right side of one of its productions. The current string is called a sentential form. It may contain both terminals and variables.

u A v ⇒ u α v

u and v are strings of terminals and variables; A is a variable; A → α is a production.

The symbol ⇒ means one rewriting step. The symbol ⇒* means zero or more steps. A derivation of a string w is a chain S ⇒ ... ⇒ w. A leftmost derivation always expands the leftmost variable in the sentential form. A rightmost derivation always expands the rightmost variable. For the grammar E → E + T | T, T → T × F | F, F → ( E ) | id, the string E + T has E as its leftmost variable and T as its rightmost variable.

Parse tree: the same rewriting drawn

A parse tree for a grammar G has root S. Each internal node is labeled by a variable A. If the children of that node are labeled X1, X2, ..., Xk from left to right, then A → X1 X2 ... Xk must be a production of G. Leaves are labeled by terminals or by ε. The yield (also called the frontier) is the string of leaf labels read left to right; an ε leaf adds the empty string.

A subtree is a node together with all its descendants. It is itself a parse tree for the variable at that node. The height of a tree is the number of edges on the longest path from root to a leaf. A tree with one node has height 0.

Theorem: w ∈ L(G) exactly when G has a parse tree with root S and yield w. Matching theorem: every parse tree comes from exactly one leftmost derivation and exactly one rightmost derivation of its yield. The leftmost derivation is forced: at each step the next variable to expand is the leftmost one still present. The rightmost derivation is forced the same way from the right.

Why parsers store trees

The number of derivations of a string grows with the number of variables. Independent variables can be expanded in different orders. All those orders can give the same tree. A parser must recover grouping, not rewriting order. That is why a compiler stores a parse tree or a syntax tree.

In id + id × id, the leftmost derivation takes 8 steps and the rightmost takes 8 steps. Both give one tree. The tree places × below +, so multiplication is done first. A compiler can walk the tree bottom-up: evaluate the two id leaves under ×, multiply them, then add the left id.

To prove ambiguity you need two different parse trees or two different leftmost derivations for the same string. Two ordinary derivations that differ only in the order of independent expansions use the same tree and prove nothing.

Worked example

Question. Grammar: E → E + T | T, T → T × F | F, F → ( E ) | id. (a) Give a leftmost derivation of id + id × id. (b) Give a rightmost derivation. (c) Count the steps in each. (d) Draw the parse tree.

  1. Leftmost derivation: always expand the leftmost variable.
  2. E ⇒ E + T ⇒ T + T ⇒ F + T ⇒ id + T ⇒ id + T × F ⇒ id + F × F ⇒ id + id × F ⇒ id + id × id. Count arrows: 8 steps.
  3. Rightmost derivation: always expand the rightmost variable.
  4. E ⇒ E + T ⇒ E + T × F ⇒ E + T × id ⇒ E + F × id ⇒ E + id × id ⇒ T + id × id ⇒ F + id × id ⇒ id + id × id. Count arrows: 8 steps.

Exam traps

  • Reading the tree from the top down as if that were the derivation order. The tree fixes grouping only; the leftmost or rightmost order is a separate choice.
  • Using two ordinary derivations that differ only in expansion order to claim ambiguity. That proves nothing; compare trees or leftmost derivations.
  • Calling every sentential form a terminal string. A sentential form may still contain variables; only a yield with no variables is a terminal string.
  • Confusing height with number of nodes. Height counts edges on the longest root-to-leaf path; a single-node tree has height 0.

3.3 Ambiguity in grammars and inherent ambiguity

A grammar is ambiguous when one terminal string has two different parse trees. The string then has two meanings, and a parser cannot choose between them. This matters because programming-language grammars must give every program exactly one tree, so the compiler builds the code you intended. This chapter defines ambiguous grammar, ambiguous string and unambiguous grammar, shows the classic expression grammar with two trees for id + id × id, fixes it by layering precedence and associativity, and explains inherent ambiguity: a language is inherently ambiguous when every grammar for it is ambiguous.

You need: 3.2 Derivations and parse trees for parse trees and leftmost derivations.

Ambiguous grammar, ambiguous string

A context-free grammar G is ambiguous if at least one terminal string w in L(G) has two different parse trees. The string w is then an ambiguous string of G. G is unambiguous if every string in L(G) has exactly one parse tree. Two parse trees always give two different leftmost derivations, so the two ideas match.

G: E → E + E | E × E | ( E ) | id

E is the only variable; id is an identifier terminal; +, ×, ( and ) are terminals.

Take the string id + id × id. Tree A uses the root rule E → E + E; its left child is id and its right child is id × id. Tree B uses the root rule E → E × E; its left child is id + id and its right child is id. Both trees have the same leaves in the same order, so both derive the one string. Thus G is ambiguous, and id + id × id is an ambiguous string of G.

Layered grammar: precedence and associativity

E → E + T | T    T → T × F | F    F → ( E ) | id

E is expression, T is term, F is factor; id is an identifier.

A string at E level is a sum of one or more terms. A term is a product of one or more factors. A factor is an id or a parenthesised E. A plus can appear only at E level and a times only at T level, so × binds tighter than +. The left recursion E → E + T makes + left associative; T → T × F makes × left associative. Some syllabi call this conversion 'ambiguous CFG to unambiguous CFG'.

For id + id × id the only tree has E → E + T at the root. The left E becomes id. The right T becomes T × F, with both T and F becoming id. The leaves are id, +, id, ×, id. With id values 1, 2, 3 the value is 1 + 2 × 3 = 7.

  1. Put the lowest-precedence operator in the start variable, for example E for +.
  2. Add a new variable for the next higher precedence, for example T for ×; let E use T.
  3. Continue down to atoms: F → ( E ) | id.
  4. Use left recursion for left associativity and right recursion for right associativity.
  5. If one rule is needed in two places, add a new start symbol and keep the old variable for the inner use.

Inherent ambiguity

A context-free language L is inherently ambiguous if every context-free grammar that generates L is ambiguous. This is a property of L, not of a chosen grammar.

L = { aⁱ bʲ cᵏ | i = j or j = k, with i, j, k ≥ 0 }

aⁱ means i copies of a, bʲ means j copies of b, and cᵏ means k copies of c.

A grammar must provide one mechanism that matches a with b and another that matches b with c. Strings with i = j and j = k, that is aⁿbⁿcⁿ, need both mechanisms at once. Any single grammar has to overlap them, so some string gets two trees.

L = { aⁿ bⁿ cᵐ dᵐ | n, m ≥ 0 } ∪ { aⁿ bᵐ cᵐ dⁿ | n, m ≥ 0 }

The two parts share strings such as aⁿbⁿcⁿdⁿ when n = m, and the same overlap forces ambiguity.

The full proofs use the pumping lemma for context-free languages (see 3.6); they are not asked in this chapter. For a given CFG, deciding whether it is ambiguous is undecidable; Unit 6 covers that result.

Worked example

Question. Consider the grammar G: E → E + E | E × E | ( E ) | id. The string is id + id × id, where the first id is 1, the second id is 2 and the third id is 3. (a) Give the two parse trees by their root rules. (b) Compute the value each tree gives. (c) Is G ambiguous? (d) Give the value from the unambiguous layered grammar.

  1. Label the leaves left to right: id₁ = 1, id₂ = 2, id₃ = 3.
  2. Tree A uses root E → E + E. Left subtree is id₁, value 1. Right subtree is id₂ × id₃, value 2 × 3 = 6. Total value 1 + 6 = 7. Grouping: (1) + (2 × 3).
  3. Tree B uses root E → E × E. Left subtree is id₁ + id₂, value 1 + 2 = 3. Right subtree is id₃, value 3. Total value 3 × 3 = 9. Grouping: (1 + 2) × (3).
  4. Both trees derive the same terminal string id + id × id, so G is ambiguous by definition.
  5. The layered grammar E → E + T | T, T → T × F | F, F → ( E ) | id has only one tree for this string: plus at the E root and times inside T. Its value is 1 + 2 × 3 = 7.

Answer. Tree A gives 7, tree B gives 9, so G is ambiguous; the layered unambiguous grammar gives 7.

Exam traps

  • Two different derivations of the same tree are not ambiguity. Only two different parse trees count; compare leftmost derivations.
  • An ambiguous grammar does not make its language inherently ambiguous. The language may have another unambiguous grammar.
  • Precedence levels do not fix associativity by themselves. Use left recursion for left associativity and right recursion for right associativity.
  • Do not drop the factor rule F → ( E ) | id when layering; without it the grammar cannot derive parenthesised strings or identifiers.

3.4 Simplifying CFGs: useless, epsilon and unit productions

Hand-written grammars carry baggage: nullable variables, unit chains, unreachable symbols. All legal, none helpful. Simplifying a context-free grammar removes this baggage and keeps the language unchanged. Parsers and normal-form constructions want the short version, so clean-up runs first. Three jobs: ε-rules, unit rules, useless symbols — in that order.

You need: 3.1 for productions and derivations, and 3.2 for the meaning of ⇒*.

Nullable variables and ε-rules

A variable A is nullable if A ⇒* ε: some derivation from A ends in the empty string ε, the string of length 0.

Find the nullable set by repeating two rules. If A → ε, A is nullable. If A → X₁X₂…Xₖ and every Xᵢ is nullable, A is nullable, because each Xᵢ can be erased.

  1. Compute the nullable set by these two rules.
  2. For every rule A → α, add a copy for each non-empty way of erasing nullable symbols from α.
  3. Delete all ε-rules.
  4. If ε ∈ L(G) and S appears on no right side, add S → ε. If S appears on a right side, add a new start S₀, add S₀ → S and S₀ → ε, make S₀ the start, and do not add S → ε.
A → α  ⇒  add A → α′ for every non-empty α′ got by erasing nullable symbols from α

A is a variable, α is a string of variables and terminals, α′ is non-empty and is α with some nullable symbols removed.

A derivation that used A ⇒ ε can use the shorter right side instead. The ε-step disappears; the language does not.

Removing unit productions

A unit production is A → B with B a single variable. It swaps one variable for another and produces no terminal, so it never helps form the final string.

Call (A, B) a unit pair if A ⇒* B using only unit rules. Every variable pairs with itself: (A, A).

  1. List all unit rules; put (A, A) for every variable A.
  2. For each unit rule A → B, add (A, B).
  3. Close the set: if (A, B) and (B, C) are pairs, add (A, C). Repeat.
  4. For each pair (A, B), add A → α for every non-unit rule B → α.
  5. Delete all unit rules.

A chain of unit steps collapses to one step. The grammar has no unit rules and the same language.

Useless symbols, and why this goes last

A symbol is generating if it derives some terminal string: A ⇒* w with w in Σ*. It is reachable if it appears in some derivation from S. It is useful only if both. Otherwise it can never appear in a finished terminal derivation.

  1. Mark every terminal generating. Mark A generating if some rule A → α has all symbols of α generating. Repeat.
  2. Delete every rule that mentions a non-generating symbol.
  3. Mark S reachable. If A is marked and A → α, mark every symbol of α. Repeat.
  4. Delete every rule that mentions an unreachable symbol.

Order matters. Removing ε-rules and unit rules can leave variables with no rules or no path from S. Those passes create useless symbols, so clear useless symbols last.

Theorem. For every context-free grammar G with L(G) nonempty, there is a grammar G′ with no ε-rules except possibly S → ε, no unit rules, and no useless symbols, with L(G′) = L(G). If L(G) is empty, handle that language separately.

Worked example

Question. Simplify the grammar G below completely. Show the nullable set, the ε-rule removal, the unit pairs, and the useless-symbol removal. S → AB | a A → aA | ε B → bB | b C → cC | c D → aDb

  1. Nullable set. A → ε makes A nullable. S → AB needs B nullable too; it is not. Nullable = {A}.
  2. Add erased versions. S → AB gives S → B. A → aA gives A → a. No other rule contains a nullable symbol.
  3. Delete ε-rules. Delete A → ε. ε ∉ L(G), so no S → ε. Now: S → AB | B | a; A → aA | a; B → bB | b; C → cC | c; D → aDb.
  4. Unit pairs. Only unit rule is S → B. Pairs: (S,S), (A,A), (B,B), (C,C), (D,D), (S,B).
  5. Copy and delete. From (S,B), copy B's non-unit rules: S → bB, S → b. Delete S → B. Now: S → AB | a | bB | b; A → aA | a; B → bB | b; C → cC | c; D → aDb.
  6. Generating. Terminals a, b, c generate. A generates via A → a; B via B → b; S via S → a; C via C → c. D → aDb contains D, so D is non-generating. Delete D.
  7. Reachable. From S: S → AB reaches A and B. A → aA reaches A; B → bB reaches B. C is never reached. Delete C.
  8. Final. S → AB | a | bB | b; A → aA | a; B → bB | b. It has 8 productions, no ε-rules, no unit rules, no useless symbols.

Output

0 0 8

Answer. Final grammar: S → AB | a | bB | b, A → aA | a, B → bB | b. It generates L(G) and has 8 productions, 0 nullable variables and 0 non-reflexive unit pairs.

Exam traps

  • Deleting useless symbols first. Epsilon and unit removal create some unreachable and non-generating symbols; clear useless last.
  • Deleting S → ε when ε ∈ L(G). Keep one ε-rule, but if S appears on a right side move it to the new start: S₀ → ε, not S → ε.
  • Forgetting reflexive unit pairs (A, A). They add nothing new but the closure needs them.
  • Adding erased versions for empty results. A → ε is handled by deletion, not re-added.
  • Confusing generating with reachable. D → aDb is reachable but non-generating; C is generating but unreachable.

3.5 Chomsky and Greibach normal forms

A normal form is a promise about the shape of every production. Chomsky normal form allows only A → BC or A → a. Greibach normal form allows only A → aα. The promise removes cases from proofs and algorithms: a check on a rule has two or three shapes, not dozens. CYK membership needs CNF (see 3.8). PDA to CFG conversions use the GNF idea (see Unit 4, Pushdown Automata). CNF covers every context-free language; GNF covers every context-free language without ε, and Section 3 shows how ε is handled. A converted grammar can be larger than the one you started with.

You need the simplification steps from 3.4: removing useless symbols, ε rules and unit rules.

Chomsky normal form: two rule shapes

Write variables as capital letters A, B, S and terminals as lowercase a, b. A context-free grammar is in Chomsky normal form (CNF) when every production has one of two shapes: A → BC, with exactly two variables on the right, or A → a, with exactly one terminal. There are no unit rules A → B and no ε rules, with one exception: S → ε is allowed if the start variable S never appears on the right side of any rule. That exception lets the grammar generate the empty string without breaking the two shapes.

The conversion starts from the simplified grammar of 3.4. First, for every terminal a that appears in a right side of length two or more, add a new variable and replace a by it. A rule A → aB becomes A → C B and C → a. A rule A → ab becomes A → C D, C → a, D → b, because two terminals are not allowed. Second split every right side of length three or more. For A → BCDE, introduce a fresh variable X and write A → B X and X → CDE. Then split X → CDE with another fresh variable Y: X → C Y and Y → D E. The figure shows the same split on the worked example’s rule S → A S B, which becomes S → A X and X → S B. Third check for unit rules as a safety step. Splitting never introduces a unit rule: every rule it produces has two variables on the right. Unit rules are removed during simplification (3.4), before terminal replacement and splitting. The result has only the two allowed shapes.

  • A → aB is not CNF.
  • A → BCD is not CNF.
  • A → B is a unit rule and is not CNF.

Carrying out the conversion

  1. Simplify the grammar: remove useless symbols, ε rules and unit rules (3.4). Keep S → ε only if S is absent from all right sides.
  2. For each terminal a that appears in a right side of length two or more, add a new variable T with rule T → a, and replace a by T in those long right sides.
  3. For each rule A → X₁X₂...Xₖ with k ≥ 3, introduce fresh variables and split from the left: A → X₁ Z₁, Z₁ → X₂ Z₂, and so on until the last rule has two symbols. For A → BCDE this can be written A → B X, X → CDE, then X → C Y, Y → D E.
  4. Remove unit rules by substituting the right side of B into A → B. Repeat until no unit rule remains.
  5. If ε is in the language and S → ε was kept, ensure S does not appear on any right side. Rename variables if needed.

Splitting adds one variable and one production per extra symbol. Terminal replacement adds one variable and one production per terminal used in long rules. The grammar grows, often to about twice the original size, but every rule now has the CNF shape.

Greibach normal form: every rule starts with a terminal

Greibach normal form (GNF) allows only productions A → aα, where a is one terminal and α is a string of variables, possibly empty. Every step of a derivation therefore writes a terminal first. GNF grammars have no ε rules and no unit rules. If the language contains ε, GNF is usually stated for the language without ε, or a separate start rule is added outside the form.

Order the variables A₁, ..., Aₙ. Rewrite rules so that Aᵢ → Aⱼα only when j > i. For a rule that starts with a lower or equal index, substitute the rules of that variable. A rule Aᵢ → Aᵢα is immediate left recursion; remove it with standard left-recursion removal, which introduces a new variable. After the ordering is clean, expand the first variable of each right side repeatedly until a terminal appears at the front. Every expansion replaces a leading variable by its rules, so the process ends with A → aα.

Take S → AB, A → aA | a, B → bB | b. Substitute A's rules into S → AB: S → aAB | aB. The rules A → aA | a and B → bB | b already start with terminals. Every rule now starts with one terminal followed by variables, so the grammar is in GNF.

Worked example

Exam traps

  • A → aB is not CNF. A terminal and a variable on the right is not one of the two shapes.
  • A → BCD must be split into binary rules. Leaving three variables on the right is not CNF.
  • Do not drop the S → ε exception when ε is in the language. Also do not allow any other ε rule.
  • In GNF, A → aBc is not allowed: after the first terminal, only variables may follow, so c must be replaced by a variable.
  • Splitting never introduces a unit rule; every rule it produces has two variables on the right. Unit rules are removed during simplification (3.4), before terminal replacement and splitting; check again at the end only as a precaution.

3.6 Pumping lemma for context-free languages

A context-free grammar can nest structures, but it cannot keep three independent counts equal. The pumping lemma turns that limit into a test: every long string in a context-free language has two small pieces that can be repeated together. It is used to prove that a language is not context-free, especially when studying the limits of parsers. It is a one-way test: failing it proves non-context-freeness, but passing it proves nothing.

You need: 3.2 for parse trees and 3.5 for CNF in the proof of the pumping length.

Statement and meaning

For every context-free language L there is a pumping length p ≥ 1 with this property. Every string s in L with |s| ≥ p can be split as s = uvwxy so that three conditions hold. Here u, v, w, x, y are strings over the same alphabet as L, i is a non-negative integer, and |z| means the length of z.

s = uvwxy with (1) |vwx| ≤ p, (2) |vx| ≥ 1, (3) uvⁱwxⁱy ∈ L for every i ≥ 0

p is the pumping length; u, v, w, x, y are the five pieces; i is the number of copies of v and x; |vwx| is the length of the middle block; |vx| is the total length of the two pumped pieces.

Condition (1) says the middle block vwx is short. Condition (2) says at least one of v and x is nonempty. Condition (3) says v and x are repeated together: i = 0 deletes both, i = 2 duplicates both. This is weaker than the regular-language pumping lemma, which pumps one piece. The lemma is one-way: it can prove that L is not context-free, but it cannot prove that L is context-free. Many non-context-free languages also satisfy it.

Why a long string repeats a variable

Take a grammar for L − {ε} in Chomsky normal form (CNF), with b variables; handle ε separately, since CNF rules cannot derive it. CNF rules have the form A → BC or A → a (see 3.5). Let q = 2^b and set the pumping length p = max(q, 1). A parse tree for a nonempty string s has variables at internal nodes and terminals at the leaves (see 3.2). If |s| ≥ p, the tree is tall enough that some root-to-leaf path contains the same variable twice. Call the upper occurrence A and the lower occurrence A.

Picture the upper A. Its yield is v w x: the lower A gives w, and the pieces around it give v and x. The rest of the tree gives u on the left and y on the right, so s = u v w x y. Because the lower A can replace the upper A, i = 0 gives u w y ∈ L. Because the upper A's rule can wrap the lower A again, i = 2 gives u v v w x x y ∈ L, and in general the upper A becomes vⁱ (lower A) xⁱ. The two occurrences are distinct, so at least one of v, x is nonempty, giving |vx| ≥ 1. Choose the repeated pair so that the upper A's subtree is short; with b variables this gives |vwx| ≤ q ≤ p.

How to use it

  1. Assume L is context-free and let p be its pumping length from the lemma.
  2. Choose one string s ∈ L with |s| ≥ p. The string usually depends on p, such as aᵖbᵖcᵖ.
  3. Write s = uvwxy and use |vwx| ≤ p and |vx| ≥ 1 to list the possible places where v and x can lie.
  4. Pick i = 0 or i = 2, and show that uvⁱwxⁱy is not in L. One counterexample i is enough.
  5. Conclude that the assumption was false, so L is not context-free.

For L = {aⁿbⁿcⁿ | n ≥ 1}, the string s = aᵖbᵖcᵖ has length 3p. Since |vwx| ≤ p, the block vwx cannot touch all three letter blocks: touching a and c would require all p b's plus at least one a and one c. So some letter keeps count p while pumping changes another count. The same style of argument proves that {ww | w ∈ {a, b}*} is not context-free.

Worked example

Exam traps

  • Using |vx| ≤ p instead of |vwx| ≤ p. v and x may sit far apart inside vwx; it is the whole block vwx that must be short.
  • Choosing v = x = ε. This breaks |vx| ≥ 1, and pumping with i = 0 or i = 2 changes nothing.
  • Checking only i = 0 and never i = 2, or the reverse. Pick the value of i that breaks the language.
  • Claiming a language is context-free because it passes the pumping lemma. The lemma is necessary, not sufficient.
  • Pumping v and x with different exponents. The lemma pumps both with the same i.

3.7 Closure properties of context-free languages

Union, concatenation, star, reversal and homomorphism keep a language context-free, and so does intersecting it with a regular set; intersection of two context-free languages and complement do not. These closure properties let you reason about whole families without rebuilding grammars: to show a language is context-free you assemble it from known pieces, and to show it is not you intersect with a regular set and land on a language the pumping lemma kills. Compiler front ends use the same split: a regular lexer feeding a context-free parser.

You need: 3.1 for grammar notation, Unit 1 for DFA, and Unit 2 for closure of regular languages.

Closure by grammar construction

A closure property says: apply the operation to context-free languages and the result is again context-free. The proof is a construction: write the two grammars, add one new start symbol, and show the new grammar generates exactly the intended set.

  • Union: from G1 = (V1, Σ, R1, S1) and G2 = (V2, Σ, R2, S2), take variables V1 ∪ V2 ∪ {S} and rules R1 ∪ R2 ∪ {S → S1, S → S2}. The first step chooses a branch, so the language is L1 ∪ L2.
  • Concatenation: the same variables with one new rule S → S1S2. A derivation is a derivation in G1 then one in G2, so the language is L1L2.
  • Kleene star: new rules S → SS1 and S → ε. The recursion adds any number of copies of L1, including none.
  • Reversal: reverse the right side of every rule, so A → α becomes A → αᴿ. The grammar generates L1ᴿ.
  • Homomorphism: replace each terminal a everywhere by h(a). If h(a) = ε you create ε-rules, which a CFG allows.

Before combining, rename variables so V1 and V2 are disjoint. Otherwise a rule of G1 can fire inside a derivation of G2, and the grammar generates strings in neither language.

Intersection with a regular set

If L is context-free and R is regular, then L ∩ R is context-free. Only one side may be regular.

Take a PDA M for L and a DFA D for R. Build the product machine: a state is a pair (p, q), p a state of M and q a state of D. Each input symbol moves both parts at once, M changing state and stack, D changing state. Accept when both accept. The product accepts exactly L ∩ R.

Grammar version: variables are triples [A, p, q], read as “A derives every string that drives D from p to q”. A rule A → a becomes [A, p, q] → a for each q with δ(p, a) = q. A rule A → BC becomes [A, p, q] → [B, p, r][C, r, q] for every state r.

Use it to prove non-context-freeness: if L ∩ R is not context-free and R is regular, then L is not context-free.

Not closed under intersection or complement

Let L1 = {aⁿbⁿcᵐ : n, m ≥ 0} with grammar S1 → AC, A → aAb | ε, C → cC | ε. Let L2 = {aᵐbⁿcⁿ : n, m ≥ 0} with grammar S2 → DB, D → aD | ε, B → bBc | ε. Both are context-free.

A string in both has as many a's as b's (L1) and as many b's as c's (L2). So L1 ∩ L2 = {aⁿbⁿcⁿ : n ≥ 0}.

{aⁿbⁿcⁿ} is not context-free by the pumping lemma for CFLs (3.6). So the family is not closed under ∩.

Complement fails by De Morgan. For any sets, L1 ∩ L2 = complement(complement L1 ∪ complement L2). If CFLs were closed under complement, both complements would be context-free, their union context-free by union closure, and the complement of that union context-free, making every intersection context-free. It is not. So complement closure fails.

Do not test complement on {aⁿbⁿ}: its complement is a CFL, so that proves nothing.

Apply Use closure properties to show that L = {w in {a,b,c}* : w has equally many a, b and c} is not context-free. 3 marks

Analyze Explain how closure under complement plus closure under union would force closure under intersection, and why that settles the complement question. 4 marks

L1 ∩ L2 = complement(complement L1 ∪ complement L2). Complement and union closure would give intersection closure. Intersection is not closed, and union is, so complement must fail.

Analyze Is the complement of {aⁿbⁿ : n ≥ 0} over {a,b} context-free? Justify. 4 marks

Yes. It is the union of strings containing ba, strings aⁱbʲ with i > j, and strings aⁱbʲ with i < j. Each is context-free, and union of CFLs is a CFL. So this example says nothing about non-closure.

Understand A CFG G1 and a CFG G2 are given. Is the question "is L(G1) ∩ L(G2) empty?" decidable? 2 marks

No. Emptiness of each single language is decidable, but emptiness of the intersection of two context-free languages is undecidable.

Beyond the syllabus

Not for the exam. Intersection with a regular set drives CFL-reachability, a static-analysis method that asks whether a value can flow from one program point to another by treating program edges as grammar rules and intersecting with a regular set of well-formed paths. Parser generators use the same split. Grammar-based verification of XML and configuration files layers regular constraints on tree structure.

3.8 CYK membership algorithm

CYK answers one question: is a given string w in the language of a context-free grammar? It needs the grammar in Chomsky normal form: every rule is A → BC with B, C variables, or A → a with a a terminal. CNF also allows the extra rule S → ε, where S is the start variable. CYK as described handles |w| ≥ 1. For w = ε, check separately: it is in L(G) exactly when S → ε is a rule. The algorithm fills a table of sets of variables for every substring of w. Each cell reuses smaller cells, like a dynamic-programming table. Membership costs about n³·|P| rule checks for |w| = n and |P| rules; for a fixed grammar this is O(n³). Compiler and parser courses use it as a clean membership test; only a few universities teach it in detail.

You need: CNF and parse trees.

The recurrence

Write w as s[1]...s[n]; s[i..j] is the substring from position i to j. V[i,j] holds every variable that derives s[i..j]. For length 1, A ∈ V[i,i] when A → s[i] is a rule. For length ℓ = j − i + 1 ≥ 2, try each split k from i to j−1. A ∈ V[i,j] if some rule A → BC has B ∈ V[i,k] and C ∈ V[k+1,j]. This is dynamic programming: each larger substring uses smaller ones. Accept w when S ∈ V[1,n]. |P| is the number of rules and |V| is the number of variables. Fill by increasing ℓ. CNF may also allow the extra rule S → ε; CYK as described covers |w| ≥ 1, so test w = ε separately. No other rule shapes are tried.

V[i,j] = ⋃ over k = i to j−1 of { A : A → BC, B ∈ V[i,k], C ∈ V[k+1,j] }

V[i,j] is the set of variables deriving s[i..j]; k is the split point; B and C are variables from the two parts; A is the left side of a CNF rule.

Filling order and cost

Start with all length-1 cells. Then fill length 2, length 3, up to n. A cell of length ℓ reads only cells of smaller lengths, so this order is safe. You can draw the n × n upper triangle, or rows of increasing length; both show the same cells. Store sets, not single variables, because several variables may derive one substring. The cell (i,j) covers exactly j−i+1 characters. Time is O(n³·|P|): n² cells, up to n splits, |P| rules. Space is O(n²·|V|). The answer is V[1,n], not the last cell you happen to fill. A parse tree can be recovered by keeping back-pointers for each split that added a variable. If S is absent from V[1,n], w is not in L(G). Empty cells mean no variable derives that substring. CYK is a decision test; it says yes or no. It does not list all derivations.

Worked example

Question. Grammar G: S → AB, A → AA | a, B → b. Test whether w = aab belongs to L(G) using CYK. Give V[1,1], V[2,2], V[3,3], V[1,2], V[2,3], V[1,3] and the decision.

  1. Write w = aab, n = 3. CNF rules: S→AB, A→AA, A→a, B→b.
  2. Length 1: V[1,1]={A}, V[2,2]={A}, V[3,3]={B}.
  3. V[1,2] for aa: split k=1 gives {A} and {A}; A→AA adds A, so V[1,2]={A}.
  4. V[2,3] for ab: split k=2 gives {A} and {B}; S→AB adds S, so V[2,3]={S}.
  5. V[1,3] for aab: k=1 gives {A} and {S}; no rule. k=2 gives {A} and {B}; S→AB adds S, so V[1,3]={S}.
  6. n(n+1)/2 = 6 cells; accepted = 1.

Answer. For w = aab, n = 3, the table has 6 cells, V[1,3] = {S}, so aab ∈ L(G) (accepted = 1).

Exam traps

  • Running CYK on a non-CNF grammar. Mixed rules such as A→aB are skipped; convert first (3.5).
  • Filling row by row left to right. Fill all shorter lengths before longer ones; otherwise needed cells are empty.
  • Putting one variable in a cell. Put a set; different variables can derive the same substring.
  • Taking the last filled cell as the answer. Read V[1,n].
  • Forgetting the terminal base case. A variable enters V[i,i] only when its rule gives exactly s[i].

Beyond the syllabus

Not for the exam. CYK is the classic O(n³) recognition algorithm. Faster in practice, not in the worst case: Earley and GLR also take O(n³) on general grammars, but they avoid the CNF conversion and run in O(n²) or O(n) for many real grammars, which is why compilers use them. The same table idea appears in RNA secondary-structure folding, where substrings combine into larger structures. Probabilistic CYK is used in statistical parsing and speech tagging. Search for 'CYK algorithm dynamic programming' and 'probabilistic CYK'.

3.9 Chomsky hierarchy and types of grammars

Grammar classes are graded by how tightly the two sides of each rule are tied. Type 0 has almost no restriction, type 1 keeps length from shrinking, type 2 has one variable on the left, and type 3 has a single terminal plus at most one variable. This ladder matches four machines and four language classes. Compiler writers use type 2 and type 3 daily; researchers use type 0 and type 1 to mark the edge of decidability.

You need: 3.1 to 3.6, and Unit 2 for regular languages.

Four rule shapes

A grammar has variables (also called nonterminals), terminals and a start symbol. The Chomsky type fixes the shape of every production. Write α, β, γ for strings of variables and terminals, and A, B for single variables.

  • Type 0 (unrestricted): α → β, where α contains at least one variable. β may be any string, including ε.
  • Type 1 (context-sensitive): αAβ → αγβ with γ ≠ ε. Equivalent form: every rule is non-contracting, |left| ≤ |right|. One exception: S → ε is allowed if S never appears on a right side.
  • Type 2 (context-free): A → α. The left side is exactly one variable.
  • Type 3 (regular): right-linear A → aB or A → a, or left-linear A → Ba or A → a. A grammar may use one direction; both directions give the same language class.

Some syllabi call type 0 phrase-structure grammars. The numbering runs from the most powerful type to the weakest: 0 is strongest, 3 is weakest. Every type 3 grammar is also type 2, every type 2 is type 1, and every type 1 is type 0.

Machines and language classes

Each grammar type has a matching machine and a matching language class.

TypeMachineLanguage class
0Turing machinerecursively enumerable
1linear bounded automatoncontext-sensitive
2pushdown automatoncontext-free
3finite automatonregular

The inclusions are strict. A witness separates each neighbouring pair.

  • 3.6 shows aⁿbⁿcⁿ is not context-free; a context-sensitive grammar generates it. So context-free ⊂ context-sensitive.
  • Unit 2 pumping lemma shows aⁿbⁿ is not regular; the grammar S → aSb | ε makes it context-free. So regular ⊂ context-free.
  • The halting set is recursively enumerable but not recursive (Unit 6). Every context-sensitive language is recursive, so the halting set is type 0 and not type 1. So context-sensitive ⊂ recursively enumerable.

A linear bounded automaton is a Turing machine whose tape is limited to the input length. That limit is exactly what non-contracting rules enforce: no derivation step can shrink the sentential form, so the machine never needs more cells than the input.

Finding the smallest type

To classify a language, test from the weakest type upward. Try a regular expression or a finite automaton first. If that fails, give a context-free grammar. If that fails, give a context-sensitive grammar. If the language is not recursive, only type 0 is possible.

  1. Look for a pattern that needs unbounded counting with one counter: aⁿbⁿ. That is context-free, not regular.
  2. Two counters that must stay equal, as in aⁿbⁿcⁿ, need context-sensitive rules; the pumping lemma for context-free languages proves it is not type 2.
  3. A set defined by halting or by an undecidable property is type 0; Unit 6 supplies the proof that it is not recursive.

Do not confuse left-linear with right-linear. A grammar that mixes both directions, such as A → aB and B → Ab in one chain, may generate a non-regular language. Type 3 requires one consistent direction, or the equivalent finite automaton.

Worked example

Question. Classify each language by the smallest grammar type that generates it. (1) L1 = {aᵐbⁿ | m, n ≥ 0}. (2) L2 = {aⁿbⁿ | n ≥ 0}. (3) L3 = {aⁿbⁿcⁿ | n ≥ 0}. (4) L4 = {⟨M, w⟩ : M halts on w}.

  1. L1 has all a's before all b's, with any counts. Grammar: S → aS | B, B → bB | ε. This is right-linear, so L1 is regular, type 3.
  2. L2 pairs each a with one b. Grammar: S → aSb | ε. This is context-free, type 2. The pumping lemma for regular languages in Unit 2 proves no type 3 grammar exists.
  3. L3 has three equal counts. A context-sensitive grammar for n ≥ 1 is: S′ → S | ε; S → aSBC | aBC; CB → BC; aB → ab; bB → bb; bC → bc; cC → cc. The rule CB → BC is not context-free because its left side has two variables. The pumping lemma in 3.6 proves no type 2 grammar exists. So L3 is type 1.
  4. L4 is the halting set. Unit 6 proves it is recursively enumerable but not recursive. Every context-sensitive language is recursive, so L4 cannot be type 1, type 2 or type 3. It is type 0 only.

Answer. L1 is type 3, L2 is type 2, L3 is type 1, and L4 is type 0.

Exam traps

  • The numbers run from most powerful to weakest: type 0 is strongest, type 3 is weakest. Do not call type 3 the strongest grammar.
  • Saying aⁿbⁿcⁿ is context-sensitive is only half the answer. The exam also wants the proof that it is not context-free, usually by the pumping lemma in 3.6.
  • Type 1 allows S → ε only when the start symbol S never appears on a right side. Otherwise every type 1 rule must be non-contracting.
  • A type 0 left side must contain at least one variable. A rule such as a → b, with only terminals on the left, is not a valid type 0 production.
  • A grammar that mixes left-linear and right-linear rules in one chain is not automatically type 3. Type 3 needs one consistent direction.

Takeaways

  1. A context-free grammar is just a finite set of rewriting rules; its language is every terminal string you can reach from the start symbol.
  2. A derivation is the rewriting written as a line of steps; a parse tree is the same rewriting drawn as a tree, and a parser builds the tree.
  3. A grammar is ambiguous when a string has two parse trees; a language is inherently ambiguous when no grammar for it avoids this.
  4. Removing useless symbols, ε-productions and unit productions gives a smaller grammar for the same language.
  5. Chomsky normal form (A → BC or A → a) and Greibach normal form (A → aα) fix the shape of every rule so proofs and algorithms have few cases.
  6. The pumping lemma for CFLs says a long enough string repeats a variable on one root-to-leaf path, so the two pieces around the repeat can be pumped together.
  7. CFLs are closed under union, concatenation, star, reversal, homomorphism and intersection with a regular set, but not under intersection or complement.
  8. CYK decides membership in about n³ rule checks on a CNF grammar, and the Chomsky hierarchy grades grammars by how tightly a rule's two sides are tied.
