3.1 Context-free grammars: definitions and examples

A context-free grammar describes a language by recursive replacement rules. One variable is replaced at a time, independently of its neighbours. This makes grammars suitable for nested structures that cannot be captured by a fixed amount of finite-state memory.

You need: alphabets, strings and languages from Unit 1, and regular languages from Unit 2.

The four components

A context-free grammar, abbreviated CFG, is a tuple G = (V, Σ, P, S). The finite set V contains variables, also called nonterminals. The finite terminal alphabet Σ contains symbols that appear in finished strings; V and Σ are disjoint. The finite set P contains productions, and S ∈ V is the start variable. Each production has the form A → α, where A is one variable and α is any string over V ∪ Σ, including the empty string ε.

The word context-free refers to the left side: replacing A does not require particular neighbours. If A → aB is a rule, then xAy can become xaBy wherever that occurrence of A appears. The strings x and y may themselves contain terminals or variables. The rule changes one selected occurrence, not every A simultaneously. Terminals are never rewritten by CFG productions.

Write α ⇒ β for one production step, α ⇒* β for zero or more steps, and α ⇒+ β for one or more. A sentential form is any string reachable from S, possibly still containing variables. A sentence is a terminal-only string derived from S. The generated language is L(G) = {w ∈ Σ* | S ⇒* w}. Here Σ* includes ε; whether ε is actually in L(G) depends on the productions.

Design from a structural invariant

Consider S → aSb | ε. One use of the recursive production adds one a on the left and one b on the right. Terminating with ε therefore gives aⁿbⁿ for n ≥ 0. The exponent n counts symbols, not a numerical value written in the string. For n = 0 the result is ε; for n = 2 it is aabb. A finite grammar can describe infinitely many strings because recursion permits arbitrarily many applications.

A construction answer needs both directions of correctness. Soundness means every generated string belongs to the intended language. Here each recursive step preserves equal counts and keeps all a symbols before all b symbols. Completeness means every intended string has a derivation. For any chosen n, apply S → aSb exactly n times and then S → ε. Merely displaying a few sample strings proves neither direction for the whole language.

For balanced parentheses, use B → (B)B | ε. The first B inside the parentheses describes a balanced interior; the final B describes whatever balanced material follows. This decomposition handles both nesting, such as (()), and concatenation, such as ()(). The simpler grammar B → (B) | ε generates only single nested chains and misses ()(). Understanding the decomposition prevents a common incomplete grammar design.

Combining grammar components

Alternative productions express a choice. The notation S → aS | bS | ε abbreviates three separate productions and generates all strings over {a, b}. By contrast, S → aS | b forces every derivation to end in one b, giving {aⁿb | n ≥ 0}. A vertical bar is grammar notation rather than a terminal unless the alphabet explicitly includes it.

Variables can name sublanguages. To generate one or more a symbols followed by one or more b symbols, use S → AB, A → aA | a and B → bB | b. The variable names do not appear in the final word. They divide the design into independent choices of positive lengths. This language is regular even though it has a CFG: context-free grammars include descriptions of regular languages too.

  1. Specify the terminal alphabet and whether the empty string is allowed.
  2. Find a recursive decomposition of a valid string and assign variables to its parts.
  3. Add base productions so every intended branch can terminate.
  4. Test a short valid word, an invalid boundary case and ε.
  5. Prove soundness and completeness using the decomposition.

A grammar is a generator, not a particular parsing algorithm. A careless top-down procedure can loop on a left-recursive rule even when the grammar is mathematically valid. Membership asks whether some finite derivation exists, rather than whether one chosen search strategy happens to find it. Parsing mechanisms and pushdown automata are treated in Unit 4.

Worked example

Construct a CFG for L = {aⁿbⁿ | n ≥ 1}, derive aaabbb and justify that ε is excluded.

Take V = {S}, Σ = {a, b}, and P = {S → aSb, S → ab}. Then S ⇒ aSb ⇒ aaSbb ⇒ aaabbb. The first two steps add two outside pairs; the final base production supplies the third pair. There are three a symbols and three b symbols, so the terminal length is 6.

After k recursive steps the sentential form is aᵏSbᵏ. Applying the base rule yields a^(k+1)b^(k+1), so every derived word has a positive equal count. Conversely, choose k = n − 1 for any n ≥ 1. No production erases S without adding terminals, so ε cannot be generated. The word abab is excluded because every derivation keeps the a block before the b block.

Exam traps

  • Do not include variables in the terminal alphabet; define both sets explicitly.
  • A rule such as aA → b is not context-free because its left side is not one variable.
  • Check the lower bound on n: using ε instead of ab changes whether the empty word is generated.
  • Examples support a design but do not replace proofs of both inclusions.

3.2 Derivations and parse trees

A derivation records the order of rule applications; a parse tree records the resulting hierarchical structure. Several application orders can build the same tree. Separating order from structure is essential when proving membership or testing ambiguity.

You need: productions, sentential forms and terminal strings from Chapter 3.1.

Leftmost and rightmost derivations

In a leftmost derivation, every step replaces the leftmost remaining variable. In a rightmost derivation, every step replaces the rightmost remaining variable. Both use exactly the grammar's productions; the restriction concerns which occurrence is expanded next. Write ⇒ₗₘ and ⇒ᵣₘ when that distinction matters. A terminal at the left edge is never rewritten merely because the derivation is called leftmost.

Take S → AB, A → aA | a, B → b. A leftmost derivation of aab is S ⇒ AB ⇒ aAB ⇒ aaB ⇒ aab. A rightmost derivation is S ⇒ AB ⇒ Ab ⇒ aAb ⇒ aab. Both construct an A branch containing two a leaves and a B branch containing one b leaf. The intermediate strings differ because independent subtrees were completed in different orders.

A general derivation allows either variable at each step. Two general derivations may differ only by swapping independent expansions, so they do not by themselves prove ambiguity. A fixed parse tree determines one leftmost derivation and one rightmost derivation. Thus two distinct leftmost derivations of the same terminal word do establish two distinct trees; one leftmost and one rightmost derivation may describe just one tree.

Reading and validating a tree

A parse tree is an ordered rooted tree. Its root is the start variable. An internal node labelled A has children labelled, from left to right, by the right side of a production for A. A terminal is a leaf. An ε production may be drawn with a single ε leaf; this represents an empty contribution rather than an actual input character. The yield is the concatenation of terminal leaves in left-to-right order, omitting ε.

To validate a proposed tree, first check every parent and its ordered children against P. Then check the root and compute the yield. Having the right leaves is insufficient if an internal expansion is not legal. The order of children also matters: a rule A → BC does not allow a C child before B. Reordering can change both the derived string and its interpretation.

Depth counts the number of edges on a longest root-to-leaf path under the convention used here. Height conventions vary, so define yours when using a bound. For the aab tree below, the deepest path is S–A–A–a, which has three edges. The two terminal a leaves do not have to occur at the same depth. A derivation step corresponds to expanding one variable node, not to creating just one edge.

Structure and interpretation

Expression grammars show why trees matter. If E → E + E | E * E | id, the same three identifiers can be grouped differently. The tree states which operation combines which subexpressions. The sequence of lexical tokens alone does not record that grouping. Chapter 3.3 examines how grammar design can enforce precedence and associativity.

A concrete parse tree includes grammar scaffolding such as parenthesis tokens and intermediate variables. An abstract syntax tree removes some scaffolding and retains the essential operations and operands. These are related but different objects. Do not omit required nodes when an exam asks for a parse tree rather than a simplified syntax tree.

  1. Place S at the root and choose the production used for its expansion.
  2. Create children in the exact right-side order.
  3. Repeat for variable children until the selected derivation reaches terminals.
  4. Read the yield and compare it with the requested word.
  5. Recover a leftmost derivation by always expanding the next leftmost unfinished variable node.

Every finite successful derivation gives a finite parse tree, and every such tree can be expanded to produce its yield. This equivalence permits two proof styles: show a sequence of legal replacements or show a tree whose local expansions are legal. A partial tree with unexpanded variables proves only a sentential form, not membership of a terminal word.

Worked example

For S → AB, A → aA | a and B → b, give both restricted derivations of aab and count production applications.

Leftmost: S ⇒ AB ⇒ aAB ⇒ aaB ⇒ aab. The rules are S → AB, A → aA, A → a, B → b. Rightmost: S ⇒ AB ⇒ Ab ⇒ aAb ⇒ aab. The rules are S → AB, B → b, A → aA, A → a. Each derivation uses four productions and ends with three terminal symbols.

The tree has four variable nodes: S, two A occurrences and one B. Each is expanded once, matching the four applications. It has three terminal leaves, so seven nodes in total and six edges. The two derivations build exactly this same tree; their difference is the schedule for expanding B. If B were allowed to derive bb instead, the leaf count and target word would change, requiring a different derivation.

Exam traps

  • Leftmost means leftmost variable, not leftmost symbol.
  • Two unrestricted derivations may represent the same tree and do not alone prove ambiguity.
  • Keep children in the production order; a parse tree is an ordered tree.
  • An ε leaf contributes zero input symbols, not a printed epsilon character.

3.3 Ambiguity in grammars and inherent ambiguity

A grammar is ambiguous when at least one generated string has two distinct parse trees. This is a property of the grammar, not automatically of its language. Some languages can be described unambiguously after redesign; inherently ambiguous languages cannot.

A finite witness for grammar ambiguity

To prove a grammar ambiguous, choose one terminal word and exhibit two different trees or two different leftmost derivations. The word must be identical in both demonstrations. Choosing one derivation of id + id and another of id * id proves nothing about ambiguity because those are different strings. Multiple derivations caused only by changing independent expansion order also do not suffice; see Chapter 3.2.

Consider E → E + E | E * E | id. The word id + id * id can have + at the root, with multiplication inside the right child, or * at the root, with addition inside the left child. The trees represent id + (id * id) and (id + id) * id. The grammar supplies no rule giving multiplication higher precedence. If all identifier values are 2, the two interpretations give 2 + 2·2 = 6 and (2 + 2)·2 = 8.

Associativity creates another ambiguity. The word id + id + id can group left or right even when no multiplication is present. Arithmetic addition may return the same number for these groupings, but equal numerical results do not make the parse trees identical. A structural definition of ambiguity does not depend on which evaluation happens to follow.

Repairing a grammar

Separate expression levels to encode precedence: E → E + T | T, T → T * F | F, F → (E) | id. An E can combine addition terms, while multiplication is contained within T. Therefore an unparenthesized multiplication binds more tightly than addition. Left recursion in E and T enforces left associativity of repeated operators. Parentheses permit a new nested E and override ordinary precedence.

For this operator language, the repaired grammar preserves the set of syntactically valid token strings while assigning one intended structure to each. Its parse trees differ from those of the original grammar. Grammar equivalence means equality of generated terminal languages; it does not require identical derivations, node labels or trees. A parser's precedence declarations can resolve implementation conflicts, but those declarations are extra information rather than a proof that the original CFG is unambiguous.

Another familiar source of ambiguity is the dangling else. With productions for both “if condition then statement” and “if condition then statement else statement”, an else can attach to different unmatched if statements. A language specification can choose the nearest unmatched if, or a grammar can distinguish matched and unmatched statements. Adding parentheses or explicit block endings is another design choice, although it may change the surface language.

Inherent ambiguity and proof limits

A context-free language is inherently ambiguous if every CFG generating it is ambiguous. This is stronger than finding a problematic grammar. For example, the regular language a* has an ambiguous grammar S → SS | a | ε, but it also has the unambiguous grammar S → aS | ε. Thus a bad description does not establish an unavoidable property of the language.

A standard inherently ambiguous language is {aⁱbʲcᵏ | i = j or j = k, with i, j, k ≥ 1}. Each equality defines a context-free component. Their union is context-free, but the full language has no unambiguous CFG. Strings aⁿbⁿcⁿ lie in both components. Showing that an obvious union grammar has two derivations for these strings proves ambiguity of that grammar only; the stronger inherent-ambiguity theorem requires an argument ruling out every alternative grammar. Treat that theorem as a standard result, not as a consequence of overlap alone.

There is no general algorithm that decides ambiguity for an arbitrary CFG. This does not prevent a proof for a particular grammar, nor does it make a finite witness invalid. For a proposed unambiguous expression grammar, explain how the top-level operator and recursive subexpressions are determined. Testing every word up to a chosen length can find counterexamples but cannot establish unambiguity over an infinite language.

Worked example

Give two leftmost derivations of id + id * id for the ambiguous grammar.

First: E ⇒ E + E ⇒ id + E ⇒ id + E * E ⇒ id + id * E ⇒ id + id * id. This uses addition at the root. Second: E ⇒ E * E ⇒ E + E * E ⇒ id + E * E ⇒ id + id * E ⇒ id + id * id. This uses multiplication at the root. Both derivations always expand the leftmost remaining E and use five productions.

The same five-token word has two different first productions, so the trees differ. Under the repaired grammar, the top-level E → E + T places the multiplication in the right T, giving the first interpretation only. To obtain the second structure, the input must explicitly contain parentheses: (id + id) * id.

Exam traps

  • A grammar is ambiguous if one word has two trees; not every word must be ambiguous.
  • Equal expression values do not imply identical trees.
  • Overlapping component languages do not alone prove inherent ambiguity.
  • Removing left recursion is not a general ambiguity-removal algorithm.

3.4 Simplifying CFGs: useless, epsilon and unit productions

Simplification removes grammar machinery that is unnecessary for generating terminal words. The challenge is to preserve the language while eliminating empty, unit or useless productions. Deleting a rule without adding its consequences can silently lose valid strings.

Useless variables: generating and reachable

A variable is generating, also called productive, if it derives some terminal string, possibly ε. Mark variables that have terminal-only right sides, then repeatedly mark A whenever a rule A → α has only terminals and already marked variables on its right. Stop when a full pass adds nothing. This least fixed point distinguishes actual finite derivations from cycles such as D → D, which never produce a terminal word.

A variable is reachable if it occurs in a sentential form derived from S. Begin by marking S, then follow productions from marked variables and mark every variable on their right sides. A useful variable must participate in a successful derivation from S, not merely be generating or reachable in isolation. First remove nongenerating variables and their incident productions, then recompute reachability on the reduced grammar. Removing dead branches can make other variables unreachable.

If S is nongenerating, the language is empty. This is a decidable property: the finite marking process settles it. It differs from generating only ε, which is a nonempty language containing one word. A variable reachable solely through a doomed branch is not useful even if it has its own terminal production.

Eliminating ε productions

A nullable variable derives ε. Compute nullability by marking direct ε producers, then repeatedly mark A if A → A₁…Aₖ consists entirely of nullable variables. An ordinary terminal prevents that right side from deriving ε. Nullable is stronger than generating: every nullable variable is generating, but a variable deriving only a is not nullable.

For each production, add variants that omit any chosen occurrences of nullable variables. Treat occurrences separately: A → BB with nullable B can produce BB, B and ε, with duplicates removed. Do not delete terminal symbols. Then remove ordinary ε productions. If ε belongs to the original language and must be preserved, introduce a fresh start S₀ with S₀ → S | ε, ensuring S₀ never occurs on a right side. Retain only this start ε exception in the final form.

There can be many omission combinations when a right side contains many nullable occurrences. The point of the construction is correctness, not a promise that the number of rules stays unchanged. When the task asks for an ε-free grammar without allowing a start exception, the usual result generates L(G) minus {ε}; state that change rather than claiming exact equivalence.

Eliminating unit productions and ordering passes

A unit production is A → B with exactly one variable on the right. A → a is a terminal production, not a unit production. Compute the unit closure U(A): every B reachable from A using only unit steps, including A itself via zero steps. For every B in U(A), copy all nonunit productions of B to A. Remove the unit productions after these consequences are available.

Unit cycles such as A → B and B → A need no special unrolling. Their closure sets are finite because V is finite. ε elimination may create unit productions, so unit elimination normally follows it. Either perform a preliminary useless-symbol cleanup or leave that cleanup until the end; in both cases recompute generating and reachable symbols after transformations. Language-preserving passes do not necessarily preserve parse-tree shape or ambiguity witnesses.

  1. Record whether S derives ε and protect it using a fresh start if necessary.
  2. Find nullable variables and add all required omission variants.
  3. Remove ordinary ε rules, then compute unit closures and copy nonunit rules.
  4. Remove nongenerating symbols, then unreachable symbols.
  5. Check short words and explain why each transformation preserves derivability.

Worked example

Simplify S → AB | C, A → aA | ε, B → b, C → B, D → d. Give an equivalent grammar, preserving ε if it exists.

Initially A is nullable, but S is not: AB always contributes b, and C derives b. D is generating but unreachable. From S → AB add S → B; from A → aA add A → a. Delete A → ε. The intermediate grammar is S → AB | B | C, A → aA | a, B → b, C → B, D → d.

The unit closure of S is {S, C, B}; the closure of C is {C, B}. Copy B → b to S and C, and remove S → B, S → C and C → B. The result has S → AB | b, A → aA | a, B → b, C → b, D → d. Now C and D are unreachable and can be removed.

Final grammar: S → AB | b, A → aA | a, B → b. Its language is {aⁿb | n ≥ 0}. The case n = 0 uses S → b; positive n uses AB. For n = 2, S ⇒ AB ⇒ aAB ⇒ aaB ⇒ aab, with length 3. ε was never in the language, so no start exception is required. Simply deleting A → ε without adding S → B would have lost b.

Exam traps

  • Generating and reachable are separate tests; do them in the right reduced grammar.
  • Nullable occurrences can be omitted; terminal symbols cannot.
  • A → a has a one-symbol right side but is not a unit production.
  • Record the empty-word convention before deleting ε rules.

3.5 Chomsky and Greibach normal forms

Normal forms restrict production shapes without reducing the class of context-free languages. Chomsky normal form makes branching binary, which supports CYK parsing. Greibach normal form makes each nonempty rule application begin with a terminal, connecting grammar steps with input consumption.

You need: nullable, unit and useless-symbol elimination from Chapter 3.4.

Chomsky normal form

A grammar in Chomsky normal form, or CNF, has productions A → BC or A → a, where A, B, C are variables and a is one terminal. We allow S₀ → ε only when ε belongs to the language, with fresh start S₀ absent from every right side. This convention also keeps the start from appearing on right sides in the rest of the grammar. A rule A → aB violates CNF even though its right side has length two: both symbols must be variables.

For a nonempty word of length n, a CNF parse tree has n terminal-producing variable nodes and n − 1 binary variable expansions. Thus its derivation uses 2n − 1 production applications. The binary skeleton has n leaves when each terminal-producing variable is treated as a leaf. Adding the terminal leaves does not change the number of production applications. The empty-word exception is handled separately.

  1. Introduce a fresh start and preserve ε if needed.
  2. Remove ordinary ε productions, unit productions and useless variables.
  3. In right sides of length at least two, replace each terminal a by a helper Tₐ with Tₐ → a.
  4. Break right sides of length greater than two into a chain of binary rules using fresh helpers.
  5. Check every resulting rule against the allowed shapes.

For example, A → BCDE becomes A → BX₁, X₁ → CX₂, X₂ → DE. The helper names must be fresh so they cannot accidentally acquire unrelated derivations. There are four original children, so three binary rules reproduce their ordered concatenation. Existing helpers may be shared only when their definitions have the same intended expansion.

Greibach normal form

Greibach normal form, or GNF, uses A → aA₁…Aₖ for k ≥ 0: one terminal first, followed only by variables. The same fresh-start ε exception can be allowed. A → a is valid with k = 0. A → ab is not GNF because b is a second terminal on the right. In any derivation of a nonempty word, each rule application contributes exactly one terminal that is never removed, so a word of length n requires n applications.

A conversion uses substitution and elimination of left recursion. Order variables A₁,…,Aₘ. When a rule for Aᵢ begins with an earlier Aⱼ, substitute the alternatives for Aⱼ at that leading occurrence. Remove immediate left recursion when it appears. Continue the ordered process, then substitute leading variables in reverse order until each right side begins with a terminal. Terminals after the leading position must be replaced by terminal-producing helpers.

For immediate left recursion A → Aα | β, where α is nonempty and β does not begin with A, the positive-repetition form A → β | βR, R → α | αR avoids an ε rule. Multiple recursive tails and nonrecursive alternatives require all corresponding variants. The remaining right sides may still need leading-variable substitutions before they satisfy GNF. This local rewrite is not the whole conversion algorithm, and blindly applying it to an arbitrary nullable grammar can break its assumptions.

Choosing and checking a normal form

CNF is useful when a parser combines two already recognized substrings. GNF is useful when reasoning about a derivation that emits one leading terminal per step, including CFG-to-PDA constructions in Unit 4. Neither form guarantees an unambiguous grammar. A language-preserving transformation can also change the number of derivations and introduce extra nodes, so compare terminal languages rather than tree shapes.

A grammar can be in both forms, but most converted grammars are not. The one-rule grammar S → a satisfies both. In contrast, S → AB is CNF but not GNF, while S → aB is GNF but not CNF. Normal form is a syntactic property of a given grammar. Being context-free is a language-class property based on the existence of some CFG.

Worked example

Convert S → aSb | ab, which generates aⁿbⁿ for n ≥ 1, into CNF. Use fresh start S₀.

Introduce A → a and B → b. Replace terminal occurrences in long right sides to obtain S → ASB | AB. Binarize ASB with T → SB. A CNF result is S₀ → AT | AB, S → AT | AB, T → SB, A → a, B → b. The fresh start copies the nonunit alternatives of S, so no S₀ → S remains.

For aabb, a leftmost derivation is S₀ ⇒ AT ⇒ aT ⇒ aSB ⇒ aABB ⇒ aaBB ⇒ aabB ⇒ aabb. It uses seven rules, agreeing with 2n − 1 = 7 for n = 4 terminals. The original grammar used only two rules, but the language is unchanged.

Worked example

Give a GNF version of the same language and derive aabb.

Use S → aSB | aB and B → b. Both alternatives for S start with a and have only variables afterward. The leftmost derivation is S ⇒ aSB ⇒ aaBB ⇒ aabB ⇒ aabb. Exactly four steps emit the four terminals. No ε production is needed because n ≥ 1. If a fresh start is required by convention, copy S's alternatives to S₀; the language and step count stay the same.

Exam traps

  • CNF does not allow a mixed terminal-variable pair or a unit rule.
  • GNF requires the first symbol to be terminal and all following symbols to be variables.
  • The count 2n − 1 applies to nonempty CNF derivations, not arbitrary CFG derivations.
  • Preserve ε explicitly rather than hiding it in a forbidden nullable helper.

3.6 Pumping lemma for context-free languages

The pumping lemma gives a necessary repetition property of every context-free language. A sufficiently long word has two linked pieces that can be repeated together or removed together. To prove a language is not context-free, show that every permitted split of a carefully chosen word fails this property.

The statement and its quantifiers

If L is context-free, there exists an integer p ≥ 1 such that every w ∈ L with |w| ≥ p can be written w = uvxyz with three conditions: |vxy| ≤ p, |vy| ≥ 1, and uvⁱxyⁱz ∈ L for every integer i ≥ 0. The notation |w| means the number of terminal symbols in w. The two pieces v and y are pumped; u, x and z stay fixed. Either v or y may be empty, but they cannot both be empty.

The order is crucial. The language provides p; the proof chooses a word depending on p; an opponent may choose any split satisfying the two length conditions; the proof then chooses a pumping value i that breaks membership. You cannot choose a convenient split and call that a contradiction. You must defeat all permitted decompositions, though you may group them into cases and choose a different i in different cases.

For a non-context-freeness proof, assume the language is context-free and let p be its pumping length. Choose a word of length at least p that actually belongs to the language. Consider an arbitrary legal split. Show that some i ≥ 0 produces a word outside the language. This contradicts the lemma and disproves the initial assumption. A successful application proves non-context-freeness, and therefore also nonregularity.

Why a parse tree can pump

Convert a CFG for the nonempty part of L into CNF. A very long yield forces a long root-to-leaf path because branching is binary. There are only finitely many variable names, so one variable A repeats on that path. The upper occurrence can derive vAy while the lower occurrence derives x. The rest of the tree contributes u before the upper subtree and z after it.

Replacing the upper A subtree by the lower A subtree removes v and y, giving uxz. Repeating the segment between the two A occurrences adds another copy of v on one side and y on the other, giving uv²xy²z. The same operation works for every i. Choosing repeated occurrences in a suitably bounded lower part of the tree bounds |vxy| by p. A nontrivial branch between them supplies at least one terminal in v or y, giving |vy| ≥ 1.

This explains why two pieces are linked. They come from the left and right fringes around the same recursive variable. Unlike the regular-language pumping lemma from Unit 2, the pump need not be one contiguous repeated substring. The middle x remains in place while the surrounding v and y grow together.

A systematic contradiction

  1. State the CFL pumping lemma and assume the target language satisfies it.
  2. Select a word whose separated blocks expose the required dependencies.
  3. Use |vxy| ≤ p to restrict which blocks the pumped material can touch.
  4. Use |vy| ≥ 1 to establish that pumping really changes something.
  5. Choose i, calculate the resulting counts or order, and derive a contradiction for every legal split.

The lemma is necessary, not sufficient. Finding a pumpable decomposition for one word does not prove that a language is context-free. Even checking the property broadly is not a substitute for constructing a CFG or PDA. If a proposed witness produces difficult cases, reconsider the witness before forcing an incomplete argument. Closure properties in Chapter 3.7 often isolate a simpler non-CFL core.

A finite language satisfies the lemma vacuously when p is greater than the length of every word. That does not contradict the nonempty-pump condition: there are then no words long enough to require a split. In all proofs, the pumping length is a hypothetical constant associated with the assumed CFL, not a number the student is entitled to fix as 2 or 3.

Worked example

Prove L = {aⁿbⁿcⁿ | n ≥ 0} is not context-free.

Assume it is context-free and let p ≥ 1 be its pumping length. Choose w = aᵖbᵖcᵖ, a member of length 3p. Let w = uvxyz be any legal decomposition. Since |vxy| ≤ p, the substring vxy cannot contain both an a and a c: even the shortest such substring would contain all p b symbols plus an a and a c, giving length p + 2.

Let dₐ, dᵦ and d꜀ be the counts of a, b and c in vy. At least one count is positive because |vy| ≥ 1, and at least one is zero because the window touches at most two blocks. Pump down with i = 0. The resulting counts are p − dₐ, p − dᵦ and p − d꜀. At least one is still p and at least one is below p, so the three counts are unequal. Deleting symbols cannot restore equality or create a new qualifying n. Thus uxz ∉ L for every legal split, contradicting the lemma.

For a numerical illustration only, if p = 4 and vy contains one a and two b symbols, pumping down changes (4, 4, 4) to (3, 2, 4). The proof above covers all p and all legal splits; this one illustration is not the proof itself.

Exam traps

  • Pump v and y together by the same exponent; leave x fixed.
  • The length bound is on vxy, while the nonempty condition is on vy.
  • Defeat every legal decomposition rather than choosing a favourable one.
  • A failure of one witness or one pumping value does not prove the language context-free.

3.7 Closure properties of context-free languages

Closure asks whether applying an operation to languages in a class always stays in that class. Context-free languages support union, concatenation and star, but not arbitrary intersection or complement. Intersection with a regular language is an important safe exception.

Constructing grammars for positive results

Let G₁ and G₂ generate CFLs L₁ and L₂. Rename their variables to be disjoint, using start variables S₁ and S₂. For union, add a fresh start S with S → S₁ | S₂ and retain both production sets. A derivation chooses one component, so the result is exactly L₁ ∪ L₂. For concatenation, use S → S₁S₂; the first part produces a word of L₁ and the second a word of L₂.

For Kleene star L₁*, use S → S₁S | ε with fresh S. Each recursion adds one component word; the base case allows zero components. These constructions remain valid when a component includes ε. Renaming is essential: accidentally sharing a variable can mix component rules and generate words belonging to neither intended construction.

CFLs are also closed under reversal. Reverse the order of symbols on every production's right side. Mirroring each parse tree reverses its yield, giving exactly Lᴿ = {wᴿ | w ∈ L}. A homomorphism h replaces each terminal by a fixed string, possibly ε. Replacing terminals in the grammar by their h images establishes closure under homomorphism. CFLs are also closed under inverse homomorphism; this is a distinct operation taking all input strings whose images belong to the original language.

Regular filters and failed closures

If L is context-free and R is regular, then L ∩ R is context-free. One proof runs a PDA for L together with a DFA for R. Its finite control remembers the pair of machine states, while the stack remains the PDA's single stack. A PDA move consuming a symbol also advances the DFA on that symbol; a PDA ε move leaves the DFA state unchanged. Accept only when both components satisfy their acceptance requirements. Unit 4 supplies the PDA formalism.

The same argument does not handle two arbitrary CFLs: two independent pushdown computations would need two stacks, which is more powerful than one. A concrete counterexample uses L₁ = {aⁿbⁿcᵐ | n, m ≥ 0} and L₂ = {aᵐbⁿcⁿ | m, n ≥ 0}. Each is context-free, but their intersection is {aⁿbⁿcⁿ | n ≥ 0}, proved non-context-free in Chapter 3.6.

CFLs are not closed under complement relative to a fixed alphabet Σ. If they were, union closure and De Morgan's law would imply intersection closure: L₁ ∩ L₂ = complement(complement(L₁) ∪ complement(L₂)). That contradicts the counterexample. CFLs are likewise not closed under difference of two arbitrary CFLs, since Σ* is context-free and Σ* minus L is its complement.

However, L minus R is context-free when L is context-free and R is regular: take L ∩ complement(R), and use regular complement closure. The reverse difference R minus L has no such general guarantee. The direction and the classes of the operands must be stated; a bare “difference is closed” is misleading.

Decision properties and structural insight

Closure and decidability ask different questions. Membership for a CFG is decidable; CYK in Chapter 3.8 is one method. Emptiness is decidable by checking whether the start is generating. Finiteness is also decidable. In a reduced CNF grammar for nonempty words, build the variable-dependency graph with an edge A → B whenever B occurs on a right side for A. A reachable cycle permits a recursive expansion with nonempty productive siblings and hence unbounded word lengths. An acyclic graph bounds derivation depth, so only finitely many words occur.

Remove useless symbols before applying that cycle criterion. A dead cycle D → D can coexist with a finite language, and raw unit cycles need not increase word length. These are why “there is recursion, therefore the language is infinite” is not a valid test on an arbitrary grammar. The CNF and usefulness assumptions ensure genuine terminal growth.

In contrast, equivalence, inclusion and universality are undecidable for arbitrary CFGs. This does not contradict decidable membership: testing one supplied word is different from comparing infinitely many possible words. Some syllabi also mention the Chomsky–Schützenberger characterization: every CFL can be represented as a homomorphic image of the intersection of a suitable balanced-bracket language with a regular language. It connects recursive nesting, finite-state restrictions and relabelling; a proof is beyond this unit's basic closure constructions.

Worked example

Let L = {aⁿbⁿ | n ≥ 0} and let R contain strings with an even number of a symbols followed by any number of b symbols. Find L ∩ R and construct its grammar.

Membership in L forces equal block counts. Membership in R forces the a count n to be even, so n = 2k for some k ≥ 0. Thus L ∩ R = {a^(2k)b^(2k) | k ≥ 0}. The grammar S → aaSbb | ε generates precisely that set. For k = 2, S ⇒ aaSbb ⇒ aaaaSbbbb ⇒ aaaabbbb. There are four a symbols, four b symbols and length 8. The word aabb is included; aaabbb is excluded by the regular filter.

For the nonclosure example, L₁ can use S₁ → AC, A → aAb | ε, C → cC | ε. L₂ can use S₂ → DB, D → aD | ε, B → bBc | ε. Any word in both has equal a and b counts from L₁ and equal b and c counts from L₂, forcing all three equal. Their individual CFGs therefore do not imply a CFG for their intersection.

Exam traps

  • Do not confuse arbitrary CFL intersection with intersection against a regular language.
  • Use a fixed alphabet when taking complements.
  • A closure counterexample requires operands in the class and a result outside it.
  • A cycle proves infinitude only under the stated reduced-CNF conditions.

3.8 CYK membership algorithm

CYK decides whether a word belongs to a language described by a CNF grammar. It records which variables derive each substring, starting with individual terminals and combining adjacent spans. The final cell answers membership without enumerating complete derivations.

Only a few universities teach this advanced topic. CYK stands for Cocke–Younger–Kasami. Use the CNF convention from Chapter 3.5; handle the empty word separately through the start ε rule.

Cells and recurrence

For a word w of length n, define T[i, j] as the set of variables deriving the nonempty half-open substring w[i:j], where 0 ≤ i < j ≤ n. Initialize T[i, i+1] with every A for which A → w[i] is a terminal production. For a longer span, try each split k with i < k < j. If A → BC, B ∈ T[i, k] and C ∈ T[k, j], add A to T[i, j].

Compute by increasing span length so both child cells are ready. Accept exactly when the start variable belongs to T[0, n]. A cell stores a set: several variables can derive the same substring. Empty cells are meaningful failed subproblems. The split order matters because BC is an ordered pair, not an unordered combination.

Why it terminates and works

A CNF tree for a span longer than one character has a root rule A → BC and a boundary between the two child yields. CYK tries that boundary and rule. Conversely, each addition joins two valid child derivations under a legal parent production. Induction on span length proves both completeness and soundness.

There are O(n²) cells and O(n) splits per cell. Testing each binary production gives time O(|P|n³) and table storage O(|V|n²); for a fixed grammar these become O(n³) and O(n²). Here |P| counts productions and |V| variables. Membership alone needs sets; reconstructing trees also needs backpointers recording rules and splits.

A small Python recognizer

The following code uses a fixed CNF grammar for aⁿbⁿ with n ≥ 1. S0 is the fresh start; the recursive S is allowed on right sides.

w = "aabb"
terminal = {"a": {"A"}, "b": {"B"}}
binary = [("S0", "A", "B"), ("S0", "A", "C"),
          ("S", "A", "B"), ("S", "A", "C"),
          ("C", "S", "B")]
n = len(w)
T = {(i, j): set() for i in range(n)
     for j in range(i + 1, n + 1)}
for i, ch in enumerate(w):
    T[i, i + 1] = set(terminal.get(ch, set()))
for length in range(2, n + 1):
    for i in range(n - length + 1):
        j = i + length
        for k in range(i + 1, j):
            for a, b, c in binary:
                if b in T[i, k] and c in T[k, j]:
                    T[i, j].add(a)
print(sorted(T[0, n]))
print("accepted" if "S0" in T[0, n] else "rejected")

  • Distinguish a cell endpoint j from a substring length.
  • Test the start variable in the final cell, not merely whether that cell is nonempty.

3.9 Chomsky hierarchy and types of grammars

The Chomsky hierarchy organizes language classes by restrictions on grammar productions. Stronger grammars describe more languages, with corresponding machine models. A language belongs to a class when some suitable grammar describes it; a needlessly powerful description does not establish its smallest class.

Four grammar types

A type-3, or regular, grammar consistently uses right-linear productions A → aB and A → a, with suitable ε rules if the convention allows them. More general right sides of terminal strings are equivalent after adding helpers. A left-linear grammar consistently puts the single variable on the left end instead. Each convention describes the regular languages, which are recognized by finite automata; see Units 1 and 2.

A type-2 grammar is context-free: its left side is one variable, with no restriction on the right side. Its languages are recognized by nondeterministic pushdown automata. Deterministic PDAs recognize a proper subclass, so the word nondeterministic matters in the correspondence. See Unit 4 for the constructions rather than trying to infer them from production lengths alone.

A type-1 grammar is context-sensitive. A contextual rule has the form αAβ → αγβ with γ nonempty, so the replacement of A may depend on the surrounding α and β. An equivalent language-class definition uses noncontracting productions: the right side is no shorter than the left, and the left side contains a variable. Individual noncontracting rules need not visibly have the contextual shape; the equivalence is between the resulting language classes.

Context-sensitive languages are recognized by nondeterministic linear-bounded automata, Turing machines restricted to tape space proportional to input length. To include ε, allow the special production S₀ → ε only for a start symbol that never occurs on any right side. Without such an exception, noncontracting rules cannot derive ε from a nonempty start symbol. State the convention when comparing classes.

A type-0, or unrestricted, grammar allows α → β whenever α is nonempty and contains a variable; β may be any string of variables and terminals, including ε. Its languages are Turing-recognizable, also called recursively enumerable. A recognizer must accept members but need not halt on nonmembers. Units 5 and 6 distinguish recognition from a decider that halts on every input.

Inclusions and strict boundaries

With compatible empty-word conventions, REG ⊊ CFL ⊊ CSL ⊊ RE. The symbol ⊊ means proper subset: every language in the smaller class is in the larger, and at least one language belongs only to the larger. A regular grammar is already a CFG. CFG-to-context-sensitive language inclusion requires handling erasing rules appropriately; it is a language theorem, not a claim that every CFG is syntactically noncontracting.

The language {aⁿbⁿ | n ≥ 0} separates regular languages from CFLs: a CFG generates it, while the regular pumping lemma rules out regularity. The language {aⁿbⁿcⁿ | n ≥ 1} separates CFLs from CSLs: Chapter 3.6 rules out context-freeness, and a noncontracting grammar can generate it. Turing-recognizable languages include undecidable languages, whereas context-sensitive languages are decidable by finite configuration search on the bounded tape. This supplies the final strict boundary.

The decidable languages are not one of the four named grammar layers. They contain all CSLs and lie within RE. A type-0 grammar may describe a very simple regular language, so type-0 does not mean its language is undecidable. Similarly, seeing a non-context-free production in one grammar does not prove that no equivalent CFG exists.

Classifying a description and a language

  1. Inspect the given production shapes and identify the most restrictive type they directly satisfy.
  2. Separate that syntactic answer from the language's possible smallest class.
  3. For a language upper bound, give a grammar or recognizer in the claimed class.
  4. For a strict lower bound, use a proved limitation of the smaller class.
  5. Check ε conventions and whether the machine correspondence needs nondeterminism.

Mixing right-linear and left-linear rules can destroy regularity. For example, S → aA and A → Sb | b generate aⁿbⁿ for n ≥ 1: one round wraps another matched pair. Each rule alone looks linear, but their combined orientations do not make a regular grammar. The word linear is also broader than regular: a linear CFG has at most one variable anywhere on a right side and can still generate nonregular languages.

Production type does not directly measure practical parsing speed. CYK provides a polynomial-time membership procedure for CFGs, but that does not classify all larger languages by one complexity bound. The hierarchy groups expressive power; time and space complexity refine different questions in Unit 6.

Worked example

Generate aabbcc with a noncontracting grammar for {aⁿbⁿcⁿ | n ≥ 1}. Use S → aSBC | aBC, CB → BC, aB → ab, bB → bb, bC → bc and cC → cc.

A derivation is S ⇒ aSBC ⇒ aaBCBC ⇒ aaBBCC ⇒ aabBCC ⇒ aabbCC ⇒ aabbcC ⇒ aabbcc. The first two steps choose n = 2. The swap CB → BC groups the B markers before the C markers. The remaining context-dependent rules turn those markers into b and c in the required order. The final word has two copies of each terminal and length 6.

No rule shortens a string. Some left sides contain terminals and variables together, so the grammar is not a CFG. Each recursive start step adds one a, one B and one C; swaps preserve counts and terminalization preserves the corresponding totals. Successful terminal derivations must finish in a-block, b-block, c-block order. Conversely, swaps can group the markers for every n, so every desired word is generated. This upper bound plus the pumping argument establishes CSL membership and failure of CFL membership.

Exam traps

  • Classify the generated language separately from the supplied grammar syntax.
  • Use an NPDA, not necessarily a DPDA, in the full CFL correspondence.
  • A noncontracting grammar needs an explicit start exception if ε is included.
  • Do not combine arbitrary left-linear and right-linear rules and assume regularity.

A permitted replacement rule.
Start symbol
The variable from which derivations begin.
Sentential form
Any string reachable from the start, possibly containing variables.
Sentence
A derived terminal-only string.
Leftmost derivation
A derivation expanding the leftmost remaining variable at each step.
Parse tree
An ordered tree whose local expansions follow productions.
Yield
The terminal sequence read from leaves left to right.
Ambiguous grammar
A grammar with at least one word having two parse trees.
Inherent ambiguity
The absence of any unambiguous CFG for a language.
Nullable variable
A variable that derives ε.
Generating variable
A variable that derives some terminal string.
Reachable variable
A variable occurring in a sentential form from the start.
Unit production
A rule A → B between single variables.
CNF
Chomsky normal form: binary-variable or single-terminal productions, with a stated ε exception.
GNF
Greibach normal form: one terminal followed by zero or more variables.
Pumping length
A threshold guaranteed by a pumping lemma under its assumptions.
Closure
Preservation of a language class under an operation.
Homomorphism
A fixed substitution of a string for each terminal, extended by concatenation.
Membership
Whether a supplied word belongs to a language.
CYK
A dynamic-programming membership algorithm for CNF grammars.
Noncontracting production
A production whose right side is not shorter than its left side.
Linear-bounded automaton
A Turing machine restricted to input-proportional tape space.
Recognizer
A machine required to accept members but not necessarily halt on nonmembers.
Decider
A machine halting with the correct answer on every input.

Sources and further reading

  • Michael Sipser, Introduction to the Theory of Computation: context-free languages, pumping arguments and decidability. No edition-specific page claims are made.
  • Peter Linz, An Introduction to Formal Languages and Automata: grammar transformations and language-class examples.
  • Natural Language Processing with Python, Chapter 8: Analyzing Sentence Structure, by Steven Bird, Ewan Klein and Edward Loper. Open source text opened for CFGs, parse trees and structural ambiguity; its examples concern natural-language parsing.
  • NLTK grammar module: public source and documentation. Opened for the representation of CFG productions and normal-form checks. Library conventions may differ from the fresh-start ε convention stated in this book.
