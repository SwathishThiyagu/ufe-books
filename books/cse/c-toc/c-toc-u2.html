2.1 Regular expressions: operators and precedence

Regular expressions describe sets of strings using a small set of symbols. They let you write patterns such as phone numbers, URLs, or binary codes in a single line. The symbols have a fixed order of evaluation, so the same text can mean different languages if the order is ignored. Knowing the operators and their precedence lets you build correct patterns quickly, which is essential when you write a search filter for a UPI transaction ID or a regex for a cricket scoreboard feed.

You need: the definition of alphabet Σ and strings from Unit 1.

Alphabet, literals and basic symbols

An alphabet Σ is a finite non‑empty set of symbols. In most exam questions Σ = {0,1} for binary strings or Σ = {a,…,z} for lower‑case letters. A literal is any single symbol from Σ that appears unchanged in a regular expression. The empty string is denoted by ε and the empty set by ∅. Concatenation of two strings x and y is written xy and has length |x|+|y|.

L(ε) = {ε}

L(ε) is the language denoted by the literal ε; it contains only the empty string.

  • Σ = set of allowed characters.
  • Literal = a symbol from Σ that matches itself.
  • ε = empty string, matches a string of length zero.

Operators and precedence rules

The meta‑characters that build complex languages are union (|), concatenation (·), Kleene star (*), and parentheses ( ). Some syllabi call them operators. Union means choice: A|B matches any string in A or in B. Concatenation means sequence: AB matches a string that first belongs to A then to B. Star means zero or more repetitions: A* matches ε, A, AA, AAA, …

L(A|B) = L(A) ∪ L(B)

L(A) and L(B) are the languages of the sub‑expressions A and B.

L(AB) = { xy | x∈L(A), y∈L(B) }

All possible concatenations of a string from A with a string from B.

L(A*) = { x1x2…xk | k≥0, each xi∈L(A) }

k = 0 gives the empty string ε.

Precedence decides which operator applies first when parentheses are omitted. The order from strongest to weakest is: ( ), then *, then concatenation, then |. This means that 0|1* is interpreted as 0|(1*), not (0|1)*.

  1. First apply parentheses.
  2. Next apply the star to the nearest sub‑expression.
  3. Then concatenate left to right.
  4. Finally apply union.

Writing expressions with correct precedence

When you write a pattern, insert parentheses only when you need to override the default order. For example, the language of strings that contain at least one 1 is expressed as 0*1(0|1)*. The star after 0 applies only to the leading zeros, then the literal 1 is concatenated, and finally the star after the parenthesised union repeats any combination of 0 and 1.

If you need a repetition of a union, place the union inside parentheses before the star: (0|1)* matches all binary strings, while 0|1* matches only 0 or any number of 1s.

  • Use ( ) to group alternatives before applying *.
  • A*B* already represents two independent repetitions: zero or more A's followed by zero or more B's. Parentheses are optional unless you need to change the grouping.

Python program.

import re
pattern = r'1(0|1)*0'
print(bool(re.fullmatch(pattern, '1010')))

Output

True

Common mistakes and tips

A frequent trap is to forget that concatenation has higher precedence than union. Writing 0|1·0 means 0|(1·0), not (0|1)·0. Another error is to place the star after a union without parentheses; 0|1* is read as 0|(1*) and does not generate strings like 01. Remember that the empty set ∅ cannot be written as just nothing; it must be written explicitly.

When you translate a verbal description into a regex, first list the required parts in order, then add * or + where repetition is allowed, and finally insert parentheses only around groups that must repeat as a whole.

  • Mistaking 0|1* for (0|1)*.
  • Writing A·B|C and thinking it means (A·B)·C.
  • Omitting parentheses around a union that is starred.

2.2 Algebraic laws for regular expressions

Algebraic laws let you rewrite regular expressions without changing the language they denote. They are useful when you need a shorter expression for a pattern, when you compare two expressions, or when you convert an expression to an automaton. Only a few universities teach these laws as a separate topic, but they appear in many exam solutions and in tools that optimise pattern matching.

You need: Regular expressions: operators and precedence.

Identity, null and idempotent laws

An identity element does not change the language when it is concatenated. The empty string ε is the identity for concatenation. For any expression a, a·ε = a and ε·a = a. Both sides denote the same set of strings.

A null element makes the whole expression denote the empty language ∅. For any a, a·∅ = ∅ and ∅·a = ∅. The language on the left contains no strings, so the right side also contains none.

Idempotent law removes duplicate alternatives. (a|a) = a because the union of a language with itself is the same language. This law works for any expression a.

L(a·ε) = L(a) L(a·∅) = ∅ L(a|a) = L(a)

L(x) is the language described by expression x.

  • Use identity to drop unnecessary ε.
  • Use null to eliminate concatenations that can never produce a string.
  • Use idempotent to shorten unions.

Distributive and star laws

Distributive law moves concatenation over union. a·(b|c) = a·b | a·c and (a|b)·c = a·c | b·c. Both sides generate exactly the same strings because each choice in the union is followed by the same concatenation.

Star law defines the Kleene closure. a* denotes zero or more repetitions of a. It satisfies a* = ε | a·a* and a* = ε | a*·a. The law shows that adding one more copy of a does not change the language.

a·(b|c) = a·b | a·c   (a|b)·c = a·c | b·c   a* = ε | a·a*

· is concatenation, | is union, * is Kleene star, ε is empty string.

  1. Identify a part of the expression that matches the left side of a law.
  2. Replace it with the right side.
  3. Repeat until no further reduction is possible.

Worked example

  3. The idempotent law does not apply because the two (a|b)* are separated by a.
  4. The distributive law cannot move a across the stars because star does not distribute over concatenation.
  5. Therefore the expression cannot be reduced further.

2.3 Converting regular expressions to finite automata

Thompson’s construction turns any regular expression into an ε‑NFA. The method builds a small machine for each operator and connects them. It is used when a pattern must be matched by a scanner or when a compiler builds lexical analyzers. The resulting automaton accepts exactly the strings described by the original expression.

You need: basic DFA and NFA concepts from Chapter 1.

Basic fragments

A literal symbol a becomes a fragment with a start state, an a‑labeled edge, and an accept state. The start state is drawn in accent colour. The accept state is drawn in live colour.

  1. Create a new start state q0.
  2. Create a new accept state q1.
  3. Add an edge q0 → q1 labelled a.

states = 2

states is the number of states added for a literal.

The fragment is an ε‑NFA because it can be combined with other fragments using ε‑moves.

Fragments for union, concatenation and star

Union (r|s) adds a new start state and a new accept state. ε‑edges go from the new start to the starts of r and s. ε‑edges go from the accepts of r and s to the new accept.

  1. Create new start q0 and new accept qf.
  2. Add ε‑edges q0 → start(r) and q0 → start(s).
  3. Add ε‑edges accept(r) → qf and accept(s) → qf.

Concatenation rs connects the accept of r to the start of s with an ε‑edge. No new start or accept is needed.

  1. Add ε‑edge accept(r) → start(s).

Kleene star r* adds a new start q0 and a new accept qf. ε‑edges go q0 → start(r), q0 → qf, accept(r) → start(r), and accept(r) → qf.

  1. Create q0, qf.
  2. Add ε‑edges q0 → start(r) and q0 → qf.
  3. Add ε‑edges accept(r) → start(r) and accept(r) → qf.

states_union = states_r + states_s + 2

states_r and states_s are the numbers of states in the fragments for r and s.

Why the construction preserves language

Each fragment accepts exactly the strings described by its sub‑expression. The proof proceeds by structural induction on the expression.

  • Base case: a literal fragment accepts only the single‑character string a.
  • Inductive step for union: any string accepted by r or s follows a path from the new start to the new accept using the ε‑edges.
  • Inductive step for concatenation: a string accepted by rs splits into a prefix accepted by r and a suffix accepted by s. The ε‑edge joins the two paths.
  • Inductive step for star: the loop ε‑edges allow zero or more repetitions of r. The direct ε‑edge from start to accept handles the empty string.

Because ε‑moves do not consume input, the machine can move freely between fragments. Therefore the language of the whole ε‑NFA equals the language of the original regular expression.

Practical notes for exam drawing

Draw each fragment clearly. Indicate start states by drawing an arrow that points to the state from outside the diagram. Mark accept states with a double circle or the live style.

  • Never omit ε‑edges. Missing one changes the language.
  • Keep the order of operators: star has highest precedence, then concatenation, then union.
  • When two fragments share a state, reuse the state instead of creating a duplicate.

Python program.

def epsilon_closure(states, eps):
    stack = list(states)
    closure = set(states)
    while stack:
        q = stack.pop()
        for r in eps.get(q, []):
            if r not in closure:
                closure.add(r)
                stack.append(r)
    return closure

The routine above computes all states reachable by ε‑moves. It is used by simulation algorithms for ε‑NFAs.

2.4 Converting DFA to regular expressions; Arden's theorem

A DFA can be turned into a regular expression. The conversion lets you replace a state machine by a pattern that matches the same strings. This is useful when you need a compact description for searching, validation, or proving language properties.

You need: deterministic finite automata and regular‑expression operators from 2.1 and algebraic laws from 2.2.

State‑elimination method

Start with a DFA M = (Q, Σ, δ, q0, F). Add a new start state s and a new final state f. Add an ε‑transition from s to the old start q0. Add an ε‑transition from each old final state to f. Remove all original final states from F.

  1. Pick a non‑start, non‑final state r to eliminate.
  2. For every pair of states (p, q) that has a path p → r → q, create a new edge label.
  3. If there is an existing edge p → q with label X, and the new label is Y, replace the label by X + Y (regular‑expression union).
  4. Remove state r and all its incident edges.

When a state has a self‑loop labelled P, the loop contributes P* to any path that passes through the state. Concatenation of edge labels follows the order of traversal.

Rnew = Rold + X·P*·Y

Rold is the previous label from p to q; X is the label from p to r; P is the label on the self‑loop of r; Y is the label from r to q.

Repeat the elimination until only s and f remain. The label on the edge s → f is a regular expression that denotes L(M).

  • The method works for any DFA.
  • The order of elimination can affect the size of the intermediate expressions but not the final language.

Arden’s theorem

Arden’s theorem solves equations of the form R = Q + R·P where R, Q, P are regular expressions and ε ∉ P.

R = Q·P*

Q is the part that does not contain R; P is the part that follows R on each recursion.

If a DFA has been reduced to two states s and f with a self‑loop on s labelled P and a direct edge s → f labelled Q, then the language is P*·Q (zero or more repetitions of P followed by Q).

The theorem guarantees a unique solution because regular expressions form a closed algebra under union, concatenation and star.

  • Do not apply Arden when P can generate ε; the star would be redundant.
  • The theorem is often the last step after state elimination.

Worked example and summary

Consider the DFA with Q = {0,1,2}, Σ = {a,b}, start state 0, final state 2, and transitions: 0 —a→ 1, 1 —b→ 2, 2 —a→ 2.

  1. Add new start s and new final f. Add ε(s,0) and ε(2,f).
  2. Eliminate state 1. Create edge 0 → 2 with label a·b.
  3. Graph now: s —ε→ 0, 0 —a·b→ 2, 2 —a→ 2, 2 —ε→ f.
  4. Apply Arden’s theorem on state 2: the equation is R = ε + R·a, so Q = ε and P = a. By Arden, R = ε·a* = a*. The expression from s to f becomes ε·(a·b)·a* = a·b·a*.

The final regular expression a·b·a* matches exactly the strings accepted by the original DFA.

The example shows every step of the algorithm: adding auxiliary states, eliminating a middle state, handling a self‑loop, and applying Arden’s theorem.

  • Treating a self‑loop label a as a instead of a* before applying Arden leads to a·b·a, which is too short.
  • Eliminating the final state before adding a new final f changes the set of accepting paths.
  • Confusing concatenation (·) with union (+) when merging edge labels.

2.5 Kleene's theorem: finite automata equal regular expressions

Kleene’s theorem says that the languages described by regular expressions are exactly the languages accepted by finite automata. This equality lets designers switch between a pattern‑matching view (RE) and a state‑machine view (FA) depending on which is easier for analysis, implementation or proof. It underlies tools such as lexical analyzers, search utilities and network firewalls, where a pattern must be compiled into a fast automaton.

You need: the definitions of DFA, NFA and regular expressions from Regular expressions: operators and precedence and the construction of an NFA from an RE from Converting regular expressions to finite automata.

Statement of Kleene’s theorem

Kleene’s theorem states that a language L over Σ is regular if and only if there exists a regular expression r such that L = L(r), which is also equivalent to the existence of a finite automaton (DFA or NFA) M with L = L(M). Some syllabi call this the RE‑FA equivalence.

  • Regular expression → NFA (proved earlier).
  • DFA → regular expression (proved later using state elimination).

The theorem has two practical consequences. First, any pattern written by a programmer can be turned into an automaton that runs in linear time on the input. Second, any automaton built for a protocol or a hardware controller can be expressed as a compact algebraic pattern, useful for documentation and equivalence checking.

From regular expression to NFA (already known)

Given a regular expression r, the Thompson construction builds an ε‑NFA N such that L(N) = L(r). Each operator has a small gadget: concatenation links two NFAs in series, union adds a new start state with ε‑branches, and Kleene star adds a loop back to the start and an ε‑edge to a new accept state.

  1. Parse r respecting precedence (·, |, *).
  2. Create a leaf NFA for each symbol a ∈ Σ.
  3. Combine leaf NFAs using the gadgets for the operators.
  4. The resulting NFA may have many ε‑moves; when converting to a DFA, the subset construction first computes ε‑closures of NFA states before processing input symbols.

L(N) = L(r)

L(N) is the set of strings accepted by the constructed NFA; L(r) is the language denoted by the regular expression.

From DFA to regular expression

To turn a DFA M = (Q, Σ, δ, q₀, F) into a regular expression we eliminate states one by one. For each elimination we update the transition labels with regular‑expression concatenation and union, preserving the language of the reduced automaton. When only the start and a single final state remain, the label on the edge between them is the desired expression.

  1. Add a new start state s with ε‑move to the original start q₀.
  2. Add a new final state f and ε‑moves from each original final state to f.
  3. While more than two states exist, pick a state r ≠ s,f and remove it.
  4. For every pair (i, j) update the edge label: R₍ᵢⱼ₎ ← R₍ᵢⱼ₎ ∪ R₍ᵢʳ₎·(R₍ʳʳ₎)*·R₍ʳⱼ₎.
  5. When only s and f remain, the label on (s,f) is the regular expression for L(M).

Arden’s theorem guarantees that a system of regular‑expression equations derived from the DFA has a unique solution, which can be used to obtain a regular expression equivalent to the one produced by state elimination. The method is systematic and works for any DFA, proving the second direction of Kleene’s theorem.

Worked example

  10. Continue exploring transitions until no new subsets appear. The final DFA has both accepting and non‑accepting states; only those subsets that contain the NFA accept state(s) are marked accepting.

2.6 Pumping lemma and non-regular languages

The pumping lemma gives a property that every regular language must satisfy. It is used to show that a language cannot be described by any finite automaton. When the property fails for a particular language, the language is proved non‑regular.

You need: deterministic and nondeterministic finite automata from Regular expressions: operators and precedence and the conversion of regular expressions to automata from Converting regular expressions to finite automata.

Statement of the pumping lemma

Let L be a regular language. Then there exists a positive integer p, called the pumping length, that depends only on L. For every string w in L with length |w| ≥ p, we can split w into three parts w = xyz such that:

  • the prefix length satisfies |xy| ≤ p,
  • the middle part is not empty, i.e., |y| > 0,
  • for every integer n ≥ 0 the string xyⁿz is also in L.

∀n≥0  xyⁿz ∈ L

n is a non‑negative integer; xyⁿz means the string obtained by repeating y n times between x and z.

The lemma follows from the pigeonhole principle applied to the finite set of states of a DFA that recognises L.

Why the lemma is only a necessary condition

If a language satisfies the three conditions for some p, the language may still be non‑regular. The pumping lemma does not give a way to construct a DFA; it only tells what must happen if a DFA exists.

Therefore the lemma is used in a proof by contradiction: assume the language is regular, obtain a pumping length p, exhibit a string that violates the conditions, and conclude that the assumption was false.

  1. Assume L is regular.
  2. Let p be the pumping length guaranteed by the lemma.
  3. Choose a specific w ∈ L with |w| ≥ p.
  4. Show that every possible split w = xyz with |xy| ≤ p and |y| > 0 leads to a violation when n = 0 or n = 2.
  5. Conclude that L cannot be regular.

Typical proof technique – example language

Consider the language L = {0ⁿ1ⁿ | n ≥ 0}. It contains equal numbers of 0s followed by 1s. We will prove that L is not regular using the pumping lemma.

Assume L is regular. Let p be the pumping length. Choose w = 0ᵖ1ᵖ. The length of w is 2p, which is ≥ p.

Because |xy| ≤ p, the substring y can contain only 0s. Let |y| = k where 1 ≤ k ≤ p.

Pump down with n = 0. The new string is xz = 0^{p‑k}1ᵖ. It has fewer 0s than 1s, so xz ∉ L. This contradicts the lemma.

Hence L does not satisfy the pumping lemma and is not regular.

def pump_check(p, k):

2.7 Closure and decision properties of regular languages

Regular languages stay regular when we combine them with common operations. This closure lets us build new recognisers quickly. It also lets us answer questions such as “does the language contain any string?” or “are two specifications equivalent?”. The properties are used in compiler tokenisers, network protocol filters, and in proving that a design cannot be expressed by a regular pattern.

You need: DFA and NFA basics from Converting regular expressions to finite automata.

Closure under the regular operations

A language is regular if some DFA accepts exactly its strings. If L1 and L2 are regular, then L1 ∪ L2 is regular because we can run the two DFAs in parallel and accept if either accepts.

  1. Construct DFA D1 for L1 and DFA D2 for L2.
  2. Form the product DFA whose states are pairs (q1,q2).
  3. Mark a pair as final if q1 is final in D1 or q2 is final in D2.

The same product construction works for intersection: a pair is final only if both components are final. For difference L1 \ L2 we accept when the first component is final and the second is not.

Concatenation L1·L2 is regular because we can modify D1 to make every final state non‑accepting and add ε‑transitions to the start state of D2. The accepting states of D2 stay accepting, so the NFA accepts a string when it reaches a final state of D2 after possibly passing through D1. The resulting NFA can be turned into a DFA.

The Kleene star L* is regular. Add a new start state that is also final, add ε‑transitions to the original start, and add ε‑transitions from every original final state back to the start.

Complement works only after the automaton is deterministic and complete. Flip the set of final states. This gives the language of all strings over the alphabet that are not in the original language.

  • Union, intersection, and difference need the product DFA.
  • Concatenation and star need ε‑transitions, then subset construction.
  • Complement needs a complete DFA.

Decision properties of regular languages

Because regular languages have a finite description, many questions can be answered algorithmically.

  • Emptiness: check if any final state is reachable from the start state.
  • Finiteness: check for a cycle reachable from the start that also reaches a final state; if such a cycle exists, the language is infinite.
  • Membership: run the DFA on the given string and see if it ends in a final state.
  • Equivalence: construct the symmetric difference (L1 \ L2) ∪ (L2 \ L1) and test it for emptiness.

All four problems are decidable in time linear in the size of the input automata; equivalence and finiteness may require a product construction, giving O(n₁·n₂) time in the worst case.

Reachable(q) = true if there exists a path from start to q

q is a state of the DFA; Reachable is computed by BFS.

Applying closure to decide a language property

Suppose L = (0|1)*01. Its complement contains all strings that do not end with 01. We can build a DFA for L, complement it, and then test emptiness.

  1. Build DFA D for (0|1)*01 (three states: q0 start, q1 after seeing a 0, q2 after seeing 01 and is accepting).
  2. Complete D by adding missing transitions to a dead state.
  3. Flip final states to obtain DFA D̅ for the complement.
  4. Run BFS from the start of D̅; find that the dead state is reachable, so the language is non‑empty.

If we restrict to strings of length 2, the complement contains 00,10,11 – three strings. This finite count shows the emptiness test works on any finite bound.

2.8 Myhill-Nerode theorem

The Myhill‑Nerode theorem characterises regular languages. It can be used to prove that a language is regular or not regular by examining the number of equivalence classes.

You need: deterministic finite automata (Chapter 2.5) and the notion of an equivalence relation (Chapter 2.1).

The Myhill‑Nerode relation

Let L be a language over an alphabet Σ. For any two strings x and y in Σ* define x ≡L y if for every string z in Σ* the concatenation xz is in L exactly when yz is in L. This relation looks at the future extensions of x and y.

x ≡L y ⇔ ∀z∈Σ* ( xz∈L ↔ yz∈L )

x, y are strings; z is any possible suffix; L is the language under study.

The relation ≡L is an equivalence relation. It partitions Σ* into disjoint classes called Myhill‑Nerode classes. All strings in the same class behave identically with respect to L.

  • Reflexive: x ≡L x for every x.
  • Symmetric: if x ≡L y then y ≡L x.
  • Transitive: if x ≡L y and y ≡L w then x ≡L w.

Statement of the Myhill‑Nerode theorem

The theorem says: A language L is regular if and only if the equivalence relation ≡L has a finite number of equivalence classes.

  • If L is regular, a DFA that recognises L can be built with one state for each class.
  • If ≡L has finitely many classes, a DFA can be constructed by taking the classes as states and using the transition rule [x] --a--> [xa].

The theorem gives both a test for regularity and a recipe for the smallest possible DFA.

From equivalence classes to a minimal DFA

  1. Compute the relation ≡L for the language of interest.
  2. Group all strings that are equivalent into classes.
  3. Create a DFA state for each class.
  4. Make the start state the class containing the empty string ε.
  5. Mark a state as accepting if its class contains at least one string in L.
  6. Define the transition: from class [x] on symbol a go to class [xa].

The resulting DFA is minimal. No two distinct states can be merged because their classes differ in future behaviour.

The algorithm is often called the Myhill‑Nerode minimisation. It is equivalent to the table‑filling method taught earlier, but it gives a clear conceptual picture.

2.9 Applications of finite automata and regular expressions

Finite automata and regular expressions turn textual patterns into fast, predictable machines. They are used in lexical analysis, form validation, and search tools. By compiling a regex to a DFA the matcher runs in linear time, which is vital for large inputs such as mobile‑number lists or IRCTC PNR searches.

You need: Regular expressions: operators and precedence, Converting regular expressions to finite automata and the basics of DFA from Unit 1.

Pattern matching in lexical analysis

A compiler reads source code as a stream of characters. The lexical analyser groups characters into tokens such as identifiers, numbers, and operators. Each token class is described by a regular expression. The analyser builds a DFA for every class and then scans the input once, moving from state to state.

  1. Write a regular expression for each token class.
  2. Convert each expression to an NFA, then to a DFA.
  3. Add a new start state with ε‑transitions to the start state of each token DFA, then apply the subset construction to obtain a single DFA.
  4. Run the combined DFA on the source file; each accepting state yields a token.
  • Keywords such as if and while have fixed strings.
  • Identifiers use the pattern [a‑zA‑Z_][a‑zA‑Z0‑9_]*.
  • Integer literals use [0‑9]+.

S_total ≤ Σ_i |Q_i|

S_total is the total number of DFA states after merging; |Q_i| is the number of states of the DFA for token i.

Input validation with regular expressions

Web forms and mobile apps often need to check that a user entered a correctly formatted value. Regular expressions describe the allowed pattern, and a compiled DFA can test the input in O(length) time without back‑tracking.

Search tools and compilation to DFA

Command‑line tools such as grep or IDE find‑replace dialogs accept a regular expression from the user. Internally they first parse the expression, then construct an NFA, convert it to a DFA, and finally run the DFA over the target text. The DFA guarantees linear‑time matching, which is why grep -E can search gigabytes of log files in seconds.

  1. Parse the regex into an abstract syntax tree.
  2. Apply Thompson’s construction to obtain an NFA.
  3. Run the subset construction to get a DFA.
  4. Minimize the DFA (optional) to reduce memory.
  5. Execute the DFA on the input stream.
  • The DFA does not need back‑tracking.
  • Memory usage grows with the number of DFA states, not with input size.
  • Complex features such as back‑references are not regular and are handled by a separate engine.

Worked example

Question. A web form must accept only valid Indian mobile numbers. The regular expression is [6-9][0-9]{9}. (a) Draw the DFA with eleven states. (b) Simulate the DFA on the strings 9876543210 and 1234567890. State the final decision for each string.

C program.

#include <stdio.h>
int main(){
    char *tests[] = {"9876543210", "1234567890"};
    for(int t=0; t<2; ++t){
        char *s = tests[t];
        int state = 0;
        for(int i=0; s[i]; ++i){
            char c = s[i];
            if(state==0){
                if(c>='6' && c<='9') state=1; else {state=-1; break;}
            } else if(state>=1 && state<=9){
                if(c>='0' && c<='9') state++; else {state=-1; break;}
            } else {state=-1; break;}
        }
        printf("%s -> %s\n", s, state==10?"Accepted":"Rejected");
    }
    return 0;
}
  1. Create start state q0.
  2. From q0, on symbols 6‑9 go to q1; any other symbol goes to dead state.
  3. For i = 1 to 9, from qi on any digit 0‑9 go to qi+1; other symbols go to dead state.
  4. State q10 is accepting.
  5. Simulation on 9876543210: q0→q1 (9), q1→q2 (8), …, q9→q10 (0). End in q10 → Accepted.
  6. Simulation on 1234567890: first symbol 1 is not in 6‑9, so q0→dead. End in dead → Rejected.

Exam traps

  • Mistaking {9} for nine repetitions plus the leading digit, thus expecting eleven digits.
  • Using [6‑9] as a character class that also matches the hyphen; actually [6‑9] matches only the digits 6, 7, 8, 9. To include a literal hyphen, place it first or escape it (e.g., [-6‑9] or [6‑9\-]).
  • Assuming the DFA automatically rejects strings longer than ten characters; without a dead state the machine may stay in the accepting state.
  • Confusing the start state q0 with the first digit state q1, leading to an off‑by‑one error in simulation.

Check yourself

Remember What is the accepting condition for a DFA? 2 marks

The input is accepted if, after consuming the whole string, the DFA is in an accepting (final) state.

Understand Explain why a regular expression that contains back‑references cannot be compiled to a DFA. 4 marks

Back‑references require remembering a previously matched substring, which needs unbounded memory. DFAs have only finite control, so they cannot model this dependency; the language is not regular.

Apply Given the regex ab*c, list the sequence of DFA states visited when the input abbbc is processed. 3 marks

Analyze A DFA for a regex has 50 states. After minimization it has 12 states. How does this affect the time and space required for matching a 1 MB text file? 5 marks

Time remains O(n) where n is the number of characters, because each character causes one transition regardless of state count. Space drops from storing 50 transition entries per input symbol to 12 entries, reducing memory usage roughly by a factor of four.

Remember Name two common tools that use regular‑expression‑to‑DFA compilation. 2 marks

grep and lex (or flex).

Understand Why is the subset construction necessary when converting an NFA to a DFA? 3 marks

An NFA can be in many states simultaneously. The subset construction creates DFA states that represent each possible set of NFA states, ensuring deterministic behaviour.

Takeaways

  1. Regular expressions and finite automata describe exactly the same class of languages.
  2. Operator precedence makes regular expressions unambiguous.
  3. Algebraic laws enable systematic simplification of regular expressions.
  4. Any regular expression can be converted to an equivalent NFA using Thompson's construction.
  5. Arden’s theorem provides a direct way to solve linear equations in regular expressions.
  6. The pumping lemma is a necessary condition for regularity and helps prove non‑regularity.
  7. Regular languages are closed under union, concatenation, star, complement, and many other operations.
  8. Myhill–Nerode theorem gives a characterization of regular languages via finitely many equivalence classes.
  9. Regular expressions are widely used in text search, lexical analysis, and network filtering.

Operation under which the class of regular languages remains closed

Set of all strings over the alphabet that are not in the given language

Operation forming strings by placing a string from L1 before a string from L2

Problem with a yes/no answer that can be algorithmically solved

Automaton with exactly one transition for each state‑symbol pair

Automaton (Mealy or Moore) that produces output symbols along transitions or states

Operator that denotes zero or more repetitions of a language

Set of strings over a given alphabet

L1 ⊆ L2 means every string of L1 is also in L2

Program that uses regular expressions to convert source code into tokens

Finite automaton where output depends on state and input symbol

DFA with the smallest possible number of states for a regular language
Moore machine
Finite automaton where output depends only on the current state
Myhill–Nerode equivalence
Relation that partitions strings based on indistinguishability by the language
Nondeterministic finite automaton (NFA)
Automaton that may have multiple or zero transitions for a state‑symbol pair

Finding substrings in a text that match a given regular expression

Property that all regular languages satisfy, used to prove non‑regularity
