2.1 Regular expressions: operators and precedence

A regular expression is a finite formula that describes a language. Its atoms are the empty set ∅, the empty string ε, and each symbol a of an alphabet Σ. Union, concatenation and Kleene star combine atoms into bigger expressions. Precedence removes most brackets: star binds tightest, then concatenation, then union. A search box, a grep command or an input validator often uses this same notation, because a short pattern must accept exactly the strings that match and reject the rest.

You need Unit 1 on alphabets, strings and languages, especially Σ*, concatenation and Kleene star, and the language operations in alphabets and strings.

Atoms, operators and the language denoted

Fix a finite alphabet Σ. A string is a finite sequence of symbols from Σ. Σ* is the set of all such strings, including ε. A language is any subset of Σ*. A regular expression over Σ is a finite formula built by the rules below.

  • Base rule 1: ∅ is a regular expression and denotes the empty language ∅.
  • Base rule 2: ε is a regular expression and denotes {ε}.
  • Base rule 3: each a ∈ Σ is a regular expression and denotes {a}.
  • Inductive rule: if r and s are regular expressions, then (r+s), (rs) and (r*) are regular expressions.

Some books write r|s instead of r+s. Concatenation is written by juxtaposition: rs means r followed by s. A centred dot is not standard for concatenation here; it is used only when explaining a parse.

L(r + s) = L(r) ∪ L(s)

r and s are regular expressions; L(r) is the language denoted by r; + is union, also written | in some books.

L(rs) = L(r)L(s)

L(r)L(s) is the concatenation of the two languages: every string xy with x in L(r) and y in L(s).

L(r*) = {w1w2...wk | k ≥ 0 and each wi ∈ L(r)}

k is the number of repetitions; k = 0 gives ε, so ε is always in L(r*). The set L(r) is also called a regular set.

Over Σ = {0,1}: 0 denotes {0}; ε denotes {ε}; ∅ denotes ∅; 0+1 denotes {0,1}; 01 denotes {01}; 0* denotes {ε,0,00,...}; (0+1)* denotes all binary strings.

Precedence: star, then concatenation, then union

Precedence fixes the order of operations when brackets are omitted. Highest is Kleene star. Next is concatenation. Lowest is union. Operators of equal precedence group from left to right.

  1. First attach each star to the smallest preceding expression: a single symbol, a bracketed group, or an already starred expression.
  2. Second group concatenations from left to right.
  3. Third group unions from left to right.
  4. Brackets override all three passes.

Example: 0+1(01)*. The brackets (01) are concatenation 0·1. The star applies to that whole group, giving (0·1)*. Concatenation joins 1 to that star, giving 1·(0·1)*. Union is last, so the full expression is 0 ∪ (1·(0·1)*). The left 0 is not starred, and the star does not apply to the leading 1.

Some syllabi write union as |. Thus a+b and a|b denote the same language. Spaces and line breaks change nothing. Parentheses can always be added for clarity, even where precedence would allow omission. A pair of parentheses around a whole expression, such as (0+1), is allowed but not needed.

Building and checking an expression

To build an expression from a short description, name the pieces and put the weakest operator at the top. For 'a 0 followed by any number of 01 pairs', write 0(01)*. For 'either a single 0 or a 1 followed by any number of 01 pairs', write 0+1(01)*. For 'any string of 0s and 1s that ends in 1', write (0+1)*1.

To check an expression, compute its language from the inside out. List the atoms. Apply stars to the smallest possible groups. Concatenate adjacent languages by writing every pair xy with x from the left language and y from the right language. Union takes all strings from both languages. To test short strings by hand, generate strings by length from 0 upward and check membership.

Two atoms look alike but are different. ∅ is a language with no strings. ε is a language with one string of length 0. Therefore ∅* = {ε} and ε* = {ε}. Also ∅+ε denotes {ε}, not ∅. Star on ∅ never creates 0 or 1. Simplifying an expression uses the laws in Chapter 2.2; turning it into a machine is Chapter 2.3.

Exam traps

  • ∅ is not ε. L(∅)=∅ has no strings; L(ε)={ε} has one string of length 0. So ∅*={ε}.
  • Concatenation is juxtaposition, not a centred dot: write 01, not 0·1, unless you are explaining the parse.
  • Star binds tighter than union: 0+1* means 0 ∪ (1*), not (0+1)*.
  • Parentheses override precedence: (01)* is not 01*. The first repeats 01; the second is a 0 followed by any number of 1s.
  • Union is sometimes written + and sometimes |; do not mix them in one expression unless the notation is defined.

2.2 Algebraic laws for regular expressions

A regular expression is a formula that describes a language. Two different formulas can describe the same language. Algebraic laws for regular expressions are equations that let you replace one formula by an equal one, without drawing an automaton. They are used to simplify patterns, to prove that two patterns match the same strings, and to clean up expressions produced by automaton-to-regex conversions. The laws mirror ordinary algebra in some places and differ sharply in others: union is idempotent, concatenation is not commutative, and star has its own rules. Only a few universities teach this as a named topic.

You need: Chapter 2.1 for the operators, precedence and the meaning of ∅, ε and Kleene star.

Core identities

Write r, s and t for regular expressions, and L(r) for the language of r. An identity r = s means L(r) = L(s): both sides match the same strings. Here + is union, juxtaposition is concatenation, and * is Kleene star.

r + s = s + r,  (r + s) + t = r + (s + t),  r + r = r,  r + ∅ = r

r, s, t are regular expressions; + is union; ∅ is the empty language, containing no string.

Concatenation has identity ε and annihilator ∅: εr = rε = r and ∅r = r∅ = ∅. Here ε is the string of length zero. Concatenation is associative: (rs)t = r(st). It distributes over union: r(s + t) = rs + rt and (s + t)r = sr + tr.

The star laws are the ones students miss. (r*)* = r*, ε + rr* = r*, and (r + s)* = (r*s*)*. Also ∅* = ε and ε* = ε. Starring any language includes the empty string, so these last two are expected.

A simplification routine

Simplify by applying one law per step and naming it. Drop ∅ from unions. Drop ε from concatenations. Collapse double stars. Replace ε + rr* by r* when the union has ε and a starred copy.

  1. Find the outermost operator.
  2. Apply one reducing law and name it.
  3. Repeat while any law changes the expression.
  4. Test short strings on both sides.

Union is idempotent: r + r = r. There is no coefficient 2. Writing r + r = 2r is wrong because 2r is not a regular expression here. Also r + ε is not r in general; it adds the empty string.

The figure after this section uses these moves on (ε + a)*. The first rewrite is the union-star law; then ε* becomes ε; then ε is removed by the concatenation identity; finally the double star collapses. Check every step against the language, not against arithmetic.

Why the laws hold

Each law is a set statement. For r + r = r, a string is in L(r + r) exactly when it is in L(r) or in L(r), which is the same as being in L(r). For ∅r = ∅, no string can split into a part from ∅ and a part from r, because the first part cannot exist.

For (r + s)* = (r*s*)*, group consecutive pieces from r and from s into alternating blocks. Each block lies in r* or s*, so the whole string lies in (r*s*)*. Conversely, r* and s* use only r and s, so every string in (r*s*)* lies in (r + s)*.

These laws shorten expressions before conversion to an automaton in Chapter 2.3 and after conversion from a DFA in Chapter 2.4. They also support language equality proofs.

Exam traps

  • r + r = r, not 2r. This algebra has no coefficients.
  • ∅ and ε are different: ∅ has no strings, ε has one empty string. r + ∅ = r, but r + ε adds ε.
  • Concatenation is not commutative: ab ≠ ba in general.
  • Star binds tightest, and (r + s)* is not r* + s*. For example, ab is in (a + b)* but not in a* + b*.

2.3 Converting regular expressions to finite automata

A regular expression is a pattern written with union, concatenation and star. A finite automaton is a machine that accepts or rejects strings. Thompson's construction turns any regular expression into an ε-NFA by building one small machine for each operator and linking the pieces with ε-transitions. The result accepts exactly the strings described by the expression. Compiler lexers, search tools and input validators use this route when a pattern must become a working recogniser.

You need: Chapter 2.1 for expression syntax and Unit 1, NFA with epsilon transitions for ε-moves.

One small machine per operator

Thompson's construction is an induction on the shape of the expression. Every atom becomes a two-state machine. Every operator takes the machines for its subexpressions and wraps them into a larger machine. The new machine keeps the old machines unchanged, so the construction is mechanical. You never need to guess a transition.

The use of an ε-NFA is deliberate. A DFA would force you to merge states and recompute transitions during construction. An ε-NFA lets each subexpression keep its own start state and final state. The ε-transition then acts as a free link: it moves control without reading an input symbol.

This construction gives one half of Kleene's theorem: every regular expression has an equivalent finite automaton. Some syllabi call this the regular-expression-to-NFA construction. The reverse direction is in Chapter 2.4.

The four rules

Use one rule per operator. Let M₁ have start s₁ and final f₁; let M₂ have start s₂ and final f₂. A final state here means the single accepting state of the small machine, not a set of accepting states.

  • Atom a: states q0 and q1 with edge q0 --a--> q1. Start q0, final q1. For ε use q0 --ε--> q1. For ∅ use q0 and q1 with no edge.
  • Union R+S: add new start q and new final f. Add ε from q to s₁ and to s₂. Add ε from f₁ to f and from f₂ to f. Start q, final f; the old finals are not accepting in the combined machine.
  • Concatenation RS: keep both machines. Add ε from f₁ to s₂. Start s₁, final f₂. No new states are needed for this operator.
  • Star R*: add new start q and new final f. Add ε from q to s₁, q to f, f₁ to s₁, and f₁ to f. Start q, final f. The q→f link accepts zero copies; the f₁→s₁ loop accepts more copies.

The final machine is an ε-NFA: several transitions may leave one state on the same symbol or on ε, and ε moves do not consume input. The language is unchanged because each added ε path corresponds to a legal way to read the expression.

Counting states and checking ε-moves

Keep every subexpression's start and final state separate. If you merge them early, you can create a path that skips a required part or loops through the wrong operator. The construction's correctness depends on the ε links being exactly the ones listed by the rules. For a quick size check, let n be the number of atom leaves and k the number of union or star nodes. Concatenation adds no states.

|Q| = 2n + 2k

|Q| is the number of states; n is the number of atom leaves (symbols, ε or ∅); k is the number of union or star nodes. A concatenation node adds one ε-transition but no state.

For a(b+c)*, n = 3 atoms (a, b, c) and k = 2 operators (one union, one star). So |Q| = 2×3 + 2×2 = 10 states. A missing ε-link does not change the state count, but it does change the language. Check the star's skip link and its loop link first.

Exam traps

  • Missing star skip ε: without the ε from the new start to the new final in R*, the machine rejects ε.
  • Wrong union ε direction: the new start goes to the starts of the alternatives, and the old finals go to the new final; reversing these changes the language.
  • Shared start or final: each subexpression keeps its own start and final state; merging them during construction can create shortcuts that skip a symbol.
  • Concatenation final: add ε from the first machine's final to the second machine's start; do not make the first final an overall final.
  • Treating ε as input: ε-transitions consume no character, so they are not listed as alphabet symbols and do not add length to the string.

2.4 Converting DFA to regular expressions; Arden's theorem

A DFA recognises a language by moving between states. A regular expression describes the same language as a pattern. Converting one to the other lets you prove equality, feed a pattern to a tool, or simplify a machine. The method is to write one equation per state, then solve the equations with Arden's theorem. A graphical shortcut, state elimination, does the same job by deleting states one at a time. Compilers and text tools use this link when they turn token patterns into matching code.

You need: DFA and transition diagrams from Unit 1, and the operators of regular expressions from Chapter 2.1.

State equations for a DFA

For a DFA M = (Q, Σ, δ, q0, F), write one equation for each state q. The variable q stands for the language of all strings that take M from q to a final state. Every outgoing transition q --a→ p adds the term a·p: symbol a followed by any string that works from p. If q is final, also add ε, because the empty string is already at a final state. The equation is:

q = Σ<sub>a ∈ Σ, δ(q,a)=p</sub> a·p + (ε if q ∈ F)

q and p are states used as language variables; a·p is concatenation of the one-symbol string a with the language p; + is union; ε is the empty string; δ is the transition function.

  1. List every state and give each one a variable.
  2. For each state, collect one term per outgoing edge. Combine edges with the same destination as (a+b)p.
  3. Add ε only in the equation of a final state.
  4. Solve the equations for the start state q0. The expression you get is the required regular expression.

This method is mechanical: a two-state DFA gives two equations; a three-state DFA gives three equations. Use it when the automaton is small. For a large drawing, state elimination is faster.

Arden's theorem

Arden's theorem solves one equation with one unknown language. Suppose X is unknown, P and Q are known languages, and ε ∉ P. Then:

X = Q + P X  ⇒  X = P* Q,    X = Q + X P  ⇒  X = Q P*

X, P, Q are languages; P* is zero or more repetitions of P; the rule needs ε ∉ P.

In X = Q + P X, strings either stop via Q or do one P then solve X again. Repeated substitution gives X = Q + P Q + P P Q + … = (ε + P + P P + …) Q = P* Q. The condition ε ∉ P says P cannot produce the empty string, so every trip around the loop consumes at least one input symbol. If P can be ε, the repeated substitution never makes progress and the simple solution may fail. The right-side form is solved by Q P*: here the loop is written after X. Identify the form before applying the formula. Some syllabi call it Arden's lemma.

State elimination: the graphical version

State elimination is the same algebra drawn on the transition graph. It removes one state at a time. Add a new start state with an ε-edge to the old start, and a new final state with ε-edges from every old final state. Then delete each old state q. For every state i with an edge into q and every state j with an edge out of q, create or extend the edge i→j by the expression:

R<sub>ij</sub> + R<sub>iq</sub> (R<sub>qq</sub>)* R<sub>qj</sub>

Rab is the label on the edge from a to b, or ∅ if there is no edge; Rqq is the label of q's self-loop, or ∅ if there is none; ∅* = ε, so a state with no self-loop just contributes Riq Rqj; * allows the loop to repeat any number of times.

  1. Pick a state q to remove, never the new start or new final.
  2. For each predecessor i and successor j of q, add the path i→q→j. The label is Rij + Riq (Rqq)* Rqj.
  3. Delete q and all its edges.
  4. Repeat until only the new start and new final remain. Read the single remaining label as the regular expression.

Order can change the intermediate expression but not the language. Keep the graph small to avoid long labels.

Worked example

Question. Convert the DFA M over Σ={0,1} with states q0 (start) and q1 (final), and transitions q0--0→q0, q0--1→q1, q1--0→q0, q1--1→q1, into a regular expression using state equations and Arden's theorem.

  1. Write one equation per state. For q0: q0 = 0 q0 + 1 q1. For q1: q1 = 0 q0 + 1 q1 + ε.
  2. Solve q0 in terms of q1. Rewrite q0 = 1 q1 + 0 q0. This is X = Q + P X with X=q0, Q=1 q1, P=0. Since ε ∉ {0}, Arden gives q0 = 0* 1 q1.
  3. Substitute q0 into the q1 equation: q1 = ε + 0(0* 1 q1) + 1 q1.

Exam traps

  • In X = Q + P X, the star goes on P: X = P* Q, not Q* P. The other side X = Q + X P gives X = Q P*.
  • Add ε only to the equation of a final state, not to every equation.
  • Do not drop self-loops: a self-loop q --a→ q contributes a q.
  • Arden's rule needs ε ∉ P. If P contains ε, the simple star formula is not justified.
  • In state elimination, the new edge label order is Riq (Rqq)* Rqj; reversing it changes the language.

2.5 Kleene's theorem: finite automata equal regular expressions

A regular expression is a formula. A finite automaton is a machine. Kleene's theorem says these two, and every variant in between, describe exactly the same languages: anything you can write as a formula you can build as a machine, and anything a machine accepts you can write as a formula. That choice of tool is why grep compiles a pattern into a state machine, a compiler turns token rules into a lexer, and a form validator rejects bad input in one pass over the text.

You need Chapter 2.1 for regular-expression syntax, and Unit 1 for deterministic (DFA) and nondeterministic (NFA) finite automata.

One theorem, four ways to say the same thing

A language L over an alphabet Σ is regular when some DFA accepts it. Separately, a regular expression over Σ denotes a language: ∅ denotes no strings, ε denotes the single empty string, each symbol a ∈ Σ denotes {a}, and union, concatenation and Kleene star build larger languages from smaller ones. The two definitions look unrelated. Kleene's theorem says they describe the same collection of languages.

L is regular ⇔ L = L(M) for some DFA M ⇔ L = L(M) for some NFA M ⇔ L = L(r) for some regular expression r

L(M) is the set of strings the machine M accepts; L(r) is the set of strings the expression r denotes. All four statements are about the same language L over one finite alphabet Σ.

The first equivalence is the definition. The second is subset construction from Unit 1: every NFA becomes a DFA with the same language. The new content is the last one, proved in two halves — every regular expression becomes an ε-NFA accepting the same language, and every DFA becomes a regular expression denoting the same language. Some syllabi call this the equivalence of finite automata and regular expressions; others call it Kleene's theorem.

The intuition is finiteness. A formula is finite; an automaton has finitely many states. Both remember a bounded amount about the input read so far, and neither can count without a limit. That shared limitation is why the two notations match exactly.

The round trip: how each half is proved

The proof is a loop with three edges. Each edge is an algorithm, and each leaves the accepted language unchanged.

  1. Regex → ε-NFA, Thompson's construction. Build two-state machines for ∅, ε and each symbol; join machines for subexpressions with fresh states and ε-transitions for union, concatenation and star. With m symbols and operators in the expression (for a*, m = 2), the result has at most 2m states. See Chapter 2.3.
  2. ε-NFA → DFA, subset construction. Each new state is a set of old states closed under ε-transitions, and final if it holds a final state. An n-state NFA gives at most 2ⁿ DFA states. See Unit 1, NFA and DFA equivalence.
  3. DFA → regex, Arden's theorem or state elimination. Write one equation per state, then solve for the start state, eliminating states one at a time. See Chapter 2.4.

Edges 1 and 2 take a regular expression to a DFA; edge 3 takes a DFA back to a regular expression. With the Unit 1 equivalence, all four statements stand or fall together.

Two cautions. The 2m and 2ⁿ figures are upper bounds, not promises of small machines: a small DFA can need a long expression. And the loop passes through an ε-NFA, so a missed ε-closure in the middle edge quietly changes the language.

What the equivalence gives you

  • Closure under union, concatenation and star comes free: these are the three operators, and each has an automaton construction.
  • Intersection comes from the product construction on two DFAs. Complement comes from making final states non-final in a complete DFA, which is why the DFA must be deterministic and complete. See Chapter 2.7.
  • Membership: run the DFA on the string w, in O(|w|) time, whatever notation you started from.
  • Emptiness: check whether any final state is reachable from the start state.
  • Equivalence of two descriptions: convert both to DFAs, minimise both with table filling from Unit 1, and compare.

The practical gain is freedom of description. A pattern easy to write as a formula, such as [a-z]+@[a-z]+\.(com|in), compiles to a machine and runs in linear time. A machine easy to draw, such as the parity machine below, turns into a formula when you want an algebraic proof.

What the theorem does not give you is a test for non-regularity. It only says that if a language has an automaton it has a formula, and the reverse. To show a language has neither, you need the pumping lemma.

Exam traps

  • The theorem does not say every language is regular. It says the automaton world and the formula world are the same size. {0ⁿ1ⁿ : n ≥ 0} has no DFA and no regular expression, and both fail together.
  • ∅ and ε are different. ∅ denotes no strings at all; ε denotes exactly one string, the empty one. Writing ε where you mean ∅ changes the language.
  • In the middle edge, forgetting ε-closures in the subset construction produces a DFA for a different language. The theorem stays true; your conversion is what is wrong.
  • The bounds are upper bounds: an expression with m symbols and operators gives an ε-NFA with at most 2m states (for a*, 4 states), and an n-state NFA gives a DFA with at most 2ⁿ states.
  • A question asking 'prove L is regular' wants a DFA, an NFA or a regular expression. An English description of L earns nothing until you build one of the three or quote closure properties from Chapter 2.7.

2.6 Pumping lemma and non-regular languages

The pumping lemma is a test for non-regularity. Every regular language has a finite automaton with finitely many states. A long string must force the machine to revisit a state; the substring read between two visits can be repeated any number of times and the string stays in the language. This gives a necessary condition that every regular language obeys. We use it to prove that languages needing unbounded counting, such as 0ⁿ1ⁿ, are not regular. Compiler lexers and pattern tools rely on this boundary.

You need: Unit 1 DFA and Chapter 2.1; Kleene's theorem in Chapter 2.5 connects automata to regular expressions.

The statement

A language L over an alphabet Σ is regular when some DFA accepts it. The pumping lemma says every regular language has a positive integer p with a repeated-substring property.

If L is regular, there exists p ≥ 1 such that every w ∈ L with |w| ≥ p can be written w = xyz, where |xy| ≤ p, |y| ≥ 1, and xyⁱz ∈ L for every i ≥ 0.

p is the pumping length; w, x, y, z are strings; |w| is length; yⁱ is i copies of y, with y⁰ = ε; ε is the empty string.

The bound |xy| ≤ p keeps the pumped part y near the start of w. The condition |y| ≥ 1 forbids an empty pumped part. The index i can be 0, 1, 2, and so on. Some syllabi call this the pumping lemma for regular languages.

A DFA with p states gives a valid pumping length p. The lemma is a necessary condition. Every regular language obeys it; a non-regular language may also obey it.

Why a DFA must loop

Take a DFA M that accepts L, and let p be its number of states. Take any w ∈ L with |w| ≥ p. Write w = a1a2…an, so n = |w| ≥ p.

On reading w, M visits states q0, q1, …, qn. State q0 is the start state; qk is the state after the first k symbols. The list q0, q1, …, qp has p+1 states but M has only p distinct states.

By the pigeonhole principle, two of these states are equal: qj = qk with 0 ≤ j < k ≤ p. The substring from position j+1 to k is a loop in M.

Set x = a1…aj, y = aj+1…ak, z = ak+1…an. Then w = xyz. Also |xy| = k ≤ p and |y| = k − j ≥ 1.

The loop y can be removed or repeated any number of times. Removing y gives i = 0 and keeps the machine in the same state at the end, so xy⁰z is accepted. Repeating y i times gives xyⁱz and also ends in the same state. Therefore xyⁱz ∈ L for every i ≥ 0.

Using the lemma

A pumping-lemma proof is a contradiction. Assume L is regular, so it has some pumping length p. Choose one string w in L whose length is at least p and whose structure depends on p. Then show every legal split w = xyz fails for some i.

  1. Assume L is regular and let p be its pumping length.
  2. Choose w ∈ L with |w| ≥ p. Use the p in the choice, for example 0ᵖ1ᵖ.
  3. Consider every split w = xyz that satisfies |xy| ≤ p and |y| ≥ 1. Say what y must look like.
  4. Pick an i, often 0 or 2, and show xyⁱz ∉ L. One failed i is enough for that split.
  5. Since every split fails, the lemma is violated, so L is not regular.

The same pattern proves L = {aⁿbⁿ | n ≥ 0} and L = {0ⁿ1ⁿ0ⁿ | n ≥ 0} are not regular. In both, a legal y lies inside a block of identical symbols, and pumping changes one block count but not the others.

The method cannot prove a language is regular. If the lemma holds for L, L may still be non-regular. Use Chapter 2.8 for a test that is both necessary and sufficient.

Exam traps

  • The lemma is necessary, not sufficient. Some non-regular languages also satisfy it, so passing all pumps does not prove regularity.
  • In a proof, cover every legal split of w, not one convenient y. The split is chosen by the adversary under |xy| ≤ p and |y| ≥ 1.
  • |xy| ≤ p is not |xyz| ≤ p. The bound keeps y inside the first p symbols.
  • i = 0 is allowed; deleting y is often the fastest contradiction.
  • p is a pumping length, not the length of w. You choose w after p, usually with length depending on p.

2.7 Closure and decision properties of regular languages

Regular languages are closed under operations that build new languages from old ones. If L₁ and L₂ are regular, so are L₁ ∪ L₂, L₁L₂, L₁*, complement, intersection, difference and reversal. Closure matters because it lets you build complex patterns from simple automata and prove a language is regular without writing a fresh machine. Decision properties go further: algorithms answer emptiness, finiteness, membership and equivalence. These checks sit inside compilers, network filters and text search tools. A regular language is one accepted by a DFA or an NFA.

You need DFA and NFA from Unit 1 and Kleene's theorem from Chapter 2.5.

Closure means the result is still regular

Closure says an operation on regular languages produces another regular language. You prove closure by construction: give a machine for the result.

  • Union L₁ ∪ L₂: make an ε-NFA with a new start state and ε-edges to the start states of machines for L₁ and L₂. A string is accepted if either copy accepts.
  • Concatenation L₁L₂: add ε-edges from every final state of the L₁ machine to the start state of the L₂ machine. The old final states stop being final; the L₂ final states remain final.
  • Kleene star L₁*: add a new start state that is also final, an ε-edge to the old start, and ε-edges from old final states back to the old start. This allows zero or more copies.
  • Complement: take a DFA for L, add one nonfinal dead state for the missing transitions (with self-loops on every symbol) so the machine becomes complete, then swap final and nonfinal states. The dead state becomes final, which is correct because every string that falls off the original machine is in the complement.
  • Intersection and difference: build the product DFA. For L₁ ∩ L₂, accept pairs final in both. For L₁ − L₂, accept pairs final in L₁ and nonfinal in L₂. Difference is L₁ ∩ complement(L₂).
  • Reversal Lᴿ: reverse every transition, make the old start state final, add a new start state with ε-edges to every old final state. The result is an ε-NFA, so Lᴿ is regular.

These constructions are enough; no counting argument is needed.

Product construction, emptiness and finiteness

For DFAs A = (Q_A, Σ, δ_A, q_A, F_A) and B = (Q_B, Σ, δ_B, q_B, F_B), the product DFA P has states Q_A × Q_B. The start state is (q_A, q_B). On symbol a, δ_P((p, q), a) = (δ_A(p, a), δ_B(q, a)).

|Q_P| = |Q_A| × |Q_B|

|Q_P| is the number of product states; |Q_A| and |Q_B| are the numbers of states in the two input DFAs.

Complete both A and B with nonfinal dead states before building the product, for every operation (union, intersection, difference). Then δ_P is total and the final-state rule for the chosen operation is sound. Choose final states: intersection final if both; union if either; difference if first final and second not.

Emptiness: L(P) = ∅ iff no final state is reachable from the start state. Run BFS or DFS on the product graph. A final state that exists but cannot be reached does not make the language nonempty.

Finiteness: L(P) is finite iff no cycle lies on a path from the start state to a final state. Mark useful states: reachable from start and able to reach a final state. If any useful state has a cycle through useful states, the language is infinite; if the useful part is acyclic, it is finite.

Membership, equivalence and complete DFAs

Membership asks whether a given string w is in L. For a DFA, start at q₀ and read symbols left to right. After |w| steps, accept iff the final state is in F. Time is O(|w|). For an NFA, simulate by carrying the set of possible states: O(|w| × |Q| × |Σ|), where |Q| is the number of NFA states and |Σ| is the alphabet size. Converting to a DFA first is also correct but can cost up to 2|Q| states, so simulate unless you need the DFA anyway.

Equivalence asks whether L(A) = L(B). Complete both DFAs, then build the product. A pair (p, q) is a mismatch if exactly one of p, q is final. Run BFS from (q_A, q_B). If a mismatch is reachable, the languages differ; that reachable string is a witness. If no mismatch is reachable, the languages are equal. The same search decides inclusion by looking for a reachable pair with p final and q nonfinal.

The symmetric-difference view is L(A) Δ L(B) = (L(A) ∩ complement L(B)) ∪ (complement L(A) ∩ L(B)). The languages are equal exactly when this union is empty.

Complete DFA is the repeated requirement. A missing transition kills the run: the string is rejected. If you swap final and nonfinal states without adding the dead state, those runs still die after swapping, so strings that belong to the complement are wrongly rejected. Add one nonfinal dead state for all missing transitions, make it loop on every symbol, then swap. Swapping finals of an NFA is the case that wrongly accepts strings, because different runs of the same string end in different states. Convert NFA to DFA first using subset construction, and keep the dead state.

2.8 Myhill-Nerode theorem

The Myhill-Nerode theorem turns a question about machines into a question about strings. Two strings are equivalent for a language L when no suffix can tell them apart: for every z, xz and yz are both in L or both outside L. If L has finitely many such classes, L is regular, and the class count is exactly the state count of its smallest DFA. If there are infinitely many classes, L is not regular. The theorem is used to prove non-regularity cleanly and to justify DFA minimization. Some syllabi spell it Myhill–Nerode.

You need: DFA and extended transition function from Unit 1, and the pumping lemma from Chapter 2.6.

Indistinguishability and right congruence

Fix an alphabet Σ and a language L ⊆ Σ*. For strings x, y ∈ Σ*, write x ≡_L y when for every suffix z ∈ Σ*, xz ∈ L exactly when yz ∈ L. The suffix may be empty, so equivalent strings agree on membership themselves. This relation is an equivalence relation: reflexive, symmetric, and transitive by using the same z. It is also a right congruence: if x ≡_L y, then xa ≡_L ya for every symbol a ∈ Σ: for every suffix z, xaz ∈ L exactly when yaz ∈ L; since az is just some suffix of x and y, xa ≡_L ya. The index of ≡_L is its number of classes.

The link to machines is direct. In a DFA for L, after reading x the machine is in state δ*(q0, x). The future depends only on this state: the set of suffixes accepted from it. If x and y reach the same state, they are ≡_L. A DFA with n states therefore gives at most n classes. Two different states may still be equivalent if the DFA is not minimal. Classes are sets of strings, not states themselves.

The theorem and the minimal DFA

L is regular ⇔ ≡_L has finitely many classes

L is a language over Σ; ≡_L compares strings by every suffix z; the number of classes is the index.

If ≡_L has finitely many classes, build a DFA whose states are the classes [x]. The start state is [ε]. On symbol a, go from [x] to [xa]. Make [x] accepting when x ∈ L. Right congruence makes the transition well defined: if x ≡_L y, then xa ≡_L ya. This DFA accepts exactly L. So finite index implies regular.

If L is regular with a DFA M of n states, map each string x to the state reached after x. This gives at most n classes, so the index is finite. Thus regular implies finite index. The constructed DFA is minimal. If x and y are distinguishable, some z puts xz in L and yz outside L. No DFA can end in the same state after x and y, because then it would treat suffix z identically. So each class needs its own state. The number of classes equals the states of the minimal DFA. This matches DFA minimization in Unit 1: equivalent states correspond to classes of their access strings.

Proving non-regularity

To prove L is not regular, exhibit an infinite set S ⊆ Σ* whose strings are pairwise distinguishable. For every two different x, y ∈ S there is a suffix z, depending on x and y, with exactly one of xz, yz in L. Then x and y lie in different ≡_L classes. Infinite S means infinitely many classes. By the theorem, L is not regular. The suffix need not be the same for every pair; it only must separate that pair.

The standard pattern uses L = {0ⁿ1ⁿ | n ≥ 0}. The strings 0ⁱ are pairwise distinguishable. For i ≠ j, choose suffix 1ⁱ. Then 0ⁱ1ⁱ ∈ L, but 0ʲ1ⁱ ∉ L because the counts of zeros and ones differ. Hence infinitely many classes exist and L is not regular. The figure shows the 4×4 table for i, j = 0,1,2,3; the diagonal marks membership.

Do not confuse an infinite language with infinite index. Σ* is infinite and regular: every string is equivalent because every concatenation stays in Σ*. The index counts classes, not strings.

Exam traps

  • You need infinitely many pairwise distinguishable strings, not just an infinite language. Σ* is infinite and regular with one class.
  • A suffix may depend on the pair of strings being separated. Do not demand one suffix work for every pair at once.
  • The index equals the number of states of the minimal DFA, not the number of states of any DFA you happen to draw.
  • Two strings can both be in L (or both outside L) and still not be equivalent, because a longer suffix may separate them. For example in L = {0ⁿ1ⁿ}, the strings 0 and 00 are both outside L, yet suffix 1 puts 01 in L and 001 outside.

2.9 Applications of finite automata and regular expressions

Finite automata and regular expressions recognise fixed patterns quickly, with no memory of how many times something has happened. A scanner, a form validator, a packet filter and a lift controller all decide from a small fixed set of states. This chapter shows where those machines sit in real software and where the model stops: unbounded counting, nested brackets and backreferences are outside it.

You need: regular expression operators, Thompson's construction, and decision properties of regular languages.

Scanners turn a character stream into tokens

A compiler, interpreter or JSON reader begins with characters and needs tokens: named pieces such as an identifier, a number, a keyword or an operator. Each token class is a fixed pattern, so each is a regular language. Over letters and digits, an identifier is letter (letter | digit)*, using the operators from chapter 2.1.

The scanner, also called the lexer, is built in five steps.

  1. Write one regular expression for each token class: identifier, number, keyword, operator.
  2. Convert each expression to an ε-NFA and merge them into one machine with a single start state, as in chapter 2.3.
  3. Apply subset construction (chapter 2.2) to get one DFA whose accepting states are tagged with the token class they report.
  4. Run the DFA from the current input position and record the last accepting position reached.
  5. Emit the longest match; on a tie, the class listed first wins. Skip whitespace and comments, then repeat.

Longest match matters. On ifx the keyword rule for if matches 2 characters, but the identifier rule matches all 3, so the scanner emits id(ifx). On if( both rules match 2 characters; the tie goes to the keyword, giving kw(if) then the operator (. Generator tools build the DFA from a list of patterns, so a new token means a new pattern, not new code.

Search, validation and protocol scanning

Text search uses the same machine with a different stopping rule. The pattern is a regular expression and the text is read once, left to right. Build the DFA for the pattern and report a match every time the machine sits in an accepting state. One transition per character gives O(n) time for n characters of text; the DFA size depends on the pattern, not the text.

Validation is strict: the whole string must match. The answer is yes only if the machine consumes the whole string and ends in an accepting state; a run that falls into the dead state, or stops early, rejects. A six-digit PIN, a 10-digit mobile number, a date in dd-mm-yyyy form, a vehicle registration number — each is regular and each is checked in one pass.

A network card, a firewall or a TCP implementation looks for short fixed patterns: a start-of-frame byte, a flag combination, the word GET at the start of an HTTP request line, a closing tag. Such patterns are regular, and a machine can emit a signal on the transition that completes the pattern. In hardware a handful of flip-flops does the job at line rate.

A vending machine that releases a snack after ₹20 is inserted, a traffic light cycling through fixed phases, a lift that opens its door in the stopped state — each has a small fixed set of situations and a fixed response for each. That is a finite automaton with output; Moore and Mealy machines are covered in chapter 2.4.

How far the model reaches

Every finite automaton has a fixed number of states, so it carries a fixed amount of memory. That memory can hold a counter up to a fixed bound: between 0 and 5 a's is regular, written a{0,5}. It cannot hold a counter that grows with the input. The language {aⁿbⁿ : n ≥ 0} needs the machine to remember how many a's it saw and compare that with the number of b's, and no finite state set does that. The pumping lemma (chapter 2.6) makes the argument precise.

Nested structure fails for the same reason. Balanced brackets of arbitrary depth, an arithmetic expression with parentheses inside parentheses, a document with tags inside tags: each needs a stack, so each needs a pushdown automaton or a context-free grammar. A DFA can check the first few levels with one state per depth, but the depth is then capped.

Backreferences are the third limit. The pattern (ab)\1 matches abab by remembering what the group matched and comparing later; that memory is a copy of part of the input, of unbounded length. Engines also offer lookahead, lookbehind and recursive patterns: useful, but outside the mathematical definition. A mathematical regular expression uses only ∅, ε, alphabet symbols, union, concatenation and star, and Kleene's theorem (chapter 2.5) is about exactly that class.

The split has a practical edge. A DFA matcher reads each character once and cannot blow up; a backtracking engine with backreferences can take exponential time on some patterns. Where worst-case speed matters, tools use the finite-automaton core.

Worked example

Question. A website form accepts a 10-digit Indian mobile number whose first digit is 6, 7, 8 or 9. (a) Write a regular expression. (b) Give the DFA and count its states. (c) Test 9876543210 and 1234567890.

  1. Alphabet Σ = {0,1,...,9}. The first digit must be in {6,7,8,9}, written [6-9].
  2. The remaining 9 digits are any digit, written [0-9]{9}.
  3. Concatenate: R = [6-9][0-9]{9}.
  4. q0 is the start. On 6–9 it moves to q1; on 0–5 it moves to a dead state d, which loops on every digit.
  5. For 1 ≤ k ≤ 9, qk moves to q(k+1) on any digit 0–9; q10 is the only accepting state.
  6. State count: q0 through q10 is 11 states. One extra dead state catches a first digit in 0–5; all later digits are accepted, so 12 states in total.
  7. 9876543210: length 10, first digit 9 in {6,7,8,9}; the run ends in q10, so accepted.
  8. 1234567890: length 10 but first digit 1 is not in {6,7,8,9}; the run is q0 → d and stays in d. Rejected.

Answer. R = [6-9][0-9]{9}; 11 live states plus one dead state, so 12; 9876543210 accepted, 1234567890 rejected.

Exam traps

  • Treating regex-engine extras as regular. Backreferences, lookahead, lookbehind and recursive patterns are outside Kleene's regular expressions; an examiner will ask for a proof.
  • Confusing bounded and unbounded counts. a{0,100} is regular because the bound is fixed; aⁿbⁿ is not.
  • Ignoring longest match: ifx is one identifier id(ifx), not kw(if) plus id(x).
  • Thinking a DFA needs one state per input character. States count pattern positions: the mobile-number DFA has 12 states whatever the length.
  • Writing a regular expression for balanced brackets or aⁿbⁿ; those need a stack, so they are not regular.

Takeaways

  1. A regular expression is just a finite formula, so it can only describe patterns that need a fixed, finite amount of memory to check.
  2. Precedence matters: star first, then concatenation, then union, and parentheses override everything.
  3. The algebraic laws let you simplify an expression or prove two expressions equal without drawing a single state.
  4. Thompson's construction builds an ε-NFA operator by operator, so the machine is correct by construction rather than by insight.
  5. Arden's theorem turns state equations into a tidy closed-form expression and is the quickest hand method for DFA to RE.
  6. Kleene's theorem is the bridge of the whole unit: DFA, NFA, ε-NFA and regular expressions all describe the same languages.
  7. The pumping lemma is a one-way test: failing it proves a language is not regular, passing it proves nothing.
  8. Myhill–Nerode is exact in both directions and also gives the smallest DFA, which the pumping lemma cannot do.
  9. Closure and decision properties mean you can answer many questions about regular languages by pure machine manipulation, with no cleverness required.
  10. Regular expressions power search boxes, tokenizers and network filters, but nested structure needs a pushdown automaton instead.

Complement: complete the DFA, then swap final and non-final states; Intersection: product construction, final states are pairs where both components are final; Difference: L₁ ∩ complement(L₂); Determinism is needed for complement, since swapping states of an NFA does not complement its language; Simultaneous simulation on all NFA states fixes the problem, at a cost in state count.

Glossary

Alphabet (Σ)
A finite, non-empty set of symbols, for example Σ = {0,1}.
Arden's theorem
If X = A X ∪ B and ε is not in A, then X = A*B is the only solution for X.
Closure property
The guarantee that applying an operation to languages of a class always yields a language of the same class.
Complement of a language
The set of strings over the alphabet that are not in the language, written L̄ or Σ* − L.
Concatenation
RS is the set of strings xy where x comes from R and y comes from S.
Context-free language
A language accepted by a pushdown automaton, which can handle unbounded nesting that regular languages cannot.
Decision procedure
An always-terminating algorithm that answers a yes/no question about a language.
Distinguishable strings
Two strings are distinguishable by L if some suffix places exactly one of them in L.
Index
The number of equivalence classes of a relation; for ≡_L the index is the size of the minimal DFA.
Kleene star
R* is the set of all strings made by concatenating zero or more strings from R.
Kleene's theorem
The statement that finite automata and regular expressions accept exactly the same languages.
Language
A set of strings over a fixed alphabet, possibly infinite, possibly empty.
Minimal DFA
The smallest DFA for a regular language, unique up to renaming of states.
Myhill–Nerode relation
x ≡_L y holds when every suffix z keeps xz and yz on the same side of L.
Product construction
Building a machine whose states are pairs of states of two given machines, used for intersection and union.
Pumping lemma
A necessary condition that every regular language must satisfy, used to prove non-regularity.
Pumping length
The constant p in the pumping lemma, bounded by the number of states of an accepting DFA.
Regular expression
A finite formula built from ∅, ε and alphabet symbols using union, concatenation and Kleene star.
State elimination
A DFA-to-RE method that removes states one by one while relabelling the remaining edges with regular expressions.
String
A finite sequence of symbols drawn from an alphabet; ε is the string of length zero.
Thompson's construction
An inductive procedure that builds an ε-NFA fragment for every operator of a regular expression.
Union operator
R ∪ S denotes the set of strings that are in R or in S, written with a plus sign in some books.
ε-closure
The set of states reachable from a state using only ε-moves, including the state itself.
ε-NFA
A non-deterministic finite automaton whose transitions may be taken without reading any symbol.
