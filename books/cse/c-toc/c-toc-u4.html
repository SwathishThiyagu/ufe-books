4.1 Pushdown automata: definition and instantaneous descriptions

A pushdown automaton is finite-state control equipped with a last-in, first-out stack. The stack stores an arbitrarily long sequence, but each move inspects only its top. This extra memory recognizes dependencies such as one b for every earlier a.

You need: finite automata from Unit 1 and context-free languages from Unit 3. The stack is unbounded in the mathematical model.

The machine and its transition function

A nondeterministic pushdown automaton, or NPDA, is a tuple M = (Q, Σ, Γ, δ, q₀, Z₀, F). Here Q is a finite state set, Σ the input alphabet, Γ the stack alphabet, q₀ the initial state, Z₀ the initial stack symbol and F the set of final states. Input symbols and stack symbols serve different roles even if their printed names coincide. The transition function is δ: Q × (Σ ∪ {ε}) × Γ → finite subsets of Q × Γ*.

An outcome (r, γ) ∈ δ(q, a, X) means: in state q, consume input symbol a, remove top symbol X and replace it by stack string γ, entering r. If a = ε, consume no input. If γ = ε, the move pops X without replacement. A transition may both consume input and pop; an ε transition may push, pop or preserve height. The two ε positions therefore describe different things.

Throughout this book, the stack top is written on the left. Replacing X in stack Xβ by YZ gives YZβ, with Y now on top. Pushing Y above X is written as replacing X by YX. Replacing X by X changes no stack content. A rule cannot inspect an arbitrary lower symbol; that symbol becomes accessible only after everything above it is removed.

Because δ returns a finite set, several moves may be possible. Missing entries mean no permitted move, not an implicit rejection transition or a self-loop. A computation branch can halt because no rule applies. Other branches may continue. A word is accepted by an NPDA if at least one finite branch satisfies the chosen acceptance condition.

Instantaneous descriptions

An instantaneous description, or ID, is a triple (q, w, α): current state q, unread input suffix w and current stack α. If (r, γ) ∈ δ(q, a, X), then (q, aw, Xβ) ⊢ (r, w, γβ). For an ε transition, (q, w, Xβ) ⊢ (r, w, γβ). The relation ⊢ denotes one move, and ⊢* denotes zero or more moves.

The unread suffix is not the prefix already consumed. Each consuming move removes its first symbol; the input head never moves backward. An ID with unread ε may still take ε moves. In the standard model used here, an empty stack has no top symbol, so no further transition is possible unless the model has been explicitly extended. A bottom marker is an ordinary member of Γ whose special role is enforced by the transition design.

A transition diagram labels an edge with “input, top → replacement”. For example, “a, Z → AZ” consumes a and pushes A above Z. Multiple labels on an edge abbreviate different transitions. The diagram must specify how moves depend on the top symbol; merely drawing a push arrow between states is insufficient for a complete machine.

Design using phases and an invariant

For L = {aⁿbⁿ | n ≥ 1}, use states p for pushing, r for matching and f for acceptance. Set q₀ = p, Z₀ = Z, Γ = {Z, A} and F = {f}. Define δ(p, a, Z) = {(p, AZ)}, δ(p, a, A) = {(p, AA)}, δ(p, b, A) = {(r, ε)}, δ(r, b, A) = {(r, ε)} and δ(r, ε, Z) = {(f, Z)}. All unlisted transitions are absent.

After k initial a symbols, the stack is AᵏZ. After the first b, the machine enters r and removes one A for each b. No a transition exists in r, so an a cannot appear after matching begins. Reaching f requires returning to Z after consuming at least one a and one b. Chapter 4.2 makes the additional full-input requirement explicit: entering f while unread b symbols remain does not accept.

  1. Choose stack symbols representing obligations, such as one A for each future b.
  2. Separate phases that permit different input patterns.
  3. Write transitions for every relevant top symbol and leave invalid cases undefined.
  4. State an invariant linking the stack to the consumed prefix.
  5. Trace one valid word and one boundary failure before claiming the language.

Worked example

Trace aabb using the machine above and explain why aab is rejected.

(p, aabb, Z) ⊢ (p, abb, AZ) ⊢ (p, bb, AAZ) ⊢ (r, b, AZ) ⊢ (r, ε, Z) ⊢ (f, ε, Z). Two a symbols create two A markers; two b symbols remove them. The run uses four input-consuming moves and one ε move. Its maximum stack height is 3 symbols, including Z.

For aab, the corresponding run stops at (r, ε, AZ). An unmatched A remains, and there is no ε transition with top A. The machine cannot reach f. For aabb followed by another b, it can reach (f, b, Z), but this is not acceptance because the unread suffix is nonempty.

Exam traps

  • State the top convention before replacing a stack symbol by a string.
  • The ID records unread input, not input already read.
  • Do not confuse an ε input label with an ε stack replacement.
  • An accepting branch must consume the whole input under either standard acceptance mode.

4.2 Acceptance by final state and by empty stack

Final-state acceptance and empty-stack acceptance are two ways to recognize completion of a PDA computation. Both require that all input has been consumed. They define the same language class for nondeterministic PDAs, through constructions that change the machine.

Only a few universities teach this acceptance-equivalence topic separately. Use the top-on-the-left ID convention from Chapter 4.1.

Two conditions on a finished run

Final-state acceptance means (q₀, w, Z₀) ⊢* (f, ε, α) for some f ∈ F and any stack α. Empty-stack acceptance means (q₀, w, Z₀) ⊢* (q, ε, ε) for any state q. Write these languages as L_F(M) and L_E(M). Final states do not matter in the second definition; remaining stack content does not matter in the first.

Neither condition merely says the run is stuck. A machine can halt without accepting. It may also enter a final state with unread input, which does not accept that word. The two acceptance languages of one unchanged machine can differ: the Chapter 4.1 machine accepts aabb by final state but never removes Z, so its empty-stack language is empty.

Converting the machines

To convert an empty-stack NPDA into a final-state NPDA, add a fresh bottom marker ⊥, a fresh initial state and a fresh final state f. Start with stack ⊥ and use an ε move to replace it by Z₀⊥ while entering the old initial state. Simulate the old transitions. From every old state, when ⊥ is exposed, take an ε move to f, keeping ⊥. Give f no outgoing moves.

The new marker is not in the old stack alphabet, so the simulation cannot accidentally treat it as old data. Exposing it corresponds exactly to emptying the old stack. If this happens before all input is consumed, the branch reaches f too early and fails the full-input requirement. Thus the wrapper does not accept extra suffixes.

To convert a final-state NPDA into an empty-stack NPDA, again start with Z₀ above fresh ⊥. Keep the old simulation. From any old final state, allow an ε move to a fresh drain state, preserving the current top. In the drain state, pop every symbol, including ⊥, by ε moves. This branch accepts only if input is already exhausted, since draining consumes none.

  1. Protect the simulated stack with a genuinely fresh bottom symbol.
  2. Run the old transitions without changing their meanings.
  3. Translate the old completion condition into a fresh finishing phase.
  4. Prove both directions by separating simulation moves from wrapper moves.

The scope of the theorem

The theorem concerns equivalent languages of constructed NPDAs, not identical runs or identical conditions on one machine. The drain construction may introduce a choice between continuing the old machine and starting to drain. It therefore need not preserve determinism. Chapter 4.3 explains why the corresponding blanket equivalence fails for ordinary DPDAs without an explicit right-end marker.

Worked example

Convert the Chapter 4.1 final-state machine to empty-stack acceptance and trace its completion on aabb.

The simulated consuming moves end at (r, ε, Z⊥). Its old ε move gives (f, ε, Z⊥). Enter drain state d by replacing top Z with Z, then pop Z and ⊥: (f, ε, Z⊥) ⊢ (d, ε, Z⊥) ⊢ (d, ε, ⊥) ⊢ (d, ε, ε). The new machine accepts by empty stack. Maximum height during this run is 4, counting two A markers, Z and ⊥.

For aabbb, any drain begun after matching aabb still leaves one unread b. Reaching (d, b, ε) does not accept. For aab, the machine never reaches old final state f, so it cannot start draining.

Exam traps

  • Both definitions require unread input ε.
  • Equivalence of language classes does not mean L_F(M) = L_E(M) for every unchanged M.
  • Use a fresh bottom marker, distinct from all old stack symbols.

4.3 Deterministic versus nondeterministic pushdown automata

A deterministic PDA has at most one enabled next move from any configuration. An NPDA can explore alternatives and accepts if one finite branch succeeds. Unlike finite automata, nondeterministic pushdown automata recognize strictly more languages than their deterministic counterparts.

The exact determinism conditions

Use the transition notation from Chapter 4.1. A PDA is deterministic when two restrictions hold. First, each set δ(q, a, X), for a ∈ Σ ∪ {ε}, has at most one outcome. Second, if δ(q, ε, X) is nonempty, then δ(q, a, X) is empty for every input symbol a. The second condition excludes a choice between consuming input and taking an ε move with the same state and top symbol.

Distinct input labels do not conflict by themselves: the next input character selects the applicable transition. Similarly, ε moves at different top symbols are not automatically a conflict. A DPDA may contain ε transitions; it simply cannot have a competing input transition at that same state-top pair. Deterministic does not mean every configuration has a move. Missing moves can reject by halting.

These conditions make the next step unique, but they do not guarantee termination. A sequence of ε moves can loop forever. A recognizer's language depends on finite accepting runs, not on a promise that every run halts. An NPDA can likewise have infinite unsuccessful branches while another branch accepts; a simulator must avoid letting one infinite branch block exploration of all others.

Visible and guessed phase boundaries

Consider L# = {w#wᴿ | w ∈ {a, b}*}, where wᴿ reverses w and # is an explicit separator. A DPDA pushes each symbol of w, switches to matching when it reads #, then pops matching symbols. The separator tells it exactly when to change phases. Its stack records the first half in reverse order, which is the order needed to compare the second half.

Use states p for pushing, r for matching and f for final-state acceptance, with bottom marker Z. For each X ∈ {a, b, Z}, set δ(p, a, X) = {(p, aX)}, δ(p, b, X) = {(p, bX)} and δ(p, #, X) = {(r, X)}. Set δ(r, a, a) = {(r, ε)}, δ(r, b, b) = {(r, ε)} and δ(r, ε, Z) = {(f, Z)}. There are no other moves. In r with top Z, no input-consuming move competes with the finishing ε move.

For the unmarked language L = {wwᴿ | w ∈ {a, b}*}, an NPDA can push a guessed first half, then take an ε transition into matching. Both continuing to push and guessing the midpoint may be possible. A branch that guesses wrongly can fail; a correctly positioned branch accepts. The language of unmarked even palindromes over this two-symbol alphabet is a standard example of a CFL that is not deterministic context-free. The lack-of-marker intuition motivates the result, but a proof must exclude every possible DPDA, not just this obvious design.

Language power and acceptance conventions

A deterministic context-free language, or DCFL, is a language accepted by a final-state DPDA under the usual full-input convention. Every DCFL is a CFL because a DPDA is a restricted NPDA. The inclusion is proper, unlike DFA and NFA equivalence in Unit 1. A subset construction cannot simply collapse PDA branches: different branches may have different unbounded stacks, not merely different finite-control states.

Every regular language is a DCFL: simulate its DFA while leaving a fixed bottom marker untouched. DCFLs are closed under complement, with appropriate treatment of halting, ε behaviour and end-of-input in the construction. Merely swapping final and nonfinal states in a partial DPDA is not a valid general complement procedure. DCFLs are not closed under arbitrary union or intersection; the wider CFL closure results from Unit 3 must not be transferred indiscriminately.

Acceptance-mode equivalence also needs care. For a DPDA that cannot move once its stack is empty and has no extra right-end marker, an empty-stack accepted language is prefix-free: no accepted word is a proper prefix of another accepted word. Once the unique run empties its stack on a prefix, it cannot continue on a longer word. But a final-state DPDA can accept a*, including both ε and a, so these deterministic acceptance modes are not equivalent in general.

An explicit right-end marker changes the encoded input and can let the machine decide when to finish. State whether it is part of the model before using it. A separator such as # in L# is part of the language's middle structure, whereas a right-end marker follows the whole word. They solve different signalling problems.

Worked example

Trace ab#ba in the marked-palindrome DPDA and identify one transition conflict that would violate determinism.

(p, ab#ba, Z) ⊢ (p, b#ba, aZ) ⊢ (p, #ba, baZ) ⊢ (r, ba, baZ) ⊢ (r, a, aZ) ⊢ (r, ε, Z) ⊢ (f, ε, Z). Five input-consuming moves and one ε move accept the length-5 word. Its maximum stack height is 3, including Z. The word # is also accepted because it represents w = ε.

Now add δ(p, ε, a) = {(r, a)} to the machine. At (p, b#ba, aZ), both that ε move and the existing b-push move are enabled. Each transition set still has only one outcome, but their competition violates the second determinism condition. This demonstrates why singleton outcomes alone do not define a DPDA.

Exam traps

  • A DPDA can have ε moves; it cannot have competing ε and consuming moves at the same state-top pair.
  • Different stacks prevent a direct finite-state subset construction.
  • A failed deterministic design is not a proof that no DPDA exists.
  • Do not assume final-state and empty-stack DPDA acceptance are interchangeable without model qualifications.

4.4 Equivalence of PDAs and CFGs: conversions

A language is context-free exactly when some nondeterministic PDA accepts it. A grammar-to-PDA conversion treats the stack as unfinished derivation work. The reverse conversion uses grammar variables that summarize how a machine removes one stack symbol between two states.

You need: CFG derivations and simplification from Unit 3, and empty-stack NPDA acceptance from Chapter 4.2.

From a CFG to a stack machine

Let G = (V, Σ, P, S). Build a one-state NPDA with state q, input alphabet Σ, stack alphabet V ∪ Σ and initial stack S. Use empty-stack acceptance. For every production A → α, include (q, α) in δ(q, ε, A). For every terminal a, include (q, ε) in δ(q, a, a). All other transition entries are absent. No final states are needed for this acceptance mode.

A variable on top is replaced nondeterministically by one of its production right sides. A terminal on top must match the next input terminal and is then popped. With top on the left, the leftmost right-side symbol must become the new top. If an implementation pushes individual symbols one at a time, it must push the right side in reverse order. The mathematical replacement operation already inserts the string in the correct orientation.

The invariant links the consumed prefix x and current stack α to a leftmost derivation S ⇒* xα. Variable expansion extends this derivation; matching moves the leftmost terminal from the pending stack to the consumed prefix. A successful empty-stack run therefore yields the entire input word. Conversely, follow a leftmost derivation of any generated word and match terminals as they become exposed. This gives an accepting machine branch.

The machine may have many failing or infinite branches, particularly with recursive productions. The theorem asserts existence of a successful finite branch, not that naïve depth-first simulation always finds it. Left recursion in a grammar does not invalidate this construction, though it can make a careless search loop. A fresh bottom marker and the Chapter 4.2 wrapper can convert the result to final-state acceptance.

From a PDA to a CFG

First arrange that the NPDA accepts by empty stack. Use a transition form that replaces one top symbol by zero, one or two symbols; a finite machine can be normalized to this form using auxiliary machinery. Let its initial state be q₀ and initial symbol Z₀. For each pair of states p, q and stack symbol X, create a variable [pXq]. It generates strings that take the machine from state p with X above a protected stack suffix to state q with that X obligation completely removed, without using the suffix.

The variable records more than a top symbol. State p tells where processing begins, and q tells where it ends after all symbols descended from X are removed. The protected suffix can be arbitrary because transitions inspect only the exposed top. The summarized computation stops when that suffix is first exposed; later moves belong to the surrounding computation.

For a transition (r, ε) ∈ δ(p, c, X), add [pXr] → c. For (r, Y) ∈ δ(p, c, X), add [pXq] → c[rYq] for every q. For (r, YZ) ∈ δ(p, c, X), add [pXq] → c[rYs][sZq] for every intermediate state s and ending state q. Here c is either an input terminal or ε; when c = ε, write no terminal at that position.

The two-symbol rule respects stack order: first remove Y, entering some guessed state s, then remove Z. It cannot remove Z first while Y is still above it. Add a fresh grammar start T with T → [q₀Z₀q] for every state q, since empty-stack acceptance does not require a particular ending state. Finally remove useless variables and simplify if desired.

  1. Fix the machine's acceptance mode and normalize transition lengths.
  2. Create state-symbol-state variables with the stack-removal meaning.
  3. Add rules for pop, one-symbol replacement and two-symbol replacement transitions.
  4. Connect the grammar start to every possible empty-stack ending state.
  5. Remove variables that cannot derive terminal strings or cannot be reached.

Why the reverse construction works

For soundness, each grammar production joins actual machine fragments. A pop consumes c and completes one obligation. A two-symbol replacement consumes c and then composes a fragment removing Y with a fragment removing Z; their shared state s matches. Induction on the grammar tree produces a valid computation.

For completeness, examine a finite machine fragment that removes X. Its first transition either pops X immediately or replaces it by symbols that must later be removed in order. Split the remaining computation at the moment the first replacement symbol is fully removed. That moment supplies the intermediate state used by the grammar rule. Recursing on shorter fragments yields a derivation of the consumed input.

This is a language equivalence, not an assertion that every CFG maps to a DPDA. Deterministic parsing grammars require extra restrictions. The conversion also need not preserve ambiguity in a simple way: multiple machine paths and multiple grammar derivations are related but are not interchangeable definitions.

Worked example

Convert S → aSb | ε to a PDA and trace aabb. The transitions are δ(q, ε, S) = {(q, aSb), (q, ε)}, δ(q, a, a) = {(q, ε)} and δ(q, b, b) = {(q, ε)}.

(q, aabb, S) ⊢ (q, aabb, aSb) ⊢ (q, abb, Sb) ⊢ (q, abb, aSbb) ⊢ (q, bb, Sbb) ⊢ (q, bb, bb) ⊢ (q, b, b) ⊢ (q, ε, ε).

There are three grammar-expansion moves, corresponding to two uses of aSb and one of ε, plus four terminal-match moves. The stack empties exactly when the four-symbol input is exhausted. A branch choosing ε at the initial S instead would leave aabb unread and fail.

Worked example

Convert the two-state empty-stack version of the Chapter 4.1 machine back to a grammar. Keep states p and r, the four consuming transitions, and replace its final move by δ(r, ε, Z) = {(r, ε)}.

Among the productive triple variables, name D = [pZr], A = [pAr], B = [rAr] and C = [rZr]. The rules surviving useless-variable removal are D → aAC, A → aAB | b, B → b and C → ε, with start T → D. For example, pushing A above Z and later emptying it in state r gives D → aAC. The two-symbol replacement AA gives A → aAB; the direct b pop gives A → b.

Variables requiring a return from r to p cannot generate terminal strings because no such machine transition exists. Variables removing A while ending in p are also unproductive. Eliminate C and substitute B → b to obtain D → aA and A → aAb | b. Thus D derives ab, aabb, aaabbb and so on. Substituting the recurrence through D yields the familiar equivalent grammar S → aSb | ab. For n = 2, D ⇒ aA ⇒ aaAb ⇒ aabb, verifying the length-4 case.

Exam traps

  • The grammar-to-PDA stack uses both variables and terminals; its input alphabet uses terminals only.
  • With top on the left, the first symbol of a production must be processed first.
  • [pXq] summarizes removal of X and its descendants, not merely visiting top X.
  • A guessed intermediate state must join adjacent computation fragments consistently.

4.5 Top-down and bottom-up parsing overview

Parsing determines a grammatical structure for an input token sequence. Top-down parsing predicts productions from the start symbol; bottom-up parsing combines recognized pieces back into the start symbol. Both organize unfinished work on a stack.

Only a few universities teach this overview in the automata unit. Use Unit 3 for parse trees and ambiguity; this chapter connects those ideas to the PDA stack.

Top-down: predict then match

A top-down parser starts with the start variable and builds the tree from root to leaves. When a variable is on top, it selects a production and replaces the variable by that right side. When a terminal is on top, it matches the next input token. This is the CFG-to-PDA construction of Chapter 4.4, with a strategy for selecting productions.

A predictive parser uses lookahead to choose without backtracking. Not every CFG permits such choices. Left recursion such as E → E + T | T can make naïve recursive descent call itself before consuming input. Removing left recursion and left factoring can help, but do not guarantee that an arbitrary grammar becomes suitable for deterministic predictive parsing.

Bottom-up: shift and reduce

A bottom-up parser begins with an empty working stack. A shift transfers the next input token onto it. A reduction replaces a suffix matching a production right side by its left-side variable. Correct reductions identify handles: the occurrences whose reduction reverses the next step of a rightmost derivation. A suffix that happens to resemble some right side is not necessarily a valid handle.

LR parsers use state information and lookahead to decide actions. Shift–reduce and reduce–reduce conflicts describe competing table actions. A conflict may result from ambiguity or from limitations of the chosen parsing method; it is not by itself proof of inherent ambiguity. Acceptance requires the whole input and the appropriate completed start configuration.

A concrete reduction demonstration

For S → aSb | ab, the following Python code illustrates reductions on aabb. It is specific to this small nested-block grammar, not a general LR parser. Its string stack is written bottom-to-top from left to right, so suffixes are on top; this reverses the written orientation used for PDA IDs earlier.

stack = ""
for ch in "aabb":
    stack += ch
    print("shift", stack)
    while stack.endswith("ab") or stack.endswith("aSb"):
        rhs = "ab" if stack.endswith("ab") else "aSb"
        stack = stack[:-len(rhs)] + "S"
        print("reduce", stack)
print("accepted" if stack == "S" else "rejected")

A top-down parser chooses those productions in the forward direction; in this grammar the only variable at each step is S, so the derivation is both leftmost and rightmost. More complex grammars require the rightmost-derivation distinction for bottom-up parsing.

Exam traps

  • A reduction reverses a production; it does not apply the production forward.
  • Recognizing a right-side suffix is not a general handle-selection algorithm.
  • Do not confuse a parser working stack written top-at-right with the top-at-left PDA ID convention.

This is not for the exam. Parser generators can produce deterministic tables or retain multiple alternatives through generalized parsing. Error recovery is a separate practical concern from language recognition. Search next for LL, LR and GLR parsing.

  2. An ID must show the current state, unread suffix and entire stack.

  4. Fresh-bottom wrappers establish NPDA acceptance-mode equivalence.

Exam question bank

The PDA-focused syllabus lists emphasize instantaneous descriptions, final-state and empty-stack acceptance, determinism, and conversions in both directions. Some also ask a parsing overview. Prepare complete traces and invariants, and use Unit 3 for pumping, CFL closure and decision properties.

Remember and understand

Define an NPDA and explain its transition notation and instantaneous descriptions. (10 marks)

Give the seven components, distinguish input and stack alphabets, explain set-valued δ and both ε positions, and write the one-step ID rule with a protected stack suffix.

Compare final-state and empty-stack acceptance, including their scope of equivalence. (12 marks)

State both full-input definitions. Explain why the same machine need not give the same language under both modes. Give fresh-bottom wrapper ideas and identify why the theorem is stated for NPDAs.

State the complete DPDA conditions and compare its power with an NPDA. (10 marks)

State singleton outcome and ε/input exclusion separately. Give a conflicting pair. Explain DCFL proper inclusion in CFL, contrast with DFA/NFA equivalence, and avoid claiming ε moves are forbidden.

Explain top-down and bottom-up parsing in relation to derivations. (10 marks)

Predict and match build a leftmost derivation from the root. Shift and reduce reconstruct a rightmost derivation in reverse. Define a handle, lookahead and the need for a selection strategy beyond suffix matching.

Apply

Construct a PDA for {aⁿbⁿ | n ≥ 1} and trace aabb and aab. (12 marks)

Use the Chapter 4.1 push and match phases. State alphabets, all five transitions and final-state acceptance. Trace the unmatched A on aab. Explain why aabb followed by b is not accepted despite reaching f.

Convert the equal-block final-state machine to empty-stack acceptance. (12 marks)

Add fresh ⊥ and an initial wrapper, simulate the old stack, then allow a drain from old final states. Trace the four-symbol word to an actually empty stack and show an unread suffix cannot be consumed by draining.

Construct a deterministic PDA for {w#wᴿ | w ∈ {a, b}*}. (12 marks)

Push a or b before #, preserve the stack at #, then pop matching symbols. Finish only at bottom after full input. Trace ab#ba, check # for the empty w case, and verify the determinism conditions at every state-top pair.

Convert S → aSb | ε to an NPDA and trace aabb. (12 marks)

Use a one-state empty-stack machine with S initially on the stack. List production-expansion and terminal-match rules. Show all seven moves, preserving the top-left convention and full-input requirement.

Apply the state–symbol–state construction to the two-state equal-block PDA. (16 marks)

Name D = [pZr], A = [pAr], B = [rAr], C = [rZr]. Obtain D → aAC, A → aAB | b, B → b, C → ε. Explain why other variables are unproductive and simplify to an equal-block grammar.

Give a shift–reduce trace of aabb for S → aSb | ab. (10 marks)

List four shifts and two reductions with stack and unread suffix. Reduce the inner ab to S, then aSb to S. Reverse the reductions to obtain the grammar derivation and distinguish stack orientation from the PDA notation.

Analyze and evaluate

Explain why an NPDA acceptance-mode conversion need not preserve determinism. (16 marks)

Span Chapters 4.2–4.3. A drain ε move can compete with an old consuming move at a final state. Use the prefix-free restriction for ordinary empty-stack DPDAs and contrast final-state acceptance of a*. State the no-right-end-marker assumption.

Prove the grammar-to-PDA conversion using an invariant. (12 marks)

Span Chapters 4.1 and 4.4. Relate consumed x and pending stack α to S ⇒* xα. Show preservation by expansion and matching. Prove both generated-word acceptance and accepted-word generation, distinguishing existence from search termination.

Explain how PDA-to-CFG rules enforce last-in, first-out order. (16 marks)

Span Chapters 4.1 and 4.4. Interpret [pXq] above a protected suffix. For replacement YZ, remove Y first, guess its exit state s, then remove Z starting at that same s. Give the pop, one-symbol and two-symbol rule schemes.

Evaluate the claims “a parser conflict proves inherent ambiguity” and “every CFG gives a DPDA”. (12 marks)

Span Chapters 4.3–4.5 and Unit 3. A conflict may reflect grammar ambiguity or limitations of a parsing method. The general grammar conversion gives an NPDA; DCFLs form a proper subclass. A proof about one implementation does not settle all grammars or machines.

Glossary

Pushdown automaton
A finite-state machine with an unbounded last-in, first-out stack.
Input alphabet
The finite set of symbols the machine can consume.
Stack alphabet
The finite set of symbols that can occur in stack memory.
Bottom marker
A distinguished stack symbol used to detect the base of simulated content.
Instantaneous description
Current state, unread input suffix and stack content.
ε move
A transition that consumes no input symbol.
Push
A replacement that adds stack content above the previous suffix.
Pop
Removal of the top symbol without replacement.
Computation branch
One sequence of choices and resulting machine moves.
Final-state acceptance
Full input consumption ending in a designated final state.
Empty-stack acceptance
Full input consumption ending with no stack symbols.
Drain state
An auxiliary state that pops stack symbols through ε moves.
NPDA
A pushdown automaton allowing multiple enabled alternatives.
DPDA
A pushdown automaton with unique enabled moves under the stated ε restrictions.
DCFL
A language recognized by a final-state deterministic PDA.
Prefix-free language
A language with no member that is a proper prefix of another member.
End marker
An explicitly modelled symbol signalling the end of the whole input.
Invariant
A property maintained throughout relevant computation steps.
Triple variable
A grammar variable summarizing a stack-removal task between two control states.
Predict
Choose and expand a grammar production during top-down parsing.
Lookahead
Upcoming input information used to choose a parser action.
Shift
Transfer the next input token to a parser stack.
Reduce
Replace a selected right-side handle by a left-side variable.
Handle
A production occurrence whose reduction reverses the next rightmost-derivation step.
Left recursion
A derivation in which a variable can reproduce itself at the left edge before consuming input.
