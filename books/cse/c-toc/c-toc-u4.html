4.1 Pushdown automata: definition and instantaneous descriptions

A pushdown automaton (PDA) is a finite automaton with a stack. The stack has no size limit, so the machine can remember a count or nesting depth and match it later. That extra store describes every context-free language. PDAs appear in compiler front ends, JSON and XML validators, and bracket checkers. This chapter gives the formal definition and the notation for one run, one move at a time.

You need DFA and NFA definitions, transition tables and the extended transition function from Unit 1 (Deterministic finite automata and Nondeterministic finite automata).

The seven-tuple

A PDA is a finite automaton plus one stack. The finite control is still states and a move table, as in a DFA (Unit 1, Deterministic finite automata). The stack gives memory that grows and shrinks with input.

P = (Q, Σ, Γ, δ, q₀, Z₀, F)

Q is a finite set of states; Σ is the input alphabet; Γ is the stack alphabet; δ is the transition function; q₀ ∈ Q is the start state; Z₀ ∈ Γ is the initial stack symbol; F ⊆ Q is the set of final states.

The stack appears in δ. Here 2^(Q × Γ*) means the set of all subsets of Q × Γ*.

δ : Q × (Σ ∪ {ε}) × Γ → 2^(Q × Γ*)

one call δ(q, a, X) takes a state q, one input symbol a (or ε for no input), and top stack symbol X, and returns a set of pairs. Each pair (p, β) means: go to state p and replace X by β ∈ Γ*.

Read (q, a, X) → (p, γ) as: in q, reading a with X on top, go to p and replace X by γ. The leftmost symbol of γ becomes the new top. Three cases cover everything:

  • γ = ε: pop X; the stack shrinks by one.
  • γ = X: the stack is unchanged.
  • γ = YX: push Y above X; X remains below.

When a = ε the move reads nothing and the input pointer stays put. Books call the stack alphabet Γ, Z or Π; the stack is also the pushdown store or pushdown list. These are the same object.

Instantaneous descriptions and the move relation

At any moment three things capture the machine: current state, unread input, and whole stack. This triple is the instantaneous description (ID), written (q, w, γ).

Here q ∈ Q is state; w ∈ Σ* is unread input (read symbols are gone); γ ∈ Γ* is full stack with top at left. For stack AAZ₀, top is A and bottom is Z₀. The start ID for input w is (q₀, w, Z₀).

(q, aw, Xγ) ⊢ (p, w, βγ) when (p, β) ∈ δ(q, a, X)

q and p are states; a is one input symbol or ε; w is the unread input after that symbol; X is the top stack symbol; γ is the rest of the stack below X; β is the string pushed in place of X. The relation ⊢ is one move.

⊢* is the reflexive-transitive closure of ⊢: x ⊢* y means y is reached from x in zero or more moves. Writing IDs with ⊢ between them gives the trace.

In a diagram, an arrow q → p labelled a, X / γ means read a, pop X, push γ. Two arrows for the same (q, a, X) make the machine nondeterministic: δ returns more than one pair (contrast in 4.3). Acceptance conventions are in 4.2.

A table you can trace

Examples use P = ({q₀, q₁, q₂}, {a, b}, {Z₀, A}, δ, q₀, Z₀, {q₂}). Only five entries of δ are non-empty; every other triple returns ∅, so no move is possible.

State qInput aTop XGoes toPushes γ (top first)
q₀aZ₀q₀AZ₀
q₀aAq₀AA
q₀bAq₁ε
q₁bAq₁ε
q₁εZ₀q₂Z₀

First two rows push one A per a. Next two pop one A per b; the first pop also enters q₁. Last row moves on ε without reading input. Z₀ is a bottom marker, so the machine never pops an empty stack: b moves stop when Z₀ is exposed. The machine counts a's, then matches b's, and accepts {aⁿbⁿ : n ≥ 1}.

Worked example

Question. For P above, (a) trace IDs for aabb, one move per line. (b) Give move count and final stack height. (c) Give L(P).

  1. Start: (q₀, aabb, Z₀).
  2. Read a, top Z₀: δ(q₀, a, Z₀) = {(q₀, AZ₀)} gives (q₀, abb, AZ₀).
  3. Read a, top A: δ(q₀, a, A) = {(q₀, AA)} gives (q₀, bb, AAZ₀); two A's sit over Z₀.
  4. Read b, top A: δ(q₀, b, A) = {(q₁, ε)} gives (q₁, b, AZ₀).
  5. Read b, top A: δ(q₁, b, A) = {(q₁, ε)} gives (q₁, ε, Z₀).
  6. No input, top Z₀: δ(q₁, ε, Z₀) = {(q₂, Z₀)} gives (q₂, ε, Z₀).
  7. Run length 4 input symbols; moves = 2 pushes + 2 pops + 1 ε-move = 5; final stack height 1 (Z₀). q₂ ∈ F, so aabb is accepted. Same pattern accepts exactly {aⁿbⁿ : n ≥ 1}.

Answer. Trace: (q₀, aabb, Z₀) ⊢ (q₀, abb, AZ₀) ⊢ (q₀, bb, AAZ₀) ⊢ (q₁, b, AZ₀) ⊢ (q₁, ε, Z₀) ⊢ (q₂, ε, Z₀). The run takes 5 moves, 1 symbol remains on the stack, and L(P) = {aⁿbⁿ : n ≥ 1}.

Exam traps

  • Top is left. Pushing A on Z₀ gives AZ₀, never Z₀A. The leftmost symbol of γ is top in every ID and push.
  • δ returns a set. An entry can have zero, one or several pairs; several at the same (q, a, X) means nondeterminism.
  • Do not reverse γ. If γ = YX, Y is top and X stays below; reversing γ accepts wrong strings.
  • ε-move consumes no input. In (q₁, ε, Z₀) ⊢ (q₂, ε, Z₀), remaining input is ε on both sides.
  • Z₀ need not be popped. The bottom marker normally stays; acceptance conventions are in 4.2.

Analyze If you delete every stack operation from a PDA, keeping only states and input, what kind of machine is left, and what does that tell you? 6 marks

What is left is an NFA over Σ, because each move now only chooses a next state on a symbol or on ε. So a PDA is an NFA whose moves also depend on the top symbol and which also writes a string. The stack is the only extra power, and it lifts the machine from regular languages to context-free languages (see 4.4).

Beyond the syllabus

Not for the exam. Parser generators build δ for real parsers and keep the unexpanded derivation on the stack. Java bytecode runs on a stack machine, and verifiers check stack discipline like a PDA checks brackets. Research uses pushdown systems for recursive-program bug finding and visibly pushdown automata for fast verification.

4.2 Acceptance by final state and by empty stack

A pushdown automaton finishes a run when its input is used up. At that moment two different conditions can declare success: the machine sits in a final state, or its stack is empty. Both are called acceptance, and each defines a language. This chapter gives both definitions and shows that each kind of machine can be rebuilt to work like the other, so the two families of languages are exactly the same. Only a few universities teach this as its own topic, but the construction is used whenever a PDA has to be turned into a grammar.

You need: 4.1 for the seven-tuple, the move relation ⊢ and instantaneous descriptions.

Two definitions of acceptance

The seven-tuple P = (Q, Σ, Γ, δ, q₀, Z₀, F) comes from 4.1. A run starts at (q₀, w, Z₀): start state, whole input, stack holding only the bottom marker. The run ends when the input is empty. Two different end conditions count as success.

Final state acceptance. The machine must be in a state of F when the input runs out; the stack may still hold anything.

L(P) = { w ∈ Σ* | (q₀, w, Z₀) ⊢* (q, ε, γ), q ∈ F }

Σ* is all strings over the input alphabet; ⊢* means zero or more moves; ε is the empty string; γ is whatever stack contents remain.

Empty stack acceptance, also called acceptance by null stack or by empty store. Here the state is irrelevant; the stack must be bare.

L(P) = { w ∈ Σ* | (q₀, w, Z₀) ⊢* (q, ε, ε), q ∈ Q }

Q is the full state set, so any state will do; ε as the third entry means the stack is empty.

The two rules look like different machines. They are not. Each can be simulated by the other, so both accept exactly the same languages.

Converting one into the other

Final state to empty stack. Given P with final set F, build P′. Keep Q, Σ, Γ, δ, q₀ and Z₀ as they are.

  1. Choose a symbol X₀ not in Γ. It is the new bottom marker.
  2. Add a start state q₀′ with δ(q₀′, ε, X₀) = {(q₀, Z₀X₀)}.
  3. Keep every old move unchanged.
  4. Add an erasing state qe. For each q ∈ F and each Y ∈ Γ ∪ {X₀}, put (qe, ε) in δ(q, ε, Y).
  5. Set δ(qe, ε, Y) = {(qe, ε)} for every such Y.

Once the old machine sits in a final state with the input finished, step 4 hands control to qe. The eraser pops one symbol per move until nothing is left. The new machine copies each move of the old one, so it accepts the same strings, now by empty stack. Its final set can be empty.

Empty stack to final state. Given P that accepts by empty stack, build P″. Keep Q, Σ, Γ, δ, q₀ and Z₀.

  1. Choose X₀ not in Γ and add a start state q₀′ with δ(q₀′, ε, X₀) = {(q₀, Z₀X₀)}.
  2. Keep every old move.
  3. Add one final state qf, and for every state q ∈ Q add (qf, ε) to δ(q, ε, X₀).

X₀ reaches the top only after the old machine has emptied its own stack, so the jump to qf fires exactly then. Again the new machine copies each move of the old one. This equality of power is what lets 4.4 choose whichever rule is convenient.

Worked example

Question. The PDA of 4.1 has Q = {q₀, q₁, q₂}, Γ = {Z₀, A}, start state q₀, bottom marker Z₀, F = {q₂}, and it accepts aabb ending in the ID (q₂, ε, Z₀). Apply the final-state-to-empty-stack construction and trace aabb on the new machine.

  1. New bottom marker X₀, not in Γ. New stack alphabet: {X₀, Z₀, A}. New states: q₀′, q₀, q₁, q₂, qe.
  2. δ(q₀′, ε, X₀) = {(q₀, Z₀X₀)}, so Z₀ sits above X₀ and the old machine sees its usual bottom.
  3. For each Y in {X₀, Z₀, A}: δ(q₂, ε, Y) = {(qe, ε)}. Only q₂ is final, so only q₂ gets these moves.
  4. For each Y in {X₀, Z₀, A}: δ(qe, ε, Y) = {(qe, ε)}. The eraser pops one symbol per move.
  5. All old moves are kept. The new final set is empty.
  6. Trace: (q₀′, aabb, X₀) ⊢ (q₀, aabb, Z₀X₀) ⊢* (q₂, ε, Z₀X₀) ⊢ (qe, ε, X₀) ⊢ (qe, ε, ε).

Answer. The run ends at (qe, ε, ε), so aabb is accepted by empty stack even though the new machine has no final states.

Exam traps

  • Taking X₀ from Γ. If the marker was already in the stack alphabet, the old machine could push or pop it and its own runs would change.
  • Adding erase moves out of non-final states. The eraser may start only after the old machine has finished, or the machine accepts prefixes it should reject.
  • In the other direction, forgetting the guard: jumping to qf whenever some symbol sits on top. Only X₀ says the old stack is empty.
  • Mixing the rules. 'Accept when in a final state and the stack is empty' is a third, stricter condition that neither standard definition uses.

Beyond the syllabus

Not for the exam. Real parsers do not run a literal PDA; they compile the moves into a table and use an array as the stack, so a parser stack overflow is a genuine bug class. Pushdown systems also appear in software model checking, where a program's call stack is abstracted as a pushdown store and reachability stays decidable. Search for 'pushdown system reachability' or 'P-automata' to go further.

4.3 Deterministic versus nondeterministic pushdown automata

Two pushdown automata can have the same states, the same stack and the same accepted language, yet differ in one thing: choice. A nondeterministic PDA may branch at a step and accept if any branch survives. A deterministic PDA has at most one move at every step, so each input has at most one run. That single restriction shrinks the family of accepted languages. It also buys two things programmers want: fast parsing in time proportional to input length, and closure under complement.

You need the machine and its instantaneous descriptions from 4.1 and the two acceptance conventions from 4.2.

Determinism means no choice

In 4.1 the transition function δ takes a state, an input symbol and the stack top, and returns a set of moves. That set may hold zero, one or many moves. When it holds several, or when the machine can also move on ε, one input string gets several runs, and the machine accepts if any run accepts. That is the ordinary pushdown automaton. It is now called an NPDA, a nondeterministic pushdown automaton.

A DPDA, a deterministic pushdown automaton, is an NPDA with two extra rules.

|δ(q, a, X)| ≤ 1 for every a in Σ ∪ {ε}   and   δ(q, ε, X) ≠ ∅  →  δ(q, a, X) = ∅ for every a in Σ

q is a state; a is an input symbol or ε; Σ is the input alphabet; X is the stack top; ε is the empty input (a silent move); δ(q, a, X) is the set of moves for that triple; |·| is the size of the set.

Rule 1 caps every set at one move. Rule 2 closes the other door: if the machine can move on ε with stack top X in state q, it may not read any input symbol with that same q and X. Rule 2 is the part students forget. Without it the machine could either read the next symbol or pop silently from the same configuration, and those are two runs. Two runs is choice.

A DFA is already a DPDA: it never changes the stack and never moves on ε. A DPDA is much stronger than a DFA, because the stack still holds an unbounded amount of information.

Three facts and the DCFL family

Three results tie the two machines together.

  • Fact 1: NPDAs accept exactly the context-free languages. 4.4 proves both directions.
  • Fact 2: every DPDA is an NPDA, so every language a DPDA accepts is a context-free language.
  • Fact 3: some context-free languages are accepted by no DPDA. The standard witness is L = {aⁿbⁿ : n ≥ 1} ∪ {aⁿb²ⁿ : n ≥ 1}.

Name the smaller family the deterministic context-free languages, DCFL. The chain regular ⊂ DCFL ⊂ CFL is strict at both steps: {aⁿbⁿ : n ≥ 1} is a DCFL but not regular, and the union L above is a CFL but not a DCFL.

What determinism buys

Complement. DCFLs are closed under complement. The swap of final and non-final states is only correct on a machine that never stops before the end of the input, so normalise first. Add a non-final state that consumes the rest of the input while popping the stack; any run that would have got stuck now finishes there and rejects. Now every run reads the whole input, so swapping final and non-final states accepts exactly the strings the original rejects. The same swap fails for an NPDA: one string can have an accepting run and a rejecting run at once, so flipping final states says nothing. Context-free languages are indeed not closed under complement (see Unit 3, Closure properties of context-free languages).

Linear-time parsing. A DPDA reads the input left to right and does a fixed amount of work per move. On a string of length n the run has O(n) moves, so recognition takes time proportional to n. Compilers live on this. A top-down or bottom-up parser (4.5) is a DPDA when the grammar permits it. When the grammar forces backtracking, the parser needs the full NPDA and can slow down badly.

Worked example

Question. Build a DPDA with final state q₂ for L₁ = {aⁿbⁿ : n ≥ 1}, check it against both determinism rules, and explain why no DPDA accepts L₁ ∪ L₂ where L₂ = {aⁿb²ⁿ : n ≥ 1}.

  1. Take stack alphabet Γ = {A, Z₀}, with Z₀ the bottom marker. States are q₀ (reading a's), q₁ (reading b's) and q₂ (final). Start state q₀.
  2. Transitions: δ(q₀,a,Z₀) = (q₀,AZ₀); δ(q₀,a,A) = (q₀,AA); δ(q₀,b,A) = (q₁,ε); δ(q₁,b,A) = (q₁,ε); δ(q₁,ε,Z₀) = (q₂,Z₀). Every other triple has no move.
  3. Rule 1: each of the five entries is a single move, and all other sets are empty. All sets have size 0 or 1.
  4. Rule 2: the only ε-entry is at (q₁, Z₀). No input row exists for (q₁, Z₀), so there is no clash. At (q₁, A) the input row δ(q₁,b,A) exists, and δ(q₁,ε,A) is empty. Both rules hold, so the machine is deterministic.
  5. Run on a²b²: (q₀,aabb,Z₀) → (q₀,abb,AZ₀) → (q₀,bb,AAZ₀) → (q₁,b,AZ₀) → (q₁,ε,Z₀) → (q₂,ε,Z₀), accepted.
  6. Move count on aⁿbⁿ: n push moves, n pop moves, one ε-move, so 2n+1 moves. For n = 3 that is 3 + 3 + 1 = 7 moves.
  7. Now add L₂ = {aⁿb²ⁿ : n ≥ 1}. On the prefix aⁿb the two languages agree. To finish aⁿbⁿ the machine pops one A per b; to finish aⁿb²ⁿ it pops one A per two b's. Both choices need the same input prefix aⁿb, so at the first b the machine must already know which case it is in.
  8. Knowing without reading is a guess. A DPDA has at most one move per triple and no ε-move beside an input move, so it cannot guess. Therefore no DPDA accepts L₁ ∪ L₂. The union is still a CFL, being the union of two CFLs, so it is a CFL that is not a DCFL.

Answer. The DPDA above accepts {aⁿbⁿ : n ≥ 1}, makes 2n+1 moves (7 moves for n = 3) and satisfies both determinism rules; the union with {aⁿb²ⁿ : n ≥ 1} forces a guess at the first b, so no DPDA accepts it.

Exam traps

  • A short transition table is not a proof of determinism. Check both clauses: at most one entry per (q, a, X), and no ε-move beside an input move for the same (q, X).
  • An ε-row is not harmless. Once δ(q, ε, X) is non-empty, every input row for that same (q, X) must be emptied, or the machine is nondeterministic.
  • Do not assume every CFL has a DPDA. {aⁿbⁿ} ∪ {aⁿb²ⁿ} is context-free and provably has no DPDA; examiners like this counterexample.
  • For DPDAs, acceptance by empty stack is weaker than acceptance by final state. The two conventions matched in 4.2 for NPDAs; they do not match here, so state which one you use.

Check yourself

Remember State the two conditions that make a pushdown automaton deterministic. 2 marks

At most one move per (state, input symbol, stack top): |δ(q,a,X)| ≤ 1. And if δ(q,ε,X) is non-empty, then δ(q,a,X) must be empty for every input symbol a.

Understand Why does an ε-move sitting beside an input move for the same (q, X) destroy determinism, even when each row holds only one move? 3 marks

From the same configuration the machine can either read the next symbol or pop silently. Those lead to different configurations on the same input, so the run branches. Two runs means choice, which a DPDA forbids.

Apply Is every DFA a DPDA? Is every DPDA a DFA? Answer with one reason each. 3 marks

Every DFA is a DPDA: keep the stack unchanged, never take an ε-move, and each (q, a, X) has at most one move. Not every DPDA is a DFA: {aⁿbⁿ : n ≥ 1} needs the stack and is not regular.

Apply L₁ = {aⁿbⁿ : n ≥ 1} is a DCFL. Show in three lines why L₁ ∪ {aⁿb²ⁿ : n ≥ 1} is not. 4 marks

Both parts share the prefix aⁿb. Finishing the first part needs one pop per b; finishing the second needs one pop per two b's. The first b is the decision point and the input seen so far is identical in both cases, so a deterministic machine would have to guess. So no DPDA accepts the union.

Analyze DCFLs are closed under complement but CFLs are not. Explain the difference using runs. 4 marks

A DPDA has at most one run per input, so swapping final and non-final states (after rewriting the machine so that every run reads the whole input) flips exactly one verdict. An NPDA can have an accepting run and a non-accepting run for the same string, so swapping final states does not produce the complement.

Analyze Why does a DPDA recognise a string of length n in time proportional to n, while an NPDA may not? 4 marks

The DPDA has one run, and each move reads at most one symbol and does constant stack work, so the run has O(n) moves. The NPDA may explore many branches, so the number of moves can grow much faster than n.

Beyond the syllabus

Not for the exam. Deterministic pushdown automata are the theory behind the parsers in real compilers: the LR(1) family generates exactly the deterministic context-free languages, while the LL and LALR(1) parsers used in practice cover proper subclasses of them. A conflict means the grammar is not in that tool's class, so a different (still deterministic) grammar or a stronger parser is needed; it does not by itself prove the language is not a DCFL. Practical data formats such as JSON are designed so a single-pass deterministic parser reads them without backtracking. 4.4 Equivalence of PDAs and CFGs: conversions

A context-free grammar and a pushdown automaton are two spellings of one idea. The grammar writes rules; the PDA runs them with a stack. This chapter gives both conversion recipes. CFG to PDA uses one working state and keeps the unexpanded part of a leftmost derivation on the stack. PDA to CFG builds variables [p A q] that mean 'go from p to q and remove A'. The pair proves that PDAs accept exactly the context-free languages, the fact every parser relies on.

You need: 4.1 for the machine and instantaneous descriptions, and Unit 3 for productions, derivations, leftmost derivations and grammar simplification.

From grammar to PDA: one working state and a stack

The stack holds the unexpanded part of a leftmost derivation. Its top is the leftmost symbol still to process. A nonterminal is expanded; a terminal is matched with input.

  1. Use one working state q, bottom marker Z₀, and stack alphabet Γ = Σ ∪ V ∪ {Z₀}. Σ is the terminal alphabet; V is the set of variables.
  2. Start by pushing the start symbol S above Z₀: δ(q,ε,Z₀) = {(q, S Z₀)} in top-left transition notation. The figure writes stacks bottom to top, so this is Z₀ S.
  3. For each production A → α, add δ(q,ε,A) = {(q, α)}. In top-left transition notation the leftmost symbol of α is the new top. For S → aSb, push a S b to get stack Z₀ b S a when written bottom to top, with a on top.
  4. For each terminal a, add δ(q,a,a) = {(q,ε)}. It pops a and consumes one input symbol.
  5. Add δ(q,ε,Z₀) = {(q,ε)} to empty the stack after S has been matched. If the grammar does not derive ε, use a separate start state for the first move so this pop cannot happen early.

Each ε-move applies one production to the leftmost nonterminal. Each terminal move matches the next input symbol. The PDA accepts exactly L(G) by empty stack.

From PDA to grammar: variables that pop one stack symbol

First put the PDA in simple form: it accepts by empty stack, and every move either pushes one symbol or pops one symbol. Use 4.2 if it currently accepts by final state.

For states p,q and stack symbol A, make a variable [p A q]. It derives the input strings that take the PDA from state p with A on top to state q with A removed. Removing A also removes everything pushed above it; the stack below A is untouched.

  1. Pop: if δ(p,a,A) contains (p′, ε), add [p A p′] → a.
  2. Push: if δ(p,a,A) contains (p′, B₁B₂…Bₖ), k ≥ 1, and B₁ is the new top, add [p A q] → a [p′ B₁ r₁] [r₁ B₂ r₂] … [r_{k-1} Bₖ q] for every state q and all intermediate states r₁,…,r_{k-1}. The first variable pops B₁, the next pops B₂, and so on.
  3. Add a new start symbol S with S → [q₀ Z₀ q] for every state q ∈ Q. q₀ is the start state and Z₀ is the bottom marker. This says: start at q₀ with Z₀, consume the input, and finish in any state with Z₀ gone.

The triple construction creates |Q|²|Γ| variables [p A q], plus the new start symbol S, so |Q|²|Γ| + 1 grammar variables, many useless. Apply the simplification steps from Unit 3 in this order: eliminate ε-productions, then unit productions, then useless variables. The language stays the same.

Why this proves PDAs and CFGs are equally powerful

The first recipe turns any CFG into a PDA, so every context-free language is PDA-accepted. The second turns any PDA into a CFG, so every PDA language is context-free. Together they prove CFL = PDA languages.

The stack in the first direction is a leftmost derivation in progress. In the second direction, each variable [p A q] summarises a whole stack-popping computation. The grammar may be huge, but it is valid.

Parsers use the first direction. A top-down parser predicts productions and keeps expected symbols on a stack. See 4.5 for the parser view.

Worked example

Question. Use the CFG-to-PDA recipe on G: S → aSb | ε. Build the one-working-state PDA P that accepts L(G) by empty stack. Trace P on input ab. Write the stack after every move, bottom to top, and say whether ab is accepted.

  1. States: {q}; start state q; input alphabet {a,b}; stack alphabet {a,b,S,Z₀}; bottom marker Z₀.
  2. Start move: δ(q,ε,Z₀) = {(q, S Z₀)}. In bottom-to-top display this gives stack Z₀ S.
  3. Production moves: S → aSb gives δ(q,ε,S) ∋ (q, a S b), since α = a S b. S → ε gives δ(q,ε,S) ∋ (q, ε).
  4. Terminal moves: δ(q,a,a) = {(q,ε)} and δ(q,b,b) = {(q,ε)}.
  5. Final pop: δ(q,ε,Z₀) = {(q,ε)}. It is safe here because S → ε, so ε is in L(G).
  6. Trace, writing each configuration as (state, input left, stack bottom to top): (q, ab, Z₀) ⊢ (q, ab, Z₀ S) start move ⊢ (q, ab, Z₀ b S a) expand S → aSb ⊢ (q, b, Z₀ b S) match a ⊢ (q, b, Z₀ b) expand S → ε ⊢ (q, ε, Z₀) match b ⊢ (q, ε, ε) pop Z₀.
  7. The input is empty and the stack is empty after six moves, so ab is accepted.

Answer. P accepts ab by empty stack; the stack sequence is Z₀S, Z₀bSa, Z₀bS, Z₀b, Z₀, ε.

Exam traps

  • Pushing αᴿ under top-left transition notation. For A → α write δ(q,ε,A) ∋ (q, α). Pushing αᴿ puts the rightmost symbol of α on top, so the PDA processes the right end first and strings come out reversed.
  • Forgetting the final pop of Z₀. Without it the stack never empties, so empty-stack acceptance fails. If the grammar does not derive ε, use a separate start state so the pop is not available at time zero.
  • In PDA-to-CFG, missing intermediate states r_i. The push production must be written for every choice of q and every r₁,…,r_{k-1}; otherwise strings are lost.
  • Expecting the PDA-to-CFG grammar to be small or clean. It has |Q|²|Γ| + 1 grammar variables and needs the Unit 3 simplification steps.
  • Mixing the two directions: CFG-to-PDA pushes the production right-hand side α; PDA-to-CFG writes one variable per pushed symbol, not one variable for the whole string.

4.5 Top-down and bottom-up parsing overview

A parser turns a token string into a parse tree. Top-down parsers start at the start symbol and predict productions. Bottom-up parsers start at the input and reduce handles back to nonterminals. Every compiler front end has one. Only a few universities cover this as an overview.

You need 4.4 for the grammar-to-PDA construction, and Unit 3 for derivations and parse trees.

Top-down: predict, then match

Keep a stack holding the unexpanded part of the tree, starting with the start symbol S. Repeat until the stack and the input are both empty.

  1. Top of stack is a nonterminal A: choose a production A → α and replace A by the symbols of α, right end deepest.
  2. Top of stack is a terminal a: it must equal the next input symbol. Pop both; a mismatch is an error.
  3. Accept when the stack and the input are both empty.

This is the PDA of 4.4. The production is chosen by one lookahead symbol through a table (predictive parsing), or by the fixed order in which code tries alternatives (recursive descent, one function per nonterminal).

The choice is deterministic only if the grammar allows it. No left recursion: A → A α makes the parser expand A forever. For each nonterminal A, the FIRST sets of its alternatives must be disjoint. FIRST(A) is the set of terminals that can begin a string derived from A. If an alternative can derive ε (a nullable production), FOLLOW(A) must also be disjoint from the FIRST sets of the other alternatives. FOLLOW(A) is the set of terminals that can appear immediately after A. A grammar meeting these conditions is LL(1): scan Left to right, build a Leftmost derivation, with 1 symbol of lookahead.

Bottom-up: shift and reduce

Keep a stack of grammar symbols, initially empty, and read the input left to right.

  1. Shift: push the next input symbol.
  2. Reduce: if the top symbols of the stack spell the body α of a production A → α, pop them and push A.
  3. Accept when the input is finished and the stack holds only S.

The body you reduce is a handle. The reduction list read backwards is a rightmost derivation; the first reduction is the last production of that rightmost derivation.

Table-driven versions are LR: LR(0), SLR(1), LALR(1), canonical LR(1), differing in how much context the table uses. A cell with two entries is a conflict — shift/reduce or reduce/reduce. It means this method cannot handle this grammar; it does not prove the grammar ambiguous.

Choosing between them

  • Recursive descent: short hand-written code, good errors, needs an LL grammar.
  • Table-driven LR: larger class, left recursion included, generator builds the table, bigger tables and cruder errors.
  • Both are deterministic PDAs; only some context-free languages have a deterministic grammar — see 4.3.

Worked example

Question. Grammar E → E + T | T, T → T * F | F, F → id. For input id + id * id, give the top-down leftmost derivation with the production used at each step, then the shift-reduce sequence of the bottom-up parser. This grammar is left-recursive, so a real top-down parser would first remove left recursion; the leftmost derivation is shown for comparison with the bottom-up rightmost derivation.

  1. E ⇒ E + T (E → E + T)
  2. ⇒ T + T (E → T)
  3. ⇒ F + T (T → F)
  4. ⇒ id + T (F → id)
  5. ⇒ id + T * F (T → T * F)
  6. ⇒ id + F * F (T → F)
  7. ⇒ id + id * F (F → id)
  8. ⇒ id + id * id (F → id). Eight productions, input consumed.
  9. Bottom-up moves: shift id; reduce F→id, T→F, E→T; shift +; shift id; reduce F→id, T→F; shift *; shift id; reduce F→id; reduce T→T*F; reduce E→E+T; accept.

Answer. Both parses build the same tree. The 8 reductions read backwards form the rightmost derivation E ⇒ E+T ⇒ E+T*F ⇒ E+T*id ⇒ E+F*id ⇒ E+id*id ⇒ T+id*id ⇒ F+id*id ⇒ id+id*id.

Exam traps

  • Feeding a left-recursive grammar to a top-down parser: E → E + T calls itself forever. Remove recursion first; bottom-up accepts it.
  • The top-down stack holds terminals too, not only nonterminals.
  • Reading reductions forwards as a leftmost derivation. They are a rightmost derivation backwards.
  • A conflict only says this table method cannot handle the grammar, not that it is ambiguous.

Beyond the syllabus

Not for the exam. Parser generators such as yacc, bison and ANTLR build these tables from a grammar file. Generalised methods — GLR, Earley, packrat (PEG) — keep several stacks or memoise results. Takeaways

  1. A PDA is a finite automaton plus one stack, so it can match nested pairs but cannot count three independent levels.
  2. An instantaneous description (q, w, γ) records the state, unread input, and full stack; a run is a chain of IDs linked by ⊢.
  3. Acceptance by final state and acceptance by empty stack are interchangeable, so either may be used in definitions.
  4. A DPDA has no choice in any configuration; an NPDA may choose among several moves or take ε-moves.
  5. NPDAs accept exactly the context-free languages, while DPDAs accept the smaller family of deterministic context-free languages.
  6. The CFG-to-PDA construction stores the unexpanded suffix of a leftmost derivation on the stack.
  7. The PDA-to-CFG construction uses variables [p, A, q] that mean the machine can go from p to q while popping A.
  8. Top-down parsing predicts a leftmost derivation from the start symbol; bottom-up parsing shifts input and reduces handles from the leaves upward.
  9. Parsing tables turn PDA ideas into practical linear-time parsers for restricted grammar classes.

Glossary

Acceptance by empty stack
Acceptance when the PDA reaches empty stack after reading all input.
Bottom marker
A special stack symbol placed at the bottom to detect an empty stack.
Bottom-up parsing
Parsing that builds the tree from the input leaves up to the start symbol.
Configuration
Another name for an instantaneous description of a machine.
Context-free grammar
A grammar whose productions have one variable on the left.
Deterministic context-free language
A language accepted by some deterministic PDA.
Deterministic PDA
A PDA with at most one legal move in every configuration.
Epsilon move
A PDA move that consumes no input symbol.
Final state
A state in F; reaching it with empty input is one way to accept.
Handle
A substring matching a production right side that a bottom-up parser may reduce.
Input alphabet Σ
The finite set of symbols that may appear on the input tape.
Instantaneous description
A triple (q, w, γ) giving state, unread input, and stack contents.
Leftmost derivation
A derivation that always expands the leftmost variable first.
LL parser
A top-down table-driven parser that reads input left to right and predicts leftmost derivations.
LR parser
A bottom-up table-driven parser that reads input left to right and builds a rightmost derivation in reverse.
Move relation
The one-step relation ⊢ between instantaneous descriptions.
Nondeterministic PDA
A PDA that may have several legal moves, including ε-moves.
Pushdown automaton (PDA)
A finite automaton with one unbounded last-in-first-out stack.
Shift-reduce parsing
A bottom-up parsing method that shifts input and reduces handles on a stack.
Stack
A last-in-first-out store whose top symbol controls the next PDA move.
Stack alphabet Γ
The finite set of symbols that may be pushed on the stack.
Top-down parsing
Parsing that builds the tree from the start symbol down to the input.
Transition function δ
The rule that maps state, input symbol or ε, and stack top to possible next moves.
Viable prefix
A prefix of a right sentential form that can appear on a shift-reduce parser stack.
