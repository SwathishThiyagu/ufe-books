1.1 Alphabets, strings and formal languages

An alphabet is the set of symbols that can appear in an input. A string is a finite sequence of those symbols. A formal language is any set of strings over a given alphabet. These concepts let us describe what a computer can read, how we model inputs, and they are the basis for automata, compilers, and pattern matching in everyday tasks like validating a UPI ID or a railway ticket number.

Alphabet and symbols

An alphabet Σ is a non‑empty finite set of symbols. Different syllabi call it a symbol set or a vocabulary. Each element a∈Σ is called a symbol. For binary data we often use Σ={0,1}. The choice of Σ determines what strings can be formed.

Σ = {0,1}

Σ is the alphabet; 0 and 1 are its symbols

The empty set ∅ is not an alphabet because an alphabet must contain at least one symbol. The empty string ε belongs to Σ* (the set of all strings over Σ). Whether ε is in a particular language L ⊆ Σ* depends on the definition of L; a language may include ε or not.

Strings and basic operations

A string w over Σ is an ordered finite sequence of symbols from Σ. The length of w, written |w|, is the number of symbols. The empty string ε has length 0. Concatenation of strings x and y is written xy and its length satisfies |xy| = |x| + |y|.

|xy| = |x| + |y|

x and y are strings; |·| denotes length

The Kleene star of Σ, written Σ* , is the set of all strings (including ε) that can be built by concatenating zero or more symbols from Σ. Formally, Σ* = { w1w2…wk | k ≥ 0 and each wi ∈ Σ }.

Common operations on languages L1 and L2 (both subsets of Σ*) are:

  • Union: L1 ∪ L2 = { w | w∈L1 or w∈L2 }
  • Intersection: L1 ∩ L2 = { w | w∈L1 and w∈L2 }
  • Concatenation: L1·L2 = { xy | x∈L1, y∈L2 }
  • Kleene star of a language: L* = ⋃_{k=0}^{∞} L^{k}

Formal languages and examples

A formal language L over Σ is any set of strings drawn from Σ*. Languages can be described by enumeration, by a rule, or by a regular expression. For example, using Σ={0,1}, the language L = { ε, 0, 1, 00, 01 } contains five strings, each of length at most two.

When we need all strings of length ≤2 over Σ={0,1}, we list them systematically: start with length 0 (ε), then length 1 (0,1), then length 2 (00,01,10,11). The total count is 1 + 2 + 4 = 7.

∑_{i=0}^{2} |Σ|^{i} = 1 + 2 + 4 = 7

|Σ| is the size of the alphabet (here 2); i is the length

Worked example

Question. Let Σ = {0,1}. List all strings of length ≤2 and give the total number of such strings.

def generate_strings(max_len):
    alphabet = ['0','1']
    result = ['']
    for l in range(1, max_len+1):
        from itertools import product
        for p in product(alphabet, repeat=l):
            result.append(''.join(p))
    return result

strings = generate_strings(2)
print(strings)
print('Count =', len(strings))

  2. Step 2: Length 1 gives 0 and 1.
  3. Step 3: Length 2 gives 00, 01, 10, 11.
  4. Step 4: Count strings: 1 (ε) + 2 (length 1) + 4 (length 2) = 7.

Exam traps

  • Counting the number of strings of length ≤2 and counting the number of strings of length exactly 2 are different; the former includes ε and length‑1 strings.
  • Confusing the alphabet Σ with a language L; Σ is a set of symbols, while L is a set of strings over Σ.
  • Treating the empty string ε as having length 1; its length is 0.
  • Assuming Σ* contains only non‑empty strings; Σ* always contains ε.
  • Using the symbol ∅ for the empty language and confusing it with the empty string ε.

1.2 Deterministic finite automata (DFA)

A deterministic finite automaton (DFA) is a mathematical model that reads a string symbol by symbol and decides whether the string belongs to a particular language. It exists to give a precise, algorithmic description of regular languages, which appear in lexical analysis, network protocol validation, and simple control logic. DFAs are used in hardware design, text search, and anywhere a fixed‑size controller must recognise patterns quickly.

You need: Alphabets, strings and formal languages.

Formal definition of a DFA

A DFA is a 5‑tuple (Q, Σ, δ, q₀, F). Q is a finite set of states. Σ is a finite alphabet of input symbols. δ is the transition function that maps a state and an input symbol to a next state, written δ: Q × Σ → Q. q₀ ∈ Q is the start state. F ⊆ Q is the set of accept (final) states.

(Q, Σ, δ, q₀, F)

Q = set of states; Σ = input alphabet; δ = transition function; q₀ = start state; F = accept states

A string w = a₁a₂…aₙ (each aᵢ ∈ Σ) is accepted if the sequence of states q₀, q₁, …, qₙ defined by for i = 0 … n‑1, q_{i+1} = δ(q_i, a_{i+1}) ends in a state belonging to F. The language of the DFA is the set of all accepted strings.

Components of a DFA

  • States (Q): distinct configurations the machine can be in.
  • Alphabet (Σ): the symbols the machine reads, e.g., {0,1} for binary strings.
  • Start state (q₀): the state before any input is read.
  • Accept states (F): the states that signal successful recognition.
  • Transition function (δ): a table that tells, for each (state, symbol) pair, which state to move to next.
  1. Read the next input symbol.
  2. Look up the pair (current state, symbol) in δ.
  3. Move to the returned next state.
  4. Repeat until the input ends.
  5. If the final state is in F, accept; otherwise reject.

Design example: strings ending in 01

We design a DFA over the binary alphabet Σ = {0,1} that accepts exactly those strings whose last two symbols are 01. The idea is to remember the most recent symbols while scanning.

  1. Create a start state q₀ meaning “no relevant suffix seen”.
  2. Create state q₁ meaning “the last symbol read was 0”.
  3. Create state q₂ meaning “the last two symbols read were 01”. This will be the only accept state.
  4. Define δ as follows:
  5. • From q₀, on 0 go to q₁; on 1 stay in q₀.
  6. • From q₁, on 0 stay in q₁; on 1 go to q₂.
  7. • From q₂, on 0 go to q₁; on 1 go to q₀.

1.3 Transition diagrams, tables and extended transition function

Transition diagrams, tables and the extended transition function let us see a finite automaton as a picture, as a spreadsheet and as a single function that reads whole words. The picture helps you trace a run by eye. The table lets a computer or a pen‑and‑paper test any input quickly. The extended function, often called δ̂, folds many single‑step moves into one step that works on strings. All three are used when you design a DFA, when you prove language properties, and when you implement a lexer for a programming language or a ticket‑booking bot.

You need: the definition of a DFA in Deterministic finite automata.

Transition diagrams

A transition diagram is a directed graph. Nodes are states. Arrows are labelled by input symbols. An arrow from q to p labelled a means the transition function δ(q,a)=p. The start state has an incoming arrow from nowhere. Accept states are drawn with a double circle.

  1. Write down all states of the DFA.
  2. For each state and each alphabet symbol, draw an arrow to the target state.
  3. Mark the start state with an incoming arrow.
  4. Mark accept states with double circles.
  • The diagram shows exactly the same information as the formal definition.
  • It is useful for visualising a run on a short input.

Transition tables

A transition table is a matrix. Rows list the states. Columns list the alphabet symbols. The entry at row q and column a is the state δ(q,a). The start state is noted separately. Accept states are listed in a separate set.

δ̂(q,w) = δ( … δ(δ(q,w₁),w₂) … , wₙ )

δ̂ is the extended transition function; q is a state; w = w₁w₂…wₙ is a string; each wᵢ is a symbol from the alphabet; δ is the single‑step transition function.

  • The table is easy to fill by hand for small DFAs.
  • A computer program can read the table and simulate the automaton in O(|w|) time.

Extended transition function

The extended transition function δ̂ processes a whole string in one call. It is defined recursively.

  1. Base case: δ̂(q, ε) = q, where ε is the empty string.
  2. Recursive case: δ̂(q, xa) = δ( δ̂(q, x), a ), where x is a (possibly empty) prefix and a is the last symbol.

Some syllabi call δ̂ the extended transition function. Using δ̂ you can decide acceptance by checking whether δ̂(q₀,w) belongs to the set of accept states.

  • Do not reverse the order of symbols. The recursion works from left to right.
  • The function works for any deterministic automaton, not only for DFAs that accept binary strings.

1.4 Nondeterministic finite automata (NFA)

A nondeterministic finite automaton (NFA) can move to many possible next states on the same input symbol. It exists to give a compact description of regular languages. It is used when a regular expression is easier to translate into parallel choices, such as pattern matching in text editors or validating a UPI ID.

You need: Deterministic finite automata (DFA).

Formal definition of an NFA

An NFA is a 5‑tuple (Q, Σ, δ, q₀, F) where Q is a finite set of states, Σ is a finite input alphabet, δ : Q × Σ → 2^Q is the transition function, q₀ ∈ Q is the start state, and F ⊆ Q is the set of accept states.

For a state p and symbol a, δ(p, a) returns the set of states reachable from p on input a. The set may be empty, contain one state, or contain many states.

δ̂(q, w) = ⋃_{p∈δ̂(q, w₁…w_{k‑1})} δ(p, w_k)

δ̂ is the extended transition function; w = w₁…w_k is a string; δ̂(q, ε) = {q}.

A string w is accepted if at least one state in δ̂(q₀, w) belongs to F. Only one accepting computation path is required.

Why nondeterminism helps

Nondeterminism lets the automaton guess a position in the input where a pattern starts. The guess is represented by branching to several states.

If any branch reaches an accept state, the whole NFA accepts. The examiner often expects you to argue that the existence of a successful branch is enough.

  • Branching reduces the number of states compared with an equivalent DFA.
  • Designing an NFA from a regular expression follows a systematic construction.
  • Later we will remove the branching by subset construction.

Acceptance example

Construct an NFA that accepts any binary string containing the substring 101. Use states p (start), q (seen 1), r (seen 10), and s (accept).

  1. From p on 1 go to q. On 0 stay in p.
  2. From q on 0 go to r. On 1 stay in q.
  3. From r on 1 go to s. On 0 return to p.
  4. State s has a self‑loop on both 0 and 1.

For input 110101 the NFA follows a single path p → q → q → r → s → s and reaches the accept state s, so the string is accepted.

Python program.

def simulate_nfa(s):
    # states: p,q,r,s
    cur = {'p'}
    for ch in s:
        nxt = set()
        for st in cur:
            if st == 'p':
                if ch == '1': nxt.add('q')
                else: nxt.add('p')
            elif st == 'q':
                if ch == '0': nxt.add('r')
                else: nxt.add('q')
            elif st == 'r':
                if ch == '1': nxt.add('s')
                else: nxt.add('p')
            elif st == 's':
                nxt.add('s')
        cur = nxt
    return 'Accepted' if 's' in cur else 'Rejected'
print(simulate_nfa('110101'))

1.5 NFA with epsilon transitions

ε‑moves let a finite automaton change state without reading an input symbol. They simplify the design of machines that need to guess or split computation paths, such as when combining smaller automata. ε‑transitions are used in regular‑expression to NFA conversion and in lexical analysis tools that must recognise patterns with optional parts.

You need: DFA, NFA, and the extended transition function from section 1.3.

ε‑transition and ε‑closure

An ε‑transition (written ε) is a move from one state to another that consumes no input symbol. Formally, δ(q, ε) ⊆ Q, where Q is the set of states. Because the move does not read a symbol, the automaton can take any number of ε‑moves before or after reading a real symbol.

ε‑closure(q) = { p ∈ Q | q →ε* p }

ε‑closure(q) is the set of states reachable from q by zero or more ε‑moves; q →ε* p means a path of only ε‑edges from q to p.

  • ε‑closure always contains the original state.
  • If a state has no outgoing ε‑edges, its ε‑closure is the singleton {state}.
  • ε‑closure is used to start the computation and after each real input symbol.
  1. Put the given state q in a stack.
  2. Pop a state r from the stack and add r to the closure set being built.
  3. For each state t in δ(r, ε) not yet visited, push t on the stack.
  4. Repeat until the stack is empty.

Python program.

def epsilon_closure(state, delta):
    stack = [state]
    closure = set()
    while stack:
        r = stack.pop()
        if r not in closure:
            closure.add(r)
            for t in delta.get((r, 'ε'), []):
                stack.append(t)
    return closure

Extended transition function with ε‑moves

The extended transition function δ̂(q, w) gives the set of states reachable from q after reading the whole string w, allowing ε‑moves before, between, and after symbols.

  1. Compute C0 = ε‑closure(q).
  2. For each symbol a in w:
  3. • From every state p in the current set Ci, take δ(p, a).
  4. • Let Ci+1 be the ε‑closure of the union of all those target states.
  5. After the last symbol, the final set is C|w|.

A string is accepted if C|w| contains at least one accepting state. This definition works for both NFA and ε‑NFA because ordinary NFA are just ε‑NFA with no ε‑edges.

Python program.

def delta_hat(start, word, delta, accept):
    cur = epsilon_closure(start, delta)
    for a in word:
        nxt = set()
        for p in cur:
            nxt.update(delta.get((p, a), []))
        cur = set()
        for q in nxt:
            cur.update(epsilon_closure(q, delta))
    return cur & accept

Why ε‑moves matter and next steps

ε‑moves let us glue two automata together without adding extra input symbols. For example, when converting a regular expression (a|b)*c to an ε‑NFA, we create separate sub‑machines for a, b and c and connect them with ε‑edges. The resulting ε‑NFA is often smaller than an equivalent DFA, but later we can eliminate ε‑moves using the subset construction described in section 1.6.

  • Design complex patterns quickly.
  • Simplify proofs of regular‑language closure properties.
  • Prepare for lexical analyser generators like Flex that internally use ε‑NFA.

When you finish a design, remember to compute ε‑closures at every step. Missing a closure is a common source of wrong answers in exams.

1.6 Equivalence of NFA and DFA: subset construction

The subset construction transforms any NFA, even one with ε‑moves, into a DFA that accepts the same language. It exists because DFAs are easier to implement and to reason about. It is used in lexical analyzers, pattern matchers and any tool that needs a deterministic scanner.

You need: DFA, NFA and ε‑NFA.

Subset construction algorithm

The algorithm builds DFA states that are subsets of NFA states. The start DFA state is the ε‑closure of the NFA start state. For each input symbol the algorithm computes the set of NFA states reachable by that symbol and then takes the ε‑closure of that set. A new DFA state is created for each distinct subset that appears.

  1. Compute ε‑closure(start) → start DFA state.
  2. For each DFA state S and each alphabet symbol a, compute move(S,a) = { q | ∃ p∈S, p --a--> q }.
  3. Take ε‑closure(move(S,a)) → new DFA state T.
  4. Add transition S --a--> T. Repeat until no new subsets appear.

ε‑closure(X) = X ∪ { r | ∃ p∈X, p --ε⁺--> r }

X is a set of NFA states; ε‑closure adds all states reachable by any number (zero or more) of ε‑moves.

  • A DFA state may be the empty set ∅. It represents dead computation.
  • The DFA is complete: every state has a transition for every symbol.

Handling ε‑moves

When the NFA contains ε‑moves, the move step must be followed by an ε‑closure. This ensures that the DFA does not miss any NFA state that can be reached without consuming input.

moveε(S,a) = ε‑closure( move(S,a) )

move(S,a) = { q | ∃ p∈S, p --a--> q }

If the NFA has no ε‑moves, ε‑closure(S) = S and the algorithm reduces to the standard subset construction.

Resulting DFA properties

The DFA obtained by subset construction accepts exactly the strings accepted by the original NFA. It may have up to 2^n states, where n is the number of NFA states. In practice many subsets are unreachable, so the DFA is often much smaller.

1.7 Minimization of DFA: table-filling algorithm

The table‑filling algorithm removes redundant states from a deterministic finite automaton (DFA). It works by identifying pairs of states that behave differently for some input. Those pairs are called distinguishable. All other pairs are indistinguishable and can be merged. The result is the smallest DFA that accepts the same language. This minimal machine saves memory in hardware design, reduces software state‑space, and appears in compiler tokenisers and network protocol parsers.

You need: deterministic finite automata (), transition tables ().

Overview of the table‑filling algorithm

Create a table that lists every unordered pair of distinct DFA states. If the DFA has n states, the table contains n·(n‑1)/2 entries.

Each entry will be marked if the two states are known to be distinguishable. Unmarked entries are candidates for merging.

  1. List all unordered pairs of states.
  2. Mark every pair that contains one accepting state and one non‑accepting state.
  3. Iteratively mark a pair (p,q) if there exists an input symbol a such that the pair of successors (δ(p,a),δ(q,a)) is already marked.
  4. Stop when a full pass makes no new markings.

The algorithm finishes in O(n²·|Σ|) time, where |Σ| is the size of the input alphabet. This bound is acceptable for the small automata used in exam problems.

Initial marking and propagation

The first pass marks pairs that differ in acceptance. This step catches the most obvious distinction: an accepting state can never be equivalent to a rejecting state.

After the initial step, look at each unmarked pair (p,q). For each alphabet symbol a, compute the successor pair (δ(p,a),δ(q,a)).

If any successor pair is already marked, then (p,q) must be marked as well because the two states lead to already distinguishable behaviour on the same input.

Repeat the scan until no new markings appear. The remaining unmarked pairs are indistinguishable.

Forming equivalence classes and building the minimized DFA

Collect all unmarked pairs into equivalence classes. Each class represents a set of states that can be merged.

Create a new DFA whose states are these equivalence classes. The start state is the class containing the original start state.

A class is accepting if any member of the class was accepting in the original DFA.

Define the transition function for the new DFA by following the original transition from any representative state and then moving to the class that contains the target state.

The resulting DFA is minimal: no two distinct states are equivalent, and any DFA that accepts the same language must have at least as many states.

1.8 Moore and Mealy machines

Moore and Mealy machines are finite‑state devices that, besides recognizing a language, also generate an output string. They are used when a system must react to each input symbol, such as a digital controller that lights an LED or a protocol that acknowledges packets. The two models differ only in where the output is attached – to states (Moore) or to transitions (Mealy) – and each can be transformed into the other without changing the recognised language.

You need: deterministic finite automata (DFA) and transition diagrams (extended transition function).

Definition of Moore and Mealy machines

A Moore machine is a 6‑tuple M = (Q, Σ, Δ, δ, λ, q0). Q is a finite set of states, Σ the input alphabet, Δ the output alphabet, δ : Q × Σ → Q the transition function, λ : Q → Δ the output function, and q0 the start state. The output depends only on the current state, so the machine emits a symbol after each state entry.

A Mealy machine is a 6‑tuple N = (Q, Σ, Δ, δ, ω, q0). The components are the same except that the output function ω : Q × Σ → Δ attaches an output symbol to each transition. The output is produced simultaneously with the move to the next state.

  • Moore output: λ(q) is read after the transition.
  • Mealy output: ω(q, a) is read while reading a.
  • Both accept exactly the regular languages.

λ(q) ∈ Δ and ω(q, a) ∈ Δ

λ(q) is the Moore output for state q; ω(q, a) is the Mealy output for transition from q on input a.

Conversion between Moore and Mealy machines

Any Mealy machine can be turned into an equivalent Moore machine by moving the output of each transition to the target state. The new Moore output λ'(q') equals the Mealy output ω(q, a) that caused the move to q'.

  1. Create a copy of every state of the Mealy machine.
  2. For each transition (q, a) → r with output o, set λ'(r) = o.
  3. Keep the same transition function δ.
  4. If two incoming transitions give different outputs, split the target state into copies, one for each distinct output.

Conversely, a Moore machine can be converted to a Mealy machine by attaching the output of the destination state to each incoming edge. The resulting Mealy machine produces the same output sequence, only shifted by one symbol.

1.9 Two-way finite automata

Two‑way finite automata let the read head move left (L) or right (R) on the input tape. The model tests whether head motion adds power to regular language recognisers. It is useful when a designer wants to scan an input repeatedly without extra memory. Only a few syllabi include this model.

You need: deterministic finite automata (DFA) and the definition of alphabet and strings (Alphabets, strings and formal languages).

Definition and transition function

A two‑way deterministic finite automaton (2DFA) is a 7‑tuple M = (Q, Σ, δ, q₀, F, ⊢, ⊣). Q is a finite set of states. Σ is the input alphabet. ⊢ and ⊣ are left and right end‑markers that are not in Σ. q₀ ∈ Q is the start state. F ⊆ Q is the set of accepting states.

The transition function is

δ : Q × (Σ ∪ {⊢,⊣}) → Q × {L,R}

δ(q, a) = (p, d) means: in state q reading symbol a, move to state p and move the head one cell in direction d (L = left, R = right).

Computation starts with the head on ⊢, in state q₀. After each move the head may read a new symbol, including the end‑markers. The input is accepted if the automaton enters a state in F and then halts (makes no further moves).

Power compared to DFA

A 2DFA can simulate any ordinary DFA by never moving left. Therefore every regular language is recognised.

Conversely, any language recognised by a 2DFA is regular. The proof uses crossing‑sequences: for each boundary between two tape cells only finitely many state sequences can appear when the head crosses that boundary. This yields a finite‑state description equivalent to a DFA.

  1. Fix a 2DFA M with n states.
  2. For each tape position record the ordered list of states seen when the head moves from left to right across that position.
  3. There are at most nⁿ different lists, a finite number.
  4. Construct a DFA whose states are these lists. The DFA accepts exactly the strings accepted by M.

Hence two‑way motion does not increase the class of recognised languages. The model is studied for theoretical interest and to illustrate the limits of finite memory.

Two‑way automaton for the palindrome 10101

Consider Σ = {0,1}. We build a 2DFA M that accepts the single string w = 10101, a palindrome of odd length.

  • Q = {q₀,q₁,q₂,q₃,q_accept,q_reject}.
  • F = {q_accept}.
  • δ is defined so that the head first reads the leftmost symbol, remembers it in the state, moves right to the rightmost symbol, compares, and returns.
  1. Start in q₀ on ⊢. Move right, read the first 1 and go to q₁ (remember ‘1’).
  2. From q₁ move right until ⊣ is seen, passing through q₂ for each interior symbol.
  3. When the symbol just before ⊣ (the last 1) is read, compare with the remembered 1. They match, so go to q₃ and move left.
  4. In q₃ move left back to ⊢, ignoring interior symbols.
  5. When ⊢ is reached, the outer pair is verified. Since the length is 5, the middle symbol 0 is automatically matched. Enter q_accept and halt.

The head visits the tape cells in the order: ⊢ → 1 → 0 → 1 → 0 → 1 → ⊣ → 1 → 0 → 1 → ⊢. Ten moves are performed before acceptance.

Exam traps

  • Assuming that moving left automatically allows counting; the head has no extra memory.
  • Confusing the end‑markers ⊢ and ⊣ with ordinary input symbols; they are never part of Σ.
  • Treating the crossing‑sequence argument as a construction algorithm; it only proves existence.

If the automaton starts in q₀, the first crossing (rightward) may put it in q₁, then the return crossing (leftward) puts it back in q₀. A possible crossing‑sequence is [q₀, q₁, q₀].

End‑markers only signal tape boundaries. A one‑way DFA can treat the first and last input symbols specially, so they do not add power.

Beyond the syllabus

Not for the exam. Two‑way automata appear in model checking when a system must scan a trace back and forth. They are used to study space‑bounded computation and to separate deterministic from nondeterministic log‑space. In hardware, bidirectional shift registers mimic two‑way head motion.

Takeaways

  1. Every regular language can be described by a DFA, an NFA, or a regular expression.
  2. A DFA has exactly one transition for each symbol from each state, while an NFA may have many or none.
  3. ε‑moves do not consume input and can be eliminated by computing ε‑closures.
  4. Subset construction guarantees an equivalent DFA for any NFA, preserving language acceptance.
  5. Minimizing a DFA yields the unique smallest automaton for a regular language.
  6. Moore and Mealy machines extend finite automata to produce outputs, useful in digital design.
  7. Two‑way finite automata have the same expressive power as one‑way DFA/NFA for regular languages.

Glossary

Accepting state
A state designated as final; reaching it means the input is accepted.
Alphabet
A finite set of symbols used to build strings.
Computation tree
A tree that shows all possible execution paths of an NFA on a given input.
Deterministic
No choice in the next move; exactly one transition is defined.
Deterministic finite automaton
A machine with a unique transition for each state‑symbol pair.
Extended transition function
Recursive extension of the transition function to whole strings.
Formal language
A set of strings over a given alphabet.
Kleene star
Operator that forms all finite concatenations (including empty) of a language.
Language of an automaton
The set of all strings that the automaton accepts.
Mealy machine
Finite automaton whose output depends on the current state and input symbol.
Minimal DFA
The DFA with the smallest number of states that accepts a given regular language.
Moore machine
Finite automaton whose output depends only on the current state.
Myhill–Nerode theorem
Characterizes regular languages via a finite index equivalence relation.
Nondeterministic
Multiple possible next moves may exist; acceptance if any path leads to a final state.
Nondeterministic finite automaton
A machine that may have multiple or zero transitions for a state‑symbol pair.
Pumping lemma
A property that all regular languages satisfy, used to prove non‑regularity.
Regular expression
A symbolic notation describing a regular language using union, concatenation, and Kleene star.
State
An element of the finite set representing the automaton's configuration.
String
A finite sequence of symbols from an alphabet.
Subset construction
Algorithm that builds a DFA whose states are subsets of NFA states.
Symbol
An individual element of an alphabet.
Table‑filling algorithm
Procedure to identify and merge indistinguishable DFA states.
Transition diagram
Graphical representation of an automaton with nodes as states and labeled edges as transitions.
Transition function
Function that defines the next state(s) given a current state and input symbol.
Transition table
Tabular form listing the next state(s) for each state‑symbol pair.
Two‑way finite automaton
Automaton whose read head can move left or right on the input tape.
ε‑closure
Set of states reachable using only ε‑moves.
ε‑move
A transition that does not consume any input symbol.
