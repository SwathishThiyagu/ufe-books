6.1 Recursive and recursively enumerable languages

A language is a set of strings, and a Turing machine may accept its strings but run forever on other strings. This chapter sorts languages by that halting behaviour alone. A recursive language has a machine that always halts and answers yes or no correctly. A recursively enumerable language has a machine that halts and says yes on every string inside the language, but may loop on strings outside it. The sorting matters because software that must always answer, such as a compiler or a type checker, needs the stronger class, and the weaker class marks the edge of what any program can promise.

You need: Turing machine acceptance, instantaneous descriptions and the universal machine from Unit 5; this chapter uses only halting behaviour, so machine design is not repeated here.

Halting behaviour defines the two classes

A language L over an alphabet Σ is a set of strings. A Turing machine M accepts L when M halts in an accepting state on exactly the strings of L. That wording says nothing about strings outside L: M may halt in a rejecting state, or it may run forever.

Definition 1. L is recursive if some Turing machine M halts on every input and answers correctly: accepting for w ∈ L, rejecting for w ∉ L. Such an M is a decider. Other names used in syllabi: decidable, Turing-decidable.

Definition 2. L is recursively enumerable (r.e.) if some Turing machine M halts in an accepting state for every w ∈ L, and never accepts any w ∉ L. On w ∉ L, M may reject or loop; nothing is promised. Other names: recognizable, semi-decidable, Turing-acceptable.

Every recursive language is r.e., because a decider is also an acceptor. The inclusion is strict. The halting language is r.e. but not recursive, as 6.3 shows, and some languages are not even r.e., such as the complement of the universal language. So:

recursive ⊂ r.e. ⊂ all languages

recursive = languages with a machine that always halts with the right answer; r.e. = languages with a machine that halts and accepts exactly on the language; all languages = every set of strings over Σ.

A decider gives a yes or no you can act on. An acceptor gives only a yes you can wait for, with no bound on the wait. That is the practical difference between the two classes.

What operations keep a language in the class

Closure asks: if L₁ and L₂ are in the class, is their union in it too? Take the deciders of L₁ and L₂ and combine their answers.

  • Recursive is closed under union and intersection: run both deciders, always halt, accept if either accepts (union) or both accept (intersection).
  • Recursive is closed under complement: swap the accepting and rejecting states of the decider.
  • Recursive is closed under concatenation and Kleene star: for a word w, only finitely many splits exist, and each split is tested by a halting decider.
  • r.e. is closed under union and intersection: run the two acceptors in parallel, one step each (dovetailing), and accept when one accepts (union) or both accept (intersection).
  • r.e. is not closed under complement: the universal language L_u is r.e., its complement is not r.e. at all.

The complement theorem and enumerators

Theorem. L is recursive if and only if both L and its complement are r.e.

(⇒) A decider for L halts with the opposite answer when its states are swapped, so the complement is recursive, hence r.e. Also L is recursive, hence r.e.

(⇐) Let M accept L and M′ accept the complement. Build a decider D that interleaves them on input w: round k runs M on w for k steps, then M′ on w for k steps, with k = 1, 2, 3, … . Since w lies in exactly one of the two languages, one machine accepts it inside some finite s steps, so D stops by round s. The work used is at most 2(1 + 2 + … + s) = s(s + 1) simulated steps, plus a constant of bookkeeping. D answers yes if M accepted and no if M′ did. D halts on every input, so L is recursive.

Corollary: if L is r.e. but not recursive, the complement of L is not r.e. This is the cleanest way to prove a language is undecidable, used in 6.2.

An enumerator is a Turing machine that prints strings on an output tape. L is r.e. exactly when some enumerator prints exactly the strings of L, each one eventually. Run M on all strings in a dovetail: pair every input with a step count, run for that many steps, print whenever M accepts.

Worked example

Question. L and its complement are both r.e.: machine M accepts L, machine M′ accepts the complement. On input w = 0110, M accepts after exactly 6 steps and M′ never accepts. A decider D interleaves them, running M for k steps then M′ for k steps in round k, for k = 1, 2, 3, … . (a) In which round does D stop? (b) How many simulated steps has D used by the end of that round, ignoring bookkeeping? (c) Give the final answer D prints.

  1. Round 1 runs 1 + 1 = 2 simulated steps.
  2. Round 2 runs 2 + 2 = 4 more steps, total 6.
  3. Round k adds 2k steps, so after round k the total is 2(1 + 2 + … + k) = k(k + 1).
  4. M needs 6 steps on 0110, so D stops in round k = 6, after 6 × 7 = 42 simulated steps.
  5. M′ never accepts 0110, so D never sees an accepting run of M′ on this input; it does not wait for one.
  6. D answers yes, because the accepting machine in round 6 was M, and M accepts L.
  7. Check the bound: 2(1 + 2 + 3 + 4 + 5 + 6) = 2 × 21 = 42 steps, matching k(k + 1) with k = 6.

Exam traps

  • Believing an r.e. language must halt on every input. r.e. promises halting only on the strings inside the language.
  • Assuming r.e. is closed under complement. L_u is r.e. and its complement is not r.e. at all.
  • Confusing "M halts and rejects w" with "M loops on w". For a decider both are answers; for an acceptor a loop is no answer.
  • Writing the theorem backwards: both L and its complement being r.e. gives decidability, but one r.e. language alone gives nothing.
  • Running M to completion and then M′. If M loops on w, D never reaches M′, so the pair is not a decider without interleaving.

6.2 Decidable and undecidable problems

A decision problem is decidable when some Turing machine halts on every instance and answers yes or no correctly, and undecidable when no such machine can exist. Encoding machines and inputs as strings turns a problem into a language, and a mapping reduction carries undecidability from one language to another. This tells a programmer when to stop hunting for an exact algorithm: comparing two programs for identical behaviour, checking whether an arbitrary program ever reaches a given line, and building sound static analysers all run into these limits.

You need: 6.1 for recursive versus r.e. languages, and the decision procedures for DFA and CFG from Units 2 and 3.

Problems become languages

A decision problem asks one yes-or-no question per instance. A Turing machine reads strings, not problems, so every instance is first written as a string. Fix an alphabet, encode every machine and every grammar as a string over it, and the set of yes-instances becomes a language L. Deciding the problem is exactly deciding L.

Write ⟨M⟩ for the code of a machine M: its states, tape symbols and transition table listed as one string. Write ⟨M,w⟩ for a machine together with an input word, with a marker between the two. Angle brackets always mean "the encoding of". A machine can read the description of another machine and simulate it, which is why these codes matter.

Three levels matter. A language is decidable (recursive) when a machine halts on every input and answers yes or no. It is partially solvable (recursively enumerable) when a machine halts and says yes on its strings but may loop forever on the rest. Some languages are not even r.e.: no machine lists their strings at all.

One fact links the levels: if L and its complement are both r.e., run the two semi-deciders in parallel and L is decidable — one of them must halt.

Samples on both sides

Decidable, using the machines built in earlier units:

  • DFA D: does D accept w, is L(D) empty, is L(D) finite, is L(D) = Σ*, is L(D1) = L(D2). Decide by running D, or by searching the product automaton for a reachable final state, a reachable cycle, or a reachable disagreeing state.
  • CFG G: does G derive w (CYK, Unit 3), is L(G) empty, is L(G) finite. These are reachability and parsing questions on the grammar itself.

Undecidable, for Turing machines:

  • A_TM = {⟨M,w⟩ : M accepts w}, the acceptance problem.
  • E_TM = {⟨M⟩ : L(M) = ∅}, the emptiness problem.
  • EQ_TM = {⟨M1,M2⟩ : L(M1) = L(M2)}, the equivalence problem.
  • P_TM = {⟨M⟩ : M, started on a blank tape, at some point writes the fixed non-blank tape symbol a}. This is undecidable: from ⟨M,w⟩ build M′ that simulates M on w and writes a only on acceptance.

Undecidable too, for context-free grammars, even though membership there is easy: whether L(G) = Σ*, whether two CFGs are equivalent, and whether G is ambiguous. Notice that for a DFA the corresponding questions (universality and equivalence of two machines) are decidable; the jump to a machine with unbounded memory is what destroys the algorithm.

Mapping reductions

A mapping reduction A ≤m B is a computable, total function f that turns every instance of A into an instance of B with the same answer. Some syllabi call this reducibility. The map needs no clever insight; it is usually a small program that copies a description and edits a few transitions.

A ≤m B  ⟺  there is a computable total f such that x ∈ A ⟺ f(x) ∈ B for every x

A and B are languages over one alphabet; f : Σ* → Σ* is computed by a Turing machine that halts on every input; ≤m is read "many-one reduces to".

(A ≤m B and B decidable) ⇒ A decidable;   (A ≤m B and A undecidable) ⇒ B undecidable

the second statement is the contrapositive of the first, and it is the one used in proofs.

  1. Name the known undecidable language A (usually A_TM) and the target B.
  2. Take a general instance of A; for A_TM that is a pair ⟨M,w⟩.
  3. Describe the object that f builds, usually a new machine M′ whose code lies in B.
  4. Prove both directions: the instance is in A exactly when the built object is in B.
  5. Show f is computable and halts: it copies descriptions and adds a fixed piece of table, it never runs M.
  6. Conclude that a decider for B would give a decider for A, so B is undecidable.

The built machine M′ is allowed to loop. Only f must halt. Confusing these two is the most common error in the exam.

Worked example

Question. Show that the language B = {⟨M⟩ : M accepts the string 101} is undecidable. Give the reduction explicitly and justify each part.

  1. Known undecidable partner: A_TM = {⟨M,w⟩ : M accepts w}. Take a general instance ⟨M,w⟩ of it.
  2. Define f on ⟨M,w⟩. It builds a new machine M′ that works like this: on input x, if x is not the three-symbol word 101, reject at once; if x is 101, simulate M on w and accept exactly when M accepts w.
  3. Why f halts: f only copies M's transition table and adds a fixed front part that compares x against 101, which costs at most 3 symbol comparisons. f never runs M or M′, so f halts on every input.
  4. Forward direction: if ⟨M,w⟩ ∈ A_TM then M accepts w, so on input 101 the machine M′ accepts. Hence ⟨M′⟩ ∈ B.
  5. Backward direction: if ⟨M′⟩ ∈ B then M′ accepts 101. By construction the only way M′ accepts any string is when it simulated M on w and M accepted, so ⟨M,w⟩ ∈ A_TM.
  6. Therefore x ∈ A_TM ⟺ f(x) ∈ B, that is A_TM ≤m B.
  7. Suppose B had a decider D. Then the machine "compute f, run D" would decide A_TM on every input and halt. A_TM is undecidable, so no such D exists.

Exam traps

  • Writing "no algorithm is known" instead of "no algorithm can exist". Undecidability is a proved impossibility, not a gap in current knowledge.
  • Reversing the arrow. To prove B undecidable you reduce a known undecidable A to B, that is A ≤m B; proving B ≤m A proves nothing about B.
  • Thinking f must simulate M′. f only writes down the description of M′; M′ itself may loop forever, and that is allowed.
  • Mixing up undecidable with not r.e. A_TM is undecidable but r.e.; only its complement fails to be r.e.
  • Forgetting that f must be total and computable. A non-computable f would make the reduction worthless, and an f that loops gives no decider.

6.3 The halting problem

The halting problem asks one question about a Turing machine M and an input w: does M stop on w? Turing proved that no Turing machine can answer this for every pair (M,w). The proof uses self-reference: a machine is given its own code. The result limits compilers, static analyzers and program verifiers. A tool can run any program on a universal machine, but no general tool can always predict whether the program will stop.

You need: 6.1 for recursive and r.e. languages, 6.2 for decidable problems, and Unit 5 for the universal Turing machine.

The set HALT and its code

Let M be a Turing machine and w a string over its input alphabet. The pair ⟨M,w⟩ is a single string that codes both M and w. Some syllabi use a binary code over {0,1}; the exact code does not matter if a machine can read it and recover M and w.

HALT = { ⟨M,w⟩ : M halts on input w }

M is a Turing machine, w is an input string, and ⟨M,w⟩ is a computable code of the pair. HALT contains exactly the coded pairs for which M reaches a halting state.

A_TM = { ⟨M,w⟩ : M accepts w }

M accepts w when M halts in an accepting state. A_TM is the acceptance problem; HALT is the stopping problem and ignores whether M accepts or rejects.

Both sets are undecidable. No Turing machine halts on every coded pair and answers yes or no correctly. HALT is the cleaner set for the diagonal proof because "halts" has only two outcomes, while "accepts" also has a rejecting halt.

The diagonal proof

Assume, for contradiction, that a Turing machine H decides HALT. H reads ⟨M,w⟩ and halts with yes if M halts on w, and no if M loops on w. H itself always halts.

  1. Build a new Turing machine D. On input ⟨M⟩, D computes H(⟨M,⟨M⟩⟩). This asks whether M halts when M is run on its own code.
  2. If H answers yes, D enters an infinite loop.
  3. If H answers no, D halts.
  4. Run D on its own code ⟨D⟩. D halts on ⟨D⟩ exactly when H says that D loops on ⟨D⟩. By the construction, that happens exactly when D loops on ⟨D⟩.
  5. So D halts on ⟨D⟩ if and only if D loops on ⟨D⟩. Both cases contradict the assumed correctness of H.

The figure shows the same idea as a table. Rows are machines M1 to M4; columns are their codes. The marked diagonal asks each machine about its own code. D answers opposite to every marked cell, so D cannot be any row. Feeding D its own code puts D on the diagonal and forces the contradiction.

r.e., not recursive, and close variants

HALT is recursively enumerable. A universal Turing machine can simulate M on w step by step. If M halts, the simulation stops and the machine accepts ⟨M,w⟩. If M loops, the simulation runs forever. This is an acceptor, not a decider.

HALT is not recursive. A recursive language has a decider, and HALT has none. The complement of HALT is not r.e. If both HALT and its complement were r.e., interleaving the two acceptors would decide HALT: run both simulations in parallel and stop when one accepts. That would make HALT recursive, a contradiction.

  • Halting on empty input: HALT_ε = { ⟨M⟩ : M halts on ε } is undecidable. From M and w, build M_w that erases its input and simulates M on w. Then M_w halts on ε exactly when M halts on w.
  • Halting on every input: HALT_all = { ⟨M⟩ : M halts on every input } is undecidable. From M and w, build M' that on any input simulates M on w and then halts. M' halts on every input exactly when M halts on w.
  • Halting on own code: HALT_self = { ⟨M⟩ : M halts on ⟨M⟩ } is undecidable. The diagonal argument works directly: a decider for HALT_self lets D flip its own answer.

These variants are reductions from HALT. A decider for a variant would give a decider for HALT, which cannot exist.

No general loop checker

A loop checker is a program that reads source code and always says whether the program terminates on a given input. If such a checker existed, it would decide HALT. So no general loop checker exists. The same limit hits full program verifiers: proving that a program always returns or never crashes on all inputs can encode termination.

The universal machine of Unit 5 can run any program. It cannot decide non-halting: after any finite number of steps, a running program may stop later. A practical tool can prove termination for restricted languages or find bugs, but it cannot be correct for every program and every input.

Rice's theorem in 6.4 generalizes the result to every nontrivial property of the language a machine accepts. The running time of the simulation is studied in 6.7.

Exam traps

  • Do not say "run M on w" decides HALT. A long run without a halt is not a no answer.
  • Keep H and D separate. H is the assumed decider for HALT; D is the machine built to contradict H.
  • HALT asks about stopping, A_TM asks about accepting. A machine can halt by rejecting, so the sets are different.
  • Recursive means a decider that always halts. Recursively enumerable allows looping on strings not in the language; HALT is r.e. but not recursive.
  • The diagonal table is not a practical algorithm. It is a proof by contradiction; the entries are assumed answers from H.

6.4 Rice's theorem

Rice's theorem says no algorithm can inspect a Turing machine and decide any nontrivial property of the language it accepts. It exists because halting is hidden inside every semantic question: emptiness, finiteness, regularity, even 'accepts every string' all encode halting. The result is used to mark problems as undecidable before trying to solve them, and to separate semantic questions about programs from syntactic checks on their code.

You need <a href='#decidable-and-undecidable-problems'>6.2 for reductions and <a href='#the-halting-problem'>6.3 for the halting problem.

Properties of languages, not code

A property here is a set P of r.e. languages. A machine M has property P when L(M) ∈ P. P is trivial when P is empty or P contains every r.e. language. Rice's theorem: if P is nontrivial, the language S_P = {⟨M⟩ : L(M) ∈ P} is undecidable. Here ⟨M⟩ is a standard encoding of M as a string, and L(M) is the language M accepts. Some syllabi call S_P an index set because it is a set of machine indices.

S_P = {⟨M⟩ : L(M) ∈ P}

S_P is the set of machine descriptions whose accepted language lies in P; P is a set of r.e. languages; L(M) is the language accepted by M; ⟨M⟩ is the encoding of M.

The theorem is about meaning, not text. A property of L(M) is semantic. Emptiness, finiteness, regularity, and 'accepts every string' are semantic. A property of the code is syntactic. 'M has three states' and 'M halts within 100 steps' are syntactic and decidable by reading the description or simulating 100 steps. Rice does not touch them.

  • Nontrivial P must have at least one r.e. language inside and at least one r.e. language outside.
  • The theorem speaks about L(M), the set of strings M accepts, not about the states or transitions of M.
  • A decider for S_P must halt on every encoded machine and answer yes or no.

Proof by reduction from halting

Use a reduction from the halting problem A_TM = {⟨M,w⟩ : M halts on w}. Suppose a Turing machine R decides S_P. Because P is nontrivial, choose an r.e. language L₁ in P and an r.e. language L₂ not in P. First assume ∅ ∉ P. Take L₂ = ∅. Let M₁ be a machine with L(M₁) = L₁. From ⟨M,w⟩ build M′ as follows.

  1. On input x, M′ simulates M on w.
  2. If that simulation halts, M′ runs M₁ on x and accepts x exactly when M₁ accepts x.
  3. If that simulation never halts, M′ never reaches step 2, so it accepts nothing.

If M halts on w, L(M′) = L₁ ∈ P. If M does not halt on w, L(M′) = ∅ ∉ P. Running R on ⟨M′⟩ therefore answers whether M halts on w. This decides A_TM, which is impossible. If ∅ ∈ P, run the same argument on the complement property P̄ = {L : L ∉ P}. P̄ is nontrivial and excludes ∅. A decider for P would decide P̄ by flipping yes and no. Contradiction again. So S_P is undecidable.

Consequences and limits

Rice's theorem immediately marks many standard problems undecidable. For each property, check only that it is nontrivial.

  • Emptiness: P = {∅}. Nontrivial because ∅ is in P and Σ* is not.
  • Finiteness: P = finite r.e. languages. Nontrivial because ∅ is finite and Σ* is infinite.
  • Regularity: P = regular r.e. languages. Nontrivial because ∅ is regular and {0ⁿ1ⁿ : n ≥ 0} is not.
  • Context-freeness: P = context-free r.e. languages. Nontrivial because ∅ is context-free and {0ⁿ1ⁿ0ⁿ : n ≥ 0} is not.
  • L(M) = Σ*: P = {Σ*}. Nontrivial because Σ* is in P and ∅ is not.

The theorem does not say S_P is unrecognizable. It says no always-halting decider exists. Some of these sets are r.e.; for example {⟨M⟩ : L(M) ≠ ∅} is r.e., because a machine can simulate M on all strings in a dovetail and accept when one string is accepted. Nontriviality is essential: if P is empty, S_P is empty and decidable; if P is all r.e. languages, S_P is all encodings and decidable.

Worked example

Question. Use Rice's theorem to show that FIN = {⟨M⟩ : L(M) is finite} is undecidable.

  1. Let P be the set of finite r.e. languages. Then FIN = S_P.
  2. P is nontrivial: the empty language ∅ is finite and r.e.; the language Σ* is infinite and r.e.
  3. Suppose a Turing machine R decides FIN. Take any ⟨M,w⟩ and build M′: on input x, simulate M on w. If the simulation halts, accept x. If the simulation never halts, M′ loops and accepts nothing.
  4. If M halts on w, M′ accepts every x, so L(M′) = Σ*, which is infinite and not in P.
  5. If M does not halt on w, M′ accepts no x, so L(M′) = ∅, which is finite and in P.
  6. Thus R on ⟨M′⟩ tells whether M halts on w, with yes and no swapped. That decides the halting problem, impossible.

Answer. The set of machines accepting finite languages is undecidable; Rice's theorem applies because finiteness is a nontrivial property of L(M).

Exam traps

  • Applying Rice to syntax: 'M has three states' is decidable by reading ⟨M⟩. Rice covers only L(M).
  • Skipping nontriviality: P = ∅ and P = all r.e. languages give decidable S_P.
  • Saying Rice proves unrecognizable. It proves undecidable; r.e. status is separate. {⟨M⟩ : L(M) ≠ ∅} is r.e.
  • Mixing machine behaviour with language: 'M halts on ε' is undecidable but not a property of L(M), so Rice does not directly apply.
  • For a direct construction, do not try to detect nonhalting. Simulate first; the nonhalting case simply loops and accepts nothing.

6.5 Post's correspondence problem and modified PCP

Post's correspondence problem asks a simple question about dominoes. Each domino has a string on top and a string below. You may use a domino as many times as you like, in any order. The question is whether some finite sequence of dominoes makes the joined top strings equal the joined bottom strings. Emil Post posed this in 1946. It looks like a puzzle, but no Turing machine can decide it for every instance. It is the standard tool for proving that other problems about grammars and machines are undecidable.

You need: 6.2 for what an undecidable problem is, and 6.3 for the halting problem that the full reduction starts from.

Dominoes, lists and a match

Fix an alphabet Σ, for example {a, b}. A PCP instance has two finite lists of nonempty strings: A = w₁, w₂, …, wₖ and B = x₁, x₂, …, xₖ. Pair the strings at each position to make a domino. Domino i has wᵢ on top and xᵢ below, written (wᵢ, xᵢ). The figure shows three dominoes.

A match is a finite sequence of indices i₁, i₂, …, iₘ, with m ≥ 1, such that the joined top strings equal the joined bottom strings. The indices can repeat. Both joins use the same order. PCP asks one yes/no question: does this instance have a match?

w<sub>i₁</sub>w<sub>i₂</sub>…w<sub>iₘ</sub> = x<sub>i₁</sub>x<sub>i₂</sub>…x<sub>iₘ</sub>

i₁, i₂, …, iₘ are indices from 1 to k; wᵢ is the top string and xᵢ the bottom string of domino i; m ≥ 1 is the number of dominoes in the match.

PCP is undecidable. No Turing machine takes every instance and always halts with the correct yes or no. Emil Post posed the problem in 1946 and proved this. Some definitions allow empty strings in the lists; the undecidability holds either way, but the nonempty form is the one used in reductions.

The modified problem MPCP

Modified PCP (MPCP) adds one rule to the same data: the match must begin with index 1. So i₁ = 1 in every solution. Domino 1 must be used first, but it may be used again later. MPCP is also undecidable.

MPCP is the easier stepping stone in proofs. A Turing machine computation has a definite first configuration. When configurations are encoded as dominoes, the domino for the start configuration is fixed. MPCP lets the proof require that domino to appear first. PCP does not have that requirement, so a direct encoding is awkward.

To reduce MPCP to PCP, add a fresh symbol ♯ that is not in Σ. Build new dominoes so that a match can begin only with a marked copy of domino 1. The ♯ travels along the join, and a closing domino absorbs it at the end. The construction is mechanical and does not change the answer: the new PCP instance has a match exactly when the old MPCP instance has one. This is why MPCP is not harder than PCP.

Proof outline: from Turing machines to PCP

The full undecidability proof is a chain of reductions. Start with the acceptance problem for Turing machines: given a machine M and a string w, does M accept w? This problem is undecidable; it follows from the halting problem in 6.3.

Reduce acceptance to MPCP. A configuration of M is written as a string: the tape contents, the state, and the head position. Dominoes encode the start configuration, the move from one configuration to the next, and the copying of tape cells that the head does not touch. A match in the MPCP instance corresponds to an accepting computation of M on w, that is, one that halts in the accept state. If M halts without accepting, or never halts, the instance has no match. The first domino is the start configuration, so the MPCP rule fits naturally.

Reduce MPCP to PCP with the ♯ construction from the previous section. Therefore PCP is undecidable. The encoding details are long, but the shape is fixed: one domino for the start, one for each transition, copy dominoes for the rest of the tape, and a closing domino at the end. You are expected to know the reduction outline, not to reproduce every domino.

Worked example

Question. Over Σ = {a, b} the dominoes are 1 = (a, aab), 2 = (ab, b), and 3 = (bab, ab). Find a match. State whether the same sequence is a valid MPCP solution.

  1. Write the lists: A = [a, ab, bab] and B = [aab, b, ab].
  2. Try sequence 1, 2, 3. Top: a then ab then bab. a·ab = aab; aab·bab = aabbab. Bottom: aab then b then ab. aab·b = aabb; aabb·ab = aabbab. Both are aabbab.
  3. Check length: top has 6 symbols, bottom has 6 symbols. Equality holds. So 1,2,3 is a match.
  4. Check the MPCP rule: the first index is 1. Yes, so the same sequence is also an MPCP solution.
  5. Check single dominoes: 1 gives a vs aab; 2 gives ab vs b; 3 gives bab vs ab. None match.
  6. Check short tries: 1,2 gives top aab and bottom aabb; 1,3 gives top abab and bottom aabab; 2,3 gives top abbab and bottom bab. None match.

Answer. The sequence 1, 2, 3 is a match: both joined strings are aabbab, each of length 6, so the equality check is 1. It starts with domino 1, so it is also a valid MPCP solution.

Exam traps

  • A partial arrangement is not a match. Only exact equality of the full joined top and bottom strings counts.
  • PCP allows any first domino; MPCP forces index 1. Mixing the two versions changes the answer.
  • Indices may repeat. A match can use the same domino many times; do not assume each domino is used at most once.
  • Strings are concatenated in the chosen order, not compared domino by domino. The top of domino 1 need not equal its bottom.
  • A single domino with equal top and bottom is a match by itself, but if no such domino exists a longer match may still exist. Do not stop after checking single dominoes.

6.6 Computable languages and functions

A Turing machine does not only say yes or no. It can also write an answer on its tape. A function is computable when some machine halts on every input and leaves the correct output. Allow the machine to loop on some inputs, and the function is partial computable. This idea turns yes/no questions into arithmetic: a language L is decidable exactly when its characteristic function, 1 on L and 0 outside, is computable. Compilers, solvers and calculators all compute functions, so the line between computable and not matters.

You need: 6.1 for decidable versus r.e., 6.3 for the halting problem, and Unit 5 for the machine model.

Total and partial computable functions

Fix an alphabet Σ. Σ* is the set of all finite strings over Σ. A function f: Σ* → Σ* maps strings to strings. A Turing machine M computes f when M, started with x on its tape, halts with f(x) written on the tape. Then f is computable, also called total computable or Turing-computable.

A partial function f: Σ* ⇀ Σ* may be undefined on some inputs. It is partial computable when some machine halts with f(x) on every input where f is defined, and loops forever where f is undefined.

Every total computable function is partial computable. The converse fails: a partial function may have no value at some input, and no machine can halt and print a value that does not exist. Totality is the promise that matters. A compiler that sometimes loops forever is not a total function from source code to object code.

f is computable ⟺ some TM halts on every x ∈ Σ* with f(x) on its tape

Σ* is the set of all strings over Σ.

For a partial f, the machine must halt with f(x) where f is defined and may loop where f is undefined.

Encodings: ⟨M⟩ and ⟨M,w⟩

Every Turing machine is a finite object: finitely many states, a finite tape alphabet, a finite transition table. Write each item in binary and join the items with a fixed separator. The result is ⟨M⟩, the encoding of M. Likewise ⟨M,w⟩ encodes a machine together with an input string w.

A pairing function packs two numbers into one. One bijection is pair(i,j) = 2ⁱ(2j+1) − 1. Gödel numbering encodes a sequence n₁,…,n_k as a single number, for example 2n₁·3n₂⋯pkn_k using the first k primes p₁=2, p₂=3, …, and each exponent is the corresponding ni. Grammars are finite too: list the productions and encode the list.

Encodings must be computable and decodable: a machine can read ⟨M⟩ and rebuild M's table. Once machines are strings, they can be listed M₁, M₂, M₃, … and handed to other machines. That is what the universal machine does (Unit 5), and it is why the halting problem can be stated at all (see 6.3).

Characteristic function and the decidability test

For a language L over Σ, the characteristic function χ_L: Σ* → {0,1} answers the membership question as a number.

χ_L(x) = 1 if x ∈ L, and 0 if x ∉ L

L is a language over Σ; χ_L is always total when written this way.

Theorem. L is decidable if and only if χ_L is computable.

Proof (⇒). Let D decide L, halting on every x. Build M: run D on x, write 1 if D accepts, write 0 if D rejects, halt. M halts on every input, so χ_L is total computable.

Proof (⇐). Let M compute χ_L. Build D: run M on x, accept when the output is 1, reject when it is 0. Since M halts on every input, D decides L.

The r.e. case replaces total by partial. L is r.e. if and only if L is the domain of a partial computable function, that is, L = {x : ψ(x) is defined}. If A accepts L, set ψ(x) = 1 when A halts on x, undefined otherwise; the domain is L. Conversely, if M computes ψ, run M and accept whenever it halts; the accepted set is the domain.

Equivalently, a nonempty L is r.e. if and only if L is the range of a total computable function. Run the recogniser on the strings in dovetail order and print each string it accepts.

Composition and the hierarchy of functions

Composition. If f and g are computable, so is h(x) = g(f(x)): run the machine for f, feed its output to the machine for g. The same proof works for partial functions, with h(x) defined exactly when both stages halt.

Strictness. The total computable functions are a strict subset of the partial computable ones. Define g(M,w) = 1 when M halts on w, undefined otherwise. A simulator computes g, so g is partial computable. If g were total computable, halting would be decidable; it is not (see 6.3).

Counting. There are countably many Turing machines and uncountably many functions Σ* → Σ*. So almost every function is not computable by any machine.

Recursive function theory builds the same class from zero, successor and projections, closed under composition, primitive recursion and μ-recursion (minimisation). The names are enough here; the resulting class equals the partial computable functions.

Worked example

Question. A unary number n is written as the string aⁿ. (a) Show that f(n) = n + 1 is computable, tracing the machine on the input aaa. (b) Define g(M,w) = 1 when M halts on w, undefined otherwise, and state exactly how much of g is computable.

  1. Encode: aaa holds three a's, so n = 3.
  2. Machine M: move the head right while the cell holds a; at the first blank cell write a; halt.
  3. Trace: cells 1, 2, 3 hold a and cell 4 is blank. The head steps right three times, writes a in cell 4, and halts with aaaa.
  4. So f(aaa) = aaaa, that is, 3 maps to 4. The same moves work for every n and M always halts, so f is total computable.
  5. For g: simulate M on w step by step. If the simulation stops, write 1 and halt. If M never stops, the simulation never stops. So g is partial computable.
  6. If g were total computable, a machine would halt on every ⟨M,w⟩ and print 1 when M halts on w and 0 otherwise, which decides halting. Halting is undecidable, so g is not total computable.

Answer. f is total computable, with f(aaa) = aaaa (3 → 4); g is partial computable but not total computable.

Exam traps

  • Assuming every r.e. language has a computable characteristic function; only the decidable ones do, and for the rest χ_L is a total function that no machine computes. The partial computable object is the semi-characteristic function: 1 on L, undefined outside L.
  • Treating a partial function as if it had a value at every input; writing f(x) for x outside the domain is meaningless.
  • Confusing 'partial computable' with 'not computable'. A partial computable function is computed by a machine; it simply need not halt everywhere.
  • Thinking a machine that loops on some inputs still decides its language. A decider must halt on every input and print 0 or 1.
  • Mixing domain and range. L r.e. means L is the domain of a partial computable function; as a range you need the empty-set exception.

6.7 Time and space complexity of Turing machines

Measuring a Turing machine's cost turns 'this machine is fast' into a function of input length n. Time counts steps; space counts tape cells. The worst case over all inputs of length n is the standard measure. These functions sort languages into classes TIME(t(n)) and SPACE(s(n)). The idea compares algorithms independently of machine details and leads to P and NP. Only a few universities teach this chapter in detail.

You need Unit 5 for tapes, heads and configurations, and 6.2 for decidable problems.

Worst-case measures

Let M halt on every input. For input w, n = |w|. The running time on w is the number of steps before M halts. The running time t(n) is the maximum of these counts over all inputs of length n. The space used on w is the number of distinct tape cells scanned. The space s(n) is the maximum over all inputs of length n. Both are worst-case: one slow input of length n sets t(n).

Big-O and Θ describe growth. f(n) = O(g(n)) when constants c > 0 and n₀ exist with f(n) ≤ c·g(n) for all n ≥ n₀. f(n) = Θ(g(n)) when f = O(g) and g = O(f). For example, 3n² + 5n = Θ(n²). Constants drop out, so machine details do not change the class.

TIME(t(n)) = { L | some TM decides L in time O(t(n)) }

L is a language; t(n) is a time bound; the machine halts on every input.

SPACE(s(n)) = { L | some TM decides L using O(s(n)) work cells }

s(n) is a space bound; on a read-only input tape only work cells count.

Input tape and hierarchy bounds

On a single-tape machine the input sits on the work tape. Reading the input scans cells, so a machine using n input cells has space at least n. Many theorems want to discuss space below n. The standard fix is a read-only input tape plus work tapes. The input head reads but cannot write. Space counts only work-tape cells. A machine can then use log₂ n space while reading all n input symbols.

  • A machine running in time t(n), with t(n) ≥ n, scans at most t(n) + 1 cells: one new cell per step plus the starting cell.
  • TIME(f(n)) ⊆ SPACE(f(n)) for f(n) ≥ n, because each step visits at most one new cell.
  • SPACE(s(n)) ⊆ TIME(2^(O(s(n)))) for s(n) ≥ log₂ n, because the number of configurations is bounded by 2^(O(s)).

The time and space hierarchy theorems say that with more time or space, strictly more languages are decidable, for reasonable constructible bounds. A machine that diagonalises against all smaller-bound machines proves this. We quote the result. P, NP and completeness are in 6.8.

Worked example

Question. The word w = 000111 has length n = 6. Machine M₁ scans to the end and checks that the last two symbols are 1s. Machine M₂ decides {0ᵏ1ᵏ} by crossing out one 0 and one 1 per round. Compare their time and space on w. Give the worst-case time class of each.

  1. n = |w| = 6, so k = 3 zeros and 3 ones.
  2. M₁ reads n symbols and makes one final check: n + 1 = 6 + 1 = 7 steps. Thus M₁ runs in TIME(n).

  4. Total steps at most k × 2n = 3 × 12 = 36 = n². Thus M₂ runs in TIME(n²).
  5. M₂ writes only on the n input cells, so it uses at most n = 6 cells. On a single tape, space is at least n.

Exam traps

  • Forgetting that on a single tape the input cells count as space, so space is at least n.
  • Calling O(n) and Θ(n) the same. O is an upper bound; Θ is a tight bound.
  • Ignoring the worst case: t(n) is set by the slowest input of length n.
  • Using a read-only input tape and then counting input cells as space; in that model only work cells count.

6.8 Classes P and NP; NP-completeness and NP-hardness

Some problems have fast algorithms; some only have fast checks of a proposed answer. P names the first group and NP the second. The hardest problems in NP are NP-complete, and no polynomial-time algorithm is known for any of them. This chapter defines P, NP, reductions, NP-hardness and NP-completeness, states the Cook–Levin theorem, and shows the standard reduction chain. These ideas decide whether a problem is likely to have an efficient algorithm, so they matter in routing, scheduling, verification and competitive programming.

You need: 6.7 for TIME and SPACE classes and 6.2 for the idea of a reduction.

P, NP and certificates

For a function t(n), TIME(t(n)) is the set of languages decided by a Turing machine that halts within t(n) steps on every input of length n. TIME(n^k) is the same class with t(n)=n^k. P is the union of TIME(n^k) over all constants k≥0. A language in P has a decider whose running time is polynomial in the input length. Sorting a list and testing whether a number is prime are standard examples; both have polynomial-time algorithms.

P = ∪_{k≥0} TIME(n^k)

TIME(n^k) is the set of languages decided in O(n^k) time; n is the input length; the union ranges over every constant k.

NP is defined by certificates. A language L is in NP when there is a polynomial-time verifier V and a polynomial p such that for every string x: x ∈ L iff there exists a string y with |y| ≤ p(|x|) and V accepts the pair (x,y). The string y is a certificate or witness. V runs in time polynomial in |x|, so it cannot read more than polynomially many characters of y.

x ∈ L ⇔ ∃y, |y| ≤ p(|x|), V(x,y) = accept

x is the input string; y is the certificate; p is a polynomial bound on certificate length; V is the polynomial-time verifier.

Equivalently, NP is the set of languages accepted by a polynomial-time nondeterministic Turing machine: the machine guesses y and then runs V. A no-instance has no certificate, so no guess makes V accept. P ⊆ NP because a decider ignores the certificate and decides x directly. Nobody knows whether P = NP. Reductions, NP-hard and NP-complete

A language A reduces to B in polynomial time, written A ≤p B, when some polynomial-time computable function f satisfies: for every x, x ∈ A iff f(x) ∈ B. The function f is the reduction. It maps yes-instances of A to yes-instances of B and no-instances to no-instances.

A ≤p B ⇔ ∃f computable in polynomial time, ∀x: x ∈ A ⇔ f(x) ∈ B

A and B are languages; f is the reduction; x is any input string; ≤p is polynomial-time many-one reduction.

B is NP-hard when every language A in NP satisfies A ≤p B. B is NP-complete when B is NP-hard and B is also in NP. An NP-complete problem is therefore a hardest problem in NP: a polynomial-time decider for it would give a polynomial-time decider for every NP language.

To prove a new problem B is NP-complete, show B ∈ NP, then choose a known NP-complete A and prove A ≤p B. The direction matters: reducing B to A proves nothing about B's hardness. NP-hard is a lower-bound label; it does not require membership in NP. Some NP-hard problems are undecidable and hence outside NP.

Cook–Levin and the standard chain

Cook–Levin theorem: SAT is NP-complete. SAT asks whether a Boolean formula in variables x1,...,xn has an assignment making it true. The proof encodes the computation of a polynomial-time nondeterministic machine as a Boolean formula whose satisfying assignments correspond to accepting computation paths. 3SAT, the restriction to clauses of exactly three literals, is also NP-complete.

Standard reductions give SAT ≤p 3SAT ≤p CLIQUE ≤p VERTEX-COVER. CLIQUE asks whether a graph has a set of k vertices all pairwise adjacent. VERTEX-COVER asks whether a graph has a set of k vertices touching every edge. SUBSET-SUM asks whether some subset of a given set of integers adds to a target T. HAMILTONIAN CYCLE asks whether a graph has a cycle visiting every vertex exactly once. All are NP-complete.

Whether P = NP is open. If any NP-complete problem has a polynomial-time algorithm, then P = NP, because every NP language reduces to it. Most researchers believe P ≠ NP, but no proof exists. co-NP contains languages whose complements are in NP; for example, unsatisfiability of Boolean formulas is in co-NP. NP and co-NP are both contained in PSPACE, the languages decided with polynomial tape. TQBF, the true quantified Boolean formula problem, is PSPACE-complete.

Worked example

Question. Show that HAMILTONIAN CYCLE is in NP, using the graph G on vertices 1 to 5 with edges 12, 23, 34, 45, 51, 13 and 24. Use the cycle certificate 1, 2, 3, 4, 5. Count the verifier's edge lookups and comparisons, and give the order of its running time.

  1. A yes-instance must carry a certificate. Here the certificate y is the sequence of vertices (1,2,3,4,5).
  2. The verifier checks that the 5 vertices are distinct. It compares the sequence entries and finds no repeat, so this check passes.
  3. It checks the four consecutive edges 12, 23, 34, 45. All four are present in G, so these lookups pass.
  4. It checks that edge 51 closes the cycle. That edge is present, so the closure check passes.
  5. Count the work: the verifier makes 5 edge lookups (four consecutive edges plus the closing edge) and up to 10 pairwise comparisons to confirm the 5 vertices are distinct. For n=5, n²=25 and 15 ≤ 25, so the work is of order n², a polynomial (in general n edge lookups and n(n-1)/2 comparisons).

Answer. The certificate is checked with 5 edge lookups and 10 comparisons, which is within O(n²) time for n=5, so HAMILTONIAN CYCLE is in NP. The problem is also NP-complete, so a polynomial-time decider for it would prove P = NP.

Exam traps

  • NP does not mean 'not polynomial'. It means nondeterministic polynomial time, equivalently a polynomial-time checkable certificate for yes-instances.
  • NP-hard problems need not be in NP; NP-complete means NP-hard and in NP.
  • To prove B NP-hard, reduce a known NP-hard problem A to B (A ≤p B), not B to A.
  • Certificates exist only for yes-instances. A no-instance of an NP language has no accepted certificate; a verifier may reject every short string.
  • P = NP is open. A fast algorithm for one NP-complete problem would settle it, but none is known.

Takeaways

  1. A language is recursive when a machine decides it with a guaranteed halt, and RE when a machine only has to accept its strings.
  2. Every recursive language is RE, but HALT shows the reverse fails.
  3. A problem is undecidable when no single machine can answer every instance, not when we have not found one yet.
  4. Diagonalization proves the halting problem undecidable by making a machine disagree with every machine in a list.
  5. Rice's theorem turns one halting-style proof into undecidability for every nontrivial property of accepted languages.
  6. PCP packages the power of Turing machine computation into a domino-matching puzzle, which is why it is undecidable.
  7. Computable functions always halt with an answer; partial computable functions may loop where the value is undefined.
  8. Time and space complexity are worst-case counts of steps and cells as functions of input length n.
  9. P ⊆ NP, and an NP-complete problem is the hardest kind inside NP: a polynomial algorithm for one solves all of NP.

Exam question bank

Long answers here are graded on clean definitions, an explicit reduction or diagonal argument, and the conclusion drawn from it, so write the machine construction and the contradiction step by step.

Remember and understand

Understand Define recursive and recursively enumerable languages. Prove that every recursive language is recursively enumerable and give an example of an RE language that is not recursive. 13 marks

Recursive: some TM halts on every input and accepts exactly L; RE: some TM accepts exactly L and may loop on strings outside L; Construction: run the decider, accept if it accepts, reject if it rejects, so the same machine is an acceptor; HALT is RE (simulate M on w and accept when it halts) but not recursive; Closure comment: recursive languages are closed under complement, RE ones are not.

Understand State the halting problem formally. Explain, using diagonalization, why no Turing machine decides it. 13 marks

HALT = {⟨M, w⟩ : M halts on w}; Assume a decider H for HALT; Build D that on input ⟨M⟩ runs H on ⟨M, ⟨M⟩⟩ and does the opposite; D(⟨D⟩) halts iff D(⟨D⟩) loops, a contradiction; Conclusion: H does not exist; HALT is undecidable.

Understand State Rice's theorem and use it to show that the language {⟨M⟩ : L(M) = Σ*} is undecidable. 12 marks

Theorem statement: nontrivial property of RE languages gives an undecidable index set; Property 'L(M) = Σ*' holds for some RE languages and fails for others, so it is nontrivial; Quote the theorem, or sketch the reduction from HALT for full marks; Conclusion: no machine decides whether a given machine accepts every string.

Understand Define Post's correspondence problem and its modified version. Explain why MPCP is reduced to PCP and not the other way round. 12 marks

Domino pairs (xᵢ, yᵢ) over a finite alphabet, repetitions allowed; A solution is a nonempty index sequence with equal top and bottom strings; MPCP adds the rule that pair 1 must come first; Direction of reduction: MPCP ≤m PCP, so undecidability of MPCP gives undecidability of PCP; Both are undecidable.

Understand Define the time complexity and space complexity of a Turing machine. Why do we ignore constant factors and use worst-case counts? 10 marks

Time: maximum steps over inputs of length n, written t(n); Space: maximum tape cells scanned, written s(n); Both are functions of the input length, not the input value; Worst case because an algorithm must work on every input; Constant factors and lower-order terms dropped since they do not change polynomial versus exponential.

Apply

Apply Let L = {⟨M⟩ : M halts on the empty tape}. Show that L is undecidable by reducing the halting problem to it. 13 marks

Define a total computable map from ⟨M, w⟩ to ⟨M′⟩; M′ erases its tape, writes w, then simulates M; M halts on w iff M′ halts on empty tape; If L were decidable, HALT would be decidable, contradiction; Reduction works in one direction only; state it clearly.

Apply Given domino pairs, find a matching sequence for a small PCP instance, and explain how a machine would generate candidate sequences. 10 marks

List the pairs with top and bottom strings; Try increasing sequence lengths, tracking the top and bottom partial strings; Stop when both strings are equal and nonempty; A machine can enumerate sequences in length order, so the problem is semidecidable; Why enumeration alone cannot decide the problem.

Apply Show using Rice's theorem that the set of machine codes whose language is finite is undecidable. 12 marks

Property 'L(M) is finite' is a property of the language, not the machine; It is nontrivial: some RE languages are finite, some are infinite; Rice's theorem applies directly; Write the index set A = {⟨M⟩ : L(M) finite} and conclude it is undecidable; Note finiteness of the machine description is decidable, finiteness of the language is not.

Apply Define a computable function and a partial computable function. Describe a Turing machine that computes f(n) = n² for unary n written as 1ⁿ, and state whether it is total. 10 marks

Computable: halts on every input with the correct output; Partial computable: halts and gives the value only where the value exists; Machine outline: count the 1s, write the product as repeated blocks of 1s; The machine halts on all unary inputs, so f is computable, hence total; Contrast with a function undefined on some inputs, which stays partial computable.

Apply Show that if any NP-complete language lies in P, then P = NP. 12 marks

Definition: L is NP-complete if L ∈ NP and every A ∈ NP has A ≤p L; Polynomial reduction composes: A decided in polynomial time by deciding L; So if L ∈ P, every A ∈ NP is in P; Hence NP ⊆ P and, with P ⊆ NP, equality follows; Consequence for a practical problem such as SAT or 3-SAT.

Analyze and evaluate

Analyze Compare the diagonalization proof of the halting problem with a reduction proof of undecidability. When is each method the better tool? 13 marks

Diagonalization uses a self-reference trick and a hypothetical decider; Reduction assumes a decider for the new problem and builds one for a known undecidable problem; Reduction is reusable and gives relative hardness; diagonalization gives the first undecidable problem; Closure consequences: RE not closed under complement, recursive closed under complement; Rice's theorem as a mass-produced reduction.

Analyze Describe how Post's correspondence problem is used to prove that deciding ambiguity of a context-free grammar is undecidable. 13 marks

Build a grammar from the domino pairs so that top strings are generated by one side, bottom by the other; A matching sequence exists exactly when the grammar is ambiguous; So PCP ≤m ambiguity of CFG; Since PCP is undecidable, ambiguity is undecidable; Note many CFG problems are decidable (emptiness, membership) while ambiguity is not.

Evaluate Explain what the Cook–Levin theorem says about SAT, and evaluate why the P versus NP question matters outside computer science. 14 marks

Cook–Levin: SAT is NP-complete; Certificate idea: a satisfying assignment is checked in polynomial time; Every NP problem reduces to SAT by writing the machine's computation as a Boolean formula; If P = NP, all NP problems become tractable; if not, none of the NP-complete ones are; Size of the search space, 2ⁿ certificates, and consequences for scheduling, routing, verification.

Analyze Prove that a language L is recursive if and only if both L and its complement are recursively enumerable. 13 marks

Forward: a decider for L also decides its complement, both are RE; Backward: run the two acceptors for L and its complement in parallel on the same input; Exactly one of them must eventually accept, so the parallel machine halts; This makes L recursive and its complement recursive too; Consequence: an RE language whose complement is not RE cannot be recursive; HALT is the standard example.

Glossary

Certificate
A short string that lets a verifier confirm membership, such as a satisfying assignment for a formula.
Church–Turing thesis
The claim that every effectively computable function can be computed by a Turing machine.
Class NP
Languages for which a polynomial-time verifier accepts some short certificate exactly for the strings in the language.
Class P
Languages decidable by a deterministic machine in time bounded by a polynomial in the input length.
Co-RE
The class of languages whose complement is recursively enumerable.
Computable function
A function for which some Turing machine halts on every input with the correct output.
Decider
A Turing machine that halts on every input, so it always gives an answer.
Diagonalization
A proof method that builds an object differing from every member of a listed family at one selected point.
Domino pair
An ordered pair of strings (xᵢ, yᵢ) in an instance of Post's correspondence problem.
DTIME(t(n))
The class of languages decided by a deterministic Turing machine in time O(t(n)).
Halting problem
The problem of deciding, for a machine M and input w, whether M halts on w.
MPCP
Post's correspondence problem with the added requirement that the first pair used is pair 1.
NP-complete
A language in NP to which every language in NP reduces in polynomial time.
NP-hard
A language to which every language in NP reduces in polynomial time, with no requirement of membership in NP.
Partial computable function
A function computed by a machine that halts with the right value where the function is defined and may loop elsewhere.
Polynomial-time reduction
A reduction computed by a deterministic machine in time polynomial in the input length, written A ≤p B.
Property of RE languages
A condition that depends only on the set L(M), not on how the machine is written.
Recursive language
A language accepted by some decider.
Recursively enumerable language
A language accepted by some Turing machine, which may loop on strings outside the language.
Reduction
A total computable mapping that turns instances of one problem into instances of another while preserving yes and no answers.
Rice's theorem
Every nontrivial property of the language accepted by a Turing machine is undecidable.
Space complexity
A worst-case count of tape cells used as a function of input length.
Time complexity
A worst-case count of machine steps as a function of input length.
Turing machine
An abstract machine with a finite state control, one tape and a read-write head that moves one cell per step.
Universal Turing machine
A machine that takes a code for any machine M and an input w and simulates M on w.
Verifier
A deterministic polynomial-time machine that reads the input and a certificate and accepts or rejects.
