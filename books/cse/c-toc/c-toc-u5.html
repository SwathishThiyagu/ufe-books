5.1 Turing machine model, notation and instantaneous descriptions

A Turing machine follows a finite transition table while reading and rewriting an unbounded tape. Its head moves in both directions, so earlier information can be revisited. The tape supplies memory; the finite control determines the next elementary action.

You need: alphabets and strings from Unit 1 and the idea of configurations from Unit 4. Unlike a PDA, this machine can rewrite a cell below its current position by travelling back to it.

A precise model

Use the deterministic machine M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject). The set Q is finite. The input alphabet Σ is contained in the finite tape alphabet Γ, which also contains a blank symbol □ not in Σ. The initial state is q₀; the distinct states q_accept and q_reject halt with their named outcomes. The transition function is δ: (Q minus {q_accept, q_reject}) × Γ → Q × Γ × {L, R}.

A transition δ(q, a) = (r, b, R) means: in state q scanning a, write b in that cell, move one cell right, and enter r. A left move is analogous. The write changes the old scanned cell before the head moves. Entering a halting state completes this move and stops. Those states have no outgoing transitions. We use a total transition function on nonhalting state-symbol pairs; any unlisted pair in a displayed design means an explicit move to rejection, preserving the symbol and moving right.

The tape has cells indexed by all integers, extending without a fixed bound in both directions. Input w occupies cells 0 through |w| − 1, all other cells are blank, and the head begins at cell 0. On input ε, cell 0 is blank. Only finitely many cells have been visited after any finite number of moves. The model does not assume the entire infinite tape is physically written in advance.

Other textbooks use a left-ended tape or allow a stationary head move. These conventions change transition details but not the languages recognizable by Turing machines. State the chosen convention before tracing an edge or counting moves. Our examples use L and R only; a stationary move can be simulated by moving right and then left through an auxiliary state.

Instantaneous descriptions and diagrams

A configuration, also called an instantaneous description or ID, records state, tape contents and head position. A compact notation is u q v: the tape displays uv, the head scans the first symbol of v, and q is the current state. Omitted cells on either side are blank. If the head scans a blank immediately after u, write u q □ rather than leaving its scanned position implicit.

For a right move δ(q, a) = (r, b, R), the local ID rule is u q av ⊢ ub r v. If v is empty, expose a trailing □. For a left move, write the preceding symbol explicitly: uc q av ⊢ u r cbv when δ(q, a) = (r, b, L). Here c is the cell immediately left of the head; if it was outside the displayed portion, it is blank. The relation ⊢ is one move, and ⊢* is zero or more.

In a transition diagram an edge q → r labelled “a → b, R” abbreviates δ(q, a) = (r, b, R). A transition table instead has a row for each state and a column for each scanned symbol. Both represent the same finite function. Neither a state diagram alone nor a tape snapshot alone is a complete machine configuration.

Reading a small machine

Let Σ = {1} and Γ = {1, □}. A unary-successor transducer uses state s with δ(s, 1) = (s, 1, R) and δ(s, □) = (q_accept, 1, R). The unary representation of n is 1ⁿ, including ε for zero. The machine scans across the input and replaces its first following blank with 1. The final output is therefore 1^(n+1), read as the contiguous block starting at cell 0.

The invariant is simple: while in s, every visited input 1 is unchanged and the head advances one position. The first blank is exactly the end of a well-formed unary input. There are n scanning moves and one final write, so the run takes n + 1 moves and always halts. Its language interpretation is “accept every unary input”; its function interpretation is “produce the successor”. Chapter 5.2 separates these two uses.

  1. Write the initial tape with a visible head position and blank convention.
  2. Find the table entry for the current state and scanned symbol.
  3. Overwrite that symbol, move exactly one cell, then update the state.
  4. Record the next ID, exposing blanks when necessary.
  5. Stop only at an explicitly defined halting outcome.

Worked example

Trace unary successor on input 111 and count moves.

s111 ⊢ 1s11 ⊢ 11s1 ⊢ 111s□ ⊢ 1111q_accept□. The first three moves preserve a 1 and move right. The fourth writes 1 into cell 3 and moves to cell 4 while entering the accepting state. The output block has length 4, so the represented number changes from 3 to 4.

On ε, the initial ID is s□ and one move gives 1q_accept□, representing 1. The blank symbol is not an extra input character; it is the initial content of every unused cell. The final head position is just right of the output, which is permitted by this transducer's stated output convention.

Exam traps

  • A transition writes at the old head position before moving.
  • The blank □ is a tape symbol; ε denotes a zero-length string.
  • An ID needs head position as well as state and tape contents.
  • State whether missing transitions reject and whether stationary moves or tape boundaries are allowed.

5.2 Language accepted by a Turing machine

The language accepted by a Turing machine consists of inputs whose computations reach its accepting state. A recognizer may reject or run forever on other inputs. A decider must halt on every input, so its negative answers are guaranteed to arrive.

Acceptance, rejection and divergence

For a deterministic machine M, define L(M) = {w ∈ Σ* | M accepts w}. Equivalently, the initial configuration on w reaches q_accept after finitely many moves. A rejecting computation reaches q_reject. A diverging computation makes infinitely many moves without reaching either halting state. Rejection and divergence both exclude w from L(M), but they are operationally different outcomes.

A language is Turing-recognizable when some TM accepts exactly its members. Some syllabi call this recursively enumerable or semidecidable. A language is decidable, also called recursive, when some TM halts on every input and accepts exactly its members. Every decider is a recognizer. A recognizer for a decidable language can still be poorly designed and loop on some nonmembers: the property of the language is based on the existence of a decider, not on every machine describing it.

Acceptance does not require visiting every input cell or erasing the tape. Unlike the input-consuming PDA convention of Unit 4, a TM starts with the whole input already written on its tape. It may have enough information to accept before scanning the last symbol. The machine designer must ensure that such an early answer is justified for all possible suffixes.

The final tape content is also not the acceptance condition. A machine can leave the original input unchanged and accept; another can erase everything and reject. For function computation, output contents matter separately, as Chapter 5.3 explains. Always identify whether a question asks for a language recognizer, a decider or a transducer.

Two machines for one language

Let L be the binary strings containing at least one 1. A decider D uses a scanning state q: on 0, preserve 0 and move right; on 1, preserve 1 and enter q_accept while moving right; on □, enter q_reject. It halts after at most |w| + 1 moves. Finding one 1 is sufficient regardless of the unexamined suffix.

A recognizer R can use the same moves on 0 and 1 but, on □, enter a nonhalting state that keeps moving right over blanks forever. Its accepted language is still L. Words of only 0 symbols never cause a false acceptance, but they never receive a negative answer either. The empty string is one such nonmember because it contains no 1.

Swapping accept and reject states complements a decider's language because every input reaches exactly one of those two outcomes. Swapping them in a general recognizer does not handle diverging inputs: those runs still diverge. This distinction is the basis for later results on decidability and complements in Unit 6.

Designing a total recognition procedure

A decider for {0ⁿ1ⁿ | n ≥ 0} illustrates a more structured argument. First check that the input has the shape 0*1*; reject a 0 occurring after a 1. Put a left anchor ⊢ in the blank cell immediately left of the input. Mark a leftmost unmarked 0 as X, search right for the next unmarked 1 and mark it Y, then return to the anchor. Reject if no partner exists.

When no unmarked 0 remains, check that there is no unmarked 1 left. Accept if only matched markers remain. The invariant is that each completed round has marked exactly one 0 and one 1. During a rightward search, skip previously marked Y symbols rather than mistaking them for unused partners. Unit 3 already gives a CFG for this language; the TM demonstrates a different recognition mechanism.

  1. Specify the language, including its alphabet and empty-string case.
  2. Prove accepted inputs satisfy its defining conditions.
  3. Prove every member eventually reaches acceptance.
  4. For a decider, give a separate termination argument covering invalid inputs too.

Each successful matching round removes one unmarked 0 and one unmarked 1 from consideration. There are finitely many input cells, and each sweep between the anchor and the first blank is finite. Thus the matching procedure cannot perform infinitely many successful rounds or get trapped in an unbounded search on a fixed finite input. “It works on a few examples” is not a substitute for this termination argument.

Exam traps

  • Rejection is a finite negative halt; divergence is not a rejection event.
  • A TM need not scan every input symbol before accepting.
  • Decidable describes a language with some total decider, not every recognizer for it.
  • Prove termination on malformed inputs as well as valid members.

5.3 Designing Turing machines; computing integer functions

A Turing machine can compute a function by transforming an encoded input into an encoded output and halting. A correct design specifies the encoding, the final tape convention and a termination argument. Arithmetic is implemented through tape operations rather than assumed as a built-in instruction.

Specify the function before the machine

For a function f: ℕᵏ → ℕ, choose an effective representation of each nonnegative integer and separators between arguments. Here ℕ includes zero. Unary encoding uses n copies of 1, so zero is ε. Binary encoding is more compact, but carry and boundary handling become explicit parts of the machine. Signed integers require an additional sign convention; the word integer alone does not choose one.

A total computable function has a machine that halts with the correct encoded result for every valid encoded argument tuple. A partial function is defined only on a subset of such tuples. Under the standard partial-computation convention, the machine halts with an output on its domain and diverges on inputs outside it. Malformed encodings are a separate matter: a total arithmetic specification can reject them rather than treating them as integers.

Fix where the result must appear and whether work symbols must be erased. Our unary-addition example leaves its output as one block starting in cell 0, blank elsewhere in the used region, with no required final head position. A machine leaving a correct number among extra markers has not met that convention. A different convention is legitimate if it is stated and can be interpreted effectively.

Unary addition by merging blocks

Represent inputs (m, n) by 1ᵐ#1ⁿ and require output 1^(m+n), where # is a separator not used as a unary digit. Replacing # by 1 joins the blocks but adds one extra 1. Erasing the final 1 corrects that extra count. This works even when either argument is zero; the separator itself supplies the temporary extra symbol when both are zero.

  1. In state sep, scan right over 1 symbols until # appears.
  2. Replace # by 1, move right and enter state end.
  3. In end, scan over the right block until the first blank.
  4. On that blank, move left into state erase without changing it.
  5. In erase, replace the final 1 by blank, move right and halt successfully.

The transition table is δ(sep, 1) = (sep, 1, R), δ(sep, #) = (end, 1, R), δ(end, 1) = (end, 1, R), δ(end, □) = (erase, □, L), and δ(erase, 1) = (q_accept, □, R). Other pairs reject under the convention of Chapter 5.1. A second # or an absent separator therefore fails rather than silently producing an arithmetic answer.

After the separator replacement, the used block has m + n + 1 copies of 1. The final erase removes exactly one. Each scan traverses a finite original block, so the procedure halts. Counting transitions gives m scans, one separator replacement, n scans, one left turn and one erase: m + n + 3 moves. This count refers to this encoding and this machine, not an encoding-independent cost of addition.

Executable transition-table trace

The following Python simulator implements that finite table. It uses an underscore for □ and a sparse dictionary for the tape; head indices may be arbitrary integers. The host language runs the transitions but does not calculate the sum directly.

word = "111#11"
delta = {("sep", "1"): ("sep", "1", 1),
         ("sep", "#"): ("end", "1", 1),
         ("end", "1"): ("end", "1", 1),
         ("end", "_"): ("erase", "_", -1),
         ("erase", "1"): ("acc", "_", 1)}
tape = dict(enumerate(word))
head, state, moves = 0, "sep", 0
while state != "acc":
    key = (state, tape.get(head, "_"))
    if key not in delta:
        raise ValueError("invalid encoding")
    state, written, direction = delta[key]
    tape[head] = written
    head += direction
    moves += 1
result = "".join(tape.get(i, "_") for i in range(len(word)))
print("output:", result.rstrip("_"))
print("moves:", moves)

The exception represents failure of this input-format contract; it is not a general simulator for every halting convention. On valid unary pairs the displayed rules always reach acc. The simulator's result extraction works because this particular procedure leaves a contiguous output at the origin and only trailing blanks.

Worked example

Explain binary successor on 1011. Scan to the right end, then propagate a carry left: trailing 1 becomes 0, the next 1 becomes 0, and the next 0 becomes 1. The result is 1100, representing 12 rather than the input 11.

If all digits are 1, the carry reaches the blank left of the original block and writes a leading 1; 111 becomes 1000. On a two-way tape this may extend the output left of cell 0. A specification demanding origin-aligned output needs an additional shift or a reserved leading cell. Ignoring this boundary changes the function's output contract.

Exam traps

  • Unary zero is ε here, while a pair of zeros still contains the separator #.
  • Replacing # alone computes m + n + 1, so the final erase is essential.
  • Do not claim a transducer correct without a precise output location and cleanup convention.
  • A bound in terms of unary length is not the same bound in terms of binary input length.

5.4 Variants: multitape and nondeterministic Turing machines

Multitape and nondeterministic machines make algorithms easier to describe, but they do not enlarge the class of Turing-computable languages or functions. Their simulations show equality of computational power. They do not imply equality of running time.

Several tapes, one finite control

A k-tape deterministic TM has k tapes and one head on each. The positive integer k is fixed as part of the machine, not supplied as an unbounded resource parameter by the input. Initially the input occupies tape 1, the others are blank, and every head starts at its origin. One transition reads the k scanned symbols, writes k symbols, chooses k head directions and updates the single shared control state.

Its transition function has the shape δ: (nonhalting Q) × Γᵏ → Q × Γᵏ × {L, R}ᵏ. A configuration therefore needs k tape contents and k head positions as well as one state. A multitape step is one simultaneous operation, not k independent machines running unrelated programs. Copying and comparisons become convenient because one head can track input while another tracks work data.

For example, to copy a binary word to tape 2, repeatedly read a symbol on tape 1, write the same symbol on tape 2 and advance both heads. On reaching the first blank, finish or begin a repositioning phase. If the next phase requires both heads back at the first symbol, those return moves must be included in the algorithm rather than assumed free.

Simulating multiple tapes on one tape

A single-tape simulator can encode the k finite active tape regions separated by delimiters, with a marked version of each symbol identifying the corresponding head location. One sweep reads the marked symbols. Their tuple is stored in finite control because k and Γ are fixed. The simulator then looks up the target transition and sweeps again to update symbols and head marks.

When a simulated head moves beyond its represented region, insert a new blank cell in that region, shifting later encoded material if necessary. The encoding always contains one head mark for each simulated tape, even when the head scans blank. Otherwise the simulator would lose track of a head positioned outside the nonblank data. Negative simulated positions on a two-way tape can be accommodated by extending the represented region on its left.

The invariant is that the encoded tape regions, head marks and stored simulated state describe exactly one configuration of the multitape machine. A bounded sequence of physical sweeps implements one simulated move. Every simulated step finishes after finitely many real steps, and the simulator accepts or rejects exactly when the target does. Time overhead exists because a single physical head must travel between distant encoded positions.

Nondeterministic computations and fair search

A nondeterministic TM has a finite set of outcomes for a state-symbol pair. Its computation forms a finitely branching tree of configurations. It accepts an input if some branch reaches acceptance after finitely many moves. A rejecting branch does not cancel an accepting branch. For an NTM decider, require every branch to halt on every input, so unsuccessful searches cannot continue indefinitely.

A deterministic simulator explores this tree breadth-first, processing all configurations at one depth before going deeper. It stores enough information to reconstruct or copy each branch's tape and state. If it finds an accepting configuration, it accepts. If all branches have halted without accepting, it rejects. If no branch accepts but some branch continues forever, the simulation may continue forever, which is permitted for a recognizer.

Depth-first search alone is unsafe: an infinite first branch can prevent exploration of a short accepting branch elsewhere. Breadth-first search is fair because every node at a finite depth is eventually reached. There are finitely many nodes at each depth, and simulating one machine transition is an effective finite operation. This proves NTM-to-DTM recognizability equivalence without appealing to an imaginary parallel machine that completes infinitely much work at once.

If every branch halts and branching is finite, the computation tree has no infinite path and is finite. Hence breadth-first simulation eventually finishes. This establishes equivalence for decidability as well. The search may be much slower than one successful branch, so this equivalence does not settle whether deterministic and nondeterministic polynomial time coincide; see Unit 6.

Other harmless model changes

A stationary head move can be replaced by a right move followed by a left move in an auxiliary state. A multi-track tape stores a fixed tuple in each cell; it still has one shared head, unlike independently moving multitape heads. A left-ended tape can encode the two sides of a two-way tape on separate tracks, with finite control recording which side is currently simulated.

These constructions depend on effective encodings and finitely many symbols and states. They do not give equivalence to arbitrary devices endowed with noncomputable information. Nor do they make a PDA equivalent to a TM: a PDA's restricted stack access is a substantive memory restriction, as Unit 4 shows.

Exam traps

  • Multitape means independently moving heads, not merely several tracks under one head.
  • Nondeterministic acceptance is existential: one accepting branch is sufficient.
  • A deterministic simulator must search fairly when infinite branches are possible.
  • Equivalent power does not imply equal time or resolve P versus NP.

5.5 Universal Turing machine

A universal Turing machine is one fixed machine that interprets an encoded machine description together with an input. It simulates the described computation rather than requiring a new transition table for every task. The program becomes ordinary finite data on the interpreter’s tape.

Encoding machines and inputs

Write ⟨M⟩ for a finite effective encoding of machine M and ⟨M, w⟩ for an unambiguous encoding of M together with input w. Effective means the interpreter can parse the description and determine its states, tape alphabet, start and halting states, blank convention and transition rules by finite procedures. State names and tape symbols can be replaced by positive integer identifiers.

An encoding need not be unique or fashionable. What matters is that records can be decoded and compared mechanically. A binary format is convenient but not essential: any fixed finite encoding alphabet can itself be recoded into binary. Delimiters must be distinguishable from encoded data; simply inserting an unescaped separator into arbitrary raw input would not guarantee unique parsing.

For illustration, number the states and tape symbols. Encode integer j ≥ 1 by 1ʲ. Encode a transition (i, j) → (k, ℓ, D) as five fields separated by #, ending in direction D ∈ {L, R}; separate records by |. A header, separated from the rules by /, lists state count, tape-symbol count, input-symbol count, initial-state index, accepting-state index, rejecting-state index and blank index. Assume input symbols are numbered first. After $, encode each input symbol's index in unary, separating successive symbols by #; no fields after $ denotes empty input.

This is an illustrative format, not a standard numerical coding. A decoder checks that indices are in range, the blank is not an input symbol, halting states are distinct and nonhalting transition entries are well formed. It can reject malformed descriptions. Equivalent textbook encodings may use different delimiters or conventions without changing universality.

The interpreter loop

A universal simulator keeps the encoded program, the simulated tape, the simulated head location and the simulated state. A multitape organization makes this clear; Chapter 5.4 then converts it to the basic model. The universal machine's own control states are fixed. An arbitrarily large target-state identifier is stored as a string on a work tape, not as a newly created control state.

  1. Decode and validate the description, then initialize a simulated tape containing w.
  2. Check whether the simulated state is accepting or rejecting and propagate that outcome.
  3. Read the encoded symbol at the simulated head and search the finite transition list for the matching state-symbol record.
  4. Rewrite that simulated cell, update the stored state and move the simulated head.
  5. Extend the represented tape with encoded blanks when needed and repeat.

The invariant is that the interpreter's encoded configuration corresponds exactly to the target's current configuration after each simulated step. One target move may require many interpreter moves for searches, comparisons and tape updates. The simulation claims matching behaviour, not one-to-one instruction timing. If the target halts, a finite sequence of simulator work reaches the same outcome; if the target runs forever, the universal simulation continues.

Universality and its limits

The acceptance language A_TM = {⟨M, w⟩ | M accepts w} is recognizable: a universal recognizer simulates M and accepts when M accepts. If M rejects, it may reject; if M diverges, the simulation can diverge. This does not decide whether every target computation will ever halt. Simulation reproduces the run rather than predicting its unbounded future.

The halting question also differs from acceptance. A machine that eventually rejects has halted but has not accepted. Unit 6 proves that there is no general decider for the halting problem and develops the corresponding limitations for acceptance. There is no contradiction with universal simulation: an interpreter can execute a nonterminating program without possessing a method to diagnose all nontermination.

Universal computation supports the stored-program idea: one device can carry out many effective procedures when given different descriptions. Real interpreters and virtual machines follow this pattern, though their architectures and resource limits differ. A universal machine is still finite in its rules and uses only a finite tape alphabet; the unbounded resource is potential tape space over the course of computation.

  • Unique parsing requires a complete delimiter or self-delimiting convention.
  • Simulation does not make nontermination decidable.
  • Target steps, record comparisons and simulator steps are different quantities.

5.6 Church-Turing thesis

The Church–Turing thesis identifies effective mechanical computation with Turing-machine computability. It connects an informal idea of following an algorithm to a precise mathematical model. It is not the theorem that two already formal machine definitions simulate each other.

What the thesis claims

An effectively calculable function is one obtained by a uniform mechanical procedure: the instructions are finite, each step is explicit and requires only a finite operation, and the same instructions apply to inputs of arbitrary finite size. The procedure may use more time and memory on larger inputs. For a total function, it must eventually produce the answer on every valid input; for a partial computation, some inputs may never produce a result.

The thesis says that every such effective computation can be carried out by a Turing machine. Conversely, a specified TM can be simulated mechanically one transition at a time, so its computations meet the intended idea of rule-following. Some syllabi call this Church's thesis, the Turing hypothesis or the Church–Turing thesis. The names point to the same basic claim about effective computability in this context.

The thesis does not say that every mathematically definable function is computable. A sentence can describe a desired output without providing an effective method to obtain it. Nor does the thesis say that every computable function is practical to calculate on available hardware. Computability requires a finite terminating computation on each domain input, not a small resource bound.

Why it is a thesis rather than an ordinary theorem

Turing machines, lambda calculus and suitable recursive-function formalisms have precise definitions. Their equivalence can be proved by translations and simulations. The informal phrase “every effective method”, however, does not start as one fixed mathematical definition covering all possible procedures. A formal equivalence proof between chosen models therefore supports, but does not by itself prove, the broader thesis.

Evidence comes from independent formalizations agreeing on the same computable functions, from systematic simulation of ordinary algorithms, and from the robustness of the model under changes such as multiple tapes or nondeterminism. Chapter 5.4 proves examples of that robustness. A new convenient programming notation is not a stronger computability model merely because it can express the same procedure more compactly.

This distinction matters in an exam answer. “Multitape TMs and single-tape TMs are equivalent” is a theorem with two formal endpoints. “Every effective algorithm is simulatable by a TM” is the thesis linking a formal endpoint to the informal notion of algorithm. Writing a proof arrow between two formal models does not remove that difference.

How to use it responsibly

  1. Describe a uniform procedure with finite, explicit instructions.
  2. Explain how its data are represented by finite strings.
  3. Reduce its operations to mechanical steps, such as symbol comparison, scanning and finite arithmetic routines.
  4. Give a termination argument if the claim is total computation.
  5. Invoke the thesis to identify this effective method as TM-computable, or give a direct simulation when a formal construction is requested.

Statements such as “choose the correct answer” or “test whether an arbitrary program will run forever” are not justified elementary operations. An unbounded search can be an effective partial procedure when a successful witness eventually appears, but it does not become a total decision method merely because each individual search step is mechanical. Unit 6 gives formal limitations, including the halting problem.

Fixed tables of finitely many answers can always be encoded into finite control or tape data. An arbitrary infinite table cannot be assumed available as one finite instruction. Similarly, an ideal device that supplies answers to a noncomputable oracle question has been granted additional information by definition; it is not a counterexample built from ordinary effective operations.

Computability versus stronger physical claims

The ordinary thesis concerns what can be computed by an effective procedure. A physical Church–Turing claim concerns what physical processes can compute, and an extended or efficiency thesis concerns efficient simulation. These are stronger or different claims and should not be silently substituted for the basic thesis.

Quantum algorithms motivate care with efficiency: a different model may improve the time needed for some tasks without computing a non-Turing-computable function. Idealized analog proposals may rely on exact real-number inputs or infinite precision, which are substantive assumptions requiring analysis. The basic thesis does not assert that all physical theories or all conceivable devices can be simulated with the same speed.

Worked example

Assess whether the least-divisor procedure for n ≥ 2 is effective: try d = 2, 3, …, n and return the first d dividing n.

For n = 21, d = 2 leaves remainder 1 and d = 3 leaves remainder 0, so the answer is 3 after two divisibility tests. For n = 7, tests at 2, 3, 4, 5 and 6 fail; d = 7 succeeds, so six tests return 7. Every input n requires at most n − 1 tests because n divides itself.

Binary or unary strings encode n and d. Incrementing d, comparing it with n and testing divisibility by finite repeated subtraction are mechanical operations that can be implemented on a tape. The same finite algorithm handles every n ≥ 2, and the bound proves termination. This is an effective total procedure on its stated domain and hence TM-computable.

Contrast “return yes exactly when an arbitrary encoded TM halts”. That is an output specification, not an implementation. Simulating the target until it halts confirms yes cases but supplies no finite stopping test for every no case. One cannot use that test as an unexplained primitive in the divisor argument or any other alleged algorithm.

Exam traps

  • The thesis concerns effective computation, not every definable function.
  • Equivalence of two formal models is a theorem; the thesis links formality with an informal notion.
  • Termination and efficiency are separate: an effective total procedure can be very slow.
  • An oracle or an arbitrary infinite table is not an ordinary finite mechanical instruction.

5.7 Programming techniques: storage in finite control

Finite control can remember a value chosen from a fixed finite set by using different states. This is useful for carrying a bit, remembering a scanned symbol or recording a phase. It cannot store an arbitrarily long input word without using the tape.

Only a few universities teach this programming technique separately. It also explains why the fixed symbol tuples in Chapter 5.4 can be stored during a multitape simulation.

Compile a bounded register into states

If an algorithm has s control phases and a register with r possible values, use product states (phase, value). There are at most sr combinations before any additional helper states. Two bounded registers with r₁ and r₂ values need at most sr₁r₂ combinations. The bounds are fixed when the machine is built, independent of input length.

Remembering one binary symbol needs two alternatives, such as save0 and save1. Remembering an arbitrary n-bit prefix needs 2ⁿ possible values, which cannot be accommodated by one fixed finite state set for every n. The tape, not a magical control variable, must hold unbounded information. Macro descriptions are legitimate only when they can be expanded to finitely many transitions.

Swap two symbols without losing one

To swap the first two bits of a binary word of length at least two, read the first bit a, preserve it and move right in state save_a. Read the second bit b, write a there and move left in state carry_b. Finally write b into the first cell and halt. The state remembers exactly the symbol needed after its original cell is overwritten.

The output begins with ba and leaves the suffix unchanged. The final head is at position 1. Input words shorter than two symbols must be rejected or excluded by the input contract; otherwise the “second bit” would actually be blank. This is a local transducer, not a general sorting procedure.

A fixed transition table in Python

This code generates ten entries from two-element loops, then runs them on 01. The loop variables build a finite table before execution; they are not unbounded registers secretly added to the TM.

delta = {}
for a in "01":
    delta["start", a] = ("save" + a, a, 1)
    for b in "01":
        delta["save" + a, b] = ("carry" + b, a, -1)
        delta["carry" + b, a] = ("acc", b, 1)
word = "01"
tape = dict(enumerate(word))
state, head, moves = "start", 0, 0
while state != "acc":
    state, written, step = delta[state, tape[head]]
    tape[head] = written
    head += step
    moves += 1
print("output:", "".join(tape[i] for i in range(len(word))))
print("moves:", moves)

Worked example

Dry-run the swap on 01.

MovesStateHeadTape
0start001
1save0101
2carry1000
3acc110

The intermediate tape 00 has lost the original second bit, but carry1 preserves that information until it is written back. The exact output is:

output: 10
moves: 3

There are two first-read entries, four second-read entries and four final-write entries: 10 in total. On 001, the same three moves produce 001 because the first two bits agree; the suffix remains unchanged.

Exam traps

  • The remembered set must have a fixed finite size, independent of input length.
  • Store a symbol before overwriting its last remaining copy.
  • A phase label and a remembered value may both be needed in a product state.

Glossary

Tape alphabet
The finite set of symbols allowed in tape cells, including blank.
Blank
A tape symbol representing an unused cell, distinct from an empty string.
Head
The position at which a tape is currently read and written.
Transition
An elementary update of state, scanned symbol and head position.
Configuration
Complete state, tape content and head position information.
Instantaneous description
A notation for one configuration at a moment in a computation.
Acceptance
Finite arrival at the designated positive halting state.
Rejection
Finite arrival at the designated negative halting state.
Divergence
An infinite computation with no halting outcome.
Recognizer
A machine accepting exactly the members of a language, possibly diverging elsewhere.
Decider
A machine halting with the correct yes/no outcome on every input.
Recursively enumerable
Another name for Turing-recognizable.
Recursive language
Another name for decidable language.
Transducer
A machine computing an output from an encoded input.
Unary encoding
Representation of a nonnegative integer n by n copies of one symbol.
Partial function
A function defined only on a specified subset of inputs.
Invariant
A property preserved across relevant computation steps.
Multitape TM
A machine with a fixed number of independently headed tapes.
Multi-track tape
A tape whose cells store fixed tuples under one shared head.
Nondeterministic TM
A TM whose state-symbol pairs may permit multiple outcomes.
Fair search
Scheduling that eventually reaches every finite computation candidate.
Universal TM
A fixed interpreter for encoded Turing machines and their inputs.
Machine encoding
A finite effectively parseable description of a machine.
Effective procedure
A uniform method built from explicit finite mechanical steps.
Church–Turing thesis
The identification of effective computability with TM computability.
Finite control
The machine’s finite set of control states and transition rules.
Product state
A state combining a control phase with values of bounded registers.
