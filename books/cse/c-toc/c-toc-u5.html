5.1 Turing machine model, notation and instantaneous descriptions

A Turing machine is the simplest machine that reads, writes and moves on an unlimited tape. A finite control holds one state, a head scans one cell, and the tape supplies as much memory as the run needs. This chapter gives the formal definition, shows moves as tables and diagrams, and explains the instantaneous description — the snapshot of tape, state and head that records a run.

You need Unit 1 on alphabets, strings and finite automata: a Turing machine's finite control is a DFA that can also write on a tape.

Finite control, head and tape

A Turing machine has three parts. The finite control holds exactly one state from a finite set Q. The head scans one cell. The tape is a row of cells holding symbols from a finite alphabet Γ; it is unbounded to the right, and every cell past the input holds the blank symbol □.

The tape is the memory. A finite automaton cannot count because it has nowhere to store a count. A Turing machine writes a mark, walks away, and reads it later. That one change takes it from regular languages to everything computable.

Formally a Turing machine is a 7-tuple M = (Q, Σ, Γ, δ, q0, qaccept, qreject). Q is the finite set of states. Σ is the input alphabet; the input string is written on the tape before the run. Γ is the tape alphabet, the symbols that may appear on the tape. δ is the transition function. q0 ∈ Q is the start state. qaccept and qreject are halting states, with qaccept ≠ qreject.

The alphabets are linked: Σ ⊆ Γ, and the blank □ is in Γ but not in Σ, so □ ∉ Σ. An input string never contains a blank; blanks fill unwritten cells.

Transitions: read, write, move

One move is decided by two things only: the current state and the symbol under the head. The transition function has the type

δ : Q × Γ → Q × Γ × {L, R}

Q is the set of states, Γ the tape alphabet, L and R the head directions left and right. The input pair is (state, symbol read); the output triple is (new state, symbol written, direction).

The symbol written replaces the symbol read, so writing the same symbol leaves the tape unchanged. δ is a partial function: it need not be defined for every pair. If δ(q, a) is undefined, the machine halts in state q. That is an ordinary stop, separate from qaccept and qreject.

A transition table has states as rows and tape symbols as columns. A filled cell holds the triple, for example "q1, 1, R"; an empty cell means δ is undefined there. A transition diagram draws one circle per state and one arrow per defined entry, labelled "a → b, R": in state q, reading a, write b, move right, go to p. Entries with the same destination and direction share one arrow.

This machine is deterministic: at most one move is possible in any situation. Section 5.4 adds choices and extra tapes.

Instantaneous descriptions

A snapshot of the tape, the state and the head position is the instantaneous description (ID); some syllabi call it a configuration.

Write the tape as one string and cut it at the head. The ID is α q β. Here α is the cells strictly left of the head, q is the current state, and β is the cells from the scanned cell rightwards, so the first symbol of β is under the head. Blanks right of the head are never written; a head on a blank cell gives β = □. Blanks left of the head stay in α, because they record how far right the head has gone: tape 1 with the head on cell 2 is 1□q, not 1q. If the head is on the leftmost cell, α is empty and the ID starts with q.

α<sub>1</sub> a q b β<sub>1</sub> ⊢ α<sub>1</sub> p a c β<sub>1</sub>

when δ(q, b) = (p, c, L). The head scans b and a is the cell to its left; a, b, c are tape symbols; α1, β1 are strings; q, p are states. Write c over b, move left, and p now sits just before a.

α<sub>1</sub> q b β<sub>1</sub> ⊢ α<sub>1</sub> c p β<sub>1</sub>

when δ(q, b) = (p, c, R). Write c over b, move right, so p sits just after the written symbol.

These rules define the yield relation ⊢. Its reflexive transitive closure ⊢* means zero or more moves. A halting configuration has no next ID: the state is qaccept or qreject, or δ is undefined for the scanned pair. A run is a chain C0 ⊢ C1 ⊢ … ⊢ Ck of IDs ending in a halting configuration; k is the number of moves.

Worked example

Question. A Turing machine M has Q = {q0, q1, q2, qaccept, qreject}, Γ = {0, 1, □}, Σ = {0, 1}, and δ(q0, 0) = (q1, 1, R), δ(q1, 0) = (q2, 0, R), δ(q2, □) = (qaccept, □, L); all other entries are undefined. The input is the string 00. Write the sequence of instantaneous descriptions from the start to the halting configuration and state the number of moves.

  1. Start: cells 0 and 1 hold 0 and 0, the rest are blank, the head is on cell 0, the state is q0. α is empty and β = 00, so the ID is q000.
  2. Apply δ(q0, 0) = (q1, 1, R): write 1 on cell 0, move right to cell 1, state becomes q1. Tape is 10, so the ID is 1q10.
  3. Apply δ(q1, 0) = (q2, 0, R): write 0 on cell 1 (no change), move right to cell 2, state becomes q2. Cell 2 is blank and the head is on it, so β = □ and the ID is 10q2□.
  4. Apply δ(q2, □) = (qaccept, □, L): write □, move left to cell 1, state becomes qaccept. Tape is still 10, so the ID is 1qaccept0.
  5. That ID halts, because qaccept is a halting state. Count the moves: three transitions were applied.

Answer. The run is q000 ⊢ 1q10 ⊢ 10q2□ ⊢ 1qaccept0, and the machine halts after 3 moves.

Exam traps

  • In α q β the state sits immediately before the scanned symbol. Writing q000 as 00q0 puts the head after the input, a different ID.
  • Never drop the scanned cell, even when it is blank: a head on a blank cell gives β = □. Never pad β with blanks to the right.
  • Σ and Γ are not the same set. The blank is in Γ but never in Σ, so an input string never contains □.
  • δ undefined means the machine halts; it does not mean accept. Acceptance needs the state qaccept, as Section 5.2 explains.
  • The triple is ordered (new state, symbol written, direction). Writing happens in the scanned cell before the head moves.
  • The tape is unbounded only to the right. If δ(q, a) = (p, b, L) and the head is on the leftmost cell, the move is illegal: treat δ on that pair as undefined. A correct design never asks for such a move.

Beyond the syllabus

Not for the exam. Real machines have finite memory, so the unbounded tape models "enough tape". Busy-beaver search programs implement these definitions literally, and a machine that visits more distinct IDs than it has configurations can never halt. Undo stacks in editors are practical cousins of the yield relation.

5.2 Language accepted by a Turing machine

A Turing machine M accepts a string w when the run that starts with w on the tape ends in the accept state. The language L(M) is the set of all strings that pass this test. This definition turns a machine into a language recognizer: each input string gets one of three fates, accept, reject, or loop forever. The idea matters because it is the standard link between computation and formal languages, used in parsing, protocol checks, and in the theory of what software can and cannot decide.

You need: instantaneous descriptions and the yield relation from 5.1.

Acceptance by final state

A run of M begins in the start state q0 with input w written on the tape. Each move rewrites one cell, changes state, and moves the head left or right. Write α q β for the instantaneous description: α is the tape left of the head, q is the state, β is the tape from the head rightward. The symbol □ is the blank. The machine accepts w if some sequence of moves from q0w reaches a configuration whose state is qaccept. The tape content at that moment does not matter.

L(M) = { w ∈ Σ* | q<sub>0</sub>w ⊢* α q<sub>accept</sub>β for some α, β }

L(M) is the language of M; Σ* is the set of all strings over input alphabet Σ; q0w is the starting configuration; ⊢* means zero or more moves; qaccept is the accept state; α and β are the tape strings left and right of the head at acceptance.

Acceptance is reaching qaccept, not merely stopping. If the machine halts in another state, it rejects. If no move is defined for the current state and cell, it halts and rejects under the usual convention. If it never reaches qaccept and never halts, it loops. Then w is not in L(M), but M has not rejected w either; the run is unfinished.

Acceptor, decider, and the name of the language

A Turing machine used this way is an acceptor: it may loop on strings outside its language. A decider is stronger: it halts on every input, so every string is either accepted or rejected. Every decider is an acceptor, but an acceptor need not be a decider. The table shows the contrast.

MachineHalts?Language
AcceptorMay loop on some inputsL(M) = accepted strings
DeciderHalts on every inputL(M) = accepted strings; all others rejected

The class of languages accepted by some Turing machine is called recursively enumerable (RE). Some syllabi call L(M) the language of the TM, or say M recognizes L(M). The class accepted by some decider is called recursive. The recursive versus recursively enumerable distinction is developed in Unit 6. Here, keep the operational meaning: L(M) contains exactly the strings on which M reaches qaccept.

This is why acceptance is weaker than deciding. If you simulate M on w and the simulation has not stopped after a long time, you have no proof that w is outside L(M). The machine may still accept later. A decider gives a definite yes or no after finite time.

Checking membership step by step

For a fixed machine and a fixed input, you test membership by simulating the run.

  1. Write w on the tape, set the state to q0, and put the head on the first symbol of w.
  2. Read the current cell symbol a and look up δ(q, a) for the current state q.
  3. If δ(q, a) is undefined, halt and reject.
  4. Apply the move: write the new symbol, change to the new state, and move the head one cell left or right.
  5. If the new state is qaccept, accept. If it is qreject, reject.
  6. Otherwise repeat. If the run never reaches qaccept or qreject, it loops; do not call that a reject.

The order matters in an exam answer. Show the starting configuration, show each rewrite, and stop at qaccept or qreject. A run that ends in qreject is a rejected string. A run that has no next move is also a rejected string. A run that goes on forever gives no decision from the machine; the string is simply not in L(M).

Worked example

Question. A Turing machine M has moves δ(q0,0)=(q0,0,R), δ(q0,1)=(qaccept,1,R), δ(q0,□)=(qreject,□,R). All other moves are undefined. Trace the runs on input 001 and input 000. State whether M accepts each string. Use accept = 1 and reject = 0 in the numerical answer.

  2. Move 1: δ(q0,0)=(q0,0,R). Configuration becomes 0q001. The head is on the second 0.
  3. Move 2: again δ(q0,0)=(q0,0,R). Configuration becomes 00q01. The head is on 1.
  4. Move 3: δ(q0,1)=(qaccept,1,R). Configuration becomes 001qaccept□. The state is qaccept, so 001 is accepted. Numerical value: 1.

  6. Move 1: 0q000. Move 2: 00q00. Move 3: 000q0□. The head is on the blank after the input.
  7. Move 4: δ(q0,□)=(qreject,□,R). Configuration becomes 000□qreject□. The state is qreject, so 000 is rejected. Numerical value: 0.
  8. Final answers: 001 gives 1 (accept); 000 gives 0 (reject).

Exam traps

  • Acceptance is reaching qaccept, not merely stopping. Halting in qreject or with no move is rejection.
  • A loop is not a rejection. If M loops on w, then w ∉ L(M), but M has not rejected w.
  • Do not confuse L(M) with the set of strings on which M halts. L(M) is only the accepted strings.
  • Undefined transition means halt and reject under the usual convention; some definitions use an explicit qreject. Read the definition given in the question.
  • The accept state must be reached. A machine that stops in a non-accepting state has not accepted, even if the tape looks correct.

Beyond the syllabus

Not for the exam. The same definition appears in modern software as a recognizer for a language of valid inputs, such as a parser that may loop on malformed input. Verification tools search for a run that reaches an error state, which is acceptance by a final state in reverse. Researchers study Turing-recognizable languages because they model semi-decision procedures: a yes can be found in finite time, but a no may not. Search for "Turing recognizable", "recursively enumerable language", and "decider versus acceptor" to go further.

5.3 Designing Turing machines; computing integer functions

A Turing machine is designed by writing small routines that scan, mark, compare and shift symbols on the tape. To compute an integer function, the arguments are placed on the tape in unary code, 0^n for the integer n, separated by 1s, and the machine halts with one unary block for the answer. This shows the Turing machine as a computer of functions, not only a language acceptor. The same style of design appears in computability proofs, in compiler and interpreter models, and in any course that treats algorithms as tape operations.

You need 5.1 for transition notation and instantaneous descriptions, and 5.2 for the acceptance test.

Design by four routines

Designing a Turing machine (TM) means writing a finite list of transitions that moves the head and rewrites the tape until the machine reaches the accept state. A large design is built from small routines. Each routine does one job and returns control to a dispatch state.

Four routines cover most exercises. Scan moves the head in one direction until a chosen symbol or a blank appears. Mark overwrites a symbol with a second symbol, say 0 with X, so the machine remembers that this cell was visited. Compare marks a symbol in the first block, scans to the second block, marks a matching symbol there, and repeats. Shift moves a block one cell left or right by carrying symbols in the state.

  1. Fix the tape alphabet and the input code before writing any transition.
  2. Write the high-level routine in words: scan to the separator, mark one symbol, return.
  3. Give each routine its own states and one dispatch state that calls them.
  4. Test the smallest inputs: an empty block, one symbol, two blocks.

State names can also store a few symbols, which reduces tape work; see 5.7.

Unary code for integer functions

An integer function f: N^k → N takes k non-negative integers and returns one. A TM computes f if, started with the arguments on the tape in an agreed code, it halts with f(arguments) on the tape in the same code.

The code used in these exercises is unary. The integer n is written as 0^n: a block of n zeros. Zero is the empty block. The k arguments are separated by single 1s:

0^{n1} 1 0^{n2} 1 ... 1 0^{nk}

n1, n2, ..., nk are the k non-negative integer arguments; each 0^n is a block of n zeros; the 1s are separators.

The output is one unary block 0^{f}. No 1 is left on the tape. Unary code has no place values, so the machine only counts. Addition becomes joining blocks. Some syllabi call the TM a computer of integer functions for this reason.

Successor f(n)=n+1: scan right over the zero block to the first blank, write 0, and halt. On input 00 the machine writes a third 0 and halts with 000.

Addition, equality and copying

Addition f(m,n)=m+n on input 0^m 1 0^n uses two routines. First scan right to the separator 1 and overwrite it with 0. The tape now holds m+n+1 zeros in one block. Second scan right to the blank after this block, step left onto the last 0, and overwrite it with blank. The tape holds m+n zeros.

Why the count is right: the new 0 replaces the separator, which adds one zero (+1), and the erased 0 removes one zero (−1), so the tape holds m+n zeros in total whichever step comes first. Order still matters for position. After the merge, the routine scan right to the blank and step left lands on the true right end of one contiguous block. Erase before the merge when n=0 and the only zero available to erase is the one touching the separator, so the join leaves a blank inside the block and the output is no longer one contiguous unary block.

Equality test f(m,n)=1 if m=n, else 0. Mark one 0 in the left block, scan right, mark one 0 in the right block. Repeat. If both blocks end together, output 0^1; if one ends first, output 0^0 (empty).

Copying f(n)=n needs a second copy of the block. A single-tape outline: mark each original 0 with X from left to right and write a new 0 after a separator; then restore the Xs to 0. Multitape machines make copying direct; see 5.4.

Worked example

Exam traps

  • Unary code is not binary code: the integer 5 is 00000, not 101. Writing a binary numeral on the tape breaks every later count.
  • The output must be one contiguous unary block. Leaving the separator 1 or leaving gaps inside the zeros is wrong even if the number of zeros is correct.
  • In addition, replace the separator 1 by 0 first and erase one 0 from the right end second. The count is m+n in either order, but doing the erase first breaks the block: when n=0 the zero you erase is the one next to the separator, so the merged tape has a blank inside and the answer is not one contiguous unary block.
  • Zero is the empty block 0^0. The input for (0,0) is just the single symbol 1, and the correct output is an empty tape, not one zero.
  • For integer functions the machine must halt with the answer written on the tape. Reaching an accept state without writing the output block does not compute the function.

5.4 Variants: multitape and nondeterministic Turing machines

A plain Turing machine has one tape and one head. Matching 0ⁿ1ⁿ then needs walking back and forth. Two variants remove that friction. A multitape machine has k tapes and k heads. A nondeterministic machine may choose among several moves at one step. Neither adds power: both accept exactly the recursively enumerable languages. They exist for shorter designs, faster algorithms and clean definitions of complexity classes.

You need: the model and instantaneous descriptions from 5.1 and acceptance from 5.2.

A multitape machine has k heads

A multitape Turing machine has k tapes and one head per tape. k is fixed when the machine is built; two or three tapes cover every design you will meet. Each tape is infinite to the right and holds symbols from Γ, which contains blank B. The input is on tape 1; other tapes start blank and serve as scratch. If a head at cell 0 is told to move left, it stays on cell 0.

δ: Q × Γ<sup>k</sup> → Q × Γ<sup>k</sup> × {L, R, S}<sup>k</sup>

Q is the finite state set; Γ is the tape alphabet; Γk is the k-tuple of scanned symbols; {L, R, S} is the direction for each head — L left, R right, S stay.

One step reads state q and the k scanned symbols a₁ … ak. It writes a new symbol on each tape, moves each head, and enters a new state. This is one move, so copying between tapes is cheap.

  • 0ⁿ1ⁿ in one pass: copy zeros to tape 2, then erase one zero per 1.
  • A work tape keeps partial results while tape 1 is reread.
  • Extra tapes give bookkeeping, not power: three tapes accept no new language.

Nondeterministic Turing machine

Nondeterministic: the next move is not unique. δ: Q × Γ → 2Q × Γ × {L, R, S}. Here 2S is the set of all subsets of S. The set may be empty, halting that branch, or contain several triples (q′, b, D).

A run is a path in a tree of configurations. A configuration is the full snapshot from 5.1: state, tape, head position. M accepts w if some run reaches q_accept. M rejects w only when every run halts without q_accept.

Use nondeterminism to “guess and verify”: guess the middle of a string, a maze path, or a factor. The check is deterministic work on the tape. Section 3 shows guesses cost time but add no languages.

Both variants accept the same languages

Theorem: single-tape, multitape and nondeterministic machines accept exactly the recursively enumerable languages. A single-tape machine is a special case. The other direction is a simulation.

  1. Encode k tapes on one tape as T₁#T₂#…#Tk.
  2. Mark each head by a marked copy of the scanned symbol.
  3. One move: sweep right to collect marks, decide, sweep again to write and shift marks.
  4. After t steps the tapes use O(t) cells, so one sweep costs O(t) and the simulation costs O(t²).

For nondeterminism, simulate by breadth-first search of the configuration tree. Keep a queue of configurations on tape 2 and the current one on tape 3. If any branch accepts, the search finds it and M accepts. With b choices per move, depth t has at most 1 + b + b² + … + bt nodes, so the run is exponential in t. If every branch halts without accepting, the search empties its queue and M rejects. If some branch runs forever, the search never stops — allowed, because the language is only required to be recognised on the strings it contains, as in 5.2.

Worked example

Question. Design a two-tape Turing machine M that accepts L = {0ⁿ1ⁿ | n ≥ 1}. Give the transition function, trace the run on w = 0011, and state the final tape contents and number of moves.

  1. Q = {q0, q1, q_accept, q_reject}, Γ = {0, 1, B}, Σ = {0, 1}, start q0. Tape 1 holds 0011; tape 2 is blank.
  2. Phase 1: δ(q0, 0, B) = (q0, 0, 0, R, R). Each 0 is copied to tape 2 and both heads move right.
  3. End phase 1: δ(q0, 1, B) = (q1, 1, B, S, S).
  4. Phase 2: δ(q1, 1, B) = (q1, 1, B, S, L); δ(q1, 1, 0) = (q1, 1, B, R, L). A 1 skips a blank on tape 2, or erases one 0 and moves head 1 right and head 2 left.
  5. Halting: δ(q1, B, B) = (q_accept, B, B, S, S); δ(q1, B, 0) = (q_reject, B, 0, S, S); δ(q0, B, B) = (q_reject, B, B, S, S), rejecting the empty string.
  6. Trace: moves 1–2 copy the two 0s. Tape 1 = 0 0 1 1, head 1 on cell 2 holding 1; tape 2 = 0 0 B, head 2 on cell 2 holding B.
  7. Move 3: δ(q0, 1, B) = (q1, 1, B, S, S). Move 4: δ(q1, 1, B) = (q1, 1, B, S, L), head 2 to cell 1 holding 0.
  8. Move 5: δ(q1, 1, 0) = (q1, 1, B, R, L). Tape 2 = 0 B B; head 1 on cell 3; head 2 on cell 0. Move 6: same rule. Tape 2 = B B B; head 1 on cell 4 holding B; head 2 stays on cell 0, now B, by the convention in Section 1.
  9. Move 7: δ(q1, B, B) = (q_accept, B, B, S, S).

Answer. M accepts 0011. Tape 1 is unchanged 0011; tape 2 has no zeros. The run takes 2n + 3 = 7 moves, and 2n + 3 for every 0ⁿ1ⁿ with n ≥ 1. On strings with more 1s than 0s, e.g. 011, M never halts (head 2 moves left while head 1 stays on a 1), so M recognises L but does not decide it.

Exam traps

  • Variants add no power. Every language is still recursively enumerable.
  • O(t²) is the single-tape simulation cost over t multitape moves; the multitape machine itself runs in t.
  • Nondeterministic acceptance needs one accepting branch. Rejection needs all branches to fail, so the simulation may run forever on rejected strings.
  • k tapes mean k heads. One head cannot read all tapes at once, and heads need not move together.
  • An empty δ set is a dead end for that branch, not a syntax error.

5.5 Universal Turing machine

A universal Turing machine U is one fixed machine that can run any other Turing machine. It reads a coded description of a machine M and an input string w, then simulates M on w step by step. U accepts exactly when M accepts, rejects when M rejects, and loops when M loops. This turns a machine into data and makes one interpreter possible. The idea is used wherever a program reads another program: a C compiler, a Python interpreter, or a virtual machine. Some syllabi call it universality of Turing machines.

You need: the Turing machine model and instantaneous descriptions (5.1), acceptance (5.2), and tape encoding used for variants (5.4).

One fixed machine, many programs

A Turing machine is a finite object. Its states, tape symbols and transition table can be written as a finite string over a fixed alphabet. So a machine M can be treated as data. Write code(M) for a binary encoding of M: a list of its states, its tape symbols, and each transition rule (p, a, q, b, D), with separators between the parts. The input to a universal machine is the pair ⟨M, w⟩, coded as code(M) # w, where # is a delimiter not used inside either part.

⟨M, w⟩ = code(M) # w

code(M) is a finite binary encoding of M's states, tape symbols and transition rules; # is a delimiter that does not occur inside either part; w is the input string to M.

The universal Turing machine U is one fixed machine. Its own finite control never changes. It reads the description of M from its tape, sets up a separate region as M's tape, and then follows M's rules. This is universality: a single machine runs every program. A phone runs UPI, a camera app and a game on the same processor by reading different code; U does the same with different code(M).

The simulation cycle

U stores three things on its tape: the code of M, the current simulated state of M, and the simulated tape of M with a marker for M's head. One cycle of U simulates one move of M.

  1. Read the simulated state p and the symbol a under the simulated head.
  2. Search code(M) for the transition rule that starts with (p, a).
  3. If the rule is (p, a, q, b, D), write b in the simulated cell, change the simulated state to q, and move the simulated head one cell in direction D.
  4. If M halts in its accept state, U enters its own accept state. If M halts in a reject state, or if no rule applies and M is not in an accept state, U rejects.
  5. Otherwise repeat.

The simulated state is a string on U's tape, not a state of U. U has a fixed small set of states for scanning, matching and copying. This is why U's own transition table is finite even when it simulates machines with millions of states. If M never halts, U never finishes the cycle sequence; U loops. It cannot report "M loops" because it never sees the end.

Recognizer, not decider

Let ATM = {⟨M, w⟩ | M accepts w}. U recognizes ATM: on input ⟨M,w⟩ it accepts exactly when M accepts w. The table shows the three possible runs.

Run of MRun of U

A language is recursive (decidable) if some TM halts on every input and answers accept or reject. A language is recursively enumerable (r.e.) if some TM accepts exactly its strings and may loop on strings outside it. U proves ATM is r.e. ATM is not recursive; the proof is in Unit 6, with the halting problem. U is a recognizer, not a decider, for ATM. It simulates M; it does not decide whether M halts.

Worked example

Question. Let M be the Turing machine over {0,1} that accepts strings ending in 1. Its states are q0 (start) and q1 (accept). Transitions: q0,1 → q1,R; q0,0 → q0,R; q1,1 → q1,R; q1,0 → q0,R. Use this convention: M has no separate reject state; it halts when no rule applies. It accepts when it halts in q1. A final state may still have outgoing moves. The universal machine U receives ⟨code(M), 101⟩. Simulate U simulating M on 101. Give the tape after each move, the final state, the number of moves, and whether U accepts.

  1. Initial: U reads code(M) and writes w = 101 on the simulated tape. Tape 101, head on cell 0 (the first 1), state q0, moves = 0.
  2. Move 1: state q0 scans 1. Rule q0,1 → q1,R. Tape 101, head on cell 1 (the 0), state q1, moves = 1.
  3. Move 2: state q1 scans 0. Rule q1,0 → q0,R. Tape 101, head on cell 2 (the last 1), state q0, moves = 2.
  4. Move 3: state q0 scans 1. Rule q0,1 → q1,R. Tape 101, head on cell 3 (blank), state q1, moves = 3.
  5. End: no rule applies to q1 on blank, so M halts in q1. q1 is the accept state, so U accepts. Final state q1, accept flag = 1.

Answer. U makes 3 simulated moves, ends in q1, and accepts; accept flag = 1.

Exam traps

  • A UTM simulates M; it does not decide whether M halts. If M loops, U loops. Do not write "U rejects a looping M".
  • Accept is not the same as halt: M can halt in a non-accept state, and then U must reject.
  • code(M) is data on U's tape, not U's own state table. U's finite control stays fixed for every M.
  • U's language ATM is recursively enumerable, not recursive. Recognizing is weaker than deciding.
  • The encoding needs separators; otherwise state 1 with symbol 11 and state 11 with symbol 1 look the same.

5.6 Church-Turing thesis

The Church-Turing thesis says that every function a human can compute by a finite, exact, mechanical procedure can also be computed by a Turing machine. It matters because it turns the informal word 'algorithm' into a formal object you can analyse. It is used to justify writing an algorithm instead of a full tape-level Turing machine, and to upgrade 'no Turing machine decides this' into 'no algorithm decides this'. The evidence is that lambda calculus, recursive functions and Post systems all define exactly the same class of functions as Turing machines. It is a thesis, not a theorem.

You need 5.1 and 5.3: how a Turing machine runs, and how integer functions are encoded on its tape.

The statement of the thesis

A Turing machine computes an integer function when you start it with the input encoded on the tape, let it run, and it halts with the output encoded on the tape. Chapter 5.3 gives the unary encoding. The function is the rule that maps each input to that output.

The thesis needs one more idea. A function is effectively computable if a person can compute it by following a finite list of exact instructions, using unlimited paper and pencil, and stop in finite time. The instructions must need no insight or guessing. This is an informal idea, not a mathematical definition.

f is effectively computable ⇒ some Turing machine computes f

f is a function from natural-number inputs to a natural-number output; the arrow means 'implies'.

The Church-Turing thesis states that the implication is always true. Every effectively computable function is computable by a Turing machine. An equivalent form says every reasonable model of mechanical computation computes exactly the Turing-computable functions. Some syllabi call it Church's thesis or the Turing hypothesis.

Evidence from independent models

Three independent formal models were built in the same era. Each tried to capture mechanical calculation, and each used a different mechanism.

  • Lambda calculus: terms are built from variables, application and abstraction; computation is substitution and reduction.
  • Recursive functions: functions are built from zero, successor and projection, then closed under composition, primitive recursion and minimization.
  • Post systems: a computation is a sequence of string rewrites using fixed rules.
  • Turing machines: a computation is a sequence of tape reads, writes and head moves.

These models look unrelated. Lambda calculus reduces expressions. Recursive functions build numbers. Post systems rewrite strings. Turing machines move a head. Yet each defines exactly the same class of functions: the Turing-computable functions.

The convergence is strong evidence. A result that one model equals Turing machines is a theorem, proved by simulation. The thesis is the further claim that this class is the whole of effective computability. No routine calculation has been found outside the class.

Thesis, not theorem

A theorem is proved from formal definitions. The Church-Turing thesis relates a formal model to an informal idea. 'Effectively computable' has no formal definition independent of the models. So no proof can compare the two in the way a theorem is proved.

We can prove that lambda calculus and Turing machines define the same functions. That is a theorem about two formal systems. It does not prove that every possible intuitive procedure is covered. One example, or one model, cannot prove the thesis. Evidence is broad: many independent models agree, and generations of algorithms have been simulated by Turing machines.

Use the thesis in two directions. To show a function is computable, give a finite mechanical procedure; the thesis says a Turing machine exists. To show a problem has no algorithm, show no Turing machine decides it; the thesis turns that into 'no effective procedure decides it'. Unit 6 uses this for undecidability.

The thesis is about what can be computed, not how fast. A language or chip is called Turing-complete when it can simulate a Turing machine. That says nothing about running time or memory. Efficiency belongs to complexity theory, not to the thesis.

Exam traps

  • The thesis is not a theorem. Writing 'by the Church-Turing theorem' loses marks; write thesis or hypothesis.
  • One simulation or one example does not prove the thesis. The evidence is the agreement of independent models.
  • 'Effectively computable' means a finite mechanical procedure, not fast or practical. A function can be computable and still need enormous time.
  • Equivalence of two formal models is a theorem. The thesis is the separate claim that the formal class matches the informal idea.
  • A Turing-complete language can simulate a Turing machine, but it does not make every program efficient. Do not mix computability with complexity.

5.7 Programming techniques: storage in finite control

A Turing machine's finite control can hold a small amount of information in the names of its states. Instead of writing a symbol on the tape, the machine moves to a state whose name records that symbol. This saves tape work for bounded memories, such as the last two input bits. It cannot replace the tape for unbounded counts. Only a few universities teach this as a separate programming technique; it is used when designing compact machines and in proofs that add finite memory to a controller.

You need: designing machines with state routines from 5.3.

States can be named for data

The finite control is the state-holding part of a Turing machine. A state is only a name, so the designer can put data into the name. To remember the last two input bits, use four states: q00, q01, q10, q11. The subscripts are the stored bits. No tape cell is written for this memory. The head reads a symbol, moves right, and changes to a state whose name includes the new symbol. This helps when memory is bounded. It is the same memory as a DFA state, now inside a Turing machine; the tape remains free for other work. The state name is data for the controller, not for the tape. For alphabet size m and k remembered symbols, the control needs mᵏ states (m to the power k) to store every combination. Two bits need 2² = 4 states. A state can also hold a tuple, such as qa,b,c, for several small facts. The gain is fewer tape moves and a shorter trace. It cannot grow with input.

How to program with state names

  1. List the bounded facts to remember and the input alphabet.
  2. Make one state for every tuple of facts; name it qtuple.
  3. For qab reading c, go to qbc and move right. The oldest bit drops and c enters.
  4. Keep a separate start state for short inputs and a separate accept state. Do not make q01 accepting, because the machine would halt before the end of the input.
  5. At the blank symbol, go to accept only if the stored tuple is the required one; otherwise go to reject.
  6. Count states as tuples plus start and accept. Test one accepted and one rejected string.
  7. To mark two symbols, use states q0, q1, q2 to count how many marks are done. On each needed symbol, write a mark and go to the next count. This count is bounded; three states cannot count 100 marks. The head movement is still one cell per step. This is a finite memory.

Worked example

Question. A Turing machine must accept strings over {0,1} ending in 01 by storing the last two bits in state names. The memory states are q00, q01, q10, q11. Trace input 1101. The separate start state checks that the input has at least two bits, then enters q00; the trace starts at q00 after that check. Inputs shorter than two bits are rejected by the start state.

No program is needed; the state table is the computation.

  4. Read 1: q01 → q11.

  6. Read 1: q10 → q01. The input ends.
  7. On blank, q01 goes to accept because the last two bits are 0,1. Accept value is 1.

  • Finite states cannot store an unbounded count; use the tape for counts that grow with input.
  • The update is qab on c to qbc, not qac.
  • Remember to add start and accept states to the state count.
  • Do not confuse stored bits with tape symbols; the tape still contains the whole input.

Takeaways

  1. A Turing machine is a finite control with one read/write head on an unbounded tape; one move depends on the state and the scanned symbol.
  2. An instantaneous description αqβ records the whole tape, the state and the head position, so a run is a sequence of IDs linked by ⊢.
  3. A TM accepts a string when its run reaches an accepting state; L(M) is the set of all such strings.
  4. TMs are designed by small state routines, and integer functions are computed using unary tape codes.
  5. Multitape and nondeterministic TMs are convenient variants; they recognize the same languages as the single-tape model.
  6. A universal TM reads a coded description of any TM and simulates it, so one fixed machine can run many programs.
  7. The Church-Turing thesis identifies TM computability with effective computability; it is a thesis, not a theorem.
  8. Storing bounded facts in state names can simplify designs and reduce tape work.

Mark a 0 and move right; Find matching 1 and mark it; Return to left end; Accept when all matched; Show ID trace for 0011.

Apply Design a Turing machine to compute f(n)=n+1 for unary input 1^n. Show the tape before and after the computation. 12 marks

Use unary code; Move to right end; Append one 1; Return or halt with output; Show tape example 111 → 1111.

Apply Design a Turing machine to compute f(n,m)=n+m using unary tape codes. Explain the state routine. 13 marks

Represent n and m as blocks of 1s; Separate blocks by blank or marker; Copy or merge blocks; Erase separators; Show output block 1^(n+m).

Apply Construct a multitape Turing machine for {a^n b^n c^n | n ≥ 1}. Explain how a single-tape TM can simulate it. 14 marks

Use one tape per symbol type; Match counts by moving heads; Accept when all three finish; Describe single-tape simulation with markers; State time cost informally.

Apply Explain storage in finite control. Design a TM that remembers the last symbol read by using state names. 10 marks

Define bounded information in states; Split states by remembered symbol; Show transition table; Explain reduced tape work.

Analyze and evaluate

Analyze Show how a single-tape TM simulates a multitape TM. Discuss the time cost of the simulation. 14 marks

Encode k tapes on one tape with markers; Track virtual head positions; Simulate one multitape move by scanning; State polynomial slowdown; Conclude language equivalence.

Analyze Explain the universal Turing machine. Describe the coding ⟨M,w⟩ and why simulation by U is mechanical. 13 marks

Define U; Encode states, symbols and δ; Input format ⟨M,w⟩; Simulate step by step; Accept iff M accepts w.

Evaluate Evaluate the Church-Turing thesis. Why is it accepted despite not being a theorem? 12 marks

State thesis; Give evidence from many models; Distinguish thesis from proof; Discuss limits and idealisation; Link to UTM and effective procedures.

Analyze Compare recursive and recursively enumerable languages using TM acceptance. Give one example of each type. 12 marks

Define decidable as halting TM; Define RE as TM acceptance; Show decidable ⊆ RE; Give halting problem as RE not decidable; Mention looping on nonmembers.

Glossary

Accepting
A run reaches a state in F.
Accepting state set F
The set of states that make the machine accept; F ⊆ Q.
Alphabet
A finite nonempty set of symbols.
Blank symbol B
A special tape symbol for empty cells; it is usually not in Σ.
Coding ⟨M,w⟩
A finite string that encodes a machine M and an input string w.
Computation
A sequence of instantaneous descriptions linked by yields.
Configuration
A complete snapshot of tape contents, state and head position.
Decidable language
A language accepted by a Turing machine that halts on every input.
Effective procedure
A finite, mechanical, step-by-step method that can be followed without insight.
Halting
The machine stops because no transition applies or because it enters an accepting or rejecting state.
Input alphabet Σ
The set of symbols allowed in input strings; usually Σ ⊆ Γ.
Instantaneous description
A string αqβ that writes a configuration compactly.
Multitape Turing machine
A Turing machine with several tapes and one head per tape.
Nondeterministic Turing machine
A Turing machine whose transition function returns a set of possible moves.
Rejecting
A run halts in a nonaccepting state.
Simulation
One machine imitating the step-by-step behaviour of another.
Start state q0
The state of the machine before any move.
State set Q
The finite set of control states of a Turing machine.
Storage in finite control
Remembering a bounded amount of data in state names rather than on the tape.
Tape alphabet Γ
The set of all symbols a tape cell may hold, including the blank symbol B.
Transition function δ
The rule giving the next state, written symbol and head move.
Turing-recognizable language
A language accepted by some Turing machine; the machine may loop on nonmembers.
Unary representation
Writing integer n as n copies of the symbol 1.
Universal Turing machine
A Turing machine that simulates any coded Turing machine on a coded input.
Yield
The one-step move relation between instantaneous descriptions.
