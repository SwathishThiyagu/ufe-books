2.1 Divide and conquer strategy

Divide and conquer solves a problem of size n by cutting it into smaller instances of the same problem, solving each in the same way, and joining their answers. The cutting stops when an instance is small enough to solve directly. The method exists because many problems get cheaper when cut: sorting n items by comparing every pair takes about n²/2 comparisons, but sorting two halves and merging them takes about n log₂ n. Binary search, merge sort, quick sort, fast multiplication and most parallel programs are built this way.

You need: recursion (a function that calls itself), and the recurrence tools of Unit 1 (Recurrences: substitution and recursion tree methods; Master theorem).

The three steps

  1. Divide: split the instance P into k smaller instances P1, …, Pk of the same problem.
  2. Conquer: solve each smaller instance by the same method. An instance small enough to solve directly is the base case, and it stops the recursion.
  3. Combine: join the k answers into the answer for P.

Algorithms differ in where the work happens. Merge sort divides for free (cut at the middle) and works while combining (merging). Quick sort works while dividing (partitioning around a pivot) and needs no combine step. Horowitz and Sahni write the general shape as a control abstraction, a procedure whose flow is fixed and whose parts change from problem to problem:

Algorithm DAndC(P)
{
    if Small(P) then return S(P);          // base case: solve directly
    else
    {
        divide P into smaller instances P1, P2, ..., Pk, k >= 1;
        apply DAndC to each of these instances;
        return Combine(DAndC(P1), DAndC(P2), ..., DAndC(Pk));
    }
}

Small(P) tests whether P is small enough to solve directly, S(P) is that direct solution, and Combine joins the sub-answers.

The recurrence of divide and conquer

Let T(n) be the time for an instance of size n, and let the smaller instances have sizes n1, …, nk. The control abstraction gives

T(n) = g(n)                              when n is small
T(n) = T(n1) + T(n2) + ... + T(nk) + f(n)  otherwise

where g(n) is the time to solve a small instance directly and f(n) is the time to divide P and combine the answers. In most algorithms of this unit the instance is cut into a pieces of equal size n/b, and the recurrence takes the standard form

T(n) = a T(n/b) + f(n)

with a = the number of smaller instances actually solved, b = the factor by which the size shrinks, and f(n) = the divide-and-combine cost of one call. Its recursion tree has about logb n levels and nlogb a leaves. Whether the top level, the leaves or every level equally carries the most work gives the three cases of the master theorem (Unit 1). When divide and conquer pays off

  • The smaller instances are independent. The plain recursive Fibonacci, F(n) = F(n − 1) + F(n − 2), solves F(n − 2) twice, F(n − 3) three times and so on, so its time grows exponentially. When sub-instances overlap, dynamic programming (Unit 4) stores each answer once.
  • The split is balanced. Halving gives about log₂ n levels; sizes 1 and n − 1 give n levels, quick sort's worst case (Chapter 2.3).
  • Combining is cheap compared with the work the split saves.
  • The base case is not too small. Each call costs time and stack space, so real code switches to a simple method, such as insertion sort (Unit 1), on short pieces.

Independent instances can also run on different cores at once. The cost is the recursion stack: one frame per level, Θ(log n) when the size halves.

Worked example

Question. Write a divide and conquer algorithm that returns the sum of A[i..j]. Trace it on A = [3, 8, 1, 6, 4, 9, 2, 7]. Find (a) the number of additions and (b) the number of calls for n = 8 and for n = 2k. (c) Does the method save work here? (8 marks)

Algorithm Sum(A, i, j)
{
    if (i = j) then return A[i];           // base case: one element
    mid := floor((i + j) / 2);
    return Sum(A, i, mid) + Sum(A, mid + 1, j);
}

(a) Additions. A call of size n makes one addition plus those of its halves: A(n) = 2A(n/2) + 1, A(1) = 0. Unroll for n = 2k:

A(n) = 2A(n/2) + 1
     = 4A(n/4) + 2 + 1
     = 8A(n/8) + 4 + 2 + 1
     ...
     = 2^k A(1) + (2^(k-1) + ... + 2 + 1) = 0 + (2^k - 1) = n - 1

For n = 8: A(8) = 4 + 2 + 1 = 7 additions.

(b) Calls. C(n) = 2C(n/2) + 1 with C(1) = 1, which unrolls to C(n) = 2n − 1: C(8) = 1 + 2 + 4 + 8 = 15 calls, at most log₂ 8 + 1 = 4 on the stack at once.

(c) Saving. None in total work: a loop also makes 7 additions, without 15 calls. The method pays only when the split lowers the total work (sorting, multiplication) or when halves run at once: with 4 cores, the 4 additions of level 2 run together, then 2, then 1, so the sum takes log₂ 8 = 3 rounds instead of 7.

Exam traps

  • In T(n) = aT(n/b) + f(n), a counts the instances actually solved. Binary search cuts the array in two but solves one half, so a = 1, b = 2.
  • A base case that is never reached recurses for ever; check that every call gets strictly smaller. "Divide and conquer is always faster" is also false: see part (c) above.
  • The examiner's favourite: "Differentiate divide and conquer from dynamic programming." Independent sub-instances solved top-down, against overlapping ones each solved once and stored.
  • Levitin calls binary search "decrease and conquer" (Chapter 2.9); Horowitz–Sahni and Cormen et al. call it divide and conquer. Follow your prescribed book.

Analyze A divide step splits n into sizes n/10 and 9n/10 every time, with f(n) = n. Is the algorithm still Θ(n log n)? Explain. 4 marks

2.2 Binary search

Binary search finds a key in a sorted array by comparing it with the middle element and throwing away the half that cannot contain it. Every comparison halves the range, so a sorted list of 10 lakh roll numbers needs at most 20 comparisons, where a scan from the front may need 10 lakh. Dictionaries, database indexes, Python's bisect module and git bisect all use it.

You need: the divide and conquer pattern (Chapter 2.1) and best, worst and average case analysis (Unit 1).

The algorithm

The array A[1..n] is sorted in increasing order and x is the key we look for. The range still in play is A[low..high].

  1. Set low = 1 and high = n.
  2. While low ≤ high: set mid = ⌊(low + high)/2⌋ and compare x with A[mid].
  3. If x = A[mid], return mid. If x < A[mid], the key can only be on the left: high = mid − 1. Otherwise it can only be on the right: low = mid + 1.
  4. When low > high the range is empty: return 0 ("not found").

The recursive form calls itself on one half: T(n) = T(n/2) + 1. The iterative form in C, which indexes from 0:

int binary_search(const int a[], int n, int key, int *probes) {
    int low = 0, high = n - 1;
    *probes = 0;
    while (low <= high) {
        int mid = low + (high - low) / 2;   /* no overflow */
        (*probes)++;
        if (a[mid] == key) return mid;
        if (key < a[mid]) high = mid - 1;
        else              low  = mid + 1;
    }
    return -1;                              /* not present */
}

Best and worst case

A probe is one comparison of x with A[mid] (one three-way comparison: equal, less or greater). The best case is x at the first middle: 1 probe, Θ(1). In the worst case each probe leaves at most ⌊n/2⌋ elements, so

C(n) = C(⌊n/2⌋) + 1,  C(1) = 1   gives   C(n) = ⌊log₂ n⌋ + 1

For n = 12 that is ⌊3.58⌋ + 1 = 4 probes; for n = 106, 20. An unsuccessful search makes ⌊log₂ n⌋ or ⌊log₂ n⌋ + 1 probes. The worst case is Θ(log n).

Average case: the comparison tree

Draw every possible run as a binary tree (Figure 2.2.1): the root is the first mid, and its subtrees are the trees for the lower and upper halves. The n internal nodes (circles) are the elements; the n + 1 external nodes (squares) are the gaps where an unsuccessful search ends. A search that ends at a node of depth d (edges from the root) makes d + 1 probes if it succeeds at a circle and d probes if it fails at a square.

Let I, the internal path length, be the sum of the depths of the circles, and E, the external path length, the sum of the depths of the squares. Then, with every key and every gap equally likely,

S(n) = 1 + I/n          average probes, successful search
U(n) = E/(n + 1)        average probes, unsuccessful search
E    = I + 2n           true for every binary tree with n internal nodes

The last line holds because turning a square at depth d into a circle with two squares below it raises I by d and E by 2(d + 1) − d = d + 2, so E − I grows by exactly 2 per circle. Putting I = E − 2n into S(n) gives

S(n) = (1 + 1/n) U(n) − 1

In binary search's tree all squares lie on two adjacent levels, so U(n) ≈ log₂ n and S(n) ≈ log₂ n − 1. The average is Θ(log n), only about one probe below the worst case, because half of all elements sit on the deepest level. When n = 2k − 1 the tree is complete: level i holds 2i−1 elements found in i probes, so S(n) = [(k − 1)2k + 1]/n and U(n) = k. For n = 7: S = 17/7 ≈ 2.43 and U = 3.

Exam traps

  • The array must be sorted and allow jumping to A[mid] in one step. On unsorted data the answer is silently wrong; on a linked list, reaching the middle alone costs Θ(n).
  • mid = (low + high)/2 overflows a 32-bit int when low + high passes 231 − 1; write low + (high − low)/2. Java's library had this bug for years.
  • Off by one: while (low < high) skips the last candidate, and high = mid instead of mid − 1 can loop for ever.
  • The worst case is ⌊log₂ n⌋ + 1 probes, a whole number: for n = 12 it is 4, not 3.58.
  • C code tests == and then <, so up to two element comparisons per probe; textbooks count one three-way comparison. Say which you count.

2.3 Merge sort and quick sort analysis

Merge sort and quick sort are the two classic divide and conquer sorts. Merge sort cuts the array by position and works while merging the sorted halves; its split is always even, so it takes Θ(n log n) on every input. Quick sort cuts the array by value around a pivot and works while partitioning; its split depends on the pivot, so it takes Θ(n²) in the worst case but about 1.39 n log₂ n comparisons on average, in place. The library sorts of C++, Java and Python are built from these two.

You need: Chapter 2.1, recurrences and the master theorem (Unit 1), and the meaning of a stable sort (equal keys keep their input order).

Merge sort

Algorithm MergeSort(A, low, high)
    if low < high then
        mid := floor((low + high) / 2)
        MergeSort(A, low, mid)
        MergeSort(A, mid + 1, high)
        Merge(A, low, mid, high)

Merge walks pointers i and j along the sorted halves, copies the smaller of A[i] and A[j] into a work array B, copies the rest when one half runs out, then copies B back. Each comparison places one element, so merging sizes p and q takes at most p + q − 1 comparisons and at least min(p, q). Each of the log₂ n levels costs Θ(n):

T(n) = 2T(n/2) + cn        gives  T(n) = Θ(n log n)   (best, worst and average)
Worst-case comparisons:  C(n) = 2C(n/2) + (n − 1),  C(1) = 0
                         C(n) = n log₂ n − n + 1   for n = 2^k   (n = 8: 17)
Best case (sorted input): C(n) = 2C(n/2) + n/2  =  (n/2) log₂ n  (n = 8: 12)

Merge sort needs Θ(n) extra space for B, and it is stable if Merge takes from the left half on ties (A[i] ≤ A[j]).

Quick sort and partition

Quick sort picks a pivot p, here the first element, and partitions: p lands at its final position s, with everything left of s at most p and everything right of s at least p. Then it sorts the two sides recursively; there is no combine step. Hoare's partition scheme, as in Levitin and Horowitz–Sahni, in C:

int partition(int a[], int lo, int hi) {
    int p = a[lo], i = lo, j = hi + 1;
    for (;;) {
        do i++; while (i <= hi && a[i] < p);   /* stop at a value >= p */
        do j--; while (a[j] > p);              /* stop at a value <= p */
        if (i >= j) break;                      /* pointers crossed */
        swap(&a[i], &a[j]);
    }
    swap(&a[lo], &a[j]);                        /* pivot to its final place */
    return j;
}
void quick_sort(int a[], int lo, int hi) {
    if (lo < hi) {
        int s = partition(a, lo, hi);
        quick_sort(a, lo, s - 1);
        quick_sort(a, s + 1, hi);
    }
}

Quick sort analysis: best, worst and average

Partitioning n elements makes about n + 1 comparisons: every element is compared with the pivot, and the two where the pointers cross are compared twice. The total depends on where the pivot lands.

  • Best case: the pivot always lands in the middle. C(n) = 2C(n/2) + n, so C(n) = n log₂ n, Θ(n log n).
  • Worst case: the pivot is always the smallest or largest element, for example an already sorted array with the first element as pivot. One side is empty and the other has n − 1 elements: C(n) = C(n − 1) + (n + 1), C(1) = 0, so C(n) = (n + 1)(n + 2)/2 − 3, which is Θ(n²). For n = 8 that is 42 comparisons.
  • Average case: every position s of the pivot is equally likely, each with probability 1/n.
C(n) = (n + 1) + (1/n) Σ[s=0..n−1] ( C(s) + C(n−1−s) ),   C(0) = C(1) = 0
The two sums hold the same terms, so
  n·C(n) = n(n + 1) + 2[ C(0) + C(1) + ... + C(n−1) ]
Write the same line for n − 1 and subtract:
  n·C(n) − (n − 1)·C(n − 1) = 2n + 2C(n − 1)
  n·C(n) = (n + 1)·C(n − 1) + 2n
Divide by n(n + 1):
  C(n)/(n + 1) = C(n − 1)/n + 2/(n + 1)
Unroll down to C(2)/3 = 1:
  C(n)/(n + 1) = 1 + 2(1/4 + 1/5 + ... + 1/(n + 1))  ≈  2 ln n
  C(n) ≈ 2n ln n ≈ 1.39 n log₂ n

The average is only about 39% above the best case. A random pivot, or the median of the first, middle and last elements, makes the worst case very unlikely on any input (randomized quick sort, Unit 7).

Exam traps

  • Quick sort's worst case comes from a sorted (or reverse-sorted) input when the pivot is the first or last element, not from a "random" input.
  • Merge sort is Θ(n log n) in the best case too; only its comparison count changes (12 against 17 for n = 8).
  • Intermediate arrays depend on the partition scheme. Levitin and Horowitz–Sahni use Hoare's two-pointer scheme with the first element as pivot; Cormen et al. use Lomuto's scheme with the last element. Name your scheme and keep to it.
  • Quick sort is called "in place" but its recursion stack can reach depth n in the worst case; recursing on the smaller side first keeps it at O(log n).

Merge takes the left element on ties, so equal keys keep their order. Partition swaps elements across long distances, so an equal key can jump over another: 5a, 3, 5b ends as 3, 5b, 5a.

Analyze Quick sort makes more comparisons than merge sort on average, yet it is often faster in practice. Why? 4 marks

Its inner loops are short (compare, move a pointer), it sorts in place so it touches less memory and uses the cache well, and it makes few swaps; merge sort copies every element at every level. The 1.39 factor is outweighed by these constants, provided the pivot choice avoids the n² case.

Beyond the syllabus

Production sorts are hybrids. C++ std::sort is usually introsort: quick sort that switches to heapsort when the recursion gets too deep and to insertion sort on small pieces. 2.4 Finding maximum and minimum

The task is to find both the largest and the smallest of n numbers with as few element comparisons as possible. Two separate scans use 2(n − 1) comparisons. The divide and conquer MaxMin of Horowitz and Sahni uses 3n/2 − 2 when n is a power of 2, a saving of a quarter, and no method that works by comparing elements can do better than ⌈3n/2⌉ − 2. It is the standard exam example of divide and conquer reducing the count of the basic operation, and of why it matters which operation you count.

You need: Chapter 2.1 and solving a recurrence by unrolling (Unit 1).

The straightforward method

Algorithm StraightMaxMin(a, n)
    max := min := a[1]
    for i := 2 to n do
        if a[i] > max then max := a[i]
        if a[i] < min then min := a[i]

Every element after the first is compared twice: 2(n − 1) comparisons on every input. Writing the second test as "else if" skips it whenever a new maximum is found: the best case (increasing order) drops to n − 1, but the worst case (decreasing order) stays 2(n − 1).

Divide and conquer MaxMin

Split the range a[i..j] at the middle, find the maximum and minimum of each half, then make two comparisons: the larger of the two maxima and the smaller of the two minima. A range of one element needs no comparison; a range of two needs one. In C, with a counter:

int a[] = {45, 12, 78, 33, 5, 91, 27, 60};
int comps = 0;                                   /* element comparisons */

void max_min(int i, int j, int *mx, int *mn) {
    if (i == j) { *mx = *mn = a[i]; return; }    /* one element  */
    if (i == j - 1) {                            /* two elements */
        comps++;
        if (a[i] > a[j]) { *mx = a[i]; *mn = a[j]; }
        else             { *mx = a[j]; *mn = a[i]; }
        return;
    }
    int mid = (i + j) / 2, mx1, mn1, mx2, mn2;
    max_min(i, mid, &mx1, &mn1);                 /* left half    */
    max_min(mid + 1, j, &mx2, &mn2);             /* right half   */
    comps += 2;                                  /* combine      */
    *mx = (mx1 > mx2) ? mx1 : mx2;
    *mn = (mn1 < mn2) ? mn1 : mn2;
}

Calling max_min(0, 7, &mx, &mn) and printing the results gives:

max = 91, min = 5, comparisons = 10

Counting the comparisons

Let T(n) be the number of element comparisons on n elements:

T(n) = 0                          n = 1
T(n) = 1                          n = 2
T(n) = T(⌈n/2⌉) + T(⌊n/2⌋) + 2    n > 2

For n = 2k, unroll it down to T(2) = 1:

T(n) = 2T(n/2) + 2
     = 4T(n/4) + 4 + 2
     = 2^(k−1) T(2) + (2^(k−1) + ... + 4 + 2)
     = n/2 + (n − 2)
     = 3n/2 − 2

For n = 8 that is 10, against 14 for two scans. The count does not depend on the order of the values, only on n. The lower bound for any comparison-based method is ⌈3n/2⌉ − 2 (an adversary argument, Unit 7 Lower bounds), so MaxMin is optimal when n is a power of 2. The pairing method reaches the bound for every n without recursion: compare the elements in pairs, then only the larger of each pair against max and the smaller against min, 3 comparisons per 2 elements.

The saving has a price. MaxMin makes n − 1 calls for n = 2k (7 for n = 8) and keeps log₂ n frames on the stack. When comparing two elements is as cheap as testing an index, the simple loop runs faster in practice; the method pays when an element comparison is expensive, such as comparing long strings or whole records.

Exam traps

2.5 Strassen's matrix multiplication

Multiplying two n × n matrices by the school method takes n³ scalar multiplications. In 1969 Volker Strassen showed that a 2 × 2 block product needs only seven block multiplications instead of eight. Applied recursively, this gives Θ(nlog₂ 7) ≈ Θ(n2.81) time, the first proof that n³ is not the limit. It is the textbook case of divide and conquer winning by cutting the number of subproblems, a, while paying with extra additions.

You need: matrix multiplication, Chapter 2.1 (T(n) = aT(n/b) + f(n)) and the master theorem (Unit 1).

The school method and the plain block method

For C = AB, each entry cij = ai1b1j + … + ainbnj needs n multiplications and n − 1 additions. With n² entries the total is n³ multiplications and n³ − n² additions: Θ(n³).

A first divide and conquer attempt splits each matrix into four n/2 × n/2 blocks (take n a power of 2):

| C11 C12 |   | A11 A12 |   | B11 B12 |
| C21 C22 | = | A21 A22 | × | B21 B22 |

C11 = A11·B11 + A12·B21      C12 = A11·B12 + A12·B22
C21 = A21·B11 + A22·B21      C22 = A21·B12 + A22·B22

That is 8 multiplications of half-size blocks and 4 additions of half-size blocks: T(n) = 8T(n/2) + Θ(n²). Since nlog₂ 8 = n³ outgrows n², the answer is still Θ(n³). Splitting alone saved nothing; the leaves of the recursion tree (8log₂ n = n³ of them) carry all the work.

Strassen's seven products

Strassen forms seven products of sums and differences of blocks (Horowitz–Sahni name them P, Q, R, S, T, U, V; Cormen et al. use other letters for the same idea):

M1 = (A11 + A22)(B11 + B22)        C11 = M1 + M4 − M5 + M7
M2 = (A21 + A22) B11               C12 = M3 + M5
M3 = A11 (B12 − B22)               C21 = M2 + M4
M4 = A22 (B21 − B11)               C22 = M1 − M2 + M3 + M6
M5 = (A11 + A12) B22
M6 = (A21 − A11)(B11 + B12)
M7 = (A12 − A22)(B21 + B22)

Expanding confirms them: for example M3 + M5 = A11B12 − A11B22 + A11B22 + A12B22 = A11B12 + A12B22 = C12. The count is 7 multiplications and 18 additions or subtractions of n/2 × n/2 blocks (10 to form the factors, 8 to combine). The products keep each A-block on the left and each B-block on the right, so the formulas stay true when the blocks are matrices, whose products do not commute. That is what lets Strassen recurse.

T(n) = 7T(n/2) + 18(n/2)²,   T(1) = 1
a = 7, b = 2: n^(log₂ 7) = n^2.807 outgrows n²  (master theorem, case 1)
T(n) = Θ(n^(log₂ 7)) ≈ Θ(n^2.81)
Scalar multiplications for n = 2^k:  7^k = n^(log₂ 7)

In practice

  • n not a power of 2: pad A and B with zero rows and columns up to the next power of 2 (n = 6 becomes 8), or pad only to an even size at each level.
  • Crossover: the 18 block additions cost more than one saved multiplication for small blocks, so real code stops recursing below a cut-off size and uses the school method there.
  • Costs: extra memory for the temporary sums, and slightly larger rounding errors with floating-point numbers than the school method.
  • Variant: Winograd's form of the algorithm keeps 7 multiplications and needs only 15 additions.

2.6 Long integer multiplication

Multiplying two n-digit numbers the school way takes n² digit multiplications. Anatoly Karatsuba found in 1960 that splitting each number in half needs only three half-size products, not four, giving Θ(nlog₂ 3) ≈ Θ(n1.585). Cryptography (RSA keys run to thousands of bits) and big-integer libraries depend on such methods.

Splitting the numbers

Let x and y have n digits and let m = ⌊n/2⌋. Write x = a·10m + b and y = c·10m + d, where b and d are the last m digits. Then

x·y = ac·10^(2m) + (ad + bc)·10^m + bd

Multiplying by 10m only appends m zeros and additions take Θ(n), so the cost is in the products. With four products ac, ad, bc, bd: T(n) = 4T(n/2) + Θ(n) = Θ(n²). No gain yet.

Karatsuba's three products

Only the sum ad + bc is needed, not ad and bc separately, and

(a + b)(c + d) = ac + ad + bc + bd   so   ad + bc = (a + b)(c + d) − ac − bd

Three products, ac, bd and (a + b)(c + d), plus a few additions and shifts:

T(n) = 3T(n/2) + Θ(n)   gives   T(n) = Θ(n^(log₂ 3)) ≈ Θ(n^1.585)
Digit multiplications for n = 2^k:  3^k  (school method: 4^k = n²)

For n = 1024 digits: 310 = 59,049 digit products against 410 = 1,048,576. In Python:

def karatsuba(x, y):
    if x < 10 or y < 10:
        return x * y                          # one-digit base case
    m = max(len(str(x)), len(str(y))) // 2
    a, b = divmod(x, 10**m)                  # x = a*10^m + b
    c, d = divmod(y, 10**m)
    ac, bd = karatsuba(a, c), karatsuba(b, d)
    mid = karatsuba(a + b, c + d) - ac - bd  # = ad + bc
    return ac * 10**(2*m) + mid * 10**m + bd

print(karatsuba(4721, 3586))                 # prints 16929506

2.7 Maximum subarray problem

Given n numbers, some of them negative, find the contiguous stretch whose sum is largest. If the numbers are a share's daily price changes, the answer is the best period to have held it. Trying every stretch takes Θ(n²) time; divide and conquer takes Θ(n log n); Kadane's scan takes Θ(n).

Divide and conquer

Cut A[low..high] at mid = ⌊(low + high)/2⌋. The best subarray lies in exactly one of three places:

  1. wholly in the left half A[low..mid]: solve it recursively;
  2. wholly in the right half A[mid+1..high]: solve it recursively;
  3. crossing the middle: it contains A[mid] and A[mid+1]. Scan left from mid, keeping the best running sum; scan right from mid + 1 the same way; add the two bests.

Return the largest of the three. A single element is its own answer.

Algorithm MaxCrossing(A, low, mid, high)
    sum := 0; leftBest := −∞
    for i := mid downto low do
        sum := sum + A[i]; if sum > leftBest then leftBest := sum
    sum := 0; rightBest := −∞
    for j := mid + 1 to high do
        sum := sum + A[j]; if sum > rightBest then rightBest := sum
    return leftBest + rightBest

The crossing step touches each element once, Θ(n), so

T(n) = 2T(n/2) + Θ(n)   gives   T(n) = Θ(n log n)   (as merge sort)

  • A subarray is contiguous; the best subsequence (any elements) is simply the sum of the positive numbers.

2.8 Convex hull: Graham's scan and Jarvis march

The convex hull of a set of points in the plane is the smallest convex polygon that contains them all: the shape a rubber band takes when stretched around nails on a board. Games use it to test collisions, map software to draw the boundary of a region, and many geometry algorithms start from it. Graham's scan finds it in O(n log n) time by sorting the points by angle and then scanning once; Jarvis march wraps the points like a gift in O(nh) time, where h is the number of hull corners.

You need: coordinates and slopes, sorting in O(n log n) (Chapter 2.3), and a stack.

The orientation test

Both algorithms need one question answered quickly: going from p to q to r, do we turn left or right? For points p, q, r,

cross(p, q, r) = (q.x − p.x)(r.y − p.y) − (q.y − p.y)(r.x − p.x)

cross > 0 : left turn (counterclockwise)
cross < 0 : right turn (clockwise)
cross = 0 : p, q, r on one line

It uses only integer multiplications, so there are no angles, square roots or rounding errors. For A(3, 0), B(7, 1), C(9, 4): (7 − 3)(4 − 0) − (1 − 0)(9 − 3) = 16 − 6 = 10 > 0, a left turn.

Graham's scan

  1. Take as anchor p0 the lowest point (smallest y; on a tie, smallest x). It must be on the hull.
  2. Sort the other points by the angle each makes with p0, measured counterclockwise from the positive x direction. Comparing two points needs only the sign of a cross product with p0, no angles.
  3. Push p0 and the first sorted point on a stack.
  4. For each next point r: while the point below the top, the top, and r do not make a left turn (cross ≤ 0), pop the top. Then push r.
  5. At the end the stack holds the hull corners in counterclockwise order.

Sorting costs O(n log n). The scan is O(n) although it has a loop inside a loop: each point is pushed once and popped at most once, so all the pops together are at most n. Total: O(n log n).

Jarvis march (gift wrapping)

  1. Start at the leftmost point; it must be on the hull.
  2. From the current corner p, pick any candidate q. For every other point r, if r is to the right of p → q (cross(p, q, r) < 0), make r the candidate. The final q has every point on its left: it is the next corner.
  3. Move to q and repeat until you return to the start.

Each corner costs one pass over the n points, so the time is O(nh). It is fast when the hull has few corners, but when every point is on the hull (points on a circle), h = n and it takes O(n²).

Where divide and conquer comes in

Graham's scan (sort, then scan) and Jarvis march (repeated selection) are not themselves divide and conquer, but syllabi teach them beside two hull methods that are. QuickHull, in Levitin's book, takes the leftmost and rightmost points (both on the hull), splits the rest by the line through them, finds on each side the point farthest from the line (also on the hull), discards the points inside the triangle so formed and recurses on the two outer groups: O(n log n) on typical inputs, O(n²) at worst, much as for quick sort. Merge hull sorts by x, builds the hulls of the left and right halves recursively and joins them along an upper and a lower tangent in O(n): T(n) = 2T(n/2) + O(n) = O(n log n). No comparison-based hull method can beat Ω(n log n) in general, because sorting can be turned into a hull problem (Unit 7, Lower bounds).

Exam traps

  • The sign of cross depends on the order p, q, r: swapping any two flips it. Write the formula once, with p as the pivot, and keep to it.
  • Graham's anchor is the lowest point (leftmost on a tie), not the leftmost point; Jarvis starts from the leftmost. Do not mix them up.
  • Pop on cross ≤ 0, not just < 0, if the answer should list only corners: a point on an edge (cross = 0) is not a corner.
  • Jarvis march is O(nh), not O(n log n); with all points on the hull it is O(n²).

2.9 Decrease and conquer; transform and conquer

Levitin's textbook names two techniques next to divide and conquer. Decrease and conquer solves one smaller instance and extends its answer to the whole. Transform and conquer first changes the instance into one that is easier to solve: a simpler instance, a better representation, or a different problem.

Decrease and conquer

Divide and conquer solves several smaller instances and combines them; decrease and conquer solves one and extends it. There are three kinds:

  • Decrease by a constant (usually 1): solve size n − 1, then add one element. Insertion sort (Unit 1) inserts A[n] into the sorted A[1..n − 1]; topological sorting (Unit 6) removes a vertex with no incoming edge and repeats.
  • Decrease by a constant factor (usually 2): binary search (Chapter 2.2) and fast powering, an = (an/2)² for even n and a·(a(n−1)/2)² for odd n. T(n) = T(n/2) + c gives Θ(log n).
  • Variable-size decrease: the size drop changes from step to step. Euclid's gcd(m, n) = gcd(n, m mod n), and quickselect (partition as in quick sort, then continue only on the side holding the k-th smallest element).

Transform and conquer

  • Instance simplification: presorting. Checking that all elements are distinct takes n(n − 1)/2 comparisons pair by pair, but after sorting, equal elements sit side by side and n − 1 neighbour comparisons settle it: Θ(n log n) in all. Gaussian elimination (to triangular form) is another example.
  • Representation change: store the data differently. A heap gives heapsort (Unit 6); a balanced search tree (AVL, 2-3 tree) keeps searches at Θ(log n); Horner's rule rewrites a polynomial so that evaluation takes n multiplications.
  • Problem reduction: solve a different problem whose answer gives yours. lcm(m, n) = m·n / gcd(m, n); the maximum of f is minus the minimum of −f. Reduction is also the tool of NP-completeness (Unit 7).

Worked example

Question. (a) Check whether 27, 14, 39, 14, 52, 8 are all distinct, by brute force and by presorting, counting comparisons. (b) Compute 313 by decrease by half, counting multiplications. (8 marks)

(a) Brute force compares pairs: 27 with the five others (5 comparisons), then 14 with 39 (6) and 14 with 14 (7): a repeat after 7 comparisons; up to 6·5/2 = 15 if all were distinct. Presorting: sort to 8, 14, 14, 27, 39, 52, then compare neighbours: 8 vs 14 differ, 14 vs 14 equal, so a repeat after 2 comparisons, at most 5. The sort costs Θ(n log n), so the method is Θ(n log n) against Θ(n²).

(b) 13 is odd, so 313 = 3·(36)²; 36 = (33)²; 33 = 3·(31)²; 31 = 3.

3^6  = 27²        =                      729    (1)
3^13 = 3 × 729²   = 3 × 531,441  = 1,594,323    (2)

Total 5 multiplications instead of 12 for 3 × 3 × … × 3. In general about 2 log₂ n against n − 1.

Exam traps

  • Binary search is "decrease by a constant factor" in Levitin and "divide and conquer" in Horowitz–Sahni and Cormen et al. Name the book's term your examiner expects.
  • Decrease by one gives n levels: T(n) = T(n − 1) + n is Θ(n²) (insertion sort's worst case), not Θ(n log n).
  • Presorting pays only for repeated or global questions. For one search in an unsorted array, a Θ(n) scan beats Θ(n log n) sorting plus binary search.

  1. Divide and conquer splits an instance into smaller instances of the same problem, solves them recursively and combines the answers; its time obeys T(n) = aT(n/b) + f(n).
  2. The method pays when the sub-instances are independent, the split is balanced and combining is cheap; with overlapping sub-instances use dynamic programming.
  3. Binary search needs ⌊log₂ n⌋ + 1 probes in the worst case and about one fewer on average; the comparison tree and E = I + 2n give the exact averages.
  4. Merge sort is Θ(n log n) on every input but needs Θ(n) extra space; quick sort is Θ(n²) in the worst case, about 1.39 n log₂ n on average, and in place.
  5. MaxMin needs 3n/2 − 2 comparisons against 2n − 2, and no comparison method can beat ⌈3n/2⌉ − 2.
  6. Strassen (8 → 7 products) and Karatsuba (4 → 3) win by cutting a, the number of sub-instances: Θ(n2.81) and Θ(n1.585), at the price of extra additions that make them slower for small sizes.
  7. The maximum subarray is the best of the left, right and crossing answers, Θ(n log n); Kadane's scan does it in Θ(n).
  8. Convex hulls rest on the sign of one cross product; Graham's scan is O(n log n), Jarvis march O(nh), and QuickHull is their divide and conquer cousin.
  9. Decrease and conquer solves one smaller instance; transform and conquer changes the instance first. Binary search, insertion sort, presorting and heapsort all fit these names.

Glossary

Divide and conquer
Solving a problem by splitting it into smaller instances of itself, solving them recursively and combining the answers.
Control abstraction
A procedure whose flow is fixed and whose parts (Small, S, Combine) change from problem to problem.
Base case
An instance small enough to solve directly; it stops the recursion.
Recurrence
An equation that gives T(n) in terms of T on smaller sizes, such as T(n) = 2T(n/2) + n.
Probe
One comparison of the key with A[mid] in binary search.
Comparison tree
A binary tree of all possible runs of a comparison algorithm; internal nodes are comparisons, external nodes are outcomes.
Internal / external path length
The sum of the depths of the internal nodes (I) or of the external nodes (E); E = I + 2n.
Merge
Combining two sorted lists into one sorted list by repeatedly taking the smaller front element.
Pivot
The element around which quick sort partitions a subarray.
Partition
Rearranging a subarray so that the pivot is in its final place with smaller elements to its left and larger to its right.
Stable sort
A sort that keeps equal keys in their input order.
In-place algorithm
One that needs only a small amount of extra memory beyond the input, apart from the recursion stack.
Lower bound
The least number of basic operations any algorithm of a given kind must use, such as ⌈3n/2⌉ − 2 comparisons for max and min.
Strassen's algorithm
Matrix multiplication with 7 half-size products per level, Θ(n2.81).
Karatsuba's algorithm
Integer multiplication with 3 half-size products per level, Θ(n1.585).
Crossover point
The size below which a simpler method beats a recursive one, so recursion stops there.
Maximum subarray
The contiguous part of an array with the largest sum.
Kadane's algorithm
A single scan that keeps the best sum ending at each position; Θ(n).
Convex hull
The smallest convex polygon containing a set of points.
Orientation test
The sign of a cross product that says whether p → q → r turns left, turns right or is straight.
Graham's scan
A hull algorithm that sorts the points by angle around the lowest point and keeps left turns on a stack.
Jarvis march
Gift wrapping: a hull algorithm that repeatedly picks the next corner with all points on its left; O(nh).
QuickHull
A divide and conquer hull algorithm that recurses on the points outside the edges through the farthest points.
Decrease and conquer
Solving one smaller instance and extending its answer.
Transform and conquer
Changing an instance into a simpler one, another representation or another problem before solving it.
Presorting
Sorting the input first so that a later question (uniqueness, mode, search) becomes easy.
