7.1 Randomized algorithms: Las Vegas and Monte Carlo

A randomized algorithm uses random choices as part of its computation. Its output, running time, or both can depend on those choices even when the input is fixed. Las Vegas and Monte Carlo describe different guarantees, so classify an algorithm by what it promises, not by the presence of a random-number call.

Fix the input and identify the experiment

Write T(x, R) for the running time on input x with random choices R. Expected time means an average over a stated distribution of R. It does not automatically mean an average over easy and difficult inputs. A randomized algorithm may offer a good expected bound for every fixed input, while a deterministic algorithm's average-case analysis may assume that the input itself was drawn from a particular distribution. Chapter 7.3 separates these two experiments.

The mathematical model commonly assumes independent, uniform random choices from a specified finite set. A pseudorandom generator produces a deterministic sequence once its seed is fixed. This is useful for repeating a debugging trace, but rerunning the same seed does not produce independent trials. Practical experiments should record the generator and seed; proofs should state the idealized probability model. Security-sensitive applications additionally need an appropriate source of unpredictability.

Las Vegas: correctness is preserved

A Las Vegas algorithm returns a correct answer whenever it terminates, with running time affected by randomness. The usual useful guarantee also includes almost-sure termination and a bounded expected running time. Randomized quicksort is an example: every pivot choice yields a correct sorted order, but the number of comparisons varies. Its finite-input termination is not in doubt because each recursive problem becomes smaller. Chapter 7.2 derives its expected comparison cost.

Another simple example assumes an array of n positions contains at least one marked entry. Repeatedly inspect a uniformly random position until a mark is found. The returned position is certainly marked. If m positions are marked, each independent inspection succeeds with probability p = m/n. The expected number of inspections is 1/p = n/m. There is no fixed finite upper bound on the number of failed inspections, and the assumption m > 0 is essential: on an unmarked array this procedure never succeeds.

Monte Carlo: bounded work with possible error

A Monte Carlo algorithm has a stated resource bound but may return an incorrect answer with a bounded probability. Limit the sampling search to k independent inspections and return false if none finds a mark. A true result is certain because an actual mark was inspected. A false result can be wrong when marked entries exist. This is one-sided error: false negatives are possible, but false positives are not. Clearly distinguish a Boolean answer from an explicitly inconclusive result.

With success probability p per inspection, the miss probability after k independent inspections is (1 − p)^k. Independence is what permits multiplication. For one mark in four positions and k = 3, the error probability is (3/4)^3 = 27/64, about 0.421875. With k = 10 it becomes (3/4)^10, about 0.056314. These are probabilities for a fixed marked input over fresh random choices, not confidence percentages inferred from one observed run.

Repetition must respect the error direction. For this sampling test, accept if any repetition finds a mark. For a two-sided decision test with success probability strictly greater than one half, independent repetition and majority voting can reduce error, but the proof and bound differ. Blindly multiplying an error probability after an arbitrary voting rule is not justified. State whether each answer can be wrong before choosing an amplification method.

A number-theory application

Some syllabi emphasize randomized primality tests. Miller–Rabin can report a definite compositeness witness or a probable-prime result. For an odd composite input under the standard uniform-base experiment, at most one quarter of bases are strong liars. Thus k independent rounds have false-prime probability at most 4 raised to −k. Four rounds give at most 1/256; this conditional error bound is not a posterior probability that an arbitrary reported number is prime.

Do not transfer that bound to the simpler Fermat test. Composite Carmichael numbers can satisfy the Fermat congruence for every coprime base, so repeated Fermat passes are not governed by the same guarantee. Unit 6 covers modular exponentiation and primality mechanics. Here the important distinction is between an exact witness and a possibly mistaken acceptance, and between a mathematical error guarantee and a particular seeded trace.

Worked example

Use Python 3 to inspect at most three randomly chosen positions of [1, 0, 0, 0]. The single mark is at index 0. A fixed seed provides a reproducible trace: indices 2, 1 and 3 all contain zero, so this run returns False despite the mark. The trace illustrates an allowed error; the 27/64 bound comes from the probability calculation, not from the seed.

from random import Random

def contains_mark(a, k, rng):
    seen = []
    for _ in range(k):
        i = rng.randrange(len(a))
        seen.append(i)
        if a[i] == 1:
            return True, seen
    return False, seen

Exam traps

  • An expected bound is not a worst-case guarantee for every random sequence.
  • Reusing a seed does not create independent repetitions.
  • Las Vegas does not mean merely running until an unverified answer looks plausible.
  • A conditional error bound is not automatically a posterior probability of correctness.

7.2 Randomized quick sort and the hiring problem

Randomness can prevent a fixed input order from consistently causing an unfortunate pivot sequence or arrival order. Randomized quicksort uses random pivots; the hiring problem counts records in a random permutation. Both analyses become simple when total cost is expressed as a sum of indicator variables.

Randomized partitioning

For n distinct keys, quicksort chooses a pivot, compares each other key with it, and recursively sorts the smaller and larger groups. A pivot chosen uniformly among the current keys has a uniform rank in that subproblem, regardless of the original input order. Every pivot choice preserves sorting correctness. Randomization changes the partition sizes and hence the number of comparisons; it does not turn quicksort into a possibly incorrect sorting method.

Unit 2 explains partitioning and the ordinary recurrence. Here let C(n) be expected comparisons, with C(0) = C(1) = 0. Uniform pivot rank gives C(n) = n − 1 + (1/n)Σ[C(q) + C(n − 1 − q)] for q from 0 to n − 1. The n − 1 term counts comparisons during the current partition. The expectation is over pivots for the fixed set of input keys. Repeatedly choosing an extreme pivot still produces quadratic cost in a possible run.

Count compared pairs

Label the keys by their sorted ranks 1 through n. For i < j, define Xᵢⱼ as 1 if keys i and j are compared and 0 otherwise. They meet only if the first pivot selected among ranks i through j is one of the two endpoints. An interior pivot separates them permanently. Each key in that interval is equally likely to be first, so Pr(Xᵢⱼ = 1) = 2/(j − i + 1).

The total comparison count is the sum of these indicators. Linearity of expectation gives E[C] = Σ over i < j of 2/(j − i + 1). Independence between the indicators is unnecessary. Grouping pairs by rank distance produces a harmonic sum and yields 2(n + 1)Hₙ − 4n comparisons, where Hₙ = 1 + 1/2 + … + 1/n. Since Hₙ grows as Θ(log n), expected comparisons are Θ(n log n).

For four keys, the three adjacent pairs contribute 3, the two pairs at distance two contribute 4/3, and the endpoints contribute 1/2. The expected total is 29/6, about 4.833 comparisons. The seeded trace below performs six comparisons: 3 + 2 + 1. A trace exceeding the expectation is entirely consistent with the theorem. Do not describe expected running time as a limit on every run or use a few experiments as a proof of the bound.

Hiring as a record process

Suppose n candidates have distinct quality ranks and appear in a uniformly random permutation. Interview every candidate, hiring only a candidate better than all previous ones. Let Iᵢ indicate that the ith candidate is hired. Among the first i candidates, each is equally likely to be the best, so E[Iᵢ] = 1/i. Therefore the expected number of hires is Hₙ, although the worst order causes n hires.

If one interview costs cᵢ and one hire costs cₕ, the expected total is ncᵢ + cₕHₙ. These symbols denote costs, not candidate indices. The interviews occur regardless of the number of replacements. A random permutation may be achieved by shuffling a known candidate list before processing it; if the arrival process is not random and cannot be changed, the random-permutation assumption needs justification rather than wishful thinking.

Implementation assumptions matter

The Python quicksort uses fresh uniform index choices from a seeded generator, and builds new lists to make the trace easy to inspect. It is a teaching implementation, not an in-place partition. The pairwise comparison derivation assumes distinct keys and one pivot comparison per other key. Many equal keys can cause poor partitions in a two-way version; three-way partitioning handles equality separately. Recursion depth and allocation behaviour require their own analysis and are not automatically bounded by the expected comparison formula.

Worked example

Run the following Python 3 program. Save it as quicksort.py. The recorded pivots are 1, 2 and 4; each line of the trace gives the pivot, lower list and higher list. The algorithm first finishes the left recursive call, then the right recursive call. Every partition excludes the pivot itself from comparison and places it between the two sorted results.

from random import Random

def quicksort(a, rng, trace):
    if len(a) < 2:
        return a[:]
    p = rng.randrange(len(a))
    pivot = a[p]
    low, high = [], []
    for i, x in enumerate(a):
        if i != p:
            (low if x < pivot else high).append(x)
    trace.append((pivot, low[:], high[:]))
    return quicksort(low, rng, trace) + [pivot] + quicksort(high, rng, trace)

trace = []
print(quicksort([4, 1, 3, 2], Random(3), trace))
print(trace)

7.3 Probabilistic and amortized analysis

Probabilistic analysis averages over a specified random experiment. Amortized analysis bounds the total cost of a sequence of operations, even when that sequence is not random. Both can yield a small cost per operation, but they justify that conclusion in different ways.

Three distinct cost questions

Worst-case analysis takes the largest cost among inputs of a given size, under the model being used. Average-case analysis places a probability distribution on inputs and averages the cost over that distribution. Expected analysis of a randomized algorithm can instead fix the input and average over internal random choices. Write the source of randomness next to the expectation; the same symbol E[T] can hide very different assumptions if its probability space is omitted.

For a discrete random variable X, E[X] is the sum of each possible value multiplied by its probability. An indicator is particularly convenient: if I is 1 when an event occurs and 0 otherwise, E[I] is the event's probability. Linearity gives E[X + Y] = E[X] + E[Y] without requiring independence. Independence becomes important when multiplying probabilities or applying some concentration bounds, not when merely adding expectations.

Amortized analysis asks for a bound on the cost of an entire valid operation sequence. A few expensive operations may be paid for by many cheap ones. The bound applies to every sequence covered by the argument; no distribution on sequences is necessary. A dynamic array's append can be linear in the current number of elements on a resizing step while still having constant amortized cost. It is wrong to describe each individual append as worst-case constant time.

Aggregate and accounting methods

Consider an initially empty array with capacity zero. On the first append allocate capacity one. Thereafter, when full, double its capacity and copy the old elements before writing the new element. Count one unit per copied or newly written element. Allocation overhead is omitted from this explicit model; if allocation itself costs proportional to capacity, the asymptotic conclusion remains, but the constants change. Deletion and shrinking are not part of this append-only example.

For m appends, the writes cost m. The copied capacities form 1 + 2 + 4 + … up to a value smaller than m. This geometric sum is less than 2m, so total element work is less than 3m. Dividing by m gives constant amortized cost. The argument includes prefixes that stop immediately after an expensive resize; it does not rely on completing some convenient cycle of future cheap operations.

The accounting method describes the same idea as saved credits. Charge a constant amount for each append, pay its immediate work, and retain enough credit to fund future copies. Credits are a proof device, not additional program instructions. A valid accounting proof must never spend more credit than has been deposited over the considered prefix. Saying that an expensive operation will eventually be compensated is insufficient if the sequence could stop before that compensation occurs.

Potential makes the balance explicit

Let s be the current size and c the capacity. Define potential Φ = 2s − c for states reachable in this append-only doubling process, with Φ = 0 initially. The potential is nonnegative because a nonempty array remains more than half full immediately after expansion and only gets fuller. Let actual cost aᵢ count copies plus the new write. Define amortized cost âᵢ = aᵢ + Φᵢ − Φᵢ₋₁.

For a nonresizing append, aᵢ = 1 and the potential rises by 2, so âᵢ = 3. If a full capacity-c array doubles, it copies c elements and writes one: aᵢ = c + 1. The old potential is c and the new potential is 2, giving âᵢ = c + 1 + 2 − c = 3. The first append from capacity zero has actual cost 1 and potential change 1, so its amortized cost is 2.

Summing makes the intermediate potentials cancel: Σaᵢ = Σâᵢ + Φ₀ − Φₘ. Since Φ₀ = 0 and Φₘ ≥ 0, total actual cost is at most total amortized cost. This telescoping identity is the proof, not merely the choice of a memorable potential formula. If shrinking is added or different occupancy states become reachable, the nonnegativity and per-operation cases must be proved again.

Choose the method for the question

A randomized data structure may need both tools: expected cost for a random structural choice and amortized cost for changes over time. State the order of these claims rather than calling everything average. Also distinguish a throughput guarantee from a latency guarantee. Constant amortized append is useful for total work, but a system with strict response deadlines may still need to avoid a single large copying pause.

Worked example

Use Python 3 to account for eight appends without actually allocating the arrays. At capacities 1, 2 and 4, a full array is copied into a doubled array. The actual costs are 1, 2, 3, 1, 5, 1, 1 and 1, summing to 15. Final size and capacity are both 8, so final potential is 8. The amortized total is 15 + 8 = 23, below the bound 3 × 8 = 24.

7.4 Lower bounds for problems

A lower bound states work that every algorithm for a problem must perform under a specified computation model and guarantee. It is stronger than showing that one particular algorithm can be slow. A useful lower-bound argument names what information an algorithm can obtain and why fewer operations cannot distinguish all required outcomes.

A bound belongs to a problem and a model

An upper bound is established by an algorithm: exhibit a method and prove its resource use. A problem lower bound quantifies over all eligible algorithms. If merge sort takes O(n log n) comparisons and every comparison sort needs Ω(n log n) comparisons in the worst case, the comparison-sorting problem has a tight Θ(n log n) worst-case bound. This does not say that every sorting implementation is optimal or that every input takes that much time.

Specify whether keys are distinct, whether only comparisons are permitted, whether the answer must be exact, and whether the bound concerns worst-case or expected cost. Different models reveal different information per operation. A comparison of two distinct keys has two possible order outcomes. Inspecting a bounded integer's digits or using it as an array index is a different operation, so an information argument based only on binary comparisons does not automatically apply.

Sorting as a decision tree

Represent a deterministic comparison sort on n distinct labelled keys by a binary decision tree. An internal node is the next key comparison; an edge records its outcome; a leaf supplies the sorted order. There are n! possible relative input orders. Correctness requires enough leaves to distinguish them, since two different required permutations cannot share an indistinguishable final decision. A binary tree of height h has at most 2ʰ leaves.

Therefore 2ʰ ≥ n!, and h ≥ ceil(log₂(n!)). The height is the maximum number of comparisons along an input path, so some input requires at least this many comparisons. The factorial's logarithm is Ω(n log n): at least roughly half the factors in n! are at least n/2, giving a lower bound proportional to n log n. Merge sort supplies the matching comparison upper bound from Unit 2.

For n = 4, there are 24 possible orders. Four binary decisions can distinguish at most 16 outcomes; five can distinguish up to 32. Thus some four-key input needs at least five comparisons. This counting argument gives a necessary bound, not a construction of a sorting algorithm with exactly that height for every n. A decision tree must also be realizable by consistent key comparisons, not merely have enough drawn leaves.

Adversaries and certificates of necessity

To find the minimum among n arbitrary distinct values, every nonminimum value must be shown larger than some other value. Otherwise an algorithm could not rule it out as the minimum while preserving the comparison information seen. One comparison can eliminate at most one remaining candidate for minimum. Starting with n candidates and ending with one therefore needs at least n − 1 comparisons. A linear scan meets this bound.

This reasoning can be phrased as an adversary that answers comparisons consistently while keeping as many candidates alive as possible. The adversary is a proof technique, not necessarily an attacker running beside the program. The goal is to show two or more possible inputs remain consistent with the observed information until enough work has been done. An unread input position can similarly defeat an exact unsorted search claiming absence, because a matching item could still occupy that position.

An output-size argument gives another elementary bound: explicitly writing n separate output items requires at least n output actions in a model where one action writes only a bounded number of items. These arguments are useful precisely because their assumptions are transparent. Do not attach Ω(n) to every task that mentions n if the task permits an implicit output or only queries a small portion of the data.

Limits of the conclusion

Counting sort can run in O(n + k) time for integer keys from a range of size k, under the usual indexing model. This does not contradict comparison sorting's lower bound because counting sort uses more than order comparisons. Randomization also needs a carefully stated theorem: the deterministic worst-case tree argument alone does not prove every randomized expected bound. Averaging leaf depths under uniformly random distinct orders can extend the comparison-sorting argument to expected cost for zero-error randomized methods, but the probability space must be specified.

Finally, an exponential search algorithm is only an upper bound on the cost of that algorithm. It is not proof that the problem inherently requires exponential time. The unresolved separation of P and NP in Chapter 7.5 is a central reminder of this distinction. A lower-bound proof must exclude better algorithms, not merely fail to discover one.

7.5 Complexity classes P and NP

P and NP classify decision problems by how efficiently they can be solved or verified. A decision problem asks a yes-or-no question about an encoded input. NP does not mean “not polynomial”; it describes polynomially checkable evidence for yes-instances, or equivalently polynomial-time nondeterministic computation.

Measure the encoded input

Let L be the number of bits in an input encoding. Polynomial time means a bound such as O(Lᵈ) for a fixed constant d. P consists of decision problems solvable by a deterministic polynomial-time algorithm. Reachability is a standard example: given a graph and two vertices, determine whether a path connects them. Unit 6 supplies graph searches that decide it in polynomial time under ordinary graph encodings.

Decision, search and optimization formulations are related but distinct. “Does this graph have a vertex cover of size at most k?” is a decision question. “Find such a cover” is a search question. “Find a smallest cover” is an optimization question. When assigning membership in P or NP, state the decision formulation. A minimum spanning tree algorithm can answer its associated cost-threshold decision problem, but the optimization task is not literally a yes-or-no language.

Numeric encoding matters. A subset-sum dynamic program taking O(nW) table steps, where W is the numeric target, need not be polynomial in the target's binary length. A target requiring b bits may be nearly 2ᵇ, so a W-dependent table can be exponentially large in b. This is called pseudopolynomial time. Unit 4 gives the dynamic-programming idea; here the point is that a polynomial-looking expression in numeric values is not automatically polynomial in input length.

NP certificates and verifiers

A decision problem is in NP if a yes-instance x has a certificate y of length polynomial in |x| that a deterministic polynomial-time verifier accepts, while no certificate makes the verifier accept a no-instance. Both conditions matter. The verifier need not find the certificate. It only checks a supplied candidate and reports whether that candidate establishes the requested property. A failed candidate does not prove that no other valid candidate exists.

For Hamiltonian cycle, the input is a finite graph and the certificate is an ordering of all vertices. Verify that every vertex occurs exactly once and that each consecutive pair, including the last-to-first pair, is an edge. The certificate uses polynomial space, and those checks take polynomial time. Searching all vertex orders may be expensive, but that brute-force search is not part of the verification procedure. Unit 5 covers an exact backtracking search for the same problem.

For subset sum, a certificate can list selected item indices. Verify that the indices are valid and distinct and that their encoded values sum to the target. Binary arithmetic on polynomially many input bits takes polynomial time. The certificate does not need to display every rejected subset. Similarly, for a satisfiable Boolean formula, an assignment to its variables is enough evidence for verification; Chapter 7.7 discusses the formula structure.

Nondeterminism is not a random guess

A nondeterministic machine can be viewed as exploring possible certificate choices, with acceptance defined by the existence of an accepting branch. Its polynomial time bound applies to each branch under the usual model. This is a mathematical acceptance rule, not a claim that real hardware can run exponentially many processors for free. It is also not the same as choosing one random certificate and hoping to be lucky.

A formula might have only one satisfying assignment among 2ⁿ assignments. Uniform random guessing would find that witness with probability 2 raised to −n per attempt. The existence of a short witness therefore does not guarantee that a randomized search will find it quickly. Randomized complexity classes have their own probability guarantees; the Las Vegas and Monte Carlo terminology from Chapter 7.1 should not be substituted for NP membership.

Every problem in P is in NP: a verifier can ignore the certificate and run the polynomial-time decision algorithm. Thus P is a subset of NP. Whether P equals NP remains unresolved. NP membership alone does not prove intractability, and an NP-completeness proof does not establish P ≠ NP. It shows that a polynomial algorithm for that problem would give polynomial algorithms for all problems in NP through reductions.

Read classifications carefully

A polynomial exponent can still be impractically large, and an exponential method can be useful on small or structured inputs. Complexity classes describe asymptotic guarantees rather than a universal stopwatch ranking. Some broad syllabi also mention PSPACE, the class decidable with polynomial workspace. The inclusions P ⊆ NP ⊆ PSPACE are useful context, but drawing them as strictly separated regions would assert unresolved separations.

Problem variants can change the classification. The standard minimum-cost assignment problem has a polynomial algorithm, despite appearing beside hard optimization problems in some lists. A routine n-queens construction problem and a constrained completion variant are not interchangeable. State the input, requested output, encoding and constraints before attaching a complexity label.

Worked example

               for i in range(n))

7.6 Reductions and NP-complete problems

A polynomial-time reduction transforms instances of one decision problem into equivalent instances of another. It transfers algorithms and hardness in opposite verbal directions: an efficient solver for the target would solve the source, so hardness of the source can establish hardness of the target.

Write the arrow and its meaning

For polynomial-time many-one reductions, A ≤ₚ B means there is a polynomial-time computable map f with x in A if and only if f(x) is in B. One target instance is constructed, and its yes-or-no answer is the answer to the original instance. Both directions of the equivalence are required. A map that preserves only yes-instances can accidentally turn a no-instance into a yes-instance and is not enough.

Suppose B has a polynomial-time decision algorithm. To decide A, compute f(x), run that algorithm on f(x), and return its answer. A polynomial-time transformation can output only polynomially many symbols, so a polynomial computation on that output is still polynomial in the original input length. Reductions compose: if A reduces to B and B reduces to C, composing the transformations gives a reduction from A to C.

To prove a new problem B is NP-hard, start with an established NP-hard source A and show A ≤ₚ B. Reducing B to an easy or known-hard problem instead gives an upper-bound relationship and does not establish B's hardness. For NP-completeness, also prove B is in NP. These are separate obligations: a polynomial verifier and a hardness reduction. Never use the desired NP-completeness claim as an unproved premise in its own reduction.

From clique to vertex cover

CLIQUE asks whether an undirected simple graph G has at least k pairwise adjacent vertices. VERTEX COVER asks whether a graph has at most t vertices touching every edge. Start with the known NP-complete CLIQUE decision problem. For 0 ≤ k ≤ n, where n is the number of vertices, construct the complement graph Ḡ and set t = n − k. The complement retains the vertices and has exactly those distinct-vertex pairs that are not edges of G.

If C is a clique in G, no pair within C is an edge of Ḡ. Thus C is an independent set in Ḡ. Every edge of Ḡ must have an endpoint outside C, so S = V minus C is a vertex cover. If |C| ≥ k, then |S| ≤ n − k. This proves that a yes-instance of CLIQUE maps to a yes-instance of VERTEX COVER.

Conversely, if S covers every edge of Ḡ, the remaining vertices C = V minus S cannot contain any Ḡ edge. Every distinct pair in C is therefore an edge of G, making C a clique. If |S| ≤ n − k, then |C| ≥ k. This proves the reverse direction. Constructing the complement by inspecting all unordered vertex pairs takes polynomial work and output space, so the transformation satisfies the size requirement.

VERTEX COVER belongs to NP because a proposed set can be checked for valid vertices, size at most t, and coverage of every edge in polynomial time. Combining that membership proof with the reduction establishes NP-completeness, assuming CLIQUE's established NP-completeness. The small example below illustrates the map, but only the general two-direction argument proves it for all permitted instances.

A second transformation: Hamiltonian cycle to TSP

For a simple undirected graph on n vertices, construct a complete weighted graph on the same vertices. Give an original edge weight 1 and a missing edge weight 2. Ask whether there is a travelling-salesman tour of total weight at most n. A Hamiltonian cycle in the original graph becomes a tour of n weight-1 edges, with total n. Conversely, every tour has n edges of weight at least 1, so a tour costing at most n must use only original edges.

This construction is polynomial and shows hardness of the decision TSP from Hamiltonian cycle. The tour certificate also proves membership in NP for binary-encoded integer weights, so the decision version is NP-complete. Finding the optimum tour is an NP-hard optimization task; do not call an optimization output a decision language without defining its threshold version. The 1-or-2 distances even satisfy the triangle inequality, showing that exact metric TSP can still be hard.

Keep exactness and approximation separate

A yes/no reduction does not automatically preserve approximation ratios. The target solver might return a near-optimal value that is insufficient to distinguish the original threshold cases. Chapter 7.8 deliberately studies approximation guarantees with their own proofs. Similarly, a reduction should construct its target without first solving the source; otherwise the claimed efficient transformation merely hides the difficult computation inside its preparation.

7.7 NP-hard problems and satisfiability (SAT, CNF)

Satisfiability asks whether a Boolean formula has at least one assignment that makes it true. SAT connects logical modelling to complexity theory: a proposed assignment is easy to check, yet finding one in general captures the difficulty of every problem in NP. Formula structure matters, and restricted SAT variants can be easier.

Literals, clauses and assignments

A Boolean variable has value true or false. A literal is a variable x or its negation ¬x. A clause is a disjunction, written with ∨, meaning at least one of its literals must be true. A formula in conjunctive normal form, or CNF, is a conjunction of clauses, written with ∧. Every clause must be satisfied by the same assignment. Satisfying one clause with one assignment and another with a conflicting assignment does not satisfy their conjunction.

The formula (x₁ ∨ x₂) ∧ (¬x₁ ∨ x₂) ∧ (x₁ ∨ ¬x₂) has one satisfying assignment: both variables true. If both are false, the first clause fails. If x₁ is true and x₂ false, the second fails. If x₁ is false and x₂ true, the third fails. An empty clause is false because it has no true literal; a conjunction with no clauses is true. These boundary conventions make algorithms and proofs consistent.

SAT refers to satisfiability of Boolean formulas generally, while CNF-SAT restricts the syntax to CNF. In 3-SAT, each clause has at most three literals under the convention used here. Many texts instead require exactly three literals; short clauses can be padded by repeating literals when repetition is allowed, or handled with small gadgets under stricter conventions. Specify the convention rather than assuming every written three-CNF definition is identical.

NP-hard versus NP-complete

A problem is NP-hard if every problem in NP can be reduced to it under the chosen polynomial reduction notion. It need not itself be in NP. NP-complete means both NP-hard and in NP. The usual use of these definitions concerns decision languages; optimization problems are commonly called NP-hard when efficiently solving them would efficiently solve an NP-hard decision problem. Membership of an optimization output task in NP is not a well-formed classification until a decision version is specified.

SAT is in NP because a Boolean assignment has polynomial length and evaluating a formula under that assignment takes polynomial time. The Cook–Levin theorem establishes that SAT is NP-hard by encoding polynomial-time nondeterministic computations into formulas. Accepting computation histories correspond to satisfying assignments, and the construction has polynomial size. A full computation-tableau proof is beyond this chapter, but its role is important: it supplies a starting complete problem rather than relying on circular claims between examples.

CNF-SAT and 3-SAT are also NP-complete. A standard route uses polynomial-size encodings and clause gadgets, with correctness in both directions. A brute-force solver that tries all 2ⁿ assignments establishes a finite exact algorithm, not an exponential lower bound. If P = NP, every NP-complete decision problem would have a polynomial-time algorithm. If P ≠ NP, no NP-complete decision problem would have one. The chapter does not assume either unresolved alternative.

Preserve satisfiability without blowing up size

Distributing OR over AND can convert formulas into CNF but may produce exponentially many clauses if applied naively. Introducing auxiliary variables for subformula values avoids that expansion. Tseitin-style encodings add clauses constraining each fresh variable to agree with the operation it represents and require the output variable to be true. The result is equisatisfiable: the original formula has a satisfying assignment if and only if the enlarged formula has one, with suitable choices for the fresh variables.

Equisatisfiable does not mean identical truth tables over an unchanged variable set. For example, replace a four-literal clause (a ∨ b ∨ c ∨ d) by (a ∨ b ∨ y) ∧ (¬y ∨ c ∨ d), where y is fresh. If a or b is true, choose y false; if c or d is true, choose y true. In either situation both new clauses can be satisfied. If all four original literals are false, the new clauses require both y and ¬y, which is impossible.

For a concrete assignment a = false, b = false, c = true, d = false, choose y = true. The first new clause becomes false ∨ false ∨ true, and the second becomes false ∨ true ∨ false. Both are true. Setting y false would fail the first clause, showing why the extension variable must be chosen appropriately rather than treated as an unconstrained copy of an original variable.

Useful tractable restrictions

2-SAT restricts clauses to at most two literals and admits polynomial-time algorithms using implication graphs. Horn-SAT restricts each clause to at most one positive literal and is also polynomial-time decidable. These facts do not contradict 3-SAT hardness: restrictions change the permitted instance set. The small two-variable example below is even a 2-CNF formula; it illustrates verification and enumeration, not a hard-instance benchmark. Unit 6's graph methods support the implication-graph approach without needing to re-teach it here.

Worked example

The Python 3 program represents a literal by a nonzero integer: 1 means x₁ and −1 means ¬x₁. An assignment is a tuple indexed from zero, so variable i uses assignment[i − 1]. from itertools import product

clauses = [(1, 2), (-1, 2), (1, -2)]
def satisfies(assignment):
    return all(any(assignment[abs(lit) - 1] == (lit > 0)
                   for lit in clause) for clause in clauses)

for assignment in product((False, True), repeat=2):
    if satisfies(assignment):
        print(assignment)

7.8 Approximation algorithms: vertex cover, TSP, set cover

An approximation algorithm runs in polynomial time and returns a feasible solution with a proved quality bound relative to an optimum. For a minimization problem, a ρ-approximation guarantees cost A ≤ ρ OPT, where OPT is the minimum feasible cost. A useful answer names the ratio, the input assumptions and the lower bound used in its proof.

Guarantees need a reference optimum

A feasible solution satisfies every problem constraint; being cheap is not enough if it fails to cover an edge or visit a city. For positive optimum cost, the ratio A/OPT measures quality. An approximation theorem bounds that ratio for every allowed input, not only the examples tested. A heuristic without such a theorem may perform well, but observed success does not establish a worst-case approximation guarantee.

NP-hardness motivates alternatives to exact optimization, but does not imply that all approximations are easy or equally good. Algorithms for special cases and exact methods from Units 4 and 5 remain useful. Choose between them using input size, structural restrictions, required accuracy and the consequences of failure. Keep optimization accuracy separate from the probability of returning an incorrect result: approximation is not the same concept as Monte Carlo error.

Unweighted vertex cover from a maximal matching

Repeatedly choose an uncovered edge, include both its endpoints in the answer, and delete all edges incident to either endpoint. The chosen edges form a matching because they never share vertices. The matching is maximal when no further edge can be added; it need not be a maximum-cardinality matching. Its endpoint set covers the graph because an uncovered edge at termination would still be available for selection.

Every vertex cover must choose at least one endpoint of every matching edge. Since the matching edges are disjoint, these choices require at least |M| distinct vertices, where M is the matching. The algorithm returns 2|M| vertices, so its size is at most 2 OPT. This proof is for unweighted cover. Taking both endpoints without considering weights does not establish the same weighted guarantee; weighted variants require a different argument, such as local-ratio methods.

Metric travelling salesman

Assume a complete undirected graph with nonnegative symmetric distances satisfying the triangle inequality: d(u,w) ≤ d(u,v) + d(v,w). Compute a minimum spanning tree T, using Unit 3's algorithms. Removing an edge from an optimum tour yields a spanning tree, so weight(T) ≤ OPT. Double the tree edges to obtain a connected graph with even degrees and an Euler walk of cost 2 weight(T).

Shortcut repeated vertices while retaining their first visits, then return to the starting vertex. The triangle inequality ensures that replacing a path segment by a direct edge cannot increase cost. The resulting Hamiltonian tour therefore costs at most 2 weight(T) ≤ 2 OPT. A preorder traversal gives the same standard shortcut construction. Without the metric assumptions, a direct shortcut can be extremely expensive and this proof fails.

Greedy set cover

Let U contain m elements and let the available sets collectively cover U. In unweighted set cover, repeatedly choose the set covering the largest number of currently uncovered elements. If none adds an element while some remain uncovered, the instance is infeasible. For weighted positive-cost sets, the corresponding greedy criterion is cost per newly covered element; choosing only the largest set ignores the weights.

For the unweighted guarantee, let an optimum cover use k sets. When r elements remain, those k optimum sets cover them, so at least one covers at least r/k remaining elements. Greedy covers at least that many. Charge the unit cost of the chosen set equally to its newly covered elements; each is charged at most k/r. Ordering elements by the time they become covered bounds the successive charges by k/m, k/(m−1), and so on, with ties broken arbitrarily within a batch.

Summing gives cost at most kHₘ, where Hₘ = 1 + 1/2 + … + 1/m ≤ 1 + ln m for m ≥ 1. Thus greedy is an Hₘ-approximation. The harmonic bound grows with universe size; it is not a constant factor like the matching-based cover bound. The proofs use different lower bounds and cannot be transferred merely because both problems contain the word cover.

Run the Python 3 vertex-cover program on path 1–2–3–4. It selects edge 12, removes incident edges 12 and 23, then selects 34. The returned cover has four vertices. Second worked example: metric TSP

Use four corners of a unit square with Manhattan distance. The supplied path 0–1–2–3 is an MST: every spanning tree has three edges, each of length at least one, and this tree costs 3. points = [(0, 0), (1, 0), (1, 1), (0, 1)]

    a, b = points[i], points[j]
    return abs(a[0] - b[0]) + abs(a[1] - b[1])

Several syllabi emphasize randomized hiring and quicksort, reducibility, satisfiability, vertex cover and travelling-salesman approximation. Some source lists also contain whole-course laboratory topics; use the relevant earlier unit for those algorithms rather than treating every listed problem as NP-complete.

Remember and understand

Compare Las Vegas and Monte Carlo algorithms with one-sided and two-sided error. 12 marks

Define what is guaranteed about correctness, termination and running time. Use randomized quicksort for Las Vegas and bounded sampling for a one-sided Monte Carlo example. Identify which answer can be wrong and explain how independent repetition reduces that error. Contrast majority voting for a suitable two-sided test. State why a fixed pseudorandom seed permits a reproducible trace but does not establish independence between repeated runs.

Explain probabilistic, average-case and amortized analysis without treating them as synonyms. 12 marks

Specify input distributions separately from internal random choices. Define expectation and the indicator identity E[I] = Pr(I = 1). Explain linearity without an independence assumption. For amortization, bound every permitted operation prefix and identify the actual work model. Use the doubling array to show that a single linear-cost append can coexist with a constant amortized bound.

Explain P, NP, NP-hard and NP-complete using decision formulations. 12 marks

Define polynomial time in encoded input length. Give a polynomial verifier and certificate-length bound for an NP example. State P ⊆ NP and the unresolved equality question. Define NP-hardness through reductions and require NP membership for completeness. Distinguish a TSP threshold question from finding an optimum tour. Do not infer hardness of the standard assignment problem merely from its placement in a syllabus list.

Explain the comparison-sorting lower bound and its limitations. 12 marks

Draw the decision-tree model for distinct keys. Count n! relative orders and at most 2ʰ leaves at height h. Derive h ≥ ceil(log₂(n!)) and the Ω(n log n) asymptotic bound. Explain why this is a worst-case necessity rather than a count for every input. Discuss integer-indexing algorithms as a different model and identify the additional argument needed for randomized expected lower bounds.

Apply

Analyze randomized quicksort and hiring for four distinct ranks. 12 marks

For sorting, use pair indicators with probability 2/(j − i + 1). Sum the distance contributions 3 + 4/3 + 1/2 = 29/6. Trace the seeded six-comparison run and explain why it is consistent with that expectation. For hiring, derive Pr(hire at i) = 1/i and H₄ = 25/12. Trace ranks 3,1,4,2 and identify two hires.

Use the potential method for nine appends to a doubling array. 12 marks

Use Φ = 2s − c, initialized to zero. The first eight appends cost 15 and leave size and capacity 8 with potential 8. The ninth copies 8 and writes 1, costing 9; size becomes 9, capacity 16 and potential 2. Its amortized cost is 9 + 2 − 8 = 3. Actual total is 24, amortized total 26, and their difference is final potential 2.

Construct the CLIQUE-to-VERTEX-COVER reduction and trace a four-vertex instance. 12 marks

Complement the graph and change threshold k to n − k. Show that a clique becomes an independent set in the complement and that its outside vertices cover all complement edges. Prove the reverse implication with the size inequality. For edges 01,02,12,23 and k = 3, obtain complement edges 03,13 and cover {3}. Establish polynomial construction and a polynomial vertex-cover verifier.

Transform a Hamiltonian-cycle instance to a TSP threshold instance. 12 marks

Keep the vertices, add every missing edge, and assign weights 1 to original edges and 2 to added edges. Set threshold n. Prove that an original Hamiltonian cycle has cost n and that any tour of cost at most n must contain only weight-1 edges. Give the polynomial encoding bound. Observe the triangle inequality for 1-or-2 distances and explain why exact metric hardness does not contradict approximate metric tours.

Analyze and evaluate

Evaluate the claim that random guessing makes every NP problem easy. 12 marks

Distinguish existence of a polynomially checkable witness from a lower bound on the fraction of valid witnesses. A unique satisfying assignment among 2ⁿ choices has exponentially small sampling probability. Explain that nondeterministic acceptance is existential, not a probabilistic success guarantee. Contrast this with a sampling algorithm whose per-trial success probability is known and sufficient for a bounded expected runtime.

Prove and compare the vertex-cover and metric-TSP 2-approximation guarantees. 12 marks

For unweighted cover, construct a maximal matching and return both endpoints; prove feasibility and OPT ≥ |M|. For metric TSP, show MST weight ≤ OPT, double tree edges and shortcut repeated visits using the triangle inequality. State both algorithms’ assumptions and give the tight path-cover example. Explain why weighted cover and nonmetric TSP need different arguments rather than inheriting these guarantees automatically.

Explain SAT encodings and the danger of exponential CNF conversion. 12 marks

Define literals, clauses and shared assignments. Explain how naive distribution can expand a formula. Show the fresh-variable replacement of (a ∨ b ∨ c ∨ d) by (a ∨ b ∨ y) ∧ (¬y ∨ c ∨ d), proving both satisfiability directions. Distinguish equisatisfiability from unchanged truth tables. Discuss 2-SAT and Horn-SAT as tractable restrictions without using them to infer tractability of arbitrary 3-SAT.

Derive the greedy set-cover guarantee and compare a concrete greedy solution with optimum. 12 marks

Let an optimum unweighted cover use k sets and let r elements remain. Some optimum set covers at least r/k of them, so greedy charges each newly covered element at most k/r. Sum charges in coverage order to obtain kHₘ. On the six-element example, greedy uses three sets while two suffice, giving ratio 1.5. Compare it with H₆ = 2.45 and explain why one successful trace is not the proof.

Glossary

Amortized cost
A per-operation charge used to bound total cost over every allowed operation sequence.
Approximation ratio
A proved comparison of feasible solution quality with an optimum, under stated assumptions.
Certificate
A polynomial-length candidate witness supplied to a verifier for an NP yes-instance.
Clause
A disjunction of Boolean literals.
CNF
Conjunctive normal form: a conjunction of clauses.
Decision problem
A problem with a yes-or-no answer for each encoded input.
Decision tree
A model recording information-gathering operations and the outcomes that determine later operations.
Equisatisfiable
Two formulas either both have some satisfying assignment or both have none, possibly using different variable sets.
Expected cost
A probability-weighted mean under an explicitly identified random experiment.
Harmonic number
Hₙ = 1 + 1/2 + … + 1/n.
Indicator variable
A variable equal to one when an event occurs and zero otherwise.
Las Vegas algorithm
A randomized method preserving answer correctness while running time depends on random choices.
Literal
A Boolean variable or its negation.
Lower bound
A necessary resource requirement for all eligible algorithms under a stated model and guarantee.
Matching
A set of graph edges with no shared endpoints.
Maximal matching
A matching to which no further edge can be added; it need not have maximum size.
Metric distances
Symmetric distances satisfying the triangle inequality and the usual nonnegativity conditions.
Monte Carlo algorithm
A randomized method with a stated resource guarantee and possible bounded error.
NP
Decision problems with polynomial-length certificates verifiable in deterministic polynomial time.
NP-complete
Both in NP and NP-hard under the specified polynomial reduction notion.
NP-hard
At least as hard as every problem in NP under the specified polynomial reductions.
P
Decision problems solvable in deterministic polynomial time.
Polynomial reduction
An efficiently computed transformation preserving yes/no answers in both directions.
Potential function
A numerical measure of state used to account for stored proof credit across operations.
Pseudopolynomial time
Time polynomial in numeric values that may be exponential in their binary encoding lengths.
SAT
The question of whether a Boolean formula has a satisfying assignment.
Set cover
Choose available subsets whose union is the whole specified universe.
Vertex cover
A set of graph vertices containing at least one endpoint of every edge.
