4.1 Principles of dynamic programming

Dynamic programming (DP) solves an optimisation or counting problem by breaking it into smaller subproblems of the same kind, solving each subproblem once, and storing its answer in a table so that the next time it is needed it is looked up, not recomputed. It pays off when the same subproblems come up again and again, as they do in route planning, spell-checkers, DNA comparison and the decoders inside every phone. Richard Bellman named the method in the 1950s; "programming" here means planning with a table, not writing code.

You need: recurrences and the recursion-tree method (Unit 1), divide and conquer (Unit 2) and the greedy method (Unit 3), which this chapter compares with DP.

Two properties a DP problem must have

Optimal substructure. An optimal solution contains optimal solutions to its subproblems. Bellman's principle of optimality says the same thing for a sequence of decisions: whatever the first decision is, the remaining decisions must be optimal for the state that the first decision leaves behind. Example: if the shortest road from Chennai to Madurai passes through Trichy, its Chennai–Trichy part is itself a shortest Chennai–Trichy road; if it were not, a shorter piece could be swapped in.

Overlapping subproblems. A plain recursive solution meets the same subproblem many times. The Fibonacci numbers show this: F(n) = F(n−1) + F(n−2), with F(0) = 0 and F(1) = 1. The naive recursive function makes 2F(n+1) − 1 calls to find F(n): 15 calls for F(5), 177 for F(10) and 2,692,537 for F(30), although only 31 different values F(0) to F(30) exist. Figure 4.1.1 shows the waste for F(5).

Top-down and bottom-up

  • Memoization (top-down). Keep the natural recursion, but store each answer in a table (the memo) the first time it is computed, and look it up before computing again. Levitin calls this a memory function. Only the subproblems the recursion actually reaches are solved: F(5) now takes 9 calls instead of 15.
  • Tabulation (bottom-up). Drop the recursion. Order the subproblems so that each depends only on earlier ones, and fill the table with loops: F[0] = 0, F[1] = 1, then F[i] = F[i−1] + F[i−2] for i = 2 to n. No recursion stack, no call overhead, and often only the last row or two of the table need be kept.

Both give the same answers and the same asymptotic time. The running time of any DP is the number of distinct subproblems times the work done for one subproblem. For Fibonacci that is (n + 1) × O(1) = O(n), down from the exponential O(1.618ⁿ) of the naive recursion.

The four-step recipe

  1. Characterise the structure of an optimal solution: what is the last (or first) decision, and what smaller problem does it leave?
  2. Define the value recursively: name the state (for example C[a] = fewest coins that make amount a), write the recurrence over every choice for that decision, and fix the base cases.
  3. Compute the values bottom-up, in an order where every value is ready before it is used.
  4. Construct an optimal solution by storing, beside each value, the choice that gave it, then following those choices back from the final state.

Every chapter of this unit follows these four steps; only the state changes. An exam answer that states the steps, the recurrence and the table order earns most of the marks before any number is computed.

Two short sequence problems show the recipe at work. In the longest increasing subsequence, L[i] = 1 + max{L[j] : j < i and a[j] < a[i]}, or 1 when no such j exists, is the length of the longest increasing subsequence that ends at position i; the answer is the largest L[i], found in O(n²). In the maximum-sum contiguous subsequence, best(i) = max(a[i], a[i] + best(i−1)) is the best sum of a block ending at position i, and the answer is the largest best(i), found in O(n). This is Kadane's algorithm; it beats the O(n log n) divide-and-conquer method of Unit 2, Maximum subarray problem.

Worked example

Question. A metro token machine accepts coins of ₹1, ₹5, ₹6 and ₹9. Using dynamic programming, find the fewest coins that make ₹11 and list them. Show that the greedy rule "take the largest coin that fits" fails here. (6 marks)

Step 1: state. C[a] = the fewest coins that make amount a, for a = 0, 1, …, 11. Base case C[0] = 0.

Step 2: recurrence. The last coin used is some c in {1, 5, 6, 9} with c ≤ a, so C[a] = 1 + min{C[a − c]}. Store last[a] = the coin that gave the minimum.

Step 3: fill for a = 1 to 11.

C[a]012341123122
last[a]–11115611915

Two cells in detail. C[8] = 1 + min(C[7], C[3], C[2]) = 1 + min(2, 3, 2) = 3; the ₹9 coin does not fit. C[11] = 1 + min(C[10], C[6], C[5], C[2]) = 1 + min(2, 1, 1, 2) = 2, first reached with the ₹5 coin.

Step 4: trace back. last[11] = 5 leaves ₹6; last[6] = 6 leaves ₹0. Answer: 2 coins, ₹5 + ₹6.

Greedy. It takes ₹9, then ₹1 and ₹1: 3 coins. The largest coin left a remainder (₹2) that only small coins can make. The DP did 11 amounts × 4 coins = 44 checks, O(A·k) for amount A and k coin types. (For the Indian denominations ₹1, 2, 5, 10, 20, 50, 100, 200 and 500, greedy is always optimal: a check of every amount up to ₹2,000 against this DP finds no failure.)

In code this is two nested loops, over a and over the coins; Chapter 4.2 gives a complete C program for the knapsack table.

Exam traps

  • "Dynamic" does not mean anything changes at run time, and DP has nothing to do with dynamic memory allocation. It is table filling.
  • A table gains nothing without overlapping subproblems. "Why is merge sort not dynamic programming?" is a favourite two-mark question: its subproblems never repeat.
  • Time is states × choices per state, not just the table size: coin change has 12 states but tries 4 coins in each.
  • Not every optimisation problem has optimal substructure. The longest simple path between two vertices does not: the two halves of a longest path can share vertices, so they cannot be solved separately.
  • A memoized function needs a "not yet computed" marker (such as −1) that no real answer can take; using 0 as the marker breaks problems where 0 is a valid answer.

4.2 0/1 knapsack problem

In the 0/1 knapsack problem you have n items, each with a weight and a value, and a bag that holds at most W kilograms. You must choose which items to pack, each one whole or not at all, so that the total value is as large as possible. The greedy "best value per kilogram first" rule that solves the fractional knapsack of Unit 3 fails here, and dynamic programming fixes it with a table of n + 1 rows and W + 1 columns. The same model fits cargo loading and picking projects within a budget.

You need: the four-step recipe of Chapter 4.1, and Unit 3, Fractional knapsack problem, for the greedy version.

The problem and its state

Item i has weight wᵢ (kg) and value vᵢ (₹). Let xᵢ = 1 if item i is packed and 0 if not. Maximise Σ vᵢxᵢ subject to Σ wᵢxᵢ ≤ W. Trying all subsets costs 2ⁿ checks: 2³⁰ is over a billion for just 30 items.

The DP state is V[i][w] = the best value using only items 1 to i with capacity w. Look at the last decision, item i:

V[0][w] = 0  and  V[i][0] = 0                       (no items, or no room)
V[i][w] = V[i−1][w]                         if wᵢ > w   (item i too heavy)
V[i][w] = max( V[i−1][w],  vᵢ + V[i−1][w − wᵢ] )   if wᵢ ≤ w

The first term skips item i and keeps the best of the first i − 1 items. The second packs item i, earns vᵢ, and leaves capacity w − wᵢ for the first i − 1 items. Each item is used at most once because both terms look only at row i − 1. The answer is V[n][W].

Filling the table and reading the answer

  1. Fill row 0 and column 0 with zeros.
  2. For i = 1 to n and w = 0 to W, apply the recurrence; row i needs only row i − 1.
  3. The best value is V[n][W].
  4. Trace back from i = n, w = W: if V[i][w] ≠ V[i−1][w], item i was packed, so record it and set w = w − wᵢ; otherwise item i was skipped. Move to i − 1 and repeat until i = 0.

Worked example

Question. A delivery rider's bag holds 6 kg. Four parcels wait, with weights and delivery fees: item 1 (3 kg, ₹25), item 2 (2 kg, ₹20), item 3 (1 kg, ₹15), item 4 (4 kg, ₹45). Which parcels earn the most? Solve by dynamic programming and compare with greedy by fee per kilogram. (8 marks)

Table. Rows i = 0 to 4, columns w = 0 to 6; the full table is Figure 4.2.1. Some cells in detail:

  • V[2][5] = max(V[1][5], 20 + V[1][3]) = max(25, 20 + 25) = 45.
  • V[3][6] = max(V[2][6], 15 + V[2][5]) = max(45, 15 + 45) = 60.
  • V[4][4] = max(V[3][4], 45 + V[3][0]) = max(40, 45 + 0) = 45.
  • V[4][6] = max(V[3][6], 45 + V[3][2]) = max(60, 45 + 20) = 65.

Trace back. V[4][6] = 65 ≠ V[3][6] = 60: item 4 packed, w = 6 − 4 = 2. V[3][2] = 20 = V[2][2]: item 3 skipped. V[2][2] = 20 ≠ V[1][2] = 0: item 2 packed, w = 2 − 2 = 0. V[1][0] = 0 = V[0][0]: item 1 skipped.

Answer: items 2 and 4, weight 2 + 4 = 6 kg, fee ₹20 + ₹45 = ₹65.

Greedy by ₹/kg. Ratios: item 1 8.33, item 2 10, item 3 15, item 4 11.25. Greedy packs item 3 (1 kg), then item 4 (5 kg used); item 2 would make 7 kg and item 1 would make 8 kg, so it stops at ₹15 + ₹45 = ₹60.

The table and trace-back in C:

#include <stdio.h>

int max(int a, int b) { return a > b ? a : b; }

int main(void) {
    int n = 4, W = 6;
    int wt[] = {0, 3, 2, 1, 4};      /* item i at index i */
    int val[] = {0, 25, 20, 15, 45};
    int V[5][7];
    for (int i = 0; i <= n; i++)
        for (int w = 0; w <= W; w++) {
            if (i == 0 || w == 0) V[i][w] = 0;
            else if (wt[i] > w)    V[i][w] = V[i-1][w];
            else V[i][w] = max(V[i-1][w], val[i] + V[i-1][w - wt[i]]);
        }
    printf("best value = %d\nitems:", V[n][W]);
    for (int i = n, w = W; i > 0; i--)
        if (V[i][w] != V[i-1][w]) { printf(" %d", i); w -= wt[i]; }
    printf("\n");
    return 0;
}

Complexity, and why it is called pseudo-polynomial

The table has (n + 1)(W + 1) cells and each takes O(1) time, so the time is Θ(nW): 5 × 7 = 35 cells in the example. The table needs Θ(nW) space, or only Θ(W) if you keep one array and run w from W down to wᵢ, so that V[w − wᵢ] still holds the previous row's value.

Θ(nW) looks polynomial but is not: W is a number written in about log₂W bits, so the time grows exponentially with the length of the input. With W = 10⁹ the table is useless. Such an algorithm is called pseudo-polynomial. The decision version of 0/1 knapsack is NP-complete (Unit 7), so no truly polynomial algorithm is known.

Two other forms in Indian textbooks

Set method (Horowitz–Sahni). Keep a list Sⁱ of (value, weight) pairs that the first i items can reach. S⁰ = {(0, 0)}; Sⁱ is Sⁱ⁻¹ merged with Sⁱ⁻¹ shifted by (vᵢ, wᵢ). Drop pairs heavier than W, and purge any pair (v₁, w₁) dominated by another (v₂, w₂) with v₂ ≥ v₁ and w₂ ≤ w₁. Here S¹ = {(0, 0), (25, 3)} and S² = {(0, 0), (20, 2), (25, 3), (45, 5)}; the final S⁴ = {(0, 0), (15, 1), (20, 2), (35, 3), (45, 4), (60, 5), (65, 6)}, exactly the distinct values of row 4.

Memory functions (Levitin). Fill the table top-down from V[n][W], with every cell set to −1 at the start, computing a cell only when a call needs it.

Exam traps

  • Greedy by value/weight is optimal only for the fractional knapsack. For 0/1, give a counter-example like the one above.
  • In the one-array version, w must run downward. Running it upward lets an item be packed twice, which solves the unbounded knapsack instead.
  • In the trace-back, compare with the cell directly above, V[i−1][w], and subtract wᵢ from w only when the item is taken.
  • Do not call Θ(nW) polynomial. Examiners want the word pseudo-polynomial and the reason (W is a value, not an input size).
  • Check wᵢ ≤ w before reading V[i−1][w − wᵢ]; a negative column index is a classic program bug.

4.3 Matrix chain multiplication

Multiplying a p × q matrix by a q × r matrix takes p·q·r scalar multiplications. A chain A₁A₂…Aₙ can be multiplied in any order, because matrix multiplication is associative, and the order can change the work by a large factor. The matrix chain multiplication problem finds the parenthesization that needs the fewest scalar multiplications. Numerical libraries, graphics pipelines that combine transforms, and database query planners all face this ordering question.

You need: Chapter 4.1. Strassen's method in Unit 2 speeds up one product; this chapter chooses the order of many products, which is a separate question.

Why the order matters

Take A (2 × 30), B (30 × 4) and C (4 × 20).

  • (AB)C: AB costs 2·30·4 = 240 and gives a 2 × 4 matrix; multiplying it by C costs 2·4·20 = 160. Total 400.
  • A(BC): BC costs 30·4·20 = 2,400 and gives 30 × 20; then A times it costs 2·30·20 = 1,200. Total 3,600, nine times more.

The number of ways to parenthesize n matrices is P(1) = 1 and P(n) = Σ P(k)·P(n − k) for k = 1 to n − 1. These are the Catalan numbers 1, 1, 2, 5, 14, 42, …; ten matrices already have 4,862 orders, and the count grows roughly like 4ⁿ. Trying them all is hopeless; DP needs only Θ(n³) work.

The recurrence

Write the dimensions as p₀, p₁, …, pₙ, so that Aᵢ is p₍ᵢ₋₁₎ × pᵢ. Let m[i][j] = the fewest scalar multiplications to compute Aᵢ…Aⱼ. The last multiplication splits the chain at some k: (Aᵢ…Aₖ)(Aₖ₊₁…Aⱼ). The left part is a p₍ᵢ₋₁₎ × pₖ matrix and the right part is pₖ × pⱼ, so the final product costs p₍ᵢ₋₁₎·pₖ·pⱼ. Each part must itself be computed in its cheapest way (optimal substructure), giving

m[i][i] = 0
m[i][j] = min over i ≤ k < j of { m[i][k] + m[k+1][j] + p(i−1)·p(k)·p(j) }    for i < j
s[i][j] = the k that gives the minimum

m[i][j] needs only shorter chains, so the table is filled by chain length L = j − i + 1 = 2, 3, …, n: diagonal by diagonal, above the main diagonal. The answer is m[1][n], and s tells where to split.

The algorithm and its complexity

MATRIX-CHAIN-ORDER(p, n)
  for i = 1 to n:  m[i][i] = 0
  for L = 2 to n                          // chain length
      for i = 1 to n − L + 1
          j = i + L − 1;   m[i][j] = ∞
          for k = i to j − 1
              q = m[i][k] + m[k+1][j] + p[i−1]·p[k]·p[j]
              if q < m[i][j]:  m[i][j] = q;  s[i][j] = k

PRINT-PARENS(s, i, j)
  if i == j:  print "A" i
  else:  print "(";  PRINT-PARENS(s, i, s[i][j]);  PRINT-PARENS(s, s[i][j]+1, j);  print ")"

For chain length L there are n − L + 1 chains and L − 1 splits each, so the innermost line runs Σ (n − L + 1)(L − 1) = (n³ − n)/6 times: 10 times for n = 4 and 165 for n = 10. The time is Θ(n³) and the m and s tables take Θ(n²) space.

Worked example

Question. Find the optimal parenthesization of A1 (5 × 4), A2 (4 × 6), A3 (6 × 2), A4 (2 × 7) and the number of scalar multiplications it needs. (10 marks)

Dimensions. p = (p₀, p₁, p₂, p₃, p₄) = (5, 4, 6, 2, 7). All m[i][i] = 0.

L = 2. m[1][2] = 5·4·6 = 120; m[2][3] = 4·6·2 = 48; m[3][4] = 6·2·7 = 84 (only k = i is possible).

L = 3.

  • m[1][3]: k = 1 gives 0 + 48 + 5·4·2 = 88; k = 2 gives 120 + 0 + 5·6·2 = 180. So m[1][3] = 88, s[1][3] = 1.
  • m[2][4]: k = 2 gives 0 + 84 + 4·6·7 = 252; k = 3 gives 48 + 0 + 4·2·7 = 104. So m[2][4] = 104, s[2][4] = 3.

L = 4. m[1][4]: k = 1 gives 0 + 104 + 5·4·7 = 244; k = 2 gives 120 + 84 + 5·6·7 = 414; k = 3 gives 88 + 0 + 5·2·7 = 158. So m[1][4] = 158, s[1][4] = 3.

Read the order. s[1][4] = 3 splits into (A1A2A3)·A4; s[1][3] = 1 splits A1A2A3 into A1·(A2A3). Answer: ((A1(A2A3))A4), 158 scalar multiplications.

Compare. Left to right, ((A1A2)A3)A4 costs 120 + 60 + 70 = 250; right to left, A1(A2(A3A4)) costs 84 + 168 + 140 = 392. The best order saves 37% over the plain left-to-right one.

Exam traps

  • Aᵢ is p₍ᵢ₋₁₎ × pᵢ. The cost term is p₍ᵢ₋₁₎·pₖ·pⱼ; writing pᵢ·pₖ·pⱼ is the most common slip.
  • k runs from i to j − 1, not to j.
  • m counts scalar multiplications. The number of matrix multiplications is always n − 1, whatever the order.
  • The algorithm never multiplies a matrix; it only chooses the order. Its Θ(n³) is in the number of matrices, not their size.
  • Fill by diagonals (chain length), not row by row from the top: m[1][3] needs m[2][3], which a top-down row order has not filled yet.

4.4 Longest common subsequence

A subsequence of a string keeps the order of its characters but may skip some: "ONE" is a subsequence of "LONGEST" (L-O-N-G-E-S-T). The longest common subsequence (LCS) of two strings X and Y is the longest string that is a subsequence of both. Its length measures how alike two sequences are, so LCS sits behind file-comparison tools such as diff, DNA and protein comparison, and plagiarism checkers. This chapter's table is that example.

You need: the four-step recipe of Chapter 4.1.

Terms and the brute-force cost

Let X = x₁x₂…xₘ and Y = y₁y₂…yₙ. The prefix Xᵢ is x₁…xᵢ, and X₀ is the empty string. A subsequence may skip characters; a substring may not (it is a contiguous block). X has 2ᵐ subsequences, and checking each against Y takes O(n) time, so brute force costs O(n·2ᵐ): about 3 × 10¹⁰ steps for two 30-letter strings.

Optimal substructure and the recurrence

Compare the last characters. If xₘ = yₙ, that character can end an LCS, and the rest is an LCS of Xₘ₋₁ and Yₙ₋₁. If xₘ ≠ yₙ, an LCS cannot use both last characters, so it is the longer of an LCS of (Xₘ₋₁, Y) and an LCS of (X, Yₙ₋₁). With c[i][j] = the length of an LCS of Xᵢ and Yⱼ:

c[i][j] = 0                              if i = 0 or j = 0
c[i][j] = c[i−1][j−1] + 1                if i, j > 0 and xᵢ = yⱼ     (arrow ↖)
c[i][j] = max( c[i−1][j], c[i][j−1] )    if i, j > 0 and xᵢ ≠ yⱼ     (arrow ↑ or ←)

Beside each value, store an arrow b[i][j] that says where it came from. Fill row by row, left to right; every cell needs only its upper, left and upper-left neighbours. The length is c[m][n]; the string is read by following the arrows back from (m, n) and collecting the letter at every ↖.

LCS-LENGTH(X, Y)
  for i = 0 to m:  c[i][0] = 0
  for j = 0 to n:  c[0][j] = 0
  for i = 1 to m
      for j = 1 to n
          if X[i] == Y[j]:              c[i][j] = c[i−1][j−1] + 1;  b[i][j] = "↖"
          else if c[i−1][j] ≥ c[i][j−1]:  c[i][j] = c[i−1][j];      b[i][j] = "↑"
          else:                          c[i][j] = c[i][j−1];      b[i][j] = "←"

Worked example

Question. Find the longest common subsequence of X = STONE and Y = LONGEST using dynamic programming. Show the table and the trace-back. (8 marks)

Complexity and space

There are m·n cells, each O(1), so the time is Θ(mn): 35 cell computations here. The c and b tables take Θ(mn) space. If you need only the length, keep two rows and the space drops to Θ(min(m, n)). Hirschberg's divide-and-conquer method recovers the string itself in linear space, at about twice the time.

Edit distance, a close relative

The edit distance between X and Y is the fewest single-character insertions, deletions and substitutions that turn X into Y. With D[i][j] for the prefixes Xᵢ and Yⱼ:

D[i][0] = i,   D[0][j] = j
D[i][j] = min( D[i−1][j] + 1,                    delete xᵢ
               D[i][j−1] + 1,                    insert yⱼ
               D[i−1][j−1] + (0 if xᵢ = yⱼ else 1) )   keep or substitute

SUNDAY becomes SATURDAY in 3 edits: insert A, insert T, substitute N → R. When only insertions and deletions are allowed, the distance is m + n − 2·LCS: for STONE and LONGEST that is 5 + 7 − 2 × 3 = 6.

Exam traps

  • Subsequence is not substring. The longest common substring uses c[i][j] = c[i−1][j−1] + 1 on a match and 0 otherwise, and its answer is the largest cell, not the corner.
  • On a match, take the diagonal value + 1, not max(up, left) + 1.
  • The table is (m + 1) × (n + 1). Forgetting row 0 and column 0 shifts every index.
  • The LCS length is unique, but the string need not be: breaking ties with ← instead of ↑ can print a different LCS of the same length. Any one is accepted if the table is right.
  • The trace-back collects letters from the end; write them in reverse.

4.5 Optimal binary search trees

A binary search tree (BST) keeps keys in sorted order, so a search follows one path down from the root. When some keys are searched far more often than others, the best tree is not simply the balanced one: popular keys should sit near the root. An optimal binary search tree (OBST) is the BST with the smallest expected number of comparisons for given search probabilities. It suits static word lists that are searched again and again, such as a compiler's keyword table or an offline dictionary.

You need: binary search trees from your data structures course, and the interval table of Chapter 4.3, which this chapter reuses.

The cost of a BST

Let the keys be k₁ < k₂ < … < kₙ, and let pᵢ be the probability that a search asks for kᵢ (here only successful searches, so Σpᵢ = 1). Finding kᵢ costs level(kᵢ) comparisons, with the root at level 1. The expected search cost of a tree is Σ pᵢ · level(kᵢ). Four keys can form 14 different BSTs (a Catalan number again), so trying every tree is exponential. Putting the most probable key at the root and repeating on each side is greedy, and Figure 4.5.1 shows it losing.

The recurrence (successful searches only)

Let C[i][j] = the smallest expected cost of a BST on keys kᵢ…kⱼ. If kₖ is the root, the left subtree holds kᵢ…kₖ₋₁ and the right subtree kₖ₊₁…kⱼ, and each must itself be optimal. Hanging both subtrees under kₖ pushes every key in them one level deeper, which adds each of their probabilities once; the root adds pₖ × 1. Together that is the whole sum pᵢ + … + pⱼ:

C[i][i−1] = 0                                   (empty tree)
C[i][i]   = pᵢ
C[i][j]   = min over i ≤ k ≤ j of { C[i][k−1] + C[k+1][j] }  +  (pᵢ + pᵢ₊₁ + … + pⱼ)
R[i][j]   = the k that gives the minimum         (the root of the subtree)

This is Levitin's form. Fill by diagonals d = j − i = 0, 1, …, n − 1, exactly as in matrix chain multiplication. The answer is C[1][n]. Build the tree from R: the root is k = R[1][n]; its left subtree comes from R[1][k−1] and its right subtree from R[k+1][n].

Many exam papers give success frequencies p(1..n) and failure frequencies q(0..n), where q(i) counts searches for values that fall between aᵢ and aᵢ₊₁ and end at an external node. The weight w(i, j) is the total frequency of the subtree holding aᵢ₊₁…aⱼ and its external nodes:

w(i, i) = q(i),   c(i, i) = 0,   r(i, i) = 0
w(i, j) = w(i, j−1) + p(j) + q(j)
c(i, j) = min over i < k ≤ j of { c(i, k−1) + c(k, j) }  +  w(i, j)
r(i, j) = the k that gives the minimum           for 0 ≤ i < j ≤ n; answer c(0, n)

The classic instance n = 4, (a₁, a₂, a₃, a₄) = (do, if, int, while), p = (3, 3, 1, 1), q = (2, 3, 1, 1, 1) gives w(0, 4) = 16, c(0, 4) = 32 and r(0, 4) = 2: "if" is the root, "do" its left child, "int" its right child, and "while" the right child of "int". CLRS counts each external node one level deeper, so its total for the same tree is larger by Σq = 8 (40 instead of 32 here); follow your own textbook's convention.

Complexity

There are about n²/2 entries, and each tries up to n roots, so the time is Θ(n³) and the C (or c, w) and R tables take Θ(n²) space. Knuth showed that the best root never moves left as the range grows: R[i][j−1] ≤ R[i][j] ≤ R[i+1][j]. Searching only that window cuts the time to Θ(n²).

Exam traps

  • The most probable key need not be the root (Figure 4.5.1), and the optimal tree need not be balanced.
  • Do not forget the weight term: after the min, add the sum of the probabilities (or w(i, j)) of every key in the range.
  • Do not mix the two forms: Levitin's k runs i ≤ k ≤ j with C[i][i−1] = 0; Horowitz's k runs i < k ≤ j with c(i, i) = 0 and w(i, i) = q(i).
  • Levels start at 1 at the root here. Books that count depth from 0 get a cost smaller by Σp; state your convention.
  • Frequencies instead of probabilities give the same tree; only the cost is multiplied by the total frequency.

4.6 All-pairs shortest paths: Floyd-Warshall algorithm

The all-pairs shortest-path problem asks for the shortest distance between every ordered pair of vertices in a weighted directed graph. The Floyd–Warshall algorithm solves it with dynamic programming over the set of vertices a path may pass through: three nested loops, Θ(n³) time, and it works with negative edge weights as long as no cycle has negative total weight. It builds distance tables between cities or network routers, and with true/false in place of numbers it computes reachability (Warshall's transitive closure).

You need: the adjacency-matrix representation (Unit 6, Graph representations) and Dijkstra's algorithm (Unit 3) for comparison.

The DP idea: allow one more stop at a time

Number the vertices 1 to n. Let D⁽ᵏ⁾[i][j] = the length of the shortest path from i to j whose intermediate vertices all come from {1, 2, …, k}. D⁽⁰⁾ allows no intermediate vertex, so it is the weight matrix: 0 on the diagonal, w(i, j) where an edge exists, ∞ elsewhere.

A shortest path allowed to use vertices 1 to k either does not use k, and then it is D⁽ᵏ⁻¹⁾[i][j], or passes through k once, as a path i ⇝ k followed by k ⇝ j, each using only 1 to k − 1:

D⁽ᵏ⁾[i][j] = min( D⁽ᵏ⁻¹⁾[i][j],  D⁽ᵏ⁻¹⁾[i][k] + D⁽ᵏ⁻¹⁾[k][j] )        for k = 1, 2, …, n

After k = n every vertex is allowed, so D⁽ⁿ⁾ holds the true shortest distances. This is optimal substructure: the two pieces of a shortest path through k are themselves shortest paths.

The algorithm

FLOYD-WARSHALL(W, n)
  D = W                                   // copy of the weight matrix
  for k = 1 to n                          // allowed stop: outermost loop
      for i = 1 to n
          for j = 1 to n
              if D[i][k] + D[k][j] < D[i][j]
                  D[i][j] = D[i][k] + D[k][j]
                  next[i][j] = next[i][k]   // first hop, for printing the path

One matrix is enough. During pass k, row k and column k do not change, because D[i][k] + D[k][k] = D[i][k] when D[k][k] = 0, so updating in place is safe. The time is Θ(n³) and the space Θ(n²). To print a path, set next[i][j] = j for every edge at the start; the path from i to j is i, next[i][j], next[next[i][j]][j], … until j.

Negative edge weights are fine. A negative cycle makes "shortest" meaningless (go round it again and the cost drops), and it shows up as a negative value on the diagonal, D[i][i] < 0, at the end.

Warshall's algorithm and the alternatives

Transitive closure. To know only whether j can be reached from i, replace numbers by 0/1, min by OR and + by AND: R⁽ᵏ⁾[i][j] = R⁽ᵏ⁻¹⁾[i][j] OR (R⁽ᵏ⁻¹⁾[i][k] AND R⁽ᵏ⁻¹⁾[k][j]). This is Warshall's algorithm, also Θ(n³). In the example every vertex reaches every other, so the closure is all 1s. Versions were published by Bernard Roy (1959), Stephen Warshall (1962) and Robert Floyd (1962).

Other choices. Running Dijkstra from every vertex costs about O(n·m log n) with a binary heap for m edges: faster on sparse graphs, but only for non-negative weights. Johnson's algorithm reweights the edges so that Dijkstra can be used even with negative ones. Floyd–Warshall is the simplest and the best choice for dense graphs.

Exam traps

  • k, the allowed stop, must be the outermost loop. With i or j outside, the result is wrong.
  • Start the diagonal at 0, not ∞, and mark missing edges ∞, not 0.
  • In code, ∞ + w overflows if ∞ is INT_MAX; use a large value such as 10⁹ or test for ∞ before adding.
  • Negative edges are allowed; negative cycles are not. Check D[i][i] < 0 at the end.
  • Floyd–Warshall is dynamic programming over sets of allowed vertices; Dijkstra is greedy. Examiners ask you to name the design method of each.

4.7 Multistage graphs

A multistage graph is a directed graph whose vertices are split into k stages V₁, V₂, …, Vₖ, with every edge going from one stage to the next. Stage 1 holds a single source s and stage k a single sink t. The problem is to find a minimum-cost path from s to t. It is one of the first DP examples in Horowitz and Sahni's textbook, and it models planning in stages, such as choosing a supplier for each step of a production line.

Forward and backward approaches

Forward approach. Let cost(i, j) be the minimum cost of a path from vertex j in stage i to t, and c(j, l) the weight of edge j → l.

cost(k, t) = 0
cost(i, j) = min over edges j → l, l in stage i+1, of { c(j, l) + cost(i+1, l) }
d(i, j)    = the l that gives the minimum

The table is filled from stage k − 1 back to stage 1, and cost(1, s) is the answer. The path follows d from s to t. It is called "forward" because each vertex looks forward to its successors.

Backward approach. Let bcost(i, j) be the minimum cost of a path from s to j. Then bcost(1, s) = 0 and bcost(i, j) = min over edges l → j of { bcost(i−1, l) + c(l, j) }, filled from stage 2 forward; bcost(k, t) is the answer.

Each edge is examined once in either approach, so the time is Θ(|V| + |E|).

Worked example

Question. Find the minimum-cost path from 1 to 9 in the graph of Figure 4.7.1 by the forward approach, and check it by the backward approach. (8 marks)

Exam traps

  • The forward approach fills the table backward from t; the backward approach fills it forward from s. Do not swap the names.
  • The cheapest first edge is not the start of the cheapest path (2 < 4 here, but the best path takes the 4).
  • Edges must join consecutive stages. If an edge skips a stage, add dummy vertices with zero-cost edges.

4.8 Travelling salesman problem

In the travelling salesman problem (TSP), a salesman must visit each of n cities exactly once and return home, at the least total cost. It is NP-hard, so no polynomial-time algorithm is known, but dynamic programming over subsets of cities, found by Held and Karp and by Bellman in 1962, cuts the (n − 1)! tours of brute force to about n²·2ⁿ steps. TSP models courier and school-bus routes, the path of a drilling head over a circuit board and the order of a warehouse picker's stops.

You need: the four-step recipe of Chapter 4.1 and basic set notation; Unit 5, Branch and bound: knapsack and travelling salesman, for the other exact method.

The problem and brute force

Cities are numbered 1 to n and c[i][j] is the cost of going from i to j; the matrix may be asymmetric (c[i][j] ≠ c[j][i], for example one-way roads or different fares). A tour starts at city 1, visits every other city once, and returns to 1. Fixing city 1 as the start leaves (n − 1)! orders of the other cities: 362,880 for n = 10 and about 1.2 × 10¹⁷ for n = 20. With symmetric costs each tour is counted twice, once in each direction.

State and recurrence

Let g(i, S) = the cost of the cheapest path that starts at city i, visits every city in the set S exactly once, and ends at city 1. S never contains 1 or i.

g(i, ∅) = c[i][1]                                     (go straight home)
g(i, S) = min over j in S of { c[i][j] + g(j, S − {j}) }
answer  = g(1, {2, 3, …, n})
J(i, S) = the j that gives the minimum                 (to rebuild the tour)

This is the principle of optimality: whichever city j comes after i, the rest of the path must be the cheapest way from j through the remaining cities back to 1. Compute g for |S| = 0, then 1, 2, …, n − 2, then the final answer. Programs store S as an n-bit mask, so that S − {j} is one bitwise operation.

Exam traps

  • The base case is g(i, ∅) = c[i][1], the cost of returning to the start, not 0.
  • For an asymmetric matrix, c[i][j] is row i, column j: the cost from i to j. Reading the column gives the cost of the reverse trip.
  • S never contains the start city 1 or the current city i.
  • Θ(n²·2ⁿ) is exponential. The DP beats (n − 1)! but does not make TSP polynomial; it remains NP-hard.
  • Nearest neighbour is a heuristic, not an exact method (38 against 35 here).

Takeaways

  1. Dynamic programming needs optimal substructure and overlapping subproblems; it solves each subproblem once and stores the answer.
  2. Every DP has a state, a recurrence with base cases, a fill order and a trace-back; its time is states × choices per state.
  3. Greedy fails where DP succeeds when a locally best choice spoils the rest: coins {1, 5, 6, 9}, the 0/1 knapsack, the multistage graph and TSP all showed it.
  4. The 0/1 knapsack runs in Θ(nW), which is pseudo-polynomial because W is a number, not an input size.
  5. Matrix chain and optimal BST are interval DPs: fill by diagonals, try every split or root, store it, Θ(n³).
  6. LCS fills an (m + 1) × (n + 1) table in Θ(mn) and reads the answer back along ↖ arrows; edit distance is the same table with costs.
  7. Floyd–Warshall adds one allowed stop per pass, with k as the outer loop; it handles negative edges and reveals negative cycles on the diagonal.
  8. A multistage graph is a shortest path in a DAG, solved stage by stage in Θ(|V| + |E|).
  9. TSP's DP over subsets is exact but Θ(n²·2ⁿ): far better than (n − 1)!, yet TSP stays NP-hard.

Glossary

Dynamic programming
Solving a problem by combining stored answers to overlapping subproblems.
Principle of optimality
Bellman's rule: the decisions after the first must be optimal for the state the first one leaves.
Optimal substructure
An optimal solution contains optimal solutions to its subproblems.
Overlapping subproblems
A plain recursion meets the same subproblem more than once.
Memoization
Top-down DP: recursion that stores each answer the first time it is computed.
Memory function
Levitin's name for memoization.
Tabulation
Bottom-up DP: filling the table with loops in dependency order.
State
The parameters that name one subproblem, such as (i, w) in the knapsack.
Trace-back
Following stored choices back from the final state to build the optimal solution.
Pseudo-polynomial
Polynomial in the numeric value of an input (such as W) but exponential in its bit length.
Dominated pair
In the set method, a (value, weight) pair beaten by another with no less value and no more weight.
Parenthesization
An order of multiplying a matrix chain, written with brackets.
Catalan number
The count 1, 1, 2, 5, 14, 42, … of parenthesizations and of BST shapes.
Subsequence
Characters taken from a string in order, possibly with gaps.
Longest common subsequence
A longest string that is a subsequence of two given strings.
Edit distance
The fewest insertions, deletions and substitutions that turn one string into another.
Optimal binary search tree
A BST with the least expected search cost for given key probabilities.
Expected search cost
Σ pᵢ × level(kᵢ), the average number of comparisons per search.
Weight w(i, j)
The total frequency of the keys and gaps in a subtree, added once per level in the OBST recurrence.
All-pairs shortest paths
Shortest distances between every ordered pair of vertices.
Transitive closure
The 0/1 matrix telling whether j is reachable from i.
Negative cycle
A cycle whose edge weights sum to less than zero; shortest paths through it are undefined.
Multistage graph
A directed graph whose vertices fall into stages, with edges only from each stage to the next.
Tour
A cycle that visits every city exactly once and returns to the start.
Held–Karp algorithm
The Θ(n²·2ⁿ) DP for the travelling salesman problem over subsets of cities.
Nearest-neighbour heuristic
A greedy TSP rule: always go to the closest unvisited city; fast but not exact.
