1.1 Algorithms: correctness and important problem types

An algorithm is a finite sequence of clear instructions that solves a problem: for every valid input it stops after a finite number of steps and gives the right output. Before we ask how fast an algorithm is (the rest of this unit), we ask whether it is correct, meaning it gives the right answer for every legal input, not only for the inputs we happened to test. The second half surveys the problem types that the whole subject keeps returning to.

What makes a procedure an algorithm

Donald Knuth lists five properties. Input: zero or more values taken from a stated set. Output: at least one value, related to the input in the required way. Definiteness: each step is precise, with one meaning. Finiteness: it stops after finitely many steps on every input. Effectiveness: each step is basic enough to be done exactly, with pencil and paper, in finite time. A recipe that says "add salt to taste" fails definiteness; a procedure that may run forever on some input fails finiteness.

A problem states what is wanted for all inputs ("sort a list of numbers"); an instance is one input (sort 31, 41, 59, 26, 53). The oldest algorithm still in daily use is Euclid's method for the greatest common divisor (gcd) of two non-negative integers m and n, not both zero. It rests on one fact: gcd(m, n) = gcd(n, m mod n), and gcd(m, 0) = m, where m mod n is the remainder when m is divided by n.

  1. If n = 0, output m and stop.
  2. Otherwise set r ← m mod n (the symbol ← means "becomes").
  3. Set m ← n and n ← r, then go back to step 1.

From problem to algorithm

Designing an algorithm follows a fixed path: understand the problem and its edge cases (empty list, equal keys); fix the model (the RAM model of Chapter 1.3) and whether an exact or an approximate answer is wanted; choose a design technique, or paradigm: brute force, divide and conquer (Unit 2), greedy (Unit 3), dynamic programming (Unit 4), backtracking and branch and bound (Unit 5), randomization (Unit 7); specify it in pseudocode; prove it correct; analyse its time and space; then code and test it.

Proving an algorithm correct

Testing runs a few instances; a proof covers all of them. Correctness has two halves. Partial correctness: if the algorithm stops, its output is right. Termination: it does stop on every valid input. Both together give total correctness. Termination is usually shown with a variant, a non-negative integer that strictly decreases on every pass; in Euclid's algorithm n is the variant, since m mod n < n.

For loops, the standard tool is a loop invariant: a statement about the variables that is true at the start of every iteration. You prove three things, exactly like induction:

  1. Initialization: it is true before the first iteration.
  2. Maintenance: if it is true before an iteration, it is still true before the next one.
  3. Termination: when the loop stops, the invariant plus the stopping condition give the required result.

For Euclid the invariant is "gcd(m, n) equals the gcd of the original inputs"; when n = 0, gcd(m, 0) = m is the answer. Recursive algorithms are proved by mathematical induction on the input size: prove the base case, assume the algorithm is correct on all smaller inputs, and show it is then correct on size n (Chapter 1.6 uses this for Tower of Hanoi).

Worked example

Question. A batter's scores in five innings are stored in an array: 31, 41, 59, 26, 53. Write an algorithm in C to find the highest score. State a loop invariant and use it to prove the algorithm correct. Trace it on this array and count the comparisons. (8 marks)

Solution. The program, in C (arrays start at index 0):

#include <stdio.h>

int find_max(const int a[], int n) {
    int max = a[0];              /* invariant: max = largest of a[0..i-1] */
    for (int i = 1; i < n; i++)
        if (a[i] > max)
            max = a[i];
    return max;
}

int main(void) {
    int runs[] = {31, 41, 59, 26, 53};
    printf("highest score = %d\n", find_max(runs, 5));
}
  1. Invariant. At the start of the iteration with index i, max is the largest of a[0], …, a[i−1].
  2. Initialization. Before the first iteration i = 1 and max = a[0], the largest of the one-element range a[0..0]. True.
  3. Maintenance. If a[i] > max, max becomes a[i]; otherwise it stays. Either way max is now the largest of a[0..i]. Then i increases by 1, so the invariant holds for the new i.
  4. Termination. i starts at 1 and rises by 1 each pass, so the loop stops when i = n (here 5). The invariant then says max is the largest of a[0..n−1], the whole array.
  5. Trace (max starts at 31):

Output: highest score = 59. The comparison a[i] > max runs once per pass, so there are n − 1 = 4 comparisons, for every input of size 5.

Exam traps

  • Algorithm versus program. A program is an algorithm written in a language for a machine. An operating system is a program that is meant never to stop, so it is not an algorithm in Knuth's sense.
  • The termination step of an invariant proof is the point of the proof. Students prove initialization and maintenance, then forget to say what the invariant gives when the loop ends.
  • Partial correctness alone is not enough. A loop that never stops is "partially correct" for every claim; you must also prove termination.
  • Euclid works when m < n too: gcd(24, 60) first computes 24 mod 60 = 24 and so swaps the numbers to gcd(60, 24).

1.2 Insertion sort as a first analysis example

Insertion sort builds a sorted list one item at a time, the way you arrange playing cards in your hand: pick up the next card and slide it left past every larger card until it fits. It is short and very fast on nearly sorted lists, and it is the classic first example of analysis because its running time depends visibly on the input. Both counts are worked here.

You need: loop invariants from Chapter 1.1.

The algorithm and why it is correct

The pseudocode follows Cormen et al. (CLRS), with the array in A[1..n]; the line numbers are used in the analysis.

INSERTION-SORT(A, n)
1  for j = 2 to n
2      key = A[j]
3      // insert A[j] into the sorted part A[1 .. j-1]
4      i = j - 1
5      while i > 0 and A[i] > key
6          A[i + 1] = A[i]          // shift the larger item right
7          i = i - 1
8      A[i + 1] = key               // drop key into the gap

Loop invariant. At the start of each iteration of the for loop, A[1..j−1] holds the items that were first in A[1..j−1], now in sorted order. Initialization: for j = 2, A[1..1] is one item, which is sorted. Maintenance: the while loop moves every item of A[1..j−1] larger than key one place right, and line 8 puts key in the gap, so A[1..j] is sorted. Termination: the loop ends with j = n + 1, so A[1..n], the whole array, is sorted.

Best case: the array is already sorted. Every test on line 5 fails at once, so tj = 1 and the shift lines never run. T(n) = (c1 + c2 + c4 + c5 + c8)n − (c2 + c4 + c5 + c8), which has the form an + b: a linear function of n.

This has the form an² + bn + c: a quadratic function. Only the shape matters, and Chapter 1.5 gives the notation for it.

Operation count: only the basic operation

The operation count method counts only the basic operation, the innermost one that dominates the time; for sorting it is the key comparison A[i] > key. Pass j makes at least 1 and at most j − 1 comparisons, so:

  • Best case: Cbest(n) = n − 1 comparisons and 0 shifts.
  • Worst case: Cworst(n) = 1 + 2 + … + (n − 1) = n(n − 1)/2 comparisons and as many shifts.
  • Average case, all orders equally likely: about n²/4 (derived in Chapter 1.4).

Each shift fixes exactly one inversion, a pair of positions i < j with A[i] > A[j], so the number of shifts equals the number of inversions in the input. Insertion sort is in place (it needs only key and i beyond the array), stable (items with equal keys keep their input order, because the strict > never moves an item past an equal one) and online (it can sort items as they arrive).

Exam traps

  • Line 1 runs n times, not n − 1: the loop test runs once more, when it fails. In the same way tj counts the final failing while test.
  • The worst case is reverse-sorted input, not "random" input. The best case is already-sorted input.
  • Comparisons and shifts are different counts. Shifts equal the number of inversions; comparisons are at most one more per pass.
  • The favourite question: "Analyse insertion sort for best and worst case using the cost × times table." Give the table, both tj values and both final forms.

Analyze Every item of an array is at most k places from its sorted position. Show that insertion sort takes O(nk) time. 4 marks

If positions i < j form an inversion, the item at i belongs after the item at j, so its sorted place is above j − k and at most i + k; hence j − i < 2k. Each item is the left end of fewer than 2k inversions, so there are fewer than 2nk in all. 1.3 Time and space complexity

The time complexity of an algorithm is the number of basic steps it performs, written as a function of the input size n. Its space complexity is the amount of memory it needs, also as a function of n. Counting steps instead of seconds makes the answer independent of the machine, the compiler and the programmer, so two algorithms can be compared before either is coded, and we can predict what happens when n grows from a thousand to ten lakh.

You need: the line count of insertion sort from Chapter 1.2.

A priori analysis and a posteriori testing

A priori analysis is done before the program runs: we count steps in a model of a computer and get a formula such as 2n + 3, valid for every n and every machine, but in steps, not seconds. A posteriori testing (profiling) runs the program and measures it, for example with clock() in C: real seconds, but only for the machine, compiler and inputs tried. Use the first to choose an algorithm and the second to confirm and tune it.

Input size, the RAM model and step counts

The input size n is the natural measure of the input: the number of items for sorting and searching, the order n of an n × n matrix, the numbers of vertices and edges for a graph. For problems on a single number N (primality, gcd) the honest size is the number of bits, about log₂ N, not N itself.

Steps are counted on the RAM model (random-access machine): one processor runs instructions one after another; each simple operation (+, −, ×, ÷, comparison, assignment, array access, function call and return) takes one unit of time; any memory cell can be read in one unit; memory is unlimited, so a program never runs out of cells; and a memory word holds a number of fixed size, so a single step cannot handle arbitrarily huge numbers. This model ignores caches and parallelism, yet it predicts the growth of real running times well.

Horowitz and Sahni define a program step as any piece of code whose time does not depend on the input size: s = a + b * c is one step, but a loop, or a call to a function that loops, is not. Steps are counted either with a count variable (a global count++ beside every step) or with a step table listing each statement's steps per execution (s/e) and frequency, the total being Σ (s/e × frequency): the line count of Chapter 1.2 with every cost set to 1.

Space complexity

The space of a program P is written S(P) = c + SP(n). The fixed part c covers the code, simple variables and constants, and does not depend on n. The variable part SP(n) covers arrays whose size depends on n and the recursion stack: every active call keeps its parameters, local variables and return address. Auxiliary space is the extra memory beyond the input itself; when a book says "insertion sort uses O(1) space" it means auxiliary space. Storing results in a table to avoid recomputing them (Unit 4) is a time–space trade-off: memory buys time.

int count = 0;                       /* global step counter */

float sum(const float a[], int n) {

Solution (b). Sum stores the n numbers of a, plus n, i and s: S(n) = n + 3 words, of which 3 are auxiliary. The recursive version is RSum(a, n) = 0 if n ≤ 0, else RSum(a, n − 1) + a[n]. RSum(a, 5) opens calls for n = 5, 4, 3, 2, 1, 0: n + 1 = 6 frames at once, each holding the array reference, n and the return address (3 words). The stack needs 3(n + 1) words: 18 words for n = 5, 3,003 for n = 1,000. Recursion turned O(1) auxiliary space into O(n).

Solution (c). n³ = 50³ = 1,25,000 steps, so 1.25 × 10⁵ ÷ 10⁹ s = 125 microseconds. 2⁵⁰ = 1,125,899,906,842,624 ≈ 1.13 × 10¹⁵ steps, so about 1.13 × 10⁶ s; dividing by 86,400 seconds per day gives about 13 days.

Exam traps

  • The loop header is counted n + 1 times, not n: the last test fails and ends the loop.
  • Recursion uses space. A recursive function with no arrays still needs stack space proportional to its depth; writing O(1) for RSum loses the marks.
  • Input size of a number is its digit count. Trial division up to √N looks fast in N but needs about 2b/2 divisions for a b-bit N, which is exponential in the input size.
  • Timings from two different computers cannot be compared; step counts can.

1.4 Best, worst and average case analysis

For a fixed input size n, different inputs can take very different times: a linear search may find the key at the first position or not at all. So one formula is not enough, and we describe an algorithm by three functions of n: the best case (the cheapest input of size n), the worst case (the most expensive one) and the average case (the expected cost when inputs follow a stated probability distribution). The worst case is the guarantee engineers rely on; the average case tells you what to expect on typical data.

You need: step and operation counts from Chapter 1.3 and Chapter 1.2.

The three cases defined

Let Dn be the set of all inputs of size n and t(I) the number of basic operations on input I.

  • Worst case: W(n) = max { t(I) : I in Dn }. No input of size n takes longer.
  • Best case: B(n) = min { t(I) : I in Dn }. No input of size n is faster.
  • Average case: A(n) = Σ p(I) · t(I) over all I in Dn, where p(I) is the probability of input I. It is an expected value, so it needs an assumption about the inputs, for example "all orderings equally likely".

Always B(n) ≤ A(n) ≤ W(n). Note that n stays fixed in all three: the best case is the best input of size n, not a small n.

Sequential search: all three cases

Sequential (linear) search compares the key with A[1], A[2], … in turn and stops at the first match or at the end. The basic operation is the key comparison.

  • Best case: the key is in A[1]. Cbest(n) = 1.
  • Worst case: the key is in A[n] or is not in the array. Cworst(n) = n.
  • Average case: assume the search succeeds with probability p (0 ≤ p ≤ 1) and, when it does, the key is equally likely to be at each of the n positions, so each position has probability p/n. Finding it at position i costs i comparisons; failing costs n.
C_avg(n) = [1·(p/n) + 2·(p/n) + … + n·(p/n)] + n·(1 − p)
         = (p/n) · n(n + 1)/2 + n(1 − p)
         = p(n + 1)/2 + n(1 − p)

If the key is always present (p = 1), Cavg(n) = (n + 1)/2: on average about half the list is scanned. If it is never present (p = 0), Cavg(n) = n.

Insertion sort: all three cases

From Chapter 1.2: the best case is sorted input with n − 1 comparisons, and the worst case is reverse-sorted input with n(n − 1)/2. For the average, assume all n! orderings of distinct keys are equally likely. Take any two positions: in exactly half of all orderings their items are out of order. There are n(n − 1)/2 pairs, so the expected number of inversions, and hence of shifts, is n(n − 1)/4. Comparisons exceed shifts by at most one per pass, so Cavg(n) ≈ n²/4: half the worst case, but still quadratic. On random data insertion sort is no rescue; on nearly sorted data it is excellent.

Which case to report

  1. Worst case is the default. It is a guarantee: an IRCTC Tatkal server must survive the worst minute, not the average one. It is also easier to compute than the average, and for many algorithms the worst case is common.
  2. Average case matters when bad inputs are rare. Quicksort makes n(n − 1)/2 comparisons in its worst case but about 1.39 n log₂ n on average, which is why it is used (Unit 2).
  3. Best case is rarely the goal. It is useful as a warning: if even the best case is slow, the algorithm is slow.
  4. Amortized analysis is different (Unit 7): it averages the cost over a sequence of operations on a worst-case input, with no probability involved.

Exam traps

  • "Best case of linear search is n = 1" is wrong. The best case is the best input for a given n: the key in the first position.
  • The average is not (best + worst)/2 in general. It is a weighted sum that depends on the probability assumption, and you must state that assumption.
  • Do not forget the unsuccessful search. It costs n comparisons and enters the average with weight 1 − p.
  • Worst case and Big-O are different ideas. The case says which input; the notation (Chapter 1.5) says how the count grows. "The best case of insertion sort is Θ(n)" is a correct sentence.
  • Amortized cost is not average-case cost: no probabilities are involved.

1.5 Asymptotic notations: Big-O, Omega, Theta, little-o

Asymptotic notation describes how a function grows when n becomes large, ignoring constant factors and small inputs. Instead of "insertion sort takes ((c5 + c6 + c7)/2)n² + … steps in the worst case" we say "its worst case is Θ(n²)": that keeps the one fact that decides performance for big inputs and drops what depends on the machine. Five notations are used: O (upper bound), Ω (lower bound), Θ (tight bound), and the strict versions o and ω.

You need: step counts from Chapter 1.3.

Big-O, Omega and Theta

In all definitions f(n) and g(n) are non-negative for large n, and c, c1, c2, n0 are constants that do not depend on n.

  • Big-O (upper bound). f(n) = O(g(n)) if there exist c > 0 and n0 ≥ 1 such that f(n) ≤ c·g(n) for all n ≥ n0. Read: f grows no faster than g.
  • Big-Omega (lower bound). f(n) = Ω(g(n)) if there exist c > 0 and n0 such that f(n) ≥ c·g(n) for all n ≥ n0. Read: f grows at least as fast as g.
  • Big-Theta (tight bound). f(n) = Θ(g(n)) if there exist c1, c2 > 0 and n0 such that c1·g(n) ≤ f(n) ≤ c2·g(n) for all n ≥ n0. Equivalently, f = O(g) and f = Ω(g).

O(g(n)) is really a set of functions, and "f(n) = O(g(n))" means f belongs to it. So n = O(n²) is true (n² is an upper bound, though not a tight one), while "O(n²) = n" is meaningless.

Little-o and little-omega

  • Little-o. f(n) = o(g(n)) if for every constant c > 0 there is an n0 with f(n) < c·g(n) for all n ≥ n0. Read: f grows strictly slower than g. Example: n = o(n²), but 2n² is not o(n²).
  • Little-omega. f(n) = ω(g(n)) if for every c > 0 there is an n0 with f(n) > c·g(n) for all n ≥ n0. Example: n² = ω(n).

Big-O asks for some c; little-o demands every c, however small. A useful picture compares growth rates like numbers: O is ≤, Ω is ≥, Θ is =, o is < and ω is >.

The limit test and the rules

Most comparisons are settled by the limit L = limn→∞ f(n)/g(n):

  • L = 0: f = o(g), and so f = O(g) but not Θ(g).
  • 0 < L < ∞ (a positive constant): f = Θ(g).
  • L = ∞: f = ω(g), and so f = Ω(g) but not Θ(g).

L'Hôpital's rule helps with logarithms: for log₂ n against √n, differentiate both: (1/(n ln 2)) ÷ (1/(2√n)) = 2/(√n ln 2) → 0, so log₂ n = o(√n). The rules used most:

  1. Constants drop: 5n² = Θ(n²). A polynomial aknk + … + a0 with ak > 0 is Θ(nk).
  2. Sum rule: O(f) + O(g) = O(max(f, g)). A program's slowest part decides its order.
  3. Product rule: a loop of O(n) passes, each costing O(n), is O(n²).
  4. Logarithm bases do not matter: loga n = logb n ÷ logb a, a constant factor, so we write O(log n). Exponential bases do matter: 2ⁿ = o(3ⁿ), since (2/3)ⁿ → 0.
  5. Transitivity: f = O(g) and g = O(h) give f = O(h); the same holds for Ω, Θ, o and ω. Also f = O(g) exactly when g = Ω(f).

Basic efficiency classes, from fastest to slowest: 1 (constant: read A[i]); log n (logarithmic: binary search); n (linear: linear search); n log n (linearithmic: merge sort); n² (quadratic: insertion sort, worst case); n³ (cubic: the usual matrix multiplication); 2ⁿ (exponential: trying all subsets); n! (factorial: trying all orderings, as in brute-force travelling salesman).

1.6 Analysis of non-recursive and recursive algorithms

This chapter turns counting into two fixed recipes, one for loops and one for algorithms that call themselves. A loop gives a sum to simplify; a recursive function gives a recurrence, an equation that defines the count for n in terms of the count for smaller inputs.

You need: cases (Chapter 1.4) and Θ (Chapter 1.5).

Plan for non-recursive algorithms

  1. Choose the parameter that measures input size, n.
  2. Identify the basic operation, usually in the innermost loop.
  3. Check whether its count depends only on n. If not, analyse the worst, best and average cases separately.
  4. Write the count as a sum, one Σ per loop.
  5. Simplify the sum to a closed form, or at least to its order of growth.

The sums needed most: Σi=l..u 1 = u − l + 1; Σi=1..n i = n(n + 1)/2 ≈ n²/2; Σi=1..n i² = n(n + 1)(2n + 1)/6 ≈ n³/3; Σi=0..n 2i = 2n+1 − 1; Σi=1..n 1/i ≈ ln n.

  • Element uniqueness (are all n items distinct?): two loops, for i = 0..n−2, for j = i+1..n−1, compare A[i], A[j]. Worst case (all distinct): Σi=0..n−2 (n − 1 − i) = (n − 1) + … + 1 = n(n − 1)/2 comparisons, Θ(n²).
  • Matrix multiplication of two n × n matrices with three loops: Σi Σj Σk 1 = n³ multiplications, Θ(n³), for every input.
  • Binary digits of n: count = 1; while n > 1: n = ⌊n/2⌋; count++. The loop halves n, so it runs ⌊log₂ n⌋ times and returns ⌊log₂ n⌋ + 1: Θ(log n).
  • Horner's rule evaluates p(x) = anxⁿ + … + a1x + a0 as (…((anx + an−1)x + an−2)x + …)x + a0: exactly n multiplications and n additions. For p(x) = 2x³ − 6x² + 2x − 1 at x = 3: b = 2; b = 2·3 − 6 = 0; b = 0·3 + 2 = 2; b = 2·3 − 1 = 5, with 3 multiplications. Computing each power separately costs 3 + 2 + 1 = 6.

Plan for recursive algorithms

  1. Choose the input-size parameter and the basic operation, and check the cases, as before.
  2. Set up a recurrence for the count, with an initial condition for the smallest input.
  3. Solve it. The basic method is backward substitution: substitute the recurrence into itself until a pattern in i appears, then choose i so that the base case is reached. (Chapters 1.7 and 1.8 give more methods.)

Factorial. F(n) = F(n − 1) · n with F(0) = 1. The multiplications satisfy M(n) = M(n − 1) + 1, M(0) = 0. Backward: M(n) = M(n − 2) + 2 = M(n − 3) + 3 = … = M(n − i) + i; at i = n, M(n) = M(0) + n = n.

Binary digits, recursive. A(n) = A(⌊n/2⌋) + 1 with A(1) = 0 counts additions. For n = 2k: A(2k) = A(2k−1) + 1 = A(2k−2) + 2 = … = A(1) + k = k = log₂ n.

Tower of Hanoi. Move n disks from peg A to peg C using peg B, one disk at a time, never a larger disk on a smaller one. Recursively: move n − 1 disks A → B, move the largest A → C, move n − 1 disks B → C. Correctness is by induction on n (Chapter 1.1): if the method works for n − 1 disks, these three steps work for n. The moves satisfy M(n) = 2M(n − 1) + 1, M(1) = 1. Figure 1.6.1 shows the calls for n = 3.

1.7 Recurrences: substitution and recursion tree methods

A recurrence gives T(n), the running time on input size n, in terms of the running time on smaller inputs. Every recursive algorithm has one, and divide-and-conquer algorithms (Unit 2) have the form T(n) = aT(n/b) + f(n): a subproblems of size n/b plus f(n) work to divide and combine. This chapter gives two general methods: the substitution method (guess the answer, then prove it by induction) and the recursion tree method (draw the calls and add their costs level by level). The master theorem (Chapter 1.8) is a shortcut built on the second.

You need: backward substitution from Chapter 1.6 and mathematical induction.

Writing the recurrence

Read the recurrence off the code: one term per recursive call, plus the non-recursive work. Merge sort sorts two halves and merges them with at most n − 1 comparisons, so T(n) = 2T(n/2) + n. Binary search looks at the middle item and recurses on one half: T(n) = T(n/2) + 1. Each needs a base case, such as T(1) = 1. We take n to be a power of b and drop floors and ceilings, which does not change the order of growth here.

A warning about names. In Cormen et al. (CLRS), the "substitution method" means guess-and-prove by induction. Many Indian textbooks also call the backward substitution of Chapter 1.6 (also called the iteration method) a substitution method. Exams use both; name the one you use and show its steps.

The substitution method: guess, then prove

  1. Guess the form of the answer, for example T(n) ≤ c·n log₂ n. A recursion tree, or experience with similar recurrences, gives the guess.
  2. Prove it by mathematical induction: assume the bound holds for all smaller inputs, substitute it into the recurrence, and show it holds for n. Find a constant c (and n0) that makes both the inductive step and the base cases work.

The inductive step must give exactly the form assumed. Try to "prove" T(n) = 2T(n/2) + n is O(n) with the guess T(n) ≤ cn: substitution gives T(n) ≤ 2c(n/2) + n = (c + 1)n, which is not ≤ cn for any c. The guess is wrong, and the proof correctly fails.

Sometimes the guess is right but too weak to carry through. For T(n) = 2T(n/2) + 1, the guess T(n) ≤ cn gives cn + 1, again not ≤ cn. The fix is to subtract a lower-order term: guess T(n) ≤ cn − d. Then T(n) ≤ 2(c·n/2 − d) + 1 = cn − 2d + 1 ≤ cn − d whenever d ≥ 1. So T(n) = O(n). A stronger hypothesis makes the induction easier, because you may assume more.

The recursion tree method

Draw each call as a node labelled with its non-recursive cost; its children are the calls it makes. Then:

  1. Cost per level: at depth i there are ai nodes of size n/bi, so the level costs ai·f(n/bi).
  2. Depth: sizes reach 1 when n/bi = 1, at i = logb n, so there are logb n + 1 levels counting the leaves.
  3. Leaves: alogb n = nlogb a leaves, each costing T(1).
  4. Add all levels, usually as an arithmetic or geometric series.

For T(n) = 2T(n/2) + n, level i has 2i nodes of cost n/2i, so every level costs n (Figure 1.7.1). With log₂ n levels of internal nodes and n leaves of cost T(1) = 1, T(n) = n log₂ n + n = Θ(n log n).

When levels are not equal, the series decides. For T(n) = 3T(n/4) + n², level i costs 3i(n/4i)² = (3/16)in², a decreasing geometric series, so the root dominates and T(n) = Θ(n²). For the unbalanced T(n) = T(n/3) + T(2n/3) + n, each full level costs n, and the longest path n → 2n/3 → 4n/9 → … → 1 has log3/2 n levels, so T(n) = O(n log n). The tree is good for guessing; the substitution method then proves the guess.

Worked example

Question. T(n) = 2T(n/2) + n, T(1) = 1. (a) Use a recursion tree to find T(16) exactly and check it by direct computation. (b) Prove T(n) = O(n log n) by the substitution method. (c) Find the level costs of T(n) = 3T(n/4) + n², T(1) = 1, for n = 64 and give its order. (12 marks)

Solution (a). n = 16 gives log₂ 16 = 4 levels of internal nodes, each costing 16, and 16 leaves of cost 1: T(16) = 4 × 16 + 16 = 80. Directly: T(2) = 2·1 + 2 = 4; T(4) = 2·4 + 4 = 12; T(8) = 2·12 + 8 = 32; T(16) = 2·32 + 16 = 80. Solution (b). Guess T(n) ≤ c·n log₂ n for n ≥ 2.

  1. Inductive step. Assume T(n/2) ≤ c(n/2) log₂(n/2). Then T(n) ≤ 2c(n/2) log₂(n/2) + n = cn(log₂ n − 1) + n = cn log₂ n − cn + n ≤ cn log₂ n whenever c ≥ 1.
  2. Base case. n = 1 cannot be the base: c·1·log₂ 1 = 0 < T(1) = 1. So start at n0 = 2 (and n = 3 when floors are used, since T(3) depends on T(1)): T(2) = 4 ≤ c·2·1 needs c ≥ 2; T(3) = 2T(1) + 3 = 5 ≤ c·3·log₂ 3 ≈ 4.75c holds for c ≥ 2.
  3. Conclusion. With c = 2 and n0 = 2, T(n) ≤ 2n log₂ n for all n ≥ 2, so T(n) = O(n log n). Check at n = 16: 80 ≤ 2 × 16 × 4 = 128.

Exam traps

  • "Substitution method" has two meanings: guess-and-prove (CLRS) and backward substitution (iteration). State which one you use.
  • The induction must return the exact hypothesis. Ending with (c + 1)n when you assumed cn proves nothing.
  • n log n is 0 at n = 1, so the base case of an O(n log n) proof starts at n0 = 2.
  • Count levels and leaves correctly: logb n + 1 levels; nlogb a leaves, which is n only when a = b.

1.8 Master theorem

The master theorem solves divide-and-conquer recurrences T(n) = aT(n/b) + f(n) in one step, without drawing a tree. It compares the work at the root, f(n), with the total work of the leaves, nlogb a. If the leaves are polynomially heavier, they decide the answer; if the root is polynomially heavier, it decides; if they balance, every level costs the same and a factor log n appears. Most recurrences of Units 2 and 6 (binary search, merge sort, Strassen, Karatsuba) are solved this way.

You need: the recursion tree method from Chapter 1.7.

The statement

Let a ≥ 1 and b > 1 be constants, let f(n) be positive for large n, and let T(n) = aT(n/b) + f(n), where n/b may be rounded up or down. Write p = logb a, so np is the number of leaves of the recursion tree. Then:

  1. Case 1 (leaves dominate). If f(n) = O(np−ε) for some constant ε > 0, then T(n) = Θ(np).
  2. Case 2 (all levels equal). If f(n) = Θ(np), then T(n) = Θ(np log n). More generally, if f(n) = Θ(np logk n) with k ≥ 0, then T(n) = Θ(np logk+1 n).
  3. Case 3 (root dominates). If f(n) = Ω(np+ε) for some ε > 0, and a·f(n/b) ≤ c·f(n) for some constant c < 1 and all large n (the regularity condition), then T(n) = Θ(f(n)).

"Polynomially smaller" means smaller by a factor nε, not just by log n. That is why n log n against n falls outside Cases 1 and 3, and is handled by the general Case 2 with k = 1.

The simple form. When f(n) = Θ(nd) with d ≥ 0, as in most exam questions, compare a with bd (the same as comparing p with d):

T(n) = aT(n/b) + Θ(n^d)
   a < b^d   →   T(n) = Θ(n^d)
   a = b^d   →   T(n) = Θ(n^d log n)
   a > b^d   →   T(n) = Θ(n^(log_b a))

Regularity holds automatically here: a(n/b)d = (a/bd)nd, and a/bd < 1 in the first line.

Why it works

From Chapter 1.7, level i of the tree costs aif(n/bi). For f(n) = nd this is nd(a/bd)i, a geometric series with ratio r = a/bd over logb n + 1 levels. If r < 1 the series falls and the first term, the root's nd, sets the order. If r = 1 all terms equal nd, giving nd times the number of levels. If r > 1 the series rises and the last term, the leaves' nlogb a, sets the order. Figure 1.8.1 shows the three shapes.

When the theorem does not apply

  • a or b not constant, or a < 1: T(n) = nT(n/2) + n, T(n) = 0.5T(n/2) + n.
  • Subproblems of different sizes: T(n) = T(n/3) + T(2n/3) + n. Use a recursion tree (Chapter 1.7).
  • Subtract-and-conquer: T(n) = T(n − 1) + n or 2T(n − 1) + 1. Use backward substitution (Chapter 1.6): Θ(n²) and Θ(2ⁿ).
  • A gap between cases: T(n) = 2T(n/2) + n/log n. Here f(n) is smaller than np = n, but only by a log factor, so Case 1 fails, and Case 2 needs k ≥ 0. (Other methods give Θ(n log log n).)

Exam traps

  • Compare f(n) with nlogb a, not with n. For T(n) = 4T(n/2) + n, f(n) = n is not "balanced": np = n².
  • Get the log the right way round: p = logb a. For 3T(n/4), p = log₄ 3 ≈ 0.79, not log₃ 4 ≈ 1.26.
  • "Larger by log n" is not "polynomially larger". 2T(n/2) + n log n is general Case 2 (Θ(n log² n)), not Case 3.
  • Case 3 needs the regularity check; write it out, even though it holds for every polynomial f.
  • Binary search, T(n) = T(n/2) + 1, is Case 2 with p = 0, giving Θ(log n); it is not Case 1.

Beyond the syllabus

The theorem goes back to Bentley, Haken and Saxe (1980) and was named and popularised by the CLRS textbook. The Akra–Bazzi method extends it to unequal parts such as T(n/3) + T(2n/3), and newer editions of CLRS also cover such generalisations. In research on fast matrix multiplication, the exponent log₂ 7 ≈ 2.81 of Strassen's algorithm has been pushed below 2.4 by much more complex methods, each analysed with this kind of recurrence. Takeaways

  1. An algorithm must stop on every valid input with the right output. Prove loops with an invariant (initialization, maintenance, termination) and stopping with a decreasing variant.
  2. Analyse a priori: count basic operations on the RAM model as a function of n, not seconds on one machine.
  3. Insertion sort makes n − 1 comparisons on sorted input, n(n − 1)/2 on reversed input and about n²/4 on average; always state the case.
  4. Space complexity includes the recursion stack: a recursive sum needs O(n) space where the loop needs O(1).
  5. O is an upper bound, Ω a lower bound and Θ a tight bound; o and ω are strict. Constants and logarithm bases drop out; exponential bases do not.
  6. Loops give sums; recursive algorithms give recurrences, which need an initial condition.
  7. A recursion tree shows where the work is (root, every level, or leaves); the substitution method proves the guess.
  8. The master theorem compares f(n) with nlogb a. It does not apply to unequal parts, subtract-and-conquer recurrences or the gaps between its cases.

Glossary

Algorithm
A finite sequence of unambiguous, effective steps that produces the right output for every valid input and stops.
Instance
One particular input of a problem, such as one list to be sorted.
Loop invariant
A statement true at the start of every iteration of a loop, proved by initialization, maintenance and termination.
Variant
A non-negative integer quantity that strictly decreases on every pass of a loop, proving that the loop stops.
Partial correctness
If the algorithm stops, its output is right.
Total correctness
Partial correctness together with termination on every valid input.
Stable sort
A sort that keeps items with equal keys in their input order.
In-place algorithm
One that needs only a constant amount of memory beyond its input.
Inversion
A pair of positions i < j with A[i] > A[j]; insertion sort makes one shift per inversion.
Input size
The measure n of an input: number of items, matrix order, vertices and edges, or bits of a number.
Basic operation
The operation that contributes most to the running time, usually in the innermost loop; its count is the time complexity.
RAM model
A model computer that runs one instruction at a time, each simple operation and memory access taking one unit of time.
Program step
A piece of code whose running time does not depend on the input size.
A priori analysis
Analysis before running, by counting steps in a model; machine-independent.
A posteriori testing
Measuring the running time of a coded program on a real machine.
Auxiliary space
Memory used beyond the input itself, including the recursion stack.
Worst-case complexity
The largest number of steps over all inputs of size n.
Average-case complexity
The expected number of steps over inputs of size n under a stated probability distribution.
Big-O
f(n) = O(g(n)): f(n) ≤ c·g(n) for some c > 0 and all n ≥ n0; an upper bound.
Big-Omega
f(n) = Ω(g(n)): f(n) ≥ c·g(n) for some c > 0 and all n ≥ n0; a lower bound.
Big-Theta
f(n) = Θ(g(n)): both O(g(n)) and Ω(g(n)); a tight bound.
Little-o, little-omega
Strict bounds: f/g → 0 for o, f/g → ∞ for ω.
Efficiency class
A standard growth rate such as log n, n, n log n, n², 2ⁿ, used to group algorithms.
Recurrence
An equation giving T(n) in terms of T at smaller sizes, with an initial condition.
Backward substitution
Solving a recurrence by substituting it into itself until the base case is reached; also called the iteration method.
Substitution method
Solving a recurrence by guessing the answer and proving it by induction.
Recursion tree
A tree of the calls of a recursive algorithm, each node labelled with its own cost, summed level by level.
Master theorem
A rule giving the order of T(n) = aT(n/b) + f(n) by comparing f(n) with nlogb a.
Regularity condition
a·f(n/b) ≤ c·f(n) for some c < 1; required in Case 3 of the master theorem.
Horner's rule
Evaluating a degree-n polynomial as nested products, with n multiplications and n additions.
