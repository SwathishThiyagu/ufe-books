About this unit

Many problems ask for an arrangement that obeys rules: eight queens that do not attack, a timetable with no clashes, a tour that visits every city once. The number of possible arrangements grows exponentially, so trying them all is hopeless beyond tiny inputs. This unit teaches two ways to search such spaces cleverly. Chapter 5.1 sets up the state-space tree and the general backtracking method. Chapters 5.2 to 5.5 apply it to four classic problems: N-Queens, sum of subsets, graph colouring and Hamiltonian cycles. Chapter 5.6 turns the same tree into branch and bound for optimisation problems, the 0/1 knapsack and the travelling salesman, and Chapter 5.7 applies it to the assignment problem and compares it with the Hungarian method. Most of these problems are NP-complete or NP-hard (Unit 7, Reductions and NP-complete problems), which is why a smart exponential search is still the practical tool.

5.1 Backtracking: general method and state-space tree

Backtracking builds an answer one decision at a time and undoes the latest decision as soon as the partial answer breaks a rule. It is a depth-first walk over the tree of all choices, the state-space tree, that never enters a subtree whose root already breaks a rule. Sudoku solvers, timetable planners and the search inside SAT and constraint solvers work this way.

You need: recursion and recursion trees (Unit 1, Analysis of non-recursive and recursive algorithms). Depth-first search (Unit 6, Breadth-first and depth-first search) helps but is not required.

The answer as a tuple, and two kinds of constraint

The answer is usually an n-tuple (x₁, x₂, …, xₙ), each xᵢ chosen from a finite set Sᵢ. In N-Queens, xᵢ is the column of the queen in row i; in sum of subsets, xᵢ = 1 if item i is taken, else 0.

  • Explicit constraints restrict each xᵢ on its own: they say which set Sᵢ it comes from, such as xᵢ ∈ {0, 1} or xᵢ ∈ {1, 2, …, n}. Together they define the solution space, |S₁| × |S₂| × … × |Sₙ| tuples.
  • Implicit constraints relate the xᵢ to one another and decide which tuples are real answers, such as "no two queens on one diagonal".

Brute force generates every tuple and then tests it. Backtracking tests partial tuples: if (x₁, …, xₖ) already breaks an implicit constraint, no choice of xₖ₊₁ … xₙ can repair it, so every tuple below that point is skipped. When the best answer is wanted, a criterion function P(x₁, …, xₙ) is also maximised or minimised.

The state-space tree and its vocabulary

The root is the empty tuple, the edges below a node at level k − 1 are the values of xₖ, and a node at level k is the partial tuple (x₁, …, xₖ). The terms are those of the Horowitz and Sahni textbook.

  • Problem state: any node of the tree. State space: all paths from the root to other nodes.
  • Solution state: a node whose path is a complete tuple of the solution space. Answer state: a solution state that also satisfies the implicit constraints.
  • Live node: generated, but its children are not all generated yet. E-node (expanding node): the live node whose children are being generated now. Dead node: killed, or all its children done.
  • Bounding function Bₖ(x₁, …, xₖ): false when the partial tuple cannot lead to an answer, and the node is killed.

In backtracking, the first promising child of the E-node becomes the new E-node at once (depth first). Branch and bound (Chapter 5.6) keeps one E-node until all its children are generated.

A fixed-tuple form has n entries of 0 or 1 with answers only at the leaves; a variable-tuple form lists the chosen indices, such as (1, 2, 4), and every node is a solution state. A binary (subset) tree with n levels has 2ⁿ⁺¹ − 1 nodes; a permutation tree has 1 + n + n(n − 1) + … + n! nodes, 65 for n = 4.

The general algorithm

To set up any backtracking solution, fix four things: what xₖ means, the implicit constraints, the bounding function Bₖ, and the order in which values are tried. The recursive template (Horowitz and Sahni style) is called as Backtrack(1):

Algorithm Backtrack(k)
// x[1..k-1] are already chosen.
// T(x[1..k-1]) is the set of values x[k] may take.
{
  for each x[k] in T(x[1..k-1]) do
    if (B_k(x[1..k]) is true) then
    {
      if (x[1..k] is a path to an answer node) then write (x[1..k]);
      if (k < n) then Backtrack(k + 1);
    }
}

When every value of x[k] has been tried, the call returns and the caller tries its next value: that return is the backtrack. An iterative version moves a level pointer k up and down instead, stopping at k = 0.

How much time it takes

Time depends on four things: generating the next xₖ, the number of xₖ allowed by the explicit constraints, evaluating Bₖ, and the number of xₖ that pass Bₖ. The first three are usually polynomial; the fourth decides. In the worst case the whole tree is searched: O(p(n) · 2ⁿ) for a subset tree, O(p(n) · n!) for a permutation tree, where p(n) is the work per node. Pruning does not improve this bound; it cuts the nodes searched on typical inputs.

That number varies with the input, so Knuth proposed a Monte Carlo estimate. Walk one random path from the root; if the root has m₁ promising children pick one, if that has m₂ pick one, and so on. The estimate is 1 + m₁ + m₁m₂ + m₁m₂m₃ + …, summed down to the leaf. In Figure 5.1.1 the walk through 1 has m₁ = 2, m₂ = 1, m₃ = 2 and gives 1 + 2 + 2 + 4 = 9; the walk 0 → 01 gives 11; the walk 0 → 00 gives 1 + 2 + 4 + 8 = 15. With probabilities ½, ¼, ¼ the average is 4.5 + 2.75 + 3.75 = 11, exactly the 11 promising nodes.

Worked example

Question. Ravi must do hostel night duty on some of the four nights Monday to Thursday, but the warden never allows two duty nights in a row. Use backtracking to list every duty plan. (a) Define xᵢ, the explicit and implicit constraints and the bounding function. (b) Count the nodes generated and compare with the full state-space tree. (6 marks)

  1. xᵢ = 1 if Ravi is on duty on night i, else 0, for i = 1 to 4. Explicit constraint: xᵢ ∈ {0, 1}, so there are 2⁴ = 16 tuples. Implicit constraint: no i with xᵢ = xᵢ₊₁ = 1. Bounding function: Bₖ is false when xₖ₋₁ = xₖ = 1.
  2. Try 0 before 1. Depth first: 0 → 00 → 000 → 0000 ✓, 0001 ✓; 001 → 0010 ✓, 0011 killed; 01 → 010 → 0100 ✓, 0101 ✓; 011 killed. Then 1 → 10 → 100 → 1000 ✓, 1001 ✓; 101 → 1010 ✓, 1011 killed; 11 killed.
  3. Answers in the order found: 0000, 0001, 0010, 0100, 0101, 1000, 1001, 1010, that is 8 plans.
  4. Promising nodes by level: 1 + 2 + 3 + 5 + 8 = 19. Killed: 11, 011, 0011, 1011, that is 4. So 23 nodes are generated against 2⁵ − 1 = 31 in the full tree; the 8 never made are 6 below 11 and 2 below 011.
  5. The counts 2, 3, 5, 8 are Fibonacci numbers: for 20 nights there are 17 711 plans out of 2²⁰ = 1 048 576 tuples, so pruning saves more as n grows.

Exam traps

  • Backtracking is depth-first search with a bounding function; without the bounding function it is plain exhaustive search.
  • Explicit constraints are the sets each xᵢ comes from; implicit constraints relate the xᵢ to each other. Do not swap them.
  • Every answer state is a solution state, but not every solution state is an answer state.
  • In backtracking an E-node hands over to its first promising child at once; in branch and bound an E-node stays the E-node until it is dead. This is the favourite "differentiate" question.
  • Pruning does not change the exponential worst case; never write a polynomial bound.

Beyond the syllabus

Modern solvers keep the backtracking skeleton and prune harder. Constraint solvers use forward checking and constraint propagation to shrink the sets Sᵢ before choosing; SAT solvers use conflict-driven clause learning, which remembers why a branch failed and jumps back several levels. Knuth's Dancing Links (Algorithm X) is a fast backtracking scheme for exact-cover puzzles such as Sudoku. Search next for "constraint propagation", "CDCL SAT solver" and "Dancing Links". 5.2 N-Queens problem

The N-Queens problem asks for every way to place n queens on an n × n chessboard so that no two attack each other: no two share a row, a column or a diagonal. It is the standard first example of backtracking because the rules are easy to state, the tree is a permutation tree, and the pruning is dramatic. It is also a common benchmark for constraint and SAT solvers, and a favourite lab program.

You need: Chapter 5.1 (state-space tree, bounding function, the Backtrack template).

Formulation

No two queens may share a row, and there are n queens for n rows, so every row holds exactly one queen. Number the rows and columns 1 to n and let xᵢ = the column of the queen in row i. The answer is the tuple (x₁, …, xₙ).

  • Explicit constraint: xᵢ ∈ {1, 2, …, n}. That gives nⁿ tuples, 8⁸ = 16 777 216 for n = 8.
  • Implicit constraint 1, columns: all xᵢ are different. The tuples are now permutations, n! of them, 40 320 for n = 8.
  • Implicit constraint 2, diagonals: for every pair of rows i ≠ j, |xᵢ − xⱼ| ≠ |i − j|.

Why the diagonal test works: along a "\" diagonal, row − column is constant, so i − xᵢ = j − xⱼ, that is i − j = xᵢ − xⱼ. Along a "/" diagonal, row + column is constant, so i − j = xⱼ − xᵢ. Both cases together say |xᵢ − xⱼ| = |i − j|: the column distance equals the row distance.

The algorithm in C

The bounding function is place(k, i): can the queen of row k go in column i, given the queens already in rows 1 to k − 1? It checks the column and both diagonals against each earlier row, so it costs O(k). The recursive function nqueens(k) is the Backtrack template of Chapter 5.1 with rows as levels. The C program below solves n = 4:

#include <stdio.h>
#include <stdlib.h>

int x[20], n, count = 0;

int place(int k, int i) {          /* row k, column i */
    for (int j = 1; j < k; j++)
        if (x[j] == i || abs(x[j] - i) == abs(j - k))
            return 0;                /* same column or diagonal */
    return 1;
}

void nqueens(int k) {
    for (int i = 1; i <= n; i++) {
        if (place(k, i)) {
            x[k] = i;
            if (k == n) {
                count++;
                for (int j = 1; j <= n; j++) printf("%d ", x[j]);
                printf("\n");
            } else {
                nqueens(k + 1);
            }
        }
    }
}

int main(void) {
    n = 4;
    nqueens(1);
    printf("Total solutions: %d\n", count);
    return 0;
}

Output:

2 4 1 3
3 1 4 2
Total solutions: 2

Each line is (x₁, x₂, x₃, x₄). The second solution is the mirror image of the first: column c becomes 5 − c. Changing n = 4 to 8 prints all 92 solutions of the eight-queens puzzle, the first being 1 5 8 6 3 7 2 4.

The search for n = 4

Counting every node that passes place, the search for both 4-queens solutions makes 17 nodes including the root, against 65 in the permutation tree and 341 in the 4⁴ tree. For n = 8 the same program makes 2057 nodes to find all 92 solutions; the permutation tree has 109 601 nodes and the 8⁸ tree 19 173 961.

Time. The tree has at most n! leaves and place costs O(n), so O(n · n!) is a safe upper bound; many books simply write O(n!). Keeping three Boolean arrays, used columns, used i − xᵢ diagonals and used i + xᵢ diagonals, makes each check O(1).

Exam traps

  • The diagonal test needs absolute values on both sides, |xᵢ − xⱼ| = |i − j|. Writing xᵢ − xⱼ = i − j catches only one diagonal direction.
  • n = 2 and n = 3 have no solution; every n ≥ 4 has at least one.
  • Eight queens: 92 solutions, but only 12 distinct ones when rotations and reflections count as the same.
  • Do not confuse the number of nodes generated with the number of solutions; examiners ask for both.
  • With one queen per row and distinct columns the tree is a permutation tree with n! leaves, not nⁿ.

5.3 Sum of subsets problem

Given n positive numbers w₁, …, wₙ (called weights) and a target m, the sum of subsets problem asks for every subset whose sum is exactly m. A shop that receives a single UPI payment of ₹30 000 and wants to know which pending invoices it settles is solving this problem. Backtracking solves it with two simple tests that need the weights in increasing order. The problem is NP-complete (Unit 7, Reductions and NP-complete problems), and it is the core of the 0/1 knapsack problem.

You need: Chapter 5.1 (fixed-tuple formulation, bounding functions).

Formulation and the two bounding tests

Use the fixed-tuple form: xᵢ = 1 if wᵢ is in the subset, else 0, and the answers are the tuples with Σ wᵢxᵢ = m. First sort the weights so that w₁ ≤ w₂ ≤ … ≤ wₙ. At a node of level k, after x₁ … xₖ are decided, keep two numbers:

  • s = Σ wᵢxᵢ over i ≤ k, the sum chosen so far;
  • r = Σ wᵢ over i > k, the total of the weights not yet decided.

The node is promising only if both tests pass:

  1. Not too small: s + r ≥ m. If even taking every remaining weight cannot reach m, the node is dead.
  2. Not too large: s + wₖ₊₁ ≤ m (or s = m already). Because the weights are sorted, wₖ₊₁ is the smallest remaining weight; if it overshoots, every later weight overshoots too.

Figure 5.3.1 shows the whole search for a small instance.

The algorithm

Horowitz and Sahni's SumOfSub carries s and r as parameters, so each call costs O(1). In a call (s, k, r), s is the sum of the weights chosen among w₁ … wₖ₋₁ and r = wₖ + … + wₙ. It tests a child before making it, so it never calls on a dead node. Start with SumOfSub(0, 1, Σwᵢ), assuming w₁ ≤ m ≤ Σwᵢ.

Algorithm SumOfSub(s, k, r)
{
  // left child: take w[k]
  x[k] := 1;
  if (s + w[k] = m) then write (x[1..k]);          // subset found
  else if (s + w[k] + w[k+1] <= m) then
      SumOfSub(s + w[k], k + 1, r - w[k]);
  // right child: leave out w[k]
  if ((s + r - w[k] >= m) and (s + w[k+1] <= m)) then
  {
      x[k] := 0;
      SumOfSub(s, k + 1, r - w[k]);
  }
}

Complexity. In the worst case every node of the binary tree is visited: 2ⁿ⁺¹ − 1 nodes at O(1) each, so O(2ⁿ) time, plus O(n) to print each answer. The dynamic-programming method of Unit 4 (0/1 knapsack problem) takes O(n · m) time, which is pseudo-polynomial: fast when m is small, hopeless when m is huge.

Exam traps

  • Sort the weights first. Without sorting, "the next weight overshoots" does not prove that every later weight overshoots.
  • Both tests are needed: "too large" uses the next weight, "too small" uses r, the sum of all undecided weights. Forgetting r is the most common slip.
  • In SumOfSub(s, k, r), r includes wₖ itself; at the first call r = Σwᵢ.
  • Write each answer both as the subset and as the 0/1 vector; the printed x[1..k] leaves out the trailing zeros.
  • O(n · m) dynamic programming is not polynomial, because m can be exponential in the number of digits of the input.

5.4 Graph colouring

Graph colouring gives each vertex a colour so that the two ends of every edge get different colours. The m-colouring problem asks whether this can be done with m colours and lists the ways; the smallest m that works is the chromatic number χ(G). Exam timetables, register allocation in compilers, frequency planning for mobile towers and colouring a map of states all reduce to it.

You need: Chapter 5.1, and the adjacency matrix (Unit 6, Graph representations: adjacency matrix and adjacency lists).

Formulation

Let G be an undirected graph with vertices 1 to n and adjacency matrix G[i, j] (1 when i and j are joined, else 0). Number the colours 1 to m and let xᵢ = the colour of vertex i.

  • Explicit constraint: xᵢ ∈ {1, 2, …, m}. The state-space tree is an m-ary tree of depth n with mⁿ leaves.
  • Implicit constraint: xᵢ ≠ xⱼ whenever G[i, j] = 1.
  • Bounding function: colour vertex k only with a colour not used by an already coloured neighbour.

Two versions are asked. The m-colourability decision problem: can G be coloured with m colours? The m-colourability optimisation problem: find the smallest such m, the chromatic number. Useful facts: χ ≤ 2 exactly when G has no odd cycle (G is bipartite), which breadth-first search checks in linear time; a triangle forces χ ≥ 3; every planar graph, and so every map, needs at most 4 colours (the four colour theorem, proved by Appel and Haken in 1976 with computer help). Deciding whether χ ≤ 3 is NP-complete (Unit 7).

In a map, each region becomes a vertex and two regions that share a border become an edge, so map colouring is graph colouring of a planar graph.

The algorithm

Horowitz and Sahni's version keeps x[1..n] initialised to 0, colours vertices in the order 1 to n, and uses NextValue(k) to move x[k] to the next colour that no coloured neighbour of k has. When x[k] comes back as 0, no colour is left and the search backtracks. Call mColoring(1).

Algorithm mColoring(k)
{
  repeat {
    NextValue(k);                     // next legal colour for vertex k
    if (x[k] = 0) then return;        // none left: backtrack
    if (k = n) then write (x[1..n]);  // all vertices coloured
    else mColoring(k + 1);
  } until (false);
}

Algorithm NextValue(k)
{
  repeat {
    x[k] := (x[k] + 1) mod (m + 1);   // try the next colour
    if (x[k] = 0) then return;        // all m colours tried
    for j := 1 to n do
      if ((G[k, j] = 1) and (x[k] = x[j])) then break;
    if (j = n + 1) then return;       // no clash: colour found
  } until (false);
}

Complexity. The tree has 1 + m + m² + … + mⁿ⁻¹ internal nodes, and NextValue at each costs O(m · n) (m colours, n neighbours to check). So the worst case is O(n · mⁿ). Fixing x₁ = 1 is safe, because colour names can be swapped, and it cuts the work by a factor of m.

5.5 Hamiltonian cycles

A Hamiltonian cycle is a round trip through a graph that visits every vertex exactly once and returns to the start. Backtracking builds the trip one vertex at a time and abandons a partial path as soon as it cannot be extended.

You need: Chapter 5.1, and the NextValue pattern of Chapter 5.4 (Graph colouring).

Definitions and quick tests

In a graph G with n vertices, a Hamiltonian cycle is a sequence v₁, v₂, …, vₙ, v₁ in which the n vertices are all different and every consecutive pair, including vₙ and v₁, is joined by an edge. A Hamiltonian path visits every vertex once but need not return. The name comes from W. R. Hamilton's 1857 Icosian game, a puzzle of touring the corners of a dodecahedron.

Do not confuse it with an Euler circuit, which uses every edge once and has an easy test: the graph is connected and every degree is even. No such easy test is known for Hamiltonian cycles. There are only partial ones:

  • Dirac's theorem (sufficient): if n ≥ 3 and every vertex has degree ≥ n/2, G has a Hamiltonian cycle.
  • Ore's theorem (sufficient): if n ≥ 3 and deg(u) + deg(v) ≥ n for every pair of non-adjacent vertices u, v, G has a Hamiltonian cycle.
  • Necessary: G is connected, no vertex has degree 1, and no single vertex (a cut vertex) disconnects G when removed. A vertex of degree 2 forces both its edges into the cycle.

Formulation and algorithm

A cycle can start anywhere, so fix x₁ = 1; xₖ for k = 2 to n is the k-th vertex visited. Explicit constraint: xₖ ∈ {2, …, n}. Implicit constraints: the xₖ are all different, G[xₖ₋₁, xₖ] = 1 for every k, and at the last step G[xₙ, x₁] = 1. Horowitz and Sahni's NextValue(k) finds the next vertex for position k that satisfies all three:

Algorithm Hamiltonian(k)
{
  repeat {
    NextValue(k);                      // next vertex for position k
    if (x[k] = 0) then return;         // none: backtrack
    if (k = n) then write (x[1..n], x[1]);
    else Hamiltonian(k + 1);
  } until (false);
}

Algorithm NextValue(k)
{
  repeat {
    x[k] := (x[k] + 1) mod (n + 1);
    if (x[k] = 0) then return;
    if (G[x[k-1], x[k]] = 1) then      // joined to the previous vertex?
    {
      for j := 1 to k - 1 do           // not visited before?
        if (x[j] = x[k]) then break;
      if (j = k) then
        if ((k < n) or (G[x[n], x[1]] = 1)) then return;  // last one must close
    }
  } until (false);
}

Start with x[1] = 1, x[2..n] = 0 and call Hamiltonian(2). Complexity: the tree orders the other n − 1 vertices, so it has up to (n − 1)! leaves and the worst case is exponential, about O(n!) up to a polynomial factor. Dynamic programming over subsets (Unit 4, Travelling salesman problem) answers the same question in O(n² · 2ⁿ), still exponential but far smaller for n = 20.

Exam traps

  • Hamiltonian visits every vertex once; Euler uses every edge once. Mixing them up costs the whole answer.
  • At the last level, check the closing edge xₙ–x₁. A path through all vertices is not yet a cycle.
  • Fixing x₁ = 1 is safe, but each undirected cycle is still printed twice, once in each direction.
  • Dirac's and Ore's conditions are sufficient, not necessary: the 6-cycle has every degree 2 < 6/2, yet it is itself Hamiltonian.
  • A vertex of degree 1, or a cut vertex, rules out a Hamiltonian cycle at once.

5.6 Branch and bound: knapsack and travelling salesman

Branch and bound searches the same state-space tree as backtracking, but for optimisation problems. At every node it computes a bound, a limit on how good any answer below that node can be, and drops the node when the bound cannot beat the best answer found so far. Route planners and integer-programming solvers are built on it.

You need: Chapter 5.1 (live node, E-node), the fractional knapsack (Unit 3, Fractional knapsack problem) and the 0/1 knapsack (Unit 4, 0/1 knapsack problem).

The method

For maximisation each node gets an upper bound ub on any solution below it; for minimisation a lower bound (Horowitz and Sahni write ĉ, an estimate never above the true cost). best is the value of the best complete solution so far. Live nodes are kept in a queue (FIFO branch and bound), a stack (LIFO) or a priority queue by bound (LC, least cost). LC usually makes the fewest nodes and is the version examiners want.

  1. Compute the root's bound and make the root live.
  2. Take the live node with the best bound as the E-node.
  3. Generate all its children and compute their bounds; a complete solution better than best replaces best.
  4. Kill children that are infeasible or whose bound is no better than best; the rest become live.
  5. Repeat until no live node's bound beats best. Then best is optimal.

The unit summary compares branch and bound with backtracking point by point.

0/1 knapsack

Items 1 to n have weights wᵢ and values vᵢ; the bag holds W. Choose xᵢ ∈ {0, 1} to maximise Σvᵢxᵢ with Σwᵢxᵢ ≤ W. Sort the items by value per unit weight, vᵢ/wᵢ, largest first. A node at level i has decided items 1 to i and has total weight w and value v.

ub = v + (W − w) × (vᵢ₊₁ / wᵢ₊₁)

the value so far plus the free capacity filled at the best remaining ratio; no remaining item pays more per kilogram, so nothing below the node can exceed ub. Horowitz and Sahni use the tighter fractional-knapsack value of the remaining items. Both are valid; the tighter one prunes more.

Worked example 1: knapsack

Question. A courier bike carries at most W = 10 kg. Parcels: item 1 weighs 4 kg and pays ₹40, item 2 is 7 kg for ₹42, item 3 is 5 kg for ₹25, item 4 is 3 kg for ₹12. Find the best load by LC branch and bound. (8 marks)

  1. Ratios vᵢ/wᵢ = 10, 6, 5, 4 ₹ per kg: already in decreasing order.
  2. Root: w = 0, v = 0, ub = 0 + 10 × 10 = 100.
  3. Expand the root. With item 1: w = 4, v = 40, ub = 40 + 6 × 6 = 76. Without: ub = 0 + 10 × 6 = 60.
  4. Expand ub 76. With item 2: w = 11 > 10, infeasible. Without: w = 4, v = 40, ub = 40 + 6 × 5 = 70.
  5. Expand ub 70. With item 3: w = 9, v = 65, ub = 65 + 1 × 4 = 69. Without: ub = 40 + 6 × 4 = 64.
  6. Expand ub 69. With item 4: w = 12, infeasible. Without: w = 9, v = 65, all items decided, so best = 65.
  7. Live nodes with ub 64 and 60 are ≤ 65: prune. Optimum: items 1 and 3, 9 kg, ₹65, with 9 of the 31 nodes of the full tree made.

Greedy by vᵢ/wᵢ (Unit 3) is optimal only for the fractional version, and dynamic programming (Unit 4) is exact in O(n · W).

Travelling salesman with reduced cost matrices

Given costs cᵢⱼ from city i to city j (cᵢᵢ = ∞), the travelling salesman problem (TSP) asks for the cheapest tour from city 1 through every city once and back.

  1. Reduce: subtract each row's minimum from the row, then each column's minimum from the column; let r be the total. Every tour uses one entry per row and per column, so every tour falls by exactly r, and r is a lower bound. The root gets ĉ = r.
  2. Branch on edge (i, j): in the parent's reduced matrix A, set row i and column j to ∞ (leave i once, enter j once) and A(j, 1) = ∞ (no early return). Reduce again, subtracting r′.
  3. Bound: ĉ(S) = ĉ(R) + A(i, j) + r′, with A(i, j) read from the parent's reduced matrix.

5.7 Assignment problem

The assignment problem has n people, n jobs and a cost for every person–job pair, and asks for a one-to-one matching of people to jobs with the least total cost. Allotting invigilators to exam halls, delivery agents to orders or machines to tasks are assignment problems. Brute force tries all n! matchings; branch and bound prunes them with a simple row-minimum bound, and the Hungarian method solves the problem exactly in polynomial time.

You need: Chapter 5.6 (least-cost branch and bound).

The problem

Let C be an n × n cost matrix, where cᵢⱼ is the cost of giving job j to person i. An assignment gives person i the job jᵢ, with all jᵢ different, so it is a permutation of the columns. Its cost is Σ cᵢ,ⱼᵢ. Put another way: pick one entry in each row, no two in the same column, with the smallest sum. There are n! assignments: 24 for n = 4, but 3 628 800 for n = 10.

Branch and bound

A node at level k has given rows 1 to k distinct columns. Its lower bound is

lb = (cost of the jobs already assigned)
   + Σ over every unassigned row of its smallest entry in a column not yet taken

Each remaining person must cost at least their cheapest free job, so no complete assignment below the node can cost less than lb. The bound ignores clashes between the remaining people (two of them may want the same column), which is why it is only a bound. LC branch and bound then expands the live node with the smallest lb, records the first complete assignment as best, and prunes every node with lb ≥ best.

The Hungarian method

Kuhn's Hungarian method (1955) solves the assignment problem exactly in O(n³) time with a careful implementation. It rests on the same fact as the TSP reduction of Chapter 5.6: subtracting a constant from a whole row or column lowers every assignment by that constant, so the optimal assignment does not change.

  1. Subtract each row's minimum from its row; then each column's minimum from its column.
  2. Cover all zeros with the fewest horizontal and vertical lines.
  3. If the number of lines is n, choose n zeros with one in each row and column: that is an optimal assignment. Stop.
  4. Otherwise let k be the smallest uncovered entry. Subtract k from every uncovered entry, add k to every entry where two lines cross, and go back to step 2.

On the invigilator matrix, the row minima 2, 3, 1, 4 and then a column-1 minimum of 3 give

a:  4  0  5  6
b:  0  1  0  4
c:  1  7  0  7
d:  0  2  5  0

The zeros at (a, 2), (b, 1), (c, 3), (d, 4) lie in different rows and columns, so 4 lines are needed and the assignment a→2, b→1, c→3, d→4 is optimal. Its cost equals the total subtracted, 10 + 3 = 13, matching branch and bound.

Question. Solve the assignment problem with rows P1 = (4, 1, 3), P2 = (2, 0, 5), P3 = (3, 2, 2) by the Hungarian method. (6 marks)

Exam traps

  • In the branch and bound lb, each unassigned row's minimum is taken only over the columns still free.
  • Prune when lb ≥ best; a node whose lb equals best cannot do better, so it need not be expanded.
  • Hungarian method: reduce rows first, then columns, and use the fewest lines; any cover with more lines than needed hides the need to adjust.
  • For a profit (maximisation) matrix, first replace every entry by (largest entry − entry), then minimise.
  • If people and jobs are unequal in number, add dummy rows or columns of zeros to make the matrix square.

Backtracking versus branch and bound

BacktrackingBranch and bound
Solvesfind all or any feasible answersfind the optimal answer
Orderdepth firstFIFO, LIFO or least cost first
E-nodehands over at once to its first promising childstays until all its children are generated
Kills a node whenit breaks a constraintit is infeasible or its bound cannot beat best
ExamplesN-Queens, sum of subsets, colouring, Hamiltonian cycles0/1 knapsack, TSP, assignment
  1. Backtracking builds a solution tuple one component at a time and kills a partial tuple the moment the bounding function says no answer lies below it.
  2. The state-space tree is a subset tree (2ⁿ leaves) or a permutation tree (n! leaves); the worst case stays exponential, but pruning makes typical searches small.
  3. N-Queens uses one queen per row and the test |xᵢ − xⱼ| ≠ |i − j|; four queens have 2 solutions and eight queens 92.
  4. Sum of subsets needs sorted weights and two tests: s + r ≥ m and s + wₖ₊₁ ≤ m.
  5. Graph colouring and Hamiltonian cycles share the NextValue pattern: try the next value, check it against the earlier choices, return 0 when none is left.
  6. Branch and bound is for optimisation: every node gets a bound, and least-cost search expands the most promising node and prunes any whose bound cannot beat the best so far.
  7. Knapsack uses the upper bound v + (W − w)(vᵢ₊₁/wᵢ₊₁); the TSP uses reduced cost matrices, ĉ(S) = ĉ(R) + A(i, j) + r′.
  8. The assignment problem can be solved by branch and bound with row-minimum bounds or, in O(n³), by the Hungarian method.

Remember and understand

Understand 1. Explain the general method of backtracking. Define solution space, state-space tree, answer state, live node, E-node, dead node and bounding function, and write the recursive backtracking algorithm. 12 marks

Answer as a tuple (x₁, …, xₙ); explicit constraints give the solution space, implicit constraints the answers. The tree: root = empty tuple, level k = (x₁, …, xₖ); solution states and answer states. Live, E- and dead nodes; Bₖ kills a node with no answer below it. Backtracking = depth-first generation with Bₖ. Backtrack(k) pseudocode with the loop over T(x[1..k−1]). Time depends on four factors; worst case O(p(n) · 2ⁿ) or O(p(n) · n!). A small tree such as Figure 5.1.1 earns the diagram marks.

Understand 2. Differentiate backtracking and branch and bound. Explain FIFO, LIFO and LC branch and bound with an example. 10 marks

The comparison table of the unit summary (purpose, order, E-node, killing rule, examples). FIFO keeps live nodes in a queue, LIFO in a stack, LC in a priority queue ordered by the bound ĉ or ub. Example: LC on the knapsack of Chapter 5.6 makes 9 nodes; FIFO would expand every node level by level until a solution exists to prune with. Mention that both use the same state-space tree and that LC usually needs the fewest nodes but more memory.

Understand 3. Write the m-colouring algorithm with NextValue and derive its time complexity. Explain the chromatic number and the four colour theorem. 10 marks

Formulation xᵢ = colour of vertex i; implicit constraint on edges. mColoring(k) and NextValue(k) as in Chapter 5.4, with x[k] = 0 meaning no colour left. Internal nodes Σ mⁱ for i = 0 to n − 1, NextValue O(mn), so O(n · mⁿ). χ(G) = least m; χ ≤ 2 iff no odd cycle; planar graphs need at most 4 colours (Appel and Haken, 1976); 3-colourability is NP-complete. A small worked colouring.

Remember 4. Write the backtracking algorithm for Hamiltonian cycles. How does a Hamiltonian cycle differ from an Euler circuit? State Dirac's theorem. 8 marks

x₁ = 1; NextValue checks the edge from xₖ₋₁, that the vertex is new, and at k = n the edge back to x₁. Hamiltonian: every vertex once; Euler: every edge once, with the easy even-degree test. Dirac: n ≥ 3 and every degree ≥ n/2 implies a Hamiltonian cycle; sufficient, not necessary. Worst case exponential, about O(n!).

Apply 5. Draw the state-space tree for 4-queens up to the first solution, give all solutions, and write the place function. How many solutions does 8-queens have? 12 marks

Tree of Figure 5.2.1: x₁ = 1 fails through (1, 3) and (1, 4, 2); x₁ = 2 gives (2, 4, 1, 3). Second solution (3, 1, 4, 2), the mirror image. place(k, i) returns false if some j < k has x[j] = i or |x[j] − i| = |j − k|. Eight queens: 92 solutions, 12 up to symmetry.

Apply 6. Find all subsets of w = {7, 11, 13, 24} with sum m = 31 by backtracking, and draw the part of the tree generated. 10 marks

Sorted already; Σw = 55. Take 7, take 11 (18), take 13: 31, print (1, 1, 1). Back: 7 without 11, 13 fails (20 + 24 > 31), skip 13, take 24: 31, print (1, 0, 0, 1). Without 7: 11 + 13 = 24 and 24 + 24 > 31; 11 + 24 = 35 > 31; 13 + 24 > 31 and the rest is too small. Answers {7, 11, 13} and {7, 24}.

Apply 7. A wheel graph has a hub h joined to every vertex of the cycle 1–2–3–4–5–1. Show by backtracking that 3 colours fail, and find its chromatic number. 8 marks

Colour h first: h = 1. The rim vertices may then use only colours 2 and 3; going round, 1 = 2, 2 = 3, 3 = 2, 4 = 3, and vertex 5 is next to 4 (3), 1 (2) and h (1): no colour. Backtracking through every choice fails the same way, because a 5-cycle is odd and needs 3 colours of its own. With m = 4: (h, 1, 2, 3, 4, 5) = (1, 2, 3, 2, 3, 4). χ = 4.

Apply 8. Solve the 0/1 knapsack with W = 16 and items (w, v) = (2, 40), (5, 30), (10, 50), (5, 10) by LC branch and bound, showing every bound. 12 marks

Ratios 20, 6, 5, 2. Root ub = 16 × 20 = 320. With 1: (2, 40), ub = 40 + 14 × 6 = 124; without 1: 96. With 1, 2: (7, 70), ub = 70 + 9 × 5 = 115; with 1 not 2: ub = 40 + 14 × 5 = 110. Under 115: with 3 weighs 17, infeasible; without 3: ub = 70 + 9 × 2 = 88. Under 110: with 3: (12, 90), ub = 90 + 4 × 2 = 98; without 3: 68. Under 98: with 4 infeasible; without 4: value 90, best = 90. The node 96 still beats 90, so expand it: children 85 and 80, both ≤ 90. Prune 88 and 68. Optimum items 1 and 3, 12 kg, value 90; 13 nodes made.

Analyze and evaluate

Analyze 11. Compare greedy, dynamic programming, backtracking and branch and bound for the 0/1 knapsack problem: correctness, time and when to prefer each. Use the instance of question 8. 12 marks

Greedy by ratio takes items 1, 2, then 4 (item 3 no longer fits): value 80, not optimal; the fractional greedy value 115 is only a bound (Unit 3). DP fills an n × W table, here 4 × 16, in O(n · W): exact, best when W is small (Unit 4). Backtracking is exact but O(2ⁿ) and prunes only on weight. Branch and bound is exact, prunes on value too, and made 13 of 31 nodes here; its worst case is still O(2ⁿ). Prefer DP for small integer W, branch and bound for large W or real-valued weights, greedy only for a quick estimate.

Analyze 12. Show that an algorithm for the TSP also decides whether a graph has a Hamiltonian cycle. What does this say about the TSP? 8 marks

From a graph G on n vertices, build a complete graph with cost 1 on the edges of G and 2 on the non-edges, in O(n²) time. G has a Hamiltonian cycle exactly when the cheapest tour costs n. So the TSP is at least as hard as the Hamiltonian cycle problem, which is NP-complete; the TSP is NP-hard (Unit 7). Branch and bound stays exact, but no bound makes its worst case polynomial unless P = NP.

Analyze 13. Analyse how the order of choices affects backtracking, using sum of subsets, graph colouring and N-Queens. 10 marks

Order never changes the set of answers, only the nodes made and which answer comes first. Sorting weights makes the "too large" test valid and kills nodes earlier. In colouring, taking the most constrained vertex first (highest degree, or DSATUR) meets conflicts near the root, where a failure removes a big subtree: the fail-first principle. In N-Queens, column order changes which solution is printed first, and symmetry lets x₁ stop at ⌈n/2⌉. Knuth's estimate can compare two orders on real inputs before a full run.

Evaluate 14. "Branch and bound is always better than backtracking." Evaluate this claim. 8 marks

False as a general rule. Branch and bound needs an objective and a bound; for "list all answers" problems such as N-Queens it adds nothing. LC and FIFO keep many live nodes, so memory can grow exponentially, while backtracking needs only an O(n) stack. Each node costs more (bound computation, priority queue). With a weak bound it explores almost as much as backtracking. For optimisation with a tight bound, though, it usually wins clearly, as the knapsack and TSP examples show.

Glossary

Answer state
A solution state whose tuple also satisfies every implicit constraint.
Assignment problem
Match n people to n jobs one-to-one at the least total cost.
Backtracking
Depth-first generation of the state-space tree that kills any node failing the bounding function.
Bounding function
A test Bₖ on a partial tuple; false means no answer lies below the node.
Branch and bound
Search of the state-space tree for an optimum, pruning nodes whose bound cannot beat the best solution found.
Chromatic number
χ(G), the least number of colours that colour a graph so that adjacent vertices differ.
Dead node
A generated node that will not be expanded, because it was killed or all its children are generated.
E-node
The live node whose children are being generated now.
Explicit constraint
A rule saying which set each xᵢ is chosen from.
FIFO branch and bound
Branch and bound that keeps live nodes in a queue (breadth first).
Hamiltonian cycle
A cycle that visits every vertex exactly once and returns to the start.
Hungarian method
Kuhn's O(n³) method for the assignment problem by row and column reduction and covering zeros.
Implicit constraint
A rule relating the xᵢ to each other that decides which tuples are answers.
Knuth's estimate
1 + m₁ + m₁m₂ + … along a random path, an estimate of the number of nodes backtracking will make.
LC branch and bound
Least-cost search: always expand the live node with the best bound, using a priority queue.
Live node
A generated node whose children are not all generated yet.
Lower bound ĉ
For minimisation, a value no greater than the cost of any solution below a node.
m-colouring problem
Decide whether a graph can be coloured with m colours, and list the colourings.
N-Queens problem
Place n non-attacking queens on an n × n board.
Promising node
Levitin's term for a node that may still lead to an answer; otherwise non-promising.
Reduced cost matrix
A cost matrix with every row and column minimum subtracted, so each has a zero; the total subtracted is a lower bound on any tour.
Solution space
All tuples that satisfy the explicit constraints.
State-space tree
The tree whose nodes are partial tuples and whose root-to-node paths are the choices made.
Sum of subsets problem
Find every subset of given positive numbers whose sum equals a target m.
Travelling salesman problem
Find the cheapest tour visiting every city once and returning to the start.
Upper bound ub
For maximisation, a value no smaller than the value of any solution below a node.
