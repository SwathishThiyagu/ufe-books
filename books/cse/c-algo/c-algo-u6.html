6.1 Graph representations: adjacency matrix and adjacency lists

Before an algorithm can walk through a graph, the graph has to sit in memory. Two layouts are used almost everywhere: the adjacency matrix, an n × n table of 0s and 1s, and adjacency lists, one list of neighbours per vertex. The choice sets the running time of every graph algorithm in this unit. The others assume it from the data structures course.

You need: arrays and linked lists from the data structures course, and O-notation from Unit 1 (Asymptotic notations).

Terms

A graph G = (V, E) has a set V of vertices and a set E of edges; in this unit n = |V| and m = |E|. An undirected edge {u, v} works both ways; a directed edge (u, v) goes from u to v only. A weighted graph gives each edge a number w(u, v), such as a distance in km. The degree of a vertex counts its edges; in a directed graph, out-degree counts edges leaving and in-degree edges arriving. A graph is dense when m is near n² and sparse when m is near n.

Adjacency matrix

Number the vertices 1 to n. The matrix A is n × n with A[i][j] = 1 when (i, j) is an edge and 0 otherwise. An undirected graph gives a symmetric matrix. In a directed graph, row i sums to the out-degree of i and column i to its in-degree. A weighted graph stores w(i, j) in place of 1 and ∞ for no edge; Floyd–Warshall (Unit 4) works on this matrix. Space is n² entries however few edges exist; an edge test takes O(1); listing the neighbours of i scans a whole row, O(n).

Adjacency lists

An array Adj[1..n] of linked lists, where Adj[u] holds every v with (u, v) an edge. An undirected edge appears in both endpoints' lists, so there are 2m nodes (m for a directed graph) and the space is Θ(n + m). Listing the neighbours of u takes O(deg u), so visiting every vertex and every list costs O(n + m); testing one pair (u, v) costs O(deg u). Exams also mention the edge list (just the m pairs, used by Kruskal's algorithm in Unit 3) and the incidence matrix (n × m, a 1 where a vertex lies on an edge).

6.2 Breadth-first and depth-first search

Breadth-first search (BFS) explores a graph in rings: first the start vertex, then every vertex one edge away, then two edges away, and so on. Depth-first search (DFS) runs along one path as far as it can, then backs up to the last junction with an unexplored edge. Both visit every reachable vertex and edge once, in O(n + m) time with adjacency lists. BFS gives shortest paths counted in edges; DFS gives discovery and finish times that expose cycles, topological order and connectivity.

You need: adjacency lists and matrices (Chapter 6.1); queues and stacks from the data structures course.

Breadth-first search

BFS from a source s keeps a FIFO queue of discovered vertices. Each vertex has a colour: white (not yet seen), grey (discovered, waiting in the queue) or black (all its neighbours examined). It also records d[v], the distance from s in edges, and π[v], the parent through which v was found.

  1. Make every vertex white with d = ∞ and π = nil. Colour s grey, set d[s] = 0 and enqueue s.
  2. While the queue is not empty, dequeue the front vertex u.
  3. For each v in Adj[u]: if v is white, colour it grey, set d[v] = d[u] + 1 and π[v] = u, and enqueue v.
  4. Colour u black and go back to step 2.

The queue always holds vertices whose d values are k or k + 1 for some k, with the k's in front. So every vertex at distance k is dequeued before any vertex at distance k + 1, and d[v] is the true shortest number of edges from s. Following π back from v gives a shortest path; the edges (π[v], v) form the BFS tree.

Time. Each vertex enters the queue once, O(n). Each adjacency list is scanned once when its vertex is dequeued, O(m) in total (2m nodes for an undirected graph). So BFS is O(n + m). On a matrix, scanning a row costs O(n) for each of n vertices, so O(n²).

In Python (the dictionary dist doubles as the colour: a vertex not in it is white):

from collections import deque
def bfs(adj, s):
    dist, parent = {s: 0}, {s: None}
    q = deque([s])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)
    return dist, parent

Depth-first search

DFS uses a stack, usually the recursion stack. A global clock gives each vertex a discovery time d[u] when it turns grey and a finish time f[u] when it turns black.

DFS(u):
    time = time + 1;  d[u] = time;  colour u grey
    for each v in Adj[u]:
        if v is white:  π[v] = u;  DFS(v)
    colour u black;  time = time + 1;  f[u] = time

DFS-ALL(G):  for each vertex u, if u is white: DFS(u)

The outer loop restarts the search in any part of the graph not yet reached, so the result is a DFS forest. The time is again O(n + m). The times obey the parenthesis theorem: for any two vertices, the intervals [d[u], f[u]] and [d[v], f[v]] are either disjoint or one nests inside the other, and v is a descendant of u exactly when its interval sits inside u's.

When DFS at u looks along an edge (u, v), the colour of v classifies the edge:

  • Tree edge: v is white; DFS goes to it.
  • Back edge: v is grey, an ancestor still on the stack. A directed graph has a cycle exactly when DFS finds a back edge.
  • Forward edge: v is black and a descendant of u (d[u] < d[v]).
  • Cross edge: v is black and in another branch (d[v] < d[u]).

In an undirected graph only tree and back edges occur, so any non-tree edge closes a cycle.

6.3 Topological sorting

A topological order of a directed graph lists its vertices so that every edge points forward: for each edge (u, v), u comes before v. It answers the everyday question "in what order can I do these jobs when some must come before others?" Course prerequisites, the build order of a software project, the order in which a spreadsheet recalculates its cells and the install order of packages are all topological sorts. An order exists exactly when the graph has no directed cycle, and two O(n + m) algorithms find one: reverse DFS finishing order, and Kahn's source-removal method.

You need: DFS with discovery and finish times (Chapter 6.2) and in-degree (Chapter 6.1).

DAGs, and why a cycle blocks an order

A DAG (directed acyclic graph) is a directed graph with no directed cycle. If a graph had a cycle v₁ → v₂ → … → v_k → v₁, then v₁ would have to come before v₂, which comes before … v_k, which comes before v₁: v₁ before itself, which is impossible. So only DAGs have topological orders.

Every DAG has at least one source, a vertex with in-degree 0. Walk backwards along incoming edges from any vertex; with no cycle you can never revisit a vertex, so with finitely many vertices the walk must stop at a vertex with no incoming edge. Put that source first, delete it, and the rest is still a DAG. Repeating this proves an order always exists, and it is also Kahn's algorithm. A DAG usually has many valid orders; any of them is a correct answer.

Method 1: reverse DFS finishing order

  1. Run DFS over the whole graph (the outer loop of Chapter 6.2), recording finish times f[u].
  2. Each time a vertex finishes, insert it at the front of a linked list.
  3. The list, which holds the vertices in decreasing order of f, is a topological order. If DFS ever meets a back edge, stop: the graph has a cycle.

Why it works. Take any edge (u, v) at the moment DFS explores it from u. Vertex v cannot be grey, because then (u, v) would be a back edge and the graph would have a cycle. If v is white, it becomes a descendant of u and finishes first. If v is black, it has already finished. Either way f[v] < f[u], so u comes before v in decreasing finish order. The cost is that of DFS, O(n + m).

Method 2: Kahn's algorithm (source removal)

  1. Compute the in-degree of every vertex by scanning all adjacency lists, O(n + m).
  2. Put every vertex of in-degree 0 into a queue.
  3. Remove a vertex u from the queue and append it to the output. For each edge (u, v), reduce in-degree[v] by 1; if it becomes 0, add v to the queue.
  4. Repeat step 3 until the queue is empty. If fewer than n vertices were output, the leftover vertices contain a cycle.

Each vertex enters the queue once and each edge decrements one counter once, so it also runs in O(n + m). In Python:

from collections import deque
def kahn(g):
    indeg = {u: 0 for u in g}
    for u in g:
        for v in g[u]:
            indeg[v] += 1
    q = deque(u for u in g if indeg[u] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == len(g) else None   # None: cycle

g = {'CO': ['OS'], 'DAA': [], 'DM': ['DAA'], 'DS': ['DAA', 'OS'],
     'M1': ['DM'], 'OS': [], 'PC': ['CO', 'DS']}
print(kahn(g))
['M1', 'PC', 'DM', 'CO', 'DS', 'DAA', 'OS']

6.4 Heaps, priority queues and heapsort

A binary heap is a complete binary tree kept in an array, in which every parent is at least as large as its children. The largest key therefore sits at the root, and inserting a key or removing the largest takes O(log n) time. That makes the heap the standard priority queue: the structure behind Dijkstra's and Prim's algorithms and Huffman coding (Unit 3), operating-system schedulers and event simulations. Heapsort uses the same array to sort in O(n log n) time even in the worst case, with no extra memory.

You need: binary trees from the data structures course; logarithms and summations from Unit 1; merge sort and quicksort from Unit 2 for comparison.

Shape and order

A max-heap satisfies two rules. Shape: the tree is complete, every level full except perhaps the last, which fills from the left; so a heap of n keys has height ⌊log₂ n⌋. Order: every parent's key is ≥ each child's key. A min-heap reverses the order, with the smallest key at the root.

Because the tree is complete, it fits in an array with no pointers. With positions 1 to n: parent(i) = ⌊i/2⌋, left(i) = 2i, right(i) = 2i + 1, and the leaves are positions ⌊n/2⌋ + 1 to n. With 0-based arrays (C, Java, Python) the formulas become (i − 1)/2, 2i + 1 and 2i + 2.

Repairs, building and the priority queue

Two repairs keep the order. Sift-down at position i (called MAX-HEAPIFY in Cormen et al.): if A[i] is smaller than its larger child, swap it with that child and continue from the child's position. Sift-up at i: while A[i] is larger than its parent, swap them and move up. Each walks one root-to-leaf path, so each is O(log n).

Building a heap bottom-up (Floyd's method): for i = ⌊n/2⌋ down to 1, sift-down(i). The leaves are already one-key heaps, so only the internal nodes need work, from the bottom. This costs O(n), not O(n log n): at most n/2^(k+1) nodes sit at height k, and each costs O(k), so the total is at most n × Σ k/2^(k+1) = n × 1 = n swaps' worth of work. Most nodes are near the bottom, where sifting is cheap. Levitin also gives the top-down method, inserting keys one at a time with sift-up, which is O(n log n).

Heapsort

  1. Build a max-heap on A[1..n].
  2. For i = n down to 2: swap A[1] with A[i], which puts the current maximum in its final place; shrink the heap to positions 1 to i − 1; sift-down(1).

The time is O(n) + (n − 1) × O(log n) = O(n log n) in the best, average and worst cases, with O(1) extra space. Heapsort is not stable: equal keys can change their relative order. Merge sort is also O(n log n) but needs O(n) extra space; quicksort is usually faster in practice but O(n²) in its worst case. Since any comparison sort needs Ω(n log n) comparisons (Unit 7, Lower bounds), heapsort is asymptotically optimal.

  3. i = 2 (13): children 25 and 7; swap with 25. At position 4, 13's children are 8 and 4: stop. A = [5, 25, 20, 13, 7, 17, 2, 8, 4]. 1 swap.
  4. i = 1 (5): swap with 25 (position 2), then with 13 (position 4), then with 8 (position 8). A = [25, 13, 20, 8, 7, 17, 2, 5, 4]. 3 swaps; 5 swaps in all, fewer than n = 9.
  5. (b) Pass 1: swap A[1] = 25 with A[9] = 4; 25 is final. Sift-down 4 over positions 1–8: swap with 20 (larger child), then with 17. Heap [20, 13, 17, 8, 7, 4, 2, 5] | 25.
  6. Pass 2: swap 20 with A[8] = 5; 20 is final. Sift-down 5: swap with 17; its new children 4 and 2 are smaller. Heap [17, 13, 5, 8, 7, 4, 2] | 20, 25.
  7. (c) Six more passes extract 17, 13, 8, 7, 5, 4 and leave 2. Output: [2, 4, 5, 7, 8, 13, 17, 20, 25].

Exam traps

  • Bottom-up build runs i from ⌊n/2⌋ down to 1, not from 1 up, and the leaves are never sifted.
  • Sift-down swaps with the larger child in a max-heap. Swapping with the left child by habit breaks the order.
  • Building a heap is O(n); heapsort is O(n log n). Writing O(n log n) for the build loses marks.
  • A heap is not a binary search tree: there is no left-smaller-than-right rule, and searching for a key is O(n).
  • Favourite question: "Construct a heap for the given list and sort it by heapsort, showing every step."

6.5 Flow networks: Ford-Fulkerson and Edmonds-Karp

A flow network is a directed graph whose edges have capacities, like water mains rated in megalitres per day, with a source s and a sink t. The maximum-flow problem asks how much can be sent from s to t without overloading any edge. The Ford–Fulkerson method keeps pushing extra flow along an augmenting path in the residual network until no such path is left; Edmonds–Karp is the same method with each path found by BFS, which bounds the time at O(n m²). The max-flow min-cut theorem then certifies the answer: it equals the capacity of the narrowest cut.

You need: BFS and DFS (Chapter 6.2). Here n is the number of vertices and m the number of edges; Cormen et al. write the Edmonds–Karp bound as O(VE²).

Flows, residual networks and augmenting paths

A flow network is a directed graph with a capacity c(u, v) ≥ 0 on each edge (c = 0 where there is no edge), a source s and a sink t. A flow f gives each edge a value obeying two rules:

  • Capacity constraint: 0 ≤ f(u, v) ≤ c(u, v) on every edge.
  • Flow conservation: at every vertex except s and t, total flow in = total flow out.

The value |f| is the net flow out of s, which equals the net flow into t. Given a flow, the residual capacity says how much more can change on each edge (u, v): forward, c_f(u, v) = c(u, v) − f(u, v), the room left; backward, c_f(v, u) = f(u, v), the flow that could be cancelled. The residual network G_f contains every forward or backward edge with positive residual capacity.

An augmenting path is a path from s to t in G_f. Its bottleneck c_f(p) is the smallest residual capacity along it. Augmenting adds c_f(p) to every forward edge of the path and subtracts it from every edge used backwards; conservation still holds and |f| grows by c_f(p).

Backward edges are what make the method correct. Take the diamond s→a, s→b, a→b, a→t, b→t, every capacity 1. If the first path chosen is s→a→b→t, no forward path is left, yet the true maximum is 2. The residual network has the backward edge b→a, so s→b→a→t is an augmenting path: it cancels the unit on a→b and reroutes it, giving flow 2.

Ford–Fulkerson and Edmonds–Karp

  1. Start with f(u, v) = 0 on every edge.
  2. While the residual network G_f has an augmenting path p, find its bottleneck c_f(p) and augment f along p.
  3. Return f. Its value is maximum (by the theorem below).

Ford–Fulkerson is a method: it does not say how to find p. With integer capacities each augmentation adds at least 1, so a DFS-based version costs O(m |f*|), where f* is a maximum flow. That depends on the capacities: with four outer edges of capacity 1,000 and a middle edge of capacity 1, bad paths cross the middle edge back and forth 2,000 times. With irrational capacities it may never stop.

Edmonds–Karp always augments along a shortest path (fewest edges), found by BFS. Two facts drive its bound: the BFS distance from s to every vertex never decreases from one augmentation to the next, and each edge can be the bottleneck at most about n/2 times. So there are O(nm) augmentations, each costing O(m) for the BFS: O(n m²) overall, whatever the capacities are.

Cuts and the max-flow min-cut theorem

A cut (S, T) splits the vertices into two sets with s in S and t in T. Its capacity c(S, T) is the sum of c(u, v) over edges from S to T; edges from T back to S are not counted. The net flow across any cut equals |f|, so |f| ≤ c(S, T) for every flow and every cut. The max-flow min-cut theorem says three statements are equivalent: (1) f is a maximum flow; (2) G_f has no augmenting path; (3) |f| = c(S, T) for some cut. When Ford–Fulkerson stops, take S = the vertices reachable from s in G_f; that cut is a minimum cut, and its capacity proves the flow is maximum.

6.6 Maximum flow: push-relabel and minimum cost flows

Augmenting-path algorithms keep a legal flow and hunt for whole paths from s to t. Push-relabel (Goldberg and Tarjan) works the other way round: it floods the network from the source, lets vertices hold excess water for a while, and moves it one edge at a time, always downhill, raising a vertex whenever its water is stuck. Its local steps make it fast in practice and easy to parallelise. The chapter then gives each edge a cost per unit: a minimum-cost flow sends a required amount from s to t as cheaply as possible.

You need: residual networks, cuts and the max-flow min-cut theorem (Chapter 6.5); Bellman–Ford shortest paths with negative edges (Unit 3, Single-source shortest paths).

Preflows and heights

A preflow obeys the capacity constraint, but a vertex may take in more than it sends out. The difference is its excess e(u) = inflow − outflow ≥ 0. A vertex other than s and t with e(u) > 0 is active (overflowing). Each vertex also has a height h(u), a whole number, with three rules: h(s) = n, h(t) = 0, and h(u) ≤ h(v) + 1 for every residual edge (u, v). So a residual edge can drop by at most one level.

Two operations move the excess:

  • Push(u, v): allowed when u is active, c_f(u, v) > 0 and h(u) = h(v) + 1 (exactly one step downhill). Send δ = min(e(u), c_f(u, v)). The push is saturating if δ = c_f(u, v).
  • Relabel(u): allowed when u is active and no residual edge leaves u downhill. Set h(u) = 1 + min{h(v) : c_f(u, v) > 0}, just high enough to make one push possible.

The generic push-relabel algorithm

  1. Set h(s) = n and every other height to 0. Saturate every edge out of s, giving its neighbours their first excess.
  2. While some vertex is active, apply any push or relabel that is allowed to it.
  3. When no vertex is active, the preflow is a flow, and it is a maximum flow.

Why it is right. The height rules forbid any s–t path in the residual network: such a path has fewer than n edges, each dropping at most one level, yet it would have to fall from h(s) = n to h(t) = 0. So there is never an augmenting path. When the excess is gone the preflow is a flow with no augmenting path, which by the max-flow min-cut theorem is maximum. Excess that cannot reach t is lifted above height n and drains back to s.

Cost. Heights never exceed 2n − 1, which bounds the relabels and pushes and gives O(n² m) for the generic algorithm. FIFO order (or the relabel-to-front rule of Cormen et al.) gives O(n³); always choosing the highest active vertex gives O(n² √m).

Minimum-cost flows

Now each edge also has a cost a(u, v) per unit of flow, such as rupees per lorry-load. The minimum-cost flow problem asks for a flow of a required value d from s to t that minimises the total cost Σ a(u, v) × f(u, v). (Sending as much as possible at least cost is the min-cost max-flow problem.) In the residual network, a forward edge costs a(u, v) and a backward edge costs −a(u, v), because cancelling a unit refunds its cost. A flow of value d has minimum cost exactly when its residual network has no cycle of negative total cost.

  1. Successive shortest paths: start with zero flow.
  2. Find the cheapest s–t path in the residual network. Backward edges have negative costs, so use Bellman–Ford (or Dijkstra with vertex potentials).
  3. Send min(bottleneck, units still needed) along it; repeat until d units are sent.

Each round costs one shortest-path computation, O(nm) with Bellman–Ford, and there are at most d rounds with integer data. The transportation problem and the assignment problem (Unit 5) are special cases.

  • Push needs h(u) = h(v) + 1 exactly, not just h(u) > h(v).
  • Relabel looks only at residual edges; saturated edges do not count.
  • The source starts at height n (the number of vertices), not at 1 or at the total capacity.
  • In a min-cost residual network the backward edge has cost −a(u, v); with negative costs, plain Dijkstra is wrong.
  • Favourite question: "Explain push and relabel and trace the generic algorithm on a small network."

6.7 String matching: naive and Rabin-Karp algorithms

String matching finds every place where a pattern P of length m occurs in a text T of length n: a word in a document (Ctrl+F), a gene sequence in a genome, a virus signature in a file. The naive algorithm slides P along T one position at a time and compares characters, which costs O((n − m + 1)m) in the worst case. Rabin–Karp compares numbers instead: it reads each m-character window as a number modulo a prime q, updates that number in O(1) time per slide (a rolling hash) and compares characters only when the numbers agree.

You need: the rule (x × y) mod q = ((x mod q) × (y mod q)) mod q, explained in Chapter 6.9, and O-notation from Unit 1.

The problem and the naive algorithm

The text is T[1..n] and the pattern P[1..m], both over an alphabet Σ (letters, digits or bytes). P occurs with shift s if T[s + 1 .. s + m] = P, for some s from 0 to n − m. The task is to report every such valid shift.

  1. For each shift s = 0, 1, …, n − m:
  2. compare P[1], P[2], … with T[s + 1], T[s + 2], …, left to right, stopping at the first mismatch;
  3. if all m characters match, report s.

It needs no preprocessing. Its worst case is T = aaa…a and P = aa…ab: each of the n − m + 1 shifts compares all m characters, (n − m + 1)m in all, which is Θ(n²) when m is about n/2. For T = AAAAAAAAAA and P = AAAB that is 7 × 4 = 28 comparisons. On ordinary English text most shifts fail at the first character, so in practice it is close to linear.

Rabin–Karp: compare numbers first

Treat the text as digits in base d, where d is the alphabet size (d = 10 for decimal digits, 256 for bytes). Let p be the value of P modulo q, and t_s the value of the window T[s + 1 .. s + m] modulo q. Compute p and t₀ with Horner's rule in O(m): v = (d × v + next digit) mod q. Then slide the window with the rolling update

t(s+1) = ( d × ( t(s) − T[s+1] × h ) + T[s+m+1] ) mod q,    where h = d^(m−1) mod q

which removes the leading digit (worth T[s + 1] × h), shifts the rest one place left (× d) and brings in the new last digit. Each update is O(1).

  • If t_s ≠ p, the window certainly differs from P: skip it.
  • If t_s = p, compare the m characters. If they agree, s is a valid shift; if not, it is a spurious hit, two different strings with the same remainder.

With q a prime around 10⁹, spurious hits are rare, about (n − m + 1)/q expected, so the expected time is O(n + m) plus O(m) per real match. The worst case is still O((n − m + 1)m), when every window hits and must be checked. Rabin–Karp shines when many patterns are searched at once: hash them all into a set, and each window needs one lookup. In Python:

def rabin_karp(T, P, d=10, q=13):
    n, m = len(T), len(P)
    h = pow(d, m - 1, q)
    p = t = 0
    for i in range(m):                       # Horner's rule
        p = (d * p + int(P[i])) % q
        t = (d * t + int(T[i])) % q
    found = []
    for s in range(n - m + 1):
        if p == t and T[s:s + m] == P:       # check on a hash hit
            found.append(s)
        if s < n - m:                        # roll the window
            t = (d * (t - int(T[s]) * h) + int(T[s + m])) % q
    return found

Input enhancement: Horspool's algorithm (taught in few syllabi)

Horspool's algorithm compares P with the text right to left. After a match or a mismatch, it looks at the text character c aligned with P's last position and shifts P by table[c] = m − 1 − (the last position of c among P[0..m − 2], counting from 0), or by m if c does not occur there. For P = IDLI (m = 4): I → 3, D → 2, L → 1, any other character → 4. On T = PLAIN IDLI the alignments are at 0 (I matches, A ≠ L; shift table[I] = 3), at 3 (I matches, space ≠ L; shift 3) and at 6, a match: 8 comparisons against 11 for the naive method. Its worst case is still Θ(nm), but on long patterns over large alphabets it skips most of the text.

Exam traps

  • Equal hashes do not prove a match. Always check the characters and count spurious hits separately.
  • h = d^(m−1) mod q, not d^m. The leading digit of an m-digit window is worth d^(m−1).
  • The update can go negative before the final mod (−575 above). In C, % of a negative number is negative, so add q.
  • There are n − m + 1 shifts, not n.

6.8 Fast Fourier transform and polynomial multiplication

Multiplying two polynomials of degree below n the school way takes n² coefficient products. The fast Fourier transform (FFT) does it in Θ(n log n): it evaluates both polynomials at n special points, the complex n-th roots of unity, multiplies the values point by point, and converts back. The same algorithm multiplies huge integers and runs inside every 4G and Wi-Fi modem, and it is a model divide-and-conquer algorithm.

You need: divide and conquer (Unit 2) and the master theorem (Unit 1); complex numbers, with i² = −1 and e^(iθ) = cos θ + i sin θ.

Two ways to hold a polynomial

In coefficient form a polynomial of degree-bound n is A(x) = a₀ + a₁x + … + a_(n−1)x^(n−1), stored as the vector (a₀, …, a_(n−1)). Evaluating it at one point takes Θ(n) by Horner's rule, and adding two takes Θ(n). Multiplying is costly: the product C(x) = A(x)B(x) has degree-bound 2n − 1 and coefficients c_k = Σ a_j b_(k−j) over all valid j (a convolution), Θ(n²) work in all.

In point-value form a polynomial is stored as its values at distinct points x₀, …, x_(n−1). Exactly one polynomial of degree-bound n passes through n given points, so the values determine it. Multiplication is now easy: C(x_k) = A(x_k) × B(x_k), Θ(n) work, provided both are evaluated at 2n − 1 or more points, because C has degree-bound 2n − 1. The plan is therefore

  1. Evaluate A and B at 2n points (coefficient form to point-value form).
  2. Multiply the values pointwise, Θ(n).
  3. Interpolate back to coefficients.

Evaluating at 2n arbitrary points costs Θ(n²), so nothing is gained yet. The FFT makes steps 1 and 3 cost Θ(n log n) by choosing the points well.

Complex roots of unity and the DFT

The principal n-th root of unity is ω_n = e^(2πi/n) = cos(2π/n) + i sin(2π/n). Its powers ω_n⁰, ω_n¹, …, ω_n^(n−1) are the n solutions of xⁿ = 1, equally spaced round the unit circle. For n = 4 they are 1, i, −1, −i. Two facts make them special:

  • Halving lemma: for even n, squaring the n roots of order n gives the n/2 roots of order n/2, each twice, because (ω_n^(k + n/2))² = (ω_n^k)².
  • ω_n^(n/2) = −1, so ω_n^(k + n/2) = −ω_n^k: the second half of the roots are the negatives of the first half.

The discrete Fourier transform (DFT) of a = (a₀, …, a_(n−1)) is the vector of values y_k = A(ω_n^k) = Σ_(j=0..n−1) a_j ω_n^(kj), for k = 0 to n − 1.

The FFT: divide and conquer

Split A by even and odd coefficients: A_even(x) = a₀ + a₂x + a₄x² + … and A_odd(x) = a₁ + a₃x + a₅x² + …. Then

A(x) = A_even(x²) + x · A_odd(x²)

By the halving lemma, x² runs over only the n/2 roots of order n/2 when x runs over the n roots of order n. So two recursive DFTs of size n/2 give every value needed, and a butterfly combines them for k = 0 to n/2 − 1, with twiddle factor ω = ω_n^k:

y_k       = y_k(even) + ω · y_k(odd)
y_(k+n/2) = y_k(even) − ω · y_k(odd)

The combining loop is Θ(n), so T(n) = 2T(n/2) + Θ(n) = Θ(n log n) by case 2 of the master theorem. The size n must be a power of 2; pad with zero coefficients. The inverse DFT, a_j = (1/n) Σ y_k ω_n^(−kj), is the same algorithm run with ω_n⁻¹ in place of ω_n, followed by division by n; it is also Θ(n log n).

In Python (recursive FFT, then multiplication; results are rounded because floating-point arithmetic leaves tiny errors):

import cmath
def fft(a, invert=False):
    n = len(a)
    if n == 1:
        return a[:]
    sign = -1 if invert else 1
    w_n = cmath.exp(sign * 2j * cmath.pi / n)
    even, odd = fft(a[0::2], invert), fft(a[1::2], invert)
    y, w = [0] * n, 1
    for k in range(n // 2):
        y[k] = even[k] + w * odd[k]
        y[k + n // 2] = even[k] - w * odd[k]
        w *= w_n
    return y

def multiply(A, B):
    n = 1
    while n < len(A) + len(B) - 1:
        n *= 2
    fa = fft(A + [0] * (n - len(A)))
    fb = fft(B + [0] * (n - len(B)))
    c = fft([x * y for x, y in zip(fa, fb)], invert=True)
    return [round((v / n).real) for v in c][:len(A) + len(B) - 1]

print(multiply([1, 2], [3, 4]))
print(multiply([2, 1], [4, 3]))      # 12 x 34, lowest digit first
[3, 10, 8]
[8, 10, 3]

The second line multiplies integers: 12 = 2 + 1·10 and 34 = 4 + 3·10, so the coefficients give 8 + 10·10 + 3·100 = 408 = 12 × 34, with carries added at the end (compare long integer multiplication, Unit 2).

Exam traps

  • The inverse DFT uses ω⁻¹ and divides by n. Forgetting 1/n gives coefficients n times too large (12, 40, 32 above).
  • Pad to a power of 2 at least the product's degree-bound (len A + len B − 1), not just len A.
  • The twiddle factor multiplies the odd half only: y_k = E_k + ω^k O_k and y_(k+n/2) = E_k − ω^k O_k.
  • The iterative FFT reads its input in bit-reversed order (0, 4, 2, 6, 1, 5, 3, 7 for n = 8).
  • Favourite question: "Explain the FFT with an example and derive its time complexity."

6.9 Number algorithms: GCD, modular exponentiation, primality testing

Number algorithms work on integers with hundreds of digits, so their cost is counted in digits, not in the size of the number. Three tools carry public-key cryptography, the security behind HTTPS and UPI: Euclid's algorithm for the greatest common divisor and its extended form for modular inverses; modular exponentiation by repeated squaring; and randomized primality tests such as Miller–Rabin. Each is polynomial in the number of bits.

You need: remainders and divisibility from school; Monte Carlo algorithms (Unit 7) for the last part.

Input size and modular arithmetic

An integer N has β = ⌊log₂ N⌋ + 1 bits; a 2048-bit RSA modulus has about 617 decimal digits. Efficient here means polynomial in β; a loop up to N, or even √N = 2^(β/2), is exponential in β. a mod n is the remainder r with 0 ≤ r < n, and a ≡ b (mod n) means n divides a − b. Products can be reduced at every step, (a × b) mod n = ((a mod n) × (b mod n)) mod n, so no intermediate value exceeds n².

Euclid's algorithm and the extended form

The greatest common divisor obeys gcd(a, b) = gcd(b, a mod b), with gcd(a, 0) = a: any number dividing a and b also divides a − qb = a mod b, and the other way round. Euclid's algorithm repeats (a, b) ← (b, a mod b) until b = 0 and returns a.

Steps. For a ≥ b, a mod b < a/2, so every two steps at least halve the larger number: O(log b) steps. By Lamé's theorem the worst inputs are consecutive Fibonacci numbers (Figure 6.9.1), and the steps never exceed about five times the decimal digits of b.

The extended Euclid algorithm also returns x, y with ax + by = gcd(a, b) (Bézout's identity), working back up the recursion:

EXT-EUCLID(a, b):
    if b = 0: return (a, 1, 0)
    (d, x', y') = EXT-EUCLID(b, a mod b)
    return (d, y', x' − ⌊a/b⌋ · y')

When gcd(a, n) = 1, ax + ny = 1 gives ax ≡ 1 (mod n), so x mod n is the modular inverse a⁻¹. RSA computes its private key this way.

Modular exponentiation by repeated squaring

RSA encrypts by computing c = m^e mod n with e of hundreds of bits, so e − 1 multiplications are impossible. Instead scan the bits of e from the left, starting with r = 1:

  1. For each bit: square, r = r² mod n.
  2. If the bit is 1, also multiply: r = r × a mod n.

A k-bit exponent needs at most 2k modular multiplications, O(β³) bit operations with school multiplication. Python's pow(a, e, n) does this; written out:

def power_mod(a, e, n):
    r = 1
    for bit in bin(e)[2:]:        # binary digits, most significant first
        r = r * r % n
        if bit == '1':
            r = r * a % n
    return r

Primality testing

Trial division up to √N takes about 2^(β/2) steps: fine for 10 digits, hopeless for a 300-digit RSA prime.

Fermat test. If N is prime, a^(N−1) ≡ 1 (mod N) for every a from 1 to N − 1 (Fermat's little theorem). So a random a with a^(N−1) mod N ≠ 1 proves N composite, while a result of 1 only suggests N is prime. Carmichael numbers pass for every a coprime to them; the smallest is 561 = 3 × 11 × 17, and indeed 2⁵⁶⁰ mod 561 = 1.

Miller–Rabin closes the gap. Write N − 1 = 2^s × d with d odd and pick a random a from 2 to N − 2. Compute x = a^d mod N; the round passes if x is 1 or N − 1, or if squaring x up to s − 1 times reaches N − 1; otherwise N is composite. The reason: modulo a prime the only square roots of 1 are ±1, so x² ≡ 1 with x ≢ ±1 proves N composite. For N = 561: 560 = 2⁴ × 35, and with a = 2 the sequence is 2³⁵ ≡ 263, then 166, 67, 1. Since 67² ≡ 1 but 67 is neither 1 nor 560, 561 is composite (indeed 66 × 68 = 4,488 = 8 × 561).

A composite N passes one round with probability at most 1/4, so k rounds err with probability at most 4^(−k); 40 rounds give less than 10⁻²⁴. It is a Monte Carlo algorithm with one-sided error (Unit 7), costing O(k β³). In 2002 Agrawal, Kayal and Saxena gave AKS, the first deterministic polynomial-time primality test, but Miller–Rabin remains far faster in practice.

Exam traps

  • The extended algorithm can return a negative coefficient (−9 above, for 120). Report the inverse in the range 0 to n − 1 by adding n.
  • a⁻¹ mod n exists only when gcd(a, n) = 1.
  • In repeated squaring, square on every bit, 0 or 1, then multiply only on 1s.
  • Passing the Fermat test does not prove N prime; failing it proves N composite.

Takeaways

  1. Store sparse graphs as adjacency lists; every traversal then costs O(n + m) instead of O(n²).
  2. BFS explores in rings and finds fewest-edge paths; DFS's discovery and finish times reveal cycles, ancestry and structure.
  3. A DAG's topological order is its reverse DFS finishing order, or the order in which Kahn's algorithm removes sources; a leftover vertex means a cycle.
  4. An array-based binary heap gives O(log n) insert and extract-max, O(n) bottom-up build, and an in-place O(n log n) heapsort.
  5. Maximum flow equals minimum cut. Ford–Fulkerson augments along residual paths, Edmonds–Karp picks them by BFS for O(n m²), and backward edges let both undo bad choices.
  6. Push-relabel moves excess locally, one level downhill at a time, and lifts stuck vertices; min-cost flow augments along the cheapest residual path, using negative-cost backward edges.
  7. Rabin–Karp rejects most windows with one O(1) hash comparison and checks characters only on hits; spurious hits are why the check is needed.
  8. The FFT evaluates at roots of unity by divide and conquer, cutting polynomial and big-integer multiplication from Θ(n²) to Θ(n log n).
  9. Euclid, repeated squaring and Miller–Rabin are polynomial in the number of bits; together they make RSA key generation, encryption and decryption practical.

p = 5358 mod 13 = 2 (13 × 412 = 5356). Rolling through the 17 windows, t_s = 2 at shifts 8, 13 and 14: shift 8 is 5358, 1 valid match; 7932 and 9323 are 2 spurious hits (both leave remainder 2).

Apply Compute the DFT of (1, 2, 3, 4) with a 4-point FFT, showing the butterflies. 10 marks

Even (1, 3) gives (4, −2); odd (2, 4) gives (6, −2). With twiddles 1 and i: y₀ = 4 + 6 = 10, y₂ = 4 − 6 = −2, y₁ = −2 + i(−2) = −2 − 2i, y₃ = −2 + 2i. DFT = (10, −2 − 2i, −2, −2 + 2i).

Apply RSA with p = 5, q = 11 and e = 3: find d, encrypt m = 7, and show decryption recovers it. 10 marks

n = 55, φ = 40; extended Euclid gives d = 27 (3 × 27 = 81 = 2 × 40 + 1). c = 7³ mod 55 = 343 − 330 = 13. Repeated squaring of 13²⁷ mod 55 (27 = 11011₂) returns 7.

Analyze and evaluate

Analyze (Spans 6.1–6.4.) A metro network has 300 stations and 340 track segments. Choose a representation and an algorithm for (a) the route with fewest stops, (b) the fastest route given travel times, (c) the order in which to build new lines when some depend on others. Justify with complexities. 12 marks

Sparse (m ≈ n), so adjacency lists. (a) BFS, O(n + m). (b) Dijkstra (Unit 3) with a binary heap as priority queue, O((n + m) log n). (c) Topological sort of the dependency DAG, O(n + m), with a cycle reported if Kahn's algorithm leaves vertices.

Evaluate (Spans 6.5–6.6.) Compare Ford–Fulkerson, Edmonds–Karp and push-relabel, and explain why backward residual edges matter in both maximum flow and minimum-cost flow. 12 marks

Path-based against local preflow; O(m |f*|), O(n m²), O(n² m) or O(n³); capacity-independent bounds; practical speed of push-relabel. Backward edges cancel earlier flow: without them max flow can stop short (10 instead of 12 in Chapter 6.5) and min-cost flow can fail to send the demand (the fourth load in Chapter 6.6).

Analyze (Spans 6.7 and 6.9.) Explain how modular arithmetic makes Rabin–Karp work. How does q affect spurious hits and running time, and how is h = d^(m−1) mod q computed for long patterns? 12 marks

Reduction after each step keeps numbers small; the rolling update is valid mod q; a wrong window hits with probability about 1/q, so expected time O(n + m) for large prime q, degrading towards (n − m + 1)m for small q (three spurious hits in Chapter 6.7's quiz with q = 11); h by repeated squaring in O(log m) multiplications.

Evaluate "Testing a 300-digit number for primality needs √N divisions, so RSA key generation is impractical." Evaluate this claim. 10 marks

√N ≈ 10¹⁵⁰ divisions would indeed be impossible, but trial division is exponential in the bit length. Miller–Rabin needs k exponentiations of O(β³) each and errs with probability ≤ 4^(−k); AKS is deterministic and polynomial. Primes are also common (roughly one in every 690 numbers near 10³⁰⁰), so a random search finds one quickly. The claim is false.

Glossary

Adjacency list
For each vertex, a list of its neighbours; space Θ(n + m).
Adjacency matrix
An n × n table with a 1 (or a weight) where an edge exists; space Θ(n²).
Augmenting path
An s–t path in the residual network along which more flow can be sent.
Back edge
A DFS edge to a grey ancestor; in a directed graph it signals a cycle.
Bottleneck
The smallest residual capacity on an augmenting path.
Butterfly
The FFT step combining two half-size results into y_k and y_(k+n/2).
Carmichael number
A composite that passes the Fermat test for every base coprime to it; 561 is the smallest.
Cut
A split of the vertices into S (holding s) and T (holding t); its capacity sums the S→T edges.
DAG
Directed acyclic graph: a directed graph with no directed cycle.
DFT
Discrete Fourier transform: the values of a polynomial at the n complex n-th roots of unity.
Excess
In a preflow, the inflow minus the outflow at a vertex.
Extended Euclid
Euclid's algorithm that also returns x, y with ax + by = gcd(a, b).
Heap property
Every parent's key is ≥ its children's (max-heap) or ≤ (min-heap).
Height (label)
The integer h(u) that tells push-relabel which way is downhill.
Kahn's algorithm
Topological sort by repeatedly removing a vertex of in-degree 0 (source removal).
Miller–Rabin test
A randomized primality test that searches for a non-trivial square root of 1.
Minimum-cost flow
A flow of required value whose total cost Σ a(u, v)f(u, v) is least.
Modular inverse
a⁻¹ mod n: the x with ax ≡ 1 (mod n); exists when gcd(a, n) = 1.
Priority queue
An abstract data type with insert and extract-max (or min); usually a heap.
Repeated squaring
Computing a^e mod n by squaring for each bit of e and multiplying on 1-bits.
Residual network
The edges that can still take more flow, or give some back, under the current flow.
Rolling hash
A window hash updated in O(1) time as the window slides one position.
Root of unity
A complex number ω with ωⁿ = 1; ω_n = e^(2πi/n) is the principal one.
Shift (string matching)
The offset s at which the pattern is compared with the text; valid if they match.
Spurious hit
A Rabin–Karp window whose hash equals the pattern's but whose characters differ.
Topological order
An ordering of a DAG's vertices with every edge pointing forward.
Twiddle factor
The power ω_n^k that multiplies the odd half in an FFT butterfly.
