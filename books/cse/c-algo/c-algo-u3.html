3.1 Greedy method: elements and examples

The greedy method solves an optimisation problem in a sequence of steps. At each step it takes the choice that looks best at that moment, checks that the partial answer is still allowed, and moves on without ever undoing a choice. It is fast and easy to code, but it is correct only for problems with a special structure, so every greedy algorithm needs a proof. Greedy ideas run inside file compression (Huffman codes), network design (minimum spanning trees), map routing (Dijkstra) and the way a shopkeeper counts out your change.

You need: asymptotic notation and the O(n log n) cost of sorting (Unit 1, Asymptotic notations); a min-heap as a priority queue (Unit 6, Heaps, priority queues and heapsort) for Chapters 3.4 to 3.7.

The parts of a greedy algorithm

Every greedy algorithm has five parts; name them first when an exam says "design a greedy algorithm".

  • Candidate set: the pieces an answer is built from (coins, items, edges, jobs).
  • Selection function: the rule that picks the best remaining candidate (largest coin, highest profit per kg, lightest edge).
  • Feasibility check: does the partial answer still obey the constraints if we add this candidate (amount not exceeded, no cycle formed, deadline met)?
  • Objective function: the value we minimise or maximise (number of coins, total profit, total weight).
  • Solution check: is the partial answer now complete (amount fully paid, n − 1 edges chosen)?

Horowitz and Sahni write these parts as a control abstraction, a template that every greedy algorithm fills in. Here a[1..n] holds the n candidates:

Algorithm Greedy(a, n)
{
    solution := ∅;
    for i := 1 to n do
    {
        x := Select(a);                  // best remaining candidate, removed from a
        if Feasible(solution ∪ {x}) then
            solution := Union(solution, x);
    }
    return solution;
}

If Select works by sorting the candidates once, the template costs O(n log n) for the sort plus n feasibility checks. If it uses a min-heap, each selection costs O(log n).

Why greedy can be correct: the two elements

A greedy algorithm gives an optimal answer when the problem has both of these properties (CLRS calls them the elements of the greedy strategy.

  1. Greedy-choice property. Some optimal solution contains the first greedy choice. So taking it never shuts us out of the best answer.
  2. Optimal substructure. After the greedy choice, what remains is a smaller problem of the same kind, and an optimal answer to it, joined with the greedy choice, is optimal for the whole problem.

The usual proof is an exchange argument: take any optimal solution that does not agree with the greedy choice, swap one of its pieces for the greedy piece, and show the result is still feasible and no worse. Repeating the swap turns the optimal solution into the greedy one without losing value. A second style, greedy stays ahead, shows that after every step greedy is at least as far along as any other solution (Chapter 3.3).

Dynamic programming (Unit 4) also needs optimal substructure. The difference is the first property. DP does not trust any single choice, so it solves every subproblem and compares; greedy commits to one choice and solves one subproblem.

When greedy fails, and a map of examples

Making change shows both sides. With Indian money (coins and notes of ₹1, 2, 5, 10, 20, 50, 100, 200 and 500) the rule "take the largest piece that fits" always gives the fewest pieces. Now invent a coin system {1, 3, 4} and pay 6. Greedy takes 4, then 1, then 1: three coins. The best answer is 3 + 3: two coins. The first greedy choice (the 4) is not part of any optimal answer, so the greedy-choice property fails. Figure 3.1.1 draws the choices as a tree.

The rest of this unit is a tour of problems where the greedy choice is safe. The greedy rule starts with every variable false and sets a variable true only when an implication forces it; at the end it checks the negative clauses. Because it never sets a variable true without being forced, if its assignment fails the negative clauses, no assignment can pass them.

Exam traps

  • "Locally best" is not "globally best". Never claim a greedy algorithm is optimal without an exchange argument or a theorem.
  • Optimal substructure alone does not justify greedy; DP problems have it too. The greedy-choice property is the extra condition.
  • Feasible is not optimal: every partial answer greedy builds is feasible, but the final one may still not be the best.
  • Favourite question: "Write the control abstraction of the greedy method and explain each function."

3.2 Fractional knapsack problem

In the knapsack problem a bag (the knapsack) can carry at most M kilograms, and there are n items, each with a weight and a profit. In the fractional version you may take any part of an item, as you can scoop part of a sack of rice. The goal is the largest total profit that fits. Taking items in order of profit per kilogram solves it exactly, in O(n log n) time. The problem models loading divisible goods (grain, fuel, sand), sharing a budget across divisible options, and it gives the upper bound used to prune the search in the 0/1 knapsack's branch and bound (Unit 5).

You need: the greedy method and the exchange argument (Chapter 3.1).

The problem in symbols

Item i has weight wᵢ > 0 and profit pᵢ > 0. Let xᵢ be the fraction of item i we take, 0 ≤ xᵢ ≤ 1. Then:

maximise    Σ pᵢ·xᵢ          (total profit,  i = 1 … n)
subject to  Σ wᵢ·xᵢ ≤ M      (total weight within capacity M)
            0 ≤ xᵢ ≤ 1

Here xᵢ = 1 means the whole item, xᵢ = 0 means none of it, and xᵢ = 0.5 means half its weight for half its profit. If all items together weigh at most M, the answer is simply xᵢ = 1 for every i. Otherwise an optimal answer fills the bag exactly: Σ wᵢxᵢ = M.

Three greedy rules, only one correct

Three selection rules look reasonable: largest profit first, lightest first, or largest profit per unit weight pᵢ/wᵢ first. The first ignores weight and the second ignores profit; only the third is always optimal, as the worked example shows.

Why the ratio rule is optimal (exchange argument). Number the items so that p₁/w₁ ≥ p₂/w₂ ≥ … ≥ pₙ/wₙ. Let x be the greedy answer and y any optimal answer. If y ≠ x, look at the first item j where they differ. Greedy took as much of item j as would fit, so yⱼ < xⱼ, and y must spend that spare weight on some later item k, whose ratio is no higher. Move δ kg in y from item k to item j. The weight is unchanged and the profit changes by δ·(pⱼ/wⱼ − pₖ/wₖ) ≥ 0. Repeating such moves turns y into x without ever losing profit, so x is optimal too.

The greedy answer has a simple shape: some whole items, then at most one fractional item (the first one that did not fit), then nothing.

Algorithm and its running time

The algorithm in pseudocode, assuming the items are already sorted by pᵢ/wᵢ, largest first:

Algorithm GreedyKnapsack(M, n)
{
    for i := 1 to n do x[i] := 0.0;
    U := M;                               // capacity left
    for i := 1 to n do
    {
        if (w[i] > U) then break;
        x[i] := 1.0;  U := U − w[i];      // take the whole item
    }
    if (i ≤ n) then x[i] := U / w[i];     // part of the first item that did not fit
}

Computing the n ratios is O(n); sorting them is O(n log n), for example by merge sort; clearing x[] is O(n); the filling loop does O(1) work for at most n items, O(n). Total T(n) = O(n) + O(n log n) + O(n) + O(n) = O(n log n), or O(n) if the items arrive sorted. Extra space is O(n).

The same algorithm in C (insertion sort is fine for five items; use qsort for large n):

#include <stdio.h>
int main(void) {
    double w[] = {10, 20, 30, 15, 25}, p[] = {60, 100, 120, 105, 75};
    int idx[] = {0, 1, 2, 3, 4}, n = 5;
    double cap = 60, total = 0;
    /* sort item numbers by p/w, largest first (insertion sort) */
    for (int i = 1; i < n; i++) {
        int k = idx[i], j = i - 1;
        while (j >= 0 && p[idx[j]] / w[idx[j]] < p[k] / w[k]) {
            idx[j + 1] = idx[j]; j--;
        }
        idx[j + 1] = k;
    }
    for (int i = 0; i < n && cap > 0; i++) {
        int k = idx[i];
        double x = (w[k] <= cap) ? 1.0 : cap / w[k];   /* whole item or the fraction that fits */
        total += x * p[k];
        cap -= x * w[k];
        printf("item %c  x = %.2f  profit so far = %.1f\n", 'A' + k, x, total);
    }
    printf("maximum profit = %.1f\n", total);
    return 0;
}

Exam traps

  • Sorting by profit alone or by weight alone is wrong; examiners often ask for all three rules, so practise the table above.
  • Write the vector x in the original item order, not the sorted order, and give the total profit and the weight check.
  • The greedy answer has at most one fractional xᵢ. Two fractions in your answer means an arithmetic slip.
  • Greedy by ratio is optimal for the fractional problem only, never claim it for 0/1 knapsack.
  • Time is O(n log n) because of the sort; the filling loop alone is O(n).

3.3 Activity selection and job sequencing with deadlines

Two scheduling problems for one room or one machine. Activity selection picks the most non-overlapping bookings for a seminar hall. Job sequencing with deadlines picks which one-hour jobs to run, and when, to earn the most from jobs finished on time. Both sort once and take greedily.

Activity selection: earliest finish first

Activity i has start time sᵢ and finish time fᵢ and uses the hall during [sᵢ, fᵢ). Two activities are compatible if one finishes before the other starts (fᵢ ≤ sⱼ). Find the largest set of compatible activities.

  1. Sort the activities by finish time, earliest first.
  2. Select the first activity; remember its finish time as last.
  3. Scan the rest in order; select an activity if its start ≥ last, then set last to its finish.

Why it works (greedy stays ahead). The activity that ends first leaves the hall free longest, so any optimal schedule can swap its first activity for it without a clash. By induction greedy's k-th activity finishes no later than any other schedule's k-th, so greedy fits at least as many. Time: O(n log n) to sort, O(n) to scan.

Job sequencing: most profit first, latest free slot

Job i takes one unit of time, has a deadline dᵢ (it must finish by time dᵢ) and earns profit pᵢ only if it does. One machine runs one job at a time. Time slot t means the interval from t − 1 to t.

  1. Sort the jobs by profit, largest first.
  2. For each job, find the latest free slot t ≤ dᵢ and put the job there.
  3. If no such slot is free, reject the job.

Placing a job as late as possible keeps early slots free for tight deadlines. Checking slots one by one costs O(n²) in all; with the disjoint sets of Chapter 3.5 the search is nearly O(1) per job and the sort dominates, O(n log n).

3.4 Huffman codes

A Huffman code gives each symbol of a message a string of bits, short strings for frequent symbols and long ones for rare symbols, so that the whole message needs as few bits as possible. David Huffman's greedy algorithm (1952) builds the best such code by repeatedly joining the two least frequent symbols into one. Huffman coding is a stage inside DEFLATE (the format of zip, gzip and PNG files) and inside JPEG and MP3, so it runs every time a zip file or a JPEG photo is made.

You need: binary trees, and a min-heap as a priority queue (Unit 6, Heaps, priority queues and heapsort); the greedy method (Chapter 3.1).

Codes, the prefix property and cost

A fixed-length code gives every symbol the same number of bits: with n symbols it needs ⌈log₂ n⌉ bits each, so 6 symbols need 3 bits each. A variable-length code can do better when frequencies differ. To decode without separators, it must be a prefix code: no codeword is the beginning of another. With a = 0, b = 01, c = 1, the bits "01" could mean "b" or "a c", so that code is useless.

A prefix code is a binary tree: symbols sit at the leaves, a left edge means 0, a right edge means 1, and a symbol's codeword is the path from the root to its leaf. If f(c) is the frequency of symbol c and d(c) is its depth in the tree (the length of its codeword), the cost of the code is

B(T) = Σ f(c) · d(c)        (total bits for the message, summed over all symbols c)

Dividing B(T) by the number of characters gives the average bits per symbol. Huffman's algorithm finds the tree with the smallest B(T).

Huffman's algorithm

  1. Make one leaf per symbol, labelled with its frequency, and put all leaves in a min-priority queue Q.
  2. Remove the two nodes x and y of smallest frequency from Q.
  3. Make a new internal node z with x as left child, y as right child and f(z) = f(x) + f(y); insert z into Q.
  4. Repeat steps 2 and 3 until one node is left; it is the root. With n symbols there are exactly n − 1 merges.

Running time. Building the heap is O(n). Each of the n − 1 merges does two extract-min operations and one insert, each O(log n). Total: O(n log n).

The algorithm in Python, using the standard heapq module as the min-heap (the counter breaks ties between equal frequencies):

import heapq

def huffman(freq):
    # heap entries: (frequency, tie-break number, subtree)
    heap = [(f, i, s) for i, (s, f) in enumerate(freq.items())]
    heapq.heapify(heap)
    count = len(heap)
    while len(heap) > 1:
        f1, _, left = heapq.heappop(heap)     # smallest
        f2, _, right = heapq.heappop(heap)    # second smallest
        heapq.heappush(heap, (f1 + f2, count, (left, right)))
        count += 1
    codes = {}
    def walk(node, code):
        if isinstance(node, str):
            codes[node] = code
        else:
            walk(node[0], code + "0")
            walk(node[1], code + "1")
    walk(heap[0][2], "")
    return codes

freq = {'A': 30, 'B': 25, 'C': 15, 'D': 12, 'E': 10, 'F': 8}
codes = huffman(freq)
print(codes)
print(sum(freq[s] * len(codes[s]) for s in freq), "bits")

Why the greedy choice is safe

The proof has the two elements of Chapter 3.1. Greedy choice: in some optimal tree, the two least frequent symbols x and y are siblings at the deepest level. If a more frequent symbol sat deeper, swapping it with x would put more of the frequency higher up and not increase the cost. Optimal substructure: replace x and y by one new symbol z with f(z) = f(x) + f(y). If T′ is an optimal tree for the smaller alphabet, then expanding z back into x and y gives B(T) = B(T′) + f(x) + f(y), and this is optimal for the original alphabet. Each merge is therefore safe.

Exam traps

  • After each merge, the new node goes back into the queue and competes with the leaves. Step 3 above merges 18 (a merged node) with B 25, not D with C.
  • Ties can be broken either way, and swapping left and right changes the codewords. Your codes may differ from the answer key, but B(T) must be the same.
  • Total bits = Σ frequency × code length. Do not add the internal-node values by hand unless you know the shortcut: their sum, 18 + 27 + 43 + 57 + 100 = 245, equals B(T).
  • Prefix property means no codeword starts another; it does not mean all codes have different lengths.

3.5 Minimum spanning trees: Prim's and Kruskal's algorithms

A spanning tree of a connected, undirected graph is a set of edges that joins every vertex with no cycle; with V vertices it always has V − 1 edges. A minimum spanning tree (MST) is a spanning tree of least total weight. It answers "which roads, pipes or fibre links connect all these villages with the least cable?", the planning behind rural networks such as BharatNet. Kruskal's algorithm adds the lightest edge anywhere that makes no cycle; Prim's grows one tree by its lightest outgoing edge. Both are greedy and optimal.

You need: adjacency lists and matrices (Unit 6, Graph representations); min-heaps (Unit 6); the exchange argument (Chapter 3.1).

The cut property: why greedy works here

A cut splits the vertices into two groups, S and V − S. An edge crosses the cut if its ends are in different groups. The cut property says: the lightest edge crossing any cut belongs to some MST. Proof by exchange: take an MST T without that edge e = (u, v). Adding e to T makes a cycle, and the cycle must cross the cut a second time through some edge e′. Removing e′ gives another spanning tree, and since w(e) ≤ w(e′) it is no heavier, so it is also an MST and it contains e.

Kruskal and Prim each choose a cut at every step, so both add only safe edges. Two facts follow: the heaviest edge on a cycle is never needed (cycle property), and if all weights differ the MST is unique.

Kruskal's algorithm and disjoint sets

  1. Sort all edges by weight, lightest first. Start with each vertex as its own tree (a forest of V trees).
  2. Take the next edge (u, v). If u and v are in different trees, add the edge and join the two trees; otherwise skip it, because it would close a cycle.
  3. Stop when V − 1 edges have been added.

"Are u and v in the same tree?" is answered by a disjoint-set (union–find) structure with three operations: MAKE-SET(x) creates the set {x}, FIND-SET(x) returns the representative of x's set, and UNION(x, y) joins two sets. UNION appends one list to the other and must update the pointer of every moved element, so it moves the shorter list (weighted union). An element moves only into a list at least twice as long, so at most log₂ n times; m operations on n elements cost O(m + n log n). The forest representation stores each set as a tree, with union by rank and path compression (FIND-SET points every visited node at the root); each operation then costs O(α(n)) amortised, where the inverse Ackermann function α is at most 4 for any real input.

Running time. Sorting E edges is O(E log E) = O(E log V), because E ≤ V². The 2E finds and V − 1 unions are almost linear. Total: O(E log V).

Kruskal's algorithm in Python, with a forest-style union–find:

def kruskal(vertices, edges):
    parent = {v: v for v in vertices}          # every vertex is its own set
    def find(x):                               # root of x's set
        while parent[x] != x:
            parent[x] = parent[parent[x]]      # path halving
            x = parent[x]
        return x
    tree, total = [], 0
    for w, u, v in sorted(edges):              # lightest edge first
        ru, rv = find(u), find(v)
        if ru != rv:                           # different sets: no cycle
            parent[ru] = rv                    # union
            tree.append(u + v); total += w
    return tree, total

Prim's algorithm

Prim's algorithm keeps, for every vertex v outside the tree, key[v] = the weight of the lightest edge from v into the tree, and parent[v] = the tree end of that edge.

Algorithm Prim(G, r)                 // r = start vertex
    for each vertex v: key[v] := ∞; parent[v] := nil
    key[r] := 0
    while some vertex is outside the tree:
        u := outside vertex with the smallest key     // extract-min
        add u to the tree (with edge parent[u]–u if u ≠ r)
        for each edge (u, v) of weight w with v outside the tree:
            if w < key[v] then key[v] := w; parent[v] := u

With an adjacency matrix and an array for key[], each of the V extract-mins scans V entries: O(V²). With adjacency lists and a binary heap, V extract-mins and up to E key decreases cost O(log V) each: O(E log V).

3.6 Single-source shortest paths: Dijkstra's algorithm

The single-source shortest-paths problem asks: from one starting vertex s, what is the cheapest route to every other vertex, where the cost of a route is the sum of its edge weights (km, minutes, rupees)? Dijkstra's algorithm, published by Edsger Dijkstra in 1959, solves it when no edge weight is negative. Its greedy step is to finalise the unfinished vertex that is currently closest to s. It runs inside map apps, ride-hailing route estimates and the OSPF routing protocol that internet routers use.

You need: directed graphs and adjacency lists (Unit 6, Graph representations); min-heaps (Unit 6); Prim's algorithm (Chapter 3.5), which has the same shape.

Distances, predecessors and relaxation

For each vertex v the algorithm keeps d[v], the length of the shortest path to v found so far (∞ at the start, 0 for s), and pred[v], the vertex just before v on that path. The basic step is relaxing an edge (u, v) of weight w:

if d[u] + w(u, v) < d[v]  then   d[v] := d[u] + w(u, v);   pred[v] := u

In words: if going to u and then along the edge to v is shorter than the best route to v known so far, use it. Following pred[] back from any vertex gives its path; together these edges form the shortest-path tree.

The algorithm and why it is correct

  1. Set d[s] = 0 and d[v] = ∞ for every other v. Put all vertices in a min-priority queue keyed by d.
  2. Extract the vertex u with the smallest d[u]. It is now finished: d[u] is final.
  3. Relax every edge leaving u.
  4. Repeat steps 2 and 3 until the queue is empty. Vertices still at ∞ cannot be reached from s.

Why the greedy choice is safe. Let u be the vertex just extracted, with the smallest d among unfinished vertices. Any other path from s to u must leave the finished set at some unfinished vertex y, and d[y] ≥ d[u]. The rest of that path adds edge weights that are ≥ 0, so it cannot end below d[u]. Hence d[u] is the true shortest distance. The argument needs every weight to be non-negative; that is the algorithm's one condition.

Running time for V vertices and E edges:

  • Array for d[], each extract-min scans all vertices: V × O(V) + E relaxations = O(V²). Best for dense graphs.
  • Binary heap: V extract-mins and up to E key decreases at O(log V) each = O((V + E) log V). Best for sparse graphs such as road maps.
  • Fibonacci heap: O(E + V log V), mostly of theoretical interest.

In Python, heapq has no decrease-key, so the usual code pushes a new entry and skips old ones when they come out:

import heapq

def dijkstra(graph, src):
    dist = {v: float('inf') for v in graph}
    dist[src] = 0
    pq = [(0, src)]                       # (distance, vertex)
    while pq:
        d, u = heapq.heappop(pq)          # closest unfinished vertex
        if d > dist[u]:
            continue                      # old entry, skip it
        for v, w in graph[u]:
            if d + w < dist[v]:           # relax edge u -> v
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist

     'C': [('D', 2), ('E', 6)], 'D': [('E', 2)], 'E': []}
print(dijkstra(G, 'S'))

Negative edges and the Bellman–Ford algorithm

With a negative edge the safety argument breaks. Take S→A 2, S→B 3, B→A −2. Dijkstra finishes A at d = 2 before it looks at B; the later relaxation B→A would give 3 − 2 = 1, but A is already final, so the answer 2 is wrong.

set d[s] := 0 and d[v] := ∞ for every other v
repeat V − 1 times:
    for each edge (u, v, w): relax (u, v)
for each edge (u, v, w):
    if d[u] + w < d[v] then report "negative cycle reachable from s"

A shortest path has at most V − 1 edges, and pass k fixes every path of k edges, so V − 1 passes are enough. Time: O(VE). On the small example, the first pass already sets d[A] = min(2, 3 − 2) = 1. For shortest paths between all pairs see Unit 4, Floyd–Warshall.

Exam traps

  • Dijkstra needs every edge weight ≥ 0. A negative edge (even without a negative cycle) can give a wrong answer; use Bellman–Ford.
  • Dijkstra's key is d[u] + w, the whole distance from s; Prim's key is w alone. Same loop, different problem.
  • In an undirected graph each edge can be used in both directions; list it twice in the adjacency list.
  • Give the path as well as the distance: keep pred[] and trace it back from the target.
  • Know both running times: O(V²) with an array, O((V + E) log V) with a binary heap.

3.7 Optimal merge patterns

Suppose n sorted files must be merged into one sorted file, two at a time. Merging files of a and b records takes about a + b record moves, and the merged file may be merged again later, so the order of merges changes the total work. The greedy rule "always merge the two smallest files" gives the least total. It is Huffman's algorithm with file sizes in place of frequencies.

You need: merging two sorted lists (Unit 2, Merge sort); Huffman's algorithm (Chapter 3.4).

The two-way merge tree and its cost

Draw every merge pattern as a binary tree. The original files are the leaves (external nodes); each internal node is a merge, labelled with the size of its output. If file i has qᵢ records and sits at depth dᵢ (the number of merges its records pass through), then

total cost = Σ qᵢ · dᵢ  =  sum of all internal-node labels

This is the weighted external path length of the tree, the same quantity Huffman minimised.

The greedy algorithm

  1. Put all n file sizes in a min-heap.
  2. Remove the two smallest, merge them, add their sum to the cost, and insert the sum back.
  3. Repeat until one file is left: n − 1 merges, O(n log n) time with a heap.

The proof of optimality is Huffman's: the two smallest files can always be the deepest pair, and merging them leaves a smaller instance of the same problem.

Takeaways

  1. A greedy algorithm makes the locally best choice, never undoes it, and is correct only when the greedy-choice property and optimal substructure both hold.
  2. Prove a greedy algorithm with an exchange argument; disprove one with a single small counterexample.
  3. Fractional knapsack: sort by pᵢ/wᵢ and fill; at most one item is split; O(n log n). The same rule fails for 0/1 knapsack.
  4. Activity selection takes the earliest finish; job sequencing takes the largest profit and puts it in the latest free slot before its deadline.
  5. Huffman coding and optimal merging both repeatedly join the two smallest weights; cost = Σ weight × depth = sum of the internal nodes.
  6. The cut property makes both MST algorithms correct: Kruskal (sorted edges + union–find, O(E log V)) and Prim (one growing tree, O(V²) or O(E log V)).
  7. Dijkstra finalises the nearest unfinished vertex; it needs non-negative weights and runs in O(V²) or O((V + E) log V). With negative edges use Bellman–Ford, O(VE).
  8. In every answer, show the table of steps: the examiner gives most marks for the intermediate values, not the final number.

J1 → slot 2; J2 → slot 1; J3 (d = 1) rejected; J4 → slot 3; J5 rejected. Sequence J2, J1, J4, profit 40; table of slots tried (Chapter 3.3).

7. Construct a Huffman code for a 10, e 15, i 12, o 3, u 4, s 13, t 1. Find the total bits and compare with a fixed-length code. 10 marks

Merges 1 + 3 = 4, 4 + 4 = 8, 8 + 10 = 18, 12 + 13 = 25, 15 + 18 = 33, 25 + 33 = 58. Code lengths i, s, e 2; a 3; u 4; o, t 5. Total 146 bits; fixed code 3 bits × 58 = 174 bits; saving 28 bits (Chapter 3.4).

8. Edges PQ 3, PR 1, QR 6, QS 5, RS 2, RT 8, ST 4. Find the MST by Kruskal's algorithm and by Prim's algorithm from Q. 12 marks

Kruskal: PR 1, RS 2, PQ 3, ST 4, then stop (4 edges for 5 vertices). Prim from Q: PQ 3, PR 1, RS 2, ST 4. Same tree, weight 10; show union–find sets and Prim's candidate edges (Chapter 3.5).

9. Undirected edges AB 4, AC 1, CB 2, BD 5, CD 8, DE 3, CE 12. Find shortest paths from A by Dijkstra's algorithm. 10 marks

Finish A 0, C 1, B 3 (via C), D 8 (via B), E 11 (via D). Paths A–C–B–D–E for E. Table of d[] per step and pred[] (Chapter 3.6).

10. Find an optimal merge pattern for files of 15, 22, 8, 40, 5, 30 and 12 records, and its cost. 8 marks

Merges 5 + 8 = 13, 12 + 13 = 25, 15 + 22 = 37, 25 + 30 = 55, 37 + 40 = 77, 55 + 77 = 132. Cost 339; draw the merge tree (Chapter 3.7).

Analyze and evaluate

11. Run Dijkstra from A on the graph of Figure 3.5.1 (as undirected) and compare its shortest-path tree with the MST. Why do they differ? 12 marks

Distances A 0, C 4, B 6, E 10, D 11, F 20 (via E or D). Tree AC, CB, CE, BD and EF or DF, weight 26 or 27, against the MST's 23. Dijkstra minimises each vertex's distance from A; the MST minimises the total cable. Same loop, different key (Chapters 3.5, 3.6).

12. "Greedy by profit/weight is optimal for knapsack." Evaluate this claim for the fractional and 0/1 versions, with proof and counterexample. 12 marks

Fractional: exchange proof, at most one fraction. 0/1: counterexample M = 50, (10, 50), (20, 90), (30, 120): greedy 140, optimal 210. The greedy-choice property fails; DP takes O(nM) (Chapters 3.1, 3.2; Unit 4).

13. Show that the optimal merge pattern problem and Huffman coding are the same problem. Use one example to draw both trees. 10 marks

Both minimise Σ weight × depth over binary trees with given leaf weights; both merge the two smallest; cost = sum of internal nodes. Draw one tree with sizes as frequencies; reading 0/1 on its edges gives the code (Chapters 3.4, 3.7).

14. Show with an example that Dijkstra's algorithm can fail with a negative edge, and explain how Bellman–Ford fixes it. Compare their running times. 10 marks

S→A 2, S→B 3, B→A −2: Dijkstra reports 2, true 1. Correctness argument needs w ≥ 0. Bellman–Ford: V − 1 passes of relaxation, extra pass detects negative cycles, O(VE) against O((V + E) log V) (Chapter 3.6).

Glossary

Greedy algorithm
An algorithm that builds a solution step by step, each time taking the best-looking choice and never undoing it.
Control abstraction
A template algorithm (Select, Feasible, Union) that every greedy algorithm fills in.
Feasible solution
A solution that satisfies all the constraints, optimal or not.
Optimal solution
A feasible solution with the best value of the objective function.
Greedy-choice property
Some optimal solution begins with the greedy choice.
Optimal substructure
An optimal solution contains optimal solutions to its subproblems.
Exchange argument
A proof that swaps parts of an optimal solution for greedy choices without losing value.
Fractional knapsack
Knapsack in which any fraction 0 ≤ xᵢ ≤ 1 of an item may be taken.
Compatible activities
Activities whose time intervals do not overlap.
Deadline
In job sequencing, the time by which a unit-time job must finish to earn its profit.
Prefix code
A code in which no codeword is the beginning of another.
Huffman tree
The binary tree built by repeatedly joining the two least frequent nodes; its paths are the codewords.
Spanning tree
A subset of V − 1 edges joining all V vertices of a connected graph with no cycle.
Minimum spanning tree
A spanning tree of least total edge weight.
Cut
A split of the vertex set into two groups; an edge crosses it if its ends are in different groups.
Disjoint-set (union–find)
A structure for non-overlapping sets with MAKE-SET, FIND-SET and UNION.
Weighted union
Joining two linked-list sets by appending the shorter list to the longer.
Path compression
Making every node on a FIND path point straight at the root.
Key (Prim)
For a vertex outside the tree, the weight of its lightest edge into the tree.
Relaxation
Replacing d[v] by d[u] + w(u, v) when that is smaller, and setting pred[v] = u.
Shortest-path tree
The tree of pred[] edges that holds a shortest path from the source to each vertex.
Negative cycle
A cycle whose edge weights add to less than zero; shortest paths through it are undefined.
Two-way merge pattern
A binary tree showing the order in which files are merged two at a time.
Weighted external path length
Σ qᵢdᵢ over the leaves of a tree; the cost minimised by Huffman and optimal merging.
