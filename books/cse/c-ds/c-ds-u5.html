5.1 Graph terminology: directed and undirected graphs

A graph is a set of vertices and a set of edges, where each edge joins two vertices. That is the whole definition, and it is enough to model a road map (cities and roads), a social network (people and friendships), a syllabus (courses and prerequisites) or the web (pages and links). Trees from Unit 4 are a special case: a connected graph with no cycles. This chapter gives the vocabulary every later algorithm is stated in; some syllabi list it as "Basic definition and terminology" and others as the "Graph ADT".

You need: tree terminology from Unit 4 (root, parent, child, leaf) and Big-O from Unit 1.

Vertices, edges and the two kinds of graph

Write a graph as G = (V, E). V is the vertex set (also called nodes), E the edge set. We use |V| or simply V for the number of vertices and |E| or E for the number of edges; the context makes clear whether a set or a count is meant.

In an undirected graph an edge is an unordered pair {u, v}: the road runs both ways, friendship is mutual. In a directed graph (digraph) an edge is an ordered pair (u, v), drawn as an arrow from u to v: a one-way street, a Twitter follow, a prerequisite "take C before DS". The edge (u, v) does not give you (v, u).

A weighted graph attaches a number w(u, v) to each edge: distance in km, cost in rupees, time in minutes, bandwidth. Chapters 5.6 to 5.8 are about weighted graphs; 5.3 to 5.5 ignore weights.

Two vertices joined by an edge are adjacent (neighbours), and the edge is incident on both. A self-loop joins a vertex to itself; parallel edges (a multigraph) join the same pair twice. A simple graph has neither, and unless a question says otherwise, "graph" means simple graph.

Degree, paths and cycles

The degree deg(v) of a vertex in an undirected graph is the number of edges incident on it (a self-loop counts twice). Because every edge contributes exactly 2 to the total, Σ deg(v) = 2|E|: the handshaking lemma. A direct consequence: the number of odd-degree vertices is even.

In a directed graph each vertex has an in-degree (arrows coming in) and an out-degree (arrows going out), and Σ in-deg = Σ out-deg = |E|, since each arrow is counted once as an exit and once as an entry.

A walk is any sequence of vertices v₀, v₁, …, vₖ where consecutive vertices are adjacent; its length is the number of edges, k. A path is a walk with no repeated vertex. A cycle is a walk that starts and ends at the same vertex with no other repetition and length at least 3 (in a simple undirected graph). A graph with no cycle is acyclic; a directed acyclic graph is a DAG, the subject of 5.4.

An undirected graph is connected if a path exists between every pair of vertices; otherwise it splits into connected components (5.5). For directed graphs the words are strongly connected (a directed path each way between every pair) and weakly connected (connected if you ignore arrow directions).

Special graphs and the Graph ADT

A complete graph Kₙ has every pair of its n vertices joined, so it has n(n−1)/2 edges; a complete digraph has n(n−1). A graph is sparse when |E| is close to |V| and dense when |E| is close to |V|². A subgraph keeps some vertices and some of the edges among them; a spanning subgraph keeps all vertices. A spanning tree of a connected graph is a spanning subgraph that is a tree: it has exactly |V|−1 edges (5.6). A bipartite graph can have its vertices coloured with two colours so that no edge joins two of the same colour.

As an ADT, a graph offers: addVertex(v), addEdge(u, v[, w]), removeEdge(u, v), adjacent(u, v) (is there an edge?), neighbours(u) (list the vertices adjacent to u), and the traversals of 5.3. How fast each runs depends on the representation chosen in 5.2.

Worked example

Question. For the undirected graph G₁ of Figure 5.1.1 (edges AB, AC, BC, BD, CD, DE): (a) list the degree of every vertex and verify the handshaking lemma; (b) is A, B, D, E a path, and is A, B, D, C, A a cycle? (c) how many edges would K₅ on the same vertices have, and how many edges are missing from G₁? (d) For G₂ (edges P→Q, Q→R, R→P, R→S) give in- and out-degrees and say whether it is a DAG.

Solution.

  1. Count edges at each vertex. A touches AB, AC: deg(A) = 2. B touches AB, BC, BD: 3. C touches AC, BC, CD: 3. D touches BD, CD, DE: 3. E touches DE: 1.
  2. Sum: 2 + 3 + 3 + 3 + 1 = 12 = 2 × 6 edges. The lemma holds. Odd-degree vertices B, C, D, E: four of them, an even count, as it must be.
  3. A, B, D, E uses edges AB, BD, DE, all present, and repeats no vertex: a path of length 3. A, B, D, C, A uses AB, BD, DC, CA, all present, returns to A, repeats nothing else, length 4 ≥ 3: a cycle. (A, B, C, A is a shorter cycle, length 3.)
  4. K₅ has 5 × 4 / 2 = 10 edges. G₁ has 6, so 4 are missing: AD, AE, BE, CE.
  5. G₂: P in 1 (from R) out 1 (to Q); Q in 1 out 1; R in 1 (from Q) out 2 (to P, S); S in 1 out 0. Sum in = 4 = sum out = |E|. P→Q→R→P is a directed cycle, so G₂ is not a DAG.

Exam traps

  • Number of edges of a complete graph: n(n−1)/2 for undirected, n(n−1) for directed. Students halve the directed count or forget to halve the undirected one.
  • A self-loop adds 2 to the degree of its vertex, not 1; otherwise the handshaking lemma breaks.
  • "Path" means no repeated vertex. If a question says "walk" or "trail", repetition is allowed (a trail repeats no edge). Writing a cycle of length 2 (u, v, u) in a simple undirected graph is wrong; the minimum cycle length is 3.
  • Connected vs strongly connected: a directed graph whose arrows form a line P→Q→R is weakly connected but not strongly connected. Say which you mean.
  • Favourite 2-mark question: "Define graph, digraph, degree, path, cycle, connected graph, complete graph." Keep each definition to one sentence with the symbol.

5.2 Graph representations: adjacency matrix and adjacency list

A graph on paper is dots and lines; in memory it must be an array or a set of linked lists. The two standard choices are the adjacency matrix, a V × V table of 0s and 1s (or weights), and the adjacency list, one linked list of neighbours per vertex. The matrix answers "is there an edge u–v?" in constant time but costs V² space whatever the edge count; the list costs only V + E space and makes "visit every neighbour of u" fast, which is what every traversal does. Choosing between them is the first design decision in any graph program, and a common tutorial exercise asks you to build both for a sample graph and compare them.

You need: 2-D arrays and linked lists from Unit 2; the terms of 5.1.

Adjacency matrix

Number the vertices 0 to V−1. The adjacency matrix M is a V × V array with M[i][j] = 1 if there is an edge from i to j and 0 otherwise. For an undirected graph the edge {i, j} sets both M[i][j] and M[j][i], so M is symmetric about its main diagonal and you may store only one triangle. For a weighted graph store w(i, j) instead of 1, and a sentinel for "no edge": 0 if weights are never zero, otherwise a large INF constant. The diagonal M[i][i] is 0 unless there are self-loops.

Costs: space Θ(V²) always, even for a graph with three edges. adjacent(u, v) is one array read, O(1). neighbours(u) scans the whole row, O(V). Adding or removing an edge is O(1). The degree of a vertex is its row sum; in a digraph the row sum is the out-degree and the column sum the in-degree. A neat property: entry (i, j) of M² counts the walks of length 2 from i to j.

Adjacency list

Keep an array adj[0..V−1] of head pointers. adj[u] points to a linked list of the vertices adjacent to u (for a weighted graph, each node also stores the weight). An undirected edge {u, v} appears twice: v in u's list and u in v's list, so the lists hold 2E nodes in total; a directed edge (u, v) appears once, in u's list only.

Costs: space Θ(V + E). neighbours(u) is a walk down one list, O(deg(u)), which is why BFS and DFS run in O(V + E) with lists but O(V²) with a matrix. adjacent(u, v) must search u's list, O(deg(u)), worst case O(V). Inserting an edge at the head of a list is O(1); deleting one is O(deg(u)). Finding in-degrees in a digraph is awkward: you must scan every list, or keep a second "reverse" list.

In practice the list is often an array of dynamic arrays (a vector<int> adj[V] in C++ or a list of lists in Python) rather than linked nodes; the costs are the same. Two other layouts you may meet: the incidence matrix (V × E, entry 1 when vertex is an endpoint of the edge) and the edge list (just an array of (u, v, w) triples), which is exactly what Kruskal's algorithm in 5.6 wants.

Which to choose

Use the matrix when the graph is dense (E near V²), when V is small (a few hundred), or when the algorithm keeps asking "is u adjacent to v?" (Floyd-Warshall in 5.8 is naturally a matrix algorithm). Use the list when the graph is sparse, which is nearly every real graph: a road network has about 2 to 4 roads per junction, a social network a few hundred friends per user out of hundreds of millions. A list for 1 million vertices and 3 million edges takes a few tens of megabytes; the matrix would need 10¹² cells.

/* C: adjacency list for an undirected graph with V vertices */
typedef struct Node { int v; int w; struct Node *next; } Node;
Node *adj[100];                       /* heads, all NULL at start */
void addEdge(int u, int v, int w) {   /* insert at head: O(1) */
    Node *a = malloc(sizeof(Node)); a->v = v; a->w = w; a->next = adj[u]; adj[u] = a;
    Node *b = malloc(sizeof(Node)); b->v = u; b->w = w; b->next = adj[v]; adj[v] = b;
}

Because each new node goes at the head, the list of 0 after calls addEdge(0,1), addEdge(0,4) reads 4 → 1, the reverse of insertion order. Traversal order in 5.3 depends on this, so state your list order in an exam answer.

Worked example

Question. A directed weighted graph has vertices A, B, C, D and edges A→B (4), A→C (1), C→B (2), B→D (5), C→D (8). (a) Write its adjacency matrix and adjacency list. (b) An undirected graph has V = 1000 vertices and E = 5000 edges. Estimate the memory of each representation with 4-byte integers and 8-byte pointers, and compare the cost of listing the neighbours of a vertex.

Solution.

  1. Order the vertices A, B, C, D as rows and columns. A row holds the edges leaving that vertex; a dash (−) or INF marks no edge. 
          A   B   C   D
  A   0   4   1   −
  B   −   0   −   5
  C   −   2   0   8
  D   −   −   −   0
    The matrix is not symmetric: M[A][B] = 4 but M[B][A] = −. Row sums of non-blank entries give out-degrees (A 2, B 1, C 2, D 0); column counts give in-degrees (A 0, B 2, C 1, D 2); both sum to 5 = |E|.
  2. Adjacency list, one node per directed edge, storing (vertex, weight): 
    A → (B,4) → (C,1)
B → (D,5)
C → (B,2) → (D,8)
D → ∅
    Five nodes in total, one per edge, because the graph is directed.
  3. Matrix for V = 1000: 1000 × 1000 = 10⁶ cells × 4 bytes = 4,000,000 bytes ≈ 4 MB (1 MB if a 1-byte flag is enough). It does not change if E grows or shrinks.
  4. List for E = 5000 undirected edges: 2E = 10,000 nodes. Each node holds an int (4 bytes) and a pointer (8 bytes), about 16 bytes with alignment: 160,000 bytes. Plus 1000 head pointers × 8 bytes = 8,000 bytes. Total ≈ 168 KB, roughly 24 times smaller than the 4 MB matrix.
  5. Listing neighbours: average degree = 2E/V = 10. The list visits 10 nodes; the matrix scans 1000 cells. Over a full traversal that is 10,000 steps against 1,000,000: O(V + E) versus O(V²).

Exam traps

  • Undirected edge, two entries: M[i][j] and M[j][i], and a node in both lists. Forgetting the mirror is the most common lost mark.
  • Space of the list is O(V + E), not O(E): the V head pointers count, and a graph with no edges still needs them.
  • A weighted matrix needs a "no edge" sentinel distinct from a real weight. If 0 can be a weight, use INF.
  • Reading degrees off a digraph matrix: rows give out-degree, columns give in-degree. Not the other way round.
  • Favourite question: "Compare adjacency matrix and adjacency list" as a table with rows space, adjacent(u, v), neighbours(u), add edge, best for. Write the five rows with Big-O entries, not prose.

5.3 Breadth-first and depth-first traversal

A traversal visits every vertex reachable from a start vertex exactly once. There are two natural orders. Breadth-first search (BFS) spreads out in rings: all vertices one edge away, then two edges away, and so on, using a queue. Depth-first search (DFS) follows one path as far as it can, backs up, and tries the next branch, using a stack or recursion. Both run in O(V + E) with adjacency lists, and almost every later algorithm in this unit is one of them with extra bookkeeping: shortest paths in unweighted graphs come from BFS; topological order, cycle detection and components come from DFS.

You need: queues and stacks from Unit 3; adjacency lists from 5.2.

Breadth-first search

Keep a visited flag per vertex and a FIFO queue. Mark the start s visited and enqueue it. Then repeat: dequeue a vertex u, "visit" it (print it), and for each neighbour v of u that is not yet visited, mark v visited and enqueue it. Stop when the queue is empty.

  1. visited[s] = true; enqueue(s); dist[s] = 0.
  2. While the queue is not empty: u = dequeue(); output u.
  3. For each v in adj[u]: if not visited[v], set visited[v] = true, dist[v] = dist[u] + 1, parent[v] = u, enqueue(v).

Marking a vertex when it is enqueued, not when it is dequeued, is what stops the same vertex entering the queue twice. The dist values are the number of edges on the shortest path from s, because a vertex at distance d is enqueued only after every vertex at distance d − 1 has been dequeued; the parent pointers form the BFS tree. This is the whole shortest-path algorithm for unweighted graphs, and the reason BFS matters in networking (fewest hops), social networks (degrees of separation) and puzzle solving (fewest moves).

/* C: BFS from s on adjacency lists adj[], V vertices */
void bfs(int s) {
    int queue[100], front = 0, rear = 0, visited[100] = {0};
    visited[s] = 1; queue[rear++] = s;
    while (front < rear) {
        int u = queue[front++];
        printf("%d ", u);
        for (Node *p = adj[u]; p != NULL; p = p->next)
            if (!visited[p->v]) { visited[p->v] = 1; queue[rear++] = p->v; }
    }
}

Each vertex enters the queue at most once (V operations) and each list is scanned once (2E node visits for undirected graphs): O(V + E). With an adjacency matrix the neighbour scan is V per vertex, so O(V²). Space is O(V) for the queue and flags.

Depth-first search

DFS is simplest as recursion: visit u, then for each unvisited neighbour v, call DFS(v). The call stack remembers where to come back to. Iteratively, replace the queue of BFS with a stack, with one subtlety: push neighbours without marking them, and mark a vertex when it is popped, skipping it if already marked; otherwise the order differs from the recursive one.

  1. DFS(u): visited[u] = true; output u; record discovery time.
  2. For each v in adj[u]: if not visited[v], parent[v] = u, DFS(v).
  3. Record the finishing time of u when the loop ends; return.

Edges fall into classes. In the DFS tree a tree edge leads to a newly discovered vertex. In an undirected graph every other edge is a back edge to an ancestor, and a back edge proves a cycle (5.5). In a digraph there are also forward edges (to a descendant already finished) and cross edges (between subtrees); only a back edge, one that reaches a vertex still on the stack, means a cycle. Finishing times give topological order (5.4). Time is again O(V + E); the recursion depth can reach V, which crashes on a deep graph unless you switch to the explicit stack.

If the graph is disconnected, wrap either search in a loop: for every vertex v, if not visited, start a new search from v. The number of restarts is the number of connected components (5.5).

Exam traps

  • State the neighbour order (alphabetical, or the order of your list) before the trace. With a different order the output differs and the examiner cannot follow your answer.
  • In BFS mark a vertex visited when it is enqueued. Marking on dequeue lets a vertex enter the queue twice and produces duplicate outputs.
  • BFS gives shortest paths only when every edge counts 1. With weights use Dijkstra (5.7); a BFS trace on a weighted graph earns nothing.
  • Iterative DFS with a stack can give a different order from recursive DFS if you mark on push. Say which you are doing; examiners usually expect the recursive order.
  • Favourite question: "Trace BFS and DFS on the given graph and draw the BFS tree and DFS tree." The tree uses parent pointers; leave non-tree edges out or draw them dashed.

Beyond the syllabus

Not for the exam. On huge graphs the frontier is processed in parallel on GPUs (direction-optimising BFS). Search: "bidirectional BFS", "A* search", "direction-optimizing BFS".

5.4 Topological sorting of directed acyclic graphs

When tasks depend on each other (take C before Data Structures, pour the foundation before the walls, compile a library before the program that links it), the dependencies form a directed graph, and a schedule that respects them is a topological order: a line-up of all vertices in which every edge u→v has u before v. Such an order exists exactly when the graph has no directed cycle, that is, when it is a DAG. Two algorithms produce one in O(V + E): Kahn's algorithm, which repeatedly removes a vertex with no incoming edges, and the DFS method, which lists vertices in reverse order of finishing time. It is a favourite exam question because a six-vertex trace fits on one page.

You need: in-degree from 5.1, DFS finishing times from 5.3, a queue from Unit 3.

What a topological order is, and when it exists

A topological order of a digraph G = (V, E) is a sequence of all vertices such that for every edge (u, v), u appears before v. If G has a cycle a→b→c→a, no order can put a before b, b before c and c before a, so cyclic graphs have no topological order. Conversely every DAG has at least one, and usually many: the order is total but the dependencies are partial, so independent vertices may be swapped. "Find a topological order" therefore has several correct answers; "find all of them" is a different and much harder question.

Why does a DAG always have a vertex with in-degree 0? Walk backwards along incoming edges; in a finite graph with no cycle the walk must stop, and it stops only at a vertex with nothing coming in. That vertex can go first, and removing it leaves a smaller DAG. This argument is Kahn's algorithm.

Kahn's algorithm (in-degree method)

  1. Compute indeg[v] for every vertex by scanning all adjacency lists: O(V + E).
  2. Put every vertex with indeg 0 into a queue (any container works; a queue gives a deterministic answer).
  3. While the queue is not empty: dequeue u, append u to the output, and for every edge (u, v) decrement indeg[v]; when indeg[v] reaches 0, enqueue v.
  4. If the output has fewer than V vertices, the graph has a cycle: the vertices never output are on or downstream of it.

Each vertex is enqueued and dequeued once and each edge is examined once: O(V + E). The side effect in step 4 makes Kahn's algorithm the standard cycle test for digraphs (see 5.5). Using a min-priority queue instead of a FIFO queue gives the lexicographically smallest order, a common variant question.

DFS method (finishing times)

Run DFS from every unvisited vertex in turn. When a vertex finishes (all its out-neighbours are explored), push it on a stack. At the end, pop the stack: that is a topological order. The reason: for an edge (u, v) in a DAG, v always finishes before u. Either v is discovered from u, so v finishes inside u's call, or v was already finished when u looked at it (it cannot be still in progress, because that would make (u, v) a back edge and the graph cyclic). So reverse finishing order puts u before v. Cost O(V + E), one DFS.

The two methods generally give different valid orders; both are accepted. If an examiner asks for "the" order, follow their stated rule (usually alphabetical or numerical tie-breaking) and show the rule you used.

5.5 Connected components and cycle detection

Two questions come up constantly about a graph: how many separate pieces does it have, and does it contain a cycle? Both are a traversal with a little bookkeeping: the restarts of DFS count the components, and an edge that returns to a visited vertex reveals a cycle. Only a few syllabi list this as a separate topic (a common tutorial asks for components while tracing BFS and DFS); elsewhere the ideas sit inside 5.3 and 5.4.

You need: DFS from 5.3; Kahn's algorithm from 5.4.

Connected components

A connected component of an undirected graph is a maximal set of vertices in which every pair is joined by a path. Every vertex lies in exactly one component. To find them:

  1. Set comp[v] = 0 for all v and a counter c = 0.
  2. For each vertex v: if comp[v] = 0, increment c and run DFS (or BFS) from v, labelling every vertex reached with c.
  3. c is the number of components; comp[u] = comp[v] tells in O(1) whether u and v are connected.

The loop is O(V + E): each vertex and edge is touched in one search. The disjoint-set (union-find) structure of 5.6 does the same job when edges arrive one at a time: union the endpoints of each edge, and the sets left are the components. For digraphs the matching idea is the strongly connected component, outside this unit.

Cycle detection

Undirected graph. Run DFS carrying the parent of each vertex. On an edge u–v: if v is unvisited, recurse (tree edge); if v is visited and v ≠ parent[u], it is a back edge and the graph has a cycle. Excluding the parent matters: u–v is the edge you just came along. A count also works: a connected graph with |E| ≥ |V| has a cycle, since a tree has only |V| − 1 edges.

Directed graph. The parent test fails, because u→v and v→u are different edges that do form a cycle. Use three colours: white (unvisited), grey (on the recursion stack), black (finished). On an edge u→v: white means recurse; grey is a back edge, hence a cycle; black is harmless. Or run Kahn's algorithm and check whether fewer than V vertices come out.

Worked example

Question. An undirected graph has vertices 1–8 and edges 1–2, 2–3, 3–1, 4–5, 6–7, 7–8. (a) Count its components with DFS. (b) Does it have a cycle? Show the back edge. (c) For the digraph P→Q, Q→R, R→P, R→S, show the colour-based test.

  5. Digraph: DFS(P): P grey → Q grey → R grey → edge R→P meets grey P: back edge, cycle P→Q→R→P. Kahn agrees: every in-degree is 1, the queue starts empty, 0 < 4 vertices come out.

Exam traps

  • Undirected test: ignore the edge back to the parent, or every tree edge looks like a cycle.
  • Directed test: a visited vertex means a cycle only if it is grey (on the stack); a black vertex reached again is a cross edge.
  • Favourite question: "Count the components and say whether the graph is a tree, a forest or has a cycle." A forest (acyclic, k components) has exactly |E| = |V| − k.

5.6 Minimum spanning trees: Prim's and Kruskal's algorithms

Suppose six villages must be joined by optical fibre and the cost of laying cable between each pair is known. You want every village connected and the total cost as small as possible. The answer is a minimum spanning tree (MST): a set of |V| − 1 edges that connects all vertices with the least total weight. Two greedy algorithms find it. Kruskal's takes edges cheapest first, skipping any that would close a cycle. Prim's grows one tree from a start vertex, always adding the cheapest edge that leaves the tree. Both are exact, not approximations, because of the cut property explained below. Most syllabi examine this chapter, and some specifically want Kruskal's with the disjoint-set structure and Prim's with a priority queue.

You need: spanning tree from 5.1; cycle detection from 5.5; binary heaps from Unit 4.

Spanning trees and the cut property

A spanning tree of a connected undirected graph G is a subgraph that contains every vertex and is a tree, so it has exactly |V| − 1 edges and no cycle. A connected weighted graph has many spanning trees; an MST is one of minimum total weight. If all edge weights are distinct the MST is unique; with ties there may be several MSTs of the same weight.

The cut property is why greedy works. A cut splits V into two non-empty parts S and V − S. Take the lightest edge e crossing the cut. Some MST contains e: if an MST T did not, adding e to T makes a cycle, that cycle must cross the cut by another edge f with w(f) ≥ w(e), and swapping f for e gives a spanning tree no heavier than T. Kruskal and Prim both repeatedly pick the lightest edge across some cut, so every edge they choose is safe.

Kruskal's algorithm

  1. Sort all E edges by weight, ascending: O(E log E).
  2. Make each vertex its own set (disjoint-set structure).
  3. For each edge (u, v) in sorted order: if find(u) ≠ find(v), the endpoints are in different trees: add the edge to the MST and union the two sets. Otherwise the edge would close a cycle: skip it.
  4. Stop after |V| − 1 edges are added.

The disjoint-set (union-find) structure keeps a parent array: find(x) follows parents to the root, union links one root under the other. With union by rank (attach the shorter tree under the taller) and path compression (make every node on a find path point straight to the root), a sequence of operations is almost O(1) each, so Kruskal's total is dominated by the sort: O(E log E), which equals O(E log V) since E ≤ V².

Prim's algorithm

  1. Pick a start vertex s. For every vertex keep key[v] = cheapest known edge from the tree to v (∞ at first, key[s] = 0) and parent[v].
  2. Repeat V times: take the vertex u not yet in the tree with smallest key; add u (and the edge parent[u]–u) to the tree.
  3. For each neighbour v of u not in the tree: if w(u, v) < key[v], set key[v] = w(u, v) and parent[v] = u.

With a plain array scan for the minimum, each of the V rounds costs O(V): O(V²), fine for dense graphs. With a binary min-heap of keys (Unit 4) the minimum is O(log V) and each key decrease O(log V), giving O((V + E) log V) = O(E log V) for connected graphs, better for sparse graphs. The structure of Prim's is identical to Dijkstra's in 5.7; only the key rule differs (edge weight here, path length there).

5.7 Single-source shortest paths: Dijkstra's algorithm

Google Maps from your hostel to Chennai Central, the cheapest IRCTC connection, the fastest route for a packet through routers: all are "shortest path from one source to everywhere" on a weighted graph. BFS (5.3) solves it only when every edge costs 1. Dijkstra's algorithm solves it for any non-negative weights by settling vertices in increasing order of distance, always taking the closest unsettled vertex and relaxing its outgoing edges. It is the most examined algorithm of this unit; tutorials often ask explicitly for the distance table after every step, and some syllabi ask for the priority-queue implementation and for Bellman-Ford, which handles negative weights.

You need: Prim's structure from 5.6; binary heaps from Unit 4.

The problem and the relaxation step

Given a directed (or undirected) graph with edge weights w(u, v) ≥ 0 and a source s, find for every vertex v the length δ(s, v) of the lightest path from s, and the path itself. Keep two arrays: dist[v], the best path length found so far (∞ until a path is known, dist[s] = 0), and parent[v], the previous vertex on that path.

To relax an edge (u, v) is to ask whether going through u improves v: if dist[u] + w(u, v) < dist[v], set dist[v] = dist[u] + w(u, v) and parent[v] = u. Every shortest-path algorithm is a strategy for the order in which to relax edges. Shortest paths have the optimal substructure property: any prefix of a shortest path is itself a shortest path, so once dist[u] is right, relaxing u's edges gives correct candidates for its neighbours.

Dijkstra's algorithm

  1. dist[s] = 0, dist[v] = ∞ for all other v; all vertices unsettled.
  2. Repeat V times: choose the unsettled vertex u with the smallest dist (a min-priority queue keyed on dist); mark u settled. Its dist is now final.
  3. For each edge (u, v) with v unsettled, relax it; if dist[v] decreased, decrease its key in the priority queue (or simply push the new (dist, v) pair and ignore stale pairs when they surface).

Why is the chosen u final? Every unsettled vertex has dist ≥ dist[u], and any path to u that leaves the settled set must pass through some unsettled vertex x first, costing at least dist[x] ≥ dist[u] already, and more after that because weights are non-negative. So no cheaper path to u exists. The argument breaks with a negative edge, which is Dijkstra's one limitation.

Cost: with an array scan for the minimum, O(V²) (good for dense graphs); with a binary heap, O((V + E) log V), usually written O(E log V); with a Fibonacci heap, O(E + V log V). The parent pointers form the shortest-path tree, and the path to any v is read backwards: v, parent[v], parent[parent[v]], … , s.

Compare Prim's algorithm: identical loop, but Prim's key is the single edge weight w(u, v) while Dijkstra's is the path length dist[u] + w(u, v). Mixing the two rules is the classic exam error.

Negative weights: Bellman-Ford

If weights can be negative (some syllabi list this), use the Bellman-Ford algorithm: relax every edge, and repeat that full pass V − 1 times. After pass i all shortest paths of at most i edges are correct, and no shortest path has more than V − 1 edges, so V − 1 passes suffice: O(VE). A V-th pass that still improves something proves a negative-weight cycle, in which case shortest paths are undefined. Bellman-Ford is slower than Dijkstra but needs no priority queue and is the basis of the distance-vector routing protocol RIP.

Its correctness proof assumes that extending any path can only make it longer, so the closest unsettled vertex cannot be reached more cheaply later. A negative edge can shorten a path after the vertex is settled, so the greedy finalisation is unsafe.

Understand Why are V − 1 passes enough in Bellman-Ford? 3 marks

A shortest path in a graph without negative cycles visits each vertex at most once, so it has at most V − 1 edges. After pass i every shortest path of at most i edges is correct; after V − 1 passes all are.

Beyond the syllabus

Not for the exam. Edsger Dijkstra designed the algorithm in 1956 in about twenty minutes at a café, as he later told it, and published it in 1959. Link-state routing (OSPF, IS-IS) runs Dijkstra inside every router; distance-vector routing (RIP) runs Bellman-Ford. Navigation services precompute shortcuts (contraction hierarchies, ALT landmarks) so that continental queries take milliseconds; A* adds a heuristic estimate of remaining distance to the priority. Johnson's algorithm reweights a graph with Bellman-Ford so Dijkstra can be run from every source even with negative edges. Search: "contraction hierarchies", "A* algorithm", "Johnson's algorithm".

5.8 All-pairs shortest paths: Floyd-Warshall algorithm

A distance chart in a railway timetable gives the shortest distance between every pair of stations, not just from one source. You could run Dijkstra from each of the V vertices, but there is a cleaner way when the graph is small or dense: the Floyd-Warshall algorithm, three nested loops over a V × V matrix that in O(V³) time produces every shortest distance at once, and works with negative edge weights as long as there is no negative cycle. It is the unit's one dynamic-programming algorithm: instead of a greedy choice it builds the answer from answers to smaller subproblems, "shortest paths that may only pass through the first k vertices". A few syllabi list it by name, and it is also the natural example for syllabi that name dynamic programming in this unit.

You need: the adjacency matrix from 5.2; relaxation from 5.7.

The subproblem

Number the vertices 1 to V. Define d(k)[i][j] as the length of the shortest path from i to j whose intermediate vertices (all vertices except the two ends) are drawn only from the set {1, 2, …, k}. For k = 0 no intermediate vertex is allowed, so d(0) is just the weight matrix: w(i, j) for an edge, 0 on the diagonal, ∞ for no edge. For k = V every vertex is allowed and d(V)[i][j] is the true shortest distance δ(i, j).

The step from k − 1 to k has only two cases. Either the best path with intermediates in {1..k} does not use vertex k, so it is the old answer d(k−1)[i][j]; or it does use k, exactly once (a shortest path never repeats a vertex when there is no negative cycle), so it is a best path i → k using only {1..k−1} followed by a best path k → j using only {1..k−1}. Hence the recurrence:

d(k)[i][j] = min( d(k−1)[i][j],  d(k−1)[i][k] + d(k−1)[k][j] )

This is the relaxation of 5.7, "is i → k → j better than what I have?", applied for every pair and every intermediate vertex in a fixed order.

The algorithm

  1. Set D = the weight matrix (0 on the diagonal, ∞ where there is no edge). Optionally set next[i][j] = j for every edge, for path recovery.
  2. For k = 1 to V: for i = 1 to V: for j = 1 to V: if D[i][k] + D[k][j] < D[i][j], set D[i][j] = D[i][k] + D[k][j] and next[i][j] = next[i][k].
  3. After the k loop, D[i][j] = δ(i, j). If any D[i][i] < 0, the graph has a negative cycle and the distances through it are meaningless.

One matrix is enough: in round k the entries D[i][k] and D[k][j] are not changed by round k itself (going through k to reach k gains nothing), so updating in place is safe. The outer loop must be k; putting k innermost is the standard wrong answer and gives incorrect distances. Three loops of V each: Θ(V³) time, Θ(V²) space, independent of E, which is why it suits dense graphs and small V (a few hundred) but not a million-vertex road map. Setting every weight to 1 and using OR/AND instead of min/+ gives Warshall's algorithm for the transitive closure: which vertices can reach which.

To read a path from the next matrix: start at i, then repeatedly move to next[current][j] until j is reached. Comparing with the alternatives: V runs of Dijkstra with a heap cost O(V E log V), which beats V³ on sparse graphs but needs non-negative weights; V runs of Bellman-Ford cost O(V² E), worse than V³ in every case.

Question. Apply Floyd-Warshall to the digraph with edges 1→2 (3), 1→4 (7), 2→1 (8), 2→3 (2), 3→1 (5), 3→4 (1), 4→1 (2). Show the matrix after each round and the shortest path from 2 to 1.

Exam traps

  • k must be the outer loop. Writing the loops as i, j, k gives a wrong matrix and is the most common loss of marks.
  • In round k, row k and column k never change; use that as a check and copy them straight across. The diagonal stays 0 unless there is a negative cycle.
  • Anything plus ∞ is ∞. Do not let a sum through a missing edge produce a number.
  • Floyd-Warshall handles negative edges; Dijkstra does not. Neither handles a negative cycle: Floyd-Warshall reports it with a negative diagonal entry.
  • Favourite question: "Apply Floyd-Warshall to the given 4-vertex graph showing D⁽⁰⁾ to D⁽⁴⁾." Write the recurrence first, then the matrices, then name the changed entries in each round.

Remember State the time and space complexity of Floyd-Warshall. 1 mark

Time Θ(V³), space Θ(V²) (one matrix, updated in place).

Understand What does d(k)[i][j] mean, and why does the final matrix give true shortest paths? 3 marks

The shortest i-to-j distance using only vertices from {1..k} as intermediates. When k = V every vertex is allowed, so no restriction remains and the value is the unrestricted shortest distance.

Understand How does the algorithm reveal a negative cycle? 2 marks

A negative cycle through vertex i makes a path from i back to i with negative total, so d[i][i] becomes negative; checking the diagonal at the end detects it.

Apply Three vertices, edges 1→2 (4), 2→3 (−2), 1→3 (5). Run Floyd-Warshall and give d[1][3]. 4 marks

k = 1: nothing (no edges into 1). k = 2: d[1][3] = d[1][2] + d[2][3] = 4 − 2 = 2 < 5. k = 3: nothing. d[1][3] = 2 via 1→2→3. Dijkstra happens to agree here, because 2 (distance 4) settles before 3 (distance 5) and relaxes 2→3 in time; with a negative edge that is luck, not a guarantee (Worked example 2 of 5.7).

Apply For V = 400, compare the operation counts of Floyd-Warshall and of 400 runs of heap Dijkstra on a graph with E = 2000. 3 marks

Floyd-Warshall: 400³ = 6.4 × 10⁷. Dijkstra × V: V · E log V ≈ 400 × 2000 × 9 ≈ 7.2 × 10⁶, about nine times fewer; the sparse graph favours repeated Dijkstra, provided weights are non-negative.

Analyze Explain why updating the matrix in place during round k does not corrupt the result. 4 marks

Round k only changes d[i][j] using d[i][k] and d[k][j]. Those two entries lie in column k and row k, and in round k they cannot improve: d[i][k] via k would be d[i][k] + d[k][k] = d[i][k] + 0. So every value read in round k is still its round-(k−1) value, and the in-place update equals the two-matrix version.

Beyond the syllabus

Not for the exam. Robert Floyd published the three-loop form in 1962, building on Stephen Warshall's transitive-closure algorithm of the same year. The same triple loop with other operators computes the transitive closure (OR, AND), the widest path (max, min) and the number of paths; this family is the "algebraic path problem" or semiring framework. Some syllabi end this unit with complexity classes: shortest paths and MSTs are in P, while the closely related longest simple path and the travelling salesman problem are NP-hard, so no known algorithm solves them in polynomial time; that distinction is the opening theme of the Design and Analysis of Algorithms course. Search: "semiring shortest paths", "Johnson's algorithm", "P versus NP".

Takeaways

  1. A graph is G = (V, E); the only decisions are directed or not, weighted or not, and matrix or list. Everything else is an algorithm.
  2. Adjacency lists make every traversal O(V + E); matrices cost O(V²) but answer "is there an edge?" instantly. Real graphs are sparse, so lists are the default.
  3. BFS with a queue finds fewest-edge paths; DFS with a stack finds structure (back edges, finishing times, components).
  4. A topological order exists only for a DAG; Kahn's in-degree queue or reverse DFS finishing order produces one, and a short output count proves a cycle.
  5. Counting DFS restarts counts components; a non-tree edge to a visited vertex (grey, in a digraph) is a cycle.
  6. MST: Kruskal sorts edges and uses union-find, Prim grows one tree with a priority queue; the cut property makes both exact.
  7. Dijkstra is Prim with path lengths as keys; it needs non-negative weights. Bellman-Ford trades speed for negative edges and negative-cycle detection.
  8. Floyd-Warshall is three loops with k outermost; Θ(V³) gives every pair, tolerates negative edges, and a negative diagonal entry means a negative cycle.
  9. In every trace question, state your tie-breaking order, show the table at every step, and finish with the answer in words: the order, the tree with its weight, or the path with its length.

Glossary

Adjacency list
One list of neighbours per vertex; Θ(V + E) space.
Adjacency matrix
V × V array with M[i][j] = 1 or the weight when edge i→j exists; Θ(V²) space.
Back edge
A DFS edge to an ancestor (undirected: a visited non-parent; directed: a grey vertex); proves a cycle.
Bellman-Ford
Shortest paths by V − 1 passes of relaxing all edges; O(VE); allows negative weights.
BFS
Breadth-first search: queue-based traversal by increasing distance in edges.
Connected component
Maximal set of mutually reachable vertices in an undirected graph.
Cut property
The lightest edge crossing any cut belongs to some MST.
DAG
Directed acyclic graph; the only digraphs with a topological order.
Degree
Number of edges at a vertex; in-degree and out-degree for digraphs.
DFS
Depth-first search: stack or recursion based traversal that goes deep before wide.
Dijkstra's algorithm
Single-source shortest paths for non-negative weights by settling the closest unsettled vertex.
Disjoint set (union-find)
Structure with find and union operations that tracks which vertices are connected; used by Kruskal.
Floyd-Warshall
All-pairs shortest paths by dynamic programming over intermediate vertices; Θ(V³).
Handshaking lemma
Σ deg(v) = 2|E|.
Kahn's algorithm
Topological sort by repeatedly removing in-degree-0 vertices.
Kruskal's algorithm
MST by taking edges in weight order and skipping those that close a cycle.
Minimum spanning tree
Spanning tree of least total weight.
Negative cycle
A cycle whose weights sum below zero; makes shortest paths undefined.
Path
Walk with no repeated vertex; its length is its edge count or weight sum.
Prim's algorithm
MST by growing one tree, always adding the cheapest edge leaving it.
Relaxation
Updating dist[v] when dist[u] + w(u, v) is smaller.
Shortest-path tree
Tree formed by the parent pointers after Dijkstra or Bellman-Ford.
Sparse / dense
E near V versus E near V²; decides list versus matrix.
Spanning tree
Subgraph that is a tree and contains every vertex; |V| − 1 edges.
Strongly connected
Every vertex reaches every other by a directed path.
Topological order
Vertex sequence with every edge pointing forward.
Transitive closure
Matrix saying which vertices can reach which; Warshall's algorithm.
Weighted graph
Graph with a number w(u, v) on each edge.
