2.1 One- and two-dimensional arrays and their operations

An array is a fixed number of items of the same type stored one after another in memory, so the address of any item can be computed from its index with one multiplication and one addition. That single fact makes arrays the fastest structure for "give me the k-th item" and the slowest for "squeeze a new item into the middle". Every later structure in this subject (lists, stacks, queues, heaps, hash tables) is built either on an array or as a reaction to its limits.

You need: static vs dynamic memory allocation and Big-O notation from Unit 1 (Foundations: ADTs and Algorithm Analysis).

One-dimensional arrays and the address formula

In C, int a[5]; reserves 5 × 4 = 20 bytes in one block. If the block starts at base address B and each element takes w bytes (the width), then element a[i] lives at

Address(a[i]) = B + (i − LB) × w

where LB is the lower bound of the index: 0 in C, Java and Python, 1 in some exam questions and in older languages. With B = 1000 and w = 4, a[3] is at 1000 + 3 × 4 = 1012. The formula is O(1): the computer never walks past the earlier elements, it jumps straight to the one you asked for. This is called random access.

The index runs from LB to UB (upper bound), and the length is UB − LB + 1. Reading a[5] when the array has five elements (indices 0 to 4) is the single most common C bug: C does not check bounds, so you quietly read whatever bytes lie beyond the block.

Two-dimensional arrays: row-major and column-major

A 2D array int m[3][4] is a table of 3 rows and 4 columns, but memory is one-dimensional, so the table has to be flattened. There are two conventions.

  • Row-major order stores row 0 completely, then row 1, then row 2. C, C++, Java and Python (NumPy by default) use it.
  • Column-major order stores column 0 completely, then column 1, and so on. Fortran, MATLAB and R use it.

For an array with R rows and C columns, zero-based indices, base address B and width w:

Row-major:     Address(m[i][j]) = B + (i × C + j) × w
Column-major:  Address(m[i][j]) = B + (j × R + i) × w

Read the row-major one as "skip i full rows of C elements each, then j more". With general bounds (rows from LR to UR, columns from LC to UC) replace i by (i − LR), j by (j − LC), C by (UC − LC + 1) and R by (UR − LR + 1). Examiners set questions with bounds like m[−2..3][1..5] precisely to test that substitution.

Operations on arrays and what they cost

Let n be the number of elements in use. The standard operations and their worst-case time are:

  • Access by index: O(1), by the address formula.
  • Traversal (visit every element): O(n).
  • Linear search for a value: O(n); binary search needs the array sorted and takes O(log n) (both are Unit 6).
  • Insertion at position p: every element from p to n − 1 moves one place right, so n − p shifts; inserting at the front is O(n), at the end O(1) if there is room.
  • Deletion at position p: elements p + 1 to n − 1 move one place left, n − p − 1 shifts; O(n) at the front, O(1) at the end.

Insertion into a full static array is impossible without creating a bigger array and copying, which is O(n) in itself. Chapter 2.3 turns this into the "array-based list" and chapter 2.4 shows how linked lists avoid the shifting.

Here is insertion in C, with the shift loop written from the right so no value is overwritten before it is moved:

int a[10] = {12, 7, 25, 3, 18};   /* n = 5 elements in use */
int n = 5;
void insertAt(int p, int x) {     /* assumes n < 10 and 0 <= p <= n */
    for (int k = n; k > p; k--)   /* shift right, last element first */
        a[k] = a[k - 1];
    a[p] = x;
    n++;
}
/* insertAt(2, 10) gives 12 7 10 25 3 18 ; three shifts (25, 3, 18) */

For 2D arrays, the common operations are traversal (two nested loops, O(R × C)), row sum and column sum, transpose (swap m[i][j] with m[j][i], O(R × C)), and matrix addition and multiplication (O(n³) for the schoolbook method on n × n matrices).

Worked example

Question. An array m[3][4] of 4-byte integers is stored from base address 1000. Find the address of m[1][2] when the array is stored (a) in row-major order and (b) in column-major order. (c) An array p[−2..3][1..5] of 2-byte elements starts at 500 in row-major order; find the address of p[2][4].

Solution.

  1. Identify the terms: R = 3 rows, C = 4 columns, B = 1000, w = 4, i = 1, j = 2, zero-based.
  2. (a) Row-major: Address = B + (i × C + j) × w = 1000 + (1 × 4 + 2) × 4 = 1000 + 6 × 4 = 1024.
  3. (b) Column-major: Address = B + (j × R + i) × w = 1000 + (2 × 3 + 1) × 4 = 1000 + 7 × 4 = 1028. The two answers differ because the element is reached after 6 elements in one layout and 7 in the other.
  4. (c) Bounds: rows LR = −2, UR = 3, so R = 3 − (−2) + 1 = 6; columns LC = 1, UC = 5, so C = 5. Row offset i − LR = 2 − (−2) = 4; column offset j − LC = 4 − 1 = 3.
  5. Address = 500 + (4 × 5 + 3) × 2 = 500 + 23 × 2 = 546.

Check (a) against the figure: the 7th cell (offset 6) is value 7, which is m[1][2]. Units: addresses in bytes.

Exam traps

  • Forgetting the lower bound: with 1-based indexing the formula is B + (i − 1) × w, not B + i × w. Always subtract LB first.
  • Swapping R and C in the column-major formula: it multiplies by the number of rows, because a column has R elements.
  • Using the element count instead of the byte count: the offset (i × C + j) is in elements and must be multiplied by w.
  • Counting shifts for an insertion: inserting at position p in n elements moves n − p elements, so inserting at p = n (the end) moves none.
  • Favourite question: "Derive the address formula for a 2D array in row-major and column-major order and compute an address with non-zero lower bounds." Show the derivation (skip i rows of C, then j) before plugging in numbers.

Analyze A program sums a 1000 × 1000 int matrix in C with the column loop outside and the row loop inside. Why is it slower than the other way round? 4 marks

C is row-major, so consecutive elements of a row are adjacent in memory. Walking down a column jumps 4000 bytes each step, missing the cache lines the processor just loaded; walking along a row uses every byte of each cache line. Same O(n²) work, far more cache misses.

2.2 Sparse matrices and their representation

A sparse matrix is one in which most entries are zero: a railway distance table between 8000 stations where each station connects to a handful of others, a document-by-word count table, the adjacency matrix of almost any real graph. Storing every zero wastes memory and time, so a sparse matrix is stored as a list of only its non-zero entries. This chapter covers the triplet (coordinate) representation, how much it saves, the transpose operation on it, and the linked alternative.

You need: 2D arrays and row-major order from chapter 2.1. The linked representation at the end uses nodes from chapter 2.4; read it after that chapter if pointers are new to you.

When a matrix counts as sparse

There is no fixed threshold. A matrix of R rows and C columns with t non-zero entries is worth storing sparsely when 3t is comfortably less than R × C, because each non-zero will cost three numbers instead of one. A 1000 × 1000 matrix with 5000 non-zeros holds 10⁶ cells of which only 0.5 % matter; stored densely it needs 4 MB of ints, stored as triplets about 60 KB. Dense storage is faster for small or nearly full matrices, so the representation is a trade-off, not a rule.

Triplet (coordinate) representation

Each non-zero entry is recorded as a triplet (row, column, value). The triplets are kept in a 2D array of t + 1 rows and 3 columns, sorted by row and, within a row, by column. Row 0 is a header: (number of rows, number of columns, number of non-zeros). Sorting matters: it makes addition and transpose single passes, and examiners deduct marks for unsorted triplets.

#define MAX 100
typedef struct { int row, col, value; } Term;
Term s[MAX];            /* s[0] is the header: s[0].row = R, s[0].col = C, s[0].value = t */

Converting a dense matrix to triplets is one double loop in row-major order, which produces the sorted order for free:

int k = 1;
for (int i = 0; i < R; i++)
    for (int j = 0; j < C; j++)
        if (m[i][j] != 0) { s[k].row = i; s[k].col = j; s[k].value = m[i][j]; k++; }
s[0].row = R; s[0].col = C; s[0].value = k - 1;

In the literature this layout is called COO (coordinate list). The space used is 3(t + 1) integers against R × C for dense storage.

Transpose of a sparse matrix

The transpose swaps rows and columns: entry (i, j, v) becomes (j, i, v). Swapping the fields of every triplet is trivial, but the result is no longer sorted by row. Two standard algorithms fix that.

  1. Simple transpose. For each column c of the original (c = 0 to C − 1), scan all t triplets and copy those with col = c, swapping row and col. Output is sorted because columns are visited in order. Time O(C × t).
  2. Fast transpose (Horowitz and Sahni). Count the terms in each column: rowTerms[c]. Compute the starting position of each column's group in the output: startPos[0] = 1 and startPos[c] = startPos[c − 1] + rowTerms[c − 1]. Then make one pass over the triplets, placing each at startPos[its column] and incrementing that slot. Time O(C + t), with O(C) extra space.

Linked representation

When the matrix changes often (entries inserted and deleted during a computation), an array of triplets forces shifting. The linked version keeps one linked list per row, each node holding (col, value, next); rows are indexed by an array of head pointers. Some textbooks also link each node into its column list ("orthogonal" or multilist representation), so a node has both a right and a down pointer. Some syllabi list sparse matrices under linked lists for this reason. The dense-to-triplet idea reappears as the adjacency list of a graph in Unit 5.

Exam traps

  • Leaving out the header triplet, or putting the count of non-zeros in the wrong field (it is the third field, where the value normally goes).
  • Listing triplets in the order you spotted them instead of row-major sorted order; the transpose and addition algorithms depend on the sort.
  • Claiming the triplet form always saves space: it only does when 3(t + 1) < R × C. Say the condition.
  • Transpose by swapping fields only: the result must be re-sorted by the new row; that is the whole point of the simple and fast transpose algorithms.
  • Favourite question: "Write the fast transpose algorithm and trace it on a given matrix." Show rowTerms, startPos and the final array as three separate tables.

2.3 List ADT: array-based implementation

A list is an ordered collection a₁, a₂, …, aₙ where you can insert, delete, find and read the k-th element. The List ADT says what these operations do; this chapter implements them on an array, which gives instant access by position but pays with shifting on every insertion and deletion. Knowing exactly what each operation costs here is what makes the linked lists of the next three chapters look worthwhile.

You need: the idea of an abstract data type from Unit 1 (Abstract data types), and array insertion and deletion from chapter 2.1.

The List ADT

An ADT lists operations and their meaning, not the code. For a list of n elements with positions 0 to n − 1 (Weiss's textbook uses this wording; some syllabi call it simply "List"):

  • makeEmpty(L): L becomes the empty list; isEmpty(L): true when n = 0.
  • insert(L, x, p): put x at position p; the old elements at p … n − 1 move to p + 1 … n.
  • delete(L, p) (or delete by value): remove the element at p; later elements move one position down.
  • find(L, x): the position of the first x, or −1; findKth(L, k): the element at position k.
  • size(L), printList(L): n, and the elements in order.

Any implementation that provides these with these meanings is a valid List. The array version is called a sequential or contiguous list; the pointer version is the linked list.

Array implementation

Keep the elements in a[0 … n − 1], with n the current size and cap the capacity of the array. Positions map straight to indices, so findKth is one array access.

typedef struct { int *a; int n; int cap; } List;

int findKth(List *L, int k) { return L->a[k]; }            /* O(1), 0 <= k < n */

int find(List *L, int x) {                                   /* O(n) linear search */
    for (int i = 0; i < L->n; i++) if (L->a[i] == x) return i;
    return -1;
}
int insert(List *L, int x, int p) {                          /* O(n - p) shifts */
    if (L->n == L->cap || p < 0 || p > L->n) return 0;      /* full or bad position */
    for (int i = L->n; i > p; i--) L->a[i] = L->a[i - 1];    /* shift right from the end */
    L->a[p] = x; L->n++; return 1;
}
int delete(List *L, int p) {                                 /* O(n - p - 1) shifts */
    if (p < 0 || p >= L->n) return 0;
    for (int i = p; i < L->n - 1; i++) L->a[i] = L->a[i + 1]; /* shift left from p */
    L->n--; return 1;
}

Two details carry marks. The insert loop runs from the end backwards so that no element is overwritten before it has been copied; the delete loop runs forwards for the same reason. And both check the position: inserting at p = n is legal (append), inserting at p = n + 1 is not.

Cost of each operation

With n elements: findKth O(1); find O(n); insert and delete O(n) in the worst case (position 0) and O(1) at the end; on average about n/2 moves when positions are equally likely. printList O(n). Space is O(cap), and the unused capacity is wasted memory, the price of fast access.

Growing the array. A static array refuses insertions once n = cap. The practical fix is to allocate a new array of double the capacity, copy the n elements, and free the old one. A single such copy costs O(n), but doubling means it happens only after n insertions, so the copying cost averaged over all insertions is O(1) per insertion. This is called amortized constant time (see the worked example). Shrinking when the list falls below a quarter full keeps memory in check without thrashing.

Question. (a) Starting from the empty list with capacity 8, perform insert(5, 0), insert(9, 1), insert(2, 0), insert(7, 1), delete(2), find(9). Exam traps

  • Writing the insert shift loop forwards (a[i+1] = a[i] for i from p upwards) copies a[p] into every later slot. Shift from the end.
  • Off-by-one on the legal positions: insert allows 0 ≤ p ≤ n, delete allows 0 ≤ p ≤ n − 1.
  • Forgetting to update n after an insert or delete, so the list "loses" or "keeps" an element.
  • Saying array lists are "O(1) insertion": only at the end, and only while there is capacity.
  • Favourite question: "Compare array and linked implementations of the List ADT." Give a table: access O(1) vs O(n); insert/delete after a known position O(n) vs O(1); memory contiguous with wasted capacity vs per-node pointer overhead.

2.4 Singly linked lists: insertion, deletion and traversal

A singly linked list stores each element in its own small block of memory, a node, together with the address of the next node. The nodes can be anywhere; the chain of addresses gives the order. Inserting or deleting now means changing one or two addresses instead of shifting everything, which is why linked lists back stacks, queues, hash-table chains and polynomial arithmetic. The price is that you can only reach a node by walking from the head.

You need: pointers, struct and malloc from Unit 1 (Static and dynamic memory allocation), and the List ADT from chapter 2.3.

Nodes, head and NULL

typedef struct Node {
    int data;
    struct Node *next;   /* address of the next node, or NULL */
} Node;
Node *head = NULL;       /* the list is empty when head is NULL */

The head is a pointer variable holding the address of the first node; it is not itself a node. The last node's next is NULL (address 0), which marks the end. A list is therefore fully described by its head; lose the head and the whole list is unreachable. Some syllabi also mention lists with a header node: a dummy first node with no data, kept so that insertion at the front and in the middle use the same code. This book uses a plain head pointer, the form most exams expect.

Creating a node is a malloc call plus two assignments; always check for NULL (allocation failure):

Node *makeNode(int x) {
    Node *p = (Node *)malloc(sizeof(Node));
    if (p == NULL) { printf("out of memory\n"); exit(1); }
    p->data = x; p->next = NULL;
    return p;
}

Traversal and search

Walk a pointer from the head until it becomes NULL. The loop is the pattern every other operation is built from.

void traverse(Node *head) {
    for (Node *p = head; p != NULL; p = p->next) printf("%d -> ", p->data);
    printf("NULL\n");
}
Node *search(Node *head, int x) {            /* returns the node holding x, or NULL */
    for (Node *p = head; p != NULL; p = p->next) if (p->data == x) return p;
    return NULL;
}

Both are O(n). Finding the k-th element is also O(n): there is no address formula, you count k steps.

Insertion

  1. At the front, O(1): make the node, point its next at the current head, make it the new head. p->next = head; head = p; The order is fixed: assign head = p first and the old list is lost.
  2. After a given node q, O(1): p->next = q->next; q->next = p; Again the new node's next is set first, so the rest of the list is never disconnected (figure 2.4.1).
  3. At the end, O(n) without a tail pointer: walk to the last node (while (t->next != NULL) t = t->next;) then t->next = p. If the list is empty, the new node becomes the head.
  4. At position k (0-based): if k = 0 use step 1; otherwise walk k − 1 steps to the node before the position and use step 2.

Deletion

To unlink a node you must change the next of the node before it, so deletion by value walks with two pointers, prev and cur:

void deleteValue(Node **head, int x) {
    Node *prev = NULL, *cur = *head;
    while (cur != NULL && cur->data != x) { prev = cur; cur = cur->next; }
    if (cur == NULL) return;                       /* not found */
    if (prev == NULL) *head = cur->next;           /* deleting the first node */
    else prev->next = cur->next;                   /* bypass cur */
    free(cur);                                     /* give the memory back */
}

The function takes Node **head (the address of the head pointer) because deleting the first node must change the caller's head. Deleting the front is O(1); deleting the last node or a value in the middle is O(n) because of the walk. free is not optional: a deleted node that is never freed is a memory leak (chapter 2.8).

2.5 Doubly linked lists

A doubly linked list gives every node two pointers, one to the next node and one to the previous. You can walk the list in both directions, and, given a pointer to any node, you can delete it or insert beside it in O(1) without a second pointer trailing behind. The cost is one more pointer per node and twice as many links to update. Browser back/forward history, undo/redo stacks, music playlists and the deque of Unit 3 are all doubly linked lists underneath.

You need: singly linked lists and the two-step insertion rule from chapter 2.4.

The node and its invariant

typedef struct DNode {
    struct DNode *prev;
    int data;
    struct DNode *next;
} DNode;
DNode *head = NULL;      /* first node's prev is NULL; last node's next is NULL */

The structure keeps one rule at all times: for every pair of neighbouring nodes a and b, a->next == b and b->prev == a. Every operation below is just "re-establish that rule for the nodes around the change". If you can state the rule, you can derive the code in the exam instead of memorising it.

Traversal forward is the same loop as chapter 2.4. Traversal backward starts from the last node and follows prev; with a tail pointer that start is O(1).

Insertion after a node

To insert new node p after node q (q not the last node), four pointers change. The order matters only in that p's pointers are set before q's and q->next's are changed:

  1. p->next = q->next; p looks forward at q's old successor.
  2. p->prev = q; p looks back at q.
  3. q->next->prev = p; the old successor looks back at p (skip this if q was last; set tail = p instead).
  4. q->next = p; q looks forward at p. Do this last, because step 3 still needs q->next to mean the old successor.

Insertion at the front: p->next = head; p->prev = NULL; if (head) head->prev = p; head = p; Insertion before a node is insertion after its prev, which is the operation a singly linked list cannot do in O(1).

Deletion of a node

Given a pointer cur to the node to remove, two links bypass it:

void deleteNode(DNode **head, DNode *cur) {
    if (cur->prev != NULL) cur->prev->next = cur->next;   /* predecessor skips cur */
    else *head = cur->next;                                /* cur was the first node */
    if (cur->next != NULL) cur->next->prev = cur->prev;   /* successor skips cur */
    free(cur);
}

No search for the previous node is needed; cur carries it. That is the whole advantage over the singly linked version, where deletion by node pointer is O(n). The two ifs handle the first and last nodes; in a list with a dummy header and trailer node they disappear, which is why many libraries use sentinels.

Cost and applications

Insert and delete beside a known node: O(1). Reaching a node by position or value: O(n), as for any linked list, but a walk can start from whichever end is nearer when the position is known. Memory: three fields per node, typically 24 bytes for an int payload on a 64-bit machine, against 16 for a singly linked node. When a syllabus lists "doubly linked lists and their applications", the usual answers are undo/redo (the current state sits in the middle, undo moves prev, redo moves next, a new action deletes everything after the cursor), browser history, the LRU cache (a hash table pointing into a doubly linked list so that any page can be moved to the front in O(1)), and the deque of Unit 3.

2.6 Circular linked lists

In a circular linked list the last node points back to the first instead of to NULL, so the list has no end: from any node you can reach every other node by walking forward. Keep a single pointer to the last node and both ends of the list are one step away, which gives O(1) insertion at the front and at the back with one pointer. Round-robin CPU scheduling, players taking turns in a game, the circular queue of Unit 3 and the Josephus problem all live naturally on this structure.

You need: singly linked list insertion and deletion from chapter 2.4.

Structure and the tail pointer

The node is the same as in chapter 2.4: data and next. What changes is the convention: the last node's next holds the address of the first node, and NULL appears nowhere except when the list is empty. Textbooks draw the list with a head pointer, but the useful choice is a pointer to the last node, usually called tail (some syllabi call the structure a "circularly linked list"). Then:

  • tail is the last node, reached in O(1).
  • tail->next is the first node, also O(1).
  • Empty list: tail == NULL. One node: tail->next == tail.

Some syllabi list "linked lists with header node": a circular list with a permanent dummy node has no empty case at all (the header points to itself), which simplifies every routine at the cost of one node.

Traversal: why a do-while

The while (p != NULL) loop of chapter 2.4 never ends on a circular list. Start at the first node, process it, and stop when you are back where you started. Because the test is at the end, a do … while visits a one-node list correctly.

void traverse(Node *tail) {
    if (tail == NULL) return;              /* empty */
    Node *p = tail->next;                  /* first node */
    do { printf("%d -> ", p->data); p = p->next; } while (p != tail->next);
    printf("(back to %d)\n", tail->next->data);
}

Insertion and deletion with a tail pointer

  1. Insert at front, O(1): if empty, p->next = p; tail = p; else p->next = tail->next; tail->next = p;.
  2. Insert at end, O(1): same two statements as the front, then tail = p;. The node becomes the new last node and the old first node stays first.
  3. Delete the front, O(1): Node *f = tail->next; if f == tail the list had one node, so tail = NULL; else tail->next = f->next;. Then free(f).
  4. Delete the last, O(n): you need the node before tail, so walk from tail->next until q->next == tail, then q->next = tail->next; free(tail); tail = q;. A circular doubly linked list makes this O(1) too.

Insertion after a given node and deletion by value are the same two-pointer walks as chapter 2.4, with the loop stopping when it returns to the first node.

Applications

Round-robin scheduling: processes form a ring; the scheduler runs the current one for a time slice and moves to next, forever, with finished processes deleted in O(1) if the scheduler holds the previous pointer. Josephus problem: n people in a circle, every k-th is removed until one remains; a circular list models it directly (worked example). Circular buffers and queues: Unit 3 implements the circular queue on an array, but the linked version with a tail pointer is the same idea. Multiplayer turns and image carousels: "next" from the last item is the first.

2.7 Polynomial manipulation using linked lists

A polynomial such as 5x³ + 4x² + 2 is a list of terms, each a coefficient and an exponent. Storing it in an array indexed by exponent wastes space the moment the polynomial is sparse (x¹⁰⁰ + 1 needs 101 slots for two terms), so each term becomes a node in a linked list kept in decreasing order of exponent. Addition then becomes a walk down two sorted lists, the same merge pattern used later in merge sort and in sparse-matrix addition. This is the linked-list application examiners ask for most.

You need: singly linked list insertion at the end from chapter 2.4.

Representation

typedef struct Term {
    int coef;            /* coefficient, never 0 in a stored term */
    int exp;             /* exponent, strictly decreasing along the list */
    struct Term *next;
} Term;

Two rules keep the representation canonical, so that two equal polynomials have identical lists: terms are sorted by decreasing exponent, and no term has coefficient 0. The zero polynomial is the empty list. A term with exp 0 is the constant. Under these rules 5x³ + 4x² + 2 is the list (5,3) → (4,2) → (2,0) → NULL; the missing x¹ term is simply absent.

Building a polynomial means appending terms in the order given; with a tail pointer each append is O(1). An attach(coef, exp, &tail) helper that creates a node and links it after the tail keeps the addition code short.

Addition: the merge walk

Keep a pointer p on P and q on Q, both starting at the first term. Repeat while both are non-NULL:

  1. If p->exp > q->exp: copy p's term to the result; advance p.
  2. If p->exp < q->exp: copy q's term; advance q.
  3. If the exponents are equal: sum = p->coef + q->coef; if sum ≠ 0 attach (sum, exp) to the result; advance both. A zero sum attaches nothing.

When one list runs out, copy the rest of the other. Each step advances at least one pointer, so the time is O(m + n) for polynomials of m and n terms, and the result has at most m + n terms.

Term *add(Term *p, Term *q) {
    Term *head = NULL, *tail = NULL;
    while (p && q) {
        if (p->exp > q->exp)      { attach(p->coef, p->exp, &head, &tail); p = p->next; }
        else if (p->exp < q->exp) { attach(q->coef, q->exp, &head, &tail); q = q->next; }
        else {
            int s = p->coef + q->coef;
            if (s != 0) attach(s, p->exp, &head, &tail);
            p = p->next; q = q->next;
        }
    }
    for (; p; p = p->next) attach(p->coef, p->exp, &head, &tail);   /* leftovers */
    for (; q; q = q->next) attach(q->coef, q->exp, &head, &tail);
    return head;
}

Subtraction, multiplication and evaluation

Subtraction (some syllabi list "Polynomial Addition/Subtraction"): P − Q is P + (−Q); either negate every coefficient of a copy of Q and call add, or write the same walk with p->coef − q->coef in the equal case and −q->coef when copying from Q. The zero-sum rule still applies.

Multiplication: for each term of P, multiply it with every term of Q (coefficients multiply, exponents add) and add the resulting single-term polynomial into the running result with the add routine, which merges like terms. With m and n terms there are m × n products. Inserting each product one at a time into a sorted result of up to m × n terms costs O(m²n²); multiplying one term of P by the whole of Q (a sorted n-term list) and merging that list into the running result with add costs O(mn) per term of P, O(m²n) overall. Evaluation at x = a is one walk computing coef × aᵉˣᵖ per node, O(n) with a power function, or Horner's rule when exponents are dense.

Fast multiplication of dense polynomials uses Karatsuba's divide-and-conquer method or the FFT (as in Schönhage–Strassen) to beat O(mn). Search "sparse polynomial representation" and "polynomial multiplication FFT".

2.8 Dynamic storage management and garbage collection

Every malloc in this unit took memory from a pool called the heap, and every free gave it back. Dynamic storage management is how that pool is organised: which free block to hand out, how to merge freed blocks, and what to do when the free space is scattered in small pieces. Garbage collection is the automatic version, where the system frees the blocks no pointer reaches. Few syllabi list this topic in Data Structures, so this chapter is short.

The free list and allocation strategies

The allocator keeps the unused blocks of the heap on a free list, a linked list in which each block records its size and the next free block. On a request for n bytes it picks a block of size ≥ n by one of three policies, splits it, and leaves the remainder on the list:

  • First fit: the first block large enough. Fast; leaves small fragments near the front of the list.
  • Best fit: the smallest block large enough. Scans the whole list; leaves tiny, often unusable, leftovers.
  • Worst fit: the largest block. Leaves big remainders; rarely best in practice.

On free, the block returns to the list and is coalesced (merged) with any free neighbour, found through size fields at both ends of each block (boundary tags). Fragmentation is external when the free space is large in total but no single block is large enough, and internal when a block handed out is bigger than requested.

Garbage collection and compaction

In C the programmer calls free; forget it and the block leaks. Java, Python and Go instead collect garbage: blocks that no live variable can reach. Two classic methods:

  1. Reference counting: each block stores how many pointers refer to it, updated on every assignment; a block whose count drops to 0 is freed at once. Simple and prompt, but two blocks that point at each other (a cycle) never reach 0, so they leak.
  2. Mark and sweep: starting from the roots (global variables, the stack), follow every pointer and mark each block reached; then sweep the whole heap, freeing every unmarked block. Cycles are no problem, but the program pauses while the collector runs, and the heap stays fragmented.

Compaction fixes the fragmentation: after marking, the live blocks are slid to one end of the heap and every pointer to them is rewritten (figure 2.8.1).

Exam traps

  • Best fit means the smallest block that fits, found by scanning every block, not the first adequate one.
  • Confusing internal (inside an allocated block) and external (between blocks) fragmentation.
  • Claiming reference counting handles all garbage: cycles are the standard counterexample.
  • Favourite question: "Explain mark-and-sweep and the need for compaction, with a diagram." Draw roots, reachable and unreachable blocks, then the compacted heap.

Takeaways

  1. An array element's address is base + offset × width; for 2D arrays the offset is i × C + j in row-major order and j × R + i in column-major order, after subtracting the lower bounds.
  2. Arrays give O(1) access by index and O(n) insertion or deletion because of shifting; linked lists reverse that trade.
  3. A sparse matrix is stored as sorted (row, col, value) triplets with a header; it saves space only when 3(t + 1) < R × C.
  4. The List ADT names the operations; array and linked implementations differ only in cost. Doubling capacity makes append amortized O(1).
  5. Every linked insertion sets the new node's pointer first and the existing node's pointer second; the reverse order loses the rest of the list.
  6. Deleting from a singly linked list needs the previous node; doubly linked nodes carry it, so deletion by node pointer is O(1).
  7. A circular list with a tail pointer gives O(1) insertion at both ends and needs a do-while to traverse.
  8. Polynomial addition is a merge of two exponent-sorted lists in O(m + n); drop any term whose coefficient sums to zero.
  9. Free-list allocators choose blocks by first, best or worst fit and must coalesce; garbage collectors mark from the roots and sweep, and compaction removes external fragmentation.

Analyze and evaluate

12. (Spans 2.1, 2.3, 2.4.) A student records sensor readings that arrive once per second and must be deleted when older than one hour, with queries for the k-th most recent reading. Evaluate array list, singly linked list and doubly linked list for this workload. (12 marks)

Outline: workload: append at one end, delete at the other, random access by position; array list: O(1) append amortized, O(n) delete at front unless a circular buffer is used (Unit 3), O(1) k-th; singly: O(1) append with tail, O(1) delete front, O(k) k-th; doubly: same plus backward walk from the tail for small k; recommend a circular array buffer or a doubly linked list with a tail, with reasons; note memory per element.

13. (Spans 2.2 and 2.7.) Sparse matrices and polynomials are both stored as lists of non-zero terms. Analyse what the two representations share, how their addition algorithms are alike, and where they differ. (10 marks)

Outline: both store only non-zero entries with their position (exponent vs row/col), both kept sorted so addition is a merge, both drop zero sums; sparse addition compares (row, col) pairs lexicographically, polynomial compares one exponent; triplets usually in an array (transpose needs re-sorting), polynomials in a linked list (insertion-friendly); complexity O(t₁ + t₂) and O(m + n).

14. (Spans 2.4, 2.5, 2.6.) For each of the following, choose the list variant and the pointers to keep, and justify with complexities: a music player with next/previous and repeat-all; a hash table's collision chain; a round-robin scheduler that removes finished tasks. (12 marks)

Outline: music: circular doubly linked list, current pointer, O(1) next/previous, repeat-all is free; chain: singly linked, head only, insert at front O(1), search O(chain length), least memory; scheduler: circular (doubly, or singly with prev kept) with current pointer, O(1) advance and O(1) removal; mention memory per node for each choice.

15. Evaluate the claim "linked lists are always better than arrays because insertion is O(1)". (8 marks)

Outline: O(1) only at a known node; finding the position is O(n); arrays have O(1) access, binary search, cache locality and no pointer overhead; amortized O(1) append; linked lists win for frequent insert/delete at known positions and unknown sizes; a measured comparison on a modern CPU often favours arrays for small elements; conclusion with conditions.

16. Analyse why reference counting cannot free a doubly linked list that has become unreachable, and propose a fix. (8 marks)

Outline: each node is referenced by its neighbour's prev and next, so counts stay ≥ 1 after the head is dropped; the cycle keeps itself alive; fixes: break links before dropping the head, use weak references for prev, or run a cycle-detecting or mark-and-sweep collector; mention CPython's approach.

Glossary

Array
Fixed number of same-type elements stored contiguously; element address computed from the index.
Base address
Address of the first element of an array, B in the address formulas.
Row-major order
2D layout storing each row completely before the next; used by C.
Column-major order
2D layout storing each column completely before the next; used by Fortran and MATLAB.
Sparse matrix
A matrix in which most entries are zero, stored as its non-zero entries only.
Triplet
(row, column, value) record of one non-zero entry; the header triplet holds (rows, columns, count).
Fast transpose
Sparse-matrix transpose that computes each column's starting position and places every term in one pass, O(C + t).
List ADT
Ordered collection with insert, delete, find, findKth and size defined by their meaning, not their code.
Amortized cost
Cost of an operation averaged over a whole sequence; a doubling array appends in amortized O(1).
Node
A block holding one element and one or more pointers to other nodes.
Head
Pointer to the first node of a list; NULL when the list is empty.
Tail
Pointer to the last node; in a circular list, tail→next is the first node.
NULL
The pointer value meaning "no node"; marks the end of a non-circular list.
Header node
A dummy node kept permanently at the front so that insert and delete have no empty-list special case.
Singly linked list
Nodes each with one next pointer; traversal in one direction only.
Doubly linked list
Nodes with prev and next pointers; O(1) deletion given a node pointer.
Circular linked list
List whose last node points back to the first; no NULL links.
Traversal
Visiting every node in order, following pointers from the head.
Josephus problem
Eliminating every k-th person around a circle; modelled by a circular list or the recurrence J(n) = (J(n − 1) + k) mod n.
Polynomial list
Linked list of (coefficient, exponent) terms in decreasing exponent order with no zero coefficients.
Merge walk
Advancing two pointers through two sorted lists, taking the smaller key each step; the shape of polynomial and sparse addition.
Free list
Linked list of unused heap blocks kept by the allocator.
First fit / best fit / worst fit
Placement policies: first adequate block, smallest adequate block, largest block.
Coalescing
Merging a freed block with adjacent free blocks.
Fragmentation
External: free memory split into blocks too small to use; internal: waste inside an allocated block.
Garbage collection
Automatic freeing of blocks no live pointer reaches; by reference counting or mark-and-sweep.
Compaction
Moving live blocks together and updating pointers to leave one large free block.
