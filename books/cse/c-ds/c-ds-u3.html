3.1 Stack ADT: push, pop and peek

A stack is a list where you may add and remove only at one end, called the top. Whatever went in last comes out first, so a stack is a LIFO (last in, first out) structure. It exists because many jobs naturally reverse order: undoing edits, returning from function calls, matching brackets, backing out of a maze. Every compiler, every browser's back button and every recursive program depends on one.

You need: the idea of an abstract data type (Unit 1, Abstract data types) and array indexing (Unit 2, One- and two-dimensional arrays).

The ADT: what a stack promises

An abstract data type lists the operations and what they do, not how they are stored. Anna Univ and SRM list this as "Stack ADT"; IITD and IITB simply say "stacks" under linear ADTs. The stack ADT has five operations on a stack S:

  • push(S, x): put item x on the top. The stack grows by one.
  • pop(S): remove the top item and return it. The stack shrinks by one.
  • peek(S) (also called top(S)): return the top item without removing it.
  • isEmpty(S): true when the stack holds nothing.
  • isFull(S): true when a bounded stack has no room left (only meaningful for array stacks).

Two error states follow. Underflow is a pop or peek on an empty stack; overflow is a push on a full one. A correct implementation checks for both before touching the data. Every operation takes constant time, O(1), because only the top is ever touched; no shifting, no searching.

How the operations behave together

Think of a pile of plates in a hostel mess. New plates go on top and the next plate taken is the top one. If you push 10, then 20, then 30, the pile reads 10 at the bottom and 30 at the top. A pop removes 30 and returns it. Push 40 and the pile reads 10, 20, 40. Figure 3.1.1 shows exactly these three moments.

Where stacks are used

SRM lists the function call stack as an application, and it is the one you use without noticing. When a C program calls a function, the machine pushes an activation record (return address, parameters, local variables) on the run-time stack; when the function returns, that record is popped. Recursion is just many pushes before the first pop. For fact(3) the records for fact(3), fact(2), fact(1) are pushed in that order, then popped in reverse: fact(1) returns 1, fact(2) returns 2, fact(3) returns 6. Too deep a recursion overflows this stack, which is the "segmentation fault" you see with a missing base case.

Other uses, each worked in the chapters that follow: converting and evaluating arithmetic expressions (3.3, 3.4), checking balanced brackets (3.4), undo in editors, the back button in a browser, and depth-first search of a graph (Unit 5, Breadth-first and depth-first traversal).

Exam traps

  • peek is not pop. peek returns the top but leaves the stack as it is. Students write the stack one item shorter after a peek and lose the rest of the trace.
  • Underflow vs overflow. Pop on empty = underflow; push on full = overflow. The examiner's favourite one-mark question is "what happens when you pop an empty stack?"
  • Which end is the top? In the trace, write the stack bottom → top and say so. Reversing it silently makes every pop look wrong.
  • Order of returned values. Push 1, 2, 3 then pop three times returns 3, 2, 1. A stack reverses the input order; that is the whole point.
  • "Is every push/pop sequence possible?" No. Pushing 1, 2, 3 in order can never produce the pop order 3, 1, 2: once 3 is popped, 2 is on top of 1 and must come out before 1.

Understand Why is a stack called LIFO, and why does recursion need one? 3 marks

Insertion and deletion both happen at the top, so the last item inserted is the first removed. Each recursive call must save where to resume and its local values; the calls finish in reverse order of starting, which is exactly LIFO, so the activation records are pushed and popped on a stack.

Trace: 4 → 4,8 → 4,8,15 → pop 15 → 4,8,16 → pop 16 → pop 8 → 4,23. Final stack (bottom → top): 4, 23. Popped values in order: 15, 16, 8.

Apply Items 1, 2, 3, 4 are pushed in that order, with pops allowed at any time. Can the pop sequence be 2, 4, 3, 1? Can it be 4, 1, 2, 3? 4 marks

2, 4, 3, 1: yes. push 1, push 2, pop 2, push 3, push 4, pop 4, pop 3, pop 1. 4, 1, 2, 3: no. To pop 4 first, 1, 2, 3 must all be on the stack below it, so after 4 the next pop must be 3, not 1.

Analyze A text editor supports Undo with a stack of edits. What happens to Redo, and how would you support both? 5 marks

Undo pops the last edit and reverses it. To allow Redo, push the undone edit onto a second stack (the redo stack); Redo pops from it and re-applies, pushing back onto the undo stack. Any new edit clears the redo stack, because the redo history is no longer valid. Two stacks give both operations in O(1).

Beyond the syllabus

Not for the exam. In practice you rarely write a stack from scratch: C++ gives std::stack (an adaptor over a deque), Java gives ArrayDeque (preferred over the old synchronised Stack class), and Python uses a plain list with append and pop. The function call stack you met here is where buffer-overflow attacks live: writing past a local array can overwrite the saved return address, which is why compilers add stack canaries and operating systems randomise stack addresses. Search "stack canary", "ArrayDeque vs Stack Java" and "tail call optimisation" to see where this topic goes next.

3.2 Array and linked list implementation of stacks

The stack ADT of 3.1 can be stored two ways. An array stack keeps the items in a fixed array and remembers the index of the top; it is fast and compact but has a capacity. A linked stack keeps the items as nodes and makes the head of the list the top; it grows as long as memory lasts but pays for a pointer per item. Both give O(1) push, pop and peek. Exams ask you to write both in C and to say when each is the better choice.

You need: 3.1 for the operations; Unit 2 (Singly linked lists: insertion, deletion and traversal) for nodes and malloc.

Array implementation

Keep an array a[MAX] and an integer top. The convention used in most Indian textbooks is top = −1 for empty, and a[top] is the top item. push first increments top, then stores; pop first reads, then decrements. isFull is top == MAX − 1. SRM lists this as "Push, Pop, Peek: array implementation"; NITK calls the two operations "insertion and deletion".

#define MAX 4
int a[MAX];
int top = -1;

int isEmpty(void) { return top == -1; }
int isFull(void)  { return top == MAX - 1; }

void push(int x) {
    if (isFull()) { printf("Overflow\n"); return; }
    a[++top] = x;                 /* increment, then store */
}
int pop(void) {
    if (isEmpty()) { printf("Underflow\n"); return -1; }
    return a[top--];              /* read, then decrement */
}
int peek(void) {
    if (isEmpty()) { printf("Underflow\n"); return -1; }
    return a[top];
}

This is C. The order inside push and pop matters: a[++top] moves to the new slot before writing; a[top--] reads the current slot and only then moves down. Nothing is erased on pop; the old value stays in memory but is now above the top and is treated as garbage.

Linked list implementation

Use a singly linked list and make the head the top. Pushing is insertion at the head and popping is deletion at the head, both O(1) with no traversal. If you made the tail the top, pop would need to walk the whole list to find the new tail, O(n), so never do that with a singly linked list. NITT and Manipal list this as "linked stacks".

struct node { int data; struct node *next; };
struct node *top = NULL;         /* empty stack */

void push(int x) {
    struct node *p = malloc(sizeof *p);
    if (p == NULL) { printf("Overflow (no memory)\n"); return; }
    p->data = x;
    p->next = top;                /* new node points to old top */
    top = p;                      /* new node becomes the top   */
}
int pop(void) {
    if (top == NULL) { printf("Underflow\n"); return -1; }
    struct node *p = top;
    int x = p->data;
    top = top->next;              /* unlink the first node */
    free(p);
    return x;
}
int peek(void) { return top ? top->data : -1; }

Two lines carry the whole logic. In push, p->next = top must come before top = p, or the old list is lost. In pop, save top in p before moving top, or you cannot free the node.

Exam traps

  • a[++top] vs a[top++]. With top = −1 for empty, push must pre-increment. Post-increment writes to a[−1] on the first push, which is undefined behaviour in C.
  • isFull test. With top starting at −1, full is top == MAX − 1, not top == MAX. If your book starts top at 0 (pointing to the next free slot), full is top == MAX; state which convention you use.
  • Order of pointer assignments in linked push. Writing top = p before p->next = top makes the node point to itself and loses the rest of the stack.
  • Linked stack never overflows? It does when malloc returns NULL. Say "overflow only when memory is exhausted"; do not say "never".
  • Favourite question: "Write C functions for push and pop using a linked list and explain why the head is used as the top." The answer is the O(1) argument above.

Apply Linked stack, starting empty: push(11), push(22), push(33), pop(), push(44). Draw the final list from top and state what pop returned. 4 marks

After the three pushes: top → 33 → 22 → 11 → NULL. pop returns 33 and frees that node: top → 22 → 11 → NULL. push(44): top → 44 → 22 → 11 → NULL. pop returned 33.

Apply An array stack of int with MAX = 1000 is used for a job that usually holds 10 items. How many bytes are reserved, and how much is typically wasted (4-byte int)? Would a linked stack be better? 4 marks

Reserved: 1000 × 4 = 4000 bytes. Typically used: 10 × 4 = 40 bytes, so about 3960 bytes wasted. A linked stack with 10 nodes uses 10 × (4 + 8) = 120 bytes plus allocator overhead, so it is better on memory here, at the cost of a malloc per push.

Analyze A student's linked pop first moves top to the next node and only then calls free on top. What goes wrong? 4 marks

After top = top->next, top already points to the second node, so free(top) frees the wrong node (the new top) and leaks the old one. The stack is then corrupt. Fix: save the old top in a temporary pointer, move top, then free the temporary.

Beyond the syllabus

Not for the exam. Real libraries use a third design: a dynamic array that doubles its capacity when full (C++ std::vector, Java ArrayList, Python list). Push is then O(1) amortised: a rare O(n) copy is paid for by the many cheap pushes before it. It keeps the array's cache-friendliness and drops the fixed limit, which is why linked stacks are rare in production code. The Linux kernel and embedded systems still use fixed array stacks where allocation is forbidden. Search "amortized analysis dynamic array" and "lock-free stack ABA problem" to go further.

3.3 Infix, prefix and postfix conversion

We write arithmetic in infix form, operator between operands: A + B. A machine prefers postfix (operator after both operands: A B +) or prefix (operator before: + A B), because those two forms need no brackets and no precedence rules to be read correctly. Converting infix to postfix is the standard first application of a stack, and the trace is a guaranteed exam question at Anna Univ, SRM, NITK, Manipal and Christ. Prefix is also called Polish notation and postfix reverse Polish notation (RPN).

You need: 3.1 (push, pop, peek). Expression trees are covered in Unit 4, Expression trees; here we use the tree only as a picture.

Precedence, associativity and why brackets vanish

In infix, which operation happens first depends on precedence (^ highest, then * and /, then + and −) and, for equal precedence, on associativity (left to right for + − * /; right to left for ^). Brackets override both. In postfix and prefix the position of each operator already says which operands it takes, so neither precedence nor brackets are needed. Figure 3.3.1 shows why: all three forms are the same expression tree read in three orders.

Infix to postfix with a stack (the shunting-yard method)

Scan the infix string left to right. Operands go straight to the output; operators wait on a stack until an operator of lower precedence, a closing bracket or the end of input forces them out.

  1. Operand (A, B, a number): append it to the output.
  2. (: push it. It acts as a wall; nothing below it can be popped by precedence.
  3. ): pop and output operators until a ( is on top; pop that ( and discard it. Brackets never reach the output.
  4. Operator op: while the stack is not empty, the top is not (, and the top has higher precedence than op, or equal precedence and op is left-associative: pop the top to the output. Then push op.
  5. End of input: pop everything to the output. If a ( appears here, the brackets were unbalanced.

Each token is pushed and popped at most once, so the conversion is O(n) for n tokens. The only decision in the whole method is step 4, the comparison with the top of the stack.

Infix to prefix

Reverse the infix string, swapping every ( with ). Run the postfix algorithm with one change in step 4: pop only while the top has strictly higher precedence (equal precedence does not pop, so that the final reversal restores left associativity). Reverse the result. The hand method is simpler for short expressions: fully bracket the infix, then move each operator to the start of its own bracket pair (prefix) or the end (postfix), and delete the brackets.

Exam traps

  • Equal precedence. For postfix, an incoming * must pop a waiting * or / (left associativity). For A / B / C the second / must pop the first; pushing instead gives A B C / /, which is A / (B / C) and wrong. The answer is A B / C /.
  • ^ is right-associative. An incoming ^ does not pop a waiting ^. 2 ^ 3 ^ 2 is 2 3 2 ^ ^ (= 2⁹ = 512), not 2 3 ^ 2 ^ (= 64).
  • Brackets in the output. Never. If a ( or ) appears in your postfix string, step 3 was done wrong.
  • Prefix by "just reverse the postfix". Wrong: reversing A B + gives + B A, which swaps operands and breaks −, / and ^. Use the reverse-convert-reverse method or the bracket method.
  • Favourite question: "Convert (A + B) * (C − D) ^ E to postfix with a stack trace", worth 8 marks for the table alone. Answer: A B + C D − E ^ *.

Understand Why does postfix notation need no brackets? 3 marks

In postfix every operator comes immediately after its two operands, so the grouping is fixed by position; the string is the postorder of the expression tree and the tree can be rebuilt uniquely from it. Brackets in infix exist only to override precedence, which postfix never consults.

A − B − C: left-associative, so the second − pops the first: A B − C −. A ^ B ^ C: right-associative, so the second ^ does not pop the first: A B C ^ ^.

Analyze A student converts A + B * C to prefix by reversing the postfix A B C * +. What do they get, and is it the same expression? 4 marks

They get + * C B A, which is C * B + A. Numerically equal here only because + and * commute; for A − B * C the same trick gives − * C B A = C * B − A, a different expression. The correct prefix is + A * B C.

Analyze What is the maximum number of items on the operator stack while converting ((((A + B)))) and why is this a worst case? 3 marks

Five: four ( plus the +. Nested brackets each add a wall that cannot be popped until its ) arrives, so the stack depth equals the nesting depth plus one; this is why the array stack for conversion must be sized for the deepest nesting, not the expression length.

Beyond the syllabus

Not for the exam. Dijkstra published the shunting-yard algorithm in 1961 for the first ALGOL compiler, and it is still how calculators and simple interpreters parse. Modern compilers generalise it into operator-precedence (Pratt) parsing, which handles unary minus, function calls and user-defined operators. Postfix is the native language of stack machines: the Java Virtual Machine's bytecode, WebAssembly, PostScript printers and the Forth language all execute postfix directly. Search "Pratt parser", "reverse Polish HP calculator" and "WebAssembly stack machine".

3.4 Evaluating postfix expressions and parenthesis matching

Once an expression is in postfix, a single left-to-right scan with one stack computes its value: operands are pushed, and every operator pops two values, computes, and pushes the result. The same "push what is open, pop when it closes" idea checks whether brackets in a program are balanced. Both are short algorithms with long traces, and the trace is what the examiner marks. Manipal lists this as "Evaluation of Expression", Christ as "Expression Evaluation", SRM as "Postfix evaluation, Parenthesis matching".

You need: 3.1 (push, pop) and 3.3 (what postfix is).

Postfix evaluation

The stack holds values, not operators. Because every operator in postfix follows its two operands, by the time you meet the operator its operands are the two most recent values on the stack.

  1. Scan the postfix string left to right, one token at a time.
  2. Operand: push its value.
  3. Operator: pop the top into b (right operand), pop again into a (left operand), compute a op b, push the result.
  4. At the end the stack holds exactly one value: the answer. More than one value means an operator is missing; a pop on an empty stack means an operand is missing.

The order in step 3 is the only place to go wrong. For 8 2 − the stack is [8, 2]; the first pop gives b = 2, the second gives a = 8, and the result is a − b = 6, not 2 − 8. Each token is handled once, so evaluation is O(n). Here it is in C for single-digit operands:

int evalPostfix(const char *s) {
    int st[100], top = -1;
    for (int i = 0; s[i]; i++) {
        char c = s[i];
        if (c >= '0' && c <= '9') { st[++top] = c - '0'; continue; }
        int b = st[top--], a = st[top--];        /* right first, then left */
        switch (c) {
            case '+': st[++top] = a + b; break;
            case '-': st[++top] = a - b; break;
            case '*': st[++top] = a * b; break;
            case '/': st[++top] = a / b; break;
        }
    }
    return st[top];
}
/* evalPostfix("532*+84/-") prints 9 */

A prefix expression is evaluated the same way but scanning right to left; then the first pop is the left operand a and the second is b. Figure 3.4.1 traces the small expression used in the code.

Parenthesis matching

A string of brackets is balanced when every opening bracket has a matching closing bracket of the same type, in the right nesting order. Compilers do this check before anything else. The rule: an opening bracket is a promise, and the most recent promise must be kept first, which is LIFO.

  1. Scan the string left to right. Ignore every character that is not a bracket.
  2. Opening bracket ( [ {: push it.
  3. Closing bracket ) ] }: if the stack is empty, report unbalanced: extra closing. Otherwise pop; if the popped bracket is not the matching opener, report unbalanced: mismatch.
  4. At the end, if the stack is empty the string is balanced; if not, report unbalanced: unclosed openers, and the ones left on the stack are exactly the unclosed ones.

The check is O(n) time and, in the worst case of n opening brackets, O(n) extra space. A counter is enough for one bracket type; a stack is needed as soon as there are two types, because a counter cannot tell ( [ ) ] from ( [ ] ).

Exam traps

  • Operand order. First pop is the right operand. 8 2 − is 6; 8 2 / is 4; 2 3 ^ is 8. Swapping them is the most common lost mark in this chapter.

3.5 Queue ADT: enqueue, dequeue and implementations

A queue is a list where items enter at one end, the rear, and leave from the other, the front. The first item in is the first out: FIFO. It is the structure of fairness: a ticket counter, a printer spool, UPI payment requests waiting at a bank server, processes waiting for the CPU, and the breadth-first traversal of a graph all use one. The array version has a famous flaw, the drift to the right, which this chapter shows and the next chapter fixes.

You need: 3.1 for the ADT idea; Unit 2 (Singly linked lists) for the linked version.

The ADT

  • enqueue(Q, x) (also "insert" at NITK, "add"): put x at the rear.
  • dequeue(Q) ("delete", "remove"): remove and return the item at the front.
  • front(Q) or peek: return the front item without removing it.
  • isEmpty(Q), isFull(Q): as for the stack.

Dequeue on an empty queue is underflow; enqueue on a full one is overflow. All operations are O(1). The difference from a stack is only which end gives: a stack removes from the same end it inserts at, a queue from the opposite end.

Array implementation and the drift problem

Keep an array q[MAX] and two indices. A common textbook convention is front = 0, rear = −1 for empty; enqueue stores at q[++rear] and dequeue returns q[front++]. The queue occupies cells front..rear, and its size is rear − front + 1.

#define MAX 5
int q[MAX], front = 0, rear = -1;

int isEmpty(void) { return rear < front; }
int isFull(void)  { return rear == MAX - 1; }

void enqueue(int x) {
    if (isFull()) { printf("Overflow\n"); return; }
    q[++rear] = x;
}
int dequeue(void) {
    if (isEmpty()) { printf("Underflow\n"); return -1; }
    return q[front++];
}

This is C. It works, but watch the indices: every dequeue moves front to the right and nothing ever moves left. After a few dequeues the cells before front are empty yet unusable, and isFull reports "full" the moment rear reaches MAX − 1, even if most of the array is empty (Figure 3.5.1). Two repairs exist. Shift all items left on each dequeue, which makes dequeue O(n). Or let rear wrap around to index 0 when it reaches the end: the circular queue of chapter 3.6, which keeps O(1).

Linked list implementation

Keep two pointers, front to the first node and rear to the last. Enqueue appends after rear (O(1) because rear is known); dequeue removes the first node (O(1) as for the linked stack). NITT and Manipal list this as "linked queues". There is no capacity and no drift, so none of the array trouble arises.

struct node { int data; struct node *next; };
struct node *front = NULL, *rear = NULL;

void enqueue(int x) {
    struct node *p = malloc(sizeof *p);
    p->data = x; p->next = NULL;
    if (rear == NULL) front = rear = p;   /* first node: both ends */
    else { rear->next = p; rear = p; }
}
int dequeue(void) {
    if (front == NULL) { printf("Underflow\n"); return -1; }
    struct node *p = front; int x = p->data;
    front = front->next;
    if (front == NULL) rear = NULL;      /* queue became empty */
    free(p);
    return x;
}

The two NULL checks are where marks are lost: the first enqueue must set both pointers, and the dequeue that empties the queue must reset rear, or the next enqueue writes through a dangling pointer.

Exam traps

  • Which end? Enqueue at the rear, dequeue at the front. Writing "insert at front" turns the queue into a stack and the whole trace goes wrong.
  • Empty test. With front = 0, rear = −1 to start, empty is rear < front, not front == rear (that means one item). Some books reset front = 0, rear = −1 whenever the queue empties; say which convention you follow.
  • Overflow with free cells is the point of the examiner's question "what is the drawback of a linear queue?" Answer: the drift; cells before front are never reused; fix with a circular queue.
  • Linked dequeue that empties the queue must set rear = NULL. Forgetting it is the classic 2-mark deduction in "write C code for a linked queue".
  • Priority queue is not a queue. Manipal lists it next to queues, but it serves the highest priority first, not the oldest; it is built with a heap in Unit 4, Binary heaps and priority queues.

3.6 Circular queues and double-ended queues (deques)

A circular queue is the array queue of 3.5 with one change: when an index reaches the last cell it wraps to cell 0, so freed cells are reused and no space drifts away. A deque (double-ended queue, say "deck") allows insertion and deletion at both ends, so it can act as a stack, a queue, or both at once. Anna Univ lists "double ended queues", Christ "Circular Queue" and "Double Ended Queue (deQueue)", Manipal adds "Input/Output Restricted Queues". The whole chapter is about getting the index arithmetic right.

You need: 3.5 (the linear array queue and its drift problem); Unit 2 (Doubly linked lists) for the linked deque.

Circular queue: wrap with modulo

Think of the MAX cells as a ring. Moving an index forward is i = (i + 1) % MAX: after cell MAX − 1 comes cell 0. The items occupy the cells from front to rear going round the ring, so the live region may cross the end of the array, as in Figure 3.6.1 where it runs 4, 5, 0, 1.

One question needs care: with both indices free to wrap, how do you tell full from empty? If front and rear simply chase each other, the two states look the same. The convention most Indian textbooks use is front = rear = −1 when empty, with rear pointing at the last item and front at the first:

  • Empty: front = −1.
  • Full: (rear + 1) % MAX = front. All MAX cells are used.
  • Enqueue: if empty, set front = rear = 0; otherwise rear = (rear + 1) % MAX. Store at q[rear].
  • Dequeue: take q[front]; if front = rear it was the only item, so set front = rear = −1; otherwise front = (front + 1) % MAX.
  • Size: when not empty, (rear − front + MAX) % MAX + 1.
#define MAX 5
int q[MAX], front = -1, rear = -1;

int isEmpty(void) { return front == -1; }
int isFull(void)  { return (rear + 1) % MAX == front; }

void enqueue(int x) {
    if (isFull()) { printf("Overflow\n"); return; }
    if (isEmpty()) front = rear = 0;
    else rear = (rear + 1) % MAX;
    q[rear] = x;
}
int dequeue(void) {
    if (isEmpty()) { printf("Underflow\n"); return -1; }
    int x = q[front];
    if (front == rear) front = rear = -1;   /* last item taken */
    else front = (front + 1) % MAX;
    return x;
}

This is C. Two other conventions appear in books and are equally correct if used consistently: keep a count variable (empty when count = 0, full when count = MAX), or keep one cell always empty with rear pointing at the next free cell (full when (rear + 1) % MAX = front, which then holds only MAX − 1 items). Name your convention at the top of an exam answer.

Deque: both ends open

A deque supports four operations: insertFront, insertRear, deleteFront, deleteRear, plus the usual peeks and isEmpty/isFull. insertRear with deleteFront is a queue; insertRear with deleteRear is a stack. Two implementations are standard:

  • Circular array. The same ring as above; insertFront moves front backwards with front = (front − 1 + MAX) % MAX (the + MAX stops the result going negative in C) and deleteRear moves rear backwards the same way. All four are O(1).
  • Doubly linked list. Head and tail pointers with prev and next links; each end can be inserted or deleted in O(1) without a traversal. A singly linked list cannot do deleteRear in O(1), which is why the doubly linked version is used.

Two restricted forms appear in Manipal's list. An input-restricted deque allows insertion at one end only (the rear) but deletion at both ends. An output-restricted deque allows deletion at one end only (the front) but insertion at both.

Exam traps

  • Full and empty both have front = rear? Only in the naive design. With the −1 convention, empty is front = −1 and full is (rear + 1) % MAX = front. Write both tests explicitly.
  • Forgetting the wrap on dequeue. front also moves with modulo; students wrap rear and then let front run off the end.
  • Negative modulo in C. (front − 1) % MAX is negative when front = 0. Write (front − 1 + MAX) % MAX.

Takeaways

  1. A stack gives back the most recent item (LIFO); a queue gives back the oldest (FIFO). Both are lists with restricted access and O(1) operations.
  2. Check for underflow before every pop or dequeue and for overflow before every push or enqueue; the examiner reads the checks before the code.
  3. Array stack: top = −1 when empty, pre-increment on push, post-decrement on pop. Linked stack: the head is the top, never the tail.
  4. Infix to postfix: operands go out, operators wait on the stack until a lower-precedence operator, a closing bracket or the end pushes them out. Equal precedence pops for left-associative operators and not for ^.
  5. Prefix: reverse the infix with brackets swapped, convert with "equal precedence does not pop", reverse the result; or move each operator to the front of its fully bracketed group.
  6. Postfix evaluation: the first pop is the right operand. 8 2 − is 6.
  7. Brackets are balanced only if every closer matches the popped opener and the stack is empty at the end.
  8. A linear array queue drifts right and reports full with free cells; a circular queue wraps with (i + 1) % MAX and reuses them.
  9. Circular queue with the −1 convention: empty when front = −1, full when (rear + 1) % MAX = front, reset both to −1 when the last item leaves.
  10. A deque opens both ends; a doubly linked list or a circular array gives all four operations in O(1).

Machines prefer prefix/postfix because operator position fixes the grouping: no precedence table, no associativity rule, no brackets; a single scan with a stack evaluates them in O(n). Relate the three forms to preorder, inorder and postorder of the expression tree (Unit 4).

Explain the drift problem of a linear array queue and show how a circular queue solves it. Discuss how full and empty are distinguished. (10 marks)

Linear queue: front advances on dequeue and never returns; cells before front are unusable; isFull triggers when rear = MAX − 1 even with free cells (give a 5-cell example). Circular queue: indices advance with (i + 1) % MAX so freed cells are reused; all operations stay O(1) without shifting. Full/empty: with pure modulo the two states coincide; resolve with the −1 convention (empty: front = −1; full: (rear + 1) % MAX = front), or a count, or one cell left free. Code for enqueue and dequeue earns the last marks.

Compare the array and linked list implementations of a stack and of a queue, with their advantages and disadvantages. (10 marks)

Points: capacity (fixed vs dynamic), memory per element (pointer overhead), wasted space (unused array cells vs none), speed (index arithmetic and cache locality vs malloc/free), overflow behaviour, and the two special cases of the linked queue (first enqueue sets both pointers, last dequeue resets rear). Conclude with when to choose each: known bound → array; unknown or widely varying size → linked. A table with six rows is the expected format.

Apply

Convert the infix expression (A + B) * C − (D − E) * (F + G) to postfix and to prefix, showing the stack contents at every step. (12 marks)

Postfix trace ends with A B + C * D E − F G + * −. Prefix: reverse with brackets swapped: ( G + F ) * ( E − D ) − C * ( B + A ); convert with "equal precedence does not pop": G F + E D − * C B A + * −; reverse: − * + A B C * − D E + F G. Marks: stack table for postfix (6), correct prefix with method (6). Check both against the fully bracketed form ((A + B) * C) − ((D − E) * (F + G)).

Evaluate the postfix expression 5 6 2 + * 12 4 / − using a stack. Show the stack after every token. Then write a C function that evaluates a postfix string of single-digit operands. (12 marks)

5 → [5]; 6 → [5, 6]; 2 → [5, 6, 2]; + → [5, 8]; * → [40]; 12 → [40, 12]; 4 → [40, 12, 4]; / → [40, 3]; − → [37]. Answer 37. Code: array stack, loop over characters, push digits, on operator pop b then a and push a op b, return the remaining value (as in 3.4). Marks for the trace (5), operand order (2), code with the correct pop order and error checks (5).

Write an algorithm to check whether the brackets in an expression are balanced. Trace it on { ( [ ] ) ( } ) and on [ ( ) { } ]. (10 marks)

Algorithm from 3.4: push openers; on a closer, report failure if the stack is empty or the popped opener does not match; at the end report failure if the stack is not empty. First string: { ( [ ] ) ( → stack { (; } pops ( → mismatch → unbalanced. Second string: every closer matches and the stack ends empty → balanced. Marks for the algorithm (4), each trace with stack contents (3 + 3).

A circular queue has MAX = 6 and front = rear = −1. Perform: enqueue 11, 22, 33, 44; dequeue; dequeue; enqueue 55, 66, 77; dequeue; enqueue 88. Show front, rear and the array after each step and give the final size. (10 marks)

After four enqueues: f = 0, r = 3, [11 22 33 44 _ _]. Two dequeues return 11, 22: f = 2. Enqueue 55, 66: r = 5. Enqueue 77: r = (5 + 1) % 6 = 0, q[0] = 77. Dequeue returns 33: f = 3. Enqueue 88: r = 1, q[1] = 88. Final: f = 3, r = 1, order 44, 55, 66, 77, 88, size = (1 − 3 + 6) % 6 + 1 = 5. Marks per row of the trace and for the wrap and size formula.

Write C functions for push, pop and peek of a linked stack, and for enqueue and dequeue of a linked queue. Explain each pointer assignment. (12 marks)

Stack: node with data and next; push allocates, sets p->next = top, then top = p; pop saves top, moves top to top->next, frees, returns data; peek returns top->data after an empty check. Queue: front and rear pointers; enqueue allocates with next = NULL, if rear is NULL sets front = rear = p, else rear->next = p and rear = p; dequeue saves front, moves front, sets rear = NULL if front became NULL, frees. Marks for each function (2 each) and for the two NULL special cases (2).

Analyze and evaluate

Show how a queue can be implemented using two stacks. Give the enqueue and dequeue algorithms and analyse their cost. Then show how a stack can be built from two queues. (12 marks)

Queue from stacks S1 (in) and S2 (out): enqueue pushes on S1, O(1). Dequeue: if S2 is empty, pop everything from S1 and push onto S2, then pop S2. Each element moves at most once from S1 to S2, so dequeue is O(1) amortised, O(n) worst case. Stack from queues Q1, Q2: push enqueues on Q1 (O(1)); pop dequeues all but the last element of Q1 into Q2, returns the last, and swaps the names, O(n). Spans 3.1, 3.2 and 3.5; marks for correct algorithms, a worked trace of three operations each, and the amortised argument.

Trace the run-time stack for the recursive C function fact(4). What is the maximum stack depth, and what happens for fact(100000)? Relate this to the array stack of chapter 3.2. (10 marks)

Calls push activation records fact(4), fact(3), fact(2), fact(1), fact(0); base case returns 1; records pop in reverse, multiplying: 1, 1, 2, 6, 24. Maximum depth is 5 records (n + 1). fact(100000) pushes 100001 records and typically exceeds the fixed run-time stack size, giving a stack overflow / segmentation fault: the run-time stack is an array stack with a fixed MAX, exactly the overflow of 3.2. Mention the iterative or tail-recursive alternative.

A student implements the circular queue with front pointing to the first item and rear to the next free cell, and tests full with front == rear. Find the bug, give a failing sequence, and propose two fixes with their trade-offs. (10 marks)

Bug: empty also has front == rear, so the queue reports full when empty (or vice versa). Failing sequence with MAX = 3: three enqueues make rear wrap to front; the state is indistinguishable from the initial empty state, so either the third enqueue is refused or a dequeue on empty succeeds. Fixes: keep one cell free (full when (rear + 1) % MAX == front; loses one cell), or maintain a count (uses all cells, one extra variable, one more update per operation), or the −1 convention of 3.6. Evaluate memory versus simplicity.

Why does A ^ B ^ C convert to A B C ^ ^ while A − B − C converts to A B − C −? Show what goes wrong numerically if the rule is applied the other way for 2 ^ 3 ^ 2 and 10 − 5 − 2. (8 marks)

Associativity: ^ groups right to left, so the second ^ does not pop the first; − groups left to right, so it does. Wrong grouping: 2 3 ^ 2 ^ = 8² = 64 instead of 2⁹ = 512; 10 5 2 − − = 10 − 3 = 7 instead of (10 − 5) − 2 = 3. Marks for the rule, the two traces and the numerical check.

Glossary

Abstract data type (ADT)
A specification of operations and their behaviour, independent of storage.
Activation record
The data pushed on the run-time stack for one function call: return address, parameters, locals.
Associativity
Grouping order for operators of equal precedence: left to right for + − * /, right to left for ^.
Balanced brackets
Every opener has a matching closer of the same type, properly nested.
Circular queue
Array queue whose indices wrap with (i + 1) % MAX so freed cells are reused.
Deque
Double-ended queue: insertion and deletion allowed at both ends.
Dequeue
Remove and return the item at the front of a queue.
Drift
The rightward movement of a linear array queue that strands free cells before front.
Enqueue
Insert an item at the rear of a queue.
FIFO
First in, first out: the order of a queue.
Front
The deletion end of a queue; also the operation that returns that item without removing it.
Infix
Operator between its operands, as in A + B; needs precedence rules and brackets.
Input-restricted deque
Deque with insertion at one end only, deletion at both.
LIFO
Last in, first out: the order of a stack.
Linked stack / queue
Implementation using list nodes; the head is the stack top, front and rear pointers mark the queue ends.
Output-restricted deque
Deque with deletion at one end only, insertion at both.
Overflow
Insertion attempted on a full structure.
Peek (top)
Return the top item of a stack without removing it.
Polish notation
Another name for prefix notation; reverse Polish notation is postfix.
Pop
Remove and return the top item of a stack.
Postfix
Operator after its operands, as in A B +; evaluated left to right with a stack.
Precedence
Priority of operators: ^ above * and /, above + and −.
Prefix
Operator before its operands, as in + A B; evaluated right to left with a stack.
Push
Insert an item on the top of a stack.
Rear
The insertion end of a queue.
Ring buffer
Industry name for a circular queue of fixed size.
Shunting-yard algorithm
Dijkstra's stack method for converting infix to postfix.
Top
The single access end of a stack; in an array stack, the index of the last item.
Underflow
Deletion attempted on an empty structure.
