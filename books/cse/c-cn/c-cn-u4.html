4.1 IPv4 addressing: classful and classless

IPv4 addresses give each host a unique number on a network. Early designs split the 32‑bit address into fixed class ranges. Each class defined a default network‑host split and a default mask. The scheme made routing tables simple but wasted address space. Classless Inter‑Domain Routing (CIDR) replaced the fixed classes. CIDR lets any number of network bits, expressed as a prefix length, to match the actual size of a network. This chapter shows the class ranges, their masks, and how CIDR works.

You need: basic binary notation from previous chapter.

Classful IPv4 addressing

An IPv4 address is a 32‑bit binary number written as four decimal octets. The first bits decide the class. Class A starts with 0, class B with 10, class C with 110, class D with 1110, and class E with 1111. Classes A‑C are used for hosts. Class D is for multicast. Class E is reserved for future use.

Class A range: 1.0.0.0 to 126.255.255.255. Network‑host split: 8 network bits, 24 host bits. Default mask: 255.0.0.0 (binary 11111111.00000000.00000000.00000000).

Class B range: 128.0.0.0 to 191.255.255.255. Split: 16 network bits, 16 host bits. Default mask: 255.255.0.0.

Class C range: 192.0.0.0 to 223.255.255.255. Split: 24 network bits, 8 host bits. Default mask: 255.255.255.0.

Class D range: 224.0.0.0 to 239.255.255.255. Used for multicast groups. No host part.

Class E range: 240.0.0.0 to 255.255.255.255. Reserved for experimental purposes.

Why classful addressing became insufficient

The fixed split caused two problems. First, many networks needed more hosts than a class C could give but fewer than a class B, leading to wasted addresses. Second, the Internet grew faster than the address pool. A class A network holds 16 million hosts, far more than any organization needed. The result was early exhaustion of IPv4 space.

Routing tables also grew large. Every class A network required a separate entry, even if the organization owned only a few sub‑networks. The inefficiency motivated a new scheme that could allocate exactly the needed number of host bits.

The new scheme is Classless Inter‑Domain Routing, abbreviated CIDR. CIDR removes the fixed class boundaries and allows any prefix length from /0 to /32.

CIDR and classless addressing

A CIDR address writes the prefix length after a slash. Example: 150.25.60.0/24 means the first 24 bits are the network part, the remaining 8 bits are for hosts. The mask can be derived by setting the first 24 bits to 1 and the rest to 0, giving 255.255.255.0.

To support a required number of hosts, calculate the smallest power of two that is greater than the host count. The number of host bits = ceil(log₂(required hosts + 2)). The +2 accounts for network and broadcast addresses.

CIDR enables aggregation. Several contiguous networks can be represented by a single shorter prefix. This reduces the size of routing tables and improves lookup speed.

Some syllabi call this IP addressing or IPv4 addressing. The concepts are used in every ISP, data‑center, and campus network in India, from a small UPI payment gateway to a large railway reservation system.

4.2 Subnetting, subnet masks and CIDR

Subnetting splits a large IP network into smaller logical pieces called subnets. It saves address space, limits broadcast traffic, and lets organisations group hosts by department, location or function. Subnetting is used in campus networks, data‑centre VLANs and when an ISP allocates address blocks to customers. The technique relies on subnet masks, prefix lengths and the classless CIDR notation that replaces the old class‑based system.

You need: basic IPv4 address concepts from IPv4 addressing: classful and classless.

Subnet masks and prefix length

An IPv4 address is 32 bits long. A subnet mask marks which bits belong to the network part and which belong to the host part. The mask is written in dotted decimal, for example 255.255.255.0, or as a prefix length after a slash, for example /24. The prefix length is the count of leading 1 bits in the mask. All hosts in the same subnet share the same network bits and differ only in the host bits.

Number of hosts = 2^h – 2

h is the number of host bits; the subtraction removes the all‑zeros (network) and all‑ones (broadcast) addresses.

  1. Write the required number of hosts.
  2. Find the smallest h such that 2^h – 2 ≥ required hosts.
  3. Set the prefix length = 32 – h.
  4. Convert the prefix length to dotted‑decimal mask if needed.
  • A /30 mask (255.255.255.252) gives 2 usable hosts – typical for point‑to‑point links.
  • A /16 mask (255.255.0.0) gives 65 534 hosts – useful for a whole campus.

Calculating subnets and host counts

When an organisation receives a large address block, it often needs several smaller subnets. The process is to decide how many hosts each subnet must support, compute the host bits for each, and then allocate consecutive address ranges. The first subnet always starts at the base address of the original block. Subsequent subnets begin at the next address after the previous subnet’s broadcast address.

Subnet size = 2^h

h is the host‑bit count for that subnet; the size includes network and broadcast addresses.

  1. Choose the required host count for the largest subnet.
  2. Calculate h for that subnet using the host formula.
  3. Set the prefix = 32 – h and write the mask.
  4. Record the first subnet address (base address).
  5. Add the subnet size to obtain the next subnet’s base address.

Variable Length Subnet Masking (VLSM) and CIDR

VLSM lets each subnet use a different mask that matches its exact size. This avoids wasting address space that occurs with a single mask for all subnets. CIDR (Classless Inter‑Domain Routing) extends VLSM to the Internet. An address block is written as network/<prefix>. For example, 192.168.0.0/22 represents the range 192.168.0.0 – 192.168.3.255 with 1022 usable hosts.

  1. Sort subnet requirements from largest to smallest.
  2. Allocate the largest subnet first using the smallest possible prefix.
  3. Move to the next requirement and repeat, always using the next free address.
  • VLSM reduces the number of required public IPv4 blocks for ISPs.
  • CIDR aggregation (supernetting) helps routers store fewer routing entries.

4.3 IPv4 datagram format, MTU and fragmentation

The IPv4 datagram is the basic unit that carries data across the Internet. Its header contains fields that identify the source, destination, length and how the packet should be treated. When a link cannot carry the whole datagram because its Maximum Transmission Unit (MTU) is smaller, the datagram is split into fragments. Each fragment is sent separately and later reassembled at the destination. Understanding the format, MTU limits and fragmentation rules is essential for designing reliable network applications and for troubleshooting packet loss.

You need: IPv4 addressing and Subnetting.

IPv4 header fields

An IPv4 datagram begins with a 20‑byte header. The first byte holds the Version (always 4) and the Internet Header Length (IHL) which tells how many 32‑bit words the header occupies. The Total Length field gives the size of the whole datagram in bytes, including header and data. Identification is a 16‑bit number that stays the same for all fragments of the same original packet.

The Flags field has three bits; the most important are DF (Don’t Fragment) and MF (More Fragments). The Fragment Offset field stores the start of the fragment in units of 8 bytes. TTL (Time‑to‑Live) limits how many hops the datagram may travel. Protocol indicates the next‑layer protocol (e.g., 6 for TCP, 17 for UDP). Header Checksum protects the header from corruption. Finally, the Source and Destination fields contain 32‑bit IPv4 addresses.

  • Version/IHL – 4 bits each
  • Total Length – 16 bits, bytes
  • Identification – 16 bits, same for all fragments
  • Flags – DF, MF, Reserved
  • Fragment Offset – 13 bits, 8‑byte units
  • TTL – 8 bits, hop count
  • Protocol – 8 bits, next‑layer ID
  • Header Checksum – 16 bits
  • Source / Destination – 32 bits each

MTU and fragmentation rules

Every physical link defines a Maximum Transmission Unit (MTU). The MTU is the largest packet size, header included, that can be transmitted without breaking the frame. If an IPv4 datagram’s Total Length exceeds the MTU of the outgoing link, the router must fragment the datagram unless the DF flag is set.

  1. Subtract the IPv4 header size (usually 20 bytes) from the MTU to obtain the maximum data payload per fragment.
  2. Divide the payload into chunks that are multiples of 8 bytes, because the Fragment Offset is measured in 8‑byte units.
  3. Create a new header for each fragment. Copy all fields from the original header, but set the Identification to the original value, set the MF flag to 1 for all fragments except the last, and compute the correct Fragment Offset.
  4. Re‑calculate the Header Checksum for each fragment.

Offset = (bytes already sent) ÷ 8

bytes already sent – sum of payload bytes in previous fragments; Offset is stored in the 13‑bit Fragment Offset field

  • All fragments must arrive at the destination for reassembly; missing fragments cause the whole packet to be discarded.
  • Fragments may follow different paths and arrive out of order.
  • The original header’s options (if any) are copied only into the first fragment.
  • All fragments except the last must have a payload length that is a multiple of 8 bytes; the final fragment may be shorter.

Reassembly at the destination

The receiving host collects fragments that share the same Identification, Source and Destination addresses. It uses the Fragment Offset to place each payload segment at the correct position in a buffer. The MF flag tells whether more fragments are expected. When a fragment with MF = 0 arrives and all earlier offsets are present, the host assembles the complete datagram and passes it to the next layer.

  1. Create a reassembly buffer sized to the total length indicated by the fragment that has MF = 0 (the last fragment), or compute the required size as (Fragment Offset × 8) + payload length of that fragment.
  2. Insert each fragment’s payload at (Fragment Offset × 8) bytes from the start of the buffer.
  3. Mark the range as received. When the MF = 0 fragment arrives, note the final length.
  4. If all byte ranges are marked, deliver the reassembled packet upward.

If any fragment is missing after a timeout (typically 60 seconds), the host discards the incomplete packet and may send an ICMP Time Exceeded – Fragment Reassembly Time Exceeded (Type 11, Code 1) message to the source.

Question. An IP packet of 3000 bytes (including the 20‑byte header) must travel over a link whose MTU is 1500 bytes. The source address is 192.168.1.10 and the destination address is 203.0.113.5.   • Using a byte offset directly in the Fragment Offset field instead of dividing by 8; the field stores 8‑byte units.

4.4 IPv6 addressing, header and transition from IPv4

IPv6 replaces the 32‑bit IPv4 address with a 128‑bit address. The larger space removes address shortage and allows automatic aggregation. A simplified header reduces processing load on routers. IPv6 is used on modern backbones, mobile networks and new campus links.

You need: basic IPv4 addressing from IPv4 addressing and the IPv4 header format from IPv4 datagram format.

IPv6 address notation

An IPv6 address is 128 bits long. It is written as eight groups of four hexadecimal digits separated by colons. Example: 2001:0db8:85a3:0000:0000:8a2e:0370:7334.

Leading zeros in a group may be omitted. A group of all zeros may be replaced by a double colon ::, but only once in an address.

  1. Split the address at each colon.
  2. Remove leading zeros in each group.
  3. Replace the longest run of consecutive zero groups by ::.

Addr = Prefix || InterfaceID

Addr is the full 128‑bit address; Prefix is the high‑order bits that identify the network; InterfaceID is the low‑order bits that identify the host.

  • Each group represents 16 bits.
  • A /64 prefix means the first 64 bits are the network part.
  • The remaining 64 bits form the Interface ID.

Address types and hierarchical prefix

IPv6 defines three main unicast address types: global, link‑local, and unique‑local. Their scopes are global, link‑local, and local to a site (unique‑local) respectively. Global addresses are routable on the Internet. Link‑local addresses start with fe80:: and are used on a single link.

Multicast addresses begin with ff00:: and replace broadcast. Anycast addresses are assigned to multiple interfaces; the nearest one receives the packet.

  • Global unicast: 2000::/3.
  • Unique‑local: fc00::/7.
  • Link‑local: fe80::/10.

The hierarchical prefix allows ISPs to allocate large blocks to customers, which they can further subdivide without renumbering.

IPv6 header fields

The IPv6 header is fixed at 40 bytes. It contains only the fields needed for basic forwarding.

  • Version (4 bits) = 6.
  • Traffic Class (8 bits) for QoS.
  • Flow Label (20 bits) for special handling.
  • Payload Length (16 bits) = size of the payload in octets, i.e., the number of bytes after the IPv6 header, including any extension headers and the upper‑layer data.
  • Next Header (8 bits) identifies the upper‑layer protocol.
  • Hop Limit (8 bits) decrements at each hop; packet is discarded at zero.
  • Source Address (128 bits).
  • Destination Address (128 bits).

There is no header checksum. Errors are detected by the upper‑layer protocol (TCP/UDP).

Transition from IPv4 to IPv6

Transition mechanisms let IPv4‑only hosts communicate with IPv6‑only hosts during the migration period.

  • Dual‑stack: a device runs both IPv4 and IPv6 stacks.
  • Tunneling: IPv6 packets are encapsulated inside IPv4 packets (e.g., 6to4, Teredo).
  • NAT64/DNS64: IPv6‑only clients use a translator that maps IPv6 to IPv4 addresses.

ISPs often deploy NAT64 to let mobile phones using only IPv6 reach legacy IPv4 services such as an IRCTC booking site.

4.5 Support protocols: ARP, ICMP, DHCP and NAT

Support protocols let a host use IP. ARP finds the MAC for a local IPv4 address. ICMP reports errors and tests reachability. DHCP gives a host its IP configuration. NAT lets many private hosts share one public address. Together they make everyday Internet work.

You need: IPv4 addressing, Subnetting, and IPv4 datagram basics.

ARP and ICMP basics

ARP stands for Address Resolution Protocol. It works in IPv4 networks over Ethernet and other broadcast link layers such as Wi‑Fi. It is not limited to Ethernet.

A host that wants to send an IP packet must know the destination MAC address on the same LAN.

  1. Host creates an ARP request. The request broadcast address is ff:ff:ff:ff:ff:ff.
  2. The request contains the sender IP, sender MAC, target IP, and a zero target MAC.
  3. All hosts on the LAN receive the request.
  4. The host whose IP matches the target IP replies with an ARP reply that includes its MAC.

The ARP reply is a unicast Ethernet frame addressed to the requester’s MAC.

ICMP stands for Internet Control Message Protocol. It lives inside the IP payload.

The most common ICMP message is the echo request and echo reply used by the ping utility.

  1. Host A sends an IP packet with protocol = 1 (ICMP) and type = 8 (echo request).
  2. If Host A and Host B are on different networks, the router forwards the packet; otherwise the packet is delivered directly on the LAN.
  3. Host B receives the request, changes type to 0 (echo reply), and swaps source and destination IPs.
  4. Host B sends the reply back to Host A.

ICMP also carries error messages such as Destination Unreachable and Time Exceeded.

When a router cannot forward a packet, it creates an ICMP Destination Unreachable message and sends it to the source.

IPv6 does not use ARP. It uses Neighbor Discovery, which is carried in ICMPv6 messages.

DHCP four‑message exchange

DHCP stands for Dynamic Host Configuration Protocol. It automates IP address allocation.

A DHCP client uses UDP ports 68 (client) and 67 (server).

  1. Client broadcasts DHCPDISCOVER. The message contains a transaction ID and a MAC address.
  2. DHCP server replies with DHCPOFFER. The offer includes an IP address, subnet mask, router, DNS, lease time, and the same transaction ID.
  3. Client sends DHCPREQUEST to accept the offer. It repeats the transaction ID and the offered IP.
  4. Server sends DHCPACK confirming the lease and repeats the configuration parameters.

If the client does not receive a DHCPOFFER, it retransmits DHCPDISCOVER after a timeout.

The lease time tells the client how long it may use the address before renewing.

DHCP can also provide options such as NTP server or custom vendor data.

In a home Wi‑Fi router, the DHCP server typically hands out addresses in the 192.168.0.0/24 range.

NAT source‑port translation and practical notes

NAT stands for Network Address Translation. It lets many private hosts share a single public IP.

The most common form is source‑port NAT (also called PAT).

  1. A private host (192.168.0.50) creates a TCP segment with source port 54321 and destination port 80.
  2. Router rewrites the source IP to its public address (203.0.113.20) and may also change the source port to a unique value, e.g., 40000.
  3. Router stores a table entry mapping (public IP, public port) → (private IP, private port).
  4. When a reply arrives, the router looks up the table, restores the original private IP and port, and forwards the packet.

Only the source port is changed in typical home NAT. The destination port stays as the server expects.

NAT breaks end‑to‑end connectivity for protocols that embed IP addresses in the payload, such as SIP or FTP.

In IPv6, NAT is rarely needed because the address space is large enough for every device to have a globally routable address.

4.6 Routing basics: static vs dynamic, hierarchical routing

Routing decides where each packet goes next. It uses a table that maps destination prefixes to next‑hop addresses. Two ways exist: static routes entered by an administrator and dynamic routes learned from protocols. Large networks also group routers into regions. Hierarchical routing keeps tables small and limits update traffic. This chapter compares static and dynamic routing and explains why hierarchy matters.

You need: Subnetting and basic IP addressing.

Static routing

Static routing uses manually configured entries. An administrator writes each destination, next‑hop IP, and outgoing interface. The entry never changes unless the admin edits it. Static routes are simple and have no protocol overhead. They are useful for stub networks, default gateways, or security policies.

  • Entry format: dest/prefix → next‑hop via interface.
  • Static routes have an administrative distance (usually 1) that determines their preference. A metric field is optional and typically not used for static routes.
  • No periodic messages are sent.

A static default route covers all unmatched traffic. It is written as 0.0.0.0/0 → X. The router forwards any packet without a more specific entry to X.

Dynamic routing

Dynamic routing protocols exchange reachability information. Each router advertises the prefixes it knows and a cost metric. Neighbors update their tables based on received advertisements.

  1. Some protocols (e.g., OSPF) send hello messages to discover neighbors, while others (e.g., RIP) use request/response exchanges.
  2. Router receives advertisements with prefix and cost.
  3. Router computes a best‑path using the protocol's algorithm.
  4. Router installs the best entry in its routing table.

Common interior protocols are OSPF and RIP; BGP is the main exterior gateway protocol used between autonomous systems. OSPF is link‑state; it floods the network with link information and runs Dijkstra's shortest‑path algorithm. Cost is inversely proportional to bandwidth; OSPF defines cost = reference bandwidth ÷ link bandwidth (result rounded to an integer).

cost = reference bandwidth ÷ link bandwidth

reference bandwidth is 100 Mbps by default; link bandwidth is the actual link speed.

Hierarchical routing

Hierarchical routing groups routers into areas or autonomous systems. Core routers store routes to other areas (network prefixes), not to every host inside those areas. This reduces table size and limits update traffic.

  • Internet is the top level.
  • ISPs form the next level.
  • Campuses are below ISPs.
  • Departments are leaf networks.

Some syllabi call this flat versus hierarchical routing. Flat routing stores every prefix at every router. Hierarchical routing stores aggregates such as 10.0.0.0/8 for a whole campus.

4.7 Distance vector routing and RIP

Distance‑vector routing lets each router share the cost of reaching every destination with its directly connected neighbours. The idea is to let routers build a table of shortest‑hop paths by repeatedly applying the Bellman‑Ford rule. It is used in small to medium networks where a simple metric and low configuration overhead are preferred, for example in campus LANs or small ISP edge routers running RIP.

You need: basic routing concepts from Routing basics and IPv4 addressing from IPv4 addressing.

Bellman‑Ford updates in a distance‑vector protocol

Each router keeps a vector D where D(y) is the current estimate of the cost to reach destination y. Cost is measured in hop count for RIP. The vector is sent to every neighbour every 30 seconds.

D_x(y) = min_{v∈N(x)} { c(x,v) + D_v(y) }

D_x(y) is the cost from router x to destination y; N(x) is the set of neighbours of x; c(x,v) is the cost of the direct link x‑v (1 hop in RIP).

  1. Router x receives D_v from neighbour v.
  2. For each destination y, compute candidate = c(x,v) + D_v(y).
  3. If candidate < D_x(y), replace D_x(y) with candidate and record v as next hop.

The process repeats until no router can improve any entry. This is exactly the Bellman‑Ford algorithm applied to a distributed graph.

RIP specifics and the count‑to‑infinity problem

RIP (Routing Information Protocol) is the classic distance‑vector protocol defined in RFC 1058. It limits the metric to a maximum of 15 hops. A metric of 16 is defined as ∞, meaning the destination is unreachable.

  • Update interval: 30 seconds.
  • Hold‑down timer: 180 seconds to suppress flapping routes.
  • Triggered updates: sent immediately when a route changes.

When a link fails, neighbours may still advertise the old cost for one period. Each router adds 1 hop to the advertised cost, so the bad route’s metric climbs slowly: 2, 3, 4 … until it reaches 16. This is the count‑to‑infinity problem.

Because RIP caps the metric at 15, the worst‑case convergence time is 15 × 30 s = 450 seconds, which is acceptable for small networks but too slow for larger ones.

Mitigations: split horizon and route poisoning

Split horizon prevents a router from advertising a route back out the interface on which it learned that route. This stops the immediate formation of a two‑node loop.

Route poisoning is a stronger rule. When a router detects that a destination has become unreachable, it advertises the metric 16 for that destination on all interfaces, even on the interface that originally supplied the route.

  1. Detect link failure (e.g., loss of hello messages).
  2. Set D_x(y) = 16 for the affected destination y.
  3. Send the poisoned vector to all neighbours immediately.

Together, split horizon and poisoning reduce the count‑to‑infinity convergence time from many minutes to a few seconds in typical campus scenarios.

4.8 Link state routing and OSPF

Link‑state routing floods a complete view of the network and then each router runs Dijkstra’s Shortest Path First (SPF) algorithm. The idea is to avoid the slow convergence of distance‑vector protocols and to compute optimal routes from a single source. OSPF (Open Shortest Path First) is the most widely used link‑state protocol in enterprise and ISP networks.

You need: Routing basics and Distance vector routing.

Link‑state advertisements (LSAs) and flooding

Each OSPF router creates a Link‑State Advertisement (LSA). An LSA lists the router's interfaces, the cost of each attached link, and the neighbor router IDs.

The cost is a numeric value that is inversely proportional to the bandwidth of the link. By default cost = 10⁸ ÷ bandwidth (bits per second).

When a router generates a new LSA, it sends the LSA to all OSPF‑enabled interfaces.

All neighbors forward the LSA to their neighbors. This process is called flooding.

Flooding continues until every router in the same OSPF area has a copy of the LSA.

  • Sequence number in the LSA prevents old copies from overwriting newer ones.
  • Acknowledgement packet confirms receipt of each LSA.

The collection of LSAs forms a complete topology map of the area.

Only routers inside the same area exchange LSAs. This limits the size of the database.

Cost calculation and Shortest Path First (SPF)

After flooding, each router runs Dijkstra’s SPF algorithm on its local link‑state database.

  1. Set the source router’s distance to 0 and all other distances to ∞.
  2. Initially the visited set is empty; the source will be selected first because its distance is 0, then marked visited.
  3. Select the unvisited node with the smallest tentative distance.
  4. Update the distance of each neighbor: new = distance(u) + cost(u,v) where u is the node just selected as visited.
  5. If new < current neighbor distance, replace it and record the predecessor.
  6. Mark the selected node as visited.
  7. Repeat until all nodes are visited.

The predecessor table yields a shortest‑path tree rooted at the source router.

From the tree, the router extracts the next‑hop for every destination network.

d(v) = min_{u∈Visited} [ d(u) + cost(u,v) ]

d(v) is the tentative distance to node v; cost(u,v) is the link cost between u and v.

OSPF uses the tree to install routes in the routing table. The route entry contains destination prefix, next‑hop IP address, and total cost.

OSPF areas and summarization

An OSPF network is divided into areas. Area 0 is the backbone. All other areas must connect to the backbone.

Area boundaries limit LSA flooding. Routers that have interfaces in more than one area are called Area Border Routers (ABR).

ABRs generate summary LSAs. A summary LSA advertises the total cost to reach networks in other OSPF areas without revealing the internal topology.

The design reduces memory and CPU load on routers deep inside an area.

  • Backbone area carries inter‑area traffic.
  • Virtual links can connect a non‑backbone area to the backbone when a physical link is missing.

In Indian campuses, OSPF areas often separate academic blocks, hostels, and data‑center zones to keep the LSA database small.

4.9 Path vector routing and BGP

Path‑vector routing lets each autonomous system (AS) announce the complete list of AS numbers a route has traversed. The list, called AS_PATH, stops routing loops because a router discards any update that already contains its own AS number. This mechanism is the core of the Border Gateway Protocol (BGP) which runs the global Internet, connecting ISPs, data‑centers, and even a campus network that uses IP to pay for traffic.

You need: routing basics and distance‑vector concepts.

Path‑vector idea and AS numbers

An autonomous system is a group of IP networks under one administrative control. Each AS is assigned a unique 16‑bit number called an AS number (ASN). Originally AS numbers were 16‑bit (0‑65535). Since 2007, 32‑bit AS numbers (0‑4294967295) are also allocated and used in BGP. For example, the Indian ISP may have ASN 64512. When an AS originates a prefix, it attaches its own ASN to the AS_PATH attribute.

  • AS_PATH = [64512] when the prefix is first announced.
  • If a neighbour AS 65001 receives the update, it prepends its ASN, forming AS_PATH = [65001,64512].
  • A third AS 65100 will see AS_PATH = [65100,65001,64512] after it adds its own number.

Loop avoidance works because an AS discards any UPDATE that already contains its own ASN. This is simpler than distance‑vector protocols that need split‑horizon or poison‑reverse tricks.

Loop condition: ASN_self ∈ AS_PATH

ASN_self is the receiver's autonomous system number; AS_PATH is the list of AS numbers in the BGP UPDATE.

BGP UPDATE message and key attributes

A BGP UPDATE carries a network prefix, the AS_PATH list, and several optional attributes. The most used attributes are NEXT_HOP, LOCAL_PREF, and MULTI_EXIT_DISC (MED).

  • NEXT_HOP: the IP address of the router that should be used to reach the advertised prefix.
  • LOCAL_PREF: a 32‑bit integer that indicates the degree of preference for an exit point; higher value wins.
  • MED: a hint to external neighbours about the preferred inbound path; lower value wins.
  1. Receive UPDATE from a neighbour.
  2. Check loop condition using AS_PATH.
  3. Store the route with its attributes in the local RIB.
  4. Run the best‑path selection algorithm.

Python program.

def best_path(routes):
    # routes is a list of dicts with keys 'local_pref' and 'as_path_len'
    # higher LOCAL_PREF wins, then shorter AS_PATH length
    routes.sort(key=lambda r: (-r['local_pref'], r['as_path_len']))
    return routes[0]

Policy‑based selection and real‑world use

Operators configure policies that modify attributes before advertising a route. For example, an Indian ISP may set LOCAL_PREF = 200 for routes learned from a partner that offers cheaper bandwidth, and LOCAL_PREF = 100 for all other peers.

  • Prefer customer routes over peer routes (higher LOCAL_PREF).
  • Prefer shorter AS_PATH when LOCAL_PREF values are equal.
  • Use MED to influence inbound traffic from a specific neighbour.

During a Chennai power cut, the ISP may temporarily lower the LOCAL_PREF of routes that go through the affected data centre, causing traffic to shift to a backup site without manual re‑routing.

Worked example

Question. AS64512 originates prefix 203.0.113.0/24 with LOCAL_PREF = 150. It sends an UPDATE to AS65001, which adds its own ASN and sets LOCAL_PREF = 200 for its internal decision before forwarding to AS65100 (the LOCAL_PREF attribute is not sent to the external AS). AS65100 also receives a second UPDATE from a different neighbour AS65200 with LOCAL_PREF = 180 and AS_PATH=[65200,64512] (again, the LOCAL_PREF is used only within AS65200). Which route will AS65100 select as best, and what is the final AS_PATH it stores?

C program.

#include <stdio.h>
int main(){
    int as_path[] = {65100,65001,64512};
    int n = sizeof(as_path)/sizeof(as_path[0]);
    printf("Selected AS_PATH: ");
    for(int i=0;i<n;i++){
        printf("%d", as_path[i]);
        if(i<n-1) printf(",");
    }
    printf("\n");
    return 0;
}
  1. Step 1: Build the AS_PATH for the first update. After AS65001 adds its ASN, AS_PATH = [65001,64512].
  2. Step 2: AS65100 receives this update and prepends its own ASN, giving AS_PATH₁ = [65100,65001,64512] with LOCAL_PREF = 200 used internally.
  3. Step 3: Build the AS_PATH for the second update. AS65200 already prepended its ASN, so AS_PATH₂ = [65200,64512] before AS65100 adds its own, resulting in AS_PATH₂ = [65100,65200,64512] with LOCAL_PREF = 180 used internally.
  4. Step 4: Apply BGP best‑path rules. Higher LOCAL_PREF wins, so the route from AS65001 (LOCAL_PREF = 200) is preferred.
  5. Step 5: Store the selected route. The final AS_PATH stored in AS65100’s RIB is [65100,65001,64512].

Exam traps

  • Assuming the route with the smallest numeric AS number is always chosen; BGP uses LOCAL_PREF first, then AS_PATH length.
  • Confusing MED with LOCAL_PREF – MED is considered only after LOCAL_PREF and AS_PATH length.
  • Forgetting that an AS must prepend its own number before checking the loop condition, leading to acceptance of a looping update.
  • Treating the AS_PATH as a simple sum of numbers; it is a list, and the order matters for loop detection.

It discards the update because its own ASN (65001) is already in the AS_PATH, indicating a loop.

Analyze Explain how changing LOCAL_PREF on a single router can shift traffic across the Internet. 6 marks

Increasing LOCAL_PREF for routes learned from a preferred provider makes those routes win the best‑path selection at that router. The router then advertises the higher LOCAL_PREF to its internal peers, causing them to prefer the same exit point. The effect propagates inward, moving traffic toward the chosen provider without changing any physical links.

MED (Multi‑Exit Disc) and BGP community.

It tells the receiving router the IP address of the next router to reach the advertised prefix.

Takeaways

  1. IPv4 addressing can be classful or classless; CIDR enables efficient use of address space.
  2. Subnet masks and prefix lengths define how a network is divided into sub‑networks.
  3. The IPv4 datagram may be fragmented when its size exceeds the MTU of a link.
  4. IPv6 expands address space to 128 bits and simplifies the header for faster processing.
  5. Support protocols such as ARP, ICMP, DHCP, and NAT are essential for end‑to‑end IP communication.
  6. Routing can be static or dynamic; hierarchical designs improve scalability.
  7. Distance‑vector protocols share cost vectors, while link‑state protocols share full topology maps.
  8. BGP, a path‑vector protocol, carries AS‑path information to prevent routing loops across the Internet.

Sequence of AS numbers a BGP route has traversed

A collection of IP networks under a single administrative domain

A BGP router that reduces the number of required peerings in an AS

Address with all host bits set to 1, used to reach all hosts in a subnet

A contiguous range of IP addresses defined by a network address and prefix length

Router IP address that forwards packets destined for external networks

Time period for which an IP address is assigned to a client

Shortest‑path algorithm used by link‑state protocols

Bit in IPv4 header indicating whether more fragments follow
