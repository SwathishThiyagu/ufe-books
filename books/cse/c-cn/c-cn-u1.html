1.1 Data communication: components and data flow modes

Data communication is the exchange of data between two devices through a transmission medium. It sounds simple, and it is, once you can name its parts. Every chat message, UPI payment and IRCTC booking follows the same five-part pattern: a message, a sender, a receiver, a medium and a protocol. Naming the parts tells you where a failure sits and which layer is expected to fix it. This chapter defines those five components, lists how data is represented, then sorts traffic by direction of flow and by type of connection.

The five components

Data communication is the exchange of data between two devices through a transmission medium. The two devices must be part of one system: a file copied to a pen drive and carried across the room is not data communication.

Message is the data itself, for example the text of a UPI payment note. Sender is the device that sends it, your phone. Receiver is the device that gets it, the bank's server. Medium is the physical path, the Wi-Fi link and the optical fibre behind it. Protocol is the agreed set of rules, HTTPS running over TCP/IP. Remove any one and nothing arrives: with no medium the message has nowhere to travel, and with no protocol it is a signal the receiver cannot interpret. Protocols get a full treatment in 1.4.

The sender is a computer. Inside the sender and receiver the chain splits further: a transmitter (a modem or network card) puts the bits on the medium as a signal and a receiver turns the signal back into bits. The destination is the computer that uses the bits. The figure shows that chain, with the message and the protocol sitting above it. Which box does which job is decided by the device's layer, covered in 1.8.

Forms of data representation

Data is anything two programs agree to call data. Five forms cover almost every exam question.

  • Text: characters coded as numbers, in ASCII or Unicode. The word Hi is two code points.
  • Numbers: stored in binary, not as characters. Integers use binary place values, fractions use floating point.
  • Images: a grid of pixels, each pixel a colour code such as an RGB triple.
  • Audio: a continuous pressure wave, sampled at fixed intervals so each sample becomes a number.
  • Video: a sequence of images plus the time order in which to show them.

One medium can carry all five forms, because each is first converted into a signal. The shape of that signal, and how it weakens over distance, belongs to Unit 2.

Direction of data flow

Some syllabi call these transmission modes. There are three.

Simplex is one direction only, always. A keyboard sends to a computer, a TV tower sends to your set-top box, and a server streams a bank statement that your app only displays: the statement data itself moves one way, and the app never sends anything back on that stream. No reverse channel exists, so the receiver cannot report an error back. Simplex works only when the protocol is fixed in advance, because the receiver has no way to ask for a repeat.

Half-duplex is both directions, one at a time. A walkie-talkie is the standard example: you press to talk and say over to hand the channel back. The link must turn around between the two directions, and that turnaround costs both time and capacity.

U = T_data ÷ (T_data + T_turn)

U is the utilisation of a half-duplex link as a fraction; T_data is the time spent carrying useful data, in seconds; T_turn is the lost time while the line reverses direction, in seconds. Multiply U by 100 for a percentage.

Full-duplex is both directions at once. A telephone call, a video call and most fibre links are full-duplex. It needs either two separate paths or a way to keep the two directions apart on one path.

Connections and network criteria

A connection is point-to-point or multipoint. Point-to-point joins exactly two devices: a TV remote and the TV, or a leased line between two offices. Multipoint, also called multi-drop, is one link shared by three or more devices: the coaxial cable of an old Ethernet, or one Wi-Fi channel with twenty laptops on it. Multipoint saves cable and ports, but each device then needs rules for taking its turn; those rules are the multiple access protocols of Unit 3. Span and ownership of the whole network are a separate question, in 1.2, and the pattern of links is the topology of 1.3.

Three criteria judge any network. Performance is how fast and how steadily data moves, measured by transit time and response time. Reliability is how rarely the network fails, how quickly it recovers, and how much damage one failure does. Security is protection of data from unauthorised access, change or destruction.

Worked example

Question. An IRCTC user books a ticket from a phone and the app shows a PNR. (a) Name the five components for this transfer. (b) Give the flow mode for each case: (i) the bank pushes a statement to your app and you can only read it; (ii) a teller terminal sends one request and waits for the reply before sending the next; (iii) two engineers talk on a video call. (c) On the teller link a request takes 200 ms to send and the reply takes 100 ms, and every direction change costs 20 ms of turnaround. Find the total time for one request-reply exchange on a half-duplex line and on a full-duplex line, and the percentage lost to turnaround.

  1. (a) Message = the booking request and the PNR screen. Sender = the phone. Receiver = the IRCTC server. Medium = the mobile data or Wi-Fi link plus the provider's network. Protocol = HTTPS over TCP/IP.
  2. (b)(i) Statement push: simplex, one direction only, no reverse channel.
  3. (b)(ii) Request then reply: half-duplex, both directions but one at a time, with the line turning around between them.
  4. (b)(iii) Video call: full-duplex, both directions at the same time.
  5. (c) Half-duplex needs two turnarounds. Time = 200 ms request + 20 ms turn + 100 ms reply + 20 ms turn = 340 ms.
  6. (c) Full-duplex sends both directions at once, so the turnarounds disappear. Time = 200 ms + 100 ms = 300 ms.
  7. (c) Loss = 340 ms − 300 ms = 40 ms. Percentage lost = 100 × 40 ÷ 340 = 11.8 %. Useful fraction U = 300 ÷ 340 = 0.882.

Answer. Half-duplex takes 340 ms and full-duplex takes 300 ms for the same exchange, so half-duplex loses 40 ms, about 11.8 % of its time, to turnaround.

Exam traps

  • Mixing up sender with transmitter and receiver with destination. The computer is the sender or receiver; the modem or network card is the transmitter or receiver.
  • Calling an ordinary telephone call half-duplex. A call is full-duplex; the walkie-talkie is the half-duplex example.
  • Treating simplex as a link with no receiver or no protocol. Simplex still has a protocol and a receiver; only the reverse channel is missing.
  • Confusing direction of flow (simplex, half-duplex, full-duplex) with type of connection (point-to-point, multipoint). They are two different classifications of the same link.
  • Listing four components and dropping the medium or the protocol. Examiners count exactly five.

Beyond the syllabus

Not for the exam. Research radios now try in-band full duplex: sending and receiving on the same frequency at the same time, which classical designs avoided because a transmitter drowns its own receiver. The trick is self-interference cancellation, subtracting a copy of your own signal before it reaches your receiver. Mobile networks in time division duplex (TDD) bands use one frequency and take turns, sending downlink and uplink in different time slots, so the link works like a half-duplex line. 1.2 Network types and categories: LAN, MAN, WAN

Networks are sorted by reach and by who pays for the links. A PAN spans a few metres and one person owns it. A LAN spans a room to a campus and one organisation owns every cable and switch. A MAN spans a city and a provider usually runs it. A WAN crosses states or countries on links leased from carriers. Joining two or more networks gives an internetwork; the Internet is the largest. Every design choice depends on which you are building.

You need Chapter 1.1 for the five parts every network is built from — message, sender, receiver, medium and protocol.

Four sizes, from pocket to planet

Classification is about span first, then ownership. A network inside one owner's budget and legal boundary is a LAN; one crossing public roads, other buildings or national borders is a WAN, whatever its length on a map.

  • PAN — personal area network. A few metres. Phone to Bluetooth earbuds, laptop to wireless mouse. One person owns both ends; no provider; a few Mbps.
  • LAN — local area network. Room, office floor or campus. One organisation owns cable, switches and Wi-Fi access points. Speed: 100 Mbps to 10 Gbps on copper or fibre. A VLAN is a logical LAN inside one switch; see Unit 3, Ethernet and VLANs.
  • MAN — metropolitan area network. One city. A provider sells metro Ethernet to offices across Chennai, or a cable operator runs fibre down every street. Span roughly 5 km to 50 km; one provider owns the street-level links.
  • WAN — wide area network. Between cities, states or countries. A firm rents a 34 Mbps link from an ISP or telecom carrier; the carrier owns the long-distance fibre. Lower speed per rupee than a LAN; the path crosses many provider switches.
  • Internetwork. Two or more networks joined by routers. Your home LAN plus your ISP's network plus a web server's LAN is already an internetwork. The Internet is the biggest: millions of networks under different owners, all speaking IP.

Span is a rough guide, not a law. Wi-Fi inside one building is a LAN. A 40 km fibre linking two plants of one company is a private WAN-style link though 40 km sounds like a MAN. Ownership and operation settle it.

LAN against WAN, side by side

Every LAN-versus-WAN difference comes from one root: a LAN has one owner, a WAN has several. One owner means one set of standards, short runs and easy upgrades. Several owners mean contracts, tariffs and fixed interfaces.

Access, core, and the leased-line versus VPN choice

A provider network has two parts. The access network is the link from your building to the provider's first router — home fibre, office Ethernet handoff, a 4G modem. The core is the high-capacity router and fibre mesh between cities. A MAN or WAN is mostly a core plus thousands of access links. The core is shared, so it runs at tens or hundreds of Gbps.

A company with two distant offices has two standard choices.

  • Private WAN link (leased line). The carrier gives a fixed-rate circuit, say 34 Mbps, reserved for your traffic. Delay is steady and errors rare because the circuit is yours. You pay fixed monthly rent whether you use it or not.
  • VPN over the Internet. You buy ordinary Internet connections at both ends and run an encrypted tunnel between routers. Capacity is whatever the Internet gives at that moment; delay varies; an attacker sees ciphertext but not your data. Far cheaper and set up in hours.

Use a leased line for guaranteed rate and steady delay — voice, machine control, bank clearing. Use a VPN when cost matters more than jitter — file sync, email, remote staff. Many firms run both.

Exam traps

  • Judging by distance alone. A 40 km link inside one company is private WAN-style; Wi-Fi in one building is a LAN.
  • Mixing MB and Mbit. 68 MB is 544 Mbit, eight times bigger. Dividing by 8 wrongly puts you off by 64.
  • Calling a VPN a private line. A VPN rides the public Internet, so rate and delay are shared; encryption hides content, not congestion.
  • Assuming a MAN always belongs to an ISP. A company can lease dark fibre across a city, so classify by span and operation together.
  • Confusing an internetwork with the Internet. Any two joined networks are an internetwork; the Internet is only the largest.

1.3 Network topologies

A topology is the pattern in which links join nodes. A node is any device that sends or receives: a computer, switch, router or printer. A link is the cable or wireless channel between two nodes. The physical topology is where the cables run; the logical topology is the path a frame takes. Each pattern trades cable and port cost against fault tolerance and easy growth. A lab may use a star, a campus a star-bus, a bank a partial mesh. The pattern decides how a frame travels, how many ports each device needs, and what happens when one cable or one device fails.

You need Chapter 1.2, to know which topology suits a LAN, a MAN and a WAN.

Mesh: every pair joined

A full mesh joins every node to every other node. For the mesh formulas, n is the total number of nodes. A frame from A to B travels one link, directly. With n nodes, each node has a link to the other n − 1 nodes. Counting each cable at both ends gives n(n − 1) ends; divide by 2 because one cable serves both ends.

links = n(n − 1) / 2

n is the total number of nodes; links is the number of cables in a full mesh.

ports per node = n − 1

n is the total number of nodes; each node needs one port for every other node.

Full mesh is the most fault tolerant. If one link fails, only that direct path is lost; traffic can often go another way. If one node fails, the rest still reach each other. Adding a node to a mesh of n nodes needs n new cables, one new port on each old node, and n ports on the new node; total ports grow as n², so growth is expensive. A partial mesh keeps some direct links and leaves the rest to indirect paths. WAN cores and data-centre spines often use partial mesh. Cost is high: links and ports grow about n².

Star, bus and ring

A star has one central device, usually a switch, with one link to each node. A frame from PC1 to PC3 goes PC1 → switch → PC3, two link hops. With n end nodes (the switch is not counted in n), a star needs n cables and n ports on the central device; each node needs one port. Cost grows linearly. If one cable fails, only that node drops. If the central device fails, the whole star drops: a single point of failure. Adding a node needs one cable and one free central port. The switch itself is in Chapter 1.8.

A bus uses one backbone cable with taps. A frame travels both directions along the backbone; every node hears it. For bus formulas, n means end nodes only; the backbone is not counted. A bus needs one backbone cable and one tap per node; a node needs one port. It is cheap for few nodes. A break in the backbone usually stops all transmission on the bus, because the cut end reflects signals; splitting it into working parts needs repeaters, bridges or separate segments. Adding a node means cutting or tapping the cable, often disrupting service. Access rules for a shared bus are in Unit 3.

A ring joins nodes in a closed loop. Each node has two ports, one to each neighbour; a frame travels around the ring until it reaches the destination. For ring formulas, n means end nodes only. A simple ring needs n links and 2 ports per node. One cable cut breaks the loop; a dual ring can survive one cut. Adding a node means opening the ring and inserting two links. Access methods are in Unit 3.

A tree is a hierarchy of stars: leaves join a switch, switches join a backbone. A frame climbs to a common parent and down. The root or backbone link is a shared risk. Real campuses use a hybrid: a star-bus or star-ring, meaning stars joined by a bus or ring backbone.

1.4 Protocols, standards and layered architecture

A protocol is an agreed set of rules that two systems follow to exchange data. It fixes the format of messages, what each message means, and when to send it. Without agreed rules, a sender's bits are just noise to a receiver. Layering splits the whole job into smaller layers. Each layer gives a service to the layer above. The transport, network and data-link layers add headers so that peers at the same layer can talk. This is how web pages, UPI payments and video calls cross many different networks.

You need: Chapter 1.3, because layering assumes links and nodes already exist.

Protocol: syntax, semantics and timing

A protocol is an agreed set of rules followed by two peer processes to exchange data. It has three elements.

Syntax is the format: which fields appear, in what order, and how bits encode them. In GET /index.html HTTP/1.1, syntax fixes the method, a space, the path, a space, the version and the line ending.

Semantics is the meaning of each field and the action to take. GET asks the server to return a file; status 200 means the request succeeded.

Timing is when to send and how fast. A TCP connection opens with SYN, then SYN-ACK, then ACK. Send the ACK too late and the connection setup fails or is retried.

Two devices can be connected by a cable and still not communicate. The cable carries bits; only a shared protocol turns those bits into a request, a reply and a correct action. A protocol also defines what to do on error, such as resending a lost message or closing the connection.

Layering, services and peer processes

Layering splits one large communication problem into ordered layers. Layer N offers a service to layer N+1 through an interface: the set of operations the upper layer may call. The upper layer does not need to know how the service is built. Each layer also has a peer process at the same layer on the other host. Peers communicate logically using that layer's protocol. Physically, data moves down the sender's stack, across the medium, and up the receiver's stack.

On the way down, the transport, network and data-link layers add their own header (the data-link layer also adds a trailer) to the data from above. This is encapsulation. The header carries control information for the peer at that layer: TCP header port numbers, IP header addresses, Ethernet header MAC addresses. On the way up, the receiver reads and removes each header, then passes the payload to the layer above.

The data unit at each layer has a name, its PDU (protocol data unit). The application data is a message. Transport adds its header to make a segment in TCP; UDP calls its PDU a datagram. Network adds an IP header to make a packet. Data link adds a MAC header and trailer to make a frame. Physical sends the frame as bits: signals on the medium. It adds no header.

Standards: de facto and de jure

A standard is a documented agreement that lets products from different makers work together. A de facto standard wins by widespread use before any formal approval. The TCP/IP protocol suite is the main example (see Chapter 1.6). A de jure standard is approved by a recognised standards body. The OSI reference model is a de jure standard from ISO; its layers are in Chapter 1.5.

Four bodies appear often. ISO (International Organization for Standardization) produced the OSI model. ITU-T (ITU Telecommunication Standardization Sector) publishes telecom standards. IEEE (Institute of Electrical and Electronics Engineers) publishes LAN and MAN standards, such as Ethernet (IEEE 802.3) and wireless LAN (IEEE 802.11). The IETF (Internet Engineering Task Force) develops Internet protocols and publishes them as RFCs (Request for Comments). An RFC has a number and, once published, is not edited; a newer RFC updates it.

De jure does not always mean successful. The OSI protocols were formal, but the Internet adopted the de facto TCP/IP suite.

Benefits and costs of layering

Layering has clear benefits. Modularity: a layer can be redesigned without rewriting the others. Replace Ethernet with Wi-Fi and IP above it still works. Vendor independence: a switch from one company and a router from another can interoperate because both follow the same layer protocols. Easier teaching and testing: each layer can be studied and tested alone.

Layering also has costs. Header overhead: every layer adds bytes that carry no user data. Small messages suffer most, as the worked example shows. Duplicated function: error checking appears in the data link layer and again in the transport layer; addressing appears at data link, network and transport. Lost detail: a layer cannot easily use a lower layer's internal information. TCP treats the network as a black box, so it cannot ask a Wi-Fi link to retry a lost frame sooner. Cross-layer tricks can help one application but break the modular contract.

The net rule: layer when the separation saves more than the headers cost.

Worked example

Question. A 1,460-byte application message is sent over Ethernet. TCP adds a 20-byte header, IP adds a 20-byte header, and Ethernet adds a 14-byte header plus a 4-byte frame check trailer.   2. (a) Frame size = application data 1,460 + overhead 58 = 1,518 bytes.
  3. (a) Efficiency = 1,460 ÷ 1,518 = 0.96179... = 96.2%.
  4. (b) Frame size = application data 10 + overhead 58 = 68 bytes.
  5. (b) Efficiency = 10 ÷ 68 = 0.14705... = 14.7%.

Exam traps

  • Peers are at the same layer. Layer N on one host talks to layer N on the other host, never to layer N+1 there. Data moves down and up only inside each host.
  • A service is what a layer offers upward; a protocol is how peers at that layer talk. Do not call the interface a protocol.
  • A segment is transport, a packet is network, a frame is data link. Mixing these names loses marks even when the idea is right.
  • The trailer is not a header. Ethernet adds 14 bytes of header and a 4-byte frame check trailer; count both in overhead.
  • De facto and de jure are not quality labels. A de facto standard (TCP/IP) can beat a de jure one (OSI).

1.5 OSI reference model

The OSI reference model splits every job a network must do into seven layers, from bits on a cable at the bottom to the user's application at the top. The International Organization for Standardization (ISO) built it in the 1980s so that designers, vendors and examiners could talk about one layer at a time. It is a model, not software: it names jobs and the interfaces between them but defines no headers. Its vocabulary — layer 2 switch, layer 3 routing, layer 4 port — is used every day by network engineers.

You need Chapter 1.4 for protocols, encapsulation and the idea of a PDU (protocol data unit): the chunk of data a layer hands down.

A model, not a protocol suite

A reference model is a template. It says which jobs exist and how they stack, so that any vendor can build compliant hardware and software that talks to another vendor's product. The OSI model defines seven layers. Each layer has exactly one job, serves the layer above it, and is served by the layer below it.

The boundary between two adjacent layers is an interface. It is a contract: the upper layer passes a data unit plus its own control information down, and it never needs to know how the lower layer does its work. Layer N on the sender adds its header and logically talks to layer N on the receiver, using that header. This is encapsulation, and the whole stack is peeled open at the far end.

Each layer names its data unit. From the bottom: bits at the physical layer, a frame at the data link layer, a packet at the network layer, a segment (or datagram, for UDP) at the transport layer, and simply data or a message above that.

Because the model is generic, it fits a phone call, a satellite link or a bank's private network. That generality is also its weakness: it is descriptive, so it can be read as vague. A real product is built from a protocol suite, which is a set of protocols that actually run. OSI, as a suite, lost to TCP/IP; OSI, as a teaching model, won everywhere.

The seven layers, from the wire up

  • 1 Physical. Moves single bits over a medium: voltage, light, radio, pin layout, data rate. PDU: bit. Examples: RS-232, the 1000BASE-T cable spec. Devices: hub, repeater, cable, connector.
  • 2 Data link. Delivers a chunk of data across one link to the next node. Frames the bits, adds MAC addresses, detects errors with a trailer, controls access to a shared medium. PDU: frame. Examples: Ethernet, HDLC, PPP. Devices: switch, bridge.
  • 3 Network. Delivers a packet from the source host to the destination host across many links. Logical addressing and routing are its job. PDU: packet. Examples: IP, ICMP. Device: router.
  • 4 Transport. End-to-end delivery of the whole message between two processes. Adds port numbers, splits data into segments, and may add retransmission and flow control. PDU: segment. Examples: TCP, UDP. Runs inside the host operating system, not on a box in the corridor.
  • 5 Session. Sets up, manages and closes a dialogue between two applications: who speaks when, and checkpoints so a long transfer can resume after a break. PDU: data.
  • 6 Presentation. Fixes the syntax of the data so both sides read the same bytes: character encoding, compression, encryption. PDU: data.
  • 7 Application. The network services a user program calls: web pages, mail, name lookup. PDU: data. Examples: HTTP, SMTP, DNS.

The upper three layers (5, 6, 7) are called the upper layers and live in software near the application. The lower four (1 to 4) are called the lower layers; layers 1 and 2 live in the network card, and layer 3 lives in the operating system and in routers. Your exam will mostly test layers 2, 3 and 4, so learn those cold and know the other four by one sentence each.

Mapping to TCP/IP, and the standard criticism

The Internet does not run OSI. It runs the TCP/IP suite, which has four layers: network access, internet, transport, and application. Map the two like this. OSI physical and data link fold into TCP/IP network access. OSI network maps to the internet layer. OSI transport maps to transport. OSI session, presentation and application all collapse into the single TCP/IP application layer. Unit 2 covers the full suite.

That collapse is the standard criticism of OSI. Session and presentation are thin in real software: a browser or a mail client does checkpoints and encodings itself, using library calls, so no separate layer exists to hand data to. TLS encryption, for example, is usually drawn beside the application rather than as a presentation layer.

Two more criticisms worth one line each. The model was written before the protocols that won, so the fit is loose. And its seven layers were once said to be a political number rather than a technical one. Keep the model anyway: it gives each job exactly one home, and that is why we still argue about which layer a firewall or a load balancer belongs to.

Worked example

Question. An application in host A produces 1200 bytes of user data, and the 1200 bytes already include the application-layer header. The data goes down a full OSI stack. The transport layer adds a 20-byte header, the network layer adds a 20-byte header, and the data link layer adds a 14-byte header and a 4-byte trailer. The session and presentation layers add nothing. Find the size of the segment, the packet and the frame, the total overhead in bytes, and the protocol efficiency as a percentage.

  1. Transport layer: it takes 1200 bytes and appends 20 bytes. Segment size = 1200 + 20 = 1220 bytes.
  2. Network layer: it takes the 1220-byte segment and appends 20 bytes. Packet size = 1220 + 20 = 1240 bytes.
  3. Data link layer: it takes the 1240-byte packet, adds a 14-byte header and a 4-byte trailer. Frame size = 1240 + 14 + 4 = 1258 bytes.
  4. Total overhead = 1258 − 1200 = 58 bytes, or 20 + 20 + 14 + 4 = 58 bytes.
  5. Efficiency = useful bytes ÷ bytes on the wire = 1200 ÷ 1258 = 0.9539, that is 95.39 percent.

Answer. The frame is 1258 bytes on the wire, 58 bytes are overhead, and the protocol efficiency is 95.39 percent.

Exam traps

  • Calling OSI a protocol suite. It is a reference model and defines no headers, ports or field layouts of its own.
  • Putting encryption in the transport layer. Encryption is presentation; TCP's job is end-to-end delivery with ports and retransmission.
  • Putting routing in the data link layer. A switch forwards frames by MAC address within one network; a router forwards packets by IP address between networks.
  • Saying the session layer is where a TCP connection is made. TCP connections belong to transport; session is about the application dialogue.
  • Forgetting the trailer. Data link overhead is header plus trailer, and one mark is lost by counting the header alone.

1.6 TCP/IP protocol suite and Internet architecture

The Internet is not one network but millions of networks joined by one common set of rules: the TCP/IP protocol suite. It sorts every networking job into four layers — application, transport, internet, network access — and hands data down from one to the next. IP sits in the middle as the narrow waist: one packet format that every link below and every service above must fit through. The architecture is an edge of hosts and access links joined to a core of routers run by competing ISPs. Every UPI payment, video call and email rides this stack.

You need: Chapter 1.5 for the seven OSI layers, and Chapter 1.4 for what a layer, a header and a peer are.

Four layers, not seven

TCP/IP is the protocol suite the Internet really runs on. It groups all networking jobs into four layers. Each layer takes data from the layer above, adds its own header, and passes the result down. The figure shows the stack with the main protocols in each layer.

  • Application: HTTP, DNS, SMTP, FTP, DHCP. Serves the user's program directly.
  • Transport: TCP, UDP. Cuts data into segments and delivers each to the right program on the right host.
  • Internet: IP, ICMP, ARP. Moves a packet from any host to any host across many networks.
  • Network access: Ethernet, Wi-Fi, PPP. Wraps the packet in a frame and then in bits on one link.

The bottom layer carries two jobs at once: the data link job and the physical job. Many Indian textbooks split it and teach five layers — application, transport, network, data link, physical. Both lists describe the same stack. If a question says five-layer model, split the bottom block; if it says four, keep it whole.

The application and transport layers run only in the two end hosts. The internet layer runs in the hosts and in every router along the path. The network access layer runs on the hosts and on every device of the link, including switches and access points.

What IP promises

IP's contract is short: connectionless, best-effort, unreliable, with no order guarantee.

  • Connectionless: no setup before sending. The packet is handed to the network and forgotten.
  • Best-effort: the network tries, and promises nothing more. A congested router may drop the packet.
  • Unreliable: a dropped, duplicated or corrupted packet is not reported back to the sender.
  • No order guarantee: packet 2 may arrive before packet 1.

Every packet carries a destination IP address and is forwarded one hop at a time. Each router decides alone, from its own routing table, which link to use next. Two packets of the same file can take different routes and arrive out of order.

Why accept so little? A simple service is cheap to build and works over any link — fibre, Wi-Fi, satellite. IP is the narrow waist: everything above and everything below must fit through one packet format. If you need reliability, TCP adds it above IP; if you do not, UDP skips it. The repair happens at the endpoints, never inside the routers.

Edge, access and core

The Internet's architecture has two parts. The edge is the end systems — phones, laptops, servers — plus the access networks that connect them. The core is the mesh of routers and long links that carries packets between ISPs.

  • Access networks: home fibre or DSL with Wi-Fi, mobile 4G/5G, campus Ethernet, a café hotspot.
  • ISP tiers: a local ISP buys transit from a regional ISP, which buys from a tier-1 backbone.
  • Internet exchange point (IXP): a building where many ISPs swap traffic directly instead of paying transit.
  • Content providers: large ones run their own backbone and place caches close to users.

Route of one packet: your phone → Wi-Fi access point → home router, your default gateway → the ISP's first router → more routers → maybe an IXP → the destination's ISP → the destination host. At each router the incoming link header is stripped, the IP destination is read, the routing table is searched, and a fresh link header is added for the next hop. The IP address stays the same end to end; the link address changes at every hop.

Nothing forces all packets of a flow onto one path, so one packet can overtake another. Addressing and routing are in Unit 4; frames and the link layer are in Unit 3.

1.7 Circuit switching versus packet switching

A switched network moves data from source to destination through intermediate nodes. Circuit switching first reserves a path for the whole call. Packet switching cuts the message into packets that share links and wait in queues. The first suits a long telephone call that needs a steady rate. The second suits a short file or a web page that arrives in bursts. This chapter shows the three phases of a circuit call, the store-and-forward rule of a packet network, and the delay each adds.

You need: <a href='#tcp-ip-protocol-suite-and-internet-architecture'>Chapter 1.6 to know which layer holds packets and which holds the call.

Circuit switching: setup, data, teardown

A circuit-switched network reserves a path before any data moves. The call has three phases. Setup: the source asks the network for a path, and each switch reserves capacity on its outgoing link. Data transfer: bits flow at a fixed rate along the reserved path. Teardown: the switches release the capacity after the call ends. The telephone network works this way.

Inside one link, the provider multiplexes many calls. FDM gives each call a frequency band. TDM gives each call a repeating time slot. Either way, the call sees a constant rate and a fixed delay, because no other call can take its share. That is why voice sounds steady. The cost is waste: when the caller is silent, the reserved slot or band carries nothing, and no other user can borrow it. Billing usually follows time and distance.

T<sub>circuit</sub> = t<sub>setup</sub> + B/R + t<sub>teardown</sub>

Tcircuit is the total time from request to release (s); tsetup is the setup time (s); B is the number of bits in the message (bits); R is the reserved rate (bits/s); tteardown is the teardown time (s). This ignores propagation delay. In the figure, setup is 3 s, data lasts 12 s and teardown is 5 s, so the call occupies 20 s.

Packet switching: store, forward, share

A packet-switched network cuts the message into packets. Each packet carries a header with the source and destination address, a sequence number, and error checks. A router receives the whole packet, stores it, reads the header, and forwards it on the best link. This is store-and-forward: the packet must fully arrive before it leaves. The delay therefore grows with the number of hops.

Links are shared by statistical multiplexing. A user sends only when it has data, and can use the full link rate for a short burst. When many bursts arrive together, packets wait in a queue. Queuing adds variable delay, called jitter. Packets may also take different paths and arrive out of order. The header is overhead: a 1,000-byte packet may carry 40 bytes of header and only 960 bytes of user data.

Two flavours exist. In a datagram network, each packet is routed on its own, as in IP. In a virtual circuit network, setup fixes a path and gives each packet a short label, but no bandwidth is reserved. The path is fixed; the rate is not.

Tpacket = (N + k − 1) × L/R

Tpacket is the time from the first bit sent to the last bit received (s); N is the number of packets; k is the number of links; L is the packet size (bits); R is the link rate (bits/s). This assumes all packets are ready, and ignores headers, queuing and propagation.

Choosing between them

Circuit switching pays a setup cost but gives a steady rate and low jitter. Packet switching pays no setup for a short transfer, shares capacity better, but adds per-packet headers and variable delay. For a long voice call, circuit switching is a good match. For a short file, a web page, or a bursty sensor reading, packet switching wins because the setup would dominate.

2 MB = 16,000,000 bits. One-link data time = 16,000,000 ÷ 2,000,000 = 8 s. Circuit total = 1 + 8 + 1 = 10 s. Packets: 2,000 packets of 8,000 bits. Per link = 8,000 ÷ 2,000,000 = 0.004 s. Packet total = 2,000 × 0.004 + 1 × 0.004 = 8.004 s.

Analyze A video call needs steady delay; a file download is bursty. Which switching suits each, and why? 4 marks

The video call suits circuit switching because the reserved path gives a constant rate and low jitter. The file download suits packet switching because it is bursty, needs no setup, and can use idle capacity; variable delay does not hurt a file.

Understand What does store-and-forward mean at a router? 2 marks

The router receives the whole packet into its buffer, reads the header, and only then sends the packet on the next link.

Apply A packet is 1,500 bytes and the link rate is 10 Mbps. Find the transmission time of the packet on that link. 3 marks

1,500 bytes = 12,000 bits. Time = 12,000 ÷ 10,000,000 = 0.0012 s = 1.2 ms.

Analyze Why can packets arrive out of order in a datagram network, and what field helps the receiver fix the order? 4 marks

Each packet is routed on its own, so different packets may take different paths and face different queuing delays. A sequence number in the header lets the receiver put them back in order.

1.8 Network devices: hubs, switches, bridges and routers

Every network device forwards something, and the thing it forwards fixes its layer. A hub repeats raw bits, so all its ports share one collision domain. A bridge or switch reads frames and forwards them by MAC address: a port connected to a single station is that station's collision domain, while a port connected to a hub shares one collision domain with all devices on that hub. A router reads packets and forwards them by IP address between networks, and it separates broadcast domains. This is why an office uses a switch for its desks and a router to reach the Internet. The devices exist to keep local traffic local and to move only what must cross a boundary.

You need Chapter 1.5 and Chapter 1.6 to attach each device to a layer, and Chapter 1.7 for store-and-forward packets.

Layer 1: repeater and hub

A repeater regenerates a weakened signal and sends the bit pattern onward. It reads no address. A hub is a multiport repeater. When PC 1 sends a frame into a hub, every other port receives the same bits. The hub has no table and makes no forwarding decision.

All hub ports sit in one collision domain. If two PCs transmit together, their signals overlap and the frame is damaged; Ethernet CSMA/CD makes them back off. A hub runs half duplex, so a port cannot send and receive at once. Its bandwidth is shared: four PCs on a 100 Mbit/s hub contend for the same 100 Mbit/s, not 400 Mbit/s.

A network interface card (NIC) is the host's own layer 2 hardware. It builds frames and holds the MAC address; it is not a shared network device. A wireless access point is a layer 2 bridge to the wireless medium: it forwards frames between wireless clients and the wired LAN.

Layer 2: bridge and switch

A bridge joins two LAN segments and forwards frames by MAC address. A switch is a bridge with many ports and hardware forwarding. The unit it handles is the Ethernet frame; see Unit 3 for frame format. Each frame carries a source MAC address and a destination MAC address.

A switch keeps a MAC table: MAC address → port. It performs four actions:

  • Learn: when a frame arrives on port p, record its source MAC with port p. Refresh the entry if it exists.
  • Filter: if the destination MAC is on port p, drop the frame.
  • Forward: if the destination MAC is in the table and its port is not p, send the frame out only that port.
  • Flood: if the destination is unknown, or is the broadcast address, send the frame out every port except p. Never send it back out of p.

MAC table entries age out after a timeout, so a station that moves is relearned. Multicast frames are flooded like broadcast frames.

A switch port connected to a single station is that station's collision domain. A port connected to a hub shares one collision domain with all devices on that hub. By the usual exam convention every switch port counts as one collision domain: a full-duplex link has no collisions but is still counted as its own domain. A switch still has one broadcast domain: a broadcast frame floods every port. VLANs can split that broadcast domain logically; detail is in Unit 3. A bridge does the same job at smaller scale.

Layer 3: router and domain counting

A router joins different networks. It receives a frame, removes the layer 2 header, reads the destination IP address, looks up the route, and sends the packet out of the chosen interface. It then builds a new frame for that hop with a new source and destination MAC address. The IP address normally stays the same from source host to destination host; the MAC header changes at every hop.

A router separates broadcast domains. It does not forward a layer 2 broadcast from one interface to another. A host sends off-LAN traffic to its default gateway, which is the router address on its own LAN. In a home box, the word gateway often means a router plus switch plus access point in one case. In general, a gateway is any device that joins two systems with different protocols.

Collision domain: the set of devices whose transmissions can collide. Broadcast domain: the set that receives a broadcast frame. By the usual exam convention every switch port counts as one collision domain; a full-duplex link has no collisions but is still counted as its own domain. In the figure, the router joins LAN 1 and LAN 2. Under Switch 1, the switch port to the hub, the hub, and PC 1, PC 2, PC 3 form one collision domain. PC 4 has its own full-duplex switch port, so a second collision domain. Switch 2 gives PC 5 and PC 6 one each. Broadcast domains: LAN 1 is one; LAN 2 is one; the router keeps them apart, so two.

Worked example

Question. A four-port switch starts with an empty MAC table. Ports are 1, 2, 3, 4. Frames arrive in this order: (1) A to B on port 1; (2) B to A on port 2; (3) A to C on port 1; (4) C to A on port 3. Fill the MAC table and state where each frame is sent. Give the number of ports flooded or forwarded at each step.

  1. Frame 1: source A on port 1, so learn A→1. Destination B is unknown, so flood to ports 2, 3, 4. Flooded ports = 3. Table: A→1.
  2. Frame 2: source B on port 2, so learn B→2. Destination A is known on port 1, so forward to port 1 only. Forwarded ports = 1. Table: A→1, B→2.
  3. Frame 3: source A on port 1; A is already on 1. Destination C is unknown, so flood to ports 2, 3, 4; never back out of port 1. Flooded ports = 3. Table unchanged.
  4. Frame 4: source C on port 3, so learn C→3. Destination A is known on port 1, so forward to port 1 only. Forwarded ports = 1. Final table: A→1, B→2, C→3.

Answer. Frame 1 floods to 3 ports, frame 2 forwards to 1 port, frame 3 floods to 3 ports, frame 4 forwards to 1 port; final MAC table A on 1, B on 2, C on 3.

Exam traps

  • A switch separates collision domains, not broadcast domains. A broadcast frame still floods every port in the VLAN until a router or VLAN boundary stops it.
  • A hub does not give each port 100 Mbit/s. All ports share one half-duplex collision domain.
  • A router forwards by IP address and writes a new MAC header for each hop; the source and destination IP addresses normally do not change.
  • A bridge and a switch work at layer 2. A switch is a multiport bridge, not a layer 3 router.
  • On a full-duplex switch port there are no collisions, but by the usual exam convention the port still counts as its own collision domain; do not merge it with a shared wire.

Remember At which OSI layer does a hub work, and what does it forward? 2 marks

Learn C on port 3. A is known on port 1, so forward the frame to port 1 only.

Apply Four PCs connect to one 100 Mbit/s hub and all try to send at once. What shared rate and duplex do they get? 3 marks

They share 100 Mbit/s in one collision domain, half duplex; they do not get 100 Mbit/s each.

Analyze Why does replacing a hub by a switch improve throughput even when the link speed stays the same? 5 marks

A switch port connected to a single station is that station's collision domain; a port connected to a hub shares one collision domain with all devices on that hub. So with stations on separate ports, each has its own collision domain and can run full duplex, and different ports send at the same time instead of contending for one shared hub segment. The broadcast domain is still one.

Analyze A broadcast frame arrives at a switch. Which ports receive it, and does a router stop it? 4 marks

The switch floods it out every other port in the same VLAN. A router does not forward a layer 2 broadcast to another interface, so it stops the broadcast at that boundary.

Takeaways

  1. Data communication needs five parts — message, sender, receiver, medium and protocol — and a link can carry data simplex, half-duplex or full-duplex.
  2. Networks are named by span and ownership: LAN is one organisation over a room-to-campus, MAN is a city run by a provider, WAN crosses states on provider links.
  3. A topology is a cost-versus-fault-tolerance bargain; mesh buys reliability with n(n−1)/2 links, star buys cheap growth with a single point of failure at the centre.
  4. A protocol is rules with syntax, semantics and timing, and without shared standards two correct machines still cannot talk.
  5. Layering trades header overhead and some lost detail for modularity, easier teaching and testing, and the freedom to change one layer without touching the others.
  6. OSI is a teaching and design reference; the real Internet runs TCP/IP, and its narrow waist at IP is what let the network grow so far.
  7. Circuit switching reserves a path for the whole call; packet switching shares links store-and-forward, wasting less capacity but giving variable delay and jitter.
  8. Devices map one-to-one onto layers: hub at physical, bridge and switch at data link, router at network — so the address a device reads tells you its layer.

Exam question bank

Long answers in this unit almost always ask you to draw a layered diagram, name the PDU and address used at each layer, and then compare two designs — OSI versus TCP/IP, or circuit versus packet — on named criteria such as delay, overhead, cost and fault tolerance.

Remember and understand

Remember List the five components of data communication and explain each with a small example. 8 marks

Message: the data being exchanged, text, numbers, image, audio or video; Sender and receiver: the devices that originate and consume the message; each needs a protocol stack; Medium: the physical path, twisted pair, coaxial, fibre or radio; Protocol: the rules of syntax, semantics and timing that both ends obey; Say clearly that a missing component means no communication, e.g. two machines with a cable but different protocols cannot exchange data.

Understand Distinguish simplex, half-duplex and full-duplex transmission, giving one real example of each. 8 marks

Simplex: one direction only, always; example keyboard to computer or a TV broadcast; Half-duplex: both directions but one at a time; example walkie-talkie; Full-duplex: both directions at once; example telephone call, or a link carrying data up and down together; Connect the mode to capacity: full-duplex needs separate paths or echo cancellation and gives roughly twice the usable throughput.

Understand Compare LAN, MAN and WAN on span, ownership, speed and cost. 8 marks

LAN: room to campus, single organisation owns the equipment, high speed, low cost per port; MAN: a city, usually a provider's links, moderate speed, higher cost; WAN: across states or countries, on provider leased lines, lowest speed per rupee, highest cost; Mention that the boundary is by ownership and span, not by technology, and that a VPN lets a WAN behave like a private network over the Internet.

Understand Explain the seven layers of the OSI reference model and give one job for each layer. 13 marks

Physical: bits onto the medium, voltages, connectors, data rate; Data link: framing, error detection, MAC addressing, access control; Network: logical addressing and routing of packets across networks; Transport: end-to-end delivery, segmentation, reliability, flow control, ports; Session: setting up and managing dialogue between applications; Presentation: translation, compression, encryption; Application: the user-facing service such as mail or web; Name the PDU per layer and say the model is a reference, not a product.

Understand What are syntax, semantics and timing in a protocol? Why are standards needed? 8 marks

Syntax: format of the fields, their order and sizes; Semantics: meaning of each field and the action to be taken; Timing: when to send, how fast, and the order of exchange; Standards let equipment from different vendors interoperate; bodies such as ISO, ITU-T, IEEE and IETF publish them, with RFCs for Internet protocols; Two systems can be individually correct and still fail if they disagree on any of the three.

Understand Describe a hub, a bridge or switch, and a router, and state the layer and address each uses. 8 marks

Hub: physical layer, repeats bits to all ports, one collision domain, no address look-up; Bridge or switch: data link layer, forwards frames by MAC address using a learn, forward, filter, flood table; Router: network layer, forwards packets by IP address between different networks, and changes the link-layer frame at each hop; Consequence: a switch keeps local traffic local, a router is needed to cross subnets.

Apply

Apply For n nodes, work out the number of links for a full mesh and for a star, and compare with a bus. Which do you choose for a 40-seat lab and why? 10 marks

Full mesh: n(n−1)/2 duplex links, and each node needs n−1 ports; Star: n links and n+1 ports if there is a central device; Bus: one backbone cable with taps, cheapest but one break or one bad tap kills the network; For a 40-seat lab: star, because cable and port count grow linearly and one faulty cable removes only one node; State the trade-off: mesh gives fault tolerance and no shared-access problem at high cost; star gives cheap growth with a central single point of failure.

Apply Trace one HTTP request from a browser to the bits on the wire. Name the PDU and the address used at each layer. 13 marks

Application: an HTTP message, using a host name resolved to an IP address; Transport: TCP segment, with source and destination port numbers; Network: IP packet, with source and destination IP addresses, routed hop by hop; Data link: frame with source and destination MAC addresses, valid only for the current hop; Physical: bits as signal on the medium; At each step the layer adds a header; at the receiver each header is stripped in reverse order; Note that the MAC address changes every hop while the IP address stays the same end to end.

Apply A link of R bits per second carries packets of L bits over a path of N links, ignoring propagation and queueing. Derive the store-and-forward delay for one packet and for P packets. 10 marks

One hop transmission time is L/R seconds; One packet over N links with store-and-forward is N × L/R, since each router must receive the whole packet before sending it; For P packets the last packet finishes at time (N + P − 1) × L/R; Define every symbol and state the units in seconds; Mention the simplifying assumptions: no propagation, no queueing, no processing delay.

Apply A circuit-switched link of 1 Mbps is divided into 100 kbps circuits. How many users fit? What changes if packet switching is used and each user is active only 10 percent of the time? 10 marks

Circuit switching supports 1 Mbps ÷ 100 kbps = 10 simultaneous users; The eleventh user is blocked even if the other ten are idle, so capacity is wasted; With packet switching users share the full 1 Mbps on demand and can exceed 10, at the risk of queueing delay; Quote the usual result: the number of users that can be supported with small probability of congestion is several times 10; Conclude that packet switching suits bursty data, circuit switching suits steady streams.

Apply A frame with destination MAC address not in the switch table arrives at a switch port. Describe step by step what the switch does. 8 marks

Learn: record source MAC address with the incoming port and a timestamp; Look up the destination MAC address in the table; No entry found, so flood: send out all ports except the incoming one; The reply from the destination lets the switch learn that address too; If the entry exists, forward on the matching port; if the entry is on the incoming port itself, filter and drop; Entries age out so that a moved device is relearned.

Analyze and evaluate

Analyze Compare circuit switching and packet switching on setup delay, utilisation, end-to-end delay and jitter. Recommend one for live voice and one for file download, with reasons. 13 marks

Circuit switching: setup and teardown phases, reserved capacity, constant delay, near-zero jitter, but idle capacity is wasted; Packet switching: no setup, statistical sharing, better utilisation, but variable queueing delay and jitter, and possible loss; Datagram versus virtual circuit: the second keeps a per-flow path but still shares links; Voice: small constant rate, delay sensitive, so circuit switching or a packet network with reservation and priority; File download: bursty, delay tolerant, so packet switching is far more efficient.

Analyze Discuss the advantages and drawbacks of layering. Why does layering sometimes duplicate functions and lose detail? 13 marks

Advantages: modularity, one job per layer, easier teaching and testing, independent replacement of a layer, standard interfaces between vendors; Drawbacks: header overhead at every layer, processing cost, and information hiding that hides useful detail — for example error checks repeated at several layers because a lower layer cannot assume the upper ones are present; Lost detail: a layer cannot see parameters it might exploit, such as wireless loss at the transport layer; Duplicated function: error control and flow control appear at more than one layer; Conclude that layering is a design bargain, not a law, and cross-layer designs trade modularity for performance.

Evaluate Compare the OSI reference model with the TCP/IP protocol suite. Why did TCP/IP become the working standard? 13 marks

OSI: seven layers, a clean reference with separate session and presentation layers, produced as a standard before a working implementation; TCP/IP: four layers — application, transport, internet, network access — with session and presentation folded into the application, and a proven implementation first; TCP/IP has a narrow waist at IP, letting new link technologies below and new applications above plug in; Simplicity and free, open RFC specifications encouraged wide adoption; OSI is still valuable vocabulary for teaching and for reasoning about which layer a fault is in.

Evaluate Design the network for a two-building campus of 300 users with a server room. Choose topologies, devices and links, and justify the choices against cost and fault tolerance. 13 marks

Access layer: star topology per floor with switches, so one cable fault affects one seat; Backbone: a fibre link between the two buildings and to the server room, possibly a redundant second path; Distribution: routers or layer-3 switches to separate subnets per department and control broadcast traffic; Devices by layer: hubs are avoided because they extend one collision domain; switches forward by MAC inside a subnet, routers forward by IP between subnets; Fault tolerance versus cost: a full mesh backbone is unnecessary; a redundant ring or dual-homed core is a reasonable compromise; Mention that a provider WAN link or VPN is needed only for outside access, not inside the campus.

Glossary

Access network
The part of a network that connects end hosts to the first provider or campus router.
Bus topology
All nodes tap one shared backbone cable, cheapest to wire but with one shared collision domain and a single cable as a failure point.
Core
The inner part of a network made of high-capacity links and routers that carry aggregated traffic between access networks.
Data communication
The exchange of data between two devices through a message, a sender, a receiver, a medium and a common protocol.
Datagram
A packet that carries its full destination address and is forwarded independently, with no prior path set up.
Frame
The data link layer PDU, carrying MAC addresses and a trailer for error detection.
Header overhead
The extra bytes each layer adds to the data, which reduce the fraction of each transmission that is useful payload.
Host
An end device that runs applications and sends or receives traffic, as opposed to a router that forwards others' traffic.
IETF
The Internet Engineering Task Force, the open body that develops Internet standards and publishes them as RFCs.
Interface
The defined boundary through which one layer passes data and parameters to the layer directly below it.
Internetwork
Two or more networks joined by routers so that hosts on different networks can exchange data.
ISO
The International Organization for Standardization, the body that published the OSI reference model.
Layer
A level in a layered architecture that performs one group of related jobs and offers a defined service to the layer above.
Packet
The network layer PDU, carrying source and destination IP addresses so routers can forward it.
PAN
Personal area network: a very short-range network around one person, such as Bluetooth between a phone and earbuds.
Peer process
The same layer on the other machine, which reads the header that its own layer added at the sender.
Point-to-point
A connection that links exactly two devices, so the whole link capacity belongs to that pair.
Ring topology
Each node connects to two neighbours forming a closed loop, giving a predictable path and possible dual-ring recovery at the cost of break handling.
Router
A network layer device that forwards packets between different networks by looking up the destination IP address.
Segment
The transport layer PDU in TCP, carrying port numbers and sequence information.
Simplex
A transmission mode in which data flows in one direction only, always.
Star topology
Every node has its own link to a central device, so growth is cheap and one cable fault isolates one node, but the centre is a single point of failure.
Switch
A data link layer device that forwards frames by MAC address and gives each port its own collision domain.
Syntax
The part of a protocol that fixes the layout, order and size of fields in a message.
TCP/IP suite
The four-layer protocol stack — application, transport, internet, network access — on which the Internet runs.
Timing
The part of a protocol that states when data may be sent, at what rate, and in what order.
Virtual circuit
A packet-switched flow that follows a path set up in advance and is identified by a short label rather than a full address.
