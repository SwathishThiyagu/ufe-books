1.1 Data communication: components and data flow modes

Data communication moves binary bits from a source that creates the information to a destination that uses it. The movement needs a transmitter to turn bits into a signal, a physical channel that carries the signal, and a receiver that reconverts the signal back to bits. Understanding these five parts and how they can exchange data in one or both directions is the basis for every network protocol and device, from a cheap IoT sensor to a high‑speed telecom backbone.

Basic components of a data‑communication system

A data‑communication system is built from five logical blocks. The **Source** generates the data bits. The **Transmitter** encodes the bits into a waveform suitable for the medium. The **Channel** is the physical path – copper wire, fiber, or air – that carries the waveform. The **Receiver** decodes the waveform back into bits. The **Destination** consumes the bits as useful information. Each block can be implemented by hardware, software, or a combination of both.

  • Source – e.g., a temperature sensor, a web server, or a user’s keyboard.
  • Transmitter – e.g., a UART, a modem, or a network interface card.
  • Channel – e.g., a twisted‑pair cable, an optical fiber, or a wireless link.
  • Receiver – e.g., a demodulator, a PHY chip, or a software driver.
  • Destination – e.g., a data logger, a computer, or a display.

These components appear in every networking standard. In the OSI model they map roughly to the Physical layer (transmitter, channel, receiver) and the upper layers (source, destination). See OSI reference model for the layer mapping.

Direction of data flow

Syllabi describe the direction of data flow with three terms. They indicate how many logical channels exist between the two ends.

  • Simplex – data moves only from source to destination. Example: a TV broadcast.
  • Half‑duplex – a single channel is shared; data can travel both ways but not at the same time. Example: walkie‑talkie.
  • Full‑duplex – two independent channels allow simultaneous two‑way transfer. Example: a telephone conversation.

Choosing the mode influences protocol design. Full‑duplex links need separate buffers for each direction, while simplex links can omit the reverse path entirely, saving cost.

Putting it together

  1. Identify the source and the destination of the information.
  2. Select a transmitter that can encode the data for the chosen channel.
  3. Pick a channel whose bandwidth meets the required data rate.
  4. Choose a receiver compatible with the transmitter’s signal format.
  5. Decide the direction mode (simplex, half‑duplex, full‑duplex) based on application needs.

For a smart‑meter reading sent to a utility server, the meter is the source, a cellular modem is the transmitter, the air‑interface is the channel, the base‑station receiver is the receiver, and the server is the destination. The link is usually full‑duplex so the server can acknowledge receipt.

Worked example

Question. A sensor sends 500 bytes to a server over a 1 Mbps full‑duplex link. Compute the transmission time required to push the entire frame onto the channel. Assume no propagation delay and no protocol overhead.

C program.

#include <stdio.h>
int main(){
    int bytes = 500;
    int bits = bytes * 8;
    double rate = 1e6; // bits per second
    double time = bits / rate;
    printf("%f\n", time);
    return 0;
}
  1. Convert bytes to bits: 500 bytes × 8 bits/byte = 4000 bits.
  2. Data rate of the link: 1 Mbps = 1 000 000 bits/s.
  3. Transmission time = total bits ÷ data rate = 4000 bits ÷ 1 000 000 bits/s = 0.004 s.

Exam traps

  • Adding the transmission time for both directions in a full‑duplex link and then doubling the result.
  • Using kilobits (kb) instead of kilobits per second (kbps) and forgetting the per‑second factor.
  • Treating the 500 bytes as 500 bits, which reduces the computed time by a factor of eight.
  • Including propagation delay when the question explicitly says to ignore it.

1.2 Network types and categories: LAN, MAN, WAN

Network categories group communication systems by how far they stretch. A LAN stays inside a single building, a MAN covers a city or campus, and a WAN spans a country or the world. The idea helps engineers pick the right technology, budget, and management style for the area they must serve. These categories appear when a college builds its internal network, when Chennai Metro runs a city‑wide fiber ring, or when a bank links branches across India.

You need: basics of data communication from Chapter 1.1.

Geographic scope of network categories

A Local Area Network (LAN) connects devices that are in one building or a tightly bounded area such as a college department. LANs use Ethernet cables or Wi‑Fi and typically provide speeds from 100 Mbps to 10 Gbps. A Metropolitan Area Network (MAN) links several LANs across a city. MANs often use fiber‑optic links and support 1 Gbps to 100 Gbps. A Wide Area Network (WAN) joins LANs or MANs that are far apart, possibly across countries. WANs use leased lines, satellite links, or the public Internet and may offer 10 Mbps to several hundred Gbps.

  • Campus LAN – Ethernet inside a university building.
  • Chennai Metro MAN – 10 Gbps fiber ring connecting stations.
  • National bank WAN – leased MPLS circuits linking branches.

Some syllabi call these three groups "network categories" because they share similar design goals and constraints. The larger the area, the higher the cost per kilometre of link and the more complex the routing.

Typical bandwidth and technology

LANs usually run Ethernet. A common campus LAN uses 1 Gbps full‑duplex copper or fiber. The technology cost is low and installation is easy. MANs often adopt dense wavelength division multiplexing (DWDM) fiber. A city MAN may be provisioned for 10 Gbps or more, allowing many LANs to share the backbone. WANs rely on leased lines or MPLS. A banking WAN might have a 100 Mbps leased line per branch, but the aggregate capacity of the backbone can be many gigabits.

Total bandwidth = B₁ + B₂ + B₃

B₁, B₂, B₃ are the individual link capacities (in the same unit).

If a college LAN (1 Gbps), a city MAN (10 Gbps), and a bank WAN (100 Mbps) are all used together, the total usable bandwidth is 1 Gbps + 10 Gbps + 0.1 Gbps = 11.1 Gbps.

Understanding these numbers helps when you later study routing in Chapter 1.8.

Why the categories matter

Design decisions differ for each category. LAN design focuses on low latency and high throughput within a short distance. MAN design balances cost of fiber deployment with the need to serve many organisations. WAN design must handle long distances, variable latency, and often uses protocols that tolerate loss, such as TCP over satellite links.

  • Cost per kilometre rises from LAN to WAN.
  • Management complexity grows with area size.
  • Choice of physical media (copper, fiber, radio) follows the category.

Later chapters on topologies, protocols, and devices will refer back to these categories when explaining why a star LAN uses a switch, why a ring MAN may use a ring topology such as SONET/SDH rings, and why a WAN needs routers.

  • Assuming a MAN is always faster than a WAN; speed depends on the specific technology, not the category.

1.3 Network topologies

Network topology is the physical layout of devices and links in a network. It decides how many cables are needed, how data travels, and how resilient the network is to failures. Different layouts suit different scales: a small office may use a star, a campus may use a partial mesh, and a data centre often combines star and mesh. Understanding each topology helps you choose the right design for cost, performance and fault‑tolerance.

You need: Data communication components and data flow modes and Network types and categories.

Bus topology

In a bus topology all nodes share a single communication line called the backbone. Each node taps the line and listens for frames addressed to it. The idea is simple: one cable, many devices, low material cost. It works well for small LANs where the total traffic is low.

  • Only one transmission at a time; CSMA/CD is used to detect and resolve collisions.
  • If the backbone fails, the whole network stops working.
  • Maximum length limited by signal attenuation; repeaters or Ethernet switches can be used to extend the network segment, but modern designs prefer switches.

C_total = C_link

C_total is the total usable bandwidth of the bus; C_link is the bandwidth of the single shared link.

  1. Place the coaxial cable across the office.
  2. Connect each computer with a T‑connector.
  3. Terminate both ends with a 50 Ω resistor to prevent signal reflections.

Star and tree topologies

A star topology connects every end device to a central hub or switch. The central node handles all traffic, making the layout easy to manage and troubleshoot. A tree (or hierarchical star) adds multiple layers of switches, creating branches that reduce cable length in large buildings.

  • Each link can operate at full duplex when a switch is used; hubs operate in half‑duplex.
  • Failure of one link isolates only the attached device; the rest of the network stays up.
  • Common in Ethernet LANs and campus networks.

C_agg = N × C_link

C_agg is the aggregate bandwidth the hub can handle; N is the number of attached devices; C_link is the bandwidth of each individual link.

The aggregate bandwidth is limited by the switching fabric; a non‑blocking switch can support N × C_link, otherwise the actual capacity may be lower.

  1. Install a managed switch in the server room.
  2. Run Cat6 cables from the switch to each workstation.
  3. Configure VLANs on the switch if logical segmentation is needed.

Ring and mesh topologies

In a ring topology each node connects to exactly two neighbours, forming a closed loop. Frames travel in one or both directions; token passing avoids collisions. Mesh topology provides multiple redundant paths between nodes. A full mesh has a direct link for every pair, while a partial mesh connects only selected pairs.

  • Ring offers deterministic latency but a single break isolates the whole network.
  • Full mesh gives the highest fault tolerance; partial mesh balances cost and resilience.
  • Data‑centre fabrics often use a leaf‑spine partial mesh.

L_mesh = n (n‑1) / 2

L_mesh is the number of links in a full mesh; n is the number of nodes.

  1. Number the nodes from 1 to n.
  2. Connect each node to its two neighbours to form a ring.
  3. Add extra links between selected pairs to create a partial mesh.

Worked example

Question. A small office has 5 computers connected in a star topology to a 100 Mbps Ethernet switch. Each computer sends data continuously to the switch. Compute (a) the total traffic arriving at the switch and (b) the maximum aggregate traffic the switch can forward if it operates in full‑duplex mode.

C program.

#include <stdio.h>
int main(){
    int n=5; int link=100; // Mbps
    int total=n*link;
    printf("%d Mbps\n", total);
    printf("%d Mbps\n", total);
    return 0;
}
  1. Each link provides 100 Mbps.
  2. There are 5 links, so total incoming traffic = 5 × 100 Mbps = 500 Mbps.
  3. In full‑duplex, the switch can send 100 Mbps on each of the 5 outgoing links simultaneously.
  4. Maximum aggregate outbound traffic = 5 × 100 Mbps = 500 Mbps.

Output

500 Mbps
500 Mbps

Answer. The switch sees 500 Mbps of incoming traffic and can forward up to 500 Mbps outbound, assuming full‑duplex operation.

Exam traps

  • Using n×(n‑1) instead of n(n‑1)/2 for the number of links in a full mesh gives twice the correct count.
  • Adding the bandwidth of all links in a star and then multiplying by 2 assumes half‑duplex; the trap is forgetting that full‑duplex allows simultaneous send and receive on each link.
  • Confusing a bus’s total bandwidth C_total with the per‑link bandwidth; the bus shares a single bandwidth among all nodes.
  • Treating a ring as having two independent paths without considering the token‑passing protocol, which limits simultaneous transmissions.

1.4 Protocols, standards and layered architecture

A protocol is a precise agreement on how two entities exchange messages. A standard records that agreement so many vendors can build compatible products. Layering hides the details of lower layers, letting each layer focus on a single function and speak a uniform protocol to the layer above. This makes network devices from different makers interoperate, and lets engineers design, test, and upgrade parts of a network independently. Layered models are used in every modern data‑communication system, from a home Wi‑Fi router to the backbone of the Internet.

You need: basic data‑communication concepts from Chapter 1.1.

Protocol and Standard

A protocol defines the syntax, semantics and timing of messages exchanged between two communication entities. Syntax is the format of bits; semantics is the meaning of each field; timing is the order and speed of exchange. A standard is a publicly documented protocol that a standards body maintains. It ensures that any product following the standard can interoperate with any other product that also follows it.

  • ISO (International Organization for Standardization) publishes the OSI model and many link‑layer standards.
  • IEEE (Institute of Electrical and Electronics Engineers) defines Ethernet (IEEE 802.3) and Wi‑Fi (IEEE 802.11).
  • IETF (Internet Engineering Task Force) publishes RFCs such as TCP (RFC 793) and IP (RFC 791).

Only a few universities call this topic "protocol layering" in their syllabus, but it appears in almost every networking course worldwide.

Why a Layered Model?

Layering separates concerns. The physical layer worries only about voltage levels, the data‑link layer about framing and error detection, the network layer about routing, and so on. Each layer communicates with the one above using a service‑access point (SAP) and receives data in a protocol data unit (PDU). By hiding lower‑layer details, an application developer can write code without knowing the exact wiring of the network.

  1. A layer receives a PDU from the layer below.
  2. It removes the header added by that lower layer.
  3. It processes the payload and adds its own header.
  4. It passes the new PDU to the next higher layer.

FrameSize = Payload + Σ Header_i

Payload is the original data in bytes; Header_i is the header size added by layer i.

The formula shows that the total size grows linearly with the number of layers that add headers. This growth is why designers try to keep header sizes small.

Worked Example of Header Addition

Consider the message "Hi" which is 2 bytes. It must travel through three layers: Application, Transport and Network. Each layer adds a 2‑byte header. Using the formula above, the final frame size is 2 + 2 + 2 + 2 = 8 bytes.

Python program.

payload = 2
header_per_layer = 2
layers = 3
frame = payload + layers * header_per_layer
print(frame)

Output

8

If a layer forgets to add its header, the frame would be only 6 bytes. That mistake is a common exam trap.

Worked example

Question. A payload of 2 bytes is sent from an application to the network. The Application, Transport and Network layers each add a 2‑byte header. Compute the size of the final frame that leaves the Network layer.

#include <stdio.h>

    int payload = 2;
    int header = 2;
    int layers = 3;

    printf("%d\n", frame);
    return 0;
}

  2. Number of layers adding headers = 3.
  3. Header per layer = 2 bytes.
  4. Total header size = 3 × 2 bytes = 6 bytes.
  5. Final frame size = Payload + Total header size = 2 bytes + 6 bytes = 8 bytes.

1.5 OSI reference model

The OSI reference model defines seven standard layers that separate networking functions. Each layer offers services to the layer above and uses services of the layer below. The model helps designers, vendors, and students to describe protocols, locate problems, and build interoperable systems. Some syllabi call this the OSI model and use it as a teaching tool for layered architecture.

You need: Protocol and layered basics.

Seven layers and their functions

The topmost layer is the Application layer. It provides network services directly to user applications such as web browsers or email clients.

Below it is the Presentation layer. It translates data formats, encrypts, and compresses information so that different systems can understand each other.

The Session layer establishes, manages, and terminates communication sessions between applications.

The Transport layer offers reliable or best‑effort delivery of data segments. It adds port numbers, sequence numbers and checksums.

The Network layer routes packets across multiple networks. It adds logical addresses such as IPv4 or IPv6.

The Data Link layer frames packets for a single link. It adds MAC addresses and error‑checking codes.

The Physical layer converts bits into electrical, optical, or radio signals and defines the medium characteristics.

  • Application – user services (HTTP, DNS)
  • Presentation – syntax, encryption, compression
  • Session – dialog control
  • Transport – end‑to‑end reliability
  • Network – routing and logical addressing
  • Data Link – framing and MAC control
  • Physical – bits on the wire

Why the OSI model is useful

When a message travels from a smartphone to a bank server, each layer adds its own header. The model lets engineers isolate problems. If a packet is dropped, examining the Network layer header (destination address) and routing information helps determine whether the cause is a routing issue, congestion, or link failure. If a checksum fails, the error is likely in the layer that generated that checksum – for example, a Frame Check Sequence error points to the Data Link layer, a TCP/UDP checksum error points to the Transport layer, and an IP header checksum error points to the Network layer.

The model also guides protocol design. New services such as UPI payments or IRCTC ticketing are built as Application‑layer protocols that rely on existing Transport and Network services.

In the exam, you will often be asked to calculate the total size of a frame after encapsulation. The example below shows a typical calculation.

  1. Start with the payload size.
  2. Add the Transport header size.
  3. Add the Network header size.
  4. Add the Data Link header size.
  5. The Physical layer transmits the sum as bits.

Common misconceptions

A frequent mistake is to place the Transport layer above the Session layer. The OSI definition puts Transport directly under Session.

Another error is swapping the order of the Data Link and Network layers. The Data Link layer always precedes the Network layer in the stack.

Remember that the Physical layer does not add a header; it only converts bits to signals.

Worked example

Question. A host sends 100 bytes of user data using TCP over IPv4 over Ethernet. TCP adds a 20‑byte header, IPv4 adds a 20‑byte header, and Ethernet adds a 14‑byte header. Compute the total number of bytes transmitted on the wire.

  1. Payload = 100 bytes.
  2. Add TCP header: 100 + 20 = 120 bytes.
  3. Add IPv4 header: 120 + 20 = 140 bytes.
  4. Add Ethernet header: 140 + 14 = 154 bytes.
  5. The Physical layer sends 154 bytes as bits.

Answer. The wire carries 154 bytes.

Exam traps

  • Confusing the order of Transport and Session layers leads to an extra header count.
  • Swapping Data Link and Network layers adds the wrong header sizes.
  • Counting a Physical‑layer header when none exists reduces the final size incorrectly.

1.6 TCP/IP protocol suite and Internet architecture

The TCP/IP protocol suite defines the practical Internet. It groups functions into four layers. Each layer hides details from the one above. The model lets devices from any vendor interoperate. It is used in every web, email, and mobile transaction across India.

You need: OSI reference model.

Four‑layer TCP/IP stack

The TCP/IP suite has four layers: Application, Transport, Internet, and Link. The Application layer hosts protocols such as HTTP, DNS, and SMTP. The Transport layer provides end‑to‑end services using TCP or UDP. The Internet layer routes packets with IPv4 or IPv6. The Link layer moves frames over a physical medium like Ethernet or Wi‑Fi.

The layers map to the OSI model. Application roughly covers OSI layers 5–7. Transport matches OSI layer 4. Internet corresponds to OSI layer 3. Link aligns with OSI layers 1–2. Some syllabi call this mapping the Internet architecture.

  • Application – user data and protocol semantics
  • Transport – ports, reliability, flow control
  • Internet – logical addressing, routing
  • Link – physical addressing, media access

Internet layer: IPv4 and IPv6

IPv4 uses a 32‑bit address written as four decimal octets. It has a 20‑byte header for basic services. IPv6 expands the address to 128 bits and uses a fixed 40‑byte header. IPv6 includes optional IPsec support for security and, because of its large address space, typically eliminates the need for NAT, though NAT may still be employed in specific scenarios.

Routers make routing decisions at the Internet layer by examining the destination IP address, but they also handle Link‑layer frames to forward packets on the appropriate physical link.

  • IPv4 header length = 20 B (without options)
  • IPv6 header length = 40 B (no options)
  • Both carry source and destination addresses

Transport and Application layers

TCP provides reliable, ordered delivery. It adds a 20‑byte header containing source and destination ports, sequence number, acknowledgment number, data offset, flags, window size, checksum, and urgent pointer. UDP offers connectionless service with a 8‑byte header and no retransmission.

Application protocols use these transport services. A web browser sends an HTTP GET request over TCP. An online game may use UDP to reduce latency.

  1. Application creates data payload.
  2. Transport encapsulates payload in a segment.
  3. Internet encapsulates segment in a packet.
  4. Link encapsulates packet in a frame.

Worked example

Question. A client sends a 500 B HTTP request over Ethernet. The TCP header is 20 B, the IPv4 header is 20 B, and the Ethernet header is 14 B. Compute the total number of bytes transmitted on the wire.

C program.

#include <stdio.h>
int main(){
    int payload = 500;
    int tcp = 20;
    int ip = 20;
    int eth = 14;
    int crc = 4;
    int total = payload + tcp + ip + eth + crc;
    printf("%d\n", total);
    return 0;
}
  1. Payload = 500 B.
  2. Add TCP header: 500 B + 20 B = 520 B.
  3. Add IPv4 header: 520 B + 20 B = 540 B.
  4. Add Ethernet header: 540 B + 14 B = 554 B.
  5. Add Ethernet CRC: 554 B + 4 B = 558 B.

1.7 Circuit switching versus packet switching

Data must travel from a source to a destination. Two fundamental ways to move that data are circuit switching, which reserves a dedicated path for the whole session, and packet switching, which lets many users share the same links by breaking data into packets. Circuit switching is used in traditional telephone networks, while packet switching underlies the Internet. Understanding the trade‑offs helps you choose the right technology for a given service.

You need: the basics of data communication from Data communication: components and data flow modes and the layered view from Protocols, standards and layered architecture.

Circuit switching – dedicated path

In circuit switching a complete path from the source to the destination is reserved before any bits travel. The path stays reserved for the whole call, even if no data are sent at a particular moment. Because the bandwidth on each link is fixed, the user gets a guaranteed data rate. The propagation delay is constant for a given physical path, independent of bandwidth.

B = R × T

B is total bits transmitted (bits); R is reserved data rate (bits ⁄ s); T is call duration (s).

  1. Determine the required data rate for the service (e.g., 64 kbps for a voice call).
  2. Reserve a physical or logical path that can sustain that rate on every link.
  3. Keep the path occupied for the entire session, regardless of actual traffic.
  • Predictable latency – useful for real‑time voice or video.
  • Inefficient use of bandwidth when the user is silent.
  • Simple switching hardware – the network only needs to connect two ends.

Packet switching – shared links

Packet switching breaks a message into small packets. Each packet carries a destination address and is forwarded independently. Links are shared among many users; If the outgoing link selected by the routing decision is free, the packet can be transmitted immediately; otherwise it is queued until the link becomes available.

D = L ⁄ R + d_prop + Q

D is total packet delay (s); L is packet length (bits); R is link data rate (bits ⁄ s); d_prop is propagation delay (seconds); Q is queuing delay (s) caused when total demand exceeds R.

  1. Segment the data stream into packets of size L.
  2. At each router, examine the packet header and forward to the next hop.
  3. If the outgoing link is busy, place the packet in a queue; Q grows with traffic load.
  • Higher link utilization – idle periods of one user can be used by another.
  • Variable delay – queuing can increase latency during congestion.
  • More complex routing logic – packets may follow different paths.

When to prefer one over the other

Circuit switching is chosen when a constant data rate and low jitter are mandatory, such as a traditional land‑line call or a dedicated video‑conference link in a corporate campus. Packet switching is preferred for bursty traffic, web browsing, or any service that can tolerate some delay, because it makes better use of expensive bandwidth.

Worked example

Question. A telephone network provides a dedicated 64 kbps circuit for a voice call lasting 10 minutes. Compute the total number of bits that can be transmitted on this circuit. In an IP network the same 64 kbps link is shared by 5 users, each generating traffic at an average rate of 20 kbps. If each user transmits continuously for 2 minutes, (a) how many bits does each user generate, (b) what is the total traffic generated, (c) how many bits can the link actually carry in 2 minutes, and (d) how many bits remain queued at the end of the 2‑minute interval.

C program.

#include <stdio.h>
int main(){
    double R = 64000; // bits per second
    double T = 120;   // seconds
    double bits = R * T;
    printf("Link can carry %.2f Mbits in 2 minutes\n", bits/1e6);
    return 0;
}
  1. Circuit: B = R × T = 64 000 bits ⁄ s × 600 s = 38 400 000 bits = 38.4 Mbits.
  2. Each packet‑switch user: B_user = 20 000 bits ⁄ s × 120 s = 2 400 000 bits = 2.4 Mbits.
  3. Total generated: B_total = 5 × 2.4 Mbits = 12.0 Mbits.
  4. Link capacity in 2 minutes: B_link = 64 000 bits ⁄ s × 120 s = 7 680 000 bits = 7.68 Mbits.
  5. Queued bits = B_total – B_link = 12.0 Mbits – 7.68 Mbits = 4.32 Mbits.

1.8 Network devices: hubs, switches, bridges and routers

Network devices move frames or packets from one end of a network to another. Different devices use different logic to decide where to send the data. Hubs repeat electrical signals, switches learn MAC addresses, bridges filter traffic between segments, and routers forward IP packets based on routing tables. These devices appear in home Wi‑Fi routers, office Ethernet closets, campus backbones and ISP core networks.

You need: basic data communication concepts from Chapter 1.1.

Hub – a physical‑layer repeater

A hub operates at the physical layer. It receives a voltage signal on one port, amplifies it, and sends the same signal out on all other ports.

Because the hub does not examine any header fields, every attached device shares one collision domain. If two devices transmit simultaneously, a collision occurs and both frames are corrupted.

  • Simple and cheap, often used in small home networks before switches became inexpensive.
  • Creates a single broadcast domain and a single collision domain.

Signal_out = Gain × Signal_in

Signal_out is the amplified voltage; Gain is the amplification factor; Signal_in is the received voltage.

Switch – MAC‑address learning at the data‑link layer

A switch works at layer 2. Each port belongs to a separate collision domain but all ports share one broadcast domain.

When a frame arrives, the switch reads the source MAC address and stores it in a MAC table together with the incoming port.

  1. Read destination MAC address from the frame header.
  2. Look up the destination in the MAC table.
  3. If an entry exists, forward the frame only to the associated port.
  4. If no entry exists, flood the frame to all ports except the source.
  • Reduces collisions compared to a hub.
  • Supports full‑duplex links, allowing simultaneous send and receive.

Python program.

mac_table = {}

def process_frame(src_mac, dst_mac, in_port):
    mac_table[src_mac] = in_port  # learn source
    out_port = mac_table.get(dst_mac)
    if out_port is None:
        return f"Flood to all ports except {in_port}"
    else:
        return f"Forward to port {out_port}"

print(process_frame('AA:BB:CC:DD:EE:01', 'FF:EE:DD:CC:BB:02', 1))

Output

Flood to all ports except 1

Bridge and Router – segment filtering and IP routing

A bridge is a two‑port switch. It separates two Ethernet segments and forwards frames only when the destination MAC belongs to the opposite segment.

A router works at layer 3. It receives an IP packet, checks the destination IP address, and looks up the best next‑hop in a routing table.

  1. Extract destination IP from the packet header.
  2. Match the IP against routing table prefixes.
  3. Select the longest‑prefix match.
  4. Encapsulate the packet in a new frame with the next‑hop MAC address and send it out the chosen interface.
  • Creates separate broadcast domains, reducing unnecessary traffic.
  • Implements NAT, firewall rules and QoS in many ISP routers.
NextHop = argmax_{r∈RoutingTable} (PrefixLength(r) where IP ∈ Prefix(r))

PrefixLength(r) is the number of bits in the prefix; IP is the destination address; Prefix(r) is the network prefix of route r.

Worked example

Question. Host A wants to send a 1 MB file to Host D over a 100 Mbps switched LAN. Compute the transmission time assuming negligible switching delay.

C program.

#include <stdio.h>
int main(){
    double size_mb = 1.0; // megabytes
    double bits = size_mb * 8 * 1e6; // convert to bits
    double speed_mbps = 100.0; // megabits per second
    double time_s = bits / (speed_mbps * 1e6);
    printf("%.2f\n", time_s);
    return 0;
}
  1. Convert file size to bits: 1 MB = 1 × 8 Mbits = 8 Mbits.
  2. Use the formula Transmission time = File size (bits) ÷ Link speed (bits/s).
  3. Plug values: 8 Mbits ÷ 100 Mbps = 0.08 s.

Exam traps

  • Assuming a hub creates separate collision domains for each port; it actually creates a single collision domain.
  • Treating a switch as a router and expecting it to examine IP addresses; a basic switch only looks at MAC addresses.
  • Adding the hub’s amplification gain to the transmission time calculation; amplification does not affect data size or speed.
  • Thinking that a bridge can route between different IP subnets; a bridge works only at layer 2 and cannot forward IP packets across subnets.
