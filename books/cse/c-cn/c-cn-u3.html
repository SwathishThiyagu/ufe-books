3.1 Framing and bit stuffing

Frames give boundaries to a continuous bit stream on a physical link. Without boundaries the receiver cannot know where one packet ends and the next begins. Bit stuffing inserts extra bits so that the special flag pattern 01111110 never appears inside the payload. The receiver removes the inserted bits and recovers the original data. This technique is used in HDLC, PPP and many serial links in telecom and in wired connections such as a railway signalling system.

You need: basics of bits and bytes from Unit 1.

Why framing is needed

The physical layer transmits a raw sequence of voltage changes. It does not indicate where a higher‑layer packet starts. If the sender and receiver share a common flag, they can agree that the flag marks the border of a frame. The flag must be a pattern that does not occur in the payload, otherwise the receiver would mistake payload bits for a border.

  • A frame carries address, control and payload fields.
  • The flag is 8 bits: 01111110.
  • The sender adds the flag at the front and rear of the payload; the receiver removes the flags after reception.

In a railway ticket booking system that uses a serial line, each ticket request is a frame. The flag tells the receiver where one request ends and the next begins, even if many requests are sent back‑to‑back.

Bit stuffing algorithm

If the payload itself contains five consecutive 1 bits, the flag could be hidden inside it. The rule is: after any run of five 1s, insert a 0. The inserted 0 is called a stuffed bit. The receiver scans the incoming bits, removes any 0 that follows five 1s, and thus restores the original data.

  1. Read the payload bit by bit.
  2. Count consecutive 1s.
  3. When the count reaches five, insert a 0 (stuffed bit), output it, and reset the count to zero; the inserted 0 is not counted as a 1.
  4. Continue until all payload bits are processed.

Flag = 01111110

Flag is the 8‑bit pattern that marks frame boundaries.

Byte stuffing is an alternative where special byte values are escaped. The concept is the same: make the delimiter unique inside the transmitted data.

Worked example

Question. A sender wants to transmit the 10‑bit payload 1101111110 using bit stuffing. Show the stuffed payload, add the start and stop flags, and write the final transmitted frame.

C program.

#include <stdio.h>
#include <string.h>

void stuff(const char *in, char *out) {
    int cnt = 0, j = 0;
    for (int i = 0; in[i]; ++i) {
        out[j++] = in[i];
        if (in[i] == '1') {
            cnt++;
            if (cnt == 5) {
                out[j++] = '0';
                cnt = 0;
            }
        } else {
            cnt = 0;
        }
    }
    out[j] = '\0';
}

int main() {
    const char *payload = "1101111110";
    char stuffed[32];
    stuff(payload, stuffed);
    printf("Stuffed: %s\n", stuffed);
    printf("Frame: 01111110%s01111110\n", stuffed);
    return 0;
}
  1. Original payload: 1101111110.
  2. Scan bits: after the first five consecutive 1s (11111) insert a 0.
  3. Stuffed payload becomes 11011111010.
  4. Add flag 01111110 at the front and rear.
  5. Final frame: 01111110 11011111010 01111110.

Exam traps

  • Forgetting to delete the stuffed 0 after five 1s yields a payload that is one bit longer than expected.
  • Treating the flag pattern as data without stuffing causes the receiver to split the frame early.
  • Counting five 1s across a flag boundary is wrong; the counter resets after each flag.
  • Using byte stuffing with the same flag value leads to ambiguous frames.

3.2 Error detection: parity, checksum and CRC

Error detection adds a small amount of extra bits to a frame so that the receiver can tell if the frame was altered during transmission. It is used in every Ethernet, Wi‑Fi and serial link to avoid passing corrupted data to higher layers. The chapter covers three practical methods – parity, one's‑complement checksum and cyclic redundancy check (CRC) – and shows which error patterns each method can guarantee to catch.

You need: Framing and bit stuffing.

Parity – single‑bit and two‑dimensional

Parity adds one extra bit to a word. Even parity makes the total number of 1 bits even; odd parity makes it odd. The sender computes the parity bit and appends it; the receiver recomputes parity on the received bits and checks if the rule is satisfied.

  • Even parity catches any odd number of bit flips in the word.
  • Odd parity also catches any odd number of flips, but the rule is reversed.

Two‑dimensional parity adds a parity bit for each row and an additional parity bit for each column of a block of bits. The bottom‑right corner cell (intersection of the last row and last column) stores the parity of all the row‑parity bits and column‑parity bits together.

  1. Arrange the data bits in a rectangular matrix.
  2. Compute a row parity bit for each row and append it at the end of the row.
  3. Compute a column parity bit for each column and append it as an extra row at the bottom.
  4. The bottom‑right corner cell is the parity of all parity bits.

Two‑dimensional parity detects any single‑bit error, any double‑bit error that lies in different rows and columns, and many triple‑bit errors. It cannot guarantee detection of errors that affect an entire row or an entire column.

One's‑complement checksum

The checksum treats the data as a sequence of 16‑bit words. All words are added using one's‑complement arithmetic: add the words, add any overflow (carry) back into the low 16 bits, then invert all bits. The result is transmitted as the checksum field.

C = ~ ( Σ_i W_i + carry )

C is the checksum; W_i is the i‑th 16‑bit word; Σ_i is the ordinary sum; carry is the overflow beyond 16 bits; ~ is bitwise NOT.

At the receiver the same addition is performed on the received words and the checksum. If the final sum equals 0xFFFF, the frame is assumed error‑free.

C program.

#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint16_t w1 = 0xABCD;
    uint16_t w2 = 0x1234;
    uint16_t w3 = 0xFFFF;
    uint32_t sum = (uint32_t)w1 + w2 + w3;   // ordinary sum
    // add carry back into low 16 bits
    while (sum >> 16) {
        sum = (sum & 0xFFFF) + (sum >> 16);
    }
    uint16_t checksum = ~ (uint16_t)sum;    // one's complement
    printf("Checksum = 0x%04X\n", checksum);
    return 0;
}

Output

Checksum = 0x41FE

The checksum catches all single‑bit errors and many multiple‑bit errors, but it does not guarantee detection of every error that flips an odd number of bits.

Cyclic Redundancy Check (CRC) with G(x)=x³+x+1

CRC treats the data block as a polynomial D(x) over GF(2). The sender multiplies D(x) by x^r where r is the degree of the generator G(x) (here r=3) and divides the result by G(x). The remainder R(x) (r bits) is appended to the original data. The transmitted frame is D(x)·x^r + R(x).

At the receiver the same division is performed on the received bits. If the final remainder is zero, the frame is accepted.

  1. Write the data bits: 11010011101100.
  2. Append three zero bits (equal to the degree r = 3 of the generator): 11010011101100000.
  3. Divide by the generator 1011 using binary long division.
  4. The remainder after the last subtraction is 100.

The generator x³+x+1 (binary 1011) detects all single‑bit errors, all double‑bit errors, and any burst error of length ≤ 3. It does not guarantee detection of all odd‑bit errors because it lacks the (x+1) factor. Longer burst errors are detected with a probability of 1‑2⁻³.

When to use which method

  • Parity is cheapest – only one extra bit – and is enough for simple serial links where error rates are very low.
  • One's‑complement checksum adds two bytes per frame and is used in IP, TCP and UDP.
  • CRC‑16 adds 2 bytes, CRC‑32 adds 4 bytes, etc., but gives far stronger guarantees; it is used in Ethernet, Wi‑Fi, USB and many storage interfaces.

Choosing the right method balances hardware complexity, bandwidth overhead and the required detection strength.

Worked example

Question. A sender must transmit three 16‑bit words: 0xABCD, 0x1234 and 0xFFFF. Compute the one's‑complement checksum, append it to the frame, and show how the receiver verifies the frame. Then compute the CRC remainder for the 14‑bit data pattern 11010011101100 using the generator G(x)=x³+x+1.

C program.

#include <stdio.h>
#include <stdint.h>

uint16_t ones_complement_checksum(uint16_t *words, int n) {
    uint32_t sum = 0;
    for (int i = 0; i < n; ++i) sum += words[i];
    while (sum >> 16) sum = (sum & 0xFFFF) + (sum >> 16);
    return ~ (uint16_t)sum;
}

int main(void) {
    uint16_t w[3] = {0xABCD, 0x1234, 0xFFFF};
    uint16_t chk = ones_complement_checksum(w, 3);
    printf("Checksum = 0x%04X\n", chk);
    return 0;
}
  1. Add the three words as ordinary integers: 0xABCD + 0x1234 = 0xBE01; 0xBE01 + 0xFFFF = 0x1BE00.
  2. Add the overflow (carry) back into the low 16 bits: 0x1BE00 → low 16 bits 0xBE00, carry 0x1. Sum = 0xBE00 + 0x1 = 0xBE01.
  3. Invert all bits: ~0xBE01 = 0x41FE. This is the checksum to be transmitted.
  4. Receiver adds the three words and the received checksum using one's‑complement addition: 0xABCD + 0x1234 = 0xBE01; +0xFFFF = 0x1BE00 → wrap to 0xBE01; +0x41FE = 0xFFFF. The final sum is 0xFFFF, indicating no error.
  5. For CRC, append three zeros to the data: 11010011101100 000.
  6. Perform binary division by 1011. After successive XOR steps the remainder is 100.
  7. The CRC field is 0b100 (hex 0x4). The transmitted frame is the original 14 bits followed by 100.

Exam traps

  • Using ordinary addition instead of one's‑complement arithmetic for the checksum leaves the carry unadded, giving a wrong checksum (e.g., 0xF659 instead of 0x41FE).
  • Treating the CRC generator as a decimal number (11) rather than the binary polynomial 1011 leads to an incorrect remainder.
  • Assuming that a parity bit can detect any even number of bit errors; it can only guarantee detection of odd‑count errors.
  • For CRC, forgetting to append r zero bits before division changes the remainder completely.
  • Comparing the received checksum directly with the computed checksum instead of checking that the final sum equals 0xFFFF.

3.3 Error correction with Hamming codes

Hamming codes add a few extra bits to a data word so that a single‑bit error can be detected and corrected without retransmission. This capability is useful on noisy links such as wireless or power‑line channels, where a corrupted frame must be fixed quickly. The (7,4) Hamming code is the smallest practical example and forms the basis for many error‑correction schemes used in storage devices and satellite links.

You need: error detection basics from Error detection.

Structure of the (7,4) Hamming code

A (7,4) Hamming code maps 4 data bits to a 7‑bit code word. The positions that are powers of two (1, 2, 4) hold parity bits p1, p2, p3. The remaining positions (3, 5, 6, 7) hold the data bits d1‑d4. Each parity bit checks a subset of the code word; the subsets are chosen so that the binary representation of the checked positions contains a 1 in the bit corresponding to that parity.

  1. Write the 4 data bits in positions 3,5,6,7.
  2. Compute p1 as XOR of bits whose index has LSB = 1 (positions 1,3,5,7).
  3. Compute p2 as XOR of bits whose index has second LSB = 1 (positions 2,3,6,7).
  4. Compute p3 as XOR of bits whose index has third LSB = 1 (positions 4,5,6,7).

p1 = d1 ⊕ d2 ⊕ d4

⊕ is XOR; d1 is bit 3, d2 is bit 5, d4 is bit 7.

p2 = d1 ⊕ d3 ⊕ d4

d3 is bit 6.

p3 = d2 ⊕ d3 ⊕ d4

p3 = d2 ⊕ d3 ⊕ d4 where: d2 is bit 5, d3 is bit 6, d4 is bit 7.

Decoding and syndrome calculation

When a code word arrives, the receiver recomputes the three parity checks using the received bits. The three results form the syndrome S = (s3 s2 s1) where s1 is the result of the p1 check, s2 of p2, and s3 of p3. If S = 000 the word is error‑free. Any non‑zero syndrome gives the binary index of the erroneous bit, which can then be flipped to recover the original data.

  1. Re‑compute the three parity checks on the received 7 bits.
  2. Form the syndrome S = s3s2s1 (most significant bit from p3).
  3. If S = 000, accept the word.
  4. Otherwise, interpret S as a binary index (1‑7) and invert that bit.
  • The syndrome works because each parity equation isolates a unique set of positions.
  • Only a single‑bit error can be corrected; two‑bit errors may produce a valid but wrong syndrome.

Extended (8,4) SEC‑DED code (advanced)

Some curricula add an overall parity bit to the (7,4) code, creating an (8,4) code that can correct a single‑bit error and also detect any double‑bit error. The extra parity bit checks all seven bits. If the syndrome is non‑zero but the overall parity is satisfied, the error is a double‑bit error and the receiver must request retransmission.

  • SEC‑DED stands for Single‑Error‑Correct, Double‑Error‑Detect.
  • Used in memory modules (ECC RAM) and some storage devices.

Worked example

Question. A sender wants to transmit the 4‑bit data word 1011 using a (7,4) Hamming code. (a) Compute the three parity bits and write the 7‑bit code word. (b) During transmission bit 3 flips. The receiver obtains 0100011. Perform syndrome decoding and state the corrected data bits.

C program.

#include <stdio.h>
int main(){
    int data[4] = {1,0,1,1}; // d1 d2 d3 d4
    int p1 = data[0]^data[1]^data[3];
    int p2 = data[0]^data[2]^data[3];
    int p3 = data[1]^data[2]^data[3];
    int code[7] = {p1,p2,data[0],p3,data[1],data[2],data[3]};
    // simulate error at position 3
    code[2] ^= 1;
    // syndrome
    int s1 = code[0]^code[2]^code[4]^code[6];
    int s2 = code[1]^code[2]^code[5]^code[6];
    int s3 = code[3]^code[4]^code[5]^code[6];
    int syndrome = (s3<<2)|(s2<<1)|s1;
    if(syndrome) code[syndrome-1] ^= 1;
    printf("%d %d %d %d\n", code[2], code[4], code[5], code[6]);
    return 0;
}
  1. Place data bits: d1=1 (pos3), d2=0 (pos5), d3=1 (pos6), d4=1 (pos7).
  2. Compute p1 = d1⊕d2⊕d4 = 1⊕0⊕1 = 0.
  3. Compute p2 = d1⊕d3⊕d4 = 1⊕1⊕1 = 1.
  4. Compute p3 = d2⊕d3⊕d4 = 0⊕1⊕1 = 0.
  5. Encoded word = p1 p2 d1 p3 d2 d3 d4 = 0 1 1 0 0 1 1 → 0110011.
  6. Received word = 0 1 0 0 0 1 1.
  7. Re‑compute checks: s1 = p1⊕d1⊕d2⊕d4 = 0⊕0⊕0⊕1 = 1.
  8. s2 = p2⊕d1⊕d3⊕d4 = 1⊕0⊕1⊕1 = 1.
  9. s3 = p3⊕d2⊕d3⊕d4 = 0⊕0⊕1⊕1 = 0.
  10. Syndrome = s3s2s1 = 0 1 1 = binary 3 → error at position 3.
  11. Flip bit 3: corrected word = 0 1 1 0 0 1 1.
  12. Extract data bits (positions 3,5,6,7): 1 0 1 1.

3.4 Flow control: stop-and-wait and sliding window

Flow control stops the sender from overwhelming the receiver. It limits how many frames can be in transit before an acknowledgement is required. Stop‑and‑wait uses a single outstanding frame. Sliding‑window lets several frames be sent before waiting. These mechanisms keep the link efficient and avoid buffer overflow in routers, switches, or end‑devices such as a mobile phone receiving video over 4G.

You need: Framing and bit stuffing and Error detection.

Stop‑and‑wait flow control

The sender transmits one data frame and then stops. It waits for an acknowledgement (ACK) from the receiver before sending the next frame. The sender starts a timer after sending. If the timer expires before the ACK arrives, the sender retransmits the same frame.

  • Sender window size = 1 frame.
  • Receiver sends cumulative ACK with the next expected sequence number.
  • Timeout = round‑trip time (RTT) plus a safety margin.

η = 1 ÷ (1 + 2a)

η is link efficiency; a = propagation delay ÷ transmission time; the factor 2 accounts for forward and return propagation.

  1. Sender puts frame in the channel.
  2. Receiver checks frame for errors.
  3. If correct, receiver sends ACK with seq = next frame number.
  4. Sender receives ACK and proceeds; otherwise timer triggers retransmission.

Stop‑and‑wait is simple but inefficient when the propagation delay is large compared to the transmission time. It is used in low‑speed links such as satellite control channels or simple UART communication.

Sliding‑window flow control

The sender may transmit up to N frames before waiting for an ACK. N is the sender window size. Each frame carries a sequence number. The receiver acknowledges the highest in‑order sequence received (cumulative ACK).

  • Sender window slides forward when ACKs arrive.
  • Receiver expects frames in order; out‑of‑order frames are discarded.
  • If a frame is lost, the receiver discards it and all later frames until the missing one is received.

η ≈ N ÷ (N + 2a)

η is efficiency; N is window size; a is as defined for stop‑and‑wait.

  1. Sender transmits frames 0 … N‑1.
  2. Receiver sends ACK = k where k is the next expected sequence number.
  3. When ACK = k arrives, the sender slides its window so that the lowest unacknowledged sequence number becomes k. It can then transmit any new frames with sequence numbers from k up to k+N‑1 that have not been sent yet.

Sliding‑window improves utilization on long‑delay links such as fiber‑optic backbones or Wi‑Fi video streaming. It is the basis for protocols like TCP and HDLC.

Worked example

Question. A link runs at 1 Mbps. Each frame carries 1000 bits of payload. The one‑way propagation delay is 20 ms. Compute the transmission time, the ratio a, and the stop‑and‑wait efficiency η (in %).

3.5 ARQ error control: Go-Back-N and Selective Repeat

ARQ error control retransmits lost or corrupted frames. Go‑Back‑N (GBN) resends the whole unacknowledged block, while Selective Repeat (SR) resends only the missing frames. Both use sliding windows, cumulative or selective acknowledgements, and sequence numbers that wrap around. They are used in Ethernet, Wi‑Fi and satellite links where occasional frame loss is normal.

You need: flow control basics from section 3.4.

Sender and receiver windows

A sender window holds frames that have been transmitted but not yet acknowledged. Its size is called the window size W. A receiver window holds frames that have been received out of order and are waiting for missing earlier frames.

  • Sender window moves forward when ACKs are received.
  • Receiver window moves forward when in‑order frames are delivered to the network layer.
W ≤ M for Go‑Back‑N; W ≤ (M+1)/2 for Selective Repeat

W is the window size; M is the largest sequence number (modulo value). The first inequality applies to Go‑Back‑N, the second to Selective Repeat. The bound prevents ambiguity between new and old frames.

Sequence numbers are taken modulo M+1. For example, with M = 7 the numbers are 0‑7 and after 7 the next number is 0 again.

Go‑Back‑N ARQ

GBN uses a cumulative ACK. The ACK number N means that all frames up to N‑1 have been received correctly. If a frame is lost, the receiver cannot acknowledge any later frame, so the sender eventually times out and retransmits the lost frame and all following frames.

  1. Sender transmits frames 0,1,2,3 (W=4).
  2. Frame 2 is lost; receiver acknowledges 0 and 1, sending ACK=2.
  3. Sender receives ACK=2 and slides the window to start at 2.
  4. Timer for frame 2 expires because no ACK for frame 2 is received (ACK=3 cannot be sent until frame 2 is received).
  5. Sender retransmits frames 2 and 3.

Total transmissions = original 4 frames + 2 retransmissions = 6 frames.

Selective Repeat ARQ

SR uses individual ACKs (or NACKs). The receiver stores out‑of‑order frames in a buffer. Only the missing frames are retransmitted.

  1. Sender transmits frames 0,1,2,3 (W=4).
  2. Frame 2 is lost; receiver ACKs 0,1 and also ACKs 3 (out‑of‑order).
  3. Sender receives ACK for 3 and knows only frame 2 is missing.
  4. Sender retransmits only frame 2.
  5. Receiver delivers frames 0‑3 in order to the network layer.

Total transmissions = original 4 frames + 1 retransmission = 5 frames.

Python program.

def simulate_gbn(window, loss_idx):
    sent = list(range(window))
    acks = []
    # loss of one frame
    for i in sent:
        if i == loss_idx:
            continue
        acks.append(i+1)
    # timeout -> retransmit lost and later
    retrans = list(range(loss_idx, window))
    return len(sent) + len(retrans)

def simulate_sr(window, loss_idx):
    sent = list(range(window))
    # loss of one frame
    acks = [i+1 for i in sent if i != loss_idx]
    # only lost frame retransmitted
    retrans = [loss_idx]
    return len(sent) + len(retrans)

print(simulate_gbn(4, 2))  # 6
print(simulate_sr(4, 2))   # 5

3.6 Data link protocols: HDLC and PPP

HDLC and PPP give reliable point‑to‑point links. They wrap user data in a flag‑delimited frame, add an address, a control field and a 16‑bit CRC. The same framing is reused in PPP, which adds a negotiation phase (LCP) so that two ends can agree on authentication, compression and network‑layer protocol. These protocols are used on serial links, DSL modems, and in many WAN routers.

You need: Framing and bit stuffing, Error detection: CRC‑16.

HDLC frame structure

An HDLC frame starts and ends with the flag pattern 01111110 (hex 0x7E). Between the flags the sender places an address byte, a control byte, the payload data and a 16‑bit Frame Check Sequence (FCS). The FCS is the CRC‑16 computed over address, control and data. After the FCS the closing flag is sent.

  1. Transmit flag 0x7E.
  2. Transmit address byte.
  3. Transmit control byte.
  4. Transmit data bytes.
  5. Compute CRC‑16 over address, control and data; append low‑order byte first.
  6. Transmit closing flag 0x7E.
  • Bit stuffing: after five consecutive 1 bits the transmitter inserts a 0 to avoid creating a false flag.
  • The receiver removes any stuffed 0 after five 1s before CRC checking.
FCS = CRC‑16(poly=0x8005, init=0xFFFF, refIn=true, refOut=true, xorOut=0x0000)

FCS is a 16‑bit value; poly is the generator polynomial; init is the initial register; refIn/Out indicate bit reflection.

HDLC operating modes

HDLC defines three link modes. In Normal Response Mode (NRM) the secondary may transmit only after receiving a Set‑Asynchronous‑Balanced‑Mode (SABM) from the primary. Asynchronous Balanced Mode (ABM) allows both ends to send frames whenever they have data, using a simple “I‑frame” for information and “RR”/“REJ” for flow control. Extended Asynchronous Balanced Mode (EABM) adds larger sequence numbers, so the window can be up to 127 frames.

  • NRM is used on legacy leased lines where one side is a master.
  • ABM is the default for modern PPP links.
  • EABM is useful when high‑speed links need a larger sliding window.
  1. Primary sends SABM → secondary replies with UA (Unnumbered Acknowledgement).
  2. Both sides may now exchange I‑frames.
  3. If a frame is lost, the receiver sends REJ; the sender retransmits from the rejected sequence number.

PPP encapsulation and LCP negotiation

PPP reuses the HDLC flag 0x7E and the same CRC‑16. The PPP frame adds a two‑byte Protocol field after the address (0xFF) and control (0x03) bytes. The Protocol field identifies the network‑layer protocol, e.g., 0x0021 for IPv4. Before data exchange the two ends run Link Control Protocol (LCP) to negotiate options such as authentication (PAP/CHAP), compression and the maximum receive unit (MRU).

  1. Send LCP Configure‑Request with desired options.
  2. Receive LCP Configure‑Ack, Configure‑Nak or Configure‑Reject.
  3. Repeat until both sides acknowledge the same set of options.
  4. Open the network‑layer protocol (e.g., IPCP for IPv4).
  • PPP is defined in RFC 1661 (and subsequently in ISO/IEC 1172).
  • Because PPP uses HDLC framing, any device that can decode HDLC can also decode PPP.

}

3.7 Multiple access protocols: ALOHA, CSMA/CD, CSMA/CA

Multiple access protocols let many devices share a single channel. They avoid or resolve collisions so that data can be sent without a central scheduler. Pure and slotted ALOHA are the earliest random access schemes. CSMA/CD is used in wired Ethernet. CSMA/CA is used in Wi‑Fi. All three families appear in campus LANs, home routers and cellular back‑haul.

You need: Framing and bit stuffing and Error detection.

Pure and Slotted ALOHA

In ALOHA a station transmits whenever it has a frame. If another station transmits within the vulnerable period, the two frames collide and are lost. The vulnerable period is twice the frame time because a collision can start at the beginning of either frame.

S = G·e^(−2G)

S is the throughput in frames per frame time; G is the offered load in frames per frame time.

Slotted ALOHA improves the situation by forcing all stations to start only at the beginning of a time slot whose length equals one frame time. The vulnerable period shrinks to one slot.

S = G·e^(−G)

S and G have the same meaning as in pure ALOHA.

  1. Choose a slot boundary.
  2. If a station has a frame, it transmits at the next slot start.
  3. If exactly one station transmits, the frame is received correctly.
  4. If two or more stations transmit, a collision occurs and the slot is wasted.
  • Maximum pure ALOHA throughput ≈ 0.184 frames/slot.
  • Maximum slotted ALOHA throughput ≈ 0.368 frames/slot.

CSMA/CD for Ethernet

Carrier Sense Multiple Access with Collision Detection (CSMA/CD) adds a listen-before‑talk rule. A station first senses the medium. If it is idle, it starts transmitting. While sending, it continues to listen. If it detects a voltage change, a collision is declared.

  1. Sense the carrier.
  2. If idle, transmit the frame.
  3. Monitor the signal for a collision.
  4. If collision detected, transmit a jam signal for 32 bits (4 bytes).
  5. Stop transmission and wait a random backoff time.
  • Ethernet slot time is 512 bits (64 bytes). At 10 Mbps this corresponds to 51.2 µs.
  • Backoff time = k × slot time, where k is a random integer in [0, 2^i−1] and i is the retry count (max i = 10).

Python program.

import random

def backoff(retry):
    # Deterministic backoff values for illustration
    ks = [0, 1, 1, 7]  # k values for retries 0‑3
    k = ks[retry] if retry < len(ks) else 0
    slot_time_us = 51.2   # 512 bits at 10 Mbps = 51.2 µs
    return k * slot_time_us

for r in range(4):
    print(f"Retry {r}: backoff = {backoff(r):.1f} µs")

CSMA/CA for Wi‑Fi

In wireless media a station cannot detect a collision while transmitting. CSMA/CA avoids collisions by using a short clear‑channel assessment (CCA) and a random backoff before each transmission.

  1. Wait for the channel to be idle for a DIFS (Distributed Inter‑Frame Space) period.
  2. If idle, start a random backoff counter measured in 20 µs slots.
  3. Decrement the counter for each idle slot.
  4. When the counter reaches zero, transmit the data frame.
  5. Optionally use RTS/CTS handshake to reserve the medium.
  • Slot time = 20 µs.
  • Backoff range = [0, CW‑1] where CW starts at 15. CW is set to (CW+1)·2 − 1 after each failure (i.e., it roughly doubles).

CW = 2^i·(CW_min+1) - 1

i = number of retransmission attempts; CW_min = 15.

3.8 Ethernet and virtual LANs (VLANs)

Ethernet carries data between devices on a LAN. Frames contain source and destination MAC addresses, a type field, optional VLAN tag, payload, and a CRC checksum. The VLAN tag lets several logical networks share the same physical cables while keeping traffic separate. This chapter shows how a frame is built, how a 802.1Q tag is inserted, and why Ethernet requires a minimum of 64 bytes to detect collisions on a shared medium.

You need: Multiple access protocols and the framing basics from Framing and bit stuffing.

Ethernet II frame format

An Ethernet II frame starts with a 48‑bit destination MAC address followed by a 48‑bit source MAC address. Each MAC address is written as six hexadecimal bytes, for example 00:1A:2B:3C:4D:5E. The next field is a 16‑bit EtherType that indicates which protocol is carried in the payload; 0x0800 means IPv4, 0x86DD means IPv6.

After the EtherType comes the payload. Payload length must be at least 46 bytes and at most 1500 bytes. If the upper‑layer data is smaller than 46 bytes, padding bytes of value 0 are added.

The frame ends with a 32‑bit CRC‑32 called the Frame Check Sequence (FCS). The CRC is computed over all bits from the destination MAC up to the last byte before the FCS, i.e., it includes any padding bytes and, if present, the 802.1Q VLAN tag.

FCS = CRC32( Dest‖Src‖[TPID‖TCI]‖Type‖Payload‖Padding )

Dest and Src are 48‑bit MAC addresses; TPID‖TCI are present only when a VLAN tag exists; Type is 16‑bit EtherType; Payload is 46‑1500 bytes; Padding are any added bytes; CRC32 uses the standard polynomial 0x04C11DB7.

  • Dest MAC: 48 bits (6 bytes)
  • Src MAC: 48 bits (6 bytes)
  • EtherType: 16 bits (2 bytes)
  • Payload: 46‑1500 bytes
  • FCS: 32 bits (4 bytes)

802.1Q VLAN tagging

A VLAN tag is a 4‑byte field inserted between the source MAC and the EtherType. The first two bytes are the Tag Protocol Identifier (TPID) with value 0x8100, signalling that a VLAN tag follows.

The next two bytes are the Tag Control Information (TCI). The three most‑significant bits are the Priority Code Point (PCP) used for QoS. Bit 12 is the Drop Eligible Indicator (DEI). The remaining 12 bits form the VLAN Identifier (VID) ranging from 1 to 4094.

TCI = PCP×2¹³ + DEI×2¹² + VID

PCP is 3‑bit priority, DEI is 1‑bit, VID is 12‑bit VLAN ID.

  1. Take the Ethernet frame without VLAN tag.
  2. Insert the 4‑byte VLAN tag after the source MAC.
  3. Set TPID = 0x8100 and encode PCP, DEI, VID in TCI.
  4. Re‑compute the FCS over the entire frame that now includes the VLAN tag.
  • VLAN tag length: 4 bytes
  • PCP range: 0‑7
  • VID range: 1‑4094

Minimum frame size and collision detection

Ethernet on a shared coaxial cable or hub uses CSMA/CD. To guarantee that a transmitting station can detect a collision, the frame must be at least 64 bytes (512 bits) long.

If the payload is smaller than 46 bytes, padding bytes are added to the payload so that the payload length becomes at least 46 bytes, which ensures the total frame length reaches the 64‑byte minimum.

T_min = 512 bits ÷ data_rate

data_rate is the link speed, e.g., 100 Mbps.

  1. Calculate total bytes: Dest + Src + (optional VLAN) + Type + Payload + Padding + FCS.
  2. If the total frame length (including headers, payload, and any existing padding) is less than 64 bytes, add additional padding bytes to the payload until the overall frame length becomes 64 bytes.
  3. Transmit the frame; the physical layer monitors the medium for a collision during T_min.

Transmission time = 64 B × 8 ÷ 100 Mbps = 5.12 µs. The station must sense the carrier for at least this duration (the slot time) to guarantee collision detection.

Beyond the syllabus

Not for the exam. VLANs are widely used in data‑center networks to separate tenant traffic without extra hardware. Software‑defined networking extends VLAN concepts with virtual overlay networks such as VXLAN. Research explores dynamic VLAN assignment based on machine‑learning predictions of traffic patterns. For deeper study, look at IEEE 802.1Q‑2018 amendments and the interaction between VLANs and link‑aggregation protocols.

3.9 Wireless LANs: IEEE 802.11 architecture and MAC

Wi‑Fi networks use the IEEE 802.11 standard to share a radio channel among many devices. The standard defines a MAC protocol called DCF that uses CSMA/CA, optional RTS/CTS handshakes and acknowledgements to avoid collisions. It is used in homes, offices, campuses and public hotspots where devices connect through an access point (AP).

You need: CSMA/CA basics and frame formation.

Basic WLAN concepts

A group of stations that communicate with the same AP forms a Basic Service Set (BSS). The BSS is identified by a Service Set Identifier (SSID), a human‑readable name such as "CampusWiFi". The AP is a fixed radio that coordinates the medium for all stations in the BSS. Stations that can hear the same AP are called associated stations.

  • Management frames: beacon, probe request/response, authentication, association.
  • Control frames: RTS, CTS, ACK, block‑acknowledge.
  • Data frames: carry upper‑layer payloads.

All frames start with a MAC header, followed by a payload, and end with a Frame Check Sequence (FCS) for error detection. The header contains the source address, destination address, and a frame type field that tells the receiver how to treat the frame. Depending on the frame type, the MAC header can contain up to four address fields (Address1‑Address4).

CW = (2^m)·(CWmin+1) – 1

CW is the size of the contention window in slots; m is the backoff stage (0 for the first attempt); CWmin is the minimum contention window (15 for DCF). For the first attempt (m = 0) the formula gives CW = CWmin.

Distributed Coordination Function (DCF)

  1. Sense the channel. If it is idle for DIFS (Distributed Inter‑Frame Space) = 50 µs for the 2.4 GHz band, proceed to step 2.
  2. Choose a random integer k in [0, CW].
  3. Wait for k × slot_time (20 µs) while the channel stays idle.
  4. If the channel becomes busy, freeze the timer and resume when idle again.
  5. Transmit the frame. If RTS/CTS is enabled, send RTS first, wait SIFS (Short Inter‑Frame Space), receive CTS, then send DATA.
  6. After the DATA transmission, wait SIFS and listen for an ACK. If ACK is not received, treat it as a collision and increase m.

The slot_time is defined as 20 µs for the 2.4 GHz band and 9 µs for the 5 GHz band. Using the wrong slot_time gives an incorrect backoff duration.

Backoff_time = k × slot_time

k is the random backoff counter; slot_time is 20 µs for 2.4 GHz.

Example: CWmin = 15, random k = 7. Backoff_time = 7 × 20 µs = 140 µs. The station will wait DIFS (50 µs) plus 140 µs before transmitting the RTS.

Optional advanced features

Only a few universities teach the 802.11ac amendment. It adds Multi‑User MIMO (MU‑MIMO) that lets the AP transmit different streams to several stations simultaneously, increasing throughput in dense environments such as stadiums or large offices.

MU‑MIMO requires the AP to know the channel state of each station. The AP sends a sounding frame, stations reply with channel feedback, and the AP schedules spatial streams accordingly.

Worked example

Question. A station wants to send a 1500‑byte MAC frame using RTS/CTS. The contention window is CWmin = 15 slots, slot_time = 20 µs, and the random backoff chosen is k = 7. DIFS = 50 µs, SIFS = 10 µs, and each frame (RTS, CTS, DATA, ACK) takes 1 ms to transmit. Compute (a) the waiting time before the RTS is sent, and (b) the total time from the start of the backoff to the receipt of the ACK.

C program.

#include <stdio.h>
int main(){
    double slot = 20e-6; // 20 µs
    int k = 7;
    double backoff = k * slot; // seconds
    double DIFS = 50e-6; // corrected DIFS for 2.4 GHz
    double wait = DIFS + backoff;
    double frame = 1e-3; // 1 ms
    double SIFS = 10e-6;
    double total = 4*frame + 3*SIFS; // RTS, CTS, DATA, ACK + three SIFS
    double final = wait + total;
    printf("Backoff = %d µs\n", (int)(backoff*1e6));
    printf("Total time = %.3f ms\n", final*1e3);
    return 0;
}
  1. Backoff_time = k × slot_time = 7 × 20 µs = 140 µs.
  2. Wait before RTS = DIFS + Backoff_time = 50 µs + 140 µs = 190 µs.
  3. RTS transmission = 1 ms.
  4. SIFS after RTS = 10 µs.
  5. CTS transmission = 1 ms.
  6. SIFS after CTS = 10 µs.
  7. DATA transmission = 1 ms.
  8. SIFS after DATA = 10 µs.
  9. ACK transmission = 1 ms.
  10. Total exchange time = 4 × 1 ms + 3 × 10 µs = 4.03 ms.
  11. Add the initial wait: 0.190 ms + 4.03 ms = 4.22 ms.

Exam traps

  • Using the 9 µs slot_time of the 5 GHz band for a 2.4 GHz network reduces the backoff calculation by more than half.
  • Forgetting to add DIFS before the random backoff leads to a shorter wait time than the protocol specifies.
  • Assuming ACK is sent after a SIFS even when RTS/CTS is not used; ACK is still required but the timing is the same.
  • Mixing up CWmin (15) with CWmax (1023) and using the larger value for the first attempt.

Understand Explain why Wi‑Fi uses CSMA/CA instead of CSMA/CD. 4 marks

Wi‑Fi uses a shared wireless medium where collisions cannot be detected while transmitting. CSMA/CA avoids collisions by listening before sending and using random backoff, whereas CSMA/CD relies on detecting a collision on a wired link.

Apply A station selects a backoff counter k = 12 in a network where slot_time = 9 µs. How long does it wait before transmitting? 3 marks

Backoff_time = 12 × 9 µs = 108 µs.

Apply Given CWmin = 15, a collision occurs and the station moves to the next backoff stage. What is the new CW value? 3 marks

After a collision the backoff stage becomes m = 1, so CW = (2^1)·(CWmin+1) – 1 = 2·16 – 1 = 31.

Analyze If a network experiences many hidden‑node collisions, which optional mechanism reduces the problem and how does it work? 5 marks

The RTS/CTS handshake. The sender first sends a short RTS; the AP replies with CTS that is heard by all stations within range. Those stations defer transmission for the duration indicated, preventing hidden‑node collisions.

Remember Name the three inter‑frame spaces defined in 802.11. 2 marks

SIFS (Short), DIFS (Distributed), and EIFS (Extended).

Takeaways

  1. Framing converts a raw bit stream into identifiable packets using flags and bit stuffing.
  2. Error detection methods add redundancy that lets the receiver spot corrupted frames.
  3. Hamming codes provide a simple way to correct a single‑bit error without retransmission.
  4. Flow‑control protocols prevent the sender from overwhelming the receiver or the network.
  5. ARQ schemes combine error detection with retransmission strategies to achieve reliable delivery.
  6. HDLC and PPP define standard frame formats for point‑to‑point links over diverse media.
  7. Medium‑access protocols decide how multiple stations share a common channel without collisions.
  8. VLAN tagging logically separates traffic on the same physical Ethernet, improving security and management.
