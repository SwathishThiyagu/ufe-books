3.1 Framing and bit stuffing

A frame is a bounded package at the data link layer. The receiver must see where it starts and ends before it can read addresses or check bits. Bit stuffing solves one exact problem: the end flag is a pattern of bits, and user data might contain that same pattern by accident. The sender inserts a zero after every five consecutive 1s so the flag can never appear inside the frame. The receiver removes those zeros. HDLC-style links and many bit-oriented protocols use this.

You need: Unit 1 for the data link layer's place in the layered model, and the idea of a packet from the network layer.

A frame is a bounded package

A frame is the data link layer's unit of transmission. It carries a packet from the network layer. The packet sits inside the frame's payload. The payload is the user data that the frame protects and delivers. A frame needs a visible start and end. Without them the receiver cannot tell where one frame stops and the next begins. Some syllabi call this frame delineation.

  • Flag: the boundary marker. In bit-oriented framing it is 01111110.
  • Header: address and control information.
  • Payload: the network-layer packet.
  • Trailer: frame check bits (FCS) for error detection, covered in 3.2.

Fixed-length frames need no end marker: the receiver counts bytes. A length field in the header also works: it states how many bytes follow. Variable-length frames often use a flag at both ends.

Byte-oriented framing with an escape byte

In byte-oriented framing the frame is a sequence of bytes. A flag byte marks start and end; a common value is 0x7E, binary 01111110. If the flag byte appears inside the data, the sender inserts an escape byte, often 0x7D, before it. If the escape byte itself appears in the data, the sender sends escape then escape. The receiver sees the escape and removes it, restoring the original bytes.

  1. Sender rule: data byte equals flag → send ESC, then flag.
  2. Sender rule: data byte equals ESC → send ESC, then ESC.
  3. Receiver rule: ESC flag → flag; ESC ESC → ESC.

Bit-oriented framing and bit stuffing

Bit-oriented framing does not align to bytes. A single flag 01111110 marks both start and end. The flag contains six consecutive 1s, so six 1s in the data would look like the flag. Bit stuffing prevents that. The sender scans every bit between the flags, including header, payload and FCS. After five consecutive 1s it inserts one 0, whether the next data bit is 0 or 1. That breaks every run of six 1s. The receiver counts 1s; after five 1s it discards the next 0. The flag itself is never stuffed.

  1. Sender: copy bits in order and keep a count of consecutive 1s.
  2. After the count reaches five, append a 0 and reset the count to zero.
  3. Receiver: copy bits and after five 1s throw away the next 0.
  4. Destuff first, then test the FCS, because the check bits were computed before stuffing.

Stuffing costs extra bits but guarantees the flag cannot appear inside the frame. If the receiver tested the FCS on the stuffed stream, the inserted zeros would look like changed data and a good frame would fail.

Worked example

Question. A bit-oriented frame uses flag 01111110. The 15 bits between the flags before stuffing are 111111011111100. Find the stuffed stream, the number of inserted zeros, and the total length. Then show the receiver's destuffed output.

Exam traps

  • Insert the 0 after the fifth 1 even if the sixth bit is 1, and even if the next bit is 0. Do not wait for a sixth 1.
  • The flag itself is never stuffed. Stuffing applies only to bits between the opening and closing flags.
  • Destuff before the FCS check. The sender computed the FCS on the original bits, not on the stuffed stream.
  • Byte stuffing uses a whole escape byte; bit stuffing inserts one zero bit. They are different fixes for the same boundary problem.
  • Do not count the flag's own six 1s as data. The receiver knows where the flags are.

3.2 Error detection: parity, checksum and CRC

A sender can never trust a link to keep every bit unchanged. Error detection adds a few redundant bits that are a fixed function of the data, so the receiver can test whether some bits changed. The extra bits are not a copy of the data; they are a fingerprint. Three common fingerprints are parity, the Internet checksum, and the cyclic redundancy check (CRC). They appear in frame trailers, IPv4 headers, TCP and UDP segments, and storage devices. This chapter shows how each is computed and which error patterns each one misses.

You need 3.1 Framing and bit stuffing, because the check bits sit in the frame trailer.

Parity: one bit, and its blind spot

Parity adds one bit to a block. For even parity, the parity bit is the XOR of all data bits, so the total number of 1s becomes even. For odd parity, flip that bit, so the total number of 1s becomes odd. The receiver recomputes the XOR of the data plus the received parity bit; even parity expects 0, odd parity expects 1. If the test fails, the receiver asks for a retransmission.

P = b₁ ⊕ b₂ ⊕ ... ⊕ bₙ

P is the even parity bit; b₁ to bₙ are the data bits; ⊕ is XOR. For odd parity, send the complement of P.

Single parity detects any odd number of flipped bits. It misses any even number of flips, because two flips cancel in the XOR. A two-bit error on a phone line is common enough that single parity is weak.

Two-dimensional parity fixes part of this. Arrange data as rows. Add one parity bit to each row and one to each column. A single flipped bit breaks its row parity and its column parity, so the receiver can locate the bit and correct it. Any two-bit error also fails at least one parity check. A four-bit error at the four corners of a rectangle passes every row and column check, so it is missed. This scheme costs one parity bit per row plus one per column, more than single parity but less than a CRC of the same strength.

Internet checksum

The Internet checksum works on 16-bit words. The sender adds all words using one's complement addition: add normally, and if a carry leaves bit 15, add that carry back to bit 0. The checksum is the one's complement of the final sum, meaning every bit is flipped. The checksum is placed in the header.

S = w₁ + w₂ + ... + wₙ  (one's complement addition)

w₁ to wₙ are 16-bit words; any carry out of bit 15 is added back to bit 0; the checksum is the one's complement of S.

The receiver adds all 16-bit words, including the checksum, with the same end-around carry. If no error occurred, the result is all 1s, that is 0xFFFF. A result other than 0xFFFF means an error was detected. IPv4 uses this checksum for its header. TCP and UDP use the same arithmetic for their checksum, which covers the segment plus a pseudo-header. The method is fast in software and needs no special hardware. It is not as strong as CRC: swapped words or changes that cancel in the sum can pass.

CRC: modulo-2 division

CRC treats bit strings as polynomials whose coefficients are 0 or 1. A generator G has degree r, the highest power in its polynomial. Common generators are CRC-32, CRC-16 and CRC-CCITT; their bit patterns are standard tables, not values to invent.

R(x) = (D(x) × xr) mod G(x)

D(x) is the data polynomial; G(x) is the generator polynomial of degree r; R(x) is the remainder polynomial of degree less than r; mod means modulo-2 division with XOR.

  1. Write the k data bits as D(x) and choose G(x) of degree r.
  2. Append r zero bits to D, which gives D(x) × x^r.
  3. Divide by G using XOR at each step; no borrows are used.
  4. The r-bit remainder R is the CRC. Append R to the original data.
  5. The receiver divides the whole frame by G; remainder 0 means accept.

The frame now has k + r bits. A non-zero remainder at the receiver means the frame is dropped. A burst error is a run of damaged bits. A CRC of degree r detects every burst error of length r or less. It detects any single-bit error. Many standard generators include the factor (x+1), so they also catch any odd number of flips. It can miss a burst longer than r, or a pattern that is a multiple of G. The chance of missing a random error is about 2^-r for a good G.

Worked example

Question. Data bits are 1001 and the generator is G = 1011. Compute the CRC, build the transmitted frame, and show that the receiver accepts it. Work in modulo-2 arithmetic.

  1. D = 1001. G = 1011 has degree r = 3, because the highest power is x³. Append r = 3 zeros to D: 1001 000 = 1001000.
  2. Divide 1001000 by 1011 modulo 2. Use a 3-bit remainder and feed bits left to right. Start rem = 000.
  3. Bit 1: rem = 001. Bit 0: rem = 010. Bit 0: rem = 100. Bit 1: rem = 1001; top bit is 1, so rem = 1001 XOR 1011 = 0010 = 2.
  4. Next bit 0: rem = 0100 = 4. Next bit 0: rem = 1000 = 8; top bit is 1, so rem = 1000 XOR 1011 = 0011 = 3. Last bit 0: rem = 0110 = 6.
  5. The remainder is 110 in binary, which is 6 in decimal. This is the CRC.
  6. Frame = D followed by CRC = 1001 110 = 1001110. In decimal this is 78.
  7. Receiver divides 1001110 by 1011. Bit sequence: 1→1, 0→2, 0→4, 1→9 XOR 1011→2, 1→5, 1→11 XOR 1011→0, 0→0. Remainder is 000 = 0, so accept.

Answer. The CRC is 110 (6 decimal), the frame is 1001110 (78 decimal), and the receiver's remainder is 000 (0 decimal), so the frame is accepted.

Exam traps

  • CRC subtraction is XOR with no borrows; do not use ordinary binary subtraction.
  • The number of appended zeros equals the degree r of G, not the bit length of G. G = 1011 has length 4 and degree 3, so append 3 zeros.
  • Single parity detects any odd number of errors only. Two flips cancel; four flips can also cancel.
  • In two-dimensional parity, a single flip is corrected by the row and column that fail; a rectangle of four flips is missed.
  • The Internet checksum is not a CRC. It uses one's complement addition with end-around carry, and it can miss reordered or compensating words.

3.3 Error correction with Hamming codes

A Hamming code adds check bits at chosen positions so the receiver can do more than notice that a bit flipped. It computes a syndrome, a number that names the position of one flipped bit, and flips that bit back. One extra overall parity bit separates a single-bit error from a double-bit error. This is used where retransmission is costly or impossible: satellite links, ECC memory, and deep-space probes. The same counting rule guides the choice of check bits.

You need 3.2, especially even parity and the idea of check bits.

Distance and the count rule

Hamming distance dmin is the smallest number of bit positions in which any two valid codewords differ. A code with distance dmin detects up to dmin − 1 errors: a burst that changes fewer bits cannot turn one valid codeword into another. It corrects up to floor((dmin − 1)/2) errors: the received word stays nearer to the original codeword than to any other. Hamming(7,4) has dmin = 3, so it detects two errors and corrects one.

The number of check bits is not arbitrary. For m data bits and r check bits, the receiver needs a distinct syndrome for each of the m + r bit positions plus one for “no error”. That gives the count rule.

2r ≥ m + r + 1

m is the number of data bits, r is the number of check bits, and m + r is the codeword length n.

Hamming(7,4) step by step

Hamming(7,4) sends four data bits in a seven-bit codeword. Number positions from 1, not 0. Put check bits at positions 1, 2, 4 — every power of two — and data bits at 3, 5, 6, 7. For data d1 d2 d3 d4 = 1011, d1 sits at 3, d2 at 5, d3 at 6, d4 at 7.

Use even parity. Check bit p1 covers positions 1, 3, 5, 7, so p1 is chosen to make that set have an even number of 1s. p2 covers 2, 3, 6, 7. p4 covers 4, 5, 6, 7. A compact rule: p_i covers every position whose index has bit i set. For 1011 this gives p1 = 0, p2 = 1, p4 = 0, so the codeword is 0 1 1 0 0 1 1.

The receiver repeats the three parity checks on the received seven bits and forms a syndrome. Let s1 be the parity of positions 1, 3, 5, 7; s2 of 2, 3, 6, 7; s4 of 4, 5, 6, 7. Each s is 0 for even and 1 for odd. Read the syndrome as a binary position.

s = 4s<sub>4</sub> + 2s<sub>2</sub> + s<sub>1</sub>

s is the syndrome as a decimal position, s4 is the most significant syndrome bit, and s1 is the least significant syndrome bit.

If s = 0, assume no error. If s is between 1 and 7, flip that position. The order matters: s4 is the most significant bit, s1 the least. In the figure, position 5 has flipped. The syndrome is 101 in binary, decimal 5, so the receiver flips position 5 and recovers the sent word.

One more bit, other codes

Hamming(7,4) corrects one error, but a second error can make the syndrome point to a wrong position. SECDED adds one overall parity bit over all seven bits, making eight bits total and total parity even. The receiver then separates one correctable error from two detected errors. This is common in server memory: ECC RAM uses such codes.

Cyclic codes treat a codeword as coefficients of a polynomial and divide by a fixed generator polynomial. The remainder is the check part; CRC is the detection-only version. Some cyclic codes are designed for correction. Convolutional codes pass data through a shift register with memory, so each output bit depends on current and earlier input bits; a decoder such as Viterbi searches for the most likely input sequence. Only a few universities teach these in the data link layer, so keep the idea: polynomial division for cyclic codes, memory and sequence estimation for convolutional codes.

Worked example

Question. Data 1011 is sent with a Hamming(7,4) code using even parity. (a) Find the check bits and codeword. (b) The received word is 0 1 1 0 1 1 1. Find the syndrome and the corrected data.

  1. Number positions 1 to 7. Data bits: d1 = 1 at position 3, d2 = 0 at 5, d3 = 1 at 6, d4 = 1 at 7.
  2. p1 covers 1, 3, 5, 7. Data contribution 1 + 0 + 1 = 2, even, so p1 = 0.
  3. p2 covers 2, 3, 6, 7. Data contribution 1 + 1 + 1 = 3, odd, so p2 = 1.
  4. p4 covers 4, 5, 6, 7. Data contribution 0 + 1 + 1 = 2, even, so p4 = 0.
  5. Codeword positions 1 to 7: p1 p2 d1 p4 d2 d3 d4 = 0 1 1 0 0 1 1.
  6. Received 0 1 1 0 1 1 1. s1 = parity of 0, 1, 1, 1 = three ones, odd, so s1 = 1.
  7. s2 = parity of 1, 1, 1, 1 = four ones, even, so s2 = 0.
  8. s4 = parity of 0, 1, 1, 1 = three ones, odd, so s4 = 1. Syndrome = 4(1) + 2(0) + 1(1) = 5.
  9. Position 5 is d2 = 0. Flip it back to 0. Corrected codeword 0 1 1 0 0 1 1; data 1011.

Answer. The sent codeword is 0110011, the syndrome is 5, and the corrected data is 1011.

Exam traps

  • Positions start at 1, not 0. With 0-based indexing every check bit is in the wrong place.
  • p_i covers every position whose index has bit i set. p4 covers 4, 5, 6, 7, not only 4 and 6.
  • Sender and receiver must agree on parity. If the sender builds even parity and the receiver checks odd, every clean word looks wrong.
  • The count rule is 2^r ≥ m + r + 1. Leaving out the +1 undercounts check bits.
  • Hamming(7,4) corrects one error. Two errors may give a nonzero syndrome that points to a third innocent bit; do not claim double correction.

3.4 Flow control: stop-and-wait and sliding window

A receiver holds incoming frames in a finite buffer. If the sender pushes frames faster than the receiver can check them and pass them upward, the buffer overflows and good frames are dropped. Flow control keeps the sender's rate within what the receiver can take. The simplest rule is one frame at a time, with an acknowledgement before the next frame — stop-and-wait. The standard fix is a sliding window of W unacknowledged frames. HDLC and TCP each carry a version of it, and Wi-Fi acknowledges each MAC frame before the next.

You need: 3.1 for what a frame is, and 3.2 because flow control assumes the frames that arrive are intact.

Why the sender must be paced

Frames that arrive while the receiver is busy checking a header or copying a payload wait in a buffer. If the sender transmits faster than the receiver empties that buffer, frames overflow and are dropped, even though no bit was damaged on the wire. Flow control keeps the sender at or below the rate the receiver can absorb.

Flow control is separate from error control. Flow control assumes intact frames and asks how many arrive per second. Error control adds timers and retransmission; see 3.5.

Three times decide everything on a link.

t_frame = L / R

t_frame is the time to push one whole frame onto the link, in seconds; L is frame length in bits; R is bit rate in bits per second.

t_prop = d / v

t_prop is one-way propagation delay in seconds; d is distance in metres; v is signal speed, about 2 × 10⁸ m/s in copper or fibre.

a = t_prop / t_frame

a is propagation delay divided by frame time, a pure number. Large a means a long or fast link where the sender waits long for each acknowledgement.

R × t_prop, in bits, is the bandwidth-delay product: bits in flight at one instant. A 100 kbps link with 20 ms one-way delay holds 100 000 × 0.020 = 2000 bits, two 1000-bit frames.

Stop-and-wait: one frame at a time

The rule is simple: send one frame, wait for its acknowledgement, then send the next.

  1. The sender builds a frame and stamps it with sequence number 0.
  2. It transmits the frame and starts a timer.
  3. The receiver checks the frame, accepts it, and sends back ACK 0.
  4. The sender receives ACK 0, discards its copy, and sends frame 1 with sequence number 1.
  5. If the timer runs out before the ACK arrives, the sender retransmits the same frame.

One bit of sequence number is enough — 0, 1, 0, 1 — because only one frame can be unacknowledged at a time.

U = t_frame / (t_frame + 2t_prop) = 1 / (1 + 2a)

U is utilisation, the fraction of time the sender transmits bits; t_frame is frame transmission time in seconds; t_prop is one-way propagation delay in seconds; a = t_prop / t_frame. The 2t_prop is one round trip spent idle.

When a is small — short link, long frame — the sender is busy almost all the time. When a is large — satellite hop, fast LAN over long cable — the sender waits most of its life for an acknowledgement. The wasted time is a full round trip carrying nothing.

Sliding window: keeping W frames in flight

The fix is several unacknowledged frames at once. The sender keeps a window of size W_s. Frames from the oldest unacknowledged frame up to W_s frames ahead may be sent without waiting. An acknowledgement that covers one new frame slides the window forward by one; a cumulative ACK n, which says every frame up to n has arrived, slides it forward past all of them at once.

Sequence numbers travel in a k-bit header field, so they run from 0 to 2k − 1 and wrap. A number may not be reused while an old frame carrying it could still be in the network, so W_s must stay strictly below 2k. The receiver also has a window, W_r, saying how many out-of-order frames it will hold.

U = min(1, W / (1 + 2a))

U is utilisation; W is the sender window in frames, not bits; a = t_prop / t_frame; min(1, …) caps the answer because the sender cannot transmit more than all the time.

Read the formula as a budget: W frames of transmission fit into one cycle of 1 + 2a frame times. Once W reaches 1 + 2a, the ACK for the oldest frame arrives exactly as the window runs out, the pipe never empties, and U = 1.

Piggybacking: when data flows both ways, the acknowledgement rides inside a reverse data frame, saving one frame of overhead per round trip.

With W = 1 the sliding window is exactly stop-and-wait, so the two schemes are one idea at two settings. Adding timers and retransmission gives the ARQ protocols of 3.5; TCP's own window is in Unit 5.

  7. W = 5: U = 5 / 5 = 1, capped at 1, so full use.

Answer. t_frame = 10 ms, a = 2, stop-and-wait utilisation 0.20; minimum window for full use 5 frames; U = 0.60 at W = 3 and U = 1 at W = 5; bandwidth-delay product 2000 bits.

Exam traps

  • a uses one-way delay, but the 2 in 1 + 2a is the round trip. Putting the round-trip delay into a doubles a, so the 2a term becomes four times t_prop/t_frame. With a = 2 the denominator goes from 5 to 9 and U drops from 0.20 to 0.11 — wrong, though not by a factor of two.
  • W is a count of frames, never bits. Mixing a window in bits with t_frame in seconds is the commonest unit slip.
  • U is capped at 1. A window of 10 with a = 1 gives U = 1, not 3.33. Examiners set this on purpose.
  • Do not write W = 2k. The window must be less than the number of sequence numbers, so a k-bit field needs W ≤ 2k − 1.
  • Stop-and-wait alternates sequence numbers 0 and 1; it does not send a constant 0. A receiver that always sees 0 cannot tell a retransmission from a fresh frame.

3.5 ARQ error control: Go-Back-N and Selective Repeat

A frame can be damaged or lost, and error detection only tells the receiver that something is wrong. ARQ (automatic repeat request) closes the loop: the sender keeps a copy, starts a timer, and waits for an acknowledgement before it trusts the frame. Adding this to the sliding window turns a link that drops frames into one that delivers every frame, in order, exactly once. Go-Back-N and Selective Repeat are the two standard ways to do it, and both sit inside TCP (Unit 5) and inside every data link protocol that retransmits.

You need: 3.4 for windows and sequence numbers, and 3.2 for how the receiver notices a damaged frame.

Stop-and-wait ARQ and the duplicate frame

ARQ means automatic repeat request: turn a detected error into a retransmission. It adds two things to a frame — a sequence number and a timer. A damaged frame is dropped silently and sent again; a frame not acknowledged in time is also sent again.

The simplest form is stop-and-wait ARQ. The sender transmits one frame, starts a timer, and waits. A correct ACK stops the timer and releases the next frame. A bad frame or an expired timer means: send it again.

One bit of sequence number, 0 and 1 alternating, is enough, because only one frame is ever in flight. That bit kills duplicates. Frame 0 arrives safely and the receiver replies ACK 1, but the ACK is lost. The sender's timer fires and it sends frame 0 again. The receiver sees sequence number 0, knows it already delivered that frame, discards it as a duplicate, and repeats ACK 1. Without the number, the same data would be handed up twice.

Stop-and-wait wastes the link. After every frame the sender sits idle for one round trip, 2Tp.

Go-Back-N: one timer, cumulative ACKs

Pipelining lets the sender keep W frames in flight, the sliding window of 3.4, with ARQ layered on top. The simpler pipelined ARQ is Go-Back-N.

The receiver window is exactly 1. It accepts only the frame it is expecting, in order. A frame that arrives early — because an earlier one was lost — is discarded, not buffered, and the receiver repeats the ACK of the last frame it accepted in order.

Acknowledgements are cumulative. ACK n means: every frame up to n − 1 is safe, and I am now expecting frame n. One ACK can therefore cover several frames.

The sender keeps a single timer, for the oldest unacknowledged frame. When it expires, the sender resends that frame and every frame after it. That is the N it goes back to, and it is the price of a one-frame receiver: one loss costs a whole window of retransmissions.

With a k-bit sequence number the sender window must be at most 2k − 1. One number is deliberately held back so a new frame can never carry the same number as an old frame still in flight.

E = W ÷ (1 + 2a) while W ≤ 1 + 2a, and E = 1 beyond that

E is the fraction of the link's capacity actually used; W is the sender window in frames; a = Tp / Tt, with Tp the one-way propagation delay and Tt the transmission time of one frame.

Selective Repeat: buffer and resend one frame

Selective Repeat removes the waste. The receiver has a window as large as the sender's and buffers frames that arrive out of order. It sends a NAK (negative acknowledgement) naming the missing frame, and delivers data as soon as the gap fills. The sender keeps a separate timer per unacknowledged frame and resends only the one whose timer fires.

The window must be halved: with a k-bit sequence number, W ≤ 2k−1. The sequence space holds 2k distinct numbers, and at some instant the receiver may still be waiting for frames of the previous window while the sender has moved into the next. The two windows together need 2W distinct numbers, so 2W ≤ 2k, giving W ≤ 2k−1. This bound is exact, not conservative.

The cost moves to the receiver: a buffer of W frames and reordering before delivery.

Worked example

Question. A data link uses a 3-bit sequence number. The sender has seven frames, numbered 0 to 6, ready to send, and frame 2 is damaged in transit. Trace the exchange and count total frame transmissions for (a) Go-Back-N and (b) Selective Repeat.

  1. k = 3 gives 23 = 8 sequence numbers, 0 to 7.
  2. Go-Back-N sender window = 2k − 1 = 7. All seven frames fit in one window, so the sender transmits 0, 1, 2, 3, 4, 5, 6: 7 transmissions.
  3. Frame 2 is damaged and discarded. Frames 0 and 1 were accepted in order, so the receiver sends ACK 2, meaning it expects frame 2.
  4. Frames 3, 4, 5, 6 arrive early. The receiver has no buffer, so each is discarded and draws another ACK 2: 4 more ACKs, all saying ACK 2.
  5. The sender's single timer, running for frame 2, expires. It resends frames 2, 3, 4, 5, 6 — 5 retransmissions. These arrive in order and draw ACK 3, ACK 4, ACK 5, ACK 6, ACK 7.
  6. Go-Back-N total = 7 + 5 = 12 frame transmissions to deliver 7 useful frames.
  7. Selective Repeat window = 2k−1 = 22 = 4. The sender sends 0, 1, 2, 3. ACKs for 0 and 1 slide the window, so it sends 4 and 5; the window base is still frame 2, so frame 6 must wait.
  8. Frame 2 is damaged and discarded, which to the sender looks the same as a loss. The receiver buffers 3, 4 and 5 — all inside its window 2 to 5 — and sends NAK 2. The NAK 2 (or, if the NAK itself is lost, the timer for frame 2) makes the sender resend frame 2 alone: 1 retransmission.
  9. The receiver now delivers 2, 3, 4, 5 in order and acknowledges them, the window slides, and frame 6 is sent. New frames = 7, resent = 1.
  10. Selective Repeat total = 7 + 1 = 8 frame transmissions. Saving = 12 − 8 = 4, at the cost of a 4-frame buffer and reordering at the receiver, and one timer per unacknowledged frame at the sender.

Answer. Go-Back-N needs 12 frame transmissions (7 new + 5 resent) while Selective Repeat needs 8 (7 new + 1 resent), a saving of 4 transmissions for the same 7 delivered frames.

Exam traps

  • Using 2k as the Go-Back-N sender window, or 2k instead of 2k−1 for Selective Repeat. Both make the protocol fail: an old frame gets mistaken for a new one.
  • Reading ACK n as 'frame n arrived'. It means frames up to n − 1 are safe and frame n is expected. Examiners ask this in almost every paper.
  • Forgetting that the Go-Back-N receiver has a window of 1. Out-of-order frames are discarded there, not buffered, so they are never delivered later.
  • Counting one retransmission for a Go-Back-N loss. It resends the lost frame and everything after it, so a loss near the start of the window costs W retransmissions.
  • Mixing up NAK with ACK. A NAK names a frame the receiver has not got; a cumulative ACK names the next frame it wants.

3.6 Data link protocols: HDLC and PPP

A frame format alone does not make a working link. You also need to know who may send, how frames are numbered, how the link is opened, and how it is closed. A data link protocol is the package that supplies all of this on top of framing and the FCS. HDLC is the bit-oriented template that fixes stations, transfer modes and three frame types. PPP is the leaner point-to-point protocol that carries IP over serial, DSL and fibre links, keeping the frame simple and pushing setup into small helper protocols. Both open and close every frame with the same flag, 01111110.

You need: 3.1 for framing and bit stuffing, 3.2 for the FCS, and 3.4 and 3.5 for the control field.

HDLC: stations, configurations and transfer modes

HDLC (High-level Data Link Control) is a bit-oriented protocol: it reads the frame as a stream of bits, not as characters, so it runs over any line. It bundles four jobs into one standard — frame format, frame numbering, error control by retransmission, and link management, meaning starting and stopping the link.

Three station types share the link:

  • Primary: sends commands, owns the link, is responsible for error recovery.
  • Secondary: sends responses and acts only on commands.
  • Combined: can take either role.

Two configurations are built from these stations. In an unbalanced configuration there is one primary and one or more secondaries — the classic multi-drop line with a host polling terminals. In a balanced configuration two combined stations face each other as equals, which is exactly what a link between two routers looks like.

Three transfer modes decide who may transmit when. NRM (normal response mode) makes a secondary transmit only after the primary polls it. ARM (asynchronous response mode) lets a secondary send without a poll, though the primary still runs the link. ABM (asynchronous balanced mode) gives two combined stations the right to send whenever they have a frame, and it is the mode used in practice.

The HDLC frame and its three frame types

The frame has six fields, all of fixed size except the payload:

  • Flag, 8 bits, 01111110, opens and closes the frame.
  • Address, 8 bits, names the secondary station for which the frame is meant.
  • Control, 8 bits normally, 16 bits when extended sequence numbers are used.
  • Information, any length, holds the network-layer packet.
  • FCS, 16 or 32 bits, a CRC over everything after the first flag.
  • Flag, 8 bits, the same 01111110 again.

Bit stuffing runs on the address, control, information and FCS fields (see 3.1): the sender inserts a 0 after every five 1s in a row, and the receiver deletes it. The flags themselves are never stuffed. A frame with no information field is 8 + 8 + 8 + 16 + 8 = 48 bits when the FCS is 16 bits.

The control field has three shapes. Bit 0 is 0 for an I-frame, 1 for both S-frames and U-frames; bit 1 is 0 for an S-frame and 1 for a U-frame.

  • I-frame (bit 0 = 0): carries data plus N(S), its own send sequence number, and N(R), the number it expects next, which is a piggybacked acknowledgement (see 3.4).
  • S-frame (bit 0 = 1, bit 1 = 0): pure control carrying N(R) — RR (receive ready, window open), RNR (receive not ready, stop sending), REJ (reject, go back), SREJ (selective reject, resend one frame).
  • U-frame (bit 0 = 1, bit 1 = 1): sets up and tears down the link — SNRM and SABM to connect, DISC to disconnect, UA and FRMR as replies.

N(S) and N(R) are 3 bits each in the basic format, counted modulo 8, so at most 7 frames may be outstanding at a time.

PPP: a simple frame with helper protocols

PPP (Point-to-Point Protocol) is the leaner relative. It assumes exactly two ends, so it drops numbering and retransmission and keeps only what a serial line needs: framing, error detection, option negotiation, and the ability to carry many network protocols.

  • Flag 01111110 (0x7E), address 0xFF, control 0x03: a fixed three-byte header.
  • Protocol, 2 bytes, saying what is inside — 0x0021 means IPv4.
  • Payload, up to the MTU, 1500 bytes by default.
  • FCS, 2 or 4 bytes, then the closing flag 0x7E.

On asynchronous links PPP stuffs bytes, not bits, because such a line carries whole characters. The sender sends 0x7D first, then the byte XOR 0x20. The receiver reverses this whenever it sees 0x7D.

Authentication, if used, comes next: PAP sends a plain password in two messages, while CHAP sends a challenge, reads a hashed reply and confirms, and repeats this during the session. Worked example

Question. A PPP sender on an asynchronous serial line must carry the 4-byte payload 7E 8A 7D 11 (all values in hex) inside a frame. Apply byte stuffing. Give the exact byte sequence placed on the line, the number of escape bytes added, and the stuffing overhead ratio (line bytes ÷ payload bytes).

  1. List the payload bytes with their decimal values: 0x7E = 126, 0x8A = 138, 0x7D = 125, 0x11 = 17. Payload length = 4 bytes.
  2. Byte 1 is 0x7E, the flag value. Escape it: send 0x7D, then 0x7E XOR 0x20 = 0x5E. Escape count = 1.
  3. Byte 2 is 0x8A = 138. It is ≥ 0x20 and is neither 0x7E nor 0x7D, so it is sent unchanged as 8A. Escape count stays 1.
  4. Byte 3 is 0x7D, the escape byte itself. Escape it: send 0x7D, then 0x7D XOR 0x20 = 0x5D. Escape count = 2.
  5. Byte 4 is 0x11 = 17, which is below 0x20. Escape it: send 0x7D, then 0x11 XOR 0x20 = 0x31. Escape count = 3.
  6. Line sequence: 7D 5E 8A 7D 5D 7D 31. Line length = 2 + 1 + 2 + 2 = 7 bytes.
  7. Overhead ratio = 7 ÷ 4 = 1.75, so 3 extra bytes were added for 4 payload bytes.

Exam traps

  • PPP detects errors but never corrects them: no sequence numbers, no acknowledgements, no flow control. Any option saying 'PPP retransmits the bad frame' is wrong.
  • REJ asks for Go-Back-N — the rejected frame and everything after it. SREJ asks for exactly one frame. Swapping the two is the most common slip; see 3.5.
  • Byte stuffing belongs to PPP on asynchronous links; bit stuffing belongs to HDLC and to synchronous PPP. A question that mentions a serial line and the byte 0x7E wants 7D 5E.
  • The escape byte escapes itself as 7D 5D, not 7D 5E. 5E is 0x7E XOR 0x20 and 5D is 0x7D XOR 0x20.
  • ABM is what examiners mean by normal operation between two equal stations. NRM applies only to an unbalanced link where a primary polls its secondaries.

3.7 Multiple access protocols: ALOHA, CSMA/CD, CSMA/CA

A shared link needs one rule at every instant: who may transmit now? A medium access protocol is that rule. Stations compete, take turns, or own a slice in advance. The competing family — ALOHA, CSMA, CSMA/CD and CSMA/CA — is what most syllabi mean by multiple access protocols. CSMA/CD shaped shared-cable Ethernet; CSMA/CA runs on Wi-Fi. Switched full-duplex Ethernet no longer needs CSMA/CD. This chapter gives the throughput formulas, collision rules and timings.

You need 3.1 for the frame, and propagation delay and bit rate from Unit 2.

Three families, then ALOHA

Two stations that start together send overlapping signals. The receiver hears noise and both frames are lost. A medium access protocol decides who talks, and how to recover from a clash.

  • Random access: stations compete. Anyone may send when the channel looks free; the protocol says how to back off after a clash. ALOHA, CSMA, CSMA/CD and CSMA/CA are here.
  • Controlled access: stations take turns. Polling has a master ask each station in turn; token passing circulates a token frame and only its holder may send.
  • Channelisation: the channel is split in advance: one frequency per station (FDMA), one time slot (TDMA), or one code (CDMA). See Unit 2.

Pure ALOHA is the simplest random rule. A station with a frame sends at once, without sensing, then waits for an acknowledgement. If none arrives it waits a random time and retries.

The weakness is the vulnerable time. Let a frame last T seconds. Another frame ruins ours if it starts from T before our first bit to T after it, a window of 2T.

S = G × e−2G

S is throughput as a fraction of channel capacity, G is offered load in frames per frame time, and e = 2.718. S peaks at G = 0.5 with S = 0.184, so about 82 percent is wasted.

Slotted ALOHA and CSMA

Slotted ALOHA cuts the window in half. Time is divided into slots of one frame time T, and a frame may start only at a slot boundary. Frames collide only if they begin in the same slot, so the window is T; G is per slot.

S = G × e−G

S and G are as before. The maximum is 0.368 at G = 1, twice pure ALOHA.

CSMA adds one habit: listen before you talk. A station senses the channel; if it hears a carrier it waits, if idle it transmits. This removes most collisions, not all.

The leftover danger is propagation delay. Suppose A starts at time 0. Its signal needs τ seconds to reach B. If B senses at τ − ε the channel is still silent, B starts too, and frames overlap. The danger window shrinks from a frame time to one propagation delay τ.

  • 1-persistent: sense; if busy keep sensing; the moment it is idle send with probability 1. Greedy, so collisions are likely when many wait.
  • Non-persistent: if busy, wait a random time and sense again. Fewer collisions, longer delays.
  • p-persistent: on an idle slotted channel, send with probability p and defer with probability 1 − p. A compromise.

CSMA/CD and CSMA/CA

CSMA/CD adds collision detection for a half-duplex cable. While sending, the station listens and compares what it hears with what it sends. When they differ, a collision is in progress. It sends a short jam signal so others notice too, then stops and backs off.

  1. Sense the channel. If busy, wait and sense again.
  2. If idle, start transmitting and keep monitoring the cable.
  3. If the received signal differs from the transmitted signal, a collision has occurred.
  4. Send a short jam signal, then stop transmitting.
  5. Wait k slot times, then retry from step 1.
slot time = 2τ,   minimum frame = 2τ × bit rate

τ is one-way propagation delay in seconds, so 2τ is the round trip. The minimum frame guarantees the sender is still transmitting when the collision signal returns; a shorter frame is padded, otherwise the sender would finish early and never learn of the collision.

Backoff is binary exponential. After the i-th collision the station picks k uniformly from {0, 1, …, 2i − 1} and waits k slot times. Early collisions give short waits; repeated collisions spread stations apart. The exponent is capped, and after too many failures the frame is dropped and reported.

CSMA/CA avoids collisions instead of detecting them. A radio cannot listen while it transmits and has hidden terminals. A station waits until the channel is idle, waits an interframe gap, then runs a random backoff counter that decreases only while the channel is silent. The receiver acknowledges every frame, so a lost frame is detected by a missing ACK. Optional RTS/CTS frames reserve the medium. Details are in 3.9.

  1. For the i-th collision the set of slots is {0, 1, …, 2i − 1}.
  2. Here i = 3, so 23 = 8 and k is uniform in {0, 1, 2, 3, 4, 5, 6, 7}.
  3. The longest wait is k = 7 slots.
  4. Time = 7 × 51.2 μs = 358.4 μs.

Answer. It waits k slot times with k uniform in {0, …, 7}, and the longest wait is 358.4 μs.

Exam traps

  • Pure ALOHA uses e−2G and slotted ALOHA uses e−G. Swapping the exponents is the commonest slip in the chapter.
  • CSMA/CA has no collision detection and no jam signal. A radio cannot hear a collision while its transmitter is on, so 802.11 avoids clashes and ACKs every frame instead.
  • In the minimum-frame calculation, use round trip 2τ, not τ, and divide bits by 8 for bytes. At 10 Mbps and 2τ = 51.2 μs the answer is 512 bits = 64 bytes.
  • The backoff set after the i-th collision has 2i slots numbered 0 to 2i − 1, so the range is not 2 × i and not 1 to 2i. The count doubles per collision but stays capped.
  • G is offered load in frames per frame time, not a success probability. At G = 1 a slotted ALOHA channel carries only 0.368 frames per frame time; the rest collide.

3.8 Ethernet and virtual LANs (VLANs)

Ethernet is the wired LAN standard: IEEE 802.3 fixes one frame format and one 48-bit address scheme, so any two Ethernet cards can talk. A switch forwards frames using those addresses and learns the LAN layout by itself. A VLAN splits one physical switch into several separate LANs, so two departments share hardware without sharing broadcasts.

You need 3.1 for what a frame is, and 3.7 for CSMA/CD on a shared cable.

The IEEE 802.3 frame

IEEE 802.3 fixes the frame fields and their order, so any two cards can exchange data.

Hardware adds and strips the preamble and SFD, so they are never counted as part of the frame. That is why the size rules start at the destination address.

frame size = 6 + 6 + 2 + payload + 4 bytes, with 46 ≤ payload ≤ 1500

6 is the destination MAC address, 6 the source MAC, 2 the type/length field, payload the data in bytes, and 4 the FCS (frame check sequence, a CRC-32 — see 3.2). The smallest frame is 64 bytes and the largest is 1518 bytes.

Why 64 bytes? On a shared 10 Mbps cable with CSMA/CD a sender must still be transmitting when a collision signal returns. The worst-case round trip was fixed at 512 bit times, so the frame must last at least 512 bits = 64 bytes. A payload shorter than 46 bytes is padded to 46. If the 2-byte field is a length, the receiver uses it to find where real data ends. If it is a type, the MAC cannot tell and the padding goes upward; the upper layer drops it, for example IPv4 uses its own Total Length field.

A value of 1536 (0x0600) or more is a type, such as 0x0800 for IPv4. A value up to 1500 is a length. The 1500 limit is the MTU that IP must respect.

MAC addresses and Ethernet names

A MAC address is 48 bits, written as six hex bytes such as 00:1A:2B:3C:4D:5E. The first three bytes are the OUI (organizationally unique identifier), bought from IEEE; the last three are assigned by that vendor.

  • The low bit of the first byte is the I/G bit: 0 is unicast, one specific card; 1 is multicast, a group of cards.
  • FF:FF:FF:FF:FF:FF is broadcast: every station on the LAN accepts it.
  • Old names read rate, signalling, medium: 10Base5 = 10 Mbps baseband, 500 m on thick coax; 10BaseT = 10 Mbps over twisted pair; 100BaseFX = 100 Mbps over fibre.

Switches and full-duplex Ethernet

A hub repeats every bit out of every other port, so all ports form one collision domain and CSMA/CD is needed. A switch stores a frame and sends it out of one chosen port, so each port is its own collision domain. With full duplex — separate transmit and receive pairs — there are no collisions, CSMA/CD is switched off, and both ends may send at once.

The switch builds its forwarding table from the traffic it sees:

  1. Read the source MAC and store it against the incoming port, with a timestamp.
  2. Look up the destination MAC.
  3. Different port: forward out of that port only.
  4. Same port it came from: drop it.
  5. Not in the table: flood out of every port except the incoming one.
  6. Age out quiet entries after a few minutes, so a station that moves is relearned.

Store-and-forward switches wait for the whole frame and check the FCS before forwarding. Cut-through switches start forwarding after the destination address: faster, but they pass on damaged frames.

Virtual LANs

A 24-port switch is one broadcast domain: a broadcast from port 1 goes out of all 23 others. A VLAN splits it. Put ports 1 to 12 in VLAN 10 and 13 to 24 in VLAN 20, and the switch keeps two forwarding tables and two broadcast domains. A broadcast from port 1 now reaches only ports 2 to 12.

To carry many VLANs over one inter-switch link, each frame gets an 802.1Q tag: 4 bytes inserted between the source MAC address and the type/length field. The first 2 bytes are the tag protocol identifier 0x8100. The next 2 hold a 3-bit priority, a 1-bit drop-eligible flag and the 12-bit VLAN ID. Twelve bits give 4096 values; 0 and 4095 are reserved, so 1 to 4094 are usable.

tagged frame = 6 + 6 + 4 + 2 + payload + 4 bytes

the extra 4 is the 802.1Q tag. The maximum frame becomes 1522 bytes and the minimum 68 bytes. The switch counts the tag; a device on an access port never sees it.

An access port belongs to exactly one VLAN and sends untagged frames to the attached PC. A trunk port carries many VLANs, each frame tagged. VLANs are separate broadcast domains and normally separate IP subnets, so the switch alone cannot move traffic between them. A router or layer-3 switch with one interface per VLAN must forward; the usual trick is one trunk to a router, called router-on-a-stick.

Worked example

Question. An IP packet of 1500 bytes is sent in one Ethernet frame. (a) Give the frame size without the preamble. (b) How many bytes does the wire carry including preamble and SFD? (c) A different frame carries a 10-byte payload; what is its final frame size? (d) What is the frame size of the full 1500-byte packet once an 802.1Q VLAN tag is added?

  1. Header and trailer without the preamble: 6 + 6 + 2 + 4 = 18 bytes.
  2. (a) Frame = 18 + 1500 = 1518 bytes, the maximum, so no padding.
  3. (b) Wire adds the 7-byte preamble and 1-byte SFD: 1518 + 7 + 1 = 1526 bytes. These 8 bytes are not part of the frame and are outside the 64-byte rule and the FCS.
  4. (c) Payload 10 is below the 46-byte floor, so 36 padding bytes are added. Frame = 6 + 6 + 2 + 46 + 4 = 64 bytes, exactly the minimum.
  5. (d) The tag adds 4 bytes: 1518 + 4 = 1522 bytes, the maximum tagged frame. On the wire it is 1522 + 8 = 1530 bytes.

Answer. The full frame is 1518 bytes (1526 on the wire), the padded short frame is 64 bytes, and with a VLAN tag the full frame is 1522 bytes.

Exam traps

  • The preamble (7 bytes) and SFD (1 byte) are not part of the frame. The 64-byte minimum and the FCS exclude them, so a 64-byte frame is 72 bytes on the wire.
  • A VLAN tag changes both ends of the size range: the maximum becomes 1522 bytes and the minimum 68 bytes.
  • The FCS is outside the 46-to-1500 payload range. 1500 is the payload limit, 1518 the frame limit.
  • The 2-byte field is type or length, never both: 1536 (0x0600) and above are types, up to 1500 are lengths.
  • The I/G bit is the low bit of the first byte, which is sent first, not the high bit. Reading it as the high bit turns a unicast address into a false multicast.

3.9 Wireless LANs: IEEE 802.11 architecture and MAC

A wireless station cannot hear collisions while it transmits, and two stations that cannot hear each other may still collide at the access point. IEEE 802.11 therefore uses carrier sense multiple access with collision avoidance (CSMA/CA): sense the radio channel, wait a fixed gap, back off a random number of slots, then send and demand an acknowledgement. Optional RTS/CTS frames reserve the channel and silence hidden stations. This is the MAC of Wi-Fi in homes, offices and campuses.

You need: 3.7 for CSMA/CA basics and 3.8 for the wired LAN it replaces.

Cells and infrastructure

An 802.11 network is built from a basic service set (BSS): one access point (AP) plus the stations that associate with it. The AP is the bridge between the radio cell and the wired network. A station joins by association after hearing the AP's beacon frames. The network name carried in management frames is the SSID, a text string such as HomeWiFi. In infrastructure mode all traffic goes through the AP, even station-to-station traffic in the same cell.

An independent BSS (IBSS) has no AP; stations talk directly. This is ad-hoc mode, used for a quick link between two laptops. A single BSS covers one radio range, typically tens of metres indoors.

An extended service set (ESS) joins several BSSs through a distribution system (DS), usually a wired Ethernet backbone. All APs in one ESS share the SSID, so a laptop can move from one cell to another; roaming is the station re-associating with a stronger AP, handled below the IP layer.

DCF: the mandatory access method

802.11 defines two coordination functions. Distributed coordination function (DCF) is mandatory and is plain CSMA/CA. Point coordination function (PCF) is an optional polled mode; most products do not use it.

  1. Sense the medium. If it is idle for DIFS (DCF interframe space), go to step 3.
  2. If it is busy, wait until it becomes idle, then wait DIFS again.
  3. Choose a random backoff integer from 0 to CW, where CW is the contention window, counted in slots. Freeze the counter while the medium is busy; resume when the medium is idle for DIFS.
  4. When the counter reaches 0, transmit one frame.
  5. The receiver waits SIFS (short interframe space) and returns an ACK.

Interframe spaces are priorities: SIFS < PIFS < DIFS. Typical 802.11b values are SIFS = 10 μs, one slot = 20 μs, DIFS = 50 μs. Because SIFS is shorter than DIFS, the receiver's ACK starts before any other station is allowed to contend.

An ACK is required because a radio cannot listen while transmitting; CSMA/CD's collision detection is impossible. A missing ACK triggers retransmission.

Hidden terminals, NAV and frames

Hidden terminal: A and C both hear the AP but not each other. Both sense idle, both send, and collide at the AP. Virtual carrier sensing fixes this. A frame carries a duration field. Any station that hears it sets its network allocation vector (NAV) to that duration and stays quiet, even if its own radio senses idle.

RTS/CTS four-way handshake: the sender sends Request to Send (RTS), the AP replies Clear to Send (CTS), then DATA, then ACK. Both RTS and CTS carry a duration covering the rest of the exchange. A station that hears the CTS knows the channel is reserved. RTS/CTS costs overhead, so it is used only for large frames or when hidden nodes are suspected. It removes the hidden-terminal collision, not every collision.

An 802.11 data frame has frame control (type, subtype, flags), duration, address 1, address 2, address 3, sequence control, frame body (payload) and FCS. In the common infrastructure case the three addresses are: address 1 = immediate receiver (the AP for an uplink frame), address 2 = transmitter (the station), address 3 = the eventual destination or the source. A fourth address appears only in a wireless distribution system.

Physical layers are named only here. The original 802.11 used DSSS at 1–2 Mbps in 2.4 GHz. 802.11b uses DSSS/CCK at up to 11 Mbps in 2.4 GHz; 802.11a uses OFDM at up to 54 Mbps in 5 GHz; 802.11g uses OFDM at up to 54 Mbps in 2.4 GHz.

Worked example

Question. A station has a 1000-byte frame ready and the medium is idle. SIFS = 10 μs, DIFS = 50 μs, one backoff slot = 20 μs, and the station draws a backoff of 5 slots. The PHY rate is 11 Mbps. Find the wait before transmission, the frame transmission time, and the time from the medium going idle until the ACK starts. Ignore ACK transmission time and preamble.

  1. Payload bits = 1000 bytes × 8 = 8000 bits.
  2. Wait = DIFS + 5 slots × 20 μs = 50 μs + 100 μs = 150 μs.
  3. Frame time = 8000 bits ÷ 11,000,000 bit/s = 0.00072727 s = 727.27 μs.
  4. ACK starts one SIFS after the frame ends: total = 150 μs + 727.27 μs + 10 μs = 887.27 μs.

Answer. The station waits 150 μs, the frame takes 727.27 μs, and the ACK starts 887.27 μs after the medium went idle.

Exam traps

  • Radio cannot hear collisions while sending, so 802.11 needs ACKs; Ethernet CSMA/CD does not.
  • A busy medium freezes the backoff counter; it does not reset it.
  • SIFS is shorter than DIFS so the ACK wins; do not swap the two.
  • RTS/CTS removes the hidden-terminal collision, not every collision.
  • Address 1 is the immediate receiver, not necessarily the final destination.

Takeaways

  1. A frame must carry its own start and end markers, and bit stuffing is what makes those markers unambiguous.
  2. Every detection scheme trades redundancy for certainty: parity catches odd numbers of errors, checksums catch most random errors cheaply, and CRC catches burst errors with a polynomial remainder.
  3. Hamming codes turn redundancy into repair, not just alarm, because well-placed check bits spell out the position of a single flipped bit.
  4. Flow control protects the receiver's buffer; a sliding window lets the sender keep the link full while still staying inside that buffer.
  5. ARQ adds a timer and acknowledgements, so Go-Back-N trades bandwidth for simple receiver logic while Selective Repeat trades receiver memory for bandwidth.
  6. HDLC shows the bit-oriented shape of a link protocol and PPP shows the byte-oriented shape; PPP skips error control and leaves reliability to higher layers.
  7. When many stations share one medium, the MAC rule decides who talks: ALOHA talks at will, CSMA listens first, and CSMA/CD both listens and detects collisions.
  8. Ethernet fixes the frame format and addressing for wired LANs, and VLANs let one switch carry many separate broadcast domains.
  9. Radio makes carrier sense unreliable, so 802.11 uses CSMA/CA with ACKs, priority gaps, backoff and optional RTS/CTS instead of collision detection.

Transmission time t_f = 1000 bits / 1 Mbps = 1 ms; Round trip = 2 × 20 ms = 40 ms; a = 40/2 = 20 relative to transmission time; Stop-and-wait utilisation = 1/(1 + 40) ≈ 2.4%; Full utilisation needs the sender busy for 41 ms per round trip, so W ≈ 41 frames; Round up to the next power-of-two-friendly value and check the sequence-number bound for the chosen ARQ scheme.

Apply A pure ALOHA system has 1000-bit frames on a 1 Mbps channel. Compute the throughput at G = 0.5 and the maximum throughput the system can reach, in frames per second. 10 marks

Frame time t_f = 1000/1 Mbps = 1 ms, so the channel offers 1000 frames per second at full load; Pure ALOHA throughput S = G·e^(−2G); at G = 0.5, e^(−1) ≈ 0.368, so S ≈ 0.184; Maximum is at G = 0.5, giving 1/(2e) ≈ 18.4% of 1000 frames per second, about 184 frames per second; Compare with slotted ALOHA, whose maximum is 1/e ≈ 36.8%, because vulnerable time halves from 2t_f to t_f; State that both figures assume Poisson arrivals and no capture effect.

Analyze and evaluate

Analyze Analyse why collision detection does not work on a radio LAN, and explain how IEEE 802.11 CSMA/CA with DIFS/SIFS and RTS/CTS makes up for it. 13 marks

A radio transmitter cannot hear a collision at its own antenna, so CSMA/CD's detection step is impossible; there is also the hidden terminal problem; Carrier sense is unreliable because of fading, distance and asymmetric links, so two stations may both think the medium is free; CSMA/CA avoids rather than detects: sense, wait DIFS if idle, take a random backoff, transmit and wait for a link-layer ACK; SIFS is shorter than DIFS, so ACKs and CTS go out before anyone else can contend; the duration field sets each station's NAV timer; RTS/CTS reserves the medium around the receiver and silences hidden terminals; binary exponential backoff spreads out stations after collisions.

Evaluate A factory wants a shared network for control traffic with hard deadlines. Compare random access, controlled access and channelisation, and recommend one with reasons. 13 marks

Random access (ALOHA, CSMA, CSMA/CD, CSMA/CA) has no central control and gives good throughput at light load, but delay is unbounded and collisions are possible at any time; Controlled access (polling, token passing) gives every station a guaranteed turn and bounded delay, at the cost of a central point or token overhead; Channelisation (FDMA, TDMA, CDMA) gives dedicated capacity with no contention, but wastes capacity when a station is idle; Hard deadlines rule out random access; token passing or a scheduled TDMA slot fits best, and a token ring or a scheduled industrial Ethernet variant is the practical choice; State the trade-off in one line: guarantees cost capacity, and random access spends capacity to buy simplicity.

Analyze Explain why Go-Back-N needs W ≤ 2^n − 1 and Selective Repeat needs W ≤ 2^(n−1). Show what goes wrong when the bound is crossed. 12 marks

n sequence bits give 2^n distinct numbers, and the receiver must never confuse a new frame with an old one that was retransmitted; In Go-Back-N the receiver accepts only in order and holds no buffer, so a window equal to 2^n makes a retransmitted frame look like the next new frame; In Selective Repeat the receiver buffers up to W frames, so W and 2^n − W must not overlap: 2W ≤ 2^n, giving W ≤ 2^(n−1); Give a small worked case, such as n = 3 with W = 8 versus W = 4, and trace the duplicate; Conclude that the bound is set by the receiver's buffer and by ACK ambiguity, and that the cost of a larger window is more sequence bits or more buffering.

Evaluate Design the link layer for a campus with three buildings: wired Ethernet between switches, an 802.1Q trunk to the core, and Wi-Fi access points on each floor. Justify the broadcast-domain and MAC choices. 13 marks

Ethernet 802.3 fixes the frame format, the 48-bit MAC address and the 64-byte minimum frame; the 4-byte FCS guards each frame; Keep one VLAN per department or per floor so broadcast traffic and ARP storms stay local; the 12-bit 802.1Q tag on the trunk keeps the domains separate over shared links; CSMA/CD governs the shared half-duplex segment; on switched full-duplex links it is effectively off, so the 5-4-3 rule matters only for legacy shared segments; Wi-Fi can not use CSMA/CD, so each AP runs CSMA/CA with its own BSS, SSID and ACKs; the AP is the bridge between the wireless and wired broadcast domains; Evaluate: VLANs give isolation and policy control at the cost of configuration and inter-VLAN routing; wireless adds contention and retransmission that wired users do not see.

Glossary

ARQ
Automatic Repeat reQuest: error control that pairs acknowledgements with a retransmission timer so lost or damaged frames are sent again.
Binary exponential backoff
Choosing a random wait of 0 to 2^n − 1 slot times after the nth collision, so contention thins out quickly.
Bit stuffing
Inserting one 0 after every five consecutive 1s in the data so the flag pattern cannot appear inside a frame.
BSS
Basic Service Set: one IEEE 802.11 cell, identified by an SSID and served by one access point.
Byte stuffing
Inserting an escape byte in front of any byte in the payload that happens to equal the flag or the escape byte.
Checksum
A ones' complement sum of 16-bit words, sent in complemented form, that the receiver re-adds to check the data.
CRC
A cyclic redundancy check, computed as the modulo-2 remainder of the data shifted left by r bits, divided by a generator polynomial of degree r.
CSMA/CA
Carrier sense multiple access with collision avoidance: sense, wait a priority gap, back off randomly, transmit, and rely on an explicit acknowledgement.
CSMA/CD
Carrier sense multiple access with collision detection: listen before sending, keep listening while sending, and stop and back off as soon as a collision is heard.
Frame
A data-link layer protocol data unit, made of a header, a payload and a trailer carrying the start and end markers.
Generator polynomial
The fixed bit pattern of degree r that both sender and receiver divide by when computing a CRC.
Go-Back-N ARQ
An ARQ scheme where the receiver discards out-of-order frames and the sender resends the missing frame and everything after it.
Hamming code
A block code with check bits at power-of-two positions, able to correct any single-bit error.
Hamming distance
The count of positions in which two codewords differ; the minimum over all pairs sets how many errors a code can detect or correct.
HDLC
A bit-oriented data link protocol with flag-delimited frames, a control field and three frame classes: information, supervisory and unnumbered.
Hidden terminal
A station that can reach the access point but not the other stations, so carrier sense does not warn it about an ongoing transmission.
NAK
A negative acknowledgement telling the sender that a specific frame arrived damaged or never arrived.
Piggybacking
Carrying the acknowledgement for the other direction inside the data frame travelling in this direction, instead of sending a separate ACK.
PPP
A byte-oriented point-to-point protocol with a fixed frame format, LCP link negotiation, per-protocol NCPs and a frame check sequence.
Pure ALOHA
A random access scheme in which a station transmits whenever it has a frame, with no sensing of the channel.
Selective Repeat ARQ
An ARQ scheme where the receiver buffers out-of-order frames and the sender resends only the frame that was lost.
Sliding window
A flow-control scheme where the sender keeps up to W unacknowledged frames in flight and advances the window as ACKs arrive.
Slotted ALOHA
Random access in which stations may transmit only at the start of a time slot, halving the vulnerable period and doubling peak throughput to 1/e.
Stop-and-wait
Flow control that sends one frame and waits for its acknowledgement before sending the next.
Two-dimensional parity
Parity computed over both the rows and the columns of a block of bits, which detects any single-bit error and locates it.
VLAN
A logical LAN created inside a switch, forming its own broadcast domain; frames on a trunk carry a 12-bit VLAN identifier.
