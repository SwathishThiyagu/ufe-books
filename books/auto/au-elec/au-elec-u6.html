6.1 Vehicle networking and need for data buses

A vehicle network lets many electronic control units (ECUs) talk over one shared medium instead of one wire per signal. A bus cuts harness weight, cost and connector count. It also makes new functions possible, because one sensor value can reach the engine, brake and dashboard computers at once. This chapter explains nodes, gateways, topologies, bandwidth, latency and determinism, and shows why a protocol must decide who talks when. The same ideas run from a cheap body bus for door switches to a high-speed bus for engine and brake control.

You need Unit 1 power distribution and harness basics, and Unit 3 sensor and actuator signal conditioning.

Nodes, ECUs and the wiring problem

A node is any device that can send or receive messages on the network. An electronic control unit (ECU) is a small computer that reads sensors and drives actuators; each ECU is a node. A gateway is a node that joins two buses and forwards selected messages between them.

In early cars, each switch, sensor and lamp had its own copper wire back to a fuse box. That bundle is the harness. Adding one feature meant adding wires, connectors and weight. A data bus replaces most of that web with one shared medium, usually a twisted pair. Every node hears the same signal, and a protocol decides who may transmit. A transceiver is the transmit and receive circuit at each node that drives the pair.

L = n(n − 1) / 2

L is the number of links for full point-to-point connection; n is the number of nodes. A bus needs one medium and n transceivers, one per node.

With three ECUs, point-to-point needs 3 × 2 / 2 = 3 links; the bus needs one medium and three transceivers. The figure shows engine, brake and door ECUs on one CAN bus, with a gateway to a slower LIN body bus. For n = 12 ECUs, full point-to-point wiring needs 66 links, so 66 twisted pairs and 132 transceiver ends. One bus needs one medium and 12 transceivers. The saving grows quickly with n.

Topologies and the electrical medium

Topology is the arrangement of nodes and links. In a bus topology, all nodes tap the same medium. In a star, each node has its own link to a central hub or switch. In a ring, nodes form a closed loop and each node connects to two neighbours. A vehicle often uses a bus inside a domain and a star-like switched backbone between domains.

The physical medium matters. A twisted pair carries the two signal wires close together, so external noise adds almost equally to both wires. The receiver reads the difference, so common-mode noise cancels. A CAN bus uses 120 Ω termination at each end of the pair. The termination absorbs reflections and keeps the differential signal clean. Missing or extra termination causes ringing and errors, not extra speed.

Fault diagnosis starts at the physical layer: open wire, short to ground, short to battery, or a node holding the bus dominant. A gateway can report which bus is faulty, but it cannot repair a broken wire. The protocol must also detect errors and stop a bad node from blocking everyone.

Bandwidth, latency, determinism and bus classes

Bandwidth is the maximum bit rate, in bit/s. Latency is the delay from a node starting a message to another node receiving it, in ms or µs. Determinism means the worst-case delay is bounded and known, not just small on average. Brake and steering messages need determinism; a door-lock message can tolerate more delay.

Some syllabi group buses into classes. Class A is body and comfort, below 10 kbit/s. Class B is low-speed data, often 10 kbit/s to 125 kbit/s. Class C is high-speed powertrain, often 125 kbit/s to 1 Mbit/s. Class D is safety and time-triggered, with strict timing. These are labels, not fixed law; always check the standard for exact rates.

One medium means shared bandwidth. If two nodes transmit together, their signals collide. The protocol must decide who talks when. CAN uses bit-wise arbitration: a dominant 0 beats a recessive 1, and the lowest identifier wins without losing data. See 6.2 for the frame details. The trade-off is simple: fewer wires, but a shared resource that needs rules.

Worked example

Question. A car has 12 ECUs. Each ECU must exchange one signal with every other ECU. Compare full point-to-point wiring with one shared bus. Find the number of links, transceiver ends, and bus transceivers.

  1. Let n = 12 ECUs.
  2. Full point-to-point links: L = n(n − 1) / 2 = 12 × 11 / 2 = 132 / 2 = 66 links.
  3. Each link has two ends, so transceiver ends = 2L = 2 × 66 = 132.
  4. One bus needs one medium and one transceiver per node: 12 transceivers.
  5. Saving in transceiver ends = 132 − 12 = 120.

Answer. Point-to-point wiring needs 66 links and 132 transceiver ends; the bus needs 12 transceivers, a saving of 120 transceiver ends.

Exam traps

  • Counting every pair twice: 12 ECUs need 66 links, not 132. A bus is one shared medium, not a star with a separate link per node.
  • Confusing bandwidth with latency and determinism: a high bit rate does not by itself guarantee a bounded worst-case delay.
  • Forgetting termination: a CAN twisted pair needs 120 Ω at each end. Missing termination causes reflections, not more bandwidth.
  • Swapping bus classes: Class A is low-rate body control, while Class C is high-speed powertrain. Do not treat the letters as order of speed without checking.

6.2 CAN and CAN FD protocols

CAN is a two-wire, multi-master broadcast bus. Every node hears every frame; there is no master and no address. A dominant 0 beats a recessive 1 on the wire, so when two nodes start together the one with the lower identifier wins arbitration and keeps transmitting. The loser stops and receives, with no data lost. Classic CAN carries 0 to 8 data bytes at up to 1 Mbit/s. CAN FD keeps the same arbitration and adds a faster data phase and up to 64 bytes, so it suits today's ECUs that exchange longer calibration and sensor packets.

You need: Chapter 6.1 for the shared-bus idea, and Unit 3 for digital signals and sensors.

Arbitration: the lowest identifier wins

CAN is broadcast and multi-master. Each node has a CAN controller and a transceiver. The bus has two wires, CAN_H and CAN_L, with 120 Ω termination at both ends. A 0 is dominant: if one node drives 0 and another drives 1, the wire reads 0. A 1 is recessive. This wired-AND behaviour is the whole trick behind arbitration.

  1. Bus idle: recessive.
  2. Nodes with a frame send SOF, a dominant 0.
  3. All nodes send identifier bits, most significant first, and listen.
  4. A node that sends 1 and reads 0 has lost.
  5. It stops transmitting, switches to receive, and the winner continues.

No data is destroyed. The winner's frame is exactly the frame that all nodes receive. The lower identifier has higher priority because a 0 at an earlier bit beats a 1. This is non-destructive arbitration. A node that loses does not retry at once; it waits for the bus to become idle and competes again. This gives predictable priority for urgent signals such as a crash sensor over a cabin temperature update.

Classic CAN frame, timing and faults

Classic CAN frame fields, left to right: SOF (1 dominant bit); arbitration field (11-bit standard identifier or 29-bit extended identifier, plus RTR and IDE); control field (DLC, 4 bits); data field (0 to 8 bytes); CRC (15 bits); ACK (2 bits); EOF (7 recessive bits). RTR marks a remote frame. IDE selects standard or extended format. DLC encodes length; for classic CAN values 9 to 15 are not used as lengths. The CRC checks the frame; after CRC, any receiver that saw a valid CRC drives ACK dominant.

Bit stuffing keeps edges for synchronisation: after five identical bits, the transmitter inserts one opposite bit. Stuffing runs from SOF through CRC. Receivers remove stuffed bits. A form, CRC or stuff error makes a node send an error frame: six dominant bits for an active error. Each node keeps a transmit error counter (TEC) and receive error counter (REC). Errors increase the counters; good frames decrease them. A node with TEC above 255 goes bus-off and stops transmitting.

Bit timing divides one bit into time quanta (tQ). The segments are sync, propagation, phase 1 and phase 2. The sample point is the end of phase 1. Classic CAN tops out at 1 Mbit/s. ISO 11898-2 is the high-speed physical layer.

SP = (1 + PROP + PHASE1) / N

SP is the sample point as a fraction of one bit; N = 1 + PROP + PHASE1 + PHASE2 is the total number of time quanta in the bit; PROP is the propagation segment in time quanta; PHASE1 and PHASE2 are the phase buffer segments.

CAN FD: same arbitration, faster data

CAN FD keeps the same arbitration and ACK scheme. It changes the frame after the identifier. FDF (FD Format) marks an FD frame. A classic controller sees a recessive bit where it expects dominant, raises a form error and sends an error frame, so the FD frame is destroyed. Classic and FD nodes therefore cannot share one bus; every controller and transceiver on the segment must support CAN FD. BRS (Bit Rate Switch) is recessive to switch to the fast data phase; the arbitration phase stays at the nominal rate. ESI (Error State Indicator) reports the sender's error state. DLC can now mean 0 to 8, 12, 16, 20, 24, 32, 48 or 64 bytes. The CRC is stronger: 17 bits for up to 16 data bytes and 21 bits for longer frames. Remote frames are dropped in CAN FD, so RTR is not used.

Typical use: nominal arbitration at 500 kbit/s or 1 Mbit/s, data phase commonly 2 to 5 Mbit/s. The faster phase shortens long calibration, software download and sensor packets. Physical layer remains ISO 11898-2 high-speed, so the same two wires and 120 Ω termination are used.

Worked example

Question. Nodes A and B start arbitration together. A uses standard identifier 0x123 and B uses 0x121. Both send data frames with 8 data bytes. Which node wins arbitration, at which identifier bit, and what are the two decimal identifiers?

  1. A: 0x123 = 291 decimal. B: 0x121 = 289 decimal.
  2. Write 11 identifier bits. A = 001 0010 0011. B = 001 0010 0001.
  3. Compare from the most significant bit. They agree until bit 1, counting bit 0 at the least significant end.
  4. At bit 1, A sends recessive 1 and B sends dominant 0.
  5. B wins arbitration. A stops transmitting and becomes a receiver. B's frame continues intact.

Answer. B wins with identifier 0x121 at bit 1; the decimal identifiers are 291 for A and 289 for B.

Exam traps

  • Lower identifier wins, not higher; dominant is 0 and recessive is 1.
  • The losing node keeps receiving the winning frame; it does not retry in the same arbitration.
  • CAN FD switches only the data phase with BRS; arbitration stays at the nominal bit rate.
  • DLC is not a plain byte count above 8 in CAN FD: 9 means 12 bytes, 10 means 16, 15 means 64.
  • Bus-off is a transmitter state after TEC exceeds 255, not a normal error frame.

6.3 LIN, FlexRay and automotive Ethernet

A car needs more than one kind of network. A door switch sends a few bits now and then; steering and damping need guaranteed timing; cameras and maps need high bandwidth. LIN is a cheap single-wire master-slave bus for body switches. FlexRay is a dual-channel time-triggered bus for x-by-wire. Automotive Ethernet is a switched high-bandwidth backbone. Each fills a niche, and they often meet through a gateway. This chapter explains how each bus works, what it costs, and where it is used.

You need: Chapter 6.1 for why buses replace point-to-point wiring, and Chapter 6.2 for CAN's arbitration and frame ideas.

LIN: one wire, one master

LIN (Local Interconnect Network) is a low-cost bus for body electronics: door switches, mirrors, wipers, seat motors and climate flaps. It uses one wire for data, with a ground return, and 12 V signal levels. One master node polls up to 15 slave nodes. The master stores a schedule table: a list of headers to send in order. A header names the slave or signal to be exchanged. The addressed slave fills the data field; other slaves listen and may use the same data. This polling makes LIN predictable without arbitration.

  1. Break: a long low pulse that wakes slaves for the frame.
  2. Sync: a fixed byte so slaves can measure bit time.
  3. Protected identifier: 6 identifier bits plus 2 parity bits.
  4. Data: 1 to 8 bytes.
  5. Checksum: covers the data; enhanced checksum also covers the identifier.

LIN runs at 1 to 20 kbit/s; 19.2 kbit/s is common. A master can put the bus to sleep with a sleep command. A wake pulse or a dominant level wakes the cluster. LIN is not multi-master: only the master starts frames. Use LIN when cost and wire count matter more than speed. For engine and chassis signals, see CAN.

FlexRay: fixed slots on two channels

FlexRay is a time-triggered bus for systems where a late message is a fault: steer-by-wire, active suspension, brake and chassis control. It has two independent channels, A and B, each at 10 Mbit/s. A node may send on both channels for redundancy, or split traffic. The bus can form a star, a bus or a hybrid, so one broken wire need not stop communication. FlexRay is deterministic: every message has a fixed slot in a repeating communication cycle.

  • Static segment: TDMA (time-division multiple access). Fixed-length slots repeat in the same order; each slot belongs to one node, with no arbitration and no collisions.
  • Dynamic segment: FTDMA (flexible TDMA). Slots are numbered; a node sends only if it has data, so short frames leave time for later slots.
  • Symbol window: carries control symbols such as startup and wakeup.
  • Network idle time: lets nodes correct clocks and compute the next cycle.

Cycle length and slot size are set at design time. The static segment is the hard real-time part; the dynamic segment handles less regular traffic. Do not call FlexRay purely event-driven: its core guarantee comes from time-triggered static slots.

Automotive Ethernet: switched and service-ready

Automotive Ethernet brings switched, high-bandwidth networking to the car. 100BASE-T1 gives 100 Mbit/s over one unshielded twisted pair; 1000BASE-T1 gives 1 Gbit/s over one pair. Office Ethernet needed four pairs, which is too heavy and costly for a car. The physical layer uses full duplex on a single pair, so there is no collision domain. Nodes connect to a switch, making a star. A switch forwards frames only to the port that needs them, so several conversations can run at once.

Ethernet is used for cameras, radar, lidar, infotainment, diagnostics and the central backbone. VLANs (virtual local area networks) tag frames so one physical switch can carry separate traffic for safety, body and infotainment. SOME/IP (Scalable service-Oriented MiddlewarE over IP) lets ECUs call services by name rather than fixed signal addresses. AVB and TSN (Time-Sensitive Networking) add time synchronisation and scheduled traffic so audio and control frames get bounded latency. 10BASE-T1S is a 10 Mbit/s single-pair standard for short zonal links that can share a multidrop segment.

Ethernet does not replace LIN or CAN everywhere. A door switch does not need 100 Mbit/s. A gateway translates between buses. Use Ethernet where bandwidth or service-style communication is needed.

Worked example

Question. A 1000-byte payload must cross the car. How long does it take on 100 Mbit/s automotive Ethernet and on a 20 kbit/s LIN bus? Ignore protocol overhead.

  1. Payload bits = 1000 bytes × 8 bits/byte = 8000 bits.
  2. Ethernet rate = 100 Mbit/s = 100 × 10⁶ bit/s.
  3. Ethernet time = 8000 bit ÷ (100 × 10⁶ bit/s) = 8 × 10⁻⁵ s = 80 µs.
  4. LIN rate = 20 kbit/s = 20 × 10³ bit/s.
  5. LIN time = 8000 bit ÷ (20 × 10³ bit/s) = 0.4 s = 400 ms.
  6. Ratio = 0.4 s ÷ 8 × 10⁻⁵ s = 5000.

Answer. The 1000-byte payload is 8000 bits; it takes 80 µs on 100 Mbit/s Ethernet and 400 ms on 20 kbit/s LIN, so Ethernet is 5000 times faster here.

Exam traps

  • LIN is not multi-master. One master polls up to 15 slaves; a slave never starts a frame on its own.
  • FlexRay's static segment is time-triggered TDMA. Do not call FlexRay purely event-driven; only the dynamic segment is flexible.
  • 100BASE-T1 and 1000BASE-T1 use one twisted pair, not the four pairs of office Ethernet. The wire count 2 means the two wires in that pair.
  • Automotive Ethernet does not make CAN or LIN obsolete. A gateway joins them; cost and determinism still decide the choice.
  • A LIN frame's protected identifier is 6 identifier bits plus 2 parity bits, not a full 8-bit ID. Do not confuse it with a CAN identifier.

6.4 On-board diagnostics: OBD-II

OBD-II, short for On-Board Diagnostics second generation, is a standard that lets one scan tool plug into almost any car made after the late 1990s and read emissions-related faults. It fixes the 16-pin connector, the electrical pins, the message services and the fault-code format. A mechanic, a fleet owner or an inspection centre uses it to find why the malfunction indicator lamp is on, to read live sensor data, and to check that the engine control unit has finished its self-tests. The same socket also gives the vehicle identification number.

You need: Chapter 6.2 for CAN frames, identifiers and the physical layer, because most OBD-II messages travel on CAN.

The 16-pin socket and its pins

OBD-II began as an emissions rule. Before it, each maker had its own connector and its own codes, so a workshop needed many adapters. The standard, often called J1962 for the connector, makes the socket shape and pin functions common. The socket sits under the dashboard near the steering column, within reach of the driver. Pins 4 and 5 are chassis and signal ground. Pin 16 is battery positive, usually through a fuse. Pins 6 and 14 are CAN high and CAN low. Pins 7 and 15 are the older K-line and L-line pair. Pins 2 and 10 carry the older J1850 bus. Other pins are left for manufacturer use or left blank.

Services and parameter identifiers

A scan tool sends a request service, and an ECU replies. A service is a one-byte command number inside a diagnostic message. Service 01 reads current data. Service 02 reads the freeze frame, a snapshot of data stored when a fault was set. Service 03 reads stored diagnostic trouble codes (DTCs). Service 04 clears codes. Service 05 reads oxygen sensor test results. Service 06 reads on-board test results. Service 09 reads the vehicle identification number (VIN). Service 0A reads permanent codes. A parameter identifier (PID) names one measured value. A reply to service 01 has service 0x41, then the PID, then data bytes A, B and so on.

RPM = ((A × 256) + B) ÷ 4

RPM is engine speed in revolutions per minute; A is the first data byte (0 to 255); B is the second data byte (0 to 255); 256 combines the two bytes into a 16-bit raw count; 4 converts the raw count to rpm because one count is 0.25 rpm.

PID 0C is engine speed. Many PIDs use one data byte, some use two, and a few use four. The scan tool must apply the scaling for that PID; the raw bytes alone are not the physical value. PID 0D, vehicle speed, uses one byte A in km/h. PID 05, coolant temperature, uses one byte A and the formula A − 40 in °C.

Fault codes, monitors and the lamp

A DTC has one letter, then four hexadecimal digits. Hexadecimal means base-16 digits 0-9 and A-F. The letter gives the system: P is powertrain, C is chassis, B is body, and U is network. In P0301, P means powertrain, the first digit 0 means a generic code defined by the standard, the second digit 3 means ignition system or misfire, and 01 means cylinder 1. A first digit 1 would mean a manufacturer-specific code. P0301 is a generic misfire code for cylinder 1.

Readiness monitors are self-tests inside the ECU, such as catalyst, oxygen sensor, evaporative emission control and misfire checks. A drive cycle is a prescribed sequence of start, warm-up, speeds and stops that lets the monitors run. The malfunction indicator lamp (MIL) is the dashboard lamp. When a fault is confirmed, the ECU stores the DTC and lights the MIL. Service 04 can clear the codes and turn the lamp off, but the fault remains if the cause is not repaired. Permanent codes in service 0A stay until the relevant self-test passes.

  • CAN runs at 500 kbit/s with 11-bit identifiers, or at 250 kbit/s with 29-bit identifiers, for OBD-II messages.
  • OBD-II is emissions-focused: generic services expose engine and emission data.
  • Manufacturer enhanced diagnostics go deeper into ABS, airbag, body and other modules.

Worked example

Question. A scan tool requests PID 0C, engine speed. The reply gives data bytes A = 0x1A and B = 0xF0. Find the engine speed in rpm.

  1. Convert A from hexadecimal: A = 0x1A = 1×16 + 10 = 26.
  2. Convert B from hexadecimal: B = 0xF0 = 15×16 + 0 = 240.
  3. Combine the two bytes: A × 256 + B = 26 × 256 + 240 = 6656 + 240 = 6896.
  4. Divide by 4 because each count is 0.25 rpm: 6896 ÷ 4 = 1724 rpm.

Answer. The engine speed is 1724 rpm.

Exam traps

  • The P in P0301 means powertrain, not petrol. C is chassis, B is body, U is network.
  • P0301 is a generic misfire code for cylinder 1. A code such as P1xxx is manufacturer-specific and needs enhanced diagnostics beyond the standard services.
  • Pins 4 and 5 are ground, and pin 16 is battery positive. Do not treat pin 16 as a signal pin.
  • Freeze frame is stored data from the moment a fault was set, not live data. Use service 02, not service 01, to read it.
  • Clearing codes with service 04 turns off the MIL but does not repair the fault; permanent codes may remain until a self-test passes.

6.5 MISRA coding and ISO 26262 functional safety

MISRA C is a coding standard that removes risky C constructs—recursion, hidden conversions, pointer arithmetic outside arrays—so embedded software behaves predictably. ISO 26262 is a functional-safety standard: it starts from a hazard, assigns an ASIL level from severity, exposure and controllability, then demands documented evidence across a safety lifecycle. Suppliers use both together: MISRA keeps the code clean, ISO 26262 proves the item is safe enough. Only a few universities teach this material in depth.

You need: Chapter 6.2 for how ECUs exchange safety-relevant frames, and Chapter 6.4 for diagnostic monitors that feed fault detection.

MISRA C: rules and deviations

MISRA C is a coding standard for C in embedded systems. MISRA C:2012 classifies each guideline as mandatory, required or advisory. A required guideline must be followed or formally deviated; a deviation is a written permit with justification and risk analysis, not a silent exception.

The rules remove risky constructs. Common rules: no recursion; no use of the dynamic memory allocation and deallocation functions (malloc, calloc, realloc, free) at all; no implicit conversion that loses a value; braces on every if and else body; no pointer arithmetic outside an array; and check every return value that reports an error. If a project needs a one-off start-up allocation, that is a documented deviation, not a MISRA rule. MISRA also limits features that are hard to analyse statically, such as macros with side effects.

A static-analysis tool checks the source. The team fixes each violation or records a deviation. Passing MISRA gives disciplined code, not proof of functional safety. Generated code must pass the same checks or the generator must be qualified.

ISO 26262: hazard to ASIL to evidence

ISO 26262:2018 is the functional-safety standard for road vehicles. It has parts 1–12 and follows a V-model: requirements, implementation, then verification. Part 3 is the concept phase; part 6 covers software.

The item definition fixes the boundary: which ECUs, sensors, actuators and functions are inside. HARA (hazard analysis and risk assessment) studies each hazardous event. It rates severity S0–S3, exposure E0–E4 and controllability C0–C3. The combination gives an ASIL: A, B, C or D, with D the highest, or QM when no safety requirement applies.

Each hazardous event produces a safety goal, such as 'no unintended full braking at speed'. The safety goal inherits the ASIL. The technical safety concept names safety mechanisms: plausibility checks, watchdog timers, redundant sensors and safe states. ASIL decomposition can split a requirement into two independent lower-ASIL requirements, but independence must be demonstrated.

The fault tolerant time interval (FTTI) is the minimum time from the occurrence of a fault to the possible occurrence of a hazardous event. The safety mechanism must detect the fault and finish the safe reaction inside that interval. Detection budget = FTTI − sensor sampling − confirmation − actuator.

Hardware metrics judge the architecture using failure rates and diagnostic coverage. SPFM = 1 − (λSPF + λRF)/λtotal, where λSPF is single-point fault rate, λRF residual fault rate, λtotal total failure rate; the diagnostic coverage of each safety mechanism is an input to these numbers. LFM judges how well latent (hidden) faults are covered. Verification includes tests, fault injection and independent assessment. MISRA supports the software part, but it does not replace HARA or metrics.

Worked example

Question. A safety goal has FTTI = 200 ms. Sensor sampling takes 20 ms, two-frame confirmation takes 40 ms, and the actuator needs 30 ms. Find the time left for fault detection.

  1. Write the budget: detection time = FTTI − sampling − confirmation − actuation.
  2. Substitute: 200 ms − 20 ms − 40 ms − 30 ms.
  3. Add the three delays: 20 + 40 + 30 = 90 ms.
  4. Subtract: 200 ms − 90 ms = 110 ms.

Answer. The detection logic has 110 ms after sampling and confirmation, so the fault must be flagged by 20 + 40 + 110 = 170 ms after it occurs; the actuator then brings the item to the safe state by 200 ms.

Exam traps

  • Passing MISRA checks proves ISO 26262 compliance — false; MISRA is coding evidence only.
  • ASIL D is the highest integrity level, not a component grade you can buy.
  • FTTI is not the same as detection time; it includes sensing, confirmation and actuation.
  • ASIL decomposition does not lower the safety goal; it splits it into independent requirements.
  • QM is not ASIL 0; it means quality management with no ASIL safety requirement.

6.6 V2X communication, connected vehicles and infotainment

V2X means Vehicle-to-Everything: a car exchanges short radio messages with other cars, roadside units, pedestrians' phones, the cloud and the grid. It exists because radar and cameras see only line of sight and cannot know intent; a V2V message can say 'I am braking' before the brake lights are visible. The same electronics unit, the telematics control unit, also feeds navigation, music and over-the-air updates into the cabin. You meet V2X in collision warnings at blind corners and in connected infotainment.

You need: Chapter 6.1 for in-car networks, Chapter 6.3 for Ethernet backbones, and Unit 5 ADAS sensors for radar, camera and LiDAR context.

V2X links and safety messages

V2X means Vehicle-to-Everything. It is a set of short radio messages between a vehicle and the world around it. The vehicle carries an on-board unit (OBU), a radio plus a small computer. A fixed roadside unit (RSU) is the infrastructure box at a junction, toll plaza or highway gantry.

The five links are: V2V, vehicle to vehicle; V2I, vehicle to infrastructure; V2P, vehicle to pedestrian, usually a phone app; V2N, vehicle to network, meaning the cellular cloud; and V2G, vehicle to grid, for an electric vehicle that charges or sends power back. V2V and V2I can work without a SIM or tower. Only V2N and cloud services need cellular coverage. Routing among moving vehicles is covered in Chapter 6.7.

A safety message carries position, speed, heading, brake status and a time stamp. From these, the receiving OBU predicts a path. Common warnings are: forward collision warning (the car ahead brakes hard); intersection movement assist (a car is about to cross your path at a blind junction); emergency vehicle warning (an ambulance is approaching); road-hazard alert (a pothole, crash or slippery patch); and green light optimal speed advisory (GLOSA), which tells the driver a speed to reach the next green light. GLOSA advises; it does not control the signal.

d = vrel × t

d is distance in metres (m); vrel is closing speed in metres per second (m/s); t is warning time in seconds (s).

At 40 m/s closing speed and 2.5 s, d = 100 m. Radio latency adds vrel × Δt, where Δt is latency in seconds; 100 ms adds 4 m.

Radio choices, TCU and cloud services

Two radio families dominate. IEEE 802.11p is a Wi-Fi-derived link in the 5.9 GHz band. It works ad hoc: an OBU sends a safety packet directly to nearby OBUs without a base station. It has no SIM and no subscription. Its stack is in Chapter 6.8. LTE-V2X is the cellular family. It defines a sidelink, a direct device-to-device radio path, so V2V can run without a tower. When coverage exists, the network can schedule resources. 5G-V2X extends this with lower latency and more capacity, but the safety idea is the same: send small, frequent, authenticated messages. 802.11p is mature and independent of cellular coverage. C-V2X can reuse cellular timing and security, and it can also use the network for V2N.

The telematics control unit (TCU) is the car's cellular gateway. It holds a modem, a GNSS receiver for position and time, and an eSIM. It connects to the in-car network through a gateway. The TCU carries V2N services: live traffic, remote diagnostics, emergency call, stolen-vehicle tracking, tolling and over-the-air (OTA) updates. OTA means the manufacturer sends new software or calibration over the cellular link, so the car need not visit a workshop. A toll plaza may read a tag over DSRC or RFID; the money message goes to the toll backend. The TCU is not the same as the safety OBU, though some cars combine both in one box. A gateway keeps infotainment traffic away from safety-critical CAN or Ethernet domains.

Infotainment, security and connected autonomy

The head unit is the cabin computer behind the dashboard screen. It plays audio and video, runs navigation with live traffic, and projects a phone through Android Auto or Apple CarPlay. Smartphone projection places the phone's apps on the car screen, so the head unit supplies the display, touch and audio while the phone does the computing. Navigation uses GNSS plus map data; the TCU adds traffic and charging-station updates. A head-up display (HUD) may show speed, a turn arrow or a warning on the windscreen. Some syllabi list HUD here; its optics and combiner belong to Unit 2.

The connected cabin widens the attack surface. Attack points include the cellular link, Wi-Fi, Bluetooth, USB ports, the OTA server and the diagnostic connector. A malicious message could fake a brake warning or unlock a door. Message authentication is the main defence for V2X: each safety packet carries a signature and a certificate, so a receiver can check that the sender is a real OBU and that the packet was not altered. Authentication proves origin and integrity; it does not by itself hide the content, and it needs a public-key infrastructure (PKI) to issue and revoke certificates. A gateway, message filtering and separate safety domains add defence in depth.

A connected autonomous vehicle uses V2X as one more input beside radar, camera and LiDAR. Radar measures range and speed; camera reads lanes and signs; LiDAR builds a point cloud. V2X adds information beyond line of sight and, more importantly, intent: 'I am braking' or 'I am turning left'. The fusion unit must weigh a delayed or false V2X message against its own sensors.

Worked example

Question. Two cars close at 40 m/s relative speed. A warning is useful 2.5 s before a possible collision. How far ahead must it arrive, and how much does 100 ms of V2X latency add?

  1. Warning distance without latency: d = v_rel × t = 40 m/s × 2.5 s = 100 m.
  2. Convert latency to seconds: 100 ms = 0.100 s.
  3. Extra distance caused by latency: d_latency = 40 m/s × 0.100 s = 4 m.
  4. Required arrival distance: 100 m + 4 m = 104 m.

Output

None

Answer. The warning must arrive by 104 m; latency adds 4 m to the ideal 100 m.

Exam traps

  • V2X is radio communication, not a radar or camera. A car with V2X still needs its own sensors; V2X adds messages beyond line of sight.
  • V2V and V2I do not need cellular coverage. Only V2N and cloud services stop when the tower is down.
  • Do not mix 802.11p and LTE-V2X. 802.11p is ad hoc Wi-Fi in 5.9 GHz; LTE-V2X has a direct sidelink plus an optional network mode.
  • Authentication is not encryption. A signature proves sender and integrity; it may leave the message readable.
  • Convert 100 ms to 0.1 s before multiplying by m/s. Using 100 gives a 100-times error.

6.7 VANET architecture, applications and routing

A VANET (vehicular ad hoc network) is a wireless network of moving vehicles. Links form as cars meet each other; roadside units (RSUs) beside the road are optional fixed access points, and the network still works without them. Road-constrained motion lets position and maps replace stable links. Safety warnings, tolling and traffic updates use it. Only a few universities teach this in depth. This chapter covers domains, applications and routing; the radio is in 6.8.

You need: 6.1 for the in-vehicle bus, 6.6 for V2X (vehicle-to-everything) messages, and basic IP routing.

Ad hoc links and VANET domains

An ad hoc wireless network has no fixed infrastructure. Every node forwards packets for others, so distant nodes communicate in multiple hops. In a VANET each vehicle carries an on-board unit (OBU): a radio plus computer that sends and receives messages. A roadside unit (RSU) is a fixed access point beside the road. Multi-hop matters when an RSU is out of range: a warning can pass car to car until it reaches a highway patrol or a connected ambulance.

Three domains fit together. The in-vehicle domain is the electronic control unit (ECU) network on the car's buses (see 6.1). The OBU joins it to the ad hoc domain, where OBUs talk to OBUs and RSUs. RSUs connect to the infrastructure domain: Internet and cloud servers. Safety messages need the ad hoc path; a toll server can use infrastructure. The same OBU can also use cellular data, but ad hoc links work without a tower and add low delay locally.

Applications and road-driven design

Road traffic deaths exceed one million a year worldwide; most occur in low- and middle-income countries. VANET safety applications aim at this: collision warning ahead, hazard warning after a crash, and intersection warning at blind corners. Connected autonomous vehicles also need V2X because cameras and radar cannot see through buildings. Non-safety uses include traffic information, electronic tolling (FASTag in India), parking payment and infotainment. Safety messages are short and repeated; non-safety messages can tolerate delay.

The radio design differs from generic mobile ad hoc networks (MANETs). Vehicles move at high speed, so a 200 m link between cars closing at 240 km/h lasts about 3 s. Contacts are short, yet paths are predictable because cars follow roads; the Global Positioning System (GPS) gives position. Vehicles have no energy limit, and the network can be very large. The message rate rises in dense traffic, so channel load is a design limit. These facts drive position-based routing.

Routing families and their failure modes

Topology-based routing stores routes to addresses. AODV (ad hoc on-demand distance vector) floods a route request, learns a route, and repairs broken links; DSR (dynamic source routing) carries the whole route in each packet. At highway speed links break before repair finishes. Routing chooses the next radio hop, not the whole road trip.

Position-based routing uses GPS coordinates. Greedy perimeter stateless routing (GPSR) first uses greedy forwarding: send to the neighbour closest to the destination. At a local maximum no neighbour is closer, so perimeter mode forwards the packet around the void by face routing on a planarized graph of the radio neighbours, using positions taken from GPS. The faces come from where the neighbours are, not from the road layout. The worked example applies the greedy rule.

Geocast sends a message to all vehicles in a target region, useful for a hazard zone. Simple flooding causes the broadcast storm problem: many vehicles rebroadcast the same alert and congest the channel. Suppression, such as waiting a random time or selecting one forwarder, reduces this. Where no next vehicle exists, store-and-forward carries the packet until a car or RSU appears.

Worked example

Question. A packet at (0,0) must reach a destination at (100,0). Neighbours are A at (40,10), B at (70,−20) and C at (20,30). Which neighbour does greedy forwarding choose?

  1. For each neighbour compute distance to the destination with d = √((100−x)² + (0−y)²), where (x,y) is the neighbour position in metres.
  2. A(40,10): 100−40 = 60, 0−10 = −10, so d = √(60²+10²) = √3700 ≈ 60.8 m.
  3. B(70,−20): 100−70 = 30, 0−(−20) = 20, so d = √(30²+20²) = √1300 ≈ 36.1 m.
  4. C(20,30): 100−20 = 80, 0−30 = −30, so d = √(80²+30²) = √7300 ≈ 85.4 m.
  5. The smallest distance is for B, about 36.1 m, so greedy forwarding sends to B.

Answer. Greedy forwarding sends the packet to neighbour B, about 36.1 m from the destination.

Exam traps

  • VANET nodes are not energy-limited and move on roads; generic MANET assumptions such as random motion and battery limits fail.
  • AODV link repair cannot keep up with 120 km/h traffic, so 'topology routing always works' is false.
  • Greedy forwarding can stop at a local maximum; perimeter mode then recovers, and delivery is guaranteed only if the neighbour graph is connected and planarized, as GPSR assumes.
  • Flooding a hazard alert is not free: it causes the broadcast storm problem.
  • GPSR sends to the neighbour closest to the destination, not closest to the source; a common exam slip.

6.8 DSRC, IEEE 802.11p and WAVE protocol stack

Dedicated short-range communication (DSRC) is a short-range radio link for vehicles, centred on 5.9 GHz. IEEE 802.11p adapts Wi-Fi to moving cars: 10 MHz channels and no association handshake. WAVE, the IEEE 1609 family, adds channel timing, networking and security above it. A car broadcasts a basic safety message about ten times each second to nearby vehicles and roadside units. Only a few universities teach this stack in depth.

You need: Chapter 6.6 for V2X applications and Chapter 6.7 for VANET routing.

The radio and 802.11p

DSRC uses spectrum near 5.9 GHz: about 5.85–5.925 GHz in the US and 5.855–5.925 GHz in Europe. The band is split into 10 MHz channels: one control channel (CCH) and several service channels (SCH). That width is half of ordinary 802.11a Wi-Fi, so the headline rate is about half.

IEEE 802.11p is the MAC and PHY. The PHY uses orthogonal frequency-division multiplexing (OFDM) and gives roughly 3 to 27 Mbit/s depending on modulation and coding. Lower rates survive longer links and more Doppler.

The MAC is Wi-Fi adapted for cars. A vehicle works outside a basic service set, so it does not associate, authenticate or exchange keys before sending. It waits for an idle channel and broadcasts. Enhanced Distributed Channel Access (EDCA) gives four access categories, so urgent safety frames wait less than ordinary data. This is connectionless broadcast, not a phone call. The radio is half-duplex: one unit cannot transmit and receive on the same channel at the same moment.

WAVE: IEEE 1609 above 802.11p

WAVE (Wireless Access in Vehicular Environments) is the IEEE 1609 set above 802.11p. It shares one radio among safety, traffic and internet traffic.

  • IEEE 1609.1 is a resource manager; an application can request services from another unit. Simple safety systems rarely use it.
  • IEEE 1609.2 defines security. Signed and encrypted messages with public-key certificates let a receiver check origin and integrity.
  • IEEE 1609.3 is networking. WSMP (WAVE Short Message Protocol) carries small safety packets with low overhead; IPv6 carries ordinary internet traffic.
  • IEEE 1609.4 coordinates the radio. A 100 ms sync interval splits into a control-channel interval and a service-channel interval, commonly 50 ms each. During CCH time vehicles tune to the control channel for announcements and safety; during SCH time they switch to a service channel for other data.

An onboard unit sends a basic safety message (BSM) about ten times per second, carrying position, speed, heading and braking. Neighbours build a local picture even without line of sight.

Worked example

Question. A 300-byte BSM is sent at 6 Mbit/s. How long is one transmission, and how many fit in a 50 ms control-channel interval that keeps 10% for overhead?

  1. Convert bytes to bits: 300 × 8 = 2400 bits.
  2. Transmission time = 2400 bits / (6×10⁶ bit/s) = 4×10⁻⁴ s = 0.4 ms.
  3. Usable interval = 50 ms × (1 − 0.10) = 45.0 ms.
  4. Messages by division = 45.0 ms / 0.4 ms = 112.5.
  5. Only whole messages fit, so 112 messages fit.

Exam traps

  • 802.11p uses 10 MHz channels, not the 20 MHz of 802.11a, so its headline rate is roughly half.
  • WAVE is not another name for 802.11p. WAVE adds the IEEE 1609 layers; 802.11p is only MAC and PHY.
  • The control channel is for short safety and control frames, not long downloads; bulk service traffic belongs on a service channel.
  • The 100 ms sync interval is a radio timing rule; it does not mean a BSM must be sent exactly every 100 ms or that only one BSM fits.
  • 3–27 Mbit/s is the PHY rate before contention and overhead; do not use it as delivered throughput in a crowded channel.

  1. A shared bus cuts harness mass, cost and connector count, but it makes bandwidth, latency and determinism design problems that point-to-point wiring did not have.
  2. CAN resolves collisions during arbitration instead of after them: the lowest numerical identifier wins and no message is destroyed.
  3. CAN FD keeps CAN's arbitration and frame structure but shortens the data phase and allows up to 64 bytes, which suits software updates and sensor fusion.
  4. LIN, FlexRay and automotive Ethernet are not competitors; they sit at different cost, speed and determinism points and are joined by a gateway.
  5. OBD-II is a legal standard, not a manufacturer feature: one connector, one set of messages and one code format for emissions-related faults.
  6. MISRA C reduces coding faults and ISO 26262 manages the remaining risk; the two together form the evidence a safety case needs.
  7. V2X extends perception beyond line of sight, which matters at blind corners and in mixed traffic where cameras and radar see too late.
  8. DSRC, IEEE 802.11p and WAVE are three layers of one system: radio, MAC/PHY, and the networking, timing and security stack above them.

Apply

Apply Three nodes start sending CAN frames with identifiers 0x123, 0x0F1 and 0x2A0 at the same instant. Trace the arbitration bit by bit, name the winner, and state when the losers retransmit. 13 marks

Write identifiers in binary, MSB first after SOF; Compare bit by bit; first difference decides; Node sending recessive 1 while bus is dominant 0 becomes receiver; 0x0F1 wins because its identifier is numerically smallest; Losers set a pending flag and retry after the interframe space; No data corrupted, only delay for the losers; Note that identifier value doubles as message priority.

Apply A powertrain CAN bus at 500 kbit/s carries twelve messages. Explain how you would calculate bus load and worst-case latency for one message, and what you would do if the load crosses 70 percent. 13 marks

Frame time = number of bits including stuffing divided by bit rate; Bus load = sum of frame times per period divided by period; Worst-case latency = blocking by lower-priority frame + own transmission + queueing; Effect of stuff bits and of error frames; Options: raise bit rate, split onto a second bus, move to CAN FD, lengthen periods; Keep margin for future messages.

Apply A scan tool reads DTC P0301 with a freeze frame showing 2,400 rpm, 62 km/h and 35 percent load. Explain how the code is interpreted, what P0301 means, and the steps you would take next. 13 marks

Analyze Analyse the IEEE 1609 WAVE stack: what each of 1609.1, 1609.2, 1609.3 and 1609.4 does, and how the stack sits on IEEE 802.11p and DSRC channels. 13 marks

Evaluate Evaluate whether DSRC or cellular V2X is the better choice for intersection warning and platooning in Indian mixed traffic, giving technical and deployment reasons. 13 marks

Evaluate A steer-by-wire system must be certified to ASIL D and runs on FlexRay. Evaluate the combined role of MISRA C coding rules and the ISO 26262 safety lifecycle as evidence. 13 marks

Glossary

Arbitration
The bit-wise contest at the start of a CAN frame that lets the lowest identifier transmit without collision.
ASIL
Automotive Safety Integrity Level, from A to D, giving the rigour required by a safety goal.
Automotive Ethernet
A switched single-pair Ethernet network used as the high-bandwidth backbone of a vehicle.
Bus
A single shared communication medium on which several nodes exchange addressed messages.
CAN FD
CAN with a faster data phase and payloads of up to 64 bytes, sharing CAN's arbitration.
Data link layer
In the bus context, the layer that frames bits, checks errors and controls access to the medium.
Determinism
A guarantee that the worst-case message delay is known before the system is built.
Dominant bit
The CAN logic 0, produced by actively pulling the bus to a low differential voltage; it overrides a recessive bit.
DSRC
Dedicated Short-Range Communications, the 5.9 GHz radio service for road safety.
DTC
Diagnostic trouble code, a five-character identifier of a specific fault.
FlexRay
A dual-channel time-triggered bus for safety-critical chassis functions, up to 10 Mbit/s per channel.
Gateway
A node that joins two or more buses and forwards only the messages that need to cross.
Harness
The complete set of wires and connectors in the vehicle.
LIN
A cheap single-wire master-slave bus for body electronics, up to 20 kbit/s.
MISRA C
A rule set restricting C so that risky constructs and undefined behaviour are removed from embedded code.
Node
A device attached to the bus that can send and receive messages.
OBD-II
A legal diagnostic standard fixing the 16-pin connector, message set and code format for emissions faults.
Pseudo-header
A short header carrying identifier and data-length information used by CAN and similar buses.
Recessive bit
The CAN logic 1, produced by releasing the bus so that the terminators hold it at the idle level.
RSU
Roadside unit, fixed infrastructure that talks to passing vehicles.
Safety case
The documented argument and evidence that a system meets its safety goals.
V2X
Vehicle-to-Everything communication covering vehicle, infrastructure, pedestrian and network peers.
VANET
An ad hoc network formed by moving vehicles without fixed infrastructure.
WAVE
The IEEE 1609 stack above IEEE 802.11p handling multi-channel use, networking and security.
WSMP
WAVE Short Message Protocol, a lightweight network protocol for safety messages defined in IEEE 1609.3.
