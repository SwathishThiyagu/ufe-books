3.1 Counting rules: sum and product rules

Counting rules answer “how many?” without listing every object. The sum rule adds the sizes of disjoint cases. The product rule multiplies the number of options at independent stages. These two rules are the base of most combinatorics: booking forms, menu combos, passwords and test-case counts. The numbers stay small here; the real work is checking that cases do not overlap and that stages do not affect each other.

You need: set operations for disjoint unions (see Unit 2, Sets, Relations and Functions) and basic proof language (see Unit 1, Logic and Proof Techniques).

Sum rule: add disjoint cases

Let A be a finite set. Write |A| for the number of elements in A. Suppose A is split into k cases A₁, A₂, …, Aₖ. The cases are disjoint when no object lies in two cases. They are exhaustive when every object lies in at least one case. If both hold, the sum rule says:

|A| = |A₁| + |A₂| + ⋯ + |Aₖ|

A₁, …, Aₖ are pairwise disjoint finite sets that together form A; k is the number of cases.

Example. A metro card can be topped up by 4 UPI apps, 3 bank pages or 2 counter windows. These are three disjoint cases, so the number of methods is 4 + 3 + 2 = 9. If one UPI app also appears on a bank page, the cases overlap; adding would count that app twice.

A decision tree shows the rule: draw one branch for each case, then add the branch sizes. Some syllabi call this the addition principle; the condition, not the name, is what matters.

Product rule: multiply independent stages

A choice has k stages. Stage i has nᵢ options. The stages are independent when every choice made earlier still allows all nᵢ options at stage i. Then the number of ordered outcomes is:

N = n₁ × n₂ × ⋯ × nₖ

N is the number of ordered stage-by-stage outcomes; nᵢ is the number of options at stage i; k is the number of stages.

Example. A thali has 3 rice options, 4 curries and 2 sweets. A meal is one rice, one curry and one sweet, so the count is 3 × 4 × 2 = 24. If the curries depend on the rice chosen, the stages are not independent and this product is wrong.

Mix product inside sum

Many counts need both rules. Split the whole set into disjoint cases. Inside each case, multiply independent stages. Then add the case totals. The order is: case first, stage second.

The railway form in the worked example has two cases. Case 1: build a ticket from one class, one quota and one payment method. The product is 4 × 3 × 5 = 60. Case 2: pick one of 6 preset tatkal combos. The preset is one choice, so its size is 6. The cases are disjoint: a custom ticket is not a preset combo. Sum rule gives 60 + 6 = 66.

For a simple combinatorial proof, let S be the set of outcomes. Partition S into S₁, …, Sₖ. A partition means each outcome is in exactly one part. Count each part. The sum rule says |S| is the sum of the part sizes. For the product rule, the outcomes are k-tuples (x₁, …, xₖ), where xᵢ comes from a set of size nᵢ; the number of such tuples is the product.

Two checks catch most errors. Disjointness: can one outcome appear in two cases? Independence: after an early choice, does every later option remain available, with the same count? If either check fails, repair the cases or use inclusion–exclusion (see 3.4). Ordered stages count sequences; if order does not matter, do not use the product rule blindly (see 3.2).

Exam traps

  • Adding overlapping cases. If one outcome can appear in two cases, the sum rule overcounts; use inclusion–exclusion (3.4) or redefine the cases.
  • Multiplying dependent stages. If a choice at stage 2 changes the number of options at stage 3, n₁×n₂×n₃ is not valid.
  • Using the product rule for unordered selections. Product counts sequences; choosing a captain then a vice-captain gives 11×10 ordered pairs, not 2-player teams (see 3.2).
  • Forgetting the single-choice case. A preset combo is one option, not a stage with several parts; do not multiply it by class or quota.
  • Not checking exhaustiveness. Cases must cover all outcomes; a missing case gives a total that is too small.

3.2 Permutations and combinations

A permutation counts ordered arrangements; a combination counts unordered selections. The same set of objects gives different answers when order matters and when it does not. This distinction is the core of counting: it tells you whether to multiply by r! or not, whether repeats are allowed, and whether the arrangement sits on a line or a circle. It appears in PIN and password rules, lottery and team selection, seating plans, and in the binomial coefficients used throughout computer science.

You need: the product rule from 3.1 Counting rules, and Unit 2 on functions if you want the permutation-function view.

Permutations: order matters

A permutation is an ordered arrangement of r objects chosen from n distinct objects. The two-letter words AB and BA use the same letters but are different permutations. Use permutations when positions, ranks or roles differ.

nPr = n! / (n − r)!

nPr is the number of ordered arrangements of r objects from n distinct objects; n! = n × (n − 1) × ... × 1; 0! = 1; 0 ≤ r ≤ n.

The formula is the product rule: n choices for the first position, n − 1 for the second, down to n − r + 1 for the last. If repetition is allowed, each of the r positions has n choices, so the count is nr. If repetition is forbidden, you cannot use nr.

A circular permutation fixes rotations. Seat n distinct people around a round table: fix one person to break the rotation, then arrange the remaining n − 1 people in a line. The count is (n − 1)!. If clockwise and anticlockwise orders are also considered the same, as with a necklace, divide by 2 for n ≥ 3; check the wording before doing this.

A permutation of all n objects is a bijection from a set to itself; see Unit 2 on functions. The factorial n! is its count.

Combinations: order does not matter

A combination is an unordered selection of r objects from n distinct objects. Choosing questions 1, 2 and 3 is the same as choosing 3, 2 and 1. Some syllabi call selections combinations and arrangements permutations.

nCr = n! / (r! (n − r)!)

nCr is the number of r-object subsets of an n-object set; the order of the r objects is ignored.

Link to permutations: nPr = r! × nCr, because each chosen set of r objects can be ordered in r! ways. Example: C(10,3) = 120; P(10,3) = 720 = 6 × 120. The identities C(n,r)=C(n,n−r) and C(n,r)=C(n−1,r−1)+C(n−1,r) follow by counting subsets.

Combinatorial proof of C(n,r)=C(n,n−r): choosing r objects to keep is the same as choosing n−r objects to leave out. Both actions describe the same subset, so the counts are equal. For Pascal's identity, split the subsets by one fixed object: either it is included, giving C(n−1,r−1), or excluded, giving C(n−1,r).

Combinations with repetition: choose r items from n types when repeats are allowed and order is ignored. Put r identical stars and n−1 dividers in a row; the count is C(n+r−1,r). Example: 3 scoops from 5 flavours, repeats allowed, gives C(7,3)=35.

Multisets and mixed arrangements

A multiset has repeated objects. The number of distinct arrangements of n objects with k types, where type i appears n_i times, is n! / (n_1! n_2! ... n_k!). Divide by each repeated factorial because swapping identical copies does not create a new arrangement.

n! / (n_1! n_2! ... n_k!)

n = n_1 + ... + n_k; n_i is the count of identical objects of type i.

Example: the letters of BANANA are 6 objects: B once, A three times, N twice. Arrangements = 6! / (1! 3! 2!) = 720 / 12 = 60. If all letters were distinct, the count would be 6! = 720; the division removes the invisible swaps.

Use a decision checklist: Does order matter? Are repeats allowed? Is the arrangement circular? For selections with repeats, use stars and bars; for arrangements with repeats, use the multiset formula. Write the count as a product of stages before simplifying factorials.

Worked example

Question. A 4-digit PIN uses four different digits from 0–9 and cannot start with 0. How many PINs exist? Also, how many ways can a student choose 3 of 10 practice questions?

  1. First digit: digits 1 to 9, so 9 choices. 0 is not allowed here.
  2. Second digit: any digit 0–9 except the first. That is 10 − 1 = 9 choices. Zero is now allowed.
  3. Third digit: exclude the first two, so 10 − 2 = 8 choices. Fourth digit: 10 − 3 = 7 choices.
  4. Product rule: 9 × 9 = 81; 81 × 8 = 648; 648 × 7 = 4536 PINs.
  5. Practice questions: order does not matter, so use combinations. C(10,3) = 10! / (3! 7!) = (10 × 9 × 8) / (3 × 2 × 1) = 720 / 6 = 120.

Answer. There are 4536 four-digit PINs and 120 ways to choose 3 of 10 practice questions.

Exam traps

  • Using nr when repeats are forbidden. For a 4-digit PIN with distinct digits, the count is not 104.
  • Forgetting that 0 cannot lead but can appear later. The first digit has 9 choices, not 10; the second digit has 9 choices, not 8.
  • Using permutations when selection order does not matter. Choosing 3 practice questions or a cricket team is a combination.
  • In circular seating, writing n! instead of (n − 1)!. Fix one person first to remove the repeated rotations.

3.3 Pigeonhole principle and its generalized form

Put N objects into k boxes. If N is larger than k, at least one box must hold more than one object. That is the pigeonhole principle. It exists to turn a counting fact into a guarantee: you do not find which box, only that one box must be full enough. The generalized form gives the exact minimum: some box holds at least ⌈N/k⌉ objects. It is used in scheduling, hashing, error detection, and quick proofs about repeated colours, months or subset sums. Some syllabi spell it 'pigeon hole principle'.

You need: 3.1 counting rules and proof by contradiction from Unit 1, Proof methods: direct, indirect and by contradiction.

The simple form

Call the containers boxes and the items objects. Every object goes into exactly one box. If there are N objects and k boxes and N > k, then some box contains at least two objects. The reason is a maximum count: if every box had at most one object, the total would be at most k. But N > k, so all N objects cannot fit.

N > k ⇒ some box has at least 2 objects

N is the number of objects; k is the number of boxes; ⇒ means implies.

This is a proof by contradiction. Assume every box holds at most one object. The largest possible total is k, which is smaller than N. Contradiction. The same idea can also be written as a contrapositive argument.

Example: 13 people and 12 birth months. Since 13 > 12, two people share a birth month. The principle does not say January. It says some month. This is why the result is a guarantee, not a prediction.

The generalized form

The simple form counts a repeat of 2. The generalized form gives the exact minimum for any repeat count. Put N objects into k boxes. Some box holds at least ⌈N/k⌉ objects. Here ⌈x⌉ is the ceiling of x: the smallest integer greater than or equal to x.

⌈N/k⌉ = ⌊(N + k − 1)/k⌋

N is the number of objects; k is the number of boxes; ⌊ ⌋ rounds down to an integer; ⌈ ⌉ rounds up to an integer.

The formula uses integer arithmetic. It is exact, not an estimate. If N = 7 and k = 3, then ⌈7/3⌉ = ⌈2.333...⌉ = 3. So 7 socks in 3 colours force 3 socks of one colour. With 6 socks, the split 2, 2, 2 is possible, so 6 is not enough.

N ≥ k(r − 1) + 1 ⇒ some box has at least r objects

N is the number of objects; k is the number of boxes; r is the target count in one box; the smallest such N is k(r − 1) + 1.

To force r objects in some box, take k(r − 1) + 1 objects. One fewer gives k(r − 1) objects, which can be split as r − 1 in every box. The bound is tight: it cannot be lowered. The principle gives a lower bound on the fullest box, not an exact count of every box; exact counts need 3.4.

Proof by contradiction and a subset pattern

Prove the generalized form by contradiction. Let m = ⌈N/k⌉. Suppose every box holds at most m − 1 objects. The total number of objects is at most k(m − 1). By the definition of ceiling, m − 1 < N/k, so k(m − 1) < N. The total would be less than N, but all N objects are placed. Contradiction. Therefore some box holds at least m objects.

The same argument proves the r-form. If every box had at most r − 1 objects, the total would be at most k(r − 1). Choosing N = k(r − 1) + 1 makes this total less than N, a contradiction.

Subset example. Choose any 6 distinct integers from 1 to 10. Pair the numbers as {1, 10}, {2, 9}, {3, 8}, {4, 7}, {5, 6}. There are 5 pairs, and each pair sums to 11. Six chosen numbers go into 5 pairs, so two chosen numbers fall in the same pair. Those two sum to 11. The principle guarantees such a pair exists; it does not say which pair.

Worked example

Question. A drawer has red, blue and green socks. In the dark, how many socks must you take to guarantee at least three socks of one colour? Show that one fewer sock does not guarantee this.

  1. Boxes are the 3 colours: red, blue and green. Objects are the socks drawn.
  2. The target repeat count is r = 3.
  3. Use the r-form: smallest N = k(r − 1) + 1 with k = 3 and r = 3.
  4. Compute N = 3(3 − 1) + 1 = 3 × 2 + 1 = 7 socks.
  5. With 6 socks, the split 2 red, 2 blue, 2 green has no colour reaching 3, so 6 socks are not enough.
  6. With 7 socks, ⌈7/3⌉ = 3, so some colour has at least 3 socks.

Answer. Answer: 7 socks; with 7 socks some colour has at least 3 socks.

Exam traps

  • Using floor instead of ceiling: floor(7/3) = 2, but 7 socks in 3 colours force 3, because 2 + 2 + 2 = 6 is the largest total with no colour reaching 3.
  • Claiming a named box, colour or month must reach the bound. The principle guarantees only that some box does.
  • Confusing 'at least r' with 'exactly r'. The fullest box may hold r + 1 or more.
  • Writing N/k with integer division. Use the ceiling formula; if N/k is an integer, the bound is N/k, not N/k + 1.
  • Forgetting the exact condition for r: N must be k(r − 1) + 1 or more, not k·r.

3.4 Principle of inclusion and exclusion

The principle of inclusion and exclusion (PIE) corrects overcounting when sets overlap. Adding the sizes of sets counts shared elements more than once. PIE subtracts pairwise intersections, adds back triple intersections, and alternates signs for more sets. It converts a question about at least one property into counts of intersections. Use it for divisibility counts, forbidden positions, and onto functions. Plain addition fails when categories overlap, as with numbers divisible by 2 or 3.

You need: <a href='#counting-rules-sum-and-product-rules'>3.1 sum and product rules for adding disjoint cases, and Unit 2 for set union, intersection and complement.

Why adding sizes overcounts

Let A and B be finite sets. The symbol |A| means the number of elements in A. The union A∪B is the set of elements in A, in B, or in both. The intersection A∩B is the set of elements in both.

|A∪B| = |A| + |B| − |A∩B|

A and B are finite sets; |A| is the size of A; ∩ is intersection; ∪ is union.

Proof by regions. Split A∪B into three disjoint parts: elements only in A, elements only in B, elements in both. The sum |A|+|B| counts the middle part twice. Subtract |A∩B| once, and every element is counted once. If A and B are disjoint, A∩B is empty and |A∩B|=0, so the formula reduces to the sum rule in <a href='#counting-rules-sum-and-product-rules'>3.1.

The idea is correction. Add everything, then remove the excess. For two overlapping lists, say students who passed maths and students who passed physics, the overlap is counted in both lists, so subtract it once.

Three sets: subtract pairs, add the triple

|A∪B∪C| = |A| + |B| + |C| − |A∩B| − |A∩C| − |B∩C| + |A∩B∩C|

A, B and C are finite sets; |A∩B| is the number of elements in both A and B; |A∩B∩C| is the number in all three.

An element in exactly one set is counted once by the three single terms and never subtracted. An element in exactly two sets is counted twice by the singles, then subtracted once by its pair term, leaving 1. An element in all three sets is counted 3 times by the singles, subtracted 3 times by the three pair terms, giving 0, so |A∩B∩C| adds it back once. Every element of the union is counted exactly once.

Some syllabi write PIE for this principle. The signs alternate: plus for one set, minus for two, plus for three. For k sets, add k-fold intersections with sign (−1)k+1.

Complement counting and integer ranges

Many questions ask for none or not. Let U be the universal set. The complement of A∪B∪C is U−(A∪B∪C). Its size is |U|−|A∪B∪C|. Count the union first, then subtract from |U|.

number of multiples of d in 1..n = ⌊n/d⌋

d is a positive integer; n is the upper limit; ⌊x⌋ is the greatest integer ≤ x.

The reason is that the multiples are d, 2d, …, kd, and kd ≤ n < (k+1)d, so k = ⌊n/d⌋. For an intersection of multiples, use the least common multiple, not the product. The multiples of both d and e are the multiples of lcm(d,e). So |A∩B| = ⌊n/lcm(d,e)⌋. For 2 and 3, lcm is 6. For 4 and 6, lcm is 12, not 24. For 2, 3 and 5, lcm is 30.

For a general range a to b, count in 1 to b and subtract count in 1 to a−1. If the range does not end at a multiple of d, ⌊b/d⌋ still works; n/2 without floor is wrong.

Where PIE is used

Divisibility counts are the standard use. The worked example below counts integers divisible by 2, 3 or 5. The same method counts integers divisible by none, by complement.

Forbidden positions. Suppose n items must be placed in n positions, but some item-position pairs are forbidden. Let Ai be the set of arrangements in which item i sits in one of its forbidden positions; the derangement case is when each item has exactly one forbidden position. Count arrangements that avoid every Ai by PIE over the forbidden events; see <a href='#derangements-and-distribution-problems'>3.8.

onto(m,n) = Σ<sub>k=0</sub><sup>n</sup> (−1)<sup>k</sup> C(n,k)(n−k)<sup>m</sup>

m is the domain size; n is the codomain size; C(n,k) is the number of ways to choose k of n elements; onto(m,n) is the number of onto functions from an m-set to an n-set.

In the onto formula, C(n,k) chooses k missed codomain elements, and (n−k)m counts functions into the remaining elements. The k=0 term is nm. The alternating signs remove functions missing at least one element. If n>m the answer is 0.

Worked example

Question. How many integers from 1 to 100 are divisible by 2, 3 or 5?

  1. Let U = {1, 2, …, 100}. Let A be the integers in U divisible by 2, B those divisible by 3, and C those divisible by 5.
  2. Count single sets. |A| = ⌊100/2⌋ = 50. |B| = ⌊100/3⌋ = 33. |C| = ⌊100/5⌋ = 20.
  3. Count pairwise intersections using least common multiples. |A∩B| = ⌊100/lcm(2,3)⌋ = ⌊100/6⌋ = 16. |A∩C| = ⌊100/lcm(2,5)⌋ = ⌊100/10⌋ = 10. |B∩C| = ⌊100/lcm(3,5)⌋ = ⌊100/15⌋ = 6.
  4. Count the triple intersection. |A∩B∩C| = ⌊100/lcm(2,3,5)⌋ = ⌊100/30⌋ = 3.
  5. Apply PIE. |A∪B∪C| = 50 + 33 + 20 − 16 − 10 − 6 + 3.
  6. Compute. 50 + 33 + 20 = 103. 16 + 10 + 6 = 32. 103 − 32 + 3 = 74.

Answer. 74 integers from 1 to 100 are divisible by 2, 3 or 5.

Exam traps

  • Forgetting to add the triple intersection |A∩B∩C| back after subtracting the three pairwise intersections.
  • Using n/2 without floor when the range does not end at a multiple of d. Use ⌊n/d⌋.
  • Using the product d·e instead of lcm(d,e) for the intersection of multiples of d and e. For 4 and 6, use 12, not 24.
  • Confusing at least one with none. For none, subtract the union from the universal set: |U| − |A∪B∪C|.
  • In the onto-function formula, a sign error or starting the sum at k=1 instead of k=0. The k=0 term is n^m.

3.5 Recurrence relations: homogeneous and non-homogeneous

A recurrence relation defines each term of a sequence from earlier terms. It describes a process that repeats: compound interest, algorithm running time, the tower of Hanoi. Linear recurrences with constant coefficients are solved in two parts: a homogeneous solution from a characteristic equation, and a particular solution that matches the forcing term. Initial conditions fix the constants. This chapter solves small-degree recurrences by hand, uses the Fibonacci and tower of Hanoi recurrences as models, and checks each closed form against the first few terms.

You need: the product rule from 3.1 to set up recurrences, and induction from Unit 1, Mathematical induction, to verify a closed form.

Linear recurrences and their order

A recurrence relation gives a_n in terms of earlier terms. The order is the number of earlier terms used. In the standard linear form, k is the order, c₁,...,c_k are constant coefficients, and f(n) is the forcing term. The recurrence is linear because every a term appears to the first power and no two a terms multiply. It is homogeneous when f(n)=0 for all n; otherwise it is nonhomogeneous.

a_n = c₁a_{n−1} + c₂a_{n−2} + ... + c_k a_{n−k} + f(n)

a_n is the nth term; k is the order; c₁,...,c_k are constant coefficients; f(n) is the forcing term.

Fibonacci: F_n = F_{n−1} + F_{n−2}, with F_0=0 and F_1=1. It has order 2, is homogeneous, and has constant coefficients. Tower of Hanoi: T(n)=2T(n−1)+1, with T(1)=1. It has order 1 and is nonhomogeneous with constant forcing 1. The +1 counts the one move of the largest disk.

A closed form is a formula for a_n that uses n only. Solving means finding that formula and fitting the initial conditions. The next sections split the job into a homogeneous part and a particular part.

Characteristic equation: distinct and repeated roots

For a homogeneous linear recurrence with constant coefficients, try a_n = r^n. Substitution gives the characteristic equation. Its roots are the characteristic roots.

r^k − c₁r^{k−1} − ... − c_k = 0

r is the trial root; c_i are the recurrence coefficients; k is the order.

If the roots r₁,...,r_k are distinct, then a_n = A₁r₁^n + ... + A_k r_k^n, where A_i are constants fixed by k initial conditions. Example: a_n=5a_{n−1}−6a_{n−2}. The characteristic equation is r²−5r+6=(r−2)(r−3), so a_n=A·2^n+B·3^n.

If a root r repeats m times, the terms for that root are (A₀+A₁n+...+A_{m−1}n^{m−1})r^n. Example: a_n=6a_{n−1}−9a_{n−2} has r²−6r+9=(r−3)². Root 3 repeats twice, so a_n=(A+Bn)3^n. Missing the Bn term is a common error.

Fibonacci's characteristic equation is r²=r+1, with distinct roots (1±√5)/2. The constants follow from F_0=0 and F_1=1.

Nonhomogeneous: add a particular solution

For a nonhomogeneous recurrence, the general solution is h_n + p_n, where h_n solves the homogeneous version and p_n is any one solution of the full recurrence. The particular solution is chosen to look like f(n), with one adjustment: if the trial already solves the homogeneous recurrence, multiply it by n, or by n^m if the matching root has multiplicity m.

a_n = h_n + p_n

h_n is the homogeneous solution; p_n is a particular solution of the full recurrence.

3.6 Generating functions

A generating function turns a whole sequence into one power series, so adding, shifting and multiplying sequences become algebra on power series, done the way you handle polynomials. It exists because counting and recurrences often produce sequences that are hard to compare term by term. Packed as one object, they can be simplified and read back. You use it for binomial identities, recurrence solving, and counting arrangements.

You need: combinations and the binomial series from 3.2, and basic algebra from Unit 2.

Pack a sequence into a series

A sequence a₀, a₁, a₂, … can be stored as one power series. The ordinary generating function (OGF) of the sequence is G(x) = Σ_{n≥0} a_n xⁿ. The symbol x is a stand-in, not a number to substitute. a_n is the nth term; for example a₀ is the first term. The coefficient of xⁿ in G(x) is written [xⁿ]G(x), and it equals a_n. No value of x is needed to define the series.

This is formal algebra. Two series are equal when every coefficient matches; we add and multiply them like polynomials, ignoring convergence. That freedom is the point: an infinite list becomes one algebraic object. Some syllabi call this simply the generating function. For example, the sequence 1, 2, 3, … has G(x)=1+2x+3x²+⋯.

G(x) = a₀ + a₁x + a₂x² + a₃x³ + ⋯

a_n is the term at index n; x is a formal variable.

Known series and operations

Three series cover most exam problems. As numeric identities, 1/(1−x) = Σxⁿ needs |x| < 1, and 1/(1−ax) = Σaⁿxⁿ needs |ax| < 1. The binomial series (1+x)ⁿ = Σ C(n,k)x^k is a finite sum, so it always holds. As formal power series, none of them needs any condition on x. C(n,k) is the binomial coefficient from 3.2.

1/(1−x) = Σ_{n≥0} xⁿ, 1/(1−ax) = Σ_{n≥0} aⁿxⁿ, (1+x)ⁿ = Σ_{k=0}^{n} C(n,k)x^k

a is a constant; C(n,k) counts k-subsets of an n-set; n is a non-negative integer.

  • Shifting: x^k G(x) has coefficients 0 up to k−1, then a₀, a₁, … at positions k, k+1, ….
  • Scaling: G(ax) has coefficients a_n aⁿ.
  • Convolution: if H(x)=G(x)F(x), then h_n=Σ_{k=0}^{n} a_k b_{n−k}.

Convolution is why generating functions solve counting problems: choosing k items from one part and n−k from another adds over all k. In the convolution formula, F(x) = Σ_{k≥0} b_k x^k, so b_k is the coefficient of x^k in F(x), and a_k = [x^k]G(x).

Closed form and coefficient extraction

A rational generating function can be split by partial fractions into pieces from the known list. First divide P by Q if deg P ≥ deg Q, and keep only the remainder over Q; also Q must have Q(0) ≠ 0 so that every factor can be written as (1−αx); if not, take out a power of x first. To find [xⁿ] P(x)/Q(x), factor Q(x), write the fraction as A/(1−αx)+B/(1−βx)+⋯, then read coefficients: [xⁿ] 1/(1−αx)=αⁿ. For a repeated factor (1−αx)², use 1/(1−αx)²=Σ(n+1)αⁿxⁿ.

If Q(x) has (1−αx)^m, include terms A₁/(1−αx)+⋯+A_m/(1−αx)^m. The worked example below carries this out for the odd numbers. The same method will solve recurrences in 3.7, where you first find G(x) from the recurrence, then extract coefficients.

Worked example

  • Treating x as a number and checking convergence. For formal power series, only the coefficients matter; no convergence test is needed.

3.7 Solving recurrence relations using generating functions

A generating function packs a whole sequence into one power series, so it can also unpack a recurrence. Multiply the recurrence by xⁿ, sum over every n where it is valid, and each shifted sum collapses into x·G(x) or x²·G(x). What remains is a plain equation in the unknown G(x). Solve it, split the answer into partial fractions, and read aₙ back off the standard series. This gives closed forms quickly, and it explains why Fibonacci numbers are built from powers of the golden ratio.

You need: recurrences and generating functions.

The method in seven steps

The recurrence links aₙ to earlier terms. Multiplying by xⁿ and summing turns the whole sequence into one function. Each shift of the index becomes a multiplication by x plus removal of the early terms.

  1. Write the recurrence as aₙ = (rest) for n ≥ k, and list a₀, a₁, …, a_{k−1}.
  2. Set G(x) = Σ_{n≥0} aₙxⁿ, the ordinary generating function.
  3. Multiply both sides by xⁿ and sum over n ≥ k, the index where the recurrence is valid.
  4. Replace each shifted sum by x·G(x), x²·G(x) and so on, subtracting the terms already lost.
  5. Solve the resulting linear equation for G(x). It will be a ratio of two polynomials.
  6. Factor the denominator and split G(x) into partial fractions of the form c/(1 − ax)^m.
  7. Expand each fraction with its standard series and add the coefficients of xⁿ.

The method works because every sum is built from the same G(x). The equation is linear in that single unknown, so ordinary algebra finishes the job.

Partial fractions and reading off aₙ

A rational G(x) splits into pieces whose coefficients are already known.

1/(1 − ax) = 1 + ax + a²x² + a³x³ + ⋯

a is a fixed real number; the coefficient of xⁿ is aⁿ, and the series converges for |x| < 1/|a|.

When G(x) = P(x)/Q(x) and Q(x) has distinct factors (1 − a₁x)(1 − a₂x)⋯, write G(x) = A₁/(1 − a₁x) + A₂/(1 − a₂x) + ⋯. To find Aᵢ, multiply both sides only by (1 − aᵢx), the factor belonging to Aᵢ. Then put x = 1/aᵢ: every other term still contains (1 − aᵢx) and vanishes. So Aᵢ = [(1 − aᵢx)·G(x)] evaluated at x = 1/aᵢ. That is the cover-up shortcut. Equivalently, cancel (1 − aᵢx) out of Q(x) before substituting. Repeated factors need the powers 1/(1 − ax)^m.

A Fibonacci-style recurrence

Take F₀ = 0, F₁ = 1 and Fₙ = Fₙ₋₁ + Fₙ₋₂ for n ≥ 2. Sum both sides over n ≥ 2.

The left side is Σ_{n≥2} Fₙxⁿ = G(x) − F₀ − F₁x = G(x) − x. The two right sides are Σ_{n≥2} Fₙ₋₁xⁿ = xG(x) and Σ_{n≥2} Fₙ₋₂xⁿ = x²G(x). Substituting gives G(x) − x = xG(x) + x²G(x), so G(x) = x/(1 − x − x²).

Factor 1 − x − x² = (1 − φx)(1 − ψx), where φ = (1 + √5)/2 ≈ 1.618 and ψ = (1 − √5)/2 ≈ −0.618. These satisfy φ + ψ = 1 and φψ = −1, as the expansion demands. Partial fractions give G(x) = (1/√5)·[1/(1 − φx) − 1/(1 − ψx)].

Reading coefficients: Fₙ = (φⁿ − ψⁿ)/√5, Binet's formula. Since |ψ| < 1, the ψⁿ term dies away, so Fₙ ≈ φⁿ/√5. That is why the numbers grow like powers of the golden ratio.

Sum over n ≥ 1: G(x) = 2xG(x) + x/(1 − x). So G(x)(1 − 2x) = x/(1 − x) and G(x) = x/((1 − x)(1 − 2x)) = −1/(1 − x) + 1/(1 − 2x). Hence aₙ = 2ⁿ − 1. Check: a₀ = 0, a₁ = 1.

Analyze A student solves aₙ = 3aₙ₋₁ + 2, a₀ = 1, reaches G(x) = (1 + x)/((1 − x)(1 − 3x)), and reports aₙ = 2 − 3ⁿ. Identify the error. 4 marks

The partial fractions are correct only as −1/(1 − x) + 2/(1 − 3x). The student attached −1 to the (1 − 3x) factor and 2 to the (1 − x) factor. Correct answer: aₙ = −1 + 2·3ⁿ, which gives 1 at n = 0 as required.

Analyze For Fₙ = Fₙ₋₁ + Fₙ₋₂ with F₀ = 0, F₁ = 1, explain why the numerator of G(x) is x and not 1. 4 marks

The recurrence holds only for n ≥ 2, so the sum starts at n = 2. The left side is Σ_{n≥2} Fₙxⁿ = G(x) − F₀ − F₁x = G(x) − x. Solving gives G(x) = x/(1 − x − x²); the numerator records that a₀ = 0.

Beyond the syllabus

Not for the exam. Generating functions open into analytic combinatorics, where the singularities of G(x) give the growth rate of aₙ without any exact formula. In algorithm analysis they produce closed forms for divide-and-conquer recurrences and for Catalan-type counting of binary trees. In probability the same object appears as a probability generating function, and derivatives at x = 1 give means and variances. 3.8 Derangements and distribution problems

Two counting problems share one toolkit. A derangement is a permutation in which nothing lands back in its own place — four letters into four addressed envelopes with every letter wrong. A distribution problem places r balls into n boxes under rules: balls identical or distinct, boxes allowed empty or not. Both show up in testing whether a shuffle fixed anything, in seat-allocation puzzles, in hashing, and in the inclusion–exclusion machinery. Only a few universities teach this as a named topic; the marks come from naming the model correctly before computing.

You need: 3.2 Permutations and combinations and 3.4 Principle of inclusion and exclusion.

Derangements: nothing in its own place

A derangement is a permutation of n labelled objects in which no object stays in its original position. Write D_n, also written !n, for the count. The small values are D_1 = 0, D_2 = 1, D_3 = 2, D_4 = 9. The standard model is letters and addressed envelopes: letter i must not go into envelope i.

D_n = (n − 1)(D_{n−1} + D_{n−2})

D_n is the number of derangements of n objects, used for n ≥ 3, with starting values D_1 = 0 and D_2 = 1.

Why the recurrence holds: letter 1 must go into one of the n − 1 wrong envelopes. Say it goes into envelope j. If letter j goes to envelope 1, the two letters have swapped and the other n − 2 letters must be deranged: D_{n−2} ways. If letter j avoids envelope 1, then the remaining n − 1 letters carry exactly the original restriction: D_{n−1} ways.

!n = n! Σ_{k=0}^{n} (−1)^k / k!

n! counts all permutations; the alternating sum cancels the ones with fixed letters, k counting how many letters are fixed. The ratio D_n/n! tends to 1/e ≈ 0.368.

Stars and bars: identical balls into distinct boxes

Place r identical balls into n distinct boxes, empty boxes allowed. Write r stars in a row; n − 1 bars cut that row into n groups. Each placement is one such string, and each string is one placement.

C(r + n − 1, n − 1)

C(a, b) = a!/(b!(a − b)!) is the binomial coefficient, r is the number of identical balls, n is the number of distinct boxes. With r = 10 and n = 4: C(13, 3) = 286 placements.

If no box may stay empty, give one ball to each box first and distribute the rest: C(r − 1, n − 1) placements, possible only when r ≥ n.

Distinct balls and onto placements

Make the r balls distinct and the n boxes distinct, empties allowed. Each ball chooses a box on its own, so the product rule gives n^r placements.

Forcing every box to be used is an onto-function count. Inclusion–exclusion over the boxes left empty:

Σ_{k=0}^{n} (−1)^k C(n, k)(n − k)^r

k is the number of boxes forced empty, (n − k)^r places the r distinct balls into the remaining boxes, and the sum is 0 when r < n. For n = 3 boxes and r = 4 balls: 81 − 48 + 3 = 36.

Worked example

Question. Four letters A, B, C, D are placed one each into four addressed envelopes. Find the number of placements in which no letter reaches its own envelope. Solve by inclusion–exclusion, then verify with the recurrence and with the factorial formula.

  1. Total placements of 4 distinct letters into 4 envelopes: 4! = 24.
  2. Let A_i be the set of placements where letter i is correct. Then |A_i| = 3! = 6, and there are C(4, 1) = 4 such sets: 4 × 6 = 24.
  3. Pairs: |A_i ∩ A_j| = 2! = 2, with C(4, 2) = 6 pairs: 6 × 2 = 12.
  4. Triples: |A_i ∩ A_j ∩ A_k| = 1! = 1, with C(4, 3) = 4 triples: 4 × 1 = 4.
  5. All four correct: 0! = 1, with C(4, 4) = 1 set: 1.
  6. Inclusion–exclusion: 24 − 24 + 12 − 4 + 1 = 9.
  7. Recurrence check: D_1 = 0, D_2 = 1, D_3 = 2 × (1 + 0) = 2, D_4 = 3 × (2 + 1) = 9.
  8. Formula check: 24 × (1 − 1 + 1/2 − 1/6 + 1/24) = 24 − 24 + 12 − 4 + 1 = 9.

Answer. Exactly 9 of the 24 placements leave every letter in a wrong envelope.

Exam traps

  • Writing n! or (n − 1)! as the derangement count. D_4 = 9, not 24 and not 6.
  • Using n^r when the balls are identical. Identical balls give C(r + n − 1, n − 1), a far smaller number.
  • Dropping the factor (n − 1) in the recurrence, or starting the recurrence at D_1 = 1 when D_1 = 0.
  • Confusing the two no-empty-box answers: C(r − 1, n − 1) for identical balls but inclusion–exclusion for distinct balls.
  • Off-by-one in the binomial: it is C(r + n − 1, n − 1), with n − 1 bars, not n.

Beyond the syllabus

Not for the exam. Derangement counts model matching problems where nobody may receive their own item, and the same alternating sum drives the hat-check puzzle and card-shuffle bets. The onto count is n! times the Stirling number of the second kind S(r, n), which counts partitions of r distinct objects into n non-empty blocks. Hashing analysis uses onto counts when every bucket must be touched. Good search words: Stirling numbers of the second kind, hat-check problem, rook polynomial.

Takeaways

  1. Counting starts with two rules: add when cases are disjoint, multiply when stages are independent.
  2. Order matters gives permutations; order does not matter gives combinations, and C(n, r) = P(n, r)/r!.
  3. The pigeonhole principle proves that a repeated or crowded case must exist, without saying which one.
  4. Inclusion–exclusion fixes double counting by alternating subtraction and addition of overlaps.
  5. Every linear homogeneous recurrence is solved by its characteristic roots; repeated roots add a factor of n.
  6. A non-homogeneous recurrence is solved as homogeneous solution plus one particular solution.
  7. A generating function turns a sequence into one algebraic object, so recurrence steps become multiplication by x.
  8. Derangements are inclusion–exclusion in action, and their count is roughly n!/e.
  9. Telling balls and boxes apart as identical or distinct decides which formula applies in distribution problems.

Glossary

Box principle
Another name for the pigeonhole principle.
Ceiling ⌈x⌉
The smallest integer greater than or equal to x.
Combination identity
C(n, r) = C(n − 1, r − 1) + C(n − 1, r), Pascal's rule.
Complementary counting
Counting the unwanted outcomes and subtracting from the total.
Convolution
The sequence cₙ = Σ aᵢbₙ₋ᵢ, whose generating function is the product A(x)B(x).
Counting principle
A rule that gives the size of a set of outcomes without listing them.
Disjoint sets
Two sets with no element in common, so their sizes add cleanly.
Distinct objects
Objects treated as labelled, so which object goes where matters.
Factorial n!
The product 1 × 2 × … × n, with 0! defined as 1.
Floor ⌊x⌋
The largest integer less than or equal to x.
Forcing term
The function f(n) on the right side of a non-homogeneous recurrence.
Formal power series
A power series treated as algebra only, with convergence not required.
General solution
The family of all sequences satisfying a recurrence before initial values are applied.
Identical objects
Objects treated as indistinguishable, so only counts per box matter.
Initial condition
Starting values such as a₀ and a₁ that fix one sequence out of a recurrence's family.
Intersection
The set of elements common to all the given sets.
Onto function
A function whose image equals its whole codomain; used in counting onto placements.
Onto placements
Distributions of n distinct balls into k distinct boxes with no box empty: k!·S(n, k).
Partial fractions
Splitting a rational generating function into simpler pieces whose coefficients are known.
Power series
An infinite sum of the form Σ aₙxⁿ.
Repeated root
A root r of multiplicity m in the characteristic equation; it contributes terms nⁱrⁿ for i = 0 to m − 1.
Stirling number S(n, k)
The number of ways to split n distinct objects into k non-empty unlabelled boxes.
Union of sets
The set of elements in at least one of the given sets.
Vandermonde identity
C(m + n, r) = Σ C(m, i)·C(n, r − i) over valid i.
