6.1 Graph terminology and special types of graphs

A graph is a set of vertices and a set of edges, where each edge joins two vertices. This simple object captures pairwise relations: roads between towns, flights between airports, links between web pages, or matches between cricket teams. The same idea answers practical questions: how many handshakes happen, whether a network splits into two groups, or how many links a complete network needs. This chapter fixes the vocabulary and the standard graph families that later chapters use for paths, colouring, trees and shortest routes.

You need Unit 2, Sets, Relations and Functions for vertex and edge sets, and Unit 3 for simple counting.

Vertices, edges and degree

A graph G = (V, E) has a vertex set V and an edge set E. In a simple undirected graph each edge is a two-element subset {u, v}, written uv; in a multigraph or pseudograph an edge is an unordered pair of endpoints that may repeat or have u = v. The endpoints u and v are adjacent. A simple graph has no loops and no parallel edges. A multigraph allows two or more parallel edges between the same pair. A pseudograph also allows a loop, an edge from a vertex to itself. A directed graph, or digraph, has ordered edges (u, v): the edge points from u to v. The indegree indeg(v) counts edges entering v; the outdegree outdeg(v) counts edges leaving v. A graph need not be connected; connectivity is studied in 6.3.

The degree deg(v) is the number of edge ends at v. A loop adds 2, because both ends meet the same vertex. The handshaking lemma connects degrees to the edge count.

Σv∈V deg(v) = 2|E|

V is the vertex set; E is the edge set; deg(v) is the degree of vertex v; |E| is the number of edges.

Proof: each edge has two ends, so it contributes 2 to the total of all degrees. Therefore the degree sum is always even. The degree sequence is the list of degrees in non-increasing order; for a simple graph on n vertices every entry is between 0 and n−1. In a digraph, Σ indeg(v) = Σ outdeg(v) = |E|, because every directed edge has one tail and one head.

Worked example

Question. For the graph G with vertex set V = {A, B, C, D} and edge set E = {AB, AC, BC, CD}: (a) list deg(v) for each vertex; (b) verify the handshaking lemma; (c) decide whether G is bipartite.

  1. Read each edge as two incidences. AB gives one to A and one to B; AC gives one to A and one to C; BC gives one to B and one to C; CD gives one to C and one to D.
  2. Count: deg(A) = 2 (AB, AC), deg(B) = 2 (AB, BC), deg(C) = 3 (AC, BC, CD), deg(D) = 1 (CD).
  3. Sum = 2 + 2 + 3 + 1 = 8. Here |E| = 4, so 2|E| = 8. The lemma holds.
  4. Bipartite test: the triangle A-B-C is a cycle of length 3. A bipartite graph has no odd cycle. So G is not bipartite.

Answer. The degrees are A=2, B=2, C=3 and D=1; their sum is 8 = 2 × 4, so the handshaking lemma holds, and the graph is not bipartite because A-B-C is a triangle.

Exam traps

  • The handshaking lemma says Σ deg(v) = 2|E|, not |E|. A sum equal to |E| means you forgot the factor 2.
  • A loop adds 2 to the degree of its vertex, not 1, because both ends of the loop meet the same vertex.
  • Km,n has mn edges, not m+n. The value m+n is the number of vertices.
  • Bipartite forbids every odd cycle, not every cycle. C4 is bipartite; C3 is not.
  • Wn notation varies: some books use n vertices (hub plus Cn−1), others use n+1 vertices (hub plus Cn). Check the definition in the question.

6.2 Graph representation and graph isomorphism

To work with a graph on a computer, you must store it. Three standard stores are the adjacency matrix, the adjacency list and the incidence matrix. Each answers a different question quickly: matrix lookup, neighbour scanning, or edge-vertex incidence. A second problem is sameness. Two graphs can look different but have the same structure. Graph isomorphism is the formal idea of that sameness: a bijection between vertices that preserves edges. These ideas appear in network routing, social-network analysis, circuit checking and any program that compares graph-shaped data.

You need 6.1 for vertices, edges, loops and degrees, and Unit 2, Functions for bijections.

Three storage methods

Fix an ordering of the vertices. For a graph G with n vertices, the adjacency matrix A is an n × n table. In a simple graph, aij = 1 when an edge joins vertex i to vertex j, and aij = 0 otherwise. In a multigraph, aij is the number of edges joining i and j. For an undirected graph A is symmetric: aij = aji. The diagonal entry aii records a loop.

A = [a<sub>ij</sub>],  a<sub>ij</sub> = 1 if {i, j} ∈ E, else 0

A is the adjacency matrix; aij is the entry in row i and column j; E is the edge set. For a multigraph, replace 1 by the number of parallel edges.

An adjacency list stores one row per vertex: the vertex followed by its neighbours. It uses space O(V + E), which is smaller than O(V²) for sparse graphs. To test whether xy is an edge, scan the shorter list of x or y; that can take O(deg x) or O(deg y) time.

An incidence matrix has one row per vertex and one column per edge. For a simple undirected graph, put 1 in the two rows of the endpoints of each edge and 0 elsewhere. Thus every column has exactly two 1s. It uses V × E cells and is useful when edges carry identity, such as edge labels or costs.

Graph isomorphism

Let G and H be graphs. An isomorphism from G to H is a bijection f: V(G) → V(H) such that xy is an edge of G exactly when f(x)f(y) is an edge of H. The graphs are isomorphic if such an f exists.

xy ∈ E(G) ⇔ f(x)f(y) ∈ E(H)

f is a bijection on the vertex sets; x and y are vertices of G; xy means the unordered pair {x,y}. For directed graphs replace xy by the ordered edge (x,y).

An isomorphism relabels vertices without changing structure. It must preserve adjacency and non-adjacency. The inverse f⁻¹ is an isomorphism from H to G, so isomorphism is an equivalence relation on graphs.

Use invariants to rule out isomorphism. The number of vertices, number of edges, degree sequence, number and lengths of cycles, number of connected components and the complement graph must match. These are necessary, not sufficient: C6 and two disjoint triangles both have 6 vertices, 6 edges and degree sequence (2,2,2,2,2,2), but one is connected and the other is not.

To prove isomorphism, give a bijection and check every edge. To disprove it, one failed invariant is enough.

Reading a matrix

Rows and columns are tied to the chosen vertex order. Reordering vertices permutes rows and columns together. Summing row i of A gives the degree of vertex i in a simple graph. In a multigraph with loops, a loop adds 2 to the degree but may appear as one diagonal 1, so row sum can differ from degree.

For an incidence matrix of a simple undirected graph, summing a vertex row gives its degree. Summing an edge column gives 2. The total of all entries is 2E. For a directed graph, a few universities teach -1 at the tail and +1 at the head; then each column sums to 0.

Use the matrix when the graph is dense and you need fast edge tests. Use the list when the graph is sparse and you need fast neighbour scans. Use the incidence matrix when you need edge-vertex incidence, for example in network flow or electrical circuits.

Exam traps

  • A diagonal 1 from a loop is not the degree. A loop adds 2 to the degree, so a row sum of the adjacency matrix can undercount degrees when loops are present.

6.3 Walks, paths, cycles and connectivity

A walk is an ordered list of vertices and edges where each edge joins the vertices on either side of it. Adding restrictions gives trails, paths, circuits and cycles. Connectivity asks whether one vertex can reach another by following edges. These ideas matter in road routing, UPI transaction networks, chip wiring and power-grid reliability, where a single weak link can split a network into separate pieces.

You need: graph vocabulary such as vertices, edges, degree and subgraph from 6.1.

Walks, trails, paths and cycles

A walk in a graph is a sequence v0, e1, v1, …, ek, vk, where each edge ei joins vi−1 to vi. The length of the walk is k, the number of edges used. A walk is closed when v0 = vk; otherwise it is open. Vertices and edges may repeat in a walk.

Add restrictions. A trail repeats no edge. A path repeats no vertex. A circuit is a closed trail. A cycle is a closed walk with no repeated vertex except the start equals the end. In a simple graph a cycle has length at least 3. Some syllabi call a circuit a closed trail; a few use circuit for any closed walk, so check the definition in your notes.

Connected graphs and removal tests

A graph is connected when a path exists between every pair of vertices. A component is a maximal connected subgraph. A disconnected graph has two or more components. The graph in the figure is connected and has one component.

  1. Remove vertex v to form G − v. If G − v has more components than G, then v is a cut vertex (articulation point).
  2. Remove edge e to form G − e. If G − e has more components than G, then e is a bridge.
  3. Repeat for each vertex and each edge to find all cuts.

Vertex connectivity κ(G) is the minimum number of vertices whose removal disconnects G or leaves one vertex. Edge connectivity λ(G) is the minimum number of edges whose removal disconnects G. For a connected graph with at least two vertices, κ(G) ≤ λ(G) ≤ δ(G).

κ(G) ≤ λ(G) ≤ δ(G)

κ(G) is vertex connectivity; λ(G) is edge connectivity; δ(G) is the minimum degree of G.

In the figure δ(G) = 1, κ(G) = 1 and λ(G) = 1. A bridge gives λ(G) = 1. The inequality is a quick check, not a full computation.

Directed graphs: reachability and strong connectivity

In a directed graph, a directed walk follows edge directions. A directed path repeats no vertex. Vertex v is reachable from u when a directed path runs from u to v. Reachability is not symmetric: one-way roads and one-way UPI settlement links are examples.

A directed graph is strongly connected when every ordered pair (u, v) has a directed path from u to v. It is weakly connected when replacing every directed edge by an undirected edge gives a connected graph. Strong connectivity implies weak connectivity; weak connectivity does not imply strong connectivity.

  • Strong component: a maximal strongly connected subgraph.
  • Directed cycle: a closed directed walk with no repeated vertex except the start.
  • u → v and v → u is strong on two vertices; u → v alone is weak, not strong.

Question. In the graph with vertices A, B, C, D, E and edges AB, BC, CD, DE, CE, find a path from A to E, one cycle, the cut vertices and the bridges.

  4. Cut vertex test for B: G − B has components {A} and {C, D, E}, so 2 components against 1 in G. B is a cut vertex.

Exam traps

  • A closed walk with a repeated vertex is not a cycle. The cycle rule allows only v0 = vk; every other vertex appears once.
  • A bridge is an edge; a cut vertex is a vertex. Removing either increases the number of components.
  • A trail may repeat vertices. A path may not. A walk may repeat both.
  • Weak connectivity of a directed graph does not give reachability in both directions. Check ordered pairs for strong connectivity.
  • The inequality κ(G) ≤ λ(G) ≤ δ(G) assumes a connected graph with at least two vertices; complete graphs and single vertices use special conventions.

6.4 Eulerian and Hamiltonian graphs

An Euler circuit is a closed walk that uses every edge exactly once. A Hamiltonian cycle visits every vertex exactly once. The two ideas look similar and are often confused. Euler problems ask whether a route can cover every road; Hamiltonian problems ask whether a route can visit every city. Euler has a clean degree test. Hamilton has no simple test, only useful sufficient conditions. The distinction matters in route inspection, delivery planning, circuit testing and tournament scheduling.

You need: graph vocabulary from 6.1 and paths, cycles and connectivity from 6.3.

Euler circuits and paths

An Euler circuit in a connected undirected graph is a closed walk that uses every edge exactly once. It may repeat vertices. The general name is Euler trail: a walk that uses every edge exactly once, closed or open. A closed trail is an Euler circuit; an open trail is an Euler path. A graph with an Euler circuit is called Eulerian. The degree of a vertex is the number of edges incident on it. A loop counts twice.

Euler circuit exists ⇔ every vertex has even degree

The graph is connected and has at least one edge. Degree counts incident edge ends.

The Euler trail test follows. A connected undirected graph has an open Euler path if and only if exactly two vertices have odd degree. Those two vertices are the start and end. If zero vertices have odd degree, the graph has a closed trail, an Euler circuit; some books also count that closed trail as an Euler path. If more than two vertices are odd, no Euler trail exists at all. Adding one edge between the two odd vertices makes the graph Eulerian.

For a directed graph, replace degree by indegree and outdegree. An Euler circuit exists if and only if every vertex has indegree = outdegree and all vertices with nonzero degree lie in one weakly connected component. Weakly connected means the graph becomes connected when edge directions are ignored. An Euler path exists if and only if at most one vertex has outdegree = indegree + 1, at most one has indegree = outdegree + 1, all other vertices balance, and the same connectivity holds.

Building an Euler circuit

Hierholzer's algorithm builds a circuit from smaller cycles. Start at any vertex. Follow unused edges until you return to the start; this gives a closed cycle. If unused edges remain at a vertex on the cycle, start another cycle there and splice it into the first. Repeat until all edges are used.

  1. Choose any start vertex with degree greater than 0.
  2. Walk along unused edges until returning to a vertex already on the current trail, forming a cycle.
  3. If unused edges remain at a vertex of the cycle, start a new cycle at that vertex.
  4. Splice the new cycle into the old cycle at that vertex.
  5. Stop when every edge is used.

Fleury's algorithm is slower but simple. At each step, choose an unused edge whose removal does not disconnect the remaining graph, unless no other choice exists. Never cross a bridge early. A bridge is an edge whose removal disconnects the remaining graph. The walk ends when all edges are used. Hierholzer is preferred for programs because it runs in O(E) time for E edges. Fleury can take O(E²) time if bridge checks are repeated.

Hamiltonian cycles and tests

A Hamiltonian cycle is a cycle that visits every vertex exactly once and returns to the start. A Hamiltonian path visits every vertex exactly once but need not return. A graph with a Hamiltonian cycle is Hamiltonian. Unlike Euler, no simple degree condition decides Hamiltonicity. The general problem is NP-complete.

  • Cut-vertex test: if a graph has a cut vertex, it has no Hamiltonian cycle. Removing that vertex would split the cycle into one path, but the graph splits into two or more components.
  • Bipartite balance: if a graph is bipartite with parts X and Y, a Hamiltonian cycle needs |X| = |Y|. A Hamiltonian path needs |X| and |Y| to differ by at most 1.
  • Degree test: every vertex in a Hamiltonian cycle has degree at least 2.
Dirac: n ≥ 3 and deg(v) ≥ n/2 for every vertex v ⇒ Hamiltonian cycle

n is the number of vertices; deg(v) is the degree of vertex v; the arrow means the condition guarantees a cycle, not that every Hamiltonian graph satisfies it.

Ore: n ≥ 3 and deg(u) + deg(v) ≥ n for every non-adjacent pair u, v ⇒ Hamiltonian cycle

n is the number of vertices; u and v are distinct vertices with no edge between them.

Dirac is a special case of Ore. Both are sufficient, not necessary. A graph can fail both and still be Hamiltonian. Only a few universities teach the Bondy–Chvátal closure. That method adds edges between non-adjacent pairs with deg(u) + deg(v) ≥ n and repeats; if the closure becomes complete, the original graph is Hamiltonian.

Worked example

Question. For the graph with edges AB, BC, CA, CD, DE, EC, list the degree of each vertex and give an Euler circuit. Does Dirac's theorem apply with n = 5?

Exam traps

  • Euler is about edges; Hamilton is about vertices. A graph can be Eulerian but not Hamiltonian, as in the two-triangle figure.
  • The even-degree test is for a connected graph. A disconnected graph can have all even degrees and still have no Euler circuit.
  • Dirac and Ore are sufficient, not necessary. Failing them does not prove that no Hamiltonian cycle exists.

6.5 Planar graphs and Euler's formula

A planar graph can be drawn on paper so that edges meet only at vertices. The drawing cuts the plane into faces, and Euler's formula V − E + F = 2 ties the numbers of vertices, edges and faces together. This is a counting identity, not a drawing trick: it holds for every connected plane graph. Engineers use it to test whether a circuit can be routed on one layer, whether a road network needs a flyover, and whether a network graph is too dense to embed without crossings. The edge bounds that follow quickly expose K5 and K3,3 as impossible.

You need: 6.1 for vertices, edges and complete/bipartite graphs, and 6.3 for connected components.

Planar drawings and faces

A graph is planar if it has at least one drawing in the plane in which edges meet only at their endpoints. Such a drawing is called a plane graph. Edges may be straight or curved; what matters is that no two edges cross at a point that is not a vertex. A plane graph divides the plane into faces: connected regions whose boundary is made of edges and vertices. Exactly one face is unbounded; it is the outer face. The same planar graph can have several drawings, but for a connected plane graph the number of faces is fixed by Euler's formula. The cube graph in the figure is planar. It is drawn as an outer square ABCD, an inner square EFGH, and four spokes AE, BF, CG and DH. It has V = 8 vertices, E = 12 edges and F = 6 faces: four side faces, the inner square, and the outside region.

V − E + F = 2

V is the number of vertices, E the number of edges, and F the number of faces including the outer face. For the cube, 8 − 12 + 6 = 2.

Euler's formula and components

For a connected plane graph, Euler's formula is V − E + F = 2. V is the number of vertices, E the number of edges, and F the number of faces, including the outer face. The formula is stable under a common operation. Pick a face and add an edge inside it between two existing vertices. E rises by 1 and F rises by 1, so V − E + F does not change. Start from a tree drawn in the plane: V − (V − 1) + 1 = 2. For k connected components, draw the components separately and the formula becomes V − E + F = 1 + k. Check with a forest of k components: E = V − k and F = 1, so V − (V − k) + 1 = 1 + k. A connected tree is the case k = 1, and then E = V − 1 and F = 1, giving 2. The outer face is counted once in every case; omitting it gives the wrong total.

V − E + F = 1 + k

k is the number of connected components; V, E and F are as above.

Edge bounds and nonplanarity

For a simple planar graph with V ≥ 3, every face boundary has length at least 3. Summing the boundary lengths over all faces counts every edge twice, because each edge has a face on each side. Therefore 2E ≥ 3F. Euler's formula gives F = 2 − V + E. Substitute: 2E ≥ 3(2 − V + E) = 6 − 3V + 3E. Rearranging gives E ≤ 3V − 6. If the graph has no triangle, every face boundary has length at least 4. Then 2E ≥ 4F, and the same substitution gives E ≤ 2V − 4. These inequalities are quick tests for nonplanarity. K5 has V = 5 and E = 5×4÷2 = 10. The bound gives 3V − 6 = 15 − 6 = 9. Since 10 > 9, K5 is nonplanar. K3,3 is bipartite, so it has no triangle. It has V = 6 and E = 9. The bound gives 2V − 4 = 12 − 4 = 8. Since 9 > 8, K3,3 is nonplanar. Passing a bound does not prove planarity; the conditions are necessary, not sufficient.

E ≤ 3V − 6

V is vertices and E is edges, for a simple planar graph with V ≥ 3.

E ≤ 2V − 4

V is vertices and E is edges, for a simple triangle-free planar graph with V ≥ 3.

Duality, subdivision and Kuratowski

The dual of a plane graph has one vertex for each face. Each original edge gives a dual edge that crosses it and joins the two faces on its two sides. The dual is another way to study faces, but it is not needed for the basic counting questions. A subdivision of a graph inserts a new vertex of degree 2 on an edge. Subdivision does not change planarity: stretching an edge cannot create a crossing, and removing the inserted vertex restores the original. Kuratowski's theorem states that a graph is nonplanar if and only if it contains a subdivision of K5 or a subdivision of K3,3. Only a few universities prove the full theorem; most exams ask for the statement and for the edge-bound arguments above. Colouring planar maps, where adjacent regions get different colours, is covered in 6.6.

Worked example

Question. A connected simple plane graph has V = 8 vertices and E = 12 edges. (a) Find F. (b) Check the simple-planar edge bound E ≤ 3V − 6. (c) Use the same bound to prove that K5 is nonplanar.

  2. Substitute V = 8 and E = 12: 8 − 12 + F = 2, so F = 2 + 12 − 8 = 6 faces.
  3. The bound for a simple planar graph with V ≥ 3 is E ≤ 3V − 6. Here 3V − 6 = 3×8 − 6 = 24 − 6 = 18. Since 12 ≤ 18, the bound does not rule out planarity; it is consistent.

6.6 Graph colouring and chromatic number

A graph colouring assigns a colour to each vertex so that neighbours get different colours. This models any situation where linked items must be kept apart: exams that share a student, variables live at the same time, or radio transmitters that interfere. The chromatic number χ(G) is the smallest number of colours that works. It measures the true conflict in the graph, not just its size. Scheduling rooms, allocating registers in a compiler and colouring maps all use this one idea.

You need: graph vocabulary and adjacency from 6.1, and the planar bound from 6.5.

Proper colourings and k-colourable graphs

A proper vertex colouring of a graph G = (V, E) gives every vertex a colour so that for each edge uv the colours of u and v differ. The graph is k-colourable if such a colouring uses at most k colours; unused colours are allowed. The chromatic number χ(G) is the least k for which G is k-colourable.

χ(G) = min { k ≥ 1 : G is k-colourable }

χ(G) is the chromatic number of G; k is a positive integer; G is k-colourable when a proper colouring with at most k colours exists.

A colour class is all vertices with one colour. No edge can lie inside a colour class, so each class is an independent set. A k-colouring splits V into k independent sets.

A graph with no edges and at least one vertex has χ = 1. The complete graph K_n has χ = n, because every pair of vertices is adjacent and all n colours must be distinct.

Bounds and greedy colouring

A clique is a set of vertices that are all pairwise adjacent. Its size is at most the number of colours, since clique vertices must all receive different colours. So χ(G) ≥ ω(G), where ω(G) is the clique number, the largest clique size. The triangle A, B, C in the figure has size 3, so at least 3 colours are needed.

  1. Order the vertices v1, v2, ..., vn.
  2. Give v1 colour 1.
  3. For each later vertex vi, look at its already coloured neighbours and give vi the smallest positive integer not used on those neighbours.
  4. Continue until every vertex has a colour.

After each step the colouring stays proper. A vertex has at most Δ(G) neighbours, where Δ(G) is the maximum degree. Those neighbours block at most Δ(G) colours, so one of Δ(G)+1 colours is always free. Therefore χ(G) ≤ Δ(G)+1. The bound is often loose; C5 has Δ = 2 and χ = 3.

A graph is bipartite exactly when it is 2-colourable exactly when it has no odd cycle. The two bipartition classes give colours 1 and 2. An odd cycle cannot alternate two colours and close. If there is no odd cycle, a breadth-first search from any vertex assigns alternating colours.

The four colour theorem says every simple planar graph is 4-colourable. K4 is planar and needs 4, so the number cannot be lowered.

Where colouring is used

Map colouring treats each region as a vertex; an edge joins regions with a shared border. The four colour theorem guarantees four colours for a planar map. The theorem covers planar graphs, not all graphs: K5 needs 5 colours.

Exam scheduling builds a graph with exams as vertices. An edge joins two exams that share a student. A colour is a time slot, and a proper colouring puts conflicting exams in different slots. The chromatic number is the minimum number of slots. The same model assigns channels to mobile towers that interfere, or rooms to classes that cannot run together.

A compiler's register allocator builds a graph of variables. An edge joins two variables live at the same time. Colours are CPU registers; χ is the minimum registers needed. If too few registers exist, some variables spill to memory.

Only a few syllabi add the chromatic polynomial P_G(k), which counts proper colourings with k colours.

Worked example

Question. For the graph with vertices A, B, C, D, E and edges AB, BC, CD, DE, EA, AC, find χ and give a proper 3-colouring.

  1. Write V = {A, B, C, D, E}. The edges are AB, BC, CD, DE, EA and AC. Degrees: deg(A) = 3, deg(B) = 2, deg(C) = 3, deg(D) = 2, deg(E) = 2, so Δ(G) = 3.
  2. The vertices A, B, C form a triangle: AB, BC and AC are all edges. A triangle is a clique of size 3, so ω(G) ≥ 3 and χ(G) ≥ 3. A K4 would need four vertices each of degree at least 3; only A and C have degree 3, so no K4 exists and ω(G) = 3.
  3. Try 3 colours. Set colour(A) = 1, colour(B) = 2, colour(C) = 3. Set colour(D) = 1, which is allowed because D's neighbours are C and E. Set colour(E) = 2.
  4. Check all edges: AB gives 1 and 2; BC gives 2 and 3; CD gives 3 and 1; DE gives 1 and 2; EA gives 2 and 1; AC gives 1 and 3. All differ, so this is a proper 3-colouring and χ(G) ≤ 3.
  5. The triangle proves χ(G) ≥ 3, and the colouring proves χ(G) ≤ 3. Hence χ(G) = 3.

  • A graph with no triangle can still need 3 colours. C5 is triangle-free (ω = 2) but χ(C5) = 3; bipartite graphs are exactly the 2-colourable graphs with no odd cycle.
  • 'k-colourable' means at most k colours, not exactly k. An empty graph is 3-colourable but has χ = 1.
  • The four colour theorem applies to simple planar graphs, not to every graph. K5 is non-planar and needs 5 colours.

6.7 Shortest path algorithms

A shortest path problem asks for the cheapest route from one vertex to another when every edge carries a nonnegative cost. Dijkstra's algorithm answers it by growing a settled set: the vertex with the smallest tentative distance is fixed, then its neighbours are relaxed. The method is the basis of route planning in maps, UPI payment routing, and network packet forwarding. This chapter shows the distance table, the predecessor array, and why negative edges break the greedy choice.

You need: adjacency lists from 6.2 and path definitions from 6.3.

Weighted graphs and path cost

A weighted graph attaches a number w(u, v) to each edge between vertices u and v. The weight can be distance in kilometres, travel time in minutes, or cost in rupees. For Dijkstra, every weight must satisfy w(u, v) ≥ 0. The cost of a path P = v₀, v₁, ..., vₖ is the sum of its edge weights.

cost(P) = Σ<sub>i=0</sub><sup>k−1</sup> w(v<sub>i</sub>, v<sub>i+1</sub>)

v₀ is the start vertex, vₖ is the end vertex, k is the number of edges, and w(vi, vi+1) is the weight of the i-th edge.

d(s, v) = min { cost(P) : P is a path from s to v }

d(s, v) is the shortest-path distance from source s to vertex v; P is any path from s to v.

  • Edge weights are not hop counts: a three-edge path can be cheaper than a one-edge path.
  • In an undirected graph, w(u, v) = w(v, u); store both directions in an adjacency list.
  • A shortest path tree stores one predecessor per vertex and rebuilds each route.

Dijkstra's algorithm step by step

Run Dijkstra from source s. Keep a tentative distance d(v) for every vertex. Initially d(s) = 0 and d(v) = ∞ for v ≠ s. Keep pred(v) to remember the previous vertex on the best known path.

  1. Mark every vertex unsettled. Set d(s) = 0, d(v) = ∞ for v ≠ s, and pred(v) = none for all v.
  2. Choose an unsettled vertex u with the smallest d(u). If d(u) = ∞, stop: the remaining vertices are unreachable.
  3. Mark u settled. Its distance d(u) is final.
  4. For each neighbour v of u, relax the edge: if d(u) + w(u, v) < d(v), set d(v) = d(u) + w(u, v) and pred(v) = u.
  5. Repeat steps 2–4 until the target is settled or no unsettled vertex is reachable.
  6. Rebuild the path from target t: write t, then pred(t), then pred(pred(t)), until s. Reverse the list.

d(v) ← min(d(v), d(u) + w(u, v))

← means assign; d(u) is the settled distance of u; w(u, v) is the edge weight; d(v) is the tentative distance of neighbour v.

  • Array version: scan all vertices to find the minimum each round, so O(V²) time. V is the number of vertices.
  • Binary-heap version: O((V + E) log V) time, where E is the number of edges.
  • The heap version is faster for sparse graphs; the array version is simple for dense graphs.

Why nonnegative weights matter

Dijkstra's greedy choice is safe only because all weights are nonnegative. The smallest tentative distance cannot later be reduced by adding a nonnegative weight. A negative edge can make a longer route cheaper, so a settled vertex may need a smaller value. Dijkstra does not update settled vertices.

Use Bellman–Ford for negative edges: O(VE) time, and it detects a negative cycle. Floyd–Warshall finds all-pairs shortest paths in O(V³) time; only some syllabi include it. Do not confuse shortest paths with minimum spanning trees in 6.9. A minimum spanning tree minimises the total weight of edges that connect all vertices; a shortest path minimises the cost from one source to one target.

Distances are path costs. A path with two edges can cost 3 rupees while a direct edge costs 10 rupees.

6.8 Trees and their properties

A tree is a connected graph with no cycle. A forest is a collection of trees that do not touch. This one restriction — no cycle — forces a rigid edge count and very simple paths. Trees model folder structures, family trees, decision paths and broadcast networks. They also give the cleanest example of minimal connection: every edge is needed, and no edge is spare. This chapter proves the standard equivalent forms and fixes the vocabulary of rooted trees.

You need: connectivity and cycles from 6.3, and basic graph terms from 6.1.

Tree definition and four equivalent forms

In a simple graph, a tree T = (V, E) is connected and acyclic. Acyclic means it has no cycle of length 3 or more. A forest is a disjoint union of trees; each component of a forest is a tree. A leaf is a vertex of degree 1. A tree is minimally connected: it is connected, but deleting any edge breaks connectivity.

m = n − 1

n is the number of vertices of the tree; m is the number of edges.

Every tree with n > 1 has a leaf. Take a longest simple path v0v1…vk in the tree. The endpoint vk has no neighbour outside the path, or the path could be extended. It is not adjacent to any earlier vertex vi with i < k − 1, or vivi+1…vk together with the edge vkvi would form a cycle. So vk has degree 1.

Proof of m = n − 1 by induction on n. For n = 1, m = 0. For n > 1, remove a leaf and its one edge. The rest is still a tree: it stays connected, because no path between two remaining vertices used the leaf, and it stays acyclic, because deleting an edge cannot create a cycle. It has n − 1 vertices and m − 1 edges. By induction m − 1 = (n − 1) − 1, so m = n − 1.

For a simple graph with n vertices, these statements are equivalent: (1) it is a tree; (2) it is connected and has n − 1 edges; (3) it is acyclic and has n − 1 edges; (4) every two vertices are joined by exactly one simple path; (5) adding an edge between two nonadjacent vertices creates exactly one cycle; (6) it is connected, and removing any edge disconnects it (equivalently, every edge is a bridge).

The unique path is the key. If two simple paths joined the same pair, their union would contain a cycle. In a tree, an extra edge between u and v closes the existing u–v path into one cycle. Any other cycle would need a second new edge. Removing an edge on the unique path leaves no alternative route.

Rooted trees and measurements

A rooted tree chooses one vertex as the root. The root has depth 0. For an edge from a parent to a child, the child is one edge farther from the root. Siblings share the same parent. A vertex with no children is a leaf of the rooted tree; in an unrooted tree with at least two vertices, a leaf has degree 1. The depth of a vertex is the number of edges from the root; the height of the tree is the largest depth. A binary tree is a rooted tree in which every vertex has at most two children.

2h+1 − 1

h is the height of a binary tree in edges; the value is the maximum number of vertices such a binary tree can have.

Rooted trees organise file folders, family records and expression parsing. A spanning tree is a tree that uses all vertices of a graph without a cycle; see 6.9.

Forests and edge counting

A forest with c components can be checked component by component. Suppose the components have n₁, n₂, …, n_c vertices. Component i is a tree, so it has n_i − 1 edges. Adding over all components gives total edges m = Σ(n_i − 1) = n − c.

m = n − c

n is the number of vertices of the forest; m is the number of edges; c is the number of connected components.

For c = 1 this becomes m = n − 1, the tree formula. For c = 3 and n = 12, m = 9, as in the worked example.

The condition “n − 1 edges” alone is not enough. A triangle plus one isolated vertex has n = 4, m = 3, but it is not a tree: it is disconnected and contains a cycle. A connected graph with n − 1 edges is a tree; an acyclic graph with n − 1 edges is also a tree.

Minimal connection has a practical meaning. If vertices are towns and edges are leased fibre links, a tree connects all towns with the fewest links and no backup route. Adding one link gives exactly one cycle, which is the cheapest form of redundancy. A minimum spanning tree finds the cheapest such tree when links have costs; see 6.9.

Worked example

Question. A simple graph T has 10 vertices and is a tree. (a) Find the number of edges of T. (b) One new edge is added between two vertices of T that were not adjacent. How many cycles does the new graph contain? (c) A forest F has 12 vertices and 3 components. Find the number of edges of F.

  1. For a tree, m = n − 1. Here n = 10, so m = 10 − 1 = 9 edges.
  2. The two chosen vertices already have exactly one simple path in T. The new edge plus that path forms one cycle. No second cycle can appear because the tree had no cycle and only one edge was added, so the answer is 1 cycle.
  3. For a forest, m = n − c. Here n = 12 and c = 3, so m = 12 − 3 = 9 edges.

Answer. The tree has 9 edges, the new graph has exactly 1 cycle, and the forest has 9 edges.

Exam traps

  • n − 1 edges alone does not make a tree; the graph must also be connected or acyclic. A triangle plus an isolated vertex has n = 4 and m = 3 but is not a tree.
  • A forest with c components has n − c edges, not n − 1. The formula n − 1 is only the special case c = 1.
  • Adding an edge between two existing nonadjacent vertices of a tree creates exactly one cycle, not zero. Adding a new vertex with one edge creates no cycle.
  • Height is the largest depth in edges, not the number of vertices on the longest path. A one-vertex tree has height 0.

6.9 Spanning trees and minimum spanning trees

A spanning tree keeps every vertex of a connected graph, uses exactly n − 1 edges, and has no cycle. Among all spanning trees of a weighted graph, the minimum spanning tree (MST) has the smallest total edge weight. Real networks — cables, roads, water pipes, circuit tracks — must join every point at least cost. Kruskal's and Prim's algorithms find an MST greedily by taking a cheapest safe edge; both rely on the cut property.

You need: 6.1 for vertices and edges, 6.8 for tree properties, and 6.7 for weighted graphs.

What a spanning tree is

Take a connected graph G = (V, E) with n = |V| vertices and m = |E| edges. A spanning tree of G is a subgraph T that keeps every vertex, is connected, and has no cycle. By 6.8, T has exactly n − 1 edges.

Every connected graph has at least one spanning tree. While a cycle exists, delete any edge of that cycle; the graph stays connected because the rest of the cycle still links the two ends. Repeat until no cycle remains. This deletes m − n + 1 edges, the cycle rank. A disconnected graph has a spanning forest, one tree per component.

Fibre plans, road plans, and Ethernet's spanning tree protocol all pick one spanning tree so every site is reached and no redundant loop remains.

Minimum spanning tree and the cut property

In a weighted graph each edge e has weight w(e): metres, rupees, milliseconds. The weight of a spanning tree T is the sum of its edge weights. An MST is a spanning tree of smallest possible weight.

w(T) = Σ w(e) for e in T

w(T) is the total weight of T; w(e) is the weight of edge e; the sum runs over the n − 1 edges of T.

A cut splits V into two non-empty sets S and V − S. An edge crosses the cut when its ends lie on opposite sides. Cut property: a lightest edge crossing any cut belongs to some MST; if it is the unique lightest edge across that cut, it belongs to every MST. Greedy choices therefore never block a cheaper finish.

Mirror rule: the heaviest edge of a cycle, when strictly heavier than every other edge of that cycle, lies in no MST. Both facts follow by an exchange argument: swap the edge for a cheaper one and keep a spanning tree of smaller weight.

Kruskal's algorithm

Kruskal builds the tree from a sorted edge list.

  1. Sort all m edges by weight, smallest first.
  2. Start with T empty. Each of the n vertices is its own component.
  3. Walk the sorted list. For edge (u, v), add it only if u and v are in different components, then merge those components. Otherwise skip it: it would close a cycle.
  4. Stop when T has n − 1 edges, or when the list ends.

Component tests use union-find. find(x) gives x's component label; union joins two labels. Each test is almost constant time, so sorting dominates: O(m log m). Kruskal suits sparse graphs and edge lists. In Figure 1, AC (3) is skipped because A and C are already joined through B.

Prim's algorithm

Prim grows one tree from a start vertex r.

  1. Put S = {r}, the vertices already in the tree, and T empty.
  2. While S ≠ V, take a cheapest edge with one end in S and one end outside S. Add it to T and add its outside end to S.
  3. When S = V, T is an MST with n − 1 edges.

Each chosen edge is a lightest edge across (S, V − S), so it is safe by the cut property. An array key[] stores the cheapest known edge from each outside vertex into S, and a min-heap picks the next vertex: O(m log n). With an adjacency matrix and a scan it is O(n²), good for dense graphs.

The total weight is the sum of the n − 1 chosen weights. The start vertex changes the order, not the total. Ties allow several MSTs with the same minimum weight.

  • Cayley's formula: n vertices give nn−2 labelled trees, so 5 vertices give 53 = 125.
  • Kruskal is edge-first; Prim is vertex-first; both return an MST of the same minimum total weight.

Worked example

Question. Figure 1 has vertices A, B, C, D, E and edges AB 2, AC 3, BC 1, BD 4, CD 5, CE 6, DE 2, BE 7. (a) Run Kruskal's algorithm and list chosen edges with total weight. (b) Confirm with Prim's algorithm from A.

  1. Sorted: BC 1, AB 2, DE 2, AC 3, BD 4, CD 5, CE 6, BE 7.
  2. n = 5, so a spanning tree needs 4 edges.
  3. BC (1): B and C are separate, add it. Weight = 1.
  4. AB (2): A alone, B with C, add it. T = {BC, AB}, weight = 3.
  5. DE (2): D and E separate, add it. Weight = 5.
  6. AC (3): A and C are both in {A, B, C}, skip it — it would close A–B–C–A.
  7. BD (4): {A, B, C} and {D, E} differ, add it. T = {BC, AB, DE, BD}, weight = 9, four edges, stop.
  8. CD 5, CE 6, BE 7 are unused.
  9. Prim from A: S = {A}; cut edges AB 2, AC 3, take AB 2. Weight = 2.
  10. S = {A, B}; cut edges AC 3, BC 1, BD 4, BE 7, take BC 1. Weight = 3.
  11. S = {A, B, C}; cut edges BD 4, CE 6, BE 7, take BD 4. Weight = 7.
  12. S = {A, B, C, D}; cut edges DE 2, CE 6, BE 7, take DE 2. Weight = 9.

Answer. Kruskal chooses BC (1), AB (2), DE (2) and BD (4); total weight 9. Prim from A chooses the same four edges with total 9.

Exam traps

  • Kruskal must test for a cycle before adding: a cheap edge such as AC (3) is skipped when its ends already sit in one component.
  • Stop at n − 1 edges. Adding a fifth edge to a spanning tree of 5 vertices always creates a cycle.
  • Prim's total weight is the same for every start vertex; only the order of chosen edges changes. Do not restart Prim at each vertex and add totals.
  • When weights tie, several MSTs exist with the same total weight. Questions asking 'the MST' usually want any one of them plus the total.
  • An MST minimises total weight, not the distance between two particular vertices. A shortest path between two vertices need not lie inside the MST (see 6.7).

It returns a minimum spanning forest, one tree per connected component with least possible weight. The rule 'stop at n − 1 edges' becomes 'stop when the edge list ends', and the result has n − c edges where c is the number of components.

Takeaways

  1. A graph is just two sets, V and E; almost every later idea is a property of those two sets.
  2. Matrix and list representations trade memory against speed, so the right choice depends on whether the graph is dense or sparse.
  3. Isomorphism asks whether two drawings are the same graph with the labels rubbed out; degree sequence and cycle structure are the first tests to try.
  4. Connectivity is about reachability: paths, components, bridges and cut vertices all measure how easily a network falls apart.
  5. Euler conditions are about edges and are easy to check (all degrees even); Hamiltonian conditions are about vertices and are hard (NP-complete).
  6. Planarity is a drawing question, and Euler's formula converts it into counting, which proves K₅ and K₃,₃ cannot be drawn flat.
  7. Colouring models conflicts; χ(G) ≤ Δ + 1 always, and χ(G) = 2 exactly for bipartite graphs with at least one edge.
  8. Dijkstra's algorithm is correct only for non-negative weights, and its running time depends on the priority queue used.
  9. A tree is the cheapest possible connected graph: connected with n − 1 edges, acyclic, or unique paths between all pairs.
  10. Greedy MST algorithms (Kruskal and Prim) are provably optimal because of the cut property of minimum weight edges.

Glossary

Bipartite test
A graph is bipartite iff it contains no odd cycle, which a breadth-first two-colouring detects.
Clique
A set of vertices in which every pair is joined by an edge; a clique of size k forces at least k colours.
Complement of a graph
The graph on the same vertices with an edge exactly where the original has none.
Cut
A partition of the vertex set into two non-empty parts; the edges crossing it are cut edges.
Cycle
A closed walk of length at least 3 with no repeated vertices except the first and last.
Directed graph (digraph)
A graph whose edges are ordered pairs, so each edge has a direction from tail to head.
Edge
A link between two vertices; written {u, v} when undirected and (u, v) when directed.
Face
A region of the plane bounded by edges in a crossing-free drawing of a planar graph, including the unbounded outer face.
Forest
An acyclic graph; each of its connected components is a tree.
Girth
The length of the shortest cycle in a graph that has one.
Greedy algorithm
A method that makes the best-looking choice at each step and never undoes it; correct for MST, not for Hamiltonian cycles.
Handshaking lemma
Σ deg(v) = 2|E| for every undirected graph.
Isomorphism invariant
A property preserved by isomorphism, such as the number of vertices, edges or components.
Leaf
A vertex of degree 1 in a tree.
Loop
An edge that joins a vertex to itself.
Multigraph
A graph in which two vertices may be joined by more than one edge.
Priority queue
A data structure that returns the smallest stored key quickly; Dijkstra uses it to pick the next vertex.
Proper colouring
An assignment of colours to vertices in which no two adjacent vertices share a colour.
Reachable
Vertex v is reachable from u if some path leads from u to v.
Simple graph
A graph with no loops and no parallel edges.
Spanning tree
A subgraph that is a tree and contains every vertex of the original graph.
Strongly connected
In a digraph, every vertex is reachable from every other vertex following edge directions.
Subgraph
A graph whose vertex set and edge set are subsets of those of the original graph.
Vertex
A point or node of a graph, usually drawn as a dot and labelled v₁, v₂, …
Walk
A sequence of vertices and edges v₀e₁v₁e₂…eₖvₖ; k is its length.
Weighted graph
A graph in which every edge carries a number, such as distance in km or cost in rupees.
