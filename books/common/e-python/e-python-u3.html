3.1 Strings: literals, indexing, slicing and methods

A string is a sequence of characters, and Python strings are immutable: you can read and copy parts of a string, but you cannot change a character in place. This matters because text is everywhere—names, UPI reference numbers, IRCTC station codes, messages—and a program must inspect, slice, search and reformat it without corrupting the original value. The chapter shows how literals create strings, how indexes and slices read them, and how methods return new strings or answers. Keep one rule in mind: s[0] = 'P' fails; s.replace('p', 'P') works and leaves s untouched.

You need Unit 1: variables, data types, operators and print(), and the habit of checking a value after each expression.

Literals, escapes and raw strings

A string literal is text written inside quotes. Python accepts 'python', "python" and '''python''' or """python""". Single and double quotes are equivalent; use double quotes when the text contains an apostrophe, as in "it's". Triple quotes keep line breaks, so they suit a short block of text.

A backslash starts an escape sequence. \n is newline, \t is a tab, \\ is one backslash, and \' is a single quote inside a single-quoted string. In a raw string, written r'...' or r"...", the backslash is ordinary: r'\n' contains two characters, backslash and n, not a newline. Raw strings help with patterns and paths, but a raw string cannot end with an odd number of backslashes.

Every string is an object of type str and an immutable sequence. Immutable means the object cannot be edited after creation. Methods and slices can build a new string; they never change the old one. Formatting of those new strings is the subject of 3.2.

Indexing, slicing and operators

len(s) gives the number of characters. Indexing reads one character: s[0] is the first, s[1] the second, and s[-1] the last. Negative indexes count from the right, so s[-2] is the second-last. An index outside -len(s) to len(s)-1 raises IndexError. Looping with for ch in s visits every character in order; some syllabi call this string traversal.

A slice reads a substring: s[start:stop:step]. It begins at start, stops before stop, and moves by step. With a positive step, defaults are start=0, stop=len(s), step=1. So s[1:4] takes indexes 1, 2 and 3, not 4. s[:3] starts at 0; s[3:] runs to the end; s[:] covers the whole string. When step is negative, the scan starts at the end of the string and stops at the beginning, so s[::-1] covers every character from last to first. A slice produces a string with the sliced value; because strings are immutable, CPython may return the same object for s[:], and nothing observable changes.

Operators: + joins strings, * repeats a string by an integer, and in / not in test whether a substring occurs. 'ab' * 3 is 'ababab'; 'y' in 'python' is True. A single character has an integer code point. ord('A') is 65, ord('a') is 97, and chr(65) is 'A'. Comparisons use these code points, so 'A' < 'a' is True. Methods that return a new value

Case methods: s.upper() returns all uppercase; s.lower() all lowercase; s.title() uppercases the first letter of each word and lowercases the remaining letters of each word ("it's a TEST".title() gives "It'S A Test"); s.capitalize() returns a copy with the first character uppercased and all remaining characters lowercased ('hELLO'.capitalize() gives 'Hello'); s.swapcase() flips case. Each returns a new string; s is unchanged.

Search and test methods: s.find(sub) returns the first index of sub, or -1 if absent. s.rfind(sub) returns the last index, or -1. s.index(sub) is like find but raises ValueError when absent. s.count(sub) counts non-overlapping occurrences. s.replace(old, new) returns a copy with every old replaced by new. s.startswith(prefix) and s.endswith(suffix) return True or False. s.isdigit(), s.isalpha(), s.isalnum() and s.isspace() test the whole non-empty string and return a bool.

join builds one string from an iterable of strings: sep.join(items) puts sep between items. It returns a string. Query methods return an int or a bool; transforming methods return a new string. No method changes s. Use 3.2 for split, strip and formatting.

Question. For s = 'python', write the value of each expression: s[0], s[-1], s[1:4], s[::-1], s.upper(), s.replace('p', 'P'), s.find('t'), len(s). Then state the value of s after these expressions run.

  1. s refers to the six characters p, y, t, h, o, n at indexes 0 to 5.
  2. s[0] reads index 0: 'p'.
  3. s[-1] counts from the end: the last index is -1, so 'n'.
  4. s[1:4] starts at 1 and stops before 4, so indexes 1, 2, 3: 'y', 't', 'h' → 'yth'.
  5. s[::-1] uses step -1 from the end to the start: 'nohtyp'.
  6. s.upper() returns 'PYTHON'; it is a new string.
  7. s.replace('p', 'P') returns 'Python'; it is a new string.

Exam traps

  • A slice stops before its second index. s[1:4] on 'python' has three characters, 'yth', not four.
  • s.upper() and s.replace(...) do not change s. The usual wrong answer to 'what is s now' is the transformed string; the correct answer is the original 'python'.
  • Negative index -1 is the last character, not the first. Reading s[-len(s)-1] raises IndexError.
  • find returns -1 when the substring is absent; index raises ValueError. They are not interchangeable.
  • isdigit() is False for an empty string and for a minus sign; '-12'.isdigit() is False.

3.2 String formatting, comparison, splitting and stripping

Formatting turns values into text; comparison orders text by Unicode code point; split, strip and join move between one string and many. These jobs appear together whenever a program reads a line from a file, cleans a CSV column, or prints a receipt. A UPI statement, for example, needs amounts formatted with commas, dates compared as text, and merchant names split and trimmed before matching. The rules are small but exact: one wrong space or one wrong case changes the result.

You need 3.1 for indexing, slicing and the base string methods.

Formatting values into text

Python has three formatting styles. The old % operator fills stand-ins: '%s scored %d' % ('Asha', 90) gives 'Asha scored 90'. str.format() uses braces: '{} scored {}'.format('Asha', 90). An f-string puts the expression inside the braces: f'{name} scored {marks}'. All three return a new string; the original is unchanged. f-strings are the usual choice in new code.

A format specification follows a colon inside the braces. Width is the minimum field size in characters. Alignment is left with a less-than sign, right with a greater-than sign, centre with a caret. A comma inserts thousands separators, and .2f keeps two digits after the decimal point. For example, f'{7:>4}' gives ' 7' (three spaces then 7), f'{0.256:.1%}' gives '25.6%', and f'₹{1234.5:,.2f}' gives '₹1,234.50'.

Width is a minimum, not a maximum: f'{12345:>4}' still prints all five digits. Precision for a float is digits after the point; for a string it is a maximum length. Named fields, such as '{amount:,.2f}'.format(amount=1234.5), make long templates readable.

Comparison: value and order

== compares the characters of two strings. 'abc' == 'abc' is True. is compares identity: whether two names refer to the same object. Two equal strings may or may not be the same object, so never use is to test text equality. Use ==.

Ordering is lexicographic. Python compares the first character of each string; if they differ, the smaller Unicode code point wins. If they are equal, it moves to the next character. A shorter string that is a prefix of a longer one sorts first: 'app' < 'apple' is True, and '' < 'a' is True.

The built-in ord() returns a code point. ord('A') is 65, ord('Z') is 90, ord('a') is 97, and ord('0') is 48. So every uppercase letter sorts before every lowercase letter, and digits sort before letters. 'Zebra' < 'apple' is True because 90 < 97. 'Apple' < 'apple' is also True because 65 < 97.

For a case-insensitive test, compare a.lower() == b.lower(). Use casefold() when text may contain non-English letters: 'STRASSE'.casefold() == 'straße'.casefold() is True. Sorting uses the same code-point rule; 3.9 covers sorted lists.

Split, strip and join

split() with no argument splits on runs of whitespace and drops empty pieces. ' a b '.split() gives ['a', 'b']. With a separator, empty pieces stay: 'a,,b'.split(',') gives ['a', '', 'b']. The second argument limits cuts: 'a,b,c'.split(',', 1) gives ['a', 'b,c']. rsplit() counts from the right. splitlines() splits on line boundaries and does not keep the newline characters.

strip() removes characters from both ends; lstrip() removes from the left and rstrip() from the right. With no argument it removes whitespace. With an argument it treats the argument as a set of characters, not as a word: 'abcba'.strip('ab') gives 'c', because every leading and trailing a or b is removed. It stops at the first character not in the set.

sep.join(iterable) is the inverse. ', '.join(['red', 'green', 'blue']) gives 'red, green, blue'. Every element must already be a string; ','.join([1, 2]) raises TypeError. Convert first with map(str, items) or a loop. This split-clean-join pattern is the standard way to tidy one line of CSV text before storing it. The result is a new string; the list is not changed.

Exam traps

  • strip('ab') removes any leading or trailing a and b characters, not the substring 'ab'. 'abcba'.strip('ab') gives 'c'.
  • split() with no argument drops empty pieces from runs of whitespace; split(' ') keeps them. On 'a b', the first gives 2 items, the second gives 3.

  • join needs strings; ','.join([1,2]) raises TypeError. map(str, items) converts first.
  • Format width is a minimum; it never truncates. f'{12345:>4}' prints all five digits.

3.3 Lists: operators, methods, aliasing and mutability

A list is a mutable ordered sequence: one name can hold many items, and the items can be changed after creation. Unlike a string, a list can grow, shrink and have any position replaced. This matters for marks, prices, sensor readings and UPI transaction logs, where a program collects many values and edits them as work proceeds. The main danger is that two names may point at one list, so a change through one name appears through the other.

You need 3.1 for indexing and slicing, and Unit 1 for assignment, id() and operators.

Literals, nesting and operators

A list literal is written in square brackets. Items are separated by commas and may have different types: [10, 'UPI', 3.5, True]. The empty list is []. A list is ordered, so each item has a position: index 0 is first, index -1 is last. Indexing and slicing work as for strings (see 3.1).

Lists can be nested. In marks = [[80, 75], [90, 88]], marks[1][0] is 90: first choose row 1, then column 0. A nested list is an item that is itself a list.

The operator + joins two lists into a new list; * repeats a list. Neither changes the original. in tests membership by equality. == compares length and then each pair of items; ordering (<, >) compares item by item, left to right, and stops at the first difference. A shorter prefix is smaller. For example, [1, 2] < [1, 3] is True and [1, 2] < [1, 2, 0] is True. Mixed types may raise TypeError because they cannot be ordered.

  • [1, 2] + [3] gives [1, 2, 3].
  • [0] * 4 gives [0, 0, 0, 0].
  • 3 in [1, 2, 3] is True.

Methods that change a list

Methods are functions attached to a list. The changing methods below — append, extend, insert, remove, pop, clear, sort, reverse — edit the same list object and return None. The non-changing methods index(x), count(x) and copy() return a value and leave the list as it is.

  • append(x) adds one item x at the end. extend(items) adds each item from items. a.append([4, 5]) adds one nested list; a.extend([4, 5]) adds two items.
  • insert(i, x) puts x before position i. remove(x) deletes the first item equal to x and raises ValueError if absent. pop() removes and returns the last item; pop(i) removes and returns position i.
  • clear() removes all items. index(x) returns first position of x and raises ValueError if x is absent; it never returns -1. count(x) counts equal items.
  • sort() sorts in place; sort(reverse=True) sorts descending. reverse() reverses in place. copy() returns a shallow copy.

sorted(a) returns a new sorted list and leaves a unchanged. a.sort() changes a and returns None. del a[i] deletes by position; del a[i:j] deletes a slice. Use remove by value, pop by index when you need the removed item, and del by position when you do not.

Aliasing and mutability

Assignment does not copy a list. In b = a, the name b is bound to the same object as a. id(a) gives the object's identity (its address in CPython); a is b returns True when both names point to one object. == compares contents, so equal lists can have different identities. A change through a, such as a.append(40), is visible through b. Some syllabi say b holds a reference to the same object; no copy, not even a shallow one, is made by assignment.

a[:] and a.copy() make a new outer list. For a flat list of numbers or strings, the copy is independent: changing one list does not change the other. This is a shallow copy: it copies the outer list only, not the objects inside it. If an item is itself a list, both copies still point to that inner list (some syllabi call this a surface copy).

Example: n = [[1], [2]]; m = n.copy(); m[0].append(5). Then n[0] is [1, 5] because n and m share the inner list. Adding m.append([3]) changes only m's outer list.

Exam traps

  • b = a does not copy: it binds a second name to one list. Use a[:] or a.copy() for a new outer list.
  • sort() returns None; sorted(a) returns a new list. Writing b = a.sort() sets b to None.
  • append([4, 5]) adds one nested list; extend([4, 5]) adds two items.
  • a[:] and a.copy() are shallow. For nested lists, use copy.deepcopy(a) from the copy module if you need independent inner lists.

3.4 List comprehension

A list comprehension builds a new list out of a loop, an optional filter and an expression, all on one line. Instead of creating an empty list, writing a for loop and calling append again and again, you write the transformation once and say which items it applies to. The result is a fresh list, so the original data is untouched. Python programmers use it constantly for small conversions: turning rupee amounts into paise, pulling names out of database rows, squaring a set of marks, keeping only the entries that pass a test.

You need: 3.3 Lists for creating, appending to and aliasing lists, and the for loop with range() from Unit 2.

The shape of a list comprehension

A list comprehension is a loop and an append squeezed into one expression. The loop walks an iterable, computes one value for each item, and appends that value to a new list.

[expr for item in iterable]

expr is the value stored, computed from item; item is the loop variable, a new name bound to each element in turn; iterable is anything a for loop can walk, such as range(1, 7), a string, or d.items() for a dictionary d. The brackets make one expression whose value is a new list.

  1. Evaluate the iterable once. range(1, 7) gives 1, 2, 3, 4, 5, 6.
  2. Bind item to the first value and compute expr.
  3. Append that result to the new list.
  4. Repeat for the remaining values, in order.
  5. Return the new list. The original iterable keeps its contents and its identity.

The loop version and the comprehension version give the same list. Compare them side by side:

Python program.

numbers = [1, 2, 3, 4, 5, 6]
doubled = []
for x in numbers:
    doubled.append(x * 2)
print(doubled)
print([x * 2 for x in numbers])

Output

[2, 4, 6, 8, 10, 12]
[2, 4, 6, 8, 10, 12]

Both printed lines are identical. The comprehension is shorter, but it does the same three things: loop, compute, append.

Filters, if-else inside the expression, and nesting

Add an if clause and the loop keeps only the items that pass the test. The item is computed only when the condition is true.

[expr for item in iterable if cond]

cond is any boolean expression written in terms of item. Items where cond is False are skipped completely; they never reach expr, so the new list is shorter than the old one.

The writing order inside the brackets is fixed: expression first, then the for clause, then the if clause. The expression itself may hold a conditional of the form a if c else b. That conditional is not a filter; it decides which value is stored for an item that is already being processed.

FormExampleResult
[expr for x in it][x * 2 for x in [1, 2, 3]][2, 4, 6]
[expr for x in it if cond][x for x in [1, 2, 3, 4] if x > 2][3, 4]
[a if c else b for x in it][x if x > 0 else 0 for x in [-1, 2]][0, 2]
two for clauses[i + j for i in range(1, 3) for j in range(1, 3)][2, 3, 3, 4]

Two for clauses act exactly like nested loops. The leftmost for is the outer loop and the next one is the inner loop. For i = 1 the inner loop gives j = 1 then j = 2, producing 2 and 3. For i = 2 it produces 3 and 4. The list fills as [2, 3, 3, 4]. Swapping the two for clauses changes the order of the results.

The if-else form needs its else. [x if x > 0 for x in data] is a SyntaxError, because the parser sees a conditional expression and finds no else to complete it.

Reading the result, and keeping it readable

A comprehension always creates a new list object. If another name points at the old list (see 3.3 Lists), the old list is not modified.

Python program.

marks = [45, 72, 30]
new = [m + 5 for m in marks]
print(marks)
print(new)
print(marks is new)

Output

[45, 72, 30]
[50, 77, 35]
False

Any iterable works as the source: a range, a string (each item is one character), or a dictionary's items, where each item is a key-value pair that you unpack into two names.

Python program.

word = "delhi"
print([c.upper() for c in word])
price = {"pen": 10, "book": 40}
print([name for name, cost in price.items() if cost > 20])

Output

['D', 'E', 'L', 'H', 'I']
['book']

Keep to one or two clauses. A line with three for clauses and two filters is correct but hard to debug, because you cannot print an intermediate value inside it. Write the plain loop instead and let the reader follow it.

Set and dictionary comprehensions reuse the same pattern with braces and a key-value pair; they are covered in 3.7 Sets and 3.6 Dictionaries. Generator expressions, which produce values one at a time instead of building a list, belong to Unit 4.

3.5 Tuples: creation and operations

A tuple is an ordered sequence that cannot be changed after creation. It stores a fixed group of values, such as (10, 20, 30), and keeps their order. Because no item slot can be replaced, the tuple's structure is safe to share between parts of a program. When every item is hashable, the whole tuple is hashable, so it can act as a dictionary key. You meet tuples in functions that return several values, in database rows, and in coordinates. The comma, not the brackets, makes the tuple.

You need: 3.3 Lists for sequence operators, slicing and shallow copying.

Creating a tuple

A tuple literal writes items inside parentheses and separates them with commas: t = (10, 20, 30). The parentheses group the items. The commas create the tuple.

An empty tuple is (). A one-item tuple needs a comma: (5,). Without the comma, (5) is the int 5, not a tuple. This small comma decides the type.

Brackets are optional in an assignment. t = 10, 20, 30 also creates a tuple. t = 10 creates an int. The built-in tuple(iterable) builds a tuple from any iterable: tuple([1, 2, 3]) gives (1, 2, 3), and tuple('abc') gives ('a', 'b', 'c').

  • tuple() gives the empty tuple ().
  • (40) is 40; (40,) is a one-item tuple. Use the comma in t + (40,).
  • A tuple can hold any objects, including other tuples and lists.

Reading and combining tuples

Indexing and slicing work as in a list: index 0 is the first item, negative indexes count from the end, and a slice stops before its end index. The table uses t = (10, 20, 30).

Immutability, unpacking and comparison

A tuple is immutable: its item slots cannot be assigned after creation. t[1] = 99 raises TypeError. The figure shows this lock on the second element of t.

Unpacking assigns items to names by position: a, b, c = t gives a = 10, b = 20, c = 30. The number of names must match the number of items. The swap a, b = b, a uses a tuple on the right side, so no temporary variable is needed.

A tuple can be nested: n = (1, (2, 3)); n[1][0] is 2. Comparison is element by element. Python compares the first item, then the second, and so on. (1, 2) < (1, 3) is True. If one tuple is a prefix of the other, the shorter one is smaller: (1, 2) < (1, 2, 3) is True.

A tuple is hashable when every item is hashable. A hashable tuple can be a dictionary key, as in d[(10, 20)] = 'point'; see 3.6. A tuple that contains a list is not hashable. The lock is on the tuple's own slots; a mutable object inside can still change.

3.6 Dictionaries: adding, accessing and removing keys

A dictionary maps unique keys to values. The key is the label you look up; the value is what comes back. It exists because many problems are lookups, not positions: a roll number to a name, a word to a count, a product code to a price. A dictionary does that lookup by key, so you do not scan items one by one. Getting, adding, replacing and deleting all use the key. Current Python keeps insertion order, so printing a dictionary shows pairs in the order you added them.

You need: 3.1 for string keys, 3.5 for tuple keys, and 3.3 for views, copying and aliasing.

Building a dictionary

A dictionary is a collection of key–value pairs. Write a literal with braces, a colon between a key and its value, and commas between pairs: d = {'a': 10, 'b': 20}. Here 'a' and 'b' are keys; 10 and 20 are values. A key is the label you look up; a value is the data stored under it.

dict() builds the same object in other ways. dict(a=10, b=20) makes keys 'a' and 'b' from the names. dict([('a', 10), ('b', 20)]) takes a list of two-item pairs. Both give {'a': 10, 'b': 20}.

Keys must be hashable. A hashable object has a stable hash value and can be compared for equality; the dictionary uses that to find a slot. int, str and a tuple of immutable hashable items are allowed. A list is not hashable, so [1, 2] cannot be a key; see 3.5 for tuple keys.

Current Python keeps insertion order. Add 'c' after 'a' and 'b', and printing shows 'a', 'b', 'c'. Order does not change lookup: d['b'] goes straight to 20.

Access uses square brackets: d[k] returns the value stored under key k. If k is absent, Python raises KeyError. That error means the key was never added, or it was removed.

Finding, adding and replacing

d[k] is strict. d.get(k) returns the value if k exists and None if k is missing. d.get(k, default) returns default instead of None. Use get when a missing key is normal, such as a new word in a word count. Use brackets when a missing key is a bug you want to see.

The in test checks keys only: 'a' in d asks whether 'a' is a key. It never checks values. To test values, use 10 in d.values(); that scans values.

Assignment adds or replaces. d['c'] = 30 adds key 'c' with value 30. d['a'] = 99 replaces the value for existing key 'a'. A key is not duplicated; one key has at most one value.

keys(), values() and items() return views. A view looks at the live dictionary; a later change appears in the view. items() gives pairs, so for k, v in d.items(): unpacks key and value. update() adds or replaces many pairs from another dictionary or from pairs. len(d) counts pairs. Some syllabi call these mapping operations.

Removing, copying and a comprehension

del d[k] removes the pair for k. If k is missing, it raises KeyError. d.pop(k) removes and returns the value; a missing key raises KeyError. d.pop(k, default) returns default and does not raise if k is missing. d.popitem() removes and returns the last inserted pair as a tuple (key, value). d.clear() removes all pairs.

Assignment with = does not copy a dictionary. e = d makes e another name for the same object, so a change through e is visible through d; this is aliasing, as in 3.3. e = d.copy() makes a new dictionary with the same pairs. The copy is shallow: if a value is a list, both dictionaries point at that one list.

A dictionary comprehension builds a dictionary in one line: {x: x*x for x in range(1, 4)} gives {1: 1, 2: 4, 3: 9}. The part before the colon is the key expression; the part after is the value expression.

3.7 Sets and set operations

A set is an unordered collection of unique items. You cannot index it, but you can ask whether a value is inside, and you can combine two sets with union, intersection, difference and symmetric difference. Sets exist because some questions are about membership and overlap, not order: which students joined both the Python club and the coding contest, which UPI transaction ids appear twice in a log. Python stores a set in a hash table, so a membership test stays fast even when the set holds lakhs of items.

You need: 3.3 for mutability and 3.5 for why a tuple of numbers is hashable but a list is not.

What a set is, and how to build one

A set holds each value at most once and gives no position to any value. A set literal uses braces: A = {1, 2, 3} makes a set of three integers. Braces alone are ambiguous, because {} is an empty dictionary, so the empty set is written set().

The constructor set(iterable) builds a set from any sequence and drops duplicates silently. set([3, 1, 3, 2, 1]) gives {1, 2, 3}. set("banana") gives {'b', 'a', 'n'}.

  • There is no indexing and no slicing. A[0] raises TypeError, because a set keeps no order.
  • Iteration order is not guaranteed. A for loop over a set can visit the items in a different order on a different run, so never depend on it.
  • Only hashable items fit. Numbers, strings and tuples of hashable items are fine; a list or a dictionary is rejected, because it can change after it is stored.

Deduplication is the everyday use. Collect the UPI transaction ids of one day into a list, pass the list to set(), and len() of the result is the number of distinct payments. Convert back with sorted() when a fixed order is needed.

Adding, removing and testing membership

A.add(x) inserts x; if x is already there, nothing changes and no error is raised. A.remove(x) deletes x and raises KeyError when x is absent. A.discard(x) deletes x and says nothing when x is absent. A.pop() removes and returns an arbitrary item, not the smallest or the first. A.clear() empties the set, and len(A) counts the items.

The in test is the reason sets exist. x in A costs about the same for ten items and for ten lakh items, because Python hashes x, computes a slot and looks there. A list has to compare items one by one; see 3.9.

Union, intersection, difference and subset tests

Four operators combine two sets. Union A | B holds every item of either set. Intersection A & B holds the items in both. Difference A - B holds the items of A that are not in B. Symmetric difference A ^ B holds the items in exactly one of the two sets.

Each operator has a method form: A.union(B), A.intersection(B), A.difference(B), A.symmetric_difference(B). The methods accept any iterable, so A.union([7, 8]) works. The operators need a set on both sides, so A | [7, 8] raises TypeError.

Comparison operators test whole-set containment. A <= B is True when every item of A lies in B, that is A is a subset of B. A >= B is True when A contains every item of B, that is A is a superset. A < B and A > B are the strict forms and are False when the two sets are equal. A.isdisjoint(B) is True when the sets share no item.

frozenset is the immutable twin: F = frozenset({1, 2}). It has the same read-only methods and the same operators, but no add or remove. Because it never changes, it is hashable, so it can be a dictionary key or an item of another set. Only a few universities ask for it in depth.

Worked example

Question. A = {1, 2, 3, 4} and B = {3, 4, 5}. Find A | B, A & B, A - B, B - A, A ^ B, state whether A <= B is True, and convert the list [3, 1, 3, 2, 1] into a set. Say what the size of that last set is.

  2. A & B keeps only items present in both: 1 is missing from B, 2 is missing from B, 3 and 4 are in both. So A & B = {3, 4}, 2 items.
  3. A - B keeps items of A that are not in B: 1 and 2. So A - B = {1, 2}, 2 items.
  4. B - A keeps items of B that are not in A: only 5. So B - A = {5}, 1 item.
  5. A ^ B keeps items in exactly one set: from A that is 1 and 2, from B that is 5. So A ^ B = {1, 2, 5}, 3 items.
  6. A <= B asks whether every item of A is in B. Check each item: 1 is not in B, so the answer is False. (2 is missing too.)
  7. set([3, 1, 3, 2, 1]) inserts 3, skips the second 3, inserts 1, inserts 2 and skips the second 1. The set is {1, 2, 3}, so the size is 3.

  • A <= B means subset, not 'numerically smaller'. A < B is strictly smaller as a set, so it is False when A and B hold the same items.

3.8 Lists as stacks and queues

A list can grow at its right end and shrink from either end. That makes one list serve two classic containers. Add with append and remove with pop() and you get a stack: last in, first out. Add with append and remove with pop(0) and you get a queue: first in, first out. Undo buttons, browser back navigation, bracket checkers, printer jobs and ticket lines all use one of these two patterns.

You need 3.3 for append, pop and list indexing.

A stack removes the newest item

A stack is a container with one working end, called the top. Push puts an item on top. Pop removes and returns the top item. Peek reads the top without removing it. The rule is last in, first out (LIFO): the item pushed most recently is the first one popped.

A Python list already has every operation a stack needs. Push x with s.append(x). Pop with top = s.pop(). Peek with top = s[-1]. Test empty with len(s) == 0. No class is required here; Unit 4 shows the class version.

  1. Push x: s.append(x) adds x at the right end.
  2. Pop: top = s.pop() removes and returns the rightmost item.
  3. Peek: top = s[-1] reads the rightmost item without removing it.
  4. Empty test: len(s) == 0 is True when the stack holds no items.

Undo in an editor is a stack: each edit is pushed, and undo pops the latest edit. The browser back button works the same way. A bracket checker pushes every opening bracket and pops on every closing bracket. A function call stack, which Unit 2 covers under recursion, also follows LIFO.

A queue removes the oldest item

A queue is a container with two ends: rear for entry and front for exit. Enqueue adds at the rear. Dequeue removes and returns from the front. The rule is first in, first out (FIFO): the item that waited longest leaves first.

On a list, enqueue x with q.append(x). Dequeue with first = q.pop(0). The call pop(0) removes index 0 and shifts every remaining item one place left, so it costs O(n) time on a list of n items.

T(n) = O(n) for q.pop(0)

n is the number of items in q; every item after index 0 shifts one place left, so the work grows in proportion to n.

When a queue is long and dequeues are frequent, that shifting matters. collections.deque provides append and popleft, both O(1). Only a few syllabi require deque at this stage.

A printer queue is FIFO: the first document sent is printed first. A ticket counter line is FIFO. Breadth-first search, covered in Unit 6, uses a queue to visit nodes level by level.

Empty pops and the right end

Both pop() and pop(0) raise IndexError when the list is empty. Check len(s) == 0 or not s before popping. The same check protects a queue.

The two patterns differ only in which end they remove from. Stack: append right, pop right. Queue: append right, pop left. Mixing them gives the wrong order. Using s.pop(0) as a stack is not LIFO. Using q.pop() as a queue is not FIFO.

Worked example

Question. A list s = [] is used as a stack. Run s.append(10), s.append(20), s.append(30), then p = s.pop(), then read s[-1]. Next a list q = [] is used as a queue. Run q.append('A'), q.append('B'), q.append('C'), then r = q.pop(0). Give p, s, s[-1], r and q.

  1. Start s = []. After append(10): s = [10]. After append(20): s = [10, 20]. After append(30): s = [10, 20, 30]. Top is index 2.
  2. p = s.pop() removes the last item, 30. So p = 30 and s = [10, 20]. The new top is index 1.
  3. s[-1] reads the last item without removal, so s[-1] = 20.
  4. Start q = []. After the appends: q = ['A', 'B', 'C']. Front is index 0.
  5. r = q.pop(0) removes index 0, 'A'. So r = 'A' and q = ['B', 'C']. Length of q is 2.

Exam traps

  • pop() removes the newest item for a stack; pop(0) removes the oldest item for a queue. Swapping them reverses the order.
  • pop(0) costs O(n) on a list because every remaining item shifts left; pop() at the end costs O(1).
  • Both pop() and pop(0) raise IndexError on an empty list; check len(s) == 0 or not s first.
  • append adds at the right end for both patterns. A queue is not made by insert(0, x), which also costs O(n).
  • A stack is LIFO and a queue is FIFO; exam questions often ask which end is removed, not which end is added.

3.9 Searching and sorting lists: linear and binary search

Searching answers one question: where is this value in the list, and is it there at all? Sorting puts a list in order so later work gets easier. You meet both constantly — a roll number in a class list, a name in your phone contacts. This chapter writes two searches in Python, compares their costs, and shows how Python sorts a list and how a simple exchange sort works by hand. Linear search checks items one by one; binary search throws away half the list at every step and needs the list sorted first.

You need: 3.3 Lists for indexing, len and slicing, and Unit 2 for while and for loops.

Linear search: compare items one at a time

Linear search starts at index 0 and compares each item with the target, returning the index of the first match. If nothing matches, it returns -1 as a "not found" signal. Real positions run from 0 to n-1, so -1 never collides with a position that was actually found. Careful: Python allows negative indexing, so a[-1] is the last item — always test the returned value against -1 before using it as an index. A few syllabi call this sequential search.

  1. Set i = 0.
  2. If i has reached len(a), stop and return -1.
  3. Compare a[i] with the target; if they are equal, return i.
  4. Add 1 to i and repeat from step 2.

Cost: one comparison in the best case (target at index 0), n in the worst case, where n = len(a), when the target is last or absent, and about n/2 on average. Time is O(n): double the list and the work roughly doubles. Linear search needs no sorted data, so it works on any list.

These versions return a pair (index, comparisons); index is the position of the first match, or -1 when the target is absent. The counter is added only to show the cost.

Python program.

def linear_search(a, target):
    comparisons = 0
    for i in range(len(a)):
        comparisons += 1
        if a[i] == target:
            return i, comparisons
    return -1, comparisons

big = list(range(1, 1001))
print(linear_search(big, 1000))
print(linear_search(big, 0))

Output

(999, 1000)
(-1, 1000)

The run returns index 999 after 1000 comparisons, and -1 after 1000 comparisons for a value that is not there.

Binary search: halve a sorted list

Binary search works only on a sorted list. It looks at the middle item and discards the half that cannot hold the target, so one comparison removes half the remaining items and the work grows with log₂ n instead of n.

mid = (low + high) // 2

low and high are the first and last indices of the part still in play; // is floor division, so mid is a whole-number index.

  1. Set low = 0 and high = len(a) - 1.
  2. While low ≤ high, compute mid = (low + high) // 2.
  3. If a[mid] equals the target, return mid.
  4. If a[mid] < target, the target can only lie to the right: set low = mid + 1.
  5. Otherwise set high = mid - 1.
  6. When low > high the part is empty: return -1.

Each comparison halves the count: n → n/2 → n/4 → ... → 1. That is log₂ n halvings, so about log₂ n comparisons in the worst case. For n = 1000, log₂ 1000 ≈ 9.97, about 10 comparisons against 1000 for linear search. The price is that the list must already be sorted.

Python program.

def binary_search(a, target):
    low, high = 0, len(a) - 1
    comparisons = 0
    while low <= high:
        mid = (low + high) // 2
        comparisons += 1
        if a[mid] == target:
            return mid, comparisons
        if a[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1, comparisons

big = list(range(1, 1001))
print(binary_search(big, 1000))
print(binary_search(big, 0))

Output

(999, 10)
(-1, 9)

Same 1000 items, same targets: 10 and 9 comparisons instead of 1000.

Sorting: list.sort(), sorted(), bubble sort and selection sort

Python sorts two ways. L.sort() rearranges the list in place and returns None. sorted(L) builds a new sorted list and leaves L untouched. Both accept reverse=True and key=, a function whose return value is used for comparison.

Python program.

marks = [("Asha", 78), ("Ravi", 92), ("Meera", 65)]
marks.sort(key=lambda p: p[1], reverse=True)
print(marks)
print(sorted([3, 1, 2]))
nums = [3, 1, 2]
out = nums.sort()
print(nums, out)

Output

[('Ravi', 92), ('Asha', 78), ('Meera', 65)]
[1, 2, 3]
[1, 2, 3] None

Read the last line twice: nums.sort() returned None, so nums = nums.sort() would wipe out the list. Python's sort is Timsort, a hybrid of merge sort and insertion sort: it finds short sorted runs, extends them by insertion sort, then merges them. Worst case n log₂ n comparisons, best case n on already-sorted data.

Bubble sort swaps neighbours that are out of order and repeats until a full pass makes no swap. On [5, 1, 4, 2]:

1[1, 4, 2, 5]3
2[1, 2, 4, 5]1

Selection sort finds the smallest item, swaps it to the front, and repeats on the rest: [5, 1, 4, 2] → [1, 5, 4, 2] → [1, 2, 4, 5]. Both are O(n²), taught to show the idea; Python's built-in sort beats them on real data.

Question. L = [3, 9, 14, 21, 27, 33, 40]. Search for 27 with linear search and with binary search. Give the index and the number of comparisons for each. Then state how many comparisons each search needs for 1,000 items in the worst case.

  1. Linear search: compare a[0] = 3 (no), a[1] = 9 (no), a[2] = 14 (no), a[3] = 21 (no), a[4] = 27 (yes). 5 comparisons, index 4.
  2. Binary search: low = 0, high = 6, mid = (0 + 6) // 2 = 3. a[3] = 21 < 27, so low = 4. 1 comparison.
  3. low = 4, high = 6, mid = 5. a[5] = 33 > 27, so high = 4. 2 comparisons.
  4. low = 4, high = 4, mid = 4. a[4] = 27, match. 3 comparisons, index 4.
  5. 1,000 items: linear search needs up to 1,000 comparisons; binary search needs about ⌈log₂ 1000⌉ = 10, since 2¹⁰ = 1024 ≥ 1000.

Answer. Linear search finds 27 at index 4 in 5 comparisons; binary search finds it at index 4 in 3 comparisons. For 1,000 items the worst case is 1,000 comparisons against about 10.

Exam traps

  • Binary search on an unsorted list returns a wrong answer with no error message. Sort first, or use linear search.
  • Writing low = mid instead of low = mid + 1 can loop forever: when low meets high, mid equals low and the range never shrinks.
  • L.sort() returns None. The line L = L.sort() leaves L as None and the next statement crashes.
  • Sorting just to run one binary search costs n log₂ n, more than one linear search at n. Sorting pays off only when you search the same list many times.
  • Always check the returned index against -1 before indexing: a[-1] is a legal Python item, not an error.

Takeaways

  1. A string is a sequence, so every read works by index or slice, but no assignment ever changes the original object.
  2. Formatting, splitting, stripping and joining are the four moves that convert between one string and many strings.
  3. A list variable stores a reference, so assignment copies the reference and not the contents, which is the root of most aliasing bugs.
  4. A list comprehension packs a loop, a filter and an expression into one readable line and returns a fresh list.
  5. A tuple is the right choice when a group of values travels together and must not be changed.
  6. Dictionary access, insertion, replacement and deletion all work by key, and all average O(1) time.
  7. Sets answer questions about membership, duplicates and overlap faster than any list loop.
  8. Choosing append with pop for a stack is cheap, but append with pop(0) for a queue is O(n) per removal.
  9. Binary search is faster than linear search only when the list is already sorted and random access is available.
