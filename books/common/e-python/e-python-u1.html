1.1 Problem solving: algorithms, flowcharts and pseudocode

A program is written twice. The first writing is a plan: a list of plain steps that says what goes in, what is done with it, and what comes out. The second writing is code. The plan is cheap to change; code is not. So the plan carries an algorithm (finite, ordered, unambiguous steps with a clear stop), a flowchart (those steps as a picture), and pseudocode (those steps in plain English). A problem analysis chart sorts the inputs, outputs and processing before either. Every program, from a shop bill to a UPI payment, passes through this stage.

Algorithm: a list of steps that stops

An algorithm is a finite, ordered set of unambiguous steps that has a clear stop. Four words carry the weight. Finite: it ends. Ordered: step 3 runs after step 2. Unambiguous: two people reading it take the same action. Stop: there is a defined end point.

Every algorithm is built from three control constructs:

  • Sequence: do A, then B, then C.
  • Selection: if a condition holds, take one path, otherwise the other.
  • Repetition: repeat steps while a condition holds.

A shop bill is pure sequence. A pass/fail mark sheet needs selection. Adding the prices of 100 items needs repetition. Every program you will write is a mix of these three.

Flowchart: the algorithm as a picture

A flowchart draws the steps and joins them with arrows that show the order. Each shape has one fixed job.

SymbolMeaning
OvalStart or stop
ParallelogramInput or output
RectangleProcess (a calculation or assignment)
DiamondDecision, one arrow out per answer

A diamond has two exits, labelled Yes and No. A rectangle has one exit. A flowchart is read from the start oval downwards; every path must reach a stop oval. If two paths exist, both must end.

Pseudocode and the problem analysis chart

Pseudocode writes the steps in plain English with a fixed shape. Keywords go in capitals and indentation shows what is inside a block: IF condition THEN ... ELSE ... ENDIF for selection, WHILE condition ... ENDWHILE for repetition. Pseudocode is language-free, so it never contains Python syntax.

Pseudocode.

READ pens, notebooks
bill ← pens × 12 + notebooks × 45
PRINT bill

Some syllabi call the written plan a problem analysis chart: four boxes for inputs, required outputs, processing, and alternative solutions. Fill the boxes before you draw anything. The processing box is where the algorithm is born.

Worked example

Question. A shop sells a pen for ₹12 and a notebook for ₹45. Write pseudocode and draw the plan for a program that reads the number of pens and notebooks bought and prints the bill. Test the plan with 3 pens and 2 notebooks.

  1. Inputs: pens = 3 and notebooks = 2. Unit prices: pen = ₹12, notebook = ₹45.
  2. Pen cost = 3 × 12 = ₹36.
  3. Notebook cost = 2 × 45 = ₹90.
  4. Bill = 36 + 90 = ₹126.
  5. Output: print ₹126 and stop.

Answer. The bill for 3 pens and 2 notebooks is ₹126.

Worked example 2

Question. Write the pseudocode that would print Pass if total ≥ 40 and Fail otherwise.

  1. The plan needs selection, because one of two outputs is chosen.
  2. IF total ≥ 40 THEN PRINT Pass ELSE PRINT Fail ENDIF.
  3. In a flowchart this is one diamond with two labelled exits, each leading to its own output parallelogram.

Answer. Selection, written with IF ... THEN ... ELSE ... ENDIF.

Exam traps

  • A decision drawn in a rectangle: the branches disappear and the marks go with them.
  • Writing Python syntax such as print(x) inside pseudocode. Pseudocode is language-free.
  • Forgetting the stop oval, or leaving one branch of a decision without a stop.
  • Calling a process an input. Parallelogram for reading or printing, rectangle for calculating.
  • Writing steps that never end or are vague ("add the prices till done"). That is not an algorithm.

1.2 Introduction to Python: need, history and first program

Python is a programming language built on one trade: you type fewer symbols, and the computer works harder to read them. A clear two-line program does real work with no header, no semicolons and no main function. Python is free, open source, and runs on Windows, Linux and macOS. That mix made it the default first language in colleges and the default glue language in industry: web back ends, data reports, automation. This chapter covers why it exists, where it came from, and your first program.

You need: 1.1 for the idea of a step-by-step plan written before the code.

Why Python exists

Every program has two readers: the machine that runs it and the human who must fix it next month. Python's design chooses the human. It drops almost everything that exists only for the compiler: header files, type declarations before each variable, a semicolon at the end of every line, a main function to hold the first statement. What is left reads close to English.

The trade is real. Python is slower than C in tight arithmetic loops, often by a large factor. Most programs do not spend their time there. They wait on a disk read, a network reply, or a person typing, and a faster language buys nothing. A shop script that reads a UPI sales export, adds the rows and prints the day's total finishes in under a second in any language; what matters is that the owner can read the script and change it.

Python is free and open source. Anyone can download it from python.org at no cost, read its source code and pass on a modified copy. There is no licence fee per machine, which matters for a lab with 60 computers and for a small startup alike.

The same program runs on Windows, Linux and macOS with few changes. Python also ships with a large standard library — modules for files, dates, arithmetic, text and network access — already installed, so a beginner can read a data file or fetch a web page without adding anything. That is why Python appears in web back ends, data analysis, automation and teaching: one language, many jobs.

History: the dates that matter

Guido van Rossum, a Dutch programmer, began Python in the late 1980s at a research institute in the Netherlands. He wanted a language that read easily and still did serious system work on Unix. He named it after Monty Python's Flying Circus, the British comedy group, not after the snake. The name is short, and the official tutorials keep the joke alive with example names such as spam and eggs.

Five years carry this story: 1991, the first public release; 2000, Python 2.0; 2008, Python 3.0; 2010, Python 2.7; and 2020, the end of Python 2 support. Python 3.0 arrived in December 2008 and was deliberately not backward compatible: it repaired old design flaws, most visibly turning print from a statement into a function and separating text from binary data. Python 2.7, released in 2010, was the last of the 2.x line, and support for Python 2 ended on 1 January 2020.

One practical rule follows. Write Python 3. Any tutorial or note that shows print "Hello" without brackets is Python 2 and predates 2020; in Python 3 that line is a syntax error. The timeline below shows both lines and the long overlap, 2008 to 2020, when working code had to be checked for which version it targeted.

Four features you feel immediately

  • Interpreted. The interpreter runs your file statement by statement, top to bottom, with no compile-and-link step that you can see. Behind the scenes it first turns the whole file into bytecode, an internal instruction list, and then executes it; your workflow is simply edit, run, read the output.
  • Dynamically typed. The type belongs to the value, not to the name. A name can hold an integer on one line and a string on the next, with nothing declared in advance. Type mistakes therefore appear while the program runs, not before it starts; see 1.5.
  • Blocks by indentation. There are no braces. The spaces at the start of a line decide which block that line belongs to, so indentation is grammar, not decoration; see 1.7.
  • Automatic memory management. You create values and Python frees their memory once nothing refers to them. There is no malloc, no free and no dangling pointer to worry about.

Readability is the goal behind all four: short programs, obvious structure, few symbols.

Your first program

Here is a complete Python program. It is the whole file; nothing is hidden or assumed.

Python program.

print("Hello, India")
print("-" * 10)

Output

Hello, India
----------

Line 1 calls print, a built-in function that writes its arguments to the screen and then starts a new line. Its argument is the string "Hello, India", the text between the double quotes. The quotes mark where the string starts and ends; they are not printed.

Line 2 prints ten dashes. "-" is a one-character string, 10 is an integer, and * between a string and an integer repeats the string that many times, so "-" * 10 evaluates to "----------". print writes that and moves to a new line.

Save the two lines in a file named hello.py. The .py extension marks it as Python source, and hello is a name you choose. Run it and the screen shows exactly the two lines above, in that order, with nothing extra: no prompt, no quotation marks, no blank line at the top. There is no header, no semicolon, no main function and no declaration. How to run the file from a terminal or an editor is in 1.3; what the error messages mean is in 1.8.

Worked example

Question. Write a Python 3 program of exactly two statements. The first prints Hello, India. The second prints a line of exactly 10 dashes. Show the code, name the file you would save it in, and write the exact screen output.

Python program.

print("Hello, India")
print("-" * 10)
  1. Statement 1: print("Hello, India"). The text inside the double quotes is a string of 12 characters. print sends it to the screen and starts a new line. The quotes themselves are not printed.
  2. Statement 2: print("-" * 10). The string "-" holds 1 character. The * operator with a string on the left and an integer on the right repeats the string: "-" * 10 gives a string of 1 × 10 = 10 characters, all dashes, written "----------".
  3. The file holds two lines of code and is saved as hello.py. The .py extension marks it as Python source.
  4. The interpreter runs line 1, then line 2, in that order. Each print ends with a newline, so the two results land on separate lines.
  5. Screen output, exactly: line 1 is Hello, India; line 2 is 10 dashes. No prompt, no quotes, no blank line before line 1.

Output

Hello, India
----------

Answer. The saved file hello.py prints Hello, India on line 1 and exactly 10 dashes on line 2.

  • print "Hello" is Python 2. Python 3 needs print("Hello"); dropping the brackets gives SyntaxError: Missing parentheses in call to 'print'.
  • Python is named after the comedy group Monty Python, not the snake. This is a standard one-mark question with a planted wrong option.
  • "Python is never compiled" is false. The standard interpreter first compiles the file to bytecode, then interprets that; the exam word is interpreted, but the compile step is real.
  • Python 2 support ended in January 2020, so any answer using print as a statement or input through raw_input counts as outdated.

1.3 Python interpreter: interactive and script mode

Python code can be fed to the interpreter in two ways. In interactive mode you type one line at the >>> prompt and the answer appears at once. In script mode you save many lines in a file, such as area.py, and run the file with python area.py. Both use the same interpreter and the same rules. The practical difference is memory: an interactive answer disappears when you exit, while a saved script keeps the steps for tomorrow.

You need: 1.2 for a first program to run.

Two ways to feed the interpreter

A Python interpreter is the program that reads Python code and carries out its instructions. You can give it code in two ways. Interactive mode feeds one line at a time and answers at once. Script mode feeds a whole file, saved with a name such as area.py. The interpreter is the same in both modes; only the source of the lines changes.

Interactive mode is also called the REPL: Read, Evaluate, Print, Loop. It reads one line, evaluates it, prints a result when there is one, and loops back for the next line. The prompt >>> marks where you type. Script mode has no >>> prompt in the file. The file is plain text, and the command python area.py asks the interpreter to run it.

The choice is about what must survive. A quick test of one expression belongs at the prompt. A calculation you must repeat tomorrow belongs in a saved file. IDLE is one editor that can open both a shell and a file; it is not a third mode.

Interactive mode: the >>> prompt

Start Python with no file name: python or python3. The screen shows a prompt >>>. Type 12 * 8 and press Enter. The interpreter evaluates the multiplication and prints 96 on the next line. A new >>> prompt appears. That is one turn of the REPL.

An expression typed at the prompt is printed automatically. An assignment such as x = 12 prints nothing, because the job is to store the name, not to show a value. After the assignment, typing x * 8 prints 96. The name x lives in that session only. Closing the session, by exit() or the keyboard end-of-file key, clears it.

Interactive mode is good for small checks: a unit conversion, a slice of a string, a doubt about operator order. It is poor for a long program, because the lines are not saved by default. A new session starts with no names from the old session. Use it as a scratch pad, not as a notebook unless you save the text yourself.

>>> 12 * 8
96
>>> x = 12
>>> x * 8
96
>>> exit()

Script mode: save, run, repeat

Script mode starts with a file. Open an editor, type the program, and save it with a .py ending, for example area.py. Put one instruction on each line. This file is the source code. The file can be opened, changed, copied and run again.

Run the file from a terminal in the folder that contains it: python area.py. On some systems the command is python3 area.py or py area.py. The interpreter reads the file from top to bottom, executes each line, and sends any print output to the screen. When the last line finishes, the program ends and its names are gone from memory.

The file survives. Running python area.py again repeats the same steps. That is the reason to use script mode for homework, lab records and real programs. If the interpreter reports an error, it gives a line number and a message; reading those is the first step of debugging. Full error families are in 1.8.

Exam traps

  • A name typed at the prompt is still there tomorrow. A new session starts with an empty namespace; only a saved script repeats the steps.
  • Typing print(12 * 8) at the prompt and expecting silence. It prints 96; the expression 12 * 8 also prints 96 because the REPL prints expression values.

  • Calling IDLE a third mode. IDLE is an editor and a shell; the two modes are interactive and script.

1.4 Variables, keywords and identifiers

A variable is a name stuck onto a value. Assignment creates the name: price = 45 makes the name price point to the value 45. Python needs no type declaration. The same name can hold an integer now and a string later; this is dynamic typing. The name itself must follow fixed rules. It may use letters, digits and underscore, but it cannot start with a digit, cannot contain a space or hyphen, cannot be a keyword, and is case sensitive. These rules keep names readable and stop clashes with Python's own words.

You need: 1.3, interactive and script mode, where names live while the file runs.

Assignment creates a name

An assignment has a left side (a name) and a right side (an expression). Python evaluates the right side first, then binds the name to that value. price = 45 evaluates 45, then binds price to 45 (rupees). qty = 3 binds qty to 3 (items). bill = price * qty evaluates 45 × 3 = 135, then binds bill to 135 (rupees). No separate declaration line is needed. The first assignment is the declaration.

Python is dynamically typed. x = 10 makes x hold an integer. x = "ten" rebinds the same name x to a string. The old integer is unchanged; x now points to a new value. The type belongs to the value, not to the name. What a name may hold is covered in 1.5.

Multiple assignment binds several names in one line. x = y = 5 binds x to 5 and y to 5. The swap a, b = b, a evaluates the right side as a pair first, then rebinds the names; it needs no temporary variable. del removes a name: del x makes x unknown until a new assignment. Scope and lifetime are in Unit 2; mutability and object identity are in Unit 3.

Use snake_case for ordinary names: total_marks, unit_price, student_count. Lowercase words joined by underscores read well.

Identifier rules and keywords

An identifier is a name you give to a variable, function, class or module. The rules are fixed.

  • Allowed characters are a–z, A–Z, 0–9 and underscore _.
  • The first character cannot be a digit. _temp is valid; 2nd_rank is not.
  • Spaces and hyphens are not allowed. my-var is invalid; my_var is valid.
  • Case matters. Total and total are two different names. Price and price are different.
  • A keyword cannot be used as an identifier. class is a keyword; class_ is not.

An identifier may contain digits after the first character: roll_no_2 is valid. Keywords are words Python reserves for its own syntax; some syllabi call them reserved words. Common keywords are: False, None, True, and, as, assert, break, class, continue, def, del, elif, else, except, finally, for, from, global, if, import, in, is, lambda, not, or, pass, raise, return, try, while, with, yield. The exact set changes with the Python version. help('keywords') prints the set for your interpreter. If a name is not a keyword and follows the character rules, it is legal.

Reading a NameError

A name has no value before its first assignment. If you print total before total = 0, Python raises NameError: name 'total' is not defined. It does not use 0, a blank string or any default. The error names the missing identifier. To fix it, assign a value first. NameError is a runtime error; see 1.8 for error families.

A keyword used as a name gives SyntaxError at the point Python parses the line, before any assignment runs. For example class = 10 is invalid; use class_name = 10. Case slips create a NameError too: Total = 10 then print(total) fails because Total and total differ. A hyphen creates SyntaxError: my-var = 5 is read as my minus var.

  • A keyword is never an identifier. class = 10 fails, but class_name = 10 works.

1.5 Data types: numbers, strings and booleans; type conversion

Every value in a Python program carries a type. The type decides what the value can do: 42 can be added to another number, "42" cannot. The three families you meet first are numbers, strings and booleans. Type conversion changes a value from one type to another on purpose, and Python also converts silently when an int meets a float. This shows up at every keyboard: input() hands you text, a price needs a float, and a test needs True or False. Knowing the type of a value tells you what a line will do before you run it.

You need: Chapter 1.4, because a name must exist before it can hold a typed value.

type() reports the kind of a value

Python stores each value with a label that says what kind of value it is. The built-in function type() reports that label. It takes one value in brackets and returns a type object.

1.6 Operators, expressions and order of operations

Python works out every expression by two fixed rules: precedence decides which operator acts first, and associativity decides what happens when two operators are on the same rung. Without those rules, 2 + 3 * 4 would have no single value. The rules matter everywhere — a bill total, a percentage, a marks average, a UPI amount split three ways — because a wrong grouping gives a wrong number silently, with no error message. This chapter names the parts of an expression, lists the precedence ladder from ** down to or, and walks one expression through its tree step by step.

You need: 1.5, since the types of the two operands decide the type of the result.

Operands, operators and expressions

An operand is a value that an operator works on. An operator is the symbol that does the work. An expression is operands joined by operators, and Python reduces the whole thing to one value. In 7 - 2, the operands are 7 and 2, the operator is -, and the value of the expression is 5. A bare value such as 42 is also an expression, the shortest one.

OperatorNameExampleValue

Read the table with the signs in mind. / is true division and always gives a float, even when it divides exactly: 8 / 2 is 4.0, not 4. // is floor division, % is the remainder left after that division, and ** is a power, so 7 ** 2 means 7 × 7.

Precedence and left-to-right order

An expression with several operators still has one correct value, fixed by two rules. Precedence says which operator grabs its operands first. Associativity says what happens when two operators share the same precedence: almost all of them go left to right. The ladder, highest first:

  • ** power
  • unary minus, a minus used as a sign, as in -x
  • * / // %
  • + and -
  • comparisons: < <= > >= == !=
  • not, then and, then or

Same rung means left to right: 20 - 5 - 3 is (20 - 5) - 3 = 12, not 20 - (5 - 3) = 18. Two rungs break that habit. Power is right associative, so 2 ** 3 ** 2 is 2 ** 9 = 512, not 8 ** 2 = 64. And unary minus binds looser than power, so -2 ** 2 is -(2 ** 2) = -4, not 4. Write (-2) ** 2 when you want 4.

Parentheses override the whole ladder, and they cost nothing but two brackets. When the grouping is not obvious at a glance, bracket it.

Floor division, remainder and mixed types

// divides and then takes the floor: the greatest whole number that is less than or equal to the exact answer. So 8 // 2 is 4 and 7 // 2 is 3, while -7 // 2 is -4, because -3.5 rounds down to -4, not toward zero. % gives what is left over, and its sign follows the divisor: -7 % 2 is 1, while 7 % -2 is -1. The two always agree with the identity a == (a // b) * b + a % b, for any nonzero b.

Mixing int and float gives a float: 3 + 2.0 is 5.0 and 4 * 1.5 is 6.0. Two ints stay int for + - * // %, with / always giving a float and ** giving a float when the exponent is negative (2 ** -1 is 0.5). These type rules come straight from the operand types of 1.5.

Comparisons, logical operators and function calls

Comparison operators compare two values and return True or False. == compares, = assigns; they are never interchangeable. Python chains comparisons, so 1 < x < 10 means (1 < x) and (x < 10). not flips a boolean; and is true only when both sides are true; or is true when at least one side is true.

But and and or hand back one of the operands, not a converted boolean: 0 or 'hello' gives 'hello', and 5 and 7 gives 7. Python stops early, so 0 and 1/0 returns 0 and never divides. A value counts as false when it is 0, 0.0, False, None, or an empty container such as '', [], () or {}.

A function call is an expression too. abs(-4) is 4, round(3.567, 2) is 3.57, int(3.9) is 3 because it chops the fraction instead of rounding, and len('delhi') is 5. At exact halves round goes to the even digit: round(2.5) is 2 and round(3.5) is 4. For a square root, import math then math.sqrt(16) gives 4.0; modules and packages are Unit 5. Augmented assignment shortens a = a + 5 to a += 5, and -=, *= follow the same pattern.

Worked example

Question. Evaluate the expression 2 + 3 * 4 ** 2 - 10 // 3 by hand, showing every intermediate value, and state the type of the final result.

  1. Scan for the highest rung present: power, **. Compute 4 ** 2 = 16. The expression is now 2 + 3 * 16 - 10 // 3.
  2. Next rung is *, /, //, %, read left to right. First 3 * 16 = 48. The expression is now 2 + 48 - 10 // 3.
  3. Still on that rung: 10 // 3 = 3, because 10 ÷ 3 = 3.333 and floor division rounds down to 3. The expression is now 2 + 48 - 3.
  4. Lowest rung is + and -, left to right. First 2 + 48 = 50.
  5. Then 50 - 3 = 47.
  6. Every operand was an int and no / appeared, so the value is the int 47, printed as 47 and not 47.0.

  • // rounds down, not toward zero. -7 // 2 is -4 and -7 % 2 is 1; C gives -3 and -1 for the same pair.
  • and and or return an operand, not True or False. 3 and 4 is 4, and 0 or 'yes' is 'yes'.
  • int(3.9) is 3 but round(3.9) is 4. Chopping and rounding are different operations with different answers.

1.7 Input, output, comments and indentation

A program that talks to nobody is a calculator nobody can reach. Python gives two built-in functions for the conversation with the user: print() writes values to the screen, and input() reads one line typed at the keyboard, always as a string. Comments let you leave notes for humans that the interpreter skips. Indentation, the spaces at the start of a line, is how Python knows which lines form one block. These four habits decide whether a program is readable, whether it accepts marks as numbers, and whether it runs at all.

You need 1.6 for the expressions you put inside print() and around input(), and 1.5 for why a string and an integer behave differently.

Output: print() and its two edges

print() takes zero or more items and writes them to the screen, then moves to a new line. Each item is converted to text before it is shown, which is why a string and a number can sit in the same call: print("Total:", 10) works. By default print() puts exactly one space between items. Called with no items at all, print() prints just a newline.

print(item1, item2, ..., sep=" ", end="\n")

item1, item2 … are the values to show, in order; sep is the text placed between items, default one space; end is the text placed after the last item, default \n, meaning go to the next line. Both sep and end must be strings.

Two keyword arguments change those edges. sep replaces the space between items, so a comma list comes out of sep=", ". end replaces the newline, so end="" keeps the cursor on the same line and the next print() continues there. A table row built by hand is just a careful choice of these two.

Python program.

a = 7
b = 3
print(a, b)
print(a, b, sep=", ")
print(a, b, sep="-", end=".\n")
print("Total:", a + b)

Output

7 3
7, 3
7-3.
Total: 10

Note the last line: a+b is computed first, giving 10, and print() then shows a string and an integer side by side. print() itself returns nothing useful; you call it for what appears on the screen.

Input: input() always hands back a string

input() reads one line from the keyboard and returns it as a string. Type 87 and you get the two-character string "87", not the number 87. The text inside the brackets is the prompt: input("Enter marks: ") shows Enter marks: and waits on the same line, so the user knows what to type.

To get a number, convert the string. int(input("Marks: ")) works from the inside out: the prompt appears, the user types, a string comes back, and int() turns that string into a whole number. Use float() for decimals such as 72.5. int("87") succeeds; int("87 marks") raises ValueError because the text is not a plain number.

The prompt is a convenience only. On a phone or a web form the user may type into a box, but the rule stays: whatever arrives is text, and you convert it before doing arithmetic. Reading many lines in a loop is Unit 2 work; reading a whole file instead of one line is Unit 5.

Comments: notes the interpreter throws away

A comment starts with # and runs to the end of the line. Python discards it before running, so it costs nothing and exists only for the human reader. A full-line comment explains the block below it; a trailing comment explains one statement.

Python program.

charge = 0.05   # service charge, 5 percent
print("#1 in the class")   # the hash is inside a string here

Output

#1 in the class

A # inside a string is just a character, as the second line shows. A triple-quoted string (''' … ''' or """ … """) is not a comment: it is a real string value. When such a string stands alone as the first line of a file or a function, it is called a docstring and Python keeps it as documentation. Ordinary # comments are gone from the running program.

Indentation and long lines

Python uses no braces to mark a block. The spaces at the start of a line decide which lines belong together. A header line that ends with a colon — an if header, a loop header, a def header — needs at least one indented line under it. All lines with the same indent belong to the same block, and the block ends when the indent drops back to an earlier column.

  • Four spaces per level is the usual convention; any consistent count works, but four is what most code uses.
  • Never mix tabs and spaces. The file can look perfectly aligned on your screen and still raise IndentationError or TabError.
  • Blank lines and lines holding only a comment are ignored when Python checks indentation, so they never break a block.

A long line can be split inside open brackets, or after a backslash: total = 1000 + 2000 + \ with 3000 on the next line is one statement. Open brackets are safer than the backslash, because a trailing space after a backslash is an error you cannot see.

Body statements that sit under if and while headers are Unit 2; here, fix the geometry — header, colon, indented body, same indent for equals.

1.8 Syntax, runtime and semantic errors; debugging

A program can go wrong in three different ways, and Python gives a different symptom for each. Bad grammar stops the file before a single line runs. A valid line that fails while running stops the program and prints a traceback. A program that runs to the end and prints the wrong number gives no message at all. Telling the three apart decides where you look: at the line's spelling, at the failing value, or at your own logic.

You need: 1.4 for names and keywords, 1.5 for types, and 1.7 for indentation, because you need working code before you can break it.

Three families, three symptoms

Python handles a file in two stages. First it reads the whole file and translates it into internal instructions. Only then does it run those instructions, one statement at a time, from top to bottom. Which stage fails decides which family of error you get.

  • Syntax error. The grammar is wrong. Nothing in the file runs, not even the correct lines above the mistake.
  • Runtime error. The grammar is fine, but a statement cannot be carried out with the values it meets. Python stops at that statement.
  • Semantic error, also called a logic error. Every statement runs, the program ends normally, and the output is wrong. No message appears anywhere.

Python's built-in error names end in Error: ZeroDivisionError, NameError, TypeError, ValueError. Catching them on purpose is Unit 5. Here you only need to read them.

Syntax errors: nothing runs

Syntax means grammar: where the brackets, colons, quotes and keywords go. A syntax error means Python could not parse the line at all. Usual causes:

  • A missing colon after if x > 0, for i in range(3) or def f().
  • An unbalanced bracket or quote: print((10 + 20) / 2.
  • A misspelled keyword: fro i in range(3):. Keywords are fixed words, listed in 1.4.
  • Old Python 2 habits such as print "hello".

Python prints SyntaxError, the file name, the line number, and a caret ^ under the place where parsing stopped. Then it stops. The caret marks the first point where the line stopped making sense, which for a missing bracket is often later than the real mistake. Two relatives are also syntax errors: IndentationError for wrong spacing at the start of a line, and TabError when one block mixes tabs and spaces. Both are subclasses of SyntaxError, so both stop the whole file before any statement runs. The indentation rules are in 1.7.

Runtime errors and the traceback

A runtime error is a statement that is legal Python but fails on the actual values. Python prints the error name, then a traceback: the file, the line number, and the chain of calls that led there. The four you meet first:

  • ZeroDivisionError: 10 / 0 or 10 % 0.
  • NameError: the name does not exist, for example print(total) when the variable is spelled totl.
  • TypeError: the type forbids the operation, for example "Age: " + 25, which adds a str to an int. Convert one side first, see 1.5.
  • ValueError: the type is right but the value is not acceptable, for example int("abc") or int("12.5").

Read a traceback from the bottom up. The last line is the error name and its message. The line just above is the file and line number where it happened. Everything above that is the call chain. Beginners start at the top, meet an unfamiliar function name from inside Python's own code, and give up. Work from the bottom. Python stops at the first runtime error, so fixing one may reveal a second.

Semantic errors and a debugging routine

The hardest family has no message. The program computes something, prints it, and the number is wrong. Debugging is the routine that finds it.

  1. Reproduce with the smallest input you can: 10 and 20, not a 500-row file.
  2. Read the traceback bottom-up, or if there is none, note the line that prints the wrong value.
  3. Print the intermediate values just before that line.
  4. Compare each printed value with what you expected. The first one that differs contains the bug.
  5. Fix one thing, run again, and delete the debug prints.

Python program.

def average(a, b):
    print("a =", a, "b =", b)
    return a + b / 2

result = average(10, 20)
print("result =", result)

Output

a = 10 b = 20
result = 20.0

The prints show the inputs arrived correctly, so the bug is inside the calculation: / binds tighter than + (see 1.6), so it computed 10 + 10.0. The corrected line return (a + b) / 2 gives 15.0. Most semantic errors are one of four things: operator precedence, integer division where you wanted /, a variable never updated inside a loop (Unit 2), or an off-by-one in a range.

Worked example

Question. A student must print the average of 10 and 20, which is 15.0. Four attempts follow. Classify each one and state exactly what Python does with it. (a) print(10 + 20 / 2) (b) print(10 / 2 + missing) (c) print((10 + 20) / 2 (d) print(10 / 0)

  1. (a) Parses correctly. / binds tighter than +, so 20 / 2 = 10.0, then 10 + 10.0 = 20.0. The program ends normally and prints 20.0, not 15.0. No message appears. Semantic error.
  2. (b) Parses correctly. Python evaluates 10 / 2 = 5.0, then looks up the name missing. No such name exists, so it raises NameError and stops at that line. Runtime error.
  3. (c) Has two opening brackets and only one closing bracket. Python cannot parse the file, reports SyntaxError for that line, and runs nothing at all. No output. Syntax error.
  4. (d) Parses correctly. 10 / 0 has no value, so Python raises ZeroDivisionError: division by zero and stops. Runtime error.
  5. The corrected line is print((10 + 20) / 2), which prints 15.0.

Answer. One syntax error at (c), two runtime errors at (b) and (d), and one semantic error at (a); the corrected line prints 15.0.

Worked example 2

Question. What does this program print, and which statement would break it? x = "5", print(int(x) + 5).

  1. int("5") converts the string to the integer 5. The type is correct and the value is valid, so no error.
  2. 5 + 5 = 10, printed as 10.
  3. Replace it with print(x + 5) and Python raises TypeError at runtime: it cannot add str and int.

Answer. The program prints 10; without the conversion it would stop with a TypeError.

Exam traps

  • A misspelled function name, prnt("hi"), is a NameError at runtime, not a syntax error. The grammar is perfect.
  • The reported SyntaxError line is where parsing gave up, not always where the bug is. For an unbalanced bracket, look at the lines above.
  • int("12.5") raises ValueError, not TypeError and not a syntax error: the type is right, the value is not.
  • IndentationError and TabError look like runtime problems but stop the file before any statement runs, exactly like SyntaxError.
  • No message does not mean no bug. A program that prints 20.0 when the answer is 15.0 ran to the end and is still wrong.

Takeaways

  1. Write the plan first — algorithm, flowchart or pseudocode — then translate it into code; the plan catches logic errors that no debugger can.
  2. Python chooses readability over raw speed, so one clear line can do work that takes many lines in older languages.
  3. Interactive mode is a scratchpad, script mode is a notebook: only the saved file still exists tomorrow.
  4. A variable name must be a legal identifier and must not be a keyword; the value it holds can change type at any time.
  5. int, float, str and bool each behave differently, and the type decides what + and * will do.
  6. Precedence decides groups, associativity decides ties inside a group; brackets override both.
  7. input() always returns a string — convert with int() or float() before doing arithmetic on it.
  8. Python reads code structure from indentation alone, so a stray space can change or break the program.
  9. Syntax errors stop the program before it starts, runtime errors stop it mid-run, semantic errors let it run and give a wrong answer.

Glossary

Algorithm
A finite sequence of clear steps that solves a problem for any valid input.
Associativity
The direction — left or right — used when two operators share the same precedence.
Block
A group of statements at the same indentation level, run together.
Comment
Text after # that the interpreter ignores, used to explain code.
Data type
The kind of a value — int, float, str, bool — which fixes the operations allowed on it.
Expression
A piece of code that evaluates to a value.
Flowchart
A diagram of an algorithm drawn with standard symbols and arrows.
Identifier
Any name the programmer writes for a variable, function or module.
Implicit conversion
Automatic promotion done by Python, such as int mixed with float giving float.
Indentation
Leading whitespace that marks a code block in Python.
Interactive mode
Running Python one line at a time at the >>> prompt, with results printed immediately.
Interpreter
A program that reads and executes source code line by line without producing a separate executable.
Keyword
A reserved word such as def or while that has a fixed meaning in Python.
Literal
A value written directly in code, such as 42, 3.14 or 'chennai'.
Operand
One of the values an operator acts on.
Operator
A symbol that acts on operands to produce a result.
Precedence
The ranking that decides which operator is applied first in a mixed expression.
Problem analysis chart
A four-part table listing the input data, the required output, the processing and the possible solutions.
Pseudocode
An informal, code-like plan written in plain language and structured keywords.
Runtime error
An error that appears only while running, such as division by zero, raising an exception.
Script
A text file of Python statements, usually ending in .py, run as a whole.
Semantic error
A logic mistake: the program runs but produces a wrong result.
Syntax error
A grammar mistake that stops Python from running the program at all.
Traceback
Python's error report naming the error and the line where it occurred.
Type conversion
Producing a value of a different type from an existing one, as float('2.5') gives 2.5.
Variable
A name that refers to a stored value; assigning to the name rebinds it.
