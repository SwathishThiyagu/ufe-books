2.1 Conditional statements: if, if-else and if-elif-else

A program often has to choose one action from several. Python does this with conditional statements: if, if-else and if-elif-else. Each condition is a boolean expression that is either True or False. Python tests conditions in the order written and runs only the first block whose condition is True. This is how marks become grades, UPI payments pass or fail checks, and a login form rejects a wrong password. The rule is simple: colon ends the test line, indentation marks the block, and the first true branch wins.

You need: booleans, comparison operators and indentation from Unit 1.

The if statement chooses one block

An if statement has three parts: the keyword if, a condition, and a colon. The condition is a boolean expression, such as marks >= 75. The colon ( : ) marks the start of the block. The block is written below, indented by four spaces. Python runs the block only when the condition is True. When it is False, Python skips the whole indented block.

Python program.

marks = 78
if marks >= 75:
    print('Pass')
print('Done')

Output

Pass
Done

Comparison operators make conditions: < (less than), <= (less than or equal), > (greater than), >= (greater than or equal), == (equal) and != (not equal). The operator = assigns a value; == compares two values. Boolean operators combine tests: and is true only when both sides are true, or is true when at least one side is true, and not reverses True to False. For example, marks >= 60 and marks <= 75 is true for 70.

Indentation is not decoration. In Python, the same indentation groups statements into one block. A missing or extra space changes the meaning or raises IndentationError. The condition line always ends with a colon. The next line must be indented more than the if line.

if-else and if-elif-else

An if-else statement gives two paths. The if block runs when the condition is True; the else block runs when it is False. else has no condition but does need a colon. Write else: and an indented block. Only one of the two blocks runs.

When there are more than two paths, use if-elif-else. elif means else if, and carries its own condition and colon. Python checks the if condition first, then each elif from top to bottom. The first True condition runs its block; all later tests are skipped. If no condition is True, the else block runs. else is optional, but it catches the remaining case.

Order matters because the first true branch wins. Suppose marks = 78 and the tests are marks >= 90, then marks >= 75, then marks >= 60. Test 1: 78 >= 90 is False. Test 2: 78 >= 75 is True. Python runs Grade B and does not test 78 >= 60. If the 75 test came before the 90 test, a mark of 95 would wrongly get B, so lower cut-offs must come after higher cut-offs.

You can nest an if inside another if's block; Python places no limit on depth, but keep nesting shallow because deep nesting is hard to read. Example: inside if marks >= 60:, write another if marks >= 75: print('B or above'). The inner if has extra indentation. Deep nesting is better handled by functions later.

Truthiness and common errors

A condition does not have to be a comparison. Python treats many values as truthy or falsy. Falsy values include False, None, 0, 0.0, '' (empty string), [] (empty list) and {} (empty dictionary). All other values are truthy. So if name: runs when name is a non-empty string. if 0: never runs its block.

  • Using = instead of == in a condition: if marks = 75: is a syntax error. Use if marks == 75:.
  • Forgetting the colon after if, elif or else: if marks >= 75 is a syntax error.
  • Wrong indentation: the block must be indented consistently; an unindented line after if is outside the block.
  • Putting a condition after else: else: is correct; else marks >= 60: is a syntax error.
  • Testing a range wrongly: marks >= 60 and <= 75 is invalid (Python does not repeat the left operand); write marks >= 60 and marks <= 75.

The if-elif-else chain is used in form validation, fee slabs, grade rules and menu choices. For repeated decisions, loops repeat the test. For reusable checks, move the rule into a function.

2.2 Loops: while, for and nested loops

A loop repeats a block of statements so you do not copy them by hand. A while loop repeats while a condition stays True. A for loop repeats once for each item in an iterable such as a range, a string or a list. Loops exist because a program often meets a list whose length is unknown while the code is being written, and because repeating one step over many items is the heart of almost every useful program. Uses: retrying a UPI PIN, printing a marks table for a class, adding a canteen bill until the last item, and drawing rows and columns of a pattern.

You need: Chapter 2.1 for boolean conditions and the if statement, and Unit 1 for range, integer arithmetic and indentation.

while: repeat while the condition is true

A while loop runs its body again and again as long as a boolean condition stays True. The condition sits at the top, so Python tests it before every pass, including the first one. If that first test is False, the body runs zero times.

The shape is the keyword while, a condition, a colon, then an indented body. Every line indented under the while line belongs to the loop.

Python program.

total = 0
i = 1
while i <= 5:
    total = total + i
    i = i + 1
print("sum =", total)
print("i after loop =", i)

Output

sum = 15
i after loop = 6

At the end of the body, control jumps back to the condition. The body must change something the condition depends on. Here i = i + 1 moves i towards 6, so the test i <= 5 finally fails and the loop stops.

  1. Evaluate the condition. It is either True or False.
  2. If it is False, leave the loop and run the first statement after it.
  3. If it is True, run the whole indented body once.
  4. Jump back to step 1.

A sentinel-controlled loop stops on a special value rather than on a count. A canteen bill keeps adding amounts until the cashier enters the sentinel -1. The sentinel is read but never added to the total; it only ends the loop.

for: once for each item in an iterable

A for loop takes each item from an iterable and runs the body once per item. It stops by itself when the items run out, so no manual update is needed. Some syllabi call this definite iteration, because the number of passes is fixed before the loop starts, and they call the while loop indefinite iteration.

range(stop) gives 0, 1, ..., stop-1. range(start, stop) gives start up to stop-1. range(start, stop, step) jumps by step and stops before reaching stop. So range(1, 6) gives 1 2 3 4 5 — the 6 is never produced, and a negative step counts downwards.

N = ceiling((b − a) / s)

N is how many values range(a, b, s) produces; a is the first value, b the stop value (excluded), s the step (positive). Example: range(3, 20, 4) gives N = ceiling(17 / 4) = ceiling(4.25) = 5 values. If b ≤ a with a positive step, range(a, b, s) is empty, so N = 0.

Python program.

word = "CHENNAI"
vowels = 0
for ch in word:
    if ch in "AEIOU":
        vowels = vowels + 1
print(vowels)
print(list(range(1, 10, 3)))

Output

3
[1, 4, 7]

Over a string the loop variable takes one character per pass; over a list it takes one element per pass. No index arithmetic is needed. The block above also shows the accumulator pattern: a variable vowels is set to 0 before the loop, and each pass adds to it. The same pattern computes a total (total = total + x) or a count (count = count + 1).

Nested loops: rows and columns

A nested loop is a loop written inside another loop's body. The outer loop takes one step; then the inner loop runs completely, from its first item to its last. Next the outer loop takes its second step and the inner loop starts again from the beginning.

If the outer loop runs m times and the inner loop runs n times for each outer pass, the inner body runs m × n times in all. That product is the number the examiner usually asks for.

Python program.

for row in range(1, 4):
    cells = []
    for col in range(1, 4):
        cells.append(str(row * col))
    print(" ".join(cells))

Output

1 2 3
2 4 6
3 6 9
  • Row and column work: a marks table, a calendar grid, a picture of stars.
  • Grid coordinates: every pixel column for every pixel row.
  • Comparing every pair of items once, which costs about n² steps for n items.
  • A break inside the inner body leaves only the inner loop; the outer loop continues (see Chapter 2.3).

2.3 break, continue and pass statements

break, continue and pass are three small keywords that change how a loop runs. break leaves the loop at once. continue skips the rest of the current iteration and starts the next one. pass does nothing. They exist so a program can stop early, skip unwanted items, or keep a block legal while it is still empty. Search loops, input checks and function stubs use them daily. Only a few universities teach this as a separate topic.

You need: Chapter 2.2 for while, for and indentation.

break and continue: leaving versus skipping

break stops the nearest loop that contains it. Control jumps to the first line after the loop; the condition is not tested again and a for takes no more items. Use it when further work is useless: in a search for a roll number, once the number is found, break saves the remaining comparisons. Inside nested loops, break leaves only the inner loop. The outer loop continues. To leave both, use a flag or return from a function.

continue ends only the current iteration. In a for, Python takes the next item. In a while, Python jumps to the condition test. Code after continue in the same block is skipped. If the increment is after continue, a while may loop forever.

The difference is scope. break exits the loop; continue exits one iteration. Example: for i in range(1, 7): if i == 3: continue; print(i) prints 1, 2, 4, 5 and 6. Only 3 is skipped. Change continue to break and the output stops at 1 and 2.

pass: the stand-in statement

pass does nothing. Python needs at least one statement in every indented block after if, for, while, def or class. When the real code is not written yet, pass keeps the block legal. A stub like def pay(): pass can be imported, called and tested before its body exists.

pass is not break and not continue. It does not skip the rest of an iteration and does not leave a loop. It simply lets the program move to the next statement. Removing it from an empty block gives IndentationError: expected an indented block.

Use pass for an unfinished branch, an empty function or class stub, or a deliberate no-op. It has no effect on loop control. In an exam, write pass when a block must exist but no action is defined.

2.4 Defining and calling functions; return values

A function gives a name to a set of steps. You define it once with def, give it inputs called parameters, and call it whenever you need the work done. The call jumps into the function body, runs the statements, and comes back with a return value. This saves repeated code and makes long programs readable. In Python, a function that returns nothing still gives None. You use functions for every reusable calculation: area of a circle, a UPI bill split, a cricket run rate, or a marks total.

You need Unit 1: expressions, indentation and simple input and output.

Defining a function and calling it

A function definition starts with def, then the function name, parentheses, and a colon. The body is indented under the colon. The names inside the parentheses in the definition are parameters. A parameter is a place to receive a value. Example:

Python program.

def area(r):
    '''Return the area of a circle.'''
    return 3.14 * r * r

print(area(2))
print(area(1))

Output

12.56
3.14

Here def is the keyword, area is the function name, r is the parameter, and the indented line is the body. The triple-quoted string is a docstring: a short description stored with the function. It does not change the result.

To run the body, call the function by writing its name and parentheses with a value: area(2). The value 2 is an argument. An argument is the actual value supplied at the call; a parameter is the formal name that receives it. Calling area(2) copies 2 into r, computes 3.14 × 2 × 2, and returns 12.56.

Parentheses matter. area is the function object; area(2) is a call. Without parentheses the body does not run. Calling a function before its definition has run in the script gives NameError, so place definitions before the calls that use them. Python reads a def statement, creates the function, and then continues.

Return values, None and void functions

return does two things: it stops the function immediately and sends one value back to the caller. The caller may store that value, print it, or pass it to another call. A function can contain many return statements, but only the first one reached runs. Code after a return in the same block is dead for that call.

If a function has no return statement, Python returns None automatically. None is a special value meaning 'no result'. It is not 0 and not an empty string. A function that returns None is often called a void function: it does work, such as printing, but gives no useful result.

A print inside a function is output, not a return value. This program shows the difference:

Python program.

def show(r):
    print(3.14 * r * r)

x = show(2)
print(x)

Output

12.56
None

The first print shows 12.56. The second print shows None, because show has no return. To use the number later, return it. A return with no expression also gives None: return. A function may return any one object: a number, a string, a list, or a tuple. To return several numbers, return a tuple such as return width, height; that is still one object.

Composition: functions calling functions

Composition means using the result of one function as input to another, or calling one function inside another. It lets you build small tested pieces instead of one long block. Suppose area(r) returns 3.14*r*r. A ring with outer radius R and inner radius r has area area(R) - area(r). You can write: def ring_area(R, r): return area(R) - area(r).

ring_area(3, 2) calls area(3) to get 28.26, calls area(2) to get 12.56, subtracts, and returns 15.70. The outer function does not repeat the circle formula; it reuses area. This is the main reason functions exist: one correct formula in one place.

Flow of execution is the order in which Python runs statements. At a call, Python pauses the caller, jumps into the called function, runs its body, gets the return value, and resumes the caller at the next step. A function can call another function; Python keeps track of where to return. The call stack holds these return points. Deep chains are fine for normal programs; a function calling itself is recursion, covered in Chapter 2.7.

Keep functions short and give them verb-like names: area, total, is_valid. A docstring on the first line states what the function returns. Details of matching many arguments, keyword arguments and defaults are in Chapter 2.5. Scope, which decides where names like r can be seen, is in Chapter 2.6.

2.5 Parameters and arguments: formal, actual, keyword and default

A function's bracket has two sides. The names written in the def line are formal parameters: stand-ins that get their values only when the function is called. The values written at the call are actual arguments. Python's job is to bind each actual argument to one formal parameter, and it can do that in three ways: by position, by name, or by falling back to a default value written in the def line. Every call you write, from a UPI fee calculator to a cricket run-rate helper, depends on this binding being correct.

You need: Chapter 2.4 — a def line, a call and a return value.

Formal parameters and actual arguments

A function names its inputs in the def line. In def bill(price, qty=1, tax=0.05): the three names inside the bracket are formal parameters. A formal parameter is a variable that exists only inside the function body. It holds no value until the function is called.

The values you write at the call are actual arguments. In bill(100, 2), the actual arguments are 100 and 2. Python binds them by position: the first argument goes to the first parameter, the second to the second, and so on. Inside the body, price is 100 and qty is 2.

Position matching makes the count matter. A call that leaves a required parameter without a value, or that supplies more arguments than there are parameters, raises a TypeError before the body runs. For a missing argument the message names the function and the missing parameter; for extra arguments it names the function and the two counts.

Python program.

def bill(price, qty=1, tax=0.05):
    print("price =", price, "qty =", qty, "tax =", tax)
    return price * qty * (1 + tax)

print(bill(100, 2, 0.05))

Output

price = 100 qty = 2 tax = 0.05
210.0

Keyword arguments: matching by name

A keyword argument writes the parameter's name at the call: bill(price=100, qty=2). Python matches by name, not by position, so the order is free. bill(qty=2, price=100) binds exactly the same way. Some syllabi call these named arguments; the call syntax is the same.

Three rules keep the matching unambiguous. Positional arguments come first, so a positional argument after a keyword argument is a syntax error, caught before the program runs. No parameter may receive two values at once. Every parameter without a default must receive exactly one value, by position or by name.

Mixing the two styles is allowed and common. bill(100, qty=2) fixes price by position and qty by name, and tax keeps its default.

The table below uses the definition def bill(price, qty=1, tax=0.05): return price * qty * (1 + tax).

Default values and the rules they follow

A default value is written after = in the def line. When the call does not supply that parameter, the default is used. In bill(100, 2) the call supplies price and qty, so tax stays at 0.05 and the function still has a value to work with.

Defaults must follow all non-default parameters. def f(a=1, b): is a SyntaxError. Positional matching fills parameters from left to right without skipping, so a required parameter placed behind a defaulted one could never be reached: the call f(5) binds a = 5 and leaves b with no value, which is a TypeError. The rule guarantees that every required parameter can still be filled from the left.

Each default is evaluated once, when the def line runs, not at every call. With a number or a string that is harmless. With a mutable default such as a list it is not: the same list object is reused, so it carries items over from earlier calls.

Python program.

2.6 Scope and lifetime of variables

A variable name is visible only inside its scope. Python looks for a name in local, enclosing, global and built-in scopes, in that order. Lifetime is how long the object bound to a name stays alive: local names live during a function call, module names live while the program runs. This separation lets a function use its own x without overwriting the module's x. You use it every time you pass a parameter or keep a counter inside a function. Confusing scope with lifetime causes errors such as UnboundLocalError.

You need: Chapter 2.4 on defining and calling functions, and Chapter 2.5 on parameters and arguments.

Local scope and function calls

A scope is the region where a name can be used. A name is an identifier such as x or total. At module level, x = 10 creates a global name. Inside a function, an assignment such as x = 20 creates a local name unless the function declares global x. Parameters are local names too. Calling show(5) binds parameter n to 5 only during that call. When the call ends, the local names are removed from the function's frame. The object they referred to may stay alive if another name still refers to it. Scope is about where a name is visible; lifetime is about how long an object stays in memory.

A function call gets a fresh local scope. Two calls do not share their locals. If show() sets x = 20, that x exists only for that call. The next call starts again with no local x. This is why a local variable cannot remember a value between calls unless you use a mutable object, a module name, or a parameter. See Chapter 2.7 for calls that keep earlier calls alive on the stack.

Lookup order: LEGB and global

Python resolves a name by checking Local, then Enclosing, then Global, then Built-in. The short form is LEGB. Local names belong to the current function. Enclosing names belong to an outer function when functions are nested. Global names are created at module top level. Built-in names are provided by Python, such as print and len. The first match wins, so a local x hides a global x.

The global keyword changes the rule for one name inside one function. Writing global count followed by count = count + 1 makes the assignment update the module name count instead of creating a local count. Use it rarely. Passing a value in and returning a result is clearer and easier to test. Shadowing a built-in name, for example len = 5, hides len in that scope and makes later calls fail.

Lifetime and UnboundLocalError

A local name lives from the moment the function call starts until the call returns. A module-level name lives from its assignment until the program ends, unless it is rebound. An object lives as long as at least one reference points to it. The name and the object are different: deleting or leaving a scope removes a name, not necessarily the object.

Python decides local names before the function runs. If a function assigns to x anywhere in its body, Python treats x as local for the whole function. Reading x before that assignment raises UnboundLocalError. Example: x = 10 at module level; def bad(): print(x); x = 20. The print(x) looks for a local x, finds it not yet assigned, and raises UnboundLocalError. It does not read the global x = 10.

  1. Python compiles the function and marks every assigned name as local.
  2. At the call, a new local frame is created.
  3. print(x) looks for local x; it is marked local but has no value yet.
  4. Python raises UnboundLocalError before x = 20 runs.

2.7 Recursion

Recursion is a way to solve a problem by solving a smaller copy of the same problem. A recursive function calls itself with a smaller input. A base case stops the calls. This style fits problems that are naturally nested: factorials, Fibonacci numbers, folder trees and parsing. Each pending call waits on the call stack, so recursion trades memory for shorter code. Used well, it turns a hard-looking problem into a few clear rules.

You need: functions and return values from Chapter 2.4, and if statements from Chapter 2.1.

Base case and recursive case

Every recursive function has two parts. The base case returns an answer directly, without another call. The recursive case calls the same function on a smaller input. The smaller input must move toward the base case, or the calls never stop. For factorial, the base case is 0! = 1. The recursive case is n! = n × (n − 1)!. So 4! calls 3!, which calls 2!, which calls 1!, which calls 0!. The answers then return: 1, 1, 2, 6, 24.

n! = 1 when n = 0; n! = n × (n − 1)! when n > 0

n is a non-negative integer; n! is the product 1 × 2 × ... × n.

  1. Identify the smallest input that has a direct answer. That is the base case.
  2. Write the recursive call on an input that is closer to the base case.
  3. Assume the recursive call is correct, then combine its result into the answer.

Tree recursion and repeated calls

Fibonacci numbers follow fib(0) = 0, fib(1) = 1, and fib(n) = fib(n−1) + fib(n−2) for n ≥ 2. A call to fib(n) makes two recursive calls, so the call tree branches. The figure traces fib(4). The same subproblem can appear in different branches: fib(2) is computed twice, and fib(1) appears three times. That repetition is the cost of naive tree recursion. The number of calls grows quickly with n, even though the final answer is small.

fib(n) = fib(n−1) + fib(n−2), with fib(0) = 0 and fib(1) = 1

n is a non-negative integer; fib(n) is the n-th Fibonacci number.

  • Linear recursion makes one recursive call per step.
  • Tree recursion makes two or more recursive calls per step.
  • Repeated subproblems waste time in naive tree recursion.

Call stack, depth limit and iteration

When a function is called, Python creates a stack frame. The frame holds the parameters and local variables of that call. In recursion, each pending call keeps its frame until its recursive call returns. The frames form the call stack. Python sets a recursion limit, about 1000 frames by default. A deeper chain raises RecursionError. Iteration repeats with a loop and needs no new frame for each step. Use recursion when the problem is naturally nested; use a loop when a simple repeat will do.

  • Missing base case: recursion never reaches a return and raises RecursionError.
  • Wrong base case: the function may return a wrong answer or miss values.
  • Deep input: correct recursive code may still hit the depth limit.

2.8 Lambda functions; map, filter and reduce

A lambda is a small function written in one line with no name. It exists because many Python tools need a tiny function for a single moment: to transform a list, to keep some items, or to fold a list into one value. Instead of writing a full def, you write the rule inline. The three helpers map, filter and reduce apply such a function across a sequence. Together they form short, readable pipelines that replace a loop, and they appear in data cleaning, marks processing and everyday scripts.

You need: functions and return values from Chapter 2.4, function arguments from Chapter 2.5, and lists from Unit 3: Lists.

Lambda: a function without a name

A def statement gives a function a name, a body and a return line. Often you need a small function for one moment only, to hand it to another function and then forget it. A lambda expression builds exactly that: a function object with no name.

lambda parameters : expression

parameters is a comma-separated list of names, possibly empty; expression is any single Python expression. The value of that expression becomes the return value of the new function.

Compare the two forms. def square(x): return x * x creates a named function. square = lambda x: x * x creates the same function and binds it to the name square. You may call it as square(5), which gives 25. The keyword return is never written inside a lambda; the expression's value comes back automatically.

The limit is strict: the body must be one expression. There is no assignment, no for loop, no if statement, no multiple lines. A conditional expression is allowed because it is still one expression: lambda x: "even" if x % 2 == 0 else "odd".

A function with no parameters is legal: lambda: 0. A lambda may take several: lambda a, b: a + b returns the sum of its two inputs.

Lambdas are used inline where a function object is expected as an argument. The common places are map, filter and reduce (this chapter), and the key argument of sorting, as in sorted(names, key=lambda s: len(s)), which sorts names by length.

map to transform and filter to select

map(function, iterable) applies function to every item and yields the results in the same order. The input list is never changed. list(map(lambda x: x * x, [1, 2, 3])) gives [1, 4, 9].

In Python 3, map returns an iterator, not a list. It computes one item at a time and stores nothing. Printing it shows something like <map object at 0x...>. Wrap it in list() to see all values at once, or consume it in a for loop. The same iterator can be read only once; a second pass is empty.

filter(function, iterable) keeps only the items for which function returns True, and drops the rest. list(filter(lambda x: x % 2 == 0, [1, 2, 3, 4])) gives [2, 4]. The function here is a test, so it should return True or False.

filter also returns an iterator in Python 3, so list() is needed to display it. A special form, filter(None, iterable), keeps every item that is truthy and removes 0, empty strings and None.

  • map: one output for every input, same length.
  • filter: zero or one output per input, never longer than the input.
  • Both read the input lazily and leave the original list unchanged.

reduce and small pipelines

reduce is not a built-in name in Python 3. It lives in the functools module, so the file must start with from functools import reduce.

reduce(function, iterable) repeatedly combines two items into one, using a function that takes two arguments. The signature is reduce(function, iterable, initializer), where initializer is optional.

  1. Take the first two items of the iterable as a and b.
  2. Compute function(a, b) and call the result the new a.
  3. Take the next item as the new b and repeat.
  4. Stop when no items remain; reduce returns the last computed value.

For [2, 4] with a sum rule, reduce calls the rule once: 2 + 4 = 6. For [1, 27, 125] it runs twice: 1 + 27 = 28, then 28 + 125 = 153. If an initializer is given, it is used as the starting a. On an empty iterable with no initializer, reduce raises a TypeError.

Python program.

from functools import reduce

nums = [1, 2, 3, 4]
evens = list(filter(lambda x: x % 2 == 0, nums))
squares = list(map(lambda x: x * x, evens))
total = reduce(lambda a, b: a + b, squares)

print(evens)
print(squares)
print(total)

Start with 1 and 2: 1 × 2 = 2. Then 2 and 3: 2 × 3 = 6. Then 6 and 4: 6 × 4 = 24. The call returns 24.

Analyze Predict the output of list(map(lambda x: x * 2, filter(lambda x: x % 2 == 0, [1, 2, 3, 4]))) and explain the order of operations. 4 marks

The inner filter keeps 2 and 4, so the iterator holds [2, 4]. The outer map doubles each: 2 × 2 = 4 and 4 × 2 = 8. Output: [4, 8]. The input to map is the filtered iterator, so filter runs first.

Analyze A student writes reduce(lambda x: x + 1, [1, 2, 3]). What goes wrong and how is it fixed? 4 marks

reduce combines two items at a time, so it calls the function with two arguments. The lambda accepts one, so Python raises a TypeError. Fix: use a two-argument rule such as lambda a, b: a + b, or write lambda x, y: x + 1 if the extra argument is meant to be ignored.

Understand State two things that a def function can do but a lambda cannot. 2 marks

A lambda cannot hold statements: no assignment, no for or while loop, no if statement, no multiple lines, and it cannot use return. It also has no name of its own until it is bound to a variable.

Understand What does list(filter(None, [0, 1, '', 'hi', None])) return and why? 3 marks

With None as the function, filter keeps the items that are truthy. 0, the empty string and None are falsy and are dropped. Output: [1, 'hi'].

Beyond the syllabus

Not for the exam. In real code, map and filter often lose to list comprehensions for readability, but lambdas stay everywhere: the key argument of sorted and min, callbacks in Tkinter button commands, and short rules passed to pandas apply. Data engineers write whole cleaning pipelines as chains of map, filter and reduce over records. Functional ideas such as these also lead into Python's itertools and functools modules, and into decorators, which take a function as input and return a new function. Search for itertools, functools.partial and operator.itemgetter to go further.

Takeaways

  1. A conditional chain runs exactly one branch: the first one whose condition is True, or else the else block.
  2. Indentation, not braces, decides which statements belong to an if or a loop body in Python.
  3. A while loop suits an unknown number of repeats; a for loop suits walking through a known iterable.
  4. break, continue and pass change loop behaviour without changing the loop condition.
  5. A function hides repeated steps behind a name, so the same logic is written once and called many times.
  6. Python matches actual arguments to formal parameters by position first, then by keyword, then by default value.
  7. Local names live inside one call and disappear afterwards; global names live for the whole program run.
  8. Every correct recursive function needs a base case and progress towards it, otherwise the call stack overflows.
  9. lambda with map, filter and reduce replaces short throwaway loops with one-line expressions.

Glossary

Anonymous function
A function with no name bound to it, typically created with lambda.
Argument
A value supplied at a function call.
Call stack
The record of function calls still in progress, each with its own local namespace.
Condition
A boolean expression whose True or False value decides which block runs.
elif
Short for else-if; adds another condition to test when the earlier ones were False.
else
The optional final block of an if chain, run when no condition matched.
Function call
Writing the function name followed by parentheses, with arguments inside, to run the body.
Function definition
The def statement that creates a function object and binds it to a name.
global statement
A declaration inside a function saying that a name refers to the module-level variable, allowing rebinding.
Global variable
A name created at module level and visible throughout the file.
Higher-order function
A function that takes another function as an argument or returns one, as map and filter do.
Indentation
Leading spaces at the start of a line that group statements into a block in Python.
Infinite loop
A loop whose condition never becomes False, so it runs until the program is stopped or a break runs.
Iterable
Any object that yields its items one at a time in a for loop, such as a string, list, tuple or range.
Iteration
One complete pass through the statements of a loop body.
Loop body
The indented statements that are repeated on every iteration.
Loop variable
The name in a for statement that is bound to the current item on each pass.
None
Python's value for 'nothing here'; it is what a function returns when no return statement runs.
Parameter
A name listed in the def line that receives an argument when the function is called.
Positional argument
An argument matched to a parameter by its order in the call.
Recursive case
The part of a recursive function that calls itself with a smaller or simpler argument.
Sentinel value
A special input value that signals the end of data and is often paired with a while loop and break.
Void function
A function that performs an action but returns None.
