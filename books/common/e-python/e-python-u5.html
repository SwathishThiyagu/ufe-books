5.1 Exception handling: try, except, else and finally

Some statements fail at run time: a division by zero, a missing dictionary key, a file that is not there. Without a plan, the whole program stops at that line. A try statement lets a block of code declare in advance what to do when a statement inside it fails, and what to do whether it fails or not. One statement carries four parts: try, except, else and finally. Every program that reads input, opens a file or calls a server uses this shape, and so does every library you import.

You need: Unit 1 (syntax, runtime and semantic errors, tracebacks) and Unit 2 (functions and return values).

One statement, four parts

Python stops at the first statement that raises an exception (see Unit 1). A try statement changes that. You wrap the risky statements in a try block and write, beside it, the code that should run instead of a crash.

try:
    risky statements
except SomeError:
    handler
except (OtherError1, OtherError2) as e:
    handler using e
else:
    code when nothing failed
finally:
    code that always runs

Only the try block is compulsory, but a try with no except and no finally is a SyntaxError, because Python would have nothing to do with the failure.

  1. Run the statements of the try block, top to bottom.
  2. If one of them raises, skip the rest of the try block and test the except clauses in the order written.
  3. The first clause whose class matches the exception runs its block, and the exception is then handled.
  4. If no clause matches, the exception leaves the try statement, as if no try existed.
  5. If the try block finished with no exception, the else block runs.
  6. Whatever happened above, the finally block runs last, before control leaves the statement.

except: name what you catch

The except clause is the exception handler. It names the class of exception it can deal with; the classes themselves are covered in 5.2.

  • One class: except ZeroDivisionError: catches that class and its subclasses.
  • A tuple: except (ValueError, KeyError): catches any of the listed classes.
  • With the object: except ValueError as e: binds the exception object to e for that block only; Python deletes the name when the block ends.
  • Bare: except: with no class catches everything at all.

A bare except is risky. It also catches KeyboardInterrupt (Ctrl-C) and SystemExit (raised by sys.exit), so the user cannot stop your program and the program cannot exit. It also hides real bugs behind an empty handler. Write except Exception: when you truly want a wide net.

Order matters. Clauses are tested from the top, so a clause for a base class shadows every later clause for its subclasses. Put the specific classes first.

An exception that no clause matches is not lost. It travels up to the calling function, and if nothing anywhere handles it, the default exception handler prints a traceback and ends the program.

else and finally, and why the order matters

The else block exists for code that must run only when the try block raised nothing. You could put that code at the end of the try block, but then an exception raised by it would be caught by your own except clauses, which were written for something else. In a divide function, printing the quotient belongs in else: a printing bug there should not be reported as a divide-by-zero.

finally runs on every exit from the statement: normal end of try, a handled error, an unhandled error on its way up, a return, a break or continue, or a call to sys.exit(). That makes finally the place for cleanup: closing a file, releasing a lock, deleting a temporary download.

One rule surprises everyone. If finally itself executes return, that return wins and the earlier one is thrown away.

Python program.

def f():
    try:
        return 'from try'
    finally:
        return 'from finally'

print(f())

Output

from finally

A function may hold a try inside another try. The inner one handles what it recognises, the outer one catches what the inner one let pass, and the inner finally still runs first.

Reading a traceback line by line

When an exception reaches the top unhandled, the default exception handler prints a traceback. Read it from the bottom up.

Traceback (most recent call last):
  File "marks.py", line 7, in <module>
    report(10, 0)
  File "marks.py", line 3, in report
    print(100 / n)
ZeroDivisionError: division by zero

The last line gives the exception class, ZeroDivisionError, and its message, division by zero. The lines above are the call chain, oldest call first. Each frame holds three facts: the file name in quotes, the line number, and the function that was running, with <module> for top-level code. The source line under each frame shows the exact statement.

Start at the bottom frame: the error happened on line 3 inside report. The frame above says report was called on line 7 of the module. A deeper call chain simply adds more frames. Some syllabi call the except clause the exception handler and the unhandled path the default exception handler; it is the same two mechanisms.

Worked example

Question. A function divide is written as shown and called twice, first as divide(10, 2) and then as divide(10, 0). Give the exact output of the whole program in order, and state the final value of q in each call.

Python program.

def divide(a, b):
    try:
        q = a / b
    except ZeroDivisionError:
        print('cannot divide by zero')
        q = None
    else:
        print('quotient', q)
    finally:
        print('done')

divide(10, 2)
divide(10, 0)
  1. First call divide(10, 2): a = 10, b = 2. No statement in the try block raises, so q = 10 / 2 = 5.0.
  2. No exception was raised, so the except clause is skipped and else runs: it prints 'quotient 5.0'.
  3. finally runs: it prints 'done'. q holds 5.0 when the call ends.
  4. Second call divide(10, 0): a = 10, b = 0. The statement q = a / b raises ZeroDivisionError, and the rest of the try block is skipped.
  5. The except clause matches ZeroDivisionError, so it prints 'cannot divide by zero' and sets q = None.
  6. else is skipped, because an exception was raised in the try block.
  7. finally still runs and prints 'done'. q is None when the call ends.

Exam traps

  • finally beats return: a return inside try or except is discarded if finally itself returns. The function returns the value from finally.
  • else is not the code written after the try statement. else runs only when the try block raised nothing; code after the whole try/except/else/finally runs always, even after a handled error.
  • A bare except swallows KeyboardInterrupt and SystemExit, so Ctrl-C and sys.exit stop working. except Exception does not catch those two.
  • A try with neither except nor finally, and a try/else with no except, are SyntaxErrors; examiners like asking which combinations are legal.
  • Writing a base class (or Exception) as the first clause makes every later clause dead code, because the first matching clause wins.

5.2 Built-in and user-defined exceptions; raising exceptions

Every failure in Python is an object. The object belongs to a class, and the class name says what went wrong. Python ships with built-in exception classes for common failures, such as dividing by zero or opening a missing file. You can also write your own class, inherit from Exception, and raise it on purpose when a rule of your program is broken. This turns an error from a surprise crash into a value that carries data and a clear name.

You need: 5.1 for try and except, and Unit 4 for classes, inheritance, super() and __str__.

The built-in exception tree

All exceptions descend from BaseException. Most normal errors sit under Exception. The figure shows the part that exam questions use.

The built-in classes are grouped by the failure they report. Learn the group, not only the name.

  • Arithmetic: ZeroDivisionError for 7/0, OverflowError for a float too large to represent.
  • Lookup: IndexError for a list index outside its range, KeyError for a missing dictionary key.
  • Type and value: TypeError for an operation on the wrong type, such as '3' + 4; ValueError for the right type with a bad value, such as int('abc').
  • Name: NameError for an unknown name; UnboundLocalError when a local variable is used before assignment.
  • Operating system and I/O: OSError is the parent; FileNotFoundError is the common child when open() cannot find a path.
  • Import: ImportError is the parent; ModuleNotFoundError is the child when import cannot find a module.

Two classes sit directly under BaseException: SystemExit and KeyboardInterrupt. SystemExit is raised by sys.exit(). KeyboardInterrupt is raised when the user presses Ctrl+C. An except Exception block does not catch either one, because neither is a subclass of Exception. This is deliberate: a program should not swallow a request to quit or an interrupt by accident.

Raising built-in exceptions

Use raise when your code detects a bad state and cannot continue correctly. The operand must be an exception class or an instance of one.

A built-in class is enough when the failure matches its meaning. Example: a function that takes a percentage should reject values above 100.

Pseudocode.

def set_percent(p):
    if p < 0 or p > 100:
        raise ValueError('percent must be 0 to 100')
    return p

The traceback ends with ValueError: percent must be 0 to 100. The class name is the type; the text is the message. A bare raise inside an except block re-raises the same exception object, so the caller sees the original traceback.

To add context while keeping the original cause, use raise ValueError('bad percent') from e. Python prints both tracebacks and a line saying the new exception was the direct cause of the old one. Without from e, the old context is still shown as 'during handling', but the link is less explicit.

User-defined exceptions

Write your own exception class when the built-in names do not describe your rule. A user-defined exception is an ordinary class that inherits from Exception. Put it near the code that raises it.

Add __init__ to store the data that explains the failure. Call super().__init__(message) so the base class holds the message. Add __str__ only when you want a custom printed form.

Pseudocode.

class InsufficientBalance(Exception):
    def __init__(self, short):
        self.short = short
        super().__init__('short by ' + str(short))
    def __str__(self):
        return 'short by ' + str(self.short)

Raise it like a built-in: raise InsufficientBalance(1000). Catch it by its own name: except InsufficientBalance as e. Inside that block, e.short is 1000 and str(e) is 'short by 1000'.

If no handler catches it, Python's default exception handler prints a traceback and stops the program. The traceback includes the custom class name, for example InsufficientBalance: short by 1000. That name is the clue for the reader.

A class that does not inherit from Exception is not an exception. raise rejects it with TypeError: exceptions must derive from BaseException. Order except blocks from the most specific to the most general. If except Exception comes first, later blocks never run.

Worked example

Question. A bank allows a withdrawal only if the balance is enough. Start with balance = 2000 rupees and withdraw = 3000 rupees. Write a user-defined exception class that carries the shortfall, raise it when the withdrawal is too large, and trace the run.

Python program.

class InsufficientBalance(Exception):
    def __init__(self, short):
        self.short = short
        super().__init__('short by ' + str(short))

balance = 2000
withdraw = 3000
try:
    if withdraw > balance:
        raise InsufficientBalance(withdraw - balance)
    balance = balance - withdraw
except InsufficientBalance as e:
    print(e, 'balance', balance)
  1. Define InsufficientBalance(Exception). Its __init__ stores short and calls super().__init__('short by ' + str(short)).
  2. Compute the shortfall: withdraw - balance = 3000 - 2000 = 1000 rupees.
  3. The test withdraw > balance is true, so raise InsufficientBalance(1000) runs.
  4. The next statement balance = balance - withdraw is skipped, so balance stays 2000 rupees.
  5. The handler except InsufficientBalance as e catches the object. str(e) is 'short by 1000', so the print gives short by 1000 balance 2000.

Exam traps

  • A class that does not inherit from Exception is not an exception; raise gives TypeError.
  • Order matters: except Exception before except ValueError catches the ValueError first, so the ValueError block is dead code.
  • except Exception does not catch SystemExit or KeyboardInterrupt; catch BaseException only if you truly mean to handle a quit or Ctrl+C.
  • ValueError and TypeError are different: int('abc') raises ValueError; '3' + 4 raises TypeError.
  • A bare raise works only inside an except block; outside it raises RuntimeError.

5.3 Text files: open, read, write, append and close

A text file is a sequence of characters stored on disk. Python does not edit the disk directly; it asks open() for a file object, and that object holds a pointer. The pointer marks the next character to read or write. This matters because marks, bills and log files live as text, and a program must move from writing a line to reading it back. The same object serves read(), readline(), write(), tell() and seek().

You need: 5.1 for FileNotFoundError, and Unit 3 strings for strip() and split().

open() and file modes

open(path, mode) returns a file object. path is a string such as 'marks.txt'. mode is a short string that decides what the program may do. The file object holds a pointer: the position of the next character to read or write. At open in 'r' or 'w', the pointer is at 0. In 'a', it is at the end of the file.

  • 'r': read only. The file must exist; otherwise open() raises FileNotFoundError.
  • 'w': write only. It erases an existing file at once, before the first write.
  • 'a': append. Writes go to the end; existing text stays.
  • 'r+': read and write. It does not erase the file.

Add 'b' for binary bytes, for example 'rb'; text work uses no 'b'. Use encoding='utf-8' once when text has characters outside plain ASCII. tell() returns the current pointer position as an opaque number. For plain ASCII text it equals the character count; with non-ASCII text under UTF-8 it is a byte offset and can be larger. seek(0) moves the pointer to the start. In text mode, any other seek() call must use a value that tell() returned earlier. Opening a file does not load the whole file into memory.

Writing and reading text

f.write(s) writes string s and returns the number of characters written. It adds no newline; put '\n' in the string yourself. f.writelines(list) writes each string in the list, again with no newline added. A file stores text, not numbers. To write 78, use str(78); f.write(78) raises TypeError.

f.read() returns all remaining text as one string. f.read(n) returns the next n characters. f.readline() returns the next line, including its '\n', or '' at end of file. f.readlines() returns a list of the remaining lines. for line in f: reads one line per turn without loading the whole file.

Each read moves the pointer forward by the characters consumed. To read a number back, take the line, use strip() to remove '\n' and spaces, then int() or float(). For two fields, parts = line.split() gives strings; int(parts[1]) gives the mark. The file does not remember that 78 was a number.

close() and the with statement

close() flushes buffered data to disk and releases the operating-system handle. Data may sit in memory until close() or flush(). The with statement closes for you even if an exception occurs: with open('marks.txt', 'r') as f: then an indented block. Use with for normal work. If open() fails, with never enters; catch FileNotFoundError with try/except from 5.1. A closed file cannot be read or written; Python raises ValueError. seek(0) returns to the start; a second read() after read() returns only the remaining text.

Worked example

Question. Write the two lines Anil 78 and Bina 91 into marks.txt, close it, append Chetan 65, then read the first line and report the pointer.

  1. Use open('marks.txt', 'w'). This creates a file object, erases any old marks.txt, and puts the pointer at 0.
  2. f.write('Anil 78\n') writes 8 characters: A, n, i, l, space, 7, 8, newline. It returns 8. The pointer moves to 8.
  3. f.write('Bina 91\n') writes 8 characters and returns 8. The pointer moves to 16.
  4. f.close() flushes the buffer. The file now holds 16 characters.
  5. Open in append mode: open('marks.txt', 'a'). f.write('Chetan 65\n') writes 10 characters and returns 10. The file now holds 26 characters.
  6. Close, then open in read mode: open('marks.txt', 'r'). f.readline() returns 'Anil 78\n'. Because all these characters are ASCII, the pointer moves to position 8, so f.tell() returns 8. For non-ASCII text, treat the value from tell() as an opaque position and pass it back to seek(); do not count characters.

Exam traps

  • Mode 'w' erases an existing file at open, before you write one character. A wrong mode loses the old data.
  • A file left open may never flush its buffer. Use close() or with, especially after writing.
  • read() at end of file returns an empty string '', not an error. A manual read loop must test for '' or use a for loop.
  • write() returns the number of characters written and adds no newline. Putting '\n' in the string is your job.
  • FileNotFoundError comes from open() in 'r' when the file is missing. Modes 'w' and 'a' create the file instead.

5.4 CSV and other formatted files

A CSV file stores a table as plain text: one record per line, fields separated by commas. Tab-separated and pipe-separated files use the same idea with another delimiter. Python's csv module reads and writes these files without you splitting lines by hand. It also handles quoting when a field itself contains a comma. Such files are common when marks, bank statements or UPI transaction exports move between Excel, Python and a database. Only a few universities teach this chapter; it is short and practical.

You need: 5.3 Text files for open, close, with and reading lines.

A table written as lines

A formatted file stores a table as plain text. One line is one record. Within a line, a delimiter separates fields. In a CSV file the delimiter is a comma. In a tab-separated file it is a tab character. A pipe-separated file uses |. The same rules apply to all three.

Open the file with newline=''. This lets the csv module see the real line endings. Then pass the file object to csv.reader. Each loop gives one list of fields. A record is also called a row; a field is also called a column value. A header row is optional, but many files use the first row for column names.

  • csv.reader(f) uses comma by default.
  • csv.reader(f, delimiter='\t') reads tab-separated data.
  • csv.writer(f) writes rows; writerow(row) writes one record.
  • The writer adds the delimiter and line ending for you. Do not split lines with str.split(',') by hand; quoting will break.
  • The csv module does not guess the delimiter; you must pass it.

Every field is text

csv.reader returns every field as a string. A mark of 78 arrives as '78', not 78. Convert before arithmetic: int(r[1]) for whole marks, float(r[2]) for prices.

If a field itself holds a comma, the writer puts double quotes around that field. The line Anil, Jr.,78 has three fields. The correct record is "Anil, Jr.",78, which has two fields. Read that line with csv.reader and the first field is Anil, Jr.. A quoted field may also contain a line break; csv.reader handles it as one field, not a new record.

  • Strings joined by + concatenate: '78' + '91' gives '7891'.
  • Convert to numbers first: int('78') + int('91') gives 169.
  • Use csv.writer to create quoted fields; do not add quotes by hand.

Named columns and JSON

csv.DictReader reads the first row as field names. Each later row becomes a dictionary keyed by those names. If the header is name,mark, then row['mark'] is still a string.

JSON is another formatted file. The json module turns a JSON file into Python lists and dictionaries. A JSON record can hold numbers as real numbers, unlike CSV text fields. CSV has no types; JSON has numbers, strings, booleans, lists and objects.

  • Use csv.DictReader(f) when column names matter.
  • Use json.load(f) for JSON objects and arrays.
  • Keep CSV for flat tables; use JSON when records are nested.
  • For full tables and column operations, see Unit 6, Pandas.

Worked example

Question. marks.csv holds two rows: Anil,78 and Bina,91. Read the file with csv.reader and print the average mark.

  2. The reader gives ['Anil', '78'] then ['Bina', '91'].
  3. r[1] is text: int('78') = 78 and int('91') = 91.
  4. total = 78 + 91 = 169.
  5. count = 2.
  6. average = 169 ÷ 2 = 84.5.

5.5 Directories with os and sys modules

A folder is a container on disk, and a path is its address. The os module lets a Python program read and change that address: it lists, creates and removes folders, and checks what a path points to. The sys module exposes the interpreter's own state, such as the command line that started the program. Scripts use both when they process a whole folder of CSV files, build output directories, or accept file names as command-line arguments.

You need 5.3 for paths and file names, and Unit 3 for strings and split().

Paths and the working directory

An absolute path starts at the root: /home/me/project on Linux, or C:\Users\me\project on Windows. A relative path starts from the current working directory (cwd), the folder the process is using. os.getcwd() returns that folder as a string. os.chdir(path) changes it. A relative open('data.txt') uses the cwd, so the same script can read different files when run from different folders.

os.path.join('project', 'data', '2024') builds project/data/2024 on Linux and project\data\2024 on Windows. It inserts os.sep, the platform separator. A hard-coded 'project\data' breaks on Linux, because Linux uses '/' only. Windows usually accepts '/' too, but the reliable, readable choice on both systems is os.path.join, which inserts os.sep.

  • os.getcwd() gives the current folder.
  • os.chdir(p) makes folder p the current folder.
  • os.path.join(a, b) joins names with os.sep.
  • os.sep is '/' on Linux and a backslash on Windows.

Create, list and remove

os.listdir(p) returns a list of names inside folder p, not full paths. Use os.path.join(p, name) to make a usable path. os.mkdir(p) creates one folder. Its parent must exist; a missing parent raises FileNotFoundError. If p already exists, it raises FileExistsError. os.makedirs(p) creates every missing parent and the leaf. os.makedirs(p, exist_ok=True) does not raise when p exists.

os.rmdir(p) removes an empty folder. os.remove(p) removes a file. os.rename(old, new) renames or moves a file or folder. A move works only within one filesystem; to move across disks, copy with shutil and then delete the original. os.path.exists(p) is True if p exists. os.path.isfile(p) and os.path.isdir(p) tell the type. os.path.getsize(p) returns a file's size in bytes. Check the type before you delete.

The folder tree in the figure is what os.listdir cannot show in one call: it lists one level only. To reach data/2024/report.txt you call os.path.join or os.walk.

sys.argv, sys.path and sys.exit

sys.argv is the list of command-line words. sys.argv[0] is the script name. sys.argv[1] is the first user argument, if any. For python add.py 12 30, sys.argv is ['add.py', '12', '30']. Convert each number with int() before adding.

sys.path is the list of folders Python searches for modules; see the chapter on modules and packages. sys.version is a string with the interpreter version. sys.exit(code) stops the program; code 0 means success. sys.stdout is the standard output stream; print() writes to it. sys.exit raises SystemExit, which ends the script.

os.walk(top) visits a folder tree. It yields one tuple (dirpath, dirnames, filenames) per folder. dirpath is the folder path, dirnames is a list of subfolder names, filenames is a list of file names. Use it to find every .csv under a project.

5.6 Built-in and user-defined modules; packages

A module is one .py file that other code imports by name. A package is a folder of modules with an __init__.py file, so Python treats the folder as one importable unit. This arrangement lets you split a long program into small files, reuse code, and borrow from Python's standard library. Every import follows the same path: check the cache, search sys.path, run the file once, bind a name. Indian exams often ask for the search order, the __name__ guard, and a dotted import such as shop.billing.

You need 5.5 for sys.path, Unit 2 for functions, and Unit 4 for grouping code into classes and modules.

Module, import, and the search path

A module is one .py file. A package is a folder with an __init__.py file and one or more module files. The folder becomes one importable unit. Python has four common import forms. import mymath binds the name mymath; use mymath.square(7). from mymath import PI binds only PI. import shop.billing binds shop; call shop.billing.gst(1000). import mymath as m binds m. from mymath import * binds all public names; avoid it in exam answers because the bound names are unclear.

An import does five things. First, Python checks sys.modules, a cache of modules already imported. If the name is there, it binds the name and stops. Second, it checks built-in modules such as sys. Third, it searches the folders listed in sys.path. The first entry is the script's folder, so a local file can hide a standard module. Fourth, for a package it runs shop/__init__.py, then runs billing.py once. Fifth, it binds the dotted name shop.billing in the importing file.

Write a module, guard it, make a package

Your own module. Put code in mymath.py in the same folder as the script. The file can hold PI = 3.14159 and def square(n): return n * n. A second file uses import mymath. Top-level code in a module runs at the first import and not again. A counter at module level keeps its old value on the next import.

The guard. A file may be run directly or imported. __name__ is '__main__' when run directly and the module name when imported. The guard keeps test code out of imports.

5.7 Regular expressions

A regular expression is a pattern written as text that describes a whole set of strings. The re module in Python compares one string against that pattern and reports whether it fits, where it fits and which pieces fit. It exists so that searching, validating and rewriting text does not need a hand-written loop for every case. Common uses are checking a date or PIN, pulling all numbers out of a log line, and replacing phone numbers in a file of customer records. See Unit 3 for plain string methods, which handle simple cases.

You need: reading lines from a file (5.3) and string methods and slicing (Unit 3).

Literal characters, classes and anchors

Most characters in a pattern match themselves. In r'cat', c matches c, a matches a, t matches t. The dot . matches any one character except a newline. A character class in square brackets matches one character from a list or range: [0-9] is any digit, [a-z] any lowercase letter. The shorthand \d means any digit 0-9, \w means a letter, digit or underscore, and \s means a space, tab or newline. The capital forms \D, \W and \S are the negations: \D is any non-digit.

Inside a class, a leading ^ negates: [^0-9] is any non-digit. Outside a class, ^ is an anchor for the start of the string and $ is an anchor for the end. So r'^\d' means the string starts with a digit, and r'\d$' means it ends with one.

Quantifiers, groups and choices

Quantifiers repeat the item just before them. \d* is zero or more digits, \d+ is one or more, \d? is zero or one, and \d{4} is exactly four; \d{2,4} allows two, three or four. By default a quantifier is greedy: it takes as many characters as possible. Add ? to make it non-greedy: .+? stops at the first chance.

The vertical bar | means alternation: (cat|dog) matches cat or dog. Parentheses group part of a pattern. Each group is numbered from 1 by its opening parenthesis; group(1), group(2) return the text each group matched. Group 0 is the whole match.

Advanced forms: a named group such as (?P<year>\d{4}) gives a capture group a name — the name must be a valid Python identifier; a backreference \1 reuses the text already captured by group 1; and a lookahead (?=...) checks what follows without consuming it.

The re functions and the match object

re.match(pattern, string) tests only at position 0; it returns a match object or None. re.search(pattern, string) scans forward and returns the first match anywhere, or None. re.findall returns a list of all non-overlapping matches; when the pattern has two or more groups, each list item is a tuple of the group texts, and with one group it is the group text. re.sub(pattern, replacement, string) replaces every match and returns a new string. re.split(pattern, string) cuts the string at each match and returns a list of pieces. re.compile(pattern) builds a pattern object once, for reuse; it has match, search, findall, sub and split methods.

A match object has group(n) for group n, start() for the index where the match begins, end() for the index just after it, and span() for the pair (start, end). Use a raw string for every pattern: r'\d' sends backslash and d to re, while '\d' is an ordinary string in which Python's escape rules apply.

Python program.

import re
m = re.match(r'(\d{4})-(\d{2})-(\d{2})', '2024-07-05')
print(m.group(0))
print(m.group(1), m.group(2), m.group(3))
print(m.start(), m.end())
print(re.findall(r'\d+', 'Anil 78, Bina 91'))
print(re.sub(r'\d+', '#', 'Anil 78, Bina 91'))
print(re.split(r',\s*', 'Anil 78, Bina 91'))

  1. Import re and call m = re.match(r'(\d{4})-(\d{2})-(\d{2})', '2024-07-05'). The pattern starts with \d{4}, exactly four digits. At position 0 the text is 2024, so group 1 is '2024'.

Exam traps

  • ^ inside [ ] negates the class; outside it anchors at the start. [^0-9] is a non-digit, while ^\d means starts with a digit.

open() returns a file object; close() releases it; 'r' read, error if missing; 'w' create or truncate; 'a' create or append; 'x' exclusive create; 'b' binary and '+' read-write combinations; Pointer starts at 0 in 'r', at end in 'a'; tell() reports it, seek() moves it; read(), readline(), readlines(), write(), writelines(); with open(...) as f: closes automatically even on exception; Text mode decodes using an encoding; binary mode returns bytes.

Analyze and evaluate

Analyze Compare the two styles of guarding against errors — checking conditions before acting, and catching exceptions after acting. Discuss which Python style is preferred for file and network work, and evaluate the risks of an empty except clause and of a finally block that returns a value. 14 marks

Check-first style: test os.path.exists then open; cost of a second call and a race with other programs; Catch-after style: attempt the operation, handle the specific failure; Python idiom favours catching specific exceptions for input/output; except: pass hides real bugs including KeyboardInterrupt; catch named classes only; A return inside finally replaces any earlier return or exception, so avoid it; finally is for cleanup such as close, not for decisions; Conclusion: name the exception, keep the try block small.

Evaluate A shop keeps transactions.csv with the columns date, upi_id, amount, where some rows have bad dates and non-numeric amounts. Design a program that validates and cleans the file, writes a clean CSV plus an error log, and is organised as a package with separate modules for validation and file input/output. Justify each design choice. 16 marks

Package layout: shop/__init__.py, shop/io_utils.py, shop/validate.py, main.py; Regular expression or datetime.strptime for the date, float() inside try for the amount; One user-defined exception such as InvalidRow carrying the line number; csv.DictReader over the input, csv.writer to the clean file, plain text log for rejects; with open for each file so every handle closes on error; __name__ guard in main.py and only function definitions in the helper modules; Trade-off: validating every row costs time but keeps bad data out of reports; Conclusion: separate reading, validating and writing so each part can be tested alone.

Glossary

__init__.py
The file that marks a directory as a package and runs when the package is first imported.
__name__
A module-level string equal to "__main__" when the file is run directly, otherwise the module's own name.
Built-in exception
A predefined exception class such as ValueError, IndexError or FileNotFoundError.
Context manager
An object usable in a with statement that performs setup on entry and cleanup on exit, such as an open file.
CSV
Comma-separated values, a plain-text table format with one record per line.
Delimiter
The character separating fields on one line of a formatted file.
Dialect
A named set of formatting rules in the csv module, such as excel or excel-tab, controlling delimiter and quoting.
else clause
The optional block of a try statement that runs only when no exception occurred.
except clause
A handler naming an exception class that runs when that class, or a subclass of it, is raised in the try.
Exception
An object created at run time that represents an error and interrupts the normal flow of statements.
Exception hierarchy
The tree of exception classes with BaseException at the root and Exception as the usual base for program errors.
File object
The handle returned by open() through which a program reads from or writes to a file.
File pointer
The current byte or character position in an open file, moved by seek() and read by tell().
finally clause
The optional block of a try statement that always runs, used for cleanup.
Mode string
The argument to open() that selects reading, writing, appending, binary or update behaviour.
Module
A single .py file whose names can be brought into another program with import.
os module
The standard library module providing directory operations and portable path helpers.
Package
A directory of modules containing an __init__.py file, imported under one dotted name.
raise
The statement that throws an exception object to the nearest enclosing handler.
Raw string
A string written as r"..." in which backslashes are kept literally, useful for regex patterns and Windows paths.
re module
The standard library module offering compile, match, search, findall, sub and split for regular expressions.
Regular expression
A pattern language describing a set of strings, used for matching, searching and replacing text.
sys module
The standard library module exposing interpreter state such as argv, path, stdin, stdout and exit().
Traceback
The report Python prints showing the call stack and the line where an uncaught exception was raised.
try block
The statements Python attempts first, with handlers attached for the errors they may raise.
User-defined exception
A class you write as a subclass of Exception to name and carry information about your own error.
