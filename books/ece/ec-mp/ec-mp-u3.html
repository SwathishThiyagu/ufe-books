3.1 Instruction formats and instruction set classification

An instruction is a coded command. The CPU fetches it as a pattern of bits and splits that pattern into fields. One field, the opcode, says what operation to perform. The rest, the operand or address field, says where the data is. The width and order of these fields is the instruction format, also called instruction encoding. Programmers never write these bits by hand; the assembler does it. Knowing the format explains why instruction lengths run from one byte on the 8085 up to six bytes on the 8086, why a PIC uses fixed 12- or 14-bit words, and why a jump needs more bytes than an increment.

You need: the stored-program idea and binary numbers from Unit 1, and the register names of the 8085 and 8086 from Unit 2.

Opcode field and operand field

Every instruction carries at least an opcode. Extra fields appear when the operation needs data. A register field is 3 bits wide on the 8085 and 8086, because 3 bits can name 8 registers. An immediate field holds the constant itself, inside the instruction. An address field holds a memory address, 16 bits on the 8085. The 8086 adds a ModRM byte, a single byte that names one register and says whether the other operand is a register or a memory location.

  • 8085: 1, 2 or 3 bytes. MOV A,B is 78H, one byte. MVI A,3FH is 3E 3F, two bytes. LDA 2000H is 3A 00 20, three bytes, address low byte first.
  • 8051: 1 to 3 bytes. INC A is 04H; MOV A,#3FH is 74 3F; LJMP 2000H takes three bytes.
  • 8086: 1 to 6 bytes. A ModRM byte, a displacement and an immediate may all follow the opcode.
  • PIC: fixed words of 12 bits (PIC12 family) or 14 bits (PIC16 family), so every instruction in these families is one word.

L = B_p + B_op + B_M + B_d + B_i

L is the instruction length in bytes; B_p is 0 to 3 prefix bytes (LOCK, REP, REPNE, segment override), each 1 byte; B_op is the opcode size (1 byte on the 8085, 8086 and 8051); B_M is a ModRM byte (0 or 1); B_d is a displacement (0, 1 or 2 bytes); B_i is an immediate (0, 1 or 2 bytes). On the 8086 the total, prefixes included, never exceeds 6 bytes.

Zero, one, two and three address formats

Formats are also named by how many operands an instruction may write down. Fewer operands mean shorter instructions but more instructions per job.

The 8086 and 8051 are two-address machines with the destination written first. On the 8085, MOV A,B names two registers with the destination first, but the arithmetic and logical instructions such as ADD B are one-address with A implicit (A ← A + B). Stack machines such as the Java virtual machine use the zero-address form, where the opcode alone is the whole instruction.

Classifying the set by function

Instruction sets are grouped by what an instruction changes. Textbooks list five or six groups; the borders are not sharp, and one instruction may sit in two groups.

  • Data transfer: MOV, MVI, LDA, STA, IN, OUT, PUSH, POP. They move bits and leave the flags alone; PUSH and POP also change the stack pointer SP. See 3.3.
  • Arithmetic: ADD, ADC, SUB, INR, DCR, DAD on the 8085; MUL and DIV on the 8086. See 3.4.
  • Logical: ANA, ORA, XRA, CMP, RLC, RRC on the 8085; AND, OR, XOR, TEST on the 8086.
  • Branch and control transfer: JMP, JZ, JNC, CALL, RET, DJNZ. These can change the program counter. See 3.5.
  • Bit manipulation: SETB, CLR, CPL, JB, JNB on the 8051; the 8086 sets and tests single bits with logical instructions.
  • Machine control: HLT, NOP, EI, DI, SIM, RIM, WAIT on the 8085; the 8051 uses power-control bits instead of HLT.

A quick test while reading a listing: if only a register, memory cell or port changes, it is data transfer; if the program counter may change, it is a branch; if nothing in the program changes, it is machine control.

The four fields of an assembly statement

One line of assembly holds up to four columns.

LOOP:   MOV   A, B      ; copy B into A
  • Label: optional, starts in column one and ends with a colon. It marks this address so a branch can name it.
  • Mnemonic: the fixed name of the opcode, such as MOV or ADD. It comes from the manufacturer's table, not from the programmer.
  • Operand: zero to three items separated by commas; for two-address instructions the destination comes first.
  • Comment: everything after a semicolon. The assembler ignores it.

Translation of these four fields into machine code is the assembler's job, covered in 3.8.

Worked example

Question. Encode these two instructions and state the length of each in bytes: (a) 8085 MVI A, 3FH; (b) 8086 MOV AX, BX.

  1. (a) The 8085 opcode for MVI A, move immediate to the accumulator, is 3EH. One byte.
  2. The immediate value 3FH follows as the second byte, because the opcode has no room for 8 data bits.
  3. Encoding: 3E 3F. Length = 1 opcode byte + 1 immediate byte = 2 bytes.
  4. (b) MOV AX,BX uses the 8086 register-to-register form, opcode 89H, which means move a 16-bit register into a register or memory operand.
  5. The next byte is ModRM. mod = 11 means both operands are registers. reg = 011 names BX, the source. r/m = 000 names AX, the destination. The byte is 11 011 000 = D8H.
  6. No displacement and no immediate follow. Encoding: 89 D8. Length = 2 bytes.

Answer. Both instructions are 2 bytes long: 3E 3F for MVI A,3FH and 89 D8 for MOV AX,BX.

Exam traps

  • Later bytes are not opcodes. In 89 D8 the D8H is a ModRM byte; reading it as an opcode gives nonsense, and the 8086 length is not fixed.
  • Little-endian addresses: LDA 2000H assembles to 3A 00 20, not 3A 20 00. Writing the high byte first points at 0020H.
  • Mnemonic is not opcode. MOV and ADD are names the assembler translates; 78H and 89H are opcodes. Examiners often ask for the opcode of a given mnemonic.
  • One-address does not mean one operand. 8085 ADD B changes A and all the flags even though only B is written on the line.
  • PIC instruction words are 12 or 14 bits, not 8. A 14-bit instruction does not fit one 8-bit memory location.

3.2 Addressing modes

An addressing mode is the rule the CPU uses to find an operand. The operand is the data an instruction works on; its address is called the effective address. A single opcode such as ADD can take its second value from a register, from the instruction itself, or from memory at an address held in another register. The mode is encoded in the instruction bits. Without modes, every instruction would need a full memory address, and code would be long and slow. Modes let the same operation work on constants, variables, arrays and stack data. Compilers and hand-written assembly choose modes to save bytes and cycles.

You need: the opcode and operand fields of an instruction from 3.1, and segment registers and memory organisation from Unit 2.

Effective address and the simple modes

The CPU executes an instruction in two parts. The opcode says what to do; the operand field says what to do it to. The effective address (EA) is the address the CPU finally uses to read or write the operand. An addressing mode is the rule that turns the operand field into that address. For a register operand the EA is the register itself; no memory address is needed.

Implied mode, also called implicit mode, has no operand field. The instruction itself fixes the operand. In 8085, CMA complements the accumulator: the accumulator is always the operand. PUSH and POP also use an implied stack pointer.

Immediate mode puts the operand inside the instruction. MVI A,32H loads the constant 32H into A. The 32H is data, not an address. The 8086 form is MOV AL,32H. Immediate operands are fast but fixed at assembly time.

Register mode names a CPU register as the operand. 8085 MOV A,B copies B into A. The data never leaves the CPU, so this is the fastest mode. The instruction is short because only a register number is encoded.

Direct mode, also called absolute mode, puts the memory address in the instruction. 8085 LDA 2050H reads the byte at memory location 2050H. The address is fixed, so the instruction is long. In 8086, MOV AL,[2050H] is direct, but the address is an offset from DS; see the trap below.

Register indirect mode puts the address in a register. 8085 MOV A,M reads the memory location whose address is in the HL pair. The 8051 form is MOV A,@R0: @R0 means 'the memory location whose address is in R0'. The register acts as a pointer, so one instruction can walk through an array by changing the pointer.

Indexed, based, relative and stack modes

Indexed mode adds an index register to a displacement. The index changes at run time, so the same instruction reaches different array elements. 8086 MOV AL,[SI+10H] uses SI as the index and 10H as the displacement.

Based mode adds a base register to a displacement. The base usually points to the start of a data structure, and the displacement selects a field. 8086 MOV AL,[BX+10H] uses BX as the base.

Based-indexed mode adds a base, an index and a displacement. 8086 MOV AL,[BX+SI+10H] uses BX as base, SI as index and 10H as displacement. The effective address is EA = BX + SI + 10H. The worked example below computes it with real numbers.

Relative mode adds a signed offset to the program counter. Branch instructions use it so that code can be moved in memory without changing the branch. 8086 JMP SHORT label adds an 8-bit displacement to IP, and 8051 SJMP label adds an 8-bit offset relative to the program counter. The 8085 has no relative branch: its JMP and conditional jumps hold a 16-bit absolute address, so 8085 code cannot simply be moved in memory.

Stack mode takes the operand from the top of the stack. The stack pointer is implied, so no address appears in the instruction. 8085 PUSH B decrements SP by 2 and stores B and C. 8086 PUSH AX subtracts 2 from SP first and then stores AX at the new [SP], so the word ends up at the address SP − 2. POP AX does the reverse: read the word at [SP], then add 2 to SP.

Some syllabi call direct mode 'absolute' and call register indirect mode 'simple indirect'. The mechanism is the same: the instruction gives an address, or gives a register that holds an address.

The same instruction in three instruction sets

The 8085 has a small but clear set. MOV A,B is register mode. MVI A,32H is immediate. LDA 2050H is direct. MOV A,M is register indirect through HL. LXI H,2050H is immediate because the 16-bit constant 2050H is loaded into HL.

The 8051 marks modes in the mnemonic. MOV A,R0 is register mode. MOV A,#32H is immediate; the # sign means the constant 32H, not address 32H. MOV A,30H is direct; 30H is a memory address. MOV A,@R0 is register indirect. MOVC A,@A+DPTR is indexed: the address is A + DPTR, and the byte comes from code memory.

The 8086 uses brackets for memory. MOV AL,BL is register mode. MOV AL,32H is immediate. MOV AL,[2050H] is direct. MOV AL,[BX] is register indirect. MOV AL,[BX+SI+10H] is based-indexed. JMP SHORT label is relative.

PIC microcontrollers use a register-file model. Most instructions address a file register directly or through the FSR/INDF pair, which acts as an indirect pointer. The idea is the same: the instruction says how to find the operand, and the mode decides whether the address is in the instruction, in a register, or computed.

Worked example

Question. An 8086 system has DS = 2000H, BX = 0100H, SI = 0020H and a displacement of 10H in the instruction MOV AL, [BX+SI+10H]. (a) Find the effective address. (b) Find the physical address. (c) Which byte is fetched?

  1. Write the rule for based-indexed addressing: EA = BX + SI + displacement. BX = 0100H, SI = 0020H, displacement = 0010H.
  2. Add the three values: 0100H + 0020H = 0120H; 0120H + 0010H = 0130H. EA = 0130H = 304 in decimal.
  3. Convert the segment base: DS × 10H = 2000H × 10H = 20000H.
  4. Add the segment base to the EA: 20000H + 0130H = 20130H. In decimal, 131072 + 304 = 131376.
  5. The CPU reads one byte from physical address 20130H into AL.

Answer. EA = 0130H (304 in decimal); physical address = 20130H (131376 in decimal); the byte is fetched from 20130H.

Exam traps

  • In 8086 the effective address is not the physical address. Add DS × 10H after computing the EA. In 8085 a direct address such as LDA 2050H is already the physical address.
  • [BX] uses DS by default, but [BP] uses SS. Check the base register before adding a segment.
  • MVI A,32H is immediate: 32H is the data. LDA 2050H is direct: 2050H is an address. Do not swap them.
  • MOV A,M is register indirect: M means the memory location whose address is in HL. MOV A,B is register mode: B holds the data itself.

3.3 Data transfer instructions

A data transfer instruction copies a byte or a word from one place to another: register to register, memory to register, register to memory, or an I/O port to the accumulator. It does not add, subtract or compare. It exists because the ALU can only work on values already in registers, so data must be moved there first. Every program uses these instructions: reading a sensor port, loading a constant from a look-up table, saving a result back to memory. The source is not erased; only the destination changes.

You need: 3.2 Addressing modes and the register models from Unit 2, 8085 and 8086 Microprocessors.

A copy, not a computation

The instruction writes a destination and reads a source. After MOV A,B both A and B hold the same byte, because B is copied and not consumed. This is why the operation is called a transfer even though nothing leaves the source.

On the 8085 the destination is written first. MOV r1,r2 copies register r2 into register r1. MVI r,data copies an 8-bit constant into r. The symbol M means the memory byte whose address is in HL, so MOV M,r writes memory and MOV r,M reads it. A memory access is slower than a register copy because it drives the address and data buses (see Unit 2, Timing diagrams and machine cycles).

Most transfers leave the flags alone. The 8085 MOV, MVI, LDA, STA, LDAX, STAX, LHLD, SHLD, XCHG, IN and OUT do not touch the five flags (S, Z, AC, P, CY). The 8086 MOV, XCHG, LEA, LDS, LES, XLAT, IN and OUT do not touch them either. A copy is not an arithmetic result: a zero byte copied is not an arithmetic zero, and the CPU must not let a later jump change because of a move. Instructions that load a flag register on purpose are the exception, and their names say so.

Two rules follow. Never expect a move to set or clear a flag. Never expect the source to be erased.

LHLD and SHLD use 16-bit addresses and store the low byte first: the byte at addr16 goes to L, the byte at addr16+1 goes to H. Reading the pair the other way is the classic byte-order mistake.

LDAX and STAX exist only for BC and DE. There is no LDAX H or STAX H opcode, and none is needed, since MOV A,M and MOV M,A already copy between A and the byte at HL. XCHG swaps HL and DE in one instruction, so 16-bit arithmetic on HL can continue on the other pair; it changes no flags, so a carry from an earlier operation survives the swap.

IN and OUT carry an 8-bit port address inside the instruction, and the accumulator is the only register that can talk to a port. Some syllabi group IN and OUT under data transfer, others under I/O; the operation is still a copy between A and a port latch.

8086 and 8051 transfers

8086. MOV copies a byte or word between registers, between a register and memory, or between a segment register and a register or memory. Memory-to-memory MOV does not exist; one operand must be a register. XCHG swaps two operands, at least one in a register. LEA loads the effective address, not the contents: with SI = 0100H, LEA BX,[SI+4] puts 0104H in BX, while MOV BX,[SI+4] would load the two bytes stored at 0104H. LDS and LES load a far pointer: a 16-bit offset into the named register and a 16-bit segment into DS or ES. XLAT replaces AL with the byte at BX+AL, a one-instruction table look-up. IN and OUT take a 16-bit port address from DX or an 8-bit address from the instruction.

8051. MOV works inside the chip: registers, internal RAM, special function registers and single bits. MOVX moves A to or from external data memory through DPTR or R0/R1. MOVC reads program memory, used for constants. XCHD swaps the low nibble of A with the low nibble of an internal RAM byte and leaves both high nibbles alone. SWAP A exchanges the two nibbles of A. PUSH and POP copy through the stack and change SP each time; the details are in 3.6 Stack and subroutines.

None of these change flags. PUSH and POP are not plain copies: they move the stack pointer, so a loop that pushes without popping will overflow the stack area.

Worked example

Question. An 8085 system has A = 25H, B = 4AH, HL = 2050H, and memory [2050H] = FFH. Execute MOV A,B and then MOV M,A. Give A, B and [2050H] after both instructions, and say what happens to the flags.

  1. Write the starting state: A = 25H = 37, B = 4AH = 74, HL = 2050H, [2050H] = FFH = 255.
  2. MOV A,B reads B and writes A. A becomes 4AH = 74. B keeps 4AH = 74. Memory is untouched at FFH.
  3. MOV M,A uses M = [HL] = [2050H]. A is 4AH, so [2050H] becomes 4AH = 74. A stays 4AH and B stays 4AH.
  4. MOV does not touch flags, so S, Z, AC, P and CY keep their earlier values.

Exam traps

  • MOV A,B changes A only; B is not cleared, so both registers end with the same byte.
  • MOV M,r writes memory at HL, while MOV r,M reads memory at HL. The position of M matters.
  • LDAX and STAX exist only for BC and DE. There is no LDAX H or STAX H opcode, and none is needed; MOV A,M and MOV M,A already copy between A and the byte at HL.
  • LEA gives the address and MOV gives the contents. LEA BX,[SI] and MOV BX,[SI] give very different values.
  • PUSH and POP change SP, so they are not simple copies; an unmatched PUSH in a loop overflows the stack.

3.4 Arithmetic and logical instructions

Arithmetic and logical instructions are the ALU's commands. They add, subtract, multiply, divide, compare, AND, OR, XOR, complement, rotate and adjust decimal results. Each instruction takes operands and computes a result. Most write a result back and update flags; compare instructions only set flags, and INR/DCR and INX/DCX leave carry (or all flags) untouched. The flags remember the last ALU result: zero, sign, carry, auxiliary carry, parity and overflow. Later branch instructions read those flags, so one compare can drive a decision. A calculator, a UPI amount check, or a motor speed limit test all reduce to these instructions plus a branch.

You need: data movement in 3.3 and the flag register from Unit 2.

Arithmetic instructions and flags

Arithmetic instructions compute in the ALU and change flags. On the 8085: ADD adds a byte to A; ADC adds with carry; SUB subtracts; SBB subtracts with borrow; INR/DCR change a byte by one; INX/DCX change a register pair by one; DAD adds a pair to HL; CPI compares A with an immediate byte; CMP compares A with a register or memory byte and leaves A unchanged. On the 8086, MUL/IMUL multiply unsigned/signed; byte results go to AX, word results to DX:AX. DIV/IDIV divide and store quotient and remainder. The 8051 has ADD, ADDC, SUBB, MUL AB, DIV AB and DA A.

Flags record the last ALU result. C is carry out of bit 7, or a borrow in subtraction. AC is carry from bit 3 to bit 4; in subtraction AC = 1 means a borrow from bit 4, just as C = 1 means a borrow from bit 8. S copies bit 7. Z is 1 when all result bits are 0. P is parity: the 8085 uses even parity, the 8051 uses odd. OV is signed overflow: the result does not fit the signed range. The 8085 has no OV flag; the 8086 and 8051 do. INR/DCR do not affect C. INX/DCX affect no flags. DAD affects only C.

Logical, rotate and decimal instructions

Logical instructions work bit by bit. AND clears bits where the mask has 0; use it to test or keep selected bits. OR sets bits where the mask has 1. XOR toggles bits where the mask has 1. CMA on the 8085 and NOT on the 8086 complement every bit. These pack status bits, select an I/O device, or clear a field. RAL and RAR move bits through carry; RLC and RRC rotate A circularly and also copy the bit that falls off into C. RLC rotates A left; bit 7 goes to C and to bit 0. RRC rotates A right; bit 0 goes to C and to bit 7. RAL rotates left through carry; old C enters bit 0 and bit 7 enters C. RAR rotates right through carry; old C enters bit 7 and bit 0 enters C. The 8085 has DAA only; it has no decimal-adjust instruction for subtraction. DAA adjusts A after packed BCD addition. DAS is an 8086 instruction; it adjusts after BCD subtraction. The 8051 uses DA A only after addition. Bit-manipulation instructions are a related group: SETB, CLR and CPL act on one bit in the 8051, while the 8086 has TEST, which ANDs two operands only to set flags; bit test and modify instructions (BT, BTS, BTR, BTC) come with the 386 and later. Use them for flags, port pins and single status bits.

Worked example

Question. 8085: A = 9CH and B = 7FH. Execute ADD B. Find A and the flags C, AC, S, Z and P. Also give the signed-overflow condition OV that an 8086 would report.

  1. 9CH = 1001 1100₂ = 156₁₀. 7FH = 0111 1111₂ = 127₁₀.
  2. ADD B: A ← A + B. Sum = 156 + 127 = 283₁₀ = 11B₁₆. Low byte = 1B₁₆ = 27₁₀. Carry out of bit 7 = 1.
  3. AC: low nibble C₁₆ + F₁₆ = 12 + 15 = 27 > 15, so carry from bit 3 to bit 4 = 1.
  4. S: bit 7 of 1BH = 0001 1011₂ is 0.
  5. Z: result 1BH ≠ 0, so Z = 0.
  6. P: 1BH = 0001 1011₂ has four 1 bits, an even number, so P = 1.
  7. Signed OV: 9CH = −100, 7FH = +127, sum = +27, which fits −128 to +127, so OV = 0. The 8085 has no OV flag; an 8086 would show OV = 0.

Answer. A = 1BH (27 decimal), C = 1, AC = 1, S = 0, Z = 0, P = 1, OV = 0.

Exam traps

  • Carry and overflow are different: C is unsigned carry or borrow; OV is signed overflow. In subtraction, C = 1 means a borrow, not a negative result.
  • INR and DCR do not affect C. INX and DCX affect no flags. DAD affects only C.
  • On the 8085 only DAA exists. On the 8086, DAA follows BCD addition and DAS follows BCD subtraction. The 8051 has DA A and uses it only after addition.
  • CMP and CPI set flags by subtraction but do not change A. Do not treat them as SUB.
  • MUL and IMUL put results in fixed registers and set CF/OF; DIV and IDIV store quotient and remainder in fixed registers. DIV and IDIV leave all flags undefined; do not test a flag after them. MUL and IMUL set only CF and OF (with SF, ZF, AF, PF undefined).

3.5 Branch, jump and call instructions

Branch, jump and call instructions change the program counter (PC), the register that holds the address of the next instruction. A jump replaces the PC with a target address. A conditional jump does that only when a flag matches, so the CPU can choose between paths after a compare. A call also saves a return address on the stack, so RET can come back. These control transfer instructions build if-then logic, loops and subroutines in every 8085, 8086 and 8051 program.

You need: flags from 3.4 and the program counter from Unit 2.

Unconditional and conditional jumps

An unconditional jump always changes the PC. The 8085 JMP addr loads addr. The 8086 JMP may be SHORT (8-bit displacement), NEAR (same code segment) or FAR (new CS:IP). The 8051 has SJMP (relative, -128 to +127 bytes), AJMP (absolute inside a 2 KB page) and LJMP (16-bit absolute). A relative target is measured from the instruction after the jump; an absolute target is the full address carried in the instruction. Some syllabi call these control transfer instructions.

A conditional jump tests flags set by an earlier instruction, often CMP. CMP subtracts operands and sets flags but stores no result. Z is the zero flag, C is carry, S is sign and P is parity. On the 8085, JZ jumps if Z = 1; JNZ if Z = 0; JC if C = 1; JNC if C = 0; JP if S = 0; JM if S = 1; JPE if P = 1; JPO if P = 0. On the 8086, JS/JNS are the usual sign jumps and JP/JNP (or JPE/JPO) test parity; assemblers may accept older aliases. Check the mnemonic against the CPU: on the 8085 JP tests S = 0 (positive) and JPE tests parity, while on the 8086 JP and JPE both mean parity even and the sign jumps are JS/JNS.

The 8051 is different: JZ jumps when accumulator A is zero, and JNZ jumps when A is not zero. CJNE compares and jumps if not equal, and sets C = 1 if the first operand is below the second unsigned. DJNZ decrements a register and jumps if it is not zero.

CALL, RET and counted loops

A call is a jump that remembers where to return. The CPU loads the target into PC and pushes the return address, the address of the instruction after CALL, on the stack. RET pops that address back into PC. On the 8085, CALL pushes the 16-bit PC. On the 8086, a near call pushes only IP; a far call pushes CS and IP. The 8051 LCALL pushes the 16-bit PC, and ACALL is a 2 KB page call. Use a call for reusable code; see 3.6 for stack details.

LOOP is a counted jump. 8086 LOOP decrements CX and jumps to the label if CX ≠ 0. If CX = 0 it falls through. 8051 DJNZ does the same with any register: DJNZ R2, label. A loop body runs once for each starting count, and the register ends at 0.

Near and far calls differ in stack use. A near target is in the same segment. A far target has a new segment and offset. A RET must match the call type; a far RET pops CS and IP. A wrong RET corrupts the stack.

Relative, absolute and page targets

A relative jump stores a small signed displacement d. The CPU computes the target from the next instruction, not from the jump's own address. Example: at 1000H, an 8051 SJMP with d = +05H jumps to 1007H, because the instruction is 2 bytes, so the next address is 1002H and 1002H + 5 = 1007H. The range is -128 to +127 bytes, so relative code is compact and movable.

target = next instruction address + d

d is the signed displacement in bytes; next instruction address is the address after the jump instruction.

An absolute jump stores the full target. AJMP stores 11 address bits (A10-A0) and takes the upper 5 bits from the address of the next instruction, so the target must lie in the same 2 KB page as the instruction after the AJMP. LJMP stores all 16 bits. The 8086 SHORT jump stores an 8-bit displacement and the NEAR jump a 16-bit displacement, both counted from the address of the next instruction, so both are relative. A FAR jump carries a full CS:IP address and is absolute. Choose relative for nearby code and absolute for fixed addresses such as interrupt vectors.

3.6 Stack and subroutines

A subroutine is a block of code written once and used many times. To use it, the CPU must remember where to come back to, and that memory is the stack: a last-in-first-out area of RAM. PUSH saves a byte or a word, POP brings it back, CALL jumps into a subroutine after saving the return address, and RET uses that saved address to return. Every function call in C and every interrupt depends on this mechanism, so the stack is the first thing an examiner asks about in an assembly question.

You need Chapter 3.5 for call and return instructions, and the memory addressing ideas of Unit 2.

The stack and the stack pointer

The stack is a block of RAM used last-in-first-out: the item written last is the first one read. A canteen stack of plates behaves the same way — you lift the top plate.

The CPU keeps the address of the top of the stack in the stack pointer, SP. In the 8085 and 8086, SP is 16 bits wide. In the 8051 it is 8 bits wide.

PUSH saves one item and moves SP; POP reads one item and moves SP back. The 8085 and 8086 stack grows towards lower addresses: SP is decremented before the write. A 16-bit push keeps the high byte at the higher address and the low byte at the lower address.

CALL and RET

In the 8085, CALL 2100H is three bytes: opcode, low byte of the target, high byte. Two things happen in order. First the CPU pushes the address of the instruction after the CALL, that is PC + 3. Then it loads PC with 2100H, so the next fetch comes from the subroutine.

RET reverses this: it pops two bytes into PC and the caller continues. The value saved is PC + 3, so the address inside CALL itself is never stored.

Conditional calls such as CC, CNC, CZ, CNZ, CP, CM, CPE and CPO test a flag before pushing. Conditional returns such as RC, RNC, RZ and RNZ test a flag before popping. An instruction that fails its test pushes (or pops) nothing at all.

Nested calls work because each call pushes a fresh return address. If A calls B and B calls C, the stack holds two return addresses (three if A was itself called), and the returns unwind in reverse order. The depth is limited only by free stack memory.

Passing parameters to a subroutine

A subroutine needs data from its caller. Three routes are common.

  • Registers: the caller loads values into A, B or HL and the subroutine reads them. Fast, no memory traffic, but only a few values fit and both sides must agree on the assignment.
  • Memory block: the caller stores the data as a table and passes the starting address in a register pair such as HL. Good for arrays and strings.
  • Stack: the caller pushes the arguments and then executes CALL; the subroutine reads them at fixed offsets from SP. The two sides must agree who removes them afterwards.

A well-written subroutine first pushes the registers it will destroy and pops them just before RET. This save-and-restore is the context save, and it lets the caller keep working values in registers across the call.

A subroutine is re-entrant if it can be interrupted and entered again before it finishes. This works when every working value sits on the stack and the code never writes to fixed memory locations. Only a few universities teach re-entrancy in detail.

Stack limits and overflow

The programmer reserves a stack area in RAM and points SP into it. On the 8085 and 8086, point SP at the highest address of the reserved area with LXI SP, 2050H; every push then moves down. On the 8051, MOV SP, #50H makes the stack grow upward from 51H, so reserve the space above SP.

If pushes run past the reserved space, the stack overflows. It overwrites variables, or the return address itself, and RET jumps to a wrong address — the program hangs or restarts.

In the 8051 everything sits in 128 bytes of internal RAM. SP resets to 07H, so about 120 bytes are free for the stack, and register banks and variables take their share. Count before you nest: on the 8085, 8086 and 8051 each call costs 2 bytes, so deep recursion on an 8051 runs out of space quickly.

Worked example

Question. In an 8085 system the instruction CALL 2100H is stored starting at address 2000H, and SP = 2050H before the call executes. The subroutine at 2100H ends with RET. Give the stack bytes at 204EH, 204FH and 2050H, the value of SP and the value of PC (a) immediately after CALL executes and (b) after RET executes.

  1. CALL 2100H occupies addresses 2000H, 2001H and 2002H, so it is 3 bytes long. The next instruction starts at 2000H + 3 = 2003H. That value, 2003H, is the return address the CPU must save.
  2. Before the call: PC = 2000H and SP = 2050H.
  3. It pushes the high byte of the return address, 20H. SP becomes 2050H − 1 = 204FH and [204FH] = 20H.
  4. It pushes the low byte, 03H. SP becomes 204FH − 1 = 204EH and [204EH] = 03H.
  5. It loads PC with the target: PC = 2100H, so the branch is taken.
  6. The subroutine runs from 2100H. On reaching RET the CPU starts popping, low byte first.
  7. The 8085 RET reads the low byte from [204EH] = 03H and SP becomes 204EH + 1 = 204FH.
  8. It reads the high byte from [204FH] = 20H and SP becomes 204FH + 1 = 2050H.
  9. The two bytes form the address 2003H and this is loaded into PC, so execution continues at 2003H.
  10. Byte at 2050H was never written by the call; it keeps whatever value it had before.

Answer. After CALL: PC = 2100H, SP = 204EH (decimal 8270), [204FH] = 20H (decimal 32) and [204EH] = 03H (decimal 3), holding the return address 2003H (decimal 8195). After RET: PC = 2003H and SP = 2050H (decimal 8272).

Exam traps

  • SP moves before the write on an 8085 or 8086 push. Writing first and decrementing afterwards gives wrong addresses in the answer.
  • On the 8085, RET pops the low byte first. Reversing the order returns to 0320H instead of 2003H.
  • SP holds an address, not the data on top of the stack. Examiners ask for 'the value of SP' and students write the byte stored there.

3.7 Assembly programs: loops, delays and look-up tables

Assembly programs rarely run straight through once. They repeat a block a fixed number of times, walk a pointer through memory, or waste exact time before the next hardware action. Counters and index registers make these loops; T-state counting turns a loop into a delay; a look-up table turns an index into a stored constant. You meet all three in keypad scanning, seven-segment displays, motor step timing and sensor linearisation.

You need: 3.5 for conditional jumps, 3.4 for DCR and the Z flag, and Unit 2 for T-states and machine cycles.

Loops with a counter or an index

A loop repeats a block until a test says stop. In assembly the test is usually a decrement followed by a conditional jump. A counter register holds the repeat count. DCR counter reduces it by one and sets the Z flag when the result is zero. JNZ jumps back while Z = 0. This is a count-down loop: the count runs from N to zero.

  1. Load the counter with N, the number of passes.
  2. Run the loop body once.
  3. Decrement the counter with DCR.
  4. Test Z: if Z = 0, jump back to the body; if Z = 1, fall through.
  5. Reload the counter before starting a new loop.

An index register holds an address, not a count. Load the base address into HL. MOV A,M reads the byte at that address, and INX H moves to the next byte. Decrement the counter and jump back. The same pattern copies a block, sums an array, or sends a table of bytes to a port.

LXI H, 2000H

A nested loop puts one loop inside another. The outer counter controls rows; the inner counter controls columns. Reload the inner counter on every outer pass. If the inner body repeats P times and the outer loop repeats Q times with no early exit, the body runs P × Q times. Delay loops use nesting to stretch time without a huge count.

Delay loops and timing

A delay loop is a loop whose only job is to consume a known time. The CPU does no useful work; it counts. The delay comes from the clock, not from the number of source lines. On the 8085, one T-state is one clock period. On the classic 8051, one machine cycle is 12 oscillator periods. Some syllabi call this a time delay loop.

T_total = T_init + (N − 1) × (T_body + T_taken) + (T_body + T_not)

T_total is the total clock periods, or T-states on the 8085; T_init is the setup time before the loop; N is the number of body executions; T_body is the body time without the conditional jump; T_taken is the jump time when taken; T_not is the jump time when not taken. For the 8085, delay = T_total / f_clk, where f_clk is the clock frequency.

On the 8051, DJNZ Rn,rel decrements Rn and branches if the result is not zero. It takes 2 machine cycles. At a 12 MHz crystal, one machine cycle is 1 µs, so one DJNZ takes 2 µs. Two hundred passes take about 400 µs, plus the setup instructions.

Look-up tables

A look-up table is a block of constants in memory. The program computes an index, adds it to the table base, and reads the entry. The index is a byte offset, not the entry value. Tables replace long calculations with one memory read: seven-segment codes, sine samples, calibration points, square-root estimates.

On the 8085, LXI H,TABLE loads the base into HL. MVI E,index and MVI D,00H put a zero-extended index into DE. DAD D adds DE to HL. MOV A,M reads the selected entry. On the 8051, MOV DPTR,#TABLE sets the base, MOV A,#index sets the offset, and MOVC A,@A+DPTR reads code memory. On the 8086, put the base in BX and the index in AL, then execute XLAT; AL is replaced by the byte at DS:[BX+AL].

DAD D is a 16-bit add. The high byte must be 00H so the addition adds only the index, not an extra 256 × high-byte offset.

Apply For 8086 XLAT, BX = 3000H and AL = 04H. What is in AL after XLAT, and what is BX? 3 marks

AL becomes the byte at DS:3004H. BX stays 3000H.

3.8 Assemblers, simulators and IDEs

An assembler converts assembly source into machine code. A simulator runs that machine code on a PC without the chip. An IDE joins an editor, assembler, downloader and debugger in one window. Together they form the development tool chain for 8085, 8086 and 8051 programs. You write mnemonics, the assembler gives bytes and a hex file, and the simulator or board runs the bytes. This chapter shows how labels become addresses, which files are produced, and how a debugger helps find mistakes before hardware is used.

You need: instruction encoding from 3.1 and program structure from 3.7.

The assembler and its directives

An assembler is a program that translates assembly source into machine code. It turns each mnemonic into an opcode and each label into an address. A directive is a command to the assembler, not an instruction to the CPU. ORG n sets the location counter to n. The location counter (LC) is the address the assembler will give to the next byte it emits. DB places byte constants in memory. DW places 16-bit words, low byte first on the 8085 and 8086. EQU gives a name a fixed value. END marks the end of the source, and lines after it are ignored.

  • A label is entered in the symbol table with the current LC; it emits no bytes.
  • An instruction is encoded from its opcode table and operand; the LC advances by the instruction length.
  • A directive changes the LC, data or symbols; only DB and DW emit bytes.

Most assemblers use two passes. Pass 1 reads every line and records labels in the symbol table. Pass 2 encodes instructions, now that every label value is known. Only a few universities teach assembler construction in detail; for exams know the two passes, the LC and the symbol table. Some syllabi call the assembler, simulator and IDE together the development tool chain.

Symbol table, object files and hex files

The symbol table maps each label or EQU name to a number. START = 2000H means the label START is address 2000H. The LC is the running address during assembly. A forward reference is a label used before its line is read; pass 1 saves the name, and pass 2 fills in the value.

An object file holds machine code plus symbol and relocation information. A hex file is a plain-text record of addresses and bytes, often in Intel HEX format. The hex file itself has no labels, so on its own a simulator shows addresses only; loading the assembler's symbol file lets it show label names. A linker joins several object files into one program and resolves labels that are external. For a single small program the assembler can output a hex file directly.

A cross-assembler runs on a PC but produces code for another processor, such as an 8085 or 8051. That is normal because the target board cannot run an editor or assembler. The produced hex file is copied to the board by a device programmer (a hardware unit that writes the hex file into the chip).

Simulator, debugger and IDE

A simulator is software that executes the machine code without the chip. It models registers, flags, memory and I/O. You can set a breakpoint, single-step one instruction, and watch the program counter and flags. A debugger is the part that gives these controls; a simulator usually includes one.

An IDE (integrated development environment) puts editor, assembler, downloader and debugger in one window. You type source, press Build, then Run or Debug. For a board, the downloader sends the hex file to the chip through a serial or USB programmer. For a simulator, the same hex file runs on the PC.

Use a simulator first for loops and delays. Use the board when ports, timers or interrupts matter, because those depend on real hardware.

Worked example

Question. Assemble this 8085 source. Give the location counter after each line, the symbol table, and the bytes in memory: ORG 2000H / START: MVI A,05H / LOOP: DCR A / JNZ LOOP / END

  1. ORG 2000H sets LC = 2000H and emits no bytes.
  2. START is entered as 2000H. MVI A,05H is 2 bytes: 3E at 2000H and 05 at 2001H. LC becomes 2002H.
  3. LOOP is entered as 2002H. DCR A is 1 byte: 3D at 2002H. LC becomes 2003H.
  4. JNZ LOOP is 3 bytes: C2, low target 02, high target 20 at 2003H, 2004H and 2005H. The target is LOOP = 2002H. LC becomes 2006H.
  5. END is a directive and emits no bytes.
  6. Symbol table: START = 2000H = 8192, LOOP = 2002H = 8194. Bytes: 3E 05 (62, 5), 3D (61), C2 02 20 (194, 2, 32).

Answer. The assembled bytes are 3E 05 3D C2 02 20 at addresses 2000H to 2005H; symbols are START = 2000H and LOOP = 2002H.

Exam traps

  • ORG sets the location counter; it does not load bytes into memory. A loader or simulator places the hex file at the address.
  • Labels such as START are addresses, not instructions. A label line emits no opcode.
  • EQU and END are assembler directives; they are not CPU instructions and have no opcodes.
  • In JNZ LOOP the target is the address of LOOP (2002H in the example), not the address of JNZ (2003H) and not the next instruction.
  • DW stores a 16-bit word low byte first on the 8085 and 8086. Writing DW 1234H puts 34H before 12H.

Check yourself

Remember What does the ORG directive do? 2 marks

ORG n sets the location counter to n, so the next emitted byte gets address n. It does not itself write memory.

Remember What is a symbol table? 2 marks

A table built by the assembler that maps each label or EQU name to its address or value.

Understand Why does an assembler usually make two passes? 3 marks

Pass 1 records labels and their addresses in the symbol table. Pass 2 encodes instructions using those label values, including forward references.

Apply Assemble: ORG 2500H / L: MVI B,0FH / NOP / JMP L. Give the bytes and the value of L. 4 marks

L = 2500H. MVI B,0FH = 06 0F at 2500H-2501H. NOP = 00 at 2502H. JMP L = C3 00 25 at 2503H-2505H. Bytes: 06 0F 00 C3 00 25.

Apply A JNZ instruction is at 2003H and jumps to LOOP = 2010H. Give its three bytes. 4 marks

JNZ opcode is C2. The low byte is 10 and the high byte is 20. Bytes: C2 10 20.

Understand State two differences between a simulator and a target board. 3 marks

A simulator runs code in software and shows registers and memory without hardware. A board runs the real chip, so ports, timers and voltage levels are real.

Analyze A program is assembled with ORG 2000H and contains JMP 2500H, written as a fixed absolute address, not a label. You change the ORG to 3000H and reassemble. Why may the program now fail? 6 marks

The bytes of the JMP operand are still 00 25, so the jump goes to 2500H. That address is now empty because the code moved to 3000H. Absolute addresses do not move with the program; only labels recomputed by the assembler move.

Takeaways

  1. Every instruction is bits split into an opcode and operand fields, so the CPU decodes the opcode first and the operand second.
  2. The addressing mode decides where the operand lives; the same opcode with a different mode can mean register, memory, or an immediate value.
  3. Data transfer instructions move bytes but never touch the flags, which is why MOV is safe between a CMP and a conditional jump.
  4. Arithmetic and logical instructions leave their result in flags, and every conditional branch is really a test of one of those flags.
  5. JMP changes the program counter and never comes back; CALL saves a return address on the stack so RET can come back.
  6. The stack is LIFO memory, so pushing the registers at the start of a subroutine and popping them before RET keeps the caller's data safe.
  7. A delay loop's time is found by multiplying the loop count by the machine cycles per iteration and the machine cycle time.
  8. A look-up table trades memory for speed: seven-segment codes, sine values and square-wave patterns are read by index, not calculated.
  9. The assembler turns text into machine code, the simulator runs that code with no chip, and an IDE wraps both with an editor and a debugger.

Glossary

Addressing mode
The rule that converts the address field of an instruction into the effective address of the operand.
Assembler directive
A line in assembly source that tells the assembler what to do, such as ORG or DB, and does not become a machine instruction.
Auxiliary carry
A flag set by a carry from bit 3 to bit 4, used by decimal-adjust instructions.
Conditional jump
A jump that takes place only if a stated flag value is present.
Cross-assembler
An assembler that runs on one computer but produces machine code for a different processor.
Debugger
A tool that lets you run code one instruction at a time and inspect registers and memory.
Direct addressing
A mode where the instruction holds the full memory address of the operand.
Effective address
The memory address finally used for the read or write.
Flag
A single bit set or cleared by the ALU to record some property of the last result.
Immediate operand
A constant carried inside the instruction, written with a # sign in many assemblers.
Index register
A register whose contents are added to a base address to step through a table or array.
Indirect addressing
A mode where the instruction holds an address, and that address holds the address of the operand.
Instruction
A coded command held in memory that tells the CPU one basic operation and the data it works on.
Instruction set
The complete list of instructions a processor can decode and execute.
Look-up table
A list of pre-computed constants read by an index instead of being calculated at run time.
Machine cycle
The time the CPU takes for one basic bus operation; on the 8051 it is 12 clock cycles.
Nesting
Calling a subroutine from inside another subroutine, which uses extra stack space.
Object file
The intermediate file of machine code and relocation information produced by the assembler.
Opcode
The bits of an instruction that identify the operation.
Operand
The data or the address of the data on which an instruction acts.
Program counter
The register holding the address of the next instruction to be fetched.
Register indirect
A mode where a named register holds the address of the operand.
Rotate instruction
An instruction that shifts bits left or right and moves the bit pushed out into the carry flag.
Stack
A LIFO area of memory used for return addresses and saved register values.
Subroutine
A named block of code that the main program can call again and again and which returns when finished.
T-state
One clock period of the processor; a machine cycle contains a fixed number of T-states.
Two's complement
The way negative numbers are stored: invert all bits and add one.
