1.1 Evolution of microprocessors; microprocessor vs microcontroller

A microprocessor is a complete CPU on one silicon chip. A microcontroller is that CPU plus program memory, data memory, timers and input/output ports on the same chip, so it runs alone. Transistors kept shrinking, so data paths widened from 4 bits to 64 bits, and then whole systems moved onto one chip. The microprocessor sits in a laptop or server; the microcontroller sits in a washing machine, a bike's engine controller, a UPI card reader and a smart meter.

You need only the everyday idea of a computer as something that takes input, processes it and gives output; the CPU, memory and bus picture comes next in 1.2.

CPU, microprocessor, microcontroller

The central processing unit (CPU) fetches an instruction from memory, decodes it and executes it. It holds a few very fast storage slots called registers, and an arithmetic logic unit (ALU) that adds, subtracts and does logic. Everything else in the machine feeds the CPU or carries away its results. The fetch-decode-execute loop is in 1.3.

A microprocessor (MPU) is a CPU on one silicon chip, and nothing more. Its pins go out to three buses: address, data and control. Program memory, data memory, timers and input/output (I/O) ports are separate chips wired to those buses. The 8085 and 8086 are microprocessors. 1.2 draws the buses.

A microcontroller (MCU) is a CPU plus the rest of a small computer on the same chip: program memory (ROM or flash), data memory (RAM), timers and counters, I/O ports and usually a serial port. It runs a program with no outside chips. The 8051 is the classic example.

An embedded system is a computer hidden inside a product to do one fixed job, where the product is not sold as a computer: a washing machine, a fuel-injection unit, an inverter. Such products must be cheap, small and low-power, so hiding the whole computer in one chip is the only way that makes sense.

From 4-bit to 64-bit: the timeline

Bit width is the number of bits the ALU and main registers handle in one operation; it is also called the word size. An 8-bit CPU adds two 8-bit numbers at a time; a 64-bit CPU adds two 64-bit numbers.

  • 4-bit: the Intel 4004 in 1971, built for calculators, about 2,300 transistors.
  • 8-bit: the Intel 8080 in 1974 and 8085 in 1976, which powered early personal computers and instruments.
  • 16-bit: the Intel 8086 in 1978, with 20 address lines reaching 1 MB; its twin the 8088 went into the first IBM PC.
  • 32-bit: the Intel 80386 in 1985, which brought protected memory and multitasking operating systems.
  • 64-bit: the early 2000s, making more than 4 GB of RAM directly addressable.

Two forces drove this: transistors shrinking, roughly doubling devices per area every two years (Moore's law), and each wider data path finishing more work per instruction.

Microcontrollers grew separately: the 8048, the 8051 in 1980, then PIC, AVR and ARM Cortex-M. Many stay at 8 or 16 bits, because a washing machine needs no 64-bit arithmetic and narrow buses waste less power.

Since the 2010s the lines merge in the system on chip (SoC): CPU, graphics unit, memory controller and radio blocks on one die, as in a phone.

One warning: bit width is not memory size. The number of address lines fixes how much memory the CPU can name.

M = 2ⁿ bytes

M is the number of directly addressable byte locations and n is the number of address lines on the address bus.

An 8086 is a 16-bit CPU with 20 address lines, so M = 2²⁰ = 1,048,576 bytes = 1 MB. Two different numbers for two different jobs. Memory chips are covered in 1.5.

Worked example

Question. An 8051-based washing-machine board carries a CPU, 4 KB of program ROM, 128 B of RAM, two timers and 32 I/O pins on one chip. A desktop board carries an 8086 CPU plus one RAM chip, one ROM chip holding the firmware, one timer chip and one I/O controller chip. (a) Classify each board, giving two reasons each. (b) Count the chips on each board. (c) Find the total on-chip memory of the 8051 board in bytes.

  1. 8051 board: CPU, ROM, RAM, timers and I/O ports all sit on one die. A device with a CPU plus on-chip memory and peripherals is a microcontroller. Reason 1: it works as a complete computer in one chip. Reason 2: program memory and I/O ports are already inside it.
  2. 8086 board: the 8086 is a CPU only, and RAM, ROM, timer and I/O are separate chips on the system bus. That is a microprocessor system. Reason 1: the processor chip is CPU-only. Reason 2: memory and peripherals are off-chip.
  3. Chip count, 8051 board: everything on one die, so 1 chip.
  4. Chip count, 8086 board: 1 CPU + 1 RAM + 1 ROM + 1 timer + 1 I/O = 5 chips.
  5. On-chip ROM in bytes: 4 KB × 1024 B per KB = 4096 B.
  6. Add on-chip RAM: 4096 B + 128 B = 4224 B.

Answer. The 8051 board is a microcontroller (1 chip, 4224 B of on-chip memory); the 8086 board is a microprocessor system (5 chips).

Worked example 2

Question. A 16-bit CPU has 20 address lines. How many bytes can it address directly, and how does that differ from its bit width?

  1. Bit width is 16 bits: the ALU adds 16-bit numbers in one operation.
  2. Address lines n = 20.
  3. Addressable locations M = 2ⁿ = 2²⁰ = 1,048,576 byte locations.
  4. In units: 1,048,576 B ÷ 1024 = 1024 KB = 1 MB.
  5. So the CPU works on 16-bit data but names 1 MB of memory; the two numbers answer different questions.

Answer. It addresses 2²⁰ = 1,048,576 bytes, that is 1 MB, while its data width stays 16 bits.

Exam traps

  • Calling any small CPU a microcontroller. A microcontroller must carry on-chip program memory, data memory and peripherals; a chip with only a CPU is a microprocessor, however small.
  • Equating bit width with addressable memory. The 8086 is 16-bit but has 20 address lines, so it reaches 1 MB, not 64 KB.
  • Mixing up the 8085 and the 8051. The 8085 is an 8-bit microprocessor with no on-chip program memory; the 8051 is an 8-bit microcontroller with 4 KB ROM and 128 B RAM inside.
  • Saying a microprocessor has no memory. It has on-chip registers; what it lacks is on-chip program and data memory.
  • Assuming a higher clock always wins. A 3 GHz desktop CPU and a 12 MHz 8051 do different jobs; the microcontroller wins on power, size and cost per unit.

Coursework increasingly adds low-power modes, interrupt latency and security features such as a trust zone.

1.2 Computer organization: CPU, memory, buses and I/O

A computer is a set of blocks that move data and instructions. The CPU does arithmetic and logic, holds a few values in registers, and controls the order of work. Memory stores instructions and data. Input and output devices connect the computer to the world. They all share three buses: address, data and control. The address bus selects a location, the data bus carries the bits, and the control bus says read or write. This organization appears in laptops, phones, washing machines and ATMs.

You need: processor terms from Chapter 1.1 and binary powers such as 210 = 1024 and 216 = 65536.

Inside the CPU

The CPU is the part that executes instructions. The arithmetic logic unit (ALU) adds, subtracts, ANDs, ORs and compares binary numbers. Registers are small, fast storage inside the CPU. A general-purpose processor has registers for operands, a program counter (PC) that holds the address of the next instruction, and an instruction register (IR) that holds the instruction being decoded. Flags are single bits that record the result of the last operation, for example zero, carry or sign. The control unit reads the opcode in the IR and sends timed signals to the ALU, registers and buses. It decides which register drives the internal bus, which ALU operation runs, and when memory is read or written. The data path is the set of registers, ALU and internal buses that carry operands and results. The control path is the control unit and its signal lines that tell the data path what to do. Data flows along the data path; control flows along the control path. This block diagram is what some syllabi call a general purpose processor or computer organization block diagram.

The three buses

A bus is a group of wires that many units share. The address bus carries the address of the memory location or I/O port. It is usually driven by the CPU and is unidirectional. If the address bus has n lines, the CPU can select 2n distinct addresses. This number is the address space. The data bus carries the actual bits. If it has m lines, one bus cycle moves m bits. An 8-bit data bus moves one byte per cycle; a 16-bit bus moves two bytes. The data bus is bidirectional, because data flows from CPU to memory or device on a write and from memory or device to CPU on a read. The control bus carries timing and command signals: read, write, clock, interrupt request and reset. A read cycle works in a fixed order. The CPU places a valid address on the address bus. It asserts the read control line. Memory or the I/O device places data on the data bus. The CPU samples the data near the end of the cycle. A write cycle is similar, but the CPU puts data on the data bus and asserts write. The address must stay valid until the transfer finishes. Bus width matters: address width sets how much memory you can reach, and data width sets how many bits move at once. Do not mix the two. The 8085 and 8086 bus signals and machine cycles are covered in Unit 2.

N = 2n

N is the number of addressable locations and n is the number of address lines.

Memory, I/O and control

Memory holds instructions and data in numbered locations. Each location has an address. Memory-mapped I/O gives an I/O device registers that look like memory locations. The CPU uses ordinary load and store instructions to read or write them. Isolated I/O keeps a separate I/O address space. The CPU uses special instructions such as IN and OUT, and the control bus carries an extra signal to choose I/O instead of memory. Isolated I/O protects memory addresses but needs extra instructions. An I/O port is the register or connection point through which the CPU talks to a device. A simple keyboard port may have a data register and a status bit. In polling, the CPU repeatedly reads the status bit until it says ready, then reads the data. Polling is simple but wastes CPU time. In interrupt operation, the device raises an interrupt request line when it is ready. The CPU finishes the current instruction, saves its state, and jumps to a short service routine. The routine reads or writes the device and returns. Both methods use the same buses; only the control sequence changes. Memory types and chip organization are in Chapter 1.5.

Worked example

Question. A simple computer has 16 address lines and 8 data lines. Find its address space in bytes and the number of bytes it can transfer in one bus cycle. It uses an 8 KB ROM and a 2 KB RAM; how many address lines does each need?

  1. Address space = 216 locations = 65536 locations. Each location holds one byte, so the address space is 65536 bytes = 64 KB.
  2. Data bus width = 8 bits = 1 byte, so one bus cycle transfers 1 byte.
  3. ROM size = 8 KB = 8 × 1024 = 8192 bytes = 213 bytes, so the ROM needs 13 address lines.
  4. RAM size = 2 KB = 2 × 1024 = 2048 bytes = 211 bytes, so the RAM needs 11 address lines.

Answer. Address space is 65536 bytes (64 KB); one bus cycle transfers 1 byte; the 8 KB ROM needs 13 address lines and the 2 KB RAM needs 11 address lines.

Exam traps

  • Address bus width is not data bus width. 16 address lines give 2¹⁶ = 65536 addresses (64 KB), not 16 KB.
  • A byte is 8 bits. A data bus of 8 lines moves 1 byte per cycle, not 8 bytes.
  • Memory-mapped I/O uses normal memory instructions; isolated I/O uses special IN/OUT instructions and a separate I/O address space.
  • In a read cycle the CPU samples data after the read strobe; in a write cycle the CPU drives data before the write strobe. Do not swap them.
  • An address space of 2ⁿ bytes needs n address lines only when each address selects one byte. Word-addressed memory changes the byte count.

1.3 Stored program concept; von Neumann and Harvard

The stored-program concept keeps a program's instructions in memory as numbers, not as fixed wiring. The CPU reads each instruction, decodes it and executes it. One machine can then run many programs by changing memory contents. The program counter (PC) holds the address of the next instruction. The instruction register (IR) holds the instruction being decoded. The CPU repeats fetch, decode, execute. Von Neumann machines use one memory for code and data; Harvard machines use separate program and data memories. Phones, cars and washing machines all use this idea.

You need: Chapter 1.2 for CPU, memory and buses.

Stored program and the CPU cycle

An instruction is a group of bits with an opcode and zero or more operands. The opcode tells the CPU what to do, such as ADD or MOV. An operand tells where the data is: a constant, a register, or a memory address. In a simple 8-bit example, 0011 0101 can mean opcode 0011 (ADD) and operand 0101 (register R5). The CPU must know the instruction length and format before it can decode.

  1. Fetch: read the byte at the address in PC into IR, then PC ← PC + 1.
  2. Decode: split IR into opcode and operand fields.
  3. Execute: do the operation; for a memory operand, compute the address and transfer data over buses.
  4. Repeat from fetch.

The PC (program counter) is a register holding the next instruction address. The IR (instruction register) holds the current instruction. Fetch sends PC on the address bus, uses the control bus to read memory, and brings the byte back on the data bus. This is why code must sit in addressable memory. The CPU does not care how the bytes arrived, only that PC points to them. A program loaded from a USB stick or a UPI app update is still just bytes in memory.

Addressing: where the operand lives

An addressing mode is the rule for finding an operand. Five intro modes cover most early examples. The mnemonics are illustrative. The memory examples below use a generic CPU with a 16-bit address field, not the 8051.

  • Immediate: the operand is inside the instruction. MOV R1, #25h loads 25h into R1. No memory read for the operand.
  • Direct: the instruction holds the memory address. MOV A, 2000h reads the byte at address 2000h.
  • Indirect: the instruction holds an address that holds another address. If the two bytes at 2000h and 2001h contain 3050h, the operand is at 3050h. The CPU reads memory twice: once for the pointer, once for the operand.
  • Register: the operand is in a named register. ADD A, R2 adds R2 to A.
  • Register indirect: a register holds the memory address. MOV A, @R0 reads the byte whose address is in R0.

Immediate operands are fast but fixed after assembly. Direct operands are simple but limited by the address field width. Indirect and register-indirect modes let one instruction reach many locations by changing a pointer. That is how loops walk an array in Unit 3. The instruction format sets the mode bits, so the CPU decodes the mode before it fetches the operand.

Von Neumann and Harvard

A von Neumann machine has one memory space for instructions and data and normally one bus set. The 8086 is in this family: code and data bytes share the same 1 MB address space, so the CPU fetches an instruction or reads data in separate bus cycles. One address can hold either an instruction byte or a data byte, not both at the same time. Advantage: simple memory and a flexible split; a program can use almost all memory for code or for data. Disadvantage: the single path can bottleneck fetch and data steps.

A Harvard machine has separate program memory and data memory, often with separate buses. The 8051 is a Harvard-style microcontroller: it has 4 KB program memory and 128 B data memory in the example below. The same address number can name one program byte and one data byte in different spaces. Because the paths are separate, the CPU can fetch the next instruction and read or write data in the same clock cycle. Advantage: higher throughput for regular embedded loops. Disadvantage: less flexible memory use and more wires or pins.

The split can be inside one chip. Harvard does not require two external memory chips; many microcontrollers keep both memories on-die. Stored-program does not mean one physical memory: it means instructions are stored as data-like numbers. Modern CPUs often mix ideas: separate instruction and data caches, but one address space. Some syllabi call this Von-Neumann Vs Harvard architecture.

Worked example

Question. An 8051 has 4 KB program memory and 128 B data memory. A von Neumann CPU has one 64 KB memory for code and data. For each, state whether the same address can hold an instruction byte and a data byte, and give one advantage of its design.

  1. Convert the 8051 program memory: 4 KB = 4 × 1024 B = 4096 B. The data memory is 128 B.
  2. The 8051 uses separate program and data spaces. Address 0000h in program memory can hold an instruction byte, and address 0000h in data memory can hold a data byte. They are different bytes in different memories, so the answer is yes.
  3. Advantage of 8051: separate paths allow instruction fetch and data access to happen together.
  4. Convert the von Neumann memory: 64 KB = 64 × 1024 B = 65536 B. It is one shared space. At one time, a given address holds one byte only, either instruction or data. So the answer is no for the same shared address.
  5. Advantage of von Neumann: simpler memory and flexible code/data split. Risk: a data write can overwrite an instruction if software is not protected.

Answer. 8051: yes, 4096 B program memory and 128 B data memory are separate, so address 0000h can hold an instruction byte and a data byte in different spaces, and separate paths allow fetch and data access together. Von Neumann: no, one 65536 B space holds one byte per address at a time, and its advantage is simple, flexible memory use.

Exam traps

  • Harvard does not always mean two separate external memory chips; the program/data split can be internal to one microcontroller chip.
  • Stored-program does not mean code and data always share one physical memory; Harvard keeps them separate but still stores instructions as numbers.
  • PC holds the next instruction address, not the current instruction. IR holds the current instruction while it is decoded.
  • Immediate mode puts the operand in the instruction itself; direct mode puts a memory address in the instruction. Do not call a constant an address.
  • A von Neumann single bus does not mean one wire; it means one shared path set, so instruction fetch and data transfer usually need separate bus cycles.

1.4 CISC and RISC design philosophy

Every processor designer faces one question: how much work should a single instruction do? CISC (complex instruction set computer) packs a lot of work into each instruction, so programs stay short. RISC (reduced instruction set computer) keeps instructions small and regular, so the hardware can overlap them and compilers can schedule them. The 8086 and 8051 are CISC-like; ARM is RISC. The choice shapes instruction length, addressing modes, register count and control logic, and it decides how easily the CPU can be pipelined.

You need: Chapter 1.3 for the fetch-decode-execute cycle and Chapter 1.2 for how the CPU reads instructions from memory.

Where to spend the transistors

CISC makes each instruction do a lot of work. RISC keeps each instruction small and pushes the work into software. Both are answers to the same question: given a fixed number of transistors, do you build complex instructions or a fast simple pipeline?

CISC grew up when memory was costly. A program that occupies fewer bytes needs less memory and fewer instruction fetches, so designers packed work into single instructions: add a memory word to a register, auto-increment a pointer, move a whole string. The 8086 is the classic case. Its instructions are 1 to 6 bytes long, it offers many addressing modes, and it has only eight general 16-bit registers (AX, BX, CX, DX, SI, DI, BP, SP). The 8051 is CISC-like in the same way.

RISC took the opposite bet: keep instructions so simple and regular that hardware can overlap them. ARM is the common example. Instructions are 4 bytes in ARM state, there are 16 general 32-bit registers, and only load and store instructions touch memory. Every arithmetic instruction works register to register. Because all instructions are the same length, the address of the next instruction is known before the current one is decoded, which makes pipelining natural.

Control logic is the last difference. A microcoded CPU holds a small internal program called microcode in a ROM inside the chip; each machine instruction becomes a sequence of micro-operations. Complex instructions are easier to build this way, so CISC uses microcode. RISC uses hardwired control: fixed logic gates decode the few instruction formats directly, which is faster and leaves chip area for pipeline registers.

Two rows need care. Load-store means arithmetic can only read and write registers; a value must be brought in by a load and written back by a store. This costs extra instructions but keeps every arithmetic instruction the same shape and the same duration. Cycles per instruction, written CPI, is the average number of clock cycles one instruction takes.

The compiler matters more on RISC. With fixed formats and few modes, a compiler can pick registers, reorder independent instructions and fill pipeline slots. On CISC the microcode already sequences the complicated steps, so the compiler has less to do but also less freedom.

Which one is faster? Count cycles, not CPI

A RISC instruction usually takes fewer cycles, but a task usually needs more RISC instructions. Neither number alone decides speed. Multiply them.

Total cycles = IC × CPI

IC is the instruction count for the whole program (a pure number); CPI is the average clock cycles per instruction; Total cycles is the number of clock periods the program needs.

Time = IC × CPI × T_clk = (IC × CPI) ÷ f

T_clk is the clock period in seconds; f is the clock frequency in hertz, f = 1 ÷ T_clk.

So a machine with CPI = 1.2 can still lose to one with CPI = 4 if it executes far more instructions. The worked example below uses exactly this comparison. Notice also that the answer depends on the program, the compiler and the clock frequency, so no design wins every time. Modern x86 chips translate complex instructions into simple internal operations before executing them, and ARM has added some multi-step instructions, which shows the two ideas have moved closer.

Worked example

Question. A CISC CPU has 120 instructions and averages 4 clock cycles per instruction. A RISC CPU has 40 instructions and averages 1.2 clock cycles per instruction. A given program needs 10⁶ CISC instructions, or 1.4 × 10⁶ RISC instructions when compiled for the RISC machine. Both CPUs run at the same clock frequency. Find the clock cycles each machine needs and the ratio of RISC time to CISC time.

  1. CISC instruction count IC = 10⁶ instructions, CISC CPI = 4 cycles per instruction.
  2. CISC cycles = IC × CPI = 10⁶ × 4 = 4 × 10⁶ cycles.
  3. RISC instruction count IC = 1.4 × 10⁶ instructions, RISC CPI = 1.2 cycles per instruction.
  4. RISC cycles = 1.4 × 10⁶ × 1.2 = 1.68 × 10⁶ cycles.
  5. Same clock frequency f means time = cycles ÷ f, so the time ratio equals the cycle ratio.
  6. Ratio = RISC cycles ÷ CISC cycles = 1.68 × 10⁶ ÷ 4 × 10⁶ = 0.42.
  7. The RISC program runs in 42 % of the CISC time, so it is about 2.38 times faster here, even though it executes 1.4 times as many instructions.

Answer. CISC needs 4 × 10⁶ cycles, RISC needs 1.68 × 10⁶ cycles, and the RISC time is 0.42 of the CISC time at the same clock frequency.

Exam traps

  • Comparing CPI alone. RISC usually has lower CPI but a larger instruction count; only IC × CPI gives the cycles.
  • Reading 'reduced' as 'fewer instructions executed'. RISC reduces the instruction set, not the program length; its programs are usually longer.
  • Mixing up the two control styles. Microcode is an internal ROM program inside the CPU; it is not the user's program in main memory.
  • Forgetting what load-store forbids. A load-store machine cannot add a memory operand straight into a register; you need a load, an add and possibly a store.
  • Claiming one style always wins. Workload, compiler and clock frequency all shift the answer; the examiner wants the cycle calculation, not a slogan.

Check yourself

Remember Expand CISC and RISC, and state in one line what each style does with instruction complexity. 2 marks

CISC is complex instruction set computer: few instructions, each doing a lot of work. RISC is reduced instruction set computer: many simple, regular instructions, each doing one small job.

Remember Which of the 8086 and ARM is CISC and which is RISC? Give one supporting fact for each. 2 marks

8086 is CISC: variable-length instructions of 1 to 6 bytes with many addressing modes and memory operands. ARM is RISC: fixed 4-byte instructions, 16 general registers, load-store memory access.

Understand Why does variable instruction length make pipelining harder? 3 marks

The pipeline must fetch the next instruction before the current one is fully decoded. With variable length, the next address depends on the current instruction's size, so fetch and decode become serial and the pipeline may stall. Fixed length lets the next address be computed immediately.

Understand Why did early CISC designs try to reduce program size, and why does that argument matter less today? 3 marks

Memory was expensive and small, so shorter programs saved cost and reduced instruction fetches from slow memory. Today memory is cheap and large, and cache plus wide fetch make code size less critical, so pipeline speed matters more.

Apply A CISC CPU runs a task in 2 × 10⁶ instructions at CPI 3. A RISC CPU runs the same task in 2.8 × 10⁶ instructions at CPI 1.15. Both run at the same clock. Find the cycles for each and the RISC/CISC time ratio. 4 marks

CISC cycles = 2 × 10⁶ × 3 = 6 × 10⁶. RISC cycles = 2.8 × 10⁶ × 1.15 = 3.22 × 10⁶. Ratio = 3.22 × 10⁶ ÷ 6 × 10⁶ = 0.5367. The RISC program takes about 0.54 of the CISC time.

Analyze A marketing sheet says a new core has CPI = 1.0 and is therefore the fastest. Explain what extra information you need before accepting the claim. 5 marks

CPI alone says nothing about total time. You need the instruction count the same program needs on each machine, the clock frequency, and cycles = IC × CPI. Time = (IC × CPI) ÷ f. A CPI of 1.0 with twice the instructions and half the clock can be much slower.

Analyze A compiler for a CISC machine almost never emits the complex multi-step instructions. What happens to the CISC advantage, and what does that suggest about the two styles? 5 marks

The advantage shrinks. The CPU still pays for microcode and decode logic that the program rarely uses, while a simple hardwired RISC core of the same area could run at a higher clock. It suggests the styles converge: keep a simple fast core and let software do the work.

Understand What does load-store mean, and what does it cost? 3 marks

Only load and store instructions move data between memory and registers; all arithmetic works register to register. The cost is extra instructions and extra register pressure, because a value must be loaded, used and stored back.

Beyond the syllabus

Not for the exam. Real x86 processors decode complex instructions into small internal operations that look much like RISC instructions, so the boundary has blurred in production silicon. ARM dominates phones and embedded boards, and the open RISC-V instruction set is now taught and used in research and startups. Compiler work on register allocation and instruction scheduling matters most on load-store machines. 1.5 Memory types and memory organization

Memory holds the program and data that the CPU uses. It is built as a hierarchy: small, fast, costly storage near the CPU and large, slow, cheap storage far away. Memory organization connects this hierarchy to the address bus: n address lines give 2ⁿ locations, and decoders place ROM and RAM chips at fixed ranges called the memory map. You use these ideas when you write a memory map for an 8085 or 8086 board, or when you read the separate program and data spaces of an 8051.

You need: Chapter 1.2 for address, data and control buses, and Chapter 1.3 for the stored-program idea; basic powers of 2 from school maths.

Bits, bytes, words and the hierarchy

A bit is one binary digit, 0 or 1. A byte is 8 bits. A word is the group of bits the CPU handles in one operation; it may be 8, 16, 32 or 64 bits. An address is a number that names one storage location. Capacity is the number of locations times the bits in each location, usually quoted in bytes. Volatile memory loses its contents when power is removed. Non-volatile memory keeps them.

RAM is read-write and volatile. SRAM stores each bit in a flip-flop, needs no refresh, is fast, and uses more area and power per bit. DRAM stores each bit as charge on a capacitor, needs periodic refresh, is denser and cheaper, and is slower. Cache is small SRAM close to the CPU. Main memory is DRAM. Secondary storage is flash, SSD, hard disk or tape.

ROM is read-only in normal use. Mask ROM is fixed at manufacture. PROM is programmed once by the user. EPROM is erased with ultraviolet light and reprogrammed. EEPROM is erased electrically, byte by byte or in blocks. Flash is an EEPROM variant erased in blocks; it holds firmware and SSD data. The hierarchy from registers to cache to main memory to flash to disk trades speed for size and cost per bit.

Address space, capacity and decoding

n address lines select 2ⁿ locations. For 16 lines, 2¹⁶ = 65536 locations. If each location is one byte, the address space is 65536 bytes = 64 KB, from 0000H to FFFFH. Byte-addressable memory gives every byte its own address. Word-addressable memory gives one address to a whole word, so consecutive addresses differ by one word, not one byte.

locations = 2ⁿ; capacity in bytes = 2ⁿ × w

n is the number of address lines; w is the number of bytes per location; w = 1 for byte-addressable memory.

Address decoding turns an address into a chip select. The CPU drives the address bus. A decoder checks the high-order bits. Its output selects exactly one ROM or RAM chip. The low-order bits choose the location inside that chip. A memory map is the list of address ranges given to ROM, RAM and I/O. Read-only regions hold code, tables and constants. Read-write regions hold variables, stack and heap.

Use capacity to find a range. A chip of C bytes starting at S ends at S + C − 1. On a 16-bit map, an 8 KB ROM has 8192 bytes = 2000H, so it occupies 2000H addresses. A 2 KB RAM has 2048 bytes = 0800H. Check that ranges do not overlap.

The memory map, the stack and separate spaces

A CPU sees memory as a map, not as separate chips. A common layout puts ROM at low addresses for reset code and fixed constants, and RAM at higher addresses for variables, stack and heap. The stack is a read-write RAM area that grows and shrinks. The stack pointer holds the address of the current top. Calls and interrupts push return addresses and saved registers; returns pop them. The stack is therefore ordinary RAM plus a pointer, not a separate memory type. Detailed push and pop instructions are in Unit 3.

Some microcontrollers have separate program and data address spaces. The 8051 is an example: code fetches use program memory, data uses data memory. This is a Harvard arrangement; one shared space is von Neumann (Chapter 1.3). The 8051 internal details and special function registers belong to Unit 4.

A wrong chip select can place two chips at the same address. The bus then drives conflicting data and the program fails. Always write the memory map and check every range.

Worked example

Question. A byte-addressable memory has 16 address lines. An 8 KB ROM is placed at 0000H and a 2 KB RAM at 2000H. Find the address range of the ROM and the RAM, and the total address space.

  1. n = 16, so total address space = 2¹⁶ = 65536 bytes = 64 KB. The highest address is FFFFH.
  2. ROM size = 8 × 1024 = 8192 bytes = 2000H. Last offset inside the ROM = 8192 − 1 = 8191 = 1FFFH.
  3. ROM starts at 0000H, so ROM ends at 0000H + 1FFFH = 1FFFH. ROM range = 0000H to 1FFFH.
  4. RAM size = 2 × 1024 = 2048 bytes = 0800H. Last offset inside the RAM = 2048 − 1 = 2047 = 07FFH.
  5. RAM starts at 2000H, so RAM ends at 2000H + 07FFH = 27FFH. RAM range = 2000H to 27FFH.
  6. The RAM end 27FFH is 10239 in decimal.
  7. Used memory = 8192 + 2048 = 10240 bytes = 10 KB. Free memory = 65536 − 10240 = 55296 bytes = 54 KB.

Answer. ROM: 0000H–1FFFH (8192 bytes); RAM: 2000H–27FFH (2048 bytes); total address space: 65536 bytes.

Exam traps

  • End address is start + size − 1. Adding the full size gives the first address after the region, not the last address inside it.
  • 1 K = 1024, so 8 KB = 8192 bytes = 2000H, not 8000 bytes. A 2 KB chip is 0800H bytes, not 0200H.
  • Byte-addressable and word-addressable are not the same: 65536 addresses cover 64 KB of bytes or 128 KB of 16-bit words.
  • SRAM is a RAM, not a ROM. SRAM is fast and volatile; flash is non-volatile but writable in blocks, not read-only forever.
  • Chip select enables a whole chip; the low address bits choose the location inside. Do not call a chip-select line an address line.

1.6 Pipelining basics

A pipeline is a set of stages, each doing one part of an instruction in one clock cycle, with different instructions in different stages at the same time. It exists because one instruction uses only a small part of the processor at each moment. Overlapping stages raises throughput, the number of instructions finished per second. Prefetch overlap appeared as early as the 8086, and modern cores such as ARM use full multi-stage pipelines. Pipelining is why a processor can keep working on the next instruction while the current one is still finishing.

You need: the instruction cycle and RISC design.

The five-stage assembly line

A pipeline divides instruction execution into stages. A stage is a block of logic and registers that completes one part of an instruction in one clock cycle. The classic five stages are IF, ID, EX, MEM and WB. IF fetches the instruction from memory. ID decodes it and reads registers. EX executes an arithmetic or logic operation, or computes an address. MEM reads or writes data memory. WB writes the result back to a register. The clock cycle T is the time of one stage; its frequency is 1/T.

Latency is the time one instruction takes from start to finish. Throughput is the number of instructions finished per unit time. Without a pipeline, one instruction uses all k stages in sequence, so latency is kT and throughput is 1/(kT). With a pipeline, after the first instruction fills the stages, one instruction can finish every cycle. Latency of one instruction is still about kT, but throughput becomes 1/T.

Throughput_ideal = 1 / T

T is the clock period in seconds; throughput is in instructions per second after the pipeline is full.

CPI means cycles per instruction: the average number of clock cycles one instruction takes. A nonpipelined processor has CPI = k. An ideal pipelined processor has CPI = 1 in steady state. Real pipelines have CPI above 1 because of stalls, which are cycles where a stage waits.

Cycles, fill and speedup

Take n independent instructions and a k-stage pipeline, with one clock cycle T per stage. Without pipelining, each instruction takes k cycles, so n instructions take nk cycles and time nkT. With pipelining, the first instruction needs k cycles to reach the end. The remaining n − 1 instructions finish one per cycle. Total cycles = k + (n − 1) = k + n − 1. Total time = (k + n − 1)T.

T_pipe = (k + n − 1) × T

k is the number of stages, n is the number of independent instructions, and T is the clock period in seconds.

S = T_no_pipe / T_pipe = nk / (k + n − 1)

S is the speedup, T_no_pipe is the time without pipelining, and T_pipe is the time with pipelining.

The fill phase is the first k − 1 cycles, when the pipeline is not yet full. The drain phase is the last k − 1 cycles, when no new instructions enter. In steady state, between fill and drain, every stage is busy. For many instructions, n is large, so S tends to k. The ideal speedup is k, but a real pipeline cannot exceed k and usually gets less because the slowest stage sets T and hazards add stalls. CPI from this count is (k + n − 1)/n; for large n it approaches 1.

Hazards that break the flow

A hazard is a condition that prevents the next instruction from starting in the next cycle. Hazards add stall cycles and lower speedup. There are three kinds.

  • Structural hazard: two instructions need the same hardware in the same cycle. Example: one memory used by IF and MEM. Fix: separate instruction and data memories, or stall.
  • Data hazard: an instruction needs a result that an earlier instruction has not written yet. Fix: forwarding, also called bypassing, sends the result from EX or MEM to where it is needed; if that is not enough, stall.
  • Control hazard: a branch changes the program counter, so the next fetched instruction may be wrong. Fix: branch prediction, a delayed branch slot, or flush the wrong instructions and stall.

RISC designs make pipelining easier. Instructions are simple and usually one word long, and only load and store instructions touch memory. That keeps IF, ID and EX regular. CISC instructions of different lengths make fetch and decode uneven. See the ARM pipeline chapter. The gain from pipelining is limited by the slowest stage, by fill and drain, and by hazards. It raises throughput, not the latency of a single instruction.

Worked example

Question. A 5-stage pipeline runs 4 independent instructions. Each stage takes one clock cycle of 2 ns. Find total time without pipelining, total time with pipelining, and the speedup.

  1. Number of stages k = 5. Number of instructions n = 4. Clock period T = 2 ns.
  2. Without pipelining, cycles = n × k = 4 × 5 = 20 cycles. Time = 20 × 2 ns = 40 ns.
  3. With pipelining, cycles = k + n − 1 = 5 + 4 − 1 = 8 cycles. Time = 8 × 2 ns = 16 ns.
  4. Speedup S = 40 ns / 16 ns = 2.5.

Answer. Without pipelining the time is 40 ns, with pipelining it is 16 ns, and the speedup is 2.5.

Exam traps

  • Using nk cycles for a pipelined run. For n independent instructions the correct count is k + n − 1 cycles, including fill and drain.
  • Thinking pipelining reduces the latency of one instruction. It raises throughput; one instruction still passes through all k stages.
  • Claiming speedup equal to k on a short program. With n = 4 and k = 5, the speedup is 2.5, not 5.
  • Forgetting the clock period. A cycle count is not a time; multiply by T in seconds, and keep ns or µs consistent.
  • Mixing up hazards: a data hazard needs a value not yet written, a control hazard comes from a branch, and a structural hazard is a hardware conflict.

Takeaways

  1. A microprocessor is a CPU alone on a chip; a microcontroller is a CPU plus memory, timers and ports on the same chip.
  2. Microprocessors evolved by shrinking transistors and widening the word from 4 bits to 8, 16, 32 and 64 bits.
  3. Every computer transfers data over an address bus, a data bus and a control bus, and the CPU drives the sequence.
  4. The stored-program concept lets instructions sit in memory beside data, which is what makes a general-purpose computer possible.
  5. Von Neumann shares one memory for code and data; Harvard separates them, trading cost for speed.
  6. CISC reduces program size by making instructions powerful; RISC reduces instruction work so pipelining and compilers stay simple.
  7. Memory is organised as a hierarchy because no single technology is fast, large and cheap at the same time.
  8. Pipelining raises throughput but never reduces the latency of one instruction, and hazards limit the real gain.

Analyze Explain why most microcontrollers use a Harvard-style memory arrangement while general-purpose computers use a von Neumann view with separate caches. 12 marks

Microcontroller code is fixed in flash and data in RAM; two memories exist anyway; Separate buses allow simultaneous fetch of instruction and operand; No cache needed, so cost and predictability stay good; General-purpose computers run changing programs and need one uniform address space; Caches give speed while keeping the programmer's von Neumann model; Modified Harvard: split first-level caches, single main memory.

Glossary

Address bus
Unidirectional lines carrying the location being read or written; n lines address 2ⁿ locations.
Address decoding
Logic that turns high-order address bits into chip-select signals so each device answers only its own range.
Address space
The set of all addresses a processor can generate, determined by the number of address lines.
ALU
The arithmetic logic unit, which performs arithmetic and logical operations and sets the flags.
Bit width
The number of bits a processor handles as one unit, fixing register size and normally the data bus width.
Bus
A shared set of wires with a defined protocol for transferring addresses, data or control signals.
CISC
A design philosophy using many complex, variable-length instructions to shorten programs.
Control bus
Lines that carry timing and command signals such as read, write, clock, reset and interrupt.
CPU
The processor block that fetches, decodes and executes instructions and controls the rest of the system.
Data bus
Bidirectional lines carrying the value transferred between the CPU and memory or I/O.
Embedded system
A computer dedicated to one control task inside a larger product.
Flag
A single status bit such as zero, carry, sign or overflow, set by the ALU and tested by branch instructions.
Harvard architecture
A design with physically separate program and data memories and buses.
Hazard
A dependency or resource conflict that prevents an instruction from issuing in its scheduled cycle.
Isolated I/O
A scheme in which I/O devices have a separate address space reached only by special instructions.
Memory hierarchy
The layered arrangement of storage from fast small registers to slow large secondary memory.
Memory-mapped I/O
A scheme in which I/O registers occupy addresses in the same space as memory and are accessed by ordinary instructions.
Microcontroller
A single chip containing a CPU, program and data memory, timers, and input/output ports for embedded control.
Microprocessor
A central processing unit fabricated on one integrated circuit chip, requiring external memory and I/O devices.
Pipelining
Overlapping the stages of several instructions so that one instruction finishes per clock in steady state.
Register
A small fast storage location inside the CPU holding one word of data or an address.
RISC
A design philosophy using few simple fixed-length instructions to make pipelining and compilation easy.
Stored-program concept
The principle that instructions are held in memory as binary codes and fetched like data.
System on chip
An integrated circuit combining a processor core with memory and peripherals.
Von Neumann architecture
A design with one memory and one bus set shared by instructions and data.
