5.1 Programmable peripheral interface (8255)

The 8255 is a programmable peripheral interface: three 8-bit ports whose direction and handshake behaviour are set by one control byte. It exists because a fast CPU bus and a slow keypad, printer or display cannot share timing directly. The CPU writes a control word once, then reads or writes the ports as if they were memory or I/O locations. The same chip gives simple input/output, strobed handshake, and a bidirectional bus. You will find it in 8085 and 8086 trainer kits, in printer ports, and in any design where a few slow signals must meet a microprocessor.

You need: Unit 2 address decoding and memory-mapped I/O, and Unit 1 buses.

Three ports, one control word

Inside the 40-pin package sit a data bus buffer, read/write control logic, two control blocks and three 8-bit ports. D0-D7 connect to the CPU data bus. CS, RD and WR are active-low control inputs. A1 and A0 choose one of four internal registers. RESET clears the control register, so all ports come up as inputs. The supply is +5 V and ground; the other pins are the 24 port lines.

Group A control owns port A and the upper half of port C, PC7-PC4. Group B control owns port B and the lower half, PC3-PC0. This split matters: one control byte can set port A as an input and port B as an output, and can set the two halves of port C in different directions.

A1A0RegisterOffset
00Port A+0
01Port B+1
10Port C+2
11Control+3

With base address 80H, the four addresses are 80H, 81H, 82H and 83H. The 8255 does not contain a base address; a decoder outside the chip asserts CS only for that four-address block.

The control word: modes, directions, and bit set/reset

Every change begins by writing one byte to the control register. Bit D7 is the master switch: D7 = 1 means I/O mode, D7 = 0 means bit set/reset (BSR) mode. In I/O mode the remaining bits have fixed jobs.

BitsMeaning in I/O mode
D71 = I/O mode
D6 D5Group A mode: 00 mode 0, 01 mode 1, 1x mode 2
D4Port A: 1 input, 0 output
D3PC7-PC4: 1 input, 0 output
D2Group B mode: 0 mode 0, 1 mode 1
D1Port B: 1 input, 0 output
D0PC3-PC0: 1 input, 0 output

Mode 0 is simple input or output. An output pin is driven from a latch, so it holds the last byte written until the CPU writes again. An input pin is only buffered, not latched, so the CPU must read while the peripheral is still presenting the data. Mode 1 is strobed input or output: port C pins become handshake lines such as STB, IBF, OBF, ACK and INTR, so a slow device can say data is ready or taken. Mode 2 is a bidirectional bus on port A only; it uses five port C pins and leaves port B free for mode 0 or 1.

BSR mode is a separate use of the same control register. D7 = 0; D3-D1 pick one of PC0-PC7; D0 = 1 sets that pin, D0 = 0 resets it. Bits D6-D4 are ignored. This gives single-bit control without rewriting the whole port C direction.

Decoding a control byte is the reverse: read D4 and D3 for group A, D1 and D0 for group B. A common mistake is to read D3 as port B or D0 as port A; the nibble split puts group A's C-half in D3 and group B's C-half in D0.

Current limits, fan-out, and an 8086 address decode

An 8255 pin is a logic output, not a power driver. A standard port pin sinks about 1.6 mA and sources only a few hundred microamperes. An LED that needs 10 mA, a relay coil, or a motor will not run directly. Use the pin to drive a transistor base, a ULN2803 darlington array, or a buffer such as 74LS245. For input, a switch can connect to a pin with a pull-up resistor; active-low wiring is common because the pin then needs only to sink.

Fan-out is also limited: one output drives one standard TTL input, or about four LS TTL inputs. For a whole board, add a buffer or driver. For a keypad matrix or a seven-segment display, add drivers and scan from software; see Chapter 5.6.

On an 8086 the 8255 is a byte-wide peripheral on one byte lane. With the 8255 on D0-D7, connect 8255 A0 to CPU A1 and 8255 A1 to CPU A2; CPU A0 is not connected to the chip (it only selects the byte lane). Base 80H then gives port A at 80H, port B at 82H, port C at 84H, control at 86H; on the upper lane D8-D15 the same registers are at 81H, 83H, 85H, 87H. The decoder compares A3-A15 with the matching bits of the base, and for I/O-mapped access it must also qualify CS with M/IO low. The CPU uses OUT and IN; Unit 3 gives the instruction encoding. The 8255's RD and WR connect to the 8086 read and write strobes, and RESET to the system reset.

Worked example

Question. An 8255 is decoded at base address 80H. Port A must be an input in mode 0, port B an output in mode 0, PC7-PC4 an input and PC3-PC0 an output. Find the control word in binary and hex, and state the address to which it is written.

  1. Base 80H gives port A = 80H, port B = 81H, port C = 82H and the control register = 83H.
  2. D7 = 1 selects I/O mode.
  3. D6 D5 = 00 selects group A mode 0.
  4. D4 = 1 makes port A an input.
  5. D3 = 1 makes PC7-PC4 an input.
  6. D2 = 0 selects group B mode 0.
  7. D1 = 0 makes port B an output.
  8. D0 = 0 makes PC3-PC0 an output.
  9. The byte is 1 0 0 1 1 0 0 0 = 98H = 152 in decimal.
  10. Write 98H to the control register at 83H.

Answer. The control word is 98H (152 decimal), written to address 83H.

Exam traps

  • D7 = 0 enters BSR mode, not I/O mode. A BSR byte written where an I/O control word is expected changes one port C pin and leaves all port directions unchanged.
  • Port C is split: D3 sets PC7-PC4, D0 sets PC3-PC0. Do not expect one direction bit to cover all eight port C pins.
  • A direction bit of 1 means input, not enable. Writing 1 to D4 makes port A an input; writing 0 makes it an output.
  • Mode 2 is available on port A only. Port B can be mode 0 or mode 1, never mode 2.
  • In mode 1, port C pins are taken for handshake signals. The remaining C pins keep their direction bits, so not all eight are free for general I/O.

5.2 Programmable interval timer (8253/8254)

The 8253 and 8254 are programmable interval timers. Each chip holds three independent 16-bit down counters. You load a count, a clock drives the counter down, and an OUT pin changes state at terminal count. One chip turns a fixed clock into delays, pulse trains and square waves while the CPU does other work. It appears on 8085 and 8086 boards and in motor pulse generation. Only a few universities teach this chapter.

You need: delay loops from Unit 3 and 8051 timer programming from Unit 4 for comparison.

Three counters and one control word

Each chip has three independent 16-bit down counters, numbered 0, 1 and 2. Every counter has a CLK input, a GATE input and an OUT pin. The clock drives the counter down by one on each falling edge. GATE enables or triggers counting, depending on the mode. OUT changes state at terminal count. The CPU programs the count once and continues.

One control word selects the counter and its behaviour. SC1 SC0 choose counter 0, 1 or 2. RW1 RW0 choose LSB only, MSB only, or LSB then MSB. M2 M1 M0 choose one of six modes. The BCD bit chooses binary or binary-coded decimal counting. A loaded count of 0 means 65536 in binary mode and 10000 in BCD mode. The count is:

N = f_clk × T_delay

N is the loaded count; f_clk is the clock frequency in hertz; T_delay is the wanted delay in seconds.

The figure uses small counts: mode 2 with count 3 and mode 3 with count 4.

The six modes in one line each

The six modes decide what OUT does. Mode 2 is a rate generator: OUT stays high, goes low for one clock at terminal count, then reloads. Mode 3 makes a square wave: OUT is high for half the count and low for half the count; with an odd count the high time is one clock longer than the low time. The table gives each mode in one line.

ModeNameOUT pin
0Interrupt on terminal countOUT low while counting; high at terminal count
1Hardware-retriggerable one-shotGATE rising edge starts a low pulse
2Rate generatorLow for one clock every N clocks
3Square waveHigh and low for half the count each; with an odd count high is one clock longer
4Software-triggered strobeOne low pulse at terminal count
5Hardware-triggered strobeOne low pulse at terminal count after GATE

GATE matters. In mode 1 and mode 5 a rising edge on GATE starts the pulse. In mode 2 and mode 3 GATE low stops the counter; GATE high lets it run. In mode 0 and mode 4 GATE low stops counting and GATE high resumes. Check the mode before you connect a gate signal.

Reading a running counter

Reading a running counter is unsafe. The low byte and high byte can come from two different counts. The latch command solves this. Write a control word with RW1 RW0 = 00 and the counter's SC bits; the chip copies the current count into a latch. Read the low byte, then the high byte. The latch holds one value.

The 8254 adds a read-back command and a status byte. The 8253 does not have them. The status byte shows the OUT pin state, the NULL COUNT flag (0 = a count has been loaded into the counting element, 1 = it has not), the RW1 RW0 bits, the mode bits and the BCD bit. If a question says 8254 read-back, do not apply it to the 8253.

Write the control word first, then the count bytes in the order fixed by RW1 RW0. For LSB-then-MSB, write low byte then high byte. Writing high byte first loads a wrong number, and the error appears only when you measure timing. Use the latch before any two-byte read of a running counter.

Worked example

Question. A 1 MHz clock drives counter 0. Produce an OUT0 pulse train of period 1 ms (1 kHz) using mode 2, binary, LSB first. Give the control word and the bytes written.

  1. Clock period = 1 / 1 MHz = 1 µs.
  2. Count = 1 ms / 1 µs = 1000 = 03E8H.
  3. SC1 SC0 = 00, RW1 RW0 = 11, M2 M1 M0 = 010, BCD = 0.
  4. Control word = 00 11 010 0 = 0011 0100 = 34H.
  5. Write 34H to control, E8H to counter 0, then 03H.
  6. OUT0 is a 1 kHz pulse train; terminal count repeats every 1 ms.

Answer. Control word 34H; count 1000 (03E8H); OUT0 is 1 kHz; write E8H then 03H to counter 0.

Exam traps

  • Writing the high byte first when the control word asks for LSB first loads a wrong count; you see it only when timing is measured.
  • Reading a running counter without the latch mixes low and high bytes from two different counts.
  • Loading 0 does not stop a counter; it loads 65536 in binary mode and 10000 in BCD mode.
  • Mode 2 repeats; it is a rate generator, not a one-shot delay. Mode 3 is the square wave.
  • The 8253 has no read-back command or status byte; those belong to the 8254.

5.3 Programmable interrupt controller (8259)

The 8259A programmable interrupt controller sits between up to eight interrupting devices and one CPU interrupt pin. It latches each request, masks the ones software disables, ranks the rest by priority, and raises a single INT. When the CPU answers with INTA, the 8259 supplies the interrupt vector, so the CPU jumps straight to the correct service routine. Without it, a CPU with one INTR pin would have to poll every device. It is used in 8085 and 8086 boards, in old PC AT systems, and in many industrial controllers.

You need: the 8086 INTR and INTA pins and the interrupt vector table from Unit 2, and the interrupt ideas in Unit 4.

Pins, bus and vector formation

The 8259A is a 28-pin chip. IR0 to IR7 are eight interrupt request inputs, active high. A device pulls its IR line high when it needs service. INT is the single output to the CPU. INTA is the input from the CPU acknowledging the interrupt. CS, WR, RD and A0 connect to the bus. A0=0 selects the even address for ICW1, OCW2 and OCW3. A0=1 selects the odd address for ICW2, ICW3, ICW4 and OCW1. D0 to D7 carry commands and the vector. CAS0 to CAS2 carry the slave identity in a cascade. SP/EN is either the slave-program input or the enable output for a bus buffer.

On an 8086, ICW2 supplies the upper five bits of the interrupt type. The lower three bits come from the winning IR line. ICW2=40H therefore gives types 40H to 47H, one type per input. Each type has a 4-byte entry in the interrupt vector table. On an 8085, the 8259 supplies a CALL instruction and a 16-bit address; ICW1 bit D2 sets the call address interval to 4 or 8 bytes.

A0 also matters during normal running. Writing OCW1 to the odd address changes the mask. Writing OCW2 to the even address sends an end-of-interrupt command. Reading the even address after OCW3 returns the register selected by OCW3.

Inside: three registers and a resolver

The interrupt request register (IRR) latches every request. The interrupt mask register (IMR) holds one mask bit per line; a 1 masks that line and a 0 enables it. The in-service register (ISR) holds the line currently being served. The priority resolver compares unmasked IRR bits with the ISR. In fully nested mode, a new request is sent to the CPU only if its priority is higher than the highest ISR bit. IR0 is highest by default and IR7 is lowest. ICW1 bit D3 selects edge triggering (0) or level triggering (1).

Initialization command words (ICW1 to ICW4) are written at start-up. Operation command words (OCW1 to OCW3) are written while the system runs.

  • ICW1: D4=1 marks ICW1, D3 sets edge or level, D2 sets the 8085 call interval, D1 SNGL=1 for a single chip, D0 IC4=1 when ICW4 follows.
  • ICW2: vector base; on the 8086 it supplies the upper five type bits.
  • ICW3: cascade wiring; on a master, one bit per IR that has a slave; on a slave, its identity.
  • ICW4: 8086 mode, end-of-interrupt mode, buffered mode and special fully nested mode.
  • OCW1: the mask byte; 1 masks, 0 enables.
  • OCW2: non-specific, specific or automatic end of interrupt, and rotation of priorities.
  • OCW3: read IRR or ISR, set special mask mode, and issue the polling command.

The polling command makes the 8259 report the highest pending request as a status byte. The CPU reads that byte instead of taking an interrupt. This is useful when interrupts are disabled for a short critical section.

Cascading and two requests at once

One master can drive up to eight slaves. Each slave's INT output connects to one master IR input, giving 64 request inputs in total. The master's ICW3 says which IR lines have slaves. Each slave's ICW3 gives its 3-bit identity. During acknowledge, the master places that identity on CAS0 to CAS2, and only the selected slave returns its vector. In non-buffered mode, SP/EN is an input: high selects master, low selects slave.

  1. IR3 and IR6 go high together. Both bits set in the IRR.
  2. Both lines are unmasked. The priority resolver compares IR3 and IR6; IR3 has higher priority.
  3. The resolver sets ISR bit 3 and raises INT. IR6 stays pending in the IRR.
  4. The CPU sends the first INTA. The 8259 sets the in-service bit and, for a master with slaves, puts the slave identity on CAS0 to CAS2.
  5. The CPU sends the second INTA. The 8259 puts the vector byte on D0 to D7: ICW2 base plus 3.
  6. The CPU jumps to the service routine. When it writes EOI, ISR bit 3 clears. The resolver then sees IR6 and raises INT again.

An 8085 needs three INTA pulses because the 8259 supplies a CALL opcode and a 16-bit address. If IR6 were higher priority than IR3, it could interrupt IR3's routine in fully nested mode, provided both lines are unmasked and IR6 is not blocked by a lower-priority ISR bit.

Worked example

Question. An 8259A in an 8086 system is at addresses 20H and 21H. It is a single chip, edge triggered, with IR0 to IR7 taking vectors 40H to 47H. Only IR0 and IR1 are to be allowed. Write ICW1, ICW2, ICW4, OCW1, and the non-specific EOI byte. Give all values in hex and decimal.

  1. ICW1 = 0001 0011 = 13H = 19. D4=1 marks ICW1, D3=0 selects edge triggering, D2=0 (not used on 8086), D1=1 means SNGL (single chip), D0=1 means IC4 follows. Write to even address 20H.
  2. ICW2 = 0100 0000 = 40H = 64. The upper five bits are 01000, so the eight vectors are 40H to 47H. Write to odd address 21H.
  3. ICW4 = 0000 0001 = 01H = 1. Bit 0=1 selects 8086 mode, bit 1=0 selects normal EOI, bits 2-3=00 select non-buffered mode, bit 4=0 means not special fully nested. Write to odd address 21H.
  4. OCW1 = 1111 1100 = FCH = 252. Bits 0 and 1 are 0, so IR0 and IR1 are enabled. Bits 2 to 7 are 1, so IR2 to IR7 are masked. Write to odd address 21H.
  5. Non-specific EOI = 0010 0000 = 20H = 32. Write to even address 20H. This clears the highest ISR bit.

Answer. ICW1=13H (19), ICW2=40H (64), ICW4=01H (1), OCW1=FCH (252), and non-specific EOI=20H (32).

Exam traps

  • Skipping the end-of-interrupt in non-automatic mode leaves the ISR bit set. That line and every lower-priority line stay blocked for ever.
  • A 1 in OCW1 masks a line; it does not enable it. Writing FFH masks all eight inputs, while 00H enables all eight.
  • On the 8086, the lower three bits of ICW2 are ignored because the IR line supplies them. Do not expect ICW2=43H to shift the vector by 3.
  • ICW1 bit D3=0 means edge triggered and D3=1 means level triggered. A level-triggered request must stay high until the acknowledge; an edge must be a transition.
  • OCW2 rotation changes priority order. It is not a mask operation. Use OCW1 to enable or disable a line.

5.4 DMA controller (8257/8237)

A DMA controller moves bytes between memory and a peripheral while the CPU stays out of the data path. The CPU programs a start address and a byte count once; the controller then takes the bus for a few clock cycles at a time and performs each memory read and each I/O write itself. This chapter covers the 8257 with the 8085 and the 8237 with the 8086: channels, registers, transfer modes, and the DREQ–HRQ–HLDA–DACK handshake.

You need Unit 2 bus timing, the HOLD and HLDA handshake, and maximum-mode 8086 signals (see Unit 2, 8085 and 8086 Microprocessors).

Why the CPU leaves the data path

A disk controller hands over 512 bytes in a burst. Suppose the CPU polls: read status, test ready, read data, store to memory, increment the pointer, decrement the counter, loop. That is about ten machine cycles per byte. With one interrupt per byte it is worse: push flags and return address, fetch a vector, run the service routine, pop everything. The useful transfer is two bus cycles; the overhead is thirty.

DMA removes that overhead. A separate controller holds the start address and the count. When the peripheral has a byte ready it raises DREQ. The controller asks the CPU for the bus: HOLD on the 8085, HRQ in 8086 maximum mode. The CPU finishes the current machine cycle, floats its address, data and control lines, and answers HLDA. The controller drives the bus: it puts out the memory address, asserts MEMR, latches the byte and writes it with IOWR. Then it gives the bus back.

The CPU is out of the data path. It programs the channel once, does other work, and takes one interrupt when the count runs out.

The 8257 with the 8085

The 8257 has four channels, 0 to 3. Channel 0 has the highest priority; a rotating-priority mode moves a just-served channel to the bottom so no channel starves.

Each channel has two 16-bit registers. The address register holds the buffer start, so the 8257 reaches 0000H–FFFFH, the full space of the 8085. The count register holds the number of bytes minus one in its low 14 bits, so the largest block is 2¹⁴ = 16384 bytes.

bytes moved = (count field) + 1,  last address = start address + (count field)

count field is bits 13–0 of the 8257 count register, a 14-bit number; start address is the 16-bit value in the channel address register.

Counting from zero is why the count is transfers minus one: a count field of 0000H means one byte. The top two bits of the count word are control bits. Bit 14 makes TC stop the channel. Bit 15 enables auto-reload, which copies the original address and count back so the buffer repeats without CPU help.

The mode word sets rotating priority, extended write and the transfer mode: single (one byte per DREQ), demand (transfer as long as DREQ stays high) and burst or block (run continuously until the count ends). The TC pin pulses at the last transfer. Verify is an 8237 option, covered in Section 3.

The 8237 with the 8086

The 8237 is an 8-bit DMA controller like the 8257, but its 16-bit address and count registers give a 64 KB block per channel, and it adds memory-to-memory transfer, cascade mode, software request and mask registers, auto-initialise and a verify transfer type.

The 8086 bus has 20 address lines. The 8237 outputs A0–A7 itself; an external latch strobed by ADSTB supplies A8–A15, and a separately programmed 4-bit page register supplies A16–A19. Together this gives a 20-bit address and a 64 KB page per channel.

The page is chosen by program, not by the counter. When the 16-bit address counter overflows it wraps to the bottom of the same page, so a block must not cross a page boundary.

Registers per channel: the current address and current count, changed during the transfer, and the base address and base count, loaded by software and used by auto-initialise. The mode register picks direction, auto-initialise, the address counter direction (increment or decrement), and single, demand or block mode; the count always decrements. The command register sets chip-wide options such as memory-to-memory and priority rotation. The request register raises a software request. The mask register disables a channel. The status register reports which channels reached terminal count. EOP is the end-of-process pin.

Memory-to-memory uses channel 0 as source and channel 1 as destination with fixed priority, one byte per transfer. Cascade mode connects a second 8237 as a slave, so its requests appear as one channel of the master.

The handshake, cycle stealing and block transfer

  1. The peripheral asserts DREQ for the channel it needs.
  2. The controller asserts HRQ to the CPU.
  3. The CPU finishes the current machine cycle, floats its buses and asserts HLDA.
  4. The controller asserts DACK to the peripheral, which also selects the channel.
  5. The controller drives the memory address and MEMR, and latches the byte on the data bus.
  6. It drives IOWR and the byte leaves for the peripheral. A memory write runs the same steps in reverse.
  7. The address increments (or decrements, if programmed), the count decrements. On terminal count or EOP, HRQ drops and the bus returns to the CPU.

Single mode is cycle stealing: one byte per bus grant. The CPU loses one bus cycle per byte and keeps its state, so it still services interrupts and memory refresh. Block mode holds the bus for the whole block. It is faster per byte, but the CPU is frozen: interrupt latency grows, and in older systems dynamic RAM refresh must come from somewhere else.

Worked example

Question. An 8257 channel 0 is loaded with a start address of 2000H. The low 14 bits of its count register hold 0FFFH. The channel runs in single mode with auto-reload disabled. How many bytes are moved, what is the last address used, and what happens on the final transfer?

  1. The count field is the low 14 bits, 0FFFH = 4095.
  2. The field holds transfers minus one, so bytes moved = 4095 + 1 = 4096.
  3. Block size = 4096 ÷ 1024 = 4 KB.
  4. Last address = start + count field = 2000H + 0FFFH = 2FFFH = 12287.
  5. The block runs 2000H to 2FFFH, inside one 64 KB space, so no wrap occurs.
  6. On the last transfer TC pulses. With the stop bit set the channel is disabled and the pulse is normally taken to an 8259 input as an end-of-block interrupt. With auto-reload set instead, 2000H and 0FFFH are restored and the channel waits for the next DREQ.

Output

4096 bytes, last address 2FFFH (12287), 4 KB, TC pulses to stop or reload.

Answer. 4096 bytes are moved, from 2000H to 2FFFH (4 KB), and TC pulses on the final transfer to stop or reload the channel.

Exam traps

  • The count field is transfers minus one. Programming 1000 for 1000 bytes moves 1001, and the extra byte lands on an address you did not reserve.
  • The 8257 count field is 14 bits, so the largest block is 16384 bytes. The 8237 count is 16 bits, so it reaches 65536 bytes. Mixing the two widths loses a factor of four.
  • The 8237 address counter wraps inside its 64 KB page. 2 KB starting at FC00H runs to 103FFH; the 16-bit counter wraps at FFFFH to 0000H of the same page, so the second half lands on wrong addresses.
  • HRQ and HLDA belong to the CPU side; DREQ and DACK belong to the peripheral side. DACK is the controller's acknowledgement to a device, never the CPU's grant.
  • Single mode drops DREQ after each byte; demand mode expects DREQ held high for the whole run. Verify mode moves no data: the channel runs its count down and moves nothing.

5.5 USART (8251) serial interface

A USART is a universal synchronous/asynchronous receiver transmitter. The 8251 turns a parallel byte into a timed serial frame and back. The CPU writes a byte; the chip adds a start bit, optional parity and stop bits, then shifts the bits out on one pin at a fixed baud rate. In the other direction it finds the start bit, samples the data bits, checks parity and hands a clean byte to the CPU. It is used for RS-232 links, modem lines and simple two-wire board-to-board connections.

You need Unit 4, serial communication and RS-232 levels: baud rate, start and stop bits, and line levels.

Inside the chip

A USART is a universal synchronous/asynchronous receiver transmitter. The 8251 is the classic programmable USART. The CPU side is parallel: D0-D7, C/D, CS, RD and WR. The line side is serial: TXD sends bits out, RXD receives bits in. A transmit buffer and transmit shift register form the outgoing path. A receive shift register and receive buffer form the incoming path. The CPU writes a byte; the shift register adds the frame and clocks it out one bit at a time. Received bits shift in and wait in the receive buffer.

C/D = 0 selects data; C/D = 1 selects control or status. TXRDY means the transmit buffer is empty. TXE means the shift register is empty too. RXRDY means a received byte is waiting. SYNDET is for synchronous mode. TXC and RXC are clock inputs; in async mode both TXC and RXC are 1, 16 or 64 times the baud rate.

The modem block has RTS (output), CTS (input), DTR (output) and DSR (input). CTS must be active before the 8251 transmits. In a board-to-board link these pins are often tied active.

Frame and mode word

An asynchronous frame sits on an idle-high line. A low start bit wakes the receiver. Data follows, least significant bit first. An optional parity bit follows. One or more high stop bits end the frame. The receiver samples each bit near its middle. A framing error means the stop bit was not high.

The mode word sets the frame. It is written to the control port after reset.

BitsFieldMeaning in async mode
D7 D6Stop bits01 = 1 stop; 10 = 1.5 stop; 11 = 2 stop; 00 = synchronous mode
D5Parity enable0 = no parity; 1 = parity added
D4Parity type0 = even; 1 = odd (used only when D5 = 1)
D3 D2Character length00 = 5; 01 = 6; 10 = 7; 11 = 8 data bits
D1 D0Baud factor01 = 1×; 10 = 16×; 11 = 64×

fTXC = baud rate × factor

fTXC is the transmit clock in Hz; baud rate is bits per second; factor is 1, 16 or 64. For 9600 baud and 16×, fTXC = 153600 Hz.

Command, status, reset and RS-232

The command word enables the directions and controls handshake. D0 = transmit enable. D2 = receive enable. D3 = send break. D4 = error reset. D5 = RTS. D6 = internal reset. D1 = DTR. D7 = hunt mode in synchronous mode. For transmit, receive and error reset, D0 = D2 = D4 = 1, giving 0001 0101 = 15H = 21 decimal.

The status word reports D0 TXRDY, D1 RXRDY, D2 TXE, D3 parity error, D4 overrun error, D5 framing error, D6 SYNDET and D7 DSR. Overrun means a new byte arrived before the old one was read. Framing means the stop bit was low. Parity means the parity bit did not match. The error reset command bit clears these three flags.

  1. Power up: write 00H to the control port three times.
  2. Write 40H to the control port. D6 = 1 is internal reset.
  3. Write the mode word to the control port.
  4. Write the command word to the control port.

The 8251 pins are TTL: 0 V and 5 V. RS-232 uses negative logic and about ±3 V to ±15 V. A MAX232 driver/receiver converts both ways and generates the negative voltage with a charge pump. Connect TXD and RXD through the driver/receiver.

Worked example

Question. An 8251 is mapped at port 80H for data and 81H for control. Configure it for asynchronous operation at 9600 baud, 8 data bits, no parity, 1 stop bit, with a 16× clock. Give the reset sequence, the mode word, a command word that enables transmit and receive and resets errors, and the required TXC frequency.

  1. Addresses: 80H is data (C/D = 0); 81H is control/status (C/D = 1).
  2. Reset: write 00H to 81H three times, then write 40H to 81H. 40H = 0100 0000; D6 = 1 is internal reset.
  3. Mode fields: D7D6 = 01 for async 1 stop; D5 = 0 for no parity; D4 = 0 even/odd (don't care when parity is off); D3D2 = 11 for 8 data bits; D1D0 = 10 for 16×. Mode word = 0100 1110 = 4EH = 78 decimal.
  4. Command fields: D0 = 1 transmit enable; D2 = 1 receive enable; D4 = 1 error reset; other bits 0. Command word = 0001 0101 = 15H = 21 decimal.
  5. Clock: f_TXC = 9600 × 16 = 153600 Hz = 153.6 kHz.

Answer. Write 00H three times, then 40H for reset; write mode word 4EH (78), then command word 15H (21); TXC must be 153600 Hz (153.6 kHz).

Exam traps

  • The mode word is accepted only after the reset sequence. If you write a command first, the chip can sit in an unknown state and the first characters disappear with no error flag.
  • C/D selects data against control/status. Writing a mode word to the data port is ignored.
  • In the standard 8251A, D7D6 = 01 is async 1 stop, 10 is 1.5 stop and 11 is 2 stop. 8EH is a 1.5-stop mode word, not 8N1.
  • TXRDY means the transmit buffer is empty. TXE means the shift register is also empty. Poll TXRDY before writing the next byte.
  • Parity, overrun and framing flags are cleared by the error reset command bit D4 = 1, not by reading the status word.

5.6 Keyboard and display interfacing: LED, seven-segment, LCD

Keys and displays are slow, numerous and often share one port. A keypad needs a scan to find which key is pressed. A seven-segment display needs one code per digit and fast switching so four digits look steady. An LCD needs a fixed command-and-data handshake before it shows a character. This chapter shows the current calculation, the scan loop, the multiplex timing and the HD44780 start-up sequence that make these peripherals work from an 8051-style port.

You need: Unit 4 port programming and Unit 3 delay loops and look-up tables; see 5.1 if the port is an 8255.

LED drive and seven-segment codes

An LED is a diode. Lit, it drops a nearly fixed forward voltage Vf; a series resistor sets the current.

R = (Vcc − Vf) / I

R is the series resistor in ohms; Vcc is the supply voltage; Vf is the LED forward voltage; I is the wanted current in amperes.

For Vcc = 5 V, Vf = 2 V and I = 8 mA, R = (5 − 2) / 0.008 = 375 Ω. Use the standard 390 Ω.

Sourcing means the pin is high and feeds the LED to ground. Sinking means the LED is fed from Vcc and the pin pulls the cathode low. Many ports sink more current than they source, so sinking is common. Check the per-pin and whole-chip limits. Eight LEDs at 8 mA can exceed a small port's total, so add a buffer such as a ULN2803.

Seven-segment display: seven LEDs a to g plus a decimal point. Common cathode joins all cathodes to ground; a high bit lights a segment. Common anode joins all anodes to Vcc; a low bit lights a segment, so every code is complemented. With bit 0 = a and bit 6 = g, digit 1 is 06H and digit 3 is 4FH. For common anode, 1 becomes F9H.

Digit multiplexing and keypad scanning

Multiplexing joins all segment lines and gives each digit its own common line. Turn one digit on at a time; persistence of vision makes the four digits look steady.

f<sub>refresh</sub> = 1 / (N × T<sub>digit</sub>)

frefresh is the refresh rate in hertz; N is the number of digits; Tdigit is the time each digit is on in seconds.

Four digits at 1 ms each: frame = 4 ms, frefresh = 250 Hz. Above 50 Hz is normally flicker-free. A segment on for 1/4 of the time needs about 4× the steady current to look as bright. For 8 mA average, allow 32 mA peak. Use a transistor per digit: low-side NPN for common cathode, high-side PNP for common anode. The port drives only the base.

4×4 keypad: four rows are outputs, four columns are inputs with pull-ups. Drive one row low and read the columns. A low column marks the closed key at that row and column.

  1. Set all rows high and all columns as inputs with pull-ups.
  2. Drive row r low; leave the other rows high.
  3. Wait 1 ms and read the four column bits.
  4. If column c is low, wait 15 ms and read again to confirm.
  5. Key code = 4r + c; restore the rows and return the code.

Key code = row×4 + column, used to index a look-up table. Debounce: after a change, wait 10 to 20 ms and read again. Without it, one press can count many times.

LCD 16×2 with the HD44780

16×2 LCD: 16 characters per line, 2 lines. HD44780 controller. RS = 0 for command, RS = 1 for data. RW = 0 for write, RW = 1 for read. E latches on its falling edge. D0-D7 carry the byte, command or busy flag.

8-bit mode uses D0-D7. 4-bit mode uses D4-D7 and sends each byte as two nibbles, high nibble first. It saves four port pins.

  1. Wait more than 15 ms after power-on.
  2. Write 38H (8-bit, 2 lines, 5×7 font); wait 5 ms.
  3. Write 38H again; wait 1 ms.
  4. Write 38H again.
  5. Write 0CH for display on, cursor off.
  6. Write 01H to clear; wait about 1.5 ms.
  7. Write 06H for entry mode increment.

In 4-bit mode the function-set byte is 28H. The repeated 38H is the reset ritual. DDRAM address: 80H + position selects line 1. Line 1 position 0 is 80H, position 5 is 85H. Line 2 starts at C0H (80H + 40H). After a write, the address increments under 06H.

Busy flag: read with RS=0, RW=1. Bit 7 = 1 means busy. Poll until 0 before the next command. If read-back is not wired, use delays: about 1.5 ms after clear and 40 µs for most commands.

Print string: send the DDRAM address, then each character with RS=1, RW=0, pulse E.

Worked example

Question. A four-digit multiplexed common-cathode display shows 1234. One digit is switched on every 1 ms, and each segment is driven from a 5 V port pin through a resistor. The LEDs drop 2 V at 8 mA. Find the frame rate, the segment codes and the resistor value.

  1. Frame time = number of digits × time per digit = 4 × 1 ms = 4 ms.
  2. Refresh rate = 1 / frame time = 1 / 0.004 s = 250 Hz. This is above 50 Hz, so flicker is not expected.
  3. From the common-cathode table: digit 1 = 06H, digit 2 = 5BH, digit 3 = 4FH, digit 4 = 66H.
  4. Series resistor: R = (Vcc − Vf) / I = (5 − 2) V / 0.008 A = 375 Ω.
  5. The nearest standard value above 375 Ω is 390 Ω.

Answer. The frame rate is 250 Hz, the codes are 06H, 5BH, 4FH, 66H, and the resistor is 375 Ω, so use 390 Ω.

Exam traps

  • Common-anode codes are the bitwise complement, not a different font. Writing 06H to a common-anode digit gives a strange but plausible pattern.
  • Multiplexed digits need peak current, not average. A resistor set for 8 mA steady gives a dim display at 1/4 duty.
  • Refresh below 50 Hz flickers; too slow a scan can also let key bounce look like several keys.
  • LCD RS and RW are not interchangeable: RS=0, RW=1 is a busy-flag read, not a data write.
  • Skipping the 15 ms power-on wait or the repeated 38H leaves the HD44780 in an unknown mode.

5.7 ADC and DAC interfacing

A sensor gives a voltage; a processor handles numbers. An ADC sits between them, measuring the voltage and returning the nearest 8-bit code. A DAC runs the other way, turning a code into a voltage. Both work from one reference voltage, and that reference fixes the step size — the smallest change either can see. The two chips to know are the DAC0808 and the ADC0808/0809, plus the way an 8086 reads a conversion through an 8255. Digital thermometers, motor drives and audio paths all rest on this pair.

You need: the 8255 port interface from chapter 5.1 and 8086 I/O instructions from Unit 2.

DAC0808: a code becomes a current

A DAC takes a binary code D and gives an output proportional to it. The DAC0808 does this with an R-2R ladder: a resistor network of only two values, R and 2R, that splits a reference current in binary ratios. Eight input pins D7–D0, one output.

Iout = (Vref / R) × (D / 256)

Iout is the output current in amperes; Vref is the reference voltage in volts; R is the resistor that sets the reference current, in ohms; D is the input code, 0 to 255.

The output is a current, not a voltage. The usual circuit feeds it into an op-amp wired as a current-to-voltage converter with feedback resistor Rf. The op-amp holds its inverting input at virtual ground, so the whole current flows through Rf.

Vout = Iout × Rf = Vref × (Rf / R) × (D / 256)

Vout is the output voltage in volts; Rf is the feedback resistor in ohms. When Rf = R the formula collapses to Vout = Vref × D / 256.

Two numbers describe any DAC when Rf = R. The step size, also called the resolution in volts, is Vref/256, the change for one count, and full scale is Vref × 255/256, one step below Vref, because 255 is the highest code, not a 256th step. In general the step is Vref × (Rf/R)/256. With Vref = 5 V and Rf = R a step is 19.53 mV and full scale is 4.98 V.

  • A staircase wave comes free: output D, add one, output, delay, repeat, wrap from 255 back to 0.
  • The delay comes from the 8253 timer (chapter 5.2) or a software loop.

ADC0808: trial codes until the comparator agrees

The ADC0808 converts the other way. It holds an internal DAC, a comparator and a successive-approximation register (SAR). The SAR guesses a code, the DAC turns the guess into a voltage, the comparator reports whether the guess is too high or too low, and the SAR adjusts. It settles one bit per clock, MSB first, so eight clocks decide eight bits.

An 8-channel multiplexer sits at the front: inputs IN0–IN7, chosen by address pins C, B, A with C as the most significant. ALE latches that address. The falling edge of START begins conversion and pulls EOC low; EOC returns high when the result sits in the output latch. OE enables the tri-state buffers so the CPU can read D0–D7.

With a 640 kHz clock, one clock period is 1.5625 µs. The chip uses eight clock periods per bit, so 64 periods give the 100 µs conversion time. The SAR still needs only eight decisions, one per bit. The ADC0809 is the same converter in the same pinout; reference and accuracy specifications differ, so check the data sheet before swapping one for the other.

step size = Vref / 2ⁿ

Vref is the reference voltage in volts; n is the number of bits, 8 here, so the step is Vref/256.

The input is continuous and the code is not, so the code can be wrong by at most half a step: ±Vref/512, written ±½ LSB. With Vref = 5 V that is ±9.77 mV. Resolution in percent is 100/256 = 0.39 percent of full scale.

Three other architectures, named only. Flash uses 2ⁿ−1 comparators in parallel and converts in one clock. Dual-slope integrates the input over a fixed time: slow, very accurate, the type inside bench multimeters. Tracking keeps a counter that follows the input up and down.

Reading an ADC on the 8086 through an 8255

The ADC data pins do not touch the 8086 bus directly. The 8255 (chapter 5.1) supplies three ports: port A input for D0–D7, port B output for the channel select and the START/ALE pulses, port C input carrying EOC on PC0. Mode 0 with control word 91H gives port A input, port C upper output, port B output, port C lower input.

  1. Write 91H to the 8255 control register.
  2. Write the channel number 0–7 on port B, then pulse ALE high and low to latch it.
  3. Pulse START high for at least 100 ns, then low. EOC falls.
  4. Poll port C bit 0 until it reads 1. Each pass is one IN and one test; at 100 µs a conversion, the loop runs a few dozen times.
  5. Set OE through port B, read port A into AL, clear OE.
  6. Convert the code: V = code × Vref / 256.

This is programmed I/O, so the CPU waits. An interrupt moves the wait out of the loop: EOC drives an 8259 input (chapter 5.3). For fast repeated sampling, DMA (chapter 5.4) moves the bytes instead.

Worked example

Question. An 8-bit ADC has Vref = 5 V and an input of 2.5 V. Find the step size in mV, the output code in hex, the resolution in percent and the quantisation error. Then feed that code to a DAC0808 with Rf = R and the same 5 V reference and find its output.

  1. Step size = Vref / 256 = 5 V / 256 = 0.01953125 V = 19.53125 mV.
  2. Code = Vin / step = 2.5 V / 0.01953125 V = 128, which is 80H.
  3. Resolution in percent = 100 / 256 = 0.390625 percent, about 0.39 percent of full scale.
  4. Quantisation error = half a step = 0.009765625 V = 9.765625 mV, so the reading is 2.5 V ± 9.77 mV.
  5. DAC output = Vref × D / 256 = 5 × 128 / 256 = 2.5 V, which returns the original input.

Answer. Step size 19.53125 mV, code 80H, resolution 0.390625 percent, error ±9.765625 mV, and the DAC0808 returns 2.5 V.

Exam traps

  • Step size is Vref/256, not Vref/255. Code 255 is the top step, one step below Vref; dividing by 255 shifts every answer.
  • The DAC0808 output is a current. Without the op-amp and Rf there is no usable voltage, and Vout = Vref × D/256 holds only when Rf = R.
  • EOC is active high on these parts: low at START, high when conversion ends. Polling for the wrong level hangs the program forever.
  • Quantisation error is ±½ LSB, not ±1 LSB. Writing ±1 LSB loses marks in a numerical answer.
  • ALE and START may be pulsed separately: latch the channel address with ALE first, then start the conversion with START. They may also be tied together and driven from one port line, because the rising edge of ALE latches the address and the falling edge of START starts the conversion.

5.8 Stepper motor, DC motor and relay interfacing

A port pin gives a few milliamps at 5 V. A motor winding or relay coil wants hundreds of milliamps, often at 12 V, and throws back a voltage spike when it switches off. The CPU never touches the load. It drives a driver stage — a ULN2003 for a stepper, an L293D for a DC motor, one NPN transistor for a relay — and the driver switches. The CPU's job is timing: a step sequence, a PWM duty cycle, or one bit.

You need: Chapter 5.1 for the port that sends the coil codes, and delay loops from Unit 3, Assembly programs: loops, delays and look-up tables.

Stepper motor: coils, step angle and coil codes

A stepper motor moves in fixed jumps called steps. Four coils, called phases, sit around the stator and are labelled A, B, C, D. Energising one coil pulls the rotor forward by one step. Nothing is fed back, so counting steps gives shaft position.

In a unipolar motor each coil has a centre tap tied to +12 V and the far end is pulled to ground to energise it. Current flows one way only, so four open-collector outputs are enough. In a bipolar motor there is no centre tap; current must reverse, so each coil needs an H-bridge.

θ = 360° / N

θ is the step angle in degrees per step; N is the number of full steps in one revolution. A common motor has θ = 1.8° and N = 200.

f = n × N / 60, T = 1 / f

n is shaft speed in rpm; f is step rate in steps per second; T is delay between steps in seconds.

Port bits P0.0 to P0.3 carry coils A to D. Port 0 has open-drain outputs, so it needs external 10 kΩ pull-ups before driving ULN2003 inputs. Full-step code keeps two coils on: 03H, 06H, 0CH, 09H — A+B, B+C, C+D, D+A. Half-step code alternates one and two coils: 01H, 03H, 02H, 06H, 04H, 0CH, 08H, 09H. Half step doubles resolution and runs smoother, but at the same step rate the shaft turns at half speed.

The ULN2003 is a seven-channel Darlington sink driver. Each channel takes a 5 V logic input and pulls its output to ground while carrying up to 500 mA at 50 V. A high on the port bit switches that coil on. A COM pin ties all seven internal freewheeling diodes to the motor supply, so each coil's turn-off spike is clamped there instead of destroying the chip.

DC motor: H-bridge, direction and PWM

A DC motor spins continuously. Its direction follows the polarity of the voltage and its speed follows the average voltage. The L293D is a dual H-bridge in a 16-pin package: two channels, 600 mA each, 4.5 V to 36 V, with internal flyback diodes.

Each channel has inputs IN1, IN2 and an enable pin EN. IN1 high with IN2 low turns the motor one way; swap them and it turns the other way; both low brakes the motor to a fast stop. To coast, hold EN low so both outputs float. PWM on EN controls speed while the two inputs hold direction.

V_avg = (D / 100) × V_s,  D = (t_on / T) × 100%

D is duty cycle in percent; t_on is high time within one period T in seconds; V_s is motor supply voltage in volts; V_avg is average motor voltage. Speed is roughly proportional to V_avg.

Keep PWM frequency between 1 kHz and 20 kHz. Below that the motor jerks and whines; above it switching losses climb. The winding is an inductor, so when the bridge turns off, L·di/dt raises a spike; the internal diodes conduct it back to the supply. Any discrete transistor switch needs the same diode. The 8051 has no PWM hardware, so a timer interrupt produces it in software — see Chapter 5.9.

Relay: one transistor, one diode, mains on the contacts

A relay is an electromagnetic switch. Current in a coil pulls an armature, and the armature moves contacts. COM is the common terminal. NO (normally open) is open with the coil off and closes when it is on; NC (normally closed) does the opposite. Coil and contact circuits are electrically separate — a 5 V logic board can switch a 230 V, 50 Hz lamp.

The coil current is too big for a port pin. A 12 V relay coil rated 360 mW draws 30 mA, while a port pin handles about 1.6 mA safely. Use an NPN transistor such as the BC547: base through R_B to the port pin, emitter to ground, collector to the low end of the coil, and the top of the coil to +12 V. A high on the port saturates the transistor and the relay pulls in.

R_B = (V_port − V_BE) / (3 × I_C / h_FE(min))

V_port is logic output voltage (5 V); V_BE is base-emitter drop (0.7 V); I_C is coil current in amperes; h_FE(min) is worst-case current gain; factor 3 is saturation overdrive. For I_C = 30 mA and h_FE = 100, design base current is 0.9 mA, giving R_B ≈ 4.8 kΩ, so use 4.7 kΩ.

An 8051 pin sinks about 1.6 mA but sources only about 60 µA, less than the base current needed, so a buffer such as a 74HC gate sits between the pin and R_B.

A 1N4007 sits across the coil with its cathode to +12 V. It is reverse biased while the coil is on. At switch-off the coil's lower end flies above +12 V, the diode conducts, and the spike is dumped into the coil supply. Fitted the other way round, it short-circuits the supply at power-up.

For mains work, place a PC817 opto-coupler between the port pin and R_B. The 230 V side then shares no ground with the CPU, so a fault on the contact side cannot reach the microcontroller.

Worked example

Question. A 4-phase unipolar stepper motor has a step angle of 1.8° and must turn at 60 rpm. Find the steps per revolution, the step rate and the delay between steps, and give the half-step sequence with coils A, B, C, D on bits 0 to 3.

  1. Steps per revolution: N = 360° / 1.8° = 200 steps.
  2. Shaft speed: 60 rpm = 1 revolution per second.
  3. Step rate in full step: f = 1 × 200 = 200 steps per second.
  4. Delay between steps: T = 1 / 200 s = 5 ms.
  5. In half step the step angle halves to 0.9°, so N = 400 steps per revolution and the step rate at 60 rpm rises to 400 steps per second, with a delay of 2.5 ms.
  6. Half-step sequence: 01H, 03H, 02H, 06H, 04H, 0CH, 08H, 09H, then repeat.

Answer. N = 200 steps per revolution, step rate 200 steps per second, delay 5 ms in full step; half step gives a 0.9° step angle and the sequence 01H, 03H, 02H, 06H, 04H, 0CH, 08H, 09H.

Exam traps

  • An external freewheeling diode is a must for a discrete transistor switch. The ULN2003 has internal diodes, but they work only if COM is wired to the motor supply.
  • Dividing the wrong way: 1.8°/360° gives N = 0.005 instead of 200, so every speed answer is wrong by that factor.
  • Assuming the ULN2003 sources current. It sinks: a high on the input pulls the output to ground, so the coil's other end must go to the positive supply.
  • Confusing the coil rating with the contact rating of a relay. A 12 V, 30 mA coil can still carry 230 V, 5 A contacts; the two numbers describe different terminals.
  • Fitting the 1N4007 the wrong way round across the coil, or driving a DC motor straight from a port pin.

5.9 Sensor and RTC interfacing; PWM generation

Sensors and clocks give a microcontroller the state of the physical world: a voltage, a pulse width, or a serial frame. The CPU reads that number through an ADC pin or a bus. A real-time clock keeps calendar time when power fails. PWM works the other way: a timer pin switches a load on and off, and the load sees the average voltage. These blocks sit around the CPU in almost every embedded board: a temperature logger, a payment terminal with a clock, a fan controller.

You need: Chapter 5.7 for the ADC step size, and Chapter 5.2 or Unit 4 timers for the PWM period.

Sensors hand over a number

A sensor turns a physical quantity into an electrical signal. The signal can be analog, a pulse width, a serial frame or a simple logic level. The CPU must know which type it is before it connects the sensor.

An LM35 gives 10 mV for every degree Celsius. Connect its output to one ADC channel, say channel 0. With an 8-bit ADC and Vref = 5 V, each code is 5/256 = 19.53 mV, as in Chapter 5.7. Temperature = sensor voltage ÷ 10 mV/°C. The LM35 needs no calibration in its normal range.

A light-dependent resistor (LDR) changes resistance with light. Put it in a divider with a fixed resistor; the junction voltage goes to an ADC. Bright light lowers LDR resistance, so the voltage moves one way. The direction depends on whether the LDR is the top or bottom resistor.

An infrared obstacle sensor has an IR LED and a photodiode. Its receiver gives a digital level: object present or absent. Connect it to a port pin, not an ADC.

The DHT11 sends temperature and humidity as a 40-bit frame on one wire: 8 bits humidity integer, 8 humidity decimal, 8 temperature integer, 8 temperature decimal, 8 checksum. The CPU times the start pulse and reads each bit from its high-time duration.

The HC-SR04 ultrasonic sensor needs a 10 µs trigger pulse. Echo then stays high for the round-trip time of sound. Distance = echo width in µs ÷ 58, in centimetres.

The DS12887 real-time clock

The DS12887 is a real-time clock module with 128 bytes of battery-backed RAM. Fourteen of those bytes are clock, alarm and control registers; the rest are general RAM. It keeps seconds, minutes, hours, day, date, month and year.

The address and data pins are multiplexed on AD0-AD7. The CPU first puts an address on the bus and drops address strobe AS to latch it. It then asserts chip select CS and data strobe DS for the access, with RW choosing read or write. This is a multiplexed bus, not separate address and data pins.

Registers 00H to 09H hold seconds, seconds alarm, minutes, minutes alarm, hours, hours alarm, day of week, date, month and year. After reset they are in BCD. Register B has a binary-mode bit and a 12/24-hour bit. Register C holds interrupt flags. Register D has the valid-RAM bit; if it is 0, the backup battery is dead and the time is invalid.

Time can roll over during a read. Read seconds, minutes, hours, day, date, month and year; then read seconds again. If the second seconds value differs, repeat the whole block. This prevents mixing fields from two different seconds.

The DS1307 is a smaller RTC on I2C: two wires, SCL and SDA, same seconds-to-year idea in BCD.

PWM from a timer

PWM switches a load at a fixed period T and changes the on-time Ton. The duty cycle sets the average. A 5 V rail at 25 percent gives 1.25 V; at 75 percent it gives 3.75 V.

D = T<sub>on</sub> / T, V<sub>avg</sub> = D × V<sub>cc</sub>

D is duty cycle; Ton is on-time in seconds; T is period in seconds; Vavg is average voltage in volts; Vcc is supply voltage in volts.

A timer makes PWM with a counter and a compare value. The counter runs from 0 to the period count and reloads. When the count is below the compare value the pin is high; above it the pin is low. On the 8051, Timer 0 mode 2 gives auto-reload; an interrupt or compare logic sets the pin. On the MSP430, Timer_A compare channels drive the pin in hardware, so the CPU only writes the compare value.

Choose the frequency from the load. Too low: a lamp flickers and a motor jerks. Too high: switching loss and driver heating rise. Lamps often use a few hundred hertz to a few kilohertz. Small DC motors use 1 kHz to 20 kHz. A hobby servo expects 50 Hz and a 1 ms to 2 ms pulse; 1.5 ms is centre.

Uses: lamp dimming, DC motor speed, servo position, and LED brightness. The duty cycle sets the average; the period sets the switching frequency.

Worked example

Question. An LM35 feeds ADC channel 0 of an 8-bit converter with Vref = 5 V. The code read is 0FH. Find the step size, the sensor voltage and the temperature. A 5 V rail drives a lamp through a transistor switched at 250 Hz with 25 percent duty cycle. Find the average voltage.

  1. Step 1: step size = Vref/28 = 5 V / 256 = 0.01953 V = 19.53 mV.
  2. Step 2: 0FH = 15 decimal. Sensor voltage = 15 × 19.53 mV = 293 mV.
  3. Step 3: temperature = 293 mV / (10 mV/°C) = 29.3°C.
  4. Step 4: period T = 1/f = 1/250 Hz = 0.004 s = 4 ms.
  5. Step 5: on-time = D × T = 0.25 × 4 ms = 1 ms.
  6. Step 6: average voltage = D × Vcc = 0.25 × 5 V = 1.25 V.

Answer. The step size is 19.53 mV, the sensor voltage is 293 mV, the temperature is 29.3°C, and the lamp average voltage is 1.25 V.

Exam traps

  • The LM35 output is 10 mV/°C, not 10 V/°C. Convert 293 mV to 0.293 V before dividing by 0.01 V/°C; otherwise the answer is 1000 times too large.
  • RTC time registers are BCD until the binary bit in register B is set. Read 45H as 45 minutes, not as hexadecimal 69; a hex display gives nonsense.
  • The DS12887 has a multiplexed address/data bus. Latch the address with AS first; treating AD0-AD7 as separate address and data pins gives wrong register accesses.
  • Duty cycle is not frequency. Changing the compare value changes average voltage; changing the period count changes switching frequency. Same duty at two frequencies has the same average but different ripple.
  • HC-SR04 echo is a round trip. Divide the echo width in µs by 58 for centimetres, not by 29; the 10 µs trigger only starts the measurement.

Takeaways

  1. The 8255 packs three ports into one control-word-programmed chip, so slow devices use handshake instead of forcing bus waits.
  2. The 8253/8254 counts a known clock down to zero, producing delays, rates and waveforms without CPU loops.
  3. The 8259 latches, masks and prioritises requests, then gives one vector so many devices share INTR.
  4. The DMA controller moves bytes by taking HRQ/HLDA bus ownership, leaving the CPU out of the copy loop.
  5. The 8251 frames each byte with start, parity and stop bits and converts between parallel and serial data.
  6. Keyboards and displays use scanning and multiplexing because human-speed devices are slow but numerous.
  7. ADC and DAC step size is set by reference voltage and bit count; code and voltage map linearly.
  8. Motor and relay loads need external driver current; the CPU supplies only the step sequence or PWM duty.
  9. Sensors and RTCs deliver analog, pulse or serial numbers; timers turn counts into PWM average voltage.

Glossary

8255
Programmable peripheral interface with three 8-bit ports whose directions and handshake modes are set by a control word.
8259
Programmable interrupt controller that latches, masks, prioritises and vectors eight interrupt request lines.
ADC
Analog-to-digital converter that maps an input voltage to the nearest binary code.
Baud rate
Number of serial signal bits per second, set by clock division and the USART mode.
BSR mode
8255 bit set/reset mode that sets or clears one selected bit of port C.
Control word
Byte written to a programmable peripheral that selects its operating mode and data direction.
Counter (8253/8254)
Programmable down-counter that divides its input clock and changes an output pin at terminal count.
Cycle stealing
DMA method that takes the bus for one transfer at a time, briefly slowing the CPU.
DAC
Digital-to-analog converter that maps a binary code to an output voltage.
DMA controller
Chip that takes bus ownership and moves data between memory and a peripheral without the CPU copying each byte.
Driver stage
Circuit that supplies the current or voltage needed by a motor, relay or lamp under a logic pin command.
End of interrupt
Command sent to the 8259 after a service routine so the in-service bit is cleared.
Framing
Start, data, parity and stop bit structure that lets a serial receiver find byte boundaries.
Gate input
8253/8254 control pin that enables, disables or restarts counting depending on the selected mode.
Interrupt mask register
8259 register that blocks selected interrupt request lines from reaching the priority resolver.
Interrupt vector
Code supplied to the CPU that identifies the address of the interrupt service routine.
LCD
Liquid-crystal display driven by commands and data bytes through control lines such as RS, RW and E.
Mode 0
8255 simple input or output mode with no handshake lines.
Mode 1
8255 strobed input or output mode that uses port C lines for handshake and status.
Multiplexing
Sharing wires by turning several devices or digits on one at a time faster than the eye can follow.
PWM
Pulse-width modulation; a square wave whose duty cycle sets the average voltage delivered to a load.
Quantisation error
Difference between the true analog value and the nearest code, at most half an LSB in ideal rounding.
Resolution
Smallest voltage change a converter can represent, equal to Vref / 2^n for n bits.
Seven-segment display
Display of seven LED segments plus a decimal point, driven by a code for each digit.
Terminal count
Counter value or state at which the programmed count ends and the output changes.
USART
Universal synchronous/asynchronous receiver-transmitter that converts parallel bytes to serial frames and back.
