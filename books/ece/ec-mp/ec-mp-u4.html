4.1 8051 architecture, pins, memory and special function registers

The 8051 is an 8-bit microcontroller: CPU, memory and I/O on one chip. It uses Harvard architecture, so code and data have separate address spaces. Code ROM is 4 KB, data RAM 128 bytes, and the special function registers (SFRs) that drive the peripherals occupy their own 128 bytes. Fixed pins and a fixed register map keep this old design inside ATMs, washing machines and lift controllers.

You need Harvard versus von Neumann organization, and microprocessor versus microcontroller, from Unit 1, Foundations.

The blocks inside the chip

The core is an 8-bit CPU with an 8-bit ALU and working registers A and B. Code comes from 4 KB of on-chip ROM at 0000-0FFF; data comes from 128 bytes of RAM at 00-7F. Two 16-bit timer/counters, one UART, an interrupt controller and four 8-bit ports complete the chip.

Harvard shows in the buses. A fetch from external program memory drives PSEN (program store enable); fetches from internal ROM do not. Data reads and writes drive RD or WR. So code address 0000 and data address 00 are different places, and the opcode decides which space you mean. That is why MOVC and MOVX sit beside plain MOV.

The 40 pins, grouped by job

The 8051 comes in a 40-pin DIP. Pin 40 is Vcc (+5 V), pin 20 is GND.

Port 0 (P0.0-P0.7) is the multiplexed low bus: AD0-AD7 carry the low address byte, then the data byte. Port 2 (P2.0-P2.7) supplies A8-A15. Port 1 is plain I/O.

Port 3 pins have second jobs: P3.0 RXD and P3.1 TXD (serial), P3.2 INT0 and P3.3 INT1 (external interrupts), P3.4 T0 and P3.5 T1 (timer inputs), P3.6 WR and P3.7 RD (external data strobes).

Control pins: XTAL1 and XTAL2 take the crystal, often 12 MHz. RST is active high. EA high selects internal ROM; EA low forces external code. PSEN is the external code read strobe; ALE latches the low address byte out of Port 0.

Pin numbering matters for wiring: P0.0 is pin 39, P1.0 is pin 1, and the control pins sit at the top of the package.

Memory map: three spaces, no overlap

Code space 0000-0FFF holds the program; execution starts at 0000 on reset.

Data RAM 00-7F is reachable directly and indirectly. The lowest 32 bytes are four register banks of eight: 00-07, 08-0F, 10-17, 18-1F. PSW bits RS1:RS0 pick the active bank. Bytes 20-2F are bit-addressable: 16 bytes × 8 bits = 128 bit addresses, numbered 00-7F.

SFR space 80-FF is reachable only by direct address; RAM 80-FF is reachable only indirectly. So the same number names an SFR in direct mode and a RAM byte in indirect mode. On a plain 8051 nothing is at 80-FF but SFRs; parts in the 8052 family add a second 128 bytes of RAM there, indirect only.

SFR addresses: ACC E0, B F0, PSW D0, SP 81, DPL 82, DPH 83, P0 80, P1 90, P2 A0, P3 B0, IE A8, IP B8, TCON 88, TMOD 89, TL0 8A, TL1 8B, TH0 8C, TH1 8D, SCON 98, SBUF 99, PCON 87.

Worked example

Question. Data RAM byte 0x2A holds 0x84. Find the bit addresses of bit 2 and bit 7, and the value at each.

  1. Bit-addressable RAM starts at 0x20 and gives bit addresses 0x00-0x7F.
  2. Offset of 0x2A from 0x20 is 10 bytes, so its bit base is 10 × 8 = 80 = 0x50.
  3. Bit 2 = 0x50 + 2 = 0x52 (82); bit 7 = 0x50 + 7 = 0x57 (87).
  4. 0x84 = 1000 0100, so bits 7 and 2 are both 1.

Answer. Bit 2 is bit address 0x52 (82) and bit 7 is 0x57 (87); both hold 1.

Exam traps

  • On an 8052, direct address 80-FF selects an SFR, never upper RAM. To read upper RAM byte 80H you must load the address into R0 or R1 and use @R0. A plain 8051 has no upper RAM.
  • EA low or floating makes the CPU fetch from the external bus, so the chip looks dead with a correct program inside. Tie EA to Vcc for internal ROM.
  • SP resets to 07, so the first PUSH goes to 08 — inside register bank 1. Move SP to 0x30 (30H) so the first push lands at 0x31 and all four banks stay free.
  • Bit address 0x52 and byte address 0x52 are different objects; the instruction picks (SETB versus MOV).

4.2 I/O ports and port programming

The 8051 has four 8-bit parallel ports, P0 to P3. Each port is a latch plus an output driver, and that pair explains every rule of port programming: to use a pin as an input you first write 1 to it, so the driver stops holding the pin low and a weak internal pull-up can raise it. Some instructions then read the pin, others read the latch. LEDs, switches, keypads, relays and LCD panels all connect through these ports, which makes them the most-used pins on the chip.

You need: Chapter 4.1 for the port SFR addresses, bit addressing and the pin functions of P3.

Four ports, four latches

The four port registers are special function registers at fixed direct addresses: P0 at 80H, P1 at 90H, P2 at A0H and P3 at B0H. All four are bit addressable, so P1.3 means bit 3 of P1, bit address 93H. Writing a byte to P1 writes its latch; the latch output drives the pin through an output transistor.

P0 is open drain. Its driver can pull a pin to 0 V but has no pull-up of its own, so it cannot pull a pin high. Put an external resistor from the pin to +5 V (10 kΩ is a common choice) or the pin floats when its latch holds 1. P0 also becomes the multiplexed address/data bus AD0–AD7 when external memory is used.

P1, P2 and P3 are quasi-bidirectional. Each pin has a weak internal pull-up. Writing 1 to the latch switches the strong driver off, and the weak pull-up holds the pin near +5 V; an external circuit that pulls the pin low wins, because the pull-up supplies only tens of microamps. Writing 0 switches the strong driver on and forces the pin to 0 V.

A pin sinks more current than it sources: the classic part lists about 1.6 mA sink for P1–P3 and 3.2 mA for P0, but only a small source current. So an LED is wired with its anode to +5 V through a resistor and its cathode to the pin: pin low means LED on.

P2 supplies A8–A15 in expanded memory systems. P3 pins carry RXD, TXD, INT0, INT1, T0, T1, WR and RD, so check those chapters before using P3 as plain I/O (see 4.3, 4.4, 4.5).

Input means writing 1 first

If the latch holds 0, the driver holds the pin at 0 V. A switch to ground then changes nothing, and the CPU always reads 0. Writing 1 turns the driver off, so a switch, keypad or sensor output can decide the pin level. The standard line before reading a port is MOV P1,#0FFH.

Two kinds of instruction touch a port. Read-pin instructions look at the outside world. Read-modify-write instructions (RMW) read the latch, change it, and write it back, so an external load that drags the pin slowly cannot be misread as the value the software intended.

Three short port programs

Blink an LED on P1.0 in assembly. CPL P1.0 is read-modify-write, which is safe here because the pin is an output.

Pseudocode.

        ORG 0000H
        MOV P1,#00H          ; every P1 pin driven low
AGAIN:  CPL P1.0             ; toggle the LED pin
        ACALL DELAY
        SJMP AGAIN
DELAY:  MOV R7,#200
D1:     MOV R6,#250
D2:     DJNZ R6,D2
        DJNZ R7,D1
        RET
        END

The delay is about 200 × 250 × 2 = 100000 machine cycles, roughly 0.1 s with a 12 MHz crystal (1 µs per machine cycle).

Copy a switch on P1.1 to the LED on P1.0. MOV C,P1.1 reads the pin; MOV P1.0,C writes the latch bit.

Pseudocode.

        MOV P1,#0FFH         ; release all pins: P1.1 can be an input
READ:   MOV C,P1.1           ; read the switch pin
        MOV P1.0,C           ; drive the LED pin
        SJMP READ

The same job in C for Keil-style 8051 compilers:

Pseudocode.

#include <reg51.h>
sbit LED = P1^0;
sbit SW  = P1^1;
void main(void) {
    P1 = 0xFF;          /* release every pin */
    while (1) {
        LED = SW;       /* read the pin, write the latch bit */
    }
}

Masking changes some bits and keeps the rest: P1 = (P1 & 0xF0) | 0x05; keeps P1.4–P1.7 and sets P1.0 and P1.2. The compiler reads P1 with MOV A,P1, which reads the pin, unlike the 8051's own RMW instruction. Any pin used as an input must already have its latch at 1, or the mask writes 0 back to it.

Worked example

Question. Port 1 is written 0FFH. An external switch from P1.0 to ground is closed and holds that pin low. The program then runs MOV A,P1 / ANL P1,#0FH / MOV A,P1. Give A after the first read, the P1 latch after ANL, and A after the second read. (Hex and decimal.)

  1. Initial latch P1 = 1111 1111 = FFH. The switch holds pin P1.0 at 0; pins P1.1–P1.7 have latch 1 and nothing pulling them, so the weak pull-up makes them 1.
  2. MOV A,P1 reads the pin: 1111 1110 = FEH = 254. So A = 254.
  3. ANL P1,#0FH is read-modify-write. It reads the latch (FFH), not the pin (FEH): FFH AND 0FH = 0FH = 15. The latch becomes 15, so P1.4–P1.7 latch bits are 0 and those pins are driven low.
  4. ANL P1,#0FH does not touch A, so A is still 254.
  5. Second MOV A,P1 reads the pin. P1.7–P1.4 are driven low = 0000. P1.3–P1.1 have latch 1 and are released = 111. P1.0 is still held by the switch = 0. Pin byte = 0000 1110 = 0EH = 14. So A = 14.

Answer. A = FEH (254) after the first read, the P1 latch becomes 0FH (15) after the ANL, and A = 0EH (14) after the second read.

Exam traps

  • Writing 0 to a pin and then expecting an external switch to change it. The driver holds the pin low, so the CPU always reads 0. Write 1 first.
  • Mixing up MOV A,P1 (reads the pin) with ANL P1,#data (reads the latch). Examiners love giving a latch value, a switch position and two reads, then asking for both A and P1.
  • Forgetting that P0 is open drain. Without external pull-up resistors P0 cannot produce a logic 1, so an LED or gate on P0 with no resistor never goes high.
  • Believing that writing 1 to P1, P2 or P3 drives the pin strongly high. It only releases the pin to a weak pull-up; the pin can still be pulled low, and it cannot source an LED.
  • Reading a whole port in C (P1 = P1 | 0x0F) reads the pins, not the latch, because the compiler emits MOV A,P1. Input pins must be kept at 1 or the mask writes 0 back.

4.3 Timers and counters: modes and programming

The 8051 has two identical 16-bit counter blocks. Each block adds 1 to a register pair on every pulse and sets a flag when the pair rolls over. The pulses are either internal machine cycles — the block is then a timer — or falling edges on a pin — the block is then an event counter. One byte, TMOD, chooses the source, the width and the gating for both blocks. Timers give the 8051 accurate delays without tying up the CPU, count external events such as pulses from a sensor, and also set the serial baud rate (see 4.4).

You need: the TMOD, TCON and TH/TL special function registers from 4.1, and the assembly loop delay programs from Unit 3.

Two counter blocks and the machine cycle

Timer 0 and Timer 1 are two identical 16-bit blocks. Each is a register pair — TH0:TL0 for Timer 0, TH1:TL1 for Timer 1 — that adds 1 on every pulse. When the value rolls from FFFFH to 0000H, hardware sets an overflow flag, TF0 or TF1, which software can poll or turn into an interrupt (see 4.5).

The bit C/T in TMOD chooses where the pulses come from. With C/T = 0 the block counts internal machine cycles, so it is a timer and gives accurate delays. With C/T = 1 it counts falling edges on pin T0 (P3.4) or T1 (P3.5), so it is an event counter — counting pulses from a slotted wheel to measure motor speed, for example.

One machine cycle is 12 oscillator periods: T = 12 / fosc. At fosc = 12 MHz, T = 1 µs, so the whole 16-bit range 0 to 65,535 is 65.536 ms. At fosc = 11.0592 MHz, T = 1.085 µs.

The CPU stays free while the timer counts. A software loop delay blocks everything else; here the CPU looks at the flag only when it needs to.

TMOD and TCON: choosing the source and the mode

TMOD at address 89H is one control byte, not bit-addressable. Its low nibble configures Timer 0 and its high nibble Timer 1, in the same bit order: GATE, C/T, M1, M0.

GATE = 0 means the timer runs whenever TRx = 1. GATE = 1 means it runs only when TRx = 1 and the matching pin INT0 or INT1 is high, so an external pulse opens and closes the counting window. That is how the 8051 measures the width of a pulse.

Programming a mode 1 delay

For Timer 0 as a plain 16-bit timer with no gating, TMOD = 0000 0001B = 01H. The same five steps set up either timer.

  1. Write TMOD to select timer or counter, mode, and gating.
  2. Compute the count N = delay ÷ T, where T = 12 / fosc is one machine cycle.
  3. Load the reload value 65,536 − N into THx (high byte) and TLx (low byte).
  4. Clear TFx, then set TRx to start counting.
  5. Wait until TFx = 1, then clear TFx and reload, or stop.
        MOV  TMOD, #01H    ; Timer 0, mode 1, internal clock, no gate
        MOV  TH0,  #3CH    ; high byte of the reload
        MOV  TL0,  #0B0H   ; low byte of the reload
        CLR  TF0           ; clear any old flag
        SETB TR0           ; start counting
WAIT:   JNB  TF0, WAIT     ; poll until overflow
        CLR  TR0           ; stop the timer
        CLR  TF0           ; ready for the next round

Output

About 50 ms after SETB TR0, TF0 becomes 1, the JNB loop falls through, and TR0 and TF0 are cleared. TH0:TL0 now reads 0000H, so it must be reloaded with 3CB0H before the next round.

The timer counts up from the reload value, so a bigger reload means a shorter delay. TF0 stays set until software clears it; a stale flag makes the next wait return at once.

For longer delays, reload inside the loop. At 12 MHz the longest single mode 1 delay is 65.536 ms, so 1 s needs twenty rounds of 50 ms.

Worked example

Question. An 8051 system uses a 12 MHz crystal. Timer 0 must produce a 50 ms delay in mode 1. (a) Find the machine cycle time. (b) Find the number of counts needed. (c) Find the reload value in hex and the bytes written to TH0 and TL0. (d) Verify the delay produced if TH0:TL0 is loaded with 3CB0H.

  1. Machine cycle: T = 12 / fosc = 12 / (12 × 10⁶ Hz) = 1 µs.
  2. Counts needed: N = 50 ms / 1 µs = 50,000.
  3. Range check: mode 1 overflows after 65,536 counts, and 50,000 ≤ 65,536, so one round is enough.
  4. Reload = 65,536 − 50,000 = 15,536.
  5. To hex: 3 × 4096 = 12,288, remainder 3,248; 12 × 256 = 3,072, so the next digit is C, remainder 176 = B0H. Hence 15,536 = 3CB0H.
  6. Write TH0 = 3CH and TL0 = B0H. The timer runs 3CB0H, 3CB1H … FFFFH and then overflows, which is 65,536 − 15,536 = 50,000 counts.
  7. Check for (d): 50,000 × 1 µs = 50 ms.

Answer. T = 1 µs, N = 50,000 counts, reload = 15,536 = 3CB0H, so TH0 = 3CH and TL0 = B0H; loading 3CB0H gives exactly 50 ms.

Exam traps

  • Mode 0 is 13 bits, not 16. It allows only 8192 counts, so a reload worked out for mode 1 gives a delay about eight times too short when the mode bits are wrong.
  • The machine cycle is 12 oscillator periods. At 11.0592 MHz one count is 1.085 µs, not 1 µs. Using 1 µs makes every delay about 8.5% too long — 10 ms becomes about 10.85 ms — because the count taken is 8.5% too large.
  • The reload is 65,536 − N, not N. Loading N itself runs the timer 65,536 − N counts: the 50 ms case then gives 15,536 counts ≈ 15.5 ms, and for small N the delay comes out longer instead of shorter.
  • In mode 2 the reload sits in THx and TLx is the counter; in mode 1 both bytes are the count. Swapping the two bytes changes the delay completely.
  • TF0 is set by hardware but not cleared by hardware when you poll. Clear it before the next round, or the next wait exits at once and the delay collapses.

4.4 Serial communication and RS-232 interfacing

A parallel byte needs eight wires; a serial link needs two. The 8051 UART (universal asynchronous receiver/transmitter) shifts a byte out one bit at a time, adds a start and stop bit, and rebuilds incoming bits. Timer 1 sets the bit rate. RS-232 raises 0–5 V logic to ±3 to ±15 V so a cable can reach a PC. GSM modems, GPS modules and old display boards use this link.

You need: 4.1 for SCON, SBUF and PCON, and 4.3 for Timer 1 in auto-reload mode.

The mode 1 frame, SCON and SBUF

Serial transmission sends bits one after another on one wire. In mode 1 the 8051 frame is ten bits: start bit (0), eight data bits least significant first, stop bit (1). No clock wire is used; the receiver restarts its clock on the start bit's falling edge, so the link is asynchronous. At 9600 baud a ten-bit frame carries 960 bytes per second, not 1200.

SCON (0x98) selects the mode and holds flags. SM0 = 0, SM1 = 1 selects mode 1; REN = 1 enables the receiver.

SBUF (0x99) has two registers behind one address. Writing SBUF loads the transmit register and starts the frame. Reading SBUF returns the received byte. Hardware sets TI when it puts the stop bit on the line, and sets RI when a whole frame arrives. Neither flag clears itself; a routine without CLR TI waits forever on the second byte.

Baud rate from Timer 1

Baud rate is bits per second. At 9600 baud one bit lasts 1/9600 s ≈ 104 µs. In mode 1 the shift clock comes from Timer 1 in mode 2, 8-bit auto-reload. The timer counts at fosc/12 and overflows every (256 − TH1) counts. Each overflow shifts one bit.

baud = (2^SMOD / 32) × fosc / (12 × (256 − TH1))

baud is bits per second; SMOD is bit 7 of PCON, 0 or 1; fosc is the crystal frequency in Hz; TH1 is the 8-bit reload value held in TH1; 12 converts fosc into the timer clock; (256 − TH1) is the number of timer clocks per overflow; 32 is the fixed divider inside the UART.

Rearranged: TH1 = 256 − fosc / (12 × 32 × 2^SMOD × baud). The 11.0592 MHz crystal is popular because 11,059,200 = 384 × 28,800, so standard rates divide it exactly. SMOD = 1 doubles the baud rate for the same TH1.

RS-232 levels and the MAX232

The 8051 pins carry TTL levels: 0 V is logic 0, 5 V is logic 1. RS-232 inverts this and uses higher voltages. Logic 0 is +3 V to +15 V (space); logic 1 is −3 V to −15 V (mark). Between −3 V and +3 V is undefined, and that dead band gives noise immunity on a long cable. A TTL pin cannot drive such a line, and ±12 V on an 8051 pin would destroy it.

The MAX232 converts both ways. It has two drivers, two receivers and a charge pump that doubles and inverts the 5 V rail, giving about +9 V and −9 V from one supply and four small capacitors. TXD (port 3.1) feeds a driver, whose output goes to DB9 pin 3. The PC signal arrives on pin 2, passes through a receiver, and reaches RXD (port 3.0) as TTL. Pin 5 is ground; the two data wires cross over.

Polling transmit and receive

Polling repeats a test until a flag changes. To transmit, write SBUF, wait for TI, clear TI. To receive, wait for RI, read SBUF, clear RI. One frame takes about 1 ms at 9600 baud, so the CPU spins doing nothing else. The interrupt version is in 4.5.

Pseudocode.

TX:  MOV  SBUF, A     ; writing SBUF starts the frame
WAIT: JNB  TI, WAIT    ; wait until TI = 1
     CLR  TI          ; clear the flag by software
     RET

RX:  JNB  RI, RX      ; wait for a full frame
     MOV  A, SBUF     ; read the received byte
     CLR  RI          ; clear the flag by software
     RET

The same two routines in C, with registers simulated so the program runs on a PC:

C program.

#include <stdio.h>

static unsigned char SBUF;
static int TI = 0, RI = 0;

static void tx_byte(unsigned char c) {
    SBUF = c;              /* write starts the frame */
    TI = 1;                /* hardware sets TI */
    while (TI) TI = 0;     /* software clears TI */
    printf("TX %02X\n", c);
}

static unsigned char rx_byte(unsigned char c) {
    SBUF = c; RI = 1;      /* hardware fills SBUF, sets RI */
    unsigned char d = SBUF;
    RI = 0;                /* software clears RI */
    printf("RX %02X\n", d);
    return d;
}

int main(void) {
    const char *s = "OK";
    for (int i = 0; s[i] != '\0'; i++)
        tx_byte((unsigned char)s[i]);
    rx_byte(0x41);

}

4.5 Interrupts and interrupt programming

An interrupt is a hardware request that makes the 8051 stop its current program and run a short routine. The chip has five sources: two external pins, two timers and the serial port. Each source has a fixed entry address called a vector. Interrupt programming means enabling only the sources you need, choosing priority, and writing short service routines that clear the correct flags. It is used for urgent events such as a key press, a timer tick, or a byte arriving on the serial line.

You need: 4.1 for the SFRs, 4.3 for TF0/TF1, and 4.4 for RI/TI.

Five sources, five vectors

An interrupt is a request for the CPU to leave its main program and run a short routine. The 8051 has five sources. Two come from pins: external interrupt 0 (INT0) and external interrupt 1 (INT1). Two come from timers: Timer 0 overflow (TF0) and Timer 1 overflow (TF1). One comes from the serial port: a byte received or transmitted (RI or TI). Each source has a fixed code address, called its vector. The five vectors are 0003H for INT0, 000BH for Timer 0, 0013H for INT1, 001BH for Timer 1, and 0023H for the serial port. The gap is 8 bytes. The reset address is 0000H. At a vector, the CPU jumps to the routine. If the routine is longer than 8 bytes, place a jump at the vector to a service routine elsewhere. Timer flags TF0 and TF1 are cleared by hardware when the vector is taken. Serial flags RI and TI are not; the routine must clear them. External requests use TCON: IT0 and IT1 choose falling-edge or low-level; IE0 and IE1 are the request flags.

IE, IP and priority

The IE register is the master switch and the per-source switch. Bit EA (IE.7) must be 1, or no masked interrupt reaches the CPU. The source bits are EX0 (IE.0) for INT0, ET0 (IE.1) for Timer 0, EX1 (IE.2) for INT1, ET1 (IE.3) for Timer 1, and ES (IE.4) for the serial port. Write IE = 0x83 to set EA, ET0 and EX0: binary 1000 0011. That enables Timer 0 and INT0 only. The IP register sets priority. PS (IP.4), PT1 (IP.3), PX1 (IP.2), PT0 (IP.1), and PX0 (IP.0) match the five sources. A 1 makes that source high priority; a 0 leaves it low. If two requests arrive together, high priority wins. If both are same priority, a fixed internal order applies; do not rely on it for new designs. Latency is the time from the request to the first instruction of the ISR. It includes finishing the current instruction and the call to the vector. A long instruction such as MUL or DIV adds to latency. Some syllabi call this the 8051 interrupt structure and interrupt programming.

Writing short ISRs in C

In C, the interrupt keyword attaches a function to a vector number. Vector 0 is INT0, 1 is Timer 0, 2 is INT1, 3 is Timer 1, 4 is serial. A Timer 0 routine is void t0_isr(void) interrupt 1. Keep the routine short. Do the urgent work, set a volatile flag, and return. The main loop tests the flag and does slow work such as display or UART formatting. Declare the flag volatile so the compiler reloads it. For the serial port, read the cause: if RI is set, read SBUF; if TI is set, prepare the next byte. Clear RI and TI in software. Do not call large library functions inside an ISR. Do not wait for a flag inside an ISR. In assembly, the vector often holds SJMP service or LJMP service; the service routine ends with RETI. RETI restores the program counter and the interrupt logic. This pattern is used in a timer tick for a seven-segment display or a serial receive handler.

Worked example

Question. IE = 0x83, IP = 0x02, and TCON = 0x01. Which interrupts are enabled, which source has high priority, and how is INT0 triggered?

  1. IE = 0x83 = 131 decimal = 1000 0011₂. Mask EA = 0x80 = 128: 131 AND 128 = 128, so EA = 1. Mask ET0 = 0x02 = 2: 131 AND 2 = 2, so ET0 = 1. Mask EX0 = 0x01 = 1: 131 AND 1 = 1, so EX0 = 1. ES, ET1 and EX1 are 0.
  2. Enabled sources: Timer 0 overflow and INT0. Serial and INT1 are disabled. EA = 1 allows the enabled requests to reach the CPU.
  3. IP = 0x02 = 2 decimal = 0000 0010₂. Mask PT0 = 0x02 = 2: 2 AND 2 = 2, so PT0 = 1. Timer 0 is high priority; all other sources are low priority.
  4. TCON = 0x01 = 1 decimal = 0000 0001₂. Mask IT0 = 0x01 = 1: 1 AND 1 = 1, so IT0 = 1. INT0 is falling-edge triggered, not low-level.

Answer. Timer 0 and external interrupt 0 are enabled; Timer 0 is high priority; INT0 is falling-edge triggered.

Exam traps

  • Forgetting EA = 1 leaves every masked source silent even when EX0 or ET0 is 1.
  • Timer flags TF0/TF1 are cleared by hardware at the vector; serial flags RI/TI are not, so the serial ISR must clear them.
  • Each vector has only 8 bytes. Writing a full routine at 000BH can spill into 0013H; use a jump to a service routine.
  • IE0/IE1 are request flags; EX0/EX1 are enable bits; IT0/IT1 choose edge or low level. Do not mix them.
  • A low-level external interrupt remains active while the pin is low, so the ISR may re-enter unless the source is removed.

4.6 Embedded C programming for microcontrollers

Embedded C keeps the C language you know but ties every byte to the 8051's fixed memory and registers. A program that would run on a PC must be told which names are special function registers, which variables a hardware interrupt can change, and where variables live. The compiler then turns the source into a HEX file for program flash. This style is used for small control tasks: reading a key on P1, timing a pulse with Timer 0, sending a byte on the UART, or blinking an LED from an interrupt.

You need: 4.2 for port latches, 4.3 for timer modes, 4.4 for SBUF and baud rate, and 4.5 for vectors and IE/IP.

C with hardware addresses

Standard C has no idea that address 0x90 is Port 1. Embedded C adds a small set of keywords so the programmer can name hardware. The C51 compiler from Keil and the free SDCC compiler both accept this idea; exact keyword spelling can differ, so check the header. The source file is compiled and linked into a HEX file, which a programmer writes into the 8051's program flash. Some syllabi call this C51 programming or 8051 C programming.

Choose data types by size, not habit. On C51, unsigned char is 8 bits (0 to 255), unsigned int is 16 bits (0 to 65535), and bit is one bit. A port byte, a counter below 256, or a bit mask should be unsigned char. Use unsigned int only for values that need more than 8 bits, such as a 16-bit timer count or a delay loop count. This saves data memory and code space.

SFRs, bits and volatile

A special function register (SFR) is declared with sfr and its byte address. For example, sfr P1 = 0x90; tells the compiler that the name P1 is the byte at address 0x90. A single pin is declared with sbit: sbit LED = P1^0; means bit 0 of P1. Most projects include a vendor header such as reg51.h instead of writing these lines by hand. The header also declares IE, IP, TMOD, SCON and SBUF.

Use bitwise operators to change selected bits without disturbing the rest. Set bits with OR: P1 = P1 | 0x09; sets bit 0 and bit 3. Clear bits with AND plus NOT: P1 = P1 & ~0x7F; clears bits 0 to 6 and leaves bit 7. Toggle bits with XOR: P2 = P2 ^ 0x04; flips bit 2. The symbol ~ is bitwise NOT; & is bitwise AND. Do not confuse & with logical &&.

A variable changed outside normal flow must be volatile. An interrupt service routine (ISR), a hardware register, or another task can change it between two reads. Without volatile, the compiler may keep the value in a register and never reload memory. Example: volatile unsigned char ticks; then ticks++; inside the Timer 0 ISR and if (ticks >= 10) in main.

  • sfr names a byte at an address.
  • sbit names one bit of an SFR or bit-addressable RAM.
  • volatile forces a fresh read from memory.
  • Use parentheses around mixed bitwise expressions.

Memory models and small programs

The 8051 has several data spaces, and the compiler must choose where variables go. The small model puts variables in internal RAM (data), which is fast but only about 128 bytes. The compact model uses one 256-byte page of external RAM (pdata), addressed through a pointer. The large model uses up to 64 KB of external RAM (xdata), which is slower and needs 16-bit pointers. Small and compact models are faster than the large model: small-model data is reached with direct and register addressing, and compact-model data uses 8-bit pointers into one page. The large model needs 16-bit pointers and external-memory (MOVX) cycles; keeping data out of xdata also leaves internal RAM free for the stack. The stack sits in internal RAM and grows upward; deep recursion or large local arrays can overflow it.

Port program: P1 = 0x0F; writes 0000 1111 to Port 1. To make P1.0 an input, set only that pin's latch to 1: P1 = P1 | 0x01; then read P1.0. Every pin must have latch 1 before it is used as an input; see 4.2. Timer 0 program in C: TMOD = 0x01; TH0 = 0xFC; TL0 = 0x18; TR0 = 1; while (!TF0); TF0 = 0; This uses mode 1, 16-bit timer, and waits for overflow. Serial program: SCON = 0x50; TMOD = 0x20; TH1 = 0xFD; TR1 = 1; SBUF = 'A'; while (!TI); TI = 0; This sets mode 1 UART with Timer 1 mode 2 baud rate. Interrupt program: volatile unsigned char ticks; void timer0_isr(void) interrupt 1 { TH0 = 0xFC; TL0 = 0x18; ticks++; } void main(void) { TMOD = 0x01; TH0 = 0xFC; TL0 = 0x18; ET0 = 1; EA = 1; TR0 = 1; while (1) { } } Mode 1 has no auto-reload, so the ISR must write TH0 and TL0 again for every 1000-count interval. The Timer 0 vector is 1 in C51; check your compiler header for exact syntax.

Exam traps

  • Do not assume int is 32 bits. On C51 int is usually 16 bits; a 32-bit value costs more code and time.

4.7 PIC and MSP430 microcontrollers

The PIC18F452 (Microchip) and MSP430 (Texas Instruments) are alternatives to the 8051. Both read a sensor, run a control loop and drive a pin, with different trade-offs. The PIC has an 8-bit data path and 16-bit instruction words in flash; its 8-bit data address forces 1536 bytes of RAM into banks selected by the BSR. The MSP430 has a 16-bit RISC core, 16 registers and named sleep modes.

You need Chapter 4.1 for the 8051 register and memory map, Chapter 4.6 for Embedded C, and Unit 1 for Harvard versus von Neumann and RISC versus CISC.

PIC18F452: an 8-bit Harvard machine

The PIC18F452 is Harvard-architecture: program and data memory use separate buses, so the CPU fetches the next instruction while reading or writing data. Flash is 32 KB = 32,768 bytes. Instructions are 16-bit words (a few use two words), so flash holds 32,768 ÷ 2 = 16,384 words. The data path is 8 bits: WREG holds one byte.

Data memory has 1536 bytes RAM plus 256 bytes EEPROM. An 8-bit address reaches 256 locations, so RAM is divided into banks of 256 bytes: 1536 ÷ 256 = 6 banks. The low four bits of the Bank Select Register (BSR) select the bank; only banks 0–5 exist. The access bank is a fixed window over part of bank 0 and bank 15 (special function registers), so it ignores BSR.

Key registers: WREG (accumulator), STATUS (carry, digit carry, zero, overflow, negative flags), BSR, and TRISA–TRISE (port direction). A 1 in a TRIS bit makes that pin an input; 0 makes it output. Code is C with XC8 or assembly in MPLAB X, loaded by in-circuit serial programming.

Tcy = 4 ÷ Fosc

Tcy is the instruction cycle time in seconds, Fosc the oscillator frequency in hertz, and 4 is the number of oscillator periods one instruction takes.

Bank switching and table reads

Bank switching is the cost of the small address field. The C compiler loads BSR before touching a banked variable and keeps hot variables in the access bank. Hand-written assembly must do the same; each switch costs an instruction.

Table reads fetch constants from flash. A seven-segment table lives in flash because flash is large and RAM small. TBLRD copies one byte from byte address TBLPTR into TABLAT; then a move brings it to WREG. Entry n starts at byte 2n, so add 2 for the next entry. The 8051 does this with MOVC A,@A+DPTR (Unit 3).

MSP430: 16-bit RISC and low power

The MSP430 is a 16-bit RISC microcontroller for battery-powered instruments. It has 16 registers R0–R15, each 16 bits. R0 is the program counter, R1 the stack pointer, R2 the status register (carry, zero, negative, overflow flags and interrupt-enable bits), and R3 a constant generator producing 0, 1, 2, 4, 8 or −1 without an operand field. R4–R15 are general purpose. Register-to-register instructions are one 16-bit word.

Peripherals are memory-mapped: timer, port, UART, SPI and I2C registers share the 16-bit address space with RAM, so ordinary moves and C pointers work on hardware registers.

The clock module saves power. A digitally controlled oscillator (DCO) starts in microseconds and can be switched off, so it costs little energy while the CPU sleeps. A 32.768 kHz watch crystal drives ACLK for the timer. Software selects the CPU clock MCLK and subsystem clock SMCLK. Low-power modes LPM0–LPM4 switch off parts of the clock tree: LPM0 stops only the CPU clock; LPM3 keeps ACLK and timer alive with DCO off; LPM4 stops everything. Any enabled interrupt returns to active mode. Tools: Code Composer Studio with Embedded C, or GCC.

The three families side by side

The differences are design choices. The 8051 and PIC18F452 are 8-bit; the MSP430 is 16-bit, so a 16-bit add handles two data bytes in one instruction and a pointer fits in one register. Banking is PIC-only: the 8051 has at most 256 bytes RAM, so a direct address always fits. The MSP430 has no separate SFR space. The MSP430 grades low power into LPM0–LPM4; the 8051 has Idle and Power-down; the PIC18 has Sleep. The MSP430 returns from LPM0 within a clock cycle and from LPM3 in microseconds because the DCO restarts.

Question. A PIC18F452 has 32 KB flash, 1536 B RAM, 16-bit instruction words, and 4 oscillator periods per instruction. The crystal is 10 MHz. Find (a) instruction words in flash, (b) 256-byte RAM banks, (c) instruction time.

  1. Flash = 32 × 1024 = 32,768 bytes.
  2. Words = 32,768 ÷ 2 = 16,384.
  3. Banks = 1536 ÷ 256 = 6.
  4. Tcy = 4 ÷ Fosc = 4 ÷ 10,000,000 Hz = 0.4 µs = 400 ns.

Answer. The flash holds 16,384 instruction words, the RAM is split into 6 banks, and one instruction takes 0.4 µs (400 ns).

Worked example 2

Question. An MSP430 draws 300 µA active at MCLK = 1 MHz and 1 µA in LPM3. A 32.768 kHz crystal wakes it for 100 µs every 10 ms. Find average current.

  1. Duty fraction = 100 µs ÷ 10,000 µs = 0.01.
  2. Sleep fraction = 0.99.
  3. Average = 0.01 × 300 µA + 0.99 × 1 µA = 3.99 µA.

Answer. The average current is about 3.99 µA, roughly 75 times less than running continuously at 300 µA.

Exam traps

  • PIC flash is counted in 16-bit words, not bytes: 32 KB = 16,384 words.
  • One PIC instruction takes 4 oscillator periods, so rate = Fosc ÷ 4. At 10 MHz, Tcy = 0.4 µs, not 0.1 µs.
  • In a PIC, TRIS = 1 makes an input. This differs from the 8051 rule of writing 1 before reading a pin.
  • MSP430 R0–R3 are not general purpose: PC, SP, status, constant generator.
  • MSP430 LPMs differ: LPM0 stops CPU clock; LPM4 stops all clocks and exits only by interrupt or reset.

Check yourself

Remember Name the register that selects the active RAM bank in the PIC18F452 and state how many banks the part implements. 2 marks

The Bank Select Register (BSR). Its low four bits hold the bank number; the part implements banks 0–5, that is six banks.

Understand Why does the PIC18F452 need bank switching when the 8051 does not? 3 marks

A PIC instruction carries only an 8-bit data address, reaching 256 locations, but the part has 1536 bytes RAM, so the BSR supplies a bank number. The 8051 has at most 256 bytes RAM, so one direct address covers it.

Apply A PIC18F452 runs from a 20 MHz crystal. Find the instruction cycle time Tcy. 3 marks

Tcy = 4 ÷ Fosc = 4 ÷ 20,000,000 Hz = 2 × 10⁻⁷ s = 0.2 µs = 200 ns.

Apply An MSP430 instruction word is 16 bits and the CPU has 16 registers. How many bits are left for opcode and other fields if a register is named by its number? 4 marks

16 registers need log₂ 16 = 4 bits. A register-to-register instruction names two, using 8 bits, leaving 8 bits. In the real encoding, 4 are opcode and 4 hold addressing-mode and byte/word bits.

Analyze Why does the MSP430 map peripherals into the same address space as RAM instead of giving them a separate SFR space? 5 marks

One address space means ordinary moves, bit and arithmetic instructions work on peripheral registers; no special I/O instructions are needed; C pointers can address hardware directly; and the compiler uses the same code for a variable and a timer register.

Analyze A coin-cell product must run for a year. Compare an MSP430 sleeping in LPM3 and waking for 100 µs every 10 ms at 300 µA with the same chip running continuously at 300 µA. 6 marks

The waking version is active for 100 µs ÷ 10,000 µs = 0.01 and sleeps at about 1 µA, giving 0.01 × 300 + 0.99 × 1 = 3.99 µA average. Continuous draws 300 µA, about 75 times more, so the sleeping design lasts about 75 times longer on the same cell.

Understand What does the PIC18F452 table read sequence do, and why is the table kept in flash? 3 marks

TBLRD copies a byte from the byte address in TBLPTR into TABLAT; a move then takes it to WREG. Flash holds the table because it is larger than RAM and the constants never change; add 2 to TBLPTR for the next entry.

Beyond the syllabus

Not for the exam. Modern parts keep the same programming model and add hardware the older syllabi do not cover: Microchip's PIC18-Q10 family puts configurable logic and an ADC with computation beside the CPU, and the MSP430FR series replaces flash with ferroelectric RAM, so writes cost less energy and survive power loss. Ultra-low-power design now competes with ARM Cortex-M0+ parts, which is why energy per operation, not clock speed, leads datasheets.

Takeaways

  1. The 8051 is a Harvard-architecture 8-bit microcontroller: code space, data space and the SFR map are separate, and most SFR addresses are fixed by the design.
  2. Every 8051 port is a latch plus a driver, so a pin used as input must first be written 1, and read-modify-write instructions act on the latch, not the pin.
  3. Timer/counter blocks count machine cycles or falling edges on T0/T1, and TMOD picks one of four modes, with mode 1 (16-bit) the usual choice for delays.
  4. The UART sends and receives bytes through the two halves of SBUF, Timer 1 supplies the baud clock, and RS-232 needs a MAX232-style level converter.
  5. Five sources share two external pins, two timers and one serial port; each has a fixed vector, IE enables it, IP prioritises it, and flags clear by hardware or software depending on the source.
  6. Embedded C keeps C syntax but adds SFR declarations, bit variables, volatile data and memory models so that code and data fit the small address space.
  7. PIC18F452 and MSP430 differ from the 8051 and from each other: PIC uses 16-bit instructions with banked 8-bit data, while MSP430 uses a 16-bit RISC core built for low power.
  8. Almost every long answer on this unit is a small program: pick the SFR settings, compute the count or baud value, then write the loop or ISR.

Remember and understand

Understand Draw the functional block diagram of the 8051 and explain each block: CPU, program memory, data memory, SFRs, ports, timers, serial port and interrupt unit. 13 marks

CPU is 8-bit with A, B, PSW, SP, PC and DPTR registers; 4 KB on-chip program memory, 128 bytes internal RAM, up to 64 KB external code and data; SFR map 80H–FFH controls ports, timers, UART and interrupts; Four 8-bit ports, two 16-bit timer/counters, full-duplex UART; Five interrupt sources with fixed vectors; Harvard split: code and data have separate spaces and buses.

Understand Explain the internal memory organization of the 8051, including register banks, the bit-addressable area, SFR space and external memory access. 13 marks

128 bytes RAM: bank 0–3 at 00H–1FH selected by RS1,RS0; Bit-addressable area 20H–2FH, 16 bytes = 128 bits; Scratch pad 30H–7FH used as stack and variables; SFR space 80H–FFH, only bit-addressable addresses 80H,88H,...,F8H; Stack grows upward from the value in SP; SP resets to 07H; EA=1 uses internal code memory up to 4 KB, then external; EA=0 all external; PSEN for code fetch, RD and WR for external data.

Understand Describe the 40-pin pin functions of the 8051, grouping pins by function. 12 marks

Port 0 (39–32): AD0–AD7 multiplexed address/data, needs external pull-ups; Port 1 (1–8): general purpose, also T2 in 8052; Port 2 (21–28): A8–A15 high address byte in external memory; Port 3 (10–17): INT0, INT1, T0, T1, WR, RD, TXD, RXD alternate functions; PSEN, ALE, EA, RST, XTAL1, XTAL2, Vcc, GND; RST is active high; two machine cycles needed for reset.

Understand Explain the TMOD register bit by bit and describe the four timer modes of the 8051. 12 marks

TMOD at 89H: GATE, C/T, M1, M0 for timer 1 in high nibble and timer 0 in low nibble; Mode 0: 13-bit, THx 8 bits + TLx 5 bits; Mode 1: 16-bit, max count 65536; Mode 2: 8-bit auto-reload, TLx counts and THx reloads; Mode 3: timer 0 splits into two 8-bit timers; timer 1 stops (used only for baud rate); GATE=1 makes INTx pin gate the run; C/T=1 counts T0/T1 falling edges.

Understand Explain the 8051 interrupt structure: sources, vector addresses, IE and IP registers, and the flag-clearing rule for each source. 13 marks

Five sources: INT0, Timer 0, INT1, Timer 1, serial; Vector addresses 0003H, 000BH, 0013H, 001BH, 0023H with the main program above 0030H; IE bits EA, ES, ET1, EX1, ET0, EX0; EA is the master switch; IP gives two levels; a high-priority source can interrupt a low-priority ISR; TF0/TF1 and IE0/IE1 (edge) cleared by hardware on entry; IE0/IE1 (level) follows the pin; TI and RI must be cleared by software in the ISR, else the interrupt repeats.

Apply

Apply Using a 12 MHz crystal, write assembly language and C programs to generate a 50 ms delay with Timer 0 in mode 1. Show the count calculation. 12 marks

Machine cycle = 12/12 MHz = 1 µs; 50 ms needs 50,000 machine cycles; 65536 − 50000 = 15536 = 3CB0H, so TH0 = 3CH, TL0 = B0H; TMOD = 01H; set TR0 = 1, wait for TF0 = 1, clear TF0; Assembly: MOV TMOD,#01H; MOV TH0,#3CH; MOV TL0,#0B0H; SETB TR0; JNB TF0,$; CLR TF0; C: TMOD=0x01; TH0=0x3C; TL0=0xB0; TR0=1; while(!TF0); TF0=0;; For longer delays repeat the loop and count with a register.

Apply Write embedded C for the 8051 that toggles an LED on port 1.0 in an external interrupt 0 service routine. Explain whether edge or level triggering should be chosen and how the flag behaves. 12 marks

Analyze and evaluate

Analyze Compare a microprocessor and a microcontroller on architecture, memory, I/O, instruction set and application, and justify which one suits a washing-machine controller. 13 marks

Microprocessor: CPU only, external RAM/ROM and I/O, general-purpose instruction set, high speed, high power; Microcontroller: CPU plus memory, timers, serial port and I/O on one chip, bit-manipulation instructions, low cost and power; List comparison table covering pins, clock, addressing, interrupts; Washing machine needs few inputs, timer delays, motor and valve outputs, cost and reliability matter; A microcontroller such as the 8051 removes external glue logic and is the right choice.

Evaluate A design needs a 1 s delay from an 8051 running at 12 MHz. Evaluate timer modes 1 and 2 for this job and calculate the reload values, including the error from crystal tolerance. 12 marks

Machine cycle 1 µs, so 1 s = 1,000,000 counts, beyond 65536; Mode 1: repeat 50 ms blocks 20 times, or use a nested software count; Mode 2 auto-reload is convenient only for short fixed periods up to 256 counts; Show the reload arithmetic and the number of repetitions; Crystal tolerance of a common crystal, roughly tens of ppm, gives timing error growing with delay; Better: use an interrupt-driven block so the CPU is free, or use a hardware real-time clock.

Evaluate Compare the 8051, PIC18F452 and MSP430 on architecture, data width, instruction width, memory banking and power, and choose one for a battery-powered sensor node that wakes once a minute. 13 marks

8051: 8-bit, Harvard, variable-length instructions, 128 bytes RAM, four register banks, no low-power modes; PIC18F452: 8-bit data, 16-bit instructions, banked data memory selected by BSR, 2 KB RAM, 32 KB flash, many peripherals; MSP430: 16-bit RISC, orthogonal registers, seven addressing modes, LPM0–LPM4 with fast wake on interrupt; Sensor node: long sleep, short active time, so sleep current dominates the energy budget; MSP430 wins on sleep current and 16-bit arithmetic; 8051 wins on cost and familiarity; PIC sits in between with rich peripherals and wide tool support.

Evaluate Explain why an RS-232 link needs a MAX232 between the 8051 and a PC, describe the connections, and evaluate the limits of the arrangement. 12 marks

8051 TXD gives TTL 0 V and 5 V; RS-232 uses about +3 V to +15 V for 0 and −3 V to −15 V for 1, inverted logic; MAX232 charge pumps make the required positive and negative rails from a single 5 V supply; TXD (P3.1) to T1IN, R1OUT to RXD (P3.0), T1OUT and R1IN to the DB9; Common ground, RTS/CTS optional; use the correct baud rate, 8 data bits, no parity, 1 stop bit; Limits: short cable length, modest baud rate, point-to-point only, no addressing or multi-drop; For a board-to-board link inside a product, plain TTL or RS-485 is usually preferred.

Glossary

Accumulator (A)
8-bit register at the centre of arithmetic, logic and data movement instructions.
Auto-reload
Mode 2 behaviour where the low byte counts and the high byte reloads it on every overflow.
Bit-addressable RAM
Bytes 20H–2FH whose 128 bits can each be set, cleared and tested by single instructions.
Bit-banging
Driving a protocol in software by toggling port pins, with no dedicated peripheral.
Cross compiler
A compiler that runs on a PC but produces machine code for the microcontroller.
In-circuit emulator
Hardware that runs and traces the microcontroller's program inside a real circuit for debugging.
Interrupt latency
Time from the flag being set to the first instruction of the ISR running; it includes finishing the current instruction.
Interrupt Service Routine (ISR)
Code placed at a vector address that runs in response to an interrupt and ends with RETI.
Memory model
Compiler option (small, compact, large) that fixes where variables are placed in the 8051 address space.
Microcontroller
A single chip containing a CPU, memory, timers, and I/O peripherals for embedded control.
Oscillator period
Time of one clock cycle fed to XTAL1 and XTAL2; the machine cycle is 12 such periods in the standard 8051.
Overflow flag (TF0, TF1)
Bit set by hardware when the timer counter rolls over from all 1s to 0.
Polling
Testing a flag repeatedly in software instead of using the interrupt mechanism.
Port latch
The flip-flop behind each port pin that stores the value the program wrote.
Prescaler
A divider placed before a counter so the counter sees a slower clock; the 8051 timer input is already divided by 12.
Program Counter (PC)
16-bit register holding the address of the next instruction byte to fetch.
Register bank
One of four groups of eight registers at 00H–1FH, selected by bits RS1 and RS0 in PSW.
RETI
Return-from-interrupt instruction that restores the PC and re-enables lower-priority interrupts.
SFR
Special Function Register: a memory-mapped control register in the 80H–FFH address range.
Simplex, half-duplex, full-duplex
One-way, either-direction-in-turn, and both-directions-at-once data flow; the 8051 UART is full-duplex.
Sink and source current
Current a pin accepts when pulled low and delivers when pulled high; 8051 pins sink much more than they source.
SMOD
Bit 7 of PCON at 87H; SMOD=1 doubles the serial baud rate in modes 1, 2 and 3.
Stack Pointer (SP)
8-bit SFR at 81H that holds the address of the last byte pushed; the 8051 stack lives in internal RAM.
Start and stop bits
Framing bits in an asynchronous frame: a 0 starts the frame and a 1 ends it.
Watchdog timer
A counter that resets the CPU if software fails to clear it within a set time.
