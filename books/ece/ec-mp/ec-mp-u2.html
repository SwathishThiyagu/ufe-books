2.1 8085 architecture, registers, flags and pin diagram

The 8085 is an 8-bit microprocessor. Inside, one 8-bit internal bus connects the ALU, accumulator, general registers, program counter, stack pointer, instruction decoder and control blocks. This single bus keeps the chip small and cheap, but it means only one byte moves at a time. The 40-pin package brings out a 16-bit address as two 8-bit halves and an 8-bit data bus that shares pins with the low address. Students meet it in lab kits, in old ticketing terminals and in every course that starts 8085 assembly.

You need: CPU, memory, buses and the stored-program idea from Unit 1, Foundations.

Internal blocks and the single bus

The 8085 is an 8-bit CPU. Every internal data transfer is 8 bits wide. The ALU does 8-bit arithmetic and logic. One ALU input comes from the accumulator (register A). The other comes from a temporary register that the programmer cannot name. The ALU writes its result back to A and sets the flag register. Some syllabi call this set of blocks the functional building blocks of the processor.

The programmer-visible registers are A, B, C, D, E, H and L. All are 8 bits. B-C, D-E and H-L can be used as three 16-bit pairs. The program counter (PC) is 16 bits and holds the address of the next instruction byte. The stack pointer (SP) is 16 bits and holds the top of the stack in memory.

The instruction register (IR) holds the opcode byte just fetched. The instruction decoder turns that opcode into control signals. Timing and control sequences the machine cycles and drives RD, WR, ALE and the status lines. Interrupt control handles the interrupt pins. Serial I/O control handles SID and SOD. The clock states inside each machine cycle are covered in 2.2.

Two buffers face the pins. The address buffer holds the high address byte A15-A8. The address/data buffer carries the low address byte AD7-AD0 in the first clock state, then carries data. Because address and data share pins, an external latch must hold the low address when ALE pulses.

Registers and flags

The accumulator A is the centre of arithmetic. Most 8-bit results land in A. The flag register is also 8 bits, but only five bits are defined: S, Z, AC, P and CY. The other three bits are unused. A flag bit changes only when an instruction affects that flag.

RegisterWidthJob
A8Accumulator: one ALU input and result
B, C, D, E, H, L8 eachGeneral registers; BC, DE, HL pairs
PC16Address of next instruction byte
SP16Top-of-stack address
Flag8S, Z, AC, P, CY
  • S (sign): copy of bit 7 of the result. S=1 means the result looks negative in two's complement.
  • Z (zero): Z=1 when all result bits are 0.
  • AC (auxiliary carry): carry from bit 3 to bit 4. The decimal-adjust instruction DAA uses it.
  • P (parity): even parity. P=1 when the result has an even number of 1 bits.
  • CY (carry): carry out of bit 7 in addition, or borrow in subtraction.

Not every instruction changes every flag. MOV changes no flags. INR does not change CY. The full instruction-by-instruction flag table belongs to Unit 3, Instruction Set and Assembly Programming.

The 40 pins that face the outside world

The 8085 comes in a 40-pin DIP. Pin 40 is Vcc (+5 V) and pin 20 is Vss (ground). Pins 1 and 2 are X1 and X2 for the crystal.

  • Pins 21-28: A15-A8, the high address byte, output.
  • Pins 12-19: AD7-AD0, multiplexed low address and data.
  • Pin 30: ALE (address latch enable). It goes high in T1; its falling edge latches AD7-AD0 into an external latch.
  • Pin 32: RD active low. Pin 31: WR active low.
  • Pin 34: IO/M. 0 selects memory; 1 selects I/O.
  • Pin 29: S0. Pin 33: S1. These status pins identify the bus cycle.
  • Pin 35: READY input. A low level inserts wait states.
  • Pin 39: HOLD input. Pin 38: HLDA output. This is the DMA handshake.
  • Pin 36: RESET IN. Pin 37: CLK OUT. Pin 3: RESET OUT resets peripherals.
  • Interrupt pins: TRAP pin 6, RST7.5 pin 7, RST6.5 pin 8, RST5.5 pin 9, INTR pin 10, INTA pin 11 active low.
  • Serial pins: SID pin 5 input, SOD pin 4 output.

A15-A8 and AD7-AD0 together form the 16-bit address. During T1 the low byte is an address; after ALE latches it, AD7-AD0 becomes the data bus. DMA and interrupt priority are expanded in Unit 5, Peripheral Interfacing.

Worked example

Question. The 8085 adds 9AH and 7CH. Give the accumulator content and the flag register bits S, Z, AC, P and CY.

  1. Write both bytes in binary: 9AH = 1001 1010, 7CH = 0111 1100.
  2. Add as 8-bit numbers: 1001 1010 + 0111 1100 = 1 0001 0110. The 9-bit sum has a carry out of bit 7, so CY = 1.
  3. Keep the low 8 bits: 0001 0110 = 16H = 22 decimal. This is the new accumulator content.
  4. S is bit 7 of 0001 0110. Bit 7 is 0, so S = 0.
  5. Z is 0 because 0001 0110 is not zero.
  6. AC uses the lower nibbles: A + C = 10 + 12 = 22 decimal = 16H. This is more than 0FH, so a carry passes from bit 3 to bit 4. AC = 1.
  7. P is even parity. The result 0001 0110 has three 1 bits (bits 4, 2 and 1), an odd count, so P = 0.
  8. The flag bits in order S Z AC P CY are 0 0 1 0 1.

Output

None

Answer. A = 16H = 22 decimal; S = 0, Z = 0, AC = 1, P = 0, CY = 1.

Exam traps

  • AC is the carry from bit 3 to bit 4, not the carry out of bit 7. CY is the carry out of bit 7.
  • 8085 parity is even parity: P = 1 only when the result has an even number of 1 bits. It is not odd parity.
  • AD7-AD0 is not a pure data bus. It carries the low address byte in T1. ALE and an external latch separate address from data.
  • IO/M = 1 selects I/O. Memory is selected when IO/M = 0.
  • A flag is not always updated. MOV changes no flags, and INR does not change CY.

2.2 Timing diagrams and machine cycles

Every 8085 instruction runs as a fixed pattern of clock periods on shared bus wires. The timing diagram draws those wires against time, so you can see when the address is valid, when ALE latches it, and when RD or WR moves data. Engineers use it to connect memory and I/O chips, to compute execution time and delays, and to debug a board with a logic analyser. This chapter defines the clock units, shows the five machine cycles, and counts T-states for MVI A, 32H.

You need: Chapter 2.1 for the 8085 registers and the names of its pins and control signals.

T-state, machine cycle, instruction cycle

A timing diagram plots bus signals against time. The 8085 sends addresses, data and control over shared wires, so the diagram records what each wire carries in each clock period.

A T-state is one period of the CPU clock. A 6 MHz crystal is divided by 2 inside the 8085, giving a 3 MHz CPU clock. One T-state is then 1 ÷ 3,000,000 s = 0.333 µs.

A machine cycle is a group of T-states that completes one bus operation. A memory read takes 3 T-states; a typical opcode fetch takes 4. An instruction cycle is the complete execution of one instruction and contains one or more machine cycles.

The diagram exists because AD7-AD0 is multiplexed. The same eight pins carry the low address byte early in the cycle and data later. ALE says when the address is present. RD or WR says which direction the data moves. A memory chip must obey this order, and a designer reads the diagram to check it.

f<sub>CPU</sub> = f<sub>crystal</sub> ÷ 2;  T = 1 ÷ f<sub>CPU</sub>;  execution time = (number of T-states) × T

fCPU is the CPU clock in hertz, fcrystal is the crystal frequency in hertz, T is one T-state in seconds, and execution time is in seconds.

The five machine cycles and their signals

All five cycles begin with T1 and ALE high. In a memory cycle the CPU puts the high address byte on A15-A8 and the low address byte on AD7-AD0. In an I/O cycle it puts the same 8-bit port address on both A15-A8 and AD7-AD0, and still raises ALE. ALE (address latch enable) is active high for one T-state. It clocks an external latch, usually a 74LS373, which holds the low address while AD7-AD0 later changes to data.

IO/M is low for a memory address and high for an I/O port. RD and WR are active low: the line drawn low is the one doing work.

  • Opcode fetch, 4 T. RD goes low in T2 and T3, the memory places the opcode on AD7-AD0, and the CPU samples it at the end of T3. In T4 the opcode moves to the instruction register and RD returns high.
  • Memory read, 3 T. Same shape, but data goes to a register, not the instruction register. RD is low in T2 and T3.
  • Memory write, 3 T. WR is low in T2 and T3, and the CPU drives data out on AD7-AD0. RD stays high.
  • I/O read, 3 T. IO/M is high, RD is low in T2 and T3. The 8-bit port address appears on both A15-A8 and AD7-AD0.
  • I/O write, 3 T. IO/M is high, WR is low in T2 and T3, and data goes out on AD7-AD0.

Read any diagram in this order: find the ALE pulses, mark where each machine cycle starts, then check RD, WR and IO/M inside that cycle.

Counting T-states for one-, two- and three-byte instructions

The number of bytes in an instruction suggests its memory accesses, but it does not fix the T-state count. Most one-byte instructions take 4 T, many two-byte instructions 7 T, and many three-byte instructions 10 T. The first byte is always an opcode fetch of 4 T. Each later byte is usually a memory read of 3 T.

InstructionBytesMachine cyclesT-states
NOP1OF4
MVI A, 32H2OF + MR7
LXI H, 2050H3OF + MR + MR10

Three corrections keep counts honest. (1) Some one-byte instructions take 6, 10 or 12 T for internal work or stack traffic with no operand fetch; use the datasheet value, not the byte rule. (2) An I/O instruction uses an I/O read or write cycle, still 3 T, with IO/M high. (3) Instructions that move data to or from memory or the stack add further machine cycles: LDA 2050H and STA 2050H are 13 T (OF + MR + MR + MR/MW) and CALL 2000H is 18 T (OF + MR + MR + MW + MW).

The figure traces MVI A, 32H. The first four T-states fetch opcode 3EH from 2000H. The next three read 32H from 2001H. ALE pulses in T1 of both cycles, RD is low in T2 and T3 of each cycle, and AD7-AD0 carries address, opcode, address and data in turn.

Worked example

Question. The 8085 instruction MVI A, 32H is stored at address 2000H. Draw the opcode fetch and memory read machine cycles and count the total T-states. A 6 MHz crystal drives the CPU. Find the execution time.

  1. MVI A, 32H is 2 bytes. Its opcode is 3EH at 2000H and its immediate byte is 32H at 2001H.
  2. Machine cycle 1, opcode fetch, 4 T. In T1, A15-A8 = 20H, AD7-AD0 = 00H, ALE = 1, IO/M = 0, RD = 1.
  3. In T2, ALE = 0 and RD = 0; AD7-AD0 becomes an input. In T3 the memory puts 3EH on AD7-AD0 and the CPU samples it.
  4. In T4 the opcode moves to the instruction register and RD returns high. The opcode fetch ends.
  5. Machine cycle 2, memory read, 3 T. In its T1, A15-A8 = 20H, AD7-AD0 = 01H, ALE = 1, RD = 1.
  6. In its T2, ALE = 0 and RD = 0; the memory drives 32H on AD7-AD0. In its T3, 32H is latched into A and RD returns high.
  7. Total T-states = 4 + 3 = 7 T.
  8. The crystal is 6 MHz, so fCPU = 6 ÷ 2 = 3 MHz. T = 1 ÷ 3,000,000 s = 0.333 µs.
  9. Execution time = 7 × 0.333 µs = 2.333 µs.

Answer. A = 32H; the instruction takes 7 T-states, which is 2.333 µs at a 3 MHz CPU clock.

Exam traps

  • ALE is high in T1 of every machine cycle, not only during an opcode fetch. RD goes low only in a read cycle, never in a write.
  • MVI A, data is 2 bytes, so it needs 4 + 3 = 7 T-states, not 4. The second byte is a memory read, not a second opcode fetch.
  • RD and WR are active low: a line drawn high is idle. Do not describe the low level as off or inactive.
  • IO/M high means an I/O port. The 8085 puts an 8-bit port address on both A15-A8 and AD7-AD0; it is not a 16-bit I/O address.
  • The opcode fetch takes 4 T because T4 transfers the opcode to the instruction register. A memory read needs only 3 T.

2.3 8086 architecture, registers and signal description

The 8085 fetches an instruction, then executes it, then fetches the next. The 8086 breaks that chain. One unit keeps talking to memory and fetching ahead; a second unit decodes and executes what was already fetched. Fetching and executing overlap, so a straight-line program finishes sooner than the clock alone suggests. This split is why an 8086 looks faster than an 8085 at the same crystal. Every later x86 chip, and so every PC and laptop you use, still carries these segment registers and the segment-base-plus-offset idea, though the address width grew: 20 bits on the 8086, 24 bits on the 80286, 32 bits on the 80386, and 64 bits in x86-64.

You need: Chapter 2.1 for the 8-bit baseline, and Unit 1 for buses, registers and the stored-program idea.

Bus interface unit and execution unit

The 8086 is a 16-bit microprocessor in a 40-pin package. Inside, it is two machines sharing one bus. The bus interface unit (BIU) owns everything that touches the outside world: address calculation, segment registers, the instruction pointer and the queue. The execution unit (EU) owns everything that touches an instruction: decoding, the ALU, the general registers and the flags.

  1. The EU needs the next opcode byte and takes it from the front of the instruction queue.
  2. If the queue is not full, the BIU forms an address from CS and IP, reads a byte or word from memory, writes it at the back of the queue, and advances IP.
  3. The EU decodes and executes from the queue, without using the address and data buses at all.
  4. While a slow instruction such as MUL runs, the BIU keeps fetching until all 6 queue bytes are filled.
  5. A jump, call, return or interrupt discards the queued bytes, because they belong to instructions that will never run. The BIU refills from the new address.

This is prefetching. The 8085 fetches and then executes, one after the other; the 8086 does both at once. The gain is free in straight-line code and is paid back at every branch, where the queue must be flushed and refilled.

The register set

All registers are 16 bits wide. The first four split into two usable bytes each, which is how 8-bit code works on a 16-bit machine.

FLAGS is 16 bits but only 9 are defined. Six are status flags: CF (carry out of the most significant bit — bit 15 of a word operation, bit 7 of a byte operation), PF (even parity of the low byte), AF (carry from bit 3, used by BCD adjust), ZF (result was zero), SF (copy of the sign bit) and OF (signed overflow). Three are control flags: TF (single-step), IF (allow maskable interrupts) and DF (string direction: 0 counts up, 1 counts down). Among the general registers only AX to DX can be used as 8-bit halves; SP, BP, SI and DI are always 16-bit. String use of SI and DI with CX is in Chapter 2.6.

Making a 20-bit address from 16-bit registers

A 16-bit register sees only 64 KB. The 8086 needs 1 MB, so it never stores a full address anywhere. It keeps a segment base and an offset, both 16-bit, and the address adder in the BIU combines them on every bus cycle.

physical address = segment × 10H + offset

segment is the value in CS, DS, SS or ES; offset is IP, a register, or a constant in the instruction; 10H is 16 decimal. Multiplying by 10H shifts the segment left by 4 bits, so every base ends in 0H.

  1. Write the segment value and append one hex digit 0 — the same as shifting left 4 bits, or multiplying by 16.
  2. Add the 16-bit offset.
  3. Keep the low 20 bits: 0H to FFFFFH. A carry out of bit 19 is dropped, so the address wraps at 1 MB.
  4. Pick the segment by the kind of access: CS with IP for an opcode fetch, SS with SP or BP for the stack, DS with BX, SI, DI or a constant for data, ES with DI for a string destination.

Because bases move in steps of 16 bytes, segments overlap and one physical byte has many names: 1000H:0020H and 1001H:0010H both mean 10020H. That overlap is useful — a small program can keep code, data and stack in separate 64 KB windows without wasting memory.

Signal groups of the 40-pin package

Learn the pins in seven groups. Each group answers one question the outside circuit asks.

  • Address and data: AD0–AD15 carry address bits A0–A15 in the first clock of a cycle and data D0–D15 afterwards, so they are multiplexed. A16/S3 to A19/S6 carry the top four address bits and then status.
  • Control: RD and WR are active-low read and write strobes; M/IO selects memory or I/O; DT/R sets data direction; DEN enables the data buffers; BHE (active low) selects the high byte lane; READY stretches the cycle for slow memory.
  • Status: ALE (address latch enable) goes high at the start of a cycle so an external latch can hold the address, and A16–A19 carry the status bits S3 to S6 for the rest of the cycle.
  • Interrupts: INTR is a maskable request, acknowledged by active-low INTA; NMI can not be masked; only INTR is controlled by IF.
  • DMA: HOLD asks the CPU to release the bus, and HLDA acknowledges it.
  • System: RESET starts the CPU from FFFF0H — it forces CS = FFFFH and IP = 0000H, so the first fetch is at FFFF0H. TEST is the pin checked by the WAIT instruction, and MN/MX chooses minimum or maximum mode (Chapter 2.4).
  • Clock and power: CLK from the 8284 generator, Vcc at +5 V, and GND.

Pins whose meaning changes with MN/MX are in Chapter 2.4, and the chip-select logic those address lines drive is in Chapter 2.5.

Worked example

Question. The 8086 has CS = 1234H and IP = 0056H. Find the 20-bit physical address of the next instruction byte.

  1. Segment base = CS × 10H = 1234H × 10H = 12340H. This is a 4-bit left shift, so one hex 0 is appended.
  2. Offset = IP = 0056H.
  3. Add: 12340H + 0056H = 12396H.
  4. The value 12396H is 20 bits (below FFFFFH), so there is no wrap.
  5. In decimal the base is 74560 and the physical address is 74646.

Answer. The physical address is 12396H, that is 74646 in decimal, and the byte fetched from it is the next opcode byte.

Exam traps

  • Using decimal 10 instead of 10H. 1234H × 10H = 12340H. Multiplying by 10 decimal instead gives 1234H × 10 = 46600 = B608H, a different and wrong physical address.
  • Pairing the wrong segment. Opcode fetch is always CS with IP; a push or pop is always SS with SP. DS:IP does not exist.
  • Trying MOV IP, 1234H. IP cannot be loaded by a data-transfer instruction; only JMP, CALL, RET and interrupts change it.
  • Saying the queue holds six instructions. It holds six bytes, and one instruction is 1 to 6 bytes long.
  • Assuming the address stays on AD0–AD15 for the whole bus cycle. Those pins become the data bus after T1, so a latch driven by ALE is required.

Fetching is done by the BIU and execution by the EU, so the two run at the same time. The EU does not wait for memory as long as the queue is not empty; that overlap hides memory access time in straight-line code.

Apply DS = 2000H and an instruction uses the offset 1234H. Give the physical address. 3 marks

Understand Which registers sit in the BIU and which in the EU? 3 marks

BIU: CS, DS, SS, ES, IP, the address adder and the 6-byte queue. EU: AX, BX, CX, DX, SP, BP, SI, DI, the ALU and FLAGS.

Analyze A JMP is taken. Explain what happens to the queue and why the branch costs extra time. 4 marks

The bytes already queued belong to instructions that will not run. The BIU throws them away, loads IP (and also CS, if it is a far jump) from the jump target, and refills from the new address. During the refill the EU has nothing to decode, so the branch costs the refill time.

Analyze CS = FFFFH and IP = 0010H. Find the physical address and explain the wrap. 4 marks

Base = FFFF0H. FFFF0H + 0010H = 100000H, which is 21 bits. Dropping the carry out of bit 19 gives 00000H, so the fetch goes to the bottom of memory. This is why the reset vector sits at FFFF0H and must contain a jump.

Remember Which signal tells an external latch that a valid address is on AD0–AD15? 2 marks

ALE, the address latch enable. It goes high in T1, and the latch driven by it grabs the address on the falling edge.

Beyond the syllabus

Not for the exam. The segmented model still lives inside every 64-bit PC: x86-64 kept FS and GS as segment bases, and an operating system uses FS to reach a thread's own data in one instruction. Emulators and retro-computing cores model the six-byte prefetch queue cycle by cycle so that old timing-sensitive code still runs. 2.4 8086 pins; minimum and maximum mode systems

The 8086 has one mode pin, MN/MX. Tie it high and the CPU drives the system control bus itself; tie it low and the CPU hands status to an external 8288 bus controller. This choice decides whether a board is a small single-processor system or a larger system with bus masters and coprocessors. The same address latches and data transceivers are used in both modes. The mode changes which pins carry ALE, DEN, DT/R, RD and WR, so read every pin name together with its mode.

You need: Chapter 2.3 for 8086 signals and the BIU, and Chapter 2.2 for T-states and bus timing.

One pin selects the control source

MN/MX is pin 33. A high level (+5 V) selects minimum mode. A low level (0 V) selects maximum mode. The pin does not change the instruction set or registers. It changes the control pins on the right side of the chip.

In minimum mode the 8086 itself drives the control bus. It produces RD, WR, M/IO, ALE, DEN, DT/R and INTA. It accepts HOLD and returns HLDA. One processor owns the bus, so no bus controller is needed.

In maximum mode the same pins carry different signals. The 8086 sends status S2, S1, S0, queue status QS1, QS0, LOCK, RQ/GT1 and RQ/GT0. It does not drive RD or WR. An external 8288 bus controller decodes S2-S0 into memory and I/O commands. The 8288 also produces ALE, DEN and DT/R. Maximum mode exists for systems with a coprocessor, a DMA controller, or more than one bus master. Minimum mode is cheaper for a small single-processor board.

Minimum mode system

Tie MN/MX to +5 V. The 8284 clock generator supplies CLK, READY and RESET to the 8086. A crystal connects to the 8284; it divides the crystal frequency and gives a clean clock. READY inserts wait states for slow memory. RESET starts the CPU.

The address bus needs latches. AD0-AD15 carry both address bits A0-A15 and data bits D0-D15. A16-A19 share pins with status S3-S6. ALE is high at the start of a bus cycle. An 8282 latch (two chips for the 16 lower address bits, one for A16-A19 and BHE) stores the address on the falling edge of ALE. The address stays stable while the same pins carry data later in the cycle. See Chapter 2.2 for the T-states.

The data bus needs a transceiver. Two 8286 chips buffer D0-D15. DEN enables the buffer. DT/R sets direction: high for transmit (CPU to memory), low for receive (memory to CPU). The 8086 drives M/IO to select memory or I/O, and RD or WR to set the direction of the transfer. Memory and I/O chips connect to the latched address, the buffered data bus, and these control lines.

HOLD and HLDA allow bus sharing. A DMA controller raises HOLD. The 8086 floats its buses and raises HLDA. The DMA controller then uses the bus. Minimum mode is used in small trainer kits and simple single-board systems.

Maximum mode system and status decoding

Tie MN/MX to 0 V. The 8086 sends S2-S0 to the 8288. The 8288 decodes the three bits into active-low bus commands. It also uses CLK and AEN; AEN can force the command outputs to a known state when another master owns the bus.

S2 S1 S08288 output and operation

The 8288 produces MRDC, MWTC, IORC, IOWC, INTA and AMWC. It also produces ALE, DEN and DT/R for the 8282 latches and 8286 transceivers. The address and data path is the same as in minimum mode; only the source of control changes.

Queue status QS1-QS0 tells what the BIU is doing: no operation, first byte of the queue, empty queue, or later byte. LOCK prevents another bus master from taking the bus during a locked instruction. RQ/GT0 and RQ/GT1 let another master request and receive the bus. Maximum mode is used with the 8087 numeric coprocessor, the 8089 I/O processor, and multiprocessor boards.

Choosing the mode

Some syllabi call these “min mode system configuration” and “max mode system configuration”. The choice is wiring, not software: the same 8086 runs the same instructions in either mode.

A small board with one CPU and ordinary memory uses minimum mode: fewer chips, direct control, lower cost. A board with a coprocessor, a DMA controller that must become bus master, or two processors uses maximum mode: the 8288 gives standard commands and the RQ/GT pins arbitrate the bus. A common exam mistake is to place an 8288 on a minimum-mode board or to look for RD and WR from the 8086 in maximum mode.

Worked example

Question. In a maximum-mode 8086 system the status lines are S2 S1 S0 = 101. Which 8288 output is active, and what bus operation does it perform?

  1. MN/MX is low, so the 8086 is in maximum mode. It drives status bits S2, S1 and S0 to the 8288 bus controller.
  2. Read the bits in the order S2 S1 S0: S2 = 1, S1 = 0, S0 = 1. The status code is binary 101, which is decimal 5.
  3. In the 8288 status table, code 101 means a memory read. The 8288 asserts its MRDC (active-low memory read command) output.
  4. The address comes from the 8282 latches, and the memory places data on D0-D15 for the 8086 to read.

Answer. MRDC (active low) is active, so the 8288 performs a memory read; the status code is decimal 5.

Exam traps

  • Learning pin names without the mode. ALE, DEN and DT/R are minimum-mode names; in maximum mode the same pins carry queue status and S2-S0, and the 8288 produces the control signals.
  • Thinking the 8288 generates the clock. The 8284 generates CLK, READY and RESET; the 8288 decodes S2-S0 into bus commands.
  • Connecting an 8288 in minimum mode or expecting RD and WR from the 8086 in maximum mode. Read the MN/MX level first, then choose the control source.
  • Reversing the status order. S2 S1 S0 = 101 is a memory read (MRDC); S2 S1 S0 = 110 is a memory write (MWTC).
  • Confusing the 8282 latch with the 8286 transceiver. The 8282 holds the address; the 8286 buffers the data and uses DEN and DT/R.

Check yourself

Remember What does the MN/MX pin of the 8086 select? 2 marks

It selects minimum mode when high (+5 V) and maximum mode when low (0 V).

Understand Why does a maximum-mode 8086 system need an 8288 bus controller? 3 marks

In maximum mode the 8086 does not drive RD and WR directly. It sends status S2-S0, and the 8288 decodes those bits into MRDC, MWTC, IORC, IOWC and INTA. The 8288 also gives ALE, DEN and DT/R for the latches and transceivers.

Apply A maximum-mode 8086 sends S2 S1 S0 = 110. Which 8288 output is active, and what operation is performed? 3 marks

Code 110 means memory write. The 8288 asserts MWTC (active low), so data is written from the 8086 to memory.

Analyze A student ties MN/MX high and also connects an 8288 to the 8086. Explain why this board will not work as intended. 4 marks

MN/MX high selects minimum mode. In minimum mode the 8086 pins carry ALE, DEN, DT/R, RD and WR, not the status S2-S0 and queue status that the 8288 needs. The 8288 therefore gets no valid status and its control outputs are wrong. The 8288 belongs only in maximum mode.

Remember Name two control signals produced by the 8086 in minimum mode but not produced by the 8086 in maximum mode. 2 marks

Any two of RD, WR, M/IO, ALE, DEN, DT/R and INTA. In maximum mode these functions move to the 8288 or become status signals.

Apply In a minimum-mode 8086 system, a DMA controller raises HOLD. What does the 8086 do? 3 marks

The 8086 finishes its current bus cycle, floats its address, data and control buses, and raises HLDA. The DMA controller can then use the bus.

Analyze Why are 8282 latches needed when the 8086 already has address pins? 4 marks

AD0-AD15 carry address and data at different times, and A16-A19 share pins with status. The address is valid only early in the bus cycle. ALE stores it in the 8282 latch so memory and I/O see a stable address while the same pins carry data later.

Understand What are S2, S1 and S0 in a maximum-mode 8086 system? 2 marks

They are the three status bits that tell the 8288 what bus operation the 8086 wants: interrupt acknowledge, I/O read, I/O write, halt, instruction fetch, memory read, memory write, or passive.

Beyond the syllabus

Not for the exam. Modern x86 chips integrate the bus controller and memory controller on the same die, so the 8288 is a museum part. The idea survives as a bus bridge or memory controller that decodes a request type into read and write strobes. Bus arbitration appears today in AMBA AHB/APB and PCIe root complexes. Search “8086 maximum mode 8288 timing” and “bus arbiter RQ/GT” to go deeper.

2.5 Memory interfacing and address decoding

A memory chip holds many bytes, but it has only a few address pins. The CPU must pick one chip and then one byte inside it. Address decoding does that job. The high address lines are compared with a chosen base address. A decoder turns that match into a chip-select signal. The low lines go to the chip's address pins. This lets a 2K chip sit at 0000H and a RAM sit at 2000H without fighting on the bus. Every 8085 and 8086 system uses this idea.

You need: Chapter 2.1 for the 8085 address, data and control buses and Chapter 2.2 for memory read and write machine cycles.

Memory map, chip select and address lines

A memory map is the list of address ranges given to each chip. The 8085 puts a 16-bit address on A15-A0, so it can name 2^16 = 65536 bytes. The 8086 uses 20 lines A19-A0 and names 2^20 = 1048576 bytes. Each chip gets a base address, the first address in its range. It also gets a size, the number of bytes it holds. The chip-select pin, usually written CS with a bar over it, is active low: 0 V selects the chip. All other chips keep their data pins in high impedance.

size = 2^n; end = base + size − 1

size is the number of bytes in the chip; n is the number of address lines wired to the chip; base is the first address; end is the last address.

A 2K × 8 chip has 2048 bytes and needs 11 address lines, because 2^11 = 2048. The low 11 lines A10-A0 go to the chip. The upper lines A15-A11 decide whether this chip is selected. For a ROM at 0000H, A15-A11 must be 00000. For a RAM at 2000H, A15-A11 must be 00100. The range of the ROM is 0000H to 07FFH. The range of the RAM is 2000H to 27FFH. The H suffix means hexadecimal.

Decoding with gates and the 74LS138

A simple decoder is a NAND gate. Its inputs are the high address lines, some inverted. Its output is active-low CS: it goes to 0 only when the address matches the base pattern. An AND gate with an inverter on its output does the same job. A 3-to-8 decoder saves gates. The 74LS138 takes three select inputs A, B, C and produces eight active-low outputs Y0-Y7. C is the most significant select input. It has enable pins: G1 active high, G2A and G2B active low. When enabled, the binary code on CBA selects one Y output low. For the two chips here, wire A13 to A, A14 to B, A15 to C. Tie A12 to G2A and A11 to G2B. Tie G1 high. ROM code 000 gives Y0; RAM code 001 gives Y1.

  • Full decoding uses every unused high address line. Each byte has one address. The map has no holes or copies.
  • Partial decoding leaves some high lines unconnected. The same chip appears at many addresses. This is called foldback or mirroring. It is cheaper but wastes address space.
  • In an 8086 system the memory is two byte banks. BHE low selects the high bank and A0 low selects the low bank. The decoder still compares the high address lines with the base address. A 2K chip still needs 11 address lines.

Interfacing a ROM and a RAM to the 8085

  1. Connect A10-A0 of the 8085 to A10-A0 of both the 2K EPROM and the 2K RAM. These lines choose the byte inside each chip.
  2. Connect D7-D0 of the 8085 to D7-D0 of both chips. Only the selected chip drives the data bus.
  3. Decode A15-A11. Use a 74LS138 or gates to make ROM CS low for 0000H-07FFH and RAM CS low for 2000H-27FFH.
  4. Make a memory-read signal MEMR = RD OR IO/M. MEMR is low only when RD is low and IO/M is low. Connect MEMR to the ROM OE and the RAM OE. In the same way make MEMW = WR OR IO/M and connect it to the RAM WE. OE and WE are active low. The EPROM has no write enable.
  5. At reset the 8085 starts at 0000H. It fetches the first instruction from the EPROM. The RAM at 2000H is free for variables and stack.

Worked example

Question. Interface a 2K × 8 EPROM and a 2K × 8 RAM to an 8085. The EPROM starts at 0000H and the RAM starts at 2000H. Give the address range of each chip and the number of address lines each chip needs.

  1. Size of each chip = 2K × 8 = 2048 bytes × 8 bits.
  2. Number of address lines n: 2^n = 2048, so n = log₂(2048) = 11. Each chip needs A10-A0, that is 11 address lines.
  3. ROM base = 0000H. End = 0000H + 2048 − 1 = 0000H + 07FFH = 07FFH. ROM range = 0000H-07FFH. In decimal: 0 to 2047.
  4. RAM base = 2000H. End = 2000H + 2048 − 1 = 2000H + 07FFH = 27FFH. RAM range = 2000H-27FFH. In decimal: 8192 to 10239.
  5. Chip-select condition: ROM CS is low when A15-A11 = 00000. RAM CS is low when A15-A11 = 00100. A12 and A11 must be 0 for both; A13 separates the two chips.

Answer. Each chip holds 2048 bytes and needs 11 address lines; the EPROM covers 0000H-07FFH (0-2047 decimal) and the RAM covers 2000H-27FFH (8192-10239 decimal).

Exam traps

  • A 2K chip needs 11 address lines, not 10. 2K = 2048 = 2^11.
  • The end address is base + size − 1. For a 2K chip starting at 2000H, the end is 27FFH, not 2800H.
  • H means hexadecimal, not a variable. 2000H is 8192 decimal.
  • Active-low CS is selected by logic 0. A high on CS deselects the chip.
  • Partial decoding gives mirror addresses; full decoding does not. The examiner often asks which lines must match.

2.6 8086 string and control transfer instructions

String instructions process a block byte by byte using SI, DI and CX. Control transfer instructions change IP, or CS and IP. A hand-written copy loop is long and slow, so REP with the direction flag lets one instruction copy, compare, scan, load or store a block. Jumps, calls, returns, loops and interrupts steer the program; CALL and RET use the stack to save return addresses. These instructions appear in memory copy, display buffers, serial buffers and delay loops. Only a few universities teach string instructions separately; some syllabi group these under advanced instructions.

You need Chapter 2.3 for 8086 registers and flags, and Unit 3 for addressing modes and the stack.

String instructions and the direction flag

String instructions treat memory as a block. The source address is DS:SI: DS is the data segment base and SI is the source index. The destination address is ES:DI: ES is the extra segment base and DI is the destination index. CX holds the count. DF, the direction flag, picks the step: DF = 0 means SI and DI increase after each byte or word; DF = 1 means they decrease. MOVS copies: MOVSB moves one byte from [SI] to [DI], MOVSW moves one word. CMPS compares the byte or word at [DS:SI] with the one at [ES:DI] and sets the flags as if the source were subtracted from the destination; SCAS compares AL or AX with [ES:DI] and sets the flags the same way. LODS loads AL or AX from [SI]. STOS stores AL or AX to [DI]. REP repeats while CX ≠ 0 and decrements CX after each move. REPE and REPNE repeat CMPS or SCAS while ZF is 1 or 0, and stop early when the condition fails or CX reaches zero. They are used for block copy, screen buffers and serial receive buffers.

Control transfer: jumps, calls and returns

Control transfer instructions change the instruction pointer. A near JMP loads IP only; a far JMP loads CS and IP. Conditional jumps read flags: JZ tests ZF = 1, JNZ ZF = 0, JC CF = 1, JNC CF = 0, JS and JNS test SF, JO and JNO test OF. Unsigned comparisons use JA and JB; signed comparisons use JG and JL. LOOP decrements CX and jumps if CX ≠ 0; LOOPE and LOOPNE also test ZF. CALL saves a return address on the stack. A near CALL pushes IP, so SP = SP − 2. A far CALL pushes CS, then IP, so SP = SP − 4. RET pops IP for a near return; RETF pops IP and CS. The stack grows down, so every push lowers SP. INT n pushes FLAGS, clears IF and TF, pushes CS, pushes IP, then loads CS:IP from the interrupt vector table at address n × 4. IRET reverses this and restores flags. A delay loop uses a count register with LOOP or DEC/JNZ.

Worked example

Question. A string of 5 bytes starts at DS:SI = 2000H:0100H. Assume ES = 2000H, DI = 3000H, CX = 0005H and DF = 0. Give the physical addresses of the source and destination, and the values of SI, DI and CX after one MOVSB.

  1. Source physical address = DS × 10H + SI = 2000H × 10H + 0100H = 20000H + 0100H = 20100H = 131328.
  2. Destination physical address = ES × 10H + DI = 2000H × 10H + 3000H = 20000H + 3000H = 23000H = 143360.
  3. MOVSB copies one byte from [DS:SI] to [ES:DI], then updates the pointers according to DF.
  4. DF = 0, so SI and DI increase: SI = 0100H + 1 = 0101H = 257; DI = 3000H + 1 = 3001H = 12289.
  5. CX counts down after the move: CX = 0005H − 1 = 0004H = 4.

Answer. Source = 20100H (131328), destination = 23000H (143360), SI = 0101H (257), DI = 3001H (12289), CX = 0004H (4).

Exam traps

  • MOVS destination is always ES:DI, not DS:DI. If ES is not given, the destination physical address cannot be found; many questions set ES = DS.
  • DF = 0 increments SI and DI; DF = 1 decrements them. Reversing this changes every address after the first byte.
  • CX decrements after the move, so after one byte it is count − 1, not count. REP tests CX at the start of each repeat.
  • A near CALL pushes only IP (2 bytes); a far CALL pushes CS and IP (4 bytes). A matching RET or RETF must be used.

Check yourself

Remember Which registers hold the source and destination addresses in MOVSB? 2 marks

Source is DS:SI; destination is ES:DI.

The repeat is handled by the processor, so one instruction replaces the move, pointer update, compare and jump sequence.

DF = 1, so SI = 01FFH, DI = 03FFH; CX = 0002H.

Analyze A near CALL executes at CS:IP = 1000H:0200H and pushes a return address. What is on the stack and how does SP change? 4 marks

SP = SP − 2, and the word at the new [SP] holds the return offset 0203H (the near CALL at 0200H is 3 bytes long); CS is not pushed, so execution returns to 1000H:0203H.

Apply A loop body is between label L and LOOP L. CX = 0002H at entry. How many times does the body run? 3 marks

Two times. The first LOOP makes CX = 1 and jumps; the second makes CX = 0 and falls through.

Understand When does REPE CMPS stop before CX reaches zero? 3 marks

It stops when ZF = 0, because REPE continues while equal (ZF = 1).

Beyond the syllabus

Not for the exam. Modern x86 processors still keep string instructions, but fast block moves often use wider loads, DMA or library routines. Operating systems use REP MOVSB for small copies and switch to other methods for large ones. The 8086 segment pair DS:SI and ES:DI still appears in x86 memory models and emulators. Search for ERMSB, REP MOVSB performance, and x86 interrupt vector table.

Takeaways

  1. The 8085 keeps every internal transfer on one 8-bit bus, so registers, ALU and flags are all wired through that single path.
  2. AD0–AD7 carry the low address byte and then data on the same eight pins, which is why an external latch is always needed.
  3. Each 8085 machine cycle has a fixed T-state count: opcode fetch 4 T, memory read 3 T, memory write 3 T, I/O read 3 T, I/O write 3 T.
  4. A timing diagram is read left to right, one T-state at a time; every line shows whether it is a valid address, valid data or a control pulse.
  5. The 8086 splits into a BIU and an EU so that fetching the next instruction overlaps with executing the current one.
  6. Physical address in the 8086 is segment × 16 + offset, which is how 20 address bits come out of 16-bit registers.
  7. Pin 33 (MN/MX) alone decides whether the 8086 generates its own bus control signals or hands status to the 8288.
  8. In both processors a memory chip works only when its chip-select input is active, so address decoding defines the whole memory map.
  9. String instructions with the REP prefix move or compare whole blocks using only SI, DI, CX and the direction flag.

8284 divides the crystal by 3 to give CLK and synchronises RESET and READY; Latches hold A0–A19 from the multiplexed AD0–AD15 and A16/S3–A19/S6 lines at the ALE pulse; 8286 transceivers buffer the data bus, direction set by DT/R and enabled by DEN; Control signals RD, WR, M/IO generated directly by the processor in minimum mode; Fully labelled diagram with pin names.

Apply An 8 KB memory chip is connected so that it responds to addresses 8000H to 9FFFH. Identify the base address, the number of address lines needed and the chip-select condition. 8 marks

8 KB = 8192 bytes = 2^13, so 13 address lines A0–A12 go to the chip; Base address 8000H in binary; A15 to A13 must be 100 for the chip to be selected; Chip select = A15 · A14′ · A13 with an active-low output; Range check: 8000H + 1FFFH = 9FFFH, matching the given range.

Analyze and evaluate

Analyze Compare the 8085 and the 8086 with respect to data bus, address bus, register width, instruction pipelining, memory capacity and interrupt structure. 13 marks

8-bit versus 16-bit data bus; 16 versus 20 address lines; 64 KB memory space versus 1 MB, and the segment-plus-offset scheme; 8085 is sequential; 8086 has a BIU and a 6-byte queue giving overlap; Flag and register sets compared; segment registers exist only in the 8086; Interrupt handling: 8085 has 5 hardware interrupts and 8 RST vectors, 8086 has a 256-entry vector table; Conclusion: a fair judgement of which suits small control tasks and which suits larger programs.

Analyze Explain why the 8086 multiplexes address and data on AD0–AD15. Show how latches solve the problem and what goes wrong if the latch is removed. 13 marks

44-pin package limits the number of pins available; During T1 the lines carry address; ALE marks the valid address time; During T2 and T3 the same lines are used for data; 8282 latch clocked by ALE stores the address for the whole bus cycle; Without the latch, memory would see the address change mid-cycle and read or write the wrong location; Also mention A16/S3 to A19/S6 which carry status bits instead of data.

Evaluate Compare full address decoding with partial decoding in a microprocessor-based system. State which one you would choose for a small 8085 instrument and why. 13 marks

Full decoding uses all unused address lines, so every address selects exactly one device; Partial decoding ignores some lines, so the device appears at many mirror addresses; Effect on memory map, on future expansion and on the cost of the decoder gates; I/O map and the IO/M signal decide whether the address is memory or port space; Recommendation with reason: full decoding for a clean map, partial decoding only where the address space is fixed and cheap; Mention the risk of two devices answering the same address if decoding is careless.

Glossary

Accumulator
The register that holds one operand and receives the result in most arithmetic and logical instructions.
ALE
Address latch enable; a pulse in T1 of the 8085 that tells external latches to capture the low address byte.
ALU
Arithmetic and logic unit; the block that adds, subtracts, ANDs, ORs, rotates and compares.
Bus interface unit
The 8086 unit that drives the buses, computes physical addresses and prefetches instructions.
Chip select
An input that enables a memory or I/O chip only when the address belongs to that chip.
Decoder
A logic block that turns a group of address bits into separate active outputs, one per device.
DMA
Direct memory access; a controller such as the 8237 moves data to or from memory without the CPU handling each byte.
Execution unit
The 8086 unit that decodes and executes the instructions supplied from the queue.
Flag
A single flip-flop that records one property of the last result, such as zero, carry or parity.
Instruction cycle
The complete sequence of fetching, decoding and executing one instruction.
Instruction queue
A 6-byte first-in-first-out store of prefetched instruction bytes in the 8086.
Interrupt vector
The address the CPU jumps to when a particular interrupt is accepted.
Machine cycle
A group of T-states that completes one bus operation.
Maximum mode
8086 configuration in which status lines are decoded by the 8288 to produce bus control signals.
Microprocessor
A single chip containing the CPU, with no built-in memory or I/O peripherals.
Minimum mode
8086 configuration in which the processor generates all its own bus control signals.
Multiplexed bus
A bus that carries two different things, such as address and data, on the same pins at different times.
Opcode
The part of an instruction byte that tells the CPU which operation to perform.
Physical address
The 20-bit address placed on the bus, computed as segment × 16 + offset.
Segment register
One of CS, DS, SS or ES; it holds the starting paragraph of a 64 KB segment.
String instruction
An instruction such as MOVSB or CMPSB that works on a block of bytes or words through SI and DI.
T-state
One clock period of the processor; timing diagrams are drawn in T-states.
Wait state
An extra T-state inserted when slow memory pulls READY low, stretching the machine cycle.
