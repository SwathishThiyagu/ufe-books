3.1 GPIO and I/O ports

A GPIO pin is a digital line that software can set high or low, or read as high or low. It exists because an MCU must talk to LEDs, switches, relays and other chips without a dedicated peripheral for each one. A port is a group of pins, usually 8, controlled by registers in the memory map. You write a direction register to choose input or output, a data register to drive outputs, and read a pin register to sense inputs. Phones, washing machines and IRCTC display boards use GPIO for buttons, lamps and buzzers.

You need: Unit 1 hardware basics and Unit 2 register maps, especially memory-mapped I/O.

Pin, port and registers

A pin is one metal pad on the chip package. A port is a group of pins, often 8, that share register addresses. On an 8-bit port, one register bit controls or reports one pin. Bit 0 is the least significant bit, with weight 1; bit 7 has weight 128.

Three registers matter. The direction register (DDR) chooses input or output for each pin. On many MCUs a 1 in DDR means output and 0 means input; some parts invert this, so check the datasheet. The output data register (PORT) holds the value to drive when a pin is an output. The input read register (PIN) reports the voltage on the pad.

An input pin is high-Z, or high impedance: it does not drive the line. A pull-up resistor to supply or a pull-down resistor to ground gives a known level when nothing else drives the pin. Without one, a floating input picks up noise.

Driving, reading and masking bits

A push-pull output uses two transistors to drive the pin actively high and actively low. An open-drain output only pulls low; it needs an external pull-up resistor to return high. Open-drain is used for shared wires such as I2C (see Unit 4, SPI and I2C buses).

Software changes one bit without disturbing others by bit masking. For pin n, mask = 1 << n. In C, PORT |= mask sets the bit high, PORT &= ~mask clears it low, PORT ^= mask toggles it, and (PIN & mask) tests it. Here << is left shift, | is bitwise OR, & is bitwise AND, ^ is bitwise XOR, and ~ is bitwise NOT.

mask = 1 << n

n is the pin number, 0 for the least significant bit; mask has one bit set at position n.

A read-modify-write statement reads the whole register, changes one bit, and writes the whole register back. On a mixed-direction port, the read may return pin levels for input bits. The write can copy those levels into the output latch, or enable pull-ups, depending on the MCU. Keep a shadow copy of the output value and write only the bits you own, or use set/clear registers if the MCU provides them.

  1. Set or clear the pin's DDR bit for output or input.
  2. For output, write the pin's PORT bit to the level you want.
  3. For input, enable a pull-up or pull-down if needed, then read the pin's PIN bit.

Mixed-direction ports

A port can split: low bits output, high bits input. The DDR value tells you which is which. On an 8-bit port with 1=output, DDR=0x0F makes bits 0-3 outputs and bits 4-7 inputs. 0x0F is 0b0000 1111.

A write to PORT only drives pins whose DDR bit is output. Input bits have no output driver, so their PORT bits do not set the pad voltage. On some MCUs those same PORT bits enable pull-ups for inputs, which is a different function; read the datasheet before assuming a write is harmless.

The safe pattern is: build the output byte from the bits you want high, AND it with the output mask from DDR, and write the result. For DDR=0x0F the output mask is 0x0F. A requested value of 0x25 (bits 0, 2 and 5) becomes 0x25 & 0x0F = 0x05, so bit 5 is dropped because it is an input. The worked example below applies this rule.

Worked example

Question. An 8-bit GPIO port uses 1 in DDR to mean output. DDR = 0x0F, so bits 0-3 are outputs and bits 4-7 are inputs. The requested high bits are 0, 2 and 5. Write the PORT value that drives only the output pins, leaving input pins undriven. Give the answer in hex and decimal.

  1. DDR = 0x0F = 0b0000 1111. With 1=output, bits 0, 1, 2 and 3 are outputs; bits 4, 5, 6 and 7 are inputs.
  2. The output mask is 0x0F. The input mask is 0xF0.
  3. Requested high bits are 0, 2 and 5. Their weights are bit0=1, bit2=4 and bit5=32. The sum is 1+4+32 = 37 = 0x25.
  4. Keep only bits that are outputs: 0x25 & 0x0F = 0x05. The 0x20 part (bit 5) is removed because bit 5 is an input.
  5. The output bit pattern is bit3=0, bit2=1, bit1=0, bit0=1: 0b0000 0101 = 0x05 = 5 decimal.
  6. The PORT write is 0x05. Input bits 4-7 are not driven. If a datasheet says writing PORT bits for inputs enables pull-ups, use a read-modify-write or shadow copy to preserve those bits.

Answer. PORT = 0x05 (5 decimal): bits 0 and 2 are high, bits 1 and 3 are low, and input bit 5 is not driven.

Exam traps

  • DDR sets direction; PORT sets the output level. Writing 1 to a DDR bit makes an output, it does not make the pin high.
  • Bit 0 is the least significant bit (weight 1), not the leftmost bit. 0x0F is bits 0-3, not bits 4-7.
  • An input pin is high-Z; it does not output a value. Reading PIN gives the pin voltage; reading PORT may give the output latch.
  • Open-drain output cannot drive high by itself; it needs a pull-up resistor. Push-pull drives both high and low.
  • On some MCUs 1 in DDR means input, and writing 1 to a PORT bit for an input enables a pull-up. Check the datasheet.

3.2 Timers, counters, capture and compare

A timer is a small counter built into the microcontroller that advances on clock edges. It gives the chip a sense of time without the CPU waiting in delay loops. The prescaler slows a fast clock down to a usable tick. The counter's value can be read, and two helper registers make it more useful: capture stores the count when an external event arrives, and compare fires an action when the count reaches a set value. Timers produce delays, measure pulse widths and frequencies, timestamp sensor edges, and drive the PWM blocks that dim LEDs and control motors.

You need: 3.1 GPIO and I/O ports for pin configuration, and Unit 2 for the special function registers that control an on-chip peripheral.

Clock, prescaler and the tick

A timer counts internal clock ticks. A counter counts edges on an external pin. The same hardware does both: only the clock source changes. Everything below applies to either role.

The prescaler sits between the clock and the counter and divides the clock by a whole number P. It lets a fast oscillator produce long delays without building a very wide counter.

T = P / f_clk

T is the tick, the time for one count, in seconds; P is the prescaler divide factor (1, 2, 4, 8, ...); f_clk is the clock feeding the timer in hertz.

A prescaler of 16 on a 4 MHz clock gives T = 16 / 4 000 000 Hz = 4 µs. An n-bit counter holds values 0 to 2ⁿ − 1. It wraps from the top value to 0, sets the overflow flag, and continues. A free-running timer therefore overflows every 2ⁿ × T seconds. An auto-reload timer copies a stored reload value into the counter at each overflow, so its period is (2ⁿ − reload) × T. Some timers count down, or up and then down, which suits centre-aligned PWM (see 3.5).

Capture and compare

Input capture. An edge on a capture pin copies the counter into a capture register in hardware, at the instant the edge arrives. Software reads that stored copy later, so interrupt latency and instruction timing do not spoil the measurement. Two captures of the same kind of edge give the period: period = (capture2 − capture1) × T, and frequency = 1 / period. If the counter wrapped between the two captures, add 2ⁿ to the difference before multiplying. Capturing on both edges of one pulse gives its width the same way.

Output compare. A compare register holds a target value. When the counter reaches it, hardware sets a match flag, can toggle, set or clear an output pin, and can raise an interrupt. That gives exact pin edges and exact delays without software loops. Repeating the match every period produces a square wave; changing the duty cycle of that square wave is PWM.

Many microcontrollers group capture, compare and PWM into one block. Some syllabi call it the CCP module (capture/compare/PWM). A compare match reaches the CPU through the interrupt system described in 3.3.

Programming a timer

Configure a timer in a fixed order, so that no half-set register fires early.

  1. Stop the timer by clearing its enable bit.
  2. Select the clock source and write the prescaler P.
  3. Select the mode: 8-bit or 16-bit, up or up/down, free-running or auto-reload.
  4. Write the reload register for a period, or the compare register for a match time.
  5. Clear the overflow or match flag.
  6. Enable the interrupt if the flag should wake the CPU.
  7. Set the enable bit to start counting.

counts = d / T reload = 2ⁿ − counts

d is the wanted delay in seconds; T is the tick in seconds; n is the counter width in bits; counts is the number of ticks in the delay; reload is the value written to the reload register.

If counts is larger than 2ⁿ, the delay cannot fit: raise the prescaler or use a wider timer. The reload value is never the delay count itself.

Worked example

Question. A 16-bit up-counter runs from a 4 MHz clock with a prescaler of 16. (a) Find the tick. (b) Find the maximum time before overflow. (c) Find the reload value that gives an overflow every 50 ms.

  1. Tick: T = P / f_clk = 16 / (4 × 10⁶ Hz) = 4 × 10⁻⁶ s = 4 µs.
  2. Range: a 16-bit counter holds 2¹⁶ = 65536 counts, from 0 to 65535.
  3. Maximum overflow time: 65536 × 4 µs = 262144 µs = 262.144 ms.
  4. Counts needed for 50 ms: counts = d / T = 50 ms / 4 µs = 0.050 s / 4 × 10⁻⁶ s = 12500.
  5. Reload: reload = 2ⁿ − counts = 65536 − 12500 = 53036, which is 0xCF2C in hex.

Answer. Tick = 4 µs, maximum overflow time = 262.144 ms, and the reload value for a 50 ms overflow is 53036 (0xCF2C).

Exam traps

  • Reload is not the delay count. A 16-bit timer overflows after 2ⁿ − reload ticks, so for 12500 ticks you load 53036, not 12500.
  • The prescaler divides the clock and never multiplies it. T = P / f_clk, so a larger P gives a longer tick, coarser resolution and a longer reachable delay.
  • Read the reference manual for two local conventions: whether the prescaler register holds the divide factor or that value minus one, and whether the match happens at the written compare value or one count later.
  • A capture difference taken across an overflow looks wrong. Add 2ⁿ to the difference before converting to time.
  • A stale flag fires the interrupt the moment you set the enable bit. Clear the flag after configuring and before enabling the interrupt.

3.3 Interrupts, ISRs, latency and priority; polling

An interrupt is a hardware signal that makes the CPU stop its current code, run a short handler called an ISR, and return to the exact instruction it left. Without interrupts the CPU must poll — read a flag again and again — which wastes cycles. Interrupts give fast reaction to button presses, incoming UART bytes, timer ticks and finished ADC conversions. The price is complexity: latency, priority, and data shared with the main program. This chapter shows the mechanism, how the delay is built up, and how to choose between polling and interrupts.

You need: 3.2 for timer and compare interrupt sources, and the stack and register ideas from Unit 2 (ARM registers and modes).

Polling versus interrupt-driven design

Polling means the program asks the peripheral again and again: read the flag, test it, loop if it is clear. The CPU spends its time asking whether anything happened, not on useful work. A keypad scanned every 10 ms costs almost nothing, but a UART receiver polled in a tight loop can eat the whole processor.

An interrupt works the other way round. The peripheral raises a request line when it needs service, an interrupt controller passes the request to the CPU, and the CPU stops the main program, runs a short function called an ISR (interrupt service routine), then resumes. Reaction time no longer depends on how long one pass of the main loop takes.

Polling still wins when the event is frequent and the cycle must stay predictable, for example reading an ADC inside a fixed control loop, where a known cycle time matters more than the cycles saved.

From event to ISR: source, flag, enable, vector

Every interrupt has four parts: a source, a flag bit, an enable bit and a vector.

  1. Source event: a timer match, a UART receive-complete, an ADC end-of-conversion, or an edge on a GPIO pin (see 3.1). The peripheral sets its flag bit in a status register.
  2. Peripheral enable: the flag reaches the controller only if that peripheral's own interrupt-enable bit is set.
  3. Global enable: the CPU must also have interrupts unmasked. On ARM this is the I bit in the program status register.
  4. Detection: the CPU finishes the instruction it is executing and samples the request line at the instruction boundary.
  5. Context save: the CPU pushes the return address and the working registers on the stack, so the ISR may overwrite them.
  6. Vector fetch: the controller supplies an ID, and the CPU reads the ISR address from the vector table, a fixed array of function pointers at the start of memory.
  7. Return: the ISR clears the peripheral flag, then a return-from-interrupt instruction restores the saved context and the main program continues.

A controller that hands over the ISR address by itself is called a vectored interrupt controller; some syllabi use that name. If the controller gives only one shared request, software must test flags in turn and the scheme is non-vectored.

Clearing the flag is part of the job. The flag stays set until software writes to it, so a forgotten clear sends the CPU straight back into the same ISR, again and again.

Latency and its parts

Interrupt latency is the time from the flag being set to the first instruction of the ISR. Three parts add up.

t_latency = t_detect + t_arbitrate + t_save

t_detect is the wait for the current instruction to finish (1 to 3 cycles); t_arbitrate is the controller deciding which pending request wins (1 to 2 cycles); t_save is pushing the context on the stack and fetching the vector (8 to 12 cycles).

A Cortex-M3 is usually quoted at 12 cycles from request to ISR entry with zero-wait-state memory. At 72 MHz that is about 0.17 µs, small compared with what software adds.

  • A critical section — interrupts masked by software — delays entry for its whole length.
  • A higher-priority ISR already running delays a lower-priority one until it finishes.
  • Flash wait states and DMA traffic on the bus slow the vector fetch and the stack push.
  • The total response time is t_response = t_latency + t_ISR, where t_ISR is the ISR's own running time.

Priority, nesting and the NVIC on ARM

Priority decides which pending source runs first. On ARM a lower number means higher urgency, so priority 0 beats priority 5. Priority is set once at startup and rarely changed afterwards.

If a higher-priority request arrives while a low-priority ISR is running, the CPU saves the low ISR's context and runs the high one first. That is nesting or pre-emption. Each nesting level uses more stack, so the deepest possible nest sets a minimum stack size.

On ARM Cortex-M the controller is the NVIC (Nested Vectored Interrupt Controller). Software reaches it through memory-mapped registers.

Data shared between an ISR and the main loop must be declared volatile, so the compiler reloads it from memory instead of keeping a stale copy in a register. A single aligned 32-bit read or write is atomic on ARM; a multi-byte update needs a critical section with interrupts briefly masked.

Keep the ISR short: set a flag, copy one byte, clear the source. Heavy maths belongs in the main loop. An ISR of 200 µs firing every 500 µs already uses 40% of the CPU, and it delays every lower-priority source by up to 200 µs. Block moves are better handed to DMA (see 3.9).

Worked example

Question. A motor controller uses a timer compare interrupt. The compare event occurs at t = 500 µs. The measured interrupt latency is 100 µs and the ISR body takes 200 µs. (a) At what time does the main loop resume? (b) The same interrupt fires 2000 times per second. What percentage of CPU time does this interrupt consume, counting latency and ISR?

  1. The ISR cannot start before the compare event, so add the latency: 500 µs + 100 µs = 600 µs is the first ISR instruction.
  2. The ISR runs for its own duration: 600 µs + 200 µs = 800 µs, where main resumes.
  3. CPU time lost per event = latency + ISR = 100 µs + 200 µs = 300 µs = 300 × 10⁻⁶ s.
  4. Events per second = 2000, so lost time per second = 2000 × 300 µs = 600 000 µs = 0.6 s.
  5. Fraction of one second = 0.6 s ÷ 1 s = 0.60, that is 60%.

Answer. Main resumes at 800 µs, and the interrupt consumes 60% of the CPU time.

Worked example 2

Question. A UART interrupt has a latency of 60 µs and an ISR of 140 µs. It fires 1000 times per second. Find the CPU load.

  1. Per event = 60 + 140 = 200 µs.
  2. Per second = 1000 × 200 µs = 200 000 µs = 0.2 s.
  3. Load = 0.2 ÷ 1 = 20%.

Answer. The UART interrupt consumes 20% of the CPU.

Exam traps

  • Forgetting to clear the peripheral flag: the request stays pending and the ISR re-enters forever, so the main loop never runs again.
  • Assuming a bigger priority number means more urgent. On ARM the opposite holds: 0 is the highest priority.
  • Confusing latency with ISR duration. Latency ends at the first ISR instruction; response time = latency + ISR.
  • Sharing a flag with an ISR without volatile: the compiler caches it in a register and the main loop never sees the change.
  • Writing a long ISR. It adds its full length to the latency of every lower-priority source and can make deadlines impossible.

3.4 Watchdog timer and real-time clock

A watchdog timer is a small counter that resets the microcontroller if software stops servicing it. It exists because a program can hang in an infinite loop, wait forever on a flag, or be corrupted by noise; a reset returns the system to a known state. A real-time clock (RTC) is a separate low-power counter that keeps calendar time from a 32.768 kHz crystal. Watches and RTCs appear in water meters, car dashboards, ATMs, UPI payment terminals and any device that must recover alone or timestamp events after mains power is removed.

You need: 3.2 for counters and prescalers, and 3.3 for interrupts and reset behaviour.

Watchdog counter, kick and reset

A watchdog timer (WDT) is an on-chip counter that resets the microcontroller if software fails to service it. It runs from its own low-speed oscillator, commonly 32 kHz, so it keeps counting even if the CPU clock or main loop stops. Software writes a service sequence, called a kick, before the counter overflows. If the counter reaches its maximum, the watchdog drives the reset line. The reset restarts the CPU from its reset vector and sets a reset-cause flag that firmware can read at boot.

t_tick = P / f_wdt,    T_timeout = 2<sup>N</sup> × t_tick

t_tick is one counter step in seconds; P is the prescaler integer; f_wdt is the watchdog clock in hertz; N is the counter width in bits; T_timeout is the maximum time between kicks in seconds.

A window watchdog adds a lower limit. The kick must arrive after the window opens and before the timeout. A kick that is too early also causes reset. This catches code that has run away and is kicking far too often.

  1. Software writes the unlock key to the watchdog key register.
  2. Software writes the service key before the timeout expires.
  3. The counter reloads and starts again.
  4. If the counter overflows, or a window watchdog receives an early kick, the watchdog asserts reset.
  5. The reset stops the CPU, sets the reset-cause flag, and restarts firmware from the reset vector.

Production policy: leave the watchdog enabled in every shipped build, service it from the main loop, and log the reset cause. Choose a timeout longer than the worst-case main loop but shorter than the time in which a stuck output could cause harm. Do not hide a hung main loop by kicking inside a fast timer ISR.

RTC crystal, divider and registers

A real-time clock (RTC) keeps wall-clock time: seconds, minutes, hours, date, month and year. It uses a 32.768 kHz crystal because 32768 = 2¹⁵, so a binary divider chain reaches exactly 1 Hz. The RTC and its oscillator sit in a low-power domain, often powered from a coin cell on a VBAT pin when the main supply is off.

f_1Hz = f_xtal / 215

f_xtal is the crystal frequency in hertz (32768 Hz); f_1Hz is the divided output in hertz (1 Hz); 215 = 32768 is the divider ratio.

The divider chain produces a 1 Hz tick. The RTC counts that tick into time registers. Many RTCs store these registers in BCD, not binary. In BCD, 0x23 means 23 decimal, while the same bits read as binary would mean 35. Firmware must convert BCD to binary before arithmetic and back before writing.

  • Alarm registers hold a target time; a match sets a flag, wakes the MCU, or toggles an output pin.
  • A square-wave output can send 1 Hz, 1024 Hz or another divided rate to a pin.
  • An epoch counter stores total seconds since 1970-01-01 00:00:00 UTC, which makes time arithmetic easy.
  • A backup battery keeps the oscillator and time registers alive when VDD is removed; it does not run the whole MCU.

A safe kick and timeout choice

A kick must prove that the main loop is alive. A timer ISR that kicks every millisecond will keep the watchdog happy even when the main loop is stuck. That is the classic mistake.

  1. Main loop sets a flag after each major task completes.
  2. At the end of one full pass, the main loop checks that all flags are set.
  3. If every flag is set, clear the flags and kick the watchdog once.
  4. If any flag is missing, do not kick; let the watchdog reset the system.
  5. During development, halt the CPU in the debugger and confirm that reset occurs.

Pick the timeout from measurements. Measure the slowest normal pass through the main loop, including flash writes and communication waits. Set the timeout above that value with margin, and below the time that a stuck actuator, display or payment terminal becomes unsafe. Test with the real clock, not a simulator only. On boot, read and clear the reset-cause register; a watchdog reset should be recorded, not silently ignored.

Worked example

Question. A watchdog timer is clocked at 32 kHz. Its prescaler is 128 and its counter is 12 bits wide. (a) Find one counter tick and the timeout. (b) Choose a safe kick period for a main loop whose worst-case pass is 6 s. (c) An RTC uses a 32.768 kHz crystal; find its 1 Hz divider ratio.

  1. f_wdt = 32 kHz = 32000 Hz.
  2. t_tick = P / f_wdt = 128 / 32000 = 0.004 s = 4 ms.
  3. Counter states = 2^N = 2^12 = 4096.
  4. T_timeout = 4096 × 0.004 s = 16.384 s.
  5. Worst-case main loop = 6 s. A 10 s kick period is above 6 s and below 16.384 s, so it gives margin and still resets on a hang.
  6. RTC divider ratio = f_xtal / f_1Hz = 32768 / 1 = 32768 = 2^15.

Answer. The watchdog tick is 4 ms, the timeout is 16.384 s, a 10 s kick period is safe for a 6 s main loop, and the RTC divides by 2^15 = 32768 to produce 1 Hz.

Exam traps

  • Kicking the watchdog inside a fast timer ISR proves only that the timer works. A hung main loop can still keep the system alive forever. Service from the main loop.
  • A watchdog timeout is the maximum time between kicks, not the period you must use. Choose a period below it with margin.
  • RTC time registers are often BCD. Reading 0x59 as binary gives 89; treat it as 59 before arithmetic.
  • A backup battery on VBAT keeps the RTC oscillator and registers, not the CPU or main RAM.
  • A window watchdog resets on an early kick as well as a late one; test both limits.

3.5 PWM generation

Pulse-width modulation (PWM) keeps a digital pin at a fixed period T and changes how long it stays high. The high time t_on sets the duty cycle D = t_on / T, and the average voltage is D × V_high. A timer and compare register make this waveform in hardware, so software only writes a number. PWM dims LEDs, controls motor speed, sets a heater, and makes a rough DAC. Its fixed period suits switching circuits and avoids the heat of a linear regulator.

You need 3.1 GPIO and I/O ports for the pin and 3.2 Timers, counters, capture and compare for the counter and compare match.

Period, duty cycle and average value

PWM is a square wave with a fixed period T in seconds. The high time ton is the part of the period at the high voltage. Duty cycle D is the fraction of the period that is high: D = ton / T. D has no unit; write it as 0.25 or 25 %. Some syllabi call this pulse-width modulation. The average voltage across a load is Vavg = D × Vhigh when the low level is 0 V. A 5 V pin at D = 0.25 gives 1.25 V average. The load sees pulses, not a steady voltage; a motor or LED responds to the average when the period is short compared with its response time. Resolution is the smallest duty step. A timer with N counts per period has step 1/N; for N = 256 the step is 1/256 ≈ 0.0039, or 0.39 %.

T = N × t<sub>tick</sub>, f = 1 / T, D = C / N, V<sub>avg</sub> = D × V<sub>high</sub>

T is the PWM period in seconds; N is the number of timer counts in one period; ttick is one timer tick in seconds; f is the PWM frequency in hertz; D is the duty cycle as a fraction; C is the compare value in timer counts; Vhigh is the high-level voltage in volts; Vavg is the average voltage in volts.

Compare register and edge-aligned counting

The compare register holds the timer count at which the output changes. In up-count or edge-aligned mode, the counter starts at 0, the pin goes high, and the counter counts up. When the counter equals compare value C, the pin goes low. The counter continues to the top, wraps to 0, and the next period starts. High time is C timer ticks, so C = D × N. Changing C changes the pulse width; the period and frequency stay fixed.

  1. Choose the timer clock so that one tick ttick is known.
  2. Choose N, the number of counts in one PWM period; then T = N × ttick.
  3. Compute C = D × N and write C to the compare register.
  4. At count 0 set the pin high; on the compare match set it low. A polarity bit may reverse these actions.
  5. To change the average voltage, write a new C; leave the period alone.

An 8-bit timer that counts 0 to 255 has N = 256 counts, not 255. Count 0 is a state, so the number of states is 256. If a timer loads a period register with P and counts 0 to P, the number of counts is P + 1; check the reference manual. Center-aligned mode makes the counter count up to the top and then down. The compare match can act on both slopes, so the pulse is placed around the middle of the period. Center-aligned PWM gives symmetric pulses and lower harmonic content, which helps motor drives; edge-aligned PWM is simpler and is common for LEDs and heaters.

Polarity, dead time and the CCP block

A polarity control bit decides whether the pin is active-high or active-low. With active-low polarity, the same compare value gives the opposite high time at the pin. A setting meant to give 25 % high in active-high mode can give 75 % high at the pin. Check the polarity bit before you compute Vavg.

  • Dead time is a short interval when both outputs of a half-bridge are off. It stops the high-side and low-side transistors from conducting at the same time.
  • Hardware in the PWM module inserts dead time. A software delay is too uncertain at switching times of microseconds.
  • CCP means capture/compare/PWM. One timer block can capture an input edge, change an output on a compare match, or generate PWM; mode bits select the function.
  • PWM dims LEDs, sets motor speed, drives heaters through a relay or SSR, and makes a low-cost DAC when followed by a filter.

Do not drive a motor or relay coil from the MCU pin. The pin drives a transistor, gate driver or driver IC; see 3.8 Sensors, actuators, relays and motor interfacing. For a servo, the period is 20 ms and the high time is about 1 ms to 2 ms, so the duty cycle is small; the same PWM block can make it if the timer has enough range.

Worked example

Question. An 8-bit timer runs at 1 MHz and counts from 0 to 255. Find the PWM frequency, the compare value for 25 % duty, and the average voltage when the high level is 5 V and the low level is 0 V.

  1. Timer clock is 1 MHz, so one tick is ttick = 1 / 1 MHz = 1 µs.
  2. The counter has 256 states, 0 to 255, so N = 256 counts per PWM period.
  3. Period T = N × ttick = 256 × 1 µs = 256 µs.
  4. Frequency f = 1 / T = 1 / 256 µs = 1 / 0.000256 s = 3906.25 Hz.
  5. D = 25 % = 0.25.
  6. High time ton = D × T = 0.25 × 256 µs = 64 µs.
  7. Compare value C = ton / ttick = 64 µs / 1 µs = 64 counts, or C = D × N = 0.25 × 256 = 64.
  8. Vavg = D × Vhigh = 0.25 × 5 V = 1.25 V.

Answer. The PWM frequency is 3906.25 Hz, the compare value is 64 counts for 25 % duty, and the average voltage is 1.25 V with a 5 V high level.

Exam traps

  • Counting 0 to N−1 gives N states. Some timers count 0 to P with N = P + 1. Duty is C/N, not C/(N−1).
  • Polarity can invert the pin. A 25 % setting in active-high mode can be 75 % high at an active-low pin.
  • Compare value is in timer ticks, not microseconds or percent. Convert ton with ttick.
  • Center-aligned mode matches on the up and down slopes. Do not reuse the edge-aligned compare formula without checking the manual.
  • Hardware dead time is not a software delay. At microsecond switching, software timing is too uncertain.

3.6 ADC and DAC interfacing

An analog voltage varies continuously; a processor stores only whole numbers. An ADC (analog-to-digital converter) maps an input voltage to a digital code. A DAC (digital-to-analog converter) maps a code back to a voltage. Both are scaled by a reference voltage Vref and a resolution of n bits, so the same code means different volts on different chips. Sensors, audio, battery monitors and motor-current loops all cross this boundary. This chapter shows the transfer equations, sample-and-hold and SAR conversion, the start-of-conversion bit and the end-of-conversion flag, and polling versus interrupt reads.

You need GPIO to drive the pins, timers for sample timing, and interrupts for the interrupt read.

Voltage in, code out

An ADC answers one question: which code best represents Vin? Two numbers fix the answer. The resolution n is the number of bits in the output code. The reference Vref is the voltage that code 2ⁿ−1 represents; code 0 represents 0 V. The gap between neighbouring codes is the quantization step q. Some syllabi call these A/D and D/A converters.

q = Vref / (2ⁿ − 1)

q is the quantization step in volts per code (one LSB); Vref is the reference voltage in volts; n is the resolution in bits.

code = round(Vin / q)

Vin is the input voltage in volts; round means nearest integer, not truncation; code is an integer from 0 to 2ⁿ−1.

Vout = code × q

Vout is the DAC output voltage in volts; code is the input code; q = Vref / (2ⁿ − 1).

For n = 10 and Vref = 3.3 V, q = 3.3/1023 = 3.226 mV. Code 310 means 310 × 3.226 mV = 1.0 V. The same code on a 12-bit converter with Vref = 3.3 V would mean 310 × 0.806 mV = 0.250 V. A code without n and Vref is meaningless. The full-scale code is 2ⁿ−1, not 2ⁿ; that one-count difference is small at 12 bits and large at 4 bits.

Sample, hold, approximate

An ADC cannot watch a moving input while it compares. A sample-and-hold circuit closes a switch, charges a capacitor to Vin, then opens the switch. The capacitor holds Vin steady while the converter works. The sample clock decides when this happens. If the signal changes faster than half the sampling rate, the readings alias: a 900 Hz tone sampled at 1 kHz looks like 100 Hz. Keep the sample rate above twice the highest input frequency.

Most microcontroller ADCs use successive approximation (SAR). The SAR register starts at mid-scale. The internal DAC produces Vref/2; the comparator says whether Vin is higher or lower. If higher, the MSB stays 1; if lower, it clears. The next trial adds Vref/4, then Vref/8, and so on. After n trials the register holds the nearest code. A 10-bit SAR conversion takes about 10 comparator steps plus sampling and settling time, typically a few microseconds.

Software controls the ADC through registers. Write the channel number to select one pin of the input multiplexer. Set the start-of-conversion bit (SOC or START). The hardware sets the end-of-conversion flag (EOC) or raises an interrupt when the data register is ready.

  1. Write the channel number in the ADC control register.
  2. Set START.
  3. Read the status register until EOC = 1.
  4. Copy the data register into a variable.
  5. Clear EOC, often by reading the data register or writing 1 to the flag.

With an interrupt, enable the ADC interrupt, set START, and return to other work. The ISR reads the data register, clears EOC and sets a software flag. Polling wastes CPU cycles but needs no ISR; interrupts free the CPU but add latency and shared-data care, as covered in interrupts.

Pseudocode.

// polling
ADC_CTRL = CH3 | START
while (ADC_STATUS & EOC) == 0:
    ;                       // wait
code = ADC_DATA
ADC_STATUS = EOC            // clear flag

// interrupt
ADC_CTRL = CH3 | START | ADC_INT_EN
// ISR when EOC sets:
isr_adc():
    code = ADC_DATA
    ADC_STATUS = EOC
    done = 1

code = 310, done = 1 after the ISR runs

DAC: code back to volts

A DAC reverses the mapping. The input is a code, the output is a voltage. The common R-2R ladder uses resistors of only two values: R and 2R. Each bit steers a binary-weighted current into an op-amp summing node. The MSB (bit n−1) contributes half the total current, the next bit down (bit n−2) contributes half of that, the next half again, and so on down to the LSB (bit 0). The op-amp turns the total current into Vout = code × Vref/(2ⁿ−1).

For an 8-bit DAC with Vref = 5 V, q = 5/255 = 19.608 mV. Code 100 gives 100 × 19.608 mV = 1.961 V. Code 255 gives 5.000 V. The output moves in steps of q. Settling time is the time from a code change until Vout stays within half an LSB of the final value. Fast DACs settle in nanoseconds; slow ones in microseconds.

DACs set analog references for motor drives, generate audio and produce test waveforms. When the required bandwidth is low, a PWM pin plus an RC low-pass filter is a cheap DAC: the duty cycle sets the average voltage (see PWM generation). Either way, Vref sets the scale, so a dirty reference adds the same percentage error to every output.

Worked example

Question. A 10-bit ADC has Vref = 3.3 V and Vin = 1.0 V. Find the quantization step and the output code. An 8-bit DAC has Vref = 5 V and input code 100. Find its output voltage.

  1. ADC step: n = 10, so 2ⁿ − 1 = 1023.
  2. q = 3.3 V / 1023 = 0.0032258 V = 3.226 mV.
  3. code = round(1.0 V / 0.0032258 V) = round(310.0) = 310.
  4. DAC step: n = 8, so 2ⁿ − 1 = 255.
  5. q = 5 V / 255 = 0.019608 V = 19.608 mV.
  6. Vout = 100 × 0.019608 V = 1.961 V.

Answer. The ADC gives code 310 with q = 3.226 mV; the DAC gives 1.961 V.

Exam traps

  • Using 2ⁿ in place of 2ⁿ−1. For 8 bits at 5 V, 5/256 = 19.53 mV, not 19.61 mV, and the top code never reaches Vref.
  • Dropping Vref. A code alone says nothing; 310 means 1.0 V only when Vref = 3.3 V and n = 10.
  • Mixing V and mV in one line. Convert q to mV only after writing all values in volts, or keep units on every number.
  • Treating resolution as accuracy. A 12-bit ADC can be less accurate than a good 10-bit part; offset, noise and missing codes matter.
  • Forgetting to wait for EOC or to clear it. Reading the data register too early returns the old code, and a stale flag starts the next read at the wrong time.

3.7 Displays and keypads: LED, seven-segment, LCD

An LED, a seven-segment display and an LCD are output devices that a microcontroller drives through GPIO pins. Each needs a safe current and correct signal timing. A keypad is many switches sharing few pins; the CPU scans rows and columns to find the pressed key. These parts appear in appliances, meters, medical panels and project boards: a microwave shows time on a seven-segment or LCD, and a door lock reads a 4×4 keypad. The sections below give the resistor calculation, display drive levels, LCD handshake and keypad scan.

You need: 3.1 GPIO and I/O ports and 3.2 timers for multiplexing.

LED and seven-segment drive

An LED is a diode that emits light when forward biased. Its forward voltage Vf is the drop across it when lit, and If is the rated current. A GPIO pin gives a source voltage Vs, usually 3.3 V or 5 V. A series resistor R limits the current. If the resistor is too small, the LED and pin overheat; if too large, the LED is dim.

R = (V<sub>s</sub> − V<sub>f</sub>) / I<sub>f</sub>

R is the series resistance in ohms (Ω); Vs is the supply or pin voltage in volts (V); Vf is the LED forward voltage in volts; If is the wanted forward current in amperes (A). Convert mA to A by dividing by 1000.

A seven-segment display is seven LEDs named a to g, plus a decimal point. In a common-cathode part all cathodes join ground; drive a segment anode high to light it. In a common-anode part all anodes join Vcc; drive a segment cathode low to light it. The drive levels are opposite, so read the part number before writing code.

Multiplexing drives one digit at a time. A timer turns on digit 1, waits about 1 ms to 5 ms, turns it off, then turns on digit 2. If the whole display refreshes faster than about 50 Hz, the eye sees all digits on because of persistence of vision. Use one series resistor per segment, not one in the common line, to keep brightness even.

LCD parallel interface

A character LCD has a controller and a parallel bus. RS selects instruction register when 0 and data register when 1. RW selects write when 0 and read when 1. E is the enable strobe. D0–D7 carry a byte, or D4–D7 carry two nibbles in 4-bit mode. To write, set RS and RW, put the byte on the data bus, then pulse E high and low. The controller samples the bus on the falling edge.

Before sending characters, initialize: wait for power-up, function set (8-bit or 4-bit, lines, font), display off, clear display, entry mode, display on. After each command, read the busy flag: RS=0, RW=1; D7=1 means busy. Wait until D7=0. If you do not check busy, commands can be lost.

A 16×2 module has two lines of 16 characters. Address the first line from 0x00 and the second from 0x40 in the common controller map. Send the address as a command, then send data bytes. Keep the E pulse within the module's timing; a slow GPIO toggle is usually safe, a very fast one is not.

Keypad matrix scan

A 4×4 keypad has 16 push buttons in four rows and four columns. Rows R0–R3 are outputs; columns C0–C3 are inputs with pull-up resistors. A pull-up holds a floating input at 1. With no key pressed, all columns read 1. A pressed key connects its row to its column.

  1. Drive all rows high; wait for lines to settle.
  2. Drive row R0 low, keep R1–R3 high; read C0–C3.
  3. If a column reads 0, the key at that row and column is pressed.
  4. Repeat for R1, R2, R3; then repeat the whole scan.
  5. After a 0 is seen, wait 10 ms to 20 ms and read again; accept the key only if it is still 0. This is debounce.

Ghosting happens when three keys form an L shape: the unpressed fourth corner can also read 0. Use diodes in series with each key, or scan one key at a time, or accept only one key. Debounce stops one physical press from becoming many key events. A timer interrupt can call the scan every 5 ms to 10 ms.

One scan step: R2 is driven low. The columns read C0=1, C1=0, C2=1, C3=1. The 0 is at column 1, so the key is at row 2, column 1. With labels left to right, top to bottom from 1, key number = row×4 + column + 1 = 2×4 + 1 + 1 = 10. The figure shows this cell.

3.8 Sensors, actuators, relays and motor interfacing

A sensor turns a physical quantity into an electrical signal; an actuator turns an electrical signal into motion, heat or light. The microcontroller reads sensors and commands actuators. Signal conditioning shapes a raw sensor output for an ADC or GPIO pin. A driver lets a weak pin switch a coil, lamp or motor that needs far more current.

You need: 3.1 for pin current limits, 3.5 for duty cycle, and 3.6 for ADC input.

Input side: sensors and signal conditioning

A sensor converts a physical quantity into an electrical one. The MCU cannot read resistance; it reads a voltage on an ADC pin (3.6) or a logic level on a GPIO pin (3.1). Signal conditioning makes the sensor output fit that input.

  • LDR: resistance falls from about 1 MΩ in darkness to a few hundred ohms in bright light; a fixed series resistor forms a divider.
  • NTC thermistor: resistance falls as temperature rises. The curve is non-linear, so accurate readings need a lookup table or the beta formula.
  • Hall sensor: a logic output that flips near a magnet. Most are open-collector and need a pull-up. Used to count shaft or wheel rotations.
  • HC-SR04 ultrasonic: a 10 µs trigger pulse starts a sound burst; the echo pin stays high for the round trip.

V_out = V_cc × R_fixed ÷ (R_sensor + R_fixed)

V_out is the divider output in volts to the ADC pin; V_cc is the supply in volts; R_sensor is the sensor resistance in ohms from V_cc to the output node; R_fixed is the resistor in ohms from the output node to ground. Bright light lowers R_sensor, so V_out rises.

d = v × t ÷ 2

d is distance in metres; v is the speed of sound, about 343 m/s at 20 °C; t is the echo pulse width in seconds. The 2 covers the outbound and return path. At 343 m/s, 1 cm costs about 58 µs.

A push button is the simplest sensor: one side to the pin, the other to ground, plus a 10 kΩ pull-up to 3.3 V. Released, the pin reads 1; pressed, 0. Contacts bounce for 5–20 ms, so debounce: read, wait 10 ms, read again, and accept the value only when both reads agree.

Output side: the pin drives a transistor, not the load

A GPIO pin sources or sinks a few milliamperes — often 4 mA guaranteed and 20 mA absolute maximum. A 5 V relay coil draws 80 mA; a small DC motor draws 500 mA. Wiring either to a pin destroys the output driver. The pin supplies a control current; a transistor supplies the load current.

In a low-side switch the emitter goes to ground, the collector to the load, and the other end of the load to the supply. A logic 1 on the base turns the transistor on and pulls the load's lower end down to about 0.2 V, written V_CE(sat). A logic 0 turns it off.

I_B = I_C ÷ β, R_B = (V_pin − V_BE) ÷ I_B

I_C is the load current in amperes; β (hFE) is the transistor's DC current gain from its datasheet, a pure number; I_B is the base current in amperes; V_pin is the GPIO high voltage in volts; V_BE is the base-emitter drop, about 0.7 V for a silicon BJT; R_B is the base resistor in ohms.

A relay coil is an inductor. At switch-off the coil current cannot stop instantly; the coil generates V = L·di/dt, a spike of hundreds of volts at the collector, and the transistor breaks down. A 1N4007 across the coil — cathode to the +5 V end, anode to the collector — gives that current a path and clamps the spike to about 0.7 V above the supply. Leaving it out is the most common way to kill a driver.

For a mains load the relay contact already isolates the mains from the coil side. An optocoupler such as the PC817 adds a second barrier between the pin and the driver transistor. A MOC3021 with a triac switches mains with no relay at all. For several relays, a ULN2003 packs seven Darlington pairs with the flyback diodes already inside.

Motors: direction, speed and steps

A DC motor reverses when the supply polarity reverses. Four switches in an H-bridge allow either polarity: close top-left with bottom-right for one direction, top-right with bottom-left for the other. Never close both switches on one side — that is shoot-through, a direct short from supply to ground. The L293D has protection diodes built in; a bare L298N needs external fast-recovery diodes across its outputs.

Speed comes from PWM on the enable pin (3.5). The motor sees the average voltage, so 50% duty from a 12 V supply gives roughly 6 V across it, about half speed. A few kHz is fine where noise does not matter; push above 20 kHz and the switching is inaudible.

A stepper moves in fixed steps — 1.8° per step is 200 steps per revolution — and holds position when stopped. A unipolar four-phase motor (ULN2003) cannot reverse a coil, so energise the phases in order A, B, C, D, or two at a time as AB, BC, CD, DA. A bipolar two-winding motor (A4988 or H-bridge) can reverse current: the full-step order is A+, B+, A−, B−, often written A, B, A′, B′. Energise them wrongly and the rotor only vibrates. The driver IC carries the coil currents; the MCU sends only step and direction pulses.

A BLDC motor has three windings and no brushes. An electronic speed controller (ESC) switches them in the right order, using three Hall sensors or the back-EMF to find the rotor angle. Many ESCs accept a 1–2 ms pulse repeating at 50 Hz.

Worked example

Question. A 5 V relay coil draws 80 mA. It is switched by an NPN transistor with β = 100 and V_BE = 0.7 V. The driving GPIO pin outputs 3.3 V when high and can source at most 4 mA. Find the base current, the base resistor and the nearest standard value, and state the protection component needed.

  1. Collector current: I_C = 80 mA = 0.080 A. The coil resistance sets it (5 V ÷ 80 mA = 62.5 Ω); the transistor only carries it.
  2. Base current: I_B = I_C ÷ β = 0.080 ÷ 100 = 0.8 mA, well inside the 4 mA the pin can source.
  3. Base resistor: R_B = (3.3 − 0.7) ÷ 0.0008 = 3250 Ω.
  4. 3.3 kΩ gives 2.6 ÷ 3300 = 0.788 mA — the rounding goes the wrong way. The next E12 value down, 2.7 kΩ, gives 2.6 ÷ 2700 = 0.96 mA. Better still, compute I_B from hFE(min) and multiply by an overdrive factor of 2–3 so the transistor sits hard in saturation.
  5. Protection: a 1N4007 across the coil, cathode to +5 V and anode to the collector, clamps the switch-off spike. The 80 mA flows from the 5 V supply through the coil and collector; the pin carries only the base current.

Answer. R_B = 2.7 kΩ gives I_B ≈ 0.96 mA, and a 1N4007 flyback diode across the coil protects the transistor.

Question. An HC-SR04 ultrasonic module sends a trigger pulse. The echo pin stays high for 580 µs. The speed of sound is 343 m/s. Find the distance to the object.

Exam traps

  • Connecting a relay coil or motor straight to a GPIO pin. The pin is rated for a few milliamperes, the coil needs 80 mA and a motor hundreds; the output driver burns.
  • Leaving out the flyback diode across a coil, or fitting it the wrong way round. Anode at +5 V makes it conduct whenever the transistor is on, shorting the coil.
  • Confusing coil ratings with contact ratings. A relay marked 5 V, 80 mA coil and 230 V, 5 A contacts describes two separate circuits; the MCU only ever sees the first.

3.9 Direct memory access

Direct memory access (DMA) is a hardware method that moves a block of bytes between a peripheral and memory, or between two memory areas, without the CPU loading and storing each byte. A small DMA controller holds the source address, destination address, count and transfer size. The CPU writes these once, starts the channel, and continues with other work. DMA is used for ADC sample buffers, UART and SPI streams, display refresh and memory copies. It saves CPU cycles, but it still uses the bus, so it is not free.

You need: interrupts and ISRs and ADC interfacing (Unit 3.3 and 3.6).

CPU setup, then DMA moves the data

Polling and per-sample interrupts both make the CPU touch every item. At 10 kHz, that is 10,000 CPU actions per second. DMA removes the CPU from the byte path. The CPU first programs the DMA controller: source address (where data comes from), destination address (where it goes), count (number of items), transfer size (bytes per item), and direction. Then it enables the channel. The peripheral raises a DMA request when it has data. The controller asks the bus arbiter for the bus, receives a grant, moves the item, updates the addresses and decrements the count. When count reaches zero, it sets a done flag and raises a completion interrupt. The CPU then reads status and starts the next block. See interrupts for how the ISR runs.

The figure shows the order. Setup goes CPU → DMA controller. Data goes ADC peripheral → DMA controller → memory. The CPU is not in the data path. The DMA controller is a bus master during the transfer, so it can read or write memory on its own. The bus is shared, so the arbiter decides who owns it in each cycle.

t_poll = N × C / f_CPU

t_poll is polling time in seconds; N is the number of samples; C is CPU cycles per sample; f_CPU is CPU clock in hertz.

Channels, descriptors, modes and arbitration

A channel is one independent DMA data path with its own source, destination, count and control registers. An MCU may have 8 or 16 channels; each can be tied to a peripheral request line. A descriptor is a small record in memory that holds the same fields, plus a link to the next descriptor. Descriptor-based DMA, also called scatter-gather, lets one start command move several buffers without CPU help between them.

Transfer modes decide how long DMA keeps the bus. Single-transfer mode moves one item per request and releases the bus. Burst or block mode holds the bus for a run of items, which is fast but delays the CPU. Cycle-steal mode takes one bus cycle at a time, so the CPU slows but does not stop. Bus arbitration uses request and grant signals: DMA asserts request, the arbiter grants, and DMA releases when done or when its burst ends. A bus matrix on advanced MCUs gives several masters separate paths to different slaves, which reduces contention (bus protocols are in Unit 4).

ADC-to-memory, memory-to-memory and cache coherency

ADC-to-memory is the standard use. The ADC conversion-complete signal is the DMA request. The source is the ADC data register, which stays at one address, so source increment is off. The destination is the sample buffer in RAM, so destination increment is on. Count is the buffer length. The CPU starts the ADC and DMA, then sleeps. DMA writes each 12-bit sample into 2 bytes. At half count, a half-transfer interrupt can signal that the first half is ready; at zero count, the completion interrupt signals the full buffer. This double-buffering keeps capture continuous.

Memory-to-memory DMA copies a block from one RAM area to another, used for display frames, audio buffers and data logging. The CPU programs source, destination and count once. Cache coherency matters on MCUs with a data cache. DMA writes RAM directly, bypassing the CPU cache. The CPU may then read a stale cache line. Fix it by cleaning and invalidating the cache region, or by placing the DMA buffer in non-cacheable memory. Small MCUs without a data cache do not have this problem.

Worked example

Question. A 12-bit ADC samples at 10 kHz for 1 s. Each sample is stored in 2 bytes. (a) How many bytes does DMA move? (b) Polling costs 20 CPU cycles per sample at 50 MHz. Find the polling time. (c) DMA setup plus completion takes 100 cycles. Find the CPU time saved by DMA over polling.

  1. Number of samples = 10 kHz × 1 s = 10,000 samples. 1 kHz = 1000 samples/s.
  2. Bytes moved = 10,000 samples × 2 bytes/sample = 20,000 bytes.
  3. Polling cycles = 10,000 samples × 20 cycles/sample = 200,000 cycles.
  4. Polling time = 200,000 cycles ÷ 50,000,000 cycles/s = 0.004 s = 4 ms.
  5. DMA time = 100 cycles ÷ 50,000,000 cycles/s = 0.000002 s = 2 µs.
  6. Saved time = 4 ms − 2 µs = 4 ms − 0.002 ms = 3.998 ms.

Answer. DMA moves 20,000 bytes; polling would take 4 ms, DMA overhead is 2 µs, so the CPU time saved is about 3.998 ms.

Exam traps

  • DMA is not free: the controller and CPU share the bus, so a long burst stalls the CPU and adds interrupt latency.
  • Count is the number of items, not bytes, unless transfer size is 1 byte; a wrong count truncates the block or overruns the buffer.
  • For a fixed peripheral data register, source or destination increment must be off; leaving it on walks through wrong addresses.
  • If software never checks the done flag or completion interrupt, the last block can be lost or the next transfer can start on stale data.
  • On a cached MCU, DMA writes RAM directly; without cache clean/invalidate or a non-cacheable buffer, the CPU reads stale data.

Takeaways

  1. A GPIO pin is only a logic line; current, voltage and direction limits decide what may hang on it.
  2. Timers count internal time, counters count outside events, and capture/compare let one timer both measure and generate waveforms.
  3. An interrupt is a hardware call: the vector table finds the ISR, latency sets how late it starts, priority decides who wins.

An IC such as a ULN2003 or H-bridge that supplies the current and voltage a load needs, controlled by a logic pin.
Duty cycle
The percentage of each period during which a PWM signal is high.
GPIO
General-Purpose Input/Output: a pin whose direction and logic level are controlled by software registers.
High-Z (high impedance)
The state of a pin configured as input or of a disabled output, where it neither sources nor sinks current.
Interrupt
A signal from hardware that makes the processor suspend main code and run a service routine.
ISR
Interrupt Service Routine: the short routine that handles one interrupt source and then returns.
Latency
The delay between an interrupt request and the first instruction of its ISR.
NVIC
Nested Vectored Interrupt Controller: the ARM Cortex-M block that handles masks, priorities and nesting in hardware.
Port
A set of GPIO pins that share one data register and one direction register.
Prescaler
A divider placed before the timer that reduces the counting clock, extending the maximum period.
Pull-up resistor
A resistor to the supply that holds an unconnected input at logic high and defines the level of an open switch.
PWM
Pulse-width modulation: a fixed-frequency square wave whose high time is varied to set the average delivered to a load.
Real-time clock
A low-power counter, usually on a 32.768 kHz crystal, that keeps calendar time even when the main supply is off.
Relay
An electromagnetically operated switch that lets a small control signal switch a large isolated load.
Resolution
The number of bits in a converter's code, giving a smallest step of V_ref ÷ 2ⁿ.
Timer
A peripheral that counts internal clock ticks and can generate interrupts or waveforms at chosen counts.
Vector table
A table at a fixed address that holds the starting address of each ISR.
Watchdog timer
A counter that resets the MCU if software does not reload it within the timeout period.
