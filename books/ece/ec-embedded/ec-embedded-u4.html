4.1 UART and RS-232 serial communication

UART turns a byte into a timed sequence of bits on one wire, and RS-232 gives that sequence real voltage levels for a cable. The receiver recovers each byte from the start bit and the agreed bit time, with no shared clock. This cheap link connects a microcontroller to a PC, a GPS module, a barcode scanner or another board. You meet it as the serial port or COM port on old equipment, and as the debug console on many embedded boards today.

You need the 8051 special function registers SBUF and SCON from Unit 2, and the idea of interrupts from Unit 3; Chapter 4.2 compares this with synchronous board buses.

The UART frame and the bit clock

A UART is a Universal Asynchronous Receiver Transmitter. Asynchronous means there is no clock wire. Both ends agree on a baud rate B, the number of line bits per second. The line rests high when idle. A frame begins with a start bit at logic 0. Then come 5 to 9 data bits, sent least significant bit first. An optional parity bit follows. The frame ends with 1 or 2 stop bits at logic 1. The short form 8N1 means 8 data bits, no parity, 1 stop bit.

Tb = 1 / B

Tb is the time for one line bit in seconds; B is the baud rate in bits per second.

N = 1 + D + P + S; R = B / N

N is the number of bits in one frame; D is the number of data bits; P is 1 with parity and 0 without parity; S is the number of stop bits; R is the maximum byte rate in bytes per second.

For 8N1, N = 1 + 8 + 0 + 1 = 10 bits. At B = 9600 baud, Tb = 1/9600 s = 0.1042 ms and R = 960 bytes/s. A receiver samples near the middle of each bit. If the stop bit is not logic 1, the receiver reports a framing error. If a new byte is ready before the old byte is read, the receiver reports an overrun. TX and RX are separate wires, so full-duplex traffic can flow both ways at once.

RS-232: the electrical layer

UART defines the bit order and timing. RS-232 defines the voltages and connector for a cable. RS-232 uses inverted, large voltages. Logic 0 is +3 V to +15 V and is called space. Logic 1 is -3 V to -15 V and is called mark. A 0 V to 5 V TTL pin cannot drive this directly. The MAX232 chip uses a charge pump and four small capacitors to make about ±10 V from a 5 V supply, then converts TTL to RS-232 and back.

The common connector is the 9-pin DB9. A computer or terminal is DTE, data terminal equipment. A modem or similar device is DCE, data communication equipment. TX from one side goes to RX on the other. A null-modem cable crosses TX and RX and swaps the handshake lines so two DTE devices can talk. RS-232 often works to about 15 m at 9600 baud; longer cable or higher baud rate increases errors. Some syllabi call RS-232 the serial port, COM port or EIA-232.

8051 serial port: SBUF, SCON, TI and RI

On the 8051, SBUF is the serial buffer register. Writing SBUF loads the transmit register. Reading SBUF returns the received byte. SCON is the serial control register. In mode 1, set SM0 = 0 and SM1 = 1 for 8-bit UART. Set REN = 1 to enable reception. TI is the transmit flag; hardware sets TI = 1 after the stop bit leaves TXD. RI is the receive flag; hardware sets RI = 1 when a byte is complete in SBUF. Software must clear TI and RI.

  1. Polled transmit: wait until TI = 0, write the byte to SBUF, wait until TI = 1, then clear TI.
  2. Polled receive: set REN = 1, wait until RI = 1, read SBUF, then clear RI.
  3. Interrupt-driven serial sets TI or RI as an interrupt source; the ISR design belongs to Unit 3.

Polling wastes processor time but is simple. Interrupt-driven serial is better when the main program has other work. The same 8051 UART can use Timer 1 to set the baud rate; check the crystal and reload value in Unit 2.

Worked example

Question. The ASCII character 'A' is 0x41. Send it over a UART link at 9600 baud with 8N1. (a) List the ten line bits in order. (b) Find the time for one character and for 100 characters.

  1. Write 0x41 in binary as 0100 0001. The data bits D0 to D7, least significant first, are 1 0 0 0 0 0 1 0.
  2. 8N1 means 8 data bits, no parity, 1 stop bit. The frame has 1 start bit + 8 data bits + 1 stop bit = 10 bits.
  3. The start bit is 0. Place D0 to D7 after it. The stop bit is 1. The line order is 0, 1, 0, 0, 0, 0, 0, 1, 0, 1.
  4. Bit time Tb = 1 / 9600 s = 0.1041667 ms.
  5. One character takes 10 × 0.1041667 ms = 1.041667 ms, about 1.0417 ms.
  6. 100 characters take 100 × 1.041667 ms = 104.1667 ms, about 104.17 ms.

Answer. The ten line bits are start 0, D0 to D7 = 1 0 0 0 0 0 1 0, stop 1; one character takes 1.0417 ms and 100 characters take 104.17 ms.

Exam traps

  • Baud is not byte rate. With 8N1 each byte needs 10 line bits, so 9600 baud carries at most 960 bytes/s, not 9600 bytes/s.
  • UART sends data least significant bit first. For 0x41 the first data bit after the start bit is 1, not 0.
  • RS-232 logic is inverted and large: logic 1 is -3 V to -15 V and logic 0 is +3 V to +15 V. A TTL 5 V pin needs a MAX232 or similar driver.
  • 8N1 is 10 bits per frame: 1 start + 8 data + 1 stop. Parity adds one bit; two stop bits add another.
  • TX and RX must cross. Two DTE devices need a null-modem cable; a straight-through cable connects TX to TX.

4.2 SPI and I2C buses

SPI and I2C are short, synchronous board buses. A master drives a clock and exchanges data with one or more slaves. SPI uses four wires and shifts bits in both directions at once. I2C uses two open-drain wires with pull-up resistors, and it addresses each slave. Both sit on the same printed circuit board, linking a microcontroller to sensors, memory, displays and power chips. They avoid the overhead of a long network stack, so they are cheap and fast for short distances. This chapter shows how each bus moves a byte, how multiple devices are handled, and when to choose one over the other.

You need: GPIO pin behaviour from Unit 3 and the serial-versus-parallel idea from Unit 1; see UART for the asynchronous contrast.

SPI: four wires and a shift register

SPI is a synchronous serial bus. A clock line carries timing, so no start and stop bits are needed. One device, the master, controls the clock and starts every transfer. Each other device is a slave.

Four wires carry the signals. SCLK is the serial clock. MOSI is master-out slave-in. MISO is master-in slave-out. SS or CS is slave select, often active low. The master pulls one SS low to choose a slave. Data moves in both directions at the same time, so SPI is full duplex.

Inside the master and the chosen slave there is an 8-bit shift register. On each SCLK pulse, the master sends one bit on MOSI and receives one bit on MISO. After eight pulses, the two bytes have swapped places, so a 16-bit transfer needs 16 SCLK pulses: the 8-bit exchange is performed twice.

CPOL sets the clock idle level: 0 means low, 1 means high. CPHA sets the sampling edge: 0 means the first edge, 1 means the second edge. These two bits give modes 0 to 3, where mode = 2×CPOL + CPHA. Both ends must use the same mode.

Adding a slave needs another SS line, because SPI has no address and no ACK. A daisy chain is the alternative: the master MOSI goes to the first slave's data input, that slave's MISO goes to the next slave's MOSI (data input), and the last slave's MISO returns to the master MISO. All slaves share one SS, and bits pass through the chain.

I2C: two wires, address and ACK

I2C uses two wires. SDA is serial data and SCL is serial clock. Both are open-drain: a device can pull a line low, or release it. A pull-up resistor to 3.3 V, or another supply, returns the released line high. Two devices can therefore share the same wire without shorting their outputs.

A transaction starts with START: SDA falls while SCL is high. It ends with STOP: SDA rises while SCL is high. Between them, the master sends a 7-bit address and then a separate R/W bit. R/W = 0 means write, 1 means read. All slaves compare the address; the one that matches responds.

  1. Master issues START.
  2. Master sends 7-bit address and R/W bit.
  3. Selected slave pulls SDA low for the ninth clock: ACK.
  4. Master and slave exchange 8-bit data bytes, each followed by an ACK or NACK.
  5. Master issues STOP.

ACK means the receiver pulled SDA low; NACK means it left SDA high. Clock stretching lets a slow slave hold SCL low and pause the master. Arbitration lets more than one master share the bus: a master that drives high but reads low loses and stops.

Standard I2C runs at 100 kbit/s, fast mode at 400 kbit/s, and fast-plus at 1 Mbit/s. I2C is also written IIC or TWI. SMBus and PMBus are I2C relatives with extra rules.

t = 8B / fSCLK

t is the time for one sample in seconds; B is the number of bytes per sample; fSCLK is the SPI clock in Hz.

The bus load is (t × S) × 100 %, where S is samples per second. The worked example below uses these two relations.

Worked example

Question. An SPI sensor needs 3 bytes per sample. The master takes 100 samples per second and the SPI clock is 2 MHz. Find the SPI time per sample, the bus load as a percentage, and the average bit rate.

  1. Bits per sample = 3 bytes × 8 bits/byte = 24 bits.
  2. Time per sample = 24 bits / 2,000,000 bit/s = 12×10⁻⁶ s = 12 µs.
  3. Total SPI time per second = 12 µs × 100 = 1200 µs = 1.2 ms.
  4. Bus load = 1.2 ms / 1000 ms = 0.0012 = 0.12 %.
  5. Average bit rate = 24 bits × 100 samples/s = 2400 bit/s.

Answer. The SPI transfer takes 12 µs per sample, the bus load is 0.12 %, and the average bit rate is 2400 bit/s.

Exam traps

  • SPI has no address and no ACK, so each slave needs its own SS line; a daisy chain is the alternative, not an address scheme.
  • The I2C 7-bit address is followed by a separate R/W bit; do not call the address 8 bits.
  • I2C lines are open-drain and need pull-up resistors; without them the bus cannot return high.
  • CPOL and CPHA must match at both ends, and mode 0 is only one of modes 0 to 3.
  • I2C is also written IIC or TWI, and SMBus and PMBus are relatives with extra rules, not identical buses.

4.3 CAN and LIN automotive buses

Modern cars contain many small computers. They must share switch states, sensor readings and commands over short wires that survive electrical noise. CAN, the Controller Area Network, is a robust multi-master differential bus for that job. LIN, the Local Interconnect Network, is a cheaper single-wire master-slave sub-bus for windows, mirrors and seats. Their wires, frames, arbitration, error checks and timing decide whether a message arrives in time. A common exam calculation finds a CAN frame time from its bit count and bit rate.

You need: Unit 3 timers and interrupts; 4.2 SPI and I2C buses for master-slave bus ideas.

CAN wires, levels and frame

CAN means Controller Area Network. It is a multi-master serial bus for vehicles. Two twisted wires, CANH and CANL, carry one differential signal. A logic 0 is dominant: the driver pulls the two wires apart. A logic 1 is recessive: the driver releases the bus and a resistor returns the wires together. Dominant always overwrites recessive. The bus needs 120 Ω termination at both ends to absorb reflections. Classic CAN runs at up to 1 Mbit/s; automotive networks commonly use 125 kbit/s, 250 kbit/s, 500 kbit/s or 1 Mbit/s. A node can join or leave without stopping traffic.

A classic CAN data frame has these fields in order: SOF, ID, RTR, IDE, r0, DLC, Data, CRC, ACK, EOF, IFS. SOF is one dominant start bit. ID is the 11-bit standard identifier. The extended format uses a 29-bit ID. RTR marks a data frame or a remote request. IDE selects standard or extended format. r0 is reserved. DLC gives the data length in bytes, 0 to 8. Data is 0 to 8 bytes. CRC checks the frame. ACK is driven by every receiver that saw a good CRC. EOF marks the end. IFS separates frames. CAN FD keeps the same idea but allows up to 64 data bytes.

Arbitration, errors and timing

CAN uses CSMA/CD with bit-wise arbitration (some books call it CSMA/CA). A collision is detected bit by bit and the losing node stops without destroying the frame. A node waits for idle, then sends SOF. All nodes that want the bus send their ID at the same time. A 0 dominates a 1. A node that sends 1 and reads 0 loses arbitration and stops. The frame with the lowest numerical ID wins, because its early 0 bits beat the 1 bits of others. The ID is a priority label, not a destination address. Many nodes may consume the same frame.

T_frame = N_bits / R_bit

T_frame is the frame time in seconds; N_bits is the total frame bits; R_bit is the bit rate in bit/s.

Bit stuffing inserts one opposite bit after five equal bits in SOF to CRC. The receiver removes it. A bit error, stuff error, CRC error, form error or ACK error makes a node send an error frame. Error frames destroy the bad frame so all nodes reject it. A transmitter repeats the frame. A receiver that has a good CRC drives ACK dominant. If no node drives ACK, the transmitter sees an ACK error.

Classic CAN carries at most 8 data bytes. CAN FD carries up to 64 data bytes and can switch to a faster data phase. The arbitration phase stays compatible. At 500 kbit/s one bit lasts 2 µs. At 1 Mbit/s one bit lasts 1 µs. The frame time is the bit count divided by the bit rate.

LIN: cheap master-slave sub-bus

LIN means Local Interconnect Network. It is a cheap single-wire bus that runs at the 12 V battery level. It uses one master and up to 15 slaves. The data rate is up to 20 kbit/s. LIN is not multi-master. The master controls all traffic with a schedule table. The table lists which frame is sent in which time slot. The schedule table gives predictable latency. The sync byte lets each slave measure the bit time, so slaves need no crystal.

A LIN frame has a break, sync, ID, data and checksum. The break is a long low pulse (at least 13 bit times) that marks the start of a new frame. A sleeping node is woken by a separate wake-up pulse, not by the break. Sync is the byte 0x55, used to measure the bit time. ID is a 6-bit identifier plus two parity bits. Data is 1 to 8 bytes. Checksum covers the data and sometimes the ID. Slaves answer only when the master sends their ID. LIN is used for windows, mirrors, seats, wipers and other body functions. CAN links the major controllers; LIN links small body loads under one master.

  • A CAN ID is a priority label, not a destination address. A node may send a frame that many nodes receive.
  • Lower numerical ID wins arbitration. This feels backwards because 0 is dominant. A node sending a larger ID loses.
  • LIN is single-wire master-slave, not multi-master. Only the LIN master starts frames; slaves answer on request.
  • Terminate CAN with 120 Ω at the two physical ends, not at every node.
  • Classic CAN data is 0 to 8 bytes; CAN FD is up to 64. Do not use 64 bytes for classic.

4.4 USB and parallel interfaces

USB is a host-controlled serial bus that replaced messy parallel ports for keyboards, cameras and printers. A host schedules every transfer through a tiered star of hubs, supplies bus power, and uses four transfer types matched to timing needs. Parallel interfaces move many bits at once with handshake lines. Centronics and IEEE 1284 printer ports use STROBE, BUSY and ACK; GPIO parallel ports drive LCDs and keypads. Embedded products use USB for PC links and charging, and parallel ports for simple local devices.

You need: Chapter 4.1 for serial versus parallel and framing; see Unit 1 for processor and interface choices.

USB is a host-controlled, tiered star

USB is a serial bus built around one host. The host owns the bus and starts every transaction; devices answer only when addressed. The physical layout is a tiered star: the host connects to a root hub, hubs branch to more hubs or devices, and the tree can hold up to 127 devices. No device talks directly to another device; all data passes through the host.

Each device exposes endpoints. An endpoint is a buffer with a direction and a transfer type; endpoint 0 is always present for control. Direction names are from the host's view: IN means device-to-host, OUT means host-to-device.

Enumeration, descriptors and speeds

When a device is plugged in, enumeration begins. The host detects the port, resets it, reads the device descriptor through endpoint 0, assigns a unique address, then reads configuration, interface and endpoint descriptors. Descriptors state vendor and product IDs, class, power demand and endpoints. A class driver such as HID or mass storage then binds to the device.

Parallel interfaces: eight bits and a handshake

A parallel interface sends several bits at once over separate wires, plus control lines. The Centronics printer port has eight data lines D0 to D7, a STROBE line, a BUSY line and an ACK line, often on a DB25 connector at the computer.

  1. The host places one byte on D0 to D7.
  2. The host asserts STROBE to say the byte is valid.
  3. The printer asserts BUSY while it takes the byte.
  4. The printer pulses ACK when it is ready for the next byte.
  5. The host removes STROBE and can place the next byte.

IEEE 1284 standardized the port and added faster modes, but its compatibility mode is Centronics. A GPIO parallel port is simpler: a microcontroller writes eight bits to a port register for an LCD, often with a strobe but with no ACK line.

Parallel is not automatically faster. Skew, where bits arrive at slightly different times, crosstalk between wires and many pins limit cable length. IEEE 488, also called GPIB, uses 8-bit parallel with a handshake and up to 15 devices on one bus; it was common for lab instruments, and only a few universities teach its details now.

Worked example

Question. A USB 2.0 full-speed bulk transfer sends a 1 MB file at 12 Mbit/s. Ignore protocol overhead. Find the transfer time in seconds.

  1. Convert 1 MB to bytes: 1 MB = 1,048,576 bytes in binary units.
  2. Convert bytes to bits: 1,048,576 bytes × 8 bits/byte = 8,388,608 bits.
  3. Convert the rate to bits per second: 12 Mbit/s = 12 × 10⁶ bit/s = 12,000,000 bit/s.
  4. Time = bits ÷ rate = 8,388,608 ÷ 12,000,000 = 0.699 s (rounded to three decimal places).

Answer. The 1 MB file takes about 0.699 s at 12 Mbit/s.

Exam traps

  • USB is not peer-to-peer except with OTG. The host schedules all transfers; two devices cannot talk directly.
  • Full speed is 12 Mbit/s and high speed is 480 Mbit/s. Saying USB 2.0 is always 480 Mbit/s ignores full and low speed devices on the same bus.
  • 1 MB is 1,048,576 bytes = 8,388,608 bits, not 8,000,000 bits. Using decimal megabytes changes the transfer time.
  • Parallel sends many bits at once, but it is not a faster UART. Skew and crosstalk limit cable length, and a GPIO parallel port may have no handshake at all.
  • Match the transfer type to the job: keyboard uses interrupt, audio uses isochronous, storage uses bulk, enumeration uses control. Examiners test this matching.

4.5 Wireless: Bluetooth, BLE, ZigBee, Wi-Fi and LoRaWAN

A cable ties a device to one place. A radio frees it, charging for that freedom in range, data rate and battery life. Five links cover most embedded products: Bluetooth Classic for audio and serial replacement, BLE for a coin-cell sensor talking to a phone, ZigBee for a mesh of meters and street lights, Wi-Fi for a camera needing megabits, and LoRaWAN for a water meter two kilometres from a tower. Each sits at a corner of the same trade-off. The requirement picks the technology.

You need: the link trade-offs of UART and RS-232 and the master-slave idea from SPI and I2C.

Four axes: range, rate, power, topology

Every radio link is judged on four axes. Range is how far one hop reaches. Data rate usually means the useful (application) rate; the airtime formula below uses the raw radio rate R, which is higher because of headers, preamble and coding. Power is the current the radio draws in mA, mostly while transmitting but also while listening. Topology is the network shape: one-to-one, a star around one master, or a mesh where nodes forward for each other.

t_air = N / R, duty = t_air / T × 100%

N is packet length in bits; R is raw bit rate in bit/s; t_air is airtime in seconds; T is period between packets in seconds; duty is transmit duty cycle in percent.

Energy per bit: E_b = P_tx / R, where P_tx is transmit power in watts. A 10 mW transmitter at 250 bit/s spends 40 µJ per bit; at 1 Mbit/s it spends 10 nJ. Long range costs joules per bit, so a LoRa node sends twenty bytes and sleeps ten minutes.

Bluetooth Classic and BLE

Bluetooth Classic is a 2.4 GHz frequency-hopping link. It uses 79 channels of 1 MHz and hops 1600 times a second, so a microwave oven or Wi-Fi access point spoils only a slice of time. One master with up to seven slaves forms a piconet. Basic rate is 1 Mbit/s; enhanced data rate reaches 2 to 3 Mbit/s. It carries audio and serial port profile, so a Bluetooth-to-UART module appears as a COM port.

BLE shares the band but not the packet. It uses 40 channels of 2 MHz. Channels 37, 38 and 39 are advertising channels placed between Wi-Fi channels 1, 6 and 11. An advertiser broadcasts a short packet on these channels and a scanner reads it without a connection. That is how a phone sees a fitness band before you pair it.

After connection, data moves through GATT, the Generic Attribute Profile. A server exposes services, each holding characteristics, each a small value with a 16-bit or 128-bit UUID. A client reads or writes a characteristic, or subscribes to notifications, so the sensor pushes a value only when it changes. Between connection events the radio sleeps, and the connection interval can be 7.5 ms to 4 s.

ZigBee, Wi-Fi and sharing 2.4 GHz

ZigBee sits on IEEE 802.15.4: 2.4 GHz, 16 channels, 250 kbit/s, offset QPSK with direct-sequence spreading. Three roles exist. The coordinator forms the network and holds the trust centre; routers have mains power and forward packets; end devices sleep most of the time. Routing is mesh, so if a lamp in a corridor fails, traffic finds another path. Smart meters and street lighting use this shape, because a 30 m hop will never cover a colony.

Wi-Fi, IEEE 802.11, uses 2.4 GHz, 5 GHz and 6 GHz. It gives 54 Mbit/s to a gigabit per second over 30 to 100 m using CSMA/CA: a station listens, waits a random backoff, then transmits. The cost is the receiver. A Wi-Fi station must stay ready for a beacon and can draw 100 mA or more, fine for a camera on mains and wrong for a coin cell.

Bluetooth, ZigBee and Wi-Fi all share 2.4 GHz and interfere. A Wi-Fi transmitter at 20 dBm easily drowns a BLE packet at 0 dBm. Three defences: channel planning, so ZigBee avoids the Wi-Fi channel in use; adaptive frequency hopping in Bluetooth, which drops bad channels; and time sharing, where the coordinator schedules around known traffic.

LoRa and LoRaWAN, and choosing

LoRa is a physical layer, not a network. It sends sub-GHz chirps, 865 to 867 MHz in India, spreading each symbol with a spreading factor SF from 7 to 12. Each step up in SF doubles the symbol time and so doubles the airtime for the same payload, and adds about 2.5 dB to the link budget; that extra margin is what buys the longer range. Range reaches 2 to 15 km in open ground, while the rate drops to a few hundred bit/s.

LoRaWAN is the layer above. A node transmits; every gateway in range forwards the packet to a network server, which removes duplicates and passes it to the application server. A device is not tied to one gateway and there is no pairing. Class A opens two short receive windows after each uplink and is the lowest power; Class B adds scheduled beacon slots for periodic downlink; Class C keeps the receiver on and runs from mains. The Indian band caps transmit power at 400 mW ERP, and LoRaWAN operators usually keep the duty cycle near 1 percent, so payloads stay small.

The choice follows from the requirement. Kilometres and a few bytes: LoRaWAN. Megabits: Wi-Fi. A mesh of mains nodes: ZigBee. A phone in the same room and a year on a coin cell: BLE. Audio or a serial cable replacement: Bluetooth Classic.

Worked example

Question. A soil sensor sends 20 bytes every 10 minutes. Ignoring all protocol overhead, find the airtime and the transmit duty cycle for (a) BLE at a raw rate of 1 Mbit/s and (b) LoRa at 250 bit/s.

Exam traps

  • BLE is not Bluetooth Classic: different packet, channels, no serial port profile or audio; not interchangeable at application level.
  • LoRa is the chirp physical layer; LoRaWAN is the network protocol. A LoRa radio without LoRaWAN has no addressing, gateways or device classes.
  • Wi-Fi is not a low-power sensor link. The receiver draws tens to hundreds of mA waiting for a beacon, so a coin cell lasts days, not years.
  • Sharing 2.4 GHz does not make radios compatible. BLE, ZigBee and Wi-Fi use different modulation, channel widths and MAC rules, and interfere.
  • Duty cycle slips: 0.1067 is a percentage, 0.001067 is a fraction. Write the unit every time.

4.6 IoT architecture and protocols

An IoT system turns many small sensor readings into useful actions. It does this by stacking four layers: perception devices, a network, middleware and applications. The device layer reads sensors and drives actuators. The network layer carries bytes over Wi-Fi, LoRaWAN or 6LoWPAN. The middleware layer stores and routes data, often through a broker or cloud service. The application layer makes decisions and shows results. MQTT and CoAP are the two common data protocols: MQTT publishes through a broker over TCP, while CoAP sends requests over UDP. This chapter shows how the layers fit and how to size their traffic.

You need: Chapter 4.5 for wireless links, and Chapters 4.1 to 4.4 for device links.

Four layers from sensor to screen

An IoT (Internet of Things) system connects physical things to software. A temperature sensor, a water-level probe or a motor relay gets a small processor and a network interface. The standard model has four layers. The perception layer, or device layer, holds sensors, actuators and the microcontroller that reads them. The network layer moves bytes using Wi-Fi, LoRaWAN, 6LoWPAN or a wire. The middleware layer sits between the network and user software: a message broker, database or cloud rule engine. Some syllabi call this the processing layer. The application layer is the dashboard, mobile app or billing system.

Data flows up: sensor → network → middleware → application. Commands flow down. A water-level sensor on an apartment tank can report every minute; the middleware stores the reading; the application switches off the pump at 95%. Edge computing puts a small processor near the sensor to filter data before sending. The cloud keeps long history and runs heavy rules. Layering lets you replace the radio without rewriting the app.

The figure shows the four layers and example protocols. MQTT and CoAP sit at the application layer even though they carry sensor data; they use the network layer below.

MQTT: publish, subscribe, broker

MQTT (Message Queuing Telemetry Transport) is a publish-subscribe protocol. A device does not send directly to another device. It connects to a broker, a server that receives messages and forwards them. A publisher sends to a topic, a text name such as home/tank/level. A subscriber asks the broker for that topic. The broker matches them. The publisher does not know who listens.

MQTT runs over TCP (Transmission Control Protocol), so the connection is reliable and ordered. A client sends CONNECT; the broker replies CONNACK. PUBLISH carries a topic and payload. SUBSCRIBE registers interest. Small keepalive messages hold the connection open.

QoS (quality of service) sets delivery effort. QoS 0 sends once and forgets; a message can be lost. QoS 1 delivers at least once; the receiver acknowledges, so duplicates can happen. QoS 2 delivers exactly once using a four-step handshake; it costs the most. Choose QoS 0 for frequent harmless readings, QoS 1 for alarms, QoS 2 for billing events.

CoAP, HTTP and IPv6 for small devices

CoAP (Constrained Application Protocol) is a request-response protocol for small devices. It uses UDP (User Datagram Protocol), not TCP. A client sends a request to a server URI, such as coap://tank/level. The methods are GET (read), POST (create), PUT (replace) and DELETE (remove), the same idea as HTTP. The server replies with a code and payload. Because UDP has no connection, CoAP adds message IDs, retransmission timers and optional confirmable messages. A confirmable request gets an ACK; a non-confirmable request does not. CoAP headers are a few bytes, not hundreds.

HTTP (Hypertext Transfer Protocol) runs over TCP, so it gives ordered, reliable delivery. It is easy to debug and passes through firewalls. Its text headers and TCP handshake are heavy for a battery sensor sending 50 bytes every minute. Use HTTP when the device has mains power and a full TCP/IP stack, or when data must reach a normal web API.

6LoWPAN (IPv6 over Low-Power Wireless Personal Area Networks) makes IPv6 fit on IEEE 802.15.4 frames. It compresses the 40-byte IPv6 header to a few bytes. RPL (Routing Protocol for Low-Power and Lossy Networks) builds a tree of routes so packets reach a border router. Together they let a small sensor run IPv6 and CoAP.

Security: TLS (Transport Layer Security) protects TCP streams such as MQTT and HTTP. DTLS (Datagram TLS) protects UDP datagrams such as CoAP. DTLS keeps TLS's handshake but handles loss and reordering.

Worked example

Question. An IoT deployment has 100 sensors. Each sensor sends one 50-byte payload every 60 s. The payload excludes protocol headers. Find (a) total payload data per day in bytes and megabytes (use 1 MB = 1,000,000 bytes), and (b) the average payload bit rate in bit/s.

Exam traps

  • MQTT is not direct device-to-device. Every message goes through the broker; the publisher sends to a topic, not to a subscriber's address.
  • CoAP runs over UDP. It adds retransmission for confirmable messages, but it does not give TCP's ordered byte stream; do not say CoAP is HTTP over UDP with TCP reliability.
  • QoS 1 is at least once, not exactly once. Duplicates are possible; QoS 2 is the exactly-once level.
  • 6LoWPAN is an adaptation layer that compresses IPv6; RPL is the routing protocol. They are not the same layer.
  • TLS protects TCP (MQTT, HTTP); DTLS protects UDP (CoAP). Writing TLS for CoAP or DTLS for MQTT loses marks.

4.7 On-chip buses: AMBA, AHB and APB

Inside a chip the CPU, memory and peripherals must move data without leaving the package. AMBA — Advanced Microcontroller Bus Architecture — is ARM's family of standards for that internal wiring. AHB (Advanced High-performance Bus) carries fast traffic such as CPU-to-memory and DMA. APB (Advanced Peripheral Bus) carries slow, cheap traffic to UART, SPI, GPIO and timers. AMBA also names AXI at the high end. Almost every ARM-based chip — a phone, a set-top box, a car body controller — is stitched together with these buses, so their timing decides the system's throughput.

You need: the master-slave idea and synchronous transfers from 4.2, and the ARM core from Unit 2.

Why a chip needs its own bus

A board bus such as SPI or I2C (4.2) crosses copper traces on a PCB and costs package pins. Inside a chip the wires are short, wide and pin-free, so the rules change: no line drivers, no termination, a fast synchronous clock, and 32 or 64 bits moved at a time.

AMBA — Advanced Microcontroller Bus Architecture — is ARM's family of standards for these internal buses. Three names matter. AHB (Advanced High-performance Bus) carries fast traffic. APB (Advanced Peripheral Bus) carries slow traffic to simple peripherals. AXI is the high-end member with separate read and write channels; only a few universities teach it, so treat it as a name here.

Four roles repeat on every AMBA bus. A master starts a transfer (the CPU, a DMA engine). A slave answers it (memory controller, UART). An arbiter decides which master owns the bus next. A decoder reads the address and selects which slave is being addressed.

AHB: pipelined, bursty, multi-master

AHB splits every transfer into an address phase, where the master drives HADDR, HTRANS and HWRITE, and a data phase, where HWDATA is written or HRDATA is read. It is pipelined: the address phase of transfer N+1 runs while the data phase of transfer N is still in progress. After one filling cycle, one transfer completes per clock.

  1. Master requests the bus; the arbiter grants it with HGRANT.
  2. Master drives the address and control lines (address phase).
  3. Decoder decodes the address and selects one slave.
  4. Next clock, the data phase runs: HWDATA out on a write, HRDATA in on a read.
  5. Slave raises HREADY when it finishes. Holding HREADY low inserts wait states, which stretch the data phase and freeze the pipeline.
  6. HRESP reports OKAY in a single cycle. ERROR takes two cycles, and so do the SPLIT and RETRY responses that a slave uses when it cannot finish at once.

Bursts are the bandwidth trick. HBURST (burst type and length) and HSIZE (bytes per beat) let the master send several beats back to back, but each beat still has its own address phase: the master drives the incremented (or wrapped) address for the next beat while the current data phase runs, so no clock is wasted. Because a burst must not cross a 1 KB boundary, the decoder's slave select stays the same for the whole burst and the slave can prepare the following beats. Sending one start address and letting the slave count is AXI, not AHB.

APB: two phases, no pipeline

APB is deliberately plain: no arbiter, no bursts, no pipelining, one master only. Every transfer takes two phases.

  1. Setup phase: the bridge drives PSEL, PADDR, PWRITE and, for a write, PWDATA; PENABLE stays low.
  2. Access phase: PENABLE goes high.
  3. The slave asserts PREADY when done and the transfer ends. PSLVERR flags an error.
  4. Minimum cost: two clock cycles per transfer.

APB normally sits behind an AHB-to-APB bridge. The bridge is a slave on AHB and the only master on APB; it converts one AHB transfer into one setup plus access, holding HREADY low meanwhile. UART, SPI, GPIO and timers hang off APB. They are slow and rarely accessed, so two cycles cost little, and the simple logic saves gates and power; the APB clock is often a divided-down copy of the AHB clock.

Turning timing into bandwidth

B = (W ÷ 8) ÷ T

B is bandwidth in bytes per second; W is the data width in bits per transfer; T is the time for one transfer in seconds.

APB needs T = 2 ÷ f_APB, because of the two phases. A pipelined AHB in steady state needs T = 1 ÷ f_AHB, one beat per clock. Two cautions. Wait states push T above the ideal, so the result is a ceiling, not a measurement. And APB usually runs slower than AHB, so the real gap is wider than the 2:1 that cycle counts alone suggest.

Worked example

Question. An APB runs at 50 MHz and takes two clock cycles per transfer (setup plus access). Each transfer moves 32 bits. Find the time per transfer and the theoretical bandwidth. Compare with a 32-bit AHB at 100 MHz that moves one beat per cycle. Use 1 MB = 10⁶ bytes.

  1. APB clock period = 1 ÷ 50,000,000 Hz = 20 ns.
  2. APB transfer time T = 2 cycles × 20 ns = 40 ns.
  3. Bytes per transfer = 32 ÷ 8 = 4 bytes.
  4. APB bandwidth = 4 bytes ÷ 40 ns = 4 ÷ (40 × 10⁻⁹) B/s = 100 × 10⁶ B/s = 100 MB/s.
  5. AHB clock period = 1 ÷ 100,000,000 Hz = 10 ns; one beat per cycle gives T = 10 ns.
  6. AHB bandwidth = 4 bytes ÷ 10 ns = 400 × 10⁶ B/s = 400 MB/s.
  7. Ratio = 400 ÷ 100 = 4. The AHB wins twice from clock (2×) and twice from pipelining (2×).

Answer. APB: 40 ns per transfer and 100 MB/s. AHB: 10 ns per transfer and 400 MB/s, four times the APB bandwidth.

Exam traps

  • APB always costs at least two cycles. Writing T = 1/f_APB for an APB transfer is the most common slip.
  • AHB pipelining does not mean two cycles per transfer. Address and data phases overlap, so steady state is one transfer per clock.
  • An AHB burst is not one address followed by slave-counted beats. Each beat has its own address phase, driven by the master while the previous data phase completes.
  • Clock frequency is not bandwidth. Bandwidth = (bits ÷ 8) ÷ time per transfer; forgetting the ÷ 8 gives an answer eight times too large.
  • HREADY low (AHB) or PREADY low (APB) adds wait states, so the computed bandwidth is an upper bound, not the observed figure.
  • A split response is not an error. It frees the bus for other masters; errors come on HRESP.

Analyze A slow memory on AHB takes 20 cycles per access. Explain how a split response helps a second master. 5 marks

Without split, the slow slave holds HREADY low and freezes the whole bus for 20 cycles. With split, it releases the bus, the arbiter grants it to the other master, and the slave signals when its data is ready so the first master retries. Bus utilisation rises; latency per access does not fall.

Understand What does HREADY control, and what happens to the pipeline when it is low? 3 marks

HREADY tells the master the current data phase is complete. When a slave holds it low, the data phase stretches, and because the phases overlap, the following address phase is also held, so the pipeline stalls until HREADY rises.

Takeaways

  1. A UART sends bytes asynchronously using a start bit, data bits, an optional parity bit and a stop bit; RS-232 only adds the voltage rules and connector for that bit stream.
  2. SPI is fast and simple but needs one chip-select wire per slave, while I2C uses two wires in total and pays for it with lower speed and addressing overhead.
  3. CAN lets several nodes share one differential pair because dominant bits override recessive bits, so collisions become arbitration, not data loss.
  4. LIN is a cheap single-wire sub-bus under a CAN gateway; it does not compete with CAN, it extends it to low-cost switches and motors.
  5. USB puts all bus control in the host, so a device never transmits unless the host polls it through an endpoint and a defined transfer type.
  6. Parallel interfaces move a whole word per clock or handshake, which is fast but needs many wires and short distances.
  7. Wireless choice is a trade between range, data rate, power and topology; no single radio wins on all four.
  8. IoT systems are layered: perception layer sensors, network layer links, middleware layer brokers and storage, application layer services; MQTT and CoAP sit in the transport-and-above region that carries the data.
  9. AMBA splits on-chip traffic into AHB for high-speed pipelined masters and APB for slow peripherals, with an arbiter granting the bus and a decoder selecting the slave.

Exam question bank

Long answers usually ask for a labelled frame or timing diagram, a written comparison table across two or three buses, and a short justification of the bus chosen for a stated product, so practise drawing the diagrams quickly and naming each signal line.

Remember and understand

Understand Explain the frame format of an asynchronous UART byte with 8-N-1 framing. Name each bit, give its purpose, and state the byte rate when the baud rate is 9600 bit/s. 8 marks

Idle line held high; falling edge of start bit begins the frame; One start bit (0), eight data bits least significant first, no parity, one stop bit (1); Total 10 bit times per byte, so 9600 ÷ 10 = 960 bytes per second; Receiver samples near the middle of each bit; mismatch between the two clocks limits how many bits may be framed together; Optional parity bit gives single-bit error detection only.

Understand Compare SPI and I2C on number of wires, speed, addressing, and multi-master capability. Draw the wire connections for one master with three slaves on each bus. 8 marks

SPI: 3 shared lines plus one chip select per slave; I2C: 2 lines total (SDA, SCL); SPI typically tens of Mbit/s; I2C 100 kbit/s standard mode, 400 kbit/s fast mode; SPI selects by hardware chip-select line, no addressing; I2C uses a 7-bit address plus read/write bit; I2C has acknowledge bits and clock stretching, and supports multi-master with arbitration; Draw SPI slaves in parallel with separate CS lines; I2C slaves in parallel on the same two wires, each with pull-up resistors.

Understand Explain why CAN uses a differential twisted pair and define dominant and recessive bits. Show how bit-wise arbitration decides which of two nodes continues transmitting. 8 marks

Two wires, CAN_H and CAN_L; the receiver reads the difference, so common-mode noise cancels; Logic 0 dominant, logic 1 recessive; wired-AND behaviour on the bus; Every node listens while it transmits and backs off on the first mismatch; Frame identifier decides priority: lower numeric identifier has more leading dominant bits and wins; Losing node becomes a receiver and retries later; no data is destroyed.

Understand List the layers of an IoT architecture and state the job of each, giving one protocol or device type found at each layer. 8 marks

Perception layer: sensors and actuators, signal conditioning, device firmware; Network layer: links and gateways (Wi-Fi, BLE, LoRaWAN, cellular), addressing and routing; Middleware layer: broker, message store, device registry, data cleaning; Application layer: dashboards, analytics, user services; Name MQTT or CoAP for the messaging that crosses network and middleware.

Apply

Apply A master must read four I2C temperature sensors on one board, but two of them are fixed at the same 7-bit address. Describe the problem and give two practical fixes, with the wiring change each needs. 12 marks

Address is set by the device, so two slaves answering the same address both drive SDA and the data is corrupted; Fix one: use an I2C multiplexer; master selects a channel before addressing the sensor; Fix two: put the duplicates on separate buses from separate master pins; Mention that many sensors have address-select pins that must be strapped differently at layout time; State the acknowledge behaviour that reveals a conflict.

Apply Design a 500 kbit/s CAN network for a car with five nodes spread over about 20 m. Specify the wire, the termination, and describe step by step what happens when two nodes start sending at the same instant. 13 marks

Twisted pair, 120 Ω characteristic impedance, 120 Ω resistor at each physical end of the bus, not at every node; Stub lengths kept short; common ground reference; Both nodes send SOF, then compare identifier bits while listening; The node sending a recessive bit while the bus shows dominant loses and switches to receive; Winner finishes the frame; loser retries after the intermission; error counters and error frames protect the bus.

Apply A UART link runs at 9600 bit/s with 8-N-1 framing between two boards clocked from different crystals. Calculate the byte rate, and explain what happens on the tenth bit if the receiver clock is 3 % fast. 12 marks

10 bits per byte, so 960 bytes per second, about 1.04 ms per byte; Receiver samples at the middle of bit 0 and then every 10 bit times; 3 % error accumulates across the frame, so the last sample drifts by roughly 3 % of 10 bits, about 0.3 bit time, still inside the bit; State the rule that total mismatch must stay well under half a bit time across the frame; Note that parity or a checksum catches the errors that do get through.

Apply A housing society wants water-meter readings from 400 flats once every 30 minutes, on battery, with no per-flat internet connection. Choose a wireless technology and an application protocol, and justify both. 13 marks

Requirement: low data rate, long range through concrete, years of battery life, many nodes; LoRaWAN fits: kilometres of range, tiny payloads, class A duty cycling; Alternatively BLE or ZigBee with a per-block gateway if the block is small; state the trade; Use a concentrator gateway per block feeding the internet; CoAP or MQTT-SN over the constrained link, MQTT to the cloud broker; Say why Wi-Fi is rejected: power and access-point load.

Apply Draw and explain a single AHB read burst of four beats. Label the address phase, the data phase, HREADY, and say where the arbiter and decoder act. 13 marks

Master drives HADDR and control in the address phase, then the slave's data comes back one cycle later in the data phase; Pipelining means the next address is issued while the previous data is still on the bus; Decoder uses HADDR to assert the correct HSELx; only that slave responds; Arbiter grants HGRANT to one master at a time and the granted master drives HTRANS; HREADY low inserts wait states in both phases; bursts of four beats keep the bus busy.

Analyze and evaluate

Analyze Compare USB and IEEE 488 as ways to connect instruments to a controller. Discuss topology, cable length, addressing, and why USB displaced the older bus in most labs. 13 marks

USB: tiered star through hubs, host-controlled polling, endpoints and four transfer types, up to a few metres per cable segment; IEEE 488: parallel party-line bus, 8 data lines plus handshake and control lines, up to 15 devices, short cable runs, slow by modern standards; Addressing: USB assigns addresses by enumeration; IEEE 488 uses dip-switch addresses on the bus; USB is cheap, hot-pluggable, powered from the bus and universal on PCs; IEEE 488 survives where a deterministic parallel handshake and mature instrument command sets matter.

Analyze A sensor node wakes every few minutes, sends a few hundred bytes, and sleeps. Compare MQTT over TCP with CoAP over UDP for this node. Recommend one and justify it in terms of power, reliability and the role of the broker. 13 marks

MQTT: long-lived TCP connection, keep-alive traffic, broker decouples publishers and subscribers, three quality-of-service levels; CoAP: UDP, short request/response, confirmable messages give retransmission without a standing connection, works with sleepy nodes; Power: MQTT keep-alives and TCP handshake cost energy; CoAP fits short bursts better; Reliability: TCP head-of-line blocking on a lossy radio link versus CoAP's own retransmission and optional observe; Recommend CoAP at the device with a gateway translating to MQTT for the cloud broker; or MQTT-SN.

Evaluate An industrial product must link eight sensor boxes spread over 30 m in a plant with heavy motor noise. Evaluate RS-232, RS-485-style differential links, and CAN for this job, and justify one choice with bus, wiring and protocol details. 14 marks

RS-232 is single-ended, short range and referenced to a common ground; noise couples into the signal, so it is rejected; CAN is differential twisted pair, has built-in arbitration, error detection and retransmission, and is well supported by microcontrollers; State the distance-versus-bit-rate trade of a differential pair and the 120 Ω termination rule; Say what CAN gives that a plain differential link does not: framing, priorities, error confinement; Add that higher-layer choices (a CAN application profile or a simple master-slave protocol) follow from this decision.

Evaluate Explain the roles of the arbiter and the decoder in AMBA. Argue why an SoC with an AHB segment and an APB segment needs a bridge between them, and what would go wrong without proper arbitration. 13 marks

Decoder: address-to-select, picks exactly one slave per transaction; Arbiter: grants the bus to one master, prevents two masters driving the shared address and data lines; Bridge holds AHB and APB timing apart, converts pipelined AHB to the simple APB setup and enable phases, and inserts wait states; Without arbitration two masters drive the bus and burn power or corrupt data; APB peripherals are slow, so the bridge's wait signalling is what keeps the fast side running correctly.

Glossary

Arbitration
The process that decides which of several devices may use a shared bus or medium at a given moment.
Asynchronous
A link with no shared clock wire, where timing is recovered from the data itself.
Bit stuffing
Inserting an opposite bit after a run of identical bits so a receiver can keep its clock aligned, as CAN does after five equal bits.
Bridge
A block that connects two different buses and translates their timing and signalling rules.
Broker
A server that receives published messages and forwards each one to the clients subscribed to its topic.
Clock stretching
An I2C slave holding the clock line low to make the master wait until the slave is ready.
Differential signalling
Sending a signal as the voltage difference between two wires so that noise common to both wires cancels out.
Frame
A complete, delimited unit of transmission that carries one or more data bytes plus control bits.
Full duplex
A link that can carry data in both directions at the same time, as SPI and UART do.
Gateway
A device that joins two networks using different protocols and translates between them.
Handshake
A pair of ready and accept signals that lets a sender and receiver agree when data is valid.
Master and slave
The device that starts and controls a transfer, and the device that answers it.
Mesh topology
A network where nodes forward each other's messages, so a message can travel further than one radio hop.
Parity bit
A single extra bit that makes the number of 1s in a byte odd or even, catching some single-bit errors.
Publish/subscribe
A messaging pattern where senders publish to a topic and receivers subscribe to topics, never addressing each other directly.
Recessive bit
The CAN bit level that loses to the opposite level when two nodes transmit different values at the same time.
Stop bit
The trailing 1 bit of a UART frame that marks the end of the byte and allows a gap before the next start bit.
Termination resistor
A resistor at the physical end of a bus that absorbs the signal energy and stops reflections.
Topic
A named string in a publish/subscribe system that decides which messages reach which subscribers.
Topology
The arrangement of the connections between nodes: bus, star, ring, mesh, or point to point.
Twisted pair
Two insulated wires twisted together so that noise and crosstalk affect both wires almost equally.
Wait state
An extra clock cycle inserted by a slow slave to delay the completion of a bus transfer.
