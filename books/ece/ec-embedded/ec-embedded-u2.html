2.1 8051 architecture and special function registers

The 8051 is an 8-bit microcontroller from the early 1980s that still runs small dedicated jobs: a washing-machine timer, a lift button panel, a lab board. Its CPU has no large register file. Most of its status and control registers sit at high data-memory addresses, 80H to FFH, called special function registers (SFRs). A program reads and writes them like ordinary memory cells. Knowing this map tells you where the accumulator, the flags, the stack pointer and the port latches actually live, and why a bank switch changes what R0 means.

You need Unit 1: what a microcontroller is, and the Harvard and von Neumann ideas about program and data memory.

What is inside the chip

The classic 8051 and 89C51-type parts put five units on one die: an 8-bit CPU; 4 KB of on-chip program memory (ROM or flash); 128 bytes of internal data RAM; four 8-bit ports, that is 32 input/output lines; and two 16-bit timers plus one serial port (UART). Five interrupt sources feed the CPU. The AT89S52 is an 8052-type part with 8 KB flash, 256 bytes RAM, three timers and six interrupt sources.

Program memory and data memory are separate address spaces. That is the Harvard idea: the same address, such as 0000H, can exist in both spaces, and the instruction tells you which space is meant. The classic core does not have two independent buses running at once; Harvard here means separate memories, not a dual-bus pipeline.

After reset the program counter is 0000H, so the first instruction of the program must sit at program address 0000H. Internal RAM is only 128 bytes, at 00H–7FH. An external bus can add up to 64 KB of program memory and 64 KB of external data memory, but small programs stay inside the chip.

Derivatives differ. 8052-type parts have 256 bytes of RAM, 8 KB of ROM and a third timer. Read the part number and the datasheet before you count bytes.

Internal RAM: banks, bit addresses, stack

Internal RAM 00H–7FH has three regions.

  • 00H–1FH: four register banks of 8 bytes. Bank 0 is 00H–07H, with R0 at 00H and R7 at 07H. Bank 1 is 08H–0FH, bank 2 is 10H–17H, bank 3 is 18H–1FH.
  • 20H–2FH: 16 bytes that are bit-addressable, giving 128 individually settable bits, numbered 00H–7FH in bit space.
  • 30H–7FH: 80 bytes of plain read/write RAM, and the stack.

Only one bank is active at a time. Two bits in PSW, RS1 and RS0, choose it. So MOV R3,#5 does not name a fixed address: it writes the fourth byte of the selected bank. Switching banks is a cheap way to answer an interrupt without saving R0–R7; the handler selects an unused bank and works there.

The stack sits in the same RAM and grows upward. A PUSH first increments SP, then stores. After reset SP = 07H, so the first push writes to 08H and destroys bank 1's R0. Any program with calls or interrupts must move SP first, for example to 30H.

The special function registers, 80H–FFH

Addresses 80H–FFH hold the special function registers. They are memory-mapped: MOV P1,A writes the port latch, MOV A,P1 reads the pin state, and read-modify-write instructions read the latch. Each SFR is one byte with a fixed address.

Two rules. SFRs whose address ends in 0H or 8H are bit-addressable: ACC, B, PSW, P0–P3, TCON, SCON, IE, IP. One bit of such a register can be set or cleared on its own. DPTR is not one register: it is the 16-bit pair DPH:DPL, loaded with MOV DPTR,#1234H or changed one byte at a time.

The program counter is not an SFR. You cannot read or write PC as a memory cell; it moves only by fetch, jump, call and return.

PSW and the bank select bits

PSW at address D0H carries the flags and the bank bits.

  • bit 7 CY: carry
  • bit 6 AC: auxiliary carry out of bit 3, used by decimal adjust after BCD addition
  • bit 5 F0: general-purpose flag, free for the programmer
  • bit 4 RS1 and bit 3 RS0: register-bank select
  • bit 2 OV: overflow
  • bit 1: F1 user flag (reserved on some variants)
  • bit 0 P: parity of ACC, 1 when ACC holds an odd number of ones

bank base address = 8 × (2 × RS1 + RS0)

RS1 and RS0 are PSW bits 4 and 3; the result is the RAM address of R0 in the active bank, from 00H for bank 0 to 18H for bank 3.

Writing 08H to PSW clears CY, AC, F0, F1 and OV and sets RS0, so the very next instruction sees bank 1 as the live bank. P is updated by hardware from ACC and is not forced by the write.

Worked example

Question. A program starts with MOV PSW,#08H followed by MOV R0,#2AH. (a) Which register bank is selected? (b) At what internal RAM address does R0 sit? (c) At which RAM address is the value 2AH stored, and what is that value in decimal?

  1. PSW = 08H. In binary, 08H = 0000 1000.
  2. RS1 is bit 4 = 0. RS0 is bit 3 = 1. So RS1:RS0 = 01.
  3. RS1:RS0 = 01 selects bank 1.
  4. Bank base = 8 × bank number = 8 × 1 = 8 = 08H.
  5. R0 is the first register of the bank, offset 0, so R0 is at 08H + 0 = 08H, that is decimal 8.
  6. MOV R0,#2AH writes the byte 2AH into that address. 2AH = 2 × 16 + 10 = 42 in decimal.
  7. So the byte 2AH sits at internal RAM address 08H, which is also bank 1's R0.

Answer. Bank 1 is selected, R0 sits at 08H (decimal 8), and the value 2AH = 42 decimal is stored at that address.

Exam traps

  • R0 is not a fixed address. After PSW = 08H, MOV R0,#2AH stores at 08H, not at 00H.
  • DPTR is not one SFR: it is the pair DPH:DPL at 83H and 82H. The program counter is not in SFR space and cannot be read as a byte.
  • Reset SP = 07H, so the first PUSH lands on 08H and destroys bank 1's R0. Move SP to 30H or higher before using the stack.
  • Changing RS1:RS0 moves no data. The byte 2AH stays at 08H; it simply stops being reachable as R0.
  • Not every SFR is bit-addressable; only those whose address ends in 0H or 8H are.

2.2 PIC microcontroller architecture

The PIC16F877A is an 8-bit microcontroller from the mid-range PIC family. It keeps program and data in separate memories (Harvard), uses 14-bit instruction words and offers only 35 instructions. The address field inside an instruction is only 7 bits, so it can name 128 locations out of the 368-byte data RAM; RP1:RP0 in STATUS supply the missing high bits and split the RAM into four banks. A two-stage pipeline fetches the next instruction while the present one executes. You find such chips in energy meters, battery chargers, washing machines and small card readers, where a cheap part must read sensors, count pulses and switch outputs.

You need: Chapter 2.1 and the Harvard and RISC ideas from Unit 1.

Data path, instruction word and pipeline

The core is 8 bits wide. All arithmetic and logic happens in the ALU, which takes one operand from the working register W and the other from a file register in data memory, or, for the literal instructions (MOVLW, ADDLW, ANDLW, IORLW, XORLW, SUBLW, RETLW), from the 8-bit operand field inside the 14-bit instruction word. The result goes back to W or to the file register, and the destination bit of the instruction chooses which.

Harvard separation matters here. Program memory has its own 14-bit bus and data memory has an 8-bit bus, so an instruction fetch and a data read can happen together, and code can never be overwritten by a stray pointer. Every instruction is exactly one 14-bit word: a 6-bit opcode plus up to 8 bits of operand. The whole instruction set is 35 instructions.

The pipeline has two stages. While an instruction executes, the next one is fetched. That is why an instruction takes one instruction cycle, written Tcy, where Tcy = 4 × TOSC. A 4 MHz crystal gives TOSC = 0.25 µs and Tcy = 1 µs. When a jump or call is taken, the word already fetched is wrong, so it is discarded and the pipeline refills: that instruction costs 2 Tcy.

Program memory, banks and the hardware stack

Program memory is 8K × 14 flash: 8192 words of 14 bits, addressed from 0000H to 1FFFH. Two addresses are fixed by hardware. After reset the CPU starts at 0000H; an interrupt sends it to 0004H. Put a jump at 0000H, and your interrupt routine or a jump to it at 0004H. The 8-level hardware stack stores return addresses only; it is not for data.

Data memory is 368 bytes of RAM, plus 256 bytes of EEPROM for values that must survive a power cut. The RAM is split into four banks of up to 128 bytes. A direct address inside an instruction is only 7 bits, so it can name a cell within one bank but cannot say which bank. The bits RP1:RP0 in STATUS choose the bank.

  • W: the working register. It is not in data memory and has no address.
  • STATUS, address 03H: holds RP1, RP0, IRP, the zero flag Z, digit carry DC and carry C.
  • FSR, 04H: an 8-bit pointer used for indirect addressing.
  • INDF, 00H: reading or writing INDF actually touches the cell that FSR points to.
  • PCL, 02H, and PCLATH, 0AH: PCL is the low 8 bits of the program counter; PCLATH holds the upper bits and must be written before a computed jump.

Indirect addressing ignores RP1:RP0. FSR supplies the low 7 bits and its bit 7 picks one bank of a pair, while IRP (bit 7 of STATUS) picks the pair: IRP = 0 means banks 0 and 1, IRP = 1 means banks 2 and 3. So FSR = A0H with IRP = 1 reaches physical address 1A0H in bank 3.

What sits on the chip

The 16F877A is a 40-pin part. Around the core sit the blocks that make it a microcontroller rather than a CPU.

  • Timer0 (8-bit), Timer1 (16-bit) and Timer2 (8-bit) for timing and counting pulses.
  • CCP modules: capture an edge, compare against a value, or generate PWM.
  • MSSP: a synchronous serial port for SPI and I2C.
  • USART: asynchronous serial, for a PC link or a radio module.
  • A 10-bit ADC with 8 input channels, so an analog sensor reads as a number from 0 to 1023.
  • Ports A to E, 33 I/O pins in total, each pin's direction set by a TRIS register.

Timers, interrupts, PWM and the ADC are detailed in Unit 3; SPI, I2C and UART frames are in Unit 4. Here you only need this: these blocks hang off the same 8-bit data bus and appear as file registers in banks 0 and 1.

Changing banks in a real program

Bank switching is the step where marks are lost, so do it in a fixed order. Instruction syntax is covered in Chapter 2.6.

  1. Decide the target bank and the 7-bit address of the register inside it.
  2. Set or clear RP1:RP0 in STATUS, for example BSF STATUS,RP0 to reach bank 1.
  3. Access the register by its 7-bit address; hardware adds the bank bits for you.
  4. Repeat for every other bank you touch. The RP bits stay where you left them.
  5. Restore the original RP1:RP0 before returning, if the calling code expects that bank.

Two common bugs. A subroutine changes RP0 and returns without restoring it, so the caller's next write lands in the wrong bank. Or PCLATH is not updated before a computed jump, and the jump lands on the wrong 2K page.

Worked example

Question. A program on a PIC16F877A writes the value 21H into the STATUS register. (a) Which data-memory bank is selected for direct addressing? (b) Which bits of RP1:RP0 are set, and which arithmetic flag is set? (c) Give 21H in decimal.

  1. Write 21H in 8-bit binary: 21H = 0010 0001.
  2. The STATUS bit order is IRP(7), RP1(6), RP0(5), TO(4), PD(3), Z(2), DC(1), C(0).
  3. Read the writable status bits from the written value: IRP = 0, RP1 = 0, RP0 = 1, Z = 0, DC = 0, C = 1. TO (bit 4) and PD (bit 3) are read-only; a write to STATUS does not change them. After power-up or a CLRWDT both are 1, so they keep TO = 1 and PD = 1 rather than taking 0 from 21H.
  4. RP1:RP0 = 01, so the bank number is 0×2 + 1 = 1. Direct addresses in the instruction now refer to data bank 1.
  5. C = 1, so the carry flag is set; Z = 0 and DC = 0.
  6. Convert to decimal: 21H = 2 × 16 + 1 = 33.

Answer. RP1:RP0 = 01 selects data bank 1, the carry flag C = 1 is set, and 21H = 33 decimal.

Exam traps

  • W has no address. It is not in the data memory map, so you cannot reach it with FSR or with a bank bit; only the destination bit of an instruction names it.
  • RP1:RP0 select the bank for direct addressing only. Indirect addressing through INDF uses IRP plus bit 7 of FSR, and ignores RP1:RP0.
  • 14-bit is the instruction width, 8-bit is the data width. Writing that the PIC has a 14-bit data bus is a common wrong answer.
  • The 8-level hardware stack holds return addresses only, pushed by CALL and by an interrupt; it is not for data. Data must be pushed by hand into RAM, not into this stack.
  • A taken branch costs 2 Tcy, not 1. The pipeline overlaps fetch with execute but does not remove the refill cost after a jump.

2.3 ARM architecture: registers, modes and pipeline

ARM is a RISC processor family. An ARM7-class core has sixteen visible 32-bit registers, a current status register, saved status copies in exception modes, and a three-stage pipeline. The design keeps instructions simple and fast, and lets an interrupt or fault switch to a private register bank quickly. You meet it in phone chips, car controllers, routers and microcontroller boards. This chapter covers the visible registers, the processor modes, and why the program counter reads ahead.

You need: the pipeline idea from Chapter 2.2 and RISC versus CISC from Unit 1.

Registers you can name

An ARM7TDMI implements the ARMv4T architecture. The name packs features: ARM7 core, Thumb, debug support and a multiplier. ARMv4T defines two instruction states: 32-bit ARM state and 16-bit Thumb state. The T bit in the status register selects the state.

An ARM7TDMI in ARM state sees sixteen 32-bit registers, R0 to R15. Each holds one 32-bit word. R0 to R12 are general purpose: arithmetic, load/store and address work use them freely. Three have agreed roles. R13 is the stack pointer (SP): it holds the address of the top of the current stack. R14 is the link register (LR): a branch with link writes the return address there. R15 is the program counter (PC): it holds the address of the instruction being fetched. SP, LR and PC are conventions; the hardware treats them as R13, R14 and R15.

Two status registers matter. The current program status register (CPSR) holds condition flags and control bits for the running program. The saved program status register (SPSR) holds a copy of CPSR when an exception occurs; it exists only in exception modes, not in User or System mode. Four CPSR flags record the last result: N means negative, Z means zero, C means carry or borrow, and V means signed overflow. Control bits include I, which disables IRQ when set, F, which disables FIQ when set, and T, which selects Thumb state when set. T = 0 means 32-bit ARM state.

Modes and banked registers

An ARM7 core has seven processor modes. User mode runs normal application code. FIQ mode handles the fast interrupt. IRQ mode handles the normal interrupt. Supervisor mode runs after reset and handles software interrupts. Abort mode handles a failed memory access. Undefined mode handles an unknown instruction. System mode is privileged and uses the User register bank; an operating system uses it to run privileged code without a mode switch.

Each exception mode has private copies of some registers. These are banked registers. In FIQ, IRQ, Supervisor, Abort and Undefined modes, R13 and R14 are banked, and an SPSR exists. FIQ also banks R8 to R12. User and System share the same R13, R14 and general registers and have no SPSR.

When an exception is taken, the core switches mode, copies CPSR into that mode's SPSR, saves the return address in that mode's LR, and starts at a fixed vector. The handler can use its private R13 as a stack pointer and R14 for return, so it need not save the User bank first. FIQ goes further: its private R8-R12 let a short handler work without saving those registers. Interrupt priority and latency belong to Unit 3.

Pipeline and PC offset

ARM7 uses a three-stage pipeline: fetch, decode, execute. Fetch reads the next instruction from memory. Decode works out what it means. Execute does the operation. In steady state, three instructions are in the pipeline at once, one in each stage.

Because fetch runs ahead, the PC value during an instruction is not that instruction's address. In ARM state, PC = address of executing instruction + 8 bytes. The +8 is two 32-bit words: the instruction being fetched is two words ahead. In Thumb state, instructions are 16 bits, so PC = executing address + 4 bytes. The offset is in bytes, not instruction count. A branch writes its target into PC; the pipeline must refill, so useful work is lost.

PC = A + 8 (ARM state); PC = A + 4 (Thumb state)

PC is the value read through R15; A is the byte address of the executing instruction. ARM state uses 4-byte instructions; Thumb state uses 2-byte instructions.

Newer ARM cores in the Cortex series keep these ideas but add deeper pipelines, caches and more modes. Only a few universities teach that detail at this depth.

Worked example

Question. An ARM7TDMI runs in ARM state. It executes an instruction at byte address 0x00002000. Give the value read from the PC and the addresses of the instructions in the decode and fetch stages. Use byte addresses.

  1. In ARM state, PC read = executing address + 8 bytes.
  2. Executing address A = 0x00002000 = 8192.
  3. PC = 0x00002000 + 0x00000008 = 0x00002008 = 8200.
  4. Decode stage holds the next instruction, one word ahead: A + 4 = 0x00002004 = 8196.
  5. Fetch stage holds the instruction being fetched, at the PC value: 0x00002008 = 8200.

Answer. The executing instruction is at 0x00002000 (8192), the decode-stage instruction at 0x00002004 (8196), and the PC/fetch-stage address is 0x00002008 (8200), all byte addresses.

Exam traps

  • PC is not the address of the executing instruction. In ARM state it is executing address + 8 bytes; in Thumb state + 4 bytes.
  • SPSR exists only in exception modes. User and System mode have CPSR only.
  • FIQ banks R8-R12 as well as R13, R14 and SPSR. IRQ does not bank R8-R12.
  • R13, R14 and R15 are not hardwired names; SP, LR and PC are programmer conventions.
  • The +8 and +4 offsets are byte counts, not instruction counts. Do not add 8 instructions.

2.4 ARM and Thumb instruction sets

An ARM processor can run two instruction sets. ARM instructions are 32 bits wide: they carry a 4-bit condition field, an optional S suffix that updates the flags, and a full choice of operands. Thumb instructions are a 16-bit compressed subset that saves program memory; Thumb-2 mixes 16-bit and 32-bit forms. The same core executes both, so a designer trades code size against instruction choice. You meet this in phones, routers, and microcontroller boards where flash is small but the CPU must still run fast.

You need: Chapter 2.3 for the 16 registers, processor modes and the N,Z,C,V flags in the CPSR.

ARM words, Thumb words, and the condition field

An ARM instruction is one 32-bit word. Bits 31–28 hold the condition field. The core tests the condition against the CPSR flags; if the condition is false, the instruction does nothing. Standard codes: EQ (Z=1), NE (Z=0), CS/HS (C=1), CC/LO (C=0), MI (N=1), PL (N=0), VS (V=1), VC (V=0), HI (C=1 and Z=0), LS (C=0 or Z=1), GE (N=V), LT (N≠V), GT (Z=0 and N=V), LE (Z=1 or N≠V), and AL (always). This lets one compare set the flags and many following instructions run or skip without branches.

The S suffix is one bit in the instruction encoding. Without S the instruction does not change N, Z, C or V. With S it updates them. ADD R0,R1,R2 leaves the flags alone; ADDS R0,R1,R2 sets them from the result. The condition field reads old flags, so the order matters: a compare or an S-form must come before a conditional instruction.

Thumb is not a separate CPU. It is a 16-bit encoding of common ARM operations. A Thumb instruction has less room for a condition field and for large immediates. Thumb-2 keeps 16-bit forms for density and adds 32-bit forms for operations that need more bits. Some syllabi call the older 16-bit set Thumb-1.

Data processing, operands and the barrel shifter

Data processing instructions work on registers. The main mnemonics are AND, EOR, SUB, RSB, ADD, ADC, SBC, RSC, TST, TEQ, CMP, CMN, ORR, MOV, BIC and MVN. ADC adds with carry; SBC subtracts with borrow. RSB reverses the subtraction: RSB R0,R1,R2 computes R2 − R1. TST, TEQ, CMP and CMN only set flags; they do not write a result register.

The second operand can take three forms. An immediate is a constant written with #, for example #5. A register is a plain register, for example R2. A shifted register passes through the barrel shifter before the ALU. The shifter can do LSL (logical shift left), LSR (logical shift right), ASR (arithmetic shift right) and ROR (rotate right) by #n or by a register. ADD R0,R1,R2,LSL #2 computes R0 = R1 + (R2 × 4). The shift is free in the same instruction; it does not need a separate instruction.

After an S-form, the four flags mean this. N is 1 when bit 31 of the result is 1. Z is 1 when the result is zero. C is the carry out of bit 31 for an addition. For a subtraction, C is the inverse of the borrow: C = 1 when the subtraction needs no borrow (unsigned Rn ≥ Rm) and C = 0 when a borrow occurs. Example: CMP R1,R2 with R1 = 5 and R2 = 2 gives C = 1; with R1 = 2 and R2 = 5 it gives C = 0. V is 1 when signed overflow occurs: for an addition, both inputs have the same sign and the result has the other sign. For a subtraction, V is 1 when the operands have different signs and the result has the sign of the second operand (equivalently, differs from the sign of the first operand). These are the same CPSR flags from Chapter 2.3.

Load/store, branch, multiply, status and assembler directives

Load and store instructions move data between registers and memory. LDR loads a 32-bit word; STR stores a 32-bit word. LDRB and STRB move one byte. LDM loads a list of registers from consecutive addresses; STM stores a list. The ! after the base register means writeback: the base register is updated after the transfer. LDM and STM have a rule about the base register. With writeback (!) and the base register also in the list, the value left in the base by LDM, or stored for it by STM, is UNPREDICTABLE or UNKNOWN in the architecture. Correct code keeps the base out of the list.

Branch instructions change the PC. B is a plain branch. BL is branch with link: it copies the return address into LR (R14) before branching, so a subroutine can return with BX LR. BX branches to the address in a register; the low bit of that address selects ARM or Thumb state (it must be 1 on Thumb-only cores such as Cortex-M). Multiply instructions include MUL (R0 = R1 × R2), MLA (multiply and accumulate), UMULL and SMULL (unsigned and signed 64-bit results). Status instructions MRS and MSR move between a general register and the CPSR or SPSR. SWI (software interrupt, called SVC in newer ARM) enters a supervisor call.

  • Keil-style directives are not machine instructions. AREA names a code or data section.
  • ENTRY marks the first instruction to execute. EXPORT makes a label visible to the linker.
  • DCD places a 32-bit constant in memory. EQU defines a symbol.
  • Thumb does not support every ARM instruction or every conditional form. Thumb-2 adds 32-bit forms and IT blocks for conditional execution.

Worked example

Question. R1 = 0x7FFFFFFF and R2 = 0x00000001. The instruction ADDS R0,R1,R2 executes. Give R0 and the N,Z,C,V flags after it. State why each flag has that value.

  1. Convert the inputs: R1 = 0x7FFFFFFF = 2147483647 and R2 = 0x00000001 = 1.
  2. Add in 32-bit form: 2147483647 + 1 = 2147483648 = 0x80000000. Write R0 = 0x80000000.
  3. N is bit 31 of R0. Bit 31 of 0x80000000 is 1, so N = 1.
  4. Z is 1 only when the result is zero. R0 is not zero, so Z = 0.
  5. C is the unsigned carry out of bit 31. The sum 0x7FFFFFFF + 1 fits in 32 bits without a carry beyond bit 31, so C = 0.
  6. V is signed overflow. Two positive inputs produced a negative result, so V = 1. Using signs: R1 and R2 are both positive, R0 has bit 31 = 1 (negative).

Answer. R0 = 0x80000000 (2147483648), with N = 1, Z = 0, C = 0 and V = 1.

Exam traps

  • Flags change only when the S suffix is present. ADD R0,R1,R2 does not update N,Z,C,V; ADDS does.
  • Thumb does not support every ARM instruction or every conditional form. Many Thumb instructions are unconditional; Thumb-2 uses IT blocks where a condition is needed.
  • In LDM and STM with writeback (!), if the base register is also in the register list, the value left in the base (LDM) or stored for it (STM) is UNPREDICTABLE or UNKNOWN in the architecture. Keep the base out of the list.
  • RSB reverses the subtraction: RSB R0,R1,R2 is R2 − R1, not R1 − R2. This is a common sign slip.
  • A conditional instruction reads the flags left by an earlier S-form or compare. If the earlier instruction had no S suffix, the condition may test stale flags.

2.5 Addressing modes and memory map

An addressing mode is the rule that tells the CPU where an operand is. A memory map is the address plan that says which addresses hold code, data, stack and registers. These two ideas must match: the addressing mode decides how an address is formed; the memory map decides what that address means. In the 8051, PIC and ARM, the same instruction mnemonic can use different modes. Read the mode and the map together, or the operand comes from the wrong place. Firmware, drivers, boot code and exam questions all depend on this.

You need: register names and bus widths from Chapter 2.1, Chapter 2.2 and Chapter 2.3.

The rule and the plan

An addressing mode is the rule for finding an operand, the value an instruction acts on. The rule produces an effective address (EA), the final address used for a memory operand. The mode can take the operand from the instruction bits, from a register, or from memory. The memory map is the address plan: it assigns ranges to code, data, stack, registers and I/O. The mode chooses the space; the map says what sits at the address.

Six operand kinds repeat across families. Immediate data is inside the instruction. A register operand names a register. A direct address is a number that points into a memory space. An indirect operand uses a register as a pointer, so the pointer's contents are the address. An indexed operand adds a base and an index to reach a table. A relative operand adds a signed offset to the program counter (PC). Some syllabi call indexed addressing based addressing. Pointer addressing usually means indirect addressing.

Use both ideas together. In the 8051, address 30H in internal RAM is a data byte; address 0030H in code memory is an instruction byte. An instruction such as MOV A,30H uses direct data addressing. An instruction such as MOVC A,@A+DPTR uses indexed code addressing. If you read only the number, you may fetch from the wrong space.

8051: modes and separate spaces

The 8051 has separate code and data spaces. Code memory starts at 0000H, the reset vector, and the basic 8051 has 4 KB on chip, 0000H-0FFFH. Internal data RAM is 00H-7FH, 128 bytes. Special function registers (SFRs) occupy 80H-FFH and include ACC at E0H, PSW at D0H, and DPTR split as DPH 83H and DPL 82H. The stack lives in internal RAM and grows upward. Direct addresses below 80H mean RAM; addresses 80H and above mean SFRs.

PIC and ARM: banks and one flat space

The PIC16F877A is Harvard: program memory stores 14-bit instructions and data memory is separate. Program memory has reset vector 0000H and interrupt vector 0004H. Data memory is banked; the STATUS register bits RP1:RP0 select one of four banks, each 128 bytes. Direct addressing uses a 7-bit address plus those bank bits. Indirect addressing uses INDF as the window; the actual data-memory address is formed from FSR and the IRP bit in STATUS (STATUS<7>).

PIC modes are immediate (literal in the instruction), direct (7-bit file address plus bank bits), indirect through FSR/INDF, and absolute GOTO/CALL using an 11-bit address plus PCLATH page bits. Computed jumps write PCL; there is no general PC-relative branch/call offset mode. The bank bits are part of the effective address, not an optional extra.

ARM has one 32-bit address space for code, data, stack and I/O. The vector table sits at low addresses: reset at 0000H, undefined at 0004H, SWI at 0008H, prefetch abort at 000CH, data abort at 0010H, IRQ at 0018H and FIQ at 001CH. The PC is visible as R15 and reads ahead because of the pipeline; a PC-relative address uses the PC value plus an offset.

ARM modes include immediate (a constant encoded in the instruction), register, shifted register (a barrel shifter scales or shifts one operand), PC-relative, pre-indexed and post-indexed load/store, and stack forms. Pre-indexed LDR R0,[R1,#4] forms R1+4 and loads; add ! to write the new address back to R1. Post-indexed LDR R0,[R1],#4 loads from R1, then sets R1=R1+4. Full descending stack: STMFD sp!,{r0-r3} pushes; LDMFD sp!,{r0-r3} pops.

Worked example

Question. Before each instruction A = 00H, R0 = 30H, internal RAM 30H = 5AH, DPTR = 1000H, and code memory 1000H = 7BH. Find A after (a) MOV A,@R0 and (b) MOVC A,@A+DPTR. Give both hex and decimal.

  1. (a) Read R0. R0 = 30H.
  2. The indirect symbol @R0 uses 30H as the data-memory address. Internal RAM 30H holds 5AH.
  3. MOV A,@R0 copies 5AH into A. So A = 5AH = 90 decimal.
  4. (b) MOVC uses code memory. A = 00H and DPTR = 1000H.
  5. Effective address = DPTR + A = 1000H + 00H = 1000H.
  6. Code memory 1000H holds 7BH. MOVC copies it into A. So A = 7BH = 123 decimal.

Answer. (a) A = 5AH = 90 decimal; (b) A = 7BH = 123 decimal.

Exam traps

  • Direct address is not immediate data: MOV A,30H loads RAM 30H; MOV A,#30H loads the constant 30H.
  • @R0 uses the contents of R0, not the address of R0. If R0=30H, @R0 points to RAM 30H.
  • MOVC reads code memory, not data RAM; MOVX is for external data. Do not mix the two.
  • PIC bank bits RP1:RP0 in STATUS select the data bank. A correct 7-bit address in the wrong bank reads the wrong byte.
  • ARM pre-indexed writeback changes the base register only with !. Post-indexed writes back the updated address to the base register.

2.6 Assembly language programming

Assembly language writes one source line for one machine instruction. Nothing is hidden: you name the register, choose the addressing mode, set the flags and count the cycles yourself. It exists because a C compiler cannot promise a fixed number of cycles for a piece of code, and reaching a special function register from C needs a compiler-specific declaration such as Keil's sfr. Some jobs — startup code, interrupt entry, bootloaders, bit-banged drivers — need exactly that control. A careful reader still meets it in datasheets, in compiler output and in industrial code that has run for twenty years. The instruction sets themselves are in 2.4.

You need: the 8051 registers from 2.1, the PIC working register from 2.2, ARM registers and the pipeline from 2.3, and addressing modes from 2.5.

One line, four fields

Almost every assembler uses the same four-field idea — optional label, mnemonic, operands, optional comment — even though the column order and the comment character vary between tools. A label is a name that stands for the address of that line, so a branch can jump to it. The mnemonic is the instruction or a directive. Operands are registers, constants or addresses.

Take AGAIN: MOV R2,#250 ; load the count. AGAIN is the label, MOV is the mnemonic, R2 is the destination register, #250 is an immediate constant, and everything after the semicolon is a comment. The # matters. Without it, MOV R2,50H means the byte stored at internal RAM address 50H (80 decimal), not the number 50H.

Directives are instructions to the assembler, not to the CPU. They place code, reserve memory and name constants.

Moving, computing, deciding

Four instruction families cover almost everything: data movement, arithmetic, logic, and control transfer. Only the names change between chips.

On the 8051, MOV A,#05H loads the accumulator A, ADD A,#03H adds 3 to it, ANL A,#0F0H keeps only the high nibble, and CJNE A,#08H,NEXT compares A with 8 and jumps if they differ. The PIC has a single working register W: MOVLW 0x05 loads it, ADDLW 0x03 adds to it, and file-register instructions carry a destination bit, where 0 writes W and 1 writes the file register. BTFSS PORTB,0 tests a bit and skips the next instruction when the bit is set; skipping is the PIC way of branching. ARM uses 32-bit registers: MOV R0,#5, then ADD R0,R0,#3, ANDS R1,R0,#0xF0, compare with CMP R0,#8, branch with BEQ.

A loop is a counter, a body and a test. On the 8051 the counter update, the test and the branch are one instruction, DJNZ R2,loop, which decrements R2 and branches back while it is not zero; the body is the code between the label and this instruction. ARM splits the job: SUBS R2,R2,#1 subtracts and sets the Z flag, then BNE loop branches while Z is 0. The S suffix is what asks for the flag update.

Subroutines, the stack and exact delay

A call must remember where to come back to. On the 8051, LCALL pushes the 2-byte address of the next instruction onto the internal RAM stack, and the stack pointer SP tracks the top; RET pops those two bytes into the program counter. ARM uses BL, which puts the return address in the link register LR (R14) instead of memory. One ARM catch: a second BL overwrites LR, so a subroutine that calls another must push LR first.

Parameters travel in registers when there are few, because registers are fast and need no memory access. They travel on the stack when there are many; the caller pushes them, the callee reads them at fixed offsets from SP, and both sides agree who removes them. Registers are quicker, but an interrupt handler that reuses the same registers destroys the values; stack slots survive such an interrupt.

T = N × t<sub>cyc</sub>,  t<sub>cyc</sub> = 12 ÷ f<sub>xtal</sub>

T is the delay in seconds; N is the number of machine cycles; tcyc is the machine cycle time in seconds; fxtal is the crystal frequency in Hz. The factor 12 is the classic 8051 divide-by-12.

At 12 MHz, tcyc = 12 ÷ (12 × 106 Hz) = 1 × 10−6 s = 1 μs. Each instruction then costs 1, 2 or 4 μs according to its machine-cycle count given in the datasheet. That predictability is why delay routines are still written in assembly.

From source to running chip

An assembler turns mnemonics into machine code. A cross-assembler runs on your PC yet produces code for a different CPU, which is the normal case for embedded work. Two passes are needed when a label is used before it is defined: pass one records addresses, pass two substitutes them. A linker joins object files, resolves symbols shared between them, and places sections at addresses taken from the memory map. Startup code, itself in assembly, sets SP, clears RAM, copies initialised variables from flash to RAM and calls main.

An in-circuit emulator (ICE) runs the real chip under your control: breakpoints, single step, register watch. Toolchain detail is in Unit 6.

The C version of the delay is for (i = 0; i < 250; i++); — and an optimiser may delete the empty loop entirely, because C says nothing about cycles. Inline assembly drops a few exact instructions into a C function: __asm in Keil, asm volatile in GCC. Reviewers still accept it where timing must be provable.

Worked example

Question. An 8051 runs from a 12 MHz crystal. Find the delay produced by the fragment MOV R2,#250 followed by AGAIN: DJNZ R2,AGAIN. Give the number of machine cycles and the time in microseconds.

  1. Machine cycle time: t_cyc = 12 ÷ f_xtal = 12 ÷ (12 × 10⁶ Hz) = 1 × 10⁻⁶ s = 1 μs.
  2. MOV R2,#250 loads a register, so it takes 1 machine cycle.
  3. DJNZ R2,AGAIN takes 2 machine cycles and executes 250 times. The last pass decrements 1 to 0 and falls through, so it is counted too.
  4. DJNZ cycles = 250 × 2 = 500 machine cycles.
  5. Total N = 1 (setup) + 500 = 501 machine cycles.
  6. Delay T = N × t_cyc = 501 × 1 μs = 501 μs.

Exam traps

  • You forget the setup MOV and the final DJNZ pass. The loop count is 250, so DJNZ costs 500 cycles and the total is 501, not 500 or 502.
  • Machine cycle is not the crystal period. At 12 MHz the oscillator period is 1/12 μs; the 8051 machine cycle is 1 μs because of the divide-by-12.
  • # is not decoration. MOV A,#30H loads the number 30H; MOV A,30H loads the byte stored at internal RAM address 30H.
  • CALL costs stack bytes. Each 8051 LCALL pushes 2 bytes of return address, so deep nesting plus an interrupt can overflow a small internal RAM stack.
  • EQU and DB look similar but EQU allocates no memory. DW 1234H stores 34H first, because the 8051 is little-endian.

2.7 Raspberry Pi and Arduino platforms

Raspberry Pi and Arduino are ready-made boards that hide hardware behind a friendly layer. The Arduino Uno is a microcontroller board: a C++ sketch calls pin and ADC functions that run directly on an ATmega328P. The Raspberry Pi is a single-board computer: a Python program asks a Linux kernel, which runs on a Broadcom SoC, to change a GPIO pin. The choice turns on voltage, analog input, compute and timing. Hobby projects, labs and product prototypes use both.

You need: Chapters 2.5 and 2.6, and Unit 3 GPIO basics.

Two ready-made platforms

A platform is a board plus a software layer that makes pins, timers and buses usable without writing every register. Arduino and Raspberry Pi sit at opposite ends of this idea.

The Arduino Uno carries an ATmega328P: an 8-bit microcontroller (MCU) with 5 V logic, 14 digital pins, 6 analog inputs and a 10-bit analog-to-digital converter (ADC). A C++ sketch calls the Arduino core, and the core writes the MCU registers. The sketch has two functions: setup() runs once, and loop() repeats forever.

The Raspberry Pi is a single-board computer. A Broadcom system on chip (SoC) runs Linux; a 40-pin general-purpose input/output (GPIO) header gives 3.3 V pins but no analog input. A Python or C program in user space asks the kernel to drive a pin. HDMI, USB and network ports make the Pi a small computer, not just a controller.

The figure shows the two stacks. Notice that the 2.5 V sensor reaches only the Arduino ADC path; the Pi needs an external ADC.

Arduino Uno: pins, ADC and timing

The Uno's 14 digital pins are numbered 0 to 13; 6 can produce pulse-width modulation (PWM). The 6 analog inputs are A0 to A5, feeding one 10-bit ADC. The ADC compares the input with a reference, usually 5 V on the Uno. The result is an integer code from 0 to 1023.

The USB bootloader loads the sketch. Then setup() runs once and loop() repeats. The pseudo-code below sets pin 13 as an output, toggles it every 500 ms, reads A0 and prints the code.

void setup() {
  pinMode(13, OUTPUT);
  Serial.begin(9600);

  digitalWrite(13, HIGH); delay(500);
  digitalWrite(13, LOW);  delay(500);

Output

Serial monitor at 9600 baud shows one integer per second, between 0 and 1023. A 2.5 V input on A0 with a 5 V reference prints 512.

Timing is more predictable than on Linux because no general-purpose scheduler preempts the loop. Interrupts and library calls still add delay, so the Uno is not a certified hard real-time board.

code = round(V<sub>in</sub> × 1023 ÷ V<sub>ref</sub>); resolution = V<sub>ref</sub> ÷ 1024

code is the ADC output (0 to 1023); Vin is the input voltage in volts; Vref is the reference voltage in volts; resolution is the voltage per step in volts.

The divisor 1023 maps the full-scale voltage to the largest code. The divisor 1024 gives the size of one step, or resolution. These two numbers are not interchangeable.

Raspberry Pi: Linux computer with GPIO

The Pi boots Linux from a microSD card. Its GPIO header has 3.3 V logic; a 5 V signal on a pin can damage the SoC. The header has no ADC, so a light sensor or potentiometer needs an external ADC chip, often over I2C or SPI.

A Python program can blink an LED or read a digital sensor. The program does not touch registers; it calls a library, the library calls the kernel, and a driver changes the SoC pin. The same board can show a camera image, log data to a file and send it over Wi-Fi.

Linux is a general-purpose OS. It may pause your program to run another task, so a GPIO pulse can be late by microseconds or more. For a strict deadline, add a small MCU or use a real-time kernel.

Choose the Pi when you need network, storage, camera, display or heavy maths. Choose the Uno when you need 5 V pins, analog input and predictable loop timing at low cost. The Uno is cheaper and draws less power; the Pi costs more and needs a larger supply.

Worked example

Question. An Arduino Uno uses its 10-bit ADC with a 5 V reference. A sensor outputs 2.5 V. Find the ADC code and the resolution in mV. Use code = round(Vin × 1023 ÷ Vref).

  1. List values: Vin = 2.5 V, Vref = 5 V, bits = 10, so full-scale code = 210 - 1 = 1023.
  2. Compute the code before rounding: 2.5 × 1023 ÷ 5 = 511.5.
  3. Round to the nearest integer code: 512.
  4. Resolution = Vref ÷ 210 = 5 V ÷ 1024 = 0.0048828125 V.
  5. Convert to mV: 0.0048828125 × 1000 = 4.8828125 mV, about 4.88 mV.

Answer. The ADC code is 512 and the resolution is 4.8828125 mV (about 4.88 mV).

Exam traps

  • Raspberry Pi GPIO is 3.3 V and not 5 V tolerant; a 5 V sensor signal can damage the SoC.
  • The Raspberry Pi has no built-in ADC; an analog sensor needs an external ADC chip.
  • Linux makes the Pi a general-purpose computer, not a hard real-time controller; GPIO pulses can jitter.
  • For a 10-bit ADC, the largest code is 1023, but resolution uses 1024 steps; do not write 5 V ÷ 1023 for resolution.
  • The Arduino Uno has an 8-bit MCU with small RAM and flash; heavy maths, camera work or networking usually needs a Pi or a host PC.

Analyze Why is a Python GPIO pulse on a Raspberry Pi less predictable than an Arduino loop pulse? 4 marks

Linux schedules many processes and may preempt the Python program; the Arduino loop runs on bare metal with no general-purpose OS scheduler. Both can be interrupted, but the Pi has more jitter.

Takeaways

  1. 8051 control lives in special function registers, so a small set of SFR bits sets ports, timers and serial mode.
  2. PIC16F877A starts at reset vector 0000H, jumps to 0004H for interrupts, and selects data banks with RP1:RP0 and IRP.
  3. ARM7 hides work behind seven modes and banked registers, so a mode switch changes R13, R14 and SPSR quickly.
  4. The three-stage ARM pipeline means the visible PC is current instruction address plus 8.
  5. ARM instructions are 32-bit and Thumb 16-bit; the condition field and S suffix decide when an instruction runs and whether flags change.
  6. An addressing mode finds the operand, while a memory map decides where code, data, stack and registers live.
  7. Assembly language gives one machine instruction per line, which makes exact delays and flag control possible.
  8. Raspberry Pi runs Linux and hides timing, while Arduino runs bare-metal firmware and hides electrical detail; choose by task.

Glossary

Addressing mode
The rule an instruction uses to find or compute its operand address.
ARM mode
A privileged or unprivileged operating state with its own banked registers.
Assembler
A program that translates assembly language into machine code.
CISC
A design style with complex, variable-length instructions that may do more work per instruction.
Condition code
A flag test that decides whether an instruction executes.
CPSR
The current program status register holding condition flags and mode bits.
Cross-compiler
A compiler that runs on one computer and produces code for another target.
GPIO
A general-purpose input/output pin used for digital signals.
Harvard architecture
A memory design with separate program and data memories and buses.
In-circuit emulator
A hardware debug tool that controls and observes a running microcontroller.
Interrupt vector
The fixed address where an interrupt service routine starts.
Linker script
A file that tells the linker where to place code and data sections in memory.
Memory map
The address plan that assigns code, data, stack and I/O to fixed ranges.
Microcontroller
A single-chip computer with CPU, memory and peripherals for control tasks.
Microprocessor
A CPU on a chip that needs external memory and peripherals to form a system.
Pipeline
A design that overlaps instruction stages so several instructions are in progress at once.
Program counter
The register that holds the address of the next instruction to fetch.
Register bank
A group of registers that can be swapped in for fast context switching.
Reset vector
The fixed address where the CPU starts execution after reset.
RISC
A design style with a small, simple instruction set, load-store memory access and many registers.
Special function register
An on-chip register that controls a peripheral or holds its status.
Stack pointer
The register that points to the top of the stack.
Thumb
A 16-bit instruction subset of the ARM architecture used for code density.
Timer
A counter peripheral used for delays, time measurement and events.
UART
A serial communication peripheral that sends and receives asynchronous data.
Von Neumann architecture
A memory design where program and data share the same memory and bus.
