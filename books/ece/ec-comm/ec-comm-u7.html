7.1 Information measure, entropy and information rate

Some messages surprise you more than others. A symbol that appears rarely carries more information than one that appears all the time. Information theory turns this everyday idea into a number. Self-information measures one symbol; entropy measures the average symbol of a source; information rate converts that average into bits per second. These numbers tell you how much a source can be compressed and how much channel capacity it needs. They sit under PCM bit rates, Huffman coding, and the Shannon capacity formula used to plan a microwave or fibre link.

You need Unit 1, Foundations: probability, random variables and the idea of a random source.

Self-information of a symbol

A discrete source emits one symbol at a time from a finite alphabet of M symbols. Call symbol i's probability pi, with 0 < pi ≤ 1 and Σpi = 1. The self-information of symbol i is the surprise when that symbol arrives. A rare symbol has small pi, so it carries a large amount of information. A certain symbol, pi = 1, carries zero information because you already knew it was coming.

I(x<sub>i</sub>) = log<sub>2</sub>(1/p<sub>i</sub>) = −log<sub>2</sub> p<sub>i</sub> bits

I(xi) is the self-information of symbol i in bits; pi is its probability; log2 is the logarithm to base 2.

The logarithm is there because independent symbols must add their information. If two independent symbols have probabilities pi and pj, their joint probability is pipj. We want total information to be the sum: I(pipj) = I(pi) + I(pj). Only a logarithm turns a product into a sum: log(1/(pipj)) = log(1/pi) + log(1/pj). Base 2 makes the unit the bit, the information in one fair coin toss.

Entropy of a source

H(X) = Σ<sub>i=1</sub><sup>M</sup> p<sub>i</sub> log<sub>2</sub>(1/p<sub>i</sub>) = −Σ<sub>i=1</sub><sup>M</sup> p<sub>i</sub> log<sub>2</sub> p<sub>i</sub> bits/symbol

H(X) is the source entropy in bits per symbol; M is the number of symbols; pi is the probability of symbol i; the term with pi = 0 is taken as 0.

Entropy is the average self-information per symbol. Before a symbol arrives it is the uncertainty about which symbol will come. After the symbol arrives it is the average information you gained. A source whose symbols have nearly equal probabilities has high entropy; a source that almost always sends the same symbol has low entropy. Some syllabi call H the average information or the uncertainty of the source.

For fixed M, H is largest when all M symbols are equally likely: Hmax = log2 M. A 4-level equal source has H = 2 bits/symbol; an 8-level equal source has H = 3 bits/symbol. Unequal probabilities always give less than log2 M. The binary case uses p for one symbol and 1−p for the other: H(p) = −p log2 p − (1−p) log2(1−p). It peaks at 1 bit when p = 0.5 and falls to 0 at p = 0 or p = 1. Entropy is the lower bound that Huffman coding tries to reach.

Information rate

R = rs H bits/s

R is the information rate in bits per second; rs is the symbol rate in symbols per second; H is the entropy in bits per symbol.

The symbol rate says how fast symbols arrive. The information rate says how fast information arrives. A source emitting 4 symbols with probabilities 1/2, 1/4, 1/8, 1/8 has H = 1.75 bits/symbol. At rs = 2000 symbols/s, R = 2000 × 1.75 = 3500 bit/s. If the 4 symbols were equally likely, H would be 2 bits/symbol and R would be 4000 bit/s at the same symbol rate.

  • An 8-level equal source has H = log2 8 = 3 bits/symbol. At 1000 symbols/s, R = 3000 bit/s.
  • Bits per symbol is an entropy answer. Bits per second is an information-rate answer. Multiply by rs and keep the units.
  • These formulas assume a memoryless source: each symbol's probability does not depend on earlier symbols. Dependence is handled by conditional entropy in 7.3.

Information rate is the number you compare with channel capacity. If R is below capacity, reliable transmission is possible; if R is above capacity, it is not. That comparison is the whole point of measuring a source before designing the link.

Worked example

Question. A memoryless source emits four symbols with probabilities 1/2, 1/4, 1/8 and 1/8 at a symbol rate of 2000 symbols per second. Find the information carried by each symbol, the source entropy, and the information rate.

  1. List the probabilities: p1 = 1/2, p2 = 1/4, p3 = 1/8, p4 = 1/8. The symbol rate is rs = 2000 symbols/s.
  2. Symbol 1: I1 = log2(1/(1/2)) = log2 2 = 1 bit.
  3. Symbol 2: I2 = log2(1/(1/4)) = log2 4 = 2 bits.
  4. Symbol 3: I3 = log2(1/(1/8)) = log2 8 = 3 bits.
  5. Symbol 4: I4 = log2(1/(1/8)) = log2 8 = 3 bits.
  6. Entropy: H = (1/2)(1) + (1/4)(2) + (1/8)(3) + (1/8)(3) = 0.5 + 0.5 + 0.375 + 0.375 = 1.75 bits/symbol.
  7. Information rate: R = rsH = 2000 × 1.75 = 3500 bit/s.

Answer. The four symbols carry 1 bit, 2 bits, 3 bits and 3 bits; the entropy is 1.75 bits/symbol; the information rate is 3500 bit/s.

Exam traps

  • Using log10 or ln and still writing the answer in bits. A base-10 answer is in hartleys and a base-e answer is in nats; convert to bits or change the base.
  • Quoting bits per symbol when the question asks for bits per second. Multiply by the symbol rate and check the units.
  • Assuming every M-level source has entropy log2 M. That maximum holds only when all M symbols are equally likely.
  • Forgetting that p log2 p tends to 0 as p tends to 0, so a zero-probability symbol adds no term to the entropy.
  • Confusing the self-information of one symbol with the average entropy of the whole source.

7.2 Source coding: Shannon-Fano and Huffman codes

Source coding assigns short binary words to likely symbols and longer words to rare symbols. A prefix code keeps every codeword from being the start of another, so the receiver decodes bit by bit with no separators. Shannon-Fano and Huffman both build such codes from a probability list; Huffman is the standard method. The average length L̄ in bits per symbol can approach the entropy H(X), never fall below it. File compression, image formats and voice codecs use these ideas daily.

You need Chapter 7.1 for entropy H(X) and information rate.

Prefix codes and the source coding theorem

A fixed-length code wastes bits when one symbol dominates. A source emits symbols with probabilities pᵢ. Give symbol i a binary codeword of length lᵢ bits. A prefix code has no codeword that is the start of another. The set {0, 10, 110, 111} is prefix-free. After reading 10, the receiver knows the symbol ended; it never needs to look ahead. Decoding is instant, one bit at a time.

The Kraft inequality says that for any binary prefix code, Σ 2−lᵢ ≤ 1, where lᵢ is the length in bits of the codeword for symbol i. It is necessary and sufficient for integer lengths. We state it without proof.

L̄ = Σ pᵢ lᵢ

L̄ is the average codeword length in bits per symbol; pᵢ is the probability of symbol i; lᵢ is the length in bits of its codeword. H(X) is the entropy from Chapter 7.1, in bits per symbol.

H(X) ≤ L̄ < H(X) + 1

H(X) is the source entropy in bits per symbol. H(X) ≤ L̄ for every prefix code. For one symbol at a time, some prefix code (Huffman is one) has L̄ < H(X) + 1. For a block of n symbols coded together, H(X) ≤ L̄ < H(X) + 1/n.

The source coding theorem says no prefix code can have L̄ below H(X). Some prefix code has L̄ less than H(X)+1 for one symbol at a time. Integer codeword lengths cause this gap; it vanishes only when all probabilities are powers of 1/2.

η = H(X) / L̄, redundancy = 1 − η

η is the coding efficiency, a pure ratio; H(X) and L̄ must use the same logarithm base, normally base 2. Redundancy is the fraction of average length not carrying entropy.

Shannon-Fano coding

Shannon-Fano builds a code top-down by repeated splitting. The split rule uses total probability, not symbol count.

  1. Sort the symbols in decreasing order of probability.
  2. Split the sorted list into two groups so that the two group probabilities are as nearly equal as possible. Keep the original order inside each group.
  3. Give every codeword in the top group a leading 0 and every codeword in the bottom group a leading 1, or the reverse. Fix the choice and keep it.
  4. Repeat the split inside each group until a group has one symbol.
  5. Read each codeword from the root to its leaf.

The split is a heuristic. A poor split gives a valid but longer code. Sorting matters; an unsorted list can lengthen many codewords. Ties can give different average lengths, so check the nearest splits.

Huffman coding

Huffman builds a code bottom-up by merging the least likely symbols first. This keeps large probabilities near the root and gives them short words.

  1. Make one leaf node for each symbol, labelled with its probability.
  2. Take the two nodes with the smallest probabilities. Join them under a new parent whose probability is their sum.
  3. Label one edge from the parent 0 and the other edge 1. The choice is arbitrary if kept consistent.
  4. Put the new parent back into the list and remove the two children.
  5. Repeat until one node remains. Its probability is 1.0.
  6. Read each codeword from the root to its leaf.

The two least likely symbols become siblings at the greatest depth. A Huffman code is prefix-free by construction. Among binary prefix codes with integer lengths, it is optimal for the given probabilities. Ties can produce different codewords, but the average length remains optimal. A heap implementation runs in O(n log n) for n symbols.

Huffman coding is used in ZIP files, JPEG and MP3 bitstreams, and many network protocols. The receiver needs the symbol probabilities or a code table; practical formats send a compact table.

Worked example

Question. A discrete memoryless source emits five symbols A, B, C, D and E with probabilities 0.4, 0.2, 0.2, 0.1 and 0.1. (a) Find the entropy H(X). (b) Build the Huffman code, merging the two smallest probabilities first, and break the 0.2 tie at the second step by merging C with DE. (c) Find the average codeword length L̄ and the coding efficiency η.

  1. Sort the probabilities: A = 0.4, B = 0.2, C = 0.2, D = 0.1, E = 0.1.
  2. Entropy: H(X) = −Σ pᵢ log₂ pᵢ = 0.4 log₂(2.5) + 2(0.2 log₂ 5) + 2(0.1 log₂ 10).
  3. Use log₂(2.5) = 1.3219, log₂ 5 = 2.3219 and log₂ 10 = 3.3219. Then H(X) = 0.4(1.3219) + 0.4(2.3219) + 0.2(3.3219) = 0.5288 + 0.9288 + 0.6644 = 2.1219 ≈ 2.12 bits/symbol.
  4. Huffman step 1: merge D 0.1 and E 0.1 into DE with probability 0.2.
  5. Huffman step 2: there is a tie at 0.2 among B, C and DE. Merge C with DE into CDE with probability 0.4.
  6. Huffman step 3: merge B 0.2 and CDE 0.4 into BCDE with probability 0.6.
  7. Huffman step 4: merge A 0.4 and BCDE 0.6 into the root 1.0.
  8. Read codes: A = 0, B = 10, C = 110, D = 1110, E = 1111. Lengths are 1, 2, 3, 4 and 4 bits.
  9. Average length: L̄ = 0.4(1) + 0.2(2) + 0.2(3) + 0.1(4) + 0.1(4) = 2.2 bits/symbol.
  10. Efficiency: η = H(X)/L̄ = 2.1219/2.2 = 0.9645 = 96.5%. Redundancy = 1 − 0.9645 = 0.0355 = 3.5%.

Answer. H(X) = 2.12 bits/symbol, L̄ = 2.2 bits/symbol, and η = 96.5% for the Huffman code A = 0, B = 10, C = 110, D = 1110, E = 1111.

Exam traps

  • Splitting an unsorted Shannon-Fano list. The rule assumes decreasing order; a valid but poor code can result.
  • Reporting one symbol's codeword length as the average length. L̄ is the probability-weighted sum Σ pᵢ lᵢ, not a single lᵢ.
  • Mixing natural logs with base-2 lengths. Use base 2 for both; answers are in bits per symbol.
  • Writing redundancy as H(X)/L̄. Efficiency is H(X)/L̄; redundancy is 1 − H(X)/L̄.

7.3 Mutual information and discrete memoryless channels

Mutual information measures how much one random variable tells you about another. In a communication link, the input X is the message symbol and the output Y is what the receiver sees. The channel adds uncertainty, so Y is an imperfect copy of X. Mutual information I(X;Y) is the part of H(X) that the output removes. Engineers use it to compare channels, predict achievable rates, and see why a noisy channel cannot carry unlimited data. It is the quantity that channel capacity maximises, and the basis for error-control coding.

You need: entropy from Chapter 7.1 and conditional probability from Unit 1.

Joint entropy and conditional entropy

Take two discrete random variables X and Y. X has alphabet {x₁,...,x_M} and Y has alphabet {y₁,...,y_N}. The joint entropy H(X,Y) is the average uncertainty of the pair:

H(X,Y) = −Σ_i Σ_j P(x_i,y_j) log₂ P(x_i,y_j)

P(x_i,y_j) is the probability that X=x_i and Y=y_j; the sum runs over all pairs; entropy is in bits when log₂ is used.

Conditional entropy H(X|Y) is the uncertainty left in X after Y is known:

H(X|Y) = −Σ_i Σ_j P(x_i,y_j) log₂ P(x_i|y_j)

P(x_i|y_j) is the conditional probability of x_i given y_j. H(Y|X) is defined the same way with the roles swapped.

Both formulas use the convention 0 log₂ 0 = 0, so terms with zero probability contribute nothing to the sum. A channel matrix with zero entries therefore causes no trouble.

The chain rule splits the joint uncertainty:

H(X,Y) = H(X) + H(Y|X) = H(Y) + H(X|Y)

H(X) is the source entropy from Chapter 7.1. The rule says: first learn X, then learn the extra uncertainty in Y given X. Order does not change the total. In general H(X|Y) ≠ H(Y|X). The first asks how much uncertainty about the input remains after the output; the second asks how much uncertainty about the output remains after the input. They are equal only in special symmetric cases.

Mutual information

Mutual information is the reduction in uncertainty:

I(X;Y) = H(X) − H(X|Y) = H(Y) − H(Y|X) = H(X) + H(Y) − H(X,Y)

I(X;Y) is mutual information in bits, H(X) and H(Y) are source and output entropies, and H(X|Y), H(Y|X) are conditional entropies. The three forms are equivalent by the chain rule.

I(X;Y) is symmetric: I(X;Y)=I(Y;X). It measures shared uncertainty, not direction. It cannot be negative, because conditioning cannot increase average uncertainty. It cannot exceed either entropy: 0 ≤ I(X;Y) ≤ min(H(X), H(Y)). If X and Y are independent, I=0. If Y is a deterministic function of X, I=H(Y) and H(Y|X)=0. If X is a deterministic function of Y, I=H(X) and H(X|Y)=0.

The Venn diagram shows H(X) and H(Y) as two regions. The overlap is I(X;Y). The non-overlapping parts are H(X|Y) and H(Y|X). Notice that I is a part of H(X), so it can never be larger than H(X). Some syllabi call this average mutual information.

Discrete memoryless channels and BSC

A discrete memoryless channel (DMC) has input alphabet X, output alphabet Y, and transition probabilities P(y_j|x_i). The channel matrix has rows for inputs and columns for outputs:

P = [ [P(y₁|x₁), ..., P(y_N|x₁)], ..., [P(y₁|x_M), ..., P(y_N|x_M)] ]

row i gives the output distribution when input x_i is sent. Every row sums to 1. Memoryless means each output Y_k depends only on the input X_k at that instant, not on earlier inputs or outputs.

For a binary symmetric channel (BSC), input and output are {0,1}. With crossover probability p, a sent bit flips with probability p and is correct with probability 1−p. The channel matrix is [[1−p, p],[p, 1−p]]. Given the input, the output uncertainty is the binary entropy:

H(Y|X) = H(p) = −p log₂ p − (1−p) log₂(1−p)

p is the crossover probability and H(p) is in bits. Then

I(X;Y) = H(Y) − H(p)

H(Y) depends on the input distribution P(X). For equiprobable input, H(Y)=1 bit because the BSC is symmetric, so I=1−H(p).

A binary erasure channel passes the bit correctly with probability 1−e and outputs an erasure symbol with probability e; its capacity is 1−e bits per channel use, reached with equiprobable input. If the channel carries r_s symbols per second, the information rate is R = r_s I(X;Y) bits/s.

Worked example

Question. A binary symmetric channel has crossover probability p = 0.1. The input symbols 0 and 1 are equally likely. The channel is used at r_s = 1000 symbols per second. Find H(X), H(Y|X), H(Y), I(X;Y) and the information rate R. Give entropies in bits per symbol and R in bit/s.

  1. Input distribution: P(0)=P(1)=0.5. H(X)=−0.5 log₂0.5 −0.5 log₂0.5 = 1 bit/symbol.
  2. For a BSC, H(Y|X)=H(p) with p=0.1. H(0.1)=0.1 log₂10 + 0.9 log₂(1/0.9) = 0.469 bits/symbol.
  3. The BSC is symmetric and the input is equiprobable, so P(Y=0)=P(Y=1)=0.5. Thus H(Y)=1 bit/symbol.
  4. I(X;Y)=H(Y)−H(Y|X)=1−0.469=0.531 bits/symbol.
  5. R=r_s I=1000×0.531=531 bit/s.

Answer. H(X)=1 bit/symbol, H(Y|X)=0.469 bits/symbol, H(Y)=1 bit/symbol, I(X;Y)=0.531 bits/symbol and R=531 bit/s.

Exam traps

  • Swapping H(X|Y) and H(Y|X). They answer different questions and are not generally equal; only symmetric cases make them equal.
  • Claiming I(X;Y) can be larger than H(X) or H(Y). The overlap cannot be larger than either region; 0 ≤ I ≤ min(H(X),H(Y)).
  • Using a plus sign in I = H(X) + H(Y) − H(X,Y). The joint entropy is subtracted, not added. With a plus sign you get H(X)+H(Y)+H(X,Y), a sum in which the shared part is counted three times, not the shared information. Only the minus sign gives the overlap of the two circles.
  • Reading a channel matrix row as an output distribution that must sum with other rows. Each row is conditional on one input and sums to 1; columns need not sum to 1.
  • For a BSC, plugging p into I directly. The input-dependent term is H(Y); the fixed noise term is H(p).

7.4 Channel capacity and Shannon-Hartley theorem

Channel capacity is the largest mutual information any input distribution can create for a given channel. It is the best error-free data rate the channel can support. For a band-limited channel with additive white Gaussian noise, the Shannon-Hartley law gives C = B log₂(1 + S/N) bits per second. That single number decides whether a telephone line, Wi-Fi link or satellite path can carry the rate we want. Link budgets, DSL planning and 5G design all start from it.

You need: Chapter 7.3 for mutual information I(X;Y), and Unit 1 for AWGN and noise power spectral density N₀.

Capacity of the AWGN channel

Take a channel with input X and output Y. Mutual information I(X;Y) measures how much of the input uncertainty the output removes. Capacity is the largest value of I(X;Y) we can get by choosing the input probabilities p(x):

C = max over p(x) of I(X;Y)

C is capacity in bits per channel use; p(x) is the input probability distribution; the channel p(y|x) is fixed.

For a continuous band-limited channel with additive white Gaussian noise, this maximisation gives the Shannon-Hartley law:

C = B log₂(1 + S/N)

C is capacity in bit/s; B is bandwidth in Hz; S is received signal power in W; N is noise power in the same bandwidth in W; S/N is a dimensionless power ratio.

Some syllabi call this result Shannon's channel capacity theorem or the Shannon-Hartley law. A decibel value is not a ratio. Convert first: S/N = 10^(SNR(dB)/10). For example, 30 dB means S/N = 10³ = 1000. Capacity per hertz is C/B = log₂(1 + S/N) bit/s/Hz; it says how many bits each hertz can carry.

Binary symmetric and erasure channels

For a binary symmetric channel (BSC), each bit flips with probability p, independent of other bits. The capacity is

C = 1 − H(p) bits per channel use

H(p) = −p log₂ p − (1−p) log₂(1−p) is the binary entropy function in bits; p is the bit-flip probability.

Equal input probabilities 0 and 1 reach this value. At p = 0 the channel is perfect, H(0)=0, so C=1. At p = 0.5 the output is independent of the input, H(0.5)=1, so C=0. At p = 1 every bit is inverted; the receiver can invert it back, so the channel is perfect again and C=1. This last point is a favourite trap. For a binary erasure channel with erasure probability p_e, the capacity is

C = 1 − p_e bits per channel use

p_e is the probability that a bit is erased, not flipped.

An erased bit is lost, so one clean bit per use is the most we can send. The derivation is in Chapter 7.3.

Limits, units and the Shannon limit

Keep the units straight. C = B log₂(1 + S/N) gives bits per second. The BSC formula gives bits per channel use. One channel use may carry several bits, so a rate in bits per second is bits per use multiplied by the number of uses per second. Mixing the two is an easy way to lose marks.

What happens as B grows without limit? Noise power is N = N₀B, where N₀ is the noise power spectral density in W/Hz. Substitute:

C = B log₂(1 + S/(N₀B)) → (S/N₀) log₂ e ≈ 1.44 S/N₀ bits/s

S is signal power in W; N₀ is noise power spectral density in W/Hz; e is 2.718...; the arrow means B tends to infinity.

So infinite bandwidth does not give infinite capacity; capacity saturates at about 1.44 S/N₀. A wider bandwidth admits more noise as well as more signal. For reliable communication, the energy per information bit is E_b. The Shannon limit is the smallest E_b/N₀ that can support arbitrarily small error probability as the rate tends to zero: about −1.6 dB. Practical codes aim near this line; Chapter 7.9 shows how close they get. Capacity is an upper bound, not a promise that a simple uncoded link will work.

Worked example

Question. A telephone channel has bandwidth B = 3.1 kHz and SNR = 30 dB. (a) Find its capacity. (b) Repeat for SNR = 20 dB. (c) A BSC has bit-flip probability p = 0.01; find its capacity per channel use.

  1. For 30 dB, convert to a power ratio: S/N = 10^(30/10) = 10³ = 1000.
  2. Use B = 3.1 kHz = 3100 Hz in the Shannon-Hartley law: C = 3100 log₂(1 + 1000) = 3100 log₂ 1001 bit/s.
  3. log₂ 1001 = ln 1001 / ln 2 = 6.9088 / 0.6931 = 9.967.
  4. C = 3100 × 9.967 = 30,898 bit/s ≈ 30.9 kbit/s.
  5. For 20 dB: S/N = 10^(20/10) = 100.
  6. C = 3100 log₂(1+100) = 3100 log₂ 101 bit/s. log₂ 101 = 6.658.
  7. C = 3100 × 6.658 = 20,640 bit/s ≈ 20.6 kbit/s.
  8. For the BSC, H(0.01) = −0.01 log₂ 0.01 − 0.99 log₂ 0.99 = 0.0808 bits.
  9. C = 1 − H(0.01) = 1 − 0.0808 = 0.9192 bit per channel use.

Answer. The telephone channel capacity is about 30.9 kbit/s at 30 dB, about 20.6 kbit/s at 20 dB, and the BSC capacity is 0.919 bit per channel use.

Exam traps

  • Putting the decibel value straight into log₂(1 + S/N). Convert with S/N = 10^(SNR(dB)/10) first.
  • Mixing bits per second with bits per channel use. Shannon-Hartley gives bit/s; the BSC and erasure formulas give bit/use.
  • Using a voltage ratio as S/N. S/N is a power ratio; if a voltage ratio is given, square it before the formula.
  • Saying capacity is zero at BSC p = 1. At p = 1 every bit is inverted, and the receiver can undo a known inversion, so C = 1.
  • Using B in kHz in the formula. Convert bandwidth to Hz so C comes out in bit/s.

7.5 Channel coding theorem

The channel coding theorem says noise sets a speed limit, not a wall. For a discrete memoryless channel with capacity C bits per channel use, every code rate R below C has some long code whose decoding error can be made as small as you want. Above C, no code and no decoder can do that. The theorem promises existence, not a construction. It explains why repetition, parity checks and modern long codes help, and it gives the target that practical coding gain is measured against.

You need: Chapter 7.4 for capacity and Chapter 7.1 for entropy; see Unit 1, Foundations for independent bit errors.

Code rate, redundancy and the theorem

Channel coding adds parity bits to message bits before transmission. A block code takes k message bits and sends n coded bits. Its code rate is R = k/n. R is information bits per channel use, not a bit rate in bit/s. The extra fraction 1 − R is the redundancy. For k = 100 and n = 150, R = 0.667 and redundancy is 0.333.

R = k / n, redundancy = 1 − R

k is the number of message bits per block; n is the number of transmitted bits per block; R is the code rate in information bits per channel use.

The theorem is stated for a discrete memoryless channel (DMC). In a DMC the output at any time depends only on the input at that time and on independent noise; past inputs do not change the present output rule. Let C be the channel capacity from Chapter 7.4, in bits per channel use.

R < C ⇒ P<sub>e</sub> → 0 as n → ∞;   R > C ⇒ P<sub>e</sub> ≥ ε > 0

C is the channel capacity in bits per channel use; Pe is the probability that the decoder output differs from the k message bits; ε is some positive number that depends on the channel and R.

One proof uses random coding. Choose 2nR codewords independently from the input distribution that achieves C. For large n, a received word is likely near its own codeword and far from the others, because typical noise sequences form a small set. Nearest-codeword decoding has small average error over the random code. Some code in that set must be at least as good as the average.

For the binary symmetric channel (BSC) with crossover probability p, C = 1 − H(p). At p = 0.01, C = 0.919 bits per channel use. A rate 0.5 is allowed; 0.95 is not.

Promises, limits and coding gain

The theorem promises existence. It does not name a code. It says a code of some length n exists with small Pe, but not how to build it. It gives no bound on delay, memory or decoder complexity. A code with n = 10,000 may need a large buffer and a complex decoder. It also does not say Pe is zero at finite n. At finite n, Pe is small but positive.

Coding gain is the saving in required signal-to-noise ratio at a fixed error rate. Compare an uncoded link and a coded link that reach the same Pe. Use energy per information bit, Eb/N0. If uncoded needs 10 dB and coded needs 7 dB at the same error rate, the coding gain is 3 dB.

G<sub>dB</sub> = 10 log₁₀[(E<sub>b</sub>/N<sub>0</sub>)<sub>uncoded</sub> / (E<sub>b</sub>/N<sub>0</sub>)<sub>coded</sub>]

Eb is energy per information bit in joules; N0 is one-sided noise power spectral density in W/Hz; the ratio is dimensionless; both links have the same error rate.

The formula needs linear power ratios, not decibel values. Convert first with Eb/N0 = 10dB/10. So 10 dB becomes 10 and 7 dB becomes 5.01, and 10 log₁₀(10/5.01) = 3.0 dB. That is simply the difference of the two dB numbers, so with decibel figures you can subtract and get the same answer.

Above capacity the converse holds. If R > C, every decoder has Pe above a positive floor, no matter how clever. A decoder cannot create information the channel did not deliver. It can only choose the most likely message. A scheme that claims zero error above C is wrong.

Repetition and single parity check

The repetition code sends each message bit n times, with n odd. The decoder takes a majority vote. For n = 3, R = 1/3; a decoded bit is wrong only when two or three copies are wrong. For independent bit errors with probability p, Pb = 3p²(1 − p) + p³. At p = 0.01 this is 2.98 × 10−4, much below 0.01. Repetition helps because independent errors must agree to defeat the majority. Its cost is a rate of 1/n.

Single parity check appends one bit so every codeword has an even number of 1s. With k message bits, n = k + 1 and R = k/(k+1). The receiver checks parity. Any odd number of bit errors makes parity odd and is detected. An even number of errors is not detected. A parity check detects errors but cannot correct them by itself; retransmission or a stronger code is needed.

These elementary codes show the trade. Repetition corrects errors but spends most bits on copies. Parity check spends one bit and detects simple errors cheaply. The theorem says better long codes exist below capacity; Chapter 7.6 to 7.9 build them.

Worked example

Question. A binary symmetric channel has crossover probability p = 0.01. Each message bit is sent three times and the receiver takes a majority vote. Find the code rate, the decoded bit error probability, and compare the rate with capacity.

  1. For a 3-repeat code, k = 1 and n = 3. Code rate R = k/n = 1/3 = 0.333.
  2. A decoded bit is wrong when two copies or all three copies are wrong. These events are disjoint for a given pattern of errors.
  3. Two wrong copies: choose which 2 of 3 are wrong in 3 ways. Probability = 3p²(1 − p) = 3 × (0.01)² × 0.99 = 0.000297.
  4. Three wrong copies: probability = p³ = (0.01)³ = 0.000001.
  5. Total decoded bit error probability Pb = 0.000297 + 0.000001 = 0.000298 = 2.98 × 10−4. Uncoded p = 0.01, so the error falls by a factor about 33.6.
  6. Capacity of the BSC: C = 1 − H(p) = 1 − [−p log₂ p − (1 − p) log₂(1 − p)]. With p = 0.01, H(p) = 0.0808 and C = 0.919 bits per channel use.
  7. R = 0.333 < C = 0.919. The theorem allows arbitrarily small error with longer codes; this 3-repeat code is only a short example.

Answer. R = 0.333, Pb = 0.000298, and C = 0.919 bits per channel use, so R < C and the theorem allows the gain.

Exam traps

  • Treating the theorem as a construction. It proves that a code exists; it does not give the parity-check matrix, encoder or decoder.
  • Believing a better decoder can push Pe to zero when R > C. The converse forbids it for every decoder.
  • Calling R = k/n a bit rate in bit/s. R is information bits per channel use; the bit rate also needs the channel symbol rate.
  • Using p = 1% as p = 1 in H(p). Probabilities in entropy formulas must be between 0 and 1; 1% is 0.01.
  • Thinking a single parity check corrects one error. It detects an odd number of errors; it does not locate or correct them.

7.6 Linear block codes, Hamming codes and syndrome decoding

A linear block code turns k message bits into n coded bits by a fixed matrix multiplication. The set of all codewords is a subspace, so the encoder is simple and the decoder can name the error instead of guessing the message. The syndrome, an n−k bit vector, depends only on the error pattern. Hamming codes are the smallest useful family: the (7,4) code corrects one bit in seven. Such codes guard computer memory, storage, and control links where retransmission is costly. The next step is to build G and H and use the syndrome table to correct errors.

You need: Chapter 7.5 for why codes are used, and Unit 1 for modulo-2 addition.

Encoding by a generator matrix

A binary linear block code takes k message bits and produces an n-bit codeword; it is called an (n,k) code. The code rate is R = k/n, the fraction of transmitted bits that carry new message information. The code is linear when the modulo-2 sum of any two codewords is also a codeword; the all-zero word is then always a codeword. Encoding is c = mG. Here m is a 1×k message row, G is a k×n generator matrix, and c is the 1×n codeword. All arithmetic is modulo 2.

Systematic form puts the message bits in plain view: G = [Ik | P]. Ik is the k×k identity block and P is a k×(n−k) parity block. The first k bits of c equal m; the last n−k bits are parity checks. The parity-check matrix is H = [PT | In−k], size (n−k)×n. Every codeword satisfies cHT = 0, and the matrices satisfy GHT = 0. The rows of H are the parity equations.

dmin = min w(c), c ≠ 0

w(c) is the Hamming weight, the number of 1 bits in c; dmin is the minimum Hamming distance between any two distinct codewords.

The Hamming distance d(c₁,c₂) is the number of positions where two words differ. For a linear code it equals the weight of c₁ ⊕ c₂, so the smallest distance is the smallest nonzero codeword weight. This one number sets how many errors the code can handle.

Syndrome decoding

Send c through a noisy channel and receive r. Write r = c ⊕ e, where e is the error pattern: a 1 marks a flipped bit. The decoder forms the syndrome s = rHT. Its length is n−k bits. Because cHT = 0, s = (c ⊕ e)HT = eHT. The syndrome therefore names the error pattern, not the message. All error patterns that differ by a codeword give the same syndrome; such patterns form a coset.

Minimum distance decides the guarantee. A code detects up to dmin − 1 errors and corrects t = ⌊(dmin − 1)/2⌋ errors. For correction, build a syndrome table: list each correctable error pattern e and its syndrome s = eHT. On reception compute s, look up e, and output r ⊕ e. If s = 0, accept r as a codeword.

The standard array is the same idea in one line: write all 2k codewords in the first row, then add the most likely error pattern (coset leader) to every codeword of that row, and repeat for every coset. The decoder finds r in the array and reads the top entry of its column.

Hardware follows the algebra. The encoder is a bank of XOR gates selected by the 1 bits of m: the encoder XORs the rows of G marked by the 1 bits of m, and bit j of the codeword is the modulo-2 sum of the entries in column j of those rows. The syndrome calculator is n−k XOR trees, one per row of H; each tree adds the received bits where that H row has a 1. A small read-only table maps the syndrome to the error pattern.

Hamming (7,4) code

The Hamming (7,4) code has n = 7, k = 4, and n−k = 3 parity bits. Its H columns are the seven nonzero 3-bit words, for example 110, 101, 011, 111, 100, 010, 001. With G = [I₄ | P] and P rows 110, 101, 011, 111, this is the H above. No column is zero and no two columns are equal, so no single error gives s = 0 and no two single errors share a syndrome. Hence dmin = 3 and t = 1.

The Hamming bound for t = 1 is 2n−k ≥ 1 + n. For (7,4): 23 = 8 and 1 + 7 = 8. The bound is met exactly, so the code is perfect: every one of the eight syndromes is used, one for no error and seven for the seven single-bit errors. It corrects one error in seven bits with only three parity bits.

Decoding is direct. Compute s. If s = 000, no correction. Otherwise s equals one column of H; flip the bit at that column position. For example, s = 111 is column 4 in the H above, so the error is 0001000. This is why the syndrome must not be read as a decimal position: 111 is binary 7, but here it means bit 4. The column order in H sets the table.

Worked example

Question. For the (7,4) Hamming code take G = [I₄ | P] with rows of P equal to 110, 101, 011 and 111. (a) Encode m = 1011. (b) Flip the fourth bit of the codeword and decode it by syndrome.

  1. Write G row by row: r1 = 1000110, r2 = 0100101, r3 = 0010011, r4 = 0001111.
  2. m = 1011 selects rows 1, 3 and 4 because its four bits are 1, 0, 1, 1.
  3. Add the selected rows modulo 2: r1 ⊕ r3 = 1010101; then 1010101 ⊕ r4 = 1011010. So c = 1011010.
  4. The parity-check matrix is H = [PT | I₃], with rows 1101100, 1011010, 0111001. Its columns are 110, 101, 011, 111, 100, 010, 001.
  5. Flip bit 4 of c. c = 1 0 1 1 0 1 0 becomes r = 1 0 1 0 0 1 0 = 1010010. The error is e = 0001000.
  6. Compute s₁ = r₁⊕r₂⊕r₄⊕r₅ = 1⊕0⊕0⊕0 = 1.
  7. Compute s₂ = r₁⊕r₃⊕r₄⊕r₆ = 1⊕1⊕0⊕1 = 1.
  8. Compute s₃ = r₂⊕r₃⊕r₄⊕r₇ = 0⊕1⊕0⊕0 = 1. So s = 111.
  9. Column 4 of H is 111. The table therefore gives e = 0001000.
  10. Correct: r ⊕ e = 1010010 ⊕ 0001000 = 1011010, the original codeword.

Answer. The codeword is c = 1011010; after one bit flip r = 1010010, the syndrome is s = 111 (bits 1, 1, 1), the error is 0001000, and the corrected word is 1011010.

Exam traps

  • Reading the syndrome as a decimal error position. In the (7,4) example 111 is a 3-bit column label; it points to column 4 because of the chosen H, not to bit 7.
  • Forgetting that dmin = 3 detects two errors but corrects only one. A two-bit error can land on a syndrome that the table maps to a single-bit pattern, so the decoder may miscorrect.
  • Mixing the blocks in G and H. Systematic G is [Ik | P], not [P | Ik]; H is [PT | In−k]. Swapping them breaks GHT = 0.
  • Using a different column order in H than the one used to build the syndrome table. The syndrome is only a pointer to that table.

7.7 Cyclic codes

A cyclic code is a linear block code with one extra promise: shift any codeword one place and you get another codeword. One polynomial, the generator polynomial g(x), then describes the whole code. Encoding becomes multiplication or polynomial division, and the hardware is a short shift register. The CRC that guards an Ethernet frame or a ZIP file is exactly this remainder circuit, and BCH and Reed-Solomon codes are its descendants.

You need Chapter 7.6 for linear block codes, parity-check matrices and syndromes, plus polynomial long division over GF(2).

Codewords as polynomials

A linear block code is cyclic if every cyclic shift of a codeword is also a codeword. Shift the (7,4) word 1101001 one place left and wrap the leading 1 to the right end: you get 1010011, another codeword. That one property lets a single polynomial define the whole code.

Number the bits from the right. The rightmost bit is c₀, the constant term; the leftmost is c₆ in a 7-bit word, in general c_{n−1}. A codeword becomes a polynomial with coefficients in GF(2) — only 0 and 1, added by XOR — so 1101001 is 1 + x³ + x⁵ + x⁶.

c(x) = c₀ + c₁x + c₂x² + … + c_{n−1}x^(n−1)

c₀ is the rightmost bit of the word, c_{n−1} the leftmost; coefficients are 0 or 1 and addition is XOR.

Multiplying c(x) by x and reducing modulo xⁿ + 1 performs the cyclic shift: over GF(2), xⁿ − 1 and xⁿ + 1 are the same polynomial, so the top bit wraps round to the end.

Linearity means the XOR of two codewords is a codeword. Among the nonzero codewords pick the one of smallest degree; call it the generator polynomial g(x). Every codeword is a multiple of g(x), and g(x) divides xⁿ + 1 exactly. Its degree fixes the code: deg g = n − k, so k = n − deg g.

For the (7,4) code g(x) = x³ + x + 1. Degree 3 gives k = 4, hence 16 codewords. The partner factor is h(x) = (x⁷ + 1)/g(x) = x⁴ + x² + x + 1.

Systematic encoding by division

Non-systematic encoding is one multiplication: c(x) = m(x)g(x), with m(x) = m₀ + m₁x + … + m_{k−1}x^(k−1) carrying the k message bits. All 2^k products are distinct codewords, but the message is mixed into the parity, so the decoder must divide before it can read it.

Systematic form keeps the k message bits unchanged in the highest-order positions — the coefficients of x^{n−1} down to x^{n−k}, sent first — and appends the n − k parity bits at the right end, in positions x^{n−k−1} down to x⁰. Division does it in three steps.

  1. Shift: multiply m(x) by x^(n−k). The message moves into the high-order positions and n − k zeros appear at the bottom.
  2. Divide x^(n−k)m(x) by g(x) with long division over GF(2). Each subtraction is an XOR; there are no borrows.
  3. Take the remainder b(x), of degree less than n − k, and add it: c(x) = x^(n−k)m(x) + b(x).
c(x) = x^(n−k)m(x) + b(x),  b(x) = [x^(n−k)m(x)] mod g(x)

m(x) is the message polynomial of degree at most k−1; b(x) holds the n−k parity bits; x^(n−k)m(x) means the message shifted left by n−k places.

Adding the remainder cancels it, so c(x) is a multiple of g(x) and hence a codeword. A CRC is this same division read as a checksum.

The parity check polynomial is h(x) = (xⁿ + 1)/g(x), of degree k. A word c(x) is a codeword exactly when c(x)h(x) is a multiple of xⁿ + 1 — the polynomial form of cHᵀ = 0 from Chapter 7.6.

Shift-register encoder and syndrome calculator

The encoder is a shift register of n − k flip-flops with feedback from the last one, and a gate wherever g(x) has a 1 coefficient. For g(x) = x³ + x + 1 there are three stages R₀R₁R₂, one XOR at the input, and one more between R₀ and R₁, since the x¹ coefficient is 1 and x² is 0.

  • First k = 4 clocks: the message switch is closed, so bits go out to the channel and also into the divider, leftmost bit first.
  • Next n − k = 3 clocks: the switch opens, the input is held at zero, and the register empties itself out as the parity bits.
  • The output is the message followed by the remainder: 1101 then 001, giving 1101001.

The syndrome calculator is the same register without the message switch. Clock all n received bits in; the register then holds s(x) = r(x) mod g(x). Zero means no detectable error. Since r(x) = c(x) + e(x) and g(x) divides c(x), the syndrome equals e(x) mod g(x) — it depends on the error alone, not on the codeword sent. That is the heart of syndrome decoding.

Worked example

Question. A (7,4) cyclic code uses the generator polynomial g(x) = x³ + x + 1. (a) Encode the message 1101 systematically. (b) The received word differs from a valid codeword by a single error in the x⁴ position; find the syndrome and say what it shows.

  1. Bits are numbered from the right, so the message 1101 with k = 4 is m(x) = x³ + x² + 1.
  2. Shift by n − k = 3: x³m(x) = x⁶ + x⁵ + x³, the 7-bit word 1101000.
  3. x⁶ ÷ x³ = x³; x³·g = x⁶ + x⁴ + x³; XOR leaves x⁵ + x⁴.
  4. x⁵ ÷ x³ = x²; x²·g = x⁵ + x³ + x²; XOR leaves x⁴ + x³ + x².
  5. x⁴ ÷ x³ = x; x·g = x⁴ + x² + x; XOR leaves x³ + x.
  6. x³ ÷ x³ = 1; g = x³ + x + 1; XOR leaves 1. Degree 0 is below 3, so stop. Remainder b(x) = 1, parity bits 001.
  7. c(x) = x⁶ + x⁵ + x³ + 1, so the codeword is 1101001 = 105 in decimal. Dividing it by g(x) leaves 0, which confirms it.
  8. The error is e(x) = x⁴, the third bit from the left of the 7-bit word. s(x) = r(x) mod g(x) = e(x) mod g(x) = x⁴ mod g(x).
  9. x⁴ ÷ x³ = x; x·g = x⁴ + x² + x; XOR leaves x² + x. Degree 2 is below 3, so s(x) = x² + x = 110 = 6 in decimal.
  10. The syndrome is nonzero, so an error is flagged; 110 is the x⁴ entry of the single-error table, so the decoder flips that bit and restores 1101001.

Answer. The codeword is 1101001 (parity 001, decimal 105) and the syndrome is 110 (decimal 6), which both detects and locates the error at x⁴.

Exam traps

  • Choosing a g(x) that does not divide xⁿ + 1. The code then fails the shift test and is not cyclic.
  • Attaching the parity bits on the left. Systematic means message in the high-order positions, parity at the right end.
  • Swapping g(x) and h(x): g(x) has degree n − k and generates the code; h(x) has degree k and checks it.
  • Borrowing in polynomial subtraction. Over GF(2), addition and subtraction are both XOR; no carries, no borrows.
  • Reading deg g as k. It is n − k, so k = n − deg g; a (7,4) code needs degree exactly 3.

7.8 Convolutional codes and Viterbi decoding

A convolutional code does not cut the message into independent blocks. It feeds each input bit through a shift register, so one input bit shapes several output bits. The encoder is simple; the decoder must search. Viterbi decoding finds the trellis path whose coded bits are closest to the received bits. These codes appear in satellite modems, deep-space links, voice-band modems and the convolutional part of many cellular and Wi-Fi systems.

You need: Chapter 7.6 for parity and Hamming distance, and Unit 5 for maximum-likelihood detection.

The encoder is a shift register

Write the code as (n, k, K). Here n is the number of output bits per encoder step, k is the number of input bits per step, and K is the constraint length in bits. The memory is K − 1 bits, so the encoder stores K − 1 past input bits. The code rate is R = k/n.

R = k/n

R is the code rate, dimensionless; k is input bits per step; n is output bits per step. For the example k = 1 and n = 2, so R = 1/2.

The rate 1/2, K = 3 encoder has two delay cells. At each step the current input bit u(i) enters, and the two cells hold u(i−1) and u(i−2). Two modulo-2 adders produce the output pair.

c<sub>1</sub>(i) = u(i) ⊕ u(i−1) ⊕ u(i−2),  c<sub>2</sub>(i) = u(i) ⊕ u(i−2)

u(i) is the input bit at step i; u(i−1) and u(i−2) are stored past bits; ⊕ is modulo-2 addition; c1(i) and c2(i) are the two output bits.

The generator sequences are g1 = 111 and g2 = 101. A 1 in a generator means that tap is connected to the adder. From state 00, input 1 gives c1 = 1 ⊕ 0 ⊕ 0 = 1 and c2 = 1 ⊕ 0 = 1, output 11. The new state is 10. This spreading lets the decoder use several received bits to decide one message bit.

State diagram, tree and trellis

The state is the last K − 1 input bits. For K = 3 there are 22 = 4 states: 00, 10, 01 and 11. Each edge is labelled input bit / two output bits. The figure shows the four states and all eight edges.

The code tree unrolls the same diagram in time. The trellis repeats it for each step and merges paths that reach the same state. The free distance dfree is the smallest Hamming distance between any two distinct valid codewords, over all message lengths. For this encoder dfree = 5.

To end at state 00, append K − 1 = 2 zero bits after the message. These flush bits are not message bits. They cost a little rate but terminate the trellis, so the decoder knows the final state.

Viterbi decoding

Viterbi decoding is maximum-likelihood sequence detection for a memoryless channel. It compares the whole received sequence with every trellis path, without listing all paths.

  1. Lay out the trellis for the received length. At time i there are 2K−1 states; for K = 3, four states.
  2. For hard decisions, compare each received n-bit group with the n output bits on each branch. The branch metric is the Hamming distance, the count of positions that differ.
  3. The path metric is the sum of branch metrics from the start to that state. At each state keep only the smallest path metric and its survivor path. This operation is add-compare-select.
  4. After the last stage, pick the state with the smallest path metric. If the trellis was terminated, pick state 00. Trace back the survivor path; its input bits are the decoded message.

Each stage does about 2K−1 compare-select operations. Traceback memory grows with the received length. Soft-decision decoding uses Euclidean distance or correlation instead of Hamming distance and gives about 2 dB gain over hard decisions.

Worked example

Question. A rate 1/2, K = 3 convolutional encoder uses g1 = 111 and g2 = 101. (a) Encode the message 1011 followed by two zero flush bits. (b) The received word has bit 7 flipped. Decode it and give the surviving path metric.

  1. Append K − 1 = 2 zero bits to 1011: message bits 1 0 1 1 0 0.
  2. Start state 00. Step 1: input 1, state 00, output 11, next state 10. Step 2: input 0, state 10, output 10, next state 01. Step 3: input 1, state 01, output 00, next state 10. Step 4: input 1, state 10, output 01, next state 11. Step 5: input 0, state 11, output 01, next state 01. Step 6: input 0, state 01, output 11, next state 00.
  3. Read outputs in order: 11 10 00 01 01 11. The transmitted word is 111000010111.
  4. Bit 7 of the transmitted word is the 0 in the fourth pair 01. Flip it: the received word is 111000110111. Received pairs are 11 10 00 11 01 11.
  5. The path 00 → 10 → 01 → 10 → 11 → 01 → 00 has branch outputs 11, 10, 00, 01, 01, 11. Branch metrics against the received pairs are 0, 0, 0, 1, 0, 0. Path metric = 0 + 0 + 0 + 1 + 0 + 0 = 1.

Answer. The encoded word is 111000010111, the received word is 111000110111, the surviving path metric is 1, and the decoded message is 1011.

Exam traps

  • Treating K as the memory. The constraint length is K = memory + 1, so a two-cell encoder has K = 3.
  • Forgetting the K − 1 flush bits, so the trellis never returns to state 00 and the final state is unknown.
  • Mixing branch metric with path metric. A branch metric covers one trellis stage; a path metric is the accumulated sum.
  • Using 2K states in the trellis. The state count is 2K−1.
  • Using Hamming distance for soft-decision decoding. Soft decisions need Euclidean distance or a correlation measure.

7.9 BCH, turbo and LDPC codes

Shannon proved codes can come close to capacity. BCH codes are cyclic codes with a guaranteed minimum distance. Turbo codes run two convolutional encoders in parallel, split by an interleaver, and decode by passing soft messages. LDPC codes do the same on a sparse graph. Turbo and LDPC reach within about a decibel of capacity; BCH stays a few dB away. Wi-Fi, 4G/5G data links and flash controllers run these codes.

You need: 7.5 for the capacity wall, 7.6 for d_min and the Hamming bound, 7.7 for generator polynomials, and 7.8 for trellis and soft decisions.

BCH codes: a guaranteed number of errors

BCH stands for Bose–Chaudhuri–Hocquenghem. A BCH code is a cyclic code (see 7.7) whose generator polynomial g(x) is built around a chosen error count t. Pick t first; the code then corrects any t errors in the block.

The arithmetic runs in GF(2m), a field with 2m elements, formed by adjoining to GF(2) a root α of a primitive polynomial. A binary BCH code contains every polynomial over GF(2) that has α, α², …, α2t as roots. Those 2t consecutive powers create the distance guarantee.

n = 2<sup>m</sup> − 1,   d<sub>min</sub> ≥ 2t + 1,   k = n − deg g(x),   R = k/n

n is the block length in bits, m is the field exponent, t is the number of correctable errors, d_min is the minimum Hamming distance, g(x) is the generator polynomial, k is the number of message bits and R is the code rate.

Take m = 4, so n = 15. Two common codes are the (15,7) code with t = 2 and d_min ≥ 5, and the (15,5) code with t = 3 and d_min ≥ 7. The (15,7) code sends 7 message bits in 15, so R = 0.467.

Decoding works on polynomials: the syndromes give an error-locator polynomial, its roots give the error positions, and those bits are flipped. Berlekamp–Massey finds the locator; a Chien search finds its roots.

Reed–Solomon codes use the same construction on symbols of GF(2m) instead of single bits. They fight bursts well and appear on CDs, DVDs, QR codes and deep-space links.

Turbo codes: two encoders, one interleaver

A turbo code makes two encoders read the same block in different orders, then lets two decoders exchange soft opinions about every bit.

Encoding: block d enters a recursive systematic convolutional (RSC) encoder, which sends d out unchanged — systematic — and adds parity p1. The interleaver π, a fixed permutation, shuffles d into a second RSC encoder producing p2. A multiplexer sends d, p1 and p2: three output bits per input bit, R = 1/3.

Recursive means the shift register has feedback, so its state depends on a running sum of past inputs. A single 1 does not quickly return the trellis to the all-zero state, which removes most low-weight codewords.

Puncturing raises the rate by deleting parity bits. Drop half of p1 and half of p2 and each input bit sends 1 + 0.5 + 0.5 = 2 bits, so R = 1/2.

The interleaver is the heart of the design. A pattern giving a low-weight codeword in encoder 1 is scattered into high-weight data for encoder 2, so a low-weight codeword needs both encoders to agree, which is rare.

Decoding is iterative and soft. Decoder 1 takes the systematic bits and p1, computes a reliability (log-likelihood ratio) per bit, removes what it already knew, and passes the leftover extrinsic information to decoder 2 along with p2. Decoder 2 answers the same way. A few rounds suffice. Each decoder is a MAP (BCJR) detector or the simpler SOVA. On blocks of thousands of bits, turbo codes come within about a decibel of capacity. LTE uses them for data channels.

LDPC codes: belief propagation on a sparse graph

An LDPC (low-density parity-check) code is a linear block code (see 7.6) whose parity-check matrix H is sparse: almost every entry is zero, with few 1s in each row and column. Sparsity lets n reach thousands of bits and still decode in real time.

The code is drawn as a Tanner graph with two kinds of nodes. Each variable node is one of the n code bits and holds a soft belief about it. Each check node is one parity equation, that is, one row of H, and there are n − k of them. An edge joins variable v to check c wherever H has a 1.

Decoding is belief propagation. Each round, every variable node sends its belief along its edges. Each check node combines the beliefs it receives and replies with how strongly each bit is constrained by its parity equation. Variable nodes then update. Only the 1s of H are touched, so a round costs time proportional to the number of edges, not to n².

Regular (j,k) codes have j ones per column and k ones per row; irregular codes with mixed degrees do better. Long blocks with good degree distributions come within a fraction of a decibel of capacity. Short blocks or badly chosen degrees show an error floor: the bit error rate curve flattens at high SNR instead of falling steeply. Wi-Fi (802.11n/ac), DVB-S2 satellite television and 5G data channels use LDPC.

Choosing between them

All three are linear codes. They differ in block length, decoder and cost. Longer blocks with soft iterative decoding buy closeness to capacity; the price is latency, since the whole block must be buffered, and decoder complexity.

Worked example

Question. A link is offered a BCH (15,7) code and a turbo code. (a) For the BCH code find n, k, t, d_min, R, and check the Hamming bound. (b) The turbo encoder uses two rate-1/2 RSC encoders and sends the systematic bit with both parity bits; find the rate, then the rate after puncturing every second parity bit.

  1. Read n = 15 and k = 7 from the notation (n,k).
  2. The block length fixes m: n = 2^m − 1 = 15 gives m = 4. For m = 4 the (15,7) BCH code has t = 2.
  3. Guaranteed minimum distance: d_min ≥ 2t + 1 = 5.
  4. Code rate: R = k/n = 7/15 = 0.4667.
  5. Hamming bound check. Patterns of weight ≤ 2: 1 + C(15,1) + C(15,2) = 1 + 15 + 105 = 121.
  6. The bound requires 2^k × 121 ≤ 2^n, i.e. 121 ≤ 2^(15−7) = 256. It holds, with 135 to spare.
  7. Spare room does not make it a 3-error code: correcting 3 would need 1 + 15 + 105 + 455 = 576 ≤ 256, which fails.
  8. Turbo, mother code: output per input bit is 1 systematic + 1 + 1 parity = 3, so R = 1/3 = 0.3333.
  9. Puncturing every second parity bit keeps half of p1 and half of p2. Output per input bit = 1 + 0.5 + 0.5 = 2, so R = 1/2 = 0.5.

Exam traps

  • Thinking a strong code can beat capacity. Turbo and LDPC codes approach the Shannon limit from below; nothing works above it.
  • Confusing code rate with redundancy when puncturing is given. Recount the bits actually transmitted, not the mother code's bits.
  • Writing d_min = 2t + 1 as exact. The design guarantees d_min ≥ 2t + 1; the true minimum distance may be larger.
  • Using n = 2^m − 1 with the wrong m. n = 15 needs m = 4, not m = 15.
  • Making the turbo rate 1/4. The systematic bit goes out once, so two rate-1/2 encoders make 1/3, not 1/4.

Takeaways

  1. Information depends only on probability: a sure symbol (P = 1) tells you nothing, so its self-information is zero.
  2. Entropy is largest when all symbols are equally likely and equals log₂ M for M equally likely symbols.
  3. Huffman coding always gives the smallest average length among prefix codes for a given set of probabilities.
  4. Mutual information measures what the channel output tells you about the input; it is zero when input and output are independent.
  5. For a band-limited AWGN channel the capacity grows only logarithmically with power but linearly with bandwidth.
  6. The channel coding theorem promises small error probability below capacity but gives no construction; the codes in 7.6 to 7.9 are that construction.
  7. Syndrome decoding turns error correction into a table lookup on the error pattern, which is far smaller than the set of received words.
  8. Cyclic codes allow encoder and syndrome circuit to be built from shift registers and XOR gates, which is why they appear in hardware.
  9. Long blocks with soft iterative decoding (turbo, LDPC) get within a fraction of a decibel of the Shannon limit.

Understand State the source coding theorem. Explain Shannon–Fano coding and Huffman coding, and list the differences between them. 12 marks

Source coding theorem: L̄ can be made as close to H as we wish but never below it, with H ≤ L̄ < H + 1; Shannon–Fano: sort probabilities, split into two groups of nearly equal total probability, assign 0 and 1, recurse; Huffman: repeatedly merge the two smallest probabilities, build the tree upward, read codes from root to leaf; Shannon–Fano is not always optimal; Huffman is optimal for a given symbol set, but needs the whole tree at the encoder.

Understand Define mutual information for a discrete memoryless channel and prove I(X;Y) = H(X) − H(X|Y) = H(Y) − H(Y|X). Also define the binary symmetric channel. 10 marks

Joint entropy H(X,Y) = H(X) + H(Y|X) = H(Y) + H(X|Y); I(X;Y) = H(X) + H(Y) − H(X,Y); BSC transition matrix with crossover probability p; symmetry gives H(Y|X) = H(p); I(X;Y) = 0 when input and output are independent; maximum for equiprobable input.

Understand State the channel coding theorem and explain its meaning and its limitations. 8 marks

Statement: for R < C, codes exist with arbitrarily small error probability; for R > C the error probability cannot be made to vanish; Applies to long blocks, so the decoder may be complex and the delay large; Does not tell us how to build the code; that is the job of the later sections; Contrast with the source coding theorem.

Apply

Apply A source has six symbols with probabilities 0.4, 0.2, 0.15, 0.1, 0.1, 0.05. Construct a Huffman code, find the average codeword length, the entropy, the efficiency and the redundancy. 12 marks

Correct merging order and the resulting tree; Codeword lengths and the average L̄ = Σ pᵢ lᵢ; Entropy H computed symbol by symbol in bits; Efficiency η = H/L̄ as a percentage and redundancy 1 − η; Check Kraft inequality Σ 2^(−lᵢ) ≤ 1.

Apply A binary symmetric channel has crossover probability p = 0.01. Find the channel capacity in bits per channel use for equiprobable input, and the capacity when p = 0.5. Comment. 10 marks

C = 1 − H(p) for the BSC, with H(p) = −p log₂ p − (1 − p) log₂(1 − p); Evaluate H(0.01) ≈ 0.08 bits, so C ≈ 0.92 bits per use; At p = 0.5 the output is independent of the input and C = 0; Comment: the channel is useless at p = 0.5, and a p near 1 is as good as p near 0 because the errors can be inverted.

Apply For the (7,4) Hamming code, write the generator and parity-check matrices, encode the message 1011, and use the syndrome to correct the received word 1011011. 15 marks

G in systematic form [I₄ | P] and H = [Pᵀ | I₃]; c = mG, giving the seven-bit codeword; Syndrome S = rHᵀ and the single-error syndrome table; Identify the error position and flip that bit; State d_min = 3, so the code corrects one error per word.

Apply A cyclic code uses generator polynomial g(x) = 1 + x + x³ over GF(2). Encode the message polynomial 1 + x² by polynomial division and find the syndrome when the received word is 1100101. 12 marks

Multiply m(x) by x^(n−k) and divide by g(x) to get the remainder as parity bits; Codeword is the remainder appended to the message; Received polynomial divided by g(x) gives the syndrome polynomial; Non-zero syndrome points to the error; the syndrome circuit is a shift register with feedback taps at g(x).

Apply A rate-1/2 convolutional code with constraint length 3 has generators 101 and 111. Draw the encoder, the state diagram and the trellis, and decode the received sequence 11 01 11 10 by the Viterbi algorithm. 13 marks

Shift register with two memory stages and two modulo-2 adders; State transition table and the trellis for at least four time steps; Add-compare-select metric update at each step; Survivor path and traceback to the most likely input bits; Free distance and the number of errors it can correct.

Analyze and evaluate

Analyze A channel has bandwidth B and signal-to-noise ratio S/N. Using C = B log₂(1 + S/N), examine how doubling the bandwidth compares with doubling the transmitted power. Support your answer with numbers. 12 marks

Doubling B roughly doubles C when S/N is fixed; Doubling S/N adds B log₂(1 + 2S/N) − B log₂(1 + S/N), which is less than a doubling; As B → ∞ with fixed total power, C tends to 1.44 S/N₀; Practical conclusion: bandwidth is the cheaper resource for capacity, power the dearer one.

Analyze Compare Hamming, BCH, turbo and LDPC codes on rate, block length, decoding complexity and error performance, and state where each is used. 13 marks

Hamming: small block, single-error correction, trivial hardware, used in memory and simple links; BCH: multiple-error correction, algebraic decoding, used in storage and older satellite links; Turbo: parallel concatenated codes with iterative soft decoding, close to the Shannon limit, used in 3G/4G; LDPC: sparse parity-check matrix, belief propagation, used in 5G, Wi-Fi and deep-space; Trade-off: long blocks and soft information buy performance at the cost of delay and complexity.

Evaluate Show that the average length of any prefix code cannot be less than the source entropy. Discuss what the extra length costs in a practical system. 10 marks

Use Kraft inequality and the log-sum inequality to show L̄ ≥ H; Equality holds when all lᵢ = −log₂ pᵢ, that is, probabilities are powers of two; The gap H ≤ L̄ < H + 1 comes from rounding lengths to whole bits; Extra bits mean extra bandwidth or storage, visible on a UPI transaction record or a call bill.

Evaluate A system must deliver a bit error rate of 10⁻⁵ over a channel of known capacity. Using the channel coding theorem and the behaviour of convolutional and LDPC codes, judge whether the requirement can be met, and what happens if the code rate is chosen above capacity. 16 marks

Compare the proposed code rate R with C; R < C is the necessary condition; Channel coding theorem: existence, not construction; long blocks and soft decoding bring practice near the bound; Above capacity no code works: the error probability tends to a floor no matter the decoder; Convolutional with Viterbi gives about 2 dB coding gain at hard decision, more with soft decision; LDPC gains more; Practical limits: delay, decoder complexity, and the gap to the Shannon limit in decibels.

Glossary

Binary symmetric channel
A two-input two-output channel that flips the bit with probability p and passes it with probability 1 − p.
Bit
Unit of information when the logarithm is taken to base 2; one fair coin toss carries one bit.
Block code
A code that maps each group of k message bits to one fixed block of n transmitted bits.
Channel capacity
The maximum mutual information over all input distributions, in bits per channel use.
Code efficiency
Entropy divided by average codeword length, usually quoted as a percentage.
Conditional entropy
The uncertainty left in the input after the output is known, H(X|Y), also called equivocation.
Constraint length
The number of input bits, including the current one, that influence any single output bit of a convolutional code.
Discrete memoryless channel
A channel with finite input and output alphabets whose behaviour at each use is fixed and independent of past uses.
Entropy
The average information per source symbol, the minimum average number of bits needed to describe it.
Generator matrix
The k × n matrix G whose rows span the code, so a codeword is c = mG.
Generator polynomial
The polynomial g(x) of degree n − k that divides xⁿ − 1 and whose multiples are exactly the codewords of a cyclic code.
Hamming weight and distance
Weight is the number of ones in a word; distance is the number of positions in which two words differ.
Information rate
Entropy multiplied by the symbol rate, in bits per second.
Joint entropy
The uncertainty of the input and output taken together, H(X,Y).
Kraft inequality
The condition Σ 2^(−lᵢ) ≤ 1 that a set of codeword lengths must satisfy for a prefix code to exist.
Minimum distance
The smallest Hamming distance between any two codewords; a code with d_min corrects t = ⌊(d_min − 1)/2⌋ errors.
Mutual information
The reduction in uncertainty about the input caused by observing the output, in bits per channel use.
Parity-check matrix
The (n − k) × n matrix H orthogonal to every codeword, satisfying cHᵀ = 0.
Prefix code
A code in which no codeword is a prefix of another, so decoding needs no separators.
Self-information
The information in one outcome of probability P, equal to log₂(1/P) bits.
Shannon limit
The minimum signal-to-noise ratio per bit, about −1.6 dB, below which reliable communication is impossible however long the code.
Soft-decision decoding
Decoding that uses quantised received amplitudes instead of firm 0/1 decisions, gaining about 2 dB.
Symbol rate
Number of source symbols produced per second, measured in baud or symbols per second.
Syndrome
The (n − k)-bit vector S = rHᵀ, which is zero for a valid codeword and depends only on the error pattern.
Trellis
A time-indexed diagram of the encoder states and allowed transitions, used by the Viterbi decoder.
