7.1 Information measure, entropy and information rate

Some messages surprise you more than others. A symbol that appears rarely carries more information than one that appears all the time. Information theory turns this everyday idea into a number. Self-information measures one symbol; entropy measures the average symbol of a source; information rate converts that average into bits per second. These numbers tell you how much a source can be compressed and how much channel capacity it needs. They sit under PCM bit rates, Huffman coding, and the Shannon capacity formula used to plan a microwave or fibre link.

You need: probability, random variables and the idea of a random source (see the probability and random variables review).

Self-information of a symbol

A discrete source emits one symbol at a time from a finite alphabet of M symbols. Call symbol i's probability pi, with 0 < pi ≤ 1 and Σpi = 1. The self-information of symbol i is the surprise when that symbol arrives. A rare symbol has small pi, so it carries a large amount of information. A certain symbol, pi = 1, carries zero information because you already knew it was coming.

I(xᵢ) = log₂(1/pᵢ) = −log₂ pᵢ bits

I(xi) is the self-information of symbol i in bits; pi is its probability; log₂ is the logarithm to base 2.

The logarithm is there because independent symbols must add their information. If two independent symbols have probabilities pi and pj, their joint probability is pipj. We want total information to be the sum: I(pipj) = I(pi) + I(pj). Only a logarithm turns a product into a sum: log(1/(pipj)) = log(1/pi) + log(1/pj). Base 2 makes the unit the bit, the information in one fair coin toss.

Entropy of a source

H(X) = Σ pᵢ log₂(1/pᵢ) = −Σ pᵢ log₂ pᵢ  bits/symbol

H(X) is the source entropy in bits per symbol; the sums run over the M symbols, i = 1 to M; pi is the probability of symbol i; a term with pi = 0 is taken as 0.

Entropy is the average self-information per symbol. Before a symbol arrives it is the uncertainty about which symbol will come. After the symbol arrives it is the average information you gained. A source whose symbols have nearly equal probabilities has high entropy; a source that almost always sends the same symbol has low entropy. Some syllabi call H the average information or the uncertainty of the source.

For fixed M, H is largest when all M symbols are equally likely: Hmax = log₂ M. A 4-level equal source has H = 2 bits/symbol; an 8-level equal source has H = 3 bits/symbol. Unequal probabilities always give less than log₂ M. The binary case uses p for one symbol and 1−p for the other: H(p) = −p log₂ p − (1−p) log₂(1−p). It peaks at 1 bit when p = 0.5 and falls to 0 at p = 0 or p = 1. Entropy is the lower bound that Huffman coding tries to reach.

Information rate

R = rs H bits/s

R is the information rate in bits per second; rs is the symbol rate in symbols per second; H is the entropy in bits per symbol.

The symbol rate says how fast symbols arrive. The information rate says how fast information arrives. A source emitting 4 symbols with probabilities 1/2, 1/4, 1/8, 1/8 has H = 1.75 bits/symbol. At rs = 2000 symbols/s, R = 2000 × 1.75 = 3500 bit/s. If the 4 symbols were equally likely, H would be 2 bits/symbol and R would be 4000 bit/s at the same symbol rate.

  • An 8-level equal source has H = log₂ 8 = 3 bits/symbol. At 1000 symbols/s, R = 3000 bit/s.
  • Bits per symbol is an entropy answer. Bits per second is an information-rate answer. Multiply by rs and keep the units.
  • These formulas assume a memoryless source: each symbol's probability does not depend on earlier symbols. Dependence between symbols is handled by conditional entropy (see mutual information).

Information rate is the number you compare with channel capacity. If R is below capacity, reliable transmission is possible; if R is above capacity, it is not. That comparison is the whole point of measuring a source before designing the link.

Worked example

Question. A memoryless source emits four symbols with probabilities 1/2, 1/4, 1/8 and 1/8 at a symbol rate of 2000 symbols per second. Find the information carried by each symbol, the source entropy, and the information rate.

  1. List the probabilities: p1 = 1/2, p2 = 1/4, p3 = 1/8, p4 = 1/8. The symbol rate is rs = 2000 symbols/s.
  2. Symbol 1: I1 = log₂(1/(1/2)) = log₂ 2 = 1 bit.
  3. Symbol 2: I2 = log₂(1/(1/4)) = log₂ 4 = 2 bits.
  4. Symbol 3: I3 = log₂(1/(1/8)) = log₂ 8 = 3 bits.
  5. Symbol 4: I4 = log₂(1/(1/8)) = log₂ 8 = 3 bits.
  6. Entropy: H = (1/2)(1) + (1/4)(2) + (1/8)(3) + (1/8)(3) = 0.5 + 0.5 + 0.375 + 0.375 = 1.75 bits/symbol.
  7. Information rate: R = rsH = 2000 × 1.75 = 3500 bit/s.

Answer. The four symbols carry 1 bit, 2 bits, 3 bits and 3 bits; the entropy is 1.75 bits/symbol; the information rate is 3500 bit/s.

Worked example 2

Question. A voice signal band-limited to 4 kHz is sampled at the Nyquist rate. Each sample is quantised to one of four levels whose probabilities are 1/8, 3/8, 3/8 and 1/8, and successive samples are independent. Find the entropy per sample and the information rate. How much higher would the rate be with four equally likely levels?

  1. Nyquist rate: rs = 2 × 4000 = 8000 samples/s. Each sample is one source symbol.
  2. Self-information: the two outer levels carry log₂ 8 = 3 bits each; the two inner levels carry log₂(8/3) = 1.415 bits each.
  3. Entropy: H = 2 × (1/8)(3) + 2 × (3/8)(1.415) = 0.750 + 1.061 = 1.811 bits/sample.
  4. Information rate: R = rsH = 8000 × 1.811 = 14 490 bit/s ≈ 14.5 kbit/s.
  5. Equal levels: Hmax = log₂ 4 = 2 bits/sample and R = 8000 × 2 = 16 000 bit/s, which is 1510 bit/s (10.4 %) more.

Answer. H = 1.811 bits/sample and R ≈ 14.5 kbit/s; equally likely levels would give 16 kbit/s.

Exam traps

  • Using log₁₀ or ln and still writing the answer in bits. A base-10 answer is in hartleys and a base-e answer is in nats; convert to bits or change the base.
  • Quoting bits per symbol when the question asks for bits per second. Multiply by the symbol rate and check the units.
  • Assuming every M-level source has entropy log₂ M. That maximum holds only when all M symbols are equally likely.
  • Forgetting that p log₂ p tends to 0 as p tends to 0, so a zero-probability symbol adds no term to the entropy.
  • Confusing the self-information of one symbol with the average entropy of the whole source.

7.2 Source coding: Shannon-Fano and Huffman codes

Source coding assigns short binary words to likely symbols and longer words to rare symbols. A prefix code keeps every codeword from being the start of another, so the receiver decodes bit by bit with no separators. Shannon-Fano and Huffman both build such codes from a probability list; Huffman is the standard method. The average length L̄ in bits per symbol can approach the entropy H(X), never fall below it. File compression, image formats and voice codecs use these ideas daily.

You need entropy and information rate for H(X).

Prefix codes and the source coding theorem

A fixed-length code wastes bits when one symbol dominates. A source emits symbols with probabilities pᵢ. Give symbol i a binary codeword of length lᵢ bits. A prefix code has no codeword that is the start of another. The set {0, 10, 110, 111} is prefix-free. After reading 10, the receiver knows the symbol ended; it never needs to look ahead. Decoding is instant, one bit at a time.

The Kraft inequality says that for any binary prefix code, Σ 2−lᵢ ≤ 1, where lᵢ is the length in bits of the codeword for symbol i. It is necessary and sufficient for integer lengths. We state it without proof.

L̄ = Σ pᵢ lᵢ

L̄ is the average codeword length in bits per symbol; pᵢ is the probability of symbol i; lᵢ is the length in bits of its codeword. H(X) is the entropy from Chapter 7.1, in bits per symbol.

H(X) ≤ L̄ < H(X) + 1

H(X) is the source entropy in bits per symbol. No prefix code goes below H(X); some prefix code (Huffman is one) has L̄ < H(X) + 1, and coding blocks of n symbols brings the gap below 1/n. The gap comes from whole-bit lengths and vanishes only when every probability is a power of 1/2.

η = H(X) / L̄, redundancy = 1 − η

η is the coding efficiency, a pure ratio; H(X) and L̄ must use the same logarithm base, normally base 2. Redundancy is the fraction of average length not carrying entropy.

Shannon-Fano coding

Shannon-Fano builds a code top-down by repeated splitting. The split rule uses total probability, not symbol count.

  1. Sort the symbols in decreasing order of probability.
  2. Split the sorted list into two groups so that the two group probabilities are as nearly equal as possible. Keep the original order inside each group.
  3. Give every codeword in the top group a leading 0 and every codeword in the bottom group a leading 1, or the reverse. Fix the choice and keep it.
  4. Repeat the split inside each group until a group has one symbol.
  5. Read each codeword from the root to its leaf.

The split is a heuristic: sort first, and where two cuts tie, try both.

Huffman coding

Huffman builds a code bottom-up by merging the least likely symbols first. This keeps large probabilities near the root and gives them short words.

  1. Make one leaf node for each symbol, labelled with its probability.
  2. Take the two nodes with the smallest probabilities. Join them under a new parent whose probability is their sum.
  3. Label one edge from the parent 0 and the other edge 1. The choice is arbitrary if kept consistent.
  4. Put the new parent back into the list and remove the two children.
  5. Repeat until one node remains. Its probability is 1.0.
  6. Read each codeword from the root to its leaf.

The two least likely symbols become siblings at the greatest depth. A Huffman code is prefix-free by construction and, among binary prefix codes coding one symbol at a time, it has the smallest possible L̄. Ties can produce different codewords but never a different L̄. They do change the spread of lengths: when a merged node ties with a single symbol, placing the merged node as high as possible (merging it later) gives the minimum-variance Huffman code, which keeps the output bit rate steadier and the buffer smaller.

Worked example

Question. A discrete memoryless source emits five symbols A, B, C, D and E with probabilities 0.4, 0.2, 0.2, 0.1 and 0.1. (a) Find the entropy H(X). (b) Build the Huffman code, merging the two smallest probabilities first, and break the 0.2 tie at the second step by merging C with DE. (c) Find the average codeword length L̄ and the coding efficiency η.

  1. Sort the probabilities: A = 0.4, B = 0.2, C = 0.2, D = 0.1, E = 0.1.
  2. Entropy: H(X) = −Σ pᵢ log₂ pᵢ = 0.4 log₂(2.5) + 2(0.2 log₂ 5) + 2(0.1 log₂ 10).
  3. Use log₂(2.5) = 1.3219, log₂ 5 = 2.3219 and log₂ 10 = 3.3219. Then H(X) = 0.4(1.3219) + 0.4(2.3219) + 0.2(3.3219) = 0.5288 + 0.9288 + 0.6644 = 2.1219 ≈ 2.12 bits/symbol.
  4. Huffman merges: D 0.1 + E 0.1 = 0.2; then B, C and DE tie at 0.2, and merging C with DE gives 0.4; then B 0.2 + CDE 0.4 = 0.6; then A 0.4 + BCDE 0.6 = 1.0.
  5. Read codes: A = 0, B = 10, C = 110, D = 1110, E = 1111. Lengths are 1, 2, 3, 4 and 4 bits.
  6. Average length: L̄ = 0.4(1) + 0.2(2) + 0.2(3) + 0.1(4) + 0.1(4) = 2.2 bits/symbol.
  7. Efficiency: η = H(X)/L̄ = 2.1219/2.2 = 0.9645 = 96.45 %. Redundancy = 1 − 0.9645 = 0.0355 = 3.55 %.
  8. Spread of lengths: σ² = Σ pi(li − L̄)² = 0.4(1.44) + 0.2(0.04) + 0.2(0.64) + 0.2(3.24) = 1.36. Breaking the same tie the other way (merge B with C, then A with DE) gives lengths 2, 2, 2, 3, 3, the same L̄ = 2.2 but σ² = 0.16.

Answer. H(X) = 2.12 bits/symbol, L̄ = 2.2 bits/symbol and η = 96.45 % for A = 0, B = 10, C = 110, D = 1110, E = 1111; the minimum-variance tie choice keeps L̄ = 2.2 with σ² = 0.16 instead of 1.36.

Exam traps

  • Splitting an unsorted Shannon-Fano list. The rule assumes decreasing order; a valid but poor code can result.
  • Reporting one symbol's codeword length as the average length. L̄ is the probability-weighted sum Σ pᵢ lᵢ, not a single lᵢ.
  • Mixing natural logs with base-2 lengths. Use base 2 for both; answers are in bits per symbol.
  • Writing redundancy as H(X)/L̄. Efficiency is H(X)/L̄; redundancy is 1 − H(X)/L̄.
  • Claiming the Huffman code of a source is unique. Tie choices change the codewords and the variance of the lengths, never L̄.

7.3 Mutual information and discrete memoryless channels

Mutual information measures how much one random variable tells you about another. In a communication link, the input X is the message symbol and the output Y is what the receiver sees. The channel adds uncertainty, so Y is an imperfect copy of X. Mutual information I(X;Y) is the part of H(X) that the output removes. Engineers use it to compare channels, predict achievable rates, and see why a noisy channel cannot carry unlimited data. It is the quantity that channel capacity maximises, and the basis for error-control coding.

You need: entropy from entropy and information rate and conditional probability (see the probability and random variables review).

Joint entropy and conditional entropy

Take two discrete random variables X and Y. X has alphabet {x₁, …, xM} and Y has alphabet {y₁, …, yN}. The joint entropy H(X,Y) is the average uncertainty of the pair:

H(X,Y) = −Σᵢ Σⱼ P(xᵢ,yⱼ) log₂ P(xᵢ,yⱼ)

P(xi,yj) is the probability that X=xi and Y=yj; the sum runs over all pairs; entropy is in bits when log₂ is used.

Conditional entropy H(X|Y) is the uncertainty left in X after Y is known:

H(X|Y) = −Σᵢ Σⱼ P(xᵢ,yⱼ) log₂ P(xᵢ|yⱼ)

P(xi|yj) is the conditional probability of xi given yj. H(Y|X) is defined the same way with the roles swapped.

Both formulas use the convention 0 log₂ 0 = 0, so terms with zero probability contribute nothing to the sum. A channel matrix with zero entries therefore causes no trouble.

The chain rule splits the joint uncertainty:

H(X,Y) = H(X) + H(Y|X) = H(Y) + H(X|Y)

H(X) is the source entropy from Chapter 7.1. The rule says: first learn X, then learn the extra uncertainty in Y given X. Order does not change the total. In general H(X|Y) ≠ H(Y|X). The first asks how much uncertainty about the input remains after the output; the second asks how much uncertainty about the output remains after the input. They are equal only in special symmetric cases.

Mutual information

Mutual information is the reduction in uncertainty:

I(X;Y) = H(X) − H(X|Y) = H(Y) − H(Y|X)
       = H(X) + H(Y) − H(X,Y)

I(X;Y) is mutual information in bits, H(X) and H(Y) are source and output entropies, and H(X|Y), H(Y|X) are conditional entropies. The three forms are equivalent by the chain rule.

I(X;Y) is symmetric: I(X;Y)=I(Y;X). It measures shared uncertainty, not direction. It cannot be negative, because conditioning cannot increase average uncertainty. It cannot exceed either entropy: 0 ≤ I(X;Y) ≤ min(H(X), H(Y)). If X and Y are independent, I=0. If Y is a deterministic function of X, I=H(Y) and H(Y|X)=0. If X is a deterministic function of Y, I=H(X) and H(X|Y)=0.

Picture H(X) and H(Y) as two overlapping regions. The overlap is I(X;Y); the part of H(X) outside it is H(X|Y), also called the equivocation, and the part of H(Y) outside it is H(Y|X). Because I is a part of H(X), it can never be larger than H(X). Some syllabi call I(X;Y) the average mutual information.

Discrete memoryless channels and BSC

A discrete memoryless channel (DMC) has input alphabet X, output alphabet Y, and transition probabilities P(yj|xi). The channel matrix has rows for inputs and columns for outputs:

[P(Y|X)] = [P(yⱼ|xᵢ)], M rows × N columns

row i gives the output distribution when input xi is sent, so every row sums to 1. Memoryless means each output Yk depends only on the input Xk at that instant, not on earlier inputs or outputs.

For a binary symmetric channel (BSC), input and output are {0,1}. With crossover probability p, a sent bit flips with probability p and is correct with probability 1−p. The channel matrix is [[1−p, p],[p, 1−p]]. Given the input, the output uncertainty is the binary entropy:

H(Y|X) = H(p) = −p log₂ p − (1−p) log₂(1−p)

p is the crossover probability and H(p) is in bits. Then

I(X;Y) = H(Y) − H(p)

H(Y) depends on the input distribution P(X). For equiprobable input, H(Y)=1 bit because the BSC is symmetric, so I=1−H(p).

A binary erasure channel passes the bit correctly with probability 1−e and outputs an erasure symbol with probability e; its capacity is 1−e bits per channel use, reached with equiprobable input. If the channel carries rs symbols per second, the information rate is R = rs I(X;Y) bits/s.

Worked example

Question. A binary symmetric channel has crossover probability p = 0.1. The input symbols 0 and 1 are equally likely. The channel is used at rs = 1000 symbols per second. Find H(X), H(Y|X), H(Y), I(X;Y) and the information rate R. Give entropies in bits per symbol and R in bit/s.

  1. Input distribution: P(0)=P(1)=0.5. H(X)=−0.5 log₂0.5 −0.5 log₂0.5 = 1 bit/symbol.
  2. For a BSC, H(Y|X) = H(p) with p = 0.1: H(0.1) = 0.1 log₂ 10 + 0.9 log₂(1/0.9) = 0.3322 + 0.1368 = 0.469 bits/symbol.
  3. The BSC is symmetric and the input is equiprobable, so P(Y=0)=P(Y=1)=0.5. Thus H(Y)=1 bit/symbol.
  4. I(X;Y)=H(Y)−H(Y|X)=1−0.469=0.531 bits/symbol.
  5. R=rs I=1000×0.531=531 bit/s.

Answer. H(X)=1 bit/symbol, H(Y|X)=0.469 bits/symbol, H(Y)=1 bit/symbol, I(X;Y)=0.531 bits/symbol and R=531 bit/s.

Exam traps

  • Swapping H(X|Y) and H(Y|X). They answer different questions and are not generally equal; only symmetric cases make them equal.
  • Claiming I(X;Y) can be larger than H(X) or H(Y). The overlap cannot be larger than either region; 0 ≤ I ≤ min(H(X),H(Y)).
  • Writing I = H(X) + H(Y) + H(X,Y). H(X) + H(Y) counts the overlap twice; subtracting H(X,Y), which counts it once, leaves the overlap alone. With the plus sign the result is larger than H(X,Y) itself, so it cannot be a shared part.
  • Reading a channel matrix row as an output distribution that must sum with other rows. Each row is conditional on one input and sums to 1; columns need not sum to 1.
  • For a BSC, plugging p into I directly. The input-dependent term is H(Y); the fixed noise term is H(p).

7.4 Channel capacity and Shannon-Hartley theorem

Channel capacity is the largest mutual information any input distribution can create for a given channel. It is the highest rate at which the error probability can be made as small as we like, using long enough codes. For a band-limited channel with additive white Gaussian noise, the Shannon-Hartley law gives C = B log₂(1 + S/N) bits per second. That single number decides whether a telephone line, Wi-Fi link or satellite path can carry the rate we want. Link budgets, DSL planning and 5G design all start from it.

You need: mutual information I(X;Y), and white noise with power spectral density N₀ (see noise sources, white noise and AWGN).

Capacity of the AWGN channel

Take a channel with input X and output Y. Mutual information I(X;Y) measures how much of the input uncertainty the output removes. Capacity is the largest value of I(X;Y) we can get by choosing the input probabilities p(x):

C = max over p(x) of I(X;Y)

C is capacity in bits per channel use; p(x) is the input probability distribution; the channel p(y|x) is fixed.

For a continuous band-limited channel with additive white Gaussian noise, this maximisation gives the Shannon-Hartley law:

C = B log₂(1 + S/N)

C is capacity in bit/s; B is bandwidth in Hz; S is received signal power in W; N is noise power in the same bandwidth in W; S/N is a dimensionless power ratio.

Some syllabi call this result Shannon's channel capacity theorem or the Shannon-Hartley law. A decibel value is not a ratio. Convert first: S/N = 10SNR(dB)/10. For example, 30 dB means S/N = 10³ = 1000. Capacity per hertz is C/B = log₂(1 + S/N) bit/s/Hz; it says how many bits each hertz can carry.

Binary symmetric and erasure channels

For a binary symmetric channel (BSC), each bit flips with probability p, independent of other bits. The capacity is

C = 1 − H(p) bits per channel use

H(p) = −p log₂ p − (1−p) log₂(1−p) is the binary entropy function in bits; p is the bit-flip probability.

Equal input probabilities 0 and 1 reach this value. At p = 0 the channel is perfect, H(0)=0, so C=1. At p = 0.5 the output is independent of the input, H(0.5)=1, so C=0. At p = 1 every bit is inverted; the receiver can invert it back, so the channel is perfect again and C=1. This last point is a favourite trap. For a binary erasure channel with erasure probability pe, the capacity is

C = 1 − pe bits per channel use

pe is the probability that a bit is erased, not flipped.

An erased bit is lost, so one clean bit per use is the most we can send. The derivation is in Chapter 7.3.

Limits, units and the Shannon limit

Keep the units straight. C = B log₂(1 + S/N) gives bits per second. The BSC formula gives bits per channel use. One channel use may carry several bits, so a rate in bits per second is bits per use multiplied by the number of uses per second. Mixing the two is an easy way to lose marks.

What happens as B grows without limit? Noise power is N = N₀B, where N₀ is the noise power spectral density in W/Hz. Substitute:

C = B log₂(1 + S/(N₀B)) → (S/N₀) log₂ e ≈ 1.44 S/N₀ bits/s

S is signal power in W; N₀ is noise power spectral density in W/Hz; e is 2.718...; the arrow means B tends to infinity.

So infinite bandwidth does not give infinite capacity; capacity saturates at about 1.44 S/N₀. A wider bandwidth admits more noise as well as more signal. For reliable communication, the energy per information bit is Eb. The Shannon limit is the smallest Eb/N₀ that can support arbitrarily small error probability as the rate tends to zero: about −1.6 dB. Practical codes aim near this line; Chapter 7.9 shows how close they get. Capacity is an upper bound, not a promise that a simple uncoded link will work.

7.5 Channel coding theorem

The channel coding theorem says noise sets a speed limit, not a wall. For a discrete memoryless channel with capacity C bits per channel use, every code rate R below C has some long code whose decoding error can be made as small as you want. Above C, no code and no decoder can do that. The theorem promises existence, not a construction. It explains why repetition, parity checks and modern long codes help, and it gives the target that practical coding gain is measured against.

You need: channel capacity and entropy, and the idea of independent bit errors.

Code rate, redundancy and the theorem

Channel coding adds parity bits to message bits before transmission. A block code takes k message bits and sends n coded bits. Its code rate is R = k/n. R is information bits per channel use, not a bit rate in bit/s. The extra fraction 1 − R is the redundancy. For k = 100 and n = 150, R = 0.667 and redundancy is 0.333.

R = k / n, redundancy = 1 − R

k is the number of message bits per block; n is the number of transmitted bits per block; R is the code rate in information bits per channel use.

The theorem is stated for a discrete memoryless channel (DMC). In a DMC the output at any time depends only on the input at that time and on independent noise; past inputs do not change the present output rule. Let C be the channel capacity from Chapter 7.4, in bits per channel use.

R < C ⇒ Pₑ → 0 as n → ∞; R > C ⇒ Pₑ ≥ ε > 0

C is the channel capacity in bits per channel use; Pe is the probability that the decoder output differs from the k message bits; ε is some positive number that depends on the channel and R.

One proof uses random coding. Choose 2nR codewords independently from the input distribution that achieves C. For large n, a received word is likely near its own codeword and far from the others, because typical noise sequences form a small set. Nearest-codeword decoding has small average error over the random code. Some code in that set must be at least as good as the average.

For the binary symmetric channel (BSC) with crossover probability p, C = 1 − H(p). At p = 0.01, C = 0.919 bits per channel use. A rate 0.5 is allowed; 0.95 is not.

Promises, limits and coding gain

The theorem promises existence. It does not name a code. It says a code of some length n exists with small Pe, but not how to build it. It gives no bound on delay, memory or decoder complexity. A code with n = 10,000 may need a large buffer and a complex decoder. It also does not say Pe is zero at finite n. At finite n, Pe is small but positive.

Coding gain is the saving in required signal-to-noise ratio at a fixed error rate. Compare an uncoded link and a coded link that reach the same Pe. Use energy per information bit, Eb/N0. If uncoded needs 10 dB and coded needs 7 dB at the same error rate, the coding gain is 3 dB.

G = 10 log₁₀(γu/γc) dB

γu and γc are the values of Eb/N0, as power ratios, that the uncoded and the coded link need for the same error rate; Eb is the energy per information bit in joules and N0 the one-sided noise power spectral density in W/Hz.

The formula needs linear power ratios, not decibel values. Convert first with Eb/N0 = 10dB/10. So 10 dB becomes 10 and 7 dB becomes 5.01, and 10 log₁₀(10/5.01) = 3.0 dB. That is simply the difference of the two dB numbers, so with decibel figures you can subtract and get the same answer.

Above capacity the converse holds. If R > C, every decoder has Pe above a positive floor, no matter how clever. A decoder cannot create information the channel did not deliver. It can only choose the most likely message. A scheme that claims zero error above C is wrong.

Repetition and single parity check

The repetition code sends each message bit n times, with n odd. The decoder takes a majority vote. For n = 3, R = 1/3; a decoded bit is wrong only when two or three copies are wrong. For independent bit errors with probability p, Pb = 3p²(1 − p) + p³. At p = 0.01 this is 2.98 × 10−4, much below 0.01. With n = 5 the vote fails only when three or more copies are wrong: Pb = 9.85 × 10−6, but the rate falls to 0.2. Repetition buys a lower error rate only by giving rate away, which is exactly the trade the theorem says a good long code avoids.

Single parity check appends one bit so every codeword has an even number of 1s. With k message bits, n = k + 1 and R = k/(k+1). The receiver checks parity. Any odd number of bit errors makes parity odd and is detected. An even number of errors is not detected. A parity check detects errors but cannot correct them by itself; retransmission or a stronger code is needed.

These elementary codes show the trade. Repetition corrects errors but spends most bits on copies. Parity check spends one bit and detects simple errors cheaply. The theorem says better long codes exist below capacity; Chapter 7.6 to 7.9 build them.

Worked example

Question. A binary symmetric channel has crossover probability p = 0.01. Each message bit is sent three times and the receiver takes a majority vote. Find the code rate, the decoded bit error probability, and compare the rate with capacity.

  1. For a 3-repeat code, k = 1 and n = 3. Code rate R = k/n = 1/3 = 0.333.
  2. A decoded bit is wrong when exactly two copies are wrong or when all three are wrong. The two cases cannot happen together, so their probabilities add.
  3. Two wrong copies: choose which 2 of 3 are wrong in 3 ways. Probability = 3p²(1 − p) = 3 × (0.01)² × 0.99 = 0.000297.
  4. Three wrong copies: probability = p³ = (0.01)³ = 0.000001.
  5. Total decoded bit error probability Pb = 0.000297 + 0.000001 = 0.000298 = 2.98 × 10−4. Uncoded p = 0.01, so the error falls by a factor of 0.01/0.000298 = 33.6.
  6. Capacity of the BSC: C = 1 − H(p) = 1 − [−p log₂ p − (1 − p) log₂(1 − p)]. With p = 0.01, H(p) = 0.0808 and C = 0.919 bits per channel use.
  7. R = 0.333 < C = 0.919. The theorem allows arbitrarily small error with longer codes; this 3-repeat code is only a short example.

Answer. R = 0.333, Pb = 0.000298, and C = 0.919 bits per channel use, so R < C and the theorem allows the gain.

Exam traps

  • Treating the theorem as a construction. It proves that a code exists; it does not give the parity-check matrix, encoder or decoder.
  • Believing a better decoder can push Pe to zero when R > C. The converse forbids it for every decoder.
  • Calling R = k/n a bit rate in bit/s. R is information bits per channel use; the bit rate also needs the channel symbol rate.
  • Using p = 1% as p = 1 in H(p). Probabilities in entropy formulas must be between 0 and 1; 1% is 0.01.
  • Thinking a single parity check corrects one error. It detects an odd number of errors; it does not locate or correct them.

7.6 Linear block codes, Hamming codes and syndrome decoding

A linear block code turns k message bits into n coded bits by a fixed matrix multiplication. The set of all codewords is a subspace, so the encoder is simple and the decoder can name the error instead of guessing the message. The syndrome, an n−k bit vector, depends only on the error pattern. Hamming codes are the smallest useful family: the (7,4) code corrects one bit in seven. Such codes guard computer memory, storage, and control links where retransmission is costly. The next step is to build G and H and use the syndrome table to correct errors.

You need: the channel coding theorem for why codes are used, and modulo-2 (XOR) addition, where 1 ⊕ 1 = 0.

Encoding by a generator matrix

A binary linear block code takes k message bits and produces an n-bit codeword; it is called an (n,k) code. The code rate is R = k/n, the fraction of transmitted bits that carry new message information. The code is linear when the modulo-2 sum of any two codewords is also a codeword; the all-zero word is then always a codeword. Encoding is c = mG. Here m is a 1×k message row, G is a k×n generator matrix, and c is the 1×n codeword. All arithmetic is modulo 2.

Systematic form puts the message bits in plain view: G = [Ik | P]. Ik is the k×k identity block and P is a k×(n−k) parity block. The first k bits of c equal m; the last n−k bits are parity checks. The parity-check matrix is H = [PT | In−k], size (n−k)×n. Every codeword satisfies cHT = 0, and the matrices satisfy GHT = 0. The rows of H are the parity equations.

dmin = min w(c), c ≠ 0

w(c) is the Hamming weight, the number of 1 bits in c; dmin is the minimum Hamming distance between any two distinct codewords.

The Hamming distance d(c₁,c₂) is the number of positions where two words differ. For a linear code it equals the weight of c₁ ⊕ c₂, so the smallest distance is the smallest nonzero codeword weight. This one number sets how many errors the code can handle.

Syndrome decoding

Send c through a noisy channel and receive r. Write r = c ⊕ e, where e is the error pattern: a 1 marks a flipped bit. The decoder forms the syndrome s = rHT. Its length is n−k bits. Because cHT = 0, s = (c ⊕ e)HT = eHT. The syndrome therefore names the error pattern, not the message. All error patterns that differ by a codeword give the same syndrome; such patterns form a coset.

Minimum distance decides the guarantee. A code detects up to dmin − 1 errors and corrects t = ⌊(dmin − 1)/2⌋ errors. For correction, build a syndrome table: list each correctable error pattern e and its syndrome s = eHT. On reception compute s, look up e, and output r ⊕ e. If s = 0, accept r as a codeword.

The standard array is the same idea in one line: write all 2k codewords in the first row, then add the most likely error pattern (coset leader) to every codeword of that row, and repeat for every coset. The decoder finds r in the array and reads the top entry of its column.

Hardware follows the algebra. The encoder XORs together the rows of G picked out by the 1 bits of m; bit j of the codeword is the modulo-2 sum of the entries in column j of those rows. In systematic form the first k bits are wires and only the n − k parity bits need XOR gates. The syndrome calculator is n − k XOR trees, one per row of H; each tree adds the received bits where that row of H has a 1. A small table (a read-only memory) maps the syndrome to the error pattern.

Hamming (7,4) code

The Hamming (7,4) code has n = 7, k = 4 and n − k = 3 parity bits. Its H has as columns all seven nonzero 3-bit words. With G = [I₄ | P] and P rows 110, 101, 011, 111, the matrix H = [PT | I₃] has columns 110, 101, 011, 111, 100, 010, 001, in that order. No column is zero and no two columns are equal, so no single error gives s = 0 and no two single errors share a syndrome. Listing all 16 codewords confirms it: one has weight 0, seven have weight 3, seven have weight 4 and one (1111111) has weight 7, so dmin = 3 and t = 1.

The Hamming bound for t = 1 is 2n−k ≥ 1 + n. For (7,4): 23 = 8 and 1 + 7 = 8. The bound is met exactly, so the code is perfect: every one of the eight syndromes is used, one for no error and seven for the seven single-bit errors. It corrects one error in seven bits with only three parity bits.

Decoding is direct. Compute s. If s = 000, no correction. Otherwise s equals one column of H; flip the bit at that column position. For example, s = 111 is column 4 in the H above, so the error is 0001000. This is why the syndrome must not be read as a decimal position: 111 is binary 7, but here it means bit 4.   3. Add the selected rows modulo 2: r1 ⊕ r3 = 1010101; then 1010101 ⊕ r4 = 1011010. So c = 1011010.
  4. The parity-check matrix is H = [PT | I₃], with rows 1101100, 1011010, 0111001. Its columns are 110, 101, 011, 111, 100, 010, 001.
  5. Flip bit 4 of c. c = 1 0 1 1 0 1 0 becomes r = 1 0 1 0 0 1 0 = 1010010. The error is e = 0001000.
  6. Compute s₁ = r₁⊕r₂⊕r₄⊕r₅ = 1⊕0⊕0⊕0 = 1.
  7. Compute s₂ = r₁⊕r₃⊕r₄⊕r₆ = 1⊕1⊕0⊕1 = 1.
  8. Compute s₃ = r₂⊕r₃⊕r₄⊕r₇ = 0⊕1⊕0⊕0 = 1. So s = 111.
  9. Column 4 of H is 111. The table therefore gives e = 0001000.
  10. Correct: r ⊕ e = 1010010 ⊕ 0001000 = 1011010, the original codeword.

Answer. The codeword is c = 1011010; after one bit flip r = 1010010, the syndrome is s = 111 (bits 1, 1, 1), the error is 0001000, and the corrected word is 1011010.

Exam traps

  • Reading the syndrome as a decimal error position. In the (7,4) example 111 is a 3-bit column label; it points to column 4 because of the chosen H, not to bit 7.
  • Forgetting that dmin = 3 detects two errors but corrects only one. A two-bit error can land on a syndrome that the table maps to a single-bit pattern, so the decoder may miscorrect.
  • Mixing the blocks in G and H. Systematic G is [Ik | P], not [P | Ik]; H is [PT | In−k]. Swapping them breaks GHT = 0.
  • Using a different column order in H than the one used to build the syndrome table. The syndrome is only a pointer to that table.

7.7 Cyclic codes

A cyclic code is a linear block code with one extra promise: shift any codeword one place and you get another codeword. One polynomial, the generator polynomial g(x), then describes the whole code. Encoding becomes multiplication or polynomial division, and the hardware is a short shift register. The CRC that guards an Ethernet frame or a ZIP file is exactly this remainder circuit, and BCH and Reed-Solomon codes are its descendants.

You need linear block codes for parity-check matrices and syndromes, plus polynomial long division over GF(2).

Codewords as polynomials

A linear block code is cyclic if every cyclic shift of a codeword is also a codeword. Shift the (7,4) word 1101001 one place left and wrap the leading 1 to the right end: you get 1010011, another codeword. That one property lets a single polynomial define the whole code.

Number the bits from the right. The rightmost bit is c₀, the constant term; the leftmost is c₆ in a 7-bit word, in general cn−1. A codeword becomes a polynomial with coefficients in GF(2) — only 0 and 1, added by XOR — so 1101001 is 1 + x³ + x⁵ + x⁶.

c(x) = c₀ + c₁x + c₂x² + … + cₙ₋₁xⁿ⁻¹

c₀ is the rightmost bit of the word, cn−1 the leftmost; coefficients are 0 or 1 and addition is XOR.

Multiplying c(x) by x and reducing modulo xⁿ + 1 performs the cyclic shift: over GF(2), xⁿ − 1 and xⁿ + 1 are the same polynomial, so the top bit wraps round to the end.

Linearity means the XOR of two codewords is a codeword. Among the nonzero codewords pick the one of smallest degree; call it the generator polynomial g(x). Every codeword is a multiple of g(x), and g(x) divides xⁿ + 1 exactly. Its degree fixes the code: deg g = n − k, so k = n − deg g.

For the (7,4) code g(x) = x³ + x + 1. Degree 3 gives k = 4, hence 16 codewords. The partner factor is h(x) = (x⁷ + 1)/g(x) = x⁴ + x² + x + 1.

Systematic encoding by division

Non-systematic encoding is one multiplication: c(x) = m(x)g(x), with m(x) = m₀ + m₁x + … + mk−1xk−1 carrying the k message bits. All 2k products are distinct codewords, but the message is mixed into the parity, so the decoder must divide before it can read it.

Systematic form keeps the k message bits unchanged in the highest-order positions — the coefficients of xn−1 down to xn−k, sent first — and appends the n − k parity bits at the right end, in positions xn−k−1 down to x⁰. Division does it in three steps.

  1. Shift: multiply m(x) by xn−k. The message moves into the high-order positions and n − k zeros appear at the bottom.
  2. Divide xn−km(x) by g(x) with long division over GF(2). Each subtraction is an XOR; there are no borrows.
  3. Take the remainder b(x), of degree less than n − k, and add it: c(x) = xn−km(x) + b(x).
c(x) = xⁿ⁻ᵏm(x) + b(x),   b(x) = [xⁿ⁻ᵏm(x)] mod g(x)

m(x) is the message polynomial of degree at most k−1; b(x) holds the n−k parity bits; xn−km(x) means the message shifted left by n−k places.

Adding the remainder cancels it, so c(x) is a multiple of g(x) and hence a codeword. A CRC is this same division read as a checksum.

The parity check polynomial is h(x) = (xⁿ + 1)/g(x), of degree k. A word c(x) is a codeword exactly when c(x)h(x) is a multiple of xⁿ + 1 — the polynomial form of cHᵀ = 0 from Chapter 7.6.

The encoder is a shift register of n − k flip-flops with feedback from the last one, and a gate wherever g(x) has a 1 coefficient. For g(x) = x³ + x + 1 there are three stages R₀R₁R₂, one XOR at the input, and one more between R₀ and R₁, since the x¹ coefficient is 1 and x² is 0.

After the k = 4 message clocks the register holds the remainder; for the next n − k = 3 clocks the switch opens and the register shifts the parity bits out, R₂ first.

Question. A (7,4) cyclic code uses the generator polynomial g(x) = x³ + x + 1. (a) Encode the message 1101 systematically. (b) The codeword is received as 1111001. Find the syndrome and correct the word.

  1. Bits are numbered from the right, so the message 1101 with k = 4 is m(x) = x³ + x² + 1.
  2. Shift by n − k = 3: x³m(x) = x⁶ + x⁵ + x³, the 7-bit word 1101000.
  3. x⁶ ÷ x³ = x³; x³·g = x⁶ + x⁴ + x³; XOR leaves x⁵ + x⁴.
  4. x⁵ ÷ x³ = x²; x²·g = x⁵ + x³ + x²; XOR leaves x⁴ + x³ + x².
  5. x⁴ ÷ x³ = x; x·g = x⁴ + x² + x; XOR leaves x³ + x.
  6. x³ ÷ x³ = 1; g = x³ + x + 1; XOR leaves 1. Degree 0 is below 3, so stop. Remainder b(x) = 1, parity bits 001.
  7. c(x) = x⁶ + x⁵ + x³ + 1, so the codeword is 1101001 = 105 in decimal. Dividing it by g(x) leaves 0, which confirms it.
  8. Received word: r = 1111001, so r(x) = x⁶ + x⁵ + x⁴ + x³ + 1. The syndrome is the remainder of r(x) ÷ g(x).
  9. x⁶ ÷ x³ = x³: XOR x³g = x⁶ + x⁴ + x³ leaves x⁵ + 1. Then x²g = x⁵ + x³ + x² leaves x³ + x² + 1. Then g leaves x² + x. Degree 2 is below 3, so s(x) = x² + x = 110.
  10. The syndrome is nonzero, so there is an error. In the single-error table 110 is the row for x⁴, so e(x) = x⁴: flip the third bit from the left. 1111001 becomes 1101001, which divides by g(x) with remainder 0.

Answer. The codeword is 1101001 (parity 001); for r = 1111001 the syndrome is 110, which points to x⁴, and the corrected word is 1101001.

Exam traps

  • Choosing a g(x) that does not divide xⁿ + 1. The code then fails the shift test and is not cyclic.
  • Attaching the parity bits on the left. Systematic means message in the high-order positions, parity at the right end.
  • Swapping g(x) and h(x): g(x) has degree n − k and generates the code; h(x) has degree k and checks it.
  • Borrowing in polynomial subtraction. Over GF(2), addition and subtraction are both XOR; no carries, no borrows.
  • Reading deg g as k. It is n − k, so k = n − deg g; a (7,4) code needs degree exactly 3.

7.8 Convolutional codes and Viterbi decoding

A convolutional code does not cut the message into independent blocks. It feeds each input bit through a shift register, so one input bit shapes several output bits. The encoder is simple; the decoder must search. Viterbi decoding finds the trellis path whose coded bits are closest to the received bits. These codes appear in satellite modems, deep-space links, voice-band modems and the convolutional part of many cellular and Wi-Fi systems.

You need: linear block codes for Hamming distance, and the idea of maximum-likelihood detection: choose the transmitted sequence most likely to have produced what was received.

The encoder is a shift register

Write the code as (n, k, K). Here n is the number of output bits per encoder step, k is the number of input bits per step, and K is the constraint length in bits. The memory is K − 1 bits, so the encoder stores K − 1 past input bits. The code rate is R = k/n.

R = k/n

R is the code rate, dimensionless; k is input bits per step; n is output bits per step. For the example k = 1 and n = 2, so R = 1/2.

The rate 1/2, K = 3 encoder has two delay cells. At each step the current input bit u(i) enters, and the two cells hold u(i−1) and u(i−2). Two modulo-2 adders produce the output pair.

c₁(i) = u(i) ⊕ u(i−1) ⊕ u(i−2)
c₂(i) = u(i) ⊕ u(i−2)

u(i) is the input bit at step i; u(i−1) and u(i−2) are stored past bits; ⊕ is modulo-2 addition; c1(i) and c2(i) are the two output bits.

The generator sequences are g1 = 111 and g2 = 101. A 1 in a generator means that tap is connected to the adder. From state 00, input 1 gives c1 = 1 ⊕ 0 ⊕ 0 = 1 and c2 = 1 ⊕ 0 = 1, output 11. The new state is 10. This spreading lets the decoder use several received bits to decide one message bit.

To end at state 00, append K − 1 = 2 zero bits after the message. These flush bits are not message bits. They cost a little rate but terminate the trellis, so the decoder knows the final state.

Viterbi decoding

Viterbi decoding is maximum-likelihood sequence detection for a memoryless channel. It compares the whole received sequence with every trellis path, without listing all paths.

  1. Lay out the trellis for the received length. At time i there are 2K−1 states; for K = 3, four states.
  2. For hard decisions, compare each received n-bit group with the n output bits on each branch. The branch metric is the Hamming distance, the count of positions that differ.
  3. The path metric is the sum of branch metrics from the start to that state. At each state keep only the smallest path metric and its survivor path. This operation is add-compare-select.
  4. After the last stage, pick the state with the smallest path metric. If the trellis was terminated, pick state 00. Trace back the survivor path; its input bits are the decoded message.

Each stage does about 2K−1 compare-select operations. Traceback memory grows with the received length. Soft-decision decoding uses Euclidean distance or correlation instead of Hamming distance and gives about 2 dB gain over hard decisions.

7.9 BCH, turbo and LDPC codes

Shannon proved codes can come close to capacity. BCH codes are cyclic codes with a guaranteed minimum distance. Turbo codes run two convolutional encoders in parallel, split by an interleaver, and decode by passing soft messages. LDPC codes do the same on a sparse graph. Turbo and LDPC reach within about a decibel of capacity; BCH stays a few dB away. Wi-Fi, 4G/5G data links and flash controllers run these codes.

You need: the channel coding theorem for the capacity wall, linear block codes for dmin and the Hamming bound, cyclic codes for generator polynomials, and convolutional codes for trellises and soft decisions.

BCH codes: a guaranteed number of errors

BCH stands for Bose–Chaudhuri–Hocquenghem. A BCH code is a cyclic code (see 7.7) whose generator polynomial g(x) is built around a chosen error count t. Pick t first; the code then corrects any t errors in the block.

The arithmetic runs in GF(2m), a field with 2m elements, formed by adjoining to GF(2) a root α of a primitive polynomial. A binary BCH code contains every polynomial over GF(2) that has α, α², …, α2t as roots. Those 2t consecutive powers create the distance guarantee.

n = 2ᵐ − 1,   dₘᵢₙ ≥ 2t + 1,   k = n − deg g(x)

n is the block length in bits, m is the field exponent, t is the number of correctable errors, dmin is the minimum Hamming distance, g(x) is the generator polynomial, k is the number of message bits and R = k/n is the code rate.

Take m = 4, so n = 15. The t = 1 member is the (15,11) Hamming code. The (15,7) code has t = 2 and dmin ≥ 5; its generator is g(x) = (x⁴ + x + 1)(x⁴ + x³ + x² + x + 1) = x⁸ + x⁷ + x⁶ + x⁴ + 1, of degree 8 = n − k. The (15,5) code has t = 3 and dmin ≥ 7. The (15,7) code sends 7 message bits in 15, so R = 0.467.

Decoding works on polynomials: the syndromes give an error-locator polynomial, its roots give the error positions, and those bits are flipped. Berlekamp–Massey finds the locator; a Chien search finds its roots.

Reed–Solomon codes use the same construction on symbols of GF(2m) instead of single bits. They fight bursts well and appear on CDs, DVDs, QR codes and deep-space links.

Turbo codes: two encoders, one interleaver

A turbo code makes two encoders read the same block in different orders, then lets two decoders exchange soft opinions about every bit.

Encoding: block d enters a recursive systematic convolutional (RSC) encoder, which sends d out unchanged — systematic — and adds parity p1. The interleaver π, a fixed permutation, shuffles d into a second RSC encoder producing p2. A multiplexer sends d, p1 and p2: three output bits per input bit, R = 1/3.

Recursive means the shift register has feedback, so its state depends on a running sum of past inputs. A single 1 does not quickly return the trellis to the all-zero state, which removes most low-weight codewords.

Puncturing raises the rate by deleting parity bits. Drop half of p1 and half of p2 and each input bit sends 1 + 0.5 + 0.5 = 2 bits, so R = 1/2.

The interleaver is the heart of the design. A pattern giving a low-weight codeword in encoder 1 is scattered into high-weight data for encoder 2, so a low-weight codeword needs both encoders to agree, which is rare.

Decoding is iterative and soft. Decoder 1 uses the systematic bits and p1 to compute a log-likelihood ratio for every bit, removes what it was told, and passes the rest, the extrinsic information, to decoder 2, which does the same with p2. After a few rounds the beliefs settle. Each decoder is a MAP (BCJR) detector or the simpler SOVA. On blocks of thousands of bits turbo codes come within about a decibel of capacity; LTE uses them for its data channels.

LDPC codes: belief propagation on a sparse graph

An LDPC (low-density parity-check) code is a linear block code (see 7.6) whose parity-check matrix H is sparse: almost every entry is zero, with few 1s in each row and column. Sparsity lets n reach thousands of bits and still decode in real time.

The code is drawn as a Tanner graph with two kinds of nodes. Each variable node is one of the n code bits and holds a soft belief about it. Each check node is one parity equation, that is, one row of H, and there are n − k of them. An edge joins variable v to check c wherever H has a 1.

Decoding is belief propagation. In each round every variable node sends its belief along its edges; each check node replies with how strongly its parity equation pulls each bit; the variable nodes update. Only the 1s of H are touched, so a round costs time in proportion to the number of edges, not to n².

Regular (j,k) codes have j ones per column and k ones per row; irregular codes with mixed degrees do better. Long blocks with good degree distributions come within a fraction of a decibel of capacity. Short blocks or badly chosen degrees show an error floor: the bit error rate curve flattens at high SNR instead of falling steeply. Wi-Fi (802.11n/ac), DVB-S2 satellite television and 5G data channels use LDPC.

Choosing between them

All three are linear codes. Longer blocks with soft iterative decoding buy closeness to capacity; the price is delay, since the whole block must be buffered, and decoder complexity.

Worked example

Question. A link is offered a BCH (15,7) code and a turbo code. (a) For the BCH code find n, k, t, dmin, R, and check the Hamming bound. (b) The turbo encoder uses two rate-1/2 RSC encoders and sends the systematic bit with both parity bits; find the rate, then the rate after puncturing every second parity bit.

  1. Read n = 15 and k = 7 from the notation (n,k).
  2. The block length fixes m: n = 2ᵐ − 1 = 15 gives m = 4. For m = 4 the (15,7) BCH code has t = 2, and its generator has degree n − k = 8.
  3. Guaranteed minimum distance: dmin ≥ 2t + 1 = 5.
  4. Code rate: R = k/n = 7/15 = 0.4667.
  5. Hamming bound check. Patterns of weight ≤ 2: 1 + C(15,1) + C(15,2) = 1 + 15 + 105 = 121.
  6. The bound requires 2k × 121 ≤ 2n, i.e. 121 ≤ 215−7 = 256. It holds, with 135 to spare.
  7. Spare room does not make it a 3-error code: correcting 3 would need 1 + 15 + 105 + 455 = 576 ≤ 256, which fails.
  8. Turbo, mother code: output per input bit is 1 systematic + 1 + 1 parity = 3, so R = 1/3 = 0.3333.
  9. Puncturing every second parity bit keeps half of p1 and half of p2. Output per input bit = 1 + 0.5 + 0.5 = 2, so R = 1/2 = 0.5.

Answer. The (15,7) BCH code has n = 15, k = 7, t = 2, dmin ≥ 5, R = 0.4667, and satisfies the Hamming bound since 121 ≤ 256. The turbo code has mother rate 1/3 = 0.3333 and punctured rate 1/2 = 0.5.

Exam traps

  • Thinking a strong code can beat capacity. Turbo and LDPC codes approach the Shannon limit from below; nothing works above it.
  • Confusing code rate with redundancy when puncturing is given. Recount the bits actually transmitted, not the mother code's bits.
  • Writing dmin = 2t + 1 as exact. The design guarantees dmin ≥ 2t + 1; the true minimum distance may be larger.
  • Using n = 2m − 1 with the wrong m. n = 15 needs m = 4, not m = 15.
  • Making the turbo rate 1/4. The systematic bit goes out once, so two rate-1/2 encoders make 1/3, not 1/4.

Remember Expand BCH and state what t means in a t-error-correcting BCH code. 2 marks

Bose–Chaudhuri–Hocquenghem. t is the number of bit errors the code is designed to correct; the code then has minimum distance at least 2t + 1.

Remember In an LDPC code, what exactly is sparse, and how is the code drawn? 2 marks

The parity-check matrix H is sparse, with very few 1s per row and column. It is drawn as a Tanner graph: variable nodes for code bits, check nodes for parity equations, one edge per 1 in H.

Understand Why does the interleaver improve a turbo code? 3 marks

A bit pattern giving a low-weight codeword in the first encoder becomes a high-weight pattern for the second. A low-weight codeword then needs both encoders to agree, which is rare.

Understand Why must turbo and LDPC decoders work on soft values rather than decided bits? 3 marks

The iterations exchange reliabilities, that is log-likelihood ratios. Deciding each bit to 0 or 1 throws away the confidence the next decoder needs, and most of the coding gain disappears.

Takeaways

  1. Information depends only on probability: a sure symbol (P = 1) tells you nothing, and a symbol of probability 1/8 carries 3 bits.
  2. Entropy is largest when all symbols are equally likely and then equals log₂ M; information rate is R = rsH in bit/s.
  3. Huffman coding gives the smallest average length of any prefix code that codes one symbol at a time; Shannon-Fano is close but not always as short.
  4. Mutual information is what the channel output tells you about the input; it is zero when input and output are independent.
  5. Capacity C = B log₂(1 + S/N) grows in proportion to bandwidth only while S/N stays fixed; with fixed power and noise density, widening the band gives less each time, up to 1.44 S/N₀.
  6. The channel coding theorem promises a small error probability at every rate below capacity but gives no construction; block, cyclic, convolutional, turbo and LDPC codes are the constructions.
  7. Syndrome decoding turns error correction into a table lookup on the error pattern: for the (7,4) Hamming code the syndrome is the column of H at the wrong bit.
  8. Cyclic codes let the encoder and the syndrome circuit be shift registers with XOR gates, which is why CRCs are everywhere in hardware.
  9. Viterbi decoding keeps one survivor per trellis state and traces back the smallest path metric; long blocks with soft iterative decoding (turbo, LDPC) get within about a decibel of the Shannon limit.

Understand Define self-information and entropy for a discrete memoryless source. Derive the expression for entropy and show that it is maximum when all symbols are equally likely. 12 marks

Points to cover. Self-information I(xᵢ) = log₂(1/P(xᵢ)) with the three properties: zero for certain events, decreases as probability rises, additive for independent events; Entropy H = Σ P(xᵢ) log₂(1/P(xᵢ)) bits/symbol; Maximum by Jensen's inequality or by the log inequality; H ≤ log₂ M with equality at P = 1/M; One numerical check with a two-symbol source.

Model answer.

  1. Self-information. A discrete memoryless source emits symbols x₁ … xM with probabilities p₁ … pM, where 0 < pi ≤ 1 and Σ pi = 1. The information carried by symbol i is I(xi) = log₂(1/pi) bits.
  2. Three properties fix this form. A certain symbol (pi = 1) carries I = 0. A rarer symbol carries more: I grows as pi falls. Information from independent symbols adds: their joint probability is pipj and log₂(1/(pipj)) = log₂(1/pi) + log₂(1/pj). The logarithm is the only continuous function that turns the product into a sum; base 2 makes the unit the bit.
  3. Entropy. Over a long run of N symbols, symbol i appears about Npi times and brings Npi log₂(1/pi) bits. Dividing the total by N gives the average information per symbol:
    H(X) = Σ pᵢ log₂(1/pᵢ) = −Σ pᵢ log₂ pᵢ   bits/symbol   (sum over i = 1 … M)
  4. A term with pi = 0 counts as 0, since p log₂(1/p) → 0 as p → 0. H(X) ≥ 0, with H = 0 only when one symbol has probability 1.
  5. Maximum. Use the inequality ln x ≤ x − 1 (equality only at x = 1), so log₂ x ≤ (x − 1) log₂ e. Compare H with log₂ M:
    H(X) − log₂ M = Σ pᵢ log₂(1/(M pᵢ))
              ≤ log₂ e · Σ pᵢ (1/(M pᵢ) − 1)
              = log₂ e · (Σ 1/M − Σ pᵢ) = log₂ e · (1 − 1) = 0
  6. So H(X) ≤ log₂ M. Equality needs 1/(Mpi) = 1 for every i, that is pi = 1/M: entropy is largest when all symbols are equally likely, and the largest value is Hmax = log₂ M.
  7. Two-symbol check. For a binary source H(p) = −p log₂ p − (1 − p) log₂(1 − p):
    pH(p) in bitsComment
    0.51.000equal symbols: the maximum, log₂ 2 = 1
    0.250.811unequal: less than 1

    0 or 10certain: no information

  9. Closing check. 0.811 < 1 and 1.75 < 2, as the proof requires; both maxima are reached only by equal probabilities.
Understand State the source coding theorem. Explain Shannon–Fano coding and Huffman coding, and list the differences between them. 12 marks

Points to cover. Source coding theorem: L̄ can be made as close to H as we wish but never below it, with H ≤ L̄ < H + 1; Shannon–Fano: sort probabilities, split into two groups of nearly equal total probability, assign 0 and 1, recurse; Huffman: repeatedly merge the two smallest probabilities, build the tree upward, read codes from root to leaf; Shannon–Fano is not always optimal; Huffman is optimal for a given symbol set, but needs the whole tree at the encoder.

Model answer.

  1. Source coding theorem. For a discrete memoryless source of entropy H(X) bits/symbol, every uniquely decodable binary code has average length L̄ = Σ pili ≥ H(X). A prefix code with L̄ < H(X) + 1 always exists; coding blocks of n symbols together brings the bound to H(X) ≤ L̄ < H(X) + 1/n per symbol. So L̄ can come as close to H(X) as we wish, but never below it. Efficiency is η = H(X)/L̄ and redundancy is 1 − η.
  2. Shannon-Fano coding (top-down).
    1. Sort the symbols in decreasing order of probability.
2. Cut the list into two groups whose total probabilities are as nearly equal as possible.
3. Give the upper group the bit 0 and the lower group the bit 1.
4. Repeat inside each group until every group holds one symbol.
5. Read each codeword from the first split to the last.
  3. Huffman coding (bottom-up).
    1. Make a leaf for each symbol with its probability.
2. Merge the two smallest probabilities under a new node with their sum.
3. Label the two branches 0 and 1.
4. Repeat until one node of probability 1 is left.
5. Read each codeword from the root down to the leaf.

Understand Define mutual information for a discrete memoryless channel and prove I(X;Y) = H(X) − H(X|Y) = H(Y) − H(Y|X). Also define the binary symmetric channel. 10 marks

Points to cover. Joint entropy H(X,Y) = H(X) + H(Y|X) = H(Y) + H(X|Y); I(X;Y) = H(X) + H(Y) − H(X,Y); BSC transition matrix with crossover probability p; symmetry gives H(Y|X) = H(p); I(X;Y) = 0 when input and output are independent; maximum for equiprobable input.

Model answer.

  1. Definitions. A discrete memoryless channel has input X, output Y and transition probabilities P(yj|xi). The entropies are H(X) = −Σ P(xi) log₂ P(xi), H(X,Y) = −Σ Σ P(xi,yj) log₂ P(xi,yj) and H(X|Y) = −Σ Σ P(xi,yj) log₂ P(xi|yj). Mutual information is the uncertainty about X that observing Y removes: I(X;Y) = H(X) − H(X|Y).
  2. Chain rule. Write P(xi,yj) = P(yj)P(xi|yj) inside the log of H(X,Y):
    H(X,Y) = −Σ Σ P(xᵢ,yⱼ) [log₂ P(yⱼ) + log₂ P(xᵢ|yⱼ)]
       = −Σⱼ P(yⱼ) log₂ P(yⱼ) − Σ Σ P(xᵢ,yⱼ) log₂ P(xᵢ|yⱼ)
       = H(Y) + H(X|Y)
  3. The first double sum collapses because Σi P(xi,yj) = P(yj). Splitting the other way, P(xi,yj) = P(xi)P(yj|xi), gives H(X,Y) = H(X) + H(Y|X).
  4. The two forms are equal. Equate the two chain rules:
    H(X) + H(Y|X) = H(Y) + H(X|Y)
⇒ H(X) − H(X|Y) = H(Y) − H(Y|X)
⇒ I(X;Y) = H(X) + H(Y) − H(X,Y)
  5. So I(X;Y) = H(X) − H(X|Y) = H(Y) − H(Y|X), and I(X;Y) = I(Y;X). I = 0 when X and Y are independent, because then H(X|Y) = H(X); I ≤ min(H(X), H(Y)).
  6. Binary symmetric channel. Inputs and outputs are 0 and 1. A bit is received correctly with probability 1 − p and flipped with probability p (the crossover probability). Its channel matrix is [[1 − p, p], [p, 1 − p]]. Every row holds the same pair, so H(Y|X) = H(p) = −p log₂ p − (1 − p) log₂(1 − p) whatever the input, and I(X;Y) = H(Y) − H(p).

Understand State the channel coding theorem and explain its meaning and its limitations. 8 marks

Points to cover. Statement: for R < C, codes exist with arbitrarily small error probability; for R > C the error probability cannot be made to vanish; Applies to long blocks, so the decoder may be complex and the delay large; Does not tell us how to build the code; that is the job of the later sections; Contrast with the source coding theorem.

Model answer.

  1. Statement. A discrete memoryless channel has capacity C bits per channel use. If the code rate R = k/n is below C, there exist codes (for large enough n) whose probability of decoding error Pe is as small as we like. If R > C, Pe stays above a positive floor for every code and every decoder.
  2. Meaning. Noise does not force errors; it limits the rate. Below C we can buy reliability with redundancy and block length, not with a lower rate alone. On a BSC with p = 0.01, C = 1 − H(0.01) = 1 − 0.0808 = 0.919 bits per use: rate 1/2 is allowed, rate 0.95 is not.
  3. The idea of the proof. Pick 2nR codewords at random. For large n the noise flips about np bits, and the received word lies near its own codeword and, when R < C, far from all others with high probability. The average error over all random codes is small, so at least one code is that good.
  4. A small example of the trade. Repetition codes on the same BSC: n = 3 gives R = 1/3 and Pb = 3p²(1 − p) + p³ = 2.98 × 10−4; n = 5 gives R = 0.2 and Pb = 9.85 × 10−6. Repetition lowers the error only by throwing rate away; the theorem says good long codes keep R fixed (any value below 0.919) and still drive Pe down.
  5. Limitations. (1) It is an existence proof: it names no code, encoder or decoder. (2) It needs n → ∞, so delay and buffer size grow. (3) It says nothing about decoder complexity; maximum-likelihood decoding of a random code is far too slow. (4) At finite n, Pe is small but not zero. (5) It assumes a memoryless channel with known statistics.
  6. Contrast with the source coding theorem. Source coding removes redundancy (L̄ ≥ H); channel coding adds it back in a controlled way (R < C). Together they say a source of entropy rate Rs can be sent reliably over a channel if Rs < C per second.
  7. Closing check. 1/3 < 0.919 and 0.2 < 0.919: both repetition codes are allowed, but neither is efficient; a rate-1/2 code below 0.919 is what the theorem promises can do better.

    Error in bit1234567

Apply A cyclic code uses generator polynomial g(x) = 1 + x + x³ over GF(2). Encode the message polynomial 1 + x² by polynomial division and find the syndrome when the received word is 1100101. 12 marks

Points to cover. Multiply m(x) by xn−k and divide by g(x) to get the remainder as parity bits; Codeword is the remainder appended to the message; Received polynomial divided by g(x) gives the syndrome polynomial; Non-zero syndrome points to the error; the syndrome circuit is a shift register with feedback taps at g(x).

Model answer.

  1. Set-up. g(x) = 1 + x + x³ has degree 3 and divides x⁷ + 1, so it generates a (7,4) cyclic code: n = 7, n − k = 3, k = 4. Bits are written with the highest power on the left.
  2. Message. m(x) = 1 + x² has degree below 4, so the 4-bit message is m₃m₂m₁m₀ = 0101.
  3. Shift and divide. x³m(x) = x³ + x⁵ (word 0101000). Divide by g(x), every subtraction an XOR:
    x⁵ + x³          ÷ x³ + x + 1
x⁵ ÷ x³ = x²:  x²g = x⁵ + x³ + x²
  (x⁵ + x³) ⊕ (x⁵ + x³ + x²) = x²
degree 2 < 3: remainder b(x) = x²   → parity 100
  4. Codeword: c(x) = x³m(x) + b(x) = x⁵ + x³ + x², the word 0101100: message 0101 then parity 100. Check: x⁵ + x³ + x² = x²(x³ + x + 1) = x²g(x), so it divides exactly.
  5. Syndrome of r = 1100101. r(x) = x⁶ + x⁵ + x² + 1. Divide by g(x):
    x⁶:  XOR x³g = x⁶ + x⁴ + x³  → x⁵ + x⁴ + x³ + x² + 1
x⁵:  XOR x²g = x⁵ + x³ + x²  → x⁴ + 1
x⁴:  XOR x·g = x⁴ + x² + x  → x² + x + 1

    Error atx⁰x¹x²x³x⁴x⁵x⁶
    Syndrome001010100011110111101
  7. 111 is the x⁵ entry, so e(x) = x⁵ (the second bit from the left). Corrected word: 1100101 ⊕ 0100000 = 1000101, that is x⁶ + x² + 1. Check: x⁶ mod g = x² + 1, so x⁶ + x² + 1 leaves (x² + 1) + x² + 1 = 0. It is a codeword, carrying the message 1000.
  8. Syndrome circuit. A 3-stage shift register R₀R₁R₂ with feedback from R₂: each clock R₀ ← r ⊕ R₂, R₁ ← R₀ ⊕ R₂, R₂ ← R₁ (taps where g has 1s, at x⁰ and x¹). Clocking in the 7 received bits, highest first, leaves s(x) in the register; the encoder is the same register with the message switch and the input added at the feedback point.

Apply A rate-1/2 convolutional code with constraint length 3 has generators g₁ = 111 and g₂ = 101. Draw the encoder and its state table, encode the message 1101 with two flush zeros, and decode the received sequence 10 01 01 00 00 11 by the Viterbi algorithm. 13 marks

Points to cover. Shift register with two memory stages and two modulo-2 adders; State table: for each of the four states, the output and next state for input 0 and 1; Encoding of 1101 00 by the table; Trellis with branch and path metrics and add-compare-select at every stage; Survivor path, traceback and the decoded bits; free distance 5 and the errors it can correct.

Analyze A channel has bandwidth B = 1 MHz. Using C = B log₂(1 + S/N), compare doubling the bandwidth with doubling the signal power, first at S/N = 15 and then at S/N = 0.1, with the noise power spectral density fixed. Explain the difference. 12 marks

Points to cover. C at the starting point for each S/N; Doubling power doubles S/N; doubling B halves S/N because N = N₀B; Numbers for both cases; High S/N: bandwidth is the stronger lever; low S/N: power is; Limit B → ∞: C → 1.44 S/N₀.

Model answer.

  1. The rule. C = B log₂(1 + S/N) with N = N₀B. Doubling S doubles S/N. Doubling B lets twice the noise in, so S/N halves, while the factor B in front doubles.
  2. High S/N: 15 at B = 1 MHz (11.8 dB).
    start:        C = 10⁶ log₂(1 + 15)       = 4.00 Mbit/s
double S:     C = 10⁶ log₂(1 + 30)       = 4.95 Mbit/s  (+0.95)
double B:     C = 2×10⁶ log₂(1 + 7.5)    = 6.17 Mbit/s  (+2.17)
  3. Low S/N: 0.1 at B = 1 MHz (−10 dB).
    start:        C = 10⁶ log₂(1.1)          = 0.1375 Mbit/s
double S:     C = 10⁶ log₂(1.2)          = 0.2630 Mbit/s  (+91 %)
double B:     C = 2×10⁶ log₂(1.05)       = 0.1408 Mbit/s  (+2.4 %)
  4. Why they differ. At high S/N, log₂(1 + S/N) ≈ log₂(S/N): doubling S adds only about 1 bit/s/Hz, B log₂ 2 = 1 Mbit/s here (0.95 exactly), while doubling B nearly doubles C (it loses only the 1 bit/s/Hz that halving S/N costs). Capacity is bandwidth-limited.
  5. At low S/N, log₂(1 + x) ≈ x log₂ e, so C ≈ B (S/(N₀B)) log₂ e = 1.44 S/N₀: B cancels. Extra bandwidth changes almost nothing, and C grows in proportion to S. Capacity is power-limited.
  6. Limit. As B → ∞ with S and N₀ fixed, C → 1.44 S/N₀. For the high-S/N case S/N₀ = 15 × 10⁶ Hz, so C can never pass 1.44 × 15 × 10⁶ = 21.6 Mbit/s, however wide the band.
  7. Conclusion. At high S/N, bandwidth is the stronger lever (satellite links and Wi-Fi add channels); at low S/N, such as deep-space links, power or antenna gain is the lever and extra bandwidth helps little. A designer first finds which regime the link is in.
  8. Closing check. 4.95 < 6.17 Mbit/s (high S/N, bandwidth wins) and 0.2630 > 0.1408 Mbit/s (low S/N, power wins); every value is below the 21.6 Mbit/s ceiling of the first link.
Analyze Compare Hamming, BCH, turbo and LDPC codes on rate, block length, decoding complexity and error performance, and state where each is used. 13 marks

Points to cover. Hamming: small block, single-error correction, trivial hardware, used in memory and simple links; BCH: multiple-error correction, algebraic decoding, used in storage and older satellite links; Turbo: parallel concatenated codes with iterative soft decoding, close to the Shannon limit, used in 3G/4G; LDPC: sparse parity-check matrix, belief propagation, used in 5G, Wi-Fi and deep-space; Trade-off: long blocks and soft information buy performance at the cost of delay and complexity.

Model answer.

  1. Common ground. All four are linear codes: the sum of two codewords is a codeword, and a code rate R = k/n measures the share of transmitted bits that carry message. They differ in how the redundancy is arranged and how the decoder uses it.
  2. Hamming codes. (2m − 1, 2m − 1 − m), for example (7,4) with R = 0.571, dmin = 3, t = 1. Decoding is one syndrome and a table lookup: a few XOR gates. Used in computer memory (as SECDED with one extra bit) and simple control links.
  3. BCH codes. Cyclic codes with a chosen t: n = 2m − 1, dmin ≥ 2t + 1. Example: (15,7), t = 2, R = 0.467, g(x) = x⁸ + x⁷ + x⁶ + x⁴ + 1. Decoding is algebraic and hard-decision (syndromes, Berlekamp-Massey, Chien search): moderate hardware, fixed latency. Used in flash storage and as an outer code in satellite television.
  4. Turbo codes. Two recursive systematic convolutional encoders, the second fed through an interleaver. The mother rate is 1/3 (d, p1, p2); puncturing half of each parity stream gives 1/2. Decoding is iterative and soft (two MAP or SOVA decoders exchanging extrinsic information), with blocks of hundreds to thousands of bits. Within about 1 dB of capacity. Used in 3G and 4G data channels and deep-space links.
  5. LDPC codes. A long code whose parity-check matrix H is sparse, drawn as a Tanner graph and decoded by belief propagation: the work per iteration grows with the number of 1s in H, not with n². Blocks of thousands to tens of thousands of bits come within a fraction of a dB of capacity. Used in Wi-Fi, DVB-S2 and 5G data channels.
  6. Comparison.
    CodeTypical rateBlock lengthDecoderGap to capacityUsed in
    Hamming (7,4)0.5717syndrome tablelarge (t = 1 only)memory, simple links
    BCH (15,7)0.46715 to a few thousandalgebraic, harda few dBflash, outer codes

  7. Trade-off. Moving down the table buys performance with longer blocks, soft information and iterations. The price is delay (the whole block must arrive before decoding), memory and decoder power. Short, latency-critical or very cheap links keep the algebraic codes; high-throughput radio links use turbo or LDPC.
  8. Closing check. 4/7 = 0.571 and 7/15 = 0.467 as stated; the Hamming bound holds for both: 2³ = 8 ≥ 1 + 7 and 2⁸ = 256 ≥ 1 + 15 + 105 = 121.
Evaluate Show that the average length of any prefix code cannot be less than the source entropy. Discuss what the extra length costs in a practical system. 10 marks

Points to cover. Kraft inequality Σ 2−lᵢ ≤ 1 for any prefix code; Use ln x ≤ x − 1 to show H(X) − L̄ ≤ 0; Equality only when every lᵢ = log₂(1/pᵢ), that is, probabilities are powers of 1/2; The gap H ≤ L̄ < H + 1 comes from rounding lengths to whole bits; Cost of the gap: extra bits per symbol become extra bit rate, bandwidth or storage.

Model answer.

  1. Set-up. A source has probabilities pi and a binary prefix code gives symbol i a word of li bits. L̄ = Σ pili and H(X) = Σ pi log₂(1/pi).
  2. Kraft inequality. In a binary tree of depth lmax, a codeword at depth li blocks the 2lmax − li leaves below it, and in a prefix code these sets do not overlap. So Σ 2lmax − li ≤ 2lmax, that is Σ 2−li ≤ 1.
  3. Proof that L̄ ≥ H. Use log₂ x ≤ (x − 1) log₂ e, with equality only at x = 1:
    H − L̄ = Σ pᵢ log₂(1/pᵢ) − Σ pᵢ log₂ 2lᵢ
      = Σ pᵢ log₂( 2−lᵢ / pᵢ )
      ≤ log₂ e · Σ pᵢ ( 2−lᵢ/pᵢ − 1 )
      = log₂ e · ( Σ 2−lᵢ − 1 ) ≤ 0     (Kraft)
  4. So L̄ ≥ H(X) for every prefix code. Equality needs 2−li = pi for every i, that is li = log₂(1/pi) exactly: every probability must be a power of 1/2. Example: 1/2, 1/4, 1/8, 1/8 with words 0, 10, 110, 111 gives L̄ = H = 1.75 bits/symbol.
  5. Why the gap is less than one bit. Choose li = ⌈log₂(1/pi)⌉. Then 2−li ≤ pi, so Kraft holds and a prefix code with these lengths exists, and li < log₂(1/pi) + 1, so L̄ < H + 1. The gap comes only from rounding lengths up to whole bits.
  6. What the extra length costs. Five symbols with 0.4, 0.2, 0.2, 0.1, 0.1: H = 2.1219 bits/symbol and the Huffman code has L̄ = 2.2 bits/symbol.

    Over one hour78 100 × 3600 = 2.81 × 10⁸ bits ≈ 35 MB of storage
    Efficiencyη = 96.45 %
  7. In practice the extra bits cost bandwidth, storage and transmit energy. Coding blocks of symbols, or arithmetic coding, shrinks the gap below 1/n bit per symbol at the price of bigger tables and more delay.
  8. Closing check. 2.1219 ≤ 2.2 < 3.1219: the example obeys H ≤ L̄ < H + 1, and the power-of-1/2 source meets the lower bound with equality.
Evaluate A binary symmetric channel with crossover probability 0.02 is used 10⁶ times per second, and the user needs a bit error rate of 10⁻⁵. Judge three proposals: (a) a rate-0.9 LDPC code; (b) the rate-1/2, K = 3 convolutional code with generators 111 and 101 and hard-decision Viterbi decoding, using the union bound Pb ≤ Σ βdPd with β₅ = 1, β₆ = 4, β₇ = 12, β₈ = 32; (c) a long rate-1/2 LDPC code. Points to cover. Capacity of the BSC, C = 1 − H(0.02), and the information rate each proposal carries; Rate above capacity: the converse gives an error floor for every decoder; Union bound for the convolutional code at p = 0.02, and the p at which it would meet 10⁻⁵; Long LDPC code below capacity: the theorem allows it, practice gets close with soft decoding; Practical limits: delay, decoder complexity and the gap to capacity.

Glossary

Binary symmetric channel
A two-input two-output channel that flips the bit with probability p and passes it with probability 1 − p.
Bit
Unit of information when the logarithm is taken to base 2; one fair coin toss carries one bit.
Block code
A code that maps each group of k message bits to one fixed block of n transmitted bits.
Channel capacity
The maximum mutual information over all input distributions, in bits per channel use.
Code efficiency
Entropy divided by average codeword length, usually quoted as a percentage.
Conditional entropy
The uncertainty left in the input after the output is known, H(X|Y), also called equivocation.
Constraint length
The number of input bits, the current one and the stored ones, that shape each output group of a convolutional code: K = memory + 1.
Discrete memoryless channel
A channel with finite input and output alphabets whose behaviour at each use is fixed and independent of past uses.
Entropy
The average information per source symbol, the minimum average number of bits needed to describe it.
Free distance
The smallest Hamming distance between two different coded sequences of a convolutional code; 5 for the rate 1/2, K = 3 code with generators 111 and 101.
Generator matrix
The k × n matrix G whose rows span the code, so a codeword is c = mG.
Generator polynomial
The polynomial g(x) of degree n − k that divides xⁿ + 1 and whose multiples are exactly the codewords of a cyclic code.
Hamming weight and distance
Weight is the number of ones in a word; distance is the number of positions in which two words differ.
Information rate
Entropy multiplied by the symbol rate, in bits per second.
Joint entropy
The uncertainty of the input and output taken together, H(X,Y).
Kraft inequality
The condition Σ 2−lᵢ ≤ 1 that a set of codeword lengths must satisfy for a prefix code to exist.
Minimum distance
The smallest Hamming distance between any two codewords; a code with dmin corrects t = ⌊(dmin − 1)/2⌋ errors.
Mutual information
The reduction in uncertainty about the input caused by observing the output, in bits per channel use.
Parity-check matrix
The (n − k) × n matrix H orthogonal to every codeword, satisfying cHᵀ = 0.
Prefix code
A code in which no codeword is a prefix of another, so decoding needs no separators.
Self-information
The information in one outcome of probability P, equal to log₂(1/P) bits.
Shannon limit
The minimum signal-to-noise ratio per bit, about −1.6 dB, below which reliable communication is impossible however long the code.
Soft-decision decoding
Decoding that uses the received amplitudes (or their reliabilities) instead of firm 0/1 decisions; for a Viterbi decoder on an AWGN channel it gains about 2 dB.
Survivor path
In Viterbi decoding, the one path kept at each trellis state: the arriving path with the smallest metric.
Symbol rate
Number of source symbols produced per second, measured in baud or symbols per second.
Syndrome
The (n − k)-bit vector S = rHᵀ, which is zero for a valid codeword and depends only on the error pattern.
Trellis
A time-indexed diagram of the encoder states and allowed transitions, used by the Viterbi decoder.
