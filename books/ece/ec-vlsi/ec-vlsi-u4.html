4.1 Adders: ripple carry and carry look-ahead

A full adder adds three bits and gives a sum and a carry. A wide adder chains full adders and passes carries along. The real design question is how fast the carry reaches the last bit. Ripple carry hands it stage by stage. Carry look-ahead computes every carry from the a and b bits.

You need: the static CMOS gates (AND, OR, XOR) from CMOS logic styles, and binary addition with carries.

Half adder, full adder and the standard cell

A half adder adds two bits, a and b. The symbol ⊕ means exclusive OR: the result is 1 when exactly one input is 1.

S = a ⊕ b, C = a · b

a and b are the input bits; S is the sum bit; C is the carry bit.

A full adder takes three inputs: a, b and the carry-in c from the right column.

S = a ⊕ b ⊕ c, C = a · b + c · (a ⊕ b)

c is the carry into this column; S is the sum bit; C is the carry out.

A carry leaves when both inputs are 1 (a·b), or when exactly one is 1 and a carry came in (c·(a⊕b)).

The standard static CMOS adder cell, usually drawn as the mirror adder, uses 28 transistors. A carry gate forms C̄out, the inverted majority of a, b and c. A sum gate reuses it: S = abc + C̄out·(a + b + c). Two output inverters restore the true polarities. Because the sum gate needs C̄out, the carry is ready before the sum.

Ripple carry adder

An n-bit ripple carry adder puts n full adders in a row. Bit i of a and bit i of b enter adder i, and the carry-out of adder i becomes the carry-in of adder i+1. Bit 0 is the least significant column. c0 is the carry into it, and c0 = 0 for plain addition.

Each full adder needs two gate delays to turn its carry-in into a carry-out: one AND level, then one OR level. The worst case is a carry born at bit 0 and propagated through every stage. That happens when g₀ = 1 and every later pᵢ = 1, for example a = 1111 and b = 0001.

tcarry = 2n gate delays, tsum = 2n − 1 gate delays

Here tcarry is when the carry-out cn settles and tsum when the top sum bit sn−1 = pn−1 ⊕ cn−1 settles; one gate delay is a few tens of picoseconds in a modern process.

For n = 32 the top sum bit settles after 63 gate delays and the carry-out after 64. At 40 ps per gate delay the whole result needs 64 × 40 ps = 2.56 ns, longer than a 1 GHz clock period. The layout is regular, so ripple adders stay in slow timers, peripheral registers and address increments. Faster answers are in Chapter 4.2.

Subtraction reuses the adder: a − b = a + b̄ + 1, so XOR each bit of b with a subtract line and drive c0 from the same line.

Carry look-ahead adder

Carry look-ahead stops waiting for the carry to walk. Each column computes two signals from its own aᵢ and bᵢ only. Generate gᵢ = aᵢ·bᵢ is 1 when the column creates a carry. Propagate pᵢ = aᵢ⊕bᵢ is 1 when the column passes an incoming carry on.

cᵢ₊₁ = gᵢ + pᵢ · cᵢ

cᵢ is the carry entering column i; gᵢ and pᵢ are that column's generate and propagate; cᵢ₊₁ is the carry leaving it.

Substituting the recurrence into itself removes every carry from the right-hand side. For four bits:

c₁ = g₀ + p₀c₀
c₂ = g₁ + p₁g₀ + p₁p₀c₀
c₃ = g₂ + p₂g₁ + p₂p₁g₀ + p₂p₁p₀c₀
c₄ = g₃ + p₃g₂ + p₃p₂g₁ + p₃p₂p₁g₀ + p₃p₂p₁p₀c₀

each cᵢ now depends only on the g and p of the columns below it and on c₀; no carry is computed from another carry in sequence.

Every carry is now a two-level AND-OR function of g, p and c0, so one block — the look-ahead carry unit, also called LCU — builds all of them at the same time. A 4-bit look-ahead adder gives all carries in about three gate delays (one for g and p, two for the widest AND-OR), against eight for ripple. Each sum then costs one more XOR: sᵢ = pᵢ ⊕ cᵢ.

For wider adders the same trick is applied to blocks. A 4-bit block has a group generate G = g₃ + p₃g₂ + p₃p₂g₁ + p₃p₂p₁g₀ and a group propagate P = p₃p₂p₁p₀. Blocks are chained with cnext = G + P·cin, giving a tree of look-ahead units whose delay grows with log n instead of n. A single-level look-ahead for n bits needs AND terms of n+1 inputs, so practical blocks stop at 4 or 8 bits.

Question. A 4-bit carry look-ahead adder has a = 1011 and b = 0110, with c0 = 0. Using gi = ai·bi and pi = ai⊕bi, find every g, every p, every carry, every sum bit, and the final result.

  1. Bits: a₃a₂a₁a₀ = 1011, so a₀ = 1, a₁ = 1, a₂ = 0, a₃ = 1. b₃b₂b₁b₀ = 0110, so b₀ = 0, b₁ = 1, b₂ = 1, b₃ = 0.
  2. Generate gᵢ = aᵢbᵢ: g₀ = 1·0 = 0, g₁ = 1·1 = 1, g₂ = 0·1 = 0, g₃ = 1·0 = 0, so g₃g₂g₁g₀ = 0010.
  3. Propagate pᵢ = aᵢ⊕bᵢ: p₀ = 1⊕0 = 1, p₁ = 1⊕1 = 0, p₂ = 0⊕1 = 1, p₃ = 1⊕0 = 1, so p₃p₂p₁p₀ = 1101.
  4. Carries from the look-ahead equations: c₁ = g₀ + p₀c₀ = 0 + 1·0 = 0; c₂ = g₁ + p₁g₀ + p₁p₀c₀ = 1 + 0 + 0 = 1; c₃ = g₂ + p₂g₁ + p₂p₁g₀ + p₂p₁p₀c₀ = 0 + 1·1 + 0 + 0 = 1; c₄ = g₃ + p₃g₂ + p₃p₂g₁ + p₃p₂p₁g₀ + p₃p₂p₁p₀c₀ = 0 + 0 + 1·1·1 + 0 + 0 = 1. No carry waited for another.
  5. Sums sᵢ = pᵢ ⊕ cᵢ: s₀ = 1⊕0 = 1, s₁ = 0⊕0 = 0, s₂ = 1⊕1 = 0, s₃ = 1⊕1 = 0. Result = c₄s₃s₂s₁s₀ = 10001₂ = 17. Check: 11 + 6 = 17.

Answer. The sum is 10001₂ = 17, with g₃g₂g₁g₀ = 0010, p₃p₂p₁p₀ = 1101 and carries c₁ = 0, c₂ = 1, c₃ = 1, c₄ = 1.

Worked example 2

Question. A 32-bit ripple carry adder uses full adder cells that turn carry-in into carry-out in 2 gate delays and form their sum one XOR delay after their carry-in arrives. Each gate delay is 40 ps. Find the worst-case delay to the top sum bit and to the carry-out.

  1. Worst case: a carry born at bit 0. g₀ is ready after 1 gate delay and c₁ after 2; each stage adds 2, so cᵢ arrives at 2i: c₃₁ at 62, c₃₂ at 64.
  2. Top sum bit: s₃₁ = p₃₁ ⊕ c₃₁ needs one XOR after c₃₁, so it settles at 62 + 1 = 63 gate delays.
  3. Time: s₃₁ at 63 × 40 ps = 2520 ps = 2.52 ns; c₃₂ at 64 × 40 ps = 2560 ps = 2.56 ns. The adder is finished only when both have settled.

Answer. The top sum bit settles at 63 gate delays (2.52 ns) and the carry-out at 64 gate delays (2.56 ns), so the adder needs 2.56 ns.

Exam traps

  • Mixing the two definitions of p. Some texts use pᵢ = aᵢ + bᵢ: the carry recurrence still holds, but sᵢ = pᵢ ⊕ cᵢ is then wrong; write aᵢ ⊕ bᵢ ⊕ cᵢ. State your choice.
  • Timing the top sum bit from cn. The top sum bit is sn−1 = pn−1 ⊕ cn−1, so it settles at 2n − 1 gate delays; the carry-out cn, at 2n, is the last output to settle.
  • Index slip: the recurrence is cᵢ₊₁ = gᵢ + pᵢcᵢ, driven by column i, not gᵢ₊₁.
  • Building a single-level look-ahead for 32 bits. The AND terms grow to 33 inputs and the gate becomes huge and slow; use 4-bit blocks with group generate and group propagate.

4.2 Carry select, carry save and carry skip adders

A wide adder is slow because the carry must reach the last bit. Three architectures attack that chain without changing the final arithmetic. Carry select computes each block twice, with carry in 0 and 1, then selects. Carry skip passes the carry over a block whose bits all propagate. Carry save never propagates the carry inside a row: it keeps a sum vector and a carry vector for a later adder. The names CSL, CSK and CSA appear in datapath and multiplier design.

You need: Chapter 4.1 for the full adder and for generate g and propagate p.

Carry select: compute both answers

Carry select splits an n-bit adder into blocks of k bits. Each block contains two ripple adders. One assumes its carry in is 0. The other assumes 1. Both run at the same time.

For each sum bit in the block, a multiplexer picks the output of the correct adder. The select signal is the real carry coming from the lower block. The carry out of the block is also selected. No sum bit waits for the lower block; only the final selection waits.

For a = 1011 and b = 0110 in two-bit blocks, the low block gives sum 01 with carry 1. The high block (10 + 01) gives sum 11, carry 0 for carry-in 0 and sum 00, carry 1 for carry-in 1. The real carry 1 selects the second: 1 00 01 = 10001 = 17 (Figure 4.2.1).

Area is the cost. A carry-select block needs four full adders plus three 2:1 multiplexers: two for the sum bits and one for the carry out. The first block has no choice to make, so it is a single ripple adder. With equal blocks of k bits, every block ripples at the same time (k carry delays), then the real carry steps through one multiplexer per block, n/k − 1 of them. The square-root carry-select adder makes each block one bit longer than the block below it (2, 3, 4, 5 …), so a block's two answers are ready just as the selected carry reaches it. Its delay then grows roughly as √(2n) multiplexer delays, while the area stays proportional to n, close to double a plain ripple adder. The carry skip adder below is also called a square-root adder; the two are different architectures.

Carry skip: bypass a propagating block

Carry skip, also called carry bypass, uses the propagate signal pi = ai XOR bi from Chapter 4.1. A bit propagates a carry when pi = 1: a carry in produces a carry out. For a block from bit m to bit n, define block propagate P = pm · pm+1 · ... · pn. The dot means AND.

If P = 1, every bit in the block propagates. Any carry entering the block will leave it unchanged. A multiplexer then sends the incoming carry straight to the next block, bypassing the ripple chain. If P = 0, at least one bit stops or generates a carry, so the block uses its normal ripple carry out.

The block size k sets the delay. In the worst case a carry is generated at the bottom of the lowest block and ripples through its k bits, then jumps over the middle blocks through one bypass multiplexer each, and finally ripples through the k bits of the top block. With tc the carry delay of one bit and tmux the delay of one bypass multiplexer:

Tskip ≈ 2k·tc + (n/k − 1)·tmux, kopt = √(n·tmux ÷ 2tc)

Here n is the adder width in bits; k is the block width in bits; 2k·tc is the ripple in the first and last blocks; n/k − 1 is the number of bypass multiplexers on the path; kopt is where the two terms balance (set dT/dk = 0).

Small blocks skip often but put many multiplexers in the path; large blocks ripple too far. With tc = tmux, a 32-bit adder has kopt = √16 = 4 and about 15 delays, against 32 for plain ripple (worked example 2). The skip logic is cheap: one AND of the block's p bits and one 2:1 multiplexer per block.

Carry save: keep the carry for later

A carry save adder does not try to finish the sum. It takes three numbers and reduces them to two. Each column uses one full adder as a 3:2 compressor. The full adder adds three input bits at the same position and produces a sum bit si and a carry bit ci. The carry bit belongs one place to the left.

For inputs a, b and d, the row produces S = sn-1...s0 and raw carry bits cn-1...c0. The arithmetic identity is a + b + d = S + 2C, where C is the raw carry word cn-1...c0. In hardware the shifted carry vector is C' = 2C, so a + b + d = S + C'. A final carry propagate adder, such as the ripple or look-ahead adder of Chapter 4.1, adds S and C'. That final adder is the only place where a carry ripples.

The delay of the compressor row is one full adder delay. There is no carry chain across columns. The price is the final adder. In a multiplier, many partial-product rows are reduced by a tree of these 3:2 compressors. Wallace tree multipliers, often fed by Booth-recoded partial products, are built from exactly this block; see Chapter 4.4.

Worked example 2

Question. A 32-bit carry skip adder is built from equal blocks. One bit's carry delay is tc = 1 unit and one bypass multiplexer is tmux = 1 unit. Find the worst-case delay for k = 2, 4 and 8, pick the best block size, and compare with a plain 32-bit ripple adder.

  1. Model: T ≈ 2k·tc + (n/k − 1)·tmux with n = 32.
  2. k = 2: 16 blocks, T = 4 + 15 = 19 units. k = 4: 8 blocks, T = 8 + 7 = 15 units. k = 8: 4 blocks, T = 16 + 3 = 19 units.
  3. Optimum: kopt = √(n·tmux ÷ 2tc) = √(32 ÷ 2) = 4, which matches the table.
  4. Plain ripple: 32 stages × 1 unit = 32 units. Speed-up = 32 ÷ 15 ≈ 2.1.

Answer. k = 4 is best at about 15 units, against 19 units for k = 2 or k = 8 and 32 units for plain ripple; the bypass logic costs only eight AND gates and eight multiplexers.

Exam traps

  • Forgetting to shift the carry vector left by one bit before the final add. The raw carry word 0111 is 7, but the shifted vector 1110 is 14.
  • Expecting a carry save adder to produce a finished sum on its own. It only reduces three inputs to two vectors; a final carry propagate adder is still needed.
  • Using OR instead of AND for block propagate P in a carry skip adder. A carry crosses the whole block only when every pi is 1.
  • In carry select, the multiplexer select is the real carry from the lower block, not the block's own carry out. Both candidate carries are already computed.

Analyze Carry select uses two ripple adders per block, yet it is faster. Explain why. 5 marks

Both adders compute in parallel before the lower-block carry is ready. When the real carry arrives, a multiplexer selects one of two ready results. The delay becomes one block ripple plus multiplexer delay, not a carry chain through all n bits. The cost is extra area.

4.3 Array multipliers: Braun and Baugh-Wooley

An array multiplier makes every partial product at the same time. Each bit of the multiplier opens a row of AND gates, and each row is the multiplicand shifted by that bit's place. Full adders then combine the rows at fixed columns, with carries moving diagonally down the array. The answer appears after one long ripple through the diagonals. Braun does this for unsigned numbers. Baugh-Wooley does it for two's complement by inverting the mixed sign partial products and adding two fixed 1 bits. Small embedded multipliers and many hardware interview questions still use these arrays.

You need: Chapter 4.1 for the full adder, and Chapter 4.2 for why saving carries helps when many rows must be added.

Rows of AND gates, added by place value

Write the multiplicand as A = an−1...a0 and the multiplier as B = bn−1...b0. Each bit ai and bj is 0 or 1, and n is the word length. Unsigned multiplication is shift and add. Multiplying by bj2j either adds A<<j or adds zero. The array does all these additions together.

P = Σj=0n−1 (Σi=0n−1 aibj 2i) 2j = Σi=0n−1Σj=0n−1 aibj 2i+j

Here P is the 2n-bit product; ai is bit i of A; bj is bit j of B; ppij = aibj is one partial product bit; 2i+j fixes its column.

A 4×4 array needs 16 AND gates to form pp00 to pp33. It needs n(n−1) = 4×3 = 12 adder cells to reduce the four rows. Cells with no carry to take in are half adders: in the usual layout n cells are half adders and n(n−2) are full adders, so a 4×4 array has 8 full adders and 4 half adders. The first row is not added to anything, so it enters the array directly. Carries do not run along a row; each carry moves one row down and one column to the left, into the next higher weight. The last row is a ripple adder that delivers the top product bits.

Braun multiplier

The Braun multiplier is the plain unsigned array just described. Row j is A AND bj, shifted left by j. Row 0 has no shift. Row 1 is shifted one place, row 2 two places, and so on. Each adder cell adds the partial product bit that lands on it, the sum coming down from the row above, and the carry from the next lower column of the row above. The array is rectangular and regular, so it maps cleanly to a cell library and a compact layout.

  • Gate count: n2 AND gates and n(n−1) adder cells, n(n−2) full adders and n half adders. A 4×4 Braun array has 16 AND gates, 8 full adders and 4 half adders.
  • Critical path: the slowest signal enters near the top and travels down the diagonal carry chain, then across the last row. It grows with n, not with n2.
  • No correction terms: every partial product is used exactly as generated. Braun is unsigned only.

A first delay estimate: the slowest signal passes about n − 1 adders down the rows and about n − 1 adders along the final ripple row, so tp ≈ tAND + 2(n−1)·tFA, where tFA is one adder delay. For n = 4 that is tAND + 6tFA. Wire delay and gate sizing matter in a real layout (see delay estimation and logical effort). Some syllabi ask only for the block diagram and the partial product array, not this estimate.

Baugh-Wooley for two's complement

Signed numbers use two's complement. For an n-bit number, A = −an−12n−1 + Σi=0n−2 ai2i. The top bit has weight −2n−1, not +2n−1. If you sign-extend both inputs to 2n bits and use a Braun array, the array becomes larger and the sign bits create long rows of copies. Baugh-Wooley keeps the n×n array and corrects the sign inside it.

Generate the low bits normally: aibj for i,j ≤ n−2. For a partial product with exactly one sign bit, use the inverted bit: NOT(an−1bj) for j ≤ n−2, and NOT(aibn−1) for i ≤ n−2. Keep the corner an−1bn−1 unchanged. Then add two 1 bits at fixed positions: bit n and bit 2n−1. In modulo 22n arithmetic, these two 1s are the correction constant 2n + 22n−1.

PBW = Σi=0n−2Σj=0n−2 aibj2i+j + Σj=0n−2 NOT(an−1bj)2n−1+j + Σi=0n−2 NOT(aibn−1)2n−1+i + an−1bn−122n−2 + 22n−1 + 2n

Here PBW is the signed product modulo 22n; NOT(x) is 1−x; the two added powers are the two 1 bits; all powers of 2 are bit positions in the final product.

Baugh-Wooley needs (n−1)2 + 1 AND gates, 2(n−1) NAND gates for the mixed sign bits, two constant 1 inputs and about n(n−1) adder cells. It avoids a separate sign-fix adder and avoids sign extension rows. The array topology and diagonal carry path stay the same as Braun, so the delay is still dominated by the diagonal carry. The saving is area and regularity, not a shorter critical path.

Worked example

Question. Multiply a = 1101₂ (13) by b = 1011₂ (11) on a 4×4 Braun array. Show every partial product row, its place value, the sum, and the final 8-bit product.

  1. Read the multiplier bits from LSB: b0=1, b1=1, b2=0, b3=1.
  2. Row for b0=1: A×1 = 1101₂ = 13. Place value 2⁰ = 1, so it contributes 13.
  3. Row for b1=1: A×2 = 1101₂<<1 = 11010₂ = 26. Contribution 26.
  4. Row for b2=0: A×0 = 0000₂ = 0. Contribution 0.
  5. Row for b3=1: A×8 = 1101₂<<3 = 1101000₂ = 104. Contribution 104.
  6. Add: 13 + 26 + 0 + 104 = 143.
  7. 143 in 8 bits: 143 = 128+8+4+2+1 = 10001111₂.
  8. Check: 13×11=143.

Answer. The product is 10001111₂ = 143.

Exam traps

  • In Braun, adding the partial products without their place-value shifts. Row 1 is shifted one place, not added as the same weight as row 0.
  • In Baugh-Wooley, dropping the two correction 1 bits, or inverting the corner an−1bn−1. The corner has a positive weight and stays normal.
  • Inverting every sign-bit row completely. Only partial products with exactly one sign bit are inverted; the corner is the exception.
  • Mixing the counts: an n×n array has n2 AND gates and n(n−1) adder cells (n(n−2) full adders and n half adders), not n2 full adders.
  • Assuming array delay is n2 gate delays. The critical path is the diagonal carry plus the final ripple, roughly linear in n.

4.4 Wallace tree and Booth multipliers

A multiplier is slow for two reasons: too many partial-product rows to add, or a long carry chain through them. A Wallace tree reduces the rows with parallel 3:2 counters, so the carry chain almost disappears until the last step. Booth recoding changes the multiplier into signed digits, so there are fewer rows to reduce. High-speed CPU and DSP multipliers use both ideas together.

You need: Chapter 4.2 for the 3:2 compressor and Chapter 4.3 for partial-product rows.

Wallace tree: reduce rows in parallel

Start with N partial-product rows from Chapter 4.3. A full adder used as a 3:2 counter takes three bits of the same weight and gives a sum bit of that weight and a carry bit of twice that weight. A carry save adder (CSA) is a row of these counters: it takes three rows and returns two, a sum row and a carry row shifted one place left. The CSA does not propagate the carry across columns, so it has no long carry chain.

At each level, split the rows into disjoint groups of three. Each group of three rows becomes two rows. Any unpaired rows pass down unchanged. All groups at a level work in parallel. For N = 8 the row count falls 8 → 6 → 4 → 3 → 2, as the figure shows. For N = 8 this is four reduction levels.

D ≈ ⌈log3/2(N/2)⌉

D is the number of reduction levels, N is the starting row count, and ⌈ ⌉ means round up. For N = 8, D = 4.

After the last level two rows remain. A final carry propagate adder (CPA) adds them and gives the product. The CPA is not a reduction level; it is the one place where carries travel. Wiring is irregular because bit columns of different weights must be aligned. The Dadda tree is a variant that uses counters as late as possible.

Booth radix-2: recode the multiplier

Booth radix-2 recodes the multiplier Q into signed digits. Let M be the multiplicand and Q an n-bit two's complement multiplier. Bit i of Q is qi. Add one extra bit q−1 = 0 below the LSB. For each i, read the pair (qi, qi−1) and choose a digit di from the table.

Then Q = Σ di 2i. In hardware all digits are formed at once, so each digit makes a partial product di M. Negative digits use the two's complement of M. In the step-by-step view, add di M to an accumulator and then do an arithmetic right shift. Arithmetic right shift copies the sign bit. A logical shift would break negative products. The extra bit q−1 = 0 starts the first pair.

Modified Booth radix-4 and why it helps

Modified Booth radix-4 reads overlapping triplets and produces digits from −2 to +2. It halves the number of partial products compared with radix-2. It needs M and 2M, where 2M is one left shift. The 3M multiple is not needed for radix-4; radix-8 Booth needs 3M. Booth's gains are fewer rows for the adder tree and a multiplier that may be negative with no correction step, because the recoding already handles its two's complement sign. Each partial product can itself be negative, so it is sign-extended to the full product width, or a few sign-extension bits are added in its place.

The cost is more selection logic: the multiplier must choose 0, ±M, or ±2M. That selection is simple in CMOS because 2M is wiring and negation is a complement plus one. For wide multipliers this trade is usually good. For an 8-bit multiplier, radix-4 gives four digits instead of eight; worked example 2 does a 4-bit case with two. Radix-4 is the common compromise in datapath libraries.

4.5 Decoders, multiplexers and comparators

A decoder takes an n-bit code and activates exactly one of 2ⁿ output lines. A multiplexer does the opposite job: it selects one of many data inputs and sends it to a single output. A comparator takes two words and decides whether they are equal, or which is larger. These three blocks route and judge data inside adders, memories and processors. A decoder drives a memory wordline, a multiplexer chooses between results, and a comparator makes a branch decision.

You need: Chapter 4.1 for XOR and equality, and pass transistor logic and transmission gates for the multiplexer switches.

Decoder: a code in, one line out

An n-to-2ⁿ decoder has n input bits and 2ⁿ output lines. For each input code exactly one output is active. A 3-to-8 decoder takes inputs A, B, C, where A is the most significant bit. Input ABC = 101 activates output Y5, because binary 101 equals decimal 5.

Inside is an AND plane. Each input bit drives an inverter, so both true and complement are available. Output Yi is an n-input AND of the chosen literals. For the 3-to-8 decoder, Y5 = A·B′·C. The decoder is a minterm generator: output i is minterm mi. Active-high means the selected line is 1. Active-low means it is 0; a NAND plane or an output inverter gives that.

Yi = 1 ⇔ (bn−1 … b0) = i

Here Yi is output line i; bn−1…b0 is the input code; i is the line number from 0 to 2ⁿ−1.

An enable input turns the whole decoder on or off. Larger decoders use enables to combine smaller ones. A 3-to-8 decoder can be two 2-to-4 decoders: A enables the upper half when A=1 and the lower half when A=0; B and C select the line inside each half. In a memory, a row decoder drives one wordline high for the addressed row (Chapter 4.10). The delay is about one inverter delay plus one n-input AND delay.

Multiplexer: many lines in, one out

A 2:1 multiplexer has data inputs D0 and D1, select S, and output Y. Y equals D0 when S=0 and D1 when S=1, so Y = S′·D0 + S·D1. A pass-transistor pair can build it with two transistors. A transmission gate uses an nMOS and a pMOS in parallel, so both 0 and 1 pass without a threshold drop (see pass transistor logic and transmission gates).

A mux tree builds wider multiplexers. A 4:1 mux uses three 2:1 muxes: the first stage selects D0/D1 and D2/D3 with S0, the second stage selects between those two results with S1. An 8:1 mux uses seven 2:1 muxes and three select levels. For an N:1 mux tree the number of select levels is ceil(log₂N), so tpd ≈ ceil(log₂N) × tmux.

Shannon expansion makes the mux a logic element. Any function f(x1,…,xn) = x1·f(1,…) + x1′·f(0,…). Use the select lines as the variables and tie each data input to 0 or 1, or to a remaining function. An 8:1 mux with selects A,B,C and data inputs equal to the truth table implements any f(A,B,C). A tristate buffer adds a high-impedance state, so many drivers can share a bus; enable exactly one driver at a time.

Comparator: two words, three decisions

A 1-bit equality gate is an XNOR: E = A·B + A′·B′. It gives 1 when the two bits are equal. For n bits, E = En−1·…·E0. This is an AND tree. A linear AND chain has delay tXNOR + (n−1)·tAND; a balanced tree has delay tXNOR + ceil(log₂n)·tAND.

The magnitude cell compares one bit pair and carries the decision. It has inputs Ai, Bi and incoming Gin, Lin, Ein. G means A>B so far, L means A<B so far, E means equal so far. Outputs are: Gout = Gin + Ein·Ai·Bi′ ; Lout = Lin + Ein·Ai′·Bi ; Eout = Ein·(Ai XNOR Bi). Where Gout, Lout, Eout are the updated flags; + is OR; · is AND; ′ is NOT.

Start at the MSB with Gin=0, Lin=0, Ein=1. Feed each cell's outputs to the next less significant cell. The first differing bit decides, and later bits cannot change it. After the last cell, Gout=1 means A>B, Lout=1 means A<B, and Eout=1 means A=B. The chain has n cells, so delay is about n × tcell. Reading from the LSB end is wrong because a later MSB difference must override the earlier answer.

  • Building a large decoder from smaller ones without using the enable as the extra address bit; the MSB must enable the correct half.
  • Letting a comparator decide from the LSB end. The first differing MSB decides, and later bits cannot override it.
  • Forgetting that a tristate bus needs exactly one enabled driver: two drivers cause contention, none causes a floating bus.
  • Confusing a multiplexer's select lines with its data inputs in Shannon expansion, or tying a data input to a variable that is also a select.

4.6 Static and dynamic latches and registers

A latch stores one bit in a feedback loop that is open for part of the clock: while open, the output follows the input; while closed, it holds. Two latches on opposite clock phases make an edge-triggered register, the store behind every pipeline stage, counter and shift register. A static latch keeps its bit in a regenerating loop for as long as power is on. A dynamic latch keeps it as charge on a capacitance, which is smaller and faster but leaks away, so the clock must keep running.

You need: transmission gates (see pass transistor logic and transmission gates), the inverter switching voltage VM (see CMOS inverter DC characteristics) and the 2:1 multiplexer of Chapter 4.5.

Bistability and static latches

Two inverters connected in a ring are bistable. Their two transfer curves, drawn on one set of axes, cross at three points. The points near 0 V and VDD are stable, because each inverter's gain is below 1 there and a small disturbance dies away. The middle point, with both nodes at the switching voltage VM, is metastable: the loop gain is above 1, so any noise grows until the loop falls to 0 or 1. Writing a latch means forcing the loop past VM; data changing too close to the clock edge can leave it hanging near VM, which is metastability.

The SR latch builds the loop from two cross-coupled NOR gates: S = 1 sets Q = 1, R = 1 resets it, S = R = 0 holds, and S = R = 1 is not allowed (both outputs go to 0 and the release is a race). NAND gates give the same latch with active-low inputs.

The gated D latch removes the forbidden input. In CMOS it is built as a multiplexer: Q = CLK·D + CLK′·Q. While CLK = 1 the latch is transparent and Q follows D; while CLK = 0 the multiplexer selects the feedback path and the loop holds the last value. A positive latch (transparent when CLK = 1) uses two transmission gates and two inverters: one gate admits D, the other closes the inverter loop on the opposite clock phase. The 6T SRAM cell keeps its bit in the same cross-coupled inverter loop but writes it through access transistors (Chapter 4.9).

Master-slave register, timing and shift registers

A master-slave register is a negative latch (the master) followed by a positive latch (the slave). While CLK = 0 the master is transparent and follows D; the slave is opaque and holds the old output. At the rising edge the master closes and keeps the value D had just before the edge, and the slave opens and copies it to Q. While CLK = 1 the master is closed, so the slave has nothing new to pass. Q therefore changes once per period, just after the rising edge: the pair is a rising-edge-triggered register. Swapping the two latches gives a falling-edge register.

Three timing numbers describe a register. Setup time tsu: D must be stable this long before the edge. Hold time th: D must stay stable this long after it. Clock-to-Q delay tcq: the time from the edge to a valid Q. For a path through logic of delay tcomb to the next register (Chapter 4.8 works a full example with skew):

T ≥ tcq + tcomb,max + tsu

Here the setup check uses the longest path; setup slack = T − tcq − tcomb,max − tsu ≥ 0, and fmax = 1 ÷ Tmin.

tcq + tcomb,min ≥ th

Here the hold check uses the shortest path (and, strictly, the fastest clock-to-Q delay). T does not appear, so slowing the clock cannot fix a hold failure. Clock skew and jitter enter both checks; Chapter 4.8 adds them.

A register is n flip-flops sharing one clock. A shift register chains them: Q of stage i drives D of stage i + 1, so each clock edge moves every bit one place. Read all stages at once and it is a serial-in parallel-out converter (worked example); load the stages in parallel and shift out, and it is parallel-in serial-out. This works only because the stages are edge-triggered: transparent latches on one clock would let a bit race through several stages.

Dynamic latches and registers: C²MOS and TSPC

A dynamic latch drops the feedback loop and keeps the bit as charge on the gate capacitance of the next inverter. The dynamic transmission-gate register is the simplest: transmission gate, inverter, transmission gate, inverter, eight transistors in all. While CLK = 0 the first gate is on and the master node follows D; at the rising edge it turns off and the node holds its charge, while the second gate passes the value on to the output inverter. It is small and fast, but if CLK and CLK′ overlap (both briefly 1, or both 0) the two gates conduct together and D can race through to Q.

The C2MOS register (clocked CMOS) removes that risk. Each transmission gate and inverter becomes one clocked inverter: two pMOS in series above the output and two nMOS in series below it, with the clock on one transistor of each pair. The master is clocked by CLK′ and the slave by CLK. During a 0-0 clock overlap only the pull-up halves of the two stages can conduct; during a 1-1 overlap only the pull-down halves. Because both stages invert, a value passing through both needs a pull-up in one stage and a pull-down in the other, and an overlap only ever turns on the same half in both. So the register is insensitive to clock overlap, as long as the clock edges are sharp.

The true single-phase clock register (TSPC) uses only CLK, so there is no CLK′ to generate, route or skew. A TSPC latch is two cascaded clocked inverter stages driven by CLK alone: a positive latch is transparent while CLK is high and a negative latch while it is low. A negative latch followed by a positive latch is a rising-edge register. It is compact and fast, and common in high-speed frequency dividers.

Static or dynamic? A static loop replaces any charge lost to leakage, so the bit survives with the clock stopped. A dynamic node only holds charge, which leaks away, so the clock must come back before the node voltage droops by more than the allowed ΔV. Treating the whole period as hold time:

fmin ≈ Ileak ÷ (C × ΔV)

Ileak is the leakage current in A, C the storage capacitance in F, ΔV the allowed droop in V and fmin the lowest safe clock frequency in Hz. A static latch has no fmin: it works down to DC.

4.7 Pipelining and nonbistable sequential circuits

Pipelining cuts a long block of logic into stages with registers between them, so a new input can start every short clock period instead of every long one: throughput rises, at the cost of some latency and some registers. The same syllabus topic groups the nonbistable sequential circuits, circuits with feedback that do not have two stable states: the Schmitt trigger with its two thresholds, the monostable one-shot that makes a pulse of fixed width, and the astable ring oscillator that never stops switching.

You need: register timing (setup time, clock-to-Q) from Chapter 4.6, and the multiplier of Chapter 4.4 for the example datapath.

Pipelining a datapath

Take a multiply-accumulate step, y = a × b + c, applied to a stream of samples. Without pipelining, an input register launches a, b and c, the multiplier and then the adder settle, and an output register captures y. The clock period must cover the whole path: T = tcq + tmult + tadd + tsu.

Put a register after the multiplier. Now the multiplier works on sample n + 1 while the adder finishes sample n, and each stage only needs its own logic in one period:

Tpipe = tcq + tstage,max + tsu

Here tstage,max is the logic delay of the slowest stage; tcq + tsu is the register overhead that every stage pays once.

Two numbers describe a pipeline. Throughput is results per second, 1 ÷ Tpipe once the pipeline is full. Latency is the time from an input to its result: k × Tpipe for k stages. Latency grows, because every stage pays the overhead and waits for the slowest stage. N inputs take (k + N − 1) periods: k to fill the pipeline, then one result per period. So k stages are at most k times faster, and only when the stages are balanced and the overhead is small.

A register cannot be dropped into a feedback loop, such as an accumulator adding its own output, because the loop would then use an older value. Latch-based pipelines use two-phase latches instead of registers, so a slow stage can borrow time from the next. NORA CMOS is a dynamic logic style built for this: alternating n-type and p-type dynamic blocks with C2MOS latches between them.

The Schmitt trigger

A Schmitt trigger is an inverter or buffer with two switching thresholds. A rising input switches it at VM+; a falling input switches it back only below VM−, with VM+ > VM−. The gap VH = VM+ − VM− is the hysteresis, and the transfer characteristic is a loop rather than one curve. Noise smaller than VH cannot make the output chatter, and a slow, noisy ramp gives one clean, fast edge (worked example 2). Input pins, reset lines and switch debouncers use one.

The CMOS Schmitt trigger is an inverter with positive feedback. In the common six-transistor form the pull-down is two nMOS in series, and a feedback nMOS, gated by the output, connects their middle node towards VDD. While the output is high, that transistor holds the middle node up, so the input must rise further before the pull-down wins: VM+ moves up. A matching feedback pMOS on the two series pMOS lowers VM− while the output is low. Sizing the feedback transistors sets the hysteresis.

Monostable and astable circuits

A monostable circuit, or one-shot, has one stable state. A trigger edge flips it into the other state and it returns by itself after a fixed time, so its output is a pulse of set width. The CMOS version needs no capacitor: feed the input to an AND gate directly and through a chain of an odd number N of inverters. After a rising edge the delayed, inverted copy stays 1 for the chain delay, so the AND gives a pulse of width about N × tp, where tp is one inverter's delay. An XOR of the input and a delayed copy pulses on both edges; memories use that as address transition detection (Chapter 4.10).

An astable circuit has no stable state and oscillates by itself. The ring oscillator is an odd number N of inverters in a loop: no set of values is consistent, so a transition runs round the ring for ever. One period needs the edge to go round twice, once rising and once falling:

f = 1 ÷ (2N·tp)

N is the odd number of inverters and tp the propagation delay of one inverter. An even ring has a consistent state, so it is a latch, not an oscillator.

Starving each inverter of current through a control voltage turns the ring into a voltage-controlled oscillator (VCO) for phase-locked loops. A relaxation oscillator, a capacitor charged until a Schmitt trigger flips and discharges it, is another astable circuit.

4.8 Timing classification: synchronous and self-timed design

Every digital system needs a rule for when a signal is valid. A synchronous system clocks every register from one clock. Parts that share a frequency but not a phase are mesochronous, parts with nearly equal frequencies are plesiochronous, and parts with no clock at all are asynchronous or self-timed. This chapter classifies these schemes, shows how clock skew and jitter eat into a synchronous design's clock period, and builds the self-timed alternative from handshakes, completion detection and the Muller C-element.

You need: setup, hold and clock-to-Q from Chapter 4.6, and pipelines from Chapter 4.7.

A truly asynchronous input reaching a clocked system needs a synchronizer, usually two flip-flops in series, so that a metastable first flip-flop has a whole period to settle before anyone reads it.

Synchronous design: clock skew and jitter

Clock skew δ is the difference in arrival time of the same clock edge at two registers: δ = arrival at the capturing register − arrival at the launching register. It is spatial and constant from cycle to cycle, caused by different wire lengths, loads and buffers in the clock tree. Clock jitter tjit is the variation of one register's edge from cycle to cycle around its ideal time, caused by supply noise and the clock generator. For the worst case, the launch edge may come tjit late and the capture edge tjit early:

T + δ ≥ tcq + tlogic + tsu + 2tjit

Here the setup check: T is the clock period and tlogic the longest logic delay. Positive δ (clock travelling with the data) gives the data extra time.

tcq,cd + tlogic,cd ≥ th + δ + 2tjit

Here the hold check: tcq,cd and tlogic,cd are the contamination (fastest) delays of the register and the shortest logic path. Positive δ lets the capture register look later, so new data can arrive before its hold time ends.

So positive skew helps setup and hurts hold; negative skew (clock against the data) helps hold and costs speed; jitter only hurts. Designers keep both small with balanced clock distribution: an H-tree, whose equal-length branches reach every leaf at the same time, or a clock grid that shorts the tree's ends together, with buffers along the way and a phase-locked or delay-locked loop to line the on-chip clock up with the outside one.

Self-timed circuit design

A self-timed circuit replaces the global clock with local handshakes. A stage tells the next that its output is valid with a request (Req), and the receiver answers that it has taken the data with an acknowledge (Ack). The four-phase, or return-to-zero, protocol has four events per transfer: Req↑ (data valid), Ack↑ (data taken), Req↓, Ack↓ (ready for the next one). The two-phase protocol uses every transition as an event, one Req edge and one Ack edge per transfer: faster, but the logic must respond to edges rather than levels.

The receiver must know when the logic has finished. Dual-rail coding sends each bit on two wires (t, f): (0, 0) is a spacer meaning not yet valid, (1, 0) means 1, (0, 1) means 0, and (1, 1) is never used. A bit is complete when t + f = 1, and the word is complete when every bit is. DCVSL produces both rails naturally, which is why self-timed adders often use it. The cheaper bundled-data method keeps single-rail data and sends Req through a matched delay line slightly slower than the logic's worst case.

The Muller C-element joins handshakes. Its output goes to 1 when both inputs are 1, goes to 0 when both are 0, and otherwise holds its value. In CMOS it is two series pMOS and two series nMOS driving a node held by a weak keeper inverter. One C-element per stage, driven by the stage's incoming Req and the inverted output of the next stage's C-element, forms a Muller pipeline: the self-timed version of Chapter 4.7.

Self-timed design removes clock power and clock skew, runs at the average delay of the data rather than the worst case, and tolerates supply and process variation. Its costs are extra wires (dual rail doubles them), completion-detection area, hazard-free logic design and weaker tool support, so most chips are synchronous with self-timed islands in memories, FIFOs and interfaces.

4.9 Memory design: SRAM, DRAM and ROM

A memory chip is a grid of identical cells. The row decoder drives one wordline high; that row's cells place their bits on vertical bitlines; sense amplifiers decide each bit as 0 or 1. This one pattern covers SRAM, DRAM and ROM, though the cell and the read mechanism differ. It exists because a processor needs many words close at hand at nanosecond speed, and a regular grid is the cheapest way to store millions of bits. Every register file, cache, main memory and instruction ROM in a phone or a laptop uses it.

You need: Chapter 4.5 for decoders, Chapter 4.6 for the storage loop and dynamic charge storage. Chapter 4.10 builds the decoders, column multiplexers and sense amplifiers around these cells.

The array, its address and its timing

Every memory is a grid of R rows by C columns of identical cells. The row decoder raises one wordline (WL); every cell on that row connects to its bitline (BL), or to a true and complement pair BL and BLB; the sense amplifiers turn the small bitline signal into full logic levels. An address of r row bits and c column bits picks one word: r bits choose one of 2r rows and c bits choose one group of bitlines from that row, so the array holds 2r+c words. How the address is split, and the decoders, column multiplexers and sense amplifiers themselves, are the subject of Chapter 4.10; this chapter is about the cell at each crossing.

Access time tAA is the delay from a new address to valid data. Cycle time tCYC is the shortest gap between the starts of two accesses. tCYC ≥ tAA, because after each access the bitlines must be precharged again and the old wordline must fall. A processor may request a word every cycle, so the array must meet tCYC. Mixing these two is a common error.

SRAM and DRAM cells

6T SRAM. Six transistors hold one bit. Two cross-coupled inverters (four transistors) form a loop; two access transistors connect the loop to BL and BLB, the true and complement bitlines. Read: precharge both bitlines to VDD, then drive WL high. The side of the cell that stores 0 pulls its bitline slightly down through the access and pull-down transistors. The sense amplifier resolves it. Write: the write driver drives BL and BLB strongly opposite; with WL high it overpowers the loop and flips it. When WL falls, the loop keeps the new bit. Read disturb: during a read the low internal node rises because the access transistor and pull-down transistor act as a divider. If it crosses the trip point, the cell flips. The cell ratio CR = (W/L of the pull-down) ÷ (W/L of the access transistor) keeps the read safe: a pull-down stronger than the access transistor holds the low node down, and textbook designs keep CR above about 1.2. Writing needs the opposite fight to be won: the access transistor must beat the pMOS pull-up, so the pull-up ratio PR = (W/L of the pull-up) ÷ (W/L of the access) is kept small, below about 1.8 in the usual textbook rule. SRAM is fast and needs no refresh, but six transistors per bit make it less dense and it leaks.

1T1C DRAM. One access transistor and one storage capacitor CS hold one bit as charge. Logic 1 is VDD on CS; logic 0 is 0 V. Read: precharge BL to VDD/2, drive WL high, and let charge share between CS and bitline capacitance CBL. The bitline moves by ΔV = (Vcell − VDD/2) × CS/(CS + CBL), where Vcell is the stored cell voltage before the read. The bitline is long and carries many cells, so CBL is several times CS; with CS/(CS + CBL) near 0.1 the swing is only tens of millivolts (worked example 2). The sense amplifier resolves it. The read is destructive: charge sharing removes charge, so the value must be written back (restore). Leakage drains CS, so every row must be refreshed within tREF, typically 64 ms. DRAM is dense and cheap per bit, but volatile and slower.

ROM and comparison

Mask ROM stores one bit at each row-column crossing by the presence or absence of a transistor: one transistor per bit. The row decoder drives a wordline; a programmed cell pulls its bitline low, a missing cell leaves it high. Mask ROM is programmed at fabrication, cheap in volume and non-volatile. PROM is one-time programmable by blowing fuses or antifuses. EPROM is erased by ultraviolet light through a quartz window. EEPROM is erased electrically, byte by byte. Flash is EEPROM-like but erased in blocks; it is the common code and SSD memory. A ROM is also a logic block: with the inputs on the address lines, a 2n × m ROM holds the truth table of any m functions of n variables. Programmable logic arrays share product terms instead of storing every minterm; see programmable logic devices and FPGA architecture.

  3. Stored 0: Vcell = 0 V. ΔV = (0 − 0.6) × 0.1 = −0.06 V = −60 mV.
  4. After charge sharing the cell and the bitline sit at the same voltage: 0.6 + 0.06 = 0.66 V for a stored 1, and 0.6 − 0.06 = 0.54 V for a stored 0. Both are close to VDD/2, so the bit is gone until the sense amplifier drives the bitline to 1.2 V or 0 V and writes it back.

Answer. The swing is ±60 mV, and the cell is left at 0.66 V or 0.54 V, which is why the read is destructive and must be restored.

Exam traps

  • Access time is address-to-data delay; cycle time is the minimum gap between two accesses. Cycle time is never smaller than access time.
  • A DRAM read shares charge with the bitline and destroys the stored value; it must be restored before the next access. SRAM read does not destroy the bit, but a poor cell ratio can disturb it.
  • Refresh interval tREF is the maximum time for all rows, not for one row. For 4096 rows and 64 ms, each row is refreshed every 15.6 µs while the whole array is refreshed every 64 ms.
  • ROM is non-volatile and needs no refresh; DRAM is volatile and needs refresh; SRAM is volatile but needs no refresh.
  • A stronger access transistor helps write but worsens read disturb; a stronger pull-down protects the read, and a weaker pMOS pull-up helps the write. SRAM cell sizing balances the cell ratio against the pull-up ratio.

4.10 Memory architecture: core and peripheral circuits

A memory macro is a core of identical cells wrapped in peripheral circuits: address decoders that pick a row and a column, sense amplifiers that read a tiny bitline swing, precharge circuits, write drivers and the timing control that sequences them. The core sets the density; the periphery sets the speed and much of the power. This chapter builds the architecture from the address bits outwards, sizes it with numbers, and explains the circuits examiners ask for: the predecoded row decoder, the column multiplexer and the latch sense amplifier.

You need: decoders and multiplexers from Chapter 4.5, and the SRAM and DRAM cells of Chapter 4.9.

Memory architecture and building blocks

Memories are classed by function (read-write SRAM and DRAM; non-volatile EPROM, EEPROM and flash; read-only ROM) and by access: random, serial (FIFO) or content-addressable (CAM), which returns the address of a stored word.

One word per row would make the array absurdly tall and its bitlines long and slow, so the array is folded to be roughly square. Each row holds 2c words side by side; the K address bits split into r row bits, which pick the wordline, and c column bits, which pick one word from that row:

N = 2K, rows = 2r, columns = M × 2c, K = r + c

Here N is the number of words, M the bits per word, K the number of address bits, r the row bits and c the column bits. Choosing r and c makes the array nearly square.

Large memories add a third level. The array is cut into blocks (banks), and block-address bits pick one block. Only that block's wordline and bitlines switch, so every wire is shorter, with less RC delay, and the power falls. The building blocks are always the same: the core array, the row and column decoders, precharge and equalise circuits, sense amplifiers, write drivers, input and output buffers and the timing control.

Address decoders and column circuits

A row decoder for r bits raises one of 2r wordlines. Built directly, every wordline needs an r-input AND gate, and each address line, true or complement, drives half of all those gates. Predecoding splits the work: small decoders first decode groups of address bits, then a 2-input or 3-input gate per wordline combines one line from each group. For 10 row bits, two 5-to-32 predecoders make 64 lines, and each of the 1024 wordlines is a 2-input AND (a NAND followed by the wordline driver) of one line from each predecoder (worked example 1). The wide gates shrink, the load on each address line falls, and the final gate fits the narrow cell pitch.

The final stage is a wordline driver, sized to charge a long, heavily loaded wordline quickly; logical effort sizes the chain from address pin to wordline. Dynamic decoders precharge all outputs and discharge all but the selected one.

The column decoder picks one word's bitlines from the row. A pass-transistor column multiplexer connects one of 2c bitline pairs to each sense amplifier. A tree multiplexer needs fewer decoded select lines but puts c pass transistors in series; a one-level multiplexer puts only one transistor in series but needs a full c-to-2c column decoder. Before every access, precharge transistors pull each bitline pair to VDD (VDD/2 in DRAM) and an equalise transistor shorts BL to BLB so the pair starts exactly equal. For a write, the write driver pulls one bitline of the selected pair to 0.

Sense amplifiers and timing control

A bitline carries hundreds of cells, so its capacitance CBL is large, while a cell's read current Icell is small. The time to build a swing ΔV is:

t = CBL × ΔV ÷ Icell

CBL is the bitline capacitance in F, ΔV the swing in V and Icell the cell read current in A. A full swing would take ten times as long as a 0.1 V one (worked example 2).

The sense amplifier needs only a small difference, about 0.1 V in SRAM or the tens of millivolts of a DRAM charge share, and amplifies it to full logic levels. The latch-type sense amplifier is a pair of cross-coupled inverters, the bistable loop of Chapter 4.6, connected to BL and BLB. With its enable off, the bitlines develop their difference; when the sense-enable signal SE turns on its tail transistor, positive feedback drives the higher side to VDD and the lower side to 0 within a few gate delays. The differential current-mirror amplifier is the other common type: slower to resolve, but it does not disturb the bitlines. DRAM uses the latch type on each folded bitline pair, which also writes the value back into the cell after the destructive read.

Timing control sequences precharge, wordline, sense enable and output latch. Many SRAMs make it self-timed: a replica bitline with dummy cells discharges like a real one, and its crossing fires SE, so the timing tracks process and temperature. Asynchronous SRAMs use address transition detection, the one-shot of Chapter 4.7, to start a cycle whenever any address bit changes. Spare rows and columns, switched in by fuses after test, repair faulty cells (see memory testing and memory fault models).

Worked example

Question. A 1 Mbit SRAM is organised as 64K words × 16 bits. (a) How many address bits does it need? (b) Lay it out as a square 1024 × 1024 cell array: how many row and column address bits, and how wide is each column multiplexer? (c) Compare a direct row decoder with one built from two 5-to-32 predecoders, by the number of gate inputs and by the load on each address line.

  1. (a) 64K = 65536 = 216 words, so K = 16 address bits. Check: 65536 × 16 = 1048576 bits = 1 Mbit.
  2. (b) 1024 rows = 210, so r = 10. Each row has 1024 cells = M × 2c = 16 × 2c, so 2c = 64 and c = 6. Check: r + c = 10 + 6 = 16 = K.
  3. Each of the 16 data bits has its own 64:1 column multiplexer and its own sense amplifier: 64 words share each row, one is picked.
  4. (c) Direct: 1024 AND gates with 10 inputs each = 10240 gate inputs. Every address literal (A or A′) appears in half the gates, so it drives 512 gates.
  5. Predecoded: two 5-to-32 predecoders have 64 five-input gates = 320 inputs, plus 1024 two-input gates = 2048 inputs, 2368 in all, about 4.3 times fewer.
  6. Loads: each address literal now drives 16 of the 32 gates in its predecoder, and each predecoder line drives 32 wordline gates, instead of 512.

Answer. 16 address bits: 10 row bits for 1024 wordlines and 6 column bits for a 64:1 multiplexer on each of the 16 outputs. Predecoding needs 2368 gate inputs instead of 10240 and cuts the load on each address line from 512 gates to 16.

Worked example 2

Question. An SRAM bitline has CBL = 100 fF and the cell read current is 40 µA. The sense amplifier needs ΔV = 100 mV. How long must the wordline be on before SE fires, and how long would a full 1.0 V swing take?

  1. Sense: t = CBL × ΔV ÷ Icell = 100 × 10−15 × 0.1 ÷ (40 × 10−6) = 10−14 ÷ (4 × 10−5) = 2.5 × 10−10 s = 0.25 ns.
  2. Full swing: t = 100 × 10−15 × 1.0 ÷ (40 × 10−6) = 2.5 × 10−9 s = 2.5 ns.
  3. Saving: 2.5 − 0.25 = 2.25 ns per read, ten times faster bitline sensing.

Answer. SE can fire after about 0.25 ns; waiting for a full swing would take 2.5 ns, so the sense amplifier saves 2.25 ns on every read.

Exam traps

  • Taking the row count straight from the word count. A 64K × 16 memory is not 65536 rows; it is folded into, for example, 1024 rows of 64 words, with 10 row bits and 6 column bits.
  • Forgetting the word width when finding column bits: columns = M × 2c, so 1024 columns of 16-bit words give 2c = 64, not 1024.
  • Saying SRAM bitlines precharge to VDD/2. SRAM precharges to VDD; DRAM precharges to VDD/2.
  • Calling the column multiplexer a decoder. The column decoder makes the select lines; the multiplexer is the pass transistors they drive.

Takeaways

  1. A wide adder is a carry problem: ripple carry settles in about 2n gate delays, and every faster adder is a different way to tell the top bits their carry sooner.
  2. Carry look-ahead computes every carry from generate and propagate terms in two-level logic; blocks of 4 bits with group generate and propagate keep the gates small and the delay logarithmic.
  3. Carry select precomputes both answers, carry skip bypasses blocks whose bits all propagate (best block size √(n·tmux ÷ 2tc)), and carry save postpones the carry to one final adder.
  4. An array multiplier is regular but its delay grows linearly with n; Baugh-Wooley handles two's complement in the same array with 2(n−1) inverted bits and two correction 1s.
  5. A Wallace tree reduces partial-product rows with 3:2 counters in logarithmic depth, and radix-4 Booth recoding halves the rows it has to reduce.
  6. A latch is level-sensitive and a master-slave register is edge-triggered; setup uses the longest path and the clock period, hold uses the shortest path and never contains T.
  7. Pipelining raises throughput, not speed per item: latency grows, and k stages give less than k times the rate because of register overhead and unbalanced stages.
  8. Skew helps one timing check and hurts the other, jitter only hurts; self-timed design replaces the clock with handshakes, completion detection and C-elements.
  9. An SRAM bit lives in a feedback loop and a DRAM bit in leaking charge read as a tens-of-millivolts swing; ROM stores bits as present or absent transistors.
  10. A memory is a square core plus periphery: K = r + c address bits, predecoded row decoders, column multiplexers, sense amplifiers and timing control set its speed.

  8. The latch sense amplifier therefore saves 5.0 − 0.6 = 4.4 ns per read. Its enable should come from a replica bitline so that it fires at about 120 mV in every process corner, and the bitlines must be precharged to VDD and equalised before each access.
  9. Block diagram to draw: address register; row predecoders and 1024 wordline drivers on the left; the 1024 × 2048 core; precharge across the top; column multiplexers, 8 sense amplifiers and write drivers below; column decoder; data I/O; timing control (CE, WE, SE).
  10. Check: 1024 rows × 256 words per row = 262,144 = 256K words, and 2048 columns ÷ 8 bits = 256 words per row, so every address maps to exactly one 8-bit word.

Analyze Compare ripple carry, carry look-ahead, carry select and carry skip adders for an N-bit word on area, delay and wiring complexity. Which would you choose at N = 64 and why? 14 marks

Points to cover. Delay order: ripple linear; skip and select about √N; hierarchical look-ahead logarithmic; Area order: ripple smallest, skip a little more, look-ahead and select largest; Wiring and layout regularity favour ripple, skip and select; Numbers for N = 64 in gate delays; Justified choice with the trade-off stated.

Model answer.

  1. Common delay model. A full adder's carry takes 2 gate delays, a 2:1 multiplexer about 2 gate delays, an XOR 1. All numbers below are for N = 64 under this model; real designs differ in detail but keep the ranking.
  2. Ripple carry. Delay 2N = 128 gate delays (carry-out). Area: N full adders, the minimum. Wiring: one cell repeated with only neighbour-to-neighbour connections. Fine for 8 bits, hopeless for a 64-bit datapath at GHz rates.
  3. Carry skip. Delay T ≈ 2k·tc + (N/k − 1)·tmux. With tc = tmux = 2 gate delays, kopt = √(64 ÷ 2) ≈ 5.7; k = 4 gives 16 + 30 = 46 and k = 8 gives 32 + 14 = 46 gate delays. Area: ripple plus one AND and one multiplexer per block (about 8 to 16 multiplexers). Wiring: regular. Delay grows as √N.
  4. Carry select (square-root). Blocks of 2, 3, 4, … 11 bits (sum 65 ≥ 64), so about 10 blocks. The first block ripples in 4 gate delays, and each later block's answers are ready as the selected carry arrives, so the carry-out is ready after about 4 + 9 × 2 = 22 gate delays, about 24 with the last sum multiplexer. Area: almost two adders plus N multiplexers. Wiring: regular but wide multiplexer select lines.
  5. Carry look-ahead (hierarchical, 4-bit blocks). Three levels for 64 bits: g, p at 1; group signals at 3 and 5; top-level carries at 7; back down at 9 and 11; sums at 12 gate delays. Area: g/p logic, 16 + 4 + 1 look-ahead units with fan-in up to 5, and long wires between levels. Wiring: the most irregular, with high fan-out of the low-order signals.
  6. Summary for N = 64:
    AdderDelay growthDelay (gate delays)AreaWiring
    RippleN128smallestsimplest
    Carry skip√Nabout 46smallregular
    Carry select√Nabout 24large (about 2 adders)regular, wide selects
    Look-aheadlog Nabout 12moderate to largeirregular, high fan-out
  7. Analysis. Going from ripple to skip removes most of the delay for a few per cent more area: the best speed-per-area step. Select halves the delay again by doubling the adder. Look-ahead halves it once more, but needs careful sizing and wiring; at 64 bits its logarithmic growth is what makes the difference, because every other scheme grows at least as √N.
  8. Choice at N = 64. For a processor ALU on the critical path: a hierarchical look-ahead adder (in practice a parallel-prefix form of it), about 12 gate delays, about ten times faster than ripple. For an address incrementer, a low-power accelerator or anything off the critical path: carry skip, which gets within a factor of four of look-ahead at little more than ripple area. Carry select is a good middle choice when a regular layout matters more than area, and is often combined with look-ahead blocks.
  9. Check: the ranking 128 > 46 > 24 > 12 gate delays follows the growth laws N > √N > log N, and the area ranking runs the other way, so the choice is an explicit speed-for-area trade.
Evaluate Compare an array multiplier with a Wallace tree multiplier for 16×16 bits on delay, area and layout regularity. Explain how Booth recoding changes the picture. 14 marks

Points to cover. Array: 256 AND gates, 240 adder cells, delay about tAND + 30tFA, regular; Wallace: 16 rows reduced in 6 levels, then a fast 32-bit adder; Counter count is similar; the tree costs long, irregular wires; Booth radix-4: 8 rows, 4 levels; extra recoding and selection logic; Recommendation depends on whether regularity or speed dominates.

Model answer.

  1. Common ground. Both multiply 16 × 16 bits into a 32-bit product from the same 16 × 16 = 256 partial-product bits (AND gates, or NAND gates for the signed bits of Baugh-Wooley). They differ in how they add the 16 rows.
  2. Array (Braun or Baugh-Wooley). n(n−1) = 16 × 15 = 240 adder cells in 15 rows, each row adding one more partial product, then a ripple row. Delay ≈ tAND + 2(n−1)tFA = tAND + 30tFA: linear in n. Layout: a rectangle of identical cells with nearest-neighbour wiring, easy to draw and to pipeline row by row.
  3. Wallace tree. Each level groups rows in threes and turns each group into two with carry save adders:
    LevelRows inGroups of 3Rows out

  4. Wallace delay. Six full-adder delays for the reduction, matching ⌈log1.5(16/2)⌉ = ⌈5.13⌉ = 6, then one 32-bit carry propagate adder. With a fast (look-ahead) final adder of roughly 12 gate delays, about 6 tFA at 2 gate delays per tFA, the total is about tAND + 12tFA, against tAND + 30tFA for the array: about 2.5 times faster.
  5. Wallace area and layout. The tree uses about the same number of full adders as the array (each full adder removes one bit, and both must remove the same bits), plus a fast final adder. The cost is wiring: bits move between columns and levels in an irregular pattern, wires are long and cross, and the layout is harder to make compact.
  6. Booth radix-4. Rows fall from 16 to 8 (plus sign-extension bits), so the Wallace tree needs 8 → 6 → 4 → 3 → 2, four levels instead of six, and about half the adders. In an array, Booth halves the height of the array and its delay.

Analyze A multiply-accumulate datapath has a 4.0 ns multiplier and a 2.0 ns adder between registers with tcq = 0.3 ns and tsu = 0.2 ns. Analyse its clock rate and latency unpipelined, in two stages and in three balanced stages, and explain how clock skew between the pipeline registers can cause a hold violation. 13 marks

Points to cover. Unpipelined T = tcq + tlogic + tsu; Two stages limited by the slower stage; three balanced stages; Throughput against latency; (k + N − 1) periods for N inputs; Setup with skew: T + δ ≥ tcq + tlogic + tsu; hold: tcq,cd + tlogic,cd ≥ th + δ; Positive skew helps setup and can break hold; fix by delaying the short path.

Model answer.

  1. Unpipelined. One register-to-register path holds both blocks: T = 0.3 + 4.0 + 2.0 + 0.2 = 6.5 ns, f = 1 ÷ 6.5 ns = 153.8 MHz, latency 6.5 ns.
  2. Two stages (register after the multiplier). Stage delays 4.0 ns and 2.0 ns; the clock must suit the slower: T = 0.3 + 4.0 + 0.2 = 4.5 ns, f = 222.2 MHz. Latency 2 × 4.5 = 9.0 ns. The adder stage idles 2.0 ns of every period, so the gain is only 6.5 ÷ 4.5 = 1.44.
  3. Three balanced stages (multiplier split into two 2.0 ns halves, for example the partial-product tree and the final adder). T = 0.3 + 2.0 + 0.2 = 2.5 ns, f = 400 MHz, latency 3 × 2.5 = 7.5 ns. Gain 6.5 ÷ 2.5 = 2.6, not 3, because each stage pays 0.5 ns of register overhead.
  4. Summary:
    DesignT (ns)f (MHz)Latency (ns)1000 samples (ns)
    Unpipelined6.5153.86.51000 × 6.5 = 6500
    2 stages4.5222.29.0(2 + 999) × 4.5 = 4504.5
    3 stages2.5400.07.5(3 + 999) × 2.5 = 2505
  5. Analysis. Pipelining raises throughput, not the speed of one sample: latency rises from 6.5 ns to 7.5 or 9.0 ns. Balancing the stages matters more than their number, and the overhead tcq + tsu sets a floor: even infinitely many stages could not beat 0.5 ns per period.
  6. Skew. Let δ = clock arrival at the capturing register − arrival at the launching register. The setup check becomes T + δ ≥ tcq + tlogic,max + tsu, so positive δ (clock routed with the data) lets T shrink: with δ = 0.15 ns, T ≥ 2.5 − 0.15 = 2.35 ns.
  7. Hold. The same edge that launches new data at one register must not let it reach the next register before that register's hold time has ended. Take th = 0.1 ns, contamination delays tcq,cd = 0.2 ns and a shortest logic path tlogic,cd = 0.1 ns (a bypass wire between two stages):
    hold: tcq,cd + tlogic,cd ≥ th + δ
δ = 0.15 ns:  0.2 + 0.1 = 0.30 ≥ 0.1 + 0.15 = 0.25   passes, margin 0.05 ns
δ = 0.25 ns:  0.30 ≥ 0.1 + 0.25 = 0.35                 fails by 0.05 ns
  8. Why skew causes it. With positive skew the capturing register is clocked later, so it is still holding when data launched at the earlier edge, through the short path, arrives: it captures the new value a cycle too early. T is not in the hold check, so slowing the clock does not help.
  9. Fixes. Add delay to the short path only (a buffer of at least 0.05 ns, say 0.1 ns, gives 0.40 ≥ 0.35), reduce the skew by balancing the clock tree, or use registers with a smaller hold time. Adding the buffer leaves the long path, and so T, unchanged.
  10. Check: with δ = 0.25 ns and a 0.1 ns buffer, setup T ≥ 2.5 − 0.25 = 2.25 ns and hold 0.40 ≥ 0.35 ns both pass, so the skew becomes a speed gain instead of a failure.
Evaluate A system needs 1 Mbit of on-chip storage and 1 Gbit of main memory. Evaluate the choice of 6T SRAM for the first and 1T1C DRAM for the second, covering cell size, speed, refresh, sense amplifier design and standby power. 13 marks

Points to cover. SRAM cell is six transistors, DRAM cell one transistor and one capacitor; SRAM read is differential, fast and non-destructive; DRAM needs charge sensing and restore; DRAM refresh costs bandwidth and standby power; Sense amplifiers and precharge differ: VDD against VDD/2; Conclusion: SRAM for speed-critical on-chip storage, DRAM for density.

Model answer.

  1. Cell size. 1 Mbit of 6T SRAM needs 6 × 220 = 6,291,456 transistors in its cells. 1 Gbit of 6T SRAM would need 6 × 230 ≈ 6.44 billion, against 230 ≈ 1.07 billion transistors (plus capacitors) for 1T1C DRAM. The DRAM cell is far smaller, which is what makes a gigabit affordable.
  2. Process. SRAM uses the ordinary logic transistors, so it sits on the processor die next to the logic. DRAM needs a large, low-leakage storage capacitor (trench or stacked) built in a special process, so gigabit DRAM is a separate chip.
  3. Speed. SRAM reads differentially: BL and BLB start at VDD, the cell pulls one down, and a latch sense amplifier fires at about 0.1 V. With CBL = 100 fF and 40 µA of cell current that takes 100 fF × 0.1 V ÷ 40 µA = 0.25 ns. DRAM reads by charge sharing: the bitline starts at VDD/2 and moves only (VDD/2) × CS ÷ (CS + CBL), ±60 mV for 30 fF and 270 fF at 1.2 V, then the sense amplifier must amplify and restore before the row can close. Row cycles take tens of nanoseconds, so DRAM is slower per access.
  4. Sense amplifier design. SRAM: one sense amplifier per column multiplexer output, fired by a replica-timed SE, with precharge to VDD. DRAM: a latch sense amplifier on every bitline pair of the open row, precharge and equalise to VDD/2, very tight offset because the signal is only tens of millivolts, and it doubles as the restore circuit after the destructive read.
  5. Refresh. A DRAM bit leaks away in milliseconds. With 8192 rows per bank and tREF = 64 ms:
    one row every 64 ms ÷ 8192 = 7.8125 µs
128 row refreshes every millisecond, each blocking that bank for one row cycle
  6. Refresh takes bandwidth from normal accesses and energy even when the system is idle. SRAM never refreshes.
  7. Standby power. An SRAM cell leaks through its off transistors all the time, so a large SRAM has high standby leakage per bit. DRAM leaks very little per cell but pays refresh power. At 1 Mbit the SRAM leakage is acceptable; at 1 Gbit SRAM leakage and area would both be prohibitive.
  8. Evaluation:
    Need1 Mbit on chip1 Gbit main memory
    Speedcritical (cache): SRAMsecondary: DRAM is enough
    Densitysmall array: 6T affordablecritical: 1T1C
    Processmust match logic: SRAMseparate chip: DRAM
    Refreshunacceptable near the coreacceptable, scheduled by the controller
    Standbyleakage acceptable at this sizerefresh power acceptable
  9. Verdict: both choices are right. SRAM gives the on-chip store sub-nanosecond, refresh-free access in the logic process; DRAM gives the main memory about six times fewer transistors per bit and a gigabit at a sensible cost, paying with slower destructive reads and refresh. Check: 6 × 230 ÷ 230 = 6 transistors against 1 per bit.

Glossary

Array multiplier
A multiplier built as a regular two-dimensional array of AND gates and adders.
Baugh-Wooley
A two's complement array multiplication scheme using bit inversion and correction constants to keep the array regular.
Bitline
The column wire that carries the stored bit from the selected cell to the sense amplifier.
Block carry
A carry computed for a group of bits using that group's generate and propagate terms.
Booth encoding
Recoding the multiplier bits into signed digits so that fewer partial products are needed.
Carry look-ahead
Computing carries in parallel from generate and propagate signals instead of waiting for them to ripple.
Carry save adder
A structured full-adder array that reduces three numbers to two without resolving carries.
Carry select adder
An adder that precomputes sums for both possible carry inputs and selects one with a multiplexer.
Carry skip adder
An adder block that bypasses the carry straight to the next block when every bit only propagates.
Clock skew
The fixed difference in arrival time of the same clock edge at two registers.
Comparator
A circuit that reports whether two binary words are equal, or which one is larger.
Dadda multiplier
A multiplier that uses the minimum number of counters at each stage, at the cost of irregular wiring.
Decoder
A circuit that asserts exactly one of 2ⁿ outputs for each n-bit input code.
Flip-flop
An edge-triggered storage element that samples data only at a clock transition.
Half adder
A two-input circuit producing a sum bit a ⊕ b and a carry bit ab.
Latch
A level-sensitive storage element that is transparent for half the clock period.
Manchester carry chain
A dynamic chain of pass transistors that propagates or kills a carry along a block.
Metastability
The unresolved state a storage element may enter when its input changes inside the setup-hold window.
Muller C-element
A gate whose output follows its inputs only when they agree and holds otherwise; used to join handshakes in self-timed circuits.
Multiplexer
A selector that connects one of several inputs to a single output under select control.
Partial product
The shifted multiplicand row produced by one multiplier bit before the rows are summed.
Pipelining
Inserting registers into long logic so a new input can start every short clock period; raises throughput at the cost of latency.
Predecoder
A small decoder for a group of address bits whose outputs are combined by 2- or 3-input gates to drive each wordline.
Refresh
Periodic rewriting of DRAM cells to replace charge lost by leakage.
Ring oscillator
An odd number of inverters connected in a loop, oscillating at 1 ÷ (2N·tp).
Ripple carry
Passing the carry out of one adder stage into the next, so carries travel through the whole word.
Schmitt trigger
A switching circuit with two thresholds, whose hysteresis turns a slow or noisy input into one clean edge.
Sense amplifier
A small cross-coupled amplifier that resolves the weak bitline signal into a full logic level.
Wallace tree
A tree of 3:2 counters that reduces partial product rows to two in logarithmic depth.
Wordline
The row wire a decoder drives to connect a whole row of memory cells to their bitlines.
