6.1 Need for testing and manufacturing test principles

Every die leaving the fab is good or bad, and nothing outside says which. Test applies inputs, reads outputs and compares them with what a good chip should give, so bad chips are removed before a customer pays. Test costs a machine, a program and seconds per chip. This chapter covers defects and failures, the test floor, and the yield-and-coverage arithmetic that sets how many bad chips escape.

You need: only the picture of a fabricated wafer full of die from Unit 2, CMOS Fabrication and Layout.

From a physical defect to a customer failure

A wafer holds hundreds or thousands of die: some perfect, some dead, most in between. Test drives known values on the input pins, samples outputs on a stated clock, and compares each result with the value in the test program. A mismatch means the chip misses its specification.

Four words describe the chain from a speck of dust to a returned product.

TermWhat it isExample
DefectA physical flaw in the manufactured structureA dust particle breaks one metal wire, leaving it open
FaultThe logical behaviour of that defectThe broken wire acts like a node stuck at 0 (see 6.2)
ErrorA wrong value at a node at a particular timeThe adder drives 0110 where 0111 is expected
FailureLoss of the function the customer boughtThe phone screen stays black

One defect creates faults; a fault produces errors when the circuit is exercised; an error reaching an output pin becomes a failure the tester sees. Good test makes that happen in the factory, not in the field.

Verification simulates the design (Unit 5) and asks whether the logic is correct. Test measures a physical chip and asks whether this copy was built right. A design can pass every simulation and still fail on the tester, because the fab produced what the netlist never described: a short, an open, a missing contact. Verification catches design bugs; test catches manufacturing defects.

The test floor

ATE, automatic test equipment, is the machine: pin electronics that drive and sense every chip pin, a precise timing generator, programmable power supplies, and a computer running the test program.

  • DUT: the device under test, the chip being measured now.
  • Probe card: fine needles that land on bond pads, so die are tested before packaging.
  • Device interface board (DIB): plugs into the tester and routes its channels to the socket or probe card.
  • Handler: lifts packaged chips from a tray, presses each into a socket at set temperature, and drops it into a pass or fail bin.

A tester has more channels than one chip needs, so one program drives many die at once. In multi-site testing with s sites in parallel, the time charged per die falls by a factor of s.

test cost per die = (R × t) / s

R is the running cost of the tester in rupees per second (depreciation, power, floor space, operator); t is the test time for one die in seconds; s is the number of sites tested in parallel.

Four costs add up: the tester, charged per second; test time per die, from milliseconds for a small analog part to seconds for a large SoC; engineering cost of vectors, paid once per design; and overkill, the loss when a good die fails a marginal measurement.

Yield, fault coverage and defect level

Yield Y is the fraction of die on a wafer that meet specification. It falls as die area grows, because a random defect anywhere on a larger die kills it (Unit 2).

Fault coverage T is the fraction of listed faults that the vector set detects. The list comes from a fault model (6.2); T is measured by fault simulation (6.3). Some syllabi call it test coverage. No real program reaches T = 1.

DL = 1 − Y^(1−T)

DL is the defect level, the fraction of shipped parts that are actually bad; Y is the yield, a fraction between 0 and 1; T is the fault coverage, also between 0 and 1; the exponent is (1 − T).

DPM = DL × 10⁶

DPM is defective parts per million shipped; DL is the defect level as a fraction.

The formula treats surviving defects as independent and assumes the test detects a random fraction T of them, letting a fraction (1 − T) escape. Clustering makes the result an estimate, not a guarantee, but the shape is right: as T rises towards 1, the exponent (1 − T) shrinks and DL falls steeply.

Quality, reliability and the four test stages

Quality describes parts at shipping: how many are bad, in DPM. Reliability describes parts after shipping: how long they keep working, in FIT, failures per 10⁹ device-hours.

The failure rate follows the bathtub curve. Infant mortality is a high, falling failure rate in the first weeks, from weak oxide, bad vias and contamination. Useful life is a long, low, almost flat rate. Wear-out is a rising rate at end of life, from electromigration and oxide breakdown. Burn-in runs chips for hours at high temperature and raised voltage so infant mortality happens in the factory; retest then removes the dead.

  • Silicon debug: first silicon on a bench, hunting design bugs.
  • Characterisation: delay, power and margins across voltage and temperature corners, for the datasheet.
  • Production test: every chip, every lot, on the ATE.
  • Incoming inspection: the customer's sampling check on a received lot.

Worked example

Question. A wafer lot has yield Y = 0.90. The production test program has fault coverage T = 0.95. (a) Find the defect level in DPM. (b) Repeat for a program with T = 0.99. (c) By what factor does the number of shipped defective parts fall?

Python program.

def dl(Y, T):
    return 1 - Y ** (1 - T)

def dpm(Y, T):
    return dl(Y, T) * 1e6

Y = 0.90
for T in (0.95, 0.99):
    print(f"T={T:.2f}  DL={dl(Y, T):.6f}  DPM={dpm(Y, T):.0f}")
print(f"ratio = {dpm(Y, 0.95) / dpm(Y, 0.99):.2f}")
  1. Formula: DL = 1 − Y^(1−T), with Y = 0.90 and 1 − T = 0.05.
  2. ln 0.90 = −0.10536. Multiply: 0.05 × (−0.10536) = −0.005268.
  3. e^(−0.005268) = 0.994746, so DL = 1 − 0.994746 = 0.005254; DPM = 0.005254 × 10⁶ = 5254.
  4. For T = 0.99: 0.01 × (−0.10536) = −0.001054; e^(−0.001054) = 0.998947; DL = 0.001053, DPM = 1053.
  5. Ratio = 5254 / 1053 = 4.99.

Output

T=0.95  DL=0.005254  DPM=5254
T=0.99  DL=0.001053  DPM=1053
ratio = 4.99

Answer. About 5254 DPM at T = 0.95 and about 1053 DPM at T = 0.99, a fall by a factor of about 5.

Exam traps

  • Assuming 100 % fault coverage means zero escaped chips. No real vector set reaches T = 1, and T counts only the faults the model listed.
  • Swapping yield and fault coverage. Yield is a fab property (good die out of total); fault coverage is a test-program property (faults detected out of faults listed).
  • Confusing the chain: defect is physical, fault is logical, error is a wrong node value, failure is lost function at the output.
  • A unit slip in DPM. DL = 0.005 is 5000 DPM: multiply by 10⁶, not 10⁴.
  • A clean simulation run does not prove the silicon works. Simulation verifies the netlist; only the tester sees the manufactured chip.

6.2 Fault models: stuck-at and delay faults

A physical defect is a short, an open or a missing implant. There are too many shapes and sizes to test one by one, so test programs work on a small logical fault list. A fault model maps a defect onto a line stuck at 0 or 1, two bridged lines, or a path that is too slow. The stuck-at model is the workhorse; delay faults catch chips that compute the right value too late. Fault simulation and ATPG in <a href='#fault-simulation-and-test-pattern-generation'>6.3 depend on this list.

You need Boolean gates and truth tables (Unit 3) and gate-level Verilog modelling (Unit 5); the fault list built here is used by <a href='#fault-simulation-and-test-pattern-generation'>fault simulation and ATPG.

From physical defect to logical fault

A defect is physical: a metal short, an open contact, a missing implant, a thin oxide pinhole. A fault is the logical abstraction of that defect: for example, line A is stuck at logic 0. An error is a wrong signal value somewhere inside the circuit. A failure is a wrong value at an output pin during a test. A short from an input of a NAND gate to ground may behave like that input stuck at 0.

A defect has a size, a resistance and a location; its effect changes with all three. A fault model fixes the effect, not the cause. The single stuck-at model assumes one line is fixed at 0 or 1 while every other line works. The list is finite, so a program can enumerate it, generate vectors and report fault coverage.

Stuck-at faults, equivalence and collapsing

A line is a primary input, a primary output or a gate terminal. A line stuck-at-0 (SA0) always reads logic 0. A line stuck-at-1 (SA1) always reads logic 1. Single means only one line is faulty at a time.

NSA = 2 × L

NSA is the number of single stuck-at faults; L is the number of lines; the factor 2 is for SA0 and SA1.

Two faults are equivalent if no input vector can tell their faulty outputs apart. On a two-input NAND gate, A/0, B/0 and Z/1 all force the output to 1 for every input, so they form one equivalence class. A/1 and B/1 are not equivalent: A/1 changes the output only when B=1, and B/1 changes it only when A=1.

Fault collapsing keeps one fault per equivalence class. If every test for fault g also detects fault f, then f dominates g; drop f because testing g covers it. With fanout, a stem fault is equivalent to the multiple fault in which every fanout branch is stuck at the same value, so test programs place checkpoints on the fanout branches and do not count the stem again. A redundant fault has no vector that detects it; ATPG identifies such faults and they are excluded from the fault list before fault coverage is computed.

Transistor, bridge and delay faults

A transistor stuck open never conducts; a transistor stuck short always conducts. In static CMOS, a stuck-open may disconnect the output from the positive supply (VDD) or from ground for one input combination. The output then holds its old value on load capacitance. Detection may need two vectors: the first sets the output to 0, the second tries to drive it to 1. If the transistor is open, the output stays at 0.

A bridging fault shorts two lines. If one driver pulls 0 and the other pulls 1, the result depends on drive strength. It is often modelled as wired-AND (0 wins) or wired-OR (1 wins). A resistive bridge may pass logic tests but add delay.

A transition delay fault makes one line slow-to-rise or slow-to-fall. A path delay fault makes a whole input-to-output path too slow. The test uses a vector pair and two clock edges: the first vector sets the line to its initial value, the launch clock edge creates the transition, and the capture clock edge captures the response after the rated clock period. If the path is too slow, the captured value is the old one.

Worked example

Question. A two-input NAND gate has inputs A, B and output Z. (a) List every single stuck-at fault. (b) Collapse the faults into equivalence classes. (c) Give the smallest test set that detects at least one fault from every class. Write each vector as (A,B).

  1. The gate has three lines: A, B and Z. Number of single stuck-at faults is 2 × 3 = 6: A/0, A/1, B/0, B/1, Z/0, Z/1.
  2. Good NAND outputs for (A,B) = 00, 01, 10, 11 are 1, 1, 1, 0.
  3. A/0 forces A=0, so Z=1 for all B. It differs from the good gate only at 11. B/0 does the same. Z/1 also forces Z=1 for all inputs. So {A/0, B/0, Z/1} is one equivalence class.
  4. A/1 forces A=1. It differs only at (0,1), where good Z=1 but faulty Z=0. B/1 differs only at (1,0). They are separate classes.
  5. Z/0 forces Z=0. It differs at 00, 01 and 10. It is a separate class. Total classes: 4.
  6. Class {A/0,B/0,Z/1} needs vector 11. A/1 needs 01. B/1 needs 10. The set {01,10,11} covers all four classes with 3 vectors. 00 detects Z/0 alone, but 01 and 10 already detect Z/0, so 00 is not needed.

Answer. The 6 single stuck-at faults collapse to 4 equivalence classes, and the smallest test set is {01, 10, 11}, which has 3 vectors.

Exam traps

  • On a two-input NAND, Z/1 is equivalent to A/0 and B/0; it is not a separate class.
  • A/1 and B/1 are not equivalent on a NAND; each is detected only when the other input is 1.
  • Single stuck-at means one line at a time, not all lines at once.
  • A stuck-open in CMOS can escape a single-vector test; it often needs a two-vector sequence because the floating output keeps its old value.
  • A delay fault test needs a launch edge that creates the transition and a capture edge after the rated period; testing only the final logic value misses a slow path.

6.3 Fault simulation and test pattern generation

Fault simulation asks how many modelled faults a vector set catches. ATPG, automatic test pattern generation, asks the reverse: for one undetected fault, what input vector exposes it at an output? The two programs form a loop. Fault simulation measures coverage after each vector; ATPG adds vectors for faults still missed. The loop ends when coverage reaches a target or no testable fault remains. Every fabricated chip then receives the compact set, so a manufacturing defect shows up as a wrong output instead of being shipped.

You need: fault collapsing from 6.2 and gate-level simulation from Unit 5.

Fault simulation measures detection

A fault list is the collapsed set of modelled faults, such as line A stuck-at-0. Fault simulation applies one input vector to the good circuit and to every faulty circuit in the list. It records a fault as detected when at least one output differs between good and faulty machines.

The good circuit is simulated once. Faulty circuits can be simulated in parallel by packing 32 or 64 faults into the bits of a machine word. Deductive simulation evaluates good lines once and deduces faulty values. Concurrent simulation keeps an event list per fault. Speed matters because a large chip can have millions of collapsed faults and thousands of vectors.

C = (N_detected ÷ N_testable) × 100%

C is fault coverage in percent, N_detected is the number of testable faults detected by the current vector set, and N_testable is the number of faults in the collapsed testable fault list.

Report coverage after each vector. Vectors that add no new detection are dropped; this is test compaction. Vector ordering can also reduce tester time, but it does not change final coverage.

ATPG methods, from exhaustive to algorithmic

Exhaustive ATPG applies all 2ⁿ vectors for n inputs. It is complete but impossible beyond small n. Pseudo-exhaustive testing partitions the circuit and exhausts small subcircuits. Random ATPG applies pseudo-random vectors; weighted random biases inputs toward values that activate faults. Algorithmic ATPG works backward from one fault.

In the D-algorithm, D means 1 in the good machine and 0 in the faulty machine. D-bar is the reverse: 0 in good, 1 in faulty. A line carrying D or D-bar is sensitized.

  1. Fault activation: assign the faulty line the value that creates D or D-bar.
  2. D-propagation: push D or D-bar toward an output through gates whose side inputs allow it.
  3. Line justification: set the side inputs and primary inputs needed for each chosen gate.
  4. Conflict and backtracking: if two requirements contradict, undo the last choice and try another.

The D-frontier is the set of gates with a D or D-bar on an input but no D or D-bar on the output. The J-frontier is the set of gates whose output is known but whose inputs are not yet justified. PODEM works on primary inputs and needs fewer backtracks. FAN uses fanout-free regions and multiple backtracks per pass.

Redundant faults, compaction and vector ordering

A redundant fault has no test: no input vector makes its effect reach an output. A stuck-at line that is logically redundant is the common case. An untestable fault has no test for another reason, such as an input tied off or a blocked path. Coverage is measured against the testable fault list, because counting redundant faults can make a 100 % target impossible.

Test compaction removes vectors that detect no new fault. Run fault simulation after each removal to confirm no fault is lost. Vector ordering puts high-coverage vectors first, or sorts by current demand when the tester and power grid need it. Compaction cuts test time and tester memory; ordering cuts test execution time and supply noise, not coverage.

The ATPG loop in the figure is therefore iterative: simulate, check coverage, generate for the undetected list, add vectors, simulate again. Stop at the target or when only redundant and untestable faults remain.

Worked example

Question. Question (6 marks): The circuit is Z = A·(B + C), built as G1 = NAND(A,B), G2 = NAND(A,C), Z = NAND(G1,G2). Use the D-algorithm to find a test for the fault A stuck-at-0. Show activation, propagation, the D-frontier and the final vector. State the good and faulty values of Z.

  1. Activation: for A stuck-at-0, set A = 1 in the good machine; the faulty line is fixed at 0. This puts D on A (good 1, faulty 0).
  2. Propagate through G1 = NAND(A,B). Set B = 1 as a side input. Then G1 = NOT(A) for this input: good A=1 gives G1=0, faulty A=0 gives G1=1. So G1 carries D-bar (good 0, faulty 1).
  3. G2 = NAND(A,C). Choose C = 0. Then G2 = 1 in both machines, because NAND(x,0)=1. G2 does not block the D-bar; it is a constant 1 side input to the last gate.
  4. D-frontier: G1 now drives the Z gate with D-bar, while G2 is 1. Z = NAND(D-bar,1). In the good machine Z = NAND(0,1)=1; in the faulty machine Z = NAND(1,1)=0. So Z carries D.
  5. Vector: (A,B,C) = (1,1,0). No line justification conflict occurred, so no backtracking was needed. The output difference Z = 1 good, Z = 0 faulty detects A stuck-at-0.

Answer. The test is (A,B,C) = (1,1,0); it gives Z = 1 in the good machine and Z = 0 in the faulty machine, so the fault is detected.

Exam traps

  • Reading D as 'the fault is present at this line' without the convention D = good 1, faulty 0; D-bar is good 0, faulty 1.
  • Forgetting that a redundant fault has no test, so 100 % coverage of all faults may be impossible; report coverage against the testable list.
  • Confusing the D-frontier, which propagates a difference, with the J-frontier, which justifies known values.
  • Calling a vector a test because it activates a fault, without checking that an output differs between good and faulty machines.
  • Counting all vectors applied as coverage, instead of detected testable faults divided by total testable faults.

6.4 Design for testability and scan design

Scan design makes a sequential chip testable by turning its flip-flops into a long shift register during test. In normal mode each flip-flop takes its functional data input. In scan mode the same flip-flops are chained, so the tester can shift any pattern into every internal state bit, apply one functional clock cycle, and shift the captured result out. This separates setting internal nodes from observing them. Full scan is standard in digital ASICs and SoCs; partial scan is used where full scan costs too much area or delay. Some syllabi call it scan-path design or scan-based DFT.

You need: latch and flip-flop structures from Unit 4, especially the D flip-flop, and combinational ATPG from 6.3.

Why sequential circuits are hard

A combinational circuit is easy to test: apply a vector at the pins, wait for settling, compare outputs. A sequential circuit hides state. To set one internal flip-flop to 1, the tester may need a long sequence of input vectors, each clocked, and the effect must propagate through other state bits. This is the controllability problem: making an internal node take a chosen value from primary inputs. Observability is the reverse: making an internal node's value visible at a primary output. Both get worse as the number of state bits grows. A single stuck-at fault deep in a finite-state machine may need dozens of cycles to excite and propagate, and ATPG time can explode. Ad-hoc DFT attacks this directly: add test points, add extra pins, or disable feedback during test. These help a little but do not give a systematic method. Scan design changes the structure so the state is loaded and read directly.

Muxed-D scan cell and full scan

The standard scan cell adds a 2:1 multiplexer before each D flip-flop. The multiplexer inputs are the functional data D and the scan-in SI. The select line is scan enable SE. When SE = 0, the cell behaves as a normal flip-flop. When SE = 1, the cell takes SI. Connecting Q of one cell to SI of the next forms a shift register, called a scan chain. The figure shows one cell.

Full scan replaces every flip-flop with a scan cell. The circuit then has two modes. In functional mode it runs normally. In scan mode all state bits form one or more shift registers. A combinational ATPG program can treat the scan flip-flops as primary inputs and primary outputs, so it sees only the combinational logic between them. Partial scan converts only some flip-flops. It saves area and delay but leaves a residual sequential circuit, so pattern generation is harder.

Overheads: one multiplexer and extra routing per flip-flop; a small area increase; one extra gate delay on the functional path from D to the flip-flop; and global SE and scan clock nets that must be routed with care.

During shift, every cell launches and captures on the same clock edge. If clock skew between adjacent cells is large, a cell can capture the new value launched by the previous cell on the same clock edge instead of the old value. This is a hold-time race. Inserting a lock-up latch between chains, or between segments on different clocks, breaks the race. LSSD uses two non-overlapping clocks instead of a multiplexer; only a few universities teach it now. Some syllabi call this scan-based DFT.

Test procedure and cost

The tester runs a scan pattern in three phases. First, shift in: SE = 1 and the pattern is clocked into the chain one bit per cycle. Second, capture: SE = 0 and one functional clock cycle launches the circuit's response into the flip-flops. Third, shift out: SE = 1 and the captured bits are clocked out to the tester, which compares them with the expected response. The tester is an ATE, automatic test equipment.

In steady state, shift-out of one response and shift-in of the next pattern share the same N clock cycles. Under this simplified count, one pattern needs N shift cycles plus 1 capture cycle. Splitting into K equal chains reduces N to N/K, so time falls roughly by K, but each chain needs its own scan-in and scan-out pin.

T_pattern = (N + 1) × T_clk

T_pattern is the test time for one scan pattern; N is the number of flip-flops in the chain; the 1 is the capture cycle; T_clk is the scan clock period.

Worked example

Question. A design has 200 flip-flops in one scan chain, 50 primary inputs, and 1000 scan test patterns. The scan clock is 100 MHz and capture takes exactly 1 cycle. Using the convention that one pattern needs N shift cycles plus 1 capture cycle, find the time per pattern including capture and the total test time. Also state the shift time alone. Then split the chain into 4 chains of 50 and repeat.

  1. Clock period T = 1 / (100 MHz) = 10 ns.
  2. One chain: N = 200 flip-flops; cycles per pattern = 200 + 1 = 201 cycles.
  3. Shift time alone = 200 × 10 ns = 2000 ns = 2.00 µs. Time per pattern including capture = 201 × 10 ns = 2010 ns = 2.01 µs.
  4. Total cycles for 1000 patterns = 1000 × 201 = 201,000 cycles.
  5. Total time = 201,000 × 10 ns = 2,010,000 ns = 2.01 ms.
  6. Split into 4 chains: N2 = 200 / 4 = 50 flip-flops per chain; cycles per pattern = 50 + 1 = 51 cycles.
  7. Shift time alone = 50 × 10 ns = 500 ns = 0.50 µs. Time per pattern including capture = 51 × 10 ns = 510 ns = 0.51 µs.
  8. Total cycles = 1000 × 51 = 51,000 cycles; total time = 51,000 × 10 ns = 510,000 ns = 0.51 ms.
  9. Speedup = 2.01 ms / 0.51 ms = 3.94, about four times faster.

Answer. One chain takes 2.01 ms total; four chains of 50 take 0.51 ms total, nearly four times faster, at the cost of four scan-in and four scan-out pins. Shift time alone is 2.00 µs per pattern for one chain and 0.50 µs for four chains; including capture, the per-pattern times are 2.01 µs and 0.51 µs.

Exam traps

  • Scan makes ATPG easier and can reduce the number of capture patterns, but it adds N shift cycles per pattern, so total test time often rises.
  • SE polarity can be flipped in a question. Here SE = 0 means functional D and SE = 1 means scan-in SI; read the definition given.
  • Full scan removes sequential depth for ATPG, but it does not remove physical delay. Scan clock skew and hold-time races can still corrupt shifted data.
  • The scan multiplexer is on the functional D-to-Q path, so it adds area and delay. Partial scan trades testability for lower area and delay.
  • LSSD is not muxed-D scan. LSSD uses two non-overlapping clocks and no multiplexer in front of the flip-flop.

6.5 Boundary scan (JTAG)

Boundary scan puts a small test cell at every chip pin and a serial controller on the chip. A board full of chips can then be tested through four wires: TCK, TMS, TDI and TDO. The standard is IEEE 1149.1, usually called JTAG. It checks the wiring between chips, not the logic inside them. Board makers use it to find open and short printed-circuit-board (PCB) traces, and to program flash and FPGAs after soldering. The same port also gives a standard way to reach internal test structures.

You need: scan cells and shift-register behaviour from 6.4, and board and packaging ideas from 6.1.

The four mandatory pins

JTAG adds a Test Access Port (TAP) to the chip. Four pins are mandatory. TCK is the test clock. TMS is Test Mode Select; the TAP controller samples it on the rising edge of TCK. TDI is Test Data In. TDO is Test Data Out. TRST, an optional asynchronous reset, is not required. A boundary-scan cell sits at every digital I/O pin, between the chip's internal logic and the pad. In normal operation the cell is transparent: signal passes in and out. In test mode the cell can drive the pad from a stored bit, or capture the pad value into a flip-flop. All cells join into one long shift register, the boundary scan register (BSR), with one cell per pin.

Why at the pin? A chip's internal logic can be tested by scan (6.4) or BIST (6.6). The PCB trace from one chip pin to another has no access point after soldering. A bed of nails probe board is expensive and cannot reach fine-pitch ball-grid arrays. Boundary scan moves the probe to the pin itself. The tester shifts a pattern into the output cells, the chip drives the board traces, and the input cells capture what arrives. A mismatch shows a trace open, a short to a neighbour, or a wrong connection.

TAP controller and registers

The TAP controller is a 16-state finite state machine. It moves on each rising edge of TCK according to TMS. The important states are Test-Logic-Reset, Run-Test/Idle, Select-DR (data register), Capture-DR, Shift-DR, Update-DR, and the same four for the instruction register: Select-IR, Capture-IR, Shift-IR, Update-IR. Holding TMS high for five TCK cycles reaches Test-Logic-Reset from any state. That is the safety reset.

Inside are four registers. The instruction register (IR) holds the current instruction; its length is device-specific. The bypass register is one bit and shortens the chain when a device is not being tested. The IDCODE register returns a device identification number. The boundary scan register has one cell per I/O pin. The TAP controller connects the chosen data register between TDI and TDO during Shift-DR.

BYPASS, EXTEST and SAMPLE/PRELOAD are mandatory. BYPASS selects the 1-bit bypass register. EXTEST drives and observes the pins through the boundary cells; it is the board-interconnect test. SAMPLE/PRELOAD captures pin values without disturbing normal operation, and preloads the BSR before EXTEST. Most devices also provide IDCODE, which shifts out the device identity. The instruction in the IR decides which data register is connected.

Daisy chain on a board

On a board, devices are wired in a daisy chain. The board's TDI goes to the first device's TDI; its TDO goes to the next device's TDI; the last TDO is the board's TDO. TCK and TMS go to every device in parallel. So the board behaves as one long shift register. All TAP controllers see the same TMS, so they step through states together. The board's total instruction length is the sum of the device IR lengths; the total data length is the sum of the selected register lengths.

Lchain = Σ Li

Lchain is the total bits shifted in one Shift-DR or Shift-IR pass; Li is the length of the selected register in device i; the sum runs over the N devices in the chain.

Board test uses EXTEST. For each net, one device drives a 0 or 1 and another device captures the value. A short to VDD, GND or a neighbour changes the captured bit. An open leaves the input floating or stuck. The tester shifts out all captured bits and compares with the expected netlist. In-system programming reuses the same TAP: the FPGA or flash is put in programming mode and its configuration is shifted through TDI/TDO. One port can control many chips and can also reach internal scan chains (6.8).

Worked example

Question. A board carries three JTAG devices in a daisy chain. Their instruction registers are 4, 4 and 5 bits long; their boundary scan registers are 20, 20 and 30 cells; each bypass register is 1 bit. (a) How many TCK cycles are needed in Shift-IR to shift an EXTEST instruction into all three? (b) How many TCK cycles are needed in Shift-DR to pass one data bit through the board in BYPASS mode? (c) How many TCK cycles are needed in Shift-DR to shift a complete boundary-scan pattern through all three boundary scan registers?

  1. Instruction shift length = 4 + 4 + 5 = 13 bits. Shift-IR shifts one bit per TCK, so (a) is 13 cycles. Entry and update add control cycles but shift no instruction bits.
  2. Bypass chain length = 1 + 1 + 1 = 3 bits. (b) is 3 cycles.
  3. Boundary scan chain length = 20 + 20 + 30 = 70 cells. (c) is 70 cycles.

Answer. The chain needs 13 TCK cycles for the instruction shift, 3 cycles for one bypass bit, and 70 cycles for a full boundary-scan pattern.

Exam traps

  • Boundary scan tests board wiring and pin behaviour; it does not test the chip's internal logic. Internal logic needs scan or BIST.
  • The whole daisy chain is one shift register: instruction lengths add and data-register lengths add. Do not use one device's IR length for the board.
  • BYPASS shortens the chain; EXTEST drives and captures pins. They are different instructions.
  • SAMPLE/PRELOAD does not drive the board. It captures pin values and preloads boundary cells before a later EXTEST.
  • TCK and TMS are not data pins: TDI/TDO carry data, TMS controls state, TCK clocks both.

6.6 Built-in self-test (BIST)

An external tester drives every input and reads every output of a chip, and that machine costs money for every second it runs. Built-in self-test (BIST) moves the pattern generator and the response checker onto the chip itself. An on-chip LFSR makes pseudo-random vectors, a MISR squeezes the replies into a short signature, and one comparator against a stored golden value gives a single pass or fail bit. The chip tests itself at power-on, after packaging, or in the field, with almost no tester.

You need: scan design from 6.4, and flip-flops and shift registers from Unit 4.

The BIST loop and its parts

Built-in self-test (BIST) wraps three blocks around the circuit under test (CUT). The test pattern generator (TPG) makes the input vectors. The output response analyser (ORA) compresses the CUT outputs into one short signature. The BIST controller sequences the run: reset, load the seed, apply N vectors, stop, compare the signature, set pass or fail.

  • TPG: an LFSR, a binary counter, or a small on-chip ROM holding ATPG vectors.
  • CUT: combinational logic, a scan chain, or a memory array.
  • ORA: a MISR or a parity tree; the pass/fail flip-flop holds one bit for the tester to read.

There are two ways to deliver vectors. In test-per-clock the TPG drives the primary inputs and the flip-flop inputs directly, one vector per clock. In test-per-scan the TPG drives the scan-in input of each chain; L shift clocks push one vector into the chain, one capture clock loads the response, and the shifted-out bits go to the ORA. A vector therefore costs L + 1 clocks. Test-per-scan needs no extra pins but is slower.

T = N × (L + 1)

T = test time in clock cycles; N = number of test vectors; L = length of the longest scan chain in flip-flops; the extra 1 is the capture clock.

The LFSR as test pattern generator

A linear feedback shift register (LFSR) is a shift register whose serial input is the XOR of a few of its stages, called taps. With the right taps an n-bit LFSR visits every non-zero n-bit word once before repeating, and is then called maximal-length.

P = 2ⁿ − 1

P = period, the number of distinct states before the pattern repeats; n = number of LFSR stages (flip-flops). The single state left out is all zeros.

In the external-XOR (Fibonacci) form, XOR gates combine the tapped stages and drive the first stage, so the feedback passes through a chain of XORs. In the internal-XOR (Galois) form the XOR gates sit between stages, so the feedback passes through only one XOR per clock and the register can run faster; the trade-off is a less obvious tap table. The taps follow a primitive polynomial, and good tap tables exist for every n.

The all-zero word is a lockup state: the feedback of zeros is zero, so the register never leaves 000…0. The seed, the starting word, must therefore be non-zero. Different seeds give shifted copies of the same 2ⁿ − 1 states.

Some faults need a vector a plain LFSR rarely makes. A weighted LFSR gates each stage output with a control bit. ANDing the output with the control pushes the probability of a 1 below 0.5, so the stream carries many 0s — good for wide OR gates, which need all-zero inputs. ORing the output with the control pushes the probability of a 1 above 0.5 — good for wide AND gates, which need all-one inputs. Reseeding loads a fresh seed after every block of vectors so the patterns decorrelate.

Signature analysis and BIST flavours

A multiple-input signature register (MISR) is an n-bit LFSR with one extra XOR per stage: the CUT outputs are XORed into the feedback path at every clock. Every output bit mixes into every register bit, and after the last vector the register holds an n-bit signature. The comparator checks it against the golden signature, the value a fault-free simulation of the same design produces.

P(aliasing) ≈ 2⁻ⁿ

P(aliasing) = probability that a faulty CUT still ends with the golden signature; n = MISR width in bits. A 16-bit MISR gives about 1 in 65,536.

  • Exhaustive BIST: a counter applies all 2ᵐ vectors of an m-input block; fine only for small blocks.
  • Pseudo-exhaustive BIST: the circuit is partitioned so each output cone still sees all of its inputs.
  • Pseudo-random BIST: the LFSR stream, cheap and effective for most faults.
  • Deterministic BIST: ATPG vectors held in an on-chip ROM, or an LFSR reseeded to generate them.

A built-in logic block observer (BILBO) is one register with two jobs. In functional mode it is an ordinary register. In test mode the same flip-flops become an LFSR as TPG or a MISR as ORA, selected by control inputs that add XOR and multiplexer gates per stage. In a chain of blocks, the register after block A is the ORA for A and the TPG for B.

The price is area for the LFSR, MISR and controller, delay from the multiplexer at each flip-flop input, extra test time, and the need to resimulate the golden signature whenever the netlist changes. Aliasing means a pass is strong evidence, not proof.

Worked example

Question. A 4-bit LFSR shifts left every clock. Its feedback bit f = b3 ⊕ b0 enters at b0, where b3 is the leftmost bit and b0 the rightmost. (a) Seed the register with 0001, list the states until the pattern repeats, and give the period. (b) The same circuit feeds a 16-bit MISR. Give the aliasing probability as a fraction and as a decimal.

  1. Write the state as b3b2b1b0. The next state is b2b1b0f, with f = b3 ⊕ b0.
  2. 0001: f = 0 ⊕ 1 = 1, next state 0011.
  3. 0011: f = 0 ⊕ 1 = 1, next 0111. 0111: f = 0 ⊕ 1 = 1, next 1111. 1111: f = 1 ⊕ 1 = 0, next 1110.
  4. 1110: f = 1 ⊕ 0 = 1, next 1101. 1101: f = 1 ⊕ 1 = 0, next 1010. 1010: f = 1 ⊕ 0 = 1, next 0101. 0101: f = 0 ⊕ 1 = 1, next 1011.

  6. 0010: f = 0 ⊕ 0 = 0, next 0100. 0100: f = 0 ⊕ 0 = 0, next 1000. 1000: f = 1 ⊕ 0 = 1, next 0001, the seed again.
  7. Count: 0001, 0011, 0111, 1111, 1110, 1101, 1010, 0101, 1011, 0110, 1100, 1001, 0010, 0100, 1000. That is 15 distinct states, then repeat.
  8. Period check: 2⁴ − 1 = 15. The period matches, so the LFSR is maximal-length and generates each non-zero 4-bit vector exactly once.

Exam traps

  • BIST does not make ATPG unnecessary. Random vectors may never hit a random-pattern-resistant fault, so weighted or deterministic vectors still need fault simulation and ATPG.
  • The all-zero seed is a lockup for an XOR-feedback LFSR: the register sits at 000…0 forever. The seed must be non-zero.
  • Maximal length is 2ⁿ − 1, not 2ⁿ. The all-zero state is never reached, and counting it is a standard mark-losing slip.
  • Aliasing: a faulty circuit can produce the golden signature. A BIST pass means the signature matched, not that the chip has zero defects.
  • A MISR only compresses. It cannot tell you which output was wrong, and the golden signature must come from simulating this exact netlist, not from another chip.

6.7 Memory testing and memory fault models

Memory arrays fail in ways logic does not. A cell can disturb its neighbour, a row can fail to switch, and the address decoder can select no cell, two cells, or the wrong cell. A vector set built for stuck-at faults in random logic misses these. Memories are therefore tested with ordered read/write sequences called march algorithms. The same tests run at wafer sort, final test, and inside the chip through memory BIST.

You need SRAM and DRAM cell structure and decoders from Unit 4, and stuck-at and coupling ideas from 6.2.

Fault models the tester must excite

A memory is not a bag of independent bits when it is tested. The tester sees five blocks: the address decoder, the cell array, the sense amplifiers, the write drivers, and the read/write control. A defect in any block produces a pattern that a plain stuck-at vector set misses. The cell array is a grid, so a write to one cell can disturb a neighbour. The decoder is a tree of gates, so a bad address can open no row, two rows, or the wrong row.

March tests and their length

Let n be the number of words in the memory. A march test is a sequence of march elements. Each element has a direction and one or more operations. The symbol ⇑ means ascending address order; ⇓ means descending. w0 writes 0. r1 reads and expects 1; a mismatch is a fail. r0 reads and expects 0.

A 1 Mb array at 4n² is too slow for production, so O(n²) tests are used on small arrays or for diagnosis. March C− covers stuck-at, transition, coupling, and address decoder faults in 10n accesses.

Memory BIST and the logic around the array

Memory BIST puts the test engine on chip. The controller has five parts: an algorithm sequencer that stores the march elements, an address counter that counts up or down, a data generator for writes and expected reads, a comparator, and a multiplexer that switches the array from functional logic to BIST mode.

  1. Sequencer selects the next march element and its direction.
  2. Address counter sweeps all addresses.
  3. Data generator drives w0 or w1 and supplies expected data.
  4. Comparator checks each read and sets pass or fail.
  5. Multiplexer returns the array to functional mode.

The logic around the array needs its own vectors. Address wrap logic, data wrap logic, byte enables, and ECC can hide a cell fault. BIST must test through that logic or mux it out. Algorithmic optimisation chooses a march variant that covers the same fault list with fewer operations; MATS+ is 5n but weaker, March C− is 10n and stronger.

Worked example

Question. A 1024-word embedded SRAM is tested with March C−. March C− has six elements: M0 ⇑w0, M1 ⇑r0w1, M2 ⇓r1w0, M3 ⇑r0w1, M4 ⇓r1w0, M5 ⇑r0. Count the operations per cell and the total accesses. At 5 ns per access, find the test time. Compare with GALPAT, which needs about 4n² accesses.

  1. Count operations per cell: M0=1, M1=2, M2=2, M3=2, M4=2, M5=1. Sum = 10.
  2. Total accesses = 10 × 1024 = 10,240.
  3. Test time = 10,240 × 5 ns = 51,200 ns = 51.2 µs.
  4. GALPAT accesses = 4 × 1024² = 4,194,304.
  5. GALPAT time = 4,194,304 × 5 ns = 20,971,520 ns = 20.97152 ms.
  6. Ratio = 4,194,304 ÷ 10,240 = 409.6, about 400 times longer.

Answer. March C− needs 10,240 accesses and 51.2 µs; GALPAT needs 4,194,304 accesses and 20.97152 ms, about 409.6 times longer, so the march test is the production choice.

Exam traps

  • Treating a memory as a set of independent stuck-at cells. Without ordered writes and reads in both directions, transition and coupling faults are never excited, and address decoder faults need the ascending and descending passes.
  • Confusing 10n with 10n². March C− is linear in n. Only walking and GALPAT are quadratic.
  • Forgetting that r1 means read and expect 1, not write 1. w and r are different operations.
  • Assuming BIST tests the array alone. Address wrap logic, data wrap logic, byte enables, and ECC must be included or muxed out.

Not for the exam. Production memories add ECC and repair: a BIST pass can fuse in spare rows or columns. Automotive and medical chips run memory BIST at every power-up because latent faults matter. 3D stacked DRAM and in-memory computing make coupling and thermal patterns harder to model. 6.8 Chip-level and system-level test techniques

A chip is tested many times: on the wafer, after packaging, after soldering to a board, and as a finished product. Each level uses a different fixture, catches a different fault class, and costs more than the one before. Planning what to test where — including reaching cores inside an SoC on a small pin budget — is chip-level and system-level test.

You need: test economics from 6.1, scan from 6.4 and boundary scan from 6.5.

Four levels, four questions

The same silicon is tested at every move from wafer to product. Each level answers a different question, so a fault that slips past one level must be caught later.

  • Wafer sort. A probe card touches every die on the wafer. It runs DC checks, scan vectors and memory march tests at low speed, records a wafer map, and bad die are not packaged.
  • Package test (final test). After dicing and assembly, the part runs the full vector set at speed and at hot and cold temperature. It catches bond-wire, assembly and speed failures a probe cannot measure.
  • Board test. After soldering, checks solder bridges, open tracks, missing or rotated components. In-circuit test and boundary scan do this work.
  • System test. The finished product runs its own software and must work as a product, not as a chip.

Cost per failure rises steeply. A fault caught at wafer sort costs one die. The same fault caught at system test costs a die, a package, a board, surrounding components, and labour.

Why earlier tests are cheaper

Compare testing every die at wafer sort with packaging everything.

C_good = (N × c_w + N_p × c_p) ÷ N_good

C_good is test and package cost per good die shipped (₹); N is die on the wafer; c_w is wafer-sort cost per die (₹6); N_p is die reaching packaging; c_p is packaging cost per die (₹80); N_good is good die that ship (800).

Wafer sort is cheap per die and packaging is expensive per die, so killing a bad die before packaging throws away only the cheap step.

  • Known-good-die (KGD). A die sold unpackaged into a multi-chip module must be proved good before bonding; one bad die loses the whole module.
  • Multi-site test. The tester contacts many die at once, lowering c_w but needing more tester channels.
  • Burn-in. Parts run for hours at raised voltage and temperature to burn out early-life failures no vector set can find.

Testing a core-based SoC

An SoC is built from bought-in IP blocks: a CPU core, a memory controller, a USB block. Each has its own test set and wrapper. The chip-level problem is delivering those test sets through a pin budget smaller than the sum of core needs.

  1. Wrapper. A ring of cells around the core. In test mode it isolates the core, feeds vectors and captures responses. IEEE 1500 standardises this core wrapper and its serial control.
  2. Test access mechanism (TAM). On-chip wires carrying vectors from chip pins to wrappers. Width w bits delivers w bits per cycle.
  3. Test scheduling. Decides which cores are tested together and in what order. Cores share the TAM only if their combined widths fit in w.
  4. Serial control. One IEEE 1149.1 TAP port drives the wrappers; its state machine is in 6.5.

T_core = (P × L) ÷ w

T_core is test time for one core in cycles; P is number of patterns; L is cycles per pattern; w is TAM width in bits given to that core.

Splitting a TAM never shortens total time by itself: serial testing at full width and balanced parallel testing give the same cycle count. Sharing pays when a core cannot use the full width, or when a power budget forbids testing all cores at once.

Only a few universities teach TAM partitioning in detail; in practice the wrapper and schedule are fixed by the IP vendor and test engineer together.

Board test and system test

In-circuit test (ICT) presses a bed of nails onto every net and measures each component. It is fast and thorough, but the fixture is expensive and built for one board. A flying probe moves a few needles over the board: no fixture, slower, good for prototypes.

Boundary scan replaces most nails. In interconnect test, a cell on one chip drives a track and a cell on another reads it, so an open or short between two pins is caught without physical access. The same four-wire port also loads chip-level tests.

System test is software driven: boot the product, run the application, exercise the interfaces. It is the only level testing the whole product, so it is the last place an escape can be caught — and the most expensive to debug.

Two practical limits shape this. Test compression packs scan vectors so a small pin count carries a huge pattern set. Pin count is money: every extra tester channel costs, so schedules fit the tester, not the reverse.

Question. An SoC has one core whose test set is 4000 patterns and 200 cycles per pattern. The chip TAM is 8 bits wide. Find the core's test time in cycles with the full TAM, and when it shares the TAM equally with a second core of the same size.

  1. Full TAM (w = 8): T = (P × L) ÷ w = (4000 × 200) ÷ 8 = 800,000 ÷ 8 = 100,000 cycles.
  2. Shared equally (w = 4 each): T = 800,000 ÷ 4 = 200,000 cycles for each core.

Answer. 100,000 cycles with the full 8-bit TAM and 200,000 cycles per core when the TAM is split 4 and 4 — the same total time either way for these two equal cores.

Exam traps

  • Comparing test cost per die instead of cost per good die shipped. The correct denominator is good parts leaving the line.
  • Forgetting that one die is tested at several levels, so total test cost is the sum over all levels.
  • Assuming wafer sort replaces final test. Package faults and speed failures only appear after assembly.
  • Mixing up scan (chip-level DFT) with boundary scan (board-level interconnect). They use different hardware and catch different faults.
  • Treating tester pins or TAM width as free. Every channel costs money and every wire costs area, so schedules fit a fixed budget.

6.9 Analog and mixed-signal testing

Analog and mixed-signal blocks — amplifiers, filters, data converters, phase-locked loops — have no truth table and no clean stuck-at fault model. Their outputs are continuous, so a chip is judged by measuring specifications and comparing each result with a tolerance window. Digital test methods do not carry over: analog nodes are few, every measurement has noise, and test cost per pin is high. Hard faults are catastrophic; soft parametric faults pass a simple check but fail a specification. Structural tests such as IDDQ, oscillation and loopback give fast checks, while DNL, INL, SNR and ENOB describe converters. Every chip with an ADC, DAC or radio needs this test.

You need: test economics from 6.1; specification-based thinking from 6.8; converter circuits from an analog course.

Why digital test methods stop at the analog boundary

Digital circuits have finite values and a stuck-at fault model, so ATPG can target a specific fault (see 6.2 and 6.3). An analog node can sit at any voltage or current. Its correct value is a range: gain 10 ± 0.2, offset below 5 mV, output noise below 1 mV rms. Measurement noise and tester error eat part of that window. Few internal nodes are brought out because a probe adds capacitance and changes the circuit. Analog test cost per pin is high, and on a mixed-signal SoC it can dominate total test cost.

Faults are split into two classes. A hard fault is catastrophic: an open, a short, a stuck component. A soft fault or parametric fault is a drift: a resistor moves 20 %, a transistor loses gain, a capacitor leaks. The block may still pass a simple functional check but fail a specification. Soft faults are why analog test measures specifications, not just connectivity.

Structural tests give a quick check. IDDQ measures the quiescent supply current after the block settles; a short or bridge raises it. Oscillation test reconfigures the block as an oscillator; the frequency depends on component values, so a shift points to a fault. Loopback sends a digital pattern through a DAC, an analog path and an ADC, then compares the returned code with a tolerance (Figure).

Converter specifications and their measurement

Let an N-bit ADC have full-scale range FSR. One least significant bit is 1 LSB = FSR / 2^N. Offset error is the output at zero input, in LSB. Gain error is the slope error after offset is removed. DNL of code k is DNL_k = W_k / (1 LSB) − 1, where W_k is the measured width of code k. INL is the running sum INL_k = Σ DNL_i, the deviation from the ideal straight line. DNL = −1 LSB means W_k = 0: a missing code. SNR = signal power ÷ noise power, with harmonics excluded. SINAD = signal power ÷ (noise + distortion) power. Ideal SNR for a full-scale sine with ideal quantization = 6.02N + 1.76 dB. ENOB = (SINAD_measured − 1.76) / 6.02. Data sheets often label the SINAD column as SINAD or SNR+THD.

The servo ramp method slowly settles each code and records transition voltages; it is accurate but slow. The ramp histogram applies a linear ramp and counts hits per code; width is proportional to count, so DNL and INL come from counters. Sine-fit and FFT apply a pure sine, fit the ideal sine, subtract it, and transform the residue to the frequency domain; this gives SNR, THD and ENOB. Histogram and FFT methods are standard production tests.

Design for testability for analog blocks

Analog DFT adds access and control. Test points bring internal nodes to pins through unity-gain buffers, so the probe does not load the node. Bypass switches isolate a block: a filter can be switched out so the ADC is tested alone. Loopback is the mixed-signal workhorse: digital pattern → on-chip DAC → analog path (filter, amplifier) → on-chip ADC → compare with tolerance. It catches opens, shorts, gross gain loss and filter shifts. It cannot catch every fault: a DAC gain error and an ADC gain error of opposite sign can cancel in the digital code.

On-chip measurement puts a peak detector, RMS detector or small ADC near the block, so the external tester reads a digital number. This is analog BIST. IEEE 1149.4 is the analog companion of boundary scan: analog test cells at pins connect the pin to a two-line analog test bus, AT1/AT2, so an external instrument can force a voltage or current at the pin and measure the response. Only a few universities teach it; it helps board-level analog interconnect test.

Worked example

Question. An 8-bit ADC has full-scale range 2.56 V. A ramp histogram gives measured code widths W64 = 14 mV and W65 = 6 mV. Take INL(63) = 0 LSB. (a) Find 1 LSB. (b) Find DNL at codes 64 and 65. (c) Find INL at codes 64 and 65. (d) A third code has measured width 0 mV; state its DNL and what it means.

  1. Number of codes = 2^8 = 256. 1 LSB = FSR / 2^N = 2.56 V / 256 = 0.010 V = 10 mV.
  2. DNL(64) = W64 / (1 LSB) − 1 = 14 mV / 10 mV − 1 = 1.4 − 1 = +0.4 LSB.
  3. DNL(65) = W65 / (1 LSB) − 1 = 6 mV / 10 mV − 1 = 0.6 − 1 = −0.4 LSB.
  4. INL(64) = INL(63) + DNL(64) = 0 + 0.4 = +0.4 LSB.
  5. INL(65) = INL(64) + DNL(65) = 0.4 − 0.4 = 0.0 LSB.
  6. For measured width 0 mV: DNL = 0 mV / 10 mV − 1 = −1 LSB. The code never appears, so it is a missing code. INL at that code = INL(previous code) − 1 LSB. It is near zero only when INL before the code is about +1.0 LSB; otherwise the missing code shows up as a 1 LSB drop in the INL curve at that point.

Answer. 1 LSB = 10 mV; DNL(64) = +0.4 LSB, DNL(65) = −0.4 LSB; INL(64) = +0.4 LSB, INL(65) = 0.0 LSB; a 0 mV code has DNL = −1 LSB and is missing; INL at it is INL(previous) − 1 LSB.

Exam traps

  • DNL is not INL. DNL is the error of one code width; INL is the running sum of DNL. A large DNL can leave INL near zero if the next code has opposite DNL.
  • A missing code has DNL = −1 LSB, not INL = −1 LSB. INL at that code falls by 1 LSB from the previous code's INL. It looks near zero only if INL before it is about +1.0 LSB; check DNL from the histogram separately.
  • DNL and INL are defined after offset and gain errors are removed. A tilted transfer curve is gain error, not a large INL.
  • 1 LSB is FSR / 2^N for an N-bit converter with 2^N codes; do not divide by 2^N − 1 unless the data sheet defines FSR that way.
  • SNR is measured with a near-full-scale sine, not with a DC input; a DC test says nothing about noise and distortion.

Analyze A code has DNL = −1 LSB but INL = 0.0 LSB at that code. Explain how this is possible. 5 marks

The code is missing. If INL before it is +1.0 LSB, adding DNL = −1 LSB returns INL to 0.0 LSB. The running sum hides the missing code, so DNL from a histogram must be checked separately.

Analyze Why can a loopback test miss a gain error in the DAC or ADC? 5 marks

Loopback compares the final digital code with the input pattern. If the DAC output is too high and the ADC also reads high by the same fraction, the two gain errors cancel in the digital code. The test then passes inside its tolerance even though each block is out of specification.

Understand What does IEEE 1149.4 add to boundary scan? 3 marks

It adds an analog test bus with two lines, AT1 and AT2, and analog test cells at pins. A cell connects the pin to the bus, so an external instrument can force a voltage or current at the pin and measure the analog response. This helps analog interconnect and some board-level analog tests.
