## Reviewer notes (after any revision)

- ch 1 [high] Section 3, comparison and spaceship bullets: The operators < and <= have disappeared from the comparison list, leaving a broken line ("!==, , >, , >=, ."), and the spaceship bullet reads "$a  $b" with the operator missing. A student reading this cannot see which operator does less-than, less-than-or-equal, or the spaceship comparison.
- ch 1 [low] Section 2, paragraph on type juggling: The paragraph calls a variable changing type on reassignment "type juggling". In standard usage type juggling is the automatic conversion of a value inside an expression (for example "250" * 2 giving 500); a variable holding a new type after a new assignment is just loose typing / dynamic typing.
- ch 1 [low] Exam traps, first trap: "\"Pay: \" + 885 is arithmetic" is loose: in PHP 8 this expression does not quietly add — a non-numeric string operand throws a TypeError (in PHP 7 it gave 885 with a warning). The trap should state what actually happens.
- ch 2 [low] Section 1, paragraph 2: PDO is described as if it alone connects to MySQL. PDO is a uniform access layer; it needs a driver (pdo_mysql) before it can reach MySQL, so a student may think installing PDO is enough.
- ch 2 [low] Section 3, WAR paragraph: "Tomcat unpacks it on start" is only the copy-before-start case. With the default autoDeploy setting, a WAR copied while Tomcat is running is also deployed and exploded without a restart, so the sentence can mislead a student debugging a live server.
- ch 2 [low] Section 2, hosts file sentence: "localhost is a name for the loopback address 127.0.0.1" is incomplete: on machines with IPv6 the hosts file usually also maps localhost to ::1, which is why a server bound only to 127.0.0.1 can refuse a localhost connection.
- ch 2 [low] Quiz Q2: "on the same machine address" is vague; students may read "machine" as the whole computer rather than one IP address.
- ch 2 [low] Worked example, step 3: The step says to change Apache's Listen port but never states that the new port must then appear in every Apache URL, which is the mistake students actually make after the fix.
- ch 3 [low] Section 2, infinite loops: "A loop that never changes its condition is infinite" is misleading: the condition text ($i <= 5) never changes; what must change is the variable inside it. A student may read this as "the condition must be rewritten each pass".
- ch 3 [low] Section 2, max_execution_time: The sentence "PHP stops at max_execution_time" is only true for web requests. Under the command line, max_execution_time defaults to 0, meaning no time limit, so a student testing an infinite loop in the terminal sees it run forever.
- ch 3 [low] Section 2, foreach by reference: "Remove the & after the loop" is not an operation a student can perform; the & lives in the foreach header. The leftover reference is removed by unsetting the loop variable, as the trap later says.
- ch 3 [low] Section 2, foreach description: "It visits each key => value pair once" is stated before the two forms are introduced, so a beginner reading foreach ($a as $v) may expect a key to be available. The plain form gives values only.
- ch 3 [low] Worked example 1, output: The code ends with echo "\n"; but the shown output has no note that a newline character sent to a browser does not create a visible line break; students may expect a blank line on the page.
- ch 4 [high] Section 1, htmlspecialchars bullet: The list of escaped characters has a hole: it reads "turns &, , >, " and '" — the less-than sign is missing, so a student cannot tell that < is escaped (it was probably swallowed as an HTML tag).
- ch 4 [high] Section 1, nl2br bullet: "nl2br($s) inserts  before newlines" — the inserted text is missing, so the sentence states nothing.
- ch 4 [high] Quiz Q2 answer: The answer reads "User text may contain , > or &" — the < character is missing from the list, which is the very character that matters for script injection.
- ch 4 [high] Section 2, paragraph on quoting patterns: "In a double-quoted string, \d may be read as an escape, so you need extra backslashes" is wrong for \d. PHP only interprets known escapes (\n, \t, \\, \$, \", octal \1, \x, \u); an unknown sequence such as \d or \s is kept literally, backslash included. The real danger in double quotes is \1 (turned into an octal character) and a doubled backslash.
- ch 4 [low] Section 1, trim bullet: trim is described as removing "spaces and newlines", but its default character list also covers tabs, carriage returns, NUL and vertical tab; a student meeting a tab-padded value may think trim fails.
- ch 5 [high] Exam traps, bullet 2, and Quiz Q5 (question and answer): The example XSS value is given as alert(1). A bare text value alert(1) printed inside HTML does nothing — it is not script, so the stated output ('the browser runs it as script') is wrong. A student would learn the wrong payload and the wrong reason for escaping.
- ch 5 [low] Section 2, third paragraph: filter_input(INPUT_POST, 'marks', FILTER_VALIDATE_INT) is said to return an integer or false. - ch 5 [low] Section 2, second paragraph, and Exam traps, bullet 1: The text says $_REQUEST merges GET, POST and cookies and that 'a cookie can override a form field'. The merge order actually comes from the request_order setting, and in the standard php.ini files request_order is 'GP', so cookies are normally not in $_REQUEST at all; the clash is usually GET overriding POST.
- ch 5 [low] Section 1, third paragraph: Idempotent is defined as 'repeating the same GET should not change data'. That is the definition of a safe method. Idempotent means repeating the request has the same effect on the server as sending it once.
- ch 5 [low] Figure (sequence spec) and its caption: The figure shows the GET returning '200 HTML Anu scored 78', but the script in Worked example 1 only processes POST; on a GET it returns the form. - ch 5 [low] Section 3, last paragraph, and Quiz Q2 answer: The text explains why GET is bad for a password but never says that a POST body is also readable on the wire unless the connection is HTTPS. A reader can conclude that POST alone makes a password safe.
- ch 6 [high] Section 1, setcookie formula: The formula lists samesite as an eighth positional argument: setcookie(name, value, expires, path, domain, secure, httponly, samesite). PHP's setcookie() takes only seven positional parameters. SameSite has no positional slot; it can be set only through the options array (PHP 7.3 and later). A student who copies the formula with eight arguments gets an ArgumentCountError / 'expects at most 7 parameters' warning and the cookie is not set.
- ch 6 [high] Worked example 1, step 6 and answer: The text says 'After 30 idle minutes the browser deletes the cookie because Max-Age has passed' and 'after 1800 idle seconds the cookie is gone'. Max-Age is an absolute lifetime counted from the moment the response is received, not an idle timeout. The cookie disappears 1800 seconds after login even if Anu keeps clicking every minute. Only the server-side session file is removed on inactivity (gc_maxlifetime); the cookie is not.
- ch 6 [low] Worked example 1, output line: The 'output:' line prints the Set-Cookie header, but the script's actual printed output is 'Session abc123 saved for Anu'. The header is not echo output, so a student reading 'output' may confuse headers with response body.

- ch 6 [low] Section 3, secure flag bullet: 'secure = true sends the cookie only over HTTPS, so it is not readable on public Wi-Fi' gives the wrong reason. Secure does not make the cookie unreadable; it stops the browser from ever putting the cookie on a plain-HTTP request, which is what a Wi-Fi sniffer could capture.
