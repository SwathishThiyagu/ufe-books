## Reviewer notes (after any revision)

- ch 1 [high] Section 3 (8086 address decode): The 8086 half of the section treats the 8255 as if it had a full 8-bit address bus: it says A1 and A0 of the CPU go to the 8255 and that base 80H gives the block 80H-83H. On an 8086 the data bus is 16 bits wide, so the 8255 (a byte-wide device) sits on one byte lane only. If its D0-D7 connect to CPU D0-D7, CPU A0 cannot go to the 8255; the 8255's A0 and A1 must connect to CPU A1 and A2 (CPU A0 left unused or used to force even addresses). The registers then appear at 80H, 82H, 84H, 86H, not 80H-83H. The earlier generic statement in Section 1 is fine for an 8-bit bus; the 8086 paragraph is not.
- ch 1 [low] Section 2 (mode 0 description): "Mode 0 is simple input or output: the CPU reads or writes the port and the pin holds the level" suggests that input is latched, which it is not. Students then look for a latch on the input side.
- ch 1 [low] Section 3 (fan-out sentence): "One output can drive a few TTL inputs" is loose. The port pin sinks about 1.6-1.7 mA, which is roughly one standard TTL input (1.6 mA), not several. Several inputs are possible only with low-power Schottky (LS) TTL, which needs about 0.4 mA each.
- ch 1 [low] Beyond: "The CMOS 82C55 and pin-compatible GPIO expanders such as the MCP23017 over I2C" can be read as saying the MCP23017 is pin-compatible with the 8255, which it is not; only the 82C55 is pin-compatible.
- ch 1 [low] Figure (block diagram edges): The data bus buffer node has no outgoing edge. The control word and port data travel from the buffer to the group A/B control blocks and to the ports on the internal data bus, but the diagram shows only the read/write logic driving the control blocks, so a student cannot see how the control word reaches the ports.
- ch 2 [high] Section 3 (8254 status byte): The status byte is said to show 'whether the count is latched'. The status byte has an OUT-pin bit, a NULL COUNT bit, the RW1 RW0 bits, the M2 M1 M0 bits and the BCD bit. The NULL COUNT bit reports whether a count written by the CPU has been loaded into the counting element, not whether the count is latched.
- ch 2 [low] Worked example 1: 'Produce a 1 ms delay in mode 2' conflicts with the exam trap that mode 2 is a repeating rate generator, not a one-shot delay. The wording invites the mistake the trap warns against.
- ch 2 [low] Section 1 (formula lead-in): 'The division is:' introduces a multiplication, which reads as a slip.
- ch 2 [low] Section 1 and Exam traps (count 0): 'A loaded count of 0 means 65536' is true only in binary counting. In BCD counting a loaded 0 means 10000, so the sentence sits too close to the BCD bit and can mislead.
- ch 2 [low] Section 2 (mode 3 line and table row): 'High for half the count; low for half the count' is exact only for even counts. For odd N the high time is (N+1)/2 clocks and the low time is (N−1)/2 clocks.
- ch 3 [low] Section 3, bullets 3 and 4: Bullet 3 says the resolver sets ISR bit 3 and then raises INT, while bullet 4 says the in-service bit is set when the first INTA arrives. A student cannot tell which is correct. The ISR bit is set on the first INTA pulse, not when INT is raised.
- ch 3 [low] Section 3, last paragraph: 'provided both lines are unmasked and IR6 is not blocked by a lower-priority ISR bit' is confusing and wrong in its condition. A lower-priority in-service bit never blocks a higher-priority request; it is a higher-priority in-service line that would block IR6.
- ch 3 [low] Section 2, ICW1 bullet: The bullet says D2 sets the 8085 call address interval to 4 or 8 bytes but does not say which value gives which interval, so a student cannot decode ICW1 D2=0.
- ch 4 [high] Section 3, first sentence: The 8237 is called 'the 16-bit successor'. The 8237 is an 8-bit DMA controller: its data path is 8 bits, only its address and count registers are 16 bits. A student will write '8237 is a 16-bit DMA controller' in the exam and lose marks. The 8257 also has 16-bit address and count registers, so '16-bit' is not what separates the two chips.
- ch 4 [high] Section 2, paragraph on the mode word: Verify is given as an 8257 transfer type ('memory read, memory write or verify, where verify moves no data'). Verify is a transfer type of the 8237 mode register (transfer-type field 00 = verify, 01 = write, 10 = read); it generates addresses and timing but no MEMR/MEMW/IOR/IOW. The 8257 does not have a verify transfer type.
- ch 4 [high] Quiz Q8 and its answer: The question says the transfer fails, but with base address 3F00H and count 07FFH it does not. The block runs 3F00H to 46FFH, which never reaches FFFFH, so the 16-bit counter never wraps, whatever the page register holds. The answer itself admits this ('it crosses no boundary') and then contradicts the question. The page register value does not move the wrap point either; the wrap always happens at offset FFFFH.
- ch 4 [low] Exam traps, third bullet: The trap example 'a 2 KB block starting at 3F00H cannot cross FFFFH' uses numbers that do not cross anything (3F00H + 2 KB ends at 46FFH). A student will wonder what the fuss is about and may think 3F00H is a dangerous start address.
- ch 4 [low] Section 3, page-register paragraph: 'The 8237 drives only A0-A15' is loose. The chip itself outputs A0-A7 only; A8-A15 come from an external latch strobed by ADSTB/AEN, and A16-A19 come from the separate page register. A student drawing the schematic will miss the A8-A15 latch.
- ch 4 [low] Section 3, register list and Section 4 last bullet: 'count up or down' and 'the chip increments and decrements' suggest the count can count up. In the 8237 the address counter can increment or decrement (mode register bit 5); the count always decrements.
- ch 4 [low] Worked example 1, output line: The question asks three things: bytes moved, last address, and what happens on the final transfer. The output shows 4096, 12287 and 4, where 4 is the block size in KB. The final-transfer event (TC pulse, channel disabled or reloaded) is never shown in the output.
- ch 4 [low] Exam traps, second bullet: The line '16385... no: 16384 bytes' reads like a typo left in the text. In an exam-trap list the wrong value should not appear as if it were an option.
- ch 5 [high] Quiz Q4: The status combination TXRDY=0 and TXE=1 is impossible on the 8251: TXE=1 (transmitter empty) means the transmit shift register and buffer are both empty, so TXRDY must be 1. The answer treats TXRDY=0 as 'the transmit buffer still holds a byte', which contradicts the chip's behaviour.
- ch 5 [low] Section 1, clock inputs: The sentence says 'in async mode TXC is 1, 16 or 64 times the baud rate' but omits that RXC must also be 1, 16 or 64 times the baud rate.
- ch 6 [low] Worked example 1, steps 4-5 and answer: The example is a multiplexed display at 1/4 duty, but step 4 picks the resistor for 8 mA with no statement of whether that is peak or average. Section 2 and the exam traps say a 1/4-duty segment needs about 4× the steady current, so a 390 Ω resistor here gives roughly 2 mA average and a dim display. A student reads the example as the correct design value and then meets a trap that says the opposite.
- ch 6 [low] Section 2, keypad scan bullets: The scan never says what to do when no column reads low. With the listed steps, a routine can fall through and still return 4r + c for a make-believe key, so the reader gets a working-looking scan that reports a key on every pass.
- ch 6 [low] Section 3, HD44780 start-up list: The start-up list is the 8-bit sequence only. The text mentions 4-bit mode and that the function-set byte there is 28H, but gives no nibble-by-nibble start-up, so a student wiring D4-D7 has no sequence to follow and may send 38H as a single byte on four lines.
- ch 7 [high] Figure (ADC0808 conversion path): The block diagram sends the SAR register straight into the comparator (dashed edge 'next trial'), with no internal DAC. The text in Section 2 correctly says the SAR code is turned into a voltage by a DAC before the comparator sees it, so the figure contradicts the explanation and teaches the wrong architecture.
- ch 7 [low] Section 2, clock and conversion time: 'eight comparison clocks plus internal overhead' suggests the overhead is small. In the ADC0808 the internal timing takes eight clock periods per bit, so 100 µs at 640 kHz is 64 clock periods, not about 8. A student multiplying 8 × 1.5625 µs gets 12.5 µs and is confused.
- ch 7 [low] Exam traps, last trap (ALE and START): It says ALE and START are separate pulses and must be done in that order. On the ADC0808/0809 the two inputs may be tied together: the address latches on the rising edge of ALE and the conversion starts on the falling edge of START, which is why many 8086 interfacing circuits drive them from one port line.
- ch 7 [low] Section 1, step size paragraph: 'Two numbers describe any DAC. The step size ... is Vref/256' is only true when Rf = R. With a different feedback resistor the step is Vref × (Rf/R)/256.
- ch 7 [low] Section 3, polling bullet: 'a few hundred polls are normal' overstates the count. On an 8086 at a few MHz one pass (IN, test, jump) takes only a few microseconds, so a 100 µs conversion completes in roughly tens of polls, not hundreds.
- ch 8 [high] Section 2 (L293D direction) and Quiz Q4: With EN high, IN1 = IN2 = 0 makes both outputs low, which shorts the two motor terminals together and brakes the motor. It does not coast. Coasting needs the channel disabled (EN low), which makes the outputs high-impedance so no current can flow.
- ch 8 [low] Exam traps, second trap: The wrong-way division N = 1.8°/360° gives 0.005 instead of 200, which is 40,000 times too small, not 200 times. The 200 is N itself, so the error factor is 200 × 200.
- ch 8 [low] Exam traps, first trap: The ULN2003 already has internal freewheeling diodes, so leaving out an external diode does not by itself destroy a ULN2003 channel. Damage happens when the COM pin is left floating instead of being tied to the coil supply positive. The missing-diode warning applies to a discrete transistor switch.
- ch 8 [low] Section 1 (coils on P0.0 to P0.3) and Section 3 (base resistor design): Port 0 of the 8051 has open-drain outputs and needs external pull-up resistors (about 10 kΩ) before it can drive anything. Also, an 8051 pin sinks about 1.6 mA but sources only about 60 µA, so it cannot supply the 0.9 mA base current the section's own design asks for; a buffer or a ULN2003 input driven by a stronger pin is needed in practice.
- ch 9 [low] Worked example 1, step 1: The exponent is printed as plain digits: "Vref/28 = 5 V / 256". A phone reader sees the number twenty-eight, not 2 to the power 8, so the formula and the 256 do not match.
- ch 9 [low] Section 1, DHT11 paragraph: "The CPU times the start pulse" reads as if the CPU measures the start pulse. The CPU drives the start pulse (line held low about 18 ms); what it times is the high-time of each of the 40 data bits.
- ch 9 [low] Quiz Q7: "poor dimming resolution" at 50 Hz is backwards. For a fixed timer clock, a longer period gives more counter steps per period, so duty resolution gets better as frequency falls; resolution comes from the counter width, not from the frequency. Only the flicker part of the answer is correct.
