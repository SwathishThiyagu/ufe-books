## Reviewer notes (after any revision)

- ch 1 [high] Section 2, masking paragraph: The mask line is broken: it reads "For pin n, mask = 1 PORT |= mask sets the bit high", with the shift and the statement separator missing. A student cannot tell how mask is formed or where the statement ends, and the following sentence defines << only after it has been used.
- ch 1 [high] Quiz Q6 answer: The C code is cut off mid-expression: "On: PORTB |= (1  Off: PORTB &= ~(1  The mask is 0x08." The shift amount and closing brackets are gone, so the answer is not valid C and cannot be copied or marked.
- ch 1 [low] Figure, One GPIO pin: The figure sends the input buffer back into the data register. Section 1 says the data register (PORT) holds the output value and a separate PIN register reports the pad voltage, so the read path in the picture contradicts the text.
- ch 1 [low] Worked example 1, question and step 6: The question asks to make output bits 0, 2 and 5 high and then says bit 5 is an input, which reads as a contradiction rather than a deliberate trap. Step 6 also has the typo "Inputs bits 4-7 are not driven."
- ch 2 [low] Figure: The compare block is labelled 'Compare' but its note says 'reload 0xCF2C'. The reload value belongs to the reload register, which sets the period; the compare register holds a match target. The diagram therefore mixes the two registers the text carefully separates, and the worked example's 0xCF2C appears in the wrong place.
- ch 2 [low] Section 1 (formula): P is described as the divide factor '1, 2, 4, 8, ...', which suggests prescalers only come in powers of two. Many timers accept any value in a small range (for example 1 to 256, or powers of two plus 1 and 3), so a student may believe a divide-by-10 setting is impossible.
- ch 2 [low] Section 3 (formula) and worked example 1: counts = d / T rarely comes out a whole number, and the chapter never says what to do with the remainder, or what small error a rounded count leaves in the period.
- ch 3 [low] Section 2, the four-part list of interrupt path: The enable chain jumps from the peripheral's own enable bit straight to the CPU global mask. On the NVIC-based Cortex-M parts this chapter teaches, there is a third gate in between: the per-source enable in the controller (ISER). A student can set the UART enable, unmask the CPU, and still see no interrupt.
- ch 3 [low] Section 2, last paragraph, and Q4 answer: 'The flag stays set until software writes to it' is not true for every peripheral. Many UART, SPI and ADC flags clear when the data or status register is read, or clear on read-then-write. Presented as a rule, it will confuse a student whose UART flag clears by itself after reading the data register.
- ch 3 [low] Section 2, Global enable bullet: 'On ARM this is the I bit in the program status register' is true for classic ARM cores (CPSR I bit) but not for the Cortex-M cores that the rest of this chapter (NVIC, ISER, IPR) describes. Cortex-M has no settable I bit in xPSR; masking is done through PRIMASK (and BASEPRI for priority-level masking).
- ch 3 [low] Figure and Worked example 1, the statement that main makes no progress during latency: The model treats the whole latency as dead time for the main program. But one of the latency causes listed in Section 3 is a software critical section, during which the main program is executing its own code, and detection time is also spent finishing a main-program instruction. The figure's blanket claim can mislead.
- ch 4 [low] Section 2, formula 'where' line: The divider ratio is printed as '215 = 32768'. The superscript was lost, so as written the line says 215 equals 32768, which is false and will confuse a student reading the formula explanation.
- ch 4 [low] Worked example 1, step 5: The step tests the kick period against the worst-case pass ('10 s is above 6 s'). That is not the rule: a kick period shorter than the loop pass time is always safer, so being 'above 6 s' is not a requirement, and a 10 s period gives less margin than the 6 s period the loop actually produces. The real check is that the timeout exceeds the worst-case pass time.
- ch 4 [low] Lead paragraph: 'Watches and RTCs appear in water meters...' reads as wristwatches; a student may not connect 'watches' to watchdog timers.
- ch 5 [low] Lead: "avoids the heat of a linear regulator" reads as if PWM itself removes the heat. PWM only cuts loss because the switching transistor is either fully on (low V, low loss) or fully off; the sentence can mislead a student into thinking duty cycle alone sets the heat.
- ch 5 [low] Section 1: "Some syllabi call this pulse-width modulation" comes right after the duty-cycle definition, so "this" seems to point at D, not at PWM (which the chapter is already about). The sentence confuses more than it helps.
- ch 5 [low] Quiz Q2: The answer says the switching period must be much shorter than the motor's mechanical time constant, but the current ripple is set by the electrical time constant L/R. Only the speed ripple is set by the mechanical time constant. A student may conclude inductance smoothing depends on the mechanical constant.
- ch 5 [low] Section 3, fourth bullet: "drives heaters through a relay or SSR" does not say that a mechanical relay cannot switch at normal PWM frequencies. A student may try 1 kHz PWM on a relay coil and get chatter and burnt contacts.
- ch 6 [high] Section 3 (DAC: code back to volts), R-2R description: The bit numbering is wrong. Bits run from 0 (LSB) to n−1 (MSB), so bit n−1 IS the MSB. Writing "Bit n−1 contributes half the current of the MSB" contradicts itself and will confuse a student trying to picture the ladder.
- ch 6 [low] Section 2 pseudo code block: The block ends with an empty "[shown output]" label. The pseudo code produces no printed output, so the reader is left looking for a result that never appears.
- ch 6 [low] Lead paragraph: The lead calls the start-of-conversion a "flag", but START/SOC is a control bit the software writes, not a status flag the hardware sets. Section 2 itself later calls it a bit, so the lead is inconsistent.
- ch 7 [low] Section 2, LCD parallel interface (addressing paragraph): The chapter says to address line 1 from 0x00 and line 2 from 0x40, then says 'send the address as a command'. A student will send 0x00 or 0x40 as the command byte. The set-DDRAM-address command needs bit 7 set, so plain 0x40 is a different command (set CGRAM address).
- ch 7 [low] Section 2, busy flag paragraph: The busy flag rule is given only for the 8-bit bus. In 4-bit mode D7 is not on the first nibble read; the program must read the high nibble (which carries BF) and then a second nibble to finish the read. A student in 4-bit mode will poll wrongly.
- ch 7 [low] Section 3, ghosting sentence: Two of the three listed cures do not stop ghosting. 'Scan one key at a time' does not help: the ghost path runs through the two pressed keys of the L, whatever the row drive is. Only series diodes, or rejecting a row where more than one column reads 0, remove the ghost.
- ch 7 [low] Worked example 1, step 3: The note 'A 300 Ω resistor is not a common E12 value' is true but misleading: 300 Ω is a standard E24 value and is sold. Calling 330 Ω 'the nearest listed standard value' implies 300 Ω does not exist.
- ch 8 [high] Section 3, first paragraph on H-bridges: The text says the L293D and L298N are H-bridges 'with the protection diodes included'. Only the L293D has internal clamp diodes (the D suffix). The L298N chip has no internal flyback diodes and needs external fast-recovery diodes; only ready-made L298N modules add them on the board.
- ch 8 [high] Quiz Q7, answer: The parenthetical 'It may be too slow (1N4148 instead of 1N4007)' is backwards. The 1N4148 is a fast small-signal diode (a few ns) and the 1N4007 is a slow mains rectifier (about 2 µs recovery). The real limit of the 1N4148 here is its small current and voltage rating (about 300 mA, 100 V), not its speed.
- ch 8 [high] Section 3, stepper paragraph (and the sequence repeated in Quiz Q6): The text says 'Four coils are energised in sequence; a full-step sequence is A, B, A′, B′.' The prime (A′) means the same winding energised with reversed current, which only a bipolar motor driven by an H-bridge driver (A4988) can do. A four-coil unipolar motor driven by a ULN2003, as the same paragraph mentions, has no way to reverse a coil, so a student wiring it in the A, B, A′, B′ order cannot make it work.
- ch 8 [low] Section 3, PWM speed paragraph: 'Use 1–20 kHz so the switching is above hearing' contradicts itself: 1 kHz is well inside the audible band (about 20 Hz to 20 kHz), so a motor driven at that frequency whines.
- ch 8 [low] Worked example 1, step 5: Rounding the base resistor up to 3.3 kΩ gives 0.788 mA, which is just below the 0.8 mA the calculation asked for. The claim 'so the transistor stays saturated' is therefore only just true on paper; in practice the datasheet hFE is a minimum only at a specified V_CE, and designers add an overdrive factor of 2 to 5.
- ch 8 [low] Section 2, optocoupler sentence: 'For a mains load, add an optocoupler such as the PC817 so the MCU side and the mains side share no conductor.' A plain optocoupler only isolates a low-voltage signal; it cannot switch a mains load by itself. A student may think the PC817 drives the lamp directly.
- ch 9 [low] Quiz Q1 (and lead vs Section 1): Q1 asks for 'four values' and the answer lists source address, destination address, count and transfer size, but Section 1 tells the student to program five fields, adding direction. A student writing five in the exam (or four, after reading the body) meets an inconsistent question.
- ch 9 [low] Section 2, mode table, Burst row: The table says burst mode holds the bus for the 'whole block', but the text says burst holds it for 'a run of items' and Exam trap 1 warns about 'a long burst'. A burst length is a programmed number of items, not necessarily the entire block; the table wording can make a student think burst mode always transfers everything.
- ch 9 [low] Section 3, cache coherency fix: 'Fix it by cleaning and invalidating the cache region' is loose for the case described (DMA has just written the buffer and the CPU reads it). Cleaning writes cached data back to RAM, so cleaning a dirty line covering the DMA buffer can overwrite the freshly DMA-written samples with stale values. Order and direction matter.
- ch 9 [low] Quiz Q2 answer: 'Polling ... can miss the exact end' is imprecise; polling software does detect the done flag, only late, and it burns cycles meanwhile. A student may repeat the wrong reason.
