## Reviewer notes (after any revision)

- ch 1 [high] Section 2, the b = −θ rewrite and the sentence 'In general, y = step(Σᵢ wᵢxᵢ + b)': The chapter mixes two conventions and they contradict each other. The stated rule is z = Σwᵢxᵢ + b and y = 1 if z ≥ θ, so the firing condition is Σwᵢxᵢ + b ≥ θ. Under that rule, setting b = −θ gives y = 1 only when Σwᵢxᵢ ≥ 2θ, not Σwᵢxᵢ ≥ θ. The claim 'y = step(Σwᵢxᵢ − θ)' is therefore wrong here, and so is 'In general, y = step(Σwᵢxᵢ + b)', which silently drops θ and is true only when θ = 0.
- ch 1 [high] Quiz Q3: The algebra in the answer is wrong. From z = Σwᵢxᵢ − θ and the chapter's rule y = 1 if z ≥ θ, the condition becomes Σwᵢxᵢ − θ ≥ θ, that is Σwᵢxᵢ ≥ 2θ. The answer says Σwᵢxᵢ ≥ θ, and then jumps to 'compare the weighted sum with 0 after subtracting θ', which is a different rule from the one stated in Section 2.
- ch 1 [low] Exam traps, third trap: The sentence 'The bias is not a separate threshold in the formula z = Σwᵢxᵢ + b' clashes with the chapter's own rule y = 1 if z ≥ θ, where b and θ both appear. As written a student cannot tell which of the two terms is the threshold.
- ch 2 [low] Section 1, the AND/bias sentence: The sentence 'Without b the boundary must pass through the origin, and a function like x₁ AND x₂ — true only at (1,1) — cannot be split, because its boundary is the line x₁ + x₂ = 1.5' reads as self-contradictory: it first says AND cannot be split, then gives a line that does split it. The missing step (that x₁ + x₂ = 1.5 does not pass through the origin, so no bias-free unit can use it) is left for the student to supply, and many will read it as an error in the chapter rather than in the bias-free perceptron.
- ch 2 [low] Section 2 step list and the Figure: The step list updates the weights and then moves straight to the next sample, but the figure sends the updated weights back to 'net' with a 're-test' edge and the caption says the same sample is tested again. The two descriptions of one algorithm disagree, and an examiner marking the figure or the pseudocode will get different traces from a student.
- ch 2 [low] Worked example 1, output block: The output block lists nine unlabelled numbers (1 1 1 0 1 0 1 2 -2). Nothing says the first three are w₁, w₂, b after step 2, the next three after step 4, and the last three at convergence, so a reader cannot tell what is being reported or check it against the steps.
- ch 2 [low] Section 2, after the step list: The claim 'no loss function appears anywhere' is too strong as written. Some textbooks present the perceptron criterion E = −Σ t(w·x + b) over misclassified samples, whose sub-gradient step has the same form as the rule. The accurate point is that the rule is a fixed correction, not derived by taking a derivative of a loss.
- ch 2 [low] Lead: The lead uses η, t and y in the formula 'add η(t − y)x' before any of them is defined; the definitions only arrive in the Section 2 formula box. A first-time reader stumbles on the first line of the chapter.
- ch 3 [low] Section 3 and Worked example 1: The network is 2–3–1, so the output unit has three inputs, but the XOR construction defines only h₁ and h₂ and writes y = step(h₁ − h₂ − 0.5). The third hidden unit and its outgoing weight w₃ are left unspecified, so a student cannot see how the 13-parameter count matches the 2-hidden-unit XOR circuit.
- ch 3 [low] Section 2, universal approximation statement: The statement is given without the nonlinearity condition, so it reads as if a single hidden layer with linear activation would also qualify, which contradicts the exam trap on linear layers collapsing.
- ch 4 [high] Section 2, ReLU paragraph: The sentence is broken: "for z  0 and 0 for z < 0" has lost its middle, so the definition of ReLU on the negative side and the statement of the derivative never appear in that sentence. A student reading it cannot tell what ReLU outputs for z < 0.
- ch 4 [low] Lead: "Both must be differentiable" is stated as a blanket rule, but the chapter itself then presents the step function (derivative zero almost everywhere) and hinge loss (kinked at 1 − ty = 0), and says ReLU is not differentiable at z = 0. The absolute wording contradicts the rest of the text.
- ch 4 [low] Figure: The y-axis is labelled σ(z) with range −1.5 to 1.5, but the plot also shows tanh, whose output runs from −1 to 1. The axis label suggests only the sigmoid is plotted.
- ch 5 [low] Section 3, first paragraph: η is called a small positive number and given as 'such as 0.1 or 0.5'. A learning rate of 0.5 is on the large side for plain gradient descent and is not a good first example for a student who will copy it.
- ch 5 [low] Quiz Q3: The explanation uses layer l (W maps a⁽ˡ⁻¹⁾ to z⁽ˡ⁾, so W⁽ˡ⁾ᵀ maps sizes nₗ → nₗ₋₁), but the formula it ends with is the shifted-index version (W⁽ˡ⁺¹⁾ᵀ δ⁽ˡ⁺¹⁾). The 'so' joins two statements with different indices, which will confuse a student checking shapes.
- ch 5 [low] Quiz Q6: 'Roughly squaring the work' is imprecise. Recomputing the forward pass for each layer during the backward sweep multiplies the step cost by about the depth L, that is, it makes the cost quadratic in depth, but it is not a squaring of the total weight-level work.
- ch 5 [low] Figure: The dashed arrow from a to z is labelled δ, but δ = ∂L/∂z is defined at z, not carried along the edge into z. Also the gradient node ∂L/∂W is drawn as fed from z alone, although ∂L/∂W⁽ˡ⁾ = δ (a⁽ˡ⁻¹⁾)ᵀ also needs the stored input a⁽ˡ⁻¹⁾ (here x).
- ch 6 [high] Lead: "Plain gradient descent uses one fixed step size, so it is slow on flat directions, noisy on steep ones, and it can overfit." Plain (batch) gradient descent is deterministic, not noisy; on steep directions a fixed step overshoots and oscillates. And overfitting is not caused by having a fixed step size — any optimizer run long enough on a small training set can overfit. A student can carry both wrong ideas into the exam.
- ch 6 [low] Section 2 and Section 3: The symbol β is used twice with unrelated meanings: the momentum coefficient in Section 2 (β = 0.9) and the learned batch-norm shift in Section 3 (y = γẑ + β). A reader skimming the formulas can confuse them.
- ch 6 [low] Section 2, Adam paragraph: The text says "know the shape and the defaults" but only gives the β defaults; Adam's default learning rate η = 0.001 and the usual ε = 10⁻⁸ are never stated, so a student cannot actually answer a question about the defaults.
- ch 7 [high] section 2, the displayed formula: The chain-rule formula is written as ∂L/∂W₁ = (∂L/∂a_L) × Π σ′(z_l) × W_l, which puts the weight matrix outside the product. As written it means the product of the sigmoid derivatives, multiplied once by a single weight matrix, which is not the backpropagation product. A student copying this into an exam writes a wrong formula.
- ch 7 [low] quiz Q2 answer: The working is written 'σ(1−σ) = 0.5 × 0.5'. The symbol σ is being used both for the function and for its own value, so the expression does not read correctly.
- ch 7 [low] worked example 1, step 2: '0.25⁵ = 0.25 × 0.25 = 0.0625' shows only two factors next to a fifth power, so the line contradicts itself even though the remaining values in the step are right.
- ch 7 [low] section 1, last sentence: 'Deep networks can represent some functions with far fewer units than a shallow network needs, which is why they became practical' gives expressivity as the reason deep networks became practical. Section 1 itself names large datasets and GPUs as the practical reason, so the two sentences disagree.
- ch 7 [low] lead paragraph, last sentence: 'Every modern image, speech and medical-imaging model uses these ideas' is too strong. Many current models use GELU or other activations and normalization instead of plain ReLU chains.
- ch 7 [low] section 2, closing sentence: 'the name unit saturation and the name vanishing gradient describe the same mechanism' blurs cause and effect: saturation of a unit is one cause, the vanishing gradient is the resulting effect over many layers.
- ch 8 [high] Section 2, vertical-edge filter sentence: The response direction is stated backwards. With the filter rows 1 0 −1 / 1 0 −1 / 1 0 −1, the left column of the patch is multiplied by +1 and the right column by −1, so the response is large and positive where the left side is brighter than the right (brightness falls from left to right), and negative where brightness rises from left to right. The chapter's own worked example agrees: the patch [[1,0,1],[0,1,2],[1,2,3]] gets brighter to the right and gives −4, not a positive value.
- ch 8 [low] Figure; section 3 pipeline: The figure goes Flatten → Softmax with no dense layer, while the pipeline given in Section 2 ends conv → ReLU → pool → flatten → dense → softmax. A student sees two different end-stages for the same network.
- ch 8 [low] Section 1, first paragraph of convolution: The operation described (multiply the patch and the filter element by element, sum, slide) is cross-correlation, not true convolution, which flips the filter. Deep-learning libraries call it convolution, so the name is correct in practice, but the chapter never says so.
- ch 9 [high] Section 2 (BPTT and gradient size), the one-step derivative and the product formula: With h_t = tanh(W x_t + U h_{t−1} + b), the Jacobian is ∂h_t/∂h_{t−1} = diag(1 − h_t²) U (a d×d matrix), because h_t is differentiated as a function of U h_{t−1}. The chapter writes ∂h_t/∂h_{t−1} = Uᵀ diag(1 − h_t²), which is the transpose of the true Jacobian, not the Jacobian itself. Uᵀ diag(1 − h_t²) is the operator used in the backward pass when multiplying ∂L/∂h_t to get ∂L/∂h_{t−1}. The worked example quietly uses the correct scalar order, U(1 − h²), so the formula and the example disagree once U is a matrix; matrix order matters and a student who computes the Jacobian from this line gives the wrong answer. The product formula inherits the same swap, and its factor order is not stated.
- ch 9 [low] Section 3 heading and first paragraph: GRU is expanded as 'gated recurrent unit' but LSTM is never expanded, so a reader meeting the acronym for the first time has no full form.
- ch 9 [low] Section 1, first paragraph ('memory cost is O(d)'): O(d) is true for the model's state at run time, but training with BPTT keeps the activations of every unrolled step in memory, so the cost per sequence is O(T·d). Read as written, a student may claim training memory is independent of sequence length, which is false and is often asked in exams.
