## Reviewer notes (after any revision)

- ch 1 [low] Section 1, certification sentence: The requirement is named but not quantified, so a student cannot state the target that examiners expect alongside 'extremely improbable'.
- ch 1 [low] Section 1, integration paragraph: 'The cockpit became fewer glass displays fed by shared computers' reads as if the cockpit itself turned into displays; the comparison with the old separate boxes is lost.
- ch 1 [low] Section 2, mission computing sentence: 'Mission computing fuses radar, EO/IR, SIGINT, communications and stores management' puts stores management into the sensor-fusion list, which contradicts the very next sentence saying it is not a sensor.
- ch 1 [low] Section 2, payload list sentence: 'radar, EO/IR, SIGINT, communications, stores and science packages' mixes three different things: sensor payloads, a link, weapons, and science packages, which belong to spacecraft, not fighters. It also asks cooling for stores, which is not how weapons are treated.
- ch 2 [low] Figure and its description (Section 3): The block diagram puts Federated LRUs and IMA modules in one series chain (Sensors → Federated LRUs → IMA modules → AFDX → Displays). Drawn that way it reads as a data path in which federated LRUs feed the IMA cabinet, which is not how either architecture works; the two are alternatives.
- ch 2 [low] Section 1, federated architecture paragraph: 'The autopilot computer moves the control surfaces' can mislead a student into thinking the computer drives the surface directly. The computer issues commands; actuators move the surface.
- ch 2 [low] Worked example 1, output block: The output lines give bare numbers (11, 230, 68.75, 71.875) with no units, while the answer line below carries units. A student copying the output block loses the units that the question asks for.
- ch 3 [high] Section 2, Worked example 1, Exam trap 3, Quiz Q5: The chapter defines a page as a screen layout that can hold many quantities, but then treats one page as one dial function. It says four displays replace twenty-four dials because each display has six pages, and the trap says they carry twenty-four dial functions 'only because' each display has six pages. Four displays with six pages each give twenty-four page slots over time, but only four pages are visible at once. Replacing twenty-four simultaneous dials is not explained by six sequential pages per display; one page can show many functions, or one function may appear on several pages. The arithmetic in the worked example and Q5 is correct only for the separate counts of page slots and functions per display, not because pages equal functions.
- ch 3 [low] Section 2 formula: N_pages = D × P is presented as the total number of pages the screens can show. It actually counts page slots if each display can show P pages. If displays share the same pages, the number of distinct pages is not D × P.
- ch 3 [low] Section 3 software assurance: DO-178B is a software assurance/certification standard, not a 'safety process'. The wording is loose.
- ch 4 [high] Section 1, last line of the PFD section: The claim that 'One PFD replaces three mechanical dials' undercounts badly and contradicts the chapter's own list. A PFD carries attitude, airspeed, altitude, vertical speed and heading, so it replaces at least five instruments from the old panel (attitude indicator, airspeed indicator, altimeter, vertical speed indicator, heading indicator/HSI), more on a full six-pack.
- ch 4 [low] Section 3, paragraph on alert levels: Naming white as the colour of advisory messages is not standard. On Boeing EICAS the advisory level is normally shown in cyan/blue and white is used for memo/status lines; on Airbus ECAM, status/memo text is white. A student who writes 'advisory = white' in an exam can lose marks.
- ch 4 [low] Section 3, first paragraph: 'Electronic system monitor displays' is not a standard textbook term; presenting it as a syllabus label may confuse students who meet only EICAS and ECAM in their notes.
- ch 5 [high] Section 1, paragraph 2: The claim 'The eye does not need to change focus when it moves from the instrument panel to the HUD' is wrong. Collimated symbols are at infinity, while the instrument panel is a near object (roughly 0.5 m). Moving the gaze from the panel to the HUD does need a change of accommodation. The real benefit of collimation is that the symbols and the distant outside scene are at the same focus, so the pilot does not refocus between the symbols and the runway.
- ch 5 [high] Section 1, formula definition and Worked example 1: θ is defined as the 'look-down angle' from the eye to the combiner, but h is defined as the height of the combiner above the eye. If the combiner is above the eye line, the eye looks up, not down. The name and the geometry contradict each other, and Worked example 1 (75 mm above the eye) is really an angle of elevation.
- ch 5 [low] Figure (HUD and HMD light path) and its caption: The dashed edge p → h shows light going from the HUD projector to the helmet display, which is not physical: an HMD has its own display and optics. The caption 'both paths end at the same eye' also suggests a HUD and an HMD are used at the same time on the same eye, which is normally not the case.
- ch 5 [low] Section 3, paragraph 3: 'The eye relief and exit pupil must allow the pilot to see the whole symbol' is unclear: there is no single 'symbol' to see; eye relief and exit pupil decide whether the pilot sees the whole image (full field of view) without vignetting.
- ch 5 [low] Quiz Q2 answer: The answer says the eyes 'do not need to refocus', which repeats the error in Section 1 and suggests no accommodation change at all when moving from the panel to the HUD.
- ch 6 [low] Figure: The caption groups displays and warnings as the information layers and controls as action, but the stack order puts Controls between Displays and Warnings, so the drawing contradicts its own description.
- ch 6 [low] Figure, Displays item: The note 'visual and aural' under the Displays layer mixes two channels; an aural alert is not a display, and the chapter itself treats sound as a separate cue.
- ch 6 [low] Worked example 1: The 2.4 s is the worst case (the warning appears just after the crew passes that display); the average delay is about half of it. Saying only '2.4 s > 2 s' can make a student think the scan is always this slow.
- ch 7 [high] Section 1, last sentence ("Its weakness is wiring: each direction and each parameter needs its own pair"): A 32-bit ARINC 429 word carries a label, and one transmitter pair sends many different labels one after another (time-multiplexed). The standard requires one pair per direction (one transmitter per pair, up to 20 receivers); it does not require one pair per parameter. Saying a pair is needed for every parameter teaches a false rule and also drives the answer to Q4.
- ch 7 [low] Quiz Q4: The question says "20 one-way parameters to send between two LRUs", which does not say whether the 20 parameters travel one way or both ways, and the model answer (20 pairs + 20 pairs) assumes one pair per parameter, a design choice rather than a standard requirement.
- ch 7 [low] Worked example 1 and Quiz Q7 (word counting): The counts (1 command + 1 data + 1 status, and 1 command + 4 data + 1 status) match only a transmit message (RT to controller). In the receive message described in Q6 and in the figure, the RT sends a status word after the command and again after the data, so the same data needs one extra word. A student who follows Q6 and then answers Q7 gets a different total.
- ch 8 [high] Exam traps, second bullet: The direction of the unit slip is stated backwards. If BAG is written as 2 instead of 0.002 s, the divisor becomes larger, so the answer comes out 1000 times too small (8000 ÷ 2 = 4000 bit/s, not 4 000 000 bit/s), not too large.
- ch 8 [high] Figure and its caption: The diagram shows redundancy as a chain: end system → switch → switch → end system, and the caption says 'the second switch forms the independent redundant network'. Two switches in series are not a redundant network; AFDX redundancy is two independent parallel networks A and B from the same source end system. The 'Virtual link' box drawn as a node feeding a switch with a dashed edge also suggests a VL is a physical device, which contradicts Section 2.
- ch 8 [low] Quiz Q6: The answer gives 120 µs for the 1500 bytes alone. It does not say that the real time on the wire is a little longer, because the frame also carries headers, a preamble and the interframe gap.
- ch 8 [low] Section 3, second paragraph: The reflection is described but not named. Students meet the term 'total internal reflection' and the critical angle in physics, and the link between the two is left implicit.
- ch 8 [low] Section 3, last paragraph: The cross-reference 'see Unit 1, Flight Control Systems' is plain text, so a student reading on a phone cannot jump to that chapter, unlike the other cross-references in the book.
- ch 9 [high] Figure (caption and spec): The caption says the two blue (accent) boxes are where the code is written and where it is first tested, but in the spec the accent nodes are 'Low-level requirements' and 'Code'. The unit test node is styled 'next', not accent. A student looking at the figure will not find the box the caption calls 'where it is first tested'.
- ch 9 [low] Figure spec: The nodes are drawn as one straight downward chain (l → c → u → i → v), so the picture is a line, not a V. The caption promises 'tests verify up the right arm', but the arrows from code to unit test to integration test to validation all point down, which contradicts the caption.
- ch 9 [low] Section 1, traceability paragraph: 'A test with no requirement is wasted effort' is too absolute. Robustness tests (for example, feeding out-of-range values to check the software fails safely) are required by DO-178B and do not trace to a requirement.
- ch 9 [low] Section 1, traceability paragraph: 'Every HLR points down to code' is not how DO-178B traceability works. High-level requirements trace down to low-level requirements, and low-level requirements trace to source code.
- ch 10 [low] Section 3, thermocouple paragraph: Saying the Seebeck emf is 'proportional to the temperature difference' is only true for small differences. Over the exhaust-gas range a thermocouple is noticeably nonlinear, which is why reference tables and linearisation are needed.
- ch 10 [low] Section 4, LVDT paragraph: 'The secondary difference gives amplitude and phase proportional to displacement' is loose. Amplitude carries the size of the displacement; phase carries the direction. A student can read it as both being proportional to displacement.
- ch 10 [low] Quiz Q2 answer: 'the cold-junction temperature must be measured and added as compensation' is ambiguous: a temperature is not added to an emf. What is added is a compensating emf.
- ch 10 [low] Figure, strain branch: The example given for the strain branch is 'Bridge', which is signal conditioning, not a strain-sensing transducer. The tree promises one example of a transducer per branch.
- ch 10 [low] Section 1, last sentence: The forward reference to section 4.11 is plain text; the book's convention is to link cross-references so a phone reader can jump to them.
- ch 11 [high] Section 3, ADC paragraph: The chapter defines the output code as floor(Vin / Q), which truncates, and then says quantisation error is up to ±Q/2. These two statements do not agree. With truncation the error is always one-sided: it lies between 0 and −Q (up to one full step). The ±Q/2 (half a step) figure is true only when the converter rounds to the nearest step.
- ch 11 [high] Section 3 prose, Exam trap 1, Worked example 1 step 1, Quiz Q3 and Q7: Exponents have been lost in the running text, so statements that are false appear: 'Q = Vref / 2N', 'use Q = Vref / 2N, not Vref / 255', 'Number of codes = 28 = 256', 'Q = 4.096 / 210 = 4.096 / 1024' and 'Q = 3.3 / 212 = 3.3 / 4096'. A student reads 28, 210 and 212 as ordinary numbers, and 28 = 256 is plainly wrong.
- ch 11 [low] Section 2, differential amplifier sentence: 'With four equal resistors it has gain Rf/Rin' is misleading. If all four resistors are equal then Rf = Rin and the gain is exactly 1; a student may think four equal resistors can give a gain other than 1.
- ch 11 [low] Section 2, buffer sentence: 'Rin open' is unclear; an open resistor is the same as no resistor at all, and the student may think a resistor is still fitted.
- ch 11 [low] Section 3, ADC paragraph: The code formula has no upper limit: for Vin at or above Vref it gives 2^N, a code that does not fit in N bits.
